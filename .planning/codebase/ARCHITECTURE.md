# Architecture

**Analysis Date:** 2026-08-10

## Pattern Overview

**Overall:** Content-driven Next.js marketing site with a locale-aware static export and documentation hub

**Key Characteristics:**
- App Router structure with server components for content and metadata
- Client components reserved for motion, viewport observers, navigation, and analytics
- Dual-domain locale ownership across `fastgpt.io` and `fastgpt.cn`
- Static export output used for Cloudflare Pages and Nginx hosting

## Layers

**Route Layer:**
- Purpose: Resolve paths, locales, metadata, and 404 behavior
- Contains: `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/[lang]/**/page.tsx`
- Depends on: locale helpers, SEO helpers, content loaders, and dictionary loaders
- Used by: browser requests and static export generation

**Presentation Layer:**
- Purpose: Render reusable page sections and layout shells
- Contains: `src/components/home/*`, `src/components/faq/*`, `src/components/price/*`, `src/components/tech-center/*`, `src/components/compare/*`
- Depends on: design tokens, motion primitives, and route data
- Used by: route components and localized page entries

**Content and Configuration Layer:**
- Purpose: Hold locale dictionaries, FAQ data, tech-center markdown, and site config
- Contains: `src/locales/*`, `src/faq/*`, `src/content/*`, `src/config/*`, `src/lib/*`
- Depends on: Node file access for markdown and JSON loading
- Used by: metadata generation and page rendering

**Integration Layer:**
- Purpose: Connect the site to analytics, attribution, and external signals
- Contains: `src/app/GoogleAnalytics.tsx`, `src/app/BaiDuAnalytics.tsx`, `src/app/ClarityAnalytics.tsx`, `src/app/RybbitAnalytics.tsx`, `src/lib/leadAttribution.ts`, `src/lib/githubStars.ts`
- Depends on: browser storage, environment variables, and public APIs
- Used by: root layout and home/CTA interactions

**Build and Export Layer:**
- Purpose: Prepare the static site and validate the exported artifacts
- Contains: `next.config.js`, `public/_redirects`, `nginx.conf`, `scripts/*.js`
- Depends on: `out/` generated by `next build`
- Used by: deployment and release checks

## Data Flow

**Home and Marketing Pages:**
1. Request reaches `src/app/layout.tsx` and the matching route entry.
2. Locale helpers in `src/lib/i18n.ts` and `src/lib/siteRouting.ts` resolve the language and site variant.
3. `getDictionary()` loads the matching locale JSON from `src/locales/`.
4. `generateMetadata()` uses `src/lib/seo.ts` to build canonical and alternate links.
5. Page components compose shared sections from `src/components/home/`.
6. Client-side motion, analytics, and CTA behavior activate after hydration.
7. `next build` exports `out/`, and verification scripts inspect the generated HTML and assets.

**Tech Center Flow:**
1. `/tech-center` resolves through `src/app/[lang]/tech-center/page.tsx` or `src/app/tech-center/page.tsx`.
2. `src/components/tech-center/data.ts` provides the entry registry.
3. `src/lib/tech-center-content.ts` loads markdown files from `src/content/tech-center/` and derives SEO descriptions.
4. The hub renders search, filters, pagination, and article cards.
5. Detail pages render the article body with related links and a CTA.

**FAQ Flow:**
1. FAQ list and detail routes resolve through `src/faq/*` helpers and `src/app/[lang]/faq/[id]/page.tsx`.
2. Locale resolution collapses to supported FAQ languages.
3. Metadata helpers build canonical URLs and hreflang values.
4. Missing slugs trigger `notFound()`.

**State Management:**
- Server-rendered content stays largely stateless.
- Browser state covers preferred language, visitor attribution, and current UI filters.
- GitHub stars use a local cache file as a fallback source.

## Key Abstractions

**Locale Ownership:**
- Purpose: Map each language to the correct domain and canonical URL
- Examples: `normalizeLocale`, `getLocaleOwner`, `getOwnedLocaleUrl`, `getAlternates`
- Pattern: registry-based routing helper

**Content Registry:**
- Purpose: Keep published docs and route metadata aligned
- Examples: `TECH_ENTRIES`, FAQ dictionaries, `siteConfig`
- Pattern: data-first page generation

**Shared Landing Shell:**
- Purpose: Reuse header, hero, CTA, and footer across root and localized routes
- Examples: `HomeLanding`, `HomeLayoutSwitcher`, `Navbar`, `Footer`
- Pattern: composed feature layout

**Fallback External Data:**
- Purpose: Keep the page usable when external data is unavailable
- Examples: GitHub stars cache and attribution fallbacks
- Pattern: best-effort fetch with local fallback

## Entry Points

**Root Layout:**
- Location: `src/app/layout.tsx`
- Triggers: every request
- Responsibilities: fonts, theme provider, analytics providers, and HTML language bootstrapping

**Home Routes:**
- Location: `src/app/page.tsx`, `src/app/[lang]/page.tsx`
- Triggers: root home requests
- Responsibilities: dictionaries, metadata, GitHub stars, and shared landing content

**Pricing and FAQ Routes:**
- Location: `src/app/[lang]/price/page.tsx`, `src/app/[lang]/faq/[id]/page.tsx`
- Triggers: locale-aware pricing and FAQ visits
- Responsibilities: localized copy, SEO metadata, related content, and CTA surfaces

**Tech Center Routes:**
- Location: `src/app/[lang]/tech-center/page.tsx`, `src/app/[lang]/[section]/[slug]/page.tsx`, `src/app/tech-center/page.tsx`
- Triggers: reference content requests
- Responsibilities: article metadata, markdown, related links, and search/filter UI

**Comparison Routes:**
- Location: `src/app/compare/[slug]/page.tsx`, `src/app/[lang]/compare/[slug]/page.tsx`
- Triggers: competitor comparison pages
- Responsibilities: structured product comparison content and canonical metadata

## Error Handling

**Strategy:** Route-level failures surface as `notFound()` or build-time exceptions; external calls use fallback paths at the boundary

**Patterns:**
- Missing FAQ or tech-center content aborts rendering through `notFound()` or parser errors
- GitHub stars return a cached fallback when the live API fails
- Analytics and attribution helpers return early when configuration is missing
- Browser-only code runs behind `use client`, `dynamic()`, and viewport observers

## Cross-Cutting Concerns

**SEO:**
- Canonical URLs, hreflang, and metadata live in `src/lib/seo.ts`, `src/lib/siteRouting.ts`, and per-route `generateMetadata()` functions

**Theming:**
- `ThemeProvider` wraps the app and global CSS variables drive the visual system

**Motion and Performance:**
- Framer Motion, IntersectionObserver gates, and lazy dynamic imports reduce initial load

**Analytics and Attribution:**
- Root layout mounts tracking scripts and `LeadAttribution` reports visitor data after idle time

**Static Export Compatibility:**
- Redirects, headers, image generation, and verification scripts all assume a build into `out/`
