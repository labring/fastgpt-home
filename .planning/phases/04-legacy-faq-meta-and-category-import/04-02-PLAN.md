# Plan 04-02: Build the fail-closed category batch engine

## Objective

Provide a deterministic full-batch dry-run for all 2,000 category rows, explicit allowlist processing for uniquely matched rows, immutable snapshots, idempotent replay, and matching-batch rollback.

## Tasks

1. Add a category batch module that consumes the Phase 1 identity and category reports, validates the nine-category contract, computes a canonical batch fingerprint, and emits every row with its source identity, category, confidence, review flag, and status.
2. Make the default full batch fail closed on the 606 identity conflicts and prove zero writes. Require source-row allowlists for any applied subset and reject implicit matched filtering.
3. Implement a local batch store under `artifacts/phase4/batches/` with immutable batch metadata, pre-write snapshots, protected body/question/key/URL hashes, result manifests, and explicit dry-run/apply/rollback commands.
4. Add deterministic tests for zero-write blocked full batches, allowlist validation, same-input idempotent no-op, changed-fingerprint invalidation, unauthorized rollback, and successful snapshot restoration.

## Verification

- Run full dry-run and inspect row totals, nine-category counts, conflict list, and zero-write result.
- Run the focused batch regression test against a temporary fixture and check `git diff --check`.
