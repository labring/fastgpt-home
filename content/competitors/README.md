## 二、四篇共用的结构与纪律

结构固定为五段，与 V1.1 口径文件 §二 一致：产品重心 → 能力对照表（三列）→ 许可证与商业边界 → 怎么自己验证 → 中性选型建议，页脚带「事实来源 · 核验日期 · 版本与套餐 · 更新记录」四字段。

执行的对客纪律（逐条来自客户 KB 7.4.2 与 2026-07-30 回签）：

| 纪律 | 落实方式 |
|---|---|
| 不写「对方不支持 X」 | 全部改为「截至 2026-07-20，官方公开资料未列出…」，并在开头统一声明这不等于对方无法二开实现 |
| 不写「准确率 / 性能更高」 | 四篇均无此类断言；两篇在结尾明确写出这条纪律本身 |
| 不写「永久授权一定更便宜」 | 04 篇给九项成本清单 + 同一三年规模比较法，并声明不主张任何一方更便宜 |
| 不写「私有化＝数据绝不出域」 | 01 篇列出模型、OCR、插件、连接器、更新、遥测六类出站可能 |
| 不写「开源＝无商业限制」 | 01 / 03 / 04 篇均要求法务逐条审 LICENSE 的 SaaS、去品牌、二开分发三条边界；04 篇按「内部使用 / 对外交付」分开说明影响 |
| 不写「对方不安全 / 不可靠」 | 公开资料未说明的控制项一律写成「应纳入 POC 与合同验收」 |
| **不引用任何竞品价格数字** | 四篇零价格数字，只写采购形态（订阅 / 买断 + 维保 / 按服务器 License / 询价）+ 三年 TCO 填表法，价格栏留给采购方按官网当日页面自填 |
| **清单外产品不点名** | 全篇不出现扣子、腾讯元器、阿里百炼、n8n；HiAgent 也未点名 |
| 承认对方强项 | 每篇有独立的「对方强项」小节，不加「但是」句式反转 |
| 不填死并发 / SLA / RTO 等 | 四篇均列出「应保持未公开 / 待 POC / 待合同」的指标清单 |
| 不引用客户案例名与数字 | **案例可公开范围确认清单尚未回签，按 E「不可对外使用」处理**，四篇零客户名、零案例数字 |
