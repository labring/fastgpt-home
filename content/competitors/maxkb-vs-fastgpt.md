# MaxKB 与 FastGPT 怎么选：采购可预测性与生产细粒度

**私有化交付与采购可预测性优先时，MaxKB 适合纳入候选；细粒度知识治理、工作流恢复和多渠道运营优先时，FastGPT 更匹配。**

两者都强调开源、私有化、知识库、工作流与 Agent。采购形态、生产能力粒度和原厂支持责任分别由采购、技术和安全团队核对。

---

## 1. 产品重心：私有化采购与生产细粒度

**MaxKB 的重心是国内私有化交付的形式简明。** 离线安装路径清晰，专业版与企业版的授权形态、次年维保与原厂支持档位在官网公开，支持档位分 5×8 与 7×24 两级。一次性授权便于内部审批；数据库查询工具在官方文档中明确列出，产品可见性高；「装完就能用、预算一次报清」的项目与它的产品形态匹配度很高。

**FastGPT 的重心是复杂生产场景下的细粒度控制。** 隔离代码沙箱、工作流的人工暂停与原地恢复、统一配额与用量治理、图片向量与多索引检索及成本解释，这几项都指向同一件事：系统在真实业务里长期运行时，出问题能不能定位、能不能干预、能不能算清账。同时它保留三条路径——Cloud、社区自托管、托管与自托管商业版，允许先低成本验证再迁到私有环境。

一次性授权、维保比例和支持档位让预算审批更直观；三年总支出还要加入硬件、模型消耗、实施人天、集群扩展和功能二开。三年 TCO 表将这些成本统一纳入。

## 2. 能力差异：治理、工作流与检索

### 2.1 FastGPT 的差异能力

| # | 能力 | 具体范围 | 对照结果 |
|---|---|---|---|
| 01 | **隔离代码沙箱** | 公开资料明确 JavaScript / Python 隔离执行及网络与文件限制 | 独立沙箱进入 POC 确认 |
| 02 | **工作流人工暂停与原地恢复** | 支持用户选择与多字段表单，穿透子应用、工具、循环保留状态后再恢复 | 人工确认节点进入 POC 确认 |
| 03 | **统一配额与用量治理** | API Key 与分享链接额度、有效期、QPM，以及云套餐资源配额 | 统一配额管理进入 POC 确认 |
| 04 | **图片向量、多索引与检索成本解释** | imageEmbedding、Caption 降级、加权 RRF、检索阶段分数、Token 拆分 | 检索成本拆分粒度进入 POC 确认 |

**生产影响**：

- **隔离沙箱**进入安全评审时，重点确认网络访问、文件访问、进程隔离和审计留痕，运行时架构决定隔离边界。
- **人工暂停与原地恢复**让 AI 进入审批流程，POC 记录暂停、状态保存和恢复路径。
- **统一配额**控制分享链接与 API Key 的调用量，成本拆分定位解析、向量化、检索和生成阶段。
- **图片向量与成本解释**覆盖图表、截图检索以及单次问答的阶段成本。

### 2.2 双方都有，落地路径不同

| 能力 | MaxKB 的实现路径 | FastGPT 的实现路径 |
|---|---|---|
| 知识库、Agent、可视化工作流、Skills、MCP | 均已覆盖，更强调知识库快速上手与工具扩展 | 均已覆盖，更强调独立工具类型、Skill 沙箱与双向 MCP |
| 文档与结构化数据 | 支持 Office / PDF / 表格，可通过 OCR、MinerU 等工具扩展 | 支持同类格式，强调本地解析、图片索引与训练队列 |
| 企业治理 | 专业版提供 RBAC、SSO 与操作日志；多租户与集群明确放在企业版 | 商业版提供 ABAC + RBAC、SSO、多租户与管理后台；高级云套餐公开 720 天团队操作日志 |
| 部署与渠道 | Docker、离线部署、Web / API 与国内 IM，形态更接近标准私有化产品 | Docker Compose、多向量后端，同时提供 Cloud、社区自托管与商业交付 |

> **验收条件**：企业治理固定组织、部门、群组、资源、日志保留时长和操作类型的权限用例；多租户与集群版本进入 POC 记录。

### 2.3 MaxKB 的优势场景

- **国内私有化交付形式简明**：离线安装路径、授权形态、次年维保与原厂支持档位均在官网公开。
- **采购可预测性**：一次性授权和公开支持档位便于预算审批，维保、实施、模型与硬件进入三年 TCO。
- **数据库查询工具的产品可见性**：官方文档明确列出数据库查询工具；FastGPT 的通用路径主要是 HTTP API 与工具封装，更开放但需多一层集成。
- **支持档位公开**：专业版 5×8、企业版 7×24 的口径对采购者更直观；具体响应与恢复目标仍需以合同为准。

## 3. 采购边界：许可证、买断与支持档位

### 3.1 两侧的公开边界

| 项 | MaxKB | FastGPT |
|---|---|---|
| 产品路径 | 社区自托管 + 专业版 / 企业版 | Cloud + 社区自托管 + 托管 / 自托管商业版 |
| 开源许可 | GPLv3；X-Pack 的商业边界需另行确认 | FastGPT Open Source License：允许作为其他应用的后端服务商用、允许作为应用开发平台交付给企业；未获书面授权不得用源码运营同类多租户 SaaS，不得移除或修改控制台内的 LOGO 与版权信息 |
| 自托管基础设施公开下限 | 至少 4 核 / 8GB / 100GB | 未固化统一最低 CPU / 内存，按向量库、文档量、模型与并发设计 |
| 部署方式 | Docker；企业版支持集群 | Docker Compose，支持多种向量后端；Kubernetes 商业交付边界需确认 |
| 私有 / 离线 | 社区版可离线自部署；专业版与企业版有原厂支持 | 商业版可私有化并完全离线 |
| 采购形态 | 专业版一次性永久授权 + 次年维保；企业版询价 | Cloud 分免费与两档月度订阅；托管商业版按月起价；私有部署按单台服务器 License，分标准 / 专业 / 旗舰三版本 |
| 原厂支持档位 | 专业版 5×8、企业版 7×24；可用性、RTO / RPO 需合同确认 | 分四个档位，覆盖时段从工作日逐档扩到 7×24，首次响应目标按档位递进；所有付费档位含安全补丁、新功能支持与远程线上协助，付费档起有专属支持群、最高档增加客户经理；私有部署交付范围可含安装部署、调试与原厂技术维保；具体可用性与恢复指标需合同确认 |

GPLv3 与 FastGPT Open Source License 的约束方向不同：分发、衍生作品、多租户 SaaS 运营和去品牌边界分别进入法务清单。X-Pack 的商业边界需要书面确认。

企业内部使用与对外交付分别列出二次开发归属、分发义务、去品牌权限和多客户服务方式，再按实际交付路径核对每份 LICENSE。

授权价、维保比例、订阅价与套餐边界采用两侧当日书面报价，含税口径、授权期限与实施维保范围同步记录。

采购清单要求责任矩阵、故障分级、恢复目标与升级回滚责任方。首次响应目标与修复时限分开记录；买断形态额外确认次年起的维保是否维持同档服务时间，最终承诺以合同为准。

### 3.2 买断与订阅的三年 TCO

买断与订阅按同一三年规模比较，成本表同时记录许可、维保、硬件、模型、实施、集群、升级、二次开发和风险准备金：

| 成本项 | 说明 |
|---|---|
| 许可 / 订阅 | 买断侧是首年授权，订阅侧是三年订阅费；两边填各自官方当日实价 |
| 次年及第三年维保 | 买断侧的关键变量，必须计入第二、第三年 |
| 硬件 | 按最低资源要求换算实际服务器或云主机成本，含存储与备份 |
| 模型消耗 | 向量化与生成，按真实问答量估算，两边用同一假设 |
| 实施 | 部署、调试、知识库建设、权限配置的人天 |
| 集群 | 是否需要多节点，多节点是否需要额外授权 |
| 升级 | 三年内的版本升级路径与是否额外收费 |
| 功能二次开发 | 缺失能力自行补齐的人天，含长期维护 |
| 风险成本 | 版本边界不匹配、迁移成本、评审不通过的返工 |

**产出是一张三年 TCO 表**，并对成员数、文档量、请求量与双节点需求做灵敏度分析。

订阅与买断的结论以同口径三年表为准，规模、增长假设和内部预算方式同步记录。

## 4. POC 验证：把三年成本和故障演练放一起

除统一 POC 测量表外，补充三组用例，覆盖沙箱、人工恢复和配额成本：

| 补测项 | 具体做法 | 判据 |
|---|---|---|
| **沙箱与工具安全** | 在工具节点里执行一段试图访问外网与读写本地文件的代码；再试一次越权与密钥读取 | 是否被隔离拦截；失败是否影响主进程；审计里是否留痕 |
| **流程中的人工确认** | 设计一个中途需要人工填多字段表单再继续的流程，且这个节点位于子应用或循环内部 | 暂停后能否原地恢复并保留状态，还是必须从头重跑 |
| **配额与成本可解释性** | 发一个分享链接并设置额度与有效期，跑一批问答后查成本 | 额度与 QPM 是否生效；成本能否拆到解析、向量化、检索、生成各阶段 |

完整的统一 POC 测量表：

| 类别 | 必测指标 | 统一条件 | 证据产物 |
|---|---|---|---|
| RAG 效果 | Recall@K、MRR / NDCG、引用正确率、幻觉率、无答案拒答率 | 同一黄金问题集、Embedding、ReRank、LLM、TopK | 可重放测试集 + 逐题结果 |
| 复杂文档 | 表格 / 标题 / 页码 / 图片保真率，解析成功率，每 100 页时间与成本 | 同一批扫描件、合同、研报、PPTX、XLSX | 原文与解析结果 diff + 人工抽检 |
| 在线性能 | P50 / P95 / P99 延迟、成功率、每秒请求、峰值并发 | 同一模型端点、向量库、机型、数据量与预热方式 | 压测脚本、原始报告、资源曲线 |
| 可靠性 | 节点失败恢复、重试幂等、队列积压、升级回滚、备份恢复 | 同一故障注入脚本与数据规模 | 故障时间线、丢数 / 重复记录、恢复时长 |
| 安全与治理 | 越权、SSRF、密钥泄漏、沙箱逃逸、租户隔离、审计覆盖 | 同一威胁用例与权限矩阵 | 用例结果、审计记录、整改项 |
| 三年 TCO | 见 3.2 | 统一三年业务增长假设 | 三年现金流 + 人天 + 风险准备金 |

以下指标进入「未公开 / 待 POC / 待合同」清单：稳态与峰值并发、每秒请求数、每分钟 Token 吞吐、指定硬件下的解析与检索延迟、最大应用数与租户数、可用性 SLA 与 RTO / RPO、模板与插件实时总数。

## 5. 选型建议：按预算口径与交付责任

| 项目的第一约束 | 建议 |
|---|---|
| 预算需要一次报清、内部审批偏好一次性授权 | **MaxKB 会直接进入比价**，并用 3.2 的三年表核算 |
| 离线安装路径与支持档位需要在采购前就明确 | MaxKB 的公开形态更直观 |
| 需要现成的数据库查询工具且不希望多一层集成 | MaxKB 的产品可见性更高 |
| 工具节点要执行代码，且需通过安全评审 | 隔离沙箱是可验证差异点，FastGPT 公开资料明确 |
| 业务流程中间必须有人工确认，且节点在子流程或循环内 | 人工暂停与原地恢复决定这类场景能否落地 |
| 需要控制分享链接与 API 的调用量、按环节看成本 | 统一配额与成本拆分是可验证差异点 |
| 图表、截图里的信息需要被检索到 | 图片向量与多索引检索是可验证差异点 |
| 需要先低成本验证、再迁到私有环境 | FastGPT 的 Cloud 到私有化路径完整 |

安全、可靠性和准确率采用统一 POC 与合同验收确认，未覆盖的控制项进入补测清单。
