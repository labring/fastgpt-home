# Domain Docs

This repo uses a single-context layout.

## Before exploring

- Read `CONTEXT.md` at the repo root.
- Read relevant decisions in `docs/adr/`.
- Use glossary terms from `CONTEXT.md` in issue titles, specs, and implementation notes.

## File structure

- `CONTEXT.md` contains shared domain vocabulary.
- `docs/adr/` contains repository-wide architectural decisions.
- `docs/agents/` contains engineering-skill configuration.

When a required domain term is missing, record the gap for domain modeling. Surface conflicts with existing ADRs before making a new decision.
