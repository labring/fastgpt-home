# Antibody-Drug Conjugate (ADC) Clinical Trial Pre-screening: HTTP Interface and External Systems

## Data Characteristics

Antibody-Drug Conjugate (ADC) clinical trial pre-screening data originates from global clinical trial registries (e.g., ClinicalTrials.gov, EMA Clinical Trials Register), internal drug development databases, and a limited number of public academic papers and conference abstracts. Data update frequencies vary. Registries typically update weekly or monthly, while internal databases may change in real-time. ADC data often has a complex document structure. It includes PDF-formatted trial protocols, investigator brochures, patient informed consent forms, and structured database records. Structured data typically includes fields such as `NCT ID` (National Clinical Trial Identifier), `drug_name`, `target_antigen`, `payload`, `linker`, `indication`, `trial_phase`, and `eligibility_criteria`. The `eligibility_criteria` field is particularly complex. It often uses unstructured text to describe dozens of inclusion/exclusion criteria. These criteria involve patient biomarker expression (e.g., `HER2+`), organ function (e.g., `CrCl > 30 mL/min`), prior treatment history, and comorbidities. Common dose units are `mg/kg` or `mg`. Time units are `days`, `weeks`, and `months`.

## Constraints Imposed by Data Characteristics on HTTP Interfaces and External Systems

The complexity of ADC clinical trial pre-screening data imposes specific constraints on HTTP interfaces and external system integration. The unstructured text in the `eligibility_criteria` field requires interfaces to process long texts and extract key information. This may involve using natural language processing services for text pre-processing or initial structuring during upload. The presence of binary document formats like PDF means interfaces must support file upload and download. Integration with external OCR or document parsing services may be necessary to convert document content into searchable text. Inconsistent data update frequencies require systems to support scheduled tasks for interface calls to periodically synchronize the latest trial information. Special characters (e.g., `+`, `+/-` in target names) and units (`mg/kg`, `mL/min`) in fields require interfaces to correctly encode and identify them during data transfer and parsing. This prevents data loss or parsing errors. Additionally, due to the large volume of data and sensitive information, HTTP interfaces must have high concurrent processing capabilities and strict access control.

## Configuration Guidelines

| Configuration Item           | Recommended Value                               | Rationale                                                    |
| :--------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `50 MB`                                         | ADC clinical trial protocol PDFs are often large; this size covers most cases. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds`                                        | Parsing complex PDF documents, especially OCR, is time-consuming. |
| `maxContext`                 | `4000 characters`                                     | Ensures full transmission and processing of long text fields like `eligibility_criteria`. |
| `Chunk size`                   | `800–1000 characters`                                 | For long text inclusion criteria, ensures each segment contains sufficient semantic information. |
| `Recall count`                   | `Top 10 entries`                                      | Recalls more potentially relevant trials initially, improving pre-screening accuracy. |
| `Similarity threshold`                 | Calibrated by actual measurements, around `0.75` recommended | Balances pre-screening recall and precision, avoiding critical information omissions. |

## Common Pitfalls

*   Uploading ADC trial protocol names containing special characters to the knowledge base returns `400 Bad Request`. This occurs when the filename or content is not URL-encoded or JSON-escaped.
*   When retrieving ADC trial eligibility criteria via API, the `eligibility_criteria` field is empty or truncated. This happens when the interface does not correctly handle long text field transmission limits or encoding issues.
*   Frequent `504 Gateway Timeout` errors occur when calling external systems to synchronize trial data. This is due to the external system processing an excessive amount of data or network latency, leading to slow responses.

## Verification Steps

*   Successfully upload and download an ADC clinical trial PDF document with complex eligibility criteria via HTTP interface. This verifies file transfer and parsing integrity.
*   Call the API to retrieve the `eligibility_criteria` field for a specific ADC trial. Compare it with the original data source to confirm content completeness, no truncation, and no garbled characters.
*   Simulate high-concurrency requests or scheduled task-triggered API calls. Observe system response times and error logs to ensure stable operation under expected load.
