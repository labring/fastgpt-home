# CRO Product Forms and Interactions

## CRO Product Data Characteristics

CRO (Contract Research Organization) product data is highly specialized and structured. Data sources include clinical trial protocols, case report forms (CRFs), laboratory test results, biological sample information, drug batch records, and regulatory approval documents. This data updates frequently, especially during clinical trials, requiring strong real-time capabilities. Document structures are complex, often involving multiple standard data formats like CDISC (Clinical Data Interchange Standards Consortium) standards, specifically SDTM (Study Data Tabulation Model) and ADaM (Analysis Data Model). Fields and units are extremely precise. For example, dosages are in milligrams (mg) or micrograms (µg), time points in hours (h), days (d), or weeks (w), and biological indicators use specific international units (IU) or concentration units (e.g., ng/mL). Data exhibits strong internal logical relationships and must strictly adhere to medical ethics and regulatory requirements.

## Constraints from Data Characteristics on Forms and Interactions

The specialized and structured nature of CRO product data imposes multiple constraints on form and interaction design. High update frequency demands forms support real-time data entry and querying, along with version control capabilities to track data change history. Complex document structures and standard data formats mean form fields must precisely map to standards like CDISC, preventing data ambiguity. The strictness of fields and units requires form input fields to have rigorous data validation mechanisms, such as limits on number ranges, unit selection, and formats, to prevent entry errors. Strong internal data relationships necessitate forms support linked logic, such as automatically populating manufacturing dates based on drug batches, or querying a subject's medical history based on their ID. Simultaneously, regulatory compliance requires forms to embed informed consent and privacy protection statements during data collection, ensuring all operations are auditable.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `maxContext` | `2000 characters` | Accommodates the typically lengthy CRO product descriptions, which include technical details and experimental methods. |
| `Chunk size` (Segment Length) | `500 characters` | Ensures knowledge base segments can contain complete experimental procedures or reagent instructions. |
| `Recall count` (Recall Count) | `8 items` | Increases the coverage of relevant information retrieved from vast CRO documentation. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | Guarantees high relevance of recalled results to user queries involving biomedical terminology. |
| `WORKFLOW_MAX_RUN_TIMES` | `500` | Addresses the potential for multiple rounds of data querying and logical judgments in CRO consultations. |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | Allows uploading large clinical trial reports, SOPs, or product specifications. |

## Common Pitfalls

*   After form submission, some critical fields are empty because mandatory validation was not set during field configuration or default value variable referencing failed.
*   When users use voice input on a non-logged-in page, occasional delays or un-displayed input content occur. This is due to voice recognition service response timeouts or incorrect handling of asynchronous callbacks in the frontend interaction logic.
*   Incorrect units for certain biological indicators in query results occur because unit standardization conversion was not performed during data import, or form validation rules did not cover all possible unit representations.

## Verification Steps

*   Simulate submitting various typical CRO product consultation forms in a real environment. Verify all mandatory fields correctly collect data, and data types and formats meet expectations.
*   Test CRO product query scenarios of varying complexity. Check the relevance of knowledge base recall results, ensuring recalled items accurately hit key technical parameters and experimental methods.
*   Perform upload and processing tests for CRO documents containing special characters, long text, or large files. Confirm the system stably parses and extracts core information without timeouts or parsing errors.

The values given are common starting points and should be measured against the reader's own samples.
