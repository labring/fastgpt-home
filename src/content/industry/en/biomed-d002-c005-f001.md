# HTTP Interface and External Systems for CSO Products

## Data Characteristics of CSO Products

CSO (Contract Sales Organization) product data primarily involves sales activities of medical representatives, customer relationship management, and drug distribution information. Data sources are diverse, including CRM systems, sales reports, pharmaceutical e-commerce platforms, and third-party market research reports. Update frequency depends on business processes; sales data typically updates daily or weekly, while inventory and logistics information may change in real-time. Document structures vary, with sales contracts, product specifications, and training materials often existing as PDFs, Word documents, or structured JSON/XML. Specific fields include `rep_id` (representative ID), `territory_code` (territory code), `product_sku` (product SKU), `sales_volume` (sales volume), and `target_physician_id` (target physician ID). Units include `boxes`, `tablets`, `milligrams`, `yuan`, and `percentage`. Unit conversion rules may differ across products or sales regions.

## Constraints Imposed by These Characteristics on "HTTP Interface and External Systems"

The complexity of CSO product data sources requires highly flexible HTTP interfaces capable of integrating with various data formats. The high update frequency of sales data necessitates incremental synchronization mechanisms in interface design to avoid resource waste and response delays from full data pulls. The presence of different document formats demands robust parsing capabilities from external systems, requiring preprocessing support for unstructured documents like PDFs and DOCX, and the extraction of key entity information. Specific fields such as `product_sku` and `target_physician_id` imply the need for precise field matching and type conversion during data mapping and querying, especially for ensuring data consistency in cross-system integration. The diversity of units and conversion rules requires standardization before data transmission and display to prevent misinterpretation or calculation errors due to inconsistent units.

## Configuration Guidelines

| Configuration Item | Suggested Value | Rationale for this Value |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 seconds` | Accommodates slow external system responses or large data transfers, preventing timeout interruptions. |
| `MAX_BODY_SIZE_MB` | `20 MB` | Supports large request or response bodies, including images and complex reports. |
| `API_KEY_HEADER_NAME` | `X-CSO-Auth` | Follows industry conventions for transmitting authentication credentials using a custom header field. |
| `DATA_SYNC_FREQUENCY_CRON` | `0 0 */1 * *` | Synchronizes core sales data daily at midnight, balancing data timeliness with system load. |
| `JSON_SCHEMA_VALIDATION_ENABLED` | `true` | Ensures incoming CSO data conforms to the expected structure, preventing dirty data from affecting subsequent processing. |
| `RETRY_STRATEGY` | `Exponential Backoff, Max 5 Retries` | Addresses intermittent external system failures, enhancing data transfer stability. |

## Three Common Pitfalls

*   Frequent `401 Unauthorized` errors from API calls occur when the `API_KEY` is incorrectly configured or expired, or when the authentication information in the request header does not meet the external system's requirements.
*   A workflow uploading a file via API results in a `File Parsing Failed` error. This happens if the file type is not supported by the external system, or if the file's content encoding does not match expectations.
*   Discrepancies between sales volume data pulled from an external system and business reports arise when the `sales_volume` field has inconsistent units across different systems, and necessary unit conversions are not performed.

## How to Verify Configuration

*   Simulate API requests using `curl` or Postman to check if product information for a specified `product_sku` can be successfully retrieved. Verify that the returned `sales_volume` field value and unit are correct.
*   Configure a workflow that includes a file upload step. After execution, check if the external system correctly receives and parses the uploaded sales contract PDF file, and if key information like `contract_id` can be extracted.
*   Set up a scheduled synchronization task in FastGPT. Monitor task logs to confirm that API calls complete within `HTTP_REQUEST_TIMEOUT_SECONDS` and that data updates at the frequency set by `DATA_SYNC_FREQUENCY_CRON`.
