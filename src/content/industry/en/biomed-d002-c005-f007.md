# Workflow Orchestration for CSO Products

## Data Characteristics for this Category

CSO (Contract Sales Organization) product data originates from pharmaceutical companies and CRO (Contract Research Organization) firms. Sources include product manuals, clinical trial reports, market analysis reports, and sales data. This data updates frequently, especially with new drug launches, expanded indications, or market strategy adjustments. Document structures typically detail product ingredients, mechanisms of action, indications, contraindications, dosage and administration, adverse reactions, and pharmacokinetics. Field types are diverse, covering text descriptions, numerical values (e.g., dosage units `mg`, `ml`), dates (e.g., launch date `YYYY-MM-DD`), and enumerations (e.g., dosage forms `tablets Agent`, `Injection Solution`). The data often contains specialized terminology and abbreviations. Inconsistencies in units or expressions may exist across different data sources.

## Constraints Imposed by these Characteristics on Workflow Orchestration

High update frequency for CSO product data requires workflows to quickly respond and update the knowledge base. This prevents the provision of outdated information. The presence of specialized terminology and abbreviations in documents challenges text understanding and entity recognition. This necessitates more refined preprocessing steps. Inconsistent units and varied expressions across multiple data sources require integrating data cleaning and standardization modules into the workflow. For example, all dosage units might be unified to `mg` or `g`. Diverse field types mean the workflow must support parsing and processing different data formats, such as extracting structured information from unstructured text. Information concerning drug safety and efficacy demands high accuracy. The workflow's retrieval and generation stages require strict control to reduce error rates and avoid misleading advice. Workflow stability and traceability are also critical for processing this data.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `maxContext`       | `4096`            | CSO product manuals are often lengthy. A larger context window is needed to capture the full product scope and details, preventing information truncation. |
| `Chunk size`         | `500–800 characters`    | Each segment must contain sufficient product information. This avoids semantic dispersion caused by excessive length and improves retrieval accuracy. |
| `Recall count`         | `Top 8–12 entries`      | CSO product inquiries often require comprehensive information. Increasing the number of retrieved items improves coverage of relevant information and reduces the risk of missing key points. |
| `Similarity threshold`       | `0.75–0.85`       | This ensures retrieved results are highly relevant to the user query. It filters out low-quality or inaccurate product information. |
| `Rerank result count`     | `Top 5 entries`         | Based on a high number of retrieved items, re-ranking selects the most relevant few. This improves the accuracy and conciseness presented to the user and reduces the model's processing burden. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds`          | CSO product documents, especially clinical reports in PDF format, can take a long time to process. Extending the timeout prevents parsing failures. |

## Three Common Mistakes

*   A "Cannot read properties of undefined" error during workflow execution typically indicates improper data transfer between components. This causes a downstream component to attempt accessing an undefined or empty variable property.
*   An input error when clicking after a plugin reference runs code may stem from a mismatch between the plugin's input parameter format and the subsequent code component's expected input format. Alternatively, unhandled runtime errors might exist in the code logic.
*   Subsequent components failing to retrieve updated values after setting a global variable often results from improper variable scope configuration. Another cause is variable update operations occurring before subsequent components read them, without correct workflow execution order synchronization.

## Verifying Correct Configuration

*   Add debug outputs at critical workflow nodes. Check intermediate variables and component outputs to ensure data format, field names, and values meet expectations.
*   Conduct end-to-end testing using a series of CSO product inquiry questions covering typical and edge cases. Compare model answers against standard answers. Evaluate the accuracy, completeness, and professionalism of responses, especially for sensitive information like dosages and contraindications.
*   Check the knowledge base update logs. Confirm that indexes are updated promptly after new product data uploads. Verify that the updated data can be correctly retrieved and utilized by the workflow.
*   Monitor workflow execution logs for anomalies such as timeouts, memory overflows, or data parsing failures. This ensures workflow stability and reasonable resource consumption.
