# Tool Calling and Plugins for IVD Diagnostic Reagents

## Data Characteristics

IVD diagnostic reagent product data comes from various sources. These include official registration documents, product manuals, technical white papers, clinical performance evaluation reports, and marketing materials. Data update frequencies vary. New product launches, batch updates, or regulatory changes can trigger data modifications. Document structures are typically highly standardized. They contain fields such as product name, registration number, manufacturer, scope of application, detection principle, intended use, main components, storage conditions, shelf life, testing methods, result interpretation, and limitations. `Registration_Number`, `Batch_Number`, and `Expiration_Date` are core identifiers. Units for reagent concentration are typically `mol/L` or `mg/mL`. Detection limits are expressed as `IU/mL` or `ng/mL`. Temperature uses `℃` or `K`, and time uses `min`, `h`, or `day`.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins

The highly structured and standardized nature of IVD diagnostic reagent data provides clear references for parameter parsing and result mapping during tool calls. For example, a registration number enables precise retrieval of detailed information for a specific product. Irregular data updates, especially for batch information and expiration dates, require tool calling mechanisms to support real-time or near real-time data queries. This prevents the use of outdated information. The extensive specialized terminology and units in documents require plugins to accurately understand natural language queries. They must map these queries to corresponding fields and values. For instance, "storage temperature" should map to the `Storage_Temperature` field. Furthermore, due to the strictness of medical devices, any query for product information must ensure accuracy and traceability. This demands high reliability in data source selection and error handling for tool calling.

## Common Pitfalls

*   When calling external HTTP services, even if parameters are parsed correctly, execution may fail due to a `Content-Type` mismatch in the request header or an expired `Authorization` token, leading to an unresponsive service.
*   For multimodal image recognition, if the `base64` string is too long or incorrectly formatted when calling the interface via `base64` encoding, it may result in a `413 Payload Too Large` error or decoding failure.
*   An HTTP plugin configured with a proxy may encounter connection timeouts or handshake failures when accessing `HTTPS` target resources if the proxy server does not support the `HTTPS` protocol.

## Verification Steps

*   Query common IVD diagnostic reagent product names and registration numbers. Verify that the returned product name, manufacturer, and scope of application match official data.
*   Attempt to query reagents including batch numbers and expiration dates. Check if tool calling accurately returns real-time or the latest batch information and verifies the expiration date.
*   Simulate a user asking about "the storage temperature of a certain reagent." Confirm that the tool correctly parses the intent and returns the `Storage_Temperature` field's value and unit via tool calling.
*   Check tool call logs. Ensure HTTP request status codes are `200` and that key fields like `Registration_Number` or `Batch_Number` are correctly passed in the request.
