# Knowledge Base Retrieval for IVD Diagnostic Reagents

## Data Characteristics

IVD diagnostic reagent data originates from product manuals, registration certificates, clinical trial reports, methodology documents, quality standards, operating procedures, and frequently asked questions (FAQs). These documents are typically in PDF, Word, or structured database formats. Data updates occur when new products launch, regulations change, manuals revise, batches update, or clinical validation data supplements. Update cycles range from weeks to months. Product manuals typically include sections like product name, intended use, main components, storage conditions, shelf life, testing methods, result interpretation, precautions, and limitations. Fields and units are highly standardized, such as detection indicator names, concentration units (e.g., `ng/mL`, `IU/L`), temperature ranges (e.g., `2-8°C`), batch numbers, and expiry dates (format `YYYY-MM-DD`). Specific medical terminology and abbreviations are common.

## Constraints on Knowledge Base Retrieval and Recall

The highly structured and specialized nature of IVD diagnostic reagent data requires precise matching of professional terminology and numerical ranges during knowledge base retrieval. Generic recall is not acceptable. Key information from product manuals, such as intended use and storage conditions, must be fully identified and associated to support accurate product inquiries. The uncertain update frequency means the knowledge base needs to support incremental updates and version management, ensuring recalled data is current. The large number of numerical fields and units means simple keyword matching is insufficient; semantic understanding and entity recognition capabilities are necessary. For example, when a user queries "storage temperature for reagent X," the system must accurately extract specific values and units like `2-8°C` from the text. Additionally, common question-answer pairs in FAQs should be high-priority recall content to improve user satisfaction.

## Configuration Guidelines

| Configuration Item         | Recommended Value          | Rationale                                                                                                       |
| :------------------------- | :------------------------- | :-------------------------------------------------------------------------------------------------------------- |
| `Chunk size` (Segment Length) | `800-1200 characters` (characters) | Ensures a complete product feature or operating step description is included.                                   |
| `Chunk Overlap Length` (Overlap Length) | `100 characters` (characters)    | Maintains semantic coherence and prevents critical information from being truncated.                            |
| `Recall count` (Recall Count)  | `5-8 entries` (items)           | Covers potential answers from different angles, improving recall accuracy.                                      |
| `Similarity threshold` (Similarity Threshold) | Calibrate based on actual measurements | Balances recall rate and precision, ensuring highly relevant recall results.                                    |
| `Rerank result count` (Rerank Return Count) | `3 entries` (items)             | Prioritizes the display of the most relevant core information.                                                  |
| `Max Context Length` | `3000-4000 characters` (characters) | Accommodates the detailed descriptions in IVD reagent manuals, ensuring completeness.                           |

## Common Mistakes

*   Retrieval results contain a large amount of irrelevant general medical information. This occurs when knowledge base segmentation granularity is too coarse or the similarity threshold is set too low, leading to the recall of general medical knowledge not specific to IVD products.
*   A user asks "reagent kit expiry date," but the recall results lack specific date information. This occurs when the knowledge base processing fails to effectively identify and extract date fields in `YYYY-MM-DD` format.
*   Knowledge base search tests yield abnormally high scores (e.g., over 4000 points). This occurs when the system's internal similarity calculation logic uses a non-standardized distance metric, not a normalized score within the `0-1` range.

## How to Verify Configuration

*   Simulate user queries for typical product inquiries. Check if recall results include correct product names, intended uses, storage conditions, and other key information. Evaluate the relevance of recalled items.
*   Select sentences from product manuals that contain clear numerical values and units (e.g., `ng/mL`, `2-8°C`). Use these as test queries. Observe if the original segments containing these values are accurately recalled.
*   Check recently updated product documents in the knowledge base. Confirm their content appears in retrieval results, for example, by querying product characteristics of a newly launched reagent.
*   Use queries containing specific batch numbers or registration certificate numbers. Verify the system can precisely locate the corresponding sections of the relevant documents.

The values provided are common starting points and should be measured against your own samples.
