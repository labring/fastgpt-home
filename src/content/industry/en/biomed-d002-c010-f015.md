# Deployment and Upgrade for IVD Diagnostic Reagents

## Data Characteristics

IVD diagnostic reagent product data sources include product manuals, registration certificates, batch reports, clinical validation reports, operating instructions, and FAQs. These documents are typically in PDF, DOCX, or plain text formats. Data update frequency is stable; new products or updated registration information for existing products trigger concentrated updates, usually quarterly or semi-annually.

Document structure: Manuals often contain fields like product name, catalog number, batch number, production date, expiration date, intended use, detection principle, main components, storage conditions, operating procedures, result interpretation, limitations, and precautions. Clinical validation reports include detailed sample information, statistical data, and charts. Field content frequently involves biological indicator names, concentration units (e.g., `mmol/L`, `ng/mL`), temperature (`℃`), and time (`min`). Numerical precision and unit consistency are critical.

## Constraints on Deployment and Upgrade

The highly structured nature of IVD diagnostic reagent data, along with strict precision and unit requirements, imposes specific constraints on knowledge base construction during deployment and upgrade.

First, a high-performance document parsing capability is essential for numerous PDF manuals and reports. This ensures accurate extraction of text information from tables and images, especially critical fields like batch numbers and expiration dates.

Second, concentrated periodic data updates necessitate support for bulk import and incremental updates. The system must identify and handle differences between various manual versions during updates to prevent information conflicts or redundancy.

Precise identification of biological indicators and units requires the semantic understanding model to possess domain-specific knowledge. This prevents unit confusion or numerical misinterpretation during Q&A.

Finally, managing product batches and expiration dates requires the system to process time-series data and perform expiration date checks during queries. This ensures that the provided information is current and valid.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | IVD manuals and reports may contain many charts, leading to large file sizes. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Parsing large PDF files can be time-consuming; sufficient time is needed to avoid timeouts. |
| `Chunk size` | `800–1200 characters` | Ensures complete semantic units for IVD product operating procedures or principle descriptions are not truncated. |
| `Recall count` | `Top 5 entries` | Guarantees coverage of key information from multiple relevant products or batches in complex Q&A. |
| `Similarity threshold` | Calibrate by measurement | Adjust through testing based on IVD domain terminology similarity to balance recall and accuracy. |
| `Rerank result count` | `Top 3 entries` | Ensures the most relevant and authoritative IVD product information is prioritized. |

## Common Pitfalls

*   Workflow code execution component errors, even with simple logic. This usually indicates missing essential dependency libraries or incorrect `Python` runtime configuration in the local deployment environment, preventing `FastGPT` from correctly calling the interpreter.
*   After uploading the latest batch report for an IVD product, query results still display old batch information. This often occurs because the knowledge base lacks an incremental update strategy or the update task failed, leading to new data not being indexed.
*   When users inquire about product expiration dates, the system returns inconsistent date formats or garbled characters. This may be due to the document parser inaccurately recognizing different date field formats or the knowledge base not standardizing date fields during storage.

## Verification Steps

*   Upload at least 5 IVD product manuals and reports in different formats (PDF, DOCX). Check if all key fields (e.g., product name, batch number, expiration date, detection principle) are accurately extracted and searchable.
*   Simulate user questions about the intended use, operating procedures, and precautions of a specific IVD diagnostic reagent. Verify that the system returns accurate and complete information, with correct units and numerical values.
*   Upload a manual containing a new batch or updated information. Then, query for relevant information about that product. Confirm that the system prioritizes the latest version of the data and identifies the outdated status of older version information.
