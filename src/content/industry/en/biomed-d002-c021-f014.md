# Forms and Interactions for Supplier Audit Products

## Data Characteristics

Supplier audit data in the biopharmaceutical industry primarily comes from audit reports, quality system documents, production licenses, inspection reports, and various compliance declarations. This data is typically in PDF format, with some structured Excel spreadsheets or database records. Core audit reports are updated periodically, such as annually or biennially. Supplementary materials, like defect corrective actions and production changes, are updated more frequently, possibly monthly or even weekly. Document structures generally follow ISO, GMP, or FDA standards, including clear section titles and numbers, such as "On-site Inspection Findings" and "Deviation Records." When specific production parameters are involved, fields like "Temperature (°C)," "Pressure (MPa)," "Batch Number," and "Production Date" are included. Data accuracy and unit consistency are critical.

## Constraints on Forms and Interactions

The varying levels of documentation and structured data in supplier audits require refined form design. Extensive unstructured PDF documents necessitate efficient document upload and parsing support. Form interactions should guide users to clearly specify document types, for example, distinguishing between "Audit Report Main Body" and "Defect Improvement Plan." Periodic updates require forms to include version management, linking audit materials from different time points and clearly displaying their update status. Compliance requirements demand highly standardized form fields. For instance, input for critical information like batch numbers and expiration dates should offer preset formats or validation rules to prevent errors. Sensitive information, such as trade secrets or personal privacy, requires permission control and anonymization prompts in interaction design to ensure information security and prevent leaks during data processing or display.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------- |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | Audit reports often contain many images and charts, resulting in large file sizes. Sufficient upload limits are necessary. |
| `maxContext` | `3000 Tokens` | Audit reports are detailed, requiring a large context window to understand overall audit findings and conclusions. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Parsing large PDF documents is time-consuming, requiring a longer timeout to prevent parsing interruptions. |
| `Chunk size` | `800 characters` | Ensures each knowledge chunk contains sufficient information, preserving the context of audit findings. |
| `Similarity threshold` | `0.78` | Audit inquiries demand high accuracy, requiring a high similarity threshold to recall the most relevant audit clauses or findings. |
| `Rerank result count` | `Top 5 entries` | Prioritizes displaying highly relevant re-ranked results, improving engineer decision-making efficiency. |

## Common Pitfalls

*   Missing critical audit clauses or report numbers in query results. This occurs when the `Similarity threshold` is set too high, filtering out relevant but not perfectly matching paragraphs and failing to recall necessary information.
*   "File parsing failed" or "Request timeout" errors when uploading large audit report files. This usually happens when `PARSE_FILE_TIMEOUT_SECONDS` or `UPLOAD_FILE_MAX_SIZE` parameters are set too low, failing to accommodate the complexity and large file sizes of biopharmaceutical audit reports.
*   Users cannot effectively distinguish between different versions of audit report content during interaction. This results from form designs lacking clear version identification fields or version linking mechanisms, leading to confusion between old data and the latest updates.

## Verification Steps

*   Upload a typical supplier audit report (e.g., a 50 MB PDF) containing multiple pages of charts and text. Observe if the file uploads and parses successfully, and check the status codes in the parsing logs.
*   Query specific audit findings or defect numbers from the report. Verify if the system accurately recalls the corresponding report sections and if the `similarity` score of the recalled results meets expectations.
*   Simulate a user submitting a form with an incorrect batch number or non-standard date. Confirm if the system triggers preset input validation rules and provides clear error messages.
