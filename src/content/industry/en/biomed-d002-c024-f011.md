# Document Parsing and Chunking for Health Management Products

## Data Characteristics in this Category

Health management products receive diverse data. Sources include user-uploaded health reports, PDF reports from medical examination centers, summarized data from smart wearables, and text records from health consultation services. Document update frequency varies: medical reports are typically periodic, while daily health monitoring data updates continuously. Structurally, medical reports often combine structured tables and unstructured descriptions, such as test results and doctor's advice. Consultation records are mostly free-form text. Fields and units involve common medical indicators like blood pressure (mmHg), blood sugar (mmol/L), heart rate (bpm), and basic physiological parameters such as weight (kg) and height (cm). Unit conversion and standardization are common requirements.

## Constraints Imposed by these Characteristics on "Document Parsing and Chunking"

The heterogeneous nature of health management product data requires document parsing tools to have robust multi-format processing capabilities. This is especially true for accurately identifying mixed table and text content within PDFs. The periodic updates of medical reports necessitate support for incremental parsing and version management to avoid duplicate processing and data redundancy. The mix of structured and unstructured information in documents challenges chunking strategies. These strategies must preserve table data integrity while extracting key health insights from free-form text. The specialized nature and diverse units of medical indicators mean that chunking must consider context to ensure correct association between values and units. This prevents semantic loss due to sentence breaks; for example, "blood sugar 5.6 mmol/L" should not be split into "blood sugar 5.6" and "mmol/L".

## Configuration Recommendations

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------- |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | Allows sufficient upload space, considering individual medical reports or health records may contain numerous images and detailed data. |
| `Chunk size` (Chunk Length) | `500–800 characters` (characters) | Balances the completeness of paragraphs in medical reports with the conversational coherence of consultation records, preventing truncation of critical information. |
| `Chunk Overlap Length` (Chunk Overlap Length) | `100 characters` (characters) | Ensures contextual continuity at chunk boundaries, helping the model understand medical terminology and advice that spans across segments. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` (seconds) | Provides ample time to process PDF documents that contain complex tables and multi-page scans, preventing parsing timeouts. |
| `PARSER_TYPE` | `marker` | For complex layouts and tables common in health reports, the `marker` parser offers superior structured extraction capabilities. |
| `SPLIT_BY_TITLE_ENABLED` | `true` | Utilizes explicit title structures in medical reports, such as "Check Results" (Test Results) and "Doctor's Advice" (Doctor's Advice), for logical chunking. |

## Three Common Pitfalls

*   Loss or corruption of some table content when parsing complex PDFs. This occurs due to the lack of a specialized parser for such documents' unique layouts or incorrect `PARSER_TYPE` configuration.
*   Numerical indicators and units in health reports are separated, leading to incorrect model understanding. This happens when `Chunk size` (chunk length) is too small, or the chunking logic fails to effectively recognize the strong association between numbers and units.
*   When calling the file parsing tool, the log shows `Error: File processing failed, status code 500`. This typically means `PARSE_FILE_TIMEOUT_SECONDS` is set too short, and large files cannot be processed within the specified time.

## How to Verify the Configuration

*   Upload a medical report PDF containing complex tables and multi-page content. Check if the parsed text fully retains table data and key descriptive text.
*   For a health consultation record containing numerical indicators (e.g., "blood pressure 120/80 mmHg"), verify that the chunking result keeps the numerical value and unit within the same chunk.
*   Upload a large file close to the `UPLOAD_FILE_MAX_SIZE` limit. Observe if the file uploads successfully, starts the parsing process, and completes within `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided are common starting points and should be measured against your own samples.
