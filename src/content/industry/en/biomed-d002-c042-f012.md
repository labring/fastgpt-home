# Model Integration and Configuration for Culture Media and Consumables

## Data Characteristics for This Category

Core data for culture media and consumables comes from product manuals, technical documents, Safety Data Sheets (SDS), batch reports, and supplier catalogs. This data typically exists as PDFs, Word documents, Excel spreadsheets, or structured database records. Data updates occur with new product releases, formula adjustments, or regulatory changes, usually on a quarterly or semi-annual basis. Document structures often include fixed fields like product name, catalog number, specifications, batch number, ingredient list, application range, storage conditions, expiration date, and quality control standards. Consumables data focuses on material, dimensions, sterility grade, and compatibility. Fields are primarily text descriptions, numerical values (e.g., pH, osmolarity), or enumeration types, with units such as `g/L`, `mol/L`, `℃`, and `mm`.

## Constraints from These Characteristics on Model Integration and Configuration

The semi-structured nature of product manuals and technical documents requires robust document parsing capabilities during model integration. This ensures accurate extraction of key information from complex layouts. The update frequency of batch reports and SDS documents necessitates support for incremental updates and version management in the knowledge base, ensuring information timeliness. Fields like ingredient lists and quality control standards contain extensive specialized terminology and specific numerical values. The model must understand the contextual semantics of these terms and handle unit-aware numerical comparisons and calculations. Different suppliers may use synonyms or varied expressions for similar products, requiring normalization during configuration. User queries might involve comparisons between multiple products or filtering by specific parameter ranges, demanding that the model effectively integrate multi-source information for recall and inference.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale                                      |
| :----------------- | :---------------- | :--------------------------------------------- |
| `Chunk size`         | `500 characters`        | Ensures sufficient context per segment, preventing critical information from being cut off. |
| `Chunk Overlap Length`     | `50 characters`         | Maintains contextual continuity, improving recall accuracy. |
| `Recall count`         | `Top 8 entries`         | Covers most query needs, balancing recall quality and computational cost. |
| `Similarity threshold`       | `0.78`            | Filters out low-relevance results, enhancing answer precision. |
| `Rerank result count`     | `Top 3 entries`         | Focuses on the most relevant results, reducing the model's processing load. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds`          | Handles parsing of large PDF documents, preventing timeout failures. |

## Common Pitfalls

*   Incomplete ingredient lists or specification parameters in model responses: This occurs when document segmentation is too fine or the segmentation strategy is inappropriate, leading to critical information being split across different segments. The model then cannot obtain complete context.
*   Outdated responses from the model regarding product batch information or expiration dates: This happens when knowledge base data is not updated promptly, failing to synchronize with the latest batch reports or product revisions.
*   Incorrect results from the model when handling numerical range queries: This indicates that the model failed to correctly identify and parse unit-aware numerical values during training or inference, or lacks logical understanding for numerical comparisons.

## Validation of Configuration

*   Submit typical queries, such as "What is the pH range for [specific culture medium]?", and verify that the numerical values returned by the model match the product manual.
*   Enter queries involving newly released products to check if the model accurately identifies and provides the latest information. This assesses the timeliness of knowledge base updates.
*   Test complex questions that compare multiple product parameters. Observe if the model can extract and integrate relevant information from different product documents to form an answer.
*   Simulate a user asking "Does [specific consumable] support high-temperature sterilization?", and verify the accuracy of the model's answer against relevant technical documentation.
