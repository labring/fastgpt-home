# Forms and Interactions for Laboratory Services Products

## Data Characteristics for this Category

Data for laboratory services products in the biomedical field primarily comes from experimental protocols, technical agreements, instrument parameters, reagent batch information, quality control reports, and historical experimental results. This data typically exists in a mixed format of structured data (e.g., experimental parameters, numerical results in Excel, CSV) and unstructured data (e.g., experimental reports, SOP documents in Word, PDF). Data update frequency varies by service type. Basic reagent information may update monthly, while customized experimental protocols or new service launches update irregularly. Document structures are relatively fixed, usually including key fields such as project name, client information, experimental objective, methods, results, and conclusions. Fields and units are highly specialized, for example, `concentration (mM)`, `time (min)`, `OD value (AU)`, `gene expression fold change`. High precision and consistency requirements apply to this data.

## Constraints from "Forms and Interactions" Due to these Characteristics

The complexity and specialized nature of laboratory service data impose specific requirements on form design. First, the presence of numerous specialized terms and measurement units requires form input fields to offer precise unit selection or automatic validation to prevent user input errors. Second, the mixed nature of structured and unstructured data means forms must support basic inputs like text and numbers, and also provide file upload functionality for users to submit experimental protocols or historical reports. The uncertainty in data update frequency implies forms need to dynamically load the latest service options, reagent batches, or instrument models, and support version rollback. Furthermore, the need for service customization requires forms to have conditional logic. This logic dynamically adjusts subsequent fields based on the user's selected service type. For example, selecting "gene sequencing" should only then display fields like "sequencing depth" and "sequencing platform." High data precision requirements mean input validation rules must be sufficiently strict, for instance, setting reasonable numerical ranges for the `sample quantity` field.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `maxContext` | `2048 characters` | Accommodates descriptions for most experimental protocols while balancing model processing efficiency. |
| `Segment Length` | `400 characters` | Suitable for common paragraph structures in biomedical documents, maintaining semantic integrity. |
| `Recall Count` | `8 entries` | Covers enough relevant experimental parameters or reagent information, improving consultation accuracy. |
| `Similarity Threshold` | `0.75` | Filters out irrelevant experimental details, focusing on core issues and reducing noise. |
| `Form Field Validation Rules` | `Calibrated by actual measurement` | Sets numerical ranges, enumeration values, or regular expressions for specific fields like `sample quantity` and `test items`. |
| `File Upload Size Limit` | `20 MB` | Meets upload requirements for PDF/Word documents such as experimental reports and SOPs. |

## Three Common Mistakes

*   Key parameters are missing or formatted incorrectly in user-submitted experimental protocols. This prevents the system from understanding the user's intent, leading to generic responses. The reason is insufficient form input validation, which fails to enforce mandatory fields or specific input formats.
*   When users inquire about specific reagent batch information or inventory status, the system provides outdated or inaccurate responses. The reason is a lagging update mechanism for reagent data in the knowledge base, which is not synchronized with actual inventory or supplier information.
*   After users upload PDF experimental reports, the system fails to accurately extract information and answer questions about the report's content. The reason is poor OCR recognition for PDF documents or the document parser's inability to correctly extract key fields.

## How to Confirm Correct Configuration

*   Submit a mock form containing all mandatory fields with correct formatting. Observe if the system processes it correctly and generates the expected response.
*   Upload a multi-page PDF experimental report with tables and charts. Then, ask questions about specific data points in the report and check if the system answers accurately.
*   Simulate an inquiry about a service or reagent whose information was recently updated. Verify that the system returns the latest version of the information.
*   Select different service types in the form. Check if the subsequent fields displayed are logically consistent with the selected service.
