# Tool Calling and Plugins for Home Medical Products

## Data Characteristics for This Category

Home medical product data is multi-source and heterogeneous. Data typically originates from manufacturer official websites, product specifications, user manuals, and third-party e-commerce product detail pages. Data update frequency is relatively low, primarily occurring with new product releases, product iterations, or regulatory changes. Document structures are semi-structured, including product parameters, function descriptions, usage instructions, contraindications, and after-sales service. Common fields include product model, batch number, production date, expiration date, applicable population, measurement range, accuracy, and power supply type. Units encompass international standard units (e.g., millimeters, grams, Celsius, volts) and specific medical measurement units (e.g., millimeters of mercury, blood glucose units).

## Constraints Imposed by These Characteristics on "Tool Calling and Plugins"

The multi-source nature of home medical product data requires tool calling to flexibly adapt to different data interfaces, such as web scraping or API integration. Low data update frequency means historical data has high value, but also necessitates regular checks for new versions or revisions. The semi-structured document structure requires parsing to balance structured field extraction and unstructured text understanding. This may require more complex regular expressions or natural language processing capabilities. The presence of specific fields and units requires tools to correctly identify and perform unit conversions or validations. This prevents information misinterpretation due to unit confusion. For example, blood pressure monitor units and blood glucose meter units differ significantly; tools must accurately distinguish them.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `maxContext` | 4000 characters | Balances product specification completeness with model processing efficiency |
| `Chunk size` (Chunk Length) | 800 characters | Adapts to home medical product text paragraph logic, maintaining semantic integrity |
| `Recall count` (Recall Count) | 5 items | Balances recall breadth with model processing load, ensuring no core information is missed |
| `Similarity threshold` (Similarity Threshold) | Calibrated by actual measurement, e.g., 0.75 | High discriminative power, filters irrelevant content, avoids interference from low-relevance information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 seconds | Ensures sufficient time for parsing large PDF manuals |
| `tool_call_timeout` | 60 seconds | Handles slow external tool interface responses, prevents prolonged blocking |

## Three Common Mistakes

*   A `401 Unauthorized` error occurs when calling an external API. The API key is incorrectly configured or expired.
*   After uploading a product manual PDF, knowledge base retrieval results are empty. This manifests as `embedding` failure or zero `chunk` count. The file is too large or parsing timed out.
*   When querying specific product parameters, the returned result lacks key fields, such as "measurement range" for a blood pressure monitor or "calibration method" for a blood glucose meter. The tool function failed to correctly extract all necessary information from unstructured text.

## How to Confirm Correct Configuration

*   Upload typical product manuals (e.g., blood pressure monitor, thermometer). Check if `Chunk size` (Chunk Length) meets expectations and if each `chunk` has readable context.
*   Simulate user queries. Verify if tool calling accurately identifies question intent and invokes the correct external tool or plugin.
*   Query multiple product parameters. Cross-reference fields and units in the returned results with original data sources. Check for omissions.
*   Monitor tool call logs. Confirm successful external API calls and acceptable response times.
