# Model Integration and Configuration for Home Healthcare Products

## Data Characteristics for This Category

Home healthcare product data is diverse and dynamic. Product manuals, user guides, and frequently asked questions (FAQs) are primary data sources, typically in PDF, DOCX, or HTML formats. These documents contain detailed information, including product models, technical parameters, usage instructions, precautions, contraindications, and maintenance. Data update frequency depends on product lifecycles and regulatory changes, usually occurring with new product releases, product iterations, or regulatory updates. Document structures are relatively fixed, often with clear section headings and tables of contents. Fields include product name, model, serial number, batch number, production date, expiration date, and medical device registration number. Units cover physical quantities like voltage (V), current (A), power (W), dimensions (cm/mm), and weight (kg/g), as well as operational parameters like dosage (mg/ml), frequency (Hz), and time (min/s).

## Constraints Imposed by These Characteristics on Model Integration and Configuration

The detail in home healthcare product manuals requires the model to process long texts and accurately extract key information. Diverse document formats necessitate robust file parsing capabilities. Data dynamism from product iterations and regulatory updates requires the knowledge base to have efficient data update and version management mechanisms, ensuring the model always provides consultation based on the latest information. Documents contain numerous specialized terms and units of measurement; the model needs strong semantic understanding to avoid misinterpretation due to unit confusion. For example, different device models may share some general instructions, but key operational parameters have subtle differences, which the model needs to distinguish. Accurate identification of critical identifiers like medical device registration numbers directly impacts information credibility and compliance. Therefore, during model integration, close attention is required for text segmentation strategies, entity recognition capabilities, and knowledge update processes.

## Configuration Settings

| Configuration Item                 | Suggested Value       | Rationale                                          |
| :--------------------------------- | :-------------------- | :------------------------------------------------- |
| `Chunk size` (Segment Length)        | `800–1200 characters`       | Balances semantic integrity of long texts with model processing efficiency |
| `Recall count` (Recall Count)          | `Top 10 entries` (Top 10)   | Covers more potentially relevant information, improving recall rate |
| `Similarity threshold` (Similarity Threshold) | `0.75`                | Balances recall precision and generalization ability, avoiding irrelevant information interference |
| `Rerank result count` (Rerank Return Count) | `Top 3 entries` (Top 3)     | Focuses on the most relevant limited information, enhancing final answer accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS`       | `600 seconds` (600 seconds) | Ensures large PDF or DOCX files have sufficient time to parse |
| `maxContext`                       | `8192`                | Accommodates detailed manual content, providing longer context window support |

## Three Common Mistakes

*   When answering product parameters, the model sometimes confuses values for different models. This is typically due to overly large knowledge base segment granularity, preventing the model from distinguishing subtle differences between models.
*   When users ask for product registration numbers, the model fails to provide correct results. This happens because file parsing did not effectively identify and extract these specific text fields, or they were truncated during knowledge segmentation.
*   After a product update, the model still provides information based on the old version of the manual. This is typically due to the knowledge base not synchronizing with the latest data in a timely manner, or the update mechanism not correctly triggering index rebuilding.

## How to Verify Configuration

*   Select several representative home healthcare products. Ask questions about their core parameters, usage steps, and precautions. Check if the model's answers align with the latest official manual content.
*   Randomly select documents containing key identifiers such as registration numbers and batch numbers. Test if the model can accurately identify and output them as answers, then compare with the original documents.
*   Simulate a product update scenario: upload a new version of the manual and verify if the model can answer questions based on the new data, while also confirming that old information is no longer cited.
*   Ask the model questions about product contraindications or potential risks. Evaluate the accuracy and completeness of its answers, ensuring critical safety information is not omitted.
