# Document Parsing and Chunking for Rehabilitation Equipment Products

## Characteristics of Rehabilitation Equipment Data

Rehabilitation equipment data primarily originates from product manuals, technical handbooks, clinical application guidelines, maintenance manuals, and compliance certification documents. Manufacturers typically publish these documents. Updates are relatively infrequent, usually coinciding with new product releases, model upgrades, or regulatory changes. Documents feature complex structures, often including numerous charts, illustrations, and technical parameter tables. Fields frequently involve physical quantities such as dimensions, weight, power, voltage, and current, alongside descriptive information like materials, functional modes, target populations, and contraindications. Units primarily adhere to international standard units, but industry-specific or regional units, such as pounds or inches, may also appear.

## Constraints Imposed by Data Characteristics on Document Parsing and Chunking

The complex structure of rehabilitation equipment documents, particularly the intermingling of charts and parameter tables, requires parsers to effectively distinguish between text and non-text content. Low update frequency means knowledge bases are stable once parsed, but initial parsing accuracy is critical. The system must correctly identify and associate numerical values and units within technical parameter tables to prevent unit confusion or misinterpretation during question answering. The existence of multilingual document versions may necessitate multilingual processing capabilities. Furthermore, the integrity and accuracy of critical information, such as clinical application scenarios and contraindications, directly impact the reliability of consultation results. Therefore, chunking must ensure that logically related segments remain intact.

## Configuration Settings

| Configuration Item | Suggested Value | Rationale |
| :----- | :------- | :----------- |
| `Chunk size` | `800–1200 characters` | Rehabilitation equipment manuals often have long logical paragraphs containing multiple technical parameters or operating steps. This length helps maintain contextual completeness. |
| `Overlap Length` | `100–200 characters` | Ensures sufficient overlap between adjacent segments to capture key cross-segment information and contextual relevance. |
| `Automatic Chunking Strategy` | `By Title and Paragraph` | Rehabilitation equipment documents typically have clear heading hierarchies and natural paragraphs. This strategy effectively preserves semantic integrity. |
| `Max File Size` | `100 MB` | Technical manuals for rehabilitation equipment may contain high-resolution images and detailed charts, leading to large file sizes. |
| `ParsingTimeout` | `300 seconds` | Parsing complex PDF documents can be time-consuming. Increasing the timeout prevents parsing interruptions. |
| `图像OCR` | `Enabled` | Many technical parameters in rehabilitation equipment documents may appear as images. Enabling OCR ensures comprehensive information extraction. |

## Three Common Pitfalls

*   Technical parameter values and units are separated in parsing results, leading to numerical mismatches or incorrect units during queries. This occurs when the parser fails to recognize a value and its adjacent unit as a single entity.
*   For uploaded Excel format documents, each row of data is incorrectly split into multiple fragments after chunking, resulting in incomplete query results. This happens when the default chunking strategy is not optimized for tabular data structures and fails to recognize table rows as independent semantic units.
*   Large PDF documents uploaded experience prolonged unresponsiveness or parsing failures, with a `PARSE_FILE_TIMEOUT` error. This is due to a default parsing timeout that is too short to handle the time required for complex document parsing.

## How to Verify Correct Configuration

*   Upload a typical product manual. Use the knowledge base preview function to check if segments are logically coherent and if critical technical parameters are fully retained within a single segment.
*   For maintenance manuals containing tabular data, upload them and verify that table rows are treated as independent segments and that all data fields within each row are complete.
*   Upload a large clinical application guideline. Observe if the parsing process completes smoothly without timeout errors, and check parsing logs to confirm a successful status code.
