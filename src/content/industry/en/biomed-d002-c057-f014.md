# Forms and Interactions for Cardiovascular Interventional Products

## Data Characteristics for This Category

Cardiovascular interventional product data sources typically include product manuals, clinical trial reports, registration certificates, operating guidelines, and marketing materials. These documents vary in structure, covering formats such as PDF, Word, and structured database exports. Data update frequency is relatively low, primarily occurring with new product launches, regulatory updates, or clinical data releases. Product manuals often contain detailed models, specifications, materials, scope of application, contraindications, intended use, performance parameters (e.g., guidewire diameter, balloon length, stent diameter), and sterilization methods. Fields and units are highly specialized, such as "mm," "Fr" (French gauge), "atm" (atmospheres), "psi" (pounds per square inch), and frequently include specific medical abbreviations. Some data may appear as images or charts, such as device structural diagrams or pressure-flow curves.

## Constraints Imposed by These Characteristics on "Forms and Interactions"

The specialized nature of cardiovascular interventional product data requires form designs to precisely capture user intent and avoid ambiguity. For example, queries about device dimensions need to clearly distinguish between "guidewire diameter" and "stent diameter," and support input and conversion across various units. Document structural complexity means single keyword matching may be insufficient for complete information retrieval. This necessitates multi-turn interactions to guide users in refining their query scope. The low update frequency, coupled with a large volume of information per update, demands that the knowledge base can rapidly ingest and index new document versions. It must also support version management to ensure that interactive responses are always current and authoritative. Furthermore, the extensive use of specialized terminology and abbreviations requires the model to possess strong semantic understanding. It must map everyday user questions to the professional knowledge domain and present answers clearly and unambiguously, providing term explanations when necessary.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Cardiovascular interventional product manuals and clinical reports often contain numerous images and charts, leading to large file sizes. |
| `maxContext` | `8000 tokens` | Ensures the model can process long document contexts containing detailed technical parameters and clinical descriptions. |
| `Chunk size` (Segment Length) | `500 characters` (characters) | Balances semantic completeness and recall efficiency, preventing information loss due to excessive segmentation. |
| `Recall count` (Recall Count) | `Top 8 entries` (top 8) | Complex queries may involve multiple products or parameters; increasing recall improves hit rate. |
| `Similarity threshold` (Similarity Threshold) | Calibrate based on actual measurements | Find a balance between precision and recall based on actual query performance, for example, `0.75`. |
| `Rerank result count` (Reranked Return Count) | `Top 5 entries` (top 5) | Reduces redundant information presented to the user, focusing on the most relevant answers. |

## Three Common Mistakes

*   **Symptom:** When a user queries "catheter diameter," the system provides an answer for "guidewire diameter." **Reason:** Lack of precise distinction between synonyms or near-synonyms; the model confuses size parameters for different devices.
*   **Symptom:** After a user enters "PTCA balloon," the system responds slowly or times out. **Reason:** The knowledge base contains a large number of images or scanned documents without effective Optical Character Recognition (OCR) or text extraction, leading to inefficient indexing.
*   **Symptom:** When selecting the unit for "stent length" in a form, the "mm" option is missing, with only "cm" available. **Reason:** Form design did not adequately consider commonly used units of measurement for this product category, preventing users from accurately entering data.

## How to Confirm Proper Configuration

*   Conduct a series of query tests including specialized terminology and abbreviations. Verify that system responses are accurate, complete, and consistent with original document content.
*   Test uploading large PDF or Word documents. Observe if the `UPLOAD_FILE_MAX_SIZE` parameter limit is effective and if file processing time is acceptable.
*   Simulate user questions about specific product models, specifications, or contraindications. Check if the system can correctly understand and guide the user through multi-turn interactions, ultimately providing precise feedback.
