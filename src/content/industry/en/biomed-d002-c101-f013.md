# Knowledge Base Retrieval and Recall for Recombinant Protein Products

## Data Characteristics

Recombinant protein product data originates from supplier product manuals, technical specifications, experimental reports, and scientific literature. These documents typically include protein sequence information, expression hosts, purification methods, biological activity data (e.g., `EC50`, `ED50`), batch information, storage conditions, shipping requirements, and quality control reports. Data updates are relatively stable, occurring when new products are released or existing products are improved. Documents are often in PDF format, rich in tables and graphs. Fields include protein name, catalog number (e.g., `Cat.No.`), molecular weight (unit `kDa`), isoelectric point (`pI`), purity (unit `%`), and various biological activity units (e.g., `ng/mL`, `U/mg`).

## Constraints on Knowledge Base Retrieval and Recall

Recombinant protein data is highly structured, but critical information is often embedded in lengthy technical descriptions or tables. This requires retrieval systems to effectively process unstructured and semi-structured data. Precise matching information like product catalog numbers and batch numbers is crucial for query accuracy. Biological activity data requires support for fuzzy matching of numerical ranges or unit conversions. The extensive use of specialized terminology and abbreviations (e.g., `SDS-PAGE`, `ELISA`) in documents challenges tokenization and semantic understanding. Additionally, data format variations across different suppliers increase the difficulty of unified knowledge representation. Recall must balance precise queries for specific parameters with exploratory queries for related products or application scenarios.

## Configuration Recommendations

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `Chunk size` (Segment Length) | `800–1200 characters` | Balances the paragraph length of recombinant protein technical documents, preventing critical information from being truncated while ensuring semantic completeness. |
| `Recall count` (Number of Retrieved Items) | `Top 5–8 items` | Covers multiple products or technical details potentially involved in user queries, providing more comprehensive references. |
| `Similarity threshold` (Similarity Threshold) | `0.75–0.85` | Balances high-precision matching and relevance recall, avoiding omission of highly relevant recombinant protein product information. |
| `Rerank result count` (Number of Reranked Items) | `Top 3 items` | Focuses on the most core products or solutions, reducing user screening costs and improving consultation efficiency. |
| `maxContext` | `4000 tokens` | Ensures the large language model can handle complex technical details and multi-parameter descriptions of recombinant protein products. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Accommodates the parsing time for large PDF product manuals or experimental reports, preventing timeouts during file uploads. |

## Common Pitfalls

*   Uploading large product manuals results in a `file parsing timeout` or `file upload failed` error. This typically occurs because the `PARSE_FILE_TIMEOUT_SECONDS` parameter is set too low, not allowing enough processing time for documents containing numerous charts and tables.
*   User queries for a specific recombinant protein's `EC50` value return missing or inaccurate key data. This happens when an improper knowledge base segmentation strategy separates contextual information containing numerical values and units, affecting precise numerical recall.
*   The knowledge base contains data for multiple batches of the same recombinant protein product, but retrieval results fail to differentiate or prioritize the latest batch. This may be due to ineffective extraction and tagging of batch information during document preprocessing, or a lack of consideration for time dimension or version priority in recall ranking.

## Validation Steps

*   Upload a PDF document containing information on various recombinant protein products. Check if the knowledge base correctly identifies and extracts key fields such as product name, `Cat.No.`, and molecular weight (`kDa`).
*   Perform a precise query for a specific recombinant protein product catalog number (e.g., `rP-12345`). Verify that the recall results accurately return all detailed technical parameters for that product and cross-reference the accuracy of values like `EC50` or `ED50`.
*   Input queries containing specialized terminology (e.g., `cytokine receptor`, `kinase activity`). Check if the recall results include document snippets related to relevant application scenarios or technical principles, and assess if their relevance to the query intent is above an acceptable threshold.
