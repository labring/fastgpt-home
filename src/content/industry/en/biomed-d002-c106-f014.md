# Forms and Interaction for High-Value Consumables

## Data Characteristics for This Category

High-value consumable data originates from manufacturer product manuals, clinical use guidelines, registration certificates, national drug administration databases, and hospital internal procurement and inventory systems. Data updates are relatively stable, typically occurring with product iterations or regulatory changes, with cycles ranging from several months to a year. Document structures for product manuals usually include fields such as product name, model, specification, batch number, production date, expiration date, scope of application, contraindications, usage instructions, precautions, and registration certificate number. Field units vary; for example, dimensions may involve millimeters (`mm`), centimeters (`cm`), inches (`inch`), volume may involve milliliters (`mL`), and weight may involve grams (`g`). Some fields, such as "registration certificate number," have strong validation rules.

## Constraints Imposed by These Characteristics on "Forms and Interaction"

The stability and field complexity of high-value consumable data require form designs that support multi-field input and strict data validation to ensure the accuracy of user-entered information. For example, for fields like the registration certificate number, the frontend must provide regular expression matching for validation. Hierarchical relationships within document structures, such as the association between a product and its different specifications and models, dictate that forms need to support cascading selection or dynamic loading of options to reduce user input burden. Diverse units and numerical types require form fields to support different data type inputs and provide unit selectors. Additionally, since query results may contain large amounts of text information, such as precautions and contraindications, the interaction design needs to provide text summarization and full text expansion features for users to quickly obtain key information. For unstructured data like images, forms must support file uploads and appropriate backend processing.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale                                                                                                       |
| :----------------- | :---------------- | :-------------------------------------------------------------------------------------------------------------- |
| `maxContext`       | `1500 tokens`     | Accommodates detailed descriptions in high-value consumable product manuals, ensuring context completeness.     |
| `Chunk size`         | `300 characters`        | Balances recall precision with processing efficiency, reducing information overload in a single segment.        |
| `Similarity threshold`       | `0.75`            | Ensures the relevance of query results, filtering out low-relevance product information.                         |
| `Rerank result count`     | `5 entries`            | Focuses on the most relevant product recommendations, preventing users from choosing among too many results.    |
| `UPLOAD_FILE_MAX_SIZE` | `20 MB`           | Supports uploading high-resolution product images or attached documents, such as scanned registration certificates. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds`          | Allows sufficient time to process large PDF product manuals or batch files.                                     |

## Three Common Mistakes

*   After querying a high-value consumable model, the results lack key parameter information. This occurs because some fields were not correctly indexed during knowledge base construction, or the segmentation strategy truncated information.
*   A user submits a registration certificate number query, and the system prompts "format error." This occurs because the form input validation rules do not match the actual registration certificate number format (e.g., `National Medical Device Registration Number202X3XX0XXX`).
*   After a user uploads a product image, the image cannot be referenced in subsequent interactions for auxiliary explanations. This occurs because the file upload function is not integrated with visual recognition or image analysis modules in the workflow, and only stores the image as an attachment.

## How to Confirm Correct Configuration

*   Submit a form containing complete product information (model, specification, batch number, registration certificate number) and verify that all fields are accurately parsed and stored.
*   Upload a PDF document containing product images and detailed text descriptions, then verify that the system can extract text information and support image preview.
*   Perform a query by entering a vague description of a high-value consumable. Check if the results include multiple highly relevant products and compare their `similarity` scores.
*   Test queries for high-value consumables with different specifications (e.g., dimensions, volume) to confirm that the unit conversion and numerical matching logic in the form are correct.

The values given are common starting points and should be measured against the reader's own samples.
