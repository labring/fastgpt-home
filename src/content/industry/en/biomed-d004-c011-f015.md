# Deployment and Upgrade for an Internal OA Workflow Assistant

## Data Characteristics for this Category

Internal office data related to OA workflow initiation primarily originates from internal enterprise automation systems. Data updates typically occur in real-time or near real-time, triggered by employee submissions, approvals, and transfers. Document structures are mainly structured data, such as workflow forms, approval records, and status change logs. Unstructured data, like attachments and approval comments, also appear. Key fields include workflow ID, initiator ID, approver ID, workflow status, initiation time, approval time, and form field values. Units are commonly time (e.g., "days," "hours"), monetary (e.g., "RMB," "USD"), or custom business units. Data volume varies with enterprise scale and workflow complexity but generally includes extensive historical workflow data.

## Constraints Imposed by These Characteristics on Deployment and Upgrade

The real-time nature of OA workflow data requires deployment solutions to have high availability and fast response capabilities. This ensures users receive immediate assistant feedback after initiating a workflow. The coexistence of structured and unstructured data means the knowledge base must effectively process different data sources and perform unified vector storage. A high update frequency necessitates incremental update mechanisms for the knowledge base. This avoids full rebuilds with every update, reducing system load and maintenance costs. The diversity and customizability of form fields demand more from parsers and data extraction modules, requiring flexible configuration to adapt to different workflow form structures. Large volumes of historical workflow data challenge storage capacity and retrieval performance. Deployment must fully consider storage scalability and query optimization.

## Configuration Settings

| Configuration Item | Suggested Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | Considers attachment size, preventing system resource exhaustion from excessively large file uploads. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` | Most attachments can be parsed within 5 minutes, preventing prolonged blocking. |
| `maxContext` | `4000 characters` | Balances context completeness with model processing efficiency, covering most workflow descriptions. |
| `Chunk size` | `500 characters` | Ensures semantic integrity of segmented content while optimizing vector retrieval granularity. |
| `Recall count` | `Top 10 entries` | Reduces model input while ensuring recall accuracy. |
| `Similarity threshold` | `0.75` | Balances recall breadth and precision, filtering out irrelevant workflow information. |

## Three Common Mistakes

*   Assistant responses still rely on old data after a knowledge base update. This occurs when incremental synchronization is misconfigured, failing to correctly identify data changes or execute synchronization tasks as planned.
*   The assistant cannot recognize or extract some workflow form fields. This happens when data source parsing configurations are incomplete, failing to cover all custom or non-standard fields.
*   System response is slow after deployment, especially during peak hours. This indicates insufficient database connection pool or computing resource configuration, unable to handle concurrent requests.

## How to Confirm Correct Configuration

*   Submit a new workflow, check its status in the OA system, then ask the assistant about the relevant workflow information. Verify if the assistant's answer matches the latest status.
*   Select a workflow with attachments and complex forms. Ask the assistant questions about attachment content or specific form fields. Check if the assistant can accurately extract and answer.
*   Under high concurrency (e.g., simulating multiple users simultaneously initiating workflows and asking questions), monitor system CPU, memory, and database connection counts. Ensure all metrics remain within reasonable ranges and that assistant response times stay stable.
