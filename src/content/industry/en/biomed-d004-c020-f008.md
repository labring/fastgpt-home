# Tool Calling and Plugins for Meeting Minutes Internal Office Assistant

## Meeting Minutes Data Characteristics

Meeting minutes data typically originates from structured or semi-structured text records. These include transcripts from meeting recordings, manually organized text, and content filled into predefined templates. Update frequency varies based on meeting intensity, ranging from daily to weekly or monthly.

Document structure commonly includes fields such as meeting topic, time, location, attendees, agenda, discussion content, resolutions, action items, and responsible parties. The discussion content section may contain free-form text, while resolutions and action items are often more structured, detailing specific tasks, deadlines, and owners. Field values can include dates, times, names, organization names, and specific numerical values (e.g., budget amounts, completion percentages). Units are usually natural language descriptions or specific numerical formats.

## Constraints Imposed by Meeting Minutes on Tool Calling and Plugins

The semi-structured nature of meeting minutes requires tool calling to flexibly adapt to different meeting formats during parsing. Summarization and key information extraction from free-form text depend on robust natural language processing capabilities.

For structured information like action items and resolutions, tool calling must accurately identify and map them to external systems, such as task or project management tools. Accurate identification of date, time, and responsible party fields is fundamental for automated follow-up.

The unpredictable update frequency necessitates that tool calling supports both periodic and manual triggering mechanisms to ensure timely information processing. Additionally, meeting minutes may contain numerous domain-specific terms, requiring tool calling to integrate with specialized knowledge bases for term parsing and concept association.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `maxTokens` | `1024–2048` | Ensures coverage of core meeting minutes content while preventing efficiency degradation from excessively long inputs. |
| `temperature` | `0.3` | A lower temperature value helps generate more focused and factual summaries and task extraction results, reducing divergence. |
| `tool_selection_threshold` | `0.75` | A higher threshold reduces the probability of mistakenly triggering tools, ensuring external tools are called only when clearly needed. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` | Provides sufficient parsing time for longer meeting minutes texts, preventing failures due to timeouts. |
| `max_concurrent_tool_calls` | `2–3` | Balances concurrent processing capability with system resource consumption, avoiding performance bottlenecks from excessive concurrency. |
| `recall_top_k` | `5` | Recalls an appropriate number of relevant documents during knowledge base retrieval, providing sufficient contextual information for tool calling. |

## Common Pitfalls

*   **Tool call returns an empty response:** The tool chain breaks. This often occurs because tool function parameters are not mapped correctly, leading to external API call failures or empty data returns.
*   **Frequent `Invalid JSON: Bad control chara` errors:** This typically happens when input text contains non-standard control characters, preventing the JSON parser from processing it correctly.
*   **Action items not synchronized to the task management system:** No new tasks are generated in the system. This can be due to incorrect formatting of task fields during tool calls, such as an incorrect date format, which does not meet the target system's requirements.

## Verification Steps

*   Select typical meeting minutes samples. Use debug mode to observe tool call inputs and outputs, verifying correct parameter passing.
*   Confirm that key entities extracted from the meeting minutes (e.g., dates, names, task descriptions) match the original text and that their format meets the requirements for subsequent tool calls.
*   For tools integrated with external systems, trigger actual calls and check the target system (e.g., task management system) for corresponding data updates, confirming data synchronization completeness.
