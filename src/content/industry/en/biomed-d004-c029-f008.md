# Tool Calling and Plugins for an Internal Policy Retrieval Assistant

## Data Characteristics for This Category

Internal policy data for a biopharmaceutical company typically originates from internal policy management systems, SharePoint document libraries, or enterprise cloud drives. Document update frequencies vary. Core policies, such as quality management system documents, might be revised annually, while operational SOPs could be updated quarterly or semi-annually based on practical needs. Documents are primarily in PDF, Word, or Markdown formats, containing elements like titles, sections, body text, and attachment links. Policy documents usually include metadata such as `Policy Name`, `Publication Date`, `Version Number`, `Effective Date`, `Revision History`, and `Scope of Application`. The main content consists of extensive normative text and process descriptions. Units involved are typically time (e.g., `days`, `hours`), quantity (e.g., `copies`, `batches`), and specialized terminology.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins

Inconsistent policy document update frequencies require tool calls to consider data synchronization strategies to ensure the timeliness of retrieval results. High-frequency SOP updates necessitate more frequent data source synchronization or incremental update mechanisms. Attachment links within policy documents mean that retrieving relevant policies might require calling external tools to parse or download these attachments. For example, an HTTP request plugin could retrieve PDF attachment content for secondary analysis. The `Version Number` and `Effective Date` fields in the document structure are crucial for accurately retrieving policy versions within a specific timeframe and must be precisely passed in tool call parameters. Additionally, the normative nature and specialized terminology of policy documents demand that plugin design supports precise matching or synonym expansion for specific terms to improve retrieval accuracy. For multimodal policy charts, an image recognition plugin might be necessary for content extraction.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000` | Policy documents are often lengthy, requiring a larger context window to understand the full semantics. |
| `Chunk size` (Segment Length) | `500–800 characters` (characters) | Ensures each segment contains sufficient semantic information, preventing truncation of key information. |
| `Recall count` (Recall Count) | `Top 10 entries` (top 10) | Policy retrieval requires a high recall rate to cover various potentially relevant policy clauses. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | Policy content is highly specialized; increasing the threshold helps filter out irrelevant fuzzy matches. |
| `Rerank result count` (Rerank Return Count) | `Top 5 entries` (top 5) | Based on high recall, reranking selects the most relevant policy snippets. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` (seconds) | Processing large policy files or attachments can be time-consuming, requiring an extended timeout. |

## Three Common Pitfalls

*   `HTTP 504 Gateway Timeout` errors when calling external APIs occur because backend service response times exceed the default timeout settings when processing large PDF attachments or requesting external knowledge bases.
*   Retrieval results lack the latest version of policy documents because the data source synchronization strategy does not cover all update frequencies of policy types, leading to outdated knowledge base data.
*   The AI assistant cannot recognize chart information in policy documents due to a lack of multimodal processing capabilities, meaning an image recognition plugin is not configured or called to parse image content.

## How to Verify Configuration

*   Test retrieving recently updated policy documents and verify that their `Version Number` and `Effective Date` are accurately returned.
*   Call policies containing attachment links and check if the configured HTTP plugin can successfully access and download the attachments.
*   For queries containing specialized terminology, check if retrieval results precisely match relevant policy clauses and evaluate their relevance.
