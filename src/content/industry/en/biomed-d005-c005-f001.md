# CSO Policies: HTTP Interface and External Systems

## Data Characteristics

CSO (Contract Sales Organization) policy and SOP documents in the biopharmaceutical industry typically contain complex business processes, compliance requirements, job responsibilities, evaluation criteria, and sales conduct guidelines. These documents originate from various sources, including internal company regulations, industry regulatory policies, legal interpretations, and business partner agreements. Update frequencies vary: core policies like compensation systems and compliance policies might update quarterly or semi-annually, while specific SOPs or project management details could revise monthly or even weekly. Document formats are primarily PDF, Word, and Markdown; some content may exist in internal wikis or knowledge bases. Fields and units commonly include "effective date," "version number," "approver," "scope," "violation penalties (fine amounts, deduction ratios)," "performance indicators (sales revenue, coverage, profit margin)," and "reimbursement standards (yuan/km, yuan/day)." These involve diverse data types such as amounts, percentages, dates, personnel, and process steps.

## Constraints Imposed by HTTP Interface and External Systems

The complexity and diverse sources of CSO policy documents require HTTP interface design to be highly flexible and robust. For example, frequent document updates necessitate interface support for incremental synchronization or periodic full refreshes to ensure knowledge base timeliness. Diverse document formats mean external systems must provide strong file parsing capabilities, especially for accurate extraction of tables and complex layouts from PDFs. Heterogeneous fields, such as differing currency units and date formats, require the interface to perform standardized conversions during data transmission. Additionally, policy documents contain sensitive information and compliance requirements. HTTP interfaces must strictly adhere to encryption protocols during transmission and feature granular permission control, ensuring only authorized users access relevant content. When processing fails, clear error codes and detailed error messages are needed to quickly identify whether the issue is a network problem, authentication failure, file parsing error, or data format mismatch.

## Configuration Guidelines

| Configuration Item          | Recommended Value                         | Rationale                                                                                                                                                           |
| :-------------------------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `datasource_url`            | `https://cso-policy.example.com/api/docs` | Specifies the API endpoint for policy documents, ensuring access to the latest data.                                                                                |
| `auth_header`               | `Bearer your_api_key`                     | Uses a Token or API Key for authentication, securing the data interface.                                                                                            |
| `update_interval_seconds`   | `86400` seconds                           | Sets daily full or incremental synchronization, balancing data freshness and system load.                                                                           |
| `file_type_whitelist`       | `pdf, docx, md, txt`                      | Restricts processing to known document types, preventing parsing exceptions or unexpected content.                                                                  |
| `max_document_size_mb`      | `50` MB                                   | Limits single document size, preventing out-of-memory errors or processing timeouts for oversized files.                                                           |
| `timeout_seconds`           | `300` seconds                             | Sets the interface request timeout, addressing unstable networks or slow external system responses, preventing prolonged waiting.                                 |

## Common Pitfalls

*   **Symptom:** Synchronization tasks hang and eventually time out. **Cause:** The external system interface responds slowly, or the document content is too large, causing transmission and parsing time to exceed the `timeout_seconds` setting.
*   **Symptom:** Some document content is missing or formatted incorrectly. **Cause:** The file parser fails to correctly handle complex tables, images, or special fonts in PDFs, resulting in incomplete text extraction.
*   **Symptom:** A new version exists in the external system, but FastGPT still shows old content. **Cause:** The `update_interval_seconds` is set too long, or the external system does not correctly mark document update status, preventing FastGPT from triggering an update.

## Verification Steps

*   Access the specified interface via `datasource_url` and confirm an HTTP status code of `200 OK` with an expected data structure.
*   Upload and parse a CSO policy PDF document containing complex tables and multi-level headings. Check that text extraction is complete and correctly formatted.
*   Manually modify an SOP document in the external system. After the `update_interval_seconds` cycle concludes, check if the document content in FastGPT has updated to the latest version.
*   Simulate an authentication failure request and observe if correct error codes like `401 Unauthorized` or `403 Forbidden` are returned.
