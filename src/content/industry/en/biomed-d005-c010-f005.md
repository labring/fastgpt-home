# Multiturn Conversation and Prompts for IVD Diagnostic Reagent Regulations

## Data Characteristics

IVD diagnostic reagent regulations and SOP data come from internal quality management system documents, national and industry regulatory guidelines, and clinical trial reports. Data updates are stable, typically occurring when regulations change or products iterate. Documents are hierarchical, including elements like `Quality Manuals`, `Procedure Files`, and `Operation Instructions`. They usually contain chapter numbers, titles, body text, attachments, and revision records. Fields often include batch number, expiration date, storage conditions, detection principle, intended use, interfering substances, and quality control limits. Units cover both International System of Units (SI) and specific biological units, such as `U/L`, `ng/mL`, `IU/mL`, `℃`, and `%`.

## Constraints on Multiturn Conversation and Prompts

IVD diagnostic data is highly structured and uses dense technical terminology. The multiturn conversation system must accurately identify specialized terms and abbreviations to understand user intent. For example, if a user queries "CV% requirements for a reagent," the system must precisely match "coefficient of variation" and its acceptable range from the knowledge base. Regulatory document updates can lag, so the system must prioritize recalling the latest version to avoid citing outdated regulations. The hierarchical document structure dictates prompt design. Prompts must guide the model to trace back to higher-level documents or specific clauses when users ask questions, providing full context. Unit mixing and specific professional fields demand high prompt accuracy to prevent misinterpretations due to unit confusion, such as the difference between `ng/mL` and `µg/mL`.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `maxContext` | `4000` tokens | Ensures capacity for critical sections of regulatory documents and multiturn conversation history, preventing information loss. |
| `Chunk size` (Chunk Size) | `500` characters | Balances semantic completeness and retrieval efficiency, avoiding noise from overly long chunks. |
| `Recall count` (Recall Count) | `8` items | Increases the recall rate of relevant document snippets, covering multiple regulatory points a user might inquire about. |
| `Similarity threshold` (Similarity Threshold) | `0.78` | Balances recall accuracy and coverage, reducing the introduction of irrelevant content. |
| `Rerank result count` (Reranked Return Count) | `3` items | Selects the most relevant few items, reducing the model's processing load and improving answer precision. |
| `systemPrompt` | Dynamic Loading | Loads corresponding role settings and constraints from the knowledge base based on the user's query type (e.g., quality management, product registration) to enhance professionalism. |

## Common Pitfalls

*   Tool call results do not display in the chat window: This typically happens when the frontend rendering logic fails to correctly process the tool's JSON structure, preventing timely UI updates.
*   Prompts fail to load dynamically or load incorrectly: This can be due to prompt formats in the knowledge base not meeting system expectations, or incorrect loading path configurations, preventing the `prompt_template` field from being read.
*   Chat interface language does not match expectations: This usually occurs when the `iframe` embed does not correctly pass language parameters, or the system's default language settings are not overridden.

## Verification Steps

*   Conduct multiturn questioning for typical IVD reagent scenarios like batch release and quality control. Check if answers accurately cite regulatory text and trace back to specific clauses.
*   Simulate user queries for a reagent's "storage conditions" or "expiration date." Verify that the system's returned values and units match the original data in the knowledge base without confusion.
*   Test the system's ability to correctly understand and explain relevant regulations when encountering technical acronyms (e.g., `LOD`, `LOQ`). Confirm the `prompt`'s understanding of specialized vocabulary.
*   Check if the system smoothly switches context when the user changes query focus during a conversation and continues to provide accurate IVD regulation-related information.
