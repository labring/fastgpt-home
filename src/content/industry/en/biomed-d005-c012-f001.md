# HTTP API and External Systems for SMO Regulations

## Data Characteristics for This Category

Site Management Organization (SMO) regulations and Standard Operating Procedure (SOP) data primarily come from clinical trial regulations published by national drug administration agencies, Good Clinical Practice (GCP) guidelines, and internal operational procedures based on these guidelines. These documents typically exist as PDFs, Word files, or in internal knowledge bases. Update frequency depends on regulatory changes and internal management adjustments, usually quarterly or annually. Document structures are rigorous, containing numerous clauses, flowcharts, tables, and terminology definitions. Common fields include `SOP Number`, `Release Date`, `Revision Version`, `Effective Date`, `Scope`, `Responsibilities`, and `Specific Steps`. Units are typically dates, version numbers, and text descriptions, without complex numerical calculation units.

## Constraints Imposed by These Characteristics on "HTTP API and External Systems"

The authoritative and rigorous nature of SMO regulations and SOP documents requires HTTP APIs to ensure content completeness and consistency during data synchronization. Any omission or alteration could lead to compliance risks. Their relatively low update frequency means external systems do not need to pull data too often. However, updates must trigger timely synchronization to reflect the latest operational procedures. Non-structural information, such as flowcharts and tables within documents, challenges the data format returned by the API. It requires consideration of how to structure this information or transmit it in a renderable format. Furthermore, unique fields in SOPs like `SOP Number` and `Revision Version` are critical for version control and traceability. External systems must accurately identify and store them for subsequent comparison and referencing.

## Configuration Settings

| Configuration Item             | Suggested Value       | Rationale                                      |
| :----------------------------- | :-------------------- | :--------------------------------------------- |
| `maxContext`                   | `8000 characters`     | Regulation texts are often long; sufficient context processing capability is needed. |
| `Recall count` (Recall Count)      | `Top 5`               | Ensures focused recall results and reduces irrelevant information. |
| `Similarity threshold` (Similarity Threshold) | `0.78–0.85`           | Ensures answer relevance and filters out low-matching content. |
| `PARSE_FILE_TIMEOUT_SECONDS`   | `600 seconds`         | Large SOP files take longer to parse; allow ample processing time. |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `30 seconds`          | External system API response times are generally fast; prevents prolonged blocking. |
| `cite`                         | `true`                | Ensures citation IDs are returned for tracing regulation sources and versions. |

## Three Common Mistakes

*   The `content` field in the JSON data returned by the HTTP API is empty or incomplete, leading to answers lacking detail. This occurs due to insufficient parsing capabilities for PDF or Word documents, failing to extract all text content correctly, especially text within tables and flowcharts.
*   After an external system requests the API, the conversation does not return a `cite` reference ID, making it impossible to locate the answer source. This happens when the `cite` parameter is not enabled or configured in FastGPT, preventing the system from including source document citation information in the response.
*   After updating SMO regulations, the AI's answers still rely on old content, resulting in outdated or incorrect information. This is due to the external system failing to trigger data synchronization in time, or FastGPT's knowledge base not successfully completing incremental updates.

## How to Confirm Correct Configuration

*   Request a typical SOP question-and-answer via the HTTP API. Check if the `content` field in the response JSON contains complete text content, especially key information from complex tables and flowcharts.
*   Verify that the `cite` field returned by the HTTP API includes the correct `SOP Number` and `Revision Version`, and ensure these IDs map to the original documents.
*   Manually upload a revised SOP document to the knowledge base. After the knowledge base update is complete, query relevant questions via the API. Confirm that the AI's answers reflect the latest content and that old content is no longer cited.
