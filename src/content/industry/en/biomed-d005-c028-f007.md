# Workflow Orchestration for Molecular Diagnostics Regulations

## Data Characteristics

Molecular diagnostics regulations and Standard Operating Procedure (SOP) documents originate from medical device registration regulations, clinical laboratory guidelines published by national health commissions, and internal quality management system documents from molecular diagnostics laboratories. These documents update infrequently, typically annually or every few years, following regulatory adjustments or technological advancements. Document structures are often hierarchical, chapter-based text, containing extensive specialized terminology, flowcharts, tables, and diagrams. Key fields include test item names, sample types, detection methods, instrument models, reagent lot numbers, quality control standards, result interpretation criteria, and abnormal situation handling procedures. Units involve concentration (e.g., `ng/µL`), time (e.g., `min`), temperature (e.g., `℃`), and volume (e.g., `µL`), with high precision requirements.

## Constraints on Workflow Orchestration

The hierarchical structure and specialized terminology of molecular diagnostics regulation documents require the workflow's document parsing stage to support deep directory extraction and glossary linking. This ensures accurate semantic understanding. Low update frequency means less pressure for daily incremental updates after knowledge base construction. However, regulatory updates necessitate processing large volumes of revisions at once. Flowcharts and tabular data in documents demand advanced content extraction modules that support structured data and image content recognition and conversion. High precision requirements mean that numerical or unit-related parts of question-answering results must strictly quote the original text, preventing AI model generative bias. Additionally, regulation Q&A often requires cross-document referencing and logical inference. For example, an SOP might cite a provision from a quality management manual, requiring the workflow to perform cross-source knowledge retrieval and integration.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `maxContext` | `3000 Tokens` | Ensures complete context for complex regulations while preventing excessively long contexts from reducing inference efficiency. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Molecular diagnostics SOP files are often large and complex, requiring sufficient file parsing time. |
| `Chunk size` | `800–1200 characters` | Balances semantic completeness and retrieval efficiency, suitable for paragraph segmentation in long regulatory documents. |
| `Recall count` | `Top 5 entries` | Ensures coverage of multiple potentially relevant regulatory clauses in the initial recall phase. |
| `Similarity threshold` | `0.78` | Filters out highly relevant regulatory entries, reducing interference from irrelevant information. |
| `Rerank result count` | `Top 3 entries` | Further focuses on the most relevant regulatory content during the reranking phase, improving final answer accuracy. |

## Common Pitfalls

*   Symptom: Workflow execution time is too long, or times out (status code `504`).
    Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is set too low, or parallel processing capability is insufficient when the file parsing module handles very large SOP files.
*   Symptom: The system fails to provide accurate answers or cites incorrectly when user questions involve flowcharts or tabular content.
    Cause: The document parsing stage did not effectively extract and understand information from images and structured tables, leading to missing critical content in the knowledge base.
*   Symptom: The system immediately answers a user query, but cannot maintain context when subsequent supplementary information is provided.
    Cause: The workflow's session management mechanism is incorrectly configured, treating each query as an independent session and failing to maintain multi-turn conversation state.

## Configuration Validation

*   Select a molecular diagnostics SOP document with complex flowcharts and multi-level chapters. Upload it via API and execute the knowledge base construction process. Check parsing logs for any parsing errors, such as `ERROR_CODE: 1001`.
*   Ask complex questions about the SOP document, including specialized terminology, cross-chapter references, and numerical units. Evaluate the accuracy of the answers and the correctness of the cited sources. Test different types of SOP documents to confirm generality.
*   Simulate a multi-turn conversation. Ask detailed questions about regulations and progressively delve deeper. Verify that the system maintains context continuity and provides logically consistent answers.
*   Select a large regulatory file (e.g., `100 MB`). Test the overall workflow execution time to ensure completion within `1200 seconds` and confirm that system resource utilization is within a reasonable range.
