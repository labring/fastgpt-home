# HTTP Interface and External Systems for Medical Affairs Regulations

## Data Characteristics in This Category
Medical affairs data primarily consists of internal company regulations, Standard Operating Procedures (SOPs), training materials, compliance documents, and product-related medical information. Data sources typically include enterprise document management systems, quality management systems, or internal collaboration platforms. Document update frequency is relatively low, usually reviewed and revised quarterly or annually. Emergency updates can occur due to regulatory changes or product iterations. These documents often exist as PDFs, Word files, or internal web pages, with varying degrees of structure. SOP documents usually contain fields such as clear numbering, version numbers, effective dates, revision records, responsibilities, process steps, attachments, and referenced documents. Field content is often descriptive text. Units involve time (e.g., `days`, `hours`), quantity (e.g., `copies`, `times`), or specific medical terminology.

## Constraints Imposed by These Characteristics on "HTTP Interface and External Systems"
The low update frequency of medical affairs documents means data synchronization does not require frequent full updates. Incremental or on-demand synchronization can be more effective. The varying document structure requires HTTP interfaces to handle multiple document formats. Content extraction needs flexibility and fault tolerance. Metadata in SOPs, such as version numbers and effective dates, must be correctly mapped and stored via the interface during data import. This enables subsequent version tracing or time-point queries. The presence of long, descriptive text fields requires HTTP interfaces to prevent truncation during transmission and processing. It also requires sufficient processing capacity for subsequent text segmentation and vectorization. Accurate recognition and processing of specific medical terminology demand specific underlying models and dictionaries for content extraction, potentially requiring customized configurations.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | Medical affairs documents, especially PDFs with images and charts, can be large. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Large PDF or Word documents are complex. Parsing can take a long time. This prevents parsing failures due to timeouts. |
| `Segment Length` | `800 characters` | SOP process descriptions are often long. This maintains appropriate contextual coherence. |
| `Recall Count` | `5 items` | Ensures coverage of multiple relevant regulations or SOP segments for complex queries. |
| `Similarity Threshold` | Calibrated by actual measurement | Balances recall and precision. Avoids interference from irrelevant content. Adjust the specific value based on test results. |
| `toolChoice` | `auto` or `required` | Ensures effective tool invocation for information retrieval or verification in regulatory Q&A. |

## Three Common Mistakes
*   The HTTP interface returns a `413 Request Entity Too Large` status code. This occurs because the upload file size limit is not correctly configured or is exceeded.
*   After knowledge base content updates, user queries still return old versions. This happens when incremental synchronization is not triggered or executed correctly, leading to data inconsistency between the external system and the knowledge base.
*   Some SOP documents fail to parse correctly after import. This is due to the lack of a configured parser or custom extraction rules for specific PDF or Word document formats, resulting in missing key information.

## How to Verify Correct Configuration
*   Upload medical affairs documents of different formats and sizes. Check if all are successfully imported into the knowledge base and if content extraction is complete.
*   For an updated regulation or SOP, modify it in the external system, trigger the synchronization mechanism, and query the knowledge base. Confirm that the latest version of the content is returned.
*   Use queries containing specific version numbers, effective dates, or process steps. Verify that the system accurately recalls corresponding document segments and that metadata is correctly associated.
