# Tool Calling and Plugins for Hospital Operational Procedures

## Data Characteristics for This Category

Hospital operational procedures and SOP documents primarily originate from internal hospital management systems, regulatory databases, and quality management system files. These are typically in PDF, Word, Excel formats, or internal knowledge base pages. Updates are influenced by policy changes, management decisions, and operational feedback, usually occurring quarterly or annually. However, critical areas like medical safety and infection control may see more frequent revisions. Document structures commonly include standardized fields such as titles, chapters, clause numbers, responsible departments, implementation details, and appendices. Content often features units like "hours," "days," "times," "%," and "mg/dL" for time, frequency, ratios, and medical laboratory values, alongside various medical equipment models and drug names.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins

The standardized document structure of hospital operational procedures requires precise parsing of hierarchical information during tool calls, for example, extracting specific operational steps from a particular clause. Units and specialized terminology within fields necessitate that plugins can identify and standardize units for numerical comparisons or conditional judgments, preventing errors due to inconsistent units. For instance, if a procedure specifies "medication interval no less than `6 hours`," the plugin must correctly convert " `360 minutes`." Update frequency means tools and plugins need to support regular data synchronization or version management mechanisms. This ensures that answers and decisions are always based on the latest procedures, preventing compliance risks from outdated information. Furthermore, procedures often contain unstructured information like flowcharts and tables, demanding OCR or table parsing capabilities from tools to support more complex queries and operations.

## Three Common Pitfalls

*   Some tools not executing after a tool call: A common reason is incorrect configuration of trigger conditions or dependencies for multiple tools mounted in a workflow, leading to the model failing to call them sequentially as expected during decision-making.
*   Model call failures or insufficient balance: This often results from incorrect API Key configuration, insufficient account balance, or concurrency limits from the model service provider. This is especially true in non-streaming call modes, where a single request may consume more resources.
*   Abnormal functionality after embedding on the frontend page: This typically occurs due to dependency conflicts between FastGPT's frontend components and Vue3 projects, CSS style overrides, or cross-origin security policy restrictions, leading to interface call failures or abnormal page rendering.

## How to Verify Correct Configuration

*   For typical procedure queries, verify that the AI Agent accurately calls relevant tools and returns expected results. For example, after querying "Emergency Department Admission Process," confirm if the flowchart parsing tool was invoked.
*   Simulate a procedure update scenario. After uploading a new version of a procedure document, query the same question again and check if the AI Agent's response is based on the latest version.
*   Check system logs to confirm no abnormal errors during tool calls, especially `HTTP 5xx` or `Connection Timeout` errors, ensuring the tool call chain is unobstructed.
*   Verify the plugin's ability to identify and process numerical fields with units within procedures. For example, inquire about "maximum dosage of a certain drug" and check if the returned result includes the correct unit.
