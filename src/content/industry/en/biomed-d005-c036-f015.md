# Monoclonal Antibody Regulation: Deployment and Upgrade

## Data Characteristics

Monoclonal antibody (mAb) regulation data primarily originates from pharmaceutical companies' quality management system documents, R&D project documentation, standard operating procedures (SOPs), batch production records, regulatory compliance reports, and clinical trial protocols. These documents typically exist as PDFs, Word files, or in structured databases. Update frequency varies from quarterly to several times a year, depending on drug development cycles, production batches, and regulatory revisions. Document structures are complex, containing extensive specialized terminology, charts, flowcharts, and cross-references. Fields and units are highly specific, such as antibody affinity (nM), potency (IU/mg), purity (%), host cell lines, expression vectors, and media components (g/L). High precision for numerical values and unit consistency are critical.

## Constraints on Deployment and Upgrade

The complexity and specialized nature of mAb regulation data impose specific requirements on FastGPT deployment and upgrades. Diverse document formats, including significant non-textual information, necessitate enhanced file parsing capabilities for accurate information extraction. Frequent data updates from multiple sources require flexible data synchronization mechanisms to maintain knowledge base timeliness. Specialized terminology and complex logical structures make chunking strategies and embedding model selection crucial for accurate Q&A. The strictness of fields and units requires careful configuration of retrieval and reranking parameters to avoid information bias from incorrect numerical or unit recognition. For example, a query about "affinity" must correctly identify both the numerical value and its unit "nM" to prevent incorrect retrieval results.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Monoclonal antibody SOPs or batch records may contain numerous images and charts, leading to large file sizes. |
| `Chunk size` (Chunk Length) | `800 characters` (characters) | Ensures capture of complete experimental steps or regulatory clauses while preventing information overload in a single chunk. |
| `maxContext` | `4000 characters` (characters) | Q&A related to monoclonal antibodies often requires a longer context to understand complex concepts and processes. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | Improves retrieval accuracy, reduces results unrelated to specialized terminology, and prevents misinformation. |
| `Rerank result count` (Reranked Results Count) | `Top 5 entries` (top 5) | Given the rigor of specialized knowledge, select the most relevant few results for reranking. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` (seconds) | Processing large PDF or Word documents can take a long time; this prevents failures due to timeouts. |

## Common Pitfalls

*   After a knowledge base update, some critical concept Q&A results might still reflect old information. This occurs when the knowledge base data synchronization mechanism is not configured for incremental updates, preventing new data from overwriting old data.
*   When a user queries a specific experimental parameter, the system might return results with mismatched numerical values and units. For example, "affinity 100 µM" could be misinterpreted as "100 nM." This happens if the embedding model lacks sufficient recognition capability for specific units or if units are separated from values during chunking.
*   After deploying FastGPT, attempting to upload large batch production record PDFs might result in a 403 status code (no response body). This typically indicates a request body size limit in the server's `nginx` or `API Gateway` configuration, set lower than `UPLOAD_FILE_MAX_SIZE`.

## Verification Steps

*   Upload a monoclonal antibody SOP file containing the latest regulatory revisions to the knowledge base. Ask about key changes within it and verify that the answer accurately reflects the latest content.
*   Randomly select 5-10 queries containing specialized terminology and numerical units, such as "What is the detection method for antibody potency?" or "How to prepare 20 g/L media?". Verify that the numerical values and units in the answers are correct and consistent.
*   Simulate high-concurrency file upload operations. Observe system response time and success rate to ensure that `PARSE_FILE_TIMEOUT_SECONDS` and `UPLOAD_FILE_MAX_SIZE` settings can handle the actual load.
*   Query content across different document types in the knowledge base (e.g., Word format quality manuals, PDF format batch production records). Confirm that information extraction and Q&A performance meet expectations for all document formats.
