# Deployment and Upgrade for Medium and Consumable Regulations

## Data Characteristics for This Category

Regulations related to culture media and consumables typically exist as documents, including PDFs, Word files, and Excel spreadsheets. These documents cover procurement specifications, quality standards, storage conditions, usage procedures, and disposal processes. The primary data sources are internal Quality Management Systems (QMS) or Manufacturing Execution Systems (MES). Regulation updates are infrequent, usually revised quarterly or annually. However, temporary updates can occur in special situations, such as supplier changes or new product introductions. Document structures often contain numerous tables, lists, and specialized terminology. Fields like batch number, expiration date, storage temperature, and concentration units (g/L, mM) have strict formatting and validation requirements.

## Constraints Imposed by These Characteristics on "Deployment and Upgrade"

The heterogeneous nature of regulation documents (PDF, Word, Excel) requires a deployment solution with robust multi-format file parsing capabilities. The low update frequency means initial deployment requires a large-scale, one-time data import. Subsequent incremental updates must support version control and differential processing to avoid duplicate imports or overwrites. Tables and specialized terminology within documents demand higher requirements for knowledge base chunking strategies and entity recognition, ensuring the integrity of table content and accuracy of terminology. The strictness of fields and units dictates precise matching and unit conversion for numerical values and units in user queries during the Q&A phase to prevent misunderstandings. Additionally, integration with QMS/MES systems requires considering data synchronization and permission control to ensure the authority and timeliness of regulatory content.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Regulation documents may contain large images or embedded objects, requiring support for large file uploads. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` | Complex PDF or Word document parsing can be time-consuming, requiring sufficient processing time. |
| `Chunk size` | `800 characters` | Ensures each knowledge chunk contains sufficient context and prevents excessive table splitting. |
| `Similarity threshold` | `0.75–0.85` | Balances recall and accuracy, reducing interference from irrelevant regulatory entries. |
| `Rerank result count` | `Top 5 entries` | Prioritizes the most relevant regulatory content, improving user efficiency in information retrieval. |
| `maxContext` | `4096 tokens` | Accommodates potentially longer context requirements in regulatory Q&A. |

## Common Pitfalls

*   When uploading a large number of PDF regulation files, the interface shows `File Parsing Timeout` (File parsing timeout). This usually indicates that the `PARSE_FILE_TIMEOUT_SECONDS` parameter is set too low to handle the parsing time of complex documents.
*   A user asks about the storage temperature for a specific batch number, but the returned result fails to accurately provide the specific value. This can happen if table fields and values are separated during knowledge base chunking, preventing the formation of a complete knowledge unit.
*   After updating some regulation files, the system still returns old content in response to queries. This typically means the incremental update mechanism is not configured correctly or the knowledge base reconstruction was not triggered, leading to old data not being overwritten by new data.

## Verification

*   Upload a PDF regulation document containing complex tables and multiple pages. Check if parsing is successful and verify that knowledge chunks retain the table structure.
*   Ask a question about a specific clause in a regulation document, including specialized terminology and units. Verify that the returned result is accurate, unambiguous, and correctly identifies units.
*   Simulate the regulation file update process by replacing an existing regulation document. Then, ask a question related to that document and verify that the system returns the latest version of the content.
*   Query the knowledge base via API to check the `source` field for specific regulatory entries, ensuring data origin matches expectations.
