# HTTP API and External Systems for Home Healthcare Regulations

## Data Characteristics in this Category
Home healthcare device regulations and SOP documents typically originate from manufacturer quality management systems, regulatory certification bodies' legal documents, and public guidelines from regulatory bodies like the National Medical Products Administration (NMPA). Data update frequency is relatively low, primarily occurring after new product launches, regulatory revisions, or quality system audits. Document structures are mainly PDF, Word, or structured XML files. Content includes product manuals, operating procedures, maintenance guides, and risk assessment reports. Fields and units are standardized, for example, device model, serial number, production batch, expiration date, calibration cycle, safety level, and units of measurement (e.g., mmHg, mL/hour). These often include specific medical or engineering terminology.

## Constraints Imposed by these Characteristics on "HTTP API and External Systems"
The low update frequency of home healthcare regulatory documents means knowledge base index rebuilding does not need to be overly frequent, avoiding unnecessary resource consumption. The prevalence of PDF and Word document formats requires HTTP APIs to have robust file parsing capabilities, especially for recognizing embedded tables and text within images. The presence of standardized fields and units allows for more precise regular expressions or pattern matching rules during information extraction, improving extraction accuracy. Additionally, the medical terminology and engineering parameters in documents require models to accurately identify and use these specialized terms when understanding and generating responses, preventing misunderstanding or ambiguity. For external systems, such as internal quality management platforms or customer service systems, the HTTP API needs to support secure and stable data transmission and handle potential queries involving specialized terminology.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | A single regulation or SOP document may contain numerous charts and detailed procedures, leading to a large file size. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` | Parsing complex PDF files can be time-consuming, requiring ample time to prevent timeouts. |
| `Chunk size` | `800 characters` | Regulatory clauses have strong semantic coherence; longer segments help retain context and prevent fragmentation. |
| `Recall count` | `Top 8 entries` | Ensures coverage of multiple relevant regulatory sections, improving answer comprehensiveness. |
| `Similarity threshold` | `0.75` | Regulatory Q&A demands high accuracy, requiring a higher threshold to ensure strong relevance of recalled content. |
| `Rerank result count` | `Top 5 entries` | Further optimizes the ranking of recalled results, improving the precision of the final answer. |

## Three Common Pitfalls
*   An HTTP 504 Gateway Timeout returns when calling the API. The model's response or cited references do not return for a long time. This occurs because downstream services take too long to process complex queries or large document parsing, exceeding the timeout settings of the proxy server or FastGPT itself.
*   The model's response confuses units of measurement or specialized terminology, for example, incorrectly stating "milligrams" instead of "milliliters." This happens because the knowledge base preprocessing did not effectively identify and standardize these specific fields, leading to a lack of accurate basis for the model's generation.
*   When querying for detailed clauses of a specific regulation via API, the returned cited references are empty or incomplete. This is due to an overly aggressive document segmentation strategy that splits critical information into different blocks, or a failure to effectively identify the internal hierarchical structure of the document during indexing.

## How to Verify Configuration
*   Select multiple regulatory documents containing specialized terminology and units of measurement. Submit queries via the HTTP API and verify the accuracy of this information in the model's responses.
*   Simulate high-concurrency API call scenarios. Observe whether the interface response time is stable and check logs for timeout errors (HTTP 504).
*   For regulatory documents in different file formats (PDF, Word), upload them and check if the knowledge base correctly parses the content, especially text within tables and images.
*   Use queries containing specific clauses or SOP steps. Verify that the returned cited references accurately point to the relevant sections of the original text and check if the `citation Citation` field includes detailed page numbers or chapter information.
