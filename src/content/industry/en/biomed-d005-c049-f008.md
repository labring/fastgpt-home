# Tool Calling and Plugins for Small Molecule Pharmaceutical Regulations

## Data Characteristics

Small molecule pharmaceutical regulations and Standard Operating Procedure (SOP) data originate from internal quality management system documents, regulatory compliance files, and R&D process specifications. These documents are typically in PDF, DOCX, or internal knowledge base page formats. Content covers drug R&D, manufacturing, quality control, and clinical trials. Data update frequency depends on regulatory changes, internal process optimizations, and new drug development progress, usually quarterly or annually, but urgent specific changes can occur at any time. Document structure is highly standardized, including titles, chapter numbers, revision history, effective dates, and version numbers as metadata. Fields and units involve batch numbers, expiration dates, concentrations (e.g., `mg/mL`), temperatures (e.g., `℃`), and pressures (e.g., `kPa`), demanding high precision and traceability.

## Constraints on Tool Calling and Plugins

The highly standardized nature and precision requirements of small molecule pharmaceutical regulation documents necessitate robust structured information extraction capabilities for tool calling and plugins. The large number of version numbers, effective dates, and revision histories in documents requires plugins to identify and process differences between versions, ensuring the timeliness and accuracy of Q&A results. For example, queries about regulations for specific batches or time points require precise matching of the corresponding version. Furthermore, specialized terminology, fields, and units within documents demand that the language model understands their contextual meaning and can convert them into structured data for external tools, such as recognizing "batch number" as a specific string format. High traceability requirements also mean that tool call results should link to the original document source, facilitating engineer verification.

## Configuration Settings

| Configuration Item                 | Recommended Value | Rationale                                                                                                       |
| :--------------------------------- | :---------------- | :-------------------------------------------------------------------------------------------------------------- |
| `maxContext`                       | `2048` characters | Ensures complete context for key clauses in regulatory documents.                                               |
| `Chunk size` (Segment Length)        | `500` characters  | Balances semantic completeness with recall efficiency, preventing information loss in long paragraphs.          |
| `Recall count` (Recall Count)          | `5` items         | Covers multiple highly relevant regulatory chapters, improving accuracy.                                        |
| `Similarity threshold` (Similarity Threshold) | `0.75`            | Filters document snippets highly relevant to the query, reducing noise.                                         |
| `Rerank result count` (Reranked Return Count) | `3` items         | Selects the most relevant regulatory provisions, enhancing the conciseness of the final answer.                 |
| `PARSE_FILE_TIMEOUT_SECONDS`       | `300` seconds     | Accommodates parsing time for large PDF/DOCX documents.                                                         |

## Common Pitfalls

*   The AI fails to correctly identify version numbers and effective dates in regulatory documents, leading to answers based on outdated information. This occurs because document parsing plugins are not optimized for specific metadata formats.
*   Tool calling returns inconsistent units or incorrect values, such as misinterpreting `mg` as `g`. This happens when the model does not fully understand specialized units and their conversion relationships in the biomedical field.
*   The SQL generation plugin cannot correctly convert natural language queries into corresponding regulatory fields in the database. This is due to ineffective mapping between the database table structure, field names, and the model.

## Verification Steps

*   Select a regulatory document with new and old version differences. Ask questions about version updates to confirm the AI provides information from the currently effective version.
*   Query regulatory clauses containing specific values and units. Check if the values and units in the AI's answer or tool call results are accurate, for example, when querying `concentration limit`.
*   Use a complex regulatory query that requires the AI to call a tool to look up production records for a specific batch. Verify that the generated SQL statement is correct and executes successfully.
*   Randomly select 5 regulatory documents from different sources. Test their parsing success rate and content extraction completeness to ensure `PARSE_FILE_TIMEOUT_SECONDS` is set appropriately.
