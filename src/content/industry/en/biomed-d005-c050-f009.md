# Reference Sourcing and Traceability for Process Validation Regulations

## Data Characteristics

Process validation data in the biopharmaceutical industry primarily exists as internal documents. These include validation protocols, validation reports, deviation handling, and change control. Documents are typically PDF, Word, or Excel files, stored on internal file servers or content management systems. Data update frequency is relatively low, usually tied to process changes or periodic reviews, with cycles spanning months or even a year. Document structures are highly standardized, containing fixed sections such as introduction, objective, scope, responsibilities, validation content, acceptance criteria, results, and conclusions. Fields include batch numbers, equipment codes, material batch numbers, operators, validation dates, key process parameters (e.g., temperature, pressure, time), and test indicators (e.g., content, purity, yield) along with their units (e.g., `℃`, `MPa`, `min`, `%`, `ppm`).

## Constraints on "Reference Sourcing and Traceability"

The low update frequency of process validation data means knowledge base content does not require frequent updates. However, historical version management is crucial to ensure citation accuracy. Standardized document structures facilitate automatic parsing and information extraction, but parsers must handle complex tables and nested structures. Diverse file formats increase preprocessing complexity, requiring support for multiple file types for text extraction. The presence of specific fields and units demands that the RAG system correctly identifies and retains this information during recall and generation, preventing misunderstandings due to unit confusion. High traceability requirements mean that answers must clearly indicate the specific document, page number, and even paragraph of the cited source to meet compliance review needs.

## Configuration Settings

| Configuration Item             | Suggested Value                                 | Rationale                                                                                                 |
| :----------------------------- | :---------------------------------------------- | :-------------------------------------------------------------------------------------------------------- |
| `Chunk size` (Chunk Size)        | `800–1200 characters`                           | Process validation documents have long paragraphs with multiple parameters and operating steps. Shorter chunks lose context; longer chunks introduce irrelevant information. |
| `Recall count` (Recall Count)      | `Top 5`                                         | Given the rigor of process validation, covering core information is essential. 5 items balance coverage and recall efficiency well. |
| `Similarity threshold` (Similarity Threshold) | `0.75`                                          | A higher threshold helps reduce the recall of irrelevant documents, lowering the risk of misinformation. |
| `Rerank result count` (Rerank Return Count) | `3 items`                                       | Reranking further optimizes answer quality. 3 items are sufficient to cover the most relevant core information. |
| `PARSE_FILE_TIMEOUT_SECONDS`   | `600 seconds`                                   | Process validation reports can contain large amounts of data and charts. File parsing takes time, so increasing the timeout prevents parsing interruptions. |
| `Citation Display Format` (Reference Display Format) | `Document Name-Page Number-Paragraph Range` | Provides a precise citation path, allowing users to quickly locate the original text, meeting audit and compliance requirements. |

## Common Pitfalls

*   The answer indicates that line breaks are possible, but outputs `\n` characters without actual line breaks. This happens when the generation model does not correctly parse line breaks under specific configurations, or the frontend display does not render `\n`.
*   When the knowledge base answers, the citation at the end of a paragraph displays "No permission to operate this chat record." This occurs when the linked resource's permissions are misconfigured, or the user's current session lacks the necessary access credentials.
*   After importing a workflow, referenced plugins are not found. This indicates that the target environment's plugin library has not installed or registered the specific plugins required by the workflow, leading to path resolution failure.

## Verification Steps

*   Upload a multi-page PDF process validation report with complex tables. Check if the parsed text content is complete and if key parameters (e.g., `batch number`, `test indicators`) and their units are correctly extracted.
*   Ask questions about a document containing specific process parameters and acceptance criteria. Verify that the returned answer accurately cites the original `document name`, `page number`, and `paragraph range`.
*   Simulate a query involving sensitive information. Confirm that the system correctly identifies and restricts or adjusts the display of reference sources based on configured permission policies.
