# HTTP Interface and External Systems for Rehabilitation Equipment Regulations

## Data Characteristics for this Category
Rehabilitation equipment regulations and SOP data originate from quality management system documents of medical device manufacturers, internal hospital regulations, and regulatory documents published by the National Medical Products Administration (NMPA). These documents are typically in PDF, Word, or scanned image formats. They have complex structures, containing numerous charts, flowcharts, and specialized terminology. Data update frequency is relatively low, occurring quarterly or annually, mainly during policy and regulation adjustments, equipment model iterations, or internal process optimizations. Fields involved in these documents include equipment name, model, department of use, operating procedures, maintenance cycle, and calibration standards. Units cover physical quantities such as time (hours, days), temperature (Celsius), pressure (Pascals), and frequency (Hertz), as well as specific device codes and batch numbers.

## Constraints Imposed by these Characteristics on "HTTP Interface and External Systems"
The complex structure and multi-source nature of rehabilitation equipment regulation documents require the HTTP interface to have robust document parsing capabilities. It must handle various formats like PDF and Word, and effectively extract text content. The low update frequency means data synchronization does not need to be frequent, but each synchronization must ensure completeness and accuracy. The specialized terminology and charts in the documents place higher demands on text embedding models, potentially requiring customized vocabularies or domain-specific models. The diversity of fields and units necessitates precise parameter mapping and data type conversion when calling external systems. For example, ensuring the device model code `device_model_code` is correctly passed, and the maintenance cycle `maintenance_cycle_days` is represented as an integer number of days. Additionally, the ability to process scanned documents determines the coverage of data sources.

## Configuration Settings

| Configuration Item             | Suggested Value                | Rationale                                      |
| :----------------------------- | :----------------------------- | :--------------------------------------------- |
| `PARSE_FILE_TIMEOUT_SECONDS`   | `600 seconds`                  | Rehabilitation equipment regulation documents are often large, requiring longer parsing times. |
| `Chunk size` (Segment Length)    | `800–1200 characters`          | Balances semantic completeness and recall efficiency, avoiding redundant information in long paragraphs. |
| `Recall count` (Number of Recalls) | `Top 5`                        | Ensures precision of retrieval results, avoiding interference from irrelevant information. |
| `Similarity threshold` (Similarity Threshold) | `0.75`                         | Improves matching accuracy for documents with extensive specialized terminology. |
| `UPLOAD_FILE_MAX_SIZE`         | `200 MB`                       | Accommodates regulation documents containing numerous charts and flowcharts. |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `120 seconds`                  | External systems may respond slowly; provides sufficient processing time. |

## Three Common Mistakes
- API call returns `{"message": "Invalid parameter format for field QWQ_32B"}`: This occurs when the external system has strict format requirements for a specific field (e.g., `QWQ_32B`), and the parameter format passed in the API call does not meet expectations.
- After document upload, some content is missing during retrieval: This typically happens when the document parser fails to correctly recognize or extract text content from scanned PDFs, leading to an incomplete index.
- After external system data synchronization, the maintenance cycle field for some equipment is empty: This may be due to the HTTP interface failing to correctly map or convert fields like `maintenance_period_in_days` when processing JSON data from the external system, or the original data returned by the external system indeed had this field empty.

## How to Verify Correct Configuration
- Upload a rehabilitation equipment SOP document containing tables and flowcharts. Verify the completeness of its parsed text content through the management interface.
- Use the API to query with a question containing device model `device_model_A123`. Check if the returned results accurately mention the relevant regulatory clauses for that model.
- Simulate an external system data synchronization. Cross-reference the values of key fields (e.g., `calibration_interval_months`) with the source system data, especially for numerical values with units.

The values provided are common starting points and should be measured against the reader's own samples.
