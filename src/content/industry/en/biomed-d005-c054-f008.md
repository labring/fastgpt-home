# Tool Calling and Plugins for Rehabilitation Equipment Regulations

## Data Characteristics for This Category

Rehabilitation equipment regulations and SOP documents originate primarily from medical device manufacturers' internal quality management systems, National Medical Products Administration regulatory documents, and industry association standards. These documents are typically stored as PDFs, Word files, or in internal knowledge bases. Updates occur quarterly or annually, driven by policy adjustments and internal process optimizations. Critical changes trigger immediate updates. Document structures are highly standardized, often including chapter titles, clause numbers, revision history, scope, definitions, responsibilities, operating procedures, and record-keeping requirements. For example, a rehabilitation equipment SOP details device models, calibration cycles, fault codes, and troubleshooting procedures. Parameters like calibration accuracy and maximum load capacity are explicitly stated with values and units, such as `±0.05mm` or `150kg`.

## Constraints on Tool Calling and Plugins from These Characteristics

The standardized structure of rehabilitation equipment documents imposes specific requirements on tool calling. The presence of numerous clause numbers and revision histories means tools must accurately identify and extract this metadata for structured retrieval, enabling precise clause location during Q&A. While the overall update frequency is not high, immediate updates for critical regulations or operating procedures require tool calling mechanisms to quickly synchronize with the latest versions, preventing answers based on outdated information. Explicit numerical values and units necessitate that tool calling handles numerical comparisons and unit conversions when querying device parameters or diagnosing faults. For instance, it should convert a user's "100 kilograms" to "100kg" if that is the document's format. Furthermore, rehabilitation equipment documents often contain specialized terminology and acronyms, requiring tools to provide term explanations via built-in dictionaries or external APIs to ensure Q&A accuracy.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `chunkSize` | `800` | Rehabilitation equipment SOPs have a rigorous structure with a moderate amount of information per segment. This length maintains semantic integrity. |
| `overlapSize` | `100` | Ensures contextual continuity and covers information spanning across paragraphs. |
| `maxContext` | `4000 tokens` | Accommodates complex regulation queries, providing sufficient context for the model to understand. |
| `rerankTopN` | `5` | Medical document retrieval often yields many results. Reranking the top 5 significantly improves relevance. |
| `similarityThreshold` | Calibrate by measurement | For documents with extensive professional terminology, experimental determination is needed to balance recall and precision. |
| `toolCallTimeout` | `60 seconds` | External tool API responses can have latency. This provides ample time to avoid frequent timeouts. |

## Three Common Pitfalls

*   Symptom: The system returns "Tool call failed: Unable to parse model response." Reason: The model's tool call output format does not match the platform's expected JSON structure. This might be due to insufficient model fine-tuning or improper prompt guidance.
*   Symptom: When users inquire about device parameters, the returned results have inconsistent units or incorrect numerical calculations. Reason: The tool call failed to correctly identify numerical units in the document or did not perform necessary unit conversions during processing.
*   Symptom: When querying a specific clause, the system's returned result does not include the latest revised content. Reason: After the knowledge base document update, the index was not rebuilt in time, or the tool call did not specify using the latest version of the data source.

## How to Verify Correct Configuration

*   Select a rehabilitation equipment SOP document with recent revisions. Ask a question whose answer is only present in the new version to verify accurate recall and response.
*   For device parameters in the document that include numerical values and units, ask queries using different units, such as "What is the maximum load capacity in kilograms?" and "What is the maximum load capacity in pounds?" Check if the tool call can correctly convert units.
*   Construct a complex question requiring multiple tool calls to resolve. For example, "If the device shows fault code `E-01` and the last calibration date was `2024-01-15`, how should it be handled?" Check if the tool chain executes as expected and provides a complete answer.
