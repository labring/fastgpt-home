# Deployment and Upgrade for Cleaning Validation Regulations

## Data Characteristics

Cleaning validation regulation data primarily originates from internal quality management system documents. These include master plans, validation protocols, validation reports, Standard Operating Procedures (SOPs), risk assessment reports, and deviation records. Documents are typically in PDF, Word, or Excel formats, with some existing as scanned images.

Update frequency varies: regulatory documents are revised annually or based on regulatory changes and process modifications. Validation reports and deviation records are generated in real-time with production batches or events.

Document structure: SOPs have clear hierarchies and steps. Validation reports contain structured and unstructured information like equipment details, cleaning agents, sampling points, analytical methods, and residue limits.

Common data fields include equipment ID, batch number, cleaning agent name, residue name, test method, limit value, and actual test results. Units involved are ppm, µg/cm², and mg/L.

## Constraints from Data Characteristics on Deployment and Upgrade

The nature of cleaning validation data imposes specific requirements on deployment and upgrade.

Long update cycles for rigorous regulatory documents necessitate effective version control and historical traceability within the knowledge base. The prevalence of PDFs and scanned documents requires robust file parsing, especially for tables and images.

Mixed structured and unstructured information demands intelligent extraction and segmentation during FastGPT data import. This ensures accurate indexing of critical fields like limit values and test results.

Specific fields and units, such as ppm and µg/cm², require the system to understand and avoid confusion during Q&A. This may require custom post-processing logic.

The sensitive nature of regulatory documents requires a highly secure deployment environment with access control. Upgrade processes must maintain data integrity and availability, preventing service interruptions due to memory issues or file upload failures.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Cleaning validation reports and SOPs can contain numerous charts and scanned images, leading to large individual file sizes. |
| `Chunk size` (Segment Length) | `800 characters` (characters) | Regulatory document paragraphs are long; shorter segments lose context, while excessively long ones reduce retrieval accuracy. |
| `Overlap Length` | `100 characters` (characters) | Ensures semantic continuity between adjacent paragraphs, preventing critical information from being cut off. |
| `maxContext` | `32768` | Complex regulatory Q&A requires a longer context window to understand related legal clauses. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | Regulatory texts are highly specialized; increasing the threshold reduces the recall of irrelevant or ambiguous results. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` (seconds) | Parsing large files is time-consuming; this prevents file import failures due to timeouts. |

## Common Pitfalls

*   Encountering `worker terminated due to reaching memory li` errors during knowledge base creation often indicates insufficient server memory to handle large file parsing or high-concurrency import tasks.
*   After upgrading FastGPT, receiving `Failed to create post presigned url` errors during file upload suggests incorrect configuration of object storage service (e.g., S3) access permissions or endpoints, leading to presigned URL generation failure.
*   Confusion between cleaning agent residue limit values and actual test results in Q&A outputs indicates ineffective distinction of similar numerical fields during text segmentation or entity recognition.

## Verification Steps

*   Upload and parse a cleaning validation report PDF containing tables and charts. Verify that key information like equipment ID and limit values are correctly extracted into the knowledge base.
*   Conduct Q&A tests on multiple cleaning validation SOP documents. Confirm the system accurately answers questions such as "What are the steps for XX equipment cleaning validation?" or "What is the recommended concentration for YY cleaning agent?"
*   Check the FastGPT management interface to confirm that system parameters like `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` are applied as expected.
*   After an upgrade, attempt to upload multiple large files (e.g., PDFs over 100 MB). Ensure files upload and parse correctly without `Failed to create post presigned url` or out-of-memory errors.
