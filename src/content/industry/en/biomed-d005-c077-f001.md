# HTTP Interface and External Systems for Dermatology Protocols

## Data Characteristics for This Category

Dermatology protocols and SOP (Standard Operating Procedure) data primarily come from internal hospital documents, clinical pathways, treatment guidelines, and drug inserts. This data typically exists as PDFs, Word documents, or internal knowledge base pages. Update frequency is relatively low, usually revised quarterly or annually, with temporary updates for special situations like new treatment guidelines. Document structures often use chapter-based organization, including titles, body text, attachments, and charts. SOPs usually describe clear, step-by-step processes, covering operation names, objectives, required equipment, steps, and precautions. The data frequently contains medical terminology, generic drug names, dosage units (e.g., `mg`, `ml`, `IU`), time units (e.g., `hours`, `days`), and specific disease classification codes (e.g., `ICD-10`).

## Constraints Imposed by These Characteristics on "HTTP Interface and External Systems"

The low update frequency of dermatology protocol data means external systems do not need to poll too frequently via HTTP interfaces. Diverse document formats (PDF, Word) require the interface to support uploading and parsing multiple file types and to effectively extract structured information. Specifically, steps and precautions within SOPs need precise identification and processing as independent knowledge units. The presence of medical terminology and specific units requires external systems to maintain semantic integrity when processing this text, avoiding information loss due to tokenization or standardization. When protocol documents include many charts or attachments, the HTTP interface needs to support large file transfers and consider how to convert this non-textual information into a retrievable or referencable format. Cross-references and version control information in documents also need to be preserved by the interface during data synchronization to allow the subsequent Q&A system to trace information sources and validity.

## Common Pitfalls

1.  **Symptom**: Uploaded PDF files show blank previews or fail to parse.
    **Reason**: The HTTP interface incorrectly identifies or processes special fonts, encryption, or scanned text within PDF files.
2.  **Symptom**: In Q&A results, drug dosage units or disease codes are misidentified or missing.
    **Reason**: The external system does not perform specialized entity recognition and standardization for medical terminology and specific units.
3.  **Symptom**: Frequent `HTTP 429 Too Many Requests` errors when calling external knowledge base interfaces.
    **Reason**: The interface call frequency or concurrency is not set appropriately, exceeding the external system's rate limits.
