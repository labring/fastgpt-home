# Deploying and Upgrading Monitoring Device Protocols

## Data Characteristics for This Category

Monitoring device protocols and Standard Operating Procedure (SOP) documents primarily originate from internal hospital regulations, equipment operation manuals, clinical practice guidelines, and relevant legal frameworks. These documents typically have a low update frequency, with revisions occurring after equipment model changes, national policy adjustments, or major safety incidents. Update cycles can range from several months to years. Document structures are often hierarchical, featuring tables of contents, main body text, and appendices. The main content is predominantly plain text, occasionally interspersed with figures and charts. Common fields include equipment model, operating procedures, error codes, alarm thresholds, and maintenance cycles. Fields involving parameters often include explicit units, such as `mmHg` (millimeters of mercury), `bpm` (beats per minute), `℃` (degrees Celsius), or `ml/h` (milliliters per hour).

## Constraints Imposed by These Characteristics on "Deployment and Upgrade"

The low update frequency of monitoring device protocol data means an initially constructed knowledge base can remain effective for an extended period. This requires ensuring data completeness and accuracy during deployment to avoid frequent corrections later. The hierarchical document structure and presence of charts demand robust text parsing and vectorization capabilities. The system must support extracting structured information and semantically linking text with graphical content to accurately answer questions like "What action should be taken for a specific device under a particular alarm state?" Furthermore, unit information within fields requires the system to correctly identify and use units in calculations or comparisons when processing numerical queries. For example, when a user asks "Above what heart rate is intervention needed?", the system must understand and provide a professional answer including the correct unit. These constraints dictate specific configurations for knowledge base construction tools during data import, parsing, and model training.

## Configuration Recommendations

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | Monitoring device protocol documents often contain extensive text, and individual files can be large. This value ensures large SOP files can be uploaded successfully. |
| `Chunk size` (Chunk Size) | `800–1200 characters` (characters) | Protocol documents are logically dense; longer chunks help maintain contextual integrity and reduce semantic fragmentation. |
| `Overlap Size` | `100 characters` (characters) | An appropriate overlap length helps maintain contextual continuity at chunk boundaries, improving retrieval accuracy. |
| `Recall count` (Recall Count) | `Top 5 entries` (top 5) | Monitoring device Q&A demands high accuracy. Increasing the recall count improves the probability of selecting relevant passages. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | A higher threshold ensures retrieved results are highly relevant to the user's query, reducing interference from inaccurate information. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` (seconds) | Processing large PDF or Word protocol documents can be time-consuming. Increasing the timeout prevents parsing interruptions. |

## Three Common Pitfalls

*   After a knowledge base content update, the Q&A results still return old information. This occurs because newly imported documents did not trigger index rebuilding or index updates failed, preventing the retrieval model from loading the latest knowledge.
*   When users query for operating procedures of a specific device model, the system replies "No relevant information found." This might be because the document parser failed to correctly extract or identify the device model field in the document, or that field was not properly indexed.
*   After deployment, some users cannot log in or access specific functions. This could be related to incorrect `AUTH_SECRET` or `JWT_SECRET` environment variable configurations, leading to user authentication failures.

## How to Verify Correct Configuration

*   Upload multiple monitoring device operation manuals in different formats (e.g., PDF, DOCX). Check if all files are successfully parsed and imported into the knowledge base. Verify that the number of imported documents matches the number of original files.
*   Formulate a series of questions targeting key information such as specific device models, error codes, or alarm thresholds. Verify if the system can accurately recall relevant document snippets and provide expected answers. Check if the answers include correct unit information.
*   Simulate users with different permission levels logging into the system. Test if they can access authorized knowledge base content and functions normally. Confirm that user management and permission configurations are effective.
