# HTTP Interface and External Systems for Lead Compound Screening Protocols

## Data Characteristics

Lead compound screening protocols and SOP documents are typically stored as PDFs, Word documents, or Markdown files. Content covers high-throughput screening processes, compound library management specifications, activity evaluation criteria, and data processing methods. These documents have a relatively low update frequency, usually updated every six months to over a year, depending on R&D pipeline adjustments or regulatory changes. Document structures often include detailed chapter titles, numbered lists, tables, and appendices. Fields and units are highly specific, such as compound ID (CAS number or internal code), screening concentration (nM, µM), inhibition rate (%), IC50 value (nM), batch number, experimentalist signature, and date. Some documents may contain chemical structure images or SMILES strings.

## Constraints Imposed by These Characteristics on "HTTP Interface and External Systems"

The low update frequency of lead compound screening protocol documents means external systems do not need to trigger frequent full crawls when synchronizing content. Periodic incremental checks or webhook notifications can be used. Documents containing tables and chemical structure images require HTTP interfaces to handle non-textual content, potentially needing OCR or image recognition services to extract key information. Diverse fields and units, especially chemical stoichiometric units, require HTTP interface data to be accurately identified and semantically preserved during parsing, avoiding unit confusion. Furthermore, complex document structures, such as multi-level headings and nested lists, demand higher requirements for text segmentation and knowledge block construction, ensuring complete context retrieval during RAG to prevent information fragmentation due to improper segmentation.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 seconds` | Most document file sizes are moderate; 60 seconds is sufficient for transfer and initial processing. |
| `MAX_FILE_SIZE_MB` | `20 MB` | Lead compound screening SOP documents typically do not exceed this size, balancing transfer efficiency and storage. |
| `CHUNK_SIZE` | `800–1200 characters` | Ensures each knowledge block contains sufficient context, covering complete experimental steps or specification definitions. |
| `OVERLAP_SIZE` | `100 characters` | Increases overlap between blocks, preventing critical information from being truncated at segmentation boundaries. |
| `METADATA_EXTRACTOR_CONFIG` | `{"fields": ["CAS_ID", "IC50", "Concentration"]}` | Explicitly extracts key entities, enhancing retrieval accuracy and answer generation quality. |
| `RETRY_ATTEMPTS` | `3 times` | Provides fault tolerance for occasional network fluctuations or transient service unavailability in external systems. |

## Common Pitfalls

*   **Observation:** IC50 values in compound screening results returned by the external system lack or have incorrect units. **Reason:** The HTTP interface failed to correctly identify and extract the unit field next to the numerical value during original document parsing, leading to data semantic loss.
*   **Observation:** When asked about the SOP for a specific screening batch, the system provides only partial fragments instead of the complete process. **Reason:** Document segmentation granularity is too fine, or context overlap is insufficient, preventing related continuous steps from being aggregated during RAG retrieval.
*   **Observation:** Frequent HTTP 401 or 403 errors occur when integrating with external systems. **Reason:** The authentication token configured for the HTTP interface has expired or has insufficient permissions, failing to refresh periodically or obtain necessary access credentials.

## Verification Steps

*   Select a lead compound screening SOP document containing complex tables and chemical structures. Upload it via the HTTP interface and observe its parsing status.
*   For the uploaded document, query the FastGPT platform for key fields (e.g., the IC50 value of a specific compound) or specific processes (e.g., high-throughput screening steps) mentioned in the document. Verify the accuracy and completeness of the returned results.
*   Simulate an external system calling the HTTP interface. Check the response time, status code, and returned data structure for expected conformity, especially regarding unit and special character encoding.
*   Regularly check logs to confirm no persistent HTTP request failures or data parsing warnings, ensuring interface stability.
