# HTTP API and External Systems for Hematologic Oncology Protocols

## Data Characteristics

Data for hematologic oncology protocols and Standard Operating Procedures (SOPs) originate from internal regulations, clinical guidelines, drug instructions, ethics review documents, and research project management specifications published by medical institutions. These documents have a relatively low update frequency, typically revised quarterly or annually. However, urgent updates occur when new drugs are released, treatment plans change significantly, or national policies are revised. Documents are often in PDF, Word, or structured XML formats. Content is highly specialized, including extensive medical terminology, gene locus information, drug dosage units (e.g., `mg/kg`, `IU/mL`), and complex flowcharts. Field structures often include "indications," "contraindications," "dosage and administration," "adverse reactions," "operating procedures," and "approval processes."

## Constraints Imposed by These Characteristics on HTTP API and External Systems

The specialized and complex nature of hematologic oncology protocol data demands robust HTTP API design. First, the low update frequency means external systems do not need to pull data too often. However, an accurate incremental update mechanism is crucial to capture key revisions. Second, diverse document formats and varying degrees of content structure require powerful document parsing capabilities from the API. The API must identify and extract key fields such as `indications` and `dosage`. Special units and medical terms within fields necessitate correct encoding and parsing during data transmission and storage to prevent information loss or misinterpretation. Due to the sensitive nature of protocol content, secure authentication and authorization management (e.g., `OAuth 2.0` protocol) are essential. This ensures only authorized external systems can access relevant SOPs.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :--------------------------------------------------------------------------------------------------------------------------------------- |
| `API_REQUEST_TIMEOUT` | `60 seconds` | Most protocol documents are large. Parsing and vectorization require time. This prevents processing interruptions due to timeouts. |
| `MAX_RETRIES_ON_FAILURE` | `3 times` | Retries improve data synchronization success rates during occasional network fluctuations or transient API service pressure. |
| `AUTH_HEADER_SCHEME` | `Bearer` | Industry-standard `OAuth 2.0` token authentication mechanism ensures the security of API calls. |
| `DATA_PULL_INTERVAL_HOURS` | `24 hours` | Hematologic oncology protocols generally do not update frequently. Daily pulls are sufficient for most updates. |
| `CHUNK_SIZE_TOKENS` | `512 tokens` | Protocol documents have high semantic integrity within paragraphs. This length balances semantic coherence and vectorization efficiency. |
| `EMBEDDING_BATCH_SIZE` | `32` | This value ensures throughput while reducing memory consumption per request, suitable for large document processing. |

## Common Pitfalls

*   External systems receive an `HTTP 401 Unauthorized` error code when calling the API. This occurs due to incorrect `Authorization` header transmission or an expired `access_token`.
*   The API returns an `HTTP 504 Gateway Timeout` error when parsing large PDF files. This may be because `API_REQUEST_TIMEOUT` is set too short, and document processing time exceeds expectations.
*   Key fields like `dosage` or `operating procedures` appear as null values in documents synchronized from external systems. This indicates a lack of refined parsing configuration tailored to the specific structure of these document types.
