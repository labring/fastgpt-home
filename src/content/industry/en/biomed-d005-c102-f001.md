# HTTP Interface and External Systems for Infection Control Management Regulations

## Data Characteristics

Infection control management regulations data originates from internal rules, operational guidelines, emergency plans, and training manuals published by medical institutions. It also includes industry standards and guidelines from national and local health commissions. These documents are often in PDF, DOCX, or HTML formats. Content structure varies, ranging from prescriptive articles to detailed operational steps. Update frequency is typically low, usually annual revisions or irregular updates based on policy changes. Document fields include regulation name, publication date, scope, specific clauses, responsible department, and operational procedures. Units may involve time (e.g., `hours`, `days`), personnel counts, and material consumption. Complex unit conversions are uncommon.

## Constraints from "HTTP Interface and External Systems"

The low update frequency of infection control management regulation documents means data synchronization does not require high-frequency triggers. Periodic or event-driven synchronization strategies are suitable. Diverse document formats require HTTP interfaces to support various file types for upload and parsing, and to handle content with varying degrees of structure. For PDF files, accurate OCR recognition is necessary to extract text content. Specific clauses and operational procedures within regulations may require fine-grained processing through text segmentation and embedding techniques to improve question-answering accuracy. The specificity of fields and units demands identification and standardization during data preprocessing to ensure effective retrieval and matching, preventing issues caused by inconsistent units.

## Configuration Guidelines

| Configuration Item           | Recommended Value | Rationale                                                    |
| :--------------------------- | :---------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `100 MB`          | Individual regulation files can be large; allocate sufficient upload space. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds`          | Large PDF files can take a long time to parse; prevent timeout interruptions. |
| `Chunk size`                   | `800–1200 characters`   | Balances the completeness of regulation articles and retrieval granularity, avoiding context loss. |
| `Recall count`                   | `Top 10 entries`        | Ensures coverage of relevant regulation clauses, improving answer comprehensiveness. |
| `Similarity threshold`                 | `0.75`            | Filters highly relevant regulation content, reducing interference from irrelevant information. |
| `HTTP Request timeout`          | `60 seconds`           | External systems may have high response latency; provide sufficient waiting time. |

## Common Pitfalls

*   **Issue:** System returns `HTTP 413 Payload Too Large` error. **Reason:** The uploaded regulation file size exceeds the limit set by the `UPLOAD_FILE_MAX_SIZE` parameter.
*   **Issue:** Document parsing task remains in "processing" status for an extended period, eventually reporting `Parse timeout`. **Reason:** `PARSE_FILE_TIMEOUT_SECONDS` is set too short; large or complex regulation files cannot be parsed within the allotted time.
*   **Issue:** When sending files via HTTP request in a workflow, the external system reports `Invalid file format` or `Missing file parameter`. **Reason:** The `Content-Type` for the file parameter in the `body` is not set correctly, or the field name does not match the external system's requirements.
