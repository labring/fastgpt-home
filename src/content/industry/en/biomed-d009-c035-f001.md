# HTTP Interface and External Systems for Hospital Operations Registration and Declaration Document Preparation

## Data Characteristics for This Category

Data sources for hospital operations registration and declaration document preparation are diverse and complex. Data primarily originates from internal hospital information systems (HIS, LIS, PACS), financial systems, human resources systems, and standard documents released by external regulatory bodies. Update frequency is relatively low, typically tied to policy and regulation release cycles, annual audits, or major operational adjustments. Most data updates occur monthly or quarterly, while some critical indicators, such as bed utilization rate and outpatient visits, may be daily. Document structures mainly consist of structured tabular data, such as various reports and lists, alongside a large volume of unstructured text, including regulations, operating manuals, and scanned approval documents. Fields and units possess strong industry-specific attributes, for example, "number of beds" (unit: units), "outpatient and emergency visits" (unit: visits), "medical waste generation" (unit: kilograms), "number of practicing physicians" (unit: individuals), as well as various financial account codes and statistical classification codes.

## Constraints Imposed by These Characteristics on "HTTP Interface and External Systems"

The scattered nature of hospital operations data sources requires FastGPT to flexibly configure connection parameters for multiple external data sources during HTTP interface integration. The low data update frequency means interface calls do not need to be overly frequent, primarily relying on on-demand triggers or scheduled batch synchronization to avoid resource waste. The diversity of document structures, especially the presence of unstructured text, poses challenges for the data format returned by interfaces. This necessitates handling various content types such as JSON, XML, PDF, or images, and may require post-processing to extract key information. Industry-specific fields and units demand high accuracy during data parsing to prevent errors due to unit conversion or field misinterpretation. For instance, "number of beds" and "actual open beds" are distinct concepts. Additionally, sensitive data transmission requires considering encryption and authentication mechanisms, such as using `HTTPS` protocol and `OAuth2.0` authentication.

## Configuration Guidelines

| Configuration Item         | Recommended Value                               | Rationale                                                    |
| :------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `requestMethod`            | `POST` or `GET`                                 | Specified by the target external system API documentation. `POST` is for submitting data; `GET` is for retrieving data. |
| `requestURL`               | `https://api.example.com/hospital/data`         | The specific API endpoint provided by the external system. Ensure `HTTPS` protocol for secure transmission. |
| `headers.Authorization`    | `Bearer YourAccessToken`                        | The authentication token required by the external system, typically `OAuth2.0` or an API Key. |
| `timeout`                  | `60000` milliseconds                            | Considering potentially large data volumes, extend the timeout to prevent connection drops due to network latency or prolonged processing. |
| `requestBody`              | JSON format, including `hospitalId`, `reportDate`, etc. | Construct the request body according to the external system API documentation, precisely specifying the data range to retrieve. |
| `responseParserScript`     | Custom script to extract key fields and handle units | Parse the returned JSON/XML data, convert fields like "number of beds" to a format usable by FastGPT, and handle unit conversions. |

## Common Pitfalls

*   Receiving an `HTTP 401 Unauthorized` error after calling the interface indicates incorrect `headers.Authorization` parameter settings, or an expired or invalid Token.
*   Missing expected fields or empty field values in the interface's returned data may be due to incomplete query parameters in `requestBody`, or `responseParserScript` failing to correctly parse complex JSON structures.
*   Interface call timeouts after a long wait may be caused by an excessively short `timeout` setting, or a slow external system API that fails to return results within the specified time.

## Verification Steps

*   Manually trigger an HTTP interface call through FastGPT's debugging interface. Check if the returned `HTTP Status Code` is `200 OK`.
*   Examine key fields in the interface's returned results, such as "outpatient visits" and "number of beds." Confirm that the data structure and values match the original data from the external system.
*   Compare data imported into the FastGPT knowledge base with the external system data source. Perform sample checks for specific dates or departments to verify data completeness and accuracy.
