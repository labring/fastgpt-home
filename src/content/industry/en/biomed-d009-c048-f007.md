# Workflow Orchestration for Home Medical Device Registration

## Data Characteristics for This Category

Registration data for home medical devices comes from various sources. These include internal R&D records, production inspection reports, and clinical trial data. External sources include regulatory standards, guidance documents, and information on similar products. Data updates are frequent, especially with regulatory changes, technical standard updates, or product iterations. Document structures typically follow the National Medical Products Administration (NMPA) registration requirements. This includes modules such as product technical requirements, instructions for use, labels, risk management reports, and clinical evaluation data. Fields cover product performance parameters, safety indicators, electromagnetic compatibility, and biological evaluations. Units strictly adhere to national standards and the International System of Units (SI), such as `V` for voltage, `A` for current, and `℃` for temperature.

## Constraints Imposed by These Characteristics on "Workflow Orchestration"

The data characteristics of home medical device registration materials place specific demands on workflow orchestration. First, multi-source heterogeneous data requires flexible integration nodes to process data from different systems and departments into a unified format. Second, frequent regulatory updates demand workflows that can quickly respond and adapt. This means easy updates to parsing rules and data extraction logic. The standardized document structure makes structured information extraction nodes crucial within the workflow. These nodes ensure accurate identification and population of key fields. Finally, strict field and unit specifications necessitate refined processing in the data cleaning and validation stages. This prevents registration failures due to inconsistent units or incorrect value formats. The workflow must handle requirements for specific performance indicators and test methods, as defined in standards like the IEC 60601 series.

## Configuration Guidelines

| Configuration Item | Suggested Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Registration documents often include large images or test reports, requiring support for large file uploads. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Complex technical documents and scanned files take longer to parse, requiring ample processing time. |
| `Chunk size` | `800 characters` | Balances semantic completeness with recall efficiency, suitable for technical specifications and regulatory texts. |
| `Recall count` | `10` | Ensures coverage of multiple highly relevant information points in complex query scenarios. |
| `Similarity threshold` | `0.75` | Balances precision and recall, effectively filtering irrelevant content while avoiding omissions. |
| `Rerank result count` | `5` | Optimizes the sorting quality of final results, focusing on the most relevant and authoritative information. |

## Three Common Pitfalls

*   A workflow template import shows success, but the workflow content is empty. This usually indicates that the imported JSON file format is incompatible with the current FastGPT version or has structural errors.
*   The file parsing node remains unresponsive for an extended period. This appears as a stalled status after file upload. The common causes are incompatible file encoding or `PARSE_FILE_TIMEOUT_SECONDS` being set too short, leading to timeouts for large or complex files.
*   The code execution node fails to run Python code, resulting in errors or no output. This occurs when the runtime environment's Python interpreter is not configured correctly or required libraries are missing.

## How to Verify Correct Configuration

*   Upload a standard registration document containing multiple pages of tables and images. Check if the file parsing node correctly extracts key information and verify the consistency of extracted fields with the original document.
*   Simulate a regulatory update. Modify the parsing rules in the workflow and run tests to verify the workflow's adaptability to new rule changes.
*   For a test report containing special units (e.g., `mEq/L` or `dB`), check if the data cleaning and validation steps accurately identify and standardize these units. Observe the `output` field for verification.

The values provided are common starting points and should be measured against the reader's own samples.
