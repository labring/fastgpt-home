# Reference Sourcing and Traceability for Home Medical Device Registration

## Data Characteristics for this Category

Home medical device registration data comes from various sources. These typically include regulatory documents from the National Medical Products Administration (NMPA), technical review guidelines, registration application forms, product technical requirements, inspection reports, clinical evaluation data, risk management reports, user manuals, and public information on similar products.

Data update frequencies vary. Regulatory documents might revise every few years, while guidelines and application forms could update annually or irregularly. Document structures also differ. Regulatory documents are often PDFs, highly standardized, with clear chapters. Technical review guidelines focus on explaining specific requirements. Product technical requirements and inspection reports usually contain significant structured data, such as performance indicators, test methods, and units (e.g., mm, ℃, V, mA, dB, m/s). Clinical evaluation data may involve extensive unstructured text, like clinical literature reviews and data analysis reports.

## Constraints on "Reference Sourcing and Traceability"

The complexity of home medical device registration data imposes specific requirements on reference sourcing and traceability. Regulatory document authority demands precise citation; any deviation could lead to review failure. The update frequency of technical review guidelines requires the knowledge base to quickly synchronize with the latest versions and ensure citations point to currently effective clauses.

Structured data in product technical requirements and inspection reports requires precise extraction of values and units during citation, preventing misinterpretation due to ambiguous context. Unstructured text in clinical evaluation data requires stronger semantic understanding to locate relevant arguments within complex contexts. For error checking, the system must trace back to the specific page or paragraph of the original document, especially with multiple versions, to ensure unique and accurate citations.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| `maxContext` | `800–1200 characters` | Captures sufficient context for regulatory clauses or technical requirements while avoiding irrelevant information. |
| `Similarity Threshold` | `0.78–0.85` | Balances recall and precision, ensuring retrieved content is highly relevant to the query intent and avoids low-quality citations. |
| `Chunk Length` | `300–500 characters` | Accommodates longer paragraphs in regulatory documents and technical guidelines, ensuring semantic completeness. |
| `Reranked Results` | `Top 5` | Given the rigor of registration data, ensures the top few results are optimized and most relevant. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Accounts for parsing time of large PDF files (e.g., clinical evaluation reports), preventing file processing failures due to timeouts. |
| `Recall Count` | `10–15` | Broadens the scope during initial recall to cover more potentially relevant content for subsequent reranking. |

## Three Common Mistakes

*   Chat responses show internal reference information like `knowledge base search`, `input`, or `response` field content. This usually indicates incorrect frontend display logic, failing to filter out intermediate processes that are not final answers.
*   When citing a regulatory clause, the system returns an old or invalid version. This happens when the knowledge base is not updated promptly, or document version management has flaws, leading to a failure to prioritize the latest effective document during retrieval.
*   The response cites a performance parameter from an inspection report with the correct value but incorrect or missing units. This indicates insufficient precision in structured data extraction during document parsing and entity recognition, or a lack of unit standardization.

## How to Verify Correct Configuration

*   Submit a query about a specific regulatory clause. Check if the cited original text in the response precisely matches the latest version published on the National Medical Products Administration official website and can be traced to a specific chapter or page.
*   Ask about a performance parameter for a home medical device. Verify if the values and units provided in the response exactly match the data in the product technical requirements or inspection report.
*   Simulate a complex query with multiple keywords. Check if the returned references cover different types (e.g., regulations, technical requirements, clinical reports) and highly relevant document snippets, and verify their semantic coherence.
