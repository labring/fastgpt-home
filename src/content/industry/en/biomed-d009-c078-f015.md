# Deployment and Upgrades for Medical Device Registration Documentation

## Data Characteristics for This Category

Medical device registration documentation draws from diverse sources. These include product technical requirements, inspection reports, clinical evaluation reports, risk management reports, instruction manuals, labels, manufacturing process flowcharts, and software validation reports. Documents are typically in PDF, Word, or Excel formats, containing both structured and unstructured information. Data update frequency correlates with product lifecycle, regulatory revisions, and clinical feedback. For example, relevant documentation is revised when software versions upgrade, key components change, or indications expand. Document structures are complex, often including numerous charts, appendices, and cross-references. Fields include `measurement range`, `accuracy`, `alarm limits`, `EMC test results`, and `software version number`. Units include medical or engineering specific terms such as `mmHg`, `bpm`, `℃`, `kPa`, and `dBμV/m`.

## Constraints Imposed by These Characteristics on "Deployment and Upgrades"

Medical device registration documentation typically involves large data volumes, including extensive unstructured text, images, and tables. This necessitates a highly scalable deployment solution for data storage and processing to accommodate continuous data accumulation and future updates. The uncertain frequency of documentation updates, especially sudden updates due to regulatory or product changes, demands an incremental update mechanism for the knowledge base. This mechanism must support efficient partial updates to avoid prolonged downtime from full re-indexing. Complex document structures and diverse fields with varying units require more refined text segmentation strategies and robust entity recognition capabilities during the document parsing phase. For instance, for chart data in `EMC test reports`, simple text splitting may lead to critical information loss, requiring image recognition or table parsing techniques. Furthermore, stringent compliance requirements in the medical device sector mean any knowledge base upgrade must ensure data integrity, retrieval accuracy, and historical version traceability. Upgrades must not result in data loss or retrieval logic discrepancies.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Medical device registration documents often contain large PDFs or image files; this ensures seamless single-file uploads. |
| `Chunk size` (Segment Length) | `800–1200 characters` (characters) | Balances contextual relevance for long documents with retrieval efficiency, preventing semantic loss from overly short segments. |
| `Recall count` (Recall Count) | `Top 10 entries` (top 10) | Contextual relevance is high in registration documents; increasing recall count improves coverage of related information. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | The medical field demands high accuracy; increasing the threshold appropriately reduces irrelevant results. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` (seconds) | Large file parsing is time-consuming; this provides ample time to prevent parsing timeout failures. |
| `QUERY_REWRITE_ENABLE` | `true` | For complex technical terms and regulatory clauses, enabling query rewriting optimizes retrieval effectiveness. |

## Three Common Pitfalls

*   Knowledge base search time significantly increases. Investigation reveals that after an embedding model upgrade, some historical data was not re-embedded with the new model, leading to reduced retrieval efficiency.
*   Docker deployment fails to pull plugins. This usually indicates incorrect image source configuration in the `docker-compose.yml` file or improper network proxy settings, preventing connection to external repositories.
*   The database connection node does not allow port number input. This might be a front-end UI caching issue or a mismatch between the back-end service version and the front-end, leading to abnormal UI control rendering or data validation logic errors.

## How to Verify Correct Configuration

*   Upload a typical medical device registration document (e.g., a clinical evaluation report with charts and extensive technical terminology). Check if knowledge base segmentation is reasonable and if key information is correctly extracted.
*   Perform targeted retrieval queries. Compare the relevance and completeness of results across different questioning styles to confirm that the recall count and similarity threshold effects meet expectations.
*   Check system logs to confirm no timeout or error messages occurred during file parsing and that knowledge base construction and update operations completed successfully.
*   Simulate a minor version upgrade. Verify that existing knowledge base data remains accessible after the upgrade and that retrieval performance does not noticeably degrade.

The values given are common starting points and should be measured against the reader's own samples.
