# HTTP Interface and External Systems for Pharmacoeconomics Regulatory Submission Preparation

## Data Characteristics in this Category
Pharmacoeconomics data primarily originates from clinical trial reports, real-world study data, health technology assessment reports, cost-effectiveness analysis models, and literature databases. This data typically exists in structured tables (e.g., Excel, CSV), unstructured text (e.g., PDF reports, Word documents), and semi-structured data (e.g., XML-formatted economic model input parameters). Data update frequency is relatively low, mainly concentrated around research publication cycles before and after drug launch, usually every six months to a year. Documents contain extensive specialized terminology, units (e.g., USD/QALY, %), statistical indicators (e.g., confidence intervals, P-values), and complex model parameters.

## Constraints Imposed by these Characteristics on "HTTP Interface and External Systems"
The diverse sources of pharmacoeconomics data require external system integration to support parsing multiple data formats. The infrequent data updates mean real-time requirements are relatively relaxed. However, data completeness and accuracy are critically important. Interface design must therefore focus on data validation and error traceability mechanisms. The complex specialized terminology and statistical units in documents require interfaces to effectively identify and maintain semantic accuracy during data extraction and vector conversion, preventing misunderstandings caused by unit or indicator confusion. Additionally, documents are often large, potentially containing charts and complex tables. This challenges the interface's file processing capabilities and timeout settings, necessitating longer processing times and larger file upload limits.

## Configuration Settings

| Configuration Item             | Recommended Value                               | Rationale                                                    |
| :----------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`         | `500 MB`                                        | Pharmacoeconomics reports often contain numerous charts and detailed data, resulting in large file sizes. |
| `PARSE_FILE_TIMEOUT_SECONDS`   | `600 seconds`                                        | Processing complex PDFs and Word documents, including chart, table, and text extraction, is time-consuming. |
| `Chunk size` (Segment Length)    | `800–1200 characters`                                 | Ensures individual segments contain sufficient context while avoiding excessive length that could lead to semantic drift. |
| `Recall count` (Recall Count)      | `Top 10 entries` (Top 10)                             | Pharmacoeconomics concepts are highly interconnected; increasing the recall count improves coverage of relevant information. |
| `Similarity threshold` (Similarity Threshold) | `0.75`                                          | Guarantees the professionalism and precision of recalled content, filtering out irrelevant or generalized information. |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `120 seconds`                                        | External data sources may respond slowly; this provides ample time to prevent connection timeouts. |

## Three Common Mistakes
1. External system calls return a 404 error because the API path or authentication information is incorrectly configured.
2. API calls return empty data fields or incorrect formats because the interface has lax data structure validation, failing to effectively handle non-standard output from external data sources.
3. Document processing times out after upload because `PARSE_FILE_TIMEOUT_SECONDS` is set too short, unable to handle parsing large or complex documents.

## How to Verify Configuration
1. Upload a typical pharmacoeconomics PDF report. Check if it successfully parses and splits into reasonable segments.
2. Call an external data source via API. Verify if the returned key field values and units match expectations.
3. Simulate concurrent requests. Verify system stability when handling multiple external interface calls and check response times.
