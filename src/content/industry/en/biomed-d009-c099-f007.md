# Workflow Orchestration for Telemedicine Registration Document Preparation

## Data Characteristics in This Category

Telemedicine registration documents integrate data from multiple systems. These include electronic health record systems, telemedicine platforms, medical device data interfaces, and clinical trial databases. Data updates frequently. Patient treatment records may update in real-time, while regulatory policy documents release quarterly or annually. Document structures typically follow standardized templates, such as the NMPA's medical device registration application form, clinical evaluation reports, and product technical requirements. Unstructured text, like expert opinions and ethical approval documents, is also common. Fields and units vary. Clinical data often includes physiological parameters in SI units, such as blood pressure (mmHg) and heart rate (bpm). Regulatory documents may involve specific terminology and codes, such as medical device classification codes.

## Constraints Imposed by These Characteristics on Workflow Orchestration

High update frequency in telemedicine data requires workflows to trigger in real-time or near real-time. This captures the latest treatment data and policy changes, ensuring the timeliness of registration documents. Diverse and heterogeneous data sources mean workflows need robust data integration and cleansing capabilities. This unifies data formats and semantics across different systems, for example, mapping patient IDs from various EHR systems. Standardized templates demand precision from document generation nodes within the workflow. Strict adherence to template structures and field specifications is necessary. The high proportion of unstructured text requires workflows to process natural language effectively. This includes text summarization and entity extraction to distill key information from expert opinions. Fields with specific terminology and codes require accurate standardization and validation during data processing to meet regulatory requirements.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `FETCH_DATA_INTERVAL_SECONDS` | `300` | Addresses the high update frequency of telemedicine data, ensuring timely acquisition of the latest information. |
| `MAX_FILE_SIZE_MB` | `50` | Accommodates potentially large image or report files included in telemedicine registration documents. |
| `CHUNK_SIZE_TOKENS` | `800–1200` | Balances semantic completeness for long documents and model processing efficiency, especially for clinical evaluation reports. |
| `RETRIEVAL_TOP_K` | `5` | For regulatory and technical documents, precise recall of a few relevant items is often better than recalling many vague ones. |
| `SIMILARITY_THRESHOLD` | `0.75` | Requires a high degree of matching for specialized medical terminology, ensuring the accuracy of retrieved content. |
| `RELEVANCE_SCORE_THRESHOLD` | `Calibrated by actual measurement` | Adjust through testing to optimize retrieval results for the specific complexity of registration documents. |

## Common Pitfalls

*   Workflow execution times out or interrupts, with logs showing `HTTP 504 Gateway Timeout`. This occurs due to slow data source interface responses or excessive processing time for a single node when handling large unstructured documents.
*   Some fields in the generated registration documents are empty or incorrectly formatted. This usually results from incomplete data cleansing or mapping rules, failing to correctly identify or convert fields from different systems. It also happens when filling standardized templates without strict type validation for specific fields.
*   Despite configuring global variables, tool call variable values do not update as expected. This might be due to improper variable scope or update trigger logic configuration. For example, the variable update occurs after the tool call, or the global variable tool call update mechanism is not correctly configured in `V4.9.7` and later versions.

## How to Verify Configuration

*   Regularly check workflow execution logs. Confirm all nodes complete successfully and no `ERROR` or `WARN` level exceptions occur.
*   Randomly sample generated registration documents. Compare them against original data sources. Verify the accuracy, completeness, and format compliance of key field content.
*   Perform end-to-end testing. Simulate the entire registration process. Validate the complete workflow from data acquisition to final document generation. Observe whether global variable values pass and update as expected during tool calls.

The values provided are common starting points and should be measured against your own samples.
