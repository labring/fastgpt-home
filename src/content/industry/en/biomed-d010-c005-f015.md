# Deployment and Upgrade for CSO R&D Document Structural Analysis

## Data Characteristics

CSO (Chief Scientific Officer) R&D documents in the biopharmaceutical sector typically include project initiation reports, research protocols, experimental records, data analysis reports, preclinical study reports, and patent application files. These documents are primarily in PDF, Word, or Markdown formats. Their internal structure varies, often containing numerous charts, chemical structures, and biological sequence information. Data sources mainly include internal R&D platforms, Laboratory Information Management Systems (LIMS), and external collaborators. Update frequency varies by R&D stage; early-stage projects might update weekly, while clinical stages might update monthly or quarterly. Document fields include compound ID, experimental batch, dosage, result indicators (e.g., IC50, EC50), units (e.g., nM, mg/kg, %), and complex biostatistical data.

## Constraints Imposed by These Characteristics on Deployment and Upgrade

The complex structure and diverse formats of CSO R&D documents demand advanced document parsing capabilities. Deployment requires ensuring that the parsing service can effectively identify and extract charts, chemical structures, and biological sequence information. This may necessitate specific preprocessing modules and OCR capabilities. The semi-structured nature of the documents means flexible text segmentation strategies are needed to avoid splitting critical information. The uncertain data update frequency requires the system to support incremental updates and version management to accommodate R&D iterations. Furthermore, the specificity of fields and units, such as IC50 in nM, requires semantic understanding and standardization during data indexing and querying to prevent recall errors due to unit mismatches. For private deployments, ensuring seamless integration of these parsing and indexing capabilities during upgrades is crucial.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | CSO documents, especially experimental reports, can contain large embedded charts and data, leading to larger file sizes. |
| `Chunk size` (Segment Length) | `800–1200 characters` (characters) | Ensures logical completeness of key experimental steps and result analyses, preventing semantic fragmentation. |
| `maxContext` | `8192` | Accommodates complex R&D backgrounds and multi-turn conversations, providing longer context understanding. |
| `Recall count` (Recall Count) | `10 entries` (items) | Given the complexity of R&D questions, increasing recall helps cover more relevant but indirect experimental records. |
| `Similarity threshold` (Similarity Threshold) | `0.75–0.85` | Balances recall accuracy and completeness, reducing interference from irrelevant information while avoiding missing critical experimental data. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` (seconds) | Parsing large PDFs or Word documents with complex charts can be time-consuming. |

## Common Pitfalls

*   Document parsing timeout or partial content missing: This occurs when `PARSE_FILE_TIMEOUT_SECONDS` is set too low, preventing large or complex documents from being parsed within the allotted time.
*   Knowledge base file details show "Invalid dataset file key": This is a common issue after private deployment upgrades, usually due to incompatibility between the data storage layer and the new version's file indexing mechanism. Database migration scripts should be checked for correct execution.
*   API key duration or usage limits cannot be set: This indicates that the deployed version might not include or have enabled the advanced permission management module. Confirm the feature set supported by the current version.

## Verification Steps

*   Upload and parse a typical R&D report containing charts and chemical structures. Check if the parsed segments are complete and logically continuous.
*   Perform a simulated document update operation. Verify that incremental indexing is successful and that the latest modified content can be retrieved.
*   For complex queries, such as "IC50 value of compound XYZ at a certain dose," check if the returned results accurately include the compound ID, IC50 value, and corresponding units.
