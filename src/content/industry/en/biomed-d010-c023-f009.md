# Reference and Traceability for Structured Analysis of Deviation and CAPA R&D Documents

## Data Characteristics

Deviation and Corrective and Preventive Action (CAPA) documents are critical in biopharmaceutical R&D. Data sources include internal Quality Management Systems (QMS), Manufacturing Execution Systems (MES), Laboratory Information Management Systems (LIMS), and audit reports. These documents typically exist as PDFs, Word files, or structured database records. Update frequency correlates with deviation events and CAPA implementation progress. This can range from multiple times daily (e.g., minor production line deviations) to monthly (e.g., phased reports for complex CAPA plans). Document structure is highly standardized, generally adhering to regulatory requirements such as GMP/GLP/GCP. Common fields include event descriptions, root cause analyses, corrective actions, preventive actions, responsible parties, planned completion dates, actual completion dates, and status. Timestamps, batch numbers, equipment IDs, product codes, and operator IDs are frequent and critical fields.

## Constraints from "Reference and Traceability"

The standardized structure and high update frequency of Deviation and CAPA documents demand high accuracy and timeliness from reference and traceability features. The richness and interconnectedness of fields require preserving sufficient contextual information during knowledge base chunking and vectorization. This supports precise root cause identification and action traceability. For example, citing only a deviation description does not provide a complete traceability path; associated batch numbers, equipment IDs, and responsible personnel must be included. High update frequency requires the knowledge base to quickly synchronize with the latest document content. This ensures the validity of references and prevents citing outdated or revised CAPA plans. Furthermore, regulatory compliance necessitates precise marking and verifiability of reference sources. Ambiguous or incorrect references can lead to compliance risks. Therefore, when generating answers, the system must accurately point to specific paragraphs in original documents and provide clear document identifiers.

## Configuration Strategy

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------- |
| `Chunk size`         | `300–500 characters`    | Paragraphs in Deviation and CAPA documents usually contain complete logical units. This length helps retain critical fields and context without diluting information by being too long. |
| `Chunk Overlap Length`     | `50 characters`         | Ensures continuity of critical information across segments (e.g., event description and root cause), improving recall accuracy. |
| `Recall count`         | `5–8 entries`          | In Deviation and CAPA scenarios, traceability requires multiple perspectives (event, cause, action). Increasing recall quantity helps ensure comprehensive coverage. |
| `Similarity threshold`       | `0.75–0.85`       | Deviation and CAPA questions demand high answer precision. A high threshold helps filter irrelevant content, improving matching accuracy. |
| `Rerank result count`     | `3 entries`            | After reranking, selecting a small number of the most relevant items for citation focuses on core information and reduces unnecessary interference. |
| `maxContext`       | `3000–4000 token` | Ensures sufficient space for recalled content and conversation history, supporting contextual understanding for complex deviation analysis. |

## Common Pitfalls

- Answers do not display reference sources, or reference sources point to irrelevant documents. This often results from overly large knowledge base chunking granularity or a similarity threshold set too low, leading to the recall of significant noise.
- Reference sources point to old or obsolete CAPA documents. This occurs when knowledge base content is not updated promptly and fails to synchronize with source systems.
- Reference document segments are too long or too short, failing to provide effective context. This may relate to improper `Chunk size` settings, leading to incomplete information cuts or excessive fragmentation.

## How to Verify Configuration

- Randomly select several Q&A pairs. Check if the displayed reference sources in the answers accurately point to relevant paragraphs in the original documents, providing document names, version numbers, or specific section identifiers.
- Verify that when a new version of a deviation or CAPA document is released, the knowledge base synchronizes within the preset time. Ensure subsequent Q&A references the latest version.
- For deviation questions involving multi-step analysis, check if the multiple pieces of recalled content form a logical chain that supports the conclusion. Also, verify that the `Chunk size` for each piece of content is appropriate and that the context is complete.

The values provided are common starting points and should be measured against specific samples.
