# Document Parsing and Chunking for R&D Documentation in Culture Media and Consumables

## Data Characteristics for this Category

R&D documentation for culture media and consumables primarily includes internal experimental records, vendor technical manuals, quality control reports, and relevant research papers. These documents are updated frequently, especially for new product batches or improved formulations. Technical manuals typically have a fixed structure, including sections like product overview, component lists, preparation methods, quality standards, and storage conditions. Experimental records often consist of time-series experimental steps, observations, and data charts. Common fields include chemical names, concentrations (e.g., `g/L`, `mM`), pH values, temperatures (`℃`), batch numbers, and expiration dates. Units are diverse and sometimes use non-standard abbreviations.

## Constraints from these Characteristics on Document Parsing and Chunking

The characteristics of R&D documentation for culture media and consumables impose specific requirements on document parsing and chunking. Diverse document sources and frequent updates necessitate flexible file upload and incremental parsing mechanisms to ensure the knowledge base's timeliness. The fixed section structure within documents, such as vendor manuals, suggests a pre-processing chunking strategy based on section titles to improve semantic completeness. However, the free-form and time-series nature of experimental records requires finer-grained text segmentation to avoid overly long chunks that introduce redundancy or overly short chunks that lose context. Chemical formulas and units (e.g., `µM`, `% (w/v)`) within fields require the parser to accurately identify and retain these special characters, preventing incorrect truncation or encoding issues during chunking.

## Configuration Settings

| Configuration Item         | Recommended Value    | Rationale                                          |
| :------------------------- | :------------------- | :------------------------------------------------- |
| `Chunk size`                 | `500–800 characters`       | Balances context completeness and retrieval efficiency, suitable for experimental records and technical manuals. |
| `Chunk Overlap Length`             | `50–100 characters`        | Ensures contextual continuity between adjacent chunks, handling key information that spans paragraphs. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds`             | Accommodates parsing time for large technical manuals or PDFs with complex diagrams. |
| `maxContext`               | `8192`               | Adapts to specialized terminology and experimental details, ensuring broad comprehension by the large language model. |
| `PDF_PARSE_STRATEGY`       | `ocr` or `auto`      | Most vendor manuals are scanned images; `ocr` ensures complete text extraction. |
| `Knowledge Base Preprocessing Rule`         | `Chunk by Title`         | For the fixed section structure of technical manuals, maintains clear semantic boundaries. |

## Three Common Mistakes

*   After uploading a large PDF file, the parsing status shows "failed" or "timed out." This usually happens when the `PARSE_FILE_TIMEOUT_SECONDS` parameter is set too low, not allowing the parser enough time to process complex document structures or large image content.
*   In retrieval results, chemical formulas or units appear as garbled text or are incomplete. This may be due to encoding incompatibility when the document parser handles special characters (e.g., `µ`, `²`), or truncation within a character during chunking.
*   When calling the knowledge base API, specified parsing parameters do not take effect, and the file is still processed with default settings. This typically occurs due to misspellings of parameter names in the API request body, or type mismatches for parameter values, preventing the backend from correctly recognizing the parsing configuration.

## How to Confirm Correct Configuration

*   Upload a typical culture medium technical manual and an experimental record. Check if the parsed chunks are semantically complete and free of obvious truncation errors.
*   Parse a document containing special units and chemical formulas. Verify that these special symbols and values are correctly retained in the extracted text.
*   Upload a file via the API and specify a parsing strategy. Check logs or verify through retrieval to confirm that custom parsing parameters (e.g., `PDF_PARSE_STRATEGY`) have taken effect as expected.
*   Simulate a query containing key technical parameters (e.g., a specific concentration `5 g/L`). Check if the retrieved results include the corresponding information and evaluate its accuracy.

The values provided are common starting points and should be measured against the reader's own samples.
