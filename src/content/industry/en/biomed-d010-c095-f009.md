# Reference Sourcing and Traceability for Quality Document Management in R&D

## Data Characteristics for This Category

Quality documents in biopharmaceutical R&D include batch production records, inspection records, validation reports, Standard Operating Procedures (SOPs), deviation handling, change control, and risk assessments. These documents are typically stored as PDFs, Word files, or Excel files within internal enterprise document management systems (e.g., LIMS, QMS). Data update frequency is relatively stable, primarily occurring during batch production, process changes, regulatory updates, or periodic audits. Document structure is highly standardized, adhering to regulatory requirements such as GMP and GLP. They contain numerous tables, diagrams, signature and date fields, specialized terminology, and abbreviations. Fields and units are strictly defined according to pharmacopoeias or industry standards, for example, batch number, production date, expiration date, inspection items, result values, and units (mg/L, IU/mL, pH value).

## Constraints Imposed by These Characteristics on "Reference Sourcing and Traceability"

The high standardization and regulatory compliance requirements of quality documents mandate that reference sourcing and traceability ensure completeness, accuracy, and contextual relevance. For instance, an operation step in an SOP must trace back to a specific version, revision date, and approver to meet audit requirements. The extensive tabular data and specialized terminology in documents demand high-precision structured parsing capabilities. This ensures key fields (e.g., batch number, inspection results, judgment criteria) are accurately identified and referenced. Although the update frequency is not high, once updated, older document versions must retain their traceability, and differences between old and new versions need clear identification. Furthermore, precise identification of specific fields and units directly impacts the reliability of referenced content, preventing quality risks due to unit confusion or misinterpretation of values.

## Configuration Settings

| Configuration Item | Suggested Value | Rationale for This Value |
| --- | --- | --- |
| `maxContext` | `1000–1500 characters` | Quality document paragraphs are often long and contextually rich; sufficient context length is needed to capture complete logic. |
| `Recall count` (Recall Count) | `8–12 items` | Given the professional and rigorous nature of quality documents, increasing the recall count enhances the coverage of relevant retrievals. |
| `Similarity threshold` (Similarity Threshold) | `0.75–0.85` | Quality document terminology is precise; a higher threshold filters out semantically imprecise matches, ensuring reference accuracy. |
| `Rerank result count` (Reranked Return Count) | `3–5 items` | After reranking, the most relevant items are selected, improving the quality and efficiency of references presented to the engineer. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600–900 seconds` | Quality documents often contain many images and tables, making parsing time-consuming; ample time is reserved to prevent parsing timeouts. |
| `Chunk size` (Chunk Length) | `300–500 characters` | An appropriate chunk length helps maintain the integrity of sentences or paragraphs in quality documents, reducing semantic fragmentation. |

## Three Common Pitfalls

*   The number of reference items returned by the model does not match the number actually sent to OneAPI. This often occurs because `maxContext` is set too low, causing the context sent to the model to be truncated internally, while the number of knowledge base chunks recalled remains unchanged.
*   The reference upper limit for knowledge base chunks (e.g., `maxContext`) is set to 1500 characters, but actual referenced chunks sometimes exceed 1500 characters. This can happen if the system, during chunking, allows individual knowledge chunks to slightly exceed the set length to ensure semantic integrity.
*   The system fails to correctly extract batch numbers and production dates when parsing a batch production record. This is due to OCR errors caused by document structure or font recognition issues, or because the parsing model has not been optimized for specific quality document templates.

## How to Verify Configuration

*   Select a representative batch of SOPs, batch production records, and inspection reports. Upload them and verify their structured parsing results, checking if key fields (e.g., batch number, expiration date, inspection results) are accurately extracted.
*   For complex queries, check if the reference sources returned by the model point to specific page numbers or paragraphs within the document. Verify the contextual relevance of the referenced content to the query.
*   Simulate a typical audit scenario. Submit a query about a quality issue for a specific batch product. Evaluate whether the system provides a clear and complete reference traceability path that supports decision-making.

Note that the values provided are common starting points and should be measured against the reader's own samples.
