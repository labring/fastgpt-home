# Lead Synchronization for Private Domain Consulting Conversion: HTTP Interface and External Systems

## Data Characteristics for This Category

Lead synchronization in the biopharmaceutical industry typically refers to potential customer information obtained from various marketing activities, online platforms, or partnership channels. This data is primarily structured, often in JSON or XML documents, and includes fields like name, contact information, intended product, consultation time, and source channel. Data update frequency is high, potentially generated in real-time during activities or synchronized in batches daily or hourly. Field names often include industry-specific abbreviations, such as `patientID`, `drugCode`, and `trialPhase`. Contact information fields may involve multiple dimensions, such as `mobile` phone number, `email`, and `wechatId`. The intended product field is usually an enumerated value corresponding to specific drugs or services, such as `product_A_therapy`.

## Constraints Imposed by These Characteristics on the "HTTP Interface and External Systems" Component

The high real-time requirement for lead data necessitates low latency and high availability for the HTTP interface. This ensures new leads quickly enter the private domain consulting process. The structured nature of the data dictates that interface design must precisely map fields to prevent data loss or parsing errors. Diverse source channels may lead to subtle differences in data formats across various interfaces, requiring a unified adaptation layer or multiple interface configurations. The presence of industry-specific fields means their semantics must be preserved during data transmission and storage to avoid information distortion from generic field mapping. Additionally, due to user privacy concerns, data transmission must use HTTPS encryption, and sensitive fields must be desensitized to ensure compliance.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `HTTP_METHOD` | `POST` | Lead data is typically created or updated as new resources; the POST method aligns better with this semantic. |
| `CONTENT_TYPE` | `application/json` | JSON format is lightweight and easy to parse, making it the current mainstream API data exchange format. |
| `REQUEST_TIMEOUT_SECONDS` | `10` | Ensures the interface responds within a reasonable time, preventing lead backlog due to network delays. |
| `RETRY_COUNT` | `3` | Addresses temporary network fluctuations or momentary service unavailability, improving lead synchronization success rates. |
| `MAX_PAYLOAD_SIZE_MB` | `2` | Limits the size of a single request body, preventing oversized requests from impacting interface performance or being rejected by the server. |
| `AUTH_HEADER` | Calibrate based on actual testing | Configure according to the authentication mechanism required by the external system, such as `Bearer Token` or `Basic Auth`. |

## Three Common Mistakes

*   The external system returns an `HTTP 500 Internal Server Error`, but FastGPT fails to effectively capture specific error information. This usually occurs because the external interface's error response body does not return in the expected format, preventing FastGPT from parsing it.
*   After lead data synchronization, some key fields in the external system are empty or incorrect. This happens when FastGPT's HTTP request body field names do not match the external system's interface requirements, or data type conversion is incorrect.
*   Synchronization requests frequently time out, leading to a large backlog or loss of leads. This may be due to insufficient processing capacity of the external system interface or FastGPT sending too many concurrent requests without proper rate limiting.

## How to Verify Correct Configuration

*   Check FastGPT's debug logs to ensure the HTTP request `URL`, `Header`, and `Body` align with the external system's API documentation.
*   Manually trigger a lead synchronization in FastGPT and log into the external system to verify that the corresponding lead data is completely and accurately created or updated.
*   Simulate high-concurrency scenarios to observe FastGPT's synchronization queue processing and the external system interface's response time, ensuring interface stability under expected load.
