# Follow-up Reminder for Private Domain Consultation Conversion: Sharing and Embedding

## Data Characteristics for This Category

In private domain consultation conversion scenarios within the biomedical sector, follow-up reminder data originates from patient consultation records, physician diagnostic suggestions, medication usage feedback, and periodic follow-up results. This data is stored in structured and semi-structured formats, such as consultation platform logs, CRM system records, and electronic medical record snippets. Data updates frequently; new consultations, feedback, and follow-up results are recorded in real-time or near real-time. Document structures typically include fields like patient ID, consultation time, consultation content summary, reminder type (e.g., medication reminder, follow-up appointment reminder, check-up reminder), reminder time, associated physician, and associated medication. Time fields are usually precise to the second. Medication dosage fields include units such as `mg` or `ml`. Check-up result fields may contain ranges or enumerated values.

## Constraints Imposed by These Characteristics on "Sharing and Embedding"

The high real-time requirement of follow-up reminder data necessitates that shared and embedded content responds quickly to data updates, preventing information lag. Structured and semi-structured data characteristics mean that sharing requires careful attention to accurate field mapping and display logic, especially for sensitive information like dosage and time units, to ensure data consistency. For example, embedded reminder cards should accurately display `next medication time` and `medication dosage`. The nature of private domain consultations demands a strong focus on privacy protection and identity authentication for data sharing and embedding, ensuring that only authorized users can access specific patient follow-up reminders. Furthermore, since data may originate from multiple systems, embedded content requires good compatibility to aggregate and display information from different sources, and to properly handle potential cross-domain access issues.

## Configuration Settings

| Configuration Item   | Recommended Value         | Rationale                                                                |
| :------------------- | :------------------------ | :----------------------------------------------------------------------- |
| `token_expiration`   | `3600 seconds`            | Balances security and user experience by setting an appropriate authentication token validity period. |
| `refresh_interval`   | `300 seconds`             | Ensures embedded content reflects the latest follow-up reminder status promptly. |
| `maxContext`         | `800 characters`          | Adapts to the limited display space of reminder cards, highlighting key information. |
| `callback_url`       | Based on actual business address | Used for redirection after successful authentication, ensuring workflow completeness. |
| `iframe_sandbox`     | `allow-scripts allow-same-origin` | Restricts permissions of embedded content, enhancing security.            |
| `data_fields_map`    | Determined by actual testing | Ensures fields from different sources are correctly mapped to the display template. |

## Three Common Mistakes

*   Embedded content appears blank, or some data is missing. This often results from cross-domain security policies, where the `iframe`'s `sandbox` attribute is too strict, blocking internal scripts or data loading.
*   Users are repeatedly prompted to log in when accessing embedded follow-up reminders. This may be due to `token_expiration` being set too short, or an incorrectly configured authentication callback URL, leading to an ineffective maintenance of the authentication state.
*   Time or dosage units in reminder content are displayed incorrectly. The cause is typically improper `data_fields_map` configuration, failing to correctly process unit information from the data source or to perform necessary format conversions.

## How to Verify Correct Configuration

*   On different browsers and devices, access the embedded page as both an anonymous user and an authorized user. Check if all follow-up reminder information displays completely and without requiring repeated logins.
*   Simulate data updates, such as changing a patient's medication time. Observe whether the reminder information in the embedded page automatically refreshes within the `refresh_interval`.
*   Check the browser developer tools console to confirm no error messages related to cross-domain issues, security policies, or data loading appear (e.g., `CORS error`, `Refused to display`).
