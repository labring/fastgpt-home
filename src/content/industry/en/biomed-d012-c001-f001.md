# HTTP Interface and External Systems for CAR-T Cell Therapy Pharmacovigilance

## Data Characteristics

CAR-T cell therapy pharmacovigilance data comes from clinical trial reports, real-world evidence (RWE), patient follow-up records, healthcare institution reports, and regulatory post-market surveillance databases. Data typically exists in structured (e.g., database records, XML), semi-structured (e.g., clinical notes in electronic medical records, PDF reports), and unstructured (e.g., free-text descriptions) formats. Data updates frequently, especially during initial market release and critical clinical trial phases. Document structures are complex, often including patient demographics, treatment regimens, adverse event (AE) descriptions, severity, onset time, outcomes, related laboratory test results, and concomitant medications. Specific fields include immune effector cell-associated neurotoxicity syndrome (ICANS) grading and cytokine release syndrome (CRS) grading, unique to cell therapy, along with CAR-T product batch numbers, infusion dosages, and cell viability. Units involve time and dosage, such as `days`, `hours`, and `μg/kg`.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems

The high update frequency of CAR-T cell therapy data requires HTTP interfaces to support efficient real-time or near real-time data synchronization mechanisms, such as timestamp-based incremental pulling or event-driven pushing. Diverse and complex document structures mean interfaces need flexible data parsing capabilities to handle various input formats and perform initial extraction and standardization of semi-structured and unstructured data. Specific fields like ICANS and CRS grading, and product batch numbers, must have their data types, enumeration values, or validation rules clearly defined during interface design to ensure data transfer accuracy and integrity. Data volumes are often large, requiring high throughput and stability from interfaces. Additionally, involving sensitive patient information, interfaces must strictly adhere to data security and privacy protocols, such as HTTPS encrypted transmission.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 seconds` | Addresses external system data transfer delays, preventing frequent timeouts due to brief network fluctuations or processing time. |
| `MAX_RETRY_ATTEMPTS` | `3` | Allows retries during transient network failures or temporary external system unavailability, improving data synchronization success rates. |
| `DATA_PULL_INTERVAL_MINUTES` | `15 minutes` | Balances data real-time requirements with external system load, suitable for incremental data updates. |
| `BATCH_SIZE_RECORDS` | `500` | Optimizes the amount of data per request, reducing external system processing pressure while maintaining transfer efficiency. |
| `ERROR_NOTIFICATION_EMAIL` | `alert@yourdomain.com` | Ensures timely notification to relevant personnel for interface failures. |
| `AUTHENTICATION_METHOD` | `OAuth 2.0` | Provides a secure authentication mechanism to protect data transfer security. |

## Common Pitfalls

*   HTTP interface returns `504 Gateway Timeout` errors when external systems fail to respond in time due to complex queries or large data volumes.
*   Some adverse event report fields are empty because the external system's returned data structure does not match the interface's expectations, or the data parsing logic fails to correctly handle optional fields.
*   Key ICANS or CRS grading information cannot be correctly identified after the interface receives data, indicating the interface is not adapted to the specific grading system for CAR-T cell therapy.

## Verification Steps

*   Simulate requests to the HTTP interface to verify successful reception and parsing of a complete report containing at least one CAR-T cell therapy adverse event.
*   Check the log system to confirm that the interface does not experience timeout errors exceeding the `HTTP_REQUEST_TIMEOUT_SECONDS` setting under varying data volumes and network conditions.
*   Cross-reference successfully imported data. Randomly select 10 records and verify that their ICANS grading, CRS grading, CAR-T product batch numbers, and other key fields are accurately mapped to the FastGPT knowledge base and match the original data.
