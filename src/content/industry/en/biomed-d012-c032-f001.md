# HTTP Interface and External Systems for Medical Insurance Settlement Drug Surveillance

## Data Structure for this Category

Medical insurance settlement data originates from medical insurance bureaus, healthcare institutions, or third-party settlement platforms. This data is typically provided in structured formats like XML, JSON, or CSV, transmitted via standardized interfaces. Data updates are frequent, usually batched daily or weekly, to reflect the latest settlement records. The document structure for medical insurance settlement data typically includes patient basic information, diagnostic information (e.g., ICD-10 codes), drug information (e.g., national medical insurance drug catalog codes, generic names, dosage forms, specifications, manufacturers), expense details (unit price, quantity, total amount), and settlement status. Drug and diagnostic information are critical for drug surveillance analysis; their coding systems and standards must strictly adhere to national regulations. Expense units are typically "Yuan" (CNY), precise to two decimal places.

## Constraints Imposed by these Characteristics on the "HTTP Interface and External Systems" Component

The high update frequency of medical insurance settlement data requires the HTTP interface to have efficient concurrent processing capabilities and stable connections. Structured data formats mean that interface configuration must precisely define field mappings for request and response bodies to ensure correct data parsing. For example, the standardization of drug and diagnosis codes necessitates strict data cleaning and validation during the Extract, Transform, Load (ETL) phase. The precision requirement for expense units means avoiding floating-point calculation errors during data processing. Additionally, diverse data sources may lead to subtle differences in interface specifications across platforms, requiring specific adjustments to `URL` paths, `HEADER` parameters, and authentication methods to accommodate various external systems. For sensitive patient information, the interface must support secure transmission protocols, such as HTTPS, and may require additional encryption or anonymization, which increases the complexity of interface calls and data processing.

## Configuration Guidelines

| Configuration Item          | Recommended Value | Rationale                                                                                                                                                                                                                                                                          |
| :-------------------------- | :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HTTP_METHOD`               | `POST`            | Medical insurance settlement data is voluminous and often contains sensitive information. The `POST` method is more suitable for transmitting complex data bodies and ensuring data security.                                                                                    |
| `CONNECT_TIMEOUT_SECONDS`   | `30 seconds`      | Most medical insurance settlement system interfaces respond within a few seconds. This value prevents long waits while allowing for some network latency.                                                                                                                         |
| `READ_TIMEOUT_SECONDS`      | `60 seconds`      | Considering batch data transfer and backend processing times, `60 seconds` covers most normal response scenarios.                                                                                                                                                              |
| `MAX_RETRIES`               | `3 times`         | Temporary network fluctuations or momentary high server load can cause failures. Appropriate retries can improve the success rate.                                                                                                                                             |
| `AUTH_TYPE`                 | `Bearer Token`    | Medical insurance settlement systems often use OAuth 2.0 or JWT for authentication. `Bearer Token` is a mainstream and secure authentication method.                                                                                                                            |
| `DATA_SCHEMA_VERSION`       | `V2.1.0`          | Explicitly specifying the data interface version ensures that the parser matches the data structure, preventing field parsing errors due to version discrepancies.                                                                                                               |

## Three Common Mistakes

*   **Symptom:** The interface returns a 401 Unauthorized error code. **Reason:** The `Bearer Token` in the `Authorization` header has expired or is incorrect, failing external system authentication.
*   **Symptom:** Drug name or diagnosis code fields are empty in the returned data. **Reason:** The field names in the external system interface do not match the field mappings configured in FastGPT, or data was truncated during transmission.
*   **Symptom:** The system shows calculation discrepancies when processing medical insurance settlement data amounts. **Reason:** The unit of currency in the original data was not correctly identified or processed, leading to floating-point precision issues or unit conversion errors.

## How to Confirm Correct Configuration

*   After calling the interface, check if the HTTP response status code is 200 OK to confirm successful interface connection.
*   Check key fields in the returned data, such as `drug_code`, `diagnosis_code`, and `total_amount`, to ensure they have values and correct formats.
*   Perform end-to-end testing with a small sample of data. Compare the data parsed in FastGPT with the original medical insurance settlement data to ensure they are identical, especially for monetary and code-based fields.
