# Workflow Orchestration for CAR-T Cell Therapy Quality Documents

## Data Characteristics in This Category
CAR-T cell therapy quality document data originates from internal pharmaceutical company sources: production control, quality inspection, clinical trial reports, and regulatory submission materials. These documents include batch production records, inspection reports, deviation management, change control, validation reports, and supplier audit records. Data updates are frequent, especially before batch release, when relevant inspection data is entered. Document structures typically follow GMP/GCP guidelines, existing as PDFs, Word documents, or structured database records. They contain numerous tables, charts, and text descriptions. Fields and units are highly specialized, such as cell counts (`cells/µL`), viral load (`copies/mL`), transduction efficiency (`%`), sterility test results (`CFU/mL`), and endotoxin levels (`EU/mL`). Strict requirements apply to numerical precision and unit consistency.

## Constraints Imposed by These Characteristics on "Workflow Orchestration"
The specialized nature and high update frequency of CAR-T cell therapy quality documents impose specific requirements on workflow orchestration. First, the large number of specialized terms and abbreviations in documents requires customized glossaries and entity recognition models to ensure accurate information extraction. Second, the strong correlation between batch production records and inspection reports demands workflows capable of handling cross-document references and validation. An example is comparing key parameters in batch production records with results in inspection reports. Due to frequent data updates, workflows must support incremental updates and version control to ensure processing of the latest data. Additionally, strict regulatory compliance requires workflows to have audit trail capabilities, recording each document processing, information extraction, and decision-making step for traceability and verification. The strict requirements for precision and units make numerical parsing and unit conversion modules crucial in workflows to prevent data misinterpretation due to unit mismatches.

## Configuration Recommendations

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------- |
| `Chunk size` (Segment Length) | `500–800 characters` | Balances the completeness of specialized terms with contextual relevance, preventing semantic truncation. |
| `Recall count` (Recall Count) | `Top 10–15 items` | Quality documents have complex reference relationships; increasing recall improves the chances of discovering relevant connections. |
| `Similarity threshold` (Similarity Threshold) | `0.75–0.85` | Ensures professional relevance of recalled content, filtering out noise but not valuable subtle differences. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | CAR-T quality documents often contain many embedded tables and charts, requiring longer parsing times. |
| `maxContext` | `32000 tokens` | Accommodates the context of multiple related documents like batch reports and inspection results, ensuring completeness. |
| `Embedding Model` | `text-embedding-ada-002` | Strong semantic understanding of specialized domain text, better at capturing the similarity of professional vocabulary. |

## Three Common Pitfalls
*   Workflow execution timeouts or parsing failures often occur when processing PDF documents with many scanned pages or complex tables. This is typically due to `PARSE_FILE_TIMEOUT_SECONDS` being set too low, preventing timely document parsing.
*   Key fields (e.g., batch number, production date, cell count) are extracted as empty or incorrect. This usually results from not configuring customized entity recognition for the specific document templates and specialized terminology unique to the CAR-T domain.
*   In multi-document comparison, data inconsistencies or logical errors appear. The root cause is insufficient consideration of document version control or incorrect handling of cross-document data references in workflow orchestration, leading to comparisons against old versions or irrelevant documents.

## How to Verify Correct Configuration
*   Select at least three complete batches of production records, inspection reports, and release documents. Run the workflow and verify the extraction accuracy of key data fields (e.g., `batch number`, `production date`, `sterility test results`).
*   Randomly select 5-10 historical quality documents. Verify if the `Recall count` (Recall Count) and `Similarity threshold` (Similarity Threshold) settings effectively recall all relevant documents and exclude irrelevant ones when the workflow retrieves information related to these documents.
*   Simulate a deviation handling process by inputting a deviation report. Check if the workflow can accurately link to the corresponding batch production records, inspection reports, and change control records, and verify if its contextual understanding aligns with actual business logic.
