# DTP Pharmacy Quality Documents: Deployment and Upgrade

## Data Characteristics

DTP pharmacy quality documents focus on drug circulation, storage, dispensing, and patient services. Data sources primarily include internal pharmacy management systems, drug regulatory compliance requirements, and drug manufacturer-provided package inserts and batch information. Document updates are frequent, especially with new drug listings, batch changes, GSP (Good Supply Practice) revisions, or regulatory inspection feedback. Document structures typically include Standard Operating Procedures (SOPs), quality management manuals, training records, deviation reports, adverse reaction monitoring records, and cold chain management records. Fields and units involve drug batch numbers, expiration dates, storage conditions (e.g., temperature in `℃`), dispensing dosages (milligrams `mg`, milliliters `ml`), and patient medication adherence data. Data accuracy and traceability requirements are extremely high.

## Constraints on Deployment and Upgrade

The diverse and frequently updated data sources for DTP pharmacy quality documents introduce challenges for FastGPT deployment, specifically concerning real-time data synchronization and accuracy. For example, new drug batch information or GSP updates require rapid import and indexing to ensure timely retrieval results. Document content includes extensive normative text and precise numerical values, demanding FastGPT's sensitivity to specialized terminology and measurement units during document parsing and vectorization. Deployment must integrate with existing pharmacy management systems for automated document fetching and updates. During upgrades, any interruption or error can affect pharmacy operations due to the documents' association with drug safety and compliance. This necessitates strict requirements for rollback mechanisms and compatibility testing. Furthermore, documents contain sensitive patient information and commercial data, requiring deployment solutions to meet high security and data isolation standards.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | DTP pharmacy SOPs and quality manuals may contain numerous images or scanned documents, leading to large individual file sizes. |
| `maxContext` | `1000–1200 characters` | Quality documents are typically rigorously structured with strong contextual relevance, requiring a longer context window for complete comprehension. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` | Complex PDF document parsing can be time-consuming; this prevents import failures due to timeouts. |
| `Chunk size` | `400 characters` | Ensures individual text segments contain sufficient information while avoiding excessive length that could disperse semantic meaning, facilitating recall. |
| `Recall count` | `Top 8 entries` | Quality document queries often require multi-faceted information support; increasing recall count improves relevance. |
| `Similarity threshold` | `0.75–0.85` (based on actual measurement) | Ensures the precision of recalled content and avoids interference from low-relevance information. This can be fine-tuned based on actual test results. |

## Common Pitfalls

*   After a new version deployment, embedded frontend pages may not display or function abnormally. This manifests as `404` errors or CORS cross-origin errors in the browser console. The cause is incorrect configuration of frontend static resource paths during deployment, or the `CORS_ALLOWED_ORIGINS` environment variable not including the pharmacy frontend system's domain.
*   After importing a large volume of quality documents, some query results show confusion in drug batch numbers or dosage units. This manifests as returned numerical values not matching the original document or incorrect units. The cause is a lack of standardization for specific numerical formats and units during document preprocessing, leading to semantic loss during vectorization.
*   After a system upgrade, existing automated document synchronization tasks fail. This manifests as log entries showing `API Key invalid` or `Connection refused`. The cause is configuration files being overwritten during the upgrade, or service port changes, leading to invalid API credentials or network configuration.

## Verification

*   Select an SOP document containing drug batch numbers, expiration dates, and storage conditions. Upload it to FastGPT and query for related information. Verify that the returned batch numbers, dates, and temperature units are accurate.
*   Simulate a GSP inspection scenario. Ask complex questions about cold chain management or drug inbound/outbound processes. Check if FastGPT's answers are complete, logically clear, and reference the correct sections of the quality management manual.
*   Use the API to trigger a document update from an external system. Observe whether the updated document content is promptly indexed and correctly retrieved in FastGPT, ensuring the data synchronization mechanism functions properly.
