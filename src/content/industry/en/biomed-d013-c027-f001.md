# HTTP Interface and External Systems for Attenuated Inactivated Vaccine Quality Documents

## Data Characteristics for This Category

Attenuated inactivated vaccine quality document data originates from R&D, production, quality inspection, and batch release processes. Data update frequency is relatively low. Updates typically occur with batch production and regulatory requirements, such as per-batch production records, inspection reports, and deviation handling reports. Document structures are primarily structured and semi-structured data. Common formats include PDF, Word, and Excel, containing numerous tables and charts. Key fields include batch number, production date, expiration date, inspection items, inspection results, limits, equipment calibration records, deviation descriptions, and change control numbers. Units involve concentration (IU/ml, μg/ml), potency (TCID50/ml, PFU/ml), pH, temperature (°C), and pressure (kPa), requiring high precision.

## Constraints from "HTTP Interface and External Systems"

The low update frequency of attenuated inactivated vaccine quality documents means external systems do not require high-frequency polling for synchronization. Event-driven or scheduled batch synchronization can reduce resource consumption. Complex table and chart structures in documents demand robust data parsing capabilities from HTTP interfaces. This requires support for multiple file formats and accurate extraction of tabular data. Diverse fields and strict unit requirements necessitate validation of field types and value ranges during data transmission. This prevents parsing errors due to data format mismatches. For example, potency data may include scientific notation, which the interface must handle correctly. Additionally, large volumes of historical batch data mean single requests can be substantial. HTTP request body size limits and chunked transfer mechanisms need consideration.

## Configuration Guidelines

| Configuration Item             | Recommended Value    | Rationale                                                                                             |
| :------------------------------- | :------------------- | :---------------------------------------------------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`           | `500 MB`             | Allows for large document sets for a single batch, providing ample file upload capacity.              |
| `PARSE_FILE_TIMEOUT_SECONDS`     | `600 seconds`             | Complex PDF or Word document parsing can be time-consuming; prevents parsing failures due to timeouts. |
| `Chunk size` (Chunk Length)        | `800–1200 characters`      | Balances semantic completeness with vector retrieval efficiency, avoiding overly long or short text segments. |
| `Similarity threshold` (Similarity Threshold) | `0.75`               | Ensures recalled quality documents are highly relevant to the query, filtering out irrelevant information. |
| `Request timeout` (Request Timeout) | `120 seconds`             | Handles potential delays from slow external system responses or large data volumes.                   |
| `Batch Interval`    | `Calibrate by actual measurement` (Calibrated based on actual measurements) | Dynamically adjusts batch synchronization interval based on external system load and data update frequency. |

## Common Pitfalls

*   `413 Request Entity Too Large` error during API calls. This occurs when the size of the document uploaded in a single HTTP request exceeds the server or gateway's configured limit.
*   `URIError: URI malformed` when accessing a login interface. This typically happens when URL parameters contain special characters that are not correctly encoded.
*   Receiving a `400 Bad Request` response despite the request body appearing correct. This could be due to a mismatch between the `Content-Type` in the request header and the actual data format sent, or an internal field format in the request body not meeting API expectations.

## Verification Steps

*   Upload a PDF file containing complex tables and charts from an attenuated inactivated vaccine batch production record via the HTTP interface. Verify successful parsing and storage.
*   Use a query with special characters (e.g., slashes in batch numbers) to call the knowledge base via the HTTP interface. Validate the accuracy of the recall results.
*   Simulate a file upload request exceeding `UPLOAD_FILE_MAX_SIZE`. Confirm the system returns the expected error code, such as `413`.
*   Check external system logs to confirm data synchronization tasks trigger normally according to the preset batch interval, without connection timeouts or data parsing errors.
