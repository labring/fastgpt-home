# Workflow Orchestration for Molecular Diagnostics Quality Documentation

## Data Characteristics in This Domain
Molecular diagnostics quality documentation primarily includes laboratory Standard Operating Procedures (SOPs), batch production records, equipment calibration records, reagent batch inspection reports, internal and external quality control reports, and non-conformance records. Data sources encompass Laboratory Information Management Systems (LIMS), Manufacturing Execution Systems (MES), and various inspection instruments. Document structures are typically semi-structured, containing fixed template fields and extensive free-text descriptions. Update frequency depends on production batches and quality control plans; for example, batch production records are generated with each batch, and equipment calibration records are updated periodically (monthly or quarterly). Fields include batch number, serial number, reagent lot number, operator ID, test results (e.g., Ct value, fluorescence signal intensity), quality control results, calibration date, and expiry date. Common units are copies/mL, ng/μL, Ct value, and nmol/L, often accompanied by specific threshold ranges.

## Constraints Imposed by These Characteristics on "Workflow Orchestration"
The semi-structured nature of molecular diagnostics data requires workflows to flexibly handle fixed field extraction and free-text understanding during document parsing. Multi-source data integration means workflows need multi-system connectivity to retrieve SOPs, batch records, and quality control reports. The uncertain update frequency, especially for batch-generated records, demands event-driven trigger mechanisms for workflows, such as automatic triggering when a new batch production record is generated. Specific fields within documents (e.g., batch number, serial number) are crucial for linking different records. After information extraction, workflows must use these fields as correlation conditions to ensure logical consistency and traceability between documents. Attention to units and thresholds requires workflows to perform preliminary compliance checks during data processing to identify potential outliers.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8192` | Balances document length and model processing capability, preventing context overflow or information loss. |
| `Chunk size` (Segment Length) | `500–800 characters` | Balances semantic completeness and recall accuracy, accommodating the paragraph length of semi-structured documents. |
| `Recall count` (Recall Count) | `Top 5 entries` (Top 5) | Ensures refined and relevant query results, reducing interference from irrelevant information. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | Filters out low-relevance results, improving recall quality and handling precise matching of specialized terminology. |
| `Tool Call Timeout` | `600 seconds` | Provides sufficient time to process data queries from LIMS or MES systems, preventing timeouts due to waiting for external system responses. |
| `Environment Variable Prefix` | `MOL_DIAG_` | Clearly distinguishes molecular diagnostics-related variables, avoiding conflicts with variables from other business lines. |

## Three Common Mistakes
*   Workflow debugging shows "Tool call failed, error code: 500" due to incorrect external LIMS system API address configuration or expired authentication information.
*   Knowledge base search results do not match expectations, with low relevance to query keywords. This occurs when `Recall count` (Recall Count) is normal but `Similarity threshold` (Similarity Threshold) is too low, caused by an inappropriate document segmentation strategy that cuts off critical information.
*   Variables in the API prompt are not effective, leading to generated content unrelated to the intended topic. This is due to variable names not matching internally defined workflow variables or incorrect API request body format.

## How to Confirm Correct Configuration
*   Execute end-to-end workflow tests to verify the complete process from data ingestion to final report generation. Check if critical fields (e.g., batch number, test results) are correctly extracted and passed.
*   Perform searches in the knowledge base for specific SOPs or quality control reports. Compare recall results with original document content to confirm relevance and completeness meet business requirements.
*   Simulate abnormal data or non-compliance scenarios. Observe if the workflow correctly captures these and triggers predefined failure handling mechanisms, such as sending alerts or generating anomaly reports.
*   Review workflow logs to confirm all API calls to external systems (e.g., LIMS, MES) are successful and response times are within acceptable limits.
