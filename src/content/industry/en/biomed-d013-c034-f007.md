# Workflow Orchestration for Pharmaceutical E-commerce Quality Documents

## Data Characteristics of This Category

Pharmaceutical e-commerce quality documents primarily cover compliance proofs for the entire process of procurement, storage, sales, and distribution of medicines, medical devices, and health foods. Data sources vary, including supplier qualification files, batch inspection reports, cold chain transportation records, customer complaint handling records, return/exchange vouchers, and internal quality audit reports. These documents often exist as PDFs, scanned images, or structured XML/JSON formats. Update frequencies differ: supplier qualifications typically update annually, batch inspection reports generate per batch, cold chain records upload in real-time, and customer complaints and return/exchange records generate dynamically in real-time. Document structures are complex, containing numerous professional terms, batch numbers, expiration dates, production dates, registration numbers, and other key fields. They often include multiple tabs, attachments, or signature information. Data field types are rich, involving dates, text, numbers, and booleans. Units such as `mg`, `ml`, `℃`, and `kPa` appear across different documents.

## Constraints Imposed by These Characteristics on "Workflow Orchestration"

The complexity of pharmaceutical e-commerce quality documents imposes multiple constraints on workflow orchestration. First, heterogeneous data from multiple sources requires workflows with robust file parsing and information extraction capabilities to accurately identify key fields in different document formats. Second, varying document update frequencies necessitate workflows that support both scheduled and event-driven triggers. For example, regularly scanning for supplier qualification updates while simultaneously responding to new complaint records. Key information in documents, such as batch numbers and expiration dates, has strong interdependencies. Workflow design must consider cross-validation and data traceability across multiple documents. For instance, a drug's sales record might need to link to its procurement batch, inbound inspection report, and cold chain transportation records. Furthermore, high compliance requirements mean any error in information extraction or logical judgment can lead to severe consequences. Therefore, workflow error handling mechanisms need to be detailed and traceable, ensuring every step is monitored and auditable. The need for long text content parsing and bulk file uploads also challenges workflow execution time and file processing capabilities.

## How to Configure

| Configuration Item | Suggested Value | Rationale for This Value |
| :----------------- | :-------------- | :----------------------- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1800 seconds` | Pharmaceutical e-commerce documents are complex, containing many scanned images. Parsing takes longer, so avoid timeout interruptions. |
| `maxContext` | `3000 tokens` | Quality documents often have high information density. A longer context window is needed for comprehensive understanding of document content. |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Batch inspection reports or cold chain records may contain many images or scanned documents, resulting in large file sizes. |
| `Chunk size` | `800 characters` | Ensure that text segmentation does not break the integrity of critical information blocks, such as batch numbers and expiration dates. |
| `Recall count` | `Top 10 entries` | Increase recall to cover all relevant compliance clauses and batch information for cross-validation. |
| `Similarity threshold` | `0.75` | The pharmaceutical field demands high precision. A higher threshold helps exclude irrelevant document snippets. |

## Three Common Pitfalls

*   The workflow errors with `Execution timeout` after running for a long time. This happens when processing a batch of scanned documents, and a single workflow execution chain is too long to complete in time.
*   Multiple files were uploaded, but the workflow only processed data from one file. This occurs because file upload interface parameters were configured incorrectly, failing to properly recognize multi-file input.
*   The workflow completed, but key fields (e.g., batch number, expiration date) were extracted as empty. This might be due to insufficient coverage of diverse document templates, preventing specific format fields from being correctly recognized and extracted.

## How to Verify Configuration

*   Select quality documents of different formats (PDF, XML, images) and complexities. Trigger workflow execution via API and verify that the extracted key fields (e.g., batch number, production date, registration number) exactly match the original document content.
*   Upload a scanned document with many pages (e.g., over 50 pages). Observe if the workflow's execution time is within the expected range and if the final output is complete and accurate.
*   Simulate uploading multiple files simultaneously. Check if the workflow can process all files in parallel or sequentially and correctly link information between them, for example, matching a purchase order with its corresponding inbound inspection report.
