# Tool Calling and Plugins for Bispecific Antibody Quality Documentation

## Bispecific Antibody Documentation Data Characteristics

Bispecific antibody quality documentation features diverse data sources. These sources span research and development, production, and quality control. Documents primarily consist of structured and semi-structured data, including batch records, test reports, stability study data, and compliance files. Update frequency typically aligns with production batches and R&D progress. Data iteration accelerates during clinical trial phases.

Document structure usually follows industry standards, such as ICH Q series guidelines. Documents contain detailed experimental methods, instrument parameters, results analysis, and batch release criteria. Common fields include batch number, production date, expiration date, purity, potency, impurity content, and endotoxin levels. Units involve specific biopharmaceutical measurements like percentages, IU/mg, ng/mL, and EU/mL, often accompanied by specific assay methodology identifiers.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins

The diverse data sources and semi-structured nature of bispecific antibody quality documentation require robust data parsing capabilities from tool calling and plugins. This is especially true when processing different formats of test reports.

Frequent updates, particularly for clinical phase data, demand real-time data synchronization and incremental processing capabilities from plugins. This prevents decision deviations due to outdated information.

Adherence to industry-standard document structures necessitates more refined templates or intelligent semantic understanding models for information extraction.

Complex fields and unique units mean plugins must correctly identify and process these specialized terms and values during data queries or conversions (e.g., converting `ng/mL` to `μg/L`).

Processing compliance files also requires plugins to perform initial compliance checks after data extraction. An example is verifying if key indicators fall within release standards.

## Configuration Settings

| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds                 | Large batch records or stability study reports can be substantial, containing multiple pages of charts and tables. | `Similarity threshold` (Similarity Threshold) | Calibrated by actual measurement, typically between 0.75–0.85 | Ensure recalled documents are highly relevant to the query intent. This reduces interference from irrelevant information while avoiding the omission of important details due to overly strict criteria.                                   |
| `Rerank result count` (Reranked Return Count) | 5 items                         | Further optimize the relevance and logical coherence of results based on initial recall. ## Three Common Mistakes

*   The application interface returns the error `You need to use the app key rather than the account key`. This indicates using the wrong API key type for authentication; an application-level `app key` should be used.
*   The image link returned after plugin execution is empty. This usually means the plugin failed to correctly parse image content within the file, or the configuration for uploading images to the designated file server is incorrect.
*   In FastGPT v4.8.10 and later versions, API calls to workflows nested with knowledge base assistants return empty values. This typically occurs because certain parameters in the workflow configuration are not correctly passed or are ignored during the API call.

## How to Confirm Correct Configuration

*   Construct a query including batch number, test item, and specific values. Check if the plugin accurately extracts and returns corresponding field values and units from the document. Compare these with the original document.
*   Upload a complex test report containing images and tables. Verify if the plugin successfully parses and uploads images, and structures the table data.
*   Simulate a compliance check scenario. Query whether a specific batch's key quality attributes meet release standards. Verify if the returned results correctly make a judgment and cite relevant compliance clauses.

The values provided are common starting points and should be measured against your own samples.
