# Reference and Traceability for Quality Documents of Culture Media and Consumables

## Data Characteristics for This Category

In the biopharmaceutical industry, quality documents for culture media and consumables are highly standardized and time-sensitive. Data primarily comes from supplier product specifications, batch inspection reports (e.g., CoA, Certificate of Analysis), Safety Data Sheets (SDS), internal incoming inspection records, usage records, and stability study reports. These documents are mostly in PDF format, with some Excel or structured text files. Update frequency is high, especially for batch inspection reports, where each product batch generates new documents. Document structures are rigorous, including key fields such as batch number, production date, expiration date, test items, test standards, test results, and units (e.g., CFU/mL, g/L, %). Some documents include experimental methods, chromatograms, or detailed testing procedures.

## Constraints Imposed by These Characteristics on "Reference and Traceability"

The high standardization of culture media and consumable documents requires references to be precise, down to specific sections or data points, to support compliance audits. The time-sensitive nature of batch reports necessitates frequent knowledge base updates and the ability to differentiate between documents from different batches. Specific units and technical terms in documents, such as `Endotoxin Units (EU/mL)` or `Osmolality (mOsm/kg)`, require the tokenizer and embedding model to accurately recognize and process them, avoiding semantic drift. Complex document structures, especially PDFs containing tables and chromatograms, challenge document parsing capabilities. Text content must be extracted correctly for subsequent referencing and traceability. Additionally, rapid retrieval of specific batch numbers is critical for quick responses to quality inquiries.

## Configuration Settings

| Configuration Item | Suggested Value | Rationale |
|---|---|---|
| `Chunk size` (Segment Length) | `300-500 characters` | Ensures critical information (e.g., batch number, test results) from batch reports is contained within a single segment for precise referencing. |
| `Chunk Overlap Length` (Segment Overlap Length) | `50 characters` | Increases contextual continuity, handles key information spanning across segments, and improves recall rate. |
| `Similarity threshold` (Similarity Threshold) | `0.75` | Reduces the risk of false positives, ensuring only highly relevant quality document snippets are returned, especially when dealing with sensitive information like batch numbers. |
| `Recall count` (Recall Count) | `10 entries` | Given the granularity of documents, increasing the recall count covers more potentially relevant batches or product specifications. |
| `Rerank result count` (Reranked Return Count) | `5 entries` | While maintaining recall breadth, reranking focuses on the most relevant, high-quality references, enhancing user experience. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Provides sufficient time to process large PDF quality documents, preventing parsing timeouts that lead to document upload failures. |

## Three Common Mistakes

*   Answers fail to list specific referenced document names or batch numbers, breaking the traceability chain. This occurs when document parsing does not effectively extract document metadata, or the reference display logic does not associate metadata with reference snippets.
*   The model references outdated batch report information, leading to incorrect quality parameters or usage recommendations. This happens due to an imperfect knowledge base update mechanism, where old batch documents are not timely marked or retired.
*   When querying specific test items, the model fails to return documents containing that item, instead returning irrelevant general descriptions. This usually results from a lack of domain-specific optimization in the embedding model for handling technical terms and units, leading to inaccurate semantic matching.

## How to Confirm Correct Configuration

*   Upload a batch of CoA documents for culture media with different batch numbers and production dates. Then, query a specific test result for a particular batch through conversation. Observe if the returned reference accurately points to that batch's document and corresponding value.
*   Deliberately ask for information about an expired product batch number. Check if the system identifies and prompts that the information is expired, or references the latest valid document.
*   Test PDF documents containing tabular data. Confirm that when the system references table content in its answer, it correctly identifies and presents the field names and corresponding values within the table.
*   Check the knowledge base management interface. Verify that the `Update Time` field for each document matches the actual upload or update time, ensuring document timeliness is correctly tracked.
