# Tool Calling and Plugins for Medical Imaging Device Quality Documentation

## Data Characteristics

Quality documentation for medical imaging devices includes design specifications, test reports, calibration records, maintenance manuals, and compliance certifications. These documents typically exist in various formats such as PDF, Word, and Excel. Data sources span R&D departments, production lines, third-party testing agencies, and regulatory databases. Update frequency varies: core designs and regulatory standards change slowly, perhaps every few months or years. Test data, calibration records, and daily maintenance logs update frequently, possibly weekly or daily. Document structures often include numerous charts, formulas, and specialized terminology in technical specifications. Test reports follow fixed templates with dense tabular data. Maintenance manuals focus on operational steps and troubleshooting procedures. Fields and units are highly specialized. Examples include "spatial resolution" in `lp/mm`, "X-ray tube voltage" in `kV`, and "dose rate" in `mGy/s`.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins

The diverse formats and specialized terminology of medical imaging device quality documentation require tool calling and plugins to support multiple file types. Strong semantic understanding is necessary to accurately extract key information. Charts and formulas mean that simple text segmentation may lose context, necessitating smarter document structure recognition and information extraction capabilities. The frequent updates of test data and calibration records demand real-time data synchronization from plugins, ensuring tools access the latest information. Strict compliance requirements mean any data extraction or analysis must guarantee accuracy and traceability. This prevents misinterpretations of specialized terms or unit discrepancies. Complex specialized fields and unit systems require tools to correctly identify and convert numerical values, for example, the relationship between `kV` and `mA`.

## Configuration Guidance

| Configuration Item | Recommended Value | Rationale |
| :----------------- | :---------------- | :-------- |
| `maxContext` | `8000` | Accommodates extensive specialized terminology and complex sentences in documents, providing a broader understanding scope. |
| `Chunk size` | `500–800 characters` | Balances contextual completeness with processing efficiency, preventing semantic loss after chart segmentation. |
| `Similarity threshold` | `0.75` | Improves recall accuracy, filtering out general information with low relevance to medical imaging device content. |
| `Rerank result count` | `Top 5 entries` | Focuses on the most relevant technical details and regulatory requirements, reducing interference from irrelevant information. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Accommodates the parsing time for large PDF technical documents, preventing file processing failures due to timeouts. |
| `pluginCallTimeout` | `120 seconds` | Ensures external tool calls (e.g., database queries or specialized calculations) have sufficient time to respond. |

## Common Pitfalls

*   Calling external specialized database interfaces returns an `HTTP 404` error. This typically occurs because the plugin's configured `URL` or `API Key` is incorrect, not pointing to a valid service address.
*   After document parsing, critical technical parameters like "spatial resolution" or "modulation transfer function" fields are empty. This happens due to complex document structures where the parser fails to correctly identify data within charts or specific layouts.
*   Numerical results returned by tool calls do not match expectations. For example, `10kV` is incorrectly processed as `10V`. This occurs when the plugin fails to correctly identify and handle specialized units, leading to numerical conversion errors.

## Verification Steps

*   Upload a medical imaging device technical specification containing charts and complex formulas. Verify the system can correctly parse and extract key information. Check if extracted fields like "X-ray tube voltage" are accurate.
*   Simulate a query to a calibration record database. Check if the plugin successfully calls the external tool and returns the date and results of the most recent calibration. Verify `pluginCallTimeout` is sufficient.
*   Test querying "CT machine dose rate compliance standards." Check if the system recalls relevant regulatory document snippets. Verify the `Similarity threshold` setting effectively filters irrelevant content.
*   For a multi-page test report containing tables, verify the system can convert the tabular data into a queryable structure. Ensure units like `mGy/s` are correctly identified.

The values provided are common starting points and should be measured against the reader's own samples.
