# HTTP Interface and External Systems for Quality Documentation in Lead Compound Screening

## Data Characteristics

Quality documentation in lead compound screening primarily includes compound structure files (e.g., `.sdf`, `.mol`), high-throughput screening (HTS) raw data reports (e.g., `.csv`, `.xlsx`), activity validation reports (e.g., `.pdf`, `.docx`), and batch analysis certificates (e.g., `.xml`). These documents typically originate from automated screening platforms, Laboratory Information Management Systems (LIMS), or file servers provided by collaborators. Data update frequency aligns with screening batches, potentially weekly or bi-weekly, involving thousands to tens of thousands of compound records. Document structures follow specific cheminformatics standards for structure files. HTS reports contain fields such as compound ID, test batch, IC50 value, EC50 value, and selectivity, often in nanomolar (nM) or micromolar (µM) units. Batch analysis certificates detail indicators like purity, chirality, and impurity content.

## Constraints from HTTP Interface and External Systems

The diverse and heterogeneous nature of lead compound screening data requires the HTTP interface to support flexible file type recognition and parsing. The batch processing and update frequency of high-throughput data demand high concurrency and efficient transmission from the interface, necessitating support for large data stream transfers or batch uploads. The coexistence of structured and unstructured documents means the interface must trigger different parsing processes after data reception. For example, it needs to perform structural analysis for `.sdf` files, numerical extraction for `.xlsx` files, and text recognition for `.pdf` files. Consistent units for key fields like activity values (e.g., nM, µM) require backend standardization or unit conversion during data ingestion. Additionally, batch analysis certificates often contain sensitive information, requiring strict authentication mechanisms and encrypted data transmission for the interface to ensure data security.

## Configuration Guidelines

| Configuration Item | Recommended Value | Rationale |
| :----- | :------- | :----------- |
| `API_KEY_MANAGEMENT_STRATEGY` | `Unified Key Service` | Secure management of authentication keys for plugin calls to third-party APIs |
| `FILE_UPLOAD_ALLOWED_EXTENSIONS` | `sdf,mol,csv,xlsx,pdf,docx,xml` | Covers all document types required for lead compound screening |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Accommodates the parsing time for large high-throughput screening report files |
| `MAX_REQUEST_BODY_SIZE_MB` | `100 MB` | Supports uploading raw data files containing a large number of compound records |
| `DOCUMENT_FIELD_MAPPING` | `Calibrate by actual measurement` | Maps key fields like IC50, EC50 in HTS reports |
| `DATA_UNIT_STANDARDIZATION_RULES` | `nM -> uM` | Standardizes activity value units to ensure data consistency |

## Common Pitfalls

*   Specific format documents (e.g., `.sdf` or `.xml`) are not correctly parsed after file upload, resulting in missing core fields. This occurs when `FILE_UPLOAD_ALLOWED_EXTENSIONS` does not include the file type, or `DOCUMENT_FIELD_MAPPING` is not configured correctly for its internal structure.
*   Calling an external API returns an `HTTP 401 Unauthorized` error code. This happens when `API_KEY_MANAGEMENT_STRATEGY` fails to correctly transmit or refresh the authentication key, or the key configuration does not match the third-party system.
*   The conversational interface returns empty results when processing image-text requests. This is due to `MAX_REQUEST_BODY_SIZE_MB` being set too small, causing the request body containing embedded image information to be truncated or rejected, or `DOCUMENT_FIELD_MAPPING` failing to recognize descriptive text associated with images.

## Verification Steps

*   Upload a test dataset containing `.sdf`, `.xlsx`, and `.pdf` files. Check that core fields (e.g., compound structure, IC50 value, purity) are correctly extracted and displayed for each document.
*   Use the HTTP interface to call a query function of an external compound database. Ensure the API key authenticates successfully and returns the expected compound information.
*   Review system logs to confirm no `PARSE_FILE_TIMEOUT_SECONDS` timeout errors occur when processing high-throughput screening reports, and data ingestion rates meet expectations.
*   Send a question containing a lead compound structure image (as an image-text request) to the conversational interface. Verify the interface can combine image information to provide relevant screening suggestions or compound property descriptions.

The values provided are common starting points and should be measured against the reader's own samples.
