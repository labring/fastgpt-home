# High-Value Consumable Quality Documents: HTTP API and External Systems

## Data Characteristics

Quality documents for high-value consumables are highly structured and versioned. Data originates from production batch records, inspection reports, sterilization validations, supplier qualifications, and regulatory approval documents. These documents typically use PDF, Word, or Excel formats. They include structured metadata such as batch number, production date, expiry date, serial number, supplier code, and registration certificate number. Updates align with batch production; each batch or quality system change generates new or revised documents. Fields and units strictly follow industry standards. For example, sterilization parameters use "Gy" or "kGy," and inspection results often include units like "%," "mm," or "ppm."

## Constraints Imposed by HTTP API and External Systems

The structured and versioned nature of high-value consumable quality documents requires HTTP APIs to support precise metadata retrieval. This ensures accurate linking to documents using key information like batch numbers or registration certificate numbers. Diverse file formats mean the API must support various file types for upload and parsing, extracting text content. Frequent batch updates and document revisions demand real-time synchronization from external systems. Webhooks or polling mechanisms are necessary to keep the knowledge base consistent with actual document states. Strict unit and field specifications require the API to accurately identify and preserve this information during data transfer and parsing. This prevents quality judgment errors due to missing units or conversion mistakes. The need for historical version traceability means API design must include version management and historical record query functions.

## Common Mistakes

*   HTTP API returns 404 or 500 errors, preventing the knowledge base from obtaining document content. This occurs due to external system authentication failure or incorrect API path configuration, blocking FastGPT from accessing target resources.
*   Uploaded HTML format API documents parse to empty content or garbled formatting. This happens because FastGPT's default parser has insufficient support for complex HTML structures generated by tools like Javadoc or Swagger, failing to extract text correctly.
*   Knowledge base query results do not accurately answer questions involving specific batch numbers. This results from failure to extract or correctly map key metadata fields like batch numbers during document upload, preventing effective scope limitation during RAG retrieval.
