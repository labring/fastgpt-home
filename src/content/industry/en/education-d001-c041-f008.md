# Workflow Orchestration for Corporate Compliance and Safety Training: Find Supporting Evidence

## What this category's data looks like

This page addresses enterprise compliance and security training scenarios; the materials include three categories: compliance training courseware, security operating procedures, and exam records. Courseware is typically updated annually or when regulations change, with fields including course name, applicable position, effective date, and version number; procedures are divided into volumes by equipment or operation type, with fields including operation steps, risk points, revision records, and approval signatures; exam records are archived by batch, with fields including trainee, exam paper version, score, invigilator signature, and receipt. When the three material categories enter workflow orchestration, their roles differ: courseware and procedures serve as basis sources, while exam records serve as supporting evidence and receipt verification objects. In terms of update cadence, courseware changes with regulatory adjustments, procedures change with equipment changes, and exam records are generated by training batch. A common field characteristic is that the name, quantity, or date of the same item may be inconsistent between courseware and procedures, versions are not synchronized, and signatures or receipts are missing. When materials enter the user selection node, the user first selects the material scope and version, then queries continue along the branch.

## Configuration and implementation checks

This step is executed by workflow nodes (user selection and branches), outputting branch direction and interaction state records. Basis entries that can be traced back to the original text are completed by subsequent nodes continuing execution along the branch. When the node is triggered, the conversation enters an interaction state and records the workflow state; after the user completes the selection, execution continues along the branch corresponding to the selected option.

| Object | Check | Verification action |
| --- | --- | --- |
| Compliance training courseware | The courseware name, applicable position, effective date, and version number must be consistent with the current version and must match the original text entries | Verify the courseware fields and dates, confirm the version is current; check the options and branch connections one by one in the node, trigger once and view the node status in the run records |
| Security operating procedures | The operation steps, risk points, revision records, and approval signatures must be consistent with the courseware references, and the dates and quantities must match the original text | Compare the name, quantity, and date of the same record in the procedures and courseware; reference the selection result variable `variables` in subsequent nodes and run a trial to confirm the branch direction |
| Exam records | The trainee, exam paper version, score, invigilator signature, and receipt must be complete and must correspond to the courseware version | Check whether signatures and receipts are missing, and verify whether the exam paper version and courseware version are synchronized; locate the branch source in subsequent nodes via `nodeId` and confirm the interaction state record |
| User selection node | Each option corresponds to one branch, the interaction state is recorded, and the selection result variable has been passed to subsequent nodes | Run a trial for each option and view the branch direction and interaction state in the run records; reference `variables` in subsequent nodes and run a trial once |

## Three common errors

- Symptom: The name, quantity, or date of the same record does not match between the courseware and the procedures, so the basis entry cannot be traced back to the original text. Cause: The two material categories are updated separately, and no field-level comparison is performed.
- Symptom: The courseware has already changed versions, but the procedures and exam records still reference the old version, so the basis entry points to invalid content. Cause: Versions are not synchronized, and a version verification step is missing.
- Symptom: The exam records lack an invigilator signature or receipt, so the basis entry cannot serve as valid supporting evidence. Cause: Signatures and receipts are not included in the material completeness check.

## How to verify the setup

This feature acceptance: run a trial for each option and check the branch direction and interaction state in the run records; confirm that each option corresponds to one branch, that the selection result variable `variables` has been passed to subsequent nodes, and that the branch source is located via `nodeId`.

Business test: ask a cross-material basis question and see whether the answer provides a traceable source; verify whether the names, quantities, and dates in the answer match the original text in the courseware, procedures, and exam records, and confirm that the version is current and that signatures and receipts are complete.

- In the user selection node, check the options and branch connections one by one, trigger once, and view the node status and branch direction in the run records.
- In subsequent nodes, reference the selection result variable `variables` and run a trial once to confirm that the process continues after the interaction is completed and can trace back to the original text basis entries.
