# Context and Token Budgets for International Student Admissions and Enrollment Records: Find Supporting Evidence

## What this category's data looks like

This page centers on international student admissions and enrollment management; the materials include international student admission brochures, admission notices, and visa application forms. Brochures are usually updated by academic year, with fields including program name, program duration, application deadline, and signature and seal positions; admission notices are issued by batch, with fields including name, passport number, admitted program, registration date, and issuer signature; visa application forms are filled out and submitted by the applicant, with fields including name spelling, date of birth, passport validity, and signature and receipt. After the materials enter this feature, the brochure serves as the basis for admission conditions, the notice serves as the basis for the admission fact, and the application form serves as the basis for identity and visa information; together, the three support basis entries that can be traced back to the original text. In terms of update cadence, brochures are adjusted with the academic year, notices are generated by batch, and application forms are submitted on a case-by-case basis; versions and signature receipts need to be checked one by one.

## Configuration and implementation checks

This step is carried out by application settings (response limit, etc.), which determine the length of a single answer and the range of context that can be accommodated. "Basis entries that can be traced back to the original text" are then completed by the model. The response limit is controlled by a slider for the length of a single answer; if set too low, the answer will be truncated, and if set too high, consumption will increase.

| Object | Check | Verification action |
| --- | --- | --- |
| International student admission brochure | Fields, dates, and signatures match the original text | Check the program name, application deadline, and signature and seal positions, and confirm the version is current; when citation budget is involved, look at `quoteMaxToken`, and record the number of citations separately by array length |
| Admission notice | The name, quantity, and date of the same record are consistent between the brochure and the notice | Compare the name, passport number, admitted program, and registration date, and check whether the issuer signature and receipt are complete; check whether `maxResponse` and `maxContext` match the answer length |
| Visa application form | Identity information, passport, and notice can mutually refer back to each other | Check the name spelling, date of birth, passport validity, and signature receipt, and confirm that if the version is not synchronized, the current materials prevail; the tokens of the cited text are calculated separately, and the number of array entries is recorded separately |

## Three common errors

- Symptom: the program name or registration date for the same student does not match between the brochure and the notice. Cause: the two materials are filled in by different steps, and no cross-check was performed.
- Symptom: the visa application form still uses an old template and lacks a signature or receipt. Cause: the version was not synchronized, and the signature positions were not checked one by one before submission.
- Symptom: the answer breaks off in the middle of a sentence, and the basis entries cannot be traced back to the original text. Cause: the response limit is set too low, and the long answer is truncated early.

## How to verify the setup

Feature acceptance: ask a question that requires a long answer, see whether the ending is complete, and check whether `maxResponse` and `maxContext` match the answer length required by the page.

Business test: ask a cross-material basis question and see whether the answer provides a traceable source.

- In the application settings, check the response limit switch and slider position, and ask a question that requires a long answer to see whether the ending is complete.
- Compare usage across two runs, confirm the change in single-run usage after adjusting the limit, and check that the tokens of the cited text and the number of array entries are recorded separately.
