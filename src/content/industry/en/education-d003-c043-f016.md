# Forms and User Interaction for Training Provider Admissions and Inquiry Follow-Up: Handle Questions and Collect Missing Information

## What this category's data looks like

This category's data involves three core types of materials: enrollment brochures, consultation records, and trial class schedules. Enrollment brochures are usually updated by the marketing or academic affairs department per semester or class session, with fields including course name, number of class hours, start date, fee range, and registration deadline; consultation records are filled in by enrollment advisors after each communication, with fields including student name, consultation channel, intended course, follow-up status, and next contact time; trial class schedules are generated by academic affairs scheduling, with fields including trial class time, instructor, classroom number, and sign-in receipt. When these materials enter the form input node, each plays a different role: enrollment brochures provide the course and date baseline, consultation records provide student intent and follow-up information, and trial class schedules provide the basis for time and receipts. In terms of update cadence, enrollment brochures change with class session adjustments, consultation records are added in real time with each communication, and trial class schedules are arranged weekly. In terms of field characteristics, date and quantity fields are most prone to version discrepancies, while signature or receipt fields are most prone to being missing.

## Configuration and implementation checks

This step is executed by the form input node (interaction node) in the workflow, which outputs the field values filled in by the user (passed to subsequent nodes after submission). "Intake records and items to be completed" are handled by subsequent nodes or manually. After the form input node is triggered, the conversation enters an interaction state and the workflow state is recorded; after the user fills in the required items and submits, the form information is passed to subsequent nodes for use.

| Object | Check | Verification action |
| --- | --- | --- |
| Enrollment brochure | Whether the course name, number of class hours, start date, and registration deadline are consistent with the consultation records, and whether the versions are synchronized | Check item by item the names, quantities, and dates in the brochure and consultation records; check the brochure version number and update date; check field names and required markers one by one in the form input node configuration |
| Consultation record | Whether the student's intended course, follow-up status, and next contact time match the trial class schedule, and whether there is a signature or receipt | Compare the dates and student names in the consultation records and trial class schedule; check whether there is an advisor signature or receipt number at the end of the record; reference the `formInputResult` field in subsequent nodes and run a test |
| Trial class schedule | Whether the trial class time, instructor, and classroom number conflict with the start date in the enrollment brochure, and whether receipts are complete | Check the dates and course names in the trial class schedule and brochure; check whether the sign-in receipt has the student's signature; check in the `userSelect` options that the course name is consistent with the brochure |
| Form input node | Whether it can be submitted when required items are empty, and whether subsequent nodes can retrieve the corresponding field values after submission | Check the required settings one by one; reference the `formInputResult` field in subsequent nodes and run a test; confirm that the conversation does not remain stuck in the interaction state |

## Three common errors

- Symptom: The same student's intended course has inconsistent names in the consultation record and trial class schedule. Cause: The two materials are filled in by different people at different times, without version synchronization and cross-checking.
- Symptom: The start date in the enrollment brochure does not match the trial class time in the trial class schedule. Cause: After the brochure is updated, it is not synchronized to the scheduling table, and the date fields are not uniformly validated.
- Symptom: The consultation record lacks an advisor signature at the end, or the trial class receipt is missing. Cause: The form does not set the signature or receipt as required, and no one reviews the completeness of the materials after submission.

## How to verify the setup

Acceptance for this feature: fill out the form once and submit it, check whether the field values retrieved by subsequent nodes are consistent with the filled-in content, and confirm that `formInput` is passed correctly.

Business test: submit a question missing key information and see whether it first asks a follow-up question before answering; if it answers directly, the missing-item follow-up was not triggered.

- Check field names and required markers one by one in the form input node configuration to ensure that key material fields are marked as required.
- Reference the `formInput` or `selectResult` output in subsequent nodes and run a test to confirm that the corresponding field values can be retrieved after submission and that the conversation does not get stuck in the interaction state.
