# Tool Calls and Plugins for Adult College Entrance Applications and Admissions: Handle Questions and Collect Missing Information

## What this category's data looks like

Materials for adult college entrance exam registration and admission management fall into three categories: registration forms, care bonus-point materials, and admission rosters. Registration forms are filled in by candidates and preliminarily reviewed by registration points, with fields including name, ID number, application level, subject category, date, and signature; care bonus-point materials are submitted as proof by candidates and verified by the handling staff, with fields including bonus item, certificate number, validity period, review opinion, and receipt; admission rosters are generated by admissions institutions by batch, with fields including candidate number, admitted major, admission date, and approval signature. The three types of materials enter in batches at the three nodes of registration, review, and admission, and the update rhythm advances with the batches. When entering the Q&A intake and missing-item follow-up function, the registration form is the draft basis for identity and application information, the care bonus-point materials are the basis for bonus points, and the admission roster is the proof of admission results; together, the three support completing missing items and handling transfer to the responsible person.

## Configuration and implementation checks

This step is executed by the tool calling node in the workflow (the model decides whether to call, and the node executes), outputting the tool call result (the input parameters and return in the call record). The intake record and the completed missing items are then finished by subsequent AI nodes or manual verification. Based on the tool description, parameter descriptions, and whether parameters are required, the model determines whether to call the tool this time.

| Object | Check | Verification action |
| --- | --- | --- |
| Registration form | Whether fields, date, and signature are complete, and whether the name, quantity, and date of the same record match between the registration form and the admission roster | Open the tool node description fields and check the parameter descriptions and whether they are required; run a trial with a question missing a required field to see whether it asks a follow-up first; check the diamond interface connections and node status |
| Care bonus-point materials | Whether the bonus item, certificate number, validity period, and review opinion correspond, and whether the signature or receipt is missing | Open each parameter configuration one by one and check the two items of description and whether required; run a trial with a question missing that field to see whether it asks a follow-up first and does not directly fabricate; check the `functionCall` call record |
| Admission roster | Whether the candidate number, admitted major, admission date, and approval signature are consistent, and whether the version is synchronized | Check the diamond connections and node status on the canvas; check the input parameters and return of `toolChoice` and `functionCall`; check whether values appear in the returned result that do not exist in the materials |
| Tool calling node | Whether the tool description can be understood on its own, and whether the parameters correspond to the material fields | Run a trial with a question missing key information, check the input parameters and return in the call record, and confirm whether it asks a follow-up or calls according to the description |

## Three common errors

- Symptom: the name, quantity, and date of the same record do not match between the registration form and the admission roster. Cause: the two materials are entered separately, lacking cross-material field comparison and receipt verification.
- Symptom: the version of the care bonus-point materials is not synchronized, and the old certificate number is still referenced. Cause: after the materials are updated, they are not synchronized to the tool parameter values, and the model calls according to the old context.
- Symptom: the registration form is missing a signature or receipt but is still accepted as complete materials. Cause: whether required is not mapped to the material fields, and the model answers directly without asking a follow-up.

## How to verify the setup

Acceptance of this function: run a trial with a question missing a required parameter, check the input parameters and return in the call record, and confirm whether it asks a follow-up or calls according to the description; check the three items of `toolChoice`, `functionCall`, and whether parameters are required.

Business test: submit a question missing key information and see whether it asks a follow-up before answering.

- Open the tool node description field and check whether this description can be understood when taken out on its own, and open each parameter configuration one by one to check the description and whether required.
- Run a trial with a question missing that field to see whether it asks a follow-up first and does not directly fabricate; check the diamond connections and node status on the canvas.
