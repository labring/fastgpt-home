# Workflow Orchestration for Initial Review of Academic Journal Submissions: Draft Materials and Hand Over Responsibilities

## What this category's data looks like

In the initial review stage of academic journal submissions, materials usually include three types: submitted manuscripts, author information forms, and plagiarism check reports. Submitted manuscripts come from author submissions, and their update cadence changes with submission batches; fields include title, author, affiliation, abstract, main text, and receipt date. Author information forms are supplemented by authors or the editorial office; fields include authorship order, corresponding author, contact information, and signature field. Plagiarism check reports are generated by plagiarism check tools; fields include similarity rate, comparison database, generation date, and check number. When the three types of materials enter the workflow, their roles differ: the submitted manuscript is the main object under review, the author information form is used to verify authorship and responsibility attribution, and the plagiarism check report is used to judge duplication risk. Drafting materials and handing off responsibility require complete fields, clear responsible parties, consistent versions and dates, and sign-off by the next stage.

## Configuration and implementation checks

This step is executed by a workflow node (user selection and branching), outputting branch direction and interaction status records. Draft materials that can be issued and handoff records are completed by subsequent nodes continuing execution according to the branch. When this node is triggered, the conversation enters an interactive state and records the workflow status; after the user completes the selection, execution continues along the branch corresponding to the selected option.

| Object | Check | Verification action |
| --- | --- | --- |
| Submitted manuscript | Whether the title, author, affiliation, and receipt date are consistent with the author information form | Check the options and branch connections one by one in the node, compare the fields of the two materials, and record discrepancies |
| Author information form | Whether the authorship order, corresponding author, and signature field are complete and consistent with the manuscript | Trigger a user selection node once, and check the node status and signature receipt in the run record |
| Plagiarism check report | Whether the similarity rate, check number, and generation date are synchronized with the manuscript version | Reference the selection result variable in a subsequent node and run a test once, and check the report and manuscript version |
| Handoff record | Whether the responsible party, version number, date, and sign-off status are clear | Reference `variables` in a subsequent node and check the branch direction corresponding to `nodeId` |

## Three common errors

- Phenomenon: The name and date of the same record do not match between the author information form and the submitted manuscript. Cause: The two materials were drafted separately and were not checked against a unified field template.
- Phenomenon: The plagiarism check report version is not synchronized with the manuscript version, and the old report is still used during handoff. Cause: The version number was not updated with the materials, and the node branch did not record the version.
- Phenomenon: The handoff record lacks a signature or receipt, and the next stage cannot sign off. Cause: The responsible party field was not filled in, and no receipt was generated after the user selection branch.

## How to verify the setup

Acceptance for this feature: run tests option by option, check the branch direction and interaction status in the run record, and confirm that `variables` and `nodeId` are correctly referenced.

Business test: draft one copy according to the template and complete one handoff, and see whether missing items are blocked.

- Check the options and branch connections one by one in the node, and confirm that each option corresponds to one branch.
- Reference the selection result variable in a subsequent node and run a test once, and check whether the process continues after the interaction is completed.
