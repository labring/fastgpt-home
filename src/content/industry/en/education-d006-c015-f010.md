# Citations and Source Traceability for School Mental Health Screening and Referrals: Track Progress and Check Statistics

## What this category's data looks like

This page addresses the scenario of mental health screening and referral in primary and secondary schools. Materials include psychological screening plans, interview records, referral forms, and the resulting progress tables and statistical scope descriptions. The screening plan specifies the target scope, tools, and schedule; interview records carry the facts of individual contacts and signatures; referral forms record the destination, receipt, and date. When these three types of materials enter the knowledge base retrieval node, each serves as a citable original source; the node is only responsible for returning an array of cited content, not for rewriting fields or generating ledgers. Updates are aggregated weekly or monthly, and field characteristics center on names, quantities, dates, signatures, and version numbers. The progress table and statistical scope description are generated by subsequent nodes or manually by comparing the citation array, using one week of records to verify the totals and checking whether the scope and exceptions are written in the header.

## Configuration and implementation checks

This step is executed by the citation output of the knowledge base retrieval node, which outputs an array of cited content, each entry containing an original text snippet and a source identifier, and the length can be 0. Even if no content is found, the output chain still completes. The "progress table and statistical scope description" is then completed by a subsequent AI node, code node, or manually.

| Object | Check | Verification action |
| --- | --- | --- |
| Psychological screening plan | The target scope, tool names, screening dates, and version numbers in the plan must be mutually referable with the interview records and referral forms | Open the citation marker to trace back to the original paragraph of the plan, and check whether the target scope, tool names, dates, and version numbers are consistent; then check whether the selected knowledge base uses the same vector model |
| Interview records | The name, quantity, date, and signature fields in the records must match the screening plan and referral forms | Trace back to the original interview records one by one, and check the name, quantity, date, and signature; entries missing signatures or receipts are listed separately in the ledger |
| Referral forms | The referral destination, receipt, date, and signature must be consistent with the screening plan and interview records | Trace back to the original referral forms, and check the destination, receipt, date, and signature; when the name, quantity, or date of the same record differs across two materials, mark the discrepancy |
| Citation content output | The number of returned entries matches the materials hit; an empty result is also normal; `quoteMaxToken` only constrains the citation text budget | Run a test with a question that matches no materials to confirm the array is empty while the chain continues; when there is original text support, check whether the citation array and markers can trace back to the original text; `responseData` (non-streaming module results returned with detailed output enabled) and `quoteList` are for viewing only |

## Three common errors

- Symptom: The name, quantity, and date of the same record do not match between the screening plan and the interview records. Cause: Material versions are not synchronized, field scope is not written in the header, and discrepancies are only discovered when tracing citations back.
- Symptom: A referral form lacks a signature or receipt, but the progress table still includes it in the totals. Cause: Signature and receipt fields are not included in the verification dimensions, and exceptions are not stated in the header.
- Symptom: There is an answer but the citation array is empty, and it is treated as a retrieval failure. Cause: An empty array is a normal output; the number of citations is the array length, and it is not compared for equality with the citation content budget of `quoteMaxToken`.

## How to verify the setup

Feature acceptance: ask a question with original text support, and check whether the citation array and markers can trace back to the original text; then ask a question with no matching materials, confirm the array is empty while the chain completes, and view `quoteList` within `responseData`.

Business testing: use one week of records to verify the totals, see whether the scope and exceptions are clearly stated, and check whether the name, quantity, date, signature, and version match.

- In the node, check the selected knowledge base collections and their vector models, and confirm that the selected knowledge bases use the same vector model.
- Open the search parameter panel and check each item, confirming that the values are consistent with those set in the knowledge base retrieval section; record the number of citations separately, and view the tokens of the citation text separately via `quoteMaxToken`.
