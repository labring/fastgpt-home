# Tool Calls and Plugins for Corporate Compliance and Safety Training: Track Progress and Check Statistics

## What this category's data looks like

This page addresses the scenario of progress records and statistics verification for enterprise compliance and safety training. The source materials include three categories: compliance training courseware, safety operating procedures, and exam records. Courseware is updated quarterly and includes chapter numbers, applicable positions, effective dates, and instructor signature fields; procedures are revised by equipment or process and include version numbers, revision dates, and approval signatures; exam records are generated by session and include personnel names, subjects, scores, dates, and receipts. When the three types of materials enter the tool call node, their roles differ: courseware and procedures serve as the source of definitions, providing versions and effective dates; exam records serve as the detail source, providing item-by-item records. The update cadence is quarterly for courseware, as needed for procedures, and per session for exams. Field characteristics are concentrated in four categories: name, quantity, date, and signature.

## Configuration and implementation checks

This step is executed by the tool call node in the workflow (the model decides whether to call, and the node executes), outputting the tool call result (the input parameters and return in the call record). The "progress table and statistical definition description" is then completed by subsequent AI nodes or manual verification.

| Object | Check | Verification action |
| --- | --- | --- |
| Compliance training courseware | Check whether the chapter number, applicable positions, effective date, and instructor signature are complete, and determine whether they are consistent with the subject name in the exam records | Open the tool node introduction fields, check whether the courseware name in the returned result matches the exam record subject; check the parameter introduction and whether it is required |
| Safety operating procedures | Check the version number, revision date, and approval signature, and determine whether they are synchronized with the procedure version referenced by the courseware | Run a test with a question missing the version number to see whether it asks a follow-up question first; check the diamond connectors and node status on the canvas, and confirm the values of `toolChoice` and `functionCall` in the call record |
| Exam records | Check the personnel name, subject, score, date, and receipt signature, and determine whether the name, quantity, and date of the same record are consistent across the courseware and procedure materials | Check the input parameters and return in the call record item by item, and confirm that the returned result does not contain values absent from the business materials; check whether `toolChoice` is triggered according to the introduction |
| Progress table and statistical definition description | Check whether the record count and statistical count match, whether the definition is written in the header, and whether exceptions are clearly stated | Use one week of records to check the totals, and see whether the definition and exceptions are clearly stated; confirm that the input parameters and return of the `functionCall` are traceable |

## Three common errors

- Symptom: The subject name, quantity, and date of the same record do not match between the courseware and the exam records. Cause: The two materials are maintained separately, versions are not synchronized, and name mapping is not performed when the tool call returns.
- Symptom: After the procedure is revised, the version number is not synchronized to the courseware reference, and the statistical definition still aggregates according to the old version. Cause: The update cadences differ, and the tool call node does not filter by effective date.
- Symptom: The exam record lacks a receipt signature, but the progress table still counts it as completed. Cause: Required parameters are not guided to be asked about in the prompt, and the model directly calls and returns according to the introduction.

## How to verify the setup

Acceptance for this feature: Run a test with a question missing required parameters, check the input parameters and return in the call record, and confirm whether it asks a follow-up question or calls according to the introduction; check the values of `toolChoice` and `functionCall`, and confirm whether parameter values are fabricated when required parameters are missing.

Business test: Use one week of records to check the totals, see whether the definition and exceptions are clearly stated, confirm that the record count and statistical count match, and that the header states the statistical definition.

- Open the tool node introduction fields, check whether this description can be understood when taken out alone, and open the parameter configuration one by one to check the introduction and whether it is required.
- Check the diamond connectors and node status on the canvas, confirm that the diamond interface is connected to the target tool, and run a test with a question missing a field to see whether it asks a follow-up question first.
