# Knowledge Base Retrieval for Kindergarten and Family Communication: Trace Exceptions and Review Results

## What this category's data looks like

This page addresses the kindergarten home-school co-education communication scenario; the materials come from class notices, teacher observation records, parent request registrations, commitment item ledgers, and delivery receipts. The update cadence is daily synchronization with communication records, and exception records are summarized weekly. Field characteristics include commitment items and response times, descriptions of child performance, parent request categories, and notice delivery status. When the materials enter the knowledge base retrieval and recall function, notices and ledgers serve as original records to support exception tracing, observation records and request registrations serve as comparison evidence, and delivery receipts are used to verify whether notices were reached. Exception lists and review conclusions are generated by subsequent nodes or manually on this basis; the retrieval step only provides candidate snippets and similarity scores, and does not directly produce statistical tables or authorization results.

## Configuration and implementation checks

This stage is executed by the knowledge base retrieval service (retrieval node and search test), outputting candidate snippets and similarity scores (after pattern, merge, rerank, filter, and upper-limit trimming). Exception lists and review conclusions are then completed by subsequent nodes or manually.

| Object | Check | Verification action |
| --- | --- | --- |
| Commitment items and response times | When a commitment has not been responded to, the commitment time and response time fields in the ledger are blank or exceed the agreed period | Retrieve commitment items with synonymous questions, check whether the candidate snippets contain the original commitment record and response time, and record the number of candidates and scores |
| Descriptions of child performance | When the statement does not match the observation record, there is a discrepancy between the performance description in the communication text and the original entry in the observation record | Switch `searchMode` to semantic, full-text, or hybrid, compare whether the candidates hit both the communication text and the observation record, and check the number of returned candidates and scores |
| Parent request categories | When feedback has not been categorized, the category field in the request registration is empty or cannot correspond to the notice delivery record | Turn `usingReRank` on and off, compare the ranking of the top few candidates, and check whether the request category field appears in the candidate snippets |
| Notice delivery | When a notice has not been delivered, the delivery receipt is missing or does not match the notice sending time | Reduce `limit` to observe whether the key delivery snippet is still retained after upper-limit trimming of references, record the number of reference array entries separately, and do not compare `quoteMaxToken` |

## Three common errors

- Symptom: a commitment item has not been responded to in the communication records. Cause: the response time field is blank and is not linked to the original commitment record, and the retrieval candidates do not cover the materials for that period.
- Symptom: the description of child performance is inconsistent with the observation record. Cause: the communication text deviates from the original observation entry after paraphrasing, and the candidate snippets do not hit both sources at the same time.
- Symptom: parent request feedback has not been categorized. Cause: the category field in the request registration is empty, and the notice delivery record has not established a corresponding relationship with the request entry.

## How to verify the setup

Feature acceptance: test once each with synonymously rewritten questions, compare candidates and scores, then turn reranking on and off to inspect the ranking of the top few; at the same time switch `searchMode` and adjust `limit`, and record the number of candidates and scores.

Business test: create one exception record, see whether the source material can be traced, verify that the exception is supported by original records and signed by the reviewer, and then hand it over to the person in charge for handling.

- In the knowledge base search test, retrieve commitment items with synonymous questions, check whether the candidate snippets contain the original commitment record and response time, and record the number of candidates and scores.
- Turn `usingReRank` on and off, compare the ranking of the top few candidates, and check whether the description of child performance and the observation record appear in the candidate snippets at the same time.
