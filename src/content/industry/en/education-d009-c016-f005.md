# Multi-Turn Conversation and Prompts for School Safety Inspections and Incident Reporting: Handle Multilingual Materials and Terminology

## What this category's data looks like

This page focuses on multilingual materials and terminology handling in the context of school safety hazard inspections and campus incident reporting. The materials come from three types of records: safety inspection checklists, hazard rectification ledgers, and emergency incident reports, and the update cadence follows inspection and reporting actions on a record-by-record basis. Field characteristics include inspection item names, hazard locations, rectification deadlines, incident dates, reporters, reviewers, and signature and receipt columns. When a safety inspection checklist enters this feature, it serves as the first-round input, providing terms to be translated and inspection dimensions; when a hazard rectification ledger enters, it serves as reference material for verifying the names and quantities of the same hazard across the two records; when an emergency incident report enters, it serves as supplementary context for unifying incident description wording and date formats. Across the unified terminology glossary and the reference draft, the three types of materials each take on the roles of source text provenance, translated-name back-reference, and version synchronization, and the glossary must ensure that the same term is consistent throughout and that translated names can back-reference the source text.

## Configuration and implementation checks

This step is executed by the memory turn count and prompt configuration in the application settings, which output the reference range of historical messages and the answer constraints. The "unified terminology glossary and reference draft" is then completed by the model. The memory turn count controls how many preceding dialogue turns can be referenced at most when answering; if the value is too small, prior context cannot be used, and if the value is too large, irrelevant content is brought in and consumption increases. The external entry point and authorization are handled by the publishing service and file permissions, and are not generated by this feature.

| Object | Check | Verification action |
| --- | --- | --- |
| Safety inspection checklist | Fields include inspection item, hazard location, rectification deadline, inspection date, and signature column; terminology must be consistent throughout and translated names must be able to back-reference the source text | Check the current value of the memory turn count in the application settings, and run a trial with two consecutive rounds of questions to confirm that the second round correctly carries forward the references from the first round |
| Hazard rectification ledger | The names, quantities, and dates of the same hazard in the two materials must match, versions must be synchronized, and missing signatures or receipts must be flagged | Compare the same hazard record in the safety inspection checklist and the ledger, and verify the name, quantity, and date item by item; check whether the signature and receipt columns are complete |

| Multi-turn dialogue record | The range of historical messages and answer constraints must match the prior context range required by the question, and `messages` and `variables` must be traceable | Run a trial with two consecutive rounds of follow-up questions to confirm that the second question carries forward the references from the first question; check the historical message range corresponding to `chatId` and the values of `variables` |

## Three common errors

- Symptom: the name, quantity, or date of the same hazard does not match between the safety inspection checklist and the rectification ledger. Cause: the two materials are entered separately, without terminology comparison and version synchronization, resulting in contradictions in the externally published draft.
- Symptom: the incident date, reporter signature, or receipt is missing in the emergency incident report and the ledger. Cause: the reporting process has no receipt, the signature column is not checked when materials are circulated, and no completeness check is performed before publishing.
- Symptom: when the second question uses a reference, the answer does not address the question, or responses become slower and consumption rises. Cause: the memory turn count value does not match the prior context range required by the question; if too small, prior context cannot be used, and if too large, irrelevant content is brought in.

## How to verify the setup

Feature acceptance: with two consecutive rounds of follow-up questions, see whether the second question carries forward the references from the first question; check whether `messages` and `variables` fall within the referenced historical message range.

Business testing: sample three terms and check whether their wording is consistent throughout, and confirm that translated names can back-reference the source text.

- Check the current value of the memory turn count in the application settings so that it matches the prior context range required by the question, and compare the usage records of two runs.
- Sample three terms and check whether their wording is consistent throughout, and verify the names, quantities, dates, and signature receipts in the safety inspection checklist, hazard rectification ledger, and emergency incident report item by item.
