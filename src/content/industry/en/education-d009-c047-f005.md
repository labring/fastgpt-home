# Multi-Turn Conversation and Prompts for Pre-Departure Training and Overseas Safety: Handle Multilingual Materials and Terminology

## What this category's data looks like

This page addresses the scenario of pre-departure training and overseas safety reminders, with materials drawn from three categories: pre-departure training courseware, safety reminder checklists, and accommodation contact lists. Training courseware is organized by module and lesson, safety reminder checklists are arranged by risk category and handling steps, and accommodation contact lists are registered row by row by accommodation site, contact person, and emergency phone number. The three types of materials play different roles when entering multilingual materials and terminology processing: courseware and checklists provide terminology source text and translated name comparisons, while contact lists provide name, address, date, and signature fields. The update cadence changes with pre-departure batches and destination safety notices, and field characteristics center on names, quantities, dates, signatures, and acknowledgments. After the materials enter this feature, the unified terminology table and comparison draft are generated by the model based on the preceding context scope, while external publishing and file permissions are handled by the publishing service.

## Configuration and implementation checks

This step is executed by the memory turn count and prompt configuration in the application settings, and the output references the historical message scope and answer constraints. The "unified terminology table and comparison draft" is then completed by the model. The memory turn count controls how many preceding dialogue turns can be referenced at most when answering; if the value is too small, the preceding context cannot be used, and if the value is too large, irrelevant content is brought in and consumption increases.

| Object | Check | Verification action |
| --- | --- | --- |
| Pre-departure training courseware | The same terminology is consistent throughout, translated names can refer back to the source text, and courseware module names are consistent with the translated names in the safety reminder checklist | Check the memory turn count value in the application settings, run a trial with two consecutive questions, and inspect whether the preceding context scope in `messages` covers the courseware terminology |
| Safety reminder checklist | The names, quantities, and dates of the same record match between the courseware and the checklist, versions are synchronized, and no acknowledgments are missing | Sample three terms to check whether their wording is consistent throughout, and compare whether the date and quantity fields in `variables` are consistent with the courseware |
| Accommodation contact list | Accommodation site names, contact persons, emergency phone numbers, and signature fields in the comparison draft can refer back to the source text, with no missing signatures | Check the signature and acknowledgment fields of the contact list, and inspect whether the terminology translated names in the session corresponding to `chatId` are consistent with the courseware |
| Unified terminology table and comparison draft | The same terminology is consistent throughout, translated names can refer back to the source text, and sampling three terms shows consistent wording throughout | Check the memory turn count value in the application settings, run a trial with two consecutive questions, and compare the usage records of the two runs |

## Three common errors

- Phenomenon: The names, quantities, and dates of the same record do not match between the courseware and the safety reminder checklist. Cause: The two materials are maintained separately, and the terminology table does not uniformly refer back to the source text.
- Phenomenon: The version of the accommodation contact list is not synchronized, and the old emergency phone number coexists with the new one. Cause: The update cadence is not aligned, and the comparison draft does not indicate the effective date.
- Phenomenon: The safety reminder checklist lacks signatures or acknowledgments, making it impossible to trace and confirm after publication. Cause: The signature field is not included in the verification scope of the terminology table and comparison draft.

## How to verify the setup

Feature acceptance: Ask two consecutive follow-up questions, see whether the second question inherits the reference from the first question, and confirm that the historical message scope and answer constraints output by the memory turn count match.

Business test: Sample three terms to check whether their wording is consistent throughout, verify whether the translated names can refer back to the source text, and inspect the records corresponding to `messages`, `variables`, and `chatId`.

- Check the current value of the memory turn count in the application settings, run a trial with two consecutive questions, and confirm that the second question inherits the reference from the first question.
- Sample three terms to check whether their wording is consistent throughout, compare the usage records of the two runs, and confirm the consumption change after adjusting the turn count.
