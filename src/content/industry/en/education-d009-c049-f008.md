# Workflow Orchestration for International Student Admissions and Enrollment Records: Handle Multilingual Materials and Terminology

## What this category's data looks like

This page addresses multilingual materials and terminology processing in international student admissions and enrollment management. The materials come from international student admission brochures, admission letters, and visa application forms. Admission brochures are updated by academic year, admission letters are generated by batch, and visa application forms are adjusted according to embassy and consulate requirements. Fields involve name, nationality, date of birth, passport number, program name, program duration, signature, and receipt. The three types of materials play different roles when entering the workflow: the admission brochure provides the baseline wording for the terminology list and the reference draft, the admission letter carries the back-reference verification of the same record in terms of names, quantities, and dates, and the visa application form serves as the verification object for the completeness of signatures and receipts. Multilingual versions must keep the same terminology consistent throughout the entire text, translated names must be able to back-reference the source text, and after version synchronization they are handed over for external release.

## Configuration and implementation checks

This step is executed by workflow nodes (user selection and branching), outputting branch directions and interaction state records. The unified terminology list and reference draft are continued and completed by subsequent nodes according to the branches. When the user selection node is triggered, the conversation enters an interactive state and records the workflow state. After the user completes the selection, execution continues along the branch corresponding to the selected option.

| Object | Check | Verification action |
| --- | --- | --- |
| International student admission brochure | The baseline wording of the terminology list is consistent with the same terminology throughout the reference draft, and translated names can back-reference the source text | Check the options and branch connections one by one in the node, trigger once to view the node status in the run record, and confirm that the selection result variable has been passed to subsequent nodes |
| Admission letter | The names, quantities, and dates of the same record in the admission brochure and the admission letter match, and versions are synchronized | Reference `variables` and `nodeId` in subsequent nodes and run a trial once, checking whether the fields in the two materials are consistent |
| Visa application form | Signatures and receipts are complete, and the dates of the same record in the admission letter and the visa application form match | Check the signature field and receipt field, and confirm whether the branch goes to the revision path when versions are not synchronized |
| Terminology list and reference draft | The same terminology is written consistently throughout the entire text, and translated names can back-reference the source text | Sample three terms to check whether their wording is consistent throughout the entire text, and record the number of array entries and the tokens of the referenced text |

## Three common errors

- Symptom: The names, quantities, and dates of the same record in the admission brochure and the admission letter do not match. Cause: Multilingual material versions are not synchronized, and fields have not undergone back-reference verification.
- Symptom: The visa application form lacks a signature or receipt. Cause: After the interaction is completed, the process stops, does not go through the supplementary signature branch, and the receipt is not returned.
- Symptom: After selecting an option, the default branch is still taken. Cause: The options and branch connections were not checked one by one, and the selection result variable was not correctly referenced.

## How to verify the setup

Acceptance of this feature: Run a trial for each option one by one, check the branch direction and interaction state in the run record, confirm that each option corresponds to one branch, that the selection result variable has been passed to subsequent nodes, and check the values of `variables` and `nodeId` in the run record.

Business testing: Sample three terms to check whether their wording is consistent throughout the entire text, verify that translated names can back-reference the source text, and record the number of referenced entries and the tokens of the referenced text.

- Check the options and branch connections one by one in the node, and trigger once to view the node status in the run record.
