# Workflow Orchestration for Teacher Qualification Exams and Certification: Coordinate Operations and Application Handover

## What this category's data looks like

The teacher qualification exam and certification involves three types of materials: written and interview registration forms, Mandarin proficiency certificates, and medical examination forms. The registration form is filled out by the candidate and generated by the exam administration system; its fields include name, ID number, subjects applied for, exam district, date, and review signature. The Mandarin proficiency certificate is issued by a testing institution; its fields include certificate number, grade, test date, issue date, and seal. The medical examination form is issued by a designated hospital; its fields include examination conclusion, physician signature, hospital stamp, and examination date. The three types of materials have different update rhythms: the registration form changes with each registration batch, the Mandarin proficiency certificate is valid long-term but its number needs verification, and the medical examination form has a validity period limit. When materials enter workflow orchestration, the registration form serves as the main record anchoring identity and subjects, while the Mandarin proficiency certificate and medical examination form serve as branch condition materials that determine subsequent paths and handover content.

## Configuration and implementation checks

This stage is executed by workflow nodes (user selection and branching), outputting branch paths and interaction state records. "Handover-ready deployment status and operation records" are completed by subsequent nodes continuing execution along the branch. When the user selection node is triggered, the conversation enters an interaction state and records the workflow state; after the user completes the selection, execution continues along the branch corresponding to the selected option.

| Object | Check | Verification action |
| --- | --- | --- |
| Written and interview registration form | Fields, dates, and signatures must correspond item by item with the Mandarin proficiency certificate and medical examination form; the name, quantity, and date of the same record must not mismatch | Check options and branch connections one by one in the node, reference `variables` and `nodeId`, and run a trial once |
| Mandarin proficiency certificate | The certificate number, grade, test date, and issue date must be consistent with the identity information in the registration form; missing signature or receipt is considered unsynchronized | Reference the selection result variable in subsequent nodes and run a trial, then check the node status in the run records |
| Medical examination form | The examination conclusion, physician signature, hospital stamp, and examination date must correspond to the registration form batch; if the version is not synchronized, the branch path will be abnormal | Trigger a user selection node once and check the interaction state and branch path in the run records |
| Deployment status and operation records | Version, connection, and task records must be consistent; check item by item against the handover form once to see which record is missing | Check the node status corresponding to `nodeId` and the `variables` transfer results in the run records |

## Three common errors

- Symptom: The name and date of the same record do not match between the registration form and the Mandarin proficiency certificate. Cause: The two material versions are not synchronized, and the node branch executes along the old version path.
- Symptom: The medical examination form lacks a physician signature or hospital receipt, and one record is missing during handover form verification. Cause: The material enters the workflow before signing and stamping are completed, and the interaction state is recorded prematurely.
- Symptom: After selecting an option, the default branch is still followed, and the process stops after the interaction is completed. Cause: Options and branch connections were not checked one by one, and the selection result variable was not passed to subsequent nodes.

## How to verify the setup

This feature acceptance: run trials for each option one by one, check the branch path and interaction state in the run records, and confirm that `variables`, `nodeId`, and the selection result are consistent

Business testing: check item by item against the handover form once to see which record is missing

- Check options and branch connections one by one in the node, trigger a user selection node once, and check the node status in the run records
- Reference the selection result variable in subsequent nodes and run a trial once; after confirming that version, connection, and task records are consistent, hand over to operations or the next shift
