# Internal System and Data Q&A for Unit-Based System Retrieval: Citation Sources and Traceability

## What the Data for This Category Looks Like
The data for unit-based system retrieval comes from official internal documents of state-owned enterprises, government departments at all levels, and their subordinate public service units. This includes management measures, official red-headed documents, and operation specifications. Updates trigger irregularly when new systems launch or existing systems are revised. There is no fixed update cycle.
A single document typically includes structured fields: issuing unit, document number, issuing date, main text, and attachments. The "affiliated unit" is the core distinguishing field. System formats for different units follow unified internal specifications. Document lengths vary widely. Some system main texts span several thousand characters. This configuration guide uses FastGPT v4.17.0.

## Constraints Imposed on Citation Sources and Traceability
Data is strictly divided by affiliated unit. The traceability link must bind a unit identifier as a filter condition. This prevents returning irrelevant documents across units.
Documents include fixed metadata fields. Traceability displays must extract and show issuing unit and document number. This lets users quickly locate source attribution.
Updates have no fixed cycle. Knowledge base synchronization must support incremental updates by unit. Full synchronization will use excessive system resources otherwise.
Long-text system citation fragments need sufficient context. Without enough context, clause positions in the original document cannot be accurately restored. This harms traceability accuracy.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the main text length of unit-based systems. Prevents truncating context critical to traceability |
| `responseData` | Enable returning issuing unit and document number fields | Displays core metadata for citation sources in responses. Meets traceability display requirements |
| `detail` | Enable full fragment display mode | Restores the context of citation fragments in the original document. Helps users confirm exact clause positions |
| Unit permission binding | Filter by the accessing user's affiliated unit | Ensures only documents from the matching unit are returned. Prevents cross-unit permission leaks |

## Three Common Misconfigurations
- Failing to show citation source metadata in responses. This happens when the `responseData` configuration is not enabled, and required fields like issuing unit and document number are not specified for return.
- Receiving red numeric error codes when calling the FastGPT API. This occurs if `quoteMaxToken` exceeds the current model's context limit, or if unit permission binding is misconfigured leading to failed permission checks.
- Failing to locate the original unit document during traceability. This happens if the affiliated unit identifier is not retained during knowledge base chunking, or if synchronization does not use unit-based incremental updates. This breaks the link between documents and their units.

## How to Verify Correct Configuration
- Submit a query about a specific unit's internal system. Check if metadata like issuing unit and document number appears in the response.
- Review uploaded system documents in the knowledge base. Confirm each document has its affiliated unit identifier bound.
- Call the test API. Verify the length of returned citation fragments matches the `quoteMaxToken` configuration range.
- Switch access permissions for different units. Confirm only citation results for the current user's unit are visible.

These values serve as common starting points, and should be evaluated against the reader’s own sample data.
