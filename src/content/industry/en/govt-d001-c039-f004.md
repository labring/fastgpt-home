# Internal System and Data Q&A for Permission-Controlled File Isolation: Workflow Orchestration
This document is adapted for FastGPT v4.17.0. It provides detailed instructions for workflow orchestration for permission-controlled file isolation scenarios. It targets internal system and data Q&A use cases for state-owned enterprises, government agencies, and public service institutions.

## What data for this category looks like
Data for this category originates from compliant internal documents including system files, business ledgers, and approval forms that require permission controls, from state-owned enterprises, government agencies, and public service institutions. Update cycles adjust alongside internal system revisions and business data iterations, with no fixed schedule. Most documents are structured text with permission tags, and some include attachments. Fields include file permission scope, effective date, file number, and main content. Units include characters, page count, and permission level identifiers.

## What constraints do these characteristics impose on workflow orchestration
Include a permission verification step in the workflow. Match the visitor’s permission identifier with the file’s permission scope to filter out documents outside the user’s permission range. Unauthorized access will occur if this step is omitted.
Configure the workflow to dynamically pull the latest version of permission-controlled files. Avoid static caching to prevent outdated content, as update cycles are not fixed.
Add multi-type file parsing nodes to the workflow. Adapt these nodes to attachment content in different formats to support documents with attachments.
Set up variable extraction rules in the workflow. Extract specified fields from documents for use in subsequent nodes. This ensures information passed through the process complies with permission requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Permission Verification Trigger | Match the user permission identifier in `variables` | Filter documents outside the user’s permission scope, ensuring data isolation |
| File Pull Cycle | 1 hour – 7 days | Adapt to non-fixed document update schedules, prevent cached content from becoming outdated |
| Multi-format Parsing Switch | Enable PDF, Word, and TXT parsing | Adapt to attachment formats for permission-controlled documents, cover common internal file types |
| Variable Extraction Rules | Extract the file number and effective date fields | Match the multi-field structure of documents, provide precise parameters for subsequent nodes |
| `nodeId` Binding | Associate the node ID of the permission knowledge base | Ensure parameter transfer in the workflow is bound to the specified knowledge base, avoid node confusion |

## Three Common Misconfigurations
- Issue: When configuring a knowledge base node in the workflow, an error occurs after directly entering the knowledge base ID or referencing a variable and applying the variable to the knowledge base node. Cause: The knowledge base ID parameter in `variables` was not correctly bound, or the parameter format does not meet the node’s requirements.
- Issue: The knowledge base search node in the workflow returns empty results, and the preset fallback logic is not triggered. Cause: No empty search branch jump was configured, causing the process to interrupt.
- Issue: Fixed parameters related to global permissions are cleared after each conversation, and cannot be saved persistently. Cause: No global variable storage node was configured in the workflow, and the `variables` parameter was not used to persistently save fixed variables.

## How to Confirm the Configuration Is Correct
- Send a test request using user accounts with different permissions. Verify that returned documents only include content within the corresponding permission scope.
- Modify the permission scope or content of an internal document, trigger the workflow to pull the file. Verify that the workflow retrieves the updated content.
- Check the workflow logs. Confirm that the permission parameters in `variables` are correctly passed to the permission verification node.
- Simulate an empty search scenario. Verify that the workflow triggers the preset fallback branch.
