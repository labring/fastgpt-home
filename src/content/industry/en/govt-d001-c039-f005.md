# Internal System and Data Q&A for Permissioned File Isolation: Tool Calling and Plugins

## What Data for This Category Looks Like
This category of data originates from internally permission-controlled system documents and business data attachments from state-owned enterprises, government agencies, and public service institutions. Most files use common office formats such as PDF and Word. Data updates are triggered by internal system revisions and business data iterations, with no fixed cycle. Document structures include structured fields such as chapter titles, clause numbers, issuing entities, effective dates, and permission scopes. The character count of individual documents varies widely, and fields are primarily text and number types, with no mandatory unified quantitative unit requirements.

## Constraints Imposed on Tool Calling and Plugins by These Characteristics
Permissioned file isolation data must align with user access permissions. The tool calling process must first verify the matching relationship between user permissions and file permission scopes to prevent unauthorized access to restricted content. Documents contain structured permission fields, so tool calling must extract these fields as retrieval filter conditions to ensure returned Q&A content only covers scopes accessible to users. Data updates have no fixed cycle, so plugins must support pulling the latest file versions on demand to avoid returning outdated content due to cached old data. The character count of individual documents varies widely, so plugins must adapt to inputs of different sizes to avoid parsing timeouts or failures caused by overly large files.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool Calling Switch | Enabled | Adapt to tool calling requirements for internal system Q&A, enable plugin processing capabilities |
| Permission Verification Configuration | Match by file permission scope | Align user access permissions with file permission fields to ensure content compliance |
| Plugin Timeout Duration | 300–600 seconds | Adapt to time requirements for parsing large internal files, avoid parsing interruptions |
| `toolChoice` | auto | Let the model independently select appropriate tools to handle file parsing or retrieval requests |
| Document Parsing Plugin | Doc2x | Support parsing of standard office format internal files, adapt to common enterprise document types |
| Result Filtering Rule | Match user permission fields | Filter parsing results that exceed the user's permission scope, ensure data security |

## Three Common Misconfigurations
- Plugins return empty results when parsing internal permission files. The cause is that permission verification rules are not configured, and user permission matching is not performed on the parsed file scope.
- When calling the API to obtain Q&A results, associated knowledge base file information is not returned. The cause is that the file traceability configuration for tool calling is not enabled, and associated file fields generated during the parsing process are not recorded.
- Internal format files cannot be parsed normally after replacing the document parsing plugin. The cause is that the adaptation configuration items for document parsing are not adjusted, and the parsing logic of the original plugin is still used.

## How to Verify Successful Configuration
- In the FastGPT v4.17.0 platform, the tool calling configuration page is accessed, and the permission verification rule is confirmed to be enabled and matching user permission fields.
- A test file within the allowed permission scope is uploaded, triggering plugin parsing, and the parsing result is checked to include the file's permission scope information.
- The API is called to initiate a test query, and the returned result is confirmed to include associated file traceability information.
- `toolChoice` is adjusted to auto, a short test query is initiated, and the model is confirmed to independently call the plugin to handle file parsing requests.
