# Internal System and Data Q&A for Permitted File Isolation: Model Integration and Configuration

## What this category of data looks like
This category of data originates from official institutional documents and permission-bound business data files from central state-owned enterprises and government internal sources. Data update rhythm aligns with internal document issuance processes and business data iteration nodes. There is no unified fixed real-time update cycle. Single documents are mostly official texts with document numbers, effective dates, and permission scope markers. Their structure includes chapter hierarchies, clause numbers, and responsible entity fields. Single-document content length ranges from thousands to tens of thousands of characters. Single-file size mostly falls between tens of KB and several MB.

## Constraints on model integration and configuration from these data characteristics
Since the data has clear permission scope markers, bind permission verification logic during model integration. This ensures only document fragments accessible to the current user load on each invocation.
Since documents use official document structure, retain metadata such as permissions and effective dates during context splicing. This avoids generating responses that violate institutional requirements.
Since update cycles are not fixed, match configured context refresh frequency to internal document update rhythms. This prevents recalling expired content.
Since single-file length varies widely, use elastic adaptation for model invocation context and generation length configurations. Do not use fixed thresholds.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the single-document length of internal institutional documents and the context splicing requirements of multiple permitted documents, avoiding exceeding the model's context limit |
| `maxTokens` | `2000–3000 token` | Controls the generation length of single-round Q&A, ensures responses are concise and accurate, and adapts to the Q&A scenario of internal institutional clauses |
| `quoteMaxToken` | `1500 token` | Limits the length of referenced fragments from a single permitted document, ensures context does not overflow, while retaining the integrity of key institutional clauses |
| `temperature` | `0.1–0.3` | Reduces the divergence of responses, ensuring the rigor and standardization of internal institutional Q&A |
| `AIPROXY_API_ENDPOINT` | Internal privately deployed proxy address | Ensures permitted file data does not leave the internal network, complying with data security requirements of central state-owned enterprises and government bodies |
| `AIPROXY_API_TOKEN` | Dynamic key bound to user permissions | Assigns independent keys to users at different permission levels, preventing cross-permission access and conversation record sharing |

## Three common mistakes
- Phenomenon: An `[] is too short - 'messages'` error occurs during model testing. The cause is that context recall logic is not configured correctly, resulting in an empty or insufficiently long conversation message array passed to the model.
- Phenomenon: After upgrading FastGPT v4.17.0, models connected via the private proxy cannot be invoked normally. The cause is that the `AIPROXY_API_ENDPOINT` configuration parameter was not updated synchronously, or the service was not restarted to load new configuration items.
- Phenomenon: After adding a new model configuration, the corresponding entry cannot be displayed in the management interface, or different users share conversation records and accessible documents. The cause is that the configuration file was not correctly written to the specified directory, or independent `AIPROXY_API_TOKEN` was not bound to each user to implement permission mapping.

## How to confirm configuration is complete
- Run the built-in model testing function in the management interface. Check that no `[] is too short - 'messages'` error or similar errors are returned, confirming the conversation message array loads normally.
- View the service running logs. Confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations have been correctly read, with no records of connection failures or key verification failures.
- Assign independent keys to users at different permission levels. Conduct cross-user Q&A testing, confirm each user can only access documents and conversation records within their own permission scope.
- Restart the FastGPT service. Confirm the new configuration entry is normally displayed in the model management interface, with no configuration loss.
