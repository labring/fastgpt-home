# Internal System and Data Q&A for Query Result Reports: Tool Calling and Plugins

## What the data for this category looks like
This documentation applies to FastGPT v4.17.0. Data for query result reports originates from archived internal system documents of state-owned and public-sector enterprises, as well as structured statistical reports generated by various business modules. Update frequencies are daily, weekly, or monthly, based on the business scenario. The core content consists of structured tables, paired with header descriptions and data rows. Fields include unique report identifiers, affiliated business modules, generation times, statistical indicators, indicator units, and more. The character length of individual documents varies widely, ranging from hundreds to tens of thousands of characters. Field types are uniformly text or numeric.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Fixed field formats in structured tables require explicit specification of target parsing fields during tool calls, to prevent format confusion caused by generalized extraction. For report data with multiple update frequencies, plugin calls must match the corresponding data refresh cycle. Cache durations must align with update rhythms to avoid returning expired statistical results. For report documents with wide character length ranges, the tool calling context window must reserve sufficient space to prevent truncation of key indicator rows and header descriptions. The binding of numeric fields and units requires plugins to support numeric verification and unit matching during calls, to ensure business rationality of output results.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically trigger tool calls adapted to structured reports, recognize fixed fields and numeric units |
| `functionCall` | `enabled` | Enable function calling capabilities, support generating structured output results based on report fields |
| Tool call timeout | `300 seconds` | Adapt to parsing and data retrieval durations for long report documents, avoid mid-call truncation |
| Plugin cache duration | `1–24 hours` | Match the daily/weekly update rhythm of reports, prevent returning expired statistical data |
| Number of items returned per single tool call | `Top 10` | Control data volume per round of calls, avoid exceeding context window limits |

## Three Common Misconfigurations
- Symptom: A `400 Bad Request` error is returned when calling the OpenApi interface, with a prompt indicating missing function call parameters. Cause: The `functionCall` configuration is not enabled, so tool calls for structured reports cannot be triggered.
- Symptom: The order of result fields returned by tool calls is disrupted, and some indicator units are missing. Cause: The `toolChoice` setting is not configured to the structured parsing adaptation mode, leading to field matching errors from generalized extraction.
- Symptom: External associated data cannot be properly retrieved when calling online plugins. Cause: Domestic network adaptation rules are not configured, causing the online plugin to fail to access target resources.

## How to Confirm Configurations Are Correctly Set
- Pass a standard internal report data sample to the test interface, verify whether tool calls are automatically triggered and return structured results categorized by fields.
- Review plugin call logs, confirm that cache duration matches the report update rhythm, and there are no records of expired data being returned.
- Adjust the configuration values of `toolChoice` or `functionCall`, verify whether tool call behavior meets expected outcomes under different parameters.
- Check the configuration items of online plugins, confirm that access paths have been adapted for domestic environments, and there are no interception prompts.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
