# Internal System and Data Q&A for Query Result Reports: Deployment and Upgrade

## What the data for this category looks like
Data sources for query result reports fall into two categories. One category is official internal system documents of state-owned and public-sector enterprises. The other category is structured business statistical reports.
Update rhythms differ significantly. System documents are updated quarterly or semi-annually with revisions and releases. Business reports are updated daily or in real time.
The document structure is divided into a metadata area and a data area. Metadata includes report number, associated system entry, and statistical cycle. The data area contains specific statistical values. Fields cover statistical item name, value, and unit. Units include multiple types such as pieces, person-times, ten thousand yuan, days, and others.

## What constraints these characteristics impose on deployment and upgrade
The data includes both unstructured system documents and structured business reports. During deployment, multi-source data synchronization adaptation rules must be configured to support access to different format data sources.
The differing update rhythms of different data sources require setting differentiated incremental synchronization cycles to avoid resource occupation from ineffective synchronization.
The diversity of fields and units requires pre-configuring unit mapping rules to ensure uniform display of values during Q&A.
During the upgrade process, existing cached report Q&A results must be kept from failing to avoid user query interruptions. Storage expansion space must also be reserved to accommodate growth in business report data.

## How to set the configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Use a dedicated cluster connection string with SASL authentication, add the `readPreference=secondaryPreferred` suffix | Stores system documents and report metadata, supports high-concurrency read/write operations and load balancing |
| `REDIS_URL` | Use a dedicated cache instance with 4096 MB of memory capacity | Caches report query results and Q&A contexts to reduce database access pressure |
| `STORAGE_S3_ENDPOINT` | Use a dedicated endpoint address adapted to local object storage or cloud service providers | Stores large-volume system documents and report attachments to avoid occupying application server disk space |
| `DB_MAX_LINK` | 64–128 connections | Matches the database connection pool upper limit to prevent connection exhaustion during concurrent report queries |
| Incremental Synchronization Cycle | Set separately by data source type: 1800 seconds for system documents, 300 seconds for business reports | Matches the update frequency of different data sources to reduce resource consumption from ineffective synchronization |
| Unit Mapping Rules | Preset a correspondence table for common statistical units | Unifies unit display for reports from different sources to avoid unit confusion during Q&A |

## Three common mistakes
- The front-end access configuration address returns a 404 status code, and the page fails to load. The cause is failure to correctly configure the `FE_DOMAIN` parameter to point to the actual deployed front-end domain name, or failure to synchronize front-end static resources to the specified storage path.
- Team members cannot log in or view report data, and user information fields are empty. The cause is failure to configure `REDIS_URL` leading to session cache failure, or a `DB_MAX_LINK` setting that is too low leading to failure to write user data.
- The number of results returned by report queries is less than the actual number of entries in the data source. The cause is an overly long incremental synchronization cycle, meaning some unsynchronized business data cannot be retrieved, or insufficient database connection pool upper limit leading to partial query failures.

## How to confirm the configuration is complete
- Access the configured `FE_DOMAIN` address to confirm the front-end page loads normally, with no prompts for failed resource loading.
- Run a manual synchronization task to check that the background logs have no database connection errors, and the number of synchronized data entries matches the statistical results from the actual data source.
- Attempt to add a team member and assign corresponding permissions, then confirm that the member can log in normally and access the report Q&A function.
- Submit a query that includes report fields to confirm that the returned results contain correct statistical values and units.
