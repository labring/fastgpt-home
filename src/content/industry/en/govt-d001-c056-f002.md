# Internal System and Data Q&A for Natural Language Query of Project Data: Vector Models and Indexing

## What This Type of Data Looks Like
Data sources include internal project ledgers of central and local state-owned enterprises, officially released internal management system documents, project approval and circulation records, weekly progress reports, and final accounting statements. Update rhythm triggers based on project progress milestones; data updates on demand alongside approval and progress changes after project initiation, while fixed system documents only receive updates when revised. Document structures combine structured fields and unstructured text. Structured fields include project number, responsible employee ID, budget amount, completion percentage, and similar items. Unstructured content includes system clauses, project descriptions, and approval opinions. Fields carry clear units such as ten thousand yuan and natural days.

## Constraints on Vector Models and Indexing Workflows
Under FastGPT v4.17.0, mixed structured and unstructured data requires distinguishing field attributes during chunking to avoid splitting cross-field associated information into different chunks. Frequently updated project data requires indexes to support incremental updates, avoiding excessive resource consumption from full reconstruction. Fields with clear units increase precision requirements for vector modeling, and unit information must be retained to avoid ambiguous matching of similar project entries. Long-text system clauses and project descriptions affect single chunk length settings; overly long chunks increase vector computation load, while overly short chunks lose contextual associations.

## Configuration Recommendations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the mixed structured field and long text structure of project documents, balancing contextual completeness and computational efficiency |
| Overlap Length | 100–150 characters | Retains coherent associations across chunks for system clauses and project progress descriptions |
| Similarity Threshold | 0.72–0.85, calibrated via actual testing | Project data fields have strong specificity, preventing accidental matching of unrelated project entries |
| Single Search Limit | Top 10 entries | Core associated project data typically appears in the top positions of search results, controlling return volume to reduce contextual load |
| `defaultToken` | 4096 | Matches the conventional contextual length of a single project document or system clause |
| `maxToken` | 8192 | Supports the Q&A requirement of integrating multiple associated project documents and system texts |

## Three Common Misconfigurations
- Single file remains stuck in indexing: The background task list shows the file’s indexing progress has stalled, with a status of “rebuilding in progress”. The cause is that the file contains an extremely long nested structured table, and chunking exceeds the single-chunk token limit.
- Knowledge base priority settings do not take effect: Q&A returns content from non-specified knowledge bases first. The cause is that the retrieval configuration did not enable the knowledge base priority switch, or the configuration order is incorrect.
- Index switch timeout: Operations return a 60-second timeout error. The cause is that concurrent thread count was not limited during index reconstruction, leading to server resource exhaustion.

## How to Verify Successful Configuration
- Upload a typical project system document, access the chunking preview interface, and confirm that chunk length and overlap length match the configured values.
- Initiate a query that includes a project number and its corresponding system clause, and verify that the similarity score of returned results falls within the set threshold interval.
- After configuring knowledge base priority, initiate a query associated with content from two knowledge bases, and confirm that results prioritize the specified high-priority knowledge base.
- Upload updated project data, check index reconstruction duration, and confirm that no long-term stalled status occurs.

The values provided here are common starting points, and should be evaluated against the reader’s own sample data.
