# Internal System and Data Q&A for Natural Language Query of Project Data: Multi-turn Dialogue and Prompt Engineering

Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category of Data Looks Like
Data for this category comes from structured files exported from internal project management systems of Chinese state-owned and public sector organizations. Updates are triggered by project initiation, modification, completion, or scheduled synchronization. Most documents are in .xlsx or .csv format, and include fields such as project unique identifier, name, responsible department, budget amount, planned cycle, and actual completion node. Field formats are unified, with no free text mixed in. Attributes of individual data entries are clear and can be directly located via their fields. Planned cycles are measured in natural days.

## Constraints Imposed by Data Characteristics on Multi-turn Dialogue and Prompt Engineering
The structured, clearly defined field characteristics of this data source require that multi-turn dialogue clearly limit the query scope to avoid cross-project data confusion. For real-time or periodically updated data sources, the latest data synchronization node must be referenced during dialogue, and prompts must specify that only the latest synchronized dataset is used. The single-format document structure requires prompts to clearly specify the worksheet and field range to read, to avoid returning irrelevant content. Multi-field attribute requirements mean users must be gradually guided to clarify specific query fields during multi-turn interactions, reducing invalid returns. Due to intranet deployment environment restrictions, corresponding access permissions must be configured, and prompts must restrict use to only authorized internal data sources. The `messages` context management for multi-turn dialogue must adapt to the retention length of project data, with `chatId` used to distinguish the query scope of different dialogues.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `variables` | Bind project unique identifier variable | Lock the current query project scope during multi-turn dialogue to avoid cross-project data confusion |
| Query Optimization | Enabled, calibrated based on actual testing | For field matching of structured project data, optimized query instructions can more accurately locate target fields |
| Maximum Context | 8000–12000 token | Adapt to project historical query and reply context retained during multi-turn dialogue |
| Maximum Tool Calls per Invocation | Top 3 entries | Avoid returning excessive redundant project data, focus on core query results |
| Tool Call Timeout | 600 seconds | Adapt to latency of reading structured files on intranet |
| Input Guidance | Preset project data query examples | Help users clarify queryable fields and scenarios, reduce invalid questions |

## Three Common Misconfigurations
- Phenomenon: Input guidance and word bank are configured, but preset project query examples are not displayed in the dialogue interface. Cause: The input guidance switch for the dialogue interface is not enabled, or the word bank is not bound to the dialogue module of the current application.
- Phenomenon: After uploading .xlsx format project data files, the dialogue cannot read and repeat the file content. Cause: The structured file parsing tool is not configured, or the prompt does not clearly specify the worksheet range for reading .xlsx files.
- Phenomenon: Consecutive queries for data from different projects in multi-turn dialogue result in cross-project confusion. Cause: The `variables` binding of the current query project identifier is not configured, and the query scope is not locked during the dialogue.

## How to Verify Successful Configuration
- Initiate a query containing specific project fields, verify that `chatId` correctly associates the current dialogue's project query scope, and that returned results only include project data within the authorized scope.
- Initiate consecutive queries across different projects, verify that the dialogue context correctly locks the current query's project scope.
- After uploading .xlsx format project data files, initiate a query to read specified fields, verify that results match the file content.
- View the input guidance area of the dialogue interface, verify that preset project data query examples are displayed.

The values provided are common starting points and should be measured against the reader's own samples.
