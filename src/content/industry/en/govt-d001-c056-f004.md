# Internal Policy and Data Q&A for Project Data Natural Language Query: Workflow Orchestration

## What Data in This Category Looks Like
Data sources are internal project management systems and internal policy compilation documents for public sector and state-owned enterprise entities. Update cadence follows two schedules: project data is updated in sync with project node progress, while internal policy documents are updated via internal document issuance processes. Document structure falls into two categories:
Project data documents include fields such as project number, project name, project initiation time, budget amount, current progress, responsible department, and node completion status.
Policy documents include fields such as document number, issuing department, effective date, and clause content.
Field units include ten thousand yuan, percentage, natural day, standard number format, and other standard units.

## What Constraints These Characteristics Impose on Workflow Orchestration
Because project data includes clear unit-bearing fields such as amount and progress, workflow orchestration must configure field validation links to ensure extracted field values match preset units.
Because the two types of data sources have different update cadences, the workflow must set separate data source synchronization trigger rules. Project data can be pulled according to the project node update cycle, while policy documents can be updated in sync with internal document issuance.
Because document structures differ significantly, the workflow must split into separate nodes to handle project data retrieval and policy document retrieval separately, to avoid confusing field logic.
Additionally, project data and policy documents have associated relationships. The workflow must configure associated fields via `variables` to enable cross-document information linkage. This configuration can be completed via the visual panel in FastGPT v4.17.0.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data Source Sync Cycle | 7 days or on-demand trigger | Matches the update cadence of project data as it progresses through nodes, avoids using expired data |
| Variable Mapping Rules | Bind project number, budget amount, progress percentage fields | Aligns with the standard field structure of project data documents, ensures extracted information is accurate |
| Context Retrieval Limit | Top 8 results | Adapts to the content length of individual project data and policy documents, prevents exceeding model processing limits |
| `variables` configuration | Associate project responsible department and document number variables | Enables cross-data source information linkage, matches the association logic between internal policies and projects |
| Node Trigger Condition | Match by question keywords | Differentiates separate processing paths for project data queries and policy Q&A, optimizes call efficiency |
| `nodeId` setting | Assign a unique identifier to each data source node | Distinguishes workflow nodes for different data sources, prevents call conflicts |

## Three Common Mistakes
- Workflow runtime generates gpt-4o-mini call error logs, but the corresponding model node is not configured. The cause is leftover unused node configuration that was not cleaned up, or unauthorized model call parameters were mistakenly bound in global variables.
- Unable to modify historical records of global variables in the workflow. The cause is not entering the variable editing panel for the corresponding node, or not unlocking editable permissions for the variable.
- The unit of project data fields returned by the workflow does not match. The cause is that no field validation link was configured, and extracted numerical values were not bound to preset units, resulting in units that do not align with business logic.

## How to Confirm the Configuration is Complete
- Trigger a test query, verify that the project data fields returned by the workflow match the fields in the internal system, confirm that the variable mapping configuration takes effect.
- View the workflow logs, confirm that the data source synchronization nodes trigger according to the preset cycle, and no timeout or data pull failure records appear.
- Check the `variables` and `nodeId` configurations, confirm that each node's identifier and variable bindings have no duplicates, to prevent call conflicts.
- Simulate different types of queries, confirm that the workflow can correctly distinguish between project data query and policy Q&A processing paths, and trigger corresponding nodes.
