# Internal System and Data Q&A for Natural Language Query of Project Data: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from structured business data in internal project management platforms, financial accounting systems, and OA approval modules of state-owned enterprises. Data update rhythm changes with the project lifecycle: full basic data is added after project approval is passed, progress report data is synced weekly, budget execution and settlement data is updated monthly, and archived locking of historical projects is completed at the end of each quarter. A single data entry includes fields such as project number, project name, declaring department, approval date, budget amount, current progress node, responsible employee ID, associated document storage path, etc. The unit of budget amount is ten thousand yuan, and progress nodes are identified by stage sequence numbers. This document is written based on FastGPT v4.17.0.

## What constraints these characteristics impose on tool calling and plugin workflows
Data sources for this category are scattered, update rhythms are uneven, and sensitive business fields are included, which creates multiple constraints for tool calling and plugin configuration. Heterogeneous data from multiple systems requires plugins to configure cross-source interface docking rules to unify authentication and data formats across different platforms. Business data with different update frequencies requires plugins to support incremental pull logic, only syncing new or changed data to avoid resource occupation from full pulls. Sensitive fields such as responsible employee ID and associated document path require plugins to have built-in desensitization rules to block or replace sensitive information before returning results. Fixed archive time nodes require plugins to add data filtering logic to automatically exclude locked historical project data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to "auto" | Allow the system to automatically match tool calling logic adapted for multi-source data |
| `functionCall` | Enable batch calling mode | Support calling interfaces from multiple internal systems simultaneously to complete cross-source data integration |
| Data pull frequency | Set by data type: basic data once daily, progress data once every 6 hours, budget data once daily | Match the update rhythm of different business data to reduce invalid requests |
| Field mapping rules | Convert internal field names to natural language expressions, for example map "budget" to "project budget amount" | Allow natural language queries to accurately match internal data fields |
| Data desensitization switch | Enable, configure replacement rules for employee ID and document path fields | Block internal sensitive business information |
| Plugin timeout period | 30 seconds | Adapt to the interface response delay of internal systems to avoid premature request interruption |

## Three common configuration errors
- Phenomenon: A "parameter format error" is returned when calling a plugin, and logs show the passed image list field format does not meet requirements. Cause: No format rules for multi-image parameter passing are configured, and image requirements from natural language queries are not converted to the array format supported by the plugin.
- Phenomenon: The plugin cannot access associated documents stored in internal MinIO, with a "connection timed out" prompt. Cause: No intranet access whitelist is configured, and the intranet address of MinIO is not added to the plugin's allowed access list.
- Phenomenon: Sensitive information such as employee ID and document path is included in results returned after plugin calling. Cause: The data desensitization switch is not enabled, or replacement rules for corresponding sensitive fields are not configured.

## How to confirm the configuration is correct
- A natural language query is initiated, such as "query the project budget of XX department's projects approved in 2024", and returned result fields are checked against expected values.
- Plugin calling logs are reviewed to confirm that the authentication process completed normally, with no authentication failure errors.
- The plugin's desensitization configuration is checked, and a query containing sensitive fields is manually triggered to confirm that sensitive information has been blocked or replaced.
- The query time range is adjusted to confirm that the plugin automatically filters archived project data and does not return outdated content.
