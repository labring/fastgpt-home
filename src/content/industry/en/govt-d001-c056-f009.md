# Internal System and Data Q&A for Project Data Natural Language Query: Model Access and Configuration

## What the Data for This Category Looks Like
Data sources for this category include internal project management systems, officially released internal system compilations, monthly progress ledgers, and approval process records. Data updates sync in real time as projects advance. System documents are updated at each revision and release node. Monthly ledgers update on a fixed schedule. Each data entry includes fields such as project number, affiliated department, budget amount, execution progress, associated system clauses, and approval node records. The budget field uses RMB ten thousand yuan as its unit. The progress field uses percentage format. The project number is a unique string identifier.

## What Constraints These Characteristics Impose on Model Access and Configuration
This category of data includes long-text system clauses and structured project fields. Long-text content may exceed the maximum context limit supported by the model. Context-related configuration adjustments are required. Structured fields have clear units and unique identifiers. The model must accurately recognize units and associate them with corresponding projects. Appropriate parameter configuration is needed to ensure semantic understanding accuracy. Data update frequency is high. Concurrency and timeout configurations for model calls must be adapted to real-time query requirements to avoid query failures caused by request overload. In addition, associated system clauses vary widely across different projects. The model’s ability to extract cross-document associated information must be ensured.

## How to Set Configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | This category includes long-text system clauses and multi-field associated data, requiring sufficient context capacity to ensure the accuracy of associated queries |
| `maxTokens` | 2000–3000 token | Parsing results for structured project fields and system clauses require sufficient output length to avoid truncation of critical information |
| `quoteMaxToken` | 1500–2000 token | Sufficient length of original system text fragments must be retained as reference basis to match the associated query requirements of project data |
| `temperature` | 0.3–0.5 | This scenario requires accurate matching of project data and system clauses. A lower temperature improves answer consistency and accuracy |
| `toolChoice` | auto | Automatic tool invocation must be triggered to extract precise information from structured project fields, adapting to multi-dimensional query requirements |
| `AIPROXY_API_ENDPOINT` | Fill in according to the interface address of the accessed large model service provider | Ensure correct model request routing, adapting to the access specifications of third-party large models |

This configuration description is written based on FastGPT v4.17.0.

## Three Common Mistakes
- Phenomenon: A third-party large model interface returns a 429 status code, prompting request limit exceeded. Cause: Concurrency limits are not configured. When multiple project data query requests are initiated simultaneously, the interface concurrency quota of the cloud service provider is exceeded.
- Phenomenon: The model fails to accurately recognize units in project data, such as mistaking "ten thousand yuan" for "yuan" in the budget field. Cause: The `toolChoice` automatic mode is not enabled, or the `temperature` parameter is configured too high, resulting in insufficient semantic understanding accuracy for structured fields.
- Phenomenon: Speech recognition model options are not displayed in the interface, making speech input configuration unavailable. Cause: Related speech module settings are not enabled, or dependency packages for the corresponding model are not loaded, causing the optional model list to fail to display normally.

## How to Confirm Configuration Is Complete
- Initiate a project query associated with long-text system content, check the context coverage of the returned results, confirm that no critical information is truncated, and adjust the corresponding configuration items to meet requirements.
- Initiate multiple concurrent query requests, verify that the interface does not return errors such as 429 indicating limit exceeded, and adjust concurrency configurations to adapt to the service provider’s quotas.
- Test the recognition accuracy of structured project fields, confirm that the model can correctly match units and associated systems, and adjust the `temperature` and `toolChoice` configurations to meet requirements.
- Verify large model API endpoint and token configuration, confirm format correctness and absence of input errors.
