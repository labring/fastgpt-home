# Internal Policy and Data Q&A for Project Data Natural Language Query: Deployment and Upgrade

## What the data for this category looks like
This category’s data comes primarily from internal project management systems, financial ledgers, approval archive files, and internal policy documents of state-owned enterprises. Data update rhythm adjusts with the project lifecycle: high-frequency synchronization during project initiation, weekly or monthly batch updates during execution, and archiving and freezing after project completion. Documents are mostly a mix of structured tables and semi-structured text, including fields such as project unique identifier, name, person in charge, budget amount, execution progress, and associated policy number. Units include ten thousand yuan, percentage, natural days, and other standard units.

## Constraints imposed on deployment and upgrade
This category’s mixed data structure and dynamic update rhythm create multiple constraints for deployment and upgrade.
Relational database storage must support structured project data. Configure parameters such as `PG_URL` to connect to internal ledger systems.
Configure `STORAGE_S3_ENDPOINT` to connect to compliant storage services for semi-structured policy documents.
Data update frequency shifts with project phases. Reserve adjustable synchronization task cycles after deployment to avoid core resource usage during peak hours.
Fields contain sensitive business information. Synchronously verify access permission configurations during upgrades to prevent unauthorized access.
Use the project unique identifier field as a retrieval association condition. Ensure database index configurations match business logic.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `PG_URL` | `postgresql://username:password@host:5432/project_db` | Connects to the relational database for internal project management, uses standard PostgreSQL connection format |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com` (or internal compliant storage node address) | Stores project-related policy documents and parsed files, must comply with state-owned enterprise data storage compliance requirements |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches retrieval results and synchronization task status, uses database 0 to isolate business data |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent query volumes for project data, avoids exhausting database connections |
| `ROOT_KEY` | Random string generated per enterprise internal key management rules | Serves as the platform super administrator verification key, must be rotated regularly during version upgrades |
| `FILE_TOKEN_KEY` | Encryption key consistent with the internal file system | Verifies uploaded file legitimacy, prevents malicious file injection into the system |

## Three common mistakes
- Symptom: When using the chat interface, uploading a project-related PDF or Word file results in parsing failure and returns storage or verification-related errors. Cause: `STORAGE_S3_ENDPOINT` or `FILE_TOKEN_KEY` is not configured correctly, interrupting storage and legitimacy verification steps after file upload.
- Symptom: After deployment completes, the registration entry cannot be found, and new users cannot create platform accounts. Cause: `ROOT_KEY` is not configured correctly, or the initial administrator account creation process is not finished, preventing permission verification logic from triggering normally.
- Symptom: The index debugging edit button cannot be located in the retrieval test interface, making direct adjustment of project data associated with retrieval results impossible. Cause: After upgrading to FastGPT v4.17.0, the temporary edit function of the retrieval test interface has been optimized. Complete index configuration adjustments in the content management module of the corresponding knowledge base.

## How to verify correct configuration
- Run the database connection test script to validate connectivity for `PG_URL` and `REDIS_URL`, and confirm the current number of connections does not exceed the `DB_MAX_LINK` configuration value.
- Upload a test project policy document to confirm file upload, parsing, and storage processes function normally with no error prompts.
- Log in to the platform using the super administrator key, create a test account, and verify permission allocation and login processes work correctly.
- Submit a natural language query targeting project data, and confirm retrieval results include accurate project fields and associated policy information.

The values provided are common starting points and should be measured against the reader's own samples.
