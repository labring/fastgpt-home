# "One Thing to Accomplish Efficiently" Joint Handling Consultation and Reply: Multi-turn Dialogue and Prompt Configuration

## What this category’s data consists of
This category’s data primarily comes from the national government service platform "One Thing" special zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. Update frequency is daily. Daily documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts. Fields cover associated handling departments, processing nodes, material requirements, circulation status, and other relevant details. No extra custom statistical fields are included. All data follows government service standard formats.

## Constraints imposed by these features in the multi-turn dialogue and prompt link
Multi-turn dialogue must retain historical context of cross-departmental item associations and material circulation to support cross-departmental data sources. This avoids repeatedly asking the public to submit duplicate materials. Prompt configuration must synchronize the latest joint handling item list regularly to support daily updated data sources. This ensures the timeliness and accuracy of replies. Dialogue must accurately match field rules for different document types during interactions. For example, extract material requirements from application forms and track processing nodes from circulation sheets. Staff must verify material reuse logic. This prevents the public from submitting duplicate materials, ensures smooth joint handling processes, and avoids violating government service requirements for reducing certificates to improve public convenience.

## How to configure the settings
These configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier per session, retain for 7 days | Associate historical dialogue for cross-departmental joint handling, ensure different acceptance links share session context |
| `messages` | Retain the first 10 rounds of dialogue content | Focus on the consultation link of the current joint handling item, avoid interference from redundant historical information on replies |
| `variables` | Preload joint handling item list and electronic certificate fields | Quickly call standardized government data, reduce real-time retrieval times |
| Maximum context length | 800–1200 characters | Adapt to the length of multi-departmental associated information for joint handling items, balance response speed and information completeness |
| Question optimization | Calibrate based on actual testing | Convert colloquial public inquiries into structured questions that comply with government service specifications |

## Three common misconfigurations
- After calling the `chatId` parameter, the dialogue log does not display the associated session identifier, and background logs cannot match historical joint handling records. Cause: The generation rule for `chatId` is not configured correctly, or the session validity period is set too short, causing the identifier to expire.
- Users accessing unauthenticated links delete dialogue content, and the corresponding background logs are synchronously deleted. Cause: The independent storage configuration for dialogue logs and user sessions is not enabled, causing user deletion operations to be synchronized to the background log database.
- Historical dialogue-saved global variables cannot be loaded in the workflow, and material list data for joint handling items cannot be reused. Cause: The historical context call node is not configured in the workflow, or the synchronization scope of global variables does not cover cross-session scenarios.

## How to confirm correct configuration
- Launch an unauthenticated joint handling consultation dialogue, check whether the dialogue interface displays a unique session identifier, and verify whether the background log associates this `chatId`.
- Call the `variables` parameter to load the pre-defined joint handling item list, confirm that corresponding field content can be directly extracted during dialogue.
- Delete user dialogue content, check whether the background log retains the original session record, and confirm that no synchronous deletion occurs.
- Launch multi-turn cross-departmental consultation, confirm that the dialogue context retains information from previous processing nodes.

The values provided here are common starting points, and should be evaluated against the user’s own samples.
