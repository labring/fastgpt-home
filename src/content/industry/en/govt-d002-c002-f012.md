# One-Stop "Efficiently Complete One Task" Collaborative Service: Inquiry and Reply — Deployment and Upgrade

## What this category of data looks like
This category of data typically originates from the national integrated government service platform’s "One Task" dedicated zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. The update frequency is daily. Daily documents include collaborative service item lists, one-time notice sheets, collaborative service application forms, material circulation sheets, parallel approval opinions, and completion receipts. Common data fields include leading department, associated item list, application material reuse rules, parallel processing nodes, and completion status identifiers. There is no unified fixed unit. Some fields need to adapt to exclusive encoding formats of departmental systems.

## What constraints do these characteristics impose during deployment and upgrade
Data sources for this category are scattered and updated daily. During deployment, configure multi-source data synchronization links to ensure real-time pulling of incremental data and avoid lag in inquiry and reply content. Collaborative service documents have diverse formats, including lists, forms, receipts, and more. During upgrade, retain compatibility with old document parsing logic to prevent service interruptions. Cross-departmental data have different field encodings. Complete exclusive field mapping configuration during deployment to avoid abnormal data circulation. Inquiry and reply need to link to real-time collaborative service status. During deployment, grant access to departmental approval system interface permissions. During upgrade, verify interface compatibility to ensure accurate reply information.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/[database name]?authSource=admin` | Collaborative service business data requires persistent storage. Correct configuration of this parameter with database connection information ensures stable reading and writing of data such as item lists and approval opinions |
| `REDIS_URL` | `redis://:[custom password]@[host address]:[port]/0` | Used to cache frequently queried collaborative service item information and user inquiry context. Proper configuration reduces database load and improves inquiry response speed |
| `STORAGE_S3_ENDPOINT` | Fill in according to the endpoint provided by the actual cloud storage service provider | Used to store attachment files such as collaborative service application forms and completion receipts. Correct endpoint configuration ensures normal file upload and download processes |
| `FILE_TOKEN_KEY` | 32-bit randomly generated string | Used to generate temporary access tokens for attachment downloads. Prevents unauthorized users from accessing sensitive documents related to collaborative services and ensures data security |
| `DB_MAX_LINK` | `200 connections` | Limits the maximum number of connections in the database connection pool. Avoids occupying excessive database resources during multi-department data synchronization and affects service availability |

## Three common mistakes
- Phenomenon: After upgrading to FastGPT v4.17.0, the plugin editing interface always displays "Unsaved" at the top regardless of whether the save button is clicked. Cause: The `FE_DOMAIN` parameter is not configured correctly, causing front-end status synchronization exceptions and failure to recognize the return result of the save operation.
- Phenomenon: After deployment, some browsers cannot load the collaborative service inquiry page normally, with style disorder or interface request failures. Cause: The browser version requirements of FastGPT v4.17.0 are not followed. Some older browsers do not support the latest front-end rendering features.
- Phenomenon: An error stating that the rehype-raw module cannot be found appears when building the deployment image, even though the dependency installation command was run. Cause: Dependencies are not locked during deployment installation, or incompatible dependency versions with FastGPT v4.17.0 are used, causing the module to fail to load correctly.

## How to confirm the configuration is correct
- Run the database connection test command to verify whether the connection information configured in `MONGODB_URI` can normally read and write collaborative service business data.
- Upload a standard collaborative service application form attachment to verify whether the storage service configured in `STORAGE_S3_ENDPOINT` can complete the upload and download process normally.
- Initiate a test inquiry to query basic information about collaborative service items to verify whether the cache service configured in `REDIS_URL` can normally cache query results.
- Generate a temporary download link for a collaborative service document to verify whether the token configured in `FILE_TOKEN_KEY` can be normally generated and pass validity verification.
