# Real Estate Registration Service Consultation and Reply: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
This category of data originates from real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories, with a daily update frequency. Documents handled daily include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and property registers. Data fields cover real estate location, right type, right holder information, restriction status, and more. All fields follow unified specifications from natural resource systems, and no custom units are used.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The multi-system collaborative data source requires retaining complete contextual connections during multi-turn dialogue. Use the `chatId` and `messages` parameters to maintain conversation state consistently. Daily updated data demands that dialogue calls access only currently valid register information. Prompts must explicitly limit calls to the latest version of system data. Diverse document structures for ownership certificates require multi-turn dialogue to gradually guide users to supplement missing materials. Prompts must preset keyword extraction logic to identify core fields such as real estate location and right holder information. Since errors may lead to registration mistakes and administrative litigation, strictly verify the consistency between input content and system data during dialogue. Avoid generating inaccurate reply guidance.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, adapted for real estate registration service consultation scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 token | Adapts to the total context volume after splicing multiple real estate registration documents, avoiding exceeding model processing limits |
| Question Optimization Switch | Enabled | Helps organize vague user inquiries and extract core keywords such as real estate location and right holder |
| Single Search Limit | Top 3 results | Matches the volume of core data for this category, avoiding redundant information interfering with reply accuracy |
| `variables` Configuration | Preset real estate location, right type, and right holder name as required variables | Used to gradually collect core missing information from users during multi-turn dialogue |
| Timeout Threshold | 600 seconds | Adapts to the time required for cross-system data retrieval, avoiding dialogue interruptions due to system response delays |

## Three Common Misconfigurations
- Symptom: A connection error appears when calling the model, and the issue persists even after enabling a network proxy. Cause: Network routing rules for model calls are not properly configured, or the FastGPT instance’s outbound permissions are not open to the target model service node.
- Symptom: The knowledge base returns registration documents containing images, but the large model reply does not display image links. Cause: The prompt does not explicitly require embedding image links in a recognizable format in the reply, and no trigger rules for image display are specified.
- Symptom: Core fields such as real estate location and right holder information cannot be accurately extracted during multi-turn dialogue. Cause: No keyword extraction logic for real estate registration core fields is preset in the prompt, and the scope of variable extraction is not limited.

## How to Verify Successful Configuration
- Initiate an inquiry containing real estate location and right holder information. Check whether `chatId` consistently associates context during the dialogue, and confirm no context loss occurs.
- Call test data to verify whether the prompt can correctly extract preset `variables`. Confirm that core fields are accurately identified.
- Simulate a cross-system data retrieval scenario. Check whether the timeout threshold adapts to system response time, and confirm no unexpected interruptions occur.
- Import a registration document containing images. Verify whether the large model reply correctly displays the image links within the document.

The values provided are common starting points and should be evaluated against the reader’s own samples.
