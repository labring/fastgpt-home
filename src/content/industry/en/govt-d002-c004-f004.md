# Service Consultation and Response for Active Public Disclosure and Policy Publication: Workflow Orchestration

## What this category of data looks like
Data for this category comes from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials, with a daily update frequency. Daily documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Fields covered include document number, publishing entity, effective date, public disclosure attribute, secrecy level, and publishing channel. Basic units are characters, items, and days. Field weights vary across different document types.

## What constraints these characteristics impose on the "workflow orchestration" link
Daily updated data sources require workflows to support incremental sync configuration to avoid excessive compute resource consumption from full pulls. Structural differences across multiple document types require workflow nodes to adapt to extraction rules for different fields. For example, policy documents need to extract document numbers and effective dates, while approval forms need to validate public disclosure attribute fields. Synchronization needs across multiple publishing channels require workflows to support parallel node configuration covering website columns and new media accounts. Pre-requirements for secrecy and public attribute validation require mandatory validation nodes in the workflow, to ensure documents that do not meet requirements cannot enter the publishing stage.

## Configuration specifications
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk length | 800–1200 characters | Matches the typical paragraph length of policy documents and interpretation drafts, balancing recall accuracy and context usage |
| Similarity threshold | 0.75–0.85 | Adapts to semantic matching needs for public disclosure directories and policy documents, filtering low-relevance historical documents |
| Single search limit | Top 10 items | Covers the typical recall range for public information, avoiding excessive redundant data occupying context space |
| Timeout setting | 600 seconds | Complies with typical response time limits for government public disclosure processes, avoiding excessive waiting that impacts publishing efficiency |
| Global variable `variables` | Bind public disclosure directory ID and secrecy level fields | Supports automatic extraction of field values by the workflow for pre-validation and process triggering |
| Workflow node `nodeId` | Trigger subsequent nodes based on approval form status | Matches the approval process logic for government publishing, ensuring only validated documents enter the publishing stage |

## Three common misconfigurations
- Phenomenon: Workflow execution times out, logs show response duration exceeds the 600-second threshold. Cause: Incremental sync nodes are not configured, and full pull of historical documents updated before the current day consumes significant compute resources.
- Phenomenon: Workflow node throws an error, logs mention unconfigured model calls. Cause: Unauthorized model parameters are incorrectly bound, and unused model call logic is not disabled in the configuration.
- Phenomenon: Global variable history records cannot be modified. Cause: History record editing permission is not enabled in the `variables` configuration, or the workflow node is not bound to the editing permission for the corresponding variable.

## How to confirm the configuration is set correctly
- Manually trigger a workflow run, check the node execution logs to confirm only documents updated on the current day are pulled, with no full sync records.
- Submit a test approval form marked with a secrecy level, verify that the workflow automatically blocks subsequent publishing nodes when detecting a secrecy attribute.
- Access the global variable `variables` management page, confirm that history record fields can be edited and changes saved.
- Adjust the similarity threshold, test the relevance of recall results, and confirm they meet preset matching requirements.

The values provided are common starting points and should be measured against the reader's own samples.
