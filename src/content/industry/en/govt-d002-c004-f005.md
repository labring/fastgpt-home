# Proactive Public Disclosure and Policy Publication Inquiry and Response: Tool Calling and Plugins

## What data does this category include?
Data for this category originates from government websites, document management systems, government information disclosure directories, policy document repositories, and press conference materials.
Data updates occur daily.
Daily documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records.
Document fields include public attribute identifiers, confidentiality review status, publishing channel attribution, audience scope, approval workflow node information. Some documents include links to associated image and text materials.

## What constraints do these characteristics impose on tool calling and plugins?
Multi-source, decentralized data sources require tool calling to adapt to authentication and data retrieval logic for different APIs, to avoid cross-system data format incompatibility issues.
Daily update frequency requires configuring scheduled incremental synchronization tasks for tools, to prevent excessive resource usage from full data pulls.
Diverse document types and field differences require plugins to preset parsing rules for different documents such as policy files and approval forms, to ensure accurate field extraction.
A sensitive information verification link must be embedded, to avoid the risk of accidental disclosure of classified or sensitive information.
The proactive publication attribute requires tools to link with website column and new media account synchronization logic, to ensure publication timeliness.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to tool calling needs for multiple document types, automatically matches parsing plugins for policy files, approval forms, etc. |
| Single search limit | Top 5 entries | Matches the volume of daily updated policy documents, avoids redundant data occupying context space |
| Reranking | Enabled | Optimizes retrieval relevance for policy interpretation drafts and public disclosure directories, improves information matching accuracy |
| Maximum context | 8000–12000 token | Adapts to long text processing needs for policy documents and interpretation drafts, calibrated based on actual testing |
| Scheduled trigger interval | 12–24 hours | Matches the update rhythm of daily incremental data, prevents resource overload from full data pulls |
| `functionCall` | Enabled | Forces tool calling output to conform to preset structured formats, ensures accurate extraction of fields such as public attribute and confidentiality status |

## Three common configuration mistakes
- Workflow outputs external search results as array-form objects, which cannot be directly used to generate policy interpretation text. The cause is failure to configure `functionCall` for forced structured output, with no format conversion rules specified for tool calling.
- MCP service calls frequently interrupt or fail to trigger. The cause is failure to set scheduled synchronization trigger logic adapted for daily incremental data updates, leading to resource overload from tool calling.
- Plugin-returned image and text materials display incompletely. The cause is failure to limit context length in configurations, with truncated long text content leading to incomplete loading of material links.

## How to verify correct configuration
- Initiate a policy document parsing test, and confirm whether the structured fields output by tool calling include preset fields such as public attribute and confidentiality status.
- Review tool calling logs, and confirm that the number of results returned per search matches the configured limit.
- Simulate a daily incremental data synchronization task, and confirm whether the plugin can normally pull newly generated public disclosure directory and approval form data.
- Test the MCP service calling workflow, and confirm that input parameters can be correctly bound to the request parameters for tool calling.

All configuration values listed here are common starting points. Adjustments should be made based on specific testing and use cases for each deployment.
