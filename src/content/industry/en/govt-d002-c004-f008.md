# Government Proactive Disclosure and Policy Publication Service Consultation and Response: Document Parsing and Chunking

## What this category of data looks like
Data sources for this category include government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. The update frequency is daily.

Commonly processed documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Document fields include policy numbers, issuing units, effective dates, column names, release links, and more. Some structured documents such as public disclosure directories include fixed entry hierarchies and metadata fields.

## What constraints these characteristics impose on document parsing and chunking
The daily update frequency mandates a lightweight parsing process. This avoids excessive time consumption that impacts multi-platform synchronization efficiency.

Document types include structured public disclosure directories and approval forms, as well as unstructured policy interpretation drafts and press releases. Different chunking and parsing rules must be adapted to these types.

Data sources include locally uploaded files and external links. Both parsing entry points must be compatible.

Some government documents have fixed headers and footers such as document numbers and issuing units. Redundant content must be removed before chunking.

Policy documents mostly use long paragraph structures. Chunking must retain semantic coherence and avoid splitting core policy clauses.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Adapts to the semantic paragraph length of policy documents and interpretation drafts, avoiding splitting core policy clauses |
| `chunkSplitter` | Separate by title + paragraph | Adapts to mixed document types with hierarchical titles and paragraphs, retaining semantic coherence |
| `customPdfParse` | Enabled | Compatible with the format of government official PDF documents, retaining text hierarchy and table structures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Meets the parsing time requirements for large policy documents and batch public disclosure directories |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to the common upload size of batch official document packages and structured directory files |
| `chunkSettingMode` | Manual configuration | Supports setting differentiated chunking rules for different document types such as public disclosure directories and policy documents |

## Three common mistakes
- Phenomenon: After passing in a government portal link, the parsing result only includes the page title and no body content. Cause: No adaptation rules were configured for the exclusive page template of government websites, and the default parsing logic cannot capture the nested body area.
- Phenomenon: Core clauses are split in the chunking results of policy documents, leading to broken contextual logic. Cause: Fixed character separation was incorrectly used as the `chunkSplitter` configuration, and the rule was not switched to separate by title + paragraph, destroying the semantic integrity of policy clauses.
- Phenomenon: Raw HTML tags are displayed in the knowledge base context reference area instead of being rendered into readable format. Cause: The format cleaning process after document parsing was not enabled, and redundant HTML tags that come with government website pages were retained.

## How to confirm the configuration is correct
- Upload a local policy PDF file. Check if the parsed text retains header information such as document numbers and issuing units, to confirm that the `customPdfParse` configuration is effective.
- Pass in a government public disclosure directory link. Check if the parsing result includes structured fields such as directory entries and release dates, to confirm that the link parsing rule adapts to government website templates.
- Adjust `chunkSize` to different values. Compare the chunking results to confirm that the chunk length matches the semantic paragraph length of policy documents.
- Check the `chunk ID` field on the knowledge base details page. Confirm that copying is supported, to confirm that the ID interaction configuration for FastGPT v4.17.0 is enabled.
