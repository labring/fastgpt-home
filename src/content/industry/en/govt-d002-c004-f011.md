# Proactive Public Disclosure and Policy Release: Service Inquiry and Response – Forms and Interactions

## What this category of data looks like
Data for this category originates from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials, with a daily update frequency. Daily documents include policy documents, policy interpretation drafts, disclosure directories, information release approval forms, press releases, and website column update records. Most document structures contain fields such as title, document number, publishing entity, main body, and attachments. Some documents include public attribute tags and approval status fields. Data formats are mainly structured tables and rich text, and some attachments include multi-column disclosure directory content.

## What constraints these characteristics impose on the forms and interactions link
High-frequency daily updated data requires form interactions to support batch import and scheduled synchronization configuration, to avoid errors caused by manual repeated entry. The multi-field document structure requires forms to adapt to verification rules for different fields such as titles, document numbers, and attachments, to prevent information misalignment or omission. Bound fields for public attributes and approval status require pre-audit logic configuration to ensure compliance checks are completed before release. Data from multiple channel sources requires forms to support adaptation settings for cross-system data pulling, to reduce additional costs of format conversion and improve synchronization efficiency.

## How to set the configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `formInput` | Multi-field validation + batch import template | Adapts to the multi-field structure of policy documents and disclosure directories, supports daily batch synchronized updated document data, and is compatible with the interaction logic of FastGPT v4.17.0 |
| `userSelect` | Public attribute + approval status option group | Matches the built-in public attribute and approval status fields of documents, binds pre-audit logic to ensure compliant release |
| Form submission timeout | `300 seconds` | Adapts to the daily batch update document submission rhythm, avoids interrupting batch synchronization tasks due to timeout |
| Batch import field mapping | Bind according to document field order | Matches the fixed field structure of policy documents and disclosure directories, reduces manual adjustment costs |
| Release channel sync trigger | Trigger upon approval completion status | Ensures public information is synchronized to designated channels after approval, conforms to government public disclosure operation requirements |
| User input validation rules | Mandatory required fields for title and document number | Avoids information omission, conforms to the basic format requirements of government public disclosure documents |

## Three common mistakes
- Phenomenon: When calling release channels via API, no form or user selection interaction interface pops up. Cause: The release channel adaptation rules for `formInput` or `userSelect` are not configured in the workflow, resulting in failure to trigger the interaction link during API calls.
- Phenomenon: When importing multi-column disclosure directory content via batch import, fields are misaligned or content is missing. Cause: Batch import mapping rules are not configured according to document field order, and the default automatic matching logic is used directly, resulting in failure to correctly correspond to multi-column structured data.
- Phenomenon: An error occurs when calling embedding models to process government documents. Cause: An embedding model adapted to government public disclosure documents is not selected in the knowledge base configuration, or model parameters that do not meet requirements are configured, triggering abnormal verification.

## How to confirm the configuration is correct
- Upload a single policy document to the form, check whether preset verification prompts are triggered for required fields such as title and document number.
- Configure a batch import template, import multi-column disclosure directory data, and verify whether the imported data fields match the original documents.
- Trigger an API call test, confirm that the form or user selection interaction interface pops up normally and can be submitted correctly.
- Simulate the approval completion process, confirm that the release channel synchronization logic is triggered normally, with no delay or omission.
