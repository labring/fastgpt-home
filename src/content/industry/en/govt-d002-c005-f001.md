# Property Rights, Asset and State-owned Capital Management Service Consultation and Reply: HTTP APIs and External Systems

This document is written based on FastGPT v4.17.0.

## What This Category of Data Looks Like
Data for this category mainly comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, valuation institution reports and financial statements. Daily business documents include property rights registration forms, asset valuation reports, property rights transfer plans, on-site transaction announcements and asset disposal approval forms.
The data update frequency is monthly. Core fields involve asset ownership number, evaluation benchmark value, transaction status and approval node. Units are mostly ten thousand yuan, square meters, pieces and other physical or monetary units. Ownership certificates and financial account books must be linked to complete verification.

## What Constraints Do These Characteristics Impose on the "HTTP APIs and External Systems" Link
Data sources for this category are scattered and involve state-owned asset confidentiality requirements. HTTP APIs must adapt to authentication rules of multiple systems to avoid unauthorized access.
Data update frequency is monthly, so API call frequency must be controlled within a reasonable range and should not be too high.
Daily document structures are complex with multiple nested fields, so APIs must support specifying fields for extraction to reduce invalid transmission.
Core business links rely on cross-system data alignment, so APIs must support batch query or associated retrieval. This ensures multi-dimensional information such as asset ownership and transaction progress can be obtained synchronously during service consultation.
At the same time, state-owned asset data has high accuracy requirements. Content returned by APIs must strictly match fields and units of business documents to avoid data deviations.

## How to Set Configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
|---|---|---|
| `Authorization` Authentication Configuration | Bearer token, valid for 12 hours | Adapts to unified authentication specifications of state-owned assets systems, avoids frequent re-authentication |
| Context `variables` Configuration | Pass asset ownership number, transaction type fields | Matches core retrieval fields of business documents, improves accuracy of service consultation replies |
| `responseData` Extraction Rules | Only return property rights status, approval progress, evaluation value fields | Reduces invalid data transmission, complies with state-owned asset data confidentiality requirements |
| Single Search Result Limit | Top 10 entries | Matches typical result counts for daily service consultations, avoids returning excessive redundant information |
| API Timeout Duration | 600 seconds | Adapts to time requirements for cross-state-owned assets system data alignment, avoids call interruptions |

## Three Common Mistakes
- Calling the `/api/v1/chat/completions` API returns a 401 Unauthorized error. The cause is failure to correctly configure the `Authorization` parameter and failure to use the Bearer token format required by state-owned assets systems.
- API return results have missing or redundant fields that do not match business document fields. The cause is failure to specify required business fields via `responseData`, or failure to include core retrieval information in the passed `variables`.
- Local deployment versions experience API call timeouts, and the issue persists after changing the domain name. The cause is failure to set a reasonable API timeout duration and failure to adapt to data pull time across state-owned assets systems.

## How to Confirm Proper Configuration
- Call the test API, check if the returned `Authorization` authentication header meets the token format requirements of state-owned assets systems.
- View the `responseData` field returned by the API, confirm that it only contains asset and transaction-related information required for business purposes.
- Simulate a service consultation scenario, verify that the content returned by the API matches the fields in property rights registration forms and asset valuation reports.
- Adjust API call frequency, confirm that access restriction rules of state-owned assets systems are not triggered.
