# Service Inquiry and Response for Property Rights, Asset and State-owned Capital Management: Deployment and Upgrade

## What data for this category looks like
Data for this category comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, valuation firm reports and financial statements. Commonly processed documents include property registration forms, asset valuation reports, property rights transfer plans, on-site transaction announcements and asset disposal approval forms. These documents contain fields such as ownership details, valuation parameters, transaction process nodes and approval workflows. Some documents include structured table content. The data update frequency is monthly. Regular synchronization of existing assets and incremental updates must be handled.

## What constraints do these data characteristics impose on deployment and upgrade
These data characteristics impose multiple constraints on the deployment and upgrade process.
Multi-source heterogeneous data sources require compatible connection configurations for different databases during deployment, to avoid cross-system connection failures.
The monthly update frequency requires retaining incremental synchronization logic during upgrades, to avoid business interruptions from full re-import operations.
Documents with structured tables and long text paragraphs require adapting chunking rules for multi-column data during upgrades, to ensure field integrity during retrieval.
The sensitivity of ownership and transaction data requires retaining permission verification configurations during upgrades, to prevent sensitive information leaks.
The high severity of error consequences requires configuring complete failure retry and alert mechanisms during deployment, to ensure data processing stability.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Fill in the MongoDB connection address for connecting to the state-owned assets supervision system, in the format `mongodb://user:pass@host:port/dbname?authSource=admin` | Property ledger data is mostly stored in MongoDB. Ensure connection permissions match the data source to guarantee normal data reading |
| `PG_URL` | Fill in the PostgreSQL connection address for the enterprise asset management system, set the connection pool size to `20–30` | Asset valuation reports and transaction approval forms are mostly stored in structured PostgreSQL databases. This adapts to concurrent connection requirements for monthly incremental synchronization |
| `REDIS_URL` | Fill in the intranet Redis cache address, set the expiration time to `600 seconds` | Cache frequently queried asset ownership information to reduce delays from multi-system connections and improve inquiry response speed |
| `DB_MAX_LINK` | Set to `20–30` | Adapts to the concurrent connection limit for monthly incremental synchronization, avoiding service interruptions caused by exhausted database connections |
| `FILE_TOKEN_KEY` | Configure a unified key with the state-owned assets system | Ensure access security for uploaded documents such as property registration forms and valuation reports, preventing unauthorized access |
| `STORAGE_S3_ENDPOINT` | Fill in the intranet object storage endpoint address | Store documents such as batch-imported asset disposal approval forms and on-site transaction announcements, uniformly managing unstructured data |

## Three common mistakes
- Symptom: After upgrading FastGPT v4.17.0, modify the `MONGODB_URI` configuration and restart the system. A `502 Bad Gateway` error appears, and login to the system fails. Cause: The MongoDB authentication source parameter is not configured correctly, or the connection address does not include the permission account required by the system, leading to database connection verification failure.
- Symptom: After importing a multi-column Excel document of property registration forms, the RAG automatic chunking result is disorganized and cannot be split aligned with the original table rows. Cause: Chunking rules are not adjusted for structured multi-column documents. The default automatic chunking logic does not retain row and column structures, resulting in chunks that do not meet business requirements.
- Symptom: After exporting workflow configurations from an older version, core configuration items are lost when importing to a newer version. Cause: Cross-version workflow field mapping is not compatible with the parameter structure of the newer version, and format conversion is not completed according to official guidelines, leading to import failure.

## How to confirm the configuration is complete
- Run a data source connection test, check the connection status of `MONGODB_URI` and `PG_URL`, confirm that normal permission verification results are returned.
- Upload a single property registration form document to trigger a chunking test, confirm that the chunking result matches the expected document structure.
- Restart the service, access the domain configured in `FE_DOMAIN`, confirm that the login page loads normally with no connection timeout errors.
- Trigger a monthly incremental synchronization task, check the data synchronization logs, confirm there are no prompts for connection failures or data loss.
