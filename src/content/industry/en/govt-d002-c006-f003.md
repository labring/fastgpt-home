# Service Inquiries and Responses for Infectious Disease Information Reporting and Monitoring: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for this category include the China Disease Prevention and Control Information System, hospital HIS and infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily documents include infectious disease reporting cards, epidemic analysis reports, case correction records, clustered outbreak reports, and epidemic investigation reports. Fields cover basic case information, diagnosis results, reporting time limits, correction notes, testing data, and more. Units include dates, case counts, testing indicator values, and more. All content must comply with format requirements for legally mandated infectious disease reporting.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering workflows
Daily cross-system data requires multi-turn dialogue to support real-time association of case information from different data sources. Fixed-format professional documents require prompt engineering to strictly match the field verification rules of legal reports. Time-consuming verification and correction links require multi-turn dialogue to guide users to gradually complete or verify information. Strict consequences of errors require the dialogue workflow to automatically avoid underreporting and delayed reporting risks, ensuring all interactive content complies with disease control reporting specifications.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Question Optimization | Enabled, calibrated based on actual testing | Adapt to professional term simplification in disease control scenarios, enabling the model to accurately understand professional inquiries about official service matters |
| Maximum Context | 8000–12000 characters | Match the combined length of multiple infectious disease reporting cards and epidemic investigation reports, covering historical interaction content for multi-turn dialogue |
| Single Retrieval Count | Top 6 entries | Match the scale of daily updated case data, avoiding redundant information interfering with dialogue logic |
| Timeout Duration | 600 seconds | Adapt to the time required for cross-system data retrieval, preventing mid-dialogue interruptions |
| `variables` | Bind legally mandated infectious disease reporting rule variables | Allow prompt engineering to automatically call preset report field verification logic |
| `messages` | Append historical interaction content by dialogue turn | Support continuous interactive processes for multi-turn verification of case correction information |
| `chatId` | Bind unique identifier of the current session | Ensure historical content of multi-turn dialogue is correctly associated with the current session |

## Three common misconfigurations
- Phenomenon: Dialogue response content is truncated, only partial case correction records are displayed. Cause: Maximum context length is not adjusted, causing the combined length of historical dialogue and current documents to exceed the character limit supported by the model.
- Phenomenon: 500 error is returned when importing an infectious disease reporting card document. Cause: Embedding model loading path is not configured correctly, or the document contains unescaped special characters leading to parsing failure.
- Phenomenon: Multi-turn dialogue cannot associate cross-system case data. Cause: Data source association rules are not bound via `variables`, causing the model to fail to call case information from different systems for verification.

## How to confirm correct configuration
- Initiate a multi-turn inquiry containing past case correction records, check whether the model can continuously call historical dialogue content to complete information verification.
- Import a standard infectious disease reporting card document, confirm that no 500 error occurs and the document content is correctly split and loaded.
- Trigger the question optimization function, input professional disease control terminology for inquiry, check whether the model can simplify complex queries into executable retrieval instructions.
- View dialogue logs in the FastGPT v4.17.0 backend, confirm that the `messages` parameter correctly appends interaction content for each turn with no omissions.
