# Inquiries and Responses for Notifiable Infectious Disease Information Reporting and Monitoring: Tool Calling and Plugins

## What the data for this category looks like
Data for this category originates primarily from the National Center for Disease Control and Prevention Information System, hospital HIS systems, infectious disease reporting systems, and laboratory testing systems. It updates once daily. Daily documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Fields include notifiable infectious disease classification codes, unique case identifiers, diagnosis times, reporting institutions, correction status, laboratory test results, and other relevant fields. All fields must comply with notifiable infectious disease reporting specifications, with no additional custom units.

## Constraints imposed on tool calling and plugins
Data sources for this category are scattered and require cross-system integration. Tool calling plugins must support standardized connections to multiple data sources and unified formatting. The daily high-frequency update requirement means single tool call response times must align with real-time monitoring and consultation needs to avoid delays. Diverse document types and strict field rules require plugins to support parsing logic for different document types, particularly version association logic for case correction records. Mandatory legal reporting specifications require tool call output fields to strictly match official formats, with no unauthorized changes to field definitions or units.

## Three Common Configuration Mistakes
- Symptom: Tool call fails after deploying a local model via OpenAPI, with the prompt "model loading exception". Cause: Model path parameters were not configured correctly, preventing the plugin from loading the locally deployed M3E model.
- Symptom: Results are empty after calling a cross-system data plugin. Cause: Permission verification parameters for multi-system connections were not configured, or the correct data source type was not specified, making it impossible to retrieve data from the CDC information system or hospital HIS systems.
- Symptom: Generated charts are empty after tool calls. Cause: The called document type was not restricted to case report cards or epidemic analysis reports, and the plugin called irrelevant unstructured data that cannot extract valid charting fields.

## How to Verify Successful Configuration
- Initiate a consultation involving case correction records, confirm that the tool call correctly retrieves historical correction data and parses fields that comply with specifications.
- Check the tool call logs to confirm that single response times fall within the preset 30–60 second range, with no timeout or parameter error prompts.
- Test the cross-system data retrieval plugin, verify that data can be simultaneously retrieved from the CDC information system and hospital HIS systems and formatted uniformly.
- Initiate a consultation related to notifiable infectious disease classifications, confirm that the fields returned by the tool call comply with mandatory legal reporting requirements.
