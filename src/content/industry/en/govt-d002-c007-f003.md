# Petition Matter Handling: Service Consultation and Response — Multi-turn Dialogue and Prompting

## What This Category of Data Looks Like
Data for this category primarily originates from the national petition information system, local petition systems, the 12345 citizen hotline, grassroots governance platforms, and historical petition archives, with daily updates. Daily documents include petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-examination applications, and resolution plans. Fields cover requester subjects, matter content, acceptance numbers, handling progress, review results, and more. The length of individual documents varies widely, and some historical archives have inconsistent formatting.

## What Constraints Do These Characteristics Impose on the "Multi-turn Dialogue and Prompting" Link
Scattered data sources and varied formats require multi-turn dialogue to support recognition of structured and unstructured petition data from different sources. The daily update feature means dialogue context must load the latest petition business data in a timely manner. Document types cover the entire petition handling workflow, so prompts must clearly distinguish between legal handling steps including acceptance scope screening, responsible unit coordination, policy explanation, and review and re-examination. Fields include sensitive requests and handling progress information, so multi-turn dialogue must strictly limit context length to prevent information overload that reduces processing accuracy.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context Length | First 10 rounds of dialogue + associated knowledge base content | Petition matter handling requires retaining complete records of requests and handling processes, while limiting context length to avoid timeouts |
| Single Search Limit | Top 6 matching results | Excessive matching results increase context burden, aligning with the need for precise matching of handling basis for petition matters |
| Variable Binding | Bind petition matter number and handling progress fields | Associate business fields via the `variables` parameter, allowing prompts to accurately call corresponding handling documents |
| Dialogue History Truncation | Retain the most recent 5000 characters via the `messages` parameter | Avoid overly long historical dialogue causing input limit exceeded, and adapt to the multi-turn communication characteristics of petition matters |
| Question Optimization Trigger | Execute automatically based on user input | Automatically optimize the expression of petition requests to improve the accuracy of acceptance scope screening |
| Default Question Preset | Preset standard opening for petition matter consultation | Enables quick initiation of service consultations, adapting to usage habits in government service scenarios |

*This page's configurations are based on FastGPT v4.17.0*

## Three Common Misconfigurations
- Symptom: A character limit exceeded prompt appears during dialogue input, making it impossible to submit petition requests. Cause: No reasonable context truncation rule is configured, causing historical content carried by the `messages` parameter to exceed system limits.
- Symptom: After associating multiple knowledge bases, dialogue returns empty or irrelevant results. Cause: No single search limit is set, leading to context overflow due to excessive matching results, making it impossible to load all content normally.
- Symptom: Dialogue works normally in preview, but an error occurs after official deployment. Cause: Business fields corresponding to the `variables` parameter are not bound, and preset variables such as petition matter numbers are missing in the official environment, causing prompts to fail to call corresponding data.

## How to Verify Successful Configuration
- Upload a petition registration form document, and test whether the dialogue can correctly identify whether it falls within the scope of petition acceptance.
- Initiate a multi-turn dialogue, check whether the `chatId` parameter is automatically generated with the dialogue, to ensure that the context is coherent and retains historical interaction content.
- Adjust the dialogue history truncation threshold, verify whether reasonable content truncation is triggered when the input exceeds the limit, to avoid input limit exceeded errors.
- Bind preset business variables, test whether the dialogue can automatically call associated handling opinions or review and re-examination application content.
