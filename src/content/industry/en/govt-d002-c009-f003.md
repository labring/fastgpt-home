# Public Data Catalog and Open Services: Service Inquiry and Response, Multi-turn Dialogue and Prompt Engineering

## Characteristics of This Category of Data
Data for this category primarily comes from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is once per month. Daily supporting documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Data fields include data item name, open scope, desensitization rules, interface address, update cycle, authorization conditions, and more. Units are mostly structured identifiers such as items, times, and GB. Some entries are linked to unstructured interface call description documents.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
The monthly update feature of this category requires multi-turn dialogue systems to synchronize the latest catalog data regularly. This avoids returning expired open lists or interface information.
Multiple data sources require dialogue systems to gradually guide users to clarify the department owning the data and the open scope during multi-turn interactions. This matches corresponding authorization rules.
Structured fields and interface documents require prompt engineering to support precise retrieval based on fields such as data item name and update cycle. For dynamic content such as interface addresses, real-time verification logic must be configured.
Desensitization rules require prompt engineering to explicitly filter sensitive data details. This prevents unauthorized disclosure of information.

## Configuration Guidelines
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Aligns with the structured paragraph length of public data catalog documents, to avoid splitting that breaks associated information such as data items and desensitization rules |
| Single Retrieval Limit | Top 5 entries | Matches the typical entry volume of public data catalogs, to reduce interference from irrelevant results on service inquiries |
| Context Window Size | 4000–6000 tokens | Carries interaction information such as department, data type, and authorization conditions during multi-turn dialogue, while adapting to the total length of a single batch of catalog documents |
| Question Optimization Switch | Enabled | Converts vague user service inquiries into precise retrieval keywords, adapting to the field-based retrieval requirements of public data catalogs |
| `messages` Parameter Configuration | Retain the most recent 8 dialogue turns | Aligns with interaction habits of government service inquiries, to avoid overly long contexts that cause the model to mix up retrieval scopes |
| Timeout Setting | 60 seconds | Adapts to the response rhythm of public data catalog retrieval, to avoid overly long user wait times that harm service experience |

## Three Common Misconfigurations
- Symptom: A 503 error is prompted when uploading public data catalog documents on the dialogue page, but background logs show the file upload was successful. Cause: No chunked upload rule is configured for large-volume catalog documents, causing a single request to exceed service thresholds.
- Symptom: After introducing a public data catalog knowledge base, when using a strict question-answering template, searching for image-format interface document addresses prompts that no answer was found. Cause: The strict question-answering template only matches text fields, and no compatible parsing logic for image addresses is configured.
- Symptom: When calling the dialogue interface associated with `chatId`, after sending short-interval questions consecutively, subsequent requests must wait for the previous generation to complete. Cause: No multi-dialogue concurrency limit is configured, causing single-session resource occupation.

## How to Verify Proper Configuration
- Upload a standard public data catalog document. Based on FastGPT v4.17.0's chunk processing logic, check if the dialogue system can accurately recall corresponding content based on fields such as data item and update cycle.
- Simulate multi-turn service inquiry interactions, check if the system can retain context information from the most recent 8 dialogue turns, and does not mix up consultation requirements from different turns.
- Send an inquiry with vague wording, such as "Query open data from XX department", check if the system can automatically optimize it into precise retrieval keywords.
- Test sending short-interval consultation requests consecutively, check if the system can normally handle concurrent sessions, and does not experience unresponsiveness or errors.

The values provided are common starting points and should be measured against the reader's own samples.
