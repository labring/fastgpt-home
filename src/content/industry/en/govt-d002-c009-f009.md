# Public Data Catalog and Opening: Service Consultation and Response - Model Access and Configuration

## What Data in This Category Looks Like
Data in this category mainly comes from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Daily maintained documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Data is updated on a monthly basis. Core fields include data item name, open scope, desensitization rules, interface address, update cycle, and others. All data uses structured format, and must strictly follow open authorization boundaries.

## What Constraints These Characteristics Impose on Model Access and Configuration
The monthly update requirement mandates configuring scheduled tasks to synchronize public data catalogs. It ensures the latest structured data is used when the model is called.
Structured data from multiple sources requires adapting parsing rules for different formats. This avoids field matching errors.
Desensitization rules and open boundaries require configuring content filtering logic for the model. This prevents unauthorized sensitive data from being output.
The existence of interface documents requires that access parameters strictly match the manufacturer’s interface specifications. This avoids call failures.
Integration of data from multiple departments requires configuring multi-data source switching logic. This adapts to the open permissions of different departments.

## How to Set Configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | The public data catalog contains multiple structured documents. Full catalog context must be accommodated to accurately match consultation questions |
| `temperature` | 0.1–0.3 | Ensures the accuracy of responses. It avoids generating content beyond the scope of the provided data |
| `vision` | Disabled | The core of this category is structured data and interface descriptions. There are no multimodal consultation requirements |
| `AIPROXY_API_ENDPOINT` | Fill in the exclusive address provided by the manufacturer | Adapts to the access addresses of different model manufacturers. It ensures normal request routing |
| `AIPROXY_API_TOKEN` | Fill in the exclusive key assigned by the platform | Completes identity verification. It prevents unauthorized access |

## Three Common Configuration Mistakes
- When adding a new model manufacturer, the target option cannot be found. The symptom is that the target option is missing from the manufacturer dropdown list on the channel configuration page. The cause is that the FastGPT built-in manufacturer adaptation list has not been updated, or the access switch for the corresponding manufacturer has not been enabled.
- After accessing Qianwen QWEN2.5-VL-7B-instruct, image analysis fails. The symptom is no parsing result or an error returned after uploading an image. The cause is that the `vision` configuration item is not enabled, or the exclusive parameters for the corresponding multimodal model have not been configured.
- Adding a local Ollama model via AI proxy returns a 404 error. The symptom is a 404 status code in the response. The cause is that `AIPROXY_API_ENDPOINT` is filled incorrectly, or the local Ollama service has not exposed the port correctly.

## How to Confirm the Configuration Is Complete
- Check the connection status indicator on the model channel configuration page. Confirm it displays as normal online.
- Initiate a test consultation, input a structured query related to the public data catalog, and verify that the response content matches the public documents.
- Review system logs to confirm there are no error records for failed model calls.
- If multimodal functionality is enabled, upload the description document for the corresponding data item to verify that the parsing result meets expectations.
