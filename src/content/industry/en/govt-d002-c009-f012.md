# Public Data Catalog and Opening: Service Consultation and Response - Deployment and Upgrade

## What this category of data looks like
This category of data includes documents such as public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documentation, and update frequency instructions. Data sources include local public data opening platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update rhythm is monthly. Data fields include data item name, open authorization scope, desensitization processing method, external interface address, update cycle, etc. These must comply with government data security and compliance requirements, with no additional statistical redundant fields.

## What constraints these characteristics impose on the deployment and upgrade link
The monthly update rhythm requires that the deployment link be configured with incremental synchronization-enabled storage and indexing strategies, to avoid computing resource occupation caused by full re-import. The need to access data from multiple sources requires that the deployment adapt to different types of data source connections, including databases, open interfaces, and file storage. The scenario where both documents and structured data coexist requires that both unstructured document parsing and structured data indexing rules be configured during deployment. The dynamic adjustment requirement for desensitization rules requires that the upgrade link support quick modification of data permission configurations, without rebuilding full indexes. Government data security compliance requirements require that intermediate processing nodes for data desensitization be pre-configured during deployment, to avoid direct circulation of sensitive data.

## How to set the configurations
This document applies to FastGPT v4.17.0. The following configuration items are standard parameters supported by this version.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–20 connections` | Matches the single query concurrency of government data catalogs, to avoid exhausting database connections |
| `FE_DOMAIN` | `https://government-consultation-subdomain.local-government-domain` | Adapts to domain specification for government service scenarios, ensuring normal cross-origin requests between frontend pages and backend services |
| `STORAGE_S3_ENDPOINT` | `intranet file storage node address:9000` | Adapts to intranet access requirements for government data storage, reducing security risks from public network transmission |
| `REDIS_URL` | `redis://:custom-password@intranet-redis-address:6379/0` | Used to cache query results of public data catalogs, reducing resource consumption from repeated requests |
| `FILE_TOKEN_KEY` | `32-bit randomly generated string` | Used to encrypt file access tokens, preventing unauthorized download of sensitive data files |
| `ROOT_KEY` | `64-bit randomly generated administrator key` | Used for highest permission verification of the admin backend, complying with permission control requirements for government systems |

## Three common errors
- Symptom: Frontend pages fail to load preview files of public data catalogs. The console prompts a cross-origin request failure. Cause: `FE_DOMAIN` is configured as a publicly accessible domain, but the deployment environment is a government intranet, and no intranet domain is used.
- Symptom: A database connection timeout error appears after executing `docker-compose up -d`. Cause: The intranet address configured in `MONGODB_URI` or `PG_URL` does not have port access permissions enabled, or the corresponding database service is not running properly.
- Symptom: The WSL2 container prompts a directory creation failure when starting, and cannot mount the local data directory. Cause: The local path configured in `STORAGE_S3_ENDPOINT` was not created in advance, or the WSL2 file system permissions are insufficient to write to the specified directory.

## How to confirm the configuration is complete
- Execute `docker-compose ps`, confirm that all service containers are in running state, with no restart or exit records.
- Access the admin backend corresponding to `FE_DOMAIN`, use `ROOT_KEY` to complete login, and verify that the admin permission configuration takes effect.
- Upload a sample file of the public data catalog, confirm that the parsed data can be properly stored in the specified storage path, matching the configuration of `STORAGE_S3_ENDPOINT`.
- Initiate a public data item query request, confirm that the number of returned results does not exceed the configuration value of `DB_MAX_LINK`.

The values provided are common starting points and should be measured against the reader's own samples.
