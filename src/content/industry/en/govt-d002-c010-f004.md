# Workflow Orchestration for Inquiry and Response in Highway Maintenance and Road Property Rights Management

## What this category of data looks like
Business data for highway maintenance and road property rights management typically comes from highway maintenance management systems, bridge and tunnel monitoring systems, road patrol inspection systems, and traffic flow monitoring data. The update frequency is daily. Daily documents include maintenance plans, patrol logs, defect disposal orders, road construction permits, and road property damage compensation forms. Fields covered include section number, defect type, location coordinates, construction scope, applicant information, and some documents include on-site photo attachments.

## What constraints these characteristics impose on workflow orchestration
Multi-source data access requires workflows to adapt to output formats of different systems. Use `variables` configuration to unify field mapping rules. Daily updated data needs scheduled workflow nodes to ensure documents used for inquiries are up to date. Large differences in fields across documents require separate extraction rules for maintenance and road administration businesses, to avoid mixing different types of business data. Photo attachments in documents must match internal access domain formats, to prevent external links from failing in internal systems. Workflows must include validation steps to ensure extracted fields meet business requirements and reduce subsequent error risks.

## How to set configurations
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Question Classification Node | Configure classification rules for maintenance and road administration businesses | Daily documents are divided into two main categories: maintenance and road administration, matching core scenarios of business inquiries |
| `variables` | Extract section number, location coordinates, applicant information | Daily documents include these fields for accurate matching of specific business inquiries from users |
| Single Search Limit | Top 5 entries | Number of daily generated documents is manageable; too many results will increase response delay |
| Maximum Context | 800–1200 characters | Road-related matters and maintenance issues in user inquiries usually focus on specific scopes; overly long context will interfere with matching |
| Workflow Timeout Threshold | 600 seconds | Processing flow for a single business document usually takes no more than 10 minutes |
| `nodeId` | Bind to the ID of the daily data synchronization node | Business documents need daily updates; associate the corresponding node to enable automatic synchronization |

## Three common mistakes
- Enabling the image upload function returns links in IP plus port format, which cannot be accessed normally in internal systems. Cause: No workflow node for image upload domain replacement is configured, and the default uses the IP port address of the deployment environment.
- Matching results of the question classification node do not match business scenarios, for example, classifying pavement defects as road construction matters. Cause: Classification rules are not configured for maintenance and road administration businesses, and general classification logic is used directly.
- Workflow runtime errors include `$schema` field exception prompts. Cause: The field structure of `variables` is not configured correctly, causing incoming parameters to not meet the preset format.

## How to confirm configurations are correct
- Trigger a test inquiry request for a road construction permit, check if the returned matching documents include construction scope information for the corresponding section.
- Upload an on-site photo of a pavement defect, check if the returned image link uses the proprietary domain format.
- Run a data synchronization node bound to `nodeId`, check if the section number field extracted in `variables` is complete.
- Trigger a test inquiry for pavement maintenance, verify if the output result of the question classification node matches the maintenance category.

The values provided here are common starting points and should be measured against the reader's own samples.
