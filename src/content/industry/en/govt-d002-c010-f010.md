# Service Inquiry and Response for Highway Maintenance and Road Property and Right Management: Knowledge Base Retrieval and Recall

## What data for this category looks like
This category of data primarily comes from highway maintenance management systems, bridge and tunnel monitoring systems, road administration patrol systems, and traffic flow monitoring data. The update frequency is daily. Daily documents include maintenance plans, patrol logs, disease disposal forms, road construction permits, and road property damage compensation forms. A single document typically includes fields such as patrol date, point coordinates, disease type, disposal process, and approval information. Some documents include on-site photos or monitoring data attachments.

## Constraints imposed by these characteristics on knowledge base retrieval and recall
Multi-source data updated daily requires the retrieval link to support incremental synchronization and incremental recall, to avoid excessive resource usage from full retrieval.
Diverse document types include structured forms and unstructured logs. Support content parsing and field extraction for different formats.
Exclusive fields such as point coordinates and disease type require the retrieval logic to support precise matching of business-specific attributes.
Documents related to road construction and road property damage have strong timeliness. Prioritize recall of recently updated content to ensure the accuracy of inquiry responses.

## Configuration settings
This page is based on FastGPT v4.17.0 configuration guidelines.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches professional terminology and point information related to highway maintenance, and avoids recalling irrelevant general traffic content |
| `limit` | Top 6 entries | Single-round retrieval results must cover multiple document types such as patrol logs, disposal forms, and permits, while controlling context length |
| `searchMode` | hybrid | Combines keyword matching and semantic retrieval to adapt to mixed structured and unstructured content such as point coordinates and disease types |
| `usingReRank` | Enabled | Reorders initial recall results by business relevance, prioritizing frequently consulted content related to road construction and disease disposal |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands professional expressions for inquiry questions, such as matching "road surface potholes" to documents related to "road surface diseases" |
| `collectionIds` | Configured in three groups: maintenance, road administration, and monitoring | Distinguishes knowledge base collections for different business lines, preventing cross-category content from interfering with retrieval results |

## Three common misconfigurations
- Phenomenon: Calling knowledge base-related interfaces returns an error message stating "document format not supported". Browsers can normally download remote docx format attachments. Cause: Parsing adaptation for remote documents is not configured, or the knowledge base does not have access permissions for docx files.
- Phenomenon: Retrieval results only include document content from first-level directories, and documents in multi-level directories are not recalled. Cause: Directory recursive scanning configuration is not enabled, and only document metadata for the top-level directory has been synchronized.
- Phenomenon: When an end user selects to skip knowledge base retrieval, the returned results still include retrieved content. Cause: The retrieval logic is not bound to the input selection variable, and the retrieval switch status is not adjusted based on the variable value.

## How to confirm successful configuration
- Upload a single maintenance patrol log document, perform relevant inquiry retrieval, and check whether the returned results include the core business information in the document.
- Modify the `similarity` parameter value, observe changes in the recall range of retrieval results, and confirm that the configuration has taken effect.
- Test documents in multi-level directories, confirm that content from all levels is included in the retrieval scope.
- Trigger an inquiry that includes remote attachments, confirm that the interface can normally parse attachment content and return relevant results.

The values provided are common starting points and should be measured against the reader's own samples.
