# Handling Consultation and Response for Pension, Work Injury, and Unemployment Benefit Verification: HTTP Interfaces and External Systems
Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category of Data Looks Like
The data sources for this category are social insurance handling systems, personal benefit records, labor relations and work injury recognition systems, and the electronic social security card platform. The update frequency is daily.
Daily associated business documents include benefit application forms, payment period proof, retirement approval forms, work injury recognition materials, and unemployment benefit application materials.
Data fields cover insured person identity identifiers, cumulative payment duration, benefit calculation base, verified payment amount, and audit node status. Units include yuan, month, and others.

## What Constraints Do These Characteristics Impose on the HTTP Interfaces and External Systems Link
Daily updated data sources require interfaces to support high-frequency synchronization and incremental queries. This avoids performance loss and data lag caused by full-volume pulling.
Data fields from multiple system sources have format differences. Interfaces must implement unified field mapping rules to ensure consistency across cross-system data.
Standardized business document requirements mean interfaces must support passing document identifier parameters. This associates the corresponding insured person’s business materials.
Amount fields for benefit verification require strict numerical format validation. This prevents subsequent benefit calculation errors caused by non-compliant values.

## How to Configure
| Config Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${external_system_token}` | Follow the identity authentication specifications of the external social insurance handling system to ensure the legality of interface calls |
| `variables` | `{"target_kb": "${api_passed_var}"}` | Support passing variables during API calls to dynamically select the corresponding insured person’s business knowledge base |
| `responseData` | `First 8 verification results and associated documents` | Control the returned data scale, adapt to interface response time requirements and avoid timeouts |
| Timeout setting | 600 seconds | Adapt to the time required for multi-system data query and benefit calculation, ensure complete data return |
| Field mapping rules | Match by insured person identity identifier | Accurately associate historical payment, work injury recognition and other business data of the corresponding insured person |

## Three Common Misconfigurations
- When calling the API to pass variables for knowledge base selection, fail to correctly configure the `variables` parameter, causing the workflow to fail to load the corresponding business knowledge base and return the error "No matching knowledge base found".
- The verification amount field returned by the interface is empty. This occurs because the `responseData` parameter is not correctly mapped to the benefit data fields returned by the external system, so valid business data is not extracted.
- The interface triggers a 504 timeout status code. This happens because the set timeout period is too short to complete multi-system data query and integration operations.

## How to Confirm Proper Configuration
- Call the test interface to check whether the `Authorization` parameter is included in the request header, to confirm that the identity authentication configuration is valid.
- Pass the preset `variables` parameter to verify whether the workflow can dynamically match the corresponding business knowledge base.
- View the fields returned by `responseData` to confirm that core business fields such as insured person identity identifier and verified amount are included.
- Simulate a single business request to verify whether the format and fields of the interface returned data meet business requirements.
