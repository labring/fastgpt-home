# Service Consultation and Response for Pension, Work Injury, and Unemployment Benefit Verification: Multi-turn Dialogue and Prompts

## What the Data for This Category Looks Like
Data for this category originates from social insurance management systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. Updates occur daily. Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment benefit applications. The overall structure primarily uses form-based submission content and certificate-based verification materials. Fields cover payment duration, benefit calculation parameters, and qualification verification conditions. Document length changes based on application type, with no fixed unified standard.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Configuration
Data sources span multiple systems and are updated daily. Multi-turn dialogue must associate context by data source category to avoid mixing cross-system data. Daily document types are diverse. Multi-turn dialogue must guide users to upload matching materials separately for pension, work injury, and unemployment benefit types. This prevents material mismatching. Fields cover payment duration, benefit calculation parameters, and similar items. Prompts must explicitly require step-by-step extraction of corresponding verification fields. This adapts to the most time-consuming calculation and verification links. Prompts must also remind users of the latest data verification logic. This ensures the dialogue uses the daily updated data source.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 8000–12000 characters | Covers the full content of multiple benefit application materials, avoiding truncation and loss of key information such as payment duration and qualification verification |
| Question Optimization | Enabled | Converts vague user inquiries into clear benefit type verification requests, adapting to the step-by-step guidance logic of multi-turn dialogue |
| `variables` | Bound to the exclusive variable pool for social insurance management systems | Distinguishes calculation parameters for pension, work injury, and unemployment benefits, avoiding global variable conflicts |
| Single Search Limit | Top 3 results | Core data is concentrated in recent payment records and identification materials; excessive results will interfere with key information extraction |
| `messages` | Retain the last 10 rounds of dialogue context | Associates previously submitted material numbers and identity information from users, avoiding repeated inquiries about the same content |
| Reordering | Calibrated via actual testing | Prioritizes matching key information such as payment duration and benefit standards, adapting to core business verification needs |

## Three Common Misconfigurations
- Phenomenon: Only two options appear for prompt configuration or global variables in the FastGPT v4.17.0 interface. Cause: Failed to correctly switch to the editing mode of the corresponding application, or failed to enable the advanced configuration switch.
- Phenomenon: The error "Cannot read properties of null (reading 'q')" is triggered during dialogue. Cause: Failed to correctly bind the `chatId` parameter, or there is an empty dialogue message field in the context queue.
- Phenomenon: Unable to upload front and back sides of identity cards separately during dialogue. Cause: Failed to configure a classified entry for multi-file upload, and failed to set independent upload trigger rules by material type.

## How to Verify Successful Configuration
- Enter the application's configuration page, check whether the `variables` parameter is bound to the exclusive variable pool of the corresponding social insurance system, and confirm that the number of variables meets business requirements.
- Initiate a simulated inquiry, enter relevant questions about pension benefit verification, check whether the dialogue context retains the last 10 rounds of interaction content, and confirm that the `messages` parameter configuration is effective.
- Upload multiple types of benefit application materials, check whether the system identifies them by material type, and confirm that the question optimization and reordering configurations adapt to business verification logic.
- Test calls with keys of different permissions, confirm that the call scope of global variables and application-specific variables meets configuration requirements, and avoid permission exceptions.
