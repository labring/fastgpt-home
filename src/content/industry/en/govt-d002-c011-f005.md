# Service Consultation and Response for Pension, Work Injury, and Unemployment Benefit Verification: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from social insurance management systems, personal benefit record systems, labor relations and work injury identification systems, and electronic social security card platforms. The update frequency is daily. Daily business documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment insurance benefit application materials. Data fields include insurance participation subject identification, payment duration, benefit calculation parameters, qualification review identification, and more. Different business types have dedicated fields: work injury benefits are linked to work injury identification numbers, and unemployment benefits are linked to insurance participation and unemployment status identification.

## What constraints these characteristics impose on tool calling and plugin workflows
Multi-source data access requires tool calling to support interfacing with multiple independent business systems, and requires configuring collaborative calling logic for multiple tools. Daily updated data requires that the context cache duration for tool calling must not exceed one calendar day, to avoid using expired payment or qualification data. Structured business documents require plugins to support extracting field-level structured information, to adapt to standardized follow-up benefit calculation processes. The rigor of benefit calculation requires that tool calling include a parameter verification step, to perform format and legality checks on key input fields, preventing incorrect parameters from triggering the calculation process.

## How to configure this
This configuration is based on the plugin and tool calling features of FastGPT v4.17.0, and includes two core parameters: `toolChoice` and `functionCall`. The specific configuration is as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic matching of tools for the current business scenario, adapting to the calling needs of pension, work injury, and unemployment benefit types |
| Timeout Duration | `600 seconds` | Adapts to the average response time of social insurance business systems, avoiding call interruptions due to system delays |
| `functionCall` | Forced structured output | Ensures that tool return results include structured fields such as payment duration and benefit standards, which can be directly used in benefit calculation workflows |
| Parameter Verification Switch | Enabled | Performs required field and format checks on key input fields such as work injury identification numbers and payment durations, reducing incorrect calls |
| Retry Count | `2–3 times` | Addresses temporary fluctuations in social insurance systems, reducing the probability of single call failure |

## Three Common Mistakes
- Scenario: The work injury identification number field is passed empty during tool calling, and a verification failure prompt is returned. Cause: The parameter verification switch is not enabled, and required field checks are not performed on input fields.
- Scenario: The code running plugin fails to reference third-party libraries during execution, returning a dependency missing error. Cause: Dependency loading configuration is not added in the plugin settings, or dependencies are not pre-deployed to the runtime environment.
- Scenario: No conversation log record is generated after the workflow calls other plugins. Cause: The plugin's log recording switch is not enabled, or parameters for synchronizing logs to the workflow context are not configured.

## How to confirm the configuration is complete
- Send a test request that includes complete payment duration and work injury identification number, check if the tool call returns structured data for the corresponding business scenario.
- Simulate a temporary delay scenario in the social insurance system, verify that the call performs retries according to the configured retry count.
- Trigger a workflow call to the plugin, check if a complete conversation log record is generated, including call parameters and return results.
- Check if the tool return result fields include key information required for benefit calculation, such as payment duration and benefit standards.
