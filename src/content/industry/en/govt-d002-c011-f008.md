# Service Consultation and Response for Pension, Work Injury, and Unemployment Benefit Verification: Document Parsing and Chunking

## What the data for this category looks like
The core goal of this category is to calculate benefit eligibility and standards. Data sources include social insurance management systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. Data updates occur daily.

Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment benefit application materials. These documents combine structured form fields and unstructured proof text, with some stored as scanned documents.

Fields cover payment duration, eligibility identification markers, and parameters related to benefit calculation. No unified fixed format exists, and field arrangement varies across different sources.

## What constraints these characteristics impose on the document parsing and chunking link
Differences in document formats across multiple sources mean parsing workflows must adapt to three types: structured forms, unstructured text, and scanned documents.

Daily updated data requires chunk length to balance retrieval timeliness and business integrity. Avoid overly coarse chunks that let outdated information interfere with retrieval, or overly fine chunks that increase computing overhead.

Associated fields related to benefit calculation must retain contextual connections during chunking. Do not separate the correspondence between payment duration and benefit standards, otherwise subsequent review errors may occur.

Scanned document formats cannot extract text directly, requiring additional OCR processes. This increases the complexity of the parsing link.

When uploading multiple documents in batches, clearly distinguish parsing results from different files to avoid content confusion across files.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category of documents includes associated business units such as payment duration and benefit calculation. Chunk length must cover complete business logic to avoid splitting core calculation information |
| `chunkSplitter` | Mixed semantic paragraph + fixed character boundary | Daily documents have both structured form fields and unstructured explanatory text. Mixed splitting balances field integrity and semantic coherence |
| `customPdfParse` | Enable scanned document OCR mode | Some work injury identification and benefit application materials are in scanned document format. Custom PDF parsing must trigger OCR processes to extract text |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Single work injury identification material may include multiple pages of proof documents. Sufficient parsing time must be reserved to avoid timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Support batch upload of multiple benefit-related documents. Must adapt to single file maximum capacity requirements |
| `chunkSettingMode` | Manual configuration | Adjust chunk parameters for different document types such as forms, proof materials, and scanned documents. Manual mode enables fine-grained control |

## Three Common Mistakes
- After uploading multiple benefit-related documents, parsing results have no file identifier to distinguish them. This causes confusion between different types of materials during retrieval. The root cause is failure to configure metadata that marks chunks by file name or file type, so chunk results cannot be linked to the original document source.
- Fields in parsed scanned work injury identification documents are empty or garbled. The root cause is not enabling the OCR mode of `customPdfParse`. Using basic PDF text extraction alone cannot recognize scanned content.
- Knowledge base search tests fail to hit target benefit calculation content. The root cause is `chunkSize` set outside the reasonable range. This merges cross-business unit content into one chunk, leading to insufficient semantic retrieval matching accuracy.

## How to Confirm Proper Configuration
- In the FastGPT v4.17.0 environment, upload a single scanned work injury identification document. Check if the parsing result includes complete text content recognized by OCR.
- Upload multiple different types of benefit documents. Verify that chunk results have file source identifiers, confirming that parsing results from different files can be distinguished.
- Adjust `chunkSize` to the test range, initiate a retrieval test, and confirm that target business unit content can be normally hit.
- Upload a test file close to `UPLOAD_FILE_MAX_SIZE`, and confirm that the parsing process has no timeout errors.

The values provided here are common starting points. They should be evaluated against the samples used in the target deployment.
