# Service Consultation and Response for Pension, Work Injury, and Unemployment Benefit Verification: Deployment and Upgrade

## What the data for this category looks like
The data for this category comes from social insurance management systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily. Daily associated business documents include benefit application forms, payment period proof, retirement approval forms, work injury identification materials, and unemployment insurance benefit application materials. Core fields include beneficiary identity identifiers, cumulative payment duration, work injury identification grade, and unemployment insurance enrollment period. These fields support the full process of benefit calculation and qualification review.

## Constraints for deployment and upgrade
Accessing multiple system data sources increases configuration complexity. Configure synchronization rules for data from different sources to prevent cross-system data inconsistencies from harming consultation response accuracy. The daily update frequency requires incremental pull mechanisms to avoid excessive system resource usage from full synchronization, and ensure service stability. Diverse business document formats need adapted parsing rules to ensure accurate extraction of core fields for all material types. Additionally, the rigor of benefit calculation requires strengthened data verification during deployment. Intercept missing or abnormal business data to reduce the risk of incorrect or missed benefit payments later.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Point to a privately deployed MongoDB instance, configure the maximum connection pool size to 200 | This category updates multi-source business data daily, requiring stable database connections to support high-frequency query and write operations |
| `REDIS_URL` | Configure as a Redis service on the local 6379 port, set the memory limit to 8000 MB | Used to cache frequently queried benefit calculation rules and user consultation history to reduce response latency from repeated calculations |
| `STORAGE_S3_ENDPOINT` | Connect to the endpoint address of an internal private object storage service | Used to store sensitive business documents such as work injury identification materials and benefit application forms, ensuring data is transferred within a private environment |
| Single search limit | Top 10 entries | A large number of fields are matched for business documents, requiring sufficient associated content to be retrieved to support accurate responses |
| Reranking | Enabled | Optimize the sorting logic of multi-source retrieval results, prioritizing document content directly related to benefit calculation |

## Three common misconfigurations
- Symptom: A `connection refused` error appears after starting the FastGPT container, and the database cannot be connected normally. Cause: `MONGODB_URI` is not correctly configured to point to an available database instance, or the database service is not running normally.
- Symptom: When using multiple knowledge base categories, consultation results frequently fall into the fallback category. Cause: Retrieval is only based on the current question to match documents without using historical consultation context, resulting in an overly broad matching scope.
- Symptom: Parsing fails when uploading work injury identification materials, with some fields returned as empty. Cause: Reasonable chunking rules are not set for business documents, causing key fields to be truncated and unable to be extracted.

## How to confirm successful configuration
- Run a database connection test command to verify that the MongoDB instance configured via `MONGODB_URI` can read and write data normally.
- Upload a standard benefit application form and check whether the parsed fields are fully extracted without missing or abnormal content.
- Submit a consultation related to benefit calculation and check whether the retrieved documents include associated business documents such as payment period proof and work injury identification materials.
- View system operation logs to confirm that there are no connection errors or out-of-memory issues with the cache service configured via `REDIS_URL`.
