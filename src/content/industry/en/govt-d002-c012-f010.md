# Administrative Consultation and Response for Elderly Care Facility Supervision: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Core data for this category comes from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and facility operation ledgers. The update frequency is monthly. Daily documents include elderly care facility registration materials, operation subsidy application documents, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. Most data fields relate to facility names, bed counts, inspection times, rectification statuses, and similar details. There is no unified fixed format. Some paper documents must first be digitized and entered before they can be imported into the knowledge base.

## What constraints these characteristics impose on knowledge base retrieval and recall
The monthly updated data source requires the knowledge base to have periodic synchronization tasks configured. This prevents data lag from impacting regulatory decision-making. Diverse non-standardized document types increase chunking difficulty. Splitting logic that adapts to different document structures is needed to avoid cutting off key regulatory information. Data covers facility registration, safety hazards, and subsidy distribution. The accuracy of retrieval results directly affects regulatory compliance, so strict control of the recall relevance threshold is required. Mixed retrieval of multi-source data also needs clear data source filtering rules. This prevents cross-departmental data confusion that reduces verification accuracy.

## How to set configurations
The following configurations are based on the interface and parameter logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the rigor requirements of elderly care regulatory documents, avoiding low-relevance non-regulatory content interfering with verification work |
| `limit` | Top 6 entries | Balances context length and information coverage, meeting the material reference volume needed for a single regulatory verification |
| `searchMode` | Hybrid retrieval | Combines semantic matching and keyword matching, adapting to retrieval needs for diverse non-standardized documents such as registration materials and rectification ledgers |
| `usingReRank` | Enabled | Performs secondary ranking on initially recalled results, raising the ranking priority of highly relevant regulatory documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Runs expansion optimization on regulatory-related user questions, covering synonymous regulatory terms and improving recall coverage |
| `collectionIds` | Bind the exclusive dataset ID for elderly care facility supervision | Ensures retrieval only covers compliant data for this category, avoiding interference from cross-category data |

## Three common errors
- Phenomenon: A "no knowledge base selected" prompt appears after submitting a question in the chat window. Cause: The corresponding elderly care facility supervision dataset is not bound in the knowledge base configuration for the supervision scenario, or the dataset association relationship was accidentally modified.
- Phenomenon: The system directly refuses to reply when no matching content exists in the knowledge base, without triggering generalized reasoning. Cause: `searchMode` was incorrectly set to knowledge base-only matching mode, the cross-context reasoning switch was not enabled, or the default retrieval logic was adjusted after a recent platform update.
- Phenomenon: Newly created folders cannot properly categorize imported registration materials. Cause: The folder is not associated with the classification directory of the corresponding dataset, or the folder name contains system-disabled characters, causing path parsing failure during import.

## How to confirm the configuration is complete
- Manually upload a copy of elderly care facility registration materials, perform a retrieval test, and verify that recall results include relevant fragments of the materials.
- Adjust the `similarity` threshold to the boundary values of 0.70 and 0.90, observe changes in the number of recall results, and confirm that the threshold takes effect.
- Check the knowledge base synchronization logs to confirm that the monthly data source synchronization task has been configured and the most recent execution was successful.
- Input a question containing synonymous regulatory terms, and verify whether `datasetSearchUsingExtensionQuery` triggers retrieval for the synonymous terms.

The values provided are common starting points and should be measured against the reader's own samples.
