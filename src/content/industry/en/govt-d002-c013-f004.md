# Service Consultation and Response for Internal Control Evaluation, Audit and Rectification: Workflow Orchestration

This configuration is based on FastGPT v4.17.0, and adapted to the business data characteristics of this category.

## What the data for this category looks like
Data for this category comes from daily business systems of central enterprise internal control departments, audit departments, finance departments, subordinate enterprises, and external audit institutions. These systems include enterprise internal control systems, ERP, financial sharing systems, audit management systems, and procurement contract project systems.

Daily generated documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closing certificates. Data update frequency is annual. Core fields cover audit issue category, rectification time limit, supporting material number, and similar items. There is no requirement for high-frequency real-time updates. Data structure adjusts with annual audit cycles.

## Constraints on workflow orchestration from these data characteristics
Since data updates occur annually, workflows do not need high-frequency triggering. Nodes can be arranged according to fixed audit cycles.

Multiple system data sources require workflows to include cross-system docking nodes. This ensures documents from different sources can be routed uniformly.

Diverse daily document structures require workflows to include field mapping nodes. These adapt to field differences across different documents.

The most time-consuming steps—extracting business samples and vouchers, forming audit issues and rectification requirements, tracking rectification supporting materials and closing—need independent long-running nodes in workflows. Configure timeout and retry mechanisms here to prevent process blocking.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` scope | Global storage, not cleared with conversation | Business data updates annually, so global default parameters such as audit cycles and rectification standards need to be retained |
| Node timeout setting | `600 seconds` | Extracting business samples and verifying vouchers takes a long time; this prevents early process termination |
| Knowledge base binding rules | Bind to the corresponding business system knowledge base by `nodeId` | Different audit links correspond to different data sources, so precise association with the corresponding document library is required |
| Variable mapping configuration | Map audit issue list fields to rectification ledger fields | Match the field structure of daily documents to ensure accurate data routing |
| Retry trigger condition | Trigger when node return status code ≥ 500, retry `3 times` | Address abnormal requests that may occur during cross-system docking, and avoid invalid retries |
| Global variable initialization | Initialize with fixed values, such as `rectification completion rate threshold = 95%` | Unify business execution standards, and prevent parameter inconsistencies across single conversations |

## Three Common Misconfigurations
- Symptom: When configuring `variables`, global storage is not enabled, and variables are cleared after the conversation ends. Cause: The variable scope is not set to global, and only applies to a single conversation flow. Fixed parameters such as audit cycles cannot be retained.
- Symptom: An error occurs when binding application variables to a knowledge base node. Cause: The knowledge base of the corresponding business system is not specified by `nodeId`, and the association configuration between variables and the knowledge base is missing. This causes the system to fail to identify the binding target.
- Symptom: After an HTTP request outputs multiple variables, the specified variable cannot be associated with the corresponding knowledge base. Cause: No variable and knowledge base mapping rules are configured, and binding is not done according to the field matching requirements of daily documents. This causes variables to fail to correctly trigger knowledge base calls.

## How to Verify a Complete Configuration
- Trigger an audit voucher extraction node, and check if the global default audit cycle parameter is retained in `variables`.
- Submit a test audit notice, and verify if the knowledge base node has bound the document of the corresponding data source by `nodeId`.
- Simulate a node returning a 500 status code, and confirm if the workflow triggers the retry mechanism.
- Import a rectification ledger template, and check if the variable mapping correctly matches the issue list fields.

The values provided are common starting points, and should be evaluated against the reader's own samples.
