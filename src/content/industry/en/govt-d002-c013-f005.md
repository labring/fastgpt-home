# Service Consultation and Response for Internal Control Evaluation, Audit and Rectification: Tool Calling and Plugins
Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category of Data Looks Like
Data for this category originates from enterprise internal control systems, ERP systems, financial shared services systems, audit management systems, and procurement contract project systems. Core regularly generated documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Data is updated on an annual basis. Individual documents contain fields such as business sample identifiers, issue descriptions, rectification requirements, and supporting material links. Document processing rules must be adapted to actual business scenarios.

## Constraints Imposed on Tool Calling and Plugin Workflows
Since data updates occur annually, high-frequency trigger rules are not required for tool calling, and a timed synchronization mode may be used. Multiple heterogeneous data sources require plugins to support connections to multiple system interfaces, with authentication parameters for each system configured separately. Diverse document types containing both structured and unstructured content require field extraction logic tailored to different documents, to avoid missing key credential fields such as rectification ledgers and closure certificates. Additionally, data covers audit issues and rectification closed-loop processes, so tool call outputs must strictly match the field specifications of business documents to ensure consistency in subsequent audit workflows.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `{"type":"function","function":{"name":"audit_data_extract"}}` | Must specify a function call adapted to internal control audit documents to avoid format errors from generic calls |
| `functionCall` | `strict: true` | Must strictly match the field structure of audit documents to ensure output conforms to rectification ledger format requirements |
| Multi-source system authentication configuration | Configure authentication parameters separately for each connected system | Different systems have distinct authentication protocols and interface addresses, requiring individual parameter setup |
| Call timeout setting | `600 seconds` | Processing audit documents requires extracting business samples and vouchers, which takes significant time; sufficient call time must be reserved |
| Document chunking rule | `800–1200 characters` | This chunking range is suitable for the content length of audit working papers and issue lists, balancing context completeness and processing efficiency |
| Timed sync frequency | `Annual update` | Data for this category is updated annually, so high-frequency synchronization is unnecessary |

## Three Common Misconfigurations
- An MCP service call returns a `400 InternalError.Algo.InvalidParameter` error. This occurs when the passed business sample range parameters do not match the field naming conventions of the internal control system, causing parameter verification failure.
- The strict mode for `functionCall` is not enabled, resulting in disorganized formatting of rectification issues in tool call outputs that cannot be directly imported into the rectification ledger system.
- The timed sync frequency is set to daily updates, which does not match the annual update rhythm of this category of data, leading to invalid calls that consume system resources.

## How to Verify Successful Configuration
- Connect the audit management system plugin, then test the call. Confirm that the returned fields include core content such as audit notice numbers and issue list items to verify that authentication and data extraction configurations are active.
- Trigger the function call specified by `toolChoice`, then check that the output format strictly matches the preset audit data extraction template to verify that the strict mode configuration for `functionCall` is active.
- Manually trigger document chunking processing, then confirm that the chunked content length falls within the `800–1200 characters` range to verify that the document chunking rule configuration is active.
- Review the timed sync task logs to confirm that the sync frequency matches the annual update setting, verifying that the timed sync configuration is active.

The values provided are common starting points and should be measured against the reader's own samples.
