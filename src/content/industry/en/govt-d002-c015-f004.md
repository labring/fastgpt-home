# Medical Insurance Fund Supervision and Audit: Service Consultation and Reply - Workflow Orchestration

## What the data for this category looks like
Data sources for this category include medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. The update frequency is monthly.
Daily processed documents include audit notices, inspection work drafts, suspicion point lists, interview records, handling decision documents, and rectification reports. Data fields cover involved subject information, expense details, suspicion point types, rectification status, and more. Most documents use a mix of structured tables and unstructured formats.
This category focuses primarily on post-event audits and special inspections, with distinct business scenarios from adjacent categories such as settlement review.

## What constraints these characteristics impose on the workflow orchestration link
Monthly updated data has a large scale. Workflows must support incremental synchronization and batch processing to avoid single-load timeouts.
Mixed processing of multiple document types requires workflows to adapt to input formats for structured settlement data and unstructured medical records, interview records.
The audit process must advance through fixed nodes in sequence: from suspicion point screening, document review, to violation determination. Workflows must strictly connect each node, ensuring the previous node is completed before entering the next.
Requirements for fixed fields such as involved subject information and expense details require workflows to bind corresponding data variables, preventing process interruptions caused by field mismatches.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind audit notice number, settlement data batch number, use 5-15 business fields | Match fixed business identifiers in the audit process, prevent process exceptions caused by empty variables |
| Node trigger condition | Set to previous node completed and form input validation passed | Restrict entry to the next link only after form input is complete, align with business process logic |
| File upload node | Allow uploading inspection work drafts, rectification reports, single file maximum size 1000 MB | Adapt to the size range of daily documents for this category, prevent upload failures |
| `nodeId` | Configure in the order of suspicion point screening, document review, violation determination, use consecutive decimal numbers | Ensure workflow nodes execute in the order of audit business, avoid chaotic node jumps |
| Timeout setting | Set to 600 seconds | Adapt to time requirements for monthly batch data processing, prevent business delays caused by process interruptions |
| Form validation rules | Require mandatory fields to be involved subject name, suspicion point type, use non-empty validation | Ensure core business information is complete, prevent missing key data when starting the process |

## Three common mistakes
- Calling workflow APIs related to file upload returns exceptions. The cause is that no file upload binding parameters are configured in `variables`, so the workflow cannot recognize incoming document resources.
- Workflows do not restrict entry to the next link only after form input is complete. The cause is that node trigger conditions are not set to form validation passed, leading to unordered triggering of process nodes.
- Conversation logs are empty after calling the workflow. The cause is that business inputs such as medical insurance settlement data are not bound via `variables`, or data synchronization is incomplete, resulting in no valid input content for the process.

## How to confirm configuration is complete
- Test calling the workflow, upload daily documents such as audit notices, rectification reports. Check if files can be correctly bound by `variables` and passed to subsequent nodes.
- Configure form validation rules, intentionally leave mandatory fields blank, trigger process startup. Check if validation prompts appear, confirm trigger conditions take effect.
- View the workflow node list, confirm the order of `nodeId` matches the business order of suspicion point screening, document review, violation determination.
- Simulate completion of monthly data synchronization, call the workflow. Check if valid business data is generated in conversation logs, confirm data binding is normal.
