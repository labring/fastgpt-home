# Administrative Consultation and Reply for Medical Insurance Fund Supervision and Audit: Forms and Interactions

## What Data for This Category Looks Like
Core data for this category originates from medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. Updates occur once per month. Daily processed documents include audit notices, inspection work papers, audit suspicion lists, interview records, handling decision letters, and rectification reports. Each document uses a unique field structure. For example, the audit suspicion list must include violation types and associated order numbers. Handling decision letters must clearly state violation facts and disposal basis. Data volume changes as audit scope expands. Core processing steps require cross-verification across multiple data sources.

## Constraints Imposed on the Forms and Interactions Link
Multi-source data association requires forms to support cross-system field mapping and bulk import. This eliminates errors from manual data entry. The monthly update schedule means forms must support historical data backtracking queries. This adapts to the periodic nature of special audits. Differentiated field structures across documents require forms with dynamic field configuration capabilities. Entry templates can be switched based on audit scenarios. Post-audit business workflows require step-by-step verification links for suspicion confirmation and evidence review. This reduces error risks.

## How to Configure Settings

| `formInput` | Bind core fields of the audit suspicion list | The audit suspicion list is the most commonly used basic data carrier for this category. It must accurately associate form input content with subsequent audit logic |
| `userSelect` | Preset audit type and violation level options | This matches the standardized classification requirements for daily processed documents such as audit notices and handling decision letters |

| Single import limit | 500 MB | This adapts to the import needs of bulk files such as monthly updated audit suspicion lists and settlement data |
| Maximum context length | 800–1200 characters | The standard length of core documents such as interview records and rectification reports falls within this range. It adapts to the context processing capabilities of large models |
| Timeout threshold | 600 seconds | Retrieving evidence materials such as medical records, prescriptions, and charging records takes a long time. Reserve sufficient time for interface calls |

## Three Common Configuration Errors
- After binding a global variable with `formInput`, the node returns empty input when called. The global variable assignment is not triggered before form submission, or the variable scope does not cover the current audit flow node.
- When calling the AI chat component, the configuration entry for the large model temperature parameter cannot be found. The advanced configuration panel of the component is not enabled, or the binding type for variable references is not selected correctly.
- The Markdown-formatted audit draft generated by the form has no line breaks when copied, and the browser prompts for manual text selection. The automatic line break rendering configuration of the component is not enabled, or the copy trigger logic is not bound to the correct DOM node.

## How to Verify Correct Configuration
- Submit a test form, check whether the fields bound by `formInput` are correctly passed to subsequent audit nodes.
- Select preset options from the `userSelect` component, verify whether the branch logic of the corresponding audit process is triggered.
- Copy the generated audit report draft, confirm that the Markdown format includes correct line breaks.
- View the global variable scope configuration, confirm that it covers all calling nodes in the current process.
