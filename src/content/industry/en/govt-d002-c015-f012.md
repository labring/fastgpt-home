# Medical Insurance Fund Supervision and Audit Service Consultation and Response: Deployment and Upgrade

## What this category of data looks like
Data sources for this category include medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. The update frequency is monthly. Daily processed documents include audit notices, inspection work drafts, suspicious item lists, interview records, handling decision documents, and rectification reports. Data fields cover audit subjects, descriptions of non-compliant matters, associated settlement order numbers, traceability code identifiers, and more. The length of a single document ranges from hundreds to thousands of characters, with a mix of structured data and unstructured documents.

## What constraints these characteristics impose on the deployment and upgrade phase
Monthly batch updates of bulk data require configuring sufficient concurrent connection buffers during deployment to prevent single synchronization timeout interruptions. Multi-source mixed data formats require preconfiguring parsing rules for different data types during deployment, to ensure audit records, settlement data, and other materials can be properly accessed. Fixed-format audit documents require updating field extraction templates during the upgrade phase, to avoid missing key information in subsequent processing. Sensitive data related to non-compliance determination requires adjusting permission control configurations during upgrades, to ensure data access meets compliance requirements.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15` | Matches the database connection concurrency requirements for monthly batch synchronization, avoiding connection pool exhaustion |
| `MONGODB_URI` | `mongodb://username:password@address:27017/fastgpt` | Stores unstructured documents such as audit records and suspicious item lists, as well as structured metadata |
| `REDIS_URL` | `redis://:custom password@local address:6379/0` | Caches frequently accessed fund supervision rule base data to reduce repeated query overhead |
| `STORAGE_S3_ENDPOINT` | `http://local object storage IP:9000` | Stores binary files and scanned documents related to drug and consumable traceability codes |
| `FILE_TOKEN_KEY` | Random 32-bit string generated according to FastGPT v4.17.0 official guidelines | Encrypts download links for sensitive documents involving non-compliance amounts |

## Three common mistakes
- Symptom: An error stating the model was not found displays in the interface when deploying M3E locally as an indexing model. Cause: The correct call address for the local M3E service was not configured during deployment, and the access path for the corresponding model was not bound.
- Symptom: A 504 timeout error occurs during batch synchronization of monthly medical insurance settlement data. Cause: The `DB_MAX_LINK` configuration was not adjusted, and insufficient concurrent connections caused the synchronization task to time out.
- Symptom: The associated settlement order number field is empty after uploading a handling decision document. Cause: The field extraction rules for the corresponding document were not preconfigured, and the document parsing template was not configured during deployment.

## How to confirm the configuration is complete
- Run a single batch synchronization test task, and check that there are no connection pool overflow errors in the database connection logs.
- Upload a standard audit notice document, and confirm that parsed fields are complete and retrievable.
- Access the configured `STORAGE_S3_ENDPOINT` to verify that drug and consumable traceability code files can be uploaded and downloaded normally.
- Call a code execution node to test that local calls to fund supervision rules do not throw abnormal errors.
