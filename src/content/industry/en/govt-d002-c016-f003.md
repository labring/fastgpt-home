# Administrative Consultation and Response for Medical Insurance Expense Settlement Audit: Multi-turn Dialogue and Prompt Words

## What This Category of Data Entails
This category of data originates from the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding database, and cross-regional medical treatment settlement platform. It is updated daily. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. The data includes standardized diagnosis and treatment and consumables coding fields, expense amount fields, and association fields between insured persons and medical institutions. The size of a single data entry varies with the number of settlements in a single transaction. Batch processing requires associating multiple types of documents to complete verification.

## Constraints Imposed on Multi-turn Dialogue and Prompt Words by These Characteristics
The daily data update requirement means prompt words must be configured with rules for regularly synchronizing the latest medical insurance catalog and coding database. This prevents expired codes from being used for verification.
The mixed processing scenario for multiple document types requires multi-turn dialogue to first guide users to clarify the current document type. This avoids associating incorrect field information.
The presence of standardized coding fields requires multi-turn dialogue to first verify the matching between coding format and the corresponding catalog before proceeding with the audit process.
The need to process batch settlement data requires the dialogue link to support passing data in batches and associating corresponding verification rules. This prevents exceptions caused by overloading data passed in a single request.

## Configuration Settings
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Question Optimization | Enabled, adapted for medical insurance settlement audit scenarios | Multi-turn dialogue needs to gradually clarify document types and audit requirements; optimized settings simplify the interaction process |
| `variables` | Preset medical insurance catalog version and settlement type variables | Bind the latest daily updated data version to ensure audit logic aligns with current rules |
| Maximum Context Length | 8000–12000 characters | Accommodate audit requests from multi-turn interactions and key fields of multiple documents, avoiding truncation of valid information |
| `messages` | Retain the last 10 rounds of dialogue content | Focus on the current audit link, preventing overly long contexts from interfering with audit judgments |
| Single Document Upload Limit | 5 documents per request | Prevent overload from batch data uploads, ensuring stable dialogue response |
| `chatId` | Bind the unique identifier of a single audit session | Distinguish contexts of different audit tasks, avoiding confusion of session data |

## Three Common Misconfigurations
- Symptom: After calling the API to initiate a dialogue, the generated response does not associate the specified medical insurance document. Cause: The association identifier or storage path of the corresponding settlement document is not bound in `variables`, causing the dialogue component to fail to access correct knowledge base data.
- Symptom: Uncaught exception prompts appear when using the AI dialogue component. Cause: In a private deployment environment, the storage service or dialogue session parameters are not correctly configured in the configuration file, preventing the session context from loading normally.
- Symptom: Uploaded medical insurance settlement list files cannot be correctly identified during multi-turn dialogue. Cause: Scenario-adapted question optimization configuration is not enabled, causing the dialogue to fail to guide users to clarify document types and confuse field information across different documents.

## How to Confirm Successful Configuration
- Check whether the current medical insurance catalog version and settlement type variables are preset in `variables`, and confirm that the variable values match the latest synchronized data.
- Initiate a simulated multi-turn dialogue, upload different types of medical insurance documents in sequence, and confirm that the dialogue can gradually guide users to clarify document types and audit requirements.
- Test the configured single upload limit of documents, and confirm that there are no response interruptions or abnormal errors in the dialogue.
- View the session log, and confirm that the session context bound by `chatId` is not confused with other audit tasks.
