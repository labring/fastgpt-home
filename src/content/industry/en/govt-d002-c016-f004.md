# Medical Insurance Expense Settlement Audit Service Consultation and Reply: Workflow Orchestration

## What the data for this category looks like
Data sources include the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical treatment settlement platform. The update frequency is daily.
Documents processed daily include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Fields cover settlement order numbers, insured person identity identifiers, diagnosis and treatment project codes, consumable codes, expense amounts, rejection reasons, and more. Coding fields are 16-digit numeric strings. The unit for expense amounts is yuan. Single settlement document size is usually no more than 10 MB.
This configuration guide is based on FastGPT v4.17.0.

## What constraints these characteristics impose on the workflow orchestration link
Daily updated data requires the workflow to include a scheduled synchronization node. This ensures daily updated medical insurance catalogs and settlement data remain consistent.
Differences in multi-type document structures require the workflow to use dedicated parsing rules for each document type. This avoids field extraction errors.
Processing requirements for single or bulk settlement documents require the workflow to support branch judgment logic. This adapts to parallel or serial processing of single and bulk documents.
Time-consuming steps such as code matching and consistency review require the workflow to call external medical insurance catalog interfaces. It must also configure timeout and retry mechanisms to prevent process blocking.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Preset medical insurance catalog interface address, settlement document parsing template, interface secret key | Uniformly manage public data source configurations to avoid repeated parameter entry for each node |
| `nodeId` | Bind nodes in business process order: Receive Document → Parse Document → Code Matching → Expense Review → Result Feedback | Match the serial business logic of medical insurance expense settlement audit to ensure the process executes in sequence |
| Bulk processing limit | Top 100 entries | Adapt to the number of conventional settlement documents uploaded in a single time to avoid overloading a single node |
| Timeout threshold | 600 seconds | Cover normal delay duration of cross-regional medical insurance interface calls to reduce false triggering of abnormal processes |
| Result rendering format | Adapt to the receiver's Markdown simplified mode | Ensure message display across different channels complies with specifications and avoid format confusion |
| Exception trigger rule | Trigger based on interface return error code | Accurately capture exceptions in code matching, interface calling and other links to trigger subsequent appeal and reconciliation processes |

## Three common errors
- Phenomenon: `variables` is not correctly bound in the workflow, and the code matching node returns empty results. Cause: The interface secret key and basic address were not entered in advance on the global variable configuration page, and the preset `variables` parameter was not referenced when the node was called.
- Phenomenon: Only the first document is processed after uploading multiple settlement documents in bulk. Cause: The bulk branch node was not configured, and the parsing node for each document was not bound in sequence according to `nodeId`, causing the process to execute only once.
- Phenomenon: The review result received on the WeChat end contains redundant Markdown syntax tags. Cause: The WeChat end format adaptation rule for the result node was not configured, and the original Markdown content was output directly without hiding non-essential format tags.

## How to confirm the configuration is complete
- Trigger a test single settlement document upload request, check whether the `variables` parameter is automatically included in the interface call link.
- Upload 5 test settlement documents in bulk, confirm that each document enters the corresponding parsing and review node without omission.
- Simulate a medical insurance interface call timeout scenario, confirm that the exception handling node is triggered and the corresponding error log is generated.
- Generate the review result and send it through the test channel, confirm that the format complies with the receiver's display requirements and has no redundant tags.
