# Enquiry and Reply for Social Insurance Participation Registration and Premium Verification: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Data for this category comes from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared data from public security and civil affairs departments. The update frequency is daily. Daily documents include social insurance participation registration forms, premium base declaration forms, personnel adjustment forms, social insurance premium verification forms, and personal benefit records. Fields include personnel identity identifiers, participating unit information, premium bases, personnel adjustment statuses, verified premium amounts, and more. Units include yuan, person-times, and unified social credit codes of units, and more.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt words link?
Multi-source data sources require multi-turn dialogue to gradually guide users to supplement associated information from different systems, to avoid verification errors caused by missing single-source data. The daily update frequency requires clearly prompting data timeliness in dialogue, to prevent users from using expired information to handle business. Multiple types of structured documents require prompts to specify specific document types to read, to avoid retrieving irrelevant treatment verification content. Field complexity requires multi-turn dialogue to confirm each required field in order, to reduce information confusion.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Question Optimization | Enabled, use trigger threshold calibrated through actual testing | Questions in social insurance registration scenarios often contain ambiguous expressions; optimization is required to accurately match knowledge base documents |
| Maximum Context | Previous 10 turns of dialogue context | Social insurance data mostly consists of structured fields; excessive historical context will interfere with current premium verification information checks |
| Single Search Limit | Top 6 retrieval results | Avoid excessive redundant data confusing the verification logic of personnel identity and premium base |
| Reranking | Enabled, sort by field matching degree | Prioritize retrieving document content directly related to participation identity and premium verification |
| Variable Substitution | Enabled, bind `variables` parameter | Automatically fill structured fields such as unit numbers and personnel ID numbers provided by users |
| Conversation ID Binding | Only bind current session `chatId` | Avoid cross-session data confusion, ensure session security |
| Conversation History Truncation | Truncate at 3000 tokens | Prevent excessive context from causing model inference timeouts or page loading exceptions |

## Three Common Mistakes
- Dialogue components throw an "uncaught exception" error, shown as a red error popup when called. The cause is incorrect configuration of multi-source system data source association, leading to missing calling parameters.
- Generated replies do not reference knowledge base documents, shown as social insurance registration guidance not including the personnel adjustment process from local documents. The cause is incorrect passing of the `messages` parameter to bind knowledge base retrieval results.
- Dialogue pages crash, shown as an unresponsive interface or "page crash" error after loading. The cause is not limiting the context length associated with `chatId`, leading to excessive memory usage.

## How to Confirm Proper Configuration
- Initiate a test dialogue, input an ambiguous question such as "How to handle social insurance registration for new employees", check if the reply includes requirements for filling out the personnel adjustment form from local documents.
- View background logs, confirm that the `variables` parameter has correctly passed the unit information fields provided by the user.
- Simulate 5 consecutive dialogue turns, check for uncaught exceptions or page crashes.
- Input a social insurance premium verification number from the tax system, verify that it can associate and retrieve social insurance management system participation records.
