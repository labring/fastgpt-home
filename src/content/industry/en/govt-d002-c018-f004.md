# Workflow Orchestration for Consultation and Reply on Social Insurance Participation Registration and Premium Payment Verification

## What the data for this category looks like
Data for this category comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and public security and civil affairs data sharing. The update frequency is daily.
Daily processed documents include social insurance registration forms, premium base declaration forms, staff adjustment (addition and reduction) forms, social insurance premium verification notices, and personal social insurance benefit records.
Data fields include unit subject identifiers, personnel identity information, premium bases, verified premium payment amounts, and other fields. Each document corresponds to a single batch or single unit's social insurance participation and payment-related business. The data structure adjusts dynamically based on business processing nodes.

## What constraints do these characteristics impose on the workflow orchestration link?
Daily updated data sources require workflow trigger frequency to match the synchronization rhythm, to avoid mixing data across cycles.
Multi-source heterogeneous data requires configuring cross-system data pull nodes in the workflow to ensure consistency of identity, premium, and other information.
Diverse document types require setting document format verification nodes in the workflow to identify required fields for different forms such as social insurance registration forms and staff adjustment forms.
Data is linked to labor relations and identity information, requiring configuring identity verification and labor relation matching steps in the workflow to reduce subsequent error risks.
Additionally, premium payment verification results need to be reconciled with tax collection data, requiring adding a reconciliation verification node at the end of the workflow to ensure data matching.

## Configuration Specifications
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Global variable configuration | Bind `variables` to the system identifier of daily updated data | Match the daily data update synchronization rhythm to avoid using expired data |
| Node sequence orchestration | Configure identity verification, premium payment verification, and reconciliation verification nodes in order by `nodeId` | Follow the sequential logic of business processing to ensure correct data flow order |
| Document format verification | Preset required field rules for forms such as social insurance registration forms and staff adjustment forms | Adapt to daily processed multi-type business documents and filter submission content with format errors |
| Error retry strategy | Retry 2 times per call, with a 60-second interval | Respond to temporary network fluctuations during cross-system data pulling and reduce call failure rates |
| Knowledge base association settings | Bind the global knowledge base ID to `variables` | Support workflow calls to knowledge base content to assist in consultation and reply services |

## Three Common Misconfigurations
- Phenomenon: An error indicating empty fields is returned when uploading a social insurance registration form via the workflow. Cause: No document format verification node was configured in the workflow, and uploaded content with non-preset fields was not filtered.
- Phenomenon: A prompt that the specified resource cannot be referenced appears after passing content to the knowledge base. Cause: The knowledge base ID was not correctly bound to the `variables` global variable, so the workflow cannot obtain knowledge base access permissions.
- Phenomenon: Workflow execution times out, with status code 504 returned. Cause: No reasonable retry strategy was set, and multi-source data pulling across systems was not split into parallel nodes, causing execution duration to exceed the threshold.

## How to Confirm Proper Configuration
- Manually trigger the workflow, upload a standard social insurance registration form, and check if nodes execute in the preset order.
- View workflow logs to confirm that the `variables` global variable has successfully bound the data source identifier and knowledge base ID.
- Simulate cross-system data pulling, and check if the identity verification node can match personnel identity and labor relation information.
- Execute the reconciliation verification step to confirm that the workflow can trigger the tax data comparison logic.
