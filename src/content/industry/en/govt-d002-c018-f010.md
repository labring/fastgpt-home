# Enrollment and Payment Verification Service Consultation and Response: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data is sourced from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. It updates once daily.
Commonly used documents include enrollment registration forms, payment base declaration forms, personnel adjustment forms, social insurance premium verification notices, and personal benefit records.
Most documents use structured form formats. They contain fields such as unit identifiers, personal identity information, payment-related parameters, and verification results. Basic measurement units include yuan and person-times.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link?
Daily updated data requires the retrieval system to support incremental index synchronization. This prevents performance losses from full index rebuilding.
Multi-source cross-system data sources require the retrieval process to align field formats across different systems. This prevents matching failures caused by differences in field names.
Mostly structured document types require retrieval to balance semantic matching and weight configuration for structured fields. It must prioritize matching core verification fields such as personal identity and unit information.
This business has severe potential error consequences. Recall results must have high confidence levels to avoid missing key verification information that causes errors in subsequent workflows.

## How to set configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Meets precision requirements for matching core fields such as enrollment identity and payment verification, balances recall rate and accuracy |
| `limit` | Top 8 entries | Covers batch verification needs for multiple document types including personnel adjustments, base declarations, and verification notices, avoids insufficient single-result coverage |
| `searchMode` | hybrid | Combines structured fields from multi-source systems and semantic matching for natural language inquiries, adapts to cross-data-source retrieval scenarios |
| `usingReRank` | Enabled | Reranks the top 10 recalled results, corrects biases from pure semantic matching, optimizes ranking weights for structured fields |
| `datasetSearchUsingExtensionQuery` | Enabled | Adds context keywords such as unit and personal identity information to user inquiries about social security issues, improves matching across system data |
| `collectionIds` | Corresponding collection IDs for enrollment and payment verification knowledge bases | Limits retrieval scope, prevents mixing with documents from other categories such as benefit verification |

## Three common misconfigurations
- Issue: Knowledge base recall results do not match user inquiries about enrollment or payment issues. Irrelevant benefit verification documents are returned. Cause: `collectionIds` is not configured correctly. The retrieval scope is not limited to the knowledge base collection for this category.
- Issue: Semantic retrieval scores fall within the 0-1 range, but some high-score results do not contain the personal identity or payment verification information requested by the user. Cause: `usingReRank` is not enabled. Ranking relies solely on original semantic similarity, without adjusting matching weights for structured fields.
- Issue: The number of retrieval results is insufficient to cover all relevant documents requested by the user. Cause: The `limit` parameter is set too low, failing to cover recall needs for multiple types of business documents.

## How to confirm correct configuration
- Review retrieval preview logs. Verify that the source documents of recalled results fall within the scope of enrollment and payment verification business.
- Test inquiry questions that include personal ID numbers and unit names. Confirm that recalled results prioritize matching core identity fields.
- Verify that after `usingReRank` is enabled, the relevance of high-score results aligns with business expectations. No obviously irrelevant documents appear at the top of results.
- Check if `datasetSearchUsingExtensionQuery` automatically adds context keywords. This can be viewed through the retrieval test interface by checking the expanded query text.

The values provided are common starting points and should be measured against the reader's own samples.
