# Service Consultation and Reply for Random Inspection and Public Disclosure Regulation: Tool Calling and Plugins

## What data falls under this category
Data for this category comes from the Random Inspection and Public Disclosure Regulation platform, Enterprise Credit Information Publicity System, industry supervision systems, and law enforcement officer directories. Daily generated documents include inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result publicity. Data updates occur on a monthly basis. Core fields include the unified social credit code of regulated entities, law enforcement officer ID numbers, inspection item codes, inspection time, rectification completion status, and additional relevant fields. Field formats match the native output of the supervision systems, with no additional custom field units.

## What constraints these characteristics impose on tool calling and plugins
Monthly updated data sources require tool calling to support scheduled synchronization of inspection target and law enforcement officer lists, to avoid using expired data. Mixed calls for multiple document types need plugins to automatically match corresponding APIs based on document type. For example, inspection result publicity must connect to the publicity system API, and on-site inspection records must link to law enforcement terminal data. The requirement for matching field formats to the supervision system means plugins must strictly use native field names in request parameters. No unauthorized modifications to field mapping rules are allowed. A single call must cover all relevant data for a single batch inspection task, to prevent incomplete tasks from split calls.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Supports automatic function calling for multiple types of regulation documents, no need to manually specify the calling tool |
| Session context retention duration | 3600 seconds | Matches the processing cycle of a single batch inspection task, ensures consultation and reply for the same batch of inspections are within the same session |
| Request retry count | 2–3 times | Addresses occasional fluctuations in supervision system APIs, prevents task interruption caused by a single failed call |
| Parameter mapping verification switch | Enabled | Ensures calling parameters fully match the native field formats of the supervision system, prevents field compatibility errors |
| Single call data limit | 1000 entries | Adapts to the single return limit of the supervision system API, avoids timeouts caused by excessive data load |
| `functionCall` | Pass parameters in the order defined in the API documentation | Strictly follows the parameter rules of the regulation platform API, ensures request validity |

## Three common configuration errors
- Consultation replies for the same batch of regulatory inspections may experience session interruptions. Subsequent consultation requests for the same batch of inspections cannot reuse prior context information. This occurs when the session context retention duration is set too short, and does not match the processing cycle of a single batch inspection task.
- Law enforcement officer list fields cannot be correctly passed to the HTTP request component, and the corresponding fields in the request body are empty. This occurs when the parameter mapping verification switch is not enabled, and no matching verification is performed between incoming fields and the native format of the supervision system.
- Calling the regulation platform API returns a `Request failed` error, with a request status code of 500. This occurs when the single call data limit is set too high, exceeding the single return limit of the supervision system API, resulting in an interface overload error.

## How to verify correct configuration
- Initiate a consultation request for a single inspection target. Check if all context information for this task is retained in the session history.
- After configuring parameter mapping rules, manually trigger a test call. Verify that fields in the HTTP request body fully match the native fields of the supervision system.
- Set the single call data limit to 100 entries, then initiate a batch call test. Confirm the API returns complete data with no timeout errors.
- Check the tool calling logs. Confirm the `toolChoice` parameter is automatically recognized as calling the corresponding regulation platform API.

The values provided are common starting points and should be evaluated against the reader's own samples.
