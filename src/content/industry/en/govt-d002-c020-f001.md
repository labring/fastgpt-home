# Service Consultation and Response for Territorial Spatial Planning Formulation and Implementation Evaluation: HTTP Interfaces and External Systems

## What this category of data entails
Core documents for this category include territorial spatial master plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data is primarily sourced from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics data, and remote sensing images. The update frequency is annual. Documents contain fields such as spatial coordinate ranges, constraint indicators, and facility layout. Units include square kilometers, population counts, and percentages. The overall content has a large volume and mixes structured and unstructured content.

## Constraints for HTTP Interfaces and External Systems
The multi-source and mixed nature of territorial spatial planning data requires interfaces to support parsing both structured fields and unstructured text simultaneously. The annual update frequency means high-frequency interface calls are unnecessary, so a long cache period can be configured. Large-volume spatial documents require interfaces to support large request contexts and long timeout periods. Associated analysis of public opinions and planning constraint indicators requires interfaces to transmit preset business parameters to limit query scopes.

## How to Configure
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| Maximum Request Context per Call | 8000–12000 characters | Matches the average length of a single block of territorial spatial planning documents to avoid truncating core spatial constraint fields |
| `Authorization` | Bearer Token | Complies with general security verification specifications for external interfaces of natural resource departments |
| `variables` Preset Parameters | Include "planning scope coordinates" and "evaluation year" | Fix core business parameters during calls to reduce repeated input and limit query boundaries |
| Maximum Search Results per Call | Top 8 entries | Covers key associated entries from multi-source data to avoid omitting special facility layout information |
| `responseData` Filter Rules | Return only "planning document body" and "public opinion summary" | Streamlines interface return content to reduce data transmission and parsing overhead |
| Interface Timeout | 120 seconds | Adapts to the pull and parsing time of multi-source spatial data, and complies with the interface timeout configuration logic of FastGPT v4.17.0 |

## Three Common Misconfigurations
- Phenomenon: API call returns `undefined` and logs show `Api response error: undefined`. Cause: `responseData` filter rules are not configured correctly, resulting in failure to properly parse unstructured spatial data returned by the interface.
- Phenomenon: The accuracy of online chat for the same knowledge base is high, but API call results have large deviations. Cause: `variables` preset parameters for planning scope and evaluation year are not passed in the API request, resulting in no business context being limited during the call.
- Phenomenon: Interface calls time out or are blocked by the target system. Cause: The interface timeout period is not adjusted to match the pull duration of multi-source spatial data, or the `Authorization` verification parameters are not configured correctly, resulting in insufficient permissions.

## How to Verify Successful Configuration
- Before calling the interface, check that the `Authorization` parameter matches the security configuration of the target natural resource system.
- View the `responseData` field returned by the interface to confirm that only the planning document body and public opinion summary are included, with no redundant fields.
- Pass the preset `variables` parameters to verify that the interface return results match the specified planning scope and evaluation year.
- Test three consecutive calls to confirm that the interface return results are stable, with no frequent timeouts or errors.
