# Government Land Spatial Planning Compilation and Implementation Assessment: Service Consultation and Reply - Workflow Orchestration

## What This Category’s Data Looks Like
Daily documents for this category include five core types: national land spatial master plans, detailed plans, special plans, planning implementation assessment reports, and public opinion summaries. Data sources include the national land spatial basic information platform, natural resource survey and monitoring data, population and economic statistics, and remote sensing images. The update frequency is annual. Documents contain fields such as spatial coordinates, planning constraint indicators, and public opinion entries. There is no unified fixed format, and structure must be adjusted based on the planning type. The length of single documents varies widely.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Annual update frequency eliminates the need for frequent knowledge base refreshes, allowing fixed scheduled sync task configuration. Multi-source heterogeneous data sources require the workflow to support cross-data-source retrieval and format compatibility, to adapt to different content types including spatial data and statistical data. Unstructured document formats require adding classification filtering logic during the retrieval phase to avoid mixing irrelevant data. Aggregating multi-source spatial data and public opinions leads to large data transfer volume between workflow nodes, so reasonable context length limits must be configured. Potential error consequences linked to planning approval require adding verification links in the workflow to ensure core data accuracy.

## Configuration Recommendations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind three types of variables: planning indicators, public opinions, and spatial coordinates | Core documents of this category need to associate three types of data to ensure accurate matching of business requirements during retrieval and generation |
| `nodeId` | Bind the IDs of knowledge base retrieval nodes and button trigger nodes | Precise invocation of resources in corresponding links is required to avoid workflow chain confusion |
| Knowledge Base Selection | Bind the national land spatial basic information platform knowledge base and planning report knowledge base | Data sources are fixed, and exclusive knowledge bases can filter irrelevant content |
| Single Search Limit | Top 5 entries | Multi-source data needs to be simplified and aggregated to avoid information overload affecting approval efficiency |
| Timeout Setting | 600 seconds | Spatial data processing takes a long time, so sufficient time must be reserved for retrieval and generation |
| Maximum Context Length | 800–1200 characters | Adapts to the text length after aggregating multi-source data, avoiding exceeding processing limits |

## Three Common Misconfigurations
- Phenomenon: Knowledge base retrieval results include a large number of irrelevant documents. Cause: The category’s exclusive knowledge base is not bound, and a general industry knowledge base is called incorrectly, reducing retrieval accuracy.
- Phenomenon: The trigger button in the conversation does not pop up normally. Cause: The `nodeId` binding for the trigger node is not configured, leading to a broken workflow chain and failure to render interactive components normally.
- Phenomenon: The generated Mermaid flowchart link fails to load. Cause: Spatial planning data fields are not correctly referenced via `variables`, leading to missing generation parameters and inability to generate valid links.

## How to Confirm Proper Configuration
- Check whether `variables` are bound to the three core data types: planning indicators, public opinions, and spatial coordinates, and confirm no omissions.
- Test the trigger button, confirm that clicking it can normally submit test opinions, and that data can be synchronized to the corresponding workflow node.
- Invoke the Mermaid MCP Server, input planning-related parameters, and verify that the generated flowchart link can be accessed normally.
- Retrieve the exclusive knowledge base, confirm that the returned results only include planning documents and related data of this category.
