# Work Consultation and Response for Territorial Spatial Planning Compilation and Implementation Evaluation: Deployment and Upgrade

## What the data for this category looks like
The core documents for this category include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data for this category is primarily sourced from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistical data, and remote sensing images. The standard update frequency is annual. Documents include fields such as spatial coordinates, constraint indicators, and regional scope. Most units use spatial and population statistical units like hectares, square kilometers, and ten thousand people. The length of individual documents varies widely, and some remote sensing image associated files have large file sizes.

## What constraints these characteristics impose on the deployment and upgrade link
The data characteristics of this category impose clear constraints on the deployment and upgrade link. The annual update frequency requires configuring adapted periodic batch data synchronization processes, supporting full or incremental spatial data import. Multi-source spatial data and large-volume remote sensing associated files require storage and vector database configurations with large-capacity support, adapting to high-concurrency spatial vector retrieval requirements. Long-text planning reports and multi-dimensional opinion summaries require context window configurations that can accommodate long text fragments, preventing key constraint indicators from being truncated. Non-standardized field structures across different documents require the knowledge base to support custom field mapping rules, adapting to format differences in planning documents.

## Three Common Mistakes
- Symptom: When calling the MCP service, the parameter `type` is fixed to the string type, and cannot adapt to non-string parameters such as spatial coordinates. Cause: Custom parameter type support for the MCP service is not enabled in the deployment configuration, or version adaptation is not completed.
- Symptom: After uploading planning documents or remote sensing images, parsing times out and the request fails. Cause: The connection timeout parameter of `PG_URL` is not adjusted, triggering the default timeout limit during batch import of large-volume files.
- Symptom: After deployment on a specific all-in-one device, spatial data synchronization fails. Cause: The `STORAGE_S3_ENDPOINT` address adapted to the device's network environment is not configured, resulting in insufficient object storage access permissions.

## How to Confirm the Configuration Is Complete
- Run a batch import test of sample data, verify that the database connection pool can cover concurrent requests during the import process, and that no connection timeout error messages appear.
- Call the MCP service to test the transfer of spatial coordinate parameters, verify that the parameter type can be customized, and that no restriction of being fixed to string applies.
- Upload a small-volume planning document via the configured frontend address, and verify that the parsing and storage processes complete normally.
- Check the memory usage of the Redis instance to verify that high-frequency cached data does not trigger memory overflow.
