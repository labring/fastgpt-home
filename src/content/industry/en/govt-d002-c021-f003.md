# Centralized Treasury Payment and Reimbursement Audit Service Inquiry and Response: Multi-turn Dialogue and Prompts

## What Data for This Category Looks Like
This category’s data originates from the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system. The update frequency is daily. Daily processed documents include payment applications, fund use plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers. Data fields cover budget indicator codes, economic classification subjects, payment amounts, contract numbers, and acceptance receipt numbers. Associated business roles include budget unit financial staff, treasury payment center staff, and department financial audit staff. All data is generated around the compliance execution link of a single fund payment.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompts
Data sources for this category are scattered and updated daily. Multi-turn dialogue must real-time associate the latest treasury indicator and contract data, avoiding expired information. The document chain for a single payment is complete. Multi-turn dialogue must gradually verify the matching relationship between invoices, contracts, and acceptance receipts. Prompts must clearly guide step-by-step verification. The verification of budget indicators and economic classification subjects is the core time-consuming link. Prompts must limit responses to only provided business documents and system data, and must not introduce external irrelevant business content. Payment amount precision requirements are high. Dialogue context must retain amount fields from each link to avoid calculation errors.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `messages` | Retain the message content of the last 10 conversation turns, only include business-related fields | Prevents overly long context from interfering with amount and compliance verification for single fund payments |
| `variables` | Inject daily updated treasury indicator balances and economic classification subject lists | Ensures dialogue uses the latest business system data |
| Single search limit | Top 5 results | The number of core documents for single payment verification in this category is limited; too many results will distract audit attention |
| Maximum context length | 8000–12000 characters | Covers the complete audit chain content of payment applications, contracts, and acceptance receipts |
| Question optimization | Enabled for business document audit scenarios | Optimizes question intent for verification of budget indicators and economic classification subjects |
| Knowledge base association trigger | Triggered when the keywords "audit", "payment", or "reimbursement" appear in conversations | Accurately matches the service inquiry and response scenario of this category |

## Three Common Misconfigurations
- Symptom: Parsing Word documents larger than 10 MB takes excessively long during conversations. Cause: No reasonable chunking parameters are set for documents in this category, such as payment applications and contracts, leading to too many chunks and redundant repeated parsing.
- Symptom: Failed to associate knowledge base data from the centralized treasury payment system after calling the API; the API returns empty fields. Cause: The `variables` parameter was not correctly injected, and the business system data source was not bound to the dialogue workflow.
- Symptom: Meaningless "|" symbols appear continuously during conversations, and normal response content cannot be generated. Cause: The prompt did not clearly define the output format, causing the model to generate debug separators.

## How to Confirm Configuration Is Complete
- Initiate a test conversation containing "check the budget indicator matching status of a single reimbursement" to verify if the conversation context retains the key fields of this business.
- Upload the complete document set for a single payment to verify if search results only include business documents of this category, with a quantity matching the business scenario requirements.
- Pass the `chatId` parameter when calling the API to verify if the multi-turn dialogue context retains the key audit information from the previous turn.
- Initiate a conversation that does not include the trigger keywords to verify that the knowledge base is not called, avoiding interference from irrelevant content in responses.
