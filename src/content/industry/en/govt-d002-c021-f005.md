# Government Centralized Payment and Reimbursement Audit Service Inquiry and Reply: Tool Calling and Plugins

## What Data This Category Includes
This category covers documents including payment applications, fund use plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers. Data sources include the government centralized payment system, unified budget management system, electronic invoice platform, and contract management system, with daily updates. Each single document contains fields such as budget indicator code, economic classification code, bill amount, contract number, and acceptance node information. Fields must strictly match the fixed format specified by financial management regulations, and there is no space for custom extended fields.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Data sources for this category are scattered and require daily synchronization. Tool calling must adapt to authentication and data format conversion across multiple system interfaces. Document fields must strictly align with financial regulations. Input parameters for tool calling must strictly validate required fields such as budget indicators and economic classifications to prevent format errors that cause audit failures. Compliance verification logic linked to a single payment is complex. Tool calling must cover linked verification across the invoice, contract, and acceptance chain, and handle callback logic for abnormal scenarios including order returns and payment corrections.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | This category requires automatic tool selection based on different business scenarios such as payment application review and reimbursement verification, with no need to fixedly call a single function |
| `functionCall` | `enabled` | The model must be forced to call specified tools to complete compliance verification, avoiding unstructured replies |
| Tool call timeout | `600 seconds` | Payment and reimbursement audits in this category connect to multiple systems to query data. 600 seconds covers the conventional time for cross-system data retrieval |
| Input parameter verification switch | Enabled | Document fields for this category must strictly match financial regulations. Enabling verification filters incorrectly formatted input parameters early |
| Log output level | Detailed | Errors in this category have serious consequences. Detailed logs quickly locate the link where the audit failed |

## Three Common Mistakes
- Unable to add connection lines to the tool call node, with no small circle on the interface: In FastGPT v4.17.0, when `toolChoice` is set to `none`, workflow nodes cannot create connection lines.
- MCP-assisted model thinking takes too long: No parameter constraints for `functionCall` are configured, causing the model to repeatedly attempt invalid tool calling logic.
- Unable to view detailed MCP service logs: Detailed log output level for tool calling is not enabled, and only basic logs are retained.

## How to Confirm Proper Configuration
- Open the tool call node in the workflow, check if `toolChoice` is set to `auto` or a specified function, and confirm the node can normally create connection lines.
- Submit test payment application data to trigger tool calling, and verify if compliance results matching financial regulations are returned.
- Navigate to the workflow operation log page, and check if detailed request and response data for tool calling are included.
- Adjust the `functionCall` configuration to confirm the model only calls specified tools to complete the review task.

The values provided are common starting points and should be measured against the reader's own samples.
