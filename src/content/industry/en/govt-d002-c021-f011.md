# Government Centralized Payment and Reimbursement Audit Service Inquiry and Reply: Forms and Interactions

## What Data for This Category Entails
Data for this category comes from the government centralized payment system, unified budget management system, electronic invoice platform, and contract management system. Updates run daily. Commonly processed documents include payment applications, fund appropriation plans, invoices, contracts, acceptance reports, reimbursement approval forms, and payment vouchers. Core fields include budget indicators, economic classification codes, invoice check codes, contract numbers, acceptance report numbers, and other relevant fields. A single data entry links to multiple types of business documents, and must include compliance check information covering the full payment execution chain.

## Constraints on the Forms and Interactions Link
Data from multiple systems requires the forms and interactions link to support cross-data source field automatic matching and verification, to avoid manual entry errors. Daily updated budget indicators require the interaction link to pull the latest available quota in real time, preventing submissions that exceed budget limits. The structure of multiple associated documents requires the form to display input items in blocks based on business scenarios, avoiding field clutter. The single data entry linked to multiple documents feature requires the interaction link to support batch import and verification, plus pre-compliance checks on input content to block content that violates financial discipline from entering the process.

## Three Common Configuration Errors
- Phenomenon: The output includes the phrase "citation mark: [1]". Cause: The automatic insertion setting for source markers of knowledge base retrieval results was not disabled, so retrieved document source identifiers are included in the final reply.
- Phenomenon: When a specified keyword is triggered, the external interface is not called, and an AI-native reply is returned. Cause: The trigger condition and external interface callback for `userSelect` were not properly bound, and the effective scope of the interception rule was not configured.
- Phenomenon: When parsing a 100,000-character Chinese Word document or a 15,000-row Excel file, an incomplete command prompt is returned. Cause: Long documents were not split into appropriate input blocks, and context passing rules for multi-turn conversations were not configured, causing a single input to exceed processing limits.

## How to Verify Correct Configuration
- Submit a simulated payment application document, confirm that input modules are displayed split by documents such as contracts, invoices, and acceptance reports, with no field clutter.
- Enter test text that exceeds the preset length, confirm that the system triggers the corresponding length limit interception prompt.
- Trigger a preset compliance keyword test, confirm that the system jumps to the bound external interface callback process.
- Upload a large-capacity test document, confirm that the system automatically splits the content and completes context passing for multi-turn conversations.

The values provided are common starting points and should be measured against the reader's own samples.
