# Transaction Consulting and Reply for Land Use Rights, Mining Rights and State-owned Property Rights: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
The data for this category mainly comes from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with a daily update frequency. Commonly involved documents include transfer announcements, trading instructions, bid application forms, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer specifications, and similar materials. These documents typically contain subject ownership descriptions, parameter information, trading process guidelines, fund vouchers, and transaction confirmation-related content. Core fields include subject location, ownership status, bid requirements, margin amount, and other key information.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt words" link
The daily update feature of the data requires that multi-turn dialogue contexts must be real-time associated with the latest listing, announcement, or transaction information to avoid referencing expired content. The document structure varies widely, ranging from short trading instructions to lengthy property right transfer specifications. Prompt words must adapt to context inputs of different lengths to ensure that core information is not truncated. Ownership, valuation, margin, and other core business fields are critical; multi-turn dialogue must focus on verifying and clarifying these contents without deviating from the core logic of the trading subject. Data formats differ across systems, so prompt words must clearly define a unified information extraction standard to avoid confusion between field definitions from different sources.

## Three Common Mistakes
- When uploading trading documents such as bid application forms and margin vouchers, the dialog box fails to parse them consistently, and no error is reported in the background. Cause: No chunking rules adapted to documents in this category are configured, or the uploaded files are not correctly associated with the conversation context.
- After copying AI dialogue content to a chat application, the Markdown formatting is lost and only plain text is displayed. Cause: The configuration for retaining dialogue content formatting is not enabled, or the correct format option is not selected during export.
- The currently running consulting dialogue cannot be stopped via the API. Cause: The dialogue termination interface bound to `chatId` is not called correctly, or the interface parameters do not match the unique identifier of the current session.

## How to Verify the Configuration is Correct
- Upload a property right transfer specification and check whether the conversation context can correctly extract core fields such as subject ownership and margin amount.
- Call the `messages` interface to verify whether the number of context records for the current conversation meets the preset 10-record limit.
- Test uploading trading-related documents and confirm that the chunked content of the file is displayed in the dialogue after parsing.
- Attempt to terminate the dialogue via the API bound to `chatId` and confirm that the dialogue stops normally.
