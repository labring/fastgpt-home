# Service Consultation and Response for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Tool Calling and Plugins

This document is written for FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category typically originates from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with daily updates. Common document types include transfer announcements, trading instructions, bid application materials, margin payment vouchers, transaction confirmation documents, listing result announcements, and property right transfer specifications. Core fields cover subject ownership information, trading restriction conditions, margin amount, bidding rules, transaction confirmation number, and other relevant details. Units include square meters, ten thousand yuan, parcels, and other measurement standards related to resource and asset ownership.

## Constraints on Tool Calling and Plugin Workflows
Multiple data sources require configuring multi-system connection adaptation logic for tool calling, to ensure complete data synchronization. Daily update frequency requires setting scheduled incremental pull tasks for plugins, to avoid data lag that impacts the accuracy of consultation responses. Diverse document types require presetting dedicated parsing rules for tool calling across different document types, to accurately extract core fields such as ownership information, margin amount, and bidding rules. Core fields involve state-owned asset ownership. The `functionCall` parameter for tool calling must have a dedicated verification function preset. The parameter verification link must strengthen legality checks, to prevent transaction risks caused by incorrect field extraction.

## Three Common Misconfigurations
- Tool calls return a 401 status code. Cause: API key permissions for connecting to public resource trading platforms are not configured correctly, or the key is not bound to the exclusive transaction data access scope for this category.
- Subject ownership information extracted after tool calling is missing. Cause: Differentiated field extraction rules are not preset for different transaction types such as land use rights and mining rights, leading to failure to match corresponding document structures.
- Tool calls trigger timeout errors. Cause: Timeout thresholds adapted to multi-source systems are not set, or incremental synchronization logic is not enabled when pulling cross-system data, causing request duration to exceed preset limits.

## How to Verify Correct Configuration
- Initiate a consultation related to state-owned property transfer, and check whether the documents returned by the tool call include category-specific documents such as transfer announcements and transaction confirmation documents.
- Check the API key configuration items, confirm that the key is bound to the access permissions of the public resource trading platform, with no cross-category data access restrictions.
- Trigger a tool call, and check whether the log includes records of the category-specific ownership verification function call, with no error messages.
- Simulate cross-system data pulling, confirm that the tool can complete multi-source data synchronization within the preset duration, with no timeout errors.
