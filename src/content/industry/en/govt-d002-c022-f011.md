# Inquiry and Response for Land Use Rights, Mining Rights, and State-owned Property Rights Transactions: Forms and Interactions

## What data for this category includes
This category of data primarily comes from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. It updates daily. Daily documents include transfer announcements, trading guidelines, bid applications, margin vouchers, transaction confirmation certificates, listing result announcements, and property right transfer descriptions. Core fields cover ownership information of trading subjects, restriction conditions, margin amounts, bidding rules, and transaction confirmation details. Most units are standard units related to resource and asset rights, such as square meters, ten thousand yuan, and parcels.

## What constraints these characteristics impose on forms and interactions
Dispersed data sources and daily updates require the form interaction link to support real-time associated calls across multiple data sources. This ensures inquiry content matches the latest listing and review statuses. Diverse document types and specialized fields require configuring input validation logic adapted to terminology such as ownership rights and bidding rules. Core fields involve critical information such as ownership certificates and margin amounts, so the interaction link must strengthen required field and format validation to reduce invalid submissions. Data links to transaction compliance, so forms must connect to the review status of preceding steps to prevent submission of non-compliant inquiries or applications.

## Three common misconfigurations
- Symptom: Only search results from a single scenario return during calls, failing to cover cross-system inquiry needs. Cause: Rules for binding corresponding knowledge bases by business scenario are not configured, and only a single data source is bound.
- Symptom: Search results cannot distinguish documents of different transaction types, leading to insufficient matching accuracy. Cause: Independent vector indexes are not configured for different business scenarios, and only a single vector model processes all data.
- Symptom: Field format errors occur after form submission, and no clear error prompt displays. Cause: Input format validation matching specialized units is not configured, causing input with non-standard units to be blocked.

## How to confirm configurations are properly set up
- Launch test inquiries for different business types, confirm returned documents match the currently selected business scenario.
- Input test content containing specialized units, confirm format validation logic correctly blocks non-standard input.
- Submit a preset field group form, confirm all required fields pass validation and have no format errors.
- Wait longer than the configured session timeout threshold, confirm the session state saves normally or a prompt to re-initiate the inquiry displays.
