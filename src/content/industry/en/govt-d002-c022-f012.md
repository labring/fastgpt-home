# Transaction Consulting and Response for Land Use Rights, Mining Rights and State-owned Property Rights: Deployment and Upgrade

## What data for this category looks like
Data for this category mainly comes from the national public resource trading platform, natural resource trading systems, property right exchange systems and state-owned asset supervision systems, with a daily update frequency. Daily documents include transfer announcements, trading instructions, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications. Core fields cover subject ownership information, trading restriction conditions, margin standards, bidding rules, and transaction confirmation content. The data structure primarily mixes structured fields and unstructured documents. This document is written based on FastGPT v4.17.0.

## What constraints do these characteristics impose on deployment and upgrades
Data sources for this category are scattered and updated daily. During deployment, adapt to multi-system data access and incremental synchronization configurations to avoid excessive resource usage from full-volume pulls. Daily document types are diverse. Optimize parsing rules for different document structures such as transfer announcements and property right transfer specifications to ensure accurate information extraction. Core fields involve sensitive content such as ownership and margin. Strengthen data verification and permission isolation configurations during deployment to prevent information leaks or incorrect calls. The consequences of trading process errors are clear. When upgrading, implement complete failure rollback and alert mechanisms to ensure business continuity in abnormal scenarios.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | This category has a large daily incremental data volume, requiring a database connection pool sufficient to support concurrent queries |
| `MONGODB_URI` | Exclusive cluster address with read-write separation suffix | Transaction data requires read-write isolation to avoid query operations affecting write performance |
| `REDIS_URL` | Exclusive cache address with password authentication | Cache high-frequency query trading rules and ownership information to reduce backend database pressure |
| `STORAGE_S3_ENDPOINT` | Endpoint address of a locally compliant storage service | Trading documents involve state-owned asset information, so compliant storage services must be used |
| `FILE_TOKEN_KEY` | `32-bit random encrypted string` | Ensure token security for document download and preview to prevent unauthorized access |
| `ROOT_KEY` | Regularly rotated high-strength key | Restrict access permissions for background management interfaces to prevent unauthorized operations |

## Three common misconfigurations
- Symptom: Unable to register an account independently after local deployment, with an interface prompt indicating no permission to create a new account. Cause: `ROOT_KEY` is not configured correctly, or the public registration switch is not enabled, resulting in restricted initial account permissions.
- Symptom: Knowledge base search response times out, taking more than 30 seconds. Cause: `DB_MAX_LINK` is configured too low, depleting the database connection pool and failing to process concurrent query requests in a timely manner.
- Symptom: Docker deployment integrated indexing model fails, unable to load trading documents. Cause: `STORAGE_S3_ENDPOINT` is not configured correctly, with an incorrect storage endpoint address causing document pull failures.

## How to confirm configurations are valid
- Run the database connection test script to verify that the connection pool configured via `DB_MAX_LINK` can normally support the preset concurrency volume, and adjust the configuration to meet business peak demand.
- Trigger an incremental synchronization task to check whether daily updated trading documents are normally loaded into the knowledge base, confirming that multi-source data access configurations are effective.
- Send high-frequency search requests to verify that search response times meet business expectations, and adjust cache configurations to optimize query performance.
- Attempt to access the document preview function using a test account to verify the validity of the token configured via `FILE_TOKEN_KEY`, confirming that permission isolation rules are effective.
