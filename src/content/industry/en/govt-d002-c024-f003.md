# Service Consultation and Response for Student Financial Aid and Subsidy Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources include the national student financial aid management information system, school student status system, civil affairs low-income and special hardship data, and fiscal payment systems. The update frequency is per semester. Daily documents include family economic hardship assessment forms, financial aid application forms, scholarship and grant review forms, distribution lists, and public notification materials. Fields cover student identity information, family economic status, financial aid application content, review results, bank card information, and more. Units include student status numbers, financial aid amounts, and distribution batches.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
The semester-based update rhythm requires the knowledge base to perform full refreshes regularly to avoid expired data. Multi-source heterogeneous data sources require unified field alignment to prevent data conflicts or inconsistencies during dialogue. Documents cover multiple stages such as review and distribution, so prompts must guide conversations to focus on core business links like qualification verification and distribution checking. Data fields involve sensitive information, so multi-turn dialogue must limit context length to prevent information leakage. Additionally, verification needs for core time-consuming links require retrieval to prioritize recalling core documents related to student status and review.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to the current consultation session | Ensure multi-turn dialogue retains historical interaction context and maintains consultation continuity |
| `variables` | Bind to student ID number, student status number fields | Accurately retrieve financial aid-related data for the corresponding student, avoid confusing different consultation subjects |
| `messages` | Concatenate according to session history | Ensure complete transmission of context for multi-turn dialogue |
| Chunk length | 800–1200 characters | Daily documents are mostly single student application or review materials; this length fully preserves core fields of single-item information |
| Similarity threshold | 0.75–0.85 | Distinguish similar student identities, financial aid amounts and other information, avoid incorrect recall of non-target documents |
| Single search limit | Top 6 entries | The number of core documents within a semester is concentrated; excessive recall increases context processing load |
| Maximum context | 4000–6000 token | Multi-turn dialogue needs to retain student consultation, historical verification results and other information, adapting to model context limits |

## Three Common Misconfigurations
- Symptom: An error is prompted when uploading documents such as family economic hardship assessment forms and financial aid application forms, but text input dialogue functions normally. Cause: Parsing rules for corresponding student financial aid documents are not configured, or the uploaded file format exceeds the platform's supported range.
- Symptom: Multi-turn dialogue response speed is slow. Cause: The number of documents recalled by a single search exceeds the configured limit, or the context length is set too large, increasing platform processing load.
- Symptom: An `Unexpected end of JSON input` error occurs when calling the model, which occurs frequently when using the `chatglm2` model. Cause: The model's returned output is not properly spliced, or the multi-turn dialogue context token length exceeds the maximum supported by the model, resulting in content truncation.

## How to Verify Correct Configuration
- Initiate a consultation that includes the student's student status number, confirm that subsequent multi-turn dialogue can continue interactions using financial aid-related information for that student.
- Upload a single family economic hardship assessment form, confirm that the document can be properly parsed and included in the retrieval scope.
- Initiate more than 5 consecutive consultations, check whether response delays or `Unexpected end of JSON input` errors occur.
- Adjust the single search limit configuration, verify that recalled documents only include student financial aid-related materials from the current semester.
