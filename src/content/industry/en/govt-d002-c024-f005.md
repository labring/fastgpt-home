# Student Financial Aid and Subsidy Review: Service Consultation and Reply - Tool Calling and Plugins

## What this category of data consists of
This category of data covers the full student financial aid workflow. Core documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Data sources include the National Student Aid Management Information System, school student registration systems, civil affairs low-income and special hardship data, and fiscal payment systems. Updates follow the semester schedule. Each document includes fields such as student identity, family economic status, student registration status, aid application tier, disbursement amount, and bank card information. All content is organized around the core logic of aid qualification and fund disbursement, with no redundant cross-category information.

## Constraints on Tool Calling and Plugin Workflows
The semester-level update frequency requires tool calling to adapt to batch verification scenarios. The set of documents processed in a single run must match the review batch for the semester. Multiple heterogeneous data sources require plugins to connect to different system interfaces separately. This prevents format conflicts during cross-source data verification. Core document fields focus on qualification and funds. Tool calling prompts must be strictly limited to aid-related fields, to avoid introducing irrelevant information. The strong correlation between public notification materials and disbursement lists requires tools to automatically associate the student identity fields of both documents during calls. This ensures consistency in verification. The `toolChoice` parameter must be configured to support automatic calling of multi-source data, without manual tool specification.

## Configuration Settings

## Three Common Misconfigurations
- Issue: Tool call return results differ from results obtained directly using function call. Logs show abnormal parameter configuration. Cause: The `toolChoice` parameter is not configured correctly, causing the tool call trigger logic to deviate from expected behavior.
- Issue: After enabling tool calling, the conversation only returns structured review results, with no thought process output. Cause: The thought process retention configuration for tool calling mode is not enabled, or the prompt does not explicitly require outputting thinking steps.
- Issue: Connection timeout errors occur when calling a local MCP service, and external data sources cannot be accessed. Cause: The port and access path of the local service are not specified in the plugin configuration, preventing the tool from identifying the locally deployed MCP node.

## How to Confirm Successful Configuration
- A test query containing student identity and family economic status is initiated. Verify that the tool automatically calls plugins for the corresponding data sources.
- Tool call logs are reviewed to confirm that return results include core fields such as family economic hardship certification forms and student registration status.
- The conversation interface is called to check whether returned results include referenced knowledge base document identifiers.
- Batch submission of review data for a single semester is tested. Confirm that no timeouts or format errors occur during tool calls.
