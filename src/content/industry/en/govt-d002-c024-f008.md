# Student Financial Aid and Subsidy Review: Service Consultation and Response - Document Parsing and Chunking

## What this category of data looks like
Data for this category primarily originates from the national student financial aid management information system, school student registration systems, civil affairs low-income and extremely poor assistance data, and fiscal payment systems. Updates occur once per semester. Daily processed documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, distribution lists, and public announcement materials. Most fields include student identity identifiers, family economic status information, review results, and bank card information. Some documents are structured tables, while others are public announcement text, with no unified fixed format.

## What constraints do these characteristics impose on the document parsing and chunking link
Semester-level batch data updates require the document parsing link to adapt to batch import scenarios, and avoid excessive parsing time for single files. Differences in document formats across multiple sources require the parsing module to support both structured tables and public announcement text. Structured documents such as family economic hardship certification forms must retain field associations, and avoid breaking contextual logic within tables during chunking. Public announcement text must be split along paragraph boundaries, and avoid splitting complete statements of review opinions or student requests. Field differences across systems require the parsing link to support custom field mapping, and adapt to identifier formats from different sources.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| `chunkSize` | 800–1200 characters | Adapts to the field density and text length of student financial aid documents, and avoids losing associated information after chunking |
| `chunkSplitter` | Split by paragraph + title | Adapts to the text structure of public announcement materials and review forms, and retains the integrity of business logic |
| `customPdfParse` | Enable structured table parsing mode | Adapts to structured PDF documents such as family economic hardship certification forms and distribution lists, and accurately extracts table fields |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to semester-level document packages for batch imports, and avoids upload failures due to oversized files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of single large review forms or batch documents, and avoids mid-task timeout interruptions |
| `chunkSettingMode` | Manual configuration | Supports adjusting chunking rules for different document types, and meets the needs of multi-format documents in this category |

## Three Common Misconfigurations
- Phenomenon: An unsupported format error is displayed when uploading Excel files, or only two columns of data are retained after importing CSV files. Cause: Custom file parsing adaptation is not enabled, or structured table parsing rules are not configured, resulting in non-standard format tables failing to be correctly identified.
- Phenomenon: A connection failure error or request timeout occurs when calling marker-pdf parsing. Cause: The locally deployed Docker service did not correctly expose ports, or the `PARSE_FILE_TIMEOUT_SECONDS` configuration value is lower than the actual parsing time, resulting in task interruption.
- Phenomenon: The generated response uses newly created content instead of original content from the knowledge base. Cause: Chunking and recall rules are not correctly configured, resulting in the recalled context not containing the original response fragment of the target question and answer pair, or the `chunkSize` setting is unreasonable, causing the original text to be lost during chunking.

## How to Confirm Proper Configuration
- Upload a single family economic hardship certification form PDF, and check whether the parsed text retains all fields in the table, with no missing or misaligned content.
- Upload a batch document package, and check whether the parsing task duration is lower than the `PARSE_FILE_TIMEOUT_SECONDS` configuration value, with no timeout errors.
- Import a preset question and answer pair document, initiate a consultation, and verify whether the response directly uses the original response content from the knowledge base.
- Upload a CSV format distribution list, and check whether all columns of data are retained after parsing, with no truncation or format confusion.
