# Student Financial Aid and Subsidy Review: Service Inquiry and Reply – Forms and Interactions

## What Data Belongs to This Category
Data for this category comes from the national student financial aid management information system, school student status system, civil affairs low-income and special hardship data system, and fiscal payment system. The update cycle follows academic semesters.
Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, distribution lists, and public announcement materials.
Core fields cover family economic status, student ID number, bank card information, review level, and more. All data supports subsidy qualification verification and fund disbursement workflows.

## Constraints Imposed on the "Forms and Interactions" Link
Multi-source data sources require forms to support cross-system data linkage verification. This prevents manual entry errors.
The semester-long update cycle means form configurations must align with phased business rhythms. No frequent adjustments are needed.
Diverse business documents require forms to support multiple file uploads and field mapping. This matches material submission needs across different stages.
Strict requirements for core fields mandate real-time verification during interactions. This reduces subsequent verification time and error rates.
Interaction and submission records must be retained. This addresses potential public notice objections or audit reviews.

| Tool call model selection | `userSelect` mode, for service staff to select appropriate question answering models | Adapt to different inquiry types in service inquiry scenarios, to flexibly use model capabilities |
| `formInput` configuration | Enable context memory, retain the last 3 rounds of inquiry content | Match the multi-round interaction scenario of service inquiries, to avoid repeated questions |

## Three Common Misconfigurations
- A specified speech recognition model cannot be selected in the interface. Only the general question answering model is displayed. The cause is that the call permission configuration for the corresponding model is not enabled, or the optional range is not set in the tool call model selection.
- After the form is submitted, an empty result is returned with no verification prompts. The cause is that no form field verification rules are configured. Invalid fields enter the backend process directly, triggering a return of no matching data.
- The corresponding tool cannot be automatically selected when calling the advanced orchestration tool. The cause is that the trigger condition for `userSelect` mode is not set, or the mapping relationship between tools and inquiry types is not bound.

## How to Confirm the Configuration Is Complete
- Submit a standard family economic hardship certification form for testing. Check if the form automatically verifies required fields and formats, and pops up corresponding prompts.
- After enabling the multi-source data linkage switch, enter a known student ID number. Check if the corresponding student status information is automatically linked.
- Initiate multiple rounds of service inquiries. Check if context memory is retained, so basic information does not need to be provided repeatedly.
- Go to the tool call configuration page. Confirm that the optional model and tool list have loaded correctly, and manual selection of corresponding items is available.
