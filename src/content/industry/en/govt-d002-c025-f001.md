# Work Consultation and Response for Safety Production Hazard Inspection and Governance: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category comes from safety production supervision systems, enterprise self-inspection hazard systems, law enforcement inspection records, and accident statistics systems, with a daily update frequency. Daily documents include hazard inspection lists, hazard governance ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Data fields include unique hazard IDs, rectification responsible persons, rectification deadlines, review statuses, hazard levels, and more. Units include items, days, level identifiers, and others. Data formats vary slightly across different sources, so unified adaptation via interfaces is required.

## Constraints on HTTP Interfaces and External Systems
Multiple data sources and daily updates require interfaces to support scheduled synchronization and multi-format adaptation. This prevents data loss from differences between data sources.
Diverse document types require interfaces to identify and filter non-hazard-related documents. This ensures accurate work consultation content.
Fields include clear responsibility and deadline information. Interface parameter validation must cover required fields to prevent invalid data from entering the system.
Failures may lead to major accidents, production suspensions, or administrative penalties. Interface failure handling must include retry and alert mechanisms.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `Authorization` | `Bearer ${Supervision System API Key}` | Complies with industrial interface authentication standards, and adapts to the authentication requirements of most safety production supervision systems |
| `variables` | `{"updateCycle": "2 AM daily", "docTypes": ["hazard inspection lists", "hazard governance ledgers"]}` | Matches the daily data update frequency and category-specific document types, and filters irrelevant content |
| `responseData` | `{"code": 200, "message": "Operation successful", "data": []}` | Complies with the return format specifications of most supervision systems, and facilitates parsing by connected parties |
| Webhook Trigger Timing | When hazard status changes | Matches the real-time synchronization requirements of work consultation, and ensures consultation content aligns with rectification progress |
| Interface Timeout Threshold | 300 seconds, adjustable to a range of 240–360 seconds based on actual testing | Prevents long-running ledger synchronization tasks from blocking interface links |

## Three Common Misconfigurations
- Failing to include a valid authentication key when configuring `Authorization` results in a 401 Unauthorized status code from the interface. This occurs because authentication parameters are not configured per the requirements of the connected supervision system, leading to authentication failure.
- Not specifying document type filtering rules via `variables` causes the interface to sync non-hazard inspection-related documents. This occurs because category-specific document structure features are not matched, leading to redundant consultation content.
- Omitting OneAPI-related parameter entries in the deployment configuration prevents external supervision system interface calls after startup. This occurs because the deployment template does not include such third-party interface configuration entries by default, and corresponding parameters must be added manually.

## How to Confirm Successful Configuration
- Review interface call logs to confirm the `Authorization` parameter is correctly included in request headers.
- Trigger a simulated request for a hazard status change, and check that the `responseData` return format matches preset rules.
- Review data synchronization records to confirm that category-specific documents such as hazard governance ledgers are synced daily according to the set cycle.
- Test Webhook triggering to confirm that the external system receives push content for rectification notices.
