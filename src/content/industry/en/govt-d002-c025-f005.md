# Work Consultation and Reply for Work Safety Hazard Investigation and Governance: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category comes from work safety supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily business documents include hazard investigation checklists, hazard governance ledgers, rectification notices, review records, and major hazard rectification supervision order forms. Data fields cover hazard level, rectification responsible party, rectification deadline, review results, and more. Common units are items, entries, and days. Single record sizes range from hundreds to thousands of characters.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Daily updated data requires configuring a scheduled synchronization mechanism during tool calls. This ensures the latest investigation and rectification records are retrieved. Expired data must be avoided to prevent inaccurate business judgments.
Large structural differences across multiple document types require plugins to adapt field parsing logic for each document type. This prevents data extraction errors.
The accuracy of fields such as hazard level and rectification deadline directly impacts business disposal outcomes. A parameter verification step must be added during tool calls to filter invalid or incorrect data.
Data sources are scattered. Plugins must support connections to multiple system interfaces. Expansion space must be reserved to support new database types.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling mode | Force `functionCall` mode | This category requires precise tool calls to extract structured business data, avoiding free-form generation that does not match actual business needs |
| Knowledge base association rules | Associate knowledge bases of hazard investigation checklists and rectification ledgers | Core business data comes from these two types of documents, which improves the accuracy of consultation and replies |
| Database connection scope | Support MySQL, PostgreSQL, SQL Server, expand support for other database types based on actual testing | Covers mainstream production system database types, while reserving expansion space to meet subsequent user needs |
| Plugin trigger timing | Trigger when the user consults issues related to hazard investigation, rectification, or review | Focuses on the business scenario of work consultation and reply, avoiding invalid calls |
| Parameter verification switch | Enabled | The accuracy of hazard-related fields directly affects business disposal, and verification reduces the inflow of incorrect data |
| Timeout setting | 600 seconds | Sufficient time must be reserved for pulling data from multiple systems, avoiding call failures due to timeout |

## Three Common Configuration Mistakes
- Not returning the knowledge base ID when calling the conversation interface: The phenomenon is that the interface return result does not include the identification field of the associated knowledge base. The cause is that the knowledge base association configuration is not enabled, or the knowledge base corresponding to the business scenario is not bound during configuration.
- Unable to connect to the local MCP service: The phenomenon is that the local MCP service cannot be properly recognized by the plugin. The cause is that the network access permission of the local service is not configured, or the plugin port is not correctly mapped.
- No response after configuring the email sending plugin: The phenomenon is that the plugin returns a sending failure prompt. The cause is that the correct SMTP server address and authorization code are not configured, or the email sending permission of the plugin is not enabled.

## How to Confirm the Configuration Is Correct
- Initiate a consultation related to hazard investigation, check the FastGPT v4.17.0 tool call log, and confirm that the corresponding plugin has been triggered.
- Call the conversation interface, check whether the return result includes knowledge base association information, and verify that the configured knowledge base has been correctly associated.
- Test the connection to the configured database, confirm that hazard ledgers or investigation checklist data can be normally pulled, and verify that the database connection configuration takes effect.
- Trigger the email sending plugin, enter test rectification notice content, and verify whether the plugin can normally complete the sending process.
