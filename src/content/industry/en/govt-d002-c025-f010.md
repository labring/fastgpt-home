# Work Consultation and Response for Safety Production Hazard Inspection and Governance: Knowledge Base Retrieval and Recall

## What data for this category includes
This category’s data comes from safety production supervision systems, enterprise hidden hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. Updates occur daily. Daily documents include hazard inspection checklists, hazard management ledgers, rectification notices, re-inspection records, and major hazard suspension and supervision orders. Individual documents carry dedicated business fields including hazard number, inspection time, rectification responsible person, rectification deadline, and re-inspection result. Data links to production and business entity codes and supervision area codes. There is no unified fixed unit of measurement.

## Constraints on knowledge base retrieval and recall
Daily updated data requires the retrieval link to support incremental synchronization and incremental recall, to avoid performance loss from full re-scanning. Multiple document types coexist, so recall priority must be set for different document types. Dedicated business fields require retrieval to support precise field matching, to improve result relevance. Data is linked to production and business entities and supervision areas, so retrieval must support filtering results by entity code and area code. Documents related to major accident hazard determination standards must be recalled first, to support comparison needs during the inspection process.

## Configuration settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Semantic similarity threshold for matching hazard-related text. Covers semantic connections between routine inspection descriptions and determination standards. Avoids too many irrelevant results if set too low, and misses valid rectification records if set too high. |
| `limit` | Top 8–12 entries | Maximum number of single-recall results. Adapts to the need for quickly viewing multiple related documents in hazard inspection scenarios, avoids context overflow from too many results. |
| `searchMode` | `vector` | Prioritizes vector retrieval mode to meet semantic matching needs for multiple types of business documents. Combines business field filtering to achieve precise recall. |
| `usingReRank` | Enabled | Reranks recall results, returns documents more relevant to hazard determination and rectification requirements first. Compensates for semantic bias in vector retrieval. |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands query terms, adds synonyms related to major accident hazard determination standards, improves matching capability for professional terminology. |
| `collectionIds` | Bind 1–3 dedicated knowledge base collections | Limits retrieval scope to only dedicated knowledge bases for the current production and business entity or supervision area, avoids interference from irrelevant documents across entities. |

## Three common misconfigurations
- Symptom: An authentication failure message is returned when calling the API to sync the hazard management knowledge base collection. Cause: The current calling entity lacks access permissions for the corresponding business knowledge base, or API key configuration errors cause identity verification failure.
- Symptom: A provider-related error triggers when adding a new knowledge base folder. Cause: No storage provider adapted to safety production document storage is selected, or basic configuration parameters for the storage provider are not fully filled in.
- Symptom: The number of hazard-related documents returned by retrieval is far lower than expected. Cause: The `similarity` threshold is set too high, filtering out rectification notices, re-inspection records, and other documents that meet semantic association requirements but have slightly lower similarity scores.

## How to confirm the configuration is correct
- Run a single retrieval test using a hazard inspection description, verify that returned results include the corresponding business document types, and check that result sorting aligns with business priority rules.
- View retrieval logs, confirm that only knowledge base documents within the specified `collectionIds` range are recalled, with no irrelevant results across business entities.
- Trigger an incremental synchronization task, check that the data update frequency matches the daily business requirement, and no full repeated synchronization logs appear.
- Simulate an unauthorized API call scenario, confirm that the request returns a clear permission exception prompt, matching the expected error handling logic.

The values provided are common starting points and should be evaluated against the reader's own samples.
