# Work Consultation and Response for Safety Production Hazard Inspection and Governance: Forms and Interactions

This guide applies to FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category includes standardized documents such as hazard inspection lists, hazard governance ledgers, rectification notices, review records, and major hazard supervision order forms. Data sources include safety production supervision systems, enterprise self-inspection systems, law enforcement inspection records, and accident statistics systems. Updates occur daily. Data fields include hazard level, rectification responsible entity, rectification deadline, review results, and other relevant items. Common units are natural days and hazard level classification tags. The size of individual records grows gradually as inspection coverage expands.

## Constraints for Forms and Interactions From These Characteristics
Multi-source data access requires forms to pull and fill data across systems, to avoid errors from duplicate entry. Daily updated data must be synchronized to the corresponding supervision system after form submission, to ensure data timeliness and consistency. This category centers on the hazard rectification process. Unlike administrative penalty scenarios, forms do not need to cover penalty process fields, and focus exclusively on inspection and rectification links. Fields include standardized content such as hazard level and rectification deadline. Preset compliant options are required to reduce manual input errors and prevent submissions that do not meet regulatory requirements. Severe potential error consequences require forms to include mandatory field checks and format checks, to avoid missing key information that causes subsequent rectification process failures.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Customized according to hazard inspection list fields | Matches the field structure of standardized documents in this category |
| `userSelect` | Preset options for hazard level and rectification deadline | Corresponds to the fixed value range of data fields |
| Context Window | 800–1200 characters | Carries complete information for a single hazard inspection record |
| Submission Validation Rules | Mandatory field check + format check | Prevents missing key information from causing subsequent rectification process failures |
| Data Synchronization Trigger | Within 60 seconds after form submission is successful | Matches the daily data synchronization requirements of this category |
| Result Output Filter | Only retain final review results | Streamlines the output content of consultation responses |

## Three Common Misconfigurations
- When configuring the `userSelect` component, failing to cover all compliant value ranges for this category’s data fields leads to empty fields after submission.
- When configuring multi-round AI conversations in the workflow, not enabling result output filtering causes the final response to include intermediate content from previous AI rounds.
- Failing to configure permission mounting during container deployment results in insufficient permissions when attempting to install dependency packages.

## How to Verify Proper Configuration
- Submit a test hazard record, and verify that the form fields match the preset business document fields.
- Trigger the data synchronization process, and verify that the synchronized record appears in the corresponding location of the corresponding supervision system.
- Initiate a consultation query, and verify that the response content only includes final information related to the current hazard.
- Simulate input that does not meet the format requirements, and verify that the form triggers the preset validation rules and provides prompts.

The configuration values provided are common starting points, and should be evaluated against the user's own specific samples.
