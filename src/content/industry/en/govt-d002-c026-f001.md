# Engineering Construction Project Approval: Inquiries and Responses — HTTP APIs and External Systems

## What data for this category looks like
Data for this category comes from engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases, and credit platforms. The update frequency is daily. Daily involved documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record filing forms. Data fields include approval node status, participating construction unit qualification information, project approval information, filing material verification results, and more. Most formats are structured JSON fields and standard PDF, DOC format file attachments. No custom special units are used.

## Constraints imposed on HTTP APIs and external systems
Data sources for this category cover multiple government systems. The daily update frequency requires APIs to support incremental pulling to reduce transmission overhead. Daily documents include structured application materials and large-volume file attachments, so APIs must support both JSON field transmission and file stream uploads. Sensitive government data such as participating unit qualifications and project approval status requires APIs to be configured with strict authentication mechanisms to ensure data security. Approval processes include time-consuming steps such as compiling materials and verifying qualifications. API timeout settings must match actual business duration to avoid data synchronization interruptions from timeouts.

## Configuration Settings

| Configuration Item | Recommended Approach | Rationale |

| `Authorization` | `Bearer API key assigned by the government platform` | This category's data comes from government systems, and standard Bearer authentication is required to ensure data transmission security |
| `variables` | Pass project ID and approval node type | Accurately locate corresponding approval data for engineering construction projects, avoiding returning irrelevant information |
| `responseData` | Only return approval status, filing material status, and participating unit qualification fields | Filter non-essential data to reduce API transmission load |
| Timeout duration | 600 seconds | Matches the time-consuming steps of compiling approval materials and verifying qualifications for this category, preventing data pulling interruptions from short timeouts |
| Attachment upload limit | Support up to 1000 MB attachments | Matches the characteristic that daily documents include large-volume files such as construction drawing review qualification certificates |
| Synchronization trigger timing | Execute daily at 2:00 AM | Matches the daily update frequency of this category's data, avoiding interference with normal approval business |

## Three Common Configuration Mistakes
- Symptom: API call returns a timeout error with status code 504 or no request response. Cause: The timeout setting does not match the time-consuming characteristics of this category's approval process, and the set timeout duration is too short to complete data pulling for material compilation or qualification verification.
- Symptom: External system API call returns empty parameters, and approval data cannot be obtained. Cause: The correct project ID or approval node type was not passed via `variables`, causing the API to fail to locate target data.
- Symptom: After uploading attachments such as completion record filing forms, data and indexing cannot be confirmed. Cause: The `responseData` configuration was not set to return the file verification status field, making it impossible to judge upload results via the API return result.

## How to Confirm Correct Configuration
- Call the configured API, pass a known project ID, and check if the returned fields include preset approval status and participating construction unit qualification information.
- Simulate an API call to confirm that the `Authorization` authentication parameter takes effect, and no 401 unauthorized error is returned.
- Upload a test file in the format of daily documents, check if the API returns the corresponding verification result, and confirm that attachment transmission works normally.
- Set a scheduled trigger test to confirm that the daily synchronization task executes as expected, with no abnormal errors.
