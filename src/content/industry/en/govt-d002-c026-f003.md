# Administrative Approval for Construction Projects: Public Inquiry and Response — Multi-turn Dialogue and Prompt Configuration

## What This Category’s Data Looks Like
Data for this category is sourced from the construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform. The update frequency is daily. Commonly associated documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision documents, completion acceptance record forms, and similar materials. Data fields cover project numbers, participating unit qualifications, approval node status, filing information, and more. Most field types are standardized text, including fixed-format project identifiers, personnel names, and approval phase names. There are no complex measurement units.

## Constraints for Multi-turn Dialogue and Prompt Configuration
This category’s data originates from multiple systems. Multi-turn dialogue must integrate approval node data, qualification information, and filing data from different systems to avoid context gaps. The daily update requirement means prompt configurations must explicitly call the latest dataset to ensure inquiry content matches currently effective approval rules. Document types across the full approval workflow are supported. Multi-turn dialogue must match corresponding document fields for each phase, such as construction permits and construction drawing reviews. Prompts must clearly state material requirements for each phase. Most fields are standardized text, so dialogue interactions must strictly match fixed fields to reduce recognition errors. Response accuracy must be maintained to avoid approval delays.

This configuration applies to FastGPT v4.17.0. Specific configuration items and recommended values are listed below:

## Three Common Misconfigurations
- Phenomenon: After uploading construction drawing or approval material images, the system does not return image text analysis results. Cause: Image OCR parsing configuration is not enabled, or the configuration does not meet the parsing needs of engineering drawing images.
- Phenomenon: After adjusting the number of displayed chat records, multi-turn dialogue context does not load as expected, and current inquiry results are interfered with by irrelevant historical data. Cause: Context filtering rules for the `messages` parameter are not configured correctly, resulting in redundant historical messages being included in the current dialogue context.
- Phenomenon: Responses from the login-free dialogue window have significant delays and do not return in real time as expected. Cause: Streaming output configuration is not enabled, or the streaming output timeout setting does not match the current hardware environment.

## How to Verify Proper Configuration
- Initiate a multi-turn dialogue describing construction permit application materials, check whether the system automatically associates document requirements for the corresponding approval phase.
- Upload engineering-related images, verify whether text content in the images is returned, confirming that the OCR parsing configuration is active.
- Adjust the dialogue context length parameter, initiate multiple consecutive inquiries, check whether historical messages load as configured and no redundant interference occurs.
- Test the response speed of the login-free dialogue window, confirm whether the streaming output configuration is enabled as expected.
