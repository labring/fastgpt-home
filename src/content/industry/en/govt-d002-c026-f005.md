# Service Inquiry and Response for Engineering Construction Project Approval: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. The update frequency is daily. Documents processed daily include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, completion record forms, and more. Fields cover approval nodes, participating unit qualifications, personnel information, material submission status, and other related content. Data dimensions focus on licensing, filing, and compliance information across the full project approval process. There is no fixed uniform word count or upper limit for the number of fields per single document.

## What constraints these characteristics impose on tool calling and plugin workflows
The multi-source data nature of this category requires tool calling to adapt to the interface formats of multiple independent data sources such as the engineering construction project approval management system and construction drawing review system, to avoid cross-system data connection exceptions. The daily data update frequency requires the tool calling caching strategy to match the update rhythm, to prevent returning expired approval node or qualification information. The differentiated fields of various approval documents require tools to recognize the exclusive information dimensions of different documents, to accurately extract required content. Errors in the approval process may lead to unlicensed construction or filing failure. The result verification link of tool calling must cover core fields such as participating unit qualifications and material completeness, to ensure compliance of the approval process.

## How to configure settings
The following configurations are based on the tool calling and plugin module of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `auto` | Adapt to the needs of dynamically deciding whether to call tools such as qualification query and material verification in engineering approval scenarios, allowing the model to independently judge the timing of tool calls |
| `functionCall` | Enable and specify the allowed tool scope as qualification database query and approval node tracking | Restrict the boundary of tool calls, avoid calling external interfaces unrelated to approval, and align with the usage scope of data in this category |
| Tool call timeout | 300 seconds | Match the average response time of multi-system interfaces, prevent overall process interruption due to slow response of a single data source |
| Automatic document recognition switch | Enable | Automatically distinguish different types of approval documents such as construction permit applications and construction drawing review qualification certificates, adapting to field extraction requirements for multiple document types |
| Data synchronization frequency | 2:00 AM daily | Match the daily update rhythm of data in this category, ensuring that the latest approval and qualification information is obtained during tool calls |
| Result verification rules | Calibrate based on actual testing | Set verification logic for core fields such as participating unit qualifications and approval node status, ensuring returned data meets approval requirements |

## Three common configuration errors
- Phenomenon: Custom external interface calls return empty fields or abnormal status codes. Cause: The data source interface address and parameter format required for this category are not specified in the plugin configuration, resulting in failure to correctly connect to the engineering construction project approval management system or qualification database.
- Phenomenon: The model does not automatically read the content of approval documents such as construction drawing review qualification certificates. Cause: The tool calling mode after automatic file upload is not enabled, or `toolChoice` is not configured as `auto`, preventing the model from independently judging whether to read the document.
- Phenomenon: Tool calls return expired approval node information. Cause: The data synchronization frequency is not configured to match the daily update rhythm of this category, and cached old data is used.

## How to confirm the configuration is complete
- Initiate a test session containing a requirement to query participating unit qualifications, check whether the tool automatically calls the preset qualification database query interface and returns corresponding results.
- Upload a construction permit application document, check whether the model automatically triggers document content reading and extracts core information such as the application unit and project name.
- View the tool call log, confirm that all called interfaces are pre-configured engineering approval-related data sources, with no unrelated external calls.
- Wait for the daily synchronization task to complete, then initiate an approval node tracking request, check that the returned node information is the latest updated data.
