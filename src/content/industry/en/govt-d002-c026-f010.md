# Administrative Approval for Construction Projects: Service Inquiry and Reply - Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for this category comes from the construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform. The update frequency is daily. Daily documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedure documents, completion acceptance record forms, and similar items. Data fields cover approval node information, participating construction units' qualifications, personnel qualifications, project progress status, and similar items. A single document typically includes standardized fields such as project number, handling link, and required submission material list. Some cross-system documents have inconsistent field formats.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Daily updated data requires the retrieval pipeline to support incremental synchronization, to avoid performance loss caused by full re-scanning. Multi-source approval documents have inconsistent field formats, so field standardization alignment must be completed before recall, to ensure that qualification and approval node information exported from different systems can be matched uniformly. Approval links are tied to the full compliance of the project process, so the accuracy of retrieval results directly affects approval efficiency and compliance. The relevance threshold of recall results must be strictly controlled, to avoid irrelevant content interfering with window staff judgments. At the same time, inquiries about approval usually focus on specific links, so retrieval results must accurately match the user's link query needs.

## Three Common Configuration Mistakes
- The semantic similarity value of retrieval return results is abnormally high, and logs show vector matching scores far exceed conventional thresholds. The cause is that the `similarity` matching parameter is not calibrated when using the `bge-m3` vector model. The vector generation logic of the model itself causes the high-score interval to be amplified, which does not meet the relevance requirements of the engineering approval scenario.
- Unable to normally obtain knowledge base recall results when calling open interfaces, and returns permission errors. The cause is that the external access permission of the corresponding engineering approval dataset is not configured in the FastGPT platform settings, and permission verification for cross-product integration is not completed.
- The model does not automatically call the knowledge base after triggering question answering, only returns general question and answer content, or cannot retrieve approval-related content in the general search engine template. The cause is that the retrieval trigger rule is not configured, or the template is not bound to the exclusive dataset for construction project approval, resulting in the retrieval scope not covering category-specific documents.

## How to Confirm Configuration is Correct
- Submit a simulated service inquiry, such as "What materials are required to apply for a construction permit", and check whether the recall results include documents related to construction permit applications.
- View the retrieval log, confirm that the `similarity` score is within the preset interval, and there are no abnormally high or low matching results.
- Test the open interface call, confirm that recall data related to engineering approval can be returned normally, and there are no permission errors.
- Trigger model question answering, confirm that the system automatically calls the knowledge base recall link, and the returned content includes approval information in the exclusive dataset.
