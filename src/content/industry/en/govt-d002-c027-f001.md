# Service Consultation and Reply for Engineering Construction Project Bidding: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category comes from national public resource trading platforms, local public resource trading platforms, project approval systems, and bidding supervision systems. Data updates occur daily.
Daily business documents include tender announcements, qualification pre-qualification documents, bidding documents, bid submission files, bid evaluation reports, successful bid candidate notices, and successful bid result announcements.
The data structure includes core fields: basic project information, section division rules, qualification requirements, bill of quantities, bid evaluation expert records, and successful bid results.
Entities including development and reform departments, housing and urban-rural development, transportation, water conservancy industry competent departments, public resource trading centers, and bidding agencies generate and maintain this data.

## What Constraints Do These Characteristics Impose on the HTTP Interfaces and External Systems Link
Multi-source data platforms require interfaces to adapt to different authentication rules and response formats. This avoids call failures caused by platform differences.
The daily update frequency requires matching interface call rhythm to the data synchronization cycle. This prevents frequent requests from triggering platform rate limits.
Multiple types of business documents need targeted data extraction rule configuration. This ensures core business fields for all document types are accurately identified.
Core field strict verification requires interface returned data to include necessary content such as qualification requirements and bill of quantities. Missing this content will reduce service consultation accuracy.

## How to Configure
This configuration guide is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Use Bearer token format, carry the API key assigned by the platform | Public resource trading platform interfaces generally require identity authentication to prevent unauthorized access |
| `responseData` | Only retain core fields such as basic project information and successful bid results, filter HTML format code | This category of documents includes multiple types of business files, and it is necessary to accurately extract the content required for service consultation |
| `variables` | Bind business variables such as section number and project name, support enumeration value configuration | Service consultation needs to accurately match data for specific projects, to avoid confusion of cross-project data |
| Request timeout setting | 600 seconds | Some local trading platform interfaces respond slowly, too short a timeout will cause normal requests to be mistakenly judged as failed |
| Retry strategy | 2 retries, 30-second interval | Public resource trading platforms may have temporary fluctuations, retries can reduce the failure rate of single requests |
| Returned data volume limit | Top 500 entries | Single documents in this category have large data volume, excessive data will occupy context space and affect consultation efficiency |

## Three Common Misconfigurations
- Symptom: HTTP interface call returns empty fields, and successful bid result information cannot be extracted. Cause: No `responseData` filtering rule is configured for the successful bid result announcement documents of this category, causing redundant HTML format code to occupy valid data space, and core fields are not extracted.
- Symptom: An error occurs when the database-associated workflow executes, and corresponding tender announcement data cannot be queried. Cause: No project number variable is bound in `variables`, causing the SQL statement to not specify specific query conditions and fail to match data for the target project.
- Symptom: Custom tool parameter configuration items are missing, and optional variables cannot be set. Cause: No enumeration value range for optional parameters is declared in `variables`, causing the FastGPT interface to not render the corresponding configuration controls, making it impossible to complete the variable optional setting.

## How to Confirm Configuration Is Successful
- Call the test interface, use the configured `Authorization` token to initiate a request, and check whether the returned result includes the core fields of the business document, with no authentication failure error.
- Bind the project number variable in `variables` to initiate a query, and confirm that the returned data matches the section, qualification requirements and other information of the specified project.
- Trigger an abnormal request, such as modifying `Authorization` to an invalid key, and check whether the configured retry strategy is triggered, or a corresponding alarm record is generated.
- View the `responseData` extraction result, confirm that redundant format code has been filtered, and only retain the core content required for service consultation.
