# Consulting and Response for Engineering Construction Project Bidding: Deployment and Upgrade

## What the data for this category looks like
The data for this category comes from the national public resource trading platform, local public resource trading platforms, engineering approval systems, and bidding supervision systems. The update frequency is daily. Daily processed documents include bidding announcements, qualification pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate announcements, and successful bid result announcements. Data fields include section information, qualification requirements, performance thresholds, bill of quantities, construction period, and more. Some documents include image attachments, and there is no unified standardized format.

## What constraints these characteristics impose on the deployment and upgrade link
Daily updated data requires configuring scheduled incremental synchronization tasks during deployment, to avoid excessive storage and computing resource usage from full pull operations. Multiple data sources require adaptation to the interface authentication rules of different platforms, and corresponding storage and database connection parameters must be configured. Diverse document types include both structured and unstructured content, so dedicated parsing rules must be configured for different document types such as bidding announcements and bid evaluation reports. Fields have strong professional characteristics, so precise matching of specific fields such as qualifications and performance must be ensured during retrieval. A fast rollback mechanism must also be reserved to address risks such as suspended successful bid results.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15` | Adapt to concurrent access demands for bidding consulting, and avoid exhausting database connection pools |
| `REDIS_URL` | `redis://:custom password@host address:6379/0` | Cache retrieval results and session data to improve consulting response speed |
| `STORAGE_S3_ENDPOINT` | `http://minio.example.com:9000` | Connect to local private storage services to store attachments and images of bidding documents |
| `FILE_TOKEN_KEY` | `32-character randomly generated string` | Generate secure access tokens for attachments of bidding documents to prevent unauthorized access |
| `PG_URL` | `postgresql://username:password@host address:5432/engineering bidding database name` | Store structured bidding data to support precise field retrieval |

## Three common mistakes
- Symptom: Images in bidding documents in retrieval results display as empty or expired. Logs show missing image index fields. Cause: The image index update logic supported by FastGPT v4.17.0 is not configured, and attachment data crawled from public resource trading platforms is not synchronized daily.
- Symptom: Locally deployed Qwen3-32B model returns connection errors when calling the MCP MySQL query service. Cause: Correct MCP service access address and authentication parameters are not configured in the locally deployed instance, or local network policies restrict access to database ports.
- Symptom: System timeouts occur when processing concurrent consulting requests, and database connection count exceeds the threshold. Cause: The value of `DB_MAX_LINK` is not set appropriately, causing the connection pool to fail to support concurrent bidding consulting requests.

## How to confirm configurations are complete
- Execute `docker logs fastgpt` to view startup logs, confirm that the storage service configured via `STORAGE_S3_ENDPOINT` connects normally, with no error messages.
- Initiate a consulting request containing qualification requirements or a bill of quantities, check that retrieval results include accurate fragments of the corresponding bidding documents, and that images load normally.
- Manually trigger a daily incremental synchronization task, check the system task execution records, confirm that the synchronization task completes normally with no data omissions.
- Initiate 3–5 concurrent consulting requests, observe that the database connection count stays within the range set by `DB_MAX_LINK`, with no connection error messages.

The values listed are common starting points, and should be evaluated against the reader's own use cases and samples.
