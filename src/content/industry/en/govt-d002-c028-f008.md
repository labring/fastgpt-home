# Service Consultation and Response for Market Entity Registration and Licensing: Document Parsing and Chunking

## What the data for this category looks like
The data for this category comes from the enterprise registration full-process electronic system, the national enterprise credit information publicity system, the electronic business license system, and the residence information database, with a daily update frequency.
Commonly processed documents include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, and food business license applications. Most document structures are fixed form formats or structured text. Some files include table fields covering core fields such as entity name, residence address, shareholder information, and licensing matters. No custom non-standard units are used.

## What constraints these characteristics impose on the document parsing and chunking link
Structured fields in fixed form documents must be split accurately to avoid information confusion caused by cross-field merging.
Daily updated batch data requires the parsing process to have stable batch processing capabilities, to avoid timeout interruptions.
Documents containing tables need to adapt to the chunking logic for table content, to prevent splitting from destroying the associated information of fields within tables.
The uniqueness requirement for structured fields means retaining the binding relationship between fields and their corresponding content during chunking. This ensures subsequent retrieval can accurately match consultation questions.
For license application documents, preconditions and postconditions must retain contextual associations during chunking. This avoids losing the ability to judge conditional logic after splitting.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific parameter settings are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field length of fixed form documents and the context range of consultation questions, avoiding splitting that destroys business logic associations |
| `chunkSplitter` | Split by form paragraphs | Matches the mostly fixed form structure of documents in this category, retaining the integrity of each business paragraph |
| `customPdfParse` | Enable table parsing mode | Adapts to documents containing tables such as business licenses and license applications, accurately extracting structured information within tables |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to batch imports of complete enterprise registration documents, avoiding upload failures caused by oversized files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers the time requirements for batch multi-document parsing, avoiding process interruptions due to parsing timeouts |
| `chunkSettingMode` | Manual configuration | For the fixed form structure of this category, chunking rules can be flexibly adjusted to adapt to different document types |

## Three Common Mistakes
- Symptom: An unsupported file type prompt appears in the interface when uploading Excel format files, or fields are missing after parsing. Cause: The default parsing rules do not adapt to Excel format, and custom parsing configuration is not enabled; only CSV format is supported, and the default limit is two columns of data.
- Symptom: A request error occurs when calling `customPdfParse`, and the log shows a connection failure. Cause: The locally deployed parsing service did not start normally in Docker Desktop, or network access permissions for the corresponding port were not opened.
- Symptom: Retrieval results contain redundant content, and only the original response of the question-and-answer pairs in the knowledge base is not returned. Cause: The chunking rules did not retain the context binding relationship of the question-and-answer pairs, or the `chunkSize` setting exceeded the original length range of the question-and-answer pairs.

## How to Verify the Configuration Is Properly Set Up
- Upload a single Excel format enterprise residence certificate file, and check whether all field information in the table is fully extracted after parsing.
- Run a batch document parsing task, confirm that all pending registration applications, articles of association and other files are parsed within 600 seconds, with no timeout errors.
- Import a preset question-and-answer pair knowledge base, initiate a corresponding consultation question, and check whether the returned results only contain the preset original response content in the knowledge base.
- View the file upload configuration items, confirm that `UPLOAD_FILE_MAX_SIZE` is set to 100 MB, and enterprise registration complete documents exceeding the default limit can be uploaded normally.

The values provided are common starting points and should be measured against the reader's own samples.
