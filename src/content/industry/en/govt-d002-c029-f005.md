# Handling Consultation and Response for Urban Environmental Sanitation and Urban Management Law Enforcement Cases: Tool Calling and Plugins

## What the data for this category looks like
This category's data mainly comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders. The update frequency is daily. Commonly involved documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and case closure reports. Common data fields include case number, violation location, responsible entity, disposal progress, and others. Some entries are associated with unstructured content such as on-site photos. The data structure changes dynamically with the case circulation stage, covering all process links from filing to closure.

## Constraints imposed by these characteristics on the tool calling and plugins workflow
Dispersed data sources and unstructured content require tool calling to support integration with multi-platform APIs for synchronizing case data. It also requires adaptation to image parsing plugins for processing on-site photos. High-frequency daily updates require tool calling trigger intervals to not exceed 24 hours, to avoid data delays. The need to associate full-process case documents requires that plugin calls carry associated fields such as case numbers, to ensure returned results are bound to the corresponding case. The rigor of law enforcement scenarios requires that tool calling return results include traceable source identifiers, to reduce the risk of law enforcement disputes.

## How to Configure the Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the flexible scenario of multi-tool calling for urban management law enforcement cases, supports automatic selection of matching plugins |
| `functionCall` | `enabled` | Supports explicit configuration of dedicated urban management law enforcement plugins, clarifies the calling scope |
| Single tool call timeout duration | `600 seconds` | Case processing involves on-site photo parsing and cross-platform data synchronization, requires sufficient time to complete full-process operations |
| Tool call context retention length | `800–1200 characters` | Matches the typical content length of documents such as inspection records and filing approval forms, avoids context truncation |
| Multi-parameter supplementary trigger rule | Ask one by one for missing fields | Urban management cases require supplementary dynamic parameters such as violation location and responsible entity, need to gradually obtain complete input parameters |
| Tool call result return limit | `Top 3 entries` | Law enforcement scenarios require precisely matched clues, avoid redundant information interfering with case judgment |

## Three Common Misconfigurations
- Symptom: Session context displays blank fragments after tool calling, or subsequent questions cannot associate previous case information. Cause: The context retention logic corresponding to `toolChoice` or `functionCall` is not configured, causing session context to reset during calling.
- Symptom: When calling dedicated urban management case tools, returned results lack the violation type field. Cause: Multi-parameter supplementary trigger rules are not enabled, and necessary case parameters are not actively obtained.
- Symptom: Tool call returns a timeout error, logs show response delay. Cause: Single tool call timeout duration is set too short, unable to complete on-site photo parsing or cross-platform data synchronization.

## How to Confirm Proper Configuration
- Initiate a simulated inspection case consultation, verify whether configured tools automatically trigger corresponding plugins
- Check whether tool call returned results are associated with the current case's number and basic information
- Test scenarios with missing parameters, confirm that the system actively asks for necessary supplementary fields
- View tool call logs, confirm that timeout duration matches business processing rhythm
