# Construction Engineering Quality and Safety Supervision: Service Consultation and Reply - Tool Calling and Plugins

## What data for this category looks like
Core data for the construction engineering quality and safety supervision field comes from the project quality and safety supervision system, construction site real-name platform, supervision logs, and test reports. The update frequency is once per week.
Daily processed documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Each document contains fields such as main entity information, on-site inspection items, rectification requirements, and acceptance verification items. There are no unified fixed units. Some fields need to be linked to on-site measured data.

## What constraints do these characteristics impose on the "tool calling and plugins" link
Dispersed data sources with weekly updates require tool calling to support synchronized pulling from multiple data sources, to avoid incomplete data from a single call.
Diverse document types with closely linked fields require plugins to support matching calling rules by document type, to avoid confusing field logic across different business documents.
The hidden danger rectification closure and completion acceptance verification links rely on real-time data verification. This requires tool calling to have short-cycle data refresh capability, otherwise on-site immediate verification needs cannot be supported.
Data association errors can lead to quality and safety accidents. Plugins must trigger alerts when calls fail, to prevent erroneous data from flowing into the consultation and reply link.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Tool calling trigger rule | Match by document type | Matches the diverse document type characteristic of this category, configure corresponding calling logic for different documents such as supervision plans and rectification notices |
| Data source sync interval | 168 hours (7 days) | Matches the weekly data update frequency, avoid excessive syncing that consumes resources or too slow syncing that causes data lag |
| `toolChoice` parameter configuration | Automatically match tools for corresponding data sources | Based on the dispersed multi-data source characteristic, automatically match calling interfaces for corresponding data sources, reduce manual configuration costs |
| Number of call failure retries | 3 times | Address on-site construction network fluctuations or temporary system failures, avoid terminating the process directly after a single failed call |
| Number of results returned | Top 3 entries | Based on the single-cycle data volume scale, return the most relevant document entries, avoid excessive results interfering with replies |
| Timeout threshold | 600 seconds | Matches the immediacy requirement of on-site verification, avoid overly long waits that affect service consultation response |

## Three common errors
- Phenomenon: Calling the exclusive supervision system interface of the construction quality and safety station returns authentication failure. Reason: The plugin key was not configured according to the exclusive authentication rules of this system, and general authentication parameters were used directly.
- Phenomenon: The number of tool call return results does not match expectations. Reason: The number of results returned was incorrectly set to a value exceeding the single-cycle data volume, resulting in redundant returns or missing key entries.
- Phenomenon: The plugin cannot automatically generate code related to hidden danger rectification tracking. Reason: The field mapping rules for the corresponding document type were not configured, so key information in the hidden danger rectification notice cannot be extracted for code generation.

## How to confirm the configuration is complete
- Manually trigger a tool call for supervision inspection records, verify that the returned document type matches the configured matching rules.
- Simulate a temporary system failure to trigger a call failure, confirm that the plugin executes retries according to the configured number of retries.
- Check the tool call logs in FastGPT v4.17.0, confirm that the `toolChoice` parameter associates with the calling interface of the corresponding data source according to the automatic matching rules.
- Enter consultation related to completion acceptance, verify that the number of returned results meets the configured top 3 entry requirement.
