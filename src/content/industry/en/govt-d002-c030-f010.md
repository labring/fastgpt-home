# Construction Engineering Quality and Safety Supervision: Inquiries, Responses, and Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for this category comes primarily from the engineering quality and safety supervision system, construction site real-name platform, supervision logs, and test reports.
Daily documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports.
Data updates occur weekly. Most documents focus on construction site process management and acceptance steps.
Fields include supervision subject, inspection items, rectification closed-loop status, and acceptance conclusion. No additional custom statistical values are included.

## What constraints these characteristics impose on knowledge base retrieval and recall
Weekly updated data requires matching synchronization cycles for retrieval and recall data sources. This prevents use of expired supervision inspection records or rectification notices.
Mixed structured and semi-structured documents need chunking logic tailored to different document types. This ensures accurate recall of both long texts from supervision logs and short texts from rectification notices.
Inquiries about construction sites often reference specific project on-site status. Prioritize recalling documents linked to the same project, and exclude acceptance report data from other projects.
The hidden danger rectification closed-loop status field needs precise identification. Ensure retrieval results include records for all relevant statuses, such as pending rectification and rectified.

## Three Common Misconfigurations
- Phenomenon: Retrieval results only include text content, and image information within documents is not extracted. Reason: Image OCR and vectorization configuration is not enabled, only plain text from documents is processed.
- Phenomenon: Retrieval returns empty results or prompts that no matching documents are found. Reason: `collectionIds` is not configured correctly, and document collections from non-this-category are bound, leading to incorrect retrieval scope.
- Phenomenon: Context exceeds the carrying limit, and the large language model cannot complete the response. Reason: The `limit` parameter is not set reasonably, too many long text documents are recalled, exceeding the preset context length.

## How to Confirm the Configuration Is Correctly Set
- Upload one typical document of this category, such as a hidden danger rectification notice, initiate a test query matching the keywords of this document, and verify whether the retrieval result includes this document.
- View the document list in the knowledge base, confirm that only category-specific documents such as supervision plans and inspection records are included, with no content from other unrelated categories.
- Initiate a query containing a project name, and verify whether the retrieval result is linked to documents such as the completion acceptance supervision report corresponding to this project.
- After enabling `usingReRank`, check whether the order of retrieval results prioritizes content directly related to the current inquiry project.
