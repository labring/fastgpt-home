# Handling Inquiries and Responses for Construction Engineering Quality and Safety Safety Supervision: Deployment and Upgrade

## What This Category’s Data Looks Like
Core data for this category comes from four sources: engineering quality and safety supervision systems, on-site construction real-name registration platforms, supervision logs, and test reports. Daily processed documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. These cover structures such as plans, inspection records, rectification notices, and acceptance reports.
Data updates occur weekly. Each document’s fields include project number, supervision subject, inspection content, rectification status, and more. There is no unified fixed unit field. Matching must be done dynamically based on document type.

## Constraints for Deployment and Upgrade Processes
The scattered data sources, diverse document structures, and fixed update frequency of this category bring three constraints to deployment and upgrade work.
First, concurrent access demand for multi-source data is high. Configure sufficient database connection pools to avoid access blocking during daily data synchronization.
Second, chunking and indexing requirements vary across different document types. Support flexible vector database import configurations to adapt to documents with different structures, such as supervision plans and rectification notices.
Third, data is directly linked to engineering quality and safety risks. Ensure service stability during deployment. Avoid data index failure or service interruptions caused by configuration errors, as these would disrupt supervision work.

## How to Set Configurations
This document applies to FastGPT v4.17.0. The following are configuration recommendations for this scenario:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://localhost:6379/0` | Adapt to session caching needs for weekly data updates, and ensure stable access tokens for shared links |
| `DB_MAX_LINK` | `20–30` | Meet concurrent synchronization requirements for multi-source data, and avoid exhausting database connections |
| `FILE_TOKEN_KEY` | `3600 seconds` | Match the shared access validity period after on-site materials are uploaded, and adapt to the temporary sharing scenario for supervision documents |
| `STORAGE_S3_ENDPOINT` | `http://localhost:9000` | Adapt to local storage deployment requirements for supervision documents, and reduce external storage costs |
| `FE_DOMAIN` | `https://quality-safety-supervision-inquiry-platform.domain.com` | Clarify the access domain name after deployment, and ensure correct redirection for shared links |

## Three Common Misconfigurations
- When accessing the application via a login-free shared link, the cite original text function fails. The cause is that the valid duration of `FILE_TOKEN_KEY` is not configured correctly, leading to early expiration of access tokens for shared files.
- Redis continues to throw errors and fails to start after one-click deployment via Sealos. The cause is that the deployment script does not automatically adapt to the host's memory limits, leading to Redis processes being terminated by the system due to insufficient memory.
- Configuration fails when attempting to connect a private reranking model. The cause is that the input format of the model is not adjusted according to the field structure of the category data, leading to the model being unable to recognize incoming supervision document content.

## How to Verify Successful Configuration
- Access the configured `FE_DOMAIN` address, confirm that the page loads normally, and that there are no resource loading failure prompts.
- Upload a supervision inspection record document, test the vector import process, and confirm that the document can be properly indexed and retrieved.
- Generate a login-free shared link, click the link, and verify that the cite original text function can open the corresponding document normally.
- Check Redis logs, confirm that there are no connection timeout or out-of-memory error reports, and that the service is running normally.
