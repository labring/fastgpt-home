# Administrative Approval of Environmental Impact Assessment for Construction Projects: Inquiries and Responses via HTTP Interfaces and External Systems

## What this category of data includes
Data for this category primarily comes from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Daily associated documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents.
Data fields include project category, EIA level, pollution prevention measures, public participation status, approval status, and others. There are no unified fixed units. Some fields must match regional requirements of ecological environment zoning control.

## Constraints for HTTP Interfaces and External Systems
Multiple data sources and irregular update cycles require interfaces to support dynamic pulling of structured and unstructured documents from different sources, and adapt to authentication rules of multiple systems.
Diverse document types require interface requests to support uploading and parsing of EIA files in different formats, and verify the validity of core fields such as project category and EIA level.
Severe potential consequences require interfaces to include retry mechanisms and error log retention, to avoid approval process interruptions caused by interface anomalies.
Strict matching of regional fields from ecological environment zoning control is required, to ensure request parameters comply with regional EIA requirements.

## Configuration Guidelines
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Platform token with Bearer prefix, 200–500 characters in length | Complies with external system authentication specifications, reduces token leakage risks |
| `variables` | Pass EIA-specific fields such as project ID and region code | Used to match ecological environment zoning control data for the corresponding region |
| `responseData` | Only return approval status and technical evaluation opinion fields | Reduces data transfer volume, adapts to lightweight calling requirements of external systems |
| Timeout setting | 600 seconds | Adapts to complex calculation time required for EIA approval data verification |
| Retry attempts | First 3 retries with 30-second intervals | Addresses temporary external system fluctuations, avoids process interruptions caused by single request failure |

## Three Common Configuration Errors
- Symptom: Returns `401 Unauthorized` status code when calling the interface, and the `responseData` field is empty. Cause: The `Authorization` parameter was not correctly added to the request header, or the token format does not meet external system requirements.
- Symptom: After an external system passes global variables, the interface cannot match the corresponding EIA project data. Cause: The project unique identifier field was not passed via the `variables` parameter, so the system cannot associate the correct data source.
- Symptom: The interface request returns a large amount of redundant content unrelated to EIA. Cause: The `responseData` setting was not restricted to only return core approval fields, leading to invalid data transmission occupying bandwidth.

## How to Verify Correct Configuration
- A test request is initiated on the FastGPT platform, a valid EIA project ID is passed, and whether the returned `responseData` includes core fields such as approval status is verified.
- Interface call logs are reviewed to confirm that the `Authorization` parameter is correctly included, with no token format errors or missing values.
- A custom `variables` parameter is passed by simulating an external system, and the system’s ability to associate ecological environment zoning control data for the corresponding region is verified.
- Multiple repeated requests are sent, and the interface retry mechanism is confirmed to trigger normally during temporary network fluctuations, with no abnormal error reports.
