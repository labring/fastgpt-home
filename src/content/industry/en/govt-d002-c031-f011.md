# Service Inquiry and Response for Environmental Impact Assessment Approval of Construction Projects: Forms and Interactions

## What this category’s data looks like
Data sources include the national unified declaration and approval system for environmental impact assessment of construction projects, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Daily processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents. Data fields include project category codes, EIA level determination items, pollution control measure lists, public participation feedback records, approval process node identifiers, and more. These are dynamically generated alongside construction project declaration progress, with no fixed single update data volume.

## What constraints these characteristics impose on the forms and interactions link
The data sources cover cross-system linkage, which requires form interactions to support cross-system data pulling and real-time verification. This ensures declaration information matches zoning control results and monitoring data. The irregular update feature requires forms to flexibly adapt to new ecological environment control rules without reconstructing the overall interaction logic. The document structure includes multi-page and multi-attachment professional reports, which requires forms to support segmented upload, attachment association field binding, and provide professional term auxiliary input. The fields include core determination items such as project category and EIA level, which requires pre-compliance verification during interaction to reduce subsequent manual verification time.

## How to configure
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | Group by project declaration fields, no more than 1200 characters per group | Daily processed EIA documents include multiple professional fields. Grouping reduces filling complexity, and 1200 characters adapts to the display width of a single-page form |
| `userSelect` | Provide pre-selected project category options covering 10 major project categories of ecological environment zoning control | Project category is the most time-consuming verification link in EIA approval. Pre-selected options reduce manual determination errors and match the classification standards of existing control rules |
| Single upload attachment limit | 10 per submission | Environmental impact assessment reports usually include multiple supporting attachments. 10 covers conventional declaration needs and avoids overloading single upload |
| Field verification trigger timing | Real-time verification after completion of filling | Core fields such as EIA level determination items require compliance verification in advance to avoid rework after submission and reduce time spent in subsequent approval links |
| Interaction context retention length | First 3 rounds of interaction records | Interactions in service inquiry scenarios usually revolve around specific links of project declaration. Short context improves response accuracy |
| Timeout period | 600 seconds | Interaction responses in service inquiry scenarios need to be completed within a reasonable time frame. 600 seconds adapts to the time required for cross-system data pulling |

## Three common configuration mistakes
- Symptom: After filling all input items in the workflow and running it, the error "Cannot convert undefined or null to object" is displayed. Cause: Form interactions are not configured with required field verification, or no fault tolerance handling is performed when EIA data pulled from cross-systems is empty, causing the workflow node to receive undefined parameters.
- Symptom: Pre-set responses based on project categories cannot be triggered during service inquiries. Cause: The pre-option association logic of `userSelect` is not enabled, or pre-options do not match the current ecological environment zoning control classification standards.
- Symptom: After retrieving EIA-related documents, only a single result is returned for response, and top 2 content cannot be selected. Cause: The return limit of retrieval results is not configured, or retrieval results are not bound to the LLM processing link, causing only a single result to be called.

## How to verify a complete configuration
- Open the form configuration page and verify that the field groups of `formInput` match the official field list for EIA declaration.
- Enable the pre-selected option function of `userSelect` and confirm that pre-selected options cover the currently effective ecological environment zoning control classifications.
- Set up a test project, submit the form and check whether real-time verification is triggered. If there are no abnormal errors, proceed to subsequent processes.
- Initiate more than two rounds of service inquiries and confirm that interaction contexts are retained and associated with subsequent responses.
