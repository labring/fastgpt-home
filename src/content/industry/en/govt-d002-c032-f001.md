# Investment Project Approval and Post-Evaluation Service Consultation and Response: HTTP Interfaces and External Systems

## What data for this category looks like
Data sources include state-owned assets supervision and administration commission investment supervision systems, enterprise ERP and project management systems, industry market data, and audit and financial statements. The update cycle is quarterly. Daily processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data fields include project identifiers, investment amounts, project initiation approval nodes, investment review committee opinions, post-evaluation indicators, and more. Units include currency units, project cycles, score ranges, and more. The data structure must comply with standardized requirements for state-owned asset supervision.

This document is written for FastGPT v4.17.0.

## Constraints imposed by these characteristics on HTTP interfaces and external systems
Data sources are scattered across multiple external systems. Interfaces must support multi-source authentication and data pull adaptation, and be compatible with parameter formats of different systems. The quarterly update frequency means the trigger interval for batch interface synchronization must match the business rhythm, to avoid invalid calls consuming system resources. Metadata for multiple document types varies. Interface parameters must have field mapping capabilities to unify data formats from different sources. Risks related to state-owned asset business require interfaces to be configured with strict access verification and operation log recording, to ensure data security and traceability.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | Configure Bearer Token or API key per external system requirements | Comply with standard authentication requirements of state-owned asset supervision systems, to ensure interface access security |
| Single pull count | Top 100 entries | Match the total quarterly updated project data volume, balance call efficiency and transmission overhead |
| Timeout period | 600 seconds | Adapt to interface response requirements for large feasibility study reports and post-investment evaluation reports |
| `responseData` | Return only core fields such as project number, project initiation status, post-evaluation score, etc. | Reduce data transmission overhead, focus on core information for business consultation |
| Document chunk length | 800–1200 characters | Adapt to the content length of investment project-related documents, optimize vector recall performance |
| `variables` | Pass business identifiers such as project industry, supervision level, etc. | Enable scenario-based adaptation of interface requests, match consultation requirements of different entities |

## Three common mistakes
- Phenomenon: The interface returns a `401 Unauthorized` status code, with empty return fields. Cause: The `Authorization` parameter is not configured correctly, and the authentication rules of the state-owned asset system are not adapted, resulting in access being blocked.
- Phenomenon: Conversation records created via the API cannot be filtered by user dimension, or only conversation data created on the page can be viewed. Cause: The user unique identifier is not passed in the `variables` parameter, and user isolation configuration for conversation data is not enabled, resulting in data confusion.
- Phenomenon: The number of results returned after interface calls does not match the actual synchronized data. Cause: The single pull count configuration is unreasonable, pagination logic is not handled, or the quarterly updated data volume is not matched, resulting in partial data not being pulled.

## How to confirm configuration is complete
- Call the interface with a valid `Authorization` credential, check that the return status code is 200 OK, confirm that the authentication configuration is effective.
- Compare the core fields returned by the interface with the actual data of the external system, confirm that the field mapping is correct, with no missing or incorrect fields.
- Pass different `variables` business identifier parameters, confirm that the interface returns results matching the business requirements of the corresponding scenario.
- Simulate long document upload or batch pull scenarios, check that the interface response time does not exceed the configured timeout period, confirm that content processing is normal.
