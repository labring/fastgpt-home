# Bidding and Procurement Compliance Management Service Consultation and Reply: Document Parsing and Chunking

## What this category of data looks like
Data sources for this category include central SOE procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases, with a daily update frequency. Daily processed documents cover procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials. Documents include fields such as procurement method, budget amount, scoring rules, supplier qualification requirements, and performance clauses, and involve standardized units like amount, time, and project number. Some materials contain multi-page attachments and table content.

## What constraints these characteristics impose on the document parsing and chunking workflow
Daily updated multi-source data requires parsing tools to support rapid batch processing, to prevent delays from disrupting compliance review timelines. Mixed document types with tables and attachments require parsing modules to identify structured tables and nested content, to avoid splitting related information during chunking. Significant field variations across documents require chunking logic to preserve contextual connections. For example, the scoring method of a bidding document must be stored in the same chunk as the corresponding supplier qualification requirements, to support subsequent compliance verification. Some documents involve sensitive compliance content, so original field identifiers must be retained during parsing to avoid information loss that would hinder audit traceability.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of bidding and procurement documents, retains contextual integrity of core associated fields such as procurement method, budget, and scoring rules |
| `chunkSplitter` | Split by title + paragraph | Matches the hierarchical structure of documents such as bidding documents and bid evaluation records, avoids splitting compliance clauses from different chapters into different chunks |
| `customPdfParse` | Enabled | Supports parsing tables and embedded attachments in PDF-format bidding documents and bid evaluation reports, restores structured content |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Accommodates multiple procurement documents uploaded in a single batch, adapts to the batch processing needs of central SOE centralized procurement |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for large bidding documents or multi-page bid evaluation records, avoids parsing failure due to timeout |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types (such as contracts and complaint materials), adapts to compliance verification logic for each scenario |

## Three common mistakes
- After uploading an Excel-format supplier database file, the table fields in the parsing result are empty. Cause: The structured table parsing configuration is not enabled, and the default parsing logic cannot recognize the cell association relationship in Excel.
- When using the qwen14b 32k model in a local deployment version, uploading a bidding document results in a request failure message after more than 2 minutes. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default timeout duration is insufficient to handle the parsing process of large bidding documents.
- After batch uploading multiple bid evaluation records, the chunking result splits scoring records from different judges into the same chunk. Cause: `chunkSplitter` is configured to split by fixed characters, and does not match the judge grouping titles in the document, resulting in broken contextual association.

## How to verify correct configuration
- Use the FastGPT v4.17.0 platform, upload a standard PDF-format bidding document, and confirm that the parsed text retains the association between chapter titles and corresponding paragraphs to verify the `chunkSplitter` configuration.
- Upload an Excel-format procurement plan table, and confirm that the parsing result fully extracts fields such as budget amount and procurement method to verify that the structured parsing configuration is active.
- Upload a bidding document larger than 200 MB, and confirm that the parsing process completes within the preset timeout duration to verify the rationality of the `PARSE_FILE_TIMEOUT_SECONDS` configuration.
- Batch upload three or more supplier complaint materials, and confirm that the chunking result is split by dimensions such as complaint reasons and evidence materials to verify the manual configuration effect of `chunkSettingMode`.
