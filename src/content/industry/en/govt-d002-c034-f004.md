# Enrollment and Student Status Management Inquiry and Response: Workflow Orchestration

## What this category of data looks like
This category of data includes standardized documents such as enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources are the national primary and secondary school student status information management system, local enrollment platforms, household registration and real estate data platforms, and school academic affairs systems, with daily updates. Core data fields include student identity identifiers, household registration and real estate information, student status status, and enrollment plan quotas. There are no additional financial-related fields, and the document structure is fixed and must match the format requirements of official systems.

## What constraints do these characteristics impose on workflow orchestration
This category of data is updated daily. The workflow must be configured with scheduled trigger rules for synchronizing data sources to avoid information lag caused by using static cached data. Multiple types of official standardized documents serve as inputs. The workflow must include field verification nodes to check the completeness and format compliance of core fields such as student identity and household registration and real estate information. Multi-source data connection requirements mean the workflow must support cross-system data pulling and associated matching. Exception interception nodes must also be configured to prevent serious errors such as duplicate or missing student status records and admission disputes.

## How to set configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single search limit | Top 5 entries | Matches the high-frequency question count for enrollment inquiries, avoids returning excessive redundant student status or enrollment information |
| Maximum context | 800–1200 characters | Adapts to the single-item content length of student status and enrollment documents, prevents context overflow |
| `variables` | Bind student ID number and enrollment year as global variables | Used to dynamically call corresponding student status system and enrollment plan data, adapting to different batch inquiry scenarios |
| Node timeout | 600 seconds | Adapts to the time required for cross-system verification of household registration and student status data, prevents workflow interruption due to slow system responses |
| Question optimization | Calibrated based on actual testing | Optimize queries for professional terms such as enrollment policies and student status changes, improving knowledge base recall accuracy |

## Three Common Mistakes
- Symptom: After deploying with docker-compose, workflow node configurations and knowledge base lists are cleared unexpectedly, but interface calls still return results normally. Cause: No data persistence mount directory is configured, and locally cached configurations and knowledge base metadata are lost after container restart.
- Symptom: When trying to reference global variables in a knowledge base search node, the corresponding knowledge base index content cannot be matched correctly. Cause: The variable is not bound to the workflow global context, or the variable format does not match the knowledge base index field rules.
- Symptom: The workflow only supports single-round questions and cannot implement multi-round questioning and follow-up inquiries. Cause: No multi-round conversation storage node is configured, and user historical inquiry content is not included in the workflow context.

## How to Confirm Proper Configuration
- Trigger the workflow test node, input simulated data from a standard enrollment application form, and verify whether the field verification node intercepts fields with incorrect formats.
- Call the global variables bound by `variables`, confirm that the workflow can dynamically pull student status data for the corresponding enrollment year.
- View the workflow logs, confirm that the response duration of the cross-system data pulling node does not exceed the configured timeout threshold.
- Trigger multi-round simulated inquiries, confirm that the workflow can retain historical context and conduct follow-up inquiries.
