# Enrollment and Student Status Management Inquiry and Response: Document Parsing and Chunking

## What the data for this category looks like
Typical entities include education bureau basic education departments, school academic affairs offices, enrollment examination institutions, and street community collaborative windows. Daily processed documents include enrollment registration forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources cover the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. The update frequency is daily. Documents contain both structured fields such as student name, student ID number, household registration address, and property certificate number, as well as unstructured enrollment policy interpretation text.

## What constraints do these characteristics impose on the "document parsing and chunking" link
Multi-source data access requires the parsing module to support importing documents in multiple formats, adapting to file types exported by different systems. The daily update frequency requires chunking logic to quickly process frequently added student status and enrollment documents to avoid data lag. Documents contain both structured fields and unstructured policy text, so chunking rules must balance the accuracy of field extraction and the integrity of semantic units, avoiding splitting that breaks business logic. Additionally, business errors directly affect students' enrollment and student status rights and interests, so the parsing link must have no obvious field omissions or recognition errors.

## How to set the configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Enrollment documents contain structured form fields and policy text. This range balances semantic integrity and retrieval accuracy |
| `chunkSplitter` | Split by paragraph + title | Enrollment documents have clear policy clauses, form titles, and student record groups. This splitting rule preserves complete semantic units |
| `customPdfParse` | Enable structured parsing mode | Documents contain structured fields such as student ID numbers and property certificate numbers. This mode improves field extraction accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | A single batch admission roster may contain hundreds of student records, requiring sufficient time to complete full parsing |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Bulk imported student status archive packages have large file sizes. This setting adapts to upload requirements for bulk business scenarios |
| `chunkSettingMode` | Manual configuration | Chunking parameters need to be adjusted separately for structured forms and policy text to adapt to the mixed document type of this category |

## Three Common Mistakes
- Phenomenon: The system prompts that the format is not supported when uploading Excel files, and only the first two columns of data are recognized when importing CSV files. Cause: Custom file parsing configuration is not enabled, and the default parsing rules do not adapt to multi-column structured student status forms.
- Phenomenon: A request error occurs when calling marker-pdf parsing, and a connection failure prompt appears when trying to deploy locally at 127.0.0.1. Cause: The port of the local parsing service is not properly exposed during Docker deployment, resulting in failed connection establishment.
- Phenomenon: The generated response does not strictly match the preset question-and-answer pair text in the knowledge base, and additional generated content appears. Cause: `trainingType` is not set to the question-and-answer pair matching mode, resulting in generative responses deviating from preset content.

## How to Confirm the Configuration is Complete
- Upload a single Excel enrollment registration form, check that the parsed result fields are complete, with no misalignment or omissions.
- View the parsing task log, confirm that the parsing time does not exceed the configured `PARSE_FILE_TIMEOUT_SECONDS` value, and no timeout errors occur.
- Import preset enrollment policy question-and-answer pairs, initiate relevant inquiries, and check that the returned content strictly matches the preset response text.
- Upload a batch of student status archive packages, confirm that the upload size does not exceed the `UPLOAD_FILE_MAX_SIZE` limit, and no upload failure prompts appear.
