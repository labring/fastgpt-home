# Enrollment and Student Status Management: Service Consultation and Response - Knowledge Base Retrieval and Recall

## What the data for this category looks like
Core data for this category originates from the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems.
Updates occur on a daily basis.
Commonly processed documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms.
Data fields center on student identity, household registration and property information, student status status, enrollment quotas, and eligibility qualifications.
The basic education division of the education bureau, school academic affairs offices, enrollment examination institutions, and street community service windows perform collaborative maintenance and updates.

## Constraints on knowledge base retrieval and recall
Daily updated data requires the retrieval link to support near-real-time data synchronization. This prevents expired student status or enrollment information from being recalled.
Multi-source heterogeneous data sources require retrieval to support cross-system data association and matching. This ensures consistency for core fields such as student identity and household registration and property information.
Diverse document structures require chunking and encoding to account for differences between structured forms, text rosters, and approval forms. This avoids critical information breaks caused by improper chunking.
Business logic centered on student eligibility requires retrieval to prioritize matching identity-related fields. This prevents irrelevant information from being recalled.
It also ensures the accuracy of recalled results, avoiding issues such as duplicate student status records or admission disputes.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | High precision is required for student status and enrollment data fields. A threshold that is too low introduces irrelevant results. A threshold that is too high may miss valid information. This value is calibrated based on actual testing. |
| `limit` | Top 6 entries | The number of single retrieval results must be controlled within a reasonable range. This prevents context overflow from affecting response logic, while covering core relevant information. |
| `usingReRank` | Enabled | Multi-source heterogeneous document structures lead to uneven relevance in initial retrieval results. Reranking optimizes sorting logic and improves the accuracy of consultation responses. |
| `datasetSearchUsingExtensionQuery` | Enabled | Enrollment policies and student status rules have fixed synonymous expressions. Extended queries cover more synonymous phrasing from user questions, improving recall coverage. |
| `collectionIds` | Corresponding dataset IDs for enrollment and student status management | Limit retrieval scope to avoid recalling irrelevant logistics or funding data, and focus on core business data for this category. |

## Three Common Misconfigurations
- Images in retrieval results fail to display properly. Symptoms: Image areas are blank or show loading failures in returned consultation results. Cause: Only image files were uploaded during knowledge base import, and no publicly accessible external link address was configured. This prevents resources from loading after retrieval and recall.
- The `similarity` score returned by semantic retrieval is abnormally high. Symptoms: Similarity scores are generally above 0.9, and irrelevant results are also recalled. Cause: The vector encoding logic was not adjusted for structured fields related to student status and enrollment. This leads to excessive weighting of critical identity-related features.
- The retrieval interface call returns a permission error. Symptoms: The interface returns an error message indicating insufficient permissions. Cause: The `collectionIds` parameter was not specified correctly, or the configured dataset did not have retrieval permissions enabled. This prevents access to the target knowledge base data.

## How to Confirm Correct Configuration
- Submit a test query, such as "What materials are required for a school transfer". Check that recalled results include valid fragments from documents related to enrollment plans and transfer applications.
- View the `similarity` scores of retrieval results. Confirm that scores fall within the preset 0.75–0.85 range, with no abnormally high or low values.
- Test a consultation query that includes images, such as "2024 enrollment application form template". Confirm that associated images in results load properly.
- Call the FastGPT v4.17.0 retrieval interface with test parameters. Check that the number of returned results matches the `limit` configuration of top 6 entries, with no excess or insufficient results.
