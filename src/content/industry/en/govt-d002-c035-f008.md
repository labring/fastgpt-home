# Pollutant Discharge Permit Management: Service Consultation and Response - Document Parsing and Chunking

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
Daily documents for this category include pollutant discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data sources include the national pollutant discharge permit management information platform, corporate environmental protection ledgers, online monitoring systems, and environmental statistics systems. Most documents are multi-page formats, containing fields such as tabular permit limits, emission boundary parameters, and monitoring data. The update frequency is quarterly. The core of the data revolves around post-commissioning emission control and post-permit supervision, and does not include pre-project approval content related to environmental impact assessment.

## What constraints do these characteristics impose on the "document parsing and chunking" link
Batch documents updated quarterly require stable parsing efficiency. Multi-page formats with tables require parsing tools to retain table structures and field associations. Heterogeneous data from multiple systems may have format differences, so business context associations must be retained during chunking. The accuracy of core fields such as permit limits and emission boundaries directly affects subsequent audits, so chunking must avoid splitting key information. The length of different documents varies greatly, ranging from a few pages of change applications to dozens of pages of annual implementation reports, so different chunking rules must be adapted to prevent key control content from being split.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Pollutant discharge permit documents contain a large number of tables and numerical fields. A chunk size of 800-1200 characters can retain the complete context of a single control rule or monitoring data set |
| `chunkSplitter` | By paragraph + title anchor | Documents contain multi-chapter structures such as application forms and implementation reports. Splitting by title can avoid confusion of control content across chapters |
| `customPdfParse` | Enabled | Most pollutant discharge permit documents are PDFs with digital signatures. Enabling custom parsing can retain table structures and field associations, and avoid content loss |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Annual implementation reports may contain multi-page monitoring data attachments, which need to adapt to the demand for batch upload of large files |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Parsing large-volume implementation reports requires a long time. 600 seconds can cover the parsing process of most documents |
| `chunkSettingMode` | Manual configuration | The chunking requirements vary greatly for different types of pollutant discharge permit documents (such as change applications and annual reports). Manual configuration allows flexible adjustment of parameters |

## Three common mistakes
- Phenomenon: An error is returned when calling the Doc2x tool, with an error prompt containing `Only support .txt, .m` and similar messages. Cause: The `customPdfParse` configuration is not enabled, or the uploaded document format exceeds the support range of the basic parsing tool.
- Phenomenon: After uploading a pollutant discharge permit PDF with a digital signature, valid business content cannot be recognized. Cause: The custom PDF parsing function is not enabled, and the basic parsing tool cannot process document formats with digital signatures.
- Phenomenon: The API knowledge base returns a document reading link, but an access error occurs after clicking, or the parsed document content does not include image information. Cause: File access permission rules are not configured correctly, or the associated context of images is not retained during parsing.

## How to confirm the configuration is correct
- Upload a signed pollutant discharge permit implementation report PDF, and check whether the parsed result includes tables and core control fields.
- Upload a single document whose volume meets the configured upper limit, and confirm that the parsing process does not trigger a timeout error.
- Test different types of pollutant discharge permit documents (such as change applications and annual implementation reports), and confirm that key business content is not split after chunking.
- Call the Doc2x tool to upload a test document, and confirm that the returned result has no format errors.
