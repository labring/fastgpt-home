# Pollutant Discharge Permit Management: Service Consultation and Reply - Model Access and Configuration

## What the data for this category looks like
Core documents for this category include pollutant discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data is sourced from the National Pollutant Discharge Permit Management Information Platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems, with a quarterly update frequency. A single document typically contains structured fields and unstructured text such as industry technical specifications, permit limits, monitoring data, emission boundaries, and more. Fields must match the production process and emission type of the pollutant discharge unit. There is no unified fixed format, but content must comply with supervision specifications issued by the ecological environment department.

## Constraints imposed by these characteristics on model access and configuration
Decentralized data sources that include both structured and unstructured content require adaptation to format requirements for multi-source data access, to prevent deviations in regulatory replies caused by field mismatches. The quarterly update feature requires model context to support regularly refreshed regulatory data, avoiding use of expired permit limits or ledger information. Document length varies widely; long-text implementation reports and ledger records require processing segmentation and context truncation during the access phase to ensure key regulatory information is not lost. Many industry-specific terms and emission-related fields must be accurately identified during model calls to prevent misjudgment of permit boundaries.

## Three common configuration mistakes
-  Phenomenon: After accessing via HTTP API, the returned long-text implementation report cannot be segmented, causing a single request to exceed the context limit. Cause: No reasonable text segmentation rule configured for pollutant discharge permit-related long documents, and content not split according to regulatory field boundaries.
-  Phenomenon: The content extraction node cannot call the self-built model interface, with no response even after configuring `toolChoice` and `functionCall` related parameters. Cause: Tool call permission not enabled in the FastGPT node configuration, or parameter configuration format does not meet node requirements.
-  Phenomenon: When attempting to create a knowledge base using a locally deployed ChatGLM2 model, the corresponding option does not appear in the model list. Cause: The model access address and key configured in OneAPI were not correctly entered into the FastGPT `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters.

## How to confirm correct configuration
-  Upload a single pollutant discharge permit implementation report, test whether the reply returned after model calls includes the latest permit limits and monitoring data, and verify that parameter configuration adapts to document length.
-  Trigger a tool call test, confirm that the model can automatically obtain the latest data from the National Pollutant Discharge Permit Management Information Platform, and verify that the `toolChoice` configuration takes effect.
-  View model access logs, confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters have no format errors, and there are no connection timeout prompts.
-  Adjust the `temperature` parameter, observe changes in the rigor of reply content, and confirm that the parameter value meets regulatory scenario requirements.
