# Administrative Service Item Catalog and Service Guide Maintenance: Inquiry and Response Workflow Orchestration

## What this type of data looks like
Data is typically maintained by bodies including administrative reform offices, government service data management bureaus, and departmental approval divisions. Daily documents include the basic catalog of administrative service items, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions.
Data sources include the national basic catalog of administrative service items, administrative licensing item list, power and responsibility list, and local administrative service item databases. Update frequency is once per month.
Core fields include item name, acceptance conditions, application materials, and handling process. A single service guide document usually contains multiple sections of structured content.

## How These Characteristics Impact Workflow Orchestration
Data sources span national and local levels, with a fixed update schedule. Configure a regular synchronization node to automatically pull the latest national and local government catalog data. This ensures locally maintained catalogs align with superior requirements.
Daily documents include multiple types of structured fields. Embed a field verification link in the workflow. Check the completeness and compliance of core fields such as acceptance conditions, application materials, and handling processes one by one.
Maintenance errors may cause inconsistent service standards between online and offline channels. Configure a failure alert node to trigger notifications when verification fails or data comparison anomalies occur.
Single service guide documents vary widely in length. Support dynamic adjustment of the context range for content processing in the workflow. This avoids truncating critical information.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Pass externally specified government service item knowledge base ID | Government service items in different regions are stored in separate databases by region. An external API dynamically specifies the knowledge base to query |
| Knowledge base search threshold | 0.75–0.85 | Government service item terminology is highly specialized. This threshold range balances recall accuracy and coverage |
| Single recall count | Top 8 entries | The number of government service items is moderate. Excessive recall increases subsequent verification workload |
| Text extraction context | 800–1200 characters | The average length of a single paragraph in service guide documents falls within this range. This fully extracts core information for a single item |
| Workflow timeout | 600 seconds | The average time spent on data comparison, field verification, and other links is within 10 minutes |
| `nodeId` | Bind the preset field verification node ID | Workflow node orchestration is fixed. The verification link must trigger accurately after data pulling |

## Three Common Configuration Errors
- After initiating an API call with the `variables` parameter, the workflow returns a "knowledge base does not exist" error. The cause is failure to correctly bind the externally passed variable to the knowledge base search node configuration.
- The text extraction node prompts "extracted content is empty". The cause is failure to configure an AI model prompt that matches the structured characteristics of government documents. The model cannot recognize fixed fields such as acceptance conditions and application materials in service guides.
- The database query node returns an empty result. The cause is failure to correctly configure the government service item database connection parameters, or failure to set query conditions that match the input item name.

## How to Verify a Successful Configuration
- Initiate an API call with the specified government service item knowledge base ID. Check if the workflow log shows a call to the corresponding knowledge base for content retrieval.
- Upload a standard service guide document. Confirm the text extraction node correctly extracts core structured fields such as acceptance conditions and application materials.
- Trigger the database query node, enter a known government service item name, and verify matching entries return from the government service item database.
- Simulate a timeout scenario, set the workflow execution time to exceed 600 seconds, and check if the preset failure alert notification triggers.
