# Administrative Service Item Catalog & Service Guide Maintenance: Inquiry and Response - Tool Calling and Plugins

## What the data for this category looks like
The maintenance entities for this category are typically departments such as the administrative review and reform office and the government service data administration bureau. The national basic catalog of government service items, administrative licensing item list, and local government service item databases provide core data. The update cycle is monthly. Organizations maintain daily documents including the basic catalog of government service items, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. The document structure uses items as its core unit, including standardized fields such as item name, acceptance conditions, and application material list. There are no custom non-standard fields.

## What constraints these characteristics impose on the tool calling and plugins workflow
The official nature of the data source requires that tool calls must strictly connect to compliant government data interfaces, and non-official data sources cannot be used. The monthly update cycle requires that the caching strategy for tool calls must match the update cycle to avoid returning expired item information. The standardized document fields require that parameter mapping for tool calls must strictly correspond to preset fields, and custom mapping rules cannot be used arbitrarily. Additionally, the most time-consuming comparison and verification links in this category require tool calls to support batch processing of multiple catalogs and lists to reduce manual repetitive operations.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | This category requires automatic calling of government data interfaces to complete field verification and comparison, without manually specifying custom tool functions |
| `functionCall` | `Disabled` | This category only requires calling official government data interfaces, and there is no need to enable custom function call functionality |
| Cache Cycle | `25–35 days` | Matches the monthly update rhythm of this category to avoid cache expiration or use of old data |
| Batch Processing Limit | `Top 200 items` | Adapts to the single-processing scale of government service item catalogs, avoiding overload of interface requests |
| Timeout Duration | `600 seconds` | Government data interfaces typically respond slowly, reserve sufficient request processing time |

## Three Common Misconfigurations
- Symptom: Calling a government data interface triggers a "Failed to fetch" error. Cause: The required timeout time for the government data interface is not configured, or the interface address lacks whitelist permission from the official government service platform.
- Symptom: Performing multimodal analysis on service guide images returns empty results. Cause: No cache path for image downloads is configured, or network permission restrictions prevent pulling image resources.
- Symptom: Batch processing items returns only partial verification results. Cause: A reasonable batch processing limit is not set, exceeding the maximum data volume limit of a single interface request.

## How to Verify Proper Configuration
- Initiate a single item verification request, and check that the returned results are consistent with the fields of local government service item data.
- View the tool call log to confirm that the `toolChoice` parameter is `auto` and that `functionCall` is not triggered.
- Simulate a monthly update scenario to verify that requests within the cache cycle do not return expired data.
- Initiate a batch processing request, and check that the number of returned results matches the set batch processing limit.

These provided values are common starting points and should be evaluated against local deployment samples.
