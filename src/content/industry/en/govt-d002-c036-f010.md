# Administrative Service Item Catalog and Service Guide Maintenance: Inquiry and Response - Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data typically comes from the national basic catalog of government service items, administrative licensing item list, and local government service item databases, with a monthly update frequency. Daily maintained documents include the basic catalog of government service items, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. Each document focuses on a single government service item, containing fixed fields such as item code, item name, acceptance conditions, application material list, and handling process. The data exists in a mixed format of structured entries and unstructured text.

## Constraints for Knowledge Base Retrieval and Recall
The data sources for this category are scattered and updated monthly. The knowledge base retrieval link must support periodic full synchronization or incremental synchronization of data sources to avoid retrieving outdated item data. Each document is structured around fixed fields, so retrieval must accurately match core fields related to the item such as acceptance conditions and application materials, rather than relying solely on full-text fuzzy matching. The mixed structure of structured and unstructured text documents requires retrieval and recall to balance precise field matching and semantic association, to avoid missing key business information. Additionally, the data volume per item is relatively fixed but the total number of entries is large, so the number of results retrieved in a single call must be controlled to avoid exceeding the context window.

## Configuration Recommendations
The following configurations are based on the knowledge base retrieval logic of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Core field matching requirements for government service items are high. This range filters low-relevance non-item content while retaining matching results for the same item with different phrasing |
| `limit` | Top 10 entries | Retrieving too many entries in a single batch will exceed the context window, while retrieving too few may miss key acceptance conditions or material information. 10 entries aligns with the typical range of associated document counts for standard items |
| `searchMode` | vectorSearch | For mixed structured and unstructured government service item documents, vector search balances semantic matching and field association, adapting to multi-field business retrieval needs |
| `usingReRank` | Enabled | Retrieval results for government service items must be sorted by business relevance. Reranking corrects ranking biases from initial vector search, ensuring core item content is returned first |
| `datasetSearchUsingExtensionQuery` | Enabled | This setting can expand queries to cover alias or common names of items, enabling matching with more comprehensive government service item data |
| `collectionIds` | Bind the collection ID of the corresponding government service item knowledge base | Ensures retrieval is limited to the knowledge base of maintained administrative service item catalogs and service guides, preventing documents from other categories from being included |

## Three Common Configuration Errors
- Phenomenon: Retrieval results do not return the top-ranked government service item guide content from the knowledge base. Cause: The `usingReRank` configuration is not enabled, and the ranking from the initial vector search is not corrected based on business relevance, causing non-core content to be displayed first.
- Phenomenon: Knowledge base retrieval returns outdated item data. Cause: No monthly scheduled data source synchronization task is configured, so the retrieved catalogs and implementation lists are not updated to the latest version.
- Phenomenon: Generated responses reference knowledge base content that does not match the item fields in the user's inquiry, with incorrect acceptance condition descriptions. Cause: No workflow is configured to perform field validation on retrieved knowledge base content, allowing incorrect content to be included in the response context.

## How to Verify Proper Configuration
- View the knowledge base synchronization log to confirm that the monthly automatic synchronization task has executed normally, and the data source update time matches the official release time.
- Initiate a retrieval test for a specific government service item, and verify that the returned results are sorted according to business core priorities, with core item content displayed first.
- Test the extended query function by entering common names or aliases of items, and confirm that the retrieval results match the corresponding official item entries.
- Check the knowledge base retrieval prompt configuration to confirm that Chinese is used, in compliance with business specifications for government affairs inquiries.

The values provided here are common starting points and should be measured against the reader's own samples.
