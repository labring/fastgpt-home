# Administrative Service Item Catalog and Service Guide Maintenance: Inquiry and Response - Forms and Interactions

## What the data for this category looks like
Core documents for this category include the basic catalog of administrative service items, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions.
Data comes from the national basic catalog of administrative service items, administrative licensing item list, power and responsibility list, and local administrative service item databases. The standard update frequency is once per month.
Documents are organized by item classification hierarchy. They include fixed fields such as acceptance conditions, application materials, and processing procedures.
All fields must strictly match standard specifications issued by superior authorities. No custom redundant fields are allowed. All content must stay consistent with the superior catalog.

## Constraints for forms and interactions
Since data updates usually once per month, and requires field consistency checks across multiple hierarchical documents, the forms and interactions stage must support bulk import and bulk editing. This cuts down on errors from manual single entries.
All fields must strictly match standard specifications from superior authorities. Forms must include built-in field validation rules to ensure no missing core fields like acceptance conditions or application materials, and eliminate terminology deviations.
Administrative service item classifications are fixed. Interaction components must support preset options by classification. This reduces arbitrary manual input and avoids inconsistent service standards between online and offline channels.

## Three common misconfigurations
- Form input components cannot pass preset variables, and submitted service guide fields do not match the standard catalog. The cause is failing to correctly configure the variable mapping rules of `formInput`, and not mapping form fields to the standard field library for administrative service items.
- Form input boxes do not support file upload, and supporting attachments for standard material catalogs cannot be submitted. The cause is failing to enable the file upload function of `formInput`, and not configuring allowed file types and maximum file size limits.
- The page only supports selecting a single vector model, and cannot configure corresponding vector libraries for multiple sets of administrative service item data, only allowing retrieval using a fixed knowledge base. The cause is failing to configure `userSelect` to bind different vector models and knowledge bases by item classification.
