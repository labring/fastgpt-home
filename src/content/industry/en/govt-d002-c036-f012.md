# Administrative Service Item Catalog and Service Guide Maintenance: Service Consultation and Reply — Deployment and Upgrade

## What the Data for This Category Looks Like
Core data for this category comes from the national basic catalog of government service items, administrative licensing item list, power and responsibility list, and local government service item databases.
Update frequency is monthly.
Daily maintained documents include the basic catalog of government service items, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions.
Core fields cover item names, acceptance conditions, application materials, service processes, and more.
Some documents require linking to standardized format templates and verification rules.

## Constraints for Deployment and Upgrade
Monthly batch updates require deployment environments to support incremental synchronization and breakpoint resume. This prevents excessive resource usage from full synchronization.
Multi-source data sources require configuring multi-source data verification rules during deployment. This ensures consistency between the local catalog and superior standards.
Complex document structures and fields require presetting field integrity verification logic during deployment. This prevents maintenance errors caused by non-standard formats.
Government service compliance requirements mandate that upgrade processes support fast rollback. This ensures business continuity for service consultation and reply.
This configuration solution is adapted for FastGPT v4.17.0.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:password@mongodb-host:27017/gov_service?authSource=admin` | Stores structured data such as administrative service item catalogs and service guides, plus unstructured attachments |
| `REDIS_URL` | `redis://:redis-password@redis-host:6379/0` | Caches frequently queried item fields and verification rules to reduce database concurrency pressure |
| `DB_MAX_LINK` | `100–150` | Adapts to concurrent database connection requests during monthly batch updates, preventing connection exhaustion |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit hexadecimal string | Encrypts download tokens for service guide attachments, blocking unauthorized access to sensitive materials |
| `STORAGE_S3_ENDPOINT` | Official access address of government cloud object storage services | Stores large files including standardized flowcharts and material templates |

## Three Common Configuration Mistakes
- Issue: Dependency version compatibility errors occur during non-Docker deployment. The cause is failure to match the official basic dependency versions of the government service cloud environment.
- Issue: The current deployed code version number cannot be viewed after a version upgrade. The cause is failure to retain the version identification file in the original deployment directory.
- Issue: Connection timeouts occur during batch synchronization of superior government service catalog data. The cause is failure to adjust the `DB_MAX_LINK` parameter to adapt to batch update concurrent requests.

## How to Verify Successful Configuration
- Run the database connectivity test script to confirm that connections for `MONGODB_URI` and `REDIS_URL` are working properly.
- Upload a test service guide attachment to confirm that download links generated via `FILE_TOKEN_KEY` can be accessed normally, with no permission leaks.
- Initiate a small-scale item catalog synchronization task to confirm that database connection counts do not exceed the `DB_MAX_LINK` set value.
- View the government cloud storage bucket to confirm that files such as flowcharts and material templates have been successfully uploaded to the path specified by `STORAGE_S3_ENDPOINT`.

The values provided are common starting points and should be evaluated against local deployment samples.
