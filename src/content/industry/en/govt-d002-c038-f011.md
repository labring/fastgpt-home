# Government Procurement Project Service Consultation and Reply: Forms and Interactions

## What this category of data looks like
Data sources for this category include the China Government Procurement Network, local government procurement networks, fiscal integration systems, procurer budget systems, and supplier credit records. The update frequency is daily. Daily documents cover procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and responses to inquiries. Four typical entities are involved: procurer units, government procurement supervision departments of finance departments, procurement agencies, and evaluation experts. Fields include project number, procurement content, budget amount, supplier qualifications, inquiry matters, and more. Strict compliance with relevant government procurement regulatory requirements must be followed.

## Constraints on forms and interactions
Scattered data sources with daily updates require form interactions to support real-time pulling of multi-source compliant data. This prevents compliance issues caused by manually entering outdated information. Diverse document types and significant field differences require adaptation to dedicated field configurations for different documents, such as procurement requirements and responses to inquiries. Handling inquiry complaints and supplier qualification verification is a core time-consuming process. Forms must include standardized field templates to reduce repetitive operations. Consequences of errors include bid invalidation, upheld complaints, and regulatory penalties. Interaction links must include mandatory verification of required fields and data format compliance to reduce the risk of operational errors.

## Three common misconfigurations
- Phenomenon: After submitting a procurement requirement form, a "field format error" error is returned, or the system fails to intercept incomplete supplier qualification information. Cause: Mandatory verification and format verification rules are not configured for government procurement-specific fields such as unified social credit code and project number.
- Phenomenon: When calling the knowledge base, only a single data source can be selected, and procurement announcements and supplier credit records cannot be associated in batches. Cause: The multi-option parameter of `userSelect` is not correctly configured, and the multi-data source association mode is not enabled.
- Phenomenon: When entering JSON-format query conditions, system variables cannot be bound to generate compliant query statements. Cause: Variable binding support for `formInput` is not enabled, or the parsing rules of the JSON input box are not correctly configured.

## How to verify successful configuration
- Submit a test form that includes a project number and supplier unified social credit code, and confirm that the system intercepts submission requests with missing required fields.
- Configure multi-data source association, and test whether procurement requirement documents and supplier credit records can be simultaneously selected as retrieval sources.
- Enter JSON-format query conditions, and confirm that system variables can be correctly bound to generate compliant query statements.
- Simulate a scenario where single data pulling takes a long time, and confirm that the system triggers a reasonable timeout processing logic.
