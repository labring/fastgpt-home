# Matter Consultation and Reply for Legal Compliance and Major Risk Management: Workflow Orchestration

## What the Data for This Category Looks Like
The data sources for this category are enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms. The update frequency is monthly. Daily documents include compliance risk lists, contract legal review opinions, legal opinions on major matters, compliance review forms, and violation report investigation results. Data fields vary by document type, with no unified fixed units, and include information such as compliance risk identifiers, review opinion content, and clue disposal progress.

## Constraints Imposed on the Workflow Orchestration Link
Because data sources are scattered across multiple business systems and the update frequency is monthly, workflows must be configured with a scheduled sync trigger node to pull full or incremental data on a monthly cycle. Daily documents have diverse types, so a document classification recognition component must be added to the workflow to match the indexing rules of the corresponding knowledge base. Data fields have no unified format, so a `variables` mapping link must be set to unify fields from different sources into a callable standard format. For the most time-consuming links such as risk identification and contract review, priority nodes must be set to prioritize high-risk documents, and a pre-check node must be added to filter input data that does not meet compliance requirements to avoid errors in subsequent processes.

## Three Common Misconfigurations
- Symptom: After modifying the `variables` global variable value in the workflow, the downstream node prompts that the input is empty when calling the variable. Cause: No persistent storage rule was configured for the variable update node. The variable was only modified in the current conversation memory, and the memory is released after node switching, causing the variable to be lost.
- Symptom: When the AI chat component uses variable reference mode to call the LLM, there is no temperature setting entry in the interface. Cause: No LLM parameter configuration node was added to the workflow. The component’s default parameters were called directly, and the temperature adjustment interface was not exposed.
- Symptom: The target knowledge base ID cannot be automatically obtained in the workflow, and matching fails after manual entry. Cause: No trigger node for automatic knowledge base ID pulling was configured, or the permission for the corresponding data source was not bound, so the system’s knowledge base metadata cannot be read.

## How to Verify Proper Configuration
- Trigger the scheduled sync node to verify that data can be pulled from the specified business system to the knowledge base per the preset cycle.
- Call the `variables` mapping link to confirm that fields from multiple document types can be unified into a callable standard format.
- Open the AI chat component configuration interface to confirm that the LLM generation parameters can be adjusted.
- Perform a knowledge base association test to confirm that the knowledge base ID for the corresponding category can be automatically pulled.
