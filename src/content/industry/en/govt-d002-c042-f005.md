# Legal Compliance and Major Risk Management Consultation and Response: Tool Calling and Plugins

## What this category's data looks like
This category of data originates from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. The update frequency is monthly. Daily generated documents include compliance risk lists, contract legal review opinions, legal opinions on major matters, compliance review forms, and violation report investigation reports. Data fields cover compliance risk levels, contract clause compliance, legal risk points for major matters, reporting clue disposal progress, and more. There are no unified fixed units, with values adjusting based on the document type.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Monthly updated data sources require that the knowledge base synchronization cycle for tool calling matches the monthly rhythm, to avoid frequent synchronization consuming system resources. Data from multiple systems requires plugins to connect to multiple heterogeneous system APIs, and handle differences in document formats and field specifications across different systems. Diverse document types require tool calling to adapt to extraction logic for different fields, such as differentiated processing for contract clause compliance fields and reporting clue disposal progress fields. Severe error consequences require tool calling to configure failure retry and alert mechanisms, while also supporting relational data association queries to adapt to the entity relationships between compliance risks, contracts, and cases.

## Three Common Misconfigurations
- Phenomenon: When calling a tool, "No matching knowledge base found" is returned. Cause: The bound knowledge base ID was not correctly passed in the workflow or API request, or the knowledge base ID does not match the data source.
- Phenomenon: The compliance risk association result returned by tool calling lacks entity relationships. Cause: Relational index configuration was not enabled, and only flat entity indexing was used, which cannot match the association logic between compliance risks, contracts, and cases.
- Phenomenon: A file format error is returned after uploading a file via the API call workflow. Cause: The file parameters were not encapsulated in multipart/form-data format as required, or the file size exceeded the preset limit of the plugin.

## How to Confirm Configuration Completion
- View tool calling logs to confirm that each call correctly matches the configured data source and knowledge base, with no empty fields or error ID prompts.
- Trigger a monthly synchronization task to check whether documents from the data source are fully synchronized to the knowledge base, matching the update rhythm of business data.
- Submit a test question involving compliance risk and contract association to verify whether tool calling returns expected relational analysis results.
- Simulate an API call workflow request to check that the returned response status code is within the normal range, with no format error prompts.
