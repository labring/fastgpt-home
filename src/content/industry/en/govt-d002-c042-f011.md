# Matters Consultation and Reply for Legal Compliance and Major Risk Management: Forms and Interactions

## What this category of data looks like
This category of data originates from enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms. Data updates run once per month. Daily covered document types include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation results. Data fields include compliance item number, risk level, review opinions, report clue details, and more. No unified fixed unit field exists. Specific fields and units adjust based on the corresponding document type.

## What constraints these characteristics create for the forms and interactions workflow
FastGPT v4.17.0 requires form interactions to support binding and switching between multiple knowledge bases for multi-source data access. This avoids confusion of cross-system compliance data. The monthly update frequency means the form’s knowledge base synchronization cycle must match this rhythm. This prevents use of outdated compliance reference data. Diverse document types require the form to support extraction configuration for different fields. This adapts to structural differences in documents such as compliance review forms and legal opinions. Compliance business carries severe error consequences. Form interactions must include input verification and result confirmation links. This reduces the probability of incorrect submissions.

## Three common misconfiguration issues
- Phenomenon: When invoking the text content extraction module, after the code block prompt within `formInput` is processed, the returned result displays the code block as undefined. Cause: The code block escape switch was not enabled in the `formInput` configuration, resulting in special symbols being truncated and lost.
- Phenomenon: After the user inputs "share", the content passed to the tool call becomes an erroneous similar term. Cause: The input verification function for `userSelect` was not enabled, and no preprocessing was done for visually similar characters or input errors.
- Phenomenon: It is not possible to select the corresponding knowledge base as required, and assigning values after defining global variables fails. Cause: The linkage rule between knowledge base selection and global variables was not configured in the form interaction, and the trigger condition for variable assignment was not bound.

## How to verify a correct configuration
- Test inputting a compliance prompt containing a code block into `formInput`, and check whether the returned result fully retains the code structure without missing content or garbled text.
- Switch between knowledge base options for different business scenarios, and confirm that the optional list of `userSelect` correctly matches the content of the corresponding data source.
- Trigger the global variable assignment operation, and confirm that the result of the knowledge base selection can be synchronized to the preset global variables without assignment failures.
- Simulate the form submission process for compliance review, and check that the extracted field content matches the corresponding fields in the source document without incorrect extraction.
