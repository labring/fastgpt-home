# Matter Consultation and Reply for Legal Compliance and Major Risk Management: Deployment and Upgrade

## What this category of data looks like
Data for this category comes from enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms. The update frequency is monthly. Daily documents include compliance risk lists, contract legal review opinions, legal opinions on major matters, compliance review forms, and violation report investigation reports. Most document fields include matter subjects, risk levels, review opinions, processing workflows, and other details. Some documents include identifiers such as case numbers and compliance clause numbers. There is no unified fixed unit.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/fastgpt?authSource=admin` | Adapts to the storage requirements of enterprise compliance databases, supports vector retrieval for multiple document types |
| `PG_URL` | `postgresql://[username]:[password]@[host address]:[port]/fastgpt` | Connects to structured data from enterprise contract management systems, supports complex queries |
| `STORAGE_S3_ENDPOINT` | Configure according to the enterprise's internal object storage address | Stores compliance documents and parsed vector data, ensuring data security and controllability |
| `REDIS_URL` | `redis://[password]@[host address]:[port]/0` | Caches frequently accessed compliance clauses and review opinions to reduce database load |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent connection requirements of multiple systems, prevents connection pool exhaustion |
| `FILE_TOKEN_KEY` | Generate a random string in accordance with enterprise key management specifications | Ensures access permission security for compliance documents |

## Three Common Mistakes
- Phenomenon: When calling the MCP service, the parameter `type` is forcibly restricted to the string type, and other data types cannot be passed. Cause: The parameter verification rules of the MCP service are not configured correctly, and strict type constraints are enabled by default.
- Phenomenon: After uploading a compliance document, parsing takes more than 2 minutes and the request fails. Restarting the server does not resolve the issue. Cause: The `FILE_TOKEN_KEY` configuration has expired or does not match the permissions of the enterprise object storage, resulting in failed file reading.
- Phenomenon: The front-end page of the compliance knowledge base cannot be accessed after deployment. Cause: The `FE_DOMAIN` configuration does not include the domain name prefix for internal enterprise access, resulting in cross-domain request interception.

## How to Verify Successful Configuration
- Run the database connection test script to verify the validity of the `MONGODB_URI` and `PG_URL` configurations, confirm that historical compliance-related data can be read.
- Trigger the monthly vector database update task, check the cache hit rate of `REDIS_URL` and the connection usage of `DB_MAX_LINK`, confirm that resource usage meets expectations.
- Upload a test compliance review form to verify that the file parsing and vector generation process works normally, with no timeouts or error prompts.
- Access the front-end page, confirm that the domain name configured in `FE_DOMAIN` can normally load knowledge base content, with no permission errors.

The values provided are common starting points and should be evaluated against the reader's own samples.
