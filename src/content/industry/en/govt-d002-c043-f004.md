# Special Equipment Safety Supervision Inquiries and Responses: Workflow Orchestration

## What Data Looks Like for This Category
Data for this category comes from special equipment safety supervision systems, inspection and testing institution systems, user unit ledgers, and operator certificate databases. Daily processed documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Data is updated once per month. Fields include equipment number, inspection validity period, maintenance cycle, operator certificate number, and others. Some fields must match the local regulatory format requirements of the device’s location, with no uniform fixed units.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Pulling multi-source data requires workflows to support cross-system integration; otherwise, automatic verification of equipment information and inspection reports cannot be completed. The monthly update frequency requires the workflow’s variable synchronization logic to match the update cycle to avoid using expired data. Diverse document types require workflows to configure different field verification rules by document category to adapt to different document structures. The most time-consuming verification links require workflows to split steps such as equipment registration, inspection cycle, qualification check, and rectification cancellation into independent nodes to reduce manual operations. Severe error consequences require workflows to add verification links to block non-compliant inquiries or data.

## How to Configure
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Form Input Component | Bind `variables` such as equipment number, operator certificate number | Core identifying information for special equipment inquiries is often entered via forms, and must be associated with business data |
| `variables` | Set to global persistent storage | Fixed business data such as equipment ledgers and inspection cycles must be retained across conversations |
| Single Search Limit | Top 10 results | The volume of documents related to special equipment is moderate, and the top 10 results can cover core inquiry content |
| Knowledge Base Search Logic | Return preset inquiry guidance when no results are triggered | Some temporary or niche equipment may not be entered into the knowledge base, requiring supplementary guidance |
| `nodeId` | Bind the node ID of the verification link | Automatic verification of qualifications and cycles must be executed in node order |
| Node Timeout Setting | 600 seconds | The time limit for cross-system data pulling aligns with actual business needs |

This configuration applies to FastGPT v4.17.0. Additionally, the maximum context can be adjusted based on the length of inquiry text, with a recommended range of 800–1200 characters.

## Three Common Mistakes
- Phenomenon: After the workflow runs, the form input component cannot extract the specified field values in `variables`, such as resultTimes and trafficFlowCounts. Cause: The form component is not bound to the corresponding `variables`, or the variable scope is only set to a single conversation.
- Phenomenon: The knowledge base search returns 0 results, and the preset no-result processing logic is not triggered. Cause: No no-result branch is configured, or the search scope does not cover all document types for special equipment.
- Phenomenon: Fixed data in global `variables` is cleared after the conversation ends. Cause: Persistent storage for `variables` is not enabled, only temporary conversation variables are used, and data is not synchronized according to the business update frequency.

## How to Confirm the Configuration Is Correct
- Submit a test inquiry containing an equipment number, check whether the form input component correctly extracts the equipment information from the bound `variables`.
- Trigger a knowledge base search, enter a test question that has not been entered into the knowledge base, check whether the preset no-result guidance script is returned.
- Initiate two consecutive inquiries, check whether the fixed business data in global `variables` is retained and not cleared.
- Run the cross-system data pulling node, check whether data acquisition is completed within the configured timeout period.
