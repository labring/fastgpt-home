# Special Equipment Safety Supervision Service Consultation and Reply: Forms and Interactions
This documentation applies to FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category originates from the special equipment safety supervision system, inspection and testing institution system, use unit ledger, and operator certificate database. Daily documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Each document corresponds to fields such as equipment number, inspection cycle, maintenance unit, operator qualification number, and hidden danger rectification status. Data update frequency is monthly. Form interactions rely on synchronized data from multiple systems to complete verification and checking.

## Constraints Imposed on the Forms and Interactions Link
Since data comes from multiple independent systems, forms must support cross-source retrieval of field information to avoid repeated entry of existing data from multiple systems. The monthly update frequency requires that inspection cycle and qualification information displayed in forms must mark data update timeliness to prevent use of expired data. Field differences across multiple document types require forms to adapt input items for different business scenarios, and verify logical matching between fields, such as the correspondence between inspection cycle and maintenance records. Business error consequences are severe, so forms must strengthen required field and format verification to reduce invalid submissions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Associate equipment number and operator certificate number fields, enable input verification | Core business fields require format verification in advance to avoid invalid submissions |
| `userSelect` | Limit maintenance units and inspection institutions to optional ranges | Reduce qualification matching errors caused by free text input |
| Maximum search results per query | Top 8 entries | Regulatory data entries are controllable; excessive results will extend interaction duration |
| Context retention length | 1200–1500 characters | Needs to cover multiple document contents related to the full equipment lifecycle |
| Timeout threshold | 60 seconds | Reserve sufficient response time for cross-system data retrieval |
| Form submission verification | Link inspection cycle and maintenance record fields | Ensure submitted content matches existing ledgers |

## Three Common Misconfigurations
- Only a small number of entries appear in the optional adaptation model list in the interface. This occurs because the optional range of `userSelect` is not configured to cover all dedicated supervision models, and some compliant models are not loaded.
- Automatic verification of the matching between equipment registration and inspection cycle does not run after form submission. This happens because the linkage verification rule for cross-ledger fields is not configured for `formInput`, so automatic verification cannot be triggered.
- The interaction process cannot automatically jump from the input stage to the result display stage. This is because the automatic flow logic of the form is not enabled, requiring users to manually confirm each step.

## How to Confirm Correct Configuration
- Enter a known special equipment number, check if the corresponding equipment registration information and inspection cycle automatically pop up.
- Open the model selection component, confirm that all models adapted for supervision scenarios appear in the optional list.
- Submit a test form with mismatched fields, check if corresponding verification prompts are triggered.
- After completing form input, check if the process automatically jumps to the result display stage without manual triggering.

The values given are common starting points and should be measured against the reader's own samples.
