# Service Inquiry and Response for Environmental Law Enforcement and Monitoring Regulation: Workflow Orchestration

Reference only; verify against the target FastGPT release and deployment documentation.

## What the Data for This Category Looks Like
Data sources for this category include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and reports submitted by third-party testing institutions. The system updates data daily, and requires synchronization of the latest operating condition, monitoring and law enforcement information. Daily documents include on-site inspection records, sampling records, monitoring reports, rectification order documents, administrative penalty decision documents, and law enforcement documents. On-site inspection records include inspection periods and operating condition data. Sampling records include point coordinates and sampling time. Monitoring reports include monitoring factors and concentration values. Law enforcement documents include the basis for identifying illegal facts and rectification requirements.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multi-source data access requires workflows to support connection to different types of data source nodes, including interfaces and file storage paths.
Daily data updates require workflow trigger timing to adapt to scheduled synchronization or real-time callbacks, to avoid using expired data.
Diverse document types, including structured law enforcement system data and unstructured PDF reports, require workflow configurations to support parsing rules for different formats.
Law enforcement processes must follow evidence chain logic strictly. Workflow node transitions must be traceable. Parameter verification must cover required fields in law enforcement documents to ensure response content is compliant and well-supported.

## How to Configure

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Scheduled trigger at 0:00 daily, or receive update callbacks from law enforcement systems | Data is updated daily. Scheduled triggers ensure inquiry responses use the latest synchronized data. Callbacks adapt to real-time data pushes |
| `variables` configuration | Pre-set law enforcement point IDs, monitoring factor lists, and rectification deadline fields | Daily law enforcement documents include fixed business fields. Using `variables` allows unified calling and reduces repeated configuration |
| Node Identification Configuration | Set a unique `nodeId` for each data source node | Workflow orchestration uses `nodeId` to distinguish different nodes, facilitating log troubleshooting and transition control |
| Failure Retry Configuration | Retry 2 times after failure, with a 60-second retry interval | Online monitoring interfaces may experience temporary fluctuations. Retries reduce the probability of data pull failures. Adjust parameters based on actual testing |
| File Parsing Configuration | Enable structured parsing for PDF-format monitoring reports | Daily documents include large numbers of PDF-format monitoring reports and law enforcement documents. Structured parsing extracts valid fields for use in responses |

## Three Common Mistakes
- The workflow runs normally on the run preview page, but displays no content on the chat page. The cause is that workflow nodes are not correctly associated with the `variables` parameters of the chat session, so the session context cannot call law enforcement data generated by the workflow.
- A "Load file error" occurs when uploading a monitoring report file for comparison. The cause is that the file upload node of the workflow is not configured with correct storage path permissions, or the file size exceeds the preset limit of the node.
- The HTTP request node fails to correctly transfer files when form-data parameters are set. The cause is that the local file path or file access link of third-party storage is not specified in the file parameter item, causing the request to fail to recognize the file content.

## How to Confirm the Configuration Is Correct
- Manually trigger the workflow, check the running logs, confirm that each data source node successfully pulls the corresponding data with no error prompts.
- Test launching an inquiry related to law enforcement, check the content returned on the chat page, confirm that it includes preset monitoring data and law enforcement document fields.
- Simulate uploading a monitoring report file, check whether the workflow node can correctly receive and parse the file content to generate corresponding data.
- View the workflow permission configuration page, confirm that only authorized roles can access the corresponding nodes to avoid sensitive data leaks.
