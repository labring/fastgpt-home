# Inquiry and Response for Environmental Law Enforcement and Monitoring Supervision: Tool Calling and Plugins

## What data for this category includes
Data sources for this category include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Commonly processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Each individual document contains fields such as sampling points, monitoring indicators, law enforcement document numbers, and rectification requirements. The data update frequency is daily. Structured data updated in a single batch includes real-time monitoring-related content, while semi-structured documents contain fixed-format law enforcement and monitoring information.

## What constraints these characteristics impose on tool calling and plugins
Data for this category comes from multiple sources and is updated daily. Tool calling must adapt to the interface formats of different data sources, including online monitoring platforms and law enforcement systems. It must also regularly synchronize the latest monitoring and law enforcement data.
Commonly processed documents include structured monitoring data and semi-structured law enforcement documents. Tool calling must support input and output in multiple formats, including jpg files of monitoring reports.
The fields in law enforcement documents are fixed and require precise matching. Tool calling must be configured with field extraction rules to prevent confusion between different document types.
This category focuses on on-site law enforcement and monitoring evidence, unlike emission permit scenarios. Priority must be given to ensuring the accuracy of data related to illegal facts.
Because the consequences of errors are serious, tool calling must include data verification and failure retry mechanisms to guarantee the accuracy of call results.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-tool calling scenarios, automatically select the tool matching the current law enforcement or monitoring task, based on the FastGPT v4.17.0 tool calling framework |
| `functionCall` | `enabled` | Support structured output of fixed fields from law enforcement documents, to facilitate subsequent data organization and connection with law enforcement workflows |
| Tool call timeout | `60 seconds` | A single tool call for this category requires pulling and verifying data from multiple sources. 60 seconds covers conventional call durations |
| Image processing tool call limit | `first 3 entries` | Monitoring report images processed daily are usually single copies or small batches. Limiting to the first 3 entries avoids excessive resource usage |
| Data synchronization frequency | `every 24 hours` | The data update frequency for this category is daily. Daily synchronization ensures that tool calls use the latest online monitoring and law enforcement data |

## Three common errors
- Symptom: Tool calls fail to load jpg-format monitoring report images, and the interface displays an "unsupported file format" error. Cause: No tool plugin supporting image formats is configured, and only text-based tool calling is enabled.
- Symptom: Calls to login-related tools return a 401 status code, and session credentials cannot be obtained normally. Cause: The pre-login interface was not called first to obtain verification parameters according to the process. Calling the login interface directly leads to identity verification failure.
- Symptom: Law enforcement document fields returned by tool calls are empty, and rectification requirements cannot be extracted. Cause: No extraction rules are configured for the corresponding fields. Tool calls only pull original documents without structured parsing.

## How to confirm the configuration is complete
- Initiate a test call that includes a jpg image. Check whether the tool can load normally and return an image preview, to confirm that the image processing plugin configuration is effective.
- Call the pre-login interface first, then call the login interface. Verify whether session credentials can be obtained normally, to confirm that the login process configuration is correct.
- View the tool call logs. Confirm that multi-source data has been synchronized at the set frequency, and that field extraction results match expectations.
- Initiate a tool call in a simulated law enforcement scenario. Check whether the matching tool is automatically selected, to confirm that the `toolChoice` configuration is effective.
