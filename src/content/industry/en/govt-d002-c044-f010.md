# Environmental Law Enforcement and Monitoring Supervision: Inquiry and Response Services — Knowledge Base Retrieval and Recall

## What Data Belongs to This Category
This category of data comes from ecological environment law enforcement detachments, monitoring stations, pollutant discharge units, and third-party testing institutions.
Daily documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions.
Data sources include online monitoring platforms, automatic pollutant source monitoring data, ecological environment law enforcement systems, and third-party test reports.
Update frequency is daily.
Most documents are structured tables and process records.
Fields include monitoring points, pollutant concentrations, law enforcement time, penalty basis, and other items.
Some documents include clear numerical units.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The daily update feature of this category of data requires retrieval links to cover the latest online monitoring, automatic pollutant source monitoring data, and law enforcement system data. This ensures recalled content matches the timeliness of current law enforcement scenarios.
Documents include structured tables and process records. Retrieval must accurately match fields and units. Avoid fuzzy matching that causes evidence deviations.
Law enforcement and monitoring documents are mostly compliance-related content. Retrieval must prioritize linking direct evidence such as on-site inspection records and sampling records. General policy documents are not included in priority retrieval scopes.
Data sources are scattered across multiple systems. Recall must integrate multi-source data to ensure complete evidence chains.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precise matching needs of law enforcement and monitoring documents, ensures recalled content is highly relevant to queries |
| `limit` | Top 8 results | Covers the completeness of evidence chains required for law enforcement scenarios, avoids excessive redundant content interfering with retrieval |
| `usingReRank` | Enabled | Sorts recall results from multi-source data, prioritizes core documents such as on-site inspection records and monitoring reports |
| `datasetSearchUsingExtensionQuery` | Enabled | Performs semantic expansion for professional terms in law enforcement queries, improves retrieval accuracy |
| `collectionIds` | Bind dedicated law enforcement and monitoring dataset ID | Limits retrieval to only cover dedicated documents such as on-site inspection records and monitoring reports, avoids irrelevant content |

## Three Common Errors
- Imported monitoring report tables cannot be split correctly. Retrieval cannot match fields such as pollutant concentrations and monitoring points within tables. The cause is failure to enable dedicated splitting rules for structured tables. Using general splitting logic fails to recognize table field structures.
- In locally deployed open-source versions, no image understanding model options are visible. Information such as sampling records in image form and monitoring point annotations cannot be extracted. The cause is failure to enable image understanding model dependencies in FastGPT v4.17.0 deployment configuration, or the version does not integrate corresponding functions.
- New folders are not classified and stored according to documents such as law enforcement and monitoring reports. This leads to retrieval recalling a large number of irrelevant documents. The cause is failure to divide folders by business scenario, and failure to classify and store on-site inspection records and administrative penalty decisions. This prevents precise limitation of retrieval scope.

## How to Confirm Configurations Are Correctly Set
- Import an on-site inspection record document, launch a query including pollutant concentrations, and check whether recall results include matching content for corresponding fields.
- Upload a monitoring report containing a table, verify whether split content retains table row and column information, and confirm splitting is complete.
- Review knowledge base settings to confirm configuration items such as `usingReRank` and `datasetSearchUsingExtensionQuery` are enabled. Check that the configuration matches the bound dedicated law enforcement and monitoring dataset ID.
- Launch a query including law enforcement time and penalty basis, and check whether recall results prioritize core documents such as on-site inspection records and order for correction decisions.

The values provided are common starting points, and should be evaluated against the reader’s own sample datasets.
