# Service Inquiry and Response for Environmental Law Enforcement and Monitoring Supervision: Forms and Interactions

## What Data for This Category Looks Like
This category of data comes from online monitoring platforms, automatic pollution source monitoring systems, ecological environment law enforcement business systems, and reports submitted by third-party testing institutions. Daily business documents include on-site inspection records, original sampling records, monitoring and analysis reports, decisions on ordering correction, administrative penalty decisions, and similar materials. Fields include monitoring point number, pollutant concentration value, law enforcement time, rectification requirements, penalty basis, and more. Data is updated daily.

## Constraints Imposed on the "Forms and Interactions" Link
Multiple data sources require forms to support associated entry and verification of cross-system data. Multiple types of business documents require forms to adapt to switching between different field templates. Daily updated data requires no delay in the form input and submission workflow. The rigor required for law enforcement and monitoring mandates strict required fields and format verification rules for forms, to prevent invalid data entry. Additionally, law enforcement documents are typically lengthy, so input length must be reasonably limited to avoid overflow. Dynamic variable reference must also be supported to adapt to knowledge base calls for different law enforcement scenarios.

| Input Format Verification | Add format rules for fields such as pollutant concentration and law enforcement number | Ensure entered data complies with business specifications, reduce subsequent data comparison errors |
| Timeout Setting | 600 second timeout threshold, calibrated based on actual testing | Adapt to response time for multi-source law enforcement data queries, avoid long waiting times |

## Three Common Configuration Errors
- Phenomenon: When entering on-site inspection record content that exceeds the set threshold, the system throws an input overflow error. Cause: No reasonable character limit is configured for `formInput`, and no input length verification rule is added.
- Phenomenon: After a parent workflow calls a sub-workflow, subsequent nodes fail to execute after the `userSelect` node in the sub-workflow completes. Cause: Execution context passing verification for the sub-workflow is not enabled, and process trigger parameters are not correctly bound.
- Phenomenon: After configuring a locally deployed model and enabling tool call support, tool calls cannot be triggered normally. Cause: The model is not bound to the exclusive knowledge base context for law enforcement scenarios, and correct tool call adaptation rules are not configured.

## How to Verify Successful Configuration
- Upload a standard on-site inspection record, test the `formInput` input length limit. Verify that content within the limit can be saved normally, and a corresponding error is triggered when the limit is exceeded.
- Configure a sub-workflow call link, add a `userSelect` node in the sub-workflow and execute it. Verify whether subsequent nodes trigger execution normally.
- Call the API to pass the law enforcement document library variable. Verify that the knowledge base search node correctly calls business document content from the specified library.
- Enter non-standard pollutant concentration values. Verify whether the system pops up corresponding format verification prompts, ensuring entered data complies with business requirements.
