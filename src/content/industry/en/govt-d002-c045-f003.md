# Land Use Preliminary Examination and Planning Permit Consultation and Reply: Multi-turn Dialogue and Prompt Words

Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Data for this category comes from the national land spatial planning unified map, project approval and supervision platform, land use status database, and ecological protection red line data. Update frequency is not fixed.
Daily processed business documents include land use preliminary examination and site selection opinions, construction land planning permits, construction engineering planning permits, red line drawings, and planning conditions. Core fields cover project site selection scope, land use scale, planning control requirements, pre-approval conditions, and more. The data structure is strongly tied to the pre-construction project approval process, and must strictly match official approval rules.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words link
Data sources for this category are scattered, and updates follow no fixed cycle. Multi-turn dialogue must fully retain associated context from different data sources to avoid cross-system data inconsistency.
Daily document types are diverse, and field logic varies significantly across different documents. Prompt words must accurately match the format and verification rules of corresponding documents to ensure replies comply with planning control requirements.
Pre-project approval conditions involve cross-departmental coordination. Dialogue must gradually guide users to supplement complete pre-approval information, while strictly verifying land use scale and red line conflicts to prevent non-compliant reply content.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | First 12 dialogue turns or 8000–10000 characters | This category has many data fields and strong context association, so sufficient historical interaction and data association information must be retained |
| `messages` | Store per individual project session | Consultations for land use preliminary examination and planning permits require context isolation per individual project to avoid cross-project data confusion |
| `variables` | Bind project number and red line coordinate fields | Project-specific identifiers and core spatial data must be stored in variables to enable quick retrieval and verification during multi-turn dialogue |
| Single search limit | Top 6 matching results | Data for this category requires precise matching of planning control requirements; excessive results will disrupt dialogue logic |
| Multimodal input support | Enabled | This category requires support for uploading business documents in image and file formats such as red line drawings and planning conditions to ensure accurate content extraction |
| Timeout setting | 600 seconds | Multi-source data synchronization must be completed to avoid interrupting critical verification processes due to timeout |

## Three Common Misconfigurations
- Phenomenon: After a multi-turn dialogue restarts, previously mentioned project information cannot be recalled, and historical interaction fields are empty. Cause: The `chatId` parameter is not correctly bound, or the session storage configuration is not isolated by project dimension.
- Phenomenon: The model selection list for text content extraction only shows some vendors, and connected GLM series models cannot be selected. Cause: Connected models are not synchronized to the model selection pool of the dialogue module, or the configuration does not associate model parameters between the text extraction and dialogue modules.
- Phenomenon: After a workflow executes, only a single step result is returned, and multi-turn verification logic cannot be chained. Cause: Multi-step variable transfer is not configured, or the output of the previous step is not used as the input context for subsequent dialogue modules.

## How to verify successful configuration
- Initiate a multi-turn consultation covering project site selection and land use scale, and check whether the dialogue process can associate previously mentioned project numbers and red line scope.
- After connecting a specified model, confirm whether the model is visible and selectable in the model selection list of the dialogue module.
- After configuring multiple workflow steps, trigger a test session, and check whether the final output includes compliance conclusions from prior step verifications.
- After uploading documents related to land use preliminary examination, check whether the dialogue module can correctly extract core fields from the documents for verification.
- After uploading image files such as red line drawings, check whether the dialogue module can correctly identify and parse spatial coordinate information in the images.
