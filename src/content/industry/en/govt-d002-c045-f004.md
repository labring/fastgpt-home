# Consulting and Reply for Land Pre-examination and Planning Permit: Workflow Orchestration

## What Data Looks Like for This Category
Data sources for this category include the National Land Space Planning One Map, Project Approval and Supervision Platform, Land Use Status Database, and Ecological Protection Redline Data. Update frequency is irregular.
Daily processed documents include Land Pre-examination and Site Selection Opinion, Construction Land Planning Permit, Construction Engineering Planning Permit, redline drawings, planning conditions, and others.
Typical associated entities are natural resources authorities’ land use control and planning permit divisions, administrative examination and approval bureaus, and project units.
Core fields involve project site selection scope, land use scale, planning control requirements, and others. There are no unified fixed standardized unit fields. Matching must be done based on the actual needs of specific project documents.

## What Constraints These Characteristics Impose on the Workflow Orchestration Link
Data sources are scattered, and updates have no fixed cycle. Workflows must support real-time pulling and incremental synchronization verification of multi-source data.
Daily document types are diverse. Parsing nodes adapted to different document formats must be configured to ensure accurate field extraction from unstructured documents such as redline drawings and planning conditions.
The most time-consuming verification step involves coordinating preconditions across multiple departments. Workflows must reserve cross-system interaction nodes to reduce manual repeated verification work.
Errors directly affect project approval and construction start. Pre-verification nodes must be added to workflows to block application materials that do not meet control requirements.

## Three Common Misconfigurations
- Issue: Voice interaction node calls in workflows fail during testing, returning connection timeout or parameter mismatch errors. Cause: The file link variable configured in `variables` is not correctly bound to the input parameters of the voice node, so the node cannot obtain the business document to be processed.
- Issue: HTTP request nodes return empty results, or parsed base64 encoding formats are incorrect. Cause: The body parameter names and values of the HTTP request are not correctly configured. The parameter names do not correspond to the field names of business documents, and the parameter values are not bound to correct data source variables.
- Issue: Redline conflict verification results are inaccurate after workflow runs. Cause: Data pull is not triggered based on data source update status, and fixed-period pull of old data is used, causing verification results to not match the latest planning control requirements.

## How to Confirm Proper Configuration
- Check if the fields configured in `variables` cover the core business fields for land pre-examination and planning permits. Export the workflow parameter list and verify each item one by one.
- Test the runtime status of individual nodes. Trigger the node with `nodeId` "Redline Conflict Verification Node", and confirm if the returned results include the latest ecological protection redline data.
- Simulate a cross-department coordination process, trigger the cross-system interaction node, and confirm if the timeout setting meets the actual time requirements of business coordination.
- Upload a real project redline drawing, test the output of the unstructured document parsing node, and confirm that field extraction meets business requirements.
