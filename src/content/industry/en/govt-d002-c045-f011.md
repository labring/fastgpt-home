# Land Pre-Screening and Planning Permit Application Consultation and Response: Forms and Interactions

## What the data for this category looks like
Data sources for this category include the unified national land and spatial planning map, project approval and supervision platform, land use status database, and ecological protection redline data. Update frequency is irregular. Daily associated documents cover land pre-screening and site selection opinions, construction land planning permits, construction engineering planning permits, redline diagrams, and planning conditions. Core data fields include project site selection scope, land scale, control boundaries, pre-coordination conditions, and others. No unified fixed standard units exist. Matching must be completed based on actual project conditions and control requirements.

## What constraints these characteristics impose on the "forms and interactions" link
Decentralized data sources and irregular update cycles require form interaction links to support real-time calls to multi-source data for verification. Diverse associated document types require forms to adapt to field extraction and upload verification rules for different documents. Core business links involve project site selection and redline conflict checks, as well as land scale review. Interactions must preload corresponding control data to reduce manual verification costs. Data errors can prevent project approval or construction startup. Forms must add required field verification and exception prompts to avoid missing critical information.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setup | Rationale |
| --- | --- | --- |
| `formInput` | Set to multi-field grouped input, including 3 core fields: project name, site selection scope, land scale. Maximum 500 characters per single field input | Matches core declaration fields of business documents, aligns with standard project declaration structures |
| `userSelect` | Preset 12 pre-coordination department options including development and reform, housing and urban-rural development, ecology and environment, etc. Default selection is none | Covers conventional department subjects requiring coordination in business processes, adapts to multi-department pre-approval requirements |
| Attachment upload limits | Maximum 100 MB per file. Supports uploading PDF, CAD, and GIS format files | Matches commonly used approval documents and drawing formats in the industry, aligns with conventional file size ranges |
| Real-time verification trigger | Automatically trigger redline conflict verification after site selection scope is entered. Return the first 3 conflict prompts | Focuses on core verification links, reduces interference from non-critical information, and improves verification efficiency |
| Error prompt configuration | Display error information categorized by field. Show after an 800 millisecond delay | Avoids frequent pop-up windows interfering with input, clearly locates problematic fields, and aligns with user operation habits |

## Three Common Misconfigurations
- Symptom: An error message "Some input information is duplicated" appears when clicking the input field after creating a plugin, referencing it in a workflow and connecting a code execution step. Cause: Duplicate verification rules are set for the `formInput` field in the form configuration, causing the system to incorrectly judge that input content is duplicated.
- Symptom: Only a small number of optional models are visible in the tool call link. Cause: The model permission range is not configured, or the model selection module for form interactions does not load the full list of available models synchronously.
- Symptom: After submitting the form, the AI does not call the data verification tool and directly returns a standard response. Cause: The interaction link is not bound to the tool call trigger logic for data verification, causing the system to not trigger the corresponding business process.

## How to Confirm Configuration is Complete
- Fill in the core form fields sequentially, trigger real-time verification, and check whether prompt information for corresponding control data pops up. Ensure verification rules match business field requirements.
- Upload a document file that meets the required format, confirm the system can correctly recognize and extract key information, and ensure upload limits align with conventional sizes of business files.
- Test calling the model selection module, confirm all available models are displayed, and ensure permission configuration covers all model types required for the business.
- Simulate abnormal input scenarios, check whether error prompts are displayed categorized by field, and confirm prompt timing matches the preset configuration.
