# Service Consultation and Reply for Land Pre-examination and Planning Permission: Deployment and Upgrade

## What the data for this category looks like
Data for land pre-examination and planning permission service consultations originates from the land spatial planning one-map, project approval and supervision platform, current land use database, and ecological protection red line data. Update frequency is irregular. Daily interaction documents include land pre-examination and site selection opinions, construction land planning permits, construction project planning permits, red line maps, and planning conditions. Core fields include project number, land area, planning control indicators, red line coordinates, and others. There is no unified fixed maximum word count per document. Parse documents according to the format of actual approval files.

## What constraints do these characteristics impose on the deployment and upgrade process
This category of data originates from multiple government department platforms, with heterogeneous formats and no fixed update cycle. During deployment, adapt multi-source data docking and incremental synchronization logic. Daily interaction documents include unstructured files such as vector red line maps and planning conditions. Configure targeted document parsing rules. Business data includes core project approval information. Enforce strict data isolation and access permission control during deployment. During upgrades, avoid damaging the consistency of existing approval data. Support the process of migrating old configurations to environment variables to reduce business interruption risks. FastGPT v4.17.0 and later versions have optimized configuration migration logic to simplify upgrade steps.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Connect to the dedicated MongoDB instance for natural resources department approval and supervision platforms, configure read-write separation addresses | Business data storage requires isolation and ensures read-write performance for approval data |
| `REDIS_URL` | Bind to an internally deployed Redis cache instance, set connection password and database index, configure maximum memory as `2048 MB` | Used to cache planning control rules and red line data for high-frequency queries, reducing cross-database query latency |
| `DB_MAX_LINK` | `100–150 connections` | Adapt to the database connection count requirements for concurrent consultations across multiple departments, avoid connection exhaustion |
| `FILE_TOKEN_KEY` | Generate a key in accordance with natural resources department document encryption specifications, set token validity period as `24 hours` | Used to sign access tokens for confidential documents such as red line maps and planning conditions, ensuring data security |
| `STORAGE_S3_ENDPOINT` | Configure as the government cloud S3 endpoint, set upload file size limit as `100 MB` | Used to store approval documents such as red line maps and planning conditions, complying with government storage requirements |

## Three common misconfigurations
- Phenomenon: Connection to a cloud RDS instance is rejected, with status code 10060. Cause: The public IP of the FastGPT deployment node is not added to the RDS whitelist, or the whitelist only configures local test IPs.
- Phenomenon: Startup error occurs after upgrading to FastGPT v4.8.20, prompting that the config.json configuration item cannot be found. Cause: Old configurations are not fully migrated to environment variables, and startup commands dependent on config.json are still retained.
- Phenomenon: Expired planning control rules appear in consultation results. Cause: Data incremental synchronization tasks are not configured, and old full synchronization configurations are still used, resulting in delayed data updates.

## How to verify proper configuration
- Run the built-in database connectivity test tool to verify that connections for `MONGODB_URI` and `REDIS_URL` have no timeout or permission errors.
- Upload a real land pre-examination and site selection opinion document to verify that core fields such as project number and land area can be correctly extracted after parsing.
- Initiate a simulated service consultation to check that the planning data referenced in the returned results matches the latest content of the current land spatial planning one-map.
- Check the security group and access control policies of the deployment node to confirm that only government extranet access ports are open, with no public network exposure risks.
