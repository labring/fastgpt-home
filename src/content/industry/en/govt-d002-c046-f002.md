# Service Consultation and Response for Social Assistance and Minimum Living Security Review: Vector Models and Indexes

## What Data Looks Like for This Category
The data for this category comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared public security, human resources and social security, medical insurance, housing construction, and tax data. Daily processed documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic review records, publicity materials, and assistance approval forms. The data update frequency is monthly. Core fields include family income, property details, family member relationships, assistance qualification determination results, etc. No additional statistical content is added.

## What Constraints Do These Characteristics Impose on the Vector Model and Index Link
Cross-department multi-source data brings format heterogeneity issues. The index link must adapt to structured forms and unstructured documents exported by different systems. The monthly update frequency does not require high-frequency incremental indexing, but fixed-cycle full synchronization is needed. Documents include forms with fixed fields and narrative materials. When chunking, both accurate extraction of structured fields and semantic integrity of unstructured text must be considered. The core business focuses on family economy and assistance qualifications. Vector recall must prioritize associating key fields such as income, property, and family member relationships to ensure that recall results are strongly relevant to business judgments.

## Three Common Mistakes
- Reranking results do not take effect during online recall testing. The symptom is that returned results are not sorted by relevance priority. The cause is that reranking configuration is only enabled in the question answering link, and the function is not enabled synchronously in the knowledge base index link.
- Index task execution fails. The symptom is that logs show empty fields or stagnant index progress. The cause is that cross-department heterogeneous data formats of this category are not adapted, and general chunking rules are directly used to process structured forms and unstructured materials.
- Vector model call times out. The symptom is that the index task returns a timeout status code. The cause is that the `defaultToken` parameter is not set reasonably, causing the processing of long documents to exceed the call time limit.

## How to Confirm Configurations Are Set Correctly
- Perform a small-batch index test, check whether the generated vector chunks cover core business fields such as family income and property details, with no obvious content splitting errors.
- Launch a test query for service consultation, verify whether the reranking function takes effect and whether the result sorting meets business relevance requirements.
- View the index task logs, confirm that vector model call parameters match the configuration items, with no timeout or format errors.
- Compare recall results under different configurations, adjust to a reasonable range that meets the semantic integrity of documents for this category.
