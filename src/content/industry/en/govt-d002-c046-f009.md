# Service Consultation and Response for Social Assistance and Minimum Living Security Review: Model Access and Configuration

## What Data for This Category Looks Like
Data for this category comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update cycle is monthly. Daily processed documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic review records, public notice materials, and assistance approval forms. Data fields focus on family income, property status, family member relationships, and assistance qualification determination. Original formats and units from each data source must be matched.

## Constraints Imposed by These Characteristics on the "Model Access and Configuration" Link
The large volume of monthly updated cross-department data requires limiting the data range accessed in a single request to avoid context overflow. Field formats of multi-source heterogeneous data are inconsistent, so the model must support dynamic adaptation to the field structures of different data sources. Verification of family economic status and member relationships relies on precise matching, which places high requirements on the model's context accuracy. A large amount of unstructured text exists in household survey and public notice materials, so processing logic adapted to unstructured data must be configured. Results of assistance qualification determination are directly linked to fund disbursement, so the compliance boundary of model output must be strictly controlled.

## Configuration Settings
Based on FastGPT v4.17.0, the following configuration items and values can be referenced for this category's characteristics:

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total context length of monthly cross-department data sources, avoids exceeding the model's processing window |
| `maxTokens` | 2000–3000 token | Controls the output length of single-round determination results, meets the text requirements for assistance qualification explanations |
| `quoteMaxToken` | 1500 token | Limits the length of referenced source data, ensures core verification information such as family income and member relationships is complete |
| `toolChoice` | auto | Automatically calls tools to complete cross-department data matching, adapts to processing requirements for multi-source heterogeneous data |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures accuracy and consistency of assistance qualification determination |
| `AIPROXY_API_TOKEN` | Generated according to permission allocation | Ensures identity verification for interface calls, prevents unauthorized access to sensitive civil affairs data |

## Three Common Configuration Mistakes
- Phenomenon: Interface calls return a 401 unauthorized error, or tool calls have no response. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or the token's permissions do not cover cross-department data interfaces.
- Phenomenon: Tool calls fail, returning an error that function call is unrecognized. Cause: The `toolChoice` parameter is not configured correctly, or the tool logic for cross-department data verification is not bound to the model.
- Phenomenon: Context overflow causes processing interruption, returning empty results or truncated content. Cause: The `maxContext` configuration value is smaller than the total length of monthly aggregated data, and does not adapt to the multi-source data volume of this category.

## How to Confirm Successful Configuration
- Submit monthly aggregated test data, check that the model's output context length does not exceed the configured range.
- Trigger the tool call flow, confirm that the model can automatically call the cross-department data verification tool to complete family economic status matching.
- Adjust the `temperature` parameter, compare the consistency of multi-round output results, and confirm that it meets business determination requirements.
- Verify the response status code of the interface call, confirm that the `AIPROXY_API_TOKEN` configuration is correct, and there are no unauthorized errors.
