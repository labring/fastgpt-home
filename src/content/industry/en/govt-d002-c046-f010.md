# Service Consultation and Response for Social Assistance and Minimum Living Security Review: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
Data for this category mainly comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Daily processed documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic review records, public notice materials, and assistance approval forms. The data update cycle is monthly. Most documents contain fields such as family income, property amount, family member relationship, and approval status, with units including yuan, household, and person.

## What Constraints Do These Characteristics Impose on Knowledge Base Retrieval and Recall
Cross-department multi-source data sources lead to mixed formats. Some data comes as structured tables exported from systems, while other data exists as unstructured text converted from paper materials. This increases the difficulty of text segmentation and embedding alignment during retrieval. The monthly update frequency requires the retrieval system to support periodic incremental synchronization, avoiding extra time spent on full reconstruction. Core documents center on family economic status and assistance eligibility. Retrieval must accurately match key fields such as family members and income items. Generalized recall easily deviates from business requirements. Additionally, the data involves sensitive people's livelihood information, so retrieval results must strictly limit the returned scope.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Match core fields related to family economic status, avoid recalling irrelevant public notice materials |
| `limit` | Top 8 entries | Control the number of documents returned per retrieval, adapt to the single consultation scenario of civil affairs business |
| `usingReRank` | Enabled | Improve recall sorting accuracy for multi-source mixed documents focused on core fields |
| `searchMode` | Semantic retrieval | Adapt to semantic matching requirements for non-keyword content such as family relationships and income items |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplement synonymous queries related to family economic status, improve recall coverage |

## Three Common Configuration Mistakes
- Phenomenon: After uploading an XLSX-format family economic status verification report, the knowledge base has no corresponding content. Cause: Table parsing rules are not configured correctly, and row data of multi-row tables is not associated as a single context, causing segmented text to fail to match queries.
- Phenomenon: When retrieving questions related to minimum living security applications, the number of returned results far exceeds expectations, causing page load timeout. Cause: A reasonable `limit` parameter value is not set, too many non-core documents are recalled, exceeding system processing thresholds.
- Phenomenon: The knowledge base always has no content after configuration is completed. Cause: The `collectionIds` parameter is not filled correctly, and the dataset storing civil affairs assistance documents is not associated.

## How to Confirm Configuration Is Complete
- Upload a single minimum living security application form document, perform a semantic retrieval test, and check whether the relevance of returned results meets business expectations.
- View retrieval logs, confirm that the number of documents returned per retrieval matches the preset `limit` parameter configuration.
- Perform a monthly incremental synchronization test, verify whether newly uploaded family economic status verification reports can be normally recalled.
- After enabling `usingReRank`, compare recall sorting results before and after enabling, confirm that sorting accuracy has improved.

The values provided are common starting points and should be measured against the reader's own samples.
