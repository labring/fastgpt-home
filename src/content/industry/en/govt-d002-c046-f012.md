# Service Consultation and Response for Social Assistance and Minimum Living Security Audit: Deployment and Upgrade

## What the data for this category looks like
Core data for this category revolves around household assistance qualification audits. Common documents include the minimum living security application form, household financial status verification report, household survey form, democratic review record, public notice materials, and assistance approval form.
Data is primarily sourced from the low-income population dynamic monitoring platform, resident household financial status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities.
Data update frequency is monthly. Core fields include household population information, income and property details, approval node status, and more. Field units vary by specific document type, with no unified fixed format.

## What constraints these characteristics impose on the deployment and upgrade link
This category’s data comes from multiple government systems with varying structural complexity. During deployment, configure storage parameters adapted to multi-source heterogeneous data to ensure effective storage and retrieval of different document types.
Data is updated monthly. During deployment, configure parameters for scheduled synchronization tasks to ensure timely access to the latest household income and property information.
There are diverse document types linked to the full approval process. The knowledge base classification must match the logic of minimum living security audit nodes to avoid retrieval confusion.
Since errors directly impact assistance funds and public rights and interests, configure data verification and cache parameters during deployment to ensure data accuracy.
During the upgrade process, ensure cross-department data synchronization links are not interrupted to avoid stagnation of audit processes.

## Three common mistakes
- Phenomenon: After upgrading to FastGPT v4.17.0, cross-department data synchronization tasks fail to start, and logs show database connection failure. Cause: Permission parameters for `MONGODB_URI` are not configured correctly, causing the system to fail to access the database storing audit documents.
- Phenomenon: Calling Tongyi Qianwen-Max returns authentication failure with a status code of 401. Cause: Model call key parameters are not correctly configured in the system, or key permissions do not cover the call scope of the corresponding model.
- Phenomenon: The system cannot access the specified document directory, retrieval results are empty, and the frontend prompts insufficient permissions. Cause: Associated parameters for `FE_DOMAIN` and `FILE_TOKEN_KEY` are not configured, causing file access permission verification to fail.

## How to confirm the configuration is correct
- Run the built-in database connectivity test script to check the connectivity status of `MONGODB_URI` and `PG_URL`, confirming that the storage configuration takes effect.
- Trigger a manual household financial status data synchronization task, check whether corresponding cache records are generated for `REDIS_URL`, confirming that the cache configuration takes effect.
- Upload a standard minimum living security application form document, verify that the system can complete indexing according to the configured classification rules, confirming that the knowledge base classification configuration takes effect.
- Call the test model interface, input preset consultation questions, check that returned results meet expectations, confirming that the model call configuration takes effect.
