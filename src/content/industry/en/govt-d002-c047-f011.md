# Administrative Penalty Case File Handling: Service Consultation and Reply - Forms and Interactions

## What the data for this category looks like
Core data for this category comes from administrative law enforcement case handling systems, law enforcement recorder footage of law enforcement agencies including market supervision, ecological environment, transportation, emergency management, and urban management, the national enterprise credit information publicity system, and departmental supervision databases. Documents processed daily include on-site inspection records, interrogation transcripts, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, service receipts, and more. Data is updated daily. Fields cover law enforcement subject information, description of illegal facts, discretionary benchmark clauses, delivery addresses, and more. Each document includes a unique case file number identifier.

## What constraints these characteristics impose on the "forms and interactions" link
Daily document types are numerous and have fixed structures. Exclusive fields for different documents must be displayed in stages according to law enforcement procedures to avoid information confusion. Data sources involve multiple external systems, so forms need to support associative synchronization of external fields to reduce duplicate data entry. Data is updated daily, so a real-time verification mechanism must be configured to avoid using expired supervision data. The consequences of errors directly affect the legality of case files, so forms need to add required field verification and logical verification for core fields to prevent unqualified review and inspection.

## How to set the configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Split into multiple independent input boxes according to law enforcement document fields, each corresponding to a single item of content | Daily law enforcement documents contain multiple independent fields; splitting allows separate verification and archiving |
| `userSelect` | Associate with the internal personnel database of law enforcement agencies, preset options for law enforcement subjects and reviewers | Data sources include departmental supervision databases, which can directly synchronize personnel information |
| Form required field verification | Cover required fields of core documents such as on-site inspection records and penalty decisions | The consequence of errors is unqualified case file review, so core information must be ensured to be complete |
| Context length | 800–1200 characters | The core content of a single law enforcement document usually falls within this range, facilitating accurate reading by AI |
| Timeout threshold | 60 seconds | Law enforcement scenarios require rapid response to consultations; excessive waiting will affect service efficiency |
| Single interaction limit | First 5 historical records | Avoid excessive historical content interfering with current consultations |
| File size limit | 1000 MB | Adapt to the storage requirements of law enforcement recorder footage |

## Three common mistakes
- Phenomenon: Form content fails to display properly after shrinking the browser window and then enlarging it. Cause: Adaptive `formInput` layout was not configured, and only fixed-width input components were used.
- Phenomenon: Multiple associated knowledge bases cannot be selected for consultation and reply. Cause: The multi-option parameter of `userSelect` was not correctly enabled, and only a single knowledge base association mode was configured.
- Phenomenon: The form can still be submitted when the law enforcement document number is entered incompletely. Cause: The format verification rule of `formInput` was not enabled, and only basic required field verification was configured.

## How to confirm the configuration is properly set
- Adjust the browser window size to different widths, test the form display effect, and confirm that content will not be lost or misaligned.
- Try selecting multiple associated law enforcement data sources, and confirm that the `userSelect` component supports multi-option checking and submission.
- Intentionally enter an incomplete law enforcement document number, and confirm that the corresponding verification prompt is triggered after submitting the form.
- Submit complete core law enforcement document fields, and confirm that the form can normally generate the corresponding consultation and reply content.
