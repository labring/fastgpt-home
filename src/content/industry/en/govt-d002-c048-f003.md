# Administrative Licensing and Approval Service Consultation and Reply: Multi-turn Dialogue and Prompt Configuration
FastGPT v4.17.0

## What This Category of Data Looks Like
This category of data covers statutory documents including service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision letters, and license certificates. Data is sourced from the national integrated government service platform item database, administrative licensing item lists, departmental business approval systems, and electronic certificate repositories, with daily updates. Data is bounded by statutory licensing items, and includes structured fields such as item setting basis, handling conditions, application material lists, approval processes, and certificate formats. No extra non-statistical items are included.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Configuration Link
Statutory documents have fixed format requirements. Prompts must strictly limit reply content to match existing item databases, and no unpublicized handling conditions may be added. Daily updated data sources require prioritizing the latest synchronized item data when calling dialogue context, to avoid using outdated information. Structured application material fields must automatically associate the material number submitted by the user during multi-turn dialogue. This ensures accuracy of the verification process. Cross-departmentally retrieved electronic certificate data must clearly define permission boundaries in dialogue. This prevents unauthorized information disclosure.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 800–1200 characters | Adapts to the average length of administrative licensing item documents, avoiding truncation of critical statutory basis |
| Question Optimization Switch | Enabled | Assists users in converting vague inquiries into precise queries matching the item database |
| Single Reply Token Limit | 1500–2000 tokens | Matches the standard information volume of government service replies, complying with platform processing thresholds |
| `variables` Storage Fields | Application Number, Item Code | Used to associate specific administrative licensing items with the user's historical inquiries, ensuring coherent multi-turn dialogue context |
| Session Binding Rule | Bound by `chatId` | Ensures that multiple inquiries from the same user only call historical data within that session, preventing cross-session confusion |

## Three Common Misconfigurations
- Phenomenon: Token consumption cannot be viewed or counted during a session. Reason: Token counting configuration for `messages` is not enabled, or the global statistics interface is not associated.
- Phenomenon: Context confusion occurs after sending two consecutive messages in a multi-turn dialogue. Reason: Session context is not bound by `chatId`, causing the model to incorrectly associate inquiry content from different sessions.
- Phenomenon: Markdown-formatted approval opinions cannot be hidden when sent via the WeChat channel. Reason: Channel-specific format filtering rules are not configured, and native Markdown content is not converted to WeChat-compatible format.

## How to Confirm Configuration Is Complete
- Initiate a vague inquiry, observe whether the system automatically optimizes it into a precise query matching the administrative licensing item database, to confirm the question optimization switch is active.
- Initiate two consecutive inquiries about the same item, check whether the session context associates the correct application number, to confirm the `variables` storage fields are configured correctly.
- Trigger the token counting logic, view the session log to confirm corresponding statistical data is generated, to confirm the token counting configuration for `messages` is active.
- Test sending a message via the WeChat channel, confirm that Markdown-formatted approval opinions are correctly converted to a compatible format.
