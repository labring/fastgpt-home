# Administrative Licensing and Approval Inquiry and Response: Workflow Orchestration

## What this category of data looks like
Administrative licensing and approval inquiry data comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository. The update frequency is daily. Commonly involved documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision letters, and license certificates. The data primarily uses structured fields, including item code, handling conditions, application material list, certificate number, and similar items. It also includes some unstructured application texts and supporting materials.

## What constraints these characteristics impose on the "workflow orchestration" link
Multiple data sources with daily updates require the workflow to be configured with a scheduled synchronization mechanism to ensure called item lists and certificate data use the latest versions. Document types cover both structured and unstructured content, requiring different nodes to be configured in the orchestration to handle materials of corresponding formats. The legal nature of administrative licensing requires the workflow to strictly match item basis and handling conditions, and add exception verification links to avoid overdue completion or compliance risks caused by data errors. Cross-departmental data retrieval needs also require the workflow to support exception capture and retry configuration for cross-system call nodes.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `variables` | Bind parameters passed by the application link, initialize global variables | Supports passing dynamic parameters such as application number and item code via links to match personalized query needs for inquiry services |
| User selection | Configure as a confirmation node before generating correction notification letters | Used to verify the matching between application materials and the legal list, complying with the legal verification process of administrative licensing |
| `nodeId` | Bind the target node ID of the electronic certificate retrieval workflow | Reuse the general cross-departmental data retrieval process to avoid repeated configuration of similar call logic |
| Single search limit | Top 10 entries | Matches the conventional number of entries in the administrative licensing item database, ensuring coverage of all relevant inquiry items |
| Variable update | Set the trigger condition for empty operations to when the AI outputs no matching results | Used to clear invalid draft approval opinions to avoid incorrect pushing of unverified content |
| Scheduled synchronization | Execute daily from 2:00 AM to 4:00 AM | Matches the daily update rhythm of data sources, ensuring the workflow uses the latest item list and certificate data |

Note: The configuration values listed above are common starting points and should be evaluated against your own specific samples.

## Three common configuration errors
- Calling a sub-workflow causes subsequent nodes of the sub-process to not execute: Phenomenon: After the parent workflow triggers the sub-workflow, all nodes after the [User Selection] node in the sub-process remain unstarted, and no errors appear in the logs. Cause: The execution completion callback for the sub-workflow is not configured in the parent workflow, causing the process to wait for an untriggered confirmation signal.
- Updating a variable to a null value has no effect: Phenomenon: After assigning the AI output result to a variable, trying to clear the variable retains the original content. Cause: The null value override switch for the variable is not enabled, and the system retains the initial variable assignment by default.
- Database query returns an incorrect number of results: Phenomenon: The number of entries returned by querying the item database is less than expected, failing to cover all relevant inquiries. Cause: Exact matching rules for query conditions are not configured, and fuzzy query is used, causing some precisely matched items to be omitted.

## How to confirm the configuration is correct
- Pass preset link parameters, check if `variables` are correctly loaded into global variables to verify that the parameter transfer function works properly.
- Trigger a sub-workflow call, check if all nodes in the sub-process execute in sequence to verify that the cross-workflow call logic takes effect.
- Submit test application materials, trigger the scenario where the AI outputs no matching results, check if the variable is correctly cleared to verify that the null value update function works properly.
- Wait for the daily scheduled synchronization task to complete, check if the item database data is updated to the latest version to verify that the synchronization configuration takes effect.
