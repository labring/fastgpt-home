# Administrative Licensing Approval Service Consultation and Reply: Deployment and Upgrade

## What the Data for This Category Looks Like
Data for this category centers on statutory administrative licensing matters. Daily documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing approval decisions, and license certificates.
Data draws from the national integrated government service platform matter database, administrative licensing matter list, departmental business approval systems, and electronic certificate database. Update frequency is set to daily.
Data fields include matter code, handling conditions, application material list, statutory handling deadline, electronic certificate number, and others. No unified unit applies to these fields, and some fields must match format specifications from cross-department systems.

## Constraints on Deployment and Upgrade
Since data comes from cross-department systems and is updated daily, configure persistent database and cache connections during deployment to avoid data synchronization interruptions.
Daily document types are diverse, and fields have no unified format. Adapt multi-format parsing rules before deployment. Maintain compatibility with old document parsing logic during upgrades to prevent material verification errors.
For cross-department certificate retrieval, configure secure storage and access keys. Preserve compatibility with existing interfaces during upgrades to avoid disrupting approval workflows.
Upgrades must also support cross-version import of workflow applications to ensure business continuity.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/admin?authSource=admin&maxPoolSize=250` | Adapt to structured and unstructured data storage across multiple department systems, ensure stable daily data synchronization |
| `REDIS_URL` | `redis://:password@host:port/0` | Cache frequently called matter lists and electronic certificate data, reduce call frequency to cross-department systems |
| `DB_MAX_LINK` | `200–300 connections` | Limit database connection count to avoid resource exhaustion from high-frequency calls to cross-department systems |
| `FE_DOMAIN` | Public network HTTPS domain name of the deployment node | Meet secure access requirements for government services, ensure normal operation of front-end interactions such as voice functions |
| `STORAGE_S3_ENDPOINT` | Exclusive access address of government cloud storage service provider, set single file upload limit to 1000 MB | Meet compliance storage requirements for government data, ensure secure storage of approval documents and certificates |
| `FILE_TOKEN_KEY` | 32-byte random string generated in accordance with government data encryption standards | Ensure access security for uploaded application materials and approval documents, prevent unauthorized access |

## Three Common Misconfigurations
- Phenomenon: Voice function fails to operate normally after front-end page loading, and the console returns cross-origin access errors. Cause: `FE_DOMAIN` is not configured as an HTTPS domain name, which does not meet secure access requirements for government services, causing HTTPS-dependent voice components to fail initialization.
- Phenomenon: After upgrading, attempting to import an old-version approval workflow triggers an interface prompt of "application format incompatible", and import cannot be completed. Cause: Old-version applications were not exported per the version migration guide, or the upgraded system did not maintain compatibility with field structure changes from old-version workflows.
- Phenomenon: After upgrading to FastGPT v4.17.0, statistical charts of approval data fail to load, and the console returns errors related to field parsing failures. Cause: Cross-department data source mapping configurations were not updated synchronously after the upgrade, causing fields from original approval data to fail correct reading.

## How to Confirm Configurations Are Correct
- Access the public network HTTPS address configured for `FE_DOMAIN`, verify that the front-end page loads normally, and voice interaction components initialize correctly.
- Run a database connection test, confirm that connections for `MONGODB_URI` and `REDIS_URL` are operational, and current connection count does not exceed the configured value of `DB_MAX_LINK`.
- Upload a standard service guide document, verify that the storage configuration for `STORAGE_S3_ENDPOINT` saves files normally and generates accessible file links.
- Attempt to import an approval workflow application exported from an older version, confirm that the import process has no errors, and application node configurations are complete and available.
