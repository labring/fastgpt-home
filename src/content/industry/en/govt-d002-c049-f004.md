# Administrative Regulatory Document Legality Review: Service Consultation and Response - Workflow Orchestration

## What Data for This Category Looks Like
This category's data primarily comes from the regulatory and rule repository, higher-level law database, departmental policy document repository, and administrative regulatory document filing system, with no fixed update frequency. Daily processed documents include regulatory document drafts, drafting explanatory notes, legality review opinions, solicited comment summaries, and filing reports. Each document contains fields such as document title, drafting unit, text content, solicited opinion records, review opinions, etc. The volume of documents processed per run ranges from hundreds to thousands of characters, with no fixed batch update cycle. Workflows must adapt to dynamically changing data sources and document structures.

## What Constraints These Characteristics Impose on Workflow Orchestration
Decentralized data sources with no fixed update cycle require workflows to support dynamic calls to multi-source databases, avoiding hard-coded fixed data source configurations. Diverse daily document types and inconsistent fields require configuring `variables` to adapt to field extraction rules for different documents, ensuring accurate information extraction. The most time-consuming higher-level law comparison and text review steps involve chained multi-stage retrieval and validation, requiring workflows to support result passing between nodes and conditional branch jumps. Pre-validation of potential error consequences is required. A result review node must be added at the end of the workflow to ensure that review results meet the format requirements of the filing system.

## Configuration Guidelines
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Multi-source database call rules | Poll in the order of filing system, regulatory repository; set single call timeout to 600 seconds | Decentralized data sources with no fixed update cycle require coverage of all necessary data sources; timeout setting adapts to cross-database retrieval latency |
| `variables` configuration | Configure extraction fields separately for drafts and review opinions; automatically skip empty-value fields | Diverse daily document types and inconsistent fields, adapting to information extraction needs for different documents |
| Node chaining order | First retrieve higher-level law basis, then review rights and obligations, finally summarize opinions | Matches the execution order of the most time-consuming business links, prioritizing core validation |
| `nodeId` mapping | Configure a unique `nodeId` for each cross-workflow call node | Avoids node conflicts during cross-workflow calls, ensuring accuracy of call links |
| Single retrieval result limit | Top 10 results | Regulatory repository search results are typically sorted by relevance; top 10 results cover core references and avoid redundant data |
| Context window | Calibrated based on actual testing | Adapts to documents and retrieval results of varying sizes, ensuring model processing accuracy |

## Three Common Misconfigurations
- Symptom: After workflow A calls workflow B, nodes following the [User Selection] node in workflow B do not execute, and the interface shows the node status as not started. Cause: No correct `nodeId` mapping configured for the cross-workflow call node, resulting in interrupted call links and subsequent nodes failing to receive trigger signals.
- Symptom: Attempting to update the output result of a previous AI model to an empty value, but the variable panel shows no change in value, and no error is logged. Cause: Empty value override permission was not enabled via `variables` configuration; the default rule retains the original variable value, and content cannot be cleared directly via variable updates.
- Symptom: Database retrieval timeout occurs during workflow execution, and the interface returns status code 504. Cause: No reasonable single call timeout period was set; cross-database retrieval latency exceeds the system default threshold, causing workflow interruption.

## How to Verify Successful Configuration
1.  Trigger workflow execution, check whether the return results of the multi-source database call node cover all configured data sources.
2.  For different types of test documents, verify that field extraction via the `variables` configuration is accurate, and that empty-value fields are correctly skipped.
3.  Initiate a cross-workflow call test, confirm that the [User Selection] node and subsequent nodes in the called workflow execute normally.
4.  Manually update a variable to an empty value, verify that the empty value override rule from the `variables` configuration takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
