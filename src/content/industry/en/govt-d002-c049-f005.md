# Administrative Regulatory Document Legality Review: Service Consultation and Reply - Tool Calling and Plugins

## What the data for this category looks like
The core data for this category revolves around the full lifecycle of administrative regulatory document generation and review. Daily processed documents include draft regulatory documents, drafting explanations, legality review opinions, summary of solicited comments, and filing reports. Data sources cover regulatory and rule databases, higher-level law databases, departmental policy document databases, and administrative regulatory document filing systems. Update cycles are not fixed. Data fields include document numbers, drafting units, review key points, summary of comments entries, and more. The character volume of single review-related documents varies widely. The workflow must support both structured and unstructured text formats.

## What constraints do these characteristics impose on the tool calling and plugin workflow
The data characteristics of this category impose multiple constraints on the tool calling and plugin workflow. Multi-source heterogeneous data sources and non-fixed update cycles require plugins to support dynamic access to multiple data types such as regulatory and rule databases and higher-level law databases. Plugins must also adapt to incremental synchronization logic to avoid data lag or redundancy. Diverse document types including drafts, drafting explanations, and comment summaries require tools to support parsing of different text formats, to ensure complete extraction of review key points. The core higher-level law comparison process requires the matching logic called by tools to strictly follow legal provision hierarchy and formulation authority, to prevent incorrect associations. The need for multi-department comment summaries also requires plugins to support structured aggregation, to ensure traceability of review basis, in compliance with FastGPT v4.17.0 plugin configuration specifications.

## How to Set Configuration
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `function` | Administrative regulatory document legality review requires fixed calling of compliance verification tools to avoid triggering general question-and-answer mode, in compliance with FastGPT v4.17.0 configuration specifications |
| Single plugin call timeout | 300–600 seconds | Review documents include multiple types of content such as drafts and higher-level law provisions, requiring sufficient time for comparison and parsing |
| `functionCall` | Specify the list of functions for permission verification and provision matching | Need to accurately call tools strongly related to legality review, filter irrelevant calling logic |
| Context window size | 8000–12000 tokens | Need to fully carry all content required for review, including drafts, higher-level law basis, comment summaries, and more |
| Result recall limit | Top 3 entries | Legality review only requires core higher-level law and authority basis; excessive recalled results will interfere with review judgment |
| Plugin trigger rule | Match by review task type | Different review scenarios require calling corresponding data source plugins to avoid matching errors caused by cross-scenario calls |

## Three Common Configuration Errors
- The plugin interface returns the error `You need to use the app key rather than the account key`. Cause: The calling key of the FastGPT application is not configured correctly, and the account key is mistakenly used as the plugin calling credential.
- The number of matching results returned by tool calling exceeds the preset range. Cause: A reasonable result recall limit is not set, or the configuration item is mistakenly modified to full recall.
- An empty legality review result is returned after plugin calling. Cause: Data sources such as the regulatory and rule database and higher-level law database are not correctly bound, or the context window configuration is too small, leading to truncation of core content.

## How to Verify Correct Configuration
- Call the FastGPT test interface, pass a single administrative regulatory document draft, and check whether the preset compliance verification plugin is triggered.
- View the tool calling log, confirm that the `toolChoice` and `functionCall` configuration parameters match the preset values.
- Verify the matching results returned by the plugin, confirm that only higher-level law and authority basis related to the current review are recalled.
- Test multi-source data access, check whether content from the regulatory and rule database and departmental policy document database can be pulled normally.
