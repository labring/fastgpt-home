# Performance Evaluation of Fiscal Expenditure: Service Consultation and Response - HTTP Interfaces and External Systems

## What data for this category looks like
Data sources for this category include the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Commonly processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. The data structure includes fields such as performance target details, corresponding fund usage records, evaluation score items, and rectification matters. Amount fields use yuan as the unit, while business indicator fields use the units corresponding to their respective business scenarios, such as number of projects, number of person-times.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The annual update feature means the interface does not need frequent calls. A single request must adapt to the transmission and processing scale of annual aggregated data. Data formats from multiple source systems vary, so the interface must support flexible field mapping and format conversion. Most supporting materials are unstructured attachments, so the interface must support file upload or external link transfer. The process involves multiple stakeholders such as finance bureaus and budget units, so the interface must include permission verification parameters to ensure data security. The document structure is complex and includes multiple types of business forms, so interface requests must support segmented transmission of batch data.

## How to set configurations

| `Authorization` | Bearer {API key generated by the platform} | Meets interface security verification requirements and adapts to permission control for multi-system docking |
| `variables` | Bind performance year and budget unit ID as global variables | Adapts to annual batch data requests and reduces repeated parameter passing |

## Three common mistakes
- An interface call prompts that the knowledge base is not bound. Upon inspection, the knowledge base was only configured globally in the platform, and the dedicated ID was not passed via the `variables` parameter. The root cause is that the knowledge base ID was not passed as a variable to the workflow interface, so the interface cannot locate the dedicated knowledge base for the corresponding business.
- A curl command error occurs when running the upgrade script after upgrading to FastGPT v4.17.0. The root cause is that the script does not adapt to the interface address format of the new version, and the old environment variable placeholder was not replaced, resulting in incorrect request parameters.
- The performance data fields returned by the interface are empty. The root cause is that the extraction rules for the `responseData` parameter were not configured correctly, and the JSON path of the business data was not matched, so core data was not extracted and returned.

## How to confirm the configuration is complete
- Call the test interface and check whether the returned `responseData` includes preset business fields such as performance indicators and fund records.
- View the global variable list and confirm that the performance year and budget unit ID have been correctly bound to the `variables` parameter.
- Verify that the `Authorization` parameter format complies with the Bearer token specification, and the interface returns a 200 status code.
- After associating the dedicated knowledge base, initiate a test request and confirm that the interface can retrieve the corresponding performance evaluation report documents.
