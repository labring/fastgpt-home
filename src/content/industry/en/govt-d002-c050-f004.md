# Fiscal Expenditure Performance Evaluation Service Consultation and Reply: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category originates from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. Updates occur on an annual basis. Commonly processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Most fields cover project codes, fund amounts, performance indicator completion status, and supporting material association relationships. The size of individual documents varies significantly, with no standardized fixed upper limit for single-record data volume.

## Constraints Imposed on Workflow Orchestration
The annual update rhythm requires workflows to trigger only during fixed cycles, without frequent runs. A single run handles a large number of documents with mixed formats. Configure multi-source data access nodes to adapt to materials from different sources. The requirement for multi-field association means connect data verification nodes to validate the correspondence between fund expenditures and performance targets. Adjust for wide variation in individual document sizes by setting flexible input processing configurations. Set up a result verification link to avoid scoring deviations caused by incorrect data associations. Batch processing of large numbers of documents may trigger execution timeouts. Adapt file upload API calls to support multi-format materials. All these steps require targeted configuration during orchestration.

| Node ID Binding                   | Associate `nodeId` to the data verification link | Accurately locate the verification node corresponding to performance targets and fund expenditures, facilitating subsequent troubleshooting and adjustment of process logic |

## Three Common Misconfigurations
- Phenomenon: Workflow execution is forced to terminate after exceeding 1200 seconds, and the interface displays a timeout status code. Cause: The single node timeout configuration was not adjusted for the large data volume of annual processing in this category, and the timeout setting for general small-volume tasks was retained.
- Phenomenon: Some supporting materials fail to parse normally after calling the file upload API. Cause: The input processing node adapted to multi-format documents was not configured, and only a single file type is supported.
- Phenomenon: The workflow can be triggered without completing required field entries in the form, leading to missing key project information in subsequent verification links. Cause: No pre-verification rules for form triggers were set, and the completion condition for required fields was not bound.

## How to Confirm Proper Configuration
- Submit a typical annual performance self-assessment form and associated supporting materials for simulation, then verify that the workflow triggers as expected and completes the node chain.
- Review the workflow timeout configuration item, confirm that the value range matches the estimated time for single processing in this category.
- Test the form trigger logic by attempting to submit without filling in required fields, then confirm that the workflow cannot start.
- Upload supporting materials in different formats, then check that the input processing node can normally identify and parse the content.
