# Government Fiscal Expenditure Performance Evaluation Service Inquiry and Reply: Forms and Interaction
Reference only; verify against the target FastGPT release and deployment documentation.

## What Does the Data for This Category Look Like
The core data sources for this category include the budget management integrated system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Daily processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Typical participating subjects include finance bureau performance departments, budget units, third-party evaluation agencies, and competent departments. The data structure primarily consists of structured form fields and unstructured supporting materials, requiring support for multi-source data integration and verification needs.

## What Constraints Do These Characteristics Impose on the Forms and Interaction Link
Multi-source data sources require the form interaction link to support field mapping across different systems, to avoid errors from manual entry. The annual update frequency means the form lifecycle must match the annual project cycle, requiring support for draft saving and staged submission. Multiple document structures require forms to be split into modules by document type, adapting to different entry logic. The most time-consuming supporting material collection and verification link requires interaction to support batch upload and progress display, reducing repeated user operations. The severe consequences of errors require forms to have strict required field validation and error prompts, avoiding missing core data.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `formInput` | Split form modules by document type | Adapt to entry requirements for multiple structured documents such as performance target forms and self-assessment forms |
| `userSelect` | Limit selectable subjects to finance bureau performance departments, budget units, and third-party evaluation agencies | Match the scope of typical participating subjects, reduce invalid selections |
| Batch upload configuration | Single file maximum 50 MB, total batch maximum 1000 MB | Match the typical size and total volume of supporting materials |
| Search result display limit | Top 5 entries | Match the typical number of supporting materials for single verification |
| Required field validation | Real-time validation before submission | Ensure core fields such as performance targets and fund data are complete |
| Timeout setting | Auto-save draft after 600 seconds of inactivity | Adapt to long-cycle filling scenarios for annual projects |

## Three Common Misconfigurations
- Phenomenon: The radio variable for the user selection component fails to load the globally stored performance project number. Cause: The global variable is not bound to the data source parameter of the radio component, resulting in failed variable transfer.
- Phenomenon: The supporting material content in AI replies is not rendered in real-time chunks. Cause: The streaming interaction parameter of `formInput` is not configured correctly, and the chunked receiving function is not enabled.
- Phenomenon: "Parameter format error" is returned when submitting the form. Cause: The field format of fund payment data is not validated, and the return data structure of the budget management integrated system is not matched.

## How to Verify Proper Configuration
- Access the user selection component, verify the selectable subject range matches the typical participating subjects.
- Test the batch upload function, verify the uploaded file size limits match the configured values.
- Trigger required field validation, verify corresponding prompts appear when core fields are left unfilled.
- Enable streaming response testing, verify AI reply content is displayed in real-time chunks.

The values provided here are common starting points and should be evaluated against the reader's own samples.
