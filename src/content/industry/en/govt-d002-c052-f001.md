# Department Final Accounts and Financial Reports: Service Consultation and Response — HTTP Interfaces and External Systems

## What this category of data looks like
Reference only; verify against the target FastGPT release and deployment documentation.

## What constraints do these characteristics impose on HTTP interfaces and external systems?
Annual update frequency means interface call frequency should be kept low. Configure annual caching of pulled final account data to reduce repeated requests. Multi-source data access requires interfaces to support authentication methods for different systems. Pass the system identifier via `variables` to distinguish data sources. Requirements for aggregating subordinate unit reports mean interfaces must support pulling data by level parameters. Single return data volume must match the complexity of the report structure. Data verification and audit requirements mean fields returned by interfaces must strictly correspond to standard final account report fields, to avoid missing fields or caliber deviations.

## How to Configure Parameters
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {<system-specific secret key>}` | Different data sources require independent authentication. This parameter distinguishes call permissions and ensures data access security |
| `variables` | `{"dataSource": "integrated budget management", "reportLevel": "current level + subordinate levels"}` | Distinguishes data sources and aggregation levels, adapts to multi-system access and subordinate report aggregation business needs |
| `responseData` | `Only returns core fields of final accounting statements + error codes` | Reduces invalid data transmission, adapts to the need for precise field matching during audit verification |
| Single request data limit | `800–1200 characters` | Matches the average character count of a single page of department final account reports, avoids interface timeouts |
| Cache validity period | `365 days` | Data is updated annually, so frequent cache refreshes are unnecessary, reducing interface call pressure |
| Authentication timeout | `60 seconds` | Covers the average response delay for cross-system data pulling, ensuring success rate of cross-system calls |

## Three Common Misconfigurations
- Phenomenon: A `401 Unauthorized` status code is returned after calling the interface, and core fields are empty. Cause: The `Authorization` parameter is not configured correctly, and the dedicated authentication key for the corresponding data source is not used, resulting in authentication failure.
- Phenomenon: When viewing the source field returned by the interface, only a generic identifier is displayed, and it cannot match the specific document type of the department final account report. Cause: No document classification parameter is passed via `variables`, causing the source field to not be filled according to the final account report standards.
- Phenomenon: Interface calls time out, returning a timeout error. Cause: The data volume configured for a single request is too large, exceeding the system processing limit, and the character count or number of data entries for a single request is not adjusted based on actual measurement.

## How to Verify Successful Configuration
- Call the interface and pass the preset `variables` parameter, check if the returned `responseData` includes the core fields of the department final account report.
- View authentication logs, confirm that call requests for different data sources can pass verification via the `Authorization` parameter.
- Simulate an annual data update and call the interface, check if the cache automatically refreshes and the returned latest data matches the source system data.
- Pull subordinate unit data, confirm that the number of returned results matches the preset number of subordinate units.
