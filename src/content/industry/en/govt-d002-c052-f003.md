# Department Final Accounts and Financial Report Inquiry and Response: Multi-turn Dialogue and Prompt Words

## What This Category of Data Looks Like
This category of data comes from the Unified Budget Management System, Centralized Treasury Payment System, Accounting System, and Asset Management System. Updates occur annually. Commonly processed documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Documents contain fields such as budget execution figures, actual revenue and expenditure, asset and liability details, and difference explanations. Units are mostly ten thousand yuan or yuan. Some fields require matching corresponding codes of treasury payment transaction records. The content scale of a single annual document is relatively concentrated.

## Constraints on Multi-turn Dialogue and Prompt Words Links
Annually updated concentrated data and combinations of multiple documents can easily cause the total context length of a single dialogue to exceed the model's capacity limit. Documents must be properly sliced. Documents exported from different systems have minor format differences. Prompt words must clearly define unified field identification and verification rules to avoid inconsistent response standards. Inquiry scenarios for this category occur after the end of the fiscal year, differing from the pre-event planning of the budget preparation phase. Responses must be based on actual revenue and expenditure and asset data. Most inquiries involve account statement verification and explanations of budget execution differences. Multi-turn interactions must retain historical context to link subsequent questions, ensuring responses are based on the complete annual final account background. Data must match exclusive rules such as treasury payment codes, and prompt words must clearly define verification logic to prevent errors in public data standards.

## How to Set the Configuration
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` | Fixed to bind the current session | Ensure multi-turn dialogue context is linked to the correct session instance |
| `variables` | Preset final account field constants | Unify field names and unit rules used in responses |
| Chunk Length | 800–1200 characters | Match the single-page content length of department final account documents, avoid information breakage affecting associated analysis |
| Overlap Length | 100–200 characters | Retain cross-chunk account and statement associated fields, ensure coherent context when verifying treasury payment data |
| Maximum Context Length | Calibrated based on actual testing | Adapt to the total length of multiple annual final account documents, avoid exceeding the model's carrying limit |
| Number of Historical Messages Retained | First 10 messages | Cover multi-turn interactions for a single inquiry, retain historical basis for budget execution difference explanations |

## Three Common Misconfigurations
- Tool call logs remain in dialogue response results: This occurs because prompt words do not explicitly hide the output content of tool execution links, causing intermediate information from tool calls to be returned together.
- Context overflow error is triggered after uploading annual final account documents: This occurs because reasonable chunk and context length limits are not set, and multi-piece annual documents are not sliced.
- Responses are off-topic after multi-turn dialogue: This occurs because the `messages` parameter is not configured to link historical interaction content, or the number of retained historical messages is set too low, causing subsequent questions to fail to connect to the earlier final account data background.

## How to Verify the Configuration Is Correct
- Launch a multi-turn dialogue involving account statement verification, check if responses to subsequent questions are linked to earlier final account data, confirm that historical interactions are correctly recognized by the system.
- Upload a single annual final account document, test the dialogue context length, confirm that no overflow error is triggered.
- Launch an inquiry after configuring prompt words, check that the returned result only contains AI response content, with no tool call execution logs remaining.
- Check the system's historical dialogue retention rules, confirm that the set number of historical messages meets the interaction needs of a single inquiry.
