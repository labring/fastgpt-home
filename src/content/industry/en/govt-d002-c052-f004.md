# Department Final Accounts and Financial Report Service Consultation and Reply: Workflow Orchestration

## Data Profile for This Category
Data sources for department final accounts and financial reports include the integrated budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Daily generated documents cover department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The data structure primarily uses standardized report fields, with core content such as unit codes, income and expenditure details, and asset and liability balances. No high-frequency temporary new fields are added. All data must go through cross-system cross-verification before the final report is generated.

## Constraints Imposed on Workflow Orchestration
The annual update frequency means the workflow does not need frequent triggers. It only needs to run during the final account cycle, but cross-system data pulling stability must be maintained. The fixed document structure requires document parsing nodes in the workflow to adapt to standard report fields, to avoid errors from unstructured parsing. Multiple system data sources create data verification needs, so links such as account statement verification and treasury payment data matching must be added to the workflow. The serious impact of errors requires the workflow to include exception interception nodes. These nodes issue early warnings for situations like data mismatches and missing fields, preventing final statements from being returned or audit risks from occurring.

## Configuration Guidelines
This page uses FastGPT v4.17.0 for configuration.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Node | Trigger according to annual final account cycle | Match the annual data update frequency to avoid invalid runs |
| Multi-system data pulling timeout threshold | 600 seconds | Cover the conventional time required for cross-system data synchronization |
| `variables` binding fields | Bind final account report number, unit code | Accurately match business data scope and narrow search scope |
| Document parsing node file size limit | 1000 MB | Adapt to large consolidated final account statements and attached documents |
| Tool call node output rule | Only return processing result summary | Avoid redundant system call logs in output |
| `nodeId` filtering configuration | Bind tool call node ID | Accurately control the source node of output content |

## Three Common Configuration Errors
- Enabling multimodal image recognition results in failed parsing of uploaded images and a prompt that image content cannot be provided. Cause: Only the global multimodal switch is enabled, the image input and output link is not configured in the corresponding workflow node, and the image storage path parameter in `variables` is not bound.
- Full tool call logs remain displayed after tool call completion. Cause: The output filtering rule of the tool call node is not correctly configured, or `nodeId` is not used to specify only retaining output from the target node.
- The document parsing node returns a 404 error after server deployment. Cause: The local environment uses relative paths to locate uploaded files, and the path is not updated to an absolute path after server deployment, so the parsing node cannot find the target file.

## How to Verify Successful Configuration
- Trigger a simulated annual final account data pull, and confirm that data from each system is correctly matched per the fields bound in `variables`.
- Upload a standard department final account statement, and confirm that the document parsing node correctly extracts core field content from the statement.
- Run the tool call node, and verify that the output only includes the processing result summary, with no redundant system call logs.
- Upload an image related to the final account statement, and confirm that the multimodal node correctly recognizes the image and returns relevant data descriptions.
