# Department Final Accounts and Financial Report Service Consultation and Response: Tool Calling and Plugins

## What data for this category looks like
Data for this category mainly comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The overall structure follows a fixed report format. Fields cover actual revenue and expenditure details, asset and liability status, budget execution difference explanations, and no additional custom extended fields.

## What constraints these characteristics impose on tool calling and plugins
The annual update feature means tool calling does not require frequent data pulling. It can be configured for annual scheduled synchronization or on-demand triggering. Fixed report formats and clear field ranges allow plugin calling to preset fixed parameter templates, reducing field verification costs. Data from multiple system sources requires tool calling to complete cross-system data pulling and verification. The tool calling chain must support calling interfaces from different systems in sequence to complete account statement matching. The data verification link is time-consuming and has serious error consequences. Tool calling must add a data consistency verification step to avoid generating responses using unvalidated raw data directly.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the cross-system tool calling requirements of this category, automatically selects the appropriate interface to complete data pulling |
| `functionCall` | Enabled | Supports passing fixed structured parameters, matching the fixed field format requirements of department final account statements |
| Single tool call timeout | `600 seconds` | Covers the typical time required for cross-system data pulling and account statement matching, prevents mid-call interruptions |
| Tool call result caching | Set according to the annual update cycle | Matches the annual update frequency of this category, reduces overhead from repeated pulling of historical data |
| Maximum tool call times | `Top 3 times` | Limits the number of cross-system verification cycles, prevents invalid repeated calls |

## Three common mistakes
- Phenomenon: An SSE connection failure error is displayed in the interface, and tool calling cannot be completed. Cause: FastGPT v4.17.0 or higher is not used to enable MCP tool support, and the MCP service address and authentication information are not correctly configured.
- Phenomenon: After tool calling terminates, subsequent conversations cannot switch to non-tool response mode. Cause: The tool call binding marker in the context is not cleared after tool calling terminates, and the system still attempts to call tools according to preset rules.
- Phenomenon: After configuring `functionCall` to mandatory mode, the generated response does not match the fixed field format of department final account statements. Cause: No function call parameter template corresponding to the report fields is preset, resulting in the data format returned by tool calling not meeting requirements.

## How to confirm the configuration is complete
- Initiate a consultation containing department final account statement fields, check whether the tool call logs pull data from the corresponding systems in the preset sequence.
- Test annual data consultation outside the update cycle, confirm that the system directly returns cached historical data without triggering new tool calls.
- Configure `toolChoice` to `auto`, initiate a cross-system data verification consultation, confirm that the system automatically selects and calls the required tool interfaces.
- Trigger a tool call timeout scenario, confirm that the system terminates the call and returns a clear timeout prompt after `600 seconds`.

The values provided are common starting points and should be measured against the reader's own samples.
