# Department Final Accounts and Financial Reports: Service Consultation and Response - Document Parsing and Chunking

## What This Category of Data Looks Like
Data originates from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system, updated on an annual basis. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The structure primarily combines standardized financial report fields and textual descriptions, including revenue and expenditure amounts, asset and liability values, budget execution difference explanations, and other content. A single document may contain multiple types of reports and explanatory text. FastGPT v4.17.0 supports the basic parsing logic for this document type.

## What Constraints These Characteristics Impose on Document Parsing and Chunking
Documents updated annually must support single batch uploads. A single document may reach 100,000 Chinese characters or 15,000 data rows, which creates clear requirements for parsing and chunking time and chunking rules. Standardized financial report structures require retaining the link between table headers and data rows to prevent loss of field correspondence after chunking. Document formats vary across exports from different systems, so parsing logic must support multiple file types. Errors directly impact audit and public data standards, so chunking must ensure key information is not omitted or incorrectly split.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Adapts to the information density of single chunks in financial documents, avoiding including too many report rows or explanatory paragraphs in a single chunk |
| `chunkSplitter` | Split by paragraph + table header | Distinguishes between table headers and data rows of final account reports, as well as natural paragraphs of final account explanations |
| `customPdfParse` | Enabled | Preserves the table structure of financial reports, avoiding chaotic text after parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports single upload of multi-document packages for annual final accounts |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing time for large files (100,000-character Word documents, 15,000-row Excel files) |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for the structured characteristics of financial documents, compatible with the manual configuration logic of FastGPT v4.17.0 |

## Three Common Misconfigurations
- Symptom: After uploading a 100,000-character Word document or 15,000-row Excel data file, the interface shows abnormal chunk count and vectorization task failure. Cause: The `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` parameters were not adjusted for large files.
- Symptom: Parsed final account report chunks only contain data rows, with no corresponding table header fields. Cause: The `chunkSplitter` was not configured to split by report table headers and data rows.
- Symptom: When uploading files larger than 10 MB to the knowledge base, chunking fails even after multiple retries. Cause: `PARSE_FILE_TIMEOUT_SECONDS` was not set appropriately, causing parsing to time out and interrupt.

## How to Verify Configurations Are Correct
- Upload a single 100,000-character Word document, check that the chunk count meets expectations and no abnormal errors occur.
- Parse a department final account report PDF, check that chunks retain the association between table headers and corresponding data rows.
- View parsing task logs, confirm there are no timeout-related error prompts.
- Test chunked text fragments, confirm that natural paragraphs of final account explanations are not incorrectly split.

The values provided here are common starting points, and should be evaluated against the user’s own samples.
