# Department Final Accounts and Financial Report Inquiry and Response: Model Access and Configuration

## What data for this category looks like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Data fields cover actual revenue and expenditure details, asset and liability balances, budget execution difference explanations, and more. The size of a single document ranges from dozens to hundreds of pages. Field formats follow unified fiscal system specifications.

## What constraints these characteristics impose on model access and configuration
Data updated on an annual basis means the knowledge base does not require frequent incremental synchronization. Only a full update is needed before the final account cycle. Single documents have large size and contain multiple types of associated fields. This requires the model context window to support long text input, to avoid truncation of critical data. Data from multiple systems that follows the same specifications requires the model to accurately associate account statements and payment data. A stable model call logic must be configured. Additionally, due to the serious consequences of errors, the random generation parameters of the model must be restricted to strictly control the accuracy of generated content.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of annual final account documents per batch, preventing truncation of key information in long texts |
| `maxTokens` | 2000–3000 token | Controls the output length of responses to single inquiries, ensuring complete content such as final account explanations and budget execution difference explanations |
| `quoteMaxToken` | 1500–2000 token | Limits the fragment length of source documents referenced, ensuring accurate referencing of account statements and treasury payment data without exceeding the context window |
| `temperature` | 0.1–0.3 | Reduces randomness in generated content, ensuring final account data formats and difference explanations comply with unified fiscal system specifications |
| `AIPROXY_API_ENDPOINT` | Fill in the actual deployment address of the self-built model | Adapts to common community scenarios for self-built model access |
| `AIPROXY_API_TOKEN` | Fill in the exclusive token generated by the deployment platform | Completes identity verification for model calls, ensuring valid and legal access permissions |

## Three common configuration errors
- An interface prompt displays "no available model". Troubleshooting reveals that `AIPROXY_API_ENDPOINT` was not correctly filled with the self-built model deployment address, or `AIPROXY_API_TOKEN` was configured incorrectly.
- Re-ranker model test errors occur, limited to this scenario. The cause is failing to adapt `quoteMaxToken` to the long fragment references in final account documents, leading to context length exceeding model limits during re-ranking.
- Model-generated responses contain data format errors. The cause is an overly high `temperature` value, causing generated content to deviate from unified fiscal system final account data specifications.

## How to confirm configurations are properly set
- Call the model test interface, input a single final account explanation document, and check if the returned result is complete with no text truncation. Confirm that `maxContext` and `maxTokens` configurations match the current document length.
- Submit a test query involving treasury payment data association, and check if the model can correctly associate account statements and payment data. Confirm that `quoteMaxToken` configuration is reasonable.
- Generate multiple rounds of test responses, and check if response content remains consistent across rounds. Confirm that `temperature` configuration meets accuracy requirements.
- Verify the self-built model access address and token, and check model call logs for successful return records. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations are correct.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
