# Department Final Accounts and Financial Report Service Consultation and Reply: Forms and Interactions

## What data in this category looks like
This category of data originates from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. It is updated annually. Core documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Fields cover actual revenue and expenditure details, asset and liability status, budget execution difference explanations, and more. Units follow unified fiscal standards, and the field count and structure of a single document adjust slightly based on the unit’s hierarchy.

## What constraints these characteristics impose on the forms and interactions link
The annual update rhythm requires the form’s default time range to be set to the previous natural year, to avoid cycle errors caused by manual adjustments. Multiple system data sources require the form to configure cross-source data verification rules that match each system’s field formats and value ranges, to ensure imported data complies with fiscal system requirements. The need to summarize subordinate unit statements requires the form to support a batch import interaction entry for subordinate unit data, while also providing data consistency verification prompts to reduce manual verification workload. The link for explaining budget execution differences requires the form to support long-text input and paragraph editing, to facilitate filling in detailed explanatory content. The serious consequences of errors require the form to add required field highlighting, real-time format verification, and a full verification pop-up before submission, to block potential erroneous data.

## Three Common Mistakes
- Symptom: The default value of the form input node fails to correctly reference the global variable, and the field is empty after submission. Cause: The global variable’s scope is not correctly bound, or the variable name contains special characters leading to parsing failure.
- Symptom: The system prompts a format error during batch data import, and the import cannot be completed. Cause: The field order of the imported file does not match the form’s configured verification rules, and fiscal system field specifications are not followed.
- Symptom: The system prompts that the field exceeds the limit after submission, and the data cannot be saved. Cause: The character count of the long-text input exceeds the configured limit range, and the value is not adjusted based on the actual needs of the final account explanation.

## How to confirm the configuration is complete
- Open the form configuration page, verify that the global variable and default value bound to the `formInput` component match the annual business cycle.
- Upload a test data file that complies with fiscal specifications, confirm that the batch import function correctly identifies and loads the data.
- Fill in all required fields and trigger submission verification, confirm that the system displays a full verification prompt pop-up.
- Switch user roles, verify that the permission range configured by `userSelect` takes effect, and unauthorized users cannot access the form.
