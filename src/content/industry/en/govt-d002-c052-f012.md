# Department Final Accounts and Financial Report Inquiry and Response: Deployment and Upgrade

## What data for this category looks like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is once per year. Daily processed documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Fields include income and expenditure details, asset and liability balances, budget execution difference explanations, and more. Units are mostly ten thousand yuan or yuan. Reports aggregate reported data from subordinate units by hierarchy.

## Constraints on Deployment and Upgrade
This category has a large annual updated data volume, and requires connections to multiple business system data sources. Reserve sufficient database connection and storage resources during deployment. Report documents have a fixed structure but multiple field levels. Adapt knowledge base configuration to structured report chunking and indexing rules. For upgrades to FastGPT v4.17.0, pay special attention to the data structure of final accounts from previous years. Avoid archived data becoming unqueryable after version updates. Additionally, data errors affect audits and public disclosure. Configure a failure retry and exception alert mechanism during deployment to ensure the accuracy of inquiry and response.

## How to Configure
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Fill in the MongoDB cluster connection address connected to the fiscal business system, including read-write permission authentication information | Store vector indexes and historical archived data of annual final account statements, adapting to storage requirements for multi-system connections |
| `PG_URL` | Fill in the read-only PostgreSQL connection address of the unified budget management system | Read structured budget execution and income and expenditure detail data, ensuring the security of data reading |
| `REDIS_URL` | Fill in the connection address of the locally deployed Redis instance, configure the memory limit to 1000 MB | Cache summaries of frequently queried final account data, reducing the pressure of repeated database reads |
| `STORAGE_S3_ENDPOINT` | Fill in the access endpoint address of the internal object storage | Store uploaded final account statement originals and parsed text data |
| `FILE_TOKEN_KEY` | Configure a randomly generated 32-bit string as the secret key | Verify the legitimacy of file upload requests, preventing unauthorized access to statement files |
| `FE_DOMAIN` | Fill in the access domain name of the internal inquiry and response system | Configure jump links for the inquiry and response page, linking to the official entry of the fiscal business system |

## Three Common Mistakes
- Symptom: File parsing fails after local deployment, with the "File parsing failed" error displayed in the interface. Cause: `FILE_TOKEN_KEY` or `STORAGE_S3_ENDPOINT` is not configured correctly, causing the file upload and storage link to be unavailable.
- Symptom: The basic chart plugin outputs "none" and does not generate the expected final account data chart URL. Cause: The fiscal business database pointed to by `PG_URL` is not correctly associated, causing the plugin to fail to read income and expenditure detail data to generate corresponding charts.
- Symptom: Multimodal visual analysis requests have no response or return an incorrect format. Cause: The structured visual elements of final account statements are not adapted, and the default visual model cannot accurately identify the report header and field format, resulting in parsing failure.

## How to Verify Successful Configuration
- Run the database connection test script to verify the validity of the connections for `MONGODB_URI` and `PG_URL`, confirming that test final account statement data can be read.
- Upload a standard department final account statement file, check whether the file parsing result includes the structured fields and content of the report, verifying that `STORAGE_S3_ENDPOINT` and `FILE_TOKEN_KEY` are configured correctly.
- Call the basic chart plugin, pass in test income and expenditure detail parameters, check whether a valid chart URL is generated, confirming that the database association configuration is correct.
- Access the inquiry page corresponding to `FE_DOMAIN`, verify that the page jump and data display link is working properly.

The values provided are common starting points and should be measured against the reader's own samples.
