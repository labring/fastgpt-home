# Administrative Budget Preparation Inquiry and Response: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category typically comes from the unified budget management system, departmental staffing establishment system, prior-year final accounts, project repository, and Ministry of Finance budget preparation notices. The update frequency follows an annual cycle. Daily produced documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. Data fields cover unit codes, staffing numbers, project expense amounts, performance indicator values, and more. Common units are ten thousand yuan and person. Some fields must comply with unified fiscal coding rules.

## Constraints Imposed on HTTP Interfaces and External Systems
The low-frequency annual update characteristic requires interfaces to support batch synchronization of historical annual data, to avoid repeated calls to high-frequency interfaces. Multiple data sources require interfaces to adapt to authentication formats of different systems. Unified docking must handle differences in field mapping. The fixed structure of documents requires that the `responseData` returned by the interface strictly matches the field order and coding rules specified by fiscal regulations. Otherwise, the budget preparation tool will fail to recognize the data. The time-consuming summary and review processes require interfaces to be configured with reasonable timeout thresholds, to prevent request interruptions caused by large data volumes.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer Token exclusive to fiscal systems, valid for 7 days | Match the authentication rules of the unified budget management system, avoid frequent token retrieval |
| `variables` | Preset two global variables: annual budget cycle and unit hierarchy | Adapt to batch requests from different budget units, reduce repeated parameter entry |
| `responseData` | Map fields according to fiscal coding rules, retain a copy of original data | Ensure the connected budget preparation tool can directly parse returned content, facilitate subsequent review and traceability |
| Single request data limit | 1000 entries | Match the maximum data volume for single exports from the project repository, prevent interface overload |
| Timeout threshold | 300 seconds | Cover the maximum time required to summarize budget data from subordinate units, avoid request interruptions |

The above configurations are based on FastGPT v4.17.0.

## Three Common Misconfigurations
- Symptom: The `responseData` field returned by the interface is empty, and the budget preparation tool prompts a format error. Cause: The returned data was not mapped according to unified fiscal field coding rules, causing the tool to fail to recognize valid content.
- Symptom: Request times out, with a 504 status code returned. Cause: The single request data volume exceeds the interface's carrying limit, and batch requests were not split, resulting in processing time exceeding the threshold.
- Symptom: Budget submissions are returned for revision by the fiscal department. Cause: The latest Ministry of Finance budget preparation notice data was not synchronized to the interface, and outdated field rules were used for data submission.

## How to Verify Correct Configuration
- Call the test interface, check if `Authorization` can pass authentication from the unified budget management system and return a valid response.
- Import the preset `variables` variables, verify that parameters are automatically filled with the correct annual and unit information during batch requests.
- Compare the `responseData` fields returned by the interface with fiscal regulatory documents to confirm that field names and coding rules match.
- Simulate a batch request, observe the interface processing duration, and adjust the timeout threshold to cover actual business processing time.

The values provided are common starting points and should be measured against the reader's own samples.
