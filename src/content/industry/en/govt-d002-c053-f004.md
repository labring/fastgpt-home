# Department Budget Preparation Service Consultation and Reply: Workflow Orchestration

## What the data for this category looks like
Data related to department budget preparation typically originates from the unified budget management system, department staff establishment system, previous year final accounts, project library, and the Ministry of Finance budget preparation notice. The update frequency is annual. Commonly involved documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and similar items. Fields cover project codes, number of staff establishments, budget amounts, performance indicators, and similar items. Common units include ten thousand yuan, person, percentage, and similar units.

## What constraints these characteristics impose on the "workflow orchestration" link
Annual updated data sources require workflows to reset configurations annually. This prevents cross-year data from being mixed. Multi-source data access requires configuring cross-system variable binding. This ensures each node can uniformly call data across dimensions such as budget, personnel, and projects. Documents have many fields and complex structures. Parameter mapping rules must be configured in the workflow to map external system fields to internal variables. The most time-consuming calculation, review, and aggregation links must be split into independent nodes. This prevents single-node timeouts or errors from affecting the entire process. A verification link must also be reserved to intercept non-compliant budget data.

## Configuration Settings
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Variable Binding | Associate corresponding fields from the unified budget management system and staff establishment system | Data comes from multiple systems. `variables` must be used to store cross-node shared budget and personnel data |
| Node Trigger Condition | Trigger based on the budget year parameter in `variables` | Data updates annually. Workflows must start annually to avoid repeated execution |
| Context Length | 8000–12000 characters | Department budget-related documents have long content. Sufficient context is needed to carry historical calculation and review data |
| Single Request Limit | Top 10 entries | The volume of subordinate unit budget data pulled in a single request must be controlled to avoid request timeouts |
| Timeout Threshold | 600 seconds | Cross-system data pulling and expense calculation links take a long time. A reasonable timeout must be set |
| Node ID Identification | Distinguish calculation, review, and aggregation nodes by `nodeId` | Unique identifiers for each workflow node must be clearly defined to facilitate subsequent troubleshooting and adjustments |

## Three Common Mistakes
- Two AI chat nodes connected in series in a workflow. The final output includes the reply content from the first node. This occurs because no context filtering rules are configured. The default setting retains input variables from previous nodes.
- Code execution node errors occur in the SaaS version. This occurs because local dependency packages related to budget preparation are not adapted, or the passed parameter format does not meet system requirements.
- HTTP request body parameters in the workflow are not correctly bound to variables. This occurs because the request body is not mapped to budget fields in `variables`, leading to empty parameters or incorrect formats.

## How to Confirm Proper Configuration
- Trigger a test workflow. Check whether variable outputs from each node match fields from external systems.
- Simulate cross-system data pulling. Confirm that the node completes the request within the 600-second timeout threshold.
- Test series-connected AI chat nodes. Confirm that the final output only retains target results, with no redundant previous reply content.
- Upload test budget documents. Confirm that the system can correctly identify and associate them with corresponding workflow nodes.

The values provided here are common starting points. They should be evaluated against relevant local samples.
