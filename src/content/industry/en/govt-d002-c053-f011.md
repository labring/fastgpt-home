# Department Budget Preparation: Service Consultation and Response - Forms and Interactions

## What This Category of Data Looks Like
Service consultation data for department budget preparation mainly comes from the integrated budget management system, department staff establishment system, prior-year final accounts, project library, and Ministry of Finance budget preparation notices. The update frequency is annual. Daily business documents include department budget drafts, project application forms, performance target forms, staff cost calculation forms, and budget approvals. Fields cover staff establishment count, project fund amount, performance target values, and similar items. Common units are ten thousand yuan, persons, and number of projects. Data must cover relevant information from the primary budget unit and subordinate budget units. The overall structure is complex and involves multi-system integration.

## What Constraints These Characteristics Impose on the Forms and Interactions Link
The annual update feature requires forms to support batch data import and validation for annual cycles, avoiding duplicate entry of basic information for the same year. Data from multiple system sources requires forms to have configured field mapping rules, enabling automatic alignment of data from different systems and reducing manual input errors. The complex document structure requires forms to display content in stages by business module, lowering the complexity of single-round filling. Diverse field units require forms to have built-in unit conversion prompts, preventing filling errors caused by inconsistent units. The hierarchical management business process requires forms to have configured permissions based on budget unit levels, ensuring data access complies with fiscal management regulations.

## Configuration Settings
The following configurations are formulated based on the form interaction rules of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Staged form grouping | Split into 3 groups: staff costs, project expenditures, performance targets | Matches the document structure of department budget preparation, reduces cognitive load for single-round filling |
| `formInput` field validation | Set positive integer validation for staff establishment count; set numerical validation ≥0 for project funds | Matches field rules of the staff establishment system and integrated budget management system, reduces filling errors |
| Single submission data limit | 1000 entries | Adapts to the maximum data volume for annual summary of subordinate unit budgets, avoids system overload |
| Timeout threshold | 600 seconds | Covers time requirements for cross-system data retrieval and batch calculation |
| `userSelect` permission configuration | Divide visible scope by budget unit level | Matches the hierarchical audit process of fiscal management, ensures data access compliance |
| Reorder retrieval switch | Enabled, set based on actual testing | Improves retrieval accuracy for complex budget documents, optimizes service consultation and response effects |

## Three Common Misconfigurations
- When calling the `formInput` interface, an "invalid parameter format" error is returned. The reason is that input structures are not unified, parameter formats differ across calling ends, and cannot match system validation rules.
- Timeout occurs when batch submitting subordinate unit budget data. The reason is that no reasonable timeout threshold is set, and the single submission data volume exceeds the system's carrying limit.
- After configuring `userSelect` permissions, some budget unit financial staff cannot access the corresponding form. The reason is that the permission division logic does not match the actual process of fiscal hierarchical management, leading to incorrect visible scope configuration.

## How to Verify Correct Configuration
- Manually enter values in different formats (such as with or without units) to check if corresponding error messages are triggered. Confirm that the `formInput` field validation rules take effect.
- Log in with a test account according to budget unit levels, confirm that only forms and data within the corresponding permission scope are accessible. Verify that the `userSelect` permission configuration takes effect.
- Submit simulated annual budget data, confirm that the form can complete summary and validation normally. Verify the rationality of the staged grouping configuration.
- Call the standardized interface format, confirm that the `formInput` input structure matches system requirements, with no parameter format errors.
