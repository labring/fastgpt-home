# Department Budget Preparation Service Consultation and Response: Deployment and Upgrade

## What the data for this category looks like
The data for this category mainly comes from the unified budget management system, department staff establishment system, prior-year final accounts, project library, and the Ministry of Finance’s budget preparation notice. Daily processed documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. The data update cycle is annual, with full updates only completed during the annual budget preparation period. Data fields include budget subject codes, staff establishment numbers, project application amounts, performance target indicators, etc. Corresponding document measurement rules must be followed, and there is no unified fixed measurement standard.

## What constraints these characteristics impose on deployment and upgrades
The annual data update cycle requires reserving a resource window for full data synchronization during deployment, to avoid impacting critical periods of annual budget preparation. Multiple heterogeneous data sources require configuring adaptation rules compatible with different system interfaces during deployment, and synchronously updating data source connection logic during upgrades to prevent data parsing errors. The need to process multiple types of business documents requires the system to support custom document parsing templates to adapt to different formats of budget-related files. The annual update rhythm reduces the need for frequent incremental synchronization configurations; full data refreshes can be triggered only when the budget preparation cycle starts, reducing unnecessary resource consumption.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Matches concurrent access demand during the annual budget preparation phase, avoiding database connection pool exhaustion |
| `MONGODB_URI` | Points to a dedicated MongoDB instance storing historical final accounts and project library data | Used to persist department budget preparation historical documents and consultation response records |
| `PG_URL` | Points to the PostgreSQL database connected to the unified budget management system | Stores real-time structured business data such as budget subjects and staff establishment information |
| `REDIS_URL` | Configure a dedicated cache instance with memory specification no less than `1000 MB` | Caches frequently queried budget indicator data to reduce access pressure on core databases |
| `STORAGE_S3_ENDPOINT` | Points to the access address of the internal unit object storage service | Used to store various business documents such as department budget drafts and performance target forms |
| `ROOT_KEY` | A strong key string custom-generated by the administrator | Ensures permission security for background system operations, complying with financial data confidentiality management requirements |

## Three common mistakes
- Symptom: After deploying the large model, GPU utilization remains at a low level for a long time, while CPU single-core occupancy stays at 100% continuously. Cause: No batch query strategy configured for the structured characteristics of budget data, leading to a large number of serial data queries occupying CPU resources and failing to fully utilize GPU computing power.
- Symptom: After upgrading to FastGPT v4.9.1, an unclickable mask layer appears on the login interface. Cause: Old frontend cache files were not cleared during the upgrade process, causing conflicts between new UI components and old cache files.
- Symptom: Unable to synchronize project library data after configuring the data source, with logs showing field matching failures. Cause: No data mapping rules configured in accordance with the interface specifications of the unified budget management system, causing the system to fail to recognize standard budget subject code fields.

## How to verify successful configuration
For deployments using FastGPT v4.17.0, follow these steps to verify configuration validity:
- Run a full data synchronization task, check that database connection logs have no errors, and that the number of synchronized data entries matches the number of entries filed in the project library after synchronization completes.
- Submit a consultation related to department budget preparation, verify that the system correctly calls cached budget indicator data, and that GPU computing power occupancy complies with preset scheduling rules.
- Access the frontend domain name `FE_DOMAIN`, check that the login interface has no abnormal mask layer, and that the identity verification process can be completed normally.
- Upload a department budget draft document, verify that the system correctly parses the project application amount field in the document, with no parsing failure prompts.
