# Work Consultation and Response for Flood Prevention, Disaster Mitigation and Emergency Duty: Tool Calling and Plugins

## What Data for This Category Looks Like
Business data for flood prevention, disaster mitigation and emergency duty typically comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Data updates occur daily. Some real-time monitoring data has update intervals shortened to minute-level.

Daily generated documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Common fields include rainfall and water level values, disaster severity levels, material quantities, number of transferred and resettled people, and corresponding units such as millimeters, cubic meters, pieces, and people.

## Constraints on Tool Calling and Plugins
Multi-source heterogeneous data sources require tool calling to support connecting multiple system interfaces at the same time. This prevents single-dimensional information from being retrieved in a single call.

Frequently updated real-time data requires tool calling timeout settings to match actual data pulling time. This stops warning delays caused by timeout interruptions.

Diverse document structures require tool calling to adapt to different parameter formats. For example, extracting specific values from rapid disaster reports differs from extracting item lists from material allocation slips.

Cross-departmental scheduling requires tool calling to link multiple types of plugins to complete data aggregation and command distribution. This reduces manual intervention steps.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to parallel tool call scenarios, automatically select tools matching current inquiries |
| Tool call timeout duration | `600 seconds` | Match average time for pulling multi-source data, avoid interrupting real-time data acquisition due to timeout |
| Maximum parallel tool calls | `2-3` | Adapt to the number of core data sources in emergency scenarios, avoid interface current limiting caused by excessive concurrency |
| `functionCall` batch processing mode | Split calls by question | Handle multi-question inquiry scenarios, assign each question to the corresponding tool or knowledge base |
| Workflow parameter mapping rules | Automatically match by file metadata | Adapt to uploaded files such as duty logs and rapid disaster reports, automatically extract key parameters and pass them to the workflow |
| Maximum knowledge base recall results per call | `Top 8` | Match the typical length of documents such as consultation minutes and warning notices, ensure relevance and completeness of recalled information |

*Note: The configurations on this page apply to FastGPT v4.17.0*

## Three Common Misconfigurations
- When a workflow is configured as a tool call, uploaded files cannot pass links as parameters to the workflow. This occurs because the automatic file metadata mapping setting for the workflow is not enabled. The system cannot recognize associated parameters for uploaded files.
- When multiple inquiries are initiated at the same time, knowledge base return results become disorganized. This occurs because the `functionCall` batch processing mode is not enabled. Recall results for multiple questions are not split by their corresponding questions.
- Connection or authentication errors occur when calling open-source MCP server or Wenxin Yiyan tools. This occurs because the tool address, port, or API key are not configured correctly. Or the corresponding model version for the tool is not matched.

## How to Verify Configurations Are Correct
- Upload a test rapid disaster report file. Trigger the bound workflow tool. Check if the workflow log obtains the complete link and metadata of the file.
- Initiate an inquiry with two separate questions, such as "What is the current rainfall situation" and "What is the material allocation status". Check if return results correspond to knowledge base or tool call results for each question respectively.
- View tool call monitoring logs. Confirm that single call duration does not exceed the configured 600-second timeout.
- Call the configured third-party large model tool. Initiate a test inquiry. Confirm that return results meet expectations and no authentication errors occur.
