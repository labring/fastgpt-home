# Work Consultation and Response for Flood Prevention, Disaster Mitigation and Emergency Duty: Document Parsing and Chunking

## What data in this category looks like
Typical entities include emergency management bureaus, water affairs bureaus, meteorological bureaus, sub-districts, towns and townships, and emergency command centers. These organizations generate daily documents including duty logs, early warning notices, consultation meeting minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources cover meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. These organizations update documents daily. Documents include structured tables and unstructured text, with fields involving clear units such as rainfall amount, water level, and number of transferred people. Some documents circulated across departments have inconsistent formats.

## What constraints these characteristics impose on document parsing and chunking
Processing flood prevention and disaster mitigation documents requires strict timeliness. Batch-updated documents must be parsed efficiently to avoid delaying emergency responses. For structured documents with multi-column fields and clear units, the parsing workflow must fully retain table structures and field information. Otherwise, data loss occurs during subsequent aggregation. Non-standard documents circulated across departments require flexible chunking rules to adapt to different formats. Overly fragmented chunks lose contextual connections. Overly long chunks reduce subsequent retrieval efficiency. Incorrect splitting of key information such as early warning levels and transfer times may cause errors in subsequent response handling.

## How to set the configuration
This document is written for FastGPT v4.17.0. The following configuration items and recommendations apply:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Flood prevention documents contain a large number of linked numerical values and contextual information. This range balances information completeness and retrieval efficiency |
| `chunkSplitter` | Split by paragraph + heading | Adapts to the hierarchical structure of consultation meeting minutes and early warning notices, and retains logical connections within documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 1200 seconds | Parsing large hydrological monitoring reports and multi-page consultation meeting minutes takes a long time. This duration covers processing for standard business documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Documents submitted in batches during emergency duty scenarios may have large file sizes. This setting meets standard business upload requirements |
| `customPdfParse` | Enabled | Flood prevention PDFs often contain tabular disaster data. Custom parsing can fully retain table structures and field information |
| `chunkSettingMode` | Manual mode | Chunking rules need to be adjusted for different document types such as duty logs and early warning notices to adapt to business scenarios |

## Three common misconfigurations
- Symptom: When uploading material allocation slips or rapid disaster report forms in Excel format, only a small number of fields are recognized after parsing, or the file fails to load. Cause: The default parsing configuration does not enable structured table parsing, and does not adapt to the multi-column field structure of flood prevention Excel files.
- Symptom: After importing question-answer pairs, the generated response does not fully match the preset original text, and irrelevant content is mixed in. Cause: The question and answer content of the question-answer pair is split during chunking, resulting in failure to accurately match the preset text during retrieval.
- Symptom: A connection failure error occurs when calling a custom PDF parsing service. Cause: Ports for the custom parsing service are not mapped during Docker deployment, or the configured service address is incorrect.

## How to confirm the configuration is properly set
- Upload a single typical flood prevention document, and check whether the parsed text retains the original document's headings, paragraphs, and table structures.
- Upload a test document set with mixed formats, and confirm that all supported file types can be parsed normally.
- Check the `PARSE_FILE_TIMEOUT_SECONDS` and `UPLOAD_FILE_MAX_SIZE` configurations to match the current business's maximum document size limits.
- Import test question-answer pairs, and verify that the parsed chunk content aligns with the preset text.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
