# Form and Interaction for Service Consultation and Response: Flood Control, Disaster Prevention and Emergency Duty

## What the data for this category looks like
Data for this category typically comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. The update frequency is daily. Daily documents include duty logs, warning notices, emergency consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Most fields contain time, location, numerical value, and status information. Units specific to emergency scenarios include millimeters, cubic meters, and number of people.

## What constraints these characteristics impose on form and interaction
Most data sources are specialized systems. Field formats are unified, but cross-system field differences are significant. Forms must support custom field mapping to adapt to different data sources.
The daily update frequency requires support for scheduled pulling of the latest data to fill form options or reference content for consultation responses.
Diverse document types require adaptation to different interaction logic. For example, rapid short text entry is needed for rapid disaster reports, and multi-field batch filling must be supported for material allocation slips.
In cross-departmental dispatch scenarios, forms must support role-based permission control to prevent unauthorized personnel from modifying critical data.

## Configuration Settings
This page is compatible with FastGPT v4.17.0. All following configurations are based on the interaction logic of this version.

| Configuration Item | Recommended Setup | Rationale |
| --- | --- | --- |
| `formInput` | Support multi-field grouping, with core fields displayed first | Emergency scenarios require rapid entry of high-frequency fields such as disaster information and materials. Grouping can distinguish basic information from detailed data |
| `userSelect` | Pre-set options for emergency departments and rescue teams within the jurisdiction | Cross-departmental dispatch scenarios require limiting the scope of operations to avoid unauthorized selections |
| Knowledge base dynamic parameter passing | Bind real-time fields from meteorological warning and hydrological monitoring systems | Data sources are fixed to specialized systems, so latest data must be dynamically pulled for consultation responses |
| Voice input timeout threshold | 10-15 seconds | Voice input in emergency scenarios needs to be completed quickly. Excessively long timeouts will affect real-time response efficiency |
| Referenced document matching rule | Prioritize documents updated within 24 hours | Data is updated daily, so the latest emergency-related content must be prioritized for display |

## Three Common Configuration Mistakes
- Phenomenon: An unmarshal_resp error is returned after voice input is triggered, and the interface shows a text conversion failure message. Cause: The voice input timeout threshold is not configured, or the threshold is set outside the 10-15 second range, causing the voice transcription process to terminate abnormally.
- Phenomenon: After configuring knowledge base dynamic parameter passing, the AI response does not display the referenced documents. Cause: The knowledge base is not bound to the corresponding data source field, or the matching rule is not set to prioritize documents updated within the current day, resulting in recalled content that does not match the consultation scenario.
- Phenomenon: A format error prompt is returned when manually selecting the knowledge base. Cause: The `userSelect` component is not used to preset a valid option range, causing the passed knowledge base parameter format to not meet system requirements.

## How to Confirm Configuration is Complete
- Open the form editing interface, confirm that the `formInput` component arranges core fields according to business priority and supports custom field mapping.
- Test the voice input function, confirm that transcription is completed within 10-15 seconds, and no unmarshal_resp errors occur.
- After configuring knowledge base dynamic parameter passing, initiate a consultation test, confirm that the AI response associates the latest documents from the corresponding data source.
- Test the `userSelect` component, confirm that only preset emergency department and rescue team options can be selected, with no illegal input allowed.
