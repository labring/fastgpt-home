# Food Safety Supervision Sampling Service Consultation and Reply: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data is sourced primarily from food safety sampling monitoring systems, the State Administration for Market Regulation sampling result query system, laboratory LIMS systems, and food producer and operator ledgers. Core daily documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements. Data is updated monthly. Core fields include sampling information, inspection items, determination results, disposal measures, and more. Laboratory test reports serve as the core evidence carrier, distinguishing this data from daily licensing business data.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Monthly updated data requires the dialogue system to support regular synchronization of the latest sampling plans and public results, to avoid referencing expired business data. Most core documents are structured forms and professional inspection reports. Prompt templates must adapt to field formats to ensure accurate extraction of key information such as sampling numbers and test results during conversations. Multi-turn dialogue must link full-process documents for the same sampling batch, which requires the context window to cover data across the sampling, inspection, and disposal workflows. It is also necessary to distinguish query permissions for different entities to ensure compliance with data access regulations. Additionally, core business operations revolve around unqualified food disposal. Conversations must quickly locate inspection reports and disposal records for the corresponding batch, which places clear requirements on the knowledge base’s tag association capabilities.

## Configuration Settings
The following configurations are formulated based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Context window length | 8000–12000 token | Must cover multiple monthly updated sampling documents and full-process disposal records |
| Variable binding rules | Bind sampling number, inspection item, and disposal measure fields | Adapt to the structured field characteristics of core documents, improving information extraction accuracy |
| Knowledge base tag filtering | Bind sampling batch and inspection institution tags | Precisely recall business data for the corresponding batch, avoiding interference from irrelevant documents |
| Multi-turn conversation identifier | Associate context by `chatId` | Ensure multi-turn inquiries for the same sampling batch can continue to call historical data |
| Result recall limit | Top 3–5 latest entries | Match the monthly updated data volume, avoiding redundant information that affects reply efficiency |
| Prompt template variables | Introduce inspection report determination results and verification disposal process variables | Focus on core business links, ensuring replies cover key business information |

## Three Common Configuration Errors
- A 400 status code is returned when calling the dialogue interface. The symptom is an interface error after submitting the prompt template. The cause is that the prompt template fails to correctly bind the `variables` parameter and does not match the field format of structured documents.
- The dialogue cannot filter results by the specified sampling batch. The symptom is that recalled documents include sampling data from non-target batches. The cause is failure to associate conversation context via `chatId` or bind knowledge base batch tags.
- The dialogue output does not include key determination items from the inspection report. The symptom is that unqualified items or disposal measures are missing from replies. The cause is that the prompt template does not reference field variables from core documents and fails to cover key information required for the business.

## How to Verify Proper Configuration
- Initiate a simulated inquiry, enter a specific sampling number, and verify whether the system automatically links to full-process documents for the corresponding batch.
- Submit a query about unqualified food disposal, and verify whether the returned content includes the inspection report’s determination results and disposal measures.
- Initiate multiple consecutive inquiries for the same sampling batch, and verify whether the conversation retains key information from previous interactions.
- Check interface call logs to confirm that request parameters include correct `chatId`, `variables`, and `messages` parameters, covering conversation association, variable binding, and context history.
