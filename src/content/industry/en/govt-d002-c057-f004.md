# Workflow Orchestration for Food Safety Supervision Sampling Service Consultation and Reply

## What this category of data looks like
Data sources for this category include the Food Safety Sampling and Monitoring System, the State Administration for Market Regulation Sampling Results Query System, the laboratory LIMS system, and the food producer and operator ledger. Core daily documents cover sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control notices. The data update cycle is monthly. Fields include sampling batch number, inspection items, unqualified judgment results, disposal measures, and more. All fields use standard business formats, with no custom statistical units.

## What constraints do these characteristics impose on workflow orchestration
Monthly updated data sources require workflows to be configured with fixed-cycle knowledge base sync tasks to avoid unnecessary frequent calls. Multiple structured and semi-structured document sources require workflow nodes to support multi-data source access verification, matching the fixed field formats of sampling slips and inspection reports. Unqualified judgment results and disposal measures in core documents serve as key decision-making bases. Workflows must include field verification links to ensure complete associated data. Lightweight usage requirements for grassroots supervision scenarios require workflow node configuration without complex code development.

The following configurations are based on FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Knowledge base sync cycle | Once monthly, executed at 2:00 AM on the 5th of each month | Matches the monthly update frequency of data sources, avoids unnecessary calls |
| `variables` | Bind sampling plan ID and sampling batch number as global variables | Core documents need to be associated with fixed business fields to ensure data accuracy |
| Node timeout setting | 300-600 seconds | Meets time requirements for multi-data source calls and inspection report parsing |
| Batch execution node | Group by sampling batch number, process no more than 20 items per run | Meets lightweight processing capacity requirements for grassroots supervision scenarios |
| Knowledge base recall limit | Top 10 results | Core information of sampling-related documents is concentrated, excessive results will interfere with decision-making |
| `nodeId` | Assign a unique identifier to each data source node | Facilitates workflow debugging and abnormal node location |

## Three common mistakes
- When calling knowledge base search, the prompt "No valid data source matched" appears. Cause: The data source of the Food Safety Sampling and Monitoring System is not bound to the `variables` configuration of the workflow, or the sync cycle is not set correctly.
- The number of results returned by the batch execution node does not match expectations. Cause: The batch rule is not configured with grouping by sampling batch number, leading to mixed cross-batch data, or the single processing limit exceeds the system's carrying capacity.
- Plugin parameters cannot be obtained from global variables and fall back to default values. Cause: The mapping relationship of the corresponding parameters is not declared in the `variables` configuration, causing the workflow to fail to read business field values.

## How to confirm the configuration is complete
- Manually trigger the workflow once, check whether the sampling plan ID and sampling batch number bound to `variables` are correctly brought into the node parameters.
- View the knowledge base sync logs to confirm that the monthly sync task is completed according to the preset cycle.
- Test the batch execution node to verify that the grouping rules and processing limits meet the scenario requirements.
- Call the knowledge base search to confirm that the returned results include core documents such as sampling plans and inspection reports.

The values given are common starting points and should be measured against the reader's own samples.
