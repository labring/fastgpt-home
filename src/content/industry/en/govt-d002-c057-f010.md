# Food Safety Supervision Sampling Service Consultation and Reply: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The data for this category comes primarily from the food safety sampling monitoring system, the national market supervision administration sampling result query system, the laboratory LIMS system, and records of food producers and operators. Data is updated once per month. Core documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements.
Data fields include sampling location information, inspection project parameters, unqualified judgment basis, and disposal process records. Different documents have dedicated fields: sampling slips include sampling date and sampling location, while inspection reports include test values and judgment standards.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The monthly data update requirement means the retrieval system must support incremental indexing and scheduled full synchronization. This prevents data lag from reducing the accuracy of consultation replies.
Multiple document types are used, including structured fields in sampling slips and inspection reports, plus unstructured announcement text. This requires adapting text splitting and field recognition for different formats.
Aggregation of data from multiple sources requires unified data source association rules. This ensures retrieval results cover all channel sources.
Core evidence comes from laboratory inspection reports. Retrieval must prioritize high-confidence inspection documents, and strictly match disposal process-related information. This avoids missing key disposal basis.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Balances recall precision and coverage, avoids mixing low-relevance results or missing critical information |
| `limit` | Top 10 entries | Controls the length of single retrieval context, adapts to the regular information needs of business consultations |
| `searchMode` | vector+keyword hybrid retrieval | Balances structured field matching and unstructured text semantic recall |
| `usingReRank` | Enabled | Improves display priority for core documents such as inspection reports |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands the semantic scope of user consultations, supplements related documents such as sampling plans and disposal announcements |
| `collectionIds` | Configure collection IDs grouped by data source | Differentiates sampling data from different sources, ensures the retrieval range accurately corresponds to the business scenario |

## Three Common Configuration Errors
- Issue: Retrieval results are far fewer than expected, or return a large number of irrelevant documents. Cause: `collectionIds` are not configured grouped by data source, so the retrieval range includes redundant data from non-target categories.
- Issue: Retrieval tests return no results or take excessive time. Cause: No incremental indexing mechanism is configured. Full indexing of hundreds of thousands of data entries triggers retrieval timeouts, or the `similarity` threshold is not adjusted, filtering out valid results.
- Issue: Core documents such as inspection reports are not displayed first. Cause: `usingReRank` is not enabled, or retrieval parameter configuration does not match the weight requirements for core documents.

## How to Confirm Proper Configuration
- Check index synchronization logs to confirm that the monthly incremental update task triggers normally, and that the data source covers all required document types.
- Simulate business consultations, retrieve different types of documents such as sampling plans, inspection reports, and disposal announcements, and verify that retrieval results cover the corresponding types.
- Compare result rankings with and without `usingReRank` enabled, to confirm that core documents such as inspection reports are displayed first.
- Review the configuration parameters returned by the retrieval interface, to confirm that `limit`, `similarity`, and other parameters meet preset requirements.

The values provided are common starting points and should be measured against the reader's own samples.
