# Food Safety Supervision Sampling Inquiry and Response: Forms and Interactions

## What This Category of Data Looks Like
Data sources for this category include the food safety sampling monitoring system, the State Administration for Market Regulation sampling results inquiry system, the laboratory LIMS system, and records of food producers and operators.
Data updates occur once per month.
Commonly involved documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements.
Core fields cover sample number, production and operation entity name, inspection items, non-conforming items, disposal status, and more.
Units include batches, copies, milligrams per kilogram, and others.
Fixed specifications exist for field priority and format across different documents.

## Constraints Imposed on Forms and Interactions
The monthly data update rhythm requires the form’s data source synchronization cycle to match the monthly update frequency. This avoids excessive system load from frequent data pulls.
Multi-source data requires the form to support cross-system field mapping. This adapts to format differences between inspection reports from the LIMS system and sampling plan fields from the market supervision system.
Fixed fields in core documents require the form to include required validation. This ensures key information such as sampling numbers and non-conforming items is not missing.
Permission differences across entities require the form to support role division. This ensures that entities such as grassroots supervision institutes and testing institutions can only access form content within their assigned permissions.

## Three Common Mistakes
- Submitting the form returns an empty error, with the interface prompting that a field is not correctly bound. The cause is that `formInput` is not bound to the category-specific field template, causing the system to fail to identify required sampling-related fields.
- Knowledge base references cannot be selected in code running nodes. The cause is that the knowledge base is not associated with the sampling data source configuration, causing the system to fail to retrieve content from the corresponding document library.
- The chat window prompts that no knowledge base is selected. The cause is that no knowledge base binding rule is preset in the form interaction link, and the user has not actively selected the knowledge base corresponding to the sampling data.

## How to Verify a Completed Configuration
- Open the form configuration page, check whether `formInput` is bound to the standard field template for sampling slips and inspection reports.
- Enter the role permission settings interface, confirm that `userSelect` has divided corresponding role groups such as supervision institutes and testing institutions.
- Submit a test data entry, verify that the required field validation takes effect and the form timeout setting meets expectations.
- Trigger manual data synchronization, check whether the corresponding data source updates are pulled according to the 720-hour cycle.
