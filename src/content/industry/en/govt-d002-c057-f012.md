# Food Safety Supervision Sampling Service Consultation and Reply: Deployment and Upgrade

## What data for this category looks like
Data for this category mainly comes from the food safety sampling monitoring system, the national market supervision administration sampling result query system, testing institution LIMS systems, and food producer and operator ledgers. The data update frequency is monthly. Commonly involved documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements. The data includes structured fields such as sampling number, inspection items, inspection results, non-conformity judgment basis, and disposal measures. It also includes unstructured content such as full inspection report text and on-site photos.

## What constraints these characteristics impose on deployment and upgrade
The monthly update frequency requires configuring scheduled tasks for incremental synchronization and full reset during deployment. This prevents service lag caused by an excessively large single data synchronization volume. Multiple heterogeneous data sources require compatibility with field formats from different systems. Field mapping configuration must be completed in advance during deployment to ensure the knowledge base correctly identifies core fields such as sampling number and non-conforming items. The integrity of core documents like inspection reports directly affects the accuracy of consultation replies. Data verification rules must be configured during deployment to filter files with missing key fields. During upgrades, session cache must be maintained without interruption to avoid disrupting ongoing service consultation services.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://admin:pass@10.0.0.1:5432/food_safety` | Structured fields in sampling data, such as sampling number and inspection results, are suitable for relational database storage |
| `MONGODB_URI` | `mongodb://admin:pass@10.0.0.2:27017/?authSource=admin` | Unstructured content such as full inspection report text and on-site photos is suitable for document database storage |
| `DB_MAX_LINK` | `20–30 connections` | Stable database connection count must be maintained during monthly batch data synchronization to avoid connection exhaustion |
| `REDIS_URL` | `redis://:redis_pass@10.0.0.3:6379/0` | Cache session information for service consultations and temporarily generated reply files to improve response speed |
| `STORAGE_S3_ENDPOINT` | Fill in according to local government cloud storage configuration | Adapt to object storage services of various government clouds for storing attachments such as inspection reports |
| `ROOT_KEY` | Configure keys according to unit security policies | Control FastGPT backend management permissions to ensure the security of configuration modifications |

## Three Common Mistakes
- Incorrectly mixing vector database configuration with PostgreSQL-related parameters during deployment. A `connection refused for postgres` error occurs. The root cause is that PostgreSQL database parameters were incorrectly written into the Milvus compose file, failing to distinguish configurations for vector storage and structured data storage.
- Unable to load sampling data after startup. A `missing required field` error occurs. The root cause is that no field mapping rules were configured, causing the knowledge base to fail to identify core fields such as sampling number and non-conforming items.
- After upgrading FastGPT v4.17.0, an `invalid token` error appears in service consultation sessions. The root cause is that the consistency of `FILE_TOKEN_KEY` was not synchronized with the legacy configuration, leading to temporary file verification failure.

## How to Confirm Proper Configuration
- Run the monthly synchronization task, check the synchronization log, and confirm that documents such as sampling plans and inspection reports have been successfully imported into the knowledge base.
- Initiate a simulated service consultation, enter "verification and disposal process for unqualified food", and check whether the returned results include relevant content from the verification and disposal report.
- View database connection monitoring metrics, and confirm that the connection count stays within the `20–30 connections` configuration range.
- Access `FE_DOMAIN`, confirm that the frontend consultation entrance loads normally, and that the attachment upload function works properly.

The values provided are common starting points and should be evaluated against the reader's own samples.
