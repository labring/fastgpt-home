# Warehousing and Logistics Service Consultation and Response: Multi-turn Dialogue and Prompt Configuration

## What this category of data looks like
Warehousing and logistics service consultation data primarily comes from inbound and outbound records in warehouse management systems, logistics waybill systems, warehouse location ledgers, and official service process guidance documents.
Data updates follow three schedules:
1. Logistics waybills and real-time operation records are updated in real time
2. Warehouse inventory ledgers are updated daily
3. Service guidance documents are revised quarterly

The structure of a single data entry includes a unique identifier field, timestamp, operation type, associated location or waybill number. Field units include pieces, boxes, orders, hours, and other standard units. Some documents include illustrated step-by-step instructions.

## What constraints do these characteristics impose on multi-turn dialogue and prompt configuration
Warehousing and logistics service consultation data characteristics create multiple constraints for multi-turn dialogue and prompt setup.
First, real-time updated logistics waybill data requires limiting dialogue context to a valid time range to avoid calling expired data.
Second, multiple data types include dedicated unit fields. Prompts must explicitly require returned results to match the corresponding units to prevent unit confusion.
Third, some service guidance includes illustrated steps. Prompts must specify retaining key illustrated associated information when citing to avoid missing content.
Fourth, data is linked to unique business identifiers. Multi-turn dialogue must bind `chatId` and `messages` context to ensure coherent, accurate dialogue for a single scenario.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Previous 25–35 dialogue messages | Warehousing and logistics service consultations focus on waybills and inventory. 25–35 messages cover multi-turn questions for complete service processes and avoid context overflow |
| Question Optimization | Enabled | Warehousing and logistics consultations often use colloquial language. Enabling this feature converts colloquial questions into standardized queries to match structured data in the knowledge base |
| Single Search Limit | Top 6 recalled results | The warehousing and logistics knowledge base includes three core data types: waybills, inventory, and service guidance. 6 results cover core business scenarios and avoid redundant output |
| Context Binding | Grouped by `chatId` | Warehousing and logistics service consultations often relate to unique waybills or warehouse locations. Grouping by `chatId` prevents context interference across different business scenarios |
| Prompt Template | Fixed business scenario prefix | Must explicitly require returned results to match warehousing and logistics-specific units (pieces, boxes, orders) and prioritize referencing the latest business data |

## Three Common Configuration Mistakes
- Phenomenon: After configuring prompts and knowledge base reference templates, returned results do not reference warehousing and logistics business documents as expected. Cause: The prompt does not explicitly specify prioritizing connected business data, so the model uses general training data instead.
- Phenomenon: API calls and online dialogue return significantly different results, and the latest logistics waybill information is not returned. Cause: Corresponding business scenario parameters are not bound in the `variables` field of the API request, so the API fails to load the dedicated warehousing and logistics knowledge base configuration.
- Phenomenon: The reply annotation of the workflow AI dialogue component does not trigger after the dialogue ends. Cause: The annotation trigger condition is not linked to the `messages` dialogue end marker, so the system cannot identify the dialogue completion node.

## How to Verify Successful Configuration
- Initiate a multi-turn dialogue covering multiple business links, and confirm returned results include warehousing and logistics-specific units and the latest data.
- Copy configuration parameters from the online dialogue to an API request, and confirm both calls return consistent results.
- Trigger the workflow AI dialogue node, and confirm the annotation executes as expected after the dialogue ends.
- View the system log to confirm `chatId` is correctly bound to context data for the corresponding business scenario.
