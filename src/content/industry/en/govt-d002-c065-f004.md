# Consulting and Reply for Survey and Design Work: Workflow Orchestration

## What This Category of Data Looks Like
Survey and design consulting and reply data mainly comes from project survey reports, construction drawing design documents, government approval receipts, site survey records, and other sources. Data updates are adjusted alongside project phase progression, and are refreshed synchronously when plans change or approval nodes are updated. A single document typically includes fields such as professional classification identifier, drawing number, version number, approval status, and project unique ID. Drawing documents use sheet units to specify specifications, report documents use thousands of characters and pages as statistical units, and approval documents include official document number identifiers.

## What Constraints Do These Characteristics Impose on the "Workflow Orchestration" Link
The multi-discipline, scattered data nature of survey and design work requires workflows to be split into processing nodes organized by discipline such as architecture, structure, and water supply and drainage, to prevent cross-discipline data confusion. The approval status flow logic requires workflows to bind approval completion nodes to trigger subsequent consulting and reply links. Large variations in drawing sheet sizes and significant fluctuations in single-file volume require workflows to limit the maximum number of files processed per node, to avoid execution timeouts. The project unique ID, as the core association field, must be passed through `variables` to ensure accurate data binding across all workflow links.

## How to Set Configurations
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind project number and professional type as fixed values | Ensure that each workflow node associates with the corresponding survey and design project data, avoiding cross-project confusion |
| Node Trigger Rule | Trigger subsequent links based on approval completion status | Match the business logic of survey and design project approval flow, start consulting and reply only after approval is passed |
| Maximum Single-Processing Files | 5 | Adapt to the volume differences of single survey and design drawings/reports, avoid single-node execution timeouts |
| Timeout Threshold | 1200 seconds | Cover the parsing and reply generation duration of complex survey reports, avoid process interruptions |
| Knowledge Base Binding Configuration | Associate the exclusive knowledge base of the corresponding project | Ensure that the knowledge base data called for consulting and reply matches the current survey and design project |
| `nodeId` | Bind the unique identifier of the knowledge base search node | Ensure the workflow accurately calls the target knowledge base node, avoiding incorrect node calls |

## Three Common Misconfigurations
- Phenomenon: The reply content returned after workflow execution is unrelated to the current survey and design project, and the association field is empty. Cause: The project number is not bound as a global parameter through `variables`, causing each node to call incorrect project data.
- Phenomenon: An error is returned directly after the workflow triggers, and the system returns an execution timeout prompt. Cause: The maximum number of single-processing files is not limited, and too many survey drawings or reports are loaded by a single node, exceeding the system execution threshold.
- Phenomenon: The consulting question entered by the user is not correctly passed to the AI dialogue link, and the reply content does not match the user's question. Cause: No inter-node parameter transfer rules are configured, and the user's input question is not bound to the input field of the AI dialogue node.

## How to Verify Correct Configuration
- Export the global variable configuration list of the workflow, check whether it includes the core fields required for the survey and design project, and confirm that the field values match the current project.
- Simulate the approval completion trigger scenario, check whether the workflow node starts the consulting and reply link as expected, and verify that the trigger rule takes effect.
- Upload a single survey report to test the workflow, check whether the node processing duration meets the preset threshold, and confirm that the timeout configuration is reasonable.
- View the knowledge base binding configuration, confirm that the associated knowledge base matches the professional scope of the current survey and design project, and verify the accuracy of data calls.

The values listed above are common starting points and should be measured against the reader's own samples.
