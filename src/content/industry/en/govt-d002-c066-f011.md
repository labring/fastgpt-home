# Service Inquiry and Response for Advanced Chemical Materials: Forms and Interactions

This document is written for FastGPT v4.17.0.

## What This Category of Data Looks Like

Data for advanced chemical materials service inquiries primarily comes from official record filings and public disclosures of state-owned and enterprise chemical sectors, compliance submission materials from industry associations, and publicly available product technical documents from enterprises. Data update cycles align with new grade releases and quarterly compliance audits; there is no real-time update requirement. Each document includes fields such as grade, CAS number, density, melting point, flash point, compliance level, and application scenarios. Fields must strictly follow legal units: for example, density uses `g/cm³`, temperature parameters use `℃`, and some compliance fields must match official published qualification coding rules.

## Constraints Imposed on Forms and Interactions

Advanced chemical materials data includes a large number of specialized chemical parameters and strict unit requirements. Therefore, forms must preset valid field options and unit validation rules to prevent invalid input. Data sources are mostly official record materials, and core fields are fixed with no room for flexible adjustment. Therefore, forms must limit the scope for adding custom fields, only allowing supplementary non-core temporary information. Some data involves compliance qualifications and sensitive parameters, so forms must distinguish between public filling and internal permission interaction logic, restricting unauthorized users from accessing sensitive fields. Data update cycles are not real-time, so forms must support quick query access to archived historical record data to reduce duplicate data entry operations.

## Three Common Mistakes

- Symptom: When attempting to jump from another process node to a form node, pre-filled parameters cannot be carried, and the link jump fails. Cause: The parameter transfer switch for node link reuse is not enabled, and the parameter mapping rule for the jump is not configured.
- Symptom: After enabling input prompts and configuring a custom term library, an error pops up in the debug preview interface. Cause: The custom term library file format does not meet requirements, or the term library contains invalid characters leading to parsing failure.
- Symptom: A quote type error occurs when referencing knowledge base variables. Cause: The variable is not written in the standard `{{variable name}}` format, or an undefined custom variable is referenced.
- Symptom: The available LLMs in the online version do not match the official introduction. Cause: The API key and permissions for the corresponding LLM are not configured in the platform backend, or the current account does not have usage permissions for the corresponding LLM.

## How to Verify Proper Configuration

- Enter the form configuration page, check if each field is bound to the corresponding unit validation rule, and confirm if a corresponding prompt pops up when entering an invalid numerical value.
- Test jumping from any process node to the form node, confirm if pre-filled parameters are automatically populated to the corresponding form fields.
- Enter a correctly formatted variable reference, confirm that no quote type error is displayed in the debug preview interface.
- After configuring the custom term library, enter specialized terms in the debug interface, confirm if the input prompt correctly matches the term library content.
