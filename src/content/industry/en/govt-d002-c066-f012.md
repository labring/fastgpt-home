# Work Consultation and Response for Advanced Chemical Materials: Deployment and Upgrade

## What the data for this category looks like
The data for advanced chemical materials work consultation comes from internal production enterprise process logs, quality inspection reports, and technical guidance documents released by industry associations. The update frequency is once per month, corresponding to product batch updates and minor adjustments to compliance standards. Most documents are structured parameter manuals and process descriptions, with fields including product grade, density, tensile strength, and heat distortion temperature, with units of g/cm³, MPa, and ℃ respectively. The length of individual documents ranges from 5,000 to 20,000 words, and some include multi-page compliance test appendices.

## What constraints these characteristics impose on deployment and upgrades
The feature of densely structured parameter documents requires that index chunking preserve field associations to avoid breaking the correspondence between parameters after splitting. The monthly update frequency requires incremental index scheduling to match this cycle, to avoid excessive synchronization or data lag. The combination of long documents and multiple fields increases the memory usage of single-document processing, which imposes requirements on resource limits for Docker deployments. For intranet deployment scenarios, external dependencies must be avoided, ensuring that both the vector model and storage services run within the intranet, while adapting to FastGPT v4.17.0 deployment specifications.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–200 connections | Adapts to the connection requirements of multi-field, high-concurrency queries for advanced chemical materials documents, and avoids connection exhaustion |
| `MONGODB_URI` | Intranet MongoDB service address with authentication parameters | Stores structured product parameters and consultation logs, ensuring data does not leave the intranet |
| `REDIS_URL` | Local Redis service address, with memory limit set to 2000 MB | Caches frequently queried product parameters to reduce database query pressure |
| `STORAGE_S3_ENDPOINT` | Intranet object storage intranet address | Stores original long documents and chunked indexes, adapting to the large-capacity storage requirements of chemical documents |
| `FE_DOMAIN` | Intranet-deployed frontend access domain name | Restricts consultation access to only be available within the intranet, complying with data security requirements |
| `FILE_TOKEN_KEY` | Custom random string | Validates the legitimacy of file upload requests to prevent unauthorized document import |

## Three common misconfigurations
- The symptom is an `EMFILE: too many open files` error thrown during Docker container build. The cause is failure to adjust the file handle limit for the Docker container. Processing long documents for advanced chemical materials will occupy more file handles, exceeding the default limit.
- The symptom is no matching results when importing documents after integrating the vector model. The cause is failure to configure `DB_MAX_LINK` to adapt to index requests for multi-field documents, leading to connection pool exhaustion and failure to complete index construction.
- The symptom is unrecognizable voice input when accessing the consultation entry from an iOS device. The cause is failure to configure `FE_DOMAIN` as an intranet-accessible domain name, causing the voice recognition callback request to fail to reach the intranet service.

## How to confirm the configuration is successful
- Run the `docker ps` command to confirm all service containers are in a running state, with no abnormally exited log records.
- Upload a process document for advanced chemical materials, wait for index construction to complete, then initiate a consultation that includes a specific product grade, and verify that the returned results include the corresponding product parameter information.
- View the Redis monitoring panel corresponding to `REDIS_URL` to confirm that the cache hit count increases gradually as consultation requests are initiated.
- Check the intranet storage bucket corresponding to `STORAGE_S3_ENDPOINT` to confirm that the uploaded document chunk files have completed synchronization and storage.
