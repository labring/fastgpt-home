# Fertilizer and Pesticide Service Consultation and Reply: HTTP Interfaces and External Systems

## What this category of data looks like
Fertilizer and pesticide service consultation data mainly comes from the Ministry of Agriculture and Rural Affairs pesticide registration database, fertilizer production license filing system, and local agricultural law enforcement inspection public notice information. Data updates are adjusted with the issuance of new registration certificates, license changes, and the release of inspection results. Core registration information is synchronized quarterly. A single record includes fields such as registration certificate number, product common name, production entity, active ingredient concentration (unit: grams per liter), applicable crops, and pre-harvest interval. Service process documents contain structured content such as application material lists and approval node descriptions. This page is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The multi-field structured nature of fertilizer and pesticide data requires HTTP interfaces to support precise parameter transmission by business dimension, such as registration certificate number and applicable crop type, to avoid result matching deviations caused by fuzzy queries. The non-fixed cycle of data updates requires incremental synchronization logic in interface configuration, only pulling changed datasets to reduce transmission overhead. The strong business relevance of service consultation scenarios requires that the `responseData` returned by the interface be mapped to agricultural input business fields, ensuring that AI can extract key information such as active ingredients and approval nodes for replies. In addition, the regulatory attribute of agricultural input data requires the interface to carry legal verification parameters to ensure compliance of data calls.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer Business-specific Secret` | Agricultural input regulatory data requires authorization verification to ensure call compliance |
| `variables` | Bind registration certificate number, applicable crop, application subject type | Fertilizer and pesticide service consultation requires accurate matching of corresponding business data; variables must cover core business fields |
| `responseData` | Only return registration certificate fields, approval node fields, pre-harvest interval fields | Service consultation scenarios only require core business information; filtering irrelevant content improves reply efficiency |
| Single search limit | Top 3 entries | Avoid redundant results interfering with AI extraction of key business information |
| Timeout period | 600 seconds | Cross-department agricultural input data interfaces may have delays; a longer timeout prevents normal requests from being interrupted |
| Maximum context length | 8000–12000 token | Fertilizer and pesticide data has many fields; sufficient context is needed to carry complete business information |

## Three common mistakes
- After sending a POST request, the interface returns a 200 status code but the `responseData` field is empty. The `variables` do not bind fertilizer and pesticide-specific business parameters, causing the system to fail to match the corresponding data.
- The results returned after calling the interface contain a large amount of non-business irrelevant content that cannot be directly used for replies. No filtering rules are configured for `responseData`, and full unprocessed raw data is returned.
- Parsing fails after uploading fertilizer and pesticide product registration documents, and valid fields cannot be extracted. The chunking rules are not configured according to the field structure of the structured document, causing long texts to be incorrectly truncated and key business information to be lost.

## How to confirm the configuration is correct
- Call the test interface, check whether the `Authorization` parameter is correctly carried, and confirm the returned status code is 200.
- View the `responseData` field returned by the interface, confirm that only the preset fertilizer and pesticide business fields are included.
- Pass a test registration certificate number, check whether the returned result matches the business information of the corresponding product.
- Adjust the `variables` parameter and call again, confirm that the returned result updates as the parameter changes.
