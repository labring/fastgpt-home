# Fertilizer and Pesticide Service Inquiry and Reply: Model Access and Configuration

## What this category of data looks like
Data for service inquiries in the fertilizer and pesticide sector comes primarily from agricultural product supervision and publicity platforms, enterprise production ledgers, pesticide registration announcements, fertilizer quality inspection reports, and similar sources.
Registration information updates quarterly. Batch inspection reports update alongside production batches.
Document structures include fields such as product name, registration certificate number, active ingredient content, application dosage, pre-harvest interval, packaging specification, and more. Units include professional measurement standards such as g/L, mg/kg, mu/hectare, kg/bag. Some documents include embedded images such as product labels and fertilization diagrams.

## Constraints imposed by these characteristics on model access and configuration
This category of data includes many professional measurement terms and standardized fields. The model must accurately identify units and professional phrasing to avoid measurement errors or ambiguity.
Embedded images carry key explanatory information such as product labels and fertilization diagrams. Visual parsing capability is required to fully extract content from these images.
Data update frequency is high. Registration information updates quarterly, and batch inspection reports update with each production batch. Regular knowledge base synchronization is required to maintain the timeliness of inquiry content.
Long documents such as production operation specifications occupy significant context space. Context and output length parameters must be configured reasonably to avoid content truncation caused by exceeding model limits.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `vision` | Enabled | Fertilizer and pesticide documents often contain images such as product labels and fertilization diagrams, and professional information within these images must be recognized |
| `maxContext` | `8000–12000 token` | Service inquiries often involve comparing multiple documents, so sufficient historical conversation and document context must be retained |
| `maxTokens` | `2000–3000 token` | Professional consultation responses need to cover detailed information such as dosage and pre-harvest interval, while avoiding overly long output that causes timeouts |
| `temperature` | `0.2–0.4` | Consultations in professional fields require answer accuracy, and randomness should not be set too high |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed model service address | Necessary interface address configuration for calling external or locally deployed large models |
| `AIPROXY_API_TOKEN` | Fill in according to the identity key assigned by the platform | Identity verification required to complete model calls |

## Three Common Configuration Mistakes
- Phenomenon: No new entries appear in the backend model list. The test interface returns normally, but the model does not display after configuration. Cause: `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` is not filled in correctly. Identity verification failure prevents the model from completing registration.
- Phenomenon: After uploading a document containing pesticide labels or fertilization diagrams, the model fails to recognize image content and only returns a text summary. Cause: The `vision` configuration item is not enabled, so visual parsing capability is not activated.
- Phenomenon: The external API interface call returns no error, but no conversation interaction interface exists in the external system. Cause: Only API access permissions are configured. The front-end conversation page is not developed, and interactive logic must be implemented independently.
