# Fertilizer and Pesticide Service Consultation and Reply: Deployment and Upgrade

## What this category of data looks like
Service consultation data for fertilizers and pesticides comes primarily from the Ministry of Agriculture and Rural Affairs agricultural input registration database, production enterprise filing documents, and local agricultural input supervision public platforms. Data updates follow product registration status: newly registered products are synced in real time, and existing products are verified and updated quarterly. Each document includes fields such as registration certificate number, generic name, trade name, production enterprise, applicable crops, active ingredient content, application dosage, and pre-harvest interval. Most active ingredient content values use units of g/L or %, while application dosage uses units of g/mu or mL/hectare. Some documents include long-text attachments such as field trial records.

## Constraints on deployment and upgrade
The multi-source mixed structure, specific field unit requirements, and regular update rhythm of this category's data impose three constraints on deployment and upgrade. First, adapt to mixed parsing of structured registration information and unstructured usage instructions to avoid field matching deviations that reduce consultation accuracy. Second, configure an incremental synchronization mechanism to adapt to quarterly existing data verification and updates, reducing resource consumption and business interruption risks associated with full synchronization. Third, include built-in unit verification rules to ensure fields such as active ingredient content and application dosage meet agricultural industry standards, preventing unit errors in replies. Additionally, data compliance requirements in government service scenarios require permission isolation configuration during deployment to prevent sensitive enterprise information from being disclosed externally.

## Three Common Configuration Mistakes
- Phenomenon: After removing `networks - fastgpt` from docker-compose.yml, database connection timeout errors occur between components, with a 500 status code displayed. Reason: FastGPT isolates component communication via a custom network by default. Removing this configuration prevents components from resolving each other's addresses using service names, leading to failed inter-service communication.
- Phenomenon: After upgrading to FastGPT v4.17.0, the root user password automatically resets to the initial value the next day. Reason: The persistent `ROOT_KEY` was not configured in the environment variables. The system uses a temporary key to generate the initial password by default, and the password resets after the key expires following a restart.
- Phenomenon: After connecting a specified vector model, the indexing task for long-text fertilizer and pesticide product manuals remains stuck in "indexing" with no progress updates. Reason: The long text document exceeds the maximum context length supported by the model, causing the indexing task to fail to complete properly and get stuck.

## How to Confirm the Configuration is Complete
- Run the `docker ps` command to confirm all FastGPT component containers are running, with no abnormal exit records.
- Access the configured frontend domain name, log in to the admin backend, and verify that the administrator permission configured via `ROOT_KEY` can normally create and edit knowledge base and model configurations.
- Upload a standard fertilizer and pesticide product manual document, check that the indexing task completes within 10 minutes, with a status of "completed".
- Initiate a consultation test that includes "active ingredient content", confirm that the returned results use field units consistent with general agricultural industry standards.
