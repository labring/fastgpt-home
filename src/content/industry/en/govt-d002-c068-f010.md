# Pharmaceutical Distribution Service Consultation and Response: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The service consultation data in the pharmaceutical distribution sector mainly comes from official documents such as GSP compliance guidelines issued by drug regulatory authorities at all levels, manual books for drug circulation approval matters, cold chain logistics control specifications, and medical insurance settlement declaration requirements. Data updates are adjusted according to industry compliance requirements, with no fixed cycle, but core documents are updated at least once a year. Most individual documents use a structured format, including fields such as matter name, handling basis, application materials, handling process, handling time limit (unit: working days), compliance thresholds (unit: degrees Celsius, relative humidity percentage), and others.

## What constraints these characteristics impose on the "knowledge base retrieval and recall" link
There are many structured fields and compliance thresholds, which requires precise matching of field keywords during retrieval to avoid generalized recall of irrelevant content. Cross-regional service consultation demands involve compliance differences across regions, so support for filtering recall results by region is necessary. Temperature and humidity parameters related to cold chain require high precision, and recalled documents must include clear quantitative standards, with no vague expressions allowed. Some documents involve hard requirements such as approval time limits and the number of application materials, and retrieval results must prioritize the latest version of compliance documents to prevent expired content from being recalled.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | The keyword matching accuracy requirement for pharmaceutical distribution compliance documents is high. This range balances recall coverage and precision, and adapts to the parameter rules of FastGPT v4.17.0 |
| `limit` | `Top 10` | Responses to service consultations need to be concise and cover core points. Excessive results will increase the context processing burden, which meets the response needs of pharmaceutical distribution service scenarios |
| `usingReRank` | Enabled | There are a large number of similar compliance expressions in pharmaceutical distribution documents. The re-ranking model can improve the sorting priority of highly relevant results and avoid displaying irrelevant content first |
| `datasetSearchUsingExtensionQuery` | Enabled | Users of service consultations often use colloquial expressions. Query optimization can supplement official terminology to improve the recall accuracy of semantic consultations |
| `collectionIds` | Bind to the exclusive knowledge base collection for pharmaceutical distribution | Avoid mixing documents from other categories, and ensure that recalled content fully matches the pharmaceutical distribution service consultation scenario |
| `searchMode` | Vector retrieval + keyword hybrid | Keyword matching of structured fields can accurately hit compliance threshold content, and vector retrieval covers semantic consultations, adapting to multiple types of service questions |

## Three common misconfigurations
- Phenomenon: After enabling `usingReRank` in the application, knowledge base retrieval returns no results, but the results are normal when tested in the knowledge base backend. Cause: The re-ranking model bound collection on the application side is inconsistent with the bound collection in the knowledge base backend, resulting in filtering of correctly recalled results.
- Phenomenon: Knowledge base search response time is too long, exceeding the response expectation of conventional service consultations. Cause: No reasonable `limit` parameter is set, and `datasetSearchUsingExtensionQuery` is not enabled, resulting in redundant processing after recalling too many documents.
- Phenomenon: After upgrading the FastGPT version, the knowledge base cannot display content normally or an abnormal version number appears. Cause: The binding configuration of the knowledge base collection is not updated synchronously, or the format of the `collectionIds` parameter has changed in the new version, and it is not adapted to the new version requirements.

## How to confirm the configuration is correctly set
- Enter the FastGPT knowledge base backend, select the bound exclusive collection for pharmaceutical distribution, perform a test retrieval, and check whether the returned content matches the service consultation scenario.
- Initiate a simulated service consultation on the application side, compare the result ranking with the knowledge base backend test results, and confirm that the `usingReRank` function is working properly.
- View the application configuration panel, confirm that the `collectionIds` parameter is bound to the exclusive knowledge base collection for pharmaceutical distribution, and no cross-category documents are mixed in.
- After upgrading the FastGPT version, check whether core parameters such as `datasetSearchUsingExtensionQuery` are fully configured and no settings are lost.
