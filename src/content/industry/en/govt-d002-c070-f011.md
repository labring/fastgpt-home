# Forms and Interactions for Administrative Inquiries and Responses in Power Generation Equipment Manufacturing

Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Data related to administrative inquiries and responses in power generation equipment manufacturing mainly comes from enterprise internal equipment operation and maintenance manuals, parts quality inspection reports, industry standard specification documents, and customer repair request work order libraries. Data updates follow new model launches, industry standard revisions, or major fault case supplements, with no fixed cycle. Document structures are mostly chaptered and structured, including fields such as equipment model, rated power, fault code, and processing flow. Units include kW, r/min, % and other professional engineering units.

## Constraints These Characteristics Impose on the Forms and Interactions Process
Standardized requirements for professional fields mean forms must pre-configure high-frequency options to avoid non-standard input. Document volumes are generally large, so form interactions must support large attachment uploads and long document loading. Dedicated fields differ across power generation equipment categories such as steam turbines and generators, so forms must display fields grouped by equipment type. Data updates have no fixed cycle, so users must be able to upload custom latest documents as inquiry bases. These characteristics mean the forms and interactions process cannot use a universal minimal configuration, and must adapt to professional field rules and data volume.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Only expose required fields, collapse non-required fields | Adapt to the professional field structure of administrative inquiries in power generation equipment manufacturing, reduce invalid input |
| `userSelect` | Pre-set 10-20 high-frequency equipment models and fault codes | Match standardized classifications in equipment documents, lower the threshold for professional term input |
| Context call duration | 600 seconds | Single equipment operation and maintenance documents have relatively high length, requiring sufficient time to load complete associated data |
| Attachment upload limit | 1000 MB | Support uploading complete equipment manuals, quality inspection reports and other large-volume files |
| Number of single recall results | Top 8 | Match the typical number of associated documents for administrative inquiries, avoid information overload |
| Form step-by-step loading | Display fields grouped by equipment type | Adapt to dedicated fields for different equipment categories such as steam turbines and generators |

## Three Common Configuration Mistakes
- Returns a network request timeout with status code 504 when calling model tools. The timeout parameter for `formInput` is not configured, and the default duration is insufficient to load associated data for long documents.
- Some professional fields are empty after form submission. Preset professional options via `userSelect` are not used, and non-standard terms entered by users cannot match background document fields.
- DingTalk robot deployment fails message receiving address verification. Public network access adaptation for form interactions is not configured, and unnecessary certificate verification restrictions are not disabled.

## How to Verify Successful Configuration
- Submit a test form, check whether required fields automatically verify formats and non-required fields can be collapsed and hidden.
- Upload an equipment operation and maintenance manual within 1000 MB, confirm that the upload is successful and can be associated and retrieved.
- Initiate an administrative inquiry request, check whether the number of recalled associated documents complies with the preset top 8 rule.
- Wait 600 seconds, check that the long document loads completely with no timeout errors.
