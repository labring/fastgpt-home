# Service Consultation and Response for Power Generation Groups: Tool Calling and Plugins

## What data for this category looks like
Data for power generation group service consultation and response comes primarily from internal service guideline repositories, customer service ticket systems, policy document announcements, and offline service window records.
There are two data update cycles.
General service procedures are updated quarterly.
Exclusive items such as grid connection and electricity price declaration have policy documents updated monthly to align with industry adjustments.
Document structures include fields such as item number, handling entity, required materials, handling time limit, consultation channel, and frequently asked questions. Material units are labeled with "copies" or "copies per set", and handling time limits use "workdays" as the standard unit.

## What constraints do these characteristics impose on tool calling and plugins
Decentralized sources of power generation group service consultation data require tool calling plugins to connect to multiple system interfaces. This enables information aggregation across data sources.
Frequently updated policy documents require plugins to include a scheduled synchronization mechanism. This prevents the return of outdated service guidelines.
Fields have a high degree of standardization, but include industry-specific terminology. Tool calling prompts must embed specialized vocabulary for power generation group service items. This ensures the large model can accurately identify calling requirements.
Some service items require linkage with internal approval systems. Tool calling must adapt to intranet access permission check rules.

## Three common mistakes
- Symptom: Tool calls return empty results or missing fields. Cause: Specialized power generation group service terms such as grid connection application and electricity price declaration are not embedded in the prompt, preventing the large model from matching the corresponding plugin.
- Symptom: Tool calls have no response when using the Gemini model. Cause: The compatible mode for `functionCall` is not configured correctly, so the model cannot trigger function calls.
- Symptom: Tool calls time out, and logs show connection failures. Cause: Intranet penetration access configuration is not adapted, so the plugin cannot properly call internal system interfaces.
