# State-owned Industrial Fund Service Inquiry and Response: HTTP Interfaces and External Systems

## What the data for this category looks like
Data sources for state-owned industrial funds include the fund filing system of the state-owned assets supervision platform, the capital flow ledger of the custodian bank, and the project post-investment management system. There are three update frequencies: real-time push for real-time changing data such as capital contributions and project status updates, monthly full ledger snapshot updates, and daily synchronization for daily post-investment progress. Each data record includes structured fields: fund subject code, project name, full investor name, total subscribed amount (unit: ten thousand yuan), paid-in progress, investment filing date (format: YYYY-MM-DD), exit status, and custodian account balance, with no free text redundancy.

## What constraints these characteristics impose on HTTP interfaces and external systems
State-owned industrial fund data sources are scattered across multiple independent business systems, so HTTP interfaces must support multi-source authentication and cross-system data aggregation. The update frequencies of different data vary significantly: short-cycle polling interfaces are required for real-time capital progress updates, while batch synchronization mode can be used for monthly full ledgers. Structured fields have unit and format constraints: interfaces must strictly validate the ten thousand yuan unit conversion for amount fields and the YYYY-MM-DD format for date fields to avoid data parsing errors. Additionally, industrial fund data involves state-owned asset sensitive information, so interface authentication must follow standard formats to ensure transmission security.

## How to configure

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | Bearer service key issued by the state-owned assets supervision platform | State-owned industrial fund data involves sensitive state-owned asset information, so the standard Bearer token authentication format must be followed to ensure controllable interface access permissions |
| `variables` | Configure fund subject code and investor code as global variables | When batch synchronizing data for multiple industrial funds, variables can dynamically replace interface request parameters to reduce repeated configuration |
| `responseData` | Only return core fields: fund subject code, paid-in progress, exit status | The state-owned industrial fund service inquiry scenario only requires core business fields, which reduces interface transmission traffic and improves response speed |
| Number of data entries per single request | 100–200 entries | Avoid excessive data volume in a single request causing interface timeout, which complies with interface rate limiting rules of most custodian systems |
| Interface timeout period | 30–60 seconds | State-owned industrial fund data needs to connect to multiple source systems, and a longer timeout period can prevent request failures caused by cross-system response delays |
| Retry count | 2 times | Limited retries for failed requests caused by temporary network fluctuations can improve interface call success rate |

## Three Common Misconfigurations
- Phenomenon: After batch calling the interface to add fund data, the return result has no data ID field, making it impossible to map with the local system. Reason: The interface configuration did not specify that `responseData` must include fields for returning IDs, and only operation status information is returned by default.
- Phenomenon: Frequent timeout errors occur during interface calls. Reason: The configured interface timeout period is too short, without accounting for response delays when connecting to state-owned asset systems.
- Phenomenon: Calling external interfaces from the web interface fails, and configurations become invalid after container restart. Reason: The external system address was not configured as an environment variable, so the locally stored address becomes invalid after container restart.

## How to confirm the configuration is set up correctly
- Call the test interface, pass preset business parameters, and check that the return result includes the pre-configured core business fields.
- Initiate a batch request, confirm that all operation statuses returned by the interface are successful, and no system rate limiting rules are triggered.
- View the interface call logs, confirm that the `Authorization` parameter is correctly carried, and there are no authentication failure related errors.
- Restart the deployment container, call the interface again, confirm that the configuration parameters are not lost, and the interface can complete data interaction normally.
