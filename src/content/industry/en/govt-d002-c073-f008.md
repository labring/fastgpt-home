# Government-backed Industrial Fund Service Inquiry and Response: Document Parsing and Chunking

## What this category of data looks like
Service inquiry and response data for government-backed industrial funds is sourced primarily from official archived documents, investment cooperation agreements, post-investment operation reports, policy guidelines, and service guides. Update frequency varies by document type:
- Archived files are updated annually
- Post-investment reports are updated quarterly or per project milestone
- Policy notices are updated immediately per regulatory requirements

Document structures include official document formats with document numbers and recipient units, structured tables including investment details and investment lists, and mixed text-image materials including project case images and policy interpretation diagrams. Fields include fund scale (unit: 100 million yuan), investor entities, investment sectors, fund duration (unit: years), and others. Some materials include confidential or sensitive information markings.

## What constraints these characteristics impose on document parsing and chunking
Multi-type document structures require parsing to support plain text, tables, and mixed text-image materials. This prevents damage to table logic or image-text binding during chunking.
Variations in file size from different update frequencies require parsing to support large file uploads and long-duration parsing. This prevents process interruptions from file capacity or time limits.
Fields with specific unit attributes require chunking to retain the association between units and corresponding values. This prevents separation of units and values after chunking.
Official document format specifications require retaining metadata such as document numbers and headers after parsing. This ensures service inquiry responses meet the rigor requirements of official documents.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Government-backed industrial fund documents often contain long paragraphs and structured tables. This range preserves semantic integrity, avoiding splitting across table rows or key policy clauses |
| `chunkSplitter` | Split by paragraph + heading | Documents have clear hierarchical headings and paragraph divisions. Splitting by this rule preserves contextual connections, avoiding breaking the logic of policy guidelines or project descriptions |
| `customPdfParse` | Enabled | Fund documents often contain embedded images, stamps, and complex tables. Custom parsing preserves text-image layout and table structure, resolves image-text separation issues, and aligns with FastGPT v4.17.0 parsing rules |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | Single archived file may include multiple period reports and attachments. This setting supports large file upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large file parsing requires longer processing time. This duration prevents mid-process timeout failures |
| `chunkSettingMode` | Manual configuration | Fund documents have diverse structures. Manual adjustment adapts to different types of service materials and policy documents |

## Three Common Mistakes
- Symptom: Embedded images in parsed documents fail to display normally or separate from text. Images in Excel files are lost. Cause: The `customPdfParse` configuration is not enabled. The default parsing logic does not retain image-text binding relationships.
- Symptom: Parsed markdown formatting is disorganized. Structured tables are split into scattered text paragraphs. Cause: The `chunkSplitter` configuration is set to split by pure characters, not by heading and paragraph hierarchy. This breaks the structural integrity of tables.
- Symptom: Parsing tasks trigger timeout errors after uploading large files, returning status code 504. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` setting value is too low, failing to adapt to the processing time required for large file parsing.

## How to Verify Proper Configuration
- Upload a fund archived file including tables and embedded images. Confirm that the parsed document retains table structures and the corresponding positions of images.
- Review detailed parsing task logs. Confirm that the `chunkSize` and `chunkSplitter` configuration parameters are active, and that chunking results do not break key semantic units.
- Test uploading a test file close to the `UPLOAD_FILE_MAX_SIZE` setting. Confirm that the upload and parsing processes do not trigger size or timeout limit errors.
- Compare the original document and parsed text content. Confirm that all field units are correctly retained, with no separation of units and values after chunking.

The values provided are common starting points and should be measured against the reader's own samples.
