# State-owned Asset Management Companies' Service Inquiries and Responses: Tool Calling and Plugins

## What this category of data looks like
Data related to service inquiries and responses for state-owned asset management companies comes primarily from asset ledgers, property registration archives, annual operation reports, and internal approval documents on the state-owned asset supervision platform.
Data updates occur monthly or quarterly. Core documents include two parts: structured fields and unstructured notes.
Structured fields cover asset ID, affiliated hierarchy, location, appraised value, ownership status, and more. Common units include ten thousand yuan, square meters, number of households, and others.
Unstructured parts mostly consist of asset disposal process explanations and policy interpretation documents.

## What constraints these characteristics impose on tool calling and plugin workflows
Structured data fields for state-owned asset management companies are fixed and clearly categorized. Tool calling must strictly match preset field names to avoid parameter mapping mismatches.
Unstructured documents are mostly policy interpretations and process explanations, with long overall length. Plugin calling must limit the context length passed in a single request to stay within model processing limits.
Data updates follow a monthly or quarterly cycle. Tool calling cache strategies must align with this cycle to prevent returning outdated asset status information.
Asset-related values must use specified units consistently. Plugins must automatically verify unit consistency to avoid errors caused by cross-unit calculations.
FastGPT v4.17.0’s plugin configuration interface supports targeted adjustments for these constraints.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `required` when querying asset status, set to `auto` when handling policy inquiries | Matches tool calling precision requirements for different scenarios, while balancing response efficiency |
| Single tool call timeout period | 300 seconds | State-owned asset data queries usually involve multiple ledger linkages, so sufficient response time must be reserved |
| Context window limit | 8000–12000 token | Adapts to the combined length of unstructured policy documents and asset ledgers |
| File upload parsing limit | 1000 MB | Matches the size range of reports and certificate documents commonly used by state-owned asset management companies |
| `functionCall` | Fixed mapping to standard asset ledger fields | Ensures tool call return results fully align with internal data structures |

## Three common configuration errors
- Phenomenon: Tool calls return empty fields or incorrect formats. Cause: Failed to map `functionCall` to the standard fields of state-owned asset management companies' asset ledgers, resulting in tool return data that cannot match the preset structure.
- Phenomenon: External interface calls experience response timeouts. Cause: Single tool call timeout period set too short, failing to reserve response time for multi-ledger linkage queries of state-owned assets.
- Phenomenon: Parsing errors occur after uploading asset reports. Cause: Failed to adjust the file upload parsing limit, exceeding the preset threshold leading to file truncation or parsing failure.

## How to confirm correct configuration
- Initiate an asset status query, check if the fields returned by the tool call fully match the internal ledger fields.
- Upload a report file in the format commonly used for state-owned assets, confirm that the parsing process has no errors and generates correct text fragments.
- Simulate an external platform calling the interface, verify that the response duration meets the preset timeout configuration requirements.
- Test policy inquiry scenarios, confirm that the tool calling function matches the inquiry topic.
