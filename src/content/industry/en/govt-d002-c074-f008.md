# State-owned Asset Management Company Inquiry and Response: Document Parsing and Chunking

## What this category of data looks like
Inquiry and response data for state-owned asset management companies originates from internal state asset supervision systems, policy document repositories, offline inquiry records, and online question-and-answer logs. Data updates have no fixed cycle. Policy documents are updated irregularly to meet regulatory requirements. Daily inquiry records are synchronized in real time. Document types cover official policy documents, service process guides, project application templates, and standardized question-and-answer entries. These include fixed fields such as item codes, processing time limits, and lists of application materials. Units used include workdays and ten thousand yuan.

## What constraints these characteristics impose on the document parsing and chunking stage
Policy documents and service guides are typically lengthy and have fixed hierarchical structures. When chunking, preserve the association between titles and their corresponding content. Do not allow splitting to break the logical integrity of service steps. Question-and-answer entries are mostly short texts but have multiple classification dimensions. Accurately match the context between questions and responses. Prevent content misalignment during retrieval after chunking. Large policy compilation documents have significant file sizes. Reserve sufficient time and upload space during parsing to avoid timeouts or upload failures.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of state asset policy documents and service processes, preserves context associations |
| `chunkSplitter` | Split by paragraph + title | Matches the hierarchical title structure of state asset documents, avoids breaking the logical integrity of service steps |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Addresses time consumption requirements for long document parsing, prevents timeout interruptions of the parsing process |
| `customPdfParse` | Enable structured parsing | Extracts metadata such as document numbers and issuing units from official documents, retains the core structure of the document |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Adapts to batch-uploaded state asset policy compilation documents, meets large file upload requirements |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types such as policy files and inquiry question-and-answer entries |

## Three common mistakes
- Symptom: Parsing fails for specific formats of state asset service configuration documents. Only some services parse normally. Cause: The system did not enable custom rule adaptation for specialized service document formats within state asset systems for `customPdfParse`.
- Symptom: After uploading a service guide document containing images to the knowledge base, question-and-answer tests cannot call content associated with the images. Cause: The system did not enable image text extraction, or did not retain the binding relationship between images and context text during chunking.
- Symptom: An upload failure prompt triggers when uploading large policy compilation documents. Cause: The system did not adjust the `UPLOAD_FILE_MAX_SIZE` parameter to a value adapted to the document size.

## How to confirm the configuration is complete
- Upload a single state asset policy PDF. Check if the parsed result includes preset metadata fields such as document numbers and issuing units in FastGPT v4.17.0.
- Upload a service process document containing images. Verify if the parsed result includes OCR-extracted text corresponding to the images.
- Submit a document larger than 200 MB. Confirm that the upload and parsing processes do not trigger timeout or failure prompts.
- Test the same document with basic chunking and custom chunking modes separately. Confirm that the chunking results conform to the logical structure of the document.
