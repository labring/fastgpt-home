# State-owned Capital Investment Company Service Inquiry and Response: Deployment and Upgrade

## What this category’s data looks like
Service inquiry and response data for state-owned capital investment companies mainly comes from service guidelines released by state-owned assets supervision and administration departments, inquiry work orders from internal subordinate enterprises, offline window reception records, and policy interpretation documents. Data documents are categorized by item type. Each document includes fields such as item number, handling entity, declaration material list, handling time limit, and inquiry channel, with units of "item" and "piece".
Data is updated quarterly to synchronize the latest requirements from supervision departments. Internal work order data is synchronized to the knowledge base daily. Policy documents undergo a full update every six months.

## What constraints these characteristics impose on the deployment and upgrade phase
Inquiry response data includes unified state-owned assets item codes. During deployment, verify the code format of imported documents to avoid mismatches with existing data from state-owned assets supervision systems.
Daily-synced work order data requires a scheduled incremental synchronization task to be configured. During upgrades, retain the historical configuration of synchronization tasks to avoid interrupting inquiry responses.
Policy documents undergo a full update every six months. During upgrades, support gray release of the updated knowledge base to ensure ongoing inquiry handling tasks are not affected.
In addition, the declaration material list includes multiple types of attachments. During deployment, configure sufficient storage capacity to meet attachment upload and retrieval requirements, while ensuring data storage compliance.

| `STORAGE_S3_ENDPOINT` | Configured according to the access address of the internal object storage service | Stores attachment materials for inquiries. Must comply with the requirements of internal compliant storage services |

## Three Common Mistakes
- Phenomenon: The frontend page returns a 502 Bad Gateway status code and fails to load normally. Cause: The domain name configured for `FE_DOMAIN` has not been resolved in the container network, or the port mapping configuration for frontend and backend services is incorrect.
- Phenomenon: Message synchronization fails after connecting to WeChat Work, and an account restriction prompt is triggered after multiple attempts. Cause: The legal callback domain name for WeChat Work has not been configured, and the access whitelist for internal interfaces has not been enabled, which does not meet the security and compliance requirements of the state-owned assets system.
- Phenomenon: The local large language model cannot be called normally, and the inquiry result is empty. Cause: The access address of the local model has not been correctly configured, and necessary port mappings have not been opened in the container network. Only the local loopback address has been opened, preventing FastGPT from connecting to the model service.

## How to confirm the configuration is complete
- Check the running status of all FastGPT-related containers to confirm that port mappings match the configuration items.
- Access the configured frontend domain name to verify that the page loads normally and can initiate basic inquiry query requests.
- Connect to the configured database address to verify that work orders and knowledge base documents for inquiries have been successfully imported and can be retrieved.
- Trigger a data synchronization task to verify that internal work order data can be normally synchronized to the knowledge base.
