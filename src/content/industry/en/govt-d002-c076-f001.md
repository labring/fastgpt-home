# Service Consultation and Response for State-owned Capital Operation Companies: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for state-owned capital operation companies' service consultation comes from the enterprise's internal service consultation ticket system and the public consultation ledger of the state-owned assets supervision and administration department. Data updates follow this rhythm: newly submitted consultation tickets are received in real time, and the response status of existing consultations is synchronized monthly. Documents use structured JSON format, with fields including consultation subject code, consultation item details, submission timestamp, response progress identifier, official response text, and associated state-owned assets supervision document number. The code is a string type, the timestamp is a millisecond-level integer, the progress identifier is a fixed enumeration value, the response text is an unlimited-length text, and the document number uses standard regulatory document string formatting.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources include internal tickets and state-owned assets supervision ledgers. This requires interfaces to connect to the internal system's identity authentication system to ensure compliance of call permissions. Real-time update business requirements mean interfaces must support real-time callbacks or long polling mechanisms. Timeout settings must adapt to the average circulation duration of state-owned assets services. Structured field requirements mean requests and responses must strictly match preset formats, and sensitive fields such as associated supervision document numbers cannot be omitted. Monthly existing data synchronization batch requirements also require interfaces to support paged queries to avoid excessive data transmission in a single request. Interfaces must also verify consultation subject codes to achieve data isolation.

## How to set the configuration

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Carry a Bearer token issued by the state-owned assets internal system, formatted as `Bearer <token>` | Adapt to the identity authentication requirements of state-owned assets systems to ensure the legality of interface call permissions |
| `variables` | Pass `{"org_code": "corresponding operation company subject code", "policy_scope": "state-owned assets supervision scope"}` | Limit the interface to only process consultation data of the company and within the supervision scope, avoiding cross-subject data leakage |
| `responseData` | Only return the `consult_id, submit_time, reply_status, reply_content` fields | Streamline response content, comply with the data desensitization requirements of state-owned capital operation companies, and reduce transmission overhead |
| Request timeout period | 600 seconds | Adapt to the average circulation duration of state-owned assets service consultations, avoiding timeout interruptions caused by process approval |
| Paged query upper limit | First 200 entries | Adapt to the batch processing requirements of monthly existing data synchronization, avoiding excessive data volume in a single request |
| Callback address | Configure as the callback interface path of the internal ticket system | Implement real-time synchronization of consultation status changes, meeting real-time update business requirements |

## Three Common Misconfigurations
- Issue: Consultation records returned by the interface cannot distinguish tickets from different operation company subjects, and some fields are empty. Cause: The correct subject code parameter was not passed in `variables`, causing the interface to not perform data isolation.
- Issue: A 401 status code is returned after calling the interface, indicating authentication failure. Cause: The `Authorization` parameter was not configured correctly, the token format is incorrect or the token has expired.
- Issue: The number of results returned by the batch synchronization interface does not match expectations, only a small number of entries are returned. Cause: A reasonable paged query upper limit was not set, or the paged offset parameter was not handled.

## How to Confirm the Configuration is Properly Set Up
- Call the interface configured with the `Authorization` parameter, check that the response status code is 200, confirming that identity verification has passed.
- Pass the test `variables` subject code parameter, query the company's consultation tickets, confirm that only data corresponding to the subject is returned.
- Initiate a request with a 600-second timeout period, simulate a consultation query with a long process, confirm that the interface does not interrupt prematurely.
- After configuring the callback address, submit a test consultation ticket, confirm that the internal system receives the callback notification of status change.
