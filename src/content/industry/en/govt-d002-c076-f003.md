# Work consultation and reply for state-owned capital operating companies: Multi-turn dialogue and prompt words

## What this category of data looks like
Work consultation data for state-owned capital operating companies mainly comes from internal state-owned asset supervision documents, group operation monthly reports, subsidiary business ledgers, and local state-owned asset department service guidelines. Data updates follow monthly or quarterly cycles, and are synchronized immediately when new policies are released. Documents use official document formats, including fields such as document number, issuing unit, effective date, applicable subjects, work processes, and responsible departments. Units for amounts, service consultation volume, and processing duration are included in relevant content.

## Constraints on multi-turn dialogue and prompt engineering
The official document format requires multi-turn dialogue to accurately match fields such as document number and effective date. Avoid fuzzy matching to prevent incorrect replies. Monthly and quarterly updated data requires regular synchronization to the knowledge base. Multi-turn dialogue context must filter expired information. Fields include units such as amounts and service consultation volume. Prompt words must clearly require attaching corresponding units when outputting replies. For process-oriented work consultation, retain historical dialogue nodes in the `messages` field. This ensures subsequent questions can reference prior information such as the applicant subject and processing progress.

## Three common configuration mistakes
- Symptom: The dialogue interface displays "No permission to operate this conversation record". Cause: `chatId` and internal group accounts are not correctly bound, session permission verification fails.
- Symptom: Citations are forcibly displayed at the end of replies and cannot be turned off. Cause: The answer citation display switch is not configured, or the switch configuration does not match the formal reply format for work consultation.
- Symptom: No quick buttons appear in the dialogue opening screen, and users must manually input questions. Cause: Quick question options corresponding to preset `variables` are not configured, or quick button configuration is not enabled.

## How to verify successful configuration
- Launch a test dialogue, input a work-related question, and check if historical dialogue nodes are retained in the context.
- After configuring the `chatId` binding rule, launch dialogues using different accounts, and check if session permissions are isolated.
- Adjust the answer citation display switch, and check if citations at the end of replies match the expected format.
- Trigger preset `variables` variables, check if quick buttons display correctly and can be sent directly.
