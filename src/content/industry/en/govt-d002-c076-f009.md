# State-owned capital operation company service consultation and reply: Model access and configuration

## What the data for this category looks like
Service consultation and reply data for state-owned capital operation companies mainly comes from service guide documents in the internal state-owned assets supervision system, archived annual consultation tickets, window service records, and public state-owned assets policy documents. Data updates are triggered by adjustments to state-owned assets policies. Service guide documents are updated quarterly. Consultation tickets are archived daily. Document structures include fields such as service item name, handling subject, application material list, handling time limit, consultation channel, and frequently asked questions. Field units include working days, copies, numbers, and others. Some documents are structured tables, others are plain text explanations.

## What constraints these characteristics impose on the "model access and configuration" link
First, data comes from intranet systems and policy documents. Deployment servers cannot access the public internet. Model access must use intranet-deployed model services, and cannot rely on public network APIs.
Second, documents include structured tables and plain text. Fields have dedicated units. Recall and matching rules must adapt to field structures and units to avoid matching errors.
Third, data update rhythm is not real-time. The vector knowledge base does not need high-frequency full updates. Only incremental synchronization is required after policy adjustments.
Fourth, service consultation requires strict compliance. Model output must match official policy content. Generation accuracy has high requirements.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | The context for service consultation includes policies, ticket history, and user questions. Sufficient contextual association must be retained to ensure coherent replies |
| `maxTokens` | `2000–3000 token` | Service replies must clearly outline handling steps, avoid overly long output that exceeds interface limits, while ensuring content completeness |
| `quoteMaxToken` | `1500 token` | Reference fragments from service guidelines must be complete but not redundant, adapting to the standard length of state-owned assets policy documents |
| `temperature` | `0.2–0.4` | Service consultation requires accurate and compliant content, avoid generating unofficial or casual content, reduce generation randomness |
| `AIPROXY_API_ENDPOINT` | Intranet-deployed model service address, for example `http://192.168.10.20:8000/v1` | The server is located on an intranet and cannot access the public internet, so a local proxy endpoint must be used to connect to the model service |
| `AIPROXY_API_TOKEN` | Dedicated access token allocated by the intranet model | Ensure the security of intranet model calls and prevent unauthorized access |

## Three common configuration errors
- Phenomenon: The interface displays a model channel error `error`, and a "data acquisition exception" field appears in the call log. Cause: `AIPROXY_API_ENDPOINT` is not configured to point to the intranet model address. The public network cannot connect to the intranet-deployed model service.
- Phenomenon: Vector recall results do not include dedicated fields such as service item name and handling time limit, or the number of recalled entries does not match expectations. Cause: Matching rules are not set for the structured fields of state-owned assets service documents. Only general text fragments are matched, and dedicated fields are not associated.
- Phenomenon: The generated reply does not reference the corresponding policy basis, or the reference fragment is incomplete. Cause: The value of `quoteMaxToken` is too small. The reference policy document fragment is truncated, and cannot match the complete policy basis content.

## How to confirm the configuration is complete
- On the intranet-deployed FastGPT v4.17.0 server, use the built-in model testing tool to initiate a call. Confirm that no `error` is returned.
- Import 10 state-owned assets service guide documents. Perform a vector recall test. Check that the returned reference documents include dedicated fields such as service item name and handling time limit.
- Submit a test consultation question. Check the call log. Confirm that there are no fields related to "data acquisition exception", and all log fields are complete.
- Verify that the content returned by the API response complies with service consultation compliance requirements. No non-official expressions are included.
