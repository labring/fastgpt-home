# State-owned capital operation company service consultation and reply: Deployment and upgrade

## What the data for this category looks like
Service consultation and reply data for state-owned capital operation companies primarily comes from consultation tickets submitted via internal office systems, state-owned assets supervision platforms, and offline service windows. Data update rhythms vary by business scenario: daily consultation tickets update in real time as users submit them, while reply content for state-owned assets policy consultations updates weekly as regulatory policies are adjusted. Each consultation document includes fields such as consultation ID, request content, processing status, involved business type (e.g., property rights transfer, investment and financing management), feedback target unit, and more. Field units include numeric ID, working day duration, character length, and others.

## What constraints these characteristics impose during deployment and upgrade
This explanation is based on the deployment logic of FastGPT v4.17.0, combined with the business characteristics of state-owned capital operation companies. State-owned assets consultation data is sourced from multiple dispersed locations, including internal systems and supervision platforms. During deployment, adaption rules for multi-source data docking must be configured to avoid data format conflicts. Data update frequencies fall into two categories: real-time and periodic. During upgrade, adjust the vector database incremental synchronization mechanism to adapt synchronization cycles to different update rhythms. Business fields include state-owned assets-specific business type classifications. Metadata labeling for the knowledge base must match these classification rules to ensure retrieval accuracy. Data involves state-owned assets supervision-related content, so storage and access must comply with state-owned assets compliance requirements. During deployment, configure compliant storage and permission rules.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `300–500 requests per minute` | Matches peak consultation concurrency during regular office hours to prevent database connection pool exhaustion |
| `STORAGE_S3_ENDPOINT` | Internal state-owned assets cloud compliant storage node address | Ensures policy documents and attachment data related to consultations reside in a compliant state-owned assets supervision storage environment |
| `REDIS_URL` | Internal dedicated cache cluster address, set expiration time to `1800 seconds` | Caches reply content for high-frequency consultations to reduce repeated database query pressure; 1800 seconds matches the daily consultation heat cycle |
| `FE_DOMAIN` | Official domain name of the company's internal service consultation portal | Unifies service entry and complies with internal system domain management specifications |
| `FILE_TOKEN_KEY` | Exclusive key generated according to the company's key management process | Ensures access permission security for uploaded consultation attachments and policy documents |

## Three Common Mistakes
- Phenomenon: An error indicating the file size limit is exceeded appears when uploading state-owned assets policy files, and the files cannot be imported into the knowledge base. Cause: The upload file size limit parameter was not configured when starting the MinerU container, and the default 2MB threshold was used, which cannot adapt to the typical length of state-owned assets policy files.
- Phenomenon: Connection timeout or page failure to load occurs when accessing the locally deployed FastGPT service via `ip:3000`. Cause: `FE_DOMAIN` was not correctly configured as the local access address, or internal network access permission for port 3000 was not enabled.
- Phenomenon: Incremental update of the knowledge base is delayed, and replies to old policy consultations do not sync the latest regulatory requirements. Cause: The vector database incremental synchronization cycle was not adjusted according to the update rhythm of state-owned assets policies, resulting in data updates lagging behind regulatory policy changes.

## How to Verify Correct Configuration
- Run database connection stress tests to verify that the connection count configured for `DB_MAX_LINK` can cover daily business peaks. Specific peak values are calibrated based on internal office hour consultation volumes.
- Upload an attachment matching the typical length of state-owned assets policy files to verify that the upload and knowledge base import processes function normally. Adjust the file size limit according to business requirements.
- Access the configured `FE_DOMAIN` to confirm that the service loads normally and internal permission verification takes effect. Configure access rules according to internal office network requirements.
- Trigger an incremental synchronization task to verify that the knowledge base's policy data can complete updates according to the set cycle. Determine the synchronization frequency based on the update rhythm of state-owned assets policies.

The values provided are common starting points and should be measured against the reader's own samples.
