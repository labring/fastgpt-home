# Municipal Water Utilities Service Inquiries and Responses: Document Parsing and Chunking

## What this category’s data looks like
Municipal water utility service inquiry and response data primarily comes from official service guides, pipe network operation documents, payment notices, and repair process manuals. Updates are made on an as-needed or monthly basis.
Document types include PDF pipe network drawing descriptions, Word service process manuals, and standardized service guidance documents. These contain fields such as service item number, processing time limit, charging standards, and service hotlines. Common units include cubic meters, yuan/ton, and workdays.

## Constraints on document parsing and chunking
PDF documents with pipe network drawings contain mixed chart and text content. Standard parsing tools cannot fully extract structured information, so mixed-format parsing must be adapted.
Standardized service guidance documents have fixed chapter structures. Chunking must not break business logic, so splitting must follow chapter boundaries instead of hard truncation.
Some individual documents have long total lengths. Chunk length must match the common scope of business inquiry questions to avoid losing contextual association after splitting.
As-needed updated documents require incremental parsing to reduce repeated processing costs.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Matches the chapter and paragraph length of municipal water utility service documents, avoiding loss of complete business information such as service processes and charging standards after splitting |
| `chunkSplitter` | Split by chapter | Adapts to the fixed structure of standardized service guidance, preserving the integrity of business logic |
| `customPdfParse` | Enable mixed-format parsing | Processes PDF documents containing pipe network drawings and charts, fully extracting text and graph-associated information |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the upload requirements of large individual pipe network operation PDF documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Prevents timeout errors during large document parsing |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for the special structure of water utility documents, adapting to contextual requirements of business inquiries |

## Three Common Configuration Mistakes
- Uploading a large pipe network PDF results in parsing failure with a timeout status code. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter; the default timeout duration is insufficient for large document parsing.
- Some PDFs containing pipe network drawings fail to recognize valid text. The cause is failure to enable `customPdfParse` mixed-format parsing; standard parsing can only extract plain text content, losing description information associated with the drawings.
- An error occurs when calling the document parsing tool in a workflow, and the uploaded file address cannot be read. The cause is failure to configure the corresponding environment variable; the local deployment environment cannot directly access local uploaded file paths.

## How to Verify Correct Configuration
- Upload a typical water utility service guide PDF, and check if the parsed text includes complete fields such as service items and processing time limits.
- Adjust the `chunkSize` parameter, then confirm that chunking results are split by chapter without incomplete cross-chapter paragraphs.
- Upload a pipe network operation document of approximately 100 MB, and verify that the parsing process does not trigger a timeout error.
- Check the system configuration items to confirm that the values of `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` align with current document processing needs.
