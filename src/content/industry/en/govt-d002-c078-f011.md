# Municipal Water Utilities Service Inquiry and Response: Forms and Interactions

## What this category of data looks like
Data for municipal water utility service inquiries primarily comes from water utility group operation management systems, pipeline network monitoring platforms, and offline repair work order repositories. There are two update schedules: real-time monitoring data such as pipeline network water quality and water pressure syncs every hour, while business data like repair work orders and payment guides updates daily. The document structure includes fields such as pipeline network point numbers, water quality indicator values, repair process steps, and fee schedule items, with most units being professional water utility units such as MPa, mg/L, and cubic meters.

## What constraints these characteristics impose on forms and interactions
The dynamic update nature of real-time monitoring data requires forms to support pulling the latest parameters in real time, and static cached storage should not be used. The presence of professional fields such as point numbers and water quality indicators requires forms to preset unit suffixes and restrict input formats. Differences in fields across multiple business scenarios require support for scenario-based form switching. The need to load large volumes of pipeline network point data requires forms to support paginated loading and fuzzy matching retrieval, to avoid interaction lag caused by loading too much content at one time.

## How to Configure
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Split fields by business scenario: repair scenario includes point number and fault type; payment scenario includes household number and payment amount | Match the differences in field requirements across water utility business scenarios, reduce user input errors |
| `userSelect` | Point number supports fuzzy matching dropdown, preset 100 common fault type options | Adapt to quick retrieval of large volumes of pipeline network point data, lower the threshold for entering professional terminology |
| File upload configuration | Limit single file size to no more than 1000 MB, support uploading jpg and pdf format files | Match the conventional storage limits and formats for water utility inspection photos and work order attachments |
| Streaming response toggle | Enable | Optimize the interaction experience for long-text inquiries, avoid the feeling of waiting caused by one-time output |
| Parameter validation rules | Perform 6-12 digit format validation on household number and point number fields, automatically complete unit suffixes such as MPa and mg/L | Avoid input errors for professional units, ensure data formats meet water utility system requirements |
| Voice input integration | Connect to general ASR services, support real-time transcription | Adapt to voice inquiry needs in offline service scenarios, improve input efficiency |

## Three Common Mistakes
- Issue: After adding a custom water utility business plugin, the input and output parameters do not appear in the workflow, and no error logs are generated. Cause: The `formInput` and `userSelect` associated fields were not correctly bound in the FastGPT v4.17.0 plugin configuration page, causing parameters to fail to sync to workflow nodes.
- Issue: After uploading water utility pipeline network photos, the document parsing tool reports an error that it cannot read the file address. Cause: The file storage path for form uploads and the access permissions of the document parsing tool were not configured, causing the tool to fail to obtain file resources.
- Issue: After triggering an inquiry, the response is a one-time output with no segmented streaming effect. Cause: The streaming response configuration item was not enabled, causing the system to aggregate all results and return them uniformly.

## How to Verify Successful Configuration
- A test form is submitted, and the automatic completion of the point number unit suffix is checked, and the format is verified against water utility professional requirements.
- A water utility inspection photo under 100 MB is uploaded, and it is confirmed that the parsing tool can normally read the file content and generate corresponding knowledge base entries.
- A streaming response test is triggered, and it is checked whether the inquiry content is output in segments step by step, with no situation of waiting for a long time before one-time return.
- The custom water utility business plugin is called, and it is confirmed that the preset input and output parameter list can be normally displayed in the workflow node.
