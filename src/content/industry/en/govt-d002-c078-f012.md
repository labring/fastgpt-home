# Municipal Water Affairs Service Consultation and Reply: Deployment and Upgrade

## What data for this category looks like
Data for municipal water affairs service consultation and reply comes from water service operators’ customer service systems, 12345 citizen hotline transfer cases, and offline service window registration ledgers. Data updates include real-time incremental synchronization of new consultation and completed records, as well as weekly full historical archive updates. Each single data entry contains 8 fields: consultation subject, consultation item, request details, handling link, reply content, completion status, handling time limit, and responsible department. Field types are mainly text and enumeration values, with some time fields using standard timestamp units.

## What constraints these characteristics impose during deployment and upgrade
Municipal water affairs service consultation data has dispersed sources. Deployment must support access configuration for multi-source heterogeneous data. Data updates use two modes: real-time incremental and scheduled full synchronization. During upgrades, synchronization tasks must not interrupt current handling processes, and gray upgrade trigger thresholds must be configured. Consultation content includes professional terms such as pipeline operation and maintenance, water meter calibration. Dedicated term glossaries must be associated to avoid semantic recognition deviations. Most water affairs service scenarios are deployed in intranet environments. HTTP proxy configuration with username and password must be supported to ensure normal access to external knowledge base and model interfaces.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/dbname?authSource=admin` | Stores unstructured consultation messages and reply scripts, meets semi-structured storage requirements for water affairs data |
| `PG_URL` | `postgresql://user:pass@host:5432/water_affairs?sslmode=disable` | Stores structured fields such as work order numbers and completion times, ensures data query efficiency |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches standard replies for high-frequency consultations and professional term mappings, reduces database query load |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent access volumes of water affairs data, prevents database connection exhaustion |
| `STORAGE_S3_ENDPOINT` | Fill in according to intranet storage service address | Stores attachment materials related to consultations, such as user-uploaded water meter photos and pipeline drawings |
| `FE_DOMAIN` | Intranet-accessible frontend domain name or IP:port | Configures the access address for the service consultation page, adapts to water affairs intranet office scenarios |

## Three common misconfigurations
- Phenomenon: After upgrading to FastGPT v4.17.0, configured professional models fail to take effect, and the chat automatically switches to other models. Cause: The original application's model binding configuration was not retained during upgrade, or the `ROOT_KEY` configuration item was not correctly associated with application permissions.
- Phenomenon: External model interfaces cannot be accessed during intranet deployment, with connection timeout prompts. Cause: HTTP proxy with username and password was not configured, or proxy parameters were not synchronized to all service nodes.
- Phenomenon: Responses to professional consultations such as abnormal pipeline pressure are inaccurate, with term misunderstandings. Cause: No dedicated water affairs term glossary was associated, or the glossary update frequency did not match business changes.

## How to confirm configurations are correctly set
- Run cross-system data synchronization scripts, check whether water affairs consultation-related data can be pulled normally, and confirm that the connection status of `MONGODB_URI` and `PG_URL` is normal.
- Submit a test consultation containing professional terms, check whether the reply calls the preset water affairs term glossary, and confirm that the cache configuration takes effect.
- Back up the current application configuration, perform an upgrade operation, verify that configuration items are not lost after the upgrade is complete, and confirm that the permission association of `ROOT_KEY` is normal.
- Access the configured frontend address in the intranet environment, confirm that the `FE_DOMAIN` configuration is correct, and that the consultation interface loads and interacts normally.

The values provided are common starting points and should be measured against the reader's own samples.
