# Urban Gas Service Consultation and Response: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Urban gas service consultation data primarily comes from official service guides of local gas operating enterprises, user frequently asked question repositories, and pipeline network operation specification documents. The data update rhythm is triggered by local policy adjustments or business process changes, with no fixed cycle but no more than 30 days between updates. Individual documents are mostly split by service items, including fields such as item name, required handling materials, handling time limit, charging standards, and consultation channels. Time limit units are mostly working days, and charging units are mostly yuan/cubic meter or yuan/household.

## What constraints these characteristics impose on the multi-turn dialogue and prompt link
The document structure split by service items requires multi-turn dialogue to track the specific current handling item, to avoid response deviations caused by context confusion. Non-fixed cycle updates require the dialogue system to verify the latest version of the knowledge base before each call, and a guide for data timeliness verification must be included in the prompt configuration. The multi-field document structure requires the prompt configuration to clearly specify that responses must prioritize matching corresponding fields; for example, handling materials must be listed separately and must not be mixed with charging standard content. Differences in gas data across regions require the dialogue system to automatically match corresponding knowledge base entries based on the user's location.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Matches the typical length of individual urban gas service item documents, to avoid truncation of core information such as handling materials and time limits |
| Single Recalled Entries | Top 3 entries | Core consultation content for gas services is concentrated in 3 or fewer official documents; excessive recalled entries will increase context redundancy |
| `variables` Configuration | Bind user location parameter | Automatically matches corresponding regional gas service knowledge base entries, to avoid cross-region response deviations |
| Question Optimization Switch | Enabled | Most gas user consultations use colloquial expressions; optimization allows more accurate matching of standardized service entries in the knowledge base |
| `chatId` Configuration | Bind user's current handling item ID | Tracks multi-turn dialogue context, to avoid context confusion across users or handling items |
| Knowledge Base Version Verification | Executed before each session | Adapts to the non-fixed update rhythm of gas policies, ensuring responses use the latest version of service guide documents |

## Three Common Misconfigurations
- A 503 error is prompted when uploading a gas service guide document via the dialogue window, but backend logs show the file upload was successful. The cause is that the `messages` parameter of the dialogue session is not correctly bound to the temporary storage path of the uploaded file, resulting in a frontend verification timeout while the backend has completed storage.
- When using a strict question-and-answer template, image address links in the knowledge base are retrieved, and a prompt indicating no answer found is displayed. The cause is that the prompt configuration does not include recognition rules for image links, and only matches text-based knowledge base entries.
- Context across handling items is not cleared during multi-turn dialogue, resulting in responses confusing handling materials for different items. The cause is that the current handling item is not bound via `chatId`, leading to context not being isolated per session.

## How to Verify Successful Configuration
- Initiate a multi-turn consultation for gas account opening, verify that the dialogue context is automatically isolated based on the bound handling item ID, and contexts from different sessions do not interfere with each other.
- Upload a gas service guide document, check that the frontend upload prompt and backend log status are consistent, with no abnormal errors or inconsistencies.
- Use a strict question-and-answer template to retrieve image address-based knowledge base entries, verify that the system can correctly recognize and return the corresponding content.
- Adjust the single recalled entries setting, verify that the number of returned knowledge base entries matches the preset configuration requirements.

The values provided are common starting points and should be measured against their respective samples.
