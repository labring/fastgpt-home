# Public Urban Construction Platform Service Inquiry and Reply: Forms and Interactions

## What this category’s data looks like
Service inquiry data for public urban construction platforms mainly comes from local government service platform appeal portals, the platform’s own work order system, and project approval archives. Data updates follow two main schedules: real-time synchronization upon work order completion, and daily batch archiving. Each data record includes fields such as appeal ID, item category, submission time, appeal content, processing status, reply opinion, and processing time limit. Most field units are "unit", "day", "yuan". Some project-type data includes binary attachments such as drawings and qualification documents.

## What constraints these characteristics impose on the forms and interactions link
Decentralized data sources mean the form must support cross-system data calls to avoid users re-entering existing information. Item categories cover multiple types such as municipal administration, infrastructure, and people’s livelihood, so multi-level classification is required to simplify user input. The processing time limit field requires the form to display a real-time countdown prompt to avoid overdue processing. Attachment upload must support large files such as drawings and qualification documents, while ensuring transmission stability.

| Attachment upload limit | Total size within 1000 MB, single file no more than 50 MB | Urban construction services often require uploading project drawings and qualification documents, and this setting adapts to common file sizes |
| Required form fields | Appeal content, contact information, processing location | Meets the core information collection requirements for urban construction service inquiries |

## Three common configuration mistakes
- After setting the search reference upper limit to 2000, short inquiry replies still exceed the token threshold. The cause is that the context token truncation rule was not configured synchronously, and the referenced knowledge base content was not cropped according to the actual available token count.
- The system cannot normally return TXT format processing results after form submission. The cause is that the file transfer format for `formInput` was not correctly configured, and the backend did not recognize the TXT file stream.
- Page lag occurs when switching multi-level `userSelect` classifications. The cause is that no classification cache was set, and full urban construction item data was re-requested every time a switch was made.

## How to confirm the configuration is complete
- Submit a test inquiry to check whether the form automatically matches the three-level classification options for the corresponding item.
- Upload a TXT format attachment that meets the size limit, and confirm that the system can normally receive it and trigger subsequent processing after submission.
- Trigger a cross-system data query, and confirm that the response time does not exceed the set 600 second threshold.
- View the knowledge base reference log, and confirm that the token proportion of each referenced content meets the expected configuration.
