# Municipal Investment Platform Service Consultation and Reply: Deployment and Upgrade

## What the data for this category looks like
Data sources for municipal investment platform service consultation and reply include government service hotline calls, offline service window registrations, online service hall messages, and transferred work orders from the 12345 citizen hotline. Data updates follow either real-time synchronization or hourly incremental pull schedules. Each consultation document includes these fields: unique consultation identifier, creation time, consultation subject type, item category, original appeal, reply content, handling node, and user feedback. Each field uses a standard data type: string, ISO8601 formatted timestamp, enumerated value, classification tag, plain text, rich text, status enumeration, or star rating numerical value.

## Constraints on Deployment and Upgrade
The above data characteristics impose clear constraints on the deployment and upgrade phase. Multi-source data access requires configuring synchronization adapters that support multiple protocols to pull consultation data from different channels. Real-time incremental updates require enabling incremental indexing mode when deploying FastGPT v4.17.0, to avoid excessive resource usage from full index rebuilding. Field standardization requires strict matching of knowledge base metadata mappings to the field names of municipal investment consultation data, to prevent data parsing errors. Sensitive data storage requires configuring encrypted storage parameters to comply with government data security specifications.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host1:27017,host2:27017/chengtao_consult?replicaSet=rs0` | Municipal investment consultation data requires highly available replica set storage to support concurrent queries and incremental synchronization |
| `DB_MAX_LINK` | `200` | Covers peak concurrent consultation data indexing and query requests during regular operations, preventing connection pool exhaustion |
| `REDIS_URL` | `redis://:redis_pass@internal-redis:6379/1` | Caches channel status and consultation session data; persistent configuration prevents loss of critical cache after restart |
| `STORAGE_S3_ENDPOINT` | `http://s3-internal.chengtou.gov.cn:9000` | Stores consultation attachments and documents; using internal object storage complies with government data security requirements |
| `FE_DOMAIN` | `https://service.chengtou.gov.cn` | Configures frontend cross-origin whitelist to ensure normal access to knowledge base content from municipal investment online service pages |

## Three Common Mistakes
- When creating a municipal investment consultation knowledge base after deployment, the index creation step times out continuously with no progress. Logs show database connection count exceeded limit. The cause is that the `DB_MAX_LINK` configuration value is lower than actual concurrent index request volume, leading to connection pool exhaustion.
- When adding a domestic large model channel connected via One API in FastGPT, the test passes but the channel shows as unavailable on the management page. The cause is incorrect `REDIS_URL` configuration. Channel status cache cannot be written normally, causing status synchronization failure.
- After configuring a data source for internal municipal investment systems, historical consultation data cannot be synchronized. The cause is that the `MONGODB_URI` does not configure access whitelists for the municipal investment database, so the database rejects external connection requests.

## How to Confirm Correct Configuration
- Access the FastGPT v4.17.0 admin backend, navigate to the data source configuration page, test the database connection corresponding to `MONGODB_URI`, and confirm a connection success prompt is returned.
- Navigate to the channel management page, test the One API channel, confirm the status changes to available, and no cache-related error logs are present.
- Upload a standard municipal investment consultation work order document, trigger manual index creation, confirm index progress completes within 10 minutes and valid vectors are generated.
- Access the configured `FE_DOMAIN`, navigate to the consultation knowledge base page, confirm uploaded consultation data can be normally retrieved and displayed.

The values provided are common starting points and should be measured against the reader's own samples.
