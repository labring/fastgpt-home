# Basic Chemicals Matter Consultation and Reply: HTTP Interfaces and External Systems

## What this category’s data looks like
Basic chemicals matter consultation data comes from internal enterprise work manuals covering safety production permits, environmental approval procedures, and other related documents. It draws on compliance guidance documents published by local emergency management and industry and information technology departments. Update frequency aligns with national or local chemical industry policy adjustments, and updates typically occur once per quarter. Document structure includes five core sections: matter name, handling entity, required materials, handling time limit, and consultation channel. Data fields include: matter name (string), handling entity (string), required materials list (array), handling time limit (working days), and consultation phone (string). All units follow standard domestic government service terminology.

## Constraints for HTTP Interfaces and External Systems
Basic chemicals matter consultation data involves compliance-related information, so HTTP interfaces require strict identity verification. Carry a compliant authentication token via the `Authorization` parameter to prevent unauthorized access to sensitive matter content. Data fields have a high degree of standardization and clear classification. Match the `variables` in interface requests strictly to preset fields to avoid data return errors caused by parameter mismatches. Data update frequency follows policy adjustments, so external systems must regularly verify the document version returned by the interface to ensure calls use the latest version of matter guidance. Some matter data links to multi-department external interfaces, and interface response times may fluctuate. Reserve sufficient timeout thresholds to ensure successful requests.

## Three Common Configuration Mistakes
- Phenomenon: When calling the matter consultation function via an HTTP interface, the external system does not receive the interactive prompt text entered by the user. Cause: No interactive prompt parameters are configured in `variables`, so the interface only returns pure business data and does not carry user-visible prompt content.
- Phenomenon: The returned matter materials list contains all original data and is not filtered according to custom rules. Cause: No filtering parameters are configured in `variables`, so all unprocessed business data is returned.
- Phenomenon: A 401 unauthorized status code is returned after calling the interface. Cause: The `Authorization` parameter format is incorrect, and no compliant authentication token is carried, so identity verification fails.

## How to Confirm the Configuration is Correct
- Call the interface with the correct `Authorization` parameter, and check that the return status code is 200.
- Pass a preset basic chemicals matter name, and check that the fields returned in `responseData` exactly match the configured `variables`.
- Simulate a timeout scenario, and confirm that the interface returns valid business data within 30-60 seconds.
- Import the structured data returned by the interface into an external test system, and confirm that the data format meets preset business requirements.
