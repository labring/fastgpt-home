# Basic Chemicals Service Consultation and Response: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The data for basic chemicals service consultation and response comes primarily from official compliance guidelines for basic chemical enterprises published by local industry and information technology, and emergency management departments. This includes official documents for matters such as hazardous chemical production permits and new project safety reviews, as well as industry compliance manuals. Data updates are aligned with the pace of official policy releases, with no fixed cycle. Most documents use a structured format, with fields including matter name, handling entity, handling time limit (unit: working days), list of application materials, and approval nodes. Some documents also include on-site inspection requirements and frequently asked questions.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
The structured fields and compliance attributes of basic chemicals service data require multi-turn dialogue to clearly guide users to ask questions by matter category, to avoid confusion across different matters. The handling time limit field measured in working days requires prompt engineering to clearly distinguish calculation rules for natural days and working days, to prevent time unit errors in responses. Data sources with no fixed update cycle require embedding a knowledge base synchronization verification link in the dialogue process, to ensure the latest policy documents are used. Additionally, the multi-item nature of the application material list requires multi-turn dialogue to collect material information sequentially, to avoid omissions caused by users submitting large amounts of information at once.

## How to Set Up the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier per session, calibrated based on actual testing | Used to distinguish different user service consultation sessions, avoiding context confusion |
| `messages` | Retain the most recent 8–12 rounds of dialogue content | Basic chemical service consultations often involve multi-round material collection; sufficient context fully conveys user requests and historical guidance |
| `variables` | Preset matter classification and handling time limit unit variables | Quickly locate corresponding service guideline fragments in the knowledge base, improving retrieval accuracy |
| Question Optimization | Enabled | Basic chemical matter names are complex; question optimization refines user core requests |
| Single Search Limit | Top 5–7 results | Matches the item density of basic chemical service data, avoiding interference from redundant information |
| Maximum Context | 7000–13000 token | Covers multi-chapter content of basic chemical service documents, ensuring complete response information |

## Three Common Configuration Mistakes
- An uncaught exception occurs when calling the dialogue component. This is usually because the format of `variables` or `messages` in the configuration file does not meet requirements, and parameters are not passed in the system’s preset JSON structure.
- Generated responses do not reference knowledge base documents. This is because the exclusive knowledge base for basic chemical service guidelines is not bound to the dialogue process, or search configuration filter settings are misaligned, leading to incorrect retrieval scope.
- The dialogue page or knowledge base page crashes. This is because the used FastGPT version is incompatible with the deployment environment’s dependency packages. Upgrade to FastGPT v4.17.0 and reinstall dependencies.

## How to Verify Successful Configuration
- A test dialogue is initiated, questions related to basic chemical services are entered, and the response is checked to confirm it includes compliant content from the knowledge base and that the retrieval scope is correct.
- The session log is reviewed to confirm that the `chatId` and `messages` parameters are passed in the preset format with no format errors.
- The multi-round material collection process is triggered, and the system is checked to confirm it guides users to submit application materials in order without missing necessary fields.
- The deployment service is restarted, and the dialogue page and knowledge base page are verified to have no crashes, confirming correct version adaptation.
