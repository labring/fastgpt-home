# Basic Chemicals Service Inquiry and Response: Deployment and Upgrade

## What Data for This Category Looks Like
Data for basic chemicals service inquiry and response mainly comes from internal enterprise process manuals, hazardous chemical safety supervision documents, product quality inspection reports, and equipment operation and maintenance logs. Data is divided into three categories:
1.  Long text: Process regulations and safety operation procedures, updated quarterly or as policies adjust
2.  Structured: Material parameter tables, including fields such as material number, CAS number, density, flash point, with units mostly g/cm³, ℃, MPa
3.  Short text: Service processes, such as hazardous chemical procurement approval steps and equipment maintenance request procedures, updated as internal systems adjust

Document formats include common formats such as PDF, Excel, and TXT.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Basic chemical data includes multiple content types: long text, structured tables, and short text, with significantly different update cycles.
During deployment, multi-type data storage must be supported.
During upgrade, incremental synchronization logic must be adapted to avoid excessive resource usage from full synchronization.
Fields for structured material parameters must be bound to knowledge base retrieval rules. Database mapping configuration must be completed before deployment.
During upgrade, verify that field mappings do not fail due to version updates.
Frequently consulted service processes and material parameters must be cached; otherwise, response delays will occur, affecting user experience.

| `MONGODB_URI` | `mongodb://chem_user:chem_pass@db-host:27017/fastgpt_chemical` | Stores unstructured long text data such as process documents and operation and maintenance logs, matching storage requirements for multiple types of unstructured data in basic chemicals scenarios |
| `PG_URL` | `postgresql://chem_user:chem_pass@db-host:5432/chemical_material` | Stores structured material parameter tables, including fields with units such as CAS number, density, flash point, supporting complex queries |

| `ROOT_KEY` | `Randomly generated 32-character English string` | Configures administrator access keys to ensure access security after deployment, complying with data security requirements in industrial scenarios |

## Three Common Misconfigurations
- Symptom: A `connection refused` error appears in logs after starting the container, and database connection fails. Cause: The account password or host address for `MONGODB_URI` or `PG_URL` is not configured correctly, resulting in failed database connection.
- Symptom: After deploying with Docker Compose, running the `docker exec -it fastgpt-redis redis-cli FLUSHALL` command to clear conversation records has no response. Cause: The Redis data volume is not mounted, or `REDIS_URL` is not configured to point to the correct Redis instance, resulting in failure to clear session cache.
- Symptom: After upgrading to FastGPT v4.17.0, the embedded front-end page fails to load, and the console returns a 403 Forbidden status code. Cause: `FE_DOMAIN` is not configured correctly. The new version's front-end domain verification logic has been updated, and requests from unbound specified domains are blocked.

## How to Verify Successful Configuration
- Run the `mongo --username chem_user --password chem_pass --host db-host --port 27017` and `psql -U chem_user -h db-host -d chemical_material` commands to verify that the databases configured via `MONGODB_URI` and `PG_URL` can connect normally.
- Start the service and access `FE_DOMAIN` to confirm that the front-end page loads normally and can initiate inquiry requests, with no console errors.
- Upload a basic chemicals process document to confirm that the file can be stored normally via the storage service corresponding to `STORAGE_S3_ENDPOINT`, and can be retrieved in the knowledge base.
- Initiate more than 3 frequent material parameter inquiries to confirm that the response time of the second and subsequent inquiries is significantly shortened, and the Redis cache takes effect.

The values given are common starting points and should be measured against the reader's own samples.
