# Basic Telecommunications Operation Service Inquiry and Reply: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data sources for basic telecommunications service inquiries include online service hall user inquiry records, offline service hall work orders, transcribed customer service dialogue texts, and billing and package rule documents. Updates are synchronized daily, as operators regularly revise package promotions, billing rules, and service terms. Each data entry includes the original inquiry question, user terminal type, attribution location information, package tier, reply script, completion timestamp, and question classification tags. All fields use standard text or timestamp formats, with no special units of measurement.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Basic telecommunications inquiry data includes user personalized information and real-time rules. Multi-turn dialogue must retain context such as user packages and attribution locations from `variables` to avoid repeating questions about information the user already knows. Data updates happen frequently, so prompt templates must sync with the latest rules daily. Outdated information will appear in replies if templates are not updated on time. Some inquiries involve long-text billing rule explanations, so multi-turn dialogue context length must accommodate long text inputs to avoid truncating key content. Telecommunications inquiries often include cross-step business handling processes, so the `messages` array must retain the full dialogue context to help the model understand the current session’s business scenario.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 8000–12000 token | Basic telecommunications inquiries often contain long texts such as package rules and billing details, to avoid truncating key context information |
| Context Retention Rounds | Previous 7 dialogue turns | Telecommunications inquiries mostly follow single-scenario, multi-step processes; retaining the last 7 rounds covers the complete business communication context |
| Variable Injection Switch | Enabled | Need to inject user package, attribution location and other information from `variables` to achieve personalized matching replies |
| Prompt Template Update Frequency | Synchronized daily | Match the daily update rhythm of operator promotions and rules, ensuring the timeliness of reply content |
| Dialogue Timeout Threshold | 60 seconds | Telecommunications inquiry replies need to call data from multiple systems, avoiding overly long waits that affect user experience |

## Three common misconfigurations
- Symptom: After upgrading FastGPT v4.17.0, model dialogue reply results end with rule traceability symbols. Cause: The system enables the prompt traceability display configuration by default, and the switch was not turned off in the template.
- Symptom: When calling the dialogue interface with high concurrency, some session reply results are empty. Cause: The session isolation parameter for `chatId` was not configured correctly, and concurrent requests overwrite shared context data.
- Symptom: When calling an MCP workflow in multi-turn dialogue, "none" is returned when the number of turns exceeds the threshold. Cause: The maximum length of the `messages` array was not limited, and context overflow causes the workflow to fail to parse the input normally.

## How to verify successful configuration
- Initiate a simulated user inquiry, send 3 related questions consecutively, and verify that the complete dialogue context is retained in the `messages` array.
- Inject test `variables` parameters such as package type and attribution location, and verify that the reply content matches the injected variable information.
- Configure a high-concurrency test script, initiate 2-3 call requests per second, and verify that sessions have no context overwrites or empty reply results.
- View the prompt template, confirm that the traceability display switch is not enabled, and verify that reply results have no extra symbols.
