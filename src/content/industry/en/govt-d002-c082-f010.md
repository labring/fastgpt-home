# Service Consultation and Response for Basic Telecommunications Operations: Knowledge Base Retrieval and Recall

## What this category of data looks like
Service consultation data for basic telecommunications operations mainly comes from internal customer service script libraries, tariff standard documents, network fault troubleshooting manuals, user frequently asked question banks, and official service handling guides. Updates are triggered by new service launches, tariff adjustments, and rule changes. There is no fixed update cycle, but update frequency is high. Documents follow standardized structures, including fields such as business type, applicable region, effective time, handling channel, and tariff unit. Some long documents include step-by-step operation procedures, while short documents are standardized question-and-answer pairs.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Standardized fields require retrieval to match dimensions such as business type and applicable region, to avoid invalid cross-business recall. Frequently updated data requires the retrieval link to support near-real-time synchronization, to prevent returning expired tariffs or business rules. Step-by-step procedures in long documents need proper chunking, to avoid semantic fragmentation that reduces recall accuracy. Format differences across multiple data sources require unified preprocessing, to ensure embedding vector consistency and guarantee accurate question-and-answer matching.

## Configuration Settings
The following configurations apply to the knowledge base retrieval module of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Q&A content for basic telecommunications operations is mostly standardized. This range filters low-correlation redundant results while retaining valid matches |
| `limit` | Top 10 entries | Users in service consultation scenarios typically need 1 to 5 core results. Taking the top 10 entries covers potential extended needs and avoids interference from excessive results |
| `searchMode` | `local` | Targeted retrieval for internal business documents, avoids retrieving irrelevant external content, and adapts to the private data scenario of basic telecommunications operations |
| `usingReRank` | Enabled | Recall results after chunking long documents need reranking, to improve the ranking priority of core steps or key information, and adapt to long fault troubleshooting content |
| `datasetSearchUsingExtensionQuery` | Enabled | For vague user questions (such as "how to apply for broadband"), automatically expand to standardized query terms to match structured business document fields |
| `collectionIds` | Bind corresponding collection IDs by business domain | Data for basic telecommunications operations is split by business domains such as tariffs, packages, and faults. Binding corresponding collection IDs can accurately limit the retrieval scope and avoid cross-domain recall |

## Three Common Misconfigurations
- Phenomenon: Retrieval results exceed the expected business scope, returning irrelevant tariff or package content. Cause: The `collectionIds` scope-limiting configuration is not enabled, leading to cross-business domain recall of non-target data.
- Phenomenon: Retrieval returns expired business rules or tariff standards. Cause: Dataset incremental synchronization is not enabled, so knowledge base data is not updated alongside business changes.
- Phenomenon: The error `worker terminated due to reaching memory limit` occurs when starting knowledge base retrieval. Cause: The `limit` parameter is not adjusted, or long documents are not properly chunked. This causes excessive data loading during a single retrieval, exceeding memory thresholds.

## How to Confirm Proper Configuration
- Submit a consultation with a region parameter, such as "5G package tariffs in Beijing". Confirm that retrieval results only include content for Beijing region packages, to verify the `collectionIds` and field matching configurations.
- Submit a vague question, such as "how to troubleshoot broadband faults". Confirm that the query is automatically expanded to a standardized term and corresponding step documents are retrieved, to verify the `datasetSearchUsingExtensionQuery` configuration.
- View retrieval logs, confirm that returned result similarity scores fall within the 0.75–0.85 range, to verify the `similarity` configuration.
- Call the knowledge base API to submit a new tariff document. Wait for synchronization, then retrieve the corresponding content to verify dynamic content addition configuration.

The values provided here are common starting points, and should be measured against the reader's own samples.
