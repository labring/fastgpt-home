# Infrastructure Construction Service Inquiry and Reply: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data for infrastructure construction service inquiries comes from project construction logs, approval and filing documents, on-site inspection ledgers, bidding technical documents, and on-site problem feedback submitted by users. Update rhythm follows project progress. Updates are made immediately after approval and quality acceptance nodes are completed. Daily inspection records are synchronized weekly.

The document structure includes project number, construction node classification, responsible entity, original inquiry text, official reply content, and associated attachment fields. Multiple file formats are supported for attachments. The project number serves as the unique identifier. Reply timeliness is counted in working days.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
The project number, as the core identifier, requires that the project number provided by the user must be obtained first in multi-turn dialogue before associating corresponding context. This avoids cross-project confusion.

Multi-source document content requires prompts to clearly specify priority retrieval of approval and inspection data for the current project. Redundant content from non-associated projects must be filtered out.

The attachment field supports multiple formats and requires classified uploads. Multi-turn dialogue must include step-by-step upload entrances. This guides users to submit files by category: construction qualifications, on-site materials, and construction drawings.

The non-fixed update rhythm requires prompt templates to reserve dynamic update fields. This facilitates synchronization of the latest approval nodes and acceptance standards.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 characters | Infrastructure construction documents include multiple sections of construction logs and approval files. Sufficient space is needed for associated historical dialogue and document fragments. This configuration follows FastGPT v4.17.0 interface rules |
| Maximum number of attachments per conversation | First 4 entries | Matches four common attachment submission scenarios in project inquiries: qualifications, materials, drawings, and inspection records |
| `chatId` session persistence toggle | Enabled | Retains project number and attachment associations across dialogue turns. This ensures coherent multi-turn dialogue context |
| `variables` dynamic field configuration | Reserve two variables: project number, construction node | Matches exclusive project data for the current inquiry. Filters non-associated content |
| Single conversation timeout setting | 600 seconds | Matches standard reply timeliness for infrastructure construction inquiries. Prevents excessive user waiting time |
| `messages` historical context truncation threshold | Retain the most recent 10 turns of dialogue | Avoids excessive historical content occupying context space. Covers sufficient inquiry background information |

## Three common misconfigurations
- Cannot upload attachments such as construction qualifications and construction drawings by category during multi-turn dialogue. The cause is failure to configure step-by-step upload entrances and guide users to submit files by type.
- The `Cannot read properties of null (reading 'q')` error triggers during dialogue. The cause is failure to correctly bind the historical dialogue field of the `messages` parameter, leading to a null pointer when reading dialogue content.
- Low accuracy of problem classification recognition in workflows. The cause is failure to optimize prompt engineering for three infrastructure construction scenarios: construction, approval, and inspection. Generic models cannot match classification rules for these specific scenarios.

## How to confirm correct configuration
- Initiate an inquiry that includes a project number. Verify that the dialogue automatically associates the corresponding project’s approval documents and inspection records.
- Attempt to submit attachments by construction qualifications and on-site materials. Verify that the system identifies and associates the corresponding files separately.
- View the dialogue log. Confirm that the `chatId` parameter updates with the session, and no context loss occurs after session interruption.
- Input questions related to construction permits and quality inspections. Verify that the system automatically matches the reply logic for the corresponding classification.
