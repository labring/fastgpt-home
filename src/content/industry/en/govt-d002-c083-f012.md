# Service Consultation and Response for Infrastructure Construction: Deployment and Upgrade

This document is written for FastGPT v4.17.0, and provides configuration guidance for the deployment and upgrade of the service consultation and response function in the infrastructure construction industry.

## What this category of data looks like

Data is primarily sourced from construction project approval documents, on-site construction Q&A logs, government service consultation ticket archives, and project acceptance documents. Update frequency aligns with project progress: initial data is imported in bulk when a project starts, and real-time supplements are made when construction nodes change or policies are updated. Each document typically includes fields for project number, construction section scope, original consultation question, official response content, processing time limit, and responsible subject. Some documents have attachments such as CAD drawings and construction videos. Field units include workdays, square meters, kilometers, and similar units. There is no fixed uniform maximum document length.

## Constraints for Deployment and Upgrade

Infrastructure construction service consultation data includes multiple types of attachments and structured fields. Deployment must support large-volume file storage and structured data read/write operations. Data update rhythms are inconsistent: there are both bulk-imported historical project data and real-time submitted consultation tickets. A dynamically adjustable concurrent connection mechanism must be configured. Data from different construction sections must be strictly isolated to prevent cross-project data leaks. Dedicated access domain names and permission control configurations must be bound. Some data includes non-text attachments, so a dedicated storage node must be configured to ensure read/write efficiency. Predefined database indexes must also be set up to speed up queries for structured fields.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:securepass@db-host:27017/fastgpt_construction?authSource=admin` | Stores project consultation tickets, response content and project-related data; requires database authentication and a dedicated database name |
| `STORAGE_S3_ENDPOINT` | `https://s3.[self-built storage region].com` | Stores large-volume attachments such as engineering drawings and construction videos, adapting to the storage needs of infrastructure construction data |
| `FILE_TOKEN_KEY` | `Randomly generated 32-digit hexadecimal string` | Encrypts and binds access permissions for engineering attachments, ensuring only authorized users can view files for their corresponding construction section |
| `DB_MAX_LINK` | `10–12` | Adapts to concurrent database access requests across multiple projects, preventing service freezes caused by exhausted connection pools |
| `FE_DOMAIN` | `https://construction-query.[enterprise domain].com` | Binds a dedicated access domain name to achieve data isolation for service consultation across different construction sections |
| `ROOT_KEY` | `Random key generated only during initial deployment` | Configures the system's highest management permissions, avoiding security risks from default keys |

## Three Common Configuration Mistakes

- Symptom: After deploying FastGPT via Docker, the `packages/plugins/register` directory cannot be located, and custom plugins fail to load. Cause: The plugin initialization command was not added to the image build script, so the directory was not automatically generated.
- Symptom: When deploying locally with a large number of workflow nodes, text input becomes sluggish. Cause: The `REDIS_URL` configuration to enable caching services was not configured. High-frequency node status updates directly request the database, leading to excessive IO load.
- Symptom: An insufficient permissions error appears when attempting to import a service consultation template. Cause: A dedicated `ROOT_KEY` was not generated, so system administrator permissions to access the template import interface cannot be obtained.

## How to Verify Configurations Are Correct

- Run the database connection test command to verify that the database configured via `MONGODB_URI` can properly read and write project-related structured data.
- Upload an engineering drawing attachment, and test the access link generated via `FILE_TOKEN_KEY` to confirm that only authorized accounts can view files for their corresponding construction section.
- Access the configured `FE_DOMAIN` to confirm that the service consultation front-end page and associated project data load normally.
- Send multiple concurrent consultation query requests to confirm that no connection pool exhaustion error messages appear with the `DB_MAX_LINK` configuration.

The values provided are common starting points and should be evaluated against samples specific to the local deployment.
