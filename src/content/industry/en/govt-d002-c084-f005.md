# Bulk Commodity Trade Inquiry and Response: Tool Calling and Plugins

## What this category of data looks like
Internal trading systems, industry monitoring platforms, customs clearance APIs, and warehouse management systems are the primary sources of this data. Spot quotation data updates daily. Warehouse management systems synchronize warehouse inventory and real-time transaction records every minute. Trade contracts and customs documents generate alongside ongoing business processes. Each data entry includes fields including product code, specification model, origin, transaction unit price, warehouse volume, logistics node, and contract number. Common units include tons, cubic meters, yuan/ton, US dollars/barrel, and some fields use structured enumeration values.

## What constraints do these characteristics impose on the tool calling and plugin workflow?
The update rhythm of bulk commodity trade data varies widely. Real-time transaction and warehouse data require access to the latest status. When calling tools, avoid using expired cached data. Configure real-time interface pull logic. Data fields include multiple unit types and structured enumeration values. When calling tools, define clear parameter mapping rules to ensure correct unit conversion and enumeration value verification. Plugins must support multi-interface aggregation to handle multi-source data. Configure data source priority and conflict handling logic to prevent returning inconsistent business data.

The following configurations apply to FastGPT v4.17.0.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports dynamic calling needs for multiple bulk commodity trade business scenarios, and enables automatic matching of corresponding tools |
| `functionCall` | `["get_spot_price", "get_storage_info", "get_customs_declaration"]` | Limits the scope of tool calling, only allowing calls to pre-configured tools related to bulk commodity trade |
| Timeout duration | `30 seconds` | Prevents business interruptions caused by network latency in real-time interface pull scenarios |
| Data source cache duration | `5 minutes` | Balances update frequency and call performance for non-real-time data |
| Number of data entries returned per request | `Top 10 entries` | Prevents call timeouts caused by returning excessive data, and meets conventional business query requirements |
| Parameter validation switch | `Enabled` | Prevents returning invalid results caused by unit errors or illegal enumeration values |

## Three common errors
- The reference file name field returned after a tool call is empty. Cause: No data source association parameters were configured during tool calling, and no mapping relationship was established between returned data and original documents.
- An error is returned when directly calling the knowledge base query interface with an application key. Cause: Application keys are only used for front-end interface authentication. Tool calling requires using the API key assigned by the platform. Directly using application keys to initiate interface requests is prohibited.
- The unit of the tool call return result does not match business requirements. Cause: The parameter validation switch was not enabled, and no forced conversion or verification was performed on the unit field of the returned data, resulting in unit mismatch.

## How to confirm the configuration is complete
- Initiate a test call, check if the returned results include the configured data source fields, and confirm that parameter mapping is active.
- View the tool calling logs, confirm that the timeout duration configuration matches actual call duration, and no timeout errors occur.
- Pass test parameters with illegal enumeration values or incorrect units, confirm that the tool triggers a validation error, and verify that the parameter validation switch is enabled.
- Compare the returned results from multiple data sources, confirm that the aggregation rules follow the preset priority, and the returned results meet business expectations.
