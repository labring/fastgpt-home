# Bulk Commodity Trade Inquiry and Response: Forms and Interactions

## What the data for this category looks like
Business data for bulk commodity trade comes primarily from internal enterprise trade management systems, warehouse receipt management platforms, real-time quote terminals, and customs declaration databases. Data update frequencies include real-time (such as spot quotes), daily (such as warehouse receipt inventory), weekly (such as trade ledgers), and monthly (such as settlement reports). Individual business documents typically include fields such as contract number, product category (e.g., steel, coal, grain and oil), transaction quantity, pricing unit, trading party information, delivery location, and validity period. Common units are tons, cubic meters, and yuan per ton; some categories use smaller units such as kilograms or liters. FastGPT v4.17.0 supports structured parsing and associated calls for this type of data.

## What constraints these characteristics impose on forms and interactions
Bulk commodity trade has many data fields and unit differences, so forms must support multi-field binding and unit verification. Data with different update frequencies need matching loading timing. Real-time quote data requires dynamic refreshing, while static ledger data can be loaded in batches as needed. There is high demand for linked selection of trading parties and product categories, to avoid incorrect input combinations. Business processes involve multi-party confirmation and document review, so the waiting time for form submission must align with long business cycles. Too short a waiting time will interrupt the process.

## How to set the configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---- | ---- | ---- |
| `formInput` | Bind the four core fields: contract number, product category, transaction quantity, pricing unit, enable real-time verification | Covers core identification information for bulk commodity transactions, real-time verification prevents incorrect input |
| `userSelect` | Preset 8 high-frequency bulk commodity category options, link and bind the corresponding exclusive knowledge base | Reduces user input costs, matches the business document and knowledge base association logic for different categories |
| Form submission timeout | 600 seconds | Bulk commodity transaction processes involve multi-party confirmation and document review, which take a long time, avoid mid-process timeout |
| Dynamic loading trigger timing | Load the corresponding knowledge base within 300 milliseconds after selecting a product category | Matches user selection rhythm, reduces waiting time, improves interaction smoothness |
| Field verification rules | Verify according to preset units, allow a ±0.5% error range for quantity fields | Adapts to the reasonable floating range of bulk commodity measurement, avoids mistakenly blocking valid business |
| Global variable assignment | Bind the category selected via `userSelect` to the knowledge base selection variable | Enables dynamic matching of the knowledge base, avoids loading irrelevant business documents |

## Three common misconfigurations
- After configuring `userSelect`, selecting a product category returns irrelevant business documents. Cause: The options from `userSelect` are not bound to the knowledge base corresponding to the category, resulting in chaotic matching logic.
- The form does not have the reference switch enabled, but returns reference content after submission. Cause: The knowledge base selection in the global variable is not correctly associated with the product category entered in the form, and the full knowledge base content loads by default.
- Fixed data analysis operations cannot be bound to the corresponding work order. Cause: The contract number output by `formInput` is not used as a workflow trigger parameter, so the operation cannot be linked to a specific business document.

## How to confirm the configuration is set correctly
- Enter the form editing interface, check if `formInput` is bound to core transaction fields such as contract number and product category.
- Select any bulk commodity category option from `userSelect`, confirm that the knowledge base for the corresponding category loads automatically.
- Simulate entering input that does not match the preset pricing unit, check if the verification rule intercepts the error.
- Trigger the bound workflow, confirm that the contract number output by the form is correctly passed to the data analysis link.
