# Engineering Consulting Supervision: Service Inquiry and Response — Workflow Orchestration

## What This Category of Data Looks Like
Engineering consulting supervision data is primarily sourced from documents generated during project execution, including submission forms, on-site supervision records, acceptance reports, change visas, rectification notices, and similar materials. Data update frequency fluctuates with project progress. Updates occur immediately after each supervision activity or approval transfer is completed. Document structures include fixed structured fields and unstructured descriptions. Structured fields include project ID, supervision section, submission content, rectification requirements, response deadline, signature block, and more. Unstructured content includes on-site problem descriptions, rectification plans, and similar content. Field units typically include project ID (string), rectification deadline (days), submission amount (ten thousand yuan), and similar formats.

## Constraints Imposed on Workflow Orchestration
The fixed approval transfer workflow for supervision data requires the workflow to follow the core node sequence of submission, rectification, and review to avoid process confusion. Non-fixed data updates tied to project progress require the workflow’s data source pulling to adapt to dynamically updated project documents, without relying on fixed-cycle synchronization. Documents with both structured fields and unstructured content require the workflow to support both structured field extraction and natural language question answering processing. Supervision documents involve project permissions and approval responsibilities, so the workflow must include permission verification nodes to ensure data access complies with supervision specifications.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | Matches the length of single-section submission and rectification content in supervision documents, preventing truncation of key approval fields |
| Overlap Length | 100–150 characters | Preserves rectification requirement descriptions across chunks, preventing context breaks |
| Single Search Limit | Top 8 entries | Matches the number of documents associated with a single approval for supervision projects, covering key related materials |
| Maximum Context | 6000 token | Adapts to context transfer requirements for multi-node workflows, avoiding exceeding model window limits |
| variables | Bound by project ID | Enables data isolation for multiple supervision projects, ensuring each project’s workflow only accesses corresponding data |
| nodeId | Configured per approval node | Matches the three core supervision nodes of submission, rectification, and review, triggering corresponding processing logic |

## Three Common Misconfigurations
- A file upload node is configured in the workflow, but calling the document parsing tool returns an error. This occurs because the `CUSTOM_READ_FILE_URL` environment variable is not properly configured, preventing the tool from accessing the local path of uploaded files.
- The workflow’s question classification node cannot select a custom model. This occurs because the workflow availability permission for the corresponding model is not enabled in system configuration, and model visibility is only configured for simple question-and-answer scenarios.
- Extracted fields from supervision documents are empty. This occurs because structured field extraction rules are not configured, and only general document parsing is used without matching the exclusive field format of supervision documents.

## How to Verify Successful Configuration
- Upload a supervision submission form document, trigger the workflow, and check if structured fields such as project ID and rectification requirements are correctly extracted.
- Review the workflow run logs to confirm that the project ID bound in `variables` matches the current supervision project.
- Test trigger logic for different approval nodes to verify that the workflow executes corresponding processing steps based on the configured `nodeId`.
- Upload a supervision document containing scanned images, and check if parsed text includes key information such as the signature block.
