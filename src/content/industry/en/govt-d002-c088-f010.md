# Engineering Consulting Supervision's Service Consultation and Reply: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Engineering consulting supervision data primarily comes from project supervision plans, on-site inspection records, sub-project acceptance reports, bill of quantities, industry standard documents, and similar sources.
Data update cadence adjusts based on project progress.
On-site inspection records are updated weekly.
Acceptance reports are updated with each acceptance batch.
Industry standard documents are updated annually.
Most documents use a multi-chapter nested structure and contain large numbers of structured tables.
Fields include project number, supervision unit, acceptance conclusion, rectification requirements, and similar items.
Units include professional engineering measurement units such as square meters, cubic meters, ten thousand yuan, and workdays.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Supervision project documents are mostly project-specific. Retrieval scope must be strictly limited to the current project's knowledge base to avoid interference from cross-project data.
Documents contain large numbers of structured tables and professional engineering terms. The retrieval system must recognize field content within tables and match variants of professional phrasing.
Data update nodes are scattered and update frequencies are uneven. The synchronization mechanism must support incremental updates to avoid resource waste and delays caused by full synchronization.
Professional units within fields require precise matching to prevent retrieval deviations caused by inconsistent units.

## Configuration Settings
This document is written for FastGPT v4.17.0. The following configuration items are customized for the business characteristics of engineering consulting supervision.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Meets the precision requirement for matching engineering professional terms, avoids low-similarity irrelevant content, and covers variants of professional phrasing |
| `limit` | Top 8 entries | Engineering consulting supervision documents are mostly project-level long documents. Too many single recall results will exceed context length limits. 8 entries cover the main relevant nodes |
| `searchMode` | Semantic Retrieval | Adapts to matching professional terms and structured fields, and fits the fuzzy consultation scenarios of engineering consulting |
| `usingReRank` | Enabled | Performs secondary sorting of recall results by relevance, corrects local deviations from semantic retrieval, and adapts to segment matching for long documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically generates extended query terms for fuzzy questions in engineering consulting, covering associated expressions of professional specifications |
| `collectionIds` | Configured with the knowledge base ID bound to the project | Ensures retrieval only calls exclusive documents for the current supervision project, avoiding interference from cross-project data |

## Three Common Misconfigurations
- Phenomenon: Retrieval results fail to correctly match consultation questions with project variables, such as "What is the rectification period for the current project". Returned results do not associate with the context of the corresponding project. Cause: Variable reference binding rules are not configured correctly, and retrieval scope is not limited to the current project's variable context.
- Phenomenon: Knowledge base content is not synchronized with updates to supervision weekly reports and acceptance records. Retrieval results still show old version data. Cause: Incremental synchronization trigger rules are not configured, and only full synchronization is performed, leading to update delays.
- Phenomenon: Table-format dataset files cannot be selected on the knowledge base creation page. Cause: The table dataset parsing switch is not enabled, or the uploaded table file format does not meet the system's supported type requirements.

## How to Confirm Configuration is Correct
- Manually enter a professional question within the current supervision project, check if retrieval results only include exclusive documents for the current project.
- Upload an updated supervision weekly report, wait for synchronization to complete, then retrieve relevant keywords, confirm returned content includes the latest updated rectification requirements.
- Upload a document containing a quantity engineering table, retrieve professional terms within the table, confirm results include structured data from the table.
- Adjust the value of the `similarity` parameter, observe changes in retrieval result relevance, confirm the configuration takes effect.

The values given are common starting points and should be measured against the reader's own samples.
