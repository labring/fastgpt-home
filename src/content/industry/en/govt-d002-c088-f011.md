# Engineering Consulting Supervision Service Inquiry and Reply: Forms and Interactions

## What this type of data looks like
Engineering consulting supervision data originates from on-site supervision materials including project submission documents, acceptance records, change visas, and on-site inspection logs. Updates are synchronized following project submission milestones, with full synchronization completed after each submission is finalized. Documents use structured forms as their core structure, with fixed fields such as project number, supervision organization, submission item, rectification requirements, and rectification deadline. Some documents include attachments such as on-site photos and measurement data. Field units include square meters, construction period days, project price in ten thousand yuan, and similar units.

## What constraints these characteristics impose on forms and interactions
Engineering consulting supervision data includes fixed structured fields and attachment resources. Forms must match preset field rules to prevent users from entering non-standard content. There are many categories of submission items, so use option-based interaction to limit input scope and reduce format errors. The rectification deadline field must be paired with a day-unit time control to ensure input aligns with business logic. Attachments such as on-site photos and measurement data must support multi-format upload and preview, with submission scale validation required. Data is updated frequently alongside project milestones. After form submission, a data update process must be triggered synchronously to avoid information lag.

## How to configure

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable mandatory field validation | Match the structured field rules of supervision documents, ensuring input content conforms to preset formats |
| `userSelect` | Preset 3 core submission option categories | Cover the main business scenarios of engineering consulting supervision, reducing input error rates |
| Maximum number of attachments per submission | 5 per submission item | Match the conventional scale of on-site materials submitted at one time, avoiding exceeding storage load |
| Maximum single input character count | 800–1200 characters | Adapt to the conventional text length of rectification instructions, inspection remarks and similar content; calibrate over-length scenarios based on actual testing |
| Callback after form submission | Trigger project data synchronization | Ensure real-time updates to the supervision project database after form submission, maintaining information consistency |

## Three common misconfigurations
- Some fields are empty after form submission. This occurs because field validation for `formInput` is not enabled, and mandatory field input formats are not restricted, causing non-standard content to be filtered incorrectly.
- Attachment upload fails. This occurs because a reasonable upload quantity limit is not set, and the submission item exceeds the preset threshold, triggering system interception.
- The application returns an abnormal format. This occurs because the option value format for `userSelect` is not unified, causing the backend interface to fail to recognize the submitted submission type parameter.

## How to confirm the configuration is successful
- Submit a test form, check that non-standard input is blocked for mandatory fields, and verify that the validation function of `formInput` is active.
- Select a preset submission type option, confirm that the submitted parameter matches the preset value of `userSelect`.
- Upload test attachments, check that the upload quantity conforms to the preset limit, and confirm that the attachment preview function works properly.
- After submitting the form, verify that the corresponding data is updated in the project database, confirming that the callback process is functioning.
