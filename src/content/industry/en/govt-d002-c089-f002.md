# Administrative Inquiries and Responses for Construction Machinery: Vector Models and Indexes

## What Data for This Category Looks Like
The administrative inquiries and responses data for construction machinery comes primarily from equipment operation and maintenance manuals, troubleshooting case libraries, spare parts parameter lists, and official administrative process documents.
The data update rhythm falls into three categories: full manual updates synchronized with new model releases, quarterly updates to spare parts parameters and compliance processes, and daily additions of fault feedback cases for individual equipment.
Each individual document includes fixed fields such as equipment model, fault symptom, troubleshooting steps, solution method, spare parts number, response time limit, and others.
Units involve professional engineering units such as pressure value (MPa), operating duration (hours), dimensions (millimeters), and similar engineering units.

## Constraints Imposed on Vector Models and Indexing
The binding relationship between professional engineering parameters and operating steps requires retaining adjacent parameter descriptions and logic during chunking. This avoids semantic fragmentation after splitting.
Document types from multiple sources need to be grouped into separate index partitions based on manuals, cases, and processes. This prevents cross-category retrieval interference.
Frequently updated fault cases need support for incremental index triggers. This avoids resource consumption from full index rebuilding.
Fields such as equipment model and fault level must be used as retrieval filter conditions. This ensures recalled results match the target inquiry scenario.

## Three Common Configuration Mistakes
- Symptom: The vector model cannot be called normally after configuration. Timeouts or parameter errors are returned.
  Cause: Long parameter blocks of construction machinery documents are not adapted. The `maxToken` parameter is not set correctly, leading to truncation of embedding requests.
- Symptom: Old fault cases cannot be retrieved after index updates.
  Cause: Incremental index triggers based on document update timestamps are not configured. Full index rebuilding is accidentally enabled, leading to overwrite conflicts.
- Symptom: Retrieval results include documents from non-target equipment.
  Cause: Field filter configuration is not enabled. Equipment model is not specified as a retrieval matching condition.

## How to Verify Proper Configuration
- Upload a complete construction machinery fault document with full parameters. Check that the chunk preview retains continuous parameters and steps.
- Trigger an incremental index. Check that the index log only synchronizes updated documents. No full index rebuilding is triggered.
- Input an inquiry question that includes a specific equipment model. Verify that retrieval results only return documents for that model.
- Call the vector embedding interface. Check that returned vector dimensions match the configured model dimensions. No truncation errors appear.

The values provided are common starting points, and should be evaluated against local sample data.
