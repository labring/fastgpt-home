# Service Inquiry and Reply for Refined Oil Sales: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Refined oil sales service inquiry data comes from offline gas station operation ledgers, official price tag systems, member management backends, and after-sales ticket repositories. Data updates follow two schedules. Fuel product prices adjust daily based on market conditions. Promotional activities and member benefits are updated quarterly or via temporary notices. Most documents use structured entries, including fields such as gas station ID, fuel grade, current price, business hours, service items, and after-sales procedures. The unit for price fields is yuan per liter. The unit for business hours fields is hours.

## Constraints on multi-turn dialogue and prompt engineering workflows
The daily update nature of fuel prices requires every dialogue to retrieve the latest knowledge base. This avoids returning outdated information. Structured multi-field data requires prompts to explicitly specify calls to corresponding fields. This ensures returned results match precise dimensions such as gas station ID and fuel grade. In multi-turn dialogues, the user-specified gas station ID must be passed as a context variable. This prevents information confusion when consulting across different stations. Temporary adjusted promotional activities require prompts to prioritize retrieving the latest knowledge base entries. This ensures returned rules reflect the currently active version. Fixed formatting for field units requires prompts to explicitly constrain unit descriptions in returned results. For example, prices must be labeled with yuan per liter.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `chatId` | Bind to the current session's unique identifier | Distinguish multi-turn dialogue contexts for different users |
| `variables` | Configure global persistent storage | Retain globally static variables such as user-specified gas station IDs |
| `messages` | Limit the context window to 8000–12000 tokens | Cover key query dimensions in multi-turn dialogues |
| Knowledge base retrieval trigger condition | Force retrieval before each user question | Adapt to the daily update characteristic of fuel prices |
| Historical dialogue reference method | Automatically associate with current session context | Ensure information consistency across multi-turn dialogues |
| Single retrieval upper limit | Top 8 knowledge base entries | Match the entry scale of refined oil sales data |

## Three common misconfigurations
- Phenomenon: Some dialogues return fuel price information that does not match official daily release prices, and no knowledge base retrieval logs are displayed. Cause: Mandatory retrieval trigger rules are not configured, and the system skips retrieval by default when context is sufficient.
- Phenomenon: In multi-turn dialogues, subsequent questions do not associate the previously specified gas station ID, and the system returns information for the wrong station. Cause: Global persistent variable storage is not configured, and only session temporary variables are used, which are lost after session switching or timeout.
- Phenomenon: After multiple consecutive questions, knowledge base retrieval latency increases significantly, and newly initiated sessions return to normal retrieval latency. Cause: The context window length is not limited, and accumulated historical conversations lead to increased context processing overhead during retrieval.

## How to verify successful configuration
- Initiate a query involving fuel prices, verify that returned results match official daily release prices, and check dialogue logs to confirm knowledge base retrieval was triggered.
- Initiate a multi-turn dialogue: first specify a gas station ID, then ask subsequent questions without repeating the specification, verify that the system correctly associates information for that gas station, and confirm that variables are not lost.
- Initiate more than 5 consecutive questions, verify that knowledge base retrieval latency does not fluctuate significantly, and confirm that context window length configuration is reasonable.
- Review dialogue history, confirm that the system automatically associates previously mentioned fuel grades and service information, and confirm that historical dialogue reference configuration is active.

The values provided here are common starting points and should be evaluated against local deployment samples.
