# Fuel Oil Retail Service Inquiry and Response: Tool Calling and Plugins

## What the data for this category looks like
Fuel oil retail service inquiry data primarily comes from three sources: offline gas station POS transaction systems, internal enterprise oil product inventory and sales management systems, and publicly available oil product retail guidance prices released by local commerce authorities.
Update frequencies: Retail guidance prices update once daily. POS transaction data syncs in real time. Inventory data refreshes every hour.
Each inquiry-related document includes fields such as oil product number, oil product name, same-day retail unit price, corresponding station inventory quantity, station address, business hours, and more. Unit price is measured in yuan per liter. Inventory quantity is measured in liters. Address fields follow the format of standard administrative division plus specific street number.

## Constraints imposed on tool calling and plugin workflows
The multi-source nature of fuel oil retail data requires tool calling plugins to differentiate authentication rules for public and internal data sources, to prevent unauthorized access to internal inventory and transaction data.
Differences in update frequencies across data sources require plugins to set corresponding data cache durations. Retail guidance price data can be cached for 24 hours. Real-time transaction and inventory data must have a cache duration no longer than 1 hour.
Standardized field requirements mean tool calls must explicitly specify return fields to avoid redundant information. Unit formats must be unified, ensuring unit prices are always returned in yuan per liter.

## Configuration settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapts to flexible needs for multi-source data calls, automatically selects matching tool types |
| Cache Duration | Retail guidance price data: 24 hours; Internal transaction data: 600 seconds | Matches the update frequency of corresponding data sources, reduces unnecessary repeated requests |
| Return Field Specification | Only include oil product name, same-day unit price, station address, business hours | Aligns with core user inquiry needs, avoids returning redundant sensitive data such as inventory |
| Authentication Configuration | Enable API key verification for internal data sources | Ensures access security for internal inventory, sales and transaction data |
| Timeout Duration | 10–15 seconds | Adapts to typical response delays of gas station systems, prevents premature request termination |

## Three common configuration mistakes
- Receiving a 422 status code when calling a third-party large language model. The cause is incorrect formatting of the `functionCall` parameter, or missing valid tool calling parameters in the request body.
- Receiving a 400 invalid image error for multimodal inquiries. The cause is missing format validation for uploaded images, with non-standard format files or files exceeding size limits being passed.
- No query results when configuring an SQL data connection tool. The cause is using field names not specified by the fuel oil retail system, or missing the correct oil product number association condition.

## How to verify proper configuration
- Initiate a simulated inquiry by entering "What is today's retail price for 92-octane gasoline". Check if the returned result includes clear unit price and corresponding station information, with no redundant fields.
- Configure an internal data source call, use a test API key to initiate a request, check if the returned result only includes fields within the authorized scope, with no leakage of sensitive inventory data.
- Initiate a multimodal inquiry, upload a properly formatted gas station site photo, check if image parsing is triggered normally and corresponding inquiry results are returned.
- View plugin operation logs, confirm that the tool calling timeout duration setting is in effect, with no frequent timeout errors.
