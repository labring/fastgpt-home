# Building Engineering General Contracting Service Consultation and Reply: HTTP Interfaces and External Systems

## What this category of data looks like
Data for building engineering general contracting service consultation and reply mainly comes from project management systems, housing and urban-rural development department approval and filing systems, and on-site construction logs. The data structure includes fields such as unique project code, consultation item type, submission time, processing progress, and official reply content. The project code uses a string format, processing progress uses fixed enumeration values, and time fields use the YYYY-MM-DD HH:mm:ss format. Data updates are triggered by service process nodes, with no fixed cycle. Updates are only synchronized when the consultation item processing status changes or the reply is updated.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
Building engineering general contracting service consultation data is scattered across multiple internal systems. HTTP interfaces must support multi-source data access formats to ensure structured data returned by different systems can be uniformly parsed. Fields such as the unique project code are strongly bound. Interface requests must carry corresponding parameters to match the correct service data, so parameter validation must cover required fields and format requirements. There is no fixed update cycle for data, so interfaces must support real-time pulling of the latest replies in response to user consultation requests, and cannot rely on fixed polling caching. Consultation content is strongly tied to project progress, so replies returned by the interface must be bound to the current project to avoid returning irrelevant service information.

## How to set up configurations
These configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {External Service Interface Assigned Secret}` | Used for identity verification, ensuring only authorized FastGPT instances can call external service interfaces |
| `variables` | `{"project_code": "{{1}}", "consult_content": "{{query}}"}` | Passes the unique code of the building engineering project and the specific content of the user's consultation to match service data for the corresponding project |
| `responseData` | Extract the reply field under the root node | Building engineering service reply data is usually encapsulated under the reply field of the root node. Direct extraction allows quick integration into AI replies |
| Timeout setting | `30 seconds` | Building engineering service interfaces mostly depend on internal approval systems. 30 seconds covers most normal response durations and avoids excessive user waiting |
| Retry count | `2 times` | Handles temporary network fluctuations or interface jitter, preventing consultation interruptions from single request failures |
| Maximum length of single request parameter | `800–1200 characters` | Adapts to the typical content length of building engineering service consultations, preventing interface request rejection due to overly long parameters |

## Three common mistakes
- Phenomenon: Returns empty results after calling the external service interface. Cause: The unique project code parameter for the building engineering project was not passed in `variables`, so the external interface cannot locate the corresponding service data.
- Phenomenon: After configuring the API key on a Linux server, the interface keeps loading and cannot complete saving. Cause: The server has not opened outbound access permissions for the external interface, or the secret was not filled in the `Bearer {secret}` format, leading to identity verification failure.
- Phenomenon: The AI reply does not trigger the custom interface and directly returns preset content. Cause: The trigger rule is not bound to the building engineering service consultation scenario, or the keyword matching logic does not cover project-related consultation keywords.

## How to confirm the configuration is complete
- Call the FastGPT test interface, pass in the building engineering project number and consultation question, and check whether the external interface receives request parameters in the correct format.
- View the response logs of the external interface to confirm that the returned reply data structure matches the extraction rule configured in `responseData`.
- Initiate a consultation in the FastGPT test chat interface, and check whether the AI reply includes the service reply content returned by the external interface.
- Simulate network fluctuations, check whether the interface automatically retries according to the configured retry count and does not have abnormal repeated calls.
