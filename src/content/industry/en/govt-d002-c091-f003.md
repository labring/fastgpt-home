# Building Engineering General Contracting Service Consultation and Reply: Multi-turn Dialogue and Prompt Engineering

This document is written for FastGPT v4.17.0.

## What this category of data looks like
Service consultation data for building engineering general contracting comes from construction logs, change orders and visa documents, progress submission review documents from the internal project management system, as well as engineering construction specifications and government service guidelines released by local housing and urban-rural development authorities. Data update rhythm is adjusted according to project progress: real-time log updates during the construction phase, monthly progress review material updates, and permanent archiving after completion. Each document includes fields such as project number, general contracting unit information, construction phase, review request, approval opinions, attachment list, and others. Units include ten thousand yuan, calendar days, square meters, and similar units.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
Service consultation for building engineering general contracting involves multi-stage processes. Multi-turn dialogue needs to associate requests across all stages of the same project, so a unique identifier must be bound to avoid context confusion. The data includes structured fields and unstructured approval opinions, so prompt engineering must clearly distinguish extraction rules to prevent confusion between professional terms and general expressions. Data is updated frequently and over long cycles, so the time range and length of the context must be limited to avoid loading expired or redundant information that affects model understanding.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chatId` binding rule | Bind to unique project number | Building engineering general contracting projects have multi-stage service processes; a unique project number ensures multi-turn dialogue associates with the same project and avoids context confusion |
| `messages` context length | 800–1200 token | Building professional documents contain many proper nouns; limiting context length prevents model overflow and retains key process information |
| `variables` injection configuration | Inject review fields of the current project | Service consultations often require verifying project-specific parameters; injecting variables reduces repeated input and improves reply accuracy |
| Question optimization switch | Enabled | Building consultation involves professional process expressions; optimization improves the model's understanding accuracy of professional terms |
| Single dialogue return limit | Top 5 latest records | Service consultations usually focus on the latest approval results; limiting the number of entries avoids redundant information interfering with decision-making |
| Context time range | Last 180 days | The cycle of conventional building engineering projects does not exceed 180 days; limiting the time range filters expired historical data |

## Three common mistakes
- Phenomenon: Only single model calls can be selected during workflow orchestration, and hiding of step-by-step processing results and display of final results cannot be implemented. Cause: The intermediate step hiding configuration of the workflow is not enabled, and node call rules for multi-model series connection are not configured.
- Phenomenon: The newly added third-party model does not appear in the model selection list of the dialogue interface. Cause: The interface address and key of the corresponding model are not configured in the system backend, so the platform cannot recognize the newly added model.
- Phenomenon: After uploading a file via the dialogue API call, the returned result is empty or has an incorrect format. Cause: The binary stream or file identifier of the file is not correctly carried in the API parameters, so the platform cannot receive the uploaded file content.

## How to confirm the configuration is correct
- Initiate multi-turn consultations for the same project, check if the conversation history automatically associates with the current project number, and confirm that the `chatId` binding configuration is effective.
- Input a consultation question containing building professional terms, check if the model reply accurately extracts review fields, and confirm that the prompt engineering configuration and `variables` injection are effective.
- Call the dialogue API to upload a project-related construction log file, check if the API normally returns processing results, and confirm that the file upload configuration is correct.
- View the model selection list, confirm that the newly added third-party model is displayed in the options, and confirm that the system backend configuration is effective.
