# Building Engineering General Contracting Service Consultation and Reply: Workflow Orchestration

## What this category’s data looks like
The business data for building engineering general contracting mainly comes from project filing archives, construction logs, quality acceptance reports, housing and urban-rural development department service guidelines, and project-specific consultation ledgers. Data updates follow project milestones, and sync after key nodes including filing, construction, and acceptance are completed. Each document includes fields such as project number, project name, matter type, approval status, and consultation reply records. Units include square meters, construction days, approval matter numbers, and more. Document length varies widely, from service notices with hundreds of characters to special rectification plans with thousands of characters.

## What constraints these characteristics impose on workflow orchestration
Data for building engineering general contracting is scattered across multiple types of business documents and stored by project node. Workflows must support dynamic matching of corresponding knowledge base content based on project attributes. Document length varies widely, so preliminary screening of retrieval results is needed to avoid interference from redundant information. Fields include unique identifiers such as project-specific numbers, so precise invocation must be achieved through variable binding. Business consultations must be associated with specific approval stages. Workflows must support jumping to corresponding process nodes based on consultation content to avoid invalid replies across stages.

## Configuration settings
These configuration items apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Preset three core variables: project number, project category, and construction phase | Building engineering business consultations often relate to specific project attributes. Variable binding enables precise matching of documents for the corresponding project in the knowledge base |
| Tag filtering | Enable, bind knowledge base tags to project category and construction phase | Consultation demands for building engineering business are concentrated by construction phase. Tag filtering removes irrelevant documents from non-current phases |
| Maximum context | 800–1200 characters | Building engineering consultation documents are mostly long texts. Overly long contexts introduce redundant historical information and lower reply accuracy |
| Single search limit | Top 8 entries | Knowledge base entries for building engineering business are categorized by approval node. Too many results interfere with reply precision |
| `nodeId` | Bind to corresponding process node ID based on consultation matter type | Building engineering business consultations must jump to corresponding approval links based on filing, construction, acceptance, and other matters |
| Timeout threshold | 600 seconds | Loading knowledge base documents for building engineering business requires accessing multiple business systems. The timeout threshold must cover cross-system retrieval time |

## Three common configuration mistakes
- Knowledge base retrieval returns approval documents from non-current construction phases. This happens when tag filtering rules are not configured, and the current project’s construction phase tag is not bound via `variables`. The retrieval scope then covers the full knowledge base.
- Workflow execution stops at a specific node without any error logs. This happens when the required project number field is not passed in `variables`, so the node trigger condition is not matched, leading to process interruption.
- The chat window associates more than the set number of historical records. This happens when the maximum context value does not cover the character count of historical records, or automatically generated redundant system logs are not excluded. Old history is then incorrectly included in the context.

## How to verify correct configuration
- Upload a building engineering consultation document tagged "main structure construction", initiate a consultation for the corresponding phase, and confirm retrieval results only return content with the same tag.
- Submit test data missing the project number field in `variables`, and check whether the workflow triggers an abnormal prompt.
- Set the maximum context to the specified value, initiate a consultation with multiple rounds of history, and confirm the number of returned historical records meets the set requirements.
- Bind `nodeId` to a specified approval node, trigger a consultation of the corresponding type, and confirm the workflow jumps to the correct node.

The values provided are common starting points and should be measured against the reader's own samples.
