# Building Engineering General Contracting Service Consultation and Reply: Document Parsing and Chunking

## What the data for this category looks like
Data sources for building engineering general contracting include project bidding documents, construction organization designs, progress payment applications, change visa forms, completion acceptance reports, and material entry inspection records. Sources include project management systems, on-site construction ledgers, and official documents issued by the client and supervision team.
Document updates adjust in real time as the project progresses. Construction logs are updated daily. Progress payment applications are updated monthly. Archived files for large projects can range from dozens to hundreds of pages.
Document structures include fixed fields such as project number, construction area, material specification, engineering quantity, and schedule milestone. Units include cubic meters, square meters, tons, man-days, ten thousand yuan, and others. Some documents contain complex tables and engineering calculation formulas.

## What constraints do these characteristics impose on document parsing and chunking?
Building documents contain a large number of structured tables and engineering calculation formulas. Parsing must preserve table structures and the integrity of formulas. Chunking cannot break cross-cell engineering quantity associations.
Documents mostly use mixed formats of PDF, Word, and Excel. Multi-source parsing engines must be adapted to fully extract content.
Single documents have large file sizes and contain extensive associated data. Parsing duration and upload size must meet large file processing requirements.
Fields include specific engineering units. Chunking must retain the binding relationship between units and corresponding engineering quantities to avoid data failure after splitting.

## How to set the configuration
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Building documents contain long text passages and table splits. This range preserves engineering quantity association logic |
| `customPdfParse` | Enable Marker parsing | Building PDFs contain complex tables and formulas. Marker retains format and formula structure |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Single building project documents have large file sizes and rich content. Sufficient parsing time is required |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports upload of single large project archive files |
| `chunkSplitter` | Split by paragraph + heading | Matches the chapter hierarchy of building documents. Avoids splitting content associated with construction locations |

## Three common errors
- Parsing tasks submit without response, and the backend returns a timeout status code. The cause is failure to adjust `PARSE_FILE_TIMEOUT_SECONDS` to a value suitable for large building documents. The default configuration duration is insufficient for complex document parsing.
- Parsed documents lose tables and engineering formulas, retaining only plain text. The cause is failure to enable `customPdfParse`. The default parsing engine cannot handle complex tables and mathematical formulas in building documents.
- Split content shows engineering quantities separated from their corresponding units. The cause is an excessively small `chunkSize` value. This splits complete passages of single engineering quantity calculations into multiple chunks, breaking data associations.

## How to confirm the configuration is correctly set
- Upload a building PDF document containing complex steel bar engineering quantity tables and concrete strength calculation formulas. Check if the parsed result retains merged table cells and formula formatting.
- Upload a single 600 MB project annual archive file. Confirm the upload and parsing process runs without interruption and shows no error prompts.
- Select a complete passage containing "XX location concrete usage 120 cubic meters". Check if the chunking result retains this passage entirely within a single chunk, without splitting.
- Navigate to the system configuration page of FastGPT v4.17.0. Check if the set value of `PARSE_FILE_TIMEOUT_SECONDS` matches the actual time taken by the current parsing task.
