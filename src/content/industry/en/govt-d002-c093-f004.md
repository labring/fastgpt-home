# Government and Enterprise Informatization Service Inquiry and Reply: Workflow Orchestration

## What Data for This Category Looks Like

Four primary sources supply inquiry and reply data for government and enterprise informatization services (communications category): government and enterprise internal customer service ticket systems, official service guide document libraries, 12345 citizen hotline transfer records, and saved consultation data from offline self-service terminals in business halls. The data updates incrementally each day. The data includes two document types: structured consultation entries and unstructured service processes. Core fields cover consultation category, handling channel, completion time limit, and consultation subject type. Completion time limits use working days as the unit.

## Constraints Imposed on Workflow Orchestration

Because the data includes both structured ticket fields and unstructured service documents, workflow orchestration must support both structured field matching and semantic recall of unstructured content. Daily incremental updates require workflow configurations to include scheduled data source synchronization nodes to maintain real-time access to the consultation library. Differences in the consultation subject type field require configuring filtering rules for subject classifications in `variables` to prevent mismatched replies across subject types. Some data links to offline handling channels, so a channel verification node must be added to the workflow to ensure reply information aligns with offline resources.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset 3 sets of variables based on consultation subject type, with values `government and enterprise employees/general citizens/external merchants` | The data field includes consultation subject type, and variable filtering is required to match corresponding reply templates |
| `nodeId` | Configure unique identifiers for data source synchronization, semantic recall, and reply generation nodes separately | Facilitates workflow debugging and cross-node connection binding, avoids node confusion |
| Data source synchronization trigger timing | Daily 2:00-4:00 AM, based on actual measurement | Data is updated incrementally daily; synchronization during low-traffic hours avoids resource usage during peak business hours |
| Semantic recall count | Top 3-5 entries | Service inquiry content is concise; too many recall results will cause redundant replies |
| Context window | 800-1200 characters | Service process documents are of moderate length; a context window covering the complete handling logic is sufficient |
| Tool call retry count | 2 times | Occasional network fluctuations occur during tool calls; a small number of retries can improve success rates |

## Three Common Misconfigurations

- Symptom: Tool call node returns Invalid JSON: Bad control character error. Cause: No escape processing for line breaks and special symbols in consultation text, resulting in generated call parameters that do not comply with JSON format specifications.
- Symptom: Workflow components cannot be dragged or pasted to other workflows, and node connections cannot be added. Cause: Component reuse mode was not enabled in the workflow editing page, and the target workflow’s node ID format was not confirmed to match the current workflow’s.
- Symptom: Data source synchronization node fails to execute and does not update the day’s consultation data. Cause: Data source permission parameters in `variables` were not configured, resulting in inability to access the interface of the government and enterprise internal ticket system.

## How to Verify a Complete Configuration

- Manually trigger the data source synchronization node. Check the node log for the number of daily incremental data entries, and confirm this number matches the daily ticket count exported from the backend.
- Call the tool call node with test consultation text that includes special symbols. Verify that the returned JSON format complies with specifications.
- Copy a component from the current workflow and paste it into a new workflow. Confirm that the component configuration and connections load normally.
- Run the full workflow, input consultation questions for different subject types, and check that reply content matches the handling rules for the corresponding subject.
