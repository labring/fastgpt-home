# Government and Enterprise Informatization Service Matter Consultation and Response: Tool Calling and Plugins

## What the data for this category looks like
Data for government and enterprise informatization service matter consultation and response mainly comes from the national integrated government service platform, internal government and enterprise work systems, and official consultation databases of communication operators. Data updates are triggered synchronously with revisions of matter handling guidelines and policy adjustments. New user consultations are added to the database in real time each day.
Each single data entry includes fields such as matter name, handling conditions, required materials, handling procedures, common consultation questions, and standard reply templates. Field units correspond to matter attributes. For example, material count uses "copies" as its unit, and handling time limits use "workdays" as their unit.

## What constraints these characteristics impose on tool calling and plugin workflows
The multi-field structure of matter consultation data requires precise matching of corresponding fields during tool calling. Extracting irrelevant content may lead to response deviations.
The synchronous update of data alongside policy adjustments requires a scheduled pull mechanism in plugin configuration. This ensures called matter handling guidelines align with current policies.
Fields have dedicated units. Tool calling must retain this unit information. Omitting units may cause format errors in replies.
Consultation data is added to the database incrementally. Plugins must support incremental recall by category or keyword. This prevents resource consumption from full-scale data pulls.

| Tool calling timeout duration | `25–35 seconds` | Government and enterprise matter data has a standardized structure. This interval covers the time required for conventional data retrieval and format processing |

| Recall result limit | `Top 4` | Core information for matter consultation is concentrated in a small number of entries. Excessive results will interfere with users obtaining valid content |

## Three common misconfigurations
- Symptom: Calling the Mermaid drawing plugin returns an empty link or error 400. Cause: The plugin configuration does not correctly specify the drawing format and an accessible output path. This prevents the plugin from generating a publicly accessible image link.
- Symptom: The code running plugin prompts that a third-party library is not found during execution. Cause: Required dependency libraries are not pre-installed in the plugin's environment configuration. Importing only in code cannot automatically complete all dependencies.
- Symptom: The matter reply fields returned by tool calling lack unit information. Cause: The field retention switch is not enabled during configuration. This causes the tool to automatically strip unit attributes when extracting data, which does not comply with the format specifications of government and enterprise matter data.

## How to confirm configurations are correct
- Trigger a test call. Enter clear matter handling keywords. Check the tool call logs for matching correct plugin execution records.
- View the plugin return results. Confirm that complete fields of the matter and their corresponding units are included. Ensure no content is missing and no format errors exist.
- Simulate a policy update scenario. Trigger a plugin data pull. Confirm that the plugin can synchronize the latest matter handling guidelines normally.
- Test an abnormal scenario, such as temporarily disconnecting the network. Check if the plugin automatically retries according to the configured retry count. Confirm that the workflow does not interrupt directly.
