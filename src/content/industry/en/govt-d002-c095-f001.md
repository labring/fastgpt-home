# Administrative consultation and response for new energy development: HTTP interfaces and external systems

## What the data for this category looks like
The data for new energy development administrative consultation and response primarily comes from state-owned and enterprise new energy project filing systems, power grid dispatching management platforms, and local government service platform guide databases.
Data update rhythm: project filing information updates in real time, approval progress updates per working day, general service guides update once per quarter.
Data documents are divided into two parts: structured fields and unstructured text. Structured fields include project ID, applying entity, approval status, processing time limit. Their units are string, organization name, status enum, and working days respectively. Unstructured text consists of service requirements and material lists for each stage, with each text length ranging from 800 to 1500 characters.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources are distributed across multiple independent systems. Interfaces must connect to multiple external endpoints and adapt to differences in permission verification rules across systems.
Structured fields have strict format requirements. Perform format checks on project ID, approval status and other fields to avoid invalid requests.
Unstructured text varies widely in length. Adapt returned text to avoid exceeding context limits.
When used across teams, configure permission parameters separately. This ensures different teams’ call requests can only access authorized knowledge bases and data.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {team-specific API key}` | Matches cross-team knowledge base permission verification requirements, ensures only authorized requests can access data |
| `variables` | `{"project_scope": "new energy development", "query_type": "administrative consultation"}` | Limits the business scope of interface queries, filters return data from irrelevant businesses |
| `responseData` | Only return `approval_status, handle_deadline` fields | Reduces interface transmission volume, focuses on core query needs for administrative consultation |
| Timeout duration | 30 seconds | Adapts to typical response times of state-owned and enterprise external systems, avoids unnecessary retries |
| Retry count | 2 times | Addresses short-term system fluctuations, reduces the probability of single request failure |
| Cache duration | 4 hours | Matches the update rhythm of approval status, balances data timeliness and interface call frequency |

## Three common mistakes
- After calling the interface, an empty `responseData` field is returned, and no valid data related to administrative consultation is returned. The cause is that the business restriction parameter is not configured in `variables`, so the interface returns full non-target business data and fails to match the query intent.
- Calling the interface returns a 403 status code, and knowledge base data cannot be obtained. The cause is that the required `Authorization` parameter is not carried, and cross-team knowledge base permission verification fails.
- Retry fails after interface calling, and a timeout error is finally returned. The cause is that a reasonable timeout duration is not set, exceeding the response waiting threshold of state-owned and enterprise systems.

## How to confirm the configuration is complete
- Verify the `responseData` field returned by the interface, confirm that it only includes the preset core fields of approval status and processing time limit.
- Pass a test new energy project ID, check that the returned result matches the public service information from external systems.
- Simulate an abnormal request scenario, confirm that the permission verification mechanism works normally, and unauthorized requests cannot access data.
- Check the format of request parameters, confirm that they comply with the external system access specifications of FastGPT v4.17.0.
