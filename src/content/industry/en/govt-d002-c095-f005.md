# Service Consultation and Response for New Energy Development: Tool Calling and Plugins

## What this category of data looks like
Data for new energy development service consultation and response is primarily sourced from central state-owned enterprise energy project approval systems, local energy authority public policy repositories, and site survey ledgers.
Update frequency aligns with approval process nodes. Policy data is updated irregularly. Project progress data is synced weekly.
Documents are categorized by approval items, and include fields such as project ID, installed capacity, land scale, processing time limit, and required material list. Units include kilowatt, square meter, calendar day, and others.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
New energy development service consultation data includes precise project identifiers and quantitative metrics. Tool calling must strictly match fields such as project ID and installed capacity to avoid result deviations caused by fuzzy queries.
Policy data is updated irregularly. Tools must be configured with a regular pull mechanism to prevent returning outdated approval requirements and policy clauses.
Site survey ledgers contain geospatial information. Plugins must support format conversion for units such as longitude, latitude, and project land scale to ensure data alignment.
Approval progress data is synced weekly. Tool call cache duration must be controlled within a reasonable range. This ensures the timeliness of progress information, and avoids overloading the system with frequent requests.

## Three common configuration mistakes
- AxiosError 404 occurs when running plugins during local deployment: The console returns AxiosError 404 when calling plugins, and the response body shows that the requested resource was not found. The cause is that the plugin API address was not configured as the internal service address of the locally deployed FastGPT, and the default public test address is still used.
- Deep thinking tool does not appear in the chat interface: The deep thinking tool entry does not appear at the bottom of the chat interface. The cause is that the deep thinking plugin was not enabled in the tool management page, or it was not bound to the new energy service consultation scenario category.
- BI chart plugin returns sample data: The chart loads and displays sample content from api.example.com. The cause is that the default sample address in the plugin configuration panel was not modified to the enterprise's internal energy data API address.

## How to confirm successful configuration
- Initiate a consultation that includes a new energy project ID, and check whether the fields returned by the tool call include exclusive information such as project installed capacity and approval status.
- Trigger a plugin call, and check whether the requested API address in the log is the configured internal address, with no 404 errors.
- Test the deep thinking tool, confirm that the corresponding entry is displayed at the bottom of the chat interface, and the generated thinking process conforms to the logic of new energy service affairs.
- Adjust the context cache duration, verify that requests exceeding 7200 seconds will trigger data refresh.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
