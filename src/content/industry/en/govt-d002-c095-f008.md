# Administrative Consultation and Response for New Energy Development: Document Parsing and Chunking

## What data for this category looks like
Data for new energy development administrative consultation and response scenarios primarily comes from approval documents for state-owned enterprise new energy projects, grid connection application materials, industry technical standards, on-site survey reports, and policy notices.
Data update rhythm adjusts dynamically with project progress and policy releases. Project files are updated once per project. Policy notices are updated irregularly.
Document types include long-text feasibility study reports, structured approval forms, tabular grid connection parameters, and survey data.
Core fields include project number, installed capacity, grid connection voltage level, approval node, and others.
Units mostly use energy industry standard units such as megawatts (MW) and kilovolts (kV).
This guide is written based on FastGPT v4.17.0.

## Constraints imposed on document parsing and chunking
Long-text feasibility study reports have large per-file sizes, which can generate excessive chunks. Chunk scale must be controlled to avoid vectorization exceptions.
Structured approval forms and tabular grid connection parameters require retention of field and row-column associations. If chunking breaks data structure, subsequent retrieval will fail.
Irregularly updated policies and project files require parsing logic adapted to dynamic content, to ensure chunks cover the latest content.
Semantic boundaries vary significantly across different document types. Chunking rules must be flexibly adjusted to match the structural characteristics of different documents, to avoid semantic fragmentation caused by rigid character-based splitting.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Ensures semantic integrity for long texts such as new energy project feasibility study reports and grid connection applications, avoids vectorization exceptions caused by overloaded single chunk content |
| `chunkSplitter` | Split by chapter + character threshold | Adapts to the multi-chapter structural characteristics of new energy documents, retains semantic associations of sections such as project approval and technical parameters |
| `customPdfParse` | Enable table structured extraction | Adapts to tabular documents such as grid connection parameters and survey data, retains cell fields and row-column associations |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets upload requirements for single large feasibility study reports or batch project files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses time consumption of long document parsing, avoids timeout interruptions |
| `chunkSettingMode` | Semi-automatic mode | Allows adjustment of chunking parameters for different types of new energy documents, balances generality and accuracy |

## Three common configuration mistakes
- Symptom: After uploading a new energy feasibility study report larger than 10 MB, more than 1000 chunks are generated, some chunks fail vectorization, and the interface displays a "vectorization exception" prompt. Cause: The `chunkSize` parameter is not adjusted. The default chunk size is too small, leading to an excessive number of chunks, and some short semantic chunks have insufficient vector features.
- Symptom: After importing grid connection parameters in enterprise online spreadsheet format, the parsed chunks lose row-column associations, and field content is disorganized. Cause: The table structured extraction function of `customPdfParse` is not enabled. The default parsing splits table content as plain text.
- Symptom: After batch uploading project approval forms, the parsing status of some documents shows timeout, and valid chunks cannot be generated. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient to complete the long document parsing process.

## How to confirm configurations are properly set
- Upload a typical new energy feasibility study report, check the number of generated chunks to confirm the expected chunk scale is met.
- Import a grid connection parameter spreadsheet, verify that the parsed chunks retain the association between fields such as project number and installed capacity.
- Upload a long document with more than 500 pages, check whether the parsing process times out, to confirm the timeout parameter setting is reasonable.
- Trigger a vectorization task, check for any exception prompts, to confirm the chunking parameters meet vector generation requirements.
