# Service Consultation and Reply for New Energy Development: Deployment and Upgrade

## What This Category of Data Looks Like
Service consultation and reply data for new energy development comes primarily from approval documents for state-owned and enterprise new energy projects, grid connection application materials, site survey records, and policy interpretation documents. Update cycles for this data align with project approval milestones or policy adjustments. Individual document lengths vary widely. The data includes structured fields such as project number, construction capacity, approval time limit, and applying unit. It also includes unstructured content such as site photos and technical parameter descriptions. Field units use professional measurement standards including megawatts, hectares, and workdays.

## What Constraints These Characteristics Impose During Deployment and Upgrade
New energy development service consultation data combines structured and unstructured content. Individual documents have large file sizes and many professional fields. During deployment, configure database settings to support large file parsing and multi-field indexing. Data update frequency fluctuates with project progress. During upgrade, implement incremental synchronization logic to avoid excessive resource usage from full synchronization. The special nature of professional terminology and measurement standards requires reserving expansion space for parsing models during deployment, to ensure accurate extraction of service consultation content. Additionally, address permission control requirements in state-owned and enterprise scenarios by configuring fine-grained access control parameters during deployment, to ensure compliant security of sensitive project data.

## Three Common Misconfigurations
- Issue: After enabling the enhanced PDF parsing feature, the locally deployed MinerU interface cannot be called, returning a connection timeout error. Cause: The local access address and port of MinerU are not specified in the FastGPT configuration, causing parsing requests to fail to route to the deployed MinerU container.
- Issue: In FastGPT v4.17.0, configured models do not appear in the workflow editor dropdown list. Cause: Administrator permission verification via `ROOT_KEY` is not completed, so the model configuration module permission is not opened, and the workflow cannot load configured models.
- Issue: Professional fields such as project capacity and approval time limit are missing after imported service documents are parsed. Cause: The structured parsing switch is not enabled, so unstructured documents cannot automatically extract professional measurement fields, affecting accurate replies to service consultations.

## How to Verify Successful Configuration
- Run a curl request to verify MinerU interface connectivity, confirm that normal PDF parsing results are returned.
- Log in to the FastGPT backend to view the knowledge base parsing logs, confirm that large new energy project documents can be parsed normally and generate structured fields.
- Check the model dropdown list in the workflow editor, confirm that configured models are displayed normally.
- Access the frontend address corresponding to `FE_DOMAIN`, verify that the system can normally load the service consultation configuration page and knowledge base module.
