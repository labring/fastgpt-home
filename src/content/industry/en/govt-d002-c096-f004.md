# Service Inquiry and Response for Non-Ferrous Metal Smelting: Workflow Orchestration
Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
The business data for non-ferrous metal smelting mainly comes from on-site production PLC collection systems, daily quality inspection ledgers, smelting work orders, and finished product warehouse inventory reports. Data update schedules fall into two categories: real-time (for process parameters such as furnace temperature and pressure) and scheduled (for daily output and quality inspection results). Each document includes fields such as smelting furnace number, shift output, impurity content, and process parameters. Output is measured in tons, impurity content in ppm, and process parameters use units of degrees Celsius and megapascals. Some inquiry documents are user-submitted process problem descriptions of up to 100,000 Chinese characters, or production data tables with up to 15,000 rows.

## What these characteristics impose on workflow orchestration
The high-frequency updates of real-time process data require workflows to support low-latency data pulling to avoid timeouts. Single documents of up to 100,000 Chinese characters or Excel data with 15,000 rows require workflows to configure reasonable splitting and batch processing rules to avoid overload from single-run processing. Business data with multiple fields and multiple units requires workflows to have built-in unified format verification logic to ensure the accuracy of parameter matching. Scheduled production reports require workflows to bind fixed time nodes to trigger tasks, while supporting alert triggers for abnormal data. The wide variation in length of user-submitted inquiry texts requires workflows to support dynamic adjustment of the context window to adapt to input content of different lengths.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the splitting needs of 100,000-character Chinese documents, avoiding processing timeouts caused by overly long single chunks |
| Overlap Length | 50–100 characters | Ensures context continuity between split text chunks, avoiding breakage of key information |
| Single-Processing Rows | 1000–2000 rows | Adapts to batch processing of 15,000-row Excel data, avoiding memory overflow from single-run loading |
| Timeout Threshold | 600 seconds | Matches the maximum wait time for real-time process data pulling, preventing task failure due to network fluctuations |
| `variables` | Bind business fields such as smelting furnace number and output unit | Unifies data formatting and parameter invocation logic within workflows |
| `nodeId` | Assign unique identifiers based on data source nodes | Differentiates processing paths for real-time process data and report data |

## Three Common Mistakes
- Phenomenon: The database connection in the workflow shows "connect ETIMEDOUT", and local access works normally. Cause: The intranet address of the smelting business database was not configured in the workflow variables, causing the container environment to fail to access local network resources.
- Phenomenon: Task execution lag occurs after nested loop bodies. Cause: The maximum number of loop iterations was not limited. Multi-layer loops targeting 15,000-row Excel data lead to excessive resource occupancy.
- Phenomenon: No results are returned after processing long documents. Cause: The chunk length parameter was not configured, causing single chunks of text to exceed the system's processing limit and leading to direct task termination.

## How to Confirm Proper Configuration
- Upload a 15,000-row Excel production data file, and check whether the workflow automatically performs batch processing and generates corresponding node logs.
- After configuring the timeout threshold, simulate a network delay scenario to verify whether the workflow triggers a timeout alert within the set duration.
- After binding `variables` business fields, submit a smelting furnace number query request, and confirm whether the workflow correctly invokes the corresponding parameters.
- After configuring chunk and overlap lengths, upload a 100,000-character Chinese document, and check whether the number of split text chunks matches expectations.

The values provided are common starting points and should be measured against the reader's own samples.
