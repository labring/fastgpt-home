# Matter consultation and reply for nuclear power operations: HTTP interfaces and external systems

## What this category of data looks like
Reference only; verify against the target FastGPT release and deployment documentation.

Consultation numbers use a format of fixed prefix plus serial number. Associated equipment ID must match the coding rules for nuclear power unit equipment. Reply content must comply with standardized expressions related to nuclear safety, typically ranging from 500 to 2000 characters, and must not include unredacted sensitive information.

## What constraints these characteristics impose on the "HTTP interfaces and external systems" link
Fixed coding rules for nuclear power operation consultation data require HTTP interface input parameters to verify the format of associated equipment ID. Requests that do not meet the unit coding rules must be blocked directly to avoid invalid queries.

The real-time update feature requires interface timeout settings to adapt to on-site operation response rhythms. Do not set the timeout too short, as this may truncate incomplete consultations.

Data fields include nuclear safety-related compliance content. Interface returned reply content must retain original standardized expressions, and field structures must not be modified arbitrarily. Sensitive information must also be desensitized.

In addition, consultation number serves as the unique identifier. The interface must support precise query by this number to ensure unique data matching and avoid confusion of consultation data across units.

## How to configure it
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `Authorization` | `Bearer {API key assigned by nuclear power operation system}` | Bearer token authentication is commonly used for external interfaces of nuclear power operation systems to ensure request legitimacy and security |
| `variables` | `Key-value pairs containing associated equipment ID and consultation number` | Matter consultation requires precise data matching by equipment and consultation number; variables can dynamically substitute query conditions |
| `responseData` | `Only retain fields of reply content, completion time, and associated equipment ID` | Filter non-essential fields to reduce data transmission overhead, which meets the lightweight data transmission requirements of nuclear power data |
| Request timeout | `30–60 seconds` | Interface response of nuclear power operation systems is usually affected by equipment data loading; this interval covers most normal request durations |
| Retry times | `1 time` | Avoid excessive interface pressure on nuclear power systems caused by repeated requests, while covering temporary network fluctuation scenarios |

## Three common mistakes
- Phenomenon: HTTP request returns empty results with no matching matter consultation data. Cause: Necessary parameters such as associated equipment ID and consultation number are not passed to the interface via `variables`, resulting in missing query conditions and failure to hit target data.
- Phenomenon: FastGPT reports an error when calling the interface, but Postman can normally call and obtain results. Cause: The format of the `Authorization` parameter is configured incorrectly, such as not adding the Bearer prefix or using an invalid API key.
- Phenomenon: The reply content returned by the interface contains unredacted sensitive information. Cause: Sensitive fields are not filtered in the `responseData` configuration, resulting in direct return of confidential or internal data within the nuclear power system.

## How to confirm the configuration is complete
- Manually fill in test associated equipment ID and consultation number, initiate a request through FastGPT's debug panel, and verify that returned fields match expected values.
- View the interface call log to confirm that the `Authorization` parameter is correctly carried with no format errors.
- Simulate a temporary network interruption scenario to verify whether the interface processes requests according to the configured retry rules.
- Check whether the returned reply content complies with the standardized expressions of nuclear power operations, with no redundant or sensitive fields.
