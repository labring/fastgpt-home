# Handling Consultation and Response for Nuclear Power Operations: Workflow Orchestration

## What This Type of Data Looks Like
Data for nuclear power operation consultation and response comes primarily from internal operation work order systems, on-site inspection archive libraries, and government service window consultation ledgers. Data update rhythms are split into real-time and batch: real-time data refers to user-submitted consultation requests, while batch data refers to monthly archived closed cases.

Document structure includes the following fields: consultation unique identifier, submission time, consultation subject (operation team, maintenance team, etc.), problem classification (equipment operation, compliance process, emergency response, etc.), response content, and closed status. Field units are string, ISO time format, enumerated text, minute-level response duration, rich text, and boolean value.

## What Constraints Do These Characteristics Impose on Workflow Orchestration?
The multi-source and heterogeneous characteristics of nuclear power operation consultation data require workflows to configure multi-system connection parameters via `variables` to automatically pull work orders and inspection records. The enumerated problem classification field requires workflow branch nodes to preset fixed routing rules to avoid exceptions triggered by non-standard inputs. Real-time submitted consultation requests must match compliance response timelines, requiring workflows to configure timeout interception mechanisms to prevent execution duration from exceeding nuclear power operation compliance requirements. The multi-format, large-volume characteristics of file attachments require workflows to support chunked upload and variable parameter passing to adapt to upload needs of nuclear power operation drawings and inspection logs. Form field mandatory constraints require configuring pre-check rules during workflow orchestration to ensure mandatory items are completed before proceeding to subsequent links.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Form Pre-check | Configure to trigger workflow only after mandatory field validation passes | Aligns with standardized nuclear power consultation process requirements, prevents incompletely submitted requests from entering workflows |
| Multi-data Source Connection | Configure connection addresses and permission parameters for work order systems and inspection libraries via `variables` | Adapts to multi-source data pulling needs, enables automatic synchronization of consultation data |
| Workflow Timeout Settings | Set to under 1200 seconds, trigger automatic termination and alerting when exceeded | Meets compliance response timeline requirements for nuclear power operations, avoids resource occupation from long-running executions |
| File Upload Configuration | Support maximum single file size of 1000 MB, allow passing to workflow nodes as variables | Adapts to large-volume upload needs of nuclear power operation drawings and log files, supports variable parameter passing scenarios |
| Branch Routing Configuration | Preset 5 fixed routing nodes based on problem classification | Matches the enumerated problem classification field characteristics, enables standardized process branching |
| Node ID Binding | Bind `nodeId` as the unique identifier for core approval nodes | Ensures accurate tracking and write-back of workflow execution status |

## Three Common Misconfigurations
- Symptom: Workflow execution duration exceeds 1200 seconds, triggering system termination alert. Cause: No timeout interception rule is configured, or the timeout threshold is set beyond nuclear power operation compliance timelines.
- Symptom: Uploaded operation drawings or logs cannot be passed to workflow nodes as variables, and file fields in nodes are empty. Cause: File variable parameter passing configuration is not enabled, or the uploaded file size exceeds the preset limit.
- Symptom: Workflows are submitted without completing form mandatory field entries, generating consultation requests with incomplete information. Cause: No form pre-check rule is configured, or the check logic is not bound to mandatory fields.

## How to Verify Correct Configuration
- A test consultation request is submitted. Confirm that the workflow cannot be triggered when form mandatory fields are left unfilled, verifying the pre-check configuration is active.
- A test file matching nuclear power operation format is uploaded. Confirm that the file can be passed as a variable to the specified workflow node, verifying the parameter passing configuration is correct.
- A large-scale data pulling scenario is simulated. Confirm that workflow execution duration meets preset thresholds, verifying the timeout interception rules are active.
- Consultation requests of different classifications are submitted. Confirm that workflows enter corresponding nodes per preset routing, verifying the branch configuration is correct.
