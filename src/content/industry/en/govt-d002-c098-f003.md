# Airport Service Inquiries and Responses: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data sources for airport service inquiries include official airport inquiry systems, terminal operation announcements, and public civil aviation administration guidelines.
Data updates follow two modes: fixed cycle and temporary adjustments. Full updates of core rules are conducted twice annually during spring and autumn flight season changes. Real-time synchronization is triggered for temporary adjustments such as flight delays or new route launches.
Documents use scenario-based question-answer pairs as their core structure. Fields include original question, standard answer, applicable terminal range, and effective date. Effective dates use the YYYY-MM-DD format. Monetary values use Chinese Yuan as the unit.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The scenario-based structure of data sources requires multi-turn dialogue to first clarify the user's travel scenario. Examples include domestic or international flights, and the current terminal. This prevents returning invalid answers across scenarios.
The combined fixed and real-time update rhythm requires the dialogue system to synchronize the knowledge base regularly. This ensures temporary adjustment content takes effect promptly.
Multi-turn conversation context must retain key user-provided information, such as flight numbers and travel dates. This reduces repeated inquiries. The system must also filter expired rule content to avoid returning invalid responses.

## Configuration Settings
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to a unique identifier for user sessions, set validity period to 3600 seconds | Maintain context consistency across multi-turn dialogue, prevent content mixing between different sessions |
| `messages` | Retain the first 10 rounds of conversation content | Conversation context for aviation inquiry scenarios focuses on content related to a single trip. Excessive rounds introduce redundant information |
| `variables` | Pass current terminal, user's queried flight date, and travel type | Match precise responses for specific scenarios, adapt to differentiated rules across different terminals |
| Maximum context length | 8000–12000 token | Cover complete inquiry context, avoid truncation of critical flight information |
| Question Optimization | Enable automatic context completion | Automatically supplement context to generate complete questions when the user omits previously mentioned information such as flight numbers |
| Single search limit | Top 3 matching results | Standard responses for aviation inquiries are usually single and precise. Excessive results will interfere with user judgment |

## Three Common Misconfigurations
- A call to the dialogue interface returns the `unAuthChat` error. This occurs when `chatId` is not correctly bound, or the API key has not been configured with access permissions for the dialogue interface.
- Dialogue response content contains line breaks, causing JSON request parsing failure. This happens when the standard answer is not properly escaped, and line breaks are not replaced with `\n`.
- An error occurs when uploading aviation-related inquiry documents, while text dialogue functions operate normally. This is caused by encrypted formatting in the uploaded PDF or document, or the file size exceeding system limits.

## How to Verify Successful Configuration
- Initiate an inquiry with multi-turn context. First ask for the flight number and departure terminal, then ask about baggage transfer rules. Confirm the system can associate previously mentioned information to generate a corresponding response.
- Pass a valid `chatId` and API key when calling the dialogue interface. Verify that the returned result has no unauthorized error, and the content complies with standard airport service rules.
- Upload a PDF document containing airport terminal guidelines. Confirm the system can parse the document normally and match corresponding inquiry content.
- Initiate multiple consecutive inquiries. Confirm response latency meets expected standards, with no obvious delays.
- Check dialogue response content. Confirm line breaks have been properly escaped, and will not cause JSON request format errors.
