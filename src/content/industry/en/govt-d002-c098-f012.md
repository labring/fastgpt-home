# Civil Aviation Airport Service Consultation and Response: Deployment and Upgrade

## What the data for this category looks like
The data for civil aviation airport service consultation primarily originates from the airport’s official operation system, airline collaborative knowledge base, and on-site service ledger. Data is split into two categories: real-time dynamic and fixed rule. Real-time dynamic data includes flight takeoffs and landings, gate changes, delay warnings, and similar items, updated minute-by-minute. Fixed rule data covers baggage allowance, security inspection standards, special passenger service workflows, and similar items, updated quarterly or per temporary policies. The document structure is divided by travel scenarios, with fields including scenario classification, content title, detailed description, and effective scope. Units use standard travel-related measurements such as minutes, kilograms, and passenger trips.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
The minute-by-minute update requirement for real-time dynamic data requires deploying a stable data source connection link. This prevents delayed consultation content caused by interface timeouts. The quarterly update rhythm for fixed rule data requires retaining a rollback mechanism for old rule caches during upgrades. This prevents service interruptions after new rules go live. The multi-scenario document structure requires creating independent vector database partitions by travel scenario during deployment. This avoids cross-scenario retrieval confusion. Airport-specific professional terminology and measurement fields require configuring word segmentation rules tailored to the civil aviation field. This ensures accurate retrieval matching.

## Configuration Recommendations
These settings apply to FastGPT v4.17.0, and are adapted for deployment needs in civil aviation airport service consultation scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Avoid exceeding the maximum allowed connections for the airport operation database when connecting, ensuring stable data reading |
| `REDIS_URL` | `redis://:airport cache password@cache service address:6379/1` | Cache high-frequency updated data such as real-time flight dynamics and gate changes to shorten consultation response times |
| `STORAGE_S3_ENDPOINT` | `S3 endpoint matching the deployment region` | Store attachment files for the airport knowledge base, such as terminal layout diagrams and special passenger service guide PDFs |
| `FE_DOMAIN` | `Airport official service subdomain` | Match the front-end access path to ensure users access the consultation service via the official domain |
| `FILE_TOKEN_KEY` | `Random 32-character sequence` | Generate secure tokens for file downloads to prevent unauthorized access to knowledge base attachments |

## Three Common Misconfigurations
- Symptom: When calling the AntV Chart-related MCP plugin, only raw XML or JSON code blocks are returned, with no rendered chart. Cause: The MCP plugin’s rendering context parameters were not configured, so the plugin only returns raw data code without triggering front-end rendering logic.
- Symptom: Errors of the type `Error response from daemon: error from registr` appear during upgrade. Cause: No architecture tag was specified when pulling the image, or the image repository does not offer image packages for the matching architecture, leading to a mismatch between the deployment node and the image architecture.
- Symptom: After upgrading to the specified version, the version number displayed on the front-end page does not match the actual deployed version. Cause: Front-end static resources were not fully cleared from cache, so the browser loads the old version identifier file.

## How to Confirm Successful Configuration
- Connect to the airport data source interface, send a real-time flight query request, and verify that the update time of the returned data matches actual flight dynamics.
- Upload a PDF attachment from the airport knowledge base, and confirm that token generation and access permission control work normally via the file download link.
- Check the database connection pool monitoring to confirm that the current number of connections does not exceed the limit set by the `DB_MAX_LINK` configuration.
- Access the front-end domain name, and verify that the knowledge base content loaded by the page matches the airport service rules configured in the backend.
