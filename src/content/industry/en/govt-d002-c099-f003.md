# Matter Consultation and Reply for Oil and Gas Exploration and Development: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Matter consultation data for oil and gas exploration and development is primarily sourced from drilling logs of exploration and development projects, trial production analysis reports, reservoir evaluation documents, administrative work process guidelines, and approval archive files. Data updates dynamically as projects progress, with content synchronized following new well commissioning and regional exploration result releases. Documents are categorized by project number and exploration block, and include fields such as well number, exploration block, processing node, approval time limit, core parameters including porosity and permeability. Some documents also include format specifications and filling requirements.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words workflow
The professional parameters and project-bound traits of oil and gas exploration and development require multi-turn dialogue to bind the context of the corresponding exploration project using `chatId`, to prevent confusion between consultation data from different blocks and well numbers. Documents include professional fields and fixed formats, so prompt words must clearly specify parameter units and legal value ranges to avoid responses that do not meet industry specifications. Data updates dynamically as projects progress, so dialogue context must restrict valid rounds to prevent loading outdated document content. Matter consultation involves approval process nodes, so prompt words must differentiate between process consultation and parameter query scenarios, matching the corresponding data call logic.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` binding rule | Bind the unique identifier of the current exploration project, such as well number + block number | Ensure multi-turn dialogue only calls documents for the corresponding project, avoiding cross-project data confusion |
| `messages` context retention rounds | Retain the previous 3–5 rounds of dialogue content | Balance context completeness and response speed, adapting to the professional complexity of oil and gas exploration data |
| `variables` parameter injection | Inject the well number, exploration block, and work node number for the current consultation | Allow prompt words to accurately match document content for the corresponding business scenario |
| Prompt word template length | 800–1200 characters | Cover industry terminology specifications, work process requirements, and data call rules, avoiding information overload |
| Dialogue timeout threshold | 600 seconds | Adapt to the time required for professional document retrieval and parameter verification, preventing mid-interruption |
| Context splicing method | Splice in reverse chronological order of dialogue time | Prioritize the latest consultation content, ensuring responses align with current user needs |

## Three Common Misconfigurations
- Form input fields in the workflow fail to display in the dialogue interface, and corresponding fields are not injected into the dialogue context via `variables`. This occurs when parameters such as well numbers and blocks collected by the form are not bound to the variable parameters of the dialogue, preventing the dialogue module from reading the input content.
- Responses returned by the dialogue module fall outside valid industry parameter ranges, and prompt words do not clearly specify the legal values and units of fields. This occurs when the prompt word template does not include standard specifications for oil and gas exploration professional parameters, leading the AI to generate content that does not meet industry standards.
- Multi-turn dialogue experiences context confusion, and `chatId` is not bound to the unique identifier of the corresponding project. This occurs when dialogues for different exploration projects share the same session identifier, resulting in cross-project data calls.

## How to Verify Proper Configuration
- Launch a consultation for the corresponding exploration project, check whether preset form input fields display in the dialogue interface, confirm that `variables` parameters have been correctly injected, and use the FastGPT v4.17.0 dialogue module to normally load bound variables.
- Launch more than 3 consecutive relevant consultations, check whether the dialogue context retains professional terminology and process information for the corresponding project, confirm that `chatId` binding is valid and no cross-project data confusion occurs.
- Submit a professional parameter query, check whether the response matches the fields and units in the document, confirm that the prompt word template has loaded industry specification content.
- Simulate a timeout scenario, check whether the dialogue completes response within the set threshold, confirm that the timeout configuration has taken effect.
