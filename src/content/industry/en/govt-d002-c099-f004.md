# Workflow Orchestration for Oil and Gas Exploration and Development: Service Inquiry and Reply

## What This Category of Data Looks Like
Business data sources for oil and gas exploration and development include internal oilfield exploration and development databases, real-time on-site monitoring equipment, and geological exploration reports.
Update frequencies fall into three categories:
- Real-time drilling parameters are updated every second
- Daily drilling reports are updated daily
- Block exploration achievement reports are delivered per project phase
Each document contains fields such as a unique well ID, collection time, physical parameter values, and operation phase tags. Physical parameters include drilling depth measured in meters, and permeability measured in millidarcys.
Document length varies widely. Short documents include shift operation records of hundreds of characters, while long documents include seismic exploration analysis reports of tens of thousands of characters.

## Constraints on Workflow Orchestration
These data characteristics create constraints for workflow orchestration:
1.  High-frequency real-time monitoring data requires reasonable pull intervals for workflow data source nodes. This avoids excessive system resource usage.
2.  Multi-field physical parameters need format validation in workflow pre-nodes. This prevents invalid values from entering subsequent processes.
3.  The presence of long documents requires chunking nodes to adapt to longer content lengths. This avoids truncating critical geological descriptions.
4.  Tags for different operation phases must be used as retrieval filter conditions. Workflows must bind corresponding tag parameters.
5.  Decentralized data sources require aggregation nodes at the start of workflows. Unify data formats before entering retrieval or analysis links.

## Configuration Rules
Configuration rules for FastGPT v4.17.0 are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the long paragraph characteristics of oil and gas exploration and development documents, avoiding truncation of critical geological descriptions |
| Single Search Limit | Top 10 entries | Matches the conventional number of associated parameters for single-well exploration, covering core retrieval needs |
| Maximum Context | 6000 characters | Accommodates spliced content from multiple daily drilling reports and logging data, meeting associated analysis requirements |
| Timeout Threshold | 300 seconds | Adapts to the computational time required for geological data retrieval, preventing process interruptions due to large data volumes |
| `variables` | Calibrated via actual testing | Used to store dynamic parameters such as well IDs and operation phases, adapting to calls for different exploration scenarios |
| `nodeId` | Bound to the corresponding data source node | Ensures accurate data transfer between workflow nodes, avoiding parameter confusion across nodes |

## Three Common Mistakes
- Code running component errors with no specific code syntax prompts. Phenomenon: The component displays "Execution timed out" or "Parameter format error", with no code syntax error logs. Cause: The component is not adapted to the long parameter format of oil and gas exploration data. This causes component input content to exceed preset length limits.
- Knowledge base retrieval cannot filter results by tag. Phenomenon: Retrieval results include documents that do not match the operation phase tags. Cause: Operation phase tags are not passed as `variables` to the retrieval module, or the tag filter switch is not enabled.
- Workflow does not complete all nodes, with no error prompts. Phenomenon: Process status remains stuck at a certain node, with no failure logs. Cause: The data source node update interval is set too long, failing to trigger subsequent node execution conditions. Or the `nodeId` binding is incorrect, causing data transfer interruptions.

## How to Confirm Correct Configuration
- Manually pass test well ID and operation phase parameters. Check whether `variables` are correctly passed to subsequent nodes.
- Trigger the workflow and view retrieval results. Confirm that only documents matching the specified tags are returned.
- Import an ultra-long exploration report. Check that chunked content is not truncated.
- Simulate a large-volume retrieval scenario. Confirm that the workflow completes execution within 300 seconds or triggers a timeout prompt.

The values provided are common starting points and should be evaluated against the reader's own samples.
