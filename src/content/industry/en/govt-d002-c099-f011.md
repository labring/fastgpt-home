# Forms and Interactions for Oil and Gas Exploration and Development: Service Inquiries and Responses

## What the data for this category looks like
Service inquiry data for oil and gas exploration and development comes primarily from structured and semi-structured documents including exploration project reports, drilling logs, well test records, reserve assessment documents, and similar materials. Data update frequency changes with project phases. Bulk updates are triggered at milestones such as new well completion and reserve review.
Document structures include multi-column structured tables (such as drilling parameter tables) and long-text reports. Core fields include well ID, drilling depth, formation pressure, fluid density, and other fields, with supporting professional units such as meters, megapascals, grams per cubic centimeter.

## What constraints these characteristics impose on the forms and interactions link
Multi-column structured table data requires form components to accurately match each column's field name. This prevents automatic segmentation from disrupting data association relationships.
Professional unit fields require clear unit prompts during interactions to prevent input errors.
Non-fixed update frequencies require forms to support on-demand upload of the latest project files.
Complex exploration data structures require form inputs to limit valid field ranges, reducing invalid input.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunking Mode | Split by row | Adapts to multi-column Excel where each row corresponds to complete data for a single measurement point or single well |
| Input Field Mapping | Match document column names | Ensure parameters received by the form fully correspond to exploration data fields |
| Unit Prompt Toggle | Enabled | Prevent professional unit input errors, such as confusing megapascals and kilopascals for pressure values |
| Single Upload File Size | 1000 MB | Adapts to large exploration reports and log files |
| `formInput` Component Configuration | Bind data fields | Enable linkage between form inputs and the knowledge base |
| `userSelect` Component Configuration | Preset the top 10 common exploration project types | Reduce non-professional input interference and simplify interaction workflows |

## Three common mistakes
- Automatic segmentation causes mixed-up data fields. Knowledge base recall results do not match the original Excel columns. The cause is failure to set chunking mode to split by row.
- No user interaction prompt follows API calls. No form or selection popup appears after the interface is called. The cause is failure to bind trigger logic for the `userSelect` or `formInput` component in the workflow.
- Form variables fail to pass correctly. Workflow variables are empty after submission. The cause is failure to correctly map form fields to preset workflow variables.

## How to confirm the configuration is set correctly
- Upload a test multi-column Excel file, check if automatic chunking is performed by row.
- Call the configured API interface, verify that the corresponding form or selection popup appears.
- Fill in the form fields and submit, check if the mapped field data is correctly received in the workflow.
- Upload a test file larger than 1000 MB, verify that the upload limit prompt is triggered.

The values provided here are common starting points and should be measured against the reader's own samples.
