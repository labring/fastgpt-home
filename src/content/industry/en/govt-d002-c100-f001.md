# Oilfield Engineering Service Consultation and Reply: HTTP Interfaces and External Systems
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Oilfield engineering service consultation and reply data comes from four main sources: field work orders, client demand letters, on-site inspection records, and compliance management documents. Data updates run per single job project. Batch updates occur either after a single job finishes, or every 7 days.

Each single document includes six core fields: work area, construction content, problem description, reply opinion, rectification requirements, and work cycle. Work area uses square kilometers as its unit. Rectification requirements use workdays. Work cycle uses calendar days.

Single document volume varies greatly. Small inspection records are only hundreds of characters. Large construction plans can reach thousands of characters.

## What constraints these characteristics impose on HTTP interfaces and external systems
Scattered data sources require connecting to HTTP endpoints from multiple internal systems. Interfaces must support multi-source data aggregation.

Batch updates require interfaces to support incremental pull mode. This avoids full pull operations consuming excessive system resources.

Unique field units and structures require interface requests to carry precise field mapping rules. This prevents unit conversion errors or missing fields.

Oilfield engineering service compliance requirements mean interface authentication must meet state-owned enterprise system security standards. This prevents unauthorized access and data leaks.

Large variation in single data volume requires interfaces to support dynamic adjustment of maximum data per request. This adapts to different scale document requests.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {API key for oilfield engineering service system}` | Meets state-owned enterprise system authentication requirements, ensuring interface access security |
| `variables` | `{"workArea": "specified work area", "updateCycle": "7 days"}` | Matches oilfield engineering service work area division and batch update rules, accurately locating target consultation data |
| Maximum data per single request | `1000 MB` | Adapts to the size variation of single documents in oilfield engineering services, preventing request failure due to excessive data volume |
| Request timeout | `600 seconds` | Matches the processing duration of large construction plans, preventing premature request disconnection |
| Field mapping rules | Calibrated based on actual testing | Matches unique oilfield engineering service fields such as work area and rectification requirements, preventing data misalignment |
| `responseData` | `Only return fields containing problem replies and rectification requirements` | Filters irrelevant data, improving the accuracy and readability of service consultation replies |

## Three common mistakes
- Empty interface response: A request is sent but no valid data is obtained. The cause is that the work area parameter is not configured in `variables`, so the interface cannot match consultation data for the corresponding job.
- Unable to add HTTP interface input parameters: Specified fields cannot be entered in the configuration interface. The cause is that `variables` are not configured according to oilfield engineering service field specifications, and required fields such as job number are omitted.
- Request timeout: The interface returns a 504 status code. The cause is that the request timeout setting is too short, and does not match the processing duration of large job orders.

## How to confirm correct configuration
- Send a test request, check if `responseData` contains unique oilfield engineering service fields such as work area, problem description, and reply opinion.
- Verify that the interface returns a 200 status code, with no 401 authentication error or 400 parameter error.
- Compare locally stored oilfield engineering work order data, confirm that the content returned in `responseData` matches the actual data.
- Simulate batch requests, check if the interface can normally process data volumes within 1000 MB, with no abnormal disconnections.
