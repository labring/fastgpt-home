# Service Consultation and Response for Oilfield Engineering Services: Workflow Orchestration

This document is written based on FastGPT v4.17.0.

## What the data for this category looks like
Oilfield engineering service data mainly comes from four categories: on-site operation records, engineering construction documents, equipment operation and maintenance logs, and approval process documents. Data update rhythm is adjusted according to operation progress. Approval documents are submitted before operation starts, construction progress and safety records are updated in real time during operation, and complete materials are archived after operation is completed. The document structure includes fields such as operation number, construction location, equipment model, process steps, safety specifications, and approval status. Units include general engineering field units such as meters, cubic meters, hours, and sets of equipment.

## What constraints these characteristics impose on the "workflow orchestration" link
Dispersed data sources and flexible update rhythms require workflows to support multi-source data pulling and scheduled synchronization nodes. Fields include exclusive identifiers for engineering operations, requiring workflow nodes to bind context via unique identifiers to avoid mixing data from different operations. The volume difference between document and log data is large, and some construction record documents are lengthy, requiring workflows to configure reasonable timeout and data splitting rules. Original documents need to be associated with the original files before slicing, requiring workflow configuration nodes to bind file paths and operation identifiers to ensure traceability of original materials during consultation.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled trigger interval | Every 30 minutes | Matches the real-time data update rhythm of oilfield engineering services, ensuring the timeliness of consultation content |
| Context binding `nodeId` | Bind the operation number field | Ensures each workflow instance corresponds to a unique engineering operation, avoiding cross-operation data mixing |
| Tool call timeout | 600 seconds | Addresses scenarios with large volumes of engineering document data, preventing node execution interruptions |
| Number of documents returned per request | Top 5 entries | Controls returned data volume to avoid overloading workflow nodes |
| Original document association configuration | Match the original file path before slicing | Enables online preview of the original file corresponding to the referenced fragment, aligning with business requirements |
| `variables` passing rule | Carry core operation fields | Ensures synchronization of operation data across nodes and maintains context consistency |

## Three common mistakes
- Generated share links include `http://localhost:3000/chat/`. This occurs because the deployment domain name is not configured, and the default address of the local development environment is used directly.
- Tool call nodes remain in the executing state with no return after execution. This occurs because a reasonable timeout period is not set, failing to adapt to the loading duration of oilfield engineering documents.
- Clicking a referenced fragment fails to jump to the original document before slicing. This occurs because the operation number field is not bound to associate the original file path, and only the knowledge base sliced fragments are displayed.

## How to confirm the configuration is complete
- Trigger the workflow to generate a share link, check that the link uses the officially deployed domain name and does not include the localhost field.
- Execute the tool call node, observe that the return is completed within 600 seconds with no timeout error.
- Generate consultation results and click a referenced fragment, confirm that the jump leads to the original document page before slicing.
- View the `variables` parameters passed across nodes, confirm that core fields such as operation number and construction location are included.
