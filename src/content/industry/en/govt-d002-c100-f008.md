# Oilfield Engineering Services Consultation and Reply: Document Parsing and Chunking
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Oilfield engineering services consultation and reply data mainly comes from construction plans, well survey reports, equipment operation logs, and administrative approval documents. The update rhythm proceeds irregularly per project cycles. Document types are mainly long-text PDFs and structured Excel files, containing fields such as well number, operation date, construction pressure, and consumable usage. Units include professional engineering units such as MPa, m³, and hours. Some documents contain charts and formulas.

## What constraints do these characteristics impose on the document parsing and chunking link
Long-text PDF documents account for a high proportion. Chunking needs to balance context integrity and embedding vector accuracy, and avoid splitting professional construction steps. Structured Excel data contains multi-field related entries. Chunking must retain row-level data association to prevent loss of complete information during retrieval. Administrative approval documents contain continuous approval nodes. Chunking must not interrupt node logic. Some documents contain professional charts and formulas. Parsing must retain format and content association.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the context length of professional long texts in oilfield engineering, balancing retrieval accuracy and chunking efficiency |
| `chunkSplitter` | By paragraph + fixed character boundary | Matches the natural segmentation logic of construction plans and operation logs, avoiding splitting professional term combinations |
| `customPdfParse` | Enabled | Supports parsing oilfield engineering PDF documents with professional charts and formulas, retaining core typesetting and content structure |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 seconds | Adapts to the parsing time of large construction plan PDFs, avoiding triggering timeout errors |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the upload requirements of single large well survey reports |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types such as PDFs and Excel, matching the content characteristics of consultation scenarios |

## Three common misconfigurations
- When uploading a single construction plan PDF larger than 500 MB, a platform timeout error is triggered. The cause is failure to adjust `PARSE_FILE_TIMEOUT_SECONDS` to the value range suitable for large documents, resulting in termination of parsing before completion.
- When retrieving consumable lists in Excel format, the number of returned results is less than the source file. The cause is failure to enable structured data parsing mode, or failure to retain complete row-level data association during chunking, resulting in some entries not being indexed.
- When retrieving construction step descriptions, connections between professional terms are broken. The cause is that `chunkSize` is set too small, splitting the continuous construction process context.

## How to verify the configuration is set correctly
- Upload a single 800 MB well survey report PDF, check that the parsing task has no timeout error and the parsing progress completes normally.
- Upload an Excel consumable list containing foreign use location fields, confirm that all matching entries are returned after retrieval with no omissions.
- Upload a drilling design document with professional formulas, check that the parsed chunks retain the connection between the formulas and the surrounding context, with no content breaks.
- Adjust `chunkSize` to 1000 characters, verify that the chunked text does not split continuous construction step descriptions.

The values provided here are common starting points and should be evaluated against the reader's own samples.
