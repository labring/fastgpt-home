# Oilfield Engineering Services Consultation and Response: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Oilfield engineering service data originates primarily from on-site construction manuals, equipment operation and maintenance procedures, emergency response records, client acceptance standards, and operation logs. Update rhythms align with job nodes. Teams upload on-site operation logs in real time, and update general procedures quarterly. Documents are mostly structured long texts, including operation steps, parameter tables, and troubleshooting checklists. Fields include operation area, equipment model, construction cycle, safety specification number, and others. Units mostly use international general engineering units and oilfield industry-specific units.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The structured long texts, specialized field units, and multi-source data characteristics of oilfield engineering services impose multiple constraints on the retrieval and recall process. Structured documents contain parameter tables and step lists. Chunked recall processes must avoid breaking table integrity to prevent loss of split critical parameters. Retrieval systems must support incremental synchronization for real-time uploaded on-site operation logs, ensuring recalled content matches the latest operation status. Matching for industry-specific units and fields must use associated matching to avoid result deviations from fuzzy matching. Multi-document scenarios require support for filtering recall scope by operation type and area to reduce interference from irrelevant documents.

## How to set the configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | `0.75–0.85` | Oilfield engineering documents have a high proportion of professional terminology. This range ensures matching accuracy and avoids recalling irrelevant documents with low similarity |
| `limit` | `Top 8–12 entries` | Single oilfield engineering documents have long content. Excessive recall will exceed the context window, while insufficient recall will fail to cover all scenario requirements |
| `searchMode` | Semantic retrieval | Professional terminology and field matching rely on semantic understanding. Prioritize documents with semantic relevance |
| `usingReRank` | Enabled | In long-text and multi-document scenarios, re-ranking optimizes the relevance ranking of results and highlights key operation parameters and steps |
| `datasetSearchUsingExtensionQuery` | Enabled | User inquiries in oilfield engineering scenarios often contain vague expressions. Extended queries supplement professional terminology variants to improve recall coverage |
| `collectionIds` | Specify 1–3 operation type collection IDs | Oilfield engineering services often divide document collections by operation area and equipment type. Limiting collections narrows the retrieval scope and improves efficiency |

## Three common mistakes
- The knowledge base fails to automatically synchronize oilfield operation documents from Feishu, and only manual file uploads are possible. The cause is incomplete authorization configuration for the Feishu knowledge base and disabled automatic synchronization trigger rules.
- Multiple documents cannot be selected in one go to add to the current retrieval scope, and only a single file can be added each time. The cause is that document collections are not created by operation type, and the batch selection function is not enabled.
- A single retrieval returns a 429 error status code or delayed results. The cause is that a reasonable request frequency threshold is not set, and the `limit` parameter is not used to control the number of recalled entries per retrieval.

## How to confirm the configuration is complete
- Initiate a test inquiry containing oilfield-specific terminology, and verify the correlation between the fields of the recalled documents and the inquiry content.
- Check the retrieval configuration interface to confirm that the document collection scope matching the operation type has been specified.
- Test the batch document addition operation to confirm that multiple target documents can be selected at one time.
- Initiate consecutive retrieval requests to confirm that current-limiting error messages are not triggered.

The values provided are common starting points and should be measured against the reader's own samples.
