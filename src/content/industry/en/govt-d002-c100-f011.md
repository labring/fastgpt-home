# Service inquiries and responses for oilfield engineering services: Forms and interactions

## What this category of data looks like
Data mainly comes from project approval documents, on-site construction logs, equipment operation and maintenance ledgers, and client demand work orders for oilfield engineering services. Data update rhythm is adjusted according to project progress. Documents within a single project cycle are updated at approval nodes. Daily operation and maintenance data is synchronized daily. Each document includes fields such as project number, construction area, equipment model, application item, and approval circulation record. Field units mostly follow engineering industry standards: construction duration is measured in hours, pressure parameters in megapascals, and material usage in cubic meters.

## Constraints imposed on forms and interactions
Fields include engineering professional units. Forms must adapt to input components with units. This avoids errors from manual unit input.
Data is updated at project approval nodes. Forms must support state linkage. Subsequent fill-in items are automatically unlocked after approval is passed.
Data sources involve multiple types of engineering documents. Forms must support quick filling of existing project data. This reduces duplicate entry.
Project number is a unique identifier. Forms must have built-in verification rules. This avoids duplicate submission of consultation work orders for the same project.

## How to configure this
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration item | Recommended setting | Rationale |
| --- | --- | --- |
| `formInput` | Input box template with units | Meet the requirement for professional unit labeling for oilfield engineering service data |
| `userSelect` | Associated equipment and area options for the current project | Reduce duplicate entry, match multi-source data characteristics |
| Form submission timeout | 300 seconds | Adapt to the review and data loading duration of engineering work orders |
| Historical context call limit | Top 10 entries | Match the associated data volume requirement for a single consultation |
| Input verification rules | Match engineering field required items and unit formats | Avoid invalid work order submission |

## Three common configuration mistakes
- Phenomenon: The `userSelect` component only displays a small number of options. It cannot load all associated equipment and construction areas. Cause: Automatic pull logic for associated project data is not configured. Only limited data from local cache is loaded.
- Phenomenon: An empty field error is returned after submitting a work order. No specific prompt text is provided. Cause: The field verification rule for `formInput` is not enabled. Input content that does not meet the format is not intercepted.
- Phenomenon: The form cannot be automatically reset. The page must be manually refreshed to initiate a new consultation. Cause: The form reset logic after successful submission is not configured. Cached data from previous fill-ins is used.

## How to confirm successful configuration
- Navigate to the form editing page. Verify whether the `formInput` component includes labeling prompts for engineering units.
- Trigger the `userSelect` component. Verify that all associated equipment and area options under the current project can be loaded.
- Submit a test work order. Verify that verification prompts matching format requirements are triggered.
- After completing form submission, verify whether the form automatically clears all fill-in items. Confirm that the form supports initiating a new consultation.
