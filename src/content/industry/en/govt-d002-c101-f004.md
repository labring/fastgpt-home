# Port and Shipping Inquiries and Responses: Workflow Orchestration

## What data for this category looks like
Data for port and shipping service inquiries and responses comes primarily from port operation systems, vessel schedule query platforms, maritime declaration databases, and port clearance systems. Two update rhythms apply:
- Vessel schedules and berthing plans update in real time per voyage
- Clearance policies and service guidelines update quarterly or when policies are adjusted

Single inquiry-associated documents include fields such as voyage number, departure port, arrival port, departure time, berthing time, service process nodes, and required material lists. Fields use standardized business codes. Time fields follow the YYYY-MM-DD HH:MM format. Port names include clear port suffix identifiers.

## Constraints imposed on workflow orchestration
Scattered data sources and inconsistent update rhythms require workflows to support both real-time API calls and scheduled batch data pulling. This prevents response errors caused by outdated data.
Business field standardization demands strict alignment with keyword extraction rules. Deviations in variable extraction will occur if rules are not matched correctly.
Inquiry requests often cover multiple business links. Workflows must connect multiple nodes to complete cross-system data linkage; full-process processing cannot be finished with a single node.
Cross-port system data interaction carries delay risks. Reasonable timeout thresholds must be set to avoid workflow interruptions.

## How to configure settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable extraction rules | Match keywords including voyage number, departure port, arrival port, departure time | Core requests for port and shipping service inquiries revolve around shipping business fields, so structured information must be extracted accurately |
| Global variable storage | Enable `variables` persistence | Transfer core business data such as tokens and voyage numbers across nodes, preventing variable loss between nodes |
| Tool call trigger | Automatically select based on inquiry question type | Adapt to tool call requirements for different business links, no manual specification needed |
| Context window | 800–1200 characters | Match the combination of short-text questions and structured business data for port business inquiries, avoiding interference from redundant information |
| Timeout threshold | 600 seconds | Cover the maximum time required for cross-port system queries and data pulling, preventing single-request interruptions |
| Node identification | Configure `nodeId` by business link | Facilitate locating abnormal workflow nodes, corresponding to links such as berthing declaration, clearance application, and inquiry response |

## Three common errors
- Phenomenon: Keyword extraction results are empty or incorrect, and core fields such as departure port and voyage number cannot be extracted. Cause: Extraction rules are not configured for port and shipping-specific business keywords such as "Tianjin Port" and "Shanghai Yangshan Port", and only general location and time matching logic is used.
- Phenomenon: Downstream nodes cannot read global variables generated by upstream nodes, and variable undefined errors are returned during tool calls. Cause: `variables` persistence configuration is not enabled, so temporary variables are not retained after workflow node execution.
- Phenomenon: MCP tools cannot obtain global tokens in the workflow, and tool calls fail. Cause: The `variables` parameter is not bound to the tool call node, and global variables are not passed to the tool input items.

## How to confirm the configuration is correct
- Submit a test inquiry containing voyage number, departure port, and arrival port, and verify that the variable extraction results cover all core business fields.
- View workflow operation logs to confirm that global variables generated by upstream nodes are properly read by downstream nodes.
- Trigger an MCP tool call, and verify that the tool input items are bound to the configured global variable parameters.
- Simulate a timeout scenario, adjust the timeout threshold to an extremely short value, and confirm that the workflow triggers expected timeout prompts.

The values provided are common starting points and should be measured against the reader's own samples.
