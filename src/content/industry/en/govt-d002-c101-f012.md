# Port and Shipping Industry Inquiry and Response: Deployment and Upgrade

## What the Data for This Category Looks Like
Data sources for port and shipping industry inquiry and response include port government service item lists, customs clearance process guides, ship operation declaration specifications, port charge catalogs, and common shipping business Q&A libraries. Government-related items are updated according to policy adjustment cycles. Schedules and operation guides are updated daily. Charge catalogs are updated monthly.
Document structures mostly consist of structured forms, step-by-step handling guides, and standardized Q&A entries. Fields include item number, processing time limit, application material list, processing channel, and charging standard. Units involved include working days, yuan/ton, and TEU. This document is written for FastGPT v4.17.0.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Data includes structured fields and unstructured guides. During deployment, configure parsing adaptation rules for multiple data types to avoid retrieval matching deviations.
Update frequencies vary widely. During upgrades, retain incremental synchronization links to prevent service outages caused by data synchronization interruptions.
Some fields involve standardized coding. When importing knowledge bases, validate field formats to ensure correct data indexing.
In container deployment scenarios, reserve sufficient storage capacity to handle long-term accumulation of historical inquiry records and uploaded files.

## How to Set the Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Adapts to concurrent query demands of port shipping inquiries, prevents database connection exhaustion |
| `MONGODB_URI` | `mongodb://admin:securepass@host:27017/port_ai?authSource=admin` | Stores historical inquiry records and knowledge base metadata; requires correct authentication information and target database name |
| `REDIS_URL` | `redis://:redispass@host:6379/0` | Caches retrieval results of high-frequency inquiries to reduce repeated query pressure on the database |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com` | Configures cloud storage endpoint address for storing uploaded service guide attachments and inquiry logs |
| `FE_DOMAIN` | `https://port-service-ai.example.com` | Configures frontend access domain name to comply with domain name specifications of internal port office systems |
| `ROOT_KEY` | `32-character randomly generated string` | Configures security key for administrator login to prevent unauthorized access to the backend management panel |

## Three Common Mistakes
- Symptom: After upgrading containers, running the initialization script returns a `connection refused` error. Cause: Correct address for `REDIS_URL` or `MONGODB_URI` was not configured in advance, causing failure to connect dependent services during initialization.
- Symptom: Cannot retrieve original knowledge base service guide entries after upgrade. Cause: Original knowledge base field mapping configuration was not retained during upgrade, causing structured data to fail to match retrieval rules correctly.
- Symptom: Modifying `config.json` after Docker deployment has no effect; model list does not update. Cause: The container was not restarted to load the new configuration, or the modified configuration item was not written to the `/app/data/config` path inside the container.

## How to Confirm Proper Configuration
- The `docker ps` command is executed to check the running status of all FastGPT containers, confirming no abnormal exits or restart records.
- The backend management address of `FE_DOMAIN` is accessed, and login is performed using `ROOT_KEY`. The dependent service connection status panel is checked to confirm normal connections to the database and cache service.
- A port service guide document is uploaded to verify that the file upload, parsing, and indexing processes complete normally.
- A simulated inquiry query is initiated to confirm that retrieval results include matching knowledge base entries.

The values provided are common starting points and should be measured against the reader's own samples.
