# Service Inquiry and Response for Refinery and Chemical Production: Model Access and Configuration

## What the data for this category looks like
Reference only; verify against the target FastGPT release and deployment documentation.

## Constraints imposed by these characteristics on the model access and configuration link
Real-time updated process parameters require the model to respond quickly to short queries, so the single inference context limit must be capped. Long-text operation specifications and fault cases require the model to support a large context window, so the `maxContext` and `maxTokens` parameters must be adjusted. Structured process data with clear units requires the model to accurately recognize unit associations, so parameters must be configured to adapt to structured field parsing. Semi-structured inspection logs require the model to extract key information, so output format-related configurations must be adjusted.

## How to Set the Configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to long-text operation specifications and fault cases for refinery and chemical production, avoiding context truncation |
| `maxTokens` | 2000–3000 token | Meets output length requirements for fault disposal steps and process parameter interpretation |
| `quoteMaxToken` | 1500 token | Limits the length of quoted document fragments, ensuring the model can focus on key process and fault information |
| `temperature` | 0.3–0.5 | Reduces output randomness, ensuring consistent and accurate expression of process parameters and disposal processes |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated interface address according to the deployment node | Adapts to the computing power server deployment environment, ensuring normal model call link operation |
| `AIPROXY_API_TOKEN` | Fill in the access key bound to the project | Ensures valid identity verification for interface calls, preventing unauthorized access |

## Three Common Configuration Mistakes
- Phenomenon: Rearrangement results after retrieval always show false. Testing works normally, but no valid rearrangement results appear during online calls. Cause: The correct rearrangement model deployment address is not bound in the model access configuration, or the configured `quoteMaxToken` parameter does not match the input length requirements of the rearrangement model.
- Phenomenon: Long-text unit operation procedures cannot be parsed normally by the content extraction component, and empty fields are returned. Cause: The `maxContext` parameter is not adjusted to fit the long document length, causing the model to fail to fully read the input document fragments.
- Phenomenon: The model output only contains text descriptions, and no pie charts or bar charts for process parameter comparison are generated. Cause: The prompt does not explicitly specify the visual output format, and no model adaptation rules that support chart generation are configured.

## How to Confirm the Configuration Is Correct
- Initiate a test query containing structured process parameters, check whether the model output accurately identifies parameter units and numerical values, and confirm that the `temperature` parameter is set as expected.
- Import a single long-text unit operation procedure, test whether the model can fully read and extract key steps, and confirm that the `maxContext` and `maxTokens` parameter configurations fit the document length.
- Call the rearrangement model associated interface, initiate a retrieval, check whether the sorting logic of the rearrangement results meets expectations, and confirm that the rearrangement model binding configuration is correct.
- Initiate a test query containing chart generation requirements, check whether the model output includes visual content in the specified format, and confirm that the prompt and model adaptation rule configurations match.
