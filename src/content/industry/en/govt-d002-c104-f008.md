# Coal Chemical Industry Matter Handling Consultation and Reply: Document Parsing and Chunking

## What this category of data looks like
Coal chemical industry matter handling consultation and reply data mainly comes from state-owned and public sector coal chemical project approval documents, safety operation procedures, process technology manuals, government service guides, and user consultation logs. Data update rhythm changes with business scenarios: project approval documents update in real time as projects progress, safety operation procedures are revised periodically, and user consultation logs are synced immediately. Document structures include formal documents with multi-level headings, process descriptions with parameterized tables, embedded doc attachments, and device flow chart images. Fields include project number, safety level, coal quality indicators, and matter handling process nodes. Units include tons, cubic meters, megapascals, degrees Celsius, and others.

## What constraints these characteristics impose on the "document parsing and chunking" link
The multi-level heading structure of coal chemical matter handling documents requires that parsing preserves hierarchical logic. Otherwise, chunking will destroy business associations. Embedded doc attachments and device flow chart images require the parsing module to support extraction of multi-format embedded content. Otherwise, key matter handling basis will be lost. Long text process manuals and approval documents require chunk length to adapt to the integrity of parameter paragraphs. Avoid splitting that breaks parameter connections. Real-time updated consultation logs and approval documents require the parsing module to support fast incremental processing. Avoid delays that affect matter handling response.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Coal chemical documents contain continuous process parameters and process descriptions. This length preserves parameter associations and avoids overly fragmented chunking |
| `chunkSplitter` | Split by heading hierarchy | Coal chemical documents mostly have multi-level table of contents structures. Splitting by headings preserves the integrity of business logic |
| `customPdfParse` | Enabled | Matter handling documents often embed doc-format process descriptions and device flow chart images. Embedded content needs to be parsed |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large coal chemical project approval documents and process manuals take longer to parse. The default duration is insufficient |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Coal chemical project approval documents often include multi-page drawings and attachments. Large file upload support is required |

## Three common mistakes
- When parsing Feishu multi-level directory documents, only top-level content is returned, and subdirectory content cannot be retrieved. The cause is that the chunking rule of splitting by heading hierarchy is not configured. Splitting only by fixed length destroys the hierarchical structure of the document.
- Calling the API to upload a doc-format document shows success but has no parsing results. The cause is that the `customPdfParse` configuration is not enabled, or the parsing switch is not correctly passed via API parameters.
- Marker reports an error indicating split exception. The cause is that `chunkSize` is set too small. Long parameter paragraphs in coal chemical documents are forcibly split, leading to broken logic.

## How to confirm the configuration is correct
- Upload a coal chemical matter handling guide document with multi-level directories. Check if the parsed chunks retain the heading hierarchy.
- Upload a PDF document containing embedded doc attachments and flow chart images. Confirm that the parsing result includes attachment text and image description content.
- Submit a coal chemical project approval package larger than 500 MB. Confirm that the upload and parsing process has no timeout errors.
- Call the FastGPT v4.17.0 file parsing API, carry the correct parsing configuration parameters, and verify that the returned result includes complete document content.
