# Coal Transportation and Sales: Service Consultation and Reply - HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Data mainly comes from internal business systems covering the entire coal transportation and sales process, including waybill management, loading and unloading scheduling, and settlement and reconciliation modules. Update rhythms fall into two categories: real-time (waybill generation, loading and unloading progress) and scheduled (daily settlement, weekly transportation capacity statistics). The structure of a single data record includes fields such as waybill number, coal type, departure location, destination, actual shipment weight, shipment time, and operator information. The weight unit is ton. Time fields are precise to the minute. The waybill number is a 16-character string.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Real-time generated waybill and loading and unloading progress data requires interface response delay to not exceed 5 seconds. Otherwise, it cannot support the real-time reply requirement for service consultations. Multi-field business data requires the interface request body to strictly match preset fields. This avoids data parsing failures caused by missing fields or format errors. The weight field uniformly uses tons as the unit. The interface must verify unit consistency during transmission to prevent conversion errors between kilograms and tons. Sensitive settlement data must pass permission verification via the interface's `Authorization` parameter. Only authorized external systems are allowed to make calls. When pulling scheduled daily statistical data in batches, the interface must support time-range-based paged queries. This adapts to the scheduled update rhythm of the data. ## How to Configure Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---- | ---- | ---- |
| `Authorization` | Fixed prefix `Bearer ` plus the token assigned by the business system, valid for 180 days | Adapts to the sensitive permission requirements of coal transportation and sales business data, prevents unauthorized calls |
| Timeout period | 3–5 seconds | Matches the response delay constraint of real-time waybill data, meets real-time consultation requirements |
| `variables` | Bind business variables such as waybill number and shipment time range | Supports dynamically passing specific business parameters for user queries |
| Batch query limit | Top 20 data entries | Adapts to the reply data volume limit for a single service consultation, avoids information overload |
| `responseData` | Only return core fields such as waybill status, actual shipment weight, and destination | Reduces interface transmission load and speeds up reply speed |
| Request retry count | 2 times | Addresses interface call failures caused by network fluctuations, improves call stability |

## Three Common Mistakes
- Phenomenon: A `401 Unauthorized` status code is returned when calling the interface to obtain waybill data. Cause: The `Authorization` parameter is not configured correctly, the token format is incorrect, or the token has expired.
- Phenomenon: The `responseData` field returned by the interface contains redundant information. This causes irrelevant content to appear in the service consultation reply. Cause: The field range returned by `responseData` is not restricted, and unnecessary data such as settlement amount is included.
- Phenomenon: Coal transportation and sales waybill images uploaded via the interface cannot load properly. The same images display normally in the official test interface. Cause: The interface transmission does not match the official base64 encoding rules, or the binary format conversion of the image is not handled correctly.

## How to Confirm the Configuration Is Complete
- Call the configured interface, pass the preset waybill number variable, and check if the returned `responseData` contains the expected core business fields.
- View the interface call log to confirm that the `Authorization` parameter is correctly carried and conforms to the required format.
- Upload test coal transportation and sales waybill images to the interface, and verify that the images can load and display normally in the test environment.
- Simulate network fluctuation scenarios, check whether the interface retries according to the set number of retries, and no consecutive call failures occur.
