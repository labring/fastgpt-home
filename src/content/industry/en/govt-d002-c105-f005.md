# Coal Transportation and Sales Consultation and Reply: Tool Calling and Plugins

## What Data for This Category Looks Like
Coal transportation and sales consultation data mainly comes from the internal transportation and sales scheduling system, contract management module, port loading and unloading ledger, and railway shipping interface. The data update rhythm is real-time synchronization or hourly batch synchronization. A single piece of data includes fields such as contract number, coal category, low heating value, total moisture, planned shipping volume, actual shipping volume, arrival station information, and business occurrence time. Field units follow industry general standards. For example, shipping volume is measured in tons, heating value is measured in kilocalories per kilogram, and the time format uses the ISO 8601 standard.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
The real-time update requirement for coal transportation and sales data requires that tool calling timeout thresholds match business response rhythms. This avoids consultation failure due to excessive waiting time. The structured multi-field feature requires that plugin parameter mapping strictly correspond to exclusive fields such as contract number and heating value. This prevents invalid returned data caused by field mismatches. The multi-data-source access scenario requires plugins to support simultaneous connection to multiple interfaces such as scheduling systems and port ledgers. This covers different consultation scenarios including contract query and shipping progress tracking. The standardized field unit requirement requires automatic unit adaptation during tool calling. This prevents returned data from conflicting with the unit expectations of the user's consultation.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Tool Calling Timeout Duration | 60-120 seconds | The average response time of coal transportation and sales business interfaces falls within the 30-90 second range. Too short a timeout will lose valid data, while too long a timeout will reduce consultation efficiency |
| `toolChoice` | auto | In consultation scenarios, the model must independently select appropriate tools. Do not force specification of a single tool to call |
| Plugin Data Source Mapping Rules | One-to-one mapping based on fields such as contract number and coal category | Coal transportation and sales data fields have strong exclusive attributes. Incorrect mapping will cause returned data to not match consultation requirements |
| `functionCall` | Enable strict mode | Consultation replies require structured data. Strict mode ensures tool return formats meet expectations |
| Number of Returned Entries per Single Tool Call | Top 3-5 entries | User needs for consultations usually focus on 1-2 transactions. Excessive returns will cause information overload |
| Plugin Data Cache Duration | 15-30 minutes | Coal transportation and sales data is updated in real time or hourly. Too long a cache will cause outdated data, while too short a cache will increase interface call frequency |

## Three Common Mistakes
- Phenomenon: The image URL returned by the plugin cannot be displayed normally in the reply. No image preview appears in the interface, and the console prompts cross-domain interception. Cause: The plugin's image resource whitelist is not configured. FastGPT blocks image loading from untrusted domains by default.
- Phenomenon: A connection timeout prompt appears when calling a local MCP service. The tool call log shows that the local address cannot be resolved. Cause: Local network access permission is not enabled in the FastGPT plugin configuration. By default, only public network domain names are allowed for calls.
- Phenomenon: Under the same consultation input, the tool call result differs from direct use of LLM function call. Returned fields are missing or formatted incorrectly. Cause: The `functionCall` strict mode is not enabled in the plugin configuration. This causes the model-generated tool call parameters to not match the preset fields.

## How to Verify Proper Configuration
- Initiate a consultation for a specific contract number. Verify that the fields returned by the tool call match the preset core fields.
- View the data source mapping list on the plugin configuration page. Confirm that all exclusive coal transportation and sales fields have been correctly bound to corresponding interface parameters.
- Simulate a call to the local MCP service (if configured). Check whether the FastGPT v4.17.0 tool call log shows a successful connection and returns valid data.
- Test the scenario where `toolChoice` is set to auto. Confirm that the model can independently select appropriate tools to complete the consultation reply.

The values provided are common starting points and should be measured against the reader's own samples.
