# Coal Transportation and Sales: Service Inquiry and Response - Forms and Interactions

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
Coal transportation and sales business data primarily comes from internal transportation and sales scheduling systems, weighing settlement documents, contract ledgers, and transportation logs. Data updates synchronously upon completion of each independent transportation and sales transaction. Most documents use structured table formats, with fixed fields including cargo type, shipment volume, settlement unit price, carrier information, and settlement cycle. Each field uses specific units such as tons, yuan per ton, and trip count. Bulk business data is often stored as Excel files, where each row corresponds to a single specific transportation and sales transaction.

## What constraints these characteristics impose on forms and interactions
Structured fixed fields require forms to support multi-condition combined input, to match inquiry needs across different business scenarios. Business fields include built-in specific units, so forms must include built-in unit validation logic. This prevents manual input unit formats from conflicting with business rules. Bulk-stored Excel ledgers require forms to support bulk import and validation, to meet daily bulk data query requirements for business inquiries. Real-time updated business data requires forms to immediately trigger knowledge base retrieval after submission. This ensures inquiry responses align with the latest business data.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Form field type | Dropdown select + numeric input combination | Most coal transportation and sales business fields have fixed categories and fixed unit types, which reduces manual input errors |
| Unit validation rules | Preset units including tons, yuan per ton, trip count, etc. | Business data fields have clear built-in units, which prevents format mismatch issues |
| Bulk import configuration | Enable bulk import, single file maximum 1000 MB | Coal transportation and sales ledgers are mostly bulk Excel files, and single file capacity is generally large |
| Retrieval matching count | Top 8-12 entries | Business knowledge base has a large number of entries, so enough matching items need to be returned to support inquiry responses |
| `formInput` submission trigger | Trigger knowledge base retrieval immediately after submission | Service inquiries need to accurately match relevant content based on complete form parameters filled by users |
| `userSelect` option configuration | Preset common options including carrier information, cargo type, etc. | Reduces frequency of manual user input and improves inquiry efficiency |

## Three common mistakes
- Phenomenon: The form returns a "field format mismatch" error after submission. Cause: Unit validation rules for corresponding business fields are not configured, and manually input units do not match preset rules.
- Phenomenon: A "file too large to parse" prompt appears when bulk importing Excel. Cause: The single file maximum limit configuration for bulk import is not adjusted, exceeding the preset threshold.
- Phenomenon: Retrieval returns empty results or fails after form submission. Cause: The `formInput` submission trigger logic is not correctly configured, or form parameters are not fully passed to the retrieval link, resulting in empty or invalid retrieval conditions.

## How to confirm the configuration is complete
- Complete test form business fields, check if corresponding unit options are automatically populated, and confirm unit validation rules are in effect.
- Upload a small test Excel ledger, check if it can be parsed normally and trigger the bulk matching process.
- Submit the test form, check if knowledge base retrieval is immediately triggered and relevant matching content is returned.
- View the form submission log, confirm that the `formInput` parameter has been correctly passed to the retrieval link.
