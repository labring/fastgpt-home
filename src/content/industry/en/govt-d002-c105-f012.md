# Coal Transportation and Sales Inquiry and Reply: Deployment and Upgrade

## What this category of data looks like
Coal transportation and sales inquiry data originates from the internal transportation and sales scheduling system, contract management ledger, weighing verification system, and public coal category guidance price database. Data updates follow three patterns:
Real-time generated waybills and weighing records update synchronously when business concludes.
Monthly contract ledgers update according to their performance cycles.
Guidance prices receive daily updates.
Single data entries contain fields including waybill number, coal variety, shipment volume, destination, contract number, weighing time, and settlement unit price. Units include tons, yuan per ton, vehicle trips, and other standard units.

## Constraints imposed by these characteristics on deployment and upgrade
The high-frequency real-time data, multi-dimensional structured fields, and intranet deployment scenario of coal transportation and sales impose multiple constraints on deployment and upgrade workflows.
Real-time generated waybills and weighing records require sufficient concurrent quotas reserved in the database connection pool to prevent index tasks from being blocked.
Structured data with multiple fields needs matching dedicated mapping rules to avoid field parsing errors.
For intranet deployment scenarios, database and cache service connection addresses must adapt to internal network segments.
Large-volume waybill attachments require matching dedicated storage configurations.
Version upgrades must maintain compatibility with historical transportation and sales data formats to avoid index interruptions.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `DB_MAX_LINK` | 20–30 connections | Adapts to the concurrent connection requirements of high-frequency real-time coal transportation and sales business, avoiding query failures caused by exhausted connections |
| `PG_URL` | Internal PostgreSQL service address, default port 5432 | Adapts to intranet deployment scenarios, connects to local transportation and sales business databases, and maintains compatibility with historical data formats |
| `STORAGE_S3_ENDPOINT` | Internal object storage service endpoint, such as `http://192.168.1.100:9000` | Adapts to storage requirements for large-volume waybill attachments, matches internal storage resource configurations |
| `REDIS_URL` | Internal Redis cache service address, default port 6379 | Caches frequently queried coal guidance prices and common inquiry scripts to reduce database pressure |
| `FILE_TOKEN_KEY` | Configured based on actual measurements | Generates access tokens for waybill attachments, adapts to internal permission control rules |
| `ROOT_KEY` | Configured per enterprise internal permission requirements | Highest permission key for the management backend, complies with security specifications |

## Three common configuration mistakes
- Chart display errors occur, with the interface returning a 500 status code. The cause is a too-low `DB_MAX_LINK` configuration value after an upgrade. High-frequency real-time data queries exhaust the connection pool, preventing the interface from returning data normally.
- Knowledge base index remains in a running state with no progress updates. The cause is that `PG_URL` points to an external public network database. A connection cannot be established in the intranet environment, and no timeout retry mechanism is configured.
- The output field of the orchestration node is not displayed in conversation results. The cause is incorrect configuration of `ROOT_KEY` permissions, preventing the orchestration task's output result from being written to the session cache normally.

## How to confirm the configuration is correct
- Execute the database connection test command inside the Docker container to confirm normal connectivity between the services configured via `PG_URL` and `REDIS_URL`.
- Upload a simulated coal waybill attachment to verify that the storage service configured via `STORAGE_S3_ENDPOINT` can receive the attachment normally and return an access link.
- Initiate an inquiry containing a waybill query, check whether the conversation result includes the field information of the corresponding waybill to confirm that data mapping takes effect.
- Check database connection pool monitoring to confirm that the current active connection count does not exceed the threshold set by the `DB_MAX_LINK` configuration.

The values provided are common starting points and should be measured against the reader's own samples.
