# Coal-Electric Integration Service Consultation and Reply: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Data for coal-electric integration service consultation and reply originates from internal production scheduling systems, mine monitoring nodes, and power grid connection platforms. Data is synchronized in batches every 15 minutes. Some core operating parameters support real-time pushing. A single data record contains five core fields: site code, collection time, raw coal output, unit operating power, and grid-connected power. The unit for raw coal output is tons, operating power is megawatts, and grid-connected power is kilowatt-hours. Data documents use JSON format, with field names following internal operation and maintenance specifications, and no overly deeply nested structures.

## Constraints Imposed on HTTP Interfaces and External Systems
High-frequency data updates require interfaces to support short-interval polling or real-time pushing. Timeout settings must align with the 15-minute synchronization cycle to prevent early termination of data acquisition. The fixed, non-nested field structure means interface request parameters do not need multi-layer parsing. However, required fields such as site code and collection time must be strictly matched, otherwise empty results will be returned. Data units are standardized to tons, megawatts, and kilowatt-hours. Interfaces must retain original units when returning data to avoid errors in consultation and reply caused by unit conversion discrepancies. The large volume of batch-synchronized data requires interfaces to support pagination parameters, preventing system stability issues from single-request overload.

## Three Common Mistakes
- Phenomenon: An error indicating incorrect file parameter format is returned when calling the interface, with HTTP status code 422. Cause: Variables are not passed in accordance with the flat structure of coal-electric integration data, and file-type variables are incorrectly nested.
- Phenomenon: Interface requests frequently trigger timeouts, with HTTP status code 504 returned. Cause: The request timeout setting is too short and does not match the 15-minute synchronization cycle of coal-electric integration data.
- Phenomenon: Required fields are missing from interface returned data, making it impossible to generate consultation and reply content. Cause: The required site code parameter is not included in the variable configuration, so the internal system cannot match the corresponding data.

## How to Verify Successful Configuration
- Send a test request and check if the returned response data includes required fields such as site code and raw coal output.
- Simulate repeated requests at 15-minute intervals to confirm the interface has no continuous timeouts or errors.
- Modify the site code in the variable configuration to an invalid value and confirm the interface returns a clear parameter error prompt.
- Compare the units of the interface returned data with those of the internal system to confirm there are no conversion deviations.

The values provided are common starting points and should be evaluated against the reader's own samples.
