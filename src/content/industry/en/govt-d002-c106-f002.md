# Coal-Electric Integration Matter Consultation and Reply: Vector Models and Indexes

## What the Data for This Category Looks Like
Data for state-owned enterprise matter consultation and reply under the coal-electric integration category comes from four main sources: internal matter handling guidelines, annual work order consultation ledgers, on-site service inquiry records, and industry policy documents.

Data updates follow three schedules:
- Matter handling guidelines are updated synchronously each year
- Work order consultation records are added daily
- Industry policy documents are updated irregularly per regulatory requirements

Each data entry includes these fields: unique matter identifier, original consultation question, standardized reply content, handling department, and completion time limit. The completion time limit is measured in days. The unique matter identifier uses a pure numeric code.

## How Data Characteristics Impact Vector Models and Indexes
The annual update requirement for matter handling guidelines means indexes must support incremental synchronization. This avoids resource consumption caused by full index reconstruction.
The large daily volume of new work order data requires configuring an index sharding strategy optimized for high-frequency writes.
Consultation questions and reply texts have significant length differences. Some long reply texts exceed standard chunking thresholds, so chunking rules must be adjusted to split long texts properly.
The completion time limit unit is fixed as days. The field unit must be clearly marked in metadata to avoid confusion of numerical meanings during retrieval.
Industry policy documents use specialized terminology. Vector models must be able to extract semantics from these professional terms. Indexes must retain precise matching capabilities for these terms.

## Three Common Configuration Mistakes
- Symptom: The exported knowledge base dataset.csv only includes the index field and no content field. Cause: The full field switch for knowledge base content export was not enabled, and only index metadata export was selected.
- Symptom: A 500 status code is returned when loading a custom index model in a Docker deployment environment. Cause: The model was not mounted to the specified directory of the FastGPT container, or the model path was not correctly configured in the configuration file.
- Symptom: After importing long-text consultation data, retrieval results show semantic fragmentation with low relevance to the original question. Cause: The chunk length parameter was not adjusted, and the default configuration was used to split long texts, resulting in truncation of professional terms.
