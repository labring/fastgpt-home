# Coal-Power Integrated Business Inquiry and Response: Workflow Orchestration

## What the data for this category looks like
Coal-power integrated business data sources include mine production monitoring systems, power unit operation logs, cross-sector collaborative approval documents, and inquiry ticket databases. Production data is pushed in near-real time. Approval and inquiry data updates align with workflow node updates. Document structure is split into three modules: coal mining, power dispatch, and cross-sector collaboration. Each document includes fields such as mine number, unit model, approval status, inquiry matter, and response time limit. Units include tons, megawatts, hours, pieces, and others.

## What constraints these characteristics impose on workflow orchestration
Dispersed data sources require workflows to be configured with multiple knowledge base association logic, to ensure cross-sector inquiries can call corresponding data sources. Near-real-time data updates require workflow node search frequencies to match this rhythm, preventing retrieval of expired information. Multi-field document structures require variable references to accurately match business fields, avoiding extraction of invalid content. Cross-sector business attributes require workflows to set branch judgments, to call corresponding processing logic based on the sector an inquiry belongs to.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Pass business type, mine number, unit ID | Match data classification rules for coal-power integrated multi-business sectors, to accurately associate corresponding knowledge bases |
| Single search limit | Top 8 entries | Coal and power business has a large volume of data entries, limiting returned entries avoids workflow overload |
| Maximum context | 800–1200 characters | Inquiry content mostly consists of cross-sector process descriptions, overly long context interferes with model understanding |
| Timeout setting | 60 seconds | Coal and power business inquiries require rapid response, overly long timeout negatively impacts user experience |
| `nodeId` | Bind dedicated nodes for coal/power sectors | Distinguish workflow branches for different businesses, ensuring inquiries from corresponding sectors call correct data |

## Three Common Configuration Errors
- Phenomenon: Audio and video tags inserted in workflow reply nodes do not render properly, only displaying raw tag code. Cause: The workflow's rich text rendering switch is not enabled, or the node configuration does not enable HTML tag parsing.
- Phenomenon: When selecting a knowledge base as a variable reference in the knowledge base search node configuration, the variable passed via the API does not take effect, returning default knowledge base results. Cause: The knowledge base ID variable is not correctly declared in the workflow's `variables`, or the variable transfer format does not meet requirements.
- Phenomenon: Text content extraction node returns empty values or incorrect fields. Cause: The specific field format of coal-power business documents is not matched, and corresponding rules for extracting approval status and unit operation parameters are not specified.

## How to Confirm Successful Configuration
- Manually trigger the workflow, pass test `variables` parameters. Verify that results returned by the knowledge base search node match the specified knowledge base.
- Insert test audio and video tags. Check that the preview content of the specified reply node renders normally.
- Submit test text containing coal-power business fields. Confirm that the text content extraction node returns correct field values.
- View workflow run logs. Verify that the branch node corresponding to `nodeId` is triggered correctly based on business type.
