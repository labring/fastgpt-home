# Coal-Electric Integration: Service Consultation and Response - Tool Calling and Plugins

## What the data for this category looks like
Business data sources for coal-electric integration include mine gas monitoring systems, generator operation logs, coal purchase and sales logs, and power dispatch order sheets. Real-time production data such as mine gas concentration and generator output power is pushed in real time along with device operating status. Log-type data such as coal output and power generation is updated daily. Power dispatch order sheets are updated in real time along with service processes. Most data uses structured fields, including mine ID, coal output (unit: tons), power generation (unit: megawatt-hours), dispatch order number, and response time limit (unit: hours). The data also includes unstructured service process descriptions and industry policy snippets.

## What constraints these characteristics impose on the "tool calling and plugins" link
The low-latency push of real-time production data requires tool calling to support fast data source pulling. This prevents information bias caused by expired cache. The multi-dimensional structured fields require tool calling parameters to match exclusive coal and power business fields. Generic data query logic cannot be used directly. Cross-business module association needs plugins that support calling both mine monitoring and power generation log data sources. This enables two-way data verification for service consultations. Data with different update frequencies needs differentiated refresh policies. Turn off local caching for real-time data. Set hourly refresh cache rules for log-type data.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the multi-tool linkage scenario for coal-electric integration, automatically select the tool matching the current consultation |
| `functionCall` | `enabled` | Support calling structured data query tools, match the exclusive structured fields for coal and power |
| Tool call timeout | 300 seconds | Cover the latency requirements of real-time production data pulling, avoid timeouts caused by slow data synchronization |
| Plugin data source binding | Mine monitoring system, power generation log database | Match the core business data sources of coal-electric integration |
| Single tool return limit | 1000 characters | Adapt to the length limit of service consultation responses, avoid overly long returned content |
| Branch execution trigger condition | According to tool return results | Avoid invalid branch execution, adapt to the progressive response logic of service consultations |

## Three common misconfigurations
- Phenomenon: The returned content of the first-layer tool call in the Workflow is printed in the final response. Cause: The output hiding rule for intermediate steps is not configured, leading to exposure of unnecessary tool execution logs.
- Phenomenon: The tool call module outputs both AI response text and triggers the next-level branch execution. Cause: The trigger rule for a single execution path is not set, leading to parallel execution of multiple tasks. This conflicts with the expected progressive response logic.
- Phenomenon: Chinese content returned after connecting the MySQL database plugin is garbled. Cause: The correct character set parameter is not specified in the database connection configuration, leading to encoding conversion failure for business data.

## How to confirm the configuration is correct
- Initiate a consultation involving coal output query. Check whether business fields such as mine ID and coal output are correctly matched in the tool call log.
- Test the tool call branch in the Workflow. Confirm that only the preset execution path runs, with no unnecessary intermediate step outputs.
- Connect the MySQL database plugin. Query business log data containing Chinese. Check whether the returned content has normal encoding.
- Initiate a consultation involving real-time power generation data. Check whether the tool call execution delay meets the preset timeout setting.
