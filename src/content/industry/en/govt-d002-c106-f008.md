# Coal-Electricity Integration Service Consultation and Reply: Document Parsing and Chunking

## What Data for This Category Looks Like
Service consultation and reply data for coal-electricity integration scenarios comes primarily from four categories: internal production ledgers, government approval documents, equipment operation and maintenance manuals, and service process documents.
Data update cycles cover three types: daily (production scheduling logs), project milestones (approval documents), and quarterly or annual (operation and maintenance manuals).
Document structures include long-form annual production plans and short-form single-service application forms. Some documents have fixed fields such as mine number, power generation, coal consumption, and approval document number. Corresponding units include tons, kilowatt-hours, and document number codes.
Document formats include PDF, TXT, Excel, and others. Approval-related documents often carry digital signatures.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
The multi-format and long-form nature of coal-electricity integration data requires the document parsing engine to adapt to different file types. This prevents content loss caused by format incompatibility.
The presence of fixed fields and units requires chunking to preserve the binding relationship between fields and units. Otherwise, subsequent semantic understanding of service consultations will be affected.
High-update-frequency scheduling log documents require the parsing process to have sufficient response speed. This prevents data from failing to enter the database in time due to timeouts.
Approval documents with digital signatures require the parsing engine to support encrypted format content extraction. Otherwise, recognition failures will occur.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0, and are adapted to the unique data characteristics of coal-electricity integration scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Coal-electricity integration documents contain production data and process descriptions. This range preserves complete semantics of a single service process or production ledger, while avoiding excessive chunk length that causes context redundancy |
| `chunkSplitter` | Split by paragraph + heading | Coal-electricity integration documents have clear chapter headings and paragraph structures. Splitting this way preserves the logical coherence of service processes |
| `customPdfParse` | Enabled | Coal-electricity integration documents often include PDF approval files with digital signatures. Enabling this setting adapts parsing for encrypted or signed PDFs |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Single annual production plans or large approval packages have large file sizes. This setting adapts to large file upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Parsing large PDF or multi-page ledgers takes a long time. This range prevents parsing failures caused by timeouts |
| `chunkSettingMode` | Manual mode | Coal-electricity integration documents have large format differences. Manual configuration allows adjusting chunking rules for different document types |

## Three Common Configuration Mistakes
- Issue: Calling the Doc2x tool returns a file read error, with an error message containing "Only support .txt, .m". Cause: The uploaded file format is not within the range of coal-electricity integration document formats supported by Doc2x, and file suffixes are not verified in advance.
- Issue: Uploaded PDF files with digital signatures cannot be recognized for content. Cause: The `customPdfParse` configuration is not enabled. The default parsing engine cannot handle PDF documents with encrypted signatures.
- Issue: The parsed knowledge base returns a reading link, and an error occurs when accessing the page. Cause: File access permissions are not configured correctly, or the `PARSE_FILE_TIMEOUT_SECONDS` value is set too short, causing the link generation process to not complete.

## How to Verify Proper Configuration
- Upload a typical coal-electricity integration approval PDF. Check that the parsed text includes complete fields such as approval document number and mine number, with no obvious sentence breaks or content loss.
- Test uploading a large-volume production ledger file. Confirm that the upload proceeds normally, and no errors related to `UPLOAD_FILE_MAX_SIZE` are triggered.
- Adjust the `PARSE_FILE_TIMEOUT_SECONDS` value. Verify that documents with long parsing times are not interrupted early, and chunking completes normally.
- Perform a parsing test on PDF files with digital signatures. Confirm that complete document content can be extracted, with no recognition failure prompts.
