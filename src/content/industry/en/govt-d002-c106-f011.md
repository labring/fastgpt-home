# Coal-Electric Integration Matter Consultation and Reply: Forms and Interactions
This document adapts to FastGPT v4.17.0.

## What this category of data looks like
Coal-electric integration matter consultation and reply data originates from internal collaborative business systems for coal mining and power production, plus government service submission and reply ledgers. Data sources include mine production capacity ledgers, power plant dispatch records, cross-department approval forms, and user consultation history databases. Business ledgers are updated daily, and consultation records are added in real time. Each data entry includes business scenario identifier, submitter information, matter number, consultation question, reply content, and processing status fields. Units include ten thousand tons, megawatt-hours, items, times, and other standard units.

## Constraints imposed by these characteristics on forms and interactions
Cross-business scenario identifiers require forms to support dynamic grouping; generic templates cannot be used. Real-time updated business ledgers require form options to pull latest data dynamically, and static configuration cannot be relied on. Binding of matter numbers requires forms to associate unique identifiers, to avoid misalignment between replies and matters. Compliance requirements for state-owned enterprises and public institutions require full traceability of form interactions, with timestamps and operator information recorded for every step. Long-text consultation and reply content requires forms to support multi-line input and formatted display, to meet the length requirements of business documents.

## Three Common Misconfigurations
- Phenomenon: Dependency installation fails after Docker deployment, and root permission switching is unavailable. Cause: FastGPT containers run by default with a non-root user, so direct execution of installation commands cannot obtain sufficient system permissions.
- Phenomenon: Final output content includes content from a previous AI conversation. Cause: No reply result filtering rule is configured, and no restriction is set to only display reply content associated with the current matter.
- Phenomenon: Output content includes the phrase "Citation Mark: [1]". Cause: No knowledge base result format cleanup rule is configured, and no filtering of citation mark fields is performed.

## How to Confirm Proper Configuration
- Submit a test form, check if field options for the corresponding business scenario are automatically loaded.
- Initiate cross-business consultation, check if the output only includes reply content for the current matter.
- Attempt voice input, check if speech can be correctly transcribed to text and submitted.
- View knowledge base call logs, check if citation mark fields have been filtered.
