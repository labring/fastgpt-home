# Coal-Electric Integration Matter Consultation and Reply: Deployment and Upgrade

## What this category of data looks like
Matter consultation and reply data in the coal-electric integration field comes from multiple sources: internal enterprise coal production ledgers, power dispatch logs, government service tickets, industry policy documents, and more. Update frequencies vary:
- Service tickets are updated in real time
- Production ledgers are synchronized daily
- Policy documents are updated quarterly

Document structures fall into two categories:
1. Structured data: Includes fields such as application number, mine number, unit model, processing time limit, with units including ton, megawatt, and working day.
2. Unstructured data: Includes consultation texts, maintenance procedures, approval documents, and more. Individual documents can exceed 10,000 characters in length.

All data must comply with internal enterprise information security specifications. Some content involves production and government-sensitive information.

## Constraints Imposed on Deployment and Upgrade by These Characteristics
The multi-source heterogeneous data traits of coal-electric integration require simultaneous connection to relational and document databases during deployment. This means configuring two data source types: `PG_URL` and `MONGODB_URI`.

Large differences in data update frequencies require incremental synchronization rule configuration to balance real-time performance and resource usage.

The high share of long documents requires sufficient storage capacity and connection pool resources to avoid matter consultation response delays caused by data loading timeouts.

The presence of sensitive government and production data requires encryption key configuration to secure data. It also requires adaptation to the enterprise's internal storage and network access policies.

## How to Configure Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://coal_user:secure_pass@internal-db:27017/coal_power?authSource=admin` | Connect to unstructured tickets, maintenance documents and other data for coal-electric integration |
| `PG_URL` | `postgresql://coal_admin:db_pass@internal-pg:5432/coal_power_ops` | Connect to structured approval processes, production statistics data |
| `DB_MAX_LINK` | `20–30 connections` | Adapt to concurrent access demands of multi-source data, calibrated based on actual testing |
| `REDIS_URL` | `redis://:redis_pass@internal-cache:6379/0` | Cache common matter consultation replies to reduce database access pressure |
| `FILE_TOKEN_KEY` | `32-character random encryption string` | Encrypt sensitive documents and interaction data during matter consultation processes |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | Connect to the enterprise's internal object storage for storing long documents and historical ticket attachments |

## Three Common Misconfigurations
- Symptom: Modified knowledge base or interface configurations do not take effect after local packaged deployment. Cause: The modified configuration file is not mounted to the corresponding container directory, or the configuration file is not correctly copied during image building.
- Symptom: Configured models fail to load after deployment using the `fastgpt:v4.8.22` image, and the page displays a configuration reading failure prompt. Cause: The image version is incompatible with the configuration file's parameter specifications, or the `MONGODB_URI` configuration is incorrect, leading to failed configuration reading.
- Symptom: Batch matter consultation queries time out and return a 408 status code. Cause: The `DB_MAX_LINK` configuration value is too low, and insufficient concurrent connections cause database request queuing timeouts.

## How to Verify Successful Configuration
- Log in to the FastGPT backend data source management page, run connection tests for `MONGODB_URI` and `PG_URL`, and confirm the test results show normal status.
- Upload a coal-electric integration matter consultation document, check the chunking and storage results, and confirm that the `STORAGE_S3_ENDPOINT` storage path supports normal read and write operations.
- Initiate a test matter consultation, review the system backend logs, and confirm there are no error messages related to database connections or cache read/write operations.
- View the system monitoring panel, confirm that the actual database connection count does not exceed the `DB_MAX_LINK` configuration threshold.
