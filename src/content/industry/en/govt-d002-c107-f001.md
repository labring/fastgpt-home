# Work Consultation and Reply for Coal Mine Production: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Work consultation and reply data for coal mine production originates from multiple sources: internal dispatching and command platforms, inspection record systems, safety management repositories, post operation manuals, and emergency response plans.
Update frequencies vary by data type:
- Safety specification documents are revised annually
- Daily work orders and inspection data are synced each day
- Equipment operation logs are updated in real time
The data uses a structured format, with fields including work area, equipment number, issue type, disposal status, and reporting time. Field units follow general coal mine production standards: work areas are identified by working face numbers, and time uses standard time formats.

## Constraints Imposed on HTTP Interfaces and External Systems
This category of data is distributed across multiple internal systems, with significant differences in update rhythms. This requires HTTP interfaces to support pulling data from multiple sources, and to allow independent `Authorization` authentication parameters to be configured for each data source.
Structured fields include coal-specific identifiers such as work area and equipment number. The `variables` parameter in interface requests must be bound to these specific fields, to ensure consultation content matches the corresponding working face or equipment scenario.
Real-time updated inspection and work order data requires interface request frequencies to align with sync rhythms, to avoid data lag or request timeouts. Additionally, document structure must align with internal coal mine systems. The `responseData` returned by the interface must be packaged using standardized work order fields, to ensure external systems can parse the data normally.

## How to Configure Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setup | Rationale |
| --- | --- | --- |
| `Authorization` | Configure according to the authentication rules of each connected system, use the corresponding system's API key or token as the value | Adapt to the independent authentication requirements of multiple internal coal mine systems, ensure data pull permissions comply with regulations |
| `variables` | Bind coal-specific fields such as work area, equipment number, and work order type, use valid enumerated values of the corresponding fields as the value range | Ensure consultation content matches specific production scenarios, return results accurately correspond to target working faces or equipment |
| `responseData` | Package into a structured format including work order ID, issue description, and disposal result, align field order with the internal coal mine work order system | Ensure external dispatching systems can directly parse returned data without additional format conversion |
| User selection configuration | Enable and bind the work order status field, with values of pending disposal, completed, rejected | Match the work consultation workflow of coal mines, facilitate external systems to identify consultation progress |
| Form input configuration | Limit input character length to 100-500 characters | Adapt to the typical length of coal mine inspection issue descriptions, avoid interface parsing failures caused by overly long content |
| API access timeout setting | Configure to 30-60 seconds | Match the data pull response duration of internal coal mine systems, avoid request failures caused by network latency |

## Three Common Configuration Errors
- Phenomenon: After calling the interface to upload images, the model cannot parse the image content and returns empty results. Cause: The FastGPT image parsing plugin associated interface is not configured, or the `variables` parameter is not bound to the image upload field, resulting in the interface not receiving image data.
- Phenomenon: When calling workflow user selection or form input components via API, the release channel has no interaction prompts. Cause: The interactive response switch for API triggering is not enabled in workflow configuration, only front-end interface interactive logic is configured.
- Phenomenon: When calling the knowledge base classification interface, first-level folders cannot be created. Cause: The FastGPT knowledge base classification management interface is not called, or the `responseData` parameter does not specify the parent node ID of the classification level, resulting in the system being unable to identify the target creation location.

## How to Verify Configurations Are Complete
- Send a test request carrying coal-specific `variables` fields, check if the returned `responseData` includes consultation content for the corresponding work area.
- Call the authentication interface, verify that the `Authorization` parameter can pass authentication of each connected system normally, with no permission error messages.
- Trigger an API call for the workflow, check if the release channel pops up the preset user selection or form input interface.
- Attempt to create a first-level knowledge base classification, verify that the interface returns a successful status code, and the classification is visible in the knowledge base.
