# Workflow Orchestration for Office Consultation and Reply in Coal Mine Production

## What Data for This Category Looks Like
Data for coal mine production office consultation and reply primarily comes from underground operation logs, safety regulation manuals, on-site problem reports, and approval records for office procedures. Data update cadences fall into three categories: real-time (for on-site problem reports), daily (for operation log updates), and periodic (for safety regulation revisions). Document structures are organized by operation type, approval node, and problem category, and include fields such as operation number, approval status, problem description, and processing time limit. Most field units are business-specific units such as hours, count, and meters.

## What Constraints These Characteristics Impose on Workflow Orchestration
Unique fields in coal mine production data require workflows to bind corresponding business variables to accurately match knowledge base content. Real-time updated operation data requires workflows to be configured with scheduled synchronization nodes to avoid using expired information. Multi-category document structures require workflows to filter knowledge bases by operation type to narrow search scope. Long-text operation records and regulation documents may exceed AI input limits, so a pre-validation link must be added to the workflow. Office consultation questions are often tied to specific operation scenarios, so workflows must support associating corresponding business fields after user input to output targeted replies.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context | 800–1200 characters | Most coal mine operation-related documents range from 500 to 1000 characters per piece; this range avoids exceeding AI input limits |
| Single Search Limit | Top 6 results | Common issues for coal mine office consultations fall into 3-5 categories; excessive search results will disrupt reply accuracy |
| `variables` | Bind operation number and approval status variables | Office consultations need to be linked to specific operation scenarios to accurately match corresponding business knowledge base content |
| `nodeId` | Bind the node ID of the session submission button | Trigger subsequent processes after the user clicks the button, which aligns with the interaction logic of office submission |
| Chunk Length | 300–500 characters | Coal mine safety regulation documents are mostly short paragraphs; this chunk range balances context completeness and retrieval efficiency |
| Timeout Duration | 600 seconds | Coal mine office consultation responses must be delivered within a reasonable time frame to avoid excessive waiting that affects operation efficiency |

## Three Common Misconfigurations
- Phenomenon: The AI chat node returns an input length limit exceeded error. Cause: No input length validation node was added before the workflow, and content exceeding the threshold was not intercepted.
- Phenomenon: Knowledge base search results are not filtered by the specified variables. Cause: The `variables` binding for the corresponding business fields was not configured correctly, and the variable reference path was wrong.
- Phenomenon: Clicking the session pop-up button does not trigger subsequent processes. Cause: The button node was not correctly associated with the `nodeId` of subsequent workflow nodes, and the trigger logic is missing.

## How to Verify Successful Configuration
- Enter test text that exceeds the preset length, check if an interception prompt is triggered.
- Bind the operation number variable to perform a knowledge base search, check if the returned results only match documents of the corresponding operation type.
- Click the session pop-up button, check if the workflow jumps to the preset subsequent node.
- View the workflow run logs to confirm that the `variables` and `nodeId` parameters are called normally.
