# Coal Mine Production Matter Consultation and Reply: Model Access and Configuration

## What this type of data looks like
Coal mine production matter consultation and reply data mainly comes from internal scheduling ledgers, matter guidelines published by various departments, and workflow documents supporting safety regulations. Data updates have no fixed cycle, and are synchronized when new matter workflows are launched or safety policies are adjusted. Each single data entry includes fields such as consultation question, official reply, handling department, handling time limit, required material list, and consultation channel. Handling time limit is measured in days, and material list is measured in pieces. Most documents use a mixed format of structured paragraphs and tables.

## Constraints on model access and configuration from these data characteristics
Data sources are scattered across multiple internal business systems. Access configuration must support multi-data source docking to avoid data silos. Document structures include mixed tables and paragraphs. Model context parameters must adapt to the text length of mixed-format content. Data updates have no fixed cycle. Incremental update configuration must allow flexible adjustment of trigger timing. Some matter data involves production safety sensitive information. Access configuration must ensure intranet transmission security and limit public network exposure scope.

## How to set configuration
| Configuration Item | Recommended Value | Basis for This Setting |
|---|---|---|
| `maxContext` | 8000–12000 token | The context of coal mine matter consultation usually includes multiple workflow steps and material lists, requiring sufficient length to carry complete business information |
| `maxTokens` | 2000–3000 token | Matter replies need to clearly state handling requirements; this value range balances output length and information density |
| `quoteMaxToken` | 3000–4000 token | Sufficient original matter document content needs to be cited as the reply basis to ensure information accuracy |
| `temperature` | 0.3–0.5 | Matter replies need to be rigorous and accurate; a lower temperature parameter reduces the randomness of generated content |
| `AIPROXY_API_ENDPOINT` | Exclusive internal proxy address for coal mines | Ensure sensitive matter data does not leave the intranet, complying with information security requirements |
| `AIPROXY_API_TOKEN` | Assigned exclusive authentication token | Enable fine-grained control of access permissions and prevent unauthorized access |

## Three common misconfigurations
- Issue: Address verification fails when accessing internal matter channels. Cause: No public network-accessible callback address is configured, or SSL certificate verification rules are not properly adapted.
- Issue: Matter replies generated by the model omit key handling materials. Cause: The `maxContext` parameter value is too small, causing context content to be truncated.
- Issue: Custom model providers cannot be selected in the configuration interface. Cause: Custom model permissions are not enabled in FastGPT v4.17.0, or API endpoints and tokens are not properly configured.

## How to confirm successful configuration
- Initiate a test consultation covering a complete matter workflow. Verify that the model's returned reply includes accurate handling department, time limit and material list, and that cited content comes from internal matter documents.
- Check the authentication configuration items `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`. Confirm that they match the current deployed internal proxy environment.
- Adjust the `maxContext` parameter, test long-text consultation scenarios, and confirm that no key content is truncated in the reply.
- Enter non-standard matter questions, and verify that the model returns standardized guidance replies.

The values provided are common starting points and should be evaluated against the reader's own samples.
