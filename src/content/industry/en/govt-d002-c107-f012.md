# Service consultation and reply for coal mining production: Deployment and Upgrade

## What the data for this category looks like
Data is primarily sourced from internal coal mine safety supervision notifications, post operation specifications, equipment operation and maintenance manuals, service approval process documents, and daily consultation records from frontline teams.
Safety supervision documents are synchronized monthly.
Operation specifications are updated quarterly alongside equipment technical renovations.
Daily consultation records receive daily incremental updates.
Most documents consist of structured process steps and parameter descriptions.
Fields include applicable positions, equipment models, approval nodes, and response time limits.
Common units include meters, megapascals, hours, and person-times.

## What constraints these characteristics impose during deployment and upgrade
Multi-source data with varied update rhythms requires a deployable scheduling module with customizable synchronization frequency, to support monthly, quarterly, and daily incremental update needs.
The large number of structured fields with professional units requires retaining compatibility of field parsing plugins during upgrades, to prevent incorrect recognition of professional parameters.
Large-volume equipment operation and maintenance manuals and drawing documents require adjusting storage configurations during deployment, to support batch uploads of long texts and multiple files.
High-frequency daily consultation records generate large incremental volumes, requiring sufficient database connection resources to avoid connection exhaustion during synchronization.

## Configuration settings
The following configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_coal?authSource=admin` | Adapts to the storage needs of multi-dimensional structured data for coal mines, supports index optimization for fields such as applicable positions and equipment models |
| `STORAGE_S3_ENDPOINT` | `http://minio-host:9000`, reserve 1000–2000 GB of storage capacity | Adapts to the storage of large-volume operation and maintenance manuals, equipment drawings and other documents, meets the storage needs of daily incremental updates |
| `DB_MAX_LINK` | `200–300` | Addresses daily incremental consultation records and document synchronization, prevents database connection exhaustion |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches reply content for high-frequency consultations, reduces database query pressure |
| `FILE_TOKEN_KEY` | Custom random 32-character string | Ensures access security for uploaded internal coal mine documents |

## Three common mistakes
- Symptom: A FastGPT workflow code execution node returns `500 Internal Server Error` when running JavaScript code, with logs showing `module not found`. Cause: The corresponding JavaScript dependency packages are not installed inside the Docker container, and dependencies are not added via mounted directories or image building.
- Symptom: After mounting a local directory via docker-compose, uploaded knowledge base files cannot be automatically synchronized and updated. Cause: File access permissions are not configured correctly, or the mounted path is not correctly mapped to the file storage directory inside the FastGPT container.
- Symptom: After deploying two FastGPT instances, external API calls to the knowledge base return empty results. Cause: The `MONGODB_URI` of the two instances is not pointed to the same database cluster, resulting in inability to share knowledge base data.

## How to confirm configurations are correct
- Run a database connection test script to verify connectivity of the `MONGODB_URI` and `REDIS_URL` configurations, and confirm that the number of connections does not exceed the value set for `DB_MAX_LINK`.
- Upload a coal mine operation and maintenance manual document, and confirm via the storage management interface that the file has been successfully written to the storage node corresponding to `STORAGE_S3_ENDPOINT`.
- Trigger an incremental synchronization task to verify that data sources with different update cycles are synchronized at the preset frequency.
- Run the code execution node in the workflow, confirm that the JavaScript code can execute normally without dependency missing errors.

The values provided are common starting points and should be evaluated against the reader's own samples.
