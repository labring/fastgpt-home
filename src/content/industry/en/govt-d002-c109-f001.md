# Power Grid Enterprise Service Inquiries and Responses: HTTP Interfaces and External Systems

## What this type of data looks like
Power grid enterprise service inquiry and response data primarily originates from user inquiries received via the 95598 customer service hotline, online business halls, offline business outlets, and associated electricity service work orders. Data update frequencies vary: real-time inquiries are generated immediately, work orders are updated in real time as processing progresses, and bulk archived data is synchronized each calendar day.
The document structure of a single data entry includes fields such as inquiry subject information (region, electricity category, user number), inquiry details, request intent, acceptance time, processing status, official reply content, and others. The format and unit for each field are as follows: region is an administrative division code string, time uses the YYYY-MM-DD HH:mm:ss format, inquiry details are plain text, and work order number is a unique identifier string.

## Constraints on HTTP Interfaces and External Systems
Dispersed data sources with multi-dimensional business attributes require HTTP interfaces to support filtering recalled content using parameters like `variables` for region, electricity category, to avoid returning irrelevant inquiry data. Real-time inquiries have strict timeliness requirements, so interfaces must support short timeout settings to prevent excessive user wait times. Inquiry data must be linked to business status from internal power grid marketing systems, so interfaces must support synchronizing business fields to ensure reply content matches actual processing progress. A large volume of specialized terminology is included in the data, so interfaces must work with the knowledge base’s specialized vocabulary configuration to improve recall matching accuracy.

| `responseData` | Structured JSON format, including inquiry details, processing status, official reply | Integration with internal power grid business systems requires structured data to facilitate automated transfer and subsequent processing |
| Request timeout setting | 10–15 seconds | Service inquiries require fast response; excessively long timeouts will reduce user experience |
| Number of recalled entries | Top 8–12 entries | Balances recall coverage and interface response speed, avoiding returning excessive redundant data |
| File upload size limit | No more than 500 MB | Inquiry attachments for power grid enterprises are typically PDF files or engineering drawings; limiting single-file size ensures interface stability |

## Three Common Configuration Errors
- Symptom: 401 Unauthorized error is returned when invoking the interface. Cause: The `Authorization` header parameter is not configured correctly, or an expired dedicated token is used.
- Symptom: The number of recalled results returned by the interface does not match expected values. Cause: The recalled entry setting is not adjusted according to the business scenario, or the region filtering parameter in `variables` is not passed.
- Symptom: Failure occurs when uploading files related to power grid inquiries to the knowledge base. Cause: The parameter format of the file upload interface is not configured correctly, or the single-file size limit is not complied with.

## How to Verify Correct Configuration
- Invoke the test interface, pass simulated region code and electricity category parameters, verify that the returned `responseData` includes matching inquiry content.

- Upload test files related to power grid inquiries, verify that the knowledge base successfully generates the corresponding text collection.
- Simulate a delay scenario, confirm that the interface returns valid results within 15 seconds, with no prolonged hanging.
