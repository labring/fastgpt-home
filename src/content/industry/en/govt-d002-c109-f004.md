# Workflow Orchestration for Power Grid Enterprise Inquiry and Response

## What this category of data looks like
Reference only; verify against the target FastGPT release and deployment documentation.

## What constraints these characteristics impose on workflow orchestration
Inquiry data comes from dispersed sources, with minor format differences across channels. Workflows must be configured with multi-source data collection nodes. These nodes unify the data structure of inquiries from different channels. Fixed classification rules for business domain codes require workflows to add classification routing nodes. These nodes automatically assign inquiries to corresponding business processing links based on the codes. Real-time newly added inquiry data requires workflows to support low-latency triggering. This avoids excessive user waiting times. Structured user address fields must be bound as subsequent processing parameters in the workflow. This ensures response content matches grid policies applicable to the user's region.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Condition | Triggered when a user sends inquiry content | Adapt to real-time interaction scenarios for power grid enterprise inquiry and response |
| Tool Call Switch | Enabled, allow the model to choose independently | Adapt to inquiry classification and processing needs across multiple business domains |
| Timeout Period | 600 seconds | Covers the full processing cycle for complex power grid inquiries |
| Variable Binding | Bind the user address and business domain code fields in `variables` | Match fixed structured fields in data documents |
| Node ID Configuration | Set `nodeId` according to collection, classification, response, and synchronization nodes | Distinguish execution order and status of each workflow link |
| Knowledge Base Association | Bind the official power grid service guideline knowledge base | Provide accurate policy and business references |

## Three common misconfigurations
- Issue: The workflow only returns fixed responses, and cannot automatically call the corresponding tool based on inquiry content. Cause: The tool independent selection configuration is not enabled, and only fixed process branches are set.
- Issue: No internal system feedback is received after calling the DingTalk webhook node, and a 403 status code is returned. Cause: The correct callback address and access permissions for the internal power grid work order system are not configured.
- Issue: BLOB files returned by the HTTP node cannot be downloaded in the dialog box. This is shown as no download button appearing in the dialog box. Cause: No file format conversion node is added, and the BLOB object is not converted to a downloadable standard file format.

## How to verify a successful configuration
- Send simulated inquiry content, check whether the workflow jumps to the corresponding processing node based on the inquiry type.
- Trigger the DingTalk webhook node, confirm that the internal work order system can receive synchronized inquiry records.
- Call the HTTP node to obtain a test BLOB file, check whether the dialog box displays a download entry.
- View workflow running logs, confirm that the user address and business domain code fields in `variables` are correctly extracted and used.
