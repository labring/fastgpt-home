# Work Consultation and Response for Power Grid Enterprises: Tool Calling and Plugins
This document applies to FastGPT v4.17.0

## What the Data for This Use Case Looks Like
Power grid enterprise work consultation and response data primarily comes from transcriptions of the 95598 power grid customer service hotline calls, offline service center consultation records, online service center work orders, and officially released electricity price policies and power outage announcements.
Data update cadence falls into two categories: real-time and scheduled. User-submitted real-time consultations and work orders are archived upon submission. Policy documents are updated when officially released.
Each data entry includes fields for consultation time, user account number, request type, response content, and processing progress. The account number uses a 10-digit numeric format. Duration fields use minutes as the unit, and monetary fields use yuan as the unit.

## Constraints for Tool Calling and Plugin Workflows
Power grid consultation data includes sensitive information such as user account numbers. Permission checks must be performed during tool calling to prevent unauthorized information disclosure.
Request types cover professional scenarios including power outage inquiries, electricity price calculations, and new connection consultations. Dedicated plugins must be called to access internal power grid interfaces.
Data update frequency is high. Plugins must support scheduled synchronization of the latest policy and work order data to ensure accurate response content.
Some consultations involve long-text policy documents. Tool calling must adapt to long-document parsing logic to avoid information truncation.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the multiple types of power grid consultation requests, automatically triggers corresponding tools |
| `functionCall` | Enabled | Supports calling dedicated plugins for electricity price inquiries and power outage announcement queries |
| Plugin call timeout | 15-20 seconds | Allocates sufficient response time, as internal power grid interface calls may have latency |
| Knowledge base recall count | Top 6 entries | Covers common power grid consultation scenarios, avoids information overload that reduces response efficiency |
| Context window size | 8000 token | Adapts to the long context requirements of power grid consultations, supports information such as user-provided account numbers and historical requests |

## Three Common Configuration Errors
- Symptom: The OpenAPI chat interface returns a "tool_call_invalid" error. Cause: The `toolChoice` parameter is not correctly set to an allowed value, resulting in non-compliant tool call formatting.
- Symptom: When entering a short question of a dozen or so characters, the response is output all at once without streaming return enabled. Cause: The streaming output option is not enabled in the interface configuration, or the context window setting exceeds the range supported by the current FastGPT version.
- Symptom: After replacing the built-in document parsing tool, power grid PDF policy files cannot be parsed. Cause: The adapted document type for the new tool is not specified in the configuration items, resulting in failure to parse power grid-specific long documents.

## How to Verify Correct Configuration
- Submit a test query involving professional power grid requests, and observe whether the corresponding tool call is automatically triggered.
- Check the tool call logs to confirm that the `functionCall` parameter is correctly identified and executed.
- Call the OpenAPI chat interface, and check whether the returned result contains fields related to tool calls.
- Test input a short text query, and confirm that the returned result is output in segmented streaming format.

The configuration values listed above are common starting points. They should be evaluated against the user's own specific samples.
