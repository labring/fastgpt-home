# Grid Enterprise Service Inquiry and Reply: Document Parsing and Chunking

## What Data Looks Like for This Category
Grid enterprise service inquiry and reply data comes from official service guides, electricity price policy documents, grid operation and maintenance service manuals, customer service specification documents, cross-regional power supply process descriptions, and similar materials. Update cycles vary: policy documents are updated irregularly, operation and maintenance and service documents are adjusted quarterly or semi-annually, and service process documents are updated immediately as business processes are optimized. Document structures include long text paragraphs, structured tables, policy entries with document numbers and implementation dates. Fields include applicable region, voltage level, processing time limit, charging standard, and more. Units include kilovolt, kilowatt-hour, yuan per kilowatt-hour, working day, and others.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
Grid enterprise service inquiry documents have mixed content types, with alternating long text paragraphs and structured tables. Parsing logic must balance semantic integrity of paragraphs and completeness of table formats. Some documents span multiple pages and include cross-page tables. Splitting must avoid breaking table content. Fields vary significantly across different documents. Exclusive fields and business-related information must be retained to avoid losing key business identifiers after chunking. Frequently updated documents require parsed chunked content to stay synchronized with source document versions, to avoid outdated content. Regional service documents must bind applicable regions to specific content, preventing separation of regional information and business content after chunking.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Grid enterprise service inquiry documents include long paragraphs and structured tables. This length range preserves semantic integrity and avoids breaking table content after splitting |
| `chunkSplitter` | Split by title + paragraph | Grid documents have clear chapter titles, document numbers, and implementation dates. Splitting by title ensures consistent topic for each chunk |
| `customPdfParse` | Enabled | Grid documents often include official seals, complex table borders, and headers/footers. Custom parsing can fully retain format and exclusive field information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Single large grid planning or annual service documents may exceed 100 pages. This duration prevents parsing timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Grid enterprises have large technical manuals and annual report files. This configuration relaxes upload limits |
| `chunkSettingMode` | Manual mode | Grid documents have significant format differences. Manual configuration adapts to different types of service inquiry documents |

Reference only; verify against the target FastGPT release and deployment documentation.

## Three Common Mistakes
- Scenario: After uploading a large PDF service guide for grid enterprises, the parsing node shows no working status. Cause: The `UPLOAD_FILE_MAX_SIZE` configuration is not adjusted. The file exceeds the default limit, so parsing is not triggered.
- Scenario: After parsing a grid electricity price table document, only the first few rows of data are captured. Cause: `customPdfParse` is not enabled. The default parsing logic cannot fully identify the complete content of cross-page tables.
- Scenario: For a grid cross-regional service process document after chunking, the final processing time limit information is truncated. Cause: The `chunkSize` is set too small, and the paragraph-ending splitting logic is not enabled. This causes long paragraphs to be forcibly split and truncated.

## How to Confirm Configurations Are Set Correctly
- Upload a typical grid service guide PDF. Check if the parsed text retains exclusive business fields such as document numbers and implementation dates.
- Randomly sample chunked content. Check the completeness of table documents, and confirm that no cross-page table content is missing.
- Test documents of different sizes. Verify that no parsing timeout errors occur. Confirm that the `PARSE_FILE_TIMEOUT_SECONDS` configuration matches the actual size of the documents.
- Adjust the `chunkSize` parameter. Compare chunking results, and confirm that each chunk has a coherent topic, with no content breaks or field loss.
