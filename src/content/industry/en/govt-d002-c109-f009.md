# Service Inquiry and Reply for Power Grid Enterprises: Model Access and Configuration

## What the data for this category looks like
The data sources for power grid enterprise service inquiry and reply are internal customer service ticket systems, offline service window records, and user inquiry content from online business handling platforms. The data structure includes standardized business fields and free text content.
Standardized fields include business type, user attributes, handling stage, and item code. Free text content includes user inquiry details and official reply guidelines.
Data update rhythms cover real-time entry of new tickets and daily updates to the standardized reply guideline database. Single data entries range from tens of characters to thousands of characters. Some business documents include specialized power terminology and process step descriptions.

## What constraints do these characteristics impose on the model access and configuration link
Data includes structured business fields and free text, so configuration options must support context splicing for mixed inputs to avoid losing critical business information.
Data update rhythms cover real-time and daily synchronization, so the knowledge base synchronization cycle in the configuration must be flexibly adjustable to adapt to frequently updated business guidelines.
Power grid business terminology is highly specialized, and single business document length is significant, so the model's context window must adapt to long text content to avoid truncating critical process descriptions.
Most power grid scenarios use intranet deployment environments, so access configuration must support model endpoints accessible locally or within the intranet, to avoid security and connectivity issues caused by public network dependencies.

## How to set the configuration
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 characters` | Power grid service inquiry data includes multiple segments such as business codes, user information, and historical conversations, requiring sufficient context to match business scenarios |
| `maxTokens` | `4000–6000 token` | Reply content must cover complete business process descriptions to avoid truncating critical information |
| `quoteMaxToken` | `2000–3000 token` | Most recalled power grid business documents are standardized process descriptions; limiting the token proportion of a single quote optimizes context splicing |
| `temperature` | `0.1–0.3` | Service inquiries require uniform and accurate reply guidelines, and overly divergent content should be avoided |
| `toolChoice` | `auto` | Some inquiries require associated business query tools; automatically selecting tools improves reply accuracy |
| `AIPROXY_API_ENDPOINT` | Intranet-deployed local model address | Most power grid scenarios use intranet environments, requiring API endpoints accessible locally or within the intranet |
| `AIPROXY_API_TOKEN` | Calibrated through actual testing | Must match the identity verification requirements of the intranet model to avoid unauthorized access |

## Three common configuration errors
- Symptom: The service process restarts repeatedly after intranet deployment, and logs prompt model connection failure. Cause: `AIPROXY_API_ENDPOINT` is not configured as an intranet-accessible model address, and a public network API endpoint is still used or the local model address is not correctly pointed to, resulting in failed connection establishment.
- Symptom: Recalled power grid business document content is not displayed in the conversation details. Cause: The value of `quoteMaxToken` is too small, causing recalled documents to be truncated or unable to be accommodated in the context, so reference content cannot be displayed normally.
- Symptom: Generated reply content deviates from business standard guidelines. Cause: The value of `temperature` is too high, causing the model to generate overly flexible content that does not meet the strict requirements of power grid service inquiries.

## How to confirm the configuration is complete
- Perform network connectivity verification operations in the intranet environment to confirm that the `AIPROXY_API_ENDPOINT` address is accessible normally, and the identity verification parameters are configured correctly.
- Import a typical power grid service inquiry data to initiate a test conversation, and check whether the associated business document content is recalled in the conversation details.
- Adjust the `temperature` parameter to the preset range, initiate multiple test inquiries, and confirm that the generated reply content conforms to business standard guidelines without divergent content.
- View the system operation logs to confirm that there are no error messages such as model connection failure or context overrun.
