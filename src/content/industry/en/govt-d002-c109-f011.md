# Service Inquiries and Responses for Power Grid Enterprises: Form and Interaction

Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category of Data Looks Like
This category of data primarily comes from service applications and inquiry records submitted via power grid enterprise self-owned customer service systems, online business halls, and offline service outlets. Data fields include user ID, electricity address, business type, problem description, associated attachments, and more. Business type is a fixed enum value, problem description is a free text field, and attachments support images and PDF formats. Data updates in real time when users submit requests; the length of single documents varies widely, there is no fixed batch update cycle, and batch processing is only performed during system upgrades or data archiving.

## Constraints on Form and Interaction Links
The fixed enum attribute of business type requires the form interaction link to use the `userSelect` component to provide dropdown options, avoiding business classification bias caused by free input. The free text problem description field requires limiting the input length range to prevent exceeding the model's processing limits. Attachment uploads must match the common image and PDF formats used by power grid enterprises, so the form needs to be configured with format validation and size limits. The real-time data update feature requires triggering knowledge base synchronization immediately after form submission to ensure the timeliness of inquiry data. Associated fields for multiple business types require the form to support linkage validation, ensuring required fields are automatically triggered based on business type.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `userSelect` | Bind to power grid business type enum values | Business type is a fixed enum field; using dropdown selection components unifies input format and reduces classification errors |
| Form input length limit | 800–1200 characters | Matches the typical description length of power grid business inquiries, avoids exceeding model processing limits |
| Attachment format validation | Only allow image and PDF formats, single file no larger than 100 MB | Matches common business attachment types and size specifications for power grid enterprises |
| `formInput` | Configure free text input area | Adapts to the free text attribute of problem descriptions, supports users in detailing business situations |
| Real-time synchronization trigger | Execute immediately after form submission | Adapts to the real-time data update feature, ensures inquiry data is stored in the knowledge base promptly |
| Context window configuration | First 2–4 rounds of conversation content | Matches typical interaction rounds for power grid inquiries, avoids context overload |

## Three Common Misconfigurations
- Phenomenon: Two AI chat nodes are connected in series in a workflow, and the final output contains the full reply content from the previous node. Cause: The output of the previous node was not truncated or filtered, resulting in redundant intermediate step content being retained during context concatenation.
- Phenomenon: Long text inquiry content entered by users is truncated by the model and cannot fully transmit business details. Cause: No length limit was configured for `formInput`, or the set length interval is smaller than the typical text length of power grid business inquiries.
- Phenomenon: The specified AI model cannot be selected during the configuration classification phase, but can be called normally after the workflow is published. Cause: Access permissions for the corresponding AI model were not bound in the global configuration, and the published workflow automatically loads the default model configuration.

## How to Verify Proper Configuration
- Submit a test business inquiry form, confirm that the dropdown options match the preset power grid business type enum values.
- Upload a test file that does not match the preset format, confirm that the interface displays a format validation prompt.
- Enter test text that exceeds the preset length, check whether an input length limit prompt is triggered.
- Publish the configured workflow, connect two AI chat nodes in series, verify that the final output only retains the reply content from the second node.

The values listed above are common starting points and should be evaluated against the samples used in the specific deployment.
