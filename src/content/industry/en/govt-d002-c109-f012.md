# Service Consultation and Response for Power Grid Enterprises: Deployment and Upgrade

## What the data for this category looks like
The data for power grid enterprise service consultation and response primarily comes from transcribed text of 95598 hotline calls, consultation ledgers from offline service windows, and records from electricity business work order systems. Data is updated daily, with new consultation entries generated each day. Each individual entry includes fields such as consultation content, user identity type (resident/enterprise), business category (application for connection, repair request, payment, etc.), affiliated power supply area, consultation initiation time, historical processing progress, and some entries include unstructured attachments like uploaded electricity bills or device photos. The data structure balances structured metadata and unstructured text, covering full process information from user consultation initiation to completion of response.

## What constraints these characteristics impose during deployment and upgrade
Multiple heterogeneous data sources require support for multi-format data access during deployment, and adaptation to the interface specifications of existing internal work order systems and hotline transcription tools within the power grid. The daily update rhythm requires the knowledge base vector synchronization cycle to match the daily data refresh rhythm, to avoid data lag. The rich metadata fields require mapping corresponding business fields during knowledge base configuration, to ensure accurate filtering by power supply area and business type during retrieval. The universal requirement for intranet deployment requires all configurations to adapt to the intranet network environment, to avoid security risks and latency issues caused by public network access.

## How to Set Configurations
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30` | The daily concurrent request volume of power grid consultation data is stable. The connection pool must cover the concurrent demands of daily customer service consultations and knowledge base retrieval |
| `MONGODB_URI` | `mongodb://[intranet database IP]:27017/fastgpt?authSource=admin` | Power grid business data is stored in intranet MongoDB. An intranet address and authentication source must be specified to ensure secure data access |
| `REDIS_URL` | `redis://:[custom password]@[intranet Redis address]:6379/0` | High-frequency session caching and retrieval result caching require intranet Redis support, to avoid public network latency affecting user experience |
| `STORAGE_S3_ENDPOINT` | `http://[intranet object storage IP]:9000` | Attachment files for power grid consultations must be stored in intranet object storage, to comply with data security and compliance requirements |
| `FE_DOMAIN` | `https://[power grid intranet service domain name]` | Domain name for integration with internal power grid office systems, to avoid interface loading errors caused by cross-domain configuration issues |

## Three Common Configuration Errors
- Symptom: A Docker-packaged deployment fails to start, with logs indicating a database connection timeout. Cause: `MONGODB_URI` is not configured to the intranet database address of the power grid, and a public network address is used by mistake, or intranet access permissions are not configured.
- Symptom: After calling an HTTP orchestration node, the output content of the node is not displayed in the conversation interface. Cause: The output pass-through configuration for conversation context is not enabled, or the return fields of the orchestration node do not match the standard output format of FastGPT.
- Symptom: When calling an intranet-deployed model service, FastGPT reports a connection timeout or format incompatibility error. Cause: `FE_DOMAIN` is not configured to the intranet domain name, or base64-formatted image recognition input is not converted to the `image_url` format required by the model.

## How to Verify Successful Configuration
- Access the FastGPT backend system status panel, check the database connection module, and confirm that the connection status corresponding to `MONGODB_URI` and `REDIS_URL` is normal.
- Initiate a test conversation simulating a power grid electricity consultation, check the conversation interface after initiation, and confirm that the return content of the HTTP orchestration node is normally displayed in the conversation flow.
- Call the configured model service interface in the intranet environment, confirm that the model response can be obtained normally, and there are no connection timeout or format error prompts.
- Upload a simulated electricity business attachment, confirm that it can be previewed and downloaded normally through the FastGPT file storage module, and there are no permission error prompts.
