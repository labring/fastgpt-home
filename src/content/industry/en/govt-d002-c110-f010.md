# Mining and Mineral Processing Inquiry and Response: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
The business data for mining and mineral processing originates primarily from mining design plans, mineral processing flow sheets, equipment operation and maintenance logs, safety and compliance regulations, mineral rights approval documents, and similar sources. The data update schedule is layered:
- Equipment operation logs are generated in real time
- Daily production reports are updated daily
- Monthly scheduling plans are revised monthly
- Annual compliance documents are updated every 12 months

Document structures include long-text process descriptions, structured parameter tables, job indicator records with units, and fields covering job locations, equipment numbers, processing capacity, job duration, and other relevant details. Some documents include professional term annotations.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
- A high proportion of long-text process documents requires that professional terms be preserved intact during segmented retrieval, to prevent semantic loss from truncation.
- A large number of structured parameter tables requires support for both numerical matching and semantic retrieval, with requirements for compatibility with hybrid retrieval workflows.
- A large volume of real-time and frequently updated data requires support for incremental recall to maintain content timeliness.
- A large number of job indicator fields with units requires matching unit information during retrieval, to avoid retrieving invalid content with mismatched units.
- High risk of cross-category document interference requires limiting the retrieval set to documents exclusive to mining and mineral processing.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | 0.72–0.85 | Semantic similarity threshold for matching mining and mineral processing professional terms, filtering low-relevance geological exploration documents |
| `limit` | Top 6 entries | Limit the number of returned results for inquiry scenarios, adapting to the content length requirements of short responses |
| `searchMode` | Hybrid retrieval | Balance retrieval performance for structured equipment parameters and unstructured process documents |
| `usingReRank` | Enabled | Re-rank retrieved results by mining and mineral processing business relevance, raising the priority of core job process content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expand professional terms for inquiries, for example expanding "ore grinding" to related expressions of the corresponding job process |
| `collectionIds` | Bind three collections: mining regulations, mineral processing reports, equipment operation and maintenance | Limit the retrieval scope to avoid cross-category document interference with business inquiries |

## Three Common Configuration Mistakes
- Symptom: Search test results do not match the preset number of entries, returning only a small volume of content or exceeding the upper limit. Cause: The `limit` parameter is not configured correctly, or the bound `collectionIds` only include a small number of exclusive document collections.
- Symptom: Hybrid retrieval requests take longer than 10 seconds, exceeding the reasonable response range for commercial scenarios. Cause: Retrieval weights are not optimized for structured mining and mineral processing data, and hybrid retrieval of full document sets is enabled simultaneously.
- Symptom: After uploading a mineral processing flow PDF, search tests return no results, and no system prompt indicates completed parsing. Cause: Text segmentation verification after PDF parsing is not enabled, or the segmentation length exceeds the typical character range for professional mining and mineral processing documents.

## How to Confirm Correct Configuration
- Access the knowledge base search test page in FastGPT v4.17.0, input a typical mining and mineral processing inquiry question, and verify that the number of returned results matches the `limit` configuration.
- Review the system retrieval log to confirm that the `searchMode`, `usingReRank`, and `datasetSearchUsingExtensionQuery` parameters are correctly called, with no abnormal error fields.
- Upload a mineral processing regulation PDF, wait for the system to finish parsing, then search for professional terms within the document to confirm that the corresponding content is included in the results.
- Test the hybrid retrieval request duration, adjust the `similarity` threshold or number of retrieved entries, and control the duration within a range that meets business requirements.
