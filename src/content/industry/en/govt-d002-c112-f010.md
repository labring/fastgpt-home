# Grain Reserve Service Consultation and Reply: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
Data sources for grain reserve-related materials include public announcements from national and local grain and material reserve departments, inventory ledgers of reserve granaries, grain quality inspection reports, rotation and transfer plan documents, daily inspection records, etc. The update frequency varies: policy-based reserve inventory data is updated quarterly, rotation plans are updated monthly, and daily inspection records are updated daily. Document structures include structured ledgers (with fields such as reserve granary number, grain variety, storage quantity, etc.), semi-structured notification announcements, and unstructured inspection logs. Field units follow standard measurement formats such as tons, percentages, kilograms, etc.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Heterogeneous data from multiple sources requires unified metadata formatting to avoid field conflicts or matching deviations during retrieval. If data with different update frequencies is not managed by category, old data may mix into currently valid retrieval results, affecting the accuracy of consultation replies. The need for precise field matching in structured ledgers means retrieval cannot rely solely on semantic similarity; exact matching capability must also be considered, otherwise it is impossible to accurately locate inventory data for a specific grain variety. Chunking long-text inspection logs easily leads to semantic fragmentation, which affects the coherence of recall results. Semi-structured notification announcements have fixed title hierarchies; chunking must retain title association information to avoid reduced retrieval accuracy caused by semantic fragmentation.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Grain reserve data requires precise field matching. A threshold that is too low will introduce irrelevant inventory data, while a threshold that is too high will miss rotation plan documents with approximate phrasing |
| `limit` | Top 8 entries | Individual reserve data entries are clear. Too many results will exceed the context window limit of FastGPT v4.17.0, while too few will miss cross-library associated information |
| `searchMode` | Hybrid retrieval | Covers both exact matching for structured ledgers and semantic retrieval for unstructured inspection logs |
| `usingReRank` | Enabled | Semantic similarity for long-text inspection logs is prone to misjudgment; re-ranking can correct ranking results and improve recall accuracy |
| `datasetSearchUsingExtensionQuery` | Enabled | Grain reserve-related consultations often use synonyms (such as "rotation", "transfer"), extended queries can cover more relevant documents |
| `collectionIds` | Configured by data type, single library no larger than 500 MB | Avoids retrieval delays caused by overly large single-library data, and distinguishes three categories of data: policy-based reserves, rotation plans, and inspection logs |

## Three Common Misconfigurations
- Phenomenon: When adding knowledge base chunks via API, the content is not imported into the expected dataset. Cause: The correct `collectionIds` parameter was not specified, resulting in data being assigned to the default category
- Phenomenon: Local image links in imported Markdown files cannot be displayed properly. Cause: Local images were not uploaded to a supported online image hosting service, and were not replaced with accessible external links
- Phenomenon: The exported knowledge base file size is too small and the content is incomplete. Cause: Only the currently active chunked data was exported, and all datasets or incrementally synchronized historical data were not checked

## How to Confirm the Configuration Is Correct
- Upload a structured inventory ledger file, search for "2024 wheat rotation plan", and confirm that the results include matching ledger entries
- Import a Markdown document containing local images, and check whether the images load normally in the retrieval result preview
- Export the full dataset of knowledge base data, and verify that the file size matches the scale of the original data
- Initiate a retrieval request, and confirm that the number of returned results matches the value set for `limit`

The values provided here are common starting points and should be measured against the reader's own samples.
