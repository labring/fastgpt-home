# Service Consultation and Response for Shipbuilding: Workflow Orchestration

## What the data for this category looks like
Shipbuilding service consultation and response data draws primarily from shipyard production management systems, China Classification Society compliance documents, ship spare parts inventory ledgers, and internal service process manuals. Production work orders are updated in real time per production node. Compliance documents are synced quarterly. Spare parts ledgers are updated monthly. Document structures include fields such as work order number, ship type, inspection item, processing time limit, and required materials. Units include vessel, unit, man-hour, cubic meter, and other standard units. Some documents contain Chinese-English bilingual content.

## What constraints these characteristics impose on the workflow orchestration link
The multiple data sources and staggered update cycles of shipbuilding service consultation data require splitting retrieval nodes by data source type, with separate connections to production systems, compliance document libraries, and inventory ledgers. The work order number, as the core unique identifier, must be passed via `variables` as a retrieval trigger condition to avoid cross-ship-type data confusion. The presence of bilingual documents requires configuring retrieval branches in the workflow that automatically adapt to the target user's language. The quarterly update cycle of compliance documents requires adding a document version verification node in the workflow to ensure the latest version of data is called. This configuration is based on FastGPT v4.17.0.

## Configuration settings
| Config item | Recommended value | Rationale |
| --- | --- | --- |
| `variables` | Includes ship type, work order number, processing scenario | Matches core retrieval and verification fields for shipbuilding service consultation |
| Form input node | Binds the work order number field in `variables` | Ensures consistent unique identifier passed in nested workflows |
| Per-search result limit | Top 8 entries | Shipbuilding service document data volume per category is moderate; excessive entries increase context processing load |
| Timeout threshold | 600 seconds | Cross-system calls to China Classification Society compliance documents take longer |
| Node trigger rule | Triggers based on the work order number in `variables` | Avoids invalid retrievals without identifiers, ensures data matches corresponding ship projects |

## Three common misconfigurations
- Phenomenon: Form input node dialog boxes nested in other workflows remain displayed and cannot be automatically hidden. Reason: The form node of the nested workflow is not configured for silent parameter passing mode, and the `variables` field passed by the parent workflow is not bound.
- Phenomenon: Workflow calls custom Python code and returns parameter errors, prompting missing ship type analysis dependencies. Reason: The corresponding Python runtime environment is not configured in the code running node of the workflow, and the dedicated analysis package required for shipbuilding business is not uploaded.
- Phenomenon: When passing global variables via a shared URL, some ship type parameters are not correctly brought into the retrieval link. Reason: Special characters in `variables` (such as hyphens in ship type numbers) are not escaped, leading to parameter parsing failure.

## How to confirm the configuration is correct
- Manually input test ship type numbers and work order numbers, trigger the workflow, and verify whether retrieval results match the service requirements and latest document versions of the corresponding ship project.
- Nested call the form input node, check if the dialog box hides as expected, and confirm if the `variables` field passed by the parent workflow is correctly received.
- Run the custom Python code node, and verify that it can correctly parse spare parts, work orders, or inspection data related to shipbuilding.
- Generate a shared link and add test parameters, verify that the parameters are correctly brought into the retrieval and verification links of the workflow.
