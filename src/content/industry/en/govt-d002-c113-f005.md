# Government Service Consultation and Response for Shipbuilding: Tool Calling and Plugins

## What data looks like for this category
Service consultation data in the shipbuilding sector primarily comes from shipyard internal operation manuals, China Classification Society standard documents, and maritime administration bureau service guidelines. The data update cadence is quarterly internal process adjustments and annual industry standard updates. Document structures are standardized, including fields such as service item code, responsible department, legal processing time limit, required material list, processing flow nodes, and contact information for inquiries. Field units are mostly working days, copies, serial numbers, and similar units.

## What constraints these characteristics impose on the tool calling and plugin workflow
The multi-source and dispersed nature of shipbuilding service consultation data requires tool calling plugins to connect both internal management systems and external industry standard databases, to avoid incomplete coverage from single-source data. The fixed-cycle update rhythm requires the tool cache validity period to match the data update cycle, preventing calls to outdated service process information. The standardized but information-rich document structure requires tool parameter parsing to strictly follow the unit rules for fields such as service item code and processing time limit, to avoid unit conversion errors. The dense professional terminology content requires plugin context prompts to adapt to shipbuilding industry-specific expressions, improving the accuracy of tool calls.

## Three Common Mistakes
- Symptom: An "Incompatible transport protocol" error occurs when calling an MCP plugin, with a status code of 400. Cause: The SSE format service generated by FastGPT is not adapted to the NPX call requirements of the target IDE, resulting in protocol incompatibility.
- Symptom: The service material list field returned by tool calls is empty. Cause: Failed to match the dedicated field naming rules of shipbuilding service documents, leading to failure to extract target content during parameter parsing.
- Symptom: A knowledge base application configured with online tools does not return the latest maritime service policy information. Cause: The linkage logic between tool calling and knowledge base retrieval is not enabled, only relying on local knowledge base documents without triggering external data source queries.

## How to Verify Proper Configuration
- Initiate a test query containing shipbuilding service-related keywords, and check whether the timing of tool calling matches expectations.
- Review the tool call return results, confirming that complete content of corresponding fields such as service item code and processing time limit is included.
- Check the tool call logs, confirming that configuration items such as timeout duration and cache validity period match the preset values.
- Trigger cross-data-source tool calls, confirming that information from both internal management systems and external industry specifications can be obtained simultaneously.
