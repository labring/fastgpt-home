# Service Inquiry and Reply for Shipbuilding: Model Integration and Configuration

## What the data for this category looks like
Shipbuilding industry service inquiry data mainly comes from four categories: internal enterprise service process manuals, ship inspection specification documents, archived order inquiry work orders, and crew service guides. Data update rhythm fluctuates with ship inspection policy adjustments and order changes, with no fixed cycle. Single documents mostly follow a chaptered structure, including fields such as service item number, processing time limit, required material list, and inquiry reply template. Units mostly use shipbuilding-specific measurement standards such as working days, tonnage, and meters. Some documents include multi-page technical attachments.

## What constraints these characteristics impose on model integration and configuration
The long-document structure and specialized terminology of shipbuilding service inquiry data require the model context window to accommodate long content, avoiding truncation of key specification information. Data updates have no fixed cycle, so the configuration must support rapid updating of connected model data sources to sync the latest ship inspection policies and service processes. The rigor required for service inquiries limits the model’s generation freedom, preventing misuse of specialized terminology. Additionally, the clear item numbers and classification fields in the data require the model to accurately match document content for the corresponding service scenario during recall.

## Three common configuration errors
- Issue: An error "This token is not authorized to use the model: text-embedding-3-large" is returned when calling the model. Cause: The dedicated shipbuilding scenario model access key has not been configured in FastGPT, or the key permissions do not cover the corresponding industry-specific model.
- Issue: The "no available channel" prompt still appears after configuring the bce-embedding channel. Cause: The shipbuilding-specific embedding model has not been added to FastGPT's allowed model list, or the channel configuration is not bound to the corresponding data source.
- Issue: The result reranking model option cannot be ticked when creating an application. Cause: The callable scope of the reranking model has not been correctly configured in config.js, or the configuration item format does not meet the requirements of FastGPT v4.17.0.

## How to confirm the configuration is complete
- Check that `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` are filled in consistently with the enterprise's connected model service, with no spelling or format errors.
- Submit a test request for a shipbuilding service inquiry, confirm that the returned result references the dedicated service specification documents, and verify that the context recall range meets expectations.
- Adjust the `temperature` parameter value, verify that the consistency of specialized terminology in the reply meets expectations, and confirm that the generation style is adapted to the scenario requirements.
- Trigger a tool call test, confirm that the system can automatically determine whether to query real-time service progress, and verify that the `toolChoice` configuration takes effect.
