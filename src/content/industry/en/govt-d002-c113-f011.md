# Shipbuilding Administrative Inquiry and Response: Forms and Interactions

## What Data for This Category Looks Like
Data for shipbuilding administrative inquiries and responses originates from project construction documents, inspection records, material application forms, and daily administrative inquiry ledgers. Data update timelines follow project construction milestones. Inspection records are updated on the day inspection is completed. Daily inquiries are entered immediately upon submission. Each document includes fields such as hull number, construction batch, associated drawing number, inquiry type, submitter position, and submission time. Field units include exclusive business identifiers such as meters, tons, hours, and batch numbers.

## Constraints Imposed on Forms and Interactions
Exclusive business fields require forms to preset mandatory items such as hull number and construction batch; generic form fields cannot be used as substitutes. The associated drawing number field requires forms to support attachment upload interactions, allowing submitters to synchronize relevant technical documents. Real-time updated data requires form dynamic assignment logic to be bound to the current project ID, ensuring the called knowledge base matches the inquiry scenario. Fixed business inquiry classification requires dropdown options to cover core scenarios such as inspection applications and material coordination, preventing users from entering non-standard classifications.

| Configuration Item | Recommended Setting | Rationale |

| Knowledge base binding rule | Dynamically match the exclusive knowledge base based on the current project ID | Ensure that the response content matches the construction standards and historical documents of the corresponding hull |
| Response length limit | 800–1200 characters | Match the standard single-paragraph length of shipbuilding technical documents, to facilitate business personnel to quickly obtain information |

## Three Common Misconfigurations
- Symptom: The `userSelect` AI model option dropdown is empty, and the specified model cannot be selected. Cause: Exclusive model permissions for the current shipbuilding project have not been bound in the FastGPT v4.17.0 system configuration, or the configured model version is incompatible with the current system.
- Symptom: The system returns cited content after form submission, but the citation switch is not enabled in the configuration. Cause: The knowledge base permission check logic has not been correctly configured, causing the system to call associated documents by default to generate a response, bypassing the citation switch setting.
- Symptom: The "Select Knowledge Base" global variable cannot be dynamically assigned. Cause: The project ID and knowledge base ID have not been bound as form linkage fields, making automatic matching of the corresponding knowledge base based on the current hull batch impossible.

## How to Verify Successful Configuration
- Navigate to the form editing page, verify that the fields configured in `formInput` include mandatory business items such as hull number and construction batch.
- Click the classification dropdown menu of `userSelect`, confirm that the preset shipbuilding business options have loaded correctly.
- Simulate submission of a test inquiry, verify that the system automatically matches the corresponding knowledge base based on the current project ID to generate a response.
- Review the generated response content, confirm that the length falls within the preset 800–1200 character range.
