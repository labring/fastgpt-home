# Service Consultation and Response for Shipbuilding: Deployment and Upgrade

## What this category of data looks like
Service consultation data for the shipbuilding sector mainly comes from internal enterprise service regulations, industry general inspection specification documents, production process service guidelines, and past consultation Q&A records. Data update cadence: Internal regulations are synchronized and adjusted quarterly, industry specifications are updated alongside standard iterations, and the Q&A library is optimized with monthly iterations. A single document typically includes fields such as service item name, handling entity, required material list, handling process steps, and consultation channel. Handling time limits are measured in working days, material quantity is counted in pieces, and most single documents range from 500 to 2000 characters in length.

## What constraints these characteristics impose during deployment and upgrade
The multi-source and heterogeneous nature of shipbuilding service consultation data requires that parsing rules adapted to different document formats be configured during the deployment phase. This includes structured extraction logic for regulation, specification, and Q&A files. The differences in update cadences across data types mean that synchronization tasks must be specifically configured during the upgrade phase. Quarterly updated industry specifications require monthly incremental synchronization, while the Q&A library needs to support weekly index updates. Fields include unit-related metadata, so field attributes must be retained during the vector storage stage to avoid losing key information such as handling time limits and material quantities during retrieval. The wide range of single document lengths requires adjusting the chunking logic to adapt to different lengths of document content.

## How to set the configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_ship?authSource=admin` | Used to store consultation Q&A history and vector indexes, matching the storage requirements of shipbuilding service data |
| `REDIS_URL` | `redis://:your_password@localhost:6379/0` | Used to cache retrieval results for high-frequency consultations, deploying on the same network segment can reduce latency |
| `STORAGE_S3_ENDPOINT` | `http://s3-cn-beijing.volces.com` | Used to store uploaded service regulation documents, must match the object storage access endpoint for the deployment region |
| `DB_MAX_LINK` | `1000–1500 entries` | Limits the number of associated documents returned in a single retrieval, adapting to the single-batch query requirements of shipbuilding service consultations |
| `FE_DOMAIN` | `https://fastgpt-shipyard.your-domain.com` | Configures the frontend access domain name, used for permission verification when generating share links and embedded pages |
| `ROOT_KEY` | `32-bit random string generated through actual testing` | Used for permission verification in the management backend, must match the key of the deployment environment |

## Three common configuration mistakes
- Symptom: After packaging with Docker, starting the container prompts a missing AI proxy component or database connection failure, and consultation requests cannot be processed normally. Cause: Associated parameters are not correctly configured in docker-compose.yml, or the address, port, or permission configuration of `MONGODB_URI` or `REDIS_URL` does not match the deployment environment.
- Symptom: After upgrading the version, original service regulation documents cannot be retrieved, and the retrieval results are empty. Cause: The original vector index migration or reindexing operation was not performed during the upgrade, or the `DB_MAX_LINK` parameter is configured too low, causing results to be truncated.
- Symptom: Consultation links embedded in other web pages prompt permission denied, and speech recognition functions cannot be used. Cause: The `FE_DOMAIN` parameter is not correctly configured, and the domain name of the embedded page is not added to the allow list, resulting in permission verification failure.

## How to confirm the configuration is complete
- Run the database connection test command to verify the connectivity of the `MONGODB_URI` and `REDIS_URL` configurations, ensuring normal data reading and writing.
- Upload a shipbuilding service regulation document, trigger the index generation process, and check whether the vector storage is normally generated and can be retrieved.
- Generate a consultation link embedded in an external web page, test the speech recognition and consultation functions on the corresponding page, and confirm that permission verification passes.
- Check the deployment logs to confirm that there are no configuration parameter error or data synchronization failure prompts, ensuring that all services start normally.

The values provided here are common starting points, and should be evaluated against the user’s own samples.
