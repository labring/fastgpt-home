## Constraints on Tool Calling and Plugin Workflows
This category’s data centers on individual base stations, and is associated with dimensions such as region and operation and maintenance time. Tool calls must accurately match base station IDs or regional codes to avoid returning irrelevant data. Data is updated in real time with operation and maintenance actions. Cache duration for plugin calls must be kept within a reasonable range to prevent returning outdated base station status information. The document includes multi-dimensional operation and maintenance fields. Tool calls must explicitly specify required return fields to reduce invalid data transmission. Additionally, consulting and reply work often involves fault handling processes. Plugins must connect to specific interface fields of the operation and maintenance system to ensure returned reply content complies with business standards.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios, automatically matches operation and maintenance-related plugins |
| `functionCall` | Triggered by base station ID in user questions | Accurately locates operation and maintenance data for the target base station, avoids confusion |
| Plugin Call Timeout | 300 seconds | Communication operation and maintenance data interfaces typically respond within 2 minutes, prevents interruptions to consulting due to timeout |
| Return Field Filtering | Only retain base station ID, installation location, fault processing result | Reduces redundant data, meets the concise requirements of consulting and reply work |
| Cache Duration | 60–120 seconds | Operation and maintenance data is updated in real time with patrols, overly long cache will cause information lag |

## Three Common Configuration Mistakes
- Symptom: The interface address returned when calling the operation and maintenance plugin is a public test domain name, and cannot connect to the internal system. Cause: The default interface address was not replaced in the plugin configuration, causing requests to point to non-target services.
- Symptom: Calling the data update interface via API returns a 500 status code, but accessing the interface via a browser works normally. Cause: The API call did not carry correct authentication credentials, or the request header did not match the browser’s session configuration.
- Symptom: Tool call results contain a large number of irrelevant fields that exceed the scope required for consulting and reply. Cause: No return field filtering rules were configured, and the plugin returns full operation and maintenance data by default, leading to redundant replies.

## How to Confirm Configuration Completion
- Initiate a consultation that includes a specific base station ID, and check whether the plugin return results correspond to the operation and maintenance information of the specified base station.
- Review plugin call logs to confirm the interface address matches the address of the internal operation and maintenance system, with no remaining test domain names.
- Cross-check the fields in the return results to confirm only core information required for consulting and reply is included, with no redundant fields.
- Wait a reasonable amount of time, then initiate the same consultation again, and confirm the returned operation and maintenance data is the latest updated content.
