# Matter Consulting and Response for Communication Towers and Infrastructure: Document Parsing and Chunking

## What this category of data looks like
This category of data primarily comes from communication tower operation and maintenance inspection reports, base station parameter ledgers, consulting work orders, and industry standard documents. Data update cycles vary by type: inspection reports are updated weekly or monthly, consulting work orders are generated in real time, and ledgers are synchronized quarterly. Documents include PDF-format operation and maintenance specifications, Excel-format base station parameter tables. Fields cover base station number, longitude and latitude, tower height, load power, and alarm type. Units include meters, kilowatts, and dBm. Long-text user consulting and response records are also included.

## What constraints these characteristics impose on document parsing and chunking
Base station parameter Excel documents contain multiple columns of structured fields. Generic text chunking will break the association between fields and their corresponding values. Prioritize identifying table structures before chunking. Long-text consulting records have contextual dependencies. When chunking, retain semantic coherence of adjacent conversations to avoid losing question-and-answer logic after splitting. Individual inspection reports are lengthy and may exceed file size and parsing timeout limits. Validate file size and parsing duration in advance. Significant format differences exist across document types. Adapt parsing rules for PDF, Excel, long text, and other formats.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Aligns with combinations of base station parameter fields and single-turn dialogue length of consulting records, avoids breaking semantic coherence |
| `chunkSplitter` | Paragraph + table recognition | Adapts to the paragraph structure of inspection reports and structured table data from Excel, retains field associations |
| `customPdfParse` | Enabled | Extracts charts and structured table content from PDF-format operation and maintenance specifications, preserves complete information |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Covers the common size upper limit of individual annual inspection reports, prevents upload failures |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 seconds` | Meets parsing time requirements for large-volume PDF or Excel documents, prevents mid-process timeouts |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules separately for structured documents and long text, adapts to the multi-type data characteristics of this category |

## Three common mistakes
- Symptom: After uploading an Excel-format base station parameter table, the parsing result only returns plain text with no structured fields. Cause: Table recognition chunking rules are not enabled, and the default plain text chunking logic is used.
- Symptom: The system returns a timeout error when parsing large inspection PDFs. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is lower than the actual document parsing time, and sufficient processing time is not reserved.
- Symptom: When splitting long-text consulting records, adjacent question-and-answer pairs are assigned to different chunks, leading to semantic breaks. Cause: The `chunkSize` configuration value is too small, and chunking settings adapted for dialogue context are not enabled.

## How to confirm configurations are set correctly
- Upload a single typical base station parameter Excel document, check if the parsing result retains the correspondence between fields and their corresponding values, confirm that the table recognition function is active.
- Upload a single 100 MB-sized inspection PDF document, wait for parsing to complete, confirm that no timeout error is triggered, verify that the timeout configuration is reasonable.
- Import a long-text consulting dialogue, check if the chunking result places complete question-and-answer turns in the same chunk, confirm that the chunking logic adapts to contextual requirements.
- Check the total size of uploaded files, confirm that it does not exceed the `UPLOAD_FILE_MAX_SIZE` configuration value, verify that the upload limit settings are correct.
