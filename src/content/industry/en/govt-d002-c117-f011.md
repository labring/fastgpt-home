# Service Consultation and Reply for Communication Towers and Infrastructure: Forms and Interactions

## What this category's data looks like
Data for this category mainly comes from communication tower operation and maintenance management systems, base station record approval platforms, and daily inspection logs. There are two data update rhythms: real-time inspection data is updated synchronously with on-site operations, and record-related data is updated after the approval process is completed. The structure of a single data record includes these fields: base station unique identifier, installation location longitude and latitude, operation and maintenance status, record number, and inspection time. The units for these fields are none, degrees, status code, none, and YYYY-MM-DD HH:mm:ss respectively.

## What constraints these characteristics impose on forms and interactions
The data includes a unique identifier field. This requires that when a form is submitted, the entered base station ID must be checked to avoid duplicate entry with existing data in the system. Forms for real-time updated inspection data must support real-time synchronization of the latest status. Record-related forms must be associated with approval process nodes. The multi-field structure requires forms to be displayed in three scenarios: operation and maintenance, record, and inspection. This avoids information confusion during user filling. Some fields require linked display. For example, entering a base station ID automatically loads the corresponding location information, reducing manual input costs.

## How to configure settings
This article is written based on FastGPT v4.17.0. The following are form interaction configuration suggestions for this category:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Form grouping | Split by three scenarios: operation and maintenance, record, inspection | Matches the multi-scenario structure of this category's data, reduces user filling complexity |
| User selection | Preset high-frequency options such as base station type and inspection type, support manual supplementation | Reduce manual input errors; the `userSelect` component can directly call the preset library |
| Form validation timeout | 600 seconds | Covers the complete filling cycle of large record forms, avoids mid-submission interruptions |
| Number of data items submitted in a single request | First 5 items | Matches the conventional scenario of single batch inspection report submission, reduces interface load |
| Maximum length of form text input box | 800–1200 characters | Matches the conventional description length of a single inspection record |
| Form data transfer | Configure the `formInput` parameter according to interface field mapping | Ensures that the workflow HTTP module can correctly receive form data |

## Three common misconfigurations
- Phenomenon: The interface returns a "field not found" error with status code 400 after form submission. Cause: The field mapping of the `formInput` parameter is not configured per interface requirements, leading to a mismatch between the passed parameter name and the interface receiving field.
- Phenomenon: No response is triggered for a long time after form submission, and a timeout is finally triggered. Cause: The form validation timeout setting is too short, such as 300 seconds, which cannot cover the complete filling cycle of large record forms.
- Phenomenon: When selecting an inspection type, only general options are displayed without covering core scenarios, resulting in high manual input error rates. Cause: The preset options of the `userSelect` component are not configured based on the actual inspection scenarios of this category.

## How to confirm the configuration is correct
- Fill in a test base station ID, confirm that the page automatically loads the corresponding location information, and the linked configuration takes effect.
- Submit a single test data entry, check that the interface returns status code 200, and confirm that the form validation and data synchronization logic is normal.
- Select an inspection type option, confirm that the `userSelect` component can expand normally and select preset options without loading exceptions.
- Stay on the form page for more than 600 seconds, confirm that no automatic timeout interruption is triggered, and the validation timeout configuration matches expectations.
