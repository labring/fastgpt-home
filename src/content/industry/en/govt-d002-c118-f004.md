# Workflow Orchestration for Administrative Inquiries and Responses in Metal Material Processing
This document is written based on FastGPT v4.17.0.

## What this category of data looks like
Inquiry data for metal material processing comes from four main sources: internal enterprise process specifications, national and industry standard documents, customer and internal employee inquiry ledgers, and quality inspection reports. Data update rhythms fall into three categories: real-time inquiry ledgers update synchronously with user submissions, process specifications are revised quarterly, and industry standard documents are released annually. Each individual document has a fixed structure, including fields such as inquiry ID, submission time, request type, core parameters (e.g., sheet thickness mm, yield strength MPa), response basis (national standard number, process document number), and required response time limit. Units are commonly used engineering units such as millimeters, megapascals, and tons.

## What constraints these characteristics impose on workflow orchestration
Metal material processing inquiry data contains a large number of professional engineering parameters and categorized requests. This requires the workflow to accurately match knowledge base entries corresponding to the parameters, to avoid mistakenly retrieving irrelevant content. The large differences in data update rhythms require the workflow to support scheduled synchronization of periodically updated standard documents, while also pulling the latest inquiry ledgers in real time. Documents are categorized by request type. This requires the workflow to use `variables` configuration to set classification rules, and automatically trigger the retrieval process for the corresponding knowledge base. Additionally, each inquiry has a clear response time limit requirement. This requires the workflow to configure timeout handling nodes to prevent process blocking.

## How to set the configurations
| Config Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variables (`variables`) | Preset three types of variables (qualification, process, quality inspection) based on inquiry type, and bind them to corresponding knowledge bases | Administrative inquiries in metal material processing fall into three categories. Using `variables` for classification enables accurate retrieval of matching knowledge base entries |
| Single search limit | Top 8 entries | There are many entries in professional documents. The top 8 entries cover common inquiry scenarios and avoid redundant output |
| Maximum context | 1200–1500 characters | Single segments of professional process documents are relatively long. This range avoids truncating critical engineering parameters |
| Node timeout | 300 seconds | Knowledge base retrieval for metal material processing requires matching professional parameters. This value reserves sufficient processing time |
| Tool call node (`nodeId`) | Bind the unique identifier of the knowledge base retrieval node | Ensure that after classification in the workflow, only the retrieval process of the corresponding knowledge base is triggered, avoiding invalid calls |
| Question optimization | Enabled | Colloquial inquiries can be optimized to standard terminology, improving matching accuracy |

## Three common mistakes
- Phenomenon: When the workflow calls an external application (such as opening Word to edit process documents), the node status shows execution failed, and the log returns missing parameters. Cause: The startup path parameter of the external application was not configured in `variables`, causing the target program to fail to be located during the call.
- Phenomenon: Global variables are not automatically assigned based on inquiry type, and the variable fields are empty. Cause: The trigger rule for `variables` was not configured in the process entry node, and the corresponding classification variable was not matched based on the user's inquiry content.
- Phenomenon: Two duplicate thinking processes appear when debugging the workflow. Cause: The automatic thinking logic of both question optimization and tool call nodes was enabled at the same time, causing duplicate generation of matching processes.

## How to confirm the configuration is correct
- Trigger an inquiry of the corresponding category (such as a process inquiry), check whether the retrieved knowledge base entries only include documents of that category, and verify whether the `variables` configuration takes effect.
- View the workflow execution log, confirm that the `nodeId` of the tool call node matches the target node, and there are no invalid call records.
- Simulate a timeout scenario, check whether the workflow triggers the preset timeout handling logic, and confirm that the node timeout setting meets the business time limit requirements.
- Submit a colloquial inquiry (such as "What is the hardness of this steel plate"), check whether the system automatically optimizes it to standard terminology and matches the corresponding knowledge base.
