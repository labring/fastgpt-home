# Service Consultation and Reply for Metal Material Processing: Document Parsing and Chunking

This guide applies to FastGPT v4.17.0. Below is the configuration guide for document parsing and chunking in the service consultation and reply scenario for the metal material processing industry.

## What data for this category looks like
Service consultation and reply data for the metal material processing industry primarily comes from internal enterprise process work instructions, metal material inspection reports, service guidelines, and archived customer consultation reply records.
This data is updated alongside process iterations, standard revisions, or newly added business consultations. Most documents contain structured tables such as composition proportion tables, mechanical performance parameter tables, long-form process descriptions, and standardized service workflows.
Fields include material grades, mechanical performance indicators, required material lists for services, and more. Common units are professional metrology standards including MPa, %, and mm.

## What constraints these characteristics impose on document parsing and chunking
Documents for metal material processing contain large amounts of structured tables and professional parameters. The parsing process must fully retain the field correspondence within tables, to avoid splitting parameters so they can no longer be linked to their corresponding material grades.
Long-form process descriptions and coherent service workflows require that chunking preserves contextual connections, to prevent truncation of critical operating steps or the complete logic of consultation replies.
Some documents have large file sizes. The system must support large file parsing, to avoid being unable to upload complete business materials due to file size limits. It must also adapt to professional terminology and standardized parameter formats.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the professional parameter density of metal material documents, retains the integrity of individual process or inspection data, and avoids truncating critical indicators |
| `chunkSplitter` | Separate by paragraph + table | Matches the structured characteristics of documents, retains the contextual connection between tables and their corresponding descriptions, and prevents table content from being separated from descriptive text |
| `customPdfParse` | Enable table recognition mode | Adapts to the common component tables and performance parameter tables in documents, and avoids loss or disorder of table content after parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports uploading complete large process manuals or annual inspection reports, and meets the parsing needs of full business documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers the complete parsing process for large metal material documents, and avoids interrupting parsing tasks due to timeout |
| `chunkSettingMode` | Manual configuration | For the special structure of professional domain documents, manually adjusting parameters is more suitable for business scenarios than automatic mode |

## Three common mistakes
- Symptom: After uploading a PDF document containing a composition table, the table fields in the parsing result are empty or only show partial rows. Cause: The table recognition mode of `customPdfParse` is not enabled, resulting in structured tables failing to be extracted correctly.
- Symptom: After uploading a file in a local deployment version, the parsing node shows no progress updates and no error logs. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is set too short, forcing termination before large process documents complete parsing.
- Symptom: Mechanical performance parameters for the same material grade are split into different chunks after chunking. Cause: `chunkSize` is set too small, truncating coherent paragraphs that contain complete parameter groups.

## How to confirm the configuration is correct
- Upload a test document containing a metal material composition table and process description, and check if the parsing result fully retains all rows and field information of the table.
- View the system parsing logs, and confirm that `PARSE_FILE_TIMEOUT_SECONDS` does not trigger a timeout error, and the parsing process completes normally.
- Randomly select chunking results from a long document, and check that critical process parameters and their corresponding descriptive text are not truncated.
- Upload a test document with a size close to 1000 MB, and confirm that the system does not trigger a file size limit error.

The values given are common starting points and should be measured against the reader's own samples.
