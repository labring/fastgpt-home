# Iron and Steel Smelting Service Inquiry and Reply: Workflow Orchestration
This document is written based on FastGPT v4.17.0.

## What the Data for This Category Looks Like
Iron and steel smelting service inquiry and reply data comes primarily from four sources: production process ledgers, equipment inspection records, quality dispute work orders, and online consultation sessions. Data update rhythms fall into three categories: real-time (equipment abnormal inquiries, online sessions), daily (process ledger updates), and weekly (quality statistical reports).
The document structure for a single data entry includes fields such as unique inquiry identifier, inquiry initiation time, affiliated smelting process (enumerated values like converter, continuous casting, hot rolling), inquiry content, reply content, handler, and processing duration. Processing duration is measured in minutes. Process names are fixed enumerated strings. The length of inquiry content varies widely.

## Constraints on Workflow Orchestration
Multi-source heterogeneous data requires workflow configuration to include cross-data-source pull nodes. Map fields from different systems to a unified format.
Data with different update rhythms requires distinct trigger methods. Configure real-time data to use interval polling or webhook triggers. Configure batch data to use scheduled execution.
Enumerated process fields require adding validation nodes to the workflow. Filter inquiries from non-target processes to avoid invalid processing.
Large variation in inquiry content length requires configuring context truncation rules in the workflow. Adapt the rules to inputs of different lengths.
Additionally, `variables` mapping must cover fields from all multi-source data. The node corresponding to `nodeId` must match the data update cycle to ensure accurate workflow execution.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Method | Real-time work order trigger + daily batch completion | Adapt to the update rhythms of real-time inquiries and batch ledger data |
| Variable Mapping Rule | Bind production system and work order system fields to `variables` | Unify the field format of multi-source heterogeneous data |
| Node Execution Cycle | Real-time nodes poll every 10 seconds, batch nodes execute at 2:00 daily | Match the real-time and batch data update frequencies |
| Context Truncation Threshold | 800–1200 characters | Adapt to the wide range of inquiry content lengths for iron and steel smelting |
| Field Validation Rule | Match enumerated process values such as converter, continuous casting | Filter invalid inquiries from non-target processes |
| Result Output Format | Structured output in the format of inquiry number + process + processing duration | Meet the traceability requirements for service replies |

## Three Common Configuration Mistakes
- Phenomenon: Duplicate service work orders appear after workflow execution, and logs show repeated node triggers. Cause: No termination node configured at the end of the tool call flow, causing the flow corresponding to `nodeId` to execute in a loop.
- Phenomenon: Returns a generic reply when the knowledge base is empty, failing to match the smelting process inquiry scenario. Cause: Only used a generic validator to check knowledge base status, without performing associated validation using the process field in `variables`.
- Phenomenon: HTTP custom interface call returns parameter error, with the interface returning a 400 status code. Cause: Failed to correctly map `variables` in the workflow to the input parameter fields required by the interface, causing the passed parameter format to not comply with interface specifications.

## How to Verify Correct Configuration
- Trigger a simulated converter process inquiry work order, check the workflow logs to confirm that `variables` correctly map fields from the production system and work order system.
- Enter the node execution record page, check whether real-time nodes execute every 10 seconds, and whether batch nodes trigger at 2:00 daily.
- Simulate an empty knowledge base scenario, combine with an inquiry for a specified smelting process, check whether the judgment node correctly returns the result after associated validation.
- Call the test HTTP interface, confirm that the input parameters passed by the workflow include all configured `variables` fields, and the format complies with interface requirements.
