# Iron and Steel Smelting Service Inquiry and Response: Forms and Interactions
This document is configured based on FastGPT v4.17.0.

## What the Data for This Category Looks Like
Service inquiry data for iron and steel smelting mainly comes from on-site production control systems, quality inspection ledgers, equipment maintenance logs, and industry process standard documents. The data update rhythm is divided into two categories: real-time process parameters collected on-site are updated in real time, while monthly-summarized quality inspection reports and equipment maintenance records are updated weekly. The document structure includes structured parameter forms and unstructured process manuals. Core fields include molten iron temperature, smelting cycle, raw material ratio, and equipment operating duration, with corresponding units of degrees Celsius, minutes, percentage, and hours respectively.

## Constraints Imposed on Forms and Interactions by These Data Characteristics
The data characteristics of iron and steel smelting impose multiple constraints on the forms and interactions link. Real-time collected process parameters require form controls to pull the latest data in real time, avoiding static cached old values. Core fields have fixed units, so interaction design must enforce unit prompts to prevent input values from not matching standard units. There is a need to upload long documents, so forms must support large file submissions and multi-format parsing. Fields vary significantly across different smelting processes, so interactions must support preset form templates by process to reduce repeated configuration operations.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Form input control | Use `formInput` to configure input boxes with fixed unit prompts | Core fields for iron and steel smelting have clear units, which can prevent input values from not matching standards |
| Single-choice and multiple-choice generation | Use `userSelect` to configure preset option sets by process | Inquiry scenarios vary significantly across different smelting processes, and preset options can simplify user operations |
| File upload configuration | Maximum upload size 1000 MB, supports PDF and CSV formats | Smelting-related documents are mostly long PDF process manuals and structured reports, requiring adaptation for large files |
| Real-time data synchronization | Synchronization interval set to 60 seconds | On-site process parameters change quickly, and 60 seconds ensures the timeliness of data used for inquiries |
| Input character limit | Maximum 800–1200 characters per field | Parameter descriptions for smelting inquiries usually fall within this range, avoiding overly long content that affects loading |

## Three Common Misconfigurations
- Symptom: Single-choice and multiple-choice options cannot be dynamically generated via parameters, only fixed options are displayed; Cause: The parameter data source of `userSelect` is not correctly bound, and static options are hard-coded directly.
- Symptom: Uploaded smelting process PDF files cannot be parsed normally, or the system returns a file size over limit error; Cause: The file upload rules do not support PDF format, or the uploaded file exceeds the preset maximum size limit.
- Symptom: No follow-up docking feedback is received after submitting the service inquiry form, and the background cannot match the inquiry scenario; Cause: Business-related fields are not set as required items, resulting in missing key information that prevents the allocation of processing resources.

## How to Confirm the Configuration Is Complete
- Submit a test inquiry, check whether the input control automatically displays the corresponding unit prompt.
- Upload a standard smelting process PDF, confirm that the upload process has no errors and the parsed content can match the form fields.
- Switch the preset process template, confirm that the form fields and option set are updated synchronously.
- Simulate a real-time parameter pull operation, confirm that the data update frequency meets the preset standards.
