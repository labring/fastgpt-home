# Work Consultation and Response for Expressway Operations: Tool Calling and Plugins

## What the data for this category looks like
Expressway operation consultation and response data primarily comes from real-time road network monitoring systems, 12328 transportation service hotline work orders, toll station window registration ledgers, and official road condition publishing platforms.
There are two update schedules for this data:
1.  Real-time road condition data syncs every minute
2.  Consultation work orders update in real time upon submission, while archived work orders sync in daily batches.

The document structure includes seven core fields: consultation unique identifier, desensitized user contact information, consultation content, associated road segment, handling department, handling time, and completion status.
The units for each field are: string, none (after desensitization processing), character count, road segment number, department name, YYYY-MM-DD HH:MM:SS, and boolean value.
Some consultations also include associated segmented scenario data such as ETC abnormalities and toll station opening status.

## What constraints these characteristics impose on tool calling and plugins
The above data characteristics impose three constraints on tool calling and plugin configuration:
1.  Real-time road condition data updates every minute. Set plugin call cache duration to no more than 1 minute to avoid returning outdated information.
2.  Work order data includes desensitized user information. Configure identity verification rules for plugin calls, only allowing authorized system accounts to trigger calls.
3.  Core fields include specialized terminology such as road segment numbers and completion status. Ensure function parameters for tool calls explicitly match these fields to avoid invalid results from parameter mismatches.

Additionally, consultation content may include dialect-based road condition descriptions. Plugins must support fuzzy matching of specialized keywords.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatically selecting between knowledge base calls or dedicated plugins based on user questions |
| Plugin Timeout Duration | `300-600 seconds` | Adapts to the real-time update rhythm of expressway road condition data, avoids truncating valid information due to timeout |
| `functionCall` | Trigger only when the question involves real-time road conditions or work order queries | Reduces unnecessary tool calls and lowers resource consumption |
| Context Window Size | `8000-12000 token` | Accommodates long-text historical consultation records and road condition details |
| Plugin Parameter Validation | Enabled | Verifies the validity of specialized fields such as road segment numbers and work order IDs |
| Plugin Display Name | Matches the function name defined in code | Ensures interface display names match internal system recognition names, avoids calling errors |

## Three Common Mistakes
-  Phenomenon: Tool call returns content that does not reference historical consultation records in the knowledge base, instead generates unmatched custom content. Cause: `toolChoice` is not configured for mixed call mode, only independent calls of dedicated plugins are triggered.
-  Phenomenon: Names displayed on the plugin list page and system plugin management page are inconsistent. The system plugin page shows the function name defined in code. Cause: The display name filled when creating the plugin does not match the function identifier configured in code.
-  Phenomenon: When debugging tool calls, the output includes an extra `0` field, and the content does not match the model's original response. Cause: The JSON format returned by the plugin does not strictly comply with requirements, including undefined null-value fields.

## How to Confirm the Configuration Is Correct
-  Submit test questions such as "Current congestion status of the Tianjin section of the Beijing-Shanghai Expressway" or "How to handle ETC abnormalities" to check if the corresponding dedicated plugin is called and matching real-time or archived data is returned.
-  Enter the FastGPT plugin management page, verify that the display name fully matches the function identifier defined in code.
-  View the tool call logs to confirm whether the `functionCall` parameter automatically triggers the dedicated plugin based on the question type.
-  Send a test request containing global variables to confirm that the variables are correctly substituted into the plugin's parameter configuration.

The values provided are common starting points and should be measured against the reader's own samples.
