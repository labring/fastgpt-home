# Service Inquiry and Response for Expressway Operations: Model Access and Configuration

## What the data for this category looks like
Data sources include the real-time traffic interface of the expressway operation management system, toll station toll ledgers, road network dispatching platform, and road law enforcement records.
There are three update frequency categories: real-time traffic data syncs every 5 minutes, toll operation ledgers update daily, and maintenance and law enforcement records are archived monthly.
Document structure includes structured fields and unstructured content.
Structured fields include station code, number of lanes, toll rate (unit: yuan/trip), congestion duration (unit: minute), and more.
Unstructured content includes traffic descriptions, inquiry response templates, and on-site law enforcement transcripts.

## Constraints imposed by these characteristics on model access and configuration
The high-frequency updates of real-time traffic data require a moderate model context window size. Excessively large windows cause processing delays that harm public inquiry response speeds.
Many structured fields have clear units. Configurations must retain unit mapping logic to prevent the model from confusing numerical meanings.
A large share of unstructured traffic descriptions and inquiry text requires setting appropriate token quotas. This ensures key information is not truncated during processing.
Large differences in data update rhythms require configuring batch knowledge base synchronization rules. Match these rules to the update frequencies of different data sources to prevent the model from calling outdated operation data.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Basis for This Setting |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the context length requirements of expressway operation inquiries, including multiple traffic updates, station information, and historical conversations |
| `maxTokens` | 1500–2000 token | Controls the output length of single-round responses, ensuring inquiry content is complete and does not exceed interface display limits |
| `quoteMaxToken` | 600 token | Limits the length of referenced knowledge base content, adapting to the average length of single documents such as traffic updates and toll rules |
| `temperature` | 0.2–0.4 | Reduces randomness, ensuring accurate responses for fixed information such as toll standards and station codes |
| `toolChoice` | auto | Automatically determines whether to call the knowledge base or real-time traffic interface, adapting to diverse inquiry scenarios |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployment environment | Matches the interface address of the large model in use, ensuring normal request routing |

## Three common mistakes
- Phenomenon: When calling the `ollama deepseek-r1` model, the content within the `<think></think>` tags in the output is empty. Reason: The model's thinking generation logic was not triggered correctly, or FastGPT's model adaptation configuration does not match the model's output format.
- Phenomenon: No search results appear when testing after connecting to SearXNG, and an error appears in the background. Reason: `AIPROXY_API_ENDPOINT` was not correctly configured to point to an available SearXNG instance, or the network access permissions of the instance were not enabled.
- Phenomenon: An error occurs when the model is called after uploading a toll rule file. Reason: `maxContext` was not correctly set to adapt to chunk processing of large files, or the file format does not match the import types supported by FastGPT.

## How to confirm the configuration is complete
- Initiate an inquiry that includes a specific toll station code, and verify that the station information returned by the model matches the latest ledger data.
- Simulate high-frequency traffic inquiries, and check that the response time meets business requirements with no obvious delays.
- View the model call logs to confirm that identity authentication was passed, and there are no interface error messages.
- Upload the latest maintenance record file, and verify that the model can correctly extract the structured field information from it.
