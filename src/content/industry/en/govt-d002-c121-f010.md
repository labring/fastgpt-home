# Service Consultation and Response for Expressway Operations: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Knowledge base data for expressway operations comes from five core sources: toll settlement systems, road network monitoring platforms, road administration inspection work orders, official service guideline repositories, and archived customer service inquiries.
Update frequency follows three categories:
- Real-time traffic conditions and emergency response information are synced hourly
- Toll standards and service process documents are updated quarterly or for temporary policies
- Customer service work order data is added to the repository via daily incremental updates
Document structures include both structured fields (such as road segment numbers, event times, processing statuses) and unstructured text (such as traffic condition descriptions, handling steps). Field units include kilometers, hours, yuan, items, and other standard units.

## Constraints on the knowledge base retrieval and recall link
Multi-source, heterogeneous data sources require retrieval systems to support cross-dataset aggregated retrieval. This prevents missing consultation answers from different business lines.
Differentiated update frequencies require configuring incremental synchronization time windows. This ensures a reasonable ratio of real-time information to static documents in recall results.
Mixed structured and unstructured document structures require retrieval logic that supports both keyword matching and semantic matching. This balances precise matching for fields like road segment numbers and toll standards, and fuzzy matching for text content such as traffic descriptions and handling processes.
Most expressway consultations involve real-time traffic conditions and emergency responses, which have strict timeliness requirements for recall results. The update time range of recalled documents must be restricted.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the accuracy requirements for expressway consultations, filters out redundant recall results with mismatched road segments |
| `limit` | Top 8 entries | Covers multi-scenario answers for common consultations, while controlling context length to stay within model input limits |
| `searchMode` | hybrid | Combines keyword and semantic retrieval, adapts to mixed consultation scenarios such as traffic conditions and service processes |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, prioritizes documents strongly related to consultation content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands consultation terms. For example, expanding "ETC handling" to "electronic toll collection system handling procedures" to cover more relevant documents |
| `collectionIds` | Bind three dedicated dataset IDs for road administration, toll collection, and customer service | Only retrieves documents from corresponding business lines, avoids irrelevant cross-category content interfering with recall results |

## Three Common Misconfigurations
- Issue: An `Invalid URL, code: 500` error is returned when uploading expressway knowledge base files via the `apiCollection` interface. Cause: The `collectionIds` parameter is not configured correctly, causing the system to fail to locate the storage path of the corresponding business dataset.
- Issue: Knowledge base recall results only match the main chunk content, and do not use auxiliary field information. Cause: Metadata-based matching logic is not enabled, ignoring weight bonuses for auxiliary data such as road segment numbers and consultation categories.
- Issue: External reference links from knowledge base documents remain in reply content. Cause: The reference tracing switch is not disabled in the retrieval configuration, causing external links from original documents to be included in reply content.

## How to Confirm Configurations Are Correct
- Submit a test consultation, for example "G5 Beijing-Kunming Expressway Chengdu section today's congestion status", and check whether the recall results include real-time information for the corresponding road segment.
- View retrieval logs, confirm that the `similarity` parameter's matching threshold is active, and that the similarity scores of recall results fall within the preset range.
- Check the final reply content, confirm that no external reference links from knowledge base documents are included, and only core reply text is retained.
- Call the interface to verify the `collectionIds` parameter, confirm that only documents from the specified business lines are retrieved, and no irrelevant cross-category content appears.
