# 12345 Citizen Hotline Work Order Processing Ledger Summary and Report Generation: Document Parsing and Chunking

## What This Category of Data Looks Like
The data for the 12345 citizen hotline work order processing category comes from the 12345 hotline platform, work order undertaking unit business systems, return visit and evaluation data, and local hotline management-related documents. Daily processed documents include appeal registration forms, dispatch records, handling responses, return visit records, extension applications, return explanations, and knowledge base entries. Data is updated daily. Core fields include appeal number, citizen appeal content, undertaking unit, handling progress, and return visit evaluation result. Document structures vary: some ledger documents aggregate multiple days of work order information in table form, while individual work order documents are plain text records.

## Constraints on Document Parsing and Chunking
Since data is updated daily and must support ledger summary and report generation, the parsing process must ensure efficient batch processing of work orders. Delays must be avoided to prevent disruptions to subsequent ledger generation and work order closed-loop processing. Work order documents have wide structural differences, ranging from plain text single appeal records to multi-day summary ledgers with tables. When chunking, business logical connections must be preserved. Splitting documents must not break the correspondence between appeals and their handling progress. The integrity of core fields directly affects the accuracy of subsequent ledger statistics. Improper chunking that splits fields across multiple chunks will cause data missing during summary. Some documents contain images or complex layouts. The parsing process must support these formats, otherwise parsing failures or information loss will occur.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field length of work order documents and the coherence of business context, avoiding loss of correspondence between appeals and handling links after splitting |
| `chunkSplitter` | Chunk by paragraph + title | Work order documents have hierarchical structures such as appeal titles and handling nodes; splitting by title preserves the integrity of business logic |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses network latency and content loading time during bulk import of work order ledgers, to avoid parsing process interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to daily exported bulk work order summary documents and attachment materials, meeting the file scale requirements for daily ledger imports |
| `customPdfParse` | Enabled | Processes work order exported PDFs with forms, tables or images, preserving original layout and field correspondence |

## Three Common Configuration Mistakes
- Parsing fails after uploading a docx work order document containing images, returning an `Invalid image file` error. The cause is that the image compatibility configuration of `customPdfParse` is not enabled, or the uploaded image format exceeds the platform's supported range.
- Some data is not captured during bulk import of work order ledgers. The cause is that `chunkSize` is set too small, causing associated information to be lost after long fields are split, or parsing time exceeds the `PARSE_FILE_TIMEOUT_SECONDS` setting value, leading to process interruption.
- The Markdown work order table content output by the model is truncated. The cause is that `chunkSize` does not match the table content length, or the complete table structure is not preserved during chunking, causing content to be split and truncated.

## How to Verify Proper Configuration
- Upload a single docx work order document with tables and images. Check if the parsing result retains the table layout and image placeholder information.
- Bulk import 10 work order ledgers from consecutive dates. Verify that the number of parsed documents matches the number of imported documents.
- Check the parsing logs of FastGPT v4.17.0. Confirm there are no `slow operation` errors, and that single parsing time does not exceed the `PARSE_FILE_TIMEOUT_SECONDS` setting value.
- Extract the chunked content. Check if core fields such as appeal number and undertaking unit are completely retained in the same chunk.

The values listed above are common starting points, and should be evaluated against the user's own samples.
