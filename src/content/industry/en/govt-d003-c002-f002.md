# Joint "One Thing Done Efficiently" Initiative: Ledger Summary and Report Generation – Vector Models and Indexing

## What this category of data entails
Typical data sources for this category include the national government service platform’s "One Thing" special zone, local integrated government service platforms, electronic certificate repositories, and approval systems of various departments. Daily processed documents cover joint work item lists, one-time notice sheets, joint application forms, material transfer forms, parallel approval opinions, completion receipts, and other related materials, with data updated daily. Document fields include associated departments for items, material lists, processing status, transfer nodes, and other details. Document structures have minor differences across departments, and some data requires cross-source association and matching.

## What constraints do these characteristics impose on the vector models and indexing workflow
Daily updated data requires indexes to support incremental updates, avoiding performance losses caused by full rebuilds. Large structural differences across departmental documents require flexible chunking strategies to adapt to content of varying lengths. Accurate vector similarity calculation is needed for association matching of cross-departmental items, to prevent mismatching of similar but unrelated joint work items. Ledger summary requires complete extraction of approval opinions and transfer records from each stage; index construction must retain the full context of original documents to avoid loss of critical information.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the paragraph length of joint work documents, avoid splitting content that links cross-departmental items |
| Overlap Length | 100–150 characters | Retain cross-chunk item transfer association information, prevent context breakage after splitting |
| Similarity Threshold | 0.75–0.85 | Meet the precise matching needs for distinguishing cross-departmental similar items, adapt to association retrieval for joint work items |
| Single Search Limit | Top 10 results | Cover the volume of multi-departmental associated data involved in joint work, meet the full association needs for ledger summary |
| `defaultToken` | 8192 | Adapt to the long-text context requirements of joint work ledger summary, support integration of multi-stage content |
| `maxToken` | 16384 | Meet vector processing requirements for long content such as cross-departmental approval opinions and completion receipts |

## Three Common Misconfigurations
- Exported ledger dataset only contains the index field, no content field: The exported dataset.csv file only includes index identification fields, with no main body content of original documents. The cause is that the chunking configuration failed to correctly associate the content field of the original document, and index construction did not extract main body content from joint application forms and material transfer forms during the indexing process.
- Number of vector search results does not match expectations: After entering a cross-departmental item association query, the number of returned results is lower than expected. The cause is that the single search limit configuration is set too low, failing to cover the multi-source data volume of cross-departmental parallel approval, or the similarity threshold is set too strictly, filtering out valid associated results.
- Index update timeout: Incremental index task execution fails, with timeout errors appearing in logs. The cause is that incremental index configuration is not enabled, and full update of daily updated joint work data exceeds the context processing limit set by the `defaultToken` configuration.

## How to Confirm Proper Configuration
- Import a test joint work item list document, perform vector index construction, and check whether the index logs include extraction records of the content field.
- Enter a cross-departmental item association query, verify that the search results include associated content such as approval opinions and completion receipts from the corresponding departments.
- Access the index management interface of FastGPT v4.17.0, confirm that incremental update tasks are triggered daily with no failed logs.
- Test exporting dataset.csv, confirm that the file contains both index and content fields, and the content matches the main body content of the original documents.

The values listed above are common starting points and should be evaluated against your own specific samples.
