# "One Task Completed Efficiently" Joint Handling Ledger Summary and Report Generation: Tool Calling and Plugins

## What the Data for This Category Looks Like
This category of data mainly comes from the "One Task" special zone of the National Government Service Platform, local integrated government service platforms, electronic certificate repositories, and approval systems of various departments. The update frequency is daily. Commonly used documents include joint handling item lists, one-time notification sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts. Data fields include cross-departmental item association identifiers, application material details, handling status for each stage, promised completion time limits, and more. Field units are typically item numbers, material quantities, and date types.

## Constraints Imposed by These Characteristics on the Tool Calling and Plugins Link
Under normal circumstances, the data for this category is scattered across multiple departmental systems. Tool calling must adapt to the authentication rules of different platforms to avoid being unable to pull data due to insufficient permissions. The daily update frequency requires that the tool calling trigger rhythm matches the data synchronization cycle, otherwise expired data will be used. The structure of different types of joint handling documents varies greatly, so plugins must support dynamic adaptation of field parsing logic, and fixed templates cannot be used universally. Associated data of cross-departmental items needs to pass context between tools to ensure consistent parameters for each link's call. If a tool call exception occurs, it may cause joint handling item stagnation, repeated material submission by the public, or failure to meet promised completion time limits.

This document applies to FastGPT v4.17.0.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to the need for on-demand calling of multiple tools in joint handling scenarios, no need to manually specify each stage |
| `functionCall` | `required` | Forces tool calling to ensure that the ledger summary stage must call external data interfaces, avoiding reliance on expired cached data |
| Single tool call timeout | 600 seconds | Response delays of cross-departmental approval systems are generally high; this duration covers most normal response scenarios |
| Maximum plugin call batches | First 8 entries | Joint handling items usually involve no more than 8 collaborating departments; limiting batches prevents excessive resource usage |
| Context retention length | 800–1200 characters | Core associated information of joint handling items must be retained; this range covers the key data volume for cross-departmental circulation |
| Plugin exception retry count | 3 times | Cross-departmental interfaces have occasional fluctuations; 3 retries can resolve temporary exceptions without affecting the overall process |

## Three Common Misconfigurations
- After deployment, tool calling fails to pull departmental data normally, with a prompt that the MCP service was not found. The cause is that the MCP server was not configured as a transit node for tool calling, or the departmental system was not connected to the MCP service.
- When calling the `api/v1/chat/completions` interface, a cross-origin error is returned, causing the front-end request to fail. The cause is that the back-end was not configured with allowed cross-origin request headers, and the specified request sources and request methods were not permitted.
- After tool calling, the `chat：llm—model—response-empty` error is returned, interrupting the workflow. The cause is that the `functionCall` parameter was not configured correctly, causing the model to return an empty response directly without triggering tool calling.

## How to Verify Correct Configuration
- View the tool calling logs to confirm that each joint handling item processing triggers the interface calls of the corresponding departments, with no omissions.
- Simulate a cross-departmental interface request to verify whether the back-end allows cross-origin access from the specified source, in line with the configuration requirements.
- Test the retry logic in exception scenarios to confirm that the tool call automatically retries according to the configured number of retries after a failure.
- Check the retained context content to confirm that it includes the core associated information of the joint handling items, and no key fields are missing.

The values provided are common starting points and should be measured against the reader's own samples.
