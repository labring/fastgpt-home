# Real Estate Registration Ledger Aggregation and Report Generation: Tool Calling and Plugins

## Data Overview
Real estate registration related data comes from the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate repository. The update frequency is daily. Daily processed documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and registration books. Core fields cover real estate location, right type, right holder information, registration type, and more. Units include square meters, parcel count, and others. The data structure changes based on registration business types, requiring multi-source information alignment across systems.

## Constraints for Tool Calling and Plugins
Multi-system data sources require plugins to support calling interfaces for multiple business systems. The daily update frequency requires plugin calls to adapt to real-time data pulling rhythms, avoiding delayed data synchronization caused by timeouts. Multiple document types and professional fields require plugin returned information to strictly align with mandatory fields of registration businesses, avoiding missing core verification content. For business attributes with severe error consequences, add result verification and retry mechanisms in the tool calling link. This ensures data accuracy and prevents registration errors or property right disputes.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | auto | Adapt to multi-source data calls for different business plugins, no need to manually specify a single tool |
| Plugin call timeout | 600 seconds | Address cross-system data pulling delays, avoid task interruption mid-execution |
| Number of returned entries per plugin call | First 3 entries | Match the core data volume of a single real estate registration business, reduce redundant information interference |
| `functionCall` | Enabled | Force the model to call plugins in standard format, ensure ledger field alignment with specifications |
| Number of retries for failed plugin execution | 2 times | Address temporary cross-system connection fluctuations, ensure successful task completion |
| Result verification trigger condition | Mandatory field completeness | Ensure generated reports include all mandatory real estate registration information |

## Three Common Mistakes
- Symptom: The plugin editing interface always displays an "Unsaved" status, and does not return to normal after clicking the save button. Cause: Mandatory configuration items on the interface have not been completed, causing the save verification to fail and the status to not update synchronously.
- Symptom: The interface call returns the `connect ECONNREFUSED 172.23.0.2:3001` error. Cause: The target plugin service is not running normally, or network policies restrict cross-service communication.
- Symptom: The generated ledger report is missing the ownership source verification field. Cause: `functionCall` forced format calling is not enabled, the model does not correctly call the ownership data verification plugin, leading to missing core fields.

## How to Verify Correct Configuration
- Enter the plugin management page of FastGPT v4.17.0, verify that all configuration item values match the preset settings, and check the switch status of `toolChoice` and `functionCall`.
- Initiate a test call for a single real estate registration business, confirm that the number of plugin returned entries matches the configured single return limit.
- Simulate a cross-system data delay scenario, verify that the plugin call timeout setting takes effect, and the task triggers a retry or interruption within the set duration.
- Check the generated ledger report, confirm that all preset mandatory real estate registration fields are included with no omissions.
