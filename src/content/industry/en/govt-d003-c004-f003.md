# Ledger Aggregation and Report Generation for Proactive Public Disclosure and Policy Release: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Data sources for this category include government websites, document management systems, government information disclosure directories, policy document repositories, and press conference materials. Daily documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Data is updated daily. Document fields include public attribution, confidentiality review status, release deadline, corresponding website column, new media account affiliation, and more. The overall structure mixes structured forms and unstructured text.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Daily high-frequency updates require the dialogue flow to support incremental data synchronization and avoid reprocessing historical documents. Mixed-structure documents require prompts to distinguish processing logic between structured approval forms and unstructured policy text. Accuracy requirements for public attribution and confidentiality review fields mandate step-by-step verification of key information during multi-turn dialogue to prevent accidental public disclosure. Synchronization across multiple sites and new media accounts requires prompts to clearly associate corresponding release channels to avoid configuration errors.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 token, calibrated via actual testing | Adapts to the mixed text length of policy documents and approval forms |
| `variables` bound fields | Public attribution, confidentiality review status, release column | Identifies core business fields that require verification during multi-turn dialogue |
| `messages` history truncation threshold | Retain the most recent 10 conversation turns | Prevents model confusion caused by overly long context |
| Knowledge Base Recall Limit | Top 8 results | Matches daily updated document volume and retrieval accuracy |
| `chatId` session isolation rule | Bind by release batch | Ensures unified conversation context for documents in the same release batch |
| Prompt Template Update Frequency | Daily synchronization | Adapts to newly added policy documents and release requirements for the current day |

## Three Common Misconfigurations
- Phenomenon: Conversation logs are not automatically cleaned, occupying storage space. Cause: No session auto-expiration rule is configured, leading to accumulated historical `messages` exceeding context limits.
- Phenomenon: Debug preview works correctly but the knowledge base is not selected in the production environment. Cause: The production environment is not bound to the corresponding public directory and policy document repository data sources, or `variables` fields are not mapped correctly.
- Phenomenon: Ledger fields generated after multi-turn dialogue are missing. Cause: The prompt does not explicitly require verification of core fields such as public attribution and confidentiality review status, and does not use multi-turn questioning to supplement missing information.

## How to Verify Proper Configuration
- Submit a newly added policy document from the current day for testing, check whether the corresponding public directory and approval form information is automatically associated during the conversation.
- View the conversation context, confirm that only the most recent specified number of `messages` are retained, with no redundant historical conversations.
- Trigger a ledger generation task, check whether the output result includes preset fields such as public attribution and confidentiality review status.
- Verify the session isolation rule, confirm that conversation contexts from different release batches do not interfere with each other.

The values provided are common starting points and should be measured against the reader's own samples.
