# Ledger Summary and Report Generation for Proactive Public Disclosure and Policy Publishing: Document Parsing and Chunking

## What this category of data looks like
This category of data primarily comes from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials, with a daily update frequency. Daily processed documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Most documents contain fields such as issuing authority, document number, release date, disclosure attribute, and column affiliation. Some interpretation drafts include additional image and text materials.

## Constraints on the document parsing and chunking workflow
Daily batch-updated documents require parsing processes to support batch processing, preventing excessive per-file parsing time from impacting overall efficiency. The range of supported document types includes plain text files and policy interpretation drafts with embedded images and text, so parsing configurations must adapt to multiple formats while extracting both text and image-related content. It is necessary to accurately extract key fields such as disclosure attribute, document number, and release date. During chunking, retain the contextual link between each field and its associated content, to ensure accurate information association during subsequent ledger summary. The requirement for cross-platform simultaneous publishing also means chunking results must support quick categorization by column and release time, to simplify subsequent report generation.

## How to configure settings
This document applies to the document parsing and chunking functions of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Matches the typical paragraph length of policy documents and interpretation drafts, preserves the connection between key fields and their context, and prevents core information such as document numbers and release dates from being split across multiple chunks |
| `chunkSplitter` | Split by paragraph + heading | Aligns with the hierarchical structure of policy documents, splitting content by chapter and paragraph to enable easy categorization and summary by column and release time later on |
| `customPdfParse` | Enable structured parsing | For PDF-format policy documents, extracts text and embedded fields, avoiding loss of formatting and critical information that can occur with plain text-only parsing |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Supports batch uploads of policy documents, press releases and other standard documents, meeting daily batch processing file size limits |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Accommodates the longer parsing time required for policy interpretation drafts with images, preventing timeout interruptions during batch processing |
| `chunkSettingMode` | Manual configuration | Adapts to the varying needs of different document types, allowing adjustment of chunking parameters for shorter documents such as public disclosure directories and approval forms |

## Three common configuration errors
- Parsing results are empty or return errors after uploading an image address. This happens when adaptation parameters for image parsing are not configured, or when image links in the document have restricted access permissions that prevent the system from pulling and parsing them normally.
- Timeout errors occur during batch uploads of policy documents. This is caused by a value for `PARSE_FILE_TIMEOUT_SECONDS` that is too short, failing to match the parsing time required for policy interpretation drafts with embedded images.
- Unable to link document numbers to their corresponding policy content during ledger summary. This occurs when `chunkSize` is set too small, splitting content from a single document number across multiple chunks and breaking contextual association.

## How to confirm the configuration is correct
- Upload a single policy document PDF, review the parsed text structure, and confirm that headings, paragraphs, and core fields are fully extracted.
- After setting `chunkSize`, manually split a section of policy text to verify that chunk lengths fall within the configured range.
- Upload a batch of documents, check the status of parsing tasks, and confirm that no batch processing timeout issues occur.
- Call the corresponding API interface, verify the transmission format of image parsing parameters, and confirm that parsing results include image-related content.

The values provided here are common starting points and should be measured against the reader's own samples.
