# Ledger Summary and Report Generation for Property Rights, Asset and State-owned Capital Management: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data draws from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, valuation institution reports, and financial statements. Updates occur on a monthly basis. Daily documents include property rights registration forms, asset evaluation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval documents. Documents fall into two groups: structured forms and unstructured reports. Fields cover asset ownership numbers, book original values, evaluation values, transaction consideration, approval node status, and more. No unified fixed format exists, so identification must be conducted separately by document type.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Monthly data updates require multi-turn dialogue to limit the time range to the current review cycle. This prevents cross-period data from interfering with summary results. Mixed structured and unstructured document types require prompts to distinguish extraction rules for different document types. This ensures accuracy of field extraction. Multiple data sources require clear priority setting in dialogue. Official data from state-owned assets supervision systems and property rights exchange systems takes priority. The fixed list of business fields requires prompts to include clear extraction items. This stops omission of key compliance information.

## Configuration Settings
The following configurations follow the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current state-owned assets project | Ensure multi-turn dialogue is associated with the same ledger project to avoid context confusion |
| `messages` | Limit to only include the context of current monthly ledger data | Match the monthly update frequency and filter cross-period invalid data |
| `variables` | Inject asset ownership field list and data source priority rules | Correspond to the fixed document fields and data source requirements of this category |
| Conversation history retention rounds | Keep the first 8 rounds of conversation content | Balance context completeness and response speed |
| Result output format | Structured table format | Adapt to the standardized output requirements of ledger summary |
| Data source filtering rules | Only call data from state-owned assets supervision systems and property rights exchange systems | Comply with the data source priority requirements of this category |

## Three Common Mistakes
- Calling the API to delete conversation records returns no response or a 400 status code. Cause: The `chatId` parameter is not correctly bound, so the system cannot locate the target conversation entry.
- Uploading Feishu online documents results in parsing failure and returns empty content. Cause: Data source access permissions are not configured, or the prompt does not clearly specify parsing format requirements for Feishu documents.
- The ledger result output after multi-turn dialogue lacks the asset ownership number field. Cause: The complete property rights and asset field list is not injected into `variables`, causing the prompt to omit key extraction items.

## How to Confirm Configuration Is Complete
- Initiate a test dialogue, enter the specified asset query instruction, and verify that the returned result includes the fields defined in the preset `variables`.
- Call the conversation deletion interface, pass the known `chatId`, and confirm the interface returns a successful status.
- Upload a Feishu online document for testing, and verify that parsed content is correctly extracted and added to the context.
- Initiate multi-turn dialogue, confirm that each interaction’s context links to the same `chatId`, with no cross-project data confusion.
