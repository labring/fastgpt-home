# Ledger Aggregation and Report Generation for Property Rights, Asset and State-owned Capital Management: Database and Operations

## Data characteristics for this category
Data for this category primarily originates from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, assessment agency reports, and financial statements. Daily processed documents include property rights registration forms, asset evaluation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval documents.
Data updates occur monthly. Individual document sizes vary widely; some evaluation reports or batch ledger files can reach tens of megabytes.
Data fields include asset ownership number, affiliated entity, evaluation benchmark value, transaction approval status, and more. Multiple units such as currency, area, and quantity are used.

## Constraints on the database and operations link
Monthly batch data updates require databases to support efficient batch import and incremental synchronization mechanisms, avoiding overly long single processing times.
Multi-source heterogeneous data from different systems demands adaptive mixed storage and parsing of structured data and unstructured documents.
Single documents up to tens of megabytes increase load on parsing and database write links. Configuring reasonable resource thresholds prevents service blocking.
Differences in units and formats across fields require unified verification at the database layer to ensure consistency of imported data.
The rigor of state-owned assets data requires databases to support transaction rollback and fine-grained permission control, preventing abnormal data changes.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `PG_URL` | Domestic relational database connection string compatible with domestic technology standards | Meets domestic replacement requirements, stores structured asset ledger data |
| `MONGODB_URI` | Domestic document database connection string compatible with domestic technology standards | Stores unstructured files such as asset evaluation reports and transaction announcements |
| `DB_MAX_LINK` | `80–120` | Adapts to concurrent requests for monthly batch data import, avoids exhausting database connections |
| `REDIS_URL` | Domestic in-memory database connection string compatible with domestic technology standards | Caches parsed document metadata to improve batch processing efficiency |

## Three common misconfigurations
- Uploading a tens-of-megabyte asset evaluation report PDF triggers the prompt `timeout of 360000ms exceeded`. This occurs because the timeout threshold for parsing and database writing for large-volume documents is not adjusted, causing single processing time to exceed the preset limit.
- Configurations that omit domestic database connection strings fail compliance checks and block data import. This happens because open-source or foreign database components are not replaced per scenario requirements, violating domestic technology usage specifications.
- Batch import of monthly ledgers fails due to exhausted database connections. This stems from failure to adjust the `DB_MAX_LINK` configuration, with concurrent requests exceeding the database's maximum carrying limit.

## How to confirm successful configuration
- Use FastGPT v4.17.0 to test importing a single tens-of-megabyte asset evaluation report PDF, then check if parsed data is successfully written to the database.
- Execute a batch data import task, monitor database connection status, and confirm the number of connections does not exceed the configured upper limit.
- Verify the availability of the domestic database connection string, then confirm that state-owned asset-related ledger data can be read and written normally.
- Check database permission configurations, then confirm that only authorized personnel can access asset data, meeting compliance requirements.
