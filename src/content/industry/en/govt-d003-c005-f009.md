# Ledger Consolidation and Report Generation for Property Rights, Asset and State-owned Capital Management: Model Access and Configuration

## What this category of data looks like
This category of data mainly comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, evaluation agency reports and financial statements. Commonly processed documents include property rights registration forms, asset evaluation reports, property rights transfer plans, on-site transaction announcements, asset disposal approval documents. These documents contain fields such as asset number, ownership subject, evaluation value, transaction status. Units involved include currency, area, quantity, etc. Data updates occur monthly. It is necessary to integrate stock assets and transaction data across cycles from multiple systems.

## What constraints these characteristics impose on the model access and configuration link
This category of data has multiple sources and inconsistent formats. Configure context processing logic adapted to multiple document types to avoid parsing failures caused by format incompatibility. The monthly batch update feature requires parameters that support large-batch data processing, to prevent single-processing timeouts. Asset ownership and transaction data have complex fields. Limit a reasonable context length to ensure the model accurately extracts core information. Data processing errors will cause serious consequences. Configure a complete failure retry and verification mechanism.

## How to set configurations
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapt to the context length after splicing multiple documents in this category, to avoid exceeding the model's carrying limit |
| `maxTokens` | 4000 token | Match the core content output length of property rights and asset reports, to ensure complete generation of consolidated reports |
| `quoteMaxToken` | 2000 token | Limit the fragment length of referenced source documents, to ensure relevance between referenced content and core tasks |
| `temperature` | 0.2–0.4 | Reduce generation randomness, to ensure ledger consolidation and report formats and content comply with state-owned assets management specifications |
| `AIPROXY_API_ENDPOINT` | Fill in the address provided by the connected model service provider | Configure the interface address for model calls, to ensure network connectivity with the deployment environment |
| `AIPROXY_API_TOKEN` | Fill in the key generated by the service provider | Used for identity verification, to ensure the security of model calls |

## Three common misconfigurations
- Incorrect interface address when configuring `AIPROXY_API_ENDPOINT`, leading to timeout errors during testing. The cause is failure to verify network connectivity between the interface address and the deployment environment, or failure to correctly configure proxy rules.
- Tasks get stuck after enabling `text-embedding-3-large` as the indexing model. The cause is failure to adjust `maxContext` to adapt to the input length limit of this model, resulting in context overflow without triggering a clear error message.
- The `Question is empty` error occurs when directly passing the String type result output from a code block to the model. The cause is failure to perform format verification on the result, with remaining newline characters or special characters preventing the model from recognizing valid question content.

## How to confirm successful configuration
- Call the configured interface, pass in a single property rights registration form document, and check that the interface returns a 200 status code.
- Submit batch monthly asset data, observe that task execution duration meets expectations, with no long-time unresponsive situations.
- Generate a ledger consolidation report, verify that asset fields extracted in the report match the content of source documents.
- Simulate an interface call failure scenario, check whether the system triggers the retry mechanism as configured.
