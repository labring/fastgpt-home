# Ledger Aggregation and Report Generation for Property Rights, Asset and State-owned Capital Management: Deployment and Upgrade

## What this category of data looks like
Data sources include state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, evaluation agency reports, and financial statements. Daily documents include property rights registration forms, asset evaluation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval forms. Update frequency is monthly. Data fields include asset ownership identifiers, evaluation benchmark information, transaction approval nodes, and others. Field names and units follow the specifications of corresponding business documents. No unified mandatory format requirements apply. Structural differences across multiple document types must be adapted to.

## What constraints do these characteristics impose during deployment and upgrade
This category of data is multi-source and heterogeneous, sourced from multiple independent business systems. During deployment, multi-source data docking rules and format conversion logic must be adapted to. The monthly batch update feature requires configuration of reasonable batch import concurrency thresholds during deployment to avoid system overload or timeouts. Daily documents include two format types: structured forms and unstructured reports. Corresponding parsing rules must be preset to ensure data extraction accuracy. Data errors can lead to serious consequences such as state-owned asset loss and transaction suspension. During deployment, trigger conditions for data verification and exception alerts must be configured to intercept invalid data in advance.

## Three Common Misconfigurations
- Symptom: After calling the API to upload files such as asset disposal approval forms, the agent backend process freezes and cannot respond to subsequent requests. Cause: Access permission verification for `FILE_TOKEN_KEY` is not configured, causing illegal files to occupy system storage and computing resources.
- Symptom: After deploying with docker-compose, the workflow and knowledge base modules on the frontend page display blank, but backend interfaces can be called normally. Cause: The `FE_DOMAIN` parameter is not configured correctly, causing frontend resources to fail to correctly associate with the backend service address.
- Symptom: The knowledge base cannot load embedded images in asset evaluation reports, and no corresponding images are displayed in search results. Cause: The local storage path rule for `STORAGE_S3_ENDPOINT` is not configured, causing image files to fail to be read and returned normally.

## How to Confirm Configurations Are Complete
- Log in to the backend management panel, check database connection usage, confirm that the actual connection count does not exceed the `DB_MAX_LINK` configuration value.
- Upload a standard document within this category, check if parsed fields match preset verification rules.
- Access the frontend service address, verify that document images in the knowledge base can load and display normally.
- Manually trigger a batch import task, confirm that there are no abnormal interruptions or process freezes during task execution.
