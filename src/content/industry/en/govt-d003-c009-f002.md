# Public Data Catalog and Publishing: Ledger Summary and Report Generation - Vector Models and Indexing

## Data Profile for This Category
Data for this category primarily comes from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Data updates occur once per month. Commonly processed documents include public data resource catalogs, data publishing lists, data item descriptions, anonymization rules, interface documentation, and update frequency descriptions. Fields include data item names, affiliated departments, publishing conditions, anonymization methods, interface addresses, update cycles, and similar attributes. Most content consists of structured data and technical documentation.

## Constraints Imposed on Vector Models and Indexing
Monthly batch data updates require indexing to support incremental synchronization and full reconstruction, to avoid reprocessing full historical data. Mixed content of structured fields and technical documents requires adapting chunking logic for varying text lengths, to prevent splitting critical information such as interface addresses and anonymization rules. Data sources are scattered, and authorization boundaries must be strictly controlled. When building indexes, authorization attributes of data items must be associated to prevent unauthorized data from being retrieved. Additionally, downstream requirements for ledger summary and report generation mandate that index recall results accurately match the publishing conditions of data items, to avoid returning non-compliant content.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the mixed text length of public data catalogs and interface documentation, avoids splitting critical technical fields |
| Overlap Length | 50–80 characters | Retains critical information such as interface addresses and anonymization rules across chunks, prevents context breaks |
| Similarity Threshold | 0.75–0.85 | Meets the precise retrieval requirements for public data items, filters low-correlation non-target data items |
| Single Search Limit | Top 10 entries | Adapts to the bulk data sorting needs of ledger summaries, controls the number of results returned per recall round |
| `defaultToken` | 8192 | Adapts to context processing for long documents, meets input requirements for interface documentation and complete data item descriptions |
| `maxToken` | 16384 | Supports context stitching for large-batch ledger summaries, avoids truncating critical summary logic |

## Three Common Configuration Errors
- When attempting to migrate old vector library data after upgrading to a new version, the system prompts that the format is incompatible and import fails. The cause is that the storage structure of the new version’s index differs from older versions, and no data mapping rules were configured in advance to complete format conversion.
- After configuring a voyage index and sending a retrieval request, a 400 status code is returned with no content. The cause is that the model access key and request parameters were not configured correctly, resulting in an invalid interface request.
- After executing a full index reconstruction task, server read and write resources remain continuously occupied, and processes are forcibly terminated daily. The cause is that no concurrency limit for chunk processing or resource threshold for single tasks was set, and processing the full monthly update batch data exceeds server carrying capacity.

## How to Verify Successful Configuration
- Manually upload a typical public data catalog document, execute index construction, and check if chunked text fully retains critical information such as interface addresses and anonymization rules.
- Initiate a retrieval test, input keywords for data item names, and verify that the number and fields of recall results match the preset single search limit.
- Execute an incremental index synchronization, verify that newly added data from monthly updates is successfully written to the index, with no duplicates or omissions.
- View the system monitoring panel, confirm that memory and disk usage for index construction tasks are within reasonable ranges, with no resource exhaustion.

The values provided are common starting points and should be measured against the reader's own samples.
