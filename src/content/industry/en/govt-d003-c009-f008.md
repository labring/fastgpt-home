# Public Data Catalog and Opening: Ledger Aggregation and Report Generation - Document Parsing and Chunking

## What this category of data looks like
The core data for this category comes from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is monthly. Commonly processed documents include public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documents, update frequency descriptions, and more. Document structures mix structured tables and unstructured text. Fields include data item codes, opening subjects, interface addresses, desensitization methods, call permissions, update cycles, and other relevant fields.

## Constraints for Document Parsing and Chunking
Batch file requirements for monthly updates require the parsing process to support batch task scheduling. The mixed structure of structured tables and unstructured text in documents requires the parsing engine to support both table extraction and paragraph splitting. Fields containing sensitive permissions and interface details require retaining contextual associations during chunking to avoid splitting critical authorization information. Single-file volume increases with the number of data items, so parsing parameters must be configured for large files to prevent interruptions or format loss.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0:

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field length and paragraph density of public data documents, avoiding splitting critical information such as interface addresses and data item codes |
| `chunkSplitter` | Split by title + paragraph | Matches the chapter structure of public data catalogs, retaining contextual associations between data items and their corresponding descriptions |
| `customPdfParse` | Enable table parsing mode | Meets the need to extract a large number of structured tables in public data catalogs, restoring field completeness |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatible with large-volume catalog file packages updated in monthly batches, preventing upload interception |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the time requirements of multi-file batch parsing, preventing task interruption due to timeout |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking rules for the mixed structure of public data documents |

## Three Common Misconfigurations
- A large number of empty fields or disordered table formats appear after parsing. Cause: The table parsing mode of `customPdfParse` is not enabled, resulting in failure to correctly extract structured tables in public data catalogs.
- Batch parsing tasks frequently trigger timeout errors. Cause: The value set for `PARSE_FILE_TIMEOUT_SECONDS` is too low, failing to adapt to the parsing time of large-volume files updated in monthly batches.
- Files pushed by external systems cannot automatically trigger parsing. Cause: No file storage path mapping for external pushes is configured, causing the parsing engine to fail to locate the pushed public data documents.

## How to Verify Correct Configuration
- Upload a sample public data catalog file containing structured tables, check that the table fields in the parsing results are complete and without missing content.
- Upload a test file with a single volume of 800 MB, confirm that the upload and parsing processes do not trigger interception or timeout errors.
- Configure an external push interface, push a test document to the specified path, confirm that the parsing task automatically triggers and generates corresponding chunked results.
- Randomly select a chunked interface document, check that the interface address and call parameters are fully retained in the same chunked content.

The values provided are common starting points and should be measured against the reader's own samples.
