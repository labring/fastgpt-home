# Ledger Summary and Report Generation for Highway Maintenance and Road Property Rights Management: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Entails
This category of data typically comes from highway maintenance management systems, bridge and tunnel monitoring systems, road administration patrol systems, and traffic flow monitoring data, with a daily update frequency. Daily documents include maintenance plans, patrol logs, defect disposal orders, road-related construction permits, and road property damage compensation forms. Document fields mostly include facility ID, location coordinates, defect type, disposal requirements, compensation standards, and more. Units include kilometers, square meters, cubic meters, workdays, and other standard units.

## Constraints Imposed by These Features on Multi-turn Dialogue and Prompt Engineering
High-frequency daily updated data requires timely synchronization of multi-turn dialogue contexts with the latest patrol and maintenance records. This avoids ledger summary errors caused by referencing outdated information.
Mixed input of multiple document types requires prompts to clearly distinguish field priorities across different documents. For example, road-related construction permits must prioritize verifying construction scope against road property ledger data.
Differences in fields across documents require multi-turn dialogue to gradually guide users to clarify document types. This prevents confusion between the field logic of maintenance work orders and road property compensation forms.
Scattered data sources require limiting the range of called data sources during dialogue. This prevents cross-category data from interfering with generation results.

## Configuration Settings

## Three Common Misconfigurations
- Uploading an XLSX format maintenance ledger fails to trigger AI dialogue. The cause is that file parsing rules are not configured to adapt to the merged cells and multi-sheet structure of maintenance-related tables, resulting in the system being unable to extract valid fields.
- Calling `variables` during dialogue returns empty values. The cause is that preset variables for the corresponding maintenance project are not bound in the application configuration, resulting in the context being unable to obtain correct business parameters.
- Unable to clear the historical dialogue records of a specified application after debugging preview. The cause is that the cleanup operation is not performed through the application management module in the workspace, and the dialogue history is mistakenly confused with system logs.

## How to Verify Correct Configuration
- Upload a standard XLSX file of maintenance patrol logs, confirm the system can correctly extract the preset core fields.
- Initiate a test dialogue containing preset variables, confirm the `variables` parameter can be correctly substituted into the professional terms of the business scenario.
- After initiating a multi-turn dialogue, check the `messages` context window only contains the latest data for the current project.
- Perform the cleanup operation, confirm the historical records from the debugging preview have been cleared.
