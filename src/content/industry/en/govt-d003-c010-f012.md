# Ledger Summary and Report Generation for Highway Maintenance and Road Property and Usage Rights Management: Deployment and Upgrade

## What This Category’s Data Looks Like
Core data for this category comes from highway maintenance management systems, bridge and tunnel monitoring systems, road administration patrol systems, and traffic flow monitoring data. The update frequency is daily. Daily documents include maintenance plans, patrol logs, disease disposal orders, road construction permits, and road property damage compensation orders. Fields cover section identifiers, disease severity levels, disposal time limits, compensation amounts, construction scopes, and more. Some documents include attachments such as images and drawings. The data structure varies across different business links.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Since data sources include multiple heterogeneous business systems, deployment must support data source connection configurations for different protocols. The daily update frequency requires setting reasonable scheduled synchronization task parameters during deployment to avoid data delays or duplicate synchronization. Document types cover multiple formats such as plans, logs, and permits. During upgrades, multi-format parsing logic must be adapted to ensure complete field extraction for all types of documents. Data is also linked to road safety and fund management. During deployment, reliable backup and permission control strategies must be configured to reduce the impact scope after data errors occur.

## Configuration Settings
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15` | Adapts to concurrent connection requirements of multiple maintenance systems, prevents connection pool exhaustion from causing data synchronization failures |
| `MONGODB_URI` | `Fill in according to the database address of each business system` | Stores unstructured documents and metadata such as patrol logs and disease disposal orders |
| `REDIS_URL` | `Local Redis service address, default port 6379` | Caches daily incremental road property synchronization data to reduce overhead from repeated system queries |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the internal object storage service endpoint` | Stores attached files for road construction permits and road property damage compensation orders |
| `FILE_TOKEN_KEY` | `Configure according to internal secret key generation rules` | Encrypts stored file access tokens to ensure access security for sensitive road property data |
| `ROOT_KEY` | `Custom complex string, minimum length of 32 characters` | Configures the system's highest permission key to ensure management permission security after deployment |

## Three Common Mistakes
- Phenomenon: After local packaging and deployment, modified ledger parsing rules do not take effect on the page. Cause: The deployment image was not rebuilt or the custom configuration directory was not mounted, so updated code or configurations were not loaded by the system.
- Phenomenon: After deployment, the system cannot load the configured data source, and the page prompts connection timeout or empty fields. Cause: Network access permissions for `MONGODB_URI` or `REDIS_URL` were not correctly configured, so the system cannot connect to dependent storage and cache services.
- Phenomenon: After upgrading the version, the daily ledger synchronization task stops running. Cause: The original scheduled task configuration parameters were not exported and restored during the upgrade process, causing the synchronization logic to interrupt.

## How to Confirm Correct Configuration
- Log in to the data source management page of the system backend, verify that the database connection status of each maintenance system shows normal.
- Trigger a manual ledger synchronization task, check that the generated intermediate data includes expected document types such as patrol logs and disease disposal orders.
- Access the front-end page, upload attached files for road construction permits, verify that file storage and preview functions work normally.
- View the system operation logs, confirm that the daily scheduled synchronization task starts normally at the preset frequency with no error messages.
