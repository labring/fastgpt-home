# Ledger Summary and Report Generation for Pension, Work Injury, and Unemployment Benefit Verification: Workflow Orchestration

## What data for this category looks like
Data sources for this category include social insurance management systems, personal entitlement record systems, labor relations and work injury recognition systems, and electronic social security card platforms. The update frequency is daily. Documents processed daily include benefit application forms, payment period certificates, retirement approval forms, work injury recognition materials, and unemployment benefit application materials. Fields cover insured person identity information, payment periods, benefit verification standards, review status, and more. Units include month, yuan, number of people per processing cycle, and others. The data structure of a single document varies based on business type.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered and updated daily. Workflows must support connecting to multiple interfaces including social insurance management systems and personal entitlement record systems, and synchronize the latest business data on a scheduled basis. There are diverse document types and strict field requirements for daily processing. Workflows must configure unified data validation rules to ensure consistent field formats across documents from different sources. The benefit verification link involves multi-dimensional data comparison. Workflows must split nodes according to business logic to avoid timeouts caused by excessive single-process data volume. Additionally, since errors directly impact benefit disbursement, workflows must configure clear failure alerts and retry mechanisms.

## How to set up the configuration
This document is written for FastGPT v4.17.0. Below are workflow configuration recommendations for this category:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Scheduled Trigger Cycle | 2:00-4:00 AM daily | Matches off-peak hours for social insurance business, avoids impacting real-time management services |
| Batch Processing Node Count | Adjust to 50-200 items per time based on business scale | Balances processing efficiency and interface call pressure, adapts to latency characteristics of multi-system connections |
| `variables` configuration | Pre-set fixed parameters such as insured person identity type, benefit type | Reduces repeated data entry, unifies business processing rules |
| Failure Retry Count | 3 times, 60-second interval | Addresses temporary interface fluctuations, prevents process interruption from single exceptions |
| Node Timeout Threshold | 1200 seconds | Adapts to time requirements for cross-system data retrieval, aligns with execution limits for the business scenario |
| `nodeId` configuration | Mark node IDs in order of business nodes | Facilitates quick location of abnormal nodes and troubleshooting of process issues |

## Three common misconfigurations
- Symptom: Workflow nodes return the `premature close` error. Cause: No reasonable timeout threshold is configured. When retrieving social insurance data or benefit materials across systems, interface responses time out and are forcibly disconnected.
- Symptom: When batch processing pension, work injury, and unemployment benefit verification data, single-node execution time exceeds 1200 seconds. Cause: Batch processing nodes are not split. The number of insured persons or data volume processed in a single run is too large, exceeding system execution limits.
- Symptom: An exception is returned when calling a workflow API with file upload functionality. Cause: File parameter transfer format is not configured correctly, and file size, format, and type limits supported by the system are not matched.

## How to confirm the configuration is complete
- Trigger a test workflow, check node logs to confirm that all connected social insurance system interfaces successfully return matching business data.
- Simulate batch processing of insured person data, check whether workflow execution duration aligns with the processing rhythm of the business window.
- Upload benefit application materials, work injury recognition materials, and other documents in different formats to verify that the file upload and parameter transfer process works correctly.
- Simulate node exception scenarios to confirm that failure alerts and retry mechanisms trigger as configured.
