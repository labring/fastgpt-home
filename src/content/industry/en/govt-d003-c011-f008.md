# Ledger Summary and Report Generation for Pension, Work Injury, and Unemployment Benefit Verification: Document Parsing and Chunking

This document was written for FastGPT v4.17.0.

## What this type of data looks like
Data for this category comes from social insurance handling systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily.
Regularly processed documents include benefit application forms, payment period certificates, retirement approval forms, work injury identification materials, and unemployment insurance benefit application materials. Most documents have a mixed structure combining structured fields and scattered supporting content.
Fields involved include applicant identity identifiers, payment periods, qualification determination results, and benefit calculation items. There are no batch files with unified fixed formats. Some materials contain non-business content such as stamps, headers, and footers.

## What constraints do these characteristics impose on the document parsing and chunking step
Multi-source data and mixed document structures require document parsing to support multiple formats including PDF, DOCX. It must also support structured field extraction and association with scattered supporting content.
The daily updated data volume requires the parsing process to control time consumption. This avoids affecting the timeliness of ledger summary.
Key content such as identity identifiers and benefit calculation items must retain full context. Chunk splitting that breaks context will prevent subsequent calculation steps from associating corresponding information.
Since errors directly affect benefit distribution and fund security, the parsing process must ensure no key fields are missed. It must avoid losing the association relationship of key supporting materials due to chunk splitting.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 characters` | The documents contain structured fields and scattered supporting content. This range balances key information integrity and chunk granularity, avoiding overly large or small single chunks |
| `chunkSplitter` | By paragraph + fixed field boundaries | Daily documents use paragraphs and benefit calculation items as business units. Splitting this way preserves the coherence of business logic |
| `customPdfParse` | Enabled | Social security PDFs often contain stamps, fixed headers, and footers. Enabling custom parsing filters out irrelevant content and improves the accuracy of key field extraction |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | Single work injury identification or retirement approval materials may include multiple attached pages. This upper limit covers the size of regular business documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Multi-page batch document parsing requires sufficient time to avoid parsing failure due to timeout |
| `chunkSettingMode` | Manual configuration | The mixed structure of social security documents requires adjusting chunking parameters. Manual configuration allows flexible adaptation to business scenarios |

## Three common misconfigurations
- Symptom: After server deployment, uploading a file causes the document parsing node to return a 404 error, and the file content cannot be read. Cause: The file path uses a relative path in the local environment. After deployment to the server, the correct static file hosting path is not configured, so the parsing node cannot access the uploaded file.
- Symptom: Benefit calculation items are split into two chunks during ledger summary, making it impossible to associate corresponding identity information. Cause: Chunking rules are not configured according to business field boundaries. Splitting only by character length causes key information to be split apart.
- Symptom: Parsing tasks time out and fail when uploading multiple work injury identification materials in batch. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted to a duration suitable for batch documents, or the single file size exceeds the `UPLOAD_FILE_MAX_SIZE` configuration.

## How to confirm the configuration is properly set
- Upload a standard retirement approval form, and check if the parsed chunks retain the association between identity information and benefit calculation items.
- Adjust the `chunkSize` parameter, and compare chunking results under different configurations to confirm that key fields are not split apart.
- Upload a work injury identification material larger than regular size, and verify that the parsing task completes within the configured timeout period.
- Check that the static file hosting path is correct, to ensure that uploaded files can be accessed normally after server deployment.
