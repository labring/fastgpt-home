# Ledger Summary and Report Generation for Pension, Work Injury, and Unemployment Benefit Verification: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category comes from social insurance handling systems, personal benefit records, labor relations and work injury recognition systems, and the electronic social security card platform.
The update frequency is daily.
Daily processed documents include benefit application forms, payment duration proofs, retirement approval forms, work injury recognition materials, and unemployment benefit application materials.
These documents fall into two categories: structured forms and unstructured recognition documents.
Data fields include core parameters such as insured years, benefit level, and application eligibility.
Units include month, year, and yuan.
The content length of individual documents varies widely.

## Constraints for Knowledge Base Retrieval and Recall
Daily updated data sources require the knowledge base sync cycle to align with daily updates. This prevents data lag from harming benefit verification accuracy.
Daily processed documents include both structured forms and unstructured recognition documents. A single retrieval mode cannot support both types of matching. Both keyword and semantic recall must be used.
Data fields include core judgment parameters such as insured years and benefit level. Retrieval result accuracy directly affects benefit verification correctness. Relevance standards for recall must be strictly controlled.
Data from multiple systems must be managed via dataset classification. This stops irrelevant cross-category content from entering the retrieval scope. It ensures retrieval results are targeted.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches the accuracy requirements for documents related to benefit verification, filtering low-relevance content |
| `limit` | `Top 10 entries` | Controls the number of documents returned per retrieval, balancing context length and information completeness |
| `searchMode` | `Hybrid retrieval` | Covers both structured field matching and unstructured semantic recall, adapting to diverse document types |
| `usingReRank` | `Enabled` | Performs secondary ranking on initial recall results to raise the priority of highly relevant documents |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Expands the synonym coverage of query terms to adapt to business documents with different phrasing |
| `collectionIds` | `Bind specified benefit verification dataset IDs` | Limits the retrieval scope to avoid interference from irrelevant dataset content |

## Three Common Mistakes
- Phenomenon: Calling the knowledge base interface returns "Request failed with status code 400". Cause: Dataset binding permissions are not configured correctly, or the incoming `collectionIds` parameter format does not meet requirements.
- Phenomenon: The number of retrieval results is much lower than expected. Cause: The `similarity` threshold is set too high, filtering out some reference documents that meet business requirements.
- Phenomenon: Retrieval results include content unrelated to social insurance benefits. Cause: `collectionIds` are not specified correctly, and the retrieval scope covers irrelevant datasets.

## How to Confirm Proper Configuration
- Check the `collectionIds` configuration to confirm that only datasets related to pension, work injury, and unemployment benefit verification are bound.
- Perform a test retrieval to verify whether the number and relevance of returned results meet business expectations.
- Confirm that the switch states of `usingReRank` and `datasetSearchUsingExtensionQuery` match the configured requirements.
- Check the knowledge base sync logs to confirm that daily updated data sources have completed synchronization with no abnormal errors.

Note: The configuration values provided here are common starting points. Adjust them based on your own specific samples and business needs.
