# Ledger Summary and Report Generation for Senior Care Facility Supervision: Workflow Orchestration

## What the data for this category looks like
The business data subjects for this category include civil affairs bureau senior care departments, senior care facilities, sub-district/township offices, and joint supervision departments. Daily documents include facility filing materials, operation subsidy applications, service quality inspection reports, safety hazard rectification ledgers, and elderly admission files. Data sources cover senior care service information platforms, civil affairs statistics systems, fire inspection records, and facility operation ledgers. The update frequency is monthly. Data fields vary by document type, with no unified fixed units. Content includes basic facility information, bed allocation, service records, and safety hazard records, among others.

## What constraints these characteristics impose on the "workflow orchestration" link
Monthly updated data sources require workflows to include a scheduled trigger mechanism to avoid repeated data scraping or missed data. Multi-source, multi-type business documents require workflows to use differentiated nodes to adapt to different document formats and validation rules. Time-consuming steps such as verifying filed beds, checking service quality, and reviewing subsidy rectification require workflows to split into independent nodes with validation steps to ensure traceability of each step. Data involving multiple collaborative departments requires workflows to configure cross-node data transfer rules to ensure information synchronization across departmental links.

| `variables` | Isolate by user ID | Adapt to exclusive ledger data for different supervisors, avoid global variable conflicts |

| Workflow timeout threshold | 1200–1800 seconds | Cover the full process duration of monthly data summary and multi-source validation |
| `nodeId` | Bind to supervision link nodes | Associate with exclusive business nodes such as filing verification, safety inspection, subsidy review |
| Document format adaptation rules | Trigger corresponding processing based on input document type | Adapt to multiple types of business documents such as filing materials and rectification ledgers |

## Three common mistakes
- Global variable values become mixed after workflow runs, with different supervisors seeing the same ledger data. Cause: The `variables` configuration was not isolated by user ID, and the global scope was used.
- Workflows stay in a loading state for a long time after startup and cannot complete ledger summary. Cause: The set concurrency limit exceeds 6, which exceeds the platform's default limit.
- API calls return parameter errors and cannot complete document classification processing. Cause: The model configuration corresponding to the supervision scenario was not explicitly specified, and generic parameters were misused.

## How to confirm the configuration is complete
- Test different supervisors to view their respective ledger summary results, confirm that data isolation takes effect.
- Start 6 workflow instances simultaneously, confirm that there are no loading exceptions or timeouts.
- Call the API with different types of business document parameters, confirm that the corresponding processing nodes trigger normally.
- Check the workflow run logs, confirm that the link nodes bound by `nodeId` execute as expected.
