# Ledger Summary and Report Generation for Elderly Care Service Institution Supervision: Knowledge Base Retrieval and Recall

## What the data for this business scenario looks like
Business data sources for elderly care service institution supervision typically include elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institution operation ledgers. Daily generated documents include filing materials, operation subsidy applications, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files, among others. Data updates mostly occur on a monthly basis.
Document structures cover structured fields such as institution ID and number of beds, semi-structured inspection items, and unstructured rectification descriptions. Fields and units must align with general business specifications for civil affairs supervision, and there is no unified fixed standard format.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Monthly updated data sources require the knowledge base to support incremental synchronization configuration, to avoid full-volume repeated pulling of redundant data. Coexistence of multiple document types requires the retrieval link to balance structured field matching and natural semantic recall, ensuring effective retrieval of business documents in different formats. Isolation requirements for multi-source data require precise specification of the retrieval scope, preventing non-supervision documents from mixing in and affecting report accuracy. Supervision businesses have high data accuracy requirements, so the number and relevance of recall results must be limited, to avoid redundant information interfering with the core processes of ledger summary and report generation.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Elderly care supervision documents are mostly rigorous business texts. A higher similarity threshold can filter irrelevant results and ensure retrieval accuracy |
| `limit` | `Top 8–12 entries` | Ledger summary and report generation need to cover multi-dimensional institution operation data. An appropriate number of recall results balances comprehensiveness and readability |
| `searchMode` | `vector+keyword` | Business documents include structured fields and natural text. The hybrid retrieval mode matches both semantics and keywords, improving recall coverage |
| `usingReRank` | `Enabled` | Supervision data sources contain redundant information from multiple sources. The re-ranking step further filters low-relevance results, optimizing the input quality for report generation |
| `collectionIds` | `ID list of the exclusive elderly care supervision dataset` | Isolate data sources from different business lines, ensuring the retrieval scope only covers documents related to elderly care service institution supervision |
| `datasetSearchUsingExtensionQuery` | `Disabled` | Supervision business terms are precise. No additional query expansion is needed, to avoid introducing ambiguity that causes retrieval results to deviate from business requirements |

## Three common mistakes
- Phenomenon: Document upload to the knowledge base via API fails, or parsing errors occur when uploading Markdown documents on the platform page. Cause: The `collectionIds` for the exclusive elderly care supervision dataset are not correctly specified, or the uploaded Markdown document contains unescaped special characters, preventing the platform from parsing normally.
- Phenomenon: Deleting a folder containing a large number of documents in the knowledge base triggers the `timeout of 60000ms exceeded` error. Cause: The batch deletion operation does not adapt to the processing logic for large-volume documents, triggering the platform's default timeout limit.
- Phenomenon: When importing a publicly shared web link from a document collaboration tool, the platform prompts that the data source cannot be parsed, and some images cannot be displayed normally in retrieval results. Cause: The shared link does not have public access permissions enabled, or the image links do not have cross-domain access permissions configured, preventing the platform from pulling and displaying image resources.

## How to confirm the configuration is properly set
- Check that the `collectionIds` of the knowledge base dataset only include data sources related to elderly care service institution supervision, confirming that documents from other business lines are not mixed in.
- Initiate a test retrieval, verifying that the `similarity` scores of returned results fall within the set `0.75–0.85` range, and the number of returned results meets the `Top 8–12 entries` requirement specified by the `limit` configuration.
- Upload a standard elderly care institution filing material template, confirming that the upload process has no errors and the document can be properly imported into the specified dataset.
- Initiate a batch deletion test, deleting a test folder containing more than 100 documents, confirming that no timeout error is triggered and the operation completes normally.
