# Ledger Aggregation and Report Generation for Elderly Care Service Institution Supervision: Deployment and Upgrade

## What Data for This Category Looks Like
The data for this category mainly comes from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institutional operation ledgers, with a monthly update frequency. Daily involved documents include elderly care institution filing materials, operation subsidy application documents, service quality inspection forms, safety hazard rectification ledgers, elderly admission files, and more. Data fields cover basic institutional information, number of beds, service records, rectification status, and other categories. Data formats vary across different sources, and unified alignment is required before ledger aggregation and report generation can proceed.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The monthly update frequency requires configuring incremental data synchronization mechanisms during deployment, to avoid excessive resource usage from full synchronization. Multi-source, multi-format data requires configuring field alignment rules during the deployment phase, to adapt to structural differences across different types of documents such as filings, subsidies, and rectifications. Errors in supervision-related data directly affect institutional operations and elderly rights and interests, so a data verification link must be added during deployment to block missing or abnormal fields. Additionally, the need for data source docking across multiple collaborative departments requires configuring a flexible external interface adaptation module to ensure the stability of data synchronization.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15 connections` | Adapts to concurrent demands of monthly batch data synchronization, avoids exhausting database connections |
| `MONGODB_URI` | Intranet MongoDB authentication address, in the format `mongodb://user:pass@host:port/db` | Stores unstructured documents such as elderly care institution filing materials and rectification ledgers |
| `REDIS_URL` | Local Redis instance address, configure cache expiration time to `600 seconds` | Caches monthly updated institution filing and bed data, reduces repeated database queries |
| `STORAGE_S3_ENDPOINT` | Intranet object storage address, such as `http://192.168.1.100:9000` | Stores files uploaded by elderly care institutions, including safety inspection photos and subsidy application attachments |
| `ROOT_KEY` | Custom string of no fewer than 32 characters | Configures the highest permission key for the FastGPT management backend, ensures access security of supervision data |
| `FE_DOMAIN` | Intranet domain name or IP address of the deployed service | Configures the access address for the frontend page, ensures normal access by internal supervision personnel |

## Three Common Mistakes
- Modifying `config.json` does not update the model list, and checking the `/app/data/config` directory in the container shows no configuration changes. The cause is that the FastGPT container was not restarted, so configuration changes were not synchronized to the running environment.
- Clicking the knowledge base module triggers an error, returning status code 500. The cause is that `MONGODB_URI` or `PG_URL` was not configured correctly, leading to failed database connection verification.
- Bed data fields are empty in the generated supervision report. The cause is that the data field formats of the elderly care service information platform and civil affairs statistics system were not aligned, and filing data for some institutions was omitted during monthly synchronization.

## How to Confirm Proper Configuration
- Enter the system settings page of the FastGPT management backend, check the database connection status, and confirm that the configured value of `DB_MAX_LINK` matches the preset value.
- Upload a scanned copy of an elderly care institution filing material, verify that the attachment upload and storage path can be accessed normally, with no error prompts.
- Manually trigger a monthly data synchronization task, check that the synchronization log has no abnormal records such as database connection timeouts or data format errors.
- Generate a supervision report, confirm that the report includes all required document type content such as filing information, service quality inspection results, and safety hazard rectification status.
