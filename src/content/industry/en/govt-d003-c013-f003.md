# Ledger Summary and Report Generation for Internal Control Evaluation, Audit and Rectification: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category of data originates from enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems. Daily processed documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Data is updated on an annual basis. Fields include rectification responsible department, issue description, supporting material path, closure status, and others. Document formats and exported fields vary across different systems, with no unified standardized structure.

## Constraints imposed by these characteristics on the multi-turn dialogue and prompt engineering link
Since data sources cover multiple heterogeneous systems, multi-turn dialogue must support mapping and integration of fields from different systems. Prompts must clearly specify data extraction rules. The annual update requirement means dialogue contexts must retain complete rectification cycle data to avoid losing key information mid-session. Extracting business samples and vouchers is the most time-consuming step. Multi-turn dialogue must support step-by-step data extraction to prevent request timeouts caused by loading excessive content at once. Additionally, the accuracy of audit issues is directly tied to regulatory risks. Prompts must include a data source verification step to ensure extracted information matches the original documents.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Unique identifier associated with the rectification ledger | Ensures coherent dialogue context for the same rectification task |
| `messages` | Pass historical conversations in batches according to the rectification cycle | Prevents request failures caused by overly long single context |
| `variables` | Pass the system field mapping table for the current audit project | Adapts to differences in document formats exported by different systems |
| Maximum context | 8000–12000 characters | Adapts to the full rectification data volume for annual audits |
| Allowed file formats | .pdf, .docx, .xlsx, .jpg | Adapts to common formats for audit working papers and rectification closure certificates |
| Single dialogue return limit | Top 10 rectification records | Prevents page freezes caused by returning too much data |

This configuration applies to FastGPT v4.17.0.

## Common Misconfiguration Issues
- 422 error when calling the dialogue interface: The interface returns a 422 status code, while the model test step displays normal functionality. The cause is incorrect formatting of the `variables` or `messages` parameters, or parameter values exceeding the configured context length limit.
- Unable to create an application via OpenAPI: The interface cannot be called to create an application, and manual creation via the web interface is required. The cause is that the current version does not expose the application creation API interface. Complete application creation via the web interface before calling the dialogue interface.
- Unisolated dialogue contexts: Different users' dialogues return rectification records from other users. The cause is that an independent `chatId` is not assigned to each user, resulting in shared dialogue contexts.
- No response or format error when uploading files: When uploading audit working papers, the system prompts an unsupported format, or the content is not displayed after upload. The cause is that the allowed upload file formats are not configured to the specified types, or the file size exceeds the system limit.

## How to verify successful configuration
- When calling the dialogue interface, check whether `chatId` is associated with the unique identifier of the current rectification ledger to ensure coherent context.
- Upload test audit working papers and rectification closure certificate files to confirm the system can normally recognize and load the content.
- Pass a small amount of historical conversation data to verify that the `messages` parameter format meets requirements and does not exceed the length limit.
- Review the interface return results to confirm that the number of returned rectification records matches the configured single dialogue return limit.

The values provided here are common starting points and should be evaluated against the reader's own samples.
