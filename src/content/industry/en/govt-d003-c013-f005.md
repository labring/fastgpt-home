# Ledger Summary and Report Generation for Internal Control Evaluation, Audit and Rectification: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from enterprise internal control systems, ERP systems, financial shared services systems, audit management systems, and procurement contract project systems. The update frequency is annual. Commonly processed documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closing certificates. Data primarily consists of a mix of structured ledgers and unstructured documents. Fields include issue number, rectification responsible person, rectification deadline, supporting material path, closing status, and other relevant fields. There is no fixed unified unit, and values adjust based on the enterprise's internal management rules.

## What constraints do these characteristics impose on the tool calling and plugins workflow?
Low-frequency data updated annually requires tool calling to support batch historical data pulling. This avoids frequent high-frequency request triggers.
Multi-source heterogeneous data sources require plugins to be compatible with interface formats of different systems. Preset field mapping rules adapted to each system.
Diverse document types including unstructured content require triggering text extraction and structured parsing plugins via `functionCall`. Preset parsing templates for audit working papers and rectification ledgers.
The requirement for rectification closed-loop tracking requires tool calling to link with the closing status field. This ensures generated reports synchronize the latest rectification progress in real time.
The complexity of cross-system data pulling requires setting reasonable timeout thresholds for tool calling. This avoids overall task failure caused by delays in a single system.

## Three common misconfigurations
- Tool calls return irrelevant fields. The symptom is that unplanned redundant information appears in returned results. The cause is missing output format constraints for `functionCall`. This allows the plugin to return unmapped fields.
- Call timeouts trigger errors. The symptom is an interface display of a call timeout status code. The cause is failure to adjust the tool timeout threshold. The time required to pull annual data across systems exceeds the default limit.
- Generated reports include issues with incomplete rectification. The symptom is missing rectification closing status markings in the report. The cause is failure to use plugin calls linked to the closing status field. This fails to synchronize the latest rectification progress in real time, and may lead to repeated occurrence of audit issues.

## How to confirm correct configuration
- Trigger a single tool call. Verify that returned fields match preset field mapping rules, with no redundant information.
- Simulate a batch call. Check if system rate limiting is triggered. Adjust the plugin call batch size to meet interface requirements.
- Generate a test report. Verify that the latest rectification closing status data is included.
- View tool call logs. Confirm that the automatically matched tool type matches the requirements of the current data source.
