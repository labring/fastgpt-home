# Ledger Summary and Report Generation for Medical Insurance Fund Supervision and Audit: Workflow Orchestration

## What data does this category contain
Data for this category comes from medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. The update frequency is monthly. Daily output documents include audit notices, inspection work papers, suspicious item lists, interview records, handling decision letters, and rectification reports. Fields cover violation types, involved amounts, involved institutions, handling opinions, and more. Single document data dimensions cover settlement details, supervision rule matching results, and clue verification statuses.

## What constraints do these characteristics impose on the workflow orchestration link
The monthly update frequency requires the workflow to use a scheduled trigger mode, and removes the need for high-frequency real-time scheduling. The need to access multi-source heterogeneous data requires setting unified data pull and cleaning nodes in workflow orchestration to adapt to output formats from different systems. Document fields cover compliance-related dimensions, so a rule verification node must be embedded in the workflow to match content from the fund supervision rule base. Errors in violation identification directly relate to fund losses, so failure retry and exception log retention links must be configured in the workflow to ensure the accuracy of audit results.

## How to set configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Node | 00:00 on the 1st of every month | Matches the monthly data update frequency of this category |
| `variables` | Bind audit cycle and involved institution scope | Adapts to core parameter configuration for monthly audits |
| Data Pull Node | Pull all data sources within the scope specified by `variables` | Covers all data sources required for this category |
| Rule Verification Node | Complete violation matching verification using the fund supervision rule base | Ensures audit results comply with regulatory requirements |
| Failure Retry Configuration | 3 retries, 60-second interval | Avoids data pull failures caused by temporary network fluctuations |
| Document Export Configuration | Support DOCX format export | Meets offline archiving requirements for ledgers and reports |

## Three Common Mistakes
- Phenomenon: No downloadable DOCX link is generated after the workflow generates a report. Cause: No document export node was added at the end of the workflow, or the export format was not configured as DOCX.
- Phenomenon: Workflow nodes fail to run after migrating a v4.8 workflow to a new version. Cause: The original workflow's `nodeId` mapping relationship was not retained; the new version's node ID rules have been updated.
- Phenomenon: Audit content output by the model cannot be automatically converted to a standard ledger format. Cause: No content formatting node was added to the workflow, and the fixed field structure of the ledger was not matched.

## How to confirm the configuration is properly set
- Check if the scheduled trigger node of the workflow matches the monthly update time requirements.
- Verify that the parameters bound to `variables` cover core configurations such as audit cycle and involved institution scope.
- Test the single data pull and verification process to confirm that all nodes are running normally.
- Trigger a test run to confirm that the generated report can be exported in DOCX format.
