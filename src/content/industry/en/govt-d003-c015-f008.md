# Ledger Summary and Report Generation for Medical Insurance Fund Supervision and Audit: Document Parsing and Chunking

## What Data This Use Case Handles
Data for this use case originates from the medical insurance intelligent monitoring system, fund supervision rule base, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. The update frequency is monthly. Commonly processed documents include audit notices, inspection work papers, suspicious item lists, interview records, handling decision letters, and rectification reports. Most documents are a mix of structured tables and semi-structured text. Fields cover violation types, involved amounts, rectification requirements, handling opinions, and similar content. Common units include amounts, person-times, and time cycles.

## Constraints Imposed on Document Parsing and Chunking
The requirement for monthly batch processing requires the parsing link to support stable batch scheduling and timeout control. Mixed structured and semi-structured document types require chunking logic to adapt to the boundaries of tables, lists, and free text, to avoid splitting critical violation records or table cells. Accurate extraction of sensitive fields such as violation amounts and handling opinions requires the document parsing link to retain original field correspondence, preventing field misalignment after parsing. Non-standardized complaint clues and rectification report formats require custom parsing adaptation, while setting a single-file processing limit to avoid timeouts.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of core paragraphs such as violation records and handling opinions in documents of this use case, to avoid splitting critical information |
| `chunkSplitter` | Split by paragraph and title boundaries | Adapts to hierarchical documents such as audit notices and rectification reports, preserving the integrity of logical units |
| `customPdfParse` | Enabled | Adapts to non-standard PDF formats such as interview records and complaint clues, resolving typesetting issues that standard parsing cannot recognize |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Matches the size of common single-batch document packages in monthly batch processing, preventing the upload process from blocking compliant files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Meets the parsing time requirements for large-volume settlement data-related documents, preventing task interruptions due to early timeouts |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking parameters for different document types (such as table-style suspicious item lists and text-style handling decision letters), adapting to diverse document structures |

## Three Common Configuration Errors
- An error "the argument ‘windows-1252’ is invalid encoding" occurs when uploading PPT or PDF files. The cause is failure to configure custom encoding adaptation, or failure to handle non-UTF-8 encoded document content during parsing.
- An error is triggered when using the document parsing tool in a workflow to parse an uploaded file URL. The cause is incorrect configuration of the `CUSTOM_READ_FILE_URL` environment variable, or the file path failing permission verification.
- Table-style suspicious item list content in chunking results is split into multiple unrelated fragments. The cause is using a fixed character chunking logic, failing to adapt to the structured typesetting of tables, and not selecting the splitter that splits by paragraph and title boundaries.

## How to Verify Correct Configuration
- Upload a single compliant audit notice PDF, check if the parsed text retains complete handling opinion and violation type fields.
- After configuring `PARSE_FILE_TIMEOUT_SECONDS`, upload a document larger than the conventional single-file size, verify that the parsing task does not terminate early.
- Check the switch status of `customPdfParse`, confirm that custom parsing is enabled for non-standard format interview record documents.
- Test batch uploading monthly batch document packages, verify that the upload process does not block files that meet the `UPLOAD_FILE_MAX_SIZE` limit.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
