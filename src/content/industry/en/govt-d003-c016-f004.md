# Reconciliation Summary and Report Generation for Medical Insurance Expense Settlement Audit: Workflow Orchestration

## What the data for this category looks like
This data originates from the national medical security information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical settlement platform. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Data is updated daily. Data fields include diagnosis and treatment item and drug consumable codes, expense detail amounts, insured person identity identifiers, and settlement status identifiers. Data formats and field order vary across different sources, so unified parsing of multi-source heterogeneous data must be supported.

## What constraints these characteristics impose on workflow orchestration
Multi-source data updated daily requires workflows to support scheduled synchronization and manual trigger mechanisms for multiple data sources, to prevent data omission or duplicate processing. Diverse document types require parsing nodes configured for different formats, to ensure accurate field extraction from settlement lists, prescriptions, and other files. Core links take extended time, so code matching, expense verification, and rejection reconciliation must be split into independent nodes. Assign a unique `nodeId` to each node to facilitate log troubleshooting and exception location. Data processing accuracy directly affects fund security, so each workflow node must have failure retry and exception alert rules configured, to enable rapid recovery after task interruption. Batch settlement data processing must support task splitting and merging, to adapt to execution efficiency for massive daily data volumes.

## How to configure the settings
This configuration is based on FastGPT v4.17.0, adapted for the medical insurance expense settlement audit business scenario.

| Tool call output control | Hides original tool call replies | Avoids redundant tool interaction details interfering with the business output of final reconciliation sheets and reports |
| Multimodal node configuration | Enables image recognition based on actual testing | Adapts to image format parsing requirements for prescriptions and settlement lists, covers unstructured document processing scenarios |

## Three common mistakes
- Tool call module output is not hidden, and the interface returns original tool call logs. This occurs because the tool call output hiding option is not configured, causing workflow execution to directly return tool interaction details, which does not meet the business output requirements for reconciliation reports.
- Judger nodes fail to correctly recognize Boolean-type global variable states. This occurs because the global variable type is not converted to an identifiable Boolean value, or the configured judgment condition does not match the variable's value range, leading to abnormal branch switching.
- Workflows trigger disconnection when the MongoDB replica set primary node drifts, and cannot automatically reconnect. This occurs because a high-availability reconnection policy for data sources is not configured, only single-node connections are supported, which cannot adapt to the distributed deployment architecture of medical insurance information platforms.

## How to confirm proper configuration
- Manually trigger a workflow, view the final output reconciliation sheet and report, confirm that original tool interaction logs are not included.
- Simulate a MongoDB replica set primary node switch, verify whether the workflow can automatically restore connections and continue task execution.
- Configure a Boolean-type global variable, trigger the judger node, verify whether branch switching conforms to the expected audit status logic.
- Upload a prescription image to the multimodal node, verify whether the image content can be properly parsed and key fields extracted.
