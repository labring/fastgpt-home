# Ledger Summary and Report Generation for Medical Insurance Expense Settlement Audit: Tool Calling and Plugins

## What data this category handles
Data sources for this category include the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-provincial medical settlement platform. The update frequency is daily. Documents processed daily include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Fields cover settlement numbers, insured person identity information, diagnosis and treatment project codes, drug and consumable unit prices, total expense amounts, rejection reasons, and more. Units follow the general specifications of medical insurance systems, with no custom units.

## Constraints on tool calling and plugins workflow
The daily updated data feature requires tool calling to support scheduled triggering and batch processing, to avoid timeouts caused by excessive single-processing data volume. The multi-source data access requirement means plugins must adapt to authentication formats and return structures of different interfaces, and a unified parameter mapping rule must be configured. The multi-field document structure requires tool calling to accurately match input parameters of tools such as medical insurance catalog queries and expense detail summaries, to avoid field omissions or format errors. Errors are linked to the safety of medical insurance funds and the reimbursement rights of insured persons, so tool calling must be configured with failure retry and parameter verification mechanisms to reduce abnormal processes.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Value |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios, automatically matches tools such as medical insurance catalog queries and detail summaries |
| HTTP request timeout | `60 seconds` | Matches the standard response duration of the national medical insurance information platform |
| Batch processing single limit | `first 200 entries` | Adapts to the single processing scale of daily updated data, avoids timeouts |
| `functionCall` parameter verification | Enabled | Ensures fields such as settlement IDs and expense amounts comply with medical insurance specifications |
| Failure retry count | `2 times` | Addresses occasional interface fluctuations, reduces manual intervention |

## Three Common Mistakes
- Charts generated by basic chart plugins have empty fields. This occurs because the amount, settlement date and other fields of medical insurance expense details are not correctly mapped, so the plugin cannot recognize the corresponding data columns.
- Calling medical insurance interfaces via the HTTP module fails, but the calls work normally in Postman. This occurs because medical insurance-specific authentication parameters for interface request headers are not added in FastGPT configuration, or the request body format is not set correctly.
- Parameter verification fails after `functionCall` is configured. This occurs because codes, amounts and other parameters are not transmitted in accordance with the field specifications of medical insurance settlement data, exceeding the preset verification rules of the plugin.

## How to Confirm Proper Configuration
- Trigger a single settlement detail summary task, check the tool calling logs in FastGPT v4.17.0, and confirm that tools such as medical insurance catalog queries and detail integration are correctly called.
- Initiate a batch data test, and verify that the generated ledger data is consistent with the settlement list fields returned by the source HIS and medical insurance platforms.
- Simulate an interface timeout scenario, and confirm that the system triggers the failure retry mechanism and continues the process after a successful retry.
- Run the chart plugin configuration, and confirm that the generated report includes core indicators of medical insurance settlement such as expense amounts and number of settled cases.
