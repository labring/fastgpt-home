# Ledger Summary and Report Generation for Medical Institution Supervision and Public Health Inspection: Multi-turn Dialogue and Prompt Engineering

## What data falls under this category
Data for this category originates from health supervision information systems, medical institution electronic registration systems, complaint and reporting platforms, and law enforcement inspection records. The update frequency is monthly. Commonly processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Each document includes fields such as institution name, license number, inspection item details, rectification requirements, and penalty basis.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering workflow?
Monthly batch data updates require multi-turn dialogue systems to support batch retrieval of documents from different data sources, to avoid single-turn context overload. Differentiated fields across multiple document types require prompts to clearly define retrieval scopes for three task types: practice qualification verification, on-site inspection compliance, and rectification tracking. The sensitive nature of law enforcement records and penalty case files requires dialogue contexts to isolate user data by `chatId`, preventing cross-institution information leaks. Ledger summary requires cross-document association of unified institution identifiers. Prompts must explicitly specify matching rules for associated fields, to avoid incorrect alignment of institution information.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Context Isolation Rule | Isolate session data by `chatId` | Matches the sensitive privacy requirements of law enforcement documents for this category, prevents cross-institution information leaks |
| Multi-turn History Call Scope | Call the first 10 `messages` | Balances context completeness and interface call efficiency, avoids single request timeout |
| Variable Binding Configuration | Bind institution unique identifiers from `variables` | Used for cross-document association of institution information, adapts to batch processing requirements for ledger summary |
| Prompt Template Update Cadence | Monthly updates | Matches the monthly update frequency of data for this category, ensures prompts align with latest document fields |
| Single Retrieval Result Limit | Return the first 5 matching documents | Controls returned information volume, avoids context overflow that disrupts dialogue logic |
| Response Timeout Setting | Set to 600 seconds | Adapts to the duration requirements of batch document calls for this category, avoids interface interruptions |

## Three Common Misconfigurations
- Symptom: The dialogue interface displays a prompt that no knowledge base is selected, but results work normally in debug preview. Cause: Permission configuration for the target knowledge base is not bound via `chatId`, so the formal environment session context fails to associate with the preset knowledge base.
- Symptom: Institution information is misaligned in ledgers generated via multi-turn dialogue. Cause: The unique institution identifier from `variables` is not bound, leading to incorrect matching of institution data during cross-document association.
- Symptom: Calling the OpenAI API to retrieve specified user chat data returns empty results. Cause: The `chatId` parameter is not correctly included as the query identifier, making it impossible to locate the complete record for the target session.

## How to Verify Successful Configuration
- Use the debug panel in FastGPT v4.17.0 to launch a multi-turn supervision inspection dialogue for a single institution. Confirm that the context only includes relevant documents for that institution, with no cross-institution information.
- Call the OpenAI API, pass the specified `chatId`, and verify that the complete `messages` record for the corresponding session is returned.
- Adjust the multi-turn history call scope, and confirm that the interface response duration meets expectations, with no timeout errors.
- Trigger a ledger summary task, and confirm that institution information in the generated report matches associated documents correctly.
