# Ledger Aggregation and Report Generation for Medical Institution Supervision and Public Health Inspection: Database and Operations

## What data for this category includes
This category of data covers documents such as supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Sources include the health supervision information system, medical institution electronic registration system, complaint and reporting platform, and law enforcement inspection records. Data is updated once per month. It includes structured institutional qualification fields, inspection times, rectification statuses, and unstructured document attachments. Each record is linked to a unique institutional identifier. Field units are primarily "entries (inspection records)" and "copies (documents)". Some fields require linking to unified cross-system codes.

## What constraints these characteristics impose on database and operations workflows
The need to synchronize multi-source data in batches each month requires databases to support high-concurrency batch writes and queries. Structured qualification and inspection fields must support complex associated queries. Unstructured documents must adapt to large-field storage. Cross-system data format differences require database operations to support data format conversion and cleaning. Data errors can lead to consequences such as medical institution penalties and practice risks. This requires operations to have data consistency verification and anomaly alert capabilities. At the same time, storage of multi-source data must balance both structured query and unstructured storage needs. This places clear constraints on database selection and configuration.

## Three common configuration mistakes
- Symptom: A `Failed to connect to jyfkk:1433` error is returned when configuring database connections. Cause: The host address, port, or authentication information in `MONGODB_URI` or `PG_URL` is not filled correctly, or the corresponding database service is not running properly.
- Symptom: MongoDB connections continue to fail during local development, and the database status shows failed. Cause: The correct authentication source is not configured in `MONGODB_URI`, or local firewall rules block traffic on the database port.
- Symptom: The system prompts that only specified database types are supported, and Oracle database connections cannot be established. Cause: The appropriate database type is not selected based on the category's data storage requirements, and an unconfigured database connection parameter is mistakenly used.

## How to verify successful configuration
- Use the database connection test tool built into FastGPT v4.17.0 to verify that `MONGODB_URI` and `PG_URL` can establish normal connections, and return a connection success prompt without errors.
- Check the monthly synchronization task logs to confirm that the number of synchronized data records matches the output of the source system, with no missing or duplicate entries.
- Check the Redis cache status query interface to confirm that `REDIS_URL` configuration is effective, and the cache data update frequency matches the set synchronization cycle.
- Adjust the concurrent connection count to verify the `DB_MAX_LINK` setting value, and ensure the database service does not throw connection exhaustion errors.
