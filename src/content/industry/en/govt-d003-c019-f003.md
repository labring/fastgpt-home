# Ledger Summary and Report Generation for Random Double-Check and Public Disclosure Regulatory Inspections: Multi-Turn Dialogue and Prompts

## What This Category of Data Looks Like
Normally, data sources for this category include the Random Double-Check and Public Disclosure regulatory platform, enterprise credit information disclosure system, industry regulatory systems, and law enforcement officer directory. Data updates occur once per month.
Daily documents include inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result announcements. Document fields include unified social credit codes of inspection targets, law enforcement officer IDs, inspection item entries, rectification deadlines, and similar details. There is no unified fixed format template. Corresponding fields must be extracted separately based on document type. Details of documents vary slightly across regulatory departments.

## What Constraints These Characteristics Impose on Multi-Turn Dialogue and Prompts
Monthly data updates require multi-turn dialogue nodes to trigger data source synchronization regularly. This prevents use of expired inspection target or law enforcement officer information.
Differentiated document structures require prompts to clearly distinguish processing logic for different document types. This ensures accurate extraction of task cycles from inspection plans and rectification requirements from on-site records.
Decentralized data sources require clear association of fields from different systems during dialogue. This avoids mismatches between law enforcement officers and inspection targets.
Accurate regulatory announcements require adding field verification links in multi-turn dialogue. This ensures generated ledgers and reports include all required announcement fields.

## Configuration Settings
This configuration applies to FastGPT v4.17.0. The specific settings are as follows:

| `variables` | Bind monthly updated data source addresses and law enforcement officer directory IDs | Adapt to the monthly data update feature, ensuring dialogue uses the latest regulatory data |
| `messages` | Preset initial dialogue rounds including document classification prompts and field verification rules | Adapt to the differentiated structure of multiple document types, clarifying extraction logic for different documents |

| Dialogue timeout | 600 seconds | Adapt to the time required for multi-document summary, avoiding task interruption due to overly long single processing |

## Three Common Mistakes
- Phenomenon: Inspection plan data that has not been updated for more than 7 days appears in the generated ledger. The interface prompts that the file has expired. Cause: The default configuration for dialogue file expiration was not adjusted, and persistent storage was not enabled. This causes dialogue files to expire automatically.
- Phenomenon: Parallel AI dialogue tasks in batch execution nodes fail, returning an abnormal status code. Cause: The `chatId` parameter was not configured correctly. Multiple dialogue tasks share the same context, triggering conflicts.
- Phenomenon: The generated inspection result announcement content does not match the on-site inspection record. Some inspection item entries are missing. Cause: Field mapping rules were not clearly defined in the initial prompt. This causes confusion in extraction logic.

## How to Confirm Proper Configuration
- Manually trigger a single-turn dialogue. Check whether the generated report includes the current month's inspection target list, to confirm data source binding is correct.
- View the dialogue log. Confirm that the `variables` parameter of each dialogue includes necessary fields such as law enforcement officer directory ID and inspection item list, with no missing entries.
- When executing batch tasks, view the session identifiers of parallel dialogues. Confirm that the `chatId` parameter is unique, with no context sharing.
- Export the generated ledger and compare it with the original documents. Confirm that all inspection item entries have been correctly extracted and summarized.
