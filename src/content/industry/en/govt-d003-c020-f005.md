# Territory Spatial Planning Compilation and Implementation Evaluation: Ledger Summary and Report Generation - Tool Calling and Plugins

## What data for this category looks like
Data sources for this category include the National Territorial Spatial Basic Information Platform, natural resource survey and monitoring data, population and economic statistical results, and remote sensing images. The update frequency is annual. Daily produced documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summary materials. Data fields cover spatial coordinate information, land use classification codes, land use area, implementation progress records, and more. Most documents take the form of structured ledgers and reports combining text and images.

## Constraints on tool calling and plugin workflows
The annual update data frequency requires tool calling to support scheduled full dataset pulls, to avoid repeated and ineffective single calls. Multi-source heterogeneous data sources require plugins to be compatible with multiple data formats and access protocols, to adapt to different types of resources such as spatial layers, statistical tables, and image files. Diverse document structures require tool calling to distinguish between structured ledger fields and unstructured report text, to avoid mixed content processing. Special spatial data fields require plugins to have format verification and conversion capabilities to ensure data usability. The `toolChoice` configuration allows the model to independently select appropriate tools, and enabling `functionCall` unlocks parallel multi-tool capabilities, which better adapts to the complex data processing needs of this category.

## How to set configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling trigger timing | Trigger according to the annual update cycle, or manually trigger | Matches the annual update frequency of data for this category, to avoid invalid calls |
| Single tool call data volume limit | 1000 MB | Adapts to the single-batch transmission and processing scale of multi-source spatial data |
| `toolChoice` | auto | Allows the model to independently select tools suitable for spatial data and ledger processing |
| `functionCall` | Enable parallel multi-tool calling | Supports pulling remote sensing images, statistical data, and opinion summary materials simultaneously |
| Tool calling timeout threshold | 600 seconds | Adapts to the time requirements of spatial data loading and multi-source aggregation |
| Tool result cache duration | 365 days | Matches the annual data update cycle, to reduce resource consumption from repeated pulls |

## Three common configuration mistakes
- Excessive log space occupied by frequent tool calling run records | The tool calling run log switch is not disabled. The default configuration outputs detailed records for every tool call.
- The final variable value output after calling an API overlaps with previous results | The variable reset switch in the tool calling configuration is not enabled, causing previous tool call variable data to remain in the context.
- Tool calling exceeds the threshold and times out | The timeout threshold is not adjusted based on the actual loading scale of spatial data. The default threshold cannot adapt to the processing duration of multi-source spatial data.

## How to confirm correct configuration
- Trigger a tool call, check that the returned fields match the ledger fields for this category, with no redundant or missing spatial data-related content.
- View the tool calling run logs, confirm that no additional redundant run records are output, or that log output has been disabled as required.
- Wait for the tool call to complete, confirm that no timeout errors occur, and that the result data volume matches the expected scale.
- Verify that variable output has no overlapping conditions, check that the final variable result does not carry residual content from previous calls.

The values provided are common starting points and should be measured against samples associated with the specific deployment.
