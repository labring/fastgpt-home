# Ledger Aggregation and Report Generation for Centralized Treasury Payment and Reimbursement Audit: Workflow Orchestration
This document applies to FastGPT v4.17.0.

## Data Profile for This Category
Data for this category comes from the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system. The update frequency is daily. Daily processed documents include payment applications, fund appropriation plans, invoices, contracts, acceptance documents, reimbursement approval forms, and payment vouchers. Data fields cover budget indicators, economic classification, payment amount, audit status, and more. Amount fields use yuan as the unit, time fields use natural day as the unit, and there are no additional custom statistical fields.

## Constraints for Workflow Orchestration
Multi-system data source access requires workflow configuration with cross-system data fetch nodes, and unified field mapping rules to adapt to output formats of different systems. Daily update frequency requires workflow scheduling cycles to match natural days, to avoid cross-cycle data confusion. Multi-type document input requires workflow support for multi-format parsing nodes, to adapt to different document structures such as invoices and contracts. Core time-consuming verification and audit links must be split into independent verification nodes, with configurable pre-verification rules to block non-compliant data. Exception scenarios such as order rejection and payment correction require preset branch processes, to ensure traceable handling of abnormal data.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data source node scheduling cycle | 2:00–4:00 daily | Matches daily data update rhythm, avoids peak business hours |
| Multi-document parsing node format support | Enable PDF, Excel, and OFD parsing switches simultaneously | Covers common document formats for this category: invoices, contracts, payment vouchers |
| Validation node trigger condition | Trigger when the budget indicator field in `variables` is empty | Blocks pending audit data missing core fields |
| Exception branch rollback node | Roll back to the audit initiation node and push an alert after triggering | Meets business requirements for high-impact errors, ensures traceable exceptions |
| Cross-system field mapping rule | Map output fields of the system corresponding to `nodeId` | Unifies field naming across different systems, prevents data misalignment |
| Single validation node timeout threshold | 600 seconds | Covers time requirements for cross-system data fetch and validation |

## Common Configuration Mistakes
- Symptom: Knowledge base search node returns empty results. Cause: The knowledge base ID configured in `variables` is not correctly bound to the node parameters, so the search does not point to the specified knowledge base.
- Symptom: Code running module cannot implement streaming output when calling external models. Cause: The streaming output switch is not enabled in the node configuration, or the returned streaming data fragments are not processed correctly.
- Symptom: Field misalignment errors occur after workflow execution. Cause: Cross-system field mapping rules are not configured, so differences in field naming across data sources are not unified, leading to data confusion.

## How to Verify Correct Configuration
- Manually trigger the workflow once, check if each data source node successfully fetches the day's updated documents such as payment applications and invoices, confirm normal data source operation.
- Submit a test audit data entry, trigger the validation node, confirm that the core field validation rules block or pass data as expected.
- Trigger the exception branch process, confirm that the workflow rolls back to the specified node and pushes alert information, verify normal exception handling logic.
- View the workflow run logs, confirm that the parameter configurations corresponding to `variables` and `nodeId` are correctly called, with no parameter binding errors.
