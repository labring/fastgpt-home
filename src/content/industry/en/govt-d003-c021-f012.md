# Centralized Treasury Payment and Reimbursement Audit: Ledger Aggregation and Report Generation - Deployment and Upgrade

## What data for this category includes
Core data for this category originates from centralized treasury payment systems, unified budget management systems, electronic invoice platforms, and contract management systems. It supports daily work for budget unit finance teams, treasury payment centers, and departmental finance audit positions.

Daily processed documents include payment applications, fund plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers. Data is updated on a daily basis.

Each data entry contains fields such as budget indicator code, economic classification code, payment amount, approval status, and associated contract number. Amounts are measured in yuan. Payment records are counted per transaction. Ledgers require summarizing multi-dimensional payment and audit details.

## What constraints these characteristics impose on deployment and upgrade
Data sources for this category are scattered and require daily synchronization. Deployment requires connecting to interfaces from multiple external systems, and configuring multiple sets of data source connection parameters.

Daily processed documents include various formats of bills and approval materials, so storage requirements are high. A stable file storage service must be configured.

Ledger aggregation requires handling complex field mapping and multi-dimensional statistics. Sufficient database computing resources must be reserved during deployment.

Since errors may lead to compliance risks such as payment returns or incorrect fund transfers, gray release must be performed during upgrades. Full data backup must be completed before deployment.

In intranet environments, storage services must not be exposed to the public internet to protect internal data security.

## How to configure settings
These configuration items are based on FastGPT v4.17.0, and are adapted for the ledger scenario of centralized treasury payment and reimbursement audit:

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.200:9000` | Adapted for intranet deployment scenarios, connects to internal MinIO storage services, and avoids public network exposure risks |
| `REDIS_URL` | `redis://:securepass@10.0.0.5:6379/1` | Caches daily synchronized ledger data to ensure response speed for multi-dimensional summary queries |
| `PG_URL` | `postgresql://gsc_admin:dbpass@10.0.0.3:5432/finance_ledger` | Stores structured ledgers and audit records, supports complex summary and statistical queries |
| `DB_MAX_LINK` | `20–30` | Adapts to database connection requirements for daily batch synchronization, prevents synchronization failures caused by resource exhaustion |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Ensures access permission security for uploaded files such as invoices and contracts |
| `FE_DOMAIN` | `https://finance-ai.your-intranet-domain.com` | Configures the actual access address of the service, ensuring the validity of webhook callbacks and plugin calls |

## Three common configuration mistakes
- Symptom: Cannot access stored bill files after starting the service. Logs display "access denied" or "invalid endpoint". Cause: `STORAGE_S3_ENDPOINT` is not set to an intranet-accessible address. A public domain name was used instead, leading to intranet resolution failure.
- Symptom: After manually triggering a ledger synchronization task, logs show "connection pool exhausted" and synchronization progress stalls. Cause: The `DB_MAX_LINK` configuration value is too low. Insufficient database connections during batch synchronization prevent full data retrieval.
- Symptom: Table data received by webhooks cannot generate corresponding ledgers, and the result is empty. Cause: `FE_DOMAIN` is not configured to the actual service access address, leading to an invalid callback address and failure to receive complete synchronization data.

## How to verify correct configuration
- Run the built-in database connection test tool to confirm that services corresponding to `PG_URL` and `REDIS_URL` can establish normal connections.
- Upload a test electronic invoice image, and use the file storage module to verify that the file can be uploaded normally and returns a valid access link.
- Trigger a manual ledger synchronization task, and check the synchronization log to confirm there are no connection errors, data is fully retrieved, and no fields are missing.
- Navigate to the plugin configuration page to confirm that the `STORAGE_S3_ENDPOINT` configuration matches the actual address of the intranet storage service.

The values provided here are common starting points, and should be evaluated against the user's own samples.
