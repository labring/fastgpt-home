# Ledger Summary and Report Generation for Land Use Rights, Mining Rights and State-owned Property Transactions: Tool Calling and Plugins

## What this category of data looks like
Data for this category typically comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. The update frequency is daily. Daily generated documents include transfer announcements, trading notices, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer prospectuses, and more. Each document contains fields such as trading subject ownership number, subject type, listing price, margin amount, transaction date, and transferee information. Field structures vary slightly across different transaction types.

## What constraints do these characteristics impose on tool calling and plugin workflows
The above data characteristics impose multiple constraints on tool calling and plugin configuration. Daily updated data requires scheduled pulling tools to maintain the timeliness of ledger data. Plugins must adapt to different interface formats for multi-source system data, to unify input into the ledger summary process. Diverse document types and differentiated field structures require specifying extraction rules tailored to specific document types during tool calling, to avoid incorrect field extraction. High accuracy requirements for core business fields such as ownership and margin require enabling parameter verification during tool calling, to prevent invalid data from entering the ledger. Cross-source transaction data association requires plugins to support field matching and merging logic across multiple data sources.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |

| `toolChoice` | `auto` | Adapt to the automatic identification needs of multiple types of transaction documents, no manual specification of tool type required |

## Three common configuration errors
1.  Phenomenon: After streaming data reception is interrupted, front-end page data remains fixed while back-end sessions continue running. Cause: No session cleanup plugin configured after stream interruption, leading to inconsistent front-end and back-end session states.
2.  Phenomenon: The `packages/plugins/register` file cannot be found when creating a system plugin. Cause: The plugin registration directory for FastGPT v4.17.0 has been adjusted. Configuration must be completed via the plugin management interface in system settings; manual creation of this file is not required.
3.  Phenomenon: Code running tools cannot be selected during tool calling, and no connection configuration entry is available. Cause: Tool calling permissions for the workflow have not been enabled, or the code running tool in the current version must be enabled separately in the plugin market before connection configuration can be performed.

## How to confirm the configuration is complete
- Enter the plugin management interface of FastGPT v4.17.0, and check whether configured public resource trading-related plugins are in an enabled state.
- Initiate a test call, input "Summarize the land use right transaction ledger from the past 7 days", and verify whether the returned results include the preset core business fields.
- Simulate a stream interruption scenario, and check whether the back-end session is automatically cleaned up and no abnormal residual data appears on the front-end page.
- Configure a scheduled pull task, and check whether the ledger data is automatically updated the following day.
