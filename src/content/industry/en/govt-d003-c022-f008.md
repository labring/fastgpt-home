# Ledger Summary and Report Generation for Land Use Rights, Mining Rights, and State-owned Property Transactions: Document Parsing and Chunking

## What this category of data looks like
Data for this category mainly comes from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with a daily update frequency. Commonly processed documents include transfer announcements, trading instructions, bid application documents, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications. Most documents contain fields such as ownership number, target location, transaction amount, and bidding rules. Some documents have multi-level attachments and table structures nested within them.

## What constraints do these characteristics impose on the document parsing and chunking step
The daily batch-updated document volume creates parsing timeliness requirements, requiring adaptation to high-frequency batch processing logic. Multiple types of structured documents and nested attachments require the parser to support mixed-format parsing, while extracting content from tables, multi-level directories, and embedded images. Core fields such as ownership number and transaction amount must be accurately located. Chunking must retain field association relationships to avoid damaging business logic after splitting. Format differences across documents require chunking rules to have flexible adaptability, meeting the length requirements of both long-text transfer announcements and short structured transaction confirmation letters.

## How to set up the configuration
The following is an explanation of configuration items for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the mixed length of long-text announcements and short structured fields in this category of documents, avoiding splitting that breaks core associated information such as ownership and transaction amount |
| `chunkSplitter` | Split by paragraph + title | Matches the multi-level directory and title hierarchy in documents such as trading instructions and transfer announcements, retaining business logic associations |
| `customPdfParse` | Enable external parser adaptation | Supports parsing multi-page tables and encrypted attachments nested in this category of documents, adapting to common transfer announcement PDF formats |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for batch processing of large multi-page property right transfer specifications, avoiding timeout interruptions |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types, adapting to format differences between bid application documents and transaction confirmation letters |

## Three common mistakes
- The key for the external PDF parser is not configured correctly, resulting in an invalid key error during parsing. Some users enter the key into a non-corresponding configuration item, failing to trigger the external parsing logic.
- Multi-level directory content from Feishu documents is not fully parsed. This occurs because the multi-level directory capture switch is not enabled, only top-level directory content is extracted, leading to missing nested clauses in bid application documents and trading instructions.
- Split-related errors occur during Marker parsing. In a Docker deployment environment, the parsing module does not correctly mount the file transfer directory, causing the parsing task to fail to obtain the files to be processed and triggering a parameter missing exception.

## How to confirm the configuration is correct
- Upload a single transfer announcement PDF, check if the parsed text blocks retain the association between titles and corresponding paragraphs, with no split breaks in core fields.
- Batch upload 3 documents of different types: transaction confirmation letter, property right transfer specification, and trading instruction. Confirm that all parsing times do not exceed the set value of `PARSE_FILE_TIMEOUT_SECONDS`.
- Check the external parser configuration items, confirm that the key has been correctly entered into the binding parameters corresponding to `customPdfParse`, with no format errors.
- Test parsing a trading instruction document that contains multi-level directories, confirm that all levels of directories and their corresponding content have been correctly extracted.
