# Student Financial Aid and Subsidy Review: Ledger Summary and Report Generation - Vector Models and Indexing

## What this category of data looks like
Data sources for this category include the national student financial aid management information system, school student registration systems, civil affairs low-income and special hardship data, and fiscal payment systems. Update frequency is once per semester.
Daily processed documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials.
Data fields include student identity identifiers, family economic status information, financial aid qualification levels, disbursement amounts, bank card information, public notification feedback, and more. Most documents are structured tables or fixed-format files. Single documents have strong internal content correlation. Multiple materials for the same student require cross-verification.

## What constraints do these characteristics place on the vector model and indexing workflow?
Multi-source heterogeneous data sources require the indexing process to support unified vectorization of cross-system documents, to avoid field mapping deviations.
Semester-level update frequency requires configurable incremental indexing mode, to reduce repeated computation overhead from full indexing.
Strong field correlation within documents requires retaining core related fields such as student identity identifiers during chunking, to avoid losing contextual correlation after splitting.
Structured table documents require indexing configurations adapted to table column structures, to prevent splitting headers from their corresponding data rows.
The verification requirement for public notification materials and disbursement lists requires index recall precision to meet exact matching standards, to avoid including irrelevant student financial aid records.

## Three common configuration errors
- Phenomenon: After uploading an Excel-format disbursement list, the number of chunks displayed after indexing does not match the estimated number at upload, with duplicate chunks. Cause: Table column recognition configuration is not enabled. The chunking process mistakenly uses line breaks within table rows as chunking criteria, resulting in repeated splitting of content from the same data row.
- Phenomenon: After upgrading from an older version to FastGPT v4.17.0, previously queryable student financial aid records can no longer be retrieved. Cause: The indexing process was not re-run. New version chunking rules or vector model parameters have changed, so old indexing chunk results cannot match the new retrieval logic.
- Phenomenon: Field confusion occurs after merging knowledge base search results, with financial aid information from different students being incorrectly concatenated. Cause: Associated field matching rules are not configured. Retrieval does not group and merge results by student identity identifier, directly concatenating all matched content chunks.

## How to verify correct configuration
- Upload a single family economic hardship certification form, check that the number of indexed chunks matches the estimated number, with no duplicate content chunks.
- Enter a specific student’s identity identifier or financial aid application number for retrieval, confirm that returned results include all associated field information for that student, with no missing or misaligned fields.
- After upgrading to FastGPT v4.17.0, re-index all existing student financial aid documents, verify that original retrieval results can be returned normally.
- Enable the search merging function, retrieve financial aid application records for the same class, confirm that results are grouped and merged by student identity identifier, with no cross-student content concatenation.
