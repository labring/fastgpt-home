# Ledger Summary and Report Generation for Student Aid and Subsidy Review: Document Parsing and Chunking

## What Data Looks Like for This Use Case
Service targets include education bureau aid centers, school student affairs offices or aid offices, and finance departments. Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, distribution lists, public notice materials, and more. Data sources cover national student aid management information systems, school student registration systems, civil affairs low-income and special hardship data, and finance payment systems. Data updates occur on a semester cycle. Most documents are fixed-format forms or bulk lists. Core fields include student identity information, hardship rating, aid amount, bank card number, and others. Cross-system data consistency verification is required.

## Constraints on Document Parsing and Chunking
Most documents use a single-student form or bulk list structure. Parsing and chunking must ensure each chunk contains complete information for one student, and avoid mixing data across multiple students. Uncontrolled mixing will lead to information misalignment during subsequent ledger summary.
Document formats differ across multiple data sources. Different parsing rules must be adapted to ensure accurate extraction of structured fields.
Semester-scale bulk data processing requires the parsing system to support large files or bulk uploads. Chunk granularity must be adjusted to balance parsing efficiency and information completeness.
Aid review errors directly impact student rights and audit compliance. The parsing process must avoid missing fields, content truncation, and similar issues to ensure accuracy of subsequent ledgers and reports.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Matches the content length of single-student forms or single aid distribution list entries, avoids splitting complete information across multiple students into one chunk |
| `chunkSplitter` | Split by title + paragraph | Aligns with the structure separated by titles such as "Student Name", "Family Situation", "Aid Amount" in documents, ensures each chunk contains all information for one student |
| `customPdfParse` | Enabled | Accurately extracts fixed fields from structured PDF documents such as family economic hardship certification forms, improving parsing accuracy for structured data |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports bulk upload of semester-scale distribution lists or review materials, prevents large files from being blocked during parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Accommodates parsing time for bulk documents or large files, prevents timeout interruptions during multi-file bulk uploads |
| `chunkSettingMode` | Manual configuration | Allows flexible adjustment of chunking parameters for different document types such as forms and lists, meets requirements for precise splitting |

## Three Common Configuration Mistakes
- After uploading a file, the parsing node shows no activity. The interface displays the file upload as successful, but the parsing status remains pending for an extended period. The cause is incorrect configuration of `UPLOAD_FILE_MAX_SIZE`. Files exceeding the threshold are blocked and not added to the parsing queue.
- Only partial student aid information is extracted from the parsed document, with remaining fields left empty. The cause is that `chunkSplitter` is configured to split by fixed characters. This leads to incorrect splitting of cross-student form content, and complete information chunks for individual students are not preserved.
- Model output Markdown tables are truncated. Conversations display `...[hide 38432 char]` at the end of the parsed result table. The cause is either `chunkSize` being set too small, leading to incomplete stitching of split long list documents, or `PARSE_FILE_TIMEOUT_SECONDS` being insufficient, causing some parsed content to fail to load fully.

## How to Verify Proper Configuration
- Upload a single family economic hardship certification form PDF. Verify that all preset fields are fully extracted from the parsing result, with no missing content or mixed cross-student information.
- Upload a bulk distribution list document. Check the processing status of the parsing queue, confirm there are no timeout errors or parsing node inactivity.
- Adjust the `chunkSize` parameter. Compare parsing results across different values to ensure complete information for individual students is not incorrectly split.
- Check system logs. Confirm parsing requests are not blocked or interrupted due to `UPLOAD_FILE_MAX_SIZE` or `PARSE_FILE_TIMEOUT_SECONDS`.
- Confirm the current FastGPT version is v4.17.0 to ensure compatibility with configuration items.
