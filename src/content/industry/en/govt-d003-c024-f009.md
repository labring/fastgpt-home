# Student Financial Aid and Subsidy Audit: Ledger Summary and Report Generation — Model Access and Configuration

## What the data for this category looks like
Data for this category comes from the National Student Aid Management Information System, school student registration systems, civil affairs low-income and special assistance data, and fiscal payment systems. The update cycle is one semester. Daily processed documents include family economic hardship assessment forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Fields include student identity identifiers, family economic assessment grades, applied aid types, approval statuses, disbursement amounts, bank card information, and more. Data formats have minor differences across source systems.

## What constraints these characteristics impose on model access and configuration
Multi-source heterogeneous data sources require model access to adapt to field formats of different systems to avoid data mapping errors. The semester-level update frequency means models do not need frequent context refreshes, but must support batch processing of full ledger data for a single semester. Diverse document types include both structured disbursement lists and unstructured public notification materials, requiring configurations that support both text parsing and structured output capabilities. Additionally, incorrect or missing aid disbursements will trigger student complaints and audit issues, so model output accuracy requirements are high, and the value range of generation parameters must be strictly controlled.

## How to Set Configuration Values
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://192.168.1.100:8000/v1` | Connects to locally deployed Qwen3 series models via VLLM, aligns with actual local deployment access scenarios |
| `AIPROXY_API_TOKEN` | Access token generated by local model deployment, leave blank if no verification is required | Adapts to access control rules for locally deployed non-public models |
| `maxTokens` | 8000–12000 token | Processes batch financial aid ledger data for a single semester, including multiple application forms and disbursement lists, to avoid truncation of core content |
| `temperature` | 0.1–0.3 | Ensures accuracy of ledger summary and report generation, reduces the probability of generating content that does not comply with business rules |
| `quoteMaxToken` | 2000–3000 characters | Retains sufficient original fragments of assessment forms and public notification materials for citation and verification in reports |
| `toolChoice` | `auto` | Supports the model in automatically determining whether to call tools to handle field mapping for cross-system data, adapting to processing needs for multi-source data |

## Three Common Configuration Mistakes
- Phenomenon: Model calls return a 404 status code or prompt that the service cannot be connected. Cause: `AIPROXY_API_ENDPOINT` is not configured correctly, the local VLLM service address format is incorrect, or the service is not started normally.
- Phenomenon: Generated ledger reports have empty fields or misplaced data. Cause: Field formats of multi-source systems are not adapted, and the model cannot correctly map student identity identifiers and aid information from different sources.
- Phenomenon: Batch omissions or duplicates appear in summarized ledger data. Cause: No reasonable `maxContext` parameter is set, leading to context overflow and the model losing some input student record data.

## How to Verify a Successful Configuration
- On the FastGPT model management page, select the configured model, enter sample text from a family economic hardship assessment form, execute a test call, and check whether structured parsing results are returned normally.
- Upload a single semester's disbursement list and public notification materials, trigger the ledger summary task, and check whether the task log shows successful model calls with no timeout or connection error prompts.
- Compare generated report fragments with core fields of original data to confirm that key content such as aid amounts and student identity information is mapped correctly.
- Run the model health check tool for FastGPT v4.17.0 to confirm that the connection status to locally deployed Qwen3 series models is normal.
