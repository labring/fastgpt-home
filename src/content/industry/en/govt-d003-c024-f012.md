# Student Subsidy and Award/Compensation Audit: Ledger Summary and Report Generation - Deployment and Upgrade

## Data Profile for This Use Case
Data sources include the national student funding management information system, school student registration system, civil affairs low-income and special hardship data system, and fiscal payment system. Updates occur once per semester. Daily processed documents include family financial hardship assessment forms, subsidy application forms, scholarship and grant review forms, distribution lists, and public notification materials. Data fields include student ID number, family financial status assessment result, applied subsidy type, distribution amount, bank card number, and more. Each document has a fixed field structure. Cross-source data from multiple systems must be linked to complete verification.

## Constraints Imposed on Deployment and Upgrade
Cross-system data sources require compatible access to different data formats during deployment, to avoid data synchronization gaps. Semester-level update frequency requires configuring fixed-cycle incremental synchronization tasks during deployment, to align with the business rhythm of concentrated application submissions during the semester. Fixed document structure requires retaining original field mapping rules during upgrades, to prevent failure of subsidy information verification due to format changes. Errors may lead to incorrect or missed distributions, student complaints, and other issues. A complete failure retry chain and alert mechanism must be configured during deployment to ensure business stability.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://username:password@host:5432/student_subsidy_db` | Meets structured storage needs for student registration and subsidy application data, supports multi-department data isolation |
| `REDIS_URL` | `redis://:custom_password@redis-host:6379/1` | Used to cache frequently queried student registration status and low-income assessment results, reducing cross-system call frequency |
| `STORAGE_S3_ENDPOINT` | Fill in according to the object storage service address of the deployment environment | Used to store unstructured documents such as batch-uploaded family financial hardship assessment forms and public notification materials |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent database connection demands during concentrated application submissions in the semester, avoiding connection exhaustion |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Used to encrypt access tokens for uploaded subsidy-related documents, ensuring sensitive data security |
| `ROOT_KEY` | Configure according to business permission divisions | Used to distinguish subsidy data isolation for different education bureaus and schools, complying with public service data management standards |

## Three Common Configuration Errors
- Running the docker run command to start dependency images results in image pull failures or startup errors. The cause is incorrect connection parameters for `REDIS_URL` or `PG_URL`, preventing dependent services from initializing properly.
- After upgrading to FastGPT v4.17.0, an error of cannot fetch internal url is displayed when creating a knowledge base using a URL. The cause is failure to configure `FE_DOMAIN` as a valid internal service domain name, leading to failed internal resource access permission verification.
- The file processing plugin cannot be found in the backend. The cause is incorrect configuration of `FILE_TOKEN_KEY` leading to failed plugin permission verification, or a mismatch between the deployment version and plugin version.

## How to Verify Successful Configuration
- Run the database connection test command to verify that the configurations for `PG_URL` and `REDIS_URL` can establish normal connections. The connection status must show normal.
- Upload a standard family financial hardship assessment form, check that the file can be parsed normally and associated with the corresponding subsidy data fields, with no missing parsing results.
- View system logs to confirm there are no error messages of the cannot fetch internal url type, and internal resource access links are normal.
- Manually trigger a semester-level synchronization task, check that cross-system data can be pulled normally and stored in the corresponding database.
