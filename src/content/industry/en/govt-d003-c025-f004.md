# Ledger Summary and Report Generation for Work Safety Hazard Inspection and Governance: Workflow Orchestration

## What Data for This Category Looks Like
Data sources for this category include work safety supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily circulated documents include hazard inspection checklists, hazard governance ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Core fields include hazard identifier, inspection subject, rectification responsibility subject, rectification time limit, review conclusion, and supervision level. All fields follow standard business formats, with no custom units.

## Constraints for Workflow Orchestration
Data sources for this category are scattered, covering multiple business systems and digitized record content. This requires configuring multi-source data pull nodes in workflow orchestration to connect to different data sources separately. The daily update frequency requires setting a scheduled trigger mechanism for the workflow to ensure timely data synchronization. Field structures vary across different document types. A field mapping step must be added during orchestration to unify the format standards of data from each source. Information dimensions differ between law enforcement inspection records and enterprise self-inspection data. A data validation node must be added to filter invalid entries missing core fields. Multi-source data aggregation must use hazard numbers as the association key to avoid duplicate statistics of hazard entries.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled trigger cycle | Fixed time window between 00:00 and 02:00 daily | Matches the daily update frequency of data for this category, and avoids peak business hours |
| Multi-source data pull configuration | Pull the four categories of data sources sequentially using hazard numbers as the association key | Meets the multi-source data aggregation requirements for this category, and ensures complete association of hazard data |
| Field mapping rules | Unify hazard identifier fields from each data source to hazard ID | Unifies field formats across different documents, eliminating statistical errors caused by data differences |
| Data validation rules | Filter entries missing the `rectification deadline` and `review result` fields, set a 600-second timeout | Covers the validation requirements for core business fields of this category, and prevents execution interruptions |
| `variables` variable configuration | Bind `hazard inspection scope` and `supervision level` as adjustable parameters | Adapts ledger summary requirements for different scenarios, eliminating the need to repeatedly modify the workflow |
| `nodeId` node binding configuration | Assign a unique ID to each data pull node | Ensures correct call order for each node in the workflow, and avoids node call confusion |

## Three Common Misconfigurations
- The output of an HTTP request node does not appear in the final report. This occurs when the output corresponding to the node's `nodeId` is not bound to the `variables` variable, or when the bound variable is not connected to the final report generation step.
- Duplicate hazard entries appear after multi-source data pull. This occurs when data aggregation is not performed using hazard numbers as the association key, leading to duplicate counting of the same hazard from different data sources.
- Workflow execution times out, causing ledger summary to fail. This occurs when a reasonable timeout is not set, or when too many data sources are pulled simultaneously, causing data processing volume to exceed the node's carrying capacity.

## How to Verify Correct Configuration
- Manually trigger the workflow, check the running logs of each node, confirm that multi-source data pull, field mapping, and data validation steps all execute successfully.
- Check the `variables` variable binding configuration, confirm that the filter parameters for ledger summary can be adjusted when the workflow starts.
- Check the `nodeId` binding configuration, confirm that each data pull node has a unique and correct ID.
- Generate a test report, verify that the hazard entries in the report match the original data from each data source.
