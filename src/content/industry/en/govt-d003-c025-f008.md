# Ledger Summary and Report Generation for Safety Production Hazard Inspection and Management: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for this category originates from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily.
Commonly processed documents include hazard inspection lists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Most document structures include fields such as hazard number, rectification responsible entity, rectification deadline, and review result. Some documents include on-site photos or scanned copies.

## Constraints for Document Parsing and Chunking
Daily updated multi-source heterogeneous data requires parsing workflows to have stable batch processing capabilities. This prevents single-file parsing timeouts from delaying overall ledger summary progress.
Document formats vary widely across different sources. These include structured table ledgers and rectification documents with scanned copies. Chunking must retain field association relationships. This avoids splitting hazard number, rectification deadline, and other linked fields for the same hazard into different chunks.
Some documents include on-site evidence photos. Parsing workflows must associate text and image content simultaneously. This ensures full presentation of hazard scenes during subsequent report generation.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Documents in this category often include linked fields. This range ensures a single chunk contains a complete hazard entry or core information for a single rectification document, avoiding field splitting |
| `chunkSplitter` | Paragraph-based + semantic chunking | Hazard ledgers and rectification documents have tight logical links across paragraphs. Semantic chunking preserves context integrity, making it easier to associate hazards and rectification records during subsequent summarization |
| `customPdfParse` | Enable structured parsing mode | Documents in this category are mostly standardized forms or ledgers. Structured parsing accurately extracts table fields, avoiding text garbling or field misalignment |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Rectification documents with multi-page scanned copies or bulk ledger files take longer to parse. This duration covers most large file parsing requirements |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Some park management committees need to bulk upload monthly hazard inspection summary files. This upper limit supports bulk processing needs |
| `chunkSettingMode` | Manual configuration | Document formats vary widely across sources for this category. Manual configuration allows flexible adjustment of chunking rules to adapt to different source document structures |

## Three Common Mistakes
1. After calling the knowledge base creation API, no status feedback is returned for parsing in progress, ready, or parsing failed. Cause: The status query interface was not called correctly, or relevant parameters for API status returns were not configured.
2. After uploading a PDF document with images, the generated chunk content does not include image-associated information. Cause: The image parsing mode of `customPdfParse` was not enabled, so image content was not extracted.
3. When parsing hazard data obtained via an HTTP interface, the Set-Cookie field in the response header was not processed correctly. Cause: Custom parsing rules to extract target fields from the response header were not configured, resulting in incomplete data parsing.

## How to Verify Proper Configuration
- Upload a single PDF hazard ledger with multiple fields. Confirm that parsed chunks retain linked fields such as hazard number and rectification deadline for the same hazard.
- Call the API to submit a parsing task. Use the query interface to verify that status feedback for parsing in progress, ready, and parsing failed is available.
- Upload a rectification notice with on-site photos. Confirm that generated chunk content includes image-associated text and corresponding identifiers.
- Upload a bulk hazard file exceeding the default size. Confirm that the system does not return a file too large error, or processes the file normally per the configured `UPLOAD_FILE_MAX_SIZE`.

The values provided here are common starting points, and should be evaluated against the samples of the respective users.
