# Ledger Summary and Report Generation for Safety Production Hazard Inspection and Governance: Deployment and Upgrade

## What data for this category looks like
Data for the safety production hazard inspection and governance category comes from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. Daily processed documents include hazard inspection lists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Fields cover hazard numbers, inspection times, rectification responsible persons, rectification deadlines, and review results. The update frequency is daily. Data covers business processes across multiple entities, including emergency management departments and production and business unit safety management departments. All documents from inspection, rectification to review must be included in the summary and report generation process. Most field types are dates, text, and status identifiers. There is no unified fixed format for a single scenario.

## What constraints these characteristics impose on deployment and upgrades
Daily updated data sources require stable scheduled synchronization tasks during deployment to avoid data delays or loss. Multiple types of documents without unified formats require adaptation to different parsing rules. Field mapping templates must be preset during deployment. Data sources from multiple systems require configuring authentication and connection parameters for cross-system docking. Upgrades must be compatible with old data formats to prevent field confusion. Since error consequences include major accidents, production suspension for rectification, administrative penalties, or criminal liability, data verification and failure alert mechanisms must be configured during deployment and upgrade to ensure data accuracy. Ledger and report generation must associate field information from multiple documents. The association logic of each document must be clarified during deployment. Upgrades require testing the stability of the full-process data link.

## Three common mistakes
- A prompt appears after startup indicating incompatible MongoDB versions, with an error message containing “unsupported wire version”. The cause is using the default MongoDB 5.x image without adapting to server environments that do not support AVX instruction sets. Replace the `mongo:4.4.29` image and adjust the `MONGODB_URI` configuration.
- External supervision system data cannot be synchronized after offline deployment. The interface displays a synchronization task timeout. The cause is failure to configure parameters such as `REDIS_URL` or `STORAGE_S3_ENDPOINT`, leading to interrupted data caching and synchronization links, and inability to complete cross-system data pulling.
- Some rectification record fields are missing from the generated ledger report. The page displays empty fields. The cause is failure to correctly map the fields of the hazard management ledger to the system-collected data fields during deployment, and failure to complete field matching configuration, resulting in inability to associate corresponding data during summary.

## How to confirm the configuration is complete
- Log in to the FastGPT v4.17.0 system backend, check the `MONGODB_URI` configuration item, and confirm that the image version matches the parameter.
- Trigger a daily synchronization task, check the system logs, and confirm that there are no connection timeout or data loss error messages.
- Generate a hazard ledger report, check the correspondence between document fields and original collected data, and confirm that the field mapping rules take effect.
- Upload a rectification notice attachment, confirm that the `STORAGE_S3_ENDPOINT` configuration can normally store files, and there are no upload failure prompts.
