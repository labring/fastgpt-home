# Ledger Summary and Report Generation for Engineering Construction Project Approval: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
The data for this category comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. It has a daily update frequency.
Commonly processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion acceptance record forms.
Each document contains fields such as project identification, construction unit information, approval node status, and corresponding qualification document number. Some fields use square meters as the unit. Number-type fields have no fixed unit.
The data structure is organized around the full approval process of a project from initiation to completion acceptance.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering link
Multi-turn dialogue must clearly specify the scope of systems to call. This avoids mixing data from other categories, addressing multiple data source requirements.
Any triggered dialogue must first retrieve the latest approval node and material information. This prevents expired data from being used, aligning with the daily update frequency.
Prompts must strictly limit the document types and extraction fields to be processed. This avoids confusing content from different approval stages, due to multiple document and field types.
Multi-turn dialogue must guide users to provide materials step by step according to approval nodes. This addresses the most time-consuming integration and verification steps.
Prompts must focus on the core tasks of ledger summary and report generation. They must not expand to unrelated business scopes.

## Configuration guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Context window size | First 8000–12000 characters | Matches the total length of documents related to engineering construction project approval, to avoid truncating key approval fields |
| `variables` | Pre-set project ID, approval node type | Fixes core identifiers for extracting specific ledgers, reducing repeated input during multi-turn dialogue |
| `messages` | Append approval node records by conversation turn | Retains submission status of approval materials for each round, for subsequent context association in report generation |
| `chatId` | Bind unique session identifier for the corresponding project | Ensures multi-turn dialogue data for the same project is not mixed, facilitating subsequent ledger archiving and querying |
| Prompt template | Limit processing to only specified documents such as construction permits and construction drawing reviews | Avoid processing unrelated data, focusing on the business scenario of this category |

## Three common configuration errors
- Phenomenon: Dialogue return results include content unrelated to engineering construction approval, and core approval fields are missing. Cause: The document types to be processed are not clearly defined in the prompt, leading to the calling of information from unrelated data sources.
- Phenomenon: The top title of the embedded dialogue page is accidentally modified, and cannot be restored through conventional settings. Cause: The page title parameter is not locked in the embedded configuration, leading to front-end rendering overwriting the preset exclusive title.
- Phenomenon: Reports generated via multi-turn dialogue include unspecified fields, deviating from ledger summary requirements. Cause: The `messages` parameter does not fully append context by conversation turn, leading to the loss of prior prompt constraints in subsequent dialogue.

## How to verify a correct configuration
- Initiate a test dialogue, enter the approval query instruction for the specified project, and check that the returned results only include document content related to engineering construction approval.
- View the `chatId` parameter of the session, confirm that multi-turn dialogue for the same project is bound to the same identifier, and no cross-project mixing of ledger data occurs.
- Trigger the report generation action, check that the output content only includes the fields specified in the preset `variables`, with no additional unrelated content.
- Verify the data update frequency, initiate a dialogue and query the daily approval node information, and confirm that the returned data is the latest updated data from the current day.
