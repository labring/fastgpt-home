# Ledger Summary and Report Generation for Engineering Construction Project Approval: Tool Calling and Plugins

## What the data for this category looks like
Data for this category mainly comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform, with a daily update frequency. Documents processed daily include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. Data fields are configured around the full project approval process, covering project identifiers, construction unit information, participating unit qualifications, approval node status, and more. Each document is bound to the unique identifier of the corresponding project, and the data structure is tightly linked to the approval workflow.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Data for this category is multi-sourced and updated daily, requiring tool calling to adapt to multi-system data pulling and prevent cross-system data inconsistency. There are various document types processed daily, so text extraction tools must support approval materials in different formats to ensure complete field extraction. The requirement that data is bound to a unique project identifier means tool calling must accurately pass the project ID as a parameter to avoid ledger data confusion. The data structure tightly linked to the approval workflow requires tool calling to support filtering data by approval node to ensure the correspondence between summary reports and workflow links, while also handling differences in data formats returned by different systems to ensure a unified ledger structure after integration.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapt to multi-tool calling scenarios, automatically matching the tool types required for the approval workflow |
| Text extraction tool format support | Supports PDF, Word, and scanned document formats | Daily approval documents include multi-format materials such as construction permit applications and construction drawing review qualification certificates |
| `functionCall` | `enabled` | Requires calling external systems to obtain real-time approval data and generate structured ledgers and reports |
| Data source synchronization interval | `86400 seconds` | Matches the daily update frequency of this category's data, ensuring the timeliness of ledger data |
| Number of items returned per tool call | `Top 20 items` | Adapts to the scale of single-project approval data, avoiding exceeding context length limits |
| Tool call timeout threshold | `600 seconds` | Reserves sufficient time to complete multi-source data pulling and format conversion, preventing call timeouts |

## Three common configuration errors
- Phenomenon: When calling a large language model that only supports stream mode, an `error` message appears in the interface, and the call log shows abnormal data acquisition. Cause: Stream mode adaptation is not enabled in the model configuration, causing the model return format to not match the platform requirements.
- Phenomenon: The text extraction tool returns the `400 Invalid JSON payload. Unknown name` error. Cause: Undefined field parameters are passed during tool calling, which does not comply with the field specifications for approval document extraction.

## How to verify that the configuration is complete
- Trigger a tool call, check if the returned approval data includes the project unique identifier, and confirm that the project ID binding configuration is effective.
- Upload approval documents in different formats, verify that the text extraction tool can correctly extract the corresponding fields, and confirm that the format adaptation configuration is effective.
- View the model call log, confirm that the `toolChoice` and `functionCall` parameters are correctly passed with no format errors.
- Manually trigger data source synchronization, check if the synchronized ledger data matches the daily updated data of external systems, and confirm that the synchronization interval configuration meets business requirements.
