# Ledger Summary and Report Generation for Engineering Construction Project Approval: Deployment and Upgrade

## What Data for This Category Looks Like
This category of data originates from engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases, and credit platforms.
Daily processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms.
These cover both structured business fields and unstructured attachments.
Data is updated daily.
Core fields include project number, participating unit name, approval node status, and qualification verification result.
Field names and formats differ across various source systems.

## Constraints Imposed on Deployment and Upgrade
Support parallel configuration of multiple databases and storage services during deployment. This addresses the need to connect multiple data sources and avoids performance bottlenecks from a single data source.
Configure incremental synchronization tasks during deployment. This matches the daily data update rhythm and reduces resource usage from full data pull operations.
Retain a field mapping configuration entry during upgrades. This adapts to field differences across systems and accommodates future version updates of approval systems.
Configure a dedicated file storage service during deployment. This meets the storage requirement for unstructured attachments and ensures reliable document storage and access.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://user:pass@host:5432/eg_approval` | Connects structured business data from engineering construction project approval management systems, uses PostgreSQL to store core ledger fields |
| `REDIS_URL` | `redis://:pass@host:6379/0` | Stores incremental synchronization markers for daily updated data and approval node status caches, reduces query pressure across multiple systems |
| `STORAGE_S3_ENDPOINT` | Configure according to local storage node or cloud storage service provider address | Stores unstructured documents such as construction drawing review qualification certificates and completion record forms, supports upload of multiple types of attachments |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent connection requirements for daily incremental synchronization across multiple systems, prevents database connection exhaustion |
| `FILE_TOKEN_KEY` | Generate according to business encryption rules | Generates temporary access tokens for ledger attachment downloads, ensures document access security |

## Three Common Misconfigurations
- Symptom: The participating unit qualification field is empty when calling the ledger generation API. Cause: The `PG_URL` was not configured to connect to the enterprise qualification database data source, resulting in missing field associations.
- Symptom: Docker containers remain in a starting state for an extended period after startup. Cause: The `REDIS_URL` was not configured correctly, causing a failure to connect to the cache service and blocking the initialization process.
- Symptom: Approval data from the website cannot be synchronized after local deployment. Cause: The access permissions for the data source corresponding to `STORAGE_S3_ENDPOINT` or `PG_URL` were not configured, resulting in an interrupted data synchronization link.

## How to Verify Correct Configuration
- Run a database connection test script to confirm that data sources configured via `PG_URL` and `REDIS_URL` can be accessed normally.
- Trigger a daily incremental synchronization task, then check whether the ledger data includes the latest approval node status.
- Generate a ledger report for a pilot project, confirm that all associated document attachments can be downloaded normally.
- Use the FastGPT v4.17.0 system log query function to confirm that there are no error messages about database connection exhaustion or cache service timeouts.
