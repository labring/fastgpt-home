# Tender and Bidding for Engineering Construction Projects: Ledger Summary and Report Generation — Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from national public resource trading platforms, local trading platforms, project approval systems, and bidding supervision systems. The update frequency is daily. Daily documents include tender announcements, qualification prequalification documents, bidding documents, bid documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements. Data fields cover section identification, qualification requirements, bid evaluation expert records, successful bid candidate information, and more. All documents have fixed structures and require associated validation per relevant bidding rules.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Daily updated data sources require the dialogue flow to support incremental data pulling and real-time validation. Multiple fixed-structure documents require prompts to adapt to exclusive field extraction rules for different document types. The accuracy of core fields such as sections and qualification requirements requires multi-turn dialogue to gradually verify key information, avoiding errors in splitting sections or qualification conditions. Associated validation of bid evaluation reports and successful bid results requires the dialogue flow to link documents from different data sources, ensuring consistency in ledger summary. Differences in field requirements between engineering construction projects and government procurement must be distinguished, with focus placed on exclusive fields such as qualifications, performance records, and bill of quantities.

## Three Common Misconfigurations
- Workflow automatically returns to the question classification start point after reaching the AI dialogue node. Phenomenon: The workflow resets to the classification node after multi-turn dialogue completes. Cause: Session context branch jump rules are not configured correctly, leading to loss of session state.
- Output from HTTP request orchestration is not displayed in the dialogue interface. Phenomenon: After calling an interface to obtain bid evaluation data, no corresponding output content appears in the dialogue panel. Cause: The output of the HTTP node is not bound to session variables, leading to results not being synchronized to the dialogue context.
- Qualification condition content extracted via multi-turn dialogue has deviations. Phenomenon: The qualification conditions returned by the AI do not match the original document text. Cause: The prompt is not optimized for the fixed structure of qualification prequalification documents, leading to incorrect field extraction.

## How to Verify Proper Configuration
- Import a local bidding document, trigger multi-turn dialogue, check whether core fields such as section number and qualification conditions can be accurately extracted.
- Simulate daily incremental data pulling, verify whether the dialogue flow can automatically associate the latest successful bid result announcement data.
- After testing the HTTP node call, check whether the dialogue interface displays the bid evaluation report content returned by the interface.
- Switch between different bidding document branches, verify whether the workflow jumps to the corresponding knowledge base via preset variables, with no repeated triggering of the classification node.

Note: The values listed above are common starting points. Adjust them based on your own specific samples and requirements.
