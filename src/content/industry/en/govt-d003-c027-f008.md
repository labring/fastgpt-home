# Tender Bidding for Construction Projects: Ledger Summary and Report Generation - Document Parsing and Chunking

## What this category of data looks like
Core data for this category comes from national public resource trading platforms, local trading platforms, project approval systems, and bidding supervision systems, with a daily update frequency. Daily processed documents include tender notices, pre-qualification documents, bidding documents, bid documents, bid evaluation reports, successful candidate announcements, and successful bid result announcements. Involved entities include development and reform departments, industry competent departments such as housing and urban-rural development, transportation, and water conservancy, public resource trading centers, and bidding agencies. Documents contain dedicated fields such as section number, qualification requirements, bill of quantities, construction period, and expert bid evaluation records. Supported formats include PDF, DOCX, and web-based announcements.

## What constraints do these characteristics impose on the document parsing and chunking process
High-frequency daily batch document updates require the parsing process to have efficient adaptation capabilities. The differentiated structures of multiple document types require chunking rules to match hierarchical logic, avoiding splitting critical business information. Dedicated fields such as section numbers, qualification requirements, and bills of quantities must be fully retained in the chunk context. Failure to retain these fields will reduce the accuracy of subsequent ledger summary and report generation. Format differences across document sources may cause parsing deviations, so parsing rules tailored to bidding-specific documents must be configured. Additionally, parsing time for large bid documents must be addressed to avoid timeouts disrupting business processes.

## How to configure the settings
For FastGPT v4.17.0, use the following configuration items to adapt document parsing and chunking:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to long text blocks such as bills of quantities and qualification requirements in bidding documents, retaining contextual associations |
| `chunkSplitter` | Split by title + paragraph | Matches the hierarchical structure of tender notices and bid evaluation reports, avoiding splitting critical content such as sections and expert records |
| `customPdfParse` | Enabled | Processes PDF-format bidding documents and bid evaluation reports, retaining original layout and chapter titles |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for large bid documents and bid evaluation reports, avoiding timeout failures |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports upload requirements for multi-section joint bid documents |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types, adapting to special fields such as qualifications and bills of quantities |

## Three common configuration mistakes
- Symptom: After server deployment, uploading DOCX or PDF bidding documents results in a 404 error from the document parsing node, and file content cannot be read. Cause: The server environment lacks corresponding document parsing dependencies, or the upload path has insufficient permissions to access files.
- Symptom: RAG retrieval results do not include chapter title information, only returning scattered body content. Cause: The chunking configuration does not enable retaining title context, or `chunkSplitter` is not set to split document structures by hierarchy.
- Symptom: Auxiliary data in parsed chunks is not included in the retrieval matching scope, only matching main body content. Cause: The chunking configuration does not include auxiliary fields such as section numbers and qualification requirements, or `chunkSettingMode` does not enable auxiliary data retention logic.

## How to confirm the configuration is correct
- Upload a standard tender notice PDF, check the parsed chunk results, and confirm that chapter titles and corresponding body content are correctly associated as a single chunk unit.
- Upload a large bid document containing multiple sections, wait for parsing to complete, and check for system prompts about timeout or file size exceeding limits.
- Initiate a RAG retrieval, enter the keyword "qualification requirements for a certain section", and confirm that the retrieval results include the title and specific content of the corresponding chunk.
- Batch upload multiple different types of bidding documents, verify that all parsing statuses show success with no abnormal errors.

The values provided are common starting points and should be evaluated against the user's own samples.
