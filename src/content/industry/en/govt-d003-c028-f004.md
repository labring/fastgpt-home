# Ledger Aggregation and Report Generation for Market Entity Registration and Licensing: Workflow Orchestration

## What the data for this category looks like
Data for market entity registration and licensing comes from the enterprise registration full electronic system, national enterprise credit information disclosure system, electronic business license system, and residence information database. The update frequency is daily. Commonly processed documents include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and more. Data fields cover entity name, unified social credit code, registration date, license type, residence information, shareholder information, and others. The unified social credit code uses an 18-character format, and the registration date uses the YYYY-MM-DD standard format. All types of documents include clear applicant subject and material attribute fields.

## What constraints these characteristics impose on the workflow orchestration link
The multi-source and scattered nature of the data requires the workflow to configure multiple nodes to pull data from different systems, and adapt to different return formats. The daily update frequency requires trigger nodes to be set to run at fixed daily time periods, to avoid peak business hours and reduce system load. The diverse document types require the document parsing node in the workflow to have general adaptation capabilities, to handle application materials in different formats. The severe consequences of errors require the workflow to configure clear exception branches, to quickly trigger correction processes when verification fails, and avoid issues such as registration rejection or fraudulent registration.

## How to set the configurations

| Config Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Scheduled Trigger Cycle | Run once daily between 02:00–04:00 | Matches daily data update frequency, avoids peak business hours, reduces system resource usage |
| Multi-data Source Variable Configuration | Pull the 4 data source types defined by `variables` in sequence | Unified management of data source parameters, adapts to data sources from enterprise registration, credit information and other systems |
| Document Parsing Threshold | Calibrate based on actual testing | Adapts to diverse business document formats such as establishment registration applications and articles of association |
| Exception Node Association Rule | When the verification node returns a failure, associate the node with `nodeId` as the correction notification | Quickly trigger the correction process, reduce business risks caused by errors |
| Code Run Timeout Setting | 120 seconds | Reserve sufficient time to complete multi-dimensional material verification and comparison |

## Three common mistakes
- Phenomenon: The workflow returns a parameter mismatch error when calling the code node, and the log shows that the body parameter name does not match the expected one. Cause: Failed to define the correspondence between parameter names and values through `variables`, mistakenly passed a file link as the parameter name.
- Phenomenon: The knowledge base search node fails to correctly load the specified knowledge base data. Cause: Did not bind the passed knowledge base ID to the search node configuration corresponding to `nodeId`, breaking the parameter transfer link.
- Phenomenon: The code node returns no streaming output content after running. Cause: Did not configure chunked return rules in the code logic, and did not output streaming data as required by the workflow.

## How to confirm the configuration is complete
- View the scheduled trigger logs of the workflow to confirm that it automatically starts execution at the fixed daily time period.
- Manually trigger the multi-data source pull node to verify that the acquired fields match the fields of the business documents.
- Simulate a verification failure test scenario to confirm that the exception branch triggers the correction notification node.
- Run the code node to verify that the parameter transfer and streaming output logic work normally.
