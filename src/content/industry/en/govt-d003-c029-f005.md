# Ledger Summary and Report Generation for Urban Sanitation and Urban Management Law Enforcement Cases: Tool Calling and Plugins

## What the data for this category looks like
The data for this category typically comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders. The update frequency is daily. Daily documents include inspection records, case filing approval forms, on-site photos, rectification notices, penalty decisions, and case closure reports. Data fields include case number, inspection time, violation type, responsible entity, rectification progress, case closure status, etc. A single piece of data is associated with multiple types of files, and there is no fixed unified structured format.

## What constraints do these characteristics impose on the tool calling and plugins link
Daily updated data requires that tool calling be configured with a scheduled trigger mechanism to avoid missing same-day cases. Cross-platform data from multiple sources requires plugins to adapt to the interface formats of different platforms to enable cross-system data pulling. Mixed data of multiple types of unstructured documents and images requires plugins to support multi-format parsing and content extraction. The feature of non-unified field structures requires adding a field mapping step during tool calling to standardize case data from different sources into the format required for ledgers. For time-consuming links such as on-site evidence location and violation type judgment, dedicated tool plugins can be called to simplify the processing flow.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Allows the model to independently select tools adapted to the case type, flexibly handle multi-source data |
| Scheduled trigger cycle | 24 hours | Matches the daily update frequency of data for this category, ensures that same-day cases are included in the ledger in a timely manner |
| Cross-platform data pulling plugin | Bind MCP services for urban management law enforcement platforms and grid platforms | Adapts to the data source channels of this category, enables multi-system data synchronization |
| Multi-format parsing plugin | Plugin that supports document and image parsing | Covers content extraction for multiple types of business documents such as inspection records and on-site photos |
| Field mapping rules | Calibrated based on actual testing | Fields of case data from different sources vary, adjustments must be made based on actual accessed data |
| `functionCall` | Enable forced mode (for standardized ledger links) | Ensures the stability of tool calling for fixed-process report generation links |

## Three common mistakes
- Symptom: Empty results returned after calling the MCP service. Cause: The proxy endpoint of the MCP service was not configured correctly, making it impossible to connect to the urban management law enforcement platform data source.
- Symptom: Tool calling times out, and the task fails. Cause: No reasonable timeout period was set, or too many cross-platform case data were pulled at the same time, exceeding the plugin processing limit.
- Symptom: Missing fields in the generated ledger. Cause: No field mapping rules were configured, and case data from different sources were not standardized to the format required for the ledger.

## How to confirm that the configuration is complete
- Manually trigger a tool call, check whether case data from the current day can be pulled, and verify that cross-platform data source connections are working properly.
- Upload a typical inspection record and on-site photos, check whether the plugin can correctly parse and extract case-related fields.
- View the tool calling logs, confirm that the trigger logic of `toolChoice` or `functionCall` matches the configured expectations.
- Run a complete ledger summary process, check whether the generated report includes all required case information.
