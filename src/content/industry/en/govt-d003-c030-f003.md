# Construction Engineering Quality and Safety Supervision: Ledger Summary and Report Generation — Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category originates from the engineering quality and safety supervision system, on-site construction real-name management platform, supervision logs, and test reports. The update frequency is weekly. Daily documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Each document contains core fields such as project subject, inspection items, rectification status, and acceptance conclusion. Field units use common engineering management units such as item, copy, and day. The length of individual documents varies widely: supervision inspection records are usually hundreds of characters, while completion acceptance supervision reports can reach thousands of characters.

## Constraints for Multi-turn Dialogue and Prompt Engineering Links
Weekly updated data sources require multi-turn dialogue to support filtering ledger data by cycle, preventing calls to expired information. Differentiated fields across multiple document types require prompts to clearly define recognition rules for each document type, avoiding confusion between the field logic of hidden danger rectification notices and completion acceptance supervision reports. Decentralized data sources require dialogue flows to guide users to specify document types clearly, reducing information matching errors. Additionally, the potential severity of quality and safety-related errors requires prompts to include rigor verification guidance, ensuring the accuracy of summarized data and avoiding omissions of rectification closed-loop information.

## How to Configure
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Maximum context length | 8000–12000 characters | Individual completion acceptance supervision reports for this category can reach thousands of characters. Multi-turn dialogue must retain the context of recent sets of supervision records. |
| Question optimization | Enabled | This category requires standardized organization of users' ledger query requirements to adapt to the field rules of multiple document types. |
| `variables` binding | Bind two variables: project name and inspection cycle | Data for this category is categorized by project and cycle. Variables enable accurate filtering of target ledgers and reduce retrieval redundancy. |
| `messages` context truncation threshold | Retain the last 10 rounds of dialogue | Weekly updated ledger data does not require retaining expired dialogue context, avoiding redundant interference with retrieval efficiency. |
| Single search limit | Top 5 matching results | Ledger entries for this category are updated weekly. The number of entries per cycle is limited, and too many results will increase summary time. |
| `chatId` session isolation | Bind chatId to project ID | Ledger data for different projects is independent. Session IDs isolate dialogue contexts for different projects. |

## Three Common Configuration Errors
- After enabling input guidance and configuring a custom thesaurus, an error appears in the debug preview interface dialogue, with a prompt indicating that prompt-related fields are empty. The cause is that the project name variable bound to `variables` is not correctly configured, causing the dialogue to fail to recognize the filtering conditions for the target ledger.
- The maximum response token for a specific question automatically changes to 200, resulting in overly short reply content. The cause is that the global maximum response token is not locked in the system settings, or there are implicit length restriction rules in the prompt.
- The number of retrieved results does not match expectations, with redundant non-target documents appearing. The cause is that the document type is not clearly limited via the `messages` context, causing retrieval to match irrelevant supervision plans or supervision logs.

## How to Verify Correct Configuration
- Enter a query request for weekly supervision inspection records of a specified project, and check whether the returned ledger data includes documents from the corresponding cycle.
- Launch multiple consecutive queries, and confirm that the session context bound to `chatId` retains the project filtering conditions from previous rounds.
- Enter a composite query containing hidden danger rectification and acceptance content, and check whether the prompt can distinguish the fields of the two document types and summarize them correctly.
- Test a dialogue that exceeds the preset context length, and confirm that the system truncates redundant content according to the configuration.
