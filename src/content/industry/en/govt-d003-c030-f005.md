# Ledger Summary and Report Generation for Construction Engineering Quality and Safety Supervision: Tool Calling and Plugins

## What the data for this category looks like
This category of data covers daily business documents from construction quality and safety supervision stations, construction units, supervision units, and construction units. These documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports.
Data originates primarily from the project quality and safety supervision system, construction site real-name management platform, supervision logs, and test reports. The update frequency is once per week.
Documents include fields such as inspection date, rectification deadline, problem description, and acceptance conclusion. Some test reports contain numeric test results, which must be matched with actual units corresponding to each test item.

## Constraints imposed by these characteristics on the tool calling and plugins link
Data for this category originates from multiple dispersed sources. Calling plugins from multiple different systems is required to obtain this data, which imposes high compatibility requirements on plugins.
Multiple document types exist. Distinct processing logic must be adapted for text-based ledgers and multimodal test reports.
The update frequency is once per week. Fixed periodic triggers are required for tool calls to avoid excessive resource consumption from overuse.
Some data requires transfer across entities. Tool calls must support permission verification links to ensure compliance with data access regulations.
Errors in quality and safety related data can lead to serious consequences. A failure retry and abnormal alert mechanism must be configured.
This configuration is based on the plugin and tool calling logic of FastGPT v4.17.0.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic calling needs for multiple types of business documents and multiple data sources, no manual tool specification required |
| `functionCall` | Allow batch calls | Supports pulling multiple ledger data entries simultaneously, improving summary efficiency |
| Single search limit | Top 3 entries | Matches the volume of ledger data updated weekly, avoids redundant information interfering with report generation |
| Timeout threshold | 600 seconds | Covers the maximum time required to pull data across supervision systems and real-name management platforms, prevents task interruptions |
| Number of failure retries | 2 times | Balances call success rate and resource consumption, adapts to occasional connection issues with dispersed data sources |
| Plugin call scope | Only allow designated quality and safety supervision plugins | Prevents unauthorized plugins from accessing sensitive business data, complies with industry data security requirements |

## Three common errors
- Phenomenon: An error stating the model is not supported is returned when calling the `toolChoice` function, with a status code of 400. Cause: The currently used model has not been verified to be compatible with the `toolChoice` function. Some lightweight models do not support this configuration.
- Phenomenon: No valid results are returned after calling an external search plugin, and missing ledger information cannot be supplemented. Cause: The selected external plugin is not adapted to the domestic network environment, or correct proxy parameters have not been configured.
- Phenomenon: Multimodal test reports cannot be parsed correctly, but pure text-based ledgers can be summarized normally. Cause: Differentiated tool calling logic has not been configured for different document types. The processing paths for multimodal and pure text data have not been distinguished.

## How to confirm the configuration is complete
- Launch a simulated ledger summary task, check the tool call logs, and confirm that the `toolChoice` function automatically triggers the corresponding data source plugin.
- Review the plugin call scope configuration, confirm that only quality and safety supervision plugins are allowed to be called, and no unauthorized plugins are enabled.
- Simulate an abnormal call, check whether the failure retry and abnormal alert mechanism is triggered, and confirm that the retry count configuration is active.
- Upload a multimodal test report and a pure text inspection record separately, confirm that both types of data can be processed correctly and included in the summary report.
