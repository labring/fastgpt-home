# Bill Summary and Report Generation for Construction Engineering Quality and Safety Supervision: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from engineering quality and safety supervision systems, on-site construction identity management platforms, supervision logs, and test reports. The update frequency is weekly.
Daily documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality issue handling forms, and completion acceptance supervision reports. Fields include project unique identifier, inspection time, rectification requirements, closed-loop confirmation mark, acceptance node, and other standard items, with no custom units added. The data structure is built around the full on-site construction supervision workflow, covering all stages of plan formulation, process inspection, hidden danger closed-loop management, and acceptance management.

## What constraints these characteristics impose on deployment and upgrade
Multiple and scattered data sources require reserving configuration space for interfacing with multiple systems during deployment, and ensuring the extensibility of storage configurations such as `PG_URL` and `REDIS_URL`. The weekly update frequency requires properly configuring the scheduled task trigger period during deployment to avoid data synchronization timeouts.
Documents have closely linked fields, so compatibility of field mapping between old and new versions must be ensured during upgrades to prevent loss of ledger data. Documents covering the full supervision workflow involve construction-sensitive information, so `FILE_TOKEN_KEY` must be configured during deployment to secure document access permissions and avoid sensitive data leaks.
When upgrading across versions, verify the compatibility between old ledger fields and new configuration to prevent report generation abnormalities caused by field changes. Production environment deployment must prioritize the stability of data persistence configurations to avoid affecting ledger summary due to storage configuration changes.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://user:pass@host:5432/quality_supervise` | Stores structured data for ledgers and reports, uses standard PostgreSQL connection format, default port 5432 |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches temporarily synchronized on-site inspection data, uses standard Redis connection format, database 0 for business caching |
| `FILE_TOKEN_KEY` | Determined through actual testing | Encrypts access tokens for on-site construction documents, must match the encryption rules of the storage service to secure access permissions for sensitive materials |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com` | Connects to engineering document storage services, must match the endpoint of the actual object storage service in use |
| `ROOT_KEY` | Random 32-character string | Generates system-wide permission tokens to secure background configuration and data access |

## Three common mistakes
- Symptom: After a major version upgrade, global variable configuration items are missing, and only a small number of preset options are displayed in the prompt editing area. Cause: Configuration migration was not performed according to the version upgrade documentation, the storage structure of global variables changed between old and new versions, and old configurations were not mapped to the new format.
- Symptom: Deployment background ledger summary tasks frequently time out. Cause: The expiration time of the cache service was not adjusted according to the weekly data update frequency, causing temporary synchronized data to accumulate and occupy resources, affecting task execution efficiency.
- Symptom: Generated completion acceptance supervision reports are missing some inspection record data. Cause: The database association relationship corresponding to `PG_URL` was not configured correctly, and the field association between inspection records and acceptance reports was not established, resulting in failure to properly summarize data.

## How to confirm configurations are set correctly
- Run a database connection test to verify that the `PG_URL` configuration can read and write ledger and report data normally, confirming connection validity.
- Upload a test hidden danger rectification notice, generate an access link via `FILE_TOKEN_KEY`, and confirm that the document can be accessed normally without permission issues.
- Trigger a weekly data synchronization task, check whether the cache service corresponding to `REDIS_URL` normally receives synchronized data, and confirm that the caching function works properly.
- Confirm that the currently running version is FastGPT v4.17.0, and verify that there are no compatibility conflicts between the version and deployment configurations.
