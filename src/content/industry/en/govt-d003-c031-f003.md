# Ledger Summary and Report Generation for Construction Project Environmental Impact Assessment Approval: Multi-turn Dialogue and Prompt Engineering

## What data for this category includes
This category of data comes primarily from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permission platform, and monitoring data.
Daily processed documents include environmental impact assessment reports or report forms, approval applications, public participation statements, technical evaluation opinions, and EIA approval documents.
Data updates follow no fixed schedule, and are synchronized with project declaration and review progress.
Individual data entries include fields such as project unique identifier, category, EIA level, pollution control measure details, public participation records, and approval status. Field formats align with standard definitions from source systems.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering?
Decentralized data sources, varied document structures, and unscheduled updates create clear constraints for multi-turn dialogue and prompt configuration.
Multi-turn dialogue must maintain a complete `messages` sequence to support gradual integration of cross-system data. This prevents single calls from failing to cover all project information from multiple sources.
Prompt engineering must adapt to extraction rules for different document types, including environmental impact assessment reports and EIA approval documents. It must accurately match field definitions for corresponding documents.
Dynamically updated data requires conversation contexts to load the latest declaration and approval records. This stops expired information from being used to generate ledgers.
Field naming standards from source systems must be strictly followed to ensure extracted content matches official ledger formats.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | `8000–12000 characters` | Single EIA report or approval document is typically thousands of characters long. Full loading of multiple associated documents and conversation history ensures no information is omitted. |
| Maximum single conversation turns | First 10 turns | Core interactions in EIA approval workflows typically do not exceed 10 turns. Historical information beyond this range provides no direct support for current ledger summary and report generation tasks. |
| `variables` | Bind project unique identifier and approval status fields | Dynamic replacement of project-specific information in conversations via variables ensures generated ledgers and reports accurately match corresponding projects. |
| `chatId` association rules | Bind a unique chatId to each individual approval project | All conversation records, extracted data, and generated ledgers for the same project must be associated. This supports subsequent archive tracing and summary statistics. |
| Prompt template adjustments | Calibrate based on actual testing | EIA approval requirements vary slightly across regions. Prompt content must be adjusted based on rules from local ecological environment departments. |
| Conversation log retention period | 180 days | EIA approval archives must be retained for a set period for law enforcement tracing and archive management, aligning with archive management requirements for public service sectors. |

## Three Common Misconfigurations
- Phenomenon: Running data in conversation logs is empty after invoking a workflow. Cause: `chatId` is not correctly bound to the unique identifier of the corresponding approval project, so the system cannot associate running data with the target project.
- Phenomenon: When using the text content extraction module, passing any parameter-wrapped code blocks in the prompt results in undefined code blocks after extraction. Cause: The prompt does not explicitly specify the extraction scope and corresponding fields for code blocks, so the system cannot identify the extraction target corresponding to the passed parameters.
- Phenomenon: Deleting a single conversation record causes the associated conversation log to be deleted simultaneously. Cause: No independent association rule between conversation logs and projects is configured. Conversation records and logs are incorrectly bound to the same storage unit, leading to log deletion when conversations are deleted.

## How to Verify Correct Configuration
- Initiate a test conversation for a single project, and check if extracted project information matches data in the national unified construction project EIA declaration and approval system.
- View conversation logs to confirm `chatId` fully matches the unique identifier of the corresponding project, with no mismatches or null values.
- Generate a draft ledger, and verify that fields align with ledger formats required by local ecological environment departments.
- Simulate deletion of a single conversation record, and check if the associated conversation log is retained. Confirm storage configuration is correct.
