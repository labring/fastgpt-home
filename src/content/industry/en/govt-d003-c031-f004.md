# Ledger Summary and Report Generation for Construction Project EIA Approval: Workflow Orchestration

## What the Data for This Category Looks Like
This category's data originates from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Commonly processed documents include environmental impact assessment reports, report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approvals. Data fields cover project category, EIA level, pollution prevention measures, public participation status, approval node status, and other items. No fixed standard units exist. Match field definitions to actual project scenarios.

## What Constraints These Characteristics Impose on Workflow Orchestration
Dispersed data sources and irregular update cycles require workflow orchestration to support trigger-based pulling from multiple data sources. This avoids missing the latest declaration data.
Diverse document types with large structural differences require different workflow nodes. Each node adapts to parsing rules for its document type.
The approval process involves multi-stakeholder collaboration. The workflow must clarify node permissions and transfer logic to ensure data transfer compliance.
Ledger summary requires integrating multi-source data. The workflow must include data verification nodes to avoid approval errors from inconsistent data.
Errors carry severe consequences. The workflow must include failure retry and alert mechanisms. This prevents project suspension or approval revocation due to process interruptions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset three global variables: project number, approval status, affiliated region | Matches core query dimensions in EIA approval, supports cross-node data reuse |
| Data source trigger rules | Trigger by declaration system update callback, set pull interval to 300 seconds | Adapts to irregularly updated data sources, balances data timeliness and system load |
| Document parsing node | Set chunking limit to 1200 characters for report/statement forms | Matches paragraph length of EIA documents to ensure context integrity |
| `nodeId` | Bind unique identifier of technical assessment opinion review node | Ensures accuracy of approval process transfer, avoids node confusion |
| Concurrent call limit | Set to 8 concurrent requests maximum, healthy concurrent volume set to 3–5 | Adapts to external call load limits, avoids triggering system current limiting |
| Failure alert configuration | Push alert to designated node after 3 retries | Matches high compliance requirements of EIA approval, resolves process abnormalities promptly |

These configurations are written based on the workflow function of FastGPT v4.17.0.

## Three Common Misconfigurations
- Phenomenon: When referencing `variables` in a workflow, no optional values appear. Preset project number variables cannot be called. Cause: Corresponding fields were not registered in the global variable configuration page. Workflow nodes cannot recognize available variables as a result.
- Phenomenon: External calls to the workflow interface return timeout errors. Concurrent requests exceed limits. Cause: Concurrent call limits were not set reasonably. Exceeding system bearing thresholds causes request queuing and timeout.
- Phenomenon: The specified EIA document library cannot be selected during knowledge base searches. Cause: The corresponding document library’s permissions were not configured for workflow node access. Or the knowledge base index update was not completed.

## How to Confirm Proper Configuration
- Trigger a test declaration data pull. Check if workflow nodes automatically fill project number, approval status, and other information using the configured `variables` parameter.
- Call the external interface to send a single request. Confirm the interface returns normally with no permission errors. Adjust concurrent configuration based on actual business load afterward.
- Manually trigger the document parsing node. Upload a sample EIA report form. Check that the parsing result includes core fields such as project category and EIA level. Ensure no content is missing or garbled.
- Simulate an approval node failure scenario. Confirm the system triggers retries and pushes alerts to the designated node as configured.
