# Construction Project EIA Approval: Ledger Summary and Report Generation - Tool Calling and Plugins

## What data for this category includes
Data for this category mainly comes from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Documents processed daily include environmental impact assessment books or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents.
Most document structures contain fields such as basic project information, EIA level determination, pollution control measure list, approval process nodes and results.
There are no unified fixed unit prefixes. Fields must match the standard formats of the corresponding declaration system.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category are scattered, and update cycles are not fixed. Tool calling must support on-demand triggering of multi-source external interfaces to avoid invalid data pulling.
Document structures vary across different projects. Plugins must adapt to variable document parsing rules to ensure core fields such as project category and EIA level can be extracted.
Errors directly affect project construction start and approval compliance. Tool calling must include built-in result verification logic. Run pre-checks on field completeness and format compliance of returned data. Configure failure retry mechanisms to handle interface call exceptions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic matching of tools required for the current task, adapting to flexible scenarios of multi-source data pulling for EIA approval |
| `functionCall` | `{"name": "format_eia_ledger", "parameters": {"project_name": "", "approval_document_number": "", "eia_level": "", "approval_reply_status": ""}}` | Standardizes the parameter structure returned by tools, ensuring extracted fields match the standard format of EIA approval ledgers |
| Tool call timeout period | `600 seconds` | EIA data pulling involves cross-system integration. 600 seconds covers most data synchronization durations, avoiding early interruptions |
| Maximum number of returned entries per tool call | `Top 20 entries` | EIA project ledger data volume is moderate. 20 entries cover recent project records required for a single summary, reducing redundant content |
| Plugin trigger condition | Trigger upon completion of approval nodes | EIA approval process has multiple nodes. Triggering by nodes ensures tool calls only execute when data summary is needed, avoiding unnecessary runs |

## Three Common Mistakes
- Phenomenon: Returns `functionCall` format error prompt when calling the session interface, with status code 400. Reason: Failed to configure the `functionCall` parameter according to the preset format, causing the content returned by the tool to fail correct parsing by the platform.
- Phenomenon: No ledger report is generated after workflow execution, and tool call results are not aggregated. Reason: Confused the trigger logic between workflow and plugins. Configured the plugin as a repeated execution node of the workflow, leading to duplicate data pulling.
- Phenomenon: Returns unauthorized error when calling the tool interface with an officially verified token. Reason: Did not bind the token to the corresponding external system call permission configuration, preventing normal access to data from the EIA declaration system.

## How to Confirm Proper Configuration
- Initiate a test request simulating an EIA project approval node. Check if tool calls trigger as configured and return data from the corresponding external system.
- View tool call logs. Confirm that the parameter format returned by `functionCall` fully matches the preset EIA ledger fields.
- Verify the number of entries returned by a single tool call. Confirm it does not exceed the configured upper limit.
- Validate the token call permission using the officially verified token. Confirm normal access to the configured external EIA system interface.
