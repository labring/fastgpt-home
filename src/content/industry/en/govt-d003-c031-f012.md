# Construction Project Environmental Impact Assessment (EIA) Approval Ledger Summary and Report Generation: Deployment and Upgrade

## What this category of data looks like
Data for this category comes from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Daily processed documents include environmental impact reports, EIA report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. Data fields include project category, EIA level, pollution prevention measures, public participation status, approval status, and more. Some fields must match standard formats set by ecological environment departments, with no fixed unified unit constraints.

## What constraints do these data characteristics impose on deployment and upgrades?
Multi-source heterogeneous data sources require configuring interfaces compatible with multi-system access during deployment, and preserving compatibility with existing data synchronization during upgrades. Irregular update frequencies require reserving flexible synchronization cycle configuration during deployment, and retaining historical data synchronization logic during upgrades to prevent data interruptions. Mixed-structure daily documents require deploying parsing modules adapted to multiple formats, and verifying parsing accuracy for all types of EIA documents during upgrades to avoid disrupting ledger summary and report generation workflows. Errors in the approval process have serious consequences, so deployment and upgrade steps must ensure stable data verification logic to prevent approval disruptions caused by configuration errors.

## Three Common Configuration Mistakes
- Symptom: After a version upgrade, only 2 global variable and prompt configuration items remain in the interface, with all other custom configurations missing. Cause: The old version’s configuration files were not backed up and restored during the upgrade, so the system loaded default configurations that overwrote custom settings.
- Symptom: After a cross-major-version upgrade, historical EIA approval ledger data cannot load normally, and some fields display as empty. Cause: The upgrade did not include a migration operation compatible with the old data structure, so the new system cannot recognize storage data in the old format.
- Symptom: After deployment in a production environment, connection timeout errors occur during batch synchronization of EIA declaration data. Cause: The `DB_MAX_LINK` configuration value is too low to support the concurrent connection requirements of multi-batch data synchronization.

## How to Verify Successful Configuration
- Access the domain configured in `FE_DOMAIN`, confirm the management backend loads normally and all configuration items are present.
- Upload a standard EIA report form, run the ledger summary process, and verify that the generated ledger fields cover all required EIA-related information.
- Check the system operation logs to confirm database connections and cache service statuses are normal, with no frequent error messages.
- Manually trigger a data source synchronization task, and verify that data can be pulled normally from the specified national unified construction project EIA declaration system interface.
