# Ledger Summary and Report Generation for Investment Project Approval and Post-Evaluation: HTTP Interfaces and External Systems

## What the data for this category looks like
This category covers the full end-to-end process from project approval to post-evaluation for central enterprise investment projects. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports.
Data sources include state-owned asset supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Data is updated quarterly.
Data fields include project identifiers, investment amounts, project approval nodes, post-investment operational data, evaluation conclusions, and more. Data formats vary across different sources. Structured conversion must be completed per external system requirements.

## What constraints these characteristics bring to HTTP interfaces and external systems
Data sources for this category involve sensitive systems such as state-owned asset supervision and internal enterprise ERP systems. Strict identity authentication is required to protect data security.
Data is updated quarterly. Interface pull cycles must align with this rhythm to avoid excessive calls or data lag.
Different external systems have varying document formats and field requirements. Interfaces must support custom field mapping and format conversion.
Business errors can lead to serious consequences including state-owned asset losses and accountability. Interfaces must be configured with failure retry and data validity verification mechanisms.

| Response Data Processing | Return only structured core project fields | Focuses on information required for ledger summary, reducing interface transmission overhead |
| Scheduled Pull Configuration | Execute once every 90 days | Matches the quarterly update frequency of business data, avoiding frequent calls to external systems |
| Error Retry Configuration | Retry 2 times after failure, with a 60-second interval | Addresses temporary fluctuations in external systems, ensuring stability of data pulling |
| Context Passing Configuration | Pass project historical ledger data from the past 12 months | Ensures complete business context is available during report generation, meeting the needs of associated analysis for project approval and post-evaluation |

## Three Common Misconfigurations
- A 401 Unauthorized status code is returned when calling the interface. This occurs when authentication information is incorrectly configured, or an expired or invalid enterprise internal gateway token is used.
- The generated report lacks associated project historical data. This occurs when associated historical ledger parameters are not included in the request, preventing the large model from accessing complete business context.
- The pulled ledger data contains a large number of redundant fields. This occurs when no response data filtering rule is configured, and full raw data from the external system is returned directly.

## How to Verify Successful Configuration
- Call the interface using the configured authentication information. Confirm that valid structured project data is returned, and no authentication failure error is present.
- Check the `responseData` field in the interface response. Confirm that only core business fields required for ledger summary are included, with no redundant information.
- Trigger a scheduled pull task. Confirm that the data update cycle aligns with the quarterly business rhythm, and the pulled data covers the complete quarterly period.
- Simulate a temporary failure of the external system. Confirm that the interface triggers the failure retry mechanism, and normal data retrieval is completed after retries.
