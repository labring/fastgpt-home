# Ledger Summary and Report Generation for Investment Project Approval and Post-Evaluation: Multi-turn Dialogue and Prompt Engineering

## What This Category’s Data Looks Like
Daily documents for this category include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data sources are the national state-owned asset supervision and administration system, enterprise ERP and project management systems, industry market data, audit and financial statements. The update frequency is quarterly. Document fields cover project number, total investment, construction period, production benefit, risk rectification status, and other items. Subtle differences exist in data formats across different sources.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Cross-system data sources require that multi-turn dialogue first completes field format alignment to avoid extracting chaotic ledger data. The quarterly update frequency requires that dialogue context be limited to the current quarter’s project scope to prevent calling expired historical data. Structural differences across multiple document types require that prompt engineering be split and adapted across three phases: project approval preparation, investment decision preparation, and post-evaluation, to ensure accuracy of extracted fields. Additionally, serious consequences of business errors require adding a result verification step in multi-turn dialogue to prevent erroneous data from entering official ledgers.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Exclusive conversation ID bound to a single project | Isolates conversation context across different projects, avoids confusion from cross-project variable caching, and complies with data isolation requirements of state-owned asset supervision |
| `messages` | Multi-turn context split by phase, with each turn associated with the corresponding document type | Adapts to structural differences across multiple document types, optimizes prompt extraction rules based on project approval, investment decision, and post-evaluation phases |
| `variables` | Pre-set two core variables: project number and statistical cycle, with values synchronized from ERP and supervision systems | Anchors the currently processed project and quarterly data scope, reduces cross-system data matching errors |
| Maximum context length | 1200–1500 characters | Matches quarterly updated data volume, prevents conversation interruptions caused by context overflow |
| Question optimization | Enabled, optimize extraction prompts separately for feasibility study reports and post-evaluation reports | Adjusts prompts based on field priorities of different documents, improves accuracy of ledger field extraction |
| Maximum workflow run count | Calibrated based on actual testing | Adapts to concurrent invocation scenarios, prevents workflows from being terminated early under high concurrency |

## Three Common Misconfigurations
- Phenomenon: When invoking workflows concurrently, some MCP invocations return empty values after 2–3 calls per second. Cause: The maximum workflow run count configuration threshold is set too low, causing workflows to be terminated early under high concurrency.
- Phenomenon: When calling the API to generate reports, the output results for variable B include historical content from variable A. Cause: No exclusive `chatId` is bound, variable caching for conversation context is not isolated, and variables from cross-turn dialogues are reused.
- Phenomenon: After configuring input guides and term banks, the expected guide questions do not display in the conversation interface. Cause: The term bank is not associated with the prompt template for the corresponding phase, and the input guide is not bound to the current conversation’s context configuration.

## How to Verify Successful Configuration
- Test conversations bound to different `chatId`s, initiate cross-project calls, and confirm that variable caching does not cross projects and no data confusion occurs.
- Manually trigger variable synchronization, check that values for `variables` match records from ERP and supervision systems, and ensure correct data sources.
- Adjust concurrency to 3 calls per second, invoke the workflow, and confirm no empty return results, verifying that the workflow run count threshold adapts to the current scenario.
- View guide questions in the conversation interface, confirm that the input guide and term bank-associated templates are active, and display expected guide content.
- Trigger multi-turn dialogue to extract ledger fields, check that extraction results match fields from corresponding documents, and verify accuracy of prompt engineering configurations.

The values provided are common starting points and should be evaluated against the operator’s own samples.
