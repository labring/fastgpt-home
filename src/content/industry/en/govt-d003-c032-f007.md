# Ledger Summary and Report Generation for Investment Project Approval and Post-Evaluation: Database and Operations

Reference only; verify against the target FastGPT release and deployment documentation.

## What data falls under this category
This category of data covers the entire investment process for central enterprise strategic investment departments, project companies, state-owned assets supervision departments, and external consulting and evaluation institutions. Data sources include state-owned assets supervision and administration commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Daily associated documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset evaluation reports, and post-investment evaluation reports. Data is updated on a quarterly basis. Fields include project approval information, investment decision-making meeting materials, post-production evaluation data, and more. There are no unified fixed units, and values vary based on document types and business modules.

## What constraints do these characteristics impose on the database and operations link
The data characteristics of this category impose multiple constraints on the database and operations link. Multi-source data access requires the database to support heterogeneous data source docking, adapting to different interface formats such as the state-owned assets supervision commission investment supervision system, enterprise ERP, and industry market data. The quarterly update rhythm requires the operations link to configure scheduled synchronization tasks to ensure data timeliness. Multiple types of documents and flexible fields require the database to support semi-structured data storage, avoiding hard-coded fields that restrict business expansion. Compliance requirements for state-owned assets-related data require the database to be configured with strict access control and backup mechanisms, while supporting data recovery processes to address data loss risks.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://username:password@host:5432/fastgpt_asset` | Adapts to structured data storage requirements of central enterprise ERP and supervision systems, supports transactional operations |
| `MONGODB_URI` | `mongodb://username:password@host:27017/asset_review?authSource=admin` | Stores semi-structured project documents and unstructured reports, supports flexible field expansion |
| `DB_MAX_LINK` | `20–30` | Matches the concurrent request volume of quarterly data synchronization, avoids database connection exhaustion |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches frequently accessed project ledger data, reduces database query pressure |
| Database backup path | `/data/backup/asset_project` | Configured for quarterly backup frequency, matches the data update cycle, meets compliant recovery requirements |

## Three common mistakes
- Phenomenon: Database connection error prompts access denied, or the interface returns a 403 status code. Cause: The external request IP of the deployment environment is not added to the database access whitelist, which does not meet the security configuration requirements for state-owned assets data access.
- Phenomenon: Syntax errors are returned when running multi-line SQL statements, or execution is interrupted. Cause: The database connection plugin is not configured to allow multi-line query execution, or the multi-statement execution logic is not correctly split, leading to deviations when adapting to the batch data writing requirements of multiple document associations for this category.
- Phenomenon: After restoring backed-up project files, the knowledge base and agent configurations are empty, and original data cannot be loaded. Cause: Only project files are restored, and the ledger and report storage data in the database are not synchronously restored, failing to follow the backup process of separating data and configurations for this category.

## How to confirm the configuration is complete
- Run the database connectivity test tool, verify the connection status of `PG_URL`, `MONGODB_URI`, and `REDIS_URL`, confirm that access permission configurations are correct.
- Trigger a temporary data synchronization task, check whether project data pulled from each source system is complete, confirm that the synchronization logic takes effect.
- Execute the database backup and recovery test process, verify that backup files can be loaded normally, confirm that the data recovery mechanism is available.
- View the database connection count monitoring panel, confirm that the current connection count does not exceed the `DB_MAX_LINK` configuration threshold, confirm that the connection pool configuration is reasonable.
