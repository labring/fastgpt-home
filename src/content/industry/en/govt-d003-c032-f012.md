# Ledger Summary and Report Generation for Investment Project Approval and Post-Evaluation: Deployment and Upgrade

## What this type of data looks like
Data sources include state-owned assets investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Data is updated quarterly. Documents processed daily include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data fields include project identifiers, investment amounts, project initiation approval nodes, post-investment operation metrics, compliance check results, and more. Units include ten thousand yuan, quarters, percentages, and others. The content length of individual documents varies widely, ranging from several thousand characters for project proposals to several hundred thousand characters for post-investment evaluation reports.

## Constraints on deployment and upgrade
Quarterly updated data sources require scheduled synchronization tasks during deployment, and require interface compatibility adaptations for multi-source data to avoid synchronization failures caused by system version differences.
Processing requirements for multiple document types require retaining parsing adaptation capabilities for different document formats during upgrades, to ensure correct field extraction for all project document types.
The diversity of data fields requires configuring flexible field mapping rules to adapt to field unification across different units and formats.
Data security requirements related to state-owned assets require synchronous configuration of permission control and storage encryption policies to avoid data leakage risks.
Errors may lead to state-owned asset losses and liability investigations, so deployments and upgrades must include pre-check steps to reduce the probability of exceptions.

## How to configure these settings
These configuration items apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15` | Adapt to concurrent load of quarterly batch synchronization for multi-source databases, avoid connection pool exhaustion |
| `MONGODB_URI` | `Connection string for dedicated read-only account of state-owned assets investment supervision system` | Ensure data reading security, avoid modifying core data of production systems |
| `PG_URL` | `Read-only PostgreSQL connection string for enterprise ERP system` | Synchronize structured project management data, ensure accuracy of data sources |
| `REDIS_URL` | `Isolated internal network Redis instance, set connection timeout to 300 seconds` | Cache ledger data and synchronization task status, ensure security of internal network data transmission |
| `ROOT_KEY` | `Random string with length of at least 32 characters` | Control highest permission access to system backend, avoid default password leakage risks |
| `STORAGE_S3_ENDPOINT` | `Internal network endpoint of enterprise internal object storage service` | Store large quantities of project documents and post-evaluation reports, ensure data storage compliance |

## Three common misconfigurations
- Phenomenon: Permission check failure is prompted when logging into the system backend, with the error message "ROOT_KEY verification failed". Cause: The custom `ROOT_KEY` value set during deployment is not used, or the `ROOT_KEY` parameter in the configuration file is filled incorrectly.
- Phenomenon: Timeout occurs during quarterly batch data synchronization, with a returned status code of 504. Cause: The `DB_MAX_LINK` configuration value is too low to support concurrent synchronization requests for multi-source databases.
- Phenomenon: Corresponding fields in the ledger are empty after importing a project proposal. Cause: No field mapping rules matching the business document are configured, causing parsed fields to fail to be correctly written to the ledger template.

## How to confirm successful configuration
- Execute a manual data synchronization task, check whether the synchronized ledger data matches the quarterly data from the source systems.
- Access the domain configured in `FE_DOMAIN`, log in to the backend using the permission account corresponding to `ROOT_KEY`, and verify that the system management interface can be accessed normally.
- Upload a test project proposal document, confirm that parsed fields can be correctly mapped to the preset ledger template.
- Check the storage service corresponding to `STORAGE_S3_ENDPOINT`, confirm that uploaded test post-evaluation reports can be stored and downloaded normally.

The values given are common starting points and should be measured against the reader's own samples.
