# Tender and Procurement Compliance Management: Ledger Aggregation and Report Generation - Database and Operations

## What This Category's Data Looks Like
Data for this category comes from enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases. It is updated daily.
Daily documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance receipts, and supplier complaint materials.
Data fields cover procurement subjects, procurement methods, budget amounts, bid evaluation results, contract performance statuses, audit rectification items, and more. Units include RMB yuan, project numbers, dates, and others. The size of a single record varies based on procurement project scale.

## Constraints on Database and Operations Workflows
Daily high-frequency updates require database connection pools to support stable concurrent writes and queries, preventing business interruptions.
Multi-source heterogeneous data formats require databases to support mixed storage of structured and unstructured data, adapting to documents like procurement plans and bid evaluation records.
Audit traceability needs require databases to enable transaction logging and permission auditing, ensuring full data traceability.
Differing access permissions across departments require databases to implement fine-grained control, preventing leakage of sensitive procurement data.
Long-text procurement documents also need proper storage and indexing configuration, ensuring efficient subsequent retrieval.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum database connection pool size | 15–25 | Adapts to daily high-frequency concurrent writes and queries of procurement data, avoiding connection exhaustion |
| Unstructured data storage address | `mongodb://fastgpt:password@db-host:27017/fastgpt?authSource=admin` | Adapts to storage and full-text retrieval of unstructured data such as procurement documents and bid evaluation records |
| Structured data storage address | `postgresql://fastgpt:password@pg-host:5432/fastgpt?sslmode=require` | Stores data requiring strong consistency such as procurement ledgers and audit rectification records |
| Cache service address | `redis://:password@redis-host:6379/0` | Caches frequently accessed supplier database data and procurement rules, reducing database load |
| Database connection timeout period | 30 seconds | Avoids business interruptions caused by delayed database responses |
| Data backup frequency | 1 time per day | Ensures complete traceability of daily updated procurement data, meeting audit requirements |

## Three Common Configuration Errors
- Symptom: Database connection failure logs appear after deployment, including the error `retry init root user mongo start connect init root user error`. Cause: The username, password, and database address for `MONGODB_URI` are not configured correctly, or the database service is not running.
- Symptom: After operating the vector database via an external management tool, FastGPT cannot retrieve the corresponding data. Cause: Data was modified directly without using FastGPT's built-in interface to operate the vector database, resulting in inconsistent indexes and metadata.
- Symptom: Users from multiple departments cannot access their corresponding procurement data, and permission errors occur. Cause: Fine-grained database access control is not configured, or permission rules do not match the business division of the procurement center and discipline inspection department.

## How to Verify Correct Configuration
- Log in to the database configuration panel in the FastGPT v4.17.0 backend, check the connection status of each storage address, and confirm it shows normal.
- Manually trigger a procurement data synchronization task, check if expected procurement data has been generated in the tables or collections of the corresponding database.
- View the database backup logs, confirm that the day's backup task has been successfully executed with no abnormal errors.
- Switch test accounts with different permission roles, attempt to access procurement ledger data, and confirm that permission rules take effect as expected.
