# Enrollment and Student Status Management: Ledger Summary and Report Generation - Database and Operations Maintenance

## What the data for this category looks like
Data sources for this category include the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and real estate data interfaces, and school academic affairs systems. Data updates occur once daily. Daily processed documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data fields focus on student identity and enrollment eligibility, including identity identification fields, household registration and residence verification fields, student status change record fields, admission batch fields, and other related fields. No additional non-business-related fields are included.

## What constraints these characteristics impose on the database and operations maintenance link
Multi-source data access requires the database to support cross-system data synchronization and field mapping to avoid data misalignment caused by differences in data source formats. Daily batch data updates require the operations link to configure an incremental synchronization mechanism to reduce resource usage from full data pulls. Data fields focus on student identity and eligibility, so field uniqueness and accuracy must be strictly ensured. Otherwise, issues such as duplicate student statuses and admission disputes may arise. Frequent queries and writes for structured ledger documents require the database cluster to reasonably allocate read and write resources to avoid read-write conflicts affecting business stability.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Connection string pointing to a 3-node replica set with at least 1000 MB of storage | Stores high-frequency write business data such as student status changes and admission rosters; replica sets ensure data high availability |
| `PG_URL` | Connection string pointing to a read-only instance | Stores read-only structured data such as enrollment plans and household registration verification results, reducing read-write resource conflicts |
| `DB_MAX_LINK` | `20–30` | Meets concurrent requirements for daily batch synchronization and ledger queries, preventing connection pool exhaustion |
| `REDIS_URL` | Connection string pointing to a dedicated cache instance with 512 MB of memory | Caches frequently reused verification rules and student status deduplication logic, reducing repeated database query pressure |

## Three common mistakes
- The exported knowledge base dataset.csv only includes the index field and no content field. This occurs because the data source field mapping is not correctly configured, and the content field of the corresponding MongoDB business table is not associated.
- Low query success rate in high-concurrency scenarios, with timeouts or 503 status codes returned. This occurs because the value of `DB_MAX_LINK` is too low, and the connection pool cannot support concurrent requests.
- Password-free sharing links cannot carry the user database identification id. This occurs because the database identification parameter transfer logic is not configured in the sharing link, and the connection identifier of the corresponding data source is not bound.

## How to confirm the configuration is complete
- Run the daily incremental synchronization task, check whether cross-source accessed student status and enrollment data are complete and free of omissions.
- Initiate simulated concurrent queries, monitor whether database connection counts are within the range specified by `DB_MAX_LINK`.
- Generate a password-free sharing link, verify whether the link includes the specified database identification parameter.
- Export the knowledge base dataset, check whether the exported file includes both index and content fields.

The values provided here are common starting points and should be evaluated against the reader's own samples.
