# Emission Permit Management Ledger Summary and Report Generation: Workflow Orchestration

This document is compiled based on FastGPT v4.17.0, and all configurations below are compatible with this version.

## What the data for this category looks like
This category serves ecological environment department emission permit management positions, environmental protection departments of pollutant discharge units, and third-party environmental service institutions. Data is sourced from the National Emission Permit Management Information Platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems, with a quarterly update frequency. Daily documents include emission permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data fields cover emission limits, monitoring frequency, ledger cycle, permitted emission quantities, and more. Units include tons/year, milligrams/cubic meter, times/quarter, and others.

## What constraints do these features impose on the "workflow orchestration" link
The quarterly update frequency requires the workflow to adapt to batch quarterly data processing and avoid single-load overload. Data from multiple sources has large format differences, so a unified format verification node must be configured in the workflow to ensure consistent ledger data formats exported from different systems. There are various document types, so dedicated parsing rules must be set for different documents to ensure the accuracy of field extraction for documents such as permit copies and self-monitoring plans. There are multiple field units, so unit conversion logic must be configured during data integration to prevent statistical deviations. The rigor of post-permit supervision requires the workflow to retain a complete audit trail to facilitate subsequent retrospective verification.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Include three types of variables: emission limits, ledger cycle, and monitoring data identifier | Adapt to core business fields of emission permit management, facilitating dynamic calls in workflows |
| Document Parsing Node | Configure dedicated parsing rules based on document type | Match the fixed formats of emission permit-related documents to improve field extraction accuracy |
| Batch Processing Threshold | Process 50 quarterly ledger files per single run | Avoid single-request overload and adapt to quarterly update data volume |
| `nodeId` | Assign unique identifiers to format verification, data integration, and report generation nodes | Facilitate workflow debugging and failed node localization |
| Timeout Setting | 1200 seconds | Adapt to the time required for multi-source data integration for large pollutant discharge units |
| Visibility Configuration | Set visibility scope based on node type | Meet the viewing requirements of users with different permissions and comply with the confidentiality requirements of post-permit supervision |

## Three common misconfigurations
- Issue: In a local deployment environment, after uploading an emission permit ledger file, the document parsing node status shows not executed. Cause: Incorrect permission configuration for the local deployment file storage directory, causing the node to fail to read the uploaded file.
- Issue: In the workflow, the self-monitoring data node displays the source text by default and cannot be hidden. Cause: No visibility control parameter is configured in `variables`, causing the node to inherit the global visibility setting by default.
- Issue: The code running node in the workflow returns an empty result after execution, failing to complete the ledger data format conversion. Cause: The workflow did not load the dependency packages required for Python runtime, and did not pass the business variables required for code execution through `variables`.

## How to verify the configuration is correct
- Upload a permit copy file and check whether the document parsing node can correctly extract core fields such as emission limits and permit cycle.
- Configure the quarterly ledger cycle parameter in `variables`, run the workflow, and check whether the data call matches the preset value.
- Trigger a batch processing task for 50 ledger files and check whether the execution status of all nodes shows success.
- Adjust the timeout setting to 1200 seconds, run the workflow containing multi-source data integration, and confirm that no timeout errors occur.
