# Emission Permit Management: Ledger Summary and Report Generation - Database and Operations

## Data Profile for This Category
Service subjects include ecological environment department emission permit management positions, pollutant discharge units' environmental protection departments, and third-party environmental service institutions. Data sources include the National Emission Permit Management Information Platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems. Update frequency is quarterly.

Daily involved documents include emission permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data fields must cover emission limits, monitoring frequency, actual discharge volume, change items, and other relevant content. Units include tons, cubic meters, milligrams per cubic meter, and others. Configurations must align with industry technical specifications and permit requirements.

## Constraints Imposed on Database and Operations
Quarterly updated bulk data requires the database to support periodic bulk writes and validation. Sufficient bulk processing cache and connection resources must be reserved.

Multi-source heterogeneous data types include structured compliance information, semi-structured monitoring data, and unstructured document materials. The database must support multi-format storage and targeted index optimization.

Data must align with industry technical specifications and permit limits. Database fields must be flexibly configurable to adapt to control rules for different pollutant discharge entities.

Errors carry compliance risks. The database must have data backup and rollback capabilities. Data access permissions must be strictly controlled to prevent unauthorized modifications.

Cross-system data docking must be stable and reliable. Reasonable connection pool parameters must be configured to ensure concurrent access.

## Configuration Guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/fastgpt?authSource=admin` | Supports storage of multi-source heterogeneous emission ledger, monitoring report and other unstructured data, and enables custom index optimization for compliance queries |
| `PG_URL` | `postgresql://user:pass@host:5432/fastgpt?sslmode=require` | Stores structured compliance data such as permit limits, change applications, implementation reports, and ensures transaction consistency and field validation capabilities |
| `DB_MAX_LINK` | `100–150` | Matches the concurrent demand of quarterly bulk data import, and avoids service interruption caused by database connection exhaustion |
| `REDIS_URL` | `redis://:pass@host:6379/0` | Caches temporary monitoring data validation results and bulk task status, and improves query efficiency during batch processing |

## Three Common Misconfigurations
- High disk read/write utilization occurs during quarterly bulk ledger imports, and logs indicate connection count exceeded. Cause: The `DB_MAX_LINK` parameter is not configured appropriately, leading to concurrent connections exceeding the database's maximum carrying capacity.
- A 400 error is returned when calling the dataset creation API, with a prompt about field format mismatch. Cause: Database mapping is not configured according to emission permit data field specifications, and required fields such as emission limits and monitoring frequency are not validated.
- A database configuration conflict occurs after deployment, preventing service startup. Cause: Configuration parameters for relational and unstructured data storage are incorrectly mixed, and storage links for compliant structured data and unstructured documents are not differentiated.

## How to Verify Successful Configuration
- Log in to the database management tool, verify that the connections configured via `MONGODB_URI` and `PG_URL` are functional, and that test emission permit data can be read.
- Run the bulk data import script, check connection pool utilization, and confirm that the `DB_MAX_LINK` value does not trigger a database connection over-limit alert.
- Check the running status of the Redis cache service, confirm that the cache node configured via `REDIS_URL` can normally store and retrieve temporary task data.
- Call the dataset creation API, verify that the returned results comply with the field specifications for emission permit data, with no format errors.
