# Emission Permit Management: Ledger Summary and Report Generation - Document Parsing and Chunking

This page's configuration is based on FastGPT v4.17.0.

## What This Category of Data Looks Like
Data for this category primarily comes from the National Emission Permit Management Information Platform, corporate environmental protection ledgers, online monitoring systems, and environmental statistics systems. The update frequency is quarterly.
Commonly processed documents include emission permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Document structures are mostly a mix of forms, structured tables, and explanatory text. Fixed fields include permitted emission concentrations, emission volumes, monitoring frequencies, and ledger record items. Field units cover mass, volume, time, and other categories.

## How These Characteristics Impact the Document Parsing and Chunking Link
Data sources are scattered and document formats are mixed, so the parsing link must adapt to three types of content: structured tables, forms, and free text. This avoids splitting context across key fields.
Quarterly batch updates involve large document volumes, so batch parsing and timeout fault tolerance must be supported.
Fixed fields have strong correlations. Chunking must retain the binding relationship between fields and their corresponding descriptions. Otherwise, information misalignment will occur in subsequent ledger verification and report generation links.
Some documents include multi-page attachments. Parsing must fully recognize cross-page table content to prevent key limit information from being truncated.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Emission permit documents include fixed fields and long explanatory text. This range avoids splitting the correlation between key limit values and their corresponding records |
| `chunkSplitter` | Separate by paragraph + table header | Adapts to the mixed form, table, and text structure in documents, retaining the binding between fields and their corresponding content |
| `customPdfParse` | Enable dynamic table recognition | Emission permit documents contain a large number of structured emission limit tables and ledger record tables. Default parsing easily loses field structure |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | When processing multiple documents in quarterly batches, prevents task failure due to overly long parsing time for a single document |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to complete sets of emission permit documents including multi-page attachments, meeting batch upload requirements |

## Three Common Misconfigurations
- Scenario: After importing emission permit documents in PPT or DOC format, the parsing result is empty or only retains a small amount of text. Cause: `customPdfParse` is not enabled to adapt to structured documents in non-PDF formats. The default parsing logic is only optimized for PDF, and cannot correctly recognize tables and fields in other formats.
- Scenario: When parsing emission permit ledger files in Excel format, only the first two columns of data are recognized. Cause: Custom table parsing rules are not configured. The default chunking logic splits by fixed number of columns, and does not adapt to the multi-column field structure of emission permit ledgers.
- Scenario: Knowledge base call parameters and streaming return results are not correctly associated, and cannot match corresponding document content. Cause: Document metadata is not retained in the parsing configuration, so chunks do not carry associated information and cannot be bound to call parameters.

## How to Verify the Configuration is Correct
- Upload a single PDF of an emission permit implementation report. Check that the parsed chunks retain the contextual association of key fields such as emission limits and monitoring periods, with no cross-field splitting.
- Upload a DOC format emission permit change application document. Confirm that the parsing result includes the structured application table and explanatory text in the document.
- Batch upload 5 quarterly updated emission permit ledger documents. Check that all tasks are completed within 600 seconds with no timeout errors.
- Upload an Excel self-monitoring plan file containing multiple columns of data. Confirm that the parsed chunks cover all fields with no omissions or truncations.

The values provided are common starting points and should be measured against the reader's own samples.
