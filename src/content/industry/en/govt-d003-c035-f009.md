# Emission Permit Management: Ledger Summary and Report Generation - Model Access and Configuration
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
This category of data covers full-process documents for emission permit management, including emission permit copies, quarterly performance reports, self-monitoring plans, ledger records, change applications, and permit application forms. Data is sourced from the national emission permit management information platform, internal enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems, and is updated quarterly. Each single document includes fields such as permitted emission limits, discharge outlet parameters, monitoring data, and compliance check items. Units include mg/m³ for emission concentration, tons for annual emission volume, and times/quarter for monitoring frequency. Configurations must strictly match the technical specifications and permit requirements of the corresponding industry.

## What constraints do these characteristics impose on model access and configuration
Data sources for this category are scattered and require cross-system pulling. Model access must support format adaptation for multiple data sources.
The scale of documents updated in quarterly batches requires models to support batch processing. This avoids overload from single requests.
Each single document must strictly match fields such as permitted emission limits and discharge outlet parameters. Model input must retain original field mappings.
Compliance check tasks have fixed requirements for output formats. Structured output templates must be preset in advance.
Ledger formats vary across different entities. Models must adapt to multiple document structures to reduce adaptation costs.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Single documents related to emission permits often reach thousands of characters. This range covers complete ledgers and monitoring data to avoid context truncation |
| `temperature` | `0.1–0.3` | Compliance checks and report generation require stable structured output. This range avoids random deviations |
| `AIPROXY_API_ENDPOINT` | `http://localhost:11434/v1` | Adapts to locally deployed Ollama open-source models. This ensures sensitive environmental protection data is not leaked externally |
| `maxTokens` | `2000–3000 token` | Controls the output length of single-round report generation. This meets typesetting and information density requirements for compliance documents |
| `vision` | Enabled | Adapts to multi-modal documents such as emission permit scans and monitoring point photos. This extracts key information from images |
| `toolChoice` | `auto` | Automatically selects whether to call tools to pull the latest ledgers and monitoring data based on tasks. This improves data timeliness |

## Three common configuration errors
- Calls to local Ollama models return 404 errors. This occurs when `AIPROXY_API_ENDPOINT` is not correctly configured to the actual service address of Ollama, or when model proxy forwarding rules are not enabled.
- Embedding models cannot connect to OneAPI, with corresponding errors returned by OneAPI. This occurs when the model name does not match the model identifier configured in OneAPI, or when interface access permissions are not granted to FastGPT.
- Multimodal visual analysis tasks produce no output. This occurs when the `vision` configuration item is not enabled, or when the uploaded image format is not supported by the currently connected model.

## How to confirm configuration is complete
- Upload a single quarterly emission ledger document. Check whether the model can correctly extract core fields such as permitted emission limits and discharge data.
- Initiate a batch ledger summary task. Confirm that the system pulls documents from corresponding data sources at the quarterly update frequency, with no timeouts or content truncation.
- Test uploading an emission permit scan. Confirm that the model recognizes and extracts image information such as permit number and validity period on the copy.
- Adjust the `temperature` parameter to 0.2. Check whether two compliance check results remain consistent, with no random deviations.

The values provided are common starting points and should be evaluated against samples relevant to the specific deployment context.
