# Emission Permit Management: Ledger Summary and Report Generation - Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
The data for this category covers environmental compliance documents and real-time monitoring data from pollutant discharge units. Daily documents include emission permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data sources are the national emission permit management information platform, internal enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems. Update frequency is quarterly. Document structures include fixed permitted emission limits, discharge outlet information, periodic emission records, and summary reports. Fields involve compliance indicators such as emission concentration and emission volume, with units following general standards for the ecological environment industry.

## Constraints Imposed on Knowledge Base Retrieval and Recall by Data Characteristics
This category’s data characteristics create multiple constraints for retrieval and recall.
Multi-source data requires matching compliance data across sources including the national emission permit management information platform and online monitoring systems.
The quarterly update frequency means retrieval must prioritize the latest data from the most recent quarter. This avoids using expired permit or ledger information.
Document types include formal permit files and real-time monitoring records. Differentiated recall priorities must be set for each document type.
Professional compliance fields such as emission concentration and emission volume require exact matching. This prevents compliance deviations caused by fuzzy retrieval.
Ledger records and implementation reports have strong field correlation. Retrieval must support associating multiple types of data for the same discharge outlet to complete summarization.

| `usingReRank` | Enabled | Re-ranks recall results by compliance relevance. Prioritizes returning core business data such as permitted emission limits and ledger records |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonymous terms related to compliance. For example, expands "emission concentration" to "pollutant emission concentration" to adapt to wording differences in professional documents |
| `collectionIds` | Bind exclusive knowledge base collection for emission permits | Restricts retrieval scope. Prevents interference from other categories of environmental protection data during compliance retrieval |

## Three Common Mistakes
- Issue: When uploading a knowledge base file with a Chinese name via API, the interface displays garbled file names or returns a 400 status code indicating an invalid file name. Cause: The API request header is not correctly configured with UTF-8 character encoding. This prevents the system from properly parsing Chinese file names.
- Issue: Retrieval results do not include the latest ledger or implementation report data from the most recent quarter. Cause: The retrieval time range is not restricted, or the knowledge base collection for the latest quarter is not bound. This leads to recall of expired historical data.
- Issue: Retrieval results include a large number of environmental impact assessment approval documents, exceeding the scope of exclusive emission permit data. Cause: The `collectionIds` parameter is not used to restrict the exclusive knowledge base collection. This causes the retrieval scope to cover other categories of environmental protection documents.

## How to Verify Successful Configuration
- Check the knowledge base binding configuration. Confirm that `collectionIds` is associated with the exclusive document collection for emission permits, and does not include other categories of environmental protection data.
- Initiate a retrieval for "self-monitoring data for a fixed discharge outlet in a quarter". Verify that the returned results cover the ledger records and permitted emission limit documents for that discharge outlet.
- Call the API to upload a test file with a Chinese name. Confirm that the file name displayed on the interface has no garbled characters and the file can be normally retrieved and used.
- After enabling `usingReRank`, check if the order of retrieval results prioritizes core compliance data, with non-relevant documents ranked lower.
