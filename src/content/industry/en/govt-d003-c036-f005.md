# Ledger Summary and Report Generation for Government Service Item Catalog & Service Guide Maintenance: Tool Calling and Plugins

## What this category of data consists of
This category of data primarily comes from the national basic directory of government service items, administrative licensing item lists, power responsibility lists, and local government service item databases. Daily maintained documents include the basic directory of government service items, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. Data is updated on a monthly basis. A single item document typically includes core fields such as item code, item name, implementing entity, acceptance conditions, application material list, and service process. There are no fixed universal unit fields. Corresponding business rules must be matched based on item category.

## What constraints do these characteristics impose on the tool calling and plugins workflow
Data sources for this category are scattered, including national and local government service item databases. Tool calling must support synchronization and comparison of multi-source data. The monthly update frequency requires tools to be configured with incremental pull scheduling to avoid excessive resource usage from full pull operations. Core documents contain multiple non-standardized fields, such as acceptance conditions and application material lists. Tool calling must perform targeted verification of field completeness. Batch item comparison and maintenance tasks take extended time. Tools must support asynchronous processing of long-cycle tasks to avoid single-call timeouts.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios, automatically selects appropriate tools to handle tasks such as item comparison and field verification, and aligns with the tool scheduling logic of FastGPT v4.17.0 |
| `functionCall` | `enabled` | Supports calling custom MCP services to handle complex item comparison and ledger generation logic, meeting the batch maintenance needs of this category |
| Tool call timeout setting | `120–180 seconds` | Complex transaction processing for this category usually exceeds 90 seconds. This setting reserves sufficient time to complete full item comparison and report generation |
| Incremental data sync frequency | `Once per month` | Matches the monthly update rhythm of this category's data, avoiding excessive system resource usage from full pull operations |
| Batch task shard size | `First 50 items` | Processing too many items in a single batch will cause call timeouts. Adjust the number of shards based on actual task load to balance efficiency and stability |
| Field verification rules | `Match by item category` | This category has no unified unit fields. Corresponding verification logic must be configured based on item type to ensure the completeness of service guide fields |

## Three common configuration errors
- Phenomenon: When calling a custom MCP service to handle complex transactions, the task returns a timeout error directly after exceeding the set threshold. Cause: The tool call timeout setting was not adjusted, and the system default 90-second wait time was used, which cannot cover the processing duration of complex transactions in this category.
- Phenomenon: Service guide fields returned by tool calls have missing content or format errors. Cause: The field verification rule configured to match by item category was not used, and a general verification logic was directly applied, which cannot adapt to the non-standardized field requirements of this category.
- Phenomenon: Incremental sync tasks fail to execute, and the latest government service item data is not obtained. Cause: Multi-source data sync scheduling was not configured, and only a single data source was pulled, which cannot cover national and local item update content.

## How to verify a successful configuration
- Initiate a tool call test for a single government service item, and check whether the field verification results returned by the tool conform to the business rules of the item category.
- Submit a batch comparison task containing 10 or more items, and confirm that the task execution duration does not trigger the default timeout limit.
- Trigger a monthly incremental sync task, and check whether the sync result includes the latest national and local item update content.
- View the tool call log, confirm that `functionCall` is enabled, and that the custom MCP service can be called normally.
