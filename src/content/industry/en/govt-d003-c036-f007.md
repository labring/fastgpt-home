# Ledger Aggregation and Report Generation for Government Service Item Directory and Service Guideline Maintenance: Database and Operations

## What Data for This Category Includes
This category of data covers basic government service item directories, implementation lists, service guidelines, standard material directories, flowcharts, and frequently asked questions. Data sources include the national basic government service item directory, administrative licensing item list, power and responsibility list, and local government service item databases. Data updates follow a monthly cycle. Each individual item data includes standardized fields such as item code, name, implementing entity, acceptance conditions, application material list, and service process. Some documents include material format requirements and frequently answered content.

## Constraints Imposed on Database and Operations Workflows by These Features
Multi-source data synchronization requires the database to support cross-data-source bulk import and incremental update capabilities, to avoid data duplication or omission. Monthly fixed-cycle updates create periodic high-concurrency data writes. The database connection pool must adapt to peak loads in this scenario. Logical relationships exist between item fields. The database must support complex associated queries and field integrity checks to ensure data consistency. Additionally, permission differences across government departments at different levels require the database to have fine-grained access control capabilities to protect data security.

## How to Configure Settings
This document is written for FastGPT v4.17.0. Configuration items must be determined based on the storage and query requirements of government service item data:

| Configuration Option | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/gov_service?authSource=admin` | Adapts to storage requirements for unstructured government service item data, supports flexible storage of multiple document types including service guidelines and flowcharts |
| `PG_URL` | `postgresql://user:pass@host:5432/gov_service_meta?sslmode=require` | Used to store structured fields such as item codes and implementing entities, as well as field verification rules, and supports complex SQL associated queries |
| `DB_MAX_LINK` | `20–30` | Adapts to high-concurrency requirements for monthly bulk data synchronization, avoids excessive database load caused by too many connections |
| `REDIS_URL` | `redis://:password@host:6379/1` | Used to cache frequently accessed basic item data, reduces direct database query volume and improves ledger aggregation efficiency |

## Three Common Configuration Mistakes
- Symptom: A `mongo connection failed` error appears when starting the development environment, and database connection cannot be completed. Cause: The `MONGODB_URI` parameter is not configured correctly, or the database service does not open the corresponding port, causing the workflow to fail to read basic government service item data.
- Symptom: An empty result is returned when executing a ledger aggregation task, and corresponding item data cannot be queried. Cause: The database permission configured via `PG_URL` is insufficient to access the structured data tables associated with items, or the query logic does not match the currently maintained item fields.
- Symptom: A timeout error occurs when synchronizing monthly update data in bulk. Cause: The `DB_MAX_LINK` configuration value is too low, which cannot support the concurrent connection requirements for bulk data import, causing some requests to time out.

## How to Confirm Successful Configuration
- Run the `pnpm run check-db` command to check the connectivity of the `MONGODB_URI` and `PG_URL` configurations, and confirm there are no connection errors.
- Import a single test government service item data, execute a field integrity check task, and confirm the database can correctly store and return verification results.
- Start the FastGPT service, access the government service item ledger aggregation function, and check whether the stored item list loads normally.
- Trigger a simulated monthly data synchronization task, check the synchronization logs, and confirm data can be normally imported from the source address and written to the database.
