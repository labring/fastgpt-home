# Government Service Item Catalog and Service Guide Maintenance: Ledger Summary and Report Generation - Deployment and Upgrade

## What this category of data looks like
Daily documents for maintaining government service item catalogs and service guides include basic government service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, frequently asked questions, and more. Data sources include the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases. The update frequency is usually monthly. Data typically contains fields such as item code, item name, implementing entity, acceptance conditions, application material list, and handling process. Most data is stored in structured table or structured text formats.

## Constraints on deployment and upgrade
Since most data sources are official public catalogs updated monthly, deployment must support configuration for batch import of multi-format government documents. Upgrades must retain configurations of historical synchronization tasks to avoid interrupting the monthly ledger summary process. Documents contain government-specific fields, so deployment must configure corresponding data validation rules. These rules ensure imported data complies with standard government service item formats, preventing inconsistent standards during subsequent ledger generation. Government data storage must comply with security specifications. Deployment must configure dedicated database and cache instances to ensure data stability and confidentiality.

## How to Set Configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/fastgpt?authSource=admin` | Government data volume is large, so a dedicated database instance must be specified to ensure stable storage of ledger data and avoid conflicts with other business databases |
| `DB_MAX_LINK` | `20–30 connections` | Multiple government documents will be imported in batches during monthly synchronization, so database connection count must be controlled to avoid resource exhaustion and ensure smooth execution of synchronization tasks |
| `REDIS_URL` | `redis://:[password]@[host address]:[port]/0` | Government item validation results and synchronization task status must be cached to improve response speed and stability of ledger summary |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` (local object storage scenario) | Attachments of government documents (such as flowcharts, material templates) must be stored uniformly to ensure consistent file access across multi-node deployments |
| `ROOT_KEY` | `Random 32-bit string generated according to enterprise internal key management rules` | Access to backend configuration for ledger summary must be restricted for unauthorized users, complying with security access requirements of government systems |

## Three Common Misconfigurations
- Symptom: When starting the FastGPT service, "MongoDB version not supported" or connection timeout errors appear in the console or logs. Cause: The runtime environment's CPU instruction set is not matched, a high-version MongoDB image is misused, and a compatible lower-version image is not used for deployment.
- Symptom: When batch importing government service item catalogs, some items have missing fields or format errors. Cause: The `DB_MAX_LINK` configuration value is not adjusted, excessive concurrent connections cause database write interruptions, and connection parameters are not optimized for the actual data volume.
- Symptom: After offline deployment, the backend cannot load locally stored government document templates and flowchart attachments. Cause: `STORAGE_S3_ENDPOINT` or the local storage path is not configured correctly, causing the system to fail to read offline imported document resources.

## How to Verify Proper Configuration
- Run the `mongo --version` command to confirm the MongoDB version is in the 4.4.x series, with no AVX instruction set related errors.
- After starting the FastGPT service, check the database connection count monitoring metrics in the logs to confirm the connection count stays within the `20–30 connections` configuration range.
- Manually trigger a monthly synchronization task, check the task logs for any prompts of failed data import, and confirm that field validation for government documents works normally.
- Access the backend address corresponding to the configured `FE_DOMAIN`, use the `ROOT_KEY` to log in with highest permissions, confirm that the configuration page can be accessed normally with no permission errors.

The values provided are common starting points and should be measured against the reader's own samples.
