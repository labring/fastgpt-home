# Ledger Summary and Report Generation for Government Information Disclosure Upon Application: Workflow Orchestration

## What the Data for This Category Looks Like
Business data for government information disclosure upon application mainly comes from government information disclosure platforms, agency archive systems, document management systems, departmental business ledgers, and standardized documents related to government information disclosure. Data updates occur irregularly, synchronized with the progress of individual application handling. Daily processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, response letters, delivery receipts, administrative reconsideration response materials, and similar items. Fields covered include application number, applicant information, application content, response content, handling status, delivery records, and similar items. Document scale varies significantly based on individual application cases.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multi-source heterogeneous data sources require workflows to support API integration with different systems or batch import interfaces. This avoids duplicate data entry or format incompatibility. Irregular update rhythms require workflows to support flexible configuration of on-demand or scheduled triggers. This adapts to the non-standard pace of government affairs handling. Diverse document types and fields require workflows to have built-in multi-format parsing nodes. This ensures accurate field mapping across different business documents. The lack of fixed document scale requires workflows to have sharding processing capabilities. This avoids resource limits triggered by large-volume documents. At the same time, statutory procedures for government affairs handling require workflows to execute in a fixed node sequence. This ensures no handling links are missed.

## How to Configure
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Loop body nesting depth | Within 2 levels | Government document structure has limited hierarchy; multi-level nesting easily causes execution timeouts, and aligns with the node resource limits of FastGPT v4.17.0 |
| `variables` mapping rules | Bind by application number, applicant information, and response content one by one | Corresponds to the fixed fields of business documents, ensuring accurate association between ledger data and individual applications |
| Number of document lines processed per run | Within 5000 lines | Adapts to the conventional sharding size of government Excel ledgers, avoiding memory overflow |
| File generation reference switch | Disabled | Prevents unauthorized reference content from appearing in generated response documents, complying with government response specifications |
| Multi-turn dialogue return rule | Return only the last answer | Ensures the response content obtained by applicants is concise and clear, complying with the conciseness requirements of government responses |
| Workflow node trigger logic | Execute in `nodeId` order | Ensures handling procedures advance in accordance with statutory steps, avoiding missed links |

## Three Common Configuration Errors
- Workflow runtime displays "Node execution timed out" error. Cause: Loop body nesting depth exceeds 2 levels. Government affairs workflows have insufficient node resources to support serial execution of multi-level loops.
- Task fails when processing 100,000-character Chinese Word documents or 15,000-line Excel data. The interface prompts "Insufficient memory". Cause: Large-volume documents are not processed via sharding. Loading full data directly triggers resource limits.
- Generated response documents include multi-turn question-and-answer historical context, with redundant content that does not meet requirements. Cause: The rule to return only the last answer is not configured. The workflow retains all dialogue history data.

## How to Verify Correct Configuration
- Manually trigger a test node with nested loops. Check that the execution log has no timeout error records.
- Upload a 15,000-line Excel test file. Confirm that the workflow automatically completes sharding processing and generates complete ledger data.
- Enable file generation testing. Confirm that the generated response documents have no additional reference content.
- Trigger multiple sets of question-and-answer workflows. Confirm that returned results only include the content of the last question-and-answer pair.
