# Ledger Summary and Report Generation for Government Procurement Projects: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data sources for this category include China Government Procurement Network, local government procurement websites, fiscal integration systems, purchaser budget systems, and supplier credit records. Data updates occur daily.
Daily documents cover procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning announcement notices, procurement contracts, and responses to objections. Involved entities include purchaser units, government procurement supervision departments of finance departments, procurement agencies, and evaluation experts.
Each document includes category-specific fields such as procurement budget number, supplier credit rating, and list of bid evaluation committee members. Document structure varies significantly based on document type.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Daily updated data sources require multi-turn dialogue to support real-time retrieval of the latest data. This prevents use of expired procurement plans or winning announcement content.
Differences across multiple document types require prompts to distinguish field rules for each document type. For example, bid evaluation reports require extraction of bid evaluation results, while responses to objections focus on handling results of complaint matters.
Multiple document fields require multi-turn dialogue to gradually confirm field completeness. This prevents omission of key information such as procurement budget numbers.
Different usage scenarios across entities require prompts to adapt to the needs of different roles. For example, supervision departments focus on compliance, while purchasers focus on procurement progress.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Unique identifier generated for each session | Multi-turn dialogue uses `chatId` to associate historical interactions with current context |
| `messages` | Retain the first 20 interaction records | Government procurement multi-turn dialogue requires retaining sufficient historical parameters and document information to avoid context truncation |
| `variables` | Bind dedicated variables such as procurement project number and procurement agency name | Multi-turn dialogue uses `variables` to pass category-specific fields and improve matching accuracy |
| Maximum context length | 8000–12000 token | Adapts to the total length requirements of government procurement documents and interaction content |
| Session expiration time | 24 hours | Data for this category updates daily. Sessions must be reset daily to obtain the latest procurement-related information |
| Number of documents recalled per single call | Top 5 | Government procurement-related data sources have a large number of documents. Prioritize recalling the most matching content |

## Three Common Misconfiguration Issues
- Conversation logs are not automatically cleaned, leading to context overflow. This manifests as a "context length exceeded" error in session responses. The cause is failure to configure session expiration time and failure to reset `messages` historical records according to the daily update schedule.
- Prompt shows "no knowledge base selected" during online calls, but works normally in debug preview. This manifests as the front-end interface displaying "no knowledge base bound". The cause is that the online environment is not bound to the permissions of the government procurement-specific data source, while the debug environment uses locally tested data source configurations.
- Generated ledger fields are missing. This manifests as the procurement ledger lacking the supplier credit rating field. The cause is failure to pass dedicated variables for supplier credit records via `variables`, and failure to cover the extraction rules for this field in the prompt.

## How to Verify Proper Configuration
- Initiate a query containing government procurement-specific terminology. Check the session details to confirm that `chatId` is correctly generated and associated with the current interaction. This verifies that the multi-turn dialogue context association function works correctly.
- Call the configured tool. Check that the returned knowledge base content only includes documents from government procurement data sources. This verifies that the knowledge base binding rules are active.
- Initiate consecutive multi-turn queries. Check that the number of retained `messages` meets the configured requirements. This verifies that the context truncation rules are active.
- Wait 24 hours, then initiate a query. Check that the returned documents are the latest government procurement data. This verifies that the session expiration time configuration is active.
