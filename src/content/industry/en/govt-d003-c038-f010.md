# Government Procurement Project Ledger Summary and Report Generation: Knowledge Base Retrieval and Recall

## What data for this category looks like
Data sources for this category include the China Government Procurement Network, local government procurement websites, fiscal integration systems, procurer budget systems, and supplier credit records. The update frequency is daily. Daily generated business documents cover procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning announcements, procurement contracts, and responses to bidder inquiries. Each document corresponds to a different procurement phase, and includes unique fields such as procurement project ID, bidding lot information, qualification requirements, and winning amount. Data users include procuring entities, fiscal department government procurement supervision offices, procurement agencies, and procurement review experts. Different user groups focus on distinct document fields.

## What constraints these characteristics impose on knowledge base retrieval and recall
Daily updated data requires the retrieval module to support real-time synchronization of the latest procurement announcements, bidder inquiry responses, and other documents. This avoids using expired data that could trigger compliance risks. Diverse business documents with significant field differences require retrieval configurations to support filtering recall scope by document type or procurement project group. This prevents unrelated cross-project documents from appearing in results. Multi-source data requires cross-system integrated retrieval, so configurations must be compatible with format differences across data sources. Government procurement business has extremely high compliance requirements. Retrieval results must accurately cover documents for key phases such as qualification review and bid evaluation. Missing these documents could lead to bid invalidation or regulatory penalties.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Government procurement documents contain a large number of compliance fields. A threshold that is too low will introduce irrelevant non-compliant documents, while a threshold that is too high will miss key qualification review materials. This range is calibrated based on actual testing |
| `limit` | Top 15 entries | Ledger summary needs to cover all relevant project documents. A single recall cap that is too small will risk missing associated information |
| `searchMode` | Full-text search | Government procurement documents contain compliance-related information across paragraphs. Full-text search can cover cross-field associated retrieval needs |
| `usingReRank` | Enabled | Key information in documents such as bid evaluation reports and winning announcements is scattered. Reranking can improve the ranking priority of highly relevant results |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplement general query terms related to procurement laws to cover compliance expressions that procurers may omit |
| `collectionIds` | Configured by corresponding project group | Divide datasets by procurement project to prevent unrelated cross-project documents from being recalled, improving retrieval accuracy |

## Three common mistakes
- Phenomenon: After referencing configuration variables in the knowledge base search module, the retrieval returns empty results or fails to match target documents. Cause: The `collectionIds` for the corresponding government procurement project are not correctly bound to the retrieval parameters, causing the retrieval scope to cover irrelevant cross-project datasets.
- Phenomenon: After uploading a CSV-format procurement plan document, it cannot be matched by the retrieval module. Cause: The CSV file was not uploaded using the template import function, and the text dataset import was used directly. This causes document fields to not be mapped correctly, and valid vectorized retrieval segments cannot be generated.
- Phenomenon: When batch retrieving government procurement project ledgers, timeout errors occur or the number of results is far lower than expected. Cause: `collectionIds` are not configured by procurement project group. A single retrieval scope covers the full dataset, exceeding the system's processing limit and causing recall failure.

## How to confirm the configuration is correct
- The retrieval configuration panel of FastGPT v4.17.0 is reviewed, and `collectionIds` are confirmed to be bound to the exclusive dataset for the corresponding procurement project, with no cross-project irrelevant datasets included in the retrieval scope.
- A query term related to procurement requirements is entered, and the document types of returned results are checked to confirm they include target documents such as procurement requirements and bidding documents, with no irrelevant documents from other projects mixed in.
- After the `usingReRank` function is enabled, the top-ranked results are checked to confirm they include core business documents such as bid evaluation reports and winning announcements, and that the ranking priority meets business needs.
- A test CSV-format procurement plan document is uploaded using the template import function, and confirmation is obtained that the document can be normally retrieved and matched to relevant query terms.
