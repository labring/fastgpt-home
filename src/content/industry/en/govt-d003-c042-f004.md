# Ledger Summary and Report Generation for Legal Compliance and Major Risk Management: Workflow Orchestration

## What this category of data looks like
Data sources include enterprise contract management systems, compliance risk databases, laws and regulations repositories, case management systems, and reporting platforms. Daily processed documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation reports. Each single data entry contains fields such as risk category, involved entity, review opinion, processing progress, and associated contract number. The update frequency is monthly.

## What constraints do these characteristics impose on the workflow orchestration link
Monthly update frequency requires workflows to support scheduled trigger configuration, with no need for high-frequency real-time response. Multiple data source access requirements mean configuring multiple data pull nodes in the workflow to adapt to interface formats and document structures of different systems. The multi-dimensional field feature of single data entries requires configuring field extraction nodes in the workflow to accurately extract key information such as compliance risk level and processing status. The business characteristic of many time-consuming links requires splitting workflow nodes and supporting parallel or serial orchestration, while configuring timeout and retry mechanisms to avoid overall process disruption from single node stuckness.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Question Optimization | Precede after data pull nodes | For long texts such as compliance risk lists and review opinions, optimization improves keyword extraction accuracy |
| Maximum Context | 8000–12000 token | Adapts to the long text length of compliance documents, avoids truncating key review opinions |
| `variables` | Bind monthly update time and risk level enumeration values | Adapts to the monthly update frequency requirement, unifies variable parameters in the workflow |
| `nodeId` | Assign a unique identifier to each data pull node | Facilitates tracking execution status of different data sources and troubleshooting process errors |
| Timeout Setting | 600 seconds | Covers the execution duration of time-consuming links such as compliance review and risk identification |
| Retry Count | 2 times | Avoids process interruption from a single interface call failure, and prevents data redundancy caused by repeated submissions |

## Three common mistakes
- Phenomenon: Workflow runs and returns empty compliance risk entries. Cause: No data source field mapping rules configured in `variables`, causing the node to fail to extract valid information from documents pulled from the contract management system.
- Phenomenon: Agent node runs with error "node not found". Cause: No unique `nodeId` assigned to each data pull node, causing process scheduling to fail to locate the corresponding execution node.
- Phenomenon: Workflow execution times out, status code shows 504. Cause: No timeout threshold configured for compliance review links, default duration is insufficient to complete long-text risk identification and review.

## How to confirm the configuration is complete
- Manually trigger the workflow, confirm that the number of pulled documents matches the monthly update entries of the data source.
- View process logs, confirm that each node's `nodeId` is correctly bound and has no duplicates.
- Check parameter configurations in `variables`, confirm that key fields of compliance risks and update cycle are covered.
- Simulate abnormal triggers, verify that timeout and retry mechanisms take effect as configured.
