# Ledger Summary and Report Generation for Legal Compliance and Major Risk Management: Tool Calling and Plugins

## What the data for this category looks like
Data comes from enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms. Data is updated monthly. Commonly generated documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation results. Data fields include compliance item name, risk level, review subject, processing result, associated case number, and others. There are no unified fixed units. Some fields require matching corresponding units based on associated business scenarios.

## What constraints these characteristics impose on the tool calling and plugins workflow
The monthly updated data volume is large. Tool calling must support batch retrieval of data from multiple systems to avoid exceeding per-request call limits. Interface formats of multi-source systems are inconsistent. Plugins need configured parsing rules adapted to different data sources to ensure alignment of data fields. Diverse document structures require tool calling to recognize fields across different types of compliance documents and automatically adapt to ledger summary logic. Errors may trigger major legal disputes, administrative penalties, asset losses, or reputational damage. Tool calling must include failure retry and exception alert configurations to avoid data omissions or processing interruptions.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to tool calling requirements for multiple types of compliance documents, automatically selects matching plugins to process different fields |
| `functionCall` | `enabled` | Supports structured output of ledger fields to facilitate subsequent summary and generation of standardized reports |
| Batch call batch size | `50–100 items/time` | Adapts to the scale of monthly multi-system data pulling, avoids exceeding per-request call limits |
| Data source adaptation rules | Calibrated based on actual testing | The interface formats of compliance-related systems vary across enterprises, so configuration must match actual data sources |
| Failure retry count | `2–3 times` | Addresses temporary network fluctuations or short-term interface exceptions, avoids direct process interruption from a single failed call |
| Exception alert trigger condition | Call failure exceeds retry limit, pulled data is empty | Prevents unrecognized exceptions in compliance data processing from leading to subsequent risks |

## Three common misconfigurations
- Calling the published API returns a 403 permission denied error. Cause: The access key for the compliance system has not been configured on the FastGPT platform, or the key's permissions do not cover the required data source scope.
- Adding an MCP plugin node in the workflow fails to trigger a call. Cause: The service address and authentication token for the MCP plugin have not been filled in correctly, and the plugin has not been bound to the corresponding workflow.
- Tool calling experiences timeout interruptions. Cause: The batch call batch size is set too large, or a reasonable waiting duration has not been configured, exceeding the interface's response limit.

## How to confirm the configuration is complete
- Call the test interface, confirm that the returned structured data includes the core fields of the compliance risk list and contract review opinions, and verify field alignment.
- Trigger batch data pulling, check the workflow logs, confirm that multiple system data sources have been successfully pulled and there are no abnormal errors.
- Simulate an interface exception scenario, verify that the process automatically recovers after the failure retry mechanism is triggered, and that exception alerts are pushed normally.
- Check the plugin binding relationship, confirm that the tool node in the workflow has been associated with the configured compliance-related plugin.
