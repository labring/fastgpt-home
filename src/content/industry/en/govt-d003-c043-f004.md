# Special Equipment Safety Supervision: Ledger Summary and Report Generation — Workflow Orchestration

## What the Data for This Category Looks Like
Data sources for this category include special equipment safety supervision systems, inspection and testing institution systems, user unit ledgers, and operator certificate databases. Data is updated once per month. Daily documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Data fields include equipment number, inspection validity period, maintenance cycle, operator certificate number, hidden danger rectification status, and others. Different documents have varying field formats. Classification processing based on business type is required, and no unified standardized field format exists.

## Constraints for Workflow Orchestration
Multi-data source access needs workflows to set up multi-source pull nodes to prevent missing information from single data sources. Monthly update frequency needs workflows to configure scheduled trigger nodes to match data update cycles. Differences across multiple document types need workflows to set up classified processing branches to adapt to different document field formats. Time-consuming core verification links need workflows to use automated verification nodes to replace manual verification processes. The serious consequences of errors need workflows to configure failure alert nodes to ensure timely response to abnormal situations and reduce supervision risks.

This document applies to FastGPT v4.17.0. The following are workflow configuration recommendations for this category:

| Failure Alert Configuration | Push alerts within 10 minutes of triggering | Matches the requirement for timely response to errors in this category |
| Node ID Configuration | Set a unique `nodeId` for each supervision-related node | Facilitates subsequent troubleshooting of workflow operation abnormalities |

## Three Common Configuration Mistakes
- A "missing required configuration item" error pop-up appears when editing the workflow template. This occurs because core fields required for special equipment supervision such as equipment number and inspection validity period are not configured in `variables`, resulting in missing necessary parameters when the node triggers.
- After referencing a created custom plugin, no preset parameters appear in the input box when connecting a code running node. This occurs because the plugin's output parameters are not bound to the workflow's `variables` node, causing downstream nodes to fail to obtain valid data.
- The generated supervision report is missing some maintenance record data after the scheduled workflow triggers. This occurs because parallel pull logic for multiple data sources is not configured, resulting in failure to synchronously pull data from the inspection and testing institution system.

## How to Verify Proper Configuration
- Manually trigger the workflow once, view the operation logs of each node, and confirm that all configured data sources have successfully pulled data.
- Enter the `variables` configuration page, check whether core verification fields for this category such as equipment number, inspection validity period and operator certificate number are included.
- Reference a custom plugin and connect a code running node, confirm that the input box has automatically loaded relevant parameters from the plugin output.
- Trigger a simulated run of the scheduled node, check whether the alert configuration normally pushes prompts when the simulated workflow fails.
