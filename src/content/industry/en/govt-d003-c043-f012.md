# Special Equipment Safety Supervision: Ledger Summary and Report Generation — Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from special equipment safety supervision systems, inspection and testing institution systems, user unit ledgers, and operator certificate databases. Daily processed documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Corresponding fields include equipment number, registration date, inspection cycle, maintenance unit, hidden danger content, certificate validity period, etc. The data update frequency is once per month.

## What constraints these characteristics impose on the deployment and upgrade process
Data sources for this category are scattered and require regular synchronization. Connection parameters for multiple data sources must be configured during deployment. During upgrades, compatibility of data source mapping rules between old and new versions must be ensured. The data update frequency is once per month. Trigger rules for scheduled synchronization tasks must be configured to avoid frequent synchronization occupying business system resources. Since the supervised objects are high-risk equipment, the accuracy of ledger data has high requirements. Data verification configuration must be enabled during deployment. Original field mapping logic must be retained during upgrades to prevent damage to the association relationships of existing ledger data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | Connection address corresponding to the special equipment safety supervision business database | Stores core business data such as equipment ledgers and periodic inspection reports, requires a dedicated database instance |
| `PG_URL` | `postgresql://username:password@host:5432/te_supervise` | Operator certificate databases and maintenance records mostly use PostgreSQL for storage, must match structured fields of business data |
| `REDIS_URL` | `redis://:password@redis-host:6379/0`, set cache validity period to 86400 seconds | Caches frequently queried equipment ledger data to reduce business system load and ensure synchronization efficiency |
| `DB_MAX_LINK` | `20` | Balances the request volume for concurrent ledger data synchronization and database load limits, avoids connection exhaustion |
| `STORAGE_S3_ENDPOINT` | Set based on actual measurement | Adapts to the file storage service of the supervision system, used for storing attachments such as periodic inspection reports and hidden danger rectification notices |
| `ROOT_KEY` | Configure as a secure random string | Used to enable background management permissions, ensures the security of operations such as version viewing and configuration modification |

## Three common mistakes
- Scenario: Special equipment ledger data exported from version v4.9.2 is modified using the CSV template of version v4.12.1 and then imported. An error "Data format incompatible" is prompted during training. Cause: Failed to correctly match the required field order of the new template, or omitted unique business fields for special equipment such as equipment registration certificate number and inspection validity period.
- Scenario: When searching special equipment ledgers, the number of returned results is fixed at 10 and cannot be adjusted based on supervision requirements. Cause: The `DB_MAX_LINK` configuration item was not modified, and the default value limits the number of associated data entries for a single query.
- Scenario: The current FastGPT version cannot be viewed in the deployed background interface. Cause: The `ROOT_KEY` permission was not configured, or the version identification file was not loaded correctly during deployment.

## How to confirm configurations are properly set
- One can access the FastGPT background, navigate to the data source management page, and verify that the database connection status configured with `MONGODB_URI` and `PG_URL` displays as normal.
- One can upload a CSV file of special equipment maintenance records, import it into the knowledge base, and check that the field mapping fully matches the fields of the business document.
- One can trigger a manual synchronization task, and check that there are no prompts for database connection timeout or data parsing errors in the system log.
- One can log in to the background using the `ROOT_KEY` permission, and confirm that the version information displays as FastGPT v4.17.0.
