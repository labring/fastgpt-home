# Ledger Summary and Report Generation for Environmental Law Enforcement and Monitoring Supervision: Multi-turn Dialogue and Prompt Engineering

## Data Overview for This Category
Data for this category originates from online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. The update frequency is daily. Daily documents include on-site inspection records, sampling records, monitoring reports, orders for rectification decisions, and administrative penalty decisions. Most document structures contain fields exclusive to law enforcement scenarios, such as inspection locations, sampling locations, pollutant concentration, exceedance determination results, rectification requirements, and more. Field units include environmental monitoring-specific units such as mg/L, Pa, hours.

## Constraints for Multi-turn Dialogue and Prompt Engineering Links
Multiple data sources with daily updates require that different system ledger data be gradually integrated during multi-turn dialogue, ensuring that reports cover the latest daily monitoring and law enforcement information. Documents have many fields with specialized units, so prompts must clearly specify field extraction rules to avoid confusion between unit standards from different scenarios. Law enforcement documents require a complete chain of evidence, so multi-turn dialogue must retain full-process context to ensure generated reports meet law enforcement compliance requirements. The daily data update feature requires the dialogue link to synchronize the latest online monitoring and law enforcement system data in a timely manner, avoiding the use of outdated ledger content.

## Configuration Recommendations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Count | First 6 conversation records | Law enforcement ledger dialogue needs to cover the full process of on-site inspection, data comparison, and report writing. 6 records retain key nodes without redundancy |
| `messages` Configuration | Only pass conversation fragments related to the current law enforcement task | Avoid irrelevant historical interference with ledger summary, meeting the accuracy requirements of law enforcement scenarios |
| Prompt Variable `variables` | Bind exclusive fields such as on-site locations and pollutant types | Ensure generated reports accurately match the exclusive fields and units of law enforcement documents |
| Conversation History Cache Duration | 24 hours | Matches the daily data update frequency, ensuring calls to the latest online monitoring and law enforcement system data of the day |
| Text Extraction Node Chat History | First 5 historical records | Used for text extraction in plugin nodes, filtering expired history to focus on the current law enforcement task |

## Three Common Misconfigurations
- Symptom: The number of context passes set in the workflow is 0, resulting in missing historical law enforcement data in generated ledger reports. Cause: The `messages` parameter was not correctly bound to the workflow's conversation context node, causing the API to receive no valid chat history.
- Symptom: After the text extraction plugin node runs, the extracted monitoring data units are mixed. Cause: No clear extraction rules for field units were specified in the prompt, leading to confusion between unit standards from different monitoring scenarios.
- Symptom: When accessing the deployed application via the API, the returned result is empty or contains no law enforcement ledger content. Cause: The `variables` variable binding was not enabled in the application configuration, causing the prompt to fail to call exclusive law enforcement fields.

## How to Verify Proper Configuration
- Manually trigger a law enforcement ledger summary task. The conversation history panel may be reviewed to confirm that the specified number of recent conversation records are retained.
- Call the API to access the application. The returned result may be checked for the exclusive law enforcement fields corresponding to the bound `variables` variables.
- Run the text extraction plugin node. The extracted monitoring data fields and units may be verified against the preset prompt rules.
- Review the workflow logs to confirm that the `messages` parameter has been correctly passed to the API call link, with no null or redundant content.
