# Ledger Summary and Report Generation for Environmental Law Enforcement and Monitoring Regulation: Document Parsing and Chunking

## Data Overview for This Category
This category covers entities including ecological environment law enforcement detachments, monitoring stations, pollutant discharge units, and third-party testing institutions. Daily generated documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Data sources cover online monitoring platforms, automatic pollutant source monitoring data, ecological environment law enforcement systems, and third-party test reports, with a daily update frequency.

Document structures vary significantly: on-site inspection records mostly consist of free text paired with fixed inspection fields, while monitoring reports include structured sampling data tables. Fields typically include exclusive law enforcement and monitoring information such as law enforcement document number, sampling location, and pollutant detection values.

## Constraints on Document Parsing and Chunking
Multi-source data and diverse document structures require the parsing module to adapt to both structured tables and free text content, and avoid splitting key law enforcement information such as penalty basis and sampling data. The daily updated document volume requires support for batch parsing to align with the update rhythm of daily law enforcement ledgers. Exclusive fields of law enforcement and monitoring documents must be fully retained, and field association cannot be disrupted during chunking. Otherwise, it will affect the accuracy of subsequent ledger summary and report generation, and prolong the core time-consuming steps of daily law enforcement. In addition, third-party test reports may have large file sizes, so the parsing process must support large files.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the length of single-segment information in law enforcement documents and monitoring reports, avoid splitting key content such as penalty basis and sampling data |
| `chunkSplitter` | Split by paragraph + heading | Match the structured paragraph structure of on-site inspection records and monitoring reports, retain context association |
| `customPdfParse` | Enable table recognition mode | Adapt to sampling data tables in monitoring reports, extract structured numerical fields, avoid loss of table content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 seconds | Address parsing time consumption of batch third-party test reports, avoid task failure caused by single-file parsing timeout |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Allow uploading complete annual monitoring report collections, meet the batch document needs of law enforcement archiving |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types such as law enforcement documents and monitoring reports, meet the field integrity requirements of ledger summary |

## Three Common Misconfigurations
- File upload parsing fails with a 404 error after server deployment. Cause: The file upload directory permissions or static resource mapping are not configured correctly, causing the parsing node to fail to read the document files stored on the server.
- Sampling data in tables is missing after uploading a PDF monitoring report. Cause: The table recognition mode of `customPdfParse` is not enabled, only plain text content is extracted, and structured table data is not recognized.
- Field breaks appear in chunking results when batch parsing law enforcement ledger documents. Cause: The `chunkSize` setting is too small, splitting a single complete law enforcement record into multiple independent chunks, making it impossible to associate complete information during subsequent summary.

## How to Verify Correct Configuration
- Upload a standard monitoring report PDF, check whether the parsed text includes structured fields in the table such as sampling location and pollutant concentration.
- Upload a DOCX format order for correction decision document, check whether the chunked content retains the complete law enforcement document number and rectification requirements.
- Adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter, then upload a 100 MB third-party test report collection, verify that there is no timeout error during the parsing process.
- Check the file upload directory to confirm that the uploaded documents have been correctly stored and the parsing node has read permissions.

The values listed here are common starting points and should be evaluated against the reader's own samples.
