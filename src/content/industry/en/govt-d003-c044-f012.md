# Ledger Summary and Report Generation for Environmental Law Enforcement and Monitoring Supervision: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Daily documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. These documents use both structured table and unstructured text formats. Data is updated daily. Fields cover sampling points, monitoring time, pollutant concentration, law enforcement officer information, rectification requirements, and other relevant items. Units change dynamically based on the type of monitoring indicator.

## What constraints these characteristics impose on the deployment and upgrade process
This category has multi-source data updated on a daily basis. During deployment, configure task scheduling rules adapted for batch synchronization to avoid system lag caused by excessive data volume in a single synchronization batch. Documents use both structured and unstructured formats. During the upgrade process, retain parsing compatibility support for different data formats to ensure core documents such as law enforcement documents and monitoring reports can be imported and parsed normally. Data fields change dynamically based on monitoring indicators. During deployment, reserve configurable items for custom field mapping, and verify data accuracy check logic to avoid missing fields or format errors in law enforcement evidence data. For internal network deployment scenarios, configure connectivity parameters for cross-system data pulling to ensure normal access to data from online monitoring platforms and law enforcement systems. Follow internal network security specifications to configure permission verification rules.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15` | Adapts to the daily batch synchronized volume of law enforcement and monitoring data, prevents database connection exhaustion |
| `REDIS_URL` | Internal Redis instance address, configure a dedicated connection password | Stores daily updated monitoring data cache and session information, ensures security for internal network deployments |
| `STORAGE_S3_ENDPOINT` | Internal network address of the internal object storage service | Stores unstructured documents such as law enforcement documents and monitoring reports, meets storage requirements for internal network deployments |
| `PG_URL` | PostgreSQL database address connected to the ecological environment law enforcement system | Stores structured law enforcement records and monitoring ledger data, ensures data persistence and query efficiency |
| `ROOT_KEY` | Random 32-bit string generated according to internal network security specifications | Configures system administrator permission verification, prevents unauthorized access to core configuration pages |
| `FILE_TOKEN_KEY` | Key string aligned with the internal network file service | Verifies the legitimacy of imported files such as third-party test reports and on-site inspection records, prevents malicious file imports |

## Three common mistakes
- Symptom: The `docker build` command returns the `EMFILE: too many open files` error. Cause: The file descriptor limit for the Docker container was not adjusted. File handle exhaustion is triggered when synchronizing a large number of documents such as monitoring reports and law enforcement records.
- Symptom: Structured fields cannot be automatically mapped when importing third-party test reports after internal network deployment. Cause: `FILE_TOKEN_KEY` was not configured to align with the internal network file service, leading to insufficient file parsing permissions and inability to read core fields such as sampling points and concentration values in documents.
- Symptom: The voice input function cannot be triggered normally when accessing the front-end page via a mobile device. Cause: No mobile internal network access domain name whitelist was added to the `FE_DOMAIN` configuration, causing front-end voice interface requests to be blocked by security policies.

## How to confirm the configuration is complete
- Run a batch synchronization test, import 100 simulated law enforcement records and monitoring reports. Verify that the database connection count does not exceed the limit set by the `DB_MAX_LINK` configuration, and no connection timeout errors occur.
- Access the front-end address configured in `FE_DOMAIN`. Use `ROOT_KEY` to verify that the administrator permission page can be logged into normally, with no unauthorized access prompts.
- Upload a standard third-party test report. Check that structured fields are automatically extracted and mapped to the system ledger, with no missing fields or parsing errors.
- Log in to the cache instance corresponding to `REDIS_URL`. Confirm that daily updated monitoring data caches have been generated normally, with no expiration or loss.
