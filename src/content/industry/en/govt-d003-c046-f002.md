# Ledger Summary and Report Generation for Social Assistance and Minimum Living Allowance Review: Vector Models and Indexing

## What this category of data consists of
Data comes from daily business documents of civil affairs bureau assistance sections, sub-district or township civil affairs offices, community committees, and verification centers. These documents include minimum living allowance application forms, family economic status verification reports, household survey forms, democratic review records, public notice materials, and assistance approval forms.
Data is sourced from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities.
Update frequency is monthly. Core fields include family member information, income and property details, approval process nodes, and public notice results.

## Constraints on vector models and indexing
Monthly batch data updates require indexes to support incremental synchronization mechanisms, to avoid excessive system resource usage from full index rebuilding.
Multi-source heterogeneous cross-department data format differences require indexes to adapt to field parsing rules for different document types.
Long text content related to family economic status requires vector models to accurately capture fine-grained semantics such as income and property, and family relationships.
Ledger summary requires association across multiple document types, so indexes must support cross-document associated retrieval. This ensures that corresponding approval, public notice, and other supporting materials can be fully retrieved during report generation.

## How to configure the system
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Core documents for this category are mostly business forms and verification reports of 1000–2000 characters. Chunk length covers complete semantic units to avoid semantic fragmentation |
| Overlap Length | 100–200 characters | Long text chunks must retain contextual connections to ensure cross-chunk semantic coherence, adapting to long paragraphs such as family income details |
| Similarity Threshold | Calibrated based on actual testing | Data for this category requires strict matching of the association between family information and assistance eligibility. The threshold must be adjusted based on actual business scenarios |
| Maximum Search Results per Request | Top 10 entries | Ledger summary only needs to retrieve core supporting materials. Excessive results will add redundant processing for report generation |
| `maxToken` | 8192 | Mainstream vector model maximum token limit supported by FastGPT v4.17.0, adapting to the total token requirements of documents in this category |
| `defaultToken` | 1024 | Average token count per text chunk, balancing retrieval accuracy and processing efficiency |

## Three common configuration errors
- Symptom: Index construction process stalls with no response, logs show timeout status. Cause: Incremental synchronization mechanism is not configured for monthly batch large-scale data updates, and full index rebuilding occupies excessive system resources.
- Symptom: Associated documents are missing in retrieval results, with empty fields. Cause: Indexes are not adapted to heterogeneous formats of cross-department shared data, and non-standard field content is not parsed correctly.
- Symptom: Language model calls fail after configuring the index model, with a prompt that the model does not exist. Cause: The configuration entry for the index model is confused with that of the language model, and independent configuration items for the language model are not retained.

## How to verify a successful configuration
- Check index construction logs to confirm that incremental synchronization tasks can automatically trigger according to the monthly update schedule, with no timeout errors.
- Test retrieval of family income detail documents to confirm that the field completeness of returned results meets business requirements, and adjust the similarity threshold as needed.
- Verify that index model and language model configurations exist independently, with no conflict errors when switching between different models.
- Retrieve associated supporting materials for a single minimum living allowance application form, to confirm that cross-document associated retrieval can normally return corresponding approval forms and public notice records.
