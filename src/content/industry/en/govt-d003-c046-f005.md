# Social Assistance and Minimum Living Standard Guarantee Audit: Ledger Summary and Report Generation - Tool Calling and Plugins

## What this category of data looks like
Core data for this category comes from daily business documents in civil affairs public service scenarios, including minimum living standard guarantee application forms, family economic status verification reports, household survey forms, democratic appraisal records, public announcement materials, and assistance approval forms. Data sources cover low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update frequency is monthly. Data fields include family income and property details, family member relationships, approval process nodes, public announcement results, assistance qualification judgments, and similar content. Field units are adapted to specific business attributes.

## What constraints do these characteristics impose on the tool calling and plugins workflow
The data sources for this category involve cross-department and cross-system interfaces. Tool calling must connect to multiple data source plugins at the same time to ensure coverage of all core business data. The monthly update frequency requires that scheduled tool calls match the data synchronization cycle to avoid missing information about the latest assistance recipients. Business document types are diverse and closely related, so tool calling must support multi-file associated parsing to ensure field linkage between household survey records and verification reports. Errors may lead to incorrect or missed assistance guarantees, recovery of assistance funds, or public complaints, so stricter parameter verification and result structuring requirements apply to tool calling.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatic tool selection logic adapted to multiple types of civil affairs business documents |
| Scheduled trigger cycle | 00:00 on the 1st of each month | Matches the completion schedule of cross-department data monthly updates |
| Multi-file association switch | Enabled | Associates related documents such as family economic status verification reports and household survey forms |
| Parameter verification level | Strict | Prevents incorrect or missed assistance guarantees caused by field errors |
| Response timeout threshold | 300 seconds | Adapts to the average response delay of cross-department data interfaces |
| `functionCall` | Force return preset structured fields | Ensures standardized field output for ledgers and reports |

## Three common mistakes
- Symptom: The API call returns empty family property fields with no error prompt. Cause: The data source plugin for cross-department shared data is not configured, and only the local document parsing module is called.
- Symptom: The monthly ledger generated on schedule is missing records of newly added minimum living standard guarantee recipients from the previous month. Cause: The scheduled trigger cycle is set later than the actual completion time of cross-department data synchronization.
- Symptom: Non-preset approval status values appear in the generated minimum living standard guarantee audit report. Cause: The parameter constraint for `functionCall` is not enabled, and the large model returns custom field content.

## How to confirm the configuration is complete
- Manually trigger a tool call, check whether the returned results include the three core business fields: family economic status, family member relationships, and approval process.
- View the data source plugin connection status panel, confirm that the interfaces of the low-income population dynamic monitoring platform and resident family economic status verification system are in normal connectivity.
- Compare the ledger generated last month with the data source files updated this month, confirm that newly added assistance recipients have been correctly included in the ledger.
- Submit test minimum living standard guarantee application forms and household survey documents, check whether `functionCall` returns structured results that conform to the preset format.
