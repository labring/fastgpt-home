# Ledger Summary and Report Generation for Social Assistance and Minimum Living Allowance Review: Model Access and Configuration

## What this category of data looks like
Data for this category comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-departmental shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax authorities, and other relevant departments. Data updates occur monthly. Core documents include minimum living allowance application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Data fields cover family income, property status, family member information, assistance application status, and other related items. Units match the standard format of the corresponding documents.

## Constraints Imposed on Model Access and Configuration
Integrating cross-departmental multi-source data requires models to support context integration of multi-format documents, avoiding data fragmentation. The low-frequency monthly update cycle does not require an extra-long context window, reducing model computing resource consumption. Complete citation of multiple supporting documents requires strict control of token allocation to prevent core verification data from being truncated. Data accuracy directly links to assistance qualification determination, so model generation must meet higher rigor standards than general scenarios.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Value |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapt to the total context length of monthly cross-departmental data, avoid window overflow |
| `maxTokens` | `2000–3000 token` | Match the conventional output length of ledger summary and report generation, control single-round generation costs |
| `quoteMaxToken` | `1500 token` | Retain complete citations of core supporting documents such as family economic status verification reports and household survey forms |
| `toolChoice` | `auto` | Support models to independently choose whether to call tools to integrate cross-departmental shared data |
| `temperature` | `0.1–0.3` | Ensure the rigor of minimum living allowance qualification determination and ledger content, reduce generation deviation |
| `AIPROXY_API_ENDPOINT` | Fill in according to the actual deployed proxy address | Adapt to domestic large model access requirements, compatible with models outside the OpenAI ecosystem |
| `AIPROXY_API_TOKEN` | Fill in according to the valid token generated by the proxy platform | Complete identity verification for model access, address scenarios without OpenAI API keys |

## Three Common Mistakes
- Phenomenon: The interface displays an invalid token, and the interface returns a 401 status code. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or the proxy platform has not opened call permissions for the corresponding model.
- Phenomenon: The generated report is missing core verification data fragments. Cause: The value of `quoteMaxToken` is too small, and supporting documents such as family economic status verification reports are truncated.
- Phenomenon: Single-round generation tasks time out. Cause: The value of `maxContext` exceeds the native context window limit of the model, or the proxy interface is not configured with a reasonable timeout threshold.

## How to Confirm the Configuration Is Complete
- Test access to the specified domestic large model, verify the connectivity of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, and confirm the interface returns a 200 status code.
- Upload a single family economic status verification report, check whether the generated context fragment completely includes the core fields of the document with no obvious truncation.
- Adjust the `temperature` parameter, compare two generated minimum living allowance qualification determination results, and confirm the difference meets rigor requirements.
- In FastGPT v4.17.0, simulate a batch processing task for monthly data updates, and verify the configuration combination does not cause generation failures.
