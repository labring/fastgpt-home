# Ledger Summary and Report Generation for Social Assistance and Minimum Living Standard Verification: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Core data for this category comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-departmental shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax and other departments. Daily documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic review records, public notice materials, and assistance approval forms. Data updates occur once per month. Most documents contain fields such as family income, property amount, personnel relationships, approval progress, with units including currency, population count, living area, and others.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Cross-departmental data sources are scattered, and the update frequency is fixed at once per month. The knowledge base retrieval and recall link must support regular full synchronization or incremental updates to avoid data lag that harms verification accuracy. Document types cover structured forms and unstructured supporting materials, including both standardized fields and handwritten or scanned original materials. The retrieval mode must balance precise field matching and fuzzy matching of supporting content. Errors in the verification link directly relate to incorrect or missed assistance security, fund recovery, and public complaints. Retrieval and recall accuracy and result relevance must strictly meet business requirements. Ledger summary and report generation need fast access to relevant materials, which imposes clear constraints on retrieval efficiency.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Social assistance verification requires highly matching supporting materials to avoid low-relevance content interfering with the verification process, which aligns with the parameter adjustment range of FastGPT v4.17.0 |
| `limit` | Top 8 entries | Ledger summary needs to cover major family economic verification and household survey-related materials. Excessive results will increase the context processing burden and reduce report generation efficiency |
| `searchMode` | Hybrid vector retrieval + keyword retrieval | Cross-departmental data has multiple sources, including both structured fields and unstructured supporting materials. The hybrid mode balances precise field matching and keyword recall |
| `usingReRank` | Enabled | Verification scenarios have high requirements for recall accuracy. The re-ranking function filters low-relevance results and reduces the risk of incorrect assistance |
| `datasetSearchUsingExtensionQuery` | Enabled | User questions may omit professional terms. Extended queries cover professional field descriptions in documents and improve recall coverage |
| `collectionIds` | Bound to the civil affairs assistance-specific knowledge base collection | Isolate data from other categories to avoid irrelevant documents interfering with minimum living security verification retrieval results, ensuring data targeting |

## Three Common Misconfigurations
- Symptom: Markdown formatting is not rendered correctly in context citations, only separators are displayed. Cause: The chunking configuration of knowledge base documents did not retain original format markers, or the format retention parameter was not enabled during retrieval.
- Symptom: 60-second timeout error occurs when switching knowledge base indexes. Cause: Cross-departmental data source synchronization is not configured for incremental updates. The data volume during full index reconstruction exceeds the single-processing threshold, leading to timeout.
- Symptom: Some questions cannot reference files in the knowledge base. Cause: The retrieval mode does not cover keyword matching, or the document fields do not match the keywords in the user's question, resulting in recall failure.

## How to Confirm the Configuration Is Properly Set Up
- Submit a test query containing the keywords "family income" and "household survey", verify that the returned context includes exclusive documents such as minimum living security application forms and family economic status verification reports.
- Check the sorting of retrieval results, confirm that highly matching documents are ranked first, and verify that the re-ranking function is active.
- Manually trigger an index update, observe whether the update status is completed within a reasonable time frame, and confirm there are no timeout errors.
- View the knowledge base collection binding status, confirm that only the civil affairs assistance-specific dataset is associated, and no irrelevant data is mixed into the retrieval results.

The values listed above are common starting points and should be evaluated against the reader's own samples.
