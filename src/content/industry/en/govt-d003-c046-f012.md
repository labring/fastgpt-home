# Ledger Summary and Report Generation for Social Assistance and Minimum Living Security Review: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update frequency is monthly. Daily processed documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Core fields include per capita household income, total property, family member relationship, and assistance qualification determination result. Field units include yuan, person, household, etc. The length of individual documents varies greatly.

## What constraints these characteristics impose on the deployment and upgrade link
Cross-department data sources require support for multi-system data docking during deployment, and a stable storage and synchronization link must be configured. The monthly update rhythm requires retaining the incremental synchronization capability of historical data during upgrades to avoid excessive time consumption from full migration. The large variation in document length requires retrieval and storage configurations to adapt to business documents of different lengths. Data accuracy is directly linked to assistance qualification determination. Data verification rules must be configured during deployment to prevent erroneous data from flowing into the ledger, and avoid the risk of incorrect or missed assistance guarantees or fund recovery.

## How to set the configurations
The following configurations apply to FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 connections` | Adapt to the concurrent connection requirements of cross-department data synchronization, and avoid connection pool exhaustion |
| `MONGODB_URI` | Fill in the dedicated connection address of the civil affairs business data storage repository | Isolate business data from other system data, and ensure the storage security of assistance ledgers |
| `REDIS_URL` | Configure a dedicated cache instance address, set the cache validity period to 7200 seconds | Accelerate high-frequency queries of cross-department data, and reduce repeated call overhead |
| `STORAGE_S3_ENDPOINT` | Connect to the endpoint address of the internal object storage of the civil affairs system | Uniformly store all types of business documents and ledger data, and adapt to the storage requirements of monthly batch updates |

## Three common mistakes
- Symptom: Database insertion operation reports an error, returns status code 500, and business fields are empty. Cause: The `DB_MAX_LINK` configuration value is set too low, and concurrent synchronization requests exhaust the database connection pool.
- Symptom: The second half of the ledger summary result for long documents is missing, and the number of retrieved results is insufficient. Cause: No adaptation is made for the length difference of civil affairs business documents, and the storage configuration is not optimized for long documents.
- Symptom: Cross-department data synchronization tasks time out and interrupt, and no synchronization data is written to the ledger. Cause: The `REDIS_URL` configuration uses a shared instance, and cache resources are occupied by other systems, causing high-frequency query delays.

## How to confirm the configuration is complete
- Execute the built-in database connectivity test, verify the connection status of `MONGODB_URI` and `REDIS_URL`, and confirm no timeout or authentication failure errors occur.
- Import the longest single business document, run the ledger generation task, and check the completeness of core fields between the output result and the original document.
- Trigger the monthly incremental synchronization task, review the synchronization log, and confirm that the number of cross-department data entries written is consistent with the statistical results of the source system.
- Check the file list in the internal object storage, confirm that all uploaded business documents have been correctly archived, with no loss or damage.
