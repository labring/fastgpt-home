# Ledger Summary and Report Generation for Administrative Penalty Case Handling: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Data for the administrative penalty case handling category comes from administrative law enforcement case handling systems, law enforcement recorder footage, the National Enterprise Credit Information Publicity System, and departmental supervision databases. The update frequency is once per day. Daily documents include on-site inspection records, interrogation records, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, and delivery receipts, among others. Core fields include law enforcement subject, determination of illegal facts, applicable legal provisions, penalty discretion results, document number, and filing status. All documents must form a complete penalty evidence chain, and the data structure changes dynamically with law enforcement process nodes.

## Constraints for HTTP Interfaces and External Systems
Multiple data sources require interfaces to support cross-system data pulling and integration, and adapt to data formats and permission rules of different systems. Daily update frequency requires interfaces to support scheduled synchronization or incremental pulling, to avoid occupying business system resources with repeated full data pulls. Diverse document types require interface parameters to support field mapping and legality verification for different documents. Severe error consequences require interfaces to have retry mechanisms and exception capture capabilities, to ensure the accuracy of ledger summary and report generation. Interfaces must also be compatible with call frequency limits of existing law enforcement agency case handling systems.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
|---|---|---|
| `Authorization` | Bearer token obtained from the FastGPT application key page, formatted as `Bearer sk-xxxxxx` | Complies with FastGPT API authentication specifications, ensures legitimacy of external system requests |
| `variables` | Pass custom parameters such as law enforcement agency ID, data synchronization start time, and associated case ID, in JSON format key-value pairs | Adapts to ledger summary requirements for multiple law enforcement subjects, enables precise matching of data and cases |
| `responseData` | Specify return fields as law enforcement subject, document number, penalty decision, and filing status | Only return core fields required for ledger summary and report generation, reduces invalid data transmission |
| Request timeout | 600 seconds | Administrative penalty case data volume is large, sufficient time must be reserved for interface response and data processing |
| File upload size limit | 1000 MB | Supports uploading and associating law enforcement recorder footage and batch evidence materials |
| Synchronization trigger mode | Scheduled trigger at 2:00 AM daily | Matches the daily update rhythm of business data, avoids peak hours of business systems |

## Three Common Mistakes
- Interface returns 404 Not Found: FastGPT application API access path is not configured correctly, or a FastGPT version that does not support external interface calls is used.
- Calling the `/api/core/dataset/update` interface returns 500 Internal Server Error: This interface is not publicly documented in FastGPT's open API documentation, and only supports internal calls from the frontend page; external systems cannot directly send requests.
- Local law enforcement files are uploaded with empty background ledger fields: The law enforcement case ID associated with the file is not passed via the `variables` parameter, causing the interface to fail to match the corresponding ledger data.

## How to Confirm Configuration Is Complete
- On the application management page of FastGPT v4.17.0 and above versions, copy the `Authorization` token, send a request with this header in an API testing tool, and confirm that a 200 OK status code is returned.
- Pass preset `variables` parameters, send a test request, and check that the returned `responseData` contains the preset core business fields.
- Upload a test law enforcement record file, and verify that the ledger data returned by the interface matches the associated information of the local file.
- Simulate a daily update scenario, send a scheduled synchronization request, and confirm that the interface can normally pull the latest administrative penalty case data and complete ledger summary.
