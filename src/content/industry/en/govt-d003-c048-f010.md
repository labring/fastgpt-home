# Administrative Licensing Approval Ledger Summary and Report Generation: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Service subjects for this category include government service centers, administrative approval bureaus, and industry authority approval divisions.
Data comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository.
Data is updated daily.
Daily documents include service guides, application forms, commitment letters, acceptance notices, correction notices, administrative licensing decision documents, and license certificates.
Data structure combines structured fields and unstructured text. Core content includes item codes, application material lists, legal basis, and handling conditions.

## What constraints these characteristics impose on knowledge base retrieval and recall
The daily update requirement means the retrieval pipeline must sync with the latest administrative licensing item list and item database. This avoids using expired content.
Document types cover structured forms and unstructured approval documents. The system must balance precise field matching and full-text semantic recall.
Core fields such as item codes and application material lists require retrieval to support targeted recall by business fields.
Electronic certificate data retrieved across departments is scattered across different systems. Multi-source dataset linked retrieval must be configured.
Recall results must strictly correspond to legal basis and handling conditions. This avoids approval risks caused by retrieval bias.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Adapts to semantic matching needs for legal basis and handling conditions of administrative licensing items, balances recall precision and coverage |
| `limit` | Top 8-12 entries | Matches single-item retrieval needs for administrative licensing approval, avoids excessive redundant results interfering with field extraction for ledger summary |
| `searchMode` | Keyword and semantic hybrid retrieval | Balances structured field matching and semantic recall for unstructured text, adapts to multiple types of approval documents |
| `usingReRank` | Enabled | Reorders recall results to improve relevance to current approval item queries, reduces incorrect matches |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates extended retrieval terms based on original queries, covers implied application material requirements in service guides, improves recall completeness |
| `collectionIds` | Dataset IDs divided by administrative licensing business domains | Divides datasets by item categories, enables targeted retrieval of approval documents in corresponding fields, avoids interference from cross-domain retrieval |

## Three common mistakes
- Phenomenon: After importing a Feishu document with images, retrieval results cannot associate approval requirements in the images, and returned fields are empty. Cause: Multimodal recall configuration for unstructured content is not enabled, only plain text fragments in the document are extracted.
- Phenomenon: A configuration error pop-up appears when creating a new knowledge base, prompting dataset connection failure. Cause: The access permission for the dataset corresponding to `collectionIds` is not correctly configured, or the data source connection for the administrative licensing item database is not completed.
- Phenomenon: Retrieval results include expired administrative licensing item content, leading to entries in ledger summary that do not match the current list. Cause: Daily automatic sync configuration is not enabled, cached historical data is used.

## How to confirm the configuration is properly set
- Log in to the FastGPT v4.17.0 backend, view the dataset sync log, confirm that the daily incremental sync task for the administrative licensing item database runs normally.
- Initiate a single-item retrieval test, verify that the number of results returned under the `similarity` threshold matches the value set in the `limit` configuration, and the top 3 results highly match the target item.
- Import a test service guide document, check whether the returned results include the approval requirements in the images after triggering retrieval, confirm that the multimodal recall function works properly.
- Check the `collectionIds` configuration, confirm that only dataset IDs corresponding to the current administrative licensing business domain are included, avoid interference from cross-domain retrieval.
