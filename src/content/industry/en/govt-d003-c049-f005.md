# Ledger Summary and Report Generation for Legality Review of Regulatory Documents: Tool Calling and Plugins

## Data for This Category
Data for this category originates from regulatory and rule databases, higher-tier law databases, departmental policy document repositories, and administrative regulatory document filing systems. Update frequency is irregular. Daily processed documents include regulatory draft documents, drafting explanatory notes, legality review opinions, solicited opinion summaries, and filing reports. Document fields include document number, drafting unit, review conclusion, opinion solicitation status, and filing transfer nodes, among others. No unified standardized field format exists, so configurations must adapt to the field definitions of each department’s internal systems.

## Constraints Imposed by Data Characteristics on Tool Calling and Plugin Workflows
Because data sources for this category are scattered and update frequency is irregular, tool calling must support on-demand or scheduled synchronization of multiple data sources to avoid legality review deviations caused by delayed data. Daily processed document types are diverse, so plugins must adapt to parsing files of different formats to ensure complete text extraction. Fields have no unified standardized format, so the tool calling workflow must support custom field mapping to align document fields from different sources to the standard structure of review ledgers. Additionally, legality review involves core steps such as higher-tier law comparison, so tool calling must be limited to compliant official data sources to prevent access to unauthorized data sources.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Select `functionCall` mode | This category requires precise calling of specified tools to complete legality comparison and ledger aggregation. This mode allows explicit specification of tool calling trigger logic |
| Tool calling timeout threshold | 600–900 seconds | Legality review requires comparison of multiple higher-tier law and policy documents. Single call duration is long, so this reasonable interval is determined based on actual testing |
| Batch document pull limit | First 20 items | Adapts to the volume of documents in a single review workflow, avoiding timeouts caused by pulling too much data at once |
| Plugin trigger timing | Trigger at review nodes | Aligns with the workflow nodes of legality review, only calling plugins when data comparison or summary generation is required |
| Result aggregation rule | Group by document number | Aligns with the standard field structure of ledgers, ensuring traceability of summarized data |

## Three Common Misconfigurations
- Issue: After configuring a plugin, the interface displays a call failure, and logs return a parameter mismatch error. Cause: FastGPT v4.17.0 updated the parameter validation rules for `functionCall` mode, and the local model’s calling parameter format was not updated synchronously.
- Issue: After calling a search plugin, the returned result is empty with no error message. Cause: The data source of the administrative regulatory document filing system was not added to the plugin’s accessible range, so the plugin cannot pull corresponding data.
- Issue: The ledger chart generated after calling the chart tool is empty. Cause: The result aggregation rule was not configured to group by document number, so the tool cannot identify valid aggregation fields and cannot generate visual content.

## How to Verify Successful Configuration
- Manually trigger a tool call, and check if logs show that `functionCall` mode is enabled with no parameter validation errors.
- Upload a test regulatory document draft, trigger plugin calls, and confirm that corresponding higher-tier law comparison data can be pulled from the specified data sources.
- Run the ledger summary workflow, and check if the generated summary document includes the expected field grouping, with no empty fields or garbled text.
- Check if the plugin trigger timing aligns with review workflow nodes, and confirm that tool calls are only triggered when necessary.
