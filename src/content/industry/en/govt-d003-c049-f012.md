# Legality Review of Regulatory Documents: Ledger Summary and Report Generation - Deployment and Upgrade

## What data for this category looks like
The data sources for this category are the regulatory and rule repository, higher-level law database, departmental policy document repository, and administrative regulatory document filing system.
Documents processed daily include regulatory document drafts, drafting explanations, legality review opinions, solicited opinion summaries, and filing reports.
Update frequency is irregular, triggered by review processes and filing progress.
Fields include document identifier, drafting entity, review node records, opinion summary entries, filing status, and others.
Document identifier uses string format. Audit date uses standard year-month-day format. Opinion summary entries use integers as the statistical unit.

## Constraints imposed by these characteristics on deployment and upgrade
Dispersed data sources and irregular updates require configuring incremental synchronization rules for multiple data sources. This avoids full data pulls consuming excessive government intranet bandwidth.
Diverse document types and sensitive review content require configuring a unified permission verification mechanism. This ensures access compliance across different review stages.
Ledger summaries require cross-node data from multiple systems. Upgrade steps must optimize cache strategies for associated queries to reduce resource usage from repeated requests.
Data storage in government scenarios must meet confidentiality requirements. Deployment steps must configure compliant storage service endpoints to ensure secure storage of review documents.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 80–120 connections | Limits the concurrent connection count of the database connection pool, adapts to the load requirements of multi-data source synchronization, prevents server resource exhaustion, and aligns with the connection pool rules of FastGPT v4.17.0 |
| `MONGODB_URI` | `mongodb://username:password@host:port/admin?authSource=admin` | Stores structured data such as legality review opinions and filing records, supports concurrent read and write operations across multiple nodes |
| `PG_URL` | `postgresql://user:pass@host:5432/fastgpt?sslmode=require` | Stores metadata of regulatory documents and associated fields for ledger summaries, supports complex cross-table associated queries |
| `REDIS_URL` | `redis://:auth@redis-host:6379/1` | Caches the results of cross-data source associated queries, improves response speed of ledger summaries, and reduces repeated request pressure on the database |
| `STORAGE_S3_ENDPOINT` | Government cloud storage endpoints determined through actual testing | Stores attachments of regulatory documents during the review process, adapts to upload and download requirements for large files |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Encrypts access tokens for regulatory documents, ensures only authorized users can access sensitive review documents, and complies with government data confidentiality specifications |

## Three common configuration errors
- Phenomenon: After upgrading to FastGPT v4.17.0, running the initial sync script returns a 404 error. Cause: The access key and endpoint address for `STORAGE_S3_ENDPOINT` were not configured correctly, causing the storage service to fail to respond to sync requests.
- Phenomenon: Some solicited opinion summary data is missing from ledger summary results. Cause: Read/write permissions for the corresponding data source were not configured in `MONGODB_URI`, so opinion summary records stored in MongoDB cannot be pulled.
- Phenomenon: Database connection timeout occurs when generating legality review reports. Cause: A reasonable upper limit for `DB_MAX_LINK` was not set, causing the connection pool to be exhausted during multi-data source sync, preventing new database connections from being established.

## How to confirm the configuration is correct
- Access the data source configuration page in the FastGPT backend, run connection tests for `MONGODB_URI` and `PG_URL`, verify test results show success, confirming that corresponding business data can be pulled normally.
- Generate a set of test document links encrypted with `FILE_TOKEN_KEY`, verify that only authorized government intranet users can access the document normally, and unauthorized users cannot view the content.
- Trigger an incremental sync task, check the storage service logs corresponding to `STORAGE_S3_ENDPOINT`, confirm there are no failed upload records for review attachments.
- Check the system's connection pool monitoring metrics, confirm that the configured value of `DB_MAX_LINK` matches the current concurrent request connection count, with no connection exhaustion alerts.

The values provided here are common starting points and should be measured against the reader's own samples.
