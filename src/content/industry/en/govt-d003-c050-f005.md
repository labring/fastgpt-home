# Ledger Summary and Report Generation for Fiscal Expenditure Performance Evaluation: Tool Calling and Plugins

## What data this category processes
Data processed by this category originates from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. Update frequency is annual. Daily processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Data fields cover project unique identifiers, fund disbursement details, performance indicator completion status, satisfaction survey results, and other fields, with units including monetary amount, number of participants, and similar units.

## Constraints imposed by these characteristics on tool calling and plugins
The annual update requirement mandates that tool calling support batch processing of full-year ledger data generated centrally at year-end, to avoid single-processing timeouts. Multi-source heterogeneous data sources require plugins to adapt to exported files in different formats, including those from the unified budget management system and business ledgers. Daily documents include both structured tables and unstructured supporting materials, so tool calling must support both structured field extraction and unstructured content parsing. The step to verify the correspondence between funds and performance targets is time-consuming. Plugins can call external verification tools to automatically complete this matching. Rectification reports must be associated with performance evaluation results, so plugins must implement cross-document content association and summarization.

## Three Common Configuration Mistakes
- Symptom: Basic chart plugin outputs `none`, cannot generate performance analysis chart URL. Cause: Incorrect configuration of the performance indicator field mapping required by the plugin, so the plugin cannot obtain valid data.
- Symptom: Code running plugin returns empty results after execution. Cause: Failure to adapt to the field naming rules of fiscal ledger data, so the JavaScript code cannot correctly extract target elements from JSON.
- Symptom: Plugin call times out and interrupts. Cause: Failure to adjust the plugin timeout setting, exceeding the default timeout limit when batch processing full-year ledger data.

## How to Confirm Successful Configuration
- Run a plugin call test for a single performance ledger entry, verify that the plugin can correctly extract specified field content.
- Batch import a small volume of annual ledger data, check that the plugin processing results cover all configured fields.
- View plugin execution logs, confirm that all call requests complete within the set timeout period.
- Test the cross-document association function, verify that rectification reports can correctly associate corresponding performance evaluation data.
