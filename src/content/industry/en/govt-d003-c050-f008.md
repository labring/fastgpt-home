# Ledger Summary and Report Generation for Fiscal Expenditure Performance Evaluation: Document Parsing and Chunking

## What this category of data looks like
Data for this category mainly comes from the budget management integrated system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Documents processed daily include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. These documents contain structured fields and unstructured supporting content. Fields cover project numbers, fund amounts, performance indicators, and similar items. Documents from different sources have varying formats, with no unified fixed typesetting standards.

## What constraints these characteristics impose on the "document parsing and chunking" link
Annual concentrated updates create demand for batch processing of multiple large-volume documents. Support for batch parsing and large file uploads is required. Diverse document types and inconsistent formats require balancing parsing accuracy for structured tables and non-paragraph text. Performance evaluation needs to accurately match fund expenditures with corresponding performance targets. Chunking operations must not split associated fields and content. Multiple supporting materials are submitted with the main report. Associated information across documents or paragraphs must be avoided from being split. The system must also adapt to the dedicated field logic of fiscal management documents to prevent loss of key performance information.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0, adapted to the document processing needs of the fiscal expenditure performance evaluation scenario:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the full length of individual performance indicators and associated fund records in performance evaluation documents, avoiding splitting associated content |
| `chunkSplitter` | Preset delimiters + semantic segmentation | Compatible with format differences across multiple document types such as performance target forms and self-assessment forms, retaining structural association between tables and corresponding explanatory text |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses large-volume performance reports and supporting materials uploaded during annual concentrated batches, avoiding timeout errors caused by overly long parsing times |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch upload of complete ledgers and report files for annual projects, adapting to single-batch large-volume data requirements |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types such as self-assessment forms and rectification reports, adapting to the dedicated field logic of fiscal management documents |
| `customPdfParse` | Enabled | Optimizes parsing of PDF-format performance evaluation reports, retaining table typesetting and field positions from the original document to reduce information loss |

## Three common mistakes
- Uploading a PDF performance report larger than 10 MB triggers the `timeout of 360000ms exceeded` error. This occurs because the `PARSE_FILE_TIMEOUT_SECONDS` parameter has not been adjusted to a value suitable for large files; the default timeout duration is insufficient to complete complex PDF parsing.
- Fields in individual DOCX-format performance self-assessment forms are empty after parsing. This happens because the default chunking rules do not adapt to the structured table typesetting of fiscal documents, and no separate delimiter logic is set for table content.
- Rectification report content spanning multiple pages is split into multiple independent chunks after chunking, causing performance rectification suggestions to be separated from corresponding issue records. This is because `chunkSplitter` only processes fixed delimiters, and does not perform semantic segmentation combined with document chapter headings.

## How to confirm the configuration is correct
- Upload a single performance evaluation report of around 100 MB, check whether the parsing status completes within the configured `PARSE_FILE_TIMEOUT_SECONDS` duration, with no timeout errors.
- Select a self-assessment form containing structured tables and large blocks of text, check whether the parsed chunks retain the association between tables and corresponding explanatory text, with no field splitting occurring.
- Verify that the total size of uploaded files complies with the `UPLOAD_FILE_MAX_SIZE` configuration, confirm that no files are blocked during batch uploads.
- Randomly select one chunk of content, confirm that it contains complete performance indicators and associated fund expenditure records, with no unnecessary truncation.

The values provided are common starting points and should be measured against the reader's own samples.
