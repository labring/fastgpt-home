# Ledger Summarization and Report Generation for Road Transport Business Licensing: Vector Models and Indexes

## What the data for this category looks like
Typical stakeholders include transportation bureau approval departments, road transport management agencies, and transport enterprises. Daily documents cover business license applications, vehicle technical files, driver qualification materials, safety production management systems, and road transport business licenses. Data sources include the road transport administration management system, the national road transport vehicle dynamic information public service platform, and the vehicle and practitioner database. The update frequency is daily. Data includes structured qualification fields and unstructured document content, and is directly tied to road transport business license eligibility and qualification renewal.

## Constraints Imposed on Vector Models and Indexes
Daily updated multi-source data requires indexes to support incremental synchronization and full re-embedding capabilities, to avoid repeated calculations of historical data. The mixed structure of multiple document types requires chunking strategies adapted to different text lengths, to ensure consistent vector representations for qualification fields and system documents. The strong tie between data and business licensing requires vector recall accuracy to match business review standards, preventing low-relevance content from interfering with ledger summarization. Additionally, differences in data formats across sources require a unified preprocessing process to support subsequent index construction, ensuring data consistency.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapt to the average length of road transport licensing documents, balancing semantic completeness and chunk granularity |
| Overlap Length | 100–150 characters | Avoid cutting key qualification information across chunks, ensuring cross-chunk semantic coherence |
| Similarity Threshold | 0.75–0.85 | Match the accuracy requirements of business reviews, filtering low-relevance vehicle or personnel data |
| Single Search Limit | Top 10 entries | Control the data source scope for ledger summarization, avoiding redundant information interfering with report generation |
| `defaultToken` | Calibrated based on actual testing | Adapt to token consumption of documents from different sources, avoiding exceeding model limits |
| `maxToken` | 4096 token | Align with the context window standards of mainstream large models, supporting complete ledger content splicing |

## Three Common Mistakes
- Phenomenon: After switching the knowledge base vector model, progress stalls. The interface displays a "not synchronized" status and cannot roll back to the original configuration. Cause: The full re-embedding operation was not executed. A vector space mismatch between the old and new models causes index conflicts, and unsaved configuration changes lead to rollback failure.
- Phenomenon: After configuring the Doubao indexing large model, interface tests return a "404 page not found" error. Cause: The API interface address was filled incorrectly, or the key permission was not activated, making normal calling of the embedding interface impossible.
- Phenomenon: The batch re-embedding task is interrupted midway. Logs show a token limit exceeded error. Cause: `defaultToken` was not adjusted for large-sized vehicle technical file documents, leading to token consumption exceeding the model upper limit and triggering the interruption.
