# Ledger Summary and Report Generation for Department Final Accounts and Financial Reports: Workflow Orchestration

## What This Category of Data Looks Like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Daily generated documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Data fields cover detailed revenue and expenditure subjects, budget execution difference items, asset and liability balances, summary data from subordinate units, and more. Units are mostly yuan or ten thousand yuan. Some fields must comply with unified fiscal coding rules.

## Constraints Imposed on Workflow Orchestration
The annual update frequency means the workflow does not need frequent triggering. It can be started on an annual cycle, and only runs after the end of the year.
Differences across multiple system data sources require the workflow to include cross-system data pull nodes. Unify data formats before performing summary operations.
The complex multi-document structure requires splitting reports, explanations, and other modules into separate components. Configure data extraction and verification rules for each module individually.
The requirement to summarize reports from subordinate units means the workflow must include hierarchical data traversal nodes. These nodes handle format alignment across different units.
Data errors can lead to returned final accounts or audit issues. Therefore, data verification and failure alert configurations must be added at key stages.
Workflows for this category focus on summarizing actual revenue and expenditure as well as asset and liability data. They do not need to cover configurations for the budget preparation stage, unlike budget preparation workflows.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Data Source Node | Connect four fiscal system interfaces | Match official source channels for data in this category |
| Scheduled Trigger Rule | Trigger once every 365 days | Align with the annual update frequency requirement |
| `variables` | Preset revenue and expenditure subject, unit hierarchy parameters | Reduce repeated configuration, adapt to fixed fields |
| Maximum Context | 8000 token | Accommodate complete data content for multiple final account statements |
| Single Pull Limit | Top 5000 entries | Control the scale of annual data pulls to avoid timeouts |
| `nodeId` | Bind subordinate unit data pull node ID | Implement process jumps for hierarchical report summary |
| Query Optimization | Optimize query words according to final account statement fields | Improve accuracy of multi-system data extraction |

## Three Common Misconfigurations
- Symptom: An error occurs when entering the edit interface after creating a workflow template, and a configuration missing prompt pops up. Cause: The `nodeId` for subordinate unit data pull is not bound, leading to missing necessary configurations in the process jump link for hierarchical report summary.
- Symptom: When using the question optimization node to process multi-system data, the extracted results do not match the expected fields. Cause: The functional boundaries between the question optimization node and the data source extraction node are confused, and the unified fiscal subject parameters preset via `variables` are not used to complete format alignment.
- Symptom: A "data verification failed" alert appears after the workflow runs, and the logs show that revenue and expenditure details do not match treasury data. Cause: The verification rules for treasury payment data are not configured.

## How to Confirm the Configuration Is Complete
- Verify that the data source node configuration has been connected to all required fiscal system interfaces, and that configuration items match the official system documentation.
- Verify that the preset values of the `variables` parameter include fixed fields such as revenue and expenditure subjects and unit hierarchies.
- Verify that the binding relationship of the `nodeId` matches the process jump logic for hierarchical report summary.
- Verify that data verification rules are configured for key stages such as account reconciliation and report consistency.
