# Ledger Aggregation and Report Generation for Department Final Accounts and Financial Reports: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system, with an annual update frequency. Daily produced documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Most document structures use fixed-format tabular fields, including unit identifiers, income and expenditure details, assets and liabilities items, budget execution difference explanations, and other content. Most fields are tied to legally required accounting units.

## What constraints these characteristics impose on the tool calling and plugins workflow
The annual update feature means tool calling does not need to be triggered frequently. A single call must integrate data from multiple systems across data sources, which places requirements on the cross-system connection stability of plugins. The fixed-format document structure requires tool calling to precisely match preset fields, to avoid extracting non-target content. Multiple system data sources require plugins to complete data verification and reconciliation, to ensure consistency between accounts and statements. Errors can lead to final account returns or audit issues, so tool calling must be configured with strict result verification and failure handling logic, and must clearly distinguish between actual income and expenditure data and budget data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or `["pull_budget_data", "pull_asset_data", "pull_payment_data", "generate_report"]` | Can adapt to flexible calling scenarios; specifying the mode improves the accuracy of large model calls to target plugins |
| `functionCall` | Strictly match preset function parameters | Ensures the fields of the generated final account report comply with legal document formats, avoiding non-standard content |
| Tool call timeout threshold | `600 seconds` | Pulling multiple types of final account data across systems requires a long synchronization time. 600 seconds covers most conventional scenarios, and can be adjusted based on actual testing |
| Tool call retry count | `2–3 times` | Addresses temporary network fluctuations that may occur during cross-system calls, reducing the failure rate of single calls |
| Plugin input parameter verification switch | Enabled | Filters invalid input parameters, ensuring that the final account data fields passed to plugins comply with legal requirements |

## Three common mistakes
- Phenomenon: MCP calls fail frequently, and logs show a `504 Gateway Timeout` status code. Cause: The tool call timeout threshold was not adjusted. The default short timeout cannot cover the full duration required to pull final account data across systems.
- Phenomenon: The HTTP response input parameter variable received by the plugin is empty, and the corresponding final account field is missing. Cause: The field mapping for the corresponding final account data was not bound in the plugin configuration, and the input parameter verification switch was not enabled.
- Phenomenon: The large model does not trigger tool calling, and the generated report only contains general descriptions without actual income and expenditure or asset data. Cause: `toolChoice` was not configured to the specified mode, and the large model did not explicitly call the corresponding data pulling plugin.

## How to confirm the configuration is correct
- Verify the configured MCP service address and final account system connection parameters against actual data sources via the plugin management page of FastGPT v4.17.0.
- Trigger a test call, review tool call logs, and confirm that cross-system data pull returns match preset final account document fields.
- Adjust `toolChoice` to the specified mode, and test whether preset plugins and report generation tools are triggered preferentially.
- Simulate an input parameter that does not comply with legal fields, check for input parameter verification interception, and confirm that the verification switch is active.
