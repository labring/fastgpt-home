# Ledger Aggregation and Report Generation for Department Final Accounts and Financial Reports: Database and Operations

## What data for this category looks like
Data for this category comes from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Core documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Fields include budget unit code, revenue and expenditure subject code, actual incurred amount, asset and liability balance, and others. The unit is mostly yuan. Some reports require aggregating subordinate unit data by administrative hierarchy.

## What constraints do these characteristics impose on database and operations workflows
The annual update feature requires the database to support batch historical data archiving and annual incremental synchronization, to prevent cross-year data confusion. Data from multiple systems needs unified field mapping rules, to avoid aggregation errors caused by differing field names across systems. The requirement to aggregate subordinate unit reports means the database must support hierarchical associated queries, and reserve sufficient storage capacity for annual full data imports. Field differences across different documents need structured classification at the database level, to avoid field mismatches during queries and reduce error rates for subsequent ledger aggregation and report generation.

## How to set configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://user:pass@host:5432/finance_db?sslmode=require` | Adapts to structured final account statement fields and supports complex hierarchical associated queries |
| `DB_MAX_LINK` | `20–30` | Meets concurrent connection requirements during annual full data imports and avoids connection exhaustion |
| `REDIS_URL` | `redis://:authpass@host:6379/0` | Caches annual fixed field mapping rules and hierarchical associated data to reduce repeated query overhead |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/finance_docs` | Stores unstructured final account explanation documents and supports flexible text retrieval and classification |

## Three common errors
- Phenomenon: Database connection errors, returning `connection refused` or `authentication failed`. Cause: Incorrect access address, port, or authentication credentials when configuring `PG_URL` or `MONGODB_URI`.
- Phenomenon: Empty fields in ledger aggregation results. Cause: Unified field mapping rules not configured in the database, leading to mismatched field names from multiple system sources.
- Phenomenon: Annual data query timeouts. Cause: `DB_MAX_LINK` set too low, unable to support concurrent query requests for full data.

## How to confirm configurations are correct
- Execute a field query for a single department final account statement, verify results match data exported from source systems, adjust field mapping rules until matching.
- Initiate a simulated annual full data import task, check database connection status, adjust connection configurations until no connection exhaustion errors occur.
- Retrieve aggregated subordinate unit report data, confirm hierarchical associated queries return results normally, verify ledger aggregation logic.
- Check database and cache service operation logs, confirm no abnormal records such as connection failures or authentication errors.
