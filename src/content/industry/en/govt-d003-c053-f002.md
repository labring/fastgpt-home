# Department Budget Preparation: Ledger Summary and Report Generation - Vector Models and Indexing

## What Data for This Category Looks Like
The data for this category primarily originates from the unified budget management system, department staff establishment system, prior-year final accounts, project repository, and Ministry of Finance budget preparation notices. Update frequency is annual. Commonly processed documents include department budget drafts, project application forms, performance target statements, personnel expense calculation forms, budget approvals, and similar materials. Most fields cover expense amounts, staff establishment counts, and project performance indicators. Units include ten thousand yuan, persons, percentage points, and others. Data structure varies slightly based on budget hierarchy and organization size.

## Constraints Imposed on Vector Models and Indexing
The annual centralized update requirement means indexes must support efficient incremental synchronization. This avoids full reindexing that uses excessive server resources. Mixed documents from multiple sources require indexes to support mixed parsing of structured tables and unstructured text. Associated strong numeric fields require vector models to align both semantic and numeric features. Field differences across organizations at different levels require indexes to support dynamic field mapping. Cross-data-source association needs for ledger summary require indexes to associate budget data from different systems during recall.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the paragraph structure of department budget documents, avoids splitting critical expense fields and project descriptions |
| Overlap Length | 100–150 characters | Preserves budget project association information across chunks, prevents loss of semantic association caused by chunk breaks |
| `defaultToken` | 8192 | Adapts to the context window of most general large models, carries full ledger data fragments after summarization |
| Similarity Threshold | 0.72–0.80, calibrated via actual testing | Distinguishes similarity between budget projects, avoids incorrectly associating similar expense entries from different organizations |
| Single Search Limit | Top 10 entries | Covers all budget application entries from subordinate organizations, meets the basic requirements for department-level summary |
| Maximum Context | 16000 characters | Carries budget document fragments from multiple sources, supports complete context requirements for report generation |

## Three Common Configuration Mistakes
- Scenario: When uploading documents to a newly created knowledge base in a locally deployed FastGPT v4.17.0, no image indexing model options are available. Cause: This feature is not integrated by default in the open-source version. Manual configuration of the corresponding plugin or commercial edition authorization is required.
- Scenario: The retrieval result page cannot directly adjust indexing parameters via the original edit button. Adjustments must be made in the knowledge base content management page. Cause: After interface interaction logic updates, the indexing debugging entry on the retrieval page has been moved to the knowledge base configuration page.
- Scenario: After batch uploading annual budget documents, indexed recalled project entries lack personnel expense data from subordinate organizations. Cause: Chunk length is set too short, which cuts the association fields between staff establishment and expense amount during splitting, resulting in failure to match complete entries during recall.

## How to Verify Proper Configuration
- Upload a single department budget draft document, check if indexed chunks retain complete project expense and performance target fields.
- Submit a retrieval request containing "subordinate organization public expenses", verify that the number of recalled results matches the configured single search limit.
- View the knowledge base indexing logs, confirm that annual update tasks only perform incremental synchronization and do not trigger full reindexing processes.
- Test cross-document associated retrieval, verify that budget data from different sources can be correctly recalled and associated.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
