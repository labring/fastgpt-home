# Ledger Consolidation and Report Generation for Department Budget Preparation: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
This category of data primarily comes from the unified budget management system, departmental staffing system, prior-year final accounts, project repository, and the annual budget preparation notice issued by the Ministry of Finance. The update frequency is annual. Commonly processed documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and similar items. Data fields cover staffing headcount, project expense amounts, performance target indicators, prior-year final account data, and other relevant content. Units involved include ten thousand yuan, person, number of projects, and similar units. A full update cycle is completed once per annual budget cycle.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
The annual update nature means a single task must handle full-cycle historical data. Context length must be limited to avoid interference from redundant information. Differentiated fields across multiple document types require multi-turn dialogue to gradually clarify the current document type, preventing confusion between personnel expense and project expenditure statistical standards. Data from multiple system sources requires multi-turn prompts to guide users to supplement field information for the corresponding system, ensuring the accuracy of ledger consolidation. Single task durations within the annual cycle are lengthy. Reasonable context retention rules must be configured to prevent data loss from interrupted dialogues.

## Configuration Settings
These configurations are based on FastGPT v4.17.0, adapted for the ledger consolidation and report generation scenario for department budget preparation:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Conversation History Retention Rounds | 3–5 previous turns | Department budget preparation tasks have long single cycles. Excessive historical rounds will consume context resources. Only core requirement confirmation and data explanation rounds need to be retained. |
| `chatId` Binding Rule | Bind to department budget fiscal year + unit code | Ensures that budget task contexts for the same fiscal year and unit are not confused, preventing cross-year and cross-unit data mixing. |
| `variables` Initialization | Preset budget fiscal year, unit hierarchy, data source type | Reduces the number of times basic information is repeatedly confirmed during multi-turn dialogue, improving ledger consolidation efficiency. |
| Single Request Context Length | 800–1200 characters | Matches the typical content length of a single page of department budget documents, preventing model processing timeouts from overly long content. |
| Prompt Template Updates | Adjust according to annual budget notices | Synchronize compliance check rules in prompts after the Ministry of Finance releases new preparation requirements each year. |
| `messages` Truncation Strategy | Only retain valid interaction rounds | Filter invalid test or duplicate dialogue content, optimizing the model's context processing efficiency. |

## Three Common Misconfigurations
- Symptom: When calling the API, logs show the token field value is `fastgpt`, and the model cannot be connected normally. Cause: The model call key parameter was not configured correctly, causing FastGPT to automatically fill in the default identifier.
- Symptom: When accessing the same `chatId` multiple times, the historical rounds of the first model call are not retained as configured. Cause: Context rules were not individually bound to each model node in the workflow, causing the context to be overwritten globally.
- Symptom: Fields for personnel expenses and project expenditures are mixed in the ledger consolidation results. Cause: The prompt did not clearly distinguish the statistical standards of different documents, and multi-turn dialogue did not guide the user to confirm the current document type.

## How to Verify Proper Configuration
- Initiate a test dialogue, enter the department budget fiscal year and unit hierarchy, check if `variables` automatically load preset parameters.
- Call the API with the specified `chatId`, check if the logs bind the unique identifier for the corresponding fiscal year and unit.
- Submit 3 consecutive requests with the same `chatId`, confirm that the conversation history retention rounds meet the configured requirements.
- Input a document fragment that mixes personnel expense and project expenditure content, check if the model guides the user to confirm the current document type.

The values provided are common starting points and should be measured against the reader's own samples.
