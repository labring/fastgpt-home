# Ledger Summary and Report Generation for Department Budget Preparation: Tool Calling and Plugins
Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category of Data Looks Like
Data for this category typically comes from the budget management integrated system, department staff establishment system, prior year final accounts, project library, and Ministry of Finance budget preparation notices. The update frequency follows an annual cycle.
Daily processed documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. Most documents are in structured table format.
Core fields include unit code, project details, number of staff establishment, expense calculation amount, and performance target indicators. Common units are ten thousand yuan, person, and number of projects.

## Constraints Imposed on Tool Calling and Plugins Workflow
Since data sources involve multiple internal fiscal systems, tool calling must adapt to interface formats and field mapping rules of different systems to avoid data parsing errors.
The annual update frequency means tool calling does not need frequent triggering, and can be fixed to run during the annual budget preparation cycle.
The structured document format requires tool calling to accurately extract corresponding fields, avoiding redundant data that interferes with ledger summary.
Budget preparation errors will lead to audit failure, so tool calling must be configured with failure retry and data verification mechanisms to ensure accuracy of returned data.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `required` | Force the model to call tools to obtain real-time budget data, do not rely on historical content from the built-in knowledge base |
| `functionCall` | Strict format validation | Ensure budget data fields returned by the plugin fully match the department ledger template, avoid format errors |
| Tool call timeout | 600 seconds | Cross internal fiscal system data retrieval has network delays, reserve sufficient response time |
| Maximum entries per plugin response | First 15 entries | Balance data completeness and context window usage, adapt to single-batch department budget data scale |
| Context window limit | 8000–12000 token | Adapt to the total scale of department budget data, avoid exceeding the model's context limit |
| Global variable binding | Bind current budget fiscal year | Automatically pass the preparation year parameter, adapt to the fixed business scenario of annual budget preparation |

## Three Common Mistakes
- Phenomenon: Tool calling does not retrieve target data from the budget management integrated system, only returns general knowledge base content. Cause: The budget system data source is not correctly bound to the tool calling configuration, resulting in the call scope being limited to the general knowledge base.
- Phenomenon: Irrelevant zero-value fields appear in post-call results, and the results differ from the model's original response. Cause: `functionCall` format validation is not enabled, and redundant fields returned by the plugin are incorrectly parsed and concatenated by the model.
- Phenomenon: The display name of a custom plugin differs between the system plugin list and the plugin management page. Cause: The internal identification name and page display name of the plugin are not correctly distinguished, leading to different name sources read by the two locations.

## How to Confirm Proper Configuration
- Trigger a test call, check the tool calling logs, confirm the `toolChoice` parameter is set to `required` and the called plugin is the preset budget data plugin.
- Submit a simulated department budget preparation request, check if the plugin returned fields include core budget fields such as number of staff establishment and project expense amount, and that the format matches the preset ledger template.
- Pass test global variables (such as budget fiscal year), confirm that the tool call automatically carries the variable without manual repeated input.
- Simulate a cross-system call timeout scenario, confirm that the preset failure retry mechanism is triggered, and no direct call error is returned.

The values provided are common starting points and should be measured against the reader's own samples.
