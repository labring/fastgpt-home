# Department Budget Preparation: Ledger Aggregation and Report Generation - Deployment and Upgrade

## What the Data for This Category Looks Like
The ledger and report data for department budget preparation typically comes from the unified budget management system, department staff establishment system, prior-year final accounts, project repository, and the annual budget preparation notice issued by the finance department. Daily output documents include department budget drafts, project application forms, performance target forms, staff expense calculation forms, budget approvals, and more. Fields cover staff establishment numbers, project expense amounts, performance indicators, approved amounts, etc. Units include people, ten thousand yuan, number of projects, etc. Data is updated annually, with full updates and validation completed only during each budget preparation cycle.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
The annual update feature requires that deployments be configured to support batch data reading and storage, to avoid overload from single requests. The need to connect multiple data sources requires configuring independent storage connections for different data sources, to prevent data mixing that would compromise aggregation accuracy. Diverse document structures require preset parsing rules adapted to different formats, to ensure that ledger fields can be correctly extracted from all types of budget documents. Additionally, the strict review requirements for budget data mean that permission control and data validation links must be configured during deployment. During upgrades, historical annual ledger data must be retained, to prevent loss or format corruption of historical data caused by version updates.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–15 connections | Adapt to the batch reading needs of annual budget data, avoid exhausting database connections |
| `MONGODB_URI` | Configure independent connection strings classified by data source | Differentiate storage of ledger data from the unified budget management system and staff establishment system, prevent data mixing |
| `PG_URL` | Configure the connection address of a local private database | Store sensitive budget approval data, comply with financial data security management requirements |
| `STORAGE_S3_ENDPOINT` | Connect to the internal object storage service address of the unit | Store original annual budget documents and parsed ledger fragments |
| `REDIS_URL` | 300–600 second expiration cache | Cache frequently queried annual budget indicator data, reduce the number of repeated calls to external systems |
| `ROOT_KEY` | Configure by unit permission hierarchy | Differentiate ledger access permissions for different budget units, enable fine-grained control |

## Three Common Configuration Mistakes
- Issue: After uploading a staff expense calculation form, the ledger aggregation result has empty fields. Cause: The `FILE_TOKEN_KEY` configuration was not set, resulting in insufficient file parsing permissions to read the original content of the attachment.
- Issue: After upgrading to FastGPT v4.17.0, openAPI module calls return authentication failures. Cause: v4.17.0 optimized the openAPI authentication logic, and the `ROOT_KEY` configuration parameters were not updated synchronously.
- Issue: The aggregation of budget data from subordinate departments takes longer than expected. Cause: No cache strategy was configured for `REDIS_URL`, causing each aggregation to repeatedly call the system interfaces of subordinate units, increasing request latency.

## How to Verify the Configuration Is Correct
- Run a database connection test to verify that the connection status of `MONGODB_URI` and `PG_URL` is normal, with no timeout or connection refused errors.
- Upload a test department budget draft document, check whether the parsed ledger fields match the content of the source document such as staff establishment numbers and project expense amounts.
- Call the openAPI interface, use the configured `ROOT_KEY` for authentication, and verify that the returned ledger aggregation data format meets expectations.
- View cache monitoring metrics, confirm that frequently queried budget indicator data has been properly cached, with no frequent records of external system calls.

The values given are common starting points and should be measured against the reader's own samples.
