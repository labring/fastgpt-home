# Ledger Summary and Report Generation for Flood Prevention, Disaster Mitigation and Emergency Duty: Vector Models and Indexes

## Data Structure for This Category
The daily documents for this category include duty logs, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, material allocation slips, and more. Data sources include meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Data is updated daily. Fields include rainfall and water level values, material quantities, number of evacuated people, and others, with corresponding units such as millimeters, cubic meters, pieces, people, etc. Some documents use structured table formatting, while others are unstructured text.

## Constraints on Vector Models and Indexing
FastGPT v4.17.0’s vector indexing functionality supports the configuration needs of this scenario. Multi-source real-time data requires the index to support incremental updates to align with the daily update rhythm, avoiding resource consumption from full index reconstruction. Mixed document formats of structured tables and unstructured text require a chunking strategy that accommodates both table field association and semantic integrity of long texts. The presence of specific unit fields requires retaining unit information during vector modeling to prevent matching deviations. The rapid response requirement of emergency scenarios requires limiting the number of single-batch returned results for index retrieval to reduce processing latency.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to mixed-format documents, balancing semantic completeness of long texts and reasonable chunk granularity |
| Overlap Length | 100–200 characters | Prevents semantic breaks across chunks, retains critical contextual associations |
| `defaultToken` | 4096 | Matches the default context window of most locally deployed embedding models |
| `maxToken` | 8192 | Supports complete indexing construction for long documents such as consultation minutes |
| Similarity Threshold | 0.75–0.85 | Filters irrelevant content, retains retrieval results strongly related to emergency scenarios |
| Single Search Limit | Top 5 entries | Adapts to the rapid response requirements of emergency scenarios, avoids processing delays from excessive results |

## Three Common Misconfigurations
- Index construction fails after deploying a local M3E model, with a model loading timeout prompt. The root cause is incorrect configuration of the local embedding model’s access port and container mapping rules in FastGPT.
- When reconfiguring the Qwen/Qwen3-Embedding-8B model, the original configuration is overwritten, and both indexing and reranking functions cannot be enabled simultaneously. The root cause is that FastGPT only allows one configuration per model name by default, and model aliases were not used to differentiate between different use cases.
- After importing an Excel-format material allocation slip, chunks contain redundant headers and cross-row data is incomplete. The root cause is failure to enable header association retention during chunking, and the default chunk granularity being too large to meet business requirements.

## How to Verify Proper Configuration
- Upload a single rapid disaster report document, check the semantic integrity in the chunk preview interface, and confirm that the chunk length falls within the preset range.
- Call the knowledge base search interface, input "today's rainfall", and verify that the number of returned results matches the single search limit setting.
- Attempt to add an embedding model with the same name, check if the interface prompts a duplicate configuration, and confirm that the model alias function is operational.
- Import a test Excel file, check whether chunks retain header associations and that data chunk granularity meets business expectations.

The values listed above are common starting points and should be evaluated against the reader’s own samples.
