# Ledger Aggregation and Report Generation for Flood Control, Disaster Prevention and Emergency Duty: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category originates from emergency management bureaus, water affairs bureaus, meteorological bureaus, sub-districts, towns, and emergency command centers. Daily documents include duty records, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources cover meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video monitoring. Updates occur daily. Document structures vary widely: single-page short early warning notices exist alongside dozens of pages of batch rapid disaster reports and consultation minutes. Fields include rainfall conditions, water levels, material quantities, and personnel transfer information. Some documents use uniformly formatted headers and footers.

## Constraints Imposed on Document Parsing and Chunking
Batch daily updated documents require the parsing workflow to support batch processing, to avoid excessive single-file parsing delays that impact ledger aggregation timelines. Structural differences across document types demand flexible chunking rules. Short notices must retain complete paragraphs, while long consultation minutes need to preserve chapter context. Business fields with units (such as water level in meters, material quantity in tons) require accurate extraction to prevent information loss from chunk truncation. Documents circulated across multiple departments have inconsistent formats; some use multi-column layouts, include embedded charts, or exist as scanned files. Custom parsing configurations are needed to adapt to these variations.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Flood control documents include short-field early warning notices and long-text consultation minutes. This range balances context completeness and retrieval accuracy |
| `chunkSplitter` | By title + paragraph | Most flood control documents have chapter titles. Splitting by title preserves the integrity of business context |
| `customPdfParse` | Enabled | Meets parsing needs for multi-column layouts, embedded charts, and scanned document formats common in flood control documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large rapid disaster report PDFs and batch log packages takes a long time; this duration covers most scenarios |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Batch log packages exported from emergency command platforms have large file sizes; this upper limit meets batch upload requirements |
| `chunkSettingMode` | Manual | Chunking rules need to be adjusted for different document types; manual mode allows flexible adaptation to business scenarios |

## Three Common Configuration Errors
- Symptom: After uploading a doc or docx document, RAG retrieval results only include the main body, with no chapter title information. Cause: The configuration to retain title context during chunking was not enabled, so chapter titles are not included in chunked content.
- Symptom: Calling the PDF parsing interface returns empty fields or parsing failures. Cause: The `customPdfParse` configuration is not enabled, so the system cannot adapt to multi-column layouts or embedded charts common in flood control documents.
- Symptom: Parsed result fields cannot be extracted when using a specific large language model. Cause: The `chunkSettingMode` is not configured to manual mode, so chunk parameters do not match the context window of the large language model.

## How to Verify Correct Configuration
- Upload a typical flood control consultation minute PDF, check if parsed chunked content includes chapter titles and main body paragraphs.
- Upload a rapid disaster report compressed package of approximately 100 MB, confirm that upload and parsing processes complete within 600 seconds.
- Test chunking effects for different document types (duty records, early warning notices), adjust `chunkSize` until chunked content covers complete business information units.
- View parsing logs in the FastGPT v4.17.0 backend, confirm that the `customPdfParse` configuration is enabled and no timeout errors occur.
