# Ledger Summary and Report Generation for Food Safety Supervision Sampling: Multi-turn Dialogue and Prompt Configuration
This document adapts to the multi-turn dialogue and prompt configuration of FastGPT v4.17.0, and provides specific guidance for ledger summary and report generation requirements in food safety supervision sampling scenarios.

## What the Data for This Use Case Looks Like
Data sources for this use case include food safety sampling monitoring systems, national market supervision administration sampling result query systems, testing institution LIMS systems, and food producer and operator ledgers. Data update frequency is monthly. Daily documents include sampling plans, sampling slips, test reports, non-compliant food verification and disposal reports, and risk control announcements. Data fields include sampling identifiers, test items, non-compliance determination results, disposal measures, and more. Units include batches, test item counts, detection values, and more.

## Constraints Imposed on Multi-turn Dialogue and Prompt Configuration
Monthly updated bulk data requires multi-turn dialogue to support loading documents in batches, to avoid single-context overflow. Multiple data sources require prompts to clearly distinguish field rules for different document types such as sampling plans, sampling slips, and test reports, to ensure field alignment during summary. Differences in ledger formats across different business entities require prompts to preset a unified output template. Strict compliance requirements for data association mandate forced verification of consistency between original data and generated reports during dialogue, to prevent incorrect associations. Additionally, adapt to context length limits of different invocation scenarios to ensure key sampling information is not truncated.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current sampling batch | Ensure multi-turn dialogue is associated with all documents of the same batch, to avoid data confusion |
| `messages` | Retain the most recent 15–20 conversation records | Focus on recent sampling-related interaction information, to avoid interference from historical redundant content on generation results |
| `variables` | Preset three types of variables: sampling number, test item, disposal measure | Unify field mapping rules for documents from different sources, to ensure format consistency during ledger summary |
| Maximum context length | 8000–12000 characters | Match the total character count of monthly bulk sampling-related documents, to prevent core sampling information from being truncated |
| Single reply token limit | 1200–1500 tokens | Match the typical output length of a single test report, to ensure complete presentation of test results |

## Three Common Misconfigurations
- Phenomenon: Empty responses occasionally appear after invoking the AI dialogue node, with no generated content. Cause: No context fallback logic is set. When bulk sampling documents exceed the context length configured by `messages`, the model outputs empty content.
- Phenomenon: Unclosed reference symbols appear at the end of generated reports, which are automatically corrected in subsequent interactions. Cause: The prompt does not clearly specify closing rules for output formats, and does not perform mandatory verification on reference fields of test reports.
- Phenomenon: The system prompts that files do not exist when attempting to call historical sampling documents older than 7 days. Cause: The file expiration time configuration is not adjusted. The default 7-day setting does not match the monthly data update rhythm, leading to early cleanup of historical data.

## How to Verify Proper Configuration
- Invoke the preset `variables` variables, check if sampling document fields from different sources can be automatically mapped, and verify field alignment effects.
- Upload multiple different types of sampling documents, verify that the maximum context length setting can fully load all document content without truncation.
- Simulate multiple multi-turn dialogue interactions, check if the number of historical records retained by `messages` meets expectations, with no redundant or missing interaction content.
- Adjust the file expiration time, verify that sampling documents exceeding the set duration can be invoked normally, matching the business update rhythm.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
