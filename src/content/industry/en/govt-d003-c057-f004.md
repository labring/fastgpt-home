# Ledger Summary and Report Generation for Food Safety Supervision Sampling: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include the food safety sampling monitoring system, the State Administration for Market Regulation sampling results query system, laboratory LIMS systems, and food producer and operator ledgers. The data update frequency is monthly. Core documents include sampling plans, sampling slips, inspection reports, non-compliant food verification and disposal reports, and risk control notices. Data fields include sampling number, inspection items, non-compliant items, disposal measures, and more. Common units are batches, copies, and test item counts. Single records are associated with multiple document types, requiring cross-system integration.

## What constraints these characteristics impose on workflow orchestration
The monthly update frequency requires workflows to support bulk monthly data processing to avoid resource waste from single triggers. Data from multiple source systems requires unified field mapping, otherwise document field mismatches will occur. Format differences across different documents require workflows to configure distinct nodes to adapt to different file types such as sampling slips and inspection reports. Core evidence comes from laboratory inspection reports, so an additional verification link must be configured to ensure data accuracy. The regular business scale of grassroots supervision offices requires workflows to adapt to small and medium-sized batch processing to avoid system overload.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Condition | Pass the monthly sampling batch list via `variables` | Adapt to monthly updated data sources, process sampling slips and inspection reports in bulk |
| Bulk Processing Limit | 500 entries | Match the regular batch scale of monthly sampling at grassroots supervision offices, avoid system overload |
| Timeout Setting | 1200 seconds | Adapt to the interface response duration of laboratory LIMS systems, comply with FastGPT v4.17.0 workflow node timeout rules |
| Variable Mapping Rule | Map fixed fields of sampling slips and inspection reports | Match the fixed structure of category documents, reduce field mismatch issues |
| `nodeId` Binding | Bind the tool node for verifying inspection reports | Ensure precise triggering of non-compliant item verification and disposal workflows |
| Retry Count | 3 times | Address network fluctuations or temporary system failures, ensure workflow stability |

## Three common errors
- Workflow runtime loop nodes only process some batches: The symptom is that only the last 6 sampling slips are processed, and the remaining batches have no response. The cause is that the complete monthly sampling batch list is not configured in `variables`, and only partial sampling slip IDs are passed.
- Tool calls work normally in debug mode but throw errors in run mode: The symptom is that the runtime returns an interface call failure status code, and logs show insufficient permissions or missing parameters. The cause is that the run mode is not bound to production environment LIMS system interface permissions, or production environment parameters in `variables` are not configured.
- Exported workflow conversation records only show the last 6 entries: The symptom is that the exported JSON or CSV file only retains recent interaction content, and early node data is missing. The cause is that full context export configuration is not enabled, and the default setting only retains recent interaction node data.

## How to confirm the configuration is correct
- Trigger the workflow by passing the preset monthly sampling batch `variables`, check if each node executes in the order of the list
- View logs after running the workflow, confirm that the field mapping of inspection reports matches the preset rules
- Simulate a non-compliant product scenario, check if the verification and disposal node triggers normally
- Export workflow conversation records, confirm that the content of all interaction nodes is fully saved

The values provided are common starting points and should be measured against the reader's own samples.
