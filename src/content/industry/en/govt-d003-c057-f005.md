# Food Safety Supervision Sampling Account Summary and Report Generation: Tool Calling and Plugins

## What this category's data looks like
Data sources for this category include food safety sampling monitoring systems, the national market supervision administration’s sampling results query system, testing institution LIMS systems, and internal accounts of food producers and operators. Data is updated monthly. Core business documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control notices. Data fields cover sampling identification, inspection indicators, non-conforming items, disposal measures, and more. Units include batches, concentration units, and others. The text volume of full monthly accounts changes with the scope of regulatory coverage.

## What constraints do these characteristics impose on the "tool calling and plugins" workflow
Multi-source data docking requires tool calling to support connections to at least three types of external system interfaces. Unified cross-data source calling rules must be configured.
The monthly update rhythm requires tool calling to adapt to scheduled triggering and incremental synchronization logic. This avoids repeated processing of historical data.
Diverse document types and high field complexity require tool calling to support structured extraction of exclusive fields for different documents. General templates cannot fully cover all scenarios.
Strict regulatory requirements for non-conforming disposal require tool calling to configure failure retry and exception verification mechanisms. These mechanisms ensure the accuracy of accounts and reports.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically matches the tool calling type for sampling-related documents, adapting to multiple document structures |
| `functionCall` | `enabled` | Supports structured extraction of core fields from sampling slips and inspection reports to generate standardized accounts |
| Single tool call timeout | `300–600 seconds` | Matches the complex calculation and data pulling duration of inspection report review and account summary |
| Tool call retry count | `2–3 times` | Addresses temporary fluctuations in data source interfaces, reducing the probability of call failures |
| Context window upper limit | `8000–12000 token` | Accommodates the text content of full monthly sampling accounts, avoiding truncation of key information |

## Three Common Misconfigurations
- Phenomenon: After streaming output via the conversation API, built-in links only cover the current page and cannot jump to new pages. Cause: The jump trigger logic for tool call return results is not configured, and only the default streaming output rendering rules are used.
- Phenomenon: In version v4.8.10, conversation log details do not match actual answer content, and log content repeats after multiple sessions. Cause: The context cache for tool calls is not refreshed at the document level of monthly sampling accounts, and historical session cache data is reused.
- Phenomenon: The streaming output return interval is fixed at 4 seconds and cannot be adjusted to 1 or 2 seconds. Cause: The streaming output interval configuration item is not enabled, and the platform's default return interval parameter is used.

## How to Confirm the Configuration is Complete
- Log in to the FastGPT v4.17.0 backend management interface, enter the plugin configuration page for the corresponding scenario, and confirm that `toolChoice` is set to `auto` and `functionCall` is enabled.
- Initiate a simulated monthly sampling account summary request, and check whether the structured data returned by the tool call includes core fields such as sampling slip number, inspection items, and non-conforming items.
- Test the streaming output function, adjust the return interval parameter, and verify that the output speed can be modified as required.
- Initiate multiple rounds of conversations, view the conversation log details, and confirm that the log content of each session matches the actual answer content.
