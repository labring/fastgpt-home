# Survey and Design Ledger Summary and Report Generation: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Data primarily comes from on-site survey original records, geotechnical test reports, construction drawing design documents, project review ledgers, and similar sources. Update rhythm follows project phases: one update during the preliminary design phase, and a second update upon completion of the construction drawing design phase. Each individual document includes two parts: structured fields and attachments. Structured fields include project number, survey point coordinates, geotechnical mechanical parameters, design load values, and more, using engineering-specific units such as meters, megapascals, kilonewtons. Attachments are mostly CAD drawings or formal reports in PDF format.

## What Constraints Do These Characteristics Impose on HTTP Interfaces and External Systems
Structured fields for survey and design ledgers and reports include engineering-specific units. HTTP interface request parameters must exactly match field names and unit formats to avoid parsing errors. Most attachments are in CAD or PDF formats, so interfaces must support binary stream transmission and large file chunk processing. Data updates adjust dynamically with project phases, so interfaces must support pulling the latest version of data using the project's unique identifier to avoid returning outdated content. Individual documents are lengthy, so the number of items returned in a single interface request must be limited to prevent timeouts or excessive bandwidth consumption.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer internally deployed large model API key` | Adapts to identity verification in internal network environments, prevents `unAuthApiKey` errors |
| `variables` | `Map the structured fields of survey and design ledgers, including project number, geotechnical parameters, etc., retain engineering-specific units` | Accurately transmits business data to avoid field parsing errors |
| `responseData` | `Only return structured fields and attachment metadata, pull large files via separate interfaces` | Reduces bandwidth usage for single interface transfers to avoid timeouts |
| Request timeout | 600 seconds | Adapts to the long processing requirements of survey and design documents |
| Large file transfer mode | Chunked transfer, 800–1200 kilobytes per chunk | Adapts to the size characteristics of CAD and PDF format attachments |
| API call mode | stream mode | Adapts to large model call requirements that only support stream mode |

## Three Common Mistakes
- Symptom: Returns `code:514` with status text `unAuthApiKey`. Cause: The `Authorization` parameter is not configured correctly, or the key does not match the deployment environment.
- Symptom: Format errors occur when calling the large model, and reports cannot be generated normally. Cause: Stream mode is not enabled, and a large model that only supports stream mode is used.
- Symptom: The interface returns a 304 status code, and the latest ledger data is not obtained. Cause: The interface cache configuration is not disabled, or the request does not carry the latest project version identifier.

## How to Confirm Proper Configuration
- Call the test interface, check whether the `Authorization` parameter is correctly carried, and the returned identity verification result is passed.
- Initiate a request containing survey and design-specific fields, check whether the fields returned in `responseData` match the preset ledger structure.
- Trigger a large model call, confirm that the returned content is streaming output, or matches the return format of large models that only support stream mode.
- Upload a large-volume CAD attachment, check whether the interface can perform normal chunked transfer and complete parsing.

The values provided here are common starting points and should be evaluated against the reader's own samples.
