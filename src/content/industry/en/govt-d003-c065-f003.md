# Survey and Design: Account Summary and Report Generation, Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Survey and design data originates from full-project-cycle survey reports, construction drawing design documents, site reconnaissance records, construction drawing review opinions, and project progress account books. Data sources cover all stages from project approval to completion acceptance. Updates align with project submission review milestones, with each update covering all documents and account entries for the current batch of submissions. Supported document formats include PDF drawings and reports, Excel progress account books, and Word rectification notes. Fields include project unique ID, survey point coordinates, structural design parameters, review batch numbers, review status, and completion deadlines. Supported units include engineering measurement standards such as meters, kilonewtons, and square meters.

## Constraints for Multi-turn Dialogue and Prompt Engineering
The mixed-format documents and multi-field account books used in survey and design work require multi-turn dialogue to first complete context anchoring for the current project. This prevents cross-project data mixing. Parsing results vary significantly across different document formats, so prompts must explicitly prioritize extraction of structured fields from Excel account books to ensure data accuracy. The project milestone-based update rhythm requires the dialogue flow to actively ask about the current review batch being processed. This ensures the latest version of account book data is used. Multi-dimensional engineering fields require clear extraction range definitions in prompts, to prevent generated results from including irrelevant non-engineering information.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Max Context | 12000–15000 prior characters | Covers account book and report content for a single project’s full batch of submissions |
| Single Dialogue Return Limit | Top 8 structured entries | Prevents excessive returned content from exceeding processing limits |
| Dialogue Timeout Threshold | 60 seconds | Accommodates time spent parsing multi-format files and summarizing data |
| Question Optimization | Enabled | Automatically corrects vague engineering terminology |
| `variables` Binding | Bind project unique ID and current review batch | Accurately anchor the survey and design project data currently being processed |
| `messages` Format | Array sorted by role and time | Ensures multi-turn dialogue context order aligns with project progression |

## Three Common Mistakes to Avoid
- Returned dialogue content includes unescaped line breaks, leading to JSON parameter request failures. This occurs when text generated during dialogue is not escaped, and the JSON format requirements of the `messages` parameter are not followed.
- An `unAuthChat` error is returned when calling the dialogue interface. This happens when project-specific access permissions are not configured correctly, or the API key is not bound to the resource scope of the current survey and design project.
- An error occurs after uploading survey drawings or progress account book files, while text input dialogue functions normally. This is due to failure to adapt to PDF and Excel file parsing rules, or file size exceeding the system’s allowed upload threshold.

## How to Verify Proper Configuration
- Initiate a test dialogue that includes the project unique ID, and check if returned results only include account book fields and design parameters for the current project.
- Construct a test input containing line breaks, and verify that returned dialogue content can be properly converted to JSON format compliant with the `messages` parameter requirements.
- Call the interface with a valid API key, and confirm that no `unAuthChat` permission-related errors are returned.
- Upload a single survey drawing and Excel-format progress account book, and verify that the file upload and parsing process does not produce errors.

The values provided here are common starting points, and should be evaluated against your own specific samples.
