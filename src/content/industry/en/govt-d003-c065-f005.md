# Survey and Design: Ledger Summary and Report Generation - Tool Calling and Plugins

## What the data for this category looks like
Survey and design ledger data mainly comes from on-site survey records, geotechnical investigation reports, construction drawing design documents, submission and approval documents, and similar sources. Data update rhythm follows project milestones: new ledger entries are generated after completing a survey point verification or drawing version update. A single ledger document includes fixed fields such as project number, survey point coordinates, geotechnical bearing capacity characteristic value (unit: kPa), design load value, drawing version number, and submission date. It also associates attached files including DWG-format construction drawings and PDF-format review opinions. A single batch of ledgers can contain tens to hundreds of point records.

## Constraints imposed on tool calling and plugins
Survey and design ledgers contain professional geotechnical parameters and drawing attachments. Tool calling must support parsing DWG and PDF formats, and verify professional units and value ranges of parameters to prevent erroneous data from entering reports. Ledger data is updated irregularly along with project milestones, so tool calling must support incremental synchronization and batch processing, with the number of entries processed per run matching project scale. For some large-scale survey projects, drawing parsing takes a long time, so tool calling must configure a reasonable timeout threshold to avoid task interruption. Summary of multi-point ledgers requires circular processing of single records, so tool calling must support array-type input parameter binding to ensure correct processing of ledger data for each point, and must follow FastGPT v4.17.0 plugin configuration specifications.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `auto` | Automatically matches multiple types of tools including ledger parsing, parameter verification, and report generation, adapting to the calling needs of multiple survey and design links |
| Maximum number of single tool calls | First 10 entries | Avoids timeouts caused by processing too many point data in a single run, aligning with the reasonable scale of single-batch processing for survey and design ledgers |
| File parsing formats | Only enable DWG and PDF | Filters out file formats unrelated to survey and design, reducing unnecessary parsing overhead |
| Parameter verification switch | Enabled | Verifies professional units and value ranges of geotechnical parameters and load values, ensuring the professionalism of report data |
| `functionCall` timeout setting | 600 seconds | Adapts to the time required for drawing parsing in large-scale survey projects, avoiding task interruption mid-process |
| Batch task processing mode | Asynchronous trigger | Supports parallel processing of multiple batches of ledger data, improving calling efficiency |

## Three common mistakes
- Custom plugins added to the workflow do not display input and output parameters. The cause is failure to declare the types and field names of input and output parameters in plugin configuration, and failure to match the plugin registration requirements of FastGPT v4.17.0.
- An error occurs when parsing survey drawing files uploaded via chat. The cause is failure to configure a dedicated DWG/PDF parsing plugin for survey and design, or the uploaded file size exceeds the 1000 MB limit.
- The chat interface call responds slowly. The cause is failure to limit the number of ledger entries per tool call, or failure to enable asynchronous processing mode for batch tasks.

## How to confirm configuration is complete
- Upload a DWG-format survey point ledger file, verify whether the extracted fields after parsing include core content such as project number and geotechnical bearing capacity characteristic value.
- Add a custom plugin to the workflow, confirm that the configured field names and types are displayed in the input and output parameter section.
- Initiate a test call containing 10 ledger entries, verify that the response duration meets expectations.
- Review the tool call logs, confirm that no error messages such as parameter verification failure or file parsing error appear.
