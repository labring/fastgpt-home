# Ledger Summary and Report Generation for Advanced Chemical Materials: Tool Calling and Plugins

## What the Data for This Category Looks Like
The ledger data for advanced chemical materials mainly comes from DCS system logs from production workshops, batch quality inspection reports, raw material purchase and warehousing documents, and downstream supply and delivery records. The data update rhythm varies by type: production ledgers are synchronized daily, batch quality inspection reports are generated with each production batch, and purchase and supply records are updated when transactions are completed. A single ledger document includes fields such as batch number, material grade, apparent density, tensile strength, total batch output, warehousing time, and supplier’s unified social credit code. Units include MPa, g/cm³, tons, days, and others.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Workflow
The multi-source and heterogeneous characteristics of advanced chemical material ledgers require tool calling to connect to three types of data sources at the same time: production, quality inspection, and procurement. Independent field mapping rules must be configured for different data sources. The batch number is the core associated field, so this parameter must be carried during tool calling to associate data; otherwise, cross-batch data confusion will occur. The existence of multi-unit fields requires plugins to have built-in unit conversion logic to avoid summary result deviations caused by inconsistent units. In addition, unstructured fragments from batch quality inspection reports must first undergo structured extraction via tool calling before entering the summary stage.

## Three Common Misconfigurations
- Symptom: The tool calling module outputs both AI reply text and a lower-level tool calling task, making it impossible to distinguish execution boundaries. Cause: The `toolChoice` parameter is not set correctly, causing the system to trigger both direct reply and tool calling processes at the same time.
- Symptom: When calling a database plugin to pull advanced chemical material ledger data, Chinese fields display garbled characters. Cause: The database connection configuration does not specify the character set as utf8mb4, leading to failed Chinese encoding parsing.
- Symptom: The charts in the ledger report generated by the basic chart plugin have no data or abnormal formatting. Cause: Correct field mapping rules are not configured, and numerical fields such as tensile strength and batch output in the ledger are not associated with the data source of the chart plugin.

## How to Confirm the Configuration Is Correct
- Run a single ledger summary test, check the tool calling logs, and confirm that the number of triggered tool calls matches the preset rules.
- Pull ledger data that includes Chinese supplier information, and confirm that the Chinese content returned by the database plugin has no garbled characters.
- Configure the basic chart plugin and bind the numerical and classification fields in the ledger, then check whether the chart generates corresponding displays that meet business requirements.
- Verify the field units returned by the tool calling, and confirm that they have been uniformly converted to the preset standard units.
