# Fertilizer and Pesticide Ledger Summary and Report Generation: Workflow Orchestration

## What the data for this category looks like
Ledger data for fertilizers and pesticides comes primarily from agricultural input inventory and sales systems, agricultural technology promotion filing platforms, field operation records, and pesticide registration databases. Two update cycles apply to this data: inventory and sales data updates in real time alongside daily transactions, while filing data synchronizes on a quarterly basis. A single ledger document includes fields including batch number, manufacturer, active ingredient content, purchase quantity, shipment quantity, inventory, used plots and corresponding area. Supported units include tons, kilograms, milliliters, hectares, and others.

## What constraints these characteristics impose on workflow orchestration
Scattered storage across multiple data sources requires workflows to configure multiple database connection nodes to connect to different systems. Use `variables` to uniformly manage cross-node field mapping rules. Data sources with different update cycles need distinct trigger intervals. Set the trigger interval for inventory and sales data within `1 day`, and set the trigger interval for filing data to `7 days`. The variety of fields and units requires workflows to include a data cleaning node. This node performs unit conversion and format validation on content and quantity fields from different sources, to prevent statistical errors during subsequent summarization.

## How to set configurations
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Map core ledger fields | Uniformly manage cross-node data such as batch numbers and active ingredients |
| Database connection timeout | 600 seconds | Adapt to latency characteristics when pulling multi-source data |
| Trigger node | Bind `nodeId` to data update events | Precisely control workflow startup timing |
| Context reuse toggle | Enabled | Retain summary parameter configurations from historical conversations |
| Error retry count | 3 times | Address temporary database connection fluctuations |

## Three common configuration errors
- Global variables fail to take effect after workflow runs. The symptom is empty single-select variable fields. This occurs when values in `variables` are not correctly bound to the option mapping of single-select nodes.
- Database connection nodes report insufficient permission errors. The symptom is content related to Access denied in returned messages. This occurs when the correct access account and permission scope for the corresponding data source are not configured.
- Historical context cannot be reused after a workflow calls an API. The symptom is previously saved ledger summary parameters being lost on each call. This occurs when the context reuse toggle is not enabled, or the context saving period is not correctly set.

## How to verify a correct configuration
- Trigger a test workflow run, and verify that pulled data source fields match the preset `variables` mapping.
- Simulate a database connection exception scenario, and check if the preset error retry mechanism activates.
- Save the workflow configuration and reload it, then confirm that the context reuse toggle status is retained.
- View workflow run logs, and confirm that the trigger condition matches the preset `nodeId` bound event.
