# Fertilizer and Pesticide Ledger Summary and Report Generation: Tool Calling and Plugins

## What the Data for This Category Looks Like
Ledger data for fertilizers and pesticides comes from three primary sources: inventory and sales systems of agricultural materials operators, pesticide and fertilizer registration databases of agricultural and rural affairs departments, and farming record systems of individual growers. Update frequencies differ across sources: inventory and sales data updates in real time with daily transactions, registration data syncs once per quarter, and field farming records update immediately after each fertilization or pesticide application. Individual ledger entries include fields such as product common name, production license number, purchase batch number, purchase quantity, sales date, target plot number, and application amount. Units for quantity and application amount include tons, kilograms, grams per mu, and others. Summary reports aggregate full-cycle batch, flow, and total application information on a monthly or quarterly basis. The overall structure of these reports must comply with specifications set by agricultural regulatory authorities.

## Constraints Imposed on Tool Calling and Plugins
Decentralized data sources and varying update frequencies require tool calling to adapt to authentication rules and update frequencies of multiple data sources. This prevents repeated pulling of outdated registration data or missing real-time inventory and sales information. Diverse field units require unified conversion during the tool calling stage. Without this, summary reports will display inconsistent unit formatting. Ledger data must meet regulatory compliance standards. Fields returned by tools must include all required items specified by regulators. Otherwise, generated reports will fail to meet compliance requirements. Structured ledger summarization also relies on standardized formats returned by tool calls. If the field order or naming from a plugin does not match the preset template, subsequent automatic summarization and report generation will be directly impacted.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic matching of tool functions suitable for ledger summarization, no manual specification of call targets required |
| `functionCall` | `enabled` | Enables structured function calling to ensure returned ledger data conforms to preset field formats, facilitating subsequent automatic summarization |
| Plugin call timeout | `300 seconds` | Single-batch data pulled for fertilizer and pesticide ledgers is moderate in volume; 300 seconds accommodates network delays when pulling data from multiple sources |
| Field mapping rules | Map according to agricultural materials regulatory standards | Ensures generated reports include required fields specified by agricultural and rural affairs departments, meeting compliance requirements |
| Error retry count | `2 times` | Avoids call failures caused by single network fluctuations or temporary interface jitter, improving overall task success rate |

## Three Common Misconfigurations
- Setting `toolChoice` or `functionCall` to `false` when initiating a tool call. This causes the plugin call to be unresponsive and returns empty ledger data.
- Failing to configure domestic network adaptation plugins, resulting in timeout errors when calling tools for overseas data sources. This prevents pulling of required registration data.
- Not configuring field mapping rules, leading to inconsistent field naming between data returned by tools and preset ledger templates. This causes missing fields or inconsistent naming in summarized reports.

## How to Verify Proper Configuration
- Initiate a simulated ledger summarization request. Check whether structured data returned by tool calls includes preset required fields such as production license number and application amount.
- View plugin call logs in FastGPT v4.17.0. Confirm that the `toolChoice` and `functionCall` parameters have taken effect as configured.
- Simulate a call to a domestic agricultural materials data source plugin. Verify that data pulling and field conversion work normally, with no inconsistent units or missing fields.
- Generate a test report. Cross-check the correspondence between fields in the report and actual ledger data, and confirm that the summarization logic is correct.
