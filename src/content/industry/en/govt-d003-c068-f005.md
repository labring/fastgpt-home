# Ledger Summary and Report Generation for Pharmaceutical Distribution: Tool Calling and Plugins

This page provides tool calling and plugin configuration references for FastGPT v4.17.0, tailored to the ledger summary and report generation scenarios in the pharmaceutical distribution sector.

## What the data for this category looks like
Pharmaceutical distribution ledger data primarily comes from internal enterprise ERP inventory systems, GSP compliance regulatory ledgers, upstream supplier delivery receipts, and downstream terminal restock records.
Data update cadence follows these rules: inbound and outbound details are synced in real time, compliance maintenance records are updated daily, and monthly operational summary reports are generated per natural month.
A single ledger document includes fields such as generic drug name, approval number, batch number, inbound quantity, outbound quantity, inventory balance, maintenance record number, and cold chain transport temperature. Units include boxes, cases, pieces, milliliters, and degrees Celsius. Some fields must comply with GSP regulatory formatting requirements.

## What constraints these characteristics impose on tool calling and plugin workflows
Multi-field compliance requirements for pharmaceutical distribution ledgers mean tool calls must accurately match GSP mandatory verification fields, and skip no compliance check steps.
Real-time updated inventory details require plugin-called APIs to adapt to high-frequency pull requests, preventing data lag from overly long call intervals.
The coexistence of multiple units in fields requires plugins to have built-in unit conversion logic to ensure consistent metrics during summarization.
The numerical verification requirement for cold chain temperature records requires tool calls to include temperature threshold checks, ensuring data complies with pharmaceutical storage standards.
Dispersed multiple data sources require plugins to support batch pulling data from different systems and completing field alignment.
Using the `toolChoice` parameter supports automatic matching of multiple data source types, improving calling efficiency.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic tool matching for multiple data source types in pharmaceutical distribution ledgers, covering scenarios such as inventory and compliance records |
| `functionCall` | `{"name":"gsp_field_check","parameters":{"required_fields":["approval document number","maintenance record number"]}}` | Precise function call for GSP compliance fields in pharmaceutical distribution, ensuring ledger verification covers mandatory regulatory items |
| Data source pull interval | 300 seconds | Matches the real-time update cadence of pharmaceutical distribution inventory data, avoiding pulling expired data |
| Unit conversion switch | Enabled | Adapts to multi-unit fields such as boxes, cases, and pieces in pharmaceutical circulation, unifying summarization metrics |
| Timeout threshold | 600 seconds | Adapts to the time required for batch pulling of multiple data sources, preventing call failures due to large data volumes |
| Compliance check trigger timing | Before ledger generation | Ensures summarized reports comply with GSP regulatory requirements |

## Three common errors
- Database query plugins return empty results or the error "field mismatch". Cause: Failure to adapt to special fields of pharmaceutical distribution ledgers such as approval number and cold chain temperature record, and the plugin's preset fields do not match the actual data source structure.
- No return data when using a document parsing tool with a custom URL. Cause: Failure to specify document parsing rules for pharmaceutical distribution ledgers in plugin configuration, such as format verification for GSP numbers and extraction logic for multi-unit fields, leading to parsing failure and no output.
- Cross-domain errors occur when calling API services. Cause: Failure to add cross-domain domain name whitelists allowed by pharmaceutical distribution systems in plugin configuration, causing the server to block cross-domain requests.

## How to confirm configuration is correct
- Initiate a simulated tool call, check if the returned results include core fields of pharmaceutical distribution ledgers such as approval number and inventory balance.
- Trigger the compliance check step, confirm that the plugin intercepts data with fields that do not comply with GSP formatting requirements.
- View workflow logs, confirm that the tool call timeout time matches the actual time required for current data source pulling.
- Generate a test report, check if multi-unit fields have completed unified conversion, such as converting cases to boxes.
