# Hazardous Chemical Storage and Transportation Ledger Summary and Report Generation: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Hazardous chemical storage and transportation ledger data comes from tank farm DCS monitoring systems, inventory management modules, transportation GPS terminals, and safety inspection forms. Data update frequencies are divided into real-time (inbound and outbound operations, tank level changes), daily (shift inspection records), and shift-level (transportation transfer documents). A single ledger document includes fields such as general hazardous chemical name, batch number, storage location, inbound and outbound time, circulation quantity (unit: ton or cubic meter), operator identifier, and abnormal alarm tag. The document structure mainly mixes structured tables and chronological logs.

## What Constraints These Data Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
The multi-turn dialogue and prompt engineering link for hazardous chemical storage and transportation is constrained by data characteristics. First, real-time and shift-level updated data requires the dialogue context to quickly load the latest fields to avoid returning expired circulation information. Second, multiple exclusive fields including hazardous chemical names, batches, quantity units, etc., requires the prompt to clearly specify field extraction and verification rules to avoid mixing circulation data from different batches. Finally, the mixed document structure of structured ledgers and chronological inspection logs requires multi-turn dialogue to associate cross-stage records of the same batch to ensure logical consistency during summarization.

## Three Common Configuration Errors
- Calling the dialogue log interface returns empty fields or only includes fragments of recent interactions. Cause: Full record pull configuration permissions are not enabled, and only partial historical content of the current session is pulled.
- Setting the streaming output interval to a fixed 4 seconds, unable to adjust to the preset 1–2 second range. Cause: The streaming output interval parameter is not configured, and the system default return interval is used.
- After splicing the output results of two AI dialogues, issues such as mixed hazardous chemical batches or inconsistent field units occur. Cause: Output data from different sessions is not isolated via `chatId`, and direct splicing leads to context crossover.
