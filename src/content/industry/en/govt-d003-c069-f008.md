# Hazardous Chemicals Storage and Transportation Ledger Summary and Report Generation: Document Parsing and Chunking

## Data Profile for This Category
The ledger data for hazardous chemicals storage and transportation mainly comes from daily inbound and outbound records, tank area inspection logs, equipment maintenance reports, and monthly/annual summary reports. The update frequency aligns with operation frequency: new records are generated after each individual operation, and monthly summaries are updated on a natural monthly cycle. Common document formats are Excel and Word, with some archived files in PDF format. Core fields include general hazardous chemical name, CAS registration number, storage location number, actual inventory (unit: kilogram, cubic meter), transport vehicle license plate, inspection validity period, and emergency response contact person. Some documents also include tank area layout diagrams or safety warning signs.

## Constraints for Document Parsing and Chunking
Fields in hazardous chemical ledgers have strict corresponding relationships. When splitting content, avoid splitting records of the same batch of hazardous chemicals into different chunks. Doing so will cause data association failures during subsequent summary processes. Mixed-format documents (tables, text, images) require the parsing module to extract both structured table data and unstructured explanatory content. Non-standard format images (such as tank area diagrams exported from CAD) increase parsing difficulty. Some fields are optional, and fields with inconsistent typesetting are easily missed. Frequently updated documents require the parsing process to have stable batch processing capabilities to avoid task interruptions caused by single parsing timeouts. All configurations below are formulated based on FastGPT v4.17.0.

## Recommended Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | A complete single record in a hazardous chemical ledger contains 5-8 core fields. This range ensures that a single chunk contains a complete single-batch operation record and avoids field splitting |
| `chunkSplitter` | Split by table + paragraph | Ledger tables carry structured data, while paragraphs carry supplementary explanations. Following this splitting rule preserves the association between fields |
| `customPdfParse` | Enabled | PDFs of hazardous chemical ledgers often contain formatted tables and custom typesetting. Custom parsing can accurately extract key fields such as CAS numbers and inventory |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Monthly summary ledgers contain multiple sub-tables and historical data, resulting in long parsing times. This duration covers the parsing needs of most large documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Annual storage and transportation ledger files are large in size. This setting allows uploading complete archived files |

## Three Common Mistakes
- Phenomenon: After uploading a docx file containing a tank area layout diagram, the parsing returns an `Invalid image file` error. Cause: Most images in hazardous chemical ledgers are in non-standard formats (such as non-standard CAD exported images), and the default image parsing module cannot recognize such files.
- Phenomenon: Only part of the data is captured in the database table, and the remaining fields are empty. Cause: Some optional fields in the ledger (such as emergency contact phone number) are not typeset in a unified format, and the complete data of the corresponding row is not associated during chunking.
- Phenomenon: The Markdown table output by the model is truncated, with `...[hide X char]` displayed at the end. Cause: The `chunkSize` setting is too small, which splits complete table rows into multiple chunks, preventing the model from restoring the complete content during stitching.

## How to Confirm Correct Configuration
- Upload a single standard hazardous chemical inbound and outbound ledger docx file, and check whether the core fields are fully extracted in the parsing results, with no field misalignment or missing fields.
- Upload a ledger PDF containing non-standard format images, and confirm that there are no `Invalid image file` related errors in the parsing log.
- Upload a monthly summary ledger of around 100 MB, and confirm that the parsing task is completed within the preset duration, with no timeout interruption prompt.
- Extract the content fragments after chunking, and verify that no cross-batch hazardous chemical records appear in a single chunk, and the field association relationship is complete.
