# Hazardous Chemical Storage and Transportation Ledger Summary and Report Generation: Knowledge Base Retrieval and Recall

## What this category’s data looks like
Hazardous chemical storage and transportation ledger data comes from on-site storage and transportation inspection records, inbound and outbound documents, and CSV files exported from tank monitoring systems. The update frequency is per shift or daily. The document structure is a structured CSV format with fixed headers. Fields include hazardous chemical name, specification and model, storage location, inbound quantity (tons), outbound quantity (tons), inspection time, temperature (℃), pressure (MPa), handler, and others. Units are uniform and fixed. The length of a single record is moderate, but the total data volume grows with the scale of storage and transportation operations.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The fixed-header CSV structure requires matching field names and units during retrieval, and cannot rely on generalized semantic matching. The high-frequency update rhythm requires configuring scheduled synchronization tasks for the knowledge base to ensure retrieved data is the latest ledger content. Fixed units and numeric types require filtering results with non-matching units during retrieval to avoid invalid data being included. Widely used Chinese field names increase the risk of encoding parsing errors, so ensure the import format meets standard requirements.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precise field and numeric requirements of hazardous chemical ledgers, filters low-correlation results |
| `limit` | Top 10 entries | Retrieves an appropriate number of ledger entries per request, meets the batch processing needs of summary and report generation |
| `searchMode` | Exact match | Adapts to the fixed fields and units of structured ledgers, avoids incorrect results from semantically vague matching |
| `usingReRank` | Enabled | Performs secondary sorting of retrieved results by relevance, optimizes the accuracy of ledger field matching |
| `datasetSearchUsingExtensionQuery` | Disabled | The data structure of hazardous chemical ledgers is fixed; expanding query terms can easily lead to matching non-target fields |
| `collectionIds` | `["65a1b2c3d4e5f67890abcdef"]` | Restricts the retrieval scope to the exclusive ledger collection for hazardous chemical storage and transportation, avoids mixing data from other categories |

## Three common errors
- Garbled Chinese characters appear in fields after importing a CSV file to the knowledge base, while English content remains normal. This occurs because the UTF-8 encoding format for the CSV file was not specified, leading to incorrect parsing of Chinese bytes.
- The text dataset function is incorrectly used to upload structured CSV ledgers. This occurs because the requirement to match fixed fields via the template import function for structured CSV is not recognized. Text datasets only support unstructured text and cannot retain field association relationships.
- The number of retrieved results does not match the configured `limit` value, resulting in a large number of redundant or missing ledger entries. This occurs because `datasetSearchUsingExtensionQuery` is not disabled, with expanded query terms leading to matches in non-target fields.

## How to confirm the configuration is complete
- Upload a test hazardous chemical CSV ledger, and check that all fields are fully displayed after import with no garbled characters.
- Initiate a query related to ledger summary, and verify that the number of retrieved results matches the configured `limit` value.
- View the vector storage logs of the knowledge base, and confirm that the similarity of retrieved results falls within the configured `similarity` range.
- Check disk usage statistics, and confirm that the knowledge base storage includes original files, split chunks, and embedding vectors, with total usage matching deployment scale requirements.
