# Hazardous Chemical Storage and Transportation Ledger Summary and Report Generation: Deployment and Upgrade

## What data for this category looks like
Data sources include real-time collection systems for on-site storage and transportation equipment, inbound and outbound registration ledgers, and transportation dispatch logs. Update frequency: Single device data is synchronized every 10 to 30 minutes. Ledger documents are submitted in real time when associated business is completed. Document structure falls into three categories: equipment ledgers, transportation tracks, and inventory details. A single ledger document contains fields such as equipment number, storage medium, stock value, inbound and outbound time, and carrier information. Stock value units are tons or cubic meters. Time fields are precise to the second.

## What constraints these characteristics impose on deployment and upgrade
High-frequency real-time data, multi-type document structures, and specific field units for hazardous chemical storage and transportation create multiple constraints for deployment and upgrade.
Real-time collected device data synchronized every 10 to 30 minutes requires stable database connections to prevent interruptions that cause data loss.
Differences in ledger structures such as inbound and outbound records and transportation tracks require configuring parsing rules adapted to different document formats during deployment.
Differences in units such as tons and cubic meters for stock values require verifying field unit mapping logic during upgrades to avoid statistical errors.
The high volume of frequently updated business data requires configuring sufficient storage capacity to prevent write failures.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100-150 connections | Adapts to concurrent connection needs for high-frequency data synchronization in hazardous chemical storage and transportation, avoids connection exhaustion, applicable to FastGPT v4.17.0 |
| `STORAGE_S3_ENDPOINT` | Access address of enterprise internal object storage | Stores large volumes of equipment ledgers and transportation track files, matches storage requirements for local private deployments |
| `REDIS_URL` | Connection address for the local Redis service on port 6379 | Caches frequently accessed basic device information, reduces access pressure on the primary database |
| `MONGODB_URI` | Connection string in replica set format | Supports multi-node redundancy, ensures stability of real-time data writing, and avoids single point of failure |
| `FILE_TOKEN_KEY` | 32-bit randomly generated secret string | Encrypts access tokens for ledger files, ensures access security for sensitive storage and transportation data |

## Three common configuration errors
- Symptom: Docker deployment results in container startup failure. Logs show `connection refused` or connection timeout errors. Cause: Access permissions for `MONGODB_URI` or `REDIS_URL` are not properly configured, preventing establishment of a valid connection.
- Symptom: After uploading a ledger file in an offline environment, the status remains stuck in loading. The console shows external API request failures. Cause: Local file storage is not configured or external dependencies are not disabled. The system attempts to access external addresses, causing blocking.
- Symptom: The Markdown format summary table in the generated ledger report is truncated. The end of the table displays `...[hide 38432 char`. Cause: Parsing rules adapted for long documents are not configured, preventing complete loading of long table content.

## How to confirm configurations are properly set
- Review Docker container runtime logs to confirm no error messages appear for database connections or Redis connections.
- Upload a simulated hazardous chemical equipment ledger file. Confirm parsed fields fully match preset structures including equipment number and stock value.
- Trigger a ledger summary task. Confirm stock value units in the generated report are unified with no inconsistencies.
- Trigger a ledger summary task containing a long table. Confirm the generated report has no content truncation.

The values provided are common starting points and should be measured against local deployment samples.
