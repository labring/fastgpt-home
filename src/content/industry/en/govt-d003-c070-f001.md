# Ledger Summary and Report Generation for Power Generation Equipment Manufacturing: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Ledger data for power generation equipment manufacturing primarily comes from on-site SCADA collection systems, equipment operation and maintenance management platforms, and quality inspection systems. Data update frequencies fall into three categories: real-time operating parameters collected by sensors update every second, monthly operation and maintenance ledgers are synchronized daily, and quarterly quality inspection reports are generated monthly.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
High-frequency updates of real-time operating parameters require interface call intervals to not exceed 10 seconds, otherwise the latest data cannot be captured. The single-batch data volume of monthly operation and maintenance ledgers is large, so the single response limit of the interface must match the total number of device ledgers across the entire deployment to avoid truncation and loss of key maintenance records.

The fixed field structure requires request parameters to strictly correspond to predefined fields such as device ID and operating temperature. Interfaces that do not support non-standard fields will cause data writing failures. Non-standard HTTP port deployment in industrial sites requires interface authentication to use the `Authorization` header carrying a fixed token to prevent unauthorized access.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer Industrial Equipment Dedicated Token` | Matches the authentication requirements of on-site industrial interfaces to ensure data transmission security |
| `variables` | `{"statPeriod": "Last 30 Days", "equipmentType": "Steam Turbine Units + Gas Generator Sets"}` | Limits the statistical scope and device type of interface requests to accurately match ledger summary requirements |
| `responseData` | `Structured array containing device ID, operating temperature, and cumulative operating duration` | Directly adapts to the fixed field structure of ledger entries, simplifying subsequent report generation logic |
| Interface timeout | 600 seconds | Adapts to the long latency characteristics of on-site industrial interfaces to avoid timeout failures during batch data pulling |
| Single request data limit | 100 entries per request | Balances data transmission efficiency and interface load, adapting to batch pulling of monthly operation and maintenance ledgers |
| Request retry threshold | 3 times | Addresses occasional fluctuations in industrial networks to ensure the stability of data pulling |

## Three Common Misconfigurations
- The interface call returns 502 Bad Gateway, and logs show connection timeout. The cause is that HTTPS forwarding rules for power generation equipment dedicated interfaces are not configured in Nginx, preventing on-site industrial devices from accessing FastGPT interfaces deployed on the public network.
- The generated ledger report is missing some operating parameter fields. The cause is that the `responseData` mapping rules do not cover core fields such as device temperature and cumulative operating duration, resulting in incomplete data extraction.
- The interface request is rejected by the server, returning a 400 error. The cause is that the `variables` parameter does not use standard JSON format, causing FastGPT to fail to parse the statistical scope parameters in the request.

## How to Confirm Proper Configuration
- Call the configured HTTP interface and check whether the returned JSON structure includes predefined fields such as device ID and operating temperature.
- View the interface call logs to confirm that the `Authorization` header is correctly carried, with no authentication failure errors.
- Compare the interface returned data volume with the single request data limit setting to confirm that no data truncation has occurred.
- Manually trigger a ledger summary task and check whether the generated report includes the latest data pulled from the interface.
