# Ledger Summary and Report Generation for Power Generation Equipment Manufacturing: Workflow Orchestration

## What the data for this category looks like
Ledger data for power generation equipment manufacturing mainly comes from the unit real-time operation collection system, monthly maintenance archive documents, spare parts in-and-out warehouse system, and ERP inventory module. Data update rhythms fall into three categories:
- Real-time operation parameters are updated every 5 minutes
- Operation and maintenance records are archived at midnight daily
- Monthly ledger summaries are completed before the 5th of each month

Ledger documents for a single device are mostly in CSV or JSON format, including fields such as device unique identifier, rated power, cumulative operating hours, number of maintenance times in the past 30 days, replaced spare part models, single maintenance duration, and monthly energy consumption data. The unit of cumulative operating hours is hours, the unit of energy consumption is kilowatt-hours, and the number of maintenance times is an integer.

## What constraints do these characteristics impose on workflow orchestration
Power generation equipment manufacturing ledger data has scattered sources, large differences in update rhythms, and fields with specific industry units, which create multiple constraints for workflow orchestration.
Pulling data from different sources must match the corresponding update frequency: real-time operation parameters need high-frequency pulling nodes, while monthly summary data needs scheduled batch pulling nodes.
Unit validation for multiple fields must be embedded into workflow nodes to prevent issues such as negative operating hours and mixed energy consumption units.
The ledger data volume for a single device is large, so workflows must support batch summarization to avoid data overload during single processing.
Cross-system data must be aligned using the device unique identifier, to ensure ledger data from different sources corresponds to the same power generation equipment.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Preset | Configure `variables` as the standard fields for device ledgers | Matches the fixed structure of power generation equipment ledgers, enabling easy calling by subsequent summary nodes |
| Loop Trigger Rule | Traverse by device number list | Adapts to batch ledger summary requirements for multiple generator sets |
| Data Verification Node | Enable field format verification | Performs legality verification on fields with units such as cumulative operating hours and energy consumption |
| Timeout Setting | 600 seconds | Covers network and processing time for batch pulling ledgers of 20 devices |
| Single Pull Limit | Top 20 devices | Avoids timeouts caused by excessive data volume in a single request |
| Environment Variable Call | Enable call permissions | Used to pass sensitive configurations such as database connection keys and system interface addresses |

## Three common mistakes
- Adding 1 to the loop running index and receiving a null output: The workflow log shows the index field is empty. The cause is that the initial value of the loop index is not preset in `variables`, so the variable is not correctly bound after the first accumulation.
- Database connection workflow reports an error where SQL cannot retrieve data: The node returns an empty result set with a status code of 200. The cause is that the device number for the corresponding power generation equipment is not passed as a SQL query parameter in the workflow, so ledger data cannot be matched.
- Calling custom environment variables deployed via Docker fails: The node prompts that the configuration is invalid. The cause is that environment variable call permissions are not enabled in the workflow settings, or the corresponding key is not correctly passed during deployment.

## How to confirm the configuration is complete
- Manually trigger the ledger pulling node for a single device, verify the returned data includes the preset `variables` fields, and that field units comply with power generation equipment industry standards.
- Run the loop traversal node, confirm that ledger data for each device is correctly pulled and summarized, with no empty fields or abnormal unit content.
- View the workflow running logs, confirm that the timeout setting does not trigger timeout alerts, the data verification node does not intercept valid ledger fields, and each node's `nodeId` is uniquely identifiable.
- Call the environment variable test node, confirm that the database connection information configured during FastGPT v4.17.0 deployment can be correctly obtained.
