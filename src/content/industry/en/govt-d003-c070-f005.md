# Power Generation Equipment Manufacturing: Ledger Summary and Report Generation - Tool Calling and Plugins

## Data Structure and Sources for This Category
Power generation equipment manufacturing ledger data comes from full lifecycle equipment management systems, manufacturing execution systems, quality control department archived documents, and spare parts inbound and outbound records.
Update frequency falls into three categories:
1. Real-time synchronization of equipment operating parameters
2. Daily updates of inventory and energy consumption data
3. Monthly summary of maintenance and production reports
A single equipment ledger document includes fields such as unique equipment code, model and specification, manufacturing date, previous maintenance times and content, spare parts replacement records, cumulative operating hours, rated output power, and more. Units follow industrial standard units such as hours, megawatts, and yuan.

## Constraints for Tool Calling and Plugin Workflows
High-frequency updates of real-time operating data require tool calling response times to match short-cycle requirements. Delays compromise the timeliness of ledger summary.
Heterogeneous data from multiple sources requires plugins to support dedicated APIs for systems including equipment management and manufacturing execution. Authentication parameters for each interface must be configured in advance.
Fixed fields and standard units require tool calling parameter extraction rules to strictly match ledger field names and industrial standard units. This prevents parameter parsing errors.
For monthly summary scenarios, historical data for multiple devices must be pulled in a single operation. Pagination parameters for batch calls must be configured to avoid call failures caused by excessive data volume in a single request.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"`, or specify dedicated tools for "ledger data pulling" and "report generation" | Adapt to multi-stage tool calling requirements for power generation equipment manufacturing, supports automatic matching or targeted calls to dedicated plugins |
| `functionCall` | Enable mandatory parameter validation | Ensure extracted fields such as equipment code, operating hours, and spare parts costs conform to preset formats and industrial units |
| Tool calling timeout | `60-120 seconds` | Match response rhythms for real-time operating data pulling and monthly batch summary |
| Plugin batch call limit | `Single request data volume does not exceed 800 MB` | Avoid call failures caused by excessive data volume in a single request |
| User input confirmation trigger | Trigger after parameter validation passes | Prevent incorrect parameters from entering the summary process, aligns with the rigor requirements of operation and maintenance scenarios |

## Three Common Configuration Errors
- Phenomenon: The summary operation runs directly after tool calling extracts equipment parameters, without triggering the user confirmation link. Cause: The parameter validation trigger logic for `functionCall` is not configured, allowing incorrect equipment codes or unit parameters to enter the process directly.
- Phenomenon: After tool calling completes, all intermediate step operation logs and parameter extraction results display on the frontend. Only the final report cannot be retained. Cause: The result display switch for intermediate steps was not turned off during workflow orchestration, resulting in full-process content output.
- Phenomenon: A 401 authentication failure status code returns when calling multi-system plugins. Cause: Authentication keys for each corresponding system are not configured separately for each plugin, and interface credentials from different systems are mixed.

## How to Verify Correct Configuration
- A ledger pulling call for a single device is initiated, and returned data fields and units are checked against the preset ledger format.
- A batch call test is triggered, and the number of returned data entries is confirmed to not exceed the configured batch limit.
- Incorrectly formatted equipment code input is initiated, and verification confirms whether a parameter error or user confirmation prompt is triggered.
- Workflow logs are reviewed, and confirmation is made that intermediate step call results are not displayed on the frontend, and only the final report content is retained.
