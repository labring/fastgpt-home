# Ledger Aggregation and Report Generation for Power Generation Groups: HTTP Interfaces and External Systems

## What the data for this use case looks like
Power generation group ledger data originates from generating unit distributed control systems (DCS), fuel management systems, and environmental monitoring systems. The system updates real-time operating parameters every 15 minutes. It generates shift-level ledgers daily, and compiles formal operational reports on a monthly basis. Data uses structured JSON format. Each ledger entry includes fields such as unit number, statistical timestamp, cumulative power generation, standard coal consumption, denitration outlet pollutant concentration, and fuel consumption. Each field has a clear physical unit: power generation is measured in MWh, coal consumption in g/kWh, and pollutant concentration in mg/m³.

## Constraints for HTTP Interfaces and External Systems
The 15-minute update cadence for real-time parameters requires that HTTP interface call intervals cannot exceed 15 minutes. Otherwise, the system cannot retrieve the latest ledger data. The structure with multiple fields and clear physical units requires that interface requests specify a whitelist of return fields to avoid transferring redundant unauthorized fields. The classification of ledger data by unit and time dimension requires that interfaces support query parameters for unit number and statistical cycle. Large data volumes during bulk ledger aggregation require that interfaces support pagination queries to control the volume of data returned per request. Additionally, ledger data for power generation groups involves sensitive production and environmental information. This requires that interfaces must carry valid permission verification parameters to prevent unauthorized access.

## Three Common Configuration Errors
- Symptom: When calling the SSE-format ledger report generation interface, the frontend cannot receive progress data in segments, and the console reports "response format incompatible". Cause: `responseData` is not correctly configured for streaming chunked mode, causing standard SSE data returned by the interface to be blocked by non-streaming processing logic.
- Symptom: Some environmental-related fields are missing from the ledger data returned by the interface, such as denitration concentration values. Cause: Required return fields are not specified in `variables`, and the default fields returned by the interface do not include sensitive or infrequently used environmental parameters.
- Symptom: Interface timeout occurs when querying multi-unit ledgers in bulk, with single request duration exceeding the preset threshold. Cause: Pagination parameters are not set, and the full volume of data returned by a single request exceeds the interface's carrying limit.

## How to Verify Correct Configuration
- Call the configured HTTP interface, check that the returned JSON structure includes preset core fields such as unit number, statistical time, and power generation value.
- Simulate two interface calls at 15-minute intervals, confirm that the returned statistical timestamps match the update cadence of the power generation group's ledgers.
- Trigger a streaming SSE report generation request, verify that progress update data can be received in segments.
- Review interface call logs, confirm that the `Authorization` parameter is correctly carried, with no permission error or missing parameter prompts.
