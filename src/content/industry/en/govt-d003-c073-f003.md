# Ledger Summary and Report Generation for State-owned Industrial Funds: Multi-turn Dialogues and Prompt Configuration

## What the Data for This Category Looks Like
Ledger data for state-owned industrial funds comes from fund filing records on the state-owned asset supervision platform, payment transaction logs from dedicated capital contribution accounts, and project tracking archives from post-investment management systems. Updates sync in real time for single capital contributions and post-investment changes. Monthly summary ledgers and annual report ledgers update on fixed cycles. The document structure of a single project ledger includes fields such as project name, capital contribution entity, capital contribution amount, arrival date, shareholding ratio, post-investment valuation, exit progress, and more. The unit for amounts is ten thousand yuan, date format follows standard Gregorian calendar standards, and ratios are recorded as decimal values.

## Constraints for Multi-turn Dialogue and Prompt Configuration
Multi-turn dialogue and prompt configuration face multiple constraints from state-owned industrial fund ledger data characteristics. Data sources are dispersed, update rhythms are flexible, and fields have specific unit and format requirements.
Clearly distinguish field prefixes for modules like capital contribution, post-investment, and exit during dialogues for cross-source ledger data. This prevents the model from confusing identical-named fields from different sources.
Frequently updated post-investment change data requires dialogues to pull latest records in real time. Do not rely on expired cached context.
Explicitly specify in prompts that amounts use ten thousand yuan as the unit and dates follow standard Gregorian calendar formats. This meets strict field unit and format requirements, and prevents the model from generating non-compliant values or formats.
Single ledger projects may have many entries. Split context by project dimension during multi-turn dialogues to avoid exceeding context window limits.

## How to Configure Settings
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 800–1200 characters | Adapts to the total number of fields in a single project ledger for state-owned industrial funds, to avoid exceeding the model's context window |
| Dialogue context binding | Bind fixed `chatId` to a single fund project | Ensures coherent context for multi-turn dialogues of the same project, avoids mixing data across projects |
| Preset variable configuration | Preset two global variables: project name and statistical cycle | Quickly switch summary tasks for different projects and statistical cycles, reduces repeated prompt writing |
| Real-time data pulling | Enable real-time pulling of the latest 5 change ledger records | Adapts to the high-frequency update characteristics of state-owned industrial fund ledgers, ensures reports use the latest data |
| Dialogue timeout setting | 600 second timeout threshold | Addresses complex calculation requirements for single project ledger summaries, prevents dialogue interruptions due to excessive waiting time |
| Generation interruption configuration | Enable sending new messages to interrupt current generation | Addresses redundant questions or incorrect instructions that may appear during multi-turn dialogues, improves interaction flexibility |

## Three Common Misconfigurations
- Symptom: After calling the API to send a dialogue request, an error message "No permission to operate this dialogue record" is returned. Cause: Fixed `chatId` is not bound to a single fund project, leading to failed cross-project permission verification for dialogue context.
- Symptom: When sending multiple dialogue requests simultaneously, subsequent requests must wait for prior requests to complete before processing, and active interruption is not supported. Cause: No concurrency limit for dialogue context is configured, leading to queued execution of requests under the same `chatId`.
- Symptom: After refreshing the dialogue page, existing ledger summary dialogue records disappear, and a new dialogue is displayed. Cause: Dialogue storage is not bound to a project-specific unique identifier, so the corresponding project's context data is not automatically loaded after page refresh.

## How to Confirm the Configuration Is Complete
- Launch a multi-turn dialogue for a single state-owned industrial fund project. Confirm the context only contains ledger data for that project, and that context length matches the preset configuration.
- Send a query requesting latest ledger data. Confirm returned results include recently updated post-investment or capital contribution records, with no expired data.
- Send multiple dialogue requests simultaneously. Confirm subsequent requests execute normally without waiting for prior requests to complete.
- Refresh the dialogue page. Confirm existing dialogue records and ledger data load normally, with no switch to a new dialogue.
