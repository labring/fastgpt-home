# State-owned Asset Management Company Ledger Aggregation and Report Generation: Workflow Orchestration

## What the data for this category looks like
Data primarily comes from state-owned asset supervision reporting systems, internal financial accounting systems, asset property right registration archives, and ad hoc disposal ledgers.
Update rhythm follows two modes: fixed periodic updates and ad hoc triggered updates. Fixed periodic updates use monthly or quarterly cycles. Ad hoc updates correspond to change scenarios such as asset transfer or disposal.
Documents use structured tables as the core carrier, with fields including asset ID, asset category, book value, service life, storage location, disposal progress, and more. Book value uses ten thousand yuan as the unit. Service life uses years as the unit. Asset quantity uses units/sets as the unit.

## What constraints these characteristics impose on workflow orchestration
Scattered data sources require workflow configurations to include cross-system data fetch nodes. These nodes connect to different data sources such as state-owned asset supervision systems and internal financial systems. Field mapping rules must also be configured to unify field formats across systems.
Dual trigger requirements of fixed periodic and ad hoc updates require workflows to support both scheduled trigger and event trigger startup modes. Branch nodes must be configured to distinguish different update scenarios.
The large number of structured fields and state-owned asset compliance requirements require embedding data verification nodes in the workflow. These nodes verify the completeness and format compliance of required fields such as asset ID and book value.

## How to configure settings
This page content is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset state-owned asset classification dictionary with initial value `["fixed assets","current assets","intangible assets"]` | Unify cross-data-source asset category field mapping rules |
| `nodeId` | Configure node IDs in the order of data fetch → field mapping → verification → aggregation → output | Ensure data processing flows execute in compliance order |
| Trigger Mode | Scheduled trigger (00:00 on the 1st of each month) + Event trigger (asset change callback) | Match business requirements for monthly fixed updates and ad hoc updates from asset changes |
| Data Verification Rules | Number of missing required fields = 0, number of format errors = 0 | Meet compliance requirements for state-owned asset ledger data |
| Result Output Format | Structured Excel + PDF dual format | Adapt to dual requirements of state-owned asset supervision reporting and internal archiving |

## Three common configuration errors
- Phenomenon: An error is returned directly when the workflow enters the tool call phase after initiating a request. Status code 400 is returned. Cause: Cross-system data source `variables` mapping rules are not configured, causing the parameter format passed during tool calls to not meet the requirements of state-owned asset ledger data.
- Phenomenon: The global variable initial value does not take effect, and the field is empty after variable update. Cause: No initial value is preset in the `variables` configuration item, only temporary assignment is made during runtime, and the trigger parameters of the workflow node are not bound.
- Phenomenon: Garbled characters or classification errors appear in the asset category field of the ledger aggregation result. Cause: Field mapping nodes are not configured in the `nodeId` order, resulting in failure to complete unified conversion of asset category fields from different data sources.

## How to confirm the configuration is complete
- Manually trigger the scheduled trigger node, check the return result of the data fetch node, confirm that the field completeness of each data source meets the requirements.
- Edit the `variables` configuration item, modify the content of the asset classification dictionary, run the workflow and check whether the fields in the aggregation result are updated synchronously.
- Check the configuration order of `nodeId`, confirm that the node order of data fetch, mapping, verification, aggregation, and output is not reversed.
- Trigger the event trigger node, simulate an asset change scenario, check whether the workflow starts automatically and generates the corresponding report.
