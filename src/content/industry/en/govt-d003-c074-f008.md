# State-owned Asset Management Companies' Ledger Aggregation and Report Generation: Document Parsing and Chunking

## What this category of data looks like
The ledger data for state-owned asset management companies primarily comes from state-owned asset supervision and reporting systems, internal financial accounting systems, property rights registration documents, and asset disposal approval documents. Data is updated on a regular monthly, quarterly, and annual schedule, with immediate updates for temporary asset changes such as transfers and disposals. Document formats include structured Word table ledgers, annual assessment reports in PDF format, and property right certificates in scanned format. Fields include asset number, book value, assessed value, affiliated unit, service life, and similar fields. Common units include ten thousand yuan, square meters, and quantity.

## What constraints do these characteristics impose on document parsing and chunking
State-owned asset ledgers have a high proportion of structured tables. The parsing process must accurately identify cell association relationships to avoid misaligned table content. Documents with long text reports and multiple attached files require support for large file uploads and timeout fault tolerance. Documents contain a large number of associated fields such as property right references and assessment basis. The parsing process must retain these reference associations. The binding relationship between asset entries and corresponding values is strong. Chunking must avoid splitting complete information units for the same asset. Some documents use encrypted or scanned formats. Parsing logic must adapt to these non-standard document types.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | State-owned asset ledgers have dense fields. This range preserves complete information for a single asset or section, avoiding overly fragmented or overly long chunks that harm retrieval performance |
| `chunkSplitter` | Split by paragraph + title | Ledgers have clear section titles and asset entry boundaries. Following this splitting rule preserves contextual associations and avoids splitting across assets |
| `customPdfParse` | Enabled | Adapts to encrypted scanned documents and complex nested tables common in state-owned asset documents, improving recognition accuracy for structured content |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Annual summary ledgers may include multiple attached documents. This setting supports batch upload and parsing of large files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large files or multi-attachment documents takes a long time. This duration prevents mid-parsing timeout failures |
| `chunkSettingMode` | Manual mode | Allows flexible adjustment of chunking rules for different types of ledger documents such as monthly reports and annual reports |

Reference only; verify against the target FastGPT release and deployment documentation.

## Three common mistakes
- Symptom: After uploading a ledger file, the model cannot read the file content, and the interface displays parsing failure. Cause: `customPdfParse` is not enabled to adapt to encrypted or complex format documents, or the `UPLOAD_FILE_MAX_SIZE` setting value is smaller than the actual uploaded file size.
- Symptom: Table content in imported Word ledger documents is disordered, and images cannot be recognized normally. Cause: Custom parsing mode is not enabled, and the default parsing logic is not optimized for multi-table, dense state-owned asset documents.
- Symptom: Asset numbers and corresponding valuation binding relationships are lost in chunked content. Cause: `chunkSplitter` is set to split by pure characters, without using asset entries or section titles as splitting boundaries.

## How to confirm the configuration is complete
- Upload a standard state-owned asset monthly ledger document, check the parsed text content, confirm that all table cell contents are complete and correctly positioned, and image descriptions can be read normally.
- Check the background logs of the parsing task, confirm that the parsing time does not exceed the duration set by `PARSE_FILE_TIMEOUT_SECONDS`, and there are no timeout-related error messages.
- Randomly sample chunked content after parsing, confirm that each chunk contains complete asset entry or section information, and no cases where the same asset's number and valuation are split into different chunks appear.
- Test uploading an annual ledger summary file larger than 500 MB, confirm that the upload and parsing process can be completed normally, and no file truncation occurs.
