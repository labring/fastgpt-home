# State-owned Asset Management Company Ledger Summary and Report Generation: Model Access and Configuration

## What this category of data looks like
Ledger data for state-owned asset management companies comes from three main sources: pushes from state-owned asset supervision platforms, entries entered via in-house business systems, and data from financial accounting modules.
Data updates follow two rhythms: Daily synchronization of incremental data such as new assets and ownership changes. Monthly generation of full ledger snapshots.
Each ledger entry is a structured entry with these fields: unique asset identifier, affiliated first-level enterprise, posting date, book value (unit: ten thousand RMB), storage location, usage status, and department responsible for centralized management. Usage status uses fixed enumeration values.

## Constraints imposed by these characteristics on model access and configuration
Multi-source updated ledger data creates batch processing requirements. Model access must be configured with sufficient context carrying capacity.
There are many structured fields with fixed units. Model output must strictly match field formats and units to avoid deviations.
Monthly full snapshot data has a large volume. Token consumption per single call must be limited to prevent timeouts.
Minor field differences exist across different business modules. Multiple sets of field mapping rules must be configured to ensure summary logic aligns with business definitions.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the stitching needs of monthly full ledger snapshots, avoids context overflow |
| `maxTokens` | 4000 token | Limits output length for single-batch report generation, matches the content volume of ledger summaries |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures consistency of structured fields and units |
| `toolChoice` | auto | Allows the model to independently choose whether to call tools for processing batch ledger data |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated address according to the deployment environment | Adapts to private deployment or dedicated line access needs of state-owned asset management companies |
| `AIPROXY_API_TOKEN` | Generate dedicated tokens according to permissions | Ensures data call security, complies with state-owned asset supervision permission requirements |

## Three Common Configuration Errors
- Phenomenon: Returns an unsupported error when calling non-OpenAI retrieval models. Cause: The dedicated access endpoint and permission token for domestic models were not correctly filled in the model access configuration, and model type adaptation configuration was not completed.
- Phenomenon: Access to the retrieval model accessed via ollama is denied, but the interface test via curl works normally. Cause: Request headers or identity verification parameters were not correctly passed in the model access configuration, causing FastGPT requests to fail the target model's permission verification.
- Phenomenon: Report fields generated during batch ledger summary are in chaotic format and do not match the preset ledger structure. Cause: The `temperature` configuration value is too high, leading to excessive model output randomness that prevents strict adherence to structured output requirements.

## How to Verify Correct Configuration
- Call the model access test interface, input a single structured ledger entry, and check if the returned result matches the preset fields and units.
- Upload the monthly full ledger snapshot, verify that context stitching operates normally with no overflow errors.
- After configuring the domestic model access endpoint, initiate a model call request and confirm the returned result has no format errors.
- Adjust the `temperature` parameter, compare the consistency of multiple call results, and confirm that output randomness meets business requirements.

The values provided are common starting points and should be measured against the reader's own samples.
