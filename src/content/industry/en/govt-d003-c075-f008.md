# Ledger Summary and Report Generation for State-owned Capital Investment Companies: Document Parsing and Chunking

This document is compatible with FastGPT v4.17.0, and explains the document parsing and chunking process for ledger summary and report generation scenarios for state-owned capital investment companies.

## What this type of data looks like

State-owned capital investment company ledger data mainly comes from state-owned assets supervision platforms, group headquarters business systems, and standardized documents submitted regularly by fully owned and controlling subsidiaries. Core operating ledgers are submitted quarterly, with real-time updates for major investment adjustments. Most documents are standardized PDF ledgers, Excel summary tables, and some scanned PDF files. Fields include investment entity code, project filing number, current contribution amount, cumulative completion rate, compliance rating, and more. Common units are ten thousand yuan, percentage, and project count.

## What constraints do these characteristics impose on the document parsing and chunking process

Standardized ledgers have numerous fixed fields. Parsing must accurately match fields to avoid misalignment. Single ledger documents may contain multiple periods of data. Chunking must retain the integrity of single-period ledgers to prevent cross-period splitting that causes subsequent summary errors. Some scanned ledgers have font shifts and table misalignment. Parsing must meet accuracy requirements for converting unstructured data to structured data. When batch processing documents submitted by multiple subsidiaries, the system must apply unified parsing logic across different file formats, and address large file timeout risks.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | State-owned capital investment company ledgers have moderately sized single records. This range covers complete information for single-period project ledgers, avoiding field fragmentation after splitting that impacts subsequent summaries |
| `chunkSplitter` | Split by table paragraphs | Standardized ledgers take tables as core units. Splitting by table paragraphs retains structural integrity of individual ledgers, preventing chunking from breaking table logic |
| `customPdfParse` | Enabled | Most ledgers for state-owned capital investment companies use standardized formats. Enabling custom PDF parsing adapts to table extraction and scanned document OCR optimization, improving field recognition accuracy |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Single annual summary ledgers may include documents from dozens of subsidiaries. This setting supports large-file batch uploads to meet batch processing needs |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large multi-hundred-page PDF ledgers take significant time to parse. 600 seconds covers the parsing cycle for conventional large files, avoiding mid-process timeout failures |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different ledger document formats, adapting to structured Excel files and semi-structured scanned PDF files, improving parsing adaptability |

## Three Common Misconfigurations

- Uploading ledger documents larger than 1000 MB results in a failed upload prompt indicating file size limit exceeded. The cause is failure to adjust the `UPLOAD_FILE_MAX_SIZE` configuration; the default value cannot accommodate large summary ledgers.
- Timeout errors occur when parsing multi-hundred-page annual summary ledgers. The parsing status remains "processing" for an extended period before failing, or returns a 504 status code. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` configuration; the default timeout period is insufficient for large file parsing durations.
- When parsing Excel-format ledgers, some fields are empty or misaligned, and merged cell content in tables is lost. The cause is failure to enable the `customPdfParse` configuration; the default parsing logic cannot adapt to Excel table merged cells and format shifts.

## How to Verify Proper Configuration

- A typical subsidiary monthly ledger PDF is uploaded. The parsed text content is checked for complete retention of all table fields, with no obvious field misalignment or missing content.
- An annual summary ledger with more than 500 pages is uploaded. The parsing task's timeout prompt is verified to match the preset `PARSE_FILE_TIMEOUT_SECONDS` configuration period.
- 3 to 5 ledger documents of different formats are batch uploaded. All files are confirmed to complete parsing normally, with no format unsupported error messages.
- The `chunkSize` configuration is adjusted. The chunked text is checked to cover the complete content of a single ledger, with no cross-period splitting.
