# Ledger Aggregation and Report Generation for State-owned Capital Investment Companies: Deployment and Upgrade

## What the data for this category looks like
State-owned capital investment companies’ ledger data comes from state-owned assets supervision reporting systems, internal financial accounting platforms, investment project management repositories, and equity transfer archives.
Update cadence follows two schedules: full quarterly updates for core ledgers, and incremental monthly updates for modified ledgers.
Documents use structured tables as their main format. They include fields such as unique ledger identifier, full operating entity name, investment amount, shareholding ratio, project implementation progress, and compliance check status.
Amount units are ten thousand yuan. Ratio fields use percentage units. Time fields follow ISO standard date format.

## What constraints these characteristics impose on deployment and upgrade
Multi-source heterogeneous data sources require configuring multiple database connections during deployment. This adapts to structured data from different systems and avoids data synchronization gaps.
Quarterly full and monthly incremental update cadences require compatibility with dynamic scheduled task adjustment logic during upgrades. This prevents interruptions to data synchronization processes.
The large number of structured fields, including compliance check status, require pre-configuring vector retrieval associated fields during deployment. This ensures retrieval results cover compliance dimensions.
Fixed units for data amounts and ratios require retaining field unit mapping rules during upgrades. This avoids format errors in subsequent parsing.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `DB_MAX_LINK` | `100–200` | Adapts to FastGPT v4.17.0 connection pool configuration rules. Meets concurrent connection needs for multi-source ledger data. Prevents connection pool exhaustion |
| `MONGODB_URI` | `mongodb://<state-owned assets business account>:<corresponding password>@<designated host address>:27017/ledger_db?authSource=admin` | Connects to historical ledger archives exported from state-owned assets supervision systems. Supports persistent storage of structured data |
| `PG_URL` | `postgresql://<ledger query account>:<corresponding password>@<financial system host address>:5432/ledger_db` | Stores incremental monthly updated modified ledger data. Supports complex conditional queries and statistics |
| `STORAGE_S3_ENDPOINT` | `https://s3-gov-<compliant-storage-domain>.com` | Adapts to compliant storage endpoints required by state-owned assets systems. Retains official report files generated from ledgers |
| `REDIS_URL` | `redis://:<cache access password>@<cache host address>:6379/0` | Caches high-frequency accessed ledger field mappings. Accelerates parsing speed during report generation |

## Three common mistakes
- Phenomenon: Container startup fails during deployment. Logs indicate MongoDB authentication failure. Cause: The connection string uses the generic placeholder `username` instead of the actual business account assigned by the state-owned assets system.
- Phenomenon: FastGPT service cannot start on arm64 architecture servers. Cause: The x86 architecture image was pulled directly. The official arm64-adapted image package was not used.
- Phenomenon: After deploying vllm locally to run the Qwen3-30B-A3B model, report generation tasks return empty results. Cause: The local model’s access port and file path were not correctly specified in the deployment configuration. Service calls cannot connect.

## How to confirm the configuration is complete
- Run the built-in database connection test tool. Verify that connections configured via `MONGODB_URI` and `PG_URL` work normally. No authentication or timeout errors appear.
- Upload a structured sample of state-owned assets ledger data. Trigger a single report generation task. Confirm the task status shows success, and the generated report format meets requirements.
- Log in to the management interface for the compliant storage endpoint. Confirm generated report files have uploaded correctly and can be downloaded normally.
- Check Redis cache monitoring logs. Confirm high-frequency ledger field cache hits work normally. No abnormal disconnections or expiration events occur.

The values provided are common starting points and should be measured against the reader's own samples.
