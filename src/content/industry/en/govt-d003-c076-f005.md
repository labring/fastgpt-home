# Ledger Summary and Report Generation for State-owned Capital Operation Companies: Tool Calling and Plugins

## What the data for this category looks like
State-owned capital operation company ledger data primarily originates from state-owned assets supervision platforms, the group’s in-house financial systems, and regular submission documents from affiliated enterprises. Two data update schedules apply: monthly operating ledgers from affiliated enterprises are synchronized monthly, and consolidated group operating ledgers are updated weekly. Each individual ledger document includes fields such as affiliated enterprise identifier, total assets, net revenue, list of major investment projects, and compliance rectification records. Field units are uniformly standardized as ten thousand yuan, number of projects, number of person-times, and similar units. Each document contains both structured data and unstructured annotation content.

## What constraints these characteristics impose on tool calling and plugins
The scattered data sources and differentiated update schedules for state-owned capital operation company ledgers require tool calling to integrate three types of MCP services: state-owned assets supervision platforms, financial systems, and affiliated enterprise submission ports. The differing update cycles for data across dimensions require configuring periodic trigger rules for tool calling to align with the synchronization rhythms of monthly operating ledgers and weekly consolidated ledgers. Ledger fields include multiple unit types and a mix of structured and unstructured content, so the parameter validation step for tool calling must strictly match preset field names and unit rules to avoid ledger summary deviations caused by data format conversion errors. Each document contains nested data across multiple affiliated enterprises, so plugins must support parallel extraction of batch data and hierarchical merging logic.

## Configuration Guidelines
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multi-tool parallel calling scenarios, meeting ledger summary needs for simultaneous integration with state-owned assets supervision and financial systems |
| `functionCall` | `{"name": "capital_statistics", "parameters": {"period": "monthly"}}` | Precise specification of state-owned assets statistics tool calls, aligning with the summary logic for monthly operating ledgers |
| Tool call timeout setting | `600 seconds` | Ledger data includes cross-system multi-interface requests; typical single interface response time is under 300 seconds, so this setting provides a reasonable buffer |
| Tool call batch limit | `Top 8 entries` | The number of affiliated enterprises included in a single ledger typically ranges from 5 to 10, matching a reasonable scale for batch extraction |
| Stream output toggle | `Disabled` | Ledger summary and report generation require full receipt of structured data before generating official documents; stream output will cause intermediate data truncation |

## Three Common Misconfigurations
- When calling MCP services to retrieve ledger data, numeric fields are forcibly converted to string types, preventing subsequent numeric summary calculations. Cause: The tool call parameter validation rule defaults to binding all input parameters as string types, does not enable type adaptation, and fails to match the multi-field type requirements of ledger data.
- The configured tool call module in the workflow does not trigger external service requests during runtime, resulting in empty module output. Cause: The `toolChoice` parameter is not configured correctly, or the target tool name is not specified, so the system cannot identify the service port to call.
- After the tool call module is connected to the knowledge base, the generated report cannot reference compliance record content from the knowledge base. Cause: The execution order of the tool call module and the knowledge base module in the workflow is incorrect; the knowledge base data is not loaded before the tool call, so it cannot be accessed during the calling phase.

## How to Verify Proper Configuration
- Run a test ledger summary task, check the tool call logs, confirm that all configured MCP services are successfully triggered, with no failed call records.
- Extract the structured data returned by tool calls, verify that field names and units match the preset ledger field rules, confirming no format conversion deviations.
- View the complete output of the tool call module, confirm that no truncated content appears, matching the expected behavior when the stream output toggle is disabled.
- Run a ledger task involving multiple affiliated enterprises, confirm that the number of extracted enterprises complies with the configured batch limit rule.
