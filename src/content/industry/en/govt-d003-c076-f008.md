# Ledger Summary and Report Generation for State-owned Capital Operation Companies: Document Parsing and Chunking

## What the data for this category looks like
State-owned capital operation companies source their ledger data from reports exported from internal state-owned assets supervision systems, operating ledgers regularly submitted by subsidiaries, property right change vouchers, and annual operating analysis reports. The data follows three update schedules: monthly operating ledgers, quarterly summary reports, and annual final accounts reports. Most documents are structured tables with fixed headers, including fields such as registered capital, net asset scale, total foreign investment, and regulatory assessment scores. Most units use ten thousand yuan, hundred million yuan, or percentage. Some documents include annotations and attachment descriptions.

## Constraints on document parsing and chunking
Structured tables serve as the core carrier for ledger and report data from state-owned capital operation companies. Conventional text chunking logic often breaks row and column associations in tables, so parsing workflows must prioritize table integrity. Ledgers submitted by subsidiaries may have non-standard formats such as shifted headers or slightly adjusted field order, so chunking rules must adapt to these minor differences. Some state-owned capital operation data involves sensitive regulatory information, so parsing processes must meet data local retention requirements. Annual final accounts reports are lengthy, so chunking workflows must balance single-block content capacity and cross-block context coherence to avoid splitting critical data associations.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density and table row width of state-owned capital operation company ledgers, avoiding splitting critical data associations |
| `chunkSplitter` | Split by paragraph + table boundaries | Matches the document characteristics of ledgers with multiple structured tables, preserving table integrity |
| `customPdfParse` | Enable local parsing service | Prevents sensitive data from being leaked during online parsing, complying with state-owned assets data security requirements |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the single-file volume limit of annual final accounts reports, meeting the demand for batch uploading large ledgers |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Reserves sufficient parsing time for lengthy final accounts reports, avoiding parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different types of ledger documents (monthly/quarterly/annual) to adapt to format differences |

## Three Common Configuration Mistakes
- Uploading a ledger PDF results in misaligned table parsing, with rows and columns displayed in disorganized order. This occurs when chunking rules adapted to structured tables are not configured, as the default text chunking logic breaks row and column associations in tables.
- Parsing large annual final accounts reports results in timeout errors, returning status code 504. This occurs when the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted to a sufficient duration, leaving inadequate time for long document parsing.
- Enabling the online parsing service triggers a sensitive data leakage risk prompt. This occurs when `customPdfParse` is not configured to enable local parsing, leaving data vulnerable to leakage during network transmission.

## How to Confirm Successful Configuration
- Upload a monthly ledger PDF, check if the parsed text retains a complete table structure with no disorganized row or column splits.
- Upload an annual final accounts report with more than 100 pages per single file, confirm that the parsing task does not fail automatically within the preset duration, verifying that the timeout configuration is effective.
- Check the parsing service running logs, confirm that no network request records appear, verifying that the local parsing configuration is enabled.
- Adjust `chunkSettingMode` to manual mode, test chunking rules for different types of ledger documents, confirm that no critical field combinations are split in single blocks.
