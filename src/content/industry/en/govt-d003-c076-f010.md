# Ledger Summary and Report Generation for State-owned Capital Operation Companies: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
Ledger data for state-owned capital operation companies primarily comes from data submitted via state-owned assets supervision platforms, financial accounting systems of the group headquarters and subsidiaries at all levels, and property right registration systems.
The update schedule follows: daily sync of monthly basic data; full quarterly summary ledgers are updated within 5 working days after the end of each quarter.
Each ledger document includes fields such as main identification code, affiliated level, total assets, long-term equity investment amount, current period revenue, profit remitted amount, report start and end dates, and more. Field units are uniformly ten thousand yuan and natural days. No custom non-standardized fields are included.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Ledger data for state-owned capital operation companies is multi-source and scattered, has layered update rhythms, and uses standardized field formats. These characteristics impose multiple constraints on the knowledge base retrieval and recall link.
Multi-source data requires association of multiple datasets to complete full recall. Layered updates require distinguishing recall priorities between full and incremental datasets to avoid mixing expired data into results.
Standardized fields require precise keyword matching to prevent invalid content from fuzzy recall. The volume of content recalled in a single pass must be adapted to the context window for subsequent ledger summary and report generation, to avoid exceeding processing limits.
In addition, ledger data contains many quantitative fields, so recall accuracy must balance numerical matching and text description.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `collectionIds` | Configure dataset ID collections separately for three categories: state-owned assets supervision and reporting, group finance, and property right registration, containing 2 to 4 datasets | Covers all sources of ledger data, avoiding missing ledger information from key subsidiaries |
| `limit` | Top 20 entries | A single ledger report for a state-owned capital operation company needs to integrate data from multiple subsidiaries. 20 entries can cover typical summary needs while avoiding context overflow |
| `similarity` | 0.72–0.78 | Ledger data includes fixed fields and quantitative values. This range filters low-match irrelevant data while retaining relevant ledgers from subsidiaries at the same level |
| `searchMode` | Precise field matching | Ledger data has standardized field formats. Precise matching improves the recall accuracy of field-related keywords |
| `usingReRank` | Enabled | Results recalled from multiple datasets have redundancy. Reranking prioritizes content most relevant to ledger summary requirements |
| `datasetSearchUsingExtensionQuery` | Disabled | Ledger data has standardized fields, so query extension is not required for precise matching, avoiding introducing irrelevant content |

## Three Common Misconfigurations
- Phenomenon: When calling the independent knowledge base search interface, the number of returned results matches the configured `limit` value, but the knowledge base retrieval node in the workflow returns far fewer results than the configured value. Cause: Parameter configurations for independent retrieval and in-workflow retrieval are not distinguished. The workflow retrieval node has a lower default reference limit, and no adjustments were made to adapt to the ledger data volume requirements of state-owned capital operation companies.
- Phenomenon: Retrieval results include expired ledger data from the previous quarter. Cause: The full-update quarterly ledger dataset and the incremental-update monthly ledger dataset were not separately configured for `collectionIds`, resulting in expired data being recalled together.
- Phenomenon: Retrieval results include a large number of documents unrelated to ledger fields. Cause: `searchMode` was set to fuzzy matching, and precise matching mode was not used for standardized ledger fields, leading to recall of irrelevant content.

## How to Confirm Proper Configuration
- View the dataset association configuration page to confirm that the `collectionIds` parameter includes the dataset IDs corresponding to the three categories: state-owned assets supervision and reporting, group finance, and property right registration.
- Perform a simulated retrieval, enter the main identification code of a subsidiary, and verify that the returned results include core ledger fields such as total assets and net revenue, and that the matching score falls within the 0.72–0.78 range.
- Test the retrieval node in the workflow to confirm that the number of returned results matches the configured `limit` value of the independent retrieval node.
- Check that the reranking function is enabled, and confirm that the order of retrieval results matches the core requirements of ledger summary.
