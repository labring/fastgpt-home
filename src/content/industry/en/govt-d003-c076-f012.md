# Ledger Aggregation and Report Generation for State-owned Capital Operation Companies: Deployment and Upgrade

## What this category of data looks like
Ledger data for state-owned capital operation companies comes primarily from three sources: the state-owned assets supervision reporting system, business reporting portals of fully owned and holding subsidiaries, and the property right registration management system. Data updates follow three rhythms: monthly basic ledger updates, quarterly business summary updates, and annual full review updates. Each ledger document uses structured table format, with fields including enterprise main body code, affiliated industrial sector, total assets, current period revenue, ledger creation date, and reporting unit. Units for assets and revenue are uniformly ten thousand yuan, and ledger numbers use a fixed 16-character format.

## What constraints do these characteristics impose on deployment and upgrade
Ledger data characteristics for state-owned capital operation companies create multiple constraints for deployment and upgrade.
Configure vector database multi-dimensional index settings for structured multi-field ledger documents to avoid invalid fields consuming storage resources.
Set up scheduled automatic synchronization tasks for monthly high-frequency basic ledger updates to reduce manual import errors and delays.
Configure exact match retrieval rules for 16-bit fixed-format ledger numbers to improve recall accuracy of associated data.
Adjust database connection pool parameters for annual full batch business data imports to avoid service interruptions from concurrent connection overload.
Deploy dedicated intranet access keys for data pulling from cross-state-owned assets systems in intranet environments to bypass public network access restrictions.

## How to set configurations
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–15 | Meets concurrent database connection requirements during annual full ledger imports, prevents connection pool exhaustion |
| `PG_URL` | Intranet-deployed PostgreSQL instance address, formatted as `postgresql://username:password@host:port/dbname` | Stores structured ledger fields and retrieval indexes, supports multi-dimensional data storage and fast recall |
| `REDIS_URL` | Intranet-deployed Redis instance address, connection timeout set to 600 seconds | Caches frequently accessed ledger retrieval results and status markers for scheduled sync tasks, reduces repeated query overhead |
| `STORAGE_S3_ENDPOINT` | Intranet object storage service address; use local file storage path if not deployed | Stores uploaded ledger original documents and automatically generated report files, complies with intranet data security requirements |
| `ROOT_KEY` | 32-bit randomly generated string | Configures the highest privilege verification key for system administrators, ensures access security for intranet deployments |

## Three common mistakes
- Running `docker-compose up -d` throws a redis image pull failure error, preventing service startup. Cause: No private mirror source is configured in the intranet environment, and public network mirror addresses cannot be used to pull dependent components.
- The system prompts that the knowledge base count has reached the limit, and new knowledge bases corresponding to ledger categories cannot be added. Cause: The default knowledge base count limit configuration is not adjusted. The open source version defaults to 30, which cannot meet the storage needs of multiple ledger categories.
- No matching results are returned during ledger retrieval, and vector-related errors appear in logs. Cause: The PgVector plugin is not upgraded per official guidelines. The plugin version is incompatible with the current FastGPT deployment version, preventing normal loading of vector indexes.

## How to confirm configurations are correct
- Log in to the FastGPT backend management interface, check the database connection status, and confirm that the instances corresponding to `PG_URL` and `REDIS_URL` show normal connections.
- Upload a test ledger document, run a manual synchronization task, and confirm that data is successfully imported and corresponding retrieval indexes are generated.
- Configure a scheduled synchronization task, check the task logs, and confirm that monthly updated ledger data is automatically synchronized successfully with no error records.
- Access the domain configured in `FE_DOMAIN`, and confirm that the system interface loads normally and ledger data can be retrieved in the intranet environment.

The values provided are common starting points and should be measured against the reader's own samples.
