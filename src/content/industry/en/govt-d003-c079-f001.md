# Urban Gas Ledger Summary and Report Generation: HTTP Interfaces and External Systems

## What the data for this category looks like
Urban gas pipeline ledger data originates from three primary sources: SCADA pipeline monitoring systems, user payment management systems, and offline inspection work order systems. Daily inspection point data is updated daily. Pipeline pressure and leak detection data is pushed in real time. User gas consumption data is synchronized on a natural day basis. A single ledger document includes fields including pipeline node ID, inspection time, point latitude and longitude, leak detection value, maintenance records, and gas load data. The unit of leak detection value is ppm, the unit of maintenance duration is hours, latitude and longitude use the WGS84 coordinate system, and the summary cycle supports custom monthly and quarterly configuration.

## Constraints for HTTP Interfaces and External Systems
Interface adaptation for multi-source data must align with the authentication rules of each connected system. The SCADA pipeline monitoring system uses `Authorization` Bearer token authentication. The offline inspection work order system supports account and password authentication, and separate configuration is required for each system. Real-time pushed leak detection data requires the interface timeout threshold to not exceed 5 seconds; otherwise, real-time alarm information will be lost. Latitude and longitude coordinates must use the WGS84 coordinate system uniformly to avoid deviations during ledger point matching. Differences in update frequencies across data sources require matching pull cycles to avoid repeated data pulls or missed data. Field units must be uniformly converted to ensure all leak detection values use ppm format, which ensures accurate summary results.

## Three Common Misconfigurations
- Phenomenon: The interface returns a 200 status code, but the `responseData` field is empty. Cause: The interface field mapping for the inspection system was not configured correctly, so valid ledger data cannot be extracted.
- Phenomenon: The interface call returns a 504 timeout status code. Cause: The timeout threshold for the SCADA system was set too long, exceeding the real-time data transmission limit.
- Phenomenon: Deviations appear in ledger summary point positions. Cause: Coordinate formats were not unified, and data from different coordinate systems was mixed, leading to incorrect point matching.

## How to Verify Successful Configuration
- Call the configured interface, check if the `responseData` includes core fields such as pipeline node ID and leak detection value, and confirm the field mapping matches the configuration requirements.
- Compare the coordinate data returned by the interface with the preset WGS84 coordinate system format, and confirm the coordinate conversion logic is correct.
- Simulate pulling ledger data from different data sources, and check if numerical units are uniformly converted to preset formats such as ppm and hours.
- Run the interface pull task continuously, and confirm the pull time interval matches the data source update frequency, with no repeated or missed data.
