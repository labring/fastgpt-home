# Ledger Summary and Report Generation for Urban Investment Platforms: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Urban investment platform ledger data mainly comes from internal project management systems, financial accounting systems, and debt supervision platforms. There are two types of data update rhythms: fund disbursement ledgers are updated daily, and project progress ledgers are updated weekly. Each standalone ledger document uses a structured table format, including fields such as project ID, project name, total investment amount, cumulative disbursement amount, responsible entity, and ledger generation date. The unit for amount fields is uniformly ten thousand yuan, and the date field format is YYYY-MM-DD.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The multi-source update rhythm and structured field features of urban investment platform ledgers require multi-turn dialogue to clearly distinguish query scopes between fund-type and project-type ledgers. Prompts must predefine a list of callable fields to prevent unauthorized access to sensitive fields. During multi-turn dialogue, the user-specified ledger time range parameter must be retained to avoid cross-cycle data mixing. Additionally, the structured table format requires prompts to clearly define the output format, ensuring that summary results align with original ledger fields and avoid missing fields or unit errors.

## How to configure the settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `chatId` | Bound to the exclusive identifier of urban investment projects | Ensure multi-turn dialogue is associated with ledger data for a specified project, avoiding cross-project confusion |
| `messages` | Retain the last 8 rounds of conversation content | Cover query conditions such as ledger type and time range mentioned multiple times by the user |
| `variables` | Preset a list of ledger field variables | Allow prompts to call preset fields such as project ID and total investment amount |
| Number of entries returned per single conversation | Top 5 matching ledgers | Adapt to the multi-field structure of single urban investment ledger documents, reducing context redundancy |
| Context timeout | 600 seconds | Meet the needs of multi-turn verification during ledger summary, avoiding mid-process timeouts |

## Three common errors
- Phenomenon: After deleting a conversation session, the associated ledger query logs cannot be retrieved. Cause: The `chatId` is not bound to the exclusive identifier of urban investment projects. The association between the session and the project is lost, making logs unavailable for associated queries.
- Phenomenon: The prompt cannot automatically call the project number specified by the user in multi-turn dialogue. Cause: The `variables` in the prompt are not configured to bind parameters from conversation history, or context extraction configuration is not enabled.
- Phenomenon: After uploading a structured ledger image via the multimodal node, table content in the image cannot be recognized. Cause: Structured image recognition adaptation is not enabled in the model configuration, or the prompt does not specify the parsing format for image content.

## How to confirm the configuration is properly set
- Initiate a multi-turn dialogue that includes a project ID, check if the previously mentioned project ID is retained in the conversation history.
- Trigger a ledger summary request, verify that the returned results include the fields in the preset `variables`.
- Delete the current session, re-enter the session, confirm that previous ledger query logs can still be viewed normally.
- Upload a structured table image, confirm that the parsed results returned by the model align with the fields of the original table.
