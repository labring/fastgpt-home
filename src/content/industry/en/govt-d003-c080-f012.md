# City Investment Platform Ledger Summary and Report Generation: Deployment and Upgrade

## What the data for this category looks like
Data primarily comes from city investment platform project management systems, debt monitoring platforms, and financial accounting systems.
Update cadence follows three schedules: daily sync of project progress increments, weekly updates of financial accounting data, and monthly generation of full ledger snapshots.
Documents use structured tables as their main format, with fields including project ID, project type, total investment, funded amount, repayment plan milestones, and affiliated administrative district.
Units include ten thousand yuan, hundred million yuan, and calendar days, among others.
Single ledger document length typically ranges from thousands to tens of thousands of characters.

## What constraints these characteristics impose on deployment and upgrade
Ledger data from city investment platforms comes from multiple sources with varying update cadences.
Daily incremental sync and full snapshot updates coexist.
This requires deployment to support parallel access to multiple data sources.
Single documents have a long length, which imposes requirements on storage read/write bandwidth.
Upgrade workflows must include pre-evaluation of storage node IO load.
Structured fields include multi-unit numeric types.
Deployment requires configured unified field parsing rules to avoid unit conversion errors.
Cross-node storage needs for multi-region project ledgers require adjusting cluster sharding strategies during upgrade.

## Three Common Mistakes
- Symptom: After deployment, attempting to connect to the city investment platform business database returns the error `Access denied for user 'xxx'@'xxx'`. Logs show the database process starts normally, but connections are rejected. Cause: Intranet access whitelist for database connections is not configured. City investment platform databases are usually deployed on independent intranet nodes, and access permissions for the corresponding port are not enabled.
- Symptom: After Docker deployment on a Windows environment, the frontend page fails to load, returning a `502 Bad Gateway` status code. Cause: Container ports are not mapped to the correct host ports, and local firewall blocking of the corresponding port is not disabled. This prevents the frontend from accessing the FastGPT service.
- Symptom: After upgrade, some field numeric content is missing from generated ledger reports. Cause: Structured field unit conversion rules are not configured in advance. City investment ledgers include multi-unit numeric values such as ten thousand yuan and hundred million yuan. Without unified parsing, fields cannot be displayed normally.

## How to Confirm Configuration Is Correct
- Run a database connection test script to verify that the connection pool configured via `DB_MAX_LINK` can establish the specified number of database connections simultaneously. Read core structured ledger fields after successful connection.
- Upload a real city investment platform ledger document to trigger a report generation task. Check that the storage path matches the address configured via `STORAGE_S3_ENDPOINT`.
- Access the domain configured via `FE_DOMAIN` to verify that the frontend page loads normally and calls backend interfaces.
- View logs for the cache node corresponding to `REDIS_URL` to confirm that incremental ledger sync data has been cached correctly.

The values provided are common starting points and should be evaluated against local deployment samples.
