# Basic Chemicals Ledger Summary and Report Generation: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Ledger data for basic chemicals primarily comes from production control systems, laboratory quality inspection systems, and warehouse management systems. Updates are typically issued per shift or daily. Common document formats are multi-sheet Excel and structured Word files. Fixed fields include material code, batch number, reaction temperature, pressure, yield, quality inspection pass rate, and others. Supported units include ℃, MPa, %, tons, and additional standard units. A single ledger file often contains tens of thousands of data rows or hundreds of thousands of Chinese characters. Clear business association logic exists between fields.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Discrepancies in field naming occur because data originates from multiple systems. Prompts must first complete field alignment to ensure accurate summarization. Large Excel and Word files require multi-turn dialogue to split tasks, avoiding loading all data at once and exceeding model context limits. Frequently updated ledger data requires real-time retrieval of the latest entries during dialogue to match the high-frequency update rhythm of ledgers. Multi-turn interactions must track specific batch numbers to avoid confusing ledger data from different production cycles. Context length must also be controlled to prevent slowed response times.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Basic chemical ledgers have many fields. Single-turn dialogue must cover complete data for at least two batches to avoid truncating core information |
| Single Dialogue Token Limit | 16000 token | Adapts to chunk processing requirements for 15000-row Excel files, preventing exceeding context limits of mainstream large models |
| File Chunk Size | 500–800 rows (Excel) | Balances parsing efficiency and single-chunk processing complexity, matching the row scale of basic chemical ledgers |
| Session Binding Parameter | `chatId` | Binds the ledger batch number for the current session, ensuring consistent tracked business objects across multi-turn dialogue |
| Historical Message Retention | First 10 `messages` | Controls context length, avoiding response delays caused by excessive historical dialogue |
| Variable Passing Rule | `variables` | Passes the core field range for the current query, simplifying field matching logic for prompts |

## Three Common Configuration Mistakes
- Phenomenon: After uploading a 15000-row Excel ledger, the number of returned dialogue results does not match expectations. Cause: No appropriate file chunk size is configured, leading to some data chunks not being loaded correctly.
- Phenomenon: After calling the dialogue interface to upload a file, returned fields are empty. Cause: No field mapping rules are configured via `variables`, and Excel column names are not aligned with standard ledger fields.
- Phenomenon: Multi-turn dialogue responses time out, with a 504 status code returned. Cause: No single dialogue token limit is set, exceeding model context limits when processing large ledger files.

## How to Confirm Proper Configuration
- Upload a preset 15000-row Excel ledger, check the parsing progress in the dialogue interface, and confirm that the number of processing chunks matches expectations.
- Initiate a multi-turn dialogue, specify querying yield and quality inspection data for a specific batch, and verify that returned results include all core fields for that batch.
- Call the dialogue interface, pass the `chatId` parameter to run two consecutive dialogues, and confirm that the second dialogue inherits the query context from the first.
- Check the token consumption statistics panel, and confirm that the token count for each dialogue does not exceed the configured single-turn limit.

The values provided here are common starting points and should be evaluated against the reader's own samples.
