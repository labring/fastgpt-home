# Basic Chemicals Ledger Summary and Report Generation: Tool Calling and Plugins

## What this category of data looks like
Basic chemical ledger data mainly comes from three core industrial systems: Distributed Control System (DCS), Warehouse Management System (WMS), and Laboratory Information Management System (LIMS). Data is synchronized after each production shift or batched archived daily. A single batch of ledger includes fixed fields such as material code, batch number, feeding amount, reaction temperature, quality inspection result, and generation time. Units are mostly industrial standard units like ton, kilogram, and degree Celsius. Ledger documents are stored as structured tables, archived by production batch or monthly cycle. The row count of a single document varies with production scale.

## What constraints do these characteristics impose on tool calling and plugins
The multi-source heterogeneous nature of basic chemical ledgers requires tool calling to adapt to interface protocols of different systems such as DCS, WMS, and LIMS. Unified standardized parsing logic cannot be used. The batch-based archive structure of data requires plugins to support cross-system data association via batch numbers, avoiding missing information from single-table queries. Fields with industrial standard units require tool calling to automatically complete unit matching and conversion, preventing numerical calculation deviations. The daily or shift-based update rhythm requires plugin scheduled triggers to adapt to production scheduling cycles, ensuring timeliness and accuracy of summary data.

## Three Common Mistakes
- Phenomenon: An error prompt "No available MCP service instance found" pops up during tool calling. Cause: Adapted MCP server service for basic chemical systems such as DCS and WMS has not been deployed, and connection configuration for core data sources has not been completed.
- Phenomenon: Feeding amount values in generated ledger summary reports display mixed kilograms and tons. Cause: Field validation configuration for `functionCall` has not been enabled, and unified conversion processing for industrial standard units has not been performed.
- Phenomenon: Workflow tool calls return a "Result is empty" prompt. Cause: Tool call parameters have not been configured according to the batch number association rules for basic chemical ledgers, only scattered data from a single system has been queried.

## How to Confirm the Configuration is Correct
- Manually trigger a tool call, check if the returned ledger data includes core fields of basic chemical ledgers such as material code, feeding amount, and quality inspection result.
- Check the execution logs of the scheduled trigger task, confirm that the task starts and completes data summary at the preset 2:00 AM daily.
- Submit test data containing multi-unit fields, verify that tool calls automatically complete unit conversion with no mixed display issues.
- View the plugin running status panel, confirm that data sources from the three core systems DCS, WMS, and LIMS have been successfully connected.
