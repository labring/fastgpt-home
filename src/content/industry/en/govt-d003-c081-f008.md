# Basic Chemicals Ledger Summary and Report Generation: Document Parsing and Chunking

## What Data for This Category Looks Like
Ledger data for basic chemicals mostly comes from production shift daily reports, equipment inspection logs, raw material inbound and outbound documents, and quality inspection retention reports. The update cycle is daily or per production shift. Most documents are structured Excel spreadsheets or fixed-format PDFs, containing fields such as ledger number, production shift, operation date, material name, feeding quantity, and equipment operating duration. Numeric fields like feeding quantity and operating duration have clear units. Some ledgers include handwritten annotations or attachments in scanned document format.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Link
The structured nature of basic chemical ledgers requires that field associations be preserved during document parsing, and continuous records across shifts or batches must not be split. Otherwise, data logic will break during subsequent summary work, making accurate summary reports impossible to generate. High-frequency daily updated ledgers create demand for batch document processing. The chunking logic must adapt to the independent integrity of single-batch ledgers. Ledgers with scanned attachments require corresponding parsing capabilities to be enabled, otherwise handwritten annotations or scanned text content will be lost, affecting subsequent data verification. Numeric fields have clear attached units, so the binding relationship between units and corresponding values must be preserved during chunking to avoid unit confusion during subsequent report generation.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | `800–1200 characters` | Basic chemical ledgers are mostly structured short text. This range preserves the integrity of single records or continuous shift records, and avoids splitting key field associations |
| `chunkSplitter` | By paragraph and fixed delimiters | Most ledgers have fixed headers and single records separated by line breaks. Splitting this way preserves the complete structure of a single ledger |
| `customPdfParse` | Enabled | Some ledgers are scanned PDFs. Enabling this allows text content to be extracted via OCR, adapting to scenarios with ledger attachments |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 seconds` | Batch ledger processing requires sufficient time reserved for single-file parsing, to avoid parsing failures and no data output caused by timeouts |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | A single batch of ledgers may include multiple monthly reports. This upper limit covers conventional batch upload requirements |
| `chunkSettingMode` | Manual configuration | Basic chemical ledgers have large structural differences. Manual configuration allows flexible adjustment of chunking rules to adapt to ledgers of different formats |

## Three Common Mistakes
- After uploading an Excel ledger, the data processing step shows as empty. The corresponding structured document parsing configuration is not enabled, or the uploaded file exceeds the `UPLOAD_FILE_MAX_SIZE` limit, resulting in parsing failure and no data output.
- After batch importing ledgers, vectorization processing takes too long. The `chunkSize` value is too small, leading to an excessive number of chunks and increased vectorization calculation load. At the same time, upload tasks are not split by batch.
- When asking a question in a conversation, the entered text content triggers the document parsing process. The `trainingType` configuration is incorrect, and the conversation mode is mistakenly set to document training mode, causing all entered content to enter the document parsing link.

## How to Confirm the Configuration Is Correct
This document is based on FastGPT v4.17.0.
- Upload a single standard-format basic chemical ledger, and check whether the parsed data fields are fully preserved, with no missing or disordered content.
- Adjust the `chunkSize` configuration, upload multiple ledgers of different lengths, and verify whether the chunking results match the expected character range.
- Upload a ledger in scanned document format, and confirm that text content can be extracted after parsing, with no blank spaces or garbled characters.
- Test batch uploading multiple ledgers, and confirm that no timeout errors occur during the parsing process, matching the configuration expectations of `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided are common starting points and should be evaluated against the reader's own samples.
