# Ledger Summary and Report Generation for Basic Telecommunications Operations: Workflow Orchestration

## What this category of data looks like
The data sources for basic telecommunications operation ledgers include three categories: local billing systems, base station operation and maintenance monitoring platforms, and customer service work order systems. Data update rhythms are divided into three types: near-real-time (operation and maintenance fault logs, updated every 5 minutes), daily updates (package usage ledgers, updated daily at midnight), and monthly updates (monthly revenue ledgers, updated at the start of each month). A single ledger document includes fields such as base station ID, billing cycle, user package type, uplink/downlink traffic usage, and cumulative fault duration. Units are base station number, natural day/month/year, GB, and hours, respectively.

## What constraints do these characteristics impose on the workflow orchestration link
Inconsistent data formats across multiple sources require configuring data cleaning nodes in the workflow to adapt to field mapping rules of different systems. The update frequency of near-real-time operation and maintenance data requires matching workflow trigger timing to the data update cycle, to avoid summarizing outdated data. Multi-dimensional combined statistical requirements require reserving configurable statistical dimension variables in the workflow to adapt to different ledger generation scenarios. The large data volume of a single ledger requires setting reasonable pagination parameters for batch processing nodes in the workflow, to avoid exceeding single-load data limits.

## How to set configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Include billing cycle, base station ID, statistical dimensions | Adapt to the multi-dimensional statistical requirements of ledger summary, ensure correct filter parameters are passed during tool calls |
| User selection node | Single-select variable with options for daily/monthly/quarterly ledgers | Match the conventional statistical cycles of basic telecommunications operations, simplify manual configuration processes |
| Database connection timeout | 600 seconds | Telecommunication system data queries involve multi-table associations, avoid query timeouts due to large data volume |
| Workflow trigger timing | Trigger hourly | Adapt to the update rhythm of near-real-time operation and maintenance data, meet the requirement for timely summarization |
| `nodeId` | Bind the unique identifier of the database query node | Ensure accurate positioning of the corresponding node during tool calls, avoid execution errors caused by node confusion |
| Number of records returned per query | Top 20 records | Balance data loading efficiency and statistical completeness, prevent workflow lag caused by loading too much data at one time |

## Three common mistakes
- Database connection node returns `Access denied for user` error. The cause is failure to configure exclusive database account permissions for basic telecommunications systems, or failure to correctly pass account and password parameters via `variables`.
- The summary result fields are empty after workflow execution. The cause is failure to configure statistical dimension variables required for the ledger in `variables`, causing the node to fail to obtain correct filter conditions.
- The single-select variable of the user selection node cannot be assigned a global variable. The cause is failure to bind global variables to the corresponding option mapping of the user selection node, causing variable transfer failure.

## How to verify the configuration is complete
- Trigger the workflow manually, check the return logs of the database connection node, confirm there are no permission errors and the returned data includes preset ledger fields.
- Modify the statistical cycle in the global variables, run the workflow, confirm that the summary result changes with the variable adjustments.
- Check the single-select options of the user selection node, confirm that they can be normally selected and passed to subsequent summary nodes.
- View the workflow execution status panel, confirm that all nodes have completed and there are no timeout prompts.
