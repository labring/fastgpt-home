# Ledger Aggregation and Report Generation for Basic Telecommunications Operations: Tool Calling and Plugins

## What the data for this category looks like
The ledger data for basic telecommunications operations comes from billing systems, base station operation and maintenance systems, user service ticket repositories, and government and enterprise customer docking systems. Data update cycles cover real-time (billing traffic, call records), hourly (node load), and daily (inspection ledgers). Most documents use structured table format, with fields including base station unique identifier, traffic usage (unit: GB), call duration (unit: minutes), ticket number, processing status, statistical cycle, and affiliated area. Some ledgers also include inspection point photos in image format.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Automatically match multiple tools, sorted by data source priority | Basic telecommunications operation ledgers need to connect to multiple systems such as billing and operation and maintenance systems. Automatic matching reduces manual configuration costs |
| Single tool call entry limit | Top 2000 entries | Single ledger data volume is large. Limiting the number of entries avoids interface timeouts |
| Image processing plugin trigger rule | Automatically trigger when inspection ledger fields are detected | Only inspection ledgers include images. Triggering on demand reduces resource consumption |
| `functionCall` | Force specified structured output format | Ledger aggregation requires generating standard reports. Structured output ensures field completeness |
| Tool call timeout period | 600 seconds | Telecommunication interface data volume is large. 600 seconds covers most data pulling scenarios |
| Authentication method selection | Use application secrets, do not use account secrets | Telecommunication system interfaces mostly require application-level authentication, which can avoid call errors |

## Three common errors
- Symptom: Tool call returns an "authentication failed" error, prompting that an application secret must be used. Cause: Did not use the application secret as required by the configuration, and mistakenly filled an account secret into the authentication parameter.
- Symptom: API call workflow returns empty values, and no summary report is generated. Cause: Using a FastGPT version below v4.8.10. There are compatibility issues with API calls for workflow-nested knowledge base assistants.
- Symptom: Image paths are not replaced with remote links after tool call. Cause: Did not configure the trigger rule for the image processing plugin, or the trigger condition does not match the ledger fields.

## How to verify the configuration is complete
- Trigger a tool call test, check the authentication log to confirm that an application secret is used, and no account secret is used.
- Call an inspection ledger that includes images, check the output result to confirm that the image path has been replaced with a remote server link.
- Run the API call workflow, check the returned result to confirm that structured ledger aggregation data is included.
- Check the tool call running log to confirm that the number of entries per call meets the preset requirements.
