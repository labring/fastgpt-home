# Ledger Summary and Report Generation for Infrastructure Construction: Tool Calling and Plugins

This configuration guide applies to FastGPT v4.17.0.

## What This Category of Data Looks Like
Infrastructure construction ledger data comes from four primary sources: on-site construction logs, material site acceptance receipts, equipment shift logs, and subdivision project acceptance reports. Update rhythm follows construction progress. Corresponding ledgers are updated after a single batch of materials enters the site or a section of construction is completed. Each ledger document has eight fixed fields: unique project identifier, construction location, material name, specification and model, incoming quantity, incoming date, inspection personnel, and usage location. Units include engineering-specific measures such as tons, cubic meters, shifts, and square meters. Monthly or quarterly summary reports draw on individual ledgers, and include aggregated statistics and exception item descriptions.

## Constraints Imposed on Tool Calling and Plugins
Multi-source, dispersed infrastructure construction data requires tool calling to support multiple independent data source plugins. Single calls must not pull only one type of data. High-frequency updated ledger data requires tool call triggers to match construction progress nodes. Overly long cache periods should be avoided. Fixed fields and specialized units require tool calling parameter validation to cover field completeness and unit matching. Invalid data must be blocked from entering the summary process. Cross-data-source associated summary needs plugins to support data merging and format conversion. Final reports must conform to engineering document standards. Set `toolChoice` to auto to adapt to multi-data-source calling needs. No manual single tool specification is required.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapts to automatic routing requirements for multi-data-source tool calling, no need to manually specify a single tool |
| Tool call timeout | 1200 seconds | Handles time spent pulling construction, material, and equipment data across systems |
| Tool call retry count | 2 times | Balances single-call success rate and overall response time |
| `functionCall` | Enabled | Supports structured output of ledger summary fields, facilitating subsequent generation of standardized engineering reports |
| Plugin data cache duration | 86400 seconds | Matches the daily update rhythm of construction ledger data |
| Parameter validation switch | Enabled | Matches the fixed format of ledger fields and engineering-specific unit requirements |

## Three Common Misconfigurations
- Connection timeout and 504 status code occur when calling local MCP services. The intranet IP and port of the local service are not specified in plugin configuration. Default public network addresses are used instead, preventing connectivity.
- After tool calling is enabled, the model only returns tool call instructions. No thinking process is included. The "retain thinking chain after tool calling" interface setting is not enabled. Context is compressed, and intermediate thinking steps are skipped.
- Ledger summary results have missing fields or incorrect units. The parameter validation switch is not enabled. No field and unit matching checks are performed on pulled construction data. Invalid data is included in summary results.

## How to Verify Proper Configuration
- A tool call is manually triggered. The returned structured data is checked to confirm it includes all preset ledger fields, with units consistent with original data sources.
- The plugin management page is reviewed. Configured local MCP services are confirmed to show a normal connection status.
- Tool call logs are reviewed. Each call's timeout period and retry count are confirmed to match the preset configuration.
- A test summary report is generated. The result format is confirmed to conform to the standard structure of infrastructure construction engineering documents.
