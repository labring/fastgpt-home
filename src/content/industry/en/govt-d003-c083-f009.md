# Ledger Summary and Report Generation for Infrastructure Construction: Model Access and Configuration

## What the Data for This Category Looks Like
On-site construction ledger systems, material incoming inspection receipts, weekly progress reports, and supervision archived documents provide ledger data for infrastructure construction. Updates follow a set schedule: daily updates for construction progress, and weekly summaries of material consumption and milestone completion. Each ledger document includes structured fields and attached scanned copies. Fields cover project unique identifier, construction section name, material category, incoming quantity, inspection status, and process milestone number. Most units use engineering-specific measurement units such as tons, cubic meters, and labor hours.

## Constraints Imposed by These Characteristics on Model Access and Configuration
Configuring field mapping rules before model invocation prevents unit identification or value matching errors for infrastructure construction ledgers’ structured fields and specialized measurement units. Daily updated dynamic data causes context length fluctuations, requiring adaptation to summary requirements for multiple batches of ledgers. Scanned attachments from paper archives require models to support visual parsing capabilities. Limiting redundant logic in tool calls ensures the rigor of summary results for ledger content linked to multiple processes. These characteristics directly restrict the value ranges of core parameters such as context length, visual configuration, and tool call rules during model access.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Config Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Covers the text length of 5-10 structured ledgers and associated attachments in a single batch, adapts to multi-day summary requirements |
| `maxTokens` | 3500–4000 token | Limits the output length of a single engineering report, complies with conventional format requirements for infrastructure construction ledger reports |
| `quoteMaxToken` | 1200–1500 token | Restricts quoted ledger fields and numerical content, avoids irrelevant text interfering with summary logic |
| `vision` | enabled | Supports parsing scanned attachments of material incoming receipts and inspection receipts, adapts to digital processing of paper archived data |
| `temperature` | 0.2–0.4 | Maintains consistency of numerical values and fields in engineering data, avoids deviations that do not comply with measurement rules |
| `AIPROXY_API_TOKEN` | Fill in the private deployment exclusive key | Ensures interface call security, adapts to compliance requirements for state-owned enterprises and government scenarios |

## Three Common Misconfigurations
- Phenomenon: Attached scanned copies cannot be parsed correctly, and the model output does not mention the inspection quantity in the attachments. Cause: The `vision` configuration item is not enabled, or configuration parameters are not correctly synchronized to the model call link.
- Phenomenon: Ledger summary results generated by multiple calls have inconsistent values, with material quantity deviations. Cause: The `temperature` value is too high, causing random fluctuations in the model's judgment of engineering measurement values.
- Phenomenon: OneAPI forwarded model requests return a 401 unauthorized error. Cause: The `AIPROXY_API_TOKEN` is filled incorrectly, or the key permission does not cover the access scope of the current deployment environment.

## How to Verify Correct Configuration
- Upload a sample infrastructure construction ledger that includes structured fields and scanned attachments, check whether the model can correctly extract core fields such as material category and incoming quantity.
- Call the same ledger summary request three times consecutively, verify whether the output values and fields remain consistent.
- Check the OneAPI logs to confirm that the interface address and key of the model request match, with no 401 or timeout errors.
- View the context length statistics of model calls, confirm that it does not exceed the `maxContext` configuration range, and no key ledger content is truncated.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
