# Ledger Summary and Report Generation for Bulk Commodity Trading: Workflow Orchestration

## What the data for this category looks like
Bulk commodity trading ledger data originates from core business systems (purchase-sales contract management, fund settlement modules), port operation EDI messages, warehouse inbound and outbound documents, and customs declaration forms. Data updates trigger with business nodes, updating in real time after a single transaction is completed. The daily batch synchronization frequency is once per day. Most documents use structured table formats, with fields including transaction number, product category, specification model, unit of measurement (tons, barrels, cubic meters, etc.), purchase-sales unit price, transaction quantity, consignor and consignee information, settlement amount, and transaction time. Most field units relate to weight, volume, and similar categories, requiring alignment across systems.

## What constraints these characteristics impose on workflow orchestration
The pull order of multi-source heterogeneous data must be strictly bound to business logic. Settlement data depends on contract and logistics data, so pull nodes must be arranged in the contract → logistics → settlement sequence. The issue of inconsistent field units requires configuring standardized conversion rules in the workflow to convert units such as kilograms and barrels from different systems into a unified unit of measurement. Batch data synchronization requires setting a fixed time window to avoid business peak hours, preventing incomplete transaction data from being pulled. Report generation must support dynamic aggregation dimensions to adapt to viewing needs for different management levels such as monthly and quarterly cycles. The workflow must reserve configurable aggregation rule entry points.

## How to set the configuration
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |

| Global Variables | Preset transaction category and statistical cycle variables, pass dynamic parameters via `variables` | Adapt to dynamic requirements for generating monthly and quarterly reports for different categories |
| Workflow Timeout Threshold | 600 seconds | Bulk commodity ledger data pulling and aggregation take extended time, reserve sufficient execution time |
| Node Failure Retry Count | 3 times | Address data pull failures caused by temporary fluctuations in cross-system interfaces |
| Multi-source Data Node Order | Contract data → Logistics data → Settlement data | Follow the business dependency logic of bulk commodity trading ledgers |
| Log Collection Configuration | Enable full-link execution logs | Facilitate locating abnormal workflow links |
| Permission Control Configuration | Divide node access permissions by department | Match the sensitive data control requirements for bulk commodity trading data |

## Three common mistakes
- Symptom: After the workflow is saved successfully, refreshing the page shows that node configurations are lost. Cause: The global save operation was not completed, only the configuration of a single node was saved.
- Symptom: When calling the workflow via API, the passed global variables are not loaded normally. Cause: Variables were not passed in the required format via the `variables` parameter.
- Symptom: Some fields in the generated ledger report are empty. Cause: No field mapping rules for multi-source data were configured, resulting in inability to align data pulled from cross-systems.

## How to confirm the configuration is complete
- Manually trigger the workflow once, check whether data is pulled in the contract → logistics → settlement sequence in the execution log.
- Pass the preset transaction category and statistical cycle global variables, verify whether the workflow can adjust the report’s aggregation dimension based on the variables.
- Simulate an interface delay scenario, verify whether the node failure retry count of 3 times takes effect.
- Switch test accounts of different departments, confirm whether the permission configuration takes effect and whether the corresponding data nodes can be accessed normally.
