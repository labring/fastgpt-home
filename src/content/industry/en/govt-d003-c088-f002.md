# Engineering Consulting Supervision Ledger Summary and Report Generation: Vector Models and Indexes

## What data for this category looks like
Ledger data for engineering consulting supervision mainly comes from on-site supervision logs, material inspection reports, progress payment approval forms, rectification and closure records, and other project documents. The update rhythm follows the supervision cycle: daily ledgers are updated daily, and project completion ledgers are summarized periodically alongside individual project progress. Most documents use structured fields, including project number, supervision unit, inspection batch, pass rate, rectification completion time, and other fields. A small amount of unstructured handwritten or electronic annotations are attached. Common engineering units include square meters, tons, workdays, and others.

## What constraints do these characteristics impose on the vector models and indexes link
The high proportion of structured fields requires retaining field associations during chunking, avoiding splitting the core information of a single inspection report, and preventing loss of business associations during vector encoding. The diverse update rhythms require indexes to support both incremental trigger and full refresh modes, adapting to high-frequency updates of daily ledgers and batch summarization after project completion. The wide range of document lengths requires vector models to adapt to text encoding of different lengths, balancing encoding accuracy for short-field inspection forms and long-document supervision monthly reports. The strong project relevance of ledger data requires indexes to prioritize matching associated documents of the target project during recall, reducing interference from irrelevant historical data.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Most single-document ledgers for engineering consulting supervision are 500–2000 characters long. Excessively long chunking will lose field associations, while excessively short chunking will destroy the integrity of a single inspection form or log. |
| Overlap Length | 100–150 characters | Avoid splitting cross-chunk supervision rectification items and progress data, ensuring continuity of business logic. |
| `maxToken` | 4096 token | Adapt to vector encoding of most long documents such as supervision monthly reports, aligns with the default compatibility range of FastGPT v4.17.0. |
| Similarity Threshold | 0.72–0.85 | Distinguish valid ledger-associated data from irrelevant historical project data, meeting the precise recall requirements for supervision ledgers. |
| Single Search Limit | Top 8 entries | Cover 3–5 core ledgers commonly used under a single project, avoiding redundant recall affecting retrieval efficiency. |
| `defaultToken` | 1024 | Configure the basic token quota for single vector encoding, balancing the encoding efficiency of long documents and index tasks. |

## Three Common Misconfigurations
- Phenomenon: After upgrading the version, the same CSV file cannot be chunked normally, with the error prompt "Chunked text exceeds encoding limit". Cause: The `maxToken` parameter was not adjusted to adapt to the new vector model encoding rules, resulting in text of the original chunk length failing to be encoded correctly.
- Phenomenon: Knowledge base indexing is stuck, with no progress update for unfinished indexing tasks. Cause: Incremental indexing trigger rules were not configured, and a large number of historical ledger data was reloaded during full indexing, causing task blocking.
- Phenomenon: Non-target project ledger data is mixed in search results, with low recall accuracy. Cause: The similarity threshold was set too low, causing irrelevant historical project data to be mistakenly recalled.

## How to Confirm the Configuration Is Correct
- Upload a single supervision inspection form CSV, run a chunking test, check whether the chunking results retain complete inspection number and inspection batch fields.
- Start a full indexing task, observe whether `defaultToken`-related quota warnings appear in the background logs, confirm that the parameter configuration takes effect.
- Enter the search term "XX Project March 2024 Rectification Ledger", verify that the recall results only include documents related to the target project.
- Wait for the indexing to complete, incrementally upload new supervision logs, confirm that the indexing task can be triggered normally and complete the update.
