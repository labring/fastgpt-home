# Engineering Consulting Supervision Ledger Summary and Report Generation: Multi-turn Dialogue and Prompt Engineering

## What the data for this use case looks like
Engineering consulting supervision ledger data originates from on-site supervision walkthrough records, material acceptance receipts, sub-project acceptance reports, rectification review records, and other related documents. Data updates follow a daily cycle: daily on-site inspection records are synchronized to the ledger database. The structure of a single ledger document includes fields such as supervision unit, affiliated project name, sub-project name, inspection date, rectification item number, rectification content, rectification completion deadline, rectification result, inspector, and inspection conclusion. Most field units use standardized engineering terms such as "item", "day", "qualified/non-qualified".

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Ledger data is updated daily, so multi-turn dialogue context must be linked to the latest same-day data to avoid calling outdated historical records. Ledger fields are numerous and use engineering-specific standardized formats. Prompts must clearly specify the extraction order and units for each field. Otherwise, the large language model may miss key items or mix up units. Additionally, ledgers are archived by supervision project, so multi-turn dialogue must bind the context of the current project to avoid retrieving irrelevant ledger data across projects, which causes responses to deviate from the current supervision work scope.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, and are adapted to the engineering consulting supervision ledger business scenario.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window length | 8000–12000 characters | Matches the total content length of a single supervision project ledger, to avoid truncating key fields such as rectification items and inspection conclusions |
| Single search limit | Top 6 entries | Corresponds to the number of archived ledger documents for a single supervision project, to avoid retrieving redundant cross-project data |
| Custom prompt template | Calibrated based on actual testing | Clearly requires extraction of fixed ledger fields, to ensure unified formatting of generated summary reports |
| `chatId` binding | Enabled | Associates the dialogue context of the current supervision project, to avoid losing earlier project information in the second and subsequent dialogue turns |
| `variables` binding | Enabled | Binds business variables such as supervision project name and inspection date, to ensure prompts accurately match target ledgers |
| Maximum context refresh interval | 24 hours | Matches the daily update cycle of supervision ledgers, to ensure each call retrieves the latest same-day records |

## Three Common Configuration Mistakes
- Issue: Responses become irrelevant after the second dialogue turn, unable to link to earlier supervision project information. Cause: The `messages` parameter is not passed correctly, leading to dialogue context not being saved properly, with each call reset to the initial state.
- Issue: Generated reports lack exclusive fields such as rectification item number and inspector. Cause: No prompt template configured to meet engineering supervision requirements, and no clear specification of required ledger fields for extraction.
- Issue: Retrieved ledger documents come from other supervision projects, unrelated to current work. Cause: No project name filtering condition added to the prompt, leading to an expanded retrieval scope.

## How to Verify Proper Configuration
- Initiate the first dialogue, enter "View the rectification ledger for [XX] supervision project today, and record returned information such as rectification item number and rectification content.
- Initiate the second dialogue, enter "What is the inspection conclusion for the above rectification items?", and confirm that returned content is fully linked to the rectification items mentioned in the first dialogue.
- Check whether the generated summary report includes preset fields such as supervision unit, sub-project name, inspector, and inspection conclusion.
- Wait 24 hours, then initiate the same dialogue again, and confirm that returned rectification ledger is the latest same-day record.
