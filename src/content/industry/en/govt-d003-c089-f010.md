# Engineering Machinery Ledger Summary and Report Generation: Knowledge Base Retrieval and Recall

## What this category of data looks like
Engineering machinery ledger data mainly comes from enterprise internal equipment IoT platforms, maintenance work order systems, and original factory parameter manuals. It updates in real time after each single maintenance. Daily operating condition data updates every hour. Most documents use structured fields, including unique device code, model specification, manufacturing date, cumulative operating hours, single maintenance content, and fault troubleshooting records. Units include hours, liters, unit counts, etc. Some long-text records include on-site operating condition analysis and fault root cause descriptions.

## What constraints these characteristics impose on knowledge base retrieval and recall
Engineering machinery ledger data has numerous structured fields and includes unique device codes. Retrieval and recall must support both semantic matching and precise field matching to avoid device confusion from fuzzy matching. High data update frequency requires aligning knowledge base synchronization cycles with equipment maintenance rhythms to prevent recalling expired maintenance records. Single ledger documents contain long-text operating condition analysis and fault records. Set chunking rules appropriately to avoid incorrect association of content across devices. Time-series data such as cumulative operating hours must support filtering by time range to narrow recall scope and improve retrieval efficiency.

## How to set configurations
These configurations are formulated for FastGPT v4.17.0 to adapt to retrieval and recall needs of engineering machinery ledger knowledge bases:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches structured fields and semantic descriptions of engineering machinery ledgers, balancing recall accuracy and coverage |
| `limit` | Top 10 entries | Each device has many ledger data entries. Limiting recalled entries avoids context overflow |
| `searchMode` | hybrid | Supports both semantic retrieval and precise field matching, adapting to multi-dimensional queries for structured ledgers |
| `usingReRank` | Enabled | Rearranges recalled ledger entries by relevance, improving display priority of high-matching device data |
| `datasetSearchUsingExtensionQuery` | Disabled | Ledger data has a fixed structure. No need to expand query terms, avoiding irrelevant content |
| `collectionIds` | Specify the knowledge base collection ID corresponding to the device ledger | Isolates ledger data of different device groups, avoiding cross-group recall |

## Three common errors
- Phenomenon: No copy button for the chunk ID field in the knowledge base details page. Users cannot copy the identifier directly. Reason: FastGPT versions prior to v4.17.0 hide the ID copy control by default. It does not adapt to batch management needs of ledger-type data.
- Phenomenon: Retrieval results mix ledger content of other engineering machinery models. Reason: The target knowledge base collection is not limited via the `collectionIds` configuration. This results in recall of cross-group data.
- Phenomenon: The number of ledger entries returned by a single retrieval is insufficient to cover summary requirements. Reason: The `limit` parameter is set too low. It fails to match the number of recall entries required for ledger summary.

## How to confirm the configuration is properly set
- Enter the FastGPT knowledge base management page. Verify that the collection ID configured in `collectionIds` matches the target engineering machinery ledger knowledge base.
- Initiate a test query containing a specific device model. Check whether the returned results only include ledger data of the corresponding device.
- Check the relevance ranking of retrieval results. Confirm that high-matching entries are displayed first, and verify that the `usingReRank` function is active.
- Copy any chunk ID. Confirm that the copy button is displayed on the page, and verify that the interactive configuration is correct.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
