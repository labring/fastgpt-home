# Ledger Summary and Report Generation for Construction Machinery: Deployment and Upgrade

## What this category’s data looks like
Ledger data for construction machinery mainly comes from equipment management systems, in-vehicle IoT sensors, and offline operation and maintenance logs. The update rhythm falls into three categories: in-vehicle sensors report real-time data such as operating hours and fuel consumption; operation and maintenance logs update maintenance records daily; monthly ledger summary reports are generated manually or automatically by administrators. Core fields of a single ledger document include unique equipment number, model specification, manufacturing date, cumulative operating hours, number of faults in the last 30 days, and maintenance cycle. Units are respectively unit, hour, incident, day, and others. Some fields must match the standard parameter format set at equipment manufacturing.

## What constraints these characteristics impose on deployment and upgrade
Because data sources are scattered and update frequencies vary widely, configure multiple data source synchronization tasks during deployment. Support three access methods: IoT protocol, CSV-formatted operation and maintenance report files, and direct database connection.
Because fields have fixed units and format requirements, retain original field mapping rules during upgrades to avoid damaging imported historical ledger data.
Because some data is synchronized in real time, configure a caching mechanism during deployment to ensure query speed. Verify synchronization consistency between the cache and database after upgrading.
Additionally, the volume of construction machinery ledger data continues to grow as equipment scale expands. Plan storage capacity in advance during deployment, and support format migration of existing data during upgrades.

## Configuration Parameters
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:your_redis_pwd@your_host:6379/1` | Cache real-time equipment operating data; use database 1 to isolate business cache from other system caches |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | Store Excel files exported from ledgers and operation and maintenance log attachments; compatible with private storage deployments |
| `DB_MAX_LINK` | `15–25` | Limit the number of concurrent database connections, adapted to the single-instance load of construction machinery ledger databases |
| Multi-account permission configuration | Enable role groups, set two levels of permissions: operation and maintenance / administrator | Meet the division of labor requirements for multiple operation and maintenance personnel to upload ledger materials and generate reports |
| `FILE_TOKEN_KEY` | Random 32-character sequence | Ensure timeliness and access security of ledger export links |
| `FE_DOMAIN` | `https://your-enterprise-gpt.com` | Configure the front-end application access domain name, unify the access entry for the ledger summary tool |

## Three Common Mistakes
- Symptom: No ledger data is returned after Docker deployment, and logs show database connection timeout. Cause: The `DB_MAX_LINK` parameter is not configured correctly, and the number of concurrent connections exceeds the database limit, causing request blocking.
- Symptom: Permission conflicts occur when multiple accounts upload ledger materials, and knowledge base content cannot be shared. Cause: Role group configuration is not enabled, and only the default single-account permission is used.
- Symptom: The Excel file exported from the ledger cannot be downloaded normally, and a signature error is prompted. Cause: The `FILE_TOKEN_KEY` configuration value has insufficient length or incorrect format, causing token verification failure.

## How to Confirm Configuration is Complete
- Run the built-in database connection test script to verify the connection status of `REDIS_URL` and `PG_URL`, and confirm there are no timeout errors.
- Upload a standard-format construction machinery ledger Excel file, check whether fields such as equipment number and operating hours can be parsed correctly, and there are no format errors.
- Create a ledger summary application, attempt to generate a monthly report, and confirm that cached real-time operating data and historical ledger data can be called.
- Configure multi-account testing, log in with different role accounts, and check whether knowledge base and ledger data with corresponding permissions can be accessed.
