# Ledger Summary and Report Generation for Refined Petroleum Product Sales: Tool Calling and Plugins

## What the data for this category looks like
Ledger data for refined petroleum product sales primarily originates from offline gas station POS terminals, oil tank inventory management systems, and enterprise ERP sales modules. Updates follow two rhythms: real-time reporting for single-site transactions, and daily updates for batch summary data. Documents use structured CSV or JSON formats. Each ledger entry includes fields such as fuel grade, transaction time, transaction volume (unit: liters or tons), sales unit price, actual received amount, payment channel, and associated site code. Some ledgers include auxiliary records of oil tank liquid level fluctuations.

## Constraints imposed by these characteristics on tool calling and plugins
Since ledger data has two update modes—real-time transactions and batch summaries—tool calling must support both synchronous triggering and asynchronous pulling scenarios. Transaction volume uses two units, liters and tons, so plugins must include built-in unit mapping rules to prevent unit confusion in generated reports. Single-batch data volume increases with the number of operating sites, so tool calling must configure pagination parameters to avoid single requests exceeding interface load limits. Fields vary slightly across different sites, so tool calling parameters must support dynamic field mapping to ensure complete data retrieval.

## Three Common Configuration Errors
- Symptom: Importing the HTTP plugin and calling the refined petroleum product sales API returns a 400 status code. Cause: The Content-Type request header was not correctly set to application/json, so the API cannot recognize the request format.
- Symptom: Application call results are directly output to the chat interface, and not used as context for the large language model. Cause: The direct output switch for tool calling was not disabled, so tool return results do not enter the context window.
- Symptom: Detailed tool calling records for the application cannot be viewed in the chat details page. Cause: The workflow log storage switch was not enabled, so intermediate tool call information is not saved.

## How to Verify Correct Configuration
- Manually trigger a tool call, check if the returned ledger data fields cover core business information, and verify field matching accuracy.
- Review tool call log details, confirm that request parameters and format comply with the refined petroleum product sales API documentation requirements, with no format errors.
- Send an API call request, check if returned results include intermediate tool call steps and ledger summary data, confirm the context is correctly loaded.
- Test the unit conversion function, verify that transaction volumes in different units are uniformly converted to the standard unit required for reports.
