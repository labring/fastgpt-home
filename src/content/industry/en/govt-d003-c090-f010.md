# Ledger Summary and Report Generation for Refined Petroleum Product Sales: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Refined petroleum product sales ledger data primarily comes from gas station POS terminals, oil tank level monitoring equipment, and inventory management systems. Data is synced in real time for individual transactions. Inventory ledgers are updated after daily inventory counts, and monthly operating summary ledgers are generated at the end of each month. Individual transaction ledgers include transaction serial number, fuel grade, sales volume, actual received amount, and transaction time fields. Inventory ledgers include oil tank number, initial inventory, outbound volume, and ending inventory fields, with units of liters, yuan, and metric tons.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
The multi-field, high-frequency update, and granular entry characteristics of refined petroleum product sales ledgers create three constraints for retrieval and recall. First, precise matching of structured fields such as fuel grade and transaction time is required to avoid recalling irrelevant inventory or other category ledger records. Second, monthly summary ledgers need to recall transaction data from the past 30 days, and the number of recalled entries must match the monthly transaction volume of a single gas station. Third, real-time updated transaction data requires a knowledge base sync cycle of no more than 1 hour, otherwise recalled data will be delayed, affecting the accuracy of ledger summary.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches precise fields such as fuel grade and transaction time to avoid recalling low-relevance non-target ledgers |
| `limit` | `Top 200 entries` | Matches the average daily transaction volume of around 150 entries per station, covering the 30-day transaction data required for monthly summaries |
| `searchMode` | `keyword + vector` | Balances keyword matching for structured fields and semantic relevance, adapting to the mixed retrieval needs of ledgers |
| `usingReRank` | `Enabled` | Filters redundant entries in recall results to ensure only valid ledger data is retained during summary |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands synonyms for fuel grades to cover possible different user expressions, such as matching 92# with 92 octane gasoline |
| `collectionIds` | `Specify the dedicated collection ID for refined petroleum product sales ledgers` | Isolates knowledge base data from other categories to avoid mixing in irrelevant administrative or inventory ledgers |

## Three Common Misconfigurations
- Symptom: When calling the `api/v1/chat/completions` interface, specifying a knowledge base tag fails to recall target refined petroleum product sales ledger data, and the returned result is empty or contains irrelevant content. Cause: The `collectionIds` parameter was not passed correctly, or the parameter format does not meet the interface requirements of FastGPT v4.17.0.
- Symptom: Retrieval results cannot be filtered by fields such as oil tank number or fuel grade, only returning generalized semantic matching results. Cause: Structured field retrieval configuration was not enabled, only pure semantic retrieval mode was used, and the recall logic was not optimized for the structured fields of ledgers.
- Symptom: Newly uploaded daily transaction ledgers in the knowledge base are not recalled and cannot participate in the same day's ledger summary. Cause: The knowledge base sync cycle was set too long, failing to match the real-time update rhythm of refined petroleum product sales data.

## How to Confirm the Configuration is Correct
- Access the FastGPT v4.17.0 backend, navigate to the management page of the target knowledge base, and verify whether `collectionIds` only contains the dedicated collection ID for refined petroleum product sales ledgers.
- Enter a query containing specific fuel grade and transaction time range to initiate retrieval, and verify whether the fields of the recalled results match the structure of refined petroleum product sales ledgers.
- View the knowledge base sync logs to confirm that newly uploaded ledger data can complete index updates within the set cycle.
- After enabling the `usingReRank` function, verify the proportion of redundant entries in the retrieval results to ensure only valid ledger data is retained.
