# Building Engineering General Contracting Account Summary and Report Generation: Database and Operations

## What the data for this category looks like
Account book data for building engineering general contracting primarily comes from on-site construction logs, material purchase and warehousing receipts, weekly progress reports, subcontract settlement documents, and similar sources. Data update frequency varies based on business nodes. Daily incoming materials and construction progress data are updated daily. Monthly settlement and annual review data are updated via periodic summarized updates. Each individual account book document includes fields such as project number, construction building, material specification, incoming quantity, tax-included unit price, incoming date, and inspection personnel. Units include commonly used engineering measurement standards such as cubic meters, tons, square meters, and yuan.

## What constraints do these characteristics impose on the database and operations link
Building engineering account books have multi-source, heterogeneous origins, requiring the database to support batch import of multi-format data and incremental synchronization to avoid errors from manual entry. Differences in update rhythms require configuring scheduled tasks to trigger data summaries daily, weekly, or monthly, while ensuring real-time incoming data does not conflict with periodically summarized data. The diversity of fields and units requires the database to have built-in field verification rules, automatically identifying and converting commonly used engineering measurement units to avoid unit mismatch issues during statistics. The massive historical account book data generated by long project cycles requires the database to store data partitioned by project number and time dimension, splitting data blocks to improve query and operation efficiency and avoid performance degradation caused by overly large single tables.

| `MONGODB_URI` | `mongodb://username:password@host:port/fastgpt?authSource=admin&replicaSet=rs0` | Building engineering account book data volume is large, using a replica set improves read/write availability and adapts to concurrent requirements for multi-source data synchronization |

| Database connection timeout period | 600 seconds | Adapts to long-cycle account book summary tasks, avoiding connection interruptions caused by overly long task execution times |

## Three Common Misconfigurations
- Phenomenon: When deploying FastGPT via Docker and running account book synchronization tasks, logs show `connection timed out` errors, and the interface displays abnormal database connections. Cause: The database connection timeout parameter is not configured, and long-idle connections are disconnected by the host firewall or cloud service provider security group.
- Phenomenon: After upgrading from an older version to FastGPT v4.17.0, previously uploaded account book data is not displayed in the knowledge base. Cause: The database migration script was not executed, the storage structure of account book data differs between old and new versions, and field mapping was not completed.
- Phenomenon: When creating a new account book classification node, an error occurs when using the default AI model, and normal operation resumes after switching to another model. Cause: The context window of the default AI model is too small to accommodate the long text of account book field content, resulting in request timeout and truncation.

## How to Confirm Proper Configuration
- Run the database connection test script to verify that the connections configured via `MONGODB_URI` and `PG_URL` are normal, with no timeout errors.
- Submit a simulated building engineering account book data entry, check that it can be stored correctly and measurement units are automatically converted.
- Trigger a monthly account book summary task, check that the task execution log has no errors such as connection abnormalities or field mismatches.
- Check that the refresh frequency of cached account book statistical data meets the preset business cycle requirements.
