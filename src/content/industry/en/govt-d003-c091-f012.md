# General Contracting for Building Construction: Ledger Summary and Report Generation - Deployment and Upgrade

## What the data for this category looks like
Ledger data for general contracting of building construction comes from on-site project construction management systems, material purchase ledgers, labor attendance records, and safety inspection archives. Core entries are synced daily, and summary reports are generated monthly. Each ledger document includes fields such as project number, section name, material category, incoming quantity, acceptance date, construction team, rectification closure status, and others. Incoming quantity units are cubic meters, tons, or man-days. Report documents are aggregated by section or month, and include itemized statistics and progress deviation analysis.

## Constraints imposed by these characteristics during deployment and upgrade
Data sources are scattered, and field formats vary across systems. Adaptation rules for multi-source data access must be configured during deployment. The daily sync update rhythm requires that the scheduled task execution interval of the deployment matches the sync cycle to avoid data lag or duplicate sync. The aggregation logic for monthly summary reports must correspond to the ledger classification fields. During upgrades, compatibility with original aggregation rules must be maintained to prevent unexpected changes to generated report formats. Ledger fields include multi-unit measurement items. Unit conversion mapping rules must be configured during deployment to prevent deviations caused by unit confusion during statistics.

## Configuration Recommendations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom_password@redis_deployment_address:6379/0` | Building construction ledger data requires high-frequency read/write operations. Redis as a cache needs a stable connection. Use database 0 to isolate business data and avoid conflicts with other services. |
| `MONGODB_URI` | `mongodb://username:password@mongo_deployment_address:27017/fastgpt?authSource=admin` | Ledger and report documents require unstructured storage. MongoDB supports multi-field aggregate queries to meet the statistical logic of monthly summaries. |
| `DB_MAX_LINK` | `20–30 connections` | Building construction project ledger data volume is large, and there are many concurrent sync tasks. This connection number range ensures stable service operation and avoids connection exhaustion. |
| `ROOT_KEY` | `32-character random string` | Ensures the security of the system administrator account, prevents triggering the built-in password reset mechanism by using the default key. |
| `FILE_TOKEN_KEY` | `16-character random string` | Used for signature verification of file uploads, ensures access security of ledger attachments. |
| `STORAGE_S3_ENDPOINT` | `project-specific object storage address` | Archived reports need to be stored in dedicated object storage to adapt to file distribution and access requirements for multiple projects. |

## Three Common Misconfigurations
- Incorrect configuration of `REDIS_URL` during deployment, resulting in container image pull failure or service connection timeout errors. The cause is failure to correctly fill in the Redis authentication password and database number, leading to image pull or service connection failure.
- `{"code":500,"message":"URI malformed` error appears after upgrade. The cause is incorrect connection string format for `MONGODB_URI` or `PG_URL`, failure to correctly add authentication source or port parameters.
- The system administrator account password is reset to the default value daily after operation. The cause is failure to correctly configure the `ROOT_KEY` parameter, using the default fixed FastGPT key, triggering the built-in default password reset mechanism.

## How to Verify Successful Configuration
- Run `docker-compose up -d`, wait 300 seconds, then use the `docker ps` command to check the running status of all containers, confirm that Redis, MongoDB, and the FastGPT main service are all operating normally.
- Log in to the system backend, enter the administrator settings page, verify that the custom key configured for `ROOT_KEY` is effective, avoid using the default key.
- Manually trigger a ledger sync task, check the task log to confirm that data sync is successful, with no connection timeout or format error prompts.
- Generate a monthly summary report, confirm that the ledger fields and units included in the report match the source data, with no statistical deviations.
