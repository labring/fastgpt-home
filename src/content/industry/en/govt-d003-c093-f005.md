# Ledger Summary and Report Generation for Government and Enterprise IT Services: Tool Calling and Plugins

## What the Data for This Category Looks Like
Ledger data for government and enterprise IT services is sourced from multiple channels including internal government and enterprise operation and maintenance systems, project management platforms, and offline inspection records. Data update cycles cover three categories: daily (for operation and maintenance inspection ledgers), weekly (for project progress ledgers), and monthly (for annual summary ledgers). Each ledger document includes fields such as device ID, operation and maintenance time, fault type, processing result, responsible person, and response duration. Fields contain enumerated values and clear units. Document formats are primarily Word, Excel, and structured JSON.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Workflow
Multi-source heterogeneous ledger data requires that tool calling be configured with multi-data source adapters to adapt to the API formats and permission rules of different systems. Ledger data with different update cycles requires that tool calling support both scheduled triggering and on-demand pulling modes. Ledger fields include enumerated values and units, so plugins must preset field verification rules to prevent invalid data from entering the summary process. Compliance requirements for government and enterprise data require that tool calling be bound with identity credentials to ensure only authorized users can trigger data pulling and report generation. Report generation requires batch processing of multi-source data, so tools must support result merging and format conversion.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling mode | Set `toolChoice` to `auto` | Adapt to the automatic matching needs of multi-source ledger data |
| Function call parameter verification | Enabled | Match the enumerated value and unit rules of ledger fields |
| Global variable passing | Enable workflow global variable injection | Meet the requirement of passing identity credentials during MCP tool calling |
| Tool timeout setting | 600–1200 seconds | Adapt to the time consumption of multi-data source pulling and long document summary |
| Single data pull limit | 50 entries | Avoid timeouts triggered by excessive data volume in a single call |
| Result merging rule | Group and summarize by device ID | Align with the conventional statistical logic of government and enterprise ledger reports |

## Three Common Mistakes
- Calling the FastGPT application API returns missing context, with a status code of 400. Cause: The context passing parameter for `functionCall` is not configured, causing tool calling to fail to retain session state.
- The token field in the input parameters of MCP tool calling is empty, making data source authentication impossible. Cause: The workflow global variable injection configuration is not enabled, and global variables are not bound to tool calling parameters.
- The number of ledger results returned by tool calling does not match expectations, only a single entry is returned. Cause: The single data pull limit parameter is not configured, and the tool triggers a single-entry data request by default.

## How to Confirm the Configuration Is Correct
- Test calling the tool to pull a single ledger entry, verify that the returned fields match the preset enumerated values and unit rules.
- Trigger the workflow to call the MCP tool, check whether the tool input parameters include global variable identity credentials.
- Submit a multi-source data summary task, verify that the final report completes group merging according to the preset rules.
- View the tool calling logs in FastGPT v4.17.0, confirm that the timeout setting matches the actual time consumption range.
