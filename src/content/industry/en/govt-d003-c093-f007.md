# Ledger Summary and Report Generation for Government and Enterprise IT Services: Database and Operations

## What This Category’s Data Looks Like
Data is sourced from internal business operation and maintenance systems and customer service ticket systems for government and enterprise communication services, updated at ticket completion nodes or fixed daily time periods. Each ledger document includes structured fields such as ticket ID, communication device number, service execution time, issue type, processing result, and associated customer filing number. These fields use string, numeric code, standard time format, enumerated text, status identifier, and filing number format as their respective data types and units. Some documents also include unstructured attachments such as ticket processing photos or audio files.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | MongoDB instance connection string pointing to unstructured government and enterprise ledger data, including authentication information | Stores unstructured attachments such as ticket photos and audio, isolating data from other business systems |
| `PG_URL` | PostgreSQL instance connection string pointing to structured government and enterprise ledger data, configured with a read-only account | Stores structured fields such as ticket ID and device number; a read-only account reduces the risk of data tampering |
| `DB_MAX_LINK` | 10–20 | Adapts to the concurrent summary and real-time query requirements of government and enterprise ledgers, balancing connection resources and response speed |
| `REDIS_URL` | Connection string pointing to a local Redis instance, with cache expiration time set to 15 minutes | Caches frequently queried ledger summary results to reduce repeated database access overhead |
| Synchronization Trigger Configuration | Dual mode: ticket completion node and daily scheduled task | Adapts to both emergency ticket and daily batch update data update scenarios |
| Data Index Configuration | Create B-tree indexes for ticket ID and device number fields | Accelerates summary queries for structured fields, reducing response latency |

## Three Common Misconfigurations
- Workflow stalls after a tool call node executes, with no error logs returned. Cause: No access whitelist for the government and enterprise-specific database is configured, causing the database connection to be blocked by the instance firewall, and no response is returned after the connection request times out.
- Database connection function is abnormal after starting the container, and mongoose dependencies cannot be found via npm list during troubleshooting. Cause: FastGPT uses pre-built container images, with dependency packages already integrated into the image layer. The node_modules folder is not generated in the local directory of the running container, so local npm commands cannot be used to query the version.
- Unable to connect to domestic database instances, with an unsupported database type prompt. Cause: No driver dependencies for the corresponding domestic database are configured. FastGPT only supports general-purpose relational and document databases by default, and domestic database adaptation packages need to be added manually.

## How to Confirm Successful Configuration
- Connection requests from the FastGPT service IP may be reviewed through the database management backend, and the account permissions configured in the connection string can be verified for correct matching.
- A ledger summary test task may be run, and prompts for successful field mapping and completed data pulling in the task logs can be checked. No abnormal errors indicate successful configuration.
- The connection status of the Redis cache instance can be checked, and automatic cleanup of cache key-value pairs according to the configured expiration time can be verified.
- Database index status can be reviewed, and confirmation that indexes for ticket ID and device number have been successfully created and activated can be obtained.
