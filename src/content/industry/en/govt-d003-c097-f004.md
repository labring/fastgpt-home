# Ledger Summary and Report Generation for Nuclear Power Operations: Workflow Orchestration

## What the Data for This Category Looks Like
Nuclear power operation ledger data mainly comes from reactor operation parameter collection systems, equipment inspection systems, radiation monitoring systems, and fuel management systems. Data update rhythms fall into three categories: operation parameter data updates in real time, inspection ledgers update daily, and fuel inventory data updates monthly. Individual ledger documents use a structured format, containing fields such as equipment ID, measurement point number, monitoring value, corresponding unit, collection time, inspection or operator ID, and others. The temperature unit is Kelvin, the radiation dose unit is microsievert, and ledger numbers follow the rule of fixed prefix plus date plus serial number.

## Constraints Imposed by These Characteristics on Workflow Orchestration
Nuclear power operation ledgers have numerous structured fields and strict unit requirements. This requires workflows to accurately match field names and units during the data extraction stage, avoiding field misalignment caused by general text extraction. The update frequencies of different ledger types vary widely, so workflows must support both scheduled trigger and real-time trigger modes to adapt to batch summary and emergency reporting scenarios. Ledger numbering rules are fixed, so report file names generated by workflows must follow the corresponding rules to facilitate subsequent archiving and retrieval. The data volume of a single batch of ledgers is large, so the number of items processed in a single run must be limited to avoid workflow timeouts or excessive resource consumption.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `variables` | Include three fields: equipment ID, collection time range, ledger type | Nuclear power operation ledgers need to be filtered and summarized by equipment and time range; variables can pass filter conditions between workflow nodes |
| `nodeId` | Bind the data extraction node ID as ext_001, and the report generation node ID as gen_002 | Accurately locate each link's node to avoid incorrect module calls during FastGPT v4.17.0 workflow execution |
| Trigger Mode | Scheduled task trigger (00:00 daily) + real-time data push trigger | Covers requirements for daily batch summary and emergency abnormal ledger reporting |
| Single Batch Data Processing Limit | Top 1000 entries | The data volume of a single batch of nuclear power ledgers is large; limiting the number of entries avoids workflow timeouts |
| Timeout Threshold | 600 seconds | Nuclear power data processing takes a long time; 600 seconds covers most batch summary scenarios |
| Unit Verification Switch | Enabled | Nuclear power data has strict unit requirements; verification can avoid unit mixing issues in summary results |

## Three Common Misconfigurations
- Phenomenon: The tool call module in the workflow does not execute, and the node status shows "Not Triggered". Cause: The equipment ID parameter is not correctly configured in `variables`, causing the tool to fail to match the corresponding nuclear power ledger data source.
- Phenomenon: The generated summary report has missing fields or incorrect units. Cause: The role of `variables` is not clarified, the ledger fields to be extracted are not added to the variable list, and the unit verification switch is not enabled.
- Phenomenon: Multiple AI conversation nodes cannot execute in parallel and can only run serially. Cause: No parallel trigger rules are configured in the workflow, and serial dependency relationships between nodes are incorrectly set.

## How to Verify Correct Configuration
The workflow is manually triggered, node logs are checked, and parameters in `variables` are confirmed to be correctly passed to the data extraction and report generation nodes.
The return results of the tool call module are reviewed, confirming that the equipment ID, monitoring value, unit and other fields of the nuclear power ledger are correctly extracted, with no field misalignment or unit errors.
The scheduled task is started, and verification is performed to confirm whether the report generated the next day is stored in the preset path and contains the ledger data of the current day.
Two parallel AI conversation nodes are configured, the test function of FastGPT v4.17.0 is used, and verification is performed to confirm whether the workflow executes the two nodes simultaneously without serial waiting.
