# Nuclear Power Plant Operations: Ledger Consolidation and Report Generation - Document Parsing and Chunking

## What This Category of Data Looks Like
Nuclear power plant operation ledger data primarily originates from documents including reactor operation logs, equipment inspection records, radiation monitoring reports, consumable issuance ledgers, safety validation reports, and more. Data updates follow a tiered schedule by shift, daily, and weekly: operation logs are updated per shift, inspection records are updated daily, and monthly consolidated ledgers are generated weekly. Most documents are in PDF format, containing a large number of structured tables. Fixed fields include equipment number, operating parameters, inspection time, anomaly records, consumable usage, and others. Units include professional metering identifiers such as MPa, ℃, mSv, kg. Some inspection records are in scanned image format, requiring OCR to extract text.

## What Constraints These Characteristics Impose on Document Parsing and Chunking
Structured tables and professional metering fields in nuclear power plant ledgers require that chunking must not disrupt data association. Otherwise, parameter matching errors will occur during subsequent consolidation. Scanned inspection records require additional OCR parsing capabilities, otherwise valid fields cannot be extracted. Large monthly consolidated ledgers can reach hundreds of pages per file, with large file sizes, placing high requirements on upload and parsing stability. Real-time updated operation logs require fast parsing and chunking to avoid delays that affect subsequent report generation. Fixed professional fields and units require that chunking preserves field integrity, and the same set of parameters must not be split across different chunks.

## How to Configure Settings
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the single-page field density of nuclear power plant ledgers, avoids splitting professional parameter units, and ensures the integrity of each data group |
| `chunkSplitter` | Split by header/footer + table boundaries | Matches the structured layout of ledgers, preserves field association within tables, and prevents cross-chunk parameter misalignment |
| `customPdfParse` | Enable table recognition mode | Adapts to tabular documents such as inspection reports and operation logs, restores the layout and content of original fields, and avoids OCR recognition confusion |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to multi-page PDF files for monthly consolidation, prevents upload interruptions or offset errors triggered by exceeding the default limit |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses the time requirements of large file parsing, prevents timeout failures caused by excessively long parsing times |
| `chunkSettingMode` | Manual mode | Adjusts chunking rules for nuclear power professional documents to match business field structures, avoids unreasonable truncation from automatic chunking |

## Three Common Configuration Mistakes
- When uploading large PDF files, the parsing progress reaches 90% with an "offset out of range" error. This occurs because the `UPLOAD_FILE_MAX_SIZE` parameter is not adjusted, and segment verification exceptions are triggered after exceeding the default limit.
- Equipment operating parameters are split across different chunks in the chunking result. This occurs because `chunkSplitter` is not configured to split by table boundaries, and professional data is only truncated by fixed character counts, causing parameter groups to be broken.
- Files uploaded via the create file collection API have inconsistent chunking compared to files uploaded directly through the platform. This occurs because the `chunkSettingMode` configuration is not unified, and the API uses the automatic chunking mode by default, which does not match the manual configuration on the platform.

## How to Verify Proper Configuration
- A sample nuclear power plant monthly ledger PDF of the same type may be uploaded. The parsed chunk list is checked, and confirmation is made that each chunk contains a complete single group of equipment operating parameters or inspection records.
- A single PDF file of no less than 500 MB may be tested for upload. Confirmation is made that the upload progress has no abnormal interruptions and no offset-related errors.
- The chunking results of the same file uploaded via the API and directly through the platform are compared, and confirmation is made that the chunking rules are consistent for both.
- A large file parsing task is triggered, and confirmation is made that the parsing time does not exceed the configured `PARSE_FILE_TIMEOUT_SECONDS` threshold.

Note: The configuration values listed above are common starting points. Adjustments should be made based on specific samples.
