# Ledger Summary and Report Generation for Oilfield Engineering Services: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Ledger data for oilfield engineering services comes primarily from four core document types: on-site construction logs, equipment inspection records, material requisition slips, and process acceptance reports. Data updates align with construction milestones, with immediate entry after a single job is completed, and daily aggregation to generate project-level ledgers. Each ledger document includes fields such as construction number, equipment model, operation duration, material consumption, and acceptance result. Units include hours, cubic meters, tons, qualified/non-qualified, and others. Fields are dynamically adjusted based on job type, with no unified fixed template.

## Constraints for Multi-turn Dialogue and Prompt Engineering
The multi-field and dynamic format requirements of oilfield ledgers mean multi-turn dialogue must lock the context of the current job project to avoid mixing data across batches. Frequently updated real-time data requires dialogue context to synchronize newly entered ledger content in a timely manner, to avoid referencing outdated information. Differences in fields across job types require prompts to explicitly specify the current job link associated with the dialogue, otherwise field matching errors are likely to occur. Splitting and retrieval of long documents must retain field associations, otherwise the binding relationship between equipment models and corresponding inspection records will be lost. The `messages` array for multi-turn dialogue must store each round of questions and replies in order, to ensure the accuracy of context transmission.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 characters | Single project-level ledger can reach thousands of characters, need to retain job batch and equipment information across multi-turn dialogue |
| Variable preset | Bind construction project ID and job type variables | Distinguish ledger data across different projects to avoid interference from cross-project data |
| Question optimization toggle | Enabled | Oilfield ledger fields are complex, optimizing questions can clearly point to required specific fields and document types |
| Single dialogue retrieval count | Top 6 entries | Match latest ledger records under the same project, control context redundancy |
| Knowledge base chunk overlap length | 200–300 characters | Retain the association between equipment models and inspection records when splitting long ledger documents, avoid field breakage |
| Single dialogue timeout setting | 300 seconds | Prevent session interruption during long ledger summary and report generation |

This configuration is based on FastGPT v4.17.0.

## Three Common Misconfigurations
- A 401 No auth credentials found error is returned. The cause is that the project-specific authorization identifier was not passed in `variables`, causing failure of knowledge base access permission verification.
- The generated report mixes ledger data from other construction projects. The cause is that the construction project ID variable was not preset, and the multi-turn dialogue did not lock the job batch associated with the current session.
- The generated report is missing key fields such as operation duration or material consumption. The cause is that the question optimization toggle was not enabled, and the user's question did not explicitly specify the required ledger fields, causing the system's retrieved documents to not cover the target fields.

## How to Verify Correct Configuration
- Initiate a question that includes the specified construction project ID, check whether the dialogue context always associates with the ledger data of that project.
- Trigger multi-turn follow-up questions, confirm that the system can correctly track the equipment model and operation duration fields mentioned in the previous round.
- Lock the exclusive context of the current session via `chatId`, verify that the question and reply association logic within the session works normally.
- View the variable preset items in the configuration interface, confirm that the project identification variable dedicated to oilfield engineering services has been bound.
- Test retrieval after splitting long documents, confirm that key fields are not truncated and their association relationships are not lost.

The values provided are common starting points and should be measured against the reader's own samples.
