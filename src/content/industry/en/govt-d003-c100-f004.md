# Oilfield Engineering Service Ledger Summary and Report Generation: Workflow Orchestration

## What the Data for This Category Looks Like
Oilfield engineering service data primarily comes from on-site construction terminals, wellsite sensors, and project ERP systems. It covers daily ledgers for processes including drilling, cementing, and fracturing. Data update frequencies range from real-time reported construction parameters to daily summarized team ledgers.
Each ledger document includes fields such as well ID, construction process, operation time, team information, material consumption, and operating pressure value. Material usage is measured in tons and cubic meters. Construction duration is measured in hours.
Summary reports integrate multi-process ledger data on a monthly or quarterly basis to form structured report files.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The multi-source heterogeneous data features of oilfield engineering services require workflow orchestration to support parallel pulling of ledger data from different data sources across multiple nodes. This avoids process delays caused by serial pulling.
Inconsistent field units require built-in standardization steps in the workflow. These steps unify material usage and duration data from different sources into preset units.
High-frequency updates of real-time construction parameters require the workflow to support both scheduled triggering and event triggering modes. This matches the update rhythms of different ledgers.
Large file sizes of summary reports require workflow nodes to support chunked processing and large file transfer configurations. This prevents transmission timeouts or parsing failures.

## How to Set the Configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Include two core variables: well ID and operation cycle | Oilfield engineering service ledgers use well ID and operation cycle as core filtering conditions, which can be dynamically passed when the workflow starts |
| Trigger Mode | Dual mode: scheduled triggering + event triggering, set scheduled triggering to every 24 hours | Matches different update rhythms of real-time construction parameters and daily summarized ledgers, covering full and incremental data pulling requirements |
| File Upload Node Size Limit | 1000 MB | Monthly summary reports for oilfield engineering services typically have large file sizes, reserving sufficient space to prevent transmission interruptions |
| Parameter Standardization Rules | Unit mapping rules calibrated through actual measurements | Adapts to unit differences such as tons, cubic meters, and hours across data sources, ensuring consistency of summarized data |
| `nodeId` | Assign a unique identifier to each data source node | Facilitates locating abnormal nodes during workflow debugging, quickly troubleshooting issues with multi-source data pulling |
| Request Retry Count | 3 times | Addresses failures to pull sensor data caused by on-site network fluctuations, avoiding process interruptions from single request errors |

## Three Common Misconfigurations
- Symptom: When configuring form-data type parameters for workflow HTTP request nodes, on-site collected construction ledger files fail to send successfully. Cause: The parameter type is not set to file stream format, only the local file path is passed.
- Symptom: A Load file error pop-up appears during the workflow's file summary execution phase. Cause: The uploaded ledger file format does not meet structured requirements, or the file is corrupted during cross-node transmission.
- Symptom: In a local deployment environment, after uploading a monthly summary ledger file, the file parsing node has no execution records. Cause: The file storage directory permissions of the deployment environment are insufficient, preventing the node from reading the uploaded file, or the parsing node's triggering rules are not bound to the corresponding file upload event.

## How to Verify the Configuration is Properly Set
- Manually pass preset well ID and operation cycle variables, check if each data source node can correctly pull corresponding ledger data.
- Trigger workflow execution, view the running logs of each node, confirm there are no abnormal errors in file transfer and parameter standardization steps.
- Compare the summary report output by the workflow with the original ledger data, confirm that field units and data entries meet expectations.
- Simulate an on-site sensor data upload event, check if the workflow in event triggering mode can automatically start and pull real-time data.
