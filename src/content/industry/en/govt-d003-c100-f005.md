# Oilfield Engineering Services Ledger Summary and Report Generation: Tool Calling and Plugins

## What constraints do these characteristics impose on the tool calling and plugins workflow
Oilfield engineering service ledger data is distributed across multiple field terminals and backend systems. Tool calling requires integration with different data source plugins, and permission verification rules for cross-system data pulling must be configured. Each ledger document has numerous fields and specific unit requirements, so preset field verification logic must be added to plugin inputs to prevent non-compliant unit values from entering the summary process. For multi-well joint operations, batch calls to ledger APIs are necessary, so the number of jobs per single call must be limited to avoid interface concurrency overload. Data updates occur at a high frequency, so a reasonable cache duration must be configured for tool calls to balance data freshness and call efficiency.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic calling needs for multiple data source plugins, no manual specification of individual functions required |
| Batch call limit | First 20 job ledgers | Matches the conventional scale of single-batch oilfield operations, prevents interface concurrency overload |
| Field verification switch | Enabled | Complies with oilfield ledger field and unit compliance requirements, filters invalid input values |
| Timeout threshold | 600 seconds | Covers cross-system data pulling delays, prevents mid-call interruptions |
| Result cache duration | 12 hours | Matches the daily update rhythm of oilfield job ledgers, balances data freshness and call efficiency |

## Three common errors
- Phenomenon: When not using tool calling mode, the ledger summary returned by the large model does not include the latest on-site data, while web search nodes can normally return public information. Cause: The non-tool calling mode lacks a bound data source plugin configuration, so it cannot pull private ledger data from internal oilfield systems.
- Phenomenon: After a plugin is published, new plugin entries do not appear in the community marketplace. Cause: The plugin’s category tags and compatible version information were not filled out correctly, and the plugin failed to pass the platform’s review and verification.
- Phenomenon: Predefined variables cannot be selected in the JSON input box. Cause: The variable binding switch was not enabled in the plugin’s JSON input configuration, so the system cannot recognize replaceable variable placeholders.

## How to confirm successful configuration
- Initiate a tool calling request for a single well ledger, and verify that the returned data fields and units match the internal oilfield reporting format.
- Trigger a batch call test, and check that the number of returned jobs matches the preset batch call limit.
- Simulate a timeout scenario, and verify that the system triggers a retry or error prompt after exceeding the timeout threshold.
- Check the marketplace display status of the published plugin, and confirm that the category tags and version information match the platform requirements.
