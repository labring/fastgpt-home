# Port and Shipping Ledger Summary and Report Generation: Workflow Orchestration

## What the data for this category looks like
Port and shipping ledger data primarily comes from terminal operation management systems, vessel scheduling platforms, customs declaration systems, and port machinery operation logs. Update frequency varies by operation area: Vessel berthing and departure ledgers are updated in real time. Cargo loading and unloading ledgers are updated per operation batch. Fee settlement ledgers are summarized per daily shift. A single ledger document has a multi-table association structure. Core fields include vessel name, IMO number, cargo loading and unloading volume (unit: tons), operation duration (unit: hours), berth number, and work team ID. Field formats are fixed, and association relationships are clear. The workflow configuration for this scenario uses FastGPT v4.17.0.

## What constraints these characteristics impose on workflow orchestration
The differing update frequencies of multi-source data require workflows to support event triggering, to adapt to the push timing of different data sources. The multi-table association structure requires workflows to first run a data association node, to merge ledger data from different systems. Fixed core field formats require workflows to have dedicated validation rules, to prevent invalid data from entering the summary process. The large data scale per shift requires workflows to have batch fetching and merging nodes, to prevent memory overflow. The real-time nature of port operations requires workflows to support resuming from breakpoints, to avoid full process interruption from a single timeout.

## How to set the configuration
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind the knowledge base ID and port area parameters passed by the API | Supports dynamically switching business knowledge bases for different port areas, adapting to multi-port area scheduling scenarios |
| `nodeId` | Bind the node ID of the vessel berthing and departure event | Triggers the workflow according to actual operation events, matching the real-time scheduling logic of port operations |
| Timeout setting | 600 seconds | Port ledger data fetching involves multiple system interfaces, reserving sufficient response time |
| Field validation rules | Validate that vessel name and cargo loading and unloading volume fields are not empty and match the unit | Prevents invalid data from entering subsequent summary processes |
| Single data fetch limit | Top 200 entries | Adapts to the data scale of single-shift port operations, preventing memory overflow |
| Rich text rendering switch | Enabled | Supports normal rendering of audio and video tags, adapting to the multimedia requirements of report generation |

## Three common misconfigurations
- Manually entered `<video>` tags in the workflow are rendered as plain text instead of playback components. This occurs because the rich text parsing switch is not enabled in the advanced settings of the reply node, and the default setting only renders plain text content.
- When configuring a knowledge base search node, referencing the API-passed knowledge base ID via `variables` returns no search results after running. This occurs because the reference parameter is not pre-declared in the global variable configuration of the workflow, causing the variable to fail to parse correctly.
- The text content extraction node returns empty results with a format error prompt. This occurs because dedicated extraction rules are not configured for the field formats of port ledgers (such as IMO numbers and tonnage units), and general extraction rules cannot match specific fields.

## How to confirm the configuration is correct
- Trigger a test workflow and view node logs to confirm that the knowledge base ID and port area parameters bound by `variables` are read correctly.
- Run the field validation node, input simulated port ledger data, and confirm that the non-empty field and unit validation rules trigger normally.
- View the output of the final report node to confirm that audio and video tags are correctly rendered as rich text components.
- Check the node connection relationships of the workflow to confirm that the trigger event bound via `nodeId` is correctly associated with the event callbacks of the port operation system.
