# Port and Shipping Industry Ledger Summary and Report Generation: Tool Calling and Plugins

## What the Data for This Category Looks Like
Port and shipping ledger data primarily comes from port operation management systems, vessel scheduling platforms, freight forwarding systems, and customs declaration systems. Data updates follow operational workflow progress. Single-vessel ledgers are updated in real time after a single berth operation is completed. Full port area daily operation ledgers are summarized each day.
Each ledger document includes structured fields such as vessel IMO number, berthing and departure times, total cargo loading and unloading volume (unit: tons), container throughput (unit: TEU), work team number, individual operation fees, and customs verification number. Some attachments include operation images and declaration scan files.

## What Constraints These Characteristics Impose on Tool Calling and Plugin Processes
The multi-source heterogeneous data sources of port and shipping ledgers require tool calling to support integration with multiple heterogeneous system APIs. A unified field mapping rule must be configured to adapt to the return formats of different systems.
Real-time updated operation data requires tool calling timeout periods to match operational workflow cycles. This prevents reduced summary efficiency from waiting for outdated data.
Fields include specific units (tons, TEU). Unit verification rules must be enforced during tool calling to prevent unit confusion during ledger summary.
Single-ledger attachments include operation images. A plugin node that supports file parsing must be configured to extract associated metadata for report generation.
The data volume growth brought by port area operation scale requires limiting the number of entries returned by a single tool call. This avoids context window overflow.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic routing for multi-source data, matching the multi-system integration needs of port ledgers |
| Field mapping rules | Map to standard formats including vessel IMO number, berthing time, total cargo loading and unloading volume (tons), container throughput (TEU) | Unifies the field structures returned by different systems, preventing field misalignment during summary |
| Timeout period | 300–600 seconds | Matches the average processing cycle of a single berth operation at a port, avoiding call failures due to system response delays |
| Return entry limit | Top 20 entries | Adapts to the typical volume of daily operation ledgers for a single port area, avoiding context window overflow |
| Unit verification switch | Enabled | Enforces unit consistency checks for cargo loading and unloading volume and container throughput, complying with port and shipping field specifications |
| Attachment parsing configuration | Enable PDF/image parsing plugins | Extracts metadata from declaration scan files and operation images, supplementing ledger report content |

## Three Common Misconfigurations
- Symptom: A `Your model may not support tool_call SyntaxError` error is returned when calling the tool. Cause: `functionCall` support is not enabled in the FastGPT tool configuration, or the selected large language model does not have tool calling permissions enabled.
- Symptom: After exporting a workflow and a JSON file, plugin nodes fail to load normally when imported across environments. Cause: Local configuration and permission binding information for the plugin was not included during export, and the plugin's API key and access path were not reconfigured after cross-environment import.
- Symptom: Undefined `Human <Instruction>` fields appear in the results returned by tool calls. Cause: The tool calling format in the system prompt was not correctly configured in the workflow, causing the large language model to generate non-compliant intermediate instructions.

## How to Verify Proper Configuration
- Initiate a single tool call, and verify that the returned fields fully match the preset mapping rules.
- Check the tool call timeout logs to confirm that no call interruptions occurred due to timeout.
- Verify the attachment parsing results returned by the plugin to confirm that the metadata required for the ledger is included.
- Trigger the complete ledger summary process in the workflow test panel of FastGPT v4.17.0, and confirm that the report generation includes complete fields and attachment information.
