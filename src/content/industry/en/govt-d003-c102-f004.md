# Ledger Summary and Report Generation for Refinery and Chemical Production: Workflow Orchestration

## What data for this category looks like
Ledger data for refinery and chemical production comes from three main sources: Distributed Control Systems (DCS), team patrol inspection systems, and production report management systems. Data updates follow three rhythms: real-time process parameters, shift team ledgers, and monthly summary reports.

Single ledger documents are structured by production unit, shift, and statistical date. Core fields include unit number, operating temperature, system pressure, material flow, patrol point anomaly records, and energy consumption data. Each field uses fixed units, with no extra redundant nested fields.

## Constraints imposed by these characteristics on workflow orchestration
High-frequency updates of real-time process parameters require workflow node trigger intervals to match data refresh rhythms. This avoids delayed summarization or repeated data pulling.

Field differences across multi-source heterogeneous data require pre-configured format alignment steps in the workflow. These steps unify field naming rules across different systems.

Monthly summary scenarios require pulling historical data across cycles. Cycle-type parameters must be bound in the workflow.

Fixed units for fields require built-in unit verification logic in the workflow. This prevents summarization errors caused by mismatched units from different sources.

Single ledger entries have large data volumes. The workflow must limit the document shard size processed per node. This avoids memory overflow.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Variable group `variables` | Bind unit number, statistical cycle, data source identifier | Match the query requirements of refinery ledgers categorized by unit and cycle, to accurately pull the corresponding data sources |
| Trigger interval | 10–30 seconds | Adapt to the refresh rhythm of real-time process parameters, avoid repeated pulling or delayed processing |
| Document shard size | 800–1200 characters | Adapt to the length of single refinery ledger entries, balance processing efficiency and memory usage |
| Node timeout threshold | 600 seconds | Cover the time requirements of cross-data-source pulling and multi-round model calls, avoid mid-execution interruptions |
| Context retention rounds | First 3 rounds | Refinery ledger data structure is fixed, no excessive historical conversations are required to complete the summarization logic, reducing model call overhead |
| Target node `nodeId` | Bind to report generation node | Ensure the workflow execution order follows the logic chain of refinery ledger summarization, avoid node misalignment |

## Three Common Configuration Mistakes
- Phenomenon: When accessing the workflow multiple times with the same business ID, the context returned by the first AI model node retains only one round, but context residue appears in subsequent calls. Cause: The `variables` parameter is not configured to reset the session context in the workflow, so session state across requests is not cleared.
- Phenomenon: After configuring a custom file reading address, the workflow cannot read local ledger files. Cause: The file storage path is not added to FastGPT's allowed access whitelist, or environment variable configurations are not synchronized to all deployment nodes.
- Phenomenon: An error is returned when using the document parsing tool in the workflow to parse an uploaded file address. Cause: The file upload node is not enabled first in the workflow, or the file address is not correctly passed to the input parameters of the document parsing tool.

## How to Confirm Configuration is Complete
- View the workflow's trigger configuration, confirm that the trigger interval matches the data refresh rhythm. Check whether node trigger times meet expectations via logs.
- Test cross-cycle data pulling, enter different cycle parameters, confirm that the workflow can pull ledger data for the corresponding time period.
- Simulate multiple request accesses, trigger the workflow multiple times with the same business ID, confirm that the context state of each request is independent.
- Verify the file upload and parsing process, upload refinery and chemical production ledger files, confirm that the parsed fields match the preset configuration.
