# Ledger Summary and Report Generation for Refinery and Chemical Production: Tool Calling and Plugins

## What this category of data looks like
Ledger data for refinery and chemical production mainly comes from three core data sources: distributed control system (DCS), tank farm metering system, and laboratory information management system (LIMS) in the laboratory. Data is updated per production shift, with one ledger document generated per shift. Each document includes fields such as unit number, material name, operating temperature, pressure, flow rate, test results, ledger number, and shift team information. Temperature is measured in degrees Celsius, pressure in megapascals, flow rate in cubic meters per hour, and timestamps are precise to the second.

## What constraints these characteristics impose on tool calling and plugins
Multi-source heterogeneous data sources require tool calling plugins to support simultaneous connection to three interfaces: DCS, tank farm metering system, and lab LIMS. This avoids missing data.
The shift-based update rhythm requires plugin call frequency to match production scheduling. This prevents pulling duplicate or expired data.
Differences in field units require plugins to include built-in unit conversion rules. This unifies output formats for summarization.
The fixed field structure requires precise filter conditions when calling tools. Only return valid data for the current shift to reduce redundant information occupying context.

## Three Common Mistakes
- Phenomenon: Tool call results include input and response fields from knowledge base search. Cause: The non-tool-call knowledge base retrieval switch was not turned off in the workflow, causing the system to trigger knowledge base retrieval by default.
- Phenomenon: No response when clicking confirm when creating a plugin from CURL. Cause: The copied CURL content lacks request headers or has incorrect parameter formatting, and the complete plugin configuration import was not completed.
- Phenomenon: Numeric type parameter transfer fails when calling the MCP client. Cause: Numeric fields were not explicitly declared as numeric types, and default string format transfer caused interface parsing errors.

## How to Confirm Correct Configuration
- Use the workflow editor of FastGPT v4.17.0 to run a test workflow, and check that the fields returned by the tool call match the configured refinery and chemical ledger fields.
- View workflow logs to confirm that no knowledge base retrieval-related input and response records appear.
- Verify the CURL-imported plugin configuration to confirm that all request parameters have been loaded correctly.
- Test the transfer of numeric type parameters to confirm that no type errors appear in the call results.
