# Coal Chemical Industry Ledger Summary and Report Generation: Tool Calling and Plugins

## What the data for this category looks like
Coal chemical industry ledger data primarily comes from three sources: the real-time collection system of production plant DCS, offline test reports from coal quality laboratories, and metering documents from storage and transportation links. Data updates are triggered by production process nodes. Full ledger entries are generated when shift handover occurs or a single production batch concludes. Documents use structured table format, with fields including equipment number, material parameters, operating parameters, and timestamp. Field units include millimeters, degrees Celsius, cubic meters per hour, tons, and other relevant units. There are no redundant fields from standard general ledgers, and all fields are tightly bound to coal chemical production workflows. This tool calling configuration is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
1.  Data updates at fixed production nodes. Tool calling trigger logic must bind to preset nodes such as shift handover and post-shift summary. It cannot support randomly triggered calling scenarios.
2.  Specialized fields such as coal mill outlet temperature and coal particle size entering the furnace use different units than standard general ledgers. Plugin parameter parsing rules require preset coal chemical-specific field mappings to prevent parsing errors.
3.  A single ledger entry contains dozens of structured fields. The single data pull limit for tool calls must match this scale to avoid model context overload.
4.  Ledger data is sourced from multiple connected systems. Plugin data source configuration must support cross-system data pulling.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-tool linkage requirements, automatically select ledger pulling, data verification, and report generation tools |
| `functionCall` | Call according to the preset function list | Fixed call to three dedicated functions: coal chemical ledger pulling, parameter verification, and report generation |
| Tool calling trigger timing | Bind to the post-shift summary node | Match the update rhythm of coal chemical ledgers, avoid pulling incomplete temporary data |
| Data source pull limit | 50 records per batch | Adapt to the field scale of a single ledger, avoid context overflow |
| Parameter parsing rules | Enable coal chemical-specific field mapping | Adapt to units and meanings of specialized fields such as coal particle size entering the furnace and coal mill temperature |
| Context length limit | 8000 token | Adapt to text length after multi-ledger summary, avoid model truncation |

## Three Common Misconfigurations
- Tool calls return an "invalid API Key" error or no response. Cause: Confused global general API Key with workflow-specific API Key, and did not use the key configuration bound to the workflow.
- Generated reports include input and output logs from knowledge base searches. Cause: Did not disable non-essential log output in workflow configuration, or the tool call chain did not filter knowledge base-related context.
- Plugin configuration imported via CURL cannot click the confirm button. Cause: Did not correctly fill in the request headers and parameter format in the CURL, or did not match FastGPT's plugin interface specifications.

## How to Confirm Successful Configuration
- Trigger the preset post-shift summary node, and check if the tool automatically pulls ledger data for the corresponding batch.
- Review workflow run logs to confirm no knowledge base search input and output fields are present.
- Import plugin configuration in CURL format, and confirm the interface displays the "Save Successful" prompt.
- After calling the tool, check if returned parameters match the specialized fields and units of coal chemical ledgers.
