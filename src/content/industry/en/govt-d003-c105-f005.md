# Coal Transportation and Sales Ledger Summary and Report Generation: Tool Calling and Plugins

## What the data for this use case looks like
Multiple business systems supply coal transportation and sales ledger data, including weighing systems, coal quality test reports, railway shipping vouchers, and internal settlement systems. Single shipping order data generates in real time. Daily summaries compile into daily operation ledgers, while monthly summaries create full-cycle sales ledgers.

Document structure splits into two categories: single shipping order details and summary ledgers. Single details include fields such as shipping time, mine site name, coal type, low heating value, ash content, shipping volume (unit: ton), consignee name, freight amount, and settlement status. Summary ledgers aggregate data by grouping on time cycle and coal type.

Most fields are professional business parameters. Single data entries have small volume, but aggregated data volume grows with the statistical cycle.

## What constraints these characteristics create for tool calling and plugins
Since data comes from multiple heterogeneous business systems, the tool calling link must connect to multiple independent data source interfaces. Configure access permissions and field mapping rules for each data source in advance to ensure accurate data extraction.

Professional business fields such as coal type, heating value, and shipping volume require tool calling function definitions to strictly match business field enumerations and value ranges. This prevents the model from generating invalid parameters that cause call failures.

Daily and monthly ledger summary needs require tool calling to support batch data processing. Control single call data volume to avoid request timeouts or exceeding interface capacity limits.

The report generation link requires tools to return structured data. Group tool call results by business dimension to enable subsequent formatted display and report splicing.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Allow the model to independently select tools suitable for coal transportation and sales ledgers, covering multi-data-source calling requirements |
| Single tool call data limit | First 150 shipping order records | Adapt to the reasonable data volume of a single batch ledger, avoiding single request timeouts |
| Timeout period | 600 seconds | Cover the processing duration of batch ledger summary and multi-data-source splicing |
| `functionCall` | Enable parameter validation | Match the professional field rules of coal transportation and sales such as coal type, heating value, and shipping volume |
| Result cache duration | 12–24 hours | Match the daily ledger update frequency, reducing repeated call overhead |
| Tool call result formatting | Group by shipping order dimension | Adapt to the structured display requirements for report generation |

## Three Common Configuration Errors
- Symptom: Missing fields in ledger data returned by tool calls. Cause: No dedicated field mapping rules for coal transportation and sales are configured, so business fields returned by data sources are not correctly extracted.
- Symptom: Initial tool calls work normally, but errors occur when entering multiple shipping order records. Cause: Single tool call data limit is set too high, triggering interface rate limiting or timeouts.
- Symptom: Disorganized coal type parameters appear in generated reports. Cause: Function call parameter validation is not enabled, so model-generated coal type parameters fall outside the business enumeration range.

## How to Verify Correct Configuration
- Submit a test request containing single shipping order information, and check whether the tool correctly calls and returns matching business fields.
- Input batch shipping order data, and confirm that the number of results returned by the tool call matches the set single data limit.
- Review tool call logs to confirm that the parameter validation link correctly blocks requests that violate business rules.
- Wait 12–24 hours before submitting another request, and check whether the cache updates normally and returns the latest ledger data.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
