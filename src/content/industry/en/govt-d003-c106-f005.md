# Coal-Electric Integration Ledger Aggregation and Report Generation: Tool Calling and Plugins

## What the data for this category looks like
Coal-electric integration ledger data comes from fully mechanized coal mining, tunneling, and coal preparation systems at coal mines, as well as power plant operation monitoring, fuel management, and desulfurization and denitrification monitoring systems. Update frequency varies by module: the system updates excavation ledgers per work shift, fuel dispatch ledgers hourly, and power generation and coal preparation ledgers daily. Single ledger documents have a multi-dimensional nested structure, including fields such as operation date, equipment ID, core parameter values, operator information, and exception records. Corresponding units for these fields include tons, megawatt-hours, kilojoules per kilogram, operating hours, and others.

## What constraints these characteristics impose on the tool calling and plugin workflow
The multi-dimensional nested ledger structure requires plugins to support multi-field associated queries. Plugins cannot retrieve complete linked data for equipment, parameters, and exceptions using only a single keyword. Data sources with different update schedules require plugins to use differentiated call intervals. Plugins for excavation class real-time data use a 15-minute call interval, and plugins for daily data use a 24-hour call interval. This setup prevents repeated pulls of outdated data or missed real-time updated parameters. Plugins must automatically verify unit consistency after calling for fields with multiple units, to prevent report errors caused by cross-unit calculations. Plugins must support paginated pulling for large data volumes during batch pulls of monthly aggregated ledgers, to avoid exceeding the interface's carrying limit with a single request.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts automatic multi-tool scheduling to cover call requirements for different coal-electric ledger data sources |
| `functionCall` | `enabled` | Enables structured function calls to ensure accuracy and standardization of coal-electric ledger field extraction |
| Plugin timeout setting | `300-600 seconds` | Covers time requirements for batch pulling multiple data sources, adapting to batch query scenarios for coal-electric integration data |
| Tool call retry count | `2 times` | Avoids call failures caused by temporary network fluctuations, while reducing unnecessary resource consumption |
| Result verification switch | `enabled` | Verifies units and formats of ledger fields, matching standardized requirements for coal-electric integration data |
| Context association scope | `previous 3 historical call records` | Avoids tool calling logic confusion caused by redundant context, ensuring coherence of report generation |

## Three common mistakes
- Phenomenon: Calling a custom coal power data interface returns a 408 status code, and logs show request timeout. Cause: The timeout setting was not adjusted according to the batch pulling requirements of coal-electric integration data sources, and the default timeout duration is insufficient.
- Phenomenon: Ledger fields extracted after tool calling are empty, and corresponding reports cannot be generated. Cause: The result verification switch was not enabled, and field unit adaptation was not performed, causing eligible coal-electric data to be filtered out.
- Phenomenon: The function call configuration entry cannot be found in the interface. Cause: The tool calling module was not enabled in the application settings of FastGPT v4.17.0; this module is hidden by default.

## How to confirm the configuration is complete
- Enter the tool management page of the application, confirm that the custom coal power data interface plugin has been added and enabled.
- Test calling the ledger tool for a single device, check whether the returned results include the preset core coal power fields and match the units.
- Simulate generating a monthly aggregated report, check whether the tool call logs show normal request and response durations with no timeout errors.
- After adjusting the timeout setting, verify that no abnormal errors occur when pulling ledgers for multiple devices in batches.
