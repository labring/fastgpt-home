# Coal-Electric Integration: Ledger Summary and Report Generation - Deployment and Upgrade

## What the data for this category looks like
Coal-electric integration ledger data sources cover production monitoring systems, equipment operation logs, energy consumption statistics reports, procurement and warehousing documents across the entire process of coal mining, washing, transportation, and power generation. Update frequency is once per shift or once per day. Some key equipment operation ledgers are updated in real time. The document structure includes multi-dimensional structured fields and unstructured content. Structured fields such as coal calorific value, power generation, coal consumption, equipment operating hours, etc., are included with corresponding units of measurement. Unstructured content includes inspection reports, maintenance records, monthly summary reports, and similar materials.

## What constraints these characteristics impose on deployment and upgrades
Coal-electric integration ledger data covers the entire process and has complex fields. Sufficient database connection pools and storage resources must be configured during deployment to support multi-dimensional queries. Ledgers updated at high frequency require near-real-time index synchronization. During upgrades, the knowledge base index mechanism must be compatible with existing data update rhythms to avoid index lag. Parsing and storing large unstructured documents requires configuring upload and processing parameters adapted to large files to prevent upload interruptions. Cross-link ledger associated queries require stable cache services to support high-frequency access and avoid service interruptions during upgrades.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | Multi-link queries for coal-electric ledgers are frequent, to avoid exhausting database connection pools |
| `MONGODB_URI` | Full connection address of the local MongoDB instance, including username and password | Stores structured metadata and index information for ledgers, to ensure query efficiency |
| `REDIS_URL` | Local Redis instance address on port 6379 | Caches high-frequency query results for ledgers and user session information, to reduce database load |
| Chunk Length | `800–1200 characters` | Adapts to the long-text structure of multi-field coal-electric ledgers, preserves contextual association |
| Single Search Limit | `Top 10 entries` | Coal-electric ledger fields have high relevance, the top 10 entries cover the required summary information |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Ensures access security for uploaded ledger files, prevents unauthorized access |

## Three common mistakes
- Symptom: After Docker deployment, accessing the address corresponding to `FE_DOMAIN` returns no response, with a connection timeout error. Cause: `MONGODB_URI` or `REDIS_URL` is not configured correctly, causing the backend service to fail to start required database connections.
- Symptom: A version update prompt pop-up appears every time a new conversation is opened. Cause: The version update prompt switch is not disabled in the configuration during deployment, or front-end static resources are not synchronized updated after upgrade.
- Symptom: When creating a new knowledge base, there are no optional configuration items for the image indexing model, and no corresponding index can be generated after uploading image-based ledgers. Cause: The locally deployed FastGPT has not loaded the extended dependencies related to image indexing, or `STORAGE_S3_ENDPOINT` is not configured correctly to support image file storage.

## How to confirm the configuration is correct
- Run the database connection test command included with FastGPT v4.17.0 to verify that the address, port, and permissions configured for `MONGODB_URI` and `REDIS_URL` are correct.
- Upload a coal-electric equipment image ledger smaller than 10MB, confirm that the upload is successful and can be previewed in the knowledge base.
- Initiate a ledger summary query, confirm that the number of returned results matches the configured single search limit.
- Open a new conversation window, confirm that the version update prompt pop-up no longer appears.

The values provided here are common starting points, and should be measured against the reader's own samples.
