# Power Grid Enterprise Ledger Summary and Report Generation: Tool Calling and Plugins

## What the data for this category looks like
Power grid enterprise ledger data originates from multiple internal business systems including dispatching automation systems, marketing business systems, and operation and maintenance inspection platforms. Real-time inspection ledgers update on a minute-level cycle, marketing ledgers are updated daily, and monthly summary ledgers are generated monthly. A single ledger document includes fields such as unique device identifier, installation location, operating parameter value, inspection time, and responsible team. Operating parameter units include professional power industry units such as kilovolts, amperes, and megapascals. The field order and required items vary across different types of ledgers.

## What constraints these characteristics impose on the tool calling and plugins workflow
The presence of multi-system data sources requires the tool calling link to connect to multiple plugins simultaneously. Ledgers with different update frequencies need to match corresponding calling intervals. Professional units and differentiated field structures require the tool calling process to unify return formats, to avoid field mismatch issues during summary. Real-time ledger calls have higher response time requirements; overly long timeout settings will reduce overall summary efficiency. For batch calls of monthly ledgers, the number of tools per single request must be controlled to prevent exceeding system load limits.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` and enable multi-tool mode | Supports calling multiple MCP plugins in sequence for a single query, adapting to multi-data-source ledger summary requirements |
| `functionCall` | Enable mandatory format validation | Ensures tool return results meet the structured field requirements of power grid ledgers, facilitating subsequent report generation |
| Maximum tools per single call | 3 | Controls the load of parallel requests, adapting to the concurrent call limits of internal power grid systems |
| Tool call timeout period | 60-120 seconds | Matches the average response time of power grid system interfaces, avoiding interruption of the summary process due to wait timeouts |
| Field mapping rules | Map device ID, operating parameters, and inspection time according to power industry ledger standards | Unifies return formats across different data sources, eliminating summary errors caused by field differences |

## Three Common Misconfigurations
- Phenomenon: After initiating a multi-ledger summary query, only some tools are triggered, and the remaining tools do not execute. Cause: The calling sequence is not configured according to the multi-tool mode of `toolChoice`, causing the tool queue to fail to load correctly.
- Phenomenon: After upgrading fastgpt-mcp-server, FastGPT fails to start normally and prompts a service connection failure. Cause: The MCP service address and port parameters in the plugin configuration are not updated, resulting in a mismatch between the new and old version service addresses.
- Phenomenon: Operating parameter units are mixed in the generated report, such as kilovolts and watts being used together. Cause: No field mapping rules are configured, and non-standard unit fields from original data sources are directly used for summary.

## How to Confirm Successful Configuration
- Initiate a test query that includes two types of ledgers: substation operation and maintenance, and transmission lines. Check the tool call logs to confirm that the MCP plugins for the corresponding data sources are triggered in sequence.
- Check the `toolChoice` parameter in the tool call configuration to confirm that multi-tool mode is enabled, and verify that the `functionCall` format validation switch is turned on.
- Upload a standard power grid ledger sample to test the field mapping rules, confirming that core fields such as device ID and operating parameters can be correctly identified and extracted.
- Simulate an upgrade of the MCP service, restart FastGPT, and test the tool connection status, confirming that the configured service address and port match the currently deployed MCP service.
