# Power Grid Enterprise Ledger Summary and Report Generation: Document Parsing and Chunking

## What the data for this category looks like
Power grid enterprise ledger data mainly comes from SCADA monitoring systems, marketing business platforms, and operation and maintenance overhaul management systems. Updates run daily or per single job cycle. Common document formats include multi-page PDF overhaul reports, Excel equipment ledgers, and internal network Confluence operation and maintenance manuals. Fields include equipment unique ID, rated voltage level, single overhaul duration, and operation and maintenance consumable costs. Units include kilovolts, hours, yuan and other power industry-specific units.

## Constraints imposed on document parsing and chunking
Multi-page long PDF overhaul reports and annual reports can reach thousands of pages per copy. These files consume significant parsing and chunking resources, so adaptation to large file processing limits is required. Internal network operation and maintenance manuals are stored on the enterprise Confluence platform, and cannot be accessed via public network parsing links. This requires configuration of internal network access adaptation rules. Excel ledgers contain associated fields such as equipment numbers and voltage levels. Chunking must retain cell row and column association structures to avoid splitting that breaks field relevance. Daily updated job ledger data has high timeliness requirements. Chunking processing must match short synchronization cycles.

## Configuration Settings
This configuration logic is based on FastGPT v4.17.0. The specific parameter configurations are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Power grid ledgers contain multi-field associated content. This range preserves the field integrity of a single ledger entry and avoids splitting that breaks business relevance |
| `chunkSplitter` | Chunk by title + paragraph | Power grid documents are mostly structured by chapters and equipment entries. Chunking by title preserves business logic coherence |
| `customPdfParse` | Enabled | Power grid PDF documents often contain embedded tables and formulas. Enabling custom parsing preserves table structure and field correspondence |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Single annual reports can reach thousands of pages. This setting adapts to large file upload requirements, and covers most scenarios based on actual measurements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing thousands of pages of PDF documents takes a long time. This duration prevents mid-parsing timeouts for large files |
| `chunkSettingMode` | Manual configuration | Power grid ledger fields and structures have industry-specific characteristics. Manual configuration enables precise matching of business requirements |

## Three Common Configuration Mistakes
- Scenario: Parent-child chunking mode is not enabled when configuring chunking rules. Nested equipment ledger entries are split into multiple independent chunks, and hierarchical associations cannot be preserved. Cause: The nested hierarchical structure of power grid documents is not adapted to, and the default chunking logic does not recognize parent-child entry relationships.
- Scenario: Attempting to parse enterprise internal network Confluence pages fails to retrieve content, and public network parsing links return empty results. Cause: Internal network access adaptation rules are not configured, and the default parsing link only supports public network address access.
- Scenario: When uploading thousands of pages of PDF annual reports, parsing progress stalls and returns a timeout error. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default duration is insufficient to complete parsing and chunking of thousands of pages of documents.

## How to Verify Successful Configuration
- Upload a power grid Excel ledger with fewer than 100 pages. Check if parsed chunks retain the association between equipment numbers and corresponding overhaul records. Adjust `chunkSize` based on business requirements.
- Upload a Confluence page link in the internal network environment. Confirm that operation and maintenance entry content from the page can be extracted after parsing. Adjust the parsing link based on internal network access configuration.
- Upload a 500-page PDF overhaul report. Check if parsing progress completes within the preset duration. Adjust `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` based on file size.
- Review chunked text content. Confirm that nested equipment hierarchical entries are correctly merged. Adjust the chunking rules for `chunkSplitter` based on business structure.
