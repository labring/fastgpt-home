# Grid Enterprise Ledger Summary and Report Generation: Model Access and Configuration

## What Data for This Category Looks Like
Grid enterprise ledger data comes from multiple business systems including SCADA monitoring systems, grid marketing systems, and equipment operation and maintenance management systems. Data update cadence falls into two categories: basic equipment ledgers are updated synchronously quarterly, while marketing metering and operation record ledgers are updated daily or in real time. A single ledger document has a multi-table linked structure. Core fields include equipment ID, voltage level (unit: kV), rated operating current (unit: A), installation location, operation and maintenance cycle, user ID, power consumption (unit: kWh). Some ledgers come with visual attachments such as inspection photos and tower aerial photos.

## What Constraints These Characteristics Impose on Model Access and Configuration
Multi-table linked ledger structures require configuring field mapping rules during model access, to ensure cross-system equipment, marketing, and operation data can be correctly associated and summarized. Core fields with units require retaining original unit parsing logic in configurations, to avoid loss of data precision. Real-time or high-frequency updated ledger data requires limiting the context length of single requests, to prevent exceeding the model's processing limit. Ledgers with visual attachments such as inspection photos and aerial photos require enabling visual recognition capabilities, to ensure ledger content in images can be correctly extracted. In addition, grid enterprise business data must comply with intranet access security requirements. Interface configurations must adapt to enterprise intranet domain names and exclusive authentication rules.

## How to Set the Configurations
| Configuration Item | Suggested Value | Rationale |
| ---- | ---- | ---- |
| `vision` | Enabled | Ledgers contain visual attachments such as equipment inspection photos and tower aerial photos, requiring recognition of content like equipment IDs and defect descriptions within images |
| `maxContext` | 8000–12000 token | Grid ledgers have many fields per record and multi-table associations, requiring sufficient context to ensure correct data association |
| `maxTokens` | 4000 token | The output length of a single summary report must be controlled within a reasonable range, to avoid exceeding the model's output limit |
| `temperature` | 0.1–0.3 | Ledger summary and report generation require maintaining data accuracy, reducing randomness of generated content |
| `AIPROXY_API_ENDPOINT` | Fill in according to the enterprise intranet deployment address | Adapt to the security requirements of grid enterprise intranet data access, avoid public network exposure |
| `AIPROXY_API_TOKEN` | Fill in according to the exclusive key allocated by the enterprise | Ensure identity authentication security for interface calls, prevent unauthorized access |

## Three Common Mistakes
- Phenomenon: Existing configurations of the same type are overwritten after creating a new model configuration; Cause: Independent `AIPROXY_API_TOKEN` is not allocated for different applications, reusing the same key causes configuration conflicts.
- Phenomenon: Frequent 429 Request rate increased too quickly error returns when calling the model; Cause: The ledger data volume of single requests is not limited, and the `maxContext` parameter is not set reasonably, causing the request rate to exceed the model's limit.
- Phenomenon: After deleting body parameters and re-entering the configuration page, the parameters still exist and cannot be completely cleared; Cause: Configuration modification operations are not saved, or the page caching mechanism of FastGPT v4.17.0 causes parameter reset.

## How to Confirm the Configuration Is Properly Configured
- Pass structured data of a single device ledger and the corresponding inspection photo, verify that the model correctly extracts fields such as equipment ID and voltage level, and accurately recognizes the content of visual attachments.
- Initiate a multi-ledger summary request, review returned results to confirm they include cross-system associated data, with no missing fields, unit errors, or format confusion issues.
- Initiate more than 10 consecutive batch summary requests, confirm no 429 errors occur, and interface call status remains stable.
- Create independent model configurations for different applications, verify that the `AIPROXY_API_TOKEN` of each configuration differs, and no configuration overwriting takes place.

The values provided are common starting points and should be measured against the reader's own samples.
