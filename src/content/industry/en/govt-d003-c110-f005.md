# Mine Mining and Beneficiation Ledger Summary and Report Generation: Tool Calling and Plugins

## What the data for this category looks like
Ledger data for mine mining and beneficiation comes from on-site PLC control systems, beneficiation central control systems, and exploration reports from geological survey departments.
There are two update cycles:
- Real-time device operating parameters are updated every 5 minutes.
- Monthly full-mine summary ledgers are updated on the 1st of each month with full data from the previous month.
The standard format is a multi-worksheet Excel file. Each mining area uses a separate sub-sheet. Fields include mining area number, device operating duration, raw ore processing volume, concentrate output, and tailings discharge volume. Their units are, respectively, none, hours, tons, tons, and cubic meters.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources are scattered across multiple independent systems. Tool calling requires configuring multi-interface pulling plugins, and handling cross-system data alignment.
Real-time data has a high update frequency. The polling interval for tool calling must match the 5-minute update cycle to avoid pulling outdated data.
Structured documents have fixed fields, but sub-sheet naming for different mining areas has minor differences. Plugins must support custom field mapping rules.
Data volume grows with the number of mining areas. The maximum return data per single call must adapt to the conventional data volume of a single mining area’s ledger to avoid content truncation.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios, automatically selects data pulling and report generation tools, and is compatible with the FastGPT v4.17.0 tool calling framework |
| `functionCall` | `enabled` | Forces the large model to use tool calling to generate ledgers, avoiding pure natural language output |
| Data pulling timeout | 30 seconds | Matches typical response delays of on-site device systems in mine intranets |
| Field mapping rules | Match by mining area code | Resolves alignment issues caused by minor differences in sub-sheet naming across mining areas |
| Single call data limit | First 100 entries | Adapts to the typical data volume of a single mining area’s monthly ledger |
| Plugin retry count | 2 retries | Handles pulling failures caused by temporary network fluctuations |

## Three common configuration errors
- Calling the data pulling interface returns the `Failed to fetch` error. The cause is missing plugin network access permission configuration. External plugins cannot normally access production systems in the mine intranet.
- The multimodal visual analysis step returns empty analysis results. The cause is incorrect image pulling permission configuration. FastGPT cannot obtain central control screenshots or camera capture files from the mine site.
- The generated ledger report has missing fields. The cause is missing custom field mapping rule configuration. The plugin’s default matched field names do not align with the actual field names in the mine ledger.

## How to verify correct configuration
- Manually trigger the tool calling workflow. Check if the returned raw data includes preset fields such as mining area number and device operating duration. Verify that the field mapping matches the configured requirements.
- Review plugin running logs. Confirm that the interface call timeout matches the configured value. Check for no unexpected retry counts.
- Generate a test ledger report. Confirm that the report covers all preset ledger fields. Ensure no data truncation or omission occurs.
- Simulate a temporary network interruption. Check if the plugin automatically retries according to the configured retry count. Confirm normal data pulling resumes after recovery.
