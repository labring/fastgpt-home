# Mine Mining and Beneficiation Ledger Summary and Report Generation: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Mine mining and beneficiation ledger data comes from manufacturing execution systems (MES), equipment PLC control systems, on-site inspection logs, beneficiation process parameter reports, and similar sources. Update cadence: Equipment operation logs are updated hourly, inspection records are updated daily per shift, and monthly summary ledgers are archived per calendar month. Each single document corresponds to production records for a single piece of equipment or a single shift, and includes fields such as equipment number, operating duration, ore output, beneficiation grade, abnormal working condition records, etc. Units include professional units such as hours, tons, grams per ton, etc. The length of a single document ranges from a few hundred characters for a single inspection record to several thousand characters for a monthly production summary.

## What constraints these characteristics impose on the "knowledge base retrieval and recall" link
Differences in the update cadence of multi-source data require that knowledge base vector updates be performed in batches by data type, to avoid excessive resource usage from full updates. The presence of professional fields and units requires that retrieval must match both semantics and field formats, to avoid confusing parameters of different equipment. A high proportion of long documents requires that professional terms be preserved intact during chunking, to prevent the logical connection of the production process from being broken after splitting. Ledger data has strong business relevance, so a single retrieval must recall multiple related segments to support the needs of summary and report generation.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Mine mining and beneficiation ledgers contain a large number of professional terms and similar fields. A threshold that is too low will mix in irrelevant equipment logs, while a threshold that is too high will miss relevant parameter paragraphs. This is calibrated based on actual testing. |
| `limit` | Top 8 entries | Single ledger documents are relatively long. Recalling too many entries at one time will exceed the context window, while recalling too few will fail to cover data from related production links. |
| `searchMode` | hybrid | Combine keyword and vector retrieval to match explicit fields such as equipment numbers and ore output in ledgers, as well as semantically related process descriptions. |
| `usingReRank` | Enabled | Mine mining and beneficiation data has strong professional relevance. Reranking can filter out retrieval results that are semantically similar but business irrelevant. |
| `datasetSearchUsingExtensionQuery` | Enabled | For user requests for ledger summary, automatically expand to related production parameter queries to cover more business-related data. |
| `collectionIds` | Bind to the dedicated ledger collection for mine mining and beneficiation | Avoid retrieving documents from other categories, and ensure the recall scope is precise. |

## Three common mistakes
- Phenomenon: The returned answer does not show the cited document sources, only returns plain text. Cause: The document source tracing configuration of the knowledge base is not enabled, or the display logic for citation fields is not configured during the generation phase.
- Phenomenon: The retrieved results do not include embedded image content from the original document. Cause: The knowledge base's image vectorization and retrieval configuration is not enabled, and only text content is stored as vectors.
- Phenomenon: Unable to retrieve uploaded ledger documents after specifying an appId. Cause: The corresponding knowledge base collection ID is not bound to the specified appId, or the uploaded documents are not categorized into this dedicated collection.

## How to confirm the configuration is correct
- Initiate a query that includes specific equipment numbers and production parameters, and check whether the returned results include the corresponding document source identifiers.
- Upload a ledger document that contains embedded images, initiate a relevant query, and check whether image-related content is correctly displayed in the results.
- Call the retrieval interface for the specified appId, pass in dedicated keywords for mine mining and beneficiation, and check whether the returned results only include ledger data of this category.
- Adjust the `similarity` parameter value, observe changes in the relevance of retrieval results, and confirm that the threshold setting meets business requirements.
