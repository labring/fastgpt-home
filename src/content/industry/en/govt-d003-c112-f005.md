# Grain Reserve Ledger Summary and Report Generation: Tool Calling and Plugins
This document is written for FastGPT v4.17.0.

## What data for this category looks like
Ledger data for grain reserves comes from grain depot warehouse management systems, quality inspection systems, and business workflow systems. Updates are triggered by business processes: single ledgers are updated in real time during inbound and outbound operations, and full warehouse summary documents are generated via monthly inventory checks. Each single ledger document includes fields such as grain type, inbound batch number, storage bin number, inbound weight, outbound weight, current inventory weight, inbound quality inspection date, and storage cycle. Weight units are uniformly tons. Batch numbers and bin numbers use string format, and there are no nested subdocuments.

## Constraints imposed on tool calling and plugins
Multiple ledger data sources require tool calling to connect to warehouse, quality inspection, and business systems at the same time. Multi-tool linkage logic must be configured. Fixed fields and units require strict parameter format matching during tool calling to avoid pull failures caused by mismatched units or incorrect field names. Daily real-time ledger updates require tool calling frequency to align with update rhythms. Avoid overly frequent duplicate pull operations. Bulk ledger summary requirements mean tools must support filtering data by specified dimensions such as bin number or batch. Bulk data processing parameters must be configured. Monthly summary report generation requirements mean tools must automatically organize pulled ledger data into structured documents. Preset field mapping rules for report templates are needed.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Supports automatically matching ledger pull, data summary, and report generation tools based on user queries, adapting to different business query scenarios |
| `functionCall` | `strict: true` | Grain reserve ledger fields are fixed; strict parameter format validation prevents field mismatch issues during data pulling |
| Timeout duration | `300 seconds` | Average time for single-bin ledger pulling and summary is 120-200 seconds; sufficient buffer time prevents mid-process interruptions |
| Bulk pull limit | `Top 100 entries` | Monthly ledger summary single-time data volume usually does not exceed 100 entries, avoids interface overload and response timeout |
| File upload limit | `1000 MB` | Supporting quality inspection scans and bin photos for a single monthly summary report can reach up to 800 MB, reserves reasonable space |
| Workflow variable binding | Enable parameter mapping | Dynamic parameters such as ledger batch numbers and bin numbers can be passed via workflow variables, adapting to different query dimensions |

## Three common mistakes
- Calling the ledger pull tool returns `500 Internal Server Error`, logs show data source connection timeout. Cause: No access whitelist configured for the grain depot business system, causing tool calling requests to be blocked.
- Calling the summary tool returns `Request Timed Out`, status code `408`. Cause: Set timeout duration is shorter than actual time for single-batch data pulling, no sufficient buffer time reserved.
- Custom workflow upload file tool cannot reference variables. Phenomenon: When configuring tool parameters, cannot select ledger batch number as a dynamic variable for file names, only fixed links are supported. Cause: The workflow variable and tool parameter binding switch is not enabled, or variables are not mapped to the named field of the file parameter.

## How to confirm configuration is correct
- Enter a specified query in the FastGPT test panel, such as "Query wheat ledgers for Bin 1 in March 2024", trigger tool calling and check logs to confirm pulled data matches the specified bin number and batch.
- Upload a simulated ledger file in workflow configuration, check if dynamic parameters such as batch numbers and bin numbers can be automatically filled via variable binding to generate compliant file names.
- Temporarily set the timeout duration to 60 seconds, trigger a bulk pull operation, confirm tool calling does not interrupt early to verify timeout configuration is effective.
- Configure field validation rules in custom tools, enter parameters that do not match units such as "kilograms" instead of "tons", check if parameter error prompts are returned to confirm format validation is effective.
