# Grain Reserve Ledger Summary and Report Generation: Deployment and Upgrade

## What the data for this category looks like
Grain reserve ledger data is sourced from inbound and outbound weighing records, inventory count reports, and quarterly quality inspection reports from grain depot warehouse management systems. Data update frequencies fall into three categories: real-time (single records generated immediately upon inbound or outbound operations), daily summary (same-day inventory movement statistics), and monthly reporting (full warehouse inventory ledgers and analysis reports). Individual ledger documents contain fields including grain type, batch number, inbound time, outbound quantity, remaining inventory quantity, quality inspection grade, and storage bin number. Weight units are tons, quantity units are bags or kilograms, and document lengths range from tens of characters to thousands of characters.

## Constraints imposed on deployment and upgrade by these characteristics
The requirement for multi-source access to grain reserve ledger data means storage connections for both structured and unstructured data must be configured during deployment. Data sources with different update frequencies need matching data synchronization cycle configurations to prevent real-time data backlogs or delayed monthly data generation. The wide range of document lengths requires storage configurations that support read and write performance for both short texts and long documents. The multi-field ledger structure also requires advance planning of database index strategies to avoid performance degradation during retrieval. During the upgrade process, mapping rules for core fields such as original batch numbers and quality inspection grades must be retained to prevent abnormal ledger data parsing.

## How to set the configurations
The following configurations are based on the deployment specifications for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 20–30 concurrent connections | Adapts to daily summary bulk data writes and concurrent requests for real-time single records |
| `MONGODB_URI` | Address of the unstructured ledger document library corresponding to the grain depot warehouse system | Stores unstructured ledger data such as batch numbers and quality inspection reports |
| `PG_URL` | Address of the structured inventory statistics database corresponding to the grain depot | Stores structured field data such as inbound and outbound quantities and remaining inventory quantities |
| `REDIS_URL` | Address of the cache service within the local private network with memory no less than 2048 MB | Caches temporary data from real-time inbound and outbound operations to reduce database read and write pressure |
| `STORAGE_S3_ENDPOINT` | Access endpoint of the enterprise internal object storage service, with a single file limit set to 1000 MB | Stores large files such as complete monthly report PDFs and quality inspection scan copies |
| `ROOT_KEY` | 32-bit random string generated according to enterprise internal permission rules | Configures the initial access permission for platform administrators to ensure deployment security |

## Three common configuration mistakes
- Accessing the OneApi page returns a 502 status code, and logs show database connection timeout. The cause is that a reasonable value for `DB_MAX_LINK` was not configured, causing the concurrent connection count to exceed the database limit, and the service cannot respond to front-end requests normally.
- Multiple accounts cannot join the same team, and there is no user addition entry on the team management page. The cause is that the administrator permission corresponding to `ROOT_KEY` was not correctly configured, and the team member management function was not enabled, causing ordinary accounts to fail to complete team association.
- Fields are empty after ledger data import, and the generated report has no remaining inventory quantity data. The cause is that `PG_URL` was not bound to the correct table name of the grain depot structured database, causing the remaining inventory quantity field to fail to match during data reading.

## How to confirm the configuration is complete
- Use the system built-in database testing tool in FastGPT v4.17.0 to verify the connectivity of `MONGODB_URI` and `PG_URL` respectively, and confirm that preset test ledger data can be read.
- Trigger a temporary ledger summary task, check whether the generated report includes all preset fields and that the data matches the statistical results of the source system.
- View the cache service monitoring metrics, confirm that the connection count of `REDIS_URL` is within the normal range, with no frequent connection disconnections or timeouts.
- Use the administrator account to create a new team and add a test account, confirm that the team member management function can be enabled normally.

The values provided are common starting points and should be measured against the reader's own samples.
