# Shipbuilding Ledger Summarization and Report Generation: Tool Calling and Plugins

## What the data for this category looks like
Shipbuilding ledger data comes from the process management system, material management system, and quality inspection system across the entire shipbuilding process. It is updated synchronously with the completion of individual sections and monthly node acceptances. Each ledger document includes structured fields and attached drawings. Fields cover section number, steel batch number, welding current, welding voltage, completion date, inspection record number, and more. Units include millimeters, amperes, man-hours, tons, and others. Some ledgers have attached CAD section drawing files.

## What constraints these characteristics impose on the tool calling and plugins workflow
The specialized multi-field nature of shipbuilding ledgers requires strict matching of field names and units during tool calling to avoid parameter parsing errors. Large CAD drawing attachments on single ledgers increase transmission time for tool calls, so reasonable timeout thresholds must be configured. Pulling ledgers across multiple work processes requires tool calling to support multi-data source field mapping rules, to ensure unified data standards during summarization. Frequently updated ledgers require configuring the data source sync frequency for tool calls, to match the update rhythm of node acceptances.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios, automatically matches data source pulling and field mapping tools required for ledger summarization |
| `functionCall` | Triggered by field matching | Ensures tool calling only starts when ledger field requests are detected, avoiding invalid calls |
| Tool call timeout | `120–180 seconds` | Adapts to CAD drawing transmission time for shipbuilding ledgers, avoids interrupting calls during large file transfers |
| Data source sync frequency | Every 8 hours | Matches the update rhythm of monthly node acceptances for shipbuilding, balances data timeliness and system load |
| Attachment upload limit | Single file no larger than 500 MB | Adapts to the size of section drawings attached to shipbuilding ledgers, avoids transfer failures |
| Field mapping rules | Calibrated based on actual measurements | Matches specialized fields and units of shipbuilding ledgers, ensures accuracy of summarized data |

## Three Common Mistakes
- Symptom: Ledger data returned by tool calls only shows numerical values, without attached specialized units. For example, welding current only displays a number without the amperes unit. Cause: Field mapping rules were not configured, so standard units for shipbuilding ledgers were not automatically completed during tool calling.
- Symptom: Uploaded ship section drawing attachments cannot be passed as parameters to bound workflows. The workflow throws an error that the parameter field is empty during execution. Cause: The automatic file link generation configuration for tool calls was not enabled, so no accessible transfer link was generated for uploaded files.
- Symptom: Connection failure error occurs when calling MCP-type tools, unable to pull ledger data. Cause: Correct access address and authentication parameters for the MCP server were not configured, and the open-source deployment adaptability of the MCP server was not confirmed.

## How to Confirm Proper Configuration
- Initiate a query containing specialized fields for shipbuilding ledgers, use the tool calling function of FastGPT v4.17.0 for testing, and verify whether the returned fields have standard units attached, such as amperes, millimeters, and others.
- Upload a small ship section drawing attachment, trigger tool calling, and check whether the bound workflow can receive a valid file access link.
- Configure cross-system ledger data source calls, and verify that the field standards of returned data are unified, with no duplicate or misaligned entries.
- Test the calling of MCP-type tools, confirm that the connection is normal and valid ledger data can be pulled.
