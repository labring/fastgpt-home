# Ledger Summary and Report Generation for Telecommunications Engineering Construction: Workflow Orchestration

## What the data for this category looks like
Ledger data for telecommunications engineering construction comes primarily from project management systems, construction log systems, material site acceptance systems, and completion acceptance archives. Data is updated in sync with construction milestones, and synced after each construction phase is completed. Each ledger document includes fields such as project number, construction section, material specification, delivery date, acceptance status, and completed project quantity. Units cover common engineering measurement standards including kilometers, sets, days, and square meters. The data is primarily in structured table format, and some attachments include on-site construction images.

## Constraints Imposed on Workflow Orchestration
Telecommunications engineering ledgers have multiple fields and units, so unit conversion nodes must be configured for different measurement standards during workflow orchestration to avoid unit confusion in summary results.
Workflows must support direct reading of Excel and CSV ledger files, without additional format conversion, due to the structured table format of the data.
Workflow trigger timing must be bound to construction node status, to ensure the called ledger data is the latest version, given the real-time data update following construction milestones.
Workflows must include multi-source data merging nodes to integrate ledger content exported from different systems, to handle mixed entry of multiple data types including structured tables and image attachments.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Trigger Timing | Bind the construction node completion event corresponding to `nodeId` | Ensure the called ledger data is the latest version for the current node |
| Variable Mapping | Match ledger-specific fields via the `variables` configuration | Accurately correspond to unique telecommunications engineering fields such as project number and completed project quantity |
| Timeout Threshold | 600 seconds | Large-scale engineering ledger summarization requires longer processing time, to avoid mid-execution interruptions |
| Context Count | Top 8 historical node records | Balance data completeness and processing efficiency |
| Multi-source Data Merging | Merge by project number | Integrate ledger content for the same project exported from different systems |
| Format Validation | Automatically validate measurement unit consistency | Avoid unit confusion in summary results |

## Three Common Mistakes
- Inconsistent units appear in workflow execution summary results. This occurs when measurement unit validation nodes are not configured, and no unit conversion is applied to quantity fields from different sources.
- Workflows cannot maintain multi-turn conversation context. This occurs when the context count parameter is not properly configured, or when trigger timing is bound to a single execution node, and no session continuation trigger logic is set.
- Attempts to directly call external pages in workflows fail. This occurs when no external jump node is configured, as workflows only support internal data processing nodes by default.

## How to Verify Proper Configuration
- Trigger the completion event for the corresponding construction node, check the workflow logs in FastGPT v4.17.0, confirm that the latest ledger data is successfully pulled.
- Export the summary report output by the workflow, verify that all ledger fields are correctly mapped, and that measurement units remain consistent.
- Submit two consecutive ledger query requests, confirm that the workflow can retain and continue the previous session context.
- Import a simulated large-scale engineering ledger file, confirm that the workflow does not experience timeout interruptions, and that execution duration matches the preset threshold.
