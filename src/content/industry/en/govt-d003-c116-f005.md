# Ledger Summary and Report Generation for Telecommunications Engineering Construction: Tool Calling and Plugins

## What this category of data looks like
Ledger data for telecommunications engineering construction comes from multiple types of business documents including construction logs, supervision inspection reports, material purchase and warehousing receipts, and completion acceptance reports. The data update rhythm is adjusted dynamically based on construction milestones. Routine updates occur daily, while real-time synchronization can be enabled on demand for large critical construction milestones.

Each individual ledger document includes fixed fields such as unique project identifier, construction area, material name, specification and model, quantity, corresponding unit (meters, tons, sets, square meters, etc.), construction date, and acceptance status. There is no unified fixed length: single-page ledgers for small projects are approximately 100 to 500 characters, while ledgers for large projects in a single batch can reach thousands of characters.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Multiple data sources require tool calling to link multiple independent data source plugins. Full data extraction cannot be completed with a single plugin.
Multiple unit fields require tool calling logic to include built-in unit verification and unified conversion rules, to avoid calculation errors caused by mismatched units during summary.
Dynamic update rhythms require tool calling to support configurable scheduled or event-triggered modes, to adapt to different data update frequencies across construction milestones.
The wide range of single document lengths requires tool calling to adapt to variable-length context processing, to avoid context overflow caused by excessive single-batch data.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Supports automatic matching of multiple tools required for telecommunications engineering ledger summary, no need to manually specify individual functions, and adapts to multi-source data extraction and format conversion needs |
| Function call timeout | `300-600 seconds` | Telecommunications engineering ledger data volume fluctuates greatly. This interval covers the duration required for rapid summary of small projects and complex calculations for large projects |
| Batch data extraction limit | `Top 200 entries` | Extracting too much data in a single batch will cause context overflow, which matches the conventional scale of single-page telecommunications engineering ledgers |
| Unit conversion plugin trigger rule | Automatically trigger based on field unit type | Telecommunications engineering ledgers contain multiple units such as meters, tons, and sets. These units must be automatically converted to a unified accounting unit before summary can be performed |
| `functionCall` | `enabled` | Enables explicit function calling mode, ensures that ledger summary logic can be accurately tracked and debugged, and meets compliance requirements for engineering scenarios |

The configurations on this page apply to FastGPT v4.17.0.

## Three common configuration errors
- The interface returns `code:514` and `unAuthApiKey` errors. Cause: The large model API key exclusive to the telecommunications engineering scenario is not correctly bound, or the key permissions do not cover the ledger summary tool calling scope.
- Call logs show "Data acquisition exception". Cause: The linkage rule for multiple data source plugins is not configured, making it impossible to extract ledger data from construction, supervision, and procurement categories simultaneously.
- Large model calls return "error" and logs show mode mismatch. Cause: Stream mode support is not enabled in FastGPT's model configuration, causing large models that only support stream mode to fail to respond to requests normally.

## How to confirm the configuration is complete
- Manually trigger the ledger summary tool call, and check if the returned result includes data with unified unit conversion for all preset fields.
- View FastGPT's call logs to confirm there are no `code:514` or "Data acquisition exception" errors.
- Verify the stream mode configuration, and confirm that the large model returns streaming output through real-time logs.
- Adjust the batch extraction quantity, and confirm that single-batch extracted data does not exceed the preset limit.

The configuration values listed here are common starting points, and should be evaluated against your own specific samples.
