# Ledger Summary and Report Generation for Telecommunications Engineering Construction: Knowledge Base Retrieval and Recall

## What data for this category looks like
Telecommunications engineering construction ledger data primarily comes from project approval documents, construction logs, material requisition slips, completion acceptance reports, and similar sources.
Data updates follow project milestones. Construction progress ledgers are updated weekly. Acceptance-related data is entered synchronously when milestones are completed.
Most documents are structured tables, containing fields such as project ID, construction location, material specification, engineering quantity, acceptance date, and others.
Units include common engineering measurement standards such as meters, square meters, tons, labor hours, and more.
Some documents include hand-drawn annotations from site surveys and photo attachments.

## Constraints on the knowledge base retrieval and recall workflow
The high proportion of structured tables requires retrieval to preserve row-column association relationships, to avoid losing field correspondence logic after splitting.
Data updated by project milestones needs to match incremental synchronization mechanisms, to ensure recalled ledger data aligns with current project progress.
Ledger content with multiple fields requires retrieval logic to link core identifiers such as project ID and construction location, to prevent irrelevant results from being included.
Unstructured attachments such as site survey annotations and photos require additional parsing configuration, to ensure such content can be properly retrieved.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | `0.72–0.85` | There are many fields in telecommunications engineering ledgers. Low-match irrelevant documents must be filtered to prevent retrieval results from including content from non-target projects |
| `limit` | `Top 8–12 entries` | Ledger data has many entries. Too many recalled entries at once will exceed context length limits. Too few will fail to cover associated data across multiple stages of the same project |
| `searchMode` | `vector+keyword` | Ledgers contain both structured fields and free text descriptions. Hybrid retrieval matches both keywords and semantically related content |
| `usingReRank` | `Enabled` | Multi-field retrieval results can easily have incorrect ordering. Re-ranking reorders results based on relevance, raising the priority of core ledger entries |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Fields such as ledger project IDs require exact matching. Extended queries automatically complete standardized formats such as ID prefixes, improving recall accuracy |
| `collectionIds` | `Bind to the dedicated knowledge base collection for telecommunications engineering construction` | Isolate ledger data from other categories to avoid interference from cross-category retrieval |

## Three Common Mistakes
- Phenomenon: Some uploaded ledger tables cannot be properly chunked, and fields such as engineering quantity and construction location within the table cannot be extracted during retrieval. Cause: Table structured parsing configuration is not enabled. The default chunking logic splits tables into scattered text, losing row-column association relationships.
- Phenomenon: Retrieval results include ledger data from non-target projects, and the matching accuracy for core project IDs is low. Cause: The `collectionIds` configuration to bind the dedicated knowledge base collection is not set. The retrieval scope covers knowledge base content from other categories across the platform.
- Phenomenon: Uploaded site survey photos cannot retrieve associated annotation content, or the image understanding model option is not visible in local deployment instances. Cause: The image understanding parsing module is not enabled, or relevant environment configuration was not completed during deployment, preventing non-text attachments from being properly recalled.

## How to Confirm Configurations Are Correctly Set
- Upload a test telecommunications engineering construction ledger table, search for the project ID keyword, and verify that retrieval results include the table’s complete field content.
- Check the sorting logic of retrieval results, confirm that highly relevant ledger entries appear first, to verify that the re-ranking configuration is active.
- Check the knowledge base collection binding relationship, confirm that only the dedicated knowledge base collection for telecommunications engineering construction is bound, with no cross-category data included.
- Upload a site survey photo, search for annotation keywords within the photo, and verify that corresponding ledger content can be recalled.
