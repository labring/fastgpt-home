# Ledger Summary and Report Generation for Communication Towers and Infrastructure: Tool Calling and Plugins

## What data for this category looks like
Data for this category primarily comes from local tower operation and maintenance management systems, base station field inspection terminals, and power environment monitoring modules. Basic attribute ledgers are updated quarterly, inspection records are synced daily, and alert data is pushed in real time. Individual ledger documents include fields such as tower unique identifier, longitude and latitude coordinates, installation height, affiliated operator, inspection time, battery voltage, and ground resistance. The units for these fields are degrees, meters, volts, and ohms respectively.

## What constraints do these characteristics impose on the tool calling and plugin workflow
The multi-source update rhythm, multiple field types, and specific format requirements of this category's data impose multiple constraints on tool calling and plugin configuration. The quarterly update of basic attribute ledgers and daily sync of inspection records require plugins to support pulling incremental data on a fixed schedule, to avoid wasting resources from repeated full data calls. Multiple fields include numerical types with specific units such as longitude and latitude, battery voltage, and ground resistance. This requires configuring field mapping rules during tool calling, to ensure that incoming parameters match the units and data ranges of ledger fields. In FastGPT v4.17.0, the `toolChoice` and `functionCall` parameters must be combined to automatically match the corresponding data processing logic.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Automatically matches the tool type required for ledger summary, adapting to multi-source data calling logic |
| `functionCall` | `[{"name":"pull_tower_ledger","parameters":{"required_fields":["tower_id","installation_height","ground_resistance"]}}]` | Specifies core ledger fields to pull, filters redundant data, and improves calling efficiency |
| Streaming output interval | `500–1000 milliseconds` | Adapts to the push rhythm of inspection data, avoids front-end loading lag, and improves interactive experience |
| Incremental data pull cycle | `1 day` | Matches the daily update rhythm of inspection records, reduces resource consumption from full data calls |
| Conversation log sync switch | Enabled | Ensures conversation details match actual returned content, avoids discrepancies between logs and responses |
| Custom icon for non-login window | Upload compliant operation and maintenance vector icons | Aligns with visual specifications for state-owned enterprise operation and maintenance scenarios, meeting visual requirements of the use case |

## Three common configuration mistakes
- Phenomenon: When a ledger link returned in streaming output is clicked, it only overwrites the current page and cannot jump to a new page. Cause: No streaming output link jump rules are configured, and the default in-page replacement interaction logic is used.
- Phenomenon: Regardless of how many conversations are held, the content in the conversation log details remains consistent and does not match the actual returned ledger data. Cause: The real-time conversation log sync switch is not enabled, and the log only caches the return result from the first call.
- Phenomenon: The return speed of streaming output is fixed at approximately 4 seconds and cannot be adjusted to the 1–2 second range. Cause: No custom parameter for streaming output interval is set, and the platform's default fixed interval value is used.

## How to confirm correct configuration
- Initiate a ledger pull call, check if the returned fields match the required_fields specified in `functionCall`.
- Enable streaming output functionality, test link click behavior, and confirm the jump logic meets expectations.
- View conversation log details, confirm that log content after each call matches the ledger data returned that time.
- Adjust the streaming output interval parameter, verify that the return speed aligns with the custom set range.
