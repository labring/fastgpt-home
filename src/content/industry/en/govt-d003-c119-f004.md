# Steel Smelting Ledger Summary and Report Generation: Workflow Orchestration

## What this category of data looks like

## What constraints these characteristics impose on workflow orchestration
Because data comes from multiple systems with inconsistent formats, the workflow must be configured with cross-source data pull and format conversion nodes to ensure field alignment. Because updates are triggered by production batches, the workflow must bind production events as startup conditions to avoid pulling incomplete semi-batch data caused by fixed timed triggers. Because a single batch ledger includes multi-dimensional numeric parameters, the workflow must set field mapping rules to unify field names from different systems into the ledger standard format. Because data volume grows with production scale, the workflow must configure a single-batch processing threshold to avoid node execution timeouts. Additionally, data compliance requirements in public sector and state-owned enterprise scenarios require adding a data verification node to the workflow to filter invalid or abnormal ledger data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data Source Node Configuration | Bind API interfaces of production execution systems, equipment monitoring systems, and quality inspection systems | Cover all ledger data sources across smelting processes |
| Trigger Condition Configuration | Bind production completion events, start after a 10-15 second delay | Ensure complete single-batch ledger data is pulled |
| `variables` | Pre-set furnace number, production batch number, and knowledge base ID as global variables | Enable cross-node transfer of unique identifiers and knowledge base associations |
| Field Mapping Configuration | Align with internal enterprise ledger standard field names | Unify formats and naming rules for multi-source data |
| `nodeId` | Assign a unique identifier to each data source node | Facilitate troubleshooting of abnormal nodes in execution logs |
| Timeout Threshold Configuration | 600 seconds | Adapt to the typical single furnace smelting cycle, avoid execution interruptions |

## Three Common Mistakes
- Symptom: Workflow execution fails during report generation, with an interface prompt of "no valid knowledge base data matched". Cause: The global variable corresponding to the knowledge base ID is not configured in `variables`, or the assignment format does not meet system requirements.
- Symptom: Ledger data pulled by the workflow has inconsistent field names, preventing automatic summary. Cause: No field mapping node is configured, and multi-system raw data is directly spliced together.
- Symptom: The workflow does not complete within the set time after startup, triggering a timeout error. Cause: No production completion event is bound as the startup condition, resulting in pulling ledger data from multiple overlapping batches, exceeding the node processing limit.

## How to Verify Correct Configuration
- Check the workflow's trigger configuration to confirm that the production system's completion event is bound.
- Access the `variables` configuration page, verify that the preset global variables include furnace number, production batch number, and knowledge base ID.
- Check the `nodeId` identifiers of each data source node to confirm there are no duplicate configurations.
- Run a test workflow, pull single-batch simulated data, and check field alignment and interface return status.
