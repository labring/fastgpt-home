# Ledger Summary and Report Generation for Expressway Operations: Workflow Orchestration

## What data for this use case looks like
Data is primarily sourced from toll station toll systems, road section monitoring platforms, maintenance inspection terminals, and road law enforcement ledger systems. It is updated per shift or natural day. Each individual ledger includes structured fields and unstructured attachments. Structured fields include: toll amount (yuan), traffic volume (vehicles), maintenance work mileage (kilometers), inspection time (YYYY-MM-DD HH:MM), and equipment fault code. Unstructured attachments include on-site photos and inspection record PDFs.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data formats require workflows to first complete structured field extraction and unstructured attachment parsing, to avoid summary errors caused by format confusion. High-frequency updates per shift or day require workflows to support scheduled triggering or event callback triggering, to ensure ledger data can be summarized promptly. Fields with dedicated units require workflows to retain field identifiers and unit information during parameter transfer, to prevent unit confusion during statistics. Long text content in unstructured attachments requires workflows to support long text splitting and segment processing, to adapt to content length limits of downstream nodes.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Scheduled trigger cycle | `15–30 minutes` | Covers the ledger update rhythm of expressway morning, midday, and evening shifts, ensuring summary timeliness meets operational requirements |
| `variables` | Custom variables including source data identifier and field units | Passes the data source path and field metadata pulled by the system, resolving issues where global variables fail to be recognized |
| `nodeId` | Unique identifier bound to data parsing, summary, and report generation nodes | Ensures the workflow executes in a preset order, avoiding chaos in node execution sequence |
| Long text splitting length | `800–1200 characters` | Adapts to the single-segment processing limit of expressway inspection records and toll details, conforming to the node content limit of FastGPT v4.17.0 |
| HTTP request timeout | `60 seconds` | Matches the average response duration of multi-source data pulling, preventing timeout interruptions of the summary process |
| Content extraction model | Calibrated based on actual testing | Adapts to structured extraction requirements for expressway ledgers, covering parsing of different types of unstructured attachments |

## Three common configuration mistakes
- Incorrect transfer of system parameters during workflow runtime, manifested as empty data source path fields in global variables. This occurs because system-passed parameters are not explicitly declared via the `variables` configuration item, and recognition fails due to reliance on implicit calls only.
- Failure to send long text in segments after receiving it via HTTP API, manifested as downstream nodes returning errors for exceeding content limits. This occurs because long text splitting rules are not configured, and complete long text is directly passed to the sending node.
- Failed calls to the content extraction node, manifested as empty results returned by the node or error prompts indicating that custom models are not supported. This occurs because the model source is not correctly specified in the node configuration, or the corresponding call permissions are not enabled as required by the platform.

## How to confirm configuration is correct
- Manually trigger the workflow once, check if the `variables` parameter in the running logs includes the system-passed data source identifier and field units.
- Simulate an inspection record text with a length exceeding 1000 characters, verify whether the workflow automatically splits the content into segments according to the configured splitting length and sends them in segments.
- View the configuration interface of the content extraction node, confirm that the correct model source is selected and the corresponding call permissions are enabled.
- Export the test report output by the workflow, compare it with the original ledger data to confirm that all fields and units are correctly summarized.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
