# Ledger Summary and Report Generation for Expressway Operations: Tool Calling and Plugins

## What this category of data looks like
Expressway operation ledger data comes from three primary data sources: toll settlement systems, pavement maintenance inspection systems, and road network monitoring systems.
Toll ledgers update every 15 minutes, and record station code, number of passing vehicles, actual collected amount, and lane number.
Maintenance ledgers update daily, and record maintenance section, inspection time, defect type, and repair status.
Monitoring ledgers push data in real time, and record device online status and traffic peak value.
All ledger documents are stored in structured format, with unified timestamp and area code fields. Units include vehicle trips, yuan, kilometers, percentage, and other standard units.

## Constraints Imposed on Tool Calling and Plugin Workflows
Differences in synchronization cycles across multiple data sources require plugin calls to align with their respective update rhythms, to avoid calling data sources that have not completed updates.
Diversity of fields and units requires preset field mapping rules during tool calling, to unify output formats for report generation.
Large monthly ledger data volume for a single station requires paging processing for batch calls, to prevent single requests from exceeding interface load limits.
Cross-system data association demands that plugins support parallel calls of multiple data sources, to ensure completeness of summary reports.

## Three Common Configuration Mistakes
- Calling the workflow returns a `401 Unauthorized` error. The cause is that the correct API key is not configured, or the key is not bound to the access permission of the corresponding ledger summary workflow.
- Stream data reception interruption causes page data to freeze but backend tasks continue running. The cause is that a stream interruption callback mechanism is not configured, and the unfinished tool call task is not actively terminated.
- FastGPT deployed via Docker cannot find the `packages/plugins/register` file. The cause is that the plugin registration path for this version has been adjusted to `data/plugins`. Manually create the corresponding directory or complete plugin configuration via the backend interface.

## How to Confirm Configuration is Correct
- Call the test interface, pass the time range parameter for the specified station, and check if the returned results include core ledger fields such as station ID, number of passing vehicles, and actual collected amount.
- View the plugin running logs, confirm that the `toolChoice` parameter is correctly set to the bound ledger summary workflow.
- Simulate stream data reception interruption, check if the backend triggers the task termination logic, with no residual background processes.
- Compare the configured timeout period with the actual data processing duration, to ensure no timeout error prompts appear.
