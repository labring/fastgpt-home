# Ledger Summary and Report Generation for Expressway Operations: Document Parsing and Chunking

## What the Data for This Category Looks Like
Expressway operation ledger data originates from multiple business modules including toll systems, maintenance inspection systems, road law enforcement systems, and monitoring and operation maintenance systems. Data updates follow shift, daily, or monthly cycles. A single ledger document typically includes multiple sets of structured entries. Each entry contains fixed fields such as passage time, lane number, toll amount (yuan), maintenance mileage (kilometers), and law enforcement duration (minutes). Common document formats are Excel spreadsheets and structured PDFs. Scanned paper ledger archives are used in some scenarios.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Link
Multiple system sources result in inconsistent ledger formats, so parsing support for multiple file formats is required. The shift or monthly update rhythm requires the parsing process to have high efficiency, to avoid slowing the overall ledger summary and report generation workflow. The presence of structured fields and fixed units requires chunking to retain the complete context of a single record, without splitting associated fields. Large monthly ledger documents have significant file size, so support for large file uploads and long-duration parsing is needed. These characteristics mean the document parsing and chunking link cannot use generic, uniform chunking rules, and configuration must be adjusted for the field association properties of structured ledgers.

## How to Configure the Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range/Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | A single expressway ledger entry contains multiple associated fields. This value range ensures that a single complete record is contained within one chunk, avoiding field splitting |
| `chunkSplitter` | Field separation + paragraph splitting | Ledger documents have fixed entry structures. Field separation retains complete information for each record, while paragraph splitting adapts to unstructured remark content |
| `customPdfParse` | Enabled | Structured PDF ledgers require retention of table layouts and field associations. Custom parsing prevents the default parser from losing unit and field correspondence |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Monthly maintenance ledgers submitted in a single batch may contain multiple sub-documents. This value supports large-scale batch file uploads |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large structured documents takes significant time. This value prevents parsing failure due to timeout |
| `chunkSettingMode` | Manual mode | Chunking rules must be adjusted for the structured characteristics of ledgers. Manual mode allows flexible configuration of chunking parameters |

## Three Common Misconfigurations
- Phenomenon: A 404 error occurs during file upload parsing after server deployment, while uploads in local environments parse normally. Cause: Read/write permissions for the server-side file storage path or reverse proxy mapping are not configured, preventing the parsing node from accessing the uploaded file address.
- Phenomenon: Parsed chunks lose unit information for ledger fields. For example, "toll amount" only displays numbers without the "yuan" unit. Cause: The `customPdfParse` configuration is not enabled. The default PDF parser does not retain field and unit associations for structured tables.
- Phenomenon: Parsing of large monthly ledger documents fails due to timeout, with a parsing timeout prompt displayed in the interface. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` value is set too short, failing to match the parsing time required for large documents.

## How to Confirm Successful Configuration
- Upload a standard expressway toll ledger PDF, view the parsed chunk list, and confirm that each chunk contains complete fields for a single toll record, with no field splitting.
- Access the system configuration page, verify that the `UPLOAD_FILE_MAX_SIZE` configuration value matches the maximum allowed upload size shown in the current upload interface.
- Upload a ledger compressed package larger than 500 MB, wait for parsing to complete, and confirm that no timeout error is triggered.
- Switch `chunkSettingMode` to manual mode, adjust `chunkSize` to 600 characters to generate test chunks, and confirm that the chunk length matches the set value.

The values listed here are common starting points, and should be evaluated against applicable sample data.
