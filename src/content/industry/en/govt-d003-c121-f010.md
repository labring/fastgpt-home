# Highway Operations Ledger Summary and Report Generation: Knowledge Base Retrieval and Recall

## What data for this category looks like
Highway operation ledger data comes from four main sources: toll settlement systems, daily maintenance inspection platforms, road administration incident management systems, and section monitoring systems.
Data updates follow two rhythms.
Real-time data includes traffic volume, toll transactions, and temporary road administration incidents. It updates every minute.
Periodic data includes monthly maintenance statistics and quarterly traffic trend ledgers. It updates based on natural cycles.
Individual ledger documents include fields such as section number, traffic count, toll amount, inspection location, incident level, and disposal duration. Common units include counts, yuan, kilometers, and hours.

## What constraints these characteristics impose on knowledge base retrieval and recall
The minute-by-minute update of real-time data requires knowledge base index incremental update frequency to match this rhythm. Otherwise, recall results will lag behind the latest operation data.
Ledger fields are numerous and include metadata such as section number and incident level. If metadata filtering is not configured, retrieval results will mix in ledgers from unrelated sections. This fails to accurately match summary needs for a specified section.
Individual ledger document lengths vary widely. Some are just over 100 characters, while others exceed 1,000 characters. This affects recall matching accuracy after chunking.
Ledgers need to aggregate indicators by time dimension. Retrieval must first recall documents within a specified time range. This requires the retrieval link to support metadata filtering for time ranges.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the field density and technical terminology specificity of highway operation ledgers, filters low-correlation non-operation documents |
| `limit` | Top 12 entries | Individual ledger document lengths vary widely. Limiting the number of recalled entries avoids context overflow, and adapts to the batch processing needs of ledger summary tasks |
| `searchMode` | hybrid | Combines keyword matching and semantic recall, covering precise matching for toll terminology and professional maintenance terms, as well as semantic association retrieval |
| `usingReRank` | Enabled | Reranks initially recalled ledger documents by relevance and time weight, prioritizing returning recent operation data |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands search terms for ledger summary, adding scenario-specific query terms such as "traffic volume summary" and "maintenance ledger statistics" |
| `collectionIds` | Bind dedicated collection IDs for operation ledgers | Isolates knowledge base data from other categories, preventing non-highway operation documents from appearing in retrieval results |

## Three common misconfigurations
- Retrieval results mix in ledgers from non-target sections. The symptom is that returned ledgers include section number fields from other cities. The cause is that dedicated collection IDs are not bound, or metadata filtering rules are not enabled. This leads to cross-category data being recalled.
- The generated summary report does not include real-time daily traffic data. The symptom is that the last update time of recalled ledgers is older than 24 hours. The cause is that the minute-by-minute update frequency for incremental indexing is not configured, and `usingReRank` is not used to sort by time weight.
- The application only recalls ledger data within the knowledge base, and cannot call online search to supplement external information. The symptom is that the generated report does not include external real-time data such as temporary traffic control or section construction. The cause is that the knowledge base retrieval link defaults to limiting the data source range, and related settings that allow cross-source retrieval are not configured.

## How to confirm the configuration is correct
- Enter the knowledge base collection management interface, check that the bound dedicated collection ID only covers highway operation ledger data.
- Launch a test query that includes a section number and time range, verify that the returned result fields match the standard structure of highway operation ledgers.
- View the retrieval log, confirm that the initial number of recalled entries and the reranking logic match the configured requirements.
- Trigger the application to call the online model, verify that external information outside the knowledge base can be obtained, and confirm that the data source restriction configuration is correct.
