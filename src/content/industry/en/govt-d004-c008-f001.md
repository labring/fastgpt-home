# Health Diagnostic Report Inspection Monitoring and Alarm Analysis: HTTP Interfaces and External Systems

## What the data for this category looks like
Health diagnostic report data comes from industrial inspection sensors, equipment operation and maintenance systems, and on-site inspection terminals. The update rhythm follows the inspection cycle, usually once daily, and is generated in real time when an exception is triggered. Documents are in structured format, with core fields including unique device identifier, inspection timestamp, monitoring parameters such as temperature, pressure, vibration amplitude (units are ℃, MPa, mm/s respectively), preset alarm thresholds, automatic diagnosis conclusions and disposal suggestions. The character count of a single report ranges from 800 to 1500 characters.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The structured fields of health diagnostic reports are numerous and carry fixed units of measurement, requiring HTTP interfaces to explicitly specify the fields to be returned and unit mappings in request parameters to avoid parsing errors. Single reports have large character counts and support batch uploads, so the maximum allowed request body size for the interface must be configured to no less than 1000 KB. Both routine reports driven by inspection cycles and real-time reports triggered by exceptions exist, requiring the interface to support both scheduled query by device ID and abnormal event callback invocation modes. The unique device identifier is the core query condition, so the interface must validate the format of the device ID carried in the request to ensure accurate data matching.

## How to set up the configuration
This configuration applies to FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${external_token}` | Complies with general HTTP authentication specifications, adapts to the token verification logic of external systems |
| `variables` | `{"target_device": "device ID", "report_scope": "routine/alert"}` | Passes the core query conditions for health diagnostic reports, meets the parameter verification rules of external interfaces |
| `responseData` | Return fields: deviceId, checkTime, temperature, pressure, vibration, diagnosisResult | Filters non-essential data, reduces transmission overhead and parsing time |
| Request timeout | `600 seconds` | Adapts to the character size of single reports, avoids timeout errors caused by data transmission delays |
| Batch upload threshold | `First 10 reports per request` | Balances interface load and data synchronization efficiency, avoids overload from single requests |

## Three common mistakes
- The symptom is that the interface call returns a 401 unauthorized error, or the logs of the connected external interface show that the received token is the fixed string `fastgpt`. The cause is that the token generated by FastGPT was not correctly filled into the `Authorization` configuration item, or a fixed test string was mistakenly written as the token during configuration.
- The symptom is that missing report fields or mismatched units are returned after calling the interface. The cause is that the fields to be returned and unit mappings were not explicitly specified in the `responseData` configuration, resulting in redundant or non-compliant data being returned by the external interface.
- The symptom is that an SQL permission error occurs when calling the interface after restarting the Docker container. The cause is that the local data volume was not correctly mounted after the container restart, or insufficient database access permissions were assigned to the FastGPT container, causing the health diagnostic report query logic to fail to read data normally.

## How to confirm the configuration is complete
- Call the configured HTTP interface, check whether the authentication field format in the returned response header complies with the Bearer token specification.
- Compare the fields returned by the interface with those specified in the `responseData` configuration, confirm that the core monitoring parameters and units are returned correctly.
- Simulate an abnormal inspection scenario to generate a health diagnostic report, call the interface to verify that the corresponding report data can be obtained.
- Restart the FastGPT container, call the interface again to confirm that there are no SQL permission-related errors.
