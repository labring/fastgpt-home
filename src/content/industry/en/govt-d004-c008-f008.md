# Health Diagnostic Report Inspection Monitoring and Alarm Analysis: Document Parsing and Chunking
This document applies to FastGPT v4.17.0.

## What This Type of Data Looks Like
Most data for health diagnostic reports comes from offline files exported by industrial equipment inspection systems and record documents synced from on-site inspection terminals. Update frequency follows the inspection cycle. A single report generated during one inspection covers parameter data for multiple devices. The document structure includes a fixed header area, structured parameter tables, text descriptions of equipment status, and supporting infrared thermograms or vibration waveform charts. Fields include equipment ID, inspection time, temperature (℃), vibration amplitude (mm/s), alarm level, exception handling suggestions, and other items. Each field has a clear physical unit.

## What Constraints Do These Characteristics Place on Document Parsing and Chunking
The structured features and large file size of health diagnostic reports create multiple constraints for parsing and chunking. First, embedded tables and text descriptions must retain content relevance. Do not truncate the correspondence between parameters and alarms during chunking. Second, a single report often contains data from multiple devices and images. Parsing takes a long time. A reasonable timeout threshold must be set. Third, report layouts vary across different inspection batches. Flexible adjustment of chunking rules must be supported to avoid merging or truncation errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Health diagnostic reports often contain multi-device inspection data and infrared images. Single files have large sizes. This setting must support large file upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 seconds` | The parsing process for large health diagnostic reports includes image recognition and text extraction. Sufficient processing time is needed to avoid mid-run interruptions |
| `chunkSplitter` | Paragraph + table separators | Health diagnostic reports include structured tables and long-form inspection descriptions. This setting must retain relevance across different content chunks |
| `chunkSize` | `1000–1500 characters` | Balance content completeness per chunk and retrieval accuracy. Avoid truncating the correspondence between equipment parameters and alarm information |
| `customPdfParse` | Enabled | Health diagnostic reports often include embedded tables and images. Enabling custom parsing preserves structured data and visual content |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters based on the layout density of reports from different inspection batches. Adapt to diverse document formats |

## Three Common Configuration Mistakes
- Uploading a 3 MB health diagnostic report triggers an upload failure error. The interface returns a generic error prompt. The cause is failing to adjust `UPLOAD_FILE_MAX_SIZE` to a threshold matching the file size. The default configuration does not support large inspection report files.
- Setting a custom separator to line breaks leads to chunking results that either merge multiple independent paragraphs or truncate table rows containing complete parameters. The cause is failing to select an appropriate `chunkSplitter` based on the structured features of health diagnostic reports. Using only line breaks cannot distinguish between table and text content.
- Using a Docker-deployed Marker parser to process a health diagnostic report PDF returns error logs. The cause is failing to correctly configure associated environment variables for `customPdfParse` in FastGPT. This prevents the parsing engine from calling dependent tools.

## How to Confirm Correct Configuration
- Upload a single standard-sized health diagnostic report. Check if parsing completes within the configured timeout threshold. Confirm the overall parsing process runs normally.
- Export chunked text fragments. Verify that complete correspondence between equipment parameters and alarm information is retained. Confirm chunking rules match document layout characteristics.
- Test uploading multiple health diagnostic reports with different layouts. Check if parsing results correctly preserve structured information from embedded tables and images.
- View file parsing logs in the knowledge base backend. Confirm no timeout or format error prompts appear. Verify configuration stability.
