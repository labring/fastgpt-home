# Health Diagnostic Report Inspection Monitoring and Alarm Judgment: Deployment and Upgrade

## What the data for this category looks like
Health diagnostic report data comes from equipment operating parameters collected by industrial inspection terminals, status logs manually entered during inspections, and abnormal logs triggered by backend alarm systems. Updates are triggered alongside inspection tasks. A single report generated during one-time inspection is a one-time update. For bulk inspection scenarios, data is synchronized on a fixed daily or weekly cycle. The document structure includes unique device identifier, inspection timestamp, core monitoring indicators (temperature, pressure, current, etc., with corresponding engineering units such as degrees Celsius, megapascals, amperes), abnormal threshold matching results, automatically judged alarm level, and manual review opinion fields.

## What constraints these characteristics impose during deployment and upgrade
Multi-source data access requires configuring storage adapters compatible with industrial protocols during deployment, to prevent data format incompatibility that causes failed data import. High-frequency updated inspection reports and alarm logs generate a large number of write requests, so database connection pool parameters must be adjusted to adapt to concurrent load. Fixed field structures require pre-creating database tables with indexes, to avoid write exceptions caused by field changes during upgrades. For alarm judgment data with high timeliness requirements, appropriate cache expiration policies must be configured to ensure query responses meet business requirements.

## How to configure settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `150–250 connections` | Adapts to database connection needs for concurrent writes from multiple inspection terminals, preventing connection exhaustion |
| `MONGODB_URI` | Enter the full authenticated connection string for a local private cloud MongoDB instance | Alarm logs and historical inspection details for health diagnostic reports are suitable for storing unstructured data with MongoDB |
| `PG_URL` | Enter the PostgreSQL instance connection string, configure connection timeout to `60 seconds` | Stores structured metadata such as device ID and inspection time, ensuring stability of relational queries |
| `REDIS_URL` | Configure the local Redis instance address, set cache key expiration time to `300 seconds` | Caches frequently queried inspection report summaries to reduce response latency for alarm judgment |
| `STORAGE_S3_ENDPOINT` | Enter the endpoint address of the private object storage | Stores original attachments of inspection reports and original sensor collection data |
| `FILE_TOKEN_KEY` | Generate a 32-bit random encrypted string | Encrypts file upload access tokens to prevent unauthorized access to report files |

## Three common configuration errors
- A `connection refused` error appears after startup, and historical inspection data cannot be loaded. The cause is incorrect configuration of `MONGODB_URI` or `PG_URL`, pointing to a database instance that is not started or unreachable over the public network.
- Uploaded inspection report attachments cannot be read by the system. The cause is failure to configure `STORAGE_S3_ENDPOINT` to point to private object storage, or the key generated by `FILE_TOKEN_KEY` does not match the upload interface, resulting in denied file access.
- Some inspection report judgment results are empty after upgrade. The cause is failure to synchronously update structured indexes in the database during upgrade, causing new report fields to fail to be retrieved and parsed.

## How to verify configurations are successful
- Run the database connection test script to verify that the configurations for `MONGODB_URI` and `PG_URL` can establish normal connections, with no timeout or rejection errors.
- Upload a test inspection report attachment to verify that the `STORAGE_S3_ENDPOINT` configuration is correct, and that the attachment can be stored normally and previewed within the system.
- Initiate a simulated inspection task to generate a health diagnostic report, verify that the `REDIS_URL` cache configuration takes effect, and that the report query response time meets expectations.
- Check the `DB_MAX_LINK` configuration value, and use database monitoring tools to confirm that the current number of connections does not exceed the set threshold, with no connection exhaustion.

The values given are common starting points and should be measured against the reader's own samples.
