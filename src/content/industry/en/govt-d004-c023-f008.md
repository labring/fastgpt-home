# Multi-source Monitoring Data Fusion for Patrol Inspection Monitoring and Alarm Analysis: Document Parsing and Chunking

## What the data for this category looks like
Multi-source monitoring data for patrol inspection monitoring and alarm analysis comes from various monitoring devices, operation and maintenance systems, and manual patrol records in state-owned enterprise, public service, and government public sectors.
Data sources include power SCADA systems, municipal water supply sensors, traffic cameras, and operation and maintenance log systems.
Update frequencies range from real-time values measured in seconds to monthly patrol summaries updated daily.
Document structures are mixed: structured parameter reports, semi-structured patrol PDF reports, device capture images, and plain-text alarm logs.
Fields include device unique identifiers, real-time monitoring values, alarm levels, and timestamps.
Units follow industry-specific measurement standards such as power, pressure, and temperature.

## What constraints do these characteristics impose on document parsing and chunking?
Diverse, heterogeneous document formats require the parsing workflow to support multiple file types, to avoid losing monitoring data due to unsupported formats.
Update frequencies from seconds to days mean the parsing process cannot take too long, otherwise it cannot meet real-time alarm analysis requirements.
Long patrol summary documents may contain dozens of pages of device records. Chunking must avoid splitting associated data of adjacent devices, or subsequent alarm correlation analysis will be impacted.
Patrol reports with embedded images require additional optical character recognition (OCR) capabilities to extract real-time monitoring values from the images. Without this, only plain text content can be retrieved.

## Configuration Settings
This guide is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to mixed content in patrol reports that includes both parameter sections and text descriptions, avoiding truncation of alarm-related information for adjacent devices |
| `chunkSplitter` | Semantic segment splitting | Adapts to scenarios where structured parameters and unstructured descriptions are mixed in multi-source data, preserving the complete logical integrity of information |
| `customPdfParse` | Enable OCR mode | Addresses scenarios where patrol reports contain embedded camera capture images, extracting real-time monitoring values from images |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch import of multiple large monthly patrol summary documents, meeting the needs of bulk knowledge base construction |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the time consumption requirements of long document parsing, avoiding parsing process interruptions due to timeouts |
| `chunkSettingMode` | Manual configuration | Adapts to the differentiated parsing needs of multi-source data, allowing separate adjustment of parameters for different document formats |

## Three Common Configuration Mistakes
- Symptom: After uploading camera capture images or patrol PDFs with embedded images, the parsing result does not include monitoring values from the images. Cause: The OCR switch for `customPdfParse` is not enabled, or the corresponding image parsing model is not configured.
- Symptom: After exporting an old server knowledge base to Excel and importing it to a new server, some patrol alarm records are missing or fields do not match. Cause: The original chunking configuration is not retained during import, or the `chunkSize` setting is too small, truncating key fields that include device IDs.
- Symptom: When parsing a long patrol report, adjacent device alarm records are split into different chunks, leading to failed correlation analysis. Cause: The `chunkSize` is set too small, and the `chunkSplitter` configuration for semantic segment splitting is not enabled.

## How to Verify Correct Configuration
- Upload a mixed-format patrol document that includes camera capture images, structured tables, and text descriptions. Confirm that the parsing result includes monitoring values from images and table field content.
- Import a structured Excel-format patrol data set. Verify that imported knowledge base entries match the original file’s fields and quantity.
- Adjust the `chunkSize` parameter, then upload a long document with multiple segments of device records. Confirm that chunking results retain the association between adjacent device alarm records.
- View parsing configuration items in platform settings. Confirm that values for parameters such as `customPdfParse` and `UPLOAD_FILE_MAX_SIZE` match the preset configuration.
