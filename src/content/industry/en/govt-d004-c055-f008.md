# Tunnel Alert Filtering: Patrol Monitoring and Alert Judgment - Document Parsing and Chunking

## What this category of data looks like
Various monitoring sensors deployed along tunnels, operation and maintenance patrol records, and emergency response ledgers provide data for this category. Update frequency varies with monitoring point density, with no fixed cycle. Document types include structured alert log tables, unstructured patrol report PDFs, and Excel-format alert summary sheets. Fields include alert code, monitoring point number, alert trigger time, alert threshold, device ID, and handling status. Units include seconds, degrees Celsius, millimeters, percentage, and similar units.

## Constraints on document parsing and chunking
Retain field associations when parsing structured alert log tables with fixed field formats, to avoid losing the correspondence between alert codes and monitoring points after chunking.
Parse Excel-format alert summary sheets that include multiple sheets and merged cells, and restore merged cell content across sheets.
Separate text from auxiliary metadata when parsing unstructured patrol reports with mixed text and image layouts, while retaining spatial location information of patrol points.
Dynamically adjust resource usage for parsing and chunking to accommodate fluctuating volumes of real-time updated alert data, to avoid single parsing timeouts.

## How to set configurations
This guide is for FastGPT v4.17.0. Use the following configuration items tailored to this version:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Matches the length of single alert records and associated text for alert data, ensuring each chunk contains complete alert context and handling instructions |
| `chunkSplitter` | Split by field association | Retains the binding relationship of core fields such as alert code and monitoring point, to avoid losing data association after chunking |
| `customPdfParse` | Enabled | Restores device point annotations, merged cell tables, and mixed text-image layouts in tunnel patrol PDFs |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 seconds` | Adapts to large Excel alert summary sheets with multiple sheets, to avoid timeout errors during parsing |
| `chunkSettingMode` | Manual configuration | Sets differentiated chunking rules for structured alert logs and unstructured patrol reports respectively |

## Three common mistakes
- Symptom: Uploading a large Excel alert summary sheet may trigger a platform timeout error with elapsed time exceeding 60000ms. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default timeout duration is used, which cannot cover the parsing time of multi-sheet documents.
- Symptom: Searching alert data may return fewer results than the actual recorded volume. For example, searching for alerts with a usage location abroad yields insufficient matching results. Cause: The association information of filter fields such as usage location is not retained during chunking, or auxiliary metadata is not bound to the main text, resulting in auxiliary information not being included in the search scope, or chunk granularity being too large, causing fields to be split into different chunks and unable to be matched by the search engine.
- Symptom: Uploading a tunnel patrol PDF may result in lost device point annotations and merged cell table content, with key spatial location information missing from parsed text. Cause: The `customPdfParse` configuration is not enabled, and native parsing logic cannot adapt to the special layout format of tunnel documents.

## How to verify correct configuration
- Upload a single structured alert log, check if parsed chunks contain complete alert code, point number, and trigger time, to confirm field associations have not been split.
- Upload an Excel alert summary sheet with multiple sheets, wait for parsing to complete, verify no timeout error is triggered, and confirm parsing time matches expected document volume.
- Upload a tunnel patrol PDF, check if parsed results include device point annotations and restored merged cell table content, to confirm layout format was correctly recognized.
- Test searching for alert data under specified conditions, verify returned result count matches actual recorded volume, to confirm chunking rules adapt to search requirements.
