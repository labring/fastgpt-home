# Tunnel Alert Filtering: Patrol Monitoring and Alert Judgment - Model Access and Configuration

## What this category of data looks like
Tunnel alert filtering data comes from temperature and humidity sensors, smoke detectors, video surveillance equipment, vibration sensors, and fire linkage systems deployed along tunnels. Data updates in real time or near real time. Each alert document includes these fields: unique device identifier, alert type code, trigger timestamp, preset threshold, current collected value, associated tunnel section number. The alert level field is an enumerated value. The current collected value includes a corresponding physical unit. Some alerts also include the address of a thumbnail for associated video clips.

## What constraints do these characteristics impose on the model access and configuration link
Real-time tunnel alert data requires the model access link to use low-latency calling logic. This avoids delayed alert processing caused by call timeouts.
Each single alert includes multi-dimensional fields and optional video attachments. Configurations must reserve sufficient context carrying space, and support visual model calls to parse associated video clips.
Alert fields bind enumerated values to physical units. Model input must clearly specify field parsing rules, to avoid judgment errors from field confusion.
For batch alert push scenarios, limit the number of input entries per model call. This prevents exceeding the model context limit.

## How to set the configuration
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the context carrying requirements of multi-field single alerts and optional video descriptions, avoiding alert information truncation caused by context overflow |
| `maxTokens` | `2000 token` | Limits the output length of a single alert judgment, ensuring that the judgment result can be quickly received by the patrol system |
| `quoteMaxToken` | `1500 token` | Limits the length of alert history fragments retrieved from the knowledge base, avoiding redundant information occupying model context space |
| `vision` | `Enabled` | Adapts to the parsing requirements of video thumbnails carried by some alerts, completing visual judgment of abnormal frames |
| `temperature` | `0.1–0.3` | Reduces randomness in alert judgment, ensuring consistency between filtering rules and threshold judgments |
| `AIPROXY_API_ENDPOINT` | Fill in the proxy address according to the actual deployment environment | Implements internal network proxy forwarding for model calls, adapting to access restrictions in state-owned enterprise and public service scenarios |
| `AIPROXY_API_TOKEN` | Fill in the exclusive key assigned by the platform | Completes identity verification for the proxy service, ensuring the security of model calls |

## Three common configuration mistakes
- Accidentally configuring `AIPROXY_API_ENDPOINT` as the service address of OneAPI, resulting in model calls returning 404 or authentication failure. This occurs because the interface differences between different proxy services are not distinguished, and the deployment type of the proxy service is confused.
- Failing to enable the `vision` configuration item, resulting in visual judgment being unable to complete for alerts carrying video thumbnails, and the visual analysis field of the corresponding alert being empty. This occurs because the scenario of visual attachments in tunnel alerts is not recognized, and the necessary configuration for visual model calls is omitted.
- Failing to configure external parsing logic according to FastGPT's return format, resulting in the inability to correctly parse the combined result of knowledge base calls and streaming returns when `detail: true`. This occurs because the field structures of streaming and non-streaming returns are not clearly distinguished, and the parsing rules for combined returns are omitted.

## How to confirm the configuration is complete
- Enter the FastGPT model management page, view the configured proxy services, and confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the actual deployed services.
- Upload a test alert document carrying a video thumbnail, trigger a model call, and check whether the returned result includes content related to visual judgment.
- Submit batch alert test data, and verify that the returned result of the model call does not show prompt information about context truncation or overflow.
- Adjust the `temperature` parameter to 0.2, call the same alert template multiple times, and confirm the consistency of the judgment results.
