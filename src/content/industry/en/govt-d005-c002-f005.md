# Q&A on Policy and Institutional Basis for "One Thing Done Efficiently" Joint Handling: Tool Calling and Plugins

## What the data for this category looks like
Data for this category mainly comes from the National Government Service Platform "One Thing" Special Zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. The update frequency is daily. Commonly involved documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation forms, parallel approval opinions, and completion receipts. Most document structures include fields such as item identification, cross-department collaboration scope, material list, and handling procedures. There is no unified fixed unit; fields adjust based on the cross-department scope of joint handling items.

## What constraints these characteristics impose on the tool calling and plugin link
Multi-source heterogeneous data sources require tool calling to adapt to interface formats of different platforms to avoid cross-department data parsing exceptions. The daily update frequency requires configuring scheduled synchronization tasks to ensure policy documents in the knowledge base align with official update rhythms. Multiple types of document structures including joint handling item lists and material circulation forms require tool calling to support field mapping functions to align content from different documents to the standard format of joint handling items. The attribute of cross-department combined handling requires plugins to link approval interfaces of multiple departments to achieve real-time acquisition and aggregation of parallel handling statuses.

## Three common mistakes
- Phenomenon: Missing fields in the joint handling material list returned after calling the policy Q&A tool. Cause: The output fields of the tool were not mapped to the standard field format of the joint handling application form.
- Phenomenon: An error is returned when calling the interface via curl, containing the `$schema` field. Cause: Invalid metadata fields were mixed into the tool calling configuration, and the FastGPT input format requirements were not strictly followed.
- Phenomenon: Unable to view historical calling logs for a single policy document. Cause: The traceability log switch for tool calling was not enabled, resulting in no calling records being saved.

## How to confirm the configuration is correct
- Initiate a policy Q&A request targeting a joint handling item, check if the tool calling return results include complete content such as joint handling item lists and material requirements.
- Enter the tool calling log page, confirm that calling records for single policy documents have been properly saved, including information such as calling time and returned content.
- Initiate a curl test call, verify that the interface returns no errors related to `$schema` fields, and confirm that the input format meets requirements.
- Test access to bound departmental data sources, confirm that approval data from corresponding joint handling departments can be obtained, and verify that the plugin linkage function works properly.
