# Q&A on Policy and Institutional Basis for "One Thing Done Efficiently" Joint Handling: Document Parsing and Chunking

## What Data for This Category Looks Like
The data for this category is primarily sourced from the "One Thing Done Efficiently" special zone of the national government service platform, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. The update frequency is daily. Commonly processed documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts. Document structures cover fields such as cross-departmental item association rules, application material lists, and processing node circulation information. Document formats and fields submitted by different departments vary.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
The daily updated data source requires the parsing process to support incremental synchronization to avoid repeated processing of full documents. Multiple types of documents with inconsistent formats require chunking rules to adapt to different document structures and avoid splitting cross-departmental associated information. The association of cross-departmental fields requires that chunks not be too fragmented, and sufficient contextual association information must be retained. Otherwise, the accuracy of subsequent question answering will be affected. A single document may contain approval content from multiple departments, so it is necessary to accurately identify the processing nodes of different departments to avoid joint handling process matching errors caused by chunk confusion.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the field lengths of multiple types of documents such as joint handling item lists and approval opinions, and retain contextual information for cross-departmental associations |
| `chunkSplitter` | Customized by document type | Distinguish between list-type, form-type, and circulation sheet-type documents to match the structural characteristics of different content |
| `customPdfParse` | Enable structured parsing | Adapt to PDF documents with form fields such as joint handling application forms and completion receipts, and extract structured departmental association and material information |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Match the conventional maximum size of single files for government joint handling documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapt to the time consumption requirements of merged parsing of multi-department documents and avoid parsing interruptions |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for special fields in joint handling scenarios to adapt to differences in cross-departmental documents |

## Three Common Misconfigurations
- Phenomenon: Calling the FastGPT v4.17.0 API to retrieve chunked index content returns empty fields. Cause: The `chunkSplitter` parameter is not configured for cross-departmental documents in joint handling scenarios, resulting in chunking failing to retain associated index fields.
- Phenomenon: Parsing times out when uploading a joint handling item list. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is too small and does not match the actual time required for merged parsing of multi-department documents.
- Phenomenon: When copying parsed content on the frontend page, the prompt "Unable to use browser automatic copy, please manually copy the content below" appears. Cause: Cross-origin resource sharing rules are not configured, which is a non-same-origin access restriction.

## How to Confirm the Configuration Is Complete
- Upload a single joint handling item list and check whether the parsed chunks retain core fields such as item number and associated department.
- Batch upload the joint handling documents updated on the current day and confirm that the parsing time does not exceed the set value of `PARSE_FILE_TIMEOUT_SECONDS`.
- Call the FastGPT v4.17.0 API to retrieve chunked data and verify that the index fields are fully present.
- Upload a joint handling application form that exceeds the conventional size and confirm that the upload request is correctly intercepted or parsed successfully.
