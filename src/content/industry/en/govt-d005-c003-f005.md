# Policy and Regulatory Basis Q&A for Real Estate Registration: Tool Calling and Plugins

## What data for this category looks like
Real estate registration scenario data comes from five core data sources: real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate library. The update frequency is daily.
Daily processed documents include registration applications, ownership certificates, survey results, tax payment vouchers, real estate property rights certificates, and registers. Data fields include real estate ownership number, right holder identity information, survey coordinate range, tax payment records, and registration status. A single data entry typically contains multi-dimensional ownership association information.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multi-source heterogeneous data sources require tool calling to adapt to different interface protocols and authentication rules, to avoid calling failures caused by system compatibility issues.
Daily updated business data requires tool calling to use real-time synchronization mechanisms, to ensure that the latest daily register and ownership certificate data is called, and prevent verification errors caused by expired information.
Multiple types of daily documents require tool calling to support multi-format content extraction and field matching, to cover parsing needs for different files such as survey results and tax payment vouchers.
The time-consuming core ownership verification link requires tool calling to prioritize scheduling interfaces for ownership data sources, to reduce redundant requests and improve response efficiency.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-data-source calling logic in real estate registration scenarios, automatically selects matching tool interfaces |
| `functionCall` | `{"name": "query_property_rights", "parameters": {"required_fields": ["<property right ID>", "<right holder information>", "<registration status>"]}}` | Accurately specifies core fields to extract, avoids returning redundant data that affects verification efficiency |
| Maximum number of single tool calls | `First 3 times` | Real estate registration verification requires multiple rounds of data comparison; 3 calls cover core verification needs, and avoid excessive requests consuming resources |
| Tool call timeout period | `30 seconds` | Covers most response durations for cross-system connections, avoids calling failures caused by system delays |
| Number of retries for failed tool calls | `2 times` | Avoids calling failures caused by temporary network fluctuations, while preventing registration exceptions caused by repeated submissions |
| Data source synchronization frequency | `2 AM daily` | Matches the daily update rhythm of business data, ensures called data is in the latest state |

## Three common mistakes
- Phenomenon: Ownership data returned by tool calls does not match actual information in real estate registers, leading to deviations in verification results. Cause: Daily data source synchronization tasks are not configured, and expired cadastral survey or tax system data is called.
- Phenomenon: API calls in some regions fail, returning connection timeout or insufficient permission errors. Cause: Region whitelists for interface access are not configured, and call permissions for corresponding regions are not enabled.
- Phenomenon: Two or more tool calls are triggered simultaneously in a single conversation, leading to system response timeout. Cause: Automatic round limit for `toolChoice` is not set, and maximum number of tool calls per single conversation is not restricted.

## How to confirm configuration is complete
- A test conversation with a real estate ownership verification request is initiated, and whether tool calls trigger interface requests for corresponding data sources is checked.
- System logs are reviewed, and tool call timeout period and retry times are confirmed to meet configuration requirements, with no abnormal error records.
- Cross-region API call requests are tested, and failures caused by regional access restrictions are confirmed to be absent.
- The number of tool call rounds in a single conversation is verified, and that it does not exceed the preset call limit is confirmed.
