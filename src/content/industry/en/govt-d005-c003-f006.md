# Policy and Regulatory Basis Q&A for Real Estate Registration: Source Citation and Traceability

## What the data for this category looks like
Real estate registration scenario data comes from five core data sources: real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate library. Full daily synchronous updates are performed. Documents involved in daily business include registration application forms, ownership certificates, survey results, tax payment vouchers, real estate property certificates, real estate registration books, and others. Different documents correspond to ownership verification needs for different business links. Data fields include core identifiers such as ownership subject, location, right type, and registration time. No additional custom statistical fields are included.

## What constraints do these characteristics impose on the source citation and traceability link
Multi-source and heterogeneous data sources require the traceability link to associate metadata identifiers from different systems, ensuring that cited sources can be traced back to specific business systems. The daily update frequency requires configurations to support real-time synchronization of the latest cadastral and tax data, to avoid using outdated information. Diverse document types require traceability displays to distinguish the business attributes of different documents, enabling verification staff to quickly locate ownership sources. The serious consequences of errors in core business require the traceability link to fully retain the original information of cited fragments, without truncating key ownership verification content.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `quoteMaxToken` | 800–1200 token | Matches the length of single cited fragments from real estate registration documents, to avoid truncating key information such as ownership subject and location |
| `responseData` | Enable citation details | Return complete source document metadata as required by business rules, including system identifier and update time of the generating source |
| `detail` | Enable traceability details | Display the document type corresponding to the cited fragment, such as ownership certificate, survey results, and others, to align with business verification logic |
| Single search limit | Top 8 results | Covers the recall scope of multi-system data sources, ensuring associated data required for cross-verification such as cadastral survey and tax data is included |
| Maximum context | 6000 characters | Adapts to the context length after splicing multi-source data, meeting the complete context requirements for policy basis Q&A |
| Citation source display granularity | Classified by document type | Aligns with the practice of one-by-one verification by material type in real estate registration business, improving verification efficiency |

## Three common mistakes
- Phenomenon: The returned cited content cannot download the original file. Cause: The original file link field in the `responseData` configuration is not enabled, only text fragments are returned, and the original file address from the electronic certificate library is not associated.
- Phenomenon: The citation source field is empty in the Q&A results. Cause: The system identifier configuration of the data sources is not correctly associated, and metadata from sources such as the cadastral survey database and tax system is not injected into the Q&A context, resulting in missing traceability information.
- Phenomenon: Data cannot be split by business category when exporting the knowledge base in batches. Cause: The directory structure of the knowledge base is not pre-configured by business category, only the export granularity at the global knowledge base dimension is enabled, which cannot match the export requirements of real estate registration classified by material type.

## How to confirm the configuration is correctly set
- Submit a test query that includes an ownership verification requirement. Confirm the returned results include the document type and source system information of the corresponding document.
- Review the `quoteMaxToken` parameter on the configuration page. Confirm the value covers the common fragment length of real estate registration documents.
- Call the FastGPT v4.17.0 Q&A API interface. Verify the `responseData` field includes complete citation traceability metadata.
- Simulate a multi-source data recall scenario. Confirm the returned citation sources cover associated data from multiple systems such as cadastral survey and tax.
