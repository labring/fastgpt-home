# Policy and Regulatory Basis Q&A for Real Estate Registration: Model Access and Configuration

## What the data for this category looks like
Data for this category originates from the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate repository. The update frequency is daily. Daily documents include registration application forms, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and registers. Core fields cover real estate location, ownership subject, right type, restriction status, and other relevant items. All data uses government-standard formats, with no custom special units.

## What constraints do these characteristics impose on the model access and configuration link
Multiple data sources with daily updates require the access link to support pulling data from multiple system interfaces and completing incremental synchronization, to avoid resource consumption caused by full data pulls. Core fields involve sensitive government information such as ownership source and restriction status. During configuration, the context must be strictly limited to only calling compliant data sources. Diverse document types require adaptation to chunking logic for different documents, to ensure accurate association of corresponding materials during policy basis Q&A. Since errors may lead to administrative disputes, the accuracy of recall results must be enhanced, to avoid incorrect conclusions from fuzzy matching.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length of multi-source government documents, covering fully associated content of multiple types of materials such as registration applications and ownership certificates |
| `maxTokens` | 2000–3000 token | Controls the output length of single-round Q&A, prevents policy basis content from being truncated, and meets the complete display requirements of government Q&A |
| `quoteMaxToken` | 1500 token | Limits the maximum length of quoted documents, ensuring recalled policy basis content is accurate and does not exceed context limits |
| `temperature` | 0.1–0.3 | Reduces random generation probability, ensures content accuracy for policy basis Q&A, and aligns with the rigor requirements of government scenarios |
| `AIPROXY_API_ENDPOINT` | Configure a dedicated endpoint based on the government cloud environment | Adapts to network isolation requirements for real estate registration scenarios, ensuring data transmission security |
| `toolChoice` | auto | Allows the model to automatically select tool calls, adapting to the associated query requirements of multi-source data |

## Three common configuration errors
- Phenomenon: The policy basis table output by the model fails to render properly, and content is truncated to display `...[hide X char]` at the end. Cause: The `maxTokens` or `quoteMaxToken` parameters are not set reasonably, causing the output length to exceed the defined threshold.
- Phenomenon: Only data from a single system can be obtained after access, and information from the cadastral survey and tax systems cannot be associated. Cause: The access link for multi-source data is not configured, and only the interface of a single real estate registration system is connected.
- Phenomenon: The Q&A result shows incorrect ownership status matching, which does not match the actual register content. Cause: The `temperature` parameter is set too high, causing the model to generate content that deviates from the original policy basis.

## How to confirm successful configuration
- Initiate test questions covering real estate ownership status and surveying and mapping data association, and check whether the recall results cover the configured data source range.
- Trigger long-text Q&A containing multiple segments of policy basis, and verify that the output content is complete, with no truncation or hidden markers.
- Verify the multi-system access link, confirming that relevant content can be retrieved from both the real estate registration information system and the cadastral survey database at the same time.
- Adjust parameters and compare the output results of similar questions, ensuring that the rigor of the results meets the requirements of government scenarios.
