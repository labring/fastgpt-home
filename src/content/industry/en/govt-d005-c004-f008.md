# Policy and Regulatory Basis Q&A for Proactive Public Disclosure and Policy Publication: Document Parsing and Chunking

This document applies to FastGPT v4.17.0.

## What data looks like for this category

Documents in this category mainly come from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials, with an update frequency of once per day. Commonly processed documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Documents contain standard fields such as official document numbers, issuing units, release dates, public disclosure attributes, main text, and attachments. Statistical units include copies, entries, and articles.

## What constraints do these characteristics impose on the document parsing and chunking stage

The multi-source, high-frequency update, and rich metadata traits of this category create multiple constraints for the document parsing and chunking stage. Documents from different sources have large format differences: some are structured formats exported from document management systems, while others are unstructured web content published on portals. Parsing rules must be adapted to multiple formats. Documents include sensitive fields such as public disclosure attributes and confidentiality review markers. Chunking must fully retain metadata associations to avoid sensitive information leakage or incorrect public disclosure attribute judgments after splitting. High-frequency update requirements mean the parsing process must be lightweight to reduce processing time per document. Policy documents and their interpretation drafts have clear hierarchical structures. Chunking must retain contextual associations to avoid the risk of taking policy statements out of context.

## How to set configurations

| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | The single-paragraph length of policy document main text falls within a reasonable range. This range ensures complete context after chunking while avoiding excessively large chunks that reduce retrieval efficiency |
| `chunkSplitter` | Markdown+heading splitting | Documents in this category mostly contain structured hierarchies such as titles, document numbers, and main text. Splitting by headings preserves the logical structure of the document |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Large policy documents include multiple attachments, leading to long parsing times. This range covers processing needs for most scenarios |
| `customPdfParse` | Enabled | Documents in this category are mostly official documents in PDF format. Enabling custom parsing accurately extracts metadata such as document numbers and issuing units |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | A single batch of uploaded policy document packages may contain multiple large documents. This upper limit meets batch processing requirements |
| `chunkSettingMode` | Manual configuration | Documents in this category have significant structural differences. Manual configuration allows flexible adjustment of chunking rules to adapt to different document types |

## Three common mistakes

- Symptom: Empty fields or mismatched indexes are returned when calling the API to obtain chunked content. Cause: `chunkSettingMode` is not correctly configured to manual mode, or the `chunkSize` value exceeds the actual length range of the document.
- Symptom: The prompt "Unable to use browser automatic copy, please manually copy the content below" pops up when clicking the copy button on the page. Cause: Cross-origin restrictions exist in the deployment environment, or front-end copy permission configuration is not enabled, which is directly related to non-same-origin requests.
- Symptom: A timeout error is triggered when parsing a large policy document package. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is set too low, failing to cover the parsing time of documents with multiple attachments.

## How to confirm the configuration is correct

- Upload a typical policy document, view the parsed chunk list, and confirm that each chunk contains complete context and metadata.
- Call the API to obtain chunked index content, and verify that the returned fields match the actual document content.
- Adjust the `chunkSize` parameter, test chunking effects under different values, and confirm that they meet the document structure requirements.
- Upload a policy document package containing attachments, and confirm that the parsing process does not trigger a timeout error.

The values provided are common starting points and should be evaluated against the reader's own samples.
