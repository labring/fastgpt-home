# Policy and Regulatory Basis Q&A for Active Public Disclosure and Policy Publishing: Knowledge Base Retrieval and Recall

## What This Category’s Data Looks Like
Data sources for this category include government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. The update frequency is daily. Daily documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Data fields include document disclosure attribute, confidentiality review mark, release document number, release time limit, affiliated column, and more. The length of individual documents varies widely, ranging from several hundred-word press releases to tens of thousands-word formal policy documents.

## Constraints on the Knowledge Base Retrieval and Recall Link
The daily update frequency requires the retrieval system to support incremental indexing mechanisms. This avoids excessive computing resource usage caused by full index rebuilding.
The wide range of document lengths requires the retrieval chunking strategy to adapt to content of different lengths. This prevents key information in long documents from being truncated, or short documents from being over-split.
Fields that include disclosure attribute and confidentiality review mark require adding metadata filtering rules during the retrieval phase. This ensures only content that meets public disclosure conditions is recalled.
Release time limit and affiliated column identification require retrieval results to be associated with corresponding release channels. This ensures recalled content complies with active public release specifications.

## Configuration Settings
The following configurations apply to the knowledge base retrieval and recall function of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Aligns with semantic matching accuracy for policy text, avoids recalling low-relevance content while covering policy-related interpretation materials |
| `limit` | `Top 10` | Active public disclosure content requires coverage of multi-dimensional associated information; 10 entries balance retrieval efficiency and information completeness |
| `usingReRank` | `Enabled` | Policy text contains a large number of technical terms and synonyms; re-ranking optimizes result sorting accuracy |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Policy questions often include abbreviations and alternative names; extended queries cover more homologous documents |
| `collectionIds` | `Configured for exclusive active public disclosure datasets` | Isolates data from other categories to avoid recalling non-public content |

## Common Misconfigurations
- Phenomenon: Retrieval takes more than 30 seconds, and the interface returns a timeout prompt. Cause: The incremental indexing mechanism is not enabled. Each retrieval performs a full scan of newly added policy documents and public disclosure directories on the day, leading to excessive computing resource usage.
- Phenomenon: A single query returns content from only one knowledge base, and does not integrate results from two active public disclosure datasets. Cause: The `collectionIds` parameter is not configured correctly. Only the ID of a single dataset is bound, and all target datasets are not covered.
- Phenomenon: Retrieval results include documents that do not meet public disclosure attributes, or confidential and sensitive content. Cause: Metadata filtering rules are not configured. Recalled results are not secondarily filtered based on the document disclosure attribute and confidentiality review mark fields.

## How to Verify Proper Configuration
- A test policy document can be uploaded, and a query containing keywords from that document initiated, to confirm that the retrieval results include the document.
- After configuring incremental indexing, manually trigger daily document synchronization, check the index update log, and confirm that newly added documents have been included in the retrieval scope.
- A test query containing confidential keywords can be initiated, to confirm that the retrieval results do not return corresponding non-public documents.
- After binding multiple target datasets, initiate a cross-dataset query, and confirm that the results include relevant content from both datasets.

The values provided are common starting points and should be measured against the reader's own samples.
