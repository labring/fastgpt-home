# Policy and Regulatory Basis Q&A for Active Public Disclosure and Policy Publication: Deployment and Upgrade

## What the Category Data Looks Like
This category of data comes from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials, with a daily update frequency. Documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. They contain fields such as document number, issuing authority, release date, public disclosure attribute, confidentiality level, and approval status. The length of individual documents varies widely, and some policy documents include multi-format attachment materials.

## Constraints Imposed on Deployment and Upgrade
The daily update rhythm requires configuring an incremental synchronization mechanism during deployment to avoid full indexing consuming excessive storage and computing resources. Data from multiple sources requires adaptation to different import processes, so multi-source data access adaptation items must be configured. Documents include sensitive fields such as confidentiality level and public disclosure attribute, so sensitive information filtering rules must be configured during deployment to prevent classified or non-compliant data from entering the knowledge base. The wide variation in individual document lengths requires matching appropriate chunking and retrieval parameters to ensure retrieval accuracy. Multi-channel synchronization requirements require configuring synchronization trigger rules for multiple sites and multiple accounts during deployment to ensure timely distribution of public information.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the wide length range of policy documents and interpretation drafts, ensuring reasonable retrieval granularity |
| Single Search Limit | Top 10 entries | Matches the entry scale of public disclosure directories, avoiding returning excessive redundant information |
| Sensitive Information Filtering Threshold | Calibrated based on actual testing | Adapts to the verification requirements of confidentiality level fields, preventing sensitive data leaks |
| `DB_MAX_LINK` | 20–30 connections | Adapts to concurrent connection requirements for multi-source data, ensuring synchronization stability |
| `REDIS_URL` | Intranet-accessible cache service address | Ensures status caching for incremental synchronization, reducing full indexing frequency |
| `STORAGE_S3_ENDPOINT` | Government cloud object storage endpoint | Adapts to storage compliance requirements for government scenarios, ensuring attachment data security |

## Three Common Mistakes
- Issue: After deploying via Docker, the knowledge base remains in the indexing state with no progress updates. Cause: No incremental synchronization trigger rule is configured, and full indexing tasks run repeatedly, consuming excessive resources.
- Issue: When orchestrating conversations via HTTP requests, the returned result contains no output field content. Cause: The output mapping rule for the orchestration process is not correctly configured, and the model return content is not bound to the conversation output node.
- Issue: After packaging and starting the Docker image, a database connection failure prompt is displayed. Cause: The `MONGODB_URI` or `PG_URL` configuration inside the container is not modified, and the default local database address is still used.

## How to Confirm the Configuration is Correct
- Log in to the deployment server's log panel, view the execution records of incremental synchronization tasks, confirm that incremental updates are triggered only once per day, and no full indexing runs repeatedly.
- Upload a test document containing a confidentiality level field, trigger the retrieval process, confirm that the sensitive information filtering rules take effect normally.
- Call the HTTP orchestration interface to initiate a test conversation, confirm that the returned result contains complete conversation output content.
- Enter the container configuration page, verify that parameters such as database connection and cache address match the deployment requirements.
