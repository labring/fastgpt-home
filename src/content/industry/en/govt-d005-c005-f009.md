# Policy and Regulatory Basis Q&A for Property, Asset and State-owned Capital Management: Model Access and Configuration

## What the data for this category looks like
The documents covered by this category include property registration forms, asset appraisal reports, property transfer plans, on-site transaction announcements, asset disposal approval documents, etc. Data is mainly sourced from state-owned asset supervision information systems, enterprise asset management systems, property exchange systems, appraisal institution reports and financial statements. The data update frequency is monthly. Most document structures include fields such as ownership number, asset category, book value, appraisal value, transaction approval node, etc. Fields must strictly match the standardized format requirements of state-owned asset management.

## What constraints these characteristics impose on the model access and configuration link
The data sources for this category involve internal systems and external institution reports. Permission isolation rules must be configured during model access to avoid leakage of sensitive state-owned asset information. The monthly update frequency requires that the recall and synchronization mechanism adapts to the low-frequency data rhythm, without the need for high-frequency update triggers. There are standardized differences in document fields across entities, so the model must be able to accurately match field formats from different sources. At the same time, the consequences of errors are severe, so the model's reference verification and source tracing capabilities must be strictly configured to ensure that generated content complies with state-owned asset management regulations.

## How to set configurations
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context requirements of long documents such as property transfer plans and asset appraisal reports, ensuring association matching between policy clauses and asset data |
| `maxTokens` | 2000–3000 token | Controls the output length of a single round of Q&A, avoiding generated content that exceeds the format of state-owned asset approval documents |
| `quoteMaxToken` | 1500 token | Limits the length of referenced original policy documents and asset document fragments, ensuring referenced content is precise and complies with compliance requirements |
| `temperature` | 0.1–0.3 | Reduces generation randomness, ensuring matching results between policies and asset data are rigorous and comply with compliance requirements of state-owned asset management |
| `AIPROXY_API_ENDPOINT` | Fill in the official access address according to the deployment environment | Adapts to the internal network environment of state-owned asset systems, ensuring stability and security of model calls |
| `AIPROXY_API_TOKEN` | Set the key validity period based on actual testing | Adapts to the rhythm of monthly data updates, regularly rotating keys to ensure interface security |

## Three common configuration errors
- Attempting to use native model keys fails access, with an interface call failure prompt. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters are not filled correctly, or the official access rules of the model are not followed.
- Adding a third-party model channel passes testing, but the channel shows as unavailable after deployment. Cause: The internal network isolation restrictions of the state-owned asset system are not considered, and no proxy or access whitelist is configured.
- A "No available channels under current group default" prompt appears when initiating policy Q&A. Cause: The configured model channel is not bound to the corresponding Q&A group, or channel permissions are not correctly assigned.

## How to confirm configurations are complete
- Perform a model connectivity test, confirm that the interface returns normally, with no prompts for unavailable channels or call failures.
- Upload a single property registration form and the corresponding policy document, initiate a Q&A test, and verify that the model can correctly associate the two contents.
- View the context loading log, confirm that the document fragment loading length matches the expected range of the configuration parameters.
- Bind the configured model channel to the corresponding Q&A group, verify that no "No available channels under group" error occurs during Q&A calls.
