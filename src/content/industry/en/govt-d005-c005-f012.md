# Policy and Regulatory Basis Q&A for Property, Asset and State-owned Capital Management: Deployment and Upgrade

## What the data for this category looks like
Data for this category originates from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, appraisal agency reports and financial statements. Daily processed documents include property registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements and asset disposal approval forms. Both structured form data and unstructured text descriptions are included.
Fields in a single document include asset number, ownership unit, appraisal value, transaction status and other items, with units such as ten thousand yuan, square meter and piece. The data update frequency is once per month, mostly consisting of batch-synced stock assets and policy documents.

## What constraints these characteristics impose on deployment and upgrade
Deployments must connect different databases and storage services to support multiple heterogeneous data sources. Configure parameters including `MONGODB_URI` and `PG_URL` to adapt to storage of structured and unstructured data.
Upgrades must support batch incremental synchronization scheduling logic to match the monthly update rhythm, to avoid service lag from excessive single synchronization data volume.
The system must support parsing multiple file types to handle diverse document formats. In addition, errors in state-owned asset-related data have severe consequences. Deployments must include reliable permission control and failure retry mechanisms to prevent data leaks or incorrect data flow.

## How to configure parameters
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Enter the MongoDB cluster address connected to the state-owned assets system, including database authentication information | Used to store vector indexes and metadata for unstructured documents such as property rights transfer plans and on-site transaction announcements |
| `PG_URL` | Enter the PostgreSQL database address connected to the enterprise asset management system, including access permissions | Used to store standardized structured data such as asset numbers, ownership units and transaction status |
| `REDIS_URL` | Enter the intranet-deployed Redis service address, set an access password | Used to cache frequently queried policy clauses and basic asset data to reduce concurrent access pressure on the database |
| `DB_MAX_LINK` | Set to `20–30` | Adapt to scenarios of concurrent queries from multiple departments of the state-owned assets system, avoid exhausting database connections |
| `STORAGE_S3_ENDPOINT` | Enter the endpoint address of the intranet object storage service | Used to store attached files such as asset appraisal reports and asset disposal approval forms, comply with compliance requirements for data retention |
| `FE_DOMAIN` | Set to the intranet-deployed frontend access domain name | Used to generate compliant document preview links, adapt to intranet access permission rules of the state-owned assets system |

## Three common misconfigurations
- Issue: An error "connection timeout or permission denied" appears when connecting to an external database. Logs show status code 110. Cause: The IP address of the FastGPT deployment server was not added to the database whitelist, so cross-network access is blocked.
- Issue: After upgrading to FastGPT v4.17.0, the service fails to start with a prompt that the configuration file is missing. Cause: The old version's `config.json` configuration was not fully migrated to environment variables or the new configuration interface, and some deployment scripts did not automatically complete configuration conversion.
- Issue: After cloning a specified version of code from GitHub, the displayed version number does not match the expected one. Cause: The corresponding tag branch was not switched to, and the latest development branch code was pulled by default, resulting in version mismatch.

## How to confirm configuration is complete
- Run the built-in database connection test tool to verify that the databases configured with `MONGODB_URI` and `PG_URL` can normally read and write asset and policy data of this category.
- Initiate a frequently queried policy clause request, check the cache hit rate of the returned results, and verify that the `REDIS_URL` configuration takes effect.
- Upload an asset appraisal report attachment, check whether it can be normally stored via the storage service corresponding to `STORAGE_S3_ENDPOINT` and generate a preview link.
- View system operation logs, confirm that the number of connections for `DB_MAX_LINK` does not exceed the set threshold, and there are no errors related to exhausted connections.

The values provided are common starting points and should be measured against the reader's own samples.
