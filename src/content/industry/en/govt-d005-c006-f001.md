# Policy and Regulatory Reference Q&A for Infectious Disease Information Reporting and Monitoring: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
The service subjects for this category are disease control institutions, medical facilities, public health departments, and disease control divisions of health commissions. Daily documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Data sources are the Chinese Disease Prevention and Control Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems, with daily updates. Document fields cover basic case information, diagnosis results, reporting time limits, correction information, and more. Units include dates, counts, test values, and more. Format requirements under statutory infectious disease reporting rules must be strictly followed.

## What Constraints These Characteristics Impose on the HTTP Interfaces and External Systems Link
Multiple data sources require interfaces to support permission verification and data pulling from multiple external systems, to avoid permission conflicts during cross-system calls. The daily update frequency requires the interface call cycle to match the data synchronization rhythm, to prevent duplicate pulling or missed daily data. The strict format requirements for document fields mean interface parameters must cover all required fields, to avoid invalid reports caused by missing fields. Error consequences include delayed epidemic alerts and regulatory notifications, so interfaces must have failure retry and exception alert capabilities to ensure the accuracy and timeliness of data reporting.

## Three Common Mistakes
- Issue: Returns a 400 status code when passing JSON-format parameters via an HTTP request, with a prompt indicating incorrect parameter format. Cause: The `Authorization` authentication header was not set correctly, or the request body does not follow the JSON structure required by the interface.
- Issue: The collection of infectious disease reports generated by the interface call does not match the collection data created in the interface, with deviations in field order or content. Cause: The correct CSV file field mapping rule was not configured in `variables`, leading to misalignment during interface data parsing.
- Issue: The policy reference returned by the Q&A does not match the queried infectious disease reporting rules, and the number of results exceeds expectations. Cause: The maximum number of retrieved entries was not limited, or the query statement was not optimized for the disease control business scenario, introducing irrelevant content.
