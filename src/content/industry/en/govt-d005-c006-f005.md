# Policy and Regulatory Basis Q&A for Infectious Disease Information Reporting and Monitoring: Tool Calling and Plugins

## What the data for this category looks like
Core data for this category comes from the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems, with daily updates. Daily processed documents include infectious disease reporting cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Document fields cover case identifiers, reporting institutions, diagnosis times, correction status, clustered epidemic scale, and more. All data must be generated and circulated strictly in accordance with legal infectious disease reporting rules, with no additional custom statistical fields.

## What constraints these characteristics impose on tool calling and plugin workflows
Since data sources include multiple independent internal business systems, tool calling must support cross-system interface linkage to ensure synchronous retrieval of case reports, correction records, and original policy documents. The daily data update requirement means tool calling trigger logic must adapt to daily task scheduling, avoiding high-frequency repeated calls that consume system resources. Documents must strictly adhere to legal reporting rules. Tool output Q&A results based on policy basis must fully align with officially released regulatory content, with no tampering or omission of key rules. For core time-consuming tasks such as verifying case time limits and correcting duplicate reports, tool calling must quickly locate historical report data and policy clauses to assist with verification work.

## Configuration Settings
This configuration is based on the feature set of FastGPT v4.17.0, with specific details below:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool linkage needs, automatically matches different tools such as policy query and case data retrieval |
| `functionCall` | Enabled | Supports structured output of policy basis and verification results, facilitating subsequent compliance checks |
| Single tool call timeout | 600 seconds | Adapts to the time required to retrieve data across multiple disease control systems, avoiding query interruptions |
| Maximum recall results | Top 10 entries | Covers core policy documents and historical report data, avoiding redundant information interfering with Q&A |
| Context window size | 8000–12000 tokens | Carries complete case reports and original policy content, ensuring complete Q&A context |
| Streaming output toggle | Enabled | Improves interactive experience for long-content Q&A, reducing user perceived wait time |

## Three Common Configuration Errors
- Symptom: Returns parameter errors after initiating a multi-tool calling request. Cause: Failed to correctly configure the `toolChoice` parameter to `auto`, causing the tool calling logic to fail to trigger multiple valid tools simultaneously.
- Symptom: API calls for some regions fail, returning connection timeout or permission denied prompts. Cause: Failed to configure interface access permissions for the corresponding regional disease control system, causing cross-region calls to be blocked.
- Symptom: Policy links in streaming output only cover the current page when clicked, and cannot jump to a new page. Cause: Failed to add a new window jump binding rule in the streaming output callback logic, with interactive behavior not meeting user expectations.

## How to Verify Successful Configuration
- Initiate a test Q&A that includes policy query and case data retrieval, check whether corresponding results are returned simultaneously to verify that the `toolChoice` configuration takes effect.
- Call the API and view the response log, confirm that the single call timeout meets the set 600 second threshold, with no frequent timeout errors.
- Enable the streaming output toggle, test a Q&A that includes policy links, observe whether the response is returned in segments and links can normally jump to a new page.
- Check the number of recalled results, confirm that the returned content does not exceed the set top 10 entry limit, and includes policy documents and case report data for the target category.
