# Policy and Regulatory Basis Q&A for Petition Matter Handling: Deployment and Upgrade
This document is written for FastGPT v4.17.0.

## What the data for this category looks like
Data for this category primarily comes from national petition information systems, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. Commonly processed documents include petition registration forms, acceptance notification letters, transfer and assignment letters, handling opinions, reexamination and review applications, resolution plans, and more. Individual documents contain fields such as requesting party, handling milestones, and policy reference entries.
Data is updated daily. Full historical handling archives and newly added petition-related materials from the current day must be covered, to support accurate matching of policy basis.

## What constraints do these data characteristics impose on deployment and upgrade
The data characteristics of this category impose multiple constraints on deployment and upgrade:
Multi-source data access must adapt to interface specifications of different petition systems, to avoid field mismatches during synchronization.
The daily update frequency requires configuring incremental synchronization mechanisms, to reduce resource consumption from full data pulls.
Diverse document types require preset corresponding parsing rules, to ensure accurate extraction of policy reference fields from materials like petition registration forms and handling opinions.
The requirement to cover full historical archives and newly added daily data requires ensuring data migration consistency during upgrades, to avoid impacting policy queries for ongoing petition matters.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/xinfang_db?authSource=admin` | Petition business data requires persistent storage. This parameter specifies the connection address for the dedicated business database, adapting to storage needs for multi-source petition data |
| `REDIS_URL` | `redis://:auth@redis-host:6379/1` | Used to cache frequently queried policy reference entries. Set the cache validity period to 3600 seconds to reduce database access pressure |
| `DB_MAX_LINK` | `20–30` | Petition business has high concurrent query volume. This parameter limits the maximum number of database connections to avoid resource exhaustion |
| `STORAGE_S3_ENDPOINT` | Configure according to the storage service provider endpoint of the deployment environment | Used to store original documents such as petition registration forms and handling opinions, adapting to storage needs of different deployment scenarios |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Used to generate access tokens for petition documents, ensuring access security for sensitive business files |

## Three Common Misconfigurations
- Issue: Docker pull command returns a pull failure error. Proxy configuration or mirror source replacement does not resolve the issue. Cause: Mirror source address not added to Docker daemon configuration, or proxy configuration does not cover Docker network requests.
- Issue: After container startup, a prompt indicates image architecture mismatch, and service processes cannot be loaded. Cause: FastGPT image matching the arm architecture was not pulled, and an amd architecture image package was used by mistake.
- Issue: Petition document parsing fails, and policy reference fields cannot be extracted. Cause: Only MongoDB and vector database images were started, and the sandbox container for document parsing and format conversion was not deployed, resulting in failure to process unstructured documents normally.

## How to Confirm Configurations Are Correct
- Run database connection test commands to verify the validity of connections configured via `MONGODB_URI` and `REDIS_URL`, confirming normal read and write access to petition business data.
- Upload a sample petition registration form to trigger the document parsing process, check whether policy reference-related fields can be correctly extracted, and verify the validity of `STORAGE_S3_ENDPOINT` and document parsing configurations.
- View system concurrent connection count monitoring to confirm that the `DB_MAX_LINK` configuration is not exceeded, avoiding connection exhaustion during concurrent queries.
- Generate a temporary access token to verify that the `FILE_TOKEN_KEY` configuration can normally generate valid document access credentials, ensuring access permissions for sensitive files.

The values provided are common starting points and should be measured against the reader's own samples.
