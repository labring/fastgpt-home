# Policy and Regulatory Basis Q&A for Highway Maintenance and Road Property and Right Management: Tool Calling and Plugins

## What this category of data looks like
This category of data originates from highway maintenance management systems, bridge and tunnel monitoring systems, road administration patrol systems, and traffic flow monitoring data. Data is updated daily. Daily documents include maintenance plans, patrol logs, defect disposal forms, road construction permits, and road property damage compensation forms. Most document structures contain fields such as main entity information, time nodes, specific matters, and disposal results. Some documents include spatial fields like road section numbers and construction scopes. Most data consists of structured text, with a small number of numerical records linked to monitoring points.

## Constraints imposed by these characteristics on tool calling and plugin workflows
Daily data updates require tool calling to be configured with a scheduled synchronization mechanism. This ensures the policy basis and business data used in calls are up to date. The structured fields across multiple document types mean tool calling must support field mapping and association matching. For example, bind road section numbers from patrol logs to corresponding maintenance road section clauses in policies. The presence of spatial fields means tool calling must link with geographic information plugins to complete scope verification. Additionally, matching errors between business data and policy basis may lead to compliance risks. Tool calling must add a parameter verification step to avoid invalid associations.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | This scenario requires automatic matching of tool calls for policy Q&A and business data, no manual tool specification is needed |
| `functionCall` | `enabled` | Tool calls are required to obtain the latest policy clauses and business data. Enabling function call enables parameterized data extraction |
| Maximum single tool call count | First 3 entries | The number of associated entries between policy documents and business data should not be too large, to avoid context overload |
| Tool call timeout | 600 seconds | Multiple system data and policy library synchronization is required, reserve sufficient time for query and matching |
| Plugin call trigger rule | Match by Q&A keywords | Policy and regulatory basis Q&A requires precise matching of keywords such as road construction and road property damage to trigger corresponding tools |

## Three common mistakes
- Symptom: Tool calls return the `400 InternalError.Algo.InvalidParameter` error, prompting that tool parameters are invalid. Cause: Fields such as road section numbers and construction scopes in business data are not correctly mapped to tool call parameters, resulting in parameter formats that fail to meet requirements.
- Symptom: Plugins created online cannot be called in process nodes, and the process node shows that the plugin is not bound. Cause: The tool has not been registered and permission configured in the global plugin management interface, or the corresponding plugin has not been associated in the process.
- Symptom: Calling the image decoding tool returns empty results, and defect photos uploaded with patrols cannot be parsed. Cause: The image format required for the scenario is not adapted, or the used model cannot correctly recognize image content in this category of business documents.

## How to confirm correct configuration
- Manually trigger a policy and regulatory basis Q&A, check if the tool call return results include matching policy clauses and corresponding business data entries.
- View the tool call logs, confirm that parameter mapping is correct, and there are no prompts for invalid fields or missing parameters.
- Simulate typical Q&A scenarios such as road construction permit handling and road property damage compensation disposal, verify whether the plugin triggers matching according to preset keywords.
- Confirm that the current FastGPT v4.17.0 version is in use, and check that enabled tools in the plugin management interface match the configuration items for this scenario.
