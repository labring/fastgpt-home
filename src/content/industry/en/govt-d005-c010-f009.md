# Policy and Regulatory Basis Q&A for Highway Maintenance and Road Property Rights Management: Model Access and Configuration

## What this category of data looks like
This category of data mainly originates from highway maintenance management systems, bridge and tunnel monitoring systems, road administration patrol systems, and traffic flow monitoring data, with a daily update frequency. Commonly processed documents include maintenance plans, patrol logs, disease disposal orders, road-related construction permits, and road property damage compensation orders. Document fields typically include section identifiers, event occurrence times, disposal process nodes, associated permit numbers, and other items. Some fields use units such as kilometers, days, and entries.

## Constraints imposed on the model access and configuration workflow
Since data comes from multiple heterogeneous systems, model access must adapt to the format specifications of each data source to prevent field mismatch issues. The daily updated data volume must align with the FastGPT platform’s incremental update logic to avoid excessive resource consumption from full synchronization. Document types cover multiple structures including plan, log, and permit categories. Targeted chunking rules must be configured for different document types to ensure accurate matching of policy basis keywords during retrieval. Additionally, since errors may lead to road safety and compliance issues, model configuration must prioritize the relevance and accuracy of retrieval results.

## Three Common Configuration Errors
- Phenomenon: GPU resources are not utilized, and single-core CPU usage stays at 100%. Cause: The large model’s acceleration backend is not properly configured, or no deployment parameters specifying GPU usage are set, causing the model to run exclusively on the CPU.
- Phenomenon: The number of retrieval results does not match expectations, and relevant policy documents cannot be located. Cause: Context matching rules are not adjusted based on the document structure of this category, or chunking settings are unreasonable, leading to truncation of key information.
- Phenomenon: The model service cannot be connected after configuring `AIPROXY_API_ENDPOINT`. Cause: The entered service address lacks the correct port path, or the access key `AIPROXY_API_TOKEN` has insufficient permissions.
