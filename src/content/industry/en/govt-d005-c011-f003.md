# Q&A on Policy and Regulatory Basis for Pension, Work Injury, and Unemployment Benefit Verification: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for this category include social insurance management systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily. Daily associated documents include benefit application forms, payment period certificates, retirement approval forms, work injury identification materials, and unemployment insurance benefit application materials. Data fields include insured person identity identifiers, payment periods, work injury identification grades, unemployment registration durations, and other relevant fields. Some fields are linked to cross-system synchronized business records, with no redundant non-business fields.

## Constraints imposed on multi-turn dialogue and prompt engineering
Since data sources cover multiple business systems and are updated daily, multi-turn dialogue must ask questions in sequence following social insurance business processing procedures. Gradually guide users to provide cross-system linked information, and avoid missing cross-system fields in a single request. Daily document formats are inconsistent. Prompt engineering must adapt to field extraction rules for different materials to ensure accurate extraction of valid information from various application materials. At the same time, data is directly linked to benefit payment results. Dialogue output must strictly match policy basis. Each round of replies must clearly mark the cited policy-related logic, and avoid vague statements.

## How to Set Configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Max Context Window | First 12000 tokens | Adapt to the requirements of cross-system linked long business data, avoid truncating key cross-system synchronized records |
| Question Optimization | Enabled, optimized for human resources and social security business scenarios | Adapt to professional terminology of social insurance policies, convert users' colloquial questions into standardized business expressions |
| Single Search Limit | Top 6 results | Match the average number of linked documents in daily business, avoid redundant results interfering with dialogue logic |
| `messages` parameter | Retain the last 20 rounds of dialogue records | Adapt to procedural questions for multi-turn qualification review, ensure coherent historical context |
| Timeout | 600 seconds | Cover the maximum time required for cross-system data retrieval and policy matching, avoid mid-process interruptions |

## Three Common Misconfigurations
- A 404 error is returned when calling the API to initiate a dialogue. The cause is that the API path for external system docking is not correctly configured, or social insurance business-specific insured person information is not passed into the `variables` parameter, causing the system to fail to match corresponding business data.
- Non-target user dialogue content is returned when retrieving historical sessions. The cause is that the `chatId` dedicated session identifier is not correctly used, causing confusion between different users' session data.
- Cross-system linked policy basis is omitted in dialogue replies. The cause is that the max context window is set too small, truncating key data such as payment periods and work injury identification grades obtained in previous rounds.

## How to Verify Correct Configuration
- Initiate a simulated dialogue, enter the insured person's identity information, verify whether the system can link corresponding payment periods, work injury identification records and other cross-system data.
- Call the `messages` parameter to view historical dialogue, confirm that only valid context of the current session is retained, with no redundant historical records.
- Trigger a timeout test, confirm that cross-system data retrieval and policy matching are completed within 600 seconds, with no interruption errors.
- Enter questions from different business scenarios, verify whether the optimized question expression conforms to the professional terminology specifications of human resources and social security policies.

The values listed above are common starting points and should be evaluated against the reader's own samples.
