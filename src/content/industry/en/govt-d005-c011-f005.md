# Q&A on Policy and Regulatory Basis for Pension, Work Injury, and Unemployment Benefit Verification: Tool Calling and Plugins

## What data looks like for this category
Data for this category comes from social insurance handling systems, personal entitlement records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily. Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment insurance benefit application materials. Data fields include insured entity information, payment duration, benefit verification standards, qualification review conditions, and more. Field formats follow the unified social insurance data standards of the Ministry of Human Resources and Social Security, with no custom special units.

## What constraints do these characteristics impose on the "tool calling and plugins" link
The data sources for this category cover multiple business systems and are updated daily. Tool calling plugins must adapt to multi-source data synchronization to ensure obtained information is up to date. Commonly processed document types are diverse, and field formats differ across documents. Tool calling must support recognizing exclusive fields of different documents to avoid matching errors. Benefit verification results are directly linked to personal benefit payments. Tool calling output must strictly match the field logic of policy basis, and include data source identifiers to facilitate subsequent audit tracing. At the same time, concurrency of multi-data source calls must be controlled to avoid exceeding the interface bearing limit of business systems.

## Three Common Errors
- Only return XML or JSON code blocks after calling tools, without rendering expected charts. The interface plugin status shows completed but has no visualized output. The cause is that the trigger logic of the chart rendering plugin is not configured, only the data acquisition plugin is called, and the visualization link is not connected.
- The API call result differs significantly from the online chat result, with core fields missing or logical errors. The cause is that the knowledge base association parameters or prompt template are not correctly passed in the API call, causing the model to not lock the exclusive context of social insurance policies and benefit verification.
- The payment duration data returned by tool calling does not match the latest records in the social insurance handling system. The log shows that an old data source interface was called. The cause is that no data source verification is set, and the daily updated personal entitlement record data is not synchronized.

## How to Confirm Configuration is Complete
- Initiate a test query requesting pension benefit verification, check whether tool calling automatically triggers the plugin for the corresponding data source.
- View the tool calling log, confirm that the returned fields include core business fields such as payment duration and benefit standards, with no missing content.
- Compare the test results of online chat and API calls, confirm that their core logic and returned content are consistent.
- Simulate a delay scenario, check whether the plugin call completes the response within the set timeout period.
