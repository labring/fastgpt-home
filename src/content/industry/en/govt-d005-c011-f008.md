# Policy and Regulatory Basis Q&A for Pension, Work Injury, and Unemployment Benefit Verification: Document Parsing and Chunking

## What This Category’s Data Looks Like
Data for this category comes from social insurance management systems, personal benefit records, labor relations and work injury determination systems, and the electronic social security card platform. The update frequency is daily.
Commonly processed documents include benefit application forms, payment period certificates, retirement approval forms, work injury determination materials, and unemployment benefit application materials.
Document structures cover policy clauses, eligibility determination fields, and calculation data tables. Most fields relate to core items such as benefit application eligibility, payment cycles, and calculation standards. There is no fixed unified format. Some materials include embedded images and structured tables.

## How These Characteristics Affect Document Parsing and Chunking
The daily update frequency of this category’s data requires the parsing process to efficiently handle batch materials. This avoids delaying business processes due to parsing timeouts.
Diverse document types, including structured tables and embedded images, require chunking rules to adapt to different document structures. This prevents splitting key eligibility determination fields and calculation data.
This data is directly linked to personal benefit payments. Parsing accuracy directly affects subsequent calculation and review steps. Ensuring the integrity and relevance of core fields prevents loss of key context information due to improper chunking.

## Configuration Settings
This document adapts to the configuration logic of FastGPT v4.17.0. The specific configuration items are as follows:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the core field length of benefit verification documents, avoids splitting continuous eligibility determination or calculation data |
| `chunkSplitter` | Split by paragraph + heading | Matches the policy clause and material chapter structure of documents, retains context relevance |
| `customPdfParse` | Enable image text extraction + table structuring | Processes image descriptions in work injury determination materials and structured tables in payment period certificates |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for batch social insurance materials, avoids task failure due to timeout |
| `chunkSettingMode` | Manual fine-tuned configuration | Adjusts chunking rules for different document types, ensures that fields related to benefit application eligibility are not split |

## Three Common Mistakes
- Phenomenon: After uploading a PDF of work injury determination materials that includes on-site photos, only text content is extracted, and explanatory text within the images is not recognized. Cause: The image text extraction configuration of `customPdfParse` is not enabled. The default PDF parsing logic ignores embedded image content.
- Phenomenon: After uploading a JavaDoc-generated HTML interface document, no parsed content appears in the knowledge base. Cause: Parsing rules for structured HTML documents are not configured. The default parsing only recognizes standard policy document tags, and does not adapt to non-standard HTML structures generated by code.
- Phenomenon: Chunked recalled results include irrelevant benefit adjustment clauses, leading to failure to accurately match eligibility conditions during Q&A. Cause: The `chunkSize` setting is too small. This splits continuous eligibility determination conditions into multiple independent chunks, losing context-related information.

## How to Verify Correct Configuration
- Upload a single PDF of work injury determination material that includes embedded images. Check whether the parsed result includes text descriptions and structured table content from the images.
- Upload a JavaDoc-format HTML document. Verify that the parsed result extracts the document title, chapter content, and core fields.
- Import a batch of benefit application forms. Check whether the chunked result retains the integrity of continuous fields such as payment period and application eligibility.
- Submit a batch parsing task. Confirm that the total time taken does not exceed the set value of `PARSE_FILE_TIMEOUT_SECONDS`, and no timeout errors occur.

The values provided are common starting points and should be measured against the reader's own samples.
