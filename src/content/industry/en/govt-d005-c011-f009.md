# Policy and Regulatory Basis Q&A for Pension, Work Injury, and Unemployment Benefit Verification: Model Access and Configuration

## What this category of data looks like
Data for this category originates from social insurance handling systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily. Daily processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment benefit application materials. Most documents combine structured fields and unstructured certification materials. Fields cover payment duration, benefit calculation standards, and qualification review conditions. Only standardized fields and units unified by the national Ministry of Human Resources and Social Security are used.

## What constraints do these characteristics impose on model access and configuration
Multi-source data access requires configuring adaptation rules that support cross-system data pulling, to avoid question-and-answer deviations caused by incompatible data formats. Daily update frequency requires configuring automatic synchronization tasks, to ensure knowledge base content aligns with the latest policies and handling data. Processing mixed structured and unstructured documents requires the model to support association verification between form fields and certification materials. Rigorous requirements for benefit calculation-related fields require configuring strict context reference rules, to avoid generating results that deviate from policy basis. The serious nature of potential error consequences requires configuring failure alerts and rollback mechanisms, to prevent fund risks or public complaints caused by incorrect or missing benefit payments.

## How to set configurations
| Configuration Item | Recommended Value Range | Basis for This Setting |
| --- | --- | --- |
| `maxContext` | 8000–12000 characters | Must cover multiple benefit application materials, payment records, and corresponding original policy texts, to avoid truncating key calculation basis |
| `quoteMaxToken` | 3000–5000 tokens | Ensure that referenced policy clauses and certification material content are complete, to support logical deduction for benefit verification |
| `temperature` | 0.1–0.3 | Reduce output randomness, to ensure consistency between benefit calculation results and policy basis |
| `maxTokens` | 2000–3000 tokens | Control the output length of single-round question and answer, to adapt to the information reading habits of handling staff |
| `toolChoice` | auto | Allow the model to automatically trigger knowledge base retrieval, to match the corresponding policies and handling rules for the current question |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated access address according to the deployment environment | Adapt to the model call link for local or cloud deployment, to ensure normal request forwarding |

## Three common misconfigurations
- Symptom: After adding a knowledge base to a locally deployed large language model, a call error occurs. Logs show context length exceeded or format incompatibility errors. Cause: The `maxContext` configuration was not adjusted for the multi-source mixed documents of this category, causing knowledge base loading to exceed the context threshold supported by the model.
- Symptom: After configuring multiple models, a specified locally deployed large language model cannot be selected in the system. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` were not filled correctly, causing model registration information to fail to sync to the platform scheduling layer.
- Symptom: Question and answer results do not reference corresponding policy basis, only providing general calculation conclusions. Cause: The `toolChoice` automatic retrieval configuration was not enabled, or the `quoteMaxToken` value was set too small, causing referenced content to be truncated and unable to support policy matching.

## How to confirm correct configuration
The following steps can be used to verify configuration effects under FastGPT v4.17.0:
- Launch a test question containing specific benefit calculation requirements, and check whether the model output automatically associates corresponding policy clauses and handling materials.
- View platform scheduling logs, confirm that model call requests can be normally forwarded to the specified deployment node, with no connection errors.
- Manually adjust the values of configuration items, verify whether behaviors such as context truncation and output length meet expected requirements.
- Trigger a knowledge base synchronization task, check whether the question and answer results after data update synchronously reflect the latest policies or handling rules.
