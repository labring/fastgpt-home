# Policy and Regulatory Basis Q&A for Elderly Care Service Institution Oversight: Citation Sources and Traceability

## What this category of data looks like
This category of data typically originates from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institution operation ledgers. It is updated on a monthly basis. Daily documents include institution filing materials, operation subsidy applications, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. Most data fields relate to filing numbers, bed scale, rectification status, subsidy application identifiers, and similar items. There is no unified fixed cross-document field format. Some documents require associating data from multiple systems to complete verification.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Monthly updated data requires the traceability link to adapt to regularly synchronized data sources, to avoid citing expired institution filing or subsidy application information. The non-uniform field formats across multiple document types require matching document types to their corresponding exclusive fields during traceability. General fields cannot be used directly for mapping. Data from multiple system sources must clearly indicate the platform they belong to, to avoid confusing records from different oversight links such as fire safety inspections and civil affairs statistics. The rigor of oversight data requires that traceability information fully display document sources and update times, and key identifiers cannot be omitted.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Elderly care oversight documents are a mix of structured and semi-structured content. This length can cover the valid content of a single core document, avoiding truncation of key filing or rectification information |
| `responseData` | Include file name, affiliated platform, and update time | Oversight data requires clear traceable sources. The affiliated system and monthly update timestamp must be marked to meet compliance verification requirements |
| `detail` | Enable full field display | Elderly care oversight data has no unified field format. Exclusive fields within documents such as filing numbers and bed counts must be displayed to facilitate manual verification |
| Recall result limit | Top 6 entries | Monthly updated data sources have a moderate volume. The top 6 entries can cover valid reference content from major oversight links, avoiding interference from redundant information |
| Context splicing rule | Group by document type | Different types of oversight documents must be spliced separately, to avoid confusing the association logic between filing materials and safety rectification records |

## Three common mistakes
- Phenomenon: The API call return result does not include the source document file name and update time fields. Cause: The source document identification configuration corresponding to `responseData` is not enabled, and the basic metadata of the source document is not specified for return.
- Phenomenon: The returned citation results are not displayed sorted by relevance to the oversight scenario. Cause: The rule to reorder by content matching degree is not configured, and the default recall order does not adapt to the priority of core documents for elderly care oversight.
- Phenomenon: The citation content output by the large model does not match the actual filing or rectification records. Cause: No citation verification link is added to the workflow, and cross-checking between recalled content and system ledgers is not performed.

## How to confirm the configuration is correct
- Call the test interface, check whether the return result includes the source document's file name, affiliated platform, and update time fields.
- Submit a test question covering multiple types of oversight documents, verify whether the returned citation results are displayed grouped by document type.
- Set `quoteMaxToken` to 1000 token, test whether core filing numbers and bed data are not truncated when reading long documents.
- Trigger the citation verification workflow, input a test question that does not match the filing information, confirm whether unreasonable citations can be identified and marked.
