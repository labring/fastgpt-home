# Policy and Regulatory Basis Q&A for Internal Control Evaluation, Audit and Rectification: HTTP Interfaces and External Systems

## What this category of data looks like
Core business documents for this category include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Data is sourced from enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems. The update frequency follows an annual cycle. Documents contain both structured fields and unstructured text. Structured fields include issue number, rectification responsible person, closure status, and similar items. There are no fixed unified units. Field content changes dynamically based on specific audit projects and rectification workflows.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
Data sources for this category are scattered, and update cycles are long. Interfaces must support connection to multiple heterogeneous business systems, and be compatible with output formats from different systems. Documents mix structured and unstructured content. Interfaces must handle both structured field extraction and unstructured policy text parsing. The annual low-frequency update feature requires interfaces to have stable bulk data pulling capabilities. This avoids frequent permission verification workflows. Rectification-related documents must be strictly linked to business vouchers. Interface transmission must ensure traceability of data links, preventing data tampering or loss.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface authentication method | Add an `Authorization` field to the request header, with the value set to `Bearer {application secret}` | Complies with FastGPT platform standard authentication specifications, ensuring secure interface access |
| Request variable configuration | Pass the `variables` parameter, which includes business filter conditions such as policy document number, audit cycle, and rectification scope | Accurately limits the scope of returned policy basis data, avoiding redundant information |
| Response data processing | Specify the `responseData` field as the returned policy basis text and associated business fields | Directly extracts structured data that meets business requirements, reducing subsequent processing costs |
| Interface timeout setting | Set to 600 seconds | Adapts to delay scenarios across multiple system integrations, avoiding timeouts caused by overly long data pulling durations |
| Bulk pulling threshold | Set to the first 100 data entries | Matches the annual update data volume, balancing interface load and data integrity |
| Data format verification | Configure to validate the JSON structure of returned content | Filters invalid responses, ensuring interface returned data meets business processing requirements |

## Three common mistakes
- Interface calls return 401 Unauthorized errors. The cause is that the `Authorization` field is not correctly configured in the request header, or the used application secret has expired.
- The returned policy basis content does not match the business scenario. The cause is that correct business filter conditions are not passed via the `variables` parameter, resulting in a returned data range that exceeds expectations.
- Response timeout occurs during bulk data pulling. The cause is that an insufficient timeout period is set, or the pulled data volume exceeds the single-processing limit.

## How to confirm correct configuration
- Send a test request with the `Authorization` field, check if the returned status code is 200.
- Pass preset `variables` parameters, verify if the returned `responseData` field contains expected policy basis content.
- Simulate a bulk pulling scenario, check if the interface can stably return data within the configured threshold.
- View the platform's interface call logs, confirm there are no authentication or format verification related error reports.
