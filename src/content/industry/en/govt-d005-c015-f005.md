# Policy and Regulatory Basis Q&A for Medical Insurance Fund Supervision and Audit: Tool Calling and Plugins

## What the data for this category looks like
Data for this category originates from the medical insurance intelligent monitoring system, fund supervision rule base, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. The update frequency is monthly. Daily processed documents include audit notices, inspection work drafts, suspicious point lists, interview records, handling decision documents, and rectification reports. Data fields cover settlement detail codes, violation judgment rule entries, involved medical institution information, complaint time, and more. The number of fields per single record adjusts based on the audit scope.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The monthly updated rule base requires plugins to synchronize the latest policy clauses regularly to avoid calling outdated rules. Multi-source data linkage scenarios require plugins to adapt to the interface formats of different systems and complete cross-data-source data retrieval. Mixed-structure daily documents require tool calling to support structured field extraction and semi-structured text parsing, adapting to different stages of the audit process. The need for accurate matching of policy basis requires tool calling results to be associated with specific rule entries to avoid invalid content from generalized returns.

## How to configure the setup
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Mandatorily set to `function` | Must accurately call the policy rule query plugin to prevent the model from freely generating irrelevant content |
| Single tool call timeout | 600 seconds | Adapt to the time-consuming requirements of batch retrieval of medical insurance settlement data |
| Number of tool call result recalls | Top 8 entries | Cover the policy basis for major violation judgments |
| Plugin data source synchronization frequency | Once per month | Match the monthly update rhythm of business data |
| Document parsing chunk length | 800–1200 characters | Adapt to the paragraph structure and field length of audit documents |

## Three common configuration errors
- A 504 status code is returned during a call, and logs show tool calling has exceeded 600 seconds. The cause is failing to adjust the tool call timeout configuration, using the short timeout setting from general scenarios, which cannot adapt to the batch retrieval needs of medical insurance settlement data.
- The plugin fails to start after configuring a database connection plugin, and logs prompt field mapping mismatch. The cause is failing to adjust the plugin mapping rules for settlement data fields in the audit scenario, mistakenly using the field template from a general-purpose database.
- Tool calling only returns 1 policy basis, and the number of results does not meet expectations. The cause is failing to set a reasonable upper limit for the number of recalls, or incorrectly configuring `toolChoice` to automatic mode, causing the model to not call all required plugins.

## How to confirm the configuration is complete
- Initiate a simulated audit suspicious point query, check the tool call log, and confirm that `toolChoice` is configured to the specified function call mode.
- Check the plugin synchronization record, confirm that the most recent synchronization time is within the monthly update cycle, and the data source matches the fund supervision rule base address.
- Call test settlement data, check whether the returned fields include audit-required content such as settlement detail codes and involved institution information.
- Trigger a batch suspicious point query, check that the tool call time does not exceed 600 seconds, and no timeout errors occur.
