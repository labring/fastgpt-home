# Policy and Regulatory Basis Q&A for Medical Insurance Settlement Audit: Workflow Orchestration

## What This Category's Data Looks Like
Data sources for this category include the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding database, and cross-regional medical settlement platform. Update frequency is daily. Daily processed documents are structured medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. These documents include standard fields such as settlement number, insured person identifier, diagnosis and treatment project code, drug and consumable expenses, and rejection reason. They support single or batch submission.

## Constraints Imposed by These Characteristics on the "Workflow Orchestration" Link
Multiple data sources requiring daily synchronization demand workflow configuration with multiple nodes to connect different data sources, plus scheduled trigger synchronization nodes. Documents are structured bills covering multiple dimensions including diagnosis and treatment, expenses, and insured persons. Nodes must be split to handle core links such as coding matching, consistency check between expenses and medical records, and rejection reconciliation. Batch processing requirements demand controlling the scale of bills submitted in a single batch to avoid node overload. Error consequences involve fund security and business timeliness, so abnormal branches must be configured to handle reconciliation failure scenarios and trigger subsequent appeal processes.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Single processing quantity | Top 100 entries | Adapt to the scale of daily updated batch bills, avoid workflow node timeouts |
| Node timeout period | 300-600 seconds | Cover average time spent across interface calls, coding matching, and bill verification |
| Context window | 8000 token | Adapt to long-text retrieval requirements of policy documents, cover complete medical insurance policy clauses |
| Global variable `variables` | Bind settlement number, insured person ID | Pass business identifiers across nodes, ensure bill consistency across processing links |
| Exception retry count | 2 times | Respond to temporary fluctuations in medical insurance interfaces, reduce probability of manual intervention |
| Node ID `nodeId` | Name in order of business process | Facilitate troubleshooting workflow execution logs, quickly locate abnormal nodes |

## Three Common Misconfigurations
- Workflow run error "Cannot convert undefined or null to object": The cause is failure to configure the required settlement number parameter in `variables`, leading to null values being passed during node calls.
- The output of the AI conversation node is displayed directly on the page, and output cannot be specified after text splicing: The cause is failure to turn off the automatic output switch of the AI node, and failure to configure the trigger condition of the text splicing node.
- Historical audit records cannot be used as global variables for the workflow: The cause is failure to bind the output of the historical record node to the `variables` configuration item, and failure to correctly set variable transfer rules.

## How to Verify Correct Configuration
- Trigger workflow runs, check node logs to confirm business parameters bound in `variables` are correctly passed to all nodes.
- Test batch bill processing, confirm single processing quantity matches preset values, with no node timeout errors.
- Disable the automatic output switch of the AI node, trigger the complete audit process, confirm output is only generated after the text splicing node completes.
- Simulate temporary exceptions in medical insurance interfaces, confirm exception retry count configuration takes effect and triggers the abnormal branch processing flow.
