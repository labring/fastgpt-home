# Policy and Regulatory Basis Q&A for Medical Insurance Expense Settlement Audit: Tool Calling and Plugins

## What the data for this category looks like
This guide is written for FastGPT v4.17.0. Data for this category comes from the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical settlement platform. Data is updated daily. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Fields include diagnosis and treatment item codes, consumable codes, expense amounts, insured person identifiers, settlement order numbers, rejection reasons, and more. Single document size varies flexibly based on business batches.

## What constraints do these characteristics impose on tool calling and plugins
Data comes from multiple sources and is updated daily. Tool calling must adapt to format specifications of different interfaces, and pull the latest medical insurance catalog and coding library on a regular basis to avoid using expired data. Daily processed document types are diverse and scales vary flexibly. Tools must support both batch and single-item processing modes, and limit the number of documents processed per single call to prevent interface overload. Fields include standardized coding content. Tool calling must pass coding matching parameters to ensure accuracy of policy basis matching. The business link occurs before and after payment. Tool calling must align strictly with the timing of the settlement process.

## Configuration Parameters

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` and bind to the dedicated medical insurance settlement audit toolset | Allows LLM to autonomously select tools matching policy bases, and adapts to multiple settlement scenarios such as outpatient and inpatient services |
| `functionCall` | Enable structured output mode | Ensures tool calling parameters conform to the field format of medical insurance data, facilitating subsequent reconciliation and auditing |
| Workflow node timeout | 300–900 seconds | Matches time requirements for pulling daily-updated medical insurance catalog data and processing batch settlement lists |
| Batch processing count | 100–500 items | Adapts to business scales of single-item or batch settlement audits, and avoids interface call overload |
| File input switch | Enable | Supports uploading documents such as settlement lists and prescriptions as input bases for tool calling |
| Session ID transmission | Carry via request header | Associates audit records with session context, facilitating subsequent reconciliation and traceability |

## Three Common Misconfigurations
- When the file input configuration is not enabled, uploaded documents such as medical insurance settlement lists and prescriptions cannot be read by tool calls. Tool calls return empty results. The cause is that the file receiving switch for the corresponding node is not enabled, so tools cannot parse uploaded document content.
- The execution order of tool nodes and RAG knowledge base nodes in the workflow is reversed. This causes policy bases to not be associated with the current settlement list, and audit conclusions lack corresponding policy bases. The cause is that settlement list data is not passed as a pre-parameter to the tool node, so no matching business data exists during tool calls.
- When session ID transmission to tool requests is not configured, audit records cannot be associated with the session. Logs lack session identifier fields. The cause is that the session ID parameter is not added to the tool request header, so audit records cannot be bound to session context.

## How to Verify Proper Configuration
- Upload a test medical insurance settlement list document, trigger a tool call, and confirm that the tool can read key field content from the document.
- Send a test request, check the tool call logs, and confirm that the session ID field is carried in the request header.
- Set `toolChoice` to `auto`, send a test request, and confirm that the LLM automatically calls the bound dedicated medical insurance settlement audit tool.
- Export the plugin node from the workflow, and confirm that configured parameters are fully saved with no missing items.
