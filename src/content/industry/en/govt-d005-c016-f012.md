# Policy and Regulatory Basis Q&A for Medical Insurance Expense Settlement Audit: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category include the National Medical Security Information Platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical treatment settlement platform. Data is updated daily. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Data fields include business-related fields such as diagnosis and treatment project codes, medical supplies codes, expense amounts, and settlement status. Units include yuan, number of visits, code numbers, and other relevant units.

## What constraints do these characteristics impose on the deployment and upgrade process
The data sources for this category are scattered and updated daily. During deployment, multiple data source connection parameters must be configured to ensure the stability of multi-interface data synchronization. The data includes coding fields such as diagnosis and treatment projects and medical supplies. During deployment, matching the vector index rules of the corresponding coding library is required to ensure the accuracy of question-and-answer matching. The processing volume of single or batch settlement data is large. During deployment, database connection pool parameters must be adjusted to avoid connection exhaustion caused by concurrent requests. At the same time, the data is associated with medical insurance fund compliance requirements. During upgrade, the original permission verification logic must be retained to avoid compliance risks caused by configuration changes.

The following configurations are based on FastGPT v4.17.0
## Recommended Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Adapts to the concurrent query and write requirements of daily batch settlement data for this category, and avoids connection exhaustion |
| `MONGODB_URI` | Address of a dedicated database instance for medical insurance settlement details and rejection lists | Isolates business data from data from other scenarios, and ensures access security of medical insurance data |
| `REDIS_URL` | Local Docker deployment instance address, or Alibaba Cloud Redis mirror address such as `redis-cn-xxxx.aliyuncs.com:6379` | Caches frequently accessed medical insurance catalog coding data to reduce interface call latency |
| `ROOT_KEY` | Random key with high complexity | Ensures the security of background management permissions, and avoids unauthorized access to configuration items |
| `STORAGE_S3_ENDPOINT` | Dedicated storage endpoint for medical insurance settlement documents | Uniformly manages storage and reading of documents such as settlement lists and prescriptions, and complies with data retention requirements |

## Three Common Configuration Mistakes
- Symptom: After upgrading to FastGPT v4.9.8, the root user password is automatically restored to the initial value the next day. Cause: Persistent storage of `ROOT_KEY` was not correctly configured during deployment. The Redis instance data relied on for password caching was not persisted, and the cache was reset after restart.
- Symptom: After accessing the Qwen3-Embedding-8B indexing model, the file status continuously displays "Indexing". Cause: Vector processing parameters were not adjusted based on the average length of medical insurance documents for this category. Ultra-long documents cannot complete index splitting, leading to task blocking.
- Symptom: Database connection timeout errors occur when batch importing settlement reconciliation statements. Cause: The `DB_MAX_LINK` parameter was not adjusted to a value suitable for batch processing. Concurrent write requests exceed the database connection limit.

## How to Verify Successful Configuration
- Run the Redis connection test command to verify that the instance configured with `REDIS_URL` can read and write cached data normally.
- Submit a small number of medical insurance settlement list documents to check whether the vector indexing task is completed within a reasonable time, with no long-term "Indexing" status.
- Modify the root user password, restart the service, and verify that the password configuration is not automatically restored to the initial value.
- Check the database connection number monitoring to confirm that current concurrent requests do not exceed the upper limit configured by `DB_MAX_LINK`.

The values provided are common starting points and should be measured against the reader's own samples.
