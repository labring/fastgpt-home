# Policy and Regulatory Basis Q&A for Medical Institution Supervision and Public Health Inspection: Citation Sources and Traceability

## What the data for this category looks like
Core data for this category comes from health supervision information systems, medical institution electronic registration systems, complaint and reporting platforms, and law enforcement inspection records. Daily generated documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Data updates occur monthly. Data fields include institution qualification identifiers, on-site inspection content, rectification requirements, and penalty-related records. Document structures fall into two categories: structured forms and semi-structured documents, with no unified fixed format.

## What constraints do these characteristics impose on the citation sources and traceability link
Data from multiple business systems must be uniformly indexed to ensure the recall scope covers all compliant basis. The monthly update feature requires regular synchronization of data sources to avoid referencing outdated supervision records. Different types of documents have large structural differences, such as qualification information from practice licenses and law enforcement content from penalty case files. Configured matching rules are required for adaptation. Citations must be associated with specific entries and generation times of original documents. This enables law enforcement personnel to verify qualifications and rectification situations, ensuring the rigor and compliance of traceability.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 10000–15000 token | Core documents for this category, including penalty case files and rectification notices, have long individual content. This range ensures coverage of complete supervision basis and rectification requirements |
| `responseData` | Structured format with original document metadata | This scenario requires associating cited content with its source system, document type, and generation time to meet compliance traceability requirements |
| `detail` | Enabled | The business scenario for this category requires clearly displaying specific document entries corresponding to cited content, to facilitate verification by law enforcement personnel |
| Data source synchronization cycle | Monthly | This aligns with the monthly update frequency of business data, ensuring recalled content matches the latest supervision records |
| Single recall count | Top 10 entries | Core compliant basis for this category is concentrated in the top 10 recall results. This avoids redundant information interfering with law enforcement personnel's verification |

## Three Common Misconfiguration Issues
- The interface displays a context token count of 30, but the actual number of cited documents far exceeds the configured value. Content sent to third-party interfaces also includes more than 300 recall results. This occurs when the `quoteMaxToken` setting is not correctly linked to the recall count truncation rule, and the system does not limit context length per configured parameters.
- `quoteMaxToken` is set to 1500 token, but documents in the knowledge base with single-block content exceeding this value are still fully cited. This occurs when long documents are not chunked, and untruncated full content is passed directly, exceeding the configured token limit.
- The citation source field returned in AI chat responses is empty, making it impossible to associate results with specific supervision documents. This occurs when metadata is not passed in the structured format required by `responseData`, so the system cannot identify the original document identifier for the citation.

## How to Verify Configuration Effectiveness
Based on FastGPT v4.17.0, configuration effectiveness can be verified through the following actions:
- A policy basis Q&A request is triggered. The citation source metadata in returned results is checked for information such as source system and document type. This confirms the `responseData` configuration is active.
- `quoteMaxToken` is adjusted to 5000 token. The actual recalled token count is compared to the configured value. This confirms the context truncation rule is active.
- A rectification notice exceeding 10000 characters is uploaded. The system’s chunking or truncation of the content per configured rules is verified. This confirms the long document processing rule is active.
- Data synchronization is triggered after one month. Newly uploaded supervision inspection forms are checked for correct recall. This confirms the data source synchronization cycle configuration is active.
