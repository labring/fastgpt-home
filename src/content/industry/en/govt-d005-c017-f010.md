# Policy and Regulatory Basis Q&A for Medical Institution Supervision and Public Health Inspection: Knowledge Base Retrieval and Recall

## What This Category’s Data Looks Like
Data for this category comes from four sources: the health supervision information system, medical institution electronic registration system, complaint and reporting platform, and law enforcement inspection records.
Daily documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files.
Data updates on a monthly basis. Document fields cover institution qualifications, personnel qualifications, disinfection and treatment records, rectification tracking, and similar content. Most content is structured or semi-structured compliance-related material, with no additional statistical values.

## What Constraints Do These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Data updates monthly. The knowledge base sync cycle must align with this monthly rhythm to avoid frequent updates consuming system resources.
Documents of multiple types have significant structural differences. Chunking logic must be adapted for each document type to ensure both semi-structured law enforcement documents and structured qualification files can be parsed effectively.
This data supports compliance supervision scenarios. Retrieval results must accurately match policy basis. Interference from irrelevant content must be limited.
Most fields focus on core law enforcement needs such as institution qualifications and rectification tracking. Retrieval keywords must align with compliance clauses in law enforcement scenarios, avoiding generalized recall.

## How to Configure the Settings
These configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | This category is used for compliance supervision, requiring accurate matching of policy clauses to avoid low-similarity irrelevant content interfering with law enforcement judgments |
| `limit` | 8–12 entries | Matches the core policy basis required by law enforcement personnel. Excessive results will exceed the context capacity limit, making it difficult for law enforcement personnel to quickly review content |
| `searchMode` | strict | This category requires accurate matching of policy and institution qualification-related content. Strict mode reduces irrelevant recall and improves retrieval accuracy |
| `usingReRank` | Enabled | Improves the ranking accuracy of highly relevant results, ensuring the most closely aligned policy basis content is returned first to assist law enforcement personnel in quickly locating compliance basis |
| `datasetSearchUsingExtensionQuery` | Enabled | Optimizes questions about policy basis by supplementing policy keywords from law enforcement scenarios, improving recall accuracy |
| `collectionIds` | Bind the exclusive dataset ID for this category | Ensures only compliance documents related to health supervision are retrieved, avoiding mixing in irrelevant dataset content and maintaining the professionalism of retrieval results |

## Three Common Misconfigurations
- Issue: An `Invalid array length` error occurs during the question answering splitting process, and it occurs consistently. Cause: Law enforcement documents in this category contain long text, and chunking parameters were not adjusted, leading to array overflow.
- Issue: The reranking model continues to occupy video memory after retrieval is complete. Cause: No relevant settings for automatically unloading the model after retrieval were configured, resulting in delayed video memory release.
- Issue: Markdown format files of medical institution practice licenses cannot be imported. Cause: The markdown files contain custom tables or special format elements that do not align with FastGPT's markdown import verification rules, leading to parsing failure.

## How to Confirm the Configuration Is Complete
- Trigger a policy basis question and answer request, then check if the similarity of returned results falls within the configured `similarity` range.
- Check if the number of retrieval results is within the set `limit` range.
- Verify that the reranking model is automatically unloaded after retrieval is complete, and check the system's video memory usage.
- Import a document exclusive to this category, confirm it can be retrieved normally, and verify that the `collectionIds` binding is correct.
- Check if the knowledge base sync cycle is set to monthly, matching the data update rhythm of this category.
