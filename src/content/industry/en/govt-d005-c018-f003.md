# Policy and Regulatory Basis Q&A for Social Insurance Enrollment Registration and Payment Verification: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category originates from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and public security and civil affairs data sharing interfaces. Common documents include enrollment registration forms, payment base declaration forms, personnel change forms, social insurance premium verification notices, and personal benefit records. Most are structured forms or reports. Fields cover unit unified social credit code identifiers, personnel identity information, payment calculation parameters, personnel change status, and more. Data is updated daily, with real-time synchronization required across multiple business systems.

## Constraints for Multi-turn Dialogue and Prompt Engineering
The daily updated data from multiple departments requires multi-turn dialogue to link to the latest business data in real time, to avoid using expired information. The field rules for structured documents require prompts to explicitly specify precise fields such as unit unified social credit codes and personnel ID numbers, to avoid result deviations from fuzzy searches. The sensitivity of personnel change and payment data requires sessions to isolate user contexts via `chatId`, to prevent data leaks. The need for cross-system reconciliation requires dialogues to link multiple knowledge bases for data cross-verification, with multi-source retrieval trigger logic configured. The business process of gradually verifying identity and labor relations requires multi-turn dialogue to retain historical conversation context, to avoid repeated questions.

## Three Common Misconfiguration Issues
- Phenomenon: Some sessions trigger knowledge base retrieval, while others generate responses directly without retrieval logs. Cause: Mandatory retrieval trigger rules are not configured. The system skips retrieval when context matching confidence is high.
- Phenomenon: Temporary variables in a session are cleared in new rounds, making fixed business parameters such as unit unified social credit codes unavailable. Cause: The `variables` global storage configuration is not used, only session temporary variables are used. Temporary variables are overwritten as conversation rounds progress.
- Phenomenon: Retrieval time increases as the number of questions in the same conversation window rises. Newly initiated sessions return to normal response times. Cause: The number of retained historical conversations is not limited. Excessively long `messages` context causes each retrieval to load large volumes of historical data, increasing processing time.

## How to Verify Proper Configuration
- Initiate a query that includes a unit unified social credit code, verify that returned results link to corresponding documents such as enrollment registration forms and payment verification notices.
- Initiate cross-round queries, verify that the system automatically references personnel identity information from historical conversations, eliminating the need for repeated input.
- Check the session variable storage panel, confirm that global parameters in `variables` are not modified or cleared as conversation rounds progress.
- Initiate multiple consecutive rounds of queries, observe that retrieval time remains stable with no significant increase.
