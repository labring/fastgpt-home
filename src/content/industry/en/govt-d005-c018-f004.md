# Policy and Regulatory Basis Q&A for Social Insurance Registration and Payment Verification: Workflow Orchestration

## What Data Belongs to This Category
This category covers documents including social insurance registration forms, payment base declaration forms, personnel change forms, social insurance premium verification notices, and personal benefit records. Data is sourced from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily. Data fields include personnel identity identifiers, labor relationship certification materials, payment base ranges, unified social credit codes of entities, and more. Data is stored in two formats: structured forms and verification documents. Fields must match cross-system shared identity and payment-related information.

## Constraints Imposed by These Characteristics on Workflow Orchestration
Data for this category relies on cross-domain synchronization across multiple systems. Workflow orchestration must adapt to the interface call logic of different systems such as social insurance handling and tax collection. The daily data update feature requires scheduled trigger nodes in workflow configurations, to ensure queried policies and basis use the latest versions. The two document formats (forms and verification notices) require format verification nodes in workflows, to filter input content that does not meet field specifications. Since incorrect data can lead to underpaid or missed premiums, or incorrect personal benefit records, workflows must add pre-verification and post-reconciliation steps to prevent abnormal data from entering the Q&A process.

## Three Common Misconfigurations
- Workflow terminates directly after reaching an intermediate node, returning only partial AI responses. The cause is missing required field validation for `variables`. When the incoming entity's unified social credit code is empty, the node triggers an exception and terminates the process immediately.
- Workflow cannot be called normally via Feishu bots after publication. The cause is either failing to enable permission configuration for the Feishu bot, or not binding the workflow to the correct bot application.
- The number of results returned by workflow nodes does not match expectations. The cause is an unreasonable setting for the single search limit. A value that is too high introduces interference from redundant data, while a value that is too low causes key policy basis to be missed.

## How to Verify Proper Configuration
- Manually input standardized entity unified social credit codes and personnel ID numbers to trigger the workflow, and check if complete policy basis and payment verification-related content are returned.
- Review workflow logs, confirm that all cross-system data call nodes return normal status codes, with no timeout or error messages.
- Test abnormal input scenarios, such as an ID number with an incorrect format, and check if the workflow triggers the format verification node and returns clear prompts.
- After binding the Feishu bot, initiate a test conversation, and confirm that the workflow can respond normally and return complete results.
