# Policy and Regulatory Basis Q&A for Social Insurance Participation Registration and Premium Verification: Tool Calling and Plugins

## What this category of data looks like
Data sources for this category include social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily.
Documents processed daily include social insurance participation registration forms, payment base declaration forms, staff change rosters, social insurance premium verification notices, and personal benefit records. Data fields cover personal identity information, insurance participation status, payment base, verified amount, registration time, and more. Units include person-times, yuan, months, and others. All data is structured form-based, with only a small amount of accompanying policy explanation text.

## What constraints do these characteristics impose on tool calling and plugin workflows
Since data is updated daily, tool calling requires configuring scheduled data source synchronization rules to ensure access to the latest social insurance participation and premium payment data.
Field differences across multiple data sources require tool calling to first complete field alignment verification to avoid confusion from cross-system data.
Structured form-based data means tool calling must use structured calls with fixed parameters to match fixed-format business requirements.
Additionally, the data verification link accounts for a high proportion of processing time. Specialized identity verification and labor relationship confirmation tool plugins must be configured. Tool call failures must trigger alerts to prevent missed or underpaid premiums or abnormal benefit records caused by incorrect data.
This category only covers the social insurance participation and premium payment stage. Tool calling cannot be bound to business plugin links from other stages.

## How to configure settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios for this category, automatically selects required tools such as identity verification and data reconciliation |
| `functionCall` | `enabled` | Enforces structured tool calling to match the parameter format of structured form data for this category |
| Tool call timeout duration | 300 seconds | Covers the standard time requirements for social insurance data reconciliation and cross-system verification |
| Knowledge base recall count | Top 5 entries | The number of policy documents for this category is limited, so excessive recall content is unnecessary |
| Knowledge base citation display toggle | Disabled | Avoids output content including citation mark text, aligns with user reading habits |
| Custom interface trigger rule | Match by business keywords | Adapts custom interface calls for specific business scenarios such as social insurance participation registration and premium verification |

## Three common configuration mistakes
- Setting `toolChoice` to `none` prevents the tool calling link from being established. The root cause is that the trigger conditions for tool calling are not clearly specified, so the large language model cannot match the required tool plugins.
- After knowledge base recall results are returned, the output content includes text in the format "Citation Mark: [1]". The root cause is that the knowledge base citation display toggle is not disabled, so the default citation mark output logic remains active.
- After preset interception keywords are entered, the custom interface call is not triggered. The root cause is that the binding relationship between keyword matching rules and the custom interface is not configured, so the large language model still generates responses according to standard logic.

## How to verify successful configuration
- Submit a query that includes the identity information of a social insurance participant. Check whether the identity verification tool plugin is automatically called and structured call results are generated.
- Submit a policy query related to premium verification. Check whether the output content does not include citation mark text, and only displays the original policy text and relevant data.
- Enter preset interception keywords. Check whether the returned content is the corresponding business content provided by the custom interface, rather than a standard response generated directly by the large language model.
- View the tool call log to confirm that the number of calls matches the data source, and there are no abnormal timeout or failure records.
