# Policy and Regulatory Basis Q&A for Insurance Registration and Payment Verification: Source Citation and Traceability

## What the Data for This Category Looks Like
Data for this category comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and public security and civil affairs shared data. The update frequency is daily. Daily documents include insurance registration forms, payment base declaration forms, staff change rosters, social insurance premium verification forms, and personal benefit records. Data fields include the unit's unified social credit code, ID number of insured personnel, payment base, verification form number, and other relevant fields. Most document structures are structured tables and standardized forms, with no excessive free text.

## What Constraints Do These Characteristics Impose on the Source Citation and Traceability Link
The cross-system sources, daily update frequency, and structured standardized document characteristics of this category's data impose multiple constraints on citation traceability. Cross-collected insurance registration and payment data must be associated with the unique identifier of the corresponding handling system or tax collection system to ensure traceability back to the original data node. Daily updated verification records require the traceability mechanism to obtain the latest daily data to avoid referencing expired staff change or payment base information. Structured form documents must be accurately positioned to specific field entries, avoiding reliance on vague paragraph ranges to improve traceability accuracy. Cross-department shared data must be labeled with the providing entity to meet compliance requirements.

| `quoteMaxToken` | 800–1200 token | Adapts to the field and content length of structured forms in this category, avoiding truncation of critical payment verification or staff change information |
| `responseData` | Return only associated knowledge base data | Filters non-compliant external data, ensuring traceability content only comes from official documents of social insurance handling and tax systems |
| `detail` | Enabled | Displays specific fields, form numbers, and source system identifiers of original documents to meet the accuracy requirements for insured data traceability |
| Knowledge base update synchronization frequency | Daily synchronization | Matches the daily update characteristic of this category's data, ensuring referenced content is the latest daily verification records |
| Maximum number of associated knowledge bases | Calibrated based on actual testing | Adapts to the needs of multi-system data integration, avoiding system resource overload |

## Three Common Configuration Errors
- Phenomenon: The output does not display source identifiers, or the source field is empty. Cause: The `detail` configuration item is not enabled, and the traceability display logic is not configured.
- Phenomenon: The number of associated knowledge bases exceeds the expected upper limit, leading to configuration failure or no query response. Cause: A reasonable upper limit is not set based on the multi-system data integration needs of this category, and too many data sources are added blindly.
- Phenomenon: The referenced content does not include the latest daily payment verification records, and old version data is still returned. Cause: Daily synchronization of knowledge base updates is not set, and static cached data is still used for traceability.

## How to Verify Successful Configuration
- Initiate a test query that includes insured personnel identification or payment base, check whether the output includes fields and source system identifiers of the original document.
- View the knowledge base management interface to confirm that the number of associated knowledge bases meets the preset upper limit requirements.
- Manually update a test staff change record, initiate a query and confirm that the returned content includes the updated latest information.
- Check the configuration log to confirm that the value of `quoteMaxToken` does not trigger content truncation, and form field information is fully displayed.

The values provided here are common starting points and should be measured against the reader's own samples.
