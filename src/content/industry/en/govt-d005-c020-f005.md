# Policy and Regulatory Basis Q&A for Territorial Spatial Planning Formulation and Implementation Evaluation: Tool Calling and Plugins

## What Data for This Category Looks Like
Daily documents for this category include territorial spatial master plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data sources include the Territorial Spatial Basic Information Platform, natural resource survey and monitoring data, population and economic statistics data, and remote sensing images. Data updates once per year. Most documents are multi-chapter structured content, with fields such as spatial coordinates, constraint indicators, and regional scope. Units include square kilometers, population counts, and project land area. Individual document lengths vary widely, from several thousand to tens of thousands of words.

## How These Characteristics Create Constraints for Tool Calling and Plugins
Data for this category updates once per year. Tool calling does not require high-frequency data source synchronization. Fixed-cycle data pulling can be configured instead. Wide variation in document length means long texts exceed context limits. Document chunking processing is required. Multi-source data includes dedicated fields such as spatial coordinates and constraint indicators. Ordinary text processing plugins cannot directly parse these fields. Dedicated spatial data parsing plugins must be used alongside standard tools. Unstructured public opinion summary text needs a text cleaning plugin first to unify formats. Cleaned text can then be used for question and answer generation. Multi-source data integration requires plugins to support cross-data source calling logic. This reduces manual summarization workload.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | This category's policy Q&A automatically selects built-in tools or dedicated plugins based on user questions, without manual specification of calling targets |
| Chunk Length | `800–1200 characters` | Individual document lengths vary widely. This range balances context length limits and policy clause information integrity |
| Single Search Limit | `Top 6 results` | Multiple multi-source data sources exist. Limiting search results avoids redundant information interfering with policy clause extraction |
| `functionCall` | `enabled` | Policy and regulatory basis Q&A requires dedicated spatial data query plugins. Enabling function calls triggers tool execution |
| Timeout Period | `120 seconds` | Spatial data queries load remote sensing images or Territorial Spatial Basic Information Platform data. This duration covers most query scenarios |
| Question Optimization | `Enabled` | Planning policy questions often use professional terminology. Optimization improves tool calling accuracy |

## Three Common Misconfigurations
- Inaccurate Q&A results for long documents. Caused by missing suitable chunk length configuration. Key policy clauses are truncated, or excessive redundant information is included.
- Empty results returned after plugin execution, with points deducted. Caused by missing dedicated spatial data parsing plugin configuration. The plugin cannot identify spatial coordinate fields in documents, leading to tool calling failure.
- No scheduled tool execution entry available. Caused by disabled scheduled task function in FastGPT v4.17.0 plugin management, or unbound corresponding execution permissions.

## How to Verify Successful Configuration
- Initiate a policy query containing spatial coordinates. Confirm the dedicated spatial data parsing plugin triggers and returns corresponding results.
- Upload a 10,000-word-level planning document. Confirm the question and answer system automatically chunks the document and returns complete policy clauses.
- View the plugin management page. Confirm configurations for `toolChoice` and `functionCall` have taken effect.
- Test the scheduled data pulling task. Confirm data from the Territorial Spatial Basic Information Platform synchronizes per the set cycle.

The values listed above are common starting points and should be evaluated against the user's own samples.
