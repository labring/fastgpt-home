# Policy and Regulatory Basis Q&A for Territorial Spatial Planning Formulation and Implementation Evaluation: Model Access and Configuration

## What data belongs to this category
This category of data mainly comes from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics, and remote sensing images. The update frequency is annual. Commonly processed documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Most document structures include spatial coordinate fields, planning constraint indicators, approval process nodes, and entries for departmental and public opinions. Field units involve spatial and statistical units such as hectares, square kilometers, population counts, and percentages.

## What constraints do these characteristics impose on the model access and configuration link
The annual updated multi-source heterogeneous data characteristics of this category require configuring batch document import and incremental synchronization logic when accessing the model, to avoid repeated processing of historical data. Documents contain mixed structures such as spatial coordinates, constraint indicators, and public opinions. It is necessary to ensure that the configured text parsing rules can accurately identify spatial fields and statistical units, to prevent parsing deviations. The mixed content of multiple departments and public opinions requires that the configured context window adapts to multi-format text lengths, while filtering irrelevant interference items to ensure the focus of policy basis Q&A. The attribute of government affairs data sources requires that the configured API call permissions adapt to relevant specifications for secure calling of government affairs data.

## How to set the configurations
The following configurations are based on the parameter rules of FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
|---|---|---|
| `maxContext` | 8000–12000 token | Documents in this category are mostly multi-page planning reports and multi-source data summaries, requiring sufficient context to associate policy clauses and planning content |
| `maxTokens` | 2000–3000 token | Policy basis Q&A needs to output structured clause references and explanations, limiting output length to avoid redundancy |
| `quoteMaxToken` | 1500 characters | It is necessary to accurately intercept policy original text fragments from planning documents, avoiding overly long fragments that interfere with Q&A accuracy |
| `temperature` | 0.2–0.4 | Policy basis Q&A needs to maintain rigorous expression, avoiding excessive randomization |
| `AIPROXY_API_ENDPOINT` | Configure a dedicated access address according to the government network environment | Data in this category is mostly government-sensitive information, requiring compliant proxy addresses to ensure data transmission security |
| `toolChoice` | auto | It is necessary to automatically trigger the knowledge base retrieval tool based on user questions to ensure the accuracy of policy basis |

## Three common misconfigurations
- Phenomenon: Occasional empty content is returned after calling, with a 200 status code but empty response fields. Cause: No reasonable value for `maxContext` is configured, leading to context overflow of multi-source documents, and the model cannot extract effective policy basis.
- Phenomenon: The same policy question returns different answers, and knowledge base retrieval results are inconsistent. Cause: No fixed interception rule for `quoteMaxToken` is set, leading to inconsistent original text fragment ranges retrieved each time, causing answer differences.
- Phenomenon: The voice function cannot call the voice model normally after being enabled. Cause: No dedicated access path for the voice model is configured in `AIPROXY_API_ENDPOINT`, or no correct `AIPROXY_API_TOKEN` permission is configured.

## How to confirm the configuration is correct
- Import one complete territorial spatial overall plan document, test the policy basis Q&A call, and check whether the context window normally loads all key content of the document.
- Input the same policy-related question three times, check whether the returned policy original text reference fragments are consistent, and verify the stability of the retrieval rules.
- View the API call log, confirm that the request address of `AIPROXY_API_ENDPOINT` matches the configuration, with no permission or connection errors.
- After enabling the voice function, test the complete link of speech-to-text and text-to-speech, and confirm that the model call has no abnormalities.

The values provided are common starting points and should be measured against the reader's own samples.
