# Policy and Regulatory Basis Q&A for Territorial Spatial Planning Compilation and Implementation Evaluation: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from territorial spatial basic information platforms, natural resource survey and monitoring data, population and economic statistics, and remote sensing images. The update frequency is annual. Daily processed documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. The data includes structured fields such as spatial coordinates, policy constraint indicator values, planning time limits, and implementation progress, along with a large amount of policy-related text descriptions and spatial association information.

## What constraints do these characteristics impose on the deployment and upgrade link
Multi-source spatial data has a large volume and is updated in batches annually. Deployments must adapt to high-capacity storage and batch data processing configurations. Documents include structured fields such as spatial coordinates and policy constraint indicators. Vector retrieval rules that support structured data embedding must be matched to avoid loss of spatial and policy association information during retrieval. The fixed annual update rhythm requires configuring incremental synchronization trigger logic to avoid repeated processing of historical data. For government service scenarios, secure and compliant access keys and permission control parameters must be configured to ensure data and service security.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://localhost:6379/0` | This category has large batch data updates, requiring low-latency caching for session and vector index caching. Local deployments can use the default port |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt` | Used to store metadata and associated information of planning documents and evaluation reports. Document databases are suitable for unstructured text storage |
| `PG_URL` | `postgresql://user:pass@localhost:5432/fastgpt` | Used to store structured data such as spatial coordinates and policy constraint indicators, supporting complex spatial queries and permission control |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | Used to store large files such as remote sensing images and large-volume planning documents, compatible with local or private cloud object storage services |
| `ROOT_KEY` | Random string of 32 or more characters | Configures super administrator permissions, adapting to account and permission control requirements for government scenarios |
| `FILE_TOKEN_KEY` | 16-character random string | Generates file access tokens to ensure secure download of planning documents and remote sensing images |

## Three common configuration errors
- Symptom: Redis connection error occurs after startup, with logs showing `Could not connect to Redis`. Cause: The `REDIS_URL` parameter is not filled correctly, or the Redis container failed to start normally during Sealos one-click deployment.
- Symptom: No registration entry appears on the login interface, making it impossible to create an initial administrator account. Cause: The `ROOT_KEY` parameter is not configured, or the initial user initialization process is not enabled.
- Symptom: Retrieval results do not include policy-related planning documents or spatially associated content, and the number of recalled entries is far lower than expected. Cause: The vector embedding logic has not been adjusted for structured policy fields and spatial fields, or the retrieval rules of the vector database have not been configured correctly.

## How to confirm configuration completion
- Access the FastGPT v4.17.0 backend system status page, confirm that the connection status of `REDIS_URL`, `MONGODB_URI`, and `PG_URL` all show normal.
- Upload a territorial spatial overall plan document, trigger the vector embedding task, and after completion, perform a search using policy-related keywords to confirm that matching document fragments can be returned.
- Use the super administrator permission corresponding to `ROOT_KEY` to create a department account, verifying that the permission control process takes effect normally.
- Upload a remote sensing image file, confirm that the storage service configured via `STORAGE_S3_ENDPOINT` can receive and read the file normally.
