# Policy and Regulatory Reference Q&A for Centralized Treasury Payment and Reimbursement Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for this category include centralized treasury payment systems, unified budget management systems, electronic invoice platforms, and contract management systems. Update frequency is daily. Daily processed documents include payment applications, fund use plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers. Core fields cover budget indicators, economic classification, payment amount, approval process nodes, and more. A single data entry corresponds to full-chain compliance materials for one-time capital payment.

## Constraints on multi-turn dialogue and prompt engineering
Multi-source data sources require the dialogue system to integrate structured and unstructured data across multiple platforms, to ensure complete policy reference matching. Daily updated data sources require dialogue context to sync the latest budget indicators and payment limits, to avoid using expired information. The chain-based nature of multiple approval document types requires multi-turn dialogue to retain information from prior approval nodes, to support compliance review. The compliance verification requirement for core fields requires prompts to clearly define verification rules for economic classification and budget indicators, to ensure responses align with financial management requirements.

## Three common configuration mistakes
- Debug preview interface error: Symptoms include no response or abnormal prompt pops up after enabling input guidance and configuring a custom thesaurus. Cause: Custom thesaurus file format does not meet system requirements, leading to thesaurus loading failure.
- Automatic maximum response token reduction to 200: Symptoms include reply content being forcibly truncated, with length far below the preset upper limit of 3000 or more. Cause: The system triggers output length fallback rules for professional scenarios, or automatic truncation due to context overrun.
- Failed to add knowledge base content during dialogue: Symptoms include knowledge base not updating after performing an add operation. Cause: Dynamic write configuration for conversational knowledge base is not enabled, or read/write permissions for the corresponding data source are not bound.

## How to confirm configurations are properly set
- Enter the debug preview interface, input a test question containing budget indicators and economic classification, check if the reply associates compliance references from corresponding documents.
- Initiate a multi-turn dialogue, sequentially ask questions about prior approval nodes and current payment limits, check if context is correctly retained.
- View the system statistics panel, confirm that the context turn count for `messages` meets configuration requirements, with no abnormal truncation.
- View the `chatId` field of the dialogue, confirm that cross-session context does not become mixed.
- Input a policy-related question exceeding 2000 tokens, check if the reply is fully output without forced truncation.
