# Policy and Regulatory Basis Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Workflow Orchestration

## What This Category of Data Looks Like
This category of data is sourced from the national public resource trading platform, natural resource trading systems, property right exchange systems and state-owned asset supervision systems. The update frequency is daily. Commonly processed documents include transfer announcements, trading notices, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements and property right transfer descriptions. Documents typically include fields such as subject ownership number, trading method, margin requirements and transaction conditions. Land use right documents include parcel area and usage term parameters. Mining right documents include mining area scope information. State-owned property right transaction documents include evaluation value and transferor qualification requirements. Common field units include square meters, parcels and ten thousand yuan.

## Constraints Imposed on Workflow Orchestration
This category of data originates from multiple sources and updates daily. The workflow’s knowledge base sync cycle must match the daily update rhythm to avoid outdated policy references. Document fields vary significantly across different types. `variables` must be configured in the workflow to distinguish exclusive field verification rules for land, mining rights and state-owned property rights. Ownership verification and material review are core time-consuming steps. The workflow must connect the policy basis Q&A node and the ownership verification node in series. Errors carry serious consequences, so a failure branch must be configured. This branch triggers a manual review process when policy matching fails or ownership verification encounters exceptions. Document formats vary across different sources. Unified document parsing adaptation rules must be configured at the workflow start node to ensure the accuracy of policy extraction.

| Configuration Item | Recommended Value | Rationale |

## Three Common Misconfigurations
- Symptom: The execution order of workflow nodes does not match expectations after configuring right and lower connection points. Cause: The functional differences of connection points are not clearly understood. The right conditional branch connection point is mistakenly used as a serial execution connection point, leading to incorrect workflow logic.
- Symptom: The question-raising link is not automatically triggered after the workflow starts. Cause: The startup trigger rule is not configured via `nodeId`, and the workflow startup event is not bound to the question-raising node.
- Symptom: No output results are generated by workflow code running nodes after local deployment. Cause: Output variable mapping for nodes is not configured. The code execution result is not bound to the output fields in `variables`, preventing the workflow from passing results between steps.

## How to Verify Correct Configuration
- View the knowledge base sync logs to confirm that data sync tasks have completed daily at midnight.
- Test different types of documents including transfer announcements and property right transfer descriptions to confirm that the workflow can correctly extract policy references from corresponding fields.
- Simulate node connection configurations to verify that right connection points are used for conditional branches and lower connection points are used for serial execution.
- Trigger an empty knowledge base scenario to confirm that the workflow skips the large model search link and directly returns preset prompts.
