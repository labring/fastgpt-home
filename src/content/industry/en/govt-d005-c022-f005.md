# Policy and Regulatory Basis Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category is primarily sourced from the national public resource trading platform, natural resource trading systems, property right exchange systems and state-owned asset supervision systems, with a daily update frequency. Commonly processed documents include transfer announcements, trading notices, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer specifications and similar items. Core fields cover trading subject ownership, restriction conditions, valuation standards, margin requirements and transaction confirmation rules. All data is generated across the full transaction lifecycle for land use rights, mining rights and state-owned property rights transactions.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Link
Data sources are scattered across multiple official systems, so tool calling must adapt to permission verification and access logic for multi-source data. The daily update requirement means plugin trigger frequency must align with the data update rhythm to avoid calling expired or unsynchronized policy content. Diverse document types require plugins to support parsing announcements, applications and transaction vouchers in different formats. Core fields involve sensitive content such as ownership and restriction conditions, so tool calling must strictly follow parameter verification rules to prevent incorrect matching of inapplicable policy bases. Since transaction legitimacy is directly linked to subject ownership and rule matching accuracy, tool calling must ensure retrieved policy content fully corresponds to the region and type of the current trading subject, avoiding cross-scenario calls of irrelevant rules.

## Three Common Mistakes
- A `400 InternalError.Algo.InvalidParameter: The tool` error is returned when calling the tool. The cause is failure to correctly limit the parameter theme of `functionCall`, causing the tool to attempt to call a policy retrieval function that does not match this category.
- The plugin call returns empty results or insufficient entries. The cause is failure to set a reasonable maximum number of documents per single call, or failure to adapt to the daily updated data rhythm of this category, resulting in calls to expired historical data.
- The created online plugin cannot be called during the process. The cause is failure to correctly bind the corresponding tool's permissions and trigger rules in the FastGPT process node, and failure to associate the plugin with the business logic of policy retrieval.

## How to Confirm the Configuration Is Correct
- Manually trigger tool calling, check if the returned policy documents include content of types such as transfer announcements and property right transfer specifications for this category.
- View the tool calling log, confirm that the `toolChoice` parameter is `auto` and the parameter theme of `functionCall` matches the three types of trading subjects in this category.
- Simulate the daily updated data scenario, trigger tool calling, confirm that the update time of the results meets the requirements of the same-day data.
- Test the trigger logic of the bound plugin in the process node, confirm that the plugin can be normally called by the process and return valid results.
