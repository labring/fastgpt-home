# Policy and Regulatory Basis Q&A for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Deployment and Upgrade

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
The daily documents for this category typically include transfer announcements, transaction notices, bid application materials, margin vouchers, transaction confirmation documents, listing result announcements, property transfer descriptions, and more. Data generally comes from national public resource trading platforms, natural resource trading systems, property exchange systems, and state-owned asset supervision systems, with an update frequency of once per day. Core fields of the documents usually involve transaction subject ownership, restriction conditions, margin requirements, transaction confirmation information, and other details. Document formats vary slightly across different sources, so parsing must be adapted to multi-source heterogeneous document structures.

## Constraints on deployment and upgrade
The multi-source heterogeneous data sources and daily update rhythm require configuring multi-data-source synchronization and incremental update logic during deployment, to avoid excessive system resource usage from full synchronization. The diversity of document formats requires configuring flexible document parsing rules to adapt to the structures of transfer announcements, transaction confirmation documents, and other documents from different sources. Core fields involve sensitive content such as ownership and margin requirements, so precise retrieval thresholds and permission controls must be configured to ensure the compliance of returned content. Errors in transaction-related Q&A can lead to serious consequences, so failure retry and content review mechanisms must be configured during deployment to prevent the output of incorrect content. For offline deployment scenarios, local dependencies must be configured in advance to avoid service exceptions caused by network dependencies.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 connections` | Adapts to the connection needs of daily multi-source data synchronization, avoiding connection pool exhaustion |
| `REDIS_URL` | `redis://:custom password@deployment server address:6379/0` | Used to cache frequently retrieved policy documents, adapting to the daily update data synchronization rhythm |
| `FE_DOMAIN` | `https://official secondary domain of the trading platform` | Binds the access address after deployment, ensuring the access link of the Q&A service complies with regulations |
| `STORAGE_S3_ENDPOINT` | `Corresponding storage node address of the public resource trading platform` | Stores daily updated transfer announcements, transaction confirmation documents, and other documents, adapting to the storage needs of category documents |
| `ROOT_KEY` | `32-bit randomly generated strong secret key` | Used to manage team permissions, ensuring only authorized personnel can access the deployed Q&A application |

## Three common mistakes
- Symptom: Team members cannot access the deployed Q&A application, and a permission denied prompt is displayed. Cause: The team permission management corresponding to `ROOT_KEY` is not configured, or members are not added to the corresponding authorized group.
- Symptom: A certificate error occurs when accessing the deployed service, and HTTPS access is unavailable. Cause: The certificate generated by mkcert is not configured in the service container corresponding to `FE_DOMAIN`, or the domain name is not bound correctly.
- Symptom: An Ai proxy error occurs during offline deployment, with the prompt get tiktoken dial tcp lookup. Cause: The tiktoken dependency package is not downloaded in advance in the offline environment, or the local model call proxy address is not configured.

## How to confirm the configuration is complete
- Execute the connection pool test command corresponding to `DB_MAX_LINK` to confirm that multi-source data connections are normal, with no connection timeout or rejection issues.
- Access the address bound to `FE_DOMAIN` to verify that the HTTPS certificate is valid, and the configured policy documents can be loaded and parsed normally.
- Submit a test query to confirm that the returned policy content comes from the configured data sources, and the update frequency meets the daily synchronization requirement.
- Verify the team permission configuration to confirm that authorized members can normally create and use the deployed Q&A application, with no permission error prompts.
