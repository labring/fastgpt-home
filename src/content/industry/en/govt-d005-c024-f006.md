# Policy and Regulatory Basis Q&A for Student Aid and Grant Review: Source Citation and Traceability

## What this category of data looks like
This category of data covers all process-related materials for student aid. Daily documents include family financial hardship assessment forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notice materials. Data sources include the national student aid management information system, school student registration systems, civil affairs low-income and special hardship data, and fiscal payment systems. Data updates follow a semester cycle. Each individual data entry includes fields such as student identity identifier, aid category, assessment result, disbursement amount, and associated public notice number. No additional statistical values are included.

## Constraints for Source Citation and Traceability
Data for this category is collected across multiple systems. Policy basis and application materials from different sources must be accurately bound for traceability. This requires ensuring that cited policy documents match specific application steps. The semester-long update cycle requires the knowledge base to complete full data synchronization each semester. This prevents expired policies or invalid data from being retrieved. Documents include public notice materials and disbursement lists. When citing, these must be linked to corresponding public notice numbers and disbursement records. This ensures traceability information can be traced back to official release channels. Fields for each individual data entry focus on student aid eligibility and fund flow. Cited content must be strictly limited to the corresponding scope of policy basis and application materials. This avoids interference from irrelevant information.

## Configuration Guidelines
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `quoteMaxToken` | 3000–5000 token | Policy documents and application materials for this category have a relatively long total length. Sufficient context is needed to carry multi-source data |
| `responseData` | Return full citation metadata | This category requires traceability to specific documents and system sources. Full metadata can include document type, source system, update time, and other information |
| `detail` | Enable detailed traceability mode | Specific cited fields and associated numbers must be displayed to meet audit and public notice requirements |
| Single search limit | Top 10 retrieved results | The number of policy basis documents for this category is relatively concentrated. Too many retrievals will cause context overload |
| Knowledge base update cycle | Synchronize once per semester | Data is updated on a semester cycle. Synchronization frequency matches business rhythm |
| Maximum context length | 8000–12000 characters | The total length of spliced multi-source documents for this category is relatively large. This setting adapts to long-context models |

## Three Common Misconfigurations
- Setting `quoteMaxToken` to 3000 results in no context being received by the large language model. This occurs when `quoteMaxToken` exceeds the context limit supported by the current model. The system truncates the content and fails to pass valid context.
- Citations are displayed, but the response content does not include policy or application material content from the knowledge base. This happens when the `detail` mode is not enabled, or `responseData` is not configured to return full metadata. Retrieved documents are not correctly injected into the large language model context.
- Knowledge base calls in workflows do not take effect. No corresponding citation results appear for the passed knowledge base ID. This occurs when the knowledge base ID is not correctly bound to the workflow's knowledge base call node, or the knowledge base is not set as a globally accessible resource for the workflow.

## How to Verify Successful Configuration
- Check the knowledge base retrieval log. Confirm that the number of retrieved documents matches the configured single search limit.
- Run a test query for student aid policy. Review the citation metadata in the returned results. Confirm that full information such as document source and associated numbers is included.
- Check the response generated by the large language model. Confirm that the content includes specific policy basis and application material content from retrieved documents.
- Verify workflow calls. Confirm that the passed knowledge base ID matches the ID of the target knowledge base. Confirm that the workflow has permission to access the knowledge base.
