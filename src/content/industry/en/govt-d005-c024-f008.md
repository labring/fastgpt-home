# Policy and Regulatory Basis Q&A for Student Aid and Subsidy Review: Document Parsing and Chunking

This document is written based on the configuration logic of FastGPT v4.17.0.

## What the Data for This Category Looks Like

Data for this category mainly comes from the national student aid management information system, school student status system, civil affairs low-income and special hardship data, and fiscal payment system. The update frequency is every semester. Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Data fields cover qualification certification-related information, student status status, fund disbursement details, and more. Single batch documents contain multiple student entry contents.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Link

Mixed structured and semi-structured documents from multiple sources require parsing logic compatible with docx, pdf, and other formats. Semester-level batch update requirements demand that document parsing and chunking have parallel processing capabilities to avoid single-processing timeouts. Single batch documents contain multiple student entries. Chunking must retain the complete context of a single student’s application or certification to avoid lost associated information after splitting. Data involves aid qualification and fund disbursement. Chunked content must accurately match policy basis and specific materials, with no field misalignment or information fragmentation. For internal network deployment scenarios, parsing rules for internal system document sources must be adapted to avoid content loss caused by differences from external network parsing logic.

## How to Configure Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Adapts to the semantic length of student aid policy clauses and application materials, avoids overly large chunks causing context fragmentation or overly small chunks causing semantic splitting |
| `chunkSplitter` | Split by paragraph + heading | Matches the structure of documents containing policy clauses, application forms, and public notification lists, retains complete context of single-category business content |
| `customPdfParse` | Enabled | Adapts to some complex format pdf versions of aid application forms and review forms, accurately extracts table fields and associated text |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Meets the parsing time requirement for single batch multi-page aid documents, avoids processing timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports uploading single packaged multi-class public notification materials and batch application documents |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking parameters for different types of aid documents, adapts to differentiated processing needs of business scenarios |

## Three Common Misconfigurations

- Phenomenon: After importing internal network Confluence pages into the knowledge base, the extracted content is empty or missing key fields. Cause: `customPdfParse` is not enabled to adapt to internal system document formats, or internal network parsing permissions are not configured, resulting in failure to pull content normally.
- Phenomenon: Parsing of a single thousand-page pdf version of a scholarship and grant review form fails, returning a timeout status code. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is less than the actual parsing time, triggering a timeout interruption.
- Phenomenon: After importing associated documents of policy materials and aid materials, chunked content is not bound to corresponding policy clauses, and context association cannot be achieved. Cause: `chunkSettingMode` is not configured as parent-child chunking mode, or the association rules between parent and child chunks are not correctly specified, resulting in chunking being disconnected from policy basis.

## How to Confirm Configurations Are Correctly Set

- Upload a single pdf version of the family economic hardship certification form, check if the parsed text contains all table fields and filled content, to confirm that the parsing configuration takes effect.
- Upload 3–5 batch aid documents, check if the task processing progress displays parallel task identifiers, to confirm that the parallel processing logic takes effect.
- Upload a combined file of policy documents and corresponding aid application forms, check if chunked content is associated with corresponding policy clauses, to confirm that the parent-child chunking configuration takes effect.
- Import internal network Confluence format aid documents, check if the extracted content is complete, to confirm that the internal network parsing configuration is correct.
