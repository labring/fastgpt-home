# Policy and Regulatory Basis Q&A for Work Safety Hazard Investigation and Governance: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category primarily comes from work safety supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily documents include hazard investigation checklists, hazard management ledgers, rectification notices, review records, and major hazard registration and supervision order forms. A single document typically includes structured fields such as hazard identifier, rectification responsible party, rectification deadline, and review conclusion. Some documents include unstructured content such as on-site inspection photos and before-and-after rectification comparison images. The size of a single document typically falls within the 100–500 MB range.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Daily updated multi-source data requires tool calling configurations to support incremental pull logic. This avoids reprocessing expired data. Mixed structured and unstructured document types require plugins to support table parsing and multimodal content recognition. Data from multiple systems requires cross-source authentication rules. This ensures compliance with data access permission requirements. The accuracy of core fields such as hazard number and rectification deadline requires tool calling return results to strictly align with original document fields. Unauthorized adjustment of field mapping relationships is not allowed.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Supports automatic selection of tools matching the current business, adapts to mixed needs of policy Q&A and hazard data query, and aligns with the tool scheduling logic of FastGPT v4.17.0 |
| `functionCall` | `enabled` | Forces the model to call tools in a specified format. This ensures that policy basis Q&A return results meet the structured output requirements of compliant documents |
| Single Tool Call Limit | `Top 6 entries` | Matches the daily updated hazard data volume, avoids returning excessive redundant information that impairs model understanding |
| Tool Call Timeout | `30–60 seconds` | Adapts to the time required for multi-system data pulling and document parsing, balances response speed and data integrity |
| Single Call Data Volume Limit | `500 MB` | Matches the average size of single documents in this category, prevents call failures due to excessive data size |
| Field Mapping Rules | Align with original document field names | Ensures accuracy of hazard data, avoids policy comparison errors caused by field mismatches |

## Three Common Misconfigurations
- Phenomenon: A format error is returned when calling multimodal tools to process hazard site photos. Cause: Input format parameters for multimodal content are not correctly configured. Image base64 encoding or standard URL format required by the tool is not passed.
- Phenomenon: Content cannot be parsed after passing in a hazard document link. Only a version update prompt is displayed. Cause: The adaptation rules of the document parsing plugin are not updated. The parsing logic is not adjusted for checklist and ledger documents of this category.
- Phenomenon: Empty content is occasionally returned when calling a deployed model. An error is reported after the process gets stuck. Cause: No timeout retry mechanism is configured for tool calling. Automatic retry is not triggered after a single call times out, resulting in the request being discarded.

## How to Verify Proper Configuration
- Initiate a policy basis Q&A request. Check whether the tool calling log correctly matches the configured tool list.
- Upload a hazard investigation checklist document. Verify that the parsing result includes the core fields in the document, with no missing or incorrect mappings.
- Pass in an on-site inspection photo. Confirm that the multimodal tool can correctly identify the hazard identification text in the image.
- Simulate a multi-system data pull request. Check whether the cross-source authentication configuration takes effect, with no permission exception errors.

The values provided are common starting points and should be measured against the reader's own samples.
