# Policy and Regulatory Basis Q&A for Engineering Construction Project Approval: Multi-turn Dialogue and Prompt Words
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category's data looks like
Data for this category comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform, and is updated daily. Daily processed documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, completion record filing forms, and similar documents. Data fields cover approval nodes, participating unit qualifications, project record information, and more. The format follows government approval standards, with no custom special units.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt words stage
The daily update feature of data requires that dialogue context must be associated with the latest approval data in real time, to avoid using cached old version information. Government approval documents are mostly structured short texts. Multi-turn dialogue must strictly limit the context scope to prevent the introduction of irrelevant general policy content. Information such as participating unit qualifications and approval links must be tracked and passed through `variables` to ensure that each round of dialogue is based on the exclusive data of the current project. Approval process nodes are highly correlated, so `chatId` must be retained to bind project uniqueness and avoid confusion of cross-project data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique approval number of the current project | Ensure that the dialogue context of the same project is not confused with other projects, which meets the project uniqueness requirements of government approval |
| `messages` | Retain the last 10 rounds of dialogue content, truncate history exceeding 2000 characters | Government approval documents are relatively long, limiting context length to avoid exceeding model processing thresholds, while retaining key approval node information |
| `variables` | Pass three core variables: project ID, approval link, participating unit name | Accurately match the exclusive approval data of the current project, avoid calling irrelevant qualification database or credit platform data |
| Maximum context | 800–1200 characters | Government approval documents are mostly structured short texts, this range can cover core approval basis content |
| Question optimization | Enabled, add approval link limiting terms to user questions | User questions often omit project background, after optimization, it can accurately associate with the approval data of the current project |
| Single match limit | Top 5 results | Government approval data has clear entries, 5 results can cover core policy basis and avoid interference from redundant information |

## Three common mistakes
- Phenomenon: The multi-turn dialogue output contains the previous round of AI reply content. Cause: No node configured in the workflow to retain only the final output, and the complete `messages` of the previous round of dialogue were passed to the subsequent dialogue link.
- Phenomenon: The workflow is configured with an HTTP request for online search, but directly calls AI dialogue during execution. Cause: No precondition set in the workflow to trigger the HTTP request, or the result of the HTTP request was not correctly bound to the input variables of the subsequent dialogue.
- Phenomenon: CORS error occurs when the frontend calls the dialogue interface. Cause: No domain name whitelist for frontend requests added in FastGPT's cross-domain configuration, causing the browser to block the cross-domain request.

## How to confirm the configuration is complete
- Initiate a test dialogue, enter a question related to the current project's approval, and check that the output only contains the approval basis content of the current project, with no irrelevant historical dialogue residues.
- View the workflow execution log, confirm that the HTTP request link is executed before the AI dialogue, and the result returned by the request has been correctly bound to the dialogue input variables.
- Check the cross-domain configuration page, confirm that the domain name of the frontend request has been added, and verify that there is no error when the frontend calls the interface.
- Pass the `variables` parameter of the test project, and check whether the dialogue output correctly associates with the exclusive approval documents of the corresponding project.
