# Policy and Regulatory Basis Q&A for Engineering Construction Project Approval: Workflow Orchestration

## What the Data for This Category Looks Like
Data sources for this category include the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. The update frequency is daily. Daily associated documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms, among others. Data fields cover approval node status, participating unit qualification information, project record numbers, licensing time limit requirements, and more. Most units are standardized fields such as project numbers, personnel names, and qualification levels. There are no custom non-standard units. The data structure is tightly bound to the full engineering construction approval workflow.

## What Constraints Do These Characteristics Impose on the "Workflow Orchestration" Link
Data sources are scattered and updated daily. Workflows must support parallel queries across multiple system data sources to ensure access to the latest approval policies and real-time project information. There are various types of daily associated documents. Workflows must preset dedicated retrieval rules for different approval links to avoid confusing policy basis across phases such as project initiation, construction, and acceptance. Most data fields are standardized items like project numbers and qualification levels. Workflows must configure precise matching logic to prevent retrieval result deviations caused by field mismatches. Additionally, the approval process involves multi-node parallel approval. Workflows must split retrieval tasks by approval link to avoid redundant data interfering with answer accuracy.

## How to Set the Configuration
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 8 entries | The retrieval content for this category mostly consists of standardized approval basis. The top 8 entries can cover core policy clauses and project-related information |
| Maximum Context Length | 1200–1500 characters | Adapts to the standard length of engineering construction approval policy texts, avoiding truncation of key basis content |
| `variables` | Bind project number and approval node type | Accurately locate the exclusive policy basis for the corresponding project, narrowing the retrieval scope |
| `nodeId` | Bind approval link node ID | Accurately match the approval node corresponding to the current workflow, avoiding cross-node retrieval confusion |
| Timeout Threshold | 60 seconds | Adapts to the response duration of multi-data source queries, preventing workflow interruptions caused by cross-system queries |

## Three Common Mistakes
- Workflow calls a specified database and returns empty fields. The cause is that the project number parameter in `variables` is not correctly bound, resulting in an unrestricted retrieval scope and matching irrelevant general policy content.
- The channel link calling the workflow prompts "undefined" is not valid JSON. The cause is that the workflow output format is not configured as a standard JSON structure. The test environment does not verify the output format, leading to normal testing but abnormal format triggering by online channels.
- The number of retrieval results exceeds the preset limit. The cause is that the single search limit is not set, resulting in too many redundant policy clauses being returned, interfering with the display and accuracy of core Q&A content.

## How to Confirm the Configuration Is Correct
- In the workflow debugging panel of FastGPT v4.17.0, manually enter the project number and approval node type, trigger the workflow, and check whether the returned results include the policy basis for the corresponding link.
- Copy the channel link of the workflow, use a simulation request tool to initiate a call, and confirm that the returned content is in standard JSON format with no syntax errors.
- Adjust the single search limit to the top 3 entries, verify whether the number of retrieval results meets expectations, and confirm that there is no redundant data interference.
- View the workflow operation log, confirm that the response duration of cross-data source queries does not exceed 60 seconds, and there are no timeout error records.
