# Policy and Regulatory Basis Q&A for Engineering Construction Project Approval: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data for this category primarily comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and public credit information platform. Daily processed documents include fixed-format approval documents such as construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, and completion acceptance record forms. Data updates occur once per day. Document structures center on three core fields: approval process nodes, participating construction unit qualifications, and licensing requirements. All data is generated around approval links from project initiation to project completion.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
Data from multiple systems requires unified indexing. The retrieval link must clearly specify the target knowledge base set to prevent mixing data from other categories. The daily update frequency requires the retrieval system to support incremental synchronization configuration, reducing resource consumption from full indexing. For fixed-format approval documents, core fields include participating construction unit qualifications, approval process nodes, and licensing requirements. Retrieval must prioritize matching these structured fields. Long policy texts account for a large share of the dataset, so block truncation rules must be configured to prevent single recalled content from exceeding the context window.

## Configuration Settings
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches the precision requirements for engineering construction policies, preventing recall of irrelevant non-approval policies |
| `limit` | `8–12 top retrieved entries` | Controls the number of knowledge base entries retrieved per request, aligned with the context window size for engineering approval policies |
| `searchMode` | `Precise Matching` | Prioritizes matching core fields such as approval nodes and qualification requirements in documents, aligning with the structured characteristics of documents in this category |
| `usingReRank` | `Enabled` | Performs secondary ranking on retrieved results to raise the display priority of highly relevant policy texts |
| `datasetSearchUsingExtensionQuery` | `Enabled, set truncation threshold to 1200 characters` | Handles policy document blocks that exceed length limits, preventing overly long content from negatively impacting retrieval performance |
| `collectionIds` | `Bind the exclusive collection ID for engineering construction project approval policies` | Only retrieves approval documents from this category, preventing mixing in knowledge base content from other domains |

## Three Common Configuration Mistakes
- When calling the API to return knowledge base content, locally uploaded policy-related images cannot be displayed in third-party systems, and the returned image link format is abnormal. This occurs because the API proxy forwarding rule for local knowledge base files is not configured, making image resources inaccessible via public network paths.
- The workflow throws a "Cannot convert undefined or null to object" error during runtime, and the interface shows process execution failed. This happens because the `collectionIds` parameter is not configured correctly, and an empty target knowledge base collection identifier is passed, causing the retrieval link to fail to identify the data source.
- Even if the `limit` parameter is set to 1500 characters, knowledge base blocks exceeding 1500 characters are still retrieved and referenced. This occurs because the block truncation configuration for `datasetSearchUsingExtensionQuery` is not enabled, or the truncation threshold is not aligned with the `limit` parameter, so overly long content is not processed correctly.

## How to Verify Successful Configuration
- Log in to the FastGPT v4.17.0 backend, navigate to the knowledge base management page, and confirm the `collectionIds` parameter is bound to the exclusive collection ID for engineering construction project approval policies.
- Submit a test query related to engineering approval, check that the number of returned results matches the preset value of the `limit` parameter, and that no irrelevant non-approval content is included.
- Upload a policy document containing local images, call the API to retrieve the document, and verify that the returned image links load normally in third-party systems.
- Upload a policy text exceeding 1500 characters, retrieve the document, and confirm that the overly long content is either truncated or fully retained per the configured rules.
