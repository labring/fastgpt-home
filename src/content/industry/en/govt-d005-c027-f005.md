# Policy and Regulatory Basis Q&A for Engineering Construction Project Bidding: Tool Calling and Plugins

## What this category of data looks like
Data for this category primarily originates from the national public resource trading platform, local trading platforms, project approval systems, and bidding and tendering supervision systems, with a daily update frequency. Commonly processed documents include bidding announcements, qualification pre-qualification documents, bidding documents, tendering documents, bid evaluation reports, bid winner candidate announcements, and bid result announcements. Most document structures include fields such as section division, qualification requirements, bid evaluation expert records, and objection and complaint records. There is no unified fixed unit, as values vary by document type.

## What constraints these characteristics impose on the tool calling and plugins workflow
Daily updated data sources require tool calling to be configured with high-frequency synchronization logic, to ensure the timeliness of retrieved corpus. Mixed calls of multiple document types require plugins to adapt to parsing rules for different formats, supporting structured field extraction from bidding announcements and unstructured text processing for bid evaluation reports. Cross-system data calls require configuring platform authentication parameters, to avoid retrieval failures caused by permission restrictions. Dispersed fields such as sections and qualification requirements in documents require tool calling to support precise field matching, to prevent irrelevant content from interfering with Q&A results. Third-party API access requires configuring authentication parameters for the corresponding platform, to avoid reliance on platform point consumption.

## How to set configurations
This guide is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ------ | -------- | ------------ |
| `toolChoice` | `auto` | Enables automatic tool selection for multiple types of bidding documents, covering structured and unstructured data retrieval |
| Single tool call timeout | 600 seconds | Matches typical response durations across multiple public resource trading platforms, avoiding call failures due to platform delays |
| `functionCall` trigger threshold | Top 8 entries | Covers necessary information from core documents such as bidding announcements and bid evaluation reports, avoiding redundant results |
| Document format adaptation plugin | Supports PDF, DOCX, XML, and files under 1000 MB | Matches common formats and size limits for bidding, bid evaluation, and winning announcement documents in this category |
| Traceability information display toggle | Enabled | Meets business requirements for policy basis traceability, and aligns with bidding compliance inspection needs |
| Third-party API access configuration | Bind official API keys for corresponding public resource trading platforms | Supports pulling bidding and tendering data using third-party platform interfaces, avoiding reliance on platform point consumption |

## Three common mistakes
- Symptom: After calling the public resource trading platform API in a workflow, the returned result is empty. Cause: API permission authentication parameters for the corresponding platform are not configured, resulting in failure to pull bidding and tendering related documents.
- Symptom: The policy basis Q&A generated by AI does not include original document traceability information. Cause: The traceability information display configuration is not enabled, or the document ID and location fields returned by the API are not bound to the response content.
- Symptom: The model used during tool calling does not match the preset, resulting in parameter incompatible errors. Cause: The model bound to tool calling is not specified in the conversation configuration, and the default model does not support structured parsing of bidding documents.

## How to confirm the configuration is correct
- Initiate a policy basis Q&A targeting a specific bidding announcement, check whether the returned result includes the name and specific location of the corresponding document.
- View the tool calling logs to confirm whether the latest document data from the public resource trading platform has been successfully pulled.
- Upload bidding documents in different formats, confirm that the plugin can normally parse text content and extract key fields.
- Adjust the recall count configuration for tool calling, verify whether the number of returned results meets the preset requirements.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
