# Policy and Regulatory Basis Q&A for Engineering Construction Project Bidding: Document Parsing and Chunking

## What data looks like for this category
Data for this category primarily comes from national public resource trading platforms, local trading platforms, project approval systems, and bidding supervision systems, with a daily update frequency. Daily processed documents include bidding announcements, pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate announcements, and successful bid result announcements.

Most document structures include fields such as bid package division, qualification requirements, bill of quantities, bid evaluation rules, and successful bid information. Some documents split content by project batch or bid package. Units involved include quantities, project cycles, and qualification levels.

## What constraints do these characteristics impose on the document parsing and chunking link
Documents from multiple platforms have inconsistent formats, including PDF, Excel, and Word. This requires the parsing link to support content extraction across different formats.

The large volume of daily updated batch documents requires setting reasonable timeouts and batch limits to avoid parsing interruptions.

Semantic units such as bid package division, qualification requirements, and bill of quantities have strong correlations. Chunking must preserve the integrity of these units to avoid semantic breaks after splitting.

Bid evaluation reports and bid announcement documents have relatively fixed formats, but their field positions are inconsistent. Parsing must accurately match corresponding content, otherwise it will affect the accurate matching of subsequent policy basis.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600–1200 seconds` | This category processes documents in batches daily, and individual document parsing takes a long time. Setting this range prevents normal parsing from being interrupted |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Documents such as bidding documents and bid evaluation reports may contain a large number of attachments. Setting this upper limit prevents upload failures |
| `customPdfParse` | Enabled | PDF documents in this category often contain complex tables and bid package divisions. Enabling custom parsing improves content extraction accuracy |
| `chunkSize` | `800–1200 characters` | Content such as qualification requirements and bid evaluation rules in documents must retain semantic integrity. This range prevents semantic breaks after chunking |
| `chunkSplitter` | Split by paragraph + heading | Documents in this category are organized by chapter and bid package. Splitting by paragraph and heading preserves the document's structural logic |
| `chunkSettingMode` | Manual configuration | The structural differences between different types of bidding documents are large. Manual configuration adapts parsing requirements for specific scenarios |

## Three Common Mistakes
- Scenario: In a private deployment scenario, the PDF bidding document parsing service returns success, but FastGPT reports a timeout error. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted, and the default timeout duration cannot adapt to the parsing process of large bidding documents.
- Scenario: Unable to read table content from uploaded Excel tender documents in a workflow. Cause: Structured document parsing configuration was not enabled, and chunking rules adapted to table content were not selected.
- Scenario: Parsing interrupts mid-process when uploading a large number of bidding documents in batches, and cannot resume parsing after restarting Docker. Cause: A reasonable upper limit for `UPLOAD_FILE_MAX_SIZE` was not set, and batch parsing concurrency control parameters were not adjusted, leading to resource exhaustion or task timeout.

## How to Verify Configuration is Complete
The following verification steps apply to FastGPT v4.17.0:
- Upload a single large bidding document, check the parsing status and results, confirm that the parsing duration does not exceed the preset `PARSE_FILE_TIMEOUT_SECONDS` range.
- Upload an Excel format tender document, verify that the parsed result includes content such as the bill of quantities and qualification requirements in the table.
- Upload multiple bidding documents in batches, observe the execution status of parsing tasks, confirm there are no mid-process interruptions.
- View the chunked document content, confirm that core semantic units such as bid packages and qualification requirements are not incorrectly split.

The values listed above are common starting points and should be evaluated against the user's own samples.
