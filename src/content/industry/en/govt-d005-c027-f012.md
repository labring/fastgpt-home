# Policy and Regulatory Basis Q&A for Engineering Construction Project Bidding: Deployment and Upgrade

## What the data for this category looks like
The data sources for this category are national public resource trading platforms, local public resource trading platforms, project approval systems, and bidding supervision systems. The update frequency is daily. Daily processed documents include bidding announcements, pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements. Core involved fields include bid section division, qualification requirements, bid evaluation expert records, objection and complaint content, and other related fields. This covers policy-related documents across all bidding process stages for engineering construction projects.

## What constraints these characteristics impose during deployment and upgrade
Daily updated data sources require a stable incremental synchronization mechanism to be configured during deployment, to avoid excessive system resource usage from full synchronization. Differences in structure across multiple document types require adapting parsing rules for different documents, to ensure accurate extraction of policy clauses. Data access from multiple government platforms requires configuring storage and authentication parameters that meet government data security requirements. Additionally, errors during the bidding process carry severe consequences, so an upgrade rollback path must be reserved during deployment. This ensures service interruptions do not impact project workflows.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 150–250 connections | Adapts to the concurrent read demand for multiple types of bidding documents in daily incremental sync, avoiding database connection exhaustion |
| `STORAGE_S3_ENDPOINT` | `https://s3.gzggzy.gov.cn` | Connects to the dedicated storage node of the local public resource trading platform, ensuring compliance when reading archived documents |
| `REDIS_URL` | `redis://localhost:6379/0?password=specified authentication key&timeout=300 seconds` | Caches frequently queried policy clause fragments, reducing latency from repeated calls to government platforms |
| `FILE_TOKEN_KEY` | 32-character authentication key | Verifies the legitimacy of incoming document sources, preventing unauthorized data from entering the Q&A service |
| `FE_DOMAIN` | `https://ggzy.gov.cn/internal` | Restricts internal government network access scope for the Q&A service, meeting security requirements |

## Three common configuration errors
- A full-screen overlay appears on the login screen, preventing user interaction, with no error logs generated. This occurs when `FE_DOMAIN` is configured with an external public network domain name, which does not comply with internal government network access restrictions, leading to failure to load front-end static resources.
- Policy clauses returned by the Q&A service are missing bid section or qualification requirement information. This occurs when `DB_MAX_LINK` is set too low. When concurrently reading multiple bidding documents, some database connections are released, and fields are not fully retrieved.
- Incremental sync tasks fail to execute, with logs showing storage connection exceptions. This occurs when `STORAGE_S3_ENDPOINT` is configured incorrectly, not pointing to the government platform's dedicated storage node, leading to failure to properly read archived documents.

## How to confirm the configuration is complete
- Complete a basic deployment using the FastGPT v4.17.0 deployment package, run a local database connection test, and verify that the configured concurrent connection number can normally handle multi-document read requests.
- Initiate a manual incremental sync task, check that archived documents from the government platform are fully transferred to local storage, with no abnormal errors.
- Access the `FE_DOMAIN` address bound to the internal government network, confirm that the login screen has no abnormal overlay, and that the Q&A service interface can be accessed normally.
- Configure a test query for objection and complaint content, verify that the returned results include corresponding qualification requirements and bid evaluation record fields.
