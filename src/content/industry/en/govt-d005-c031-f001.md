# Policy and Regulatory Basis Q&A for Construction Project Environmental Impact Assessment (EIA) Approval: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data originates from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Updates occur on an irregular basis. Routine documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. The data exists as a mix of structured declaration form fields and unstructured documents. Core fields include project category, EIA level, pollution prevention measures, public participation status, approval opinions, and other relevant items.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
Data sources are diverse and combine structured and unstructured formats. Interfaces must support both structured field queries and unstructured document content parsing. Updates occur on an irregular basis. Interfaces must accommodate both incremental synchronization and full data query requirements. Routine document formats vary. Interfaces must support reading and parsing of different file types. Core fields such as project category and EIA level are key for matching policy basis. Interface parameters must accurately match the corresponding field names. Error consequences are severe. Interfaces must include pre-check logic to prevent incorrect data from flowing to downstream links.

## Three common errors
- Empty policy basis content is returned after calling the interface. Cause: The project core fields in `variables` are not correctly bound, causing the Q&A model to fail to match the corresponding policy basis.
- Importing the HTTP plugin fails, with a configuration error prompt. Cause: The `Authorization` parameter is not set according to government system interface requirements, or the token format does not meet verification rules.
- Interface call triggers a timeout error. Cause: The timeout threshold is not set to a duration that meets business requirements, making it impossible to complete long document parsing and cross-system data verification.

## How to confirm the configuration is complete
- Use the interface testing tool in the FastGPT backend, pass preset project category and EIA level parameters, initiate a call, and check if the returned results include matching policy basis content.
- Call the interface to obtain `responseData`, confirm that the returned content only includes structured core fields and document summaries, with no redundant unnecessary data.
- Simulate a request containing a long EIA document, verify that the interface response time does not exceed the set timeout threshold.
- Replace an invalid `Authorization` token, test whether the interface returns an identity verification failure prompt, confirm that the permission logic functions correctly.
