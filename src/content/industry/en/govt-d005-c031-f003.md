# Policy and Regulatory Basis Q&A for Construction Project Environmental Impact Assessment (EIA) Approval: Multi-turn Dialogue and Prompt Configuration
## What This Category of Data Entails
This category of data covers daily operational documents from EIA departments of ecological environment authorities, administrative examination and approval bureaus, construction units, and EIA institutions. Included documents are environmental impact assessment reports or report forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval replies. Data sources include the national unified EIA declaration and approval system for construction projects, ecological environment zoning control results, pollutant discharge permission platforms, and monitoring data. Update frequency is irregular, with no fixed cycle. The document structure centers on individual projects, and includes fields such as project category, EIA level, and pollution prevention measures. There are no unified fixed units; fields and units adjust based on specific project details.

## Constraints Imposed by Data Characteristics on Multi-turn Dialogue and Prompt Configuration
The characteristics of this category of data impose multiple constraints on multi-turn dialogue and prompt configuration. First, multi-source and heterogeneous data sources require that unique project identifiers be retained in multi-turn dialogue. These identifiers link declaration, approval, and monitoring data from different systems, and prevent context fragmentation. Second, irregular update frequencies require prompts to prioritize calling real-time synchronized system data. Reference static documents only when real-time synchronized data is unavailable. Third, the document structure centers on individual projects, and fields have no fixed units. Multi-turn dialogue must gradually clarify key information such as project category and EIA level. Prompts must limit output to match specific project scenarios, and avoid generic statements.

## Three Common Misconfigurations
- Issue: Cannot upload EIA-related documents when calling the dialogue interface, and the interface returns an empty file field. Cause: No binding parameters for file upload are configured in `variables`, and front-end uploaded documents are not linked to the current unique project identifier.
- Issue: Prompt accuracy is insufficient, and cannot accurately distinguish EIA policy basis from general environmental protection knowledge. Cause: The system prompt does not clearly limit the response scope to only policy and regulatory basis for construction project EIA approval, and does not distinguish boundaries between different prompt roles.
- Issue: Output content is scattered across multiple modules during multi-turn dialogue, and cannot be integrated into a unified policy basis response as required. Cause: No binding rules for output modules are configured in `variables`, and no logic for content integration is defined.

## How to Verify Proper Configuration
- Initiate a test dialogue with a preset unique project identifier, check whether `chatId` is correctly bound, and confirm that the dialogue context retains core information of the corresponding project.
- Upload a single EIA-related document, call the dialogue interface, and confirm that the interface can normally receive and link the uploaded document content.
- After configuring a prompt with limited scope, initiate a query, and check that the output content only focuses on policy and regulatory basis for construction project EIA approval, with no irrelevant statements.
- Simulate a multi-turn interaction process, check whether `messages` appends system prompts and user queries by turn, and confirm that no context loss or cross-project confusion occurs.
