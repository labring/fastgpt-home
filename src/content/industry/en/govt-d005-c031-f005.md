# Policy and Regulatory Basis Q&A for Construction Project Environmental Impact Assessment (EIA) Approval: Tool Calling and Plugins

## What This Category of Data Looks Like
The data sources for this category include the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and environmental monitoring data.
Daily documents cover five core types: environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. Each individual project has a complete set of associated approval documents.
Data updates occur on an irregular schedule, synchronized with project approval progress and policy adjustments.
Core document fields include project category, EIA level, pollution prevention measures, public participation status, and approval opinions, among others. There is no unified fixed unit field; values adjust based on document type.

## Constraints for Tool Calling and Plugins
Multi-source data sources require cross-system docking plugins for tool calling. This ensures synchronous access to information from different platforms such as the declaration system and zoning control results.
Single-project documents have large volumes and diverse structures. Tool calling must limit the range of recalled documents and number of tools used per call to avoid context overload.
Data updates have no fixed cycle. Plugins must support dynamic pulling of latest data to maintain information timeliness.
Core fields are closely linked. Tool calling must ensure parameters match field formats across different document types to prevent information extraction errors from field incompatibility.
Approval process errors have serious consequences. Tool calling must include failure retry and clear exception prompt mechanisms to ensure calling rigor.

## Three Common Misconfigurations
- Phenomenon: Extra irrelevant numbers or garbled text appear in tool calling return results, which do not match preset specified reply content. Cause: Constraint rules for `functionCall` are not configured correctly. This creates a conflict between tool calling logic and trigger conditions for specified replies, leading to unexpected tool calls.
- Phenomenon: Document fields returned by tool calling are empty, and valid policy basis cannot be extracted. Cause: Field formats for documents in this category are not matched. Plugins cannot identify core content fields across different document types, causing information extraction failure.
- Phenomenon: Tool calling times out, and the approval process is interrupted. Cause: A reasonable call timeout threshold is not set. Cross-system data pulling time exceeds the preset threshold, triggering a timeout interruption.

## How to Verify Correct Configuration
- Trigger a project EIA policy basis query. Confirm tool calling only triggers when EIA level and ecological zoning are matched.
- View tool calling logs. Verify `toolChoice` automatically selects the docking plugin for the corresponding system, with no abnormal calling records.
- Simulate cross-system data pulling. Confirm the call timeout threshold setting aligns with actual pulling time, and adjust to a reasonable range.
- Check context window configuration. Ensure total character count of single-project documents does not exceed the preset limit, with no context overflow prompts.
