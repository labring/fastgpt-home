# Policy and Regulatory Basis Q&A for Construction Project Environmental Impact Assessment Approval: Deployment and Upgrade

This page configuration applies to FastGPT v4.17.0.

## What this category of data looks like

Data sources for this category include the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Documents processed daily include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approvals. Document structure covers fields such as basic project information, pollution prevention measures, public participation status, and approval process results. There are no fixed unified units, and fields adjust dynamically based on project type and approval stage.

## What constraints these characteristics impose on deployment and upgrade

Data sources are scattered and updates have no fixed cycle. During deployment, configure multi-source data synchronization adaptation logic to avoid data lag or loss. Document structure is dynamic with non-fixed fields. During upgrade, support flexible document parsing and field mapping; fixed chunking rules cannot be relied upon. Compliance requirements for approval-related documents are high. During deployment, strengthen permission control and data traceability capabilities. During upgrade, synchronously update compliance verification logic. Additionally, format differences across multi-source data are significant. During deployment, configure a unified data standardization processing module to reduce subsequent maintenance costs.

## Configuration Parameters

| Configuration Parameter | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:yourpass@localhost:27017/fastgpt?authSource=admin` | Adapts to the multi-document storage needs of EIA approval business, ensuring persistent storage of approval applications, reports and other data |
| `REDIS_URL` | `redis://:yourredispass@localhost:6379/0` | Used to cache frequently queried policy provisions and approval rules, reducing repeated query load on the database |
| `DB_MAX_LINK` | `20–30` | Matches the peak concurrent query volume of EIA approval business, preventing query failures caused by exhausted database connections |
| `STORAGE_S3_ENDPOINT` | `http://localhost:9000` | Used to store large documents such as EIA reports and approval documents, compatible with locally deployed object storage services |
| `FE_DOMAIN` | `http://localhost:3000` | Configures the frontend access address, facilitating internal personnel access to the policy Q&A interface |
| `FILE_TOKEN_KEY` | `Random 32-character string` | Used to generate access tokens for EIA documents, ensuring access security for sensitive approval files |
| `ROOT_KEY` | `Custom complex key string` | Used to configure background management permissions, preventing unauthorized access to approval data and system configurations |

## Three Common Misconfigurations

- A curl-related execution error appears shortly after starting the `aiproxy` container. This occurs when `STORAGE_S3_ENDPOINT` is not configured correctly, or the associated storage service is not running normally, preventing the proxy from accessing EIA document resources.
- Historical approval data fails to load after upgrading the platform version. This occurs when the database configuration corresponding to `MONGODB_URI` was not migrated correctly, causing the new instance to fail to connect to the original data storage.
- The number of query results after deployment does not meet expectations. This occurs when the value of `DB_MAX_LINK` is not adjusted to match concurrent request volume, causing some queries to be truncated due to insufficient connections.

## How to Verify Successful Configuration

- Run the `docker-compose ps` command to confirm that all dependent services such as databases, caches, and proxies are in the Up state.
- Upload a test EIA report file, trigger a policy basis Q&A through the interface, and verify that the file can be parsed normally and relevant results are returned.
- Access the frontend address configured in `FE_DOMAIN`, log in to the background management interface, and verify that the permission configuration takes effect normally.
- Simulate multi-user concurrent queries, check whether the `DB_MAX_LINK` configuration can support concurrent requests without connection errors.

The values provided are common starting points and should be measured against the reader's own samples.
