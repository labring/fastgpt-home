# Policy and Regulatory Basis Q&A for Investment Project Approval and Post-Evaluation: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from state-owned assets supervision and administration commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data is updated quarterly. Fields include project ID, investment scale, project initiation approval nodes, post-evaluation completion progress, and more. Units include ten thousand yuan, days, and other standard units.

## Constraints imposed on the "tool calling and plugins" workflow
Data sources for this category are scattered, covering multiple system types including state-owned asset supervision, internal enterprise management, and external market systems. Tool calling must adapt to the access logic of multiple data sources. Data is updated quarterly, so cache configurations for tool calling must match this update rhythm to avoid using outdated data. Daily document types vary widely, from planning materials to post-evaluation reports. Tools must support field extraction and querying for different document structures. Some business processes take extended periods. Timeout settings for tool calling must adapt to complex transaction processing requirements. Failure retry and exception alert mechanisms must also be configured to prevent tool call interruptions from impacting project workflows.

## Three common misconfigurations
- Symptom: Local privately deployed models return call failures when invoking MCP services, while the same models function normally online. Cause: The local deployment environment lacks correct internal system access permissions or network policies, preventing retrieval of required policy and project data.
- Symptom: Custom MCP services return timeout errors directly after processing complex transactions for more than 90 seconds. Cause: The FastGPT platform’s default MCP service timeout is 90 seconds, and the timeout configuration has not been adjusted for the complex business scenarios of this category.
- Symptom: Tool call returns missing key clauses in policy basis content. Cause: The configured plugin data source scope does not include a complete policy library or project management system data, leading to incomplete query results.

## How to confirm correct configuration
- A test request containing an investment project initiation policy query is initiated, and the system’s automatic triggering of tool calls for corresponding data sources is confirmed.
- A complex transaction call that exceeds 90 seconds is simulated, and the system’s timeout setting is confirmed to be adjusted to meet business requirements.
- Field values returned by tool calls are cross-checked, and core information such as project ID and initiation approval nodes required for this category is confirmed to be included.
- A temporary network failure is simulated to trigger a tool call failure, and the system’s automatic execution of retries and return of normal results after a successful retry is confirmed.
