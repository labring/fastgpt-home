# Policy and Regulatory Basis Q&A for Investment Project Approval and Post-Evaluation: Citation Sources and Traceability

## What data for this category includes
Data for this category primarily comes from State-owned Assets Supervision and Administration Commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Data update frequency is quarterly. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Fields include project approval numbers, investment amounts, post-evaluation milestones, regulatory compliance requirements, and additional relevant fields. Units include ten thousand yuan, year, project cycle, and other standard units.

## Constraints for Citation Sources and Traceability
Data sources for this category are scattered and tied to state-owned assets supervision compliance requirements. The citation and traceability workflow must strictly match officially released policy texts and project documents, to ensure cited content aligns with state-owned assets supervision regulations. The quarterly update feature requires regular refreshing of policy and project documents in the knowledge base, to avoid relying on expired approval or post-evaluation basis. Documents contain fields such as professional approval numbers and financial data, so the original source of corresponding fields must be accurately located to avoid cross-document citation confusion. Incorrect citations may lead to state-owned asset losses or liability investigation. The traceability workflow must retain complete citation pathways to ensure full traceability.

## Three Common Configuration Errors
-  A POST request returns an empty content field with no clear error message. Cause: Incorrect configuration of the `responseData` parameter return format, or failure to match the snippet length of documents for this category, leading to truncated retrieved content.
-  After configuring an Nginx proxy for knowledge base original document links, the download function fails. Cause: Failure to enable original path return in the `responseData` parameter, causing the proxy rule to fail to link to the correct file storage path.
-  Citation snippets appear garbled, and traceability information is incomplete. Cause: Failure to enable full context return via the `detail` parameter, or inconsistent encoding formats of knowledge base documents, leading to garbled text during snippet concatenation.

## How to Confirm Proper Configuration
-  Submit a test query, check if the returned results include document title, source path, snippet position and other information to confirm the `responseData` configuration is active.
-  Check the length of returned citation snippets, confirm they do not exceed the `quoteMaxToken` setting range, to verify the parameter matches the length characteristics of documents for this category.
-  Manually trigger a knowledge base update task, check if the update log shows the quarterly update task has executed, to confirm the data update rhythm meets requirements.
-  Simulate a compliance verification scenario, verify if the returned results include a complete citation traceability link, to confirm the `detail` parameter is configured correctly.
