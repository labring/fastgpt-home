# Policy and Regulatory Basis Q&A for Investment Project Approval and Post-Evaluation: Document Parsing and Chunking

## What this category of data looks like
This category of data originates from the State-owned Assets Supervision and Administration Commission investment supervision system, enterprise ERP and project management systems, industry market data, audit and financial statements. It is updated quarterly.
Daily processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Some documents are multi-column structured Excel tables, with fields covering project number, investment amount, approval nodes, post-evaluation scores, and other items. There is no unified fixed layout format. Some PDF and Word documents contain nested tables and repeated headers and footers across pages.

## Constraints imposed on document parsing and chunking
Bulk documents updated quarterly require parsing processes to only handle currently uploaded attachments, preventing historical documents from being accidentally loaded.
Multi-column structured Excel and nested tables require parsing modules to accurately identify table row and column structures. These modules must avoid disrupting table logic during automatic chunking, and support custom chunking by row or table cell.
Mixed document format scenarios require parsing configurations to support multiple file types including PDF, Word, and Excel. Configurations must also adapt to header and footer interference across different documents.
The professional nature of project-related fields requires chunking to retain full contextual integrity of policy clauses, approval processes, and post-evaluation data. This avoids semantic breaks caused by cross-paragraph splitting.

## How to configure settings
This configuration guide is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Adapts to the paragraph length of policy clauses and approval processes in investment project documents, avoiding semantic breaks |
| `chunkSplitter` | Paragraph + table row | Compatible with structured data from multi-column Excel and nested tables, meets row-based chunking business requirements, and avoids chaotic automatic segmentation |
| `customPdfParse` | `Enabled` | Most investment project documents include headers, footers, and nested tables. Enabling this setting accurately extracts text and table structures, reducing parsing errors |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 seconds` | Large feasibility study reports and post-evaluation reports have lengthy content. Sufficient parsing time must be reserved to avoid timeout failures |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types to meet differentiated chunking needs for policy text and structured tables |

## Three common misconfigurations
1.  Phenomenon: Multi-column structured Excel documents are chunked chaotically after automatic parsing, failing to meet row-based chunking requirements. Cause: Custom chunking rules are not configured. The default chunking logic does not adapt to table row and column structures, leading to cross-column and cross-row content splitting.
2.  Phenomenon: When uploading new attachments, the system loads previously uploaded documents for parsing at the same time, causing irrelevant project documents to be mixed into the knowledge base. Cause: Filter logic to only process currently uploaded files is not set. The parsing module pulls all historical documents for processing by default.
3.  Phenomenon: Timeout errors occur when parsing large feasibility study reports, and the parsing status shows failure. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient to complete full parsing of long documents.

## How to confirm correct configuration
- Upload a test Excel document containing multi-column project information, review the parsed chunking results, and confirm that content is split by row or table cell.
- Before uploading new attachments, check the parsing module configuration items to confirm that only currently uploaded files are included in the parsing scope, with no historical documents mixed in.
- Upload a lengthy feasibility study report, check the parsing progress, and confirm that no timeout errors are triggered and the parsing completes successfully.
- Upload a single post-investment evaluation report in PDF format, review the parsed text and table structures, and confirm that nested table content is fully retained.

The values provided above are common starting points, and should be evaluated against the user's own samples.
