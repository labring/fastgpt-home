# Investment Project Approval and Post-Evaluation Policy and Regulatory Basis Q&A: Deployment and Upgrade

## What does the data for this category look like?
Core documents for this category include annual investment plans, project proposals, feasibility study reports, due diligence reports, post-investment evaluation reports, and similar materials. Data comes from State-owned Assets Supervision and Administration Commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit reports and financial statements.

Data updates follow a quarterly cycle. Each document includes structured content such as project approval basis, approval procedures, post-evaluation indicators, and original excerpts of corresponding policy documents. Fields adjust dynamically based on document type. No unified fixed unit applies.

## What constraints do these characteristics impose on deployment and upgrade?
The quarterly data update cycle requires a stable cross-system data synchronization channel during deployment. This channel pulls content from data sources including State-owned Assets Supervision and Administration Commission supervision systems and enterprise ERP systems.

Handling multiple document types requires adapting parsing rules for different document structures during deployment. This avoids field parsing deviations.

Data sources involve sensitive systems such as state-owned assets supervision. Deployment must meet intranet isolation or permission control requirements.

Accurate policy Q&A requires updating policy document versions in the knowledge base during upgrade. This prevents outdated content from being retrieved.

FastGPT v4.17.0 deployment tool optimizes intranet adaptation logic. It must still match internal system network policies.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `120–180 concurrent connections` | Supports simultaneous policy Q&A requests from multiple departments, adapts to concurrent access peaks during quarterly data updates |
| `STORAGE_S3_ENDPOINT` | `http://minio.internal:9000` | Stores project documents and original policy documents, adapts to intranet deployment requirements, no need to expose storage services over the public internet |
| `REDIS_URL` | `redis://:custom password@redis.internal:6379/1` | Caches session data and vector retrieval results, speeds up Q&A response times |
| `PG_URL` | `postgresql://fastgpt:custom password@pg.internal:5432/fastgpt` | Stores project metadata and Q&A logs, adapts to quarterly data archiving requirements |
| `ROOT_KEY` | `randomly generated 32-character sequence` | Controls access to the system backend, prevents unauthorized configuration modifications |
| `FE_DOMAIN` | `http://fastgpt.internal` | Adapts to intranet access paths for internal users, no need to configure public domain names |

## Three Common Misconfigurations
- Phenomenon: Plugin calls return an error that the storage service is unreachable, with status code 502. Cause: A public network address is used for `STORAGE_S3_ENDPOINT`. The internal deployment environment cannot access public network storage services.
- Phenomenon: The Q&A system cannot load the latest quarterly updated data. Cause: No scheduled synchronization task is configured, and policy and project documents in the knowledge base are not updated quarterly.
- Phenomenon: Users cannot log into the backend configuration interface normally. Cause: `ROOT_KEY` is configured incorrectly or the default value is not modified, triggering permission verification failure.

## How to Verify Successful Configuration
- Run a database connection test script to verify connectivity for `PG_URL` and `REDIS_URL`, confirm no connection timeout errors.
- Upload a test project proposal document, check if the storage service corresponding to `STORAGE_S3_ENDPOINT` can store and read files normally.
- Use `ROOT_KEY` to access the system backend configuration interface, confirm normal login and parameter modification.
- Submit a test policy-related question, confirm the system returns corresponding document excerpts, verify the knowledge base index is working correctly.

The values provided are common starting points and should be measured against the reader's own samples.
