# Policy and Regulatory Basis Q&A for Tendering and Procurement Compliance Management: Multi-turn Dialogue and Prompt Settings

## What this category of data looks like
This category of data covers daily business documents from state-owned enterprise and public sector procurement centers, tendering offices, business requirement departments, audit and discipline inspection departments, and tendering agencies. Included documents are procurement plans, requirement specifications, tender documents, bid evaluation records, contracts, acceptance documents, supplier complaint materials, and more.
Data sources include enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases. The update frequency is daily.
Core fields include procurement method, budget basis, scoring rules, supplier qualification requirements, and others. There is no unified fixed unit; values are dynamically matched based on the category and implementation requirements of specific procurement projects.

## Constraints on multi-turn dialogue and prompt settings
Daily updated data sources require multi-turn dialogue to pull the latest policies and business documents in real time. This prevents use of expired compliance references.
Mixed types of business documents require prompts to clearly distinguish applicable scenarios for different documents. This avoids confusing the retrieval scope of procurement plans and bid evaluation records.
The lack of unified units for core fields requires dialogue to retain project context for each interaction. This ensures accurate field matching during verification.
Cross-departmental data sources require dialogue to isolate data by project dimension. This prevents interference between compliance references of different procurement projects, while facilitating subsequent audit tracing.
Multi-turn interaction scenarios require complete retention of each round of question and reply content via the `messages` field. This ensures coherent context.

## Configuration setup
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Previous 10 turns of dialogue + 8000–12000 characters | Matches the long text characteristics of tendering and procurement documents, fully retains interactive context for multi-turn compliance verification |
| Single Search Limit | Top 8 results | Covers retrieval needs for multiple types of documents including procurement plans and tender documents, avoids excessive results interfering with judgment |
| Dialogue Timeout | 600 seconds | Adapts to the long interaction duration of multi-turn compliance verification, avoids interrupting the verification process midway |
| Variable Binding | Bind procurement project ID from `variables` | Accurately locates policy documents for the corresponding project, avoids cross-project confusion of compliance references |
| Dialogue History Binding | Bind `chatId` to specific procurement projects | Facilitates subsequent audit tracing of the complete process of each compliance verification |

## Three common misconfigurations
- Symptom: A connection error prompt appears after submitting a question. Cause: Data source access permissions for enterprise procurement platforms or public resource trading platforms are not configured, resulting in failure to pull the corresponding policy documents.
- Symptom: Context is lost after multi-turn dialogue, making it impossible to continue the previous compliance verification process. Cause: `chatId` is not bound by project, and cross-project sharing of dialogue history causes context to be overwritten.
- Symptom: Search results include non-tendering administrative documents, interfering with compliance judgment. Cause: The retrieval data source scope is not limited to tendering and procurement-related business systems, resulting in irrelevant documents being retrieved.

## How to verify correct configuration
- Initiate a query about the policy basis for a specific procurement project. Verify whether the returned results include documents corresponding to the project such as procurement plans and tender documents.
- Initiate two consecutive compliance verification queries. Verify whether the dialogue interface fully retains the interactive context from the first round.
- Check that the data source configuration only includes tendering and procurement-related systems such as enterprise procurement platforms and public resource trading platforms.
- Test binding the procurement project ID from `variables`. Verify whether the returned results only relate to compliance documents for that project.
