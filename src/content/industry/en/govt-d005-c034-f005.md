# Policy and Regulatory Basis Q&A for Student Enrollment and Student Academic Status Management: Tool Calling and Plugins

## What This Category’s Data Includes
This category’s data covers enrollment application forms, student academic status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms.
Data sources include the National Primary and Secondary School Student Academic Status Management System, local enrollment platforms, household registration and property data, and school educational administration systems.
Data updates daily.
Core fields include student identity identifiers, enrollment qualification verification items, student status change approval status, and admission batches.
All information relates solely to student enrollment and academic status transfer.

## Constraints Imposed on Tool Calling and Plugins Workflow
This category’s data sources are scattered and updated daily.
Tool calling must be configured with a scheduled synchronization mechanism to ensure access to the latest versions of policy basis, student status, and enrollment data.
Core documents are structured forms and approval materials.
Tool calling must limit the scope of queried fields to avoid returning irrelevant information.
For household registration and property verification links, external government system interfaces must be called.
Cross-system data format compatibility issues must be addressed.
Errors can lead to student status abnormalities or admission disputes.
Tool calling must add pre-verification logic to avoid invalid or incorrect policy basis calls.

## Three Common Mistakes
- Symptom: No tools run in the tool calling module, and no tool calling records appear in session logs. Cause: No trigger rules matching this category’s keywords are configured, or the trigger condition’s keyword settings are incomplete.
- Symptom: 504 timeout error is returned when calling external household registration verification tools. Cause: Single tool call timeout duration is set too short, and does not align with the actual response duration of government systems.
- Symptom: Tools cannot be called normally after deploying the MCP server service. Cause: Local service port is not opened to the accessible network segment, or the service address is not correctly configured in the platform.

## How to Confirm Configuration Is Complete
- Input a test question containing "transfer application" and check if tool calling triggers in session logs.
- Open the tool calling configuration panel, confirm that `toolChoice` is set to `auto` and the parameter verification mode for `functionCall` is enabled.
- Input a test question containing only "funding policy" and confirm that tool calling does not trigger, to verify the accuracy of the trigger rules.
- Wait 1 data update cycle, query the latest student status change data, and confirm that tool calling can retrieve the day’s updated information.
