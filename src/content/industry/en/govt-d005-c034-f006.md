# Policy and Regulatory Basis Q&A for Enrollment and Student Status Management: Source Citation and Traceability

## What This Category of Data Covers
This category of data covers all process-related materials for enrollment and student status management. Daily documents include enrollment registration forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources include the National Primary and Secondary School Student Status Information Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. The update frequency is daily. Core fields revolve around student identity, enrollment eligibility, and student status, focusing on student status transfer and enrollment eligibility verification. No additional financial-related fields are included.

## Constraints for Source Citation and Traceability
Data sources are scattered and updated daily. This requires the traceability workflow to bind fixed data source identifiers to avoid cross-system data confusion. Daily documents are mostly structured forms and approval files, so policy basis associated with specific fields must be accurately matched, not cited generally. Student status data involves core student rights and interests, so traceability results must clearly correspond to specific document versions and update times to ensure full traceability. Household registration and property data need to connect to local platform interfaces. During traceability, the compliance path of data retrieval must be marked, in line with public service data usage specifications.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Citation Token Count | Set `quoteMaxToken` to 800–1200 tokens | Matches the average length of structured documents in this category, avoids truncating core policy basis |
| Citation Data Return Format | Set `responseData` to Full Source Information | Ensures document name, source system, and update time fields are included, meeting student status data traceability requirements |
| Traceability Detail Display | Set `detail` to Enabled | Shows the corresponding association between policy clauses and student status documents, facilitating enrollment eligibility verification |
| Maximum Number of Citations | Top 3–5 entries | Avoids excessive citations interfering with policy interpretation, meeting the simplicity requirement of public service Q&A |
| Source System Binding | Tag by data source category | Distinguishes between national student status systems, local enrollment platforms, and other data, preventing cross-system confusion |
| Data Timeliness Verification | Only display data updated on the same day | Matches the daily update rhythm of data in this category, ensuring cited content is the latest valid version |

## Three Common Configuration Mistakes
- Configuring `responseData` to simplified mode but still displaying unrelated citation content. The cause is failing to bind the category-specific knowledge base, and non-target data from the general knowledge base is called.
- Unrelated student aid documents appear in mixed search results. The cause is not configuring filtering rules according to the data sources of this category, and failing to exclude non-student status and non-enrollment data sources.
- An error is triggered when applying variables to the knowledge base. The cause is variables not being written in FastGPT standard format, and the knowledge base ID is directly written without using the correct calling syntax.

## How to Confirm Proper Configuration
- Initiate a policy Q&A related to student status changes, check if the returned results include the document name, source system, and update time of the corresponding document.
- Adjust the value of `quoteMaxToken`, verify that the returned citation content fully retains the core content of policy clauses without truncation.
- After enabling the `detail` parameter, confirm that each citation marks the specific associated field corresponding to the question, such as the corresponding clause of the student status change approval form.
- Test the mixed retrieval scenario, confirm that the results only include enrollment and student status documents of this category, with no unrelated content.
