# Policy and Regulatory Basis Q&A for Student Enrollment and Student Status Management: Document Parsing and Chunking

## What this category of data looks like
This category of data mainly comes from the National Primary and Secondary School Student Status Information Management System, local enrollment platforms, household registration and real estate data, and school educational administration systems. The update frequency is daily. Commonly processed documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. These documents have both structured table fields and unstructured policy text. Fields cover student identity information, household registration and real estate verification conditions, student status change approval processes, admission rules, and other content. No additional non-core business statistical data is included.

## What constraints do these characteristics impose on the document parsing and chunking link?
The data characteristics of this category impose clear constraints on document parsing and chunking. Mixed data from multiple sources require distinguishing parsing rules for structured student status tables and unstructured policy text, to avoid misextracting core fields such as identity and real estate information. High-frequency, small-batch documents updated daily require adapting to fast parsing processes to meet real-time policy Q&A needs. Documents contain key content such as student status change approval nodes and admission rules. Chunking must retain contextual associations to avoid losing complete logical information after splitting. Fields in structured tables must be extracted accurately. Otherwise, the accuracy of subsequent qualification verification and policy Q&A will be directly affected.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of enrollment policy documents and student status tables, avoiding loss of policy context or table association information after splitting |
| `customPdfParse` | Enabled | Adapts to PDF documents with form fields such as enrollment application forms and student status change approval forms, to accurately extract structured form content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 seconds | Matches the size of individual enrollment documents added daily, to avoid parsing timeouts for large files |
| `UPLOAD_FILE_MAX_SIZE` | 50–100 MB | Meets the upload requirements for batch documents such as enrollment plans and admission rosters |
| `chunkSplitter` | Split by paragraph + heading | Matches the chapter structure of policy documents and row context of student status tables, ensuring that corresponding approval rules can be associated during Q&A |

## Three common errors
- Phenomenon: A timeout error is returned after calling the custom PDF parsing service, and the interface displays parsing failure. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for processing batch student status table files.
- Phenomenon: Only the first two columns of data are displayed for imported CSV student status tables, and the remaining fields are not extracted. Cause: Corresponding field extraction rules are not configured. The default parsing logic only reads the first two columns of CSV files.
- Phenomenon: Parsed enrollment policy document chunks truncate complete transfer approval process descriptions. Cause: The `chunkSize` setting is too small, splitting complete approval steps into multiple independent chunks and losing contextual associations.

## How to verify proper configuration
- Upload a single complete enrollment policy PDF document, check whether the parsed chunk content retains complete chapter headings and paragraph logic, with no forced truncation.
- Upload a CSV student status table file with multiple fields, confirm that all preset fields are correctly extracted and displayed, with no omissions or only the first two columns displayed.
- Adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter, then upload an admission roster file within the preset `UPLOAD_FILE_MAX_SIZE`, verify that there are no parsing timeout errors.
- Test with `chunkSize` set to 1000 characters, check whether the chunking of transfer application documents does not truncate approval node descriptions, and can fully transmit process logic.

The values provided are common starting points and should be measured against the reader's own samples.
