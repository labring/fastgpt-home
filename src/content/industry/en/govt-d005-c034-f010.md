# Policy and Regulatory Reference Q&A for Student Enrollment and Student Record Management: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Business data for this category covers daily operational documents from education bureau basic education departments, school academic affairs offices, enrollment examination institutions, and street community collaborative windows. Included documents are enrollment application forms, student record information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources include the national primary and secondary school student record information management system, local enrollment platforms, household registration and property data, and school academic affairs systems. Updates occur daily. Data fields focus on student identity, enrollment eligibility, and student record transfers. Core associated identifiers include household registration numbers, property certificate numbers, and student record numbers. No additional financial-related fields are included.

## Constraints on Knowledge Base Retrieval and Recall
Daily updated data sources require the retrieval and recall process to support incremental synchronization configuration. This prevents full reindexing that uses excessive system resources. Multi-source heterogeneous data includes structured student record numbers, semi-structured application forms, and unstructured policy texts. This means retrieval modes must adapt to hybrid retrieval scenarios, covering needs for all document types. Field requirements focused on student identity and enrollment eligibility mean retrieval results must strictly match core associated identifiers. This stops irrelevant data from interfering with query results. Errors directly impact students’ enrollment rights and interests. This requires strict control of recall result accuracy, to prevent incorrect matches related to duplicate student records or admission disputes.

## How to Configure Settings

| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Meets precise retrieval needs for student record and enrollment-related content, and avoids recalling irrelevant documents with low matching scores |
| `limit` | Top 8–12 results | Controls the number of single-recall results, balances context length and information completeness, and aligns with the information density requirements of enrollment policy Q&A |
| `searchMode` | hybrid | Adapts to hybrid retrieval scenarios for structured student record data and unstructured policy texts, covering retrieval needs for multi-source data |
| `usingReRank` | Enabled | Re-ranks recall results, raises the display priority of high-matching documents, and reduces manual filtering costs |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands relevant policy keywords based on user questions, covering implicit expressions that users may omit. For example, "kindergarten to primary school transition" corresponds to "compulsory education enrollment policy" |
| `collectionIds` | Bind corresponding student enrollment and record management knowledge base collections | Limits the retrieval scope, avoids interference from cross-category data, and ensures recall results only come from business documents of this category |

## Three Common Configuration Errors
- No index entries appear after uploading the knowledge base. Cause: Incremental synchronization trigger rules are not configured correctly, or index updates are not triggered after data sources are updated, resulting in documents not being included in the retrieval scope.
- Retrieval results include document chunks that exceed the preset reference limit. Cause: Chunk length verification configuration is not enabled, or the reference limit setting does not match the knowledge base chunk length, resulting in long document chunks being recalled directly.
- A "Cannot convert undefined or null to object" error occurs during workflow runtime. Cause: The target knowledge base collection is not correctly bound in the retrieval configuration, or the collection ID parameter is empty, causing the system to fail to obtain the retrieval data source.

## How to Verify Successful Configuration
- Upload a single test document, wait for indexing to complete, then run a targeted retrieval. Confirm that the test document is recalled normally.
- Adjust the `similarity` parameter range, compare the number of retrieval results across different thresholds, and confirm that matching accuracy meets business requirements.
- Trigger an incremental data source synchronization, check indexing logs for update records of the corresponding document, and confirm that the daily update configuration is active.
- Enter a query term containing a student record number, confirm that retrieval results only include documents related to that student record number, and verify the effectiveness of the collection binding configuration.
