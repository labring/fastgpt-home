# Policy and Regulatory Basis Q&A for Pollution Discharge Permit Management: Tool Calling and Plugins

## What the data for this category looks like
This category of data covers all documents related to the post-issuance management process of pollution discharge units, including pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications and permit copies. Data sources include the National Pollution Discharge Permit Management Information Platform, enterprise environmental protection ledgers, online monitoring systems and environmental statistics systems, with updates made quarterly. Data fields include limits corresponding to industry technical specifications, discharge port parameters, self-monitoring results, content filled in implementation reports, etc., involving standard measured values of emission concentration and discharge amount, as well as timestamp information from ledger records.

## What constraints these characteristics impose on the "tool calling and plugins" link
This category of data is updated quarterly, so tool calling must adapt to the synchronization verification logic for batch quarterly data to avoid calling expired or not yet updated information. Multiple document types have significant structural differences, so differentiated plugin trigger rules need to be configured for different document types such as pollution discharge permit copies and implementation reports. Data sources are scattered, so plugins must be used to connect multiple external systems such as the National Pollution Discharge Permit Management Information Platform and online monitoring systems to pull raw data. Fields involve environmental protection professional metering, so corresponding unit conversion logic must be matched during tool calling to ensure measurement accuracy of Q&A content. The rigor of post-issuance supervision requires that tool calling results be linked to raw data traceability to ensure the compliance of Q&A basis.

## How to Set Configurations

*Note: The configurations on this page are based on FastGPT v4.17.0.*

## Three Common Misconfigurations
- Phenomenon: Non-expected tool types are returned when calling `toolChoice`, or no tool is called. Cause: Corresponding `toolChoice` trigger rules are not configured for the policy document types of pollution discharge permit management, causing the model to fail to match the correct calling logic.
- Phenomenon: Empty results or status code 400 are returned when calling the API after publishing the application. Cause: Plugin parameters for external system connection are not correctly configured, and authorization and connection for data sources such as the National Pollution Discharge Permit Management Information Platform are not completed.
- Phenomenon: The policy data interface cannot be called normally after importing the HTTP plugin. Cause: Correct interface address and request header are not filled in the plugin configuration, and the authentication requirements of the pollution discharge permit data interface are not adapted.

## How to Confirm the Configuration is Complete
- Manually trigger Q&A targeting pollution discharge permit copies, check if the returned results are linked to the policy basis of the corresponding document.
- Call the API with a question related to implementation reports, check if the returned results include matching fields and data sources.
- View plugin operation logs to confirm that external system data pull requests have been successfully sent and returned valid content.
- Adjust the `toolChoice` configuration to manual mode, verify if the model can correctly prompt to select the corresponding policy calling tool.
