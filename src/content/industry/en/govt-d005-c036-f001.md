# Policy and Regulatory Basis Q&A for Government Service Item Catalog and Service Guide Maintenance: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
The core data of this category includes basic government service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, and more. Data sources are the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases, with updates typically occurring monthly. Each document includes standardized fields such as item code, item name, implementing entity, acceptance conditions, application materials, and processing procedures. No custom units are used, and some fields must strictly match the standardized expressions from the superior catalog.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
The standardized field requirements for this category of data mean that interface input parameters must match standardized field names to avoid field incompatibility issues. The monthly update rhythm requires interfaces to support incremental synchronization mode to reduce resource usage from full data pulls. Each individual document has long content and many fields, so a reasonable upper limit must be set for the amount of data returned in a single interface call to prevent request timeouts. Data must strictly match superior catalog specifications, so interfaces must include verification mechanisms to ensure incoming item information meets superior requirements.

## Three Common Misconfigurations
- Scenario: Policy basis Q&A results can be obtained normally in the FastGPT debug page, but no matching knowledge base results appear when calling the same query via the HTTP interface. Cause: The interface does not carry the retrieval parameters for the corresponding government service item, or is not bound to the dedicated government service item catalog knowledge base.
- Scenario: Service guide fields returned by the HTTP interface are missing or non-compliant. Cause: The correct `variables` parameter binding for the superior catalog's field mapping rules is not configured, leading to incorrect data matching.
- Scenario: Timeout errors occur during HTTP interface calls. Cause: The amount of government document data returned in a single request is too large, and no reasonable single return upper limit is set.

## How to Confirm Configuration Is Correct
- Call the HTTP interface, check if the returned `responseData` field includes the core fields of government service items, confirm that the fields match standardized requirements.
- Compare the return results of the debug page and the HTTP interface, ensure that the matching results for the same query are consistent, confirm that parameter transmission and configuration take effect.
- Simulate a monthly incremental update request, check if the interface can correctly pull newly added or modified government service item data, confirm that the update logic works properly.
- Call the interface with an incorrect `Authorization` parameter, confirm that the interface returns an unauthorized error, confirm that the security verification configuration takes effect.
