# Policy and Regulatory Basis Q&A for Government Service Item Catalog and Service Guide Maintenance: Multi-turn Dialogue and Prompt Engineering

## What This Category's Data Looks Like
The core data of this category includes basic government service item catalogs, implementation lists, service guides, standard material catalogs, and flowcharts. Data is primarily sourced from the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases, with a monthly update frequency.
Documents primarily use structured fields, including fixed fields such as item name, acceptance conditions, and application material list. Some local jurisdictions add local characteristic service rules. Data must remain consistent with higher-level catalogs to avoid caliber deviations.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Decentralized data sources and the requirement to maintain hierarchical consistency mean multi-turn dialogue must track the unique identifier of the currently maintained item. This avoids caliber deviations caused by cross-version references.
The monthly update frequency requires the dialogue system to quickly load the latest version of the item database data, and avoid reliance on outdated caches.
A large number of structured fields must be strictly matched. Prompt engineering must clearly limit calls to only the policy basis of the corresponding fields, and must not generate unincluded rules.
Multi-turn dialogue must retain the item ID currently being maintained by the user. This ensures the context is associated with the policy basis of the same item, and avoids confusion between different entries.

## Three Common Configuration Errors
- Forced citation prompt displayed at the end of responses, cannot be hidden directly. Phenomenon: A fixed citation annotation appears at the end of responses after triggering Q&A, and cannot be canceled via interface operations. Cause: The global citation display switch is not turned off, or a custom hiding rule for government document scenarios is not configured.
- Dialogue returns "No permission to operate this conversation record" error. Phenomenon: A red permission error pop-up appears when opening a specified session, making continued dialogue impossible. Cause: The government item bound to `chatId` is not within the current user's permission range, or the `messages` context was not refreshed after session timeout.
- Clicking the quick reply button does not directly send the preset question. Phenomenon: After clicking the preset "Compare Higher-level Catalog" button, only the instruction is filled into the input box, and manual clicking send is required to submit. Cause: The automatic send configuration for quick replies is not enabled, or the `messages` parameter is not correctly bound to pass the preset instruction.

## How to Verify Proper Configuration
- Initiate a multi-turn dialogue for a single government service item, check if `chatId` updates automatically when switching items, to ensure correct context association.
- After triggering Q&A, check the citation display status at the end of the response, to confirm it matches the preset enable or hide configuration.
- Click the preset quick reply button, check if the preset instruction is sent automatically without manual confirmation to submit.
- Call the dialogue API for testing, check if the `variables` parameter can be correctly passed to load policy data for the specified cycle.

The values listed above are common starting points, and should be evaluated against the user's own samples.
