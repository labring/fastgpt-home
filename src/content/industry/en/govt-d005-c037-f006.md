# Policy and Regulatory Basis Q&A for Government Information Disclosure Upon Application: Citation Sources and Traceability

## What the data for this category looks like
The main data for this category comes from daily business documents of government offices, government information disclosure offices and other relevant units, including government information disclosure application forms, supplementary notification letters, reply letters and similar materials. Data sources cover government information disclosure platforms, official archive systems, document management systems, departmental business ledgers and normative documents such as the Regulations on Government Information Disclosure. The update frequency is irregular. Each individual document contains fixed fields including applicant information, application matters, reply basis, relief pathways and other standard content. Each business document only targets a specific individual applicant’s case, with no generalized public content.

## Constraints imposed by these characteristics on the "citation sources and traceability" link
Since data sources are scattered across multiple different business systems, the traceability link must implement cross-system data source binding to ensure cited content corresponds one-to-one with actual stored documents. The irregular data update feature requires the traceability system to support incremental synchronization, avoiding use of expired regulatory basis. The strong binding attribute between business documents and regulatory basis requires that recalled cited content must accurately match the specific clauses corresponding to the application matters, rather than broadly citing general norms. At the same time, the rigor required for government replies means traceability results must be directly linked to the original document’s metadata, with no citation markers generated without basis.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapt to the common length of regulatory basis documents, ensuring complete citation of core clause content |
| Max context recall count | Top 5 entries | Regulatory basis for application-based disclosure mostly consists of 1 to 3 items; excessive recall will introduce irrelevant content that disrupts reply quality |
| `detail` | Enabled | Used to return complete metadata of citation sources, including document storage location, release time and other relevant information |
| `responseData` | Return only citation content and traceability links | Avoid outputting redundant information, meeting the rigor requirements of government replies |
| Incremental sync trigger frequency | Triggered daily | Matches the irregular data update feature, ensuring the data sources used for retrieval are always the latest version |

## Three Common Misconfigurations
- Phenomenon: Citation markers unlinked to actual documents appear in output content, such as "[1]" with no corresponding source link or metadata. Cause: Cross-system data source binding logic is not configured, so citation markers are only generated via generative output, without mandatory association with retrieved valid data sources.
- Phenomenon: The large language model generates forged citation IDs that do not point to actual stored regulatory documents or business documents. Cause: Traceability verification mechanism is not enabled, allowing generative content to independently generate citation markers separate from retrieved data sources.
- Phenomenon: The release time of citation sources does not match the actual document. Cause: Incremental sync configuration is not enabled, so cached expired data source copies are used, and latest regulatory basis is not updated in a timely manner.

## How to Confirm Configuration Is Successful
- Upload one government information disclosure reply letter template as test input, retrieve relevant regulatory basis, and check whether the output content includes traceable source metadata.
- Check the FastGPT v4.17.0 system logs to confirm that each retrieval request returns a matching data source ID, with no null values or forged citation markers.
- Adjust the value range of the `quoteMaxToken` parameter, verify whether the length of the output citation content changes with the parameter, and confirm that the configuration takes effect.
- Temporarily disable the incremental sync configuration, wait for a period of time before retrieving again, check whether the output regulatory basis is still the old version, and verify that the synchronization logic operates correctly.
