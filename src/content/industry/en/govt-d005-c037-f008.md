# Policy and Regulatory Basis Q&A for Government Information Application Disclosure: Document Parsing and Chunking

## What the data for this category looks like
Data for this category comes from government information disclosure platforms, agency archive systems, document management systems, and departmental business ledgers, with irregular update frequencies. Daily processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, response letters, service receipt forms, and administrative reconsideration response materials. Most documents follow standardized official document formats, with fixed fields such as applicant information, application matters, response basis, and relief channels. Some materials include complex tables or scanned documents.

## What constraints do these characteristics impose on the document parsing and chunking link
The mixed document characteristics of standardized official documents, complex tables, and scanned documents in this category require the document parsing link to support both text extraction and structured recognition. Dispersed data sources with irregular updates require the parsing process to have stable batch processing capabilities. The document structure combining fixed fields and case-specific content requires that context associations be retained during chunking, to avoid breaking the logical connection between application matters and response basis. Additionally, errors in the parsing link may lead to delayed responses or administrative reconsideration corrections, so a clear failure feedback and retry mechanism is required.

## How to set the configuration
This configuration is based on FastGPT v4.17.0, and is formulated for the document characteristics of this category:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category's documents include fixed fields and case-specific content. This range balances context integrity and retrieval accuracy |
| `customPdfParse` | Enable pdf-marker parsing mode | Documents mixing standardized official documents and complex tables require retention of structured information, to avoid loss of table content via conventional parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Large scanned documents or multi-page administrative reconsideration response materials require sufficient time for parsing, to avoid timeout interruptions |
| `chunkSplitter` | Chunk by paragraph + title | Documents contain clear response basis and application matter paragraphs. Chunking by title preserves logical connections |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Meets upload requirements for large documents such as multi-page administrative reconsideration response materials |

## Three common misconfigurations
- Phenomenon: After uploading a standardized PDF document, no parsed text fragments are generated in the knowledge base, or the Doc2x tool returns a file read error. Cause: The `customPdfParse` configuration is not enabled. Conventional PDF parsing cannot extract response basis content from complex tables or scanned documents.
- Phenomenon: The parsing process fails to complete within the set time, returning a timeout error. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is too low, and does not adapt to the parsing duration of large multi-page administrative reconsideration response materials.
- Phenomenon: Chunked text fragments break the connection between application matters and response basis. Cause: The `chunkSplitter` configuration is set to chunk by fixed character count, and does not retain logical context by title or paragraph.

## How to confirm the configuration is correct
- Upload a PDF of a government information disclosure response document that includes complex tables, and check whether the parsed result retains the complete content and original format of the table.
- View the parsing log to confirm that no timeout errors occur, and that the configured value of `PARSE_FILE_TIMEOUT_SECONDS` matches the current parsing duration.
- Randomly select a chunked text fragment, and verify that it contains a complete application matter or response basis fragment with no broken connections.
- Test uploading a document of the maximum allowed size, and confirm that the `UPLOAD_FILE_MAX_SIZE` configuration permits upload and completion of parsing.

The values provided are common starting points and should be measured against the user's own samples.
