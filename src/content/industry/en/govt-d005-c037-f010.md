# Policy and Regulatory Basis Q&A for Government Information Application Disclosure: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category primarily comes from government information disclosure platforms, official archive systems, document management systems, departmental business ledgers, and official documents including the Government Information Disclosure Regulations. Documents handled daily include government information disclosure application forms, correction notice letters, third-party opinion solicitation letters, reply documents, service receipts, and administrative reconsideration response materials. Data updates have no fixed cycle, changing alongside business processing and regulatory revisions. Most documents are structured forms and standard official papers, with fixed fields including applicant information, application items, reply content, and relief channels.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Decentralized data sources and diverse formats require retrieval to adapt to both structured forms and unstructured official documents, avoiding single chunking rules that lead to loss of key information. Irregular updates require recall logic to support incremental synchronization without full index reconstruction, reducing operation and maintenance costs. Fixed fields and standard documents mean priority should be given to matching core fields such as application items and reply basis, avoiding irrelevant content interfering with retrieval results. Additionally, business processing has time requirements, so retrieval response must be controlled within a reasonable range to avoid affecting reply processes and compliance.

Configuration settings are based on FastGPT v4.17.0.

| `similarity` | 0.72–0.80 | Matches semantic matching accuracy for standard official documents and forms, filtering low-relevance non-business documents |
| `limit` | Top 8 entries | Covers multiple basis documents that may be involved in a single application, while controlling total context length |
| `searchMode` | Semantic retrieval | Adapts to unstructured regulatory provisions and structured form content, improving cross-type matching effectiveness |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, prioritizing matching between application items and disclosure basis relevance |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically generates extended query terms based on application items, covering synonyms and government disclosure-related expressions |
| `collectionIds` | Bind the dedicated collection ID for this category | Restrict retrieval scope to only business data related to government information application disclosure, avoiding mixing with other datasets |

## Three Common Misconfigurations
- Symptom: The `pushData` API returns a failure when uploading data in batches, with a 400 status code. Cause: The number of entries uploaded in a single batch exceeds 200 groups, and submissions were not split into batches as required.
- Symptom: Retrieval results include non-government disclosure-related documents, leading to reduced matching accuracy. Cause: The `collectionIds` configuration to restrict retrieval scope was not set, and the knowledge base collection of another category was bound.
- Symptom: Enabling the web search tool returns empty results. Cause: Search rules were not adjusted for government affairs scenarios, or no internally accessible retrieval source was configured, causing external search to fail to obtain valid government affairs content.

## How to Confirm Proper Configuration
- Upload a single government information disclosure reply document and corresponding regulatory provisions, perform retrieval and check whether the target document is included in the returned results.
- Use the `pushData` API to submit data in batches with no more than 200 groups, confirm that the interface returns a successful status.
- View the configuration parameters of the knowledge base collection, confirm that `collectionIds` only binds the dedicated dataset for this category.
- Enable debug mode, view the number of recalled entries and reranking results during the retrieval process, confirm they match the preset configuration parameters.

The values provided are common starting points and should be measured against the reader's own samples.
