# Policy and Regulatory Basis Q&A for Government Procurement Projects: Tool Calling and Plugins

## What This Category of Data Looks Like
Data sources for this category include China Government Procurement Network, local government procurement websites, the fiscal integration system, procurer budget systems, and supplier credit records. Updates occur daily.
Daily processed documents cover procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning announcement notices, procurement contracts, and responses to procurement inquiries.
Document structures include procurement project details, policy basis associated fields, and regulatory requirement identifiers. The data includes business information from multiple parties: procurers, financial regulatory departments, procurement agencies, and bid review experts.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Workflow
Daily updated data sources require tool calling to use a scheduled synchronization mechanism. This ensures Q&A data matches officially published content.
Multiple types of business documents require plugins to support multi-format parsing, including PDF bidding documents and bid evaluation reports.
Multiple data source integration needs require plugin configurations to distinguish authentication methods and interface specifications for different systems.
Government procurement business has strict regulatory requirements. Tool calling results must be traceable back to original documents. A persistent storage plugin must be configured to save parsed business data.
Differences in fields across different documents require `toolChoice` to adapt to calling logic for different types of policy basis.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto | Adapts to Q&A scenarios for multiple types of policy documents in government procurement, automatically matching corresponding calling logic |
| `functionCall` | Enabled | Used to call external plugins to pull the latest government procurement data, ensuring real-time Q&A content |
| Scheduled Sync Cycle | Daily 00:00 | Matches the daily update frequency of data sources, ensuring Q&A data is always the latest version |
| Document Storage Plugin | MinIO | Saves parsed procurement documents and intermediate results, meeting persistent storage requirements for daily updated data |
| Document Storage Capacity | 1000–2000 MB | Covers storage needs for all procurement project documents |
| Number of Results Returned Per Request | Top 10 | Controls the number of policy basis items returned in Q&A, avoiding information overload |
| PDF Enhanced Parsing | Enabled | Adapts to parsing requirements for PDF format documents such as bidding documents and bid evaluation reports |

## Three Common Misconfigurations
- Issue: PDF enhanced parsing is enabled but still fails to parse government procurement bidding document PDFs. Cause: The PDF enhanced parsing switch was not enabled in plugin configurations, or the uploaded PDF file format does not meet standards.
- Issue: An internal server error appears when installing the database connection plugin. Cause: The database authentication key for the fiscal integration system was not configured correctly, or the plugin version is incompatible with FastGPT v4.17.0.
- Issue: An empty dataId is returned when calling the API to obtain policy basis. Cause: The unique identifier field of the government procurement project was not correctly associated, making it impossible to match business records from the corresponding data source.

## How to Verify Successful Configuration
- Manually trigger a scheduled synchronization task, then check if parsed copies of corresponding government procurement documents are generated in the MinIO storage bucket.
- Call the API to initiate a policy Q&A request, then verify that the returned results include policy basis content for the corresponding procurement project.
- View the plugin management page, then confirm that configuration items such as multi-data source connections and PDF enhanced parsing are in an enabled state.
- Simulate a database connection request, then check if procurement plan data can be successfully pulled from the fiscal integration system.
