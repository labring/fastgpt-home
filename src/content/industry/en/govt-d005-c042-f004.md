# Policy and Regulatory Basis Q&A for Legal Compliance and Major Risk Management: Workflow Orchestration

## What data this category uses
The core data for this category comes from enterprise contract management systems, compliance risk databases, law and regulation libraries, case management systems, and reporting platforms. Daily processed documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation results. Data is updated monthly. Most documents contain fields such as compliance clauses, review opinions, and handling results. There is no unified fixed unit, and field formats must be adapted based on document type.

## What constraints these characteristics impose on workflow orchestration
Multi-data source access requires the workflow to bind multiple data source variables, ensuring the Q&A can call all full compliance-related data. The monthly update frequency requires the workflow configuration sync cycle to match the data update rhythm, avoiding expired content use. The variety of document types requires chunking rules to adapt to different lengths of content such as review opinions and review forms. Severe error consequences require the workflow to be configured with a reference verification link, ensuring returned content meets compliance requirements.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind three data sources: compliance risk database, contract management system, and law and regulation library | Matches the multi-data source business data characteristics of this category |
| `nodeId` | Correspond to the root node ID of the compliance Q&A workflow | Ensures correct binding of the appropriate node for workflow debugging and triggering |
| Single recall limit | Top 5 entries | Avoids excessive irrelevant content interfering with large model judgment, aligns with the accuracy requirements of compliance Q&A |
| Context length limit | 8000–12000 token | Adapts to the average length of compliance documents, ensuring complete calling of relevant compliance basis |
| Reference verification trigger | Set based on actual testing | Matches the business characteristic of severe error consequences for this category, ensuring effective verification logic |
| Failure retry count | 2 times | Addresses temporary exceptions that may occur during multi-data source calls, avoiding direct workflow interruption |

## Three common misconfigurations
- Unable to stop the current node during workflow debugging, with the interface showing the debugging status running continuously: The cause is that the `nodeId` parameter is not configured correctly, and the unique identifier of the corresponding workflow node is not bound, leading to the inability to accurately terminate the debugging process.
- The variable selection dropdown menu only allows selecting a single variable, and cannot reference multi-data source content: The cause is that the `variables` configuration does not include multi-data source binding items, and only a single data source variable is bound.
- The large model returned answer does not mark reference sources, or the referenced content does not match the question: The cause is that the reference verification trigger rule is not configured, and the large model generated content is not matched and verified against compliance documents in the knowledge base.

## How to confirm the configuration is complete
- Check if the `variables` configuration binds the three specified data sources: compliance risk database, contract management system, and law and regulation library.
- Trigger a workflow test to confirm that the variable selection dropdown menu can select multiple bound data source variables.
- Submit a test compliance review request to verify that the large model returns a reference verification result and marks the knowledge base source.
- Enter the workflow debugging mode, attempt to stop the current node, and confirm that the debugging status can be terminated normally.
