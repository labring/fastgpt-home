# Policy and Regulatory Basis Q&A for Legal Compliance and Major Risk Management: Source Citation and Traceability

## What the data for this category looks like
This category's data comes from enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms. Daily generated documents include compliance risk lists, contract legal review opinions, legal opinions on major matters, compliance review forms, and violation report investigation results. Data is updated monthly. Each individual data entry includes fields such as file name, generation time, review entity, core compliance clauses, and violation situation description. Some structured data is attached with a unique identifier, while unstructured documents only retain file paths and generation records.

## What constraints these characteristics impose on the "source citation and traceability" link
Data sources are scattered across multiple internal systems. Citation traceability must link to the original data identifiers of each system to avoid matching deviations during cross-system citation. The monthly update frequency requires regular synchronization of incremental compliance data to ensure cited policies and regulations remain effective. Document formats are inconsistent, and identification methods differ between structured and unstructured data, increasing the complexity of chunking and traceability. Since errors may lead to major legal risks, the traceability link must ensure every citation can be traced back to the original data source, and key source information cannot be omitted.

## How to set the configuration
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Compliance documents for this category are mostly long texts, requiring sufficient citation context to accurately restore the original text of policy clauses |
| `responseData` | `Return all matched original data fields` | Full access to traceability-required information such as file name, generation time, and review entity is necessary |
| `detail` | `Enable detailed traceability mode` | Compliance scenarios require clear original generation records and source systems for each cited content |
| Maximum number of citations | Top 5 entries | Compliance citations must focus on core basis; excessive citations will interfere with Q&A accuracy |
| Original data binding | Bind unique file ID based on matched content | Data for this category comes from multiple internal systems, requiring precise traceability back to the original data source via ID |

## Three common misconfigurations
- Phenomenon: When configuring `responseData`, the field to return the original ID is not checked, and the `{{id}}` field in citation content is empty. Cause: All original data fields are not correctly configured for return, making it impossible to extract the unique identifier of matched content.
- Phenomenon: After enabling `detail` mode, traceability information in Q&A results is too long and exceeds the display range. Cause: The value of `quoteMaxToken` is not restricted, causing citation context to occupy excessive output space.
- Phenomenon: After setting variable references for the large model, the temperature setting button disappears and cannot be adjusted. Cause: Conversation configuration is mistakenly changed to variable reference mode, hiding the standard parameter setting entry.

## How to confirm the configuration is complete
- Initiate a test Q&A related to policy basis, and check whether returned results include the file name and unique identifier of the matched file.
- View the configuration panel, and confirm that the value of `quoteMaxToken` falls within the preset range.
- Test multi-round Q&A scenarios, and confirm that traceability information for cited content does not appear duplicated or misaligned.
- Check system logs, and confirm that each citation can be linked to the corresponding original data source.
