# Special Equipment Safety Supervision Policy and Regulatory Basis Q&A: HTTP Interfaces and External Systems

Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
This category of data covers documents including special equipment use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Data sources include the special equipment safety supervision system, inspection and testing institution system, user unit account books, and operator certificate database. The data update frequency is once per month. Core fields include unique device identifier, inspection expiration date, operator qualification number, hidden danger rectification closed-loop status, and others. Some fields need to match the internal coding rules of the supervision system, and there are no unified fixed formats for unit fields.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
Multi-source heterogeneous data sources require interfaces to adapt to authentication rules and data formats of different systems to avoid format incompatibility issues. The monthly update frequency reduces the need for high-frequency pulling, allowing relaxation of request timeout and retry configuration thresholds. The regulatory attributes of core fields require that data returned by interfaces must accurately match the retrieval needs of policy Q&A, and no redundant or irrelevant content can be returned. The full-life-cycle supervision logic of equipment requires interfaces to support cross-system data associated queries, realizing linked verification of registration, inspection, maintenance and other links.

## How to set configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer Token format, carry the exclusive key assigned by the supervision system | Interfaces of special equipment supervision systems generally use this authentication method to ensure data security |
| `variables` | Pass in the unique device number, inspection cycle start node | The core retrieval conditions for business Q&A are device identifiers and time nodes |
| `responseData` | Extract device status, rectification progress, qualification expiration date fields | Policy Q&A needs to return structured results that accurately match regulatory requirements |
| Request timeout period | 600 seconds | The data update frequency is monthly, short-cycle response is not required, avoiding invalid timeouts triggered by network fluctuations |
| Request retry count | 3 times | Balance network stability and interface call costs |
| Cross-domain access permission | Add domain name whitelists for supervision systems and user unit systems | Prevent cross-domain requests from being blocked by browsers |

## Three common mistakes
- A `getaddrinfo ENOTFOUND` error is returned when calling an external interface. The cause is that the configured target system address has no valid domain name or has not been added to the local DNS resolution list.
- The file relative path obtained via FastGPT carries a token, and direct submission for Flask processing fails. The cause is that the token parameter in the path was not removed, causing the target service to fail to recognize the valid file address.
- No response is received when passing an external image URL to the conversation interface. The cause is that the image storage address accessible within the FastGPT platform was not used, or the permission whitelist for image access was not configured.

## How to confirm the configuration is correct
- Send a test request to the configured external interface, check if the `Authorization` header is correctly carried, and confirm the returned status code is 200.
- Pass a preset special equipment device number, check if core fields such as matching inspection cycle and operator qualification are returned in `responseData`.
- Upload a test file to FastGPT, remove the token parameter from the extracted relative path, submit it to the external service, and confirm that file processing proceeds normally.
- Simulate a network interruption scenario, check if the interface triggers the retry mechanism, and confirm no data loss or duplicate submission occurs.
