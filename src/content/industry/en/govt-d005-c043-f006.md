# Policy and Regulatory Basis Q&A for Special Equipment Safety Supervision: Citation Sources and Traceability

## What this category of data looks like
This category of data includes documents such as special equipment use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Data is sourced from special equipment safety supervision systems, inspection and testing institution business systems, user equipment ledgers, and operator certificate databases. Data updates occur once per month. Each single data entry includes structured fields such as the device unique ID, inspection cycle node, maintenance unit qualification number, and operator certification number. Some documents are in the format of scanned documents with official signatures.

## What constraints do these characteristics impose on the "citation sources and traceability" link
The monthly update rhythm of this category of data requires knowledge base synchronization tasks to match the monthly report cycle of supervision business. This prevents expired data from being recalled. The mixed document structure of structured fields and scanned documents requires the traceability link to support both structured metadata matching and unstructured document text traceability. The strong correlation between core fields such as device unique ID and inspection cycle requires citation traceability to be bound to the full lifecycle data of a specific device, rather than generalized matching. The seriousness of documents such as hidden danger rectification notices and accident reports requires traceability results to clearly point to the entry time and storage path of the original system.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Matches the average text length of a single core document for this category, such as a periodic inspection report, to ensure complete citation of key supervision content |
| `responseData` | Includes original document ID, entry time | Meets compliance requirements for clearly identifying data sources and update times for traceability in supervision scenarios |
| `detail` | Enabled | Supports returning original text fragments of unstructured documents and structured metadata, adapting to traceability for mixed-format data |
| Single Recall Limit | Top 6 entries | Matches the total volume of single-category documents updated each month, avoiding excessive irrelevant recall that interferes with supervision-related responses |
| Knowledge Base Sync Cycle | Once per month | Matches the official update frequency of this category of data, ensuring the timeliness of recalled data |

Note: These configurations are based on FastGPT v4.17.0.

## Three Common Misconfigurations
- Phenomenon: The response does not include compliant body content from the local knowledge base, and only displays metadata for the first correct knowledge base entry. Cause: The `detail` configuration is not enabled. The system only returns basic document information without extracting text fragments.
- Phenomenon: The knowledge base synchronization task fails, and the system prompts a synchronization timeout. Cause: A synchronization cycle matching the monthly update rhythm is not set. The single synchronization data volume exceeds the system processing limit.
- Phenomenon: The traceability result is not associated with the device unique ID, and cannot be bound to a specific supervision object. Cause: The `responseData` configuration for returning structured metadata fields is not set. This prevents association with core supervision identifiers.

## How to Confirm Proper Configuration
- Initiate a query containing a specific special equipment ID, and verify that the response includes relevant content such as the inspection cycle and maintenance records of the corresponding device.
- View the traceability module of the response, and confirm that the ID and entry time of the original document are displayed.
- Trigger a knowledge base synchronization task, and check that the synchronization completes within the measured duration.
- Test a query for a scanned hidden danger rectification notice, and confirm that the original text fragment and structured metadata are returned.
