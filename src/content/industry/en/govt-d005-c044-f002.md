# Policy and Regulatory Basis Q&A for Environmental Law Enforcement and Monitoring Supervision: Vector Models and Indexes

## What the data for this category looks like
Documents covered in this category include on-site inspection records, sampling records, monitoring reports, order for correction decisions, administrative penalty decisions, and more. Data sources include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Each document includes structured fields such as law enforcement subject, law enforcement time, monitoring point, test value, document number, and more. The update frequency is daily synchronization of law enforcement documents and online monitoring data generated on the same day. Data types cover two categories: text records and structured test values.

## What constraints these characteristics impose on the vector models and indexes link
Data sources cover multiple channels including online monitoring, law enforcement systems, third-party reports, and include both text records and structured test values. This requires vector models to support vectorization of mixed fields, to avoid losing key test information. The high-frequency daily update feature requires the index link to support incremental synchronization, to avoid performance loss from full indexing. Document lengths vary significantly, so flexible chunking rules must be configured to retain the integrity of law enforcement logic. The rigor of law enforcement basis requires retrieval results to accurately match policy clauses, which imposes high constraints on vector recall accuracy.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the average content length of on-site inspection records and monitoring reports, avoids splitting law enforcement logic in a single chunk |
| Overlap Length | 100–150 characters | Retains associated information between adjacent law enforcement documents, avoids key law enforcement basis being truncated by chunking |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Balances recall accuracy and recall volume for law enforcement basis, meets the rigor requirements of policy basis Q&A |
| Single Search Limit | Top 10 results | Aligns with the information carrying capacity of a single law enforcement personnel search, avoids excessive redundant data interfering with judgment |
| `defaultToken` | 8192 | Adapts to the context splicing needs of multiple law enforcement documents, supports long text processing for policy basis Q&A |
| `maxToken` | 16384 | Reserves sufficient model input space to handle complex queries containing multiple monitoring reports |

## Three common mistakes
- Symptom: The indexing process continues to time out, and background logs show full scanning of all historical law enforcement data. Cause: Incremental indexing mode is not enabled, and each synchronization repeatedly processes historical documents that have already been indexed.
- Symptom: A large number of non-policy basis monitoring data is mixed in retrieval results, and it is impossible to accurately match regulatory clauses. Cause: No vector model configuration is set for the structured fields of law enforcement documents, and a general text model is used, which ignores key features of test values.
- Symptom: Unable to add an index in a docker-compose deployment environment, and the interface prompts that the configuration path is invalid. Cause: The local index configuration directory is not mounted in docker-compose.yml, causing the service to fail to read index mapping rules.

## How to confirm the configuration is correct
- View the index synchronization logs of FastGPT v4.17.0, confirm that only law enforcement records and monitoring data newly added on the current day have been vectorized, with no duplicate indexing records.
- Enter a query related to policy basis, verify that the retrieval results include matching law enforcement document and monitoring data fields, with no irrelevant content mixed in.
- Check the docker-compose mount configuration, confirm that the index configuration directory has been correctly mapped to the specified path within the container.
- Test long-text query scenarios, confirm that the `defaultToken` and `maxToken` configurations can normally splice context and return valid results.
