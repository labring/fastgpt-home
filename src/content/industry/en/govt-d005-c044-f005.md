# Policy and Regulatory Basis Q&A for Environmental Law Enforcement and Monitoring Supervision: Tool Calling and Plugins

## What this category of data looks like
Data for this category originates from the ecological environment law enforcement system, online monitoring platforms, automatic pollutant source monitoring data, and test reports submitted by third-party testing institutions. Daily work documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Data updates occur daily. Fields include law enforcement number, monitoring point, pollutant concentration value, law enforcement execution time, rectification requirements, and more. Some documents contain both structured numerical values and unstructured descriptive content.

## What constraints do these characteristics impose on tool calling and plugins
Daily updated data from dispersed sources requires tool calling to support real-time pulling of multi-source data, with no reliance on static caching. Documents have both structured fields and unstructured text, so tools must support both precise database queries and text snippet extraction. Law enforcement-related data must strictly align with policy basis. Tool calling results must be linked to original text fragments to ensure Q&A credibility. When processing batch law enforcement and monitoring data, single call duration may be lengthy, so reasonable timeout and batch processing limits must be configured.

## How to configure the setup

## Three common misconfigurations
- After calling a MySQL database, the response does not include database original text fragments, only generalized concluding content. This happens because the original text binding configuration for `functionCall` is not enabled, and only data pulling is completed without linking results to Q&A response citation rules.
- When calling the ecological environment knowledge base API, a universal authentication KEY is used, triggering a permission error. This happens because a dedicated authentication KEY is not bound, violating data access security specifications.
- When processing batch law enforcement and monitoring data, single workflow execution times out, returning status code 504. This happens because a reasonable tool call timeout duration is not set, exceeding default configuration limits.

## How to verify correct configuration
- Initiate a test request with a structured field query, check if tool call return results include database original text fragments and link them to the Q&A response.
- Check the tool authentication configuration page, confirm that a universal KEY is not used, and a dedicated authentication credential for the corresponding data source is bound.
- Submit a batch law enforcement data test request, check if execution duration falls within the preset 600-1200 second range.
- Verify that when `toolChoice` is set to `auto`, the tool automatically matches call requirements for database queries and text extraction.
