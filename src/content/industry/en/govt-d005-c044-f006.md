# Policy and Regulatory Basis Q&A for Environmental Law Enforcement and Monitoring Supervision: Citation Sources and Traceability

## What This Category of Data Looks Like
This category covers business data from ecological and environmental law enforcement detachments, monitoring stations, pollutant discharge units, and third-party testing institutions. Daily documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Data sources include online monitoring platforms, automatic pollutant source monitoring data, ecological and environmental law enforcement systems, and third-party test reports. The update frequency is daily. Document structures vary significantly: on-site records are mostly unstructured text, while monitoring reports contain standardized numerical fields. Core fields include monitoring points, pollutant concentrations, law enforcement time, and penalty basis.

## What Constraints These Characteristics Impose on Citation Sources and Traceability
Coexisting multi-source data requires the traceability link to associate metadata from different data sources such as law enforcement systems, online monitoring platforms, and third-party institutions. This ensures cited sources can be traced back to specific business systems. The daily update frequency requires indexing strategies to adapt to real-time synchronization needs, and prevents outdated data from being used in citations. Diverse document structures require chunking rules that balance unstructured text and structured numerical fields. This ensures cited fragments accurately match policy basis. The high compliance requirements of law enforcement scenarios mean traceability information must be complete, with no key evidence omitted. Omission will lead to serious consequences such as insufficient penalty evidence.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to single-segment citation lengths for policy and law enforcement documents, avoids context overflow |
| Maximum number of citations | Top 3–5 entries | Controls redundancy of traceability information, focuses on core law enforcement basis |
| `responseData` | Enabled | Binds source identifiers for raw data, ensures traceability to specific business systems |
| `detail` | Enabled | Displays specific locations and metadata of cited fragments, meets law enforcement compliance requirements |
| Context recall upper limit | Calibrated via actual testing | Adapts to total multi-source data updated daily, prevents loading timeouts |

## Three Common Configuration Errors
- The model context count displayed on the page is 30, but the actual number of matched cited documents reaches 310. The number sent to the caller is also 310, creating a discrepancy. This happens because the configured context recall upper limit only restricts the number of entries displayed on the interface, and the recall rules during the indexing phase are not adjusted synchronously. This means the configuration does not take effect during actual calls.
- Citation source markers cannot be removed from responses. This occurs because the `detail` configuration item is not disabled, or the option to hide citations is not checked in the interface settings.
- Citation traceability cannot be linked to raw data. This happens because the `responseData` configuration is not enabled, and metadata fields for data sources such as law enforcement systems and online monitoring platforms are not mapped.

## How to Verify Correct Configuration
- Submit a test query, check the citation list at the end of the response. Confirm that each citation is labeled with source type and specific document fragment.
- Review call logs, verify that the number of returned citations matches the configured maximum number of citations.
- Check interface switches, confirm alignment with business requirements. Disable the `detail` configuration to hide citations, or keep it enabled to display detailed traceability information.
- Verify the number of context recall entries, confirm it matches the actual indexed document pool. No discrepancies in entry counts should exist.
