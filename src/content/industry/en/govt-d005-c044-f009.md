# Policy and Regulatory Basis Q&A for Environmental Law Enforcement and Monitoring Supervision: Model Access and Configuration

## Data Characteristics of This Category
Data sources for this category include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Data updates daily.
Commonly processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Each document contains fields such as law enforcement subject, monitoring point, pollutant indicators, test values, and rectification requirements. Supported units include mg/m³, mg/L, ppm, and others. Individual document length varies widely, ranging from hundreds to thousands of characters.

## Constraints on Model Access and Configuration
Data for this category updates daily and originates from multiple dispersed sources. Model access and configuration must support real-time synchronization for multi-source data, to avoid retrieving outdated or mismatched law enforcement and monitoring data.
Individual document length varies widely. Set a reasonable limit on the total token count of documents retrieved per round, to prevent exceeding the model's context limit.
Law enforcement and monitoring data must strictly align with policy basis. During configuration, ensure the accuracy of retrieved content, to avoid introducing irrelevant information that disrupts Q&A results.

## Three Common Mistakes
- Phenomenon: Model output content is truncated, displayed as a fragment of around 4000 tokens. Cause: The `maxTokens` parameter is not adjusted, the default 4000 token limit is used, which cannot support complete Q&A content for policy basis and law enforcement data.
- Phenomenon: Model channel configuration error during local deployment, prompt for connection timeout or invalid key. Cause: The `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters are not filled correctly, or the local network cannot access the specified model proxy address.
- Phenomenon: Global variables in the workflow fail to correctly obtain the return value of the API access link, causing model call failure. Cause: The assignment logic of the API access link is not configured correctly, and the returned interface address is not bound to the corresponding global variable.

## How to Verify Successful Configuration
- Initiate a test Q&A that includes multiple law enforcement documents and monitoring data, check whether the model output completely covers the required policy basis content, with no truncation.
- Initiate a test call for local deployment, check whether Q&A results can be returned normally, with no connection error prompts.
- Initiate a Q&A for a specific law enforcement scenario, check whether all retrieved documents are valid data from the corresponding monitoring points and law enforcement periods, with no irrelevant content mixed in.
- View the model call log, confirm that the actual values of the core configuration parameters match the preset configuration, with no overwriting by default parameters.
