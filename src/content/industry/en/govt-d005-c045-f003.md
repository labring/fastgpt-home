# Policy and Regulatory Basis Q&A for Land Pre-examination and Planning Permit: Multi-turn Dialogue and Prompt Words

## What this category of data looks like
Typical stakeholders include natural resources authorities’ land use control and planning permit divisions, administrative examination and approval bureaus, and project entities. Daily business documents include land pre-examination and site selection opinions, construction land planning permits, construction engineering planning permits, red line drawings, and planning conditions. Data sources include the national integrated land spatial planning map, project approval and supervision platform, current land use database, and ecological protection red line data. Update frequency is irregular, with no fixed cycle. Data fields include project site selection scope, land scale, control requirements, prior examination conditions, and some documents contain spatial coordinates and graphic information.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words link
Data sources cover multiple types of spatial and examination and approval information. Prompt words must clearly define retrieval scope to avoid recalling policy content from unrelated categories. Daily documents include unstructured red line drawings and planning conditions. Multi-turn dialogue must guide users to supplement specific project details such as site location and project type to match corresponding documents. Update frequency is irregular. Prompt words must note data timeliness, and require dialogue results to only reference the latest currently available policy content. Errors may lead to severe consequences. Multi-turn dialogue must add a verification step to confirm no conflicts between project site selection, control requirements, and land scale.

## Three Common Misconfigurations
- Issue: Garbled text appears in dialogue responses. Cause: No OCR preprocessing was applied to unstructured documents such as scanned red line drawings and planning conditions. Direct embedding causes text parsing failure.
- Issue: Conversation logs for local deployments are not automatically retained. Cause: Conversation log persistence configuration was not enabled, causing conversation records to be lost upon instance restart.
- Issue: Retrieval results include policy content unrelated to land pre-examination. Cause: The data source scope was not defined in the prompt words, leading to recall of documents from other natural resource categories such as real estate registration.

## How to Verify Proper Configuration
- Initiate a test dialogue that includes specific project site selection coordinates, check that returned content only includes policy documents related to land pre-examination and planning permits.
- Generate a `chatId` for different projects to initiate dialogue, check that conversation history only associates context content for the corresponding project, with no cross-project confusion.
- Upload a scanned red line drawing and initiate a dialogue, check that the returned text has no garbled characters and the OCR recognition result is accurate.
- View the prompt word template configuration, confirm that `variables` such as project type and examination and approval stage have been bound.
