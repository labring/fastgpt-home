# Policy and Regulatory Basis Q&A for Land Pre-examination and Planning Permit: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from the national land and space planning unified map, project approval and supervision platform, land use status database, and ecological protection red line data. Update frequency is irregular. Daily supporting documents include land pre-examination and site selection opinions, construction land planning permits, construction project planning permits, red line drawings, and planning conditions. Fields include project site selection scope, land scale, planning control requirements, and more. Some documents contain vector spatial coordinate information. Available formats include structured forms and drawing files.

## What constraints do these characteristics impose on the deployment and upgrade process
Data sources for this category are multiple, and updates have no fixed cycle. During deployment, support must be added for mixed data access from structured forms and vector drawings. During upgrade, incremental update logic must be compatible to avoid time-consuming full re-import operations. Since data involves spatial coordinates and control rules, resource allocation for spatial data processing must be reserved during deployment. As errors directly affect project approval and construction start, complete retrieval result verification logic must be configured during deployment to avoid returning incorrect policy basis. Format differences across multiple data sources require unified field mapping configuration during deployment. Mapping rules must be updated synchronously during upgrade to adapt to new data source formats.

## Three Common Mistakes
- Symptom: Mixed retrieval response time exceeds business expectations, single retrieval time is significantly longer than vector retrieval. Cause: Retrieval configuration is not optimized for the multi-source data structure of this category. Mixed retrieval calls multiple types of data sources and spatial data at the same time, leading to increased time consumption.
- Symptom: After Docker deployment is complete, the front-end page cannot display configuration entries or function modules. Cause: The `FE_DOMAIN` parameter is not configured correctly, leading to abnormal communication links between the front-end and back-end, and unable to load necessary page resources.
- Symptom: Workflow debugging returns field mismatch errors, and the corresponding policy documents cannot be obtained. Cause: Field mapping between structured policy documents and spatial data is not completed, leading to failure to correctly match the control rules required for the project during retrieval.

## How to Confirm Configuration is Complete
- Access the front-end page, confirm that all configuration entries and function modules load normally, with no blank spaces or error prompts.
- Initiate a policy basis retrieval, check that the returned document types match the daily supporting document types of this category.
- View back-end logs, confirm that the connection status of storage configurations such as `REDIS_URL` and `PG_URL` is normal, with no abnormal errors.
- Upload a test red line drawing document, confirm that the file can be stored normally and generate an access link, with no storage-related errors.
