# Policy and Regulatory Basis Q&A for Social Assistance and Minimum Living Security Review: Tool Calling and Plugins

## What Data for This Category Looks Like
This category falls under the civil affairs public service sub-scenario. Its core data covers the full process of social assistance and minimum living security review. Daily business documents include minimum living security application forms, family economic status verification reports, household investigation forms, democratic appraisal records, public notice materials, and assistance approval forms.
Data sources include the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Update frequency is once per month.
Data fields include family population information, income and property details, and application and approval process node records. All data is linked to a unique assistance application number, used to match policy basis and specific application materials.

## Constraints Imposed on Tool Calling and Plugins
Monthly updated cross-department shared data requires the tool calling knowledge base sync cycle to match this frequency. This avoids review deviations caused by expired data.
Mixed types of business documents require plugins to support parsing structured verification reports and unstructured household investigation records. Plugins must accurately extract core fields such as family population and income and property.
Strongly linked business data fields require simultaneous verification of multiple field consistency during tool calling. This prevents incorrect insurance issuance or missed insurance caused by single-field matching errors.
Full-process node records require plugins to link corresponding policy clauses. This ensures Q&A basis covers all process links: application, verification, approval, and public notice.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to mixed retrieval of multiple policy documents and business data, automatically selects the appropriate tool calling type |
| Knowledge base sync cycle | Once per month | Matches the monthly update frequency of cross-department shared data for this category, ensures Q&A basis stays synchronized with latest data |
| Document chunk length | 800–1200 characters | Adapts to policy matching for long fields like family income and population information, avoids truncating key linked information |
| Tool calling timeout threshold | 600 seconds | Covers time requirements for cross-department data retrieval and multi-document parsing, prevents mid-process interruptions |
| Maximum data returned per tool call | Top 10 entries | Adapts to single-return scale of cross-department shared data, avoids interface overload |
| `functionCall` | Enabled | Supports structured extraction of income and property data from verification reports, for accurate matching of policy basis |

## Three Common Misconfigurations
- No response after tool calling node execution. Logs show connection timeout or database connection failure. Cause: The setup does not match cross-department data retrieval time requirements, the timeout threshold is set too short, or access permissions for cross-department data sources are not configured.
- Intermediate plugin execution logs and structured data appear in the conversation interface. Cause: The intermediate result display switch for tool calling is not disabled, causing plugin execution content during the process to be output directly.
- Q&A results do not link to corresponding policy clauses or application materials. Cause: The `functionCall` function is not enabled, making it impossible to extract key fields from verification reports for matching policy basis.

## How to Confirm Proper Configuration
- Trigger a minimum living security policy Q&A request. Check if the returned result includes matching explanations for linked policy clauses and application material fields.
- View the knowledge base sync log. Confirm the most recent sync time matches the current month, verifying the monthly update configuration is effective.
- Call the tool calling interface. Check if the returned structured data includes core fields for this category, such as family income and population information.
- Disable the tool intermediate result display switch and initiate a test. Confirm the conversation interface only displays the final Q&A result, with no plugin execution logs.
