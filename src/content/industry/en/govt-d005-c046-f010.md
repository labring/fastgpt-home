## What this category of data looks like
Social assistance and minimum living allowance review scenario data covers full civil affairs business process documents and cross-department shared data. Daily documents include minimum living allowance application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, assistance approval forms, and similar items. Data sources include low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Update frequency is monthly. Data fields include family member information, income and property details, approval process nodes, and more. Individual document sizes range from several pages to dozens of pages. Some documents require association with cross-department structured verification results.

## Constraints imposed by these characteristics on knowledge base retrieval and recall
Cross-department shared data requires permission isolation rules to be configured, to prevent unauthorized roles from accessing sensitive civil affairs data. The monthly update schedule requires scheduled synchronization tasks to ensure data timeliness aligns with business processes. Documents include structured forms and unstructured supporting materials, so a mixed chunking strategy must be used to balance precise field matching and full-text semantic retrieval. Family unique identifiers act as core retrieval fields, so precise matching rules must be configured to avoid associating incorrect family data. Review results directly link to assistance eligibility, so retrieval result confidence must be increased to reduce risks of incorrect eligibility determinations and missed eligible cases.

## Three common errors
- Local deployment of the open-source knowledge base has entry count limits, and the upper limit cannot be adjusted independently. The cause is failure to modify the default knowledge base configuration parameters, and using the platform's built-in entry limit.
- When creating a knowledge base using a URL, the backend log prompts `cannot fetch internal url`. The cause is that the deployment environment has not opened access permissions for internal data sources, or the configured URL contains a private address not mapped by the intranet.
- PDF files in the knowledge base cannot be read, and chunk previews return that the file content cannot be read. The cause is that the PDF contains encrypted content, is a scanned image version without OCR processing, or the chunking configuration does not adapt to the pagination loading rules for long documents.
