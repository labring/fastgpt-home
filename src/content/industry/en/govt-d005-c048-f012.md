# Administrative Licensing and Approval Policy and Regulatory Basis Q&A: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository. The update frequency is daily. Documents processed daily include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing approval decisions, and license certificates. The document structure is bounded by statutory licensing items. It includes standard government affairs fields such as item name, legal basis, handling conditions, and application material list. There are no custom special units. All fields follow the national government service standard format.

## Constraints imposed on deployment and upgrade workflows
This category includes multiple data sources that update daily. Deployments must use stable persistent storage and incremental synchronization mechanisms to prevent data lag from reducing Q&A accuracy. The document structure follows standardized fixed fields. Knowledge bases must match the legal basis and handling condition fields of items. Arbitrary adjustments to chunking logic will cause Q&A matching errors. Cross-departmental system access requires reserving standard interface adaptation space during deployment. This space facilitates subsequent connection to approval systems from different departments. During upgrades, the item library cache must be updated synchronously. This avoids conflicts between old and new data that lead to incorrect approval basis references. Upgrade processes must not interrupt existing government affairs Q&A services.

## Three common configuration mistakes
- Issue: Redis connection error after startup. Logs show connection timeout or password verification failure. Cause: `REDIS_URL` is not configured as the Redis instance address on the government intranet, or a public network Redis service is used leading to network unreachability. This does not meet government data security control requirements.
- Issue: The latest administrative licensing item list is not updated after knowledge base synchronization. Cause: The daily incremental synchronization trigger rule is not configured, or the official update time node of the administrative licensing item library is not matched. This leads to data synchronization lag.
- Issue: No registration entry appears when accessing the frontend page. Administrator accounts cannot be created. Cause: `ROOT_KEY` is not correctly set and initial configuration is not completed, or the initial user generation step is skipped during deployment. This leads to the default administrator account not being created.

## How to verify correct configuration
- Run the database connection test tool included with FastGPT. Verify that databases configured with `MONGODB_URI` and `PG_URL` can establish normal connections and perform read/write operations.
- Log in to the FastGPT backend management interface. Check the knowledge base synchronization task logs. Confirm that the daily incremental synchronization task for the administrative licensing item library has executed normally with no errors.
- Access the frontend address corresponding to the configured `FE_DOMAIN`. Verify that the page loads normally, with no cross-domain or resource loading failure prompts.
- Submit a test query, such as "What is the legal basis for a certain administrative licensing item". Confirm that the returned content matches the official content in the current administrative licensing item library.
