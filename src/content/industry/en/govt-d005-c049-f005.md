# Policy and Regulatory Basis Q&A for Normative Document Legality Review: Tool Calling and Plugins

## What this category of data looks like
This category of data primarily comes from the regulatory and rule library, higher-level law database, departmental policy document library, and administrative normative document filing system. This data is updated on an irregular basis. Daily processed documents include normative document drafts, drafting explanations, legality review opinions, solicited opinion summaries, and filing reports. Documents typically contain fields such as document name, issuing authority, effective date, article content, authority basis, and solicited opinion content. There is no unified fixed unit. Distinction is based solely on the document's own text length and number of clauses.

## What constraints do these characteristics impose on the tool calling and plugin workflow
Decentralized data sources and heterogeneous formats require tool calling to support integration with multiple types of data sources and adaptation to parsing rules for different documents. Irregular update frequency requires tool calling to support on-demand pulling of the latest data to avoid using expired policy references. Daily processed documents cover multiple compliance-related contents, so tool calling needs to configure different recall priorities for different documents to ensure that data matching higher-level laws and authority basis is prioritized during legality review. Reviews require accurate comparison of article contents, so tool calling must limit its recall scope to policy references strongly related to the currently reviewed article to reduce irrelevant information interference.

## How to set the configurations
The following configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Allows the AI to independently determine whether to call tools to obtain policy references, adapting to the dynamic needs of review scenarios |
| Single recall result count | Top 5 results | Controls the number of returned policy references to avoid context overload |
| Tool calling timeout | 600 seconds | Adapts to the time required for pulling data from multiple sources, preventing review process interruptions due to timeout |
| `functionCall` | Enabled | Allows the AI to call preset tools to complete policy reference retrieval and comparison |
| Data source whitelist | Regulatory and rule library, higher-level law database, departmental policy document library | Limits the scope of data sources for tool calling to ensure only compliant policy references are used |

## Three common mistakes
- Symptom: Tool calling module does not trigger, and no tool calling records appear in the interface. Cause: `toolChoice` is not set to auto, or the global tool calling function is not enabled.
- Symptom: Policy references returned by the tool do not match the currently reviewed article, and recall results have significant deviations. Cause: The data source whitelist is not configured, and the tool calling scope covers non-compliant and unnecessary data sources.
- Symptom: Tool calling times out, and timeout errors are shown in logs. Cause: The timeout setting is lower than the actual time required for pulling data from multiple sources, and parameters are not adjusted based on the business scenario.

## How to confirm the configuration is complete
- Enter the tool calling module in the workflow, and check whether the `toolChoice` configuration item is set to auto.
- Trigger a simulated review request, and check whether corresponding requests are generated in the tool calling logs.
- Check the data source configuration to confirm that only the regulatory and rule library, higher-level law database, and departmental policy document library are included.
- Test the tool calling timeout time, simulate a multi-data-source pulling scenario, and confirm that no timeout errors are triggered.

The values provided are common starting points and should be measured against the reader's own samples.
