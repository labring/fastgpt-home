# Policy and Regulatory Basis Q&A for Legality Review of Normative Documents: Knowledge Base Retrieval and Recall

## Data for this category
This category’s data mainly comes from the regulatory and rule library, higher-level law database, departmental policy document library, and administrative normative document filing system. Update frequency is irregular. Daily processed documents include normative document drafts, drafting explanations, legality review opinions, summaries of solicited comments, and filing reports. The content length of a single document ranges from several articles to dozens of pages of complete files. Fields include document identifier, publishing entity, effective date, original text of articles, and review-related records. There is no fixed unified unit field. Management permission scope varies based on the administrative level of the file the document belongs to.

## Constraints on the retrieval and recall link from these data traits
The data traits of this category impose clear constraints on the retrieval and recall link. Dispersed data sources require cross-collection recall capabilities to cover multiple sources such as the regulatory and rule library and higher-level law database. Irregular update cycles require synchronization logic adapted to non-fixed-period data sources to avoid missing the latest policy documents. Large differences in document length require chunking strategies adapted to text lengths ranging from several articles to dozens of pages of complete files. Data includes historical review-related records, requiring retrieval to associate context for auxiliary verification. The core requirement to compare against higher-level laws requires recall results to prioritize matching higher-level legal basis.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Legality review of normative documents requires strict matching of article legality. A threshold that is too low will introduce irrelevant content, while a threshold that is too high will miss compliant basis |
| `limit` | `Return the top 10 results` | Too many single recall results will exceed the context window, while too few will fail to cover multi-dimensional legality review basis |
| `searchMode` | Hybrid semantic and keyword retrieval mode | Need to match both article semantics and precise metadata such as document number and publishing entity, to improve retrieval accuracy for legality review |
| `usingReRank` | Enabled | Need to reorder recall results by legality relevance, prioritize returning key basis such as higher-level laws and core policies |
| `datasetSearchUsingExtensionQuery` | Enabled | Can supplement the background basis of policy formulation through extended queries, to assist in completing legality verification |
| `collectionIds` | Bind corresponding dataset IDs according to the review scenario | Only recall datasets corresponding to regulations and policies for the current review task, to avoid irrelevant data interfering with the review process |

## Three common errors
- Symptom: Query read timeout error returned when calling the dataset collection creation interface. Cause: No reasonable interface timeout logic configured, or retrieval request waiting timeout caused by incomplete data source synchronization.
- Symptom: No retrieval results returned after passing the knowledge base ID externally. Cause: The `collectionIds` parameter for the corresponding dataset is not correctly bound, or the passed ID does not fall within the dataset scope authorized for the current application.
- Symptom: Unable to obtain a valid knowledge base ID for retrieval in the workflow. Cause: No dataset association logic configured in the workflow node, or the created collection ID variable not correctly referenced.

## How to confirm the configuration is complete
- Confirm that FastGPT v4.17.0 is currently in use, view the retrieval configuration panel, and confirm that parameters such as `similarity` and `limit` have been set according to the specified values.
- Initiate a simulated retrieval request, pass the core articles of the normative document draft, and check whether the returned results include higher-level legal basis and relevant policy documents.
- Check the workflow node configuration, confirm that the `collectionIds` variable of the target dataset has been correctly referenced, with no null values or invalid IDs.
- Test interface calls, verify that the number of returned results matches the setting of the `limit` parameter, with no timeout errors.
