# Policy and Regulatory Basis Q&A for Fiscal Expenditure Performance Evaluation: HTTP APIs and External Systems

## Data overview for this category
This category’s data covers the full workflow of fiscal expenditure performance evaluation. Daily documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports.
Data sources include the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. Update frequency is annual.
Data fields include project ID, performance indicator value, actual completion value, fund allocation amount, supporting material association identifier, and more. Units include ten thousand yuan, person-times, percentage, and others.
Data must link fund usage and performance output across the full project lifecycle, and match evaluation standards specified by policies and regulations.

## Constraints on HTTP APIs and external systems
Annual updated bulk data requires APIs to support one-time bulk pulling or import, to avoid system load from high-frequency calls.
Multiple data sources require APIs to adapt to output formats of different fiscal systems. This is done by passing system identification parameters via `variables`.
Policy basis Q&A for performance evaluation requires linking policy texts and project data. APIs must support carrying policy document numbers as retrieval parameters.
Verification of supporting materials requires APIs to return structured matching results. `responseData` must include supporting material association paths and matching identifiers.
API calls must comply with fiscal system security requirements. Valid identity credentials must be passed via `Authorization`.

## Configuration guidelines

## Three common configuration errors
- Failing to configure a system proxy during initial deployment prevents connection to the unified budget management system, resulting in a `504 Gateway Timeout` error. Fiscal systems are typically deployed on internal networks, so a specified HTTP proxy is required to access external interfaces.
- Failing to pass the policy document number in the `variables` parameter when calling the API causes retrieval results to fail to match the corresponding policy basis, returning an empty `responseData` field. Performance evaluation Q&A strictly relies on regulatory clauses linked to policy document numbers.
- When using the create file collection feature to upload CSV-format performance data, failing to specify data field mapping rules causes the system to fail to recognize performance indicator values and actual completion values, resulting in an import failure prompt. The field format of fiscal performance data differs from general CSV templates.

## How to confirm successful configuration
- Call the API with a test project ID and policy document number, check if the policy clauses returned in `responseData` match the performance requirements of the test project.
- Review API call logs to confirm the `Authorization` token was correctly carried, with no identity verification failure errors.
- Upload a test performance data CSV file, confirm the system can correctly recognize fields and link to corresponding policy basis.
- Simulate a user-initiated policy basis Q&A request, check if the returned results include association explanations between project data and policies and regulations.
