# Policy and Regulatory Basis Q&A for Fiscal Expenditure Performance Evaluation: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data mainly comes from the unified budget management system, project declaration materials, fund payment ledgers, business system records, and satisfaction survey results. Core daily documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Fields cover project codes, fund-related information, performance indicators, output effects, rectification status, and more. The data update frequency is annual. Each individual document contains structured fields and multiple types of unstructured supporting content, and requires linking business and financial dimension information.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
The annual update feature of the data requires multi-turn dialogue contexts to support targeted retrieval of annual datasets, to avoid interference from invalid cross-cycle information.
Multi-dimensionally associated business and financial fields require prompts to clearly specify retrieval scopes, preventing information confusion across projects or indicators.
The feature of individual documents containing both structured and unstructured content requires multi-turn dialogue to gradually guide users to clarify specific projects, performance indicators, or report types, avoiding result deviations from generalized retrieval.
The requirement for associating data from multiple systems requires the dialogue link to verify information source consistency, ensuring Q&A is based on valid current annual datasets.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 token | Adapts to the total token size of annual datasets, to avoid truncating core performance indicators and supporting information |
| Single Search Limit | Top 3 entries | Matches the number of core supporting materials in a single performance evaluation report, to reduce interference from irrelevant information |
| Question Optimization | Enabled | Handles vague project names or indicator descriptions in user questions, and automatically supplements associated fields |
| Variable Binding | Bind the project annual parameter in `variables` | Adapts to the annual data update feature, for targeted retrieval of datasets for the corresponding cycle |
| Conversation History Association | Maintain based on `messages` and `chatId` | Ensures context consistency for multi-turn dialogue, to avoid information chaos across sessions |
| Session Expiration Time | 30–90 days | Adapts to the annual work cycle of fiscal performance evaluation, to avoid expired sessions interfering with subsequent queries |

## Three Common Misconfigurations
- "No available index model detected" prompt after refreshing the page: The index source for the corresponding annual dataset is not bound in the configuration, or the update cycle of the index model does not align with the annual data update rhythm.
- Multi-turn dialogue cannot continue historical conversations from months prior: Conversation context is not persistently saved based on `chatId` and `messages`, or the session expiration time is set too short.
- Single dialogue response time exceeds 10 seconds: The single search limit is not configured, or question optimization is not enabled, resulting in an overly large retrieval scope and triggering excessive document loading and matching operations.

## How to Verify Successful Configuration
- Initiate a query that includes a clear project year and indicator, and verify that returned results only associate with datasets for the corresponding year.
- Initiate multiple consecutive queries, and verify that the conversation context retains project information from the previous round without requiring repeated explanation.
- Check system logs to confirm that each retrieval only returns no more than the set limit of document entries.
- Test after the session expires, and verify that the previous `chatId` conversation cannot be continued, to confirm the validity of the session configuration.
