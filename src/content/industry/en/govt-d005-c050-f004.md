# Policy and Regulatory Basis Q&A for Fiscal Expenditure Performance Evaluation: Workflow Orchestration

## What This Category’s Data Looks Like
Data for this category mainly comes from the unified budget management system, project declaration materials, fiscal fund payment data, business system ledgers, and satisfaction survey results. Routinely processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Data fields cover project ID, fund amount, performance indicators, supporting material association relationships, and more. The data update frequency is annual. A single update covers all materials related to active and completed fiscal expenditure projects for the current year.

## What Constraints These Characteristics Impose on Workflow Orchestration
Annual data updates require workflows to support batch processing and archiving of annual project data, eliminating repeated configuration.
Multiple document types require workflows to include input nodes adapted to different formats, covering business documents such as performance target forms and self-assessment forms.
Data from multiple systems requires cross-system data pulling connection nodes in workflows, to ensure consistent data sources.
Strong correlations between project fields require embedded field verification links in workflows, to check the correspondence between fund expenditure and performance targets.
Time-consuming supporting material collection and verification steps require configurable parallel processing nodes or timeout reminder mechanisms, to prevent process blocking.

## Three Common Configuration Mistakes
- The workflow sharing configuration interface does not display identity authentication related options. The cause is that the authentication switch for workflow sharing is not enabled in global permission configuration, and permission rules are only configured at the node level.
- Database connection plugin execution time has increased significantly compared to older versions. The cause is that no filtering conditions are set for data pulling, and the new version of the system pulls all annual project data by default, exceeding the reasonable range of single-batch data processing.
- The classify module cannot select an AI model during editing. The cause is that the editing page does not synchronize the list of available models bound to the current workflow. The system will automatically match the preset model after publishing, and it will run normally.

## How to Confirm Configuration Is Complete
- Manually trigger the workflow for a single annual project, check whether the input and output data of each node match the preset `variables` fields.
- View the workflow’s node logs to confirm that cross-system data source pulling requests return normally, with no timeout error messages.
- Test input of different types of business documents to confirm that the workflow can normally adapt to business materials such as performance self-assessment forms and rectification reports.
- Trigger the abnormal branch of the workflow to confirm that the node jump rule triggers the corresponding business link according to the preset logic.
