# Policy and Regulatory Basis Q&A for Fiscal Expenditure Performance Evaluation: Tool Calling and Plugins

## What this category's data looks like
Data sources for this category include the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction survey results. The update frequency is annual. Commonly processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Data fields cover performance quantitative indicators, fund disbursement nodes, supporting material numbers, evaluation scoring items, and rectification completion status. No additional custom statistical fields are included.

## What constraints these characteristics impose on the tool calling and plugins link
The annual update feature requires the tool calling caching strategy to align with the annual data cycle, preventing repeated calls of existing data. The need to integrate data from multiple sources requires plugins to support API interfaces for various data sources, including the unified budget management system and business ledger systems. The varied document structures require the tool calling module to support parsing rules for different document formats, such as performance target forms and self-assessment reports. The fixed field structure requires tool call outputs to strictly match preset fields, preventing irrelevant content from being included in the Q&A workflow.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `"auto"` | Adapts automatic tool selection logic for multiple types of policy documents and performance data |
| `functionCall` | `"strict"` | Ensures tool call output strictly matches preset fields including performance indicators and fund disbursement nodes |
| Tool call running log switch | Off | Avoids generating redundant running log content |
| API call timeout period | `120 seconds` | Adapts to response delays for annual batch data queries |
| Tool call retry count | `2 times` | Addresses temporary connection exceptions for multi-system integrations |
| Data cache validity period | `365 days` | Aligns with the annual update feature of this category, preventing repeated calls of existing data |

This configuration was validated on FastGPT v4.17.0.

## Three common mistakes
- Phenomenon: The tool calling module continuously outputs running logs, disrupting normal Q&A workflows. Cause: The default tool call running log switch was not disabled, resulting in full logs being returned synchronously.
- Phenomenon: Connection failure errors occur when calling external tools, and performance data cannot be retrieved normally. Cause: Reasonable retry counts and timeout periods were not configured, failing to handle temporary connection fluctuations in the unified budget management system.
- Phenomenon: Tool call output does not match preset performance fields, making it unsuitable for direct use in evaluation report generation. Cause: Strict mode for `functionCall` was not enabled, allowing irrelevant field content to be included in tool outputs.

## How to verify correct configuration
- Initiate a single policy basis Q&A test to confirm that tool call running logs are not returned alongside the final answer.
- Connect to the test interface of the unified budget management system, send a data query request, and confirm that the tool call can successfully retrieve content from the corresponding data source.
- Input a test question containing performance indicators, and check whether the tool call output strictly matches the preset performance fields and document formats.
- Test disabling stream output to confirm that the Q&A workflow returns content in the expected format.
