# Policy and Regulatory Basis Q&A for Department Final Accounts and Financial Reports: Workflow Orchestration

## What Data for This Category Looks Like
Typical data for this category comes from the integrated budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual, with processing starting after the end of each calendar year. Daily generated documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The document structure primarily uses standardized report fields and written explanations, covering actual revenue and expenditure, assets and liabilities, and budget execution differences. This page configuration is based on FastGPT v4.17.0.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The annual update cycle requires the workflow's knowledge base to sync once per year, to avoid high-frequency, ineffective updates. Multiple data sources require the workflow to bind multiple system retrieval nodes corresponding to `nodeId`, to ensure coverage of all relevant policy basis documents. The standardized report and explanation structure demands precise retrieval rules for core links such as difference explanations and income and expenditure reconciliation. It also requires adaptation to error consequence constraints, and strengthening of compliance checks for referenced content. Set node timeout to 60 seconds, to avoid long waits for retrieval results, aligning with annual final account processing rhythms.

## Three Common Configuration Mistakes
- Issue: Passing the `variables` parameter during API calls results in unexpected output, caused by failure to correctly bind variables to business parameters for final account scenarios.
- Issue: Setting the single search reference limit to 2000 causes the answer's token count to exceed limits, resulting in truncated content or API errors, caused by failing to account for the length of single department final account documents.
- Issue: Failing to configure the auto-trigger node, requiring users to manually send messages to generate a response, caused by not enabling the workflow configuration triggered when a session starts.

## How to Verify Successful Configuration
- Start a blank session, check if the workflow is automatically triggered and returns content related to policy basis.
- Call the API interface, pass preset `variables` parameters, verify if the returned results match the passed business scenario.
- Adjust the single search reference limit to 5, check if the token count of the returned results meets expectations.
- Trigger the reference validation node, input a reference content that does not comply with final account policies, verify if the system can identify it and return an error prompt.
