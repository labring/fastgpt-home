# Policy and Regulatory Basis Q&A for Department Final Accounts and Financial Reports: Deployment and Upgrade

## What data for this category looks like
Data for this category primarily comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system, with an annual update cycle. Daily output documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Data fields cover revenue and expenditure details, asset and liability balances, budget execution difference explanations, and more. The core unit of measurement is the Chinese Yuan, and all data must comply with unified report format specifications set by the finance department.

## What constraints do these characteristics impose on deployment and upgrades
The annual update cycle of this category requires a stable batch data synchronization mechanism to be configured during deployment, to support data access from multiple system sources. The fixed document structure and unified report format require the knowledge base index to match the chapter divisions of department final account statements, ensuring that Q&A can accurately locate corresponding content. Multiple system data sources require compliant data source connections to be configured in advance. For intranet deployment scenarios, network access policies must be adjusted to avoid cross-system data pull failures. The high compliance requirements of annual final accounts require strengthening the source traceability capability of Q&A results during the upgrade phase, ensuring that policy bases are accurately matched.

## Three common misconfigurations
- Symptom: Database connection timeout error with 504 status code occurs during intranet deployment. Cause: IP whitelist for intranet systems is not configured, resulting in cross-system data pull being blocked.
- Symptom: All configurations and knowledge base data in Docker containers are cleared after server restart. Cause: Local volume persistent storage for databases and cache data is not mounted, temporary files are cleared when the container restarts.
- Symptom: Empty results are returned when calling the policy Q&A API. Cause: The chapter structure of final account statements is not matched with knowledge base chunks, resulting in the Q&A being unable to locate the corresponding policy basis.

## How to confirm configurations are correctly set
- Run the database connection test script to verify the connection status of `MONGODB_URI` and `PG_URL`, ensuring no timeout or permission errors occur.
- Upload an example annual final account statement file, check whether `STORAGE_S3_ENDPOINT` can normally store and parse the file.
- Initiate a policy Q&A regarding the format of department final account statements, verify that the returned results match the corresponding document chapters and data sources.
- Restart the Docker container, check whether the knowledge base and configuration data are fully retained, confirming that the persistent storage configuration is effective.
