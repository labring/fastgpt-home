# Policy and Regulatory Basis Q&A for Departmental Budget Preparation: Vector Models and Indexing

## What the Data for This Category Looks Like
Core data for this category comes from the unified budget management system, departmental staffing system, prior-year final accounts, project repository, and Ministry of Finance budget preparation notices. Daily output documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and similar materials. Data updates follow an annual cycle. Bulk updates of existing data and new policy documents are only initiated when budget preparation for the new year begins. Document structures mostly mix structured tables and policy provisions. Fields include project code, expense amount, performance indicators, compiling unit, and others. No unified cross-departmental format standard exists.

## What Constraints Do These Characteristics Impose on Vector Models and Indexing?
Bulk data updated annually and mixed policy provision structures require indexing systems to support a combination of periodic full reindexing and incremental updates. Structured fields and unstructured policy text coexist. This requires simultaneous adaptation to semantic encoding for both structured numeric fields and unstructured policy text. Doing so avoids information loss caused by using a single model. Ununiform cross-departmental document formats require chunking strategies tailored to different document lengths. This prevents policy clauses from being broken by long text truncation. Data volume grows as budget hierarchy expands. Resource usage per indexing batch must be limited to prevent system overload.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the mixed length of policy provisions and tables in departmental budget documents, avoiding truncation of key clauses |
| Overlap Length | 100–150 characters | Retains contextual connections across chunks, preventing policy clauses from being split by chunking |
| `maxToken` | 4096 token | Matches the input limit of the bge-m3 model and FastGPT v4.17.0 version, adapting to semantic encoding of long-text policy documents |
| `defaultToken` | 200 token | Controls the return length of single retrieval results, avoiding context overload |
| Similarity Threshold | 0.72–0.78, calibrated via actual testing | Distinguishes semantic relevance of policy provisions, filtering low-match irrelevant documents |
| Single Search Limit | Top 8 results | Adapts to the need for multiple reference sources in budget preparation review, avoiding excessive results that interfere with judgment |

## Three Common Misconfigurations
- Symptom: Retrieval results only return vector data, with no original document content. Cause: No mapping storage between original documents and chunks is configured. Only vector embeddings are saved to the database. Associated information such as source file path and chunk position is not retained.
- Symptom: Retrieval scores are generally high when using the bge-m3 model. Cause: No format preprocessing is performed for structured tables in budget documents. Meaningless table separator characters are mixed into semantic encoding. This leads to abnormal similarity calculation.
- Symptom: Indexing tasks remain in a running state with no data generated. Cause: No reasonable chunk length limit is set. Chunk processing of ultra-long documents times out. This prevents the indexing process from advancing.

## How to Verify Successful Configuration
- Check vector database storage content. Confirm that both vector embeddings and metadata of original chunks are present. This includes source file path, chunk start position, and other information.
- Import a typical Ministry of Finance budget preparation notice document. Perform a semantic retrieval test. Verify that the similarity scores of returned results fall within the preset range.
- Trigger an incremental indexing task. Check the task log to confirm chunk encoding is completed within the `maxToken` limit. No truncation-related errors are present.
- Verify the annual bulk update task trigger logic. Confirm full reindexing is only executed when the budget preparation cycle starts. No abnormal repeated execution occurs.

The values provided here are common starting points and should be measured against the reader's own samples.
