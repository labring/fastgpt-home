# Policy and Regulatory Basis Q&A for Departmental Budget Preparation: Document Parsing and Chunking

## What this category of data looks like
Departmental budget preparation-related data typically comes from the unified budget management system, departmental staffing system, prior-year final accounts, project library, and Ministry of Finance budget preparation notices. Its update frequency is annual. Daily documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and more. Document structures contain hierarchical policy clauses, structured budget tables, project codes and expense detail fields. Relevant measurement standards include common fiscal-related units such as ten thousand yuan, person, project number, and others.

## What constraints do these characteristics impose on the document parsing and chunking link
The annual batch update document feature requires parsing and chunking to support batch processing, avoiding single-task timeouts. Mixed multi-type document scenarios require adaptation to the paragraph structure of policy texts and the row-column association of budget tables, preventing chunking from truncating critical data associations. Document formats from different sources are inconsistent. Some PDFs exported from systems contain fixed redundant header and footer information, requiring targeted filtering. At the same time, the accuracy of budget data directly affects subsequent review results. Parsing and chunking must retain field context, avoiding loss of the binding relationship between policies and corresponding budget items after splitting.

## Configuration Settings
The following configuration references apply for FastGPT v4.17.0:

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the mixed structure of policy clauses and budget tables in departmental budget documents, preserving contextual association while avoiding excessively long chunks that reduce retrieval efficiency |
| `chunkSplitter` | Split by title + paragraph | Matches the hierarchical title structure of budget documents, ensuring that the binding relationship between policy clauses and corresponding project budgets, performance targets is not split |
| `customPdfParse` | Enabled | Filters fixed redundant header and footer information from PDFs exported by the unified budget management system, extracting core policy and budget data |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of large annual budget draft PDFs, avoiding interruptions from timeouts during batch tasks |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploads of annual budget document collections, meeting file size requirements for multi-department budget summaries |
| `chunkSettingMode` | Manual mode | Flexibly adjusts chunking rules for different document types such as policy texts and budget tables, adapting to retrieval needs for specific scenarios |

## Three Common Misconfigurations
- Uploading some budget PDF files results in empty content, or only headers and footers are displayed. The cause is that `customPdfParse` is not enabled, so fixed encrypted headers and footers from PDFs generated by the unified budget management system cannot be filtered, leading to failure to correctly extract valid content.
- Importing non-standard format files (such as Java interface documents with renamed file extensions to .txt) yields no parsing results. The cause is that core documents for departmental budget preparation are in PDF and table formats. No corresponding format parsing rules are configured, and plain TXT files lack structured markers, making it impossible for chunking to identify valid content.
- After calling the chunk mode pushdata API to upload a collection of budget documents, the task remains in the indexing state for a long time. The cause is that `PARSE_FILE_TIMEOUT_SECONDS` is set to a value smaller than the actual parsing time. Parsing completes before the indexing process is triggered, leading to task stagnation.

## How to Verify Proper Configuration
- Upload a single departmental budget draft PDF, check that the parsing result contains complete policy clauses and budget table content, with no redundant header or footer information.
- Upload a batch of annual budget documents, confirm that the total file size does not exceed the `UPLOAD_FILE_MAX_SIZE` limit, and no upload failure prompts appear.
- Call the pushdata API to upload a test document, check the parsing log to confirm that the chunking duration does not exceed the `PARSE_FILE_TIMEOUT_SECONDS` setting value.
- Manually adjust `chunkSize`, compare the completeness of policy clauses under different chunk lengths, confirm that chunks do not truncate the association between critical budget fields and corresponding policies.

The values provided here are common starting points, and should be evaluated against local samples.
