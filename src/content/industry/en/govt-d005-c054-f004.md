# Policy and Regulatory Basis Q&A for Flood Control, Disaster Prevention and Emergency Duty: Workflow Orchestration

## What this category of data looks like
Daily documents for this category include duty logs, early warning notifications, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Fields typically cover event level, occurrence time, impact scope, disposal progress, responsible entity, and other items. Data is primarily sourced from meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video monitoring. The standard update frequency is daily; some real-time early warning documents have higher update frequencies.

## What constraints do these characteristics impose on the workflow orchestration link
Multi-source heterogeneous data access creates differences in field formats, requiring a unified format conversion node to be configured during workflow orchestration to adapt to document specifications output by different systems. The daily basic update frequency and the sudden nature of real-time early warnings require workflows to support both scheduled triggering and event triggering modes, ensuring timeliness and flexibility of information synchronization. Document types include both structured and unstructured content, requiring differentiated parsing and recall rules for different documents to prevent invalid information from entering the Q&A chain. Cross-department collaborative scheduling needs require workflows to support parameter passing functions to enable linkage of business data across different stages.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Selection | Bind multiple knowledge base tags and corresponding data sources | Data for this category comes from multiple systems, so `variables` must be used to associate the retrieval scope of different knowledge bases and cover all policy and early warning information |
| Concurrency Setting | Set 30-40 concurrency for 4c16g machines | Testing shows this configuration runs stably and avoids exhausting resources on a single node |
| API Access Configuration | Enable signature verification, set timeout to 600 seconds | Based on FastGPT v4.17.0 API security configuration rules, adapts to long-chain call requirements in emergency scenarios and ensures interface call security |
| Node ID Configuration | Assign a unique `nodeId` to each data access node | Ensures parameter passing between workflow nodes and rapid troubleshooting of errors |
| JSON Input Processing | Enable variable mapping mode and bind business fields | Adapts to parameter reading for structured documents such as material allocation slips, and enables accurate recall of policy and scheduling information |
| Single Search Limit | Retrieve the top 8 results | Balances information completeness and Q&A response speed, meets real-time requirements of emergency scenarios |

## Three Common Misconfigurations
- Workflow search results only cover documents from a single system, and cannot cover multi-source policy and early warning information from meteorology, hydrology, etc.: The `variables` configuration only binds a single knowledge base, and the multi-knowledge base association option is not enabled.
- High memory usage and service crashes occur on a 4c16g single node during operation: The concurrency setting exceeds the machine's carrying limit, and the value is not adjusted based on tested benchmarks.
- Empty or incorrectly formatted parameters are returned when accessing the workflow via API: The variable mapping in the JSON input field is not properly configured, and business fields are not bound to workflow parameters.

## How to Verify Successful Configuration
- Check the workflow's `variables` configuration interface, confirm that all required data source knowledge base tags have been checked, covering the multi-source data sources of this category.
- Run a single-node stress test, observe CPU and memory usage, confirm that the concurrency setting matches the machine's carrying range and no resource exhaustion occurs.
- Call the test API interface, pass simulated policy query parameters, and verify that the returned results include correct emergency documents and policy basis.
- View workflow running logs, confirm that each node with a `nodeId` runs normally, with no parameter passing failures or error messages.
