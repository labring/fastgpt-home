# Policy and Regulatory Basis Q&A for Flood Control, Disaster Prevention and Emergency Duty: Tool Calling and Plugins

## What the Data for This Category Looks Like
The data for this category primarily comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Daily generated documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data updates occur daily; some real-time warning data has shorter update intervals. Document fields include rainfall and water level values, disaster severity levels, material stock levels, transferred and resettled population counts, disposal progress, and more. Some documents require associated dimension information such as administrative divisions and disaster types.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins Workflow
Data sources are spread across multiple specialized systems. Tool calling must support parallel API calls to retrieve cross-system rainfall, water level, and disaster data.
Daily documents have varied structures. Tool calling must adapt to parsing documents with different field formats. This prevents extraction failures caused by field mismatches.
Data updates daily, and some real-time data requires frequent pulling. Tool calling must configure reasonable call intervals and timeout thresholds. This avoids exceeding system interface limits.
Consultation and warning materials need rapid integration of multi-source data. Tool calling must support batch extraction and structured output. This meets the short-cycle response requirements of emergency response work.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Supports automatic matching of tools required for the current scenario, adapting to dynamic call demands for multi-source data |
| `functionCall` | enabled | Forces tools to return results in a structured format, facilitating rapid organization and reuse of policy basis |
| Single tool call timeout | 600 seconds | Covers interface response times across multiple specialized systems, preventing critical data loss from timeouts |
| Number of parallel tool calls | 3 | Adapts to concurrent request limits of grassroots emergency systems, preventing interface rate limiting |
| Tool call result cache duration | 30 minutes | Balances real-time performance of emergency data and call frequency, aligning with the daily update rhythm of data |

## Three Common Configuration Errors
- When configuring a model connected via OneAPI, entering the token key directly and calling the tool returns empty results. The cause is failure to correctly associate the model's API address and key verification rules in tool configuration, leading to authentication failure.
- Tool calls to a local MCP Server fail to connect properly. The cause is failure to configure port mapping and access whitelists for the local service, preventing FastGPT from accessing the locally deployed tool service.
- Text content extraction tools prompt format errors. The cause is failure to adapt to the multi-field structure of emergency documents. The tool only extracts a single paragraph of content, and fails to associate corresponding disaster type and administrative division fields.

## How to Verify Successful Configuration
- Initiate a simulated call, check if the tool's returned results include structured fields from multi-source emergency data. Verify that `toolChoice` and `functionCall` configurations are active.
- View tool call logs, confirm that parallel call counts and timeout times match preset configurations. Ensure there are no frequent timeout or rate limit error messages.
- Import a typical emergency duty log document, verify that the text extraction tool can correctly extract core fields such as disaster severity level and material quantity.
- Test cross-system data integration, confirm that results returned by different tools can be correctly spliced into the format required for consultation materials.

The values provided are common starting points and should be measured against the reader's own samples.
