# Policy and Regulatory Basis Q&A for Flood Prevention, Disaster Mitigation and Emergency Duty: Citation Source and Traceability

This document is written based on FastGPT v4.17.0.

## What This Category's Data Looks Like

Daily documents for this category include duty logs, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data mainly comes from meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. The update frequency is daily. Most document fields include rainfall and water level data, danger level, material allocation quantity, and personnel evacuation information. Units involve millimeters, cubic meters, number of people, and the like. Some documents need to be linked with real-time monitoring data and historical response records.

## Constraints on Citation Source and Traceability from These Data Characteristics

The data characteristics of this category impose multiple constraints on the citation traceability process.
Multi-source heterogeneous data sources require the traceability link to associate metadata from different systems such as meteorological, hydrological, and emergency command systems, to avoid limited traceability scope.
The daily update frequency requires traceability to quickly match the latest released versions of policies and regulatory bases, to ensure the timeliness of cited content.
Documents include specific numerical values with units such as rainfall, water levels, and material quantities. Traceability must accurately bind the original source of the corresponding field, to avoid disconnect between values and their sources.
The fast pace of emergency response requires the traceability link to control time consumption, balancing traceability accuracy and response generation speed.

## Configuration Recommendations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | The common knowledge base chunk size for this category is 5000 tokens. This setting can fully retain the core content of policy documents and real-time monitoring data, avoiding truncation of key traceability information |
| `responseData` | Enable source display | Emergency duty requires clear citation of policy and regulatory basis sources to facilitate quick compliance verification |
| `detail` | Full metadata | Need to display the publishing organization, update time, and associated hydrological/meteorological monitoring fields of the source document to meet precise traceability requirements |
| Number of recalled sources per single query | Top 5 | Control the total amount of traceability information, avoid excessive content occupying response space, and adapt to the fast-paced emergency response scenario |
| Source display format | Label system name + document title | Aligns with the decentralized nature of data sources for this category, facilitating quick location of original records from corresponding systems |

## Three Common Configuration Mistakes

- Symptom: `quote type error` occurs when calling the knowledge base Q&A plugin. Cause: The input citation variable format does not meet system requirements, and the metadata fields of the corresponding source document are not correctly bound.
- Symptom: No citation sources for the knowledge base are displayed in the response. Cause: The source display switch corresponding to `responseData` is not enabled, or the `detail` parameter configuration does not enable metadata return.
- Symptom: The `quoteMaxToken` is set to 1500 tokens, but chunk content exceeding the length is still recalled. Cause: The knowledge base chunk size is set to 5000 tokens, and the recalled chunks are not truncated, or the system does not perform secondary verification on the recalled content according to the configured `quoteMaxToken`.

## How to Verify Configuration Validity

- Submit a test query containing flood prevention policy keywords. Check if the response includes traceable source information.
- View the metadata fields in the returned results. Confirm that necessary information such as source system and release time is included, and verify that the `detail` parameter configuration takes effect.
- Adjust the value of `quoteMaxToken`. Test recalled content of different lengths, and confirm that the system limits the total token count of cited content according to the configuration.
- Input a citation variable with incorrect format. Verify that the `quote type error` prompt is triggered, and confirm that the error handling configuration takes effect.
