# Survey and Design Policy and Regulatory Basis Q&A: Model Access and Configuration

## What the data for this category looks like
Policy and regulatory basis data for the survey and design field mainly comes from formal specifications, approval documents and regulatory requirements released by the Ministry of Housing and Urban-Rural Development, provincial and municipal housing and urban-rural development authorities, and industry associations. Data updates are synchronized with the release of new policies, with no fixed cycle. Most documents are structured text with document numbers, release dates and effective clauses. Some documents include fields such as applicable project scope, qualification requirements and approval processes. Units are identified by "article", "paragraph", "subparagraph", document number year or regional code. Some specifications include design drawing attachments.

## What constraints these characteristics impose on the "model access and configuration" link
The structured nature of policy documents requires retrieval results to accurately match clause levels, and prevent irrelevant content from being included to maintain answer accuracy. The non-fixed update rhythm requires that when synchronizing the knowledge base, the consistency of data sources accessed by the model must be verified to ensure the latest version of documents is called. Some specifications include attached drawing supplements, which requires configuration to support visual content parsing. The authority of official documents requires that model outputs strictly quote original text fragments, and appropriate context and quotation limits must be configured to avoid generating unsupported interpretations.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Survey and design policy documents are mostly long texts, requiring sufficient original text fragments to support accurate answers |
| `maxTokens` | 2000–3000 token | Single-round responses need to cover complete policy clause explanations to avoid truncating key content |
| `quoteMaxToken` | 1500 characters | Strict quoting of original policy text fragments is required, limiting the total length of quoted content |
| `temperature` | 0.1–0.3 | Policy explanations need to remain rigorous, reducing randomness to ensure content aligns with official statements |
| `vision` | Enabled | Some design specifications include attached drawings, requiring support for image content parsing |
| `AIPROXY_API_ENDPOINT` | Fill in the actual interface address based on the deployment environment | Adapt to the network path requirements for model calls |
| `AIPROXY_API_TOKEN` | Fill in the access key for the corresponding model | Complete identity verification for model access |

## Three common errors
- Phenomenon: The model displayed in the chat interface does not match the configured model, or an API key invalid prompt is shown. Cause: `AIPROXY_API_TOKEN` was not filled correctly, or the key permissions do not match the configured model.
- Phenomenon: Responses do not quote original policy text, or quoted content exceeds the scope of clauses. Cause: `quoteMaxToken` was not configured, or the value was set too large, causing the model to generate unsupported content.
- Phenomenon: Policy documents with attached drawings cannot be parsed correctly. Cause: The `vision` configuration was not enabled, or model dependencies supporting image decoding were not deployed.

## How to confirm the configuration is complete
- Enter the model configuration page, verify that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the parameters in the deployment documentation.
- Initiate a test query containing specific policy clauses, check whether the response quotes original text fragments from the knowledge base, and whether the quotation length meets expectations.
- Upload a policy document with attached drawings, verify that the model can correctly identify and interpret the content in the images.
- Adjust the `temperature` parameter and initiate a test, confirm that the rigor of the response changes as expected with the parameter.

The values provided are common starting points and should be evaluated against the reader's own samples.
