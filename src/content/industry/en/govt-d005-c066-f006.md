# Policy and Regulatory Basis Q&A for Advanced Chemical Materials: Citation Sources and Traceability

## What this category’s data looks like
Policy and regulatory basis data for the advanced chemical materials category comes from multiple sources. These include normative announcements from industry regulatory authorities such as the Ministry of Industry and Information Technology and the National Development and Reform Commission, national and industry standard texts, and supporting implementation documents from local industry and information technology departments.

Update data when new policies launch, with no fixed cycle. Most single documents follow this structure: "document number - issuing entity - effective date - scope of application - technical clauses - attachments". Fields include policy number, issuing unit, effective time, applicable advanced chemical material categories, specific technical indicator requirements. Some documents include quantitative parameters and unit descriptions.

## What constraints do these characteristics impose on citation sources and traceability
Use clear document numbers, clause IDs and effective dates to precisely match specific clause positions in original policy documents during traceability.
When chunking multi-chapter, multi-clause documents, retain metadata such as clause numbers. This ensures traceability results directly correspond to specific paragraphs in the original text.
Set up knowledge base synchronization to pull latest documents on demand. This avoids returning expired policy basis, since policies update without a fixed cycle.
Retain original units and numerical values when displaying traceability results. This prevents information distortion for documents with attached quantitative parameters.

## Three common configuration mistakes
- Traceability results only show the document name without specific clause annotations. This occurs because clause number fields of policy documents are not retained during chunking, making it impossible to match specific citation positions.
- The knowledge base variable passed when invoking the workflow does not take effect, and returned traceability results come from the default knowledge base. This occurs because the binding logic for variable references is not configured in the workflow’s knowledge base search node, so the node does not read the passed knowledge base parameters.
- The interface returns the citation list first and then the answer, with no way to adjust the order. This occurs because the synchronous output mode for answers and traceability results is not enabled in the configuration, and the default pre-citation list return logic is triggered.

## How to confirm the configuration is correct
- Initiate a test query to verify that the traceability information attached to the answer includes specific policy document numbers, clause numbers and release dates.
- Call the workflow interface with a custom knowledge base identifier, check that returned traceability results only come from the specified knowledge base.
- View the `responseData` field in the interface return, confirm that it contains complete traceable document chunk content and associated parameters.
- Adjust the `quoteMaxToken` parameter value, verify that the original text length displayed in traceability changes with the parameter.
