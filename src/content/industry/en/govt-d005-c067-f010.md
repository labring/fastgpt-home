# Fertilizer and Pesticide Policy and Regulatory Basis Q&A: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Fertilizer and pesticide policy and regulatory basis data is sourced from official public channels of relevant government departments, including the Ministry of Agriculture and Rural Affairs, Ministry of Industry and Information Technology, State Administration for Market Regulation, and others.
The data includes regulatory texts, industry standards, public announcements, and related documents.
Update frequency aligns with the release of new policies and revision of standards, with no fixed cycle.
Documents contain fields such as document number, issuing authority, effective date, scope of application, and specific clauses.
Some files include structured tables, such as pesticide residue limit tables and fertilizer nutrient content standard tables.
Field units include document number identifiers, date formats, and measurement values.

## Constraints Imposed on Knowledge Base Retrieval and Recall by These Data Characteristics
The above data characteristics impose three constraints on the retrieval and recall link.
First, documents from multiple departments have inconsistent formats. Perform uniform format preprocessing before import to avoid vector generation bias caused by format differences.
Second, documents contain technical terms and structured fields. Retrieval must balance semantic matching and precise field matching to avoid missing key information.
Third, there is no fixed update cycle. Regularly sync the latest data sources, and prioritize returning the most recently effective policy entries during recall to avoid returning expired content.
Additionally, structured table data requires additional multi-vector configuration to enable precise retrieval of table content.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Fertilizer and pesticide policy texts contain a large number of technical terms. A threshold that is too low will introduce irrelevant policy clauses, while a threshold that is too high will miss matching valid older supporting policies |
| `limit` | `Top 8 entries` | Policy texts are usually lengthy. Too many results will exceed the context window, while too few will miss associated supporting policy documents |
| `searchMode` | `semantic + keyword` | Policy texts have both semantically related expressions and clear identifiers such as document numbers and keywords (e.g., "pesticide registration", "fertilizer production license"). The mixed mode balances precise matching and semantic recall |
| `usingReRank` | `Enabled` | Policy texts contain many paraphrased expressions. Reranking corrects initial recall sorting bias and prioritizes entries most relevant to the query |
| `datasetSearchUsingExtensionQuery` | `Enabled` | User queries may use colloquial expressions (e.g., "What compound fertilizer can be used for wheat planting"). Extended queries link to technical terms in official policies (e.g., "wheat-specific compound fertilizer registration standards") |
| `collectionIds` | `Bind to the dedicated fertilizer and pesticide policy knowledge base collection` | Isolate policy data across different categories to avoid recalling regulatory content from unrelated fields, and ensure retrieval results are accurately focused |

## Three Common Configuration Mistakes
- Symptom: When accessing FastGPT v4.17.0 via an internal network Nginx reverse proxy, uploading fertilizer and pesticide policy PDF files fails with a 502 status code. Cause: The Nginx file upload size limit is not configured. Fertilizer and pesticide policy files often include attachments or high-resolution scanned copies, and the default Nginx limit causes upload interruptions.
- Symptom: When calling the API to add content to the knowledge base, an invalid parameter error is returned. Cause: The dedicated knowledge base collection ID corresponding to `collectionIds` is not specified correctly. Fertilizer and pesticide policy data must be bound to a dedicated collection. Failure to specify this will cause data to be written to the wrong knowledge base space.
- Symptom: After importing a policy file containing nutrient content tables, specific values in the tables cannot be recalled. Cause: Multi-vector support for table columns is not enabled in the knowledge base settings. Structured tables in fertilizer and pesticide policy documents require this configuration to be enabled separately to generate corresponding vectors and enable table content retrieval.

## How to Verify Successful Configuration
- Upload a fertilizer and pesticide policy PDF file, wait for indexing to complete, enter a relevant query in the chat window, and check if matching policy clauses and corresponding document numbers are returned.
- Call the knowledge base add API, pass test policy data, check if the returned result includes a success flag and that the data appears in the specified `collectionIds` collection.
- Import a policy file containing nutrient content tables, check the multi-vector support status of table columns in the knowledge base settings, and confirm it is enabled.
- View system retrieval logs, check if parameters such as `similarity` and `limit` match the configured values, and that there are no abnormal errors.
