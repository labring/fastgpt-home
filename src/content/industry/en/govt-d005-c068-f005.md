# Policy and Regulatory Basis Q&A for Pharmaceutical Distribution: Tool Calling and Plugins

## What the data for this category looks like
Pharmaceutical distribution policy data is primarily sourced from official announcement pages and normative documents published by the National Medical Products Administration, the Ministry of Commerce, and provincial and municipal medical insurance bureaus. Updates take effect in real time when new regulatory policies are released, with no fixed update cycle. Each policy document includes structured fields such as policy document number, issuing authority, effective date, applicable business formats (drug wholesale, retail chain, cold chain transport, etc.), and core implementation clauses. Most documents are in PDF or structured web page format, and some include penalty clauses and detailed compliance requirement entries.

## Constraints on Tool Calling and Plugins
Because policy data includes clear document numbers, effective dates, and applicable business format fields, tool calling must support using these fields as retrieval criteria. This prevents returning expired or irrelevant policies that do not match the current scenario.
All data sources are official regulatory authorities, so plugins must connect exclusively to official data source interfaces. Unauthorized third-party data sources must not be accessed.
Policy updates have no fixed cycle, so tool calling cache duration must be set to no more than 72 hours. This ensures the timeliness of retrieval results.
Additionally, policy documents have multiple hierarchical levels and lengthy content. Tool calling must support extracting result fragments by clause to avoid context overflow that disrupts model inference.

## Three Common Misconfigurations
- Tool call parsing errors occur, with logs showing `Tool call Parser` related errors. The manifestation is invalid tool call results returned. The cause is that the content field returned by the inference model includes nested think tags, which do not meet the format requirements of the tool call parser.
- Long error codes are returned when forwarding models via aiproxy, with no valid response content for interface requests. The cause is that a valid aiproxy secret key was not filled in the FastGPT plugin configuration, resulting in request interception.
- A cross-origin error occurs when externally calling `api/v1/chat/completions` via fetch, with CORS-related errors displayed in the browser console. The cause is that FastGPT has not configured cross-domain allowed request headers, or the frontend has not forwarded interface requests via a proxy.

## How to Confirm Proper Configuration
- Send a question containing "2024 pharmaceutical wholesale enterprise regulatory policies" to the platform, and confirm that the tool call log shows the pharmaceutical distribution policy retrieval tool was triggered.
- View the tool call return results, and confirm that the results include exclusive fields such as policy document number, applicable business format, and effective date, matching the data structure of pharmaceutical distribution policies.
- Call the `api/v1/chat/completions` interface, and confirm that no cross-domain related errors occur.
- Send a simulated request with nested think tags for testing, check whether a tool call parsing error is triggered, verifying that the format verification configuration is effective.
