# Policy and Regulatory Basis Q&A for Hazardous Chemicals Storage and Transportation: Workflow Orchestration

## What this category of data looks like
Hazardous chemicals storage and transportation policy data mainly comes from official standards and announcements released by the Ministry of Emergency Management’s Hazardous Chemicals Supervision Department and the Ministry of Transport, as well as national regulations including Regulations on the Safety Management of Hazardous Chemicals and Rules for Road Transportation of Dangerous Goods. The update cycle is to synchronize updates within 1 to 2 weeks after major policy revisions.

## What constraints these characteristics impose on workflow orchestration
Policy data has clear effective dates and document numbers, so workflows must add timeliness verification steps to avoid calling expired policy content.
Documents are split by storage and transportation links, so workflows must configure branch judgment nodes to match policy requirements for different scenarios.
Data comes from official authoritative sources, so workflows must configure trusted data source verification to filter non-official content.
Most fields are quantitative indicators, so workflows must configure numerical matching rules to ensure returned control requirements align with the problem scenario.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Data source configuration | Only bind official public hazardous chemicals policy documents from the Ministry of Emergency Management and the Ministry of Transport | Matches the authoritative source requirements for hazardous chemicals storage and transportation policies |
| Branch trigger rules | Split nodes by warehousing, road transportation, and terminal loading and unloading | Corresponds to the structure of policy documents split by storage and transportation links |
| Timeliness verification | Filter policy content with effective dates earlier than the current date | Avoids calling expired policy documents |
| Variable binding | Bind policy document number and effective date fields in `variables` | Matches the structured fields of policy documents |
| Single search limit | Top 3 entries | Corresponds to the limited number of policy entries for a single scenario |
| Context length | 800–1200 characters | Adapts to the core content length of a single policy document |

## Three common configuration mistakes
- Phenomenon: Workflow returns an "Access denied for us" type error. Cause: Failed to configure the trusted data source whitelist for database connections, and directly called non-official hazardous chemicals policy documents, resulting in permission verification failure.
- Phenomenon: Global variables do not update the policy effective date during tool calls. Cause: Did not enable the variable synchronization switch in the `variables` configuration, causing workflow nodes to fail to read the latest policy time parameters.
- Phenomenon: Branch nodes do not correctly match storage and transportation scenarios. Cause: Did not configure trigger conditions according to the segmented links of policy documents, causing branch judgment logic to not align with policy requirements.

## How to confirm the configuration is complete
- Run the workflow, input a question for a specific storage and transportation scenario, and check whether the policy document number and effective date of the returned result match the official documents.
- View workflow logs to confirm that branch nodes correctly trigger corresponding policy content based on the input storage and transportation link.
- Test global variable updates, and check whether policy parameters in `variables` are synchronized after tool calls.
- Check the data source configuration to confirm that only official authorized hazardous chemicals policy document links are included.
