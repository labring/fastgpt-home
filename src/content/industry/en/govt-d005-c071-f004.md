# Policy and Regulatory Basis Q&A for Power Generation Groups: Workflow Orchestration

## What this category of data looks like
Policy and regulatory basis data for power generation groups mainly comes from group official websites, internal OA regulatory libraries, and standard power industry documents issued by the State-owned Assets Supervision and Administration Commission and the National Energy Administration. Data updates follow a regular monthly sync mechanism, with incremental updates completed within 72 hours after a major policy is released. Each individual policy document includes fields such as regulatory number, issuing authority, effective date, applicable unit type, clause content, and attachments. Clauses are layered by article, paragraph, and sub-paragraph. The effective date uses the YYYY-MM-DD format, and the applicable scope marks specific power production types.

## What constraints these characteristics impose on the "workflow orchestration" link
Multi-source data access requires the workflow to configure cross-data source synchronization nodes covering official websites, internal libraries, and external regulatory documents. High-frequency updated policy data requires the workflow to embed scheduled trigger synchronization nodes to avoid using expired policy clauses. The multi-field document structure requires the workflow to configure filter nodes based on applicable unit type and release time to accurately recall target policies. The long-text clause structure requires the workflow to support clause-by-clause split recall to avoid overloading context loading in a single run, and also needs to support associated retrieval of attachments.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Variable retrieval rule | Prioritize reading from `variables`, use plugin default values if no match | Adapt to multi-source variable requirements of power generation group policy data, avoid QA failures caused by missing parameters |
| Batch execution node | Trigger by regulatory category, no more than 20 items per execution | Power generation group policy documents are categorized by production type; batch execution controls single-node load to avoid timeouts |
| Long text concatenation | Concatenate by clause segments, no more than 1500 characters per segment | Aligns with the clause structure of policy documents, avoids exceeding context window limits |
| Variable count configuration | Bind the `nodeId` of the corresponding category node, increment by 1 per call | Accurately record the number of QA calls for specific categories such as thermal power policies |
| Timeout threshold | 600 seconds | Policy retrieval requires loading multi-source data, reserve sufficient time for document parsing and matching |

## Three common mistakes
- Phenomenon: Parameters are not read from specified variables during plugin calls, fixed default values are always used. Cause: The variable priority reading rule is not configured in the workflow, and hard-coded parameters of the plugin are directly bound.
- Phenomenon: The number of policy entries returned by the batch execution node is far lower than the set upper limit. Cause: The data source is not filtered according to the regulatory categories of the power generation group such as wind power and photovoltaic, resulting in failure to recall policies of some categories.
- Phenomenon: The call count statistics field for category questions is empty. Cause: The `nodeId` of the corresponding category node is not bound, causing the count node to fail to match the target QA workflow.

## How to confirm the configuration is correct
This verification action is based on FastGPT v4.17.0 version specifications:
- Trigger a thermal power policy QA, check the workflow log to confirm that parameters are read from `variables`, and no fixed default values appear.
- Run the batch execution node, check that the number of returned policy entries matches the number of data sources in the corresponding category.
- Call the thermal power policy category question 10 times, check whether the value of the variable count field matches the number of calls.
- Submit a long policy text concatenation task, confirm that no truncation error appears in the output, and it meets the context window requirements.
