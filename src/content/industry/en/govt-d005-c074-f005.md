# Policy and Regulatory Basis Q&A for State-owned Asset Management Companies: Tool Calling and Plugins

## What this category of data looks like
Data for policy and regulatory basis Q&A for state-owned asset management companies comes primarily from two sources.
First, normative documents issued by the State-owned Assets Supervision and Administration Commission of the State Council and local state-owned assets supervision departments.
Second, internal state-owned asset management rules and approval process specifications of the company.
Update schedules follow the pace of policy releases. Synchronization is completed within 1 to 3 working days after major regulatory policies are issued.
Most individual documents use structured clause formatting. They include fields such as document number, issuing authority, effective date, applicable scenario, core clauses, and supporting forms.
Some documents attach unit specifications for asset statistics and approval processes. Approval time limits use working days as the unit. Asset size uses ten thousand yuan as the measurement standard.

## Constraints on Tool Calling and Plugin Workflows
Data sources cover central and local state-owned assets regulatory documents, and are dispersed. Tool calling must support filtering retrieval scope by regulatory hierarchy. This prevents confusion between cross-level policies.
Most documents use structured clause formatting. Tool calling must accurately match clause numbers and core content. Broad retrieval may return irrelevant fragments.
Documents include metadata fields such as effective date and applicable scenario. Plugins must carry this metadata during calls. This ensures policy basis can be traced during Q&A.
Approval time limits use working days as the unit, per document specifications. Tool calling must uniformly convert natural days to working day counting. This prevents response deviations.
Update schedules adjust dynamically with policy releases. Plugins must support incremental synchronization of the latest policy documents. This avoids using expired data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Bind to the dedicated state-owned assets policy retrieval function | State-owned asset management policy Q&A requires calling dedicated tools to ensure retrieval accurately matches state-owned assets regulatory documents |
| `functionCall` | Force tool calling before generating a response | Policy Q&A must be based on accurate policy documents. Prohibit generating responses without basis, to meet compliance requirements |
| Tool call trigger condition | Trigger when the user's question includes a state-owned assets policy document number or regulatory matter | Most state-owned assets management policy questions involve specific document numbers or regulatory scenarios. Precise triggering reduces invalid calls |
| Metadata carrying configuration | Synchronously carry document number, effective date, and applicable hierarchy | Policy Q&A requires tracing the basis. Carrying metadata ensures responses can be traced, and meets state-owned assets regulatory compliance requirements |
| Timeout handling strategy | Set a 300-second timeout, return a preset policy query failure prompt on timeout | Most state-owned assets policy documents are long text, and retrieval takes a long time. 300 seconds covers most retrieval scenarios. The timeout prompt prevents users from waiting too long |
| Result filtering rule | Filter expired policies with effective dates earlier than the current date | State-owned assets policies are time-sensitive. Expired policies must not be used as response basis |

## Three Common Misconfigurations
- Symptom: Results returned after tool calling include non-state-owned assets policy general content, and lack metadata such as document number and effective date.
  Cause: The `toolChoice` configuration is not set to bind the dedicated retrieval function, and metadata carrying configuration is not enabled. This leads to broad retrieval scope.
- Symptom: After triggering tool calling, the system directly generates an AI response without starting the retrieval process.
  Cause: The `functionCall` mode is not set to mandatory calling, or the trigger condition is configured incorrectly. The tool is not started for policy-related questions.
- Symptom: GPU memory usage grows rapidly when calling the reranking tool, and abnormal usage appears on multiple GPU nodes.
  Cause: The single recall limit for the reranking tool is not configured. Loading too many document fragments at one time exhausts video memory resources.
