# Policy and Regulatory Basis Q&A for State-owned Capital Operation Companies: Deployment and Upgrade

## What this category of data looks like
Policy and regulatory basis data for state-owned capital operation companies primarily comes from officially published public documents of the State-owned Assets Supervision and Administration Commission of the State Council and local state-owned assets supervision institutions, plus internal operation management systems and subsidiary company supervision rules released by the group.
The data update rhythm is monthly additions of regulatory documents and quarterly revisions of internal systems.
Most documents are official formal papers with fixed document numbers, issuing units, effective dates, and applicable scopes. They use articles, clauses, and items as hierarchical structures.
Fields include document number, issuing entity, effective time, and clause content. There is no unified fixed character length limit. Some long documents can reach dozens of pages.

## What constraints do these characteristics impose on the deployment and upgrade process
The above data characteristics impose clear constraints on the deployment and upgrade process.
The fixed metadata format of official and internal formal documents requires configuring matching metadata extraction rules during deployment. This ensures accurate filtering by document number and effective date during retrieval.
The monthly/quarterly update rhythm requires adapting incremental synchronization storage links during upgrades. This avoids resource usage from full indexing.
The feature of many long documents with clear hierarchical structures requires adjusting long text indexing configurations during deployment. This ensures reasonable content splitting.
The permission grading attribute of internal documents requires configuring secure and compliant storage and database connection parameters. This prevents sensitive information leaks.

## How to set the configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
|---|---|---|
| `STORAGE_S3_ENDPOINT` | Access address of the intranet object storage for state-owned assets | Policy documents of state-owned capital operation companies are mostly stored in intranet object storage. Matching the endpoint configuration of internal storage is required |
| `MONGODB_URI` | Authentication connection string for intranet MongoDB, including read and write permissions | Metadata and index data of policy documents must be stored in intranet databases to ensure data security |
| `REDIS_URL` | Connection address for intranet Redis, set with an expiration time of 600 seconds | Cache retrieval results of policy documents to reduce resource consumption from repeated indexing and adapt to high-frequency retrieval needs |
| `DB_MAX_LINK` | 20–30 | State-owned capital operation companies have a large number of policy documents. Limiting database connection counts prevents resource exhaustion |
| `FILE_TOKEN_KEY` | Key generated according to internal document encryption rules | Internal policy documents involve state-owned assets supervision information. A dedicated token key must be configured to ensure access security |

## Three common error cases
- Phenomenon: Image OCR results for some policy documents are empty. Regulatory clauses in images cannot be extracted during retrieval. Cause: Only indexing rules for text content were configured during deployment. The OCR processing module for embedded images was not enabled.
- Phenomenon: After upgrading the version, published agents cannot load historical policy documents. Cause: Compatible logic for metadata storage was not synchronized during the upgrade. The old index data structure does not match the new version.
- Phenomenon: Retrieval requests return too many irrelevant results. Response time exceeds the threshold. Cause: The connection count limit for `DB_MAX_LINK` was not configured correctly. This causes the database to return excessive redundant data.

## How to confirm the configuration is complete
- Perform a connection test for the intranet object storage. Confirm that the address configured in `STORAGE_S3_ENDPOINT` can read and write policy documents normally.
- Check database connection logs. Confirm that the connection string configured in `MONGODB_URI` can establish normal read and write sessions.
- Send a simulated retrieval request. Verify cache hit status. Confirm that the configuration of `REDIS_URL` takes effect normally.
- Check metadata extraction rules. Confirm that specified fields such as document number and effective date can be extracted from policy documents.
