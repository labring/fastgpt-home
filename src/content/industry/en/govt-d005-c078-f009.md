# Policy and Regulatory Basis Q&A for Urban Water Utilities: Model Integration and Configuration

## What this category of data looks like
Policy data for urban water utilities mainly comes from the official government platforms of the Ministry of Housing and Urban-Rural Development, the Ministry of Water Resources, and official websites of local water utility and housing and urban-rural development departments. Data is synced within 72 hours after a new policy is released, and incremental content is synced when quarterly regulatory documents are updated. Documents are structured policy entries, including fields such as policy ID, document number, issuing body, effective time, applicable region, clause number, clause content, quantitative indicators and corresponding units. Most quantitative indicator units are water industry-specific units such as cubic meters per household per month, liters per person per day.

## How these characteristics create constraints for model integration and configuration
The characteristics of urban water utility policy data impose three core constraints on model integration and configuration:
1. Policies are divided by administrative region and updated frequently. Configuration must support filtering recalled context by region, and set an automatic knowledge base sync cycle to ensure data timeliness.
2. Clauses contain specialized quantitative units. The model must retain unit identification and verification during invocation to avoid unit confusion errors.
3. Documents include metadata such as document number and effective time. Configuration must enable metadata reference output to ensure traceable Q&A.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 characters` | Single clauses of urban water utility policies are relatively long. This setting accommodates context from multiple related policies, avoids truncating critical information, and adapts to the context processing limit of FastGPT v4.17.0. |
| `quoteMaxToken` | `1500 token` | This setting fully references the core content of policy clauses, ensuring traceable reference fragments during Q&A are detailed enough to cover quantitative indicators and units in clauses. |
| `temperature` | `0.1–0.3` | Policy Q&A must strictly follow the original text, and avoid generating content that deviates from the basis. A lower temperature improves answer rigor. |
| `AIPROXY_API_ENDPOINT` | Fill in the official access address according to the deployment environment | This matches the access specifications of the selected large model, ensuring normal request forwarding. |
| `AIPROXY_API_TOKEN` | Fill in the bound proxy key | This is used for identity verification, ensuring the security of access requests. |
| `toolChoice` | `none` | Policy Q&A does not require calling external tools, and answers are generated directly based on knowledge base content. |

## Three common configuration mistakes
- Phenomenon: An "access restricted" prompt appears when opening the configuration page in a browser, and model integration settings cannot be completed. Cause: The browser version used is not supported by FastGPT, or the browser has enabled strict privacy blocking rules.
- Phenomenon: Policy content recalled by the model loses unit information, leading to errors such as confusion between "water use quota" and "water consumption". Cause: A reasonable value for the `quoteMaxToken` parameter is not set, causing reference fragments to be truncated and losing critical unit fields.
- Phenomenon: Newly released water utility policies are not recalled after knowledge base synchronization, and Q&A results still use old version clauses. Cause: Automatic sync trigger rules are not configured, or the sync cycle is set too long to fail to pull the latest policy data in a timely manner.

## How to confirm the configuration is complete
- Initiate a Q&A test for water utility policies in a specific region, check if the returned results include metadata such as policy document number and effective time, confirming the metadata reference configuration is enabled.
- Submit a policy query covering different administrative regions, check if the recalled context only includes policy content from the corresponding regions, confirming the region filtering configuration is enabled.
- Manually trigger a knowledge base sync, wait for the sync to complete, then query newly released policies, confirming the automatic sync configuration is enabled.
- View the model call log, check if parameters such as `maxContext` and `temperature` of the request match the configured values, confirming the access parameter configuration is enabled.

The values provided are common starting points and should be measured against the reader's own samples.
