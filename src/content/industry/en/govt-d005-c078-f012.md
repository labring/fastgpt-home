# Policy and Regulatory Basis Q&A for Urban Water Services: Deployment and Upgrade

## What the data for this category looks like
Policy data for urban water services comes from official announcements of housing and urban-rural development, water resources, and ecological environment departments at all levels, plus internal institutional compilations from local urban investment water utilities. Updates align with the release of new policies. Stock policies are sorted and archived annually. Most documents are official papers with document numbers, including issuing entity, effective date, clause details, and scope of application. Fields include policy number, applicable scenario, execution standard, and penalty clauses. Units include cubic meters, daily water supply volume, and population covered, among others.

## What constraints these characteristics impose on the deployment and upgrade phase
Official policy documents are mostly long PDF and Word files, with many multi-page bulk files. During deployment, configure storage services that support large file chunked upload to avoid upload interruptions. Policy update frequency is irregular. During upgrade, support incremental data synchronization to reduce resource consumption from full reconstruction. Policy fields include specialized units. Pre-set field mapping rules during knowledge base import to avoid QA deviations caused by incorrect unit recognition. Policy texts from multiple sources require unified formatting; complete basic text cleaning configuration before deployment.

This configuration applies to FastGPT v4.17.0.

| `STORAGE_S3_ENDPOINT` | `http://minio.example.com:9000` or compliant cloud storage endpoint | Adapt to the bulk upload and large file storage needs of urban water service policy documents |

| `PG_URL` | `postgresql://pg_user:pg_pass@postgres:5432/fastgpt` | Store system configuration and user session data to ensure deployment stability |

## Three Common Misconfigurations
- Scenario: Docker local deployment fails to pull images, with error prompts "network unreachable" or "image does not exist". Cause: No domestic mirror acceleration source configured, or local network cannot access the official image repository.
- Scenario: When uploading large PDF policy documents, upload progress reaches 90% then prompts "offset out of range". Cause: Chunked upload threshold for the storage service corresponding to `STORAGE_S3_ENDPOINT` is not configured, or chunk size is set improperly.
- Scenario: Cannot find the text processing module after deployment. Cause: `ROOT_KEY` is not configured in environment variables with corresponding permissions enabled, or the deployment package did not fully load functional plugins.

## How to Confirm the Configuration Is Complete
- Run container status check commands to confirm all deployed service containers are running normally.
- Upload a single policy PDF document over 100 MB to confirm the upload process completes fully without error prompts.
- Call the built-in configuration connectivity verification interface to verify normal connections to databases, cache, and storage services.
- Enter the knowledge base management interface to confirm the text processing function module has loaded and can be enabled normally.
