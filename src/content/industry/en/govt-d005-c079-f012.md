# Policy and Regulatory Basis Q&A for Urban Gas: Deployment and Upgrade

## What the data for this category looks like
Urban gas policy and regulatory basis data mainly comes from official public documents of local housing and urban-rural development departments and urban administration bureaus, as well as internal operation and maintenance management systems of local urban investment gas enterprises. Data updates are triggered by new policy releases or local regulation revisions, with no fixed cycle. Most documents are in PDF or web page format, with structures including document number, issuing unit, effective date, applicable region, and clause text. Fields include geographic scope, clause number, and execution standard. The length of a single document ranges from thousands to tens of thousands of characters.

## What constraints do these characteristics impose on the deployment and upgrade phase
Because policy data sources are scattered and have no fixed update cycle, deployment must support multi-source batch import and incremental synchronization configuration to avoid full-volume duplicate processing. Single document length varies widely, so long text chunking and retrieval logic must be adapted to prevent context overflow. Execution standards differ across regional policies, so geographic filtering rules must be bound during retrieval to ensure returned results match the compliance requirements of the corresponding city. In addition, a large number of structured policy documents require dedicated storage configuration to ensure retrieval efficiency.

## How to set the configuration
This guide is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | Urban gas policy documents are mostly long-text PDFs, requiring external object storage to host a large number of uploaded files and avoid insufficient local disk space |
| `DB_MAX_LINK` | `800–1200 entries` | A single knowledge base needs to associate policy documents across multiple regions. Setting a reasonable upper limit covers all compliant files and avoids retrieval omissions |
| `REDIS_URL` | `redis://:custom password@127.0.0.1:6379/0` | Used to cache frequently retrieved policy clauses, reduce database query pressure, and adapt to multi-user concurrent access scenarios |
| `FE_DOMAIN` | `http://public IP of deployment server:3000` | Used to generate valid links for file access, ensuring the front-end interface can normally load policy document previews |
| `ROOT_KEY` | Custom complex string of at least 32 characters | Used for administrator permission verification, ensuring the security of knowledge base configuration and preventing unauthorized modification operations |

## Three common configuration errors
- Phenomenon: Calling the ollama model returns empty content with no clear error log. Cause: The local access address of ollama is not configured correctly, or the firewall blocks local communication on port 11434, causing FastGPT to fail to obtain model return results.
- Phenomenon: Accessing port 3000 of the deployment server results in a continuously loading blank page with no response in the browser. Cause: `FE_DOMAIN` is not correctly configured to the server's public IP or bound domain name, or the front-end container does not correctly map port 3000, causing front-end resources to fail to load normally.
- Phenomenon: Model testing fails after restarting the server, with abnormal return results. Cause: ollama and FastGPT containers are not started in the correct order, or the ollama service is not running continuously in the background, causing the model call link to be interrupted.

## How to confirm the configuration is complete
- Access the configured `FE_DOMAIN` address to confirm that the front-end interface loads normally and displays the login entry.
- Add the ollama model on the FastGPT model configuration page and initiate a test call to confirm that non-empty text results are returned.
- Upload an urban gas policy document to confirm that the file can be stored normally and associated for retrieval in the knowledge base.
- View the connection logs of `REDIS_URL` to confirm that there are no error messages about connection timeouts or authentication failures.
