# Policy and Regulatory Basis Q&A for Basic Chemical Industry: Tool Calling and Plugins

## What this category's data looks like
Data for basic chemical industry policy and regulatory basis comes mainly from official public documents issued by the Ministry of Emergency Management, the Ministry of Ecology and Environment, the Ministry of Industry and Information Technology, and local chemical park management authorities. The data update schedule is monthly additions of special policies, and quarterly updates of industry standard revision versions. The document structure is fixed, including policy document number, issuing authority, effective date, applicable chemical category scope, core compliance clauses, and penalty details fields. Field formats follow official document specifications, with no custom units or special format requirements.

## What constraints these characteristics impose on tool calling and plugins workflows
Policy documents are lengthy and contain multi-dimensional compliance clauses. Precise matching of policy document numbers and applicable chemical categories is required when calling tools, to avoid returning irrelevant content. Policy update frequency is high, so plugins must be configured with a scheduled synchronization mechanism to ensure the latest effective policy documents are returned during calls. The standardized document structure of official papers requires tools to prioritize extracting core clauses and effective date fields during parsing, rather than crawling full text. At the same time, policy compliance requirements and penalty fields must correspond to the production links of the basic chemical industry. Tool input parameters must clearly specify the production link type to narrow the return scope.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Plugin synchronization cycle | Every 7 days | Matches the monthly update frequency of basic chemical industry policies to ensure data timeliness |
| Tool call timeout | 300 seconds | Policy documents are lengthy, so sufficient time must be reserved for parsing and retrieval |
| Number of policies returned per request | Top 3 | Avoid returning excessive redundant content, focus on core compliance basis |
| Matching rules | Dual verification by policy document number and applicable chemical category | Ensure returned content is strongly related to specific basic chemical industry segments |
| `toolChoice` | Auto | Allow the model to independently select the most suitable policy retrieval tool to cover complex compliance Q&A scenarios |

## Three common mistakes
- Tool calls return empty results, and logs show input parameter fields are empty. The cause is that the applicable basic chemical industry category was not correctly specified as an input parameter, preventing the tool from matching the corresponding policy documents.
- After calling the plugin, the returned policy content is unrelated to the current production link. The cause is that the dual matching rule was not configured, and only keyword retrieval was used to return general chemical industry policies, without limiting the specific basic chemical industry segment.
- Tool call times out, returning a 504 status code. The cause is that the timeout duration was not adjusted. Basic chemical industry policy documents are lengthy, and the default timeout duration is insufficient to complete parsing and retrieval.

## How to confirm the configuration is complete
- Manually trigger a tool call, pass in the specified basic chemical industry category such as caustic soda production and a policy document number, and check whether the returned content includes the corresponding clauses.
- View the plugin synchronization log to confirm that a policy library update was completed within the last 7 days, ensuring the data is the latest version.
- Call the tool and observe the number of returned entries, confirming that only the top 3 eligible policy documents are returned, with no redundant content.
- Adjust `toolChoice` to manual specification, verify that the model can correctly call the preset policy retrieval tool without configuration errors.

The values provided are common starting points and should be measured against the reader's own samples.
