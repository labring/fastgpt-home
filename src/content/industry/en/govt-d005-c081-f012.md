# Policy and Regulatory Basis Q&A for Basic Chemical Industry: Deployment and Upgrade

This page applies to deployment and upgrade scenarios for FastGPT v4.17.0.

## Data characteristics for this category
The policy and regulatory basis data for the basic chemical industry mainly comes from industry normative documents, mandatory standards, and joint issuances released by the Ministry of Emergency Management, Ministry of Ecology and Environment, and Ministry of Industry and Information Technology. Data updates are triggered by the release of new policies or revisions of existing standards, with no fixed schedule. Document structures typically include policy document numbers, issuing authorities, effective dates, clause texts, and applicable sub-sectors such as fertilizers and rubber products. Fields include policy numbers, implementation standard numbers, and applicable scenario scopes. Units mainly use document number formats, date formats, and clause word counts. A single complete policy collection document can exceed 500 MB.

## Constraints imposed on deployment and upgrade workflows
Large volume and lengthy content of basic chemical policy documents increase concurrent connection requirements during the upload phase, and increase chunk processing pressure during retrieval. No fixed update schedule requires deploying scripts that can regularly synchronize external policy data sources. Upgrades must be compatible with field mapping rules from older knowledge bases. The precise matching requirement for sub-sector fields puts higher demands on knowledge base retrieval and recall configuration. Adaptation to multi-label classification indexing logic is needed to avoid generalized retrieval results.

## Configuration settings
| Configuration Item | Recommended Value | Rationale for This Value |
|---|---|---|
| `DB_MAX_LINK` | `120–180 items/minute` | Basic chemical policy documents have large per-document volume, leading to high database connection frequency during upload and retrieval. Matching the connection upper limit ensures stable concurrency |
| `REDIS_URL` | `redis://:custompass@localhost:6379/0` | Caches frequent policy retrieval results and user sessions to reduce repeated database query pressure, adapting to latency requirements of large document retrieval |
| `STORAGE_S3_ENDPOINT` | `http://192.168.10.20:9000` | Stores large-volume policy documents, adapting to high throughput requirements of local or private cloud storage |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit ASCII string` | Ensures access permission security for uploaded files, preventing unauthorized document downloads |
| `MONGODB_URI` | `mongodb://admin:securepass@localhost:27017/fastgpt?authSource=admin` | Stores policy knowledge base metadata and retrieval logs, enabling data persistence and traceability |

## Three common misconfigurations
- Uploading a basic chemical policy collection document larger than 500 MB results in a timeout error returned by the interface, but the background upload process runs normally, and the file appears in the list after a period of time. The cause is that the connection upper limit of `DB_MAX_LINK` is not adjusted, leading to database connection exhaustion during the upload process.
- After Docker deployment is completed, the built-in model cannot be called normally, and the interface prompts that the model is not configured. The cause is that the authentication parameters of `MONGODB_URI` are not filled correctly, causing model configuration information to fail to be read from the database.
- After changing the password and trying to restart the service, accessing the login page using the local area network IP fails. The cause is that `FE_DOMAIN` is not configured as the local area network access address, leading to incorrect binding of front-end resources and failure to load the page normally.

## How to confirm correct configuration
- Upload one basic chemical policy document larger than 300 MB, check that the upload progress has no timeout errors, and the document is normally displayed in the file list.
- Run the `docker ps` command, confirm that the Redis container bound to `REDIS_URL` is in running state, and there are no abnormal exit logs.
- Access the local area network address configured in `FE_DOMAIN`, after logging in, try to initiate a policy-related Q&A request, and confirm that there is no model configuration error prompt.
- Check the storage directory corresponding to `STORAGE_S3_ENDPOINT`, confirm that the uploaded policy documents are fully stored and there is no file damage.

The values given are common starting points and should be measured against the reader's own samples.
