# Policy and Regulatory Basis Q&A for Infrastructure Construction: Deployment and Upgrade

## What this category of data looks like
Data for infrastructure construction policy and regulatory basis comes from official announcements, industry standards, and normative documents published by the Ministry of Housing and Urban-Rural Development, the Ministry of Transport, the National Development and Reform Commission, and local housing and urban-rural development and transport authorities. Data updates happen in real time as new policies launch, and industry standards are revised annually or quarterly. Individual documents range from thousands to tens of thousands of characters, with fields including document number, issuing authority, effective date, applicable scenarios, and core clauses. Some files include supporting interpretation documents, and no unified fixed format applies to these materials.

## What constraints do these characteristics bring to the deployment and upgrade process
The inconsistent format, large individual file size, and non-fixed update cycle of infrastructure construction policy documents create multiple constraints for the deployment and upgrade workflow. During deployment, the parsing and preprocessing workflow must adapt to multi-source heterogeneous data to avoid text truncation or field parsing errors. Since policy updates follow no fixed schedule, the upgrade phase requires configurable, flexibly adjustable incremental synchronization scheduling rules to accommodate synchronization needs for temporarily issued policy documents. Policy fields vary across different regions, so configuration entrances for field mapping must be reserved during deployment to avoid compatibility issues with cross-regional policy data. Vector storage of large volumes of long documents consumes significant resources, so teams must evaluate the balance between storage capacity and retrieval performance during upgrades.

## How to configure the settings
The following configuration items apply to the deployment and upgrade workflow for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | Use a locally deployed replica set address or a connection string for a cloud service-hosted MongoDB instance | Infrastructure construction policy document data volume is large, and replica sets ensure read-write stability and data redundancy |
| `REDIS_URL` | Configure as a local Redis instance on port 6379, with memory allocation of no less than 1000 MB | High-frequency retrieval of policy clauses and user sessions requires caching; sufficient memory reduces retrieval latency |
| `STORAGE_S3_ENDPOINT` | Use the access address of a local MinIO instance or the endpoint of a cloud object storage service | Long documents and supporting interpretation files require reliable object storage to ensure data persistence |
| `DB_MAX_LINK` | Set to 200–300 | Policy documents have many associated references; a reasonable connection limit prevents database connection exhaustion |
| `FE_DOMAIN` | Configure as the public or internal domain name of the deployed service | Used to generate permissioned file access links to ensure secure distribution of policy documents |

## Three common configuration mistakes
- Symptom: After building the knowledge base, the number of returned results differs between the public network version and local deployments. Cause: The `DB_MAX_LINK` parameter is not uniformly configured; the local deployment connection limit restricts the number of associated clauses retrieved.
- Symptom: The team management function cannot be enabled normally for local deployments. Cause: Basic parameters related to `ROOT_KEY` and team permissions are not correctly configured, or the team management service switch is not enabled.
- Symptom: Data synchronization fails after multi-node deployment. Cause: `STORAGE_S3_ENDPOINT` and `REDIS_URL` parameters are not uniformly configured; storage and cache addresses of each node are inconsistent, preventing data sharing.

## How to confirm the configuration is complete
- Log in to the FastGPT management backend, check the data source connection status of the knowledge base, and confirm that all policy document parsing tasks show as successful.
- Initiate a policy-related query, verify that the number of retrieved results matches expectations, and adjust the corresponding parameters until retrieval requirements are met.
- Test the team management function's creation and permission allocation process, and confirm that members can normally access the specified policy knowledge base.
- For multi-node deployment scenarios, check the logs of each node to confirm that the storage and cache service connection status is consistent, with no synchronization errors.
