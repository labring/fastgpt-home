# Policy and Regulatory Basis Q&A for Commodity Trading: Citation Sources and Traceability

## What the data for this category looks like
Policy and regulatory basis data for commodity trading originates from official announcements of national and local development and reform, commerce, customs and other relevant departments, as well as self-disciplinary norms of national commodity trading industry associations. Updates follow no fixed cycle, and are synced to the knowledge base immediately when new policies are released. Most documents are clause-style texts, with clear fields for policy document numbers, issuing authorities, and effective dates. Content covers trade category scope, tariff rates, regulatory requirements and similar topics. Units include tons, yuan per ton, percentage, regulatory codes and others.

## Constraints on Citation Sources and Traceability
Policy sources are scattered across multiple department websites, with varying page structures across platforms. Multi-source crawling logic must be adapted to fully extract document content. Since updates have no fixed cycle, trigger-based updates must be used. This avoids redundant storage or missed latest policies caused by scheduled full synchronization. Since documents include clear identifying fields such as document numbers and effective dates, the traceability link must prioritize extracting these fields as core traceability basis. Relying solely on text matching cannot meet precise traceability requirements. Since policies are segmented by trade category, vector chunking must be performed per category. This prevents invalid recall interference across categories.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Commodity trading policy documents are mostly long clause-style texts. Complete policy clauses must be retained for traceability |
| `responseData` | Return only document number, issuing authority, effective date | The core traceability identifiers for trade policies are official document numbers and effective information. Redundant content can be omitted |
| `detail` | Enabled | Policy original text snippets and official source links must be displayed to meet traceability requirements |
| Single search limit | Top 6 results | Covers policies for the same category released by multiple departments, preventing missed key basis |
| Chunk length | 1500–2000 characters | Adapts to the clause length of policy documents, avoiding splitting that disrupts policy logic |
| Reranking | Reverse chronological order by release date | Prioritize displaying the latest policies, aligning with the timeliness requirements of trade policies |

## Three Common Misconfigurations
- Issue: The knowledge base citation module in chat responses pops up an "invalid traceability information" error. Cause: The `responseData` parameter is not configured to return required fields such as policy document numbers and issuing authorities. The system cannot generate compliant traceability links and identifiers.
- Issue: Redundant content such as "knowledge base search input" or "knowledge base search response" appears in responses. Cause: Intermediate step output is not disabled in the workflow search node, or non-core display content is not filtered via the `detail` parameter.
- Issue: The code running plugin prompts missing dependencies during execution. Cause: Third-party library dependencies required for commodity trading policy analysis are not configured in the FastGPT code running environment, leading to execution failure.

## How to Verify Successful Configuration
- Submit a policy inquiry targeting a specific commodity category. Check if the traceability module below the response displays policy document numbers, issuing authorities, and official source links.
- Enter the workflow configuration page. Confirm that the "output intermediate steps" switch for the search node is turned off, to avoid displaying redundant citation content.
- Adjust the `quoteMaxToken` parameter to a smaller value. Verify that the length of the policy text referenced in the response matches expectations, confirming the parameter takes effect.
- Upload a test policy document, trigger a knowledge base update. Confirm that the new document displays normally in search results, verifying that the update configuration works correctly.
