# Policy and Regulatory Basis Q&A for Engineering Consulting Supervision: Document Parsing and Chunking

## What the data for this category looks like
The policy and regulatory basis data for engineering consulting supervision mainly comes from normative documents, industry standards, and project-specific supervision rules issued by the Ministry of Housing and Urban-Rural Development and local housing and urban-rural development authorities. Update cycles align with policy revision timelines, and routine supplementary notices are released alongside industry developments. Most documents follow formal official document formats, including fields such as chapters and clauses, tabular supervision requirements, document numbers, and effective dates. Some documents include on-site supervision point location diagrams. Units involved include project area, construction duration, and cost budget.

## What constraints do these characteristics impose on document parsing and chunking
The hierarchical chapter structure of formal official documents requires chunking to match clause logic, and avoid splitting complete statements of a single supervision requirement. Tabular content carries core supervision basis such as qualifications and workflows. Parsed results must retain table structures and field associations. Attached on-site point location diagrams must be accurately identified. Otherwise, on-site execution requirements linked to corresponding clauses cannot be matched. Metadata such as document numbers and effective dates must be used as retrieval anchors, so they must be extracted during parsing. Individual policy documents cover large spans of content. The length of individual chunks must be limited to ensure contextual integrity during retrieval.

## Configuration Settings
The following configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Engineering supervision policy clauses are mostly short paragraphs. This range preserves the integrity of individual supervision requirements and avoids contextual breaks |
| `chunkSplitter` | Split by chapter and clause | Most engineering policy documents have hierarchical structures. Splitting by chapter and clause matches user retrieval habits for locating policy clauses |
| `customPdfParse` | Enabled | Engineering policy documents often include tables and point location diagrams. Enabling custom PDF parsing preserves table structures and image association information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Individual supervision standard documents have large page counts. Sufficient parsing time is required to avoid timeout failures |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Some project supervision policy collection files have large file sizes. This setting accommodates large file upload requirements |
| `chunkSettingMode` | Manual configuration | Engineering policy documents have special structures. Manual configuration allows flexible adjustment of chunking rules to adapt to different types of policy documents |

## Three Common Configuration Mistakes
- After uploading a PDF policy file that includes point location diagrams, the parsed result has no image content and messy table formatting. The cause is that the `customPdfParse` configuration is not enabled. The default parsing rules do not adapt to tables and image elements in engineering documents.
- After exporting a knowledge base from an old server and importing it to a new server, the chunking results differ from the original environment. The cause is that only the knowledge base files in Excel format were packaged, and parsing configuration parameters such as `chunkSettingMode` were not exported synchronously. The new environment cannot reuse the original chunking rules.
- The table dataset option cannot be selected during the knowledge base construction process. The cause is that the table parsing function is not enabled in the platform basic settings, or the table dataset entry in the current version is not properly activated.

## How to Verify Correct Configuration
- Upload a typical supervision policy file that includes tables and point location diagrams, and check whether the table structures and image annotations in the parsed result are complete.
- Manually adjust the `chunkSize` parameter, perform multiple parsing runs on the same file, and compare whether the chunking results match the expected character length range.
- Export the parsing configuration file of the current knowledge base, import it to a test environment, and re-parse the same file to verify that the chunking rules are consistent.
- Upload a single maximum-size policy file, and confirm that no timeout prompt appears during the parsing process.
