# Policy and Regulatory Basis Q&A for Engineering Consulting Supervision: Deployment and Upgrade

## What the data for this category looks like
The policy and regulatory basis data for the engineering consulting supervision field mainly comes from official documents released by the Ministry of Housing and Urban-Rural Development, housing and urban-rural development authorities of various provinces and cities, and industry associations. It includes supervision specifications, bidding and tendering policies, quality control details, etc. Most documents are in PDF or official web page format, with fields including document number, issuing authority, release date, applicable scenario, core clauses, supplementary provisions, etc. The document number format uniformly follows the pattern of “Jianshi [Year] XX No.”. Some local implementation details mark the applicable administrative region scope. Policy updates follow no fixed cycle; local implementation details are updated every quarter to once a year.

## What constraints these characteristics impose on deployment and upgrade links
The official sources and format differences of engineering consulting supervision policy data require deployments to adapt to multi-source file parsing logic, and configure standardized data cleaning rules for the fixed document number format. Local implementation details have regional characteristics, so the knowledge base must support dividing retrieval scopes by province and city to avoid cross-regional policy confusion. Policy updates follow no fixed cycle, so upgrade links must configure incremental synchronization tasks that only update newly added or revised policy documents, preventing full re-import from occupying resources. The mixed PDF and web page document format requires parsing plugins to support text extraction and original document structure restoration for both formats.

## How to set configurations
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Basis for This Value |
| --- | --- | --- |
| `DB_MAX_LINK` | `200 links` | Engineering consulting supervision policy documents often include external links to multiple related documents, requiring sufficient jump support |
| `MONGODB_URI` | For local deployment, fill in `mongodb://localhost:27017/fastgpt` | Stores metadata, vector indexes and retrieval logs of policy documents, adapting to large text storage needs |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | Stores original PDF and web files of policies, adapting to the persistence requirements of mixed formats |
| `FILE_TOKEN_KEY` | 32-character random string | Generates access tokens for policy documents, restricting unauthorized access to internal policy files |
| `REDIS_URL` | `redis://localhost:6379/0` | Caches frequently retrieved policy Q&A results and incremental synchronization task status, reducing response latency |

## Three common mistakes
- A 403 status code is returned when calling a third-party policy data source interface after deployment. Cause: `FILE_TOKEN_KEY` is not configured correctly, and a legitimate document access token is not generated, resulting in failed interface authentication.
- The `packages/plugins/register` directory cannot be found when deploying with Docker. Cause: The plugin initialization command is not executed in the deployment script, or the mounted volume does not correctly map the plugin directory.
- Text input lags occur when there are many workflow nodes. Cause: The caching strategy for `REDIS_URL` is not configured, resulting in ineffective caching of page status, and a large number of node renderings occupying front-end resources.

## How to confirm configuration is complete
- Execute `docker logs fastgpt` to view container logs, and confirm that there are no error logs for MongoDB and Redis connections.
- Upload a PDF file of engineering supervision policy, verify that the file can be parsed normally and stored in the configured object storage path.
- Initiate a test question related to policies, confirm that the retrieval results include matching policy clauses, and that external links can jump normally.
- View the running logs of the incremental synchronization task, confirm that newly added policy files can be automatically identified and imported into the knowledge base.
