# Policy and Regulatory Basis Q&A for Construction Machinery: Workflow Orchestration

## What this category of data looks like
Data for policy and regulatory basis related to construction machinery mainly comes from public announcements issued by the Ministry of Housing and Urban-Rural Development, the Ministry of Industry and Information Technology, and special equipment supervision departments at provincial and municipal levels. The update schedule is adjusted irregularly when new regulations are released, with no fixed cycle. Documents follow official document formats, and include fields such as policy document number, issuing authority, effective date, applicable equipment types (such as lifting machinery, tunneling machinery), clause content, implementation standards, and penalties. Most field units use equipment-related standard units such as MPa, operating hours, and sets.

## What constraints do these characteristics impose on the workflow orchestration link?
The characteristic that policy data is classified by equipment type requires the workflow to bind equipment type parameters via variables, to accurately route to the corresponding policy subset. There is large variation in document length. Long clauses must be split appropriately to adapt to context windows and prevent information truncation. Irregularly updated data sources require the workflow to integrate regular synchronization nodes, to ensure retrieved content uses the latest versions. The multi-field document structure requires extracting key fields as filter conditions during the retrieval step, to narrow the retrieval scope.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Chunk length | 800–1200 characters | The length of single clauses in construction machinery policies mostly ranges from 500 to 1500 characters. This value avoids truncation across clauses |
| Maximum search results per request | Top 10 | The number of policy documents is relatively fixed. Excessive results will exceed the context window |
| Maximum context size | 6000 characters | Adapt to the interpretation needs of a single complete policy document |
| `variables` | Bind by equipment type | Construction machinery policies are classified by equipment types such as lifting machinery and tunneling machinery. Pass equipment type parameters via variables |
| `nodeId` | Bind synchronization node ID | Trigger synchronization tasks via the node ID when regularly pulling policy updates |
| Parallel flow settings | Enable multi-branch parallelism | Support simultaneous connection to multiple policy retrieval nodes, adapt to parallel queries for multiple equipment types |

## Three common mistakes
- The workflow cannot perform cyclic policy verification. The cause is that the cycle trigger node is not configured. The workflow runs only once by default.
- Exported conversation records only show the last 6 entries. The cause is that the full context export parameter is not configured. Only recent interaction content is retained by default.
- Tool calls work normally in debug mode but throw errors in runtime mode. The cause is that the correct policy data source `variables` is not bound in the production environment. Parameters differ between debug and production environments.

## How to confirm the configuration is correct
- Manually trigger the workflow, input questions about different construction machinery types, and verify that the workflow routes to the corresponding policy retrieval node and returns matching content.
- Simulate a policy update, trigger the synchronization node bound to `nodeId`, and check whether the latest published policy files are pulled from the data source.
- Enable parallel flow testing, initiate 3 queries for different equipment types at the same time, and confirm that all branches execute and return results.
- Export the complete conversation record, verify that the number of exported entries matches the number of input questions, with no content truncation.
