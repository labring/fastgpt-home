# Policy and Regulatory Basis Q&A for Construction Machinery: Document Parsing and Chunking

Reference only; verify against the target FastGPT release and deployment documentation.

## What the Data for This Category Looks Like
The data for this category mainly comes from public documents such as construction machinery supervision policies, industry technical standards, and construction permit specifications released by the Ministry of Housing and Urban-Rural Development, the Ministry of Industry and Information Technology, and local housing and urban-rural development departments, as well as equipment operation and maintenance guidelines compiled by industry associations. Documents are primarily in Word and PDF formats, with some supporting quota documents released in Excel format. The structure includes document numbers, issuing authorities, effective dates, chapters, clauses, and appendix parameter tables. Document updates follow national policy revisions and industry standard iterations, with single-file size varying widely.

## Constraints Imposed on Document Parsing and Chunking
The mixed multi-format nature, clear chapter hierarchy, and large number of parameter tables in construction machinery policy documents impose multiple constraints on document parsing and chunking.
Large standard compilation files in Word format have significant file size. Direct parsing consumes substantial computing resources, which slows processing speed.
Excel-format supporting quota documents often use one row as one independent policy entry. The default chunking logic may merge multiple rows into a single chunk, breaking entry independence.
If parameter tables in documents are split across different chunks, subsequent Q&A fails to associate complete equipment parameters and policy requirements.
For some long documents, chapter titles are bound to main text. Chunking must retain contextual connections to avoid clause breaks.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `15 MB` | Matches the common size range of construction machinery policy documents, allows import of large standard compilation files, and avoids upload blocking |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Covers the full parsing time of large Word-format policy files, avoids interruptions before parsing completes |
| `chunkSplitter` | Paragraph + custom delimiter | Matches the chapter and clause separation logic of policy documents, and adapts to the single-row single-entry structure of Excel files |
| `chunkSize` | `800–1200 characters` | Ensures each chunk contains complete policy logic, avoids over-splitting that causes contextual breaks, or over-length that leads to ambiguous semantics |
| `chunkSettingMode` | Custom mode | Supports separate chunking rule configuration for different file formats such as Word, PDF, and Excel, adapting to the mixed document characteristics of this category |
| `customPdfParse` | Enabled | Retains the parameter table structure in PDF-format policy documents, avoids table content disorder caused by default parsing |

## Three Common Mistakes
- Scenario: When uploading a 10+ MB Word-format industry standard file, parsing progress stalls for more than 10 minutes before a timeout error pops up. Cause: The `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations are not adjusted. Default parameters are insufficient to support complete parsing of large files.
- Scenario: After importing Excel-format equipment quota files, the chunk preview shows three consecutive policy entries merged into a single chunk. Cause: The `chunkSplitter` is not configured to use row or custom delimiter. The default chunking logic splits by paragraph, which cannot adapt to the single-row single-entry structure of Excel files.
- Scenario: After uploading multiple construction machinery policy PDF files, the applicable equipment range corresponding to each file cannot be accurately extracted. Cause: `customPdfParse` is not enabled. The default parsing logic cannot retain independent metadata for each file, leading to mixed content from different files during chunking.

## How to Verify Correct Configuration
- A single Word-format industry standard file of around 10 MB is uploaded. Upload progress and parsing logs are checked to confirm no timeout or upload failure prompts appear.
- Excel-format equipment quota test files are imported. The chunk preview interface is checked to confirm each policy entry corresponds to one independent chunk.
- `customPdfParse` is enabled. A PDF policy file with parameter tables is uploaded, and parsed content is checked to confirm the row and column structure of the table is complete and not disrupted.
- `chunkSize` is set to 800–1200 characters. Chunk previews are checked to confirm each chunk contains complete policy clauses, and no chapter titles and main text are split into different chunks.

The values listed above are common starting points. They should be evaluated against relevant samples.
