## What constraints these characteristics impose on the "tool calling and plugins" workflow
Because policies have region-specific clauses and timeliness requirements, tool calling must support parameter filtering based on applicable region and effective date to ensure returned policy content matches the current scenario. Structured policy fields require tool calling to accurately extract metadata such as policy document number and effective date for result traceability and compliance verification. The wide range of individual document lengths requires tool calling context processing capabilities to adapt to policy texts from hundreds to thousands of characters, avoiding truncation of core implementation rules. At the same time, the frequency of policy updates requires plugins to support configuration items for regular synchronization of official data sources to ensure the timeliness of Q&A content.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to scenarios where tool calls are triggered randomly in policy Q&A, no manual function specification required |
| `functionCall` | Allow automatic invocation | Policy Q&A requires frequent retrieval of structured policy fields; automatic invocation improves response efficiency |
| Regional policy matching priority | Prioritize the top 3 policy entries applicable to the current region | The number of region-specific policies is limited; prioritize returning locally effective compliance content |
| Context window upper limit | 8000 token | Adapts to individual policy documents with thousands of characters, avoiding truncation of core implementation rules |
| Data source synchronization cycle | 7 days | Matches the update rhythm of routine policy reviews to ensure the timeliness of Q&A content |
| Metadata extraction toggle | Enabled | Policy document number and effective date need to be extracted for result verification, meeting compliance traceability requirements |

## Three common mistakes
- Scenario: When calling a locally deployed large model, even if the tool call related switches are enabled, the policy data query tool still cannot be triggered. Cause: The tool call protocol of the local model does not adapt to the `functionCall` format requirements of FastGPT, and cannot correctly parse tool call parameters.
- Scenario: When a general account KEY is configured as the aggregated BASE_URI, the returned policy content does not distinguish between applicable regional scopes. Cause: No context parameters for region filtering are bound, and applicable region information of the current scenario is not passed during tool calling.
- Scenario: When calling a document parsing tool in a workflow to process policy documents, field empty or timeout errors occur. Cause: The context window upper limit adapted to long-text policy documents is not set, and the processing threshold is exceeded during tool calling.

## How to confirm the configuration is complete
- Initiate a policy query with clear regional attributes, and check whether the returned result includes exclusive policy clauses of the corresponding region.
- After triggering tool calling, check the system log to see if extracted metadata fields such as policy document number and effective date are included.
- Upload a single long-text policy document to confirm that no truncation or timeout errors occur during tool calling.
- Wait for the configured data source synchronization cycle to end, and check whether the latest policy entries are automatically updated.
