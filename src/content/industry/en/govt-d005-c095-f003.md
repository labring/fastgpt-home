# Policy and Regulatory Basis Q&A for New Energy Development: Multi-turn Dialogue and Prompts

## What Data for This Category Looks Like
The data for this category comes primarily from publicly released new energy development policy documents, industry standards, and project filing specifications issued by the National Energy Administration and provincial and municipal development and reform commissions. Data documents follow official document formatting, including fields such as policy document number, issuing authority, effective date, applicable region, core clauses, and associated documents. Updates occur on an irregular cycle: national-level policies are revised irregularly as the industry develops, local policies are adjusted based on regional development progress, and synchronization updates are completed within 24 hours after core policies are released.

## Constraints on Multi-turn Dialogue and Prompts From These Characteristics
Long text data in official document formatting requires that multi-turn dialogue retain context for key fields such as policy document numbers and effective dates to avoid vague references. The irregular update cycle requires that the dialogue actively verify the timeliness of current policies. When a party references old policy clauses, the latest version content must be provided. The presence of applicable region fields requires that prompts guide clarification of the project's deployment region to match corresponding local policies. The long text structure results in a large amount of content retrieved in a single call, so the effective length of the context window must be limited to avoid redundant information interfering with dialogue logic.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bound to the user's project ID to maintain session uniqueness | Used to associate the current dialogue's historical context, ensuring consistency of policy references across multi-turn dialogues |
| `messages` | Retain policy reference snippets from the first 20 turns of dialogue | New energy policy documents are often long; excessive history will occupy the context window. 20 turns covers the user's complete consultation logic |
| `variables` | Store the effective date and region code of the currently applicable policy | Used to pass global parameters across multi-turn dialogues, quickly matching local policies for the user's region |
| Maximum Context Window | 8000–12000 token | New energy policy documents are often long. FastGPT v4.17.0 supports this window limit, covering core policy clauses retrieved in a single call and historical dialogue content |
| Single Retrieval Limit | Top 3 entries | New energy policy-related documents have strong relevance; the top 3 entries cover the core clauses and associated documents required by the user |
| Query Optimization | Enabled, optimize queries for region + policy type | User questions often omit the region or policy document number; optimization enables accurate retrieval of corresponding documents |

## Three Common Configuration Mistakes
- Symptom: A 400 status code (no body) is returned when calling database tools to query policy data. Cause: Global parameters for database connections are not configured in `variables`, causing the dialogue call to fail to pass correct connection information.
- Symptom: Previously saved global variables cannot be loaded during multi-turn dialogue. Cause: `chatId` is not bound to the user session, causing the system to fail to associate variable storage for the corresponding session.
- Symptom: Returned policy clauses do not include effective date annotations. Cause: The prompt does not require referencing the policy's effective date field, and the region and date matching logic is not enabled.

## How to Verify Proper Configuration
- One can initiate a multi-turn dialogue including region and policy type, and check whether the dialogue context retains previously referenced policy document numbers.
- Database tools can be called to query policy data, and the returned results can be confirmed to match the region parameter bound to the current session.
- The context window length can be adjusted, and it can be verified that long-text policy documents can be retrieved normally without truncation.
- Historical dialogue loading can be triggered, and it can be confirmed that global parameters in `variables` can be restored normally.

The values provided are common starting points and should be measured against the reader's own samples.
