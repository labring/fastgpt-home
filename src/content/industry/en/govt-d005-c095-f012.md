# Policy and Regulatory Basis Q&A for New Energy Development: Deployment and Upgrade

## What the data for this category looks like
The policy and regulatory basis data for new energy development comes primarily from officially published documents of national development and reform commissions, national energy administrations, and energy authorities of various provinces and cities. New policy releases trigger data updates, with no fixed cycle. Individual documents include fields such as policy title, document number, issuing authority, release date, main text clauses, and supporting attachments. Some files include supplementary information like applicable regions, industry categories, and validity periods. Document lengths vary widely, from thousand-word management regulations to hundred-word notices.

## What constraints these characteristics impose on deployment and upgrade
Wide variation in policy document lengths means chunking and vector encoding long documents uses more server resources. Deployments require matching reasonable storage and computing configurations. Differences in policy formats across multiple sources require configuring unified preprocessing rules during deployment to adapt to documents with varying numbers and structures. The lack of a fixed update cycle requires supporting incremental synchronization upgrade logic to prevent service interruptions from full reconstruction. Some policies include supplementary fields for regions and industry categories. Deployments must reserve index space for these fields to ensure accurate retrieval and filtering.

| `ROOT_KEY` | `Custom key string with a complexity of no less than 16 characters` | Ensures the security of system background operations, preventing unauthorized modification of knowledge base configurations and data export |
| `FILE_TOKEN_KEY` | `Custom 32-character random string` | Used to encrypt access links for knowledge base attachments, ensuring the security of attachment downloads |

## Three Common Configuration Mistakes
- Server memory continues to rise, and OOM errors are triggered at fixed times each day. Cause: The `DB_MAX_LINK` parameter is not adjusted according to the length characteristics of new energy policy documents, leading to too many documents imported in a single batch and exhausting the database connection pool.
- A `MongoServerError: The dollar ($) p` error is thrown during plugin loading, and plugin confirmation cannot be completed. Cause: The MongoDB 4.4.29 version is incompatible with FastGPT v4.17.0, causing conflicts in partial syntax parsing.
- When importing a knowledge base across instances, only a single CSV file is generated, and the original multi-file classification structure cannot be retained. Cause: The association parameters between `FILE_TOKEN_KEY` and object storage are not correctly configured, causing attachment files to not be exported synchronously with the knowledge base.

## How to Verify Correct Configuration
- Batch import 10 new energy policy documents of different lengths, check that server memory usage remains stable, and no OOM errors are triggered.
- Connect to the configured `MONGODB_URI`, verify that the number of database connection pool connections does not exceed the set maxPoolSize value.
- Export the current knowledge base, check that attachment files are generated synchronously with knowledge base entries, with no missing or abnormal formats.
- Attempt to access the background management interface after modifying `ROOT_KEY`, verify that unauthorized access is successfully blocked.

The values given are common starting points and should be measured against the reader's own samples.
