# Policy and Regulatory Basis Q&A for Non-Ferrous Metal Smelting: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Data for policy and regulatory basis Q&A in the non-ferrous metal smelting field comes primarily from public announcements. These announcements are issued by the national Ministry of Industry and Information Technology, Ministry of Ecology and Environment, Ministry of Emergency Management, and local industry and information departments. The data also includes industry standard documents released by the China Nonferrous Metals Industry Association.
The platform adds data to the library within seven working days after a new policy is released. A full regular update of the policy library runs once per month.
Most individual documents are official formal papers with document numbers. Their structure includes the issuing body, effective date, applicable smelting categories, core compliance clauses, and attached indicators. Fields include policy number, applicable scope, and quantitative indicator units (such as ten thousand tons per year production capacity, mg/m³ emission concentration).

## Constraints for Multi-turn Dialogue and Prompt Engineering
Policy documents have long text and professional terminology. This requires multi-turn dialogue to maintain consistent professional expression across context, and avoid repeated misinterpretation of compliance clauses.
Policy update rhythms are not fixed, but the cycle for adding new policies to the library is clear. Prompts must support dynamic calls to newly added policy entries, and cannot rely on static caching.
Different smelting categories correspond to exclusive policies. Multi-turn dialogue must identify specific categories mentioned by users such as copper, aluminum, lead-zinc, and automatically filter non-matching policy content.
Quantitative indicators come with dedicated units. The dialogue flow must associate the correct unit when extracting data, to avoid unit mix-up errors.

## Configuration Settings

| `chatId` | Bind a unique string identifier to user sessions | Multi-turn dialogue uses `chatId` to associate context, ensuring data isolation across different user sessions, in compliance with FastGPT v4.17.0 session management rules |
| `messages` | Retain the most recent 8–10 rounds of dialogue content | The context for non-ferrous metal policy Q&A mostly consists of professional terminology and category information. 8–10 rounds cover conventional continuous questioning scenarios, and avoid context overflow |
| `variables` | Inject smelting category and language parameters for the current session | Pass categories mentioned by users such as copper, aluminum, lead-zinc, and specify output language via `variables`, to improve the accuracy of policy recall and responses |
| Maximum context length | `8000–12000 characters` | A single policy document can be several thousand characters long. Multi-turn dialogue must accommodate 3–5 rounds of context. This range balances recall volume and response speed |
| Similarity threshold | `0.78–0.85` | Policy clauses are expressed precisely. This threshold filters low-match irrelevant policies, and avoids confusion of compliance requirements across different categories |
| Single search limit | `Top 5–7 entries` | The number of policies in the non-ferrous metal field is relatively concentrated. Too many entries exceed context capacity, while too few may miss critical clauses |

## Three Common Misconfigurations
- Symptom: After uploading local non-ferrous metal smelting policy files, corresponding clauses cannot be recalled during dialogue, and empty results are returned. Cause: No reasonable document chunk length is configured. Long policy files are truncated, losing critical compliance clauses, so they cannot match user questions.
- Symptom: During continuous questioning, subsequent responses forget previously mentioned smelting categories or core policy information. Cause: `chatId` is not correctly bound, or context storage function is not enabled, so session context is not retained.
- Symptom: Prompt output is in Chinese, but the business requires English formatting, or recall results do not return in the specified language. Cause: No language parameter is injected via `variables`, or the prompt does not explicitly specify output language requirements.

## How to Verify Proper Configuration
- Launch three consecutive questions that include smelting categories and core policy clauses. Check whether subsequent responses reference previously mentioned key information, to confirm the context storage function works correctly.
- Upload a local non-ferrous metal smelting policy file, launch a targeted question. Check whether the recall result includes the corresponding content from the uploaded file, to confirm file loading configuration is active.
- Modify the smelting category in the question. Check whether recalled policy clauses only match the specified category, to confirm category filtering configuration works correctly.
- Run cross-user session tests. Check whether dialogue data from different users does not show cross-session association, to confirm session identifier configuration is active.
