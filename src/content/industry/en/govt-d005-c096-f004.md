# Policy and Regulatory Basis Q&A for Non-Ferrous Metal Smelting: Workflow Orchestration

## What Data for This Category Looks Like
Non-ferrous metal smelting policy and regulatory basis data primarily comes from official announcements of the Ministry of Industry and Information Technology, Ministry of Ecology and Environment, and Ministry of Emergency Management, as well as industry standards released by the China Nonferrous Metals Industry Association. Update frequency follows policy releases, with no fixed cycle.
Document structure includes document number, effective date, applicable smelting process clauses, and other content. Fields cover policy category, emission limits, production capacity requirements, safety standards, and more. Units include tons, milligrams per cubic meter, kilowatt-hours, and other industry-specific metrics.
This scenario’s workflow configuration is implemented using FastGPT v4.17.0.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
These characteristics impose the following constraints:
- Policy sources are scattered and formats are inconsistent. First match the corresponding topic knowledge base via question classification to avoid cross-category retrieval interference.
- Documents are lengthy and include specialized units. Validate field and unit consistency during result processing to prevent matching errors.
- Data updates have no fixed cycle. Configure a scheduled synchronization node to maintain knowledge base content timeliness.
- Policy applicability varies by smelting process. Configure independent retrieval paths for different question branches.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Question classification rules | Divided by policy topic | Non-ferrous metal smelting policies fall into three categories: environmental emissions, production capacity control, and work safety, which match dedicated knowledge bases |
| Single recall limit | Top 8 entries | Core clauses of policy documents are usually concentrated in early retrieval results; 8 entries cover complete core content |
| Timeout setting | 600 seconds | Policy document parsing requires loading full text; avoid interrupting processing due to insufficient duration |
| Document chunk length | 800–1200 characters | Adapt to the lengthy clause structure of non-ferrous metal policy documents, ensuring core information remains intact after chunking |
| Variable storage | `variables` | Store classified question types and current uploaded file identifiers for subsequent calls by unified processing nodes |
| Node aggregation | Enabled | Only retain the final aggregated policy basis results, hide intermediate step outputs |

## Three Common Configuration Mistakes
- Symptom: After the workflow runs, the interface displays multiple intermediate AI outputs instead of only the final aggregated result. Cause: The node aggregation configuration item is not enabled, and no result aggregation step is configured to uniformly process all branch outputs.
- Symptom: The document parsing step loads previously uploaded policy documents instead of only processing the currently uploaded file. Cause: The `variables` field is not used to store the current uploaded file identifier, and no historical file parameter filtering is configured before parsing.
- Symptom: The workflow execution returns a timeout error and fails to complete policy document retrieval and processing. Cause: The timeout setting duration is insufficient, and it does not adapt to the full loading and parsing requirements of non-ferrous metal policy documents.

## How to Verify Correct Configuration
- Upload a non-ferrous metal smelting policy document, trigger the workflow, and check if it is automatically classified to the corresponding topic knowledge base node.
- View the workflow run logs, confirm that only the final aggregated policy basis results are displayed, with no intermediate AI output fragments.
- Upload multiple policy documents of different topics, check that the parsing step only loads the currently uploaded file and does not introduce historical documents.
- Adjust the timeout setting duration, verify that the workflow can fully process long documents, and confirm that the configuration adapts to document length requirements.
