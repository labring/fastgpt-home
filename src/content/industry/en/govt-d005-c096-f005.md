# Policy and Regulatory Basis Q&A for Non-Ferrous Metal Smelting: Tool Calling and Plugins

## What this category of data looks like
Official announcements and industry-specific specifications from the Ministry of Industry and Information Technology, the Ministry of Ecology and Environment, the Ministry of Emergency Management, and local industry and information technology departments form the main source of policy and regulatory basis data for non-ferrous metal smelting. Updates to this data occur when official policies are released, with no fixed cycle. Core national standards are revised every 1 to 2 years. Each document includes fields such as release document number, issuing authority, effective date, applicable scenarios, and clause details. Policies related to energy consumption and emissions include clear units, such as kilograms of standard coal per ton and milligrams per cubic meter.

## What constraints these characteristics impose on the tool calling and plugins link
Tool calling must include parameter checks for policy timeliness and compliance, based on the document number and effective date fields of policy documents, to avoid returning expired or inapplicable clauses. Plugins must align unit formats when calling external systems, per the clear unit fields included in policy documents, to prevent data parsing errors. A scheduled synchronization plugin must be configured to regularly pull newly released policy documents, due to the lack of a fixed update cycle for this data. Tool calling must limit the number of recalled clauses, given the structure of long documents with multiple clauses, to avoid context overflow and ensure the accuracy and readability of responses.

## How to set the configuration
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios for policy Q&A, automatically selects matching policy query or data synchronization tools |
| `functionCall` | `enabled` | Supports precise calling of tools for policy clause extraction, compliance verification, and other functions, covering core needs of specific scenarios |
| Plugin scheduled synchronization cycle | `7 days` | Core national standards for non-ferrous metal smelting policies are revised every 1 to 2 years, and local regulations are updated at a lower frequency. A 7-day synchronization cycle balances timeliness and resource usage |
| Policy recall limit | `top 3` | A single policy document contains multiple clauses. Limiting the number of recalled clauses avoids context overflow and ensures responses focus on core content |
| Unit verification switch | Enabled | Fields such as energy consumption and emissions in policies have clear units. Enabling verification prevents returned data from mismatching the unit format required by the business |

## Three common configuration mistakes
- Issue: When nesting workflows, the child workflow does not return complete policy data. Cause: Key parameters such as policy type and effective time are not passed through in the parent workflow, causing the child workflow to fail to accurately match target data.
- Issue: An `Error: write EPROT` error occurs when calling an external policy interface. Cause: The HTTPS connection parameters of the plugin are not configured correctly, resulting in protocol verification failure during data transmission.
- Issue: When using `functionCall` to extract policy clauses, key fields are not returned correctly. Cause: The range of recalled policy clauses is not limited, causing context overflow and truncation, resulting in key fields being filtered out or lost.

## How to confirm the configuration is complete
- Submit a policy query request that includes effective date and document number, check whether the returned results filter out expired or inapplicable policy documents, to confirm that the parameter verification function is working.
- Trigger a scheduled synchronization task, check whether there are records of newly pulled policy files in the plugin operation logs, to confirm that the synchronization cycle configuration is correct.
- Call the `toolChoice` automatic mode, observe whether the tool calling link automatically selects the matching policy query plugin, to confirm that the automatic selection function is working properly.
- Test the unit verification switch, enter a query term that includes units, check whether the returned results align with the unit format required by the business, to confirm that the verification function is working.
