# Policy and Regulatory Basis Q&A for Nuclear Power Operations: HTTP Interfaces and External Systems

## What this category of data looks like
Nuclear power operations policy and regulatory basis data mainly comes from publicly available compliance documents released by the National Energy Administration and nuclear power industry standardization organizations, as well as annual compliance update documents internal to nuclear power operation entities. Data update cycles fall into two categories: public policy documents are revised and released annually or quarterly, while internal compliance documents are updated quarterly alongside business process adjustments. Document structures uniformly include fields such as policy document number, issuing authority, effective date, applicable unit type, and compliance clause content. Effective dates use the YYYY-MM-DD format. Clause content is organized in single paragraphs of no more than 2000 characters each. Some cross-chapter documents include hierarchical clause numbering.

## What constraints these characteristics impose on HTTP interfaces and external systems
Mixed public and internal data sources require interfaces to be configured with differentiated authentication rules to prevent unauthorized access to internal compliance documents. Differences in update cycles require interfaces to support filtering incremental data by release time to reduce invalid request volume. Hierarchical document structures and fixed fields require interface return data to strictly map to internal system field naming conventions to avoid data parsing errors. The highly compliance-focused nature of nuclear power policies requires interfaces’ authentication and data transmission processes to meet industry security standards. Single return data volume must also be controlled to avoid information overload during compliance reviews.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer nuclear power operations exclusive access key` | Differentiate access permissions for internal and public data sources, comply with nuclear power industry compliance requirements |
| `variables` | `Map policy document number and effective date to internal system fields` | Align with field naming rules of existing nuclear power operation systems to avoid data mapping errors |
| `responseData` | `Return the first 8 matching policy clauses` | Control single return data volume to adapt to nuclear power policy compliance review processes |
| Single search limit | `Top 10 entries` | Limit the number of search results to avoid returning too many non-core clauses |
| Maximum context | `1200–1500 characters` | Adapt to the average length of nuclear power policy clauses to avoid context overflow |
| Timeout period | `600 seconds` | Cover time requirements for long document retrieval and compliance verification |

## Three common misconfigurations
- Invoking the interface returns an empty `responseData` field. The cause is incorrect configuration of the `variables` field mapping rule, which prevents matching internal nuclear power policy fields.
- The interface returns a 400 status code. The cause is an incorrect `Authorization` parameter format, missing the Bearer prefix or having an invalid secret key.
- After upgrading to FastGPT v4.17.0, historical policy documents cannot be retrieved. The cause is not enabling the incremental sync configuration for filtering by update time, which results in only pulling the latest released policy content.

## How to confirm the configuration is correct
- Invoke the interface using a test nuclear power policy document number, check if the returned `responseData` includes the corresponding clause content.
- Review interface logs to confirm the `Authorization` parameter is correctly parsed, with no authentication failure related logs.
- Compare the update times of official public policies to confirm that the incremental data returned by the interface matches the release cycle.
- Adjust the single search limit to "Top 5 entries", verify that the number of returned results aligns with the configured value range.
