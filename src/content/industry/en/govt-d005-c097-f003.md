# Policy and Regulatory Basis Q&A for Nuclear Power Operations: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data primarily comes from policy documents, safety operation procedures, and industry standard documents officially released by the National Energy Administration, nuclear power industry self-regulatory organizations, and enterprises operating nuclear power projects. Updates to this data occur in sync with revisions to national energy policies, upgrades to nuclear power industry standards, and supplementary procedures after new unit commissioning. Each individual document includes fields such as policy document number, issuing authority, effective date, applicable unit scenario, clause number, and main text details. Units include Chinese character numbering, date formats, and applicable unit model identifiers. Document lengths range from several pages to dozens of pages, and some core procedures are split and stored by chapter.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The characteristics of this category of data impose multiple constraints on the multi-turn dialogue and prompt engineering workflow. First, individual documents are lengthy and split into chapters. The multi-turn dialogue workflow must limit the total amount of document fragments carried in the context to avoid exceeding the model's context capacity limit. Second, policy documents have clear effective dates, applicable unit scenarios, and document number identifiers. The workflow must track parameters such as the unit model and policy time period mentioned by users to avoid returning cross-scenario or outdated policy content. In addition, data updates have no fixed cycle. Prompt engineering must add logic to confirm the current version of the knowledge base to ensure returned content matches the latest synchronized policy documents.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Nuclear power policy documents mostly use clause-based structures. This length can cover a complete single policy clause and avoid split breaks |
| Overlap Length | 100–150 characters | There are associated logical relationships between policy clauses. The overlap length preserves context connection information and avoids losing clause associations during retrieval |
| Similarity Threshold | 0.75–0.85 | Nuclear power policy terminology is highly professional. This threshold can filter irrelevant documents while retaining relevant clauses |
| Single-round Recall Limit | Top 8 results | The number of policy clauses that need to be covered in a single round of dialogue is limited. Exceeding this number will exceed the model's context capacity |
| `messages` Context Length | 4000–6000 token | Complies with the multi-turn dialogue context limit of FastGPT v4.17.0, and adapts to the average length of nuclear power policy documents |
| Question Optimization | Enabled | Nuclear power policy terminology is mostly professional expressions. Question optimization converts colloquial questions into professional retrieval terms to improve retrieval accuracy |

## Three Common Misconfiguration Issues
- Phenomenon: Returned policy content in dialogue is truncated, and the full text of the clause is not displayed. Cause: The `messages` context length is set too small, exceeding the model's capacity limit, resulting in some document fragments not being included in the context.
- Phenomenon: A 500 status code is returned when importing nuclear power policy documents. Cause: The deployed embedding model does not match the embedding format of FastGPT v4.17.0, or the document size exceeds the single upload limit.
- Phenomenon: The outputs of multiple AI dialogue modules in the workflow are all returned, and only the last result is not retained. Cause: No result filtering logic is configured in the workflow, or the dialogue result in the last `variables` is not specified as the only output.

## How to Verify Correct Configuration
- Upload a single nuclear power policy standard document, initiate a query for the corresponding clause, and check whether the returned content fully covers the target clause without truncation or missing content.
- Initiate a multi-turn dialogue that specifies a unit model and policy effective time period, and check whether the returned results match the user-specified scenario and time range.
- Run the configured workflow, and check that the output only includes the content of the last AI dialogue module, with no redundant preceding results.
- View the knowledge base synchronization log to confirm that the latest released nuclear power policy documents have completed index updates with no omissions.

The values provided are common starting points and should be measured against the reader's own samples.
