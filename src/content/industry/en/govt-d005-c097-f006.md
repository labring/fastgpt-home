# Policy and Regulatory Basis Q&A for Nuclear Power Operations: Citation Sources and Traceability

## What This Category of Data Looks Like
The data is primarily sourced from official nuclear power operation regulatory documents released by the National Nuclear Safety Administration and the National Energy Administration, industry national standards, and internal enterprise operation and maintenance procedures. The update rhythm adjusts dynamically with new policy releases and standard revisions. Most documents are structured long texts that include fields such as document number, issuing authority, effective date, chapters and clauses. The length of individual documents varies widely, with clauses numbered hierarchically, and some include attachments and explanatory notes.

## Constraints on Citation Sources and Traceability
Nuclear power operation policy texts are mostly long structured documents with clear clause hierarchies. Citations must be precise to specific clause numbers. Therefore, the traceability link must support locating content by hierarchy. If long text chunking does not adapt to chapter hierarchies, citation fragments will deviate from the original document clauses. Policy update frequency is not fixed. The knowledge base must be synchronized with the latest document versions, otherwise citations will become invalid. Additionally, regulatory requirements mandate that citations clearly state document numbers and issuing authorities. The traceability link must extract and display these metadata to avoid vague citations and ensure compliance.

## How to Configure
This setup is compatible with FastGPT v4.17.0. The following are the core configuration items:

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Nuclear power policy clauses are mostly long paragraphs. Sufficient context must be retained to ensure semantic completeness, while avoiding exceeding model context limits |
| Chunking Delimiter | Match the clause numbering structure of nuclear power policies using #, ##, ### | Nuclear power policy documents are numbered by clause hierarchy. Using title markers of corresponding levels as delimiters ensures that chunked content corresponds to complete clauses, facilitating traceable positioning |
| `responseData` | Enable citation metadata return | Nuclear power operations require clear citation of document numbers and issuing authorities. When enabled, this configuration allows extraction and display of this information from responses to meet regulatory traceability requirements |
| Dynamic Knowledge Base Value Pass Configuration | Bind variables for the dedicated nuclear power policy knowledge base | Nuclear power policy data is stored independently. Dynamic value passing ensures that only the target knowledge base is retrieved, avoiding interference from irrelevant data |
| `detail` | Enable full citation details | Citation fragments’ original text content and location must be displayed to meet compliance traceability requirements for nuclear power operations |
| Maximum Number of Recalled Entries | Top 3–5 entries | Nuclear power policy citations require precision. Too many recalled entries will introduce irrelevant content, while too few will fail to cover relevant clauses |

## Three Common Misconfigurations
- Symptom: No citation source field appears in the response returned after calling the API, or the citation source field is an empty string. Cause: The `responseData` citation metadata return configuration is not enabled, or the dynamic knowledge base value pass did not correctly bind the target nuclear power policy knowledge base.
- Symptom: Chunked citation clauses do not match the original document chapters, with cross-clause citations occurring. Cause: The chunking delimiter does not adapt to the hierarchical numbering structure of nuclear power policies. Generic delimiters were used, resulting in chunk breaks.
- Symptom: Citation details are not displayed on the terminal page. Cause: The `detail` configuration is not enabled, or the front-end rendering logic did not bind the citation data field.

## How to Verify Successful Configuration
- Call the configured API, check whether the response fields include citation-related metadata fields to confirm that the `responseData` configuration is active.
- Upload a test nuclear power policy document, initiate a test query, and check whether the returned citations accurately correspond to specific clauses in the document to confirm that the chunking delimiter configuration adapts to the document structure.
- Initiate a query on the terminal page, confirm that the file information and fragment details of the citation source are displayed on the page to confirm that the `detail` configuration is active.
- Dynamically modify the knowledge base value pass variable, initiate a query, and confirm that only content from the target nuclear power policy knowledge base is retrieved to confirm that the dynamic value pass configuration is active.
