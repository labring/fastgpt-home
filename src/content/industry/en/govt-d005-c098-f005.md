# Policy and Regulatory Basis Q&A for Civil Aviation Airports: Tool Calling and Plugins

## What this category of data looks like
Civil aviation airport policy and regulatory basis data primarily comes from the official website of the Civil Aviation Administration of China, internal institutional repositories of regional airport management groups, and civil aviation industry standard documents. Data synchronization is completed within 1 to 3 days after the Civil Aviation Administration issues official documents. The structure of a single policy document usually includes fields such as document number, issuing authority, effective date, clause text, and attachment description. Fields are categorized by dimensions including policy category, applicable airport grade, and penalty clauses. Document content uses clauses as the smallest unit, and some documents include multi-page attachments.

## What constraints these characteristics impose on tool calling and plugins
Policy documents include identifying fields such as document number and effective date. Tool calling must match these fields to accurately recall corresponding policies, and cannot rely solely on fuzzy keyword retrieval. Data update frequency is relatively fast, which requires that the plugin's data source synchronization cycle cannot be too long, otherwise it will fail to cover the latest released industry policies. A single document has a relatively long length and independent clauses, so tool calling must retain clause integrity to avoid logical breaks caused by splitting. The civil aviation policy interface requires verification of territorial jurisdiction permissions, so tool calling must carry parameters such as the airport territorial code, otherwise it cannot obtain policy data for the corresponding region.

| Data source synchronization cycle | Every 12 hours | The update frequency of civil aviation policies is 1 to 3 days. Synchronizing every 12 hours can cover the latest issued documents and avoid resource waste |
| `toolChoice` | Auto select tool | Policy Q&A requires alternating between knowledge base retrieval and civil aviation public policy interface calls. Auto selection can match different scenario requirements |
| Plugin call timeout | 600 seconds | Civil aviation public interfaces may have delayed returns of batch policy data. 600 seconds covers most request scenarios |
| Knowledge base recall count | Top 8 entries | A single policy document includes multiple clauses. The top 8 entries can cover core policy content without exceeding the context limit |
| `functionCall` | Enable forced tool calling | Ensure that the civil aviation policy interface is called to obtain real-time data when necessary during the Q&A process, avoiding reliance on outdated knowledge base content |
| Plugin request header configuration | Carry airport territorial code | The civil aviation policy interface requires verification of territorial jurisdiction permissions. Carrying the code can obtain valid policy data for the corresponding region |

## Three common errors
- A 403 status code is returned when calling the civil aviation policy public interface, because the request header does not carry the airport territorial code, and the interface permission verification fails.
- Nested workflow execution is incomplete, because the parent workflow does not pass necessary parameters such as policy document number and effective date, so the child workflow cannot match the corresponding policy data.
- An empty result is returned when calling a third-party model, because the `functionCall` parameter is not enabled correctly, so the model cannot trigger tool calls to obtain real-time policy data.

## How to confirm the configuration is complete
- Manually trigger a civil aviation policy Q&A request, check the FastGPT tool call log to confirm whether the civil aviation policy interface and knowledge base retrieval function are called.
- Check the data source synchronization record to confirm that the latest policy documents have been synchronized within the last 12 hours.
- Use an interface testing tool, pass the airport territorial code parameter, and verify whether the policy data returned by the civil aviation policy interface meets expectations.
- Check the nested workflow execution log to confirm whether the parameters such as policy document number and effective date passed by the parent workflow are complete, and whether the child workflow is executed normally.
