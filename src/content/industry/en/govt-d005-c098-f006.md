# Policy and Regulatory Basis Q&A for Civil Aviation Airports: Citation Sources and Traceability

## What Data for This Category Looks Like
The policy and regulatory basis data for civil aviation airports is primarily sourced from the official website of the Civil Aviation Administration of China and normative documents publicly released by regional civil aviation administrations. Data updates occur in real time alongside new policy releases. Documents follow standard official document formatting, and include fields such as document number, issuing authority, effective date, and full text of clauses. Content is labeled hierarchically by article, paragraph, and subparagraph. The length of a single document ranges from hundreds to tens of thousands of characters.

## Constraints for Citation and Traceability
Official documents use precise document numbers and clause markings. Traceability must link to specific document numbers and clause levels. Fuzzy citation using only a title is not permitted.
Frequently updated policies require knowledge base sync cycles to align with regulatory release rhythms. This prevents citing expired or invalid content.
Hierarchical document structures require retention of article, paragraph, and subparagraph hierarchies. This ensures exact original text positions can be located during traceability.
The formal nature of government documents requires cited content to exactly match the original text. Semantic rewriting is not allowed, and exact wording must be retained.

## Configuration Settings
All configurations below are based on FastGPT v4.17.0.

| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average length of single clauses from civil aviation policies, prevents truncation of critical traceability information |
| `responseData` | Enabled | Forces return of original text fragments matched by the knowledge base, ensures responses are strictly based on knowledge base content |
| `detail` | Enabled | Retains metadata such as original document numbers and clause hierarchies, supports precise traceability |
| Single search limit | `Top 3 results` | Civil aviation policy clauses are highly correlated; limiting to top 3 results focuses on core supporting basis |
| Knowledge base sync frequency | Daily early morning | Aligns with the frequent update rhythm of civil aviation policies, avoids citing expired documents |

## Three Common Configuration Errors
- Phenomenon: Q&A results do not return original text fragments matched by the knowledge base, only generic responses are generated. Cause: The `responseData` configuration item is not enabled, so the system does not enforce binding to knowledge base content.
- Phenomenon: Knowledge base citation variables cannot be selected in workflow code nodes, and the first search result fails to output. Cause: The `detail` configuration item is not enabled, so metadata fields from knowledge base matching results are not retained.
- Phenomenon: Expired policy content is still returned after knowledge base sync. Cause: A reasonable knowledge base sync frequency is not set, or the sync task did not run normally.

## How to Verify Correct Configuration
- Submit a query related to civil aviation policies, check if document numbers and clause hierarchy information are attached at the end of the response.
- Navigate to the FastGPT knowledge base management page, check sync task execution logs to confirm daily sync tasks are running normally.
- Modify the single search limit configuration, verify that the number of recalled results matches the set value.
- Adjust the `quoteMaxToken` configuration, verify that original text fragments are not truncated in responses.

The values given are common starting points and should be measured against the reader's own samples.
