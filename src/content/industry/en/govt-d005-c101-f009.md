# Policy and Regulatory Basis Q&A for Port Shipping: Model Integration and Configuration

## What the data for this category looks like
Data for port shipping policy and regulatory basis Q&A primarily comes from official public channels of the Ministry of Transport, direct maritime safety administrations, General Administration of Customs, and local port administrations. Updates are synchronized immediately when new policies are released, and old policies are removed when revised or revoked. Most documents are in PDF or structured Word format, including fields such as policy number, issuing authority, effective date, applicable port areas, core constraints, and execution standards. Some documents include attached workflow or quantitative indicator tables, with units including natural tons, TEU, operation duration, rate percentage, and others.

## What constraints do these characteristics impose on model integration and configuration
The characteristics of port shipping policy data impose multiple constraints on model integration and configuration.
First, policy documents have clear effective dates and applicable port area ranges. Recall rules must be configured to filter non-target port policy content to avoid returning invalid information.
Second, policy clauses are mostly structured, with unique numbers and effective periods. The model must accurately extract and reference this information, so context matching precision must be adjusted.
Third, policy updates have no fixed cycle. A mechanism supporting manual knowledge base updates must be configured to ensure Q&A content always matches the latest policies.
Fourth, some policies include quantitative indicators. The model must accurately identify unit types to avoid matching errors.

This configuration guide applies to FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Port shipping policy documents are mostly long clauses, requiring sufficient context to ensure the model matches complete policy scope |
| `quoteMaxToken` | 1500–2000 token | Policy references must accurately return complete clause content, avoiding truncation of critical numbering and effective date information |
| `maxTokens` | 2000–3000 token | Limit the maximum length of a single model output to ensure policy interpretation content is concise and complete |
| `toolChoice` | "auto" | Require the model to independently determine whether to call the knowledge base to recall policy documents, adapting to policy differences across port areas |
| `temperature` | 0.1–0.3 | Policy Q&A requires rigor, reducing randomness to ensure returned content is highly consistent with the original text |
| `AIPROXY_API_ENDPOINT` | Fill in the corresponding interface address according to the deployment environment | Adapt to local or cloud deployment model call paths to ensure normal request routing |
| `AIPROXY_API_TOKEN` | Fill in the key generated according to actual conditions | Verify model call permissions to avoid request failures caused by unauthorized access |

## Three common mistakes
- Phenomenon: The model returns a `model response empty` error or no output at all. Cause: `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is not configured correctly, resulting in failed connection establishment for model requests.
- Phenomenon: Recalled policy documents are not filtered by applicable port areas, returning invalid cross-port policy content. Cause: Recall filtering rules by applicable area are not configured, or rule parameters are set incorrectly.
- Phenomenon: The policy reference returned by the model does not include complete clause numbers or effective times. Cause: `quoteMaxToken` is set too small, truncating critical identification fields in clauses.

## How to confirm the configuration is complete
- Manually trigger a knowledge base update, check if the update log shows successful synchronization of policy documents with no error prompts.
- Enter a test question such as "What are the container loading and unloading charging standards for a certain port area", check if the returned result includes accurate policy clause numbers and effective dates.
- View the model call log, confirm that the request header carries the correct `AIPROXY_API_TOKEN`, and the interface address matches the deployment environment.
- Adjust the port area of the test question, check if the recall results only return policy content for the corresponding port area.

The values provided are common starting points and should be measured against the reader's own samples.
