# Policy and Regulatory Basis Q&A for Refining and Chemical Production: Tool Calling and Plugins

## What This Category of Data Looks Like
Data for refining and chemical production policy and regulatory basis Q&A mainly comes from petrochemical industry compliance documents released by the National Energy Administration and the Ministry of Emergency Management, as well as internal production operation compliance manuals and safety procedures of enterprises. The data update schedule is as follows: national-level policies are updated and synchronized quarterly, and internal procedures are updated irregularly when new regulations are issued or processes are adjusted. Each single document usually includes document number, issuing authority, effective date, and clause number. Fields cover applicable refining and chemical production units such as atmospheric and vacuum distillation and catalytic cracking, compliance requirements, corresponding disposal processes, and quantitative indicators are uniformly marked using legal units of measurement.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Because the data includes both national public compliance documents and internal enterprise-specific procedures, tool calling requires configuration of dual data source permission verification logic to prevent unauthorized access to internal sensitive documents. The data includes a field for applicable refining and chemical production units. When calling tools, target process parameters must be passed to filter policy clauses unrelated to the current production link, reducing invalid retrieval results. The data has clear effective dates. Tools need to add effective time verification logic to automatically filter expired policy content. The document structure includes standardized clause numbers. Tool return results must be sorted by clause number and applicable unit to enable quick matching of business needs in subsequent calling links. This page is written based on FastGPT v4.17.0.

## How to Configure
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Automatically adapts to multi-scenario calling needs for policy retrieval, no manual specification of tool type required |
| `functionCall` | Enabled | Enables structured tool calling to ensure return results can be directly parsed by business systems |
| Tool call timeout | `300–600 seconds` | Policy documents usually contain multiple chapters, sufficient timeout ensures complete retrieval and loading |
| Retrieval result filtering rules | Filter content from the last 12 months by effective date | Refining and chemical industry policies are updated frequently, clauses from the last 12 months align better with current compliance requirements |
| Applicable production unit matching | Pass current process identifier | The data includes a field for applicable refining units, allowing precise filtering of policies unrelated to the current production link |
| Number of single return results | `Top 3–5 entries` | Individual policy clauses are concise in content, a small number of results covers the core needs of business queries |
| Knowledge base sync frequency | `Every 7 days` | Balances the timeliness of quarterly national policy updates and irregular internal procedure adjustments, avoiding excessive resource consumption |

## Three Common Mistakes
- Symptom: Calling the `/api/core/dataset/update` interface returns a 500 status code, and the knowledge base management page is accessible normally via the browser. Cause: The correct knowledge base permission token is not carried in the API request header, and the permission verification rules for `functionCall` are not configured correctly, leading to backend verification failure.
- Symptom: The semantic retrieval tool returns a "Connection error" error and cannot pull compliance documents. Cause: The network access whitelist for the private knowledge base is not configured, or the tool call timeout period is set too short to establish a normal connection.
- Symptom: When calling other models in the workflow, the code running module has no streaming output results. Cause: The streaming transmission configuration for tool calling is not enabled, or the automatic calling logic of `toolChoice` is not matched correctly, leading to abnormal data transmission format.

## How to Verify Correct Configuration
- Submit a policy query for the atmospheric and vacuum distillation process, and check if the tool return results only include compliance clauses applicable to this process.
- View the tool call logs to confirm that the effective date filtering condition and current production process identifier are included in the request parameters.
- Test the API interface call to verify that the return result is in structured format with no abnormal error messages.
- Check the knowledge base sync task records to confirm that the data update cycle matches the configured sync frequency.
