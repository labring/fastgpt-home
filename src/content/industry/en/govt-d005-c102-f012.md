# Policy and Regulatory Basis Q&A for Refinery Production: Deployment and Upgrade

## What this category of data looks like
The policy and regulatory basis data for refinery production is sourced primarily from officially published documents of the National Energy Administration, Ministry of Emergency Management, and China Petroleum and Chemical Industry Federation. Data is updated quarterly with new compliance requirements. Individual policy documents can be several thousand characters in length, following standard official document formatting. They include policy number, release date, applicable refinery production links, specific compliance clauses, penalty standards, and implementation cycles. Fields include policy ID, applicable scenario, compliance requirements, and penalty clauses. Units follow the "No. XX" format from policy document numbers, and "year" or "month" for implementation cycles.

## What constraints do these characteristics impose during deployment and upgrade
Longer individual policy documents require sufficient vector storage and database resources during deployment to support long-text vector extraction and storage. Higher data update frequency requires scheduled synchronization scripts after deployment to keep the knowledge base synchronized with official policies. Policy content covers safety and environmental compliance requirements for refinery production, which are sensitive information. Strict internal access permission controls must be configured during deployment. Refinery enterprises have unified domain name specifications, so the front-end access domain name must be matched during deployment to ensure normal access for internal employees.

## How to configure the settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://refinery-admin:securePass@internal-db:27017/fastgpt_policy?authSource=admin` | Stores metadata and vector indexes for refinery policy documents, suitable for scenarios with long individual documents and large data volumes |
| `REDIS_URL` | `redis://policy-cache:6379/1` | Caches frequently queried policy Q&A pairs to reduce query pressure on the vector database and lower inference latency |
| `FE_DOMAIN` | `https://refinery-policy.enterprise.com` | Matches the internal front-end access domain name specifications of refinery enterprises to ensure normal access for internal employees |
| `ROOT_KEY` | `32-bit randomly generated secure string` | Configures the super administrator access key to secure access and modification permissions for policy data |
| `DB_MAX_LINK` | `80–120 concurrent connections` | Adapts to the query concurrency of refinery policy data, preventing service interruptions caused by exhausted connection pools |
| `STORAGE_S3_ENDPOINT` | `https://s3.enterprise-cn.com` | Stores original policy documents and attachments, adapting to the access address of the enterprise's internal object storage service |

## Three common misconfigurations
- Symptom: OneApi page returns 502 error and fails to load normally. Cause: Incorrect `REDIS_URL` configuration, which prevents normal session cache establishment and prevents correct routing of front-end requests.
- Symptom: Cannot create multiple accounts, and uploaded policy document table data has no response. Cause: `PG_URL` is not configured with read-write permissions for the enterprise internal database, making it impossible to store account and document metadata.
- Symptom: Policy Q&A inference latency exceeds 30 seconds, and the number of returned results is insufficient. Cause: `DB_MAX_LINK` is set too low, and the database connection pool cannot support concurrent query requests.

## How to confirm the configuration is correct
- Access the address specified by `FE_DOMAIN` to verify that the front-end page loads normally with no resource loading failure prompts.
- Log in to the FastGPT backend management interface using `ROOT_KEY` to verify that policy document upload, metadata extraction, and synchronization functions operate normally.
- Run the `redis-cli -h internal-redis -p 6379 ping` command to verify that the cache service configured via `REDIS_URL` is connected normally.
- Submit a test query regarding refinery safety compliance to verify that the returned results include preset fields such as policy number and applicable links.
