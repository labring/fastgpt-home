# Coal Chemical Industry Policy and Regulatory Basis Q&A: Deployment and Upgrade

## What the data for this category looks like
Data sources for coal chemical industry policy and regulatory basis materials include normative documents released via official channels such as the National Energy Administration, Ministry of Ecology and Environment, and National Development and Reform Commission, as well as industry standard texts.
Update schedules align with the release of new policies, with no fixed cycle. New policies related to energy consumption control, environmental emissions, and capacity planning must be synchronized immediately upon release.
Document structures typically include document number, issuing authority, release date, core clauses, attached tables, and similar components. Fields cover policy ID, applicable scope, implementation date, and quantitative indicators. Units include professional measurement standards such as ton, cubic meter, and milligram per cubic meter.

## What constraints do these characteristics impose on deployment and upgrade
The characteristics of coal chemical policy data create multiple constraints for the deployment and upgrade stage:
- The combination of long documents and attached tables requires support for large file splitting and structured extraction during deployment, to avoid information loss.
- The lack of a fixed update cycle requires a configurable incremental synchronization mechanism during upgrades, without needing to fully rebuild the knowledge base each time.
- The strictness of professional fields and units requires the import process to retain original data formats, without arbitrary conversion or omission.
- The regional and industry scope limitations of some policies require precise field-based filtering in the retrieval stage.

## How to set configurations
| Configuration Item | Recommended Value | Rationale for This Value |
| --- | --- | --- |
| `DB_MAX_LINK` | 1000–1500 entries | The single-document length of coal chemical policy documents varies widely, requiring adaptation to the splitting and storage limits for long documents |
| `MONGODB_URI` | Connection string pointing to a dedicated storage node | Policy data requires persistent storage, and dedicated nodes avoid resource conflicts with other business databases |
| `REDIS_URL` | Configured as a cache instance with 1000 MB of memory | Caches frequently retrieved policy clauses to reduce database query pressure |
| `STORAGE_S3_ENDPOINT` | Bound to a domestically compliant object storage service endpoint | Meets data storage compliance requirements for state-owned enterprises and public sector entities, avoiding cross-border data transmission risks |
| `FILE_TOKEN_KEY` | 3600 seconds valid duration | Limits temporary access permissions for policy documents, complying with data security management requirements |

## Three common configuration mistakes
- Database connection errors with status code 503 occur after upgrade. Cause: The original `MONGODB_URI` configuration was not retained during the upgrade process, causing the new instance to fail to access the historical policy knowledge base, creating a risk of data loss.
- Permission verification failure is returned when calling the model, and the specified model cannot be used. Cause: Model permission rules were not configured according to the deployment documentation, and domestic model mandatory verification was enabled, resulting in foreign model calls being blocked.
- Only some entries load successfully when batch importing policy documents. Cause: The `DB_MAX_LINK` parameter was not adjusted to a range suitable for long documents, and documents exceeding the upper limit were truncated before completing import.

## How to confirm the configuration is complete
- Run the `docker ps` command to confirm that the services corresponding to `MONGODB_URI` and `REDIS_URL` are running.
- Upload a coal chemical industry policy document, check the completeness of fields after import, and confirm that core information such as document number, issuing authority, and quantitative indicators is not lost.
- Initiate a policy-related retrieval request to verify that the number of returned results falls within the configuration range of `DB_MAX_LINK`.
- Access the backend address corresponding to `FE_DOMAIN`, complete login using the preset `ROOT_KEY`, and confirm that permission control is active.
