# Policy and Regulatory Basis Q&A for Coal Transportation and Sales: Workflow Orchestration

## What this category's data looks like
The data for this category primarily comes from official policy documents released by the National Energy Administration, provincial energy authorities, and coal industry associations. It is synchronized in real time when new policies are issued.
Document structure includes fixed modules: policy document number, issuing authority, effective date, applicable region, core clauses, and implementation requirements.
Fields include unified policy number, coal transportation and sales exclusive industry classification identifier, applicable geographic boundary, quantitative implementation standards, and similar items.
Common business units include tons, kilometers, yuan per ton, and other standard units.

## Constraints on workflow orchestration from these characteristics
Coal transportation and sales policy data is scattered and exclusive. Workflows must be bound to exclusive policy knowledge bases to avoid interference from irrelevant results in general knowledge bases.
Policy effective dates and applicable regions are core query conditions. Variables must be configured in the workflow to associate with corresponding fields to ensure accurate matching.
Individual policy documents are lengthy. The workflow's search result limit and context window must adapt to document length to avoid truncating core clauses.
Policy updates follow no fixed cycle. The knowledge base synchronization cycle must be set to once daily to ensure data timeliness.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Knowledge Base Selection | Bind to an exclusive coal transportation and sales policy knowledge base | Coal transportation and sales policy data is scattered and exclusive, avoid interference from irrelevant knowledge bases |
| Variable Reference Configuration | Associate with the policy document number and applicable region fields in `variables` | Accurately match policy entries corresponding to user queries |
| Single Search Result Limit | Top 8 entries | Coal transportation and sales policy documents are lengthy; too many results will exceed context capacity |
| Context Window | 8000–12000 characters | Adapt to the full length of core clauses in a single policy document |
| Workflow Trigger Node | Bind the `nodeId` to the user question node | Ensure policy matching is automatically triggered when a user initiates a query |
| Failure Retry Count | 2 times | Address temporary search failures caused by knowledge base synchronization delays |

## Three Common Misconfigurations
- Failing to associate the policy document number field in `variables` during configuration, which causes search results to fail to match the policy number specified by the user, and the interface returns an empty result list.
- Not adding a user confirmation node in the workflow, which prevents a submit button from popping up in the conversation for users to confirm query conditions, and prevents the subsequent policy matching process from being triggered.
- Not configuring the timeout parameter for Mermaid calls, which causes a 504 status code to be returned due to network latency when generating policy flowcharts, leading to direct workflow interruption.

## How to Verify Successful Configuration
- Access the workflow editing interface of FastGPT v4.17.0, confirm that the knowledge base selection is bound to the exclusive coal transportation and sales policy knowledge base.
- Review the variable configuration panel, confirm that the business fields including policy document number and applicable region in `variables` have been associated.
- Initiate a test conversation, enter a query containing a specific policy document number, confirm that the core content of the corresponding policy document is returned.
- Simulate a knowledge base synchronization delay scenario, confirm that the workflow triggers the failure retry mechanism and returns a friendly prompt.
