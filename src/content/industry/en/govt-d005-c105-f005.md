# Policy and Regulatory Basis Q&A for Coal Transportation and Sales: Tool Calling and Plugins

## What the Data for This Category Looks Like
Coal transportation and sales policy and regulatory basis data mainly comes from official documents released by the National Energy Administration, provincial energy regulatory departments, coal industry associations, and internal compliant transportation and sales systems of large coal transportation and sales enterprises. There is no fixed update cycle; data is updated synchronously when new policies are issued or systems are revised. Each document follows a formal official document structure spanning thousands of characters, including fields such as document number, issuing authority, effective date, applicable region, and core transportation and sales clauses. Units for transportation volume-related fields are ten thousand tons, and rate units are yuan per ton.

## Constraints on Tool Calling and Plugin Workflows
Coal transportation and sales policy documents are lengthy and formally structured. Tool calling must adapt to long-context input and output limits to avoid truncating core compliance clauses. The official nature of data sources requires plugins to verify the issuing entity and version of documents, preventing calls to expired or non-official incorrect content. The specialized nature of fields requires tool calling parameters to accurately correspond to exclusive fields such as document number, effective date, and applicable region, avoiding generalized matching that causes result deviations. The lack of a fixed update cycle requires plugin configuration to regularly synchronize knowledge base trigger mechanisms to ensure called policy content is the latest valid version.

## Three Common Configuration Mistakes
- Scenario: A 403 status code is returned when calling a multi-dimensional table service via an HTTP node. Cause: The permission scope of the associated application is not correctly configured, and edit permissions for the multi-dimensional table are not granted.
- Scenario: Policy clauses returned by tool calling are truncated. Cause: The context window size is set too small, failing to adapt to the length of single policy documents.
- Scenario: Tool calling has no response after connecting to MCP. Cause: The access key for MCP is not correctly bound to the FastGPT environment variable configuration, resulting in failure to call external data sources.

## How to Verify Correct Configuration
- Initiate a policy query test, check whether the issuing entity in the returned result is the designated official entity, to confirm that the document source verification configuration is effective.
- View the tool calling logs, confirm that the returned policy clauses are not truncated, to verify that the context window setting meets requirements.
- Trigger a manual knowledge base synchronization operation, check the knowledge base update records, to confirm that the synchronization cycle configuration matches expectations.
- Initiate a query containing field requirements, check whether the returned result accurately matches exclusive fields such as document number and effective date, to verify that the field matching precision configuration is effective.
