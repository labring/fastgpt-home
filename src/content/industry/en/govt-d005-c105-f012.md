# Policy and Regulatory Basis Q&A for Coal Transportation and Sales: Deployment and Upgrade

This page is compatible with FastGPT v4.17.0.

## What this category of data looks like
The policy and regulatory basis data for coal transportation and sales comes primarily from official documents released by the National Energy Administration, local coal industry regulatory authorities, and internal transportation and sales management departments of state-owned and state-holding enterprises. Updates occur when new policies are issued or internal regulations are revised, with no fixed schedule. Most documents are long texts with structured metadata, including fields such as document number, issuing authority, effective date, applicable scope, and compliance clauses for transportation volume and freight rates. Some attachments include transportation and sales indicator tables, using units including ten thousand tons, yuan per ton, and transportation kilometers.

## What constraints do these characteristics impose during deployment and upgrade
Because policy data sources are scattered and updates have no fixed cycle, deployments must support batch import of multi-source data and scheduled synchronization configuration. The coexistence of long texts and structured metadata requires knowledge bases to support metadata field mapping and large chunk storage. Units for transportation and sales-related fields have industry-specific characteristics, so preset field matching rules must be configured during deployment to avoid unit confusion during retrieval. Data security requirements for state-owned and state-holding enterprise scenarios require configuration of permission isolation and access token mechanisms to prevent unauthorized access to internal policy documents. During upgrades, retain existing metadata mapping rules to avoid field configuration failures caused by version updates.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 seconds` | Most coal transportation and sales policy documents are long texts. Long connections reduce reconnection overhead and adapt to large-file retrieval scenarios |
| `REDIS_URL` | `Local Redis instance port 6379` | Used to cache metadata for policy retrieval and user session information, reducing database query pressure |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the enterprise's self-built object storage address` | Adapt to the storage needs of large-capacity policy documents for batch uploads and ensure data persistence |
| `FILE_TOKEN_KEY` | `Set based on actual testing` | Generate unique access tokens for uploaded policy documents to achieve permission isolation for internal documents |
| `ROOT_KEY` | `Only used for initial administrator configuration` | Restrict non-authorized users from modifying core knowledge base configurations, complying with state-owned and state-holding enterprise data security specifications |

## Three common mistakes
- The symptom is failure to parse uploaded coal transportation and sales policy documents after local deployment, with the interface displaying "File parsing failed". The cause is incorrect configuration of `FILE_TOKEN_KEY`, which prevents the system from reading uploaded documents.
- The symptom is failure to assign different knowledge base permissions after creating multiple accounts, with the interface displaying "Invalid permission configuration". The cause is failure to complete administrator permission initialization via `ROOT_KEY`, so the account permission system is not established.
- The symptom is that the number of returned results during policy document retrieval does not match expectations, with logs showing database connection timeout. The cause is that `DB_MAX_LINK` is set too small, causing connections to disconnect prematurely during long-text retrieval.

- Upload a coal transportation and sales policy PDF document, verify that it parses normally and generates knowledge base entries with structured metadata.

- Run a policy keyword search, check that returned results include correct industry-specific fields such as document number and effective date.
- Review monitoring data for the instance associated with `REDIS_URL`, confirm that connection counts stay within a stable operating range.
