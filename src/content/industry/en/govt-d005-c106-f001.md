# Policy and Regulatory Basis Q&A for Coal-Electric Integration: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Coal-electric integration policy and regulatory basis data originates from official public documents issued by the Coal Department and Electric Power Department of the National Energy Administration, and the State-owned Assets Supervision and Administration Commission. Updates are adjusted alongside new policy releases, with no fixed cycle.

Document structure includes policy title, issuing document number, issuing authority, effective date, scope of application, core clauses, and rectification requirements for violations. Fields include policy number, issuing entity, effective time, applicable scenario, and clause content. Units are clauses and documents.

## Constraints Imposed on HTTP Interfaces and External Systems
Fixed document numbers and issuing authorities for official policy documents require interfaces to include classification parameters to filter data for the corresponding category, avoiding returns of irrelevant content. The lack of a fixed update cycle requires interfaces to support on-demand pulling of the latest policies, without relying on static caching.

Long single policy clauses require interfaces to adapt to long-content transmission, preventing connection interruptions caused by response timeouts. Additionally, compliance requirements for state-owned enterprise and public sector scenarios require interfaces to include permission verification steps to ensure data access security.

## Three Common Misconfigurations
- Phenomenon: Page data remains fixed after streaming data reception is interrupted, with no obvious interface error. Cause: Response logic adapted to long content is not configured, leading to connection disconnection due to transmission timeout of long-clause policy documents.
- Phenomenon: Unable to upload policy files for Q&A when calling the interface, with empty return parameters. Cause: Parameters related to file upload are not configured in `variables`, and the interface is not associated with a file parsing module.
- Phenomenon: Source information in historical queries only shows generic identifiers, and policy document numbers cannot be displayed. Cause: The policy number field is not included in `responseData`, and the interface does not return corresponding metadata.

## How to Confirm Proper Configuration
- Send an interface request carrying `Authorization` and `variables`, check if the returned results only include the specified fields for coal-electric integration policies.
- Initiate a Q&A request for long-clause policies, confirm that the interface response time meets the set timeout threshold, with no mid-transmission disconnections.
- Call the historical record interface, check if the returned results include metadata fields such as policy document numbers.
- Upload policy files related to coal-electric integration, confirm that the interface can correctly parse them for use in Q&A.
