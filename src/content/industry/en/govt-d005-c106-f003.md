# Coal-Electric Integration Policy and Regulatory Basis Q&A: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Coal-electric integration policy and regulatory basis data primarily comes from official documents issued by the National Energy Administration, National Development and Reform Commission, State-owned Assets Supervision and Administration Commission of the State Council, and local energy regulatory authorities. Updates occur irregularly, in sync with the release of new pilot policies and energy consumption control requirements.

Document structure uniformly includes fields such as policy document number, issuing authority, release date, enforcement clauses, applicable scope attachments, and more. Field units mostly use industry standard units such as ten thousand kilowatts (for installed capacity) and year-month-day (for enforcement time). The length of a single policy document typically ranges from 1000 to 5000 characters.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
The official nature of policy sources requires multi-turn dialogue to strictly verify the issuing entity and document number of quoted content, to avoid mixing in non-official information.
The irregular update feature requires the knowledge base to regularly trigger manual synchronization, and cannot rely on automatic real-time crawling.
The structured field requirements for documents require prompt engineering to guide the extraction of specific clause numbers and applicable scopes, to avoid fuzzy matching.
The uniformity of units requires the dialogue flow to automatically unify parameter units, to prevent retrieval deviations caused by non-standard units entered by users.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| --- | --- | --- |
| `variables` | Preset policy document number matching rules | Restrict dialogue to only extract included coal-electric integration policy clauses |
| Maximum context length | 6000–10000 characters | Adapt to the length of single policy documents and the context retention needs of multi-turn dialogue |
| `chatId` | Bind unique user session identifier | Ensure coherent association of context during multi-turn dialogue |
| Question optimization | Enabled | Improve matching accuracy for coal-electric professional terminology and policy clause numbers |
| Single recall limit | Top 5 entries | Control the number of policy items returned per round, avoid information overload |
| `messages` | Concatenate historical conversations in session order | Retain policy reference context from earlier questions, avoid repeated retrieval |

## Three common configuration errors
- A `Cannot read properties of null (reading 'q')` error pops up during dialogue. The cause is that the historical conversation concatenation logic for the `messages` parameter is not configured correctly, leading to empty fields being passed to the interface.
- The number of returned policy items exceeds the set single recall limit. The cause is that question optimization is not enabled, so irrelevant retrieved items are not effectively filtered.
- The accuracy of the question classification model in the workflow is low. The cause is that prompt engineering is not configured for coal-electric policy-specific terminology, so the general model cannot accurately distinguish policy types and clause numbers.

## How to confirm the configuration is complete
- Initiate a query that includes a specific coal-electric integration policy document number, check if the returned results match the included official clause content.
- Initiate 3 consecutive progressive questions, check if the session context is correctly retained, and previously referenced policy clauses can be reused in subsequent questions.
- View the knowledge base update log, confirm that the latest released coal-electric integration policies have been synchronized to the repository.
- Test a query that includes non-standard units, check if the system automatically completes unit conversion and matching verification.
