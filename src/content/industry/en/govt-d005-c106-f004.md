# Policy and Regulatory Basis Q&A for Coal-Electric Integration: Workflow Orchestration

## What This Category’s Data Looks Like
Coal-electric integration policy and regulatory basis data mainly comes from official public documents issued by the National Energy Administration, the State-owned Assets Supervision and Administration Commission, and energy authorities of various provinces and municipalities. The data update rhythm adjusts synchronously with new policy releases, with no fixed cycle. Each document includes fields such as document number, issuing authority, effective date, core clauses, applicable scenarios, etc. Fields are labeled with hierarchical units in accordance with policy text specifications. For example, clauses are divided into "articles, paragraphs, sub-paragraphs". The length of individual documents varies widely. Policy content suitable for coal-electric integration projects focuses on areas such as capacity coordination, energy transition, and project approval.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Official data source attributes require a data source verification step in workflow configuration. This ensures only policy content officially released by the National Energy Administration, the State-owned Assets Supervision and Administration Commission, and other authorities is retrieved. Subdivided attributes of policy hierarchy and applicable scenarios require adding classification nodes to filter clauses matching coal-electric integration projects. This avoids retrieving irrelevant energy policies. The large variation in document length requires configuring context truncation parameters. This prevents ultra-long documents from exceeding model context limits. The lack of a fixed cycle for data updates requires configuring scheduled update tasks according to the synchronization cycle defined by `variables`. This ensures the timeliness of knowledge base content.

## Three Common Misconfigurations
- Phenomenon: The workflow AI chat node outputs slightly different content when running the same test input twice. Cause: When the temperature switch is enabled and set to 0, some large language models still retain minor randomness. This is inconsistent with the deterministic output mode when the temperature switch is disabled.
- Phenomenon: After entering multiple lines of text in the specified reply node, the preview interface displays the content as a single concatenated line. Cause: No standard line break is inserted at line breaks, or the node's text format is not configured to support multi-line display.
- Phenomenon: When testing the workflow, the AI reply always appends the phrase "FastGPT is a large language model (LLM) based knowledge base question answering system" at the end. Cause: The default FastGPT system prompt content is not removed from the system prompt.

## How to Confirm Proper Configuration
- Run a test workflow, check that the issuing authority of the retrieved policy documents meets the preset official whitelist requirements.
- Adjust the temperature parameter of the AI chat node, run the same test input multiple times, and confirm the consistency of the output content.
- Enter test text containing multiple lines in the specified reply node, confirm that line breaks are displayed normally in the preview interface.
- Check the system prompt of the workflow, confirm that no default FastGPT identification content is included.

The values listed above are common starting points, and should be evaluated against the reader’s own samples.
