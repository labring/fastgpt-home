# Policy and Regulatory Basis Q&A for Coal-Electric Integration: Tool Calling and Plugins

## What the Data for This Category Looks Like
Coal-electric integration policy and regulatory basis data is sourced primarily from industry normative documents publicly released by the National Energy Administration and the National Development and Reform Commission, local supporting implementation rules, and compliance guidelines issued by coal industry associations. Data updates sync in real time alongside policy releases, with full synchronization completed within 24 hours following major policy adjustments. Each document includes core fields such as issuing authority, document number, effective date, clause identifier, applicable scenarios, and specific requirements. Clauses are labeled by article, paragraph, and subparagraph, and some documents include annexes explaining industry terminology.

## Constraints on Tool Calling and Plugins Workflow
Policy documents are lengthy with complex clause hierarchies. Tool calling must accurately locate relevant clauses to avoid returning off-topic content. Data sources carry official authority, so tool calling must only use publicly available official policy data sources to prevent non-compliant content from being included. Policy updates do not follow a fixed schedule, so plugins must be configured with a scheduled synchronization mechanism to ensure Q&A uses the latest policy versions. Fields include metadata such as document number and effective date, so tool calling must support filtering policy entries by issuing authority and effective time to improve Q&A accuracy.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Policy Q&A requires automatic matching of relevant clauses, no need to force a single tool |
| Single tool call return limit | Top 5 entries | A single policy document may contain multiple clauses; limiting entries avoids context overload |
| Tool response timeout | 600 seconds | Policy data is distributed across multiple official sources, so sufficient retrieval time must be allocated |
| `functionCall` | Extract clauses, document numbers, effective dates | Accurate retrieval of core policy metadata is required to ensure compliant and accurate Q&A content |
| Plugin data synchronization frequency | Once daily | Policy updates do not follow a fixed schedule; daily synchronization covers routine updates promptly |

*This configuration applies to FastGPT v4.17.0*

## Three Common Misconfigurations
- A connection timeout error occurs when calling a locally created MCP service. This happens because whitelist permissions for the local service are not configured, and the FastGPT plugin does not have local network access enabled.
- After enabling tool calling, the model's reply does not include intermediate reasoning steps. This occurs because the chain-of-thought output switch for tool calling is not enabled, or `toolChoice` is set to forced calling, which causes the model to skip thinking steps.
- Policy clauses returned by tool calling do not match the query. This occurs because the single tool call return limit is set too high, or filtering policy data by effective date is not enabled.

## How to Verify the Configuration Is Complete
- Navigate to the FastGPT plugin management page, check the synchronization status of the coal-electric integration policy tool, and confirm the last synchronization time was within the past 24 hours.
- Submit a test query with the prompt "What are the approval basis for coal-electric integration projects?" and verify that the tool call returns results include metadata such as policy document numbers and effective dates.
- Check the tool call logs to confirm the number of returned entries matches the configured single return limit.
- Manually modify local test policy data, wait for the synchronization cycle to complete, then submit another query to confirm the returned content has been updated.

The configuration values provided are common starting points. Adjustments should be made based on local samples and use cases.
