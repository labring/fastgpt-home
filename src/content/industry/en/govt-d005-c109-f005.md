# Policy and Regulatory Basis Q&A for Power Grid Enterprises: Tool Calling and Plugins

## What the data for this category looks like
Data sources include public documents from national energy regulatory authorities, standard industry power regulatory compilations, and internal compliance document collections of power grid enterprises. Data updates align with official policy releases, with no fixed schedule. Synchronization is completed promptly after new policies are issued. Documents follow standard official document format, including fields such as document number, issuing authority, effective date, clause number, applicable scenario, and specific content. Effective dates use the YYYY-MM-DD format. Clause numbers use the chapter + clause number marking format. Most individual documents are under 5000 characters.

## What constraints these characteristics impose on tool calling and plugins
The official document structure of power grid policy data requires tool calling to accurately match fields such as document number and clause number. This avoids content deviations caused by vague retrieval. The non-fixed update cycle of data requires plugins to support scheduled pulling of the latest data sources. This prevents outdated content from static caching. The presence of the effective date field requires tool calling to pass the current time parameter. This filters expired policy content. The per-document length limit requires tool calling to limit the number of results returned in a single call. This avoids generation interruptions caused by exceeding the context window.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `"auto"` | Adapts to multi-tool calling scenarios for power grid policy Q&A, automatically selects between calling the knowledge base or external policy query API |
| Single retrieval result limit | `Top 3` | Power grid policy clauses are concentrated. Too many results will exceed the context window and reduce generation accuracy |
| Plugin update cycle | `Every 12 hours` | Policy updates occur at relatively high frequency. Scheduled synchronization ensures the timeliness of returned content |
| `functionCall` | `Mandatory clause number matching` | Policy Q&A requires precise correspondence to document numbers and clauses, to avoid vagueness in general responses |
| Context window limit | `8000 token` | Power grid policy documents are relatively long. Context length must be controlled to avoid generation overflow |
| Tool calling timeout | `600 seconds` | Response times for power grid policy-related APIs fluctuate. Sufficient call duration must be reserved |

## Three common misconfigurations
- Phenomenon: After initiating a policy Q&A, the model does not automatically call the bound policy knowledge base plugin, and directly generates a general response. Cause: `toolChoice` is not configured to mandatory calling mode, or the power grid policy knowledge base data source is not correctly bound.
- Phenomenon: When calling an external policy query HTTP API, the returned result is empty or has an incorrect format. Cause: The format of request parameters is not correctly configured, and the corresponding identifier for file-type parameters is not specified, causing the API to fail to recognize incoming query conditions.
- Phenomenon: When calling a packaged policy Q&A application as a tool, a permission error or abnormal status code is returned. Cause: The team application is not enabled for plugin mode, or cross-application tool calling permissions are not configured.

## How to confirm configurations are correct
- Initiate a known valid power grid policy-related question, check the tool calling log to confirm that the bound knowledge base or HTTP plugin call is triggered.
- Enter the plugin management page, check the time of the most recent synchronization record to confirm it matches the configured update cycle.
- Simulate passing query parameters with effective date and document number, check if the returned results match the content of the corresponding policy clauses.
- Test calling a packaged policy Q&A application as a tool, confirm that the returned policy content conforms to the expected format.
