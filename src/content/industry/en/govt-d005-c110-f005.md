# Policy and Regulatory Basis Q&A for Mineral Mining and Processing: Tool Calling and Plugins

## What the data for this category looks like
Policy and regulatory basis data for mineral mining and processing is primarily sourced from public official documents and real-time updated supervision announcements released by the Ministry of Natural Resources, provincial mine safety supervision departments, and industry associations. Data is synced to the repository on the day new policies are released, and routine policies are reviewed quarterly. Document structure includes fields such as policy document number, issuing authority, effective date, applicable mine type, specific clauses, and supporting attachments (e.g., safety regulations, mining standards). Fields cover industry classification (metal ore/non-metal ore), production capacity requirements, and penalty thresholds. Units include million tons per year, cubic meters per second, square meters, and other measurement standards specific to mineral mining and processing.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Mineral mining and processing policy data comes from dispersed sources, requiring integration with multiple official APIs and static file libraries. Tool calling must therefore support multi-source aggregation configuration. Policy documents contain long-text clauses and attachments, with large single-pull data volumes, so reasonable timeout and pagination rules must be configured. Fields include detailed mine types, so corresponding filter parameters must be included during tool calling to avoid returning irrelevant policy content. Attachments require separate download and parsing, so plugins must support file stream processing and format conversion.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Automatically matches scenarios for tool calling and direct responses, adapting to the needs of both clause queries and comprehensive interpretation in policy Q&A |
| `functionCall` | Enabled | Forces binding of preset policy data pulling tools, avoids generating irrelevant content, and ensures accurate Q&A basis |
| Tool calling timeout | 120 seconds | Mineral mining and processing policy documents include multi-chapter attachments, requiring sufficient time to complete full data pulling |
| Tool result caching rule | Cache by policy document number, valid for 7 days | Most policies do not change in the short term after release, caching reduces repeated API calls and lowers latency |
| HTTP toolset request parameters | Carry mine type filter field, set to metal ore/non-metal ore | Filters policy data for the corresponding mine category, avoiding returning irrelevant general policy content |
| Tool calling response format | Structured JSON | Facilitates subsequent splitting and comparison of policy clauses, improving the accuracy of Q&A |

## Three Common Misconfigurations
- Calling the policy API tool returns `Invalid URL` with a 500 status code. The cause is an incorrectly filled full request path for the official policy interface, or a filter parameter format that does not meet interface verification rules.
- The tool calling node outputs both tool results and redundant AI-generated responses after execution. The cause is that the forced calling mode of `functionCall` is not enabled, causing the system to automatically generate additional interpretation content.
- Connection to the internal mine policy ledger database to obtain structured data fails. The cause is that the appropriate database connection plugin is not deployed, or the FastGPT service IP is not added to the database access whitelist.

## How to Verify Correct Configuration
- Manually trigger the tool calling node, and check if the returned JSON data includes policy clauses for the corresponding mine category, with no irrelevant general policy content.
- View the tool calling logs, confirm that the timeout setting meets the 120-second requirement, and there are no frequent timeout error records.
- Check the caching configuration, confirm that two relatively short-interval calls for the same policy document number reuse cached results, and no new pulling requests are initiated within the cache validity period.
- Verify that under the `functionCall` mode, only the preset policy tools are called, and no response content without official basis is generated.
