# Policy and Regulatory Basis Q&A for Grain Reserves: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The primary sources of grain reserve policy and regulatory basis data are normative documents officially released by the National Food and Strategic Reserves Administration, local grain reserve management regulations, and annual reserve rotation plan announcements. Data updates are triggered by policy revisions, with no fixed cycle. Document structures uniformly include fields such as document number, issuing authority, effective date, clause content, applicable region, and implementation standard. Field units are clearly defined: reserve scale is measured in ten thousand tons, rotation cycle in years, and subsidy standards in yuan per ton.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt link
Grain reserve policy documents are lengthy; a single document may contain dozens of clauses. Multi-turn dialogue requires retaining context to associate specific clauses referenced in user follow-up questions, so excessive historical messages must be limited to avoid interfering with current queries. The clearly defined field units require prompts to strictly align with unit descriptions to prevent unit confusion. Since data updates have no fixed cycle, prompts must explicitly require responses to only use the currently bound local knowledge base files, and not rely on outdated content from training data. Users may ask for detailed information such as the applicable region and effective date of a policy during multi-turn dialogue, so the `messages` parameter must be used to retain historical interaction content to ensure answer relevance.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 characters | Adapts to the typical length of single grain reserve policy documents, avoiding truncation of key clause content |
| Historical dialogue retention rounds | Top 5–10 rounds | Covers the common scope of user multi-turn follow-up questions, avoiding excessive historical messages from occupying context space |
| `variables` parameter configuration | Bind parameters such as user query region and grain category | Enables dynamic insertion of user-specific query conditions to improve answer targeting |
| `messages` parameter configuration | Append historical messages by conversation turn | Retains context association to ensure multi-turn dialogue can link previously referenced policy clauses |
| `chatId` parameter configuration | Serve as an independent identifier for conversations and logs | Distinguishes conversation records of different users, preventing associated system logs from being deleted when conversations are removed |
| Prompt template configuration | Fixed inclusion of "Only respond using the currently bound grain reserve policy documents" | Ensures response sources comply with requirements, avoiding reference to external unrelated content |

## Three Common Configuration Mistakes
- Issue: Code block returns undefined in the text content extraction module. Cause: The extracted code block variables were not correctly bound via the `variables` parameter, resulting in target parameters not being passed in the context.
- Issue: System logs are deleted after a user deletes a conversation. Cause: `chatId` was incorrectly used as the unique identifier for both conversations and logs, leading to associated logs being deleted when the conversation is removed.
- Issue: Previous referenced policy clause numbers cannot be linked during multi-turn dialogue. Cause: The historical message append configuration for the `messages` parameter was not enabled, only retaining the current single-turn query content and losing context association logic.

## How to Verify Proper Configuration
- Initiate a single-turn query, check that the response only references the currently bound grain reserve policy documents, with no external unrelated content.
- Initiate two consecutive follow-up questions, check that the system can associate the policy clause referenced in the first question without repeating background explanations.
- Test deleting a single conversation record, check that the system logs still retain the interaction data for that conversation.
- Enter a query with region and grain category parameters, check that the response correctly inserts the content bound via the `variables` parameter.
