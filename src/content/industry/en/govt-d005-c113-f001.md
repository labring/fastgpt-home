# Policy and Regulatory Basis Q&A for Shipbuilding: HTTP Interfaces and External Systems

## What the data for this category looks like
Policy and regulatory basis data for the shipbuilding industry originates from official announcements, industry standard documents, and internal compliance systems of central state-owned enterprises, released by the Ministry of Industry and Information Technology’s shipbuilding management departments, the Maritime Safety Administration of the Ministry of Transport, and the China Shipbuilding Industry Association. Updates occur on an irregular basis. The core policy revision cycle is approximately 1 to 2 years. Industry standards receive minor quarterly updates. The document structure includes fields such as document number, issuing authority, release date, applicable ship type (measured in gross tonnage and deadweight tonnage), core clauses, implementation requirements, and attachment list. Individual document lengths range from hundreds of characters to tens of thousands of characters.

## What constraints these characteristics impose on HTTP interfaces and external systems
Policy documents vary widely in length. Interfaces must support large text requests and responses. Proper timeout configuration is required. Fields include ship type parameters with units. External systems must validate unit formats when passing input parameters to avoid retrieval deviations. Policy update frequency is low. Knowledge base synchronization cycles do not need to be overly short. A stable incremental synchronization mechanism must be configured. Document structure is fixed but includes many fields. Specified parameters must be used to accurately map fields, ensuring retrieval and return accuracy.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Exclusive API key obtained from the FastGPT v4.17.0 backend | Used for interface identity verification to ensure call security |
| variables | Maps to the document number, issuing authority, and applicable ship type fields of policy documents | Ensures precise matching of policy dimensions in user queries during retrieval |
| responseData | Structured fields containing full policy text, document number, and release date | Enables external systems to directly parse and use returned results |
| Model and Knowledge Base Selection | Binds the shipbuilding policy knowledge base and specified embedding model preset in the FastGPT backend | Supports switching models and knowledge bases via API |
| Interface Timeout | 30 seconds | Adapts to loading and retrieval times for long policy documents |
| Knowledge Base Synchronization Cycle | Synchronize every 7 days | Matches the update frequency of shipbuilding policies |

## Three common configuration mistakes
- A 401 Unauthorized error is returned when calling the interface. This is caused by incorrect configuration of the `Authorization` parameter, using an invalid or expired API key.
- The knowledge base parsing status returned by the interface is empty. This is caused by failure to configure the parsing status mapping field in variables, leading to incomplete extraction of this information into `responseData`.
- Image pull times are excessively long when deploying with docker-compose. This is caused by failure to configure a domestic mirror source, resulting in insufficient download speeds.

## How to confirm configuration is complete
- Call the test interface, check that the `Authorization` verification passes, and no error messages are present.
- Check whether the returned `responseData` includes preset policy document numbers, release dates, and other fields.
- Manually trigger the knowledge base synchronization operation, confirm that the external system receives the synchronization completion status notification.
- Simulate a user query for shipbuilding-related policy clauses, check that the field matching degree of the returned results meets expectations.
