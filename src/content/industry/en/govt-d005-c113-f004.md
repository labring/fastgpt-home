# Policy and Regulatory Basis Q&A for Shipbuilding: Workflow Orchestration

## What the Data for This Category Looks Like
Policy and regulatory basis data for the shipbuilding sector comes primarily from official normative documents, industry standards, and shipyard compliance archives published by the Ministry of Industry and Information Technology, the Ministry of Transport, and the China Shipbuilding Industry Association. Data updates align with policy revisions, and syncs complete within 7 business days after a new policy releases. Each document includes fields such as document number, issuing authority, effective date, applicable ship type, core clauses, and compliance requirements. Fields use Chinese numbering, date formats, and industry terminology, with no additional quantitative statistical items.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Limit data sources to official channels. Add a data source validation node to the workflow to filter non-official content.
Policy updates have no fixed cycle. Embed a scheduled sync trigger node in the workflow to ensure data timeliness.
The document field structure is fixed. Configure preset regular expressions for matching document numbers and effective dates in the text extraction node to avoid extraction errors.
Policy content covers specific scenarios such as ship type and production capacity. The workflow must support filtering recalled content by ship type parameters in user questions to narrow the matching scope.

## Configuration Settings
This configuration uses FastGPT v4.17.0. Specific parameters are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data Source Configuration | Only select the official document libraries of the Ministry of Industry and Information Technology and the Ministry of Transport | Matches the official source requirements for shipbuilding policies |
| Text Extraction Rules | Preset regular expressions matching "Ministry of Industry and Information Technology [202X] XX Number" and "Article X" | Adapts to the fixed field format of policy documents |
| Scheduled Sync Trigger | Perform a full sync every 7 days | Matches the average cycle of policy updates |
| Context Recall Limit | Top 6 matching results | Prevents excessive policy clauses from causing context overload |
| Workflow Call Parameters | Bind the ship type field in `variables` | Supports filtering policy content by ship type parameters in user questions |
| Node Timeout Setting | 300 seconds | Adapts to the response duration of official document interfaces |
| Sub-workflow Binding | Bind the `nodeId` of the target workflow | Ensures the called sub-workflow accurately matches the business scenario |

## Three Common Misconfigurations
- Phenomenon: After workflow A calls workflow B, all nodes after the [User Selection] node in workflow B have no execution logs. Reason: No output parameters are configured for the [User Selection] node in workflow B, preventing upstream nodes from passing trigger signals.
- Phenomenon: The text extraction node returns empty values. Reason: The regular expression for the policy document's number format is not matched, so the number field of official documents cannot be identified.
- Phenomenon: The workflow returns non-official policy content after triggering. Reason: The data source range is not restricted, and non-compliant third-party documents are mistakenly introduced.

## How to Confirm the Configuration Is Complete
- Manually trigger the workflow, enter a question that includes a specific ship type, and verify that the recalled content only includes officially released policy documents.
- View the data source sync logs to confirm that the scheduled sync task executes successfully according to the preset cycle.
- Call workflow A to trigger the bound workflow B, and check that the nodes after the [User Selection] node in workflow B have execution logs.
- Review the output results of the text extraction node to confirm that preset fields such as policy document numbers and effective dates can be extracted correctly.
