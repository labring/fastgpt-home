# Policy and Regulatory Basis Q&A for Shipbuilding: Tool Calling and Plugins

## What this category of data looks like
Policy and regulatory basis data for the shipbuilding sector primarily comes from official documents and industry standards released by the Ministry of Industry and Information Technology, the Ministry of Transport, and the China Shipbuilding Industry Association. Data updates align with annual industry compliance requirements. Core documents include fields such as document number, issuing authority, effective date, applicable vessel type scope, technical parameter thresholds, and compliance determination clauses. Units mostly use common shipbuilding industry metrics like gross tonnage, kilowatts, and meters. Document lengths vary widely, ranging from hundreds-of-word notices to full specifications tens of thousands of words long.

## What constraints do these characteristics impose on the tool calling and plugins workflow
The varied length of shipbuilding policy documents requires configuring differentiated context truncation rules for short notices and long specifications to avoid cutting off core compliance clauses. The presence of specialized metric fields requires plugins to include built-in shipbuilding terminology mapping logic to accurately identify parameter thresholds corresponding to specialized units like gross tonnage and kilowatts. The annual update cadence of policy data requires configuring a scheduled pull trigger mechanism for the policy library in tool calling to ensure returned content uses the latest version. The applicable vessel type classification field requires the tool to automatically associate the policy subset for the corresponding vessel type when receiving user queries, narrowing the search scope.

## How to set the configurations
This chapter’s configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Force enabled | Ensure tool calling strictly matches specialized parameters and fields from shipbuilding policies |
| `toolChoice` | Limited to policy retrieval functions | Prevent tool calling from triggering unrelated functions, focus on shipbuilding policy queries |
| Policy library update cycle | 7 days | Align with the annual industry policy update rhythm, balance timeliness and call efficiency |
| Single retrieval document limit | Top 8 entries | Cover policy coverage for most shipbuilding scenarios, avoid redundant results |
| Context truncation threshold | 1200–1500 characters | Adapt to the core clause length of most shipbuilding policy documents, avoid information loss |
| Batch retrieval concurrency | 2 | Balance retrieval efficiency and interface load, match the single retrieval volume of the shipbuilding policy library |

## Three common misconfigurations
- Phenomenon: The policy clauses returned by the tool do not match the vessel type specified in the user’s query, and the number of results exceeds expectations. Cause: The retrieval filtering logic associated with the vessel type field is not configured, leading to an overly broad search scope and insufficient tool calling accuracy.
- Phenomenon: No streaming output results are obtained when calling the conversation via API, and the returned content is in single-packet synchronous format. Cause: Streaming response configuration is not enabled, and the streaming transmission logic is not activated for tool calling.
- Phenomenon: Irrelevant multimodal processing workflows are triggered during tool calling, returning meaningless image recognition results. Cause: `toolChoice` is not limited to policy retrieval functions, leading to uncontrolled tool calling scope and invocation of unconfigured plugins.

## How to confirm the configuration is correct
- Initiate a query that includes specific vessel type parameters and specialized units, verify whether the policy documents returned by the tool are associated with the applicable scope of the corresponding vessel type.
- Check the tool calling logs to confirm that only policy retrieval-related functions are triggered, and no unrelated plugins or multimodal processing workflows are called.
- Check the last update time of the policy library to confirm it matches the configured update cycle.
- Initiate an API call test to confirm that the returned results support the streaming output format.
