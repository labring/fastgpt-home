# Policy and Regulatory Reference Q&A for Telecommunications Engineering Construction: Workflow Orchestration

## What this category of data looks like
Telecommunications engineering construction policies and regulatory references primarily come from official documents issued by the Ministry of Industry and Information Technology, Ministry of Housing and Urban-Rural Development, and provincial communications administrations. These documents include telecommunications engineering quality management measures, construction project approval specifications, construction safety regulations, and similar materials. Updates are issued immediately when new regulations are released, with no fixed cycle.

Each document follows a standardized structure with five fields: issuing document number, issuing authority, effective date, applicable scenario, and core clauses. The document number format is `MIIT Notice [Year] XX No.`. Effective dates use the YYYY-MM-DD standard format. Individual document lengths range from 1000 to 5000 characters.

## What constraints these characteristics impose on the workflow orchestration link
Policy sources are scattered across multiple departments and regional levels. This requires the workflow to support dynamic matching of knowledge bases from different sources. Effective dates are strongly tied to project cycles. This requires the workflow to automatically filter valid policies that align with the project’s time range. Documents have relatively long content. This requires workflow nodes to have sufficient processing time and text parsing capabilities. Some policies contain region-specific clauses. This requires the workflow to dynamically adjust the retrieval scope using project location parameters passed externally.

Workflow orchestration must balance flexibility and accuracy to avoid invalid retrieval or return of expired policies.

## Three common mistakes
- Symptom: Manually inserting HTML audio or video tags in a custom response node results in the interface still displaying plain text. Cause: FastGPT v4.17.0 disables rendering permissions for non-standard text tags by default. The policy Q&A scenario requires strict matching of official document formats, and the node’s HTML rendering configuration is not enabled.
- Symptom: Custom knowledge base parameters cannot be passed via the API when configuring a knowledge base search node. Cause: The `variables` external passing permission for the workflow is not enabled, and the knowledge base selection item is not bound to the passed variable.
- Symptom: The document number and effective date fields returned by the text extraction node are empty. Cause: The dedicated field structure of telecommunications engineering policy documents is not matched, and extraction rules for the corresponding fields are not specified, leading to parsing failure.

## How to confirm the configuration is complete
- Pass test project location parameters, check if the workflow automatically matches the telecommunications engineering policy knowledge base for the corresponding region.
- Trigger the workflow, then check if the returned results include policy clauses with effective dates that fit the project’s time range.
- Call the API to pass a custom project start date parameter, confirm that results dated earlier than this date are automatically filtered out.
- View the workflow node’s running logs, confirm there are no error messages such as timeouts or failed field extraction.
