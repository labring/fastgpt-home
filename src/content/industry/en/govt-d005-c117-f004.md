# Policy and Regulatory Basis Q&A for Communication Towers and Infrastructure: Workflow Orchestration

## What the data for this category looks like
Policy and regulatory basis data for this category is mainly sourced from official documents released by the Ministry of Industry and Information Technology, provincial communications administrations, and China Tower Co., Ltd. Update rhythm is adjusted irregularly alongside policy revisions. Internal operation and maintenance documents are updated quarterly. The document structure includes five core fields: document number, issuing authority, effective date, clause number, applicable sub-scenario, and specific requirements. Document numbers follow the format "Ministry of Industry and Information Technology Tong [Year] XX No.". Effective dates use the standard YYYY-MM-DD format. The applicable sub-scenario field marks scenarios such as base station construction, operation and maintenance, and spectrum management. Standard engineering units such as meters, kilowatts, and square meters are used.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered and update rhythm is inconsistent. Workflow configuration must include multiple data source synchronization nodes, supporting batch data pulling from official websites and internal document libraries. Document fields include specially formatted document numbers and effective dates. Workflow configuration must include a `variables` extraction node to accurately capture field values and perform format validation. Sub-scenario labeling requires adding a classification filter component to the workflow, retaining only policy clauses related to communication tower construction and operation. The diversity of engineering units requires built-in unit standardization conversion rules in the workflow to avoid unit confusion during Q&A.

## Three Common Mistakes
- Phenomenon: Tool call node returns Invalid JSON: Bad control character error. Cause: No escape processing for line breaks and special symbols in policy documents, resulting in invalid generated JSON format.
- Phenomenon: Components in the workflow cannot be pasted to other workflows, and drag-and-drop movement is unresponsive. Cause: Workflow template was not exported correctly, or the component's `nodeId` was not properly synchronized to the target workflow.
- Phenomenon: Cannot add connection lines to tool call nodes, no connection small circles appear on the interface. Cause: Component connection permission for the workflow is not enabled, or the node type does not match the current link requirements.

## How to Confirm Proper Configuration
- View data source synchronization logs to confirm that the pull quantity and update time of policy documents meet preset requirements.
- Test the variable extraction node to confirm that core fields such as document number and effective date are correctly captured.
- Run the tool call node to confirm that the returned content format meets expectations and has no syntax errors.
- Try copying components in the workflow to confirm that cross-process paste and reuse is possible.
