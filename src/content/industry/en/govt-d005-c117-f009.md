# Policy and Regulatory Basis Q&A for Communication Towers and Infrastructure: Model Access and Configuration

## What the data for this category looks like
Policy data for communication towers and infrastructure is primarily sourced from normative documents related to communication infrastructure construction and operation and maintenance issued by the Ministry of Industry and Information Technology and the Ministry of Housing and Urban-Rural Development, as well as relevant internal policy manuals and industry operation and maintenance procedures. Documents mostly follow a chapter-based structure, including fields such as policy number, issuing authority, effective date, applicable scenarios, and implementation requirements, with units related to construction height, coverage scope, and operation and maintenance cycle included. The data update schedule aligns with national policy adjustments or industry standard updates, with no fixed cycle. This document is written based on FastGPT v4.17.0.

## What constraints these characteristics impose on the model access and configuration link
The long-text structure of policy documents requires model access to adapt to large context processing to avoid truncating key policy clauses. Structured fields such as policy number and effective date require configuration to support precise field matching logic to ensure response accuracy. The lack of a fixed update schedule requires configuration to support a flexible knowledge base synchronization mechanism to update the latest policy content in a timely manner. The presence of multiple unit types such as meters, kilowatts, and operation and maintenance cycles requires the model to have unit identification and verification capabilities to avoid unit confusion in responses.

## How to set up the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Communication tower policy documents are mostly long texts, requiring sufficient capacity for complete policy clauses and multi-turn conversation history context |
| `maxTokens` | `2000–3000 token` | Policy Q&A needs to cover clause details while controlling output length |
| `quoteMaxToken` | `1500 characters` | Need to retain the complete semantics of original policy fragments to avoid truncating key supporting content |
| `temperature` | `0.2–0.4` | Policy Q&A needs to strictly match the original text, reducing randomness to ensure response accuracy |
| `toolChoice` | `auto` | Need to automatically select whether to call the knowledge base or tools based on user questions, adapting to multi-scenario policy queries |
| `AIPROXY_API_ENDPOINT` | Fill in the officially specified endpoint according to the deployment environment | Ensure the correct network path for model calls, avoiding connection failures |
| `AIPROXY_API_TOKEN` | Fill in the valid key for the corresponding model | Complete identity verification for model calls to ensure access permissions |

## Three common configuration mistakes
- Symptom: In a locally deployed FastGPT environment, a 403 status code (no body) is returned when testing after adding a new model. Cause: `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` is not configured correctly, leading to identity verification failure or incorrect path.
- Symptom: When accessing an application created in the workspace via the API release channel, multi-turn conversation context is lost, and responses cannot continue the previous query logic. Cause: The `maxContext` parameter is not set correctly, causing the context window to be insufficient to accommodate the historical content of multi-turn interactions.
- Symptom: After calling data via Function CALL, original database fragments cannot be referenced, only summarized content is returned. Cause: The `quoteMaxToken` parameter is not configured to retain the original text length, or the original text reference logic after tool calling is not enabled.

## How to verify successful configuration
- Initiate a single-turn query about communication tower construction policies, verify that the content returned by the model includes accurate policy clauses and original fragments, and check the retention effect of `quoteMaxToken`.
- Initiate consecutive multi-turn policy queries, verify that the context is correctly loaded and responses continue the previous query logic, and check the configuration effect of `maxContext`.
- Submit an incorrect API key or endpoint, verify that the system returns a corresponding error, and check the configuration correctness of `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT`.
- Adjust the `temperature` parameter to 0.1, verify the rigor of responses, and confirm the effect of the parameter on controlling response randomness.
