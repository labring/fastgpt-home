# Policy and Regulatory Basis Q&A for Metal Material Processing: Workflow Orchestration

## What This Category of Data Looks Like
Metal material processing policy and regulatory basis data mainly comes from iron and steel and non-ferrous metal industry policy documents released by the Ministry of Industry and Information Technology and the State Administration for Standardization, as well as national and industry standard documents for metal materials. The data update rhythm is as follows: national standards revise a small number of core clauses each year, and industry policies update quarterly per regulatory requirements. Document structure includes fields such as policy document number, issuing authority, effective date, applicable process scope, clause content, violation penalties and declaration requirements. Field units include document number format, date format, process classification tags and more. A single document covers multiple processing scenarios such as hot rolling, cold rolling and alloy smelting.

## What Constraints These Characteristics Impose on Workflow Orchestration
Policy documents vary widely in length and contain substantial content per piece. This requires the workflow to support long text segment retrieval and merged output, to avoid context overflow. Policies include clear applicable process scope fields. This requires the workflow to set branch nodes based on metal processing processes, to accurately match corresponding policy clauses. Data update frequency is relatively fixed but requires regular synchronization. This requires the workflow to integrate a timed-triggered data source update step, to ensure retrieved policies are up to date. Effective dates and document numbers are core verification fields. This requires the workflow to add timeliness filtering logic during retrieval, to automatically exclude expired policies.

## How to Configure Settings

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Pass policy applicable process and effective date range | Accurately match policy fields for metal material processing scenarios, narrow retrieval scope, and improve answer accuracy |
| `nodeId` | Set unique identifiers for branch nodes such as hot rolling, cold rolling, alloy smelting | Distinguish policy retrieval branches for different metal processing processes, avoid workflow routing confusion |

| Timed synchronization cycle | Every 7 days | Industry policy update frequency is quarterly; regular synchronization ensures timeliness of retrieved data |
| Branch trigger condition | Match the process type in user questions | Automatically jump to the policy retrieval node for the corresponding processing process, adapting to different business scenarios |

## Three Common Mistakes
- Phenomenon: The workflow cannot perform retrieval in a loop per metal processing process, only executes a single branch. Cause: No independent `nodeId` configured for each process branch, leading to workflow routing logic conflicts and inability to trigger multi-branch loops.
- Phenomenon: Tool calls work normally in debug mode, but an "parameter undefined" error occurs in runtime mode. Cause: No process type parameter corresponding to the user's question passed in `variables`. Debug mode fills test parameters by default, while runtime mode has no default parameters, leading to retrieval failure.
- Phenomenon: Exported workflow conversation records only show the last 6 questions, and cannot export the full session. Cause: The workflow did not enable full context recording configuration, only retaining the latest conversation fragments, with no complete record storage rules set.

## How to Confirm the Configuration is Correct
- Check that the `variables` configuration item includes the policy applicable process and effective date range fields, ensuring retrieval parameters are complete.
- Trigger test questions for different process types, verify that the workflow jumps to the corresponding branch node and returns matching policy content.
- Manually trigger the timed synchronization task, confirm that the data source updates successfully with no error logs.
- Launch a multi-round conversation test, export the conversation records, confirm that all conversation fragments are fully exported.
