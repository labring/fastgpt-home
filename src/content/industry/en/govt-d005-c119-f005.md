# Policy and Regulatory Basis Q&A for Iron and Steel Smelting: Tool Calling and Plugins

## What this category of data looks like
This category of data covers policy and regulatory basis questions for the iron and steel smelting field.
It draws primarily from official documents released by the Ministry of Industry and Information Technology, State-owned Assets Supervision and Administration Commission, and provincial-level industry and information departments.
It also includes industry standards compiled by the China Iron and Steel Industry Association.
Update frequency follows the schedule of policy releases, with no fixed cycle.
Single policy documents range from 5000 to 10000 characters in length.
Document structures include document number, issuing authority, effective date, applicable processes, and core clause content.
Applicable processes include blast furnace ironmaking, converter steelmaking, and steel rolling and forming.
Fields covered include pollutant emission limits, capacity replacement requirements, safety production specifications, and more.
Units use industry standard values like mg/m³, ton, and cubic meter.

## What constraints these characteristics impose on tool calling and plugin workflows
Iron and steel smelting policy documents are lengthy, with clearly segmented clauses.
Tool calling must support long-text retrieval and clause-by-clause matching. This prevents truncation of critical information.
Official data sources carry authoritative status. Plugins must bind verifiable official link indexes to prevent calls to non-compliant data sources.
No fixed update cycle creates specific requirements. Plugins must support manual data source synchronization, or configure automatic synchronization logic that checks for updates quarterly.
Policy requirements differ across production processes. Tool calling must support filtering matching policy clauses using smelting process keywords. This narrows the search scope.

| Content truncation rule | Retain complete clauses | Avoids splitting policy clauses which leads to understanding inaccuracies |

## Three common configuration errors
- When previewing the plugin, policy content is retrieved but the final output is empty. This happens because the plugin did not correctly bind the index mapping for the iron and steel smelting policy data source. Search results cannot then be linked to the conversation context.
- After using chunk mode to call the pushdata API to upload policy files, the index status always shows "in progress". This occurs because `toolChoice` was not configured to trigger mode. The index status is not synchronized to the conversation chain as a result.
- Calling tools via the API fails to return the referenced policy file name. This happens because the `functionCall` traceability configuration was not enabled. The metadata return field was not activated either.
