# Policy and Regulatory Basis Q&A for Railway Operations: Citation Sources and Traceability

## What the data for this category looks like
Railway operation policy and regulatory basis data mainly comes from regulations, normative documents, and operation rules officially released by the National Railway Administration and China State Railway Group Co., Ltd., as well as operation rules from individual railway bureaus. Data updates are synchronized with official policy releases, with no fixed cycle. A single document usually includes fields such as document number, issuing authority, effective date, clause number, applicable scenario, and specific clause content. Field units are uniformly "article", "subparagraph", and "paragraph". Effective dates use standard Gregorian calendar format.

## What constraints do these characteristics impose on the "citation sources and traceability" link
The document number and effective date of railway operation policies are core identifiers for traceability. Precise matching during retrieval is required to ensure citation legality. The clause hierarchy (article, subparagraph, paragraph) format varies across different documents. Hierarchical relationships must be preserved to restore complete supporting basis. Policy updates have no fixed cycle. The knowledge base’s data source range must be adjusted synchronously to avoid citing expired documents. Railway operation policies involve heavily regulated areas such as safety and transportation. Citation traceability must clearly link to the original issuing entity. Relying solely on content matching is not sufficient, as this fails to meet compliance requirements.

## How to set up the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | The content length of a single clause in railway policies is moderate. This range can fully cover core supporting basis |
| `responseData` | Structured source + original text | Required fields for traceability such as document number and effective date must be included |
| `detail` | Enabled | Original clause text must be returned to support manual traceability verification |
| Single recall limit | Top 5 results | Railway policy questions usually relate to 1-3 core documents. This avoids redundant results |
| Source matching rule | Match by document number + effective date | Matches the unique identifier of railway policies, prevents traceability errors caused by duplicate content |

## Three common mistakes
- Symptom: The knowledge base retrieval node returns empty results or a red error when referencing the global variable datasetid. Cause: Variable mapping is not bound during the knowledge base selection step of the workflow, causing the variable to not be passed correctly.
- Symptom: Only the first round of multi-turn QA displays knowledge base citation sources. Subsequent rounds show no citation content. Cause: The traceability cache switch for conversation context is not enabled, causing subsequent rounds to not link to historical knowledge base results.
- Symptom: Retrieval results show citation sources with no document number, using vague content. Cause: The matching rule based on document number + effective date is not configured. Relying solely on content keyword matching leads to duplicate or invalid sources.

## How to confirm the configuration is complete
- Submit a question related to railway policies. Check if the returned result includes traceability fields such as document number and effective date.
- Test multi-turn QA. Confirm that each round of results displays the corresponding citation source.
- Manually cross-check the returned clause original text against official policy documents to confirm the matching meets expectations.
- Adjust the `quoteMaxToken` parameter. Verify that the length of returned citation content falls within the configured range.
