# Policy and Regulatory Basis Q&A for Expressway Operations: Citation Sources and Traceability

## What the data for this category looks like
This category's data primarily comes from official policy documents, industry standards, and local expressway operation management regulations issued by the Ministry of Transport and provincial transport departments. Data updates are triggered when new policies are released, with no fixed cycle. Each document includes fields such as document number, issuing authority, effective date, applicable road section scope, and core clauses. Units follow standard Chinese official document formatting, clauses are marked in chapter + article format, and some local documents include special management requirements for toll stations and service areas under their jurisdiction.

## What constraints do these characteristics impose on the "citation sources and traceability" link?
The document number, effective date, and applicable road section fields of official policies require that traceability must return exact corresponding metadata. Fuzzy content snippets alone cannot be used for traceability. Special management documents from different jurisdictions have format differences. Retrieval must automatically associate exclusive rules for corresponding road sections to avoid cross-region citation errors. Clauses marked in chapter + article format require preserving the original chapter path during traceability. This ensures the location of cited clauses can be traced. The non-fixed update cycle requires displaying the latest version identifier of the document alongside traceability information. This prevents referencing expired old policies.

## How to configure this
The following configurations apply to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single search limit | Top 8 results | Expressway policy documents have a moderate volume. The top 8 results cover the core policy scope and avoid redundant results |
| Maximum context length | 1200–1800 characters | Policy clauses are typically short paragraphs. This length fully carries key content from a single core document |
| `quoteMaxToken` | 300–500 token | Limits token usage per citation. This ensures multiple sources can be displayed in the response |
| `detail` | Enable full metadata | Ensures returned citations include all required traceability fields such as document number and effective date |
| `responseData` | Structured format | Ensures cited sources can directly extract source fields, making traceability information easy to display in the interface |

## Three common configuration errors
- Only the "Knowledge Base Citation (1 entry)" label is displayed below the response. This occurs when the single search limit is set to 1, or when multi-document recall logic is not enabled during retrieval.
- An insufficient citation limit error is prompted when calling the knowledge base. This occurs when `quoteMaxToken` is set too small. It cannot carry the metadata and content snippets of multiple policy documents.
- The application has no selected content by default after importing the knowledge base. This occurs when no default knowledge base association rule is configured, or when automatic binding to the application was not checked during import.

## How to confirm the configuration is complete
- Submit a test query containing policy keywords. Check if the number of citation sources displayed below the response matches the configured single search limit.
- Review the displayed content of each citation source. Confirm that it includes metadata fields such as document number, effective date, and applicable road section.
- Adjust the `quoteMaxToken` value. Verify that the number of citations displayed in the response changes accordingly.
- After importing local policy documents, confirm that the application can automatically associate the knowledge base without manual selection.

The values provided are common starting points and should be measured against the reader's own samples.
