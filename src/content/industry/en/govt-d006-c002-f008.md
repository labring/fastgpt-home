# Document and Material Drafting for "One Thing Done Efficiently" Joint Handling: Document Parsing and Chunking

## What this category of data looks like
The data for this category comes primarily from the national government service platform "One Thing" special zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. Update frequency is daily.
Commonly processed documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts.
Document structures typically include cross-departmental associated fields: leading department, associated departments, material items, handling links, and more. Field units are mostly item, copy, and entry. Some forms contain structured content such as applicant information and approval opinions.

## Constraints imposed on the document parsing and chunking link
Documents from multiple sources have large format differences, including standardized PDFs, electronic forms, and scanned image files. The parsing link must adapt to diverse layouts and formats.
Daily updated batch materials require efficient parsing processes, to avoid delaying joint handling item circulation due to excessive processing time.
Cross-departmental associated content requires chunking to retain business logic. It must not split the front-back relationship of items or material reuse rules. Otherwise, joint handling process stagnation may occur.
Documents with many structured fields must retain full field associations after chunking, to avoid information loss that affects subsequent approval work.

## Configuration settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Joint handling documents contain cross-departmental associated content. Chunks that are too long lose contextual associations. Chunks that are too short damage material integrity. This setting is calibrated to the average length of government joint handling documents. |
| `chunkSplitter` | Split by paragraph + title | Joint handling documents have clear item titles and departmental link titles. Splitting by title retains business logic, and avoids mixing content across links. |
| `customPdfParse` | Enable enhanced mode | Some joint handling materials are scanned files or PDFs with embedded complex tables. Enhanced mode supports parsing image text and complex layouts. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Joint handling documents may contain summaries of approval opinions from multiple departments, which have long parsing times. This setting avoids interrupting the parsing process due to timeout. |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploading of full material lists and historical circulation documents for joint handling items, adapting to batch processing needs in government scenarios. |
| `chunkSettingMode` | Manual configuration | Different types of joint handling documents (such as list types, application form types) can flexibly adjust chunking parameters, adapting to diverse business document structures. |

## Three common configuration mistakes
- After uploading a joint handling notice in image format, the parsing result is empty or has missing fields. The `customPdfParse` enhanced parsing mode is not enabled. The default parsing cannot recognize text content embedded in images.
- After deploying FastGPT locally and enabling enhanced PDF parsing, the local MinerU interface cannot be called. The local API address and port of MinerU are not configured in FastGPT's knowledge base settings, causing parsing requests to fail to route to the deployed container service.
- After enabling multi-vector support, table data in joint handling application forms does not generate corresponding vectors. The independent chunking logic for table content is not enabled in the chunking configuration. This causes table data to be merged into ordinary text blocks, and the multi-vector generation rule is not triggered.

## How to confirm configurations are correct
- Upload a single-page scanned joint handling material. Check whether the parsing result contains the text content in the image, to confirm that `customPdfParse` is enabled.
- Call the local MinerU API interface to test port connectivity. Verify whether the MinerU address and port configured in FastGPT are correct.
- Upload a joint handling item list containing complex tables. Check whether the chunking result splits table content into independent vector entries, to confirm that the multi-vector support configuration is reasonable.
- Upload a single joint handling document package exceeding 500 MB. Verify that uploading and parsing do not trigger timeout errors, to confirm that the `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations are reasonable.

The values given here are common starting points and should be measured against the reader's own samples.
