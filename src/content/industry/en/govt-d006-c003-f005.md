# Document and Material Drafting for Real Estate Registration: Tool Calling and Plugins

## What the Data for This Category Looks Like
This category's data mainly comes from real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. The update frequency is daily. Commonly processed documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and real estate registers. Document fields cover real estate location, owner information, right type, surveying and mapping area, tax payment status, and more. Some electronic certificates require extracting structured fields from the unified repository. No additional statistical or fabricated data is included.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Workflow
Data for this category is obtained across multiple systems, so tool calling must adapt to the interface formats of different data sources. The daily update requirement means plugin calls must maintain real-time response speeds. Commonly processed document types are diverse, so support is needed for content parsing and field extraction of different formats such as registration applications and surveying and mapping results. Fields involve sensitive and strongly correlated information such as owners and right types, so tool calling must strictly match field mapping rules to avoid data misalignment. The real estate register is the core output carrier, and documents generated by tools must fully align with the register's fields, otherwise registration errors or property right disputes may occur.

## Configuration Settings
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the automatic calling needs of multiple document and data source types, no need to manually specify a single tool |
| `functionCall` | Enable structured output | Ensure that the generated document fields strictly align with the real estate register format, preventing unstructured content from being unable to be stored in the database |
| Plugin call timeout | 30–60 seconds | Cover the normal response duration of cross-system data pulling, avoiding overall process interruption due to delays from a single system |
| Maximum number of returned entries per single tool call | First 3 entries | Control the returned data volume, adapting to the normal carrying limit of the system context |
| Field mapping verification switch | Enable | Verify the matching degree between generated documents and system fields, early detecting misalignment issues of key information such as ownership and area |
| Multi-source data merging strategy | Associate by owner + location | Match the core association dimension of real estate registration data, ensuring accurate merging of information from different systems |

## Three Common Errors
- The real estate location field is empty in the results returned when calling the API. The cause is that the multi-source data merging strategy by owner + location is not configured, and data pulled across systems is not correctly matched.
- The tool calling process times out and returns timeout-related status codes. The cause is that the set timeout duration is shorter than the average duration of cross-system data pulling, and does not cover the integration time of multi-source data.
- The generated document fields do not match the real estate register format. The cause is that the structured output switch for `functionCall` is not enabled, and the content generated by the large model does not follow fixed field rules.

## How to Confirm the Configuration Is Complete
- Manually trigger a tool calling process, check whether the returned document fields include the required items for registration applications and ownership certificates.
- View the plugin call logs, confirm that the multi-source data merging strategy by owner + location is executed normally.
- Verify that when `toolChoice` is configured as `auto`, the system can automatically select the plugin for the corresponding data source to pull data.
- After enabling the field mapping verification switch, input a set of test content that does not match the system fields, confirm that the system can trigger verification prompts.
