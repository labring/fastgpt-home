# Document and Material Drafting for Real Estate Registration: Citation Source and Traceability

## What the data for this category looks like
Core documents for real estate registration scenarios include registration application forms, ownership certificates, survey results, tax payment vouchers, real estate ownership certificates, property registers, and more. Fields cover right holder information, real estate certificate number, location, area, and other relevant details.
Data sources include the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate library. The update frequency is once per day.
Documents are split into two categories: structured fields and unstructured attachments. Unique identifiers from each system must be linked to avoid data confusion.

## Constraints imposed on citation source and traceability by these characteristics
Multi-system data sources require clear association with each system's unique identifier during citation to prevent cross-system data misattribution.
The daily update frequency requires configuring daily incremental sync tasks to ensure cited ownership information is up to date.
Diverse document types require configuring different citation rules based on registration document type. For example, survey data needs coordinate field comparison, and ownership certificates need right holder information verification.
The high severity of potential errors requires the full traceability chain to be retained, with no source links omitted. This ensures every citation can be traced back to the original data source.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Documents related to real estate registration have long fields and attachment content. Sufficient length is needed to fully display the original cited content |
| `responseData` | Enabled | Specific field information of the original data source must be returned to meet the traceability and verification requirements of registration documents |
| `detail` | Full | Registration documents need to accurately present ownership source details. Key information such as right holder and location must not be omitted |
| Data Source Scope | Real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, electronic certificate library | Only use legally compliant official data sources for this category |
| Sync Frequency | Daily incremental sync | Match the daily update frequency of data sources to ensure the timeliness of cited content |
| Citation Limit | Top 3 entries | Ownership source associated data for a single registration document usually does not exceed 3 items, avoiding redundant content interfering with generation |

## Three Common Mistakes
- Phenomenon: The generated registration document does not include the original data source text fragment, only showing descriptive summaries. Cause: The `responseData` configuration is not enabled, and the return rule for the corresponding data source is not bound.
- Phenomenon: The knowledge base citation limit cannot be adjusted, resulting in insufficient cited content to cover complete ownership information. Cause: The citation limit is not adjusted, or the value range of `quoteMaxToken` is incorrectly restricted.
- Phenomenon: A context overflow error occurs in the generated document. Cause: The value of `quoteMaxToken` is not restricted, or the value exceeds the maximum token threshold allowed by the system.
