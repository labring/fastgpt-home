# Document and Material Drafting for Real Estate Registration: Document Parsing and Chunking

## What the data for this category looks like
The core data for this category comes from the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate library, and is updated daily. Commonly processed documents include registration applications, ownership certificates, survey results, tax payment vouchers, real estate ownership certificates and registers. These documents contain structured form fields, multi-format tables, and images such as parcel maps and house floor plans. Fields cover real estate right types, area, location, right holder information, and other details. There is no fixed unified format template, and the structure of documents from different sources varies significantly.

## Constraints imposed on document parsing and chunking
Heterogeneous documents from multiple sources require the parsing module to adapt to different formats of forms, tables, and images, to avoid missing content or format errors. The daily updated business rhythm requires the parsing process to have stable throughput, to prevent task backlogs caused by timeouts. The accuracy requirement for ownership-related fields in documents means semantic integrity must be retained during chunking, and associated information must not be split. For example, area data in survey results must not be separated from ownership certificates. At the same time, the associated attributes of real estate registration documents require retaining cross-document context associations during chunking, to ensure that complete right basis can be obtained during retrieval.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Real estate registration documents include structured fields and long text descriptions. This range balances single-chunk information integrity and retrieval granularity |
| `chunkSplitter` | Split by paragraph + heading | Documents often contain hierarchical application instructions and survey data. Splitting by paragraph preserves semantic coherence |
| `customPdfParse` | Enable table and image extraction mode | Daily documents include images such as survey results and parcel maps, as well as tax detail tables. Enabling this mode improves recognition completeness |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | A single registration material may include multiple attachments. Sufficient parsing time must be reserved |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch import of multi-page documents exported from cadastral survey databases |
| `chunkSettingMode` | Manual configuration | Chunking parameters must be adjusted for different document types to adapt to differences between registration applications and survey reports |

## Three Common Misconfigurations
- Phenomenon: Knowledge base retrieval returns no results, and the interface shows a file parsing failed status code 400. Cause: `UPLOAD_FILE_MAX_SIZE` is not set to adapt to the single-file size of real estate registration documents, or `PARSE_FILE_TIMEOUT_SECONDS` is set too short, causing large file parsing timeouts.
- Phenomenon: Tables and images in imported Word documents are not fully recognized. Parsed content has missing table data and empty text corresponding to images. Cause: The multi-format extraction mode of `customPdfParse` is not enabled, or cross-page tables or text content associated with images is truncated during chunking.
- Phenomenon: The ownership basis text corresponding to the references field does not appear in retrieval results. Cause: `chunkSplitter` is not configured to retain reference paragraphs, or the extraction logic for non-core fields is skipped during parsing.

## How to Verify Proper Configuration
- Upload a single registration application containing tables and images, and check if the parsed text includes complete table content and image descriptions.
- Test a single cadastral survey document of approximately 800 MB in size, and confirm that the parsing status shows success with no timeout errors.
- Search for preset ownership field keywords, and confirm that the returned chunked content includes complete information for the corresponding fields.
- Adjust the `chunkSize` parameter to the range of 600 to 1500 characters, and check if the length of the chunked text matches the expected range.

The values provided are common starting points and should be measured against the reader's own samples.
