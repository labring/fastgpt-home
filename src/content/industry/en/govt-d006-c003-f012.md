# Document and Material Drafting for Real Estate Registration: Deployment and Upgrade

## What the data for this category looks like
The data for this category primarily comes from the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate repository. The update frequency is daily. Commonly processed documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real property right certificates, and real estate registers. Document fields cover right holder information, real estate location, right type, area, ownership restriction status, and more. Both structured data and unstructured scanned documents are present. Cross-system association and verification are required to generate documents that comply with registration regulations.

## What constraints these characteristics impose on the deployment and upgrade phase
Cross-system data sources require stable multi-source data access connections to be configured during deployment. The daily update rhythm requires indexing and synchronization tasks to adapt to high-frequency update scheduling rules. Processing multiple document types requires configuring tailored parsing logic for different document structures such as registration applications and surveying and mapping results. Registration errors can lead to property rights disputes and administrative litigation, so deployment must ensure high service availability. In Docker deployment scenarios, database connection parameters must be clearly configured to avoid process blocking caused by cross-system data association failures.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15 connections` | Adapts to daily high-frequency cross-system data synchronization and document parsing tasks, prevents connection pool exhaustion |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt_register` | Stores unstructured documents and session data for real estate registration, adapts to temporary caching needs for multi-source data |
| `PG_URL` | `postgresql://user:pass@pg-host:5432/register_db` | Retrieves structured ownership information and surveying and mapping data, ensures stable data reading |
| `REDIS_URL` | `redis://localhost:6379/0?maxIdle=10&expire=3600` | Caches frequently retrieved cadastral data and electronic certificate information, reduces cross-system request latency |
| `STORAGE_S3_ENDPOINT` | `http://s3.your-domain.com` | Stores generated registration documents and archived materials, ensures data persistence |

## Three common mistakes
- After deployment, a startup error indicates a database connection failure. The container log returns `connection refused`. The cause is that the database address for the real estate registration system pointed to by `MONGODB_URI` or `PG_URL` is not configured correctly, or the container port is not mapped to the host machine's database port during Docker deployment.
- After upgrading to FastGPT v4.17.0, an error is displayed in the generated registration document preview chart. The cause is that the chart rendering dependency of the document parsing module was not installed correctly after the upgrade, or the configured storage path has no write permission.
- The knowledge base indexing task remains in a running state with no progress. The cause is that the cache expiration and connection parameters of `REDIS_URL` are not configured properly, causing frequently updated cadastral data to repeatedly trigger indexing, or a deadlock occurs during cross-system data synchronization.

## How to confirm the configuration is complete
- Run the container log viewing command, confirm there are no abnormal messages such as database connection failures or storage permission errors.
- Initiate a registration application generation test, verify that the returned result includes required fields, and that the data matches the information from the associated real estate registration system.
- View the indexing task monitoring panel, confirm that daily updated cadastral data synchronization is completed, and there are no continuously accumulating indexing queues.
- Call the HTTP orchestration interface, confirm that the returned result includes generated document content, with no empty fields or abnormal errors.

The values provided are common starting points and should be measured against the user's own samples.
