# Document and Material Drafting for Property Rights, Asset and State-owned Capital Management: HTTP Interfaces and External Systems

## What the data for this category looks like
The data for this category primarily comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, assessment agency reports and financial statements, with a monthly update cycle. Daily documents involved include property rights registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval forms. Fields cover asset ownership numbers, appraisal benchmark values, transaction base prices, approval node statuses, and more. Units are mostly quantity, monetary amount, and percentage. A single core document has more than 15 required fields.

## What constraints do these characteristics impose on HTTP interfaces and external systems?
The monthly update frequency means interface calls do not need to run frequently, which avoids exceeding the interface permission limits of external systems. Heterogeneous data from multiple sources requires unified format validation, so interfaces must support field mapping and format conversion for different data sources. Strongly related fields such as ownership, transaction, and approval involved in documents require interface parameters to cover the full set of required fields. Because errors directly relate to state-owned asset loss and compliance accountability, interfaces must add exception retry, data validation, and alert mechanisms to prevent incorrect data from flowing to the document generation stage.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface timeout period | 600 seconds | When connecting to external systems such as state-owned asset supervision and property rights exchanges, data return requires multi-stage approval and verification, so sufficient response time must be reserved |
| `Authorization` verification method | Bearer Token | Complies with interface authentication specifications for most state-owned asset-related external systems, ensuring data transmission security |
| `variables` field mapping | Match by external system field names | Simplifies parameter passing logic when FastGPT is called, and adapts to field differences across different data sources |
| Single request data volume | 800–1200 characters | Matches the single-batch data transmission limit of most external systems, preventing requests from being intercepted or truncated |
| Error retry count | 3 times | Addresses temporary network fluctuations or system busy status, while avoiding transaction exceptions caused by repeated submissions |
| `responseData` parsing rule | Map by field priority | Ensures core ownership data is extracted first, adapting to field order requirements for document generation |

## Three common misconfigurations
- The asset ownership number field returned by the interface is empty, causing the generated property rights transfer plan to lack a core identifier. This happens when no default value is set for empty fields returned by external systems, and the completeness of required fields is not verified.
- Interface calls trigger a 429 status code, and requests are blocked by external system rate limiting. This happens when call frequency is not planned according to the monthly update cycle, and high-frequency requests exceed the interface permission threshold of the external system.
- The generated asset disposal approval form does not match actual transaction information, leading to transaction suspension. This happens when cross-verification of appraisal data obtained from the interface and financial statement data is not performed, and documents are generated using single-source data directly.

## How to confirm the configuration is complete
- Call the test interface to check whether returned asset and transaction fields match the original data displayed in the external system.
- Simulate a monthly batch call scenario to confirm the interface does not trigger external system rate limiting rules.
- Trigger an interface exception scenario to check whether the preset alert mechanism and retry logic activate.
- Generate a single standard document to verify all required fields have been fully extracted from the interface data.
