# Document and Material Drafting for Property Rights, Asset and State-owned Capital Management: Tool Calling and Plugins

## What data is included in this category
The core data for this category comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, valuation institution reports and financial statements, with a monthly update cycle. Daily processed documents include property rights registration forms, asset valuation reports, property rights transfer plans, on-site transaction announcements and asset disposal approval forms. Most document structures contain fixed fields such as ownership subject, asset details, valuation value, transaction conditions and others. Units involved include asset-related measurement standards such as ten thousand yuan, square meter, piece and similar units.

## What constraints do these characteristics impose on the tool calling and plugins workflow
Dispersed data sources and monthly updates require tool calling to interface with multiple systems, and adapt to field formats and permission rules of different systems. Fixed document structures with many fields require tool calling to accurately match property rights and asset-related fields, to avoid omitting ownership information or transaction conditions. Monthly updated batch data requires tools to support batch processing, to avoid overload from single calls. The consequences of errors are severe, so tool calling must add a pre-check link. This ensures generated documents comply with ownership and transaction requirements, and prevents state-owned asset loss or transaction suspension caused by incorrect materials.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `toolChoice` | Bind a dedicated property rights document generation tool | Ensure the calling logic focuses on document generation related to state-owned assets, avoiding generalized tool calls |
| `functionCall` | Enable forced calling mode | Force generated documents to include required fields such as asset ownership and transaction conditions, complying with business specifications |
| Maximum context length | 8000–12000 token | Cover monthly batch asset data, historical approval forms and valuation report content |
| Single call timeout threshold | 600 seconds | Adapt to the reading and verification duration of batch asset details, avoiding call interruptions |
| Tool retry count | 2 times | Respond to temporary exceptions in multi-system interfaces, ensuring stability of data acquisition |

## Three common errors
- Phenomenon: Tool calling errors occur when using non-Tongyi Qianwen models, with returned fields empty or formatted incorrectly. Cause: The tool calling format requirements are not adapted for the target model, and some models have varying compatibility with the `functionCall` format.
- Phenomenon: Concurrent requests appear during tool calling, causing the system to return duplicate tool selection results or abnormal statuses. Cause: Mutual exclusion trigger rules for tool calling are not configured, and multiple threaded requests trigger the tool selection logic simultaneously.
- Phenomenon: Unable to obtain the latest data in the asset system when calling the document reading plugin. Cause: The plugin is not configured to connect to the monthly data update interface of the state-owned assets supervision system, only reading old data from local cache.

## How to verify successful configuration
- Initiate a simulated call, pass a single asset disposal approval form data set, and check whether the generated document includes required fields such as ownership subject, asset details and approval process.
- Check the FastGPT v4.17.0 tool calling logs, confirm that each call triggers the preset property rights document generation tool, and no generalized calls occur.
- Test calls for multiple batches of monthly batch data, check for timeout or data truncation issues, and adjust relevant configuration items to meet business requirements.
- Trigger abnormal interface call scenarios, check whether the preset retry mechanism is activated, and confirm the stability of tool calling.
