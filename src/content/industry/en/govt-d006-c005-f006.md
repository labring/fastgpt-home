# Document and Material Drafting for Property Rights, Assets and State-owned Capital Management: Source Citation and Traceability

## What data for this category looks like
Data for this category primarily comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, appraisal agency reports, and financial statements. The update frequency is once per month. Daily generated documents include property rights registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval forms. Document structures include core fields such as ownership number, asset category, appraisal value, and transaction approval status. The length of a single core document is typically thousands of characters.

## How These Characteristics Impact Source Citation and Traceability
Multi-source, heterogeneous data sources require linking to multiple independent knowledge bases. Accurate permission configuration and field mapping for knowledge bases across different systems must be maintained. The monthly official update frequency requires matching the knowledge base synchronization cycle, to prevent citing outdated asset information. Documents include sensitive fields such as clear ownership and transaction details. Citations must accurately match corresponding asset entries, and asset information from different entities must not be mixed. Errors in citation traceability for this category can lead to serious outcomes including state-owned asset loss or transaction suspension. Traceability information must be complete and retrievable.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single recall count | Top 6 entries | Matches the number of core asset documents covered in a single round of questioning |
| `quoteMaxToken` | 1500–2000 token | Adapts to the average length of single core documents for this category |
| `responseData` | Enable returning associated document metadata | Meets the requirement to display document sources and generation times during traceability |
| `detail` | Enable detailed traceability mode | Supports displaying core field details of cited documents |
| Knowledge base synchronization frequency | Once per month | Matches the official update rhythm of data for this category |

## Three Common Misconfigurations
- Responses do not include asset content associated with the knowledge base, but the citation list shows matching knowledge base entries. The cause is incorrect configuration of metadata association for `responseData`, or failure to correctly inject recalled knowledge base content into the response context.
- Cited document fields do not match actual asset documents. For example, citing the appraisal value of asset A in the transfer plan for asset B. The cause is failure to retain unique ownership number fields during knowledge base chunking, leading to recalled content not matching the target asset.
- Old data is still cited after knowledge base synchronization is complete. The cause is setting the synchronization cycle longer than the monthly update frequency of this category, resulting in failure to pull the latest asset change information.

## How to Verify Correct Configuration
- Confirm that the deployed FastGPT version is v4.17.0.
- Check knowledge base synchronization logs to confirm the most recent synchronization completed without errors.
- Submit a test question targeting a specific asset, then check if the citation list under the response includes matching property rights or appraisal document entries.
- View citation details to confirm displayed fields include core information such as asset ownership number and appraisal value.
- Test content that exceeds the `quoteMaxToken` limit, then check if the response is truncated as configured and sources are labeled.

The values given are common starting points and should be measured against the reader's own samples.
