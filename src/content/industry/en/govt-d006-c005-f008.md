# Document and Material Drafting for Property Rights, Asset and State-owned Capital Management: Document Parsing and Chunking

## What this type of data entails
Typical stakeholders include state-owned assets supervision and administration authority property rights divisions, central enterprise asset management departments, and similar entities. Daily processed documents include property registration forms, asset evaluation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval slips. Data sources include state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, evaluation agency reports, and financial statements. Update frequency is monthly. Most documents contain structured fields and unstructured paragraphs. Some reports include tables with multi-column layouts. Fields cover asset ownership information, transaction approval nodes, evaluation values, and similar content. No unified format specifications exist for these documents.

## Constraints on document parsing and chunking
Multi-source data creates format differences that require parsing logic to adapt to document styles exported by different systems. Monthly updated batch documents require parsing processes to support stability and batch processing capabilities. Reports and announcements with multi-column tables and long approval paragraphs require chunking logic that avoids splitting key ownership fields and transaction nodes. Strict risk prevention and control requirements mandate that core data is not lost during parsing and chunking, to prevent issues such as state-owned asset losses or transaction suspensions in subsequent verification workflows.

## Configuration Settings
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the typical paragraph length of property rights transfer plans and asset evaluation reports, avoid splitting complete ownership information blocks |
| `chunkSplitter` | Split by paragraph + title | Match the chapter hierarchy of documents, retain approval process nodes on property registration forms and asset disposal approval slips |
| `customPdfParse` | Enable multi-column recognition mode | Adapt to the multi-column layout of on-site transaction announcements and asset evaluation reports, prevent table content from being lost across columns |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Cover the complete parsing time of large asset evaluation reports, prevent parsing process from being interrupted due to timeout |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types (registration forms/reports/announcements) to adapt to their respective field and structure characteristics |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapt to the upload requirements of single large asset evaluation reports, avoid inability to parse due to oversized files |

## Three Common Misconfigurations
- Phenomenon: Multi-column table content is misaligned and core fields are lost after parsing | Cause: Multi-column recognition mode for `customPdfParse` is not enabled, default parsing logic splits cross-column content as single-column content
- Phenomenon: Parsing times out and is interrupted after uploading a large asset evaluation report | Cause: The value set for `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual parsing time of the document, triggering the system timeout limit
- Phenomenon: Core fields such as asset number and evaluation base date are missing after chunking | Cause: The `chunkSize` setting is too small, splitting complete ownership information blocks into scattered fragments, preventing complete information from being associated in subsequent retrieval

## How to Verify Proper Configuration
- Upload a typical on-site transaction announcement document, confirm the parsed text retains complete multi-column layout content with no misalignment or loss
- Upload an asset evaluation report with a single file size not exceeding `UPLOAD_FILE_MAX_SIZE`, confirm parsing time does not exceed the threshold set for `PARSE_FILE_TIMEOUT_SECONDS`
- Randomly extract text fragments after chunking, verify they contain complete core content including asset ownership information and transaction approval nodes
- Check that associated image files generated during parsing are stored as expected, and that chunked text correctly links to corresponding image content

The values provided here are common starting points and should be measured against the reader's own samples.
