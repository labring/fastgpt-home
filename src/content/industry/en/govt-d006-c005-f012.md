# Document and Material Drafting for Property Rights, Asset and State-owned Capital Management: Deployment and Upgrade

## What this category of data looks like
This category of data mainly comes from state-owned asset supervision information systems, enterprise asset management systems, property right exchange systems, valuation firm reports, and financial statements. Common documents involved include property right registration forms, asset valuation reports, property right transfer plans, on-site transaction announcements, and asset disposal approval forms. The data contains both structured fields and unstructured text. The data update frequency is monthly. Documents usually include core content such as asset ownership identifiers, valuation results, and transaction terms. Fields and units vary depending on the document type, and some documents need to meet the fixed format requirements of state-owned asset supervision.

## What constraints these characteristics impose during deployment and upgrade
Data sources for this category are scattered, covering multiple internal and external systems. During deployment, it is necessary to adapt to the data formats of different systems and reserve configuration space for data cleaning and format conversion. The monthly update frequency requires configuring a reasonable incremental synchronization mechanism during deployment to avoid excessive resource occupation caused by full pulls. Fixed-type documents must match the fixed formats of state-owned asset supervision. During upgrades, it is necessary to retain the parsing and generation rules of corresponding documents to prevent damage to original compliance. Additionally, document errors can lead to serious consequences such as state-owned asset loss or transaction suspension. Therefore, deployment needs to strengthen configuration items for operation logs and permission control.

## How to set configurations
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://asset_user:secure_pass@internal-host:27017/asset_management?authSource=admin` | Stores structured metadata and unstructured document content related to property rights and assets |
| `STORAGE_S3_ENDPOINT` | `http://192.168.50.20:9000` | Connects to privately deployed object storage services, stores large files such as asset valuation reports and on-site transaction announcements |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent connection requirements for monthly batch data synchronization, prevents database connection pool exhaustion |
| `REDIS_URL` | `redis://redis_pass@internal-redis:6379/1` | Caches frequently accessed asset ownership data to improve response speed for document generation and queries |
| `FE_DOMAIN` | `https://asset-doc.internal.gov.cn` | Configures the frontend access domain name, matches the internal access domain name rules of state-owned asset systems |

## Three common errors
- Phenomenon: An error `Failed to create post presigned url` is displayed when uploading an asset valuation report. Cause: The `STORAGE_S3_ENDPOINT` or associated storage access key was not reconfigured after upgrading the version, resulting in storage service authentication failure.
- Phenomenon: The currently deployed FastGPT code version cannot be confirmed. Cause: No version verification step was added to the deployment script, or the initially downloaded code package metadata was not retained.
- Phenomenon: Container startup fails on ARM architecture Galaxy Kylin Linux systems. Cause: The FastGPT image adapted for the ARM architecture was not used, or the container's CPU architecture compatibility parameters were not configured.

## How to confirm the configuration is valid
- Run the database connection test script to verify that the configurations of `MONGODB_URI` and `REDIS_URL` can establish normal connections.
- Upload a standard asset disposal approval form, check that the file can be uploaded and generate an accessible storage link, confirming that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- View the deployment logs to confirm that the `DB_MAX_LINK` configuration value does not trigger connection pool over-limit alarms.
- Access the configured `FE_DOMAIN`, confirm that the frontend interface loads normally and has no access exceptions.

The values provided here are common starting points and should be measured against the reader's own samples.
