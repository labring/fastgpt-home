# Document and Material Drafting for Infectious Disease Information Reporting and Monitoring: HTTP Interfaces and External Systems
This page is written based on FastGPT v4.17.0.

## What this category of data looks like
This category of data mainly comes from China's national disease prevention and control information system, hospital HIS systems, and laboratory testing systems. Daily generated documents and materials include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports.
Data is updated daily. Each document includes standardized fields such as case identification, diagnosis information, reporting deadline, and correction marker. The most time-consuming processing steps are verifying case diagnoses and reporting deadlines, correcting duplicate and incorrect report cards, and summarizing abnormal signals. All data must comply with the format requirements of legal reporting procedures, and there are no custom extended fields.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
Since data sources include three independent systems, HTTP interfaces must support parallel configuration for multi-source data pulling to avoid overall task blocking caused by slow responses from single-source systems. The daily update rhythm requires the interface to set a scheduled triggering mechanism to ensure that same-day data is synchronized to the document drafting process in a timely manner.
Standardized document fields require that the field names of data returned by the interface fully match the preset template, and non-standard fields cannot be accepted. At the same time, the rigor of legal reporting requires the interface to have a retry mechanism and exception alerting capabilities to avoid missed or delayed data reports caused by interface failures.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface timeout period | 600 seconds | Adapt to the total time required for multi-source data pulling, avoid task interruption caused by response delays from single-source systems |
| Rearrangement configuration | Enabled, first 5 entries | Prioritize matching core fields required by legal reporting requirements, improve the accuracy of document drafting |
| Authentication method | `Authorization` header carries Bearer token | Complies with interface authentication specifications of most public health systems |
| Template variable configuration | Bind core parameters such as case ID and report date | Automatically fill required fields in document templates |
| Response data processing | Extract core fields via `responseData` | Filter unnecessary system return content to match standardized document formats |
| Scheduled trigger frequency | 2:00 AM daily | Avoid business peak hours to ensure same-day data synchronization is completed |

## Three common mistakes
- Interface call interruption without saving temporary data: When the client closes the SSE connection, synchronized data is not stored in the database. This occurs because no breakpoint continuation mechanism is configured, and no data persistence operation is triggered when the connection is interrupted.
- Authentication configuration error leading to 401 interface response: An unauthorized status code is returned when calling the interface. This happens because the official authentication token for public health systems is not used correctly, and keys from other channels are mistakenly used.
- Rearrangement configuration not taking effect leading to missing fields: The generated document lacks core fields required by legal reporting requirements. This occurs because the rearrangement function is not enabled, or the set number of returned entries does not cover core report fields.

## How to confirm the configuration is complete
- Call the test interface, check if the returned `responseData` includes core fields such as case ID and diagnosis time.
- Trigger a manual synchronization task, check if the interface logs have records of successful authentication, with no abnormal errors.
- View the number of rearranged results, confirm it falls within the preset range.
- Compare the fields returned by the interface with the required items in the template document, confirm all fields match.
