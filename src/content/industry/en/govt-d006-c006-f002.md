# Document and Material Drafting for Infectious Disease Information Reporting and Monitoring: Vector Models and Indexes
## What Data Looks Like for This Category
The typical data sources for this category are the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily generated documents include infectious disease report cards, epidemic situation analysis reports, case correction records, clustered epidemic situation reports, and epidemiological investigation reports. Core fields include case diagnosis information, reporting time limit, case number, correction records, basis for clustered epidemic situation determination, and others. Some documents contain both structured statistical data and unstructured descriptive content.

## Constraints Imposed on the Vector Models and Indexes Link
Multi-source heterogeneous data sources require the index layer to support unified field mapping across systems, to avoid retrieval deviations caused by system differences. The daily update frequency requires incremental index scheduling to adapt to high-frequency batch updates, ensuring that newly added case correction records and clustered epidemic situation reports on the same day can be retrieved in a timely manner. Diverse document types with core business fields require chunking strategies that balance the integrity of structured fields and semantic coherence of unstructured content, avoiding cuts to key information such as case diagnosis and reporting time limit. Legal reporting core business requirements demand that retrieval results accurately associate key fields, avoiding irrelevant content interfering with epidemic monitoring and report drafting work.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the average length of single documents in this category, balancing semantic integrity and retrieval efficiency |
| Overlap Length | 50–100 characters | Avoids cutting core business fields such as case diagnosis and reporting time limit during chunking |
| `defaultToken` | 4096 | Matches the conventional text length of a single epidemic situation analysis report, ensuring complete embedding in retrieval context |
| `maxToken` | 8192 | Adapts to the long text content of clustered epidemic situation reports and epidemiological investigation reports, avoiding truncation of core data |
| Similarity Threshold | 0.75–0.85 range | Filters low-relevance retrieval results, ensuring accuracy of case information matching |
| Single Search Limit | Top 10 entries | Covers the recall sample size required for daily monitoring, avoiding redundant data interfering with analysis |

## Three Common Mistakes
- Phenomenon: When retrieving, the page displays empty original document fields, making it impossible to view specific case diagnosis information or reporting time limit. Cause: No association mapping between original documents and vector data is configured. Only vector features are stored in the vector database, and the storage association between original text and business fields such as case number and reporting date is not retained.
- Phenomenon: The similarity scores of retrieved results are generally high, and a large number of irrelevant documents are recalled. Cause: Retrieval weights are not adjusted for the core business fields of this category. General semantic models excessively match irrelevant content.
- Phenomenon: After the index task is completed, the retrieval page shows no matching results. Background logs show that index records are empty. Cause: The daily update frequency of this category is not adapted. Incremental index scheduling does not cover newly added case correction records or clustered epidemic situation reports on the same day.

## How to Confirm the Configuration Is Correct
- Check the associated fields between the vector database and original document storage. Confirm that each vector data is bound to corresponding business fields such as case number and reporting date.
- Input a known case diagnosis content, verify that the similarity score of the retrieval result falls within the preset threshold range.
- Trigger an incremental index task. Wait for the task to complete, then retrieve the newly added clustered epidemic situation report on the same day. Confirm that the result returns normally.
- Check the `defaultToken` and `maxToken` configurations. Confirm that long text documents are not truncated and are fully embedded in the retrieval context. FastGPT v4.17.0 allows viewing corresponding parameters via the system settings page.

The values provided are common starting points and should be validated against the samples used in actual deployment.
