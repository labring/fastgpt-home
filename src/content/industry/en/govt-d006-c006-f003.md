# Document and Material Drafting for Infectious Disease Information Reporting and Monitoring: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This segment’s data comes from the Chinese Center for Disease Control and Prevention Information System, medical institution HIS and infectious disease reporting systems, and laboratory testing systems, and is updated daily. Daily generated documents include infectious disease report cards, epidemic situation analysis reports, case correction records, clustered epidemic situation reports, and epidemiological investigation reports. The document structure is fixed, including fields such as case number, diagnosis time, reporting time limit, correction records, and clustered epidemic situation related information. All fields must comply with legal reporting specifications.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
This segment’s data is updated daily. Document fields are fixed and must comply with legal reporting specifications. Frequent daily operations include case correction, time limit verification, and abnormal signal aggregation. Multi-turn dialogue must retain recent case data and correction records to avoid context overload that disrupts model processing. Prompts must enforce verification of legal reporting fields to ensure output complies with specifications. Daily updated data must be real-time associated with current tasks, and the number of information items returned in a single dialogue must be limited to prevent core data overflow from interfering with tasks.

## How to Configure
This page is based on FastGPT v4.17.0. The specific configuration items are as follows:
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the fixed ID of the current disease control monitoring task | Ensure context association for dialogues under the same task, avoid data confusion across tasks |
| `messages` | Retain the first 12-18 historical dialogue entries | Match the dialogue context length of daily case data, avoid exceeding the model's processing limit |
| Maximum context length | 8000 token | Match the character count of a single infectious disease report document, calibrated via actual testing |
| `variables` | Bind the variable list of legal reporting fields | Ensure prompts verify that all mandatory reporting fields are included in the document |
| Number of items returned per dialogue | The first 5 latest case data entries | Avoid context overload, focus on core information for the current task |
| Dialogue timeout threshold | 600 seconds | Match the conventional response time for disease control data queries, avoid task interruption due to long waiting times |

## Three Common Misconfigurations
- Phenomenon: The dialogue can only respond to the first request, with no feedback for subsequent interactions. Cause: `chatId` is not bound to a fixed task ID, resulting in failure to associate context.
- Phenomenon: After connecting to a locally deployed model, the actual called model does not match the configured one. Cause: The correct model identifier is not specified in the configuration, resulting in the default model being called.
- Phenomenon: After inputting JSON case data in the dialogue, the model has no response or reports an error. Cause: The maximum context length is set insufficiently, exceeding the model's processing limit.

## How to Verify Successful Configuration
- In the debug preview interface of FastGPT v4.17.0, input test case data and check whether `chatId` is bound to the current task.
- Trigger multi-turn dialogue to verify whether the first 12-18 historical dialogue entries are retained.
- Check whether the fields in `variables` include all mandatory legal reporting items.
- Test inputting JSON case data containing multiple fields, verify that it can be processed normally, and confirm that the maximum context length setting meets requirements.

The values provided here are common starting points and should be evaluated against the reader's own samples.
