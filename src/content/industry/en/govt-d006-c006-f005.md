# Document and Material Drafting for Infectious Disease Information Reporting and Monitoring: Tool Calling and Plugins

## What Data Looks Like for This Category
Target entities for this category include disease control institutions, medical facilities, public health departments, and disease control divisions of health and health authorities. Data sources include China’s disease prevention and control information system, medical institution HIS and infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily produced documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Core fields include case unique identifier, diagnosis time, reporting unit, correction status, test results, and others. Strict compliance with legal infectious disease reporting format specifications is required.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Multi-system cross-source data requirements mean tool calling must support integration with multiple types of business interfaces to complete field encoding and unified format mapping across different systems. The daily update business rhythm requires plugin trigger frequency to match the daily update cycle, avoiding repeated pulling of expired historical data. Legal format document requirements mean content generated by tools must strictly match fixed field order and filling rules, with no arbitrary structural adjustments. Core time-consuming verification links must be completed automatically via tool calling to reduce errors caused by manual intervention.

## Three Common Mistakes
- Phenomenon: A 400 <400> InternalError.Algo.InvalidParameter: Range of i error is returned when calling the MCP service. Cause: Parameters were not passed within the field range specified by disease control reports, for example, the case number format does not meet system requirements.
- Phenomenon: Google Search in the workflow returns array<object> formatted results that cannot be directly filled into the report template. Cause: No dedicated array-to-text formatting tool was configured, and using general processing logic directly caused field misalignment.
- Phenomenon: Online application API calls frequently fail. Cause: No concurrency threshold was set according to the interface current limiting rules of the disease control system, and blindly increasing concurrency parameters triggered current limiting.

## How to Confirm Configuration Is Complete
- Trigger a full synchronization task, check that the number of pulled records matches the single pull limit preset in the system, and confirm that the data source connection is normal.
- Pass simulated abnormal case data, verify whether the tool triggers the verification function specified by `toolChoice`, and confirm that the tool calling logic takes effect.
- View the report format output by the workflow, confirm whether it matches the field order and structure of legal documents, and confirm that the formatting rules take effect.
- Simulate multiple concurrent requests, check the interface return status codes, and confirm that the concurrency settings comply with system current limiting requirements.
