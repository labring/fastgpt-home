# Document and Material Drafting for Petition Matter Handling: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data comes from the national petition information system, local petition systems, the 12345 citizen hotline, grassroots governance platforms, and historical petition archives. It is updated daily. Core documents include petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-examination applications, and resolution plans. Fields cover request subjects, matter content, handling progress, policy basis, responsible units, and more. The length of a single document ranges from hundreds to thousands of characters.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering?
Decentralized data sources create inconsistent request field formats across different channels. Multi-turn dialogue must first complete cross-system field alignment to avoid information misalignment. Daily updated request data requires dialogue context to support incremental loading, ensuring real-time calls for the latest daily matters. Multiple fixed-format documents require prompts to bind required fields matching the target document. For example, handling opinions must include responsible units, handling results, and response wording. The legal handling process for petition matters sets rules for dialogue logic. The dialogue must cover acceptance verification, responsibility coordination, and policy explanation steps. Missing these steps can lead to repeated or higher-level unauthorized petitions.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Pre-set 4 variables: petition matter source, request subject, handling progress, responsible unit. Maximum input limit per variable is `800 characters` | Covers core identification fields for petition matters, simplifies the information extraction process for multi-turn dialogue |
| `messages` | Retain the most recent `20` dialogue history entries | Petition handling dialogue includes multiple rounds of requests, verification, responses, and more. Retaining sufficient history ensures context coherence and avoids information gaps |
| Maximum context length | `4000–8000 characters`, calibrated via actual testing | Adapts to the length requirements of multiple document types from acceptance notices to resolution plans, balances model response efficiency and context completeness |
| File upload parsing | Enable the document parsing tool, supports importing PDF and DOCX format petition archives | Requires calling historical petition archives as handling references, aligns with business data sources |
| `chatId` binding | Assign a unique `chatId` to each petition matter, associate and store complete dialogue records | Petition matters require full traceability, facilitating review of handling processes during review and re-examination, and complying with legal archiving requirements. This function optimized multi-matter isolation logic in FastGPT v4.17.0 |
| Dialogue export | Supports export to PDF or structured text format, storage limit is `1000 MB` per matter | Meets the archiving and retrieval requirements of petition archives, fits the business scenario |
| Timeout threshold | `600 seconds`, calibrated via actual testing | Prevents model response timeout caused by overly long context in long dialogues, adapts to the average number of dialogue rounds for petition matter handling |

## Three common mistakes
- Phenomenon: Fields are empty or formatted incorrectly when exporting dialogue history. Cause: Core fields of petition matters are not configured in `variables`, causing extracted dialogue information to fail to bind to corresponding business fields.
- Phenomenon: An error occurs when uploading petition archives after local deployment, and file content cannot be parsed. Cause: The dependency environment of the document parsing tool is not configured correctly, or the uploaded file format exceeds the supported range.
- Phenomenon: Multi-turn dialogue times out, and response time exceeds the preset threshold. Cause: The number of retained `messages` is not limited, causing the context to be too long and exceed the model's processing threshold, or reasonable timeout parameters are not configured.

## How to confirm the configuration is correct
- Initiate a simulated petition matter dialogue, check whether `variables` automatically fill in corresponding business fields, and confirm that information extraction is accurate.
- Upload a test petition archive, verify that the document parsing tool can normally read content and associate it with the dialogue context.
- Check whether a unique `chatId` is generated for each test matter, and confirm that dialogue records are correctly bound to the matter.
- Trigger the dialogue export function, verify that the export format meets the archiving requirements of petition archives.

The values provided are common starting points and should be measured against the reader's own samples.
