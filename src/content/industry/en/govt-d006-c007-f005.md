# Document and Material Drafting for Petition Matter Handling: Tool Calling and Plugins

## What Data for This Category Includes
Data for this category originates from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. Data is synchronized and updated daily.
Commonly generated documents include petition registration forms, acceptance notices, transfer and assignment notices, handling opinions, review and recheck applications, and resolution plans.
Data fields include requester information, matter details, handling units, response guidelines, request classifications, and more. All documents must include fixed fields that meet statutory format requirements.

## Constraints on Tool Calling and Plugin Workflows
The multi-platform nature of data sources requires plugins to support multiple authentication methods and adapt to interface specifications of different systems.
Fixed document formats require tool calls to bind matching document templates, ensuring generated content complies with statutory requirements.
The daily update frequency requires plugins to be configured with scheduled synchronization tasks to avoid using expired data.
Standardized field requirements mean corresponding fields must be accurately extracted from data sources as plugin input parameters, preventing missing key information in generated content that could lead to repeated petitions or petitions submitted beyond the proper hierarchy.

## Configuration Settings
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically match the tool calling logic for petition document generation; no manual specification required |
| Authentication Configuration | Configure exclusive keys and request headers per the interface documentation of the target petition system | Data sources come from multiple official petition platforms, so independent authentication verification is necessary |
| Maximum Documents per Single Call | Top 6 entries | Daily synchronized historical archive volume is moderate; excessive content will exceed context capacity limits |
| Timeout Threshold | 300 seconds | Petition matter verification requires coordination across multiple departments, so sufficient interface response time must be reserved |
| `functionCall` | `enabled` | Enable function calling capability to generate standardized petition documents that comply with statutory formats |
| Document Template Matching Rule | Match corresponding document templates by matter type | Petition documents have clear statutory format requirements; call matching templates based on request classifications |

## Three Common Misconfigurations
- Symptom: Interface returns a 401 unauthorized error. Cause: Exclusive keys and request headers are not configured per the authentication format of the petition system, leading the platform to reject the request.
- Symptom: Tools do not automatically trigger document generation logic, and generated content fails to meet statutory format requirements. Cause: `toolChoice` is set to `none`, disabling automatic tool selection and preventing matching of petition document generation rules.
- Symptom: Generated handling opinions are missing the responsible unit field. Cause: Corresponding fields are not extracted from data sources as plugin input parameters, resulting in missing key information in generated content.

## How to Confirm Configuration Is Correct
- Initiate a test call simulating a petition request, check whether the tool automatically triggers the function for corresponding document generation, and confirm that the `functionCall` and `toolChoice` configurations are active.
- Review interface request logs to confirm that authentication keys and request headers matching the target petition system are included, verifying that the authentication configuration is correct.
- Generate a test document, verify that required fields for statutory documents such as petition registration forms and acceptance notices are present, confirming that the template matching rule is active.

The values provided here are common starting points and should be measured against the reader's own samples.
