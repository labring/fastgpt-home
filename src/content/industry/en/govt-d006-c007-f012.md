# Document and Material Drafting for Petition Matter Handling: Deployment and Upgrade

## What the data for this category looks like
This category’s data primarily comes from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. Data is updated via daily incremental synchronization. Daily generated documents include petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-examination applications, resolution plans, and more. Each document contains core fields such as the requesting party, matter content, handling milestones, responsible units, policy basis, and must strictly match the legal process structure for petition handling.

## What constraints do these characteristics impose on the deployment and upgrade phase?
This category’s data characteristics impose three core constraints on the deployment and upgrade phase.
First, multi-source data access requires configuring synchronization rules adapted to different systems to avoid data format conflicts.
Second, the daily incremental update frequency requires deploying scheduled synchronization tasks and incremental data verification mechanisms to ensure data timeliness and accuracy.
Third, the diverse document types and legal handling process fields require retaining original document templates and field mapping configurations during upgrades. This prevents generation of non-compliant petition documents due to configuration changes, which could lead to repeated petitions or review and correction issues.
Additionally, it is necessary to distinguish between petition business data and 12345 hotline business data to avoid cross-category data confusion.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30 connections` | Adapt to concurrent data requests from daily incremental synchronization, avoid exhausting the database connection pool |
| `MONGODB_URI` | `mongodb://fastgpt:secure_pass@localhost:27017/petition_business_db` | Core database connection address for storing petition archives, application configurations, and process data |
| `REDIS_URL` | `redis://:redis_secure_pass@localhost:6379/1` | Cache retrieval results and session information to reduce query pressure on the core database |
| `STORAGE_S3_ENDPOINT` | `http://192.168.0.100:9000` | Configure the access address for local object storage, used to store electronic attachments of various petition documents |
| `FILE_TOKEN_KEY` | `32-bit randomly generated encryption string` | Encrypt download links for petition documents to prevent unauthorized access to sensitive business documents |
| `ROOT_KEY` | `Deployment-environment-specific random secret key` | Verification key for the highest permissions of the management platform, ensuring the security of configuration modifications |

## Three Common Misconfigurations
- After upgrading FastGPT v4.17.0, all custom petition document drafting application configurations are lost. This occurs because application configuration backups were not exported in advance, or the original database storage volume was not mounted during the upgrade, resulting in failure to retain configuration data.
- Frequent connection timeout errors occur during daily incremental petition data synchronization. This occurs because the `DB_MAX_LINK` parameter was not adjusted to accommodate concurrent requests, leading to exhaustion of the database connection pool and inability to process synchronization tasks.
- Searching historical petition archives mixes in request data from the 12345 platform. This occurs because classification retrieval rules for multiple data sources were not configured, and data sources from petition systems and other platforms were not distinguished.

## How to Verify Proper Configuration
- Navigate to the FastGPT platform’s system settings page, review the database connection status, and confirm that the connection test results for `MONGODB_URI` and `REDIS_URL` indicate success.
- Manually trigger an incremental data synchronization task, verify that petition documents are properly imported into the system, and confirm that document fields match business requirements.
- Upload a petition registration form template, generate a download link, and confirm that the link includes encryption parameters and cannot be accessed directly via a static address.
- Review the custom application list, confirm that the petition document drafting application configuration has been retained, and that associated data sources and document templates have not been lost.
