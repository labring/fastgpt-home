# Document and Material Drafting for Public Data Catalogs and Open Data: HTTP Interfaces and External Systems

## What data falls under this category
Data under this category mainly comes from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Daily generated documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions.
Data update frequency is monthly. Core fields include data item name, open scope, desensitization rules, interface address, and update cycle. Document structures mainly use structured tables, and some fields need to match authorization boundaries and data security requirements.

## What constraints do these characteristics impose on HTTP interfaces and external systems
The monthly update frequency requires interface calls to adapt to a fixed rhythm, avoiding excessive requests that affect data source stability. Multi-source data access scenarios require interface configurations to be compatible with different data source return formats, ensuring correct parsing of structured data.
Desensitization rules and authorization boundaries require that only compliant fields are exposed during interface transmission. The `Authorization` parameter must be strictly bound to the corresponding data open permissions to prevent sensitive data leakage. At the same time, interface failures must trigger corresponding alerts to avoid inconsistencies between the catalog and actual data, or unavailable interfaces.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {public data interface key assigned by the platform} | Complies with identity verification requirements for public data interfaces, ensuring call permissions are compliant |
| `variables` | Specify target data catalog ID, desensitized field identifier | Accurately locate target public data resources, matching structured fields in catalog documents |
| `responseData` | Return only desensitized data items and open condition fields | Follows data desensitization rules to avoid leakage of original sensitive data via interfaces |
| Interface timeout period | 300–600 seconds | Adapts to the time required for cross-departmental data retrieval, avoiding timeout errors due to slow responses |
| Retry count | 2 times | Covers temporary network fluctuations, while avoiding repeated calls that increase pressure on data sources |

## Three Common Mistakes
- Phenomenon: A public data interface call returns a timeout error, with the interface displaying request timeout or status code 504. Cause: The time required for cross-departmental data retrieval was not accounted for, and the interface timeout setting was too short.
- Phenomenon: The external system interface cannot be called even after configuring the `Authorization` parameter. Cause: The key permissions were not bound according to the authorization rules of the public data catalog, or the key does not cover the target data open scope.
- Phenomenon: The fields returned by `responseData` do not match the public data catalog documents. Cause: The return fields were not configured according to the data item description, and sensitive fields required by the desensitization rules were omitted.

## How to Confirm Configuration is Complete
- Call the test interface to verify whether the returned fields match the desensitized fields in the public data catalog documents.
- Simulate an interface call after the monthly update to check whether the update time of the returned data matches the update frequency description in the catalog.
- Trigger abnormal scenarios such as key expiration and network fluctuations to confirm that the system can correctly capture errors and trigger alerts.
- Check whether the `variables` parameter accurately matches the ID of the target data catalog to avoid calling irrelevant data interfaces.
