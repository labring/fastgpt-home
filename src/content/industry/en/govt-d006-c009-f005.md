# Document and Material Drafting for Public Data Catalogs and Open Data: Tool Calling and Plugins

## What data in this category looks like
Data in this category originates primarily from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Daily produced documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Data updates follow a monthly cycle. Core fields include data item name, open scope, desensitization rules, interface address, update cycle, and authorization conditions. Most content uses structured formats, with some accompanying unstructured supplementary description documents.

## What constraints do these characteristics impose on tool calling and plugins
The monthly update cycle requires tool calling to be configured with a regular synchronization mechanism, to ensure catalog data obtained matches actual data sources. Multi-source data assets require plugins to support integration with different types of data source interfaces, and adapt to both standardized and non-standardized document formats. The variety of structured fields requires tool calling parameters to cover core fields such as data items, desensitization rules, and interface addresses, to avoid missing key information. Additionally, given the risks of data leaks and catalog inconsistencies, tool calling must be configured with parameter verification and error backtracking mechanisms, to ensure request legality and returned data accuracy.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multiple scenarios of public data catalog queries, allowing the system to automatically match appropriate tools |
| Single call timeout | `600 seconds` | Public data interfaces usually have long response cycles, to avoid interrupting valid requests |
| Maximum number of returned results per call | `Top 10` | Control the scale of returned data to prevent context overflow from affecting subsequent processing |
| `functionCall` | Enable field verification | Ensure that the parameters of tool calling comply with the field specifications of public data catalogs |
| Web content reading plugin | Enabled | Support reading the full text of searched public data documents to supplement complete content beyond metadata |

## Three common misconfigurations
- Phenomenon: Only link titles are returned after calling the search plugin, and the full text within the link cannot be read. Cause: The web content reading plugin is not enabled, only the metadata of the search results is obtained, and the link body content is not crawled.
- Phenomenon: The HTTP plugin returns a 502 error when calling a third-party API, but the call works in other tools. Cause: Authentication information or timeout thresholds in the request header are not configured correctly, causing FastGPT requests to be intercepted or timed out by upstream services.
- Phenomenon: Only a small number of optional models are displayed in the tool selection interface, and the specified model cannot be called. Cause: API access permissions for the corresponding model are not configured in the system, or the loading switch for the model plugin is not enabled, causing some models to not be loaded.

## How to confirm configurations are properly set
- A tool call for a public data catalog query may be initiated, and returned results checked for core fields such as data item name, open scope, and desensitization rules.
- A previously included public data document link may be used to test the web content reading plugin, and confirmation made that full text within the link can be obtained.
- The HTTP plugin may be used to call a third-party API for testing, and confirmation made that the returned status code is 200 and data format meets expectations.
- The tool configuration interface may be opened, configurations of `toolChoice` and `functionCall` checked for correctness, and all configured models confirmed to appear in the optional list.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
