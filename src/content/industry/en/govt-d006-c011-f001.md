# Document and Material Drafting for Pension, Work Injury, and Unemployment Benefit Verification: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category comes from social insurance management systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily. Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment benefit application materials. Data fields include applicant identity identifiers, payment duration, qualification assessment results, and benefit calculation-related parameters. The structure aligns with standardized social insurance business workflows. Structured and unstructured data from multiple systems must be integrated.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
The multi-source data docking needs of this category require HTTP interfaces to support simultaneous calls to multiple external systems, including social insurance management and work injury identification systems. The daily data update frequency requires configuring reasonable request intervals for the interface to avoid exceeding the concurrency limits of external systems. Diverse document types require the interface to support binary file transfer and synchronous submission of structured parameters. The requirement for accurate benefit data requires an identity verification mechanism to prevent tampering during data transmission. Field differences across different business scenarios require the interface to support dynamic parameter adaptation, to avoid request failures caused by fixed parameter formats.

## How to Configure the Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | `Bearer {external_sys_token}` | Complies with identity verification specifications of external social insurance systems, ensuring legal interface call permissions |
| `variables` | `{"doc_type": ["pension benefit", "work injury benefit", "unemployment benefit"], "update_freq": "daily"}` | Adapts to the multiple business types and daily data update characteristics of this category, and transmits business context parameters |
| `responseData` | Return only structured fields and binary file streams | Filters irrelevant return content, reduces data transmission volume, and meets the core data requirements of social insurance businesses |
| Request timeout | `600 seconds` | This category's data processing includes time-consuming steps such as payment duration calculation, so sufficient response time is reserved |
| File upload size limit | `1000 MB` | Supports transfer of large documents such as work injury identification materials and payment duration certificates, adapting to the conventional size of business documents |
| Parameter validation switch | Enabled | This category has high requirements for data accuracy; validating parameter formats can intercept invalid requests in advance |

## Three Common Misconfigurations
- Issue: After calling the interface, the external system receives empty file fields and cannot parse binary data. Cause: `responseData` is not configured to use binary stream format, and only file paths or metadata are returned.
- Issue: The interface call returns a 401 status code, and identity verification fails. Cause: The token format of the `Authorization` parameter is incorrect, and the Bearer token specification of the external system is not followed.
- Issue: The interface call times out and returns a 504 status code. Cause: The request timeout is set too short, and it does not accommodate the time-consuming steps of benefit calculation in this category.

## How to Verify Correct Configuration
- Submit a simulated binary file of a benefit application form to the test interface, and check whether the external system can receive and parse the file content normally.
- View interface call logs to confirm that the `Authorization` parameter is correctly carried, with no format errors or omissions.
- Trigger a simulated daily data update request, and check whether the interface returns `responseData` matching the business fields of this category.
- Trigger a simulated time-consuming benefit calculation request, and confirm that the interface is not interrupted due to timeout, and the response time meets the preset configuration.
