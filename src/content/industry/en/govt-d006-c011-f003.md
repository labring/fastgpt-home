# Document and Material Drafting for Old-Age, Work-Related Injury, and Unemployment Benefit Verification: Multi-Turn Dialogue and Prompt Engineering

## What Data for This Category Includes
Data for this category comes from social insurance handling systems, personal benefit records, labor relations and work-related injury determination systems, and the electronic social security card platform. The update frequency is daily. Documents processed daily include benefit application forms, payment duration certificates, retirement approval forms, work-related injury determination materials, and unemployment insurance benefit application materials. Data fields include insured entity identity identifiers, payment duration ranges, work-related injury determination numbers, unemployment insurance enrollment records, and other relevant items. Single-document structure varies by business type, with no fixed unified maximum word count per document.

## Constraints for Multi-Turn Dialogue and Prompt Engineering
The daily data update requirement means multi-turn dialogue context must be linked to real-time latest business data, to avoid calculation deviations caused by using expired information. Multi-source data access requires clearly distinguishing the data source identifiers of the three types of businesses (old-age, work-related injury, unemployment) during the dialogue flow, to prevent field confusion. Differences in document structures require prompts to be tailored to official templates for different business types. Multi-turn dialogue must gradually guide users to supplement missing business scenario information, such as work-related injury determination grade, cumulative payment duration, and other fields. At the same time, the accuracy of benefit verification data is high, so the context of multi-turn dialogue must be limited to the current handling business scope, to avoid irrelevant historical dialogue interfering with calculation logic.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` | Retain the first 12 turns of dialogue content in the current session | Covers key context of the handling process, avoids loss of business parameters |
| `variables` | Bind to the same-day social insurance business data interface, set timeout threshold to `600 seconds` | Obtain real-time latest payment records and calculation benchmark data |
| Maximum context length | `8000–12000 characters` | Adapts to the core information capacity of a single business document and multi-turn dialogue |
| Maximum single reply length | `2000 characters` | Meets the standard output format requirements of benefit verification documents |
| `chatId` | Bind to the unique business number of the current handling business | Distinguishes context of different handling sessions, prevents data confusion |
| Question optimization switch | Enabled | Converts colloquial requests into instructions compliant with social insurance business specifications |

## Three Common Misconfigurations
- Symptom: No parsed results after uploading social insurance business documents, no error logs in the background. Cause: No tailored chunking rules configured for social insurance business documents, large documents cannot be correctly split and identified.
- Symptom: Unable to actively terminate a running dialogue session. Cause: The session termination configuration for `chatId` is not correctly bound, or the corresponding session cleanup logic is not called.
- Symptom: The workflow run displays the output results of all AI dialogue nodes. Cause: No output filtering rules configured for the workflow, and only the return content of the last AI node is not specified.

## How to Verify Successful Configuration
- Upload a standard social insurance business document, check whether the parsed fields cover the core information required for the business.
- Initiate a multi-turn dialogue session, test the session termination operation, confirm that subsequent requests no longer associate the context of the current session.
- Configure and trigger a workflow run, check that the output result only includes the return content of the last AI dialogue node.
- Initiate a document polishing and expansion request, check that the generated content complies with the standard format requirements of social insurance business.

The values provided are common starting points and should be measured against the reader's own samples.
