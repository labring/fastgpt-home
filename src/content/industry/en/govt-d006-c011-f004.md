# Document and Material Drafting for Pension, Work Injury, and Unemployment Benefit Verification: Workflow Orchestration

## What This Category of Data Looks Like

## Constraints Imposed on Workflow Orchestration by These Characteristics
The daily update feature of the data requires that the workflow supports real-time pulling of the latest personal social insurance participation, work injury identification, unemployment registration and other data, to avoid verification deviations caused by using expired information. The format differences of multi-source data require that the workflow be configured with a unified data verification node to block inputs with missing fields or mismatched types. The fixed field structure of form-based documents requires that the workflow supports dynamic filling of structured data, while retaining an entry for manual adjustment. Differences in verification rules across insurance types require that the workflow can switch configuration parameters according to business scenarios, to avoid mixing settings across categories. At the same time, document generation must comply with the standardized format of social insurance handling, requiring the workflow to automatically adjust field order and typesetting.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Isolate by user ID, scope limited to a single session | Data in this category involves personal social insurance participation privacy, ensuring that variables with the same name from different applicants do not interfere with each other |
| `nodeId` | Assign unique identifiers to the three verification nodes for pension, work injury, and unemployment | Facilitate workflow exception troubleshooting by node, quickly locating data verification or document generation links |
| Context Loading Node | Load global variables from the first 3 rounds of historical conversations | Verification in this category needs to associate historical payment records, and 3 rounds of conversations can cover conventional business review needs |
| Custom Reply Node | Add a fixed guiding statement after the AI generates the document | Uniformly inform applicants of subsequent processing procedures, replacing the default suggested questions |
| API Call Timeout | 600 seconds | Pulling data for this category requires connecting to multiple systems, 600 seconds covers the time required for most cross-system queries |
| Single Generation Character Limit | 800–1200 characters | The length of conventional documents in this category falls within this range, avoiding generating overly long or short documents |

## Three Common Mistakes
- Symptom: The benefit verification document returned by the workflow lacks historical payment period data, and there is no context-associated content after the API call. Cause: The scope rules of `variables` are not configured correctly, causing global variables to not be bound to the current applicant's session, and data from different users interfere with each other.
- Symptom: The workflow status shows "Node execution failed", returning status code 400. Cause: Unique `nodeId` is not assigned to each business node, causing the workflow scheduler to fail to identify the corresponding link, triggering parameter verification failure.
- Symptom: After the AI generates the document, the preset processing procedure guiding statement is not displayed, only the default suggested questions appear. Cause: The custom reply node is not connected to the output link of the AI generation node, causing the guiding statement to not be inserted correctly.

## How to Verify Proper Configuration
- Initiate a simulated business session, enter the applicant's social insurance participation information, and check whether the generated document includes the corresponding applicant's payment period data.
- Switch to different simulated user IDs to initiate sessions, check that the document data generated by the two sessions does not interfere with each other, verifying that the `variables` scope configuration takes effect.
- View the workflow node link, confirm that the custom reply node is connected after the AI generation node, and the trigger order conforms to the business process.
- Simulate cross-system data pulling, check whether the workflow completes data verification and document generation within 600 seconds, verifying that the timeout configuration is reasonable.
