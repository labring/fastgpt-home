# Document and Material Drafting for Pension, Work Injury, and Unemployment Benefit Verification: Tool Calling and Plugins

## What data for this category includes
Data for this category comes from social insurance handling systems, personal benefit records, labor relations and work injury verification systems, and the electronic social security card platform. Data is updated daily.
Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury certification materials, and unemployment benefit application materials.
Core fields include insured person identity identifiers, cumulative payment durations, work injury certification conclusions, unemployment registration statuses, and benefit calculation bases. Most field units are basic measurement units such as years, months, and yuan.

## Constraints imposed by these characteristics on tool calling and plugins
The daily data update requirement means tool calls must pull the latest insured, payment, and certification data in real time. This avoids benefit calculation errors caused by using expired cached data.
Differences in the structure of multiple document types require plugins to configure differentiated validation rules for required fields of different documents. This ensures complete fields for submitted materials.
Reliance on multiple system data sources requires tool calls to support format conversion across system interfaces. This unifies data field mapping logic.
Differences in field units require plugins to standardize values of different measurement units. This prevents calculation errors.

## Configuration Settings
This guide is written for FastGPT v4.17.0. Specific configuration items and recommended values are listed below:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically matches the currently processed document type to meet tool calling needs for multi-scenario documents |
| Custom tool parameter optional values | Enumerate and configure according to the required fields of the corresponding document | Matches field requirements for different documents such as benefit applications and work injury certifications |
| Interface call timeout | `300–600 seconds` | Matches the average time range for pulling data across social insurance systems |
| `functionCall` | `strict: true` | Enforce parameter format validation for plugin calls to avoid missing or incorrectly formatted fields |
| Tool call retry count | `2–3 times` | Addresses temporary system interface fluctuations and reduces call failure rates |
| Return result field filtering | Only retain required fields for the current document | Streamlines context content and improves the accuracy of tool calls |

## Three Common Misconfigurations
- Symptom: Tool calls return a "parameter format error" prompt, with an interface return status code of 400. Cause: Strict validation mode for `functionCall` is not enabled, leading to passed fields that do not meet the required requirements of the corresponding document.
- Symptom: Connection timeout occurs when calling a local large model tool in a Linux deployment environment. Cause: Correct local model interface address and port mapping are not configured, leading to abnormal network connectivity.
- Symptom: HTTP call parameter configuration items for custom tools disappear, and optional variables cannot be set. Cause: The parameter mapping field in the tool configuration was accidentally deleted, and corresponding business fields were not bound as required by the documentation.

## How to Confirm Proper Configuration
- Submit test basic information for an insured person, and check whether the fields returned by the tool call fully match the currently processed document type.
- Simulate temporary fluctuations in cross-system interfaces, and verify whether the tool performs automatic retries according to the configured retry count.
- Check the custom tool parameter configuration page, and confirm that optional variables have been enumerated and set according to the fields of the corresponding document.
- Review tool call logs, and confirm that the interface timeout and retry count match the preset configuration parameters.

The values provided are common starting points and should be measured against the reader's own samples.
