# Document and Material Drafting for Elderly Care Service Institution Supervision: Citation Source and Traceability
This document applies to FastGPT v4.17.0

## What this category of data looks like
Data for the elderly care service institution supervision scenario typically comes from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institution operation ledgers. Daily produced documents and materials include filing materials, operation subsidy applications, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. The data update rhythm is monthly synchronization. Fields cover basic institution information, bed allocation, operation records, safety inspection results, and other core business dimensions required for supervision. There is no unified fixed output format, and the original field structure of each source system must be matched.

## What constraints do these characteristics impose on the citation source and traceability link
Dispersed data from multiple sources requires the traceability link to accurately match the original fields of each data source, to avoid confusion of cross-system data. The monthly update rhythm requires regular synchronization of knowledge base data sources, to prevent the use of expired institution filing, bed, or operation data. Different types of supervision documents have different traceability precision requirements. Operation subsidy applications need to be associated with operation ledger data. Safety rectification ledgers need to be bound to fire safety inspection records. Traceability matching weights and rules must be adjusted for different document types. At the same time, the consequences of errors in supervision scenarios are clear. Each citation must directly correspond to a specific entry of the original data, with no vague traceability allowed.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | The citation content for elderly care supervision documents usually includes institution filing materials, inspection records, etc. This length can cover core traceability information and avoid truncating critical data |
| `responseData` | Enable full raw data output | Supervision scenarios require complete citation of original data entries to meet the traceability verification needs of subsidy review and hazard rectification |
| `detail` | Enable detailed traceability mode | It is necessary to clearly mark the source system, update time, and specific fields of the cited data, to comply with the compliance requirements of supervision documents |
| Data source refresh cycle | Synchronize monthly | Matches the monthly update rhythm of this category of data, ensuring that cited data is consistent with the latest business data |
| Citation source formatting | Restore according to the original document structure | Avoid chaotic citation content formatting, and meet the formal format requirements of supervision documents |

## Three common mistakes
- The phenomenon is that the content field returned after calling the traceability interface is empty. The cause is that the `responseData` configuration is not correctly enabled, resulting in only the generated document content being returned, without carrying the original cited data.
- The phenomenon is that garbled characters or chaotic formatting appear in the citation content of the generated document. The cause is that the correct citation source formatting is not configured, the field structure of the original document is not restored, and the encoding of cross-system sources is not uniformly processed.
- The phenomenon is that the citation source in the generated document is displayed non-standardly, and the original knowledge base content cannot be downloaded normally. The cause is that the `detail` configuration for displaying complete traceability information is not enabled, and the proxy rule for forwarding access requests to the original knowledge base content is not correctly configured.

## How to confirm the configuration is correct
- Generate an operation subsidy application document, check whether the cited content in the main text includes specific fields of institution operation data, and can be associated with the corresponding data source name.
- Check the traceability section at the end of the generated document, to confirm whether the source system, update time, and specific entry of the cited data are marked.
- Try to download the original knowledge base content through the traceability link in the generated document, to confirm that the proxy configuration can normally access the data source.
- After simulating a monthly data update, regenerate the same type of document, and check whether the cited data is synchronized to the latest monthly data.
