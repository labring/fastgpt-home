# Document and Material Drafting for Internal Control Evaluation, Audit and Rectification: Tool Calling and Plugins

## What this category's data looks like
Data originates from enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems. Update frequency is annual. Daily output documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Most document structures combine structured fields (such as issue number, rectification responsible person, completion deadline) with unstructured supporting materials. Common data fields involve business samples, voucher numbers, rectification closed-loop status, and similar items. Configurations must match enterprise internal management specifications, and there are no fixed universal statistical values.

## What constraints these characteristics impose on tool calling and plugins
Data sources are scattered across multiple heterogeneous systems. Tool calling adapts to API formats and permission rules of different systems, and mapping logic for multi-source data pulling is configured in advance. The low-frequency annual update feature requires tool calling to support batch pulling of full historical data. The single-time data processing upper limit must match enterprise internal storage and transmission specifications. The mixed structured and unstructured nature of documents requires plugins to support both field extraction and text generation adaptation. For documents requiring closed-loop verification such as rectification ledgers and closure certificates, tool calling associates status verification logic. The post-inspection business attribute requires documents generated by tools to retain sampling basis and supporting associations, and avoid generating unsubstantiated audit conclusions.

## How to configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to mixed scenarios of multi-source data pulling and document generation, no manual tool switching required, compatible with FastGPT v4.17.0 tool calling logic |
| `functionCall` | Force trigger | Ensures structured fields associated with audit documents must be obtained via tool calling, avoids generating unsubstantiated text content |
| Single tool call timeout | 600 seconds | Covers response delays from multi-system data integration, prevents process interruption due to slow responses from individual systems |
| Tool call result cache duration | 7 days | Matches annual data update frequency, reduces overhead of repeated pulling of historical data |
| Single data pull upper limit | 1000 entries | Matches specification thresholds for single data returns from enterprise internal systems, prevents overload |
| Plugin call retry count | 2 times | Addresses temporary response failures from individual systems, ensures process stability |

## Three common misconfigurations
- The model generates generic text without triggering tool calls. The cause is that `toolChoice` is not set to automatic mode, so tool calling is not actively triggered.
- Abnormal errors occur during sequential execution of tool calls. The cause is that context passing rules for multi-tool calls are not configured, and results from previous tools are not correctly brought into subsequent processes.
- Associated fields for rectification ledgers are missing in generated audit documents. The cause is that `functionCall` forced calling is not enabled, so the model generates text directly without pulling actual rectification data from the system.

## How to confirm configuration is correct
- Initiate a simulated call, check if the tool can pull issue list data from the audit management system, and verify that returned fields match enterprise internal specifications.
- Test the sequential execution workflow for multiple tools, confirm that results from previous tools are correctly brought into subsequent generation links.
- Check system logs, confirm that the tool call timeout configuration meets response requirements for the business scenario, with no frequent timeout errors.
- Verify permission configuration, attempt to access unauthorized system datasets, confirm that security intercept prompts are triggered.

The values provided are common starting points and should be measured against the reader's own samples.
