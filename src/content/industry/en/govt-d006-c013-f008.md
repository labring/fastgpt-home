# Document Writing and Material Drafting for Internal Control Evaluation, Audit and Rectification: Document Parsing and Chunking

## Data Profile for This Category
This category of data primarily originates from central enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems. Daily documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Data update frequency is annual. Most documents are a mix of structured fields and unstructured text, involving fields such as issue number, rectification responsible person, completion deadline, associated path of supporting materials, and there is no unified fixed format template.

## Constraints Imposed on Document Parsing and Chunking
The annual batch update feature requires document parsing to support batch uploads and avoid reloading historical documents. Documents mixing structured tables and unstructured text risk having their business associations broken by automatic chunking. For example, if multi-row and multi-column data in a rectification ledger is split randomly, the corresponding relationship between each row’s issue and rectification requirements will be lost. Audit documents often contain clear business node fields; chunking must retain field associations and avoid splitting a single rectification requirement into multiple chunks. Additionally, documents originate from diverse systems, so parsing must adapt to exported files in different formats to prevent parsing failures.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Adapts to the text length of audit working papers and rectification ledgers, retaining the complete semantic meaning of a single rectification requirement or audit issue |
| `chunkSplitter` | `By line + By paragraph` | Adapts to structured data in multi-column Excel rectification ledgers and issue lists, avoiding splitting a single business record |
| `customPdfParse` | `Enabled` | Adapts to PDF documents with tables such as internal control self-evaluation reports, retaining table row and column structure and preventing text disorder |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Adapts to annual batch uploads of multiple audit document collections, meeting batch import requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Prevents parsing timeouts for large PDFs or Excel files, enabling complete parsing of multi-page audit reports |
| `chunkSettingMode` | `Manual configuration` | Adjusts chunking rules for structured documents, avoiding business association breaks caused by automatic chunking |

## Common Misconfigurations
- Symptom: When uploading documents in batch, the parsing result includes all previously uploaded document content. Cause: The parsing scope is not restricted, or the configuration to only parse currently uploaded attachments is not enabled, causing the system to load all historical documents for chunking.
- Symptom: After uploading a multi-column rectification ledger Excel file, automatic chunking splits cross-row and cross-column data, failing to retain the integrity of a single rectification record. Cause: The default paragraph-based chunking rule is used, which does not adapt to the row-level association of structured tables, and the `chunkSplitter` configuration is not adjusted.
- Symptom: After uploading an audit notice PDF with embedded tables, the parsed result loses table column alignment information and text displays incorrectly. Cause: The `customPdfParse` configuration is not enabled, and the default PDF parsing engine is used, which cannot retain table structure.

## How to Verify Correct Configuration
- Upload a single rectification ledger Excel file, check if the chunking result treats each row of data as an independent chunk to verify that the chunking rule is active.
- Upload a multi-page audit report PDF, view the parsing progress log to confirm that only the currently uploaded document is parsed, and no historical documents are loaded.
- Upload a large internal control self-evaluation report, check if the parsing task completes within the time set by `PARSE_FILE_TIMEOUT_SECONDS` without timeout errors.
- Upload a document containing tables, check if the parsed text retains the table row and column structure to verify that the PDF parsing configuration is active.

The values provided are common starting points and should be evaluated against the reader's own samples.
