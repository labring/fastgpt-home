# Document and Material Drafting for Medical Insurance Fund Supervision and Audit: Citation Source and Traceability

## What the data for this category looks like
This category's data comes from medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and complaint clues. The update frequency is monthly. Daily produced documents include audit notices, inspection work papers, suspicion lists, interview records, handling decision letters, and rectification reports. Most document structures include main body information, suspicion descriptions, supporting material numbers, and processing basis fields. These fields are often linked to standardized coding fields such as medical insurance settlement serial numbers and drug and consumable codes.

## What constraints these characteristics impose on the citation source and traceability link
The monthly updated data characteristics require the traceability link to adapt to batch synchronized knowledge base update logic, to avoid referencing expired supervision rules or settlement data. Documents must be linked to standardized fields such as medical insurance settlement serial numbers and drug and consumable codes. Precise matching of corresponding data entries is required during traceability, and generalized reference to vague content is not allowed. Supporting materials from multiple system sources require the traceability link to support cross-data source entry association. At the same time, a single document has a large number of supporting materials, so the length of the referenced context must be limited to prevent exceeding the model's processing limit.

## How to set the configuration
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 characters` | The supporting materials for documents in this category are mostly structured entries, with moderate single-reference length. This range can cover core supporting content and avoid context overflow. |
| `responseData` | Return only associated document chunks | Audit documents require precise association with compliant supporting materials, filtering out irrelevant content to avoid returning settlement data unrelated to suspicions. |
| `detail` | Enabled | The processing decisions for this category need to clearly mark supporting sources. When enabled, traceability information can be embedded in the generated documents. |
| Single search limit | Top 8 entries | The knowledge base data volume updated monthly is moderate. The top 8 entries can cover main suspicion supporting materials, avoiding redundant content interfering with document drafting. |
| Knowledge base chunk length | `1500–2000 characters` | The settlement data and rule entries for this category are mostly structured long texts. This chunk length can retain complete rule or settlement entry information, facilitating precise traceability.

## Three common mistakes
- Phenomenon: The generated audit document references settlement data entries unrelated to the current suspicion. Cause: The `responseData` setting was not configured to return only associated document chunks, causing the model to recall irrelevant content from the knowledge base.
- Phenomenon: Traceability information is missing or formatted chaotically in the generated documents. Cause: The `detail` configuration was not enabled, so no traceability identifiers for associated documents were embedded in the generated content.
- Phenomenon: The generated traceability content exceeds the model's processing limit, causing response errors or content truncation. Cause: `quoteMaxToken` was not set reasonably, and the referenced context length exceeds the maximum character limit supported by the model.

## How to confirm the configuration is correct
- Upload a sample of medical insurance settlement data and a sample of supervision rules to the knowledge base, trigger the audit document drafting process, and check whether the returned traceability information is linked to the corresponding sample entries.
- Check the length of the referenced context in the generated documents to confirm it does not exceed the preset `quoteMaxToken` range.
- Check whether the generated traceability identifiers include key information such as document source and entry number, confirming that the `detail` configuration is enabled.
- Simulate a query unrelated to medical insurance audit suspicions, confirm that the system only returns content related to the current audit topic and filters out irrelevant results.

Note: The values listed here are common starting points and should be evaluated against the reader's own samples.
