# Document and Material Drafting for Medical Insurance Fee Settlement Audit: Workflow Orchestration

## What This Category of Data Entails
Core data for this category covers daily business documents of national medical insurance administration and designated medical institutions, including medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection notice lists, and settlement reconciliation statements. These documents support drafting documents related to settlement audit, such as rejection appeal letters and settlement reconciliation reports.
Data sources include the National Medical Security Information Platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding libraries, and cross-regional medical settlement platform. The update frequency is daily.
Data fields include diagnosis and treatment project matching codes with the medical insurance catalog, single or batch expense amounts, insured person identity identifiers, and rejection reason identifiers. These fields support core verification links for settlement audit.

## Constraints Imposed on Workflow Orchestration
Diverse data sources require workflows to integrate multiple nodes that call different data sources. This ensures complete retrieval of settlement lists, expense details, and other documents. It provides accurate materials for subsequent document drafting.
The daily update frequency requires workflows to support daily-scheduled batch processing. This adapts to the processing rhythm of massive daily settlement data and ensures the timeliness of document drafting.
The high time consumption of core verification links requires workflows to split independent nodes for tasks such as coding matching, expense consistency verification, and rejection reconciliation. This avoids excessive load on a single node that reduces document generation efficiency.
The potential impact of data verification errors requires workflows to configure exception branches. These branches trigger alert and manual intervention processes for scenarios such as coding mismatches and expense inconsistencies, ensuring drafted documents meet compliance requirements.
The parallel business demand for single and batch processing requires workflows to support two trigger modes: single data entry and batch batches. This adapts to audit scenarios of different scales.

## Three Common Misconfigurations
- Symptom: The session button added in the workflow does not trigger subsequent nodes. Cause: The button's submit event is not bound to the correct `nodeId`.
- Symptom: Flowchart links generated by Mermaid cannot be displayed normally in workflow nodes. Cause: The correct output format is not configured to adapt to the workflow's display rules.
- Symptom: An error occurs for the cycle processing node's trigger count limit in the workflow. Cause: The cycle trigger threshold is not adjusted according to the single-batch settlement data scale, resulting in exceeding the preset limit.

## How to Verify Correct Configuration
- Trigger a test batch of settlement data, check whether the workflow starts the corresponding nodes based on the batch number in `variables`.
- Simulate a coding matching failure scenario, confirm whether the exception branch triggers the preset alert and manual intervention nodes.
- Click the submit button in the session, check whether it jumps to the subsequent reconciliation and archiving process nodes.
- View the workflow running logs, confirm that no timeout or abnormal errors occur in the batch processing nodes.
