# Document and Material Drafting for Medical Insurance Expense Settlement Audit: Source Citation and Traceability

## What the data for this category looks like
Core data for this category comes from the national medical security information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical settlement platform. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Most documents are in structured formats, with fields including settlement number, diagnosis and treatment project code, expense amount, insured person identity identifier, payment time, and more. The data update frequency is daily, covering all settlement businesses completed on the same day.

## Constraints on the "source citation and traceability" link
The data sources for medical insurance settlement audit are scattered and updated daily. Traceability information must accurately associate with original documents of the corresponding time and institution. A single settlement involves multiple related documents. Traceability must clearly match specific fields of each document to avoid confusion across documents. The audit link requires verification of consistency between expenses, medical records, and prescriptions. Traceability must display the original catalog library basis for coding matching. In batch processing scenarios, traceability must support full-link document association for a single settlement to ensure audit results are traceable.

## How to Configure
This configuration is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the text length of medical insurance settlement detail documents to avoid truncating key traceability information such as expense codes and amounts |
| `responseData` | Enabled | Binds the storage path and field information of original documents such as settlement lists and prescriptions stored in the knowledge base |
| `detail` | Enabled | Displays specific expense items and coding matching results in traceability information to meet the detailed verification needs of audits |
| Single recall limit | Top 5 entries | Matches the number of related documents corresponding to a single settlement to avoid redundant information interfering with audit judgment |
| Maximum context length | Calibrated based on actual testing | Adapts to multi-document association requirements during batch settlement audit |

## Three Common Configuration Mistakes
- Failing to enable the `responseData` configuration results in the answer content output by the workflow not being attached with original document information recalled from the knowledge base, leading to empty citation results. The cause is that the source data return configuration is not enabled, and the association between the answer and original settlement documents is not established.
- Incorrectly setting the `quoteMaxToken` value results in reference text being excessively truncated, leading to incomplete display on the interface or text overflow prompts in logs. The cause is that the actual text length of medical insurance settlement documents is not matched, and key expense details or coding information is truncated.
- Failing to enable the `detail` configuration results in traceability information only displaying document titles, unable to display specific matched expense items and coding basis, leading to auditors being unable to complete verification. The cause is that the detailed traceability mode is not enabled, and detailed fields of traceability are not expanded.

## How to Confirm the Configuration Is Correct
- Initiate a simulated settlement audit request, and check whether associated document identification and specific field information are attached at the end of the answer content.
- Check the output variables of the workflow node to confirm whether original settlement document content recalled from the knowledge base is included.
- Adjust the value of `quoteMaxToken` to verify whether the truncated text conforms to the expected length range.
- Check system operation logs to confirm that the traceability request has correctly associated data sources related to medical insurance settlement.
