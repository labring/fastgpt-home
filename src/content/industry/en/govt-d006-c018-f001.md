# Document and Material Drafting for Enrollment Registration and Payment Verification: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
This category’s data originates from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily. Daily produced documents include enrollment registration forms, payment base declaration forms, personnel change forms, social insurance premium verification forms, and personal benefit records. Fields cover unit subject identifiers, personnel identity information, payment bases, enrollment status, and more. Different connected systems have varying field formats. Field mapping must be completed per external interface requirements.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Multi-source data docking requires interfaces to support multiple authentication methods, to adapt to identity verification rules of different systems. The daily update frequency requires interface configuration of scheduled trigger logic, to ensure data synchronization timeliness. The heterogeneity of document fields requires a flexible variable mapping mechanism, to achieve automatic matching between different system data and document templates. Data errors can lead to underpayment, missed payments, or incorrect personal benefit records. Therefore, interfaces must be configured with retry and exception verification mechanisms, to ensure data consistency.

## How to Configure Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {system-generated interface secret}` | Complies with general interface authentication specifications when connecting to external social insurance and tax systems |
| `variables` | Map fields such as enrollment registration number and payment base to variables, with a value range of 100-500 characters | Enables automatic injection of external system data into document templates, and adapts to different field formats |
| `responseData` | Extract core fields such as verification form number and payment amount, filter null values and redundant data | Only retains valid information required for business, simplifying subsequent document generation processes |
| Interface call timeout | 600 seconds | Addresses long-duration scenarios of cross-system reconciliation, avoiding synchronization interruptions |
| Retry trigger rule | Triggered when the response status code is 5xx or a timeout occurs, with 3 retry attempts | Addresses temporary fluctuations in external systems, ensuring stability of data synchronization |

## Three Common Misconfigurations
- Symptom: HTTP interface returns 401 unauthorized error. Cause: The `Authorization` header is not configured correctly, or the secret format or permissions do not meet the external system’s authentication requirements.
- Symptom: Personnel identity fields are empty in generated documents. Cause: External system returned identity data is not correctly mapped to the `variables` parameter, resulting in uncompleted injection of business variables.
- Symptom: Generated payment verification forms do not match tax system data. Cause: Latest payment base data is not pulled from the daily updated data source, so the interface uses outdated business data, leading to data reconciliation errors.

## How to Confirm Configurations Are Complete
- Call the configured HTTP interface, check whether the `responseData` contains expected core fields such as enrollment registration number and payment amount.
- Simulate a personnel change scenario, inject test personnel identity and payment base data via `variables`, and verify that the generated document template correctly fills the corresponding fields.
- Simulate a 503 error returned by an external system, trigger the interface retry mechanism, and check whether automatic retry is completed as configured.
- Compare the original data returned by the interface with the field format of local business documents, confirm that the mapping relationship meets the requirements of the connected system.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
