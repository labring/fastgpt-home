# Document and Material Drafting for Social Insurance Registration and Premium Verification: Tool Calling and Plugins

This document applies to FastGPT v4.17.0.

## What the data for this category looks like
Data for this category comes from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. Daily processed documents include social insurance registration forms, payment base declaration forms, personnel adjustment forms, social insurance premium verification notices, and personal benefit records.

Data is updated daily. Each document includes fields such as main entity identity information, personnel insurance status, payment base, verified amount, and more. Field units match business scenarios: payment base uses yuan as the unit, and personnel count uses persons as the unit.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data for this category comes from multiple sources and is updated daily. This requires tool calling to support connecting to plugins for social insurance management, tax collection, and other systems, to ensure the latest registration and premium data is retrieved.

Document fields include multiple types of unit and personnel information. Field mapping rules must be configured via plugins to unify data formats and units returned by different systems.

Since core steps involve verifying personnel identity and labor relations, and cross-system data reconciliation, tool calling must integrate dedicated identity verification and data reconciliation tools to prevent subsequent errors caused by data mismatches.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto`, bound to identity verification, data reconciliation, and document generation tools | Adapts to multi-step business requirements, automatically selecting corresponding tools to handle scenarios such as insurance registration, premium verification, and reconciliation |
| `functionCall` | Enabled, requires returning JSON format results | Ensures tool call results meet the field format requirements of social insurance documents, facilitating direct integration to generate standard documents |
| Tool call timeout period | 600 seconds | Requires pulling data from multiple systems and completing cross-source reconciliation; a longer timeout prevents call failures due to incomplete data return |
| Context window size | 8000–12000 token | Must accommodate field information from multiple social insurance documents and cross-system data to ensure information integrity during tool calls |
| Tool call retry count | 3 times | Addresses occasional fluctuations in multi-system interfaces, preventing business process interruptions from a single failed call |

## Three common mistakes
- Symptom: Tool call returns `messages is empty` error. Cause: Basic data from the social insurance management system was not loaded into the context window, resulting in no available business information to support tool calls.
- Symptom: Tool calls after configuration are slow, but directly curling the target interface has normal speed. Cause: No caching mechanism for multi-system data was configured; each call repeatedly pulls full daily updated data, leading to increased latency.
- Symptom: Generated social insurance registration forms lack the unified social credit code field. Cause: Required fields were not specified in the `functionCall` configuration, so the tool call results do not include core information required for the document.

## How to confirm the configuration is correct
- Initiate a simulated social insurance registration tool call, check if the returned results include the preset tool list and parameter format.
- View tool call logs to confirm that the latest data from the social insurance management system and tax system has been successfully pulled.
- Generate a test payment base declaration form, verify that the fields match the preset social insurance document structure.
- Simulate multiple calls, check if the retry mechanism triggers normally during interface fluctuations.

The values provided are common starting points and should be measured against the reader's own samples.
