# Document and Material Drafting for "Double Random, One Public" Supervision Inspections: Tool Calling and Plugins

## What the data for this category looks like
Data for this category typically comes from the "Double Random, One Public" supervision platform, enterprise credit information disclosure system, industry supervision systems, and law enforcement officer directory. The update frequency is once per month. Daily generated documents include inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result announcements. Data fields include the unified social credit code of inspection targets, supervision category, law enforcement officer qualification number, and other relevant fields. Documents are stored grouped by administrative region and supervision batch.

## What constraints these characteristics impose on tool calling and plugins
The monthly data update requirement means tool calling logic must be configured to regularly synchronize data sources. This prevents use of expired inspection target or law enforcement officer information. The need for multiple document types means plugins must adapt to field-filling rules for different templates. For example, inspection plans require batch numbers and administrative regions to be filled in. On-site inspection records must link to inspection item lists. Scattered data sources mean plugins must pull data from multiple systems uniformly. They also require validation of field completeness to avoid missed public disclosure of inspection results or non-compliant extraction caused by missing information.

## How to set up the configuration
All configurations below are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Auto-match business plugins | Must automatically call dedicated plugins for law enforcement officer matching and inspection target extraction to reduce manual configuration errors |
| `functionCall` | Enable mandatory field validation | Must validate required fields such as the unified social credit code of inspection targets and supervision item code to ensure compliance of document formats |
| Data source synchronization cycle | 7 days | Matches the monthly data update frequency, balances data timeliness and call resource consumption |
| Plugin call trigger timing | Trigger at supervision batch generation node | Aligns with the batch-based workflow of "Double Random, One Public" supervision work, avoids invalid calls |
| Workflow unique ID binding rule | Link to supervision batch number | Facilitates tracking workflow execution status by batch, meets the traceability requirements of supervision archives |
| Call retry count | 3 times | Addresses network fluctuations or temporary unavailability of data sources during single calls, improves call success rate |

## Three Common Mistakes
- Symptom: The generated inspection target list includes canceled entities or duplicate entries. Supervision target extraction is non-compliant. Cause: No data source synchronization logic is configured. Expired enterprise credit information data is used, and duplicate item validation is not enabled.
- Symptom: No return result is generated after the workflow calls an external Python code function. Logs show parameter transfer failure. Cause: Parameter transfer rules are not configured according to business field formats. For example, the unified social credit code of inspection targets is not converted to a standard string format.
- Symptom: No inspection result announcement document is generated after plugin calls, and the call process cannot be traced. Cause: The workflow log recording switch is not enabled, or the log storage path is not configured. This prevents troubleshooting of missed inspection result public disclosure issues.

## How to confirm the configuration is correct
- Manually trigger a test supervision batch workflow. Verify that the generated inspection target list matches the locally synchronized data source.
- Review workflow execution logs. Confirm that `toolChoice` automatically calls the corresponding business plugin, and that `functionCall` validates all required fields.
- Check that the workflow unique ID is bound to the test batch number. This ID can be used to retrieve the corresponding execution record.
- Simulate a plugin call failure scenario. Confirm that the system attempts to retry calls according to the configured retry count.

The values provided are common starting points and should be measured against the reader's own samples.
