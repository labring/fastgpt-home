# Document and Material Drafting for Territorial Spatial Planning Compilation and Implementation Evaluation: HTTP Interfaces and External Systems

## What data is included in this category
This category’s daily documents include territorial spatial master plans, detailed plans, special plans, planning implementation evaluation reports, public opinion summaries, and similar materials. Data sources include the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics data, and remote sensing image data. Data is updated annually. Most document structures include three core modules: regional spatial layout, constraint indicators, and departmental and public opinions. Fields include spatial coordinates, construction land scale, ecological protection red line area, planning cycle, and similar items. Each individual document links to multi-source heterogeneous spatial and statistical data.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Most data sources are regional-level spatial and statistical data. Single requests carry large data volumes. Interfaces must support high-volume transmission. Data is updated annually. Interface call frequency must stay low. Frequent data pulling must be avoided. Document structured modules require interfaces to return splittable structured data. This adapts to drafting needs for different document chapters. Multi-source data integration requires interfaces to support parallel calls of multiple data sources and result aggregation. This reduces local organization workload.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication configuration | Valid token with Bearer prefix, set expiration to 7 days | Adapts to external system interface authentication requirements, avoids frequent token refreshes that affect call stability |
| Request variables | Pass two required parameters: planning area code, evaluation year | Matches territorial spatial planning data retrieval logic by area and year |
| Response data format | Structured data blocks split by planning document chapters | Adapts to chapter-by-chapter drafting needs for different planning document types |
| Timeout setting | 600 seconds | Handles long response times for multi-source spatial data pulling |
| Single request data volume | Within 1000 MB | Avoids exceeding external interface transmission thresholds |
| Retry strategy | Retry 2 times when network timeout or 5xx status code occurs | Addresses occasional fluctuations in natural resource data interfaces |

## Three common misconfigurations
- A 401 unauthorized error is returned during calls, and the interface prompts a call failure. The cause is incorrect configuration of the `Authorization` parameter, or expired tokens that are not updated in time. This is a common issue where third-party interfaces cannot be called after configuration.
- An SQL permission error occurs after restarting the Docker container, and logs prompt a database connection failure. The cause is unadjusted correct permissions for the database directory mounted by the container under the Ubuntu system, preventing the FastGPT process from reading database files.
- The number of planning data entries recalled by the knowledge base is insufficient and cannot cover the complete regional scope. The cause is failure to correctly pass the planning area code request variable, causing the interface to only return data for part of the area, which affects the completeness of document drafting.

## How to confirm correct configuration
- Send a test request, pass the planning area code and evaluation year parameters, and check if the interface returns structured data blocks split by document chapters.
- View interface call logs, confirm authentication parameters are correctly carried, and there are no 401 or 5xx error records.
- Simulate a timeout scenario and send a high-volume request, confirm the retry strategy takes effect, and there is no data loss or call interruption.
- Compare returned response data with public data from the territorial spatial basic information platform, confirm field matching meets business requirements.
