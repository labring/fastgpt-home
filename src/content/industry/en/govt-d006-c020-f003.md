# Document and Material Drafting for Territorial Spatial Planning Compilation and Implementation Evaluation: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category primarily originates from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistical data, and public remote sensing images. Daily produced documents include territorial spatial overall planning, detailed planning, special planning texts, planning implementation evaluation reports, and public opinion summary materials. The data update cycle is annual. Most document structures include fields such as spatial coordinate annotations, constraint indicator entries, and regional development calculation data. All content must match the compilation specifications of regional planning.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Most data in this category is cross-source aggregated spatial and government affairs information. The annual update feature requires multi-turn dialogue to use the latest basic data. Outdated constraint indicators must be avoided. Document types cover planning texts and evaluation reports. Field differences across document types require prompts to adapt to different output format requirements. Multi-source data integration demands gradual clarification of data sources and accuracy ranges during dialogue. This prevents information deviation across links. The unstructured nature of public opinion summaries requires multi-turn dialogue to support gradual sorting of scattered demands. Unlike individual planning permit documents, this category handles multi-year constraint indicators for entire regions. Multi-turn dialogue must therefore cover a wider range of spatial data.

## Configuration Settings

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current planning project | Distinguish planning compilation tasks for different regions or batches |
| `messages` | Organize as multi-turn context according to the segmented structure of planning documents | Adapt to the structured characteristics of documents in this category, avoid context confusion |
| `variables` | Preset territorial spatial constraint indicators and regional population data as fixed variables | Reduce repeated input, match the annual update data feature |
| Maximum context window | 8000–12000 characters | Accommodate complete fragments of multi-source spatial data and planning texts |
| Single dialogue timeout | 600 seconds | Prevent dialogue interruption caused by multi-source data queries |
| Single dialogue return limit | Top 3 entries | Avoid excessive output content interfering with the coordination work of planning layout |

## Three Common Configuration Mistakes
- Phenomenon: Configured guide prompts do not take effect. Output content deviates from planning document format requirements.
  Cause: The `variables` parameter is not bound to the guide prompt. The prompt fails to match preset planning terminology rules.
- Phenomenon: A call failure error occurs when switching dialogue models. Planning-related content cannot be generated normally.
  Cause: Model switching permission is not enabled in the application configuration. No corresponding call key is configured for the new model.
- Phenomenon: An unauthorized prompt displays when calling the knowledge base dialogue application. The API key has been configured.
  Cause: The `chatId` is not bound to the authorization scope. The system cannot verify the access permission of the current planning project.

## How to Verify Successful Configuration
- Manually enter a planning-related test question. Check if output content matches constraint indicators in the preset `variables` parameter.
- Switch between different model options. Confirm the dialogue process runs normally and returns content compliant with planning specifications.
- Check if the `messages` context includes the latest annual updated data. Avoid calling outdated information.
- Generate test content for public opinion summary. Check if output format matches planning document structural requirements.
