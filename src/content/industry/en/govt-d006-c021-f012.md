# Document and Material Drafting for Centralized Treasury Payment and Reimbursement Audit: Deployment and Upgrade

## What the data for this category looks like
Daily processing documents for this category include payment applications, fund use plans, invoices, contracts, acceptance receipts, reimbursement approval forms, payment vouchers, and other materials. Data sources are the centralized treasury payment system, integrated budget management system, electronic invoice platform, and contract management system, with updates daily. Documents must verify core fields such as budget indicators, economic classification, and the invoice-contract-acceptance chain. Single fund payment compliance is the core check point. This is document processing work in the daily fiscal payment execution link.

## What constraints these characteristics impose on the deployment and upgrade link
The data sources for this category cover multiple fiscal business systems. The daily update frequency requires configuring a stable cross-system data synchronization link during deployment. Documents need to verify associated fields such as budget indicators and economic classification. The upgrade process must retain original business check rules to avoid compliance logic failure. There are strict time requirements for document processing of single fund payments. Deployment nodes must ensure single request response aligns with business rhythm. For multi-reviewer collaboration scenarios, support fine-grained permission configuration to adapt to the operation scope of different positions.

## How to Set Configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `DB_MAX_LINK` | `100–150` | This category synchronizes data from multiple systems daily, requiring a database connection pool sufficient to support concurrent requests |
| `MONGODB_URI` | Use the read-only replica set address exclusive to fiscal business systems | This category's data needs to connect to multiple systems, and read-only replicas avoid affecting the performance of core business databases |
| `PG_URL` | Bind to the locally deployed fiscal data storage repository address | Audit documents for this category require persistent storage, and local repositories ensure data compliance |
| `REDIS_URL` | Configure a cache address with a 600-second expiration time | Daily updated business data needs temporary caching to reduce repeated query overhead |
| `STORAGE_S3_ENDPOINT` | Connect to the endpoint of the fiscal electronic archive storage service | Document materials for this category require compliant storage, and connecting to official storage services meets regulatory requirements |
| `FILE_TOKEN_KEY` | Encryption key calibrated through actual testing | Document materials involve fiscal sensitive data, requiring secure transmission encryption |

## Three Common Misconfigurations
- Issue: After deployment, using the same model to build a knowledge base results in fiscal document markdown hierarchy inconsistent with the public network version. Cause: No exclusive text parsing rule configured for the fixed format of documents in this category, leading to incorrect splitting of structured fields.
- Issue: After multi-node deployment, some nodes cannot access uploaded documents such as reimbursement audit forms. Cause: No unified `STORAGE_S3_ENDPOINT` shared storage configured, and nodes do not share data storage paths.
- Issue: After local deployment, the team management function cannot be enabled, and operation permissions for different review positions cannot be assigned. Cause: `FE_DOMAIN` and backend service association parameters not correctly configured, or the built-in switch for team management not enabled.

## How to Confirm Configuration Is Complete
- Run a cross-system data synchronization test, check the field integrity of payment application documents imported from the centralized treasury payment system, and confirm the data synchronization link is normal.
- Upload a single reimbursement approval form, trigger knowledge base retrieval, check that the returned text parsing format conforms to the business document structure, and confirm the text parsing rules take effect.
- After configuring a multi-node cluster, upload a document material, perform a retrieval operation on all nodes, confirm all nodes can access the document, and confirm the shared storage configuration is correct.
- Enable the team management function, create two test accounts with different permissions, attempt to access and modify audit documents respectively, and confirm the permission configuration takes effect.
