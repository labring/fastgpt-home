# Document and Material Drafting for Land Use Rights, Mineral Rights, and State-Owned Property Transactions: Tool Calling and Plugins

## Data Profile for This Category
This category’s data typically comes from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. Data updates occur daily. Daily processed documents include transfer announcements, trading notices, bid applications, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications. Most document fields include transaction subject ownership information, restriction conditions, valuation standards, margin amounts, transaction time, and other details. Units include specific measurement items such as plot area, mineral reserve, and property transaction amount.

## Constraints for Tool Calling and Plugins
Data comes from multiple independent business systems and is updated daily. Tool calling must use multi-source data synchronization logic to ensure plugins access the latest transaction subject information in real time. Different document types have unique field requirements. Plugins must support structured extraction rules for documents like transfer announcements and transaction confirmation letters. Fields related to transaction subject ownership and valuation involve state-owned asset security. Tool calling parameter passing must adapt to sensitive data verification logic. Document drafting errors can lead to invalid transactions and disputes over state-owned asset loss. Plugins must include built-in call failure retry and exception alert mechanisms.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto or bound to a designated transaction-type tool | This category requires precise calling of ownership verification and document generation tools to avoid irrelevant calls interfering with document drafting |
| Plugin data source synchronization frequency | every 24 hours | Matches the daily update rhythm of this category’s data to ensure the information obtained by the plugin is the latest version |
| `functionCall` | mandatory enablement of parameter verification | Transaction-related documents involve sensitive fields such as ownership and amount, requiring compliance with parameter format and field rules |
| Call timeout threshold | 600 seconds | Adapts to the network delay range of multi-system docking, reducing call failures caused by temporary network fluctuations |
| Call failure retry count | 2–3 times | Addresses temporary exceptions from multi-source system docking, improving plugin call stability |

## Three Common Misconfigurations
- Phenomenon: When the stream parameter is set to true in the calling interface, segmented streaming results are returned. Complete transaction document content cannot be obtained directly. Cause: Aggregation logic for streaming results is not configured, and the step to concatenate segmented results is not implemented in the plugin.
- Phenomenon: When calling the plugin via API, file-type transaction parameters cannot be passed normally. This causes failure to generate documents such as bid applications and transaction confirmation letters. Cause: The mapping relationship for file parameters is not configured per the field rules of this category’s documents, and required fields in file content are not verified.
- Phenomenon: When importing a plugin in a privately deployed FastGPT v4.14.1 instance, an internal server error is displayed. Cause: The plugin configuration includes unsupported multi-source business system addresses, or the deployment environment’s network policy restricts access to plugin interfaces.

## How to Verify a Complete Configuration
- For FastGPT v4.17.0, manually trigger a plugin call and confirm the returned document content covers all required fields for this category’s documents.
- Set the stream parameter to true, call the plugin, and verify that complete transaction-related documents can be generated by aggregating results.
- After importing the plugin, test the connected configured business system data source and confirm daily updated transaction data can be synchronized normally.
- Call the configured tools and confirm only legal tools related to land use rights, mineral rights, and state-owned property transactions are triggered.
