# Document and Material Drafting for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Deployment and Upgrade

## What this category of data looks like
Daily documents for this category typically include transfer announcements, transaction notices, bid applications, margin vouchers, transaction confirmation letters, listing result announcements, property transfer descriptions, and similar materials. Data typically comes from the national public resource trading platform, natural resource trading systems, property exchange systems, and state-owned asset supervision systems, with a daily update frequency. Most document structures revolve around core fields such as transaction object ownership, restriction conditions, bidding rules, margin requirements, and transaction confirmation. They include unitized information such as right type, object location, and transaction amount. There is no unified fixed format, and adjustments are required to meet the field requirements of different transaction scenarios.

## What constraints these characteristics impose on deployment and upgrades
Data sources are scattered and updated daily. During deployment, configure multi-source data synchronization to adapt to the interface formats of different systems. During upgrades, ensure synchronization tasks do not interrupt current transaction document generation. Document fields are diverse and scenario-specific. Reserve sufficient custom field mapping space to avoid hardcoding restrictions. Transaction documents involve ownership and state-owned asset security. Strictly configure permission isolation during the deployment phase. Prepare rollback plans during upgrades to prevent data tampering. Daily updated batch data requires adaptation to large-file storage and retrieval configurations to avoid resource exhaustion during document generation.

## How to set configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `PG_URL` | `postgresql://user:pass@host:5432/resource_trade` | Stores structured metadata for transaction objects and documents, adapts to database specifications of state-owned asset and natural resource systems |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-north-1.example.com` | Stores batch-generated transaction documents and margin vouchers, adapts to access addresses for public cloud or intranet storage |
| `REDIS_URL` | `redis://:auth@host:6379/0` | Caches daily updated transaction announcement data to reduce source system call frequency, expiration time is determined based on actual testing |
| `FE_DOMAIN` | `https://trade-docs.example.com` | Configures the access domain name for the document generation page, must match the public network filing address |
| `ROOT_KEY` | `Randomly generated 32-bit string` | Configures the initial system administrator key for first-time login and permission management |
| `DB_MAX_LINK` | `20–30` | Controls the number of database connection pools, adapts to concurrent requests from daily batch document generation, avoids connection exhaustion |

## Three common mistakes
- A `POST /api/admin/initv4818 404` error is returned when running the upgrade script. The cause is that the front-end domain name and back-end interface mapping relationship are not correctly configured, causing the upgrade interface path to fail to parse correctly.
- The initial login username and password cannot be retrieved after deployment. The cause is that the `ROOT_KEY` parameter was not correctly generated or configured, causing the system to fail to initialize administrator account information.
- Message receiving address verification fails when configuring the DingTalk robot. The cause is that the public network address of the document generation service is not configured to be accessible, or non-secure certificate verification is not disabled when no valid SSL certificate is present.

## How to confirm successful configuration
- Run the database connection test command to verify that the address, port, and authentication information configured in `PG_URL` and `REDIS_URL` can connect normally.
- Upload a sample transaction transfer announcement document to trigger the document generation process, and check whether the generated document fields match the ownership and transaction information of the source data.
- Access the configured `FE_DOMAIN` address to verify that the front-end page loads normally and the administrator login entry is available.
- Trigger a daily data synchronization task and check that there are no source system interface call failure records in the synchronization log.

The values provided are common starting points and should be measured against the reader's own samples.
