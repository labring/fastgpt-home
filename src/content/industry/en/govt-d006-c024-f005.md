# Document and Material Drafting for Student Aid and Subsidy Review: Tool Calling and Plugins

## What this category of data looks like
Typical business entities include education bureau aid centers, school student affairs offices or aid offices, and financial departments. Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Data sources cover the national student aid management information system, school student status systems, civil affairs low-income and extremely poor household data, and financial payment systems. The update cycle is per semester. Data fields include identity identifiers, student status numbers, low-income certification numbers, bank card numbers, applied amounts, and other relevant fields. Units adjust based on the specific business document type, with no unified fixed standard.

## Constraints imposed on tool calling and plugins
Multi-source cross-system data sources require tool calling to connect multiple independent data sources simultaneously. Corresponding plugins must be configured to pull data across systems. The semester-level update cycle requires tool calling to support scheduled data synchronization, preventing use of expired student status or civil affairs data. Strict document field matching requirements mean tool calling must first verify data field consistency, to avoid mismatched identities and aid information. Error outcomes directly affect aid disbursement accuracy. Therefore, a verification step must be added to tool calling results, to ensure generated documents and materials use accurate data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `required` | Force the model to call tools to process business data, avoid directly generating unsubstantiated responses |
| Tool call timeout duration | `300–600 seconds` | Querying student status, civil affairs, and financial data across multiple systems typically takes a long time. Sufficient response time must be reserved |
| `functionCall` | `Only call preset tool sets` | Limit the model to only call data source query and document generation tools required for the business. Prevent calls to unrelated functions |
| Number of items returned per single tool call | `Top 10 items` | Control the volume of returned data. This avoids processing delays caused by overload, while covering most business data |
| Data source field mapping switch | Enabled | Ensure that data fields pulled across systems correspond one-to-one with fields required by business documents |
| Public notification material template binding | Bind by review batch | Match the format requirements of different batches, ensure generated materials comply with specifications |

Reference only; verify against the target FastGPT release and deployment documentation.

## Three common configuration errors
- Phenomenon: The model fails to select tools and directly generates natural language responses. Cause: `toolChoice` is not set to `required`, or the preset tool set does not include the data source query and document generation actions required for the business.
- Phenomenon: The database plugin cannot connect to the specified data source. Cause: Corresponding database driver parameters are not configured, preventing access to business data from student status or financial systems.
- Phenomenon: Tool call returns a format error. Cause: The model’s `functionCall` format requirements are not matched, making the request non-compliant with the model’s interface specifications.

## How to verify correct configuration
- Manually trigger a tool call, then check system logs to confirm the specified data source query plugin and document generation tool are called as preset.
- Review the tool call return results, confirm core business fields such as student status numbers, low-income certification numbers, and bank card numbers are included.
- Check the tool call duration record, confirm the duration falls within the `300–600 seconds` preset range.
- Generate a test public notification material, confirm its format matches business document requirements.
