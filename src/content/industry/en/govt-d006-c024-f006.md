# Document and Material Drafting for Student Aid and Subsidy Review: Citation Sourcing and Traceability

## What the data for this category looks like
Data involved in this category mainly comes from the National Student Aid Management Information System, school student status system, civil affairs low-income and special hardship data, and fiscal payment system. Documents routinely generated and verified include family economic hardship certification forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Data updates follow a semester cycle. Each document contains core fields such as student identity identifier, family economic status certification result, aid application information, and disbursement details. Cross-system data must be associated to complete cross-verification.

## What constraints these characteristics impose on the "citation sourcing and traceability" link
Cross-system data sources require the traceability link to connect multiple independent data sources, to avoid bias from a single data source. The semester-level update cycle means the knowledge base synchronization frequency must match the semester rhythm, to avoid using expired data. Document types cover certification forms, review forms, disbursement lists, and others. Core verification fields differ across document types, so corresponding data traceability rules must be matched for each document type. Error consequences in the verification link directly relate to student aid eligibility and fund disbursement. This requires accuracy and traceability of traceability information, ensuring every audit basis can be linked to the original data node.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–12000 token | Matches the total length of cross-system student aid data, to avoid truncating core verification information |
| Maximum Knowledge Base Citations | Top 6 entries | Covers core data sources across multiple systems, to avoid redundant information interfering with audit logic |
| `quoteMaxToken` | 1500–2000 characters | Limits the length of a single citation, to ensure cited content is clear and non-redundant during document drafting |
| `responseData` | Enabled | Retains fields of original citation data, to facilitate subsequent traceability verification |
| `detail` | Enabled | Displays the source system and update time of cited data, matching the traceability requirements of semester-level data |
| Maximum Response Tokens | 3000–4000 token | Adapts to the drafting needs of long documents such as review forms and public notification materials |

## Three common errors
- Excessive and cluttered citation marks appear in generated documents. The cause is failure to limit the values of `quoteMaxToken` and maximum knowledge base citations, leading to a large number of redundant data sources being included in the citation scope.
- Red error prompts appear in the interface and citation content is empty. The cause is that the `responseData` configuration is not enabled, so the system cannot obtain valid fields of original citation data, resulting in traceability information failing to display normally.
- Expired data appears in generated audit documents. The cause is that the knowledge base synchronization frequency does not match the semester update cycle, so cited student status and low-income data are from the previous semester, and synchronization for the latest cycle has not been completed.

## How to confirm the configuration is properly set
- Test generating a draft of the family economic hardship certification form, check if the number of citation marks and source systems match the preset maximum knowledge base citation value.
- View the citation details of the generated content, confirm that it includes the source system and update time information displayed by the `detail` configuration.
- Trigger the traceability verification process to verify that the cited content can be linked to the original data node of the corresponding system.
- Adjust the value of `quoteMaxToken`, observe the length change of a single citation content, and confirm that the configuration takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
