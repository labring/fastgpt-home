# Document and Material Drafting for Student Financial Aid and Subsidy Review: Knowledge Base Retrieval and Recall

## What data for this category looks like
Data for this category originates from the National Student Financial Aid Management Information System, school student status systems, civil affairs low-income and extremely poor household data, and fiscal payment systems. The update frequency is once per semester.
Daily processed documents include the Family Economic Difficulty Certification Form, Financial Aid Application Form, Scholarship and Grant Review Form, Distribution List, and Publicity Materials.
Data fields cover student identity identifiers, family economic status, student status, financial aid eligibility, bank card binding information, and more. All documents are structured or semi-structured standardized text, with fields and units strictly following the unified specifications of educational financial aid systems.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Multi-source heterogeneous data sources require retrieval to cover field associations across different systems, and cross-system data confusion must be avoided.
Semester-level update frequency requires the knowledge base to perform full synchronization on a regular basis to ensure data timeliness.
Standardized document structures require chunk matching of fixed document fields, and chunking that destroys the integrity of key information must be avoided.
The high accuracy requirement of the review link determines that retrieval must strictly limit the scope, reduce the workload of manual secondary verification, and control retrieval time to meet the time requirements of on-site review.

## How to set configurations
The following configurations are formulated based on the parameter specifications of FastGPT v4.17.0, and are adapted to the business scenario of student financial aid and subsidy review.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the accuracy requirement for matching student financial aid-related content, and prevents low-relevance non-financial aid data from being included in results |
| `limit` | Top 8 entries | Covers multiple associated materials required for review and publicity, while controlling context length to avoid exceeding model processing limits |
| `searchMode` | hybrid | Combines semantic and keyword retrieval, adapts to structured financial aid data fields, and balances semantic association and precise field matching |
| `usingReRank` | Enabled | Performs secondary sorting on recall results, corrects deviations from single semantic matching, and differentiates between students with the same name but different student status and economic situations |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplements synonyms related to financial aid scenarios, expands effective recall scope, and covers eligibility verification needs expressed in different ways |
| `collectionIds` | Bind the exclusive knowledge base ID for student financial aid | Limits the retrieval scope, prevents mixing of other educational non-financial aid data, and ensures results only come from the specified data source |

## Three common mistakes
- Phenomenon: The generated response does not use the financial aid data in the knowledge base, and the referenced knowledge base entries have no connection to the main text. Cause: The exclusive `collectionIds` is not bound, or the `similarity` threshold is set incorrectly, leading to irrelevant data being recalled, and the retrieval scope is not strictly limited.
- Phenomenon: Retrieval response time exceeds 20 seconds, which cannot meet the rapid verification needs of on-site review. Cause: The `collectionIds` is not limited to the exclusive knowledge base, the retrieval scope covers too many irrelevant documents, or the `limit` value is set too high, causing context overload.
- Phenomenon: The exported knowledge base dataset.csv only contains the `index` field and no `content` field. Cause: The knowledge base was created without configuring chunk extraction of original document content, or the export operation did not check the box to synchronously export original text fields.

## How to confirm the configuration is correct
- Initiate a test retrieval, input "2024 academic year family economic difficulty student eligibility verification", and check whether the returned results include student status and low-income data entries from the corresponding systems.
- View the reference list of retrieval results, confirm that each reference comes from the knowledge base corresponding to the bound `collectionIds`, and directly matches the main text content.
- Test exporting the dataset.csv, confirm that the file contains both the `index` and `content` fields, and that the `content` field contains the complete text of the original document.
- Initiate multiple retrievals in a simulated batch review scenario, and check whether the response time meets business expectations.
