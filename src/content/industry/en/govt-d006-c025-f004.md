# Document and Material Drafting for Safety Production Hazard Inspection and Governance: Workflow Orchestration

This configuration is built based on the workflow functions of FastGPT v4.17.0.

## What this category of data looks like
This category of data mainly comes from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily generated documents include hazard inspection lists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Document structures typically include fields such as hazard identification, inspection subject, rectification responsible party, time limit requirements, and review results. Fields for different documents must match the format specifications of corresponding regulatory requirements to meet reporting and archiving standards.

## What constraints do these characteristics impose on the "workflow orchestration" link
Dispersed data sources requiring cross-system access mean workflow configuration needs cross-node data retrieval links to adapt to interface formats of different systems.
Daily updated hazard data scale requires workflow configuration of batch processing nodes to avoid single-node overload affecting execution efficiency.
Inspection links aligned with major accident hazard judgment standards require workflow configuration of standard verification nodes to ensure inspection results meet regulatory requirements.
Field differences across different documents require workflow configuration of variable mapping links to automatically align raw data extracted from cross-systems to required fields of corresponding documents.
Full hazard rectification process requires workflow configuration of status transition nodes to track the full process status of hazards from inspection, rectification to review, ensuring full-process tracking required by regulations is implemented.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Variable Mapping Rules | Preset field alignment templates by document type | Match required field requirements for different documents such as hazard inspection lists and rectification notices |
| Batch Processing Threshold | 5000 records per day | Adapt to the daily updated hazard data scale and avoid single-node overload |
| Node Timeout Setting | 600 seconds | Ensure response stability when retrieving regulatory data across systems |
| Status Transition Trigger Condition | Trigger the review link based on rectification completion markers | Align with full-process requirements of hazard inspection and governance |
| `variables` configuration | Bind core fields such as hazard level and rectification deadline | Ensure generated documents include required information specified by regulatory requirements |

## Three common mistakes
- Empty fields in rectification notices generated after workflow execution. Cause: Failed to bind the hazard responsible subject field extracted from the corresponding system via `variables` configuration, leading to missing core information.
- Timeout errors triggered when cyclically processing hazard data. Cause: Batch processing threshold set too high, exceeding the node's carrying limit, and node timeout parameters not adjusted.
- Failed to generate flowcharts via Mermaid node, unable to obtain image links. Cause: Failed to configure the Mermaid node's output format as an accessible image link, and failed to verify interface call permissions.

## How to confirm the configuration is correct
- Manually trigger workflow execution for a single hazard record, check if the generated document includes all preset required fields.
- Simulate daily batch data import, observe the running status of workflow nodes to confirm no timeout errors.
- Test status transition after hazard rectification is completed, check if the review link's workflow node is automatically triggered.
- Call the Mermaid node to generate a flowchart, confirm the returned link is accessible and matches the hazard governance process.

The values listed above are common starting points and should be evaluated against your own specific samples.
