# Document and Material Drafting for Safety Production Hazard Inspection and Governance: Tool Calling and Plugins

## What data for this category consists of
Data for this category originates from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Commonly generated documents include hazard inspection lists, hazard governance ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Data fields include hazard unique identifier, inspection subject, hazard type, rectification responsibility subject, rectification deadline, and review result. No additional custom statistical units are used.

## Constraints imposed by these characteristics on tool calling and plugins
Multi-source data access requires tools to support interfacing with different systems to pull real-time updated hazard inspection and rectification data. This ensures generated documents contain the latest business information. Official documents of different types have fixed formats, so plugins must adapt to multiple document structures such as lists, ledgers, and notices, and match preset field rules. The daily updated data volume requires tool calling response speeds to be compatible, to avoid delaying document generation due to data pull latency. Fixed business fields require that plugins pass compliant parameters strictly when called, to ensure generated documents meet regulatory specifications.

## Configuration Settings
This guidance is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match the tools required for current document generation, adapting to multi-type document scenarios |
| `functionCall` | `Bind dedicated hazard governance function set` | Ensure called tools can access exclusive business data for hazard inspection and rectification |
| Single tool call data volume | Top 3 latest records | Control context length to avoid exceeding model processing limits |
| Tool call timeout | 600 seconds | Adapt to average time required for pulling data from multiple systems |
| Plugin data source matching rule | Associate corresponding business system by document type | Accurately obtain exclusive data for this category |

## Three Common Misconfigurations
- The symptom is that tool calling prompts that external services cannot be connected, and supervision system data cannot be pulled. The cause is that a domestically accessible proxy or local data source interface is not configured, and a tool node deployed overseas is relied on.
- The symptom is that a 401 status code is returned when calling the plugin, while the same key works in Postman. The cause is that the key configured in FastGPT is not correctly bound to the permission scope of the corresponding plugin, or there is an input error in the key format.
- The symptom is that the preset hazard data plugin is not called when generating documents, and vague content is generated directly. The cause is that the tool calling switch is not enabled, or `toolChoice` is configured to a fixed non-automatic mode.

## How to Verify Correct Configuration
- Manually trigger tool calling, check if the returned business data includes hazard fields for this category, such as rectification deadline and responsibility subject.
- View plugin calling logs, confirm that the `functionCall` parameter has correctly passed the business identifier with no format errors.
- Simulate generating different types of documents, check if the plugin for the corresponding data source is automatically matched.
- Test timeout scenarios, confirm that tool calling returns valid data within the preset time.

The values provided are common starting points and should be measured against the reader's own samples.
