# Document and Material Drafting for Engineering Construction Project Approval: Citation Sources and Traceability

## What the data for this category looks like
Core data for this category is sourced from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. The update frequency is daily.

Commonly processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion acceptance record forms. Document structures contain fixed fields such as approval node numbers, participating unit qualification information, personnel practice qualifications, and material generation time.

The core information of each material must be strictly aligned with real-time data from the corresponding approval system.

## What constraints these characteristics impose on the citation sources and traceability link
Combining multiple system data sources requires associating multiple knowledge bases simultaneously. This prevents incomplete information caused by relying on a single data source for citations.

The daily update frequency requires configuring scheduled synchronization rules. This ensures cited content reflects the latest approval status.

The fixed field structure requires precise matching of fields such as approval numbers and participating units in materials. This stops cited content from being disconnected from the actual approval process.

Multiple stage material data must be integrated, so the traceability link must cover data sources from multiple approval nodes including project initiation and construction permits.

In addition, errors directly relate to construction delays or record filing failures. This requires the traceability link to clearly display the generation system and update time of cited materials, to help approval staff verify information.

Also, avoid code operations in custom prompt words that may trigger system errors. This prevents exceptions such as property redefinition.

## Three common errors
- Phenomenon: No selectable values appear in the variable reference dropdown menu. Approval material numbers, participating unit qualifications, and other fields cannot be selected. Cause: No variable mapping rule for the corresponding fields has been configured in the associated knowledge base, or the variable export switch has not been enabled.
- Phenomenon: The system throws the error `Cannot redefine property: toString`. Cause: The custom citation template prompt word incorrectly modifies the prototype properties of built-in JavaScript objects directly.
- Phenomenon: Cited materials in generated documents do not show the latest approval status. Cause: No daily knowledge base synchronization rule has been configured, so cited data uses an outdated version not updated on the current day.
