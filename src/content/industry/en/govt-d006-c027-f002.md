# Document and Material Drafting for Engineering Construction Project Bidding: Vector Models and Indexing

## What This Category of Data Looks Like
Service subjects for this category include development and reform departments, industry competent departments such as housing and urban-rural development, transportation, water resources, public resource trading centers, and bidding agencies. Core documents include bidding announcements, pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements.

Data sources are national public resource trading platforms, local public resource trading platforms, project approval systems, and bidding supervision systems. Data is updated daily, covering engineering construction projects at different levels. Document structures include core fields such as section division, qualification requirements, bill of quantities, and bid evaluation rules. There is no unified fixed unit format. Some documents contain tabular parameter content.

## What Constraints These Characteristics Impose on the Vector Models and Indexing Link
Daily updated data requires indexes to support incremental updates, avoiding excessive resource consumption from full index reconstruction. Mixed indexing of multiple document types needs to adapt to different document field structures, ensuring core information such as sections and qualifications is accurately chunked.

Documents contain long text passages like bills of quantities. Chunking rules must balance context integrity and indexing efficiency. Decentralized data sources lead to differences in document formats, requiring compatibility with non-standard text structures. Index stability must also be ensured, avoiding indexing failures caused by abnormal documents. Such failures could lead to risks such as suspended bid results or delayed project commencement.

## How to Set the Configuration
This configuration scheme is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Covers core fields such as sections and qualifications, avoiding information loss from long text truncation |
| Overlap Length | 100–150 characters | Retains cross-chunk qualification condition associations, ensuring complete matching of qualification requirements during retrieval |
| `defaultToken` | 8192 | Adapts to the single-chunk text length of most bidding documents, balancing chunking efficiency and context integrity |
| `maxToken` | 16384 | Handles ultra-long documents containing bills of quantities, avoiding chunk overflow |
| Similarity Threshold | 0.75–0.85 | Differentiates text differences between bidding requirements and tender responses, improving retrieval accuracy during bid evaluation |
| Single Search Limit | Top 10 entries | Covers associated content of multiple tender documents, meeting the needs of bid evaluation verification |

## Three Common Mistakes
- Phenomenon: After an upgrade, the indexing service returns a 400 status code with no response body. Cause: The long text chunking rules for bidding documents were not adapted, causing the token parameter of the indexing request to exceed the model's upper limit.
- Phenomenon: After local deployment, server memory continues to be exhausted, triggered daily on a scheduled basis. Cause: The number of files and chunk size for batch indexing were not limited, and batch processing of daily updated multiple bidding documents exceeds the server memory threshold.
- Phenomenon: Knowledge base file upload is stuck at 1 or 2 indexing progress groups. Cause: When using the m3e-large model, the chunk length was not adjusted, causing the token count of chunks to exceed the model's supported upper limit, triggering indexing blocking.

## How to Confirm the Configuration Is Complete
- Check the execution time of indexing tasks, match the daily update frequency of the data, confirm that incremental indexing can be completed on schedule.
- Test retrieval of specific qualification or bill of quantities keywords, confirm that the recall results include core fragments of the corresponding documents.
- Verify the chunking parameters, check that the chunking results of long documents have no truncation or excessive splitting.
- View indexing request logs, confirm that there are no 400-level errors or blocking states.

The values provided are common starting points and should be measured against the reader's own samples.
