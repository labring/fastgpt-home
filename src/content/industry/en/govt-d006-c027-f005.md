# Document and Material Drafting for Engineering Construction Project Bidding and Tendering: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from the national public resource trading platform, local public resource trading platforms, engineering approval systems, and bidding and tendering supervision systems, with a daily update frequency. Daily processed documents include bidding announcements, qualification pre-qualification documents, bidding documents, tender documents, bid evaluation reports, public notices of successful bidders, and winning bid result announcements. These documents contain unique fields such as section division, qualification requirements, qualification and performance requirements, bill of quantities, and construction period. Service subjects include development and reform departments, industry competent departments such as housing and urban-rural development, transportation, and water conservancy, public resource trading centers, and bidding agency institutions.

## What constraints these characteristics impose on the tool calling and plugins link
Multiple data sources require tool calling to support cross-platform data pulling and integration, to avoid data fragmentation. The daily update frequency requires configuring scheduled synchronization rules to ensure the timeliness of data in the knowledge base. Bidding and tendering documents have many structured fields, so tool calling must have the ability to accurately extract specific fields such as sections and qualification requirements. Otherwise, it will affect the accuracy of document drafting. At the same time, the consequences of errors in this category are severe, so the result verification link of tool calling must be strengthened to ensure extracted fields comply with relevant bidding and tendering business specifications.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the dual needs of general text generation and structured field extraction in bidding and tendering documents, automatically selecting whether to call tools or generate content directly |
| `functionCall` | `enabled` | Structured extraction of unique fields such as sections, qualification requirements, and bill of quantities is required. Enabling function call ensures the output format complies with business requirements |
| Single tool call timeout | `600 seconds` | Bidding and tendering documents usually contain multiple sections and multi-page content, which requires longer processing time. Reserve sufficient time to complete data extraction and verification |
| Tool call return result limit | `Top 3–5 entries` | The core fields of bidding and tendering documents are concentrated. Excessive results will increase the context burden and reduce generation efficiency and accuracy |
| Knowledge base binding scope | Bind by data source category | Data comes from multiple public resource trading platforms. Binding by category avoids cross-source data confusion and improves field extraction accuracy |

## Three common mistakes
- Phenomenon: Fields such as qualification and performance are returned empty when calling tools to process bidding and tendering documents. Cause: The knowledge base corresponding to the target data source is not bound, so unique bidding and tendering business data cannot be accessed, and structured field extraction cannot be completed.
- Phenomenon: A parameter error prompt is displayed after uploading a file via a workflow invoked by API. Cause: The knowledge base ID is not passed as a global variable as required, or the code format does not comply with system specifications, so the workflow cannot trigger the corresponding tool calling link.
- Phenomenon: The relationship between bidders and winning projects cannot be correctly associated when using the graphRAG tool. Cause: Entity relationship extraction rules are not configured for the unique fields of bidding and tendering documents, so general relationship extraction cannot adapt to the exclusive logic of bidding and tendering business.

## How to confirm the configuration is properly set
- Upload a standard bidding document, and check whether the tool call automatically extracts fields such as sections and qualification requirements and generates corresponding content.
- View the knowledge base binding list, and confirm that data from sources including the national public resource trading platform and local public resource trading platforms has been bound by data source category.
- Call the test API, pass a test bidding document, and check whether the returned result contains structured field information.
- View the workflow log, and confirm that the tool calling link is automatically triggered after the file is uploaded.

The values provided are common starting points and should be measured against the reader's own samples.
