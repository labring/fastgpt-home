# Document and Material Drafting for Market Entity Registration and Licensing: Tool Calling and Plugins

## What the data for this category looks like
The core data for this category comes from four official data sources: the enterprise registration fully electronic system, the national enterprise credit information public disclosure system, the electronic business license system, and the residence information database. The update frequency is once per day. Daily processed documents include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and more. All document types have fixed field structures. For example, an establishment registration application must include required fields such as applicant information, residence address, and business scope. A food business license application must link to compliance data for the business premises. The overall data structure is tightly bound to the market entity access process.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Since the data sources include four separate official systems, tool calling must adapt to different interface formats and permission rules. Exclusive plugin access configuration must be created for each data source. The daily data update requirement means the tool calling cache and synchronization mechanism must match the update rhythm, to prevent use of expired residence information or enterprise credit data. Documents with fixed field structures require tool calling to accurately match required fields, instead of broadly extracting content. Otherwise, generated documents will fail to meet registration requirements. The verification step in the business process requires passing parameters such as name, residence, and shareholder materials. Tool calling must support standardized transmission of these fields.

## How to set configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically select tools adapted to the market entity registration process, no manual plugin specification needed |
| `functionCall` | Enable mandatory parameter validation | Ensure fields passed during tool calls meet the fixed format requirements of registration documents |
| Single tool call timeout | `600 seconds` | Match the typical duration of market entity registration verification, to avoid premature call termination |
| Tool call result cache duration | `86400 seconds` | Match the once-per-day update frequency of data sources, to avoid using expired data |
| Tool call retry count | `2 times` | Mitigate call failures caused by single network fluctuations or temporary system response delays |
| Maximum character count of single tool call return result | `8000 characters` | Match the length requirements of typical registration documents, to avoid content truncation |

## Three common mistakes
- Phenomenon: The residence information field returned after a tool call is empty, with a 200 status code but no data. Cause: Residence information database data source synchronization is not configured, so the tool cannot obtain valid and compliant residence data.
- Phenomenon: Attempting to retrieve a business license image via an HTTP tool, but the image cannot be displayed in the response. Cause: No image format output parameters are configured, and the image display requirements for business license documents in this category are not addressed, corresponding to the image access related questions shared in the community.
- Phenomenon: Calling `functionCall` triggers a parameter format error, and compliant establishment registration applications cannot be generated. Cause: Parameters are not passed per the fixed field structure, such as omitting the required "business scope" field, which violates the format requirements of category documents.

## How to confirm correct configuration
- Initiate a simulated establishment registration application tool call, and check if the returned result includes preset fields including applicant information, residence address, and business scope.
- View the tool call log to confirm the `toolChoice` parameter is active, and the plugin related to market entity registration is automatically selected.
- Verify the daily data synchronization task, and confirm the latest data has been pulled from the four official data sources and updated to the plugin data source.
- Call `functionCall` with parameters that do not follow the fixed format, and confirm a parameter verification error prompt is triggered.
