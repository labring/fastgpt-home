# Document and Material Drafting for Market Entity Registration and Licensing: Source Citation and Traceability

This document applies to FastGPT v4.17.0.

## What the data for this category looks like
Core data involved in this category comes from the enterprise registration full-process electronic system, the national enterprise credit information public disclosure system, the electronic business license system, and the residence information database. The update frequency is daily. Commonly processed documents include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and similar materials. Single documents have a relatively fixed structure, including standardized fields such as entity name, residence address, shareholder information, and license scope. There is no additional unstructured redundant content, and all data fields correspond to legal handling requirements for market entity registration and licensing.

## What constraints do these characteristics impose on the source citation and traceability link
These data characteristics impose multiple constraints on the source citation and traceability link. First, data sources are scattered and updated daily, so the retrieval link must accurately match real-time data sources to avoid calling outdated information. Second, document fields are standardized but cover all process nodes of legal handling. Recalled content must strictly correspond to the type of document currently being drafted. For example, residence certificates must match verification results from the residence information database. In addition, errors in the registration and licensing link directly affect an entity’s business qualification. Traceability information must clearly mark the source system and update time to facilitate subsequent verification.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Matches the average length of single core documents in this category, to avoid context overflow |
| `responseData` | `Original snippet + source system identifier` | Retains original content while clearly marking data sources to meet traceability requirements |
| `detail` | Enabled | Retains standardized field details in documents to ensure drafted content complies with legal formats |
| Single search limit | Top 6 results | Covers core recall results from multiple data sources, avoids interference from redundant information |
| Maximum context | `15000 characters` | Controls total length of multiple recalled documents, adapts to input limits of large language models |

## Three common mistakes
- Phenomenon: Global variables configured in the workflow cannot be properly referenced in the retrieval node, and returned results do not include corresponding data source content. Cause: The scope of the global variable is not bound in the data source configuration of the retrieval node, or the variable has not been declared in the workflow global configuration.
- Phenomenon: AI-generated document materials include non-original embellishment content that does not match original fragments in the knowledge base. Cause: The original output configuration of `responseData` is not enabled correctly, or an unconfigured content polishing link is active.
- Phenomenon: Single retrieval takes too long or the number of returned results is abnormal. Cause: The value of `quoteMaxToken` is not set reasonably, or the number of returned results per single search is not restricted, leading to retrieval resource overload.

## How to confirm the configuration is correct
- Trigger a complete document drafting process, and check whether returned results include clear source system identifiers, such as "Data from the National Enterprise Credit Information Public Disclosure System".
- Enter the configuration interface of the retrieval node, verify that the value of `quoteMaxToken` matches the preset configuration, and confirm there are no context overflow prompts.
- Configure multiple associated data sources, test whether the retrieval link can recall content from different systems simultaneously, and verify the effectiveness of multi-knowledge base calls.
- View the workflow operation log, and confirm there are no error messages such as unloaded variables, context overflow, or retrieval timeout.

The values provided are common starting points and should be measured against the reader's own samples.
