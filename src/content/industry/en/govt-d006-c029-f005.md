# Document and Material Drafting for Urban Sanitation and Urban Management Law Enforcement Cases: Tool Calling and Plugins

## What data for this category looks like
This category of data typically comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders, and is updated daily. Daily documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and case closure reports. Core fields include case number, violation location, responsible entity, rectification requirements, and execution status. Some documents are associated with multimedia evidence materials. The data structure adjusts dynamically based on the case workflow stage.

## Constraints imposed by these characteristics on the tool calling and plugins workflow
Data sources for this category are scattered, covering multiple types of systems and multimedia materials. Tool calling must support cross-platform data pulling and multimedia parsing. There are diverse document types with strict field requirements. Parsing tools adapted to different document formats must be called to ensure returned fields align with law enforcement document templates. The daily data update feature requires the tool calling chain to adapt to high-frequency synchronization needs, avoiding missing the latest case information. The accuracy of core case information directly affects law enforcement procedures. Tool returned content must undergo verification to prevent law enforcement disputes caused by missing key evidence.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto mode | Adapts to dynamically changing tool calling needs for urban management cases, no manual tool specification required, matches FastGPT v4.17.0 tool scheduling logic |
| Single tool call limit | First 6 entries | Matches the number of data sources associated with a single case, avoids call overload |
| Tool call timeout | 120 seconds | Covers the typical time required for cross-platform data pulling and multimedia parsing |
| `functionCall` | Enforce JSON format | Ensures generated law enforcement document fields strictly align with templates |
| Tool call retry count | 3 times | Covers temporary network fluctuations during single calls |

## Three common configuration mistakes
- Tool call timers trigger continuously but no valid case data is retrieved. Cause: No trigger conditions or filtering rules for already processed daily cases are configured, leading to repeated calls to invalid data.
- Law enforcement documents generated via `functionCall` are missing required fields. Cause: Tool returned fields are not aligned with required items in the law enforcement document template, resulting in non-compliant generated content.
- Failure logs cannot be viewed after calling the large model interface. Cause: No log storage path is configured, so detailed failed call information is not recorded.

## How to verify correct configuration
- Trigger a single tool call, check if returned data includes the latest same-day case information.
- Call `functionCall` to generate a test document, confirm fields align with the law enforcement template.
- Simulate a tool call failure, check if corresponding log records are generated.
- Adjust the tool call limit parameter, verify that the number of returned results matches expectations.

The values provided are common starting points and should be evaluated against local deployment samples.
