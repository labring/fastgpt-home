# Document and Material Drafting for Urban Sanitation and Urban Management Law Enforcement Cases: Source Citation and Traceability

## What data for this category looks like
Data for this category typically comes from urban management law enforcement platforms, urban operation grid platforms, on-site video surveillance, and public complaint work orders. Update frequency is daily. Daily documents include inspection records, case filing approval forms, on-site photos, rectification notices, penalty decisions, and case closure reports. Document fields usually include case numbers, inspection times, responsible party information, on-site evidence content, and rectification tracking records. Some documents include multimedia evidence files.

## What constraints these characteristics impose on source citation and traceability
Dispersed data sources that include both structured documents and multimedia content require the citation and traceability link to support cross-platform data association and non-text material matching. The daily update feature requires the retrieval pipeline to adapt to high-frequency data refreshes, preventing the use of expired cited content. The multi-field attributes linked to cases require strict binding of original data to the currently drafted document, ensuring cited content matches the case scenario. The rigor of law enforcement cases requires traceability information to be directly linked to law enforcement case files, supporting subsequent dispute verification.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Urban management law enforcement documents usually require cited content to cover core case information. This range balances context length and citation accuracy, and adapts to the context processing logic of FastGPT v4.17.0 |
| `responseData` | Return original source identifier and file path | Law enforcement document traceability requires clear identification of which inspection record or work order cited content comes from, facilitating subsequent law enforcement case file verification |
| `detail` | Enable full-field traceability | Fields such as responsible party and rectification status for urban management cases require complete association, preventing key law enforcement information from being missing |
| Single search limit | Top 10 matching results | The volume of urban management case data is relatively concentrated. Too many results will interfere with the accuracy of document drafting |
| Maximum context length | Calibrated based on actual testing | The scale of law enforcement case file data varies across regions. Adjust based on actual data scale |

## Three common configuration mistakes
- Phenomenon: The number of context items displayed on the interface does not match the number actually passed to the model. For example, 30 items are displayed but 310 are actually passed. Cause: `quoteMaxToken` and retrieval result truncation logic are not configured correctly, leading to a mismatch between front-end display and back-end call parameters.
- Phenomenon: `quoteMaxToken` is set to 1500, but content longer than this length is still cited from the knowledge base. Cause: Length check logic for individual cited blocks is not linked. Only the total context token count is restricted, causing overly long content to be included in retrieval results.
- Phenomenon: Knowledge base retrieval results passed via HTTP requests cannot be correctly identified by the AI as cited sources. Cause: Retrieval results are not converted to the standard format including source identifiers, content fragments, and associated fields as required. Only plain text content is passed.

## How to confirm configuration is properly set up
- Submit a simulated document drafting request for urban management law enforcement cases. Check the cited source identifiers in the returned results to confirm they include correct inspection records or work order numbers.
- Adjust the `quoteMaxToken` parameter value, compare the model context token counts recorded in back-end logs before and after, to confirm the parameter takes effect.
- Upload a test urban management law enforcement case file, verify that retrieval results can be linked to corresponding on-site photos or rectification tracking records.
- Check that the number of cited items displayed on the front end matches the number of retrieval results recorded in back-end logs.
