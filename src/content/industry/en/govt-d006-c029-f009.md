# Document and Material Drafting for Urban Sanitation and Urban Management Law Enforcement Cases: Model Access and Configuration

## What This Category of Data Looks Like
Daily data for urban sanitation and urban management law enforcement cases includes patrol records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and closing reports. Data is updated daily. Sources include urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders. A single case data package usually includes case number, patrol time, on-site location, violation description, and involved party information. Some data includes on-site images with location tags. Overall formats vary across sources, leading to certain heterogeneity.

## What Constraints These Characteristics Impose on the "Model Access and Configuration" Link
Multi-source, heterogeneous data sources require model access to support unified parsing of multiple formats: structured tables, text records, and image content. Daily updated case data needs a regular synchronization mechanism. This prevents data lag from delaying document drafting. Mixed input of on-site photos and patrol records requires the model to have visual understanding capabilities. It also needs sufficient context length to cover complete case information. The rigor of law enforcement documents requires model output to match the standard format of urban management law enforcement. It must avoid content that does not comply with business specifications, and ensure data call security to prevent leaks of sensitive law enforcement information.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `vision` | Enabled | This category of cases contains a large amount of unstructured on-site photo data. Visual capabilities are needed to extract key information from images |
| `maxContext` | 8000–12000 token | A complete single case data package includes patrol records, filing approval forms, OCR text from on-site photos, and other content. Sufficient context supports the model in understanding the full case |
| `maxTokens` | 2000–3000 token | The output length of a single law enforcement document such as a penalty decision usually falls within this range. This ensures complete generation of document content |
| `temperature` | 0.3–0.5 | Law enforcement documents need to maintain rigor and standardization. A lower temperature parameter reduces the randomness of generated content, aligning with business requirements |
| `toolChoice` | auto | The model needs to independently determine whether to call historical case data or associated work order information. Automatic mode adapts to diverse case processing scenarios |
| `AIPROXY_API_ENDPOINT` | Fill in the compliant proxy address | Adapt to the data security requirements of the urban management system. Use a proxy to forward large model calls to avoid direct exposure of internal interfaces |
| `AIPROXY_API_TOKEN` | Fill in the exclusive authentication token | Ensure the security of interface calls and prevent unauthorized access to law enforcement-related data |

## Three Common Errors
- When batch uploading grid work order data, only the first dozen entries are processed normally. No valid output is generated for subsequent entries. Cause: No reasonable context truncation rule is configured for the multi-source heterogeneous data of urban management cases. This leads to context overflow, and the model cannot fully process subsequent batch data.
- After connecting Casdoor, identity verification cannot be completed. A 401 error is reported when calling the model interface. Cause: The callback address was not filled in according to the OAuth2 configuration requirements of Casdoor. This causes the authentication process to fail to complete normally.
- When using Qwen2-72B-Instruct-Int8 for function calls to generate law enforcement documents, the identified violation type does not match the actual case. Cause: No exclusive prompt constraint is configured for the violation type library of urban management law enforcement. The model did not accurately match the judgment standards of the business scenario.

## How to Confirm Configuration Is Complete
- Upload a single case data package that includes on-site photos and patrol records. Trigger a document drafting test, and check whether the generated content covers core case information.
- Configure a tool call test task. Confirm that the model can independently call associated historical law enforcement data to complete context supplementation.
- Run a batch data processing task. Monitor the running logs of FastGPT v4.17.0, and confirm that there are no context overflow or timeout errors.
- Verify the login process of the connected Casdoor. Confirm that identity verification can be completed normally and the model interface can be called successfully.
- Trigger a function call test. Confirm that the violation type judgment generated by the model complies with the business specifications of urban management law enforcement.
