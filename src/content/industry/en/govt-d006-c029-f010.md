# Document and Material Drafting for Urban Environmental Sanitation and Urban Management Law Enforcement Cases: Knowledge Base Retrieval and Recall

## What this category of data looks like
Daily documents for this category mainly include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and closing reports. Data sources cover urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders. Updates occur daily. Common data fields include case number, responsible entity, violation type, rectification requirements, and penalty results. Some documents include multimedia attachments. The structure changes dynamically with the case handling process.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Retrieval systems must support high-frequency incremental synchronization for daily updated multi-source data. This stops the system from recalling outdated or unassociated case information.
Adapt embedding and retrieval logic for different formats to handle multiple document types including text and multimedia attachments. This ensures on-site photos, work order text, and other content can be effectively recalled.
Adjust retrieval scopes with the case stage to match dynamically changing case process structures. This avoids recalling historical documents that do not match the current link.
Apply unified field mapping to dispersed data generated by multiple entities. This ensures semantic consistency during retrieval, and prevents matching deviations caused by field differences.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Meets semantic similarity requirements for urban management law enforcement case documents, filters low-correlation non-law enforcement content |
| `limit` | `Top 6–8 entries` | Controls the number of documents recalled per retrieval, avoids context overload, and covers reference documents needed for the full case process |
| `searchMode` | `Keyword + semantic hybrid` | Balances explicit keywords such as case numbers and violation types in law enforcement documents, and vague semantic descriptions of rectification requirements |
| `usingReRank` | `Enabled` | Performs secondary ranking on initial recall results, corrects deviations from single semantic matching, and prioritizes documents matching the current case scenario |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands retrieval terms based on case information entered by users, supplements implicit information such as on-site details described by grid inspectors |
| `collectionIds` | `Bind exclusive collections by law enforcement case category` | Isolates knowledge bases for different streets or law enforcement domains, avoids recalling irrelevant documents from cross-regional cases |

## Three Common Mistakes
- The interface displays retrieval hits but returns no results. The cause is that `usingReRank` is not enabled, and initial recall results are restricted too strictly by the `similarity` threshold, causing valid results to be excluded.
- Retrieval results do not include on-site photos or public complaint work order content. The cause is that embedding and retrieval logic for multimodal documents is not configured, and only text-based documents are recalled.
- Incorrect classification leads to recalling irrelevant law enforcement case documents. The cause is that `datasetSearchUsingExtensionQuery` is not enabled, so retrieval terms cannot be supplemented based on context, and matching relies solely on a single query.

## How to Confirm the Configuration is Correct
- Import 10 typical urban management law enforcement case documents, run retrieval tests, and check if recall results include documents matching the current case type.
- Adjust the `similarity` threshold to verify if recall result relevance meets business requirements. No fixed value is required.
- After enabling `usingReRank`, compare recall results before and after, and confirm highly relevant documents are prioritized after secondary ranking.
- After binding exclusive `collectionIds`, run cross-knowledge base retrieval tests, and confirm only documents within the bound collection are recalled.

The values provided here are common starting points and should be measured against the reader's own samples.
