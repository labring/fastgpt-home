# Document and Material Drafting for Construction Engineering Quality and Safety Supervision: Tool Calling and Plugins

## What this category's data looks like
Data for this category comes from construction quality and safety supervision systems, construction site real-name platforms, supervision logs, and test reports. The update frequency is weekly. Daily generated documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Documents contain fields such as project number, on-site participating units, hidden danger items, rectification time limits, and acceptance inspection items. There are no unified fixed units; values match the specific parameters of corresponding projects.

## What constraints do these characteristics impose on the "tool calling and plugins" link
Data sources are scattered and mostly vertical business systems. Tool calling must connect to multiple interfaces to pull data, to avoid generated content deviating from on-site reality. The weekly update rhythm means the tool calling trigger interval should not be too short. Otherwise, a large amount of redundant data will be generated. There are many document fields associated with on-site specific parameters. Tool calling must accurately match the corresponding fields, and cannot generalize generated content. Documents related to rectification closure need to track status changes. Tool calling must link to status update logic, otherwise information lag is likely to occur. The completion acceptance report involves multi-link inspection. Tool calling must integrate multi-source data, otherwise the generated content does not meet acceptance requirements.

## How to Configure

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts to tool calling scenarios, covers multiple types of document generation needs such as supervision plans and rectification notices |
| `functionCall` | `enabled` | Forcibly enables function calling to ensure that generated document fields accurately match the standard fields of the engineering quality and safety supervision system |
| Single generation character limit | `800–1200 characters` | Adapts to the conventional length of a single quality and safety document, avoids content redundancy or missing key information |
| Trigger interval | `7 days` | Matches the weekly update rhythm of data in this category, reduces repeated pulling of redundant on-site data |
| Maximum number of recalled data entries | `Top 3` | Avoids pulling too much historical data, improves the execution efficiency of tool calling |
| Data source binding rules | `Associated engineering quality and safety supervision system, supervision log interfaces` | Fits the core data sources of this category, ensures that generated document content is consistent with on-site actual conditions |

This configuration is adapted for FastGPT v4.17.0.

## Three Common Mistakes
- Calling the engineering quality and safety supervision system interface returns a 422 error code. The cause is that the field mapping rules of `functionCall` are not correctly configured, causing the request body format to not meet the interface requirements.
- The generated hidden danger rectification notice does not associate the specific number of the on-site test report. The cause is that the data source interface of the construction site real-name platform is not bound, so the corresponding unique identifier field cannot be obtained.
- Multimodal tool calling returns a 400 invalid image error. The cause is that the format and size limits for image upload are not configured, and the passed on-site photos exceed the `≤5 MB` requirement, causing interface verification failure.

## How to Confirm the Configuration is Valid
- Initiate a test call, check whether the returned request body format meets the supervision system interface requirements, and confirm that the `toolChoice` and `functionCall` parameters take effect.
- Check whether the generated document fields include core fields of this category such as project number, participating units, and hidden danger items, and confirm that the data source binding rules take effect.
- View the tool calling trigger log, confirm that the trigger interval conforms to the 7-day setting, and there is no frequent repeated calling.
- Upload an on-site photo that meets the format requirements to initiate a multimodal test, confirm that no 400 error is returned, and verify that the image verification rules take effect.
