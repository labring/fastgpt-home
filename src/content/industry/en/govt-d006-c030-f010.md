# Document and Material Drafting for Construction Engineering Quality and Safety Supervision: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
This category of data primarily comes from the engineering quality and safety supervision system, construction site real-name management platform, supervision logs, and test reports. The update frequency is weekly.
Daily generated documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports.
Most document structures include fields such as project number, participating unit information, inspection time, problem description, and rectification requirements. Common units used include project numbers, square meters, days, and other standard engineering industry units.

## Constraints Imposed on Knowledge Base Retrieval and Recall by These Characteristics
Dispersed data sources require association with multiple datasets, so cross-dataset retrieval capability must be configured.
The weekly update rhythm requires the knowledge base synchronization cycle to match the business update pace, to avoid retrieving expired data.
Most documents contain precise fields such as project number and participating units, so retrieval must support field-level matching.
The rigor of supervision documents requires recall results to have high confidence, to avoid incorrectly associating materials from non-corresponding projects.
Daily document drafting requires fast access to past similar templates, so retrieval speed must meet real-time requirements. Excessive latency will affect work efficiency and even delay the hidden danger rectification closed-loop process.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | This category of supervision documents requires high matching accuracy to avoid interference from irrelevant materials. This range balances recall coverage and precision |
| `limit` | Top 10 entries | Too many single-round retrieval results increase context pressure. 10 entries can cover core supervision-related materials |
| `searchMode` | Exact match | Supervision documents mostly contain unique project numbers. Exact match avoids recalling materials from non-corresponding projects |
| `usingReRank` | Enabled | Multi-dataset retrieval results need re-ranking to prioritize results more relevant to the current supervision task |
| `datasetSearchUsingExtensionQuery` | Enabled | Can automatically expand retrieval keywords based on project information entered by users, covering data from multiple sources such as supervision logs and test reports |
| `collectionIds` | Configure according to the corresponding supervision dataset IDs | Only recall supervision-related datasets uploaded by the construction quality and safety supervision station and participating units, to avoid mixing in irrelevant business data |

These configurations are based on the functional logic of FastGPT v4.17.0.

## Three Common Misconfigurations
- Symptom: Knowledge base retrieval is slow, with response time exceeding 10 seconds. Cause: The `limit` parameter is not configured, and too much content from irrelevant datasets is recalled, leading to an overly long retrieval chain that affects document drafting efficiency.
- Symptom: Some image output addresses are truncated and cannot be viewed fully. Cause: The dataset's image external link permission configuration is not enabled, or complete file path parameters are not carried during retrieval, causing test report images in documents to fail to display properly.
- Symptom: Retrieval results incorrectly associate rectification notices from other projects, leading to incorrect content in drafted documents. Cause: The `collectionIds` parameter is not configured to limit the retrieval scope, or `searchMode` exact match is not enabled, resulting in mixing documents from unrelated projects, which may trigger quality and safety incidents.

## How to Confirm Proper Configuration
- Manually enter a query containing a known project number, and check whether the returned results only include supervision documents for the corresponding project.
- Upload a test supervision log document, wait for the weekly synchronization, then retrieve keywords from this document to confirm normal recall.
- Initiate a retrieval request, check whether the response time meets expectations, and confirm no timeout occurs.
- Check the image links in the retrieval results to confirm they can be opened fully with no truncation.

The values provided here are common starting points and should be evaluated against the reader's own samples.
