# Document and Material Drafting for Construction Project Environmental Impact Assessment (EIA) Approval: Multi-turn Dialogue and Prompt Engineering

## Data for This Category
Data for this category comes from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Documents processed daily include environmental impact statements, environmental impact report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval replies.
Document structures include fixed fields such as project category, EIA level, pollution prevention measures, public participation status, and approval requirements. No unified fixed units apply. Matching must be done based on actual project scenarios.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Scattered data sources require multi-turn dialogue to guide users to provide project identifiers or parameters from corresponding systems. The dialogue associates multi-source data to complete verification.
Fixed document fields cover the full project approval process. Dialogue must confirm missing information step by step according to approval stages. This avoids interaction confusion caused by loading excessive content at one time.
Irregular update frequency requires adding steps to check the latest ecological environment zoning control results in prompts. This ensures accurate approval basis.
Serious error consequences require embedding field verification logic in the dialogue link. This intercepts non-compliant content in advance. It prevents issues such as project suspension or approval revocation.

## Configuration Settings
These configurations are based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to unique project identifier | Associate with existing project data from the national unified construction project EIA declaration and approval system |
| `messages` | Retain 15–20 rounds of previous interaction records | Cover the complete dialogue process of multi-turn approval confirmation, avoid loss of key information |
| `variables` | Bind project category and EIA level variables | Dynamically trigger corresponding EIA approval verification rules |
| Single response character limit | 3000–5000 characters | Match the output length of a single EIA document fragment, avoid content truncation |
| Dialogue timeout period | 600 seconds | Prevent interaction interruption caused by long waiting times |
| Prompt triggering rule | Switch according to the approval stage entered by the user | Focus on document drafting for the current stage, avoid confusion of cross-stage information |

## Three Common Mistakes
- Phenomenon: Form input fields configured in the workflow do not display in the dialogue interface, and interaction content is empty. Cause: Form variables are not correctly bound to the `variables` configuration item, causing the dialogue module to fail to read preset input items.
- Phenomenon: Configured file links do not load reference content in the dialogue, and corresponding EIA document data cannot be called. Cause: File link variables are not bound to the data source configuration of the dialogue module, or system permissions pointed to by the links are not enabled.
- Phenomenon: Dialogue roles do not switch according to the approval process, and generated documents do not meet approval stage requirements. Cause: Prompts do not clearly bind role rules for different `messages` rounds, causing confusion in role logic.

## How to Verify Successful Configuration
- A test dialogue is triggered, the project category and approval type are entered, and whether the dialogue automatically pops up preset form input fields is checked.
- A test link corresponding to an EIA document is uploaded, and whether the dialogue module can load and reference the document content is confirmed.
- Multi-turn interaction instructions are sent, and whether the `messages` history record retains the specified number of rounds of content as configured is checked.
- The variable values bound to `variables` are adjusted, and whether the dialogue triggers verification rules for the corresponding stage is confirmed.
