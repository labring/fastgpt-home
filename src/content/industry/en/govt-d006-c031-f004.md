# Document and Material Drafting for Construction Project Environmental Impact Assessment Approval: Workflow Orchestration

## What data looks like for this category
This category of data comes from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. The update frequency is irregular. Daily generated documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. Core fields include project category, EIA level, pollution prevention measures, public participation feedback, approval status, etc. The length of individual documents varies widely.

## What constraints these characteristics impose on the workflow orchestration link
Multi-source, irregularly updated data requires workflows to support dynamic access to different data sources, to avoid data mismatches caused by fixed configurations. Complex document structures and core fields require workflows to include built-in parameter verification steps to ensure complete key information. The need to automate core time-consuming links requires workflow nodes to be connected in accordance with business logic to reduce manual intervention. The serious consequences of errors require workflows to be configured with failure retry and exception alert steps to ensure compliance of the approval process.

## How to configure
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Bind EIA project ID and exclusive knowledge base ID | Used to dynamically pass business-specific parameters in the workflow |
| Knowledge base search node parameters | Call the knowledge base ID passed in `variables` | Adapt to the needs of calling exclusive EIA knowledge bases for different projects |
| Code run node timeout | 600 seconds | Meet the time requirements for EIA data verification and format conversion |
| Text splice node character limit | 800–1200 characters | Adapt to the conventional length of documents such as EIA approvals and technical assessment opinions |
| AI question and answer node trigger condition | Execute only when the output of the previous node contains valid non-empty content | Avoid redundant costs caused by invalid model calls |

## Three common misconfigurations
- The phenomenon where variables can be spliced normally during workflow local debugging, but the variables are not replaced during API calls, is caused by failing to correctly configure the `variables` parameter as a global parameter that can be passed by external requests.
- The phenomenon where the code run node cannot output streaming results is caused by failing to configure the return format for streaming output according to node requirements, which prevents the results from being received in streaming mode.
- The phenomenon where the AI question and answer node cannot receive input from the text splice node is caused by the output of the text splice node not matching the plain text input format required by the AI question and answer node.

## How to verify a correct configuration
- Manually pass test project ID and knowledge base ID, check whether the `variables` parameter is correctly passed to the corresponding workflow nodes.
- Run the workflow, check whether the code run node completes execution within 600 seconds with no timeout errors.
- Trigger an API call to the workflow, verify whether the returned results include the correctly replaced project ID and knowledge base ID variables.
- Check whether the output of the text splice node matches the preset EIA document format, with no missing or redundant content.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
