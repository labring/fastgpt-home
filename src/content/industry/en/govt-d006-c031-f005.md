# Document and Material Drafting for Construction Project Environmental Impact Assessment Approval: Tool Calling and Plugins

## What This Category’s Data Looks Like
Data sources for this category include the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Commonly processed documents include environmental impact assessment reports, environmental impact assessment statement forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents.
Document structures cover basic project information, pollution prevention and control plans, public participation materials, and approval-related documents.
Fields include project category, EIA level, pollution prevention measure content, public participation feedback status, and some documents include image-format monitoring report attachments.

## Constraints Imposed on Tool Calling and Plugins Workflows
Data sources for this category are scattered, and updates follow no fixed schedule. Tools and plugins must support integration with multiple heterogeneous systems, and pull files and data from different sources on demand.
Documents include long text and multimodal attachments. Processes must distinguish between plain text and multimodal inputs, and adapt to the processing capabilities of different models.
Core business steps rely on standardized checks such as project category verification and pollution measure review. Tools must bind dedicated verification logic.
Data is linked to the full approval workflow. Tool call failures or incorrect results directly impact project approval progress. Complete failure retry and log retention mechanisms must be configured.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapt to input types that include both plain text documents and multimodal monitoring reports in EIA scenarios, automatically assign appropriate processing models |
| `functionCall` | Enabled, bound to EIA classification and text generation tools | Implement core business functions including automatic project category verification, pollution prevention measure review, and automatic generation of EIA documents |
| Plugin call timeout | 300–600 seconds | EIA data pulling and document generation require long processing cycles, avoid task interruption due to timeout |
| Text generation length limit | 8000–10000 characters | Match the standard length of a single chapter of an EIA report, meet the generation requirements for a single document |
| External API call permissions | Configure whitelist IPs and signature verification | Protect sensitive EIA data, only allow authorized internal systems to make calls |
| HTTP plugin import | Import via plugin marketplace or manually configure request parameters | Support integration with external interfaces such as the national unified construction project EIA declaration system |

## Three Common Misconfigurations
- A 400 status code error indicating model incompatibility may occur when calling the `toolChoice` function. This occurs if the in-use model has not been pre-verified to support the `toolChoice` function, and a model limited to plain text generation is mistakenly used for tool calling scenarios.
- External API calls may return empty result fields after the application is published. This occurs if the application's API access permission is not enabled, or if the signature and parameter format for external calls are not correctly configured.
- Generated EIA documents may lack pollution prevention measure content after uploading multimodal monitoring reports. This occurs if no input type routing rule is configured, and multimodal data is processed by a plain text model, which cannot extract monitoring data from images.

## How to Verify Proper Configuration
- Test with a plain text EIA approval application. After calling the tool, check whether the `functionCall`-bound classification tool is triggered, and whether a compliant project category verification result is returned.
- Upload an image-format monitoring report, verify that a multimodal model is called to complete information extraction, and that structured pollution prevention measure content is generated.
- Call the configured external API, pass test parameters, and check whether a correct generation result is returned with no error messages.
- Check the HTTP plugin configuration, confirm that the request address, request headers, and parameters match the requirements of the connected system, with no configuration errors.
