# Document and Material Drafting for Construction Project Environmental Impact Assessment Approval: Model Access and Configuration

## What data for this category looks like
Data for this category primarily comes from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Documents processed daily include environmental impact assessment reports/report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approvals. The core document structure follows project basic information, pollution factor analysis, prevention measures, public participation status, and approval conclusion. Fields cover project category, EIA level, pollutant emission parameters, regional control requirements, and more. Some documents require cross-verification using ecological environment data from the corresponding region.

## What constraints these characteristics impose on the "model access and configuration" link
Data for this category is scattered across multiple official systems with no fixed update cycle. This requires the model access link to support dynamic pulling of multi-source data and format adaptation. Daily documents have fixed structures but contain dense professional terminology, so a context window adapted to the EIA professional field must be configured to fully carry professional content. EIA levels and project categories vary significantly across different projects, leading to wide fluctuations in document length. Model generation parameters must be flexibly adjusted to match output requirements for different scenarios. At the same time, since errors directly affect project construction and approval validity, the configuration link must strengthen result traceability and pre-error interception capabilities.

## How to set the configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | EIA reports are usually lengthy, requiring full carrying of project basic information and regional control data, and adapting to the context limit of FastGPT v4.17.0 |
| `maxTokens` | `2000–3000 token` | Standard output length for EIA approval documents, avoiding generated content exceeding the length required for approval |
| `quoteMaxToken` | `1500 token` | Structured data from the unified EIA declaration system must be prioritized as the basis for generation, controlling the total length of quoted content to ensure accuracy |
| `toolChoice` | `auto` | Automatically select whether to call tools for data verification based on the document processing link, adapting to the complexity of different projects |
| `temperature` | `0.2–0.4` | EIA documents must maintain rigor, reducing randomness in generated content to ensure consistency with official data |
| `AIPROXY_API_ENDPOINT` | Fill in the official interface address according to the deployment environment | Ensure stability and compliance of model calls, matching the interface specification of FastGPT v4.17.0 |

## Three common configuration errors
- Configuration errors pop up after clicking model properties. The cause is that `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is not filled correctly, and the parameter format does not meet the docking specifications of FastGPT v4.17.0.
- Abnormal generated results when calling a vision model to process EIA drawings. The cause is that the `vision` configuration item is not enabled, or the drawing file format is not adjusted to the type supported by the model.
- Connection timeout occurs after adding a local Ollama model. The cause is that `maxContext` is not adjusted to adapt to the context limit of the local model, causing the request data volume to exceed the model's processing capacity.

## How to confirm the configuration is correct
- After filling in `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, perform a model connectivity test to confirm that a normal response conforming to the FastGPT v4.17.0 specification is returned.
- Import a standard EIA report form sample, trigger the document generation process, and check whether the generated content includes core business fields such as project category and EIA level.
- Adjust the `temperature` parameter, compare the two generated EIA approval contents, and confirm that the rigor of the generated results meets business requirements.
- Enable the `toolChoice` automatic mode, upload a document containing regional control data, and confirm that the model automatically calls the corresponding tool to complete data verification.

The values provided are common starting points and should be measured against the reader's own samples.
