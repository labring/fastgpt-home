# Document and Material Drafting for Construction Project Environmental Impact Assessment Approval: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data covers daily business documents from ecological environment department EIA divisions, administrative approval bureaus, construction units, and EIA institutions. These documents include environmental impact assessment reports, EIA report forms, approval applications, public participation statements, technical assessment opinions, and EIA approval decisions. Data sources include the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platforms, and monitoring data. Updates do not follow a fixed cycle. Single environmental impact assessment reports typically range from 5000 to 20000 characters. Documents are stored and categorized by fields such as project category, EIA grade, and pollution prevention measures. Some documents include structured monitoring data and zoning control requirements.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Dispersed data sources and non-fixed update cycles require knowledge base retrieval to support synchronization across multiple data sources, to avoid expired content or content that does not cover the latest policies. Diverse document types and large differences in document length require adaptation to retrieval of EIA documents of varying lengths, to prevent overly long single documents from exceeding context windows. The strong correlation between project category and EIA grade requires prioritizing matching of project attribute fields during retrieval, to avoid recalling historical documents unrelated to the current project. The mixed document structure of structured fields and non-professional text requires support for a hybrid retrieval mode, to balance semantic matching and precise keyword matching.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | EIA documents have a high density of professional terms. This interval filters low-relevance results while balancing recall precision and coverage |
| `limit` | Top 8–12 entries | EIA documents carry a large amount of information per batch. This interval provides sufficient reference content without exceeding context windows |
| `searchMode` | Hybrid vector + keyword retrieval | EIA documents contain structured fields and professional text. Hybrid retrieval can match both semantic and keyword features |
| `usingReRank` | Enabled | EIA technical documents have high similarity. Re-ranking optimizes result sorting and improves the recall priority of core content |
| `datasetSearchUsingExtensionQuery` | Enabled | EIA project descriptions often contain custom terms. Extended queries can cover synonyms and professional expressions to improve recall coverage |
| `collectionIds` | Specify collections by EIA document type | Different types of EIA documents require independent management. Specifying collection IDs avoids recalling documents from non-target categories |

## Three common mistakes
- Phenomenon: Retrieval results include non-target EIA documents, with irrelevant approval content across categories. Cause: The `collectionIds` parameter is not configured correctly, and no exclusive collection is specified by document type, leading to recall of approval documents from other categories.
- Phenomenon: After enabling a web-connected model, retrieval results still do not include the latest EIA policy content. Cause: `datasetSearchUsingExtensionQuery` is not enabled, or real-time data source synchronization is not configured. Only relying on a static knowledge base cache prevents pulling the latest public data.
- Phenomenon: Structured fields in some EIA reports are not retrieved. Cause: Hybrid retrieval mode is not enabled. Only using vector retrieval cannot precisely match the keyword features of structured fields.

## How to confirm the configuration is correct
- Confirm that FastGPT v4.17.0 is currently in use. Check the knowledge base collection configuration, confirm that corresponding `collectionIds` are specified by EIA document type. Verify that non-target category documents are filtered by testing retrieval of such documents.
- Initiate a test retrieval containing professional terms. Check if the `similarity` scores of returned results fall within the preset interval, to verify that the similarity threshold configuration takes effect.
- After enabling `usingReRank`, compare the result sorting before and after re-ranking, to confirm that core EIA documents are displayed first.
- Test a query containing custom project terms, to verify that `datasetSearchUsingExtensionQuery` expands the query scope and recalls relevant content.

The values provided are common starting points and should be measured against the reader's own samples.
