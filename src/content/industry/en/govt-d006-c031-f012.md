# Document and Material Drafting for Construction Project Environmental Impact Assessment (EIA) Approval: Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category comes from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Commonly processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents. Document structure follows EIA specification chapter divisions, and includes fields such as project category, EIA level, pollution prevention measures, and public participation feedback. There is no fixed unified statistical unit, and field content is adjusted based on the actual situation of each project.

## Constraints for Deployment and Upgrade
Data sources for this category are scattered, document structures vary widely, and updates follow no fixed cycle. These factors create multiple constraints for deployment and upgrade.
It is necessary to connect to multiple external data sources, including the national unified construction project EIA declaration and approval system. Stable cross-system connection parameters must be configured during deployment.
Document length varies significantly: small project report forms are only hundreds of characters, while large reports can reach tens of thousands of characters. Text processing logic must be adapted to support these different lengths.
Data updates have no fixed rhythm, so support for switching between incremental synchronization and full updates is required to avoid repeated processing of historical data.
EIA documents involve compliance verification. A reliable error capture mechanism must be configured during deployment to prevent compliance risks caused by processing errors.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Connect to a local or cloud-hosted MongoDB instance, configure read-write separation nodes | EIA data requires persistent storage and supports multiple concurrent queries; read-write separation improves processing efficiency |
| `REDIS_URL` | Configure a key expiration time of 600–1200 seconds, enable memory elimination policy | Used to cache basic EIA project information and zoning control data, reducing the number of repeated calls to external systems |
| `STORAGE_S3_ENDPOINT` | Connect to an object storage service that meets compliance requirements, configure private read-write permissions | Used to store original EIA documents and processed intermediate results, ensuring data security |
| `FILE_TOKEN_KEY` | Use a randomly generated string of 32 bits or more as the secret key | Used to generate access tokens for EIA documents, preventing unauthorized access to sensitive approval materials |
| `ROOT_KEY` | Configure a randomly generated string with strong complexity to restrict only administrators from accessing the backend | Ensures the security of the backend management of the deployment environment, avoiding unauthorized modification of configurations and data |

## Three Common Configuration Mistakes
- Phenomenon: After deployment, logs show `ocr error`, and scanned drawings in EIA reports cannot be parsed. Cause: The dependency environment required for image processing is not configured, or the OCR service interface is not correctly connected.
- Phenomenon: No image understanding model option appears when creating a new knowledge base, and chart data in the report form cannot be extracted. Cause: The image processing plugin is not enabled during deployment, or the corresponding model call parameters are not configured.
- Phenomenon: After starting the container, a database connection failure prompt appears, and the EIA project list cannot be loaded. Cause: The connection parameters for `MONGODB_URI` or `REDIS_URL` are not correctly filled, resulting in failure to establish a data connection.

## How to Verify Successful Configuration
- Run the environment health check script to verify that the connection status of `MONGODB_URI` and `REDIS_URL` is normal.
- Upload a small EIA report form to test whether the document parsing and knowledge base creation process completes successfully.
- Attempt to generate a draft public participation explanation to confirm that the model call and content generation logic are functioning.
- Review backend logs to confirm there are no frequent external system call timeouts or data storage failure records.
