# Document and Material Drafting for Investment Project Approval and Post-Evaluation: Workflow Orchestration

## What the data for this category looks like
This category’s data originates from State-owned Assets Supervision and Administration Commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements, and is updated quarterly. Daily produced documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset evaluation reports, and post-investment evaluation reports. Document fields cover project investment amount, construction cycle, market forecast data, financial calculation indicators, risk control ratings, and more. Core fields differ across documents: project proposals focus on pre-demonstration data, while post-evaluation reports focus on post-launch operational data.

## What constraints these characteristics impose on the "workflow orchestration" link
This category’s data is updated quarterly, so workflow data source synchronization nodes must match the quarterly update rhythm, and overly frequent triggering logic must be avoided. There are significant differences in fields across different document types, so workflows must be configured with differentiated field mapping rules for each document type to ensure accurate data extraction. The need to connect multiple data sources requires setting multiple cross-system nodes in the workflow, and `nodeId` must be used to distinguish the calling logic of different data sources to avoid node conflicts. Additionally, errors in this category have serious consequences, so workflows must be configured with failure retry and exception alert nodes to ensure process stability.

## Three common mistakes
- Phenomenon: The data analysis node in the workflow cannot execute consistently, and selecting the corresponding work order fails to trigger the preset operation. Cause: The association mapping rule between work orders and project data is not configured via `variables`, causing the node to fail to recognize the target data source.
- Phenomenon: The workflow runs normally in debug mode, but a call error occurs in production mode. Cause: Unique `nodeId` is not assigned to different cross-system nodes, leading to conflicts in node calling logic in the production environment.
- Phenomenon: Loop execution nodes cannot be added to the workflow, and multi-project data cannot be processed in batches. Cause: The conditional parameters for loop triggering are not configured in `variables`, causing the loop logic to fail to take effect.

## How to confirm the configuration is complete
- Trigger the workflow, check whether the data source synchronization node pulls project data from the corresponding system with quarterly update rhythm.
- Switch to production mode to run the workflow, confirm that the calling logic of all cross-system nodes is normal and no error messages are displayed.
- Test the fixed operation node: after selecting the corresponding work order, check whether the node can trigger the preset data analysis or document generation operation.
- Export the complete session record of the workflow, confirm that all session fragments are included.
