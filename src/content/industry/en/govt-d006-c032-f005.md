# Document and Material Drafting for Investment Project Approval and Post-Evaluation: Tool Calling and Plugins

## What This Category of Data Entails
The daily documents covered by this category include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, post-investment evaluation reports, and similar materials. Data sources include the State-owned Assets Supervision and Administration Commission investment supervision system, enterprise ERP and project management systems, industry market data, audit and financial statements. The update frequency is quarterly.

Document structures cover modules such as basic project information, investment calculation, risk assessment, post-evaluation indicators, and more. Fields include project number, investment amount, construction period, production benefit, risk rectification status, and more. There is no unified fixed unit standard, and matching must be done against the business specifications of the corresponding documents.

## Constraints Imposed on Tool Calling and Plugins
Since data sources involve multiple internal management systems and external data sources, tool calling must support connections to multiple data sources and data pulling to avoid data loss caused by differences in system permissions or interface formats.

Individual documents have long length and complex structure, so tool calling must adapt to chunk processing logic to avoid exceeding context limits. The quarterly update frequency means high-frequency data synchronization is unnecessary, and a reasonable cache cycle can be set to improve efficiency.

At the same time, operational errors in this category may lead to serious consequences such as losses of state-owned assets. Tool calling must configure failure retry and verification mechanisms to ensure data accuracy and process compliance.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |

| `toolChoice` | `auto` | Adapts to multi-type tool calling requirements, automatically selects the corresponding data source or document processing tool |
| Single tool call limit | Top 6 entries | Matches the number of core chapters in a single feasibility study report, avoids excessive redundant data causing context overflow |
| Failure retry count | 3 times | Addresses temporary fluctuations in cross-system access, balances success rate and response speed |
| Maximum context length | 8000–12000 token | Adapts to the content length of a complete single feasibility study report, covers core business fields |
| Tool call timeout | 600 seconds | Adapts to delays in cross-system data pulling, avoids request interruptions caused by large data volume |
| Knowledge base recall threshold | Calibrated via actual testing | Matches the similarity characteristics of documents in this category, avoids recalling irrelevant historical project data |

## Three Common Misconfigurations
-  A connection error is encountered during tool calling. The cause is that the connection keys for multiple data sources are not properly configured, or cross-system access permissions have not been granted.
-  The content returned by the API call does not include project data from the knowledge base. The cause is that the exclusive knowledge base for this category is not bound in the application configuration, or the recall threshold is set too high to match relevant documents.
-  The platform test runs normally but the API call results are inconsistent. The cause is that the API request does not carry the correct context parameters, or the bound knowledge base is not specified for use.
