# Document and Material Drafting for Investment Project Approval and Post-Evaluation: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from state-owned assets investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Updates occur quarterly. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset evaluation reports, and post-investment evaluation reports. These documents fall into two structural categories: project initiation approval and post-investment evaluation. They include business fields such as project investment, compliance, and post-investment benefits, plus unstructured text content. Field units vary by specific business document type.

## What constraints these characteristics impose during deployment and upgrade
Data comes from multiple sources and includes state-owned assets supervision-related content. During deployment, configure permissions for connecting multiple systems to ensure data reading compliance. The quarterly update rhythm requires the data synchronization cycle to match business update frequency, preventing data delay or redundancy. A large share of long-text documents means sufficient context processing resources must be reserved during deployment. During cross-version upgrades, some server scenarios cannot connect to the public internet. Complete upgrades via offline migration of databases and configuration files. Ensure core business data flow is not interrupted during the upgrade process, to avoid disrupting state-owned assets supervision reporting work.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username:password]@internal-db:27017/fastgpt?authSource=admin` | Stores project documents and business data, must match the address and permission configuration of the enterprise’s internal database |
| `REDIS_URL` | `redis://:[secure-password]@internal-redis:6379` | Caches retrieval results and session data to ensure response speed for long-text processing |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | Stores compliance documents and large-volume reports to avoid compliance risks from public internet transmission |
| Maximum Context Window | 8000-12000 token | Adapts to the long-text content of feasibility study reports and post-investment evaluation reports, preventing key information from being truncated |
| Data Synchronization Cycle | Once per month | Matches the quarterly update rhythm of business data, balancing data freshness and synchronization costs |

## Three Common Mistakes
- Symptom: Project document retrieval returns empty results after upgrade. Cause: Database access permissions were not updated when migrating the `MONGODB_URI` configuration, resulting in failure to read existing business data.
- Symptom: Long-text generation task times out and throws an error. Cause: The context parameter was not adjusted to match the length of business documents, causing model processing to exceed the preset threshold.
- Symptom: Rerank model call fails. Cause: A rerank model incompatible with FastGPT v4.17.0 was used, and a model configuration matching the compatible version was not selected.

## How to confirm the configuration is complete
- Log in to the FastGPT management backend, check the connectivity of connection configurations such as `MONGODB_URI` and `REDIS_URL`, and run a database read test to confirm that project document data can be obtained normally.
- Upload a standard feasibility study report, trigger the retrieval and generation process, and verify that the output content includes business-standard fields and text structure.
- Manually trigger a data synchronization task, review the synchronization log for no errors, and confirm that data can be updated according to the configured cycle.
- Configure the rerank model and initiate a test call, confirm that the number of returned results meets the preset requirements, and that no call errors occur.
