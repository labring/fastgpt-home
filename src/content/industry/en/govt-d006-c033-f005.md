# Document and Material Drafting for Tendering and Procurement Compliance Management: Tool Calling and Plugins

## What Data Looks Like for This Category
Data sources for this category include enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases, with daily updates. Daily processed documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials. Document fields cover procurement methods, budget basis, scoring methods, supplier qualification conditions, performance clauses, and more. Field priorities and validation rules differ across documents, and configurations must adapt to centralized procurement and disciplinary inspection and audit requirements of domestic state-owned enterprises and their parent groups.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
Dispersed, daily-updated data sources require tool calling to connect to multiple systems in real time to pull the latest data, avoiding use of expired supplier database or procurement plan information. Multiple document types with varying field rules require configuring dedicated field validation logic for each document type, and switching corresponding data source association rules based on document type during tool calling. Verification of procurement methods and budget basis must accurately match internal regulations; tool calling must link to past compliance cases in the audit issue database to ensure validation logic complies with regulatory requirements. Additionally, tool calling output must adapt to usage scenarios of different departments: for example, the procurement center requires a complete document framework, while the audit department requires clear compliance verification results.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapt to tool calling requirements for different document types, automatically match data sources required for compliance verification, and comply with FastGPT v4.17.0 tool calling specifications |
| `functionCall` | Enabled | Force tool calling to return structured results, facilitating the generation of document frameworks and verification reports that meet compliance requirements |
| Tool Trigger Condition | Trigger based on document type | Match field validation rules for different documents, avoiding logical conflicts from cross-type calls |
| Context Window Size | 8000–12000 token | Accommodate full data pulled from multiple systems including procurement, contract, and audit information, ensuring completeness of validation logic |
| Maximum Request Retry Count | 3 times | Address temporary fluctuations in multi-system interface calls, preventing process interruptions caused by single request failures |
| Result Rearrangement Threshold | Calibrated based on actual testing | Adapt to weight differences across different data sources, ensuring correct priority of compliance verification |

## Three Common Misconfigurations
- Phenomenon: Compliance verification results returned by API calls differ from those in online chat, with some fields empty or incorrect validation logic. Cause: API calls did not set `toolChoice` to `auto`, and did not bind dedicated data source mapping rules for this category, leading to failure to automatically pull the latest procurement platform and audit issue database data during calls.
- Phenomenon: Pie charts generated by tool calls fail to render properly, and the output markdown format does not meet requirements. Cause: No format validation rules were configured for tool calls, and no adaptive format was specified for chart output, resulting in content that does not comply with document typesetting specifications.
- Phenomenon: Added external services cannot be called normally in the tool set, and the tool returns a timeout error. Cause: Correct service ports and request timeout values were not set in tool configuration, and service permission verification binding was not completed, preventing normal connection to external services.

## How to Confirm Proper Configuration
- Initiate a tool call for a procurement plan document, verify whether the returned results automatically pull the latest budget data and procurement method rules from the enterprise procurement platform.
- Submit the same bidding document verification request via API call and online chat separately, compare whether their compliance verification results are consistent.
- Trigger an external service call, check whether the tool set can normally pull the latest qualification data from the supplier database.
- Generate a bid evaluation record document containing a pie chart, verify whether the output markdown format complies with document typesetting requirements.
