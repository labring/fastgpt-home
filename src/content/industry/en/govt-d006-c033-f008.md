# Document and Material Drafting for Tendering and Procurement Compliance Management: Document Parsing and Chunking

## What the Data for This Category Looks Like
Core data for this category comes from daily business documents of entities including central and local state-owned enterprise procurement centers and tendering offices. Documents include procurement plans, requirement specifications, tender documents, bid evaluation records, contracts, acceptance slips, and supplier complaint materials.
Data sources cover enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases. The update frequency is daily.
Document structures include both structured templates and unstructured records. Core fields include procurement method, budget basis, scoring rules, supplier qualification requirements, and others. There is no fixed unified unit format. Some documents require interpretation of field meanings in combination with business scenarios.

## How These Characteristics Create Constraints for Document Parsing and Chunking
The multi-source, multi-format nature of daily documents requires parsing logic to adapt to multiple file types including PDF, Word, and TXT. It also requires maintaining parsing accuracy for both structured templates and unstructured records.
The high-frequency daily data update demand requires sufficient response efficiency from the parsing process, to avoid delays that affect compliance review progress.
Core fields such as scoring rules and supplier qualification requirements are directly linked to bid rigging risks. Parsing processes must ensure no field omissions or semantic fragmentation.
For some business documents such as Java interface documents renamed to TXT, general parsing logic cannot recognize professional format content, requiring additional adaptive rules.

## Configuration Settings
This configuration is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Tendering and procurement documents contain long paragraphs of compliance clauses. Excessively long chunks will split clause associations, while excessively short chunks will lose contextual semantics. This range is calibrated through testing to maintain business logic integrity. |
| `chunkSplitter` | Split by paragraph + title | Procurement documents often have clear section titles such as "Bid Evaluation Rules" and "Supplier Qualifications". Splitting by titles preserves the coherence of business logic. |
| `customPdfParse` | Enabled | Adapts to encrypted PDF and scanned tender documents, avoiding empty parsing results. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large centralized procurement tender documents take longer to parse. 600 seconds covers parsing needs for most large files. |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch upload of multiple attachments for group-level centralized procurement, adapting to batch business documents exported from enterprise procurement platforms. |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types such as contracts vs bid evaluation records, to meet precise parsing requirements for compliance reviews. |

## Three Common Errors
- Phenomenon: After uploading a Java interface file renamed to TXT, the parsing result is empty, with no valid content in returned fields. Cause: General TXT parsing logic can only recognize plain text content, cannot adapt to code blocks, comments, and professionally formatted content in Java interface documents, and custom parsing rules are not enabled.
- Phenomenon: Some PDF files show empty content after upload. Cause: The `customPdfParse` configuration is not enabled, or the file is in encrypted or scanned format. General parsing logic cannot extract text information.
- Phenomenon: A timeout error occurs when parsing large tender documents. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient to complete parsing of large files, leading to interruption of the parsing task.

## How to Verify Correct Configuration
- Upload a single compliant tender document in PDF format, and check that the parsing result includes core compliance fields such as procurement method, budget basis, scoring rules, with no missing fields or null values.
- Upload a Java interface document renamed to TXT, enable the `customPdfParse` configuration, and verify that valid business content such as interface names and parameter lists can be extracted.
- Upload batch procurement attachments larger than 100 MB, and check that the parsing task completes within the duration set by `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout errors.
- Adjust the `chunkSize` parameter, compare semantic integrity across different chunk lengths, and ensure that compliance clauses are not split.

The values provided are common starting points and should be evaluated against available sample data.
