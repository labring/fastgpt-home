# Document and Material Drafting for Tendering and Procurement Compliance Management: Deployment and Upgrade

## What the data for this category looks like
This category’s data originates from enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases, with a daily update frequency. Daily processed documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance slips, and supplier complaint materials. Different documents have distinct field structures: bidding documents include procurement methods, scoring items, and budget basis; contracts include performance clauses and acceptance standards; audit issue databases include past compliance rectification records.

## What constraints these characteristics impose on the deployment and upgrade phase
The data characteristics of this category impose clear constraints on the deployment and upgrade phase. Multi-source, scattered data sources require configuring multi-data source connection parameters during deployment to prevent synchronization omissions. The daily update frequency demands incremental synchronization logic to ensure timely storage of the latest supplier qualification and audit issue data. Diverse document types require adapted parsing rules for common formats including PDF and Word. Strict compliance verification requires accurate field association in knowledge base metadata to avoid missing key compliance items such as budget basis and scoring methods. During upgrades, the storage path of original procurement documents must be retained to avoid interrupting queries of historical compliance data.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://localhost:6379/0` | Supports session caching and vector retrieval acceleration; use default local port and database for local deployment |
| `STORAGE_S3_ENDPOINT` | `http://minio:9000` | Stores binary files of bidding documents; adapts to default port for local object storage deployment |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt` | Stores metadata of procurement documents and compliance audit logs; use default port for local deployment |
| `DB_MAX_LINK` | 100 | Limits the number of associated documents pulled to avoid performance degradation caused by loading excessive historical procurement data |
| Single search limit | Top 10 entries | Matches associated entries of procurement documents to cover common compliance verification dimensions |
| File parsing timeout | 600 seconds | Processes large PDF-format bid evaluation records to avoid timeout interruptions during parsing |

## Three common mistakes
- The phenomenon is that when parsing bid evaluation records marked in PDF format, FastGPT returns a timeout, and the parsing service side log shows that the task has been completed. The cause is that `STORAGE_S3_ENDPOINT` is not configured, causing the parsed documents to fail to be written to storage and triggering a timeout rollback.
- The phenomenon is that the answer only lists knowledge base reference entries at the bottom, and cannot associate specific compliance clauses of bidding documents. The cause is that incremental synchronization configuration is not enabled, and the knowledge base has not loaded the supplier complaint materials and audit issue records updated on the current day.
- The phenomenon is that the Docker-deployed instance triggers an abnormal alarm every 30 minutes, and resumes normal operation after restart. The cause is that the persistence parameter for `REDIS_URL` is not configured, and cached session data is lost regularly, causing the scheduled synchronization task to interrupt.

## How to confirm the configurations are set correctly
- The knowledge base management page at `FE_DOMAIN` can be accessed to confirm that the status of added procurement platform and contract system data sources is normal.
- Upload a bidding document in PDF format, wait for parsing to complete, and check whether metadata fields include compliance verification items such as procurement method and budget basis.
- Trigger a compliance verification task, and check for successful connection records for `MONGODB_URI` and `REDIS_URL` in system logs.
- Wait 24 hours, then check the knowledge base update log to confirm that the same day’s supplier database data has completed synchronization.

The values given are common starting points and should be measured against the reader's own samples.
