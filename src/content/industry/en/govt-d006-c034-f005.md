# Document and Material Drafting for Student Enrollment and Student Record Management: Tool Calling and Plugins

This documentation is written for FastGPT v4.17.0.

## What data this category includes
This category’s data includes core documents such as enrollment application forms, student record forms, transfer applications, enrollment plans, admission rosters, and student record change approval forms. Data sources include the National Primary and Secondary School Student Record Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. Data update frequency is daily. Document fields cover standard business items such as student identity identifiers, household registration and property association information, student record numbers, and enrollment qualification verification items, with no additional fictional statistical content included.

## Constraints imposed by these characteristics on tool calling and plugins workflows
The data sources for this category are scattered and contain sensitive identity information. Tool calling must interface with multiple external system APIs simultaneously to complete cross-data source field mapping. Data is updated daily, so a fixed synchronization cycle must be set for tool calling to ensure the latest student record, household registration, and enrollment data is used. Most document fields are standardized items related to identity verification. Tool parameters must strictly match the field names to avoid missing key verification content. Additionally, since errors may lead to student record anomalies or admission disputes, a result verification step must be added after tool calling to confirm data consistency.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the need for parallel tool calling in enrollment and student record management scenarios, automatically matching corresponding business tools |
| `functionCall` | `Enabled` | Supports structured output of document field content, meeting the standardized format requirements for student record documents |
| Tool call timeout duration | `30–60 seconds` | Adapt to the response times of multiple data source APIs, preventing overall workflow interruption caused by lag in a single API |
| Synchronization data source scope | `Data updated in the last 1 day` | Match the daily update frequency of this category’s data, ensuring the latest student record and enrollment information is used |
| Result verification count | `Top 3 entries` | Limit the number of returned verification results, focusing on core enrollment qualification and student record information to avoid interference from redundant data |
| Field mapping rules | `Match by business document field names` | Correspond to the standardized field structure of this category’s documents, ensuring accurate data extraction |

## Three common configuration mistakes
- Phenomenon: Empty fields returned after calling a custom external interface. Cause: Plugin parameters not configured according to the standardized field names of this category’s documents, resulting in interface returned data that cannot be correctly mapped to tool variables.
- Phenomenon: Tool calling module fails to trigger normally. Cause: The `functionCall` configuration item not enabled, causing the system to fail to recognize structured calling instructions and locate the corresponding tool entry.
- Phenomenon: Plugin call timeout error occurs. Cause: No reasonable timeout duration set, using an overly long wait time that exceeds the system’s default limit, or external data sources responding slowly with no retry mechanism configured.

## How to confirm configuration is correct
- Run a single tool calling test and verify that returned data matches the fields of this category’s student record and enrollment documents.
- Check plugin calling logs to confirm the data source synchronization scope matches the configured update frequency.
- Verify the configuration status of `toolChoice` and `functionCall` to ensure they match the calling requirements of the business scenario.
- Simulate abnormal API responses to confirm whether the timeout and retry configurations take effect.
