# Document and Material Drafting for Enrollment and Student Status Management: Citation Source and Traceability

## What this category of data looks like
Daily documents for this category include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources cover the national primary and secondary school student status information management system, local enrollment platforms, household registration and property data, and school educational administration systems. Data updates occur daily. Most individual documents are structured forms or standardized texts. They contain core fields such as student identity identifiers, household registration addresses, student status numbers, enrollment batches, and change types. These documents cover the full process management link from enrollment application to student status changes.

## What constraints these characteristics impose on the citation source and traceability link
Data for this category comes from multiple sources and updates daily. The citation traceability link must accurately match the document source system, to avoid confusion of student status data across different platforms. Structured form documents include core identification fields such as student status numbers and household registration addresses. Recalled citation documents must be accurately bound to the queried student identity, to avoid invalid citations across students. Document types covering the full process require the traceability link to recall documents for enrollment or student status change scenarios, to meet query needs for different business use cases. Context length must also be controlled, to avoid redundant answers caused by too many documents being included.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average single-document length of enrollment and student status documents, to avoid context overflow |
| `responseData` | Enabled | Citation document metadata must be collected for traceability verification |
| `detail` | Full | Core fields such as student status number and household registration address must be displayed to ensure traceability accuracy |
| Knowledge base sync frequency | Daily | Matches the daily update rhythm of business data to ensure the timeliness of cited content |
| Maximum number of citation recall entries | Top 6 | Controls the number of documents introduced in a single run to avoid lengthy answers |
| Total knowledge base capacity | No more than 2000 MB | Adapts to the total storage requirement of student status and enrollment documents in a single scenario |

## Three common misconfigurations
- Phenomenon: A blank citation area appears only at the end of the answer, with no specific knowledge base document sources listed. Cause: The `responseData` configuration item is not enabled. The system does not collect metadata for cited documents, so citation lists cannot be generated.
- Phenomenon: Cited document content does not match the currently queried student identity, and student status information for other students is displayed. Cause: No recall filtering rules based on student identity identifiers are set, leading to the recall of irrelevant document entries.
- Phenomenon: The system prompts a context overflow error, and the answer cannot be generated normally. Cause: The value of `quoteMaxToken` exceeds the context length threshold of the currently used model, resulting in overly long input content.

## How to confirm configurations are properly applied
- Initiate a test conversation involving specific student status information. Check whether metadata such as the source and fields of cited documents is displayed at the end of the answer.
- Adjust the value of `quoteMaxToken`. Test whether citing long documents triggers a context overflow error, to verify the rationality of the configuration.
- Check the knowledge base sync logs to confirm that the daily automatic sync configuration has taken effect. Ensure cited content is the latest available data.
- Test associating multiple knowledge bases of the same category. Confirm that recalled documents all belong to enrollment and student status management content, with no cross-category irrelevant documents.
