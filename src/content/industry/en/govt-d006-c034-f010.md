# Document and Material Drafting for Student Enrollment and Student Status Management: Knowledge Base Retrieval and Recall

## What data looks like for this category
This category of data supports daily operations for education bureau basic education departments, school academic affairs offices, enrollment examination institutions, and street community collaborative windows. It covers enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources include the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. The update frequency is daily. Most documents are structured forms with fixed fields including student ID number, name, household registration address, application reason, and similar fields, with no complex unstructured formatting.

## What constraints these characteristics impose on knowledge base retrieval and recall
This category of data has scattered sources and is updated daily. Knowledge base retrieval must support multi-data source associated recall to ensure data timeliness. Most documents are structured forms, with fields focused on student identity and enrollment eligibility. Retrieval must prioritize matching core fields to reduce irrelevant results. Individual data entry volume is small but total volume is large. The number of returned recall results must be controlled to avoid context overload. Additionally, the data involves sensitive student personal information. Retrieval must strictly comply with compliance requirements, and only authorized roles can access corresponding results.

## Configuration settings
This configuration is based on FastGPT v4.17.0. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches core fields of structured student status and enrollment forms, avoids introducing irrelevant results if set too low, and prevents missing valid matches if set too high |
| `limit` | Top 8 entries | Adapts to the context capacity of single-round retrieval, avoids exceeding the model's processing limit with excessive data, and aligns with the information density of enrollment scenarios |
| `searchMode` | vector_search | Meets the semantic matching needs of structured forms in this category, prioritizes recalling content related to student identity and enrollment eligibility |
| `usingReRank` | Enabled | Performs secondary ranking on recall results, improves the priority of core field matches, and optimizes the relevance of retrieval results |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands the retrieval association scope, integrates cross-source data from the National Primary and Secondary School Student Status Management System and local enrollment platforms |

## Three common configuration errors
- Phenomenon: A large number of irrelevant results are returned after searching uploaded structured student status forms. Cause: The `similarity` threshold is set below 0.75, failing to accurately match core identity fields such as student ID number and household registration address.
- Phenomenon: Retrieval results do not include the latest enrollment plans or student status change data. Cause: Daily incremental data source synchronization is not configured, and the knowledge base has not updated the latest data from the National Primary and Secondary School Student Status Management System in a timely manner.
- Phenomenon: The number of single-round retrieval results is insufficient to cover required student status-related information. Cause: `datasetSearchUsingExtensionQuery` is not enabled, and cross-source data from local enrollment platforms is not associated.

## How to verify proper configuration
- Upload one latest student status information form, search for specified enrollment qualification review keywords, and check whether the returned results include the core field information of the corresponding form.
- View the dataset synchronization logs to confirm that the daily automatic synchronization function is operating normally, with no data update failure records.
- Adjust the `similarity` parameter to 0.8, search for keywords related to transfer application approval, and check whether the relevance of the returned results meets expectations.
- Check the number of retrieval returned results to confirm that it does not exceed the upper limit set by the `limit` parameter, and aligns with the information density requirements of the scenario.
