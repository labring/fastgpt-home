# Document and Material Drafting for Pollution Discharge Permit Management: Vector Models and Indexes

## What the data for this category looks like
Documents involved in this category include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies.
Data sources cover the National Pollution Discharge Permit Management Information Platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems.
The update frequency is quarterly.
Document fields include permitted emission limits, discharge outlet codes, monitoring periods, ledger reporting cycles, change item descriptions, and other relevant fields.
Data formats vary across different sources. Some content exported from systems mixes structured fields and unstructured text.

## What constraints do these characteristics impose on the vector models and indexing step?
Multi-source heterogeneous data sources require indexes to support mixed storage of structured fields and unstructured text. This ensures unified retrieval of pollution discharge permit documents imported from different systems.
The quarterly update frequency means index synchronization cycles do not need to be overly short. Full updates via scheduled tasks can reduce system resource usage.
Documents contain strictly compliance-related fields. Vector models must accurately capture core information such as permitted limits and emission requirements, to avoid retrieval results deviating from business needs.
Additionally, the audit link has high accuracy requirements. Index recall results must have clear business relevance to support compliance verification work.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the length of single business modules in pollution discharge permit documents, to avoid splitting permitted emission limits and corresponding discharge outlet information |
| Chunk Overlap Length | 100–150 characters | Preserves cross-chunk monitoring period and ledger cycle association information |
| Similarity Threshold | 0.75–0.85 | Accurately matches compliance requirements, reduces recall interference from unrelated documents |
| Single Search Limit | Top 5 results | Supports multi-dimensional compliance verification for pollution discharge permit audits, avoids redundant results |
| `maxToken` | 4096 | Adapts to the total content length of pollution discharge permit documents, avoids truncating core permit clauses |
| `defaultToken` | 256 | Matches the display length of single retrieval results, adapts to the quick review needs of audit personnel |

## Three Common Configuration Errors
- Phenomenon: The exported knowledge base dataset.csv only contains the index field, with no content field. Cause: Content index association was not enabled during chunk configuration, or document body fields were not correctly mapped during data source synchronization.
- Phenomenon: Vector model calls return parameter over-limit errors. Cause: The `maxToken` setting exceeds the single-processing limit of the model interface, or the single-batch index data volume exceeds system limits.
- Phenomenon: Retrieval results recall a large number of unrelated environmental statistical reports. Cause: The similarity threshold was set too low, and feature optimization was not performed for exclusive fields of pollution discharge permits such as permitted emission limits and discharge outlet codes.

## How to Verify Correct Configuration
- Manually upload a pollution discharge permit copy document, view the preview content after knowledge base chunking, confirm that core permit clauses and corresponding discharge outlet information are not split during chunking.
- Input test questions such as "permitted emission limits for a certain industry", view the similarity scores of recall results, confirm that the threshold setting meets business accuracy matching requirements.
- Export the knowledge base dataset.csv, check whether both index and content fields are included, confirm that the index mapping configuration is correct.
- View vector model call logs, confirm that the values of `defaultToken` and `maxToken` do not trigger interface errors.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
