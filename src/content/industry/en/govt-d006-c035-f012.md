# Document and Material Drafting for Pollution Discharge Permit Management: Deployment and Upgrade

## What the Data for This Category Looks Like
Service subjects for this category include pollution discharge permit management staff in ecological environment departments, environmental protection teams of polluting enterprises, and third-party environmental protection service institutions. Data sources include the National Pollution Discharge Permit Management Information Platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems. Update frequency is quarterly. Daily processed documents include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Document fields cover limits aligned with industry technical specifications, discharge outlet information, monitoring data, change matters, and more. All fields use unified standardized formats and measurement standards issued by ecological environment departments, with no custom units added.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
The quarterly updated data pattern for this category requires configuring incremental synchronization tasks during deployment. This avoids full data migration that consumes excessive storage and bandwidth. The need to integrate data from multiple sources requires the deployment phase to support diverse interface formats, including those from the National Pollution Discharge Permit Management Information Platform and enterprise ledger systems. Standardized document fields must align with ecological environment management specifications for vector database and knowledge base field mapping. This prevents retrieval failures caused by field mismatches. Frequently processed ledgers and implementation reports have large file sizes, so sufficient disk storage and concurrent connection limits must be configured. During upgrades, the archive path for historical permit copies must be retained to ensure traceability of regulatory data.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–150 connections | Adapts to concurrent demands of quarterly batch data synchronization and daily document retrieval, preventing connection exhaustion |
| `MONGODB_URI` | Exclusive connection string with read-write separation suffix | Stores unstructured documents such as ledger records and implementation reports; separating read and write operations reduces query latency |
| `PG_URL` | Connection address configured for a dedicated pgvector instance | Stores structured data of standardized pollution discharge permit fields, supporting exact retrieval and vector association |
| `REDIS_URL` | Cache configuration with 600-second expiration time | Caches frequently accessed industry technical specifications and permit limit data, reducing repeated queries |
| `STORAGE_S3_ENDPOINT` | Endpoint address adapted to local storage or cloud object storage | Stores large-volume files such as permit copies and monitoring reports, meeting regulatory archive requirements |

## Three Common Configuration Mistakes
- Symptom: Sustained high disk read/write activity occurs after Docker deployment, and disk usage spikes after a single quarter's data synchronization. Cause: Incremental synchronization and `DB_MAX_LINK` were not configured, leading to full repeated pulling of pollution discharge permit data and a large volume of invalid disk I/O operations.
- Symptom: Milvus deployment fails, with logs indicating a database connection configuration error. Cause: Connection parameters for pgvector and other databases were mixed, and a dedicated PG instance was not configured per the structured data requirements of this category.
- Symptom: Historical pollution discharge permit copies cannot be retrieved. Cause: `STORAGE_S3_ENDPOINT` was not configured correctly, resulting in incorrect file storage path mapping and inability to load archived documents.

## How to Verify Proper Configuration
- Run the incremental synchronization task, and confirm disk read/write volume matches expected levels with no sustained high usage.
- Call the knowledge base retrieval interface, input keywords for pollution discharge permit limits, and verify returned results include corresponding document fields.
- Access the storage path, and confirm that permit copy files can be read and downloaded normally.
- Review database connection logs, and confirm there are no frequent connection timeout or disconnection errors.
