# Document and Material Drafting for Government Service Item Catalog and Service Guide Maintenance: Workflow Orchestration
This document is compatible with FastGPT v4.17.0.

## What the data for this category looks like
Data for this category primarily comes from the national basic catalog of government service items, administrative licensing item list, and local government service item database. Daily maintained documents include the basic government service item catalog, implementation list, service guide, standard material directory, flowchart, and frequently asked questions. The data update frequency is once per month, requiring synchronization with the latest upper-level catalog and sorting out local implementation details. Document fields include item unique identifier, implementing entity, acceptance conditions, application material details, service process nodes, and more. The number of materials associated with a single item and the length of documents vary significantly.

## What constraints these characteristics bring to the workflow orchestration link
The official attribute of data sources requires the workflow to include a built-in compliance check link, to ensure generated documents align with the caliber of upper-level catalogs. The monthly update frequency requires the workflow to support scheduled trigger or on-demand trigger batch maintenance modes. The feature of multiple types of associated documents requires the workflow to configure cross-node `variables` transmission, to realize linked updates of basic item information, service guides, and application materials. The requirement for field verification requires embedding judge nodes in the workflow to conduct integrity checks on required fields, avoiding empty values or content with format errors. At the same time, since maintenance work does not involve individual service cases, the workflow must isolate single-user interaction logic and focus on batch updates of the rule base.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Judge trigger condition | Trigger based on Boolean type status in `variables` | Need to control process flow based on global variable item verification results |
| Multimodal node image recognition switch | Enable, set confidence threshold to 0.7–0.9 based on actual measurement | Adapt to image text extraction requirements for flowcharts and material examples in service guides |
| Tool call output control | Turn off front-end display of tool call results | Only retain verification and update results for internal maintenance, no need to expose tool execution details |
| File parsing timeout | 600 seconds | A single service guide document usually includes multiple process and material descriptions, requiring sufficient time for full parsing |
| Global variable binding | Bind `nodeId` as the context of the current item node | Ensure multi-link workflows for the same item share unified item identifiers and associated data |
| Batch update batch size | First 20 items per batch | Match the total number of items updated each month, avoiding overload from single requests |

## Three common errors
- Phenomenon: "Unable to provide image content" is returned after calling the multimodal node. Cause: The node's image recognition switch was not enabled correctly, or the uploaded image was not associated with the corresponding workflow node.
- Phenomenon: Tool call results are still displayed on the front-end interface. Cause: The tool call output control item was not configured correctly, or a tool call end node was added incorrectly but not bound to the corresponding execution link.
- Phenomenon: The file parsing node returns a 404 error after server deployment. Cause: No server-side file storage path mapping was configured, or the front-end uploaded file path was not synchronized to the workflow's `variables`.

## How to confirm the configuration is correct
- Manually trigger the workflow for a single government service item, check whether the verification status in the global `variables` correctly triggers the branch flow of the judge node.
- Upload a test image containing a flowchart to the multimodal node, confirm that the extracted image text content can be normally written to the corresponding document field.
- After configuring the tool call link, check the workflow execution log to confirm that the front-end interface does not display the original output content of the tool call.
- Upload a test file in the server deployment environment, confirm that the file parsing node can normally read the file content without 404-level errors.

The values provided here are common starting points and should be measured against the reader's own samples.
