# Document and Material Drafting for Government Service Item Catalog and Service Guide Maintenance: Tool Calling and Plugins

## What the Data for This Category Looks Like
The core data for this category consists of structured documents related to government services. Main sources include the national basic catalog of government service items, administrative licensing item list, power and responsibility list, and local government service item databases. Daily maintained documents cover basic government service item catalogs, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. The data update frequency is once per month. Document fields include government-specific content such as item codes, implementing entities, acceptance conditions, and application material details. Processing must be split by single item or batch items.

## Constraints Imposed on Tool Calling and Plugins
The multiple sources of data require tool calling to adapt to government data sources in different formats, to avoid extraction failures caused by format incompatibility. The monthly update frequency means tool calling must be configured with scheduled synchronization tasks, pulling incremental or full data on a monthly cycle, without frequent real-time full pulls. The diversity of document types requires plugins to support field mapping rules for different documents, for example, extracting application materials from service guides and extracting item codes from catalogs. The complexity of government-specific fields requires tool calling functions to preset parsing logic for corresponding fields, to ensure extracted content complies with government service specification requirements.

## Three Common Misconfigurations
- Symptom: Tool calling returns empty results, or extracted application material fields are missing. Cause: Parsing rules for `functionCall` are not configured for the specific fields of government service guides, causing plugins to fail to recognize target fields.
- Symptom: Timeout errors occur after calling, or response delays exceed expectations. Cause: Single call data volume exceeds the interface's carrying limit, and no reasonable single call data limit is configured.
- Symptom: Tool calling and knowledge base search cannot be linked, and missing information in item catalogs cannot be supplemented via the knowledge base. Cause: Knowledge base recall results are not bound to the context parameters of tool calling, so no association is established between the two.

## How to Verify Successful Configuration
- Manually trigger a tool call, and check whether extracted fields such as item codes and acceptance conditions match the source documents.
- View the execution logs of scheduled synchronization tasks, confirm that the monthly 1st synchronization task completed successfully with no errors.
- Test the linkage process between tool calling and the knowledge base, confirm that knowledge base recalled content can be correctly referenced by tool calling.
- Simulate a call timeout scenario, confirm that the configured timeout threshold triggers a reasonable retry or alert mechanism.
