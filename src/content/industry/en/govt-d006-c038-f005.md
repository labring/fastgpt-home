# Document and Material Drafting for Government Procurement Projects: Tool Calling and Plugins
This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Data sources for this category include China Government Procurement Network, local government procurement websites, the fiscal integration system, the purchaser’s budget system, and supplier credit records. The update frequency is daily. Daily processed documents cover the entire procurement lifecycle, including procurement requirements, procurement plans, bidding documents, bid submissions, bid evaluation reports, winning bid announcements, procurement contracts, and responses to procurement objections. Most fields follow statutory government procurement formats, and include core content such as project number, budget amount, supplier qualification requirements, and scoring rules.

## What constraints this category of characteristics imposes on the "tool calling and plugins" link
This category of data is updated daily and sourced from multiple dispersed systems. This requires the tool calling link to be configured with scheduled data source synchronization logic to adapt to format differences across multiple systems. Document types cover the entire statutory procurement workflow, and each document type has dedicated field requirements. Tools must support calling corresponding templates to generate content based on document type. Since errors can lead to bid invalidation or regulatory penalties, a dual verification link must be added for tool calling results. The setup must also adapt to exclusive government procurement regulatory rules, and avoid using general bidding plugin logic.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` and bind to the exclusive government procurement plugin set | Automatically match procurement document types to call corresponding tools, adapting to various procurement scenarios |
| `functionCall` | Enabled and limited to only calling procurement document generation and qualification verification plugins | Restrict the scope of tool calls to meet compliance requirements for government procurement business |
| Single tool call timeout | 600 seconds | Covers time-consuming scenarios such as large bidding document generation and multi-supplier credit verification |
| Data source synchronization cycle | 2:00 AM daily | Matches the daily update rhythm of this category of data, ensuring the latest data is used for tool calls |
| Tool result verification switch | Enabled | Avoids generating procurement documents that do not comply with statutory formats, reducing error risks |

## Three common mistakes
- Phenomenon: After configuring specified response rules, the tool still automatically calls the large model to generate non-specified content. Cause: The trigger conditions for `functionCall` are not correctly limited, resulting in a conflict between the tool calling logic and the specified response rules.
- Phenomenon: The number of supplier credit records returned after tool calling does not match the actual data source. Cause: No recall rule adapted to government procurement credit data is configured, causing the called plugin to fail to correctly match the data source fields of this category.
- Phenomenon: GPU memory usage quickly grows to 6-7G after calling the reranking model. Cause: The model call batch size is not adjusted for the single-batch data volume of government procurement projects, and the single-call data volume exceeds the memory capacity limit.

## How to confirm the configuration is correct
- Trigger a tool call for procurement requirement document generation, and check if the called plugin is the exclusive government procurement document generation tool.
- View the tool call log to confirm that the value of the `toolChoice` parameter matches the configured setting, with no abnormal automatic calling behavior.
- Simulate a supplier qualification verification scenario, and check if the tool call result includes the credit record fields required for this category.
- Test the timeout scenario to confirm that the tool call completes within the set duration, with no timeout errors.
