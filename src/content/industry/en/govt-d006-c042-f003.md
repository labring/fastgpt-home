# Document and Material Drafting for Legal Compliance and Major Risk Management: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
The data for this category primarily comes from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. The update frequency is monthly. Commonly generated and used documents include compliance risk lists, contract legal review opinions, legal opinions on major matters, compliance review forms, and violation report investigation results. Data fields cover compliance risk levels, contract clause compliance, violation details, handling suggestions, and more. Fields and units are adjusted flexibly based on document type, with no unified fixed standards.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Monthly updated data requires the knowledge base sync cycle to match the update rhythm, to avoid using expired compliance clauses. Differences in document formats and fields across multiple document types require prompt engineering to preset adaptation rules for different scenarios, distinguishing tasks such as contract review, compliance list organization, and violation report drafting. Multiple data sources require associating corresponding knowledge base sets during dialogue to ensure retrieved content matches the current task. The risk identification and review links in the business process take a long time; multi-turn dialogue must gradually guide users to supplement necessary information, reduce information omissions in initial prompts, and retain conversation context to track review progress.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single search limit | Top 3–5 results | Compliance-related documents are professional and lengthy; excessive search results increase context processing pressure, so prioritize highly relevant content |
| Maximum context length | 8000–12000 token | Compliance documents contain numerous professional clauses, historical review records, and regulatory content; sufficient context must be retained to ensure logical coherence |
| `variables` | Preset compliance scenario variables, such as contract type, risk level | Adapt prompt engineering calls for different legal tasks, enabling quick switching between scenarios such as contract review and compliance report drafting |
| `chatId` | Bind exclusive session ID | Record review progress and user-supplemented information during multi-turn dialogue, ensuring context is not lost |
| `messages` | Retain the most recent 10–15 dialogue turns | Multi-turn dialogue for compliance review typically requires tracking supplemented risk information; retaining an appropriate amount of historical context ensures logical coherence |
| Query optimization | Enabled | There are many legal terms; optimization improves the accuracy of knowledge base retrieval and term matching |

## Three Common Misconfigurations
- Configuring a database connection plugin results in an error. Symptoms include a configuration failure prompt popping up on the interface or an interface call error. The cause is failure to correctly bind compliance-related data sources such as enterprise contract management systems and compliance risk databases to corresponding knowledge base sets, or failure to configure permissions to cover the corresponding data interfaces.
- Clicking the copy button in Google Chrome prompts that copying failed, and the generated Markdown content has no line breaks. Symptoms include no line breaks in copied text, and the browser pops up a window for manually selecting text. The cause is failure to enable the Markdown format rendering switch for conversation content, causing line breaks to not be parsed correctly.
- Unable to set the temperature parameter after switching to variable reference mode. Symptoms include no temperature setting button on the configuration page. The cause is that the variable reference configuration page in FastGPT v4.17.0 does not display the temperature setting item synchronously; the temperature parameter must be preset via the global prompt template.

## How to Verify Successful Configuration
- Initiate a simulated compliance review dialogue, input "Please review the compliance of this procurement contract", and check whether the retrieval results come from the preset compliance knowledge base set.
- Enable multi-turn dialogue, save the `chatId`, exit the session, and re-enter the session to confirm that historical conversation content and user-supplemented information are correctly retained.
- Switch to variable reference mode, check whether the temperature parameter can be configured via the global prompt template, or verify that preset variables load normally.
- Copy the document content generated in the dialogue, paste it into a plain text editor, and confirm that line breaks are displayed normally with no format errors.
