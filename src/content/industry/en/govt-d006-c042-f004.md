# Document and Material Drafting for Legal Compliance and Major Risk Management: Workflow Orchestration

## What This Category of Data Looks Like
Data for this category comes from enterprise contract management systems, compliance risk databases, laws and regulations databases, case management systems, and reporting platforms. The update frequency is monthly. Daily generated documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation reports. Document structures typically include fields such as subject of the matter, core content, compliance basis, and handling opinions. There are no fixed unified units for fields, and adjustments are made based on the specific document type.

## Constraints Imposed by These Characteristics on the "Workflow Orchestration" Link
Decentralized data sources require workflows to configure multiple data source call nodes, supporting operations such as pulling contract texts from contract management systems and retrieving risk lists from compliance risk databases. Monthly update frequency requires workflows to configure scheduled sync tasks to ensure laws, regulations and risk data in the knowledge base are up to date. Demand for generating multiple types of documents requires workflows to support configuring distinct generation rules and verification logic for each document type. Since errors carry major legal risks, workflows must add pre-verification nodes to check the integrity of input business data, preventing compliance review errors caused by missing data.

## How to Set Configurations

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Form input node default value | Reference global business variables in `variables` | Reuse fixed data such as compliance matter numbers and business subject names already maintained by the enterprise, reduce repeated input |
| Node trigger rule | Bind processing logic for the corresponding document type by `nodeId` | Ensure exclusive workflow nodes are called for different types of compliance documents, avoid mixed logic |
| Knowledge base call scope | Restrict to the compliance knowledge base of the corresponding business line | Filter irrelevant laws, regulations and risk data, improve review accuracy |
| MCP call node timeout setting | 600 seconds | Generating compliance documents requires cross-system calls of multiple types of data, which takes a long time |
| Single knowledge base recall count | Top 5 entries | Compliance review requires accurate matching of core regulatory basis, too many entries will increase processing burden |
| Document upload supported formats | Cover PDF, Word, TXT, Excel | Adapt to common document formats such as daily compliance review forms and violation report investigation reports |

## Three Common Misconfigurations
- When configuring default values for form input nodes, the fields displayed on the interface are empty. The cause is failure to correctly reference global variables in `variables`, or the variable name does not match the configuration rules.
- Tool call and MCP call split flow logic is mixed up, and trigger node execution order is incorrect. The cause is failure to configure precise split flow trigger conditions by document type, leading to mixed processing of cross-type data.
- Workflow execution is terminated due to timeout. The cause is failure to adjust the timeout setting of the MCP call node, with cross-system data calls required for generating compliance documents not completed within the default time limit.

## How to Confirm the Configuration Is Correct
- Start a test workflow, input preset compliance matter data, check whether the form input node automatically loads the default values of global variables.
- Upload different types of compliance documents, verify whether the workflow triggers the corresponding generation and review nodes according to the document type.
- Call the MCP node to retrieve external system data, confirm that the timeout setting covers the time required for normal data retrieval.
- Upload documents of different formats such as compliance review forms and violation report investigation reports, verify that the upload function correctly recognizes and loads the file content.
