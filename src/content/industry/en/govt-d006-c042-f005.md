# Document and Material Drafting for Legal Compliance and Major Risk Management: Tool Calling and Plugins

## What data looks like for this category
Data for this category comes from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. The update frequency is monthly. Commonly processed documents include compliance risk lists, legal review opinions for contracts, legal opinions on major matters, compliance review forms, and violation report investigation reports. Most documents contain fields such as compliance clauses, risk levels, involved parties, and handling suggestions. There is no unified fixed format, and some documents require cross-module data association across multiple systems.

## Constraints on tool calling and plugin workflows from these characteristics
Monthly updated data requires plugins to support regular permission synchronization to avoid using expired compliance clauses or cases. Documents associated across systems require plugins to have multi-source data pulling capabilities, and compatibility with interface formats of different systems. Documents without unified formats require plugins to support unstructured text parsing, while also identifying key fields such as risk levels and involved parties in the documents. Tool calls related to compliance may trigger major legal risks if they fail, so tool calls must include a result verification mechanism to avoid generating documents that do not meet compliance requirements.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-plugin calling scenarios, automatically matching compliance document parsing and data pulling requirements |
| Plugin timeout threshold | `600 seconds` | Compliance document parsing requires pulling cross-module data from multiple systems, with longer duration requirements than general scenarios |
| Single plugin call return entries | `Top 3` | Compliance review requires accurate matching of risk cases; too many entries will interfere with key risk identification |
| Document parsing plugin | Determined based on actual testing | Must be compatible with existing enterprise document parsing tools, supporting flexible replacement of configurations |
| `functionCall` | `strict: true` | Ensures generated compliance documents strictly match preset compliance fields and format requirements |
| Context window size | `8000–12000 token` | Compliance documents need to associate multiple historical review documents; sufficient context ensures logical coherence |

## Three common configuration mistakes
- Phenomenon: An empty parsing result is returned when calling the document parsing plugin to process uploaded compliance documents. Cause: The permission connection between the plugin and the enterprise's existing document system is not configured, or the uploaded document format exceeds the plugin's supported range.
- Phenomenon: No associated knowledge base file list is returned when generating compliance documents via API calls. Cause: The file traceability configuration for tool calls is not enabled, or the data source recording function is not enabled in the plugin.
- Phenomenon: The field recognition accuracy of compliance documents decreases after replacing the document parsing tool. Cause: The plugin's field mapping configuration is not adjusted, and the output format of the new plugin does not match the field requirements of the original system.

## How to confirm the configuration is complete
- Upload a compliance risk list document, call the configured plugin, and check if the parsing result includes preset key fields such as risk levels and involved parties.
- Initiate a tool call for compliance document drafting, and verify that the returned result is associated with the preset compliance knowledge base files.
- After replacing the document parsing plugin, compare the parsing results of the new and old plugins for the same compliance document, confirming that the core field recognition logic is consistent.
- Test the configuration effects of the `toolChoice` and `functionCall` parameters, confirming that the system automatically calls plugins and generates compliance documents that meet format requirements, and that the total duration of a single call does not exceed `600 seconds`.

The values provided are common starting points and should be measured against the reader's own samples.
