# Document and Material Drafting for Legal Compliance and Major Risk Management: Model Access and Configuration

## What data looks like for this category
Data for this category comes from enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms. Daily documents include compliance risk lists, legal review opinions for contracts, legal opinions on major matters, compliance review forms, and violation report investigation results. Data is updated once per month. Documents contain a mix of structured and unstructured content, including business scenario descriptions, compliance bases, risk reminders, and handling suggestions. There are no fixed standardized units, and fields focus on compliance-related content for business operations.

## What constraints these characteristics impose on model access and configuration
Data sources are scattered across multiple internal systems. Model access must adapt to export formats from different systems, so adaptation rules for multi-source data access must be configured. The monthly update frequency requires configuring data sync trigger logic to reserve space for monthly updates in the access link. Documents contain high-risk associated content, so unrelated information must be restricted from entering the context. Therefore, `maxContext` must match the average length of documents in this category to avoid truncating critical compliance bases and risk analysis. Errors in compliance documents have serious consequences, so configuration must ensure retrieval and matching rules to avoid missing key compliance clauses. Documents contain a mix of structured and unstructured content, so appropriate chunking rules must be configured to adapt to mixed formats, ensuring parsed content can be effectively recognized by the model. ## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the average length of compliance documents in this category, avoiding truncation of critical compliance bases and risk analysis content |
| `maxTokens` | 2000–3000 token | Meets the output length requirements for compliance document drafting, covering the output needs of complete review opinions and risk reminders |
| `quoteMaxToken` | 1000–1500 token | Ensures the total length of referenced compliance databases and contract clauses, retaining sufficient details of compliance bases |
| `temperature` | 0.1–0.3 | Reduces randomness in generated content, ensuring the rigor of compliance outputs and meeting business compliance requirements |
| `AIPROXY_API_ENDPOINT` | API address deployed within the enterprise | Adapts to the compliance requirement of not allowing domestic public sector and state-owned enterprise data to leave the country, ensuring data security |
| `toolChoice` | `none` | Avoids calling external tools, ensuring all generated content is strictly based on internal compliance data |

## Three common configuration mistakes
- Symptom: The model cannot read uploaded compliance documents, or no response is returned after upload. Cause: Adaptation rules for document parsing nodes are not configured, or `maxContext` is set too small, causing document content to be truncated and uploaded files cannot be fully parsed.
- Symptom: The knowledge base matching result only returns 1 text block, and cannot return multiple text blocks. Cause: The reference length limit for `quoteMaxToken` is not correctly configured, or the number of returned multi-text blocks is not set in the retrieval matching rules, resulting in only a single matching entry being returned.
- Symptom: After deploying a model locally, uploading attachments in the chat window has no response. Cause: `AIPROXY_API_ENDPOINT` is not configured with the correct address for the local model, or access timeout parameters are not adapted to the latency of local deployment, causing requests to fail to send normally.

## How to confirm configuration is complete
- Upload a compliance risk list, check if the model can extract risk levels and trigger scenarios, and verify that the parsed content matches the original document.
- Trigger knowledge base retrieval, check that the number of returned text blocks meets expectations, and verify that it matches the `quoteMaxToken` configuration rules.
- Call the API interface, check that the returned compliance review opinion format conforms to the standard structure of compliance documents, and ensure the content is rigorous.
- Configure a monthly data sync task, check that the data sync logic works normally, and verify that updated compliance data is correctly loaded into the knowledge base.
