# Document Drafting for Legal Compliance and Major Risk Management: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The documents covered in this category include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, violation report investigation reports, and similar materials. Data sources include enterprise contract management systems, compliance risk databases, law and regulation libraries, case management systems, and reporting platforms. The update frequency is monthly. Most documents are structured or semi-structured text, with fields such as risk level, associated business segments, violation clauses, and processing time limits. There is no fixed unified format, and adjustments are made based on specific business scenarios.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
Data collected across multiple systems has inconsistent formats, which increases the difficulty of field mapping during retrieval. Additional configuration of cross-source data alignment rules is required. The monthly update frequency requires the retrieval system to support stable incremental synchronization, without frequent full updates. Documents contain professional fields such as risk level and violation clauses, so retrieval must match professional compliance terminology, rather than relying solely on basic keyword matching. Since errors may result in major legal risks, retrieval results must ensure that core compliance clauses are not missed, while avoiding irrelevant content interfering with the review process.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Semantic similarity threshold for matching compliance professional text, balances recall completeness and result relevance, and avoids missing high-risk associated content |
| `limit` | `Top 8–12 results` | Legal documents are mostly long text, retrieving an appropriate number of results at one time balances review efficiency and information comprehensiveness, and avoids overloading manual screening due to too many results |
| `searchMode` | `Semantic Retrieval` | Fits the professional terminology and complex semantic logic of compliance documents, and is more likely to identify hidden compliance risk-related content than basic keyword retrieval |
| `usingReRank` | `Enabled` | Performs secondary sorting on retrieved results, prioritizes returning compliance clauses or historical opinions most relevant to the current document drafting scenario, and improves result accuracy |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands retrieval terms to cover synonyms and near-synonyms in the compliance field, for example expanding "contract review" to "contract legal review", improving recall coverage |
| `collectionIds` | `Bind corresponding datasets by business module` | Only retrieves compliance data associated with the current business scenario, for example only calling the contract management system dataset for contract drafting scenarios, reducing interference from irrelevant data |

## Three Common Misconfigurations
- A `text index required for $text query` error is returned when calling the API to trigger knowledge base retrieval. The cause is that a full-text index was not created for the corresponding dataset in the FastGPT v4.17.0 backend, or the index configuration was not synchronized after upgrading the version.
- When configuring a knowledge base search node in a workflow, the referenced dynamic variable is not correctly bound to dataset permissions, resulting in empty retrieval results or returning irrelevant content. The cause is that the valid value range for the dataset ID was not configured in the workflow variables.
- Single retrieval time exceeds 4 seconds. The cause is that the `usingReRank` configuration is not enabled, or the number of retrieved results is set too high, causing the system to process excessive redundant retrieval result data.

## How to Verify Correct Configuration
- Manually trigger a knowledge base retrieval, check the similarity distribution of returned results, and confirm whether it falls within the preset threshold interval.
- Check the source dataset of retrieval results, confirm that only compliance documents of the current business module are included, and no data from irrelevant business segments are mixed in.
- Test the dataset ID bound by the dynamic variable, confirm that normal retrieval results of the corresponding dataset can be returned after passing a valid ID.
- Record the single retrieval time, compare it with the preset threshold, and confirm that no obvious timeout occurs.

The values provided are common starting points and should be measured against the reader's own samples.
