# Document and Material Drafting for Legal Compliance and Major Risk Management: Deployment and Upgrade

## What the data for this category looks like
This category of data primarily comes from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. The update frequency is once per month. Daily generated documents include compliance risk lists, contract legal review opinions, major matter legal opinions, compliance review forms, and violation report investigation reports. Documents usually contain risk identification content, compliance judgment bases, and handling suggestions, and are linked to the full process of internal enterprise operations and compliance management.

## What constraints these characteristics bring to the deployment and upgrade phase
Data sources for this category are scattered and have fixed update cycles. During deployment, multi-data source connection logic must be configured to ensure that data from contracts, compliance risks, laws and regulations can be synchronously accessed into the knowledge base. Document types cover structured tables and long-text legal files. During upgrade, parsing rules for different document formats must be adapted to avoid content truncation or parsing errors. Since errors in compliance documents can lead to major legal risks, high-availability storage and failure retry mechanisms must be prioritized during deployment, while ensuring that knowledge base updates do not affect online services. The configuration logic for intranet deployment has been optimized in the current FastGPT v4.17.0 version, and deployment must be completed in accordance with the parameter requirements of this version.

## How to Set the Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Legal compliance data is accessed from multiple systems, so concurrent access stability must be ensured. This range balances resource usage and access efficiency, and is calibrated based on actual testing |
| `STORAGE_S3_ENDPOINT` | Intranet object storage node address | Deployed on intranet servers, the access endpoint for internal enterprise compliance document storage must be specified to ensure data storage security |
| `REDIS_URL` | Intranet Redis service address, port 6379 | Used to cache frequently accessed regulatory clauses and compliance templates. Intranet deployment requires specifying internal service addresses to avoid public network exposure risks |
| `FE_DOMAIN` | Enterprise intranet access domain name | Used to configure the access address of the front-end service, adapting to intranet usage scenarios and ensuring that the service is only accessible within the enterprise |
| `ROOT_KEY` | Randomly generated 32-character string | Used for system administrator permission verification to ensure the security of background configuration, and must comply with internal enterprise key management specifications |
| `MONGODB_URI` | Intranet MongoDB service connection address | Stores vector data and document metadata of the compliance knowledge base. Intranet deployment requires specifying internal database addresses to ensure data privacy |

## Three Common Errors
- Symptom: After uploading an XLSX-format compliance review form, the table content cannot be parsed correctly, and only the file name is displayed in the knowledge base. Cause: Document parsing rules adapted for structured tables are not configured. The default parsing logic only extracts plain text content and does not recognize the association relationship between table cells.
- Symptom: The knowledge base chunk size is set to 5000 tokens, and the citation limit is set to 1500 tokens, but the retrieval results still return the complete chunk content. Cause: The chunk configuration and context citation filtering logic are not correctly associated. The system does not truncate the retrieved chunks.
- Symptom: Only the FastGPT container image is upgraded, and the dependent database configuration is not updated synchronously, resulting in service startup failure. Cause: Version compatibility rules are not followed. New versions of FastGPT may have updated requirements for connection parameters such as `MONGODB_URI` or `PG_URL`. Upgrading only the image will cause configuration mismatches.

## How to Verify the Configuration is Complete
- Log in to the data source management page in the system backend, and confirm that the connection status of configured systems such as the contract management system and compliance risk database is normal.
- Upload a compliance review form XLSX file, wait for the parsing to complete, and check whether the content of this document in the knowledge base includes complete table cell information.
- Simulate a search for keywords related to compliance risks, and check whether the reference length of the returned results meets the configured citation limit requirements.
- Execute a manual knowledge base update task, confirm that the update task can be completed normally without error logs.
