# Document and Material Drafting for Special Equipment Safety Supervision: Workflow Orchestration

## Data Overview for This Category
Data for this category originates from special equipment safety supervision systems, inspection and testing institution systems, user unit ledgers, and operator certificate databases. Data is updated monthly. Commonly used documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Documents use unique equipment numbers as the core associated field, and include fields such as inspection cycle, maintenance date, hidden danger level, and certificate validity period. Units include sets, times, days, levels, and other standard units.

## Constraints on Workflow Orchestration
Cross-system data sources require workflows to support cross-node variable transfer, ensuring unified equipment ledger and inspection data can be called across different links. Monthly update frequency requires workflows to be configured with a scheduled trigger mechanism, to avoid document errors caused by expired data. Diverse document types and differentiated fields require workflows to support variable binding and verification logic for different documents. For example, verify the inspection cycle field for periodic inspection reports, and verify the certificate validity period for operator certificates. The most time-consuming verification link requires workflows to support cyclic verification logic, repeatedly checking equipment registration, inspection cycle, maintenance qualifications and other information until verification passes. Regulatory objects for this category include high-risk equipment such as elevators, boilers, and pressure vessels. Errors directly relate to equipment shutdown, administrative penalties, or even accidents, so workflows must be configured with failure retry and exception alert mechanisms, to avoid regulatory process interruptions caused by node execution errors.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Top 10 entries | Regulatory documents need to associate multiple equipment ledgers and inspection data. The top 10 entries can cover core associated information and avoid context overload |
| Cyclic Trigger Condition | Branch based on `variables` verification results | Aligns with the cyclic verification logic of special equipment supervision, allowing termination of the cycle based on qualification and cycle verification results |
| Node Context Entries | 30 entries | Tested on FastGPT v4.17.0, matches the text length of a single special equipment inspection report, ensuring the large model can fully read core information |
| File Import Method | Direct import | Avoids loss of format metadata from special equipment documents during default text parsing, ensuring the large model can identify core fields such as inspection cycle and equipment model |
| Failure Retry Count | 2 times | Addresses unstable cross-system call scenarios, avoiding resource waste caused by repeated triggering of regulatory processes |
| Timeout Threshold | 600 seconds | Matches the average time required to pull cross-system data, avoiding workflow interruptions caused by excessive waiting time |
| Node Binding | Bind `nodeId` and upstream variables | Ensures each workflow node executes in the correct sequence, avoiding errors in cross-node data transfer |

## Three Common Configuration Mistakes
- Phenomenon: The workflow cyclic node does not terminate based on verification results, and logs show the branch logic was not triggered. Cause: The verification result was not bound to the `nodeId` parameter, causing the cycle to fail to correctly judge the termination condition and enter an invalid cycle.
- Phenomenon: The conversation details only show 2 context entries, even when the 30-context upper limit is configured. Cause: The context variable of the upstream equipment ledger was not bound to the workflow node, and only the default single-round conversation context was called, resulting in unloaded associated data.
- Phenomenon: Execution order is chaotic after adding multiple code running components to the workflow. Cause: No clear trigger dependency was configured for each code component, causing the sequence to not meet the sequential requirements of the regulatory process.

## How to Verify Proper Configuration
- Trigger the workflow and enter a simulated special equipment number, check whether the cyclic node terminates after qualification verification passes, and trigger the regeneration node when verification fails.
- View the conversation details of the workflow, confirm that the number of displayed context entries matches the configured maximum context setting, and that the associated equipment ledger and inspection data have been correctly loaded.
- Upload a periodic inspection report, check whether the output content of the large model includes core fields such as inspection cycle and equipment model, and confirm that no parsing loss has occurred.
- Test adding two code running components, confirm that each component executes in the configured trigger sequence, and no sequence errors occur.
