# Document and Material Drafting for Environmental Law Enforcement and Monitoring Supervision: HTTP Interfaces and External Systems

## What data for this category looks like
This category’s data comes from online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. The update frequency is daily. Commonly generated documents include on-site inspection records, sampling records, monitoring reports, order correction decisions, and administrative penalty decisions. Each document follows a fixed field structure. For example, a monitoring report must include fields such as monitoring point number, pollutant concentration value, and sampling time. Supported units include mg/m³, mg/L, hours, and others. The time format uses the uniform standard YYYY-MM-DD HH:mm:ss.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Multi-data source docking requires interfaces to adapt to the call formats of different systems. Different `Authorization` parameters must be configured separately. The daily data update frequency limits how often interfaces can be called, to avoid overusing business system resources. The fixed field structure requires that the `responseData` returned by the interface must exactly match the required fields of the law enforcement document. If not, the generated law enforcement document will lack key evidence. The accuracy of law enforcement data directly affects the legality of penalties, so field verification must be completed at the interface layer to block invalid data from entering the system.

## How to set configurations
| Configuration Item | Recommended Configuration | Rationale |
| --- | --- | --- |
| API call frequency | 1 time per hour (calibrated based on actual testing) | Adapts to the daily data update rhythm and avoids high-frequency calls occupying law enforcement system resources |
| Authorization method | Use `Authorization` Bearer token | Complies with standard authorization specifications for ecological environment department systems |
| Timeout period | 300 seconds | Matches the average response time for batch pulling law enforcement data |
| Field mapping rules | Map `responseData` to the 12 fixed fields of the law enforcement document | Meets the fixed structure requirements for documents in this category |
| Variable configuration | Bind law enforcement personnel and sampling point parameters returned by the law enforcement system in `variables` | Enable automatic filling of document fields |
| Retry mechanism | Up to 2 retries, with a 60-second interval | Avoids duplicate generation of law enforcement documents caused by repeated submission of law enforcement data |

## Three common mistakes
- Symptom: The interface returns an empty `responseData` field, making it impossible to extract valid monitoring data. Cause: Field mapping rules are not configured correctly, and fields from automatic pollution source monitoring data are not bound to law enforcement document fields.
- Symptom: The interface call returns a 504 timeout status code. Cause: A reasonable timeout period is not set, and a batch data pull request is initiated during peak business hours.
- Symptom: The generated order correction decision document lacks the law enforcement time field. Cause: The law enforcement time parameter returned by the law enforcement system is not configured in `variables`, resulting in incorrect variable filling.

## How to confirm the configuration is complete
- Call the test interface and check whether `responseData` includes required fields such as monitoring point number and pollutant concentration value.
- Verify the validity of the `Authorization` token and confirm that daily data from the online monitoring platform can be pulled normally.
- Configure the scheduled task for FastGPT v4.17.0 and confirm that the data pull and document generation process is automatically triggered every early morning.
- Simulate submitting a single piece of law enforcement data and check whether the fields of the generated on-site inspection record completely match the preset rules.
