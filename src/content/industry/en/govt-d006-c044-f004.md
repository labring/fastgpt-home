# Document and Material Drafting for Environmental Law Enforcement and Monitoring Supervision: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. The update frequency is daily. Daily generated documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Fields cover law enforcement time, monitoring point number, pollutant concentration value, rectification requirements, penalty basis, and more. Some documents must match legal formats and fixed field order.

## What constraints these characteristics impose on the "workflow orchestration" link
The data sources for this category are scattered and updated daily, requiring the workflow to support integration with multiple external systems to pull real-time data. Daily documents must strictly match fixed formats and fields, requiring the workflow to include field verification nodes to ensure complete information. The core time-consuming links are multi-source data comparison, over-standard judgment, and law enforcement document generation, requiring the workflow to split long-time nodes to avoid execution timeouts. It must also support uploading third-party test reports and other files and passing parameters, to meet the requirements of law enforcement evidence archiving.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Include structured fields for law enforcement time, monitoring points, and pollutant concentrations | Match the required fields of core law enforcement documents for this category, ensuring generated content complies with format requirements |
| Timeout Settings | 1200–1800 seconds | Cover the longest time-consuming scenarios of multi-source data comparison and document generation, adapting to the basic execution duration limit of FastGPT v4.17.0 |
| File Upload Node | Allow uploading PDF and CSV format files, with a single file limit of 1000 MB | Match the format and size requirements of common archived files such as third-party test reports and law enforcement images |
| Single Call Data Count | Top 10 entries | Match the single data return limit of the ecological environment law enforcement system, avoiding interface overload |
| Trigger Node | Trigger after form submission | Ensure all law enforcement information is fully filled before starting the workflow, avoiding missing key fields |
| `nodeId` | Bind the node ID of the online monitoring platform data interface | Pull real-time pollution source monitoring data updated on the same day, meeting the timeliness requirements of law enforcement data |

## Three common mistakes
- Workflow execution timeout, with the interface showing abnormal execution status or returning a 504 status code. The cause is that long-time nodes such as multi-source data comparison and document generation are not split, and the overall execution duration exceeds the configured threshold.
- Uploaded test reports cannot be passed as parameters into the workflow, shown as empty file fields in subsequent document generation nodes. The cause is that the file variable transfer permission is not enabled in the workflow configuration.
- The workflow is triggered before the form is fully filled, resulting in missing required fields in the generated law enforcement document. The cause is that the form submission trigger node is not configured, and the change event of the input component is mistakenly used as the trigger condition.

## How to confirm the configuration is correct
- Trigger a test workflow, check the `variables` field in the execution log, confirm that it includes preset structured fields such as law enforcement time and monitoring points.
- Upload a third-party test report file that meets the format requirements, confirm that subsequent nodes can read the file content and call it as a parameter.
- Test that the workflow cannot be triggered when the form is not fully filled.
- Check the workflow timeout settings, confirm that the threshold matches the longest time-consuming scenario of this category.

The values provided are common starting points and should be measured against the reader's own samples.
