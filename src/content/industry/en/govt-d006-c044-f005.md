# Document and Material Drafting for Environmental Law Enforcement and Monitoring Supervision: Tool Calling and Plugins

## What the data for this category looks like
The data for this category mainly comes from online monitoring platforms, automatic pollution source monitoring data, ecological and environmental law enforcement systems, and third-party test reports. The update frequency is daily. Daily generated documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. On-site inspection records include fields such as inspection location, inspection time, and working condition parameters. Sampling records include sampling location number, sampling time, and pollutant sample information. Monitoring reports include pollutant concentration values and corresponding testing units. All types of law enforcement documents include standardized fields such as illegal fact descriptions and rectification requirements. Data units include commonly used environmental monitoring units such as mg/m³ and tons.

## What constraints these characteristics impose on the "tool calling and plugins" link
Dispersed data sources with daily updates require tool calling to adapt to interface permissions and data formats of multiple types of systems. This prevents document generation errors caused by incompatible data sources. The field structures of different documents vary significantly. Tool calling must match corresponding data extraction rules based on document type, and cannot uniformly adapt to all documents. Real-time synchronized daily update data requires tool calling to configure scheduled trigger logic. This avoids generating law enforcement documents using expired data. Data association logic is complex. It requires simultaneous matching of online monitoring data and on-site law enforcement records. Tool calling parameter configuration must cover multi-source data association verification. Otherwise, situations with insufficient evidence may occur.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically match different types of law enforcement data and document generation requirements, and adapt to multi-source data calling logic |
| `functionCall` | Triggered by document type | Call corresponding data extraction and generation functions for different documents such as on-site inspection records and monitoring reports |
| API call timeout setting | `600 seconds` | Pulling historical data from online monitoring platforms and third-party test reports takes a long time. Sufficient synchronization time must be reserved |
| Multimodal data processing switch | Enabled | Adapt to processing requirements for multimodal data such as on-site law enforcement photos and sampling record attachments |
| Model binding rules | Bind plain text data to Qwen2, bind multimodal data to dedicated multimodal models | Differentiate processing for different types of input data, and adapt to business requirements for mixed text and image scenarios in law enforcement |

## Three common misconfigurations
- Phenomenon: Law enforcement data fields returned by API calls are empty. Cause: Plugin permissions for the corresponding ecological and environmental law enforcement system or online monitoring platform are not configured. Required on-site inspection records or monitoring data cannot be pulled.
- Phenomenon: Timeout error occurs after tool calling is triggered, with status code 504. Cause: The set timeout period is shorter than the time required to pull third-party test reports. This causes the call to terminate before data is fully loaded.
- Phenomenon: Multimodal law enforcement photos cannot correctly generate attachment descriptions for corresponding monitoring reports. Cause: Model binding rules for plain text and multimodal data are not configured separately. Multimodal data is assigned to a model that only supports plain text processing.

## How to confirm the configuration is complete
- Manually trigger tool calling. Check whether on-site inspection records or monitoring data from the corresponding data source can be successfully pulled. Confirm that fields are complete and conform to business formats.
- Upload multimodal law enforcement photos and plain text law enforcement text. Test model calling results separately. Confirm that multimodal data is processed by the multimodal model, and plain text data is processed by Qwen2.
- Call the published API interface, pass the specified law enforcement document type parameter. Check whether the returned result matches the corresponding data extraction and generation logic.
- View the tool calling logs in FastGPT v4.17.0. Confirm that the `toolChoice` and `functionCall` parameters take effect according to the configured rules.

The values listed here are common starting points. Adjust them based on your own specific samples and operational requirements.
