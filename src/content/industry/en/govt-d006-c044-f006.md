# Document and Material Drafting for Environmental Law Enforcement and Monitoring Supervision: Citation Source and Traceability

## What the data for this category looks like
Data for this category comes from online monitoring platforms, automatic pollution source monitoring data, ecological and environmental law enforcement systems, and third-party test reports. The update frequency is daily.
Documents produced regularly include on-site inspection records, sampling records, monitoring reports, correction order decisions, and administrative penalty decisions. Each single document contains fixed fields such as monitoring points, pollutant concentration, law enforcement time, sampling personnel, and testing instrument model. Most data formats are a mix of structured tables and structured text.

## What constraints these characteristics impose on the citation source and traceability link
Real-time monitoring data updated daily requires the traceability link to quickly associate the latest law enforcement and monitoring records, to avoid citing expired data.
The mixed multi-source document structure requires precise matching of document types and corresponding data sources during traceability, to prevent confusion between fields from on-site records and third-party test reports.
The presence of fixed fields requires the traceability result to clearly mark the source system, generation time, and testing entity of the corresponding data, to ensure the legality of evidence in law enforcement documents.
The decentralized storage of multi-source data requires the traceability link to establish data association paths across different systems, to ensure that cited monitoring data corresponds one-to-one with on-site inspection records, and avoid evidence disconnection issues.

## How to configure the settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 5 entries | Law enforcement documents for this category need to associate core data sources such as on-site records and monitoring reports. The top 5 entries can cover core evidence and avoid interference from redundant results |
| `quoteMaxToken` | 800–1200 token | The content length of a single core document for law enforcement documents mostly falls within this range, which can fully retain the evidence details of the traced original text |
| `responseData` | Enabled | The original text retrieved from the knowledge base must be directly used as the reply content, to ensure the original evidence validity of law enforcement documents |
| `detail` | Enabled | The traceability result must clearly mark fields such as data source type and generation time, to meet the compliance requirements of law enforcement evidence |
| Maximum Context | Calibrated based on actual testing | Adapt to the mixed multi-source document structure, and avoid retrieval deviation caused by overly long context |

## Three common configuration mistakes
- Generated law enforcement documents fail to associate the retrieved monitoring data. The `responseData` configuration is not enabled, causing the system to not directly call the original content of the knowledge base, and instead generate generalized replies.
- Knowledge base reference variables cannot be selected in workflow nodes. The data output switch is not enabled in the knowledge base configuration, or the workflow node is not bound to the corresponding knowledge base data source.
- The number of retrieval results exceeds the preset range. The single search limit configuration value is set too high, resulting in too many non-core historical data being returned, which interferes with evidence selection for law enforcement documents.

## How to verify successful configuration
- Perform a test draft for on-site inspection records, and check whether the generated content directly reuses the original text of the corresponding document in the knowledge base, with no additional generalized expressions.
- Check the marking information of the traceability result, confirm that it includes fields such as data source system and generation time, which meets the compliance requirements of law enforcement evidence.
- Adjust the single search limit parameter, and verify whether the number of retrieval results matches the configured value.
- View the variable options in the workflow node, confirm that the knowledge base reference variables can be normally selected and called.
