# Document and Material Drafting for Environmental Law Enforcement and Monitoring Supervision: Knowledge Base Retrieval and Recall

## What the data for this category looks like
This category's data comes primarily from ecological and environmental law enforcement systems, automatic pollution source monitoring platforms, and reports submitted by third-party testing institutions. Daily documents include on-site inspection records, sampling records, monitoring reports, correction orders, and administrative penalty decisions. Most individual documents combine structured and semi-structured content, with fields such as inspection points, pollutant concentrations, testing methods, and law enforcement officer signatures. Concentration-related data uses mg/m³ and mg/L as standard units. Data updates occur daily. Online monitoring data is synchronized in real time. Law enforcement documents and testing reports are generated following the same-day completed law enforcement process.

## What constraints these characteristics impose on knowledge base retrieval and recall
Data for this category has multiple sources and updates frequently. Online monitoring data synchronized daily and law enforcement documents generated the same day must be processed separately to prevent recall bias caused by mixing new and old data. Documents include professional testing terminology and structured fields. Differences in semantic weight across fields require prioritizing matching core law enforcement fields during retrieval. Individual documents have strong business relevance. Retrieval of similar materials unrelated to the current law enforcement scenario must be avoided. The daily incremental update data synchronization rhythm must also be adapted to ensure recalled data stays timely. Additionally, differences in data formats across sources cause fluctuations in initial retrieval matching accuracy. Retrieval matching rules must be adjusted to address this.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Filters low-correlation recall results, ensuring only professional documents required for law enforcement scenarios are matched |
| `limit` | `Top 6` | Covers the number of reference documents needed for drafting a single law enforcement document, avoiding context overload |
| `searchMode` | `Semantic Retrieval` | Adapts to semantic matching requirements for professional terminology and structured fields, improving recall accuracy for core fields |
| `usingReRank` | `Enabled` | Re-ranks initial recall results, prioritizing documents strongly related to the current law enforcement scenario |
| `datasetSearchUsingExtensionQuery` | `Disabled` | Prevents extended queries from introducing irrelevant historical data, ensuring recall results focus on the current law enforcement scenario |
| `collectionIds` | `Configured by data source grouping` | Distinguishes three dataset types: online monitoring data, law enforcement system documents, and third-party testing reports, enabling precise recall of documents for target scenarios |

## Three Common Misconfigurations
- Issue: A large number of third-party testing reports unrelated to the current law enforcement scenario appear in retrieval results. Cause: `collectionIds` are not configured by data source, leading to cross-dataset recall of non-target documents.
- Issue: The generated law enforcement document references expired monitoring data. Cause: Daily incremental synchronization configuration is not enabled, resulting in recall of non-current-day old data.
- Issue: Professional term matching accuracy of initial recall results is insufficient, with core fields not prioritized for recall. Cause: A reasonable `similarity` threshold is not set, filtering out professional documents with high semantic matching.

## How to Confirm Proper Configuration
- Upload a test on-site inspection record, initiate a query for the corresponding law enforcement scenario, and verify whether same-point same-day monitoring data is included in the recall results.
- Check the retrieval log to confirm the number of recall results matches the `limit` configuration value.
- Verify dataset grouping settings to confirm only `collectionIds` corresponding to the current law enforcement scenario are enabled.
- Compare recall results with and without `usingReRank` enabled, confirming high-correlation documents are returned first after re-ranking.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
