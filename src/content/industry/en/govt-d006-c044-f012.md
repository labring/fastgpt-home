# Document and Material Drafting for Environmental Law Enforcement and Monitoring Supervision: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category include the ecological environment online monitoring platform, automatic pollution source monitoring system, internal law enforcement case handling system, and reports submitted by third-party testing institutions. Data is updated daily. Commonly processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Each document contains fields such as sampling points, pollutant concentration, law enforcement time, rectification requirements, and some documents have standardized formats and numerical units.

## What constraints these characteristics impose during the deployment and upgrade phase
Daily updated data sources require a stable connection link to be configured during deployment, to avoid data synchronization interruptions that affect law enforcement processes. Mixed processing of multiple document types requires retaining compatibility with older versions of law enforcement document templates during upgrades, to prevent the new system from being unable to read historical data. The requirement for standardized fields and units means data parsing rules must be clearly defined during the configuration phase, to avoid document errors caused by mismatched values and units. The high fault tolerance requirement of law enforcement scenarios requires a rollback plan to be configured during the upgrade process, to prevent law enforcement work from stalling due to configuration errors.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/ecology_env?authSource=admin` | Stores structured and unstructured data such as law enforcement records and monitoring reports |
| `REDIS_URL` | `redis://:pass@host:6379/1` | Caches daily synchronized online monitoring data to reduce data retrieval latency |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` | Stores document resources such as sampling records and administrative penalty decisions |
| Maximum database connections | 20–30 | Adapts to daily high-frequency data synchronization and document generation requests, avoiding database connection exhaustion |
| Document chunk length | 800–1200 characters | Adapts to the field density of law enforcement documents while retaining contextual relevance |

## Three common mistakes
- System login fails after upgrade, with the interface returning a 500 status code. The cause is that the authentication source parameter was not configured correctly when modifying the `MONGODB_URI` configuration, resulting in a failed database connection.
- When importing multi-column Excel law enforcement data, the automatic chunking results are chaotic, and each row of data is not treated as an independent segment. The cause is that the chunking rules were not set correctly, and the default automatic chunking does not adapt to the single-column, single-row law enforcement record format.
- Workflow orchestration cannot import older versions of configurations, and configuration loss occurs after import. The cause is that the workflow file in compatible format was not exported during cross-version upgrade, causing the new version to fail to recognize the older orchestration logic.

## How to confirm the configuration is complete
- Run the database connection test command to verify that the `MONGODB_URI` and `REDIS_URL` configurations can establish normal connections.
- Upload a sampling record Excel file and manually trigger chunking to confirm that each row of data is treated as an independent segment.
- Export the current version of the workflow configuration, attempt to import it into the FastGPT v4.17.0 environment, and verify that the import process has no errors.
- Simulate a daily data synchronization task to confirm that online monitoring data can be normally pulled and stored in the system.
