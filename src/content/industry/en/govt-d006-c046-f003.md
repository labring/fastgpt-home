# Document and Material Drafting for Social Assistance and Minimum Living Security Review: Multi-turn Dialogue and Prompting

## What the data for this category looks like
Service entities for this category include civil affairs bureau assistance sections, sub-district/township civil affairs offices, community committees, and verification centers. Documents routinely generated and used include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Core fields cover family population, income and property details, member relationships, and approval process nodes. Data is sourced from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update frequency is monthly, and each application's materials must match the latest shared data from the corresponding cycle.

## What constraints do these characteristics impose on the "multi-turn dialogue and prompting" link
Monthly updated cross-department data requires multi-turn dialogue to synchronize the latest verification rules and data sources, to avoid generating documents using outdated information. Fixed-format application documents require prompts to accurately match required fields, to avoid omitting core content such as family income and property details. Cross-department data retrieval must be confirmed step-by-step via multi-turn dialogue, to prevent excessive information loading in a single conversation from causing context overflow. At the same time, the risk of incorrect or missed assistance coverage requires multi-turn dialogue to perform secondary verification of key information, to ensure that generated documents are consistent with actual conditions.

## How to set the configurations

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Context window length | 8000–12000 characters | Documents in this category contain multiple sections of family information and cross-department verification data, requiring complete loading of historical dialogue and material snippets |
| `variables` bound fields | Application number, family address, per capita income | Exclusive information for each minimum living security application must be dynamically inserted into generated documents to ensure content matches accurately |
| Knowledge base recall limit | Top 3 entries | Core documents for this category are 5 fixed types of application materials, so no excessive recall of redundant content is needed |
| Dialogue history retention duration | 30 days | Matches the monthly update cycle of business data, to retain complete dialogue records for the corresponding application period |
| `messages` parameter configuration | Append tool-returned verification data snippets | Ensure tool call results are synchronized to the dialogue context, avoiding the need to re-enter the page to view results |
| `chatId` association rule | Bind the unique identifier of the corresponding application | Ensure that the dialogue record for each application is associated with its exclusive material, facilitating subsequent review and archiving |

## Three common mistakes
- Phenomenon: Tool call results are not displayed in the dialogue box, and can only be viewed after re-entering the page. Cause: The tool-returned cross-department verification data snippets were not correctly appended to the `messages` parameter, resulting in incomplete synchronization of the dialogue context.
- Phenomenon: Prompts cannot dynamically load content from the knowledge base. Cause: The prompt template is not associated with the application-specific fields bound by the `variables` parameter, or the knowledge base recall trigger conditions are not configured.
- Phenomenon: Generated assistance approval forms lack the family property details field. Cause: The supplementary link for income and property information was not triggered during multi-turn dialogue, resulting in the context not covering all required fields.

## How to confirm configurations are correctly set
- Launch a simulated minimum living security application dialogue process, call the cross-department data verification tool, and check whether the tool's returned results are fully displayed in the dialogue history.
- Call the knowledge base to query the preset minimum living security application document template, confirm that the prompt can dynamically replace the exclusive fields bound by the `variables` parameter and generate documents in the corresponding format.
- Configure iframe access parameters, check whether the interface switches to Chinese display, and confirm that the language configuration takes effect.
- Extract the current dialogue link, confirm that the `chatId` parameter is properly carried and associated with the unique identifier of the corresponding simulated application.
