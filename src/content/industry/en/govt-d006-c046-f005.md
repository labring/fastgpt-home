# Document and Material Drafting for Social Assistance and Minimum Living Standard Verification: Tool Calling and Plugins

## What the Data for This Category Looks Like
This category serves civil affairs bureau relief departments, subdistrict or township civil affairs offices, community committees, and verification centers. Staff handle daily documents including minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Data mainly comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax authorities, and other departments. The data updates once per month. Document fields cover family population information, income and property details, verification results, and other content. No unified fixed units exist, and actual values must match specific business fields.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Link
Cross-department shared data updated monthly requires regular sync of the latest data sources during tool calling, to avoid verification deviations caused by expired information. The need to draft multiple types of specialized documents requires plugins to support on-demand calling of corresponding document templates and field filling logic. Decentralized cross-department data sources require configuration of multiple data source connection plugins to complete unified extraction. Verification of sensitive information such as family income and property requires tool calling processes to comply with data security regulations to avoid information leakage. Generation of household survey and public notice materials requires plugins to call a local template library to complete format standardization.

## Three Common Misconfigurations
- When calling a tool, a prompt appears that the knowledge base cannot be referenced, and the returned fields are empty. The cause is that the knowledge base ID is not correctly bound to the tool calling node in the workflow, and only the global variable is configured without completing parameter passing.
- After configuring the MySQL database connection, SQL extraction results cannot be executed. The cause is that the database access permission is not opened to the FastGPT deployment node, or the database instance address of the target verification system is not correctly configured in the connection string.
- The generation process is blocked when sending consecutive conversation requests. The cause is that no concurrent request limit is set, and the resources of the tool calling node are occupied by previous requests, causing subsequent requests to queue and wait.

## How to Confirm the Configuration Is Properly Set Up
- Manually trigger the tool calling node, and check whether the returned data source data includes the latest monthly cross-department shared information.
- Call the template generation tool corresponding to the document type, and check whether the generated document matches the preset format of the minimum living security application form or verification report.
- View the tool calling logs, confirm that there are no errors in database connection and knowledge base reference, and the timeout threshold is not triggered.
- Simulate sending two consecutive requests, and confirm that the second request can start normally without blocking.
