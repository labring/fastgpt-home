# Document and Material Drafting for Social Assistance and Minimum Living Security Review: Model Access and Configuration

## What the data for this category looks like
This category involves documents centered on individual households, including standardized civil affairs documents such as minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Data is primarily sourced from low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-departmental shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update cycle is monthly. Document fields include family member information, income and property details, assistance application reasons, and other content. These must match the standardized fields of local civil affairs departments; there is no unified fixed unit.

## What constraints these characteristics impose on the model access and configuration link
Cross-departmental shared data access requires models to support context integration of multi-source heterogeneous data, and adapt to the monthly updated data source synchronization rhythm. Therefore, the context length configuration must reserve sufficient space to accommodate multiple batches of verification data. The fields of standardized documents depend on local civil affairs regulations, so the range of model output fields must be limited to avoid generating content that does not meet local requirements. Household survey supporting materials are mostly scanned documents or PDF files, so visual recognition capabilities are required to process non-text materials. Errors in assistance review have serious consequences, so the accuracy of generated content must be strictly controlled to avoid issues of incorrect security coverage or missed security coverage. FastGPT v4.17.0 configuration items can adapt to these constraints in a targeted manner.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Needs to accommodate cross-departmental shared monthly updated data and context information from multiple documents, ensuring the model can fully obtain all associated data for family economic status verification |
| `temperature` | `0.1–0.3` | Minimum living security review documents must strictly match civil affairs regulations; low temperature values improve the accuracy and consistency of output content |
| `vision` | Enabled | Needs to process visual supporting materials such as scanned household survey documents and public notice materials, extracting key information from them |
| `toolChoice` | `auto` | Needs to automatically select whether to call multi-source data verification tools based on tasks, adapting to the needs of different review scenarios |
| `AIPROXY_API_ENDPOINT` | Interface address of locally deployed large models | Adapts to the call needs of locally deployed large models, ensuring data transmission complies with the security specifications of civil affairs systems |
| `AIPROXY_API_TOKEN` | Exclusive token generated according to the platform | Ensures the security of interface calls and prevents unauthorized access |

## Three common configuration mistakes
- The symptom is a null content return value after calling the interface. The cause is incorrect configuration of `AIPROXY_API_TOKEN` or an incorrect interface address, preventing the large model from returning generated results normally.
- The symptom is a request error triggered when uploading a household survey PDF. The cause is that the `vision` configuration item is not enabled; the model cannot recognize image content in the PDF, leading to parsing failure.
- The symptom is that the generated assistance approval form lacks specific fields required by local civil affairs regulations. The cause is that the `maxContext` configuration value is too small, failing to fully load cross-departmental shared verification data, so the model cannot obtain complete family economic status information.

## How to confirm the configuration is complete
- Initiate a test for generating a minimum living security application form for a single household, verifying that the generated content includes all required civil affairs document fields and that the fields match local regulations.
- Upload a scanned PDF of a household survey, confirming that the model can correctly extract family member and income-related information from it.
- Simulate the monthly data update process, resynchronize cross-departmental shared data sources, and confirm that the knowledge base can normally load new verification data.
- Call the interface and check the returned results, confirming that the complete content field is included and there are no abnormal error messages.
