# Document and Material Drafting for Social Assistance and Minimum Living Security Review: Knowledge Base Retrieval and Recall

## What the data for this category looks like
This category covers core civil affairs social assistance business scenarios. Daily documents include fixed-format forms such as minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Fields include verification items such as family composition, income type, property category, and application reason. Data sources include the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax authorities, and other departments. The update frequency is once per month. The data mainly consists of structured forms and semi-structured business records, and some cross-department data has format differences.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Cross-department sources of business data lead to format differences. The retrieval link must adapt to unified parsing of multi-source heterogeneous data to avoid retrieval omissions caused by format incompatibility. The monthly update frequency means the knowledge base must run incremental synchronization at fixed intervals. This prevents data lag from impacting review accuracy. Fixed-format business documents require segmentation logic to match form structure. This ensures retrieval results accurately correspond to specific verification items and improves review efficiency. Core verification dimensions are family economic status and member relationships. Retrieval results must prioritize matching high-weight fields, reduce interference from irrelevant content, and lower the risk of incorrect or missed security approvals.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | `0.72–0.85` | Accurately match core verification fields such as family economic status and member relationships, filter low-correlation retrieval results |
| `limit` | `Top 8` | Cover multi-dimensional supporting materials required for minimum living security review, avoid overloading review work with too many recall results |
| `searchMode` | Semantic retrieval + keyword hybrid | Balance keyword matching for structured form fields and semantic association for naturally described content, adapt to multiple types of business documents |
| `usingReRank` | Enabled | Reorder recall results by relevance, improve the display priority of high-value verification materials |
| `datasetSearchUsingExtensionQuery` | Enabled | Expand the retrieval scope to cover associated fields in cross-department shared data, such as associating family member information through public security data |
| `collectionIds` | Bind the exclusive dataset ID for civil affairs assistance | Isolate business data, avoid interference from irrelevant knowledge base content on retrieval results, and ensure the exclusive security of review data |

## Three common misconfigurations
- Phenomenon: An unauthorized prompt is returned when calling the knowledge base retrieval API. Cause: The API key is not bound to the corresponding civil affairs assistance exclusive dataset, or the key permission is not configured as dataset retrieval permission.
- Phenomenon: The knowledge base segmentation results do not correspond to the directory structure of the minimum living security application form, making it impossible to match materials in corresponding chapters during retrieval. Cause: The automatic segmentation configuration based on document directories is not enabled, and only the default fixed character segmentation logic is used.
- Phenomenon: Unable to connect a self-hosted vector database to the current knowledge base retrieval process. Cause: The vector database connection address and dataset ID are not bound according to the FastGPT custom data source configuration process, or cross-source access permissions are not configured.

## How to confirm the configuration is complete
- Verify the `collectionIds` configuration, confirm that only the exclusive data source collection for civil affairs assistance is bound.
- Initiate a test retrieval, enter business keywords related to minimum living security review, and verify that the relevance sorting of returned results conforms to business logic.
- Check the API call logs to confirm that there are no unauthorized or permission-related error messages.
- Import a standard minimum living security application form document, verify that the segmentation results match the directory structure of the document.
