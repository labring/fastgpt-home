# Document and Material Drafting for Administrative Penalty Case Handling: Multi-turn Dialogue and Prompt Engineering

## Data profile for this category
This category covers end-to-end administrative penalty data from law enforcement agencies across market supervision, ecological environment, transportation, and other fields. Standardized documents generated daily include on-site inspection records, interrogation records, evidence lists, administrative penalty prior notice letters, penalty decisions, and similar fixed-format materials. Data is primarily sourced from administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information public disclosure system, and departmental supervision databases, with daily updates. Core data focuses on illegal facts and penalty decisions. A traceable evidence chain must be established. Errors may lead to failed case file reviews or revoked penalties.

## Constraints on multi-turn dialogue and prompt engineering
Fixed formats for law enforcement documents require prompts to match the field structure of documents such as on-site inspection records and penalty decisions. Prompts must explicitly link evidence-related data. Real-time updates of multi-source data require dialogue contexts to be bound to the unique identifier of the current law enforcement case, to avoid cross-case confusion. Traceability of the evidence chain requires multi-turn dialogue to retain law enforcement information from each turn, to ensure generated documents can be mapped to original evidence. The severe consequences of errors require prompts to cover verification rules for links such as legal review and service filing, to reduce compliance risks.

## Configuration guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| User Query | Fixed script template including illegal facts, evidence types, and target document type | Matches the fixed fields and business logic of law enforcement documents |
| Context Window Size | 8000–12000 characters | Accommodates multi-turn law enforcement dialogue, multiple records, and evidence list content |
| Associated File Scope | All associated documents of the current law enforcement case | Ensures called evidence and case handling information only come from the target case |
| Dialogue Role Setup | Dual roles of law enforcement case handler and legal review personnel | Covers different permission and verification requirements across the full case handling process |
| `chatId` Configuration | Bind to the unique identifier of the current law enforcement case | Ensures multi-turn dialogue contexts are linked to the same case, to avoid confusion |
| Error Retry Count | 2–3 times | Addresses temporary network or resource fluctuations, without interrupting case handling workflows |
| Dialogue Timeout Duration | 600 seconds | Prevents case handling workflow interruptions due to prolonged law enforcement document parsing |
| Maximum Generated Document Length | 5000 characters | Complies with standard length requirements for law enforcement documents |

## Three common configuration errors
- A 503 status code is returned when uploading law enforcement documents via the dialogue page, while backend logs show the file upload was successful. The cause is that the context window configuration exceeds the system's carrying threshold, triggering resource limits during the file parsing phase.
- The penalty decision generated via multi-turn dialogue lacks the evidence list field. The cause is that the user query template does not explicitly require association with evidence documents, resulting in the prompt not covering evidence citation rules.
- Multi-turn dialogue context is lost, and generated documents do not match prior law enforcement information. The cause is that `chatId` is not bound, so the unique case identifier is not retained during dialogue flow.

## How to verify successful configuration
- Initiate a test dialogue referencing an on-site inspection record, and check if the generated interrogation record correctly associates this evidence.
- Bind the unique identifier of a law enforcement case, initiate three consecutive dialogue turns, and verify that the `messages` parameter retains historical information as dialogue flow progresses.
- Verify that the `variables` parameter correctly transmits custom case handling variables such as case number and illegal subject.
- Upload a law enforcement-related document, and verify that the associated file scope only loads documents from the current case, with no data from other cases mixed in.
