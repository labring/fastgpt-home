# Administrative Penalty Case File Handling: Document and Material Drafting - Deployment and Upgrade

## What the data for this category looks like
Core documents for this category include on-site inspection records, interrogation records, evidence lists, prior administrative penalty notices, hearing notices, penalty decisions, and service return receipts. All have fixed format fields.
Data sources cover administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information publicity system, and departmental supervision databases. The update frequency is daily.
A single law enforcement case file includes structured fields and unstructured audio, video, and image attachments. Fields must be linked to core information such as violating subjects, illegal facts, discretion bases, penalty content, and must remain consistent with real-time collected data during law enforcement processes.

## What constraints these characteristics impose on deployment and upgrades
Multi-source data sources require permission isolation rules for multiple data sources to be configured during deployment, to avoid business conflicts between production systems and FastGPT instances.
Daily updated law enforcement data requires incremental synchronization scheduled task configurations to be retained during upgrades, to prevent interruptions to real-time case file data acquisition.
Fixed format document templates require preset field mapping rules to be configured during deployment, to ensure generated documents meet law enforcement case file archiving requirements.
High risk of errors requires a rollback mechanism to be retained during upgrades, to avoid law enforcement process interruptions caused by configuration changes.
Additionally, intranet deployment scenarios require configuration items to adapt to law enforcement agencies' intranet access restrictions, to ensure data security.

## How to configure the settings
These configurations are based on FastGPT v4.17.0, and are tailored for the exclusive business scenario of administrative penalty case file handling.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 connections | Adapt to daily high-frequency law enforcement document query and generation requests, avoid database connection exhaustion, and ensure stability for simultaneous access by multiple law enforcement terminals |
| `MONGODB_URI` | Point to the dedicated read-only replica set address of the administrative law enforcement case handling system | Store unstructured data such as law enforcement recorder footage and evidence lists, isolate from the production business database to prevent accidental operations from affecting law enforcement business |
| `REDIS_URL` | Bind to a local cache instance, configure a 600-second expiration time | Cache daily updated query results from the national enterprise credit information publicity system, reduce the frequency and latency of repeated calls |
| `STORAGE_S3_ENDPOINT` | Point to the internal object storage service address of the law enforcement agency | Store archived files such as generated penalty decisions and service return receipts, comply with case file archiving storage specifications and permission requirements |
| `FE_DOMAIN` | Configure as the access domain name of the law enforcement intranet | Restrict front-end access scope, ensure law enforcement data only circulates within the intranet environment, and comply with law enforcement agencies' security management requirements |

## Three common errors
- Phenomenon: Initialization fails during source code deployment because the server does not support Docker. Cause: Dependencies and runtime parameters are not configured according to non-Docker deployment documentation, and necessary system components are missing.
- Phenomenon: The `WARNING: current commit information was not captured by the` error occurs during local image packaging. Cause: The Git repository has not been initialized in the project root directory, or the current code has not been committed, causing the build script to fail to obtain version metadata.
- Phenomenon: When connecting funasr for speech transcription of interrogation records, audio files from law enforcement recorders cannot be recognized properly. Cause: The model path and sampling rate parameters of funasr are not configured, leading to incompatibility with the audio format of law enforcement recorders.

## How to confirm the configuration is successful
- Run the built-in data source connectivity test script of FastGPT, verify the connection status of configurations such as `MONGODB_URI` and `PG_URL`, and confirm there are no timeout or permission errors.
- Trigger a simulated law enforcement document generation task, check if the generated document includes preset fields such as on-site inspection records and illegal facts, and verify that field mapping matches law enforcement business requirements.
- View the monitoring panel of the cache instance bound to `REDIS_URL`, confirm that daily updated publicity system data has been cached normally, and the expiration time meets configuration requirements.
- Test the speech transcription function connected to funasr, upload audio files from law enforcement recorders, and confirm that the transcription results can be synchronized to the record template normally.
