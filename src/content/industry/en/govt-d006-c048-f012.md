# Administrative Licensing Approval: Document and Material Drafting - Deployment and Upgrade

## What this category of data looks like
This category of data comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate database. The update frequency is daily. Commonly processed documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision letters, and license certificates. The document structure is bounded by legal licensing items. Each item corresponds to standardized fields including item identifiers, handling conditions, application material lists, and approval process node documents. All fields follow unified government service specifications.

## Constraints imposed on the deployment and upgrade process
Multiple data sources with daily updates require deployments to adapt to government intranet network isolation rules to ensure data synchronization stability. Document structures are standardized, but minor differences exist across departments, so upgrades must support parsing logic for multi-format government documents. Government data has high security requirements, so deployment and upgrade processes must strictly follow government data storage and access specifications to avoid data leaks. Errors in administrative licensing approval directly affect work progress, so a complete rollback mechanism must be configured before upgrades to ensure service continuity.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Fill in the MongoDB connection address compliant with the government intranet, configure access whitelist to only allow government intranet IPs | Government data must be stored in a compliant intranet environment to ensure data security and prevent unauthorized external access |
| `REDIS_URL` | Use a government cloud-exclusive Redis instance, set connection timeout to `600 seconds` | Government data synchronization frequency is high, so cache stability must be ensured to avoid frequent reconnections affecting retrieval efficiency |
| `STORAGE_S3_ENDPOINT` | Fill in the access endpoint of the government cloud object storage service, configure bucket permissions to private read/write | Confidential documents such as electronic certificates must be stored in government cloud compliant storage media to ensure secure file access |
| `DB_MAX_LINK` | Set the connection pool upper limit to `20 total connections` | Government intranet server resources are limited, so excessive connections will not occupy bandwidth and ensure normal database service operation |
| `ROOT_KEY` | Use a government intranet-exclusive encryption key and rotate it regularly | Ensure the security of system access permissions, comply with government data security specifications, and prevent unauthorized access |

## Three common mistakes
- Symptom: A `connection refused` error is returned when running the local deployment script. Cause: `MONGODB_URI` is not configured as a database address accessible from the government intranet, or the deployment server IP is not added to the database whitelist.
- Symptom: A `storage bucket access denied` error occurs when starting the service after upgrade. Cause: The permissions of the storage bucket corresponding to `STORAGE_S3_ENDPOINT` are not configured as required, and the government cloud storage access key is not synchronized.
- Symptom: Empty results are returned when searching government service guides. Cause: `DB_MAX_LINK` is not configured to adapt to the connection limits of the government database, resulting in connection pool exhaustion and inability to read data normally.

## How to confirm configuration is complete
- Run the command `curl --location --request GET '${MONGODB_URI}/admin'` to confirm normal connection to the government intranet database.
- Upload a sample correction notification letter to the configured storage bucket, and verify that the file can be downloaded normally through the access link generated by `FILE_TOKEN_KEY`.
- Start the FastGPT v4.17.0 service, then access the frontend address specified by `FE_DOMAIN` to confirm that the government item database search interface loads correctly.
- Check the monitoring panel corresponding to `REDIS_URL` to confirm that the number of connections stays within the range configured by `DB_MAX_LINK`.

The values provided are common starting points and should be measured against the reader's own samples.
