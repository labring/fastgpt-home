# Document and Material Drafting for Legality Review of Regulatory Documents: Multi-turn Dialogue and Prompts

## What Data for This Category Looks Like
The data sources for this category include regulatory and rule databases, higher-level law databases, departmental policy document repositories, and administrative regulatory document filing systems. Update frequency is irregular.
Daily processed documents include regulatory document drafts, drafting explanations, legality review opinions, solicitation opinion summaries, and filing reports. Each type of document has dedicated business fields:
- Drafts include issuing entity, clause content, and rights and obligations setting
- Review opinions include review basis, correction points, and rectification suggestions
- Filing reports include submitting unit, filing number, and other information

## Constraints Imposed on the "Multi-turn Dialogue and Prompts" Link
Scattered data sources with irregular updates require multi-turn dialogue to support step-by-step retrieval of compliance basis from different databases, avoiding loading excessive redundant data at one time.
Diverse document structures and dedicated fields require prompts to adapt to the format and field requirements of different documents, guiding users to submit materials in accordance with business processes.
The most time-consuming higher-level law comparison link requires clause-by-clause verification. Multi-turn dialogue must support segmented backtracking of the review process to ensure that the compliance basis for each step is traceable.
The consequences of errors must be traceable, so the dialogue context must fully store all opinions and adjustment records generated during the review process.

## Configuration Settings
All configurations below are based on FastGPT v4.17.0
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context Size | 8000–12000 characters | Adapt to the total length of associated documents such as regulatory drafts and drafting explanations, avoiding truncation of key review content |
| `chatId` | Bind to current review session ID | Retain multi-round review context to facilitate backtracking of modification opinions and associated filing system numbers |
| `messages` | Store in segments according to the review process | Distinguish dialogue content from stages such as draft submission, basis retrieval, and opinion summary, facilitating subsequent audit traceability |
| `variables` | Inject current review entity and filing system number | Dynamically associate dedicated business data, automatically adapting to review rules of different units |
| Prompt Optimization | Calibrate based on actual testing | Adapt to professional terminology and review logic of legality review, and optimize the accuracy of dialogue guidance |
| Single Call Count | Top 3 | Avoid redundant data interference with higher-level law comparison, focus on core compliance basis |

## Three Common Misconfigurations
- A version update prompt pops up every time a new conversation is started, and it cannot be closed via the interface. This occurs because the switch for version prompts is not disabled in the session initialization configuration.
- Tool call results are not displayed in the dialog box in real time, and only become visible after re-entering the conversation. This occurs because the context storage logic for `messages` is not correctly bound, resulting in non-persistent session state.
- Prompts cannot be dynamically loaded and used from the knowledge base. This occurs because prompts are not configured to associate with corresponding entries in the knowledge base via `variables`, and dynamic variable replacement is not enabled.

## How to Verify Successful Configuration
- Initiate a new legality review session, confirm that no extra version update prompt pops up.
- Submit a regulatory document draft and trigger a higher-level law comparison tool call, check if the call result is displayed in the dialog box in real time.
- Configure dynamic prompt variables, associate with review templates in the knowledge base, check if corresponding professional content can be loaded.
- Verify the `chatId` binding logic, retain previous review opinions after switching sessions, confirm that the context is not lost.
