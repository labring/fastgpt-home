# Document and Material Drafting for Legality Review of Regulatory Documents: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category primarily comes from regulatory and rule databases, higher-level law databases, departmental policy document libraries, and administrative regulatory document filing systems. Update frequency is irregular. Daily processed documents include regulatory document drafts, drafting explanations, legality review opinions, solicited opinion summary reports, and filing reports. Document fields include drafting entity, clause content, basis for drafting authority, solicited opinion feedback content, and more. The length of individual documents varies widely; some draft files can reach several thousand characters.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Decentralized data sources and irregular update cycles require workflows to support dynamic pulling and real-time comparison of multi-source data, and prohibit reliance on fixed cached historical data. Daily documents have distinct structural differences, with varying fields and formats from drafts to filing reports. Workflows must be configured with flexibly adjustable document parsing rules. Comparing higher-level laws against authority bases is a core time-consuming step. Workflows must include a dedicated independent node for this step, and reserve a trigger entry for manual review to prevent automated reviews from missing compliance risks. Errors directly impact the legality of policy release and implementation. Workflows must set mandatory verification nodes to ensure core review steps are completed before advancing to the next stage.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |

## Three Common Configuration Mistakes
- Form input fields do not appear interactively in conversations. This occurs when the form visibility switch is not enabled in the workflow's global configuration, meaning the input component is not mounted to the conversation interface.
- Tool call steps cannot dynamically select execution tools. This occurs when the `variables` parameter binding for tool trigger conditions is not configured correctly, meaning only preset fixed tool chains can be executed.
- Variable values only support fixed input and cannot be dynamically updated. This occurs when variables are not associated with upstream node outputs of the workflow, and only static text is manually entered.

## How to Verify Correct Configuration
- Start a test conversation, input content related to regulatory document drafts, and confirm that form input fields display normally and allow text entry.
- Trigger the tool call step, and check whether it can automatically switch to the corresponding execution tool based on the current review node's status.
- Modify upstream node data associated with the `variables` parameter, and confirm that variable values update synchronously with upstream outputs.
- Initiate a review process, and check whether retrieval results only come from the specified compliance data source knowledge base.
