# Document and Material Drafting for Legality Review of Regulatory Documents: Model Integration and Configuration

This documentation applies to FastGPT v4.17.0.

## What the data for this category looks like
The core documents for this category include regulatory document drafts, drafting explanations, legality review opinions, solicited opinion summaries, and filing reports. Data sources include regulatory and rule databases, higher-level law databases, departmental policy document databases, and administrative regulatory document filing systems. Update frequency is irregular. Each individual document contains fixed fields such as draft clauses, authority basis explanations, public and departmental opinion summaries, and drafting unit information. The document structure has clear hierarchical levels, and all associated materials across the full process from drafting to filing must be covered.

## What constraints these characteristics impose on the model integration and configuration link
Integrated data sources must be secured against sensitive permission leakage risks, and synchronization logic must adapt to irregular update characteristics, as data sources are official authoritative regulatory databases. The document structure includes multiple types of associated materials, so metadata for each document must be retained during model integration to associate review basis materials. The core link of comparing higher-level laws and authority basis requires retrieved legal texts to cover sufficient context length to avoid review oversights caused by missing information. At the same time, review errors can lead to consequences such as filing corrections and failed policy releases, so configuration must strictly control the rigor of generated content and must not deviate from legal provisions.

## How to configure the settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Must cover multiple review basis materials including regulatory document drafts, higher-level law clauses, and opinion summaries to ensure complete context |
| `temperature` | `0.1–0.3` | Rigorous output is required for review scenarios to avoid content that deviates from legal provisions |
| `quoteMaxToken` | `3000–5000 token` | Must fully quote higher-level law clauses as review basis to avoid truncation of key provisions |
| `toolChoice` | `auto` | Automatically call document retrieval tools to complete higher-level law comparison and opinion summary analysis |
| `AIPROXY_API_ENDPOINT` | Compliant proxy address deployed locally | Adapt to data security requirements of state-owned enterprises and government scenarios to prevent sensitive data from being leaked |
| `AIPROXY_API_TOKEN` | Access key corresponding to the proxy service | Verify model call permissions to ensure compliant interface access |

## Three common configuration mistakes
- Symptom: Model icons do not display in the workflow, and the interface prompts "Model loading failed". Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters are not configured correctly, causing the model service to fail to invoke normally.
- Symptom: A network error prompt appears when uploading a PDF-format regulatory document draft. Cause: When deployed locally, the API port of the MinerU document parsing service is not mapped to the FastGPT container network, preventing the parsing process from being triggered.
- Symptom: Retrieved higher-level law clauses do not match the review content, and the number of results deviates significantly. Cause: `maxContext` is set too small to fully load associated clauses in the legal database, or `temperature` is set too high, causing the retrieval logic to deviate.

## How to verify successful configuration
- Call the interface corresponding to `AIPROXY_API_ENDPOINT` to verify that a normal model response is returned, confirming that the key and address configurations are correct.
- Upload a small regulatory document draft, check that there are no file upload or parsing error prompts on the interface, confirming that the document parsing link is working properly.
- Trigger an audit test task, check that the number of retrieved associated legal clauses meets the preset threshold, confirming that the context configuration takes effect.
- Check that the model icons on the workflow canvas display normally, with no loading failures or gray placeholder states, confirming that the model integration configuration is correct.
