# Document and Material Drafting for Fiscal Expenditure Performance Evaluation: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category comes from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual.
Daily produced documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports.
Data fields focus on performance targets for fiscal fund use, actual output, effect verification, and rectification status. There are no uniform fixed unit requirements. Configurations must match the specific declaration and implementation standards of the corresponding project.

## What constraints do these characteristics impose on HTTP interfaces and external systems
The low-frequency annual update property means interface calls do not require high-frequency polling, and fixed periodic triggers can be configured. Multiple heterogeneous data sources require interfaces to support batch pulling of structured and unstructured data from different systems. Document material drafting requirements mean data returned by interfaces must include complete field mappings to avoid missing key supporting information. Single-operation document volume is large, so sufficient request timeout time must be reserved to prevent drafting failures caused by incomplete data pulling. The data verification link relies on the corresponding relationship between fund payment and performance targets returned by the interface. The interface must ensure data accuracy; otherwise, subsequent scoring deviations or budget adjustment risks may occur.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Bearer {dedicated key for the connected system} | Complies with government system identity verification specifications to ensure secure interface access |
| Request timeout duration | 600 seconds | Adapts to low-frequency, high-volume multi-source data pulling requirements, prevents call failures from incomplete data return |
| `variables` | Bind fixed parameters including performance year and budget unit code | Simplifies repeated configuration, ensures each call's business scenario matches the current drafting task |
| `responseData` | Extract structured fields and associated supporting material paths | Directly maps to document drafting template fields, reduces secondary data processing workload |
| Proxy configuration | Use user names, passwords, and ports determined via actual testing | Adapts to internet access needs for intranet deployment, meets proxy identity verification requirements |

## Three Common Configuration Mistakes
- Symptom: Calling an external fiscal system interface returns a 502 status code, while calls work normally in other testing tools. Cause: The `Authorization` parameter is not configured correctly, or the key format in the request header does not meet the connected system's verification rules.
- Symptom: The `responseData` field returned by the interface call is missing, causing the document template to fail to fill in corresponding content. Cause: Specified business fields are not configured for extraction, or pulled data does not match template field mappings.
- Symptom: External systems cannot be accessed in an intranet deployment scenario, and proxy configuration does not take effect. Cause: Proxy user name and password parameters are not configured; only IP addresses and ports are filled, leading to failed identity verification.

## How to Verify Correct Configuration
- Initiate a single test call to confirm that the `responseData` returned by the interface includes all fields required for the current business scenario.
- Verify that the `Authorization` parameter configuration matches the connected system's identity verification rules.
- In the intranet environment, test whether the proxy configuration can successfully establish a connection and access the external target interface.
- After calling the interface to obtain data, verify that the data can correctly match preset document template fields.
