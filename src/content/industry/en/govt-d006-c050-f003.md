# Document and Material Drafting for Fiscal Expenditure Performance Evaluation: Multi-turn Dialogue and Prompts

## What the data for this category looks like
The data for this category comes from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Daily output documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. The document structure follows the workflow of performance target setting, implementation tracking, result verification, and rectification closure. Fields include project code, fund amount, output indicators, benefit indicators, satisfaction scores, and no additional custom units. All fields comply with fiscal business specifications.

## What constraints these characteristics impose on the multi-turn dialogue and prompts link
The annual updated data scale is fixed. Dialogues must be limited to single-year project scope to avoid mixing cross-year data. The multi-document structure requires prompts to clearly distinguish field rules for different document types. For example, the performance self-assessment form must match preset indicators from budget declaration. Data sources are scattered, so multi-turn dialogue is needed to gradually guide users to provide supporting materials from corresponding sources, while clarifying verification logic for data from different sources. Since errors directly relate to budget adjustments and accountability, content generated via dialogue must strictly correspond to preset performance indicators and fund usage records, ensuring complete fields and compliance with business logic.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Fixed binding to single-year project | Data for this category is updated annually; fixed session ID prevents mixing cross-year project data |
| `variables` | Preset 10-15 performance-related field variables | Documents in this category have a fixed field structure; preset variables reduce user input errors |
| `messages` | Initial prompt includes annual verification rules, retain the first 3 rounds of dialogue context | This category requires gradual guidance for users to supplement supporting materials; limiting context length improves logical consistency |
| Maximum context length | 800–1200 characters | Document fields for this category are concentrated; overly long context may introduce irrelevant data; adjust based on actual measurements |
| Concurrent call threshold | 1–2 calls per second | Data for this category comes from fiscal business systems; high-frequency calls may trigger interface rate limits |

*This configuration is adjusted based on FastGPT v4.17.0*

## Three common mistakes
- Phenomenon: Workflow returns empty fields after concurrent calls exceed the threshold. Cause: No reasonable concurrent call limit set; high-frequency requests trigger fiscal system interface rate limits.
- Phenomenon: Symbols tracing display rules appear at the end of dialogue response results. Cause: The model's built-in rule tracing switch was not turned off; FastGPT v4.17.0 retains this display item by default.
- Phenomenon: Satisfaction survey fields are missing from multi-turn dialogue-generated performance reports. Cause: The initial prompt did not explicitly include mandatory verification rules for satisfaction scores, and no corresponding variable binding was used to constrain generated content.

## How to confirm the configuration is complete
- Initiate a test dialogue for a single-year project, check generated document fields for coverage of preset performance indicators and fund records, adjust the prompt until fields are complete.
- Simulate concurrent calls, observe returned results for empty fields or abnormal symbols, adjust the concurrent threshold to comply with business system rate limit rules.
- View session context, confirm the project scope bound to `chatId` does not span multiple years, and that preset fields in `variables` have loaded correctly.
- Test the multi-turn process for guiding supplementary supporting materials, confirm the dialogue logic does not introduce irrelevant non-fiscal performance content.
