# Document and Material Drafting for Fiscal Expenditure Performance Evaluation: Workflow Orchestration

## What the data for this category looks like
Data for this category originates from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys, and is updated on an annual basis. Daily generated documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Document fields cover performance target details, fund usage correspondence, supporting material association identifiers, satisfaction survey results, and similar metrics. Units include monetary amount, completion quantity, person-times, and other relevant units.

## What constraints these characteristics impose on the "workflow orchestration" link
Annual data updates require workflow trigger cycles to align with annual rhythms, to avoid frequent execution that wastes resources. Multiple data sources require workflow configurations to include cross-system data retrieval nodes, to integrate scattered budget, payment, ledger, and other data. Fixed-structure documents require workflows to include format verification nodes, to ensure submitted self-assessment forms and supporting material lists comply with specifications. The most time-consuming supporting material collection and verification links must be split into independent sub-nodes, to facilitate separate adjustment and monitoring. Verification nodes must also be configured to associate fund expenditures with performance targets, to avoid scoring deviations.

## Configuration Recommendations

| `variables` | Bind global parameters such as annual performance cycle and budget unit ID | Align with the annual update feature of data for this category, and uniformly pass fixed business parameters across nodes |
| `nodeId` | Assign unique identifiers to data retrieval, format verification, and report generation nodes | Facilitate locating execution status of each workflow link and troubleshooting exceptions |

| Log collection and management | Retain input and output records for all nodes | Facilitate verification of the correspondence between fund expenditures and performance targets, and trace problematic links |

## Three Common Misconfigurations
- Workflow fails to update after page refresh following save. The save operation shows as successful, but configuration reverts to its pre-modification state after page refresh. Causes include incomplete configuration persistence verification, or local cache overwriting the new configuration.
- Global variables cannot be passed during API calls. The interface returns a parameter missing error, or the workflow fails to obtain expected business parameters. Causes include failure to correctly bind the `variables` parameter in the workflow, resulting in unrecognized global parameters passed via the interface.
- Generated reports lack supporting material association information after workflow execution. The output performance evaluation report does not include specified supporting material numbers. Causes include failure to configure inter-node association verification logic, resulting in the data retrieval link failing to correctly associate fund payment and supporting material data.

## How to Confirm Proper Configuration
- Trigger a test workflow, view execution logs for each node, and confirm that the `variables` parameter and `nodeId` identifier are both displayed correctly. These logs can be viewed directly on the workflow management page of FastGPT v4.17.0.
- Call the corresponding API interface, pass preset global business parameters, and verify whether the workflow can correctly obtain and use these parameters.
- Check the knowledge base access permission configuration, and confirm that test accounts at different hierarchy levels can normally access supporting material data within their corresponding scope.
- Manually modify one workflow configuration, save it, and refresh the page, and confirm that the configuration content has been updated synchronously.
