# Document and Material Drafting for Department Final Accounts and Financial Reports: HTTP Interfaces and External Systems

## What data in this category looks like
This category of data originates from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. It is updated annually.
Daily generated documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports.
Fields cover income and expenditure details, asset and liability balances, budget execution difference explanations, and more. Units use standard financial units such as yuan and ten thousand yuan, and must comply with the original data format output by each system.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
The low-frequency annual update feature requires interfaces to support batch synchronization of historical annual data, without frequent calls.
Data from multiple system sources must be integrated via interfaces, so support for multi-source data pulling and format conversion is required.
Documents include fixed-format statements and explanations. Interface returned data must match preset field structures to avoid missing fields or format errors.
The time-consuming account statement verification process requires interfaces to provide data verification capabilities. This assists in quickly matching treasury payment data and accounting data.
Error consequences are significant. Interfaces must return clear error codes and logs to facilitate locating issues such as inconsistent accounts and records or caliber errors.

## How to Configure Settings
| Configuration Item | Recommended Setting Method | Rationale for This Setting |
| ---- | ---- | ---- |
| `Authorization` | Pass a secret in app key format, placed after `Bearer ` in the request header | Follow FastGPT official secret usage specifications to avoid security issues caused by account secret leakage |
| `variables` | Pass business variables such as final account year and budget unit code, with a quantity of 1–10 | Adapt to annual update business scenarios, accurately match historical data from corresponding systems |
| `responseData` | Specify returning core fields such as income and expenditure details, asset balance, and difference explanation | Match the fixed field structure of department final account documents, reduce redundant data processing steps |
| Request timeout | 600 seconds | Adapt to the time-consuming requirement of batch pulling data from multiple systems, avoid interface interruption mid-process |
| Single request data volume | 800–1200 characters | Adapt to the single length of financial statement data, balance transmission efficiency and stability |

## Three Common Mistakes
- The error `Key is error. You need to use the app key rather than the account key` appears. The cause is passing an account login secret instead of an application-level app key, and not following FastGPT's secret usage specifications.
- After calling the interface to pull final account data, returned fields are empty. The cause is failing to specify core fields via `responseData`, or passing `variables` parameters that do not match the data source, making it impossible to locate financial data for the corresponding year.
- Authentication failure occurs when connecting to external system interfaces that use header authentication. The cause is failing to correctly configure the `Authorization` parameter in the request header, or failing to adapt to the authentication format requirements of the external system.

## How to Confirm Configuration is Correct
- Initiate a test request, check if the returned `responseData` fields include income and expenditure details, asset balance and other content required for department final accounts, and confirm that field matching meets business requirements.
- View the authentication result returned by the interface, confirm that no secret-related error messages appear, and verify the validity of the `Authorization` configuration.
- Call the interface to pull a single subordinate unit statement data, check if the data update time matches the final account cycle of the corresponding year, and confirm data source adaptability.
- Simulate a request to batch pull data from multiple systems, check if the interface response duration matches business processing rhythm, and confirm the rationality of the timeout configuration.
