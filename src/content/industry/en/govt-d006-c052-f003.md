# Document and Material Drafting for Department Final Accounts and Financial Reports: Multi-turn Dialogue and Prompts

This document is compatible with FastGPT v4.17.0.

## What Data Looks Like for This Category
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency follows an annual cycle. Daily produced documents and materials include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The document structure follows unified fiscal standards, including standardized fields such as income and expenditure details, assets and liability items. Maintenance and filling are handled by entities such as the budget unit’s finance department and the treasury department of the finance bureau.

## Constraints on Multi-turn Dialogue and Prompts
Because data comes from multiple independent systems, multi-turn dialogue must pull reconciliation data from different systems step by step. This avoids context overload. The annual update feature requires prompts to bind to the current fiscal year’s context. This prevents referencing non-current year data. The standardized document structure requires prompts to preset field rules for fiscal reports. This ensures generated final account explanations and report notes conform to unified formats. The most time-consuming account statement reconciliation step requires multi-turn dialogue to guide gradual matching of income and expenditure data with treasury payment records. This reduces manual reconciliation workload. The serious consequences of errors require the dialogue flow to include caliber verification steps. This prevents public data caliber errors.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique value based on unit + year | Ensures isolation of dialogue context across different budget units and years, preventing data confusion |
| `messages` | Concatenate and group by fiscal document fields | Concatenate historical dialogue in the order of final account statements, treasury data, and accounting vouchers, aligning with business logic |
| `variables` | Preset current fiscal year and unit code | Provide fixed context parameters for prompts, ensuring unified caliber of generated content |
| Maximum context length | 800–1200 characters | Matches the typical length of annual final account documents, avoiding logical confusion caused by context overload |
| Dialogue timeout threshold | 600 seconds | Accommodates the time required for pulling data from multiple systems and reconciling accounts and statements, preventing mid-process interruptions |
| Dialogue rearrangement rule | Reverse chronological order | Prioritize displaying the latest reconciliation results for quick identification of discrepancies |

## Three Common Mistakes
- Phenomenon: Dialogue context is lost, and historical reconciliation data cannot be traced. Cause: No exclusive `chatId` is set. This causes dialogue context to be shared across different units, triggering the default 7-day dialogue file expiration rule.
- Phenomenon: Generated final account explanations do not match report fields. Cause: Prompts are not bound to the unit code and fiscal year parameters in `variables`. This leads to inconsistent caliber of generated content.
- Phenomenon: Results are cross-mixed when running 3 AI dialogue nodes in parallel. Cause: No independent `chatId` is assigned to each dialogue node. This causes context interference across different nodes.

## How to Verify Correct Configuration
- Manually create a test dialogue for a single unit and single year. Check that the context only includes relevant data for that unit and current year.
- Trigger a batch execution flow that includes 3 dialogue nodes. Verify that each dialogue node has a unique `chatId` and no context crossover occurs.
- Generate a final account explanation document. Check that fields conform to the preset fiscal report format.
- View dialogue logs. Confirm that each record is associated with the corresponding unit and year identifier.
