# Document and Material Drafting for Department Final Accounts and Financial Reports: Tool Calling and Plugins

## What the data for this category looks like
Core data for this category comes from four fiscal business systems: the budget management integration system, the centralized treasury payment system, the accounting system, and the asset management system. Daily produced documents and materials include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The structure covers standardized report data and unstructured explanatory text. Data is updated annually. Fields follow unified fiscal specifications, covering core content such as actual revenue and expenditure, assets and liabilities, and budget execution differences.

## What constraints these characteristics impose on tool calling and plugin workflows
The annual update feature means tool calling does not need frequent triggering, making it suitable for batch annual final account process handling. Data from multiple system sources requires plugins to support multi-source data pulling and format unification, to avoid cross-system caliber deviations. Complex document structures require tool calling to distinguish generation logic between structured report data and unstructured explanatory text, to ensure output complies with fiscal document specifications. Strict error consequences require tool calling to configure parameter verification and result checking steps, to prevent report returns or caliber mismatches caused by calling errors. Standardized field requirements mean plugin function parameters must strictly match preset fields of fiscal reports, to ensure compliance of generated content.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or `required` | Department final accounts must strictly follow preset plugin logic for execution, avoid the model from independently selecting irrelevant tools, to ensure compliant calling |
| `functionCall` | Bind plugin functions for fiscal data pulling and report verification | Must accurately call data interfaces of corresponding fiscal systems to generate required document content |
| Plugin import path | Custom plugin folder under the "Plugin Management" directory in the FastGPT backend | The plugin configuration path for FastGPT v4.17.0 is a fixed backend directory, facilitating unified management |
| Plugin Schema import | Import using JSON format files | Can quickly reuse developed fiscal report verification plugin structures, avoid manual configuration errors |
| Tool call timeout | 600-1200 seconds | Pulling data across fiscal systems takes a long time; insufficient timeout settings will cause calling failures |
| Result verification threshold | Calibrate based on actual testing | Must match the caliber consistency requirements of fiscal reports, avoid verification deviations |

## Three Common Configuration Mistakes
- Phenomenon: The plugin cannot be found in the workflow after import, and the interface displays an error "specified plugin not found". Cause: The plugin file was not placed in the correct directory of FastGPT backend "Plugin Management", or the service was not restarted to load the plugin.
- Phenomenon: Tool calling returns empty results, or fields do not match the fiscal report format. Cause: The plugin function for corresponding fiscal data was not bound in `functionCall`, or the plugin Schema does not match preset report fields.
- Phenomenon: Tool calling times out and interrupts, and the generated final account explanation does not include budget execution difference content. Cause: The tool calling timeout setting is too short, failing to reserve sufficient time for cross-system data pulling.

## How to Confirm Configuration is Complete
- Enter the FastGPT backend "Plugin Management" page, confirm the target plugin is displayed in the list and its status is enabled.
- Initiate a test call, check the tool calling log, confirm the plugin function was triggered correctly, and returned fields match fiscal report requirements.
- Check the `toolChoice` parameter configuration, confirm the preset plugin calling logic is bound in the workflow, and no irrelevant tools are called independently.
- Simulate the annual final account data pulling process, verify that tool calling time meets the preset timeout settings, and no interruptions occur.

The values provided are common starting points and should be measured against the reader's own samples.
