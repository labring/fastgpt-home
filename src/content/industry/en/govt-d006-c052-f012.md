# Document and Material Drafting for Department Final Accounts and Financial Reports: Deployment and Upgrade

## What data for this category looks like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system, with an annual update cycle. Daily generated documents and materials include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Documents contain fixed-format reporting fields, revenue and expenditure details, asset and liability data, difference explanation notes, and other content. Fields must match the standard format of fiscal systems, and units are mostly ten thousand yuan, yuan, and other fiscal measurement standards.

## What constraints these characteristics impose on deployment and upgrade
The annual update cycle of this category creates annual peak data processing pressure. Resource thresholds adapted for batch data import must be configured during deployment. The need to connect data from multiple systems requires deployment to support multi-database connection configuration, to avoid reliance on a single data source. Fixed-format fiscal document requirements mean field matching rules must be preset during deployment, and the parsing logic of original reporting templates must be compatible during upgrades. Errors may affect audit and public reporting standards, so data verification nodes must be added during deployment and upgrade to prevent abnormal data from entering the generation phase.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Requires sufficient database connection pool for annual peak data processing, to avoid connection exhaustion, and adapts to the connection pool mechanism of FastGPT v4.17.0 |
| `PG_URL` | Connection address pointing to the synchronized database of the unified budget management system | Core data for this category comes from the unified budget management system, so direct connection to the dedicated PostgreSQL database is required |
| `REDIS_URL` | Local deployment dedicated Redis instance address, with memory configuration of 4096 MB or higher | Requires caching intermediate data for batch processing to ensure stability of annual data synchronization |
| `STORAGE_S3_ENDPOINT` | Endpoint pointing to the unit's internal file storage service | Required to store large documents such as annual final account statements and balance sheets, to ensure data persistence |
| `FE_DOMAIN` | Unit's internal office domain name | Restricts access scope to ensure security of internal fiscal data |
| `ROOT_KEY` | Calibrated based on actual testing | Used for administrator permission verification, must match the unit's internal security policy |

## Three common mistakes
- Phenomenon: Input text lags when there are many nodes in the local deployment workflow configuration interface. Cause: Front-end resource allocation is not optimized for annual batch data processing, and too many hidden configuration items are loaded during node rendering, leading to excessive memory usage.
- Phenomenon: Database connection errors occur after executing the `docker compose pull` upgrade command. Cause: Original data source configurations such as `PG_URL` and `REDIS_URL` were not retained during the upgrade, causing the container to fail to connect to the original fiscal system database after restarting.
- Phenomenon: The generated final account explanation document lacks the budget execution difference explanation field. Cause: Fixed field mapping rules for fiscal documents were not preset during deployment, and the original custom field matching configuration was overwritten after the upgrade.

## How to confirm the configuration is correct
- Execute an annual simulated data import task, check that the database connection pool connection count does not become exhausted, and confirm that the `DB_MAX_LINK` configuration takes effect.
- Access the internal address specified by `FE_DOMAIN`, verify that the front-end interface can normally load fiscal document template configuration items, and confirm that the `FE_DOMAIN` configuration is correct.
- Upload a test final account statement document, check whether the storage service normally receives and stores the file, and confirm that the `STORAGE_S3_ENDPOINT` configuration is valid.
- Attempt to log in to the system backend using the administrator key, verify that the `ROOT_KEY` configuration can complete permission verification normally.

The values provided are common starting points and should be measured against the reader's own samples.
