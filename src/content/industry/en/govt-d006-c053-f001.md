# Document and Material Drafting for Departmental Budget Preparation: HTTP Interfaces and External Systems

## What this category of data looks like
Common data sources include the budget management integrated system, departmental staffing establishment system, prior year final accounts, project repository, and Ministry of Finance budget preparation notices. Data is updated once annually. Daily generated documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approval documents. Common document fields include unit establishment number, personnel expense standard, project expenditure details, and performance indicator values. Units are ten thousand yuan and person.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
Data sources for this category are scattered and involve specialized fiscal standards. The annual update rhythm requires interface calls to adapt to the annual budget preparation time window. Field differences across multiple data sources require passing unified field mapping rules via `variables` in requests to ensure matching data formats across different systems. The sensitivity of fiscal data requires the `Authorization` parameter to use authentication methods compliant with internal system specifications to prevent permission leaks. Summary documents have large data volumes, so single request return limits must match the data scale to prevent transmission timeouts or truncation.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Adopt the Bearer Token format specified by fiscal internal systems, validity period matches the budget preparation cycle | Complies with authentication specifications of fiscal systems, prevents permission failures from interrupting budget workflows |
| `variables` | Pass key-value pairs for field mappings including unit establishment number, project expenditure details, performance indicators | Unifies field formats across multi-source heterogeneous data, ensures accuracy of fields in generated documents |
| `responseData` | Only extract core fields of budget drafts and performance target forms | Filters redundant data, reduces transmission and parsing overhead |
| Request timeout | 600–1200 seconds | Matches average response delay of internal data queries in fiscal systems |
| Request retry count | 2–3 times | Addresses request failures caused by temporary fluctuations in fiscal systems |
| Return data format | JSON format | Complies with parsing rules of FastGPT v4.17.0, facilitates subsequent calls for document generation |

## Three common misconfigurations
- Phenomenon: Interface returns 401 unauthorized error, or requests are intercepted by fiscal systems. Cause: The `Authorization` parameter is not configured correctly, using authentication methods that do not meet fiscal system requirements.
- Phenomenon: Generated budget documents have missing fields or incorrect values. Cause: Accurate field mapping rules are not passed via `variables`, leading to field mismatches across multi-source data.
- Phenomenon: Interface requests time out or returned data is truncated. Cause: Reasonable request timeout is not set, and the scope of returned data fields is not limited, exceeding system transmission thresholds.

## How to confirm configurations are properly set
- Call the test interface, check the returned authentication status code to confirm that the `Authorization` parameter configuration meets the requirements of the target fiscal system.
- Export the `variables` parameter of the request, verify that the passed fields match the document fields required by the fiscal system.
- Simulate a single request, check that the returned `responseData` only contains the required core document fields with no redundant data.
- Observe the response duration of interface calls, confirm that it does not exceed the preset timeout range.
