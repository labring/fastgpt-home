# Document and Material Drafting for Departmental Budget Preparation: Vector Models and Indexes

## What this category of data looks like
Departmental budget preparation data typically comes from the unified budget management system, departmental staffing system, prior-year final accounts, project library, and Ministry of Finance budget preparation notices. Daily processed documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approval documents, and others. Some documents are structured tables with fields such as staffing numbers, project funding amounts, performance indicators, with units mostly in ten thousand yuan and persons. Data update frequency is annual; full updates and aggregation are completed only during the annual budget preparation cycle.

## What constraints do these characteristics impose on the vector models and indexes workflow
The data characteristics of departmental budget preparation impose multiple constraints on the vector models and indexes workflow. Annual full updates require the indexing process to support batch data processing, to avoid single indexing timeouts. Structured table documents require that chunking does not split cell content, to prevent field information from being broken. Cross-system data association requirements for multi-source data mean indexes must support unified vector embedding of cross-system data, while avoiding confusion between identically named fields from different sources. The presence of specialized terminology and fixed units requires retrieval results to match semantic accuracy and format consistency, to ensure valid content can be directly referenced during review.

## Three common misconfigurations
- The number of chunks displayed in the interface does not match the actual number of index segments. For example, upload shows 8 segments, then later changes to 13 segments with duplicate entries. The cause is that the chunk overlap length is set too high, and document deduplication configuration is not enabled, leading to the same content being split and indexed multiple times.
- Unable to retrieve existing document content after upgrading the version. For example, historical queries return no matching results. The cause is that the vector model embedding dimension changed in the new version, and the original index was not regenerated. A full reindex must be performed.
- Incorrect indexing results for Excel-format budget calculation forms. For example, retrieved content has missing fields or mixed units. The cause is that Excel structured parsing configuration is not enabled, leading to table cell content being incorrectly spliced into meaningless paragraphs.

## How to verify correct configuration
- Upload a single typical document, such as a personnel expense calculation form, and check the chunk preview interface. Confirm that each chunk contains complete single-item calculation content, with no split field breaks.
- Perform a cross-source retrieval test, enter a query containing keywords for subordinate unit budget entries. Confirm that retrieval results cover the preset search limit quantity, with no obvious duplicate entries.
- After upgrading the version, perform a full reindex operation for all historical documents, and verify that retrieval results match those before the upgrade.
- Upload an Excel-format budget document, check the indexed fragments. Confirm that cell content is fully retained in row and column order, with no mixed units or fields.
