# Document and Material Drafting for Departmental Budget Preparation: Document Parsing and Chunking

## What this category of data looks like
Service subjects typically include finance bureau budget departments, budget unit finance departments, and similar roles. Daily processed documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and related materials. Data mostly originates from unified budget management systems, departmental staffing systems, prior-year final accounts, project repositories, and Ministry of Finance budget preparation notices, and is updated annually. Most documents contain structured fields such as unit codes, project amounts, staffing numbers, and performance targets, alongside explanatory text. Some documents feature cross-system associated nested data structures.

## Constraints Imposed on Document Parsing and Chunking
The annual update requirement means the parsing process must adapt to format differences between bulk historical data and newly added documents from the current year. Multi-source nested data structures require accurate identification of cross-system associated fields, to avoid splitting associated information during chunking. Documents mixing structured fields and explanatory text need differentiation between core budget data and auxiliary explanatory content, to prevent chunking from destroying budget project integrity. Format differences across document types require parsing rules with type adaptability, to avoid field loss or redundancy caused by uniform chunking logic.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the description length of individual items in budget documents, avoiding splitting core budget project information |
| `chunkSplitter` | By paragraph + title hierarchy | Matches the title hierarchy and paragraph structure of budget documents, preserving the logical integrity of project applications and calculation explanations |
| `customPdfParse` | Enable structured parsing mode | Adapts to the common format of multi-table nesting in budget documents, accurately extracting budget data and associated explanations within cells |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Compatibility with the common size of bulk-imported prior-year final accounts and project repository documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of large budget draft documents, avoiding timeout interruptions |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for different types of budget documents, adapting to differentiated document structures |

## Three Common Errors
- Phenomenon: Some PDF-format budget documents fail to parse, and the interface displays a parsing failure status. Cause: The structured parsing mode of `customPdfParse` is not enabled, so nested multi-table structures in budget documents cannot be identified.
- Phenomenon: Uploading a large departmental budget file triggers a timeout error, returning status code 504. Cause: The configured value of `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual parsing time of the document.
- Phenomenon: Calling the document parsing tool in a workflow returns empty fields or scattered text. Cause: Chunking rules for budget documents are not matched, splitting complete budget projects into unrelated scattered text chunks.

## How to Verify Correct Configuration
- Upload a single typical budget document, such as a project application form, and confirm whether the parsed text blocks retain complete project titles and amount information.
- Check if the `UPLOAD_FILE_MAX_SIZE` configuration covers the maximum document volume currently being imported, and upload a test file of the corresponding size to verify no truncation or upload failure occurs.
- Review the configured value of `PARSE_FILE_TIMEOUT_SECONDS`, compare it with the actual parsing time of bulk large documents, and confirm no early interruptions occur.
- For different types of budget documents, adjust the chunking rules and verify the field integrity of the parsing results.

The values provided here are common starting points and should be measured against the reader's own samples.
