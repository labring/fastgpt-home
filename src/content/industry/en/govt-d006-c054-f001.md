# Document and Material Drafting for Flood Prevention, Disaster Mitigation and Emergency Duty: HTTP Interfaces and External Systems

## What this category’s data looks like
This category of data typically originates from meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance, with a daily update frequency. Documents produced daily include duty records, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Most data fields include real-time monitoring values such as precipitation and water level, event occurrence time, early warning levels, statistics related to personnel transfer and material allocation, and the document structure primarily uses structured fields paired with free text descriptions.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multi-source data access requires interfaces to support adaptation to authentication rules and data formats of different business systems, to prevent deviations in document content caused by field mismatches. Fixed update frequencies require interfaces to be configured with appropriate polling or trigger mechanisms to ensure data timeliness. The diverse range of document types requires interfaces to support dynamic adjustment of field mapping rules, to adapt to different document structures such as duty records and early warning notices. Additionally, the high-risk nature of emergency scenarios requires interfaces to be configured with timeout, failed retry, and abnormal alert mechanisms, to avoid delays in document drafting and emergency response processes caused by interface failures.

## How to configure
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry the Bearer Token issued by the business system | Adapt to authentication rules of multi-source business systems, ensure legitimacy of interface calls |
| Polling Interval | 600–1800 seconds | Match the daily data update frequency, balance timeliness and interface call costs |
| `variables` | Bind variable mappings for monitoring fields such as hydrology and meteorology | Enable automatic matching of business system data to document template fields |
| Retry Count | First 3 attempts | Address temporary network fluctuations, avoid data synchronization interruptions caused by a single interface failure |
| `responseData` | Extract structured fields and free text content | Adapt to content extraction needs for multiple document types, simplify subsequent document drafting logic |
| Timeout Duration | 30 seconds | Match response timeliness requirements in emergency scenarios, avoid long-term blocking of processes |

## Three common mistakes
- Symptom: An error `Failed to connect to [system identifier]:[port]` is returned when calling external system interfaces, with status codes mostly 500 or timeout. Cause: No interface call whitelist or port mapping has been configured, causing the FastGPT node to fail to access the business system normally.
- Symptom: Generated documents contain large amounts of redundant or irrelevant content, with inaccurate field matching. Cause: No corresponding fields of business data have been bound via the `variables` configuration, and full interface return content is directly injected into the document template.
- Symptom: Interface calls directly return original response data, without generating required document content. Cause: The interface return result has not been integrated into the document generation process, and only the original interface return content is output.

## How to verify correct configuration
- Call the test interface, check whether the core monitoring fields of the business system are included in the return results, and verify that the field mapping matches the configured settings.
- Simulate a data update from the business system, check whether FastGPT can synchronize the latest data at the configured polling interval.
- Trigger the document generation process, confirm that the generated content includes structured data and free text descriptions returned by the interface.
- View the interface call logs, confirm that the authentication parameter `Authorization` has been correctly included, and that there are no timeout or failed retry exceptions.
