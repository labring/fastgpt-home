# Document and Material Drafting for Flood Prevention, Disaster Mitigation and Emergency Duty: Workflow Orchestration

## What Data for This Category Looks Like
The core data for this category comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance, with a daily update frequency. Commonly generated documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Fields typically cover rainfall and water level values, danger locations, material category and quantity, personnel transfer information, and more. Units include millimeters, meters, pieces, person-times, and others. Required fields and format requirements vary across different document types.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Multiple data sources and daily update frequency require the workflow to include a scheduled trigger node, which pulls the latest data from each system at fixed intervals. Differences in fields and formats across documents require the workflow to set up branch nodes to match corresponding processing logic based on the generation task type. Real-time cross-department scheduling needs for disposal require the workflow to support storing real-time disaster, material, and personnel dynamic data via `variables`, and associating information transfer nodes across different departments via `nodeId`. Data missing or delays will directly impact disposal effectiveness, so the workflow must be configured with an exception handling node to trigger alerts when data anomalies occur.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Cycle | 3600 seconds | Adapts to the daily data update frequency and meets the real-time requirements of emergency disposal. FastGPT v4.17.0 supports this cycle configuration |
| Branch Node Trigger Rule | Match by generated document type | Covers different field requirements for multiple types of documents such as duty logs and warning notices |
| `variables` Storage Fields | Rainfall data, water level data, material list, personnel transfer information | Stores core dynamic data required by the workflow for subsequent generation nodes to call |
| `nodeId` Association Rule | Bind corresponding processing templates by data source node | Unifies the format of data from different systems and avoids missing fields in generated content |
| Exception Trigger Threshold | Trigger alert when data missing rate ≥10% | Intervenes in data anomalies in a timely manner to prevent generation of incorrect response documents |
| Response Content Format | No leading line breaks | Adapts to scenarios where documents are pushed directly and avoids format issues |

## Three Common Misconfigurations
- Plugins referenced after importing a workflow from another environment cannot be located. Phenomenon: When the imported workflow is opened, configured plugins display an unbound status. Cause: Only the basic workflow JSON file was exported, and local plugin configuration information was not exported synchronously, so the new environment cannot recognize plugin parameters.
- Empty results are returned when using text2sql to generate statements in the workflow. Phenomenon: No SQL statements are output after calling the text2sql node. Cause: Real-time disaster data stored in `variables` was not passed to the node as a query condition, leading to an unclear query scope and failure to generate valid statements.
- AI conversation nodes in the workflow generate content that starts with a line break. Phenomenon: An extra blank line appears at the start of generated consultation minutes and warning notices. Cause: The automatic line break setting for AI responses was not disabled, or leading line break truncation processing was not applied to the output content.

## How to Verify Correct Configuration
- Manually trigger the workflow and check if each data node has pulled the latest rainfall, water level, and disaster data from the corresponding systems.
- Switch between different document generation types to confirm that the branch node correctly calls the corresponding template to generate content that meets format requirements.
- Simulate a single-source data missing scenario to verify that the exception node triggers an alert and pauses workflow execution.
- Review the final generated document content to confirm there are no extra leading line breaks and that field formats meet requirements.
