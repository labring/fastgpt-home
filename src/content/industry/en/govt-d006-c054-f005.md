# Document and Material Drafting for Flood Prevention, Disaster Mitigation and Emergency Duty: Tool Calling and Plugins

## What the data for this category looks like
The core data for this category comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Update frequency is mostly daily or real-time triggered. Daily produced documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Most document structures include fields such as timestamps, geographic scope, quantitative monitoring values, and response measures. Units involve specific measurement identifiers like millimeters of rainfall, cubic meters of flow, number of personnel, and number of material items. The priority of core fields varies across different documents.

## What constraints these characteristics impose on the "tool calling and plugins" link
Data sources for this category are scattered and update quickly, requiring tool calling to support parallel pulling of multi-source data to avoid delays caused by single-interface calls. Daily documents contain a large number of quantitative fields with units and geographic identifiers, so plugins must have the ability to recognize fields and standardize units to ensure the accuracy of drafted content. The fast pace of emergency response requires the response time of tool calling to match real-time disposal needs, while also adapting to the format requirements of different document templates to avoid generated content that does not align with business specifications. Cross-department collaboration scenarios also require plugins to support permission adaptation to ensure that pulled data complies with the access scope of different entities.

## How to Configure the Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call timeout | 60–120 seconds | Matches the real-time response requirements of emergency scenarios, avoiding excessive delays that affect document drafting efficiency |
| Multi-tool parallel call switch | Enabled | Adapts to the needs of multi-source data pulling, reducing total time spent on single calls |
| `toolChoice` | auto | Lets the model independently select appropriate tools to complete data pulling and field extraction, adapting to multi-type document scenarios |
| Field standardization plugin | Calibrated based on actual testing | Performs standardization processing on quantitative fields with units such as rainfall and flow, meeting the format requirements of business documents |
| `functionCall` | Enabled | Forces the model to call tools in the specified function format, ensuring that the structure of generated document content complies with emergency management specifications |
| Number of returns per single tool call | First 5 items | Avoids returning excessive redundant data, compresses context length, and improves generation speed |

## Three Common Mistakes
- An `unAuthApiKey` error is returned when calling tools. The cause is that the API key for tool calling is not configured correctly, or the key permissions do not cover the access scope of the corresponding data source.
- Abnormal data acquisition occurs when calling a large model that only supports stream mode. The cause is that stream mode adaptation is not enabled in the model configuration, causing the model return format to not match the tool calling requirements.
- Abnormal number of returned results occurs after configuring multi-tool parallel calls. The cause is that the return limit for single tool calls is not set, leading to context overload and affecting subsequent document generation logic.

## How to Confirm the Configuration is Correct
- Initiate a simulated call to check whether the data source data returned by the tool matches the preset meteorological and hydrological system data.
- Check whether the units of quantitative fields in the generated document content comply with business specifications, confirming that the field formatting plugin is active.
- View the call log to confirm that the tool call timeout has not triggered a timeout error, and that the response time meets expectations.
- Test the configuration effects of the `toolChoice` or `functionCall` parameters, confirming that the model can correctly call the specified tools to complete data extraction.

The values given are common starting points and should be measured against the reader's own samples.
