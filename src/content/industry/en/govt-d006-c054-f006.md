# Document and Material Drafting for Flood Prevention, Disaster Mitigation and Emergency Duty: Source Citation and Traceability

## What data in this category looks like
Data for this category comes primarily from weather warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance.
Daily generated documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips.
Each document contains fields such as timestamp, monitoring point, quantitative indicators, and disposal status. Some fields use fixed units: water level is measured in meters, rainfall in millimeters.
Data typically updates daily. Some real-time monitoring nodes have shorter update intervals.
All data is generated for emergency response and daily duty scenarios.

## Constraints on source citation and traceability
This category has scattered data sources, diverse document types, and some fields with fixed units. These factors create multiple constraints for the citation and traceability process.
Users must link multiple data sources including meteorological, hydrological, and grassroots disaster reporting systems. This ensures the scope of cited content aligns with emergency response needs.
Citation format requirements vary by document type. Consultation minutes must clearly mark the source of monitoring points and quantitative indicators. Material allocation slips must correspond to grassroots disaster reporting application records.
Fields with units must be fully preserved during citation. Missing units can lead to incorrect data interpretation.
Emergency scenarios have strict timeliness requirements. Cited data sources must be the most recently updated content. Lagging information may negatively impact decision-making.

## How to configure the settings
This page’s configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Emergency documents are compact. This range retains core monitoring data and response basis within limited token limits, avoiding exceeding model context restrictions |
| `responseData` | Enabled | Generated documents must clearly mark data source systems and update times to meet traceability requirements for emergency duty |
| `detail` | Enabled | Details such as monitoring points, quantitative indicators, and units must be preserved. Simplification can lead to inaccurate data |
| Single recall limit | Top 3–5 entries | Emergency scenarios require quick access to core data. Excessive recalled content increases processing time and harms timeliness |
| Data source matching rule | Match by timestamp | Emergency data has strong timeliness. Timestamps must be used to link monitoring data and document content from the same time period |

## Three common configuration mistakes
- Normal interface response but no returned content after calling the tool: The data source matching rule is not configured correctly, so the model cannot match valid citation data. Or the value of `quoteMaxToken` is too small, truncating core citation content.
- Garbled text in cited content: Unified preprocessing is not applied to data source formats across multiple systems. Inconsistent encoding formats between systems cause garbled text during model parsing.
- Cited knowledge base content missing from the main text: The `responseData` configuration item is not enabled. Or the single recall limit is set too low, so valid knowledge base entries are not recalled.

## How to verify correct configuration
- Import a single emergency document for testing. Check if the generated document includes source annotations for corresponding monitoring data.
- View the call log. Confirm that the returned result contains data source detail fields, and the field content is complete and free of garbled text.
- Adjust the value of `quoteMaxToken`. Verify that the length of the generated content meets expectations, with no core content truncated.
- Simulate a multi-data source call. Check if the model can correctly link monitoring data from different systems to corresponding document processes.

The values given are common starting points and should be measured against the reader's own samples.
