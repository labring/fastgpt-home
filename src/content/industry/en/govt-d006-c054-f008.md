# Document and Material Drafting for Flood Prevention, Disaster Mitigation and Emergency Duty: Document Parsing and Chunking

## What the data for this category looks like
Daily documents for this category include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, material transfer slips, and more. Data sources include meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. The update frequency is daily. Most documents combine structured fields and unstructured text. For example, duty logs record time periods, on-duty personnel, rainfall and water level values, while material transfer slips mark categories, quantities, transfer locations, and other information.

## What constraints these characteristics impose on the "document parsing and chunking" link
Multi-source and heterogeneous data sources lead to differences in document layout and format exported by different systems, which creates requirements for parsing and adaptation capabilities. The high-frequency daily update feature requires the document parsing and chunking process to be efficient, to avoid delays that affect emergency response links. Documents contain both structured professional values such as water levels and rainfall, and unstructured text for cross-departmental collaboration. Chunking must retain the association between fields to prevent loss of key context after splitting. At the same time, documents in emergency scenarios are mostly generated immediately, and may have non-standard formats, requiring flexible parsing rules to adapt to non-standard content.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Most documents in this category combine structured values and text. This range retains the complete context of a single rainfall, water level or consultation entry, avoiding field association breakage after splitting |
| `chunkSplitter` | Split by paragraph + fixed character truncation | Adapt to the mixed format of multi-source documents. Prioritize splitting by natural paragraphs, and truncate by characters when exceeding `chunkSize` to retain semantic integrity |
| `customPdfParse` | Enabled | Warning notices and consultation minutes in this category are mostly in PDF format. Enabling this option retains the original layout and field hierarchy, improving parsing accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 seconds` | Emergency documents may contain multiple high-definition attachments or multi-page content. 120 seconds covers conventional parsing durations, avoiding upload failures caused by timeouts |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types such as duty logs and material transfer slips. Manual configuration enables precise control |

## Three Common Misconfigurations
- Phenomenon: After uploading a multi-column Excel document such as a network segment log, only the first two columns are recognized, and the remaining fields are missing. Cause: No multi-column parsing rules are configured. The default logic only parses two columns: title and content, and does not adapt to the structured table format with multiple fields.
- Phenomenon: After enabling PDF parsing, the table fields of the hydrological monitoring report cannot be fully extracted. Cause: The `customPdfParse` configuration is not enabled. The default parsing logic cannot adapt to professional PDF table formats.
- Phenomenon: When searching after chunking, all content from the same consultation cannot be associated and found. Cause: The `chunkSize` setting is too small, splitting a single consultation minute into multiple chunks and losing context association.

## How to Confirm the Configuration Is Correct
- Upload a typical document such as that day's duty log or material transfer slip, and check whether the parsed text retains all structured fields and original layout.
- Adjust the chunking parameters, then check whether the chunk content in the chunking preview interface covers complete single business information, without field splitting breakage.
- Test uploading documents in multiple formats including Excel, PDF, and TXT, and confirm that the parsing results of each format meet expectations.
- Conduct high-frequency upload tests to confirm that the parsing timeout configuration does not trigger errors.
