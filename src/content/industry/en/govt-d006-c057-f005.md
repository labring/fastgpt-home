# Document and Material Drafting for Food Safety Supervision and Sampling: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from food safety sampling monitoring systems, the State Administration for Market Regulation sampling results query system, laboratory LIMS systems, and food producer and operator ledgers.
Data updates occur monthly.
Core documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements.
Most documents combine structured tables and standardized official document templates. Fields include sampling number, inspection items, non-conformity judgment basis, disposal measures, and more. All documents must strictly follow the unified document format requirements set by regulatory authorities.

## Constraints on tool calling and plugin workflows
Monthly updated data sources require tool calling to support batch pulling and incremental synchronization logic, to avoid repeated processing of historical data.
Scenarios with multiple types of mixed structured documents require plugins to support field mapping rules for different documents. For example, mapping fields from inspection reports exported from LIMS to required fields in verification and disposal reports.
Unified regulatory format requirements mean documents generated by tools must strictly follow preset templates, with no arbitrary adjustments to field order or wording.
Documents related to non-conformity disposal must be linked to corresponding sampling numbers and inspection data. Tool calling must ensure consistency across data links, to avoid field mismatches or data misalignment.
Additionally, the `toolChoice` configuration must be used to automatically match scenarios, and `functionCall` must be used to enforce structured output, to ensure generated content meets regulatory requirements.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically matches tool calling logic for sampling document drafting scenarios, adapting to mixed processing needs for multi-source documents |
| `functionCall` | `enabled` | Forces structured output, ensuring generated document fields comply with unified format requirements from regulatory authorities, and follows FastGPT v4.17.0 plugin loading rules |
| Single tool call duration limit | `300–600 seconds` | Reserves sufficient time to pull multi-source data and complete field mapping when processing monthly batch sampling plans, avoiding timeout interruptions |
| Document parsing tool switching configuration | Modify corresponding configuration items per plugin documentation | Adapts to document formats from different sources, such as processing LIMS exported files under 100 MB and official document templates exported from market supervision systems |
| Context window size | `8000–12000 token` | Fully carries associated data from sampling plans, sampling slips, and inspection reports, avoiding truncation of critical information |
| Batch processing task limit | `Top 100 entries` | Calibrated based on actual testing, preventing excessive single processing data volume from causing platform resource overload |

## Three Common Mistakes
- Symptom: Plugin returns empty fields when processing uploaded sampling reports. Cause: No field mapping rules configured for the target document, and no binding between inspection data exported from LIMS and required fields in the document template.
- Symptom: Timeout errors occur when using the Doc2x plugin to process sampling corpus in a local WSL + Docker Compose deployment environment. Cause: Single tool call duration limit was not adjusted, and hardware resource scheduling delays in the Win11 environment caused processing timeouts.
- Symptom: Generated document format does not comply with regulatory requirements after replacing the document parsing tool. Cause: Template matching rules were not updated synchronously, and the field order output by the new parsing tool does not match the original template.

## How to Verify Proper Configuration
- Upload a standard sampling slip file, check if the tool calling returned content includes required fields such as sampling number, sampling date, and inspected unit name.
- Initiate a monthly batch sampling plan processing task, check if the task status completes within the preset duration, with no timeout error prompts.
- After modifying the document parsing tool configuration, upload an inspection report exported from LIMS, confirm that the non-conformity items in the generated verification and disposal report match the inspection data.
- Call the API interface, check if the returned result includes the data source file name associated with this processing.

The values provided are common starting points and should be measured against the reader's own samples.
