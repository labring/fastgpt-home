# Document and Material Drafting for Food Safety Supervision and Sampling: Source Citation and Traceability

## What this category of data looks like
This category of data covers standardized documents including sampling plans, sampling sheets, inspection reports, unqualified food verification and disposal reports, risk control notices, and similar materials. Data sources include the food safety sampling and monitoring system, the State Administration for Market Regulation sampling results query system, the laboratory information management system (LIMS) of inspection institutions, and account books of food producers and operators. Data is updated on a monthly basis. Documents include unified fields such as sampling number, inspection items, unqualified judgment basis, disposal process, and similar fields. All data is stored in a structured manner in accordance with regulatory requirements, with no custom non-general fields.

## What constraints these characteristics impose on the "source citation and traceability" link
Monthly updated data sources require the knowledge base to perform full synchronization on a regular basis to avoid citing expired sampling plans or inspection results. Format differences across multiple data sources require the traceability link to complete association matching through identification fields such as unified sampling numbers and inspection report numbers, to prevent cross-system data mismatching. The standardized document structure means that citation traceability must be strictly bound to specific fields such as inspection items and unqualified judgment basis, to ensure the accuracy of cited content. At the same time, traceability results must be directly associated with the original data generation system to ensure that evidence in the unqualified disposal link can be traced.

## How to set the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | Matches the average content length of a single inspection report or sampling sheet, to ensure complete citation of original data fragments |
| `responseData` | Enabled | Required to output document numbers, source systems and other identification information corresponding to the cited content, for traceability verification |
| `detail` | Full | Output the original text of the cited content and the storage path of the corresponding data source, to facilitate review by regulatory personnel |
| Single recall limit | Top 3 entries | Matches the number of sampling data entries associated with a single document, to avoid redundant results causing interference |
| Total knowledge base capacity limit | 1000 MB | Adapts to the full data storage requirements of monthly updates |
| Context window | Calibrated based on actual testing | Adapts to the scale of full knowledge base data updated monthly, to avoid exceeding system processing limits |

## Three common mistakes
- The symptom is a string of red numeric errors returned during invocation. The cause is that the `responseData` parameter is not configured correctly, causing the system to fail to match the source identification fields required for traceability.
- The symptom is that the output content does not include any source identification, making it impossible to confirm whether the content comes from the knowledge base. The cause is that the `detail` parameter is not enabled, and the original source information of the cited fragment is not returned.
- The symptom is that the original text of documents uploaded to the knowledge base cannot be viewed. The cause is that the `detail` parameter is not configured to enable full traceability, or the storage path of the corresponding data source system is not included in the knowledge base association scope.

## How to confirm the configuration is correct
- Initiate a dialogue for drafting a sampling report, and check whether the output content includes source identifiers such as sampling number and inspection report number.
- Check whether the output content includes cited fragments consistent with the original document, and confirm that there is no unnecessary truncation.
- Test invoking expired monthly data, and confirm that the system cannot cite data sources that have not completed synchronization.
- Check the system logs to confirm that the `quoteMaxToken` parameter does not trigger content truncation errors.

The values provided here are common starting points and should be measured against the reader's own samples.
