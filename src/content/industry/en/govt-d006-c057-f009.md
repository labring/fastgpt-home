# Document and Material Drafting for Food Safety Supervision and Sampling: Model Access and Configuration

## What the data for this category looks like
This category includes the following documents: sampling plans, sampling forms, inspection reports, non-compliant food verification and disposal reports, and risk control notices. Data sources are the food safety sampling monitoring system, the State Administration for Market Regulation sampling results query system, inspection institution LIMS systems, and food producer and operator ledgers. Data updates occur monthly. Single core documents have fixed fields:
- Sampling plans include batch number, sampling location, and time limit requirements
- Sampling forms include sample number, production unit, and inspection items
- Inspection reports include test values and judgment basis

## What constraints do these characteristics impose on the model access and configuration link
Monthly updated data requires model configuration to support regular synchronization of the latest sampling data, to avoid expired information in context. Multi-source data access needs configuration compatible with tool calling, to integrate scattered data from regulatory systems and LIMS. Fixed-field document structure requires model output to strictly match business fields, with no irrelevant or missing items. Severe error consequences require configuration to limit model generation deviation, to ensure document content complies with regulatory requirements. Different user scenarios require configuration to support permission isolation, to prevent data leaks.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | Single inspection report contains multiple sets of test data, and verification and disposal reports are lengthy, requiring coverage of complete document content |
| `quoteMaxToken` | 2000–3000 token | Used to extract key test data and judgment basis from inspection reports, to avoid context overflow |
| `temperature` | 0.2–0.4 | Ensures consistency of document format and business fields, to avoid generating irrelevant or deviant content |
| `toolChoice` | auto | Needs to call sampling monitoring systems, LIMS and other data sources to obtain real-time sampling data and test results |
| `AIPROXY_API_TOKEN` | Bind dedicated call key | Ensures data call permissions are only open to internal regulatory and inspection institutions, to prevent unauthorized access |
| `maxContext` | 10–15 days of historical data | Formulation of monthly sampling plans needs reference to recent sampling results, to avoid context redundancy |

## Three common mistakes
- Phenomenon: Generated sampling forms lack required fields such as sample number and inspection items, with empty content or non-compliant format. Cause: The configuration does not limit the model to reference preset fixed business fields, leading to generated content deviating from business requirements.
- Phenomenon: After enabling the tool calling function, the model does not output intermediate reasoning processes. Cause: Some models disable chain-of-thought output by default in tool calling mode, and the corresponding configuration is not adjusted to retain reasoning steps.
- Phenomenon: After configuring the local MCP service, the service cannot be selected during model calls. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to point to the local MCP address, or the key has not been granted permissions for the local service.

## Verification steps for FastGPT v4.17.0
### How to confirm the configuration is complete
- Manually trigger a single document generation task, check whether the generated content includes all required business fields and whether the format complies with specifications.
- Call tools to obtain sampling data of a specified batch, verify whether the model can correctly pull and integrate content from multiple system data sources.
- View model output logs, confirm that tool calling processes and thinking process outputs meet expectations.
- Simulate monthly data update, check whether the context configuration can correctly load recent sampling data without including expired information.

The values provided are common starting points and should be measured against the reader's own samples.
