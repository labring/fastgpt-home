# Document and Material Drafting for Warehousing and Logistics: Tool Calling and Plugins

## What the Data for This Category Looks Like
Warehousing and logistics-related documents and materials mainly include inbound orders, outbound orders, transportation dispatch orders, inventory ledgers, customs declarations, delivery receipts, and others. Data sources primarily come from warehouse management systems, transportation management systems, and scanned copies of offline paper documents. Update cycles are mostly real-time or scheduled daily synchronization. The length of a single document ranges from hundreds to thousands of characters. Some documents also include extended fields such as transportation routes and customs declaration numbers. Document structures are fixed, containing fields like document number, operation time, cargo quantity, storage location, responsible person, and amount. Units include pieces, tons, cubic meters, yuan, and others.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
The fixed, multi-field document structure requires tool calling to accurately match field rules to avoid missing key information. Real-time or high-frequency updated data requires plugins to support scheduled pulling or event triggering to ensure returned document content is up to date. Differences across multiple document types require tool calling to automatically switch to corresponding data interfaces based on document type. The high proportion of long documents requires tool calling to adapt to large text processing logic to avoid call failures due to excessive content length. In addition, the existence of offline scanned copies and multi-format documents requires plugins to integrate multi-format parsing capabilities to adapt to document data from different sources.

## How to Set the Configurations
This chapter’s configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically matches the tool calling logic required for warehousing and logistics documents, adapting to multiple document types such as inbound and outbound orders |
| `functionCall` | Enabled | Supports active calling of data pulling tools to obtain the latest warehousing document data |
| Single tool call timeout | 30 seconds | Data pulling for warehousing documents usually takes a short time; this timeout setting prevents blocking of the overall process |
| Tool return result cache duration | 1 hour | Warehousing inventory data has a high update frequency; this cache duration balances data timeliness and call efficiency |
| Maximum text length per tool call | 800–1200 characters | Adapts to the standard length of warehousing documents, avoiding call failures due to excessive text length |
| Document parsing tool switching | Select corresponding plugins based on document type | Adapts to multi-format documents for warehousing and logistics such as PDF, Excel, and paper scanned copies |

## Three Common Mistakes
- Phenomenon: After calling the OpenApi interface, the returned results do not show the warehousing document file names associated with the knowledge base. The cause is that the file tracing configuration for tool calling is not enabled, making it impossible to track the original documents used during the call.
- Phenomenon: Tool calling returns a timeout error with status code 504. The cause is that the single tool call timeout setting is too short, failing to adapt to the pulling time required for batch warehousing documents.
- Phenomenon: Only a dozen or so characters of input trigger full streaming output without calling tools. The cause is that `toolChoice` is incorrectly set to `none`, which disables the automatic tool calling logic and directly returns fixed results.

## How to Confirm the Configuration Is Correct
- Initiate a test request containing "query today's inbound orders" to check whether tool calling is triggered and structured data of the corresponding orders is returned.
- View the tool calling log to confirm that the returned results include standard fields for warehousing documents such as document number, cargo quantity, and inbound time.
- Test whether uploaded PDF-format warehousing documents can be parsed normally after replacing the document parsing tool, with no parsing failure prompts.
- Check the current value of the configuration item `toolChoice` to confirm it matches the preset automatic matching logic and has not been incorrectly set to `none`.

The values provided are common starting points and should be measured against the reader's own samples.
