# Survey and Design Document and Material Drafting: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Survey and design data primarily originates from project survey reports, preliminary design documents, construction drawing design files, project cost estimates, and similar materials. Data is updated alongside project design phases. The scheme design, preliminary design, and construction drawing design stages each produce exclusive documents for their respective phases. Individual documents typically range from tens to hundreds of pages, with structures including fields such as basic project information, professional design parameters, material specifications, construction requirements, and others. Parameter fields have clear units, such as building area (㎡), structural load (kN/㎡), reinforcing bar diameter (mm), and similar examples.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Survey and design documents are lengthy and produced in phases. Multi-turn dialogue must retain the context of the current design phase to avoid mixing parameters across phases. Documents contain a large number of professional parameters with units, so prompts must explicitly require output results to match the corresponding units to prevent unit errors. Different design phases have different data update frequencies, so the dialogue flow must support switching phase contexts to ensure the latest data for the current phase is used. Multiple professional terms are present, so prompts must limit usage to standard expressions within the survey and design field to avoid non-professional interpretations.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Survey and design documents are mostly long texts; this length adapts to professional paragraph structures and avoids splitting independent professional parameter units |
| Maximum Context | Previous 10 dialogue histories | Survey and design conversations need to retain phase parameters and requirement changes; excessive history will interfere with the accuracy of current responses |
| Variable Binding | Bind project-specific fields | Survey and design project parameters are independent; binding fields such as project number and professional type via `variables` allows accurate calling of corresponding document data |
| Timeout Duration | 120 seconds | Long document parsing and professional parameter calculation require longer processing time; this duration covers processing requirements for most survey and design scenarios |
| Question Optimization | Enabled | Survey and design requirement descriptions often include professional abbreviations; optimization improves matching accuracy for professional parameters |

## Three Common Configuration Errors
- Dialogue response times out, with the interface displaying a "request timed out" status or the backend log returning a timeout error code. The cause is failing to adjust the timeout configuration for survey and design long document parsing and professional parameter calculation; the default duration is insufficient to complete the full process.
- Generating an empty chart after calling the chart tool, with no visual content output. The cause is failing to bind project-specific parameter variables for survey and design; core data such as building area and load grade is not passed to the chart generation logic.
- The workflow does not automatically trigger an initial question after startup, requiring manual sending of the first instruction. The cause is failing to correctly configure the project trigger conditions bound by `variables`, and failing to associate the project startup event with the dialogue startup instruction.

## How to Verify Correct Configuration
- A test dialogue containing professional parameters is initiated, and the response content is checked against the document data for the current design phase.
- The number of retained dialogue histories is adjusted, and it is verified that old dialogue content no longer interferes with current responses once the set quantity is exceeded.
- A chart generation action is triggered, and the passed parameters are checked for survey and design-specific units and values.
- Workflow logs are viewed, and the binding relationship between `chatId` and `messages` is confirmed to correctly associate the current project.

The values provided are common starting points and should be measured against the reader's own samples.
