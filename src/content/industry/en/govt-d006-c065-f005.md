# Document and Material Drafting for Survey and Design: Tool Calling and Plugins
## What the Data for This Category Looks Like
Data mainly comes from full-cycle project documents including survey reports, preliminary design specifications, construction drawing review comments, site verification slips, and similar files. The update rhythm follows project progress, with dedicated data produced in the scheme design, preliminary design, and construction drawing phases respectively. The document structure includes fields such as project unique ID, survey point coordinates, structural load parameters, material specification models, approval process nodes, and more. Units involve professional engineering units such as meters, megapascals, square meters, and cubic meters. Individual document lengths range from thousands to tens of thousands of characters.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugin Workflow
Multi-source and scattered data sources require plugin configurations to support connecting multiple engineering data interfaces, to avoid missing information from a single data source. The specificity of professional fields and units requires the parameter verification logic of tool calls to adapt to engineering-specific fields, preventing valid data from being filtered by generic parameter verification. Dynamically updated data along with project progress requires plugins to support triggering data pulling based on project phases. The wide range of document lengths requires the context length configuration for tool calls to reserve sufficient space, to avoid truncation of long document content.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic tool scheduling across multiple survey and design links, covering multiple types of data calls required for document drafting |
| `functionCall` | `enabled` | Triggers structured parameter calls, making it easy to verify the format and unit compliance of engineering-specific fields |
| Plugin data source binding scope | Only associate dedicated data sources for the current project's survey and design phases | Prevent cross-project data from being mixed in, ensuring the accuracy of data sources for document drafting |
| Context length threshold | 8000–12000 characters | Adapt to the content transmission needs of long documents such as survey reports and construction drawing descriptions |
| Parameter verification rules | Enable engineering unit verification | Match the format requirements of professional units such as meters, megapascals, and square meters, preventing parameter errors |

## Three Common Mistakes
-  A `400 InternalError.Algo.InvalidParameter` error is returned when calling a tool, prompting that the tool parameters are invalid. The cause is that engineering unit verification is not enabled, and parameters with non-professional units are passed into the tool call logic, triggering parameter verification interception.
-  A plugin created online cannot be called in the process orchestration node. The cause is that the plugin has not been published to the available plugin library, or the plugin permissions for the corresponding project have not been bound in the process node.
-  The tool call returns an empty result or a format error. The cause is that the selected model does not support structured output in the `functionCall` format, making it impossible to correctly parse engineering field parameters.

## How to Confirm the Configuration Is Correct
This verification is based on FastGPT v4.17.0.
-  Initiate a document drafting test call, and check whether the returned tool call parameters include the dedicated fields and units of the current project.
-  View the plugin running logs, confirm that only the survey and design data of the currently bound project is pulled, and no cross-project data is loaded.
-  Test document inputs of different lengths, confirm that the context length configuration can fully carry the test document content without truncation.
-  Trigger a tool call, check whether a structured output result that meets engineering specifications is returned.
