# Documentation and Material Drafting for Survey and Design: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Survey and design data sources include on-site survey records, construction drawing design documents, industry specification standards, project budget estimates and change negotiation records. Update rhythm adjusts with project progress. Construction drawings and survey data update weekly after project initiation. Industry specifications receive new supplementary versions quarterly. Document structures include long-text specification clauses, bill of quantities with tables, and survey reports with coordinate points. Fields include project number, survey coordinates, material specifications, bearing capacity parameters and others. Units include meters, square meters, megapascals, cubic meters and other professional engineering units.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
Multi-source professional data requires limiting retrieval scope to the current project’s exclusive document collection to avoid cross-project data interference. Long-text specification clauses and structured coordinate data require retaining original formats and field associations during retrieval; do not split or damage tables or coordinate data. Polysemy in professional terms (such as "pile foundation" and "pile foundation") requires retrieval to support synonym expansion to improve recall accuracy. Frequently updated project data requires the knowledge base to support incremental synchronization to prevent generated documents from mismatching current project requirements due to expired data.

## Configuration Settings
These configurations are formulated based on FastGPT v4.17.0, and adapt to documentation drafting needs in survey and design scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision of professional terms and parameters in survey and design, filters low-relevance general specification content |
| `limit` | Top 10 entries | Controls the number of documents recalled per run, adapts to context length limits for documentation drafting |
| `searchMode` | Exact Match | Targets structured fields with coordinates and specification parameters to improve matching accuracy |
| `usingReRank` | Enabled | Performs secondary ranking on recalled survey reports and design texts to prioritize highly relevant content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands professional term queries to cover synonyms and near-synonyms in survey and design |
| `collectionIds` | Bind project-exclusive knowledge base ID | Limits recall scope to avoid interference from non-target cross-project data in retrieval results |

## Three Common Mistakes
- Phenomenon: Tool workflows call the knowledge base but return empty document references. Cause: Project-exclusive `collectionIds` are not bound, and the recall scope covers irrelevant cross-project survey data.
- Phenomenon: Some numerical fields are missing from uploaded survey bill of quantities tables. Cause: Format-preserving chunking rules are not configured for structured tables, leading to split and damaged table cell data.
- Phenomenon: AI-generated survey reports do not reference recalled professional specification clauses. Cause: `usingReRank` is not enabled, and highly relevant specification documents are pushed out of the context window by low-relevance general content.

## How to Confirm Proper Configuration
- Check `collectionIds` in the knowledge base configuration to confirm only the current survey and design project’s exclusive document collection is associated.
- Enter a query containing professional parameters, and verify that recall result fields and units match source data.
- Run a workflow including knowledge base retrieval and tool calls to confirm both functions trigger normally and return valid content.
- Upload a structured table to test the data set, and confirm all cell data is fully retained without missing values.

The values provided are common starting points and should be measured against the reader's own samples.
