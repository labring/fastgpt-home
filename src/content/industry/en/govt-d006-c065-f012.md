# Document and Material Drafting for Survey and Design: Deployment and Upgrade

## What the data for this category looks like
Documents and materials for survey and design originate primarily from full project cycle survey records, design construction drawings, change negotiation documents, and professional calculation reports. Update timelines align with project progress, with immediate updates when changes occur. Document structures include project numbers, professional chapters, parameter data tables, and drawing indexes. Fields include survey hole coordinates, soil layer thickness, load values, and material strength. Common units are meters, kilonewtons, megapascals, and cubic meters. Single document lengths range from several thousand to tens of thousands of characters.

## What constraints these characteristics impose on deployment and upgrade
Survey and design documents and materials are mostly long texts with professional parameters. Deployment must support storage and reading of large-volume files. Project data updates frequently with project progress, so deployment requires configured triggerable incremental synchronization logic. The accuracy of professional fields and units directly impacts document generation quality. Deployment must ensure knowledge base chunking does not break professional information integrity. When upgrading versions, retain knowledge base associations for historical projects, and avoid clearing existing configurations and data.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `800–1200 connections` | Survey and design documents are mostly long texts. Batch import and retrieval require sufficient database connections to support concurrent requests |
| `STORAGE_S3_ENDPOINT` | Intranet access endpoint provided by the object storage service provider | Drawings and calculation reports for survey and design are mostly large-volume files. Intranet access reduces file loading latency |
| `REDIS_URL` | Local Redis instance address, with memory limit set to 8000 MB | Professional term vectors and document indexes require caching. Larger memory improves retrieval speed for professional content |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Encrypts file download links, preventing unauthorized access to project-specific survey and design documents |
| `ROOT_KEY` | Only used during initial deployment, disable this key afterward | This key has the highest system permissions, and is only used to initialize the knowledge base and application configurations, to avoid security risks from long-term exposure |
| `FE_DOMAIN` | Public network domain name of the deployment server | Generates access entries for front-end pages and preview links for knowledge base files, ensuring users can access the application normally |

## Three common errors
- After upgrading to FastGPT v4.17.0, database connection timeouts occur, and the console returns a 503 status code. The cause is failure to adjust `DB_MAX_LINK` to match the concurrent request volume after the upgrade, leading to exhaustion of the database connection pool.
- When creating a general knowledge base, preview content for supporting drawings fails to load, and the image field is empty. The cause is failure to configure `STORAGE_S3_ENDPOINT` to point to the local storage path, resulting in inability to read uploaded image files.
- Attempting to generate an application-specific key returns a 401 error. The cause is failure to retain the initial deployment `ROOT_KEY` configuration, leading to permission verification failure and inability to generate valid keys.

## How to confirm configurations are properly set
- Access the front-end address corresponding to `FE_DOMAIN`, and verify that the application home page and login interface load normally.
- Import a small survey report document, and verify that contextually relevant content for document drafting can be successfully generated.
- Call the key generation interface, and confirm that an application-specific key can be normally generated and interface call verification can be completed.
- View the storage bucket corresponding to `STORAGE_S3_ENDPOINT`, and confirm that imported survey and design documents have been synchronously stored to the specified path.

The values provided are common starting points and should be measured against the reader's own samples.
