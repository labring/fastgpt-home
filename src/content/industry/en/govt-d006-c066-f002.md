# Document and Material Drafting for Advanced Chemical Materials: Vector Models and Indexing

## What the data for this category looks like
Advanced chemical material document data mainly comes from internal enterprise R&D records, process specifications, compliance filing documents, material specifications provided by suppliers, and publicly available industry standard documents. Data updates follow R&D iterations and adjustments to compliance requirements, with no fixed cycle. Most documents have long text structures, containing fields such as material grades, performance parameters, preparation processes, and safety instructions. Professional measurement standards such as pascals, degrees Celsius, and molar mass are commonly used for units.

## Constraints imposed by these characteristics on vector models and indexing
The long text structure of advanced chemical material documents requires vector chunking to preserve technical term integrity, to avoid splitting that disrupts process descriptions or parameter associations. Multi-field document structures require indexes to be stored grouped by business fields, to avoid invalid cross-field recall. No fixed update cycle means indexes must support incremental updates, to avoid resource consumption from full reindexing. The presence of multilingual documents requires vector models to support multilingual encoding, otherwise cross-language recall rates will be insufficient.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Advanced chemical material documents are mostly long professional texts; this range preserves the integrity of process descriptions and parameters |
| Overlap Length | 100–150 characters | Avoids loss of contextual association for technical terms between chunks |
| Similarity Threshold | 0.72–0.80 | Technical terms for chemical materials have high recognizability; this range filters invalid recall results |
| Single Search Maximum | Top 8 entries | Multi-field indexes require controlling return volume to ensure retrieval efficiency |
| `maxToken` | `8192` | Adapts to the input upper limit of mainstream vector models, avoiding truncation of long professional texts |
| `defaultToken` | `256` | Meets basic vector encoding requirements for general documents |

The configuration values listed above are common starting points, and should be evaluated against the reader's own samples.

## Three common errors
- A 404 error occurs during testing after configuring the API for the Doubao-embedding indexing large model. The cause is failure to correctly configure the domain name path for API requests, or failure to add channel permissions for the corresponding model in the FastGPT backend.
- When batch re-embedding knowledge base content after replacing the embedding model, some document vectors are missing. The cause is failure to enable incremental update mode as required; full replacement operations result in incomplete coverage of old indexes.
- The default index generated for manually inserted knowledge base documents disappears after several hours. The cause is insufficient available space in the index storage directory, or the system automatically cleaning temporary indexes that exceed the retention period.

## How to confirm the configuration is properly set
- Navigate to the model channel management page in FastGPT, check if the API configuration for the target embedding model has been saved and has no error prompts.
- Upload a standard advanced chemical material document, manually trigger the vector embedding process, and check that chunked text retains complete professional field content.
- Initiate a retrieval test based on material technical terms, and confirm that the number of returned results matches the configured single search maximum.
- View the disk usage status of the index storage directory, and confirm that no insufficient space alerts are present.
