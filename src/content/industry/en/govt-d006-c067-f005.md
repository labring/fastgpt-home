# Document and Material Drafting for Fertilizers and Pesticides: Tool Calling and Plugins

This document was created using FastGPT v4.17.0.

## What Data for This Category Looks Like

Data related to fertilizers and pesticides originates from three main sources: the national agricultural materials registration management platform, enterprise production ledgers, and industry standard documents. Data on the national platform updates alongside industry standard revisions. Enterprise ledger data updates per production batch.

Document structures include fixed fields such as registration certificate number, active ingredient content, applicable crops, application dosage, and pre-harvest interval. Most active ingredient content units use grams per liter or mass percentage. Most application dosage units use kilograms per hectare or application rate per mu.

## Constraints Imposed on Tool Calling and Plugins

The data includes strictly regulated mandatory fields and fixed units. Tool calling must accurately match field formats to avoid generating documents that fail to meet regulatory requirements.

Differences in update rhythms across multi-source data mean plugins must support scheduled synchronization of the latest standard data from the national platform. Plugins must also remain compatible with real-time updated internal enterprise production ledgers.

The fixed field structure also requires tool calling recall scopes to be limited to agricultural materials-specific data. This prevents irrelevant content from disrupting document generation logic.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multiple document scenarios such as fertilizer and pesticide registration certificates and application instructions, automatically matching the corresponding tools |
| `functionCall` | `["generate_fertilizer_spec", "generate_pesticide_label"]` | Limits calls to agricultural materials-specific tools, preventing triggering of unrelated functions |
| Stream output toggle | Disabled | Fertilizer and pesticide documents require a fixed format. Stream output will cause incorrect segment breaks |
| Knowledge base recall limit | Top 10 entries | Agricultural materials data fields are precise. Excessive recall results will add redundant context |
| Interface timeout threshold | `120 seconds` | Connecting to the national agricultural materials platform interface requires a certain amount of query time, preventing early interruption |
| Output format constraint | Strictly follow the national standard field order | Meets the format requirements for agricultural materials documents from regulatory authorities |

## Three Common Mistakes

- When a knowledge base is connected to the tool calling module in a workflow, valid data cannot be referenced. The generated document lacks the active ingredient content field. This occurs because the knowledge base recall limit is set too low, failing to recall core data for the target agricultural materials.
- The tool calling module has no trigger action, and the module status shows as not executed. This occurs because the `toolChoice` parameter is set to `none`, with no specified tool type to call.
- Documents generated after enabling stream output have chaotic segment breaks and cannot be directly used for regulatory reporting. This occurs because the stream output toggle was not disabled, and real-time pushed content disrupts the fixed format.

## How to Confirm Proper Configuration

- Generate a pesticide registration certificate document. Check whether the output includes mandatory fields such as registration certificate number, active ingredient content, and applicable crops.
- Review the tool calling logs to confirm that the query interface for corresponding agricultural materials data has been triggered, with no timeout errors.
- After disabling the stream output toggle, check that the generated document is a complete fixed segmented format, with no real-time pushed segment markers.
- Verify that when the `toolChoice` parameter is set to `auto`, it can automatically match the tool calling logic for the current document scenario.
