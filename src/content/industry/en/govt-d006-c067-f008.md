# Document and Material Drafting for Fertilizers and Pesticides: Document Parsing and Chunking

## What the data for this category looks like
Business data for fertilizers and pesticides originates primarily from internal production ledgers, pesticide registration certificate documents, fertilizer nutrient test reports, formula documents, and similar sources. Update cycles fall into two categories: on-demand updates (such as for pesticide registration certificates and new formula documents) and scheduled updates (such as daily production ledgers). Document types include structured CSV tables (with fields like product name, active ingredient, content, and more), PDF quality inspection reports (with fixed headers and standardized fields), and Word-format formula descriptions. Fields and units have category-specific traits: for example, active ingredient content uses units of g/L or %, total nutrient content is the sum of N + P2O5 + K2O, with a unit of %.

## What constraints these characteristics impose on document parsing and chunking
Category data includes both structured tables and non-standardized text. Parsing processes must avoid splitting associated data across rows or columns, which would disconnect active ingredients from their corresponding content values. Because document update frequencies vary widely, the system must support both rapid batch uploads and parsing of single large files. Fixed-format PDF and CSV documents require targeted parsing rule configuration, to prevent the default parsing logic from extracting redundant or irrelevant content. For fields with category-specific units, chunking must retain contextual associations, to avoid splitting units away from their associated numerical values, which would impair subsequent retrieval.

## Configuration Recommendations
The following configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Category documents include long-form formula text and multi-column structured tables. This range balances contextual completeness and chunk granularity |
| `chunkSplitter` | Adaptive by document type | Category data includes plain-text reports, structured CSV files, and PDF tables. Adaptive splitting prevents damage to cross-column associated data |
| `customPdfParse` | Enabled | Fertilizer and pesticide PDF quality inspection reports have fixed headers and field order. Custom parsing can accurately extract target fields and prevent redundant content from being included in chunks |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Single annual production ledgers or multi-page quality inspection reports for this category may be large in size. This upper limit covers most batch upload scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large PDF quality inspection reports and multi-sheet tables takes significant time. This duration prevents mid-parsing timeouts |
| `chunkSettingMode` | Manual configuration | Category data has large structural differences. Manual configuration allows flexible adjustment of chunking parameters to adapt to different document types |

## Three Common Configuration Mistakes
- Only the first two columns of data are extracted when uploading a CSV table, with remaining column fields left empty. Cause: Full-column parsing configuration for structured documents is not enabled. The default parsing logic only reads the first two columns of associated data.
- A 413 error is returned when parsing large PDFs or multi-sheet tables. Cause: The `UPLOAD_FILE_MAX_SIZE` configuration value is smaller than the uploaded file size, or the container file upload limit was not adjusted synchronously when using Docker deployment.
- The external pdf-maker parser fails to work after being enabled. Cause: The external parser’s authorization key was not correctly filled in the corresponding configuration item, or the configuration path does not match the deployment environment.

## How to Verify Correct Configuration
- Upload a standard CSV table from this category, check that all column fields are extracted, and confirm that the parsing configuration adapts to structured data.
- Upload a test file with a size close to `UPLOAD_FILE_MAX_SIZE`, verify that the parsing process does not trigger timeouts or 413 errors.
- After enabling the `customPdfParse` configuration, upload a PDF quality inspection report from this category, check that the extracted fields match the preset parsing rules.
- Review the chunked text fragments, confirm that active ingredient content values and their associated units are not split into different chunks.

The values provided here are common starting points, and should be evaluated against the user’s own samples.
