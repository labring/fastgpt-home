# Document and Material Drafting for Fertilizers and Pesticides: Deployment and Upgrade

## What this category of data looks like
Data sources for fertilizer and pesticide-related documents and materials mainly come from enterprise internal production ledgers, product quality inspection reports, Ministry of Agriculture and Rural Affairs registration and filing documents, and agricultural chemical service guidance manuals. The data update rhythm adjusts based on production batches or quarterly filing requirements. Each single updated document includes fixed fields: product common name, active ingredient content, registration certificate number, applicable crops, application dosage, and pre-harvest interval. The unit for active ingredient content is mostly g/L or mass percentage. The unit for application dosage is mu or hectare usage. Each individual document ranges from several pages to dozens of pages in length.

## Constraints during deployment and upgrade
Fixed metadata fields require enabling metadata verification during deployment to prevent invalid filing data from being imported. Frequent batch updates require configuring incremental synchronization tasks to reduce resource consumption from full synchronization operations. Documents contain professional units and long text, so chunking logic must be adjusted to preserve units and contextual associations. Management of multiple versions of production data requires compatibility with older metadata structures during upgrades to avoid historical data becoming unsearchable after the upgrade. Large volumes of filing documents and quality inspection reports also impose higher requirements on storage bandwidth and cache performance. Adaptation to the enterprise intranet’s storage and cache configurations is necessary.

## How to set configurations
These configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Enterprise intranet object storage address, such as `http://192.168.1.100:9000` | Bulk uploads of fertilizer and pesticide filing documents are common. Intranet storage reduces latency and ensures data security. |
| `REDIS_URL` | `redis://:custom password@intranet Redis address:6379/0` | Frequently updated production data requires session caching to ensure retrieval speed. |
| `DB_MAX_LINK` | `1000 entries` | A large number of filing documents are imported per batch. Limiting connection jumps prevents memory overflow. |
| `MONGODB_URI` | `mongodb://username:password@intranet Mongo address:27017/fastgpt?authSource=admin` | Stores multiple versions of production ledger data to ensure data persistence. |
| `FILE_TOKEN_KEY` | 32-bit randomly generated secret string | Ensures access security for uploaded quality inspection report files. |
| `FE_DOMAIN` | Enterprise intranet domain, such as `https://fastgpt.chem-enterprise.com` | Provides a unified frontend access entry, adapted to internal office networks. |

## Three common mistakes
- Symptom: An error `Failed to create post presigned url` is returned when uploading fertilizer and pesticide filing documents via workflow. Cause: `STORAGE_S3_ENDPOINT` is not correctly configured to point to the intranet storage, or storage key permissions are insufficient to generate presigned links.
- Symptom: The service fails to start after deployment on an ARM architecture server. Cause: The image for the corresponding architecture was not pulled, or memory allocation parameters for the ARM environment were not adapted.
- Symptom: Metadata fields from older versions of production ledgers are lost after upgrading from an older version. Cause: The metadata structure was not exported in advance, and older field mappings were not compatible during the upgrade.

## How to confirm configurations are properly set
- Bulk import documents of this category, check that the upload process has no errors and corresponding files are generated in the target storage directory.
- Access the configured frontend access address, confirm that the frontend page can normally load the metadata fields of the knowledge base.
- Trigger an incremental sync of the latest production data, confirm that the latest ledger data exists in the cache.
- Check the database logs, confirm that the number of connections per batch import does not exceed the configured limit.

The values given are common starting points and should be measured against the reader's own samples.
