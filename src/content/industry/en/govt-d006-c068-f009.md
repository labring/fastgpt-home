# Document and Material Drafting for Pharmaceutical Distribution: Model Access and Configuration

## What data for this category looks like
Pharmaceutical distribution documents and materials mainly come from internal ERP systems, temperature and humidity monitoring devices, drug regulatory filing platforms, and qualification documents from upstream and downstream partners. Data update frequencies fall into three categories: real-time (warehouse acceptance slips, outbound orders), daily (purchase and sales ledgers, daily temperature and humidity reports), and monthly (compliance self-inspection reports). Document structures are fixed, including fields such as purchase and sales party qualification numbers, generic drug names, production batch numbers, expiration dates, storage and transportation conditions, and acceptance results. Units include pieces, boxes, cases, degrees Celsius, and others.

## What constraints these characteristics impose on model access and configuration
Pharmaceutical distribution documents must strictly comply with GSP compliance requirements. The format and content of fixed fields cannot be adjusted arbitrarily. Therefore, the prompt’s verification logic must be fixed during model access to avoid generating non-compliant content. Real-time updated warehouse acceptance slips and outbound orders require the model to quickly pull the latest data, so context cache configuration must adapt to high-frequency updated data sources. Cold chain transportation records include temperature and humidity values with units. The model must accurately identify and integrate these data into documents, so parameter configuration must ensure parsing accuracy for structured numerical values. In addition, some sensitive qualification documents require local storage, and model calls must adapt to private deployment environment requirements.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Pharmaceutical distribution documents often include multiple purchase and sales contracts and cold chain transportation records. Complete context must be retained to complete GSP compliance verification |
| `maxTokens` | 4000 token | Drafting a single compliant document must cover fixed fields such as qualifications, batches, and storage and transportation requirements. This avoids truncated output content that affects compliance |
| `temperature` | 0.1–0.3 | Documents must strictly comply with drug regulatory specifications. Low randomness ensures accuracy of format and content |
| `AIPROXY_API_ENDPOINT` | Locally deployed node address, such as `http://192.168.1.100:8080/v1` | Connect to privately deployed large models, and adapt to local storage and compliance requirements for sensitive pharmaceutical data |
| `AIPROXY_API_TOKEN` | Exclusive token generated during deployment | Verify model call permissions and ensure access security for pharmaceutical data |

## Three common mistakes
- A 404 no body response occurs during model testing. The cause is that the `AIPROXY_API_ENDPOINT` configuration does not include the correct API path suffix, or the local model service is not running normally.
- An unmarshal_resp error occurs when generating documents or performing speech-to-text. The cause is that the `maxTokens` value exceeds the output upper limit supported by the model, leading to response format parsing failure.
- Abnormal streaming output occurs when accessing the TTS model. The cause is that the `maxContext` configuration is too small, and complete context data is not retained, leading to incomplete generated text.

## How to confirm configuration is complete
- Input a simulated pharmaceutical purchase and sales slip in the model testing interface of FastGPT v4.17.0. A normal response body is returned after calling, with no 404 or parsing errors.
- The generated document includes all preset fixed fields, and the content matches the input simulated data without format deviations.
- When testing the speech input transcription function, the transcribed text can be correctly loaded into the model context without parsing errors.
- After accessing the TTS model, streaming output can normally return generated content sentence by sentence without interruption or truncation.
