# Document and Material Drafting for Power Generation Equipment Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Document drafting data for power generation equipment manufacturing mainly comes from internal enterprise PLM systems, ERP operation logs, compliance inspection reports, and project technical documents. The data update rhythm changes with project phases: weekly updates during new equipment model R&D, and monthly updates for regular operation and maintenance projects. Most documents use structured formats, containing fields such as equipment model, operating parameters, component number, and inspection date. Parameters have dedicated units: for example, turbine output uses MW as the unit, and boiler evaporation capacity uses t/h as the unit. Some documents contain multi-level nested technical descriptions.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering workflow
The diversity of professional parameters and units requires multi-turn dialogue to retain equipment-specific identifiers within the context, to avoid mixing parameters from different batches and models of equipment. The non-fixed update frequency requires prompt engineering to support dynamic loading of the latest project documents, and multi-turn dialogue must clearly define the current session's project scope. The nested levels of structured documents require prompt engineering to guide the model to accurately extract information by field, avoiding missing key units and numbers. Large differences in documents across projects require multi-turn dialogue to fix the current session's context boundaries, preventing cross-project data from interfering with generation results.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Max context length | 8000–12000 characters | Power generation equipment documents contain a large amount of long-text technical descriptions and parameters; sufficient length avoids truncating critical information |
| `messages` | Automatically concatenate the most recent 15 conversation turns | Retain contextual association for multi-turn dialogue, ensuring the model understands continuous requirements |
| `variables` | Inject current equipment model, batch number, and inspection standards | Allow the prompt to accurately match the target object of the current drafted document, avoiding parameter errors |
| Single response timeout | 60 seconds | Reserve sufficient time for model generation and data calls when drafting documents associated with long documents |
| `chatId` | Bind the unique identifier of the current project | Ensure multi-turn dialogue for the same project shares a dedicated context, avoiding cross-project data confusion |

## Three Common Misconfigurations
- Phenomenon: When initiating a conversation for the first time, the first response delay exceeds 3 seconds, and subsequent dialogue response speeds return to normal. Cause: The first conversation needs to load the professional document vector library associated with the current project, and the lack of pre-warmed context leads to increased initialization time.
- Phenomenon: Cross-project parameter confusion appears in generated documents during multi-turn dialogue, such as referencing thermal power equipment parameters when drafting wind power equipment documents. Cause: `chatId` is not bound, leading to incorrect sharing of context across different sessions, and the model cannot distinguish the dedicated data of the current project.
- Phenomenon: Generated compliance documents lack mandatory required fields, such as not marking the equipment batch number and inspection date. Cause: Required field variables for the current project are not injected via `variables`, and the prompt does not explicitly require extracting corresponding information.

## How to Confirm Proper Configuration
- Initiate a new conversation, enter the current project's equipment model, and verify whether the model can directly associate parameters from the corresponding document without repeatedly asking for basic information.
- Initiate a multi-turn dialogue, modify the equipment parameters once, and verify that all subsequently generated documents use the updated parameters without retaining old parameters.
- Wait for the first conversation response, confirm that the delay meets expectations, then check whether the generated document contains all injected `variables` fields.
- Switch to a session for another project, verify that the current session's context is not interfered with by documents from other projects, and the generated document only uses data from the current project.
