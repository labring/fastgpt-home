# Document and Material Drafting for Power Generation Equipment Manufacturing: Model Access and Configuration
## What the Data for This Category Looks Like
Power generation equipment manufacturing document data mainly comes from technical manuals accompanying unit design drawings, production process specifications, factory quality inspection reports, bidding technical documents, and operation and maintenance repair ledgers. Data updates are adjusted with the launch of new models, annual compliance inspections, or major technical renovation projects. Single documents often include structured fields such as rated power, rotor weight, and insulation class, with units mostly using industrial standard units like megawatts, tons, and kilovolts. Some long documents include drawing indexes and parameter comparison tables.

## Constraints Imposed by These Characteristics on Model Access and Configuration
Documents for power generation equipment manufacturing have characteristics of high long-text proportion, numerous structured parameters, and update rhythms that fluctuate with projects. These characteristics impose constraints on model access and configuration. Long texts must adapt to model context window limits to avoid truncating core unit parameters. Structured fields require clear model output formats to ensure accurate extraction of parameters such as rated power and rotor weight. Documents updated with projects need quickly synchronizable data source connections to avoid using expired data during model calls. The presence of industrial standard units requires model output to match document units to reduce conversion errors.

## Three Common Misconfigurations
- Phenomenon: The generated document includes the complete model thinking process, and does not only output the final document content as required. Cause: No targeted prompt constraints are configured, and the `maxTokens` parameter is not restricted, causing the model to output unexpected intermediate steps.
- Phenomenon: Model calls return connection failures or permission errors. Cause: Proxy service-related configurations are not filled in correctly, or the proxy service has not opened the corresponding call permissions.
- Phenomenon: Extracted parameters such as unit rated power and rotor weight do not match the actual values in the document. Cause: Automatic tool calls via `toolChoice` are not enabled, or the structured format of model output is not clearly defined, leading to parameter extraction deviations.

## How to Verify Successful Configuration
- Submit a typical long document for power generation equipment manufacturing, check the context usage prompt during model calls to confirm that forced truncation is not triggered.
- Input a query containing structured parameters, check that the parameter format of the model output matches the document fields, and confirm that the tool call configuration takes effect.
- Call the configured proxy service interface to confirm that the authentication and data transmission processes are completed normally.
- Simulate a multi-concurrent call scenario, check the allocation status of different call nodes, and confirm that the load allocation logic meets expectations.
