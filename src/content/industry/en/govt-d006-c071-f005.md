# Document and Material Drafting for Power Generation Groups: Tool Calling and Plugins

## What data looks like for this category
Data for power generation group document and material drafting comes mainly from internal production and operation systems, safety management platforms, and archive repositories. It is updated alongside business nodes, and archived once a single project is completed. Most documents are a mix of structured and semi-structured content. They include fields such as document number, issuing unit, effective date, and core business parameters like unit number, maintenance cycle, and grid connection indicators. Units include megawatts, operating hours, units, and more. The main body is usually split into chapters by business module, with corresponding technical attachments and parameter explanations attached.

## What constraints these characteristics impose on tool calling and plugins
The structured fields and exclusive business parameters of power generation group documents require that input parameters for tool calling strictly match the field definitions of internal systems. Parameter mismatches will cause calling failures. Internal data is stored in dedicated databases. Plugins must support connecting to compliant internal data sources. They must also handle document splitting and reading across multiple chapters and attachments. The update rhythm driven by business nodes requires plugins to pull the latest business data in real time. Using fixed caches will lead to outdated generated materials. Plugins must also adapt to multi-row query and multi-result set scenarios. This meets the need for batch generation of materials such as maintenance reports and grid connection applications.

## How to set up configurations
This guide is written based on the tool calling and plugin configuration logic of FastGPT v4.17.0. The specific configuration items are as follows:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapts to multi-tool calling scenarios during document drafting, automatically selects the plugin matching the current task |
| `functionCall` | Enabled | Ensures generated content complies with internal business field specifications, and can be directly imported into internal systems |
| Tool call timeout | 60–120 seconds | Matches the average response time of internal database queries, prevents calling failures due to latency |
| Data source authorization scope | Only add internal production database and archive repository addresses | Complies with data security and compliance requirements for Chinese state-owned enterprises and public sector entities, restricts plugin access scope |
| Multi-row query support | Enabled | Supports running multiple SQL statements in one execution, meets the need for pulling multiple data sets for batch material generation |

## Three common mistakes
- Scenario: Tool call results have empty fields or messy formatting. The error message displays "parameter mismatch". Cause: Tool input parameters are not mapped to internal business fields. Generic generation logic is used directly, so it cannot match exclusive fields of power generation groups such as unit number and grid connection indicators.
- Scenario: The MySQL database plugin throws an error when running multi-row queries. The return message displays "syntax error". Cause: The multi-row query configuration item is not enabled. The plugin only supports single statement execution by default. The return format of multiple result sets is not handled.
- Scenario: Tool call results are unstable. Some generated content lacks attachment information. Cause: Adaptation rules for document chunk reading are not configured. Long documents are truncated, so attachment information is not fully read.

## How to confirm the configuration is correct
- Launch a material drafting test. Call the database plugin to pull maintenance data for a specified unit. Check that the returned result fields match those of the internal system.
- Input a prompt that includes multiple query requirements. Verify that the plugin can normally execute multi-row queries and return complete result sets.
- View plugin logs. Confirm that only authorized internal data sources are accessed. There are no call records for external unauthorized data sources.
- Adjust the tool call timeout threshold. Simulate a network latency scenario. Verify that the plugin completes the call within the preset duration.

The values provided are common starting points, and should be evaluated against the reader's own samples.
