# Document and Material Drafting for Power Generation Groups: Deployment and Upgrade

## What the Data for This Category Looks Like
Data for document and material drafting for power generation groups comes primarily from internal production scheduling records, safety control documents, project approval replies, monthly operation summaries, and external bidding documents.
Update rhythms vary by document type: monthly operation documents update monthly, project documents update irregularly as projects progress, and safety regulation documents update annually or when revised.
Document structure includes document number, creation date, issuing entity, main text, and attachment list. Fields include unit number, power generation, equipment model, safety threshold, and similar items. Common units are kilowatts, tons, operating hours, and others.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
Power generation group document data includes multi-dimensional business fields and sensitive production information. Ensure data storage compliance and access permission isolation during deployment.
Document update frequencies are uneven, and some documents have large file sizes. Avoid data write interruptions during upgrades. Interruptions may cause partial loss of scheduling records and project files.
The structured nature of multiple fields requires higher database connection stability. Verify field mapping compatibility in advance during cross-version upgrades to avoid parsing exceptions.
External bidding documents have strict timeliness. Schedule upgrade windows to avoid peak business hours.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Power generation group document data includes multiple business fields and uneven update frequencies. A sufficient database connection pool supports concurrent document parsing and storage requests |
| `MONGODB_URI` | `Exclusive cluster address with read-write separation suffix` | Document data contains sensitive production information. Exclusive clusters isolate business traffic. Read-write separation reduces pressure on single nodes |
| `REDIS_URL` | `Local cache cluster address using port 6379` | Temporary storage of intermediate text fragments is required during document parsing. Local clusters reduce cross-node latency |
| `STORAGE_S3_ENDPOINT` | `Regional endpoint adapted to domestic compliant storage` | Power generation group documents must comply with data localization requirements. Compliant storage endpoints ensure data storage compliance |
| `FE_DOMAIN` | `Group intranet registered domain name` | Internal office scenarios use intranet domains to restrict unauthorized access and protect document data security |

## Three Common Misconfigurations
- After an upgrade, the front-end interface displays the old version and fails to load new document parsing templates. This occurs when the front-end static resource package is not updated synchronously during the upgrade, and only the back-end service is replaced.
- In Docker deployment scenarios, the MongoDB connection works normally initially, but connection timeout errors appear after several hours of operation. This occurs when a reasonable threshold for `DB_MAX_LINK` is not configured. The connection pool is exhausted and cannot create new connections, and the database connection automatic reconnection mechanism is not enabled.
- Skipping intermediate script-free versions during cross-version upgrades causes abnormal document field mapping relationships. The unit number field of some bidding documents cannot be parsed normally. This occurs because FastGPT version upgrade scripts rely on field adjustments from intermediate versions. Skipping intermediate versions leads to incompatible data structures.

## How to Verify Configurations Are Correctly Set
- Execute the back-end service health check interface to confirm that the connection status of configuration items such as `MONGODB_URI` and `REDIS_URL` is normal. Check results must match the configured cluster parameters.
- Upload a typical power generation group monthly summary document, trigger the document drafting process, and verify that parsed fields match the original document. Adjust configuration items to adapt to field parsing rules.
- Restart the back-end service, check whether the front-end interface version number matches the deployment package version, and confirm that static resources have been updated correctly.
- Simulate high-concurrency document upload requests, check database connection pool usage, and confirm that the `DB_MAX_LINK` configuration supports concurrent requests.
