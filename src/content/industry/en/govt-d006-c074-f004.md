# Document and Material Drafting for State-owned Asset Management Companies: Workflow Orchestration
Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
State-owned asset management companies' document data mainly comes from standardized templates issued by state-owned asset supervision departments, internal asset ledgers, property transfer agreements, project approval forms, and similar sources. The data update rhythm fluctuates with project cycles. Documents for individual projects may be gradually generated over several days to months between project initiation and archiving. Daily ledger data is updated daily. The document structure follows unified state-owned asset system specifications, including fixed fields such as asset number, evaluation value (unit: ten thousand yuan), approval document number, transferee information, and others. The length of a single document varies widely, ranging from a few pages to dozens of pages.

## What constraints these characteristics impose on the "workflow orchestration" link
Decentralized data sources mean the workflow must support multi-source data access. Fields from different sources such as internal ledgers and supervision documents must be uniformly bound to workflow variables. The wide range of document lengths requires workflow nodes to adapt to long-text processing, avoiding interruptions caused by single-node processing limits. The requirement for fixed fields means the workflow must include a required field verification link to ensure generated documents comply with state-owned asset system specifications. Dynamically updated project data requires the workflow to support real-time variable references to adapt to temporary supplementary document content needs.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Reference | Bind the asset number field in `variables` | State-owned asset management documents require precise matching of exclusive asset identifiers to avoid confusion between different projects |
| Knowledge Base Selection | Reference the specified knowledge base variable passed in | Adapt to state-owned asset supervision knowledge bases and internal ledger knowledge bases corresponding to different projects |
| Node Trigger Condition | Bind the completion signal of the preceding approval node by `nodeId` | Ensure document generation starts only after the preceding approval process is completed, which complies with state-owned asset project approval logic |
| Timeout Setting | 600 seconds | Handle long-text state-owned asset document parsing and generation, adapting to the processing needs of dozens of pages of documents |
| Text Chunk Length | 800–1200 characters | Adapt to the long-text structure of state-owned asset documents, avoiding single-node processing limits |
| Result Verification | Check for required fields such as asset number and evaluation value | Ensure generated documents comply with the unified format requirements of the state-owned asset system |

## Three common mistakes
- Phenomenon: The `<video>` tag inserted in the workflow is not rendered correctly, only showing the original tag code. Cause: The rendering switch is not enabled in the rich text output node, or the tag is not written in the format required by the platform.
- Phenomenon: The knowledge base search node returns empty results, prompting that no matching content is found. Cause: The knowledge base identification parameter corresponding to `variables` is not configured at the workflow entry, or the passed variable format does not meet the requirements.
- Phenomenon: The text content extraction node returns an error of field mismatch. Cause: The extracted fields are not aligned with the fixed required fields of state-owned asset management documents, and field verification is not completed in the preceding link.

## How to confirm the configuration is correct
- Trigger the workflow and pass in the specified asset number variable, check whether the knowledge base search node loads the knowledge base corresponding to the project
- After running the workflow, view the generated document and confirm whether all required fields such as asset number and evaluation value are included
- Test inserting audio and video tags, check whether the final output rich text content renders the tags normally
- Check the workflow log to confirm that the node trigger condition correctly matches the completion signal of the preceding approval node by `nodeId`
