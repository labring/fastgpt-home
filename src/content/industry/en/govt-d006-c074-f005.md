# Document and Material Drafting for State-owned Asset Management Companies: Tool Calling and Plugins

## What the data for this category looks like
State-owned asset management companies’ documents and materials primarily originate from normative documents issued by state-owned asset supervision departments, internal asset disposal approval forms, equity transfer agreements, annual operation reports, and ownership certificate documents. Data update cycles follow state-owned asset supervision requirements. Regular reports are updated quarterly. Temporary asset change documents are updated when triggered by business nodes. Most documents use fixed template structures. Core fields include asset number, book value, ownership certificate number, and storage location. Common units are ten thousand yuan, square meters, and shareholding ratio.

## What constraints these characteristics impose on tool calling and plugins
Fixed template document structures require tool calling functions to predefine clear field extraction rules. This prevents the model from randomly parsing unintended content. Compliance requirements for state-owned asset supervision documents mandate that results returned by tool calls strictly match the field formats specified by supervision rules. No core information may be omitted. Quarterly updated regular reports and temporarily triggered change documents require plugins to support dynamic matching of different document template structures. Plugins must also restrict tool calling permission scope. Only authorized internal document libraries may be accessed. Additionally, consistent unit requirements for asset-related fields require plugins to automatically verify whether extracted value units meet preset standards. This prevents document deviations caused by unit errors.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-business scenarios of state-owned asset management company document drafting, automatically decides whether to call tools or read files |
| `functionCall` | Enabled | Ensures model output formats meet fixed field requirements for state-owned asset documents, avoids unstructured results |
| Custom plugin timeout | 120 seconds | Addresses time-consuming needs of long document parsing and external interface queries, prevents call interruptions |
| File reading trigger threshold | 800–1200 characters | Distinguishes regular short text and long documents, triggers file reading tools only when document content exceeds the threshold |
| Plugin access scope | Internal asset document library only | Complies with state-owned asset data security specifications, limits data source boundaries for tool calls |

## Three Common Misconfigurations
- Phenomenon: The model fails to trigger the file reading tool. This results in incorrect extraction of asset data from long documents. Cause: No reasonable file reading trigger threshold is configured, or `toolChoice` is set to `none`, which restricts the model’s independent decision-making authority.
- Phenomenon: A custom plugin calls an external interface and returns a timeout error. Plugin execution fails. Cause: The custom plugin timeout value is not adjusted. Time spent parsing state-owned asset documents or querying external interfaces exceeds the default threshold, leading to request interruption.
- Phenomenon: Incorrect units are extracted for asset book values. This causes numerical deviations in documents. Cause: No unit verification logic is configured for the plugin. The model does not extract unit information according to preset field rules, leading to data formats that do not meet state-owned asset document requirements.

## How to Verify Configurations Are Correct
- Upload a long document matching the business scenario. Check whether the model automatically triggers the file reading tool. Confirm the automatic decision-making logic of the `toolChoice` configuration is active.
- Trigger a custom plugin execution task. Review the elapsed time in the plugin running logs. Confirm the timeout configuration meets business requirements.
- Extract core asset fields from documents. Compare extracted result formats against preset requirements. Confirm the format constraints of `functionCall` are active.
- Attempt to trigger the plugin to access unauthorized data sources. Confirm permission restriction rules function correctly.

The configuration values provided here are common starting points. They should be evaluated against samples specific to the actual deployment context.
