# Document and Material Drafting for State-owned Capital Investment Companies: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
The document and material data for state-owned capital investment companies mainly originates from internal state-owned assets supervision reporting documents, full-process investment project documents, group board of directors, board of supervisors and shareholders' meeting resolutions, annual operating reports, and external regulatory policy documents. Data update rhythms vary by business scenario: project-related documents are updated dynamically with nodes such as project initiation, due diligence, and approval. Annual reports are updated once per year. External regulatory policy documents are synchronized immediately upon release.

Document structures uniformly include these fields: document number, issuing entity, topic category, main text content, attachment list, issuing unit, and date. Field units follow general state-owned assets system specifications. Document numbers use the format "GuoZiTou [Year] Serial Number". Individual main text lengths range from hundreds to tens of thousands of characters.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Documents for this category are sourced across multiple internal business systems and external regulatory platforms. HTTP interfaces must support pulling data from multiple sources and adapt to authentication rules of different systems.

Individual document lengths vary widely. Interfaces must support large text requests and responses to avoid transmission truncation or timeouts.

Document fields must strictly follow general state-owned assets system specifications. Interface returned data must verify document number format and topic category field legality. Non-compliant content must be intercepted.

Update rhythms differ significantly across document types. Interfaces must support both on-demand triggering and scheduled synchronization modes. These modes adapt to dynamic update and periodic reporting requirements.

## Configuration Settings
The following configuration items apply to the HTTP node function of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Carry the API token uniformly allocated by the state-owned assets system, set validity period to 7 days | Adapt to authentication rules of multiple internal systems, avoid frequent token refreshes interfering with document drafting processes |
| `variables` | Pass three core parameters: document type, affiliated project ID, issuing unit code | Match classification and traceability requirements of state-owned assets documents, facilitate subsequent archiving and regulatory reporting |
| `responseData` | Only return verified main text, document number, and attachment list fields | Filter irrelevant data, reduce interface transmission overhead, comply with state-owned assets document reporting specifications |
| Timeout Duration | 600 seconds | Adapt to parsing and transmission requirements of long documents, avoid timeout errors during transmission of large-volume documents |
| Retry Count | 2 times | Respond to temporary fluctuations in internal business systems, reduce document drafting interruptions caused by single interface call failures |

## Three Common Mistakes
- Scenario: An interface call returns a 403 status code, with a prompt that the token lacks permission to use the corresponding resource. Cause: The exclusive API token uniformly allocated by the state-owned assets system was not used, or the token permissions do not cover the document data interface of the target internal system.
- Scenario: The document content returned by the interface is missing the document number or attachment fields. Cause: Traceability parameters such as the issuing unit code were not passed in `variables`, causing the interface verification logic to intercept incomplete document data.
- Scenario: A timeout error occurs during long document transmission. Cause: The interface timeout duration was not set to a value suitable for long document transmission. The default timeout configuration is insufficient to support document data of tens of thousands of characters.

## How to Confirm the Configuration Is Correct
- Call the configured HTTP interface, pass test document type and project ID, check that the returned results include the expected core fields.
- Simulate calling the interface with document data in an incorrect format that does not comply with state-owned assets specifications, confirm that the interface returns a verification failure prompt matching the expected interception logic.
- Call the interface multiple times consecutively, observe the interface return status codes and response durations, confirm that there are no frequent timeouts or authentication failure issues.
- Pass test documents of different lengths, confirm that the interface can normally receive and return complete data, adapting to document requirements of different scenarios.
