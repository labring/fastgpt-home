# Document and Material Drafting for State-owned Capital Investment Companies: Workflow Orchestration

## What this category's data looks like
Data for documents and materials of state-owned capital investment companies mainly comes from internal state-owned assets supervision submission documents, investment project feasibility study reports, board of directors/party committee meeting resolutions, group annual operation summaries, and similar sources. It is exclusive business data under the state-owned enterprise state-owned capital investment and operation category. The data update rhythm adjusts with project progress milestones and quarterly state-owned asset report submission deadlines. The document structure fixedly includes fields such as document number, responsible department, investment target name, approval level, and compliance description. The length of a single document ranges from thousands to tens of thousands of words, and some attachment materials are in structured table format. This article is written based on FastGPT v4.17.0.

## What constraints do these characteristics impose on the "workflow orchestration" link
Data sources are scattered across different internal systems and departments. This requires configuring cross-data-source pull trigger rules during workflow orchestration to support multi-port data access. The length of single documents varies widely, and some materials contain tens of thousands of words of structured content. This requires the text processing node corresponding to `nodeId` to adapt to different input lengths to avoid context overflow. Fixed document fields require `variables` configuration to bind preset field mappings, and field extraction logic cannot be adjusted arbitrarily. Data updates adjust with project nodes and state-owned asset submission cycles, so workflow trigger rules must match corresponding time nodes to avoid invalid runs.

## How to set the configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset to "document number, responsible department, investment target name, approval level" | Matches the fixed field structure of documents for state-owned capital investment companies |
| `nodeId` | Set up 3 processing nodes by text length, corresponding to thousands of words, tens of thousands of words, and attachment tables respectively | Adapts to the wide range of document lengths |
| Trigger Rules | Trigger on the 5th day of the first month of each quarter, 3 days before project approval | Matches the rhythm of data updates following state-owned asset submission and project milestones |
| Variable Mapping | Bind preset fields to workflow output items | Follows the extraction requirements of fixed document fields |
| Timeout Setting | 1200 seconds | Meets the processing duration requirements for large feasibility study reports, calibrated based on actual testing |
| Context Limit | 8000–12000 token | Adapts to the context capacity requirements for long document processing, calibrated based on actual testing |

## Three common mistakes
- Workflow API calls return empty fields. The cause is failing to bind the corresponding document fields in the `variables` configuration, resulting in the variable extraction node not obtaining valid data.
- Workflow runs terminate due to timeout. The cause is not adjusting the processing node corresponding to `nodeId` according to document length, and processing a tens of thousands of word document with a single node exceeds the default timeout limit.
- External systems cannot call published workflows. The cause is failing to enable application public permissions or configure the correct API call key, resulting in external requests being blocked.

## How to confirm the configuration is complete
- Trigger the workflow manually once, and check whether the extracted fields match the preset fields of the target document.
- Upload document samples of different lengths to verify whether each processing node corresponding to `nodeId` starts normally.
- Simulate an external system calling the API to confirm that the returned results contain the expected document processing content.
- Wait for the preset trigger node time, and verify that the workflow runs automatically according to the set rules.
