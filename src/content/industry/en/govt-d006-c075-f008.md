# Document and Material Drafting for State-owned Capital Investment Companies: Document Parsing and Chunking

## What documents in this category look like
Documents related to document and material drafting for state-owned capital investment companies are sourced from internal office system archives, documents submitted to state-owned asset supervision platforms, and full-cycle project materials. Update frequency adjusts with project progress and regulatory reporting cycles. Most use formal official document formats, including document numbers, project codes, financial calculation data, equity structure details, and other content. Some documents contain multi-page attachments, with fields including project amount, shareholding ratio values, capital contribution deadlines, and other items. Units are mostly ten thousand yuan and years. Document volume varies widely, ranging from single-page correspondence to dozens of pages of feasibility study reports and investment plan documents.

## What constraints do these characteristics impose on document parsing and chunking
The document characteristics of this category impose multiple constraints on the parsing and chunking process. Documents with multiple tables and nested attachments cause default chunking engines to split table content incorrectly and miss attachment information. Targeted adjustments to parsing logic are required. For long documents and content with coherent business logic, improper chunking parameter settings split a single project plan into multiple knowledge blocks, damaging business relevance. Document formats from different sources are inconsistent, requiring adaptation to multiple layout structures to avoid field loss or misalignment after parsing. Additionally, parsing large documents takes longer, so timeout parameters must be adjusted to ensure complete parsing.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents for state-owned capital investment companies often contain coherent project logic and table content. This range preserves complete business units of single files and avoids splitting critical information |
| `chunkSplitter` | Chunk by paragraph + heading | Adapts to the heading hierarchy of formal official documents, preventing core content from a single paragraph from being split across multiple blocks |
| `customPdfParse` | Enabled | Supports parsing nested PDF attachments and embedded tables, preserving the original document layout and field relevance |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets upload requirements for large feasibility study reports and packaged files with multiple attachments, matching the document volume characteristics of state-owned capital investment companies |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large documents and multi-attachment files requires longer processing time, preventing parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking parameters for specific business documents such as state-owned asset reporting files, adapting to requirements for different document formats |

## Three Common Configuration Mistakes
- Symptom: An upload request error appears after uploading a PDF, with status code 504 or 408. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and parsing timeouts for large documents are not handled correctly.
- Symptom: Parsed knowledge base content only retains plain text, with embedded table data missing. Cause: `customPdfParse` is not enabled, and the default parsing engine cannot preserve PDF embedded table structures.
- Symptom: Parsed chunked content cannot link corresponding business fields, such as project codes and amounts being split into different knowledge blocks. Cause: `chunkSize` is set too small, splitting coherent business units into multiple independent blocks.

## How to Verify Correct Configuration
- Upload a single formal official document with more than 100 pages, check if parsed content contains complete tables and heading hierarchies.
- Access the system configuration page, confirm that `customPdfParse` is enabled, and `PARSE_FILE_TIMEOUT_SECONDS` is set to a duration matching the document volume.
- Upload a packaged file with multiple attachments, check if all attachments are successfully parsed and added to the knowledge base.
- Test chunked content, confirm that core business fields are not split across different knowledge blocks.

The values provided are common starting points and should be measured against the reader's own samples.
