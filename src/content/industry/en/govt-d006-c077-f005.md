# Document and Material Drafting for Urban Public Transit: Tool Calling and Plugins

## What this category of data looks like
Urban public transit documents and materials mainly come from four categories: daily operation ledgers, safety inspection archives, passenger service records, and route adjustment announcements.
Data sources include station operation and maintenance systems, on-board scheduling terminals, passenger service platforms, and internal office systems.
Update rhythm follows real-time daily updates as the primary mode. Schedules and complaint handling letters are updated daily. Monthly safety reports and annual operation summaries are updated monthly or annually.
Document structures mostly use structured tables paired with explanatory text. Fields include route number, station name, operation hours, complaint ID, processing progress, and others. Units include passenger trips, operation kilometers, service duration, and others.

## How These Data Characteristics Constrain Tool Calling and Plugins
The above data characteristics impose three core constraints on tool calling and plugin configuration.
First, structured fields of public transit documents have dedicated rules. For example, route numbers must match the format of three digits plus a letter combination. Tool calling must adapt to this rule, otherwise valid information cannot be accurately extracted.
Second, data update frequency is high and real-time requirements are strict. Plugins must be configured with a scheduled pull mechanism to avoid generating documents using expired operation data.
Third, document types are diverse. Different scenarios require different operation data plugins. The tool selection logic must cover all scenarios, otherwise calling errors will occur.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Automatically match tools for the corresponding scenario, covering all public transit document types including safety reports, complaint letters, route announcements, and others |
| `functionCall` | Enabled | Accurately extract dedicated structured fields such as route numbers and station names from public transit documents |
| Tool call timeout | 600 seconds | Reserve sufficient time for parsing and data pulling when processing public transit documents containing long-text operation records |
| Maximum number of tool return entries | Top 8 entries | Match the number of operation data entries associated with a single document, avoiding redundant irrelevant information |
| Model compatibility | Large models that support `functionCall` | Ensure correct triggering of tool calls and parsing of structured fields |

## Three Common Mistakes
- Phenomenon: Tool calls return empty results or dedicated fields are missing. Cause: The `functionCall` configuration is not enabled. Generic large models cannot accurately extract dedicated structured fields such as route numbers and station names from public transit documents.
- Phenomenon: Tool calls throw timeout errors, returning status code 504. Cause: The tool call timeout duration is not adjusted. The default configuration duration is insufficient to complete parsing of long-text operation records and data pulling.
- Phenomenon: Tool calls make incorrect judgments, calling unrelated station operation and maintenance plugins. Cause: `toolChoice` is configured as a fixed single tool, which does not adapt to the multi-scenario types of public transit documents.

## How to Confirm Proper Configuration
- Upload a public transit station operation and maintenance record document, trigger tool calls, and check if the corresponding operation data plugin is automatically matched.
- View tool call logs, confirm that `functionCall` successfully extracts dedicated fields such as route numbers and station names.
- Adjust the tool call timeout to 300 seconds, simulate a long-text parsing scenario, and confirm that no timeout error occurs in the request.
- Switch between different types of public transit documents such as complaint handling letters and route adjustment announcements, confirm that `toolChoice` automatically matches the corresponding tools.
