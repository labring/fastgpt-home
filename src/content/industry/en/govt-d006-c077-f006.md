# Document and Material Drafting for Urban Public Transit: Citation Source and Traceability
## What the data for this category looks like
Urban public transit documents and operation data originate from internal operation management systems. These include scheduling logs, safety inspection records, route operation reports, passenger service ledgers, emergency response archives, and other types. Daily scheduling logs are updated each day. Monthly operation summaries are generated each month. Annual safety reports are updated annually. Each individual document includes fields such as route number, departure time, passenger trips, abnormal event description, and rectification measures. Units include trips, minutes, kilometers, and others. Field combinations vary across different documents.

## What constraints these characteristics impose on the citation source and traceability workflow
Dispersed multi-source data requires configuring multiple knowledge base association rules to avoid missing different types of public transit operation documents. Different update frequencies require setting differentiated incremental synchronization cycles to ensure the latest scheduling logs and rectification records are recalled promptly. Multi-field document structures require fully displaying associated fields to avoid missing traceability information. Large variation in single-document length requires setting a reasonable content truncation threshold to prevent valid citations from being cut off.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single documents for urban public transit materials, avoiding truncation of key citation fields such as route number and passenger trips |
| `responseData` | Return only associated source data | Ensures output content is strictly based on public transit operation documents in the knowledge base, without generating irrelevant supplementary text |
| `detail` | Enabled | Fully displays exclusive fields of citation sources such as route number and departure time, meeting the accuracy requirements for public transit document traceability |
| Incremental synchronization interval | 2:00 AM daily | Matches the daily update rhythm of daily scheduling logs, ensuring the latest operation data is included in the recall scope in a timely manner |
| Recall upper limit | Top 3 entries | Avoids excessive redundant citations interfering with the rigor of public transit documents, focusing on core associated documents |

## Three Common Misconfigurations
- Phenomenon: In FastGPT v4.17.0, closing the citation traceability switch still returns citation content. Cause: The linkage logic between the `responseData` parameter and the citation switch is not bound, causing the traceability function to trigger by default.
- Phenomenon: Using the `[{datasetId: xxx}]` format to configure variable references fails to correctly associate knowledge base data. Cause: The platform-specified variable syntax rules are not followed, resulting in parameter parsing failure.
- Phenomenon: After enabling the traceability function, the associated source data is not displayed in the output. Cause: The `detail` parameter is not enabled, causing only summaries to be returned instead of complete source data fields.

## How to Confirm Configuration is Correct
- Upload a test scheduling log containing route number and passenger trips, submit a corresponding document drafting request, and check whether the output associates the exclusive field information of this document.
- Adjust the `quoteMaxToken` parameter value, check whether the length of the cited source content in the output changes with the parameter, to verify that the parameter takes effect.
- After configuring variable references, submit a test request, check whether variables are correctly replaced with content from the specified knowledge base.
- Close the citation traceability switch, confirm that the output no longer displays any source data association information, to verify that the switch logic takes effect.
