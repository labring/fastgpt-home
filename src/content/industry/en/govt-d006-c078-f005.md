# Document and Material Drafting for Urban Water Utilities: Tool Calling and Plugins

## What data for this category looks like
Data related to document and material drafting for urban water utilities primarily originates from water operation logs, pipeline inspection logs, water quality test reports, drainage permit application archives, water supply dispatch records, and similar sources. Update frequencies vary by data type: pipeline inspection logs are updated daily, water quality test reports are updated weekly or monthly, and operation logs are synchronized in real time.

Document structures typically include location identifiers, timestamps, quantitative metrics, and execution requirements. Exclusive water utility fields include pipe diameter (unit: millimeters), water pressure (unit: kilopascals), pollutant concentration (unit: milligrams per liter), and permit validity period (unit: days).

## What constraints these characteristics impose on tool calling and plugins
The exclusive fields and unit requirements for water utility data require that tool calls must precisely match field names and units, to avoid indicator errors in generated documents caused by parameter mismatches. Dispersed multi-source data sources require the tool calling module to connect to multiple data source plugins such as inspection and water quality testing at the same time, which increases the complexity of the calling chain.

Water utility documents have fixed formats and compliance requirements, so tool calls must synchronously invoke format verification plugins to ensure generated materials comply with water industry standards. The update rhythm of real-time operation data requires that the trigger timing of tool calls must align with data synchronization nodes, to avoid using expired data to generate documents.

## Configuration Settings
All configuration recommendations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Tool call trigger timing | Within 10 minutes after data update | Matches the update rhythm of real-time water utility operation data, avoids using expired information |
| `toolChoice` | auto | Adapts to scenarios with parallel calls to multiple data sources, automatically matches corresponding water utility data plugins |
| `functionCall` | Enable multi-tool parallel execution | Adapts to complex scenarios of pulling data from multiple water utility sources |
| Format verification plugin | Enabled | Ensures generated water utility documents comply with industry compliance requirements |
| Single tool call timeout duration | 600 seconds | Covers the time required for pulling data from multiple water utility sources, calibrated based on actual testing |
| Tool call result cache duration | 30 minutes | Balances data timeliness and resource consumption of the calling chain |

## Three Common Misconfigurations
- Phenomenon: Tool calls exceed the preset threshold duration, resulting in timeout errors. Cause: The update rhythm of water utility data was not aligned, and unupdated multi-source data source plugins were called, leading to extended data pulling time.
- Phenomenon: Generated documents include results from two prior tool calls, with overlapping field content. Cause: The `toolChoice` parameter was not configured correctly, so the tool call context was not properly reset, and results from the previous call were carried into the current process.
- Phenomenon: The tool call module continuously outputs redundant operation logs, consuming interface and log storage space. Cause: The detailed log switch for tool calls was not disabled, and full-link log output was enabled by default, which does not meet the need for lightweight viewing of final results in water utility scenarios.

## How to Verify Proper Configuration
- Manually trigger a tool call, check that the returned result fields include water utility-exclusive metrics and their corresponding units, and verify alignment with the data source's field definitions.
- Review the tool call output, confirm that only the final generated document material is displayed, with no redundant operation records.
- Compare the actual tool call duration to the configured timeout duration, confirm that the duration stays within a reasonable range and meets water utility data pulling requirements.
- Check the feedback results from the format verification plugin, confirm that the generated document complies with water utility industry format specifications.

The values provided are common starting points and should be evaluated against individual deployment samples.
