# Document and Material Drafting for Urban Water Utilities: Deployment and Upgrade

## What the data for this category looks like
Data for urban water utility document and material drafting comes from multiple sources. These include pipe network operation logs, water quality testing archives, drainage approval dossiers, water fee settlement receipts, and emergency response plans.

Daily updates are applied to inspection records. Water quality testing reports update per sampling batch. Approval documents update as application processes advance.

Documents include structured forms and unstructured plan texts. Structured forms carry physical unit fields such as point number, pressure value, and turbidity. Most fields include unique water utility identifiers like geographic codes, device numbers, and approval statuses.

## What constraints these characteristics impose on deployment and upgrade
Structured forms include dedicated fields with units. Preset field mapping rules during deployment to avoid data parsing exceptions.

Unstructured plan texts have long length. Adapt context window parameters during upgrade to fully load document content.

Data update frequencies vary widely across sources. Configure incremental sync trigger logic during the deployment phase.

Water utility documents link to internal approval permission chains. Retain original permission configurations during upgrade operations to avoid interrupting business processes.

Data scale grows gradually as pipe network operation scope expands. Reserve configuration space for database expansion.

## How to set the configurations
This guide applies to FastGPT v4.17.0. The following configuration items are formulated based on the specific needs of the water utility document scenario:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Water utility document data volume grows as operation scope expands. This parameter controls the upper limit of the database connection pool, matching the concurrency needs of daily incremental sync |
| `REDIS_URL` | `redis://:custom complex password@local IP:6379/0` | Context caching and incremental sync tags for water utility documents require low-latency storage. Local deployment reduces network overhead |
| `STORAGE_S3_ENDPOINT` | `Configure using the intranet address of the local object storage service` | Water utility documents include a large number of drawings and test report attachments. Intranet storage improves upload and download speeds |
| `PG_URL` | `postgresql://username:password@database IP:5432/water utility document knowledge base` | Structured form data must be stored in a relational database, matching the structured storage needs of water utility fields |
| `FE_DOMAIN` | `Public domain name or intranet IP of the deployment server` | Must match the frontend access address to ensure normal document preview and knowledge base call links |

## Three common errors
- Phenomenon: After running the docker-compose up command, port occupied errors or "unable to connect to database" error logs are returned. Cause: `MONGODB_URI` and `PG_URL` are not configured to point to available database instances in advance, or deployment ports conflict with other locally running services.
- Phenomenon: The knowledge base only responds to the first question. Subsequent consecutive questions cannot associate context, and answer content is unrelated to prior text. Cause: `REDIS_URL` is not correctly configured to store session context, or `DB_MAX_LINK` is set too low, causing session cache to be cleared prematurely.
- Phenomenon: After accessing the frontend address, the document management directory page displays blankly or returns a 404 status code. Cause: The `FE_DOMAIN` configuration does not match the actual frontend access address, causing static resource loading links to fail.

## How to confirm configurations are set correctly
- Run the docker-compose ps command to confirm all service containers are in running status with no abnormal exit records.
- Upload a water utility inspection form to the knowledge base, initiate multiple consecutive questions, and verify that subsequent questions can associate prior content.
- Access the address corresponding to the configured `FE_DOMAIN`, confirm that the document management module loads normally with no interface error prompts.
- Check database connection logs to confirm the current connection count does not exceed the `DB_MAX_LINK` configuration limit, and that incremental sync tasks have no failed records.

The provided values are common starting points and should be measured against the reader's own samples.
