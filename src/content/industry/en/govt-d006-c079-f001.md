# Document and Material Drafting for Urban Gas Utilities: HTTP Interfaces and External Systems

## What the data for this category looks like
Document and material data for urban gas utilities primarily originates from business modules within gas operation systems. This includes user installation application forms, safety inspection rectification notices, payment receipts, gas supply confirmation letters, and similar items. Data is entered by frontline operations and installation window staff, with updates triggered in line with business nodes—synchronization completes once a single business process finishes. Documents are split into two categories: structured fields and attachments. Structured fields include user ID, gas usage address, designed gas usage scale (unit: cubic meters per day), installation type, safety inspection date, and rectification completion status. Attachments are mostly PDF-format scanned documents or electronically signed documents.

## What constraints do these characteristics impose on the HTTP interfaces and external systems workflow
The characteristics of urban gas utility document data impose clear constraints on the HTTP interfaces and external systems workflow. Fixed naming and unit requirements for structured fields mean interface request parameters must strictly match preset fields to avoid missing fields or format errors. PDF format and size limits for attachment documents require interfaces to support binary stream or Base64 encoded transmission, and require configuring reasonable timeout thresholds. The update rhythm triggered by business nodes means interface calls must be bound to business event hooks to reduce invalid polling requests. Differences in documents across different business scenarios require interfaces to support dynamically switching template parameters to adapt to document generation needs for installation, safety inspection, rectification, and other processes.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {encrypted enterprise API key}` | Complies with HTTP authentication standards and adapts to the unified key management rules of urban gas systems |
| `variables` | `{"user_id":"${business system user ID}","gas_volume":"${designed gas usage scale}","address":"${gas usage address}"}` | Maps core business fields from external systems to FastGPT's document generation variables, matching structured data formats |
| Timeout Duration | `600 seconds` | Urban gas business document generation includes attachment processing, requiring sufficient time for transmission and generation |
| Attachment Size Limit | `1000 MB` | Meets the size requirements for common gas business documents such as safety inspection reports and installation drawings |
| `responseData` | `{"status":"success","document_url":"${generated document storage path}"}` | Returns generation results in a standardized format to facilitate external systems to synchronously obtain the document address |
| Authentication Key Management | Managed via the enterprise's unified key platform | Avoids hardcoding keys, improves security, and adapts to unified authentication management requirements |

## Three Common Configuration Errors
- Symptom: The interface returns a 401 Unauthorized status code or prompts authentication failure. Cause: The enterprise's unified managed API key is not used, and a plaintext key is hardcoded directly in the configuration, leading to key leakage or unauthorized calls.
- Symptom: Attachments cannot be recognized by FastGPT after upload, or the generated document lacks attachment content. Cause: Attachment transmission supporting PDF format is not configured, or the attachment field is not correctly mapped to the `variables` parameter.
- Symptom: Fields in the generated gas utility document are empty or do not match the business system data. Cause: Core fields from the business system such as designed gas usage scale and user address are not correctly bound to the `variables` parameter, or the parameter naming does not match FastGPT's variable rules.

## How to Confirm Proper Configuration
- Call the test interface, check if the returned `responseData` contains the correct document storage path, and verify the interface return status code.
- Upload a commonly used PDF attachment for urban gas business, confirm that FastGPT can read it normally and associate the attachment content in the generated document.
- Pass simulated business system fields to generate a test document, verify that the structured fields match the passed parameters.
- Check the authentication configuration, confirm that plaintext API keys are not exposed in code or the interface, complying with enterprise security specifications.
