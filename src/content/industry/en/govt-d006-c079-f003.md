# Document and Material Drafting for Urban Gas: Multi-turn Dialogue and Prompt Engineering
This document is written based on FastGPT v4.17.0.

## What the data for this category looks like
The data sources for urban gas document and material drafting mainly come from internal business systems of gas enterprises. These include installation applications, safety inspection reports, payment notices, and compliance approval documents. Data updates trigger alongside business processes. Synchronization occurs when an installation application is submitted, an inspection is completed, or an approval node changes.
Document structures typically include modules such as business subject information, gas usage address, gas usage scale, approval nodes, and compliance clauses. Fields include a 12-digit gas installation number, gas load measured in cubic meters per hour, pipeline pressure measured in kilopascals, inspection dates in YYYY-MM-DD format, and some documents must match fixed compliance clauses from local gas management authorities.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Fields in gas documents have clear business attributes and associated units. Multi-turn dialogue must strictly match field formats to avoid unit confusion or content that does not align with actual gas usage. Business processes follow a clear sequence of nodes. Multi-turn prompt engineering must track the current approval link, and must not generate document content that skips steps or falls outside the current node. Data is updated in real time alongside business processes. Dialogue context must sync the latest approval status and on-site data to prevent use of expired information. Some documents require fixed compliance clauses. Prompt engineering must preset rules for calling these clauses to ensure generated content meets local gas management requirements.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind installation number, gas load, and approval node fields | Urban gas documents require precise matching of business system fields to avoid generating content inconsistent with actual gas usage |
| `messages` | Retain the most recent 5 rounds of dialogue context | Gas approval processes have clear node sequences, and excessive historical dialogue will interfere with compliance judgments for the current link |
| `chatId` | Enable session persistence, with a session validity period of 7 days | Urban gas installation and inspection rectification processes usually span 1 to 3 days. Session IDs are needed to track the complete process |
| Maximum context length | 8000–12000 token | A single gas document usually contains 1000 to 3000 characters. Multi-turn dialogue must retain core information such as approval opinions and on-site data |
| Timeout setting | 600 seconds | Queries for gas business data usually require connecting to internal systems, so sufficient interface call time must be reserved |

## Three Common Mistakes
- Symptom: Tool call results do not display in the dialogue box. The results become visible after re-entering the session, but no tool return content is present. Cause: `variables` are not correctly bound to associated business data. This prevents retrieval of the latest gas installation parameters during tool calls, triggering a context matching failure.
- Symptom: The iframe-integrated interface displays in English. Cause: Session language binding is not configured, so the default FastGPT English template loads automatically.
- Symptom: Request Time errors occur frequently during dialogue. Cause: The timeout setting value is lower than the response duration of the business system’s interface. This terminates the session before internal data queries are completed.

## How to Verify Proper Configuration
- Launch a dialogue for drafting installation documents, enter the installation number, and confirm the generated document automatically populates the corresponding gas usage address and gas load fields.
- Launch a 3-round approval process dialogue, confirm the `chatId` does not change, and verify historical approval opinions are correctly retained in the context.
- Launch a dialogue involving complex compliance clauses, confirm the generated document includes mandatory clauses from local gas management authorities.
- Test the timeout scenario, set a 600-second timeout, launch an internal data query, and confirm no Request Time errors appear.
