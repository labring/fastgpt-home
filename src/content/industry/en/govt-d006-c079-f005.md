# Document and Material Drafting for Urban Gas: Tool Calling and Plugins

## What This Category of Data Looks Like
This category of data primarily originates from gas operation management systems, GIS pipeline network platforms, and user application and ventilation business databases. Data sources include daily inspection logs, application forms, ventilation acceptance reports, pipeline renovation plans, and similar materials.
Update frequencies fall into three categories:
- Inspection records are updated daily
- Application and ventilation data is updated monthly
- Pipeline renovation plans are updated based on project cycles
Documents primarily use structured fields, including pipeline number, user address, operating pressure (unit: kPa), construction date, rectification items, and some include on-site image attachments.

## Constraints Imposed by These Characteristics on Tool Calling and Plugin Workflows
The structured fields and varying update frequencies of urban gas data impose clear constraints on tool calling and plugin configuration.
Fields with units such as pressure values and construction dates require plugins to enforce matching preset formats during calls, to avoid unit conversion or field mismatch errors.
Differences in update cycles across data sources require adding timeliness filtering rules in plugin logic, to only call inspection records from the last 7 days and application data from the current month.
Documents with on-site images require plugins to support multi-modal parsing, otherwise rectification text content in attachments cannot be extracted.
Pipeline number association requirements require adding number validation during tool calls, to prevent cross-region data confusion.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios for gas document drafting, covering document generation needs for different business types |
| `functionCall` | `enabled` | Enforces generation of structured tool calling parameters, ensuring output complies with format requirements for gas business fields |
| Single tool call limit | Top 3 entries | Gas business data has moderate per-entry volume; too many calls will exceed context window limits |
| Tool call timeout | 60 seconds | Internal business data APIs typically respond within 30 seconds, providing a reasonable buffer |
| Multi-modal plugin switch | Enabled | Some gas documents include on-site image attachments, requiring text parsing from attachments |

## Three Common Mistakes
- 500 error occurs when importing gas business documents. Cause: Multi-modal plugin switch is not enabled, unable to parse on-site image attachments attached to documents, causing system parsing process to interrupt.
- Unable to retrieve gas data references when calling online tools. Cause: No data source filtering rules are configured for tool calling, and no restriction is set to only call compliant data from the gas business database.
- Incorrect units appear in document fields generated after tool calling. Cause: `functionCall` forced format validation is not enabled, resulting in generated pressure values that do not match the kPa unit requirement.

## How to Verify Configuration is Correct
- Upload a gas inspection report with on-site images, check if the system can successfully parse rectification text content in the attachments.
- Set `toolChoice` to `auto`, submit a request to draft a ventilation acceptance report, check if the system automatically calls the corresponding tool to obtain pipeline data.
- Submit a tool calling request, verify if a normal result is returned within 60 seconds to confirm the timeout configuration is effective.
- Check if the pressure value field in the generated document includes the kPa unit, confirming that `functionCall` format validation is effective.
