# Document and Material Drafting for Urban Investment Platforms: Knowledge Base Retrieval and Recall

## What This Category’s Data Looks Like
The data for urban investment platform document and material drafting is mainly sourced from project approvals on official government disclosure platforms, urban investment bond issuance announcements, internal project ledgers, compliance requests and approval documents, as well as business documents such as tendering and contract performance. Update cadences include scheduled quarterly and annual updates, plus immediate updates triggered by temporary project initiation or policy adjustments. Document structures mostly include structured fields such as document number, issuing unit, issuing date, project code, involved amount (unit: ten thousand yuan), and approval level. Single document length varies widely, from hundreds of words for simple requests to tens of thousands of words for feasibility study reports.

## Constraints on Knowledge Base Retrieval and Recall
Data sources include both public and internal categories, so retrieval systems require permission isolation configuration to prevent unauthorized access to internal sensitive documents.
Different update cadences require knowledge bases to support incremental synchronization and manual trigger updates, to enable fast indexing of temporary project files.
Structured fields and unified units in documents require retrieval systems to support field-level matching and unit-associated retrieval, to improve recall accuracy for compliance-focused content.
Wide variation in document length requires chunking and recall parameters to adapt to different text lengths, avoiding over-cutting of long documents or loss of key information in short documents.

## Configuration Parameters
This document uses the configuration logic of FastGPT v4.17.0. The specific parameter configurations are as follows:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Urban investment documents are mostly compliance-focused content. A high matching threshold is needed to filter out irrelevant documents and avoid using incorrect reference materials during drafting. |
| `limit` | Top 8–12 results | Urban investment documents involve many projects. Too many results will exceed the context length limit, while too few will miss relevant compliance references. |
| `searchMode` | Semantic + keyword hybrid retrieval | Balances precise matching of structured fields such as document numbers and semantic association of business content, adapting to professional queries for document drafting. |
| `usingReRank` | Enabled | Filters low-matching recall results, improves the relevance of returned content, and meets the strict requirements of urban investment document drafting. |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements synonym matching for professional terms. For example, it matches "project feasibility study" to "feasibility study report", covering different expression habits used during drafting. |
| `collectionIds` | Fill in the collection ID of the exclusive knowledge base for the corresponding urban investment platform | Isolates document resources from different platforms, prevents recall of irrelevant data, and ensures the retrieval scope only covers compliance documents from the current platform. |

## Three Common Configuration Mistakes
- After calling the `/api/v1/chat/completions` interface, the returned results do not include source document information such as file name and chunk position. The cause is that the retrieval result traceability switch is not enabled, or relevant fields for returning source text are not configured in the retrieval parameters.
- After configuring the application appId, no documents from the urban investment platform uploaded to the knowledge base are recalled. The cause is that the corresponding knowledge base collection is not specified via the `collectionIds` parameter, or valid documents have not been uploaded and indexed in the collection.
- The retrieval results contain a large amount of content irrelevant to the current document drafting. The cause is that the `similarity` parameter threshold is set too low, or the reranking function is not enabled, resulting in recall of low-matching documents.

## How to Verify Correct Configuration
- Upload a project approval document from an urban investment platform to the exclusive knowledge base, initiate a query that includes the approval document number, and check whether the returned results include the traceability information of this document.
- Check the index status of the knowledge base collection, confirm that all urban investment documents have been indexed, and there are no failed tasks.
- Call the retrieval interface, pass the specified `collectionIds` parameter, and check that the returned results only include documents from this collection.
- Adjust the `similarity` parameter and initiate a query, check whether the matching degree of the returned results meets the expected threshold.

The values provided here are common starting points and should be measured against the reader's own samples.
