# Document and Material Drafting for Basic Chemical Industry: Workflow Orchestration
This document is compatible with FastGPT v4.17.0.

## What This Category of Data Looks Like
Document and material drafting for basic chemical industry relies on multi-source data, including production shift logs, quality inspection reports, material MSDS documents, and safety operation procedures. Data update cadence: production logs are updated per shift, quality inspection reports are updated daily, and MSDS documents are updated irregularly as materials are iterated. Document structure includes structured fields and unstructured text. Structured fields include material code, batch number, density, pressure, etc., with units mostly kg/m³, MPa, ℃. Unstructured text includes long-form content such as process steps and exception handling records.

## How These Characteristics Impact Workflow Orchestration
The mixed data structure of basic chemical industry requires workflows to first extract structured fields, then integrate unstructured text to generate documents. Frequently updated production data requires workflows to set timed trigger nodes to ensure the latest log data is used. Structured fields with multiple units require adding unit verification nodes in orchestration to avoid unit errors in generated documents. Long-text process documents require workflows to support chunking to prevent exceeding context limits. Cross-node parameter passing must strictly match field names to ensure accurate field mapping between production data and document templates.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `variables` | `{"material_code": "", "batch_no": "", "pressure": 0}` | Matches core structured fields from basic chemical industry logs, used for parameter passing between nodes |
| `nodeId` | Use actual IDs of document extraction nodes and SQL query nodes | Accurately binds output results of corresponding nodes to avoid parameter transfer errors |
| Cycle trigger interval | `3600 seconds` | Basic chemical production logs are updated per shift; pulling data hourly covers the latest available data |
| Document chunk length | `800–1200 characters` | Adapts to average paragraph length of basic chemical industry MSDS documents and process specifications |
| Timeout period | `120 seconds` | Generating basic chemical industry documents requires calling multiple nodes; this setting avoids long waits blocking the workflow |
| Exception node retry count | `3 times` | Basic chemical industry data updates occasionally have delays; retries reduce workflow failure rates |

## Three Common Mistakes
- The output fields of HTTP request nodes in the workflow are empty and cannot be displayed in the chat interface. Cause: Output variable mapping is not configured in `variables`, causing node results to not be passed to the chat context.
- Loop body nodes do not set termination conditions, causing document generation to run in an infinite loop. Cause: The basic chemical industry batch number is not bound as the loop termination identifier, so the process cannot stop automatically.
- Workflow node order is reversed: SQL query is executed before document extraction. Cause: Nodes are not orchestrated in data dependency order, leading to pre-node data being unavailable, so subsequent nodes cannot obtain valid parameters.

## How to Confirm Proper Configuration
- Manually trigger the workflow, check if `variables` in node logs include core fields for basic chemical industry materials.
- Simulate production shift data updates, verify whether the workflow pulls data again at the set 3600-second interval.
- Test triggering retries for exception nodes, check if the process terminates after 3 retries and returns corresponding error messages.
- Check the workflow node order, confirm that data-dependent nodes execute before nodes that rely on their results.
