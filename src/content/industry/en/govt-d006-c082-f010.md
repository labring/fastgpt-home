# Document and Material Drafting for Basic Telecommunications Operations: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data for document and material drafting in basic telecommunications operations mainly comes from operation and maintenance ticket libraries, communication tariff specifications, network technical documents, customer service templates, fault handling manuals, and other sources. The update rhythm adjusts with business changes. Tariff standards are updated with policy changes. Operation and maintenance documents are updated with network fault optimizations. Service templates are iterated with compliance requirements. Document structures include structured tables, long-text technical descriptions, and standardized document formats. Fields include service codes, effective dates, fault levels, bandwidth parameters, and others. Units involve yuan/minute, Mbps, hours, and similar units.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
The characteristics of basic telecommunications operation business data impose multiple constraints on retrieval and recall. The feature of multiple associated fields in structured tables requires retrieval to support field-level precise matching, to avoid semantic recall deviating from business dimensions. A high proportion of long-text technical documents are prone to semantic fragmentation after single-block embedding, so chunking parameters need adjustment to adapt to long paragraph splitting. Frequently updated operation and maintenance and tariff data require the recall link to prioritize matching the latest data sources, to avoid returning expired content. The fixed format of standardized document templates requires retrieval results to retain the original typesetting structure, to avoid generating drafting content with format errors.

## How to configure the settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | Match the semantic matching accuracy of telecommunications business terms, avoid recalling irrelevant operation and maintenance documents or tariff descriptions |
| `limit` | Top 8–12 results | Cover multiple types of reference data required for telecommunications document drafting, avoid insufficient information in a single result |
| `searchMode` | semantic | Meet the semantic recall needs for long-text and structured documents, match the association logic of business terms |
| `usingReRank` | Enabled | Perform secondary sorting on initial recall results by relevance, correct semantic misjudgments of telecommunications professional terms |
| `datasetSearchUsingExtensionQuery` | Disabled | Avoid tampering of telecommunications professional terms caused by automatic query expansion, retain the original retrieval intent |
| `collectionIds` | Configured with specified telecommunications business knowledge base IDs | Limit the retrieval scope to documents exclusive to basic telecommunications operations, exclude irrelevant business libraries |

## Three common configuration mistakes
- Phenomenon: Retrieval score exceeds 1000, which falls outside the normal 0-1 range. Cause: The threshold verification logic for the `similarity` parameter is not configured correctly, and a non-normalized similarity calculation method is used.
- Phenomenon: Retrieval results from the specified knowledge base cannot be called in the workflow. Cause: The correct knowledge base ID is not passed in the `collectionIds` parameter, or the ID format does not meet platform requirements.
- Phenomenon: Retrieval cannot match cell content after a complex table is imported into the knowledge base. Cause: Structured data parsing mode is not enabled, causing table content to be split into unrelated text blocks.

## How to confirm the configuration is correct
- On the knowledge base retrieval test page in the workspace, enter telecommunications business terms, and check whether the correlation scores of returned results fall within the 0-1 range.
- After configuring the `collectionIds` parameter in the workflow, run test cases to confirm that retrieval results only come from the specified basic telecommunications operations knowledge base.
- After importing a structured table document, perform retrieval, and check whether the returned results contain complete table cell content.
- After enabling `usingReRank`, compare the initial recall results with the reordered results to confirm that highly relevant results are displayed first.

The values provided are common starting points and should be measured against the user's own samples.
