# Document and Material Drafting for Infrastructure Construction: Multi-turn Dialogue and Prompt Engineering
## What the Data for This Category Looks Like
Data related to document and material drafting for infrastructure construction mainly comes from project management systems, BIM ledgers, on-site inspection records, contract attachments, and past completion archives. Data update rhythms vary significantly by document type: weekly work reports are synchronized and updated weekly, engineering visa forms are submitted in real time with on-site changes, and completion-related materials are collected in batches during the project closing phase. Each individual document has fixed fields including project number, section code, issuance date, responsible team, quantifiable items, and attachment list. Quantifiable fields mostly use units such as cubic meters, square meters, yuan, and days.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The scattered data sources and differentiated update rhythms for infrastructure construction documents require that multi-turn dialogue must first bind the project number and section as context anchors to avoid mixing data across projects. For real-time updated visa forms and weekly reports, prompt engineering must explicitly specify prioritizing the latest data from the project bound to the current conversation to prevent use of outdated information. Fixed quantifiable fields and dedicated units require prompt engineering to enforce matching the unit format of the corresponding construction section, ensuring consistent measurement specifications for generated documents. For batch-collected completion archives, multi-turn dialogue must support batch recall of historical documents by keywords while retaining project context association for each conversation turn.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `chatId` | Use the unique section number bound to the current project as the value | Anchor conversation context, avoid mixing data across construction sections, and adapt to parallel construction scenarios for multiple projects |
| `messages` | Retain the first 8 historical messages per conversation turn, automatically truncate earlier content | Balance context completeness and response speed, adapting to the rhythm of multi-turn communication for infrastructure construction documents |
| `variables` | Preset three variables: project number, section code, and common units of measurement | Enforce matching the fixed fields of infrastructure construction documents, ensuring generated content complies with project specifications |
| Maximum context length per single conversation | 8000–12000 token | Cover the context requirements of a single core construction document and multi-turn communication |
| Data recall priority | Prioritize recalling documents updated in the last 7 days | Adapt to the real-time update characteristics of on-site infrastructure construction data, avoiding the use of outdated information |
| Document type template binding | Bind templates classified by visa form, progress report, and acceptance materials | Match the fixed format requirements of various documents for infrastructure construction |

## Three Common Misconfigurations
- Symptom: After calling the API to start a conversation, the generated reply does not reference infrastructure construction documents in the knowledge base. Cause: The project number and other dedicated variables are not bound in `variables`, causing the model to fail to accurately recall documents for the corresponding construction section.
- Symptom: When using versions of FastGPT below v4.17.0, the conversation or knowledge base page crashes. Cause: Older versions have memory overflow issues with multi-turn context processing, leading to insufficient stability when adapting to large infrastructure-related documents.
- Symptom: The configured guide prompt does not take effect, and the generated documents do not comply with the format requirements of infrastructure construction documents. Cause: The document type template is not bound to the corresponding conversation, or the prompt engineering does not explicitly specify the fixed field requirements for infrastructure construction documents.

## How to Verify Correct Configuration
- Initiate a test conversation, enter the project number and section code, and check whether the bound `chatId` of the conversation matches the preset value.
- Call the API to start a multi-turn conversation, check whether the returned `messages` list retains the specified number of historical messages.
- Generate a visa form, check whether the generated content includes the preset `variables` fields and corresponding units of measurement.
- Trigger data recall, check whether the returned documents are infrastructure-related documents updated within the last 7 days.

The values provided are common starting points and should be evaluated against individual use case samples.
