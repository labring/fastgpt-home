# Document and Material Drafting for Infrastructure Construction: Workflow Orchestration

## What this category of data looks like
Documents and materials for infrastructure construction mainly come from project construction logs, bidding documents, change visas, completion acceptance reports, and similar sources. Data update rhythm adjusts based on project progress nodes. Construction logs update daily or weekly. Progress ledgers update monthly. Acceptance documents are archived once after the corresponding node is completed. Each individual document includes fields such as project number, section information, construction date, project quantity, and acceptance opinions. Field units are mostly cubic meters, square meters, working days, ten thousand yuan, and similar units. Some documents have cross-page field associations.

## What constraints do these characteristics impose on workflow orchestration?
Infrastructure construction document data comes from scattered sources and has inconsistent structures. Workflows must configure field mapping rules for multi-source data to avoid information extraction deviations. Data updates trigger with project nodes. Workflow startup timing must match project nodes to avoid unnecessary runs. Individual documents are lengthy and have cross-page field associations. Workflows must support segmented extraction and retain field context. They must also control the amount of information processed per round to prevent resource overload. Core global fields such as project number must be reused across multi-link workflows. A global variable storage mechanism must be configured to ensure data consistency across nodes.

## How to set the configurations
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Global variable storage | Enable and bind project ID as the fixed key | Infrastructure construction project documents need to reuse core fields such as section information and project quantity across nodes, preventing variable loss from session resets |
| Workflow trigger node | Trigger on completion events of construction nodes | Matches the rhythm of data updates based on project nodes, starting the workflow only when valid data is generated |
| Knowledge base recall limit | Top 8 entries | Individual construction documents have high information density, controlling the number of recall results to avoid context overload |
| Variable extraction rule | Bind the `variables` parameter to specify core fields | Accurately extract key fields such as project quantity and acceptance opinions from documents, preventing invalid information from being included |
| Timeout threshold | 600 seconds | Large construction documents take longer to process, reserving sufficient processing time |
| Inter-node data transfer | Enable `nodeId` to associate context | Retain variables extracted in the previous node, ensuring data continuity across multi-link workflows |
| Chunk length | 800-1200 characters | Adapts to the field density of construction documents, avoiding damage to cross-page field associations from chunking |

## Three common errors
- Phenomenon: The project quantity field extracted after the workflow runs is empty, and there is no extraction record for the corresponding field in the logs. Cause: The `variables` parameter is not bound to specify the extraction rule for the corresponding field, so the system cannot match the target field in the document.
- Phenomenon: The knowledge base search returns no results, and the interface displays "No matching results". Cause: Precise retrieval conditions are not set based on the project number and section information of the construction document, and only generalized questions are used to trigger the search.
- Phenomenon: Global variables are reset after the session ends, and the previously stored project ID cannot be read when the workflow starts again. Cause: The global variable storage function is not enabled, and only session-level variables are used, causing variables to be cleared after the session ends.

## How to confirm the configuration is correct
- Trigger a simulated completion event for a construction node, check if the workflow starts as expected.
- View the variable panel, confirm that core fields such as section information and project quantity are correctly stored and not reset.
- Initiate a document retrieval, check if the number of returned results matches the preset recall limit.
- View the workflow run logs, confirm that the `variables` and `nodeId` parameters are correctly called.
