# Documentation and Material Drafting for Infrastructure Construction: Tool Calling and Plugins

## What data for this category looks like
Infrastructure construction document data originates primarily from project construction logs, bidding filing documents, completion acceptance materials, and on-site supervision records. Data updates align with project milestones. On-site logs receive weekly updates during the construction phase, and all materials are archived centrally during the completion phase. Single document length varies widely, from several hundred-word on-site visa forms to tens of thousands-word completion summary reports. Fixed fields in documents include project section number, construction location, operation date, responsible entity, and inspection result. Some special documents attach engineering quantity measurement values, with units of cubic meters, linear meters, or square meters.

## What constraints these characteristics impose on the "tool calling and plugins" link
The variable length of infrastructure construction documents requires tool calling to support dynamic adaptation of input context length, to prevent long documents from being forcibly truncated and losing key measurement information. Differences between fixed fields and special measurement units require plugin calls to pre-bind field mapping rules for corresponding documents, to prevent misidentification of measurement values and units. Update rhythm following project milestones requires tool calling links to support real-time pulling of newly archived project documents, to avoid using outdated historical data. Required field requirements for form documents require plugin calls to verify completeness of required items, to avoid generating non-standard submission materials.

The following configurations apply to FastGPT v4.17.0.
## How to set the configurations

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Tool calling mode | Enable `functionCall` mode, with `toolChoice` automatically matching tools | Adapt to structured field requirements of infrastructure documents, clarify execution logic of tool calling |
| Plugin context length | 8000–12000 characters | Cover completion reports and construction logs up to tens of thousands of words, prevent key information from being truncated |
| Field mapping verification | Enable | Match fixed field rules of infrastructure documents, automatically verify required items such as project section number and operation date |
| Call timeout period | 60 seconds | Adapt to time consumption of large document parsing and tool calling, avoid process interruption |
| Document upload size limit | 1000 MB | Adapt to upload requirements of large infrastructure completion reports, avoid upload failure due to oversized files |
| Real-time data synchronization | Triggered by project milestones | Update data sources following construction, completion and other milestones, ensure called documents are the latest versions |

## Three common mistakes
- Phenomenon: Infrastructure documents generated via API calls differ from results generated in the platform chat interface, with some measurement fields empty. Cause: API calls did not bind the dedicated document data source for the corresponding project, only called general knowledge base content, and did not match the dedicated field rules of infrastructure projects.
- Phenomenon: Tool calling cannot distinguish workflows of different sections, with returned content mixing document data from multiple projects. Cause: No project section number was specified as a filter condition in tool calling parameters, resulting in results from all workflows.
- Phenomenon: Local construction log documents cannot be uploaded via API calls, and generated documents lack latest on-site data. Cause: No adaptation rules for local document upload were configured, only document upload operations via the platform interface were supported, and the API calling scenario was not covered.

## How to confirm the configuration is correct
- Initiate an API call, check the tool calling log, confirm that the `functionCall` mode and `toolChoice` matching logic have taken effect as configured.
- Upload an infrastructure document corresponding to a section, verify that the generated document contains correct fixed fields such as section number and operation date.
- Trigger a project milestone update, confirm that the called data source is the latest version document of the current project.
- Upload a large completion report within 1000 MB, verify that no key content has been truncated in the generated document.
