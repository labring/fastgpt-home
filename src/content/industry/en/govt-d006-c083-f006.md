# Document and Material Drafting for Infrastructure Construction: Source Citation and Traceability

## What the data for this category looks like
Infrastructure construction document data primarily comes from project output documents such as construction logs, bidding documents, design clarification records, and completion acceptance reports. Data update rhythm follows project milestones. Submitted documents are mostly a mix of structured and semi-structured formats. They include fields like project number, section division, construction date, material specification, and acceptance conclusion. Units include engineering-specific measurement units such as cubic meters, meters, and tons. Single document length varies widely, from hundreds to tens of thousands of characters.

## What constraints do these characteristics impose on the "source citation and traceability" link
The long text span of infrastructure construction documents requires retaining key context during traceability, to avoid losing project logical connections after splitting. The presence of specialized measurement fields and units means traceability matching must accurately correspond to field dimensions, and cannot rely solely on keyword hits. Irregular milestone-based updates require the knowledge base traceability to associate with the corresponding project version, to avoid citing expired documents. Most internal project documents are not bound to public web links, so external link-based traceability methods cannot be used directly.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 6 results | Infrastructure construction documents are mostly categorized by section. Too many recall results will cause context overload. 6 results can cover core documents for a single section |
| Reranking | Enabled | Long documents are prone to logical breaks after splitting. Reranking prioritizes retrieving paragraphs more relevant to the query |
| Maximum Context | 8000–12000 token | Single engineering documents can be tens of thousands of characters long. Sufficient context preserves construction logical connections |
| `quoteMaxToken` | 300–500 token | Limits the length of cited passages, matching the information density of individual clauses in engineering documents |
| `responseData` | Enable source field display | Directly displays fields such as project number and section from documents, replacing vague source annotations |
| `detail` | Enable detailed traceability | Displays context paragraphs of cited passages, making it easier to verify the accuracy of engineering parameters |

## Three Common Mistakes
- Phenomenon: After configuration, the citation source is displayed as an external web link, which cannot match internal engineering documents. Cause: Core infrastructure construction documents are mostly internal project files, not bound to public web or Notion links. Using external link-based traceability configuration cannot target intended data.
- Phenomenon: Returned cited passages lose engineering-specific units or field information. Cause: The `detail` configuration is not enabled, or the context length is not set sufficiently. Field association logic is lost when splitting documents.
- Phenomenon: Retrieved cited content is completely unrelated to the queried engineering requirements. Cause: The single search limit is set too high, retrieving documents from non-corresponding sections, or reranking is not enabled, causing low-relevance passages to be prioritized for display.

## How to Confirm the Configuration is Correct
- Upload a typical construction log document, submit a query containing specific engineering parameters, and check if the source annotation of the returned result includes exclusive fields such as project number and section.
- Check if the context of the cited passage covers key information such as construction date and material specification, and confirm that the context length matches the information density of the current document.
- Submit a query targeting an expired project, verify if the returned result is associated with the latest updated version, and confirm that the knowledge base version traceability configuration is effective.
- Check the application logs for FastGPT v4.17.0, confirm that the `responseData` configuration is enabled, and that no null values or error identifiers appear in the source fields.
