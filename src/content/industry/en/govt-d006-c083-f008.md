# Documentation and Material Drafting for Infrastructure Construction: Document Parsing and Chunking

## What data in this category looks like
Under FastGPT v4.17.0, documents for infrastructure construction documentation and material drafting primarily originate from various files across the full project lifecycle, including bidding documents, construction logs, supervision reports, completion materials, and supporting design documents. Update frequency varies by project phase: bidding phase concurrently updates bidding and tendering documents, construction phase updates site records daily or weekly, and completion phase outputs full archived materials. Most documents are multi-page PDFs, containing nested table of contents, structured engineering quantity tables, scanned drawing explanations, and fields including project number, section number, engineering quantity values and corresponding units (cubic meters, meters, tons, etc.). Some documents include handwritten annotations and official seals.

## Constraints imposed on the document parsing and chunking link by these characteristics
Multi-source, mixed-format documents require parsing tools to support both editable PDFs and scanned documents, to prevent partial content from failing extraction. Long documents can reach hundreds of pages, extending parsing time and exceeding default thresholds which leads to task interruption. Nested table of contents and structured engineering quantity tables demand precise chunking logic; otherwise, semantic content will be split, reducing subsequent retrieval accuracy. If engineering quantity data with specific units is incorrectly split, the value and unit will be separated, resulting in loss of critical business information.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodate the total size of a single set of completion materials or multi-page bidding documents, prevent file truncation during upload |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 seconds | Handle parsing of long documents with hundreds of pages, avoid task interruption from default timeout |
| `customPdfParse` | Enable OCR mode | Adapt to scanned construction drawing supporting documents, restore printed text and handwritten annotation content |
| `chunkSplitter` | Split by paragraph + heading hierarchy | Match the nested table of contents and chapter structure of infrastructure documents, preserve contextual association |
| `chunkSize` | 800–1200 characters | Balance semantic completeness of single chunk and retrieval accuracy, adapt to the length of engineering quantity descriptions and progress data |
| `chunkSettingMode` | Manual configuration mode | Adjust chunking rules for the special format of infrastructure documents, avoid generic chunking breaking unit and field association |

## Three Common Errors
- Phenomenon: Parsing API calls return timeout errors, or pages display "Parsing incomplete". Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default duration is insufficient for parsing hundreds of pages of infrastructure documents.
- Phenomenon: Engineering quantity values and their corresponding units are separated in chunking results, with empty fields. Cause: The `chunkSplitter` is not configured to split by heading hierarchy, causing cross-block truncation of engineering quantity entries with units.
- Phenomenon: Large file uploads prompt upload failure. Cause: The `UPLOAD_FILE_MAX_SIZE` parameter is not adjusted. The default size limit cannot accommodate a single set of completion material packages.

## How to Confirm Configurations Are Set Correctly
- A multi-page infrastructure PDF document with more than 100 pages is uploaded. Parsing time is verified to fall within the preset range of `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout errors occurring.
- Chunked content is reviewed to confirm that engineering quantity values and their corresponding units are contained within the same chunk, with no split breaks.
- The retrieval function is tested. A query containing section information and engineering quantity keywords is entered, and retrieved chunks are confirmed to include corresponding business content.
- A scanned infrastructure document is uploaded. Extraction of printed text and handwritten annotation content after parsing is confirmed.

The values listed above are common starting points and should be evaluated against the user’s own samples.
