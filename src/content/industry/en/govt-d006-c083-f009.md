# Document and Material Drafting for Infrastructure Construction: Model Access and Configuration

## What Data for This Category Looks Like
Documents and materials for infrastructure construction mainly originate from construction logs, bidding documents, completion acceptance submissions, and supervision weekly reports generated during project construction. Data is updated in stages aligned with project progress. The length of individual documents varies widely, from several hundred-word site visas to tens of thousands-word completion final account reports. Document structures follow fixed industry specification fields, including project number, engineering location, material specifications, acceptance level, and more. Common units follow engineering measurement standards such as meters, cubic meters, and tons.

## Constraints Imposed on Model Access and Configuration
The wide range of document lengths for infrastructure construction materials requires model access to adapt to variable context windows, preventing truncation of key content such as engineering measurements and acceptance standards. Fixed professional fields and measurement units require model configuration to enable professional term recognition logic, to avoid errors in parsing parameters or units. Staged updated data sources require configuration to associate regularly synchronized data source paths, ensuring documents called by the model are the latest project materials. The high density of professional details in individual documents requires adjusting the model's output rigor parameters during configuration, to avoid generating vague content that does not meet industry specifications.

## How to Configure the Settings

| `maxContext` | 8000–12000 token | Adapts to the long text characteristics of infrastructure construction documents, avoiding truncation of key content such as engineering measurements and acceptance standards |
| `maxTokens` | 2000–3000 token | Meets the detailed output requirements for engineering document drafting, covering the complete generation logic of documents such as construction plans and visa forms |

| `toolChoice` | auto | Allows the model to automatically select tools based on document drafting needs, adapting to the generation of different types of documents such as bidding documents and completion reports |
| `AIPROXY_API_TOKEN` | Fill in the model service key applied for in actual practice | Ensures legitimate identity verification for model calls, avoiding access failures |

## Three Common Misconfigurations
- Phenomenon: After upgrading the FastGPT version, the specified large model configured changes to another model when returning to the chat interface after saving. Cause: The model key and deployment endpoint are not correctly bound, or configuration items are not retained synchronously after the upgrade.
- Phenomenon: After accessing the document processing tool, the parsing speed of uploaded engineering documents slows significantly. Cause: The tool's chunking parameters are not adjusted for long-text engineering documents, resulting in excessive single processing data volume.
- Phenomenon: When adding a model token through a third-party API gateway, the error "Data too long for column 'models'" is prompted. Cause: The length of the model list associated with the token is not limited, exceeding the storage limit of the database field.

## How to Verify Successful Configuration
- Check the content filled in `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` to ensure they match the deployed model service address and key.
- Initiate a drafting test for a short document such as a site visa to verify that the generated content includes correct engineering fields and units.
- Upload a long-text engineering document and check that no context window truncation prompt appears during model calls.
- Adjust the `temperature` parameter and initiate a test to confirm that the rigor of generated content changes as expected with the parameter.

The values provided are common starting points and should be evaluated against the reader's own samples.
