# Document and Material Drafting for Infrastructure Construction: Deployment and Upgrade

## What the data for this category looks like
Document data for infrastructure construction is sourced from project approval documents, construction logs, material site acceptance receipts, progress submission forms, completion acceptance reports, and similar materials. Updates follow project milestones: initial documents are uploaded during the project initiation phase, progress-related documents are updated weekly during the construction phase, and finalized files are archived during the acceptance phase.
Document structures typically include fields such as project number, section name, construction entity, progress node, material usage, and acceptance criteria. Units used include engineering-specific units such as cubic meters, meters, man-days, and ten thousand yuan. The length of a single document mostly falls between thousands and tens of thousands of characters.

## Constraints imposed by these characteristics on deployment and upgrade
The multi-source, non-standardized structure of infrastructure construction documents requires deployments to support parsing of multiple document formats. The incremental update pattern tied to project milestones requires deployment workflows to support resumable synchronization logic. Large-volume attachments and long text content require upgrades to not interrupt ongoing file storage and indexing tasks. Retrieval requirements for dedicated engineering fields require post-upgrade systems to retain existing custom field mapping rules to prevent retrieval failures.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 120–180 connections per minute | Single infrastructure construction documents often contain multiple sections of construction parameters and process records. Restricting database connection count during high-frequency retrieval prevents overload |
| `MONGODB_URI` | Local replica set connection string with read-write authentication | Stores project document metadata, version history, and retrieval logs. Requires support for high-availability read-write operations |
| `REDIS_URL` | redis://127.0.0.1:6379/0 | Caches frequently accessed section document fragments to reduce access pressure on core databases |
| `STORAGE_S3_ENDPOINT` | Internal object storage service domain name | Stores large-volume attachments such as construction drawings and acceptance scan copies, and supports batch file upload requirements |
| `ROOT_KEY` | Randomly generated 32-bit hexadecimal string | Used for configuration administrator permission verification, preventing unauthorized access to the deployment backend |

## Three Common Misconfigurations
- Symptom: Database connection error `ETIMEDOUT`, interface displays "Retrieval failed". Cause: The `DB_MAX_LINK` parameter was not adjusted for the high-frequency retrieval scenario of infrastructure documents, and the connection pool upper limit was set too low.
- Symptom: When deploying without Docker, dependency package version conflicts cause service startup failure. Cause: Dependencies with specified versions were not installed per the official deployment process, and engineering document parsing plugins were not loaded correctly.
- Symptom: After upgrading to FastGPT v4.17.0, dedicated engineering fields from existing section documents cannot be retrieved correctly. Cause: Existing custom field mapping configurations were not retained during the upgrade, leading to invalid indexing rules for infrastructure-specific fields.

## How to Confirm Configurations Are Correct
- Access the domain configured in `FE_DOMAIN`, log in to the administrator backend, and check the database connection panel to confirm there are no red error prompts.
- Upload an infrastructure construction document containing engineering drawing attachments, confirm that the file can be stored normally and displayed completely in search results.
- Perform a batch indexing test, import 5 section documents, confirm that the number of matching entries in search results matches the number of imported documents.
- Restart the service, check the cache logs for `REDIS_URL`, confirm there are no connection failure error messages.
