# Document and Material Drafting for Commodity Trading: Citation Sourcing and Traceability

## What the data for this category looks like
The data sources for commodity trading cover five core document types: trade contracts, warehouse receipts, customs declarations, spot price quotes, and logistics waybills. Trade contracts are structured documents with fields including contract number, product category, transaction quantity, unit price, and more. Common units are tons and cubic meters. Warehouse receipts include fields such as warehouse receipt number, stored weight, storage location, and more, and are updated as goods enter or leave storage. Spot price quotes are updated hourly to daily. Customs declarations are updated once the customs clearance process is complete. Document lengths vary widely, ranging from hundreds to thousands of characters.

## What constraints these characteristics impose on citation sourcing and traceability
Unique identifier fields differ across data source types. Trade contracts use contract numbers, warehouse receipts use warehouse receipt numbers, and customs declarations use customs declaration numbers. Traceability requires matching corresponding identifiers based on document type, and a universal ID template cannot be used. Update cycles vary significantly across different documents. Spot price quotes require real-time matching of the latest data, while trade contracts and warehouse receipts are static data. Reference work must distinguish between timeliness requirements. Documents include units exclusive to commodity trading. Full retention of unit information is required during citation, otherwise traceability information will become invalid. Longer individual document lengths consume more context tokens, so the length of content cited in a single instance must be limited.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the typical length of reference documents for commodity trading, avoids context overflow |
| `responseData` | Enabled | Requires complete return of identification information for cited sources to support traceability |
| `detail` | Enabled | Requires retention of exclusive fields and units in documents to ensure traceability accuracy |
| Citation Matching Rule | Bind unique identifiers by document type | Adapts to exclusive identifier fields for different documents such as contracts and warehouse receipts |
| Single Recall Limit | Top 3 entries | Avoids excessive citations interfering with the specificity of document drafting |

## Three common mistakes
- The ID field of cited content is empty, and logs show no corresponding document identifier was matched. This occurs because unique identifier fields are not bound by document type, and a universal ID template is incorrectly used.
- The temperature parameter cannot be set after variable reference mode is enabled. This occurs because the model parameter adjustment entry is disabled by default in variable reference mode for FastGPT v4.17.0 and earlier versions, and must be enabled via global configuration.
- The number of cited results does not match the configured recall limit, and repeated citations occur across multiple rounds. This occurs because recall rules for real-time updated quote data and static contract data are not distinguished, leading to repeated recall of the same documents.

## How to confirm configurations are set correctly
- Generate a draft trade contract, check if the cited section at the end includes the unique identifier and field information of the corresponding document.
- View the metadata of the cited source, confirm that the matched identifier field matches the actual document's unique number.
- Adjust the `quoteMaxToken` parameter, verify that the citation length of generated content meets expectations.
- Test two different document types: contract and warehouse receipt, confirm that citation identifiers can correctly match the corresponding document type.

The values provided are common starting points and should be measured against the reader's own samples.
