# Document and Material Drafting for Commodity Trading: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for document and material drafting in commodity trading comes primarily from trade contracts, warehouse receipts, quality inspection reports, and settlement statements exported from internal ERP systems, plus paper compliance documents filed offline. Data is generated when individual trade transactions complete. Some batch-archived historical documents sync to the knowledge base weekly. Documents use a mixed structure: fixed structured fields and unstructured clause text. Structured fields include contract number, commodity category, transaction quantity (unit: ton), unit price (unit: yuan/ton), delivery location, and other standard fields. Unstructured sections contain long text such as transaction terms and compliance requirements.

## What constraints these characteristics impose on knowledge base retrieval and recall
Commodity trade document data mixes structured fields and unstructured clauses. The retrieval process must match both text semantics and structured metadata. Otherwise, documents from different commodity categories may be mixed together. If long text clauses are segmented without retaining hierarchical logic, retrieval results will have broken context and cannot fully match complete transaction terms. Irregular data updates require the retrieval process to support incremental recall and real-time synchronization configuration. This prevents missing newly generated trade documents. High concentrations of specialized terminology require retrieval to accurately match professional expressions. This avoids interference from low-relevance general content.

| `similarity` | 0.72–0.80 | Matches the precision of commodity trade specialized terms, avoids interference from low-relevance general clauses |
| `limit` | Top 8 results | Controls the number of returned results, prevents AI response interruption caused by context overflow |
| `searchMode` | hybrid | Combines keyword retrieval and vector retrieval, adapts to mixed content of structured fields and unstructured clauses |
| `usingReRank` | Enabled, use top 3 reranked results | Corrects deviations in vector retrieval, prioritizes matching core trade clauses and compliance content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands trade specialized terms, associates terms such as "FOB" and "CIF" with relevant compliance clauses |
| `collectionIds` | Bind to the exclusive knowledge base collection for commodity trading | Prevents mixing documents from other categories, ensures precise retrieval scope |

## Three Common Misconfigurations
- Phenomenon: Returned result count is far lower than expected, or non-commodity trading documents are included. Cause: Failed to bind `collectionIds` to specify the exclusive knowledge base collection, so the retrieval scope covers documents from other categories.
- Phenomenon: AI responses are interrupted mid-way, unable to output complete content. Cause: Did not set a reasonable `limit` parameter. Returning too many long documents causes the context length to exceed limits, triggering response truncation.
- Phenomenon: Retrieval results lose clause hierarchical logic, unable to match complete transaction terms. Cause: Did not retain Markdown heading structure when uploading documents to the knowledge base. Direct segmentation leads to lost logical relationships, so retrieval results cannot associate complete context.

## How to Verify Correct Configuration
- Before executing retrieval, check if `collectionIds` is bound to the current exclusive commodity trading knowledge base collection. Confirm the retrieval scope only covers target category documents.
- Trigger a specialized term retrieval, such as entering "CIF delivery terms". Check if returned results include relevant trade compliance content, and that matching meets expectations.
- View the metadata fields of retrieval results. Confirm that structured information such as contract number and commodity category is associated. This can be verified via interface metadata display or logs.
- Upload a trade contract with Markdown headings. Check if retrieval results retain heading hierarchical logic, with no broken context.

The values given are common starting points and should be measured against the reader's own samples.
