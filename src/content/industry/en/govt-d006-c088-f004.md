# Document and Material Drafting for Engineering Consulting Supervision: Workflow Orchestration

## What this category of data looks like
The document sources for engineering consulting supervision are on-site supervision process files. These include on-site supervision records, sub-project acceptance forms, supervision notices, quantity verification forms, and similar materials. Document updates trigger when project advancement milestones are reached, such as after completing sub-project acceptance or issuing rectification notices. Documents follow fixed structures, with fields including unique project ID, supervision unit signature section, construction location parameters, rectification closure status. Most fields use engineering units such as square meters, cubic meters, workdays. Single document lengths vary widely, from hundreds to tens of thousands of characters.

## What constraints do these characteristics impose on workflow orchestration
The characteristics of engineering consulting supervision documents create multiple constraints for workflow orchestration.
First, document sources are scattered across dedicated storage paths for individual projects. Use `variables` to link data source paths for corresponding projects, preventing cross-project data confusion.
Second, documents include engineering-specific units and fixed fields. Add field validation nodes in the workflow to ensure extracted units, project numbers, and other information meet standards.
Third, single document lengths vary widely, with some acceptance reports reaching tens of thousands of characters. Set a per-node character limit to avoid workflow execution timeouts.
Fourth, document updates trigger with project acceptance milestones. Bind project status as the workflow trigger condition, starting the workflow based on project node status.

## How to set the configuration
This page is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Method | Bind project acceptance node trigger | Matches the rhythm of supervision document updates with project milestones, avoids invalid execution |
| `variables` | Configure dedicated fields such as project number, construction location | Matches the fixed field structure of supervision documents, enables accurate data extraction |
| Content Processing Limit | 800–1200 characters per node | Adapts to single-paragraph processing needs of most supervision documents, avoids execution timeouts |
| Field Validation Switch | Enabled | Ensures extracted engineering units, numerical fields comply with standards, reduces subsequent document errors |
| Timeout Threshold | 600 seconds | Adapts to waiting needs for long document processing, prevents task interruption |
| Number of Recalled Results | Top 5 | Filters redundant non-essential engineering content |
| `nodeId` | Bind the export node of the preceding workflow | Supports cross-workflow data transfer, ensures correct delivery of intermediate results |

## Three Common Mistakes
- After importing preceding export configurations into the workflow, intermediate results do not meet expectations. Phenomenon: The second workflow can output final results normally, but intermediate extracted construction locations, quantity values do not match the output of the preceding workflow. Cause: Failed to bind the accurate output path of the preceding node via `nodeId`, resulting in reading incorrect intermediate data cache.
- The workflow cannot be called in the chat window after configuration. Phenomenon: After sending instructions in the FastGPT application chat interface, no corresponding workflow execution record appears, the interface returns empty results or prompts that the workflow is not configured. Cause: Failed to bind the workflow to the trigger rules of the corresponding application, or failed to enable the workflow call permission for the application.
- Redundant engineering terms appear in workflow processing results. Phenomenon: Generated supervision documents contain excessive non-essential industry specification content, interfering with the delivery of core information. Cause: Failed to configure field validation nodes to filter irrelevant recalled content, or failed to limit the number of recalled results.

## How to Confirm Correct Configuration
- Upload a supervision on-site record as test data, trigger workflow execution, and check if intermediate node field extraction results include required information such as project number, construction location.
- Manually modify the output content of the preceding workflow, verify whether the second workflow can correctly process the modified results.
- Disable the workflow's field validation switch, check whether intermediate results with incorrect units appear, to confirm that the validation function works correctly.
- View the workflow execution logs, confirm that the trigger timing is bound to project acceptance milestones, with no invalid automatic execution records.
