# Document and Material Drafting for Engineering Consulting Supervision: Citation Sources and Traceability

## What the Data for This Category Looks Like
Engineering consulting supervision document and material data primarily originates from on-site supervision ledgers, construction inspection submission materials, acceptance approval documents, engineering change negotiation records, and similar resources. Update frequency fluctuates with project progress. Supervision logs are updated daily, project weekly reports are generated each week, and monthly supervision summary reports are compiled each month. Each individual document includes structured fields such as project number, professional classification, timestamp, supervising engineer signature, rectification requirements, and acceptance results. Units include quantity units such as square meters and cubic meters, and time units such as day, week, and month. Some documents include responsible person fields linked to approval workflows.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
Engineering consulting supervision documents are managed independently per project. Documents from different projects have no universal cross-project links. Citation and traceability operations must be bound to project-level context, otherwise the system will retrieve irrelevant supervision data from other projects. Document update frequency shifts with project milestones. During retrieval, prioritize the latest supervision logs and acceptance records to avoid citing expired content. Documents contain specialized industry terminology and structured approval fields. Chunking and retrieval processes must preserve field associations, otherwise accurate traceability to specific approval links and responsible persons will not be achievable. Individual documents are lengthy. Total token count must be controlled during citation to avoid exceeding the context window limit.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 8 entries | Individual engineering consulting supervision documents are lengthy. Too many citations will exceed context limits. 8 entries can cover core supervision references |
| Similarity Threshold | 0.65–0.75, calibrated via actual testing | Supervision documents contain many specialized terms. A threshold that is too low will introduce irrelevant construction documents. A threshold that is too high will miss key supervision records |
| `quoteMaxToken` | 3000–4000 tokens | Individual supervision documents can reach thousands of characters. This range can fully retain citation content from a single core document |
| `responseData` | Enable metadata return | Supervision documents require traceability of fields such as supervising engineer and acceptance time. Metadata can be directly used to label sources |
| `detail` | Enable detailed traceability | Citations for engineering consulting supervision need clear labeling of document type and project number. Detailed mode can automatically extract metadata fields |

## Three Common Configuration Mistakes
- Phenomenon: Directly entering a knowledge base ID or citation variable results in consistent output. Applying the variable to the knowledge base triggers an interface error. Cause: Project-specific context filter parameters are not bound. The system cannot locate the exclusive document subset for the target supervision project, triggering a parameter verification failure.
- Phenomenon: Adjusting the similarity threshold or citation limit does not change the number of retrieved documents. Cause: Project metadata association for document chunking is not enabled. The system only retrieves from the full global knowledge base and does not filter data exclusive to the current supervision project.
- Phenomenon: Output includes raw Markdown syntax instead of rendered, readable formatting. Cause: Format optimization for the `detail` parameter is not enabled, or the prompt does not explicitly require converting citation content into a naturally readable labeling format.

## How to Verify Correct Configuration
- Submit a test supervision project number as a context variable, and confirm that retrieved documents only include supervision logs and acceptance records for that specific project.
- Adjust the `quoteMaxToken` parameter value, and confirm that the total length of citation fragments in the response changes in line with the parameter adjustment.
- After enabling the `responseData` parameter, check if the reply automatically includes metadata annotations such as document type, generation time, and linked project at the end.
- Input a test question containing industry-specific terminology, and confirm that the number of retrieved documents changes when the similarity threshold is adjusted.
