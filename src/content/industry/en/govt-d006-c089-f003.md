# Document and Material Drafting for Construction Machinery: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Internal enterprise design drawings, production process manuals, compliance inspection standards, equipment maintenance records, and project operation documents provide core data for construction machinery document and material drafting. The data update rhythm adjusts with project initiation, equipment iteration, or compliance standard revisions, with no fixed cycle. Single documents typically include fields such as equipment model, rated lifting capacity, working radius, and maintenance cycle. Units are mostly tons, meters, and hours. Document structure is layered by component, process, and compliance requirements.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Professional fields in construction machinery documents are numerous and their units are clearly defined. Prompts must explicitly specify parameter names and their corresponding units to avoid unit confusion in generated content. Multi-turn dialogue must continuously track the specific equipment model mentioned by the user to ensure context synchronization, otherwise parameter misalignment will occur. After long documents are split, component association relationships must be retained. Therefore, chunking and retrieval links must balance fragment integrity to avoid professional information breakage caused by splitting. References in compliance documents must clearly indicate sources, and prompts must require marking the referenced standard number or document chapter.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Construction machinery documents often contain continuous process or parameter descriptions; this length preserves complete information for a single component |
| Single Retrieval Count | Top 5 entries | Avoids excessive redundant content interfering with the large language model's extraction of professional parameters |
| Maximum Context Size | 12000 token | Adapts to equipment models and historical requirements mentioned multiple times during multi-turn dialogue |
| Reference Content Template | Calibrated based on actual testing | Must adapt to the field structure of construction machinery documents to ensure retrieved content can be correctly cited |
| `variables` Parameter Binding | Bind equipment model, job scene variables | Enables dynamic replacement of core parameters during multi-turn dialogue, avoiding repeated input |
| `chatId` Configuration | Bind session unique identifier | Ensures multi-turn dialogue context is synchronized across API calls |

## Three Common Mistakes
- Phenomenon: API calls return results that differ significantly from online conversations, and the `messages` field does not include historical conversation content. Cause: The `chatId` parameter was not correctly passed in the API request, causing context synchronization to fail.
- Phenomenon: Generated documents omit professional parameters such as the rated lifting capacity of equipment, and do not mark reference sources. Cause: The prompt did not explicitly require including construction machinery-specific fields and citing compliance documents.
- Phenomenon: Retrieved document fragments are unrelated to the current draft being created, with irrelevant general equipment descriptions appearing. Cause: Chunk length was set too short, causing component association information to be lost from split document fragments, leading to reduced retrieval accuracy.

## How to Verify Correct Configuration
- Initiate a draft request for a specific construction machinery model, and check if the returned result includes exclusive parameters such as the model's rated lifting capacity and working radius.
- Review the `messages` field in the API response to confirm it contains complete multi-turn dialogue context, and that the `variables` parameter has correctly bound preset equipment information.
- Compare the returned results from online conversations and API calls, and confirm that there are no significant differences in output when configurations are consistent.
- Verify that the reference content template can correctly extract compliance clauses from documents, and check if the generated document marks the corresponding document source.

The values provided are common starting points and should be measured against the reader's own samples.
