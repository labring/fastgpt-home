# Document and Material Drafting for Construction Machinery: Model Access and Configuration

## What Data for This Category Looks Like
Document data for construction machinery mainly comes from complete machine technical manuals, equipment maintenance ledgers, bidding requirement documents, construction logs, and contract templates. Update frequency differs across document types. Complete machine parameter documents receive synchronized updates every quarter. On-site maintenance records are uploaded in real time alongside construction milestones. Bidding documents are updated when a project starts. Most document structures include fields such as equipment model, rated load, working radius, maintenance cycle, and contract amount. Units include tons, meters, hours, ten thousand yuan, and similar units. Some long documents also include parts lists and parameter comparison tables.

## Constraints Imposed by These Characteristics on Model Access and Configuration
Professional parameter fields for construction machinery are numerous and use specialized units. Models must accurately match field semantics to avoid unit confusion. Long documents such as complete machine technical manuals and full contract templates consume large amounts of context tokens, which can easily trigger `maxContext` or `maxTokens` limits. Differences in structure across document types require configurations to adapt to different text splitting logic, ensuring key parameters are not lost during splitting. Real-time updated maintenance records and bidding documents require model access to support dynamic loading of the latest data. It is also necessary to limit the volume of documents processed in a single session to avoid timeouts.

## How to Set the Configurations

| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context requirements of long construction machinery documents, preventing loss of professional parameters during splitting |
| `maxTokens` | 4000–6000 token | Balances single-round generation length and response speed, meeting the drafting needs of documents such as contracts and maintenance reports |
| `quoteMaxToken` | 1500–2000 token | Limits the context proportion of knowledge base references, preventing overall token overlimit |
| `temperature` | 0.3–0.6 | Balances standardization and flexibility of documents, avoiding deviations in professional term generation |
| `toolChoice` | auto | Automatically matches tool call requirements, adapting to equipment parameter query scenarios during bidding document generation |
| `AIPROXY_API_TOKEN` | Fill in the key bound to the account | Completes identity verification for model access, ensuring request legitimacy |
| `AIPROXY_API_ENDPOINT` | Fill in the exclusive address provided by the platform | Ensures correct routing of model requests, avoiding connection failures |

## Three Common Configuration Mistakes
- Phenomenon: A context token overlimit prompt displays when generating construction machinery documents, or the interface returns a 413 status code. Cause: The `maxContext` parameter is not adjusted based on long document volume, causing input context to exceed the model limit.
- Phenomenon: Preset environment variable configurations cannot be read during the problem optimization phase. Cause: The environment variable key is not correctly bound in the model access configuration, resulting in restricted call permissions.
- Phenomenon: MCP tools cannot be called normally to complete equipment parameter queries, or knowledge base references cannot switch vector models. Cause: The binding relationship between model access, tools, and vector model configurations is confused, and cross-module parameters are incorrectly modified in a single link.

## How to Confirm the Configuration Is Complete
- Upload a complete construction machinery contract template document, trigger a document drafting task, and check whether the generated result accurately matches professional fields such as equipment model and rated load.
- Submit a test task containing multiple types of construction machinery documents, check for context-related errors, and adjust the value of the corresponding configuration item as needed.
- View the running logs of model access, confirm that the API endpoint and key configuration have taken effect normally, and there are no connection error prompts.
- Test the tool call and knowledge base reference functions, confirm that equipment parameter queries and document references can be completed normally, and adjust related configurations as needed.
