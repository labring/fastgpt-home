# Document and Material Drafting for Construction Machinery: Deployment and Upgrade

## What the data for this category looks like
Data sources include construction machinery factory technical documents, on-site operation and maintenance logs, regular maintenance reports, and bidding technical documents.
Update rhythm: Factory documents are updated statically. Operation and maintenance logs are updated daily per work shift. Maintenance reports are submitted in real time per work order. Bidding documents are updated per project cycle.
Document structure: Each single document includes structured fields such as equipment serial number, model, rated lifting capacity (unit: ton), operating hours (unit: hour), fault code, replacement parts list, and maintenance cycle (unit: day). Some long documents include scanned drawing attachments.

## What constraints these characteristics impose on deployment and upgrade
Construction machinery operation and maintenance logs have high data volume and frequent updates. Configure sufficient database connection pool and cache resources during deployment to avoid concurrent access timeouts.
Documents contain many structured fields and specific units. Configure adapted file reading and field extraction rules during deployment to ensure generated documents include accurate equipment parameters.
Most state-owned enterprise and public institution scenarios use intranet deployment. Configure adapted storage and database connection settings without public network access, and prohibit opening public network permissions.
Long documents and drawing attachments require sufficient storage capacity and chunk processing capabilities during deployment to avoid loading timeouts or content truncation.

## How to set configurations
This configuration guide applies to FastGPT v4.17.0. The specific configuration items are listed below:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30` | Adapts to the concurrent connection requirements of construction machinery operation and maintenance logs |
| `REDIS_URL` | `redis://intranet redis instance address:6379/0` | Meets cache and session storage requirements in intranet environments |
| `STORAGE_S3_ENDPOINT` | `intranet object storage service address` | Adapts to intranet deployment scenarios without public network access for state-owned enterprises and public institutions |
| Document chunk length | `800–1200 characters` | Matches the single-paragraph content length of construction machinery factory documents and maintenance reports |
| Single recall limit | `Top 8 entries` | Adapts to scenarios with many data fields and high accuracy requirements for construction machinery data |

## Three common errors
- Phenomenon: The frontend page cannot be accessed after Docker deployment, returning a 502 status code. Cause: `FE_DOMAIN` is not configured to an intranet-accessible address, causing the reverse proxy to point to the wrong service port.
- Phenomenon: Deployment logs show database connection refused, while the database process runs normally. Cause: The correct intranet database access address is not configured, or the `DB_MAX_LINK` value exceeds the database's maximum connection threshold.
- Phenomenon: Generated documents lack structured fields such as equipment rated lifting capacity and operating hours. Cause: The correct access permission for `FILE_TOKEN_KEY` is not configured, resulting in failure to read structured data fields from construction machinery documents.

## How to confirm the configuration is complete
- Access the configured `FE_DOMAIN` address, confirm the frontend page loads normally with no resource loading failure prompts.
- Run a database connection test, confirm the configured `DB_MAX_LINK` value does not exceed the maximum connection limit of the corresponding database.
- Upload a construction machinery maintenance report, trigger the document generation process, and check that the output includes preset fields such as equipment model and operating duration.
- View monitoring metrics for the instance specified in `REDIS_URL`, confirm the cache hit rate is within a reasonable range, and no large-scale cache breakdown occurs.

The values provided are common starting points and should be measured against the reader's own samples.
