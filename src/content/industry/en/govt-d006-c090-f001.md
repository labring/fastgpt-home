# Document and Material Drafting for Refined Oil Product Sales: HTTP Interfaces and External Systems

## What the data for this category looks like
Business data for refined oil product sales comes from gas station POS terminals, oil tank level monitoring systems, ERP inventory and procurement modules, and tax-controlled invoicing systems. Data update rhythms fall into three categories: real-time transaction data updates after each sale is completed, daily summary reports are generated after daily business closes, and monthly operating ledgers are updated at the start of each month with the previous month's data. Documents use a structured format, including fields such as unique gas station identifier, fuel grade (such as 92#, 95#), transaction time, transaction volume (unit: liters or tons), settlement unit price (yuan per liter), revenue amount, and inventory balance. All fields have uniform formats with no free text content. This adaptation supports FastGPT v4.17.0.

## What constraints these characteristics place on the HTTP Interfaces and External Systems workflow
Since the data includes both real-time transactions and scheduled summaries, the interface must support both short-connection real-time calls and scheduled batch pull modes. Since fields include industry-specific attributes such as fuel grade and transaction volume unit, the `variables` in interface requests must bind fixed identifier parameters for gas stations and fuel types, to ensure external systems match the correct business data. Since tax-related sales documents are involved, the interface must comply with the signature verification rules of tax-controlled systems, to prevent generated invoicing documents from failing tax verification. As data volume grows with the number of gas stations, the interface must support paginated return of structured data, to avoid timeouts caused by overload from single-transmission data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Use a Bearer token generated by the connected system, valid for 12 hours | Refined oil product sales integrations with external systems such as tax control and ERP require identity verification, and tokens must match the validity rules of the corresponding system |
| `variables` | Include gas station ID, fuel grade, and statistical cycle parameters | Document drafting requires binding business data for specific gas stations and fuel types, so parameters must clearly define the business scope |
| `responseData` | Return in structured paginated format, with no more than 1000 entries per page | Refined oil product transaction volume grows with business scale, pagination prevents interface timeouts and transmission overload |
| Interface timeout period | 60 seconds | Real-time transaction document drafting requires rapid response; excessively long timeouts will disrupt business processes |
| Data verification rules | Verify that transaction volume units and fuel grades comply with industry standards | Prevent submission of non-compliant fields and ensure accurate data for generated documents |
| Scheduled task trigger frequency | Once per day | Summary documents only require daily data updates; frequent pulls have no business value |

## Three Common Errors
- A 401 Unauthorized error is returned when calling the interface, making sales invoicing documents impossible to generate. Cause: The `Authorization` token for the connected tax control system has not been updated, or the token has exceeded its 12-hour validity period set by the system.
- The `responseData` field returned by the interface is empty, resulting in no transaction data in the generated document. Cause: No correct gas station ID or fuel grade is specified in `variables`, causing the external system to fail to match the corresponding business data.
- Interface calls time out, returning a 504 Gateway Timeout error. Cause: The volume of transaction data pulled in a single request exceeds the interface's carrying limit, and no pagination parameters were configured.

## How to Confirm Configuration is Complete
- Call the test interface with preset gas station ID and fuel grade, check if `responseData` returns the corresponding business fields.
- Verify that the `Authorization` token is within its validity period, and call the interface without returning a 401 error.
- Configure a scheduled pull task, check that it triggers at the set frequency and that the returned data volume meets business requirements.
- Generate a daily sales report document, cross-check that the transaction volume and revenue amount match the report data exported from the external system.
