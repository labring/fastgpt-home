# Document and Material Drafting for Refined Oil Sales: Multi-turn Dialogue and Prompt Engineering

## Constraints on multi-turn dialogue and prompt engineering
Daily updated sales transactions require that the data source called by multi-turn dialogue be limited to the last 24 hours, otherwise the model will generate documents using outdated data. Differences in field units (liters vs tons) can easily cause confusion, so prompts must clearly specify unit conversion rules and verification logic. Required compliance fields such as customer unified social credit code require confirmation one by one during multi-turn dialogue to avoid omissions that render documents invalid. Standardized contract templates require multi-turn dialogue outputs to strictly match preset formats, with no arbitrary adjustment of field order or omission of required items.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context window length | 8000–12000 characters | Refined oil sales documents include multiple sets of sales data and fields. Overly long contexts can cause the model to confuse field ownership |
| `messages` history filtering rule | Only retain dialogue history from the last 24 hours | Sales data updates daily, and data in old history becomes invalid |
| `variables` field verification switch | Enable required item verification | Documents include required fields such as customer unified social credit code and sales volume. All fields must be correctly filled |
| Single dialogue reply token limit | 2000–3000 tokens | The content length of a single sales document is moderate, to avoid exceeding model output limits |
| Context data refresh frequency | Sync sales ledgers every 12 hours | Sales data updates frequently. Delayed synchronization causes generated document data to be outdated |
| Connection timeout threshold | 60 seconds | Matches the typical response duration of sales ledger data interfaces, to avoid frequent connection errors |

## Three common configuration errors
- Symptom: Replies from multiple <ai dialogue> nodes in the workflow are all displayed in the final chat interface, and the output of specified nodes cannot be hidden. Cause: The node output hide switch is not enabled in workflow configuration, or `chatId` is not correctly bound to associate the specified dialogue context.
- Symptom: Unit confusion appears in generated sales documents, such as incorrectly converting liters to tons. Cause: The prompt does not clearly specify the conversion rules for oil product units, and unit verification fields are not bound in `variables`.
- Symptom: A connection error prompt appears during dialogue. Cause: Reasonable connection timeout parameters are not configured, or the sales ledger data synchronization interface response exceeds the set threshold.

## How to confirm correct configuration
- Trigger a complete multi-turn dialogue process, and check that only specified dialogue history content is displayed in the chat interface, with no excess output from <ai dialogue> nodes.
- Input test content including oil product grade, sales volume, and customer information, and check that all field units in the generated document match the input, with no confusion.
- View the workflow configuration interface, confirm that the `variables` field verification switch is enabled, and required fields are not set to skippable status.
- Simulate a slow data synchronization scenario, and check whether an expected timeout prompt is triggered when the interface response exceeds 60 seconds.

The values provided here are common starting points, and should be measured against the reader's own samples.
