# Document and Material Drafting for Refined Oil Sales: Workflow Orchestration

## What the data for this category looks like
Core data for refined oil sales comes from gas station POS transaction systems, oil product inventory and sales management platforms, and quality inspection qualification certificates. Data updates daily per business batch. Each document includes fields such as oil grade, total daily sales volume, single transaction unit price, customer type, and transaction time. Units include liters, yuan, tons, transaction counts, and others. Most documents are structured tables or formatted ledgers. Some offline scenarios require handwritten fuel vouchers to supplement unstructured content. This content is written for FastGPT v4.17.0.

## What constraints these characteristics impose on workflow orchestration
Refined oil sales data updates per business batch and uses diverse field units. Workflows must split execution steps by transaction node to avoid mixing cross-batch data. Coexistence of structured ledgers and unstructured vouchers requires workflows to include an OCR preprocessing node to extract standardized fields uniformly. Different oil grades correspond to distinct pricing and compliance requirements. A field verification link must be embedded in workflows to ensure correct matching of associated data. Sales documents must link to customer invoicing information, so workflows need cross-system data pull trigger conditions configured.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Variable configuration | Bind oil grade, sales volume, transaction time in `variables`, and configure REDIS_URL for caching retrieval results | Match core fields of refined oil sales, and improve retrieval efficiency via caching |
| Node trigger condition | Trigger per daily business batch | Align with data update rhythm to ensure workflows process the latest batch of sales data |
| Knowledge base association scope | Associate quality inspection reports and pricing documents from the past 30 days | Cover compliance and pricing references within the current sales cycle |
| Single data pull limit | Top 50 transaction records | Balance workflow execution efficiency and data integrity, avoid overloading from single batch loading |
| Failure retry count | 3 times, 60-second interval | Address data pull failures caused by temporary POS system fluctuations, reduce manual intervention |
| Context length | 800–1200 characters | Adapt to the conventional length of refined oil sales documents, ensure complete delivery of key information |

## Three common errors
- Phenomenon: Knowledge base references cannot be selected as output variables in code run nodes. Cause: Knowledge base association parameters are not configured in pre-workflow nodes, so the variable pool does not load retrieval results from the corresponding knowledge base.
- Phenomenon: Empty field errors occur during workflow execution, prompting that the oil grade does not match. Cause: Workflows are not triggered per business batch, leading to mixed cross-batch data, with some transactions missing corresponding oil grade fields.
- Phenomenon: Node trigger conditions cannot be configured when creating workflows via API. Cause: The `nodeId` parameter is not passed as required by the API documentation, so nodes cannot be correctly identified.

## How to confirm configurations are properly set
- Review the workflow variable configuration list to confirm that core business fields and system environment variables for refined oil sales have been bound.
- Trigger a test execution to check whether each node's output includes sales data and compliance documents for the corresponding batch.
- Simulate an abnormal scenario where the POS system is temporarily interrupted to verify whether the failure retry mechanism triggers as configured.
- Cross-check workflow trigger conditions and knowledge base association scope to confirm they match the current business cycle.
