# Document and Material Drafting for Refined Oil Sales: Deployment and Upgrade
This guide is compatible with FastGPT v4.17.0, and provides specific configuration references for the deployment and upgrade stages of document and material drafting scenarios in the refined oil sales industry.

## What the Data for This Category Looks Like
The data related to document and material drafting for refined oil sales primarily comes from internal retail management systems, ERP systems, and compliance management platforms. Data types include real-time sales ledgers, monthly operation reports, station inspection records, compliance document templates, and more. Document structures mostly include standardized fields: fuel grade (such as 92#, 95#), sales volume (unit: liters), unit price (unit: yuan per liter), revenue amount, station ID, inspection time, hidden danger level, and others. Data update rhythms fall into three categories: real-time (sales ledgers), daily (station daily reports), and monthly (operation reports). Compliance documents are updated via version iterations.

## What Constraints These Characteristics Impose During the Deployment and Upgrade Stage
Dispersed data sources and varying update rhythms require support for multi-source data synchronization configuration during deployment, and differentiated knowledge base refresh rules must be set for different update frequencies. Specialized fields (such as fuel grade, sales volume measured in liters) require retention of field identifiers during knowledge base chunking and retrieval, to avoid missing fields or formatting errors in generated documents. As the number of stations increases, business data volume will grow gradually. Sufficient storage and connection resources must be reserved during deployment, and upgrades must be compatible with legacy ledger formats to avoid broken historical data associations. Real-time sales data requirements mandate that the knowledge base supports incremental synchronization, to avoid performance losses caused by full updates.

## How to Set the Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://oiluser:oilpass@host:27017/oil_gpt?authSource=admin` | Stores metadata for sales ledgers and compliance documents, supports multi-station business data storage |
| `PG_URL` | `postgresql://pguser:pgpass@host:5432/oil_gpt` | Stores vector index association data after knowledge base chunking, supports complex field queries |
| `REDIS_URL` | `redis://redispass@host:6379/0` | Caches retrieval results for real-time sales data, reduces database load |
| `STORAGE_S3_ENDPOINT` | `http://s3.oilcompany.com:9000` | Stores large-volume documents such as bulk-uploaded oil product sales reports and inspection records |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent document generation requests across multiple stations, prevents connection exhaustion |
| `FE_DOMAIN` | `https://oil-doc.oilcompany.com` | Binds a dedicated business domain name, ensures generated document links are accessible normally |

## Three Common Mistakes
- Symptom: Unable to create multiple accounts via the in-container interface, with an insufficient permissions prompt. Cause: The `ROOT_KEY` parameter is not configured correctly, and the administrator account's permission management function is not enabled.
- Symptom: After a document generation request is initiated, the service times out with no response. Cause: The `DB_MAX_LINK` parameter is not adjusted to a reasonable range, causing the database connection pool to be exhausted by concurrent requests.
- Symptom: Uploaded refined oil sales reports cannot be parsed correctly, and the generated documents lack the fuel grade field. Cause: The chunking rule for the corresponding document is not configured in the knowledge base, and the identifier information for specialized fields is not retained.

## How to Confirm the Configuration Is Complete
- Access the dedicated domain bound to `FE_DOMAIN`, confirm that the front-end interface loads normally with no resource loading failure prompts.
- Run a database connection test script to verify that the connection status of `MONGODB_URI`, `PG_URL`, and `REDIS_URL` is normal.
- Upload a refined oil sales report document, confirm that the file can be uploaded normally and a corresponding knowledge base entry is generated.
- Initiate a simple document generation request, confirm that the generated result contains correct oil product sales field information.
