# Document and Material Drafting for General Contracting of Residential Construction Projects: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Document data for general contracting of residential construction projects comes from full-cycle project ledgers, bidding documents, construction logs, change visas, completion acceptance materials, and similar sources.
Update timing follows project milestones. Update documents for the bidding preparation phase, mid-construction phase, and pre-completion phase respectively.
Document structures include bidding documents, construction organization designs, change visa forms, project settlement reports, and similar items.
Fields include project ID, building area, project cost, planned duration, main material consumption, and similar items.
Common units are square meters, ten thousand yuan, calendar days, tons, and similar standard units.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Project-specific fields are numerous and require precise matching.
Multi-turn dialogue must bind project parameters fixedly. This avoids re-entering basic information for each query.
Individual documents are lengthy. Overly long context interferes with generation accuracy. Limit the scope of dialogue context.
Document formats are fixed across different phases. Multi-turn dialogue must switch prompt templates by phase. This ensures generated content meets the requirements of the corresponding stage.
Fields must strictly match units and formats. Multi-turn dialogue must track confirmed parameters. This avoids unit errors or format deviations in generated content that harm document compliance.

## Three common mistakes
- Repeatedly request input of confirmed project parameters during multi-turn dialogue. Cause: Fixed project fields are not bound via `variables`, so basic information must be re-entered for each dialogue.
- Unable to pass the generated document draft as context to the next round of revision dialogue. Cause: The generated draft content is not appended as a new context entry in `messages`.
- Return an error where fields are not replaced during invocation. Cause: Prompt placeholders are not correctly bound to project ledger fields, resulting in variables not being properly populated.

## How to confirm the configuration is complete
- Import the ledger data of the corresponding project, and check whether the fields in `variables` are correctly mapped to the pending verification positions in the prompt.
- Initiate 3 consecutive rounds of project-related dialogue, and verify that the retained context only contains content from the current project with no irrelevant historical entries.
- Simulate the document drafting process, trigger the timeout judgment, and confirm that the dialogue completes the response within the preset duration.
- Input project-specific parameters to generate the corresponding document, and check whether the fields are automatically replaced with actual project data.
