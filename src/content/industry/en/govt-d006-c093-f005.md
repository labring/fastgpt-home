# Document and Material Drafting for Government and Enterprise IT Services: Tool Calling and Plugins

## What the data for this category looks like
The document and material data for government and enterprise IT services mainly comes from internal operation and maintenance ticket systems, communication node logs, compliance management documents, and project declaration materials. Data update rhythm varies with business scenarios: daily operation and maintenance documents are updated daily. Special compliance documents are updated quarterly or at project milestones.

The document structure includes ticket number, operation and maintenance node identifier, fault description, processing flow, and compliance basis fields. Field units include string numbers, minutes, character counts, etc. The length of individual documents varies widely.

## What constraints these characteristics impose on the tool calling and plugins link
Data for government and enterprise IT services is scattered across multiple internal heterogeneous systems. Tool calling requires connecting to multiple independent APIs. Dedicated authentication parameters must be configured for different systems.

The data update rhythm differs significantly. Real-time operation and maintenance tickets require frequent tool calls. Tools for special compliance documents need their calling frequency adjusted according to business cycles.

Field units and structures are diverse. Tool input parameters must strictly match specific field formats such as ticket numbers and operation and maintenance nodes. Calls will fail otherwise.

In scenarios with a mix of long documents and structured data, the content length returned by tools must be limited. This avoids exceeding the context window.

## How to set configurations
This chapter’s configurations are adapted for FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Auto mode | Allows the model to independently determine whether to call tools, adapting to tool calling requirements across different document drafting scenarios |
| Tool call timeout | 30 seconds | Matches the typical response duration of internal government and enterprise system interfaces, preventing process interruptions due to excessive waiting time |
| Single tool return entry count | Top 3 entries | Adapts to the single-batch processing scale of tickets and documents associated with government and enterprise documents, reducing interference from redundant data |
| Tool return content length limit | Calibrated to 8000–12000 tokens based on actual testing | Adapts to the processing requirements of long government and enterprise documents, avoiding exceeding the context window |
| `functionCall` input parameter validation | Enforce matching of business fields | Ensures that input parameters for tool calls align with the format of government and enterprise document fields such as ticket numbers and operation and maintenance nodes |
| Intranet access configuration | Enable private network proxy | Adapts to access restrictions on internal government and enterprise resources, resolving resource calling issues in private networks |

## Three common mistakes
- Symptom: Calling a DingTalk webhook plugin returns empty results, or fails to push drafted material content. Cause: The authentication key for the DingTalk bot has not been configured, or the message format in the input parameters does not match the requirements of the DingTalk API.
- Symptom: Calling a multimodal visual large model returns a download failure error with a status code of 403 or connection timeout. Cause: The intranet access proxy has not been enabled, making it impossible to access operation and maintenance screenshot resources stored in internal government and enterprise storage.
- Symptom: Drafted materials generated after tool calls lack associated ticket numbers. Cause: `functionCall` input parameter validation has not been enabled, and the model failed to correctly bind specific business fields for government and enterprise documents.

## How to confirm configurations are correct
- Trigger a document drafting process, and check whether the tool calling log displays the API address and input parameter fields that match business requirements.
- Test calling the DingTalk webhook plugin, and verify whether the target recipient receives the test-pushed document-related content.
- Upload internal government and enterprise operation and maintenance screenshots, and verify whether the tool calling process can normally obtain and process the image resources.
- Switch the `toolChoice` configuration item, and confirm that the model’s tool calling behavior matches the expected automatic or manual mode.
