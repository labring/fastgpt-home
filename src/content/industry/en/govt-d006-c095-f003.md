# Document and Material Drafting for New Energy Development: Multi-turn Dialogue and Prompt Engineering

## Data Sources and Structure for This Category
Document and material data for new energy development primarily comes from official end-to-end documents for central and local state-owned enterprise new energy projects. These include project approval applications, environmental impact assessment reports, grid connection access plans, construction organization designs, and completion acceptance reports.
Update frequency adjusts based on project progression phases. Approval documents are updated during the project approval phase. Construction logs and progress reports are updated during the construction phase.
Document structures include standardized project identification fields, technical parameter fields, and approval process fields. Fields include project number, construction entity, installed capacity, land area, total investment, and other relevant items. Most units use industry standard metrics such as megawatts, hectares, and ten thousand yuan.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Fixed project fields and approval processes require multi-turn dialogue prompts to clearly specify the scope of required fields. This prevents generation of content that fails to meet approval requirements.
Phased data updates require multi-turn dialogue to bind the current project via `chatId`. This ensures context only links to historical records from the corresponding project cycle, and no information from other projects is included.
Industry standard units require prompts to enforce that generated content uses legal units. This prevents unit errors in technical parameters.
Long documents require multi-turn dialogue context windows to accommodate the length of new energy development documents. This avoids truncation of critical approval information.

## Configuration Guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | New energy development documents have a relatively long average single-document length, requiring coverage of complete context related to project approval and construction |
| Context retention rule | Only retain `messages` associated with the current `chatId` | Avoid cross-project context interference, ensuring dialogue only links to the current new energy project |
| Variable substitution settings | Enable `variables` to bind system variables | Support automatic insertion of standardized fields such as project number and current date, reducing manual input errors |
| `chatId` binding rule | Bind the project's unique identifier | Ensure multi-turn dialogue context only loads historical records for the current project, preventing disorganized historical content |
| Prompt field validation | Enable required field validation | Force generated documents to include mandatory approval and technical fields required for new energy projects |

## Three Common Configuration Errors
- Phenomenon: Auto-reply content is empty when opening a conversation for the second time. Cause: The `chatId` for the corresponding project is not bound, causing the system to fail to load historical `messages` context.
- Phenomenon: The signature date inserted in the prompt does not match the current system date. Cause: The platform time variable in `variables` is not correctly bound, or the variable substitution order is configured incorrectly.
- Phenomenon: Content from a previous AI dialogue in a workflow is included in the final output. Cause: The second AI dialogue component is not configured to only receive specified input parameters, causing context from the previous dialogue to be mixed in.

## How to Verify Correct Configuration
- Initiate a test dialogue, enter basic parameters for a new energy project, and check if the generated document includes all preset required fields.
- Close the dialogue page and re-enter it, check if historical `messages` are fully loaded and no reply content is missing.
- Insert the platform time variable into the prompt, verify that the signature date in the generated content matches the current system date.
- Configure a dual AI dialogue workflow, check that the final output only includes the generated results from the second dialogue, with no content from the previous round mixed in.
