# Document and Material Drafting for New Energy Development: Workflow Orchestration

## What the data for this category looks like
New energy development document and material data mainly comes from approval documents, technical reports, and internal management documents across the full project lifecycle. Sources include approval documents from natural resources and energy authorities, as well as self-prepared materials such as project feasibility study reports, environmental impact assessments, and grid connection applications. Data update frequency follows project phases: update basic project parameters during the project initiation phase, synchronize progress supporting materials during the construction phase, and supplement acceptance documents during the grid connection phase. Most documents use a multi-chapter nested format, including standardized fields such as project number, installed capacity (unit: MW), land scope (unit: hectare), and approval node status. Some materials contain fixed-format seals and document number information.

## What constraints these characteristics impose on workflow orchestration
Dispersed sources and large format differences of new energy development document data mean that workflow orchestration needs to configure multiple data source access nodes to connect with government platform approval documents and project self-prepared documents respectively. Standardized fields have dedicated units, requiring the addition of parameter verification nodes in the workflow to perform unit matching and format verification for fields such as installed capacity and land scope. Data updates driven by project phases require workflow trigger conditions to be bound to project node status, avoiding fixed timed triggers and reducing invalid executions. The long document nested structure requires workflow configuration nodes to support content splitting by chapter, preventing single nodes from processing excessive text.

## Configuration Specifications
The following configurations are based on the workflow orchestration features of FastGPT v4.17.0, as detailed below:
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapt to the average length of a single chapter of new energy project documents to avoid overloading a single chunk |
| Trigger Condition | Trigger based on project node status changes | Match the data update rhythm driven by project phases to reduce invalid runs |
| `variables` | Include project number, installed capacity fields | Cover the verification and call requirements of standardized fields, adapt to fixed parameters of new energy projects |
| Node Timeout Duration | 600 seconds | Adapt to the time requirements of long document processing and cross-department data source pulling |
| `nodeId` | Assign unique identifiers based on data source type | Differentiate processing nodes for government approval documents and self-prepared documents to avoid call conflicts |
| Field Validation Rules | Match units such as MW and hectare | Correspond to the standardized field unit requirements of new energy documents to ensure data format compliance |

## Three Common Misconfigurations
- Clicking the code run node input box after referencing a custom plugin in the workflow triggers an error. The cause is that the plugin-bound `variables` do not cover the standardized parameters of new energy projects, so preset fields cannot be read during node calls.
- Opening the workflow editing page in a local deployment environment triggers a "Cannot read properties of undefined (reading 'incl')" error. The cause is that the workflow's `nodeId` has duplicate configurations or has not completed initialization, causing the page to fail to recognize node identifiers during rendering.
- The workflow-generated grid connection application material omits the unit information for installed capacity. The cause is that no field validation rules are configured, and no unit binding is applied to the standardized fields of new energy projects, leading to non-compliant output formats.

## How to Verify Correct Configuration
- Trigger the workflow once, check each data source node for successful pulling of the corresponding type of new energy project documents, and confirm that the trigger condition binds to the project node status and takes effect.
- View the workflow's parameter verification node, confirm that unit rules matching new energy document fields have been configured, and verify whether the validation logic triggers by importing a test document.
- Check the binding parameters of the custom plugin, confirm that `variables` includes new energy project-specific fields such as project number and installed capacity to avoid field missing during calls.
- View the workflow's node identifier list, confirm that all `nodeId` values are unique and have completed initialization, to avoid page rendering or node call errors.
