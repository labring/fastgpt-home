# Document and Material Drafting for New Energy Development: Model Integration and Configuration

## What the data for this category looks like
Documents and materials for new energy development originate from full-process approval documents, technical plans, and on-site survey records for projects. Update rhythms are adjusted based on project advancement stages:
- Project application materials are updated during the project initiation phase
- Environmental impact assessment reports are updated during the EIA phase
- Grid connection acceptance documents are updated during the grid connection phase

Most documents follow a fixed structure: project overview, technical parameters, approval process, and attachment list. Common fields include installed capacity (unit: MW), grid connection voltage (unit: kV), floor area (unit: hectare), approval document number, and project number. Some documents include jpg-format project drawings or scanned approval documents.

## Constraints imposed on model integration and configuration
Fixed fields and professional terminology in new energy development documents require model output to accurately match preset formats and domain knowledge. This prevents generation of content that does not comply with approval specifications.
Jpg-format attachments included in documents require the model to have visual input capabilities to parse parameters and information from images.
Single documents often contain multiple pages, so context length must be controlled to avoid exceeding model thresholds.
Document update frequencies vary by project stage, so interface call stability must be ensured to support real-time data requirements.

## How to configure the settings
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | A single new energy development document often exceeds 5000 characters, so sufficient context must be retained to match project historical data and approval requirements |
| `maxTokens` | 2000–3000 token | Document drafting requires generating complete paragraphs or structured tables, to avoid truncated output content |
| `vision` | Enabled | New energy documents are often attached with project drawings and scanned approval documents, so image content parsing and information extraction must be supported |
| `temperature` | 0.3–0.5 | Documents must comply with official standard formats, so generation randomness should be reduced to ensure consistency of output content |
| `AIPROXY_API_ENDPOINT` | Fill in the exclusive address provided by the service provider | Adapt the interface call paths of different large models to ensure correct request forwarding |
| `AIPROXY_API_TOKEN` | Fill in the exclusive key allocated by the platform | Complete interface identity verification to ensure valid call permissions |

## Three common configuration mistakes
- Symptom: Uploaded jpg project drawings cannot be parsed by the AI module, and the interface displays "Unable to read attachment content". Cause: The `vision` configuration item is not enabled, so the model lacks visual input capabilities and cannot process image-format document attachments.
- Symptom: When using Qwen2-72B-Instruct-Int8, function call output does not meet expectations, and large amounts of irrelevant content are generated. Cause: The `temperature` value is set too high, and `toolChoice` is not set to forced function call mode, so the model does not follow preset call rules.
- Symptom: A 401 permission error is returned when connecting to a third-party large model in the commercial version. Cause: `AIPROXY_API_TOKEN` is not filled in correctly, or a key that does not match `AIPROXY_API_ENDPOINT` is used, resulting in identity verification failure.

## How to verify successful configuration
- Upload a jpg drawing of a new energy project, trigger the AI module to send a content extraction request, and confirm whether parameters such as installed capacity and grid connection voltage can be accurately extracted from the drawing.
- Set `toolChoice` to forced mode, send a document drafting request that includes structured function call requirements, and confirm whether the model generates output that complies with the preset format.
- View the interface call logs for FastGPT v4.17.0, confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` request parameters are correctly included, and that no 401 or 404 errors are present.
- Adjust `temperature` to the 0.3–0.5 range, send the same document drafting request multiple times, and confirm that the consistency of the output content meets expectations.
