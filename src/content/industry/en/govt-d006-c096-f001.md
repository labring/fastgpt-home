# Document and Material Drafting for Non-Ferrous Metal Smelting: HTTP Interfaces and External Systems

## What the data for this category looks like
Document and material data for non-ferrous metal smelting primarily comes from internal MES production systems, online quality inspection equipment, and ERP contract management systems. Production ledger documents are updated per shift. Quality inspection reports are generated synchronously when each furnace batch completes production. Compliance documents are updated quarterly. Most documents use semi-structured formats, with fields including document number, generation time, furnace batch ID, metal output, impurity limits, process energy consumption, and more. Output is measured in tons. Energy consumption is measured in kilowatt-hours. Field formats are standardized to support bulk import and interface calls.

## What constraints these characteristics impose on HTTP interfaces and external systems
Non-ferrous metal smelting document data is updated in batches by furnace batch, shift, and quarter. Fields include fixed units. This creates multiple constraints for HTTP interface and external system integration.
First, interfaces must precisely match request parameters using furnace batch ID or document number to prevent document misalignment during bulk calls.
Second, request bodies must strictly match preset field names and unit formats, or downstream systems will fail to parse the data.
Third, individual documents have widely varying character lengths. Interfaces must support dynamic adjustment of returned data truncation ranges to avoid single request timeouts.
Finally, some documents include quality inspection scan attachments. Interfaces must support both binary stream and base64 encoded upload formats.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Authentication Method | Use Bearer token authentication, token validity period is 7 days | Aligns with the security specifications of internal non-ferrous metal smelting systems |
| Request Variable Configuration | Include 5–10 core fields such as furnace batch ID, output, energy consumption indicators | Adapts to the structured data characteristics of smelting documents |
| Return Data Truncation | Truncate the first 800–1200 characters as input material | Balances document information completeness and interface call efficiency |
| Call Frequency Configuration | Trigger calls per furnace batch, no more than 1000 calls per day | Avoids exceeding interface call limits of internal systems |
| Attachment Upload Configuration | Support base64 encoding format, single file no larger than 1000 MB | Adapts to the size of quality inspection scan attachments included with smelting documents |

These configuration instructions are compatible with FastGPT v4.17.0.

## Three common configuration errors
- Phenomenon: Interface calls return 401 unauthorized errors, or fail to read document data from external systems. Cause: The `Authorization` parameter is not configured correctly, and invalid or expired identity credentials are used.
- Phenomenon: Incomplete document content is returned after interface calls, or core fields parse as empty. Cause: Unique furnace batch ID or unit fields for smelting documents are not included in `variables`, causing downstream systems to fail to match corresponding data.
- Phenomenon: Returned document fragments are too long or too short, not matching drafting requirements. Cause: The truncation range for `responseData` is not set appropriately, and does not match the character length characteristics of smelting documents.

## How to confirm the configuration is correct
- Initiate a test call, and verify that returned document content includes preset core fields for smelting documents, with formats matching internal systems.
- Initiate a call using expired identity credentials, confirm that an unauthorized error is returned, then replace with valid credentials and verify the call succeeds.
- Simulate an interface request for a single batch of documents, check that the external system can normally receive and parse all request parameters.
- Adjust the trigger timing of interface calls, confirm that internal system rate limit intercepts are not triggered.

The values provided are common starting points, and should be evaluated against the reader's own samples.
