# Document and Material Drafting for Non-Ferrous Metal Smelting: Vector Models and Indexes

## What the Data for This Category Looks Like
Documents and materials for non-ferrous metal smelting are primarily sourced from production process specifications, quality inspection reports, energy consumption ledgers, safety compliance documents, and technical summaries generated during production. Data is updated per production shift or daily. Some monthly summary documents can reach several thousand characters in length.
Documents include structured fields such as furnace number, metal grade, and energy consumption values, paired with unstructured process descriptions and explanatory text. Common units include tons, grams per ton, degrees Celsius, and pascals. A large number of industrial technical terms and fixed-format report content are also present.

## What Constraints Do These Characteristics Impose on Vector Models and Indexes
High-frequency updated production ledgers and quality inspection data require indexes to support incremental synchronization, to avoid resource consumption caused by full reconstruction.
Mixed structured and unstructured document types require balancing field integrity and semantic coherence during chunking, to prevent splitting of technical terms or process steps.
The presence of industrial-specific technical terms requires vector models to adapt to the semantic features of industrial corpora, otherwise retrieval matching deviations will occur.
The high proportion of long documents also imposes clear requirements on the context window used for vector concatenation.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the typical paragraph length of smelting documents, avoids splitting technical terms across chunks |
| Overlap Length | 50–100 characters | Retains contextual association between chunks, prevents breaks in process steps or parameter descriptions |
| Similarity Threshold | 0.72–0.80 | Matches the semantic similarity range for smelting technical terms, calibrated via actual testing |
| Single Search Limit | Top 8 entries | Balances retrieval accuracy and response speed, fits the retrieval scenario for industrial documents |
| Maximum Context | Set `maxToken` to 8000 | Adapts to recall content concatenation for long documents, avoids exceeding model window limits |
| Reranking | Enabled | Filters low-relevance parameter entries, improves the targeting of retrieval results |

## Three Common Configuration Mistakes
- Issue: Retrieval response timeout occurs when creating a QA split collection via the knowledge base API. Cause: No reasonable chunk length and overlap parameters configured, resulting in an excessive number of chunks, causing index loading and retrieval time to exceed thresholds.
- Issue: The interface shows the embedding model has been changed to embedding-3, and the original index using ada-002 cannot match new retrieval requests. Cause: The embedding model version was not locked, resulting in inconsistent vector spaces between the new and old indexes, leading to retrieval result deviations.
- Issue: Irrelevant administrative document entries are mixed into retrieval results. Cause: The similarity threshold was set too low, including non-target documents with insufficient semantic relevance in the recall range.

## How to Verify Correct Configuration
- Check the index creation logs in FastGPT v4.17.0 to confirm the number of chunks matches expectations, with no abnormal errors or truncation prompts.
- Retrieve industrial technical terms such as "matte grade control range", and verify the relevance and number of returned results.
- Compare retrieval results from different embedding models, confirm that the currently used model version and configuration parameters are consistent.
- Simulate batch retrieval requests to verify that response speed meets the time requirements of the business scenario.
