# Document and Material Drafting for Non-Ferrous Metal Smelting: Tool Calling and Plugins

## What the data for this category looks like
Production data for non-ferrous metal smelting mainly comes from production ledgers, quality inspection reports, raw material purchase and storage slips, and smelting process parameter records. Data is updated per production batch, with a single update cycle per shift or per day. A single batch document includes fields such as furnace number, raw material type, feeding amount, furnace temperature, output metal amount, and energy consumption value. Most field units are tons, cubic meters, kilowatt-hours, and standard coal equivalents. Each batch is uniquely identified only by its batch ID, and there is no unified multi-version archiving logic.

## What constraints these characteristics impose on the tool calling and plugins workflow
Because data is updated per batch and linked to a unique furnace number, tool calling must bind the batch ID as a retrieval condition to avoid pulling expired or cross-batch data. Because fields include professional production parameters, plugins must preset fixed field mapping rules to prevent the AI from generating incorrect field names or units. Because single-batch data has a large volume, the tool calling context must adapt to full parameter display to avoid truncating key process information. Because data is stored in a structured format, plugins must support joined table queries to associate raw material, quality inspection, and production data for document drafting.

| Result cache duration | 4 hours | Balances data freshness and query efficiency, adapting to production ledger data updated daily |

## Three Common Mistakes
- Phenomenon: The return content of the first tool call in a Workflow is printed to logs, and the next-level branch executes. Cause: The intermediate result output switch for tool calling is not disabled, and the branch trigger condition only depends on tool returns without additional configuration.
- Phenomenon: Tool calling fails to trigger when calling the Qwen2.5 model, and logs prompt function format mismatch. Cause: The `functionCall` configuration item is not enabled, or the parameter transfer format does not align with model requirements.
- Phenomenon: Chinese characters in MySQL plugin query results display as garbled text. Cause: The character set is not specified as utf8mb4 in the database connection configuration, or the plugin does not use this character set to parse returned data.

## How to Confirm Configurations Are Correct
- Initiate a test query with a specified smelting batch ID, verify that tool calling only returns production data for the corresponding batch, with no irrelevant batch information.
- View tool calling logs, confirm that only the final generated document content is output, with no redundant parameter displays from intermediate tool returns.
- Switch to the Qwen2.5 model to initiate a test, confirm that tool calling triggers normally, and parameter transfer has no format errors.
- Execute a MySQL query containing Chinese fields, confirm that Chinese fields display normally with no garbled text issues.
