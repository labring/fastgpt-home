# Document and Material Drafting for Non-Ferrous Metal Smelting: Deployment and Upgrade

This document is compatible with FastGPT v4.17.0, and provides targeted configuration guidance for the deployment and upgrade phase of document and material drafting for non-ferrous metal smelting.

## What the data for this category looks like

Data sources involved in document and material drafting for non-ferrous metal smelting include production shift reports, grade test reports issued by quality inspection centers, process procedure manuals, and procurement and sales contract documents. Data updates are completed per production shift or daily. Single document length varies widely, from shift logs of hundreds of characters to process optimization plans of thousands of characters. Documents include fixed fields such as furnace body number, metal grade, smelting duration, and unit energy consumption. Common field units are tons, %, hours, and kilowatt-hours.

## What constraints these characteristics impose during deployment and upgrade

Scattered data sources covering production, quality inspection, business and other document types require configuration of cross-source data access storage connection parameters during deployment. The wide range of document lengths, from short logs to long plan documents, requires vector database parameters adapted to different text processing length requirements. Data updates per shift or daily require retaining incremental synchronization configuration entries during upgrade, to avoid excessive system resource usage from full re-import. Clear requirements for fixed fields and units require presetting field mapping rules during knowledge base construction, to ensure accurate field matching during subsequent retrieval.

| `ROOT_KEY` | Randomly generated 32-character string | Configures the highest access permission for the knowledge base, ensuring access to smelting confidential documents is controllable |

## Three common mistakes

- Phenomenon: After starting the Docker container, the access interface prompts model connection failure, and checking the logs shows curl connection timeout. Cause: Ollama and FastGPT containers were not started in order, and the Ollama service was not initialized before FastGPT started.
- Phenomenon: Empty results are returned when retrieving smelting documents, or field matching errors occur. Cause: Corresponding field mapping rules were not configured, causing the knowledge base to fail to recognize dedicated fields such as furnace number and grade.
- Phenomenon: The aiproxy container continuously reports errors and exits after docker-compose startup. Cause: The `STORAGE_S3_ENDPOINT` parameter was not configured correctly, causing large-volume documents to fail to be stored normally, triggering storage verification failure.

## How to confirm the configuration is complete

- Run the docker ps command to confirm that all FastGPT-related containers and dependent containers are in running state.
- Enter the FastGPT knowledge base management interface, upload a smelting shift report, and confirm that the document can be parsed normally and an index is generated.
- Configure a model test interface, enter a test question containing furnace number and grade fields, and confirm that matching document fragments can be returned.
- Check the background logs to confirm that there are no error messages for database connections or cache service connections.

The values given are common starting points and should be measured against the reader's own samples.
