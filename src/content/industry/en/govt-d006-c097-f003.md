# Document and Material Drafting for Nuclear Power Operations: Multi-turn Dialogue and Prompt Engineering

## Data Characteristics for This Category
Nuclear power operation document and material data comes primarily from internal standardized procedures, shift handover records, incident report templates, and safety review documents. Updates occur quarterly alongside procedure revisions, or annually during safety compliance reviews. Document structures include fixed fields: document number, executing position, operation steps, safety limits, and version number. Units follow nuclear power professional metrology standards, including microsieverts (μSv), hours, and minutes. Individual document length ranges from 3000 to 8000 characters.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The fixed fields and specialized unit requirements for nuclear power operation documents require multi-turn dialogue to retain safety limit and position information from prior interactions. This prevents generated content from deviating from compliance rules. The quarterly update cycle for documents means prompts must specify calling the latest internal procedure version. This avoids use of expired clauses. Longer individual documents require multi-turn dialogue contexts to filter core content accurately. Redundant information can interfere with generation logic. Specialized professional terminology requires prompts to optimize question keywords. This matches the specialized expressions used in internal procedures.

| `chatId` | Bind on-duty team ID | Distinguish operation document contexts across different shifts. Avoid parameter confusion across shifts |

## Three Common Mistakes
- Phenomenon: When calling the streaming output interface of the dialogue API, embedded procedure links only overwrite the current page when clicked, and cannot jump to a new page. Cause: No new window jump rule is configured in the streaming output callback logic. Links use the current page context for rendering by default.
- Phenomenon: When viewing dialogue log details, the returned content of all rounds is exactly the same as the latest answer, and is not affected by the number of multi-turn interactions. Cause: The `chatId` parameter is not correctly bound. Each request reuses a fixed session context without updating historical interaction records.
- Phenomenon: Multi-turn dialogue-generated shift handover records or operation tickets include parameters that do not comply with nuclear power safety limits. Cause: Preset safety variables are not embedded in the prompt. Generated content does not match mandatory requirements from internal procedures.

## How to Verify Proper Configuration
- Initiate a test dialogue, input the document drafting requirement for the corresponding position, and check whether the returned content includes the preset safety variables and bound team ID.
- Initiate 3 consecutive rounds of interaction, check whether the `messages` field in the dialogue log fully retains key information from prior interactions with no content loss.
- Call the streaming output interface, click the links in the returned content, and confirm the jump behavior matches expectations.
- Initiate two test requests from different sessions, confirm that each log detail only corresponds to its own interaction content, with no cross-session content confusion.
