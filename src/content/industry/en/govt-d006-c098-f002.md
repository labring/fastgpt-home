# Document and Material Drafting for Civil Aviation Airports: Vector Models and Indexing

## What the Data for This Category Looks Like
Civil aviation airport document data comes from official documents across scenarios including flight support scheduling, security operation and maintenance management, passenger service specifications, and terminal building operations. These documents include flight delay notices, security procedure manuals, passenger service guides, and airport emergency response plans.

Three update cadences apply: daily updated flight dynamic documents, quarterly revised operation and maintenance specification documents, and temporarily generated notice documents for emergencies.

Document structures fall into two categories: standardized notices with document numbers, dates, and intended audiences, and chaptered, clause-numbered manual content. Exclusive fields include airport three-letter code, flight number, terminal number, and support time windows, among others. Units include minutes, flights, and square meters, among others.

## What Constraints Do These Characteristics Impose on the Vector Model and Indexing Process
Data sources cover multiple scenarios with significant format differences. Unified format standardization must be completed first to avoid damaging the integrity of exclusive fields during chunking.

Daily updated flight dynamic documents require support for incremental indexing. This reduces resource consumption from full reindexing.

Long-paragraph operation and maintenance manual documents require reasonable control of chunk length. This ensures complete semantic units.

Exclusive fields such as airport three-letter code and flight number must be included as metadata in the index. This improves the efficiency of accurate recall.

Additionally, large differences in document lengths across types require adaptation of different chunking strategies. This ensures vectorization quality.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Civil aviation airport documents are mostly long-paragraph professional specification documents; this length preserves complete semantic units and avoids overly fragmented chunking |
| Overlap Length | 100–150 characters | Prevents loss of semantic information across chunks, adapts to the coherent expression logic of long documents |
| Similarity Threshold | 0.65–0.75 | Civil aviation documents are dense with professional terminology; this range filters irrelevant recalls while retaining accurate matching results |
| Single Search Limit | Top 8 entries | Retrieval demands for airport documents mostly focus on accurate matching of specific processes or clauses; too many results increase the burden of context processing |
| `maxToken` | 8000 token | Adapts to the context window requirements of FastGPT v4.17.0, set in combination with the document length of a single batch of recalls |
| `defaultToken` | 200 token | Controls the vector storage overhead of a single chunk, adapts to the performance requirements of incremental indexing |

## Three Common Misconfigurations
- After importing an airport operation and maintenance document dataset, the knowledge base status continuously displays "indexing". The cause is that no incremental indexing strategy was configured for daily updated flight data. The full indexing process cannot complete vectorization processing for large-scale documents in a timely manner.
- The semantic similarity score returned by the vector model call falls outside the 0–1 range. The cause is that non-standard similarity calculation parameters were used, and the threshold range was not locked to 0–1.
- Retrieval results only return a small number of entries and fail to cover the required airport process clauses. The cause is that the single search limit is set too low, not adapting to the retrieval scenario where multiple clauses are associated in civil aviation documents.

## How to Confirm Proper Configuration
- View the FastGPT v4.17.0 vector model call logs to confirm that the returned similarity scores fall within the 0–1 range.
- Manually import a test airport security specification document to verify that the index completion time matches the expected configuration.
- Retrieve keywords for a specific flight support process to confirm that the similarity scores of the recalled results fall within the set threshold range.
- Check the metadata configuration items to confirm that exclusive fields such as airport three-letter code and flight number have been included in the indexing rules.
