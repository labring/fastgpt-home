# Document and Material Drafting for Civil Aviation Airports: Tool Calling and Plugins

## What the data for this category looks like
Data for civil aviation airport document and material drafting mainly comes from internal business systems including airport collaborative decision systems, flight operation management, ground service scheduling, and security control. Data update frequency changes with business scenarios. Flight plan data is released 7 to 30 days in advance, with real-time synchronization of dynamic updates such as flight delays and cancellations. Daily operation records are updated per flight batch.
Document structures include fields such as flight number, takeoff and landing time, terminal, gate, passenger capacity, and baggage handling volume. Units involve person-times, tons, minutes, and other units. Some classified documents have a single file size no larger than 100 MB, and security level and approval process must be additionally marked.

## What constraints these characteristics impose on tool calling and plugins
The characteristics of civil aviation airport business data create multiple constraints for tool calling and plugin configuration. Real-time synchronized flight dynamic data requires plugin interface timeout settings to align with business response rhythms, to avoid request failures from temporary flight adjustments. The high number of structured fields and strict unit uniformity requirements mean plugin return formats must exactly match preset fields. Otherwise, document templates cannot be automatically filled. The drafting of classified documents requires additional integration of permission verification plugins to restrict calls from unauthorized accounts. Operation data updated per flight batch requires plugins to support data pulling via batch parameters, to avoid obtaining redundant or missing business information. Significant differences in document fields across different positions require plugins to support custom field mapping rules to meet drafting needs across multiple scenarios.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call timeout | 60-120 seconds | Adapt to standard response durations of civil aviation business interfaces, avoid request interruptions from flight dynamic updates |
| `functionCall` | Force enabled | Ensure structured return fields match preset airport document templates, prevent unstructured output from failing automatic template filling |
| Plugin permission verification | Enable per business scenario | Configure permission verification for classified documents; disable in non-classified scenarios to simplify processes |
| Field mapping rules | Customize per position scenario | Match exclusive fields for documents of different positions; for example, add baggage handling volume fields for ground service documents |
| Batch pull batch size | 5-10 items per batch | Adapt to the batch scale of civil aviation flight operations, avoid interface overload from pulling too much data at one time |
| `toolChoice` | Auto-select per task | Use general models for general document drafting; call dedicated model interfaces for classified documents |

## Three common errors
- Symptom: "Failed to fetch" error returned when calling airport business interfaces. Cause: No whitelist permission configured for airport business systems, so FastGPT cannot access internal interfaces.
- Symptom: Plugin return fields do not match preset document templates, with empty fields or format errors. Cause: `functionCall` forced calling not enabled, so the large language model returns unstructured text.
- Symptom: Number of returned results during batch data pulling does not match expectations. Cause: Batch pull batch size set too large, exceeding the single return limit of the interface, or not pulling data via flight batch parameters.

## How to confirm the configuration is correct
- Launch a test for flight support document drafting, check whether the plugin can pull real-time data for the corresponding flight and fill the preset template.
- View plugin call logs, confirm that interface request parameters match preset configurations.
- For classified document scenarios, test whether unauthorized accounts cannot call the corresponding plugin.
- After adjusting field mapping rules, verify whether return fields match the exclusive requirements of documents for the corresponding position.
