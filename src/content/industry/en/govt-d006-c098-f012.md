# Document and Material Drafting for Civil Aviation Airports: Deployment and Upgrade

## What the data for this category looks like
Civil aviation airport document and material drafting data mainly comes from airport operation logs, flight support records, administrative approval documents, and passenger service templates. Daily flight-related documents are updated per the daily flight cycle. Administrative documents are generated on demand or synced weekly. Most documents use fixed structure templates, with fields including flight number, terminal number, takeoff and landing time, delay cause, and other fields. Some temporary emergency documents are unstructured text. Units include sorties, passenger trips, square meters, and others. Some fields must match standard format requirements released by the Civil Aviation Administration.

## What constraints these characteristics impose during deployment and upgrade
Fixed-structure standardized documents require preloading the official template library released by the Civil Aviation Administration during deployment, and sufficient knowledge base storage space must be reserved. Daily updated flight-related documents need regular synchronization of data sources, so a stable scheduled trigger mechanism must be configured to avoid data lag. Long unstructured emergency documents require adapting resource allocation for long-text processing during deployment. During upgrades, keep the mapping rules of original fields to prevent damage to the adapted Civil Aviation standard format verification logic, and also maintain compatibility with the import process of old version templates.

## How to set the configurations
These configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Civil aviation airport document data volume is large, so sufficient database connection pool is needed to support concurrent read/write and scheduled synchronization tasks |
| `MONGODB_URI` | `mongodb://username:password@host:port/airport_docs?authSource=admin` | Stores unstructured emergency documents and historical flight records, so a dedicated database instance and authentication source must be specified |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches scheduled synchronized flight data and template verification results to reduce repeated calculation overhead |
| `STORAGE_S3_ENDPOINT` | Configured according to the internal network endpoint of the civil aviation cloud storage service provider | Ensures low latency and security for internal data transmission at the airport |
| `ROOT_KEY` | Randomly generated 32-bit string | Used to encrypt sensitive airport operation and document data to improve deployment security |

## Three common mistakes
- Issue: Version verification failure occurs after running the upgrade script, with an HTTP 400 status code returned. Cause: Intermediate upgrade scripts are not executed in version order, directly jumping from 4.9.10 to 4.9.13 and skipping the version adaptation step for 4.9.11.
- Issue: Voice input function cannot be called normally inside the container, and the console prompts that the ffmpeg executable file is missing. Cause: The FastGPT container is not started in privileged mode, so system-level dependency packages cannot be installed inside the container.
- Issue: Deployment fails in a localized environment (Kunpeng 920 chip + Kylin V10 operating system), with an architecture incompatibility error returned when pulling the image. Cause: The FastGPT image adapted for the Kunpeng architecture is not used, and the default image only supports x86 architecture.

## How to confirm the configuration is complete
- Run the database connection test script to verify whether the connection pool configured by `DB_MAX_LINK` can support the preset concurrent read/write requests. Adjust the threshold according to the actual document processing volume during operation.
- Submit a standardized flight delay notification template to check whether the knowledge base can correctly load and match the Civil Aviation Administration format requirements. Adjust the verification logic according to the airport’s internal document specifications.
- Trigger a scheduled synchronization task to verify whether flight data is automatically updated according to the preset cycle. Set the synchronization delay according to the real-time requirements of airport operations.
- View the container logs to confirm whether the cache service configured by `REDIS_URL` is connected normally, with no timeout errors.

The values provided here are common starting points and should be measured against the reader's own samples.
