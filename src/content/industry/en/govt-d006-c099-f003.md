# Document and Material Drafting for Oil and Gas Exploration and Development: Multi-turn Dialogue and Prompt Engineering
This page is compatible with FastGPT v4.17.0.

## What This Category of Data Looks Like
Documents and materials for oil and gas exploration and development mainly come from exploration databases, real-time drilling site collection systems, geological modeling files, and project review archives. Update frequency adjusts based on project phase. Single-well exploration documents are updated weekly. Block reserve assessment documents are updated quarterly. Document structure includes three parts: project overview, measured data section, and conclusion and recommendations. Core fields include well ID, well depth, porosity, and permeability, with corresponding units of none, meters, percent, and millidarcy respectively. Some long documents can reach tens of thousands of characters.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Professional fields and units require prompts to embed standardized definitions of corresponding terms, to avoid generating content that does not meet industry standards. Long documents and frequently updated data require multi-turn dialogue to retain complete historical interaction context, to avoid repeated inquiries about basic project information. Document structures vary significantly across different exploration stages. Differentiated prompts must be configured for scenarios such as drilling logs, trial production plans, and reserve reports, while supporting dynamic switching. When multiple users use the platform concurrently, strict isolation of their respective session data is required to prevent mixing of draft documents from different projects.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Single documents for oil and gas exploration and development can reach tens of thousands of characters, requiring retention of professional parameters and historical interaction content in multi-turn dialogue |
| User session isolation | Enable independent session storage | Multiple business users need to distinguish their own exploration document drafting records to avoid data mixing |
| Dynamic prompt loading | Call from a specified folder associated with the knowledge base | Different exploration stages require matching corresponding professional prompts to improve the accuracy of document drafting |
| Tool call result display | Enable real-time dialog box synchronization | Logging data and wellsite parameters returned by tools must be presented immediately to ensure interaction continuity |
| `chatId` parameter configuration | Bind to the unique identifier of the business system user | When connecting via the FastGPT API, it is necessary to distinguish the chat records of different users to ensure session data isolation |
| `variables` parameter configuration | Pass in exclusive fields of the current exploration project | Inject professional variables such as well ID and well depth into prompts to improve the accuracy of generated content |

## Three Common Mistakes
- Phenomenon: Tool call results are only displayed when re-entering the dialogue, with no returned content on the first call. Cause: The context sequence of the `messages` parameter is not correctly bound, resulting in tool return results not being included in the dialogue history.
- Phenomenon: A version update prompt pops up every time a new dialogue is opened. Cause: The initialization prompt configuration item for new sessions is not turned off, and the global update prompt is loaded by default.
- Phenomenon: Prompts cannot be dynamically loaded from the knowledge base. Cause: Prompt files are not uploaded to the specified knowledge base associated directory, or dynamic call permission is not enabled in the dialogue configuration.

## How to Confirm the Configuration Is Complete
- Initiate a multi-turn dialogue containing professional parameters such as well ID and porosity, and check whether the historical interaction content is fully retained in the dialogue interface.
- Use different business user identifiers to call the FastGPT API, and confirm that the chat records of each user are isolated from each other with no data crossover.
- Switch prompt configurations for different exploration scenarios, and check whether the professional guidance content corresponding to the scenario is loaded in the dialogue interface.
- Initiate a tool call request, and check whether the logging data returned by the tool is immediately displayed in the dialogue box.
