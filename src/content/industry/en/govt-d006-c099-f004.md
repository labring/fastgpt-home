# Document and Material Drafting for Oil and Gas Exploration and Development: Workflow Orchestration

## What this type of data looks like
Document data for oil and gas exploration and development primarily comes from on-site collected drilling logs, seismic interpretation reports, pilot production analysis documents, and industry compliance regulations. Data update rhythm follows exploration project progress: documents are generated or updated immediately after single-well operations are completed. Document structure includes modules such as well number, operating horizon, measured physical property parameters, operating process records, and compliance check results. Most fields are quantitative data with professional units, such as porosity, permeability, and well depth, plus standardized operating node names. Overall document length varies based on operating complexity.

## What constraints these characteristics impose on workflow orchestration
Oil and gas exploration and development document data includes a large number of quantitative fields with professional units and periodically updated operating records. This requires workflows to verify the content integrity of associated knowledge bases before starting, to avoid generating invalid documents with empty data. Document formats vary significantly across different operating phases. Branch nodes must be used to match corresponding templates and data sources. Frequently updated on-site data requires workflows to be configured with real-time pull interfaces, to ensure generated content aligns with the latest exploration progress. Format checks for professional fields must be bound to industry compliance knowledge bases, to prevent generating non-compliant document content.

## Configuration guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| Knowledge base matching threshold | 0.75–0.85 | Meets accuracy requirements for matching oil and gas exploration professional terminology |
| Branch trigger condition | By operating phase tags | Distinguishes between different document types such as drilling reports and pilot production reports |
| `variables` binding | By measured calibration | Adapts to dynamic exploration data for different well numbers and horizons |
| Single match upper limit | Top 10 entries | Covers the reference range of major exploration data |
| Workflow timeout setting | 300–600 seconds | Covers generation and verification time for large-scale exploration documents |
| Knowledge base refresh frequency | Every 24 hours | Aligns with the update rhythm of on-site data |

## Three common configuration errors
- Phenomenon: Workflows directly return the "associated knowledge base has no valid data" error after starting, and cannot enter the generation phase. Cause: No knowledge base null value verification node is configured, and the document generation logic is called directly.
- Phenomenon: Workflows repeatedly trigger tool calls, generating duplicate content until the timeout terminates. Cause: No termination node is added after the tool call node, and the loop is not properly ended.
- Phenomenon: The HTTP module returns empty data after being called, and subsequent nodes cannot read exploration parameters. Cause: Input parameters are not bound to variable names defined in the interface documentation, resulting in the interface failing to receive requests correctly.

## How to verify correct configuration
- Manually trigger the workflow, check whether the node logic corresponding to `nodeId` is correct, and whether branch nodes correctly jump to corresponding templates based on preset operating phase tags.
- View knowledge base matching results, confirm that matched content aligns with current operating professional terminology, and adjust the matching threshold based on actual accuracy requirements.
- Test the interface via the HTTP module, confirm that returned parameters can be properly read by subsequent nodes, and ensure variable binding matches definitions in the interface documentation.
- Simulate a null knowledge base scenario, verify whether the verification node triggers abnormal interception, and ensure invalid data does not enter the generation phase.

The values listed above are common starting points. Adjust them based on your own specific samples and requirements.
