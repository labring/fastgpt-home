# Document and Material Drafting for Oil and Gas Exploration and Development: Model Access and Configuration

## What this category of data looks like
Oil and gas exploration and development document data mainly comes from field exploration operation sites, drilling construction logs, trial production monitoring reports, reserve assessment reports, and project approval documents. Data is generated in real time as operations progress. Update frequency is high during the exploration phase, and regular updates occur during the development phase along with well location adjustments and reserve accounting. Most documents use a mixed format of structured and semi-structured content, including professional fields such as well ID, well depth, lithology, porosity, and permeability. Units mostly follow industry standards including meters, millidarcys, percentages, and cubic meters per day.

## What constraints these characteristics impose on model access and configuration
Long document lengths and dense professional terminology for oil and gas exploration and development require sufficient context windows during model access to avoid truncating core professional content. High data update frequency requires configuration to support real-time or near-real-time data source synchronization logic. A large number of structured fields and specialized units require strict format compliance during model calls, to prevent generated content from deviating from industry standards. Dispersed storage of multi-source data requires access configuration to support unified calls for multi-path data sources.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `maxContext` | 8000–12000 token | Single documents for oil and gas exploration and development often contain thousands of characters of professional content. Complete context retention is needed to avoid truncating core information |
| `maxTokens` | 2000–3000 token | Document drafting requires generating complete paragraphs and professional conclusions, to avoid early truncation of output |
| `quoteMaxToken` | 1500–2000 token | Original fragments such as exploration logs and trial production data must be referenced as generation basis. This range controls the length of referenced content |
| `temperature` | 0.3–0.5 | Documents need to maintain a professional and rigorous style. This range reduces the probability of randomly generated content and avoids deviation from industry standards |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated access address for domestic large models | This adapts to the network environment for direct connection to domestic models, avoiding delays and verification issues caused by cross-region calls |
| `AIPROXY_API_TOKEN` | Fill in the dedicated token that has passed permission verification | This ensures compliance of model call permissions, avoiding access failures caused by invalid tokens |

## Three Common Misconfigurations
- Phenomenon: An invalid token error is returned when calling a domestic model, but tests via oneapi succeed. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to point to the dedicated address for domestic models. The general access address is still used, resulting in token verification mismatch.
- Phenomenon: After the bge-reranker model is called, GPU video memory continues to occupy 6-7G, and multiple GPUs show occupancy. Cause: The length of quoted fragments for `quoteMaxToken` is not limited. A large amount of high-dimensional professional text is sent to the reranking model, increasing video memory overhead.
- Phenomenon: Professional fields are missing or units are incorrect in generated documents. Cause: The `temperature` parameter is not adjusted to a reasonable range. Randomly generated content deviates from established professional formats and unit requirements.

## How to Confirm Successful Configuration
- Perform a test call for a single long document. Check whether the output contains complete professional fields and units, with no early truncated content.
- View the model call log. Confirm that `AIPROXY_API_TOKEN` verification passes, and there are no invalid token errors.
- Monitor GPU video memory usage. Confirm that video memory fluctuations are within the expected range when the reranking model is called.
- Trigger a multi-round document drafting test. Check the consistency of generated content and source data professional terms.

The values provided are common starting points and should be measured against the reader's own samples.
