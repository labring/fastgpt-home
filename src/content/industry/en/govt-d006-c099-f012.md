# Document and Material Drafting for Oil and Gas Exploration and Development: Deployment and Upgrade

## What this category of data looks like
Oil and gas exploration and development documents and materials mainly come from original logs collected during field exploration, drilling construction records, reservoir analysis reports, development plan documents, compliance approval documents, and other sources. Field operations generate single-well documents in real time. Development and operation phases update existing documents according to project cycles. Document structures include fixed fields such as project number, well location coordinates, formation parameters, operation procedures, and approval seals. Units include meters, cubic meters, megapascals, tons, and other professional engineering units. Single document lengths range from hundreds of characters for operation records to tens of thousands of characters for comprehensive reports.

## What constraints these characteristics impose on deployment and upgrade
For FastGPT v4.17.0 deployment and upgrade, adapt to the following requirements based on the long text span and real-time update characteristics of oil and gas exploration and development documents:
- Adapt storage and incremental synchronization logic for large files during deployment
- Use stable structured and unstructured data separate storage configurations to support vector matching requirements for professional fields
- Configure fine-grained access control parameters during deployment to meet hierarchical permission requirements in state-owned enterprise and public sector scenarios

During upgrade, retain the original incremental synchronization link to avoid interrupting the generation of operation documents. Also verify the vector encoding compatibility of professional fields to prevent a decline in retrieval accuracy after upgrade.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| DB_MAX_LINK | 100–150 connections | Adapts to the batch reading requirements of oil and gas exploration and development documents, avoids database connection exhaustion |
| PG_URL | Local private address, port set to 5432 | Stores structured project metadata and approval records, complies with structured storage specifications for professional documents |
| REDIS_URL | Memory quota no less than 4000 MB | Caches frequently accessed exploration operation logs, reduces read pressure on the core database |
| STORAGE_S3_ENDPOINT | Intranet address adapted to local object storage | Stores original exploration documents and scanned files, meets high-speed read/write requirements for large-volume files |
| FILE_TOKEN_KEY | Custom key per project group | Manages signature verification for custom userId parameters, adapts to user identity management rules in state-owned enterprise and public sector scenarios |

## Three Common Mistakes
- Phenomenon: The thinking process is not displayed correctly after upgrade, and appears in the reply body in the form of `<think></think>` tags. Reason: The `ROOT_KEY` and front-end output switch are not correctly associated in the deployment configuration, or the front-end configuration parameters are not updated synchronously after upgrade.
- Phenomenon: After selecting the PG version during deployment, it is not convenient to migrate to the vector database version. Reason: The association mapping between `PG_URL` and vector storage is not configured in advance, and the format compatibility between structured data and unstructured data is not verified before migration.
- Phenomenon: The custom incoming `userId` parameter cannot be recognized by the system, and the interface returns an empty value. Reason: The signature verification rule of `FILE_TOKEN_KEY` is not updated synchronously after upgrade, resulting in the custom user identifier not being parsed correctly.

## How to Verify Successful Configuration
- Log in to the FastGPT management backend, check the database connection status panel, confirm that the current running value of `DB_MAX_LINK` matches the configured value.
- Upload a reservoir analysis report with a single length exceeding 10,000 characters, verify that the system can complete storage and chunk processing normally.
- Initiate an interface call with a custom `userId` parameter, confirm that the correct user identifier field is included in the returned result.
- Restart the deployment service, check the system logs, and there are no error messages of database connection exhaustion or cache timeout.
