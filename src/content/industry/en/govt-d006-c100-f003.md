# Document and Material Drafting for Oilfield Engineering Services: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data primarily comes from construction documents, approval documents, safety inspection records, and acceptance reports for projects such as oilfield drilling, fracturing, and well testing. Data is generated and updated along with the construction milestones of individual projects, and the number of documents within a single project cycle increases gradually as the work progresses. Most documents follow a fixed template structure, including project number, well ID, operation date, operation parameters (such as pump pressure, flow rate), problem rectification items, and approval signature columns. Fields have clear units, such as pressure unit MPa and flow rate unit m³/min.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
The fixed template structure requires prompt engineering to explicitly match preset fields to avoid generating non-compliant content. Operation parameters with units require the dialogue model to accurately identify and retain unit information to prevent parameter confusion. As project documents increase gradually with work progress, multi-turn dialogue needs to limit the context window length to avoid interference from redundant historical information on current generation. Data is dynamically updated along with construction milestones, requiring the dialogue flow to bind project-specific identifiers to ensure the called knowledge base is synchronized with documents from the current construction phase.

## Configuration Settings
These configurations are written for FastGPT v4.17.0.
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` parameter configuration | Bind project number, well ID, and operation type | Pass core identification fields for oilfield engineering documents to ensure generated content matches the template |
| `messages` parameter processing | Only retain the most recent 5 rounds of dialogue | Reduce interference from redundant historical information on current generation, and adapt to dynamically updated construction data |
| `chatId` binding rule | Bind unique identifier for a single project | Ensure multi-turn dialogue context is associated with the knowledge base and documents of the specified project |
| Maximum context window | 8000–12000 characters | Match the average total length of construction documents for a single project to prevent information overflow |
| Prompt template loading | Triggered by operation procedure | Match the exclusive document template for the current construction phase to ensure format compliance |

## Three Common Mistakes
- Issue: Calling the multi-turn dialogue interface returns a 400 status code, with a prompt indicating that the context length exceeds the limit. Cause: The number of historical dialogue entries in the `messages` parameter is not restricted, causing the incoming historical information to exceed the configured context window.
- Issue: Calling the interface fails to retrieve all dialogue records for the specified project, and returned fields are empty. Cause: The unique project identifier is not bound via `chatId`, and the interface returns global dialogue data by default, which cannot accurately match the target project.
- Issue: Generated operation parameters have unit confusion, such as mixing MPa and m³/min. Cause: The prompt engineering does not explicitly require retaining parameter units, and standardized field information is not passed via the `variables` parameter.

## How to Verify Proper Configuration
- Pass the `variables` parameter for a test project, and check whether the generated document includes preset fields such as project number and well ID.
- Call the dialogue interface with multiple rounds of historical messages, and verify whether the returned result only retains the specified number of context rounds.
- After binding `chatId`, confirm that the returned dialogue records only belong to the currently bound project.
- Pass identifiers for different operation types, and check whether the prompt template automatically switches to the format corresponding to the current procedure.

The values provided here are common starting points and should be measured against the reader's own samples.
