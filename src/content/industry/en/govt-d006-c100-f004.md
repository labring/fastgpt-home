# Document and Material Drafting for Oilfield Engineering Services: Workflow Orchestration

## What the data for this category looks like
The data sources involved in document and material drafting for oilfield engineering services include on-site construction logs, geological survey archives, engineering budget forms, completion acceptance documents, and more. Data is updated synchronously as individual projects progress, with no fixed cycle. Most document structures include fields such as construction parameters, geological data, approval nodes, acceptance standards, and others. Fields often carry professional units such as meters, megapascals, cubic meters, working days, and others. The length of individual documents varies widely, ranging from a few hundred characters to tens of thousands of characters.

## What constraints these characteristics place on the workflow orchestration step
The long-text nature of oilfield engineering documents can easily trigger model context length limits, leading to 400 errors. Multiple fields and professional units require workflows to accurately bind dynamic variables to avoid parameter transfer errors. Structural differences between different documents require workflows to support node conditional judgment to adapt to different types of drafting needs. Redundant output from multi-stage AI conversations will interfere with final document review, so valid results must be filtered. On-site data that is dynamically updated for projects requires global variables to be synchronized in real time to adapt to parameter transfer for shared links.

## How to set the configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Multi-node output filtering | Only retain the last AI node result | Oilfield engineering document drafting follows approval node progression; only final approval drafts are needed, avoiding redundancy from multi-stage results |
| File preprocessing chunking | 800–1200 characters per chunk, 150-character overlap | Single entries in oilfield construction logs often exceed 1000 characters; chunking adapts to context limits and reduces 400 errors |
| Maximum context length | 12000 token | Covers core parameters of oilfield geological reports and construction plans, while avoiding exceeding model limits |
| Variable reference configuration | Bind the `variables` parameter to pass project ID, construction parameters | Accurately reference dynamically updated on-site data to adapt to parameter changes across different project phases |
| Global variable update trigger | Trigger updates at project completion nodes | Oilfield project parameters change as construction progresses; global variables in shared links must be synchronized |

## Three common mistakes
- Symptom: The workflow displays output results from all AI conversation nodes, without retaining only the last one. Cause: No multi-node output filtering rule is configured, and all node output content is retained by default.
- Symptom: A 400 error is returned when uploading long documents, and processing cannot be completed. Cause: No file preprocessing chunking logic is added, and directly uploaded documents exceed model context length limits.
- Symptom: After a shared link is embedded in an external system, global variables do not update as project progress changes. Cause: No global variable update trigger is configured based on project nodes, only initial static parameters are set.

## How to confirm the configuration is correct
- Launch a simulated oilfield project test, upload documents of the corresponding type, trigger the workflow, and confirm that only the last AI node result is retained in the output.
- Upload a single construction log document exceeding 10,000 characters, confirm that no 400 error is returned, and the workflow can complete processing normally.
- Modify the value of the global variable bound to the `variables` parameter, refresh the shared link, and confirm that the parameters have been synchronized to the target system.
- Call the variable node with the specified `nodeId`, enter simulated on-site construction parameters, and confirm that parameters can be normally passed to subsequent AI conversation links.
