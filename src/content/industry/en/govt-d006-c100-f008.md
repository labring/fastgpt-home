# Document and Material Drafting for Oilfield Engineering Services: Document Parsing and Chunking

## What this category of data looks like
Oilfield engineering service documents and materials mainly originate from on-site operation records, engineering construction plans, acceptance reports, cost ledgers, and equipment operation and maintenance logs. Data is updated per project cycle, covering the full workflow: from plan documents during the project approval stage, to periodic records during construction, to acceptance documents upon project completion. Document types include Word reports with fixed templates, Excel operation data tables with multiple sheets, and PDF construction files with vector drawings. Fields include well number, operation time, pressure value, displacement, and other relevant metrics. Common units are engineering-specific ones such as cubic meters per hour, megapascals, and degrees Celsius.

## Constraints on the document parsing and chunking step
Multi-sheet Excel operation data tables carry a risk of messy data splitting. If sheet names cannot be identified, parameters from different operation segments will be merged, leading to errors in subsequent retrieval and analysis. PDF documents with vector drawings will lose original image information if parsed using full OCR, only returning garbled text and failing to retain the original visual reference of engineering drawings. Single-project documents have large file sizes and require long parsing times. If reasonable timeouts and file size limits are not configured, parsing tasks will be interrupted or fail. Chunking long documents requires preserving the semantic integrity of the operation workflow. Chunks that are too short will break the contextual connection of operation steps, while chunks that are too long will reduce retrieval accuracy.

## Configuration Settings
These configurations are based on the document parsing module of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 1000–1500 characters | Oilfield engineering documents contain continuous operation parameters and process descriptions. Settings that are too long will lose contextual connections, while settings that are too short will split operation units |
| `chunkSplitter` | Split by paragraph + title | Documents have fixed chapter titles such as "Drilling Parameter Record" and "Fracturing Construction Plan". Splitting by paragraph retains semantic integrity |
| `customPdfParse` | Enable non-OCR mode | Some documents contain vector construction drawings. Enabling this mode preserves the original image and avoids incorrect parsing of drawing content |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | Single-project engineering documents may include multiple large PDF and Excel files. This setting adapts to the single-file upload limit |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 seconds | Large engineering documents take a long time to parse. This avoids interrupting parsing tasks due to timeout |
| `chunkSettingMode` | Manual configuration | Parameters need to be adjusted based on different document types such as logs, reports, and tables to adapt to scenario requirements |

## Three common configuration errors
- Symptom: After enabling PDF enhancement features, the original vector drawing is not retained, only garbled text generated via OCR is returned. Cause: `customPdfParse` is not correctly set to non-OCR mode. The default full OCR setting overrides vector image parsing logic.
- Symptom: When parsing Excel documents, sheet names cannot be identified, and data from all sheets is merged into a single text block. Cause: The sheet recognition configuration for Excel parsing is not enabled. The default setting merges all worksheet data into a single global content block.
- Symptom: When importing PPT or DOC documents, enabling PDF enhancement features produces no change in parsing results. Cause: PDF enhancement features only apply to PDF format documents. Non-PDF files cannot trigger this parsing logic.

## How to confirm the configuration is correct
- Upload a single PDF document with vector construction drawings, and check if the parsing result retains the original image, with no garbled text covering the drawing area.
- Upload an Excel operation data table with multiple sheets, and check if the parsed data is split by sheet, allowing separate extraction of content from specific worksheets.
- Upload a single engineering document with a file size exceeding 1000 MB, and confirm that the parsing task does not trigger a timeout error, with the status showing completed.
- Adjust the `chunkSize` parameter and parse a long document, and check if the chunked results are split by chapter titles and paragraphs, with no content spliced across operation units.

The values provided are common starting points and should be measured against the reader's own samples.
