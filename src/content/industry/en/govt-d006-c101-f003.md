# Document and Material Drafting for Port Shipping: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The data used for document and material drafting in port shipping mainly comes from port operation systems, vessel scheduling platforms, customs declaration systems, and business documents submitted by freight forwarders. Data is updated per voyage or daily operation batch. A single document includes fixed fields such as voyage number, vessel name, container count, cargo category, loading and unloading port, declaration entity, and approval status. Some documents include dynamically changing operation progress fields. Units mostly use shipping-specific measurement standards such as TEU, net ton, and cubic meter.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Port shipping document data is updated per voyage or operation batch, and includes many specialized measurement fields and business nodes. This creates multiple constraints for the multi-turn dialogue and prompt engineering workflow. Dialogue must be bound to the context of a specific voyage to avoid mixing data across voyages. Prompts must clearly specify shipping-specific units and field formats to prevent generating document content that does not meet industry specifications. Real-time retrieval of the latest operation progress data must be supported to ensure generated documents match current operation status. Format requirements for different document types such as manifests, customs declarations, and operation instructions must also be distinguished to adapt to output specifications for multiple business scenarios.

## Three Common Misconfigurations
- Phenomenon: The online dialogue interface returns empty data or status code 500. Cause: The `chatId` parameter is not correctly bound, so the system cannot match the business context of the corresponding voyage and retrieve required document data.
- Phenomenon: Results are output fully at once for short-text questions, without enabling streaming return. Cause: Context caching logic for multi-turn dialogue is not configured, so the system treats each single question as an independent task and does not retain historical dialogue status.
- Phenomenon: Clicking a custom question does not redirect to the corresponding dialogue window. Cause: The voyage number parameter in `variables` is not associated, so the manually triggered dialogue is not bound to the current business scenario and cannot open the preset dialogue interface.

## How to Confirm Configuration Is Complete
- A question including a specific voyage number is initiated, and the dialogue context is verified to always associate with the business data of that voyage.
- A short-text question is submitted, and the output is observed to confirm whether streaming return mode is used.
- The online dialogue interface is called, and the returned data is verified to include expected business fields and document content.
- The custom trigger button is clicked, and the redirection to the dialogue window bound to the current business scenario is verified.
