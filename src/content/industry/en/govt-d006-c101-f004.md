# Document and Material Drafting for Port and Shipping: Workflow Orchestration

## What the data for this category looks like
Port and shipping document and material data mainly comes from port operation scheduling systems, vessel customs declaration systems, and port shipping operation ledger databases. Data updates trigger with job nodes. New document entries generate during vessel berthing, loading/unloading operations, and departure stages. A single document has fixed fields including vessel name, voyage number, berth number, cargo volume, customs commodity code, and declaration number. Field units include tons, TEU, hours, and other units. Single document length ranges from hundreds to thousands of characters.

## What constraints these characteristics impose on workflow orchestration
Dispersed data sources require workflows to configure multi-source data fetch nodes and connect to interfaces of different systems, such as port scheduling and customs declaration systems. Update rhythm triggered by job nodes requires workflows to bind corresponding event hooks, and support manual on-demand triggering. Fixed fields and units require variable definitions to strictly match field formats, to avoid format errors caused by incompatible units. Wide range of document lengths requires workflows to configure dynamic context cropping rules to adapt to document content of different lengths. Customs-related fields must comply with regulatory specifications, so workflows need to add compliance check nodes to filter non-compliant field content in advance.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Configure fields such as vessel name, voyage number, and cargo volume, use standardized field values returned by corresponding systems | Match the fixed field structure of port documents to ensure data format compliance |
| Trigger node configuration | Enable both event trigger and manual trigger modes | Adapt to the update rhythm triggered by port job nodes, and support on-demand workflow adjustments |
| Context cropping threshold | 800–1200 characters | Adapt to the average length of single port documents, avoid model call failures caused by context overflow |
| Compliance check node | Configure customs code check and unit matching rules | Ensure generated documents comply with port and shipping regulatory format and content requirements |
| Fetch timeout | 60 seconds | Match the average response time of port system interfaces, avoid unnecessary waiting |
| `nodeId` flow condition | Trigger subsequent document generation nodes only after the data fetch node corresponding to `nodeId` is executed successfully | Ensure the workflow executes subsequent steps only after valid data is obtained, avoid invalid documents generated from empty data |

This document applies to FastGPT v4.17.0.

## Three Common Configuration Errors
- Phenomenon: When the workflow calls an external interface that returns images, the node status shows execution failed, and the returned content is garbled or empty. Cause: The receiving and processing logic for binary file streams is not configured, and the default API response parsing only supports text formats.
- Phenomenon: Unit mismatch errors appear in documents generated by the workflow, such as marking "TEU" for cargo volume as "tons". Cause: Unit verification rules for fields are not bound in the `variables` configuration, and unit format verification is not performed on the obtained field values.
- Phenomenon: The workflow cannot support users to independently choose whether to skip the knowledge base retrieval link. Cause: A selection variable of `variables` type is not added to the workflow, and this variable is not associated with the execution condition of the retrieval node.

## How to Verify Correct Configuration
- Manually trigger the workflow, pass simulated port document field data, check whether `variables` are correctly associated with the input parameters of corresponding nodes.
- Configure event hooks, simulate port job nodes to trigger the workflow, confirm that the workflow can start normally and pull field values from corresponding data sources.
- Adjust the context cropping threshold, test document content of different lengths, confirm that the workflow can automatically adapt to the cropping rules.
- Trigger the compliance check node, pass field values that do not meet the format requirements, confirm that the node can correctly intercept and return a verification failure prompt.

The values provided here are common starting points. Adjust configurations based on your own samples and use cases.
