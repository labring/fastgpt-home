# Document and Material Drafting for Port Shipping: Citation Sources and Traceability

## What the data for this category looks like
The data sources used for port shipping document and material drafting mainly include port operation scheduling documents, container bills of lading, vessel stowage lists, customs declaration documents, port fee receipts, and more. Document update cycles follow single-operation generation or daily batch synchronization. Structures primarily combine structured fields and free text. Core fields include vessel name, voyage number, container number, port of loading, port of discharge, fee details, and other relevant items. Units mostly use industry standard units such as TEU, ton, yuan, and similar standards. Some documents also include associated upstream and downstream document numbers for tracing full-process operation information.

## What constraints these characteristics impose on the citation sources and traceability link
The multi-source mixed structure and specific field identifiers of port shipping documents require traceability to accurately match core identifiers such as vessel name and container number, to avoid incorrect association of unrelated documents. The high-frequency update feature of documents requires the traceability link to support real-time or near-real-time document synchronization verification, to ensure that cited content is the latest version. Differences in priority among different document types require configuring recall weights by document category, to prioritize returning core citation sources such as bills of lading and stowage manifests. The existence of some confidential documents requires traceability to strictly limit the range of documents that can be cited, to avoid sensitive information leaks.

## Configuration settings
This configuration is based on FastGPT v4.17.0.

| `quoteMaxToken` | 8000–12000 token | Port shipping documents have long individual lengths, so sufficient original citation content must be retained |
| `responseData` | Enabled | Complete citation metadata must be returned to support traceability verification |
| `detail` | Top 3–5 entries | Port documents have strong relevance, prioritize recalling the most relevant core documents |
| Maximum context length | 12000–15000 characters | Retain sufficient context information when processing long documents to avoid taking content out of context |
| Reranking switch | Enabled | Sort citation sources by relevance to improve traceability accuracy |

## Three common mistakes
- Garbled end citation marks appear in conversation output, eventually displayed as standard quotation marks. The cause is failure to correctly configure the escape rules for citation formats, leading to special characters not being properly handled during output.
- Citation entries are still returned when no matching content exists in the knowledge base. The cause is failing to disable the switch for generating responses when no matching content is found, or failing to limit recall to only specified ranges of knowledge base documents.
- The dialogue request interface does not return cite citation IDs. The cause is failing to enable the `responseData` configuration item, or failing to correctly configure the return fields for citation data.

## How to confirm the configuration is correct
- Initiate a test query containing port document keywords, check whether clear citation source information is attached at the end of the response.
- Call the dialogue interface, check whether citation-related metadata fields are included in the returned results.
- Construct a question that does not exist in the knowledge base, confirm that irrelevant citation entries are not attached to the response.
- Adjust the `quoteMaxToken` parameter, verify whether the length of the output citation content meets expectations.

The values given are common starting points and should be measured against the reader's own samples.
