# Document and Material Drafting for Port and Shipping Industry: Document Parsing and Chunking

## What the data for this category looks like
Port and shipping documents and materials mainly originate from port operation systems, vessel scheduling platforms, customs declaration systems, and tallying organizations. Data update cycles span from real-time operation updates to daily summary reports. Document types include structured manifest tables, semi-structured operation logs, and standardized customs declaration documents. The length of individual documents varies widely, ranging from berth scheduling notices of several hundred characters to full-vessel tally reports of tens of thousands of characters. Core fields include vessel name, voyage number, container number, and loading and unloading tonnage. Common units are TEU, net ton, and meter.

## Constraints on Document Parsing and Chunking From These Characteristics
The wide range of document lengths, structured fields, and specialized terminology of port and shipping materials impose multiple constraints on the document parsing and chunking process. Short berth scheduling notices must avoid overly fine-grained chunking that causes semantic breaks. Long full-vessel tally reports must retain contextual connections when split. The fixed field format of structured manifests requires that parsing does not split content across fields, to avoid damaging data relevance. Specialized terms such as TEU and net ton must be identified as independent semantic units to prevent truncation during chunking. Real-time operation documents have timeliness requirements, so the parsing link must adapt to fast-response parameter configurations that match the response rhythm of port operations.

## How to Configure the Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the average semantic block length of port documents, and avoids splitting specialized terms and structured fields |
| `chunkSplitter` | Split by paragraph + heading | Matches the paragraph structure of port documents, and retains the integrity of operation logic |
| `customPdfParse` | Enabled | Adapts to the fixed format of port standard PDF documents, and improves the accuracy of structured field extraction |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the upload requirements of ultra-large documents such as full-vessel tally reports |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Meets the time requirements for long document parsing, and avoids timeout interruptions |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking parameters for different types of port documents |

## Three Common Misconfigurations
- After uploading an image file or image URL, the parsing result is empty or an error is returned indicating that the file cannot be recognized. This occurs because the image parsing rules for port documents are not adapted. The default configuration only supports text and standard PDF documents, and the parameter settings related to image parsing are not enabled.
- Parsing of long full-vessel tally reports times out, and the task status returns a timeout error. This occurs because the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default duration is insufficient to complete the parsing process for ultra-large port documents.
- Chunking results split specialized terms such as TEU and net ton, causing subsequent retrieval to fail to match precise business semantics. This occurs because the `chunkSplitter` is not configured to split by semantic unit, and the default character-level splitting logic is used instead.

## How to Verify the Configuration Is Correct
- Upload a typical port standard manifest document, and check whether the parsed text completely retains the preset core business fields.
- View the chunked content fragments, and confirm that specialized business terms are not split across chunks.
- Upload an ultra-long tally report, and confirm that the parsing task does not trigger a timeout exception.
- Call the corresponding API interface, and verify that the file parameter transfer format can be correctly recognized by the system.
