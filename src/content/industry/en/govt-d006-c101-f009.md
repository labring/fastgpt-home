# Document and Material Drafting for Port and Shipping: Model Access and Configuration

## What the data for this category looks like
Port and shipping documents and materials mainly originate from port operation management systems, vessel scheduling platforms, customs declaration systems, and freight forwarding documents. Core documents include manifests, bills of lading, loading and unloading operation reports, and cargo declaration forms.
Document updates trigger based on operation nodes: Official manifests are generated 1 to 3 days before a vessel berths. Daily loading and unloading operation logs are updated each day. Cargo declaration forms are synchronized after customs clearance is completed.
Document structures primarily use structured fields, including vessel name, voyage number, cargo name, container quantity, port of discharge, and other fields. Most units use industry-standard measures such as TEU, ton, and meter.

## Constraints imposed by these characteristics on model access and configuration
The multi-source, heterogeneous data feature of port and shipping documents requires model access to support field mapping and format alignment. This avoids recognition errors caused by differing field names across systems.
The high proportion of long documents requires configuration to adapt to text processing needs of varying lengths. This prevents key operation information from being truncated.
The presence of specialized industry units and terms requires model configuration to include contextual constraints for industry terms. This ensures the professionalism and accuracy of generated content.
For internally deployed models under compliance requirements, a dedicated proxy address must be configured. This meets the requirement of not letting sensitive data leave the internal network.

## How to set the configuration
This configuration applies to FastGPT v4.17.0, optimized for port and shipping document drafting scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxTokens` | 8000–16000 token | Port and shipping documents include long sections of loading and unloading operation records and manifest details. Full context must be retained |
| `maxContext` | 12000–18000 characters | Supports splicing multiple related documents. Prevents truncation of key fields such as vessel name and voyage number |
| `temperature` | 0.1–0.3 | Document drafting requires strictness. Reduces random generation probability to ensure field accuracy and format compliance |
| `AIPROXY_API_ENDPOINT` | Bind the dedicated proxy address of the internally deployed port-specific model | Meets compliance requirements. Ensures sensitive operation data does not leave the internal network |
| `vision` | Enabled | Supports recognition of image-format content such as manifests and operation documents. Adapts to scanned copies of paper documents uploaded on-site |

## Three common mistakes
- Phenomenon: Missing fields or incorrect units appear in generated documents. Cause: No contextual constraints for port industry terms are added to the configuration. The model cannot correctly recognize specialized content such as TEU and voyage number.
- Phenomenon: Interface calls return timeout errors. Cause: The `maxTokens` setting is too small. Forced truncation during long document processing causes repeated request retries.
- Phenomenon: Errors occur when entering Chinese text, but English input runs normally. Cause: The proxy address is not correctly bound to the deployment path of the Chinese model, or language adaptation parameters are not configured.

## How to confirm the configuration is properly set
- Upload a standard port manifest document. Check whether the generated draft content includes required fields such as vessel name, voyage number, and container quantity.
- Submit a loading and unloading operation report with a length exceeding 5000 characters. Confirm that the output content does not show context truncation prompts or incomplete paragraphs.
- Call the configured proxy interface. Check that the returned response code is 200, with no prompts for authentication failure or address error.
- Upload a scanned image of a paper manifest. Confirm that the model can correctly extract text content from the image and generate compliant draft documents.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
