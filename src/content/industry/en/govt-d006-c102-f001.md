# Document and Material Drafting for Refinery and Chemical Production: HTTP Interfaces and External Systems

## What data for this category looks like
Data related to document and material drafting for refinery and chemical production mainly comes from distributed control systems (DCS), enterprise asset management systems (EAM), on-site inspection terminals, and production scheduling ledgers. Data update frequencies cover three categories: real-time (such as process parameter fluctuation records), shift-based (such as inspection logs), and daily (such as material balance reports). Documents primarily use structured fields, including unit number, inspection period, medium temperature (℃), pressure (MPa), material flow rate (m³/h), operator ID, and other standardized fields. Unstructured exception remarks are also attached.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multi-frequency data updates require HTTP interfaces to support two invocation modes: one-time triggering to pull historical bulk data, and scheduled triggering to synchronize real-time incremental data. The standardized attributes of structured fields require interface parameters to strictly match preset field names and industrial units to prevent format parsing failures. Security and compliance requirements for production-related data require interface configurations to include encrypted transmission and permission verification mechanisms. The need to associate data from multiple system sources requires interfaces to support passing multiple system identifiers as filter conditions, enabling joint invocation of cross-system data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Authentication Configuration | Set the `Authorization` parameter to Bearer Token format | Aligns with FastGPT v4.17.0 security configuration specifications, and meets security verification requirements for refinery and chemical production data |
| Request Parameters | Pass the `variables` parameter containing fields such as unit number and inspection period | Accurately matches the filtering requirements for structured data, narrowing the scope of returned data |
| Response Parsing | Extract content based on the fields specified in `responseData` | Reduces invalid data transmission and improves the efficiency of document generation |
| Polling Cycle | 600 seconds | Adapts to the update frequency of real-time process data, avoiding frequent calls that occupy system resources |
| Timeout Threshold | 30 seconds | Prevents long waits from blocking production processes, and meets the response requirements of industrial systems |
| Pagination Limit | Top 100 entries | Adapts to the reasonable range of single-batch data volume, avoiding excessively large interface return data |

## Three common configuration errors
- A 401 Unauthorized error is returned when calling the interface. The cause is failure to correctly configure the `Authorization` parameter, or failure to update the token as required.
- The interface returns empty fields after the `variables` parameter is passed. The cause is a mismatch between the parameter name and the field naming of the target system, and standard refinery and chemical production field names were not used.
- The access link generated after local deployment still points to localhost. The cause is failure to correctly configure the external access domain name in the system configuration, and only the local HTTP service was enabled.

## How to confirm the configuration is complete
- Call the test interface and check whether the returned `responseData` includes preset refinery and chemical production fields, such as unit number and medium temperature.
- Manually pass test `variables` parameters to verify whether the interface can filter historical data for the corresponding unit.
- Check the system logs to confirm that the timeout time of interface requests matches the configured threshold, and no frequent timeout errors occur.
- Check the access logs of external systems to confirm that the request authentication information and IP address meet the configuration requirements, and there are no interception records.
