# Document and Material Drafting for Refinery and Chemical Production: Workflow Orchestration

## What This Category of Data Looks Like
Refinery and chemical production document and material drafting covers multiple types of production-related documents. Data sources include plant operation reports, equipment inspection ledgers, process operation procedures, safety compliance documents, and more. Data update rhythms fall into three groups: real-time (inspection records), daily (shift reports), and monthly (equipment ledger updates).
Document structures combine structured fields and free text. Structured fields include plant ID, operating pressure, operating temperature, inspection time, and others. Units include MPa, ℃, hours, and similar units. The free text section records abnormal conditions, process adjustment explanations, and related content.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The characteristics of refinery production document data impose multiple constraints on workflow orchestration.
Many structured fields must match production scenarios. `variables` must be used to bind structured fields to ensure generated content matches specific production scenarios. Workflows must include field validation steps to ensure generated documents include required items such as plant ID and process parameters.
Long text accounts for a large proportion of content. Workflows must perform reasonable chunking on input text to avoid exceeding model context limits.
Update frequencies vary widely across different documents. Workflows must support two trigger modes: scheduled trigger or new document upload trigger.
Compliance requirements are strict. Workflows must include built-in compliance check nodes to ensure generated content conforms to petroleum and chemical industry specifications.

## How to Configure
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context | 800–1200 preceding characters | Refinery documents have long single-segment text, avoid exceeding model context capacity limits |
| `variables` | Bind plant ID and operating pressure fields | Match the structured data characteristics of refinery documents, ensure generated content is linked to specific production parameters |
| Node Timeout | 600 seconds | Refinery data retrieval may involve cross-database queries across multiple systems, reserve sufficient response time |
| Trigger Mode | New document upload trigger | Adapt to the batch or real-time update release rhythm of refinery documents |
| Historical Conversation Count | First 3 entries | Avoid interference from redundant historical information on accurate generation of production-related documents |

## Three Common Misconfigurations
- Workflow execution times out, with status code 504 displayed in the interface. Cause: Node timeout setting is too short, no reserved response time for cross-system data retrieval in refinery operations.
- Workflow call branches do not perform as expected, irrelevant knowledge base content is returned. Cause: `variables` are not correctly configured to bind the dedicated production knowledge base, leading to calls to general knowledge base resources.
- Generated documents lack the required plant ID field. Cause: No field validation node added to the workflow, failed to forcibly extract core production information from structured data.

## How to Confirm Proper Configuration
- Upload a refinery test document with clear plant ID and process parameters, check whether the workflow automatically triggers and extracts the corresponding fields.
- Simulate a long text input scenario, verify whether the workflow processes content according to the configured maximum context length.
- View workflow logs, confirm that the execution status of the node corresponding to `nodeId` is normal, with no error messages.
- Test trigger branch switching, confirm that only the preset dedicated knowledge base content is called, with no irrelevant information returned.
