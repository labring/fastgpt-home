# Document and Material Drafting for Refinery and Chemical Production: Tool Calling and Plugins

## What the data for this category looks like
Refinery and chemical production document and material data mainly comes from unit operation logs, process operation specifications, quality inspection reports, equipment maintenance ledgers, and production scheduling reports. Data sources cover the entire production process. Real-time operation data updates with unit start and stop, while report data updates on a shift or daily fixed schedule. Document structures typically include fields such as equipment number, process parameters, test values, and timestamps. Parameter units are mostly industrial standard units such as MPa, ℃, tons per hour. The length of individual documents varies widely, ranging from a few hundred characters to several thousand characters.

## What constraints these characteristics impose on the "tool calling and plugins" link
The multi-source real-time or timed update characteristics of refinery and chemical production documents require plugin calling interfaces to adapt to the response speed of high-frequency data pulling. Otherwise, document generation delays will occur. Parameter fields with specific industrial units require plugins to include built-in unit verification logic, to avoid generating content that does not comply with process specifications. The wide span in length of individual documents requires that the context length configuration for tool calling supports flexible adjustment, to prevent truncation of key process data. The differences in field structures across different document types require plugins to support dynamic field matching, rather than using fixed templates for all scenarios.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to different types of refinery and chemical document generation needs, automatically matching corresponding dedicated plugins |
| `functionCall` | `required` | Force tool calling to ensure that generated documents include valid process data obtained from plugins |
| Plugin timeout period | `10–15 seconds` | Refinery data interfaces typically respond quickly, this duration avoids excessive waiting that affects generation efficiency |
| Maximum context length | `8000–12000 characters` | Adapt to process parameters and equipment information in long documents, preventing truncation of key content |
| Number of plugin return data entries | `Top 5–8 entries` | Focus on the core parameter requirements of refinery documents, avoiding returning excessive redundant data |
| Plugin parameter verification switch | Enabled | Verify the units and value ranges of refinery parameters to ensure process compliance of generated documents |

This configuration is based on FastGPT v4.17.0.

## Three common mistakes
- Phenomenon: The refinery parameter fields returned after calling the plugin are empty. Cause: The plugin parameter verification switch is not enabled, causing parameters that do not comply with industrial specifications to be filtered out, and no valid data is returned.
- Phenomenon: Plugin calling times out, and document generation fails. Cause: The timeout period is set too short, which does not match the actual response rhythm of the refinery data interface.
- Phenomenon: The large model calling prompt shows abnormal costs, but the API balance is sufficient. Cause: The billing binding logic of the plugin is not configured correctly, causing tool calling costs to be misjudged as large model calling overdue payments.

## How to confirm the configuration is correct
- Manually trigger a refinery document generation, check whether the result includes process data and equipment information obtained from the plugin, to confirm that tool calling is triggered normally.
- View the plugin calling log to confirm that the interface response status and time are as expected, with no timeout or error messages.
- Test document generation scenarios of different lengths to confirm that no forced truncation of context occurs.
- Verify the plugin parameter verification logic, input parameters that do not comply with industrial units, and confirm that the system triggers corresponding verification prompts.
