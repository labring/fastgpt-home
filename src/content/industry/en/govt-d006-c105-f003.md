# Document and Material Drafting for Coal Transportation and Sales: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Coal transportation and sales document data mainly comes from business documents such as purchase and sales contracts, railway/road waybills, weighing tickets, settlement reconciliation forms, and value-added tax special invoices.
Data updates for each single batch of transportation and sales business. A single business generates multiple associated documents from contract signing to settlement.
Fields of a single document include coal type, shipment volume, transportation mileage, settlement unit price, qualification information of paying and receiving parties, and more. Common units are tons, yuan per ton, kilometers, percentage (for moisture content), and others. Some documents require matching coal industry-specific quality indicator parameters.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Coal transportation and sales business documents have many fields and industry-specific parameters. Multi-turn dialogue must continuously track the complete context of a single batch of transportation and sales business to avoid confusing core information such as coal type and tonnage across different batches.
General document templates cannot adapt to format requirements for different settlement rules and transportation methods. Prompts must explicitly bind exclusive fields of business documents.
A single transportation and sales business has a large number of associated documents. Multi-turn dialogue must filter redundant historical content through the `messages` parameter, and bind business-exclusive fields through `variables` to prevent redundant content from interfering with instruction execution.
When calling external data tools, match the database table structure of the transportation and sales business to ensure accurate field mapping.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Session ID Binding | Bind to single batch transportation and sales business ID | Ensure multi-turn dialogue context is tied to a specific waybill to avoid cross-business confusion |
| Number of Retained Conversation History Entries | Retain the latest 8–12 conversation messages | Focus on the communication context of the current transportation and sales business, filter redundant historical content |
| Prompt Variable Configuration | Bind variables for waybill number, coal type, and shipment volume | Automatically fill industry-exclusive fields in documents to reduce manual input |
| Tool Call Timeout Setting | 60 seconds | Adapt to query response durations of coal transportation and sales databases to avoid timeout errors |
| Context Window Upper Limit | 10000 characters | Adapt to the total length of associated documents for a single batch of transportation and sales business, align with model processing capabilities |

## Three Common Mistakes
- Phenomenon: A 400 status code returns when calling database tools, with no response body. Cause: Exclusive fields of the transportation and sales business are not accurately mapped to database table fields, leading to request parameter formats that do not meet interface requirements.
- Phenomenon: Documents generated by multi-turn dialogue contain incorrect coal type or tonnage information across batches. Cause: The single-batch transportation and sales context is not bound via `chatId`, causing the model to confuse parameters from different businesses.
- Phenomenon: Historical conversation records cannot be retrieved after sharing a web application. Cause: Conversation record persistence configuration is not enabled, or the correct session storage path is not bound.

## How to Confirm the Configuration is Correct
- Initiate a test conversation that includes a specific waybill number, check if the generated document automatically fills in the exclusive fields of the corresponding business.
- Call the database tool to query records for a specified waybill, confirm that the returned results match the fields of the business document.
- Switch to different models to initiate multi-turn dialogue, check if the context is retained normally and no parameter confusion occurs.
- Restart the service and initiate a new conversation, check if historical sessions can be recovered normally.
