# Document and Material Drafting for Coal-Electricity Integration: Workflow Orchestration

## What this category of data looks like
Data for document and material drafting in coal-electricity integration projects comes primarily from business systems: mine excavation ledgers, power plant operation logs, and coal sales reports.
Data updates follow shift, daily, and monthly cycles.
The data includes structured production parameters and unstructured scheduling reports.
Structured data fields include mine number, unit load, coal calorific value, power generation, and more. Corresponding units include tons, kilowatt-hours, kilocalories per kilogram, ten thousand cubic meters, and others.
Unstructured documents are long texts of thousands to tens of thousands of characters, including safety inspection records, production scheduling minutes, and similar content.

## What constraints these characteristics impose on workflow orchestration
Multiple heterogeneous data sources require the workflow to use multiple independent data pull nodes. This avoids data conflicts across different systems.
Long-text scheduling reports need to retain contextual links. The workflow must include a context storage node to prevent content fragmentation.
Specialized fields and units require the workflow to use variable binding to validate data formats. This prevents generation of documents that fail to meet business specifications.
Multi-stage approval and data transfer require the workflow to support parallel branches and cyclic execution. This adapts to the multi-shift, multi-unit collaborative workflows of coal-electricity integration projects.

## Three common configuration errors
- Scenario: The workflow runs correctly in debug mode, but returns a node configuration error during runtime. Cause: The `nodeId` was not updated to the formal environment node identifier, and the temporary node ID used in debug mode was not replaced.
- Scenario: Exported conversation records only display the last 6 entries. Cause: Full context storage was not configured via `variables`, so only conversation data from the current node was cached.
- Scenario: Only one branch of a multi-branch workflow executes. Cause: The parallel branch execution switch was not enabled, and branches were incorrectly set to mutually exclusive transitions.

## How to verify a complete configuration
- Trigger debug mode, and confirm that each node corresponding to a `nodeId` pulls data normally and generates drafts.
- Run test cases to confirm that exported conversation records include questions and replies from all workflow stages.
- Start the formal runtime workflow, and confirm that multi-branch nodes execute simultaneously and complete data aggregation.
- Check that fields bound via `variables` include specialized production parameters and units for coal-electricity integration projects.
