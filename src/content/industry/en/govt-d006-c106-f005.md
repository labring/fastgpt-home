# Document and Material Drafting for Coal-Electricity Integration: Tool Calling and Plugins

## What this category’s data looks like
Document drafting data for coal-electricity integration scenarios mainly comes from coal mining ledgers, power plant operation logs, coal purchase and sales contracts, power dispatch approvals, and environmental emission reports. Data is updated per production shift or daily. Document structures include fields such as work order number, coal calorific value, power generation load, approval document number, and environmental emission indicators. Units cover professional measurement standards including kilocalories per kilogram, megawatts, tons, cubic meters, and more. Document lengths range from dozens-of-page monthly summary reports to single-page shift dispatch sheets.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Data sources are scattered and include both structured ledgers and unstructured reports. This requires plugins to support batch pulling from multiple data sources and field alignment. Data has a high update frequency, so plugins must include a scheduled synchronization mechanism to avoid calling outdated production and dispatch data. There are many professional fields and units, so parameters for tool calls must clearly specify field names and corresponding units to prevent the AI from generating requests that do not meet industry specifications. Documents must comply with energy regulatory compliance requirements, so compliance verification tools must be additionally linked to ensure drafted content aligns with local power and coal industry policy standards.

## How to configure settings

| `toolChoice` | `auto` | Adapts to the multi-tool automatic scheduling needs of coal-electricity document drafting, no manual tool specification required |

| `functionCall` | Generate structured calls per coal-electricity-specific parameter template | Ensures generated data requests comply with the specifications of coal-electricity professional fields and units |
| Maximum number of data entries pulled per data source | Top 20 entries | Controls the amount of data returned per call, avoids context overload that impacts document generation efficiency |

## Three common errors
- Empty fields returned by tool calls: No coal-electricity-specific field mapping configured, causing the AI to fail to recognize parameter requirements for professional fields such as calorific value and power generation load.
- Unable to locate the plugin import entry in the interface: The tool calling module is not enabled in system settings, or the used FastGPT v4.17.0 does not support the plugin management function.
- Generated requests contain incorrect units: No unit rules for coal-electricity fields specified in plugin parameters, causing the AI to confuse parameter formats for professional measurement standards.

## How to confirm configurations are complete
- Enter the tool management page, confirm that the coal-electricity data pulling plugin has been uploaded and enabled.
- Initiate a test call, enter test instructions related to coal-electricity dispatch or document drafting, and check whether the tool automatically calls the corresponding data source and returns structured data.
- View the tool call log, confirm that the parameter format complies with coal-electricity field specifications, with no missing fields or unit errors.
- Adjust the plugin cache duration parameter, and verify that plugin data is automatically updated at the set frequency.
