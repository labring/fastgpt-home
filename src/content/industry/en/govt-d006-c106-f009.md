# Document and Material Drafting for Coal-Electric Integration: Model Access and Configuration

## What the data for this category looks like
Document sources for coal-electric integration scenarios include enterprise production scheduling logs, safety inspection records, project declaration materials, monthly operation summaries, coal mining and power production ledgers, and more. Update cadences fall into three categories: scheduling logs are updated daily, monthly summaries are updated on fixed monthly dates, and safety regulations and industry standard documents are updated quarterly or annually. Document structures include long-text reports spanning dozens of pages per copy, as well as short fields for single records. Fields include mine number, power generation, coal consumption rate, power supply, and others. Units involve ten thousand kilowatt-hours, tons of standard coal, megawatts, and additional relevant units.

## Constraints imposed by these characteristics on model access and configuration
Documents for coal-electric integration have both long-text report and short-field record characteristics. This requires model access to adapt to input and output of varying lengths, to avoid truncating critical production or safety data. Differences in update frequencies across data sources require distinguishing between high-frequency and low-frequency update document types when configuring indexing strategies, to balance data timeliness and storage costs. Industry-specific fields and units require adding targeted context guidance during model configuration, to ensure generated documents comply with industry specifications. Additionally, data localization requirements for state-owned enterprises, public sector, and public service scenarios require model access to support local API deployment and authentication, to safeguard data security.

| `AIPROXY_API_TOKEN` | Enterprise-customized authentication token | Ensure the security of internal data calls, and comply with data security specifications for state-owned enterprises, public sector, and public service scenarios |

## Three Common Configuration Mistakes
- Phenomenon: Unable to select a configured model in the workflow, and the model list appears empty. Cause: The "Enable" option was not checked in the model configuration page of FastGPT v4.17.0, or the configuration was not synchronized to the workflow module.
- Phenomenon: Calling a locally deployed MinerU parsing service returns a 503 status code. Cause: The port of the local Docker container was not correctly mapped, or the address configured in `AIPROXY_API_ENDPOINT` does not match the actual deployed MinerU service address.
- Phenomenon: Unit errors or missing fields appear in generated document materials. Cause: No targeted context guidance was configured for the model for specific fields in the coal-electric industry, leading to the model failing to correctly recognize the data format.

## How to Confirm Successful Configuration
- Enter the model configuration page, check that the status of the added model is enabled, and that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are filled correctly.
- Upload a standard coal-electric industry document (such as a monthly production summary), trigger a model call, and check whether the returned result includes complete industry terminology and compliant format.
- Configure a workflow node, select the connected model, and confirm that the node can be saved normally and the call result can be previewed.
- Use a curl command to call the locally deployed MinerU service, confirm that the returned parsed content format meets expectations, with no errors or exceptions.
