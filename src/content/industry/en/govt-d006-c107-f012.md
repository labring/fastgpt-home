# Document and Material Drafting for Coal Mining Production: Deployment and Upgrade

## What the data for this category looks like
The documents and materials for coal mining production mainly come from daily reports from on-site work teams, scheduling ledgers, safety acceptance forms, excavation and mining operation procedure documents, etc. Data updates are submitted immediately after each work shift, with daily aggregation forming that day’s production report, and monthly aggregation forming safety and production summaries. The length of individual documents varies widely, from a few hundred words for pre-shift meeting records to tens of thousands of words for annual excavation and mining plans. Document fields include fixed items such as work location, work time, operating personnel, hidden danger inspection items, rectification time limits, etc. Some safety-related documents have mandatory formatted parameter items, with professional units such as meters, %LEL, person-times, etc.

## What constraints these characteristics impose during the deployment and upgrade phase
The varied document lengths for coal mining production documents require that deployments adapt to file processing workflows of different scales, to avoid excessive splitting of short documents or truncation of long documents. The requirements for fixed fields and professional units mean that the original field format must be retained during the data access phase, to avoid standardization processing damaging the accuracy of professional parameters. The high-frequency update rhythm based on shifts and daily cycles requires the server to have sufficient CPU and memory resources to support high-frequency document data processing, while also meeting database connection stability requirements during deployment. During upgrades, compatibility between incremental synchronization and full updates must be considered, to avoid data synchronization interruptions affecting the generation of that day’s work documents. In addition, the mandatory format requirements for safety-related documents require that original document structure markers be retained during knowledge base embedding, to avoid generated documents failing to meet coal mining industry specifications.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 connections | Matches the high-frequency read/write demands of coal mining production documents, avoids connection exhaustion when multiple work teams submit data simultaneously |
| `MONGODB_URI` | Configure as the connection string for a dedicated MongoDB instance on the coal mining intranet | Stores unstructured work documents and archived documents, intranet deployment ensures security of sensitive production data |
| `REDIS_URL` | Configure as an intranet Redis cache instance, set cache validity period to 3600 seconds | Caches basic data such as personnel and equipment for that day’s work teams, reduces delays from repeated database queries |
| `STORAGE_S3_ENDPOINT` | Configure as the endpoint address for the coal mining intranet object storage service | Stores uploaded original document scans and generated official documents, complies with enterprise intranet data storage specifications |
| `FE_DOMAIN` | Configure as the coal mining intranet access domain name | Restricts front-end access to the enterprise intranet only, prevents unauthorized external access |

## Three Common Mistakes
- Issue: The OneApi page fails to load after deployment, and the console returns a 404 status code. Cause: The `FE_DOMAIN` parameter is not configured correctly, or the front-end static resource deployment path does not match the configuration, resulting in failure to properly load page resources.
- Issue: Multiple accounts cannot be created, or team shared login fails, making it impossible to enable knowledge base sharing across multiple accounts within the same team. Cause: The `PG_URL` is not configured correctly to connect to a multi-tenant supported database instance, or database permission configuration does not open associated permissions for team accounts.
- Issue: Generated document content does not match the format of the original coal mining documents, and professional fields or units are missing. Cause: The fixed field format of coal mining documents is not retained during the data preprocessing stage, or unit information of professional parameters is not retained during knowledge base embedding, resulting in generated documents failing to meet industry specifications.

## How to Confirm the Configuration is Correct
- Run the database connection test script to verify that the configurations for `DB_MAX_LINK`, `MONGODB_URI`, `PG_URL`, and `REDIS_URL` can establish normal connections, and that the number of connections does not exceed the preset maximum connection limit.
- Upload an original coal mining production daily report, check that the file can be properly parsed and stored in the configured object storage service, and verify that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Access the configured `FE_DOMAIN` address, confirm that the front-end page loads normally, with no prompts for failed resource loading.
- Create test accounts and add them to the same team, verify that multi-account login and team sharing functions are enabled normally.
