# Document and Material Drafting for Power Grid Enterprises: HTTP Interfaces and External Systems

## What this category of data looks like
Data for document and material drafting for power grid enterprises mainly comes from internal production and operation, bidding, safety management and other business systems. There are three types of data update rhythms: daily maintenance records are updated in real time according to operation nodes, annual compliance reports are released annually, and bidding project documents are updated irregularly as projects progress. The document structure includes fields such as document number, issuing entity, effective date, main text content, attachment list, etc. Some professional documents are attached with professional unit markings such as voltage level and equipment capacity.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Power grid enterprise document data is scattered across multiple internal business systems. Interfaces must adapt to the authentication rules of multiple systems, and the `Authorization` parameter must be compatible with token formats from different vendors. The update rhythms of different types of documents vary greatly, so interfaces must support flexible triggering mechanisms to adapt to both real-time pull and batch synchronization modes. Professional unit fields such as voltage level and equipment capacity attached to professional documents must retain their original format during interface transmission to avoid information deviation caused by unit conversion. Some documents contain binary attachments, so interfaces must support streaming transmission of multiple types of files.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `Authorization` | Carry a Bearer token compatible with internal systems, set with a 24-hour validity period | Adapt to the authentication specifications of internal power grid enterprise systems, avoid frequent token refreshes that affect interface stability |
| `variables` | Preset professional variables such as voltage level and equipment number, with values calibrated according to actual business ledgers | Simplify professional information entry during document drafting, ensure generated content complies with power grid industry standards |
| `responseData` | Only return three core fields: main text, document number, and issuing date, filter redundant business logs | Reduce interface transmission data volume, adapt to transmission efficiency in intranet scenarios with low bandwidth |
| Timeout period | 30–60 seconds | Cover processing duration for large bidding documents, avoid interface interruptions caused by network delays |
| Attachment upload size limit | 1000 MB | Adapt to upload requirements for large-volume attachments such as power grid enterprise maintenance reports and CAD drawings |

## Three Common Mistakes
- Phenomenon: The interface returns a 401 Unauthorized status code. Cause: The `Authorization` parameter does not carry a token format that meets internal system requirements, or the token has expired.
- Phenomenon: Uploading files fails when accessing via nginx reverse proxy in an intranet environment, and the chat box is unresponsive. Cause: nginx is not configured with a sufficient client request body size limit, which cannot carry large-volume document attachments of power grid enterprises.
- Phenomenon: When calling the knowledge base addition interface via `curl --location --request POST`, the returned fields are empty. Cause: The `variables` parameter is not correctly set to pass business context, causing the interface to fail to match the corresponding data template.

## How to Confirm Proper Configuration
- Execute the preset curl call command, check whether the returned `responseData` contains core document fields.
- Upload a large-volume test file in the intranet environment, confirm that there are no client request body size too large errors in nginx logs.
- Call the interface to trigger document generation, check whether the generated content contains the preset professional variable values.
- Use the FastGPT v4.17.0 system log query function to confirm that the `Authorization` parameter of the interface request is parsed normally.
