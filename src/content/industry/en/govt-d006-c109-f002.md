# Document and Material Drafting for Power Grid Enterprises: Vector Models and Indexes

## What Data Looks Like for This Category
The documents and materials of power grid enterprises mainly come from daily dispatch logs, equipment operation and maintenance records, safety operation regulations, bidding documents, and internal administrative notices. The data update rhythm varies by scenario: dispatch logs are updated daily, safety regulations are revised annually, and bidding documents are generated irregularly with projects. The document structure includes structured fields (such as equipment ID, voltage level unit kV, operation and maintenance duration unit hours) and unstructured text paragraphs. Some long documents can reach tens of thousands of characters per single piece.

## What Constraints These Characteristics Impose on Vector Models and Indexes
The structured fields and unit requirements of power grid enterprise documents require vector models to retain semantic associations between fields during encoding, and avoid matching deviations caused by loss of unit information. In scenarios with a high proportion of long documents, it is necessary to limit the length of individual text chunks to prevent exceeding the token limit of the vector model. For data sources with multiple update rhythms, a hybrid strategy of incremental indexing and full indexing is needed, distinguishing between frequently updated dispatch logs and infrequently updated safety regulations. Unstructured paragraph formats are inconsistent, so text formats must be unified before chunking to avoid redundant symbols interfering with vector encoding.

## How to Set the Configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Ensures semantic integrity for long power grid enterprise documents, avoids vector encoding deviations caused by broken single-chunk content |
| Overlap Length | 100–150 characters | Retains contextual association between adjacent chunks, prevents loss of cross-chunk semantics |
| `defaultToken` | 4096 token | Matches the default input limit of most open-source vector models, adapts to the chunking and encoding needs of routine power grid enterprise documents |
| `maxToken` | 8192 token | Reserves sufficient token space for complete vector encoding of ultra-long annual operation and maintenance summary documents |
| Similarity Threshold | 0.75–0.85 | Filters low-match irrelevant documents, adapts to the professional semantic matching accuracy required for power grid enterprise documents |
| Single Search Limit | Top 10 entries | Controls the number of returned results, avoids context overload that affects the accuracy of document drafting |

## Three Common Mistakes
- Phenomenon: After upgrading the FastGPT version, chunking fails for power grid document CSV files with the same configuration, and a parameter overrun error pops up on the interface. Cause: The new version optimizes the chunk length verification rules, and the original chunk length exceeds the new compliance range.
- Phenomenon: The knowledge base indexing task gets stuck for a long time, and incomplete datasets show an unindexed status. Cause: The `maxToken` configuration is not adjusted for power grid enterprise long documents, resulting in ultra-long operation and maintenance summary documents failing to complete vector encoding.
- Phenomenon: A large number of irrelevant administrative notices are mixed into the retrieved document materials, and the matching results do not meet the requirements of professional scenarios. Cause: The similarity threshold is set too low, failing to filter low-match content outside the professional domain.

## How to Confirm the Configuration Is Correct
- Upload a single typical long power grid document (such as an annual operation and maintenance summary), check whether the chunking results retain complete professional paragraphs without content breaks.
- Trigger a full indexing task, monitor the task progress, and confirm that no nodes get stuck for a long time.
- Enter a professional search term (such as "110kV substation operation regulations"), verify whether the matching degree of the returned results meets the expectations of the professional scenario.
- Check the vector model encoding logs, confirm that the unit information of structured fields is not lost, and the vector encoding semantics are consistent.
