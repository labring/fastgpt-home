# Document and Material Drafting for Power Grid Enterprises: Citation Source and Traceability

## What this category of data looks like
Power grid enterprise document and material data mainly comes from business links including production scheduling, operation and maintenance, marketing accounting, and bidding and tendering. It includes types such as scheduling logs, maintenance reports, electricity accounting sheets, and equipment ledgers.
Update frequency follows business nodes: maintenance documents are updated immediately after job completion, while monthly report documents are updated monthly.
Each single document usually contains structured fields and unstructured body text. Structured fields include equipment number, operation time, safety measure items, and corresponding units such as kilovolts, megawatt-hours, and person-times. The body text mostly consists of standardized descriptions spanning thousands of characters.

## Constraints Imposed on Citation Source and Traceability
The standardized structured fields and units for power grid documents require accurate matching of field names and corresponding units during traceability to avoid ambiguity.
Multi-node updated documents require prioritizing the latest version of document content for citation traceability, to ensure the timeliness of cited information.
The long length of single documents requires filtering core citation fragments during context processing, to avoid exceeding the large model's context capacity limit.
Additionally, clearly classified business documents require limiting the citation scope to the dataset for the corresponding business scenario, to avoid irrelevant data interfering with traceability results.

| `quoteMaxToken` | 8000–12000 token | The body of a single power grid enterprise document is typically 3000–8000 characters, requiring coverage of sufficient citation fragments |
| `responseData` | Structured format with metadata | Core traceability fields such as document equipment number and operation time must be retained |
| `detail` | Full details | Both structured fields and body content of power grid documents are required for traceability verification |
| Single citation limit | Top 8 entries | Adapts to the conventional number of retrieval results for power grid business documents |
| Context timeout | 60 seconds | Calibrated via actual testing, adapts to retrieval and recall time for power grid documents |

## Three Common Misconfigurations
- Setting `quoteMaxToken` to 3000 results in generated output without attached knowledge base context fragments. The parameter configuration exceeds the system default threshold, blocking the context loading process.
- Garbled text appears after uploading CSV-format power grid document files. Power grid business CSV files typically use GBK encoding; the default UTF-8 encoding causes parsing errors.
- Configuring the response data format as plain text prevents retrieval of structured document field information. The metadata return switch is not enabled, so structured fields are not included in the response content.

## How to Verify Successful Configuration
- Initiate a power grid document drafting test, check if the generated output includes the source document name, field information, and update time at the end.
- View the FastGPT knowledge base retrieval log to confirm the number of returned citation fragments matches the configured single citation limit.
- Upload a test power grid document CSV file, confirm no garbled text appears after parsing and all fields are fully displayed.
- When calling the API interface, check if the returned `responseData` field includes the expected metadata information.

The values listed are common starting points, and should be evaluated against the user's own samples.
