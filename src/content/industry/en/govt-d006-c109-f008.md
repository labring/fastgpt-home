# Document Drafting for Power Grid Enterprises: Document Parsing and Chunking

## What This Category of Data Looks Like
Documents and materials for power grid enterprises cover operation and maintenance logs, safety regulations, bidding documents, monthly work summaries, and annual reports. Daily operation and maintenance logs are updated in real time. Monthly reports are generated and updated each month. Annual summaries are released annually. Document structures include two categories: official documents with fixed templates (with headers, footers, and official letterhead markings), and unstructured on-site inspection records (including tables and handwritten annotations). Fields include equipment number, voltage level, inspection time, defect level, and more. Units include kilovolt, ampere, hour, number of inspections, and more.

## Constraints Imposed on the "Document Parsing and Chunking" Step
The fixed format of power grid official documents requires that chunking must not damage headers, footers, official letterhead, or other markings. Otherwise, semantic association will break during subsequent retrieval. For tables and professional fields in unstructured inspection records, parsing tools must accurately identify table structures and field associations. This avoids losing the binding relationship between equipment numbers and corresponding defect information after chunking. Large annual summaries and bidding documents may exceed default upload and parsing limits. In LAN deployment scenarios, parsing services must not rely on external network resources, and must adapt to intranet access and parsing requirements.

## How to Configure Settings
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Power grid documents contain many professional terms and fixed fields. Chunks that are too long lose field associations. Chunks that are too short damage semantic integrity. This value is calibrated based on the average length of power grid documents. |
| `chunkSplitter` | Split by paragraph + header and footer | Power grid official documents have fixed header markings. Splitting by paragraph preserves the semantic unit of each individual document, and avoids damaging official document formatting during chunking. |
| `customPdfParse` | Enabled | Most power grid documents are PDFs with tables and seals. Enabling custom parsing accurately extracts table content and professional fields, and avoids missing key information such as equipment numbers. |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Power grid annual summaries and large bidding documents have large file sizes. This setting adapts to large file upload requirements, and is calibrated based on the maximum measured size of power grid documents. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large power grid documents takes a long time. The default timeout is insufficient to complete parsing. This value is adjusted based on measured parsing time for large documents. |
| `chunkSettingMode` | Manual mode | Adjusting chunking rules is required for different types of power grid documents: inspection records, official documents, and reports. Manual mode allows flexible parameter configuration. |

## Three Common Misconfigurations
- Symptom: A `net::ERR_INCOMP` error occurs when other devices on the local area network (LAN) access the FastGPT service, and the login page fails to load. Cause: The service is only bound to the local loopback address, and access permissions for the LAN segment are not enabled. External LAN devices cannot establish a connection.
- Symptom: Parsing fails when uploading large power grid documents, with a prompt that chunking exceeds limits. Cause: Matching parameters for `UPLOAD_FILE_MAX_SIZE` and `chunkSize` have not been adjusted. The default configuration cannot adapt to the chunking requirements of large power grid documents.
- Symptom: An empty result is returned when calling the API to obtain chunk index content. Cause: The manual configuration mode for `chunkSettingMode` has not been enabled. Chunk indexes are not generated according to the field rules of power grid documents, making them unreadable by the API.

## How to Verify Proper Configuration
- Upload a standard power grid operation and maintenance report, check the parsed chunk results, and confirm that professional fields such as equipment number and voltage level are not damaged during chunking.
- Call the API to test the chunk index acquisition function, and confirm that the returned chunk content contains key professional information from the document.
- Access the FastGPT service from another device on the LAN, confirm that the login page loads normally, and no connection errors occur.
- Upload the maximum size power grid document, confirm that the parsing process does not trigger a timeout error, and that the chunk results are complete.

The values provided here are common starting points, and should be evaluated against the samples from the respective deployments.
