# Document and Material Drafting for Mineral Mining and Beneficiation: HTTP Interfaces and External Systems

## What this category of data looks like
Mineral mining and beneficiation document and material drafting involves multiple types of internal documents. Data mainly comes from mining operation daily reports, mineral processing flow records, safety compliance ledgers, procurement and settlement contracts. Data update frequencies fall into three categories: operation daily reports updated daily, monthly settlement reports updated monthly, and annual compliance documents updated annually. Each single document includes four parts: project identifier, operation parameters, approval process, and attachments. Unique fields include mine number, mineral processing batch number, operation volume (unit: ton), ore grade (unit: %). Some documents include on-site inspection photos as binary attachments.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
The varied update frequencies of mineral mining and beneficiation documents require the interface to support both scheduled synchronization and real-time triggering modes, to avoid data lag caused by mismatched synchronization frequencies. There are many unique fields with unit differences, so interface parameters must strictly match the field names and units of the internal system. Otherwise, the internal system cannot correctly parse requests. Each single document may include binary attachments, so the interface must support multipart form data transmission. Operation data has high real-time requirements, so the interface timeout setting must adapt to the time consumed by multi-link data pulling, to avoid interrupting the request process due to timeout.

## How to Configure the Setup
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {internal enterprise API key}` | Adapts to the enterprise-level authentication rules of the mineral mining and beneficiation system, to avoid unauthorized access to internal data |
| `variables` | Include fields for mine number, operation batch, and grade threshold; parameter length 800–1200 characters | Matches the core required fields of mineral mining and beneficiation documents, to ensure the internal system correctly receives request parameters |
| `responseData` | Only extract fields for approval status, generated document ID, and synchronization timestamp | Reduces interface transmission load, focusing on core status information for document circulation |
| Request timeout | 600 seconds | Mineral mining and beneficiation document generation involves multi-link data pulling, to avoid request interruptions caused by short timeouts |
| Number of documents per request | First 3 entries | Avoids exceeding interface transmission limits with a single request, adapting to batch document synchronization needs |

## Three Common Misconfigurations
- Phenomenon: HTTP request returns `Host 'xxx.xxx.xxx.xxx' is not allowed to connect` error. Cause: The internal IP of the mineral mining and beneficiation system was not added to the FastGPT interface whitelist, resulting in authentication failure.
- Phenomenon: HTTP request does not execute after configuration, with no return results. Cause: The `variables` parameter does not include required fields such as mine number or operation batch, so the internal system cannot match the corresponding operation data for the request.
- Phenomenon: Generated documents are inconsistent with internal system data. Cause: `responseData` does not correctly map the fields of the internal system, resulting in returned data not being properly parsed and synchronized.

## How to Verify Successful Configuration
- Call the FastGPT test interface, pass preset mineral mining and beneficiation document parameters, and check if the returned `responseData` includes preset fields such as approval status and document ID.
- Simulate submission of the `variables` parameter, check if the internal mineral mining and beneficiation system can normally receive and generate the corresponding operation report.
- View the FastGPT interface logs, confirm that the request status code is 200, with no timeout or authentication error records.
- Generate a test monthly settlement report for mineral mining and beneficiation, confirm that the document synchronized by the external system matches the content generated by FastGPT.
