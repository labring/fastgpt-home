# Document and Material Drafting for Mineral Mining and Beneficiation: Citation Source and Traceability

## What This Category of Data Looks Like
Core data for mineral mining and beneficiation includes geological exploration reports, mining plan documents, beneficiation process parameter tables, safety inspection records, beneficiation indicator reports, and more. Data sources cover multiple roles including exploration departments, production teams, and safety management positions. Update frequencies are split into periodic (e.g., geological exploration reports updated quarterly) and daily (e.g., inspection records updated daily, beneficiation indicators generated per shift). The document structure mixes structured reports and unstructured long text, with fields such as ore grade (unit: %, g/t), stripping and mining volume (unit: tons), beneficiation recovery rate (unit: %), and other professional content.

## What Constraints Do These Characteristics Impose on the Citation Source and Traceability Link
Mixed structured and unstructured document types require the traceability process to match both text semantics and structured field information, avoiding deviations caused by relying solely on keyword recall. Multi-source data with varying update frequencies requires distinguishing update trigger conditions for different data sources when configuring incremental synchronization rules, to ensure the timeliness of traceability data. Professional fields carry specific units, so unit information must be retained during traceability; otherwise, professional matching will fail. Long process description paragraphs in long documents require that professional term combinations not be split arbitrarily during chunking, otherwise context association will be lost.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the length of professional paragraphs for mineral mining and beneficiation, avoiding splitting process descriptions or professional terms |
| Reranking | Enabled, retrieve top 3 results | Filters low-match recall results, focusing on core production data |
| Maximum Context | 6000 characters | Accommodates retrieval content from multi-source production reports and exploration reports |
| `detail` | Full | Retains fields, units, and update times of source documents to ensure traceability accuracy |
| `responseData` | Include source path, field names | Meets compliant archiving requirements for mineral mining and beneficiation documents |

## Three Common Misconfigurations
- Phenomenon: The beneficiation indicator data returned by retrieval is unrelated to the queried mining plan, and the number of results exceeds the set limit. Cause: The reranking function is not enabled, or the number of retrieved entries for reranking is set too large, resulting in low-match data being recalled.
- Phenomenon: The cited source fields in the generated document lack unit information. Cause: The `detail` full mode is not enabled, and only text content is recalled without carrying professional fields and units.
- Phenomenon: The cited paragraph in the generated document is truncated, losing core process descriptions. Cause: The `quoteMaxToken` setting is too small, splitting complete paragraphs containing professional terms.

## How to Confirm the Configuration Is Correct
- Import a beneficiation report and geological exploration report for mineral mining and beneficiation, initiate a query containing professional terms, and check whether the returned results include the file name and field information of the source documents.
- Review the cited fragments in the generated document to confirm that the length of the untruncated professional description meets expectations.
- Simulate updating an inspection record, trigger knowledge base synchronization, and check whether the updated timestamp is included during traceability.
- Adjust the `quoteMaxToken` value to verify whether the length of the cited paragraph in the generated content changes accordingly.
