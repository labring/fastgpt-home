# Grain Reserve Document and Material Drafting: Citation Source and Traceability

## What Data for This Category Looks Like
Grain reserve-related data mainly comes from daily inbound and outbound ledgers, rotation plan documents, quality inspection reports, inventory check reports, and special audit records. The data update schedule is as follows: inbound and outbound operations update ledgers in real time, monthly inventory updates summary reports, and quarterly/annual special reports are updated per established plans. Document structure includes fields such as batch number, storage bin number, quality inspection indicators (moisture content, impurity rate), inbound and outbound quantity, and operation date. Common units are tons, percentage, and calendar days.

## What Constraints These Characteristics Bring to the Citation Source and Traceability Process
Grain reserve data has strong field correlation. Citation and traceability require precise matching of core identifiers such as batch number and bin number, otherwise original records cannot be accurately located. Data update frequency is high, so knowledge bases must be refreshed regularly to avoid referencing outdated inventory or quality inspection information. The core information length of a single document is relatively long. When drafting documents, complete key quality inspection and inbound and outbound data must be retained, so there are clear requirements for citation token limits. At the same time, document drafting often requires integrating multiple related documents, so retrieval results must cover enough related entries.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Core fields of grain reserve documents are mostly short paragraphs. This length preserves key associated information such as batch number and bin number |
| Overlap Length | 100–200 characters | Prevents core information such as cross-chunk batch numbers and operation dates from being truncated, ensuring complete association during traceability |
| Single Search Limit | Top 10 results | There are many reserve data entries. Excessive results will exceed the context window. Prioritize returning highly matched core records |
| Reranking | Enabled | Prioritizes matching core retrieval conditions such as batch number and storage bin number, improving the accuracy of citation sources |
| Maximum Context | 8000–10000 tokens | Document drafting requires integrating multiple related reserve records. This window covers common integration needs |
| `quoteMaxToken` | 1500–2000 tokens | The core information length of a single reserve document mostly falls within this range, allowing complete retention of key quality inspection and inbound and outbound data |

## Three Common Mistakes
- Phenomenon: After setting `quoteMaxToken` to 1500, document chunks longer than 1500 characters in the knowledge base are still cited. Cause: Forced chunk truncation is not enabled. The system only truncates according to the global context limit, and does not separately limit the token length of a single citation.
- Phenomenon: Matching reserve data is retrieved, but the citation source is not displayed in the conversation interface, only an empty citation field is returned. Cause: The metadata return switch in the `responseData` configuration is not enabled, so the retrieval result does not carry document identification information.
- Phenomenon: After retrieval results are passed into an HTTP request in a workflow, AI conversations cannot correctly associate citations. Cause: Structured data containing batch number, storage bin number, and document title is not returned as required, so the AI cannot match traceability information.

## How to Confirm Configuration Is Correct
- Upload a standard grain reserve inbound ledger document, set the chunk length to 1000 characters, and check whether the chunked results split long paragraphs into blocks that meet the length requirement.
- Initiate a query containing "2024 Q1 XX Grain Depot Rotation Plan", and verify that the returned citation sources include core metadata such as grain depot number and rotation batch.
- Set the single search limit to 8, initiate a multi-condition retrieval, and check whether the number of returned citation entries does not exceed 8.
- In FastGPT v4.17.0, check the "Citation Settings" module of the knowledge base, confirm that the `detail` configuration is enabled, to ensure that the returned citation information includes complete document paths and metadata.

The values provided are common starting points and should be evaluated against the reader's own samples.
