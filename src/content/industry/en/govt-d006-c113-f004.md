# Document and Material Drafting for Shipbuilding: Workflow Orchestration
## What the Data for This Category Looks Like
Document and material drafting data for shipbuilding mainly comes from hull section design drawings, construction process specifications, classification society compliance standards, equipment factory certificates, section inspection reports, and similar sources. Data is updated per construction milestone. New documents are generated after key milestones such as section joining, launching and sea trials. Most documents are structured text with chapter hierarchies, containing fields including classification society number, section number, process ID, material grade, inspection date, and others. Units involve professional maritime units such as millimeters, tons, hours, and knots.

## What Constraints These Characteristics Impose on Workflow Orchestration
Shipbuilding documents are categorized and updated based on construction milestones. Workflows must be bound to corresponding milestones to avoid calling expired documents. There are many structured fields with fixed units, so workflows must perform format and unit validation on incoming field parameters to prevent generating documents that do not meet maritime standards. Different processes correspond to different compliance documents and process data, so workflows must associate exclusive knowledge bases based on process type to ensure content calls accurately match current process requirements. Large design drawings and compliance documents have significant file size, so workflows must reserve sufficient processing time to avoid timeout interruptions.

## Configuration Specifications
This configuration follows the workflow function specifications of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `variables` | Bind fields such as section number, classification society number, process ID | Shipbuilding documents require precise matching of corresponding documents by project and process |
| `nodeId` | Assign a unique ID per construction milestone, associate with corresponding knowledge base | Process and compliance requirements vary significantly across different construction milestones |
| Knowledge Base Selection | Associate exclusive knowledge bases based on process type | Different processes require calls to different process specifications and compliance documents |
| Variable Validation Rules | Validate material grade, inspection date format and units | Ship document fields must comply with fixed format requirements of the maritime industry |
| Chunk Length | 800–1200 characters | Adapt to the paragraph length of ship documents and improve retrieval accuracy |
| Timeout Setting | 600 seconds | Processing large ship documents requires a long duration to avoid mid-process interruptions |

## Three Common Errors
- Workflow calls to the database return errors when passing the `variables` parameter, while manual SQL execution works normally. The cause is that unit validation is not added for fields in `variables`, causing the incoming material grade to carry invalid characters that cannot be correctly recognized by the database.
- Unable to select a knowledge base in real time during conversations. The cause is that dynamic knowledge base trigger rules associated with `nodeId` are not configured, and the node is fixedly bound to a single knowledge base, making it impossible to switch based on conversation context.
- Workflow nodes execute timeout and become unresponsive. The cause is that the timeout setting value is less than 300 seconds, which does not match the processing duration of large ship documents, causing a timeout to be triggered before the document is fully loaded.

## How to Confirm Proper Configuration
- Manually trigger the workflow for the corresponding construction milestone, check whether knowledge base documents matching that milestone are automatically called.
- Pass `variables` parameters that include valid units, check whether the tool call successfully returns matching process or compliance content.
- View the workflow operation log, confirm that `nodeId` matches the current construction milestone configuration with no binding errors.
- Simulate a large document processing scenario, check whether the workflow completes processing within 600 seconds without triggering a timeout error.
