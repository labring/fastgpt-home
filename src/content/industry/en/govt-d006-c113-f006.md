# Document and Material Drafting for Shipbuilding: Citation Sourcing and Traceability

## What the Data for This Category Looks Like
Core data for shipbuilding document and material drafting comes from technical specification documents for hull structures, marine engineering systems, and electrical systems, block construction process records, inspection reports, and general compliance documents.
Data is updated per individual shipbuilding project or in monthly batches. A single document typically includes fields such as hull type number, block number, material grade, specification parameters, inspection batch, inspection date, and more. Units are standard engineering units like millimeters, tons, and hours.
Document structures are split into submodules for three construction phases: design, construction, and inspection, based on project milestones.

## Constraints Imposed by These Characteristics on Citation Sourcing and Traceability
Professional shipbuilding data is updated per project milestone and has high field specificity. Citation traceability must be tied to the exclusive knowledge base of the corresponding shipbuilding project to avoid mismatched material parameter citations across projects.
Document structures are split by construction phase. When citing, the association between key fields such as block number and material grade must be retained to prevent breaks in traceability information.
Compliance documents undergo version iterations. When tracing, the specification version number must also be marked to ensure cited content meets compliance requirements for the current shipbuilding phase.
Single documents are lengthy. Citation context length must be limited to avoid exceeding model processing limits.

## Three Common Misconfigurations
- Phenomenon: When configuring a knowledge base ID citation variable, directly filling in the variable value produces consistent results, but binding the variable to the knowledge base configuration item triggers an error. Cause: The association verification between knowledge base permissions and variables was not completed in the application configuration, so the variable cannot be correctly mapped to the knowledge base of the target shipbuilding project.
- Phenomenon: Mixed retrieval returns citation content that includes documents from non-current shipbuilding phases, and irrelevant data cannot be filtered. Cause: No field filtering rules based on construction milestones were set, so the retrieval scope covers all project documents, and the exclusive identifier of the current shipbuilding block was not bound.
- Phenomenon: Key fields such as material grade or inspection batch are missing from the citation traceability information in the generated shipbuilding documents. Cause: The `quoteMaxToken` value is set too small, so document chunks containing core fields cannot be fully loaded, leading to truncated traceability information.

## How to Confirm the Configuration Is Complete
- Generate a material drafting document for a hull block, check whether the cited content includes the exclusive hull type number and block number of the current project.
- Review the display format of traceability information, confirm that the `detail` configuration is enabled to display document chapters and update times.
- Test adjusting the `quoteMaxToken` value, observe whether the completeness of cited content meets the requirements of shipbuilding documents.
- Trigger mixed retrieval, check that returned citations only include documents related to the current shipbuilding project, with no cross-project redundant content.
