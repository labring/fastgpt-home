# Document and Material Drafting for Rail Transit Equipment: Deployment and Upgrade

## What the data for this category looks like
Data for rail transit equipment document and material drafting comes primarily from internal enterprise sources: design drawings, process specifications, inspection reports, bidding documents, and operation and maintenance manuals.
Data updates align with new vehicle model development, quarterly process iterations, and annual compliance reviews.
Document structures include standardized fields: equipment model, drawing number, material grade, tolerance parameters, and inspection batch.
Supported units include millimeters (mm), megapascals (MPa), kilometers per hour (km/h), and others.
Single document length ranges from hundreds of characters for inspection records to tens of thousands of characters for full vehicle design descriptions.

## What constraints these characteristics impose during deployment and upgrade
Specialized fields and multi-source data for rail transit equipment require adaptations during FastGPT v4.17.0 deployment. These adaptations support multi-format document parsing and specialized terminology vector mapping, to avoid mismatches in professional parameter matching.
Frequent incremental update demands require configuration of an incremental synchronization scheduling mechanism during upgrades. This prevents full updates from consuming excessive system resources.
The high share of long document files creates requirements for vector database storage capacity and recall efficiency.
Permission differences across job roles require pre-configuration of layered access rules during deployment. This prevents leakage of core design documents.

## Three common mistakes
- Phenomenon: Regular employee accounts can view unauthorized full vehicle design documents, and permission control fails. Cause: Layered access rules are not configured for different job roles, only the global default permission configuration is used.
- Phenomenon: PDF drawing documents for rail transit equipment cannot be loaded after deployment, and the interface displays file parsing failure. Cause: The `STORAGE_S3_ENDPOINT` parameter is not correctly configured, and the internal enterprise object storage service is not connected, resulting in failure to properly read documents.
- Phenomenon: Calling the qwen-max model in the corresponding deployment environment returns an API key invalid error. Cause: The Alibaba Cloud API key is not correctly filled in the corresponding model configuration item, or the key has not been granted large model call permissions.

## How to confirm the configuration is complete
- Log in to test accounts with different permission levels, verify that only document files within the corresponding job role's permissions can be accessed.
- Upload an inspection report document for rail transit equipment, trigger the document drafting process, confirm that the parsing result includes specialized fields such as equipment model and material grade.
- View the database connection monitoring panel, confirm that the current connection count does not exceed the `DB_MAX_LINK` configuration value.
- Restart the deployment service, verify that the document drafting tool's access domain name `FE_DOMAIN` loads normally without errors.
