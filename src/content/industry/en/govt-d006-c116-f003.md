# Document and Material Drafting for Telecommunications Engineering Construction: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The data used for document and material drafting in telecommunications engineering construction comes primarily from official deliverable documents including project approval documents, construction drawing designs, supervision weekly reports, and completion acceptance reports. Data is updated per project implementation phases: basic project information is synchronized after approval, weekly progress reports update engineering quantities during the construction stage, and final acceptance standards are synchronized during the acceptance phase. Document structures include a project basic information section, engineering quantity list section, material parameter section, construction procedure section, and acceptance standard section. Fields include project number, optical fiber core count, base station height, port count, and others. Common units are engineering-specific ones such as meters, kilometers, ports, and sets.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Lengthy telecommunications engineering drafting documents contain many specialized parameters. Multi-turn dialogue context can easily exceed the model’s processing limit. Strictly limit the range of retained historical dialogue.
The unique nature of specialized fields and units requires prompts to explicitly bind project-specific data, preventing the model from confusing parameters across different projects.
Follow phase-based data update rules: prioritize calling the latest project data bound to the current session during multi-turn dialogue, to ensure valid current project information is used.
Complex document structures require prompts to split tasks. First confirm basic project information before processing specific drafting content, to avoid generated results deviating from actual project needs.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 characters | Single telecommunications engineering documents often exceed 5000 characters; retaining sufficient context avoids truncating critical parameters |
| Number of multi-turn dialogue history entries to retain | First 8 entries | Covers key dialogues for project requirement changes, while avoiding excessive historical content occupying model resources |
| `variables` binding | Bind project-specific project number and material specification fields | Ensure prompts accurately match the dedicated data of the current project when called |
| `chatId` session binding | Bind the unique session identifier of the current project | Ensure multi-turn dialogue context is only associated with the current project, avoiding cross-project data confusion |
| Prompt optimization | Enabled | Automatically convert colloquial engineering requirements from users into standardized document formats |
| Maximum response timeout | 120 seconds | Complex document generation requires sufficient time to process engineering quantity calculations and format adjustments |

## Three Common Misconfigurations
- Phenomenon: The supporting equipment topology diagram in the generated engineering material list is incomplete, only showing a partial view. Cause: The prompt fails to explicitly require embedding complete resource reference paths, or the context of image placeholders is not retained during multi-turn dialogue.
- Phenomenon: After upgrading to FastGPT v4.17.0, rule traceability display symbols appear at the end of dialogue response results. Cause: The instruction to turn off default rule display is not configured in the system prompt.
- Phenomenon: Response delay occurs after initiating more than 3 consecutive document generation requests. Cause: The concurrent request limit for a single session is not set, causing resource usage to exceed the system's carrying capacity.

## How to Verify Correct Configuration
- Initiate a test dialogue that includes the project number and specified material specifications, and check whether the returned results accurately match the content of the bound `variables` fields.
- Initiate consecutive multi-turn dialogues, and check whether the `messages` field loads historical conversations according to the set retention limit, with no redundant content.
- Generate a complete engineering acceptance report, and check whether unexpected rule display symbols appear at the end of the result.
- Test document generation requests of different complexity levels, and confirm that the response time meets the expected requirements of the business scenario.

The values provided are common starting points and should be measured against the reader's own samples.
