# Document and Material Drafting for Telecommunications Engineering Construction: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The document data for telecommunications engineering construction primarily originates from industry telecommunications engineering construction specifications, project approval documents, construction organization designs, material submission forms, completion acceptance reports, and similar materials. Data is updated in sync with annual industry standard revisions and special documents for new construction projects. Documents include fixed fields such as project number, budget amount (unit: ten thousand yuan), construction period (unit: days), equipment model, and more. There are both hundreds-page long construction plan documents and single-page approval forms.

## Constraints on Knowledge Base Retrieval and Recall
A high proportion of telecommunications engineering construction documents are long-form. Retrieval must avoid semantic breaks between chunks, and requires chunking logic tailored for long documents. Documents contain specialized fields with specific units. Retrieval must retain unit associations to prevent matching content with mismatched parameters. Data is scattered across industry standard libraries and project-specific libraries. Datasets must be divided by document type to avoid invalid cross-library recall. Project documents are updated dynamically alongside construction progress. Vector databases must be synchronized regularly to prevent retrieval of outdated construction specifications or budget standards.

## Configuration Settings

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Telecommunications engineering has dense specialized terminology, requiring filtering of low-match irrelevant content |
| `limit` | Top 8–12 results | Avoid excessive recall results exceeding the context window, which impacts generation efficiency |
| `searchMode` | Semantic retrieval | Higher matching accuracy for specialized terminology, aligns with actual usage feedback |
| `usingReRank` | Enabled | Reorder chunked document fragments to optimize the relevance of recalled segments |
| `datasetSearchUsingExtensionQuery` | Disabled | Specialized terminology does not require additional expansion, avoiding introduction of non-target industry expressions |
| `collectionIds` | ID sets divided by document type | Distinguish between industry standard libraries and project-specific libraries to prevent invalid cross-library recall |

## Three Common Misconfigurations
- Symptom: Some questions in conversations do not trigger knowledge base retrieval, and responses are generated solely based on the base large model. Cause: `collectionIds` is not configured to bind the corresponding dataset, or the trigger rule is not associated with the exclusive document type for telecommunications engineering.
- Symptom: After consecutive questions in the same conversation window, retrieval latency increases significantly, with some retrievals timing out after more than 1 minute. Cause: Vector recall cache from historical context is not cleared, causing each retrieval to load the full dataset.
- Symptom: When using hybrid retrieval mode, results include non-telecommunications engineering specialized expressions, with matching accuracy lower than semantic retrieval. Cause: `datasetSearchUsingExtensionQuery` is enabled, and the additionally expanded expressions do not match telecommunications engineering specialized terminology.

## How to Verify Correct Configuration
- Submit a question containing telecommunications engineering specialized terminology, and check if the retrieval results include fragments from the corresponding documents.
- View retrieval logs to confirm that the number of recalled results matches the `limit` setting.
- Switch between different search modes and compare the professional matching accuracy of returned results.
- After binding multiple datasets, verify that only recall from the target datasets is triggered.
