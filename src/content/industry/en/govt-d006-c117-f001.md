# Document and Material Drafting for Communication Towers and Infrastructure: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data primarily comes from operation and maintenance management systems, asset ledger platforms, and on-site inspection terminals. There are two update rhythm categories: basic asset information is synchronized every quarter, while inspection and hidden danger data is updated daily. The document structure includes fields for tower unique identifier, installation location, tower height, operation and maintenance cycle, and hidden danger level. Units include meters, degrees Celsius, and percentage. Some fields are associated with third-party surveying and mapping longitude and latitude data.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
The difference in update rhythms between basic asset information and inspection data requires distinguishing scheduled trigger periods in HTTP request configuration. Basic information synchronization uses a 6-hour trigger interval. Inspection data uses a 15-minute trigger interval. Fields associated with third-party surveying and mapping longitude and latitude data require carrying the tower unique identifier in `variables` as a query parameter to avoid cross-data source matching errors. Fields include specific units, requiring the interface to return data with original unit fields to avoid document content errors caused by format conversion deviations. Data sensitivity requires configuring `Authorization` authentication for requests to prevent unauthorized access to confidential operation and maintenance data.

## How to Configure
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---- | ---- | ---- |
| `Authorization` | Use a fixed Bearer Token format, with the value being the authentication key for the communication operation and maintenance system assigned by the platform | Match the authentication rules of third-party operation and maintenance systems to ensure the legality of interface calls |
| `variables` | Carry `Tower ID` and `Inspection Cycle` parameters. The value range for Tower ID is 100000-999999. Set Inspection Cycle to `15 minutes` | Accurately locate operation and maintenance data for a single tower, matching the query logic of the data source |
| `responseData` | Only retain the `Tower ID`, `Hidden Danger Level`, and `Maintenance Record` fields | Filter redundant data to reduce information processing volume during document drafting |
| Request Timeout | 600 seconds | Adapt to the batch data return delay of third-party systems to avoid request interruptions |
| Retry Count | 3 times | Respond to request failures caused by temporary network fluctuations |
| Trigger Rules | Scheduled trigger daily or hourly | Match the update rhythms of asset and inspection data |

## Three Common Configuration Mistakes
- Phenomenon: After the conditional judgment component processes a boolean-type parameter parsed from HTTP, the parameter becomes a null value. Cause: The type conversion rule for `responseData` is not configured in the HTTP component, causing the boolean value to be incorrectly parsed as a string. The conditional judgment component cannot recognize the non-standard format boolean value.
- Phenomenon: Calling the third-party operation and maintenance interface returns a `getaddrinfo ENOTFOUND` error, accompanied by a 406 status code. Cause: The Tower ID parameter carried in `variables` is not correctly spliced into the request URL, resulting in domain name resolution failure. The request header does not match the content type requirements of the third-party system.
- Phenomenon: The uploaded file relative path carries a token parameter, causing the external service to fail to read the file normally. Cause: The token parameter in the path is not stripped in the HTTP component. The full path containing authentication information is directly passed, exceeding the path reading permission range of the external service.

## How to Verify Correct Configuration
- View the HTTP component request logs in FastGPT v4.17.0, confirm that the `Authorization` authentication header is correctly carried, and the `variables` parameters are passed according to the configured rules.
- Call the test interface, check whether the fields returned by `responseData` only include the preset necessary fields with no redundant information.
- Simulate a scheduled trigger request, confirm that the request cycle matches the update rhythms of asset and inspection data.
- Pass a test Tower ID parameter, check whether the third-party system returns the corresponding data content.
