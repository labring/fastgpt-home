# Document and Material Drafting for Communication Towers and Infrastructure: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category primarily comes from communication tower operation and maintenance management systems, base station inspection reports, project approval documents, site lease agreements, and similar sources. Basic ledger data is updated monthly. Inspection records are updated per individual inspection cycle. Most documents combine structured tables with unstructured notes. Core fields include tower type, installation height, latitude and longitude coordinates, operation and maintenance level, lease term, and inspection frequency. Units include meters, square meters, years, times, and similar units.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
The differences between structured fields and multi-source update rhythms require multi-turn dialogue to clearly distinguish boundaries between structured parameter extraction and unstructured content generation. For professional fields such as latitude and longitude and height, units must be explicitly specified in prompts to avoid generating content that does not meet industry standards. Differences in update cycles across multiple data sources require dialogue to guide users to clearly specify the data time range, to avoid mixing ledgers and inspection records from different cycles. When introducing long document content, the effective length of the context window must be limited to prevent redundant information from interfering with core drafting tasks.

## Three Common Mistakes
- Phenomenon: Generated content cannot create a Word export download link at the bottom of the dialogue. Cause: The workflow's export node is not bound to the current session's `variables` parameter, so drafting content cannot be retrieved.
- Phenomenon: An API call prompts "No permission to operate this dialogue record". Cause: The session corresponding to `chatId` has no shared permission configured, or the caller did not carry the correct session identifier.
- Phenomenon: After upgrading to FastGPT v4.17.0, refreshing the dialogue page shows a new dialogue instead of existing records. Cause: `chatId` is not correctly bound to the session storage path, leading to failed session association.

## How to Confirm Successful Configuration
- Initiate a multi-turn dialogue that includes tower type and installation height, check if the generated document automatically associates with preset `variables` parameters.
- Manually modify `chatId` to initiate a new dialogue, confirm that the session record will not be confused with existing sessions.
- Trigger the workflow export function, check if the generated document includes all core fields confirmed in the dialogue.
- Send two different drafting requirements consecutively, confirm that sessions store dialogue content separately based on `chatId`.
