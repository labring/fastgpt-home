# Document and Material Drafting for Communication Towers and Infrastructure: Citation Source and Traceability

## What the data for this category looks like
Data sources for communication towers and infrastructure include communication operator tower asset management systems, daily inspection logs, project completion archives, and maintenance work orders. Update cadence follows this pattern: asset ledgers are updated quarterly, inspection reports are generated per individual inspection task, and completion archives are only updated after new construction or modification. Document structure primarily uses structured fields, including tower number, installation location (latitude and longitude), tower height (meters), load capacity (kilowatts), inspection date, maintenance responsible person, and more. Unstructured inspection record text and on-site photo descriptions are also included.

## What constraints these characteristics impose on the citation source and traceability link
The uniqueness requirement of structured fields means citations must match the tower number to avoid traceability errors. The length of unstructured inspection reports varies widely, with some single reports exceeding 2000 tokens, so the length of cited segments must be controlled. Differences in update frequencies require that retrieval prioritizes the latest ledger and inspection data. In multi-document association scenarios, the specific data source corresponding to each cited content must be clearly identified to avoid confusion between maintenance records of different towers.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `quoteMaxToken` | 1200–1800 tokens | Communication tower inspection report single-block matching content is around 1500 tokens, avoids truncating key parameters and maintenance records |
| `responseData` | Return only asset fields and source paths | Document drafting requires clear unique tower number and document storage location to meet traceability requirements |
| `detail` | Enabled | Specific maintenance content and time of inspection records must be displayed to support document compliance requirements |
| Single search limit | Top 6 retrieval results | Associated inspection records for a single tower document are no more than 5 at maximum, retain redundant space for multi-tower queries |
| Maximum context | 8000–10000 tokens | Includes associated fields and cited content from multiple tower documents, avoids context overflow causing generation interruptions |

Reference only; verify against the target FastGPT release and deployment documentation.

## Three common errors
- Phenomenon: The generated document does not include the address of the cited file. Cause: The path return switch for the `responseData` configuration item is not enabled, only text content is returned without associating the source storage path.
- Phenomenon: A 5000-token chunk is retrieved, but only 1500 tokens of cited content are finally displayed. Cause: `quoteMaxToken` is set to 1500 tokens, chunk content exceeding the threshold is automatically truncated, and complete matching core segments are not returned.
- Phenomenon: The generated document does not contain any citation traceability information. Cause: The `detail` configuration item is not enabled, or the tower asset ledger data source of the corresponding knowledge base is not associated, so associated fields and source identifiers cannot be extracted.

## How to confirm the configuration is active
A single tower asset number is input into the platform to generate a test document, and whether the corresponding tower parameters and source path are included is verified.
An inspection report exceeding 2000 tokens is uploaded, the length of the cited segment is checked after retrieval is triggered, and whether it matches the `quoteMaxToken` setting is confirmed.
The `responseData` configuration item is temporarily disabled, a test document is generated, and whether the source path is no longer displayed is verified to confirm the configuration takes effect.
`quoteMaxToken` is adjusted to 500 tokens, a test document is generated, and whether the cited segment is truncated is verified to confirm the parameter takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
