# Document and Material Drafting for Communication Towers and Infrastructure: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for this category originates primarily from infrastructure archive databases, daily operation and maintenance systems, design specification documents, and acceptance ledgers. Three update rhythms apply:
- Inspection logs sync and update daily
- Annual design specifications are revised quarterly
- Material lists update monthly alongside centralized procurement plans

Most documents use a mixed structure of structured paragraphs and tables. They include fields such as tower number, installation location, inspection date, hidden danger level, rectification plan, and material model. Common units follow general engineering standards, including meters, sets, kilograms, and square meters.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The mixed structured and tabular format of infrastructure archives and operation and maintenance data requires retrieval processes to preserve contextual associations between table rows and paragraphs. This avoids splitting key parameter-containing paragraphs.
Redundant duplicate data across multiple sources requires adding deduplication logic during the recall stage. This prevents multiple duplicate results for the same hidden danger.
Strict field and unit requirements mean retrieval matching must link to field attributes. This stops invalid results from unit mismatches.
Data sources with differing update rhythms require regular dataset refreshes. This syncs the latest inspection and specification content, ensuring retrieval results stay timely.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the field precision of communication tower inspection reports and design specifications. Avoid overly low values that produce invalid results, and overly high values that lead to insufficient recall. |
| `limit` | Top 8 entries | Balances context length and information coverage for document drafting. Prevents excessive content from exceeding the context window. |
| `usingReRank` | Enabled | For documents with mixed structures, re-ranking prioritizes returning rectification plans and material lists most relevant to drafting needs. |
| `datasetSearchUsingExtensionQuery` | Enabled | For precise fields such as tower numbers and locations, expand synonymous retrieval term expressions to improve matching coverage. |
| `collectionIds` | Bind specified infrastructure archive and operation log datasets | Limit the retrieval scope to avoid interference from irrelevant public service documents. |

## Three Common Configuration Errors
- Retrieval results only return a single matching entry, making it impossible to extract sufficient drafting reference information. Cause: `datasetSearchUsingExtensionQuery` is not enabled, and retrieval terms for precise fields such as tower numbers and locations are not expanded. This results in matching only exact identical issues, and fails to retrieve relevant associated documents.
- Retrieval results contain content with mismatched units, such as results that confuse "meters" and equivalent unit terms. Cause: Matching relies solely on text literal values without linking to field attributes. Unit fields are not standardized during processing.
- Document fragments returned during drafting have split table rows. Cause: Table context is not preserved during chunking. This splits key table parameters across different retrieval results.

## How to Confirm the Configuration Is Correct
- Manually enter a known tower inspection question, and check whether the number of returned results matches the configured `limit` setting.
- View the similarity scores of retrieval results to confirm they fall within the configured `similarity` range.
- Upload an inspection report containing tables, and confirm after retrieval that table rows are not split and contextual associations are complete.
- Compare retrieval results with and without `usingReRank` enabled, confirming that re-ranked results prioritize matching the current drafting document needs.
