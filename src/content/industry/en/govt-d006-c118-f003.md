# Document and Material Drafting for Metal Material Processing: Multi-turn Dialogue and Prompt Engineering
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category's data looks like
Document data for metal material processing mainly comes from internal enterprise process cards, quality inspection reports, procurement contract templates, and corresponding national standard and industry standard documents. The data update rhythm adjusts with production batches, and also syncs with national standard revisions. Each single document has a fixed structure, including fields such as material grade, yield strength, tensile strength, delivery condition, batch number, etc. Most units use general engineering units such as megapascals (MPa), millimeters (mm), tons (t).

## What constraints do these characteristics impose on the "multi-turn dialogue and prompt engineering" link
Documents for this category must comply with fixed field and engineering unit requirements. Therefore, multi-turn dialogue must continuously retain acquired parameter information to avoid repeated inquiries. Different types of documents (such as process cards and inspection reports) have obvious format differences, so prompts need to clearly distinguish scenarios. Data updates dynamically with production batches. Dialogue must allow users to add exclusive parameters for the latest batches, and verify the consistency between parameter units and fields to prevent errors where values do not match their units.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `variables` | Include three custom variables: material grade, yield strength, production batch number | Metal material processing documents require fixed core parameters to avoid generated content being disconnected from actual production data |
| `messages` | Retain the last 10 rounds of dialogue context | Parameter transfer across rounds is required during process drafting to avoid repeated inquiries of already acquired field information |
| `chatId` | Bind to production batch ID | Documents from the same batch must use the batch's parameters uniformly to ensure data consistency within the session |
| System prompt | Clearly specify the document type and required fields, for example "Generate a process card compliant with GB/T 700 standards, which must include grade and yield strength parameters" | Metal material documents have mandatory standard and format requirements to guide generated content to comply with specifications |
| Session timeout period | 3600 seconds | Balances cross-time needs for process drafting and server resource usage |
| Context truncation length | 8000–12000 characters | Retains complete process parameters and dialogue logic to avoid truncation of critical production information |

## Three common errors
- Phenomenon: The generated process document does not include the specified yield strength value, and the format does not match the preset template. Cause: The system prompt fails to explicitly reference the custom variables configured in `variables`, so the prompt cannot associate actual production parameters.
- Phenomenon: The same material grade information is repeatedly asked during multi-turn dialogue. Cause: The `messages` parameter is not configured to retain recent dialogue context, so the session context is truncated and previously acquired field information cannot be remembered.
- Phenomenon: The generated inspection report and procurement contract content are mixed, with incorrect cross-field errors. Cause: The production batch ID is not bound via `chatId`, and different types of documents share session context, leading to parameter conflicts.

## How to confirm that the configuration is correct
- Enter known material grade and yield strength values, check whether the generated document automatically fills the corresponding fields to confirm that the `variables` configuration takes effect.
- Initiate more than two rounds of dialogue, add different process parameters, check whether subsequent generated documents retain previously entered information to confirm that the `messages` parameter is configured correctly.
- Switch between different document types (such as process card, inspection report), check whether the generated content conforms to the corresponding template to confirm that the system prompt configuration meets requirements.
- Wait 3600 seconds before initiating another dialogue, check whether the session still retains previous context to confirm that the `chatId` binding and timeout period configuration are reasonable.
