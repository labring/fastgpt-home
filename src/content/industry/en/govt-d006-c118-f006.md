# Document and Material Drafting for Metal Material Processing: Citation Source and Traceability

## What data for this category includes
Data for this category originates from three primary sources: enterprise MES system production ledgers, national metal material-related standard documents, and on-site original quality inspection records. Production ledgers generate and update in real time for each processing batch. Process standard documents update once every quarter. Quality inspection reports generate synchronously when a batch finishes processing.
Documents fall into two categories: structured tables and unstructured manuals. Structured fields include batch number, processing equipment number, process parameter range, quality inspection item results, and implementation standard number. Units used include millimeters, meters, hours, and Rockwell hardness units, among others.

## Constraints on citation and traceability workflows
Real-time single-batch production data requires traceability to tie precisely to a unique batch number. Using only fuzzy keywords for traceability causes cross-batch citation errors.
Mixed structured and unstructured documents require traceability workflows to support both structured field search and full-text content matching. This covers two core data source types: process standards and on-site production records.
Differing update frequencies across data sources require configuring separate index refresh cycles for static standard libraries and dynamic production data. This prevents referencing outdated process standards or unsynchronized production data.
Fields with multiple units require automatic unit normalization during retrieval. This ensures correct matching of parameters using different units.

## Recommended configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single-batch data and standard documents for metal material processing, avoids truncating valid traceability information |
| `responseData` | Structured fields + full content | Covers traceability needs for both structured production ledgers and unstructured process manuals |
| `detail` | Full source path + field values | Meets precise traceability needs for engineers to verify batch numbers and implementation standard numbers |
| Single retrieval limit | Top 5–7 results | Covers the three core data source types required for single-batch processing: process standards, quality inspection records, and equipment parameters |
| Unit normalization switch | Enabled | Adapts to retrieval matching for multi-unit fields, resolves citation confusion from mismatched parameter units |
| Index refresh cycle | Static library once per quarter, dynamic library once per hour | Matches actual update rhythms of different data sources, prevents referencing outdated or unsynchronized data |

## Three common configuration errors
1. After calling the generation interface, the returned result contains no cite reference ID field. The cause is that the `quoteMaxToken` configuration value is too small, leading to truncation of traceability information and failure to generate valid citation identifiers.
2. When clicking to view knowledge base citation details, a parameter error prompt pops up. The cause is that the `responseData` configuration does not enable both structured and full-text retrieval, leading to failure to load some data sources normally.
3. After selecting the corresponding knowledge base in the knowledge base search card, variable references cannot match the target batch data. The cause is that the unit normalization switch is not enabled, leading to a mismatch between the units of variable parameters and the retrieval data source.

## How to confirm proper configuration
This verification process uses FastGPT v4.17.0.
- Submit a document drafting request for a single batch of metal material processing. Check whether the returned result includes traceability information matching the configured length.
- View the citation details module, confirm that both structured fields and full source paths are displayed.
- Enter similar parameters with different units, verify that retrieval results correctly match the corresponding data.
- Call the generation interface, confirm that the returned result includes a valid citation identifier field.

The values given are common starting points and should be measured against the reader's own samples.
