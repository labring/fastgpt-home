# Document and Material Drafting for Metal Material Processing: Deployment and Upgrade

Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Document and material documents for metal material processing mainly come from workshop MES systems, quality inspection systems, and ERP production management systems. They cover types such as raw material inspection reports, process specification cards, production material requisitions, finished product certificates, and process transfer orders. The update rhythm is triggered by production batches, with a complete set of documents corresponding to each batch. The document structure is fixed, including fields such as material grade, specification and size, furnace batch number, tensile strength, yield strength, and impact energy. The units are no unit, mm, no unit, MPa, MPa, and J respectively. The length of a single document ranges from hundreds to thousands of characters, and some are attached with scanned documents or inspection images.

## What constraints these characteristics impose on deployment and upgrade
Fixed fields and unit requirements require pre-configuring database connections matching the business system during deployment, to avoid field loss or unit mismatch caused by parsing errors. The batch-based update rhythm requires retaining the incremental sync trigger logic during upgrades, and changing it to full scheduled updates arbitrarily will increase system load. Multi-source document data requires configuring reasonable database connection pool parameters during deployment to adapt to concurrent data requests from multiple workshops. Documents with attached scanned materials require retaining the original file storage path rules during upgrades, to avoid inability to read historical documents. At the same time, for domain name and security requirements in central state-owned enterprise and public sector scenarios, a dedicated intranet or public network domain name must be configured during deployment to meet compliance requirements.

## How to set configurations
| Configuration Item | Recommended Value | Basis for This Setting |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://metal_user:secure_pass@internal-db:5432/metal_manufacture?schema=public` | Business data for metal material processing is mostly stored in a dedicated PostgreSQL business database, matching the storage format of ERP and MES systems |
| `REDIS_URL` | `redis://:redis_pass@internal-cache:6379/1` | Cache temporary production batch data and user sessions, adapting to the batch-triggered update rhythm |
| `DB_MAX_LINK` | `20–30` | Adapt to concurrent data requests from multiple workshops, avoiding database connection pool exhaustion |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | Store inspection report scanned documents and process documents, using intranet object storage to ensure data security in central state-owned enterprise and public sector scenarios |
| `FE_DOMAIN` | `https://metal-docs.enterprise-domain.com` | Bind a dedicated front-end domain for document drafting, meeting domain name compliance requirements for central state-owned enterprises |
| `ROOT_KEY` | Determined through actual testing | Control administrator permissions, preventing unauthorized modification of knowledge bases and configuration rules related to metal materials |

## Three common mistakes
- Docker upgrade results in incorrect version display. After running `docker pull fastgpt/fastgpt:v4.8.10`, the container displays version 4.1.16 at startup. The cause is local caching of the old version image, without adding the `--no-cache` parameter to force pulling the latest image.
- DingTalk integration prompts receiving message address verification failure. The open platform returns a verification failure prompt when publishing the application. The cause is that the service port corresponding to the publicly accessible `FE_DOMAIN` is not configured, or the 80/443 port rules of the firewall are not opened.
- Knowledge base cannot be updated in offline environments. The latest metal material processing document data cannot be pulled. The cause is that local image caching or offline synchronization scripts are not configured, and the system relies on public networks to pull business data and model files.

## How to confirm the configuration is correct
- Run a database connection test command to verify the connection status of `PG_URL` and `REDIS_URL`, confirming that business tables and cached data for metal material processing can be read.
- Upload a standard metal material inspection report document, verifying that fixed fields such as material grade and tensile strength are correctly extracted after knowledge base parsing.
- Check the Docker container startup logs, confirming there are no prompts for version pulling errors, verifying that the upgraded version meets expectations.
- Configure an intranet test environment, simulate public network access verification, confirming that the service corresponding to `FE_DOMAIN` can respond to requests normally.
