# Document and Material Drafting for Iron and Steel Smelting: Workflow Orchestration

## What Data for This Category Looks Like
Data related to document and material drafting for iron and steel smelting primarily comes from production MES systems, quality inspection ledgers, process specification documents, and contract approval documents. Data update cadence falls into three categories:
- Heat operation data is updated in real time
- Shift production reports are updated daily
- Bidding and compliance documents are generated and updated as needed

Document structures include fields such as smelt batch identifiers, operation process nodes, composition test parameters, and equipment operation parameters. Field units use industry standard units like degrees Celsius, hours, and kilograms per ton. Single-document length varies widely, ranging from several hundred characters of heat records to tens of thousands of characters of complete process specifications.

## How These Characteristics Impact Workflow Orchestration
Real-time heat operation data requires keeping workflow node trigger delays within a reasonable range to avoid disrupting synchronous processing of heat operations.
Multi-source data requires configuring multiple data source access nodes to match the field formats of different systems.
Long documents such as complete process specifications require proper configuration of chunking and context carrying capacity to avoid exceeding node processing limits.
The fixed process sequence of smelting operations requires workflow node transfer logic to strictly align with process nodes; the sequence cannot be adjusted arbitrarily.
When batch processing daily reports, configure parallel execution nodes to improve processing efficiency.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Prompt Optimization | Enabled, with customized optimization for iron and steel smelting terminology | Iron and steel smelting terminology has high professionality; optimization is needed to match professional documents in the knowledge base |
| Single Search Limit | Top 8 entries | Iron and steel smelting document data is concentrated; too many results will exceed context carrying limits |
| Maximum Context | 8000–12000 token | Long documents such as complete process specifications require sufficient context to carry detailed parameters |
| Document Chunk Length | 1500–2000 characters | Balances professional parameter recall accuracy and context overhead, adapting to the content density of iron and steel smelting documents |
| `variables` | Bind smelt batch number, tapping temperature, and composition test value fields | Real-time production data must be used as core input variables for document drafting |
| `nodeId` | Configure continuous transfer in smelting process order | Aligns with the fixed process logic of iron and steel smelting, ensuring workflow nodes execute in the correct order |

## Three Common Misconfigurations
- Phenomenon: An error `Cannot convert undefined or null to object` appears when running the workflow, and subsequent node transfers cannot be completed. Cause: The iron and steel smelting fields corresponding to `variables` are not correctly bound. For example, failing to pass the smelt batch number causes node parameters to be empty.
- Phenomenon: After triggering a workflow for a specific smelting-related query, no subsequent transfer occurs after the knowledge base search node, and the workflow ends early. Cause: No node failure retry or branch jump logic is configured. When the search result is empty, the preset exception handling branch is not triggered.
- Phenomenon: Historical conversation content cannot be called as an input variable for document drafting in the workflow. Cause: The context storage switch of the workflow is not enabled, and historical records are not bound to the `variables` parameter.

## How to Confirm the Configuration Is Correct
- Trigger a typical smelt heat document drafting task, and verify that the production fields bound to `variables` are correctly passed to each node of the workflow.
- Check the workflow's node transfer logic, confirm that the `nodeId` configuration fully matches the smelting process sequence, and that nodes can transfer normally in order.
- Simulate an exception scenario with no search results, confirm that the preset exception handling branch is triggered, and the workflow will not stall at the search node.
- View the workflow running logs in FastGPT v4.17.0, and confirm that there are no error messages about empty parameters or type mismatches.
