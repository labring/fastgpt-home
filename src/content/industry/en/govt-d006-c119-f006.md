# Document and Material Drafting for Iron and Steel Smelting: Source Citation and Traceability

## What the Data for This Category Looks Like
Core data for iron and steel smelting documents and materials comes from on-site production ledgers, process specification documents, quality inspection reports, safety compliance records, and equipment operation logs. Data is updated by production batch, and multiple documents of different dimensions can be generated in a single day. A single document typically includes fields such as batch number, smelting temperature, carbon content, tapped steel volume, equipment operation parameters, and more. Units include tons, minutes, percentages, degrees Celsius, and others. Some long documents are split into multiple chapters to mark process nodes and quality inspection results.

## Constraints for Source Citation and Traceability
The batch-based data update logic for iron and steel smelting requires citation traceability to be bound to a specific production batch number, to avoid mixing data across batches. Professional fields have exclusive units. The original units and parameter formats must be fully retained during citation to prevent deviations in process interpretation. Multiple documents generated in a single day have similar parameter items. It is necessary to limit the recall time range and batch dimension to reduce interference from irrelevant content. Traceability for compliance documents requires precise matching of clause numbers. The compliance chapter and section identifiers of the document must be associated during recall.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Maximum number of recalled documents per single call | Top 5 entries | Controls context length, preventing output confusion caused by excessive similar production data |
| Citation content format | Retain original units and field names | Aligns with the format specifications of professional documents for iron and steel smelting, preventing deviations in parameter interpretation |

## Three Common Configuration Mistakes
- Issue: Citation fields in generated documents lack batch numbers or original units. Cause: The `detail` configuration item is not enabled, resulting in recalled data not carrying core fields required for traceability.
- Issue: No selectable values for variable references when selecting a knowledge base in the interface. Cause: Fields such as batch numbers and equipment numbers for iron and steel smelting have not been configured as custom variables for the knowledge base in advance, or the variables are not associated with the currently recalled knowledge base.
- Issue: Cannot redefine property: toString error is thrown during invocation. Cause: Incompatible document formats are mixed in the citation configuration, or the `quoteMaxToken` setting exceeds the maximum token limit allowed by the system, resulting in parameter parsing exceptions.

## How to Confirm Successful Configuration
- Manually trigger a document drafting process, and check whether the generated content includes traceability fields such as batch number and equipment number from the original document.
- Enter the knowledge base configuration page, and check whether custom variables have been associated with the iron and steel smelting production ledger and quality inspection report knowledge bases.
- View system logs to confirm that no Cannot redefine property: toString parameter parsing errors have occurred.
- Adjust the `quoteMaxToken` value, then verify that the citation content of long documents is not truncated.
