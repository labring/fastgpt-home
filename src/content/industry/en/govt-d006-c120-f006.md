# Document and Material Drafting for Railway Operations: Citation Source and Traceability

## What the Data for This Category Looks Like
Data related to document and material drafting for railway operations mainly comes from train operation dispatch logs, line maintenance weekly reports, ticket operation reports, temporary dispatch orders, and similar sources. Update frequency varies by type: daily dispatch documents are updated in real time or hourly, while monthly operation reports are updated monthly. Documents have a fixed structure including fields such as operation number, execution time, line section, operation category, and associated personnel number. Standard railway industry units such as kilometers, passenger trips, and minutes are mostly used.

## Constraints Imposed on Citation Source and Traceability
Real-time performance, structured fields, and compliance requirements for railway operation data impose multiple constraints on citation traceability. Real-time updated dispatch documents require retrieval nodes to prioritize recalling the latest entries to avoid referencing expired information. Fixed fields such as operation number and line section require precise binding to corresponding field values during traceability. Relying solely on keyword matching can easily confuse documents of the same type but different operations. Documents vary widely in length, from hundreds of words for dispatch orders to tens of thousands of words for monthly reports. The traceability link must adapt to source documents of different lengths to avoid truncating critical compliance information.

## How to Set Configurations
| Configuration Item | Recommended Value Range | Basis for This Setting |
| ---- | ---- | ---- |
| `quoteMaxToken` | 4000–6000 token | Adapts to the average single-document length of railway operation documents, avoids exceeding model context limits, and covers core traceability information |
| `responseData` | Return only source document fragments | Meets the compliance traceability requirements for railway operation documents, and prevents AI from modifying original content |
| `detail` | Enabled | Retains fields such as operation number and execution time from source documents, ensuring complete traceability information |
| Single recall limit | Top 8 entries | Matches the volume of documents for daily railway operation tasks, avoiding excessive redundant information interfering with retrieval |
| Context splicing length | Calibrated via actual testing | Adapts to the context window of large language models, avoiding exceeding processing limits after splicing |

## Three Common Misconfigurations
- Phenomenon: When a knowledge base node is called in a workflow, the global variable datasetid does not take effect, and the node returns empty results. Reason: The global variable scope is not bound in the node configuration, or the variable name does not match the parameter name in the configuration item.
- Phenomenon: The citation content returned by AI is modified a second time, with non-original decorative expressions added. Reason: The `responseData` configuration item is not enabled, causing the large language model to rewrite the source document.
- Phenomenon: The number of source documents returned by knowledge base retrieval exceeds expectations, and query time is excessively long. Reason: No reasonable single recall limit is set, and the value of `quoteMaxToken` is not restricted, leading to a large amount of redundant data being sent to the model.

## How to Confirm the Configuration Is Properly Set
- Access the knowledge base retrieval node configuration page in FastGPT v4.17.0, and check whether the value of `quoteMaxToken` matches the length of business documents.
- Initiate a test call, and check whether the returned results include fields such as the operation number and execution time of the source document, to confirm that the `detail` configuration is enabled.
- Trigger a workflow run, and check whether the returned citation content is completely consistent with the source document, with no additional decorative content added.
- View the node run logs, and confirm that the global variable datasetid has been correctly loaded, with no undefined variable error messages appearing.
