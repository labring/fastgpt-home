# Document and Material Drafting for Railway Operations: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data related to document and material drafting for railway operations mainly comes from train operation logs, passenger service specifications, train operation regulations, emergency response plans, and monthly operation statistical reports. Data update cycles fall into three categories: fixed regulations are updated quarterly or annually, train logs are updated daily, and emergency plans are revised as needed. Most documents follow a fixed chapter framework, with fields including operation number, execution time, responsible team, line section, and others. Units use industry standard metrics such as kilometers, hours/minutes/seconds, and passenger trips.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Daily updated train logs require the retrieval system to support incremental synchronization and incremental recall, to avoid reloading full datasets and improve retrieval efficiency. Documents with fixed chapter structures must be chunked by chapter, to ensure precise matching of content for corresponding operation links during retrieval and avoid interference from irrelevant cross-chapter information. Professional fields such as line numbers and train numbers must be used as retrieval filters to narrow the recall scope and ensure results align with current operation scenarios. Long documents like emergency response plans require reasonable control of chunk length, to avoid overly long single chunks that reduce semantic recall accuracy. Additionally, there are many industry-specific terms, so both precise matching and semantic expansion need to be balanced.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Railway operation documents contain many professional terms. A threshold that is too low will include irrelevant industry documents, while a threshold that is too high will miss accurately matched emergency response entries. This range is calibrated based on actual testing. |
| `limit` | Top 8 entries | Railway operation documents are often lengthy in single pieces. Too many citations will exceed the context window, while too few will fail to cover the complete operation process. This value is set based on the multi-step nature of railway operations. |
| `searchMode` | semantic+keyword | Railway documents require precise matching for fixed terms and semantic association across chapters. Using both modes improves recall accuracy. |
| `usingReRank` | Enabled | There are many entries with similar similarity scores for emergency-related documents in railway operations. Reranking prioritizes recall of content most relevant to the current drafting scenario. |
| `datasetSearchUsingExtensionQuery` | Enabled | Railway documents contain many professional terms. Expanded queries can supplement synonyms and industry abbreviations to improve recall coverage. |
| `collectionIds` | ID of the exclusive railway operation knowledge base dataset | An exclusive collection must be specified to avoid mixing in knowledge base content from other categories. |

## Three Common Mistakes
- An API call returns an unauthorized prompt. Check the status code returned by the interface is 403. After troubleshooting, the cause is either that the `collectionIds` parameter for the corresponding railway operation knowledge base was not included in the request, or the API key permission was not configured to allow access to the specified dataset.
- After increasing the `limit` parameter, the large language model does not reference any recalled content. Checking the recall log shows the number of results matches the configuration, but the context splicing result is empty. The reason is that the maximum token limit for the context window was not adjusted synchronously, causing recalled content to be truncated and discarded.
- Retrieval results mix operation regulations from non-current lines. Checking the recalled entries shows they include operation requirements for other sections. The cause is that a precise matching parameter for line numbers was not added to the retrieval request, and no filter conditions were used to narrow the recall scope.

- Include the specified `collectionIds` parameter when calling the API, verify that the returned results only contain documents related to railway operations.
