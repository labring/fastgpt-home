# Document and Material Drafting for Expressway Operations: Tool Calling and Plugins

## What the Data for This Category Looks Like
The data required for document and material drafting in expressway operations mainly comes from four data sources: toll collection systems, road patrol systems, maintenance management systems, and emergency response ledgers. Data update frequencies fall into three categories: real-time (lane traffic volume, emergency response records), daily (maintenance daily reports), and monthly (operation monthly reports). The document structure linked to a single draft is mostly structured tables, containing fields like lane number, traffic volume, patrol time, maintenance mileage, and disposal result. Field units are typically trips, kilometers, and hours. Some documents include unique file numbers and timestamps.

## Constraints Imposed on Tool Calling and Plugins
Multi-source, heterogeneous data sources require adapting to the field naming rules of different systems, so additional field mapping logic must be configured. Real-time traffic and emergency data have strict real-time requirements, so tool call response times must not be excessive. Otherwise, document generation efficiency will be impacted. Structured document fields require tool-returned data to strictly match preset field names and units. Otherwise, data errors will appear in generated documents. A single draft usually only needs partial data from a recent period, so tool calls must support limiting data range and quantity to avoid redundant data occupying context space.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically select the appropriate tool calling strategy to adapt to complex scenarios of multi-source data retrieval |
| `functionCall` | `["get_toll_data", "get_patrol_record", "get_maintenance_report"]` | Bind three dedicated data retrieval tools for expressway operations, covering the core data sources required for drafting documents |
| Single Call Data Limit | `Top 20 entries` | A single operation draft usually only requires the most recent 20 traffic or patrol data entries to avoid redundant data occupying context |
| Tool Call Timeout | `30–60 seconds` | Real-time operation data must be returned in a short time; an overly long timeout will affect the overall efficiency of document generation |
| Maximum Context Length | `8000–12000 token` | Adapt to the long-text generation requirements of expressway operation documents, while avoiding context overflow |
| Field Matching Rule | Strictly match preset field names | Ensure the accuracy of units and formats for key data such as lane numbers and traffic volumes in documents |

## Three Common Mistakes
- Phenomenon: Empty tool call results are returned when calling the session interface. Cause: The dedicated tool functions for expressway operations are not correctly bound, making it impossible to retrieve the corresponding data sources.
- Phenomenon: Tool calls return status code 504 timeout. Cause: The set timeout period is too short to complete the retrieval and integration of multi-source heterogeneous data.
- Phenomenon: Mixed units for maintenance mileage appear in the generated documents. Cause: Strict field matching rules are not enabled, and the fields returned by the tool are not aligned with the preset "kilometer" unit.
