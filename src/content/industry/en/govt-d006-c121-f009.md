# Document and Material Drafting for Expressway Operations: Model Access and Configuration

## What data is included in this category
Expressway operation document and material drafting uses multiple types of business data. Sources include daily road patrol records, toll reconciliation reports, emergency response reports, traffic policy documents, and section operation and maintenance archives.

Update rhythms vary. Patrol records and daily work orders update daily. Policy documents and standard specifications are revised irregularly. Reconciliation reports are compiled monthly.

Most document structures use structured fields. Patrol records include fields such as patrol time, section number, issue type, response measures, and responsible person. Units include kilometers, yuan, and hours. Policy documents are paragraph-style text, with clause numbers and scope of application descriptions.

## What constraints do these characteristics impose on the model access and configuration link
Model access must support scheduled synchronization and incremental updates for business data with varying update rhythms. This prevents reloading expired files.

Mixed structured and unstructured data formats require configuration to balance field extraction accuracy and context capacity for long texts.

Fields with units such as section numbers and monetary amounts require model output to strictly match preset units. This prevents unit confusion.

Internal confidential operation and maintenance archives must be accessed via private interfaces. This requires configuration of custom proxy addresses and authentication parameters to ensure data transmission security.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Expressway operation documents usually include multiple patrol records, policy clauses, and reconciliation data. They require sufficient context to hold multiple related documents |
| `maxTokens` | `4000–6000 token` | The output length of a single drafted document usually falls within this range. This avoids exceeding the model's output limit |
| `quoteMaxToken` | `2000–3000 token` | Quoted segments of road management specifications and toll policy documents are usually limited in length. This reserves enough space to retain original quoted content |
| `temperature` | `0.3–0.5` | Document drafting requires precision and accuracy. It avoids excessive divergence to ensure content complies with business standards |
| `AIPROXY_API_ENDPOINT` | Full address of the deployed private proxy, including port and route suffix | When the internal network environment cannot directly access public large model interfaces, use a proxy to forward requests. This ensures data security |
| `AIPROXY_API_TOKEN` | Authentication token assigned by the proxy service | This verifies request legitimacy to prevent unauthorized access to private model services |

## Three Common Mistakes
- Generated documents lack core fields such as section numbers and toll amounts. Returned content is incomplete. The cause is incorrect configuration of the `maxContext` parameter. Long documents get truncated, and key fields in structured data are lost.
- Connection timeouts or 404 status codes appear when calling a custom reranker model. The cause is that the `AIPROXY_API_ENDPOINT` field does not include the correct port number or route suffix. Requests fail to reach the target service.
- Generated documents do not reference specified policy files. Global variables do not sync the latest toll standards. The cause is failing to sync the latest values from external data sources to global variables via the correct API call chain. Or failing to add specified files to a separate associated group in the knowledge base.

## How to Confirm Configuration Is Complete
- Upload a standard road patrol record. Check whether the drafted document generated by the model includes core fields such as patrol time, section number, and response measures.
- Send a test request to the configured `AIPROXY_API_ENDPOINT`. Verify that the returned status code is 200, and the response content includes the expected model output format.
- Manually modify the test value of the global variable. Check whether the generated document synchronously updates corresponding content such as toll standards.
- Upload a specified policy file. Verify that the generated document correctly references the clause content in that file.
