# Document and Material Drafting for Expressway Operations: Deployment and Upgrade

## What data for this category looks like
The data is primarily sourced from fee settlement receipts, road patrol logs, maintenance work plans, emergency response ledgers, and annual operation reports generated during expressway operations. Update schedules follow two patterns: daily updates for daily documents, and fixed-cycle updates for quarterly and annual reports. Most documents have fixed structured headers, including fields like road section number, operation time, responsible entity, and disposal result. Industry-standard units such as kilometers, hours, and yuan are used uniformly. The length of individual documents varies significantly.

## What constraints these characteristics impose on deployment and upgrade
The fixed structured header of documents requires pre-configuring mapping rules between fields and vector extraction during deployment. This prevents unstructured content from interfering with retrieval accuracy. Daily work documents updated daily and report data updated on a fixed cycle require configuring both incremental sync and full sync task modes during deployment. This adapts to different data update rhythms. The wide variation in document length requires adjusting context window adaptation parameters during the upgrade phase. This prevents long documents from being truncated and short documents from having redundant content. The requirement for industry-standard units requires configuring unit validation rules during deployment. This ensures that the units of generated operation documents match those of the original data.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `80–120 entries` | Expressway operation documents often relate to road sections and work records. This setting adapts to multi-link retrieval needs and avoids missed retrieval results |
| `MONGODB_URI` | `Intranet-only connection address` | Stores unstructured operation documents. Deploying in an intranet environment ensures data compliance |
| `REDIS_URL` | `Intranet cluster address using port 6379` | Caches frequently accessed daily work documents. Reduces vector database query pressure and adapts to daily updated document volume |
| `STORAGE_S3_ENDPOINT` | `Intranet object storage service address` | Stores large maintenance reports and settlement receipts. Meets data storage compliance requirements for state-owned enterprises and public sector entities |
| `FILE_TOKEN_KEY` | `Key configuration with a 7-day validity period` | Ensures the security of file download links. Prevents unauthorized access to sensitive operation documents |
| `ROOT_KEY` | `Intranet administrator-only secret key` | Ensures permission security for platform background management. Prevents unauthorized modification of operation document configurations |

## Three common errors
- Attempting to adjust the custom retrieval count to more than 6 via the API returns a parameter error. This occurs when the `DB_MAX_LINK` parameter is not configured correctly, as the default value limits the maximum allowed number of retrieval links.
- The reranker service call returns a success flag, but retrieval results always show false, and the interface displays no valid hits. This happens when the matching reranker service address is not configured during deployment, or when the field mapping rules between the vector database and reranker are inconsistent. This leads to result verification failure.
- After upgrading to FastGPT v4.17.0, the plugin editing page always displays an "unsaved" prompt at the top, regardless of whether a save operation is performed. This is caused by uncleared front-end local cache after the upgrade, or when the `FE_DOMAIN` configuration does not match the actual deployed intranet address. This leads to abnormal front-end state synchronization.

## How to confirm the configuration is correct
- Run an incremental sync task for daily work documents. Check that the number of new documents in the vector database matches the sync log. This confirms that the data sync configuration is active.
- Call the retrieval interface with a query string containing a road section number. Verify that the number of returned result links does not exceed the value set in the `DB_MAX_LINK` configuration. This confirms that the retrieval upper limit configuration is correct.
- Upload a large maintenance report. Confirm that the front-end page loads normally and generates a corresponding document draft. This confirms that the context window and storage configuration are properly adapted.
- Access the intranet front-end address, log in with an administrator account, modify the plugin configuration, and save it. Confirm that the top prompt disappears. This confirms that the front-end state synchronization configuration is normal.
