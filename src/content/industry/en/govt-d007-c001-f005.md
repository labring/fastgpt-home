# 12345 Citizen Hotline Ticket Handling: Declaration Materials and File Review - Tool Calling and Plugins

## What the data for this category looks like
Typical data sources for this category include the 12345 citizen hotline platform, contractor business systems, official knowledge bases, citizen feedback evaluation data, and local hotline management regulations. Data is updated daily, covering all ticket workflow records.

Daily processed documents include request registration forms, dispatch records, handling responses, follow-up records, delay applications, return explanations, and standardized knowledge base entries. Core document fields typically include request number, contractor unit, request content, handling status, citizen evaluation, and other key information. No fixed legal time limit or amount-type mandatory fields are bound.

## Constraints imposed by these characteristics on tool calling and plugins
Daily updated full data requires tool calling to support scheduled synchronization of cross-system ticket records. This prevents data lag from impacting review efficiency.

Multiple document structures require tool calling to adapt to different formats of request materials. It must also have the ability to automatically identify core document fields.

Core time-consuming steps include request type judgment, cross-department verification of response content, return and re-dispatch processing, and follow-up on dissatisfied follow-up tickets. Tool calling must specifically cover these steps.

Multi-source data requires plugins to connect to different business systems. It must also handle differences in return formats across systems.

Errors may lead to overdue tickets, rejected responses, or repeated citizen complaints. Therefore, tool calling must include failure retry and exception alert mechanisms.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapts to the multi-tool calling needs of 12345 ticket review. It automatically selects appropriate tools for request type judgment, material verification, and other steps |
| Tool call timeout threshold | 600 seconds | Ticket review typically requires cross-system queries of contractor business data. 600 seconds covers most cross-system response durations |
| Maximum number of tools called per single invocation | First 3 | Declaration materials associated with 12345 tickets usually do not exceed 3 categories. Excessive numbers increase context burden and reduce review efficiency |
| Context window length | 8000–12000 token | Must accommodate multiple document contents such as request registration, dispatch records, and handling responses. This ensures complete review basis |
| Number of tool call failure retries | 2 | Avoids interrupting ticket review due to temporary network fluctuations or system temporary failures. It also prevents repeated calls from triggering interface restrictions |

## Three common misconfigurations
- Phenomenon: Tool calling returns status code 504 with a timeout prompt. Cause: No timeout threshold adapted for cross-system queries is set. The general short timeout setting from common scenarios is used, which cannot cover the time required for cross-department data queries in 12345 ticket review.
- Phenomenon: Calling `functionCall` returns an empty result, with no valid review opinion generated. Cause: No reasonable context window length is configured, leading to key ticket materials being truncated. The tool cannot obtain complete review basis.
- Phenomenon: Direct curl calls to the model interface run at normal speed, but calls in FastGPT run slower. Cause: Unnecessary context preprocessing steps are not disabled, or no reasonable maximum number of single tool calls is set, leading to additional document parsing and splicing time.

## How to confirm configurations are properly set
- Submit a simulated ticket review request, check the tool calling logs, confirm that the `toolChoice` parameter triggers in auto mode, and that tool call times meet the preset first 3 limit.
- Simulate a cross-system query scenario, wait for tool calling to complete, confirm that the response duration does not exceed the preset 600-second timeout threshold.
- Check tool call failure records, confirm that the system automatically triggers 2 retries during temporary network fluctuations, with no direct termination of review.
- Compare the response duration of FastGPT and direct curl calls to the same model, confirm that no significant additional time delay occurs.
