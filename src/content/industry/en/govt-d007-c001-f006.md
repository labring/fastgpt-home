# 12345 Citizen Hotline Ticket Handling: Declaration Materials and File Review — Citation Source and Traceability

## What the data for this category looks like
This category of data mainly comes from the 12345 citizen hotline platform, contractor business systems, official knowledge bases, follow-up evaluation data, and local hotline management regulations. Daily processed documents include request registration forms, dispatch records, handling responses, follow-up records, extension applications, return explanations, and knowledge base entries. Each document contains fixed fields such as request number, contractor unit, response content, and follow-up score. Data is updated daily, synchronizing newly added tickets, responses, and archived file information from the current day each day. The volume of documents synchronized in a single batch fluctuates with the number of requests received that day.

## What constraints these characteristics impose on the citation source and traceability link
The scattered nature of data sources requires that the citation traceability link support multi-source data association matching, using unique identifiers such as request numbers to associate dispatch records, response content, and follow-up data. The structural differences between multiple types of documents require distinguishing the field definitions of different documents when configuring field mapping rules. The daily update rhythm requires using an incremental synchronization mechanism to avoid resource occupation from full-volume loading. At the same time, the time limit constraints for ticket handling require that the response time of the traceability link adapts to the daily handling rhythm to prevent delays in ticket processing.

## How to configure settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 300–500 token | Limits the length of a single quoted content, adapts to the core information volume of file documents, and aligns with the processing limit of FastGPT v4.17.0 |
| Maximum Context | 800–1200 characters | Carries the total length of multiple documents such as associated dispatch records and response content, avoiding exceeding the model's processing threshold |
| Single Search Limit | Top 5 entries | Covers recently archived ticket files and knowledge base entries, balancing information sufficiency and response speed |
| Similarity Threshold | 0.72–0.80, calibrated via actual testing | Filters historical responses and management specification content unrelated to the current request, improving matching accuracy |
| `detail` | Enabled | Outputs the original source identifier and field information of quoted content, facilitating subsequent file review and traceability |
| `responseData` | Return only matching items | Avoids returning irrelevant knowledge base content, aligning with the precise needs of ticket handling |

## Three common misconfiguration issues
- Phenomenon: After configuring `quoteMaxToken`, the returned quoted content still exceeds the expected length. Cause: The value range of the maximum context was not adjusted synchronously, leading to overall context overflow.
- Phenomenon: After calling the knowledge base in the application, content completely unrelated to the current ticket request is returned. Cause: A reasonable similarity threshold was not set, or the association matching filtering rule was not enabled.
- Phenomenon: The original source request number or contractor unit information is not displayed in the quoted content. Cause: The `detail` configuration item was not enabled, and the original field output logic was not activated.

## How to verify successful configuration
- Upload one typical request registration form and historical response document, initiate a simulated ticket query, and check whether the returned quoted content includes the core fields of the corresponding document.
- Review the configuration item values, confirm that the `quoteMaxToken` setting matches the expected quoted length, and that `detail` is enabled.
- Simulate triggering an incremental synchronization task, check whether only newly added ticket data from the current day is synchronized, with no duplicate loading of old files.
- Adjust the similarity threshold and initiate a test, confirm that the number of returned results fluctuates reasonably with changes to the threshold.

The values provided are common starting points and should be measured against the reader's own samples.
