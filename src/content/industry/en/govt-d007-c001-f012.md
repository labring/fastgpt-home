# 12345 Citizen Hotline Ticket Handling: Declaration Materials and Case Review - Deployment and Upgrade

## What the data for this category looks like
This category of data primarily originates from the 12345 citizen hotline platform, contractor business systems, public knowledge bases, return visit evaluation data, and local hotline management specifications. Daily processed documents include request registration forms, dispatch records, handling responses, return visit records, extension applications, return instructions, and knowledge base entries. Data updates occur daily. Core fields include request number, contracting entity, response content, return visit evaluation result, and others. The overall workflow follows the closed-loop circulation of mass requests.

## Constraints Imposed on Deployment and Upgrade
Since data sources are scattered and updated daily, configure a stable multi-source data synchronization link during deployment to avoid missing incremental updates. Different ticket document types have distinct structural differences. Preset parsing rules adapted to each document type to ensure accurate extraction of core fields such as request type and responsible unit. Errors in ticket processing directly impact public satisfaction. Reserve monitoring and alert configuration during deployment, and adapt configurations to the exclusive business fields of the 12345 citizen hotline to prevent field matching deviations from generic configurations. Additionally, configure separate storage paths for attachment-based ticket materials to ensure unified management of all document types.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–20 connections | Adapts to daily incremental ticket data connection count, prevents connection pool exhaustion |
| `MONGODB_URI` | Connection string pointing to the 12345 citizen hotline unstructured business database | Stores unstructured ticket data such as dispatch records and return instructions |
| `PG_URL` | Connection string pointing to the 12345 citizen hotline structured business database | Stores structured ticket fields such as request number and contracting entity |
| `REDIS_URL` | Connection address of a local cache instance with 512 MB memory | Caches frequently accessed hotline knowledge base entries and same-day request cache to reduce database pressure |
| `STORAGE_S3_ENDPOINT` | Access endpoint corresponding to the cloud storage service provider | Stores attachment files such as return visit recordings and scanned request materials |
| `FILE_TOKEN_KEY` | Random key generated according to business scenarios | Encrypts access tokens for ticket attachments to prevent unauthorized access |
| `ROOT_KEY` | Management key configured according to the deployment environment | Controls core configuration permissions of the FastGPT backend, adapts to the security management requirements of the 12345 citizen hotline |

## Three Common Configuration Errors
- Pulling the Redis image fails with an "image not found" prompt. When using FastGPT v4.17.0, the official image repository updated the Redis image version, and the old pull command cannot adapt to the new image tags.
- The MCP tool in workflows cannot read the global variable token. Global variable delivery rules are not correctly configured, and the token is not bound to the input parameter fields of the MCP tool.
- Saving fails when configuring the Xinference model channel on the page. The model's API address and port parameters are not correctly filled, causing verification failure.

## How to Verify Successful Configuration
- Run the database connection test command to verify that the connection status of `MONGODB_URI` and `PG_URL` is normal.
- Upload a simulated request registration form to check if core parsed fields are accurately extracted.
- Access the backend address corresponding to `FE_DOMAIN`, log in using `ROOT_KEY`, and check if the system operating status is normal.
- Trigger an incremental synchronization of ticket data to check if the cache configured via `REDIS_URL` updates as expected.

The values provided here are common starting points and should be evaluated against the reader's own samples.
