# "One-Stop One-Task Efficient Completion" Joint Handling: Declaration Materials and File Review — HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data typically comes from the national government service platform's "one task" special zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. Commonly processed documents include joint handling item lists, one-time notice sheets, joint handling application forms, material transfer sheets, parallel approval opinions, and completion receipts. Data is updated daily. The field structure varies depending on the cross-departmental combination of joint handling items, so adaptation is required for different formats and field differences across multiple sources.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Multi-source heterogeneous data sources require interfaces to support integration with external systems of different formats, and unified cross-departmental field mapping logic must be handled. The daily update frequency requires the interface to be configured with a scheduled synchronization mechanism to avoid data lag affecting joint handling progress. Cross-departmental material transfer and approval status tracking require the interface to support persistent storage of file status at each stage, while also being compatible with permission verification logic from different departments. Differences in document structures across joint handling items require the interface's request parameters to support dynamic field adaptation to avoid adaptation failures caused by hardcoding.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer example value` | Complies with HTTP interface identity authentication standards, adapts to government system permission verification requirements. FastGPT v4.17.0 and above support this format |
| `variables` | `{"dept_list": ["Leading Department", "Collaborating Departments"], "update_cycle": "daily"}` | Adapts to cross-departmental configuration of joint handling items and daily update synchronization needs, supports dynamic parameter adjustment |
| `responseData` | `{"status": "string", "task_id": "string", "case information": "object"}` | Returns standardized joint review status and case ID to facilitate external system tracking of process progress |
| Interface timeout | 600 seconds | Adapts to the average processing duration of government joint handling workflows, avoids prematurely interrupting data synchronization |
| Retry count | 3 times | Addresses temporary fluctuations in external systems, ensures data synchronization success rate |

## Three common mistakes
- Symptom: After calling the pushdata API using chunk mode to upload, the interface always shows "indexing in progress". Cause: Failed to correctly configure chunk and metadata parameters in `variables`, or failed to pass complete material information as required by the interface, causing the indexing process to fail to trigger the completion marker.
- Symptom: After connecting an external model to the system, the corresponding model does not appear in the text content extraction module's model selection list. Cause: Failed to correctly declare supported model identifiers in `variables`, or the model list returned by the interface was not synchronized to the system configuration.
- Symptom: An error is returned when calling the knowledge base query interface using an application secret. Cause: Failed to correctly set the token format of the `Authorization` parameter, or failed to configure access permissions for the corresponding interface for the application secret, resulting in identity verification failure.

## How to confirm the configuration is correct
- Call the test interface, check that the `Authorization` parameter correctly carries the system secret, and the returned status code is 200.
- Submit a test joint handling application form, check that `responseData` contains the correct case ID and status information.
- Configure the scheduled synchronization task, check that daily data updates trigger as planned, with no abnormal error logs.
- Verify cross-departmental field mapping logic, confirm that different formatted data input by external systems can be correctly parsed and stored.
