# Real Estate Registration Declaration Materials and File Review: Workflow Orchestration

## What the data for this category looks like
Data for this category comes from the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate repository. The update frequency is daily. Documents processed daily include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and real estate registers. Data fields cover real estate location address, area measured in square meters, rights type, right holder information, registration reasons, and more. The character count of single core documents varies widely.

## What constraints do these characteristics impose on the "workflow orchestration" link
The daily update of multi-source data requires complete context to be passed between workflow nodes, to prevent cross-system data inconsistency. The diverse document types with distinct structural differences require workflows to have parsing nodes configured to adapt to different input formats. The wide character count range of core documents requires reasonable configuration of context capacity parameters, to avoid truncation of key content such as ownership information and location addresses. High-time-consuming links that verify ownership sources and restriction status require workflows to support parallel node task splitting. This shortens overall processing cycles and reduces the risk of registration errors.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Context window size | `8000–12000 characters` | The wide character count range of core documents requires covering the full content of most single documents to avoid truncation of key information |
| `variables` | Bind core data fields synchronized across multiple systems | Need to pass variables shared across nodes such as real estate location and right holder information, to ensure unified context |
| Node retry count | `3 times` | Verification links may fail due to temporary system fluctuations; retries can reduce invalid interruptions |
| Tool call timeout | `60 seconds` | Response cycles for cross-system retrieval of cadastral data and tax vouchers usually fall within tens of seconds; timeouts can trigger correction processes |
| `nodeId` | Assign unique identifiers to each cross-system node | Facilitate workflow debugging and context tracking, to avoid node confusion |
| Input format validation rules | Configure required field validation per document type | Ensure required items of documents such as registration applications and ownership certificates are complete, to reduce subsequent correction links |

## Three common mistakes
- Tool call nodes return Invalid JSON errors, and the interface displays "Invalid JSON: Bad control character". The cause is that raw data returned when calling cross-system interfaces contains unescaped line breaks or special characters, and no data cleaning step is added in the node configuration.
- Workflow components cannot be copied and pasted. After dragging components, copy operations fail, or node conflicts occur after pasting. The cause is that the workflow's batch editing mode is not enabled, or the component's `nodeId` is duplicated, causing the system to block copy operations.
- Workflow context is not passed uniformly, and subsequent verification nodes have missing or inconsistent ownership information. The cause is that the `variables` parameter is not bound between nodes, causing cross-system retrieved data to not be synchronized to subsequent links.

## How to confirm the configuration is correct
- Trigger a complete workflow, use the workflow debugging panel of FastGPT v4.17.0 to view node logs, confirm that the `variables` parameter of each node synchronously passes real estate core information.
- Simulate submitting a test document with incomplete format, check if the input format validation node triggers interception, and confirm that the validation rules take effect.
- When calling a tool node, check if the JSON format of the returned result meets expectations, and confirm that the data cleaning step has processed special characters.
- Copy a single component in the workflow, paste it into a blank workflow, confirm that the component's `nodeId` is automatically updated without conflicts, and confirm that the copy function works normally.
