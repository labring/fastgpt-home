# Real Estate Registration Declaration Materials and File Review: Source Citation and Traceability

## What this category of data looks like
The core sources of data for this category are the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate repository. The update frequency is daily.
Documents processed daily include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and real estate registers.
Data fields cover real estate location, right type, right holder information, right restriction status, and more. National unified real estate registration standard fields are used, with no custom units.

## How these characteristics impose constraints on the source citation and traceability link
Data sources cover multiple business systems and update daily. Citation and traceability workflows must match the latest ownership, transaction, and tax data. Expired information causes registration errors, so this step is critical.
Daily processing involves diverse document types. The system must support precise traceability for materials in different formats, including registration applications, ownership certificates, and real estate registers.
The ownership source and restriction status of real estate registration data directly affect the legality of final registration results. The traceability link must strictly link the generation time and source system of original data. Every verification basis must be traceable.
Cross-system data comparison is a common requirement. The traceability function must integrate citation paths from multiple sources. This prevents information bias from relying on a single source.

## Configuration Settings
All configuration settings below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Adapts to the length of single citation content for real estate registration documents. Avoids truncating key information such as core ownership details and real estate location. |
| `responseData` | Enabled | Must return the system name and generation time of the original data source. This meets traceability and compliance requirements for review workflows. |
| `detail` | Full | Displays core fields of cited content, such as right holder, right type, and restriction status. This helps reviewers quickly verify information. |
| Citation Sorting Logic | Weighted by content relevance + data source update time | Prioritizes matching the latest cadastral and transaction data. Also ensures content aligns with review requirements. |
| Citation Display Toggle | Configured per scenario | Internal review scenarios can hide citations. External display scenarios must clearly show citation sources. |
| Minimum Citation Relevance | `0.75–0.85` | Calibrated via actual testing. Filters irrelevant historical data and retains valid verification bases. |

## Three Common Configuration Errors
- Phenomenon: Knowledge base search returns citations in an unexpected order. Expired historical data appears at the top of results. Cause: No weighted sorting rule based on data source update time is configured. Only basic similarity sorting is used. Non-latest registration data is recalled first as a result.
- Phenomenon: Locally imported real estate registration data is not recalled. Citations from external data sources are returned instead. Cause: Data source filtering rules are not configured correctly. Or the chunks of the imported knowledge base do not match core fields such as real estate location and right type. The system fails to identify locally valid data as a result.
- Phenomenon: Citation content is forcibly displayed in the conversation interface. It cannot be turned off per scenario. Cause: The citation display toggle is not configured for different scenarios of internal review and external display. Default full-scenario citation display is enabled. Usage scenarios are not distinguished.

## How to Confirm Proper Configuration
- Submit a test review request that includes ownership certificates and surveying and mapping results. Check whether the returned citation content includes the system name and generation time of the corresponding data source.
- Adjust the minimum citation relevance configuration. Test the number of recalled citations under different thresholds. Confirm that the results meet the business review requirement range.
- Switch between internal and external scenario configurations. Confirm that the display status of citation content matches the requirements of the current scenario.
- Verify the `quoteMaxToken` configuration. Confirm that citation content from long documents is not truncated. Ensure core right information and real estate location details are retained.

The values provided are common starting points and should be measured against the reader's own samples.
