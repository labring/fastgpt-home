# Real Estate Registration Declaration Materials and File Review: Knowledge Base Retrieval and Recall

## Data Overview for This Use Case
The data for this use case comes from real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. The update frequency is daily. Commonly processed documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates and registers. Data fields include ownership numbers, surveying and mapping coordinates, tax payment information, certificate identifiers, and more. Most individual documents use a mixed format of structured and semi-structured content, with some electronic certificates using standardized packaging formats.

## Constraints for Knowledge Base Retrieval and Recall
Daily updated data requires the retrieval link to support incremental synchronization and incremental recall, to avoid performance loss caused by full-scan operations. The mixed multi-type document structure requires the retrieval model to adapt to both structured field matching and semi-structured text retrieval needs. The matching accuracy of core fields such as ownership numbers and surveying and mapping coordinates directly affects review results, so the recall weight of high-confidence fields must be prioritized. At the same time, verifying ownership sources and restriction status is the most time-consuming step. Retrieval must quickly locate associated ownership certificates and surveying and mapping data to shorten the overall review cycle. Cross-system data sources require the retrieval scope to be limited to knowledge base collections related to real estate registration, to avoid interference from irrelevant data.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the accuracy requirement for matching core ownership-related fields, avoids low-confidence results interfering with ownership verification |
| `limit` | Top 10 entries | Covers the common number of associated documents such as ownership certificates and surveying and mapping results linked to a single declaration material |
| `searchMode` | hybrid | Adapts to mixed document types with structured fields and semi-structured text, balancing keyword matching and semantic recall |
| `usingReRank` | Enabled | Improves the sorting priority of highly relevant documents, reducing the risk of false positives in ownership verification |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements keywords from declaration materials to expand the retrieval scope and cover cross-system associated data |
| `collectionIds` | Configured in groups based on real estate registration-related knowledge bases | Limits the retrieval scope to only knowledge bases related to ownership, surveying and mapping, and tax categories, avoiding interference from irrelevant data |

## Common Configuration Mistakes
- Issue: After upgrading FastGPT v4.17.0, retrieval latency for the same knowledge base increases significantly. Cause: No incremental recall strategy configured for the daily incrementally updated dataset, resulting in full-scan of all data for each retrieval.
- Issue: The front end cannot display retrieved document names or support click-to-view. Cause: Metadata return fields for retrieval results are not properly configured, and information such as document names and access links are not included in recall results.
- Issue: Reference variables display as empty after selecting a knowledge base. Cause: Knowledge base metadata fields are not properly mapped to reference variable templates, or associated retrieval configuration is not enabled.

## How to Verify Correct Configuration
- Review retrieval logs to confirm that returned document types include core documents for this use case such as registration applications and ownership certificates, and that the number of results matches the configured `limit` value.
- Submit a test query containing an ownership number or surveying and mapping coordinates, and verify that the `similarity` scores of retrieval results fall within the preset range.
- Check the running status of incremental synchronization tasks to confirm that daily updated data has been correctly included in the retrieval scope, with no synchronization delays.
- Test reference variable calls to confirm that fields such as document names and links in retrieval results can be properly called and displayed by the front end.

The values provided are common starting points and should be measured against the reader's own samples.
