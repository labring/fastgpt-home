# Proactive Public Disclosure and Policy Publication: Application Materials and File Review, Tool Calling and Plugins

This document is written for FastGPT v4.17.0.

## What the data for this category looks like
The data sources for this category include government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. The update frequency is daily. Daily processed documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Document fields cover document number, publishing entity, disclosure attribute, secrecy level, publishing time limit, associated columns, and more. Single document length varies widely, ranging from approval forms with hundreds of characters to policy documents with tens of thousands of characters.

## What constraints these characteristics impose on the tool calling and plugins workflow
High-frequency daily updated data sources require tool calling to adapt to batch synchronization logic to avoid overloading during single processing. The wide range of document types requires plugins to support text parsing and field extraction for different formats. Strictly validated fields such as disclosure attribute and secrecy level require tool calling to bind fixed validation rules to prevent accidental disclosure of sensitive information. The need to access cross-system data sources requires plugin configurations to be compatible with different interface formats, adapting to data pulling from multiple channels such as document management systems and government portals. Policy consistency requirements require the output of tool calling to go through preset rule validation to avoid misinterpretation.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic tool call triggering for multiple document types, no manual specification of call functions, suitable for the multi-document scenario of this category |
| `functionCall` | Triggered by public attribute verification and secrecy check | Matches the core fields that require mandatory verification in this category, ensuring the call logic complies with government disclosure compliance requirements |
| Batch execution node timeout | `600–1200 seconds` | Meets the time requirements for batch processing multiple policy documents and approval forms daily, avoiding single task interruptions |
| Tool call output toggle | Hide tool input and response | Meets the output simplicity requirements in government disclosure scenarios, avoiding internal verification details from being exposed externally |
| Database connection plugin configuration | Calibrated based on actual testing | Adapts to the interface formats of document management systems and government portals of different government departments, avoiding errors caused by incompatible configurations |
| Batch execution node loop limit | `First 200 items` | Matches the daily updated document volume, avoiding loop calls exceeding the system's single processing limit |

## Three common mistakes
- Symptom: Batch execution nodes run fully during online debugging but fail to complete when called via API. Cause: The API call does not have a timeout time configured for batch tasks, or the loop limit is set beyond the system's single processing threshold.
- Symptom: An error is triggered after configuring the database connection plugin. Cause: The interface permissions or data format of government department document management systems or government portals are not adapted, and the plugin configuration is incompatible with the data source.
- Symptom: Tool calling takes significantly longer than the model call grouping duration, with response content taking over 600 seconds to return. Cause: No sharding processing rules are set for batch tasks, and single call loads too much document data, leading to timeout.

## How to confirm the configuration is correct
- Trigger the tool calling workflow for a single policy document, verify whether the output result includes the preset public attribute verification result.
- Call the batch execution node, check whether timeout or interruption errors appear in the task log, and adjust the timeout time to meet task requirements.
- After configuring the database connection plugin, perform a data pulling test to confirm that document data from the document management system or government portal can be obtained normally.
- Enable the tool call output toggle, generate a test result, and confirm that internal tool input and response fields are not exposed externally.
