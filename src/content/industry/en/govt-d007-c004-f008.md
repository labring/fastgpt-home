# Proactive Public Disclosure and Policy Publication: Declaration Materials and File Review - Document Parsing and Chunking

## What the data for this category looks like
This category’s data comes from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. Documents processed daily include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. The data updates daily, covering proactive disclosure content from government departments at all levels. Document structures include fixed-format official documents with official letterheads, structured public disclosure directory entries, flexible press releases, and more. Some documents include metadata fields such as public attribute and confidentiality level.

## What constraints these characteristics impose on the document parsing and chunking workflow
The daily update frequency requires the parsing process to run efficiently, avoiding timeouts caused by batch processing. There are diverse document types, ranging from short texts like approval forms and column update records to long texts like policy compilations. The chunking logic must adapt to different content lengths. Data from multiple sources uses varying formats, such as structured formats from document management systems and HTML formats from portals. Parsing tools must support multiple input formats. The accuracy of public attributes and confidential information directly affects publication compliance. Chunking must retain key metadata to avoid losing core judgment basis after splitting. Unlike application-based public disclosure scenarios, this category must strictly match the entry structure of the public disclosure directory. Chunking must correspond to directory entries to ensure publication completeness and timeliness.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Adapts to the typical paragraph length of policy documents and interpretation drafts, avoids splitting key policy clauses or core content of approval forms |
| `chunkSplitter` | Split by title + paragraph | Matches the chapter structure of policy documents, retains contextual associations, avoids splitting policy content from the same paragraph into different chunks |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for large policy compilations and batch public disclosure directory files, avoids interrupting the parsing process due to timeouts |
| `customPdfParse` | Enabled | Adapts to the fixed header, footer and official letterhead formats of government documents, accurately extracts main body content and excludes redundant formatting information |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploading of large files such as policy compilations and quarterly public disclosure directories, adapts to daily batch processing needs |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters separately for different document types, adapts to differentiated processing of short-text approval forms and long-text policy documents |

## Three Common Mistakes
- When calling a specified large model, the file parsing tool fails to launch. This is shown by an interface prompt of "parsing service not found" or a 404 status code returned by the API. The cause is failure to correctly bind the parsing container corresponding to `customPdfParse`, or missing container mounting parameter configurations.
- The online version can parse complex formulas normally, but the local version cannot recognize formula content. This manifests as empty values or garbled characters in the formula area. The cause is incompatibility between the local FastGPT version and the formula parsing plugin version, or failure to install corresponding dependency packages.
- Parsed chunks lose metadata such as public attribute and confidentiality level. This is shown by an inability to filter content by public attribute during retrieval. The cause is that the `chunkSplitter` configuration does not enable metadata extraction, or the chunking logic does not retain additional document fields.

## How to Confirm the Configuration Is Correct
- Upload a policy PDF file with official letterhead format, and check that the parsed main body content is complete, with no redundant header, footer or official seal interfering content.
- Upload a structured public disclosure directory Excel file, and check that each chunk after chunking corresponds to a single directory entry from the original file, with no cross-entry splitting.
- Upload a policy compilation file under 1000 MB, and confirm that the parsing process does not trigger timeout errors, and all page content is correctly extracted.
- View the FastGPT v4.17.0 service logs, and confirm that the `customPdfParse` service starts normally, with no error messages about connection failures or configuration errors.

The values listed above are common starting points, and should be evaluated against the user's own samples.
