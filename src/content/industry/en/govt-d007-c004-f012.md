# Declaration Materials and File Review for Proactive Disclosure and Policy Publication: Deployment and Upgrade

## What This Category’s Data Looks Like
The data for this category comes from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. Daily documents include policy documents, policy interpretation drafts, disclosure directories, information release approval forms, press releases, and website column update records.

The data update frequency is daily. Synchronization of structured and unstructured documents from multiple sources is required. Documents contain exclusive fields such as disclosure attribute, confidentiality level, publication time limit, and column affiliation, and must strictly align with government disclosure specifications.

## Constraints Imposed on Deployment and Upgrade
The daily high-frequency update requirement means an incremental synchronization mechanism must be configured during deployment, to avoid excessive system resource usage from full data pulls. Documents from multiple sources and types require adaptation to different format parsing rules, so corresponding parsing logic must be pre-configured during deployment.

The exclusive fields for disclosure attributes and confidentiality reviews require configuration of field mapping rules aligned with government disclosure directories. The need to synchronize multiple website columns and new media accounts requires reserving interface configuration space for multi-channel publishing.

The risk of accidental disclosure of classified information requires configuring permission isolation and sensitive content verification modules during deployment, to ensure compliance of published content.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent requirements of daily high-frequency synchronization, avoiding database connection exhaustion |
| `PG_URL` | `postgresql://gov_user:gov_pass@pg-gov:5432/gov_public?schema=public` | Adapts to structured storage requirements for government data, used to store disclosure directory and approval form data |
| `MONGODB_URI` | `mongodb://gov_user:gov_pass@mongo-gov:27017/gov_docs?authSource=admin` | Stores unstructured policy documents and interpretation drafts, supports metadata management for daily incremental synchronization |
| `REDIS_URL` | `redis://:gov_redis_pass@redis-gov:6379/0` | Caches daily synchronization task queues and disclosure attribute verification results, reducing duplicate computation overhead |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage.gov.cn:9000` | Adapts to government intranet object storage services, used to store uploaded original documents and parsed text |
| `ROOT_KEY` | Set based on actual testing | Configures system administrator access permissions, isolating operation links for classified and non-classified data |

## Three Common Configuration Mistakes
- A `connection refused` error occurs during deployment, preventing associated services from starting. The cause is mixing container configurations for relational databases and vector databases, failing to correctly specify the `PG_URL` parameter to point to an independent pgvector instance, and incorrectly binding the vector database and relational database to the same container.
- Image pull failure occurs after startup, preventing system modules from loading. The cause is not using the official FastGPT v4.17.0 image, and using an image with an incompatible architecture instead, preventing the system from starting normally.
- Daily synchronization tasks fail to execute, and disclosure directory data is not updated. The cause is failing to correctly configure access permissions for `MONGODB_URI`, unable to read document metadata exported from the document management system, leading to interruption of the incremental synchronization process.

## How to Verify Configuration Correctness
- Log in to the system backend’s status monitoring page, check the connection status of `REDIS_URL`, `MONGODB_URI`, and `PG_URL`, and confirm all show normal.
- Manually trigger an incremental synchronization task, check that there are no data reading or parsing failure errors in the system logs, and confirm the document synchronization process is working properly.
- Check the field mapping configuration of the disclosure attribute review module, confirm it is fully aligned with the government disclosure directory, and can normally read document disclosure attributes and confidentiality levels.
- Upload a test policy document, confirm the system can generate the corresponding parsed text and synchronize it to the specified disclosure directory column, verifying the publishing process works properly.

The values provided are common starting points and should be measured against the reader's own samples.
