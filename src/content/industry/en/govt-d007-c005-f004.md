# Declaration Materials and File Review for Property Rights, Asset and State-owned Capital Management: Workflow Orchestration

## What the data for this category looks like
This category covers daily business documents from state-owned assets supervision institutions’ property rights departments, central enterprise asset management departments, property rights trading institutions, and evaluation agencies. Documents include property registration forms, asset evaluation reports, property rights transfer plans, on-site trading announcements, and asset disposal approval forms.
Data sources include state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, evaluation agency reports and financial statements. The update frequency is monthly.
Document structures include fixed fields such as ownership ID, asset category, evaluation value, and transaction progress. Units include standard business units such as ten thousand yuan, square meter, and piece.

## What constraints these characteristics impose on workflow orchestration
Monthly updated data sources require the workflow to include a scheduled synchronization node. This ensures the files and declaration materials used for review are the latest versions.
Mixed processing of multiple document types requires the workflow to split nodes for different formats. Each node adapts to the verification logic for property registration forms and asset evaluation reports.
Access to data from multiple systems requires a cross-source data aggregation node. This allows ownership verification to retrieve information from both state-owned assets systems and trading exchange systems simultaneously.
The serious consequences of errors require the workflow to include multi-level review nodes. Each verification step triggers result feedback and abnormal alerts.
The business focus on existing asset disposal requires the workflow to prioritize ownership verification and account-physical consistency checks before proceeding to follow-up evaluation filing and transaction review processes.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Loop trigger rule | Cycle through the asset ID list in `variables` | Declaration materials are submitted in batches per asset, so each asset’s ownership and file data must be traversed. |
| Tool call parameter mapping | Extract declaration material numbers and ownership fields from `variables` | Business query content must be accurately matched to the parameters required by the tool. |
| Workflow node timeout setting | 600 seconds | Reviewing a single asset evaluation report or property rights transfer plan requires a longer verification duration. |
| Batch processing node limit | First 20 asset IDs | Avoid overloading a single processing run, and align with the batch review rhythm of state-owned assets business. |
| Login-free publishing permission | Bind to internal office network segment | Declaration materials and files involve sensitive state-owned asset information. Access scope must be restricted. |
| Context window length | 8000 token | Multiple linked documents must be fully loaded for cross-verification. |

## Three Common Configuration Errors
- Workflow runs correctly in preview, but returns empty results after publishing the login-free application | The cause is that the login-free publishing did not configure internal network segment access restrictions, or did not map sensitive field permissions to public access rules.
- Cannot fill specified parts of user questions into parameters during tool calls | The cause is that the `variables` mapping rules were not correctly bound, so the required declaration material numbers or ownership fields were not extracted from the query parameters.
- Some asset files are missed during loop execution | The cause is that `nodeId` was not configured as the unique identifier for the loop body, leading to node status conflicts during batch processing.

## How to Verify a Complete Configuration
- Export the workflow configuration file, and check that the mapped fields in `variables` match the standard fields of property rights and asset documents.
- Trigger a test loop, and verify that `nodeId` generates a unique identifier for each loop node with no conflicts.
- Publish the login-free application, access it using the internal office network segment, and confirm that the returned results match the output from the preview stage.
- Adjust the context window length, and verify that multiple linked documents can be fully loaded for cross-verification.
