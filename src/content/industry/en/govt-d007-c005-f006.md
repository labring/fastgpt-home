# Declaration Materials and File Review for Property, Asset and State-owned Capital Management: Citation Source and Traceability

This document is written based on FastGPT v4.17.0.

## What this category of data looks like
Data for this category primarily comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, evaluation agency reports, and financial statements. The update frequency is monthly. Daily processed documents include property registration forms, asset evaluation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval slips. Most documents have fixed fields such as ownership number, evaluation benchmark value, and transaction approval node. The length of single documents varies widely.

## What constraints do these characteristics impose on the citation source and traceability link
Data sources are scattered across multiple internal and external systems. Traceability mechanisms must support associating original files from multiple platforms. The monthly update feature requires traceability configuration to adapt to periodic data synchronization logic. This ensures the latest asset data can be quickly traced. Large variation in document length requires precise positioning of the original document location corresponding to the cited fragment. Documents contain fixed ownership fields. Traceability must quickly match the original source corresponding to these fields to avoid confusion across documents. The rigor of the review process also requires traceability results to clearly point to the specific page or slice location of the original file. Vague source descriptions are not sufficient.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the wide variation in single document length for this category, ensuring complete context for cited fragments |
| `responseData` | Enable original file path and page number fields | Meets the review process requirements for precise traceability, enabling direct association with original documents |
| `detail` | Enable preview of original document before chunking | Supports users to directly view details of the original file before importing into the knowledge base |
| Single recall limit | Top 6 entries | Adapts to scenarios where this category requires checking multiple related materials, avoiding recalling too many irrelevant documents |
| Context window size | 4000–6000 characters | Balances traceability information and model processing capabilities, ensuring complete associated data required for review |

## Three Common Misconfigurations
- The citation snippet displayed in the interface cannot be associated with an online preview of the original file. The cause is that the `detail` configuration item is not enabled, or the configured preview path does not point to the storage location of the original file before importing into the knowledge base.
- A string of red numeric error is returned when calling FastGPT. The cause is that the `responseData` configuration does not correctly associate the storage interface of the original data, or there is a delay in cross-system data synchronization, making it impossible to obtain the metadata required for traceability.
- The output content does not show clear source identification. The cause is that the `responseData` configuration is not enabled, or the recalled document slices do not carry the corresponding original file metadata.

## How to Verify Correct Configuration
- Upload a typical document of this category, submit a query containing specific fields in the document, and check whether the output result includes original file path or page number information.
- View the document management interface of the knowledge base, and confirm that the storage path of the uploaded original file matches the configured preview path.
- Trigger a review process, and check whether the returned result includes a link or preview entry that can jump to the original document.
- Test the API call, and confirm that the returned `responseData` field includes relevant metadata of the original file.

The values provided are common starting points and should be measured against the reader's own samples.
