# Petition Case Handling: Declaration Materials and File Review - HTTP Interfaces and External Systems

## What this category of data looks like
Typical processing entities for this category include petition bureaus, departmental petition offices, subdistrict and township offices, and offices of responsible units. Data sources include the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. Data is updated daily.

Documents processed daily include petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-review applications, and resolution plans. Data fields cover the requesting party, matter content, handling progress, review results, and more. Each document is linked to a unique petition number, stored by handling stage, with no fixed per-document character limit, varying based on matter complexity.

## What constraints do these characteristics impose on the HTTP interfaces and external systems link
Data sources cover multiple external systems, so multiple types of external interfaces must be connected to pull and synchronize data, and authentication rules of different systems must be adapted. The daily update frequency requires interface calls to match batch pulling rhythms to avoid excessive calls consuming system resources.

Diverse document types and field structures require configuration to adapt to field mapping rules for different documents. Additionally, handling errors can lead to repeated or escalated petitions. The accuracy and completeness of interface return data must be strictly verified to prevent erroneous data from entering the handling process.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Application-specific API Key | FastGPT v4.17.0’s API Keys are divided into global general and application-specific types. Application-specific Keys can precisely limit call scope and avoid risks of global Key leaks |
| `variables` | Custom variables mapping petition document fields, such as `{petition number}`, `{handling status}` | Adapt to field differences across multiple document types in petition case handling, enabling precise extraction and transfer of data |
| `responseData` | Extract core fields such as `acceptance notice number`, `handling opinion content` | Only return core data required for business, reducing interface transmission load and improving processing efficiency |
| Interface timeout period | 600 seconds | Petition data pulling involves interactions across multiple systems, so sufficient response time must be reserved to avoid data synchronization interruptions due to timeouts |
| External system whitelist | Add domain names of connected systems such as the national petition information system and the 12345 citizen hotline platform | Limit interface call scope, improve system security, and prevent unauthorized access |

## Three common configuration mistakes
- Phenomenon: The `Key is error` error is returned, or a prompt indicates an incorrect API Key. Cause: The global general API Key was mistakenly used for application calls, and the application-specific Key provided by FastGPT was not used.
- Phenomenon: Errors such as `400 do request failed: Post "https://xxx dial t` are returned after calling the interface. Cause: The correct external system domain name whitelist was not configured, or network access permissions for the target system were not opened, causing the interface to fail to initiate requests normally.
- Phenomenon: The `responseData` field returned by the interface is empty. Cause: Correct field mapping rules were not configured via `variables`, so business-required content could not be extracted from the raw data returned by the external system.

## How to confirm the configuration is complete
- Call the test interface, check the returned `Authorization` authentication result to confirm that the application-specific Key has taken effect.
- Trigger a data pulling task, verify that the fields mapped via `variables` match the document fields returned by the external system.
- Check that the content extracted via `responseData` includes the core information required for business, with no redundancy or missing data.
- View system logs to confirm that no timeout or unauthorized error was triggered during interface calls, and that preset security rules are followed.
