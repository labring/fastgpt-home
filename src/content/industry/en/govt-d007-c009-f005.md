# Public Data Catalog and Disclosure: Declaration Materials and File Review - Tool Calling and Plugins

## What data in this category looks like
Data in this category primarily comes from local public data disclosure platforms, integrated big data platforms, departmental business databases, and electronic credential repositories. Daily maintenance documents include public data resource catalogs, data disclosure lists, data item descriptions, anonymization rules, interface documentation, and update frequency descriptions.
Data updates follow a monthly schedule. Core fields include data item codes, affiliated departments, disclosure conditions, anonymization rules, interface addresses, and update cycles. All content centers on shareable structured data assets. Authorization boundaries and usage restrictions must be clearly labeled.

## What constraints these characteristics impose on tool calling and plugins
Monthly updated data sources and document structures require tool calling to adapt to periodic data validation logic. This prevents calls to expired interfaces or outdated anonymization rules.
Mixed input scenarios with multiple document types require plugins to accurately identify specific fields such as data item codes and interface addresses. This avoids confusion between government public text and structured data assets.
Differences in data formats across multiple sources require plugins to support multiple database query and interface call formats. Plugins must also strictly follow authorization boundaries for data disclosure, and not exceed configured call ranges.
The monthly update schedule also requires plugin cache cycles to match the update frequency. This prevents returning outdated data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios, automatically matches tool requirements for declaration material review, and aligns with FastGPT v4.17.0 tool calling logic |
| `functionCall` | `required` | Ensures tool calling is forcibly triggered during the file review workflow, preventing omission of critical data validation steps |
| Tool timeout | `600 seconds` | Data interfaces and database queries typically require a certain response time. Monthly update data validation does not need an overly short timeout |
| Maximum number of returns per tool call | `Top 10` | Public data catalog entries have a moderate volume. Excessive returns increase context load and reduce review efficiency |
| Context window size | `8000 token` | Adapts to the combined document length of public data catalogs and case files, preventing content truncation |
| Plugin cache cycle | `30 days` | Matches the monthly update frequency, preventing calls to outdated public data catalog content |
| Plugin parameter validation toggle | Enabled | Strictly validates the legality of fields such as data item codes and interface addresses, preventing unauthorized calls to data resources |

## Three Common Misconfigurations
- Symptom: The SQL statement returned by tool calling fails to match interface fields in the public data catalog. Cause: The mapping relationship between data item codes and database table fields is not bound in the plugin configuration.
- Symptom: The plugin prompts for missing parameters during invocation, and cannot obtain anonymization rules for the specified data item. Cause: The data item name in the user query is not accurately mapped to the field corresponding to the `q` parameter in the plugin configuration, so the `q` parameter does not carry a valid data item identifier.
- Symptom: Tool calling returns outdated update frequency information. Cause: The plugin cache cycle is not set to match the monthly update schedule, resulting in calls to unupdated old data.

## How to Verify Proper Configuration
- Initiate a test query that includes a specific data item code, and verify that the tool call returns the corresponding data item description and interface address.
- Trigger a simulated monthly data validation task, and verify that the tool call automatically adapts to updated public data catalog content.
- Review plugin runtime logs, and confirm that the actual invocation status of the `toolChoice` and `functionCall` parameters aligns with configuration requirements.
- Simulate a query request that exceeds the authorization scope, and verify that the plugin blocks unauthorized calls and returns a clear prompt.

The values provided are common starting points and should be measured against the reader's own samples.
