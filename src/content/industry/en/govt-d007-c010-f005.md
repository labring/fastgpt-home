# Declaration Materials and Case Review for Highway Maintenance and Road Property and Right Management: Tool Calling and Plugins

This configuration is developed for FastGPT v4.17.0.

## What data looks like for this category
Daily documents for this category typically include maintenance plans, patrol logs, defect disposal forms, road construction permits, and road damage compensation forms. Data usually originates from highway maintenance management systems, bridge and tunnel monitoring systems, road patrol systems, and traffic flow monitoring data. The update frequency is daily. Document structures cover both structured fields and unstructured content. For example, patrol logs include fields such as patrol time, road section number, defect type, and disposal status. Road construction permits include information such as applicant subject and construction scope. Some documents include on-site photos or monitoring data files.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The need to access multi-source data requires plugins to adapt to API formats of different systems. This prevents call failures caused by incompatible data formats. The daily update frequency means tool calling must prioritize fetching the latest maintenance and road administration data. This ensures the timeliness of review. The diverse document types require tool calling to support structured field extraction and unstructured content parsing. This covers all review materials from table-based work orders to PDF-based permits. The high-risk nature of the business workflow also requires tool call results to accurately match business fields. This avoids road safety or financial disputes caused by incorrect information extraction.

## How to set the configuration

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Supports automatic tool calling for multiple types of review materials. No manual tool specification is needed, covering scenarios such as patrol logs and road construction permits |
| `functionCall` | `enabled` | Supports extraction of structured fields from defect disposal forms and road construction permits. This completes field verification and information matching for case files |
| Single tool call timeout | `60-120 seconds` | When connecting to multiple system APIs, sufficient time must be reserved to fetch cross-system maintenance and road administration data. This prevents call failures caused by interface delays |
| Tool call context limit | `8000-12000 token` | Must accommodate the full content of multiple documents including patrol logs, maintenance plans, and road construction applications. This prevents truncation of critical review information |
| Number of tool call results returned | `Top 3-5` | Case review only requires matching the latest maintenance work orders or road construction application materials. Excessive results will interfere with review judgments |
| Structured parsing rules | Configured according to maintenance business fields | Ensures that fields extracted by tools such as road section number and defect type fully match the fields in the business system |

## Three common mistakes
- Symptom: After an application is set as a team plugin, its functions cannot be called directly via tool calling. Empty results or parameter errors are returned. Cause: `toolChoice` is not correctly configured as `auto` or `required`, so the plugin is not automatically triggered.
- Symptom: After calling the CSV file collection interface, the generated dataset has fields that do not match the dataset created via the UI. Cause: No targeted structured parsing rules are configured, so the fields automatically identified by the tool do not match the road section and defect fields required for maintenance business.
- Symptom: Associated maintenance data can be obtained when previewing the plugin, but the final output is empty. Cause: The content returned by the plugin is not bound to the context generation step. This means the tool call results are not included in the final prompt processing workflow.

## How to confirm the configuration is correct
- Submit a simulated road construction permit declaration material to trigger the tool calling workflow. Check if the corresponding plugin is automatically called to extract associated road damage compensation form information.
- View the tool call log to confirm that the returned fields match the fields required for maintenance business, such as road section number, defect type, and disposal time.
- Simulate a system interface delay scenario to test the timeout threshold. Check if an expected error or retry mechanism is triggered.
- Compare the CSV dataset created via the UI with the dataset generated via interface calls. Confirm that the field structures fully match.
