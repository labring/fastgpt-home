# Declaration Material and Case Review for Pension, Work Injury, and Unemployment Benefit Verification: HTTP Interfaces and External Systems

## What data for this category looks like
This category draws data from social insurance management systems, personal benefit records, labor relations and work injury identification systems, and electronic social security card platforms. Data updates occur daily. Commonly processed documents include benefit application forms, payment period certificates, retirement approval forms, work injury identification materials, and unemployment benefit application materials. Data fields cover insured person identity identifiers, payment periods, work injury identification results, unemployment insurance enrollment durations, benefit calculation baseline values, and more. Documents exist as a mix of structured forms and scanned files, with no unified fixed field length limit.

## Constraints on HTTP Interfaces and External Systems from These Characteristics
Multiple internal systems provide data sources for this category, so interfaces must support different system return formats to avoid verification errors caused by format conversion. Daily data updates require interface cache durations to stay under 24 hours, to ensure retrieved information is up to date. Mixed document formats require interfaces to accept both text parameters and file streams, to adapt to different types of declaration materials. Core fields affect the accuracy of benefit calculations, so interface parameter verification must cover all required items to prevent errors and omissions in subsequent review steps.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {FastGPT-assigned API key}` | Follows the HTTP interface authentication specification for FastGPT v4.17.0, to ensure call legitimacy |
| `variables` | Pass fields including insured person ID number, benefit application type, business handling location, etc. | Adapts to benefit verification query needs for different insured groups, and associates corresponding data sources |
| `responseData` | Only return payment period, qualification verification result, and amount to be calculated fields | Streamlines returned content to reduce data transmission overhead |
| Request timeout duration | `300-600 seconds` | Covers processing duration for multi-system data aggregation and material verification, to avoid mid-process interruptions |
| Single file upload limit | `1000 MB` | Adapts to upload requirements for large documents such as work injury identification materials and retirement approval forms |

## Three Common Configuration Mistakes
- Issue: API calls return results that do not match those from the platform test interface, with core fields such as payment period left empty. Cause: Required parameters such as insured person identity identifier are not passed via `variables`, causing the interface to fail to associate the corresponding data source.
- Issue: Interfaces return 403 authentication failure errors. Cause: The `Authorization` parameter does not use the Bearer prefix, or an invalid API key is used.
- Issue: When batch processing benefit verification for multiple insured persons, some requests time out and interrupt. Cause: Request timeout duration adapted for multi-data aggregation is not set, exceeding system processing limits.

## How to Confirm Configuration Is Complete
- Call the interface with a test insured person identity identifier, and check whether the fields returned in `responseData` include expected benefit-related content.
- Check whether the format of the `Authorization` parameter conforms to the Bearer token specification, and confirm key validity via the platform's API key management page.
- Upload a single standard-sized business document, and confirm that the interface can normally receive the document and return verification results.
- After calling the interface, check whether the returned response format is JSON structured format, with no garbled characters or format errors.
