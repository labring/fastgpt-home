# Declaration Materials and Case Review for Pension, Work Injury, and Unemployment Benefit Verification: Multi-turn Dialogue and Prompt Engineering
This configuration guide is based on FastGPT v4.17.0.

## What the data for this category looks like
Data for this category comes from social insurance management systems, personal benefit records, labor relations and work injury identification systems, and electronic social security card platforms. The update frequency is daily.
Commonly processed documents include benefit application forms, payment period certification forms, retirement approval forms, work injury identification materials, and unemployment benefit application materials. Most documents contain fields such as identity identifiers, payment details, and qualification certificates. Some are structured forms, while others are unstructured materials in the form of scanned documents.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data comes from multiple sources and updates daily. This requires multi-turn dialogue to track the consistency of identity, payment, and work injury identification fields returned by different systems, to avoid referencing expired data.
Document formats are diverse, including structured forms and unstructured scanned materials. Prompts must adapt to extraction rules for both format types.
The review process focuses on payment period calculation and qualification verification. Multi-turn dialogue must break down questions according to business processes, gradually guide the supplementation of missing materials, and retain material information from historical conversations for context association.

## Three Common Misconfigurations
- Missing cite reference ID in dialogue requests: The symptom is that the interface response has no associated social security material reference identifier field. The cause is that the configuration did not enable traceability binding for multi-source data, or did not associate document metadata from social security business systems.
- Lost historical question keywords in multi-turn dialogue: The symptom is that subsequent replies do not reference previously mentioned content such as payment periods or work injury identification numbers. The cause is that session context was not bound via `chatId`, or the maximum context configuration was too short, resulting in historical information being truncated.
- Agent runtime outputs thought process without hiding it from conversation records: The symptom is that model thought logs are displayed in the interface conversation. The cause is that the configuration did not turn off the agent's thought process output switch, or did not filter non-answer content returned by the agent.

## How to Confirm Proper Configuration
- A multi-turn dialogue containing payment period and work injury identification information should be initiated, and whether subsequent replies reference previously mentioned fields should be verified.
- The dialogue interface should be called, and whether the response contains traceability identifiers associated with social security business materials should be checked.
- After configuring the agent, a test conversation should be initiated, and it should be confirmed that the interface display only includes business reply content, with no additional thought process.
- `chatId` values across different sessions should be tested, and it should be confirmed that conversation history for the same session is correctly retained, and context between different sessions does not interfere with each other.

The values provided are common starting points and should be measured against the reader's own samples.
