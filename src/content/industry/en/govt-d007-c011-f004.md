# Declaration Materials and File Review for Pension, Work-related Injury, and Unemployment Benefit Verification: Workflow Orchestration

This page configuration is based on FastGPT v4.17.0.

## What the data for this category looks like
Data for this category originates from social insurance handling systems, personal benefit records, labor relations and work-related injury identification systems, and the electronic social security card platform. Data is updated daily.

Daily processed documents include benefit application forms, payment period certificates, retirement approval forms, work-related injury identification materials, and unemployment insurance benefit application materials. Core fields cover payment periods, benefit calculation standards, qualification review conditions, and more. Individual file sets include insurance participation information, work-related injury identification results, unemployment registration status, and other business-related fields.

## What constraints these characteristics impose on the workflow orchestration link
Decentralized data sources require workflows to be configured with multiple data source pull nodes. The daily update frequency requires scheduled scheduling rules for process trigger nodes.

Multiple types of business documents require format verification and field matching nodes in the workflow. This ensures core fields of different materials meet review standards. Core fields relate to benefit calculation and qualification judgment. The workflow must set multi-layer verification links to prevent erroneous data from entering subsequent stages. It must also retain review traces to meet compliance requirements.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| System configuration interface address | Official interface address corresponding to the social insurance handling system | Required parameter for connecting to business systems. Use interface addresses accessible in the production environment. |
| HTTP request node timeout | 600 seconds | Social security business system interface responses have certain delays. Reserve sufficient waiting time. |
| JSON content extraction rules | Configure extraction paths using jsonPath syntax | Used to extract core fields such as payment periods and benefit standards from insurance participation data returned by interfaces. |
| Maximum number of fields extracted per request | First 10 entries | Control the volume of data returned by interfaces to avoid excessive workflow load. |
| `variables` configuration | Define core field variables for benefit verification | Uniformly manage reusable review data in the workflow to avoid repeated configuration. |
| `nodeId` naming | Name according to node function, such as "Pull insurance participation data" | Facilitate cross-node reference and debugging in the workflow. |
| Scheduled trigger setting | 1 time per day | Match the daily update frequency of business data. |

## Three Common Mistakes
- Phenomenon: HTTP request nodes return empty fields or 404 errors. Cause: Interface address is not correctly configured as a production-environment accessible social security system address, or interface access permissions are not enabled.
- Phenomenon: Extracted JSON content cannot be passed to downstream nodes. Cause: `variables` configuration is not correctly enabled, or extracted fields are not bound to workflow variables.
- Phenomenon: Workflows cannot be imported normally after export. Cause: Complete workflow configuration was not saved as required, or the exported file is corrupted.

## How to Confirm Configuration is Complete
- Run a test workflow, check if the return results of each node include expected fields such as insurance participation information and benefit standards.
- Trigger the scheduled scheduling node, confirm that the workflow starts automatically at the specified time with no abnormal interruptions.
- Verify that the variable names configured in `variables` match the reference names used in downstream nodes.
- Export the workflow configuration file, confirm that parameters for all nodes have been correctly saved with no missing items.
