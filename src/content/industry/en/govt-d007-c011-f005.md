# Declaration Materials and Case Review for Pension, Work Injury, and Unemployment Benefit Verification: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from social insurance management systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily.
Commonly processed documents include benefit application forms, payment period certificates, retirement approval forms, work injury certification materials, and unemployment benefit application materials.
Core fields include payment period (unit: year or month), benefit calculation standards (unit: yuan), qualification certification numbers, and others. The character volume of individual case file materials varies widely, ranging from hundreds to tens of thousands of characters.

## How these characteristics create constraints for the tool calling and plugins workflow
Multiple and scattered data sources require tool calling to adapt to the calling logic of multiple system interfaces. Exclusive calling rules must be configured for the three different verification scenarios of pension, work injury, and unemployment.
Daily updated data requires tool calling to match real-time synchronized data sources, avoiding expired payment records or certification materials.
The wide span of document character volume requires adjusting the context bearing parameters of tool calling to adapt to case file materials ranging from hundreds to tens of thousands of characters.
The accuracy of core fields is directly linked to benefit calculation results. Tool calling must add a parameter verification link to ensure that the formats of fields such as incoming payment period and benefit standards meet business requirements.

## How to configure settings
All configurations below are written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match tools corresponding to the three verification scenarios of pension, work injury, and unemployment to adapt to business diversity |
| Single tool call timeout | 600 seconds | Social security system interface responses have certain delays; 600 seconds covers most normal call scenarios |
| `functionCall` | Enable strict parameter verification | Ensure that the formats of core fields such as incoming payment period and benefit standards meet business requirements |
| Tool execution order configuration | Execute in accordance with business process sequence | Benefit verification requires completing material verification, qualification review, and benefit calculation in sequence; sequential execution avoids logical conflicts |
| Knowledge base binding scope | Bind the exclusive document library for this category | Ensure that the latest business data such as payment records and certification materials can be obtained during tool calling |
| Tool call retry count | 2 times | Respond to call failures caused by temporary network fluctuations; 2 retries balances success rate and time consumption |

## Three common misconfigurations
- Symptom: Tools do not execute in the expected order, and some tools are not triggered. Cause: The tool execution order is not configured correctly, or there is a conflict in the tool binding logic in the workflow.
- Symptom: A parsing failure error is returned when calling tools for a specific system. Cause: The tool parameter format corresponding to the business is not matched, or the data source interface permission configuration is incorrect.
- Symptom: An empty result is returned after tool calling. Cause: The exclusive knowledge base or data source for this category is not bound, so corresponding payment records, certification materials and other data cannot be obtained.

## How to confirm the configuration is complete
- Trigger a simulated pension benefit verification request, view the tool call log, and confirm that `toolChoice` automatically matches the corresponding business tool.
- Execute the complete tool calling process, check whether the execution order of each step matches the business process of material verification, qualification review, and benefit calculation.
- Pass in core fields with incorrect formats, such as filling in the payment period in a non-year/month format, and confirm that the strict verification mode of `functionCall` triggers an intercept.
- View the data source binding status, and confirm that the exclusive data sources for this category such as social insurance management systems and personal benefit records have been associated.
