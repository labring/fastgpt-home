# Declaring Materials and File Review for Pension, Work Injury, and Unemployment Benefit Verification: Source Citation and Traceability

## What this category of data looks like
This category of data primarily comes from social insurance handling systems, personal benefit record systems, labor relations and work injury certification systems, and electronic social security card platforms. It updates once per day. Documents processed daily include benefit application forms, payment period certificates, retirement approval forms, work injury certification materials, and unemployment benefit application materials. Core fields include applicant identity information, payment years, work injury certification results, and benefit verification standards. Most documents are structured forms or standardized electronic files. Fields must strictly match registered information in social insurance systems.

## How These Characteristics Impact the Source Citation and Traceability Process
Daily updated data sources require the traceability process to quickly retrieve the latest data. This avoids use of expired payment records or work injury certification results. Mixed processing of multiple standardized documents requires the traceability system to identify field correspondence across different documents. This ensures cited materials and verification basis are accurately matched. Strong correlation with applicant information requires traceability results to bind precisely to the specific applicant. This prevents cross-subject citation errors. The rigor of benefit verification requires traceability content to fully cover all basis for qualification review and benefit calculation. This prevents omission of key supporting materials.

## Configuration Settings
| Config Item | Recommended Value | Basis for This Value |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Covers core fields of a single social insurance benefit-related document, avoiding truncation of critical information |
| `responseData` | Enabled | Allows calling structured data from social insurance handling systems as traceability sources to meet review requirements |
| `detail` | Top 3–5 entries | Retrieves materials directly related to the current verification task, avoiding interference from redundant information |
| Context window size | 1500–2000 tokens | Integrates all relevant materials for the applicant, ensuring complete verification basis |
| Request timeout threshold | 30 seconds | Adapts to response times of social insurance system interfaces, avoiding loss of traceability data due to timeout |

## Three Common Mistakes
- Issue: An error occurs when calling HTTP interface data from social insurance handling systems. Cause: The data source switch corresponding to `responseData` is not enabled, or the interface is not configured as an allowed traceability source.
- Issue: Outputted cited content includes a large number of irrelevant materials not related to the current verification task. Cause: No upper limit is set for the number of `detail` retrievals, resulting in retrieval of excessive redundant data.
- Issue: The content of cited payment period certificates is truncated and cannot be fully displayed. Cause: The value set for `quoteMaxToken` is too small to cover all core fields of a single document.

## How to Confirm the Configuration Is Correct
- Log in to the FastGPT v4.17.0 backend, initiate a simulated benefit verification request, and check whether returned results include clear data source identifiers and update times.
- View the retrieval list in the traceability module, confirm that only materials related to the current applicant are displayed, with no cross-subject irrelevant content.
- Verify that cited document content fully covers core fields, and confirm that the value set for `quoteMaxToken` meets requirements.
- Test calling the configured social insurance interface data, confirm that the `responseData` switch takes effect and traceability content can be normally obtained and displayed.
