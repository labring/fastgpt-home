# Declaration Material and File Review for Pension, Work Injury, and Unemployment Benefit Verification: Document Parsing and Chunking

## Data Profile for This Category
This category of data originates from social insurance handling systems, personal benefit records, labor relations and work injury verification systems, and the electronic social security card platform. The update frequency is daily. Documents processed daily include benefit application forms, payment period certificates, retirement approval forms, work injury verification materials, and unemployment insurance benefit application materials. Most documents are standardized forms or structured text. Fields include insured person identity information, payment period, work injury rating, unemployment insurance enrollment duration, and similar items. Units involved include month, year, and yuan. Some documents exist as scanned copies or handwritten supplementary entry formats.

## Constraints on Document Parsing and Chunking
Mixed document structures of standardized forms and scanned copies require parsing links to support multiple input formats and retain structured field associations. Daily updated business data volumes require parsing processes to have stable concurrent processing capabilities and reasonable timeout settings. Precise extraction of core fields such as insured person identity, payment period, and benefit standard requires retaining contextual relevance during chunking, to avoid splitting content across fields. OCR errors in scanned copies require configuring fault-tolerant parameters to reduce the impact of recognition errors on subsequent reviews. Differences in document structures across insurance types require chunking rules to adapt to multiple document templates.

## Configuration Settings
These configurations are based on FastGPT v4.17.0, and are adapted for the declaration material parsing scenario for pension, work injury, and unemployment benefit verification.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the field block length of standardized social security documents, avoids splitting continuous core text containing payment period and benefit standards |
| `chunkSplitter` | Split by paragraph + semantic boundary | Matches the structured paragraph structure of social security documents, retains the relevance of insured person information and content related to benefit calculation |
| `customPdfParse` | Enable OCR enhancement mode | Adapts to the parsing needs of scanned work injury verification materials and paper application forms, improves recognition accuracy for mixed handwritten/printed text |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time consumption for long documents or batch scanned copies, prevents task failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to the maximum document size limit for single-batch declaration materials, meets the batch upload scenario of street social security service windows |
| `chunkSettingMode` | Manual configuration mode | Flexibly adjusts chunking rules for the different document structures of the three types of businesses: pension, work injury, and unemployment |

## Three Common Configuration Mistakes
- Parsing tasks return connection failure errors, with logs showing failure to connect to the locally deployed parsing service. The cause is incorrect configuration of the local service address corresponding to `customPdfParse`, or ineffective Docker container port mapping, which prevents FastGPT from calling the parsing component.
- Core fields are empty after parsing uploaded social security declaration documents. The cause is an excessively small `chunkSize` setting, which splits continuous text containing payment period and benefit standards into multiple incomplete chunks, resulting in lost field associations.
- Timeout errors occur when uploading multiple documents in batch. The cause is an excessively short `PARSE_FILE_TIMEOUT_SECONDS` setting, which does not reserve sufficient time for complete parsing of long documents or scanned copies.

## How to Verify Correct Configuration
- Upload a standardized pension benefit application form, review the field integrity of the parsing result, and confirm that core information is not split or lost.
- Attempt to upload a scanned copy of work injury verification material, verify whether the OCR enhancement mode is active, and check for inclusion of handwritten supplementary content in the parsing result.
- Adjust `PARSE_FILE_TIMEOUT_SECONDS` to 600 seconds, then upload a batch of documents with individual sizes under 100 MB, and confirm that no timeout error occurs for tasks.
- Review parsing logs in the FastGPT backend, confirm that the parsing service connection is normal, with no connection failure or timeout records.
