# Declaration Materials and Case File Review for Elderly Care Service Institution Supervision: Vector Models and Indexes

## What this category of data looks like
This data serves elderly care service departments of civil affairs bureaus, sub-districts, towns, and joint supervision departments. Daily processed documents include elderly care institution filing materials, operation subsidy applications, service quality inspection reports, safety hazard rectification ledgers, elderly admission files, and more. Data comes primarily from elderly care service information platforms, civil affairs statistics systems, fire inspection records, and institution operation ledgers, with a monthly update frequency. Documents include both structured tables and unstructured text. Fields include institution name, filing number, bed count, rectification requirements, and more, along with unit identifiers such as beds (units) and subsidy amount (yuan).

## What constraints do these characteristics impose on the vector model and index link
The multi-source and multi-format nature of elderly care supervision data requires the index system to support mixed-format document parsing and batch import. The monthly update frequency requires configuration for incremental indexing, to avoid resource consumption from full reconstruction. Structured fields such as bed count and subsidy amount require the index to retain metadata to distinguish field attributes, preventing confusion between different types of information during semantic matching. The 100,000-scale CSV ledger data requires the import process to include abnormal row filtering and breakpoint resume capabilities, to prevent data loss.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Ensures semantic integrity for unstructured documents such as elderly care filing materials and rectification ledgers, avoiding loss of cross-paragraph supervision-related information due to overly small chunks |
| Overlap Length | 100–150 characters | Covers key content across chunks, such as cross-page requirements for safety hazard rectification and supplementary explanations for institution filings |
| `maxToken` | 4096 token | Adapts to the input length limit of mainstream embedding models, matching the average semantic volume of chunked elderly care documents |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Distinguishes valid matching results for elderly care institutions, avoiding misjudgments of similar institution names or bed count data |
| Single Search Limit | Top 10 results | Controls the number of returned results, adapting to the batch verification needs of supervision reviews |
| `defaultToken` | 1024 token | Unifies the embedding length of basic contexts, ensuring index consistency across different documents |

## Three common configuration errors
- Phenomenon: After importing 100,000 CSV-format institution operation ledgers, the total number of entries after indexing is less than the source data. Cause: The import process was not configured with a skip rule for abnormally formatted rows. Some ledger rows containing empty fields or special characters were not correctly identified, leading to automatic filtering during indexing.
- Phenomenon: The vectorization task remains in the indexing state for a long time with no progress updates. Cause: A reasonable `defaultToken` length was not configured, leading to timeout when calling the embedding model, and breakpoint resume functionality for batch imports was not enabled, resulting in inability to resume after task interruption.
- Phenomenon: Vector calculation scores are abnormally high, with multiple results showing identical scores. Cause: The chunk length was set too large, leading to overly high semantic overlap between chunks from different documents, making it impossible to distinguish differences between institutions during matching.

## How to confirm configurations are properly applied
- Randomly select 10 chunks of elderly care institution filing materials, check whether the chunk length falls within the preset 800–1200 character range, and whether overlapping parts cover key supervision fields such as filing number and bed count.
- Import a 100-entry test CSV file of institution bed count data, verify that the total number of entries after indexing matches the source data, confirming no abnormal data filtering.
- Submit a typical supervision query, such as "Verify the safety hazard rectification status of a certain elderly care institution", check whether the similarity scores of returned results fall within the preset 0.75–0.85 range, with no abnormally high scores.
- View the embedding task logs in FastGPT v4.17.0, confirm that no `maxToken` overlimit error prompts are triggered, and that the parameter configurations have taken effect.
