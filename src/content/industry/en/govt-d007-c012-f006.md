# Declaration Material and Case File Review for Elderly Care Service Institution Supervision: Citation Source and Traceability

This document is written based on the configuration logic of FastGPT v4.17.0.

## What this category’s data looks like

Data for this category typically originates from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institution operation ledgers. The update frequency is monthly.

Daily documents include filing materials, operation subsidy applications, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. Fields cover three categories: institution qualifications, operation data, and safety inspection results. No unified fixed format exists. Some documents are structured forms, others are semi-structured ledgers. Fields include institution name, filing number, service volume, hazard level, and more. No unified naming convention is used.

## Constraints on citation source and traceability

As data sources are scattered and field naming is inconsistent, the citation traceability link must first complete cross-system field mapping to avoid matching failures caused by name differences. The monthly update frequency requires configuring a regular synchronization mechanism to ensure cited content is the latest version and prevent use of expired data.

Mixed use of multiple document types requires setting differentiated matching rules for different documents to ensure citation accuracy for structured forms and semi-structured ledgers. Review errors can lead to incorrect subsidy distribution or safety accidents, so the uniqueness of citation sources must be strictly limited to prevent risks from fuzzy matching.

## Configuration settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Filing materials and rectification ledgers for elderly care service institutions have large individual text volumes. This parameter limits the total length of cited segments to adapt to the context requirements of multi-document splicing |
| `responseData` | Return institution name, filing number, hazard rectification status | Supervision review core needs to trace qualification certificates and safety rectification results. Accurately returning specified fields filters redundant information and improves traceability efficiency |
| `detail` | Enabled | Specific source system and record number of citations must be displayed to meet the traceability and archiving requirements of case file review |
| Single search limit | Top 3 entries | Supervision documents of the same category have duplicate fields. Limiting the number of search results avoids redundant citations and focuses on core matching content |
| Knowledge base automatic synchronization | Execute monthly | Business data update frequency is monthly. Synchronization cycle matches data update rhythm to ensure cited content is the latest version |

## Three common configuration errors

- Symptom: When configuring `responseData`, required return fields are not specified, resulting in empty returned content. Cause: No data source fields to extract are declared in the knowledge base configuration, so corresponding content cannot be matched during citation.
- Symptom: An error "Cannot redefine property: toString" occurs in the production environment. Cause: System built-in `toString` property is redefined, usually caused by conflicts in custom scripts or node configurations.
- Symptom: No corresponding variable options are available when selecting a knowledge base. Cause: Structured field mapping is not configured in the data source associated with the knowledge base, or the automatic synchronization function for variable references is not enabled.

## How to verify successful configuration

- Submit a test query, such as "Please trace the filing materials of XX elderly care institution", check if the returned results include the specified source fields and numbers.
- View the knowledge base synchronization log to confirm that the most recent synchronization time matches the monthly update cycle.
- Trigger a test call to check if the length of the returned citation segment is within the range limited by `quoteMaxToken`.
- Check custom node configurations to confirm no duplicate system property definitions exist, to avoid runtime errors.
