# Declaration Materials and File Review for Internal Control Evaluation, Audit and Rectification: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data comes from enterprise internal control systems, ERP, financial sharing systems, audit management systems, and procurement contract project systems. The update frequency is annual. Commonly processed documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closing certificates. Document fields include audit item number, rectification responsible person, completion deadline, supporting material association identifier, and other fields. The character count of individual documents varies widely, ranging from thousands to hundreds of thousands of characters.

## What constraints do these characteristics impose on the HTTP interfaces and external systems link
Batch documents updated annually require interfaces to support large-volume file segmented uploads to avoid single-request timeouts. The need to connect multiple system data sources requires interfaces to support format conversion and adaptation of multi-source data, compatible with field structures returned by different systems. The requirement for standardized document fields requires interfaces to support custom field mapping, converting fields from external systems into the platform's unified review fields. The need to associate supporting materials such as rectification closing certificates requires interfaces to support simultaneous transmission of file streams and metadata, ensuring traceability during the review process.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Bearer plus the API key generated by the platform | Complies with identity authentication specifications of external systems, ensuring the legitimacy of interface calls |
| `variables` | Configures custom field variables such as audit item number and rectification responsible person | Adapts to field naming differences across different external systems, enabling standardized data mapping |
| `responseData` | Returns only approved rectification ledger entries | Filters invalid data, reducing platform processing load |
| Interface timeout duration | 600 seconds | Adapts to the upload and processing duration of large-volume audit documents |
| Field mapping rules | Map external system field names to platform review fields | Ensures data pulled from external systems can be correctly recognized by the platform |
| Request retry count | First 3 attempts | Addresses interface call failures caused by temporary network fluctuations |

## Three common configuration mistakes
- A 401 Unauthorized error is returned when calling the interface. The cause is that the `Authorization` parameter is not configured with the correct Bearer prefix or the key is invalid.
- An error occurs in the AI chat component used in the workflow. The cause is that the interface address of the external system is not correctly associated in the configuration file, resulting in failure to pull data normally in the private deployment environment.
- The pulled rectification ledger data fields are empty. The cause is that the field mapping rules corresponding to `variables` are not configured, so external system fields cannot be converted into a format recognizable by the platform.

## How to confirm the configuration is correct
- On the FastGPT v4.17.0 interface debugging page, a test external system interface address is input. After the interface is called, check whether the returned `responseData` includes the expected audit working paper fields.
- The configuration of the `Authorization` parameter is reviewed. A valid key is generated using the key generation tool provided by the platform, and a 200 status code is verified to be returned after the call.
- After the field mapping rules are configured, a test rectification ledger document is uploaded. Verify whether the platform correctly recognizes fields such as the rectification responsible person and completion deadline.
- Annual batch data upload is simulated. Verify whether the interface completes the request and returns valid results within 600 seconds.
