# Declaration Materials and File Review for Internal Control Evaluation, Audit and Rectification: Deployment and Upgrade

## What the Data for This Category Looks Like
This category of data originates from central enterprise internal control departments, audit departments, finance departments, subordinate enterprises, and external audit institutions. It is collected from enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems. Commonly processed documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Data updates occur annually. Documents contain structured business fields and unstructured attachments. Fields vary based on document business attributes, with no unified fixed unit.

## What Constraints These Characteristics Impose During Deployment and Upgrade
Annual batch-updated data has a large scale. Configure parameters adapted for large-capacity storage during deployment. Documents include unstructured attachments and structured fields, so support multi-modal parsing and structured extraction. Documents generated through multi-stakeholder collaboration require permission isolation parameters. These parameters ensure different departments can only access files within their corresponding permissions. Sensitive credential documents such as rectification closure certificates need accurate matching with business fields, so optimize index matching rules. Retain existing audit workflows and agent configurations during upgrades to avoid disrupting active internal control and audit processes.

## Recommended Configuration Settings
Based on the FastGPT v4.17.0 deployment specifications, adjust the following configuration items to match the characteristics of this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Internal network access address adapted for the enterprise's internal object storage | This category of documents includes unstructured attachments such as rectification closure certificates, requiring stable internal network storage and access |
| `REDIS_URL` | Configure a Redis instance with 8 GB of memory, set connection timeout to 300 seconds | Annual batch data updates require stable cache support to avoid interruptions during index construction |
| `MONGODB_URI` | Allocate no less than 5000 MB of storage space | Store structured documents such as audit working papers and issue lists, adapting to annual data incremental requirements |
| `DB_MAX_LINK` | Set to 20 | Adapt to the concurrent access needs of multiple departments accessing audit files simultaneously, avoiding database connection exhaustion |
| `FILE_TOKEN_KEY` | Configure the enterprise's unified internal file access key | Ensure that access permissions for sensitive documents such as rectification closure certificates are controllable, preventing unauthorized access |
| `ROOT_KEY` | Assign a dedicated key based on the enterprise's internal permission system | Isolate knowledge bases and agent configurations for different audit projects, avoiding cross-project data confusion |

## Three Common Misconfigurations
- Symptom: Some image attachments of rectification closure certificates cannot be recognized, and the interface returns "No valid text extracted". Cause: The storage path for multi-modal parsing is not configured, or the storage pointed to by `STORAGE_S3_ENDPOINT` does not have image access permissions enabled.
- Symptom: After directly upgrading from v4.12.3 to v4.14.29, published audit agents cannot load original workflow configurations. Cause: The database configuration associated with `PG_URL` was not backed up in advance, and compatibility processing was not performed for database table structure changes during the upgrade.
- Symptom: Timeout errors occur when batch importing audit working papers, with the log returning a 504 status code. Cause: The cache instance configured in `REDIS_URL` has insufficient memory, unable to support index construction caching for batch documents.

## How to Verify Correct Configuration
- Upload an image attachment of a rectification closure certificate, verify that text and metadata can be successfully extracted.
- Call the cache instance corresponding to `REDIS_URL`, check if there are index cache records for audit files.
- Test accounts from multiple departments accessing their respective authorized audit knowledge bases via `FE_DOMAIN`, confirm that permission isolation is effective.
- Execute an annual batch data import task, verify that there are no connection exhaustion or timeout errors.
