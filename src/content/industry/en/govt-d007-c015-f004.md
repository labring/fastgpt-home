# Medical Insurance Fund Supervision Audit: Declaration Material and Case File Review - Workflow Orchestration

## What data does this category process?
Data sources for this category include the medical insurance intelligent monitoring system, fund supervision rule base, medical insurance settlement data, drug and consumable traceability codes, and report clues. The update frequency is monthly.
Documents processed daily include audit notices, inspection work drafts, suspicion lists, interview records, handling decision letters, and rectification reports. Core fields cover violation types, involved expense amounts, designated medical institution names, medical treatment personnel information, and more. There is no unified fixed format, so processing must be adapted to each individual document's structure.

## What constraints do these characteristics impose on workflow orchestration?
The monthly update frequency means the workflow does not need high-frequency real-time triggering, and scheduled scheduling tasks can be configured.
Multiple document types and non-standardized fields require the workflow to adapt to node processing for different formats, so format conversion steps must be added.
Multiple data source access requirements require the workflow to configure multiple nodes to call different data sources.
The most time-consuming steps of suspicion screening, material retrieval, and violation determination must be split into independent orchestration steps to optimize execution efficiency.
The risk of fund loss and the consequences of errors require the workflow to configure failure retry and exception alert mechanisms.

## Recommended configuration settings
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| Variable Configuration | `variables` set as fixed parameters including suspicion list ID, institution name, and violation type | Ensure core audit business fields are stably passed between nodes |
| Node Timeout Setting | 600 seconds | Match conventional processing time for retrieving medical records, prescriptions, and cross-system data |
| Branch Trigger Rule | Trigger corresponding branches by matching suspicion result status via `nodeId` | Divert to different processing flows to adapt to the graded disposal logic of audits |
| Single Data Retrieval Count | First 5 entries | Control data loading volume per node to avoid operational lag |
| Timeout Retry Count | 3 times | Match exception recovery requirements of the audit process, avoid process interruption from a single failure |
| Response Format Control | Only return structured text no longer than 1000 characters | Adapt to generation requirements for standardized documents such as handling decision letters and rectification reports |

## Three common configuration mistakes
- After configuring a login-free window to bind an external API key, actual calls consume the platform's default quota. The symptom is that the operation log shows the API call source is the platform's public key. The cause is that the custom API key binding parameter was not correctly configured in `variables`.
- Using a specified response node to output HTML code does not display properly, and the process proceeds directly to the next branch. The symptom is that the node output field is empty, and the process skips the current step. The cause is that the raw content output switch for the node was not enabled, causing HTML tags to be automatically filtered.
- A single workflow execution time exceeds the preset threshold. The symptom is that the operation log shows a node timeout alert. The cause is that long document processing steps were not split, and the volume of medical insurance settlement data loaded by a single node is too large.

## How to verify correct configuration
- Trigger a test run, check whether the business parameters in `variables` are correctly passed to the input fields of each node.
- Simulate suspicion results of different levels, verify whether the branch trigger rules jump to the corresponding processing steps as expected.
- View the tool call configuration page, confirm that the input and output display switches for knowledge base search have been turned off.
- View the operation log, confirm that the node timeout setting does not trigger abnormal error reports, and the process execution meets expectations.
