# Medical Insurance Fund Supervision Audit: Declaration Materials and File Review - Tool Calling and Plugins

## Data overview for this category
The entities involved in this category include medical insurance fund supervision divisions of medical insurance bureaus, medical insurance handling institutions, flight inspection teams, and designated medical and pharmaceutical institutions. Daily processed documents include audit notices, inspection work papers, suspicious point lists, interview records, handling decision documents, and rectification reports. Data sources include intelligent medical insurance monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and report clues. The update frequency is monthly. Core time-consuming links include screening suspicious points from settlement data, retrieving medical records, prescriptions and charging records, identifying non-compliant expenses and forming handling opinions. Consequences of errors include fund losses, recovery of disallowed payments, suspension of service agreements, or administrative penalties.

## Constraints on tool calling and plugins workflow
The data sources for this category are scattered across multiple systems, requiring tool calling to support cross-data source linkage. The monthly update frequency means real-time data synchronization is not needed, but regular incremental pull trigger rules must be configured. Document types include structured suspicious point lists and unstructured medical records, so different types of tools must be called to handle each. The automation requirements for core time-consuming links mean tool calling must automatically match different nodes in the audit workflow to reduce manual intervention.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the need for automatic matching of multiple tools to suspicious point processing nodes in audit scenarios |
| Single tool call timeout | `600 seconds` | Covers the reasonable time required to retrieve settlement data and medical records across multiple medical insurance systems |
| Maximum tool call retries | `2 times` | Avoids occupying public resources of medical insurance supervision systems with repeated requests |
| `functionCall` format validation | Enabled | Aligns with the interface parameter format requirements of medical insurance fund supervision systems |
| Tool call result aggregation rule | Aggregate by suspicious point list | Matches the business logic of organizing audit files by suspicious point groups |

## Three common misconfigurations
- Symptom: Calling the medical insurance settlement data interface returns a 400 status code with no response body. Cause: Failure to add the required request header parameters specified by the medical insurance supervision system in the tool configuration results in authentication failure.
- Symptom: When using the Qwen2 series models, the generated function call parameters do not comply with audit rules, resulting in low accuracy. Cause: Failure to enable the `functionCall` format validation switch and force the model to output parameter structures that meet the supervision system’s requirements leads to low result accuracy.
- Symptom: Authentication errors occur when connecting to SSE interfaces with header authentication. Cause: Failure to configure custom request headers in the tool configuration and pass necessary authentication credential information triggers authentication errors.

## How to confirm configuration is complete
- In the FastGPT v4.17.0 debugging interface, run a simulated audit suspicious point query, and verify if the bound medical insurance data retrieval plugin is automatically triggered.
- View the tool call logs to confirm that the returned response body format complies with `functionCall` specification requirements.
- Test timeout scenarios by simulating the time required to retrieve data across systems, and confirm that the tool triggers a retry or terminates the process after the set timeout period.
- Check the tool configuration list to confirm that custom request header parameters have been correctly added to the configuration of authentication-related interfaces.
