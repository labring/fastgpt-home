# Medical Insurance Expense Settlement Audit: Declaration Material and File Audit - Tool Calling and Plugins

## What the data for this category looks like
Data sources include the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-provincial medical treatment settlement platform. Update frequency is once daily. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection payment lists, and settlement reconciliation statements. Some documents use structured table formats, while others are in PDF or scanned document formats. Fields include settlement number, insured person identity identifier, diagnosis and treatment project code, consumables code, expense amount, treatment date, and more. Format and field requirements strictly follow medical insurance business specifications.

## What constraints these characteristics impose on the tool calling and plugins link
Data sources are scattered. Multiple different plugins must be called to connect to distinct systems. Call order and access permissions for multiple plugins must be configured. Update frequency is daily. Plugins must be set up for scheduled synchronization of the latest data from the medical insurance catalog and coding library. Daily document formats vary. Parsing plugins must be called to unify structured formats and adapt to materials from different sources. The most time-consuming coding matching link requires calling the medical insurance coding library plugin to complete accurate matching. Call frequency must be controlled to avoid triggering interface current limiting. Error consequences directly affect medical insurance funds and the rights and interests of insured persons. Failure retry and result verification logic for tool calls must be configured.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling mode | Auto-matching or specified coding matching tool | Adapt to calling needs of different audit scenarios, support flexible tool switching |
| Function call configuration | Enable `functionCall`, set `toolChoice` to `required` | Force tool calling, ensure coding matching and reconciliation links are executed as required, avoid missing key audit steps |
| Batch task timeout | 600 seconds | Adapt to processing duration for up to 500 declaration materials per batch, avoid task interruption due to processing timeout |
| Plugin network configuration | Bind to the same Docker network, or configure a publicly accessible address | Resolve plugin connection issues across containers or hosts, adapt to different deployment environments |
| Catalog library synchronization frequency | 0:00 daily | Match the daily update rhythm of medical insurance data, ensure accuracy and timeliness of coding matching |
| Failure retry count | 3 times | Respond to temporary interface fluctuations, avoid overall audit process interruption caused by single call failure |

## Three common misconfigurations
- Connection failure errors occur when calling the marker-pdf parsing plugin. Connection fails even when using the 127.0.0.1 address. The deployment environment is Docker Desktop. The cause is that the plugin container and FastGPT container are not on the same network, so local addresses cannot be resolved.
- `functionCall` related error logs appear during workflow runtime, but no plugin requests are actually triggered. The cause is that the tool calling mode is configured incorrectly, and the forced calling switch is not enabled.
- Batch declaration material audit tasks get stuck in processing. No relevant records appear in call logs. The cause is that the batch task timeout is set too short, exceeding the actual processing duration of the batch of materials.

## How to confirm correct configuration
- Log in to the FastGPT v4.17.0 backend, enter the plugin configuration page of the corresponding application, and confirm all configuration items are set as required.
- Upload a single medical insurance settlement list, trigger tool calling, and check whether the diagnosis and treatment project code matching results returned by the plugin match the actual data.
- Initiate a batch audit task of no more than 100 copies, check whether the system log has complete tool calling records, with no connection failure or timeout errors.
- Import the rejection payment list and settlement reconciliation statement, call the reconciliation plugin, and confirm that the returned expense difference fields are complete and conform to business logic.
