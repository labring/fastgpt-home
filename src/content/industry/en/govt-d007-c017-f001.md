# Declaration Material and Case File Audit for Medical Institution Supervision and Public Health Inspection: HTTP Interfaces and External Systems

## Data Profile for This Category
Data for this category originates primarily from health supervision information systems, medical institution electronic registration systems, complaint and reporting platforms, and law enforcement inspection records. Daily processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Data is updated on a monthly basis. Individual case file documents contain fields such as institution identifiers, inspection records, rectification statuses, and penalty bases. No fixed unified format specification exists. Character lengths of individual documents vary widely.

## Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Data sources for this category are scattered, and formats are inconsistent. HTTP interfaces must support authentication rules and response formats of multiple external systems. Monthly data updates mean interface call frequency must stay low. This prevents triggering rate limiting policies of external systems. Daily processed documents cover a broad range of fields. Interfaces must support precise filtering and designated field extraction. Business errors carry direct compliance risks. Interfaces must include clear error capture and retry mechanisms. This ensures stability and accuracy of data interactions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer + API key assigned by the external system | Complies with standard authentication formats for health supervision external systems, ensures legitimacy of interface access |
| `variables` | Pass institution unified social credit code, inspection start date | Precise filtering of monthly inspection case file data for corresponding medical institutions, narrows query scope |
| `responseData` | Retain only case file number, institution name, rectification status fields | Reduces invalid data transmission, lowers bandwidth consumption of interface calls |
| Interface call timeout | 30-60 seconds | Average time for external systems to return complete case file data is approximately 25 seconds, reserves reasonable response buffer |
| Interface retry count | 2 times | Avoids frequent retries triggering rate limiting policies of external systems, covers temporary network fluctuations |
| Request frequency limit | No more than 200 times per day | Matches monthly data update rhythm of external systems, avoids exceeding call quotas |

## Three Common Misconfiguration Scenarios
- Symptom: External system interface calls return 503 Service Unavailable status code. Cause: Interface call frequency exceeds the monthly quota of the external system, or concurrent requests exceed the system's carrying capacity.
- Symptom: Custom plugin interface calls return empty case file data. Cause: Filter parameters such as the institution unified social credit code are not passed in `variables`, so the interface cannot match corresponding data.
- Symptom: The FastGPT application's voice function cannot call external interfaces normally. Cause: The interface root address uses the HTTP protocol, and has not been upgraded to the HTTPS protocol required for security compliance.

## How to Verify Correct Configuration
- Pass a known medical institution's unified social credit code and inspection date range, call the test interface. Check if the fields returned in `responseData` match the configured requirements.
- Review interface call logs. Confirm that the `Authorization` authentication header is correctly included, with no unauthorized access error messages.
- Send three consecutive test requests. Confirm that interface return results are stable, with no 503 status codes or timeout errors.
- Verify that the FastGPT application's interface root address is configured with the HTTPS protocol, to meet the external system's security access requirements.
