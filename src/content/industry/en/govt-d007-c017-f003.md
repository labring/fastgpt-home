# Declaration Materials and Case File Review for Medical Institution Supervision and Public Health Inspection: Multi-turn Dialogue and Prompts

## What the Data for This Category Looks Like
Data for this category comes primarily from health supervision information systems, medical institution electronic registration systems, complaint reporting platforms, and law enforcement inspection records. Updates occur monthly. Daily processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Data fields cover institution qualification information, on-site inspection items, rectification requirements, penalty basis, and other content. The data includes both structured and unstructured formats, with no unified fixed structure. Field extraction and verification must be adapted for multiple document types.

## Constraints on Multi-turn Dialogue and Prompts
Decentralized data sources and monthly updates require multi-turn dialogue to support context continuity for cross-system data calls, and prevent repeated pulling of historical data. A high share of unstructured documents means prompts must adapt to content in varying formats such as inspection forms and case files, and accurately extract core fields including institution qualifications and rectification status. Law enforcement scenarios demand extremely high accuracy, so multi-turn dialogue must retain historical inspection records as context references to ensure consistent rectification tracking. Monthly batch-updated case file data requires prompts to support batch verification logic, and avoid missing cross-cycle inspection information in single-turn processing.

## Three Common Misconfigurations
- Symptom: A dialogue workflow orchestrated via HTTP requests does not display output results in the conversation interface. Cause: The return value of the `variables` parameter is not bound to the conversation context output node for synchronization.
- Symptom: Multi-turn dialogue cannot retain historical inspection context, and institution information must be re-entered for each interaction. Cause: The `messages` parameter is not configured to save historical interaction records, leading to context reset for each dialogue.
- Symptom: When reviewing batch case files, the number of returned results does not match expectations, and historical data from non-current months is included. Cause: The data source range for dialogue calls is not restricted, resulting in retrieval of redundant documents outside the monthly update cycle.

## How to Verify Proper Configuration
- Upload a single supervision inspection form and medical institution practice license, trigger multi-turn dialogue, and confirm that the prompt accurately extracts core fields such as institution name and license scope.
- Call the HTTP orchestration interface, check whether the returned output content appears in the conversation interface, and verify that context binding for the `chatId` parameter works correctly.
- Run a timeout test, simulate cross-system data pulling, and confirm that the processing duration does not exceed the preset threshold.
- Import batch case files updated in the current month, and check that the dialogue only calls current-month inspection records and rectification notices.

The values provided are common starting points and should be measured against the reader's own samples.
