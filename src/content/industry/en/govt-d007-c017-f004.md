# Declaration Materials and Case File Review for Medical Institution Supervision and Public Health Inspection: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include health supervision information systems, medical institution electronic registration systems, complaint and reporting platforms, and law enforcement inspection records. Documents handled daily include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Each document's fields correspond to institution qualifications, inspection content, rectification requirements, penalty results, and other details, with matching field formats based on document type. The data update frequency is monthly; latest institution qualification and inspection records must be synchronized on a regular basis.

## What constraints these characteristics impose on the workflow orchestration link
Data sources cover multiple systems, so workflow orchestration must configure multiple data source connection nodes to adapt to the interface formats of different systems. There are diverse daily document types with large differences in field rules, so independent parsing and verification rules must be configured for different documents. The data update frequency is monthly, so high-frequency synchronization is unnecessary; regularly triggered pull nodes can be set up. The core time-consuming links are qualification verification and rectification tracking. These links must be split into orchestrable independent nodes to facilitate configuring rollback and reminder processes after failures.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind monthly synchronized health supervision data | Match the monthly data update frequency to enable dynamic value retrieval |
| Tool call model selection | Select a model that supports multi-intent classification | Need to identify review rules for different document types |
| Form interaction settings | Display institution name, inspection date, and case file number fields | Match the core input items for daily review |
| AI conversation context configuration | Maximum context 8000 token | Adapt to the review requirements for long texts such as penalty case files |
| Node timeout threshold | 600 seconds | Cover the time required for multi-system data pulling and document parsing |
| `nodeId` | Bind the unique identifier of the qualification verification node | Used for route jump configuration during tool calls |

## Three Common Mistakes
- The value of `variables` in the workflow cannot be dynamically updated, only the initially hardcoded content is retained. This occurs because the timed synchronization node configured to trigger `variables` updates is missing, and static values are only loaded when the workflow starts.
- Tool calls in advanced orchestration do not select subsequent execution nodes as expected, leading to execution errors. This occurs because the routing rules for tool calls are not properly configured, and no trigger conditions or corresponding `nodeId` are specified.
- Form input fields do not display in the conversation interface, resulting in blank interactive content. This occurs because the "Display in conversation" option is not checked in the form configuration, or the field name does not match the workflow call parameters.

## How to Verify a Successful Configuration
- Trigger a workflow test to check whether `variables` has loaded the latest medical institution practice license information.
- Submit a simulated form to confirm that all configured fields display normally in the conversation interface.
- Call the tool node to verify that the subsequent execution `nodeId` can be correctly selected based on the input parameters.
- Wait for the workflow execution to complete and confirm that no abnormal errors are triggered by the node timeout threshold.
