# Declaration Material and Case File Review for Medical Institution Supervision and Public Health Inspection: Tool Calling and Plugins

This document applies to FastGPT v4.17.0.

## What this category of data looks like
The data involved in this category mainly comes from health supervision information systems, medical institution electronic registration systems, complaint and reporting platforms, and law enforcement inspection records. Commonly processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. The data update frequency is monthly. Core processing steps focus on verifying institutional and personnel qualifications, checking hospital infection control, disinfection, and diagnosis and treatment behaviors, forming supervision opinions, and tracking rectification.

## Constraints imposed on tool calling and plugins by these characteristics
Data sources are scattered across multiple independent systems. This requires tool calling to support pulling structured and unstructured data across systems. The monthly update frequency means tools must adapt to batch processing workflows to avoid resource overload from single calls. The diverse document types require plugins to have targeted parsing capabilities, supporting content extraction for different formats such as inspection forms, licenses, and case files. The core steps of qualification verification and behavior inspection require tool calling to accurately locate specific fields, avoiding irrelevant information interfering with review results.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum single tool call count | First 8 entries | Matches the number of core verification points such as institutional qualifications and diagnosis and treatment behaviors that need to be checked in a single round of review |
| Tool call timeout | 120 seconds | Adapts to the average time required for cross-system data pulling and case file parsing |
| Knowledge base recall count | First 10 entries | Matches the monthly updated supervision data volume, avoiding redundant information interference |
| `toolChoice` | auto | Automatically matches tool calling scenarios required for compliance review, no manual specification needed |
| `functionCall` | Enabled | Supports structured output of review results, facilitating case file archiving and rectification tracking |
| Query optimization | Calibrated based on actual testing | Adapts to professional terminology in medical institution supervision scenarios, improving tool calling accuracy |

## Three common mistakes
- Tool calls return empty fields. Log checking reveals the `functionCall` parameter was not properly configured. The cause is that structured output configuration was not enabled, so tool-returned review results cannot be correctly extracted into the structured fields required for case files.
- Significant differences exist between online chat and API call results. API call return accuracy is lower. The cause is that query optimization configuration was not enabled for API calls. No adaptation was made for professional terminology in medical institution supervision, leading to tool calls matching incorrect data sources.
- The basic chart plugin fails to generate pie charts and cannot output markdown-formatted content. The cause is that correct data source fields were not configured. Only unstructured case file text was passed, and no visualizable numerical fields such as compliance rate and rectification completion rate were extracted.

## How to confirm correct configuration
- Initiate a simulated medical institution qualification review request. Check the tool call log to confirm that `toolChoice` automatically matched the data source calling action.
- Initiate identical review requests via API call and online chat. Compare the two return results to confirm the difference aligns with scenario expectations.
- Pass structured numerical fields such as compliance rate and rectification completion rate to the basic chart plugin. Verify that a markdown-formatted pie chart meeting requirements can be generated.
- Simulate a batch scenario of cross-system data pulling. Check the tool call timeout configuration to confirm no timeout errors occur.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
