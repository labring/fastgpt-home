# Declaration Material and Case File Review for Medical Institution Supervision and Public Health Inspection: Deployment and Upgrade

This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
This category of data primarily comes from health supervision information systems, medical institution electronic registration systems, complaint and reporting platforms, and law enforcement inspection records. Commonly processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. A single case file includes fields such as institution qualification information, on-site inspection items, rectification requirements, and handling results. The data update frequency is monthly, and cross-source data from multiple systems must be associated to complete review work.

## What constraints these characteristics impose during deployment and upgrade
The need to collect cross-system, multi-source data requires configuring multiple data source connections during deployment. This prevents review omissions caused by incomplete data from a single system.
The monthly update frequency and historical case file retention requirements mean review records and institution qualification data in the original database must be retained during upgrades. This prevents data loss.
Differences in the structure of multiple document types require adapting to parsing for different formats. The accuracy of field extraction for all document types must be verified after an upgrade.
The review logic that associates qualification and rectification information requires corresponding verification rules to be fixed during deployment. This avoids logic conflicts after an upgrade that impact review efficiency.

## Three common mistakes
- Issue: The displayed version after deployment does not match the target version. For example, an old version number is shown after installing the specified version. Cause: The correct version tag was not specified when pulling the image, and the old version image from the public repository was pulled by default.
- Issue: Historical case file data cannot be loaded after an upgrade. Cause: Database connection parameters were not configured correctly, or necessary data migration scripts were not executed during the upgrade process.
- Issue: Connection errors occur when testing the locally deployed model. Cause: Network permissions for model calls were not configured correctly, or the associated model service did not start properly.

## How to confirm configuration is complete
- Log in to the FastGPT management platform and check the system version information to confirm it matches the target deployment version.
- Upload a supervision inspection form attachment to verify that the file can be stored and downloaded normally, confirming that the storage configuration is active.
- Initiate a cross-system data query to verify that medical institution qualification information can be obtained, confirming that database and cache configurations are working correctly.
- Attempt to log in to the management backend using the custom ROOT_KEY to verify that highest privilege access control is active.
