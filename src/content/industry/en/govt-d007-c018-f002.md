# Declaration Materials and File Review for Insurance Registration and Premium Verification: Vector Models and Indexes

## What the Data for This Category Looks Like
Data for this category originates from social insurance management systems, tax social insurance collection systems, market entity registration information, and shared public security and civil affairs data. Data is updated daily. Daily processed documents include insurance registration forms, premium base declaration forms, personnel adjustment forms, social insurance premium verification slips, personal benefit records, and similar items. Most documents are structured forms. Core fields include personnel identity identifiers, premium bases, insurance status, personnel adjustment information, and similar items. Data links across multiple business systems, with no complex nested content.

## Constraints for Vector Models and Indexing
Daily updated data requires indexes to support incremental updates, to avoid performance losses from full index reconstruction. Structured form documents have high field density. Vector chunking must adapt to field boundaries to ensure retrieval accuracy. Data from cross-system sources has inconsistent field formats. Basic format alignment must be completed during the indexing stage. Matching accuracy of core fields such as personnel identity identifiers directly affects business compliance. This sets clear requirements for similarity threshold settings in vector retrieval.

## Configuration Settings
| Configuration Item | Recommended Values | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the field density of structured forms such as insurance registration forms and premium verification slips, avoids including too many unrelated associated fields in a single chunk |
| Overlap Length | 100–200 characters | Covers key cross-chunk information such as personnel identity and premium base, prevents key content from being truncated by chunking |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Matches identity verification standards of human resources and social security systems, reduces false match probability for non-target files |
| Single Search Limit | Top 10 results | Adapts to the daily updated file volume, avoids redundant retrieval results affecting subsequent processing efficiency |
| `defaultToken` | 8192 | Adapts to context length after splicing multi-source data, complies with input limits of text-embedding-ada-002 |
| `maxToken` | 16384 | Reserves long text processing space for cross-system data reconciliation, meets context requirements for complex business scenarios |

## Three Common Mistakes
- The interface displays the "Indexing" status for extended periods with no progress updates. Causes include failure to configure incremental index trigger rules per the daily update frequency, or insufficient resources for locally deployed vector models causing indexing construction lag.
- Returns "No matching results" error when calling the knowledge base. Causes include overly high similarity threshold settings, failure to adapt to subtle differences in personnel identity fields in insurance registration data, leading to valid matches being filtered out.
- Vector model call fails, with console displaying "model not found". Causes include failure to correctly add text-embedding-ada-002 or the local m3e model to the API channel, or failure to correctly associate model identifiers in configuration items.

## How to Verify Proper Configuration
- Review FastGPT v4.17.0 indexing construction logs to confirm daily incremental update tasks trigger automatically at the set time, with no error records.
- Input an insured personnel's ID number as a search term, verify that the similarity scores of returned results fall within the preset threshold range.
- Call the vector model interface, confirm that correctly formatted embedding vector results are returned, with no format errors or permission errors.
- Check model binding parameters in the configuration file, confirm that model identifiers for the corresponding API channel are correctly associated, with no missing configurations.
