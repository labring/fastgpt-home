# Declaration Materials and File Review for Social Insurance Participant Registration and Premium Verification: Tool Calling and Plugins

## What this category of data looks like
The data involved in this category comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily. Commonly processed documents include social insurance participant registration forms, payment base declaration forms, personnel change forms, social insurance premium verification forms, and personal social insurance benefit records. Data fields include unified social credit code, resident ID number, payment base, personnel social insurance participation status, and more. Units include yuan, person-times, and more. The core association links insurance participants with their corresponding payment behaviors.

## What constraints do these characteristics impose on the tool calling and plugins link
The multi-source data feature requires tool calling to connect to multiple independent system plugins such as social insurance handling and tax collection. Cross-source data verification logic must be configured. The `toolChoice` parameter must be used to automatically match the corresponding data source tool to avoid missed configurations from manual setup. The daily update frequency requires tool calling to support scheduled synchronization or real-time pulling of the latest data to avoid using expired market entity or social insurance participant information. The standardization of document fields requires precise matching of corresponding fields during tool calling to avoid parameter misalignment. Errors directly affect personal rights and interests, so parameter verification and failure retry mechanisms must be configured to ensure data accuracy during the review process.

## How to set up configurations
This page’s configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match the required tools to adapt to complex scenarios of multi-source data verification |
| `functionCall` | Mandatory enable | Ensure strict matching between declaration material fields and system data, avoiding errors from fuzzy matching |
| Timeout period | 600 seconds | Cover the maximum time required for cross-system data pulling, adapting to multi-data-source interaction scenarios |
| Retry count | 2 times | Balance data accuracy and call efficiency, avoiding review interruptions caused by temporary network fluctuations |
| Maximum context token count | 8192 tokens | Adapt to the field count and data length of documents in this category, avoiding truncation of key review information |
| Data source binding | Social insurance handling, tax collection plugin combination | Match the multi-system characteristics of data sources in this category, ensuring compliance of called data |

## Three common misconfigurations
- Symptom: Empty fields are returned when calling tax collection data. Cause: The corresponding data source plugin is not bound, or the plugin permissions are not configured for the current workflow.
- Symptom: Personnel identity matching errors appear in review results. Cause: The `functionCall` mandatory matching is not enabled, and fuzzy matching logic is used, leading to parameter misalignment.
- Symptom: Tool calling times out and interrupts the review process. Cause: The timeout period configuration is lower than the actual time required for cross-system data pulling, and the waiting period for multi-data-source interactions is not covered.

## How to confirm configurations are correctly set
- Enter the tool calling configuration page and confirm that the settings for `toolChoice` and `functionCall` match the configuration table.
- Import a standard social insurance participant registration form test dataset, trigger tool calling, and verify that the returned data source data matches the actual system data.
- Simulate a network fluctuation scenario, verify that the tool calling triggers the retry mechanism, and confirm that the retry count meets the configuration requirements.
- View the workflow logs to confirm that all bound data source plugins are properly connected, with no permission error reports.
