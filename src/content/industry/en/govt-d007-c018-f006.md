# Declaration Materials and File Review for Insurance Registration and Premium Payment Verification: Source Citation and Traceability

## What the data for this category looks like
Core data for this category comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily. Commonly processed documents include insurance registration forms, payment base declaration forms, personnel change forms, social insurance premium verification notices, and personal benefit records. Document fields include personnel identity identifiers, payment bases, insurance registration status, unified social credit codes of units, and more. Units of measurement include yuan, dates, and headcount.

## What constraints these characteristics impose on the source citation and traceability link
Since data is updated daily, the source citation and traceability link must call the latest synchronized data source and avoid using expired information. Different documents correspond to different business systems: associate insurance registration forms with social insurance handling system data, and associate payment verification notices with the tax collection system data. Fields include precise information such as identity identifiers and payment bases, so corresponding fields must be matched during citation to avoid cross-field mismatches. Errors here will affect personal benefits and payment records, so the traceability link must clearly mark the document source and data update time.

## How to configure the system
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Documents in this category have dense fields, so sufficient context must be retained to match precise fields such as personnel identity and payment base |
| `responseData` | Return original document fragments | Corresponding content of specific documents such as insurance registration forms and payment verification notices must be displayed to meet traceability requirements for file review |
| `detail` | Enable detailed traceability | Clearly mark the data source system and update time, which complies with compliance requirements for public sector and state-owned enterprise reviews |
| Data source binding rules | Associate corresponding systems by document type | Associate insurance registration forms with the social insurance handling system, and associate payment verification notices with the tax collection system to match business data sources |
| Synchronization frequency | Trigger full synchronization every early morning | Business data is updated daily, ensuring the latest data is used during the traceability link |

## Three common misconfigurations
- Symptom: Only quoted content is returned after configuration, and natural answers cannot be generated. Cause: The return logic of `responseData` is not set correctly. Only original document fragments are called, without integrating the answer logic.
- Symptom: Some documents do not generate corresponding question-and-answer pairs, and the original text is directly included. Cause: Data source binding rules are not configured by document type, so the associated logic for corresponding fields cannot be matched during splitting.
- Symptom: A configuration error is prompted during testing, and the traceability result lacks system labels after forced operation. Cause: The `detail` configuration item is not enabled, and the data source system label field is not added, which does not meet audit traceability requirements.

## How to confirm the configuration is correct
- Initiate a query related to insurance registration. Check whether the returned content includes the field information of the corresponding document, and confirm whether the context length of `quoteMaxToken` is sufficient to cover the query keywords.
- View the traceability labels in the returned results. Confirm whether the data source system and update time are included, and verify whether the `detail` configuration item takes effect.
- Upload different types of business documents. Check whether the system automatically associates the corresponding data sources by document type, and verify whether the data source binding rules are correct.
- Wait for the daily synchronization to complete, then initiate a query related to premium payment verification. Confirm that the update time of the returned data matches the system synchronization time.

The values given are common starting points and should be measured against the reader's own samples.
