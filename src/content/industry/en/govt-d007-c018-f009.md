# Declaration Materials and File Review for Insurance Enrollment and Payment Verification: Model Access and Configuration

## What This Category of Data Looks Like
This category of data originates from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data, and is updated daily. Daily processed documents include enrollment registration forms, payment base declaration forms, personnel addition and reduction forms, social insurance premium verification notices, and personal social insurance entitlement records. Core fields cover personnel identity identifiers, labor relationship status, payment base, enrollment status, tax collection matching identifiers, and more. Single documents contain a large number of fields and require cross-system associated verification.

## Constraints Imposed by These Characteristics on Model Access and Configuration
Cross-system, multi-source data access requires the model to support cross-data source associated verification. Daily updated data requires configuring context loading logic adapted to high-frequency data synchronization. The multi-field document structure increases the context length of a single file, so it is necessary to limit invalid redundant content to avoid context overflow. The high accuracy requirement for personnel identity and labor relationship verification requires model output to be bound to original document references, while adapting to field format differences across documents to avoid parsing misalignment. The tax collection data reconciliation link involves multi-dimensional numerical comparison, requiring the model to support structured data verification logic to ensure consistency of comparison results.

## How to Set the Configurations
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the context length requirements of multi-field documents and cross-system associations, avoiding truncation of critical data |
| `maxTokens` | 2000–3000 token | Covers the full output requirements for single file review, including field verification and reconciliation result explanations |
| `quoteMaxToken` | 1500 token | Ensures that the original document fragments referenced by the model sufficiently cover verification bases, avoiding incomplete reference content |
| `temperature` | 0.1–0.3 | Reduces random output probability, ensuring consistency of results for identity verification and data reconciliation |
| `AIPROXY_API_ENDPOINT` | Fill in according to the platform deployment address | Adapts to FastGPT's proxy call chain, ensuring normal routing of model requests |
| `toolChoice` | auto | Allows the model to automatically call tools to complete cross-system data matching, improving verification accuracy |

## Three Common Misconfigurations
- Phenomenon: The reranker model fails to start, and the interface displays model loading timeout. Cause: The document shard length for the social insurance scenario is not adapted, causing the reranker model input to exceed the threshold.
- Phenomenon: The model output field is empty, and the payment base verification result cannot be returned. Cause: `maxContext` is set too small, and the content of the original enrollment registration form is truncated, preventing the model from extracting key fields.
- Phenomenon: The review result has a large deviation from the tax data reconciliation result. Cause: `temperature` is set too high, and the model randomly generates non-standard comparison logic, leading to inconsistent verification results.

## How to Verify the Configuration Is Complete
- Upload a single enrollment registration form and personnel addition and reduction form, check whether the model output completely extracts personnel identity and enrollment status fields.
- Initiate a cross-system data reconciliation test, confirm whether the model automatically calls associated data to complete verification.
- Compare review results before and after adjusting the `temperature` parameter, confirm that output consistency meets expectations.
- View the proxy interface logs, confirm that the `AIPROXY_API_ENDPOINT` configuration can normally receive and forward model requests.

The values provided are common starting points and should be measured against the reader's own samples.
