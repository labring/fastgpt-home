# Declaration Materials and File Review for Social Insurance Enrollment and Premium Verification: Deployment and Upgrade

This document is compatible with FastGPT v4.17.0 deployment workflows.

## What the data for this category looks like
The core data for this category comes from social insurance management systems, tax social premium collection systems, market entity registration information, and public security and civil affairs shared data, with a daily update frequency. Daily processed documents include social insurance enrollment registration forms, payment base declaration forms, personnel adjustment forms, social premium verification notices, and personal benefit records. Data fields cover personnel identity identifiers, labor relationship information, payment base, enrollment status, and more. Some documents are structured forms, while others are scanned paper materials.

## Constraints imposed on deployment and upgrade by these characteristics
Multi-source data integration requires configuring multiple database connections during deployment to ensure synchronized verification between social insurance management and tax collection data.
Daily update frequency requires incremental synchronization tasks to align with the daily rhythm of personnel adjustments and base declarations, avoiding full synchronization that consumes excessive system resources.
Mixed document types require storage configurations that support both structured field storage and unstructured file storage, to retain full-process data for file review.
Cross-system data correlation requires pre-sorting field mapping rules during deployment, to prevent field mismatches in SQL queries or semantic matching.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30` | Connects to multi-source databases including social insurance management and tax collection systems, avoids connection exhaustion |
| `MONGODB_URI` | Configured according to business system storage format | Stores unstructured scanned files and incremental personnel data for file review |
| `PG_URL` | Points to a locally privately deployed PostgreSQL instance | Stores structured fields for enrollment registration and review operation logs |
| `REDIS_URL` | `127.0.0.1:6379` (local deployment) or cluster address | Caches frequently accessed personnel identity verification data, adapts to daily update frequency |
| `STORAGE_S3_ENDPOINT` | Intranet object storage service address | Stores scanned copies and electronic documents of declaration materials, ensures data security |
| `FE_DOMAIN` | Configured according to intranet access address | Adapts to intranet deployment scenarios of social insurance management institutions, restricts unauthorized access |

## Three common configuration mistakes
- Symptom: Index model failed to load, logs show the specified embedding model is unrecognized. Cause: Did not use an open-source model adapted to social insurance text semantics, mistakenly used a general embedding model for semantic matching in personnel identity verification.
- Symptom: Frontend access has a certificate error, cannot load the declaration material preview page. Cause: Did not configure an HTTPS certificate, only started the frontend service using the default HTTP port, which does not meet intranet secure access requirements.
- Symptom: text2sql-generated SQL cannot retrieve valid data. Cause: Did not map database table fields to business fields for enrollment registration and premium verification, resulting in the generated SQL failing to associate social insurance management and tax collection data sources.

## How to confirm the configuration is correct
- Log in to a database management tool, verify that the PostgreSQL instance pointed to by `PG_URL` contains business tables for enrollment registration and premium verification, as well as review operation log tables.
- Call the FastGPT built-in embedding model interface, pass a segment of enrollment registration form text, confirm that the returned vector data format meets expectations.
- Access the configured `FE_DOMAIN` address, verify that the declaration material preview page loads normally without certificate errors.
- Run the text2sql test script, pass the requirement "query monthly personnel adjustment status", confirm that the generated SQL can correctly associate social insurance management and tax collection data sources.

The values provided are common starting points and should be measured against the reader's own samples.
