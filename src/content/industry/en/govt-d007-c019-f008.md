# Declaration Materials and Case File Review for Random Inspection and Public Disclosure Supervision: Document Parsing and Chunking

## What the data for this category looks like
Documents in this category typically include types such as inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result announcements. Data mainly comes from the random inspection and public disclosure supervision platform, enterprise credit information publicity system, industry supervision system, and law enforcement officer directory. The data update frequency is monthly. Most documents have fixed fields, such as inspection target unified social credit code, inspection item category, law enforcement officer number, rectification time limit, etc. Some documents have multi-column tables or cross-page pagination formats.

## What constraints these characteristics impose on the document parsing and chunking link
Monthly batch-updated documents require the parsing link to support batch processing to avoid single-document parsing timeouts. Scenarios with mixed fixed fields and multiple document types require retaining field relevance when chunking, to avoid splitting key identifiers such as law enforcement officer numbers and unified social credit codes. Multi-column formatted inspection target lists and inspection item list documents may cause conventional parsing tools to incorrectly split column content, so parsing rules need to be adjusted to adapt to multi-column structures. Some documents have pagination or cross-page continuous fields, so chunking must avoid truncating complete information across pages.

## How to Set Configurations
The following configurations are implemented based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapt to the field length of inspection item lists and on-site inspection records, avoid splitting key supervision information |
| `chunkSplitter` | Chunk by paragraph + semantics | Match the structure of multiple document types, retain the semantic integrity of rectification notices and inspection result announcements |
| `customPdfParse` | Enable multi-column recognition mode | Adapt to the multi-column layout of inspection target lists, avoid misalignment and merging of column data during parsing |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Adapt to monthly updated batch upload documents, avoid upload failures caused by oversized single files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Cover the parsing time of large on-site inspection records, avoid mid-processing timeout interruptions |
| `chunkSettingMode` | Manual configuration mode | Adjust chunking rules for different document types, adapt to differences between inspection plans and announcement documents |

## Three Common Mistakes
- Symptom: Images uploaded with PDF are not properly associated with knowledge base content, or parsed image resources cannot be retrieved. Cause: The image embedding configuration of `customPdfParse` is not enabled, resulting in parsed image resources not being synchronously bound to chunked text.
- Symptom: Multi-column formatted inspection target lists have column misalignment and field merging into single-paragraph text after parsing. Cause: Multi-column recognition mode is not enabled, and the default chunking logic incorrectly merges multi-column content, destroying field correspondence.
- Symptom: Parsing timeout errors occur when batch uploading monthly updated documents. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is lower than the actual parsing time of a single large document, failing to cover the full processing cycle.

## How to Confirm Configurations Are Set Correctly
- Upload a standard multi-column inspection target list PDF, check if the parsed text retains column-aligned field content to verify that the multi-column recognition configuration is effective.
- Check the knowledge base upload log to confirm that single files under 500 MB do not trigger upload failure prompts, verifying that the `UPLOAD_FILE_MAX_SIZE` configuration is compliant.
- Submit a large on-site inspection record document, wait for parsing to complete and check for timeout errors, verifying that the `PARSE_FILE_TIMEOUT_SECONDS` configuration meets requirements.
- Randomly sample chunked text fragments to confirm that key fields such as law enforcement officer numbers and unified social credit codes are not split across chunks, verifying that the `chunkSize` and chunking rule configurations are reasonable.

The values provided are common starting points and should be measured against the reader's own samples.
