# Declaration Materials and Case File Review for "Double Random, One Public" Supervision Checks: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data comes from the "double random, one public" supervision platform, enterprise credit information publicity system, industry supervision system, and law enforcement officer directory. The update cycle is usually monthly. Daily documents include inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result announcements. Fields include the unified social credit code of supervised entities, law enforcement officer ID numbers, inspection item categories, rectification time limits, and other relevant fields. There is no unified fixed single document length, and single batch data volume fluctuates with the scale of the supervision area.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Decentralized data sources require cross-system integration and recall, so retrieval logic supporting multi-data source association must be configured. The monthly update frequency requires the knowledge base synchronization cycle to align with the supervision data update rhythm to avoid lagging retrieval results. Document types cover structured list data and unstructured text records, so chunking and recall rules for different formats must be adapted. Fields include exclusive fields such as supervised entity identifiers and law enforcement officer information, so targeted retrieval by specific business fields must be supported to improve matching accuracy.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | Precision requirements for matching exclusive fields such as supervised entities and law enforcement officers, calibrated based on actual testing |
| `limit` | Top 10 entries | Single retrieval results do not exceed the conventional single-batch quantity range of law enforcement officers and inspection targets |
| `searchMode` | Hybrid vector + keyword retrieval | Adapts to document types mixing structured lists and unstructured records |
| `usingReRank` | Enabled | Perform secondary sorting on returned texts such as inspection records and rectification notices to improve relevance |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplement synonymous retrieval terms related to supervision items to cover inspection categories expressed in different ways |
| `collectionIds` | Bind the corresponding supervision business dataset ID | Limit the retrieval scope to only knowledge base content related to double random supervision |

## Three Common Misconfiguration Issues
- Phenomenon: The order of returned inspection records does not match the order of manually split documents. Reason: The automatic deduplication function is enabled and no fixed sorting field is specified, causing duplicate documents to be removed and the original retrieval order to be disrupted.
- Phenomenon: Retrieval times out and returns empty results. Reason: The `limit` parameter is not adjusted according to the single-batch data volume, causing the retrieval scope to be too large and exceed system thresholds.
- Phenomenon: Cross-system associated supervision data is not synchronized to the knowledge base. Reason: The automatic synchronization task is not configured according to the business update cycle, or the bound `collectionIds` range is incorrect.

## How to Verify Successful Configuration
- Access the knowledge base management interface, check whether the bound `collectionIds` only include datasets related to double random supervision.
- Initiate a retrieval targeting the inspection item list, confirm that the returned results include information about supervised entities of the specified category.
- After enabling `usingReRank`, compare the sorting differences of retrieval results before and after enabling to verify that the reranking function is active.
- Simulate a monthly data update, check whether the knowledge base synchronization task is triggered normally and updates content.

The values provided are common starting points and should be evaluated against the reader's own samples.
