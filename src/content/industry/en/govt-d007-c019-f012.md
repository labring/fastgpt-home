# Declaration Materials and Case File Review for Dual Random Inspection and Public Disclosure Regulatory Oversight: Deployment and Upgrade

## What the Data for This Category Looks Like
The daily documents for this category include inspection plans, target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result announcements. Data sources are the dual random inspection and public disclosure regulatory platform, enterprise credit information disclosure system, industry regulatory systems, and law enforcement officer directory. Update frequency is monthly. Core data is generated around inspection tasks and law enforcement workflows, and must be linked with law enforcement officer and regulated object information to ensure data relevance and timeliness. Daily maintenance covers synchronization and verification across multiple document types.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The monthly update frequency requires configuring scheduled synchronization tasks to align with the pull rhythm of multi-source regulatory data. The need to parse multiple document types requires the system to support configuration of extraction rules for different fields, to adapt to documents in varying formats such as inspection plans and on-site records. Linked data for law enforcement officers and regulated objects requires stable storage and query capabilities, so appropriate database connection parameters must be configured. During the upgrade process, existing inspection plans and inspection result data must be retained to avoid repeated imports or data loss, so data backup and incremental synchronization logic must be configured.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:123456@localhost:27017/regulatory?authSource=admin` | Stores the law enforcement officer directory and regulated object database, supports linked queries, and meets storage requirements for monthly data updates |
| `REDIS_URL` | `redis://:6379pass@127.0.0.1:6379/1` | Caches monthly synchronized inspection plan data, reducing the frequency of interface calls to external regulatory platforms |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-south-1.tencentcloudapi.com` | Stores video and image attachments for on-site inspection records, aligning with attachment storage specifications for regulatory documents |
| `DB_MAX_LINK` | `15 connections` | Limits the number of database connections to avoid excessive system resource usage by monthly synchronization tasks |
| Scheduled synchronization cycle | `720 hours` | Aligns with the monthly data update frequency, balancing data timeliness and interface call pressure |

## Three Common Errors
- Symptom: When creating a system plugin, the system prompts that the packages/plugins/register directory cannot be found. Cause: When deploying via Docker, the local plugin directory was not mounted to the specified path inside the container, resulting in missing plugin registration files.
- Symptom: In the locally deployed workflow configuration interface, obvious text delay occurs after adding more than 10 nodes. Cause: Node lazy loading is not enabled on the frontend, and rendering a large number of nodes simultaneously consumes browser memory and computing resources.
- Symptom: After importing an inspection result announcement document, the announcement date field cannot be extracted correctly. Cause: No dedicated field extraction rule was configured for this document type, causing the parsing engine to fail to recognize the target field format.

## How to Confirm Configuration Is Complete
- Run the database connection test command to verify whether the `MONGODB_URI` and `REDIS_URL` configurations take effect, and check that the system log has no connection errors.
- Upload a standard-format inspection plan document to trigger a parsing task, and check whether the parsing result includes core fields such as inspection objects and inspection items.
- Manually trigger a scheduled synchronization task, and check whether data from the data source is successfully synchronized to the system with no duplicate or missing entries.
- Access the system plugin management page of FastGPT v4.17.0, and confirm that the regulatory data synchronization-related plugin is included in the loaded plugin list.
