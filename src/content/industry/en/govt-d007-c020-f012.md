# Declaration Materials and File Review for Territorial Spatial Planning Compilation and Implementation Evaluation: Deployment and Upgrade

## What this category of data looks like
Daily documents for this category include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data comes primarily from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistical results, and remote sensing images. Update frequency is annual. Data fields include spatial coordinates, constraint indicators, regional scope, opinion feedback content, and other items. Most units use standard spatial and statistical units such as square kilometers, population counts, and percentages. Overall document structure follows a formal report format with nested multi-chapters.

## What constraints do these characteristics impose during deployment and upgrade
Annual batch data synchronization creates load pressure during single imports. Deployments must support high-capacity database and storage configurations. Multi-source heterogeneous data types include spatial vector files, remote sensing images, statistical tables, and unstructured opinion text. Deployments must configure parsing rules compatible with multiple formats. Government data compliance requirements demand secure storage and access links to prevent sensitive information leaks. The file review process has strong interdependencies. Deployments must configure stable caching and database connections to avoid data processing interruptions that delay approval progress.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `DB_MAX_LINK` | `15–20 connections` | The multi-source data volume for single imports in this category is large. Adapt to high-concurrency database connection requirements to avoid connection exhaustion |
| `MONGODB_URI` | `dedicated database address for local private deployment` | Data in this category involves spatial and government information. Guarantee data storage security and avoid access risks from public clusters |
| `REDIS_URL` | `local cache address with 15-minute persistence configuration` | Annual batch data synchronization and high-frequency queries from file review require reducing repeated computing load on the database |
| `STORAGE_S3_ENDPOINT` | `private storage endpoint compliant with territorial spatial data storage standards` | This category includes large files such as remote sensing images. Adapt to high-throughput storage access |
| `FILE_TOKEN_KEY` | `32-bit encryption key calibrated through actual testing` | Files and planning documents include internal approval information. Guarantee file access security |

## Three common misconfigurations
- Symptom: After deploying with docker compose and modifying a configuration file, knowledge base access throws an error or the model list fails to update. Cause: The corresponding service container was not restarted, or the configuration file was not correctly mounted to the `/app/data/config` directory inside the container.
- Symptom: Timeout errors appear during batch import of planning documents. Cause: The `DB_MAX_LINK` configuration was not adjusted. Insufficient database connections cause request blocking.
- Symptom: Model interfaces cannot be accessed normally after private deployment. Cause: `ROOT_KEY` was not correctly configured. Permission verification fails for model calls.

## How to confirm the configuration is correct
- Enter the corresponding service container for FastGPT v4.17.0. View the configuration file in the `/app/data/config` directory to confirm modified parameters are written and active.
- Run a batch import test for document files. Use the container’s internal monitoring tool to check database connection counts. Confirm the `DB_MAX_LINK` configuration does not trigger connection exhaustion.
- Upload a test file in remote sensing image format. Confirm the storage endpoint is accessible and the file uploads to the specified storage location normally.
- Send a test request by calling the model interface. Confirm the returned result has no permission or link abnormality errors.
