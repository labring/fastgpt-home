# Declaration Material and File Audit for Centralized Treasury Payment and Reimbursement: Vector Models and Indexes

## What Data for This Category Entails
The documents involved in this category include payment applications, fund appropriation plans, invoices, contracts, acceptance reports, reimbursement approval forms, payment vouchers, and more. Data sources include centralized treasury payment systems, unified budget management systems, electronic invoice platforms, and contract management systems. Update frequency is daily. Most document structures contain fields such as budget indicators, economic classification, payment amounts, approval process nodes, and others. Amount fields use yuan as the unit, date fields mark the time of business occurrence, and a single document corresponds to one fund payment application or reimbursement item.

## What Constraints Do These Characteristics Impose on the Vector Model and Index Link
Data sources for this category are scattered and updated daily, requiring the index link to support incremental synchronization and cross-system data association. A single document corresponds to one fund payment item, so chunk length must adapt to the complete logic of a single business material, avoiding splitting core audit materials such as related contracts and invoices. Financial fields including budget indicators and economic classification are core audit items, so the vector model must adapt to professional text encoding to ensure accurate semantic matching of core fields. At the same time, compliance association for a single payment is strong, so index recall must ensure precise matching of related materials, avoiding missed or incorrect judgments that impact fund payment security.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the core audit field range of a single business material, avoiding splitting related contract and invoice information |
| Overlap Length | 100–150 characters | Retains cross-chunk approval process and amount association information, avoiding semantic fragmentation |
| Similarity Threshold | 0.75–0.85 | Balances semantic matching accuracy for financial text, reducing false recall probability |
| Single Search Limit | Top 10 entries | Covers the number of related materials required for a single audit, avoiding interference from redundant data |
| `maxToken` | 4000 token | Adapts to the context length requirements of audit scenarios, ensuring complete semantic input of related documents |
| `defaultToken` | 150 token | Controls the embedding output length of a single chunk, adapting to vector database storage and retrieval efficiency |

## Three Common Misconfigurations
- Issue: After upgrading from FastGPT v4.9.0 to v4.17.0, previously queryable centralized treasury payment data can no longer be retrieved. Cause: Incremental index synchronization was not performed, and the existing index did not adapt to the data parsing logic after the upgrade.
- Issue: After uploading Excel-format invoice and contract files, the vectorized index cannot correctly match core audit fields. Cause: No field extraction rules were configured for Excel files, resulting in key information such as budget indicators and amounts not being correctly embedded.
- Issue: When searching audit files, multiple duplicate payment voucher reference results appear, and related entries cannot be correctly merged. Cause: Automatic merging of search results was not enabled, or the merging rule was not set to deduplicate by payment voucher number.

## How to Confirm Proper Configuration
- Upload a single standard payment application document, check whether the index status under FastGPT v4.17.0 shows success, and confirm that the chunk length matches the actual character count of the document.
- Initiate a retrieval request for budget indicators and economic classification, and verify that the similarity of the recall results meets the preset audit scenario threshold.
- Batch import the reimbursement approval forms updated on the current day, check whether incremental indexing is completed automatically with no abnormal failed entries.
- After configuring the vector model gateway, test that the embedding vector generation request returns normally with no error messages.
