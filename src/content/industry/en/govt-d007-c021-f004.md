# Declaration Materials and File Review for Centralized Treasury Payment and Reimbursement Audit: Workflow Orchestration

## What data for this category looks like
The data for this category comes from the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system, and is updated daily. Daily processed documents include payment applications, fund use plans, invoices, contracts, acceptance reports, reimbursement approval forms, and payment vouchers. Each type of document has fixed fields such as payment amount, economic classification code, budget indicator number, and contract number. Compliance verification must be completed by matching existing data within the system.

## What constraints do these characteristics impose on the workflow orchestration link
Data for this category is updated daily. Workflows must pull the latest budget indicator, electronic invoice, and contract data each day to avoid using expired information for audits. Multiple document types with fixed fields require workflows to support sequential verification of matching relationships across materials such as payment applications, invoices, contracts, and acceptance reports. Cross-system data dependencies require workflow configuration nodes to pull existing data from different business systems, ensuring consistency of audit basis. Strict compliance requirements for single fund payments mean workflows must preset branch processes for order rejection and payment correction to handle failed audit scenarios.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | First 8000 characters | The total amount of core fields and material text for a single audit file in this category typically does not exceed 8000 characters, avoiding redundant information interfering with model judgment |
| Variable Binding Rule | Use `variables` to bind node-specific data | Different audit nodes need to call field data from different systems. Using variable binding ensures each node only obtains the required dedicated context, avoiding data confusion |
| Node Execution Order | Execute in `nodeId` order | The audit process must complete material verification, data matching, and compliance judgment sequentially. Executing in node ID order ensures process logic remains unconfused |
| File Upload Parsing Configuration | Enable local file parsing cache | This category requires verifying attachments such as invoices and contracts. Enabling the cache reduces repeated parsing time and avoids errors from repeated file pulling |
| Timeout Threshold | 600 seconds | Pulling data across systems and verifying multiple documents requires sufficient time. 600 seconds covers most conventional audit scenarios, and a retry branch is triggered on timeout |
| Environment Variable Configuration | Fill `CUSTOM_READ_FILE_URL` in config.json | Local deployment requires configuring this variable to allow workflows to pull local files, ensuring the file upload function operates correctly |

## Three Common Errors
- Symptom: Context data returned by the model is inconsistent when audit requests are initiated multiple times with the same business ID. Cause: `variables` was not used to bind dedicated context for each model node, causing the global context to be overwritten by multiple requests.
- Symptom: An error is triggered when enabling the workflow file upload node and using the document parsing tool to pull the file address after local deployment. Cause: The `CUSTOM_READ_FILE_URL` environment variable was not configured correctly, or the corresponding file read permission was not enabled in config.json.
- Symptom: The latest budget indicator data is not pulled after the audit node is triggered. Cause: The data pulling node was not configured with a daily update frequency for the workflow, and expired existing data was used.

## How to Confirm the Configuration is Correct
- Submit a simulated audit request, check whether the context data of each node in the workflow log is bound to the current request's business ID, with no cross-request data confusion.
- Upload a standard reimbursement material and file, check whether the document parsing tool can correctly identify core fields of attachments such as invoices and contracts, with no parsing errors.
- Simulate a scenario where the audit fails, confirm whether the workflow can automatically jump to the order rejection branch and generate corresponding audit opinions.
- Check the system environment variable configuration, confirm that `CUSTOM_READ_FILE_URL` has been filled correctly, and the file read permission in config.json has been enabled.
