# Declaration Materials and File Review for Centralized Treasury Payment and Reimbursement Audit: Citation Sources and Traceability

## What this category of data looks like
The daily documents involved in this category include payment applications, fund use plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers, all of which are associated materials linked to a single fund payment. Data sources are the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system, with daily synchronous updates. Document formats exported from different systems vary, and each material contains core identification information for the corresponding business, used to link similar businesses across systems.

## What constraints these characteristics impose on the citation sources and traceability link
The data in this category is multi-source, heterogeneous, and updated daily. A single payment business is linked to multiple materials generated by different systems, which requires the traceability link to accurately bind business identifiers and corresponding documents. Differences in document formats and field naming caused by multiple system sources require cross-system association through unified business identifiers to avoid matching errors. The daily update feature requires the traceability system to support incremental synchronization of the latest data to ensure that the cited source materials are the currently valid versions. Compliance review for a single business relies on full-chain materials, so traceability must cover all associated documents and must not miss key review basis.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Covers the total character count of multiple materials linked to a single business, avoids truncating traceability content, based on the token allocation rules of FastGPT v4.17.0 |
| `responseData` | Returns the original path and archive number of associated documents | Meets the requirement of clearly identifying the archive location of source documents during fiscal review |
| `detail` | Enable full-field matching | Covers all business identification fields to improve cross-system matching accuracy |
| Single search limit | Top 10 results | Materials linked to a single business typically do not exceed 10 copies, avoids redundant results interfering with review |
| Homologous identifier matching rule | Match both payment application number and contract number | Businesses in this category must link payment and contract vouchers simultaneously; a single identifier is prone to matching deviations |
| Incremental synchronization interval | Every 1 hour, full daily synchronization | Meets the requirement of daily business data updates to ensure traceability content is real-time and valid |

## Three Common Misconfigurations
- Issue: Search results return historical materials unrelated to the current payment business, and the business identification fields of associated documents are empty. Cause: Homologous identifier matching rules are not configured, and only keyword fuzzy matching is used, leading to incorrect associations.
- Issue: When the workflow calls the knowledge base search node, the incoming external business number variable cannot be correctly brought into the search conditions. Cause: The variable reference function is not enabled in the node configuration, or variable syntax not in the `{{}}` format is used.
- Issue: The traceability result only returns a single invoice message, and does not include associated contracts and acceptance receipts. Cause: The single search limit is set too low, or multi-document association matching configuration is not enabled.

## How to Confirm Proper Configuration
- Upload the associated document package for a single business, perform a search test, confirm that the returned results include all associated materials and the business identification matches correctly.
- Configure variable reference parameters in the workflow, pass the test payment application number, confirm that the search condition is automatically replaced with the corresponding number.
- View the knowledge base synchronization logs, confirm that the daily full synchronization and incremental synchronization tasks are executed normally with no failed records.
- View the `responseData` field returned by traceability, confirm that it includes the original path and archive number of the document.

The values provided here are common starting points and should be measured against the reader's own samples.
