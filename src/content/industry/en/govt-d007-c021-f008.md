# Declaration Material and File Review for Centralized Treasury Payment and Reimbursement Audit: Document Parsing and Chunking

## What data for this category consists of
This category's data comes from the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system. The update frequency is daily. Documents processed daily include payment applications, fund appropriation plans, invoices, contracts, acceptance reports, reimbursement approval forms, and payment vouchers.
Payment applications contain fixed fields such as budget index code, economic classification code, and payment amount. Invoices contain invoice number, check code, and issue date. Contracts contain contract number, signing date, target amount, and other fixed fields. Some documents from different systems have inconsistent formats.

## What constraints these characteristics impose on document parsing and chunking
Format differences across documents from multiple systems require parsing tools to support multiple formats including Excel, PDF, and Word. Tools must also accurately extract content from PDFs with digital signatures.
Daily high-frequency update demands require parsing workflows to have sufficient processing efficiency to avoid delaying audit progress.
Core fields to verify and associated approval chains require retaining contextual connections during chunking, to avoid breaking audit logic after splitting.
Complex table documents require parsing tools to accurately identify fields and values within tables, preventing missing or misaligned fields.

## How to configure
This document provides configuration guidance based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | This category’s documents need to retain contextual links for budget indicators and associated vouchers. This range avoids breaking audit logic after splitting |
| `chunkSplitter` | Split by paragraph + semantic meaning | Adapts to the fixed approval process structure of this category’s documents, retaining complete "application-approval-verification" paragraph logic |
| `customPdfParse` | Enabled | Adapts to digitally signed PDF documents in this category, avoiding inability to extract content from signed files |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Covers upload requirements for large-volume contract PDFs and bulk Excel reports from daily batch updates |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Meets parsing duration requirements for complex table documents and bulk documents, avoiding timeout interruptions |
| `chunkSettingMode` | Manual mode | Allows flexible adjustment of chunking parameters for format differences exported from different systems |

## Three common misconfigurations
- Phenomenon: Calling the Doc2x tool returns a file read failure error, with error text containing "Only support .txt, .m". Cause: The uploaded document has not completed format conversion, or is an encrypted system-exported file that exceeds the format range supported by the tool.
- Phenomenon: Fields are missing from the parsing result after uploading a digitally signed PDF. Cause: The `customPdfParse` configuration is not enabled, and adaptive parsing logic for signed PDFs is not activated.
- Phenomenon: A timeout error triggers when uploading daily updated documents in bulk. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too low, leaving insufficient time for the bulk parsing process of multiple documents.

## How to confirm the configuration is correct
- Uploading a single digitally signed electronic invoice PDF enables verification that the parsing result extracts core fields including invoice number, check code, and issue date.
- Uploading an Excel payment application document exported from the treasury system enables verification that the chunking result retains associated fields including budget index code and payment amount.
- Adjusting `PARSE_FILE_TIMEOUT_SECONDS` to 600 seconds, then uploading a single contract PDF under 500 MB, enables confirmation that no timeout error triggers during parsing.
- Bulk uploading three daily updated reimbursement file documents enables verification that the chunking result retains the contextual connection between the reimbursement approval form and the corresponding invoice.
