# Declaration Materials and File Review for Centralized Treasury Payment and Reimbursement Audit: Model Access and Configuration
Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category's Data Looks Like
Core data for this category comes from the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system, with daily updates. Daily processed documents include payment applications, fund appropriation plans, invoices, contracts, acceptance reports, reimbursement approval forms, and payment vouchers. Each document must match fields such as budget indicators, economic classification codes, and payment amounts. Individual payment records are linked to complete sets of documents and approval chains, with fields strictly aligned to fiscal standard codes and units.

## Constraints Imposed on Model Access and Configuration
Since this category's data is updated daily and sourced from multiple heterogeneous systems, the model access link must configure cross-system data format alignment rules to prevent verification failures caused by field mismatches. Individual payment records require linking to complete chains including invoices, contracts, and acceptance reports, so context configuration must cover sufficient associated document length to ensure complete review logic. Diverse document types and strict field alignment to fiscal standards require configurations to support precise extraction and verification of specific fields, while also adapting to rapid fallback mechanisms after errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Covers the total length of multiple documents linked to a single payment, ensuring context support for complete review chains |
| `maxTokens` | 2000–3000 token | Meets the output length requirements for a single review report, avoiding truncation of critical verification conclusions |
| `quoteMaxToken` | 1500 token | Retains sufficient original reference fragments for traceability in compliance verification |
| `toolChoice` | auto | Automatically adapts to tool call requirements, supporting associated verification across multiple documents |
| `temperature` | 0.1–0.3 | Reduces randomness to ensure consistency of compliance verification results |
| `AIPROXY_API_ENDPOINT` | Fill in the actual deployed proxy address | Adapts to the invocation link for Doubao models from Volcano Engine |
| `AIPROXY_API_TOKEN` | Fill in the key issued by the platform | Completes identity verification for model invocation |

## Three Common Misconfigurations
- Model calls return a `401 Unauthorized` status code. This occurs when `AIPROXY_API_TOKEN` is not filled correctly, or the key has insufficient permissions. This is a common issue with aiproxy channel configuration.
- Context overflow errors occur during tool calls. This happens when the `maxContext` configuration value is lower than the total length of documents linked to a single payment, failing to cover the complete review chain.
- Economic classification fields are not extracted in review results. This is caused by failing to configure precise extraction rules for the target fields, or having a `quoteMaxToken` value that is too small, leading to truncation of original document fragments.

## How to Verify Correct Configuration
- Submit a simulated payment review request, check whether the returned result includes all core fields of associated documents, to confirm that the context configuration covers the complete chain.
- Call the model test interface, check whether the returned token usage is lower than the `maxContext` configuration value, to confirm that the context capacity meets requirements.
- Verify the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations, submit a parameter-free test request, to confirm that identity verification and link connectivity are working properly.
- Adjust the `temperature` configuration value, submit the same review request multiple times, to confirm that result consistency meets expectations.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
