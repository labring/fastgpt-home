# Centralized Treasury Payment and Reimbursement Audit: Declaration Material and File Audit — Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category comes from the centralized treasury payment system, unified budget management system, electronic invoice platform, and contract management system. It is updated daily.
Documents processed daily include payment applications, fund plans, invoices, contracts, acceptance records, reimbursement approval forms, and payment vouchers. Each document typically includes fields such as budget indicator code, economic classification code, amount, and approval node information. Units involved include RMB yuan, batch number, contract number, and others. Most document structures combine structured forms and unstructured attachments.

## Constraints on knowledge base retrieval and recall
Dispersed data sources and daily updates require the knowledge base to support incremental synchronization of multi-system data. This avoids delays caused by full index reconstruction.
Daily documents include both structured fields and unstructured attachments. Retrieval must cover both structured metadata and text content.
A single audit links to multiple documents. Retrieval must accurately recall contracts, invoices, and acceptance records that match the current declaration form. This prevents irrelevant results from interfering with audits.
Since errors directly affect fund compliance, retrieval result relevance must meet audit requirements. This reduces compliance risks from false recalls.

## Three common configuration errors
### Mistake 1
Phenomenon: Significant differences between results from online chat and API calls. Deviations are large when the API enables `stream: false` and `detail: true`.
Cause: Global knowledge base retrieval parameters are not unified. Parameter override rules vary across call chains.

### Mistake 2
Phenomenon: API calls return the error `invalid configuration parameter name "hnsw.max_scan_tuples"`.
Cause: An invalid configuration parameter name was used, causing the retrieval engine to fail to recognize the request.

### Mistake 3
Phenomenon: After upgrading FastGPT to version 4.9–4.10, the previously indexed knowledge base cannot trigger vector retrieval, and searches return no results.
Cause: The old index format is incompatible with the new version’s vector retrieval engine. Reindex or update the index configuration to resolve this.
