# Declaration Material and File Review for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Vector Models and Indexes

## What Data in This Category Looks Like
This category of data primarily comes from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. The update frequency is daily. Commonly processed review-related documents include transfer announcements, trading notices, bid application forms, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer specifications, and similar materials. Most documents contain fields such as ownership numbers, trading target types, margin amounts, and transaction confirmation times. The structure is mostly a mixed format combining standardized templates and free text.

## What Constraints These Characteristics Impose on Vector Models and Indexing
Daily updated data requires indexes to support incremental synchronization, to avoid resource consumption caused by full reconstruction. Mixed format documents require balanced splitting of standardized fields and free text, to prevent key information such as ownership numbers and trading target types from being split into different chunks. Data from multiple systems has inconsistent formats, so unified standardization processing must be completed before indexing to ensure consistency in vector embeddings. Additionally, review scenarios require precise matching of ownership and restriction conditions. Vector models must have stable semantic recognition capabilities for professional terms related to public resource trading. Differences in multi-source fields may also lead to uneven distribution of embedded vectors, so standardization adaptation must be completed in advance.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the mixed structure of standardized documents and free text, prevents key fields from being split |
| Overlap Length | 100–150 characters | Retains contextual association between adjacent chunks, ensures semantic coherence of ownership information |
| Similarity Threshold | 0.75–0.85 | Filters low-match irrelevant materials, meets the precision requirements of review scenarios |
| Single Retrieval Limit | Top 10 entries | Controls the number of retrieval results, avoids redundant information interfering with review judgments |
| `maxToken` | 4096 token | Adapts to the input upper limit of mainstream open-source vector models, ensures completeness of embedded content |
| `defaultToken` | Calibrated via actual testing | Adapts default embedding parameters for different scenarios, supports multi-source data format compatibility |

## Three Common Misconfigurations
- Phenomenon: After switching vector models in different environments, embedding results deviate or fail to match target ownership materials. Cause: Embedding dimensions and preprocessing logic of vector models are not unified, leading to inconsistent vector spaces across models.
- Phenomenon: A single large file remains in the indexing queue for an extended period, with no progress updates on the interface. Cause: No reasonable chunk threshold is set, oversized chunks cause embedding calculation timeouts, or the file format is not parsed correctly.
- Phenomenon: Retrieval results do not prioritize content from the specified knowledge base. Cause: No knowledge base priority rules are configured, or the rules are not bound to the retrieval logic, leading to randomly returned results.

## How to Verify Proper Configuration
- Upload a standardized transfer announcement document, check if the chunking results retain complete ownership numbers and trading target information.
- Switch between different vector models to conduct embedding tests, verify dimensional consistency and semantic matching of embedding results.
- After configuring knowledge base priority rules, initiate a query that includes content associated with two knowledge bases, confirm that content from the prioritized knowledge base is retrieved first.
- Submit a large file, check if indexing progress completes within a reasonable time frame, with no freezes or timeout errors.
