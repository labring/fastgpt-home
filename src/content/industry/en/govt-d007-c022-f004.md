# Declaration Material and File Review for Land Use Rights, Mining Rights and State-owned Property Transactions: Workflow Orchestration

This page is compatible with FastGPT v4.17.0, and the following configurations are formulated based on this version.

## What the data for this category looks like
The daily business documents of this category include transfer announcements, transaction notices, bid application forms, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer specifications, etc. Data sources are the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. The update frequency is daily. Data fields usually include transaction object ownership information, margin amount, bidder qualifications, transaction time, etc. Different documents correspond to exclusive fields. Overall data is scattered across multiple independent business systems.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Data scattered across multiple systems requires workflows to support retrieving specified knowledge base file sets, to avoid cross-source data interference. The daily update frequency requires the knowledge base synchronization mechanism to adapt to real-time requirements, ensuring the timeliness of retrieved data. Multiple document types and exclusive fields require workflows to configure corresponding verification rules for different documents, to avoid field matching errors. The scale of daily processing volume requires setting a reasonable cycle limit for batch execution nodes, to prevent resource overload. Audit errors can lead to consequences such as invalid transactions and disputes over asset loss, requiring workflows to configure complete failure handling and log recording mechanisms.

## Configuration Settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Knowledge base specified collection | Bind the exclusive file set of the corresponding trading system | Data for this category is scattered across multiple independent business systems, so retrieval scope must be limited to avoid interference from irrelevant data |
| Batch execution node cycle limit | Top 1000 entries | Daily declaration material processing volume is usually in the thousands, to avoid excessive resource occupation |
| `variables` temperature configuration | 0.2–0.4 | Ownership review requires rigor, low temperature ensures output consistency |
| `nodeId` binding rule | Bind corresponding system interfaces according to node functions | Cross-system calls require precise matching of node IDs to avoid call errors |
| API call timeout period | 600 seconds | Cross-system material retrieval has a long response cycle, calibrated based on actual testing |
| Node log configuration | Enable full logs | Audit process errors have serious consequences, so complete operation data must be recorded |

## Three Common Misconfigurations
- Batch execution nodes work normally during online debugging but fail to complete all cycles during API calls: The loop index variable is not correctly passed in the `variables` configuration, and no corresponding context parameter is carried during API calls, causing the cycle to fail to continue execution.
- Knowledge base search fails to hit specified business documents: The exclusive file set of the corresponding trading system is not bound, and the retrieval scope covers documents from irrelevant business systems, resulting in matching results that do not meet review requirements.
- After calling the API to trigger the workflow, the conversation log has no operation data: The node full log configuration is not enabled, and `nodeId` is not bound to the log collection node, causing operation data to not be recorded correctly.

## How to Verify a Correct Configuration
- Initiate a retrieval test for a single document, verify that the returned results only include the exclusive trading system documents pre-bound.
- Submit a small batch of test declaration materials, confirm that the batch execution node completes all preset cycle processes.
- Call the API to trigger the workflow, check whether the conversation log records complete node operation data and parameter transfer conditions.
- Enter the variable reference configuration interface, confirm that the temperature setting item is normally displayed and the parameters can be adjusted.
