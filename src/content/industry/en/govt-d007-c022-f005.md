# Declaration Material and File Review for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Tool Calling and Plugins

## What data for this category includes
Daily documents for this category typically include transfer announcements, transaction notices, bid applications, margin payment vouchers, transaction confirmation letters, listing result announcements, property transfer descriptions, and similar materials. Data is sourced from national public resource trading platforms, natural resource trading systems, property exchange systems, and state-owned asset supervision systems, with a daily update frequency. Document fields typically cover transaction object ownership details, object valuation, margin amounts, bidding rules, and more. Document formats and field order differ across exports from different systems. Plugins are required to adapt to multi-source data structures.

## What constraints these characteristics impose on tool calling and plugins
Multi-source data sources require plugins to support connecting to API interfaces of different systems. This avoids field parsing errors caused by incompatible data formats.
Daily update frequency requires tool calling to have a scheduled synchronization mechanism. This ensures review uses the latest ownership and transaction data.
Differences in document formats and fields require tool calling parameters to support dynamic adaptation. Fixed single parsing rules are not sufficient.
The core review steps for this category are ownership verification and material validation. Errors have severe consequences. Plugins must trigger alerts and retries when calls fail. This prevents invalid transactions, disputes over state-owned asset loss, or blocked property transfers from data errors.

## Configuration Settings
This document is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto (auto) | Adapt to dynamic tool calling requirements for multiple types of transaction documents, no need to manually specify a single tool |
| Tool call timeout duration | 600 seconds | Match the typical time requirements for ownership verification and cross-system data pulling |
| Number of returns per single tool call | First 10 entries | Cover the core material fields required for single-batch review, avoid redundant data occupying context window |
| `functionCall` format validation | Validate against business field rules | Ensure returned results match the required mandatory fields for state-owned property transactions, such as ownership information and margin amount |
| Data source synchronization frequency | 1 time per day | Match the daily update rhythm of business data, ensure timeliness of review data |
| Context window size | 8000–12000 token | Adapt to the total content length of multiple transaction documents, avoid truncation of core review information |

## Three Common Configuration Mistakes
- Connection timeout when calling local MCP services: This occurs because the intranet access permission for the local service is not added in the FastGPT plugin configuration, or the correct local port and protocol are not specified.
- No intermediate thought process output after tool calling: This occurs because the intermediate step logging switch in `functionCall` mode is not enabled, or the weight for thought output is not retained in the model configuration.
- Missing material fields in batch review: This occurs because the number of returns per single tool call is set too low, failing to cover all validation fields across multiple documents such as bid applications and transaction confirmation letters.

## How to Verify Configurations Are Correct
- Uploading a single bid application document to trigger tool calling enables verification that the corresponding object's ownership information and transaction rules are correctly pulled.
- After configuring the local MCP service, a test call is initiated, and confirmation is made that the returned results include the expected margin payment voucher and transaction confirmation letter fields.
- Tool calling logs are reviewed to confirm that the `toolChoice` parameter is correctly applied, with no format errors or timeout alerts.
- A daily data synchronization is simulated, and checks are performed to confirm whether the plugin automatically pulls the latest listing result announcement data, verifying that the synchronization mechanism functions.
