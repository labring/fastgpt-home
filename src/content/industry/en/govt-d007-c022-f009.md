# Declaration Material and File Review for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Model Access and Configuration

## What this category of data looks like
Data for this category primarily comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, and is updated daily. Commonly processed documents include transfer announcements, trading notices, bid applications, margin payment vouchers, transaction confirmation letters, listing result announcements, and property right transfer descriptions. Core fields cover ownership information of transaction subjects, restriction conditions, margin amounts, transaction confirmation details, and more. The data structure is built around the transaction process of resource and asset rights.

## What constraints do these characteristics impose on model access and configuration
Data formats vary across different source systems. Model access must adapt to the return structures of multiple data interfaces to avoid parsing errors. Daily updated business data requires configuring trigger logic that supports high-frequency synchronization, to prevent data lag from impacting review efficiency. Diverse document types and differentiated core fields require the model to preset dedicated recognition rules for different documents, ensuring accurate extraction of key information such as ownership, margin amounts, and transaction confirmation details. Additionally, errors in data association carry serious consequences. Configuration must strengthen verification logic for key information to reduce misjudgment risks.

## How to set the configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Documents in this category are lengthy, containing multiple sections such as ownership descriptions and transaction processes. Sufficient context capacity accommodates complete review materials and historical data |
| `maxTokens` | `4000–6000 token` | Meets the output length requirements for core review content, avoiding truncation of key ownership verification or transaction confirmation conclusions |
| `temperature` | `0.1–0.3` | Reviews require strict accuracy. Reducing generation randomness ensures consistent recognition of key information such as ownership and margin amounts |
| `AIPROXY_API_ENDPOINT` | Exclusive access address corresponding to the model service provider | Adapts to the high-compliance data transmission requirements of this category, ensuring stability of interface calls |
| `AIPROXY_API_TOKEN` | Token value bound to exclusive business permissions | Differentiates access permissions for business scenarios, ensuring access security for state-owned asset and natural resource-related data |
| `toolChoice` | `auto` | Supports the model to independently choose whether to call tools to assist in verifying ownership information, adapting to the review scenarios of multiple document types |

## Three common misconfigurations
- Symptom: The agent execution details page shows a disconnected link, and the interface returns a timeout error. Cause: No timeout threshold adapted to public resource trading systems is configured, causing interface call timeouts during long-document review.
- Symptom: After uploading style reference files and business content files, the review materials generated by the model do not match the expected style. Cause: The `vision` parameter is not enabled, so the model cannot recognize the format and typesetting style of reference files.
- Symptom: Call logs are not displayed on the model provider management page. Cause: No `AIPROXY_API_TOKEN` with log viewing permissions is bound, or context log collection configuration is not enabled.

## How to confirm successful configuration
- Manually upload 1 bid application form and 1 transaction confirmation letter, verify whether the subject ownership and margin amount fields extracted by the model match the original text, and adjust relevant parameters until extraction accuracy meets business requirements.
- Configure a scheduled synchronization task, check whether data updates match the release rhythm of the business system, and adjust the synchronization trigger logic to adapt to the daily update frequency.
- Access the model provider management page, confirm that the configured values of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the information provided by the service provider, and verify interface connectivity.
- Test a long-document review task, check whether the context and output length configurations avoid content truncation, and ensure that all key transaction information is fully processed.
