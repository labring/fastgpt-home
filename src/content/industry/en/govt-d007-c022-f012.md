# Declaration Materials and File Review for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Deployment and Upgrade

## What data for this category looks like
This category’s daily documents typically include transfer announcements, transaction notices, bid applications, margin payment vouchers, transaction confirmation letters, listing result announcements, property right transfer descriptions, and similar materials. Data usually comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with a daily update frequency. Common data fields include transaction subject ownership information, subject type, margin amount, transaction confirmation time, listing bidding records, and more. The field structure of different documents adjusts based on transaction type: land use right documents focus on parcel location and usage term, mining right documents focus on mining area scope and resource reserves, and state-owned property transaction documents focus on transferor qualifications and evaluation value.

## Constraints during deployment and upgrade
This category’s data is multi-source, heterogeneous, and updated daily. During deployment, multiple data source connections must be configured to adapt to the interface formats of different systems such as national public resource trading platforms and natural resource trading systems. Document fields vary significantly across different transaction types, so custom parsing rules must be configured to accurately extract core fields like ownership information and margin amount. Daily updated data requires scheduled synchronization tasks to ensure the data used for review is the latest version. During upgrades, existing review process configurations must be retained to avoid interrupting daily review work, and the permission control logic of existing systems must be compatible to prevent leakage of sensitive transaction materials.

| `STORAGE_S3_ENDPOINT` | `https://oss-cn-shanghai.aliyuncs.com` | Stores large-volume documents such as margin payment vouchers and transaction confirmation letters, compatible with multi-cloud storage interfaces to meet storage requirements for newly added documents each day |

| `DB_MAX_LINK` | `15–25` | Controls concurrent connection count for multiple data sources, avoids exceeding connection limits of source systems, adapts to daily incremental data synchronization |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Encrypts document download links to prevent unauthorized access to sensitive materials such as bid application documents and transaction confirmation letters |
| `ROOT_KEY` | `Configured in accordance with internal enterprise security specifications` | Highest permission key for the management platform, ensures only authorized operation and maintenance personnel can modify review rules |

## Three common configuration mistakes
- Symptom: `Error response from daemon` error occurs when deploying with Docker Compose. Cause: The storage volume mount corresponding to `STORAGE_S3_ENDPOINT` is not configured correctly, or the host port is occupied, causing container startup failure.
- Symptom: `TypeError: Cannot read properties of undefined` error occurs after upgrading to FastGPT v4.17.0. Cause: The `DB_MAX_LINK` parameter in the original configuration is not adapted to the new version's database connection logic, or the old version's document parsing rules were not migrated.
- Symptom: Username or password error prompt appears when calling the model interface. Cause: The permission verification logic corresponding to `ROOT_KEY` is not configured correctly, or the key configuration for model calls was not updated, causing interface authentication failure.

## How to confirm correct configuration
- Run the `docker compose ps` command to confirm all containers are in running state with no abnormal exit records.
- Manually trigger a data synchronization task to check if the day's transaction announcement data can be pulled from the specified source system, with no error logs output.
- Upload a bid application document to verify that core fields such as subject ownership and margin amount can be extracted correctly, and the generated document download link can be accessed normally.
- Log in to the management backend to check that the values of configuration items such as `MONGODB_URI` and `REDIS_URL` match the preset values, with no abnormal tampering.
