# Declaration Material and Case Review for Student Financial Aid and Award Subsidies: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from four official systems: the national student financial aid management information system, school student status system, civil affairs minimum living allowance and extremely poor assistance data system, and fiscal payment system. Commonly processed documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, disbursement lists, and public notice materials. Document fields include per capita monthly household income (unit: yuan), student ID number, applied amount, bank card number, and others. The data update frequency is once per semester. A single batch of declaration materials usually corresponds to the total applications from a single class or college.

## What constraints do these characteristics impose on the tool calling and plugins link
Tool calling must support multi-interface adaptation to connect data from multiple official sources.
Configure call permissions and parameter formats for each data source separately.
The semester-level update frequency requires matching the cache validity period of tool calls to this cycle.
This prevents use of expired civil affairs low-income or student status data.
The variety of document fields requires setting validation rules for specific fields like per capita monthly household income and student ID number.
This ensures input data formats comply with requirements.
The batch nature of single-batch declaration materials requires tool calling to support batch processing.
This avoids overloading single requests.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Automatically adapts to tool calling needs across different review links, matches multi-data source verification scenarios |
| `functionCall` | `"required"` | Forces tool calling to trigger, ensures all qualification verification steps are completed via external interfaces |
| Tool call timeout period | `600 seconds` | Interface responses when connecting to multiple official systems usually take a long time, this prevents verification from being interrupted by timeouts |
| Single batch processing count | `Top 15 entries` | Matches the typical processing scale of declaration materials for a single class, avoids request overload |
| Cache validity period | `90 days` | Matches the official data update frequency per semester, ensures student status and low-income data used are up to date |
| Parameter validation rule configuration | Preset rules based on document fields | Covers format and value validation for specific fields including per capita monthly household income and student ID number |

## Three common misconfigurations
- Phenomenon: External data source interface calls return the `getaddrinfo ENOTFOUND` error. Cause: Domain names and network permissions for connection interfaces such as the national student financial aid management information system and civil affairs low-income system were not configured correctly. This prevents successful domain name resolution.
- Phenomenon: 400 errors are returned when calling MCP tools with the Xinference large language model. Cause: The tool call parameter format does not adapt to the interface requirements of Xinference. The parameter structure for `toolChoice` or `functionCall` was not matched correctly.
- Phenomenon: The `aiPointsNotEnough` error is returned from interface calls. Cause: Insufficient model call quota was configured, or the request volume for single-batch tool calls exceeded the current available quota limit.

## How to confirm the configuration is complete
- Initiate a tool call test for a single family economic hardship certification form. Confirm that associated data from the corresponding student status system and civil affairs system is successfully pulled.
- Review the FastGPT v4.17.0 tool call logs. Confirm that the `toolChoice` and `functionCall` parameters have taken effect as configured, with no format errors.
- Trigger a batch review task. Confirm that the single batch processing count and cache validity period match the preset configuration.
- Simulate input of an application amount with an invalid format. Confirm that the tool call parameter validation rules properly intercept the abnormal request.
