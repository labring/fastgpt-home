# Declaration Material and Case Review for Student Aid and Grant Verification: Citation Source and Traceability

## What this category of data looks like
Service subjects include education bureau aid centers, school student affairs offices or aid offices, and finance departments. Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Data sources cover the national student aid management information system, school student status systems, civil affairs low-income and special hardship data, and finance payment systems. Update frequency is once per semester. Most documents are structured forms with fixed fields including family income, student ID number, low-income or special hardship status, and finance payment serial number, with no complex nested content.

## What constraints these characteristics impose on the citation source and traceability link
Multiple system data sources require the traceability link to support cross-source correlation and matching, to ensure consistency between student status, low-income certification, and finance payment information. Semester-level update frequency requires the knowledge base to perform full synchronization regularly, to avoid using expired data for review. Structured document format requires traceability to precisely match specific fields; generalized content matching may lead to incorrect qualification judgments. Errors directly affect students' vital interests and audit compliance, so the traceability link must ensure the accuracy and completeness of cited content, and must not miss key review basis.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the paragraph length of documents such as family economic hardship certification forms and aid application forms, avoids splitting key fields such as student ID number and home address into different chunks |
| Overlap Length | 100–150 characters | Retains key identifying information across chunks, prevents field matching failures caused by chunk boundary breaks during traceability |
| `quoteMaxToken` | 1500–2000 tokens | Matches the total document length required for a single review batch, ensures cited content fully covers core materials such as application forms and review forms |
| Maximum Number of Citations | First 6 entries | Covers the typical number of documents for a single class or college review batch, avoids redundant information interfering with review judgments |
| `detail` | Enabled | Displays specific field content of cited documents, allows reviewers to directly check key review items such as family income and student status |
| `responseData` | Return only identifiers and core fields of matched documents | Streamlines returned content, focuses on core data required for aid review such as student ID number and low-income certification status |

The above configurations are designed based on the functional logic of FastGPT v4.17.0.

## Three common configuration mistakes
- Issue: Document content displayed in the context citation area does not render Markdown formatting, only raw text is shown. Cause: The format rendering switch for the `detail` configuration item is not enabled, or Markdown formatting was not correctly parsed when importing knowledge base documents.
- Issue: No matching aid documents are returned when submitting a review query. Cause: Chunk length is set too large, causing key fields such as student ID number and family income to be split outside of chunks and unable to be recalled for matching.
- Issue: The number of returned cited documents exceeds the preset range, leading to redundant review information. Cause: Maximum number of citations is set too high, and the value is not adjusted based on the actual number of documents in a single review batch.

## How to confirm correct configuration
- Upload a standard family economic hardship certification form to the knowledge base, submit a query including "verify this student's family economic status", check if the returned cited content includes key fields from the form.
- View the context citation area, confirm that document content has been correctly formatted, with no raw Markdown syntax remaining.
- Adjust the `quoteMaxToken` parameter, test a review query covering multi-page materials, check if the returned cited content fully covers required information without truncation.
- Submit a query exceeding the number of documents in a typical review batch, check if the number of returned citations matches the preset maximum value.

The values provided are common starting points and should be measured against the reader's own samples.
