# Application Material and Case Review for Student Financial Aid and Award/Subsidy Audit: Document Parsing and Chunking

## What this category of data looks like
Core data for this category comes from the national student financial aid management information system, school student status system, civil affairs low-income and special hardship data, and fiscal payment system. The update cycle is per semester. Daily processed documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, distribution lists, and public notice materials. Fields in the documents cover per capita household income, student ID number, financial aid amount, bank card number, and more. Some documents contain structured tables and unstructured explanatory text. Data is sourced from multiple systems, so field consistency and completeness must be ensured.

## What constraints do these characteristics impose on the document parsing and chunking step
Data from multiple systems leads to scattered fields. Chunking must retain cross-document associated fields to ensure subsequent verification logic is complete. Structured table documents account for a high proportion. The default chunking logic easily splits table rows and causes information breaks, so chunking rules adapted to table structures are needed. The semester-level update frequency requires the parsing process to be stable and reliable, to avoid exceptions during batch processing. Errors can lead to incorrect or missing financial aid disbursements or audit issues, so parsing accuracy and field integrity must be guaranteed.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the paragraph and table row lengths of documents such as financial aid application forms and review forms, to avoid information breaks |
| `chunkSplitter` | Split by paragraph + table boundaries | Address the mixed structure of a large number of structured tables and explanatory text in this category of documents |
| `customPdfParse` | Enable and configure adapted rules | Resolve parsing and chunking issues for multi-table PDF documents, and adapt to the formats of public notice materials and review forms in this category |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Support batch import of semester-level public notice materials and distribution list documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Meet the time requirements of batch multi-document parsing, to avoid timeout interruptions |
| `chunkSettingMode` | Manual mode | Allow adjustment of chunking parameters for exclusive documents of this category, to meet field retention requirements |

## Three common mistakes
- Some tables in uploaded knowledge base documents cannot be chunked properly, appearing as tables split into scattered text blocks. The cause is that chunking rules adapted to structured tables are not enabled. The default chunking logic prioritizes paragraph splitting and ignores the structural relevance of tables.
- Frequent out-of-memory errors occur when parsing documents after deployment, shown as system prompts indicating insufficient video memory. The cause is that GPU recognition parameters are not configured correctly, and the `chunkSize` setting exceeds the video memory quota of the current graphics card, with no adjustment of chunking parameters based on hardware.
- Image links are lost when importing markdown-format application materials, shown as images not displaying in conversations. The cause is that image domain names are automatically completed only when importing directly from Word, and the markdown import process does not inherit this configuration logic.

## How to confirm configurations are set correctly
- A single family economic hardship certification form is uploaded, and the parsed chunks are checked to confirm they retain core fields such as per capita household income and student ID number, with no missing or broken fields.
- The system parameter interface is viewed, and the settings for `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` are confirmed to match the configuration table, with the FastGPT v4.17.0 GPU recognition module loading normally.
- Five semester-level distribution list documents are batch imported, and the number of parsed chunks is checked to meet expectations, with no timeout or parsing failed entries.
- Public notice materials in Word and markdown formats are uploaded respectively, and image links in both formats are confirmed to carry the specified domain name, with no missing cases.
