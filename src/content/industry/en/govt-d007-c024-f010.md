# Application Material and Case Review for Student Financial Aid and Subsidy Audit: Knowledge Base Retrieval and Recall

## What this category of data consists of
The data for this category primarily originates from the national student financial aid management information system, school student status systems, civil affairs low-income and extremely impoverished household data, and fiscal payment systems. Daily processed documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, disbursement lists, and public notification materials. Fields covered include student ID numbers, low-income certification identifiers, bank card numbers, financial aid amounts, and more. Data updates follow a semester cycle. The volume of documents involved in a single audit batch fluctuates with the scale of the service entities. The core association dimension of a single data entry is the binding relationship between student identity and financial aid eligibility.

## Constraints imposed on knowledge base retrieval and recall by these characteristics
The multi-source cross nature of this category of data requires retrieval and recall to support cross-dataset associated matching. This ensures that information across dimensions such as student status, low-income certification, and fiscal payment can be linked and called. The semester-level update cycle requires the knowledge base to complete a full synchronization per semester. This prevents expired data from interfering with audit results. Document fields center on student identity identifiers and financial aid eligibility judgment items. Retrieval must prioritize matching these high-weight fields to reduce the return of irrelevant results. Format differences across multiple document types require retrieval configurations to adapt to different field structures. This prevents valid recall content from being lost due to field mismatches.

## How to configure settings
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the core association degree of student identity and eligibility fields, filters low-relevance non-audit content |
| `limit` | Top 10 entries | Controls context length to avoid exceeding model processing limits |
| `searchMode` | Semantic retrieval + keyword retrieval hybrid | Balances exact matching of core fields and eligibility judgment via semantic association |
| `usingReRank` | Enabled | Sorts recall results by relevance, optimizes the display position of highly matched content |
| `datasetSearchUsingExtensionQuery` | Enabled | Adds pre-fixed query terms related to student identity, improves recall accuracy for cross-source data |
| `collectionIds` | Fill in according to the actually bound financial aid-related datasets | Restricts retrieval scope to only official documents and system data of this category |

## Three common misconfigurations
- Phenomenon: Auxiliary data in retrieval results has higher priority than core certification field content. Cause: The `similarity` threshold is not configured, set too low, or the retrieval weight between core fields and auxiliary data is not distinguished.
- Phenomenon: Knowledge base retrieval results are returned even when the query is unrelated to financial aid audit. Cause: No specified reply logic is set for empty retrieval results, or the retrieval dataset scope is not correctly restricted.
- Phenomenon: The number of retrieval results returned in a single query exceeds expectations. Cause: The `limit` parameter is not set, or the parameter value is too high, causing context overflow that affects model output.

## How to verify correct configuration
- Upload a single family economic hardship certification form, run a retrieval with the keyword "student family economic hardship certification", and verify that the relevance scores of returned results fall within the preset range.
- Submit a test query unrelated to financial aid audit, and confirm that the system triggers the preset fallback reply and does not return knowledge base content.
- View retrieval logs, confirm that only the retrieval scope bound to financial aid-related datasets is called, and no irrelevant knowledge base content is retrieved.
- Adjust the `limit` parameter to the preset value, and verify that the number of retrieval results returned matches the set value.

The values provided here are common starting points, and should be evaluated against samples relevant to the actual use case.
