# Declaration Materials and Case File Review for Work Safety Hazard Investigation and Management: Tool Calling and Plugins

## What Data Looks Like for This Category
Data sources for this category include work safety supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. Update frequency is daily. Daily documents include hazard investigation checklists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Core fields cover hazard category, level, rectification responsible entity, rectification deadline, review results, and other related items. The content length of individual documents varies widely, ranging from hundreds to thousands of characters.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
The daily multi-source updated data requires tool calling to support multi-interface batch pulling and incremental synchronization, to avoid repeated processing of old data. The wide variation in document length requires the context adaptation logic of tool calling to be flexibly adjustable, to fit case file materials of different lengths. The requirement for core fixed fields requires the parameter configuration of tool calling to accurately match the extraction rules for fields such as hazard level and rectification deadline, to avoid information misalignment. Additionally, since errors may lead to major accidents and administrative penalties, the failure retry and exception capture mechanisms of tool calling must have high reliability.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to case file materials of different lengths, automatically selects appropriate tool calling logic |
| Tool call timeout duration | `600 seconds` | Processing a single case file requires multi-source data pulling and field extraction. 600 seconds covers processing durations for most scenarios |
| Batch execution node cycle limit | `Top 1000 entries` | The daily updated hazard data volume is usually within 1000 entries. Limiting the cycle upper limit avoids resource overload |
| `functionCall` | `Force match core fields` | Accurate extraction of core fields such as hazard level and rectification deadline is required. Forced matching improves information extraction accuracy |
| Tool call result filtering | `Hide input and response fields` | Case file review scenarios do not require exposing internal parameters of tool calls, simplifying output content |
| Failure retry count | `2–3 times` | Temporary network fluctuations may occur during multi-source interface calls. Limited retries reduce the impact of single call failures |

This configuration is based on FastGPT v4.17.0.

## Three Common Mistakes
- Symptom: After configuring the work safety supervision system database connection plugin, the call returns connection timeout or insufficient permission errors. Cause: The access whitelist for the corresponding system is not configured, or the timeout duration is set too short, failing to match the duration requirements for multi-source data pulling.
- Symptom: The tool call output retains the tool's input and response fields, which does not meet the output requirements for case file review. Cause: The tool call result filtering configuration is not enabled, or the filtering rule does not correctly match the fields to be hidden.
- Symptom: When calling the workflow via API, the batch execution node fails to complete all cycles, or the running data in the conversation log is empty. Cause: The cycle upper limit configuration of the batch execution node does not match the actual data volume, or the context parameters of the API call fail to correctly pass the tool call return results.

## How to Confirm the Configuration Is Correct
- Initiate a tool call test for a single case file, check whether the output content includes the required hazard fields, with no redundant internal tool parameters.
- Configure the batch execution node, import a small amount of test data, confirm complete cycle execution via online debugging, then adjust the cycle upper limit to match the actual data volume.
- Call the database connection plugin, verify that the daily updated hazard data can be pulled normally, with no connection errors.
- Initiate an API call, check whether the conversation log includes the running data of the tool call, with no null values.
