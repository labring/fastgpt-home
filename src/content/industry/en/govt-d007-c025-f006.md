# Declaration Materials and Case File Review for Work Safety Hazard Investigation and Governance: Source Citation and Traceability

## What this category of data looks like
The entities involved in this category include emergency management departments, industry competent departments, production and business unit safety management departments, and park management committees. Daily generated documents include hazard investigation lists, hazard governance ledgers, rectification notices, review records, and major hazard listing and supervision notices. Data sources cover work safety supervision systems, enterprise self-inspection systems for hazards, law enforcement inspection records, and accident statistics systems. The update frequency is daily. The core fields of a single document include the unique hazard identifier, rectification responsible entity, rectification time limit, and review result. Field formats vary slightly across different sources.

## What constraints do these characteristics impose on the "source citation and traceability" link
Because data sources are diverse and field formats differ, the traceability link must accurately match field identifiers across different systems to avoid association errors. Daily updated documents require the traceability process to support real-time synchronized data sources, ensuring that the latest rectification and review records are used during review. Mixed calls of multiple document types require the system to recognize the metadata characteristics of different documents and align them with the archiving requirements of case file review. The accuracy of traceability results is directly linked to the closed-loop management of hazard rectification. Matching errors may lead to deviations in subsequent supervision and accountability links.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 tokens | Matches the valid single-paragraph information length of hazard investigation documents, avoiding truncation of key fields such as rectification time limits and hazard IDs |
| `responseData` | Include document metadata and original text snippets | Retains database fields such as hazard ID and responsible entity, supports associating corresponding records via sourceid |
| `detail` | Enabled | Retains the Markdown format and field identifiers of the original document, allowing reviewers to quickly identify document types |
| Single recall limit | Top 10 entries | Covers multiple documents in a single batch of investigations, meeting the multi-source verification requirements for case file archiving |
| Similarity threshold | 0.75–0.85, calibrated via actual testing | Differentiates distinct rectification records for similar hazards, preventing incorrect traceability matches |

## Three Common Configuration Mistakes
- Recall results are empty, and the interface displays no matching documents. The cause is that `responseData` is not configured to return document metadata, making it impossible to associate field records in the corresponding database via sourceid.
- Context citations only display plain text without the Markdown format of the original document. The cause is that the `detail` parameter is not enabled, so the format identifiers of the original text are not retained.
- The number of recall results is insufficient to cover all hazard sources for this review. The cause is that the similarity threshold is set too high, filtering out some eligible law enforcement inspection records or investigation lists.

## How to Verify Proper Configuration
- Upload a hazard rectification notice, initiate a query asking for the rectification time limit of this notice, and check whether the returned context citations include the original text snippet and metadata of this document.
- Review the fields in the citation results to confirm whether they include database field information such as hazard ID and responsible entity.
- Test uploading multiple documents of the same type, initiate a query for batch hazard verification, and confirm that the number of returned results matches the preset single recall limit.
- Check the format of the cited content to confirm that Markdown identifiers such as original document titles and lists are retained.

Note: The configuration values listed above are common starting points. Adjustments should be made based on local sample data and use cases.
