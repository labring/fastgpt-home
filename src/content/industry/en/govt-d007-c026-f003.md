# Declaration Materials and File Review for Engineering Construction Project Approval: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform, with a daily update frequency. Commonly processed documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, completion record forms, and similar items. Most document structures combine structured forms and unstructured attachments, including fields such as participating construction unit qualifications, personnel qualifications, and approval node progress. There is no unified fixed unit, and adjustments are made according to specific approval items.

## Constraints imposed on multi-turn dialogue and prompt engineering
Decentralized data sources require dialogue to retrieve information across multiple systems. Daily updates require dialogue contexts to synchronize the latest data. Mixed document types require prompt engineering to clearly distinguish approval material types and verification rules. Verification of fields such as participating construction unit qualifications and personnel qualifications requires precise matching of cross-database data, which places higher requirements on the information extraction accuracy of the context window. Tracking parallel nodes in the approval process requires dialogue to associate historical approval links, and independent responses cannot be provided without context.

## Three common configuration mistakes
- When asking multiple consecutive questions in a dialogue, irrelevant content may be returned that does not match the current question. The cause is that the retention rules for the `messages` context are not configured correctly, causing the context window to be occupied by old data and failing to associate the context of the current approval link.
- After a tool call is made, both the tool call log and the AI response result are displayed, which does not meet the concise requirements of the review scenario. The cause is that the hiding rule for tool call results is not configured, and the complete process of tool execution is retained by default.
- An error is directly thrown when the conversation context exceeds the model's supported length, making material review impossible. The cause is that no context slicing rules are set, and key approval fields are not filtered, causing the overall content to exceed the window limit.

## How to verify correct configuration
- Initiate 3 consecutive questions related to approval material verification, and confirm that the response can associate the approval item information from previous conversations.
- Upload a single engineering approval document and initiate a question, and confirm that no context overflow error occurs in the dialogue.
- Trigger a tool call operation, and confirm that only the AI response result is returned, with no additional tool call logs displayed.
- Quickly locate the dialogue log for a single approval process via `chatId`, and confirm that log storage meets business archiving requirements.
