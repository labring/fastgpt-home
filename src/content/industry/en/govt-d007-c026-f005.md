# Declaration Materials and File Review for Engineering Construction Project Approval: Tool Calling and Plugins

This guide is developed for FastGPT v4.17.0. It organizes relevant configurations, parameters, and failure handling rules for tool calling and plugins in the declaration materials and file review scenario of engineering construction project approval.

## What this category of data looks like

The data for this category mainly comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform. The update frequency is once per day. Daily processed documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. Document fields cover project number, participating units’ qualifications, personnel practice qualifications, approval node status, and more. Some documents include multi-modal files such as construction drawing PDFs and qualification scan copies. The content scale and format of single documents vary widely.

## What constraints do these characteristics impose on the "tool calling and plugins" link

Data sources are scattered. Multiple external interfaces must be called to obtain qualification, credit, and other information. The daily update frequency requires tool calling to adapt to real-time data pulling logic. Daily documents include plain text approval applications and multi-modal attachments. Calling paths that distinguish different data types must be configured. File review requires associating data from multiple systems. Tool calling must ensure consistency checks for cross-system data, to avoid review deviations caused by data lag. The approval process has strict field verification requirements. Tool calling must accurately match document fields and verification rules, to ensure returned data meets business review requirements.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Automatically switch based on data type | Adapt to different calling requirements for plain text approval materials and multi-modal construction drawings, match mixed data processing scenarios in business |
| `functionCall` | Enable mandatory verification mode | Ensure fields returned by tool calling fully match approval document fields, meet precise verification requirements for file review |
| External interface call timeout | 30 seconds | Adapt to real-time requirements of cross-system data pulling, avoid blocking approval processes due to interface delays |
| Multi-modal attachment call limit | First 3 entries | Match the feature of small number of attachments in daily approval materials, reduce unnecessary tool calling overhead |
| Data synchronization frequency | 1 time per day | Match the daily update rhythm of business data, ensure timeliness of data used for review |

## Three common errors

-  When configuring `toolChoice`, fail to distinguish data types. This causes multi-modal construction drawings to be passed to plain text models, leading to incorrect return formats or no valid results. The root cause is that no corresponding calling rules are configured for document types, and the processing logic for multi-modal and plain text data is mixed up.
-  Set external interface call timeout too short. This causes data pulling failures from the enterprise qualification database and public credit platform, returning empty fields. The root cause is failure to adapt to response delays of cross-system interfaces, and not reserving sufficient calling time.
-  Do not enable field verification for `functionCall`. This causes the returned participating unit qualification information from tools to not match the fields in approval documents, leading to file review errors. The root cause is that the mandatory verification mechanism is not enabled, so consistency between returned data and business fields cannot be guaranteed.

## How to confirm the configuration is correct

-  Upload a test document containing plain text application materials and multi-modal construction drawings, check whether the tool calling automatically switches to the corresponding processing logic.
-  Call external interfaces to obtain enterprise qualification data, verify whether the field format of the returned results matches the field requirements of approval documents.
-  Simulate a cross-system data pulling scenario, confirm whether the interface call timeout setting meets the actual business response requirements.
-  Check the tool calling logs, confirm that the verification rules for `functionCall` are normally enabled, and there are no error prompts for field mismatches.
