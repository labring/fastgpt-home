# Construction Project Approval: Declaration Materials and File Review — Source Citation and Traceability

## What this category of data looks like
Data for this category comes from the construction project approval management system, construction drawing review system, enterprise qualification database, and public credit information platform. It is updated daily. Documents processed daily include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, completion record filing forms, and others. Document fields include project unique ID, participating construction unit qualification level, personnel qualification certificate number, approval node status, and others. The character count per single document varies widely. Some approval materials include structured forms and unstructured attachments.

## What constraints do these characteristics impose on source citation and traceability?
Daily updated data sources require the traceability process to pull the latest qualification and approval node data synchronously. This prevents audit errors caused by referencing expired information. Mixed multi-type document scenarios require traceability to distinguish citation logic for structured forms and unstructured attachments. This ensures accurate matching to the correct source of corresponding materials. Precise fields such as project number and participating unit qualification require traceability to associate data using unique identifiers. This avoids incorrect content association. At the same time, cross-system data sources require unified display formats for traceability. This allows original materials from corresponding systems to be quickly located during file review.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the character span of construction approval materials, fully retains key content required for traceability |
| `responseData` | Return only associated approval material fields | Focuses on core audit fields such as project number and participating unit qualification, filters irrelevant information |
| `detail` | Enable full traceability display | Shows the source system and update time of original materials, meets compliance audit requirements for files |
| Single search limit | Top 5 results | Matches the typical number of approval materials per project, avoids redundant results |
| Maximum context length | Calibrated based on actual testing | Adapts to the length requirements of cross-system data integration, ensures traceability information is coherent |

## Three common configuration mistakes
- An error message reading "No valid approval materials matched" appears in the interface. The cause is that `responseData` is not configured to only associate approval-related fields, leading the search scope to cover non-approval data.
- Results are returned even when the query is unrelated to construction approval matters. The cause is that a reasonable search limit is not set, introducing excessive low-relevance redundant content.
- The source system identifier of the material is missing from the traceability display. The cause is that the `detail` configuration item is not enabled, so metadata of the original data is not captured.

## How to verify correct configuration
- Upload a typical construction permit application material, initiate a query related to the corresponding approval matter, and verify that the returned results only include the associated fields of this material.
- View the traceability display area, and confirm that the source system and update time of the original material are shown.
- Adjust the value of `quoteMaxToken`, and test whether traceability information for materials of different lengths can be fully displayed.
- Use FastGPT v4.17.0 to initiate a test, and confirm that there are no abnormal errors after the configuration takes effect.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
