# Construction Project Approval Declaration Materials and File Review: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from the construction project approval management system, construction drawing review system, enterprise qualification database, and public credit platform, with full and incremental updates performed daily. Documents processed daily include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision documents, completion record forms, and more. Each individual document contains fields such as project number, participating unit qualifications, personnel practice qualifications, and approval node status. Some documents require cross-system qualification verification data and credit records. The data structure must align with cross-department collaborative verification rules.

## What constraints these characteristics impose during deployment and upgrade
Multiple system data sources and daily update frequency require a stable cross-system data synchronization link to be configured during deployment. Upgrades must retain compatibility with older version interfaces to avoid approval interruptions. Diverse document types require adaptation to multi-format parsing such as structured forms and PDF drawings. Expansion space for custom parsing rules must be reserved. Verification logic for cross-system associated fields must be tied to existing approval processes. Field mapping configuration must be completed in advance during deployment to prevent approval delays caused by data verification failures. Data storage security must also be ensured to prevent leaks of sensitive declaration materials.

## Configuration settings
The following configuration items apply to FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://admin:secure_pass@internal-host:5432/construction_db` | Connects to structured business data from the construction project approval management system, uses a standard relational database to store basic project information |
| `REDIS_URL` | `redis://:cache_auth@cache-host:6379/1` | Caches daily incremental qualification verification data and approval node status, reduces repeated query overhead |
| `STORAGE_S3_ENDPOINT` | `http://storage.internal:9000` | Stores large-volume documents such as construction drawing review qualification certificates and completion record forms, adapts to multi-format file storage requirements |
| `FILE_TOKEN_KEY` | `32-bit random encrypted string` | Encrypts access credentials for approval documents, restricts access to sensitive declaration materials only by authorized windows |
| `DB_MAX_LINK` | `80–120 requests per minute` | Limits the concurrency upper limit for cross-system data calls, adapts to interface call quotas for housing and urban-rural development systems |
| `FE_DOMAIN` | `https://approval-docs.internal` | Configures the frontend access domain name, matches the access address for internal approval windows |

## Three common mistakes
- Cross-system interface calls return 500 errors. This occurs when connection parameters for `PG_URL` or `REDIS_URL` are not configured correctly, leading to failure to read business data from the approval management system, or authentication failure for the cache link.
- Full declaration materials fail to load after offline deployment. This occurs when `STORAGE_S3_ENDPOINT` is not configured to point to a local storage node, preventing access to locally stored document resources in an offline environment.
- Script loading errors appear on the frontend page. This occurs when the domain name configured for `FE_DOMAIN` does not match the actual deployment address, leading to failure to load frontend resources normally.

## How to confirm correct configuration
- Run a standard database connection test command targeting the configured `PG_URL` address to confirm normal database connectivity.
- Upload a standard construction permit application material, check whether `STORAGE_S3_ENDPOINT` can properly store and retrieve the file.
- Trigger a cross-system qualification verification request, confirm that `REDIS_URL` can normally cache verification result data.
- Access the configured `FE_DOMAIN` address, check that the frontend page has no script loading or resource loading errors.

The values provided are common starting points, and should be evaluated against samples specific to the actual deployment.
