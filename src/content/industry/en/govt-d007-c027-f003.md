# Bid Documentation and File Review for Construction Projects: Multi-turn Dialogue and Prompting

Reference only; verify against the target FastGPT release and deployment documentation.

## What This Category of Data Looks Like
Data sources include national public resource trading platforms, local trading platforms, project approval systems, and bidding and tendering supervision systems, with a daily update frequency. Commonly processed documents include bidding announcements, qualification pre-qualification documents, bidding documents, tender documents, bid evaluation reports, winning candidate announcements, and winning result announcements. Documents contain fields such as bid section number, qualification requirements, performance requirements, bill of quantities, and construction period. Associated units include ten thousand yuan, days, square meters, and similar units.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompting Workflow
Daily updated data sources require real-time retrieval of the latest document content to avoid using expired data. Significant field differences across multiple document types require clear identification of the current document type during multi-turn dialogue to prevent confusion of review standards. Variations in document formats across different sources require prompts to adapt to the structural characteristics of different documents. The consequences of project errors are severe, so each response in multi-turn dialogue must undergo strict verification to ensure compliance with bidding and tendering related regulations.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `messages` | Limit context to 10,000 characters or fewer per single-turn dialogue | Adapts to the length of core content for a single bidding document |
| `chatId` | Bind to the unique identifier of the project bid section | Distinguishes independent dialogue contexts for different bidding projects |
| `variables` | Preset qualification requirements, bill of quantities fields | Quickly call structured data for this category |
| Maximum context length | 8000–12000 token | Covers the full review scope of a complete bidding document |
| Maximum number of single matching results | Top 6 | Avoids redundant information interfering with review judgments |
| Streaming output interval | 1–2 seconds per response | Adapts to smooth front-end display requirements |

## Three Common Mistakes
- Phenomenon: The links returned by streaming output only cover the current page and cannot jump to new pages. Cause: No dedicated context jump rules configured for link types in bidding documents.
- Phenomenon: The conversation log details are exactly the same as the actual generated response, and are not affected by the number of multi-turn dialogue turns. Cause: The `messages` parameter does not correctly pass each round of user questions and assistant responses, resulting in unupdated context.
- Phenomenon: Streaming output consistently returns data every 4 seconds and cannot be adjusted to a shorter interval. Cause: The streaming output trigger interval configuration is not adjusted based on front-end display requirements.

## How to Verify Proper Configuration
- Initiate a multi-turn review dialogue for the tender document of a specific bid section, and check if `chatId` is bound to the unique identifier of the corresponding bid section.
- View the conversation log to confirm that the `messages` parameter for each round includes the current round's question and historical context.
- Test streaming output and observe if the return interval falls within the preset 1–2 second range.
- Input a complex question containing qualification requirements and bill of quantities, and check if `variables` correctly calls the preset structured fields.

The values provided are common starting points and should be measured against the reader's own samples.
