# Construction Project Bidding and Tendering: Declaration Materials and File Review - Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category originates from the national public resource trading platform, local trading platforms, project approval systems, and bidding and tendering supervision systems. Updates occur daily.
Commonly processed documents include bidding announcements, qualification pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements.
Document structures revolve around core fields such as section division, qualification requirements, bill of quantities, and bid evaluation rules. Most fields include project numbers, section information, qualification conditions, performance requirements, and bid evaluation expert information. There is no unified fixed unit; values vary based on document type.

## Constraints Imposed on the Tool Calling and Plugins Workflow
Scattered data sources with daily updates require calling multiple platform interfaces to sync the latest documents. Adaptation to different platforms' interface formats is necessary.
Many document types with significant structural differences require tailored tool calling rules for each type to avoid field matching errors.
Core fields include sections, qualifications, and performance. Tool calling must accurately locate these fields, otherwise review accuracy will be compromised.
Large daily data volumes require setting reasonable frequency limits for tool calling to avoid exceeding interface call quotas.
Documents related to bid evaluation reports and objection and complaints involve sensitive information. Permission verification must be configured for tool calling to prevent data leaks.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `auto` | Adapt to automatic matching needs for different bidding and tendering document types. Automatically call corresponding tools based on document titles and content |
| `functionCall` | Enabled | Force tool calls to return structured results, simplifying extraction of core review fields such as sections, qualifications, and performance |
| Single tool call data limit | First 8–12 entries | Match the daily batch document processing rhythm, avoid exceeding the interface's carrying capacity with a single call data volume |
| Tool call timeout | 600 seconds | Accommodate processing durations for large construction project documents, prevent call interruptions due to lengthy documents |
| Tool call retry count | 3 times | Support automatic recovery after interface call failures, reduce manual intervention |
| Interface permission verification | Bind dedicated call keys | Comply with security requirements of bidding and tendering supervision systems, restrict unauthorized entities from accessing sensitive document data |

## Three Common Misconfigurations
- Symptom: Tool calls return empty fields. Cause: No matching rules for tool calls are configured for core fields of bidding and tendering documents (such as section numbers, qualification requirements). The tool cannot accurately extract corresponding content.
- Symptom: When calling tools via API, logs display title content but review results are abnormal. Cause: The `functionCall` parameter is not configured correctly. Tool call results are not structured, preventing automatic file review.
- Symptom: Added custom keys cannot complete tool calls. Cause: No dedicated authorization key for the public resource trading platform is bound. This fails to meet the interface permission verification requirements of the supervision system.

## How to Confirm Proper Configuration
- Upload a single bidding and tendering document. Check if tool calling triggers automatically and returns corresponding structured results. Adjust the `toolChoice` configuration based on returned results.
- Submit batch documents via API call. Check if the interface returns the expected status code. Adjust the timeout configuration based on returned error information.
- View tool call logs. Confirm that only authorized keys can initiate calls. Verify that the interface permission configuration is effective.
- For bid evaluation report documents, manually verify that extracted expert information and bid evaluation results match the original text. Adjust field matching rules as needed.
