# Declaration Materials and Dossier Review for Engineering Construction Project Bidding: Deployment and Upgrade

## What data for this category looks like
This category’s data originates from the national public resource trading platform, local trading platforms, engineering approval systems, and bidding and tendering supervision systems. Data updates occur daily. Daily documents include bidding announcements, qualification pre-qualification documents, bidding documents, tender documents, bid evaluation reports, public notices of successful bidders, and successful bid result announcements. These documents cover core fields for engineering construction projects: section division, qualification requirements, bill of quantities, and construction period. Development and reform departments, industry competent departments such as housing and urban-rural development, transportation, and water conservancy, public resource trading centers, and bidding agency institutions generate and maintain these documents.

## Constraints imposed by these characteristics on deployment and upgrade
Multi-source, heterogeneous document structures require adapting text parsing and index configurations for different formats during deployment. The daily updated data volume requires stable database and cache support to prevent synchronization interruptions. Review of bidding and tendering documents includes compliance verification. Sufficient connection resources must be reserved during deployment to handle concurrent access requests. During upgrades, consistency between metadata and document storage must be maintained to prevent interruptions to the dossier review process caused by configuration changes. Interface specifications of existing business systems must also be compatible to avoid disrupting the circulation of existing declaration materials.

## Three common errors
- After upgrading to FastGPT v4.17.0, an error occurs when using knowledge base question answering. The log shows a 404 status. The cause is that `STORAGE_S3_ENDPOINT` is not configured correctly, or the read/write permissions of the corresponding storage bucket are incorrect, resulting in failure to properly read document metadata.
- The database connection fails after running the initial deployment script. The cause is that the `MONGODB_URI` or `PG_URL` parameters are filled incorrectly, and do not match the database address, username, or password of the deployment environment.
- An empty result is returned when calling a database query for dossier data in a workflow. The cause is that `REDIS_URL` is not configured as a cache middleware, resulting in failure to synchronize the configuration of session context and database connection pool.

## How to confirm the configuration is complete
- Access the FastGPT backend knowledge base management page, view the synchronized document list, and confirm that core documents of this category such as bidding announcements, tender documents, and bid evaluation reports are included.
- Initiate a question-and-answer request targeting the qualification requirements in the qualification pre-qualification document, verify that the returned result has no errors and matches the specific content in the document.
- Review system operation logs, confirm that the connection status of `MONGODB_URI` and `REDIS_URL` shows normal, with no timeout or connection refused errors.
- Trigger a manual synchronization task, check whether the newly added successful bid result announcement is automatically imported into the knowledge base, and confirm that metadata is complete.
