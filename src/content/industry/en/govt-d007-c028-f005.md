# Declaration Materials and File Review for Market Entity Registration and Licensing: Tool Calling and Plugins

## What data in this category looks like
This category of data is sourced from the full-process electronic enterprise registration system, the National Enterprise Credit Information Publicity System, the electronic business license system, and the residence information database, with daily updates. Commonly processed documents include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and similar materials. Most documents are a mix of structured forms and unstructured text, with fields covering entity name, residence address, shareholder information, license type, and other relevant details. There is no unified fixed unit, so identification must be carried out in combination with specific business scenarios.

## What constraints do these characteristics impose on the tool calling and plugins workflow?
Multiple data sources with daily updates require that tool calls connect to official systems in real time to obtain the latest entity information and avoid using expired data. Documents contain a mix of structured and unstructured content, so plugins must support parsing and field extraction for both formats. Document fields vary significantly across different business scenarios, so tool calling parameters must adapt to multiple form structures and cannot rely on fixed field templates. The verification step also relies on cross-verification of multi-source data, so plugins must call multiple data sources to complete comparisons. Call frequency must be reasonably allocated to avoid triggering system rate limits.

## Three common configuration mistakes
- Symptom: Tool calls do not return the latest data from the registration system, and generated content deviates from the original declaration materials. Cause: Official data sources are not configured as prioritized tools, and the model mistakenly uses general knowledge base content as the review basis.
- Symptom: Custom plugin display names differ between the system plugin list and the call interface. Cause: The interface display name and code identifier name are not filled in synchronously in the plugin configuration, causing the two locations to read from different name sources.
- Symptom: Extra numeric 0 appears in debug tool call return results. Cause: The output format of `functionCall` is not limited, and the model generates irrelevant formatted characters that interfere with field extraction of review results.

## How to confirm the configuration is complete
- Initiate a test call simulating a declaration material submission, and verify whether the tool has called the specified data sources such as the registration system and residence information database.
- Check the plugin call logs to confirm that the number of tools called each time meets the configured limit, and no additional irrelevant tools are triggered.
- Review the return results in the debug interface to confirm that no extra meaningless characters or fields appear.
- Verify that global variables are automatically included during tool calls, ensuring that data source access permissions are normal.
