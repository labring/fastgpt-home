# Declaration Materials and File Review for Market Entity Registration and Licensing: Source Citation and Traceability

## What data for this category looks like
Documents covered under this category include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and similar materials. Data is sourced from the full-process electronic enterprise registration system, national enterprise credit information publicity system, electronic business license system, and residence information database, with updates daily. Most documents are structured forms and compliance certification files. Fields include entity name, unified social credit code, residence address, license scope, and similar items. No extra custom unit identifiers are present. Core fields must fully match data from official systems.

## What constraints these characteristics impose on the source citation and traceability workflow
Data sources for this category are scattered and updated daily. The citation and traceability workflow must directly link to the latest snapshot of official systems, to avoid verification failure caused by using expired cached data. Most documents are structured forms and compliance certificates. Precise matching of core fields such as unified social credit code and residence address is required; fuzzy semantic retrieval alone cannot meet requirements. Data scale continues to grow with the increase in market entities. Retrieval token usage must be strictly controlled to prevent triggering time-out limits. At the same time, verification errors will directly lead to registration rejection or operational restrictions. The confidence level of traceability results must meet standards that can be directly used for official review.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | A single core declaration material for this category is approximately 1000-2000 characters. Combined with the need to reference multiple files, sufficient tokens are reserved to retain complete original text details |
| `responseData` | `Only return original knowledge base content` | Original document content must be directly output for official review, to avoid AI rewriting causing field mismatches with official systems |
| `detail` | `Fully retain original format and content` | Declaration materials and files must fully display all fields of certification documents, with no key information omitted |
| Single retrieval limit | `Top 6 retrieval results` | This category covers multiple scenarios such as establishment, modification, and licensing. 6 results can cover associated data for common files |
| Retrieval matching threshold | `Calibrated through actual testing` | Must match the field accuracy of official system data, to avoid low-matching results interfering with review |

## Three common configuration errors
- Issue: AI-generated content has been modified and rewritten. Cause: `responseData` was not configured to only return original knowledge base content.
- Issue: Insufficient number of retrieval results leads to key files not being cited. Cause: Single retrieval limit was set too low, failing to cover associated data requirements for multiple scenarios.
- Issue: Retrieval triggers time-out or token overflow errors. Cause: `quoteMaxToken` setting exceeds the model's supported range, and parameters were not adjusted based on the document scale of this category.

## How to confirm proper configuration
- Upload a single declaration material document to trigger retrieval, check that returned content fully matches the original text, with no AI-modified or polished content.
- Simulate a multi-file associated retrieval scenario, check that the number of returned results matches the preset single retrieval limit.
- Adjust the `quoteMaxToken` parameter, test retrieval response duration across different values, confirm no time-out errors occur.
- Check that the platform version identifier is FastGPT v4.17.0, to ensure use of the current stable version's features.

The values provided are common starting points and should be measured against the reader's own samples.
