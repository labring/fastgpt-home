# Market Entity Registration and Licensing: Declaration Materials and Case Review — Model Access and Configuration

## Data Profile for This Category
This category includes daily documents such as establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, and food business license applications. Data sources include the full-process electronic enterprise registration system, the National Enterprise Credit Information Publicity System, the electronic business license system, and the residence information database. Data is updated daily. Most documents combine structured forms and unstructured text, with core fields including entity name, residence address, shareholder information, and licensing items. Some review links require cross-verification by associating external public data.

## Constraints for Model Access and Configuration
Daily data updates require models to support near-real-time data pulling after access. This avoids using expired public information that reduces review accuracy. Mixed multi-type document processing needs parsing rules adapted to different formats. This ensures accurate identification of both structured form fields and unstructured text content. Cross-system data association needs configuration items that support unified access to multiple data sources. It also requires consistent verification of data from different sources. Differences in document field standardization need model context length configurations that cover full business field content. This prevents truncation of key information.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Covers complete content of multiple documents in declaration materials, avoiding truncation of key fields such as shareholder information and residence address |
| `maxTokens` | 4000 token | Adapts to output length of a single review result, ensuring full return of contents such as rectification opinions and verification conclusions |
| `quoteMaxToken` | 2000 token | Limits length of referenced external public data, preventing redundant content from interfering with review judgments |
| `toolChoice` | auto | Supports models in autonomously choosing whether to call external data interfaces for cross-verification |
| `temperature` | 0.2–0.4 | Reduces randomness of review results, ensuring consistency in business judgments |
| `AIPROXY_API_ENDPOINT` | Fill in actual access address based on deployment environment | Adapts to internal or external network model access paths, ensuring normal connection |

## Three Common Configuration Mistakes
- Incorrect model access point configuration displayed in the interface, preventing successful calls. The root cause is failure to correctly match the actual deployment address of `AIPROXY_API_ENDPOINT`, and incorrect entry of the external network address mapped from the internal network.
- The knowledge base remains in the indexing state indefinitely and cannot complete initialization. The root cause is that the data source is a daily updated public system, and no reasonable incremental index triggering rule is configured, leading to repeated full index execution.
- Driver errors occur when deploying the Ollama large model using an AMD GPU. The root cause is failure to adapt to the AMD GPU’s model quantization format, or incompatibility between the driver version and the large model running environment.

## How to Confirm Proper Configuration
- Run the built-in model test call function included in FastGPT v4.17.0. Input a standard establishment registration application template, and check if the returned verification result includes judgments for all required fields.
- View the knowledge base index logs. Confirm that the daily incremental update task triggers normally, with no timeout or failure records.
- Check the returned results of model calls. Confirm that referenced external data comes from the specified public system, with no irrelevant content included.
- Access the configured `AIPROXY_API_ENDPOINT` in the internal network environment. Confirm that network connections work normally, with no timeout errors.
