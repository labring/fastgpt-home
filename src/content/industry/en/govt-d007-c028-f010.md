# Declaration Materials and File Review for Market Entity Registration and Licensing: Knowledge Base Retrieval and Recall

## Data Processed by This Category
Documents processed by this category are mostly fixed-format declaration materials and archived files. These include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and similar items. Data is primarily sourced from the full-process electronic enterprise registration system, the national enterprise credit information publicity system, the electronic business license system, and the residence information database, with daily synchronized updates. Document structures primarily use structured form fields, supplemented by unstructured supporting materials. Fields cover core content such as entity name, residence address, shareholder information, and license application items.

## Constraints on Knowledge Base Retrieval and Recall
Fixed-format declaration materials and archived files require retrieval to match both structured fields and unstructured text. A single retrieval mode cannot cover all document types. Daily updated data sources require the retrieval pipeline to support incremental synchronization and high-frequency recall, to avoid mistakenly recalling expired data. The need for precise matching of core fields limits the flexibility of fuzzy retrieval. File review requires associating multi-source data, so retrieval results must include associated content across multiple datasets, to avoid information gaps from single data sources.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches fixed-format fields of declaration materials, balances precision and recall coverage |
| `limit` | Top 6 entries | File review requires associating up to 6 core supporting materials, to avoid redundant results interfering with review |
| `searchMode` | hybrid | Matches both structured fields and unstructured text, covering both document types of declaration materials |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, improves ranking priority for core fields such as shareholder information and residence address |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands and associates multi-source data such as the national enterprise credit information publicity system, to complete associated information required for file review |
| `collectionIds` | Configured per business dataset group | Distinguishes declaration material libraries and file review libraries, to avoid interference from cross-category data |

## Three Common Configuration Mistakes
- Symptom: No download links appear in retrieval results after publishing the application, but works normally in debug mode. Cause: Public access permissions for the dataset are not configured, or document download permissions are not enabled for the application. Temporary access permissions are only retained in debug mode.
- Symptom: Format errors occur when importing declaration materials via Excel, and import cannot be completed. Cause: The Excel table was not organized according to the fixed field format of the category documents, and did not match the required mandatory fields for declaration materials.
- Symptom: Knowledge base vectorization tasks take too long, exceeding expected duration. Cause: Large-volume PDF archived files were not properly chunked, or appropriate chunking parameters were not configured, leading to overly high single-file vectorization load.

## How to Verify Proper Configuration
- Use the knowledge base management interface of FastGPT v4.17.0, enter the configuration page of the corresponding business dataset, and check the switch status of `datasetSearchUsingExtensionQuery` to confirm that multi-source data association configuration is enabled.
- Perform a single retrieval test, check whether the number of returned results matches the configured value of `limit`, and whether the ranking matches the expected effect of `usingReRank`.
- Compare retrieval results between debug mode and the published application, confirm that the download link display logic meets configuration requirements.
- View the progress logs of vectorization tasks, confirm that chunking parameters for large-volume documents are adapted to the length requirements of category documents.
