# Declaration Materials and Case File Review for Market Entity Registration and Licensing: Deployment and Upgrade

## What this category of data looks like
This category of data mainly comes from the full-process electronic enterprise registration system, the National Enterprise Credit Information Publicity System, the electronic business license system, and the residence information database, and is updated daily. Commonly processed documents include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and more. Data fields cover entity name, residence address, shareholder identity information, pre- and post-licensing conditions, and more. The character count of individual documents varies widely, including mixed content of structured fields and unstructured text.

## What constraints these characteristics impose on the deployment and upgrade link
Multi-source government data updated daily for this category requires a stable intranet database connection and synchronization mechanism to be configured during deployment. This avoids interruptions to the review process caused by data pull timeouts.
Mixed-format business documents require configuration items adapted to different parsing rules. This ensures that both structured fields and unstructured text can be correctly identified.
Since data sources involve multiple government systems, permissions and proxy parameters for cross-system access must be configured in advance during deployment. Configuration space for failure retries and log retention must also be reserved to address risk scenarios such as verification rejection and false registration.

## How to set the configurations
The content on this page is adapted to the FastGPT v4.17.0 deployment process.

| Configuration Item | Recommended Approach | Basis for This Setting |
| --- | --- | --- |
| `MONGODB_URI` | Full URI connecting to the dedicated MongoDB instance on the government intranet, for example `mongodb://internal-mongo:27017/reg_db` | Business data of this category must be stored in a compliant intranet environment to avoid leakage of sensitive entity information |
| `REDIS_URL` | Configure the address of the intranet Redis cache instance, set the cache validity period to 86400 seconds | Matches the daily update cycle of data for this category, reducing overhead from repeated pulls of government system data |
| `DB_MAX_LINK` | 10–15 | Adapts to the average daily number of declaration materials and case files to avoid exhausting database connections |
| `STORAGE_S3_ENDPOINT` | Point to the endpoint address of the intranet object storage service, for example `http://internal-storage:9000` | Sensitive documents of declaration materials and case files must be stored in an intranet environment to comply with government data regulatory requirements |
| `FILE_TOKEN_KEY` | Configure a signature key matching the intranet file system | Ensures only authorized internal review systems can access stored documents, preventing unauthorized access |

## Three common configuration mistakes
- A configuration error prompt pops up when creating a knowledge base, and the log shows a database connection timeout. The cause is that `MONGODB_URI` is not configured as an intranet-accessible instance address, and a public network database address is used by mistake.
- An error `Cannot read properties of undefined` appears when opening the workflow, and the log points to the file reading link. The cause is that `FILE_TOKEN_KEY` is not configured correctly, making it impossible to read declaration documents stored on the intranet.
- Unable to synchronize external government system data in the intranet environment, with a connection timeout prompt. The cause is that the username and password parameters of the intranet proxy are not configured, making it impossible to access external data interfaces through compliant proxies.

## How to confirm configurations are correctly set
- Run the built-in database connection test tool to verify that the instances configured with `MONGODB_URI` and `REDIS_URL` can establish normal connections.
- Upload a standard establishment registration application document to confirm that preset fields such as entity name and residence address can be correctly extracted after parsing.
- Trigger a manual data synchronization task to confirm that daily updated case file data can be pulled from the specified government system.
- Check the system operation logs to confirm that all data flows are completed in the intranet environment, with no unauthorized external access records.
