# Declaration Materials and Case File Review for Urban Environmental Sanitation and Urban Management Law Enforcement Cases: Tool Calling and Plugins

## What data for this category looks like
This category of data typically comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders, and is updated daily. Daily documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and closing reports. Fields cover event occurrence time, point coordinates, violation type descriptions, rectification requirements, and execution status. Some documents include multimedia files.

## What constraints these characteristics impose on the "tool calling and plugins" link
Data sources for this category are scattered and include unstructured content. Tool calling must adapt to field extraction across multiple document types, and support associating core fields such as point coordinates and violation types. The daily update feature requires that the context for tool calling be limited to case data from the current day or the past 3 days, to avoid introducing outdated redundant information. The on-site disposal attribute means that tools must prioritize matching the association between inspection records and on-site photos, and parameter validation must cover required fields for evidence documents to prevent insufficient case evidence due to missing fields.

## Three common mistakes
- Phenomenon: Parameters passed during tool calling fail to accurately extract point coordinates or violation types from cases, causing tools to fail to match core business logic. Cause: No parameter extraction rules are configured, and segmented fields in user questions are not mapped to the required parameters of the tool.
- Phenomenon: Tool calls return a 400 status code or empty results. Cause: Required fields required by the tool are not validated, and the case file documents passed lack core information, causing the tool to fail to process normally.
- Phenomenon: Plugins cannot re-export properly formatted configuration files after updates. Cause: Configuration is not saved correctly in the plugin management interface before export, or the correct format option is not selected during export.

## How to confirm the configuration is correct
- Initiate a simulated urban management case review request, check whether point coordinates and violation type parameters are automatically extracted during tool calling.
- Upload a simulated case file missing point coordinates, confirm that the system triggers a prompt for missing parameters.
- Call a tool to process on-site photos, check whether matching inspection record association information is returned.
- Modify the plugin configuration, re-export the configuration file, and confirm that the format meets requirements.
