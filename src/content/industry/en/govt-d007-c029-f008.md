# Declaration Materials and Case File Review for Urban Environmental Sanitation and Urban Management Law Enforcement Cases: Document Parsing and Chunking

## What This Category of Data Looks Like
It typically originates from urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders. The update frequency is daily. Common documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and case closure reports. Most document structures contain fields such as on-site descriptions, responsible party information, rectification requirements, and penalty content. Some documents include image attachments, with formats covering PDF, Excel, and image archive files.

## Constraints Imposed on Document Parsing and Chunking
Documents in this category come from scattered sources and include mixed text and image content. This demands that the parsing module adapt to both structured tables and unstructured text, as well as image attachments. Unlike professional law enforcement in areas such as market supervision, cases in this category mostly come from inspections and grid discoveries. Documents are mostly generated on-site in real time, with greater structural flexibility. The high-frequency daily data update requirement creates clear constraints on the response speed of parsing and chunking. The structures of multiple types of law enforcement documents vary significantly. Some documents have non-fixed fields, requiring flexible adjustment of chunking logic to match different case file formats. On-site photos are closely tied to text content. The chunking process must retain their association to avoid losing contextual connections after splitting.

The following configurations are based on FastGPT v4.17.0.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the field length of single case files for law enforcement documents, avoid losing the association between responsible parties and factual violations after splitting |
| `chunkSplitter` | By paragraph + semantic boundary | Adapt to documents with large structural differences such as inspection records and penalty decisions, retain semantic completeness |
| `customPdfParse` | Enable image-text separation mode | Process documents such as filing approval forms that include on-site photos, separate text and image metadata |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodate single-batch bulk uploads of law enforcement case file archives, meet bulk daily inspection filing requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Address parsing time consumption for complex documents containing multiple on-site photos, avoid timeout interruptions |
| `chunkSettingMode` | Custom mode | Adjust chunking rules for different law enforcement document types, adapt to structural differences between inspection records and penalty decisions |

## Three Common Mistakes
- Phenomenon: On-site photos in the parsed document are not associated with the corresponding text paragraphs. Cause: The image-text separation configuration of `customPdfParse` is not enabled, resulting in incorrect splitting or chaotic binding of images and text.
- Phenomenon: Embedded on-site photos cannot be properly recognized when uploading Excel-format complaint work orders. Cause: The default parsing rule does not adapt to table documents containing embedded images, and the cross-format image-text parsing logic is not enabled.
- Phenomenon: The number of chunks after parsing bulk case file archives exceeds expectations. Cause: The `chunkSize` value is too small, splitting a single penalty decision into multiple chunks, making it impossible to fully match factual violations and penalty basis during subsequent review.

## How to Verify Configurations Are Set Correctly
- Upload a filing approval form that includes on-site photos, check whether the parsing result retains the association between image metadata and corresponding text paragraphs.
- Upload bulk inspection record documents, verify that no parsing timeout errors occur under the configured `PARSE_FILE_TIMEOUT_SECONDS` value.
- Adjust the `chunkSize` parameter, then upload a penalty decision, confirm that a single penalty content is not split into multiple semantically incomplete chunks.
- Upload an Excel-format complaint work order, check whether embedded images are correctly recognized and associated with the corresponding work order entries.
