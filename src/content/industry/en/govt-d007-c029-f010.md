# Declaration Materials and Case File Review for Urban Environmental Sanitation and Urban Management Law Enforcement Cases: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category primarily comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance devices, and public complaint tickets. Daily generated documents include inspection records, case filing approval forms, on-site photos, correction order notices, penalty decisions, and case closure reports. Data updates occur daily. Common fields include inspection time, violation location coordinates, responsible party information, rectification requirements, and case numbers. Some documents include unstructured on-site images and colloquial complaint content.

## What constraints do these characteristics impose on knowledge base retrieval and recall?
Multi-source heterogeneous data sources require the retrieval system to support structured ledgers, unstructured images, and unstructured text. Format incompatibility will cause missed recalls otherwise.
Daily updated data needs a synchronization mechanism. This keeps the knowledge base matched to the law enforcement platform in real time. Outdated information will interfere with review without this step.
Precise matching is required for the link between on-site photos and inspection records. Broken case evidence chains will result otherwise.
Colloquial public complaints and standardized law enforcement document terminology differences will cause basic retrieval to miss associated case files. Extra terminology optimization steps are needed to address this.

## How to set up the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.88 | Matches core law enforcement fields for urban management cases. Prevents irrelevant results if set too low, and filters weakly associated supplementary evidence if set too high |
| `limit` | Top 8–12 entries | Covers the number of associated materials required for case file review, and avoids exceeding context window limits |
| `usingReRank` | Enabled | Re-ranks initial retrieval results to prioritize documents strongly related to violation types and responsible parties |
| `datasetSearchUsingExtensionQuery` | Enabled | Converts colloquial complaints from grid inspectors into standardized law enforcement terminology, improving retrieval matching across data sources |
| `collectionIds` | Bind the exclusive dataset ID for urban management law enforcement case files | Isolates knowledge base data from other business scenarios, preventing irrelevant content from interfering with the current review process |

## Three common configuration errors
- Issue: When retrieving law enforcement ledgers in Excel format, the number of overseas use location entries returned is less than the source file. Cause: `datasetSearchUsingExtensionQuery` retrieval term optimization is not enabled, or the `similarity` threshold is set too high, filtering some weakly matched associated data.
- Issue: When calling a third-party interface to send a retrieval request, an `Error: write EPROT` error is returned. Cause: HTTPS request timeout parameters are not configured correctly, or the interface response rules of the urban management law enforcement platform are not adapted.
- Issue: Multiple duplicate inspection record documents exist in the knowledge base, and automatic deduplication is not completed. Cause: Duplicate file recognition configuration is not enabled, or valid versions are not filtered based on document update time.

## How to confirm the configuration is complete
- Upload a set of standardized urban management case file documents, retrieve "unauthorized road occupation", and check if returned results include associated materials such as filing approval forms, on-site photos, and penalty decisions.
- Upload an Excel law enforcement ledger containing overseas use location records, retrieve relevant keywords, and verify that the number of returned entries matches the source file.
- Call a third-party interface to send a test request, confirm that the returned status code is 200 and no `Error: write EPROT` type errors occur.
- Check the duplicate file management interface of the knowledge base, and confirm that redundant inspection records have been automatically cleaned up or marked.
