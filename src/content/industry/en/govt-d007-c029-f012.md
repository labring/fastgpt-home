# Declaration Materials and Case File Review for Urban Sanitation and Urban Management Law Enforcement Cases: Deployment and Upgrade

## What this category of data looks like
Typical data for urban management law enforcement and urban sanitation cases originates from urban management law enforcement platforms, urban operation grid platforms, video surveillance systems, and public complaint work orders. Data is updated daily. Daily documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and closing reports. The structure covers on-site evidence attachments, approval process forms, and law enforcement document files. Fields include law enforcement subjects, case locations, descriptions of violations, party information, and other relevant details.

## What constraints these characteristics impose during deployment and upgrade
The need to access multi-source heterogeneous data requires compatibility with different system formats and interfaces during deployment. It also requires ensuring synchronization link stability during upgrades.
Daily updated case data requires scheduled synchronization tasks. Configure a reliable scheduled trigger mechanism during deployment. Avoid synchronization task interruptions that cause information delays during upgrades.
Large-volume on-site photos and law enforcement documents require configuring appropriate storage services during deployment. Ensure compatibility with large file parsing and transmission during upgrades.
The multi-node review process requires database and cache services to have high availability capabilities. This avoids single points of failure that disrupt case review progress.

## How to set configurations
This page’s configurations are based on FastGPT v4.17.0. The specific configuration items and recommendations are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 150–200 | Meets concurrent connection requirements for multi-source data synchronization and multi-node review, and avoids exhausting database connections |
| `MONGODB_URI` | Full connection string with read-write separation address | Stores multiple versions of case file documents and law enforcement records. Read-write separation improves query and write performance |
| `REDIS_URL` | Cluster connection address with password authentication | Caches frequently queried basic case information and work order status to reduce database load |
| `STORAGE_S3_ENDPOINT` | Endpoint address adapted to local object storage, supports a maximum single file size of 1000 MB | Stores large-volume attachments such as on-site photos and law enforcement documents, and meets daily update storage requirements |
| `FILE_TOKEN_KEY` | Random key determined through actual testing | Generates attachment access tokens to ensure access permission security for case file materials |
| `FE_DOMAIN` | Internal domain name of the urban management law enforcement system | Restricts front-end access scope to ensure access security for internal review scenarios |

## Three common mistakes
- Symptom: A several-second delay occurs when dragging on the workflow canvas, and nodes load slowly. Cause: The `DB_MAX_LINK` configuration was not adjusted for the concurrent multi-node review process of urban management law enforcement cases, leading to excessive system resource usage.
- Symptom: Case file attachments cannot be accessed normally, returning a 403 permission error. Cause: `FILE_TOKEN_KEY` was not configured correctly, leading to failed attachment access token verification.
- Symptom: Multi-source data synchronization tasks are interrupted, and case information is not updated in a timely manner. Cause: `REDIS_URL` was not configured for cluster mode. A single point of failure caused the cache service to stop operating.

## How to confirm the configuration is complete
- Run the built-in database connection test tool in FastGPT to verify that the number of connections set by `DB_MAX_LINK` can be accessed normally concurrently.
- Upload an on-site photo attachment, and use the generated access link to verify that it can be opened normally without permission errors.
- Trigger a daily data synchronization task, and check the system logs for no connection exhaustion or timeout errors.
- Access the configured `FE_DOMAIN` to confirm that the case file review interface can normally load the case list and associated attachments.
