# Declaration Materials and File Archive Review for Construction Engineering Quality and Safety Supervision: HTTP Interfaces and External Systems

## What This Category of Data Includes
This category of data covers daily business documents from construction quality and safety supervision stations, construction units, supervision units, and construction units. These documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports.

Data mainly comes from engineering quality and safety supervision systems, construction site real-name platforms, supervision logs, and test reports. The update frequency is weekly.

Each individual document includes core fields such as business subject identification, timestamp, rectification status, and acceptance status. Data formats vary across different sources. Some unstructured documents collected on-site require format standardization before they can be connected to the system.

## Constraints on HTTP Interfaces and External Systems Posed by These Characteristics
Weekly updated business data does not require high-frequency interface calls. Set reasonable request interval durations.

Differences in data formats from multiple sources require interfaces to support dynamic parameters for different document structures.

Core business documents such as completion acceptance supervision reports involve verification of acceptance conditions. Interfaces must carry complete associated fields for validation.

Unstructured documents collected on-site must be uploaded and parsed via interfaces. Interfaces must support file transfer capabilities.

Errors in quality accident-related review links have serious consequences. Interfaces must include retry mechanisms and status code verification capabilities.

## How to Configure
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | `Bearer {Platform-assigned secret key}` | Complies with HTTP interface authentication standards to ensure secure transmission of business data |
| Single request file size limit | `1000 MB` | Meets upload requirements for large documents such as test reports and on-site images |
| Request timeout | `600 seconds` | Parsing and transferring large completion acceptance reports takes a long time; prevents mid-transfer interruptions |
| `variables` | Calibrated based on actual measurements | Business fields vary across different projects, so passed parameters need flexible adjustment |
| `responseData` | Filter returned fields by business document type | Only retain core data required for review to reduce transmission load |
| Concurrent request limit | `First 5 requests` | Weekly updated data volume is limited; excessive concurrency increases system load pressure |

## Three Common Misconfigurations
- Symptom: The interface returns a 503 status code, and batch requests have no response. Cause: No reasonable concurrent request limit is set, and simultaneous requests exceed the system's carrying capacity.
- Symptom: Uploaded files such as supervision logs and test reports cannot be parsed by the system. Cause: No upload interface permissions are configured for the corresponding file types, or the file size exceeds the preset limit.
- Symptom: The `responseData` field returned by the interface is empty, and the file archive information required for review cannot be obtained. Cause: The `variables` parameter is not correctly configured to pass the business subject identification, so the interface cannot match the relevant data for the corresponding project.

## How to Confirm the Configuration Is Correct
- Initiate an interface request for a single business document, and verify whether the returned `responseData` includes the expected core fields.
- Upload test files matching the business scenario, and confirm that the interface can normally receive the files and complete the parsing process.
- Simulate weekly batch requests, and observe the consistency between the interface's response status and returned results.
- Adjust the interface's authentication parameters, and confirm that a valid error prompt is returned when a valid `Authorization` is not included.
