# Declaration Materials and File Review for Construction Engineering Quality and Safety Supervision: Workflow Orchestration

## What this category of data looks like
Data for the construction engineering quality and safety supervision scenario comes from the engineering quality and safety supervision system, on-site construction real-name management platform, supervision logs, and test reports. Daily processed documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. The core identification fields are project number and rectification item ID. The update frequency is once per week. The content length and storage size of a single document conform to general specifications for engineering supervision documents.

## What constraints do these characteristics impose on workflow orchestration
The data sources for this scenario are scattered and the update cycle is fixed. The workflow must support connecting to multiple data source nodes such as the engineering quality and safety supervision system and on-site construction real-name management platform, and schedule automatic synchronous data updates on a weekly basis. There are various document types associated with specific projects and rectification items. The workflow must be configured with classification recognition rules to ensure that the processing logic for different documents matches business requirements. Core business links take a long time. The workflow must connect nodes such as document review, rectification tracking, and acceptance verification, and set verification links to ensure closed-loop processes. Errors may cause quality and safety risks. The workflow must be configured with failure retry and alert mechanisms to ensure process stability.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `variables` dynamic parameter configuration | Pass project number and hidden danger rectification number as dynamic variables | This category of data uses projects and rectification items as unique identifiers. Dynamic parameter passing can accurately associate corresponding files and avoid generalized searches |
| `nodeId` node identification configuration | Configure unique `nodeId` for document upload nodes and knowledge base search nodes respectively | Cross-node data transfer requires precise targeting of target nodes to ensure correct flow of variables and content |
| Document upload rules | Only allow uploading specified document types such as supervision plans and test reports, with a single file size not exceeding 100 MB (calibrated through actual testing) | The scope of daily processed documents is fixed. Limiting size can avoid node overload |
| Workflow trigger method | Parallel weekly scheduled trigger + manual trigger | Matches the weekly data update frequency, while supporting emergency needs for temporary review |
| Export function configuration | Generate Word download link at the bottom of the conversation | Businesses need to retain reviewed file documents, which complies with regulatory filing requirements |
| Failure handling strategy | Trigger in-site alert after 2 retries | Errors may cause quality and safety risks. Timely alerts allow for rapid intervention and handling |

## Three common mistakes
- Phenomenon: The knowledge base search does not return matching documents, and the interface displays "No relevant results". Cause: Business variables such as project number are not passed to the search node via `variables`, leading to a generalized search scope that cannot match corresponding files.
- Phenomenon: After deploying an older version workflow, an error occurs during operation, and the node status shows abnormal. Cause: The workflow orchestration configuration from version 4.8 was not migrated correctly, and the binding logic between `nodeId` and dynamic parameters was not updated.
- Phenomenon: The Word export function cannot generate a download link. Cause: No export node configuration was added at the end of the workflow, or the correct content generation output was not bound.

## How to confirm the configuration is complete
- Upload a supervision inspection record, trigger the workflow, and check whether the corresponding project's file data is automatically associated.
- Adjust the project number passed in `variables` to a non-existent ID, confirm that the search result is empty, and verify that the parameter passing takes effect.
- Trigger the scheduled task, check whether the workflow starts automatically on a weekly basis to process updated documents.
- After completing the review process, confirm that a downloadable Word file link is generated at the bottom of the conversation.
- Migrate the workflow from version 4.8 to FastGPT v4.17.0, and verify that the nodes run without errors.
