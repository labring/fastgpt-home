# Declaration Materials and File Review for Construction Engineering Quality and Safety Supervision: Source Citation and Traceability

## What This Category of Data Looks Like
This category of data primarily comes from engineering quality and safety supervision systems, construction site real-name platforms, supervision logs, and test reports. The update frequency is weekly.
Daily documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Every document has a unique ID, generation timestamp, and responsible entity field.
Some on-site documents include additional structured fields such as point coordinates and test values. File documents are archived by supervision node, and include associated IDs linking multiple related materials.

## Constraints for Source Citation and Traceability
Data sources for this category are scattered. Teams must associate heterogeneous documents across multiple systems. Citation traceability must match associated IDs across data sources.
The weekly update cycle requires the knowledge base sync schedule to align with supervision node timelines. This prevents expired data from being cited.
Each document’s unique ID and associated fields provide clear traceability markers. Direct access to the archived location of the corresponding material must be ensured during citation.
Point and value fields in on-site documents require precise matching of retrieval conditions. Compliance verification cannot be completed without this matching.
The multi-material association in file documents requires traceability to display the complete rectification or acceptance process.

## Configuration Settings
This configuration is based on FastGPT v4.17.0 functionality. The following configuration items and recommendations apply:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Aligns with the average length of file documents in this category, and avoids truncating key associated IDs and rectification processes |
| `responseData` | Enable | Ensures that document IDs and archive paths of citation sources are returned, to meet compliance traceability requirements |
| `detail` | Enable | Displays core business fields of cited documents, such as rectification requirements and acceptance opinions, to facilitate on-site verification |
| Similarity Threshold | `0.6–0.7` | Matches the structured field characteristics of documents in this category, and avoids recalling irrelevant non-supervision materials |
| Single Retrieval Limit | Top 6 results | Controls context length, while covering all main associated documents under a single supervision node |

## Three Common Misconfigurations
- Symptom: The target hidden danger rectification notice does not appear in search results. Returned documents are unrelated to the current supervision task. Cause: The similarity threshold is set too low, causing non-associated general documents to be prioritized in recall.
- Symptom: The AI response does not display document IDs or archive paths of citation sources. Cause: The `responseData` configuration item is not enabled, so the system does not return metadata required for traceability.
- Symptom: Cited content is truncated, and complete rectification process records cannot be displayed. Cause: The `quoteMaxToken` setting value is less than the total token count of the target document, and key associated information is truncated prematurely.

## How to Verify Successful Configuration
- Upload a single supervision inspection record and its associated hidden danger rectification notice, initiate a search, and confirm that the returned results include the target associated document.
- After enabling the `detail` configuration, check the citation block in the AI response, and confirm that core business fields of the document are displayed.
- Adjust the `quoteMaxToken` value, and verify that cited content of ultra-long file documents is not truncated.
- Check the knowledge base sync logs, confirm that weekly update tasks execute normally, and no expired data is included in the search scope.

The values provided are common starting points, and should be evaluated against the user’s own samples.
