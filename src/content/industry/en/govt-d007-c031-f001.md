# Environmental Impact Assessment (EIA) Approval for Construction Projects: Declaration Materials and File Review - HTTP Interfaces and External Systems

## What this category of data looks like
Data sources for this category include the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Commonly processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. The character count of individual documents varies widely. Fields include project code, EIA level, pollution prevention measures, and public participation feedback. There are no unified fixed limits on the size of individual documents.

## Constraints Imposed on HTTP Interfaces and External Systems
Scattered data sources and irregular update cycles require interfaces to support flexible configuration for multi-source data pulling, and avoid hardcoding fixed data source addresses.
Large variations in document structures require interfaces to support parsing and adaptation for different document formats, and cannot rely on a single parsing rule.
Lack of unified mandatory field formats requires interfaces to support custom field mapping when receiving declaration materials, to avoid data loss caused by mismatched field names.
Severe potential error consequences require interfaces to include complete failure retry and log retention mechanisms, to ensure traceability of the review process.

## How to Configure the Setup

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | `Bearer ${Pre-configured system authentication key}` | Required for identity verification when connecting to external EIA approval systems, in compliance with general interface authentication standards |
| Single request timeout | `600 seconds` | Parsing EIA declaration materials and verifying multi-source data takes a long time, so sufficient response time must be reserved |
| `variables` | `{"dataSource": "National Unified Construction Project EIA Declaration System", "updateRule": "Pull on demand"}` | Centralize fixed business parameters for configuration, making it easy to adjust data sources later without modifying core interface logic |
| `responseData` | Map fields returned by external systems to local review field structures | Ensure the format of received approval data matches the local file review workflow, and avoid field incompatibility issues |
| Interface failure retry count | `First 3 attempts` | Address temporary network fluctuations or system response delays, reducing the probability of review interruptions caused by a single failed request |
| Single pull data volume limit | `1000 MB` | The size of individual EIA declaration materials varies widely, so limiting the total data pulled per request avoids interface overload |

## Three Common Misconfigurations
- Symptom: Interface requests return a 401 Unauthorized error, and external system data cannot be pulled. Cause: The `Authorization` parameter is not configured correctly, an unauthorized or expired authentication key is used, which does not comply with the external system's authentication specifications.
- Symptom: Local review workflows receive external data with missing fields or abnormal formats. Cause: External system returned fields are not mapped according to the `responseData` requirements, raw response content is used directly, and no format adaptation is completed.
- Symptom: No response is received within the preset time after the request is sent, causing the review task to fail. Cause: An insufficient timeout time is set, or no failure retry mechanism is configured, so temporary network fluctuations or external system delays cannot be addressed.

## How to Verify the Configuration is Complete
- Call the configured interface, check if the `Authorization` parameter is correctly included in the request header, and confirm that the authentication logic is working.
- Pull test data from the external EIA declaration system, check if the fields mapped via `responseData` match the local review workflow's field requirements.
- Simulate network fluctuation scenarios to trigger interface request failures, confirm that the system automatically retries requests according to the configured retry count.
- View interface operation logs, confirm that the timeout time setting meets business requirements, and no request interruptions caused by insufficient duration occur.
