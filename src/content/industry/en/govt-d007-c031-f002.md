# Environmental Impact Assessment (EIA) Approval for Construction Projects: Declaration Materials and File Review - Vector Models and Indexing

## What Data Looks Like for This Category
This category of data primarily comes from the national unified construction project environmental impact assessment declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Commonly processed documents include environmental impact assessment reports, statement forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents. Documents include both structured forms and semi-structured text formats, with core fields such as project category, EIA level, pollution prevention measures, and public participation status. Update frequency is irregular, and single document volume varies significantly.

## Constraints on Vector Models and Indexing From These Characteristics
Dispersed data sources lead to inconsistent document formats across different systems. Custom chunking rules must be developed for content from different sources, such as government systems and monitoring data. Irregular updates require indexes to support incremental synchronization, avoiding resource consumption caused by full reconstruction. Large single document volumes require controlling chunk length to avoid exceeding model context limits, while retaining sufficient semantic relevance. Core retrieval fields vary significantly across different document types. Targeted retrieval weight configuration is needed to match the professional logic of EIA review. Many professional terms exist in the EIA field. A vector model adapted to the ecological environment field must be selected to ensure accurate semantic matching.

## Three Common Misconfigurations
-  An error `503 No available channel for model text-embedding-v3 under current group default` is thrown when calling the embedding model. The cause is that an embedding model adapted for EIA review is not configured separately, and the default general model channel is still used, resulting in failure to call the domain model normally.
-  The interface displays an empty API key after starting the container. The cause is that the CHAT_API_KEY environment variable is not correctly mounted in docker-compose.yml, and the container is not rebuilt to apply the configuration.
-  The number of knowledge base retrieval results does not match expectations, showing empty retrieval results or exceeding the set limit. The cause is that the chunking rules are not adjusted based on the large volume of EIA documents, resulting in some document chunks not being correctly indexed.

## How to Verify Successful Configuration
-  Access the FastGPT knowledge base management page, check the embedding model configuration item, confirm that a dedicated model adapted to the ecological environment field has been selected, and the general model channel is not used.
-  Upload a standard environmental impact assessment report, perform a retrieval test, and verify whether the similarity score of the returned results falls within the set threshold range.
-  Review the docker-compose running logs, confirm that the CHAT_API_KEY environment variable has been correctly loaded, and there are no key missing errors.
-  Access the index management page, check the configuration parameters for chunk length and overlap length, confirm that they match the paragraph characteristics of EIA documents.
