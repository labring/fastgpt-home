# Declaration Materials and File Review for Construction Project Environmental Impact Assessment Approval: Tool Calling and Plugins

## What this category of data consists of
Data for this category comes from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Commonly processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. Document structure follows the EIA approval process, with fixed sections including project overview, pollution prevention measures, public participation, and more. Fields include project category, EIA level, details of pollution prevention plans, and so on. There are no unified fixed units; values adjust based on specific document content.

## What constraints these characteristics impose on the tool calling and plugins workflow
Because data sources involve multiple independent systems, tool calling must support parallel pulling and integration of multi-source data to avoid data inconsistency. EIA documents have complex structures with fixed sections. Tools must be able to recognize section divisions across different documents and accurately extract content for the corresponding review link. Irregular update frequencies mean tools must support real-time or on-demand pulling of the latest data, and cannot rely on fixed-cycle caching. Core review links include project category verification, pollution prevention measure review, and other tasks. Tool calling must accurately match dedicated fields, otherwise review errors may occur. Additionally, the consequences of errors are severe, so the parameter verification link for tool calling must be strictly configured to prevent incorrect data from entering the review process.

## Three common configuration errors
- Phenomenon: Tool calls return empty results, and valid content from declaration materials cannot be extracted. Cause: Interface permissions for multi-source data docking were not configured correctly, resulting in failure to pull data from the national unified construction project EIA declaration and approval system.
- Phenomenon: Generated review matching rules cannot correspond to EIA-specific fields, resulting in parameter mismatch errors. Cause: Dedicated fields such as project category and EIA level from declaration materials were not accurately mapped to tool calling parameters, causing the tool to fail to recognize corresponding review content.
- Phenomenon: Plugin configurations cannot be re-exported as schema format files, making subsequent modifications difficult. Cause: Plugin settings were not saved in the standard tool configuration format, resulting in exported schema files that do not meet requirements.

## How to confirm correct configuration
- Submit a standard EIA approval application material to trigger tool calling, and check whether corresponding data source content can be correctly pulled and preliminary review completed.
- Manually input a known project category and EIA level to verify whether the tool can accurately call the corresponding review rules for verification.
- View tool call logs to confirm that parameters are passed correctly, with no null values or incorrect fields.
- Simulate a complete file review process to check whether tool return results cover core links that need verification, such as pollution prevention measures and public participation explanations.
