# Application Materials and File Review for Construction Project Environmental Impact Assessment Approval: Document Parsing and Chunking

## What this category’s data looks like
This category’s data comes from the national unified construction project environmental impact assessment declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Commonly processed documents include environmental impact assessment reports/report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. Individual documents have clear structures but large chapter spans, containing fixed business fields such as basic project information, EIA level determination, pollution prevention measures, public participation survey results, with no unified single-page character count standard.

## What constraints do these characteristics impose on document parsing and chunking
Dispersed data sources result in diverse document formats, including standardized system-exported files and custom docx templates submitted by EIA institutions. Multi-format parsing capabilities are required. Irregular business update cycles require parsing nodes to support mixed processing of batch historical documents and real-time uploaded documents. Documents have large chapter spans, and core business fields are bound to chapter contexts. Fixed chunk lengths can easily split associated content such as EIA levels and pollution prevention measures, so semantic integrity must be prioritized. The clarity of fixed fields requires that the binding relationship between fields and their corresponding descriptions be retained during chunking, to prevent failure to match corresponding review logic after splitting. Additionally, the accountability risk in the review process requires that parsed and chunked results can be traced back to their original document positions.

## How to set configurations
The following configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Core chapters of EIA documents have large spans; this range can retain core semantics of single chapters and avoid excessive splitting |
| `chunkSplitter` | Split by chapter titles | EIA documents have clear chapter title specifications; splitting by titles can retain business logic integrity |
| `customPdfParse` | Enabled | Adapts to multi-source PDF formats, including system-exported files and custom template files |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | EIA reports are usually lengthy, requiring support for large file upload parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large EIA documents takes a long time; this duration covers most scenarios |
| `chunkSettingMode` | Manual configuration | Chunking rules must be adjusted based on the chapter characteristics of EIA documents to adapt to business needs |

## Three common mistakes
- Symptom: After server deployment, upload an EIA document, and the document parsing node returns a 404 error, unable to read file content. Cause: The correct static file storage path is not configured, and front-end uploaded files are not synchronized to the directory accessible by the server parsing node.
- Symptom: When using a specific large model, core fields such as EIA level and project number cannot be extracted from the parsed EIA document. Cause: The model version has insufficient matching degree with the semantic context after chunking, or the binding relationship between fields and their corresponding descriptions is split during chunking.
- Symptom: When batch uploading historical EIA documents, some large-volume documents fail parsing due to timeout. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the parsing time of large-volume documents exceeds the default threshold.

## How to confirm configurations are properly set
- Upload a single standard EIA PDF document, check if the chunks of the parsing result retain complete chapter content without core semantic splitting.
- Upload a large-volume EIA report under 1000 MB, confirm that the parsing node has no timeout errors and can normally return parsing results.
- Switch between different models, verify that the extraction function for core fields such as EIA level and project number works normally.
- Check the server storage path configuration, confirm that front-end uploaded files can be accessed by the parsing node with no access errors.

The values given are common starting points and should be measured against the reader's own samples.
