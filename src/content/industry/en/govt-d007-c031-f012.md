# Declaration Materials and File Review for Construction Project EIA Approval: Deployment and Upgrade

## What the Data for This Category Looks Like
This category involves four types of entities: ecological environment department EIA offices, administrative approval bureaus, project construction units, and EIA institutions. Daily work involves processing documents such as environmental impact assessment reports, environmental impact assessment report forms, approval applications, public participation statements, technical assessment opinions, and EIA approval documents. Covered fields include basic project information, pollution prevention measures, public participation content, and approval process nodes. Data sources include the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular, with no fixed synchronization cycle.

## Constraints on Deployment and Upgrade
Data sources for this category are scattered, and updates have no fixed cycle. During deployment, configure data integration logic across multiple systems to ensure synchronized access to the latest EIA project information and documents. Daily document formats and fields vary widely. Adapt parsing rules for different types of EIA documents to avoid parsing failures or incomplete field extraction. Approval errors directly lead to project suspension, revocation of approvals, or subsequent law enforcement accountability. Strengthen data verification and permission control during deployment to ensure the accuracy and security of the review process. Multiple concurrent operations across entities are common. Configure reasonable database connection limits and caching strategies to avoid service freezes or data inconsistency.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `PG_URL` | `jdbc:postgresql://[EIA approval system database address]:5432/epia_db` | Connect to structured data from the national unified construction project EIA declaration and approval system to obtain basic project information and approval node data |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com` (can be replaced with government cloud object storage address) | Store EIA declaration documents and approval materials, adapt to the upload and reading requirements of multi-source files |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Verify the upload legitimacy of EIA files, prevent unauthorized files from accessing the review system |
| `REDIS_URL` | `redis://:[custom password]@[redis service address]:6379/0` | Cache classification tags and approval node status of EIA projects, reduce the pressure of repeated database queries |
| `DB_MAX_LINK` | `20–30` | Adapt to the connection number requirements for parallel retrieval of EIA data across multiple departments, avoid service interruptions caused by exhausted database connections |
| `FE_DOMAIN` | `https://epia-review.your-gov-domain.cn` | Configure the access domain name of the front-end service, adapt to deployment scenarios on government intranets or extranets |

## Three Common Misconfigurations
- Phenomenon: A non-clickable overlay appears on the login page, and the front-end console reports a cross-origin error. Cause: The `FE_DOMAIN` parameter is not configured correctly, resulting in a mismatch between the front-end domain name and the back-end service domain name, and static resource loading is blocked.
- Phenomenon: Calls to the EIA data interface return a 405 status code, and logs show that the remote WWW service supports TRACE requests. Cause: TRACE request support on the remote WWW service is not disabled, which does not meet the security compliance requirements of government systems and may be exploited by attackers.
- Phenomenon: File parsing fails during batch import of EIA report forms. Cause: Parsing rules are only configured for environmental impact assessment reports, and no adaptation is made for the structured fields of report forms, resulting in failure to normally extract content from documents in unexpected formats.

## How to Verify Successful Configuration
- Call the database connection test interface to verify that the database connections configured via `PG_URL` and `DB_MAX_LINK` function normally, and can return basic field data of EIA projects.
- Upload a standard EIA public participation statement document to verify that the `FILE_TOKEN_KEY` configuration takes effect, and the file can be stored normally in the configured object storage service.
- Access the front-end domain name to verify that the `FE_DOMAIN` configuration is correct, and there are no abnormal overlays or cross-origin errors on the page.
- Initiate a batch file parsing task to verify that the `REDIS_URL` configuration takes effect, and the parsing progress can be cached normally and displayed on the front-end page.
