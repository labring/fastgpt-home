# Investment Project Approval and Post-Evaluation: Declaration Materials and File Audit - HTTP APIs and External Systems

## What this category of data looks like
Core data for this category comes from investment supervision systems of the state-owned asset regulatory authority, enterprise ERP and project management systems, industry market data, and audit and financial statements.
Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, post-investment evaluation reports, and other relevant materials.
Data updates occur quarterly.
Fields cover project identifiers, investment scale, project initiation approval nodes, post-evaluation indicators, and other business-related content.
Compliance with state-owned asset supervision requirements must be strictly followed.

## What constraints do these characteristics impose on HTTP APIs and external systems?
Data sources include multiple internal enterprise and external regulatory systems. APIs must support unified identity authentication to protect data security.
Daily documents have diverse formats. APIs must adapt to upload and parsing logic for different file types.
Data updates follow a quarterly rhythm. API synchronization tasks must plan call frequencies appropriately to avoid overusing system resources.
Data related to state-owned assets requires API return fields to strictly match business compliance rules. Core compliance information must not be omitted.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {access token issued by internal enterprise systems} | Unified identity authentication is required when connecting to external systems such as state-owned asset regulatory investment supervision systems, to comply with internal enterprise security specifications |
| Request timeout | 600–1200 seconds | Uploading and parsing investment project-related documents takes a long time. This range accommodates time requirements for large file processing |
| `variables` | Pass business identification parameters such as project ID, report type | Accurately match knowledge bases and workflows for target business scenarios, and avoid cross-project data confusion |
| File upload size limit | 1000 MB | Documents such as feasibility study reports and due diligence reports have large file sizes. This limit accommodates maximum required file dimensions |
| `responseData` | Specify a field set containing audit status and file parsing results | Only retrieve content necessary for business operations, reduce data transmission overhead, and simplify subsequent processing |
| Maximum batch request count | First 5 entries | Processing too many project data entries in a single batch will exceed rate limit thresholds of external system APIs. Adjust this value based on actual measurements |

## Three Common Configuration Mistakes
- Phenomenon: CSV files uploaded via the API do not recognize the first column as the question field and the second column as the answer field as expected. Cause: No field mapping rules for file parsing were configured in the API request. The default parsing logic does not match the column order required by the business.
- Phenomenon: A null value is returned after calling the API to trigger a workflow. Cause: No correct business scenario identifier was passed via the `variables` parameter. The workflow cannot match the preset knowledge base assistant process.
- Phenomenon: Attachment links returned by the API cannot be extracted after upgrading to FastGPT v4.17.0 or later. Cause: Configuration rules for the `responseData` parameter were not adjusted. The old version return value extraction logic was retained, which does not adapt to the new version's field parsing method.

## How to confirm the configuration is complete
- A test request with the correct `Authorization` parameter is sent. The API returns a status code of 200 and includes expected business fields.
- A test CSV file in the required format is uploaded. The first and second columns are correctly recognized as question and answer fields, and the parsing result meets business expectations.
- A workflow is triggered and the return result is reviewed. The fields specified by the `responseData` parameter are correctly returned, with no null values or missing content.
- A test file of maximum allowed size is uploaded. The API does not trigger a timeout error, and the request timeout configuration is confirmed to be effective.

The values provided are common starting points and should be measured against the reader's own samples.
