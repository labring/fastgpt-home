# Declaration Materials and File Review for Investment Project Approval and Post-Evaluation: Multi-turn Dialogue and Prompt Engineering

## What this category of data includes
Data for this category comes from state-owned assets investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements, with updates on a quarterly basis.
Commonly processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports.
These cover fields related to project initiation approval, investment decision materials, and post-investment evaluation across the full project lifecycle.
Data is maintained by central enterprise strategic investment teams, project companies, state-owned assets supervision departments, and external consulting and evaluation institutions.

## Constraints for multi-turn dialogue and prompt engineering workflows
This category of data is updated quarterly. Multi-turn dialogue must limit context to valid data from the most recent quarter, to avoid using outdated information beyond the update cycle.
Document types vary widely with significant structural differences. Prompts must include preset dedicated field mapping rules for different documents, to adapt to information extraction logic for documents like project proposals and post-investment evaluation reports.
Data comes from multiple systems. Multi-turn dialogue must support cross-system parameter passing, to ensure `variables` can synchronously retrieve project progress from ERP and approval status from supervision systems.
File review must strictly comply with compliance requirements. Prompts must use fixed validation logic, to avoid review deviations caused by changes to document formats.

## Configuration recommendations
These configuration recommendations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Matches total character volume of multiple quarterly project documents, prevents context overflow |
| `variables` binding rules | Bind specified fields from ERP and supervision systems by system category | Meets cross-system data transfer requirements for this category of multi-source data |
| Prompt template grouping | Group by document type (initiation declaration / post-evaluation) | Adapts to structural differences in fields across different documents |
| Dialogue timeout threshold | 600 seconds | Covers multi-turn review interaction duration for complex feasibility study reports |
| Historical dialogue recall count | Top 3–5 entries | Prevents redundant information from interfering with current review logic |

## Three common configuration errors
- Symptom: `variables` fields are empty during dialogue interactions, and project data from ERP or supervision systems cannot be retrieved. Cause: Variable parameters are not bound by system category, and cross-system information such as project progress and approval status is not correctly injected into the dialogue context.
- Symptom: The dialogue API call returns the unAuthChat status code. Cause: The binding rule between `chatId` and sessions is not correctly configured, or API key permissions do not cover the multi-document review scenario for this category.
- Symptom: Fields extracted by prompts during multi-turn review do not match document formats. Cause: Prompt template grouping by document type is not enabled, and a generic template is reused without adapting to structural differences between project proposals and post-investment evaluation reports.

## How to verify correct configuration
- Launch a multi-turn review dialogue for a single project proposal, and check if the `variables` field synchronously displays project data from the corresponding systems.
- Call the dialogue API, verify that the returned status code is not unAuthChat, to confirm that session binding and key permission configurations are correct.
- Switch between initiation declaration and post-evaluation review scenarios, and check if prompts automatically match the corresponding templates.
- Test response status during consecutive multi-turn interactions, confirm that the preset timeout threshold is not triggered.

The values provided here are common starting points, and should be evaluated against the user's own samples.
