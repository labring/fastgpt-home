# Declaration Materials and File Review for Investment Project Initiation and Post-Evaluation: Workflow Orchestration

## What this category of data looks like
Data sources for this category include the State-owned Assets Supervision and Administration Commission (SASAC) investment supervision system, enterprise ERP and project management systems, industry market data, audit and financial statements, with a quarterly update frequency. Commonly processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Structured fields such as project number, investment amount, and project initiation approval nodes are included, alongside unstructured text such as technical demonstrations, financial calculations, and investment decision meeting minutes. Fields and units align with general specifications for the corresponding business scenarios.

## What constraints do these characteristics impose on the workflow orchestration stage
Quarterly data updates require workflows to support periodic batch data synchronization and verification, to avoid using expired industry market data or financial statements. Mixed processing of multiple document types requires workflow nodes to support automatic recognition and chunking of different document formats, while addressing differentiated needs for structured field extraction and unstructured text parsing. Cross-system data sources require configuration of cross-system pull rules to ensure data consistency across project initiation and post-evaluation links. Full-cycle document chains require workflows to connect links such as project initiation declaration, material review, investment decision meetings, and post-evaluation data collection. Each link retains traceable review nodes to meet state-owned asset supervision compliance requirements.

## Three Common Mistakes
- Phenomenon: Workflow runs show failures, but response logs exist in the model backend. Cause: Port configuration restrictions in the deployment environment block data transfer between workflow nodes.
- Phenomenon: The prompt for the agent node does not process declaration materials as expected. Cause: The prompt configuration is not associated with the business fields bound to `variables`, leading to missing key business information in the context.
- Phenomenon: Configuring the question optimization component does not change the relevance ranking of review results. Cause: The question optimization component is not placed before the agent node, so no preprocessing is done on original declaration materials, and keyword precision for subsequent retrieval cannot be optimized.

## How to Confirm Proper Configuration
- Run a single workflow test, check if node logs include the business fields bound to `variables`, to confirm normal data transfer.
- Review the workflow node order, confirm that the question optimization component is placed before the agent node and covers the current document type being processed.
- Check the `nodeId` configuration, confirm that each link's node ID is unique and arranged in execution order, verify jump logic via node status tracking.
- Trigger a quarterly data synchronization test, check if pulled documents match updated content from business systems.
