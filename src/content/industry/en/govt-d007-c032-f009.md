# Declaration Material and File Review for Investment Project Approval and Post-Evaluation: Model Access and Configuration

## What data for this category looks like
This category of data primarily comes from state-owned asset investment supervision systems, enterprise ERP and project management systems, industry market data, and audit financial statements, with a quarterly update frequency. Commonly processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Each document contains fields such as basic project information, financial calculations, and risk assessment, involving units like investment amount and project cycle. The core content focuses on capital investment direction and state-owned asset value preservation.

## What constraints these characteristics impose on the model access and configuration link
Quarterly updated data requires regular synchronization with the vector database to avoid using expired project data. Individual documents are lengthy, so the context and generated token length must be reasonably controlled to prevent core business information from being truncated. Documents involve professional content across finance, law, engineering and other fields, so vector models and generation parameters adapted to professional text must be matched. Content related to state-owned assets requires strict restrictions on generation randomness to ensure the rigor of review conclusions, while also ensuring identity verification security for interface calls.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total text length of a single feasibility study report, avoiding truncation of core business data |
| `maxTokens` | 4000 token | Controls the length of single-round generated content, adapting to the standardized review output format of investment decision-making meeting materials |
| `quoteMaxToken` | 1500 token | Limits the length of quoted original text, ensuring that only key compliance clauses and financial data are extracted during file review |
| `temperature` | 0.1–0.3 | Reduces generation randomness, ensuring the rigor and consistency of review conclusions for state-owned asset projects |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed large model service address | Adapts to the call link for docking locally deployed large models |
| `AIPROXY_API_TOKEN` | Fill in according to the generated deployment key | Ensures identity verification security for model calls |

## Three common mistakes
- Symptom: When deploying a large model service, GPU power consumption and utilization rate are low, while single-core CPU utilization reaches 100%. Cause: The large model inference task is not scheduled to the GPU resource pool, and only the CPU is used to execute the inference process.
- Symptom: When calling the vector model, the number of matching files returned does not match expectations. Cause: The `quoteMaxToken` parameter is not configured correctly, causing the system to filter out some eligible text fragments.
- Symptom: FastGPT v4.17.0 returns a 401 status code when configuring an online model. Cause: The `AIPROXY_API_TOKEN` is not filled in correctly, or the key permission does not cover the current call scenario.

## How to confirm the configuration is complete
- Upload a single feasibility study report, check whether the review summary generated by the model extracts the core compliance clauses of the project.
- Initiate a batch file review task, check whether the GPU resource utilization rate is within a reasonable range.
- Test the vector model call, confirm that the returned matching results are consistent with the key content in the files.
- Verify the `maxContext` parameter setting, ensure that no text truncation prompt appears for the imported maximum document.
