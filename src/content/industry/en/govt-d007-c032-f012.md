# Declaration Materials and File Review for Investment Project Approval and Post-Evaluation: Deployment and Upgrade

## What Data for This Category Looks Like
This category of data primarily comes from state-owned assets supervision and administration investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. Commonly processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data is updated on a quarterly cycle. Core fields cover project investment-related indicators, implementation progress, revenue status, risk control ratings, and more. Different documents correspond to different structured and unstructured content, and some data requires synchronization and integration across multiple systems.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The need to synchronize data across multiple systems requires that deployments support multiple database and storage service types. The quarterly update cycle means data synchronization scripts must support scheduled triggering. The variety of document types, from structured reports to unstructured feasibility study reports, requires deployed document parsing modules to support multi-format adaptation. Core fields involve content related to state-owned assets supervision, so compliant storage and access permissions must be configured during deployment. During upgrades, the context of existing file review workflows must be preserved, while compatibility with new post-investment evaluation data structures must be maintained to avoid disrupting current business processes.

## Configuration Guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://user:pass@host:5432/fastgpt?sslmode=disable` | Adapts to the PostgreSQL databases commonly used in state-owned assets systems for storing structured case data |
| `REDIS_URL` | `redis://:password@host:6379/0` | Used to cache frequently accessed project document metadata, reducing pressure from cross-system synchronization |
| `STORAGE_S3_ENDPOINT` | `http://s3-cn-beijing.example.com:9000` | Stores large unstructured documents such as feasibility study reports and post-evaluation reports |
| `DB_MAX_LINK` | `20–30` | Matches the concurrent volume of bulk data synchronization during quarterly updates, preventing database connection exhaustion |
| Single search limit | `Top 10 results` | Adapts to multi-source information retrieval needs during project review, balancing retrieval efficiency and result comprehensiveness |
| File chunk length | `800–1200 characters` | Adapts to semantic chunking requirements for long documents such as feasibility study reports, ensuring context integrity |

## Three Common Misconfiguration Issues
- Symptom: Initialization script returns a connection timeout error after container startup. Cause: Access permissions for `PG_URL` or `REDIS_URL` are not configured correctly, resulting in failure to connect to database components.
- Symptom: Empty results are returned when retrieving external industry data. Cause: The access address of the external retrieval service is not configured correctly, or firewall ports are not opened to allow outbound retrieval requests.
- Symptom: Out-of-memory errors occur when bulk importing quarterly updated case data. Cause: The value of `DB_MAX_LINK` is not adjusted, leading to excessive concurrent connections that exhaust system resources.

## How to Verify Successful Configuration
- Run a database connection test script to verify connectivity for the `PG_URL` and `REDIS_URL` configurations, confirming there are no authentication or address errors.
- Upload a typical project proposal document to trigger the parsing workflow, checking whether chunking and storage results meet expectations.
- Configure a scheduled synchronization task to trigger a quarterly data sync, verifying that cross-system data can be properly pulled and written to storage.
- Access the frontend page, confirming that the domain configured for `FE_DOMAIN` is accessible normally and that file upload functions operate without issues.
