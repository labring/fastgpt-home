# Enrollment and Student Status Management: Application Materials and File Review - Vector Models and Indexing

## What the data for this category looks like
Documents involved in this category include enrollment application forms, student status information sheets, transfer applications, enrollment plans, admission rosters, student status change approval forms, and more. Data sources include the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. Data is updated daily. Core fields focus on student identity, admission eligibility, and student status transfer status. Data formats vary across sources, some fields are duplicated across systems, and cross-source consistency verification is required.

## What constraints these characteristics impose on the vector model and indexing stage
Multiple data sources and varying formats require vector indexes to support unified embedding and matching of multi-source data. Daily high-frequency updates require indexes to support incremental updates, avoiding resource consumption from full reprocessing. High precision requirements for core fields prevent mismatches that lead to duplicate or missing student status records. Duplicate cross-system fields require setting a reasonable similarity matching threshold to balance recall and precision. Differences in length across document types require chunking strategies adapted to texts with different structures such as forms and rosters.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the field length of form documents such as enrollment application forms and student status information sheets, avoid including too much irrelevant information in a single chunk |
| Overlap Length | 100–150 characters | Retain key identity information across chunks, such as student ID numbers and student status numbers, prevent key content from being truncated during chunking |
| Similarity Threshold | 0.85–0.92 | Precisely match core fields such as student status and household registration, avoid misjudgments from low similarity, reduce the risk of duplicate or missing student status records |
| Single Search Limit | Top 10 results | Control the number of returned results, adapt to the scale of enrollment data, avoid excessive redundant results affecting review efficiency |
| `maxToken` | 8000 | Adapt to the embedding requirements of longer documents such as enrollment policy texts and admission rosters, align with the general configuration standards of FastGPT v4.17.0 |
| `defaultToken` | Calibrated via actual testing | Adapt to token limits of different embedding models, such as the exclusive token rules of bce-embedding-v1 |

## Three Common Misconfigurations
- Index task status remains "Indexing" with no progress displayed in the interface. Causes include unreasonable chunk parameters not configured when uploading in chunk mode, oversized single chunk data causing index node processing timeouts, or incremental indexing not enabled for daily updated student status data, triggering full reindexing.
- Embedding model calls return the "This token does not have permission to use the model" error. Causes include incorrect access key configuration for the target model, or use of an unauthorized commercial model such as text-embedding-3-large.
- Direct embedding model calls fail and return empty fields. Causes include not skipping the one API proxy, directly configuring the official embedding interface address and key, or interface parameter format not meeting the requirements of the target model.

## How to Verify Proper Configuration
- Review index task logs to confirm that the number of chunked documents matches the number of original uploaded student status and enrollment data entries.
- Test matching core fields such as student ID numbers and student status numbers, confirm that the similarity values of returned results fall within the preset threshold range.
- Upload daily newly added student status change data, confirm that the index task completes within a reasonable time frame, with no long-term queuing status.
- Verify that the vector data returned by the embedding model call is non-empty and the format meets the requirements of FastGPT v4.17.0.
