# Enrollment and Student Status Management: Application Materials and File Review - Tool Calling and Plugins

## What this category of data looks like
Data sources for this category include the National Primary and Secondary School Student Status Information Management System, local enrollment platforms, household registration and property data, and school educational administration systems. Daily processed documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data updates occur daily. Document fields cover student identity identifiers, household registration and residential addresses, student status numbers, change application types, admission batches, and more. All core fields are standardized government service fields, with no custom special units.

## Constraints for Tool Calling and Plugin Workflows
Dispersed data sources and daily updates require tool calling to integrate with multi-source heterogeneous APIs. A stable incremental synchronization mechanism must be configured. Daily processed documents have highly standardized fields but cover fixed use cases. The `functionCall` parameter must bind preset review functions to ensure calling logic aligns with business processes. Core links include household registration and property verification, and student status change processing. Tool calling must limit call scope to prevent unauthorized access to non-authorized data. The daily update requirement means plugin execution rhythm must match the response pace of government data APIs, avoiding review interruptions caused by timeouts.

## Configuration Settings
This configuration is defined for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `"auto"` | Meets tool calling requirements for multiple review scenarios |
| `functionCall` | Preset function names and parameter templates based on review scenarios | Matches the field structure of standardized documents in this category |
| MCP service timeout | `600 seconds` | Adapts to the typical response duration of government data APIs |
| Input parameter validation rules | Only allow preset fields to be passed | Prevents review exceptions caused by unexpected fields |
| Call trigger condition | Within 10 seconds after detecting that application materials have finished uploading | Aligns with the submit-for-review workflow |
| Maximum number of returned results | `Top 5 entries` | Focuses on key data required for core review |

## Three Common Configuration Mistakes
- Symptom: The large language model fails to call the MCP service as expected, or receives no response after calling. Cause: No timeout configuration adapted to government data APIs is set, leading to forced request interruption.
- Symptom: Images returned by MCP calls are not fully displayed. Cause: No limit is set on the size of image resources returned by the tool, exceeding the default `200 MB` content capacity threshold of FastGPT.
- Symptom: Input parameters cannot be added to HTTP responses. Cause: Input parameters are not bound to the standardized fields of documents in this category, resulting in variable parsing failure.

## How to Verify a Successful Configuration
- Submit a standardized enrollment application form document, and check whether the preset review function is triggered in the tool calling log.
- Simulate a response from a government data API to verify that input parameter fields are correctly validated and received.
- Adjust the timeout parameter for tool calling, and observe whether the interface response meets the preset duration requirements.
- Check the number of returned results to confirm that it matches the preset upper limit configuration.

The values provided here are common starting points and should be measured against the reader's own samples.
