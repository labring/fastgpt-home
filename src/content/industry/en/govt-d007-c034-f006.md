# Enrollment and Student Status Management: Application Materials and File Review — Citation Source and Traceability

## What the data for this category looks like
Stakeholders in this category include the basic education department of the education bureau, school academic affairs offices, enrollment examination institutions, and street community collaborative windows.
Daily processed documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms.
Data sources cover the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems.
The update frequency is daily.
Core data fields center on student identity identifiers, household registration and property information, and student status transfer records.
Core fields for a single document include student name, student status number, residential address, and related dimensions.

## What constraints these characteristics impose on the citation source and traceability process
The scattered nature of multi-source data requires the traceability process to connect data sources from multiple different platforms, to avoid information bias from a single source.
The daily update feature requires cited data sources to use the latest synchronized content. Failure to do so may lead to errors in student status or enrollment qualification verification.
The uniqueness of core fields requires precise matching of student IDs during traceability, to prevent duplicate student status records or association errors.
The diversity of document types requires traceability displays to be categorized by enrollment, student status, household registration and other types, to help reviewers quickly locate valid information.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `quoteMaxToken` | `800–1200 token` | The core content length of a single enrollment or student status document falls within this token range, ensuring complete display of traceability snippets |
| `responseData` | Extract fields including student ID, student status number, and residential address | Matches the core data fields of this category, ensuring extracted traceability content is directly relevant to review requirements |
| `detail` | Enabled | Displays specific document snippets and source platforms for traceability, meeting the verification needs of reviewers |
| Number of single recall sources | Top 3 | The number of associated data sources involved in daily review usually does not exceed 3, avoiding redundant information display |
| Traceability display sorting | Arranged by document type group | Distinguishes document types such as enrollment plans, student status records, and household registration certificates, enabling quick identification |

## Three Common Configuration Errors
- Phenomenon: The generated review result does not display any citation source snippets. Cause: The `detail` configuration item is not enabled, or `quoteMaxToken` is set too small, causing traceability content to be completely truncated.
- Phenomenon: The cited data source fields are empty, and the student's student status or household registration information cannot be matched. Cause: The extraction rules for `responseData` are not configured correctly, and the core student ID or student status number fields of this category are not bound, resulting in failure to associate corresponding data.
- Phenomenon: The cited content includes redundant document snippets that are not required for the review. Cause: `quoteMaxToken` is set too large, recalling data source content beyond the current review requirements, or the number of single recall sources is set too high.

## How to Verify the Configuration is Correct
- Upload a standard enrollment application form as test data, trigger the review process, and check whether the corresponding source platform and document snippets are displayed in the results.
- Adjust the value of `quoteMaxToken`, observe the length change of the cited content, and confirm that the configuration parameters take effect.
- Enter the test student ID, check whether `responseData` correctly extracts the corresponding student status or household registration information.
- Disable the `detail` configuration, confirm that traceability details are no longer displayed in the results, and verify that the switch function operates correctly.
