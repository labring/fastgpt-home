# Enrollment and Student Status Management: Application Materials and File Review - Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
This category of data covers documents including enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources include the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic administration systems.
Data is updated daily. Structured fields include student name, ID number, student status number, household registration address, property certificate number, enrollment batch, and other similar content. It also includes semi-structured text such as enrollment policy explanations and student status change rules.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Data for this category comes from multiple government and academic administration systems. Retrieval must support matching both structured fields and semi-structured policy text, which requires mixed recall capabilities.
Daily updated student status and enrollment data require the knowledge base to support incremental synchronization. This prevents the use of expired historical batch data.
Document fields involve sensitive and critical review basis such as student identity, household registration, and property. The accuracy of recall results directly affects review conclusions. Redundant data from non-target regions or non-current batches must be filtered.
A single review material needs to associate multiple document types. The context length of retrieved recall results must adapt to model input limits.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Enrollment and student status data fields are precise. Low-match irrelevant documents must be filtered to ensure recall accuracy for critical information such as student status number and household registration address |
| `limit` | `Top 6–8 entries` | Single review needs to cover multiple document types including registration information, student status records, property certificates, and enrollment policies. Too many entries will exceed model context length |
| `searchMode` | `keyword + semantic` | Balances precise keyword matching for structured fields such as student status number and semantic recall for enrollment policy text |
| `usingReRank` | Enabled | Re-ranks results retrieved from multiple sources by relevance, to ensure core documents from the current enrollment batch appear first |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements synonymous expressions related to enrollment policies, such as "enrollment eligibility" corresponding to "application requirements", to improve recall coverage |
| `collectionIds` | Bind exclusive dataset IDs for corresponding school districts and schools | Isolates student status and enrollment data from different regions, avoids cross-region data confusion, and ensures review only uses documents within the target scope |

## Three Common Misconfigurations
- Phenomenon: Attempting to import content from WeChat Official Accounts into the knowledge base results in no matching results during retrieval. Cause: External data source synchronization plugin is not configured, and the structured conversion and dataset import process for Official Account content is not completed.
- Phenomenon: After adjusting the `limit` parameter to 2000, the model output does not include any citation markers, but retrieval details show all recalled entries are complete. Cause: The total context length of recalled content exceeds the model input limit, and key citation content is truncated, so the model cannot identify citations.
- Phenomenon: After local deployment, a knowledge base built using enrollment policy documents generates review conclusions that do not match the policies. Cause: Field-level filtering rules are not configured, and historical student status data from non-current enrollment batches and outdated policy text are recalled.

## How to Confirm Proper Configuration
- Upload a single enrollment application form to the corresponding dataset, retrieve "student ID number", confirm that the recall results include matching content for this field, and that similarity scores fall within the preset range.
- Adjust the `limit` parameter to `Top 5 entries`, retrieve "2024 Enrollment Plan", confirm that the number of returned document entries matches the set requirement.
- After enabling the `usingReRank` function, retrieve "transfer application", confirm that student status change approval form results appear before non-policy documents.
- View synchronization logs in the dataset management interface of FastGPT v4.17.0, confirm that daily incrementally updated student status data has been automatically synchronized to the knowledge base.
