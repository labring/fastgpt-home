# Emission Permit Management: Declaration Materials and Case Review - Tool Calling and Plugins

## What the data for this category looks like
Core data for this category comes from four sources: the National Emission Permit Management Information Platform, corporate environmental protection ledgers, online monitoring systems, and environmental statistics systems. Data updates occur quarterly.
Commonly processed documents include emission permit application forms, annual implementation reports, self-monitoring plans, production ledger records, change applications, and permit copies. Document structures differ based on business process:
- Application forms require emission source information to be completed
- Annual implementation reports need to summarize monitoring data and compliance status
- Ledger records update emission data on a daily or weekly basis
Fields include industry-specific values such as emission limits, monitoring frequencies, and permitted emission quantities. Supported units include tons per year, milligrams per cubic meter, and others.

## How these data characteristics create constraints for tool calling and plugins
This category’s data characteristics create multiple constraints for tool calling. First, multi-source data requires plugins to integrate interfaces from different systems. Tool calling must adapt to the exclusive data format of the National Emission Permit Management Information Platform to avoid field mismatches. Second, low-frequency quarterly updated data does not require real-time tool calls. Timed pulling and caching can be configured instead. Third, differences in document structures require tool calls to trigger based on document type. For example, call a monitoring data verification tool when reviewing an annual implementation report, and call a compliance comparison tool when reviewing a change application. Finally, industry-specific fields require tools to return standardized results to ensure accuracy during verification steps.

## Three common configuration mistakes
- Phenomenon: Tool calls return the `unAuthChat` error, and an apikey has been filled in. Cause: The dedicated apikey for the National Emission Permit Management Information Platform was not bound in the tool configuration. Only the general FastGPT apikey was used for verification.
- Phenomenon: Tool calls return empty results when reviewing long documents such as annual implementation reports, and points are consumed. Cause: Reasonable chunking rules were not configured for long documents, leading to tool call context overflow and failure to pull data normally.
- Phenomenon: Scheduled review tools do not appear in the workflow list. Cause: The scheduled trigger permission for the tool was not enabled, or the tool was not bound to the corresponding workflow for emission permit review.

## How to confirm the configuration is correct
- Test the emission permit application form review tool, and check if basic application form data from the corresponding platform can be pulled automatically.
- Simulate a scenario where emission limits are exceeded, and verify if the tool can call the ecological environment specification query interface to return corresponding compliance requirements.
- View tool call logs to confirm that apikey verification passed, and there are no timeout or field mismatch errors.
- Check workflow configurations to confirm that the tool has been bound to the corresponding link for declaration materials and case review.
