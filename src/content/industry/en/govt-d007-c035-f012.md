# Pollution Discharge Permit Management: Declaration Materials and File Review - Deployment and Upgrade

## Data Overview
This category’s data sources include the national pollution discharge permit management information platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems. The update frequency is quarterly.
Commonly processed documents include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies.
Data fields center on industry technical specifications, permit limits, monitoring data, and ledger items, covering core indicators such as emission concentration and total emission volume.

## Constraints for Deployment and Upgrade
The quarterly data update frequency requires configuring scheduled incremental synchronization tasks during deployment, to avoid excessive system resource usage from full synchronization.
Multiple data source access demands require configuring different types of databases and storage connections. For example, use MongoDB for ledger data, PostgreSQL for environmental statistics system data, and object storage for online monitoring reports.
Diverse document structures require parsing rules adapted to different document types, to ensure accurate field extraction for application forms, implementation reports, and other document types.
High-frequency queries of permit limit data require a caching mechanism to reduce repeated query pressure, and adjust the cache expiration time to match the quarterly update frequency.

## Three Common Configuration Mistakes
- Symptom: Throws `MongoServerSelectionError: replicaSet not configured` error during service startup, cannot connect to the ledger database. Cause: Failed to correctly configure the replicaSet parameter in `MONGODB_URI`, only filled in a single-node connection address.
- Symptom: Fails to preview uploaded online monitoring reports, returns a 403 status code. Cause: The object storage endpoint configured in `STORAGE_S3_ENDPOINT` does not match the actual storage region, and correct access permissions are not configured.
- Symptom: Expired permit limit data appears in review results, inconsistent with the latest quarterly statistics. Cause: Did not adjust the Redis cache expiration time, used the default short-term expiration configuration, and did not match the quarterly data update frequency.

## How to Verify Successful Configuration
- Run the built-in FastGPT database connection test tool to verify the connection status of `MONGODB_URI` and `PG_URL`, confirm that ledger and environmental statistics data can be read normally.
- Upload a standard pollution discharge permit implementation report, verify that files can be loaded and parsed normally through the path configured in `STORAGE_S3_ENDPOINT`.
- View the Redis cache key list, confirm that high-frequency permit limit data has been cached, and the expiration time meets the configuration requirements for quarterly data updates.
- Access the configured `FE_DOMAIN` address, confirm that the front-end page loads normally, and the generated file access links point to the correct service address.
