# Maintenance of Government Service Item Catalogs and Service Guides: Declaration Materials and File Review, Tool Calling and Plugins

## What data for this category looks like
The core data for this category includes basic government service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions.
Data sources include the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases.
The update cycle is monthly.
Documents include fields such as item code, item name, acceptance conditions, application material list, and handling process.
Fields must strictly match the standard format issued by superior authorities. No custom fields are allowed.

## Constraints imposed by these features on the tool calling and plugins workflow
Fixed monthly updated data requires regular tool synchronization.
Tool calling must be configured with scheduled trigger rules to avoid delays from manual operations.
Multiple sources of government data require calling different interfaces to pull data.
`toolChoice` must adapt to the interface calling logic of multiple data sources to automatically match corresponding tools.
Frequent operations to verify the completeness of service guide fields must use plugins to batch call field verification logic, reducing manual verification workload.
Data must strictly follow superior standards.
Tool calling return results must automatically compare field compliance.
Non-compliant entries must be marked as abnormal to ensure local items align with superior catalog standards.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-data-source interface calls, automatically match corresponding tools |
| Scheduled trigger cycle | 00:00 on the 1st of each month | Aligns with the monthly data update schedule |
| Field verification threshold | 100% match rate | Ensure service guide fields fully comply with superior standards |
| Number of data sources per call | First 3 | Avoid excessive load on single requests |
| Timeout setting | 600 seconds | Adapts to response delays of government data interfaces |
| `functionCall` | Strict field mapping | Ensure returned data corresponds one-to-one with local document fields |

## Three Common Configuration Errors
- Tool calling returns "parameter format error" with status code 400. Cause: No mapping is made between government data fields and tool calling parameters. Passing raw data format directly causes mismatches.
- Tool calling returns empty results with no field content. Cause: `toolChoice` is set to `auto` but no interfaces for corresponding data sources are bound. The system cannot automatically match available tools.
- Java API calls remain in a waiting state for response bodies with no returned results. Cause: Timeout settings do not adapt to government interface delays. Default values are too low, causing requests to be forcibly interrupted and retry logic not handled correctly.

## How to Confirm Successful Configuration
- Manually trigger a tool call, check if returned government data fields correspond one-to-one with local document fields.
- View scheduled task logs to confirm data synchronization and verification operations were automatically triggered at 00:00 on the 1st of each month.
- Simulate non-compliant service guide fields, call the tool verification plugin, and confirm abnormal markers are generated normally.
- View tool calling history records to confirm `functionCall` parameter configurations were applied correctly.

The values listed are common starting points. They should be evaluated against the reader's own samples.
