# Maintenance of Government Service Item Catalogs and Service Guidelines: Declaration Materials and File Review — Model Access and Configuration

## What the data for this category looks like
Core data for the maintenance of government service item catalogs and service guidelines comes from the national basic directory of government service items, administrative licensing item lists, power and responsibility lists, and local government service item databases. Daily maintenance documents include basic government service item directories, implementation lists, service guidelines, standard material directories, flowcharts, and frequently asked questions.
Data is updated monthly. Each document includes standardized fields such as item codes, implementing entities, acceptance conditions, and application material lists. Cross-level comparison of item specifications across different regions is required.

## Constraints imposed on the model access and configuration link
This category of data comes from official, authoritative directories. Strict alignment with standardized expressions is required, so model configuration must prioritize output accuracy to avoid deviant generated content.
The monthly update frequency requires configuration to support regular synchronization of data sources. When batch processing multiple documents, the configuration must adapt to text structures of different lengths.
The multi-field document structure requires the model to accurately extract and verify field completeness. It must also adapt to access restrictions on government networks to ensure data does not leave the domain.
Additionally, this scenario is for background rule base maintenance, and does not handle individual applicant request handling. No conversational context retention configuration is needed.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `12000–15000 characters` | Most single government service documents are several thousand characters long. Sufficient context must be retained when batch processing multiple documents to enable cross-document comparison |
| `maxTokens` | `8000 tokens` | Meets the context window limit of most mainstream large models, preventing truncation of critical item fields or official standard text |
| `temperature` | `0.1–0.3` | This scenario requires strict alignment with standardized expressions from official directories. A lower temperature reduces generation deviations and ensures the standardization of output content |
| `toolChoice` | `none` | This scenario involves batch document verification and rule base maintenance. No external tool calls are needed to complete tasks |
| `AIPROXY_API_ENDPOINT` | `Proxy address accessible via the locally deployed government network` | Adapts to the requirement that data does not leave the domain in government scenarios, preventing sensitive government data from being transmitted over public networks |
| `AIPROXY_API_TOKEN` | `Only authorized internal access tokens` | Restricts model call permissions to prevent unauthorized access to configurations |

## Three common configuration errors
- After saving the model configuration, triggering a batch comparison task automatically switches to a preset other large model. This occurs because after upgrading the FastGPT version, the binding configuration between the application and the model was not retained, or model parameters were not saved correctly.
- Processing speed is too slow when uploading government documents. This occurs because the `vision` parameter configuration is enabled, or `maxContext` is not set reasonably, causing excessive redundant text to be loaded into the model context.
- An error "Data too long for column 'models'" is displayed when adding an API token. This occurs because the token or model configuration information exceeds the length limit of the database field, and no truncation processing was applied to over-length content.

## How to confirm the configuration is properly set
- Log in to the FastGPT v4.17.0 management backend, enter the configuration page of the corresponding application, and confirm that the selected model and parameters such as `maxContext` and `temperature` match the preset configuration.
- Upload a single standard service guideline document, trigger a field extraction test, and check that the output fields such as item codes and application material lists fully match the original document.
- Initiate a batch government directory comparison task, view the task logs, and confirm that there are no error messages such as context truncation, model call failure, or network timeout.
- Call the configured `AIPROXY_API_ENDPOINT`, verify that model call results can be returned normally, and there are no access permission or network connection error prompts.

The values listed above are common starting points and should be measured against the reader's own samples.
