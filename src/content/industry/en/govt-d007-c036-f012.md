# Administrative Service Item Catalog and Service Guide Maintenance: Declaration Material and File Review - Deployment and Upgrade

## Page Scope
- Client industry: Administrative service item catalog and service guide maintenance
- Business direction: Declaration material and file review
- Capability area: Deployment and upgrade

## What the data for this category looks like
The core data for administrative service item catalog and service guide maintenance includes basic administrative service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions. The data is mainly sourced from the national basic administrative service item catalog, administrative licensing item list, power and responsibility list, and local administrative service item databases. The update frequency is monthly. The document structure includes standardized fields such as item code, item name, acceptance conditions, application material list, and handling process. Some materials require supporting scanned files or electronic documents. The overall data volume changes gradually as local administrative service items are expanded.

## What constraints these characteristics impose on deployment and upgrade
Monthly updated bulk data synchronization requires deployment configurations to support stable concurrent data import and verification capabilities. Integration requirements for multi-source data require configuring storage and parsing rules adapted to multiple document formats. Verification requirements for standardized fields require clarifying field mapping rules during deployment, to avoid inconsistent service standards between online and offline handling. In addition, the seriousness of government data requires that deployment processes ensure configuration traceability. Upgrade operations must reserve rollback paths, to prevent item data errors caused by configuration mistakes.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://{intranet IP}:27017/fastgpt` | Stores structured data such as administrative service item catalogs and service guides, and must adapt to concurrent requirements of monthly bulk imports |
| `REDIS_URL` | `redis://{intranet IP}:6379/0` | Caches session information and vector retrieval intermediate results, to ensure stability during data synchronization |
| `STORAGE_S3_ENDPOINT` | `http://{local storage address}:9000` | Stores unstructured files such as service guide attachments and scanned file materials, to adapt to storage requirements for government documents |
| `DB_MAX_LINK` | `100–200` | Sets concurrent connection limit for monthly bulk data imports, to avoid exhausting database resources |
| `FILE_TOKEN_KEY` | Random 32-character string | Generates secure file access tokens, to protect access permissions for government materials |
| `FE_DOMAIN` | `http://{private deployment domain or intranet IP}:3000` | Generates basic links for file preview and download, to ensure the frontend page loads knowledge base content normally |

## Three Common Mistakes
- Symptom: A connection failure error with status code 500 pops up when accessing the knowledge base module. Cause: `MONGODB_URI` or `REDIS_URL` is not configured correctly, causing failure to connect to core storage services.
- Symptom: An invalid interface prompt appears when connecting an external model. Cause: The FastGPT official website general account KEY is filled in the BASE_URI configuration item, and the official interface address of the corresponding model is not used.
- Symptom: After upgrading to FastGPT v4.17.0, an uncaught exception occurs when loading a simple application. Cause: The supporting database migration script is not executed, causing a mismatch between old and new version data structures.

## How to Verify Correct Configuration
- Log in to the FastGPT management backend, enter the system configuration page, and check whether the format and address of core configuration items such as `MONGODB_URI` and `REDIS_URL` are correct.
- Upload a standard service guide PDF, verify that the file upload and preview functions work normally, and confirm that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Initiate a single administrative service item data import task, check whether the task log shows successful connection and normal data writing.
- Restart the FastGPT service, access the frontend page, and verify that the service guide knowledge base list loads normally without error pop-ups.
