# Government Information Disclosure by Application: Submission Materials and File Review – Multi-turn Dialogue and Prompt Engineering

## What this category of data includes
This category’s data comes from government information disclosure platforms, official agency archive systems, document management systems, departmental business ledgers, and relevant specifications of the Regulations on Government Information Disclosure. Data updates happen irregularly, generated alongside individual application and processing workflows. Daily processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, response letters, service receipt records, and administrative reconsideration response materials. Fields cover applicant identity information, application content orientation, application date, response document number, and remedy pathway reminders. There is no unified fixed batch format, with content dynamically generated along processing stages.

## Constraints for multi-turn dialogue and prompt engineering
Scattered data sources and irregular updates require multi-turn dialogue to real-time link to the current individual case’s application materials and historical processing records. This avoids mixing contexts across different applications. Diverse document types and non-uniform field formats require prompt engineering to clearly define key information extraction rules for different documents. Examples include application content from application forms and supplementary requirements from supplementary notice letters. The core of individual case processing is judging the disclosure attribute of specific information. Multi-turn dialogue must gradually clarify specific details of the information orientation through structured interaction. This prevents review errors caused by ambiguous information. The system must also link to legal regulatory requirements to ensure prompt engineering covers relevant processing rules.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Context Window Upper Limit | `10000–15000 token calibrated via actual testing` | Government documents and dialogue content have moderate total length. An overly large window dilutes key review information |
| `variables` Variable Extraction Rules | Preset three types of variables: applicant information, application content orientation, supplementary requirements | Accurately extract core business fields, avoiding redundant information that interferes with review |
| `messages` Historical Message Filtering | Retain all dialogue and associated documents for the current application. Remove cross-application sessions | Ensure multi-turn dialogue only links to the current individual case, avoiding context confusion |
| Keyword Extraction Trigger Threshold | `0.8 calibrated via actual testing` | Government-specific technical terms are common. This threshold balances extraction accuracy and recall efficiency |
| Voice Input Enable Switch | Enable as needed based on scenario | Only enable in scenarios requiring voice interaction. This avoids unnecessary resource consumption |

## Three Common Mistakes
- Issue: The `variables` extracted application content orientation field is empty or incorrect. Cause: No variable extraction rules configured for the specific format of the government information disclosure application form. This causes the model to fail to accurately locate key information.
- Issue: After enabling voice input, voice content does not convert to text. Cause: The voice-to-text function switch is not enabled, or correct voice model call parameters are not configured.
- Issue: Multi-turn dialogue mixes context content from other applications. Cause: No case isolation is performed for `messages` historical messages. This causes session content from cross-applications to load incorrectly.

## How to Verify Proper Configuration
- Import an example government information disclosure application form, trigger multi-turn dialogue, and check if `variables` correctly extract fields such as applicant name and application content.
- Enable the voice input function, record a voice query, and check if the content correctly converts to text and links to the current session.
- Import dialogue and documents from two different application cases, and check if the `messages` filtering rule only retains content from the current case, without mixing information from other applications.
- Adjust the context window upper limit, test loading multi-turn dialogue and documents, and check if the model processes normally without significant delay.

The values provided are common starting points and should be evaluated against relevant specific samples.
