# Declaration Materials and File Review for Government Information Disclosure Upon Application: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from government information disclosure platforms, official archive systems, internal document systems, departmental business ledgers, and government disclosure-related specifications. Commonly processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, response letters, delivery receipts, and administrative reconsideration response materials. Data updates have no fixed cycle, changing with individual case applications, file archiving, or policy adjustments. A single case file includes fields such as applicant information, application content, retrieval scope, review opinions, and response documents, existing in a mixed form of structured case files and unstructured documents.

## What constraints do these characteristics impose on the tool calling and plugins link
Dispersed data sources and inconsistent formats require tool calling to adapt to multi-system interfaces and support cross-data source retrieval. Case-specific processing logic requires tool calling to be bound to the specific application case context to avoid mixing data across applications. Irregularly updated data requires tools to support dynamic loading of the latest archives and policy content, and cannot rely on static caching. Complex review links involve multi-step judgment, requiring tool calling to support chained execution, completing information retrieval, attribute judgment, and document generation step by step. Error consequences directly affect administrative compliance, requiring tool calling to be configured with complete error capture and retry mechanisms.

## Three common mistakes
- Phenomenon: MCP service calls fail when calling a locally privately deployed model, but work normally when calling an online model. Cause: The local model is not correctly configured with access permissions or interface whitelists for the MCP service, resulting in failure to normally initiate cross-service requests.
- Phenomenon: MCP service calls for complex transaction processing time out, returning MC-related error messages. Cause: The default MCP service timeout duration of the system is 90 seconds, which is not adjusted to match the duration of long-time transactions, and forced interruption is triggered after the threshold is exceeded.
- Phenomenon: The number of retrieved government information items does not match the actual application scope, and cannot match the specified retrieval conditions. Cause: The tool call is not bound to the exclusive retrieval parameters of the current application, and the global retrieval interface is mistakenly called, resulting in redundant or missing results.

## How to confirm the configuration is complete
- Initiate a simulated review process for a single government case file, check whether the tool triggers calls according to the preset review nodes, with no redundant or missing tool call actions.
- Configure a long-time test MCP service, set the timeout duration to more than 2 minutes, initiate a call, and confirm that the process is not interrupted early and returns a complete execution result.
- Verify the MCP service call permissions of the locally privately deployed model, initiate a cross-service request, and confirm that normal results are returned with no permission or connection errors.
- Import a single complete case file into the context window, check that all key fields are retained, and no truncation or loss occurs.
