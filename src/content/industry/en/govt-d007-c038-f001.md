# Government Procurement Project Declaration Materials and File Review: HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data includes core documents such as procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and responses to inquiries. Data sources include the China Government Procurement Network, local government procurement websites, fiscal integration systems, procurer budget systems, and supplier credit record systems, with daily updates. Document structures primarily use structured fields, including project number, procurement content, supplier qualifications, evaluation results, and more. Some documents must follow format specifications under the government procurement law framework.

## What constraints these characteristics impose on HTTP interfaces and external systems
Daily updated data sources require interfaces to support high-frequency requests and maintain idempotency, to avoid data conflicts caused by repeated submissions. Data from multiple sources must be aligned in format via interfaces, to adapt to field differences across different systems. Government procurement documents have strict format requirements, so interface returned data must retain the original field structure and cannot be modified arbitrarily. Additionally, interfaces involving supplier credit records must ensure encrypted data transmission, comply with fiscal supervision security requirements, and support precise queries using key fields such as project number and supplier name.

## How to Configure
This document is written based on FastGPT v4.17.0. The specific configuration items are listed below:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {API key assigned by the government procurement platform} | Complies with the interface authentication specifications of government procurement systems, ensuring data access security |
| `variables` | Preset project number, supplier query scope parameters | Adapts to multiple types of file review scenarios, simplifying interface configuration |
| `responseData` | Only return core business fields of procurement projects | Reduces data transmission load and improves interface processing efficiency |
| Request timeout period | 600 seconds | Adapts to large-data-volume batch file review scenarios, avoiding request interruption |
| Batch request limit | 50 items/request | Complies with current limiting rules of government procurement systems, avoiding triggering interception |
| Retry strategy | Retry 2 times for temporary failures | Addresses request failures caused by network fluctuations, reducing manual intervention |

## Three Common Misconfigurations
-  Phenomenon: The interface returns a 401 unauthorized error, or no matching procurement document data is returned after the request. Cause: The `Authorization` parameter is not configured with the exclusive API key assigned by the government procurement platform, or the key permissions do not cover the required data source scope.
-  Phenomenon: When calling workflow interaction components via API, no user input prompt is triggered, or the returned result is empty. Cause: No interaction trigger parameter is configured in the `variables` of the interface request, or the API release permission of the workflow is not enabled.
-  Phenomenon: Timeout interruption occurs when importing file data in batches, or system current limiting interception is triggered. Cause: The batch request limit exceeds the current limiting threshold of the government procurement system, or the request timeout period is configured too short.

## How to Verify Successful Configuration
-  Call the test interface, check if the returned `responseData` only contains the preset core business fields, with no redundant data.
-  After configuring the `Authorization` parameter, initiate a single data query, confirm that the returned result matches the public data of the government procurement system.
-  Initiate a batch request, check if current limiting interception is triggered, adjust the batch request limit to a range that complies with system rules.
-  Call the workflow API interface, confirm that the interaction component normally triggers user input prompts, and the returned result meets expectations.
