# Government Procurement Project Declaration Materials and File Review: Tool Calling and Plugins

## What this category of data looks like
Data sources for this category include the China Government Procurement Network, local government procurement websites, fiscal integration systems, procurer budget systems, and supplier credit records. The update frequency is daily. Commonly processed documents cover procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and question and response replies. The data is associated with entities including procuring units, government procurement supervision departments of finance departments, procurement agencies, and procurement review experts. Documents must comply with format and field requirements under the government procurement law framework.

## What constraints these characteristics impose on the "tool calling and plugins" link
This category of data comes from multiple sources and is updated daily. Tool calling must support scheduled pulling of data from multiple platforms to avoid using outdated information for review. Documents have diverse types and formats constrained by the government procurement law framework. Plugins must adapt to the field parsing rules of different documents to accurately extract core content such as procurement requirements and supplier qualifications. Errors in the review process have serious consequences. Tool calling must be configured with failure retry and result verification logic to ensure every operation is traceable and meets regulatory requirements. Additionally, data is associated with multiple regulatory and execution entities. Permission configuration for tool calling must distinguish access scopes for different roles to prevent unauthorized operations.

## Configuration guidelines
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the automatic matching needs of multiple types of documents and tools in government procurement scenarios, no need to manually specify tools |
| Multi-source data synchronization cycle | `24 hours` | Match the daily update frequency of this category of data to ensure the data sources used for review are always up to date |
| Single tool call timeout | `600 seconds` | Adapt to the response duration of multi-source government procurement data interfaces to avoid valid calls being interrupted due to timeout |
| Document parsing template | Preset by government procurement document category | Adapt to field extraction rules for different types of documents such as procurement requirements and tender documents, comply with format requirements under the government procurement law framework |
| Failure retry count | `2–3 times` | Balance the success rate of data pulling and system resource usage to handle occasional call failures of multi-source interfaces |
| Result verification switch | Enabled | Ensure core fields such as extracted supplier qualifications and procurement amounts meet regulatory requirements, prevent erroneous data from entering the review process |

## Three common configuration mistakes
- Tool calls return "no matching plugin name found" because the dedicated plugin adapted for government procurement scenarios was not imported into the workflow, or the `functionCall` parameter in the configuration is not associated with the correct plugin identifier.
- Timeout errors are triggered when pulling government procurement data in batches, because the timeout parameter matching the interface response duration was not set, or the multi-source data synchronization cycle is too short, causing concurrent calls to exceed interface limits.
- Core scoring fields are empty after parsing bid evaluation reports, because the parsing template preset for government procurement documents was not used, and industry-specific field naming rules cannot be matched.

## How to confirm the configuration is correct
- Manually trigger a tool call and check whether the returned document fields match the source government procurement data.
- View workflow run logs to confirm that multi-source data synchronization tasks start and execute normally according to the preset cycle.
- Simulate a tool call failure scenario to verify whether the system performs retry operations according to the configured retry count.
- Import a standard government procurement tender document and check whether the parsed fields comply with the extraction rules of the industry preset template.
