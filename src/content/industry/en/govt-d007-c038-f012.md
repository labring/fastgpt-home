# Government Procurement Project Declaration Materials and File Review: Deployment and Upgrade

## What the data for this category looks like
The business data for this category comes from the national government procurement website, local government procurement websites, the fiscal integration system, the procurer’s budget system, and supplier credit records, with a daily update frequency. Daily processed documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and responses to inquiries. It involves four types of stakeholders: procurers, the government procurement supervision department of the finance department, procurement agencies, and evaluation experts. Documents must cover core fields such as procurement budget, supplier qualifications, and evaluation results.

## What constraints these characteristics impose on the deployment and upgrade phase
The daily updated data source requires deployed synchronization tasks to have stable calling capabilities and an exception alert mechanism, to avoid data synchronization interruptions affecting the review process. The need to connect multiple types of documents and multiple data sources requires the platform to support multi-format parsing and cross-system data pull configuration. Sensitive government procurement data requires strict access control; secure identity verification and data storage rules must be configured during deployment. At the same time, errors in the review process will directly lead to bid invalidation or regulatory penalties, so data verification and failure rollback mechanisms must be preset during the deployment phase.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://username:password@host:port/gov_fastgpt?authSource=admin` | Connect to the government procurement business database, store all documents and review logs for file review |
| `REDIS_URL` | `redis://:your_password@host:port/0`, set cache expiration time to 600 seconds | Cache daily synchronized publicly available government procurement data, reduce the frequency of cross-system calls |
| `STORAGE_S3_ENDPOINT` | `https://s3-your-region.amazonaws.com` or local storage endpoint, set single file maximum size to 1000 MB | Store large documents such as scanned copies of procurement files and electronic signatures, meet the storage requirements for government procurement documents |
| `FE_DOMAIN` | `https://gov-procurement-fastgpt.your-domain.com` | Configure the jump domain for login-free share links, comply with internal access specifications for government procurement scenarios |
| `DB_MAX_LINK` | `50–80` | Limit the number of government procurement documents for a single batch synchronization, avoid synchronization task timeouts |
| `ROOT_KEY` | `32-bit randomly generated string` | Configure the platform administrator permission key, ensure access security for sensitive government procurement data |

## Three common mistakes
- Symptom: Returns 404 Not Found error when deploying with Vercel. Cause: The `FE_DOMAIN` parameter is not configured correctly, causing the access path of front-end static resources to not match the deployment environment.
- Symptom: After upgrading to FastGPT v4.17.0, the startup prompts that configuration parameters are missing. Cause: The configuration file structure was not adjusted according to the version update instructions; the position of parameters under the original `systemEnv` was changed, and the configuration was not updated synchronously.
- Symptom: After disabling the login-free share link reference and view original text functions, the functions still take effect. Cause: The back-end and front-end permission configurations were not updated at the same time, causing the configuration parameters to not take effect synchronously.

## How to confirm the configuration is complete
- Access the configured `FE_DOMAIN` address to confirm that the front-end page loads normally without 404 errors.
- Manually trigger a government procurement data synchronization task to confirm that data can be pulled from the specified data source and stored in the database, with no synchronization failure logs.
- Generate a login-free share link to test whether the original text content cannot be viewed after disabling the reference function.
- Check the background running logs to confirm that the connection status of services such as `MONGODB_URI` and `REDIS_URL` is normal, with no authentication failure or timeout prompts.
