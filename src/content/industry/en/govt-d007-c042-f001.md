# Declaration Materials and Case File Review for Legal Compliance and Major Risk Management: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category comes from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. The update frequency is monthly.
Documents processed daily include compliance risk lists, legal review opinions for contracts, legal opinions on major matters, compliance review forms, and investigation reports on violation reports.
Data includes structured fields and associated attachments. Structured fields cover business subject information, compliance risk identifiers, review conclusions, case numbering, and similar items. Attachments are mostly scanned contracts, formal review documents, and similar materials.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Data for this category comes from dispersed sources. It requires integration with multiple independent external systems. HTTP interfaces must support multi-domain configuration and differentiated authentication logic.
Documents include structured fields and attachments. Interfaces must support binary stream or base64 encoded attachment transfer formats.
Data updates occur monthly. Interface call frequency does not need to be high. Reasonable timeout and retry thresholds can be set.
Errors may lead to major legal risks. Interfaces must clearly return error status codes and detailed logs to facilitate traceback of abnormal links in review processes.
This page is written for FastGPT v4.17.0.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authorization | `Bearer ${External System API Key}` | Most compliance-focused external interfaces use Bearer token authentication, which aligns with the HTTP module security specifications of FastGPT v4.17.0 |
| Request Timeout Setting | 600 seconds | Compliance review documents include long text and attachments, leading to longer interface response times |
| variables | Pass the update identifier for monthly compliance baseline data | Ensure each call retrieves the latest compliance risk list and regulatory repository content |
| responseData | Only extract review conclusion and case number fields | Filter redundant data to reduce interface transmission load |
| Retry Count | 2 times | Avoid call failures from temporary network fluctuations, while reducing pressure on external systems |
| Attachment Transfer Method | base64 encoding | Compatible with file upload interface formats of most external systems |

## Three Common Configuration Errors
- Phenomenon: Interface calls return connection timeout or 404 status code. External systems deployed on Alibaba Cloud or via intranet penetration domains cannot be accessed. Cause: FastGPT's outbound access whitelist is not configured, or the port of the intranet penetration domain is not open. This prevents normal resolution and connection to external systems.
- Phenomenon: Scripts written in the HTTP module fail to parse asynchronous return results, or uncaught asynchronous errors occur. Cause: The `responseData` parameter is not used correctly to bind return results, or interface responses are not processed via standard asynchronous logic. This prevents data from being called by subsequent processes.
- Phenomenon: Interface return data fields are empty, or returned content does not match the expected review conclusion format. Cause: The `Authorization` parameter is not configured correctly, or interface permissions for the external system are not enabled. This prevents retrieval of valid response data.

## How to Confirm Configuration Is Complete
- Enter the test compliance data identifier in the FastGPT HTTP module test panel, initiate a call, and check if the return result includes the expected review conclusion fields.
- Check the interface call log to confirm the `Authorization` parameter is correctly carried, and no authentication failure error messages appear.
- Simulate a monthly data update scenario, pass a new update identifier, and verify if the interface returns the latest compliance risk list content.
- Upload a test contract attachment, and confirm if the interface can normally receive and transmit attachment data.
