# Declaration Materials and File Review for Special Equipment Safety Supervision: Vector Models and Indexes

## What the data for this category looks like
Special equipment safety supervision scenario data covers use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Data sources include special equipment safety supervision systems, inspection and testing institution systems, user account books, and operator certificate databases. Data is updated monthly. Each document includes fields such as equipment number, inspection cycle, maintenance unit, operator qualification number, and rectification time limit. Core fields use a mixed format of structured and semi-structured data. Data volume grows with the number of equipment in the supervision area.

## Constraints on the Vector Models and Indexes Workflow
Monthly updated datasets require index processes to support incremental synchronization. This avoids excessive time spent on full reconstruction. Mixed multi-type document structures require tailored chunking rules for each document type. This prevents truncation of key fields in long texts. Strongly associated fields such as equipment number and inspection cycle require retaining field-level association information during indexing. This prevents incorrect cross-document matches during retrieval. High-risk supervision attributes mean retrieval recall accuracy requirements are higher than standard scenarios. This requires limiting interference from irrelevant content. It also requires adherence to the input limits of `maxToken` and `defaultToken`. This accommodates special equipment documents of varying lengths.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the complete semantics of core fields such as equipment information and inspection cycle in a single document |
| Overlap Length | 100–150 characters | Retains associated information such as inspection cycle and equipment number across chunks, preventing semantic breaks |
| `maxToken` | 4096 token | Matches the maximum input limit of open-source embedding models, ensuring complete embedding after long document chunking |
| `defaultToken` | 512 token | Configures the default embedding length for short text such as operator certificate numbers, avoiding truncation of critical identifiers |
| Similarity Threshold | Calibrated based on actual testing | Meets recall accuracy requirements for high-risk supervision scenarios, avoiding missed detections or incorrect matches |
| Single Search Limit | Top 8 results | Balances retrieval efficiency and recall completeness, covering retrieval needs for multiple associated documents |

## Three Common Configuration Errors
- Index tasks display a timeout status in the console. Execution time exceeds the preset threshold. The cause is unconfigured incremental index processes. Full dataset reconstruction is still executed. This leads to repeated processing of large volumes of redundant data during monthly updates.
- Retrieval results include non-special equipment documents. The cause is lack of dedicated data source filtering rules for this category’s document types. Datasets from other supervision categories are included in the index scope.
- Operator qualification fields cannot be matched accurately. The cause is failure to retain key structured fields such as certificate numbers and qualification validity periods during chunking. This causes vector embeddings to lose core identifier information.

## How to Verify Correct Configuration
- View index logs. Confirm only monthly updated special equipment documents are synchronized. Verify that the incremental index configuration is active.
- Input a query containing an equipment number or inspection cycle. Check if retrieval results include the corresponding equipment’s periodic inspection reports and maintenance records. Verify that field association configurations are correct.
- Call the embedding model test interface. Upload a single operator certificate document. Confirm that returned vector results differ from outputs of general domain models. Verify that the embedding model selection is correct.
- View index task time statistics. Confirm that single-batch indexing stays within a reasonable range. Verify that chunking and index process efficiency configurations are appropriate.
