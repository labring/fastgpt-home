# Special Equipment Safety Supervision: Declaration Materials and File Review - Tool Calling and Plugins

## What data looks like for this category
Data sources for special equipment safety supervision scenarios include special equipment safety supervision systems, inspection and testing institution systems, user ledgers, and operator certificate databases.
Daily review involves documents such as use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates.
Common fields across these documents include unique device ID, inspection validity period, maintenance cycle, operator certificate number, and rectification completion status.
Data is updated monthly. The overall data structure follows the full device lifecycle and supervision processes. Field formats vary slightly across different document types.

## Constraints on Tool Calling and Plugins Workflow
Decentralized data sources require tool calling to cover multiple system interfaces. Cross-system tool permissions and field mapping rules must be configured.
Monthly data update frequency means tool calling cache cycles must match the data update rhythm. This prevents use of expired device ledgers and inspection data.
Diverse document types and distinct field differences require tools to automatically recognize field formats across different documents. Tools must complete cross-document field verification and association.
The most time-consuming verification links require tool calling to support batch data pulling. This reduces manual repetitive operations.
Consequences of errors are severe. A failure retry and result verification mechanism for tool calling must be configured. This prevents incorrect data from entering the review process.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool linkage scenarios in special equipment review, automatically matches ledger, inspection, and qualification-related tools that need to be called |
| Tool calling timeout | `600 seconds` | Special equipment system interfaces have certain response delays; this duration covers most normal calling scenarios |
| Tool calling retry count | `2 times` | Addresses temporary network fluctuations or brief interface unavailability, avoids terminating the review process directly due to a single failed call |
| `functionCall` | Force-specified tool list | Ensures only tools related to special equipment supervision are called, prevents calling unrelated interfaces that could lead to data leakage or misuse |
| Batch tool calling limit | `First 10 items` | The number of files in a single review should not be too large; this limit balances review efficiency and system load |
| Stream response configuration | Enabled | Adapts to long-text review result output, improves interactive experience for lengthy file reviews |

## Three Common Configuration Mistakes
- Phenomenon: Empty device ledger fields are returned by tool calls. Cause: No mapping relationship is configured between tool parameters and special equipment system interface fields. This prevents correct extraction of device numbers and inspection cycles.
- Phenomenon: Tool calling triggers a timeout error with status code 504. Cause: The set timeout period is shorter than the average response duration of special equipment system interfaces. Additional delays from cross-system calls are not accounted for.
- Phenomenon: Stream response does not take effect. Returns full packaged content instead of segmented data. Cause: Stream response configuration was not correctly enabled in FastGPT v4.17.0. This fails to match the long-text output scenario of special equipment review.

## How to Confirm Configuration is Correct
- Initiate a test request containing a known special equipment device ID. Check if the tool successfully pulls the corresponding ledger and inspection report data.
- View the tool calling log. Confirm the `toolChoice` parameter is correctly applied. Confirm the specified tool list has loaded and can be called normally.
- Simulate a scenario where temporary network interruption is followed by recovery. Check if the tool executes retry operations as configured and completes the call eventually.
- After enabling stream response, check if returned results are pushed in segments. Do not return all review content at once.

The values provided here are common starting points and should be measured against the reader's own samples.
