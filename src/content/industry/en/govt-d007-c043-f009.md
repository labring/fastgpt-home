# Special Equipment Safety Supervision: Declaration Materials and File Review - Model Access and Configuration

## What Data for This Category Looks Like
Data covers documents related to the full lifecycle of special equipment, including use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Data sources include the special equipment safety supervision system, inspection and testing institution systems, user unit ledgers, and the operator certificate database. Update frequency is monthly. Each individual document contains structured fields such as unique equipment ID, inspection validity period, maintenance unit name, and operator certificate number. Some reports such as periodic inspection reports include tabulated inspection items and result data.

## Constraints Imposed on Model Access and Configuration
Business data sources are scattered with significant format differences. Multi-system integration requires model access to support unified parsing of multi-source data. The monthly update frequency requires vector databases and model context to adapt to periodic incremental document updates, preventing data lag from affecting review timeliness. Core review links require accurate extraction of strongly verified fields such as equipment ID, inspection cycle, and qualification certificate number, placing high accuracy requirements on model output. The high-risk supervision attribute requires stable and reliable model call links, avoiding review process interruptions caused by configuration errors that could lead to equipment shutdown or administrative penalty risks.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of spliced multiple file documents, avoids truncation of key review information |
| `maxTokens` | 2000–3000 token | Meets the complete output requirement for a single review report, covers all content of qualification verification and rectification conclusions |
| `quoteMaxToken` | 1000–1500 token | Limits the length of a single referenced document, focuses on core review fields |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures consistency in extraction of structured fields such as equipment ID and inspection cycle |
| `AIPROXY_API_ENDPOINT` | Exclusive API address provided by cloud platform large models | Adapts to cloud large model call links under private deployment, compatible with OneAPI forwarding configuration rules |
| `AIPROXY_API_TOKEN` | Exactly matches the key generated by the cloud platform model provider | Ensures successful model call authentication, matches verified access parameters in OneAPI |

## Three Common Configuration Mistakes
- A 404 error is returned during model testing. The cause is that the entered model ID does not match the identifier recognized internally by FastGPT, and the actual model identifier of the cloud platform model provider has not been synchronized.
- The container displays the error `Api response error: /api/core/ai/model/test?model=Doubao-l`. The cause is that the `AIPROXY_API_ENDPOINT` configuration does not include the complete API path, or the permission scope of `AIPROXY_API_TOKEN` is insufficient.
- Model inference effect differs from native cloud platform calls. The cause is that `temperature` is set too high, or `maxContext` does not cover the actual spliced length of business documents.

## How to Verify Correct Configuration
- Access the model provider management page of FastGPT v4.17.0, click the test button for the configured model, and confirm that normal structured response content is returned.
- Import a single special equipment periodic inspection report, trigger the automatic review process, and check whether core fields such as equipment ID and inspection validity period are accurately extracted in the output result.
- Adjust the `temperature` parameter and compare two review results, and confirm that there is no obvious random fluctuation in field extraction results.
- View the FastGPT container running logs, and confirm that there are no 404 or authentication errors related to model calls.
