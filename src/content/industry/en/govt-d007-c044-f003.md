# Declaration Materials and Case Review for Environmental Law Enforcement and Monitoring Supervision: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category comes primarily from online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Update frequency is daily.
Commonly processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Document fields cover core content such as monitoring points, test indicators, test results, law enforcement time, and rectification requirements. Individual document lengths vary widely, ranging from hundreds to thousands of characters.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Daily updated data sources require multi-turn dialogue workflows to pull the latest monitoring and law enforcement data in real time. This avoids use of expired information.
Diverse document types require prompt engineering to clearly distinguish processing rules for on-site records, test reports, and law enforcement documents. This prevents confusion over field meanings.
Multi-field document structures require multi-turn dialogue to guide users to supplement or confirm information step by step. This reduces omissions.
Errors in law enforcement and monitoring directly affect compliance. Prompt engineering must include data comparison and verification logic to ensure results meet supervision requirements.

## How to configure settings

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 characters | Covers core content of a single law enforcement document and multiple associated documents |
| Multi-turn dialogue context retention rule | Retain the first 10 turns of conversation | Matches the step-by-step information supplement logic used in law enforcement review |
| `variables` variable binding | Bind monitoring point and law enforcement time fields | Quickly call basic data stored in the law enforcement system |
| Prompt template segmented loading | Enabled | Adapts to differentiated processing for different document types such as on-site inspection records and monitoring reports |
| Dialogue timeout duration | 600 seconds | Allows sufficient time to complete comparison and review of multiple test reports |
| Form popup trigger rule | Triggered by conversation nodes | Prevents abnormal popup display in nested workflows |

## Three common misconfigurations
- Phenomenon: No corresponding interaction record appears in the conversation log after calling an external application or plugin. Cause: Conversation log synchronization configuration is not enabled in the workflow. Only the interface call is executed, without binding the conversation context.
- Phenomenon: Form input node popups in nested workflows continue to display and cannot hide automatically. Cause: The form popup trigger rule does not adapt to nested scenarios. The default trigger logic follows independent workflow rules, and does not inherit the hiding rules of the parent workflow.
- Phenomenon: Clickable web content or text-to-image output cannot be rendered in the dialog box. Cause: Rich text rendering configuration is not enabled, and the output format adaptation rules for the text-to-image model to match dialog box display are not configured.

## How to verify successful configuration
- Trigger a complete law enforcement case review process. Check whether the conversation log includes interaction records for all links. Confirm that the bound fields in `variables`, the case identifier associated with `chatId`, and the conversation content stored in `messages` meet configuration requirements.
- Nest the configured application into a test workflow. Trigger the form input node, and confirm that the popup hides automatically as expected.
- Upload multiple different types of law enforcement documents. Test the multi-turn dialogue process, and confirm that the prompt engineering correctly distinguishes document types and executes corresponding verification logic.
- Run a long-process test lasting more than 600 seconds. Confirm that no timeout error occurs in the dialogue, and all data comparison links are completed.
