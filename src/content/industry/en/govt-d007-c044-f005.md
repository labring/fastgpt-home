# Declaration Materials and Case File Review for Environmental Law Enforcement and Monitoring Supervision: Tool Calling and Plugins

## What this category’s data includes
Data for this category originates from online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Updates occur daily. Commonly processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Fields include sampling point coordinates, pollutant concentration values, law enforcement officer identification numbers, inspection time periods, operating condition parameters, and more. Individual document lengths vary significantly; some professional monitoring reports exceed 2000 characters.

## Constraints imposed on the "tool calling and plugins" workflow by these characteristics
Decentralized data sources require tool calling to interface with multiple system types. Separate call permissions must be configured for each data source. The daily update requirement means tool calling tasks need reasonable trigger cycles. This avoids delayed data impacting review efficiency. Large variations in document fields, plus some monitoring reports with non-standardized professional parameters, require adapting field extraction rules for different documents. This prevents parameter identification errors. Law enforcement documents must strictly match legal formats. Tool-generated content must strictly correspond to original data fields to avoid inconsistent information.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapts to parameter extraction needs for multiple types of law enforcement documents, automatically matches corresponding tool calling logic |
| Plugin call timeout | 600 seconds | Parsing some third-party test reports takes longer, prevents task interruption due to timeout |
| Parameter extraction confidence threshold | 0.85–0.90 | Filters low-reliability field identification results, ensures accuracy of law enforcement document data |
| Single tool call data volume limit | First 10 daily monitoring data entries | Matches the daily data processing rhythm of law enforcement reviews, avoids overloading single requests |
| `functionCall` | Enable mandatory parameter validation | Ensures complete law enforcement-related fields are passed during tool calls, prevents generation of non-standard documents |
| FastGPT version | v4.17.0 | Supports plugin calling and parameter validation features of this version |

## Three common configuration errors
- A custom plugin call returns an interface error stating the key is invalid. This occurs when the exclusive interface key of the ecological environment law enforcement system is not configured as the plugin’s call key, and the application’s universal key is used instead.
- The sampling point field extracted after tool calling is empty. This happens when parameter extraction rules are not configured for the specific field format of monitoring reports, making non-standard point naming unrecognizable.
- No user confirmation step triggers during tool calling, and law enforcement document generation runs directly. This is caused by not enabling user input confirmation before tool calling, and not setting verification steps after parameter extraction.

## How to verify correct configuration
- Upload a standard sampling record document, trigger tool calling, and confirm the corresponding plugin is automatically matched and correct parameter extraction results are returned.
- Simulate a call to the third-party test report parsing plugin, verify the timeout setting works as expected, with no early task interruption.
- Review plugin call logs, confirm the passed key matches the ecological environment law enforcement system’s interface key, and no key error prompts appear.
- After enabling `functionCall` validation, submit test data with missing key fields, and check if parameter completion or interception prompts are triggered.

The values provided are common starting points and should be measured against the reader's own samples.
