# Declaration Materials and File Review for Environmental Law Enforcement and Monitoring Supervision: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category covers daily business documents from ecological environment law enforcement detachments, monitoring stations, pollutant discharge units, and third-party testing institutions. Documents include on-site inspection records, sampling records, monitoring reports, orders to rectify, and administrative penalty decisions.

Data sources include online monitoring platforms, pollutant source automatic monitoring data, ecological environment law enforcement systems, and third-party test reports. Data is updated daily. Most documents are structured forms and semi-structured reports, with fields such as monitoring points, pollutant concentration, law enforcement time, and rectification requirements. Units include mg/m³, mg/L, hour, batch, and others.

## What constraints these characteristics impose on knowledge base retrieval and recall
Data is updated daily, so retrieval and recall must be timely to avoid calling expired online monitoring or law enforcement system data.
Documents have multi-dimensional fields, so retrieval must support precise matching by pollutant type, law enforcement time, rectification status, and other criteria.
Third-party test reports and law enforcement documents have format differences, so chunking and indexing must adapt to different document structures.
The need to compare on-site working conditions with online data requires that recall results associate multi-source data entries, avoiding retrieval bias from single data sources.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | Match precise fields in law enforcement documents and monitoring reports, filter low-relevance redundant results |
| `limit` | Top 6–10 results | Cover multiple related documents required for a single review, such as on-site inspection records, monitoring reports, and penalty decisions |
| `searchMode` | semantic+keyword | Balance semantic matching and precise keyword retrieval, adapt to fixed fields such as pollutant names and law enforcement numbers |
| `usingReRank` | Enabled | Reorder recall results by relevance, optimize the retrieval ranking priority for law enforcement basis and over-standard judgment |
| `datasetSearchUsingExtensionQuery` | Disabled | Prevent the system from automatically expanding query content, ensure retrieval results only include uploaded business documents |
| `collectionIds` | Bind exclusive law enforcement and monitoring datasets | Limit retrieval scope, exclude non-category redundant documents, improve retrieval accuracy |

## Three Common Configuration Errors
- Non-law enforcement or monitoring documents appear in retrieval results. This occurs when `collectionIds` is incorrectly configured, and the exclusive dataset scope is not bound.
- Retrieval results include additional AI-generated completion content. This occurs when `datasetSearchUsingExtensionQuery` is not disabled, triggering automatic query expansion logic.
- Knowledge base index creation fails. This occurs when the format of semi-structured monitoring reports is not adapted, and chunking rules are not adjusted according to business document structures.

## How to Verify Successful Configuration
- Enter the FastGPT v4.17.0 knowledge base management interface, check whether `collectionIds` is bound to exclusive law enforcement and monitoring datasets.
- Initiate a test retrieval for pollutant concentration or law enforcement time, confirm that the number of returned results matches the `limit` setting.
- Review retrieval result details, confirm no additional AI-generated completion content is present, and verify that `datasetSearchUsingExtensionQuery` is disabled.
- Submit a sampling record or on-site inspection record for indexing, confirm the index status shows completed with no error prompts.

All provided configuration values are common starting points, and should be evaluated against the reader's own sample data.
