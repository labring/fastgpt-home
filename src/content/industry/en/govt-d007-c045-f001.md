# Land Pre-examination and Planning Permit Declaration Materials and File Review: HTTP Interfaces and External Systems

## What this category of business data looks like
The data sources for this category of business data are the national land and spatial planning one-map, project approval and supervision platform, current land use database, and ecological protection red line data. The update frequency is irregular.
Daily generated documents include land pre-examination and site selection opinions, construction land planning permits, construction engineering planning permits, red line drawings, and planning conditions.
The data structure revolves around project site selection, land scale, and planning control requirements. It includes core fields such as project unique identifier, coordinate range, and license effective conditions.

## What constraints these characteristics impose on HTTP interfaces and external systems
This category of data is multi-source across departments and has no fixed update cycle. It requires HTTP interfaces to support multi-source data pulling and cross-system format compatibility.
Documents include structured license files and unstructured drawings. Interfaces must support field-level parsing and image content extraction.
Core data is directly linked to the entire project approval process. Interface call failures directly affect project approval and construction startup.
Strict retry mechanisms and exception alert logic must be configured to ensure review processes are not interrupted.

## How to configure the settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Basis for This Setting |
|---|---|---|
| `Authorization` | `Bearer {API key assigned by FastGPT platform}` | Complies with authentication specifications of natural resource system interfaces, ensures security of data calls |
| Request timeout | 600 seconds | Land pre-examination data pulling involves cross-departmental interfaces. Single requests take longer time, avoid interrupting review processes due to timeout |
| `variables` | Bind business variables such as project number and red line coordinate range | Adapt to personalized query needs of different projects, accurately match corresponding file and declaration material data |
| `responseData` | Extract business content according to structured fields, include drawing links and text information | Standardize parsing of document data returned by natural resource departments, facilitate subsequent review and verification |
| Retry times | 2–3 times | Respond to temporary fluctuations of cross-departmental interfaces, reduce process interruptions caused by single request failure |
| Data pulling trigger timing | Trigger according to project declaration nodes | Match the approval process of land pre-examination and planning permit, avoid invalid data pulling |

## Three common misconfigurations
- Empty business fields returned after calling the interface. Cause: The project unique identifier parameter is not bound in `variables`, so declaration materials and license documents corresponding to the project cannot be matched.
- Persistent interface request timeouts. Cause: The request timeout time is set too short, not adapted to the average response duration of cross-departmental natural resource system interfaces.
- Unable to extract image content after connecting to an external document system. Cause: No image parsing rules are configured for `responseData`, only text-format document content is extracted.

## How to confirm the configuration is complete
- Initiate a test request, pass preset project variables, check whether the returned `responseData` includes core business fields of the corresponding category.
- Simulate an interface delay scenario, verify whether the system triggers the preset retry mechanism without direct errors.
- After connecting to an external document system, query documents containing drawings, confirm that image content can be extracted normally.
- Check the `Authorization` parameter configuration, confirm that no authentication failure error logs appear.
