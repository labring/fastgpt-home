# Declaration Materials and File Review for Land Pre-examination and Planning Permit: Workflow Orchestration

## What data for this category consists of
Data sources for this category include the national land spatial planning one-map, project approval and supervision platform, land use status database, and ecological protection red line data. Update frequency is irregular. Daily processed documents include land pre-examination and site selection opinions, construction land planning permits, construction project planning permits, red line drawings, and planning conditions. These documents contain structured fields such as project site selection scope, land scale, planning control requirements, and red line coordinates, as well as graphical spatial data. Verification must be completed by associating spatial and approval data from multiple sources.

## Constraints imposed on workflow orchestration by these characteristics
Multi-source and irregularly updated data for this category requires workflows to support real-time pulling of latest national land spatial planning, ecological protection red line and other data for compliance verification. Documents include structured fields and graphical red line data, so workflows must configure parsing and association nodes for multiple data types. Core time-consuming links of project review focus on site compliance, land scale and red line conflict verification. Workflows must split such verification into independently configurable nodes, and add circulation branches for cross-department pre-condition coordination to adapt to actual approval process logic.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Knowledge base search file scope | Bind project-specific red line drawing and planning condition file set | Review for this category must focus on project-specific planning documents to avoid irrelevant data interfering with verification |
| Batch execution node cycle limit | 3-5 times, calibrated via actual testing | Cross-department pre-conditions with development and reform, housing and urban-rural development, ecological and other departments need coordination, cycle count matches actual coordination node count |
| LLM parameter binding | Set the `variables` parameter to 0.2-0.5 | Review tasks require stable output of compliance conclusions, avoid randomized generated content |
| Node timeout duration | 600 seconds | Spatial data verification and multi-source data pulling require long processing time, avoid workflow interruption |
| Knowledge base ID acquisition method | Copy from the details page of the FastGPT knowledge base management page | Must accurately bind the category-specific knowledge base to ensure search coverage of standard documents |
| Context isolation configuration | After enabling, bind the context of the node corresponding to `nodeId` | Adapt to context isolation requirements during multi-node parallel processing |

## Three Common Mistakes
- Phenomenon: When configuring the knowledge base search node, the project-specific file set is not specified, and the number of returned results far exceeds expectations. Cause: The search scope is not limited according to the category's review requirements, and the default full knowledge base data is retrieved, leading to redundant information interfering with verification.
- Phenomenon: When calling the workflow via API, the batch execution node does not complete all cycles, and a 504 status code is returned. Cause: The batch execution node cycle limit is set too high, and no timeout retry mechanism is configured, exceeding the default duration limit of the API call.
- Phenomenon: After enabling variable reference, the LLM temperature setting button disappears, and the generation parameters cannot be adjusted. Cause: In FastGPT v4.17.0, the native setting item is hidden in variable reference mode, and adjustment must be implemented via code-bound parameters.

## How to Confirm Configuration is Complete
- Check the bound files on the FastGPT knowledge base management page, confirm they match the search scope configured in the workflow.
- Perform single-node debugging to verify that the knowledge base search results only include the preset project-specific documents.
- Call the API to trigger the complete workflow, check the execution logs of the batch execution node, and confirm the cycle process is completed normally.
- Check the LLM parameter binding configuration, ensure the parameters in variable reference mode are correctly associated.
