# Declaration Materials and File Review for Land Pre-examination and Planning Permission: Source Citation and Traceability

## What this category of data looks like
This category of data primarily comes from the national land spatial planning unified map, project approval and supervision platform, current land use database, and ecological protection redline data. Update frequency is irregular. Commonly processed documents include land pre-examination and site selection opinions, construction land planning permits, construction engineering planning permits, redline diagrams, and planning conditions. Document structures include fields such as project subject information, site selection scope, land use scale, and control requirements. Some spatial documents include coordinate units and geographic range parameters.

## What constraints these characteristics impose on the "source citation and traceability" link
Data sources are scattered and updated irregularly. Precise matching of the corresponding relationship between approval documents and original data sources is required to avoid using expired planning data. Coordinate and scope fields in spatial documents must strictly correspond to original geographic data. During traceability, the land spatial planning layer to which the data belongs must be clearly marked. Field formats vary widely across different documents, so unified field mapping rules must be implemented to ensure consistency of cited sources. At the same time, pre-files across the entire project approval process must be associated to avoid missing basis for cross-departmental preconditions.

## Three common configuration errors
- Setting `quoteMaxToken` too large, causing responses to exceed model context limits, resulting in content truncation or interface errors. This occurs because the parameter is not adjusted based on the total token count of land pre-examination materials, and the value is blindly increased.
- Not enabling the source layer annotation in `responseData`, making it impossible to confirm whether data comes from the latest national land spatial planning unified map during file review. This occurs because the core traceability requirement for spatial data in this category is overlooked.
- Setting the single search limit too high, such as exceeding 10 entries, resulting in a large number of redundant historical approval data being returned, occupying model context and interfering with review judgments. This occurs because the parameter is not adjusted based on the number of linked cross-departmental data in this category.

## How to confirm correct configuration
- Upload a land pre-examination declaration material, trigger knowledge base search, and check whether the returned results include document title, source layer, and update time.
- Check the value of `quoteMaxToken`, confirm that the returned traceability content is not truncated, and the total token count complies with the current model's limit requirements.
- Compare search results with original project approval data, confirm that field mapping rules are correct, and spatial parameters such as redline coordinates and land use scale match the original documents.
- Test workflow calls, confirm that search results can be correctly passed as background knowledge to subsequent processing modules, with no missing fields or format errors.
