# Declaration Materials and File Review for Land Pre-examination and Planning Permission: Document Parsing and Chunking

## What This Type of Data Looks Like
Data for this category originates from the national land and spatial planning one-map system, project approval and supervision platform, land use status database, and ecological protection redline data. Update frequency is irregular. Commonly processed documents include land pre-examination and site selection opinions, construction land planning permits, redline diagrams, planning conditions, and similar materials. Some approval materials are multi-column Excel tables with fields such as land scale, redline coordinates, and planning control indicators. Units used include hectares, square meters, and others.

## Constraints for Document Parsing and Chunking
Scattered data sources and varied formats require the parsing module to support multiple formats including PDF and multi-column Excel. This prevents loss of core fields such as redline coordinates and land scale due to format incompatibility. Irregular update frequency means the parsing process must support batch processing of newly uploaded materials in a single run, without reloading historical documents. Multi-column approval tables have strong field relevance. Chunking must retain complete business information for each row, to avoid breaking the association between land scale and control requirements. File review requires coherent project context. Chunk length must align with the logical paragraphs of approval materials, to avoid splitting associated information between project site selection and preconditions.

The following configurations are formulated based on the rules of FastGPT v4.17.0.

| `chunkSize` | 800–1200 characters | Adapts to the logical paragraph length of land pre-examination materials, retains the integrity of core business fields |
| `chunkSplitter` | Mixed paragraph and fixed-length splitting | Balances business logic coherence and chunk granularity, adapts to multi-column Excel and PDF approval documents |
| `customPdfParse` | Enabled | Accurately extracts redline diagram annotations and planning condition text from PDFs, avoids field loss caused by format confusion |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing time for large redline diagram PDFs or multi-page approval files, avoids mid-process timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploading of full approval materials for a single project, including multiple redline diagrams and historical approval documents |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for multi-column Excel, avoids automatic chunking disrupting row-level field associations |

## Three Common Configuration Mistakes
- Phenomenon: Multi-column Excel approval materials split after automatic chunking, with land scale and control indicators from the same row separated into different chunks. Cause: Manual chunking mode is not enabled, and default chunking rules do not adapt to the strong field relevance of multi-column tables.
- Phenomenon: The system returns a timeout error during single-batch parsing of a large redline diagram PDF. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too low, failing to reserve sufficient time for parsing large documents with vector annotations.
- Phenomenon: When uploading new approval materials, the system automatically parses historical files alongside the new uploads. Cause: The global historical document loading switch is not disabled, expanding the parsing scope beyond the currently uploaded attachments.

## How to Verify Correct Configuration
- A standard land pre-examination PDF document is uploaded, and the parsed text is reviewed to confirm full retention of core fields including redline coordinates and land scale.
- A multi-column format approval Excel table is uploaded, and chunking results are verified to retain complete business information for each row.
- A single large PDF document is uploaded, and the parsing process is confirmed to avoid timeout errors and meet expected elapsed time.
- A new attachment is uploaded, and the parsing log is reviewed to confirm it only includes records for the currently uploaded file, with no historical document entries.

The configuration values listed above are common starting points. They should be evaluated against the reader’s own sample materials.
