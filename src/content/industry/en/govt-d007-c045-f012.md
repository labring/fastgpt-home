# Land Use Preliminary Examination and Planning Permit: Declaration Materials and File Review - Deployment and Upgrade

## What This Category of Data Looks Like
The data sources for this category include the national land spatial planning unified map, project approval and supervision platform, land use status database, and ecological protection redline data. Update frequency is irregular. Daily processed documents include land use preliminary examination and site selection opinions, construction land planning permits, construction engineering planning permits, redline diagrams, and planning conditions. Core fields cover project site selection range coordinates, land use scale parameters, planning control requirements, etc. Multi-source spatial and approval data must be associated to complete verification.

## How These Characteristics Impact Deployment and Upgrade Requirements
Multi-source heterogeneous data sources require support for multiple data access protocols and format parsing rules during deployment, to avoid parsing failures caused by data source changes. The irregularly updated data feature requires dynamic adjustment of synchronization frequency and verification logic, without service restarts to adapt to new business data. Standardized verification requirements for fields such as spatial coordinates and land use scale require targeted field rule configuration. For government affairs file review business continuity requirements, a rollback mechanism and gray release path must be reserved during upgrades.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Full connection address for the dedicated MongoDB instance on the government affairs intranet | Stores historical data and temporary parsing results for file review, requires intranet access permissions and stability |
| `REDIS_URL` | Address of the dedicated Redis cluster on the government affairs cloud, set connection timeout to 300 seconds | Caches frequently queried planning control rules and redline data, reduces repeated calls to multi-source data sources |
| `STORAGE_S3_ENDPOINT` | Endpoint address connected to the government affairs cloud object storage service | Stores large-volume spatial documents such as redline diagrams and planning conditions, complies with government data storage compliance requirements |
| `DB_MAX_LINK` | 80–120 connections | Adapts to parallel file review requests from multiple departments, avoids exhausting database connections |
| `FILE_TOKEN_KEY` | Configured with the unified government affairs security token key | Ensures document download and parsing permission verification complies with government affairs security specifications |
| `ROOT_KEY` | Dedicated administrator key for local deployment | Restricts unauthorized modification of review configurations, complies with government affairs system permission management requirements |

## Three Common Misconfigurations
- Symptom: Connection timeout error returned when calling external models. Cause: No outbound proxy rules for the government affairs intranet configured, unable to access external model services.
- Symptom: Some historical files fail to load after upgrade. Cause: No backup of the database corresponding to `MONGODB_URI` in advance, configuration was accidentally overwritten during the upgrade process.
- Symptom: Redline diagram parsing failed. Cause: The key parameter of `FILE_TOKEN_KEY` was not configured correctly, unable to pass document permission verification.

## How to Confirm Successful Configuration
- Log in to the FastGPT v4.17.0 backend, check the connection status of `MONGODB_URI`, confirm it shows a normal connection.
- Upload a test redline diagram document, confirm it can be parsed normally and extract spatial coordinates and land use scale fields.
- Initiate a simulated file review request, confirm the system can call the configured model to complete content verification.
- Check the cache metrics for `REDIS_URL`, confirm frequently queried planning control rules are correctly cached.
