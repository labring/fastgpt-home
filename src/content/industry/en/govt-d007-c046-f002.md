# Declaration Materials and Case Review for Social Assistance and Minimum Living Security Audit: Vector Models and Indexing

## What the data for this category looks like
Organizations including civil affairs bureau assistance sections, sub-district and township civil affairs offices, community committees, and verification centers provide daily work documents as the primary data source for this category. These documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms.

Data synchronization pulls from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Updates occur on a monthly basis.

Data fields focus on three core areas: family economic status, member relationships, and assistance eligibility. Each individual document mixes structured form entries and multi-page semi-structured supporting materials.

## What constraints these characteristics impose on vector models and indexing
Monthly batch data updates require indexing systems to support incremental synchronization. This avoids full reindexing that uses excessive system resources.

Cross-department shared data has scattered fields and inconsistent formats. Vector models must adapt to multi-field mixed text structures. This ensures accurate semantic matching for core review fields such as family income, property, and member relationships.

Each individual document mixes short form entries and long paragraph supporting materials. Chunking processes must balance semantic integrity for both text types. This prevents key information from being fragmented.

Errors in assistance reviews have serious consequences. Index recall results must have high confidence levels. This stops low-matching irrelevant data from entering the context, which creates risks of incorrect or missed assistance approvals.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk length | 800–1200 characters | Balances short fields on minimum living security application forms and long paragraphs on household survey forms. Avoids semantic fragmentation or overly small chunks that cause scattered recall |
| Overlap length | 100–150 characters | Covers semantic boundaries across related fields. Ensures coherent context for family income and property verification |
| Similarity threshold | 0.75–0.85 | Adapts to field differences in cross-department data. Balances recall completeness and result accuracy, and reduces risks of incorrect or missed assistance approvals |
| Single search limit | Top 10 entries | Controls context window size. Aligns with the core information volume of civil affairs review, and avoids redundant data interfering with review judgments |
| `defaultToken` | `4096` | Adapts to context length requirements for most daily review scenarios. Ensures complete inclusion of key content about family status and supporting materials |
| `maxToken` | `8192` | Handles case review scenarios containing multiple supporting materials. Meets the transmission requirements for long-text context |

## Three common misconfigurations
-  Issue: No matching options appear in the index model selection list. Vector model configuration cannot be completed. Cause: The runtime environment for the target vector model is not deployed, or the installed FastGPT v4.17.0 version is not compatible with the target model.
-  Issue: Recalled document fragments lack labels for source document names and specific locations. Cause: The metadata retention switch is not enabled, and the document identification field was not included in the vectorization context during chunking.
-  Issue: A large number of irrelevant recall results appear after synchronizing monthly batch data. Cause: The similarity threshold is set too low, causing low-matching cross-department data to be included in the context and creating risks of incorrect or missed assistance approvals.

## How to confirm correct configuration
-  Upload a single minimum living security application form and family economic status verification report. Check whether the chunked text covers core fields and has no obvious semantic fragmentation.
-  Submit a query about family income verification. Verify that recalled results have complete source labels, and confirm that the document tracing function is enabled normally.
-  Import test data for monthly batch updates. Observe the time consumption and status of index synchronization, and confirm that no timeouts or abnormal errors occur.
-  Adjust test parameters for the similarity threshold. Verify whether the number of recalled results changes in line with scenario requirements.

The values provided here are common starting points, and should be adjusted based on deployment-specific samples.
