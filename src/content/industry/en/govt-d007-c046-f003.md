# Application Materials and Case Review for Social Assistance and Minimum Living Security Eligibility Review: Multi-turn Dialogue and Prompt Engineering

## Data Overview for This Category
This category of data covers standardized documents including minimum living security application forms, household economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. This data originates primarily from the low-income population dynamic monitoring platform, resident household economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Data updates occur on a monthly basis. Core fields include household income, total property, family member relationships, and assistance eligibility determination items. Most field units are yuan, persons, and natural months. The data volume of a single case fluctuates based on family size.

## Constraints for Multi-turn Dialogue and Prompt Engineering Links
Decentralized cross-department data sources require multi-turn dialogue to gradually trigger data retrieval from different systems. Prompts must clearly guide alignment with the field formats of each system to avoid data matching deviations. The monthly update cadence of data sources requires conversation contexts to retain recent cycle verification data, preventing calls to expired information. Structural differences across multiple standardized document types require prompts to first identify the currently processed document type before matching corresponding review rules. Verification of sensitive fields such as household income and property requires multi-turn dialogue to conduct step-by-step validation. At the same time, prompts must be restricted to returning only compliant review determination results to prevent sensitive information leaks.

## Three Common Configuration Errors
- After configuring database tool calls, the conversation returns a 400 status code with no response body: The cause is that access keys and permission scopes for cross-department data sources are not correctly bound, resulting in an interruption of the tool call chain.
- Unable to add an internet access button or switch models in the conversation interface: The cause is that the model switching and external tool configuration items for the conversation interface are not enabled, failing to adapt to the interactive expansion requirements of multi-turn dialogue.
- After local deployment, historical conversation records shared via web links cannot be retrieved: The cause is that the persistent storage path for conversation storage is not correctly configured, or access permissions for the corresponding interface are not granted.

## How to Verify Successful Configuration
- Launch a simulated minimum living security household review conversation to verify that tool calls can correctly retrieve field data from corresponding cross-department data sources.
- Switch between different models to test the multi-turn dialogue process, and confirm that the interface can normally complete model switching operations.
- Execute the conversation record cleanup command for local deployment, and verify that conversation data in the storage directory is completely cleared.
- Generate a web share link, launch a conversation, then revisit the link to confirm that historical conversation records can be loaded and displayed normally.
