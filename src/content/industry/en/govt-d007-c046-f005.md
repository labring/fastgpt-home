# Declarations and Case Review for Social Assistance and Minimum Living Standard Allowance: Tool Calling and Plugins

## What this category of data looks like
This category covers all documents across the civil affairs social assistance workflow, including minimum living standard allowance application forms, family economic status verification reports, household investigation forms, democratic review records, public notice materials, and assistance approval forms.
Data sources include low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities.
The update frequency is monthly.
Data fields include household population information, income and property details, household inspection records, review and public notice results, and more. There is no unified standardized field format, so cross-department data source field mapping rules must be matched.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Cross-department data sources are dispersed. Plugins must be used to call multiple system APIs to complete data pulling and verification. Tool calling must support cross-data source field mapping.
The monthly update frequency requires that the tool calling cache update cycle matches the business rhythm, to avoid using expired cross-department data.
Multiple types of documents have large structural differences. Tools must be configured to adapt to field extraction rules for different documents, to ensure complete information for declaration materials and case review.
Data verification results directly relate to assistance qualification determination. Tool calling outputs must retain complete traceability fields, to facilitate subsequent review and problem troubleshooting.

## Configuration Settings
This document applies to FastGPT v4.17.0 tool calling and plugin configurations.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` and bind the preset civil affairs review tool group | Adapt to multi-tool calling scenarios, automatically match the data sources or document processing tools required for the current review task |
| `functionCall` | Set to explicitly specify the calling format of review tools | Adapt to special review scenarios that require clear parameters |
| Document type adaptation switch | Enable multi-document recognition mode | Adapt to multiple review document structures such as minimum living standard allowance application forms and verification reports |
| Cross-data source mapping rules | Configure mappings based on cross-department shared fields | Align data field formats across systems such as public security and human resources and social security |
| Cache update cycle | 30 days | Match the monthly business update frequency, avoid using expired cross-department data |
| Single tool call wait time | 60 seconds | Adapt to the normal response time of cross-department APIs |
| Result traceability switch | Enable complete field traceability | Retain the original data sources and processing steps of tool calls, facilitate subsequent review |

## Three Common Misconfigurations
- Phenomenon: Image links returned after calling multimodal tools cannot be displayed in third-party systems, and fields are empty. Cause: The image link return format for tool calls is not configured, and recognition results are not packaged according to the `![] (/api/....)` rule.
- Phenomenon: Timeout errors occur when processing cases in batches, with a 504 status code. Cause: The cache update cycle is set too short, leading to frequent calls to cross-department system interfaces that exceed call limits.
- Phenomenon: Incomplete field information is extracted when reviewing household investigation forms. Cause: The document type adaptation switch is not enabled, so non-standard format household investigation document structures cannot be recognized.

## How to Confirm Proper Configuration
- Run a tool call test for a single minimum living standard allowance application form, check whether cross-department data for the corresponding household can be correctly pulled and field matching completed.
- Trigger a batch case review task, check logs to confirm that the tool call cache update cycle matches the set duration, and there are no records of frequent cross-department interface calls.
- View tool call traceability logs, confirm that each review result retains the original data source and processing steps.
- Test multimodal tool calls, confirm that the returned image link format can be properly parsed by third-party systems.
- After adjusting tool call parameters, verify that all types of review documents can be correctly identified and processed.
