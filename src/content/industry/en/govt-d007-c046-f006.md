# Social Assistance and Minimum Living Security Review: Application Materials and Case Review – Citation Source and Traceability

## What the data for this category looks like
The core documents for this category include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Data sources include the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax authorities, and other relevant departments. Data updates once per month. Document structure includes fields such as family population, income details, total property, and approval process. Some fields must align with format specifications for cross-department shared data.

## Constraints on citation source and traceability
The decentralized nature of cross-department multi-source data requires the citation traceability process to connect multiple knowledge bases, covering internal business documents and external shared data. The monthly update frequency requires regular knowledge base synchronization to avoid using expired family economic status data. Diverse document types and structured fields demand precise matching of original document fields and sources during traceability to ensure review accuracy. Errors directly lead to incorrect or missed assistance eligibility and public complaints, requiring citation content to be complete, traceable, and free of missing key review information.

## Configuration setup
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Adapts to the average text length of a single social assistance document, fully retaining key fields such as family income and member relationships |
| `responseData` | Enabled | Meets compliance requirements for tracing original materials during case review |
| `detail` | Enabled | Displays source system and update time of cited data, matching traceability specifications for civil affairs business |
| Knowledge base synchronization cycle | 30 days | Matches the monthly update frequency of data sources, ensuring knowledge base data is synchronized with official monitoring platforms |
| Single recall limit | Top 5 entries | Covers associated information for multiple types of review documents such as household survey records and public notice materials, avoiding redundant interference |
| Timeout threshold | 600 seconds | Prevents cross-department data query timeouts, adapting to recall delays for multi-source data |

## Three common configuration errors
- Symptom: After associating a local knowledge base, the citation list displays correct family economic status verification report entries, but the response body does not include this content. Cause: The `quoteMaxToken` value is too small, truncating core review fields, or knowledge base association permissions are not configured correctly.
- Symptom: When calling the API to access a private knowledge base, the returned results do not include document content such as household survey records. Cause: The single recall limit value is too low, failing to cover required review document types.
- Symptom: Traceability information does not label the cross-department system name of the data source. Cause: The `detail` parameter is not enabled, or an independent knowledge base classification is not configured for cross-department shared data.

## How to verify successful configuration
- Upload a sample minimum living security application form to the knowledge base, initiate a query containing "family income status", and check whether the response body includes the corresponding fields from the application form.
- View the citation list at the bottom of the response, confirm that each citation is labeled with the source document type and update time.
- Call the API to query knowledge base content, check that the returned results include source data fields and traceability information.
- Wait 30 days and check the knowledge base synchronization status, confirm that data is consistent with updates from official monitoring platforms.
