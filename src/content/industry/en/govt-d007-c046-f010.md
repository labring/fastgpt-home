# Social Assistance and Minimum Living Standard Guarantee Review: Application Materials and Case Review — Knowledge Base Retrieval and Recall

## Data Profile for This Category
This category of data is primarily sourced from daily work documents of civil affairs bureau assistance departments, sub-district and township civil affairs offices, community committees, and verification centers. Included documents are minimum living standard guarantee application forms, family economic status verification reports, household survey records, democratic appraisal minutes, public notice materials, and assistance approval forms. Data originates from low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Update frequency is monthly. Data fields include household income details, property status, member relationships, application reasons, and more. There are no unified fixed units, and fields adjust based on the format of specific application materials.

## Constraints for Knowledge Base Retrieval and Recall
Cross-department and cross-source shared data requires retrieval to support association recall across multiple datasets. This avoids review omissions caused by information silos.
Monthly update cycles require knowledge base synchronization tasks to run on a scheduled basis. This ensures data timeliness and accuracy.
Diverse document types require adaptation to different structures of forms, reports, and public notice materials. This optimizes chunking and retrieval matching logic.
Core fields focus on key review items such as household economy and member relationships. Retrieval weight must be configured specifically to improve accuracy.
Clear consequences of errors require a verification step for retrieval results. This prevents incorrect or missed guarantee issues caused by mismatched data.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Focuses on core review fields such as household economy and member relationships. This range filters low-match irrelevant materials and ensures review accuracy |
| `limit` | `Top 8–12 entries` | Case review covers multiple document types including application materials, verification reports, and household surveys. This quantity balances recall comprehensiveness and context length |
| `searchMode` | `vector + keyword` | Adapts to structured fields from cross-department shared data and unstructured review documents. Combines vector and keyword retrieval to improve matching precision for core fields |
| `usingReRank` | `Enabled` | Core fields have higher matching weights. Reranking further corrects biases from vector retrieval and filters the most relevant review materials |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands synonymous queries related to review work. For example, expanding "household income" to "family economic status" to cover more relevant materials |
| `collectionIds` | `Bind dedicated civil affairs assistance datasets` | Isolates dedicated data for this category to avoid confusion with other government affairs datasets, ensuring retrieval precision |

## Common Misconfigurations
- Retrieval throws the error `text index required for $text query`. This occurs when keyword retrieval index association is not configured correctly, or indexes are not rebuilt after dataset chunking.
- The number of retrieval results is far lower than expected. This happens when the `similarity` threshold is set too high, filtering eligible cross-department shared data.
- Retrieval results include irrelevant social security benefit materials. This occurs when `collectionIds` is not used to bind dedicated civil affairs assistance datasets, leading the retrieval scope to cover data from other government affairs categories.

## How to Verify Proper Configuration
- Manually input query terms containing household economic status and member relationships. Verify returned results cover core review documents such as minimum living standard guarantee application forms and family economic status verification reports.
- Access the retrieval configuration panel. Confirm that `usingReRank` and `datasetSearchUsingExtensionQuery` are both enabled.
- Trigger a temporary data synchronization task. Check system logs to confirm cross-department shared data has been successfully pulled and updated to the knowledge base.
- Test non-review query terms with low matching relevance. Confirm the `similarity` threshold effectively filters irrelevant results.

The values listed above are common starting points, and should be measured against the reader's own samples.
