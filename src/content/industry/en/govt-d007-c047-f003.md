# Administrative Penalty Case File Handling: Declaration Materials and Case File Review — Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for this category include administrative law enforcement case handling systems, law enforcement recorder footage, the National Enterprise Credit Information Publicity System, and departmental supervision databases. Update frequency is daily. Documents processed daily include on-site inspection records, interrogation records, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, and service receipts. Core work revolves around traceable evidence chains for illegal facts and penalty decisions. Case file fields across all law enforcement entities follow unified administrative law enforcement standard formats.

## Constraints on multi-turn dialogue and prompt engineering
The diversity of data sources requires dialogue systems to support context retrieval across multiple document types. Daily updated supervision data requires dialogues to associate real-time latest subject information. The structured characteristics of multiple case file documents require multi-turn dialogue to accurately bind exclusive information for a single case file, avoiding context confusion across cases. The strict requirements for evidence chains mean prompts must include fixed steps of evidence verification, discretion matching, and document standardization. Complete historical interaction records must also be retained to ensure audit process traceability and avoid audit errors caused by missing information.

## How to configure settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current case file, 10–20 characters in length | Distinguish dialogue contexts for different administrative penalty case files, avoid cross-case information confusion |
| `messages` | Append in the order of case file documents, retain 1000–1500 characters of historical interactions | Cover core materials and review processes for a single case file, avoid context overflow |
| `variables` | Pass three fixed fields: case file number, law enforcement entity, and violation type | Allow prompts to accurately match exclusive information for the current case, reduce verification errors |
| Maximum context size | 8000–12000 tokens, calibrated based on actual testing | Adapt to the total length of multiple documents for a single case file, ensure complete context for review dialogues |
| Question optimization | Enabled, restructure user queries in accordance with law enforcement document standards | Convert colloquial review requests into expressions compliant with administrative law enforcement requirements, improve prompt matching accuracy |
| Single search limit | Top 6 recall results | Match the number of core evidence items for a single case file, avoid redundant information interfering with review |

## Three common misconfigurations
- Symptom: Multi-turn dialogue cannot follow up on previous case file review questions, and each query requires repeating case information. Cause: The `chatId` parameter is not correctly bound, resulting in independent context instances being created for each dialogue, losing historical interaction records.
- Symptom: Review suggestions generated by prompts do not match the exclusive information of the current case file. Cause: Fixed fields such as case file number, law enforcement entity, and violation type are not passed via `variables`, so prompts cannot accurately call document data for the corresponding case.
- Symptom: Dialogue return results include irrelevant non-case-file information. Cause: No reasonable single search limit is set, resulting in recall of excessive irrelevant supervision data that interferes with review judgments.

## How to confirm correct configuration
- Initiate a new case file review dialogue, check that the bound identifier matches the unique identifier of the current case file, to ensure context is not confused.
- Call the dialogue interface, review that historical interactions and core document fragments are included in the context, to confirm complete information.
- Pass test exclusive case fields, verify that prompts can accurately match the passed information and generate compliant review content.
- Initiate two or more rounds of interaction, check that the dialogue can follow up on previous questions without requiring repeated explanation of basic case information.
