# Administrative Penalty Case File Handling: Declaration Materials and Case Review - Citation Source and Traceability

## What the data for this category looks like
This category serves law enforcement agencies including market supervision and ecological environment departments. Data comes from administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information publicity system, and departmental supervision databases. The update frequency is daily.
Daily documents include on-site inspection records, interrogation transcripts, evidence lists, prior administrative penalty notification letters, and penalty decisions. Their structures cover fields such as illegal fact determination, discretionary benchmark citation, document number, and service records.
Law enforcement recorder footage is unstructured video data. Document-type materials are structured text data, with fields including standardized law enforcement subject identifiers and illegal timestamps.

## Constraints on Citation Source and Traceability
The data characteristics of this category impose multiple constraints on the citation source and traceability process. Structured law enforcement documents and unstructured law enforcement recorder footage coexist. This requires simultaneous support for precise text fragment matching and multimedia association verification.
Daily updated data sources require configuring recall logic adapted to incremental synchronization to avoid citing expired or duplicate data.
Law enforcement documents contain unique identifier fields. Traceability must be strictly bound to the corresponding identifiers. Otherwise, penalties may be revoked, administrative reconsideration may result in loss, or case file review may fail.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average text length of a single law enforcement document, avoids truncating critical traceability information |
| Maximum number of recall entries | Top 5 entries | Aligns with the range of associated evidence quantities for single case file review, avoids redundant information interfering with the review process |
| `responseData` | Enable citation source display | Mandatorily returns traceable document identifiers and fragments, meets the traceability requirements for case file archiving |
| Similarity threshold | 0.75–0.85 range | Adapts to the matching accuracy of professional terminology in law enforcement documents, filters low-correlation non-law enforcement data |
| `detail` | Enable full traceability information | Displays the specific location of cited fragments and source document numbers, facilitates case file review and verification |

## Three Common Configuration Errors
- When configuring a knowledge base search node in a workflow, selecting a knowledge base as a variable reference but failing to pass parameters correctly. This results in empty return results or non-law enforcement related content. The cause is failure to correctly bind the value range of the knowledge base variable during API calls, or the variable not matching the access permissions of the corresponding law enforcement data source.
- The chat interface first returns a citation list without sorting according to law enforcement priority. This prevents reviewers from quickly locating core evidence. The cause is failure to configure the `detail` parameter to adjust the citation sorting logic; the default sorting does not arrange documents by the importance of law enforcement documents.
- After associating a local law enforcement knowledge base, the returned results do not include local documents, and the citation list shows external irrelevant data. The cause is failure to correctly configure the data source synchronization range of the knowledge base, resulting in documents from the local law enforcement case handling system not being included in the recall pool.

## How to Confirm Proper Configuration
- Initiate an API call with the knowledge base variable, check if the FastGPT v4.17.0 workflow node correctly loads the corresponding law enforcement data source, and verify that the returned results include document fragments from the local knowledge base
- View the returned `responseData` field, confirm that it includes the document number and fragment location of the citation source, and match the unique identifier of the law enforcement document
- Test a query associated with law enforcement recorder footage, check if corresponding multimedia traceability information is returned
- Adjust the `quoteMaxToken` parameter, verify that the returned citation fragments do not truncate critical content

The values provided are common starting points and should be measured against the reader's own samples.
