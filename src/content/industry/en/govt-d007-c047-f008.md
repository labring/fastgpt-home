# Administrative Penalty Case File Handling: Declaration Materials and Case Review — Document Parsing and Chunking

## Data Profile for This Category
This category of data originates from administrative law enforcement case systems, law enforcement recorder footage, national enterprise credit information publicity systems, and departmental supervision databases of law enforcement agencies including market supervision, ecological environment, and transportation. Daily processed documents include fixed-format files such as on-site inspection records, interrogation transcripts, evidence lists, prior administrative penalty notification letters, and penalty decisions.
Data updates occur daily. Most documents are a mix of structured and semi-structured content, containing fixed fields including law enforcement officer information, party subject information, illegal facts, penalty basis, and document number. No custom non-standard fields are included.

## Constraints Imposed on Document Parsing and Chunking
Most documents come from law enforcement case systems and law enforcement recorder footage, and include scanned files and image-based PDFs. Parsing processes must support non-pure text formats.
Fixed-format documents require chunking to preserve complete document units. This avoids splitting core sections such as penalty decision numbers and illegal fact paragraphs across different chunks. List-style documents such as evidence lists require retaining entry relevance, to prevent splitting explanations for the same evidence.
Daily high-frequency data updates require parsing processes to have low latency. This prevents impacts to law enforcement case handling progress. Additionally, case file traceability requires retaining inter-document associated metadata after chunking. This enables quick location of corresponding evidence and documents during review.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Most documents in this category are fixed-format law enforcement documents. Each chunk must accommodate complete illegal fact paragraphs or core content of a single transcript, to avoid splitting critical information |
| `chunkSplitter` | Split by document paragraphs | Documents in this category have clear structural formatting. Splitting by paragraphs preserves the integrity of law enforcement logic, and adapts to context association needs for subsequent case review |
| `customPdfParse` | Enabled | This category includes scanned PDFs generated by law enforcement recorders and non-standard format law enforcement documents. Enabling custom parsing supports text extraction for multiple document types |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | A single law enforcement case file may include multiple associated documents. Sufficient parsing time must be reserved to avoid parsing failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Law enforcement case files may include high-definition law enforcement recorder footage and multiple scanned documents. This setting accommodates upload and parsing of large-capacity files |
| `chunkSettingMode` | Manual configuration | Documents in this category have uniform structures but require minor custom adjustments. Manual configuration enables precise matching of chunking logic for law enforcement documents |

## Three Common Configuration Mistakes
- Symptom: After uploading an administrative penalty case file PDF, a parsing timeout prompt appears, with a 504 status code returned. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted. The default duration is insufficient to parse a complete case file containing multiple scanned documents.
- Symptom: After importing an Excel-format law enforcement officer ledger, some fields are empty. Cause: `customPdfParse` was not enabled to adapt to semi-structured tables. The default parsing logic cannot recognize special format fields in the ledger.
- Symptom: When submitting a plain text question to the knowledge base, the system triggers a document parsing process. Cause: `chunkSettingMode` was not configured correctly. The general question-and-answer mode was mistakenly set to document parsing only mode, causing parsing logic to trigger for non-document queries.

## How to Verify Correct Configuration
- Upload a law enforcement transcript PDF that includes scanned content, and check if the parsed text fully extracts handwritten or printed content from the transcript.
- Upload a single penalty decision document, and verify that the chunking result retains complete illegal fact paragraphs within a single chunk, with no cross-chunk splitting.
- Check system logs to confirm that no timeout errors occur when uploading case files under 1000 MB.
- Submit a plain text question, and confirm that the system does not trigger a document parsing process, and directly returns a question-and-answer result.
