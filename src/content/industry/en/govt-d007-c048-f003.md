# Administrative Licensing Approval: Declaration Materials and Case Review — Multi-turn Dialogue and Prompting

## What this category of data looks like
This category of data is primarily sourced from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository. The update frequency is daily. Daily documents include service guides, application forms, commitment letters, acceptance notices, correction notices, administrative licensing decision documents, and license certificates. Data is bounded by legally defined licensing items, and includes fields such as item codes, application material details, handling conditions, and legal basis. No custom special units are used, and all fields follow unified government service specifications.

## Constraints on multi-turn dialogue and prompting workflows
The daily update feature of the data requires that prompt configurations support regular synchronization of the latest administrative licensing item lists and service guides, to avoid using expired rules. There are diverse document types, so multi-turn dialogue must sequentially identify the field requirements of different documents such as application forms and correction notices. Prompts must clearly define the verification logic for each document. Data is bounded by legally defined items, so multi-turn dialogue must strictly match the legal basis and handling conditions, and cannot arbitrarily adjust review standards. The need to retrieve electronic certificates across departments requires that the multi-turn dialogue process clearly define data retrieval permissions and format requirements, to ensure compliance with government data security specifications.

## Configuration guidelines
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Conversation context window | Previous 10 turns of dialogue + most recent 8000 characters | Administrative licensing material review requires tracing multi-round correction communication records. An overly long window will introduce irrelevant information, so this setting is calibrated based on actual testing |
| Prompt template | Bind exclusive verification rules for the corresponding administrative licensing item | Must match the legal basis and material list of the item to ensure compliance of the review logic |
| `variables` | Call the handling condition fields from the daily updated item database | Data is updated daily, so the latest handling requirements must be pulled in real time |
| `messages` | Splice current materials and historical communication content by dialogue turn | Ensure each round of review is based on the complete current application status |
| `chatId` | Bind the unique code of the current item | Ensure multi-turn dialogue is bound to the corresponding administrative licensing item to avoid confusion across items |
| Knowledge base recall limit | Top 5 matching results | Government affair item rules are clear, excessive recall will interfere with review judgments |
| Timeout setting | 600 seconds | Cross-departmental certificate retrieval requires sufficient response time, which meets the conventional time limit requirements for government affairs handling |

## Three common configuration mistakes
- Phenomenon: The generated content of the AI dialogue node is directly displayed in the front-end dialog box, and cannot be received and processed by subsequent text splicing components. Cause: The output route of the dialogue node is not configured, and the model response content is returned directly by default.
- Phenomenon: The annotation fields added in the dialogue log cannot be called in subsequent workflow nodes. Cause: The annotation content is not bound to the `variables` parameter, resulting in context data not being passed to downstream nodes.
- Phenomenon: After the knowledge base retrieval results are passed to the AI dialogue node, they cannot be used for verification and matching of declaration materials. Cause: The retrieval data is not passed in accordance with the standard field format of the government affair item database, resulting in the model being unable to identify the corresponding verification rules.

## How to verify correct configuration
- Trigger a simulated correction notice generation process, and check whether the dialogue context contains complete information of historical application materials and correction requirements.
- Call the `variables` parameter to check whether the daily updated administrative licensing item handling condition fields are bound, and confirm that the data source is the national integrated government service platform item database.
- Submit a test application form, and check whether the AI review output only includes verification conclusions that comply with legal basis, with no irrelevant redundant information.
- After configuring the timeout time, simulate the waiting scenario for cross-departmental certificate retrieval, and confirm that the node completes the response within 600 seconds without triggering a timeout error.
