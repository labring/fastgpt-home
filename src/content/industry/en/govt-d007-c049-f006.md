# Declaration Materials and File Review for Legality Review of Regulatory Documents: Citation Sources and Traceability

## What this category of data consists of
The core documents for this category include regulatory document drafts, drafting explanatory notes, legality review opinions, solicited opinion summaries, and filing reports. Data sources cover regulatory and rule repositories, higher-level law databases, departmental policy document repositories, and the administrative regulatory document filing system. Update frequency is irregular. The core fields of document structure are clauses, explanations, and review conclusions. There are no unified fixed unit fields. Most content consists of abstract policy rule texts, focusing on various materials related to review of legislative authority, procedures, and clause legality.

## Constraints Imposed by These Data Characteristics on Citation Sources and Traceability
Data sources are scattered and updates have no fixed cycle. To ensure traceability can match the latest regulatory policy versions, real-time indexes from multiple source databases must be connected synchronously. Most documents are abstract rule texts, so the higher-level legal basis corresponding to a clause must be accurately located. As a result, traceability results must strictly match clause levels. The seriousness of filing and review processes requires that traceability information can be traced back to the original system, with no empty citations or permission issues. Additionally, file review needs to link cross-references across multiple materials, so the number of single traceability results must be limited to avoid information overload that reduces review efficiency.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the context length of a single clause in regulatory documents, ensuring cited content is complete and does not exceed model context limits |
| Rerank configuration | Enabled, use a general legal domain fine-tuned version, threshold set to 0.75–0.85 based on actual testing | This category of documents is mostly professional legal texts; enabling reranking improves recall accuracy of relevant segments and adapts to professional semantic matching needs |
| Single search limit | Top 8 results | Avoids excessive irrelevant content returned by multi-source data, adapting to the precise traceability requirements of file review |
| Maximum context | 16000 characters | Accommodates traceability content from multiple associated materials, meeting information needs for cross-review |
| `responseData` | Enable returning original source fields | Ensures traceability information can be linked to original records in the administrative regulatory document filing system |
| `detail` | Enable full citation | Displays original clause text and source references, meeting the rigor requirements of legal review |

## Three Common Misconfigurations
- Symptom: Empty citations appear after enabling rerank, or no matching segments are found in search results. Cause: The rerank model has not been fine-tuned for legal professional texts, or the rerank threshold is set too high, filtering out valid relevant reference segments.
- Symptom: Imported plugins fail to load after exporting and importing a workflow. Cause: The corresponding regulatory database connection keys and permissions have not been synchronized in the new environment, or the associated parameters of the original data source are not retained in the workflow configuration.
- Symptom: "No permission to operate this conversation record" is displayed at the end of the response paragraph, and citation display cannot be canceled. Cause: The mandatory citation display switch has not been turned off, or the dialogue permission configuration restricts editing permissions for traceability information.

## How to Verify Correct Configuration
- Upload a single regulatory document draft, trigger traceability verification, and check returned citation segments to confirm they match corresponding higher-level law clauses.
- Adjust the `quoteMaxToken` parameter, and verify whether the truncation or full display of cited content meets expectations.
- Import a test workflow, and confirm that the associated regulatory database plugin can be called normally and returns traceability data.
- View the citation identifier at the end of the response, and confirm whether the display status can be controlled via the configuration switch.
