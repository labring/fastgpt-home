# Financial Expenditure Performance Evaluation: Declaration Materials and File Review - Workflow Orchestration

## What data looks like for this category
Data sources for this category include the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Commonly processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Fields cover performance target details, fund usage details, output effect data, and rectification status. Only standard fields for each document are associated based on business logic, with no additional custom statistical values.

## Constraints on workflow orchestration
The annual update cycle requirement mandates that workflows trigger on a fixed annual schedule. This avoids unnecessary high-frequency execution and reduces resource consumption. Multiple data sources require configuring cross-system data pull nodes to ensure consistent verification of data from budgets, payments, ledgers, and other sources. The need to process multiple document types requires splitting verification nodes for each document type. These nodes separately check performance target matching and the correspondence between fund expenditures and performance targets. Clear error consequences require configuring interception rules at key verification links. This prevents unqualified materials from entering subsequent processes and affecting evaluation results.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable settings | Bind fixed values such as annual performance cycles and unit codes | Adapt to the annual update rhythm of business data and reduce repeated configuration |
| Node ID configuration | Assign a unique `nodeId` by document type | Distinguish verification processes for different documents and avoid node configuration conflicts |
| Timeout threshold | 600 seconds | Match the typical response duration of cross-system data pulls |
| Data source synchronization frequency | Trigger once annually in advance | Align with the actual situation where business data is only updated annually |
| Verification rule trigger condition | Trigger at the material submission node | Ensure verification runs after materials are fully uploaded |
| Variable transfer rule | Enable global `variables` transfer | Uniformly pass performance indicators and fund data to each verification node |

## Three common configuration errors
- A configuration error prompt appears after entering the workflow. The cause is failure to mount the workflow configuration directory during Docker deployment, which prevents node dependency files from loading properly.
- Subsequent components cannot retrieve updated values after global variables are modified. The cause is failure to enable the real-time synchronization switch for `variables`, which delays variable cache updates.
- Workflow import fails. The cause is that the imported file format does not match the FastGPT v4.17.0 workflow export specification, and required node configuration fields are missing.

## How to confirm the configuration is complete
- Manually trigger the workflow, and verify that each node’s data source can pull document data from the corresponding system normally.
- Adjust global variable values, and confirm that subsequent nodes can retrieve the updated variable content.
- Import the preset performance review workflow template, and check that node configurations are complete and free of errors.
- Simulate submitting a complete performance declaration material, and confirm that the workflow triggers verification links according to preset rules.
