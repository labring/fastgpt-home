# Declaration Materials and Case File Review for Fiscal Expenditure Performance Evaluation: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from the budget management integrated system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Documents processed daily include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Data fields cover project performance targets, fund usage details, output effect verification, rectification measures, and more. There are no fixed unified standard units; field meanings must be matched to specific project scenarios. The data volume of a single case file fluctuates with project scale.

## What constraints these characteristics impose on the tool calling and plugins link
The annual update feature requires tool calling to only trigger during declaration and review cycles, with no continuous scheduled runs, to avoid invalid resource consumption. Multiple data sources require plugins to adapt to different interface formats such as the budget management integrated system and business ledgers, and require configuration of cross-system data pulling adaptation rules. Diverse document types require tool calling to support multi-format file parsing, and dedicated tools must be designed for association verification between performance targets and fund expenditures, to ensure verification logic matches business rules. Additionally, case file review requires association of multi-dimensional data, so tool calling must support batch data comparison to reduce error risks from single-item data processing.

## Three common misconfigurations
- Configuring scheduled tasks to trigger tool calls continuously. Symptoms: The system generates call logs continuously, with no pattern tied to business triggers. Cause: Did not match the annual update business rhythm, incorrectly set high-frequency scheduled tasks, leading to invalid calls consuming resources.
- The large model returns results that do not match the performance evaluation business requirements, failing to meet expected outcomes. Symptoms: The model does not correctly associate performance target and fund expenditure data. Cause: Did not correctly configure the `functionCall` parameter to limit the tool calling scope, causing the model to deviate from the dedicated verification logic.
- Unable to view failure logs for large models or tool calls. Symptoms: No corresponding log records after a call fails, or logs have been cleared. Cause: Did not enable log retention configuration, or set the retention duration too short, causing logs to be automatically cleaned up.

## How to confirm configurations are properly set
- Trigger a tool call, verify that the pulled data comes from specified data sources such as the budget management integrated system and project declaration materials.
- View tool call logs, confirm that the trigger timing matches the declared cycle settings, with no invalid scheduled trigger records.
- Test the tool call process for a single case file, confirm that the returned verification results cover the association verification links for performance targets, fund expenditures, and supporting materials.
- Check the `toolChoice` and `functionCall` parameter configurations, confirm they adapt to the tool types required for the current business, with no parameter errors causing call failures.
