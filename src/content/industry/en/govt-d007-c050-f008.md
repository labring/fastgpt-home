# Fiscal Expenditure Performance Evaluation Declaration Materials and File Review: Document Parsing and Chunking

## What this category of data looks like
The core data for this category comes from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Commonly processed documents include performance target forms, self-evaluation forms, performance evaluation reports, supporting material lists, and rectification reports. These cover structured tables, long-text descriptions, and itemized list structures. Fields include project identifiers, performance indicators, fund amounts, supporting document numbers, and more. Some documents are exported from systems, while others are manually filled electronic files with significant format differences.

## What constraints these characteristics impose on the "document parsing and chunking" link
The annual centralized update requirement means the parsing process must support batch processing of all documents for a single year, to avoid overloading during single parsing. Documents with multiple types and large format differences require parsing logic that adapts to both structured tables and free text, to prevent splitting the association between performance indicators and their corresponding supporting explanations. Since verifying the correspondence between fund expenditures and performance targets is a core time-consuming step, chunking must retain contextual associations between fields. It cannot separate indicators from their corresponding fund data or supporting materials, as this will directly affect subsequent review and scoring results.

## How to set the configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Ensures semantic integrity for long texts such as performance evaluation reports and self-evaluation forms, avoids splitting performance indicators from their corresponding supporting explanations |
| `chunkSplitter` | Split by paragraph + heading hierarchy | Matches the structure of multiple document types, retains the table titles and row-item association relationships of performance target forms |
| `customPdfParse` | Enable structured table parsing | Adapts to PDF tables exported from the unified budget management system, accurately extracts performance indicator and fund allocation data fields |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch import of annual supporting material packages and complete performance evaluation reports |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing large-volume performance evaluation reports, avoids timeout interruptions |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types, adapts to the short-text chunking requirements of supporting material lists |

## Three common misconfigurations
- Symptom: Embedded images in parsed PDFs are not extracted, or cannot display image content in the large model context. Cause: The image extraction switch for custom PDF parsing is not enabled, only text content is extracted without capturing embedded images.
- Symptom: An error prompts when importing a publicly shared Yuque link, indicating that parsing failed. Cause: The link is not confirmed to be publicly accessible, or the shared format is not supported by the platform. Some links with restricted permissions cannot be parsed normally.
- Symptom: HTTP tool calls have normal parameter parsing but do not execute the corresponding operations. Cause: Correct request headers or request body formats are not configured, or access permissions for the target interface are not enabled.

## How to confirm the configuration is complete
- Upload a typical performance evaluation report PDF, check if the parsed result retains the row-column structure of the table and core field content.
- Upload a supporting material PDF containing embedded images, confirm that the parsed result includes extracted image content or placeholder identifiers.
- Import a compliant publicly shared Yuque link, check if page content loads normally and parsing is completed.
- Set `PARSE_FILE_TIMEOUT_SECONDS` to 600 seconds, upload a 500MB test document, check that no timeout error occurs during parsing.

The values provided are common starting points and should be measured against the reader's own samples.
