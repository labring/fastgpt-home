# Department Final Accounts and Financial Report Submission Materials and File Review: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category comes from four systems: unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Content covers actual revenue and expenditure, asset and liability status, and budget execution difference explanations. Fields follow fiscal business specifications, including standardized items such as unit code, revenue and expenditure details, and original asset value.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
The annual update feature requires interface call frequency to match the business cycle. High-frequency triggering should be avoided. The need to connect multiple system data sources means the interface must support cross-system data pulling and format conversion. It must adapt to structured reports and unstructured explanatory documents returned by different systems. Documents include standardized fields and difference explanation content, so the interface must verify field integrity and format compliance. This avoids errors in the review link caused by data format mismatches. Single-call business data volume is large, so the interface must configure reasonable timeout thresholds and shard transmission rules. This prevents transmission interruptions.

## How to Configure Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {FastGPT-assigned API key}` | Follows HTTP interface authentication standards to ensure permission legitimacy for external system calls |
| `variables` | `{"target_year": "202X", "unit_code": "XXX"}` | Passes core business parameters such as year and unit code, adapts to fixed verification logic for final account review |
| Single call timeout threshold | 600 seconds | Matches the transmission and parsing time of annual final account data, avoids task interruption due to timeout |
| `responseData` | Structured format mapped to fiscal report fields | Directly matches field parsing requirements for subsequent file review, reduces secondary data processing |
| Allowed document types | docx, xlsx, pdf | Covers business document types such as daily submitted final account statements and explanatory documents |

## Three Common Errors
- A 401 Unauthorized status code is returned when calling the interface, caused by the `Authorization` parameter not being carried correctly or the assigned API key expiring.
- Local documents cannot be uploaded when calling the API, but can be uploaded and analyzed normally in the chat interface, caused by the interface not being configured with parsing types matching business documents, or not passing document-related business identification parameters via `variables`.
- A format unsupported error is returned when calling the content interface, and the corresponding link can be downloaded normally when accessed via a browser, caused by the interface not being correctly configured with parsing rules for document types, or the request header not declaring the correct content type.

## How to Confirm the Configuration Is Complete
- Initiate a test call with a valid `Authorization` parameter and business `variables`, confirm that the returned HTTP status code is 200.
- Upload department final account statement documents, verify that the `responseData` returned by the interface can parse business fields such as unit code and revenue and expenditure details.
- Simulate a cross-system data pulling scenario, check that the interface does not trigger abnormal interruptions due to excessive data volume.
- Check the document types configured for the interface, confirm that they include daily submitted final account-related file formats.
