# Declaration Materials and File Review for Department Final Accounts and Financial Reports: Workflow Orchestration

## What data for this category looks like
This category of data originates from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update cycle is annual. Commonly processed documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Fields cover income and expenditure details, asset and liability balances, budget execution difference explanations, and similar items. Common units are yuan and ten thousand yuan. Document formats primarily combine structured tables and explanatory text.

## What constraints these characteristics impose on the "workflow orchestration" link
The annual update cycle requires workflows to support centralized scheduling and processing of batch annual data, and reserve resource space for batch node execution. Data from multiple systems requires configuring cross-system data pulling and standard alignment steps in the workflow to ensure unified data format across exported files from different systems. The mixed document structure of structured reports and explanatory text requires workflows to support both structured field extraction and unstructured text parsing nodes. Diverse field units require configuring unit conversion rules in the data verification link to avoid audit rejection caused by inconsistent standards.

## Three common mistakes
- Symptom: The workflow runs with a prompt "The specified knowledge base was not found", returning status code 404. Cause: The knowledge base identifier was not passed via the `variables` parameter during API calls, causing the node to fail to match the corresponding knowledge base scope.
- Symptom: The text content extraction node fails to run, with the interface displaying "Model parsing exception". Cause: The single processing length was not adjusted for the long-text structure of final account documents, causing the model to fail to fully parse paragraph content.
- Symptom: The database query node times out, and the task status changes to failed. Cause: A reasonable timeout duration was not configured, failing to adapt to the time-consuming requirements of annual batch data queries.

## How to confirm the configuration is complete
- Trigger an API call, pass test `variables` parameters, check if the workflow automatically matches the corresponding knowledge base.
- Upload a standard final account document, run the text content extraction node, check if the parsing result covers the core fields of the document.
- Perform a database query test, confirm that the task completes within the preset duration with no timeout errors.
- Submit multiple test files, check if the workflow executes node tasks in the order of submission.
