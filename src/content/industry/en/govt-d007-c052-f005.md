# Declaration Materials and File Review for Department Final Accounts and Financial Reports: Tool Calling and Plugins

## What this category's data looks like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. It is updated on an annual cycle. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Data fields cover revenue and expenditure details, asset and liability balances, budget execution difference explanations, and more. Units are mostly yuan or ten thousand yuan. Some reports require summarizing subordinate unit data by hierarchy.

## What constraints these characteristics impose on tool calling and plugin workflows
The annual update requirement means tool calling must support batch historical data pulling and incremental verification to avoid repeated calls to high-frequency system interfaces. Multiple data sources require plugins to configure multi-data source adaptation logic, ensuring consistent field formats when synchronizing data from different systems. Complex document structures and hierarchical summarization needs mean tool calling must support nested data parsing and summary calculations, while retaining original data traceability capabilities. Clear error consequences mean tool calling must add a pre-verification step to prevent incorrect data from entering the review process.

## Three common configuration mistakes
- A `The dollar ($) prefixed field '$schema'` error is returned during calls. This occurs because metadata fields are not properly filtered in plugin configuration, causing non-business fields to be passed into the tool calling workflow.
- A 400 parameter error is returned by the interface when calling via curl. This occurs because the request body is not encapsulated according to FastGPT v4.17.0 interface specifications, and the `application/json` request header is not correctly configured.
- Tool calling fails to access a data source bound to a preset environment variable. This occurs because the environment variable permission switch is not enabled in the tool calling configuration, preventing the model from accessing required system data.

## How to confirm configuration is complete
- Initiate a simulated call, check if the returned structured data includes core fields of department final account statements, such as revenue and expenditure details, asset and liability balances, and more.
- Review tool calling logs to confirm that the `toolChoice` and `functionCall` parameters take effect as configured, with no abnormal parameter errors.
- Verify the multi-data source synchronization function, confirm that data formats from the unified budget management system and centralized treasury payment system are consistent, with no missing fields.
- Trigger abnormal data verification, check if the pre-verification step correctly intercepts non-compliant financial data.
