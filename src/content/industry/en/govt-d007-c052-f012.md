# Department Final Accounts and Financial Report Submission Materials and File Review: Deployment and Upgrade

## What the data for this category looks like
Data for this category originates from the integrated budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency follows an annual cycle. Daily processed documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. These documents cover actual revenue and expenditure, assets and liabilities, and budget execution difference explanations. Data fields strictly align with fiscal accounting standard specifications, use a fixed format, and must meet unified submission requirements.

## Constraints Imposed on Deployment and Upgrade by These Characteristics
The annual update nature of this category requires sufficient historical data storage capacity to be reserved during deployment. During upgrades, compatibility with previous years’ report formats and field rules must be maintained to prevent historical data from becoming unreviewable due to format changes. The need for multi-system data source access requires configuration items to support independent setup of multiple database connection parameters, to avoid mixing fiscal data from different systems. Fixed-format submission documents require preset field validation rules during deployment, to ensure subsequent review links can automatically identify format anomalies and missing fields. The severity of potential errors requires a rollback mechanism to be retained during upgrades, to prevent configuration changes from affecting already launched review processes and ensure normal progress of annual final account work.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://username:password@host:port/fastgpt?authSource=admin` | Stores annual batch final account statements and difference explanation documents; requires an independent database instance with permission verification enabled |
| `PG_URL` | `postgresql://username:password@host:port/financial_db?sslmode=require` | Stores centralized treasury payment data and accounting details; supports complex associated queries |
| `DB_MAX_LINK` | `200–300 concurrent connections` | Adapts to concurrent data reading requirements for annual batch reviews, prevents connection pool exhaustion |
| `FE_DOMAIN` | `https://financial-audit.internal` | Adapts to office scenarios on budget unit local area networks; configures a unified access entry |
| `ROOT_KEY` | `Randomly generated 32-bit secure string` | Sets administrator privilege access keys, prevents unauthorized configuration changes |
| `STORAGE_S3_ENDPOINT` | `Compliant cloud storage endpoint address` | Stores batch-submitted document attachments, meets compliance requirements for fiscal data storage |

## Three Common Errors
- Phenomenon: After deployment, 127.0.0.1 can access the service normally, but local area network IP addresses cannot load the page. Cause: `FE_DOMAIN` is not correctly configured to a domain name or IP accessible on the local area network, or firewall rules for the corresponding port are not opened.
- Phenomenon: Database connection timeout errors occur after starting the service, and final account data cannot be retrieved. Cause: `DB_MAX_LINK` is set too low, or permission configuration for `MONGODB_URI` is incorrect, failing to support annual batch data reading requirements.
- Phenomenon: Some previous years’ report files cannot trigger the review process after an upgrade. Cause: The original field validation rules were not retained during the upgrade, or previous years’ report formats were not compatible, resulting in field matching failures.

## How to Confirm Proper Configuration
- Run database connection test scripts to verify that configurations for `MONGODB_URI` and `PG_URL` can normally read business data from corresponding systems.
- Check firewall and network policies to confirm that the port corresponding to `FE_DOMAIN` is open, supporting access from local area networks and specified networks.
- Upload a sample final account statement from a previous year to trigger the validation process, confirming that field recognition and rule matching work normally.
- Perform a rollback test to verify that the rollback mechanism during the upgrade works correctly, ensuring that the original state can be restored if configuration changes fail.

The values provided are common starting points and should be measured against the deployment’s own sample data.
