# Department Budget Preparation: Declaration Materials and File Review — Multi-turn Dialogue and Prompting

## What Data for This Category Looks Like
The data for this category primarily comes from the unified budget management system, departmental staffing system, prior-year final accounts, project library, and the Ministry of Finance's annual budget preparation notice. The update frequency is annual. Commonly processed documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and more. Fields include staffing headcount, project expense amount, performance indicator values, unit codes, and other relevant items. Units of measurement include ten thousand yuan, person, project number, and others.

## What Constraints Do These Characteristics Impose on the Multi-turn Dialogue and Prompting Link
Annually updated data requires that conversation context be strictly limited to the current declaration year to avoid confusion across annual data sets. Multiple data sources require prompts to explicitly specify the scope of systems to call, preventing the retrieval of irrelevant data. Document fields are subdivided and have distinct differences; multi-turn dialogue must gradually guide users to clarify specific fields and parameters to reduce review errors. Error outcomes are directly linked to budget approval results, so required field verification logic must be integrated into conversations to ensure complete declaration materials.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Session Identifier | Bind the `chatId` parameter, generate a unique value per budget declaration batch | Avoid confusion across declaration batches, aligns with the business logic of departmental budget declarations by annual batches |
| Context Window | 8000–12000 characters | Accommodate annual budget documents, declaration materials, and complete historical conversation for a single year |
| Dynamic Variables | Bind the `variables` parameter, pass budget unit code and declaration year | Limit conversation scope to the specified unit and year, narrow data retrieval scope |
| Conversation Output Filter | Configure the `messages` parameter to only retain interaction content from the current stage | Prevent redundant replies from multi-node workflows from appearing in the chat interface |
| Prompt Template | Include data source scope and required field verification logic | Explicitly call documents from specified systems, guide users to supplement missing declaration fields |
| Turn Limit | Set based on actual testing | Adapt to the conversation length for annual budget review, avoid excessive length leading to timeouts |

## Three Common Misconfigurations
- Symptom: Replies from multiple AI dialogue nodes in the workflow are all displayed in the final chat interface. Cause: The `messages` parameter was not configured to filter output from non-current stages, resulting in redundant content being included in the context.
- Symptom: Only a single question can be initiated each time, making multi-turn question-and-answer and follow-up questions impossible. Cause: No follow-up question guidance logic was added to the prompt, and the `variables` parameter was not bound to dynamically adjust conversation branches.
- Symptom: A timeout error occurs after the conversation is initiated. Cause: A reasonable context window upper limit was not set, causing the system to load excessive historical documents and conversation content beyond the processing threshold.

## How to Confirm Successful Configuration
- Initiate a budget declaration query that includes cross-year information, verify that the system automatically limits results to the current declaration year.
- Trigger multiple AI dialogue nodes in the workflow, verify that only replies from the current stage appear in the chat interface.
- Check that dynamic variables such as the specified budget unit code and declaration year are bound in the conversation configuration.
- Initiate multi-step progressive review questions, verify that the system can gradually guide users to supplement missing declaration fields.
