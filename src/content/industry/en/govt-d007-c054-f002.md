# Declaration Materials and File Review for Flood Prevention, Disaster Mitigation and Emergency Duty: Vector Models and Indexes

## What this category of data looks like
Daily data for emergency duty and flood prevention scenarios includes duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources include weather warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Updates occur daily. Documents contain quantified fields with units, such as millimeters of rainfall and metric tons of materials. Some documents are multimodal, mixing text and monitoring screenshots.

## What constraints these characteristics impose on vector models and indexing
Multi-source heterogeneous data sources require indexing to support vector alignment across systems. This prevents semantic deviation between identical document types from different sources. Daily data updates require configuring incremental indexing mode. This avoids resource consumption and long indexing delays caused by full reindexing. Document lengths vary widely. Short duty logs of just a few dozen characters sit alongside thousand-word consultation minutes. This demands flexible chunking strategies to fit different document lengths. Quantified fields with units require retaining unit information during vector encoding. This ensures semantic consistency during retrieval. Multimodal documents require vector models that support mixed text and image encoding.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Fits the length of consultation minutes, rapid disaster reports and similar documents. Avoids information overload in single chunks. |
| Overlap Length | 100–150 characters | Maintains coherent context across chunks. Works well for regularly updated duty logs. |
| `maxToken` | 4096 token | Matches the input limit of mainstream vector models. Supports concatenation of chunks from long documents. |
| `defaultToken` | 256 token | Balances single-chunk vector accuracy and retrieval recall efficiency. |
| Similarity Threshold | 0.72–0.78 | Distinguishes valid warning information from irrelevant historical records. Meets high-confidence requirements for emergency scenarios. |
| Single Search Limit | Top 10 results | Quickly locates core disaster data. Prevents redundant information from interfering with emergency decision-making.

## Three Common Misconfigurations
- Phenomenon: Document indexing takes longer than 30 minutes. The interface displays "Indexing" with no progress updates. Cause: Incremental indexing mode is not enabled. Full reindexing runs on daily updated multi-source heterogeneous data. This leads to excessive computational resource consumption.
- Phenomenon: Retrieval results include large volumes of non-current historical warning information. Confidence levels fail to meet emergency requirements. Cause: No update time filtering metadata is configured. The similarity threshold is set below 0.7. This does not effectively filter expired data.
- Phenomenon: An error "Parameter mismatch" appears when calling the multimodal-embedding-v1 model. Cause: The model’s API call address and key are not correctly entered in the FastGPT configuration. Or the text length requirements for multimodal input are not adapted.

## How to Verify Correct Configuration
- On the vector model configuration page of FastGPT v4.17.0, confirm that `maxToken` and `defaultToken` values match the preset configuration.
- Upload a test duty log document. Check that indexing completes within a reasonable time frame. No error logs are generated.
- Enter the search term "today's rainfall data". Verify that returned document sources include current-day data from hydrological monitoring systems.
- Adjust the similarity threshold. Confirm that the number of retrieval results changes as expected when the threshold is modified.

The values provided are common starting points and should be measured against the reader's own samples.
