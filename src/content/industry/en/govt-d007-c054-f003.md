# Flood Prevention, Disaster Mitigation and Emergency Duty: Declaration Materials and File Review - Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The daily documents for this category include duty logs, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources include meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Data is updated daily. Fields cover rainfall and water level values, affected population numbers, material allocation quantities, and more. Some documents combine structured fields with free-text descriptions. The length of individual documents typically ranges between 500 and 1500 characters. Data formats from different sources have minor variations.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The daily updated, multi-source heterogeneous data requires multi-turn dialogue to gradually integrate information from different systems, avoiding timeouts caused by loading too much content at once. The mixed document structure of structured fields and free text requires prompt engineering to distinguish between different tasks of field extraction and material generation, ensuring information accuracy during the review process. The fast-paced nature of emergency response requires that multi-turn dialogue context not be too long, with redundant historical information filtered out to focus on core content of the current duty link. The cross-department scheduling feature requires the dialogue to associate the corresponding file number, facilitating subsequent traceability and verification.

## How to set up the configuration
This configuration is based on FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 800–1200 characters | Matches the length range of individual daily documents, avoiding exceeding the model's processing limit |
| Multi-turn dialogue history retention rounds | First 3 dialogue turns | Aligns with the fast-paced emergency response, filtering redundant historical information to focus on the current duty task |
| Variable binding configuration | Enable `variables` parameter | Automatically fills real-time updated fields such as rainfall, population, and materials, reducing manual input errors |
| Dialogue trigger verification | Trigger based on `messages` field completeness | Ensures that core disaster information is included in the input before generating review materials, avoiding invalid output |
| Session association configuration | Bind `chatId` to associate with the corresponding file | Facilitates tracing all dialogues and associated documents for the current duty, meeting the traceability requirements of file review |

## Three common misconfigurations
- Dialogue page or knowledge base page crashes, manifested as error prompts popping up during loading or direct unresponsiveness. The cause is failing to limit the maximum context length, loading too many historical documents exceeding the system memory limit.
- Prompt guidance does not work, manifested as generated review materials not following the preset logic. The cause is failing to arrange the `messages` field in chronological order, causing the model to fail to recognize the dialogue context logic.
- Plugin connection fails, manifested as being unable to associate the dialogue application with integrated plugins. The cause is failing to bind `chatId` to associate the dialogue with the corresponding file, causing the plugin to fail to obtain the corresponding review data.

## How to confirm the configuration is properly set up
- Upload a single rapid disaster report, trigger a dialogue, and check whether the fields bound by `variables` are automatically filled into the generated review materials.
- Initiate a multi-turn dialogue, sequentially input rainfall and water level data from different systems, and check whether the model integrates information according to the `messages` time sequence and generates coherent consultation materials.
- After generating the review materials, verify whether the corresponding file number associated with the current `chatId` is included, ensuring the traceability function works properly.
- Simulate a dialogue missing core disaster data, and check whether the system intercepts the invalid request and prompts for supplementary information.
