# Declaration Materials and Case Review for Flood Prevention, Disaster Mitigation and Emergency Duty: Workflow Orchestration
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Typical data sources for this category include meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance.
Daily generated documents cover duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips.
Data updates happen daily, with temporary high-frequency updates triggered during emergency scenarios.
Document fields include rainfall and water level values, danger level, number of people transferred, material types and quantities, and more.
Corresponding units include millimeters, cubic meters per second, people, pieces, and others.

## What constraints do these characteristics impose on the workflow orchestration link
Multi-source data access needs require workflows to support parallel data pulling from different systems. This avoids performance bottlenecks on single nodes.
The real-time requirement for data updates, especially high-frequency updates during emergency scenarios, needs workflows to support dynamic triggering mechanisms.
The diversity of document structures and fields needs the workflow's `variables` configuration to support flexible mapping of fixed fields from different documents. This ensures accurate data extraction.
Fixed field units need workflows to integrate validation nodes. This prevents subsequent scheduling issues caused by unit errors.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable settings (`variables`) | Preset variables mapped to document fields, covering core fields such as rainfall, water level, and danger level | Matches the fixed field structure of documents in this category, ensuring accurate extraction of key data |
| Node trigger delay threshold | 300 seconds, calibrated based on actual testing | Adapts to the daily data update frequency and real-time response requirements of emergency scenarios |
| Multi-workflow binding rules | Bind corresponding scenario nodes by `nodeId`, such as warning material drafting and material allocation review | Separates independent logic for different review links, avoiding process confusion |
| Context length setting | 800–1200 characters | Adapts to the average length of a single emergency document, ensuring core information is not lost |
| Field validation configuration | Enable unit matching validation, covering common units such as millimeters, cubic meters per second, and pieces | Matches the fixed field unit rules of data in this category, preventing incorrect input |

## Three Common Mistakes
Node confusion occurs when calling multiple workflows, leading to unexpected execution results. This happens when failing to bind workflows for corresponding scenarios by `nodeId`, causing mismatched processes to trigger.
Unit mismatches appear in review results, such as rainfall displayed as "pieces". This occurs when failing to enable field unit validation configuration, and not matching the fixed field rules of this category's data.
Workflow execution times out, triggering failure alerts. This happens when setting the node trigger delay threshold too long, failing to adapt to the real-time requirements of emergency scenarios.

## How to Confirm the Configuration Is Correct
Import a single standard emergency document. Check whether `variables` automatically maps core fields in the document. Confirm the mapping rules match the category's data structure.
Trigger the workflow for the corresponding scenario. Confirm that the correct process nodes are called by `nodeId`, with no cross-process confusion.
Simulate input of field values that do not comply with unit rules. Check whether validation interception is triggered.
Set a short delay threshold to run a test workflow. Confirm no timeout alerts are triggered.
