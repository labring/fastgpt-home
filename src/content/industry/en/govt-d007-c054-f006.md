# Flood Prevention, Disaster Mitigation and Emergency Duty: Declaration Materials and File Review - Citation Source and Traceability

## What this category of data looks like
Data for this category typically originates from weather warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. It updates daily. Daily processed documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data fields often include specific business parameters such as rainfall and water level values, the number of people transferred for evacuation, material categories, inventory quantities, and other relevant metrics. Some documents are structured forms, while others are semi-structured text, with no unified fixed format.

## Constraints Imposed on Citation Source and Traceability Workflows
Multi-source heterogeneous data sources require the traceability process to support access to diverse data formats, ensuring accurate association of meteorological, hydrological, grassroots disaster reporting, and other data types. The daily update frequency requires index construction and update cycles to align with business rhythms, preventing data from lagging behind real-time disposal needs. The mixed structured and semi-structured document structure requires flexible adjustment of citation fragment extraction rules, ensuring accurate traceability of original text fragments across all document types. The specificity of business fields requires traceability results to match exclusive parameters such as rainfall conditions, materials, and personnel, avoiding information bias caused by generalized citations.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Aligns with paragraph lengths of documents such as consultation minutes and rapid disaster reports |
| Overlap Length | 100–200 characters | Ensures cross-paragraph business logic is not split |
| Single Search Limit | Top 8 results | Matches recall requirements for multi-source data, avoiding context overflow |
| `quoteMaxToken` | 1500 token | Retains complete original text fragments of material allocation slips or rainfall data |
| `responseData` | Enabled | Directly returns original text fragments from databases or knowledge bases for traceability |
| `detail` | Enabled | Displays specific source paths and collection times of data sources |

## Three Common Configuration Errors
- Phenomenon: Search results only return scattered short sentences, and cannot cover the complete content of rapid disaster reports or material allocation slips. Cause: The `quoteMaxToken` value is too small to cover complete business document paragraphs.
- Phenomenon: After calling MySQL data via Function CALL, the large model response does not include database original text fragments. Cause: The `responseData` configuration item is not enabled, and the original text return function is not activated.
- Phenomenon: The number of search recall results far exceeds the preset value, causing large model context overflow. Cause: The single search upper limit is set too high, which does not adapt to the real-time recall requirements of emergency data.

## How to Verify Correct Configuration
- Upload a typical material allocation slip or rapid rainfall report document, trigger a knowledge base search, and check if the returned results include complete original text fragments.
- Check the traceability column of search results to confirm if the system name and collection time of the data source are marked.
- Adjust the single search upper limit and verify if the number of recall results matches the expected setting.
- Check if the `detail` option in the configuration page is enabled to ensure complete display of traceability information.
