# Flood Prevention, Disaster Mitigation and Emergency Duty: Application Material and File Review - Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Typical involved entities include emergency management bureaus, water affairs bureaus, meteorological bureaus, sub-districts and townships, and emergency command centers. Daily documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources include meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Update frequency is daily. Document structure covers structured fields such as material numbers and rainfall values, as well as unstructured consultation discussion content. Fields include rainfall (unit: millimeters), material stock (unit: pieces), and risk avoidance areas (unit: square kilometers).

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Multi-source heterogeneous data sources require retrieval to cover document formats from different systems, to avoid missing structured material allocation slips or unstructured consultation minutes with a single retrieval mode. The daily update frequency requires the retrieval scope to support incremental synchronization, to ensure retrieved content is the latest rainfall and disaster data. Document fields include professional numerical values and scenario-based descriptions, requiring retrieval to balance semantic matching and precise keyword matching, to avoid mistakenly retrieving irrelevant daily office documents. The cross-departmental dispatch business characteristic requires retrieval to be limited to the exclusive emergency dataset scope, to prevent mixing non-emergency data from other categories.

## Configuration Setup
This configuration is based on FastGPT v4.17.0. Specific parameter configurations are listed below:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | `0.75–0.85` | Emergency scenario data has strong professionalism. A threshold that is too low will introduce irrelevant historical records, while a threshold that is too high will miss key consultation minutes. Calibrated based on actual testing |
| `limit` | `Top 10` | Consultation materials for emergency duty usually need to associate multiple recent warning and response records. Avoid excessive redundant data exceeding the context length limit |
| `usingReRank` | Enabled | Precise sorting of high-priority rapid disaster reports and material allocation information is required to avoid low-relevance content interfering with emergency decision-making |
| `datasetSearchUsingExtensionQuery` | Enabled | Can expand user duty queries into associated queries including rainfall, hydrological conditions, and risk avoidance areas, covering more relevant documents |
| `collectionIds` | Fill in the collection IDs of accessed data sources such as emergency command and meteorological warning | Accurately limit the retrieval scope, avoid mixing non-emergency data from other categories |
| `searchMode` | Hybrid Retrieval | Supports both keyword matching and semantic retrieval, adapts to structured material allocation slips and unstructured consultation minutes |

## Three Common Misconfigurations
- Phenomenon: The exported dataset.csv uses the general Q&A format template and cannot directly import custom emergency documents. Cause: The dataset template for the corresponding category was not selected, and the general Q&A format template was mistakenly used to generate the file.
- Phenomenon: After the reranking model is deployed, every retrieval result reranking is false. Cause: The `usingReRank` parameter was not enabled in the configuration, or the correct reranking model collection was not bound.
- Phenomenon: The number of retrieval return results does not match the set `limit`, and a large number of non-emergency documents appear. Cause: The `collectionIds` parameter was not configured to limit the retrieval scope, resulting in retrieval covering non-emergency data from other systems.

## How to Verify Proper Configuration
- A test duty log and material allocation slip may be uploaded, a retrieval query for "yesterday's rainfall summary" executed, and the returned results confirmed to include the corresponding documents.
- The retrieval configuration panel may be reviewed to confirm that `usingReRank` is enabled and the deployed reranking model is associated.
- The interface may be called with the `collectionIds` parameter, and the retrieval results confirmed to only include emergency documents from the specified data sources.
- After confirming `datasetSearchUsingExtensionQuery` is enabled, entering "transfer and risk avoidance plan" may be tested, and the returned results confirmed to include associated warning notices and consultation minutes.

The values provided here are common starting points and should be measured against the reader's own samples.
