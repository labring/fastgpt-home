# Declaration Materials and Case File Review for Food Safety Supervision Sampling: Tool Calling and Plugins

## Data for this category
This category's data originates from the food safety sampling monitoring system, the State Administration for Market Regulation sampling results query system, the laboratory LIMS system, and the ledgers of food producers and operators. Daily documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements. Each document contains fixed fields such as sampling number, inspection items, unqualified judgment items, and disposal progress, with a monthly update cadence.

## Constraints for tool calling and plugins
Monthly updated data sources require tool calling to align with batch retrieval time windows, to prevent frequent requests from exceeding system interface limits. The mixed structure of multiple document types requires plugins to support parsing rules matched to document type. Field differences across documents must have preset mappings in tool parameters. The dedicated data format of the LIMS system requires plugins to handle non-standard JSON or table-structured return results, with additional field alignment processing required. Regulatory processes tied to sampling require tool calling outputs to be traceable, with association records retained between call logs and original data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the automatic matching needs of multiple types of sampling documents for this category, covering business scenarios including sampling slips and inspection reports |
| `functionCall` | Enabled | Support calling preset data source interfaces to retrieve dedicated data such as sampling plans and inspection reports |
| Tool call timeout period | 300–600 seconds | Align with the time requirements of monthly batch data retrieval, preventing timeout errors caused by large data volumes |
| Document field mapping rules | Preset mappings based on sampling number and inspection items | Match the fixed field structure of documents in this category to reduce parsing deviations |
| Retry count | 2 times | Adapt to temporary fluctuations in data source interfaces, improving the stability of batch calls |
| Context window size | Calibrated via actual testing | Match the full content length of a single batch of sampling case files, avoiding truncation of critical information |

## Three common configuration mistakes
- Only tool call parameters are returned after a request, with no pre-call thought process. This occurs when the thought output switch for `functionCall` is not configured, resulting in only tool call parameters being output without chain-of-thought content.
- Concurrent requests during tool calling return multiple duplicate sampling data sets. This occurs when `toolChoice` is not restricted to single-tool mode, causing multiple tools to trigger calls simultaneously.
- A 400 status code error is thrown when calling a third-party tool. This occurs when the model's supported tool list is not adapted, and incompatible tool configurations are used, preventing the model from recognizing the call instruction.

## How to verify correct configuration
- Initiate a tool call request for a single sampling slip, and confirm the returned result includes complete inspection items and unqualified judgment fields.
- Set `toolChoice` to `auto`, then initiate a mixed document type call test to confirm the tool automatically matches the corresponding parsing rules.
- Simulate temporary interface fluctuations, initiate a batch call request, and confirm the retry mechanism activates and no duplicate results are generated.
- View the call logs in FastGPT v4.17.0 to confirm the complete thought process and tool call parameters are recorded, with no truncation or missing content.
