# Food Safety Supervision Sampling Declaration Materials and File Review: Document Parsing and Chunking

## What this category of data looks like
Data sources include the food safety sampling monitoring system, the State Administration for Market Regulation sampling results query system, testing institution LIMS systems, and enterprise ledgers. The update frequency is monthly. Daily documents include sampling plans, sampling forms, inspection reports, unqualified food verification and disposal reports, and risk control notices. Most document structures combine fixed form formats and long-text reports, with fields such as sampling number, inspection items, unqualified judgment basis, and disposal measures. There are no unified fixed units, and some fields need to be linked with original inspection records.

## What constraints do these characteristics impose on the document parsing and chunking link
Batch documents updated monthly require parsing tools to support batch processing. The mixed structure of fixed forms and long text requires chunking logic to balance structured field extraction and long paragraph splitting. Data from multiple sources may have format differences, so adaptation to document styles exported by different systems is needed. The unqualified judgment basis in inspection reports must accurately retain associated fields to avoid chunking destroying the integrity of the evidence chain. Document sizes vary greatly between grassroots supervision institutes and testing institutions, so parsing needs to support both small forms and thousand-page reports.

## How to set configurations
All configurations below are verified based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Sampling reports mostly contain professional testing data and long-text judgments. This range balances context relevance and retrieval accuracy |
| `chunkSplitter` | Split by paragraph + title | Documents include different structural modules such as sampling plans, sampling forms, and inspection reports. Splitting by title retains the integrity of business logic |
| `customPdfParse` | Enable structured parsing | Sampling forms and inspection reports use fixed form formats. Structured parsing accurately extracts field values and avoids redundant text interference |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 seconds` | Parsing thousand-page inspection reports requires a long time. This range covers the parsing time of most documents |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | A single annual sampling summary document may exceed conventional sizes. This threshold supports batch upload requirements |
| `chunkSettingMode` | Manual configuration | Chunking requirements differ across document types (forms/reports/notices). Manual configuration allows flexible parameter adjustment |

## Three Common Mistakes
- Phenomenon: Intranet Confluence pages cannot be parsed to valid content, returning empty text or vague prompts. Cause: Intranet access permissions or custom parsing rules are not configured. The default external network parsing rules cannot adapt to intranet domain names and permission verification logic.
- Phenomenon: Chunking results do not retain document hierarchy, making it impossible to link sampling forms with corresponding inspection reports. Cause: Parent-child chunking configuration is not enabled, or chunking rules do not match document title hierarchy.
- Phenomenon: Thousand-page PDF documents fail to parse due to timeout, or Excel documents return incomplete prompts after parsing. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too low, or structured parsing is not enabled for Excel tables, leading to long-text parsing failure.

## How to confirm the configuration is correct
- Upload a single sampling report document, check if the parsed text retains core fields such as inspection items and unqualified judgments, with no obvious redundancy or missing content.
- Adjust the `chunkSize` parameter, compare chunking results of different documents, and confirm that the chunk length meets business retrieval needs.
- Upload batch monthly documents, verify that the parsing time does not exceed the threshold range set by the `PARSE_FILE_TIMEOUT_SECONDS` configuration.
- Test the parsing effect of documents exported from intranet systems, confirm that custom parsing rules adapt to intranet access logic.

The values provided are common starting points and should be measured against the reader's own samples.
