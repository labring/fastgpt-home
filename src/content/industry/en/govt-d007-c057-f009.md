# Declaration Materials and Case File Review for Food Safety Supervision and Sampling: Model Access and Configuration

## What the data for this category looks like
Data for this category mainly comes from the food safety sampling and monitoring system, the State Administration for Market Regulation sampling results query system, laboratory LIMS, and enterprise account books. Daily documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control notices. The update frequency is monthly. Core fields cover sampling information, test results, disposal processes, and more. Field formats of different documents are uniformly standardized by regulatory systems, with no custom field space available.

## What constraints these characteristics impose on the model access and configuration link
Monthly updated batch data requires model access to support batch task scheduling, to avoid overload from single processing. Differences in data formats across multiple sources require configuring unified document parsing rules to adapt to different document structures such as sampling slips and inspection reports. Core documents such as inspection reports need precise mapping of original fields, and must not lose key information like non-conforming items and disposal progress. Strict compliance requirements in regulatory scenarios mean audit results output by the model must be traceable, retain the ability to cite original text, and avoid tampering with original data fields. Data volume changes with monthly sampling batches, so adaptive context length parameters must be configured to adapt to differences in document lengths across batches.

## How to set configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | API address specified by the regulatory system | Adapts to the official data interface specifications of the food safety sampling and monitoring system |
| `AIPROXY_API_TOKEN` | Exclusive authentication token assigned by the regulatory system | Ensures identity legitimacy of data calls, meets security requirements of regulatory scenarios |
| `maxContext` | 8000–12000 token | Adapts to the total length of monthly batch sampling documents, avoids context overflow |
| `quoteMaxToken` | 1500 token | Retains complete reference fragments of core documents such as inspection reports and sampling slips, meets audit traceability requirements |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures consistency of audit results, meets strict requirements of regulatory scenarios |
| `maxTokens` | 2000 token | Controls the output length of a single audit result, adapts to the standardized format requirements of case file review |

## Three common errors
- Phenomenon: Entering a non-officially assigned token when configuring `AIPROXY_API_TOKEN`, resulting in a 401 status code return. Reason: The exclusive authentication credential of the regulatory system was not used, violating interface security verification rules.
- Phenomenon: Setting an excessively large `maxContext` value, resulting in a context overflow error. Reason: The total length of monthly batch sampling documents was not adapted to, exceeding the maximum context limit supported by the model.
- Phenomenon: Setting an excessively high `temperature` value, leading to inconsistent judgment conclusions in audit results. Reason: The strict requirements of regulatory scenarios were not considered, and overly randomized output does not meet the standards of compliant audits.

## How to confirm the configuration is successful
- Call the test interface to verify the authentication validity of `AIPROXY_API_TOKEN`, and confirm that normal document parsing results are returned.
- Upload a single inspection report, check whether the configurations of `maxContext` and `maxTokens` adapt to the document length, and there are no context overflow prompts.
- Generate audit results for multiple identical types of documents, check whether the output conclusions remain consistent under the `temperature` configuration.
- After configuring `quoteMaxToken`, check whether the audit results completely retain key reference fragments of core documents such as inspection reports and sampling slips.

The values provided are common starting points and should be measured against the reader's own samples.
