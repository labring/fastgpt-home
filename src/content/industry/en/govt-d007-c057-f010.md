# Declaration Materials and File Review for Food Safety Supervision Sampling: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data for this category comes from the food safety sampling and monitoring system, the national market supervision administration sampling results query system, the inspection institution LIMS, and the food producer and operator ledger. Daily documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements. The data update frequency is monthly. The document structure centers on sampling process nodes. A sampling slip includes fields such as sampling number, sampling location, and inspection items. An inspection report includes fields such as test value and qualified determination result. A verification and disposal report includes fields such as problem rectification requirements. All fields correspond to standardized requirements of regulatory processes, with no custom non-general fields.

## What constraints do these characteristics impose on the "knowledge base retrieval and recall" link
The data characteristics of this category impose multiple constraints on the retrieval and recall link. The multi-source data import requirement requires the retrieval tool to support standardized synchronization connected to multiple data sources such as the sampling and monitoring system and LIMS. The monthly update rhythm requires configuring incremental synchronization trigger logic. The coexistence of multiple document types requires that retrieval can perform field filtering by document types such as sampling plans and inspection reports, to avoid interference from irrelevant content. Core documents such as inspection reports contain professional testing terms, requiring higher retrieval matching accuracy, and exclusive recall rules need to be set for professional fields. At the same time, the strong compliance of regulatory processes requires that recall results must cover the latest monthly data to ensure the timeliness of verification and disposal.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale for This Value |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Professional testing documents require high accuracy for term matching, to filter low-relevance retrieval results |
| `limit` | `Top 8 entries` | The number of relevant documents for sampling files is limited; 8 entries can cover core relevant materials and avoid context overflow |
| `searchMode` | `Semantic matching` | Adapt to the semantic association requirements of professional documents such as inspection reports, which is better than keyword-only matching |
| `usingReRank` | `Enabled` | Perform secondary sorting on multi-source recall results to improve the display priority of highly relevant documents |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expand synonymous terms related to sampling, such as expanding "non-conforming item" to "non-compliant standard item", to improve recall coverage |
| `collectionIds` | `Bind the collection ID of the special food safety supervision sampling knowledge base` | Only recall documents exclusive to this category to avoid interference from cross-category irrelevant content |

## Three common mistakes
- Phenomenon: An error prompt "Illegal data range" pops up after accessing the knowledge base, and retrieval results cannot be loaded. Cause: The `collectionIds` configuration is not correctly bound to the exclusive food safety supervision sampling knowledge base collection, causing the retrieval scope to cover unauthorized documents and triggering system verification failure.
- Phenomenon: Retrieval response time exceeds 30 seconds, exceeding business processing expectations. Cause: `usingReRank` is not enabled and the `limit` value is too high, causing a large number of low-relevance documents to be loaded and participate in sorting, increasing processing time.
- Phenomenon: Detailed error information cannot be obtained after retrieval fails. Cause: The debug log switch of the FastGPT platform is not enabled, so detailed logs of the retrieval process cannot be viewed to locate problems.

## How to confirm that the configuration is complete
- Log in to the knowledge base management interface of the FastGPT platform, and check whether the bound collection ID matches the special food safety supervision sampling knowledge base.
- Submit a retrieval request containing professional terms such as "total bacterial count" and "unqualified food", and check whether the returned results include core documents such as inspection reports, sampling slips, and verification and disposal reports.
- View the knowledge base synchronization records to confirm that the most recent data update uses the monthly incremental synchronization mode.
- After initiating a retrieval request, view the detailed information of the retrieval process through the platform debug log to confirm that the configuration parameters take effect.

The values given are common starting points and should be measured against the reader's own samples.
