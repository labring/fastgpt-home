# Declaration Materials and Case Review for Warehousing and Logistics: Document Parsing and Chunking

## What this category of data looks like
Data for warehousing and logistics declaration materials and case review mainly originates from business documents including customs declarations, inbound and outbound inventory ledgers, shipping packing lists, and quality inspection reports. Data update frequency aligns with business processes: customs documents are updated in real time as goods clear customs, while inbound and outbound documents are synced daily. Supported document formats include PDF, Word, Excel, and scanned copies. Most documents have fixed headers, with fields such as goods name, container number, declaration number, weight, and quantity. These fields use dedicated units such as kilograms, cubic meters, and pallet counts. Some cases are linked to multiple supplementary documents.

## What constraints these characteristics impose on document parsing and chunking
Fixed headers and dedicated field units require parsing to preserve binding relationships between fields, to avoid splitting associated data from the same business unit. Diverse document formats and multiple supplementary documents require chunking rules to adapt to different file types, while preserving contextual links between main documents and supplementary materials. High-frequency updated business data requires parsing tasks to limit runtime, preventing task failure due to timeout. Additionally, case review requires associating content across multiple documents, so chunking must place related content in adjacent chunk ranges to support subsequent retrieval and review.

## Configuration Guidelines
This guide applies to FastGPT v4.17.0, and the following configurations are formulated for this version:

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Warehousing and logistics documents contain multiple sets of structured fields. Chunks that are too long will lose field associations, while chunks that are too short will damage the integrity of business logic |
| `chunkSplitter` | Use custom rules | Warehousing documents have fixed headers and associated supplementary documents. Generic chunking will split associated information between main documents and attachments |
| `customPdfParse` | Enable structured parsing | Some customs declarations and packing lists are PDF forms. Enabling this option preserves field hierarchy |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 seconds | Large customs case files include multiple attachments. Parsing time increases with the number of attachments, and this range fits most business scenarios |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Warehousing and logistics case files may include batch scanned copies or high-definition documents, so support for large file uploads is required |
| `chunkSettingMode` | Manual configuration | Different types of warehousing documents (such as customs declarations and inbound/outbound documents) have different chunking rules. Manual configuration allows flexible adjustments |

## Three Common Misconfigurations
- Phenomenon: After uploading a PDF customs declaration form, knowledge base search tests fail to return results that include the declared amount. Cause: Chunking split the binding relationship between the goods name and declared amount, making it impossible to associate the corresponding fields during retrieval.
- Phenomenon: After uploading an Excel inbound/outbound document, the parsed chunks split multiple rows of data from the same document into different chunks. Cause: `chunkSplitter` was not configured to use custom rules, and the generic chunking logic did not recognize the row association of the table.
- Phenomenon: Parsing tasks trigger timeout errors when uploading scanned case files larger than 800 MB. Cause: `PARSE_FILE_TIMEOUT_SECONDS` was set too low, failing to fit the parsing time of large case files.

## How to Verify Proper Configuration
- Upload a single typical warehousing document (such as a customs declaration form), check the parsed chunk content, and confirm that fields from the same business unit are not split.
- Run a knowledge base search test, enter a query term that includes a specific field (such as customs code, container number), and confirm that the returned results include the complete context of the corresponding field.
- Upload a case file that meets the maximum business size limit, and confirm that no parsing task timeout errors occur.
- Adjust the value range of `chunkSize`, compare chunking effects under different configurations, and confirm that they match the structural characteristics of current business documents.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
