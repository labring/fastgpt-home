# Warehouse Logistics Declaration Materials and File Review: Knowledge Base Retrieval and Recall

## What this category's data looks like
The data for declaration materials and file review in the warehouse logistics sector primarily comes from warehouse operation systems, customs declaration and inspection platforms, inventory management ledgers, and transportation and delivery documents. Data updates align with business nodes: daily batch updates are used in regular review scenarios, and real-time synchronization is used for urgent customs declaration scenarios. The document structure includes two types of content: first, structured metadata fields, including cargo category, batch number, warehouse location, customs declaration number, review status, etc., with corresponding units such as pieces, cubic meters, tons, dates, etc.; second, unstructured attachments such as scanned customs declarations and electronic inventory ledger text.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
The coexistence of structured metadata and unstructured attachments requires retrieval to balance precise field matching and text semantic recall, to prevent missed or incorrect recalls caused by relying solely on a single retrieval method. Real-time or high-frequency updated data requires regular index refreshes to prevent retrieval results from being out of sync with the latest warehouse business data. Structured data with multiple fields requires limiting the retrieval scope to avoid mixing in file data from other categories, while long-text attachments need to be properly split into chunks to avoid semantic deviation caused by overly long single chunks. In addition, the strong association between declaration materials and files requires that retrieval results highly match the fields of the currently submitted declaration form, and irrelevant cross-batch files should not be included in results.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Warehouse logistics declaration materials have fixed business fields. This range filters low-match irrelevant files and retains highly relevant review materials |
| `limit` | Top 8–12 entries | The number of files associated with a single declaration material usually does not exceed 10. This value balances recall coverage and context length |
| `searchMode` | `vector+keyword` | Balances keyword matching for structured fields and semantic retrieval for unstructured attachments, adapting to mixed-structure document data |
| `usingReRank` | Enabled | Many long-text attachments exist. Reranking improves the sorting priority of highly relevant files and optimizes review efficiency for reviewers |
| `datasetSearchUsingExtensionQuery` | Disabled | Keywords for declaration materials are clear, so no additional query expansion is needed. This avoids introducing irrelevant retrieval results |
| `collectionIds` | Fill in the dataset ID of the corresponding warehouse declaration files | Limits the retrieval scope, excludes documents from other categories, and ensures recall results only relate to warehouse logistics declaration business |

## Three common configuration errors
- Phenomenon: Irrelevant non-warehouse category file data is mixed into retrieval results, and field content has no relation to the declaration business. Cause: The `collectionIds` parameter was not filled in correctly, and the retrieval scope was not limited to the corresponding warehouse dataset.
- Phenomenon: Attempting to copy a `chunk ID` or knowledge base ID fails to select the content, and the content cannot be directly copied to the clipboard. Cause: FastGPT v4.17.0 does not enable copy permission for this field by default. The corresponding permission must be enabled in system settings before operation.
- Phenomenon: Duplicate warehouse files of the same batch appear in retrieval results, and the number exceeds the range set by the `limit` configuration. Cause: The FastGPT knowledge base index merging component was not used to deduplicate imported documents, resulting in duplicate data being indexed and recalled multiple times.

## How to verify correct configuration
- Log in to the FastGPT v4.17.0 backend, enter the dataset management page for the corresponding warehouse declaration files, and confirm that the `collectionIds` parameter has been correctly filled in the retrieval configuration.
- Submit a test query, such as "2024 Q2 Shenzhen warehouse import declaration files", and check whether the `similarity` score of the returned results falls within the 0.75–0.85 range.
- Check the number of results returned by the retrieval, confirm that it matches the value set by the `limit` configuration, with no obvious excess or shortage.
- Try to select and copy the `chunk ID` field of any retrieval result, confirm that the interface has enabled copy permission, and that the content can be normally pasted into other tools.

The values provided are common starting points and should be evaluated using samples from the specific deployment context.
