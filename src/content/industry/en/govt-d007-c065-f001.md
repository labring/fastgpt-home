# Survey and Design Project Declaration Materials and File Review: HTTP Interfaces and External Systems

## What this category of data looks like
Data primarily comes from declaration submission materials and archived files for survey and design projects. This includes survey point coordinate documents, construction drawing design files, declaration application forms, archived file ledgers, and similar items. Update timing is triggered on demand according to the project declaration process, with no fixed cycle. The length of individual documents varies widely, ranging from hundreds of characters of declaration forms to dozens of pages of survey reports and CAD attachments. Fields include structured fields such as project number, declaring unit, survey scope, and drawing version number. It also includes unique identifiers like point coordinates (unit: meters) and archive filing numbers.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer sk-xxxxxx` | Complies with FastGPT interface authentication standards to ensure call legitimacy |
| `variables` | `{"project_type": "survey and design", "doc_category": "declaration files"}` | Passes exclusive business context for survey and design projects to improve knowledge base matching accuracy |
| `responseData` | `Return matched file numbers and matching scores` | Simplifies returned content to adapt to the business verification logic of external systems |
| Maximum documents per single request | Top 10 | Adapts to the conventional quantity of batch-declared survey and design files, avoiding interface timeouts |
| Request timeout | 600 seconds | Covers the transmission and processing duration of large-volume survey reports, calibrated via actual testing |
| Maximum attachment size | 100 MB | Adapts to the conventional size of CAD drawings and survey reports, avoiding transmission failures |

## Three Common Misconfigurations
- Interface calls return a 514 status code. Cause: The `Authorization` parameter is not configured correctly, or the API key has expired.
- Knowledge base search fails to associate uploaded survey and design documents. Cause: The exclusive business classification parameter for survey and design projects is not passed in `variables`, so the index range does not cover the target documents.
- The number of matching results returned after calling the interface does not match expectations. Cause: A reasonable maximum number of documents per single request is not set, or the knowledge base association range is not limited to survey and design file types.

## How to Verify Configurations Are Correct
- After calling the interface, check if the returned `responseData` includes the expected file numbers and matching scores. This confirms authentication and return format configurations are correct.
- Upload a test survey and design declaration document, call the interface, and verify whether the document can be matched. This confirms business context parameter configuration is valid.
- Simulate a call to the interface for a batch of 10 or fewer survey and design files. Confirm that the request does not trigger a timeout restriction, and that the timeout configuration meets actual needs.
- Check the project declaration nodes of the external system. Confirm that the interface trigger timing is synchronized with the process nodes, and that the call logic complies with business requirements.
