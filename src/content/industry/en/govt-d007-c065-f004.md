# Survey and Design: Declaration Materials and File Review - Workflow Orchestration

## What this category of data looks like
Data for survey and design declaration materials and file review comes from internal review systems of survey units, BIM model export files, and housing and urban-rural development department review templates.
Updates occur in batches per approval node within a single project's review cycle. No fixed update cycle exists.
Documents split into two parts: structured fields and unstructured attachments.
Structured fields include project name, survey phase, qualification certificate number, and review submission date. Some fields use enumeration types.
Unstructured attachments include geological survey report PDFs, structural calculation documents, and compressed-format construction drawings. Some attachments have large file sizes.
Field units include "item" (for integrity check items) and "working days" (for approval duration recording).
This configuration guide uses FastGPT v4.17.0.

## What constraints these characteristics impose on workflow orchestration
Enumerated structured fields require pre-configured field validation rules in workflows. These rules match preset validation items in the review template to avoid invalid reviews.
Large unstructured attachment sizes require workflow nodes to limit per-attempt file size ranges. This prevents excessive resource usage.
Batch-updated review rhythms require workflows to support node triggers per review batch. Only updated materials are processed to avoid repeated calculations.
File review requires association with historical approval records. Workflow nodes must support attaching historical data query links. These links associate approval logs and past review results for the corresponding project.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable configuration | Bind `variables` to project number, qualification level, review batch | Match fixed structured fields of survey and design declaration materials, enable cross-node data reuse |
| Node trigger condition | Trigger by `nodeId` as the completion status of the previous node | Adapt to batch-updated review rhythms, execute subsequent reviews only after pre-submitted material validation passes |
| Problem optimization configuration | Enable historical record association optimization | Resolve ambiguous reference recognition issues in declaration materials, such as matching "this report" to the corresponding document |
| Single file processing limit | 500 MB | Adapt to processing requirements for large attachments such as CAD drawings and structural calculation documents |
| Debug node timeout setting | 600 seconds | Avoid unresponsive interruptions during large file parsing or long-text review |
| Result display control | Only display the output of the last model node | Meet business requirements for presenting only final review conclusions |

## Three common configuration errors
- Symptom: Debug mode cannot be exited after the debug node runs. The interface displays a "running" status with no response. Cause: No timeout threshold is configured in the debug node settings. Unlimited waiting occurs during parsing of large survey reports.
- Symptom: Workflow return results include intermediate content from prior steps. Final review conclusions are not the only displayed content. Cause: No result display control rules are configured. All node output content is retained by default.
- Symptom: Knowledge base search nodes cannot correctly match reference expressions in declaration materials. For example, "this structural calculation document" fails to match the corresponding document. Cause: Historical context is not passed to the search node as `variables`. No problem optimization rules are configured.

## How to verify a successful configuration
- Upload a single survey report attachment under 500 MB. Trigger workflow execution, and check whether the node status completes within 600 seconds.
- Configure to only display the output of the last model node. Submit test materials containing reference expressions, and check whether the knowledge base search node correctly matches the corresponding document.
- Enter debug mode to run the workflow. Wait 600 seconds, then check whether the debug state exits normally with no unresponsive situations.
- Submit test declaration materials, and check whether returned results only include the final review conclusion. No intermediate content from prior steps is included.

The values provided are common starting points and should be measured against the reader's own samples.
