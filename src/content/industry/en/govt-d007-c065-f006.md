# Survey and Design Declaration Materials and File Review: Citation Sources and Traceability

## What this category of data looks like
This category of data mainly comes from internal management systems, submission platforms, and archived files of survey and design projects. It includes structured declaration forms, survey and mapping reports, construction drawing design documents, review opinions, and other types. Data is updated by project phase, gradually generated from project approval to completion acceptance archiving. The length of single file documents varies widely, ranging from qualification certificates with hundreds of characters to CAD drawings and PDF reports of tens of megabytes. Fields include project number, survey hole coordinates, load parameters, qualification level of submitting units, and more. Commonly used engineering units such as meters, megapascals, and square meters are involved.

## What constraints do these characteristics impose on the citation and traceability link
The wide span and mixed structure of this category of data create multiple constraints for the citation and traceability link. Long documents and large files need to retain chapter and page associations of the original document to avoid losing contextual logic during traceability. Coexistence of structured fields and unstructured reports requires matching both precise field retrieval and full-text semantic recall to ensure correspondence between cited content and declaration items. Data updated by project phase requires associating version information across the full project cycle during traceability to avoid citing expired review opinions or drawings. Engineering data has high requirements for units and parameter accuracy; traceability must retain unit markings of original data to prevent parameter confusion.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–12000 token | Survey and design declaration materials often include multiple long documents, requiring sufficient context to retain project logic, consistent with FastGPT v4.17.0 parameter logic |
| Maximum Knowledge Base Citations | Top 8–12 entries | Balances recall accuracy and response length, avoiding redundant citations of excessive file content |
| `quoteMaxToken` | 1500–2000 characters | Limits the length of a single citation, adapting to the parameter and paragraph length of engineering documents |
| Single Search Limit | Top 20 recall results | Covers multiple types of documents related to the project, avoiding missing key review opinions |
| `responseData` | Enabled | Retains fields and metadata of original cited data, facilitating association of project numbers and unit information during traceability |
| `detail` | Enabled | Displays full context of cited content, avoiding truncation of engineering parameters and key instructions |

## Three Common Configuration Mistakes
- Phenomenon: Line breaks in source text are not rendered, with `\n` output verbatim. Cause: The format parsing switch corresponding to `responseData` is not enabled, causing line breaks in original documents to be treated as ordinary characters.
- Phenomenon: The number of citations exceeds expectations or key files are not recalled. Cause: The maximum knowledge base citations or single search limit is set too low, failing to cover declaration and review documents across the full project cycle.
- Phenomenon: Returned results forcibly carry citation markers and cannot be turned off. Cause: The `responseData` parameter is not configured correctly, or the forced display mode of `detail` is not disabled.

## How to Verify Configuration Success
- Upload a typical survey and design declaration file, initiate a query with specific parameters, and check whether the units and parameters of the cited content in the response match the original document.
- View the citation traceability module, confirm that each citation is associated with the original document name and project number, with no missing metadata fields.
- Adjust the maximum knowledge base citations value, observe changes in the number of citations in the response, and confirm that the configuration takes effect.
- Test a query about an engineering report containing line breaks, confirm that line breaks in the response are rendered normally and not displayed as `\n`.
