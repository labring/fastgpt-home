# Survey and Design Declaration Materials and File Review: Deployment and Upgrade

## Data Characteristics for This Use Case
The data for survey and design declaration materials and file review mainly comes from internal project management systems, original records collected at survey sites, reviewed feasibility study reports, CAD-format construction drawings, and qualification submission documents. Data update frequency fluctuates with project declaration deadlines. Complete materials are submitted in a concentrated manner before declaration, and only small-scale updates for revision comments are made on a daily basis. Documents include structured declaration forms (with fixed fields such as project code, survey scope, qualification level) and unstructured files (drawings, PDF reports). Field units include square meters, meters, qualification level and other level identifiers, and there is no unified single-document length limit.

## Constraints Imposed on Deployment and Upgrade
Fixed fields in structured declaration forms require targeted database indexes to speed up queries. Large unstructured drawing files require services adapted for large-file storage. The concentrated periodic submission feature means upgrade operations must avoid project declaration peak periods to prevent disruption to business workflows. For multi-node deployments, cache and database configurations must be unified to ensure consistency of file data across nodes. Encrypted storage and access tokens must be configured for classified survey and design documents to prevent unauthorized access.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–15 connections/second | Survey and design declaration materials have high database query frequency. This parameter controls the maximum number of connections in the database connection pool to avoid connection exhaustion disrupting review workflows |
| `MONGODB_URI` | Local instance address, default port 27017 | Survey and design file data includes large amounts of unstructured text and binary drawings. MongoDB is suited for storage and query of this type of data |
| `REDIS_URL` | Single instance with memory no less than 2048 MB | Multi-node deployments require unified caching of sessions and temporary file metadata to ensure consistency across node access |
| `STORAGE_S3_ENDPOINT` | Object storage endpoint that supports resumable uploads | Survey and design drawing files are generally large in size. This configuration adapts to large-file upload and storage requirements |
| `FE_DOMAIN` | Public domain name of the deployment server | Used as the domain identifier for generating login-free window links, adapting to multi-terminal access to survey and design project review pages |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Used to encrypt file access tokens, preventing unauthorized access to classified survey and design drawings and files |

## Three Common Configuration Errors
- Login-free link after upgrade redirects to incorrect model page: The symptom is that clicking the published login-free window link loads a large model that does not match the preset configuration. The cause is that the `FE_DOMAIN` and `REDIS_URL` configurations were not synchronized during the upgrade process, resulting in a mismatch between the session cache and the frontend domain name.
- Login prompt shows incorrect username or password after deployment: The symptom is that authentication fails after entering the preset administrator account password. The cause is that the `ROOT_KEY` parameter was not configured correctly, or the environment variable file was not mounted during container deployment, causing the parameters to fail to load properly.
- Workflow startup prompts storage connection failure: The symptom is that a storage service connection timeout error pops up after entering the workflow editor. The cause is that the object storage endpoint configured in `STORAGE_S3_ENDPOINT` does not have access permissions enabled, or network policies restrict access to the corresponding port.

## How to Verify Configurations Are Correct
- Run the `docker ps` command to confirm that all FastGPT v4.17.0 related containers are running, with no abnormal exit records.
- Access the frontend address corresponding to `FE_DOMAIN`, log in to the backend, locate the `STORAGE_S3_ENDPOINT` configuration item, upload a small survey and design drawing, and verify that the file can be uploaded and previewed normally.
- Open a database management tool, connect to the instance configured in `MONGODB_URI`, and confirm that a dedicated collection for storing file data exists.
- Generate a login-free link, access it on another device, and confirm that the page loads normally and matches the preset model parameters.

The values provided here are common starting points and should be measured against the reader's own samples.
