# Filing Submission and Case Review for Advanced Chemical Materials: Vector Models and Indexing

## What this category’s data looks like
Advanced chemical materials filing and case review data primarily comes from enterprise R&D logs, patent filing documents, safety supervision filing materials, project acceptance case files, and similar sources. The data update cadence is full batch import when a project is initiated, with daily updates only adding newly filed test reports and change materials. Document structure includes both structured fields and unstructured content: structured fields include material number, filing date, raw material ratio, test data, and similar items, with professional units such as g/mol, °C, MPa. Unstructured content includes multi-page PDF lab reports and scanned original case files.

## What constraints these characteristics impose on the vector model and indexing workflow
Structured fields and professional units require the indexing system to support both precise metadata matching and text semantic recall. Long documents and batch update requirements mean indexing must support incremental rebuilding, to avoid full repeated processing. Variations in document formats across multiple sources require chunking strategies adapted to text content of varying lengths. The presence of classified and compliance-related fields requires field validity checks before indexing, to filter sensitive content.

## How to configure the system
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the paragraph length of chemical lab reports, avoid semantic breaks within chunks |
| Overlap Length | 100–200 characters | Preserve cross-chunk lab data associations, avoid truncation of key ratio information |
| Similarity Threshold | 0.75–0.85 | Match the test data precision of chemical materials, filter low-relevance filing materials |
| Single Search Limit | Top 8 results | Cover the number of associated materials in typical case files, avoid redundant recall |
| maxToken | 4000 token | Adapt to the context length of filing materials, meet the full information requirement for compliance checks |
| defaultToken | 1000 token | Handle metadata retrieval for short fields, balance recall precision and speed |

## Three common configuration mistakes
- Phenomenon: A 60-second timeout status code is returned when switching the knowledge base index. Cause: No reasonable chunking and recall parameters configured for advanced chemical materials, leading to data processing time exceeding the system's default threshold during index rebuilding.
- Phenomenon: The knowledge base continuously shows training or rebuilding status, and index switching cannot be completed after more than 24 hours. Cause: Incremental indexing mode is not enabled, and full repeated indexing is performed on all historical filing materials.
- Phenomenon: Batch index addition requests return format verification failures. Cause: Classified or non-compliant fields in filing materials are not filtered, leading to format mismatches during index import.

## How to confirm the configuration is correct
- Import a typical chemical filing case file, use the built-in index testing tool in FastGPT v4.17.0 to check generation time, adjust parameters until the time meets business expectations.
- Submit a retrieval request, verify the number and relevance of returned results, adjust the similarity threshold and single search limit to meet business requirements.
- Check the system index logs, confirm that incremental indexing only processes new materials, and no full rebuilding process is triggered.
- Submit a batch indexing request, confirm that the parameter configuration meets the system interface requirements, with no format verification errors.

The values provided are common starting points and should be measured against the reader's own samples.
