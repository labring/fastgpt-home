# Declaration Materials and Case Review for Advanced Chemical Materials: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Advanced chemical material declaration materials and case data come from enterprise R&D record ledgers, national industry standard documents, and official approval record files. Updates occur when individual declaration batches finish or industry standards are revised, with no fixed cycle. The document structure has two parts: standardized declaration forms and archived cases. The declaration form includes fields such as material grade, CAS number, tensile strength, and heat distortion temperature. The case includes approval process records, third-party test reports, and compliance statements. All fields use specialized chemical units, such as MPa, ℃, and kg/ton.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Multi-turn dialogue prompts for chemical declaration work must clearly specify field extraction formats and unit verification rules to avoid ambiguity from professional terminology. Documents are lengthy, so single dialogues require wide context coverage. Limit the number of retained invalid historical dialogues to prevent context overflow that causes verification failures. The system must synchronize latest industry standards and approval requirements regularly, as data has no fixed update cycle. Multi-turn dialogue must support dynamic loading of the latest compliance rules. Compliance verification for declaration materials requires multiple rounds of confirmation. The dialogue process must retain verification records for each step to support subsequent case archiving and traceability.

## How to configure the settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to the unique business number of the declaration batch | Associate the case and dialogue logs of the corresponding batch to enable precise traceability |
| `messages` | Retain the last 20 rounds of dialogue context | Many chemical professional terms require retention of previously confirmed parameter details to avoid repeated verification |
| `variables` | Preset three core variables: CAS number, declaration unit, approval document number | Reduce repeated input and ensure consistency of required fields |
| Maximum context length | 8000–12000 token | Cover complete case files and multi-round verification dialogues to prevent content truncation |
| Dialogue expiration time | 30–60 days | Match the review cycle of chemical declaration materials to avoid premature expiration |
| Prompt optimization | Calibrate based on actual testing | Ambiguity is common in chemical professional terms, so adjust optimization rules based on actual verification effects |

## Three common mistakes
- Phenomenon: Historical verification records cannot be retrieved after the dialogue file expires, and the interface displays "Session has expired". Cause: The default dialogue expiration time configuration was not adjusted. The default 7-day validity period is shorter than the review cycle of the chemical declaration process.
- Phenomenon: Parallel AI dialogue calls in batch execution nodes return only one set of verification results. Cause: The `variables` were not used to bind independent declaration batch identifiers for each dialogue, leading to context coverage conflicts.
- Phenomenon: The corresponding declaring user cannot be matched in the dialogue log, and the user field is empty. Cause: `chatId` was not configured as the unique business number of the user's declaration, and relevant session traceability settings were not enabled.

## How to confirm the configuration is complete
- View the session configuration page to confirm that the dialogue expiration time matches the current declaration process cycle.
- Test batch insertion of dialogues for multiple different declaration batches to confirm that each generates independent verification results.
- Export the dialogue log to confirm that each log is bound to the corresponding `chatId` business number.
- Input chemical professional terms and fields to confirm that the prompt correctly identifies and verifies the format and units of the fields.

The values given are common starting points and should be measured against the reader's own samples.
