# Declaration Materials and File Review for Advanced Chemical Materials: Source Citation and Traceability

## What Data for This Category Looks Like
Declaration materials and file data for advanced chemical materials mainly originate from internal enterprise R&D record databases, industry compliance public platforms, and archived files from third-party testing institutions. Data updates are synchronized in real time with project approval progress, and batch compliance declarations are updated in batches. A single document typically includes a technical indicator table, scanned test reports, and compliance certification attachments. Fields cover material number, test date, compliance level, and molecular structure parameters, with units mostly being professional chemical units such as g/mol, ℃, and MPa.

## What Constraints These Characteristics Impose on the "Source Citation and Traceability" Link
Advanced chemical material declaration materials contain numerous professional parameters, single documents are relatively lengthy, and file archives include multiple rounds of approval records, leading to high token consumption for a single knowledge base chunk. Compliance audits require traceability to precisely match fields such as material number and test date, placing strict requirements on retrieval accuracy. Data updates occur at a relatively high frequency, so it is necessary to ensure that cited data sources align with the current record status and avoid using expired compliance documents. Some test reports are unstructured scanned files, which require OCR conversion before being included in retrieval, adding pre-processing steps for traceability.

## Configuration Guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context | 12000–15000 token | Adapts to the average token size of a single document for chemical declaration materials, avoiding truncation of core technical parameters |
| `quoteMaxToken` | 2500–3500 token | Limits the token consumption of a single citation, preventing long test report chunks from exceeding the context threshold |
| `responseData` | Enable source fields | Forces return of identifiers such as the cited material’s number and test date, meeting the traceability requirements for compliance audits |
| `detail` | Full display mode | Retains all structured fields of cited content, making it easier to verify professional parameters and compliance levels |
| Single Retrieval Limit | Top 6–10 entries | Matches the number of rounds of approval records in chemical case files, covering major associated review materials |
| Reranking Sort | Descending by match score | Prioritizes retrieving compliance materials that match declaration requirements, avoiding interference from irrelevant documents during review |

## Three Common Misconfigurations
- The number of context entries displayed in the interface does not match the number actually sent to the model. For example, the interface shows 30 entries but 310 are actually sent. This occurs because the matching relationship between `quoteMaxToken` and maximum context is not correctly configured, causing the system’s automatic truncation logic to fail.
- After setting a citation limit, chunks exceeding the limit in the knowledge base are still retrieved. This happens because the citation limit is not linked to retrieval filtering rules, only restricting token consumption during the output stage and not limiting chunk length during the retrieval stage.
- Citation content does not display source fields, making compliance traceability impossible. This occurs because the `responseData` configuration item is not enabled, and the system by default only returns text content without accompanying identifier information.

## How to Verify Proper Configuration
- Call the test tool and check the citation source fields returned by the model to confirm that identifiers such as material number and test date are included.
- Adjust the `quoteMaxToken` value to verify that long document chunks are correctly truncated without overflow errors.
- Upload a single over-length chemical test report to test whether the retrieval logic complies with the configured limit rules.
- Check the knowledge base chunk index logs to confirm that unstructured documents converted via OCR have been included in the retrieval scope.

The values provided are common starting points and should be measured against the reader's own samples.
