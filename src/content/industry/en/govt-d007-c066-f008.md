# Declaration Materials and File Review for Advanced Chemical Materials: Document Parsing and Chunking

## What the Data for This Category Looks Like
Declaration materials and file review data for advanced chemical materials come from four main sources: enterprise R&D ledgers, third-party authoritative test reports, patent application documents, and government compliance declaration forms.
Data updates align with project declaration milestones. Bulk updates occur concentrated during the declaration period.
Document structures include fixed-format application forms, performance test pages with values and dedicated units, compliance documents with digital signatures, and scanned original records.
Fields include material grades, performance parameters, declaration batches, and compliance numbers.
Units include standard and industry-specific terms such as MPa, g/cm³, and molar concentration.

## Constraints on Document Parsing and Chunking
Document characteristics for this category create multiple parsing and chunking constraints:
- A large volume of performance data is tied to dedicated units. Single data sets must not be split during chunking to preserve their complete association.
- Some documents are PDFs with digital signatures. Parsing tools must retain signature metadata. Lost metadata interrupts content recognition.
- Single file sets range from a few pages of application forms to dozens of pages of combined reports. Chunking must adapt to document units of varying lengths.
- Most declaration materials upload in batches. The system must handle large file parsing within set duration and size limits to avoid mid-process failures.

## Configuration Settings
These configuration items work with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Advanced chemical material declaration materials contain dense performance parameters and compliance clauses. This range avoids splitting that breaks the integrity of a single set of data or clause |
| `chunkSplitter` | By paragraph + semantic boundary | The logical units of declaration materials are mostly paragraph-style test descriptions and compliance commitments. Splitting by semantic boundaries preserves contextual association |
| `customPdfParse` | Enable signature retention mode | A large number of materials carry digital signatures. Enabling this mode avoids incomplete content recognition caused by lost signature metadata during parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | A single complete file set may include multiple test reports and patent attachments. This upper limit covers most bulk declaration scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large file set parsing requires a longer duration. This duration avoids mid-process timeout interruptions |
| `chunkSettingMode` | Custom mode | Adjustment of chunking rules is required for different document types (application forms, test reports). Custom mode supports flexible configuration |

## Three Common Configuration Mistakes
- Symptom: A PDF with a digital signature is uploaded. The parsing result contains no valid text content. Cause: The signature retention mode for `customPdfParse` is not enabled. The parsing tool strips signature metadata, interrupting content recognition.
- Symptom: The knowledge base API returns a reading link. Clicking the link produces a specified error message. Cause: `UPLOAD_FILE_MAX_SIZE` is not configured to support large file sets. Links generated after uploaded files exceed the limit cannot be accessed normally.
- Symptom: A normally parsing document is uploaded. The large model’s generated answer does not include performance chart content from the document. Cause: Chunking does not preserve image contextual association, or parsing does not extract auxiliary text descriptions for images.

## How to Verify Correct Configuration
- A test PDF with a digital signature is uploaded. The parsing result is checked for complete body text and signature metadata.
- A large file set exceeding 500 MB is uploaded. The parsing process is monitored for timeout prompts.
- `chunkSize` is set to 1000 characters. A document containing continuous performance parameters is uploaded. The chunking result is checked for unbroken single parameter entries.
- The knowledge base API is called to generate an answer. The answer is verified to include auxiliary image descriptions from the document.

The values provided are common starting points and should be measured against the reader's own samples.
