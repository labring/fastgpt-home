# Declaration Materials and File Review for Advanced Chemical New Materials: Model Integration and Configuration

## What this category of data looks like
Declaration materials and file data for advanced chemical new materials primarily come from internal enterprise project declaration systems, industry regulatory authority filing documents, and composition and performance reports issued by third-party testing institutions. Data update frequency follows project timelines. There are no frequent daily updates after batch uploads for a single declaration project. Updates only occur when supplementary materials are submitted during project review nodes.

Each individual file includes modules such as the project basic information sheet, raw material composition test report, process flow diagram, safety assessment report, and production capacity calculation sheet. Fields include molecular weight (unit: g/mol), purity, production capacity (unit: tons/year), declaration date, and file number, among other professional attributes. Most documents use PDF or Word formats.

## What constraints these characteristics impose during model integration and configuration
Single declaration files for advanced chemical new materials are lengthy, and contain a large number of professional terms and non-standard fields. Model integration must support long context processing and professional content recognition.

Data sources are scattered and involve internal sensitive information. Local deployment is required to protect data security, so model calls must be configured with a local proxy.

Declaration files from different projects use inconsistent formats, so multi-format document parsing must be supported. The review process must strictly align with official standards, with high requirements for model generation rigor. The model’s random generation space must be limited.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Single declaration files for advanced chemical new materials often exceed 5000 tokens. This range covers full context to avoid truncating core information |
| `maxTokens` | `4000–6000 token` | Professional review content requires sufficient generation space to ensure complete output of review conclusions and supporting basis |
| `quoteMaxToken` | `2000–3000 token` | Core reference fragments such as raw material test reports and process parameters must be retained to ensure audit logic is traceable |
| `toolChoice` | `auto` | Automatically determine whether to call external document verification tools to adapt to multi-node review requirements for declaration materials |
| `temperature` | `0.2–0.4` | The review process requires rigor. This range reduces random output risks and avoids generating factually inconsistent judgments |
| `AIPROXY_API_ENDPOINT` | `Full address of the local xinference service` | Adapts to the security requirements of local deployment for advanced chemical new material data, preventing leakage of sensitive information |

## Three Common Mistakes
- Phenomenon: The available model list is empty, and locally deployed models cannot be selected. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to point to the xinference service address, or `AIPROXY_API_TOKEN` has insufficient permissions.
- Phenomenon: Model calls take more than 15 seconds, and some requests trigger timeouts. Cause: `maxContext` is set too large, or `maxTokens` exceeds the model's carrying limit, leading to excessive local inference resource usage.
- Phenomenon: Preset document verification logic is not triggered during tool calls. Cause: `toolChoice` is incorrectly set to `none`, which forcibly disables tool call capabilities and fails to adapt to verification requirements for multi-node reviews.

## How to Verify Correct Configuration
- Access the FastGPT v4.17.0 model management page, confirm that the local xinference model appears in the available model list.
- Upload a standard advanced chemical new material declaration file, trigger model review, and check that the generated conclusion covers core fields such as raw material composition and production capacity calculation.
- Configure a tool call test task, confirm that the model can automatically call the preset document verification tool to complete node verification.
- View the interface call log, confirm that the request return status codes for `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are 200, with no permission or connection errors.
