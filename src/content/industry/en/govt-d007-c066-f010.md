# Chemical New Materials Declaration Materials and File Review: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Data for chemical new materials declaration materials and file review comes primarily from internal R&D project ledgers of state-owned and central enterprises, industry standard documents, third-party test reports, and industry and information technology department filing data. Update frequency fluctuates with project declaration cycles: daily updates during concentrated declaration periods, and quarterly synchronization otherwise. Single documents use mixed structures, including structured fields such as material number, R&D batch, and test parameters, plus unstructured content like R&D logs and approval comments. Field units include chemical-specific units such as MPa, ℃, and kg/m³. File documents are stored split by approval stage.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
The mixed document structure of chemical new materials declarations and files requires retrieval to cover both structured fields and unstructured content. This creates a requirement for multi-modal adaptation capabilities in retrieval models. Professional test parameter units and terminology require the retrieval pipeline to use chemical domain embedding models to avoid semantic deviations. The storage method of splitting files by approval stage requires recalling associated materials from the same file during retrieval, to prevent scattered return results. Data incremental fluctuations during concentrated declaration periods require dynamic adjustment of recall limits to prevent resource overload. Wide variations in single document length—from a few-page forms to dozens of pages of test reports—impact matching accuracy for chunked recall.

## How to Set Configurations
These configurations are developed for FastGPT v4.17.0 to support retrieval needs for chemical new materials declaration materials and file review.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Semantic differences between chemical material professional terms are small. An overly high threshold filters valid matching results, while an overly low threshold introduces irrelevant test data |
| `limit` | Top 8 entries | A single file has many associated materials. Prioritize returning high-matching core approval documents to avoid result overload |
| `searchMode` | hybrid | Supports simultaneous retrieval of structured fields and full text, adapting to mixed-format declaration materials |
| `usingReRank` | Enabled | Re-ranks initial recall results using chemical domain semantics to correct semantic deviations from basic retrieval |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplements professional synonyms for declaration materials to improve recall coverage |
| `collectionIds` | Collection IDs grouped by file | Restricts retrieval scope to the file collection associated with the current declaration project, avoiding cross-project interference |

## Three Common Mistakes
- Phenomenon: Clicking the reading link returned by the knowledge base retrieval interface prompts an error message like "Only support .txt, .m". Cause: No parsing plugin is configured for the corresponding chemical document format. Only plain text formats can be previewed; PDF test reports and Excel test data tables cannot render properly.
- Phenomenon: The original storage path of uploaded chemical material declaration documents cannot be located in the knowledge base. Cause: FastGPT's dataset storage mapping configuration is not enabled, or independent storage directories are not set up per file.
- Phenomenon: Retrieval result matching consistency is poor, with large amounts of irrelevant general chemical terminology content. Cause: A reasonable `similarity` threshold is not set, or the `usingReRank` re-ranking logic is not enabled, causing basic retrieval results to mix invalid content.

## How to Confirm Configurations Are Set Correctly
- Upload a typical chemical new materials test report or approval file document, perform targeted retrieval, and verify whether returned results include professional parameters and approval comments from the document.
- Access the retrieval configuration panel, confirm that `searchMode` is set to hybrid and `usingReRank` is enabled, and verify retrieval capabilities for multi-format content.
- Simulate data incremental volume during concentrated declaration periods, adjust the value range of the `limit` parameter, and check whether the number of retrieval results matches the file scale of the current project.
- Check the `collectionIds` configuration, confirm that the retrieval scope only covers files associated with the current declaration project, to avoid returning irrelevant cross-project results.

The values provided here are common starting points and should be measured against the reader's own samples.
