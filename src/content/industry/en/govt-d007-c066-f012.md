# Declaration Materials and Case Review for Advanced Chemical New Materials: Deployment and Upgrade

## What the data for this category looks like
Declaration materials and case review data for advanced chemical new materials mainly come from enterprise R&D ledgers, third-party testing institution reports, and compliance approval declaration documents. Declaration materials include fields such as project name, raw material composition, performance test data, and compliance certification documents. Units cover indicators such as density, tensile strength, and thermal stability. Cases include content such as review nodes, approval opinions, and archive numbers. Most documents are a mix of PDF-format attachments and structured tabular data. The length of individual declaration material documents varies widely, ranging from hundreds of characters to tens of thousands of characters. Data is updated via batch imports during the project declaration phase, with daily review cases archived in batches and no fixed daily update cycle.

## What constraints these characteristics impose on deployment and upgrade
The mixed documents for advanced chemical new material declaration materials and cases have wide length variations and many attachments. Deployments must adapt to large-file storage configurations, and upgrades must retain the original storage path. Batch-imported declaration data requires the database connection pool to support high-concurrency access. Minor differences may exist in the data structure of different batches. Upgrades must maintain compatibility with field mappings for old-version data. Ensure that the dependent storage module configuration is correct when pulling images, to avoid data failure to load due to storage node changes. During upgrades, synchronously update the database connection string to avoid incompatibility between the data structures of new and old versions.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://<admin-user>:<admin-pass>@<db-host>:<port>/fastgpt?authSource=admin` | Stores structured case records and unstructured attachment indexes for advanced chemical new material declarations |
| `REDIS_URL` | `redis://:<redis-pass>@<redis-host>:<port>/0` | Caches temporary review logs and file download tokens to reduce database load |
| `STORAGE_S3_ENDPOINT` | `http://<internal-s3-host>:<port>` | Stores large-volume attachments such as test report PDFs and test data CSV files |
| `DB_MAX_LINK` | `150–250` | Adapts to concurrent access demands for batch declaration data, avoids connection pool exhaustion |
| `FILE_TOKEN_KEY` | `32-digit random hexadecimal string` | Verifies the identity of file download requests, prevents unauthorized access |
| `ROOT_KEY` | `Custom mixed characters with complexity ≥16 bits` | Permissions verification for the backend management interface, protects modification permissions for review configurations |

## Three common errors
- Symptom: Docker pull of the FastGPT image fails, logs show pull timeout or image not found. Cause: Domestic mirror source is not configured, or `STORAGE_S3_ENDPOINT` points to an incorrect address, causing the dependent storage module to fail normal initialization.
- Symptom: After upgrading from 4.9.0 to 4.12.3, attachments from existing declaration data fail to load normally. Cause: Old configuration for `MONGODB_URI` was not backed up and migrated, causing a database connection string change.
- Symptom: Uploaded advanced chemical new material test reports cannot be downloaded, and the page prompts insufficient permissions. Cause: The `FILE_TOKEN_KEY` configuration does not match the key used to generate tokens, causing verification failure.

## How to confirm configurations are correct
- Run the `docker ps` command, confirm that the FastGPT v4.17.0 container is running, and the port mapping matches the port configured in `FE_DOMAIN`.
- Access the domain configured in `FE_DOMAIN`, enter `ROOT_KEY` for successful verification, and enter the backend management interface.
- Upload a PDF of the advanced chemical new material tensile strength test report, use the generated download token to verify normal download.
- Log in to the Redis instance configured in `REDIS_URL`, check that cache keys exist for review logs and tokens, confirm normal connection.
- Check that database connection counts do not exceed the threshold configured in `DB_MAX_LINK`, matching actual concurrent access demands.
