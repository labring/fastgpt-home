# Fertilizer and pesticide declaration materials and case review: workflow orchestration

## What this category of data looks like
Fertilizer and pesticide declaration materials and case review data primarily comes from the agricultural input production enterprise reporting system and testing databases of relevant agricultural and rural affairs ministry inspection institutions. Data updates trigger with each product batch reporting process. A single batch of declaration materials includes multiple types of documents such as basic product information, test reports, and production license certificates. Core fields of a single declaration document include product common name, registration certificate number, active ingredient concentration, and production batch number. Most field units are milligrams per kilogram and milliliters per liter. Case archive files are bound to reporting batches, and the total size of materials associated with a single case varies with the number of reported products.

## What constraints these characteristics impose on workflow orchestration
The batch-based archiving feature of this category requires workflows to split knowledge base association scope by reporting batch to avoid cross-batch data confusion. Multiple attached test reports and certificate files require workflows to support bulk document upload and parsing, and set field format validation rules for each material to ensure units match numeric fields like active ingredient concentration. The variable size of individual case materials requires workflows to adapt dynamically to context length to prevent parsing interruptions from oversized materials. Fixed field naming and unit rules require workflow nodes to pre-set field extraction templates to reduce manual entry errors.

## Three common mistakes
- After workflow runs, the AI response does not reference any declaration documents, and node logs show empty knowledge base search scope. The cause is failure to correctly pass the dedicated knowledge base ID for the current batch via the `variables` parameter, resulting in no binding of corresponding archived materials for the search.
- After uploading multiple test reports, field extraction results lack active ingredient concentration information. The cause is failure to pre-set an extraction template for the corresponding field, and failure to match the fixed field naming rules of this category.
- Uploading a single oversized declaration material triggers an upload timeout error. The cause is failure to set a single-file upload size limit, resulting in oversized attachments exceeding the default bearing threshold of the node.

## How to confirm the configuration is correct
- Upload a single declaration material, check if the field extraction node returns the preset core fields, and verify that the field units match the category rules.
- Pass a test batch knowledge base ID, run the knowledge base search node, and confirm that the search scope is limited to the associated materials of the current batch.
- Upload a test attachment of maximum size, check that the document upload node completes parsing normally, with no timeout or format error prompts.
- View the workflow run logs, confirm that the knowledge base ID passed via the `variables` parameter matches the current batch, with no missing or incorrect parameters.
