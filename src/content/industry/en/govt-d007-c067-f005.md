# Fertilizer and Pesticide Declaration Materials and Case Review: Tool Calling and Plugins

## What Data for This Category Looks Like
Fertilizer and pesticide declaration materials and case data mainly come from the Ministry of Agriculture and Rural Affairs agricultural input registration system, enterprise self-inspection reports, and local agricultural input supervision platforms. The data update rhythm is that newly registered products are synced monthly, and stock compliant data is calibrated quarterly. The document structure of declaration materials includes product basic information forms, active ingredient test reports, field trial data, approval transfer case files, and other components. Core fields include registration certificate number, active ingredient content (unit: g/L or %), production license number, toxicity classification, and residue limit. Case data includes fields such as audit nodes, rectification records, and approval opinions.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
Data sources for this category are scattered, requiring connections to multiple external supervision platforms and internal business systems. Plugins must support cross-database queries for multiple data sources. Differences in data update rhythms require plugins to be configured with scheduled incremental sync tasks to avoid resource occupation from full data pulls. Inconsistent field units in declaration materials and case files require built-in unit conversion logic during tool calling to ensure accurate data matching. Long-text test reports and approval case files require tool calling to support chunked parsing while retaining field associations, to avoid truncation of key information.

## How to Configure Settings
These configurations apply to FastGPT v4.17.0, including settings for core parameters such as `toolChoice` and `functionCall`.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Tool call trigger threshold | 0.7–0.9 | Distinguish scenarios requiring tool calls, and adapt to the long-text and multi-field characteristics of fertilizer and pesticide declaration materials |
| Maximum tokens per single tool call | 8000–12000 token | Cover the core field content of a single declaration material, and avoid truncation of key test data and registration information |
| `toolChoice` | auto | Allow the model to independently determine whether to call a tool, adapting to the dynamic needs of review scenarios |
| Database connection timeout | 30–60 seconds | Adapt to the interface response delay of agricultural input supervision platforms, and avoid tool call failures |
| Maximum number of results returned | Top 3 | Focus on the most relevant registration data, and avoid information overload affecting review judgments |
| `functionCall` | enabled | Enable explicit function call mode to ensure that the parameter format of tool calls complies with the verification rules of fertilizer and pesticide declaration fields |

## Three Common Misconfigurations
- Phenomenon: An error message "Workflow verification failed, please check for missing or empty values, and whether connections are normal" is displayed when using the database connection plugin to connect to PostgreSQL. Cause: The dedicated field mapping for fertilizer and pesticide declaration data is not correctly configured, such as not specifying query conditions for fields including active ingredient content and registration certificate number.
- Phenomenon: The number of results returned after the model calls a tool does not match expectations, for example, only 1 result or more than 5 results are returned. Cause: The maximum number of returned results is not set, or the threshold setting does not align with the association characteristics of agricultural input data, leading to too much or too little returned information.
- Phenomenon: Tool call execution exceeds 15 seconds, triggering a timeout error. Cause: The database connection timeout is not adjusted, or the chunked parsing logic for tool calls is not optimized for long-text declaration materials, resulting in excessively long model waiting times.

## How to Confirm the Configuration Is Complete
- A single standardized fertilizer and pesticide declaration material can be uploaded, and verification can be performed to confirm whether the model automatically triggers tool calls and returns matching agricultural input supervision data.
- Tool call logs can be reviewed to confirm that returned fields include category-specific fields such as registration certificate number and active ingredient content.
- A declaration material with missing key fields can be simulated, and verification can be performed to confirm whether the corresponding tool is triggered for completion or verification.
- The tool call trigger threshold can be adjusted, and verification can be performed to confirm that the model can independently choose whether to call a tool based on text complexity.

The values provided here are common starting points, and validation should be performed against applicable project samples.
