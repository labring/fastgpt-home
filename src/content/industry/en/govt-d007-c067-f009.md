# Fertilizer and Pesticide Declaration Materials and Case Review: Model Access and Configuration

## What This Category of Data Looks Like
Data for fertilizer and pesticide declaration materials and case review comes primarily from the Ministry of Agriculture and Rural Affairs official registration platform and archived files from provincial agricultural law enforcement departments. Update cycles align with new registration application submissions, existing registration certificate renewals, or the release of compliance inspection results.
Each case typically includes three document types: application forms, ingredient test reports, and production qualification certificates. The structure splits into a structured field area and a long text description area. Structured fields include active ingredient percentage, registration certificate number, and production license number, with corresponding units such as %, g/L, and mg/kg. Long text sections include test method explanations and compliance self-check descriptions.

## Constraints for Model Access and Configuration
The data characteristics above impose three constraints on model access configuration.
First, mixed structured and long-text document structures require models to support both field extraction and long-text compliance verification, and adapt to mixed-format processing logic.
Second, industry-specific unit and field naming rules require models to accurately match these rules during processing, to avoid unit identification deviations.
Third, non-fixed-frequency data source updates require the configuration to support regular synchronization of the latest compliance standards and registration information, to ensure review results align with current policy requirements.

## How to Set Configuration
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `maxContext` | 8000–12000 token | Adapts to the total length of multiple spliced declaration documents, avoiding truncation of core compliance verification information |
| `maxTokens` | 4000 token | Controls the output length of a single review round, matching the detail level required for page-by-page case verification |
| `quoteMaxToken` | 1500 token | Limits the length of referenced declaration material fragments, ensuring only content directly related to review items is extracted |
| `toolChoice` | auto | Automatically triggers field extraction and compliance verification tools, adapting to mixed-structure document processing |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensuring consistency of review results and meeting the strict requirements of compliance reviews |
| `AIPROXY_API_TOKEN` | Bind dedicated service key | Ensures call permissions are only used for review tasks in this scenario, to safeguard data security |

## Three Common Configuration Mistakes
- Unit identification deviations appear in review results, such as incorrectly identifying "g/100g" as "mg/kg". This occurs because the `maxContext` parameter is not adjusted for mixed-structure documents, causing unit description fragments to be truncated. The model cannot fully match industry standard unit rules as a result.
- During multi-round case review, subsequent questions cannot associate details of previously confirmed declaration materials. This occurs because insufficient `maxContext` length is configured, so historical conversations and uploaded declaration document context are not retained.
- Interface calls return an HTTP 403 status code. This occurs because `AIPROXY_API_TOKEN` is not filled correctly, or the configured access node does not meet the compliance call requirements for this scenario.

## How to Verify Proper Configuration
- Upload a standard fertilizer and pesticide registration application form, and confirm the model correctly extracts specified fields such as registration certificate number and active ingredient content, with no unit identification deviations.
- Initiate two consecutive review questions, and confirm the second question can associate details of the declaration material mentioned in the first round.
- After verifying the `AIPROXY_API_TOKEN` configuration, confirm the interface call returns normal review results with no permission-related errors.
- View the declaration material fragments referenced by the model, and confirm the fragment length meets the set requirements, with no irrelevant content included.
