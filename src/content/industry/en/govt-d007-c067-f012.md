# Fertilizer and Pesticide Declaration Materials and Case Review: Deployment and Upgrade

## What this category’s data looks like
Data for fertilizer and pesticide declaration materials and case review primarily comes from the Ministry of Agriculture and Rural Affairs official registration database, enterprise-submitted filing documents, and third-party quality inspection reports. Data updates follow the issuance of new pesticide registration certificates and annual filing cycles, with no fixed batch update window. Each individual case includes structured metadata and unstructured attachments. Structured fields include registration certificate number, active ingredient content, production license number, and applicable crop scope. Units include kilograms, milliliters, milligrams per kilogram, and others. Attachments are typically dozens of pages of field test reports and safety assessment documents.

## What constraints these characteristics impose on deployment and upgrade
Because data includes structured metadata and long-text attachments, deployment requires simultaneous configuration of adaptation rules for both vector retrieval and structured data storage. No fixed update windows require upgrade processes to support incremental synchronization, preventing full updates from consuming excessive resources. Different entities use varying units for content fields, so preset mapping rules must be configured to avoid incorrect results caused by unit mismatches during retrieval. As a chemical category for state-owned and public sector enterprises, data compliance requirements must align with domestic storage node specifications. Upgrade processes must include simultaneous verification of storage configuration compliance.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | `https://s3.cn-north-1.amazonaws.com.cn` | Fertilizer and pesticide declaration data involves agricultural compliance information, and domestic compliant storage nodes must be used to ensure data localization compliance |
| `REDIS_URL` | Domestic Redis instance address with memory no less than 8 GB | A large number of declaration material metadata retrieval results need to be cached to ensure response speed for multi-user concurrent access |
| `DB_MAX_LINK` | `50–80 connections` | Single-instance connection count must adapt to concurrent requests for batch case review, avoiding task interruptions caused by exhausted connections |
| `MONGODB_URI` | Domestic MongoDB cluster address with read-write separation configuration | A large number of structured declaration case metadata need to be stored, and read-write separation balances retrieval and write performance |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string key | Used to encrypt access tokens for declaration materials, preventing unauthorized access to sensitive compliance data |
| `ROOT_KEY` | Configure a random secure key during initial deployment, hide it after deployment | Used to initialize system administrator permissions, avoiding unauthorized access after leakage |

## Three Common Mistakes
- Phenomenon: Pulling the FastGPT image in a Linux environment times out, even after configuring a domestic mirror source. Cause: The archive package for fertilizer and pesticide declaration data has a large volume, and the image layer contains a large number of compliance document samples. Synchronization delays from domestic mirror sources cause pull timeouts.
- Phenomenon: After deployment, the active ingredient content field is empty when retrieving case review results. Cause: Metadata mapping rules are not configured correctly, and the active ingredient units in the declaration materials are not matched to the system’s preset fields.
- Phenomenon: FastGPT deployed via Docker cannot update configurations online. Cause: The local configuration directory is not mounted to the container. Updating the container image overwrites the original configuration file, leading to lost configurations after upgrade.

## How to Confirm Configuration is Correct
- Run the `docker ps` command to confirm that all FastGPT v4.17.0-related containers are in a running state, with no abnormally exited logs.
- Upload a standard fertilizer and pesticide declaration material, check whether metadata fields are correctly extracted and stored in the specified database.
- Initiate a batch case review task, confirm that no connection timeout errors are returned in retrieval results, and the number of results matches expectations.
- Access the configured `FE_DOMAIN` frontend address, log in to the system and verify that administrator permissions function normally.

The values provided are common starting points and should be measured against the reader's own samples.
