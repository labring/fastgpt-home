# Pharmaceutical Distribution: Declaration Materials and File Review — Document Parsing and Chunking

## What the Data for This Category Looks Like
The data for pharmaceutical distribution declaration materials and file review mainly comes from archived documents for pharmaceutical business qualification filing, compliance inspections in circulation links, and cold chain transportation traceability. Data updates are triggered by single declarations or annual qualification audits. A single declaration package may include multiple scanned qualification certificates, structured inventory and sales ledgers, and long-form compliance explanations. Document structures mix editable text and scanned files, with fields including generic drug names, approval numbers, circulation scopes, and cold chain temperature thresholds. Units involve exclusive identifiers such as boxes, cases, and document batch numbers.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Link
The mixed format and structured characteristics of pharmaceutical distribution declaration materials impose multiple constraints on document parsing and chunking. First, a large number of scanned qualification documents require enhanced PDF parsing capabilities to avoid extracting only blank text. Second, multi-column structured data from inventory and sales ledgers requires independent chunking and multi-vector storage to prevent loss of field associations. Third, a single declaration package may include dozens of pages of long documents, which requires adapting to longer parsing and chunking times to avoid mid-process interruptions. Finally, the exclusive field format requires that parsed chunks retain the binding relationship between fields and corresponding text, to ensure accurate matching in subsequent review links.

## How to Configure Settings
| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| `customPdfParse` | Enabled | Pharmaceutical distribution declaration materials contain a large number of scanned qualification documents and mixed-format PDFs, requiring MinerU enhanced parsing capabilities |
| `UPLOAD_FILE_MAX_SIZE` | `500–1000 MB` | A single file review package may contain multiple qualification scans and inventory and sales ledgers, requiring support for large file uploads |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Long file review documents take longer to parse, avoiding parsing interruptions caused by default thresholds |
| `chunkSize` | `800–1200 characters` | Pharmaceutical distribution declaration materials contain structured fields and long-form explanations, with chunk length adapted to field associations and contextual completeness |
| `chunkSplitter` | Split by paragraph + table | Balances chunking accuracy for text paragraphs and inventory and sales tables, retaining the binding relationship between fields and text |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for pharmaceutical distribution-specific document structures; automatic adaptation mode is not required |

## Three Common Misconfigurations
- Issue: Knowledge base parsing status shows failure, with logs returning PDF parsing timeout. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted, and long file review document parsing time exceeded the default threshold.
- Issue: Extracted table data after parsing only contains a single column vector, with field associations lost. Cause: The table splitting rule for `chunkSplitter` was not configured, and table multi-vector support was not enabled.
- Issue: MinerU cannot be called by FastGPT after local deployment, and PDF enhanced parsing cannot be enabled in the plugin. Cause: The `customPdfParse` option was not checked in the knowledge base settings, and the local API access address for MinerU was not configured.

## How to Verify Configurations Are Correct
- A scanned pharmaceutical qualification PDF may be uploaded, and the parsed result checked for complete qualification fields and scanned text.
- The knowledge base settings page of FastGPT v4.17.0 may be accessed, with confirmation that `customPdfParse` is checked and the local API port for MinerU is correctly configured.
- A document containing an inventory and sales table may be uploaded, and the parsed result checked for split independent table chunks and associated text chunks.
- A document exceeding the default upload limit may be uploaded, and verification performed that the `UPLOAD_FILE_MAX_SIZE` configuration takes effect, with no upload failure prompts.
