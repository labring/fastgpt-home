# Hazardous Chemical Storage and Transportation Declaration Materials and File Review: Workflow Orchestration

## What data for this category looks like
Data for hazardous chemical storage and transportation declaration materials and file review primarily comes from enterprise storage and transportation management systems, local emergency management department filing databases, and carrier qualification archives. New files are generated in real time with each individual storage and transportation task. Filing data is updated quarterly.
The document structure of a single file includes basic hazardous chemical information (name, CAS number, storage and transportation volume), qualification verification documents, approval circulation records, and on-site inspection metadata. Fields include storage tank number, filing number, carrier unified social credit code. The unit for storage and transportation volume is tons. CAS numbers follow a 10-character format.

## What constraints these characteristics impose on workflow orchestration
Real-time generated files require workflows to support triggering startup upon completion of a storage and transportation task, to avoid ineffective scheduled runs. Multiple data sources require workflows to be configured with cross-node data pulling, to connect separately to enterprise systems, filing databases, and qualification archives. Fixed field formats for CAS numbers and storage and transportation volumes require workflows to include format verification nodes to filter invalid data. Quarterly updated filing data requires workflows to be configured with a knowledge base synchronization node for regular updates, to ensure verification bases are up to date. File content includes on-site inspection metadata, requiring workflows to support associated image verification nodes to confirm consistency between on-site photos and declared information.

## How to set configurations
The following configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Triggered by storage and transportation task completion event | Matches real-time generated file data, avoids ineffective scheduled runs |
| Field Verification Node | Embed CAS number and storage and transportation volume format verification | Filters invalid files that do not comply with hazardous chemical storage and transportation declaration specifications |
| Knowledge Base Synchronization Cycle | 90 days | Matches the quarterly update rhythm of local emergency management department filing data |
| Variable Binding | Bind hazardous chemical name and storage and transportation volume fields in `variables` | Accurately reads core business parameters from declaration materials |
| Node Timeout Setting | 600 seconds | Adapts to the average response duration for pulling data across enterprise systems and filing databases |
| Tool Call Output | Return only review conclusions, hide tool details | Complies with formal output requirements for file review |

## Three common configuration mistakes
- Workflow code execution node run logs show normal output, but the specified reply node’s output fields are empty. This occurs when the output of the code execution node is not bound to `variables` or the input parameters of the specified node, resulting in interrupted data links.
- After configuring knowledge base synchronization, filing data is not updated, and node run logs show synchronization failure. This occurs when the synchronization cycle is not set to match the filing data update rhythm, or when knowledge base data source connection permissions are not correctly configured.
- Tool call module output is forcibly displayed in audit results, and cannot be hidden. This occurs when the tool output switch is not turned off in the workflow’s specified reply node, or when output rules to return only review conclusions are not configured.

## How to confirm configuration is complete
- Manually trigger a simulated storage and transportation task file, check whether the workflow starts automatically, and confirm that verification, data pulling, and review processes all complete normally in node run logs.
- Check the knowledge base synchronization logs to confirm that filing data has been updated according to the 90-day cycle.
- View the workflow’s node run logs to confirm that core fields in `variables` have been correctly read and passed to subsequent nodes.
- Trigger the tool call node, confirm that the review result only returns conclusion content, with no additional tool call details displayed.
