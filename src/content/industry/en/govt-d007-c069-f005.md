# Hazardous Chemicals Storage and Transportation Declaration Materials and File Review: Tool Calling and Plugins

## What the data for this category looks like
Hazardous chemicals storage and transportation declaration materials and file data primarily come from internal enterprise storage ledgers, hazardous chemicals filing systems of emergency management departments, and upstream and downstream transportation commission documents.
Data update cadence: storage ledgers are synchronized daily, filing data is updated quarterly, and transportation documents are generated per batch of transport.
Document structure includes fields such as the unified social credit code of the declaring entity, hazardous chemical name, CAS registry number, storage volume (unit: ton or cubic meter), transport route, approval node number, and file number. Some files include PDF-format on-site inspection record attachments.

## What constraints these characteristics impose on tool calling and plugins
Core verification fields in the data are CAS numbers and storage volume. When calling tools, field names and units must be strictly matched to avoid query failures caused by format errors.
Real-time updated storage ledgers require tools to pull the latest dataset. Caching should not be used, otherwise expired data will be returned.
Files include multi-page approval records and attachments. Tool calling must support batch pulling of associated documents and parsing PDF attachments.
Additionally, the field format of emergency management department filing data is fixed. Tool calling parameters must align with the interface fields of the filing system, otherwise valid data cannot be retrieved.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Hazardous chemical declaration materials include structured fields and unstructured attachments; automatic tool selection better adapts to multi-type content |
| `functionCall` | Enabled | Database calls are required to query storage specifications corresponding to CAS numbers; function calls can accurately trigger data pulling |
| Tool call timeout | 30-60 seconds | Must wait for responses from the emergency management filing interface and local storage ledgers; prevents timeout caused by large data volumes |
| Number of returns per tool call | Top 10 entries | File review requires matching the latest 10 approval records; excessive entries will consume context space |
| Database connection timeout | 20 seconds | Database queries for hazardous chemical data need fast responses to avoid blocking review processes |

## Three Common Mistakes
- Symptom: No output after calling the database connection tool; logs show SQL query conditions are empty. Cause: The hazardous chemical CAS number field is not correctly bound to the tool's parameter variables, resulting in missing query conditions.
- Symptom: Timeout error triggered when calling tools in the workflow; logs show requests exceed configured thresholds. Cause: Tool call timeout is set too short, not adapting to the response delay of the emergency management filing interface.
- Symptom: Storage volume data returned by the model after tool calling has mixed units, with tons and cubic meters confused. Cause: No field unit verification rules specified in tool call configurations, leading to mismatched parameter formats.

## How to Confirm Proper Configuration
- Manually trigger tool calling, input a known hazardous chemical CAS number, and verify whether the returned database query results match the local ledger.
- Submit test declaration materials, and check whether tool calling automatically triggers the corresponding SQL query and document parsing steps.
- Review tool call logs to confirm that variable parameters are correctly passed to the SQL statement, with no null values or format errors.
- Simulate approval node switching, and verify whether tool calling can pull corresponding file data based on the current node.
