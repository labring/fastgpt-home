# Hazardous Chemicals Storage and Transportation: Declaration Materials and File Review — Citation Source and Traceability

## What this category of data looks like
Data for hazardous chemicals storage and transportation declaration materials and file reviews comes primarily from internal enterprise storage and transportation ledgers, emergency management department filing documents, carrier qualification documents, and loading and unloading operation records. There are two update frequency categories: daily storage and transportation ledgers are updated daily, while filing documents and qualification documents are updated when their content changes or during quarterly inspections.
Document structure includes structured forms with fields such as hazardous chemical UN number, CAS number, storage temperature, transportation route, and unstructured attachments such as test reports and scanned transporter qualification certificates. Field units include professional formats such as ℃, tons, cubic meters, and compliance level numbers.

## What constraints do these characteristics impose on the citation source and traceability link?
Decentralized data sources require traceability to associate multiple system data sources. Accurate matching of hazardous chemicals-specific codes is necessary to prevent irrelevant results from being included. The coexistence of structured fields and unstructured attachments requires traceability tools to support both field-level matching and text fragment extraction.
Differences in update frequencies require verifying data timeliness during traceability, to avoid referencing expired filings or outdated ledger data. Fixed formats for professional fields require traceability results to accurately display codes such as UN number and CAS number, otherwise they cannot meet review and verification requirements.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Core citation content for hazardous chemicals declaration materials, such as test reports and transportation plans, falls within this length range, and can cover key information for a single review |
| `responseData` | `return top 6 matching sources` | A single file review requires associating multiple supporting materials, and 6 entries can cover all relevant basis for common review scenarios |
| `detail` | `enable full field traceability` | Hazardous chemical reviews require verification of professional fields such as UN number and storage temperature. Full traceability can extract and display corresponding structured data |
| Source data timeliness verification | `match update cycle by data type` | Filing documents are updated quarterly, while daily ledgers are updated daily. The latest status of traceability data must be verified accordingly |

## Three Common Errors
- Phenomenon: Irrelevant documents from non-hazardous chemical categories are mixed into citation results. Cause: No professional code matching rules are configured. Only text keyword matching is used during retrieval, and exclusive fields such as UN number and CAS number are not filtered.
- Phenomenon: Locally uploaded file records cannot be loaded when calling the review node in a custom workflow. Cause: The tool only supports source data in public link format during tool invocation, and cannot directly reference files with local variable paths.
- Phenomenon: Hazardous chemical professional fields such as UN number are missing in traceability results. Cause: The `detail` configuration item is not enabled. Only unstructured text content is captured, and structured field information is not extracted.

## How to Confirm the Configuration Is Properly Set
- Submit a review request that includes a clear UN number, and check whether the structured field information of the corresponding filing document is included in the citation results.
- Check the FastGPT v4.17.0 runtime logs to confirm that the returned citation token count falls within the `800–1200 token` range.
- Test the custom workflow invocation to confirm that only source data in public link format can be uploaded, and files with local variable paths cannot be directly referenced.
- Trigger a review request for expired filing data, and confirm that the update time and timeliness status of the data are marked in the traceability results.
