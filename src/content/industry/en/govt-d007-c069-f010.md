# Hazardous Chemical Storage and Transportation Declaration Materials and File Review: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for hazardous chemical storage and transportation declaration materials and file review comes primarily from internal enterprise storage and transportation ledgers, safety supervision department filing and approval documents, hazardous chemical safety data sheets (MSDS), daily operation records, and compliance files.
Data update rhythm falls into two categories: Daily operation records update in real time alongside daily storage and transportation operations. Filing documents update with approval nodes or quarterly compliance inspections.
Document structures include fixed professional fields: general hazardous chemical name, CAS registration number, storage bin number, approval document number, validity period, flash point, explosion-proof grade. Units include professional measurement standards such as tons, cubic meters, degrees Celsius, and megapascals.

## Constraints on knowledge base retrieval and recall
Professional fields and terms require retrieval to match professional expressions accurately, avoiding generalized recall of irrelevant content.
Document lengths vary widely: Some short approval documents are fewer than 500 characters, while full storage and transportation plans can exceed 100,000 words. This requires adapting chunking and retrieval logic for different lengths.
Differences in update rhythms require synchronization mechanisms to distinguish real-time incremental updates from periodic full updates, avoiding data lag or redundancy.
Strict compliance requirements mean retrieval results must cover all compliance clauses needed for approval, with no key field information omitted.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirement for hazardous chemical professional terms, filters irrelevant documents with low matching scores |
| `limit` | Top 10 entries | Covers the typical number of items in a single declaration review, controls total context length |
| `searchMode` | Vector search + keyword hybrid | Adapts to dual retrieval needs for structured fields and professional terms |
| `usingReRank` | Enabled | Runs secondary ranking on initial recall results to correct content with mismatched professional terms |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates supplementary compliance-related extended query terms to match implicit requirements in filing documents |
| `collectionIds` | Fill in using actual deployed knowledge base collection IDs | Limits retrieval scope to prevent cross-category data from interfering with results |

## Three common configuration errors
- API calls to pull the document library return parameter errors. Cause: The `collectionIds` parameter is not configured correctly, or the passed collection ID does not match the actual deployed knowledge base.
- After upgrading to FastGPT v4.17.0, clicking the knowledge base file details page displays the "Invalid dataset file key" error. Cause: The knowledge base file key mapping was not resynced after the upgrade, or the old version file index was not fully migrated.
- Retrieval time increases significantly under the same knowledge base. Cause: Redundant extended query configurations are not disabled, or the `similarity` threshold is set too low, resulting in too many invalid documents being recalled.

## How to confirm the configuration is correct
- Enter a professional search term, such as "storage approval requirements for a hazardous chemical", and check if returned results include fields like the approval document number and storage conditions of the corresponding filing document.
- View the retrieval log to confirm the `similarity` parameter is active, and that returned result matching degrees fall within the preset range.
- Call the API pull interface, pass the correct `collectionIds`, and verify that the document list for the specified knowledge base can be retrieved normally.
- Simulate a post-upgrade operation scenario, check that the knowledge base file details page shows no errors, and confirm that the key mapping has been updated.
