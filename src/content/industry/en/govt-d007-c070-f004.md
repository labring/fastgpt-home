# Declaration Materials and File Review for Power Generation Equipment Manufacturing: Workflow Orchestration
This page’s configuration instructions apply to FastGPT v4.17.0.

## What this category of data looks like
Declaration materials and file review data for power generation equipment manufacturing mainly come from enterprise PLM systems, factory quality inspection reports, local regulatory filing documents, and project approval documents. Data updates follow project node timelines. Full sets of declaration materials for a single unit are fully updated before factory shipment. Most documents are long texts with multi-level heading structures. They include fixed fields such as rated power (unit: MW), inspection batch number, and service life, as well as multi-page process description and compliance certificate attachments.

## What constraints do these characteristics impose on the workflow orchestration link
The long-text structure of power generation equipment declaration materials requires workflow document chunks to adapt to multi-level headings. This avoids losing parameter associations after splitting. The standardization requirement for fixed fields requires binding specific fields via `variables` to simplify audit and verification steps. The cross-department approval process requires workflow nodes to flow through links such as project initiation, quality inspection, and filing. Node identifiers must be clearly defined via `nodeId`. The node-based data update requirement means trigger timing must match the fixed window after project upload is completed. This avoids repeated triggers and process confusion.

## Three common errors
- Phenomenon: Parameter matching failures occur during retrieval after using #/##/### heading symbols as long document separators. Cause: Power generation equipment declaration materials have multiple multi-level heading tiers. Using only basic heading symbols for separation causes incorrect chunk boundaries. This makes it impossible to identify specific parameter fields.
- Phenomenon: Links generated after publishing the workflow point to local addresses. Cause: The public network domain name of the deployment environment was not configured. Only the default local startup address was used.
- Phenomenon: The process stalls after the tool call node is executed. Cause: The fields corresponding to `variables` were not correctly bound. This results in empty parameter transmission and failure to trigger subsequent nodes.

## How to confirm the configuration is complete
- Upload a typical power generation equipment declaration document. Check whether the chunked content retains complete equipment parameter paragraphs.
- Trigger the workflow. View the node flow log to confirm that the approval links corresponding to `nodeId` are executed in sequence.
- Test the variable extraction function. Verify that the fields bound by `variables` can be accurately extracted from the document.
- Access the published link. Confirm that it can be opened normally and initiate conversations without local address errors.
