# Declaration Materials and File Review for Power Generation Equipment Manufacturing: Document Parsing and Chunking

## What this type of data looks like
Data for declaration materials and file review in power generation equipment manufacturing mainly comes from project establishment applications, equipment design drawings, type test reports, manufacturing logs, and approval files. Update frequency follows project progress: documents are submitted in bulk during the project establishment phase, and revised on demand during the manufacturing phase. Most documents are PDF technical descriptions, structured CSV parameter logs, and some Word approval documents. Fields include equipment model, rated power, heat rate, manufacturing serial number, approval document number, and more. Units include megawatts, percentage, hours, sets, and more.

## What constraints do these characteristics impose on document parsing and chunking
Documents for declaration materials and file review in power generation equipment manufacturing have multiple structural differences. Long technical descriptions are bound to structured parameter tables. Standard chunking may split parameters and their corresponding descriptions, which affects field matching for subsequent file review. A single declaration file may include multiple test reports, resulting in a long total document length. This carries a risk of parsing timeout. A large number of project documents are submitted in bulk. Single files may exceed upload limits. Different document types have widely varying chunking needs, making uniform chunking rules difficult to adapt to all scenarios. Additionally, approval opinions in declaration materials must be bound to corresponding equipment parameters. Chunking must retain contextual associations to avoid splitting that breaks matching between related information.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 1000–1500 characters | The document lengths of power generation equipment declaration materials vary widely. This range balances contextual completeness and chunk granularity, and avoids exceeding a reasonable number of chunks per file |
| `chunkSplitter` | Prioritize paragraphs + headers | Documents include structured parameter tables and long technical descriptions. Splitting by paragraph preserves the association between parameters and their corresponding descriptions, preventing separation. For example, a turbine heat rate parameter and its corresponding test conditions are not split into different chunks |
| `customPdfParse` | Enabled | Power generation equipment PDF documents contain a large number of technical drawings and parameter tables. Enabling custom parsing preserves table structure and line break formatting, improving the accuracy of subsequent field association |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | A single declaration file may include multiple test reports, resulting in long parsing times. This range prevents task failure due to parsing timeout |
| `chunkSettingMode` | Manual mode | Different types of declaration documents (such as test reports, approval files, parameter logs) have large structural differences. Manual configuration allows adjusting chunking rules for individual documents, adapting to the structural needs of all document types |

## Three Common Misconfigurations
- Console error `Cannot redefine property: toString at Object.defineProperty`: Custom PDF parsing scripts conflict with built-in system parsing rules. Incorrect configuration of custom parsing parameters for `customPdfParse` results in a property redefinition error.
- A single declaration material exceeds 3000 chunks after splitting, preventing indexing: `chunkSize` is set too small. Chunk granularity is not adjusted based on document length, causing the number of chunks to exceed the system default limit.
- After upgrading to FastGPT v4.17.0, chunking of previously parsable CSV files fails: `chunkSettingMode` remains in automatic mode. The new version’s parsing logic has changed for structured CSV data, and configurations are not updated accordingly.

## How to Confirm Correct Configuration
- A single power generation equipment test report PDF is uploaded. The parsed chunk list is reviewed to confirm that table headers and content are not split into different chunks, and that the association between technical descriptions and corresponding parameters is preserved.
- Parsing logs are reviewed to confirm that no timeout errors occur after applying the `PARSE_FILE_TIMEOUT_SECONDS` configuration, and that single document parsing succeeds.
- `chunkSize` is adjusted, then the number of chunks is counted. The system does not trigger a chunk count limit warning.
- A CSV-format parameter log is uploaded. The association between equipment models and their corresponding parameters is preserved after chunking.

The values provided are common starting points and should be measured against the reader's own samples.
