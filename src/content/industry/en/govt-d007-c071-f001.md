# Declaration Materials and Case Review for Power Generation Groups: HTTP Interfaces and External Systems

## What this category of data looks like
Data for declaration materials and case review for power generation groups comes from internal business systems such as production management, fuel control, and safety supervision. Data updates trigger alongside business nodes. The update cycle for a single batch of declaration materials runs 1 to 7 days. Case data generates in real time during the review process.

The document structure includes fields such as the unified social credit code of the declaration subject, unit rated capacity, monthly fuel consumption, compliance document number, and review node transfer records. Field units include megawatt (MW), ton, and YYYY-MM-DD format timestamps, among others.

## What constraints these characteristics impose on HTTP interfaces and external systems
Declaration data for power generation groups comes from dispersed sources. It covers multiple internal business systems including production, fuel, and safety supervision. A single case may contain multi-page scanned documents, with wide differences in file size. This requires HTTP interfaces to support multi-source data docking and large file transmission.

Update rhythms vary across different business data. Declaration materials update in batches. Case data generates in real time during the review process. Trigger mechanisms for real-time and batch requests must be distinguished.

Fields include specific units and standardized formats. Interface requests must carry unified field mapping rules to avoid review failures caused by format mismatches. In addition, internal systems of power generation groups usually enforce strict authentication and current limiting requirements. Configurations must adapt to enterprise-level security specifications.

## How to set configurations
This document is written based on FastGPT v4.17.0. All following configurations are compatible with this version.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {Internal System API Key} | Internal business systems of power generation groups uniformly use Bearer Token authentication to secure interface calls |
| Request timeout | 600 seconds | Accommodates transmission and parsing time for large single-case files, including multi-page scanned documents |
| `variables` | Map internal system fields to `Declaration Subject`, `Unit Rated Capacity` | Standardizes FastGPT context variable formats to match field verification rules for review processes |
| `responseData` | Only return `Review Conclusion`, `Compliance Status` fields | Filters invalid data to reduce data processing loads on external systems |
| Batch request frequency | Once every 120 seconds | Aligns with the batch update rhythm of power generation group declaration materials, and avoids triggering internal system current limits |

## Three common configuration mistakes
- Phenomenon: External case data cannot be read after configuring the `CUSTOM_READ_FILE_URL` environment variable. Cause: The `Authorization` parameter is not configured correctly, so the internal system rejects the interface call request.
- Phenomenon: An empty reference list returns first when calling the chat interface. Cause: The `variables` field mapping is not configured correctly. FastGPT cannot retrieve standardized declaration data from the external system, so it cannot generate valid reference content.
- Phenomenon: Excessive response delay occurs after the external system calls the interface. Cause: The request timeout is not adjusted, and the batch request frequency is too high. This triggers internal system current limiting, which increases data transmission and processing time.

## How to confirm the configuration is complete
- Initiate a single HTTP request. Check if the returned `responseData` field includes preset review-related fields.
- Log in to the FastGPT backend. Review environment variable configurations to confirm the `Authorization` parameter key matches the one assigned by the internal system.
- Trigger a batch update request. Check the internal system’s monitoring logs. Adjust the request frequency after confirming no current limiting errors occur.
- Submit a test declaration material. Check if the review context generated by FastGPT includes correctly mapped `variables` field content.
