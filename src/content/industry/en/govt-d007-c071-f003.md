# Power Generation Group Declaration Materials and Case Review: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data sources for power generation group declaration materials and case review include internal production management systems, project declaration archive libraries, and power industry regulatory filing documents. Updates follow individual declaration project cycles or monthly regulatory filing requirements.
Document structures include declaration letter bodies, unit operation parameter tables, approval case attachments, and regulatory receipts. Fields include unit number, rated power generation capacity, declaration year, approval document number, and on-site inspection records. Units include professional power industry units such as megawatt-hours, units, days, and percent.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Declaration materials and case data for power generation groups have complex structures, specialized fields, and diverse units. Multi-turn dialogue must precisely match exclusive fields to avoid mixing parameters of different units.
Data updates follow project cycles. Dialogue processes must confirm the latest case version of the current project in real time, and cannot rely on fixed cached data.
Data is scattered across different archive modules. Dialogue processes must support switching knowledge base sources on demand to ensure retrieved content matches the current query’s project scope.
Long declaration materials and cases occupy large context space. Dialogue history retention ranges must be limited to prevent context overflow.

## Three Common Misconfigurations
- 422 status code triggered during dialogue: The symptom is normal knowledge base retrieval but a 422 error returned in dialogue. The cause is failure to correctly bind exclusive fields in `variables`, causing the prompt to fail to match fixed parameters of power generation group declaration materials.
- Multi-turn dialogue context loss: The symptom is subsequent dialogue unable to call unit parameter information submitted earlier. The cause is failure to limit the retention rounds of `messages`, causing early content to be automatically truncated after the context window exceeds its carrying limit.
- Unable to switch knowledge bases for corresponding cases: The symptom is dialogue unable to accurately call declaration cases for a specific unit. The cause is failure to bind the project unique identifier via `chatId`, causing the context to link to incorrect project data.

## How to Verify Correct Configuration
- Launch a simulated declaration dialogue, check if `chatId` is bound to the unique identifier of the corresponding project, and confirm that context association is correct.
- Test continuous multi-turn queries, verify if the retention rounds of `messages` cover the dialogue requirements of the current project.
- Input a query containing specialized power industry terminology, check if the fields bound in `variables` are correctly identified and applied to the prompt.
- Trigger a knowledge base retrieval operation, confirm that the number of results from the single retrieval limit matches the material batch count requirements of the current project.
