# Declaration Materials and Case Review for Power Generation Groups: Workflow Orchestration
*This document is written for FastGPT v4.17.0*

## What the Data for This Use Case Looks Like
Declaration materials and case review data for power generation groups mainly come from internal production and operation systems, fuel management platforms, administrative approval portals, and archive management repositories. There are two update cycles: monthly electricity declaration and fuel consumption declaration are updated monthly, while annual compliance case files are updated via quarterly archiving. The document structure includes fields such as declaration subject information, unit number, power generation ledger, approval node records, and archive number. The unit number follows the fixed format "GD+6 digits", the power generation unit is megawatt-hours, and the approval number is a string with no unified fixed template format.

## Constraints for Workflow Orchestration
Differences in multi-source data formats require built-in format validation nodes in the workflow to adapt to the structure of declaration materials exported from different systems. The monthly and annual update cycles require the workflow to support both scheduled triggering and manual triggering modes to meet the needs of different declaration periods. Specific field formats and units require adding field validation rules to prevent non-standard format materials from entering the review process. The archive attribute of case files requires binding an archive synchronization node at the end of the workflow to automatically push approved materials to the archive management repository.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Mapping | Bind declaration subject ID, unit number, power generation fields | Match the standard field structure of power generation group declaration materials |
| Node Timeout Setting | 1200 seconds | Cover the material validation and cross-system transfer duration for large case reviews |
| File Upload Validation | Single file size no more than 1000 MB | Adapt to the file size of power generation group unit parameter reports and fuel ledgers |
| `variables` Reference Configuration | Bind preset approval node variables | Enable automatic synchronization of node status from the review process to the archive system |
| `nodeId` Association Configuration | Bind archive node ID | Complete automatic archiving after approval |
| Bulk Pull Limit | Top 20 entries | Adapt to the conventional batch processing scale of monthly declaration materials |

## Three Common Mistakes
- Phenomenon: The workflow throws a `Failed to create post presigned url` error during execution, and the file upload step shows a failed status. Cause: File storage access permission parameters are not configured correctly, making it impossible to generate valid upload signature links.
- Phenomenon: Fields are empty after variable reference in the workflow, and the review node cannot obtain declaration data. Cause: The data source fields corresponding to `variables` are not correctly bound, and the variable mapping does not match the exclusive fields of power generation group declaration materials.
- Phenomenon: The workflow terminates early, and the case review node fails to complete all validations. Cause: The node timeout setting is too small, failing to cover the full processing duration for large case files.

## How to Verify Proper Configuration
- Manually trigger a test workflow, upload a standard power generation group declaration material sample, and check that the file upload step completes normally with no signature errors.
- Import the preset variable mapping rules, verify that the fields referenced in the workflow match the standard fields of power generation group declaration materials, with no empty values or mismatches.
- Adjust the node timeout setting to match the estimated duration of a single review, and verify that the workflow does not terminate early during the review.
- Trigger a batch declaration task, check that the number of pulled data entries matches the preset processing scale, with no missing or over-pulled entries.

The values provided are common starting points and should be measured against the reader's own samples.
