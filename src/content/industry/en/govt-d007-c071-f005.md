# Declaration Materials and Case Review for Power Generation Groups: Tool Calling and Plugins

## What the data for this category looks like
Data comes from internal project declaration systems, safety supervision archives, unit operation and maintenance ledgers, and administrative approval case files of power generation groups. Updates are triggered by project batches. Declared materials are not modified frequently after archiving for a single batch. Case files are finalized and archived monthly. Documents include structured approval forms and unstructured scanned materials. Fields cover project number, unit model, approval document number, declaration date, and rectification item list. Units include megawatts (MW), workdays, and compliance rate percentages. Individual document lengths range from hundreds of characters to tens of thousands of characters.

## What Constraints These Data Characteristics Impose on Tool Calling and Plugins
Mixed structured and unstructured data requires tool calling to support both structured field verification and unstructured content parsing. Avoid calling logic that only adapts to a single data type. Batch-based archiving updates require tool triggering to be bound to project approval nodes. This reduces invalid calls caused by fixed-cycle polling. Fields with specific unit requirements mean tool calling must include built-in unit verification rules. Ensure declared values match approval standard units. Differences in content volume from long documents require tool calling to support dynamic adjustment of the text range processed per call. This avoids context overflow.

## Configuration Settings
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically matches tools for mixed structured and unstructured review data, no manual tool specification required |
| Tool call concurrency limit | `2` | No more than 2 tool calls are associated with a single declaration material for power generation groups, preventing excessive resource usage |
| Tool call timeout threshold | `600 seconds` | Case review involves cross-library retrieval of multiple historical documents, requiring sufficient query response time |
| Maximum text processed per tool call | `8000–12000 characters` | Adapts to the parsing length of single case file scanned materials, avoiding context overflow |
| Tool parameter verification switch | `enabled` | Ensures declared values match approval standard units, preventing incorrectly formatted parameters from being passed to tools |
| `functionCall` | `only triggered at approval nodes` | Binds to project process nodes, reducing resource consumption from invalid tool calls |

## Three Common Mistakes
- Attempting to call 2 tools simultaneously returns a parameter error or only triggers 1 call. The cause is failing to correctly configure `toolChoice` as `auto` or enable multi-tool concurrency support. The default limit restricts single calls to one tool.
- FastGPT API calls fail in some regions such as Henan and Fujian, returning connection timeout or 403 status codes. The cause is failing to configure region-adapted network proxies or whitelist rules, and failing to open API access permissions for the corresponding regions.
- Links returned in streaming output only overwrite the current page when clicked, and cannot jump to a new page. The cause is failing to configure correct link jump parameters in the streaming response, or the front-end rendering logic not handling new window trigger rules.

## How to Confirm the Configuration Is Correct
- Submit a single structured declaration form. Check if the tool call log triggers the corresponding verification tool, and confirm that the call record for the `toolChoice` parameter is normal.
- Initiate API call requests from different regions. Verify connection status and response results, confirming that network and permission configurations meet regional requirements.
- Enable the streaming output function. Test the rendering of returned content and link jump behavior, verifying that the jump logic meets expectations.
- Submit an ultra-long document. Check if tool calls process the content normally, with no context overflow or timeout errors.
