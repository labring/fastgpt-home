# Power Generation Group Declaration Materials and File Review: Citation Sources and Traceability

## What this type of data looks like
Data for power generation group declaration materials and file review comes from internal project declaration ledgers, unit maintenance files, energy consumption declaration documents, environmental approval materials, and similar sources. Update cadence falls into two categories: project declaration documents are updated in real time during the project initiation workflow, while routine files are archived and updated monthly. Documents contain structured fields and attachments. Structured fields include project number, declaring entity, unit model, approval node, and energy consumption data, with units of ten thousand kilowatt-hours and tons of standard coal. Most attachments are PDF and Excel format declaration details and on-site operation records.

## What constraints these characteristics impose on the citation sources and traceability link
The combination of structured fields and mixed attachments requires the traceability process to match both text content and structured identifiers, ensuring cited files or materials accurately correspond to specific projects. Data sources with different update cadences require configured differentiated synchronization strategies to avoid unarchived real-time data or unsynced historical files in the knowledge base. Fixed field and unit requirements demand retaining original units and identifiers during citation to prevent information distortion. Declaration materials associated with multiple units require retrieved citation content to cover all associated file nodes, avoiding missing key review basis.

## Three common errors
- Phenomenon: The returned result does not include specific information about the cited declaration file or material, only generated text is displayed. Cause: The `responseData` configuration is not enabled, and source traceability fields are not mounted.
- Phenomenon: After setting the single retrieval limit to more than 8 entries, search results cannot be properly pushed to the large model context. Cause: Exceeds the preset context carrying limit of the platform, resulting in incorrect context splicing.
- Phenomenon: Uploaded CSV format declaration detail files display garbled characters. Cause: The file was not uploaded in UTF-8 encoding format, or contains non-standard merged table cell content.

## How to confirm the configuration is correct
- Initiate a query for declaration materials that includes a specific unit number, and verify whether the returned result contains structured fields such as the corresponding project number and unit model.
- Check the end of the returned result to confirm whether traceability information such as the archive time and upload source of the cited document is displayed.
- Adjust the single retrieval limit to different values, and verify that the large model context is properly spliced without truncation or loss.
- Upload a test CSV file encoded in UTF-8, and confirm that the preview and downloaded content have no garbled characters.

The values provided are common starting points and should be validated against the actual samples used in deployment.
