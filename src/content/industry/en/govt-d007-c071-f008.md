# Declaration Materials and File Review for Power Generation Groups: Document Parsing and Chunking

## What this category of data looks like
Data for declaration materials and file review from power generation groups comes from official declaration documents such as project grid connection applications, environmental acceptance checks, and qualification assessments, as well as internal archived files. Submissions are concentrated irregularly aligned with project initiation and approval milestones. Single documents contain fixed-format parameter tables, long text description sections, and embedded site photos and equipment drawings. Document fields include fixed information such as professional power units, approval document numbers, and project node times. Some archives bundle multiple associated documents.

## Constraints on document parsing and chunking
Power generation group declaration materials are mostly fixed-format professional documents with continuous parameter tables and long text descriptions. Parsing must retain field associations and semantic integrity. Large-volume archives submitted in batches create parsing time pressure, so support for large files and batch tasks is required. Embedded images and drawings may cause parsing errors, so targeted format compatibility handling is needed. Professional terms and fixed fields must not be incorrectly split, as this will disrupt semantic matching in subsequent review links.

## Configuration settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Aligns with continuous semantics of long text paragraphs and embedded tables in declaration materials, avoiding splitting professional terms such as rated power and grid connection service duration |
| `chunkSplitter` | Paragraph + semantic boundary | Prioritize Markdown headings and tables as chunking anchors, avoiding splitting coherent approval processes or equipment parameter content |
| `customPdfParse` | Enabled | Adapts to fixed headers and footers in power generation group documents (such as group document numbers, approval seals), extracts valid content and reduces invalid interference |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers full parsing time for large-volume file archives (including multi-page drawings and high-definition images), avoiding mid-parsing timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports requirements for uploading single large feasibility study reports or bundled batch archives |
| `chunkSettingMode` | Manual configuration | Adjust chunking thresholds separately for professional power fields to ensure key parameters are not split across chunks |

## Three common configuration mistakes
- Symptom: After uploading a DOCX file containing high-definition equipment photos, the parsing log returns the `Invalid image file` error. Cause: The image adaptation mode of `customPdfParse` is not enabled, or the uploaded image resolution exceeds the default parsing threshold.
- Symptom: When parsing declaration tables exported from a database, only partial column data is captured. Cause: `chunkSplitter` is not configured to split by table semantics, causing the table to be split horizontally and losing field associations.
- Symptom: When uploading annual archives in batches, the parsing task triggers a `slow operation xxxxms` log. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is set lower than the actual parsing time of a single large file, failing to adapt to the large-volume characteristics of power generation group archives.

## How to confirm correct configuration
- Upload a test document containing equipment parameter tables and embedded images, check that the table fields in the parsing result are complete and no image parsing errors occur.
- View the parsing task log to confirm that no timeout alert is triggered for large-volume archives uploaded in batches.
- Compare the chunking results with the original document to confirm that professional terms such as rated power and annual power generation are not split across different chunks.
- Test uploading a large feasibility study report under 1000 MB, confirm that the upload and parsing processes complete normally.
