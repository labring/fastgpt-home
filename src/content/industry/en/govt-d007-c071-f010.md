# Declaration Materials and File Review for Power Generation Groups: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for declaration materials and file review for power generation groups mainly comes from internal project declaration documents and electric power business files. These include grid connection acceptance files, technical transformation project declaration files, coal consumption accounting files, and more. Data updates primarily use batch uploads for single declaration batches. Daily new files are updated via monthly archiving. Individual documents mostly combine structured tables and long text descriptions. They include fields such as project number, unit number, declaration date, approval status, energy consumption data, and compliance clauses. Units include megawatts (MW), standard coal tons (tce), yuan, and natural days.

## What constraints these characteristics impose on knowledge base retrieval and recall
The mixed structure of structured fields and long text requires retrieval to support both semantic matching and precise field filtering. This prevents missing key compliance clauses when using only semantic retrieval.
The batch update rhythm means no real-time synchronization tasks are needed. Knowledge base training can be triggered per archiving cycle.
Business scenarios with high compliance requirements require strictly limiting retrieval scope to only documents exclusive to power generation groups. This prevents the introduction of review materials from unrelated categories.
Individual documents have relatively long lengths. Chunk length must adapt to long text contexts. This avoids excessive chunking that breaks semantic integrity, or overly long chunks that cause context overflow.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches compliance clauses and file details in declaration materials, filters low-relevance retrieval results |
| `limit` | Top 10 entries | Single batches of declaration materials have a large number of entries, controlling recalled entries avoids context token overload |
| `searchMode` | hybrid | Adapts to mixed documents of structured fields and long text descriptions, balances semantic matching and field filtering |
| `usingReRank` | Enabled | Semantic relevance differentiation for long text files is relatively low, re-ranking improves result accuracy |
| `datasetSearchUsingExtensionQuery` | Disabled | Declaration materials and files have fixed business formats, extended queries may introduce unrelated business content |
| `collectionIds` | Exclusive collection ID for power generation group declaration files | Restrict retrieval scope to only the knowledge base exclusive to this category, preventing cross-category data interference |

## Three common mistakes
- Recalled results include review materials from non-target categories: The retrieval results returned by the interface are mixed with declaration documents from other industries. The cause is that the `collectionIds` parameter is not correctly configured, and the retrieval collection scope is not limited.
- Responses include external content not included in the knowledge base: Audit responses include unpublished policies or industry standard content. The cause is that strict knowledge base content restrictions are not enabled, allowing calls to external generation capabilities.
- Export of knowledge base file details fails: The interface call returns empty results or a 404 status code. The cause is that the correct endpoint from the Knowledge Base Interface section is not used, or valid permission parameters are not carried.

## How to verify the configuration is correct
- Upload an exclusive test document, retrieve the exclusive keywords within the document, confirm that the recalled results only come from content within the currently configured exclusive collection.
- Call the knowledge base file details export interface, confirm that the returned results include the names, upload times and file sizes of all uploaded files within the current collection.
- Submit a business question not included in the knowledge base, confirm that the preset custom no-result response is returned.
- View the retrieval log, confirm that the actual effective status of parameters such as `searchMode` and `usingReRank` matches the configured settings.

The values provided are common starting points and should be measured against the reader's own samples.
