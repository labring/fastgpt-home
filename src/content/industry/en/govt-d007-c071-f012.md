# Declaration Materials and Case Review for Power Generation Groups: Deployment and Upgrade
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Declaration materials and case review data for power generation groups mainly come from internal project declaration systems, historical approval case archive libraries, and paper scans uploaded by on-site safety supervisors. The data update rhythm has no fixed cycle. Bulk additions occur during project declaration seasons, with scattered archive supplements on regular days. Single documents are mostly multi-page PDFs or structured tables, containing fields such as project number, rated installed capacity (unit MW), grid-connected power generation, approval node records, etc. Some cases come with attachments like engineering drawings and qualification certificates, in formats including PDF, JPEG, Excel, and others.

## What constraints do these characteristics impose on deployment and upgrade
This category of data includes multi-format attachments, structured numeric fields, and bulk import scenarios.
During deployment, configure multi-source data docking and structured parsing rules in advance. Ensure declaration files in different formats can be processed uniformly.
The high-concurrency requirement for bulk imports demands that the deployed database and cache services have sufficient concurrent processing capacity.
Upgrade operations must avoid project declaration peak periods to prevent interruptions to daily review workflows. They must also be compatible with old-format data from historical cases to avoid parsing errors.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Fill in the access address of the group's internal object storage, bind a storage quota of 1500 MB or higher | Declaration cases contain a large number of scanned documents and long files. Sufficient storage capacity is required to support bulk imports |
| `MONGODB_URI` | Configure a database connection string with read-write separation nodes | Bulk declaration material imports require high concurrent read-write capacity to avoid blocking review workflows |
| `REDIS_URL` | Fill in the internal cache service address, set the connection timeout to 600 seconds | Cache structured field parsing results to reduce repeated calculations, and adapt to bulk review scenarios |
| `DB_MAX_LINK` | Set to `200–300` | Adapt to concurrent requests from multiple users submitting review materials simultaneously, and avoid exhausting database connections |
| `FE_DOMAIN` | Fill in the frontend access domain name deployed within the group, configure the internal firewall whitelist | Only allow group internal personnel to access the review tool to ensure data security |

## Three common mistakes
- Phenomenon: After importing bulk declaration cases, some embedded engineering drawings are not recognized. Cause: Multimodal parsing configuration is not enabled, and preprocessing rules for power engineering drawings are not adapted. This causes some complex images to fail to parse correctly.
- Phenomenon: After importing a backed-up knowledge base across instances, the original case classification structure disappears. Cause: `ROOT_KEY` is not configured to implement permission and metadata isolation between instances, leading to overwriting of classification information during import.
- Phenomenon: Instances deployed via Sealos crash during bulk imports. Cause: The `DB_MAX_LINK` parameter is not adjusted to adapt to concurrent requests, leading to exhausted database connections and service interruption.

## How to confirm the configuration is correct
- Perform a bulk import of 10 declaration cases containing scanned documents and structured tables. Check whether all attachments are correctly associated with the corresponding case entries.
- Access the domain name configured via `FE_DOMAIN`. Confirm that internal authorized personnel can log in normally and submit review materials.
- View the cache service monitoring metrics. Confirm that the cache hit rate of structured parsing results remains in a stable range.
- Export the backup file of the current knowledge base. Complete the import in a test instance. Confirm that the case classification structure matches the original instance.
