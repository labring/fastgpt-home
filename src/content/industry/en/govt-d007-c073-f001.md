# Declaration Materials and File Review for State-owned Industrial Funds: HTTP Interfaces and External Systems

## What this type of data looks like
Data for declaration materials and file review for state-owned industrial funds mainly comes from the fund declaration portal, state-owned assets supervision systems, and internal enterprise approval platforms. Data is synced in real time within a single declaration cycle. A single review case includes multiple structured field documents and attachments. Structured fields include the declaration subject's unified social credit code, fund subscribed scale, project investment amount, and review node status. Units are none, ten thousand yuan, ten thousand yuan, and natural days respectively. Attachments are mostly declaration documents and qualification certificates in PDF or Word format, with a maximum size of 1000 MB per attachment. This page is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on HTTP interfaces and external systems
Fixed format requirements for structured fields mean interfaces must support precise field validation to prevent invalid data flow. Large-size attachments require interfaces to support chunked upload or long-connection transmission to avoid timeout interruptions. Real-time update requirements mean interface timeout periods must align with business time costs and should not be too short. Cross-domain invocation scenarios across multiple systems require interfaces to configure unified authentication rules to ensure data transmission security. Additionally, the multi-version nature of review cases requires interfaces to support version number passing to facilitate review process tracing.

## How to configure settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {Exclusive API key assigned by the state-owned assets supervision platform} | Complies with Bearer token authentication specifications for external systems |
| `variables` | JSON key-value pairs containing declaration project ID and file case number | Passes business context to facilitate external systems associating with corresponding review tasks |
| `responseData` | Simplified fields containing only review status, failure reason, and update time | Reduces interface transmission data volume, adapting to bandwidth restrictions in large-material scenarios |
| Request timeout period | 600 seconds | Adapts to time cost requirements for declaration material upload and review result return |
| Retry count | 2 times | Addresses temporary network fluctuations and avoids review interruptions caused by single request failure |

## Three common misconfigurations
- An interface call returns `do_request_failed do request failed: Post "http://xxx"`. The cause is incorrect configuration of the `Authorization` parameter, or network policies of the target external system restricting cross-domain access.
- Accidentally synchronizing file case review materials to the knowledge base using the create training order function, resulting in index formats that do not match business requirements. The symptom is empty or incorrectly formatted knowledge base search results.
- An interface call returns a 404 status code. The cause is not enabling API permissions in the FastGPT application management page, or using an incorrect application ID or interface path.

## How to confirm correct configuration
- Call the test interface and check if the returned `responseData` contains the expected review status fields.
- Check that the `Authorization` parameter carries the correct Bearer token, which can be verified through the external system's authentication logs.
- Simulate submitting a standard declaration material and confirm that the interface returns a 200 status code with no error messages.
- Review the FastGPT application logs to confirm that the `variables` parameter of the interface request has correctly bound the business context.
