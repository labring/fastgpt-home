# Declaration Materials and Case Review for State-owned Industrial Funds: Workflow Orchestration
This document applies to FastGPT v4.17.0.

## What this type of data looks like
Data for state-owned industrial fund declaration materials and case review mainly comes from electronic files uploaded by declaration entities via official declaration portals, and paper scans collected offline. Updates follow the timeline of individual declaration project cycles. Basic materials for a single project receive their first update after submission, and supporting materials added during the review process are synced incrementally.

Documents exist in mixed formats, including official declaration letters in PDF format, financial calculation sheets in Excel format, and scanned qualification certificates in image format. Fields include the declaration entity’s unified social credit code, project investment amount, declaration submission time, and review node identifier. Units include ten thousand yuan, calendar days, and others.

## What constraints these characteristics impose on workflow orchestration
The mixed-format document structure requires workflow nodes to support multi-type file parsing and unified format output. It avoids split processing logic for different format materials.

The data updated per project cycle requires workflows to support incremental supplementary materials linked to the same project. It prevents duplicate creation of review processes.

Fields include structured information such as unified social credit code and investment amount. This requires the `variables` configuration of the workflow to bind standardized fields from the declaration system. It ensures accurate data extraction.

The multi-node review process requirement means configuring independent trigger conditions and permission checks for each review link. It guarantees compliance of the review workflow.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Multi-format file parsing switch | Enable PDF, Excel, and image formats | Adapts to the mixed format characteristics of declaration materials |
| Variable binding rule | Bind the declaration entity’s unified social credit code and project investment amount | Matches the extraction requirements for structured fields |
| Node timeout threshold | 600 seconds | Adapts to the average processing duration of a single review link |
| Knowledge base variable reference | Call the state-owned asset supervision-related knowledge base | Supplement verification basis for declaration materials |
| Workflow trigger condition | Match by declaration project number | Links all review materials for the same project |
| Failure retry configuration | Retry 3 times, 60-second interval | Addresses temporary interface or file processing exceptions |

## Three common mistakes
- Phenomenon: A "Failed to create post presigned url" error appears when uploading files via the workflow. The interface shows file upload failed. Cause: The correct object storage path parameter is not configured. This prevents generation of pre-signed links for file uploads.
- Phenomenon: The return result is empty after calling the image parsing node in the workflow. Cause: The image format parsing switch is not enabled in the configuration, or the incoming image parameters do not meet the system’s required format and size limits.
- Phenomenon: The extracted declaration fields in the workflow do not match the actual submitted content. Cause: The `variables` are not correctly bound to the declaration system fields. This leads to incorrect extracted variable data.

## How to confirm the configuration is correct
- Upload a test declaration material. Check if the workflow automatically triggers the corresponding node. Confirm the trigger rule is active.
- View node logs. Confirm that the multi-format parsing node can correctly extract content from PDF, Excel, and image files. Verify the parsing configuration is active.
- Cross-check the extracted fields against the actual content in the test material. Confirm that the `variables` bound fields are accurate.
- Simulate node timeout or upload failure scenarios. Check if the failure retry configuration executes according to the set rules.

The values listed here are common starting points and should be evaluated against the reader’s own samples.
