# State-owned Industrial Fund Declaration Materials and File Review: Citation Sources and Traceability

## What this category of data looks like
Data for state-owned industrial fund declaration materials and file review mainly comes from project establishment applications submitted by declaring entities, financial audit reports, compliance qualification documents, and review files archived by state-owned asset supervision departments.
Data is updated per project declaration batch. Each declaration package includes structured fields and unstructured text.
Structured fields include project number, declaring entity's unified social credit code, planned investment amount (unit: ten thousand yuan), and review node status.
Unstructured text mostly consists of long-form content such as project feasibility analysis and compliance explanations.

## What constraints these features impose on the citation sources and traceability link
The mixed structured and unstructured data feature of state-owned industrial fund declaration materials and review files requires citation traceability to match both structured fields such as project number and declaring entity, and corresponding text content. This prevents cross-project citation of incorrect data.
The high proportion of long text in individual materials occupies more context tokens. This requires limiting the text length of single citations.
The data update logic based on declaration batches requires the traceability link to associate with archived files of the current batch. This prevents citation of expired review node information.
Multiple sources of declaration and file data require clear marking of source types. This ensures rapid location of corresponding materials or files during traceability.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Adapts to the high proportion of long text in state-owned industrial fund declaration materials, prevents context overflow |
| `responseData` | Return only entries matching the project number | Ensures citation content is accurately bound to the corresponding declaration project, prevents invalid cross-project citations |
| `detail` | Enabled | Displays fields such as citation source file number and declaring entity, allows reviewers to quickly trace sources |
| Single recall upper limit | Top 8 entries | Controls the number of results returned per retrieval round, reduces context load |
| Single citation token limit | 1500 token/entry | Limits the text length of single citations, adapts to the splitting logic of long declaration materials |

This configuration applies to FastGPT v4.17.0

## Three common configuration mistakes
- Phenomenon: The token count displayed in the model context window does not match the actual token consumption of cited entries. For example, the window shows 30 tokens but actually references tokens from 310 entries. Cause: Structured field matching is not enabled, and irrelevant declaration materials from other projects are recalled. This causes the context to be occupied by invalid data.
- Phenomenon: The single citation token limit is set to 1500, but some knowledge base chunks exceeding this length are still cited in full. Cause: Long text is not split according to declaration project boundaries, or content exceeding the limit is not truncated during splitting. This causes long chunks to not be processed correctly.
- Phenomenon: Key fields of citation sources are empty, making it impossible to locate specific files or declaration materials. Cause: The `detail` configuration is not enabled, so information such as project number and file number required for traceability is not included in the returned results.

## How to confirm the configuration is correctly set
- Upload a single state-owned industrial fund declaration material, initiate a retrieval, and check if the returned results only include entries matching the project number.
- Check the token count in the model context window, compare it with the sum of the actual cited text lengths, and confirm the difference is within a reasonable range.
- After enabling the `detail` configuration, check if citation sources display structured fields such as file number and declaring entity.
- Submit a test request, confirm that the returned `responseData` format meets the preset structured field requirements.

The values provided here are common starting points and should be measured against the reader's own samples.
