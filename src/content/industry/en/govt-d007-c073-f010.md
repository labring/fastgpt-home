# Declaration Materials and Case Review for State-owned Industrial Funds: Knowledge Base Retrieval and Recall

## What this type of data looks like
State-owned industrial fund declaration materials and case review data mainly come from state-owned assets supervision platforms, internal declaration ledgers of fund managers, archived review cases, and supporting policy documents. Data updates are triggered by annual or quarterly declaration batches, with sporadic supplementary compliance documents added on an as-needed basis. Declaration materials follow fixed template formats, including modules such as enterprise qualifications, project feasibility studies, financial statements, and compliance certificates. Cases include review circulation records, opinion letters, and approval documents. Core fields include fund filing number, unified social credit code of the declaration subject, review node, and compliance clause number. Amounts are measured in ten thousand yuan, and time is counted in natural days.

## What constraints these characteristics impose on knowledge base retrieval and recall
The fixed template structure of declaration materials requires knowledge base chunking to preserve field associations, to avoid splitting that damages the integrity of declaration subject and project information. Core fields including the unified social credit code and compliance clause number must support precise field matching retrieval, to avoid fuzzy recall of irrelevant content. Data updates are tied to declaration batches, so incremental synchronization by batch must be supported, to avoid excessive time consumption from full updates. Review cases include circulation records and approval documents, so recall must associate context to ensure review opinions match declaration materials. Compliance policy documents have timeliness, so the latest version of clause content must be prioritized for recall.

## How to configure this
This document uses FastGPT v4.17.0. Below are knowledge base retrieval and recall configurations tailored for the state-owned industrial fund scenario:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | `0.72–0.80` | State-owned industrial fund declaration materials require precise matching of compliance clauses. A threshold that is too low introduces irrelevant review opinions, while a threshold that is too high misses compliance matching items. This range is calibrated based on actual testing. |
| `limit` | `Top 8–12 results` | Relevant information for declaration materials and case review typically ranges from 8 to 12 entries. Beyond this number, content exceeds the context window, leading to truncation of core matching items. |
| `searchMode` | `Precise matching + semantic recall` | Both field codes and semantic content must be matched, to cover literal matching of compliance clauses and semantic association of project feasibility studies. |
| `usingReRank` | `Enabled` | A large number of similar expressions exist in review cases and declaration materials. Reranking filters low-correlation results and improves matching accuracy. |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Declaration subject names may use abbreviations. Extended queries cover associative retrieval for both full names and abbreviations. |
| `collectionIds` | `Specify the knowledge base collection corresponding to the fund filing number` | State-owned industrial funds isolate data by filing number, to avoid recalling irrelevant content across funds and ensure precise retrieval scope. |

## Three common mistakes
- Issue: After uploading a PDF with embedded images or individual image-format declaration attachments, retrieval results do not include compliance clause content from the images. Cause: The FastGPT OCR image parsing module is not enabled. By default, only plain text documents are processed.
- Issue: After packaging an old server knowledge base into an Excel file and importing it to a new server, the metadata and collection association relationship of some chunks are lost. Cause: Excel format cannot store non-text metadata such as knowledge base chunking configurations and collection IDs, and can only synchronize basic text content.
- Issue: After configuring a custom knowledge base selection variable in a workflow, retrieval returns no results. Cause: The variable data type is not set to knowledge base collection ID, so the retrieval scope does not point to a valid dataset.

## How to confirm the configuration is correct
- Upload a typical sample of declaration materials and review cases, check whether retrieval results include matching compliance clauses and review opinions.
- Adjust the `similarity` parameter, verify whether the relevance of retrieval results meets review requirements. No fixed value is required.
- Test the incremental update function, confirm that newly submitted declaration batch data can be recalled normally. Full synchronization is not necessary.
- Check the custom variable configuration, confirm that the knowledge base selection variable is associated with the correct collection ID, and that the retrieval scope covers the target dataset.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
