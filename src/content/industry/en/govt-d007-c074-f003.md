# State-owned Asset Management Company Declaration Materials and Case Review: Multi-turn Dialogue and Prompt Engineering

## What the data for this use case looks like
Data sources include state-owned asset supervision reporting systems, internal enterprise approval ledgers, and project declaration archive libraries. Updates complete with each individual declaration batch. No additional changes occur to data within a single declaration cycle.

Documents fall into two categories: declaration materials and case review materials. Declaration materials include project basic information forms, financial calculation sheets, and compliance explanation documents. Case review materials include process node records, rectification opinion lists, and final approval documents.

Unique fields include project number, state-owned asset share ratio, declaration amount, and review node status. Declaration amount is denominated in ten thousand yuan.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
Decentralized data sources require multi-turn dialogue to call different document types across systems. Prompts must explicitly specify field mapping rules for each data source. This prevents the model from confusing project data from different batches.

Long text structures require the multi-turn dialogue context window to fit the length of a single declaration material. This avoids truncating core review fields.

Unique state-owned asset fields require prompts to permanently include verification rules. This ensures the model accurately identifies key information such as project number and declaration amount.

Data updated per batch requires the dialogue flow to support temporary binding of exclusive datasets. This ensures the dialogue calls the latest content from the current review batch.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Accommodates the average length of a single declaration material, avoiding truncation of core review fields |
| Prompt template | Permanently include state-owned asset project field verification rules | Accurately identifies unique fields including project number, declaration amount, and state-owned asset share ratio |
| Multi-turn dialogue history retention | 15–20 dialogue turns | Covers the full process from submission to final review for a single declaration |
| `variables` configuration | Bind exclusive datasets corresponding to the declaration batch | Precisely calls declaration materials and case data for the target batch |
| `chatId` configuration | Bind the unique project number | Differentiates review dialogue contexts across batches to avoid confusion |
| Front-end file upload interface | Support PDF and Excel formats, maximum 1000 MB | Adapts to attachment types and size limits for declaration materials |

## Three Common Mistakes
- Phenomenon: Multi-turn dialogue returns declaration materials from other batches, leading to cross-project confusion in review results. Cause: `chatId` and unique project number are not bound. Dialogue contexts across different batches remain unisolated.
- Phenomenon: After enabling front-end file upload, the dialogue interface cannot read uploaded declaration attachments. Cause: `variables` configuration for binding temporary storage paths of uploaded files is missing. The dialogue flow cannot access attachment content.
- Phenomenon: Adjusting the prompt produces no significant change in review accuracy, and may even introduce field identification errors. Cause: State-owned asset unique field verification rules are not added to the system prompt section of `messages`. The model fails to focus on core review requirements.

## How to Verify Proper Configuration
- Initiate a dialogue for a single declaration review. Enter the project number, then check if returned content only includes data for that batch’s declaration materials and case records.
- Upload declaration attachments for the target batch. Confirm the dialogue flow reads core fields from the attachments without missing or mixing data.
- Adjust the number of retained multi-turn dialogue history rounds. Test that context continues normally across process nodes.
- Review the `chatId` binding configuration. Confirm each project’s dialogue context is fully isolated from other batches.

The values provided here are common starting points and should be evaluated against the reader's own samples.
