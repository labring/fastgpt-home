# State-owned Asset Management Company Declaration Materials and File Review: Workflow Orchestration

## What This Category of Data Looks Like
Data primarily comes from enterprise declaration ledgers synced from the state-owned asset supervision platform, scanned copies of review files archived in internal business systems, and electronic declaration materials submitted by declaration entities. Updates are triggered upon completion of a single declaration batch. A single declaration package includes three core documents: entity qualification certificates, asset valuation details, and approval circulation records. Fields include file number, declaration batch number, asset book value (unit: ten thousand yuan), submission time, and others. The length of electronic documents for a single file ranges between 500 and 2000 characters.

## Constraints on Workflow Orchestration
Dispersed data sources require configuring multi-source data access nodes to connect structured ledgers and unstructured scanned files separately.
The update rhythm driven by declaration batches requires the workflow to execute when a single declaration is triggered.
Fields include asset amounts measured in ten thousand yuan units. A format verification node must be added to the workflow to ensure matching numerical units.
The wide range of single file document lengths requires configuring processing nodes adapted to multi-length inputs to avoid node timeouts caused by overly long documents.
The file structure of review circulation requires the workflow to support status circulation and permission verification for serial approval nodes.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger by declaration batch, bind the batch number parameter in `variables` | Matches the rhythm of declaration data updated by batch, ensures the workflow only executes after batch submission |
| Node Timeout Setting | 300–600 seconds | Adapts to the processing duration of single file documents, avoids timeouts caused by long documents or serial multi-node processing flows |
| File Upload Node | Supports PDF and Excel formats, maximum file size 1000 MB | Matches common formats of declaration materials and the file size limit for single files |
| Variable Configuration | Bind fields such as file number and declaration batch number | Connects structured data from the state-owned asset supervision platform, enables automatic field filling |
| Model Call Node | Call an enabled compliance verification model | Used to review the compliance of qualification documents in declaration materials |
| Workflow Verification Node | Verify that the asset amount unit is ten thousand yuan | Matches the unit requirements of data fields, avoids format errors |

## Three Common Configuration Mistakes
- Phenomenon: The workflow terminates automatically after exceeding 120 seconds of execution, with the node status showing timeout. Cause: The node timeout setting is not adjusted, and the default timeout duration is insufficient to cover the multi-node serial processing flow for long file documents.
- Phenomenon: An already globally configured and enabled model cannot be found in the model selection list of workflow nodes. Cause: The corresponding `nodeId` is not bound in the workflow node, or the model has not been confirmed to have completed global deployment and enabling configuration.
- Phenomenon: When calling a custom upload file tool, workflow internal file variables cannot be referenced, and only external file links are supported. Cause: The variable reference switch of the file upload node is not enabled, or the tool's parameter binding rules are not configured correctly.

## How to Verify Correct Configuration
- Trigger Test: Submit a single declaration batch, observe whether the workflow starts automatically, and verify that the `variables` parameter of the trigger node is correctly bound to the batch number.
- Format Verification: Input simulated asset amount data, run a workflow test case, and confirm that the verification node can recognize and match the unit requirements of the data fields.
- Model Call: Add a test node in the workflow, call the configured compliance verification model, and confirm that the corresponding model appears in the drop-down list and can complete the call.
- File Transfer: Upload a file simulating declaration materials, confirm that the file upload node can normally receive the file and pass the file variable to subsequent processing nodes.

The values provided are common starting points and should be measured against the samples of the target deployment environment.
