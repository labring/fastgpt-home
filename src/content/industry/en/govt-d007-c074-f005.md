# Declaration Materials and Case Review for State-owned Asset Management Companies: Tool Calling and Plugins

## What the data for this category looks like
Data mainly comes from state-owned asset supervision and reporting systems, internal asset disposal ledgers, and offline case scan files. Update rhythm follows project progress: basic materials are uploaded in batches when a single declaration project is initiated for approval. Supplementary materials generated during the approval stage are updated incrementally. Most documents are multi-page PDF format, with some being structured form files. Fields include asset ownership number, declared disposal amount, approval circulation node, handler information, and others. Units include ten thousand yuan, square meters, number of households, and similar units.

## What constraints these characteristics impose on the tool calling and plugins stage
Decentralized data sources require calling multi-source data synchronization plugins. This ensures complete retrieval of declaration materials and case data across systems. The batch and incremental update rhythm requires tool calling to support breakpoint resuming and incremental comparison. This avoids repeatedly pulling historical data. The mixed format of multi-page PDFs and structured forms requires calling OCR recognition and structured parsing plugins. These plugins extract field information usable for review. Fields include numerical items with specific units, so unit verification logic must be added during the tool calling stage. This ensures that fields such as declared amount and area meet the format requirements of state-owned asset management.

## How to configure settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ------ | -------- | ----------- |
| Workflow tool call trigger timing | Triggered when the declaration material upload is completed | Matches the node sequence of the state-owned asset management company's declaration process, preventing early calls that result in incomplete data uploads |
| DingTalk Webhook push configuration | Push to the designated state-owned asset supervision docking group, retry 3 times on timeout | Adapts to the internal communication link of the state-owned asset system, the retry mechanism ensures that review progress notifications are not lost |
| Multimodal model call timeout | 600 seconds | Covers the recognition and parsing duration of multi-page case images, preventing call failures caused by large file sizes |
| `functionCall` trigger rule | Call only when missing structured fields are detected | Focuses on completing and verifying missing fields, reducing unnecessary model call costs |
| Structured parsing plugin call threshold | First 10 pending review cases | Matches the batch processing limit of a single review, avoiding excessive resource usage |
| `toolChoice` parameter configuration | Bind the preset state-owned asset review tool set | Ensures that the model only calls tools related to state-owned asset management, avoiding unnecessary calls |

## Three common configuration errors
- Issue: A `Failed to fetch` error is returned when calling a multimodal visual model. The log shows that case images cannot be downloaded. Cause: Intranet penetration or whitelist permissions are not configured. FastGPT cannot access case image resources stored in the state-owned asset management company's internal storage.
- Issue: The DingTalk message pushed after tool calling is empty. Review fields are not synchronized normally. Cause: The trigger timing is configured before material upload. Data has not been stored yet, so valid field information cannot be extracted.
- Issue: The `toolChoice` parameter is configured incorrectly. The model does not call the specified tool as required. Cause: The parameter rules for tool calling are confused. The calling format of the corresponding tool is not matched.

## How to verify the configuration is complete
- Upload a test state-owned asset declaration case PDF, trigger the workflow tool call, and check for normal data source retrieval records in the logs.
- Configure a test address for the DingTalk Webhook, initiate a simulated review process, and confirm receipt of a push message containing declaration fields.
- Adjust the `functionCall` trigger threshold to 1, upload test materials with missing fields, and confirm the model automatically calls tools to complete the fields.
- Check the workflow running status panel, confirm tool call duration is within the configured 600 seconds, and no timeout errors occur.

The values provided are common starting points and should be evaluated against the reader's own samples.
