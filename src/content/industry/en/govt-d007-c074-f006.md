# Declaration Materials and File Review for State-owned Asset Management Companies: Citation Sources and Traceability

## What data looks like for this category
Declaration materials and file review data for state-owned asset management companies originates from state-owned asset supervision reporting systems, internal approval circulation documents, ownership registration archives, and asset evaluation reports. Each project’s declaration workflow generates data, which is updated immediately during major asset adjustments and synced to storage in archived batches for routine files. Each individual document includes fields such as declaration subject qualification, asset detail list, approval node records, supporting document numbers, and some files include scanned copies and electronic signature information. Most fields consist of structured text combined with standardized identification numbers.

## Constraints on Citation Sources and Traceability
The large number of structured fields and high standardization of declaration materials and files require precise matching of key fields such as asset numbers and approval document numbers during citation traceability, to avoid generic recall of irrelevant content. Data updates immediately as projects progress, so knowledge base sync frequency must align with business nodes to prevent referencing expired approval or ownership information. Some files include electronic signatures and scanned copies, so systems must support associating original file paths and generation times to ensure complete traceability. Individual document sizes vary significantly, so context calls of different lengths must be supported to avoid truncating critical approval node records.

This configuration is formulated based on FastGPT v4.17.0.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | The structured fields of declaration materials and files are mostly continuous business text, this length preserves the complete logic of individual approval node records |
| Overlap Length | 100–200 characters | Prevents cross-block approval processes from being truncated, ensuring context coherence during traceability |
| `quoteMaxToken` | 1500–2000 tokens | Supporting materials for individual files are numerous, so sufficient reference context must be retained for precise traceability |
| Similarity Threshold | Calibrated based on actual testing | Different asset types have varying requirements for field matching accuracy, adjustments must be made based on business operation logs |
| Single Search Limit | Top 8 entries | Associated supporting documents for declaration projects usually do not exceed 10, to avoid recalling file content from unrelated batches |
| `responseData` | Return original fields and file paths | Traceability information must be bound with answers to facilitate auditors' verification of original business data |

## Three Common Mistakes
- Symptom: When calling via external interface, returned reference fields are empty or cannot be associated with local knowledge base files. Cause: The `responseData` configuration item is not enabled, or knowledge base sync does not cover the permission scope of external release channels.
- Symptom: Returned answer content is completely unrelated to annotated knowledge base references, and the referenced file does not contain the asset data in the answer. Cause: The similarity threshold is set too low, recalling irrelevant files from non-current declaration projects, or chunk length is too large leading to truncation of key fields.
- Symptom: When calling via the connected WeChat Work channel, only the referenced file number is returned, and no corresponding answer content is generated. Cause: Context binding in the question optimization link is not configured correctly, or the `detail` configuration item is not enabled, leading to missing answer generation logic.

## How to Confirm Proper Configuration
- Enter the FastGPT knowledge base management page, check the chunk and overlap length configurations, confirm they match the average length of current business documents.
- Initiate a test query for a single file, check the actual usage of `quoteMaxToken` in returned results, confirm it meets business requirements.
- Manually upload a test file, initiate a related query, then verify whether returned reference information includes the original fields and file path of this file.
- Check system operation logs, confirm that the number of search results recalled each time does not exceed the set single search limit, and similarity meets business expectations.
