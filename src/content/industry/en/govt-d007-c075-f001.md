# Declaration Materials and File Review for State-owned Capital Investment Companies: HTTP Interfaces and External Systems

## What the data for this category looks like
Data comes from three sources: the state-owned assets supervision and reporting system, internal project declaration management platform, and file archive database.
Updates happen in concentrated batches during annual declaration cycles. Single files are added or edited on demand during regular operations.
The document structure has three core modules: main qualification documents, project feasibility analysis content, and approval circulation records.
Fields include: unified social credit code, declaration batch number, file archive date, and declared budget amount. Their respective units are: none, batch, year-month-day, and ten thousand yuan.
Most single file documents are 500 to 2000 characters long. Some major project files can extend to ten thousand characters or more.

## Constraints imposed on HTTP interfaces and external systems
Multi-source data access requires interfaces to support cross-system authentication. The `Authorization` header must be configured to adapt to different authentication rules of the state-owned assets supervision system and internal management platforms.
Specific field unit requirements mandate retaining native units for fields such as unified social credit code and declared budget amount when mapping `responseData`, to avoid conversion errors.
The concentrated update business rhythm requires interfaces to support batch submission requests. Required fields including file archive date and declaration batch number must have their format compliance verified.
Differences in update delays across systems require configuring reasonable timeout parameters, to prevent overall request failure due to slow responses from a single system.
Differences in single file lengths require interfaces to support dynamic adjustment of per-request document transmission limits, to adapt to declaration materials of different sizes.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Use Bearer Token format for state-owned assets systems, use API keys for internal systems | Adapts to the authentication standards of the two data sources, complies with state-owned assets supervision security and compliance requirements |
| `variables` | Pass declaration batch number and file archive date as context variables | Matches core business data identifiers, enabling the interface to filter request data by batch |
| `responseData` | Map unified social credit code and declared budget amount fields to specified business system fields | Retains native data units and formats, avoiding errors from secondary conversion |
| Request timeout | 60-120 seconds | Adapts to state-owned assets system response delays, preventing timeout interruptions for batch requests |
| Batch request limit | Submit up to 50 files per request | Balances interface load and business submission efficiency, aligning with conventional file counts for single declarations |
| Retry strategy | Retry 2 times after failure, with a 10-second interval | Addresses temporary network fluctuations or short system outages, reducing batch submission failure rates |

## Three common errors
- Phenomenon: Review results returned after interface calls are not sorted by relevance. Cause: No rearrangement-related parameters were bound in the interface configuration, so the rearrangement logic was not triggered.
- Phenomenon: Submitted file data is not stored in the system after the client interrupts the interface connection. Cause: No persistent storage parameter was configured for the interface, resulting in uncompleted request data not being written to the database.
- Phenomenon: An invalid key prompt appears when calling the model interface. Cause: The positions of system-level and interface-level authentication keys were confused, and the correct key was not entered in the corresponding configuration page of FastGPT v4.17.0.

## How to confirm the configuration is complete
- Call the test interface with a simulated declaration batch number, check whether the fields returned in `responseData` include the unified social credit code and declared budget amount, and whether their units match the native data.
- View FastGPT interface logs, confirm that the Token format of the `Authorization` header matches the configuration, and no 401 unauthorized errors are present.
- Submit batch test data, check whether the sorting logic of the returned results meets expectations, and confirm that the rearrangement function has triggered normally.
- Simulate an interrupted interface request, check whether uncompleted file data is retained in the database, and confirm that the persistent configuration has taken effect.
