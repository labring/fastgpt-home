# Declaration Materials and File Review for State-owned Capital Investment Companies: Workflow Orchestration

## What This Category of Data Looks Like
The data used for declaration materials and file review at state-owned capital investment companies mainly comes from internal state-owned assets declaration systems, enterprise archive repositories, and filing templates issued by the state-owned assets supervision and administration commission. Data updates follow an annual and quarterly declaration batch rhythm, with synchronized updates when new files are archived on a daily basis. Each individual document includes sub-files such as declaration forms, financial audit reports, property right certificates, and project feasibility reports. Core fields include project number, declaration subject, state-owned assets proportion, approval node, and file archive number. Financial fields use ten thousand yuan as their unit, and file fields use piece as their unit.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Decentralized data sources require workflows to support pulling different types of declaration materials across multiple systems. Full-process processing cannot rely on a single data source. The batch-based update feature means workflows must adapt to scheduled or manual trigger startup logic to align with declaration cycle rhythms. Complex document structures and specialized review fields require workflow nodes to support customized text extraction and classification rules. This meets the identification needs of state-owned assets-related specialized fields. The length of individual documents varies widely, so workflows need flexible chunking and processing capabilities. This prevents node failures caused by overly long single text segments.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Variable Mapping | Bind the project number and state-owned assets proportion fields in `variables` | The core review fields of state-owned capital investment company declaration materials are project number and state-owned assets proportion, which require precise mapping and extraction |
| Node Timeout Setting | `300-600 seconds` | Single declaration materials have a relatively long average length, so sufficient processing time must be reserved |
| Node ID Binding | Bind `nodeId` as the exclusive identifier for file review | Distinguish review processes of different batches and subjects to avoid process confusion |
| Text Chunk Length | `800-1200 characters` | Adapt to the common paragraph length in declaration materials, balancing extraction accuracy and processing efficiency |
| Single-Processing Limit | `Top 20 files` | The number of files per batch is moderate, avoiding excessive load on a single node |
| Trigger Condition Configuration | Triggered by newly uploaded files | Daily file review takes newly archived materials as the trigger source, which aligns with workflow startup logic |

## Three Common Misconfigurations
- The symptom is empty results returned by the text classification extraction node. The cause is that extraction rules are not configured for specialized fields of state-owned capital investment companies, such as state-owned assets proportion and project approval document number. General extraction templates cannot match these specialized fields.
- The symptom is an error during workflow import, with unrecognized node configuration. The cause is that the old workflow was not exported under FastGPT v4.17.0. Node parameters are not automatically compatible during cross-version imports.
- The symptom is that custom tool variables do not take effect. The cause is that field parameters for the corresponding file are not bound in `variables`, and variable mapping is not associated with the actual data source.

## How to Verify Correct Configuration
- Upload a single standard declaration material, trigger the workflow, and check the return results of the text extraction node to confirm core fields are correctly extracted.
- Check the `variables` configuration items to confirm that specialized review fields such as project number and file archive number have been bound, with no missing necessary parameters.
- Trigger a test process to verify that the node timeout setting does not trigger a timeout error, and that processes for multiple batches of files can run independently without mutual interference.
- View workflow logs to confirm that the exclusive identifier bound by `nodeId` has been correctly associated with the file review process for the corresponding batch.
