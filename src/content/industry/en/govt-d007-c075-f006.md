# Declaration Materials and File Review for State-owned Capital Investment Companies: Citation Sources and Traceability

## What this type of data looks like
The data used for declaration materials and file review in state-owned capital investment companies primarily originates from internal project declaration systems, state-owned assets supervision and administration record archives, and investment decision dossier libraries. Data for individual projects is uploaded as a full set once during declaration. Archived files are synced to the knowledge base in quarterly batches. Each individual document contains the declaration text, approval circulation records, attachment list, and unique file number. Core fields include project name, unified social credit code of the declaring entity, applied amount (unit: ten thousand yuan), approval level, and filing date. Some confidential dossiers must undergo desensitization before being added to the knowledge base.

## What constraints these characteristics impose on citation sources and traceability
Because the data includes unique file numbers and supervision-related fields, citation traceability must accurately bind the corresponding identifiers to avoid mixing materials from different projects. Bulk-updated archived data requires the knowledge base to support incremental synchronization to prevent duplicate indexing and expired data. Individual documents are lengthy and include multi-level approval records, so the token range for citations must be limited to ensure complete display of core content. Reviewers need to quickly locate specific supervision fields, so content returned via traceability must focus on preset core fields and only show content relevant to review.

## Three Common Configuration Mistakes
- The symptom is that chat content returned by the API does not include the cite reference ID. The cause is that the `detail` configuration item is not enabled, or the mapping relationship between file numbers and system variables is not configured.
- The symptom is an error when viewing knowledge base citations. The cause is that synced dossier data has duplicate unique numbers, leading to conflicts in traceability matching logic.
- The symptom is that variable references do not correctly associate with corresponding declaration materials. The cause is that the knowledge base's file number field is not bound to system preset variables, making precise matching impossible.

## How to Verify Successful Configuration
- Initiate a query targeting a known file number, check if the returned results include the unique identifier field of the corresponding dossier.
- View the `responseData` field in the API return, confirm that it includes the preset core supervision-related fields.
- Trigger a manual sync task, check if archived dossiers are correctly indexed to the knowledge base.
- Test the citation display function, confirm that clicking the traceability link jumps to the detail page of the corresponding dossier.
