# Declaration Materials and Case Review for State-owned Capital Investment Companies: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for declaration materials and case review for state-owned capital investment companies comes primarily from annual investment declaration documents required by state-owned assets supervision regulations, project approval case files, internal approval circulation records, and compliance qualification certification materials. Data updates follow two rhythms: concentrated batch updates during project declaration periods, and monthly synchronization of existing case files during normal operations. Most documents use structured fields, including project number, investment amount (unit: ten thousand yuan or hundred million yuan), approval nodes, declaration subject qualifications, compliance document numbers, and more. Some case files include scanned copies of handwritten approval annotations as unstructured content.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The data covers multiple types of structured and unstructured content, so retrieval must support mixed field matching and multimodal recall to avoid missing key approval node information. Updates are concentrated with large single-batch data volumes, so retrieval configurations must adapt to incremental updates and batch indexing to avoid excessive time spent on full reindexing. Fields such as investment amount and approval document number have clear unit and format requirements, so retrieval must match field semantics and unit consistency to prevent irrelevant results from being included. The length of individual case files varies widely, so the total token consumption of recalled content must be reasonably controlled to avoid exceeding model context limits.

## Three Common Mistakes
- Symptom: After the workflow runs, the model outputs a general answer directly without calling knowledge base retrieval content. Cause: The automatic trigger rule for the retrieval node is not configured in the workflow, only the node for manually calling the retrieval tool is retained.
- Symptom: The token consumption of a single answer exceeds 3000, even if a low reference limit is set. Cause: The actual value of the `limit` parameter is too high, or reranking is not enabled to filter redundant results, causing the total length of recalled case file fragments to exceed expectations.
- Symptom: Retrieval results are displayed directly in the workflow interface, and the subsequent AI node outputs the same content again, resulting in duplicate answers. Cause: The retrieval node is configured to return results directly, and the mode of only recalling document fragments without outputting is not enabled.

## How to Confirm the Configuration is Correct
- Upload a single test file of a state-owned capital investment project declaration, trigger the retrieval node, and check whether the similarity scores of the recalled results fall within the set range.
- Manually trigger the retrieval node, confirm that the interface only returns recalled document fragments and does not output a complete answer directly, to avoid duplicate output by subsequent AI nodes.
- Input a test question containing specific investment amount and approval document number, check whether the recalled results match the field units and format requirements, with no irrelevant content included.
- View the dataset update log, confirm that incremental updates follow the set rhythm of monthly or project declaration periods, with no abnormal full reindexing prompts.
