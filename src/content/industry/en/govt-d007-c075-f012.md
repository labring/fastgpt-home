# Declaration Materials and File Review for State-owned Capital Investment Companies: Deployment and Upgrade

## What This Category of Data Looks Like
Declaration materials and files for state-owned capital investment companies originate from project declaration documents required for submission by state-owned assets supervision departments, and file archives generated by internal project management systems. Submissions are concentrated during project declaration cycles, with supplementary archived files submitted on an ongoing basis. Document structure includes the main body of the declaration form, supporting material attachments, and file catalog tables. Fields include project unified number, unified social credit code of the declaring entity, planned investment amount, approval node status, archiving date, and more. Some fields are fixed-format enumeration values.

## What Constraints These Characteristics Impose During Deployment and Upgrade
Declaration materials and files contain long text and large-capacity attachments, requiring configuration of storage and computing resources that meet scenario needs during deployment. Concentrated submissions during declaration cycles create peak traffic, requiring rolling update windows to be reserved during upgrades to avoid service interruptions. Fixed formats for structured fields and enumeration values require strict alignment of data import and retrieval configurations with field rules. Some materials involve state-owned assets sensitive information, requiring configuration of storage and access permissions that comply with internal security specifications.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Setting |
| --- | --- | --- |
| `MONGODB_URI` | Fill in the connection string for a high-availability MongoDB cluster, with read-write authentication parameters included | Stores metadata and full-text indexes for declaration materials, to meet the retrieval needs of large-capacity files |
| `PG_URL` | Fill in the connection string for the read-only replica of the state-owned assets business database | Synchronizes structured declaration field data, to avoid impacting business database stability from write operations |
| `REDIS_URL` | Configure as the address of a Redis cluster with a memory limit of 16 GB | Caches frequently accessed file retrieval results to reduce database concurrent pressure |
| `STORAGE_S3_ENDPOINT` | Fill in the access endpoint for the internal object storage, such as `http://172.16.10.20:9000` | Stores large files such as declaration attachments, in compliance with the internal storage specifications of state-owned capital investment companies |
| `ROOT_KEY` | Set as a strong random string with a length of no less than 32 characters | Serves as the system core authentication key to ensure access security after deployment |
| `DB_MAX_LINK` | Configure as 200–300 | Limits the number of concurrent database connections to avoid resource exhaustion during peak submissions |

## Three Common Misconfigurations
- An error `text index required for $text query` is returned after executing the upgrade script. This occurs because the full-text index for MongoDB was not reinitialized during the upgrade process, and retrieval for declaration materials and files relies on this index.
- A locally deployed large model cannot be selected when configuring the model provider. This happens because the default configuration does not enable local model access permissions, and the corresponding environment variables were not correctly configured.
- Some structured fields are empty after batch file import. This is because the data mapping rules were not configured according to the fixed field format of the declaration materials, leading to field matching failures.

## How to Verify Correct Configuration
- Execute `curl -X GET ${FE_DOMAIN}/api/health` and check that the returned status code is 200.
- Upload a standard declaration attachment and check that the file storage path matches the endpoint configured in `STORAGE_S3_ENDPOINT`.
- Initiate a file retrieval request and check that the number of returned results is within the range configured in `DB_MAX_LINK`.
- Verify that the string configured for `ROOT_KEY` has a length of no less than 32 characters, and use this key to initiate an authentication request that returns successfully.
- Confirm that the current deployment version is FastGPT v4.17.0, which meets scenario adaptation requirements.
