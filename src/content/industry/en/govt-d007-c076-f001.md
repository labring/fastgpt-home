# Declaration Material and Case File Audit for State-owned Capital Operation Companies: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data mainly comes from state-owned assets supervision and reporting systems, internal project management archives, and electronic materials submitted by declaration entities.
Update rhythm follows the progress of individual declaration project workflows, and becomes archived static data after audit is completed.
The document structure includes structured metadata and attachment packages.
Metadata fields include project unique identifier, unified social credit code of the declaration entity, audit node status, and total material size.
Attachments include PDF scans, Excel forms, and similar file types.
Field units uniformly follow standardized formats published by state-owned assets systems.

## What Constraints Do These Characteristics Impose on HTTP Interfaces and External Systems
Structured metadata must strictly match standardized fields from state-owned assets systems.
Interface request parameters must include complete and compliant metadata items, otherwise they will be intercepted by the supervision system.
The size of a single declaration material attachment can reach hundreds of megabytes.
Interfaces must be configured for large file transfer adaptation to prevent transmission interruptions.
Data in the declaration process is updated as needed.
Interfaces must support pulling incremental data by project number.
Archived case file data is read-only.
Interfaces must be configured with `Authorization` permission verification, and only allow calls from service accounts belonging to audit personnel.
In FastGPT v4.17.0, corresponding permission verification rules must be enabled in the external interface configuration module to ensure interface call security.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface timeout period | 600 seconds | Adapt to the transmission and audit parsing duration of single large attachments |
| `Authorization` | Fixed service account secret | Match the permission verification rules of state-owned assets systems to prevent unauthorized access |
| `variables` | Bind project number variables | Implement pulling corresponding case file data by individual declaration project |
| Large file upload threshold | 1000 MB | Cover the common attachment upper limit of declaration materials for state-owned capital operation companies |
| `responseData` | Return only structured audit fields | Reduce invalid data transmission and improve interface call efficiency |
| Request retry count | 3 times | Respond to temporary network fluctuations and avoid single call failures |

## Three Common Misconfigurations
- Interface calls return cross-origin interception errors, with status codes indicating CORS-related exceptions. Cause: No allowed call domain name whitelist configured for the interface, and cross-origin request adaptation not enabled.
- Interface calls return `401 Unauthorized`, or FastGPT testing prompts insufficient permissions. Cause: The service account secret configured for the `Authorization` parameter failed permission verification by the state-owned assets system.
- Uploading large declaration case files prompts transmission failure, with file upload progress interrupted. Cause: Large file upload threshold not adjusted, or interface timeout settings adapted to large files not configured.

## How to Verify Proper Configuration
- Call the configured interface, pass a test project number, and check if the returned `responseData` contains the expected structured metadata fields.
- Use the FastGPT v4.17.0 interface testing tool, initiate a request with the correct `Authorization` parameter, and confirm the returned status code is 200.
- Upload a test material with a volume matching the business upper limit, and check if the interface can receive the material normally and return a processing result.
- Configure the project variable bound by `variables`, initiate multiple calls, and confirm that each call only pulls case file data for the corresponding project.
