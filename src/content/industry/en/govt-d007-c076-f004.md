# Declaration Materials and File Review for State-owned Capital Operation Companies: Workflow Orchestration

## What the data for this category looks like
Data for declaration materials and case files from state-owned capital operation companies comes from state-owned assets supervision and administration submission documents, internal approval case files, and project declaration correspondence. The update rhythm follows the completion of single declaration projects or monthly supervision submission deadlines. Document structures mostly combine structured forms and scanned attachment files. Fields include declaration subject qualification information, fund amount, compliance certificate number, and approval node records. Unit and format requirements include ten thousand yuan, document numbering, and similar specifications.

## What constraints these characteristics impose on the workflow orchestration link
The mixed document structure of structured forms and attachments requires the workflow to cover both structured field extraction and knowledge base association for unstructured attachments. The data feature that updates with project nodes requires the workflow to support triggering execution based on approval nodes. Fields including compliance certificate numbers and fund amounts require the workflow to include format verification and numerical range verification steps. The requirement for parallel processing of multiple attachments requires the workflow configuration to support batch calls to knowledge base search nodes, adapting to scenarios where multiple documents are retrieved simultaneously.

## How to set up configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single search limit | Top 5 entries | The core compliance certificates for declaration materials of state-owned capital operation companies are mostly 3 to 5 copies. Excessive entries will increase token consumption |
| Maximum context | 8000–12000 token | Declaration case files include multiple attachments, so sufficient context must be retained to support content verification |
| `variables` configuration | Bind project unique identifier | Adapt to API call scenarios, assign the identifier corresponding to the declared project to the global variable |
| Node triggering method | Trigger based on approval nodes | Match the rhythm of data updates with project nodes, no need to manually start sessions |
| Reference validity verification | Calibrate based on actual testing | Must match the specific compliance format and content rules required by state-owned assets supervision regulations |

## Three common configuration errors
- Phenomenon: The single search limit is set to 2000 entries, and the token consumption for generated responses exceeds the preset threshold. Reason: The limit was not configured based on the number of core documents in the declaration materials, and redundant retrieval content occupies too much context quota.
- Phenomenon: No automatic reply appears after the conversation window is opened, and the workflow does not trigger execution. Reason: The rule of triggering based on approval nodes was not configured, only user message triggering logic was set.
- Phenomenon: The global variable field is empty during API calls, and the verification link returns an error. Reason: The `variables` parameter was not assigned a value in the format of the declared project number, resulting in failed variable binding.

## How to confirm the configuration is complete
- Trigger the preset approval node, confirm that the workflow starts automatically and executes knowledge base retrieval and verification steps.
- Pass a test project identifier through the API interface, check whether the `variables` parameter is correctly associated with the workflow global configuration.
- Upload simulated declaration attachments, verify that the reference validity verification link can identify compliant and non-compliant content.
- Use the FastGPT v4.17.0 workflow editor to check whether all configuration items take effect synchronously.
