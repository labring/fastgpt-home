# Declaration Materials and Case File Review for State-owned Capital Operation Companies: Tool Calling and Plugins

## What This Category of Data Looks Like
Data originates from internal state-owned assets supervision declaration documents, property rights transfer case files, budget adjustment declaration materials, and similar sources for state-owned capital operation companies. Data updates trigger per single declaration batch, and updates complete after a single batch of declaration materials is submitted. Document structures include fields such as the unified social credit code of the declaration subject, item category, supporting attachment number, and audit node records. Amount fields use ten thousand yuan as the unit. Time fields follow the YYYY-MM-DD format. Case file numbers use the rule of fixed prefix plus serial number.

## Constraints Imposed on Tool Calling and Plugins
Fixed field format requirements for declaration materials and case files mandate that tool calls must strictly match preset fields such as unified social credit codes and amount units. This prevents parsing failures caused by format incompatibility.
Data updated per declaration batch requires plugins to support pulling data per single declaration batch, rather than fully synchronizing historical case files. This reduces interface load.
The chained record structure of audit nodes requires tool calls to read historical case file content in audit order. This ensures coherent contextual logic.
The multi-attachment associated document structure requires plugins to support pulling metadata of associated attachments. This supplements complete information for declaration materials.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto | Adapts to parsing requirements for multiple fields in declaration materials, automatically matching tool functions for different field types |
| `functionCall` | Trigger based on required fields | Ensures calls are only triggered when required fields such as unified social credit code and item amount are detected, reducing invalid requests |
| Single tool call timeout | 600 seconds | Adapts to long document parsing scenarios for declaration materials, preventing call interruptions caused by large material volume |
| Tool call result cache | Cache for 24 hours per declaration batch | Aligns with the rhythm of data updates per batch, reducing interface load from repeated pulls |
| Audited case file association scope | Previous 3 historical case files | Aligns with the chained logic of state-owned assets review, avoiding excessive historical data that interferes with current judgment |

## Three Common Mistakes
- Symptom: A custom environment variable called in a workflow returns a null value, with logs indicating the variable was not found. Cause: The environment variable was not correctly mounted in the Docker configuration for the FastGPT deployment, or the variable naming rules were not correctly matched in the workflow.
- Symptom: A null response is returned after calling a model, with logs showing required fields are missing. Cause: The trigger rules for `functionCall` were not configured per the fixed field format of declaration materials, leading to failure to correctly pull required field data during tool calls.
- Symptom: Parsing errors occur when calling m3e-related tools after upgrading to FastGPT v4.17.0. Cause: The model adaptation configuration for tool calls was not updated synchronously, causing a mismatch between the embedding model input format and current version requirements.

## How to Verify Correct Configuration
- Submit a test declaration material. Check whether the tool call automatically matches preset fields, and verify whether trigger timing aligns with configuration requirements.
- Review tool call logs. Confirm that the timeout time adapts to the parsing duration of the current test material, with no interruptions occurring.
- Verify environment variable references. Use workflow test nodes to output variable values, confirming they match the configuration set during Docker deployment.
- Call upgraded model tools. Check whether parsing results include all complete fields of the declaration material, with no format errors.
