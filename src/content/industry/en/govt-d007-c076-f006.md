# Declaration Materials and File Review for State-owned Capital Operation Companies: Citation Sources and Traceability

## What This Type of Data Entails
Data sources for declaration materials and file data of state-owned capital operation companies include state-owned assets supervision department filing documents, internal business ledgers, project declaration correspondences, past approval files and other materials. Data updates are tied to individual project declaration cycles. Updates are first completed in a centralized manner, followed by routine supplementary adjustments. Document structure includes main qualification documents, financial audit reports, project feasibility study reports, approval process files and other modules. Fields include unified social credit code, state-owned assets filing number, project investment amount (unit: ten thousand yuan), approval node timestamp and other exclusive business identifiers.

## Constraints for Citation Sources and Traceability
Dispersed data sources require retrieving associated information across multiple systems. This increases the matching complexity of traceability. Individual documents are lengthy. Traceable citations must not excessively truncate key compliance fields. Otherwise, audit judgments will be affected. Exclusive business fields require precise matching of corresponding identifiers during traceability. This avoids mixing materials from different projects. The centralized update rhythm requires regular synchronization of traceability data. This ensures information timeliness during audits. Out-of-date content may be cited otherwise.

| `quoteMaxToken` | `800–1200 token` | Matches the average character length of single declaration documents for state-owned capital operation companies, avoids truncating key traceability fields |
| `responseData` | Enabled | Requires output of the original text of cited content to meet compliance traceability requirements for state-owned assets audits |
| `detail` | Enabled | Displays complete node information for file approval, helps audit personnel trace process details |
| Single recall limit | `Top 5` | Associated files for declaration materials of state-owned capital operation companies usually do not exceed 5 related items, avoids redundant information interfering with audits |
| Knowledge base incremental sync frequency | `Once daily` | Matches the centralized update rhythm during project declaration cycles, ensures timeliness of traceability data |

## Three Common Configuration Mistakes
- Phenomenon: An interface request is initiated, the connection is successful, but no content return value is present. Cause: The `responseData` configuration item is not enabled, causing the interface to only return structured identifiers without carrying the original cited content.
- Phenomenon: Cited content has messy formatting, and fields are displayed non-standardly. Cause: The `detail` configuration item is not enabled, and cited fragments are not split according to document structure, leading to cluttered display.
- Phenomenon: The number of recalled citations does not match the actual related files. Cause: The single recall limit setting does not match the business scenario. A setting that is too high will introduce unrelated files, while a setting that is too low will miss necessary traceability information.

## How to Confirm Configuration Completion
- Initiate a test request, check whether the original cited content corresponding to the `responseData` field is included in the returned results.
- View the citation display area, confirm that file approval node information at the `detail` level is split and displayed according to the document structure.
- Submit a standard declaration material, check whether the number of recalled related files matches the business expectation.
- Check the knowledge base sync logs, confirm that the incremental update task is executed at the preset frequency.
