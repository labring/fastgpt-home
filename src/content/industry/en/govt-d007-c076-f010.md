# Declaration Materials and Case Review for State-owned Capital Operation Companies: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Data for this category comes from declaration and review workflows of state-owned capital operation companies. It includes declaration materials such as state-owned capital budgets, equity transfers, and annual operating performance assessments. It also covers case files for project initiation, due diligence, and compliance reviews. Data updates align with project cycles and review batches. Single declaration materials are updated with project progress. Archived cases are updated in bulk quarterly. Documents contain structured fields and long-text attachments. Structured fields include the unified social credit code of the declaring entity, project number, declared amount (unit: ten thousand yuan), and review node status. Most attachments are PDF and Word format declaration descriptions and supporting materials.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Structured fields in declaration materials require retrieval to match both exact fields and semantic content. Long-text attachments need segmented recall that retains context, to avoid breaking review logic. Declaration materials updated with project cycles require the knowledge base to support incremental updates, without needing to retransmit all historical data. Review node status in case review files changes frequently, so the system needs to recall historical documents for the corresponding nodes as references. Single files can be large in size, and vectorization exceptions may occur after chunking, so supporting verification mechanisms are needed. There are many professional terms in state-owned capital declarations, and general semantic retrieval may not accurately match review content, so term optimization is required.

## Configuration Settings

| `limit` | Top 8 entries | Number of case and declaration material chunks retrieved per single call, aligns with the volume range of review materials for state-owned capital operation reviews, and avoids context overflow |

| `datasetSearchUsingExtensionQuery` | Enabled | Performs expansion optimization on user review questions, supplements professional terms for state-owned capital declarations, and improves retrieval matching accuracy |
| `collectionIds` | Bind corresponding knowledge base IDs by business domain | Isolates declaration materials and cases from different projects, avoids cross-domain retrieval interference with review workflows |

## Three Common Mistakes
- Phenomenon: After uploading a state-owned capital operation declaration PDF file larger than 10MB, the backend shows that some chunks have vectorization failure status, and recovery fails after multiple retries. Cause: No automatic verification mechanism is configured for large file chunking, and some long-text chunks suffer semantic truncation, preventing the vectorization model from encoding correctly.
- Phenomenon: The number of knowledge base retrieval results does not match the configured `limit` parameter, with excess or insufficient results. Cause: The `collectionIds` parameter is not bound correctly, leading to retrieval of redundant data across business domains, or the similarity threshold is set unreasonably, causing filtering exceptions.
- Phenomenon: Retrieval shunting exceptions occur when the workflow calls the knowledge base, and retrieval results from tool calls and MCP calls are mixed. Cause: No dedicated retrieval mode is configured for the structured fields of state-owned capital declarations, causing general retrieval to fail to match the precise fields required for reviews.

## How to Confirm the Configuration Is Set Correctly
- A state-owned capital operation declaration file larger than 10MB is uploaded, the chunk status after splitting is checked, and it is confirmed that there are no vectorization failure entries.
- A review query including the unified social credit code of the declaring entity is entered, and it is verified that retrieval results prioritize returning declaration materials for the corresponding entity.
- The value of the `similarity` parameter is adjusted, changes in the number of retrieval results are observed, and it is confirmed that the value range meets business requirements.
- A bulk knowledge base update is triggered, and it is verified that the incremental update only synchronizes newly uploaded declaration materials and cases, and does not trigger full retransmission.
