# Declaration Materials and Case File Review for State-owned Capital Operation Companies: Deployment and Upgrade

## What the data for this category looks like
Data sources include internal property right transfer declaration forms, operational performance case files, state-owned asset supervision approval documents, and standard declaration templates issued by regulatory authorities.
Data updates align with project cycles.
Individual documents have wide length variation. Simple declaration forms are only tens of characters long. Complete case files can reach tens of thousands of characters.
Document structure has two parts: structured fields and unstructured content. Structured fields include the unified social credit code of the declaring entity, project number, approval node, review opinions, and other items. Unstructured content includes scanned documents, attachment descriptions, and similar materials.

## What constraints these characteristics impose on deployment and upgrades
Variations in document length require deployments to support large file processing and retrieval logic for all document lengths. This avoids wasting resources on short documents and truncating core information in long documents.
Mixed multi-source data structures require deployments to support simultaneous access to structured databases and unstructured storage. Upgrades must maintain synchronization consistency across all data sources.
Update rhythms tied to project cycles require deployment incremental synchronization mechanisms to adapt to irregular bulk data updates. This prevents data interruptions during upgrades.
Multi-dimensional field requirements require retrieval configurations to support multi-field joint queries. This ensures accurate positioning during the review process.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 1000–1500 characters | Matches the average length of a single declaration case file, prevents truncation of core review fields |
| `STORAGE_S3_ENDPOINT` | Internal enterprise object storage access address | Used to store backup copies of scanned case files and structured declaration data |
| `REDIS_URL` | Dedicated cache instance, memory allocation no less than 2 GB | Supports real-time retrieval and status caching for batches of declaration materials |
| `MONGODB_URI` | Bind to an independent database instance, enable read-write separation | Meets the multi-dimensional field joint query requirements for review case files |
| `FILE_TOKEN_KEY` | Enterprise-developed encryption key | Ensures access permissions and data security for declaration materials |
| `FE_DOMAIN` | Actual externally accessible domain name | Ensures correct status synchronization and interface calls for the frontend pages |

## Three common configuration errors
- Issue: Custom retrieval count cannot be adjusted above 6. Cause: The `DB_MAX_LINK` configuration value was not modified. The default setting limits the maximum number of entries per retrieval.
- Issue: The reranking component called via docker deployment returns false, but the interface returns a 200 status code. Cause: Correct cross-origin permissions were not configured in the `REDIS_URL` setting. This prevents retrieval results from being properly passed to the reranking stage.
- Issue: After upgrading to FastGPT v4.17.0, the plugin editing page continuously displays an unsaved changes prompt. Cause: `FE_DOMAIN` was not correctly configured to the actual access domain name. This causes frontend status synchronization failures.

## How to confirm the configuration is set correctly
- Upload a standard property right transfer case file document. Check that all structured fields are fully included in the retrieval results, with no truncation.
- Call the reranking component interface. Verify that the credibility score of the returned results is not empty and meets expectations.
- Modify and save the plugin configuration. Check that the unsaved changes prompt in the upper right corner of the page disappears.
- Adjust retrieval-related configurations. Verify that the number of retrieval entries shown in the backend logs matches the configured value.

The values listed above are common starting points. They should be evaluated against the reader’s own samples.
