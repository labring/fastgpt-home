# Public Transit Declaration Materials and File Review: Citation Sources and Traceability

## What This Category of Data Looks Like
The data for public transit declaration materials and file review comes primarily from internal scheduling systems, ticket settlement platforms, vehicle operation maintenance archives, and industry regulatory reporting systems. Daily operation data is updated daily. Single declaration files are archived and updated per project batch. Documents are a mix of structured forms and unstructured scanned files. Structured fields include route number, operating mileage, passenger trips, declaration date, and review node. Units include kilometers, trips, and vehicle counts. Most scanned files are in PDF format, with electronic signature information attached.

## What Constraints These Characteristics Impose on Citation Sources and Traceability
The mixed structured and unstructured data structure requires the traceability link to support both field-level precise matching and full-text recall of scanned files. Batch-archived files need to be associated with declaration batch metadata. This ensures that cited content belongs to the corresponding declaration project and avoids cross-batch confusion. Specialized industry fields and units require the knowledge base to classify and bind public transit operation-specific terminology. This prevents matching with irrelevant industry data. The traceability requirement for electronic signatures requires retaining the original file's archive path and timestamp. This ensures that citation sources can be traced back to the original submission node.

## How to Configure
Configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average text length of a single public transit file, avoids truncating core review materials |
| `responseData` | Enabled | Adapts to the field traceability needs of structured declaration materials, associates corresponding review nodes |
| `detail` | Enable full traceability details | Retains the original file's archive path and electronic signature information to meet compliance traceability requirements |
| Single recall limit | Top 6 entries | Covers the main citation sources for a single declaration material, avoids redundant information interfering with review |
| Knowledge base classification binding | Public transit operation declaration exclusive classification | Matches industry-specific terminology, reduces recall of irrelevant industry content |

## Three Common Misconfigurations
- Phenomenon: An API call returns a 200 status code but no content field. Cause: The `responseData` configuration is not enabled. This excludes structured fields from the return scope, only returning unstructured text without correct mapping.
- Phenomenon: Cited content contains garbled characters or inconsistent formatting. Cause: Scanned PDF files have not undergone OCR preprocessing, or the exclusive classification for knowledge base matching is not specified. This causes garbled text from non-public transit industries to be included.
- Phenomenon: Cited content exceeds the scope required for review, with file content from unrelated projects appearing. Cause: The single recall limit is not set, or the exclusive knowledge base classification for public transit operation declarations is not bound. This results in recall of declaration materials from other industries.

## How to Verify Proper Configuration
- Submit a test request for a single declaration material. Check if the returned result includes the archive path and signature information corresponding to the `detail` field.
- Review knowledge base recall results. Confirm that only public transit operation declaration documents are included, with no irrelevant content from other industries.
- Adjust the value range of `quoteMaxToken`. Verify that returned cited content does not have core text truncated.
- Trigger a batch file review request. Check that the citation source of each result corresponds to the correct declaration batch metadata.

The values provided are common starting points and should be measured against the reader's own samples.
