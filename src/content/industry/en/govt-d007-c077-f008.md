# Public Transit Agency: Declaration Materials and Case Review — Document Parsing and Chunking

## What This Category of Data Looks Like
Public transit agency declaration materials and case data primarily come from daily operational declarations, administrative approval case files, monthly operational reports, and annual inspection documents. Update frequency aligns with business milestones: daily route adjustment submissions are made on demand, quarterly case files are uploaded in batches per archiving cycles, and annual inspection materials are submitted ahead of inspection periods. Main document formats are PDF and Excel, with some case files including scanned copies of on-site inspection photos. Documents include fixed fields such as route number, approved passenger capacity, average daily passenger flow, and approval process nodes. Units include passenger trips, operational kilometers, and number of scheduled trips.

## Constraints on Document Parsing and Chunking
The data characteristics outlined above create multiple constraints for the document parsing and chunking workflow. Mixed-format documents require the parsing pipeline to support both plain text extraction and OCR recognition. This accommodates scanned case files and photo attachments. There are many tightly linked fixed fields. Chunking must avoid splitting cross-page approval process explanation paragraphs. Splitting these breaks the logical coherence of the approval workflow. Batch documents uploaded in concentrated monthly batches require longer parsing timeout settings. This prevents parsing failures from excessive task duration. Large individual annual inspection case files may exceed default upload limits. This requires adjustment of the upload size threshold.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `customPdfParse` | Enabled | Accommodate scanned approval documents and on-site inspection photos in case files, extract annotated text embedded in images |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meet the large-volume storage and upload requirements of individual annual inspection case files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 seconds | Address the extended parsing time required for batch monthly declaration materials, avoid mid-task timeout interruptions |
| `chunkSize` | 800–1200 characters | Balance the integrity of approval node paragraphs and retrieval granularity after chunking, avoid excessive splitting or merging of content |
| `chunkSplitter` | Paragraph + custom delimiter | Preserve the relational association between Excel report headers and detail rows, avoid splitting structured data |
| `chunkSettingMode` | Manual configuration | Adapt to the mixed-format characteristics of transit documents, flexibly adjust chunking rules to match different document types |

## Three Common Misconfigurations
- Uploading annual inspection case files larger than 3 MB results in an immediate error indicating an upload limit violation. This occurs because the `UPLOAD_FILE_MAX_SIZE` parameter was not adjusted, and the default small-volume upload threshold was used instead.
- After setting a custom delimiter to a line break, chunking results either merge multiple approval explanation paragraphs or split individual passenger flow statistics detail rows. This happens because the `chunkSize` parameter was not adjusted to match the chunking granularity, or matching rules were not manually configured via `chunkSettingMode`.
- Uploading an Excel-format monthly passenger flow report only extracts the header without detail data. This is because the parsing logic for structured tables was not adapted, and the default chunking rules cannot preserve the row-column association structure of Excel files.

## How to Verify Proper Configuration
- Upload a single scanned case file larger than 1 MB, check if the parsed result includes OCR-recognized annotated text to confirm the `customPdfParse` configuration is active.
- Upload a batch of small declaration documents, verify that parsing task durations meet expected values to confirm the `PARSE_FILE_TIMEOUT_SECONDS` parameter supports batch processing requirements.
- Upload a multi-page PDF document containing approval processes, manually review chunking results to confirm cross-page approval node content is preserved, verifying that the `chunkSize` and `chunkSplitter` configurations match the document structure.
- Upload an Excel-format report file, check if parsed text retains the relational association between headers and corresponding detail rows to confirm chunking configurations are adapted for structured tables.

Note: The configuration values listed above are common starting points. Always validate settings against your own specific sample data.
