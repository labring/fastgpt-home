# Public Transit Declaration Materials and Case Review: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for public transit declaration materials and case review comes primarily from internal operation archives of transit companies, administrative approval declaration systems, and vehicle operation ledgers. Data updates are triggered by daily business processes. Daily declaration materials are archived when submitted at approval nodes. Case materials are updated in bulk each quarter. Document structures combine structured forms and scanned attachments, with fields including route number, approved passenger capacity, application reason, and approval node records. Units include kilometers, passenger trips, vehicle trips, and similar metrics.

## What constraints these characteristics impose on knowledge base retrieval and recall
The mixed structure of structured fields and scanned attachments requires retrieval to support both exact keyword matching and full-text semantic recall. This avoids missing valid content by relying solely on a single retrieval mode. The update rhythm driven by daily business processes requires recall logic to support incremental synchronization. This prevents excessive system resource usage from full refreshes. The binding relationship between specific fields and units requires retrieval to associate fields with their corresponding values. This prevents misjudgments caused by semantic ambiguity. The large length of individual case files requires controlling chunking and the number of recalled entries. This avoids context overflow that reduces review efficiency.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | 0.72–0.80 | Balances exact field accuracy and semantic relevance for transit declaration materials. Avoids being too strict and missing valid cases, or too broad and introducing irrelevant materials |
| `limit` | Top 8 entries | Adapts to the length of individual transit case files. Controls the number of recalled entries to avoid context overflow, while covering reference content for core review nodes |
| `searchMode` | semantic+keyword | Balances keyword matching for structured fields and full-text semantic recall. Meets retrieval needs for mixed document structures |
| `usingReRank` | Enabled | Rearranges recalled results by review priority. Prioritizes matches for core review fields such as route number and approved passenger capacity |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplements specialized terminology for transit declaration business. Optimizes search term coverage and improves recall rate of relevant results |
| `collectionIds` | Bind the exclusive transit declaration case folder ID | Isolates knowledge base content across different business lines. Avoids cross-category retrieval interference, and ensures the independence of review data |

## Three Common Misconfigurations
- Phenomenon: A provider-related error pops up after creating a new folder in the knowledge base. Cause: The exclusive transit declaration case folder for the current business is not bound to the specified `collectionIds`, resulting in failed permission verification.
- Phenomenon: An authentication failure prompt appears when synchronizing knowledge base collections via API. Cause: Valid credentials for the corresponding business folder are not included in the API request, or credentials are not refreshed according to the quarterly update rhythm.
- Phenomenon: Single retrieval takes too long, and returned results have insufficient relevance. Cause: `datasetSearchUsingExtensionQuery` is not enabled to supplement specialized business terminology, and the `similarity` threshold is set too high, resulting in valid recalled content being filtered out.

## How to Confirm Proper Configuration
- Enter the knowledge base management page, check if the transit declaration case folder is bound to the specified `collectionIds`, and confirm no folders from other business lines are included.
- Submit a simulated search request for a bus route adjustment declaration, check if the number of returned results matches the `limit` parameter setting, and that core field matching meets standards.
- Submit a new transit declaration material and trigger incremental synchronization, confirm that the new content is included in retrieval results within a reasonable time frame.
- Check the retrieval log, confirm that `usingReRank` is active, and that results are sorted to prioritize matches for core review fields such as route number and approved passenger capacity.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
