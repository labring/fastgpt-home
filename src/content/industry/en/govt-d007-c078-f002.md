# Municipal Water Utilities Application Materials and Case Review: Vector Models and Indexing

## What this category of data looks like
Data for municipal water utilities application materials and case review is sourced from electronic and paper documents including service connection applications, water quality testing declarations, pipeline maintenance approval requests, as well as administrative licensing and administrative penalty case files. Update cadences include daily batch submission of operational ledger data and one-off special declaration materials. Document formats include PDF declaration forms, Word approval sheets, and Excel operational ledgers. Fields include project ID, declaring entity, designed water usage, approval status, case archive number, and others. Units include cubic meters, tons, workdays, and others.

## What constraints these characteristics impose on vector models and indexing
Mixed-format data sources require the indexing stage to support cross-format text parsing and unified preprocessing. This avoids vectorization bias caused by format differences.
Coexisting daily batch operational ledgers and one-off special declaration materials require indexing to support incremental updates and batch submission configurations. This adapts to high-frequency update scenarios.
The presence of long-text case files and declaration forms requires chunking parameters to accommodate long paragraph splitting. This prevents single chunks from exceeding model processing limits.
The presence of exclusive business fields requires indexing to retain metadata fields. This enables precise filtering of results by business dimension during subsequent retrieval.

## Configuration Settings
These configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `defaultToken` | 8192 | Adapts to the token requirements of single chunks after splitting water utility case files, covering the paragraph length of most single declaration materials |
| `maxToken` | 16384 | Meets the context length after splicing multiple chunks, adapting to retrieval and inference requirements for long case files |
| Chunk Length | 800–1200 characters | Adapts to the paragraph structure of water utility declaration materials, avoiding overly long or short single chunks that negatively impact vectorization performance |
| Overlap Length | 100–200 characters | Ensures contextual coherence between chunks, covering cross-paragraph approval comments in case files |
| Similarity Threshold | 0.72–0.80 | Filters low-match non-business-related results, accurately matching core key fields of declaration materials |
| Single Search Limit | Top 10 entries | Controls the volume of retrieval results, adapting to parallel retrieval scenarios for multiple case files in water utility review |

## Three common errors
- Retrieval returns zero results. This occurs when the similarity threshold is set too high, filtering all matching water utility declaration material text.
- Indexing tasks frequently time out and interrupt. This occurs when `defaultToken` is not adjusted to accommodate long case file text, leading to token limit exceeded after single chunk parsing which triggers timeout.
- Retrieval results include non-water utility business content. This occurs when metadata is not filtered using exclusive business fields, leading to invalid cross-category recall.

## How to confirm correct configuration
- Upload a single water utility approval case PDF, check the chunk details after indexing, and confirm that chunk lengths fall within the preset 800–1200 character range.
- Submit a batch of 100,000-level water utility ledger data, check the completion status of indexing tasks, and ensure no timeout errors occur.
- Enter the search term "XX project declaration materials", verify that the similarity threshold of returned results falls within the preset 0.72–0.80 range, and that results only include water utility business-related content.
- View the metadata fields in the vector store, and confirm that business fields such as project ID and declaring entity have been correctly indexed.
