# Urban Water Utilities Declaration Material and File Review: Workflow Orchestration

## What the data for this category looks like
Data for urban water utilities declaration material and file review comes primarily from online fill-in forms in the water utility business management system, scanned paper documents submitted offline, and archived data from services such as water quality testing and drainage permits. Data updates trigger per declaration batch, with each completed submission updating the corresponding file. Document structure includes fields such as declaration subject information, project address, water quality test parameters, and approval node records. Water quality parameter fields include professional units such as mg/L. Files must be linked to a unique archive number and declaration batch number. Some materials use unstructured scanned document formats.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Global Variables | Store declaration batch number, COD concentration threshold, archive number | Used to pass core water utility business parameters across review nodes, use the `variables` parameter to manage global state uniformly |
| Node ID Association | Bind `nodeId` according to approval sequence | Ensures the file review workflow corresponds one-to-one with water utility approval nodes, fixes execution order for nodes |
| Tool Call Output | Hide raw logs returned by tools | Prevents unnecessary API debugging information from mixing into official review files, meets formal output requirements for water utility files |
| Boolean Judgment Trigger | Trigger branches based on approval status in `variables` | Used to judge format verification results of declaration materials, supports switch-style workflow branches |
| Multimodal Image Recognition | Enable image recognition and set confidence threshold 0.7-0.9 | Used to identify numerical values in scanned water quality test reports, adapts to unstructured content in water utility materials |
| Timeout Setting | 600 second timeout | Adapts to parsing duration of large-volume water utility scanned materials, prevents workflow interruptions from parsing timeouts |

## Three common mistakes
- Tool call module output not hidden, review interface displays redundant API call logs | Reason: Failed to configure output hiding rules for tool calls, so debugging information remains in official files.
- After MongoDB replica set primary node switchover, workflow cannot read new declaration data | Reason: Automatic reconnection configuration for MongoDB Change Streams was not enabled, so data source connection cannot be restored after interruption.
- No content returned after uploading images to multimodal image recognition node | Reason: Image recognition switch for the node was not enabled, or permissions for the corresponding multimodal model were not configured, so water utility material information in images cannot be extracted.

## How to confirm the configuration is complete
- Submit a standard water utility declaration test material, verify whether workflow nodes execute in preset order, check whether global variables are passed correctly.
- Trigger the tool call link, confirm that only review conclusions are retained in the output, with no additional tool debugging information.
- Simulate MongoDB replica set primary node switchover, verify whether the workflow automatically restores the data source connection.
- Upload unstructured water utility material images, confirm that the multimodal recognition node can normally return extracted numerical information.
