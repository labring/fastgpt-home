# Municipal Water Utility Application Materials and Case Review: Tool Calling and Plugins

## What the data for this category looks like
Municipal water utility application materials and case review data primarily comes from water utility government approval platforms, water supply enterprise business archives, and pipeline operation and maintenance case systems. Data is updated in real time alongside approval workflows. Individual application materials typically include structured application fields and attached documents, while cases include approval node circulation records, on-site inspection photos, water quality test reports, and more. Core fields cover project number, applicant subject, pipeline site coordinates, average daily water supply, and approval status. Units follow water industry professional metering standards such as cubic meters, millimeters, and days.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The coexistence of structured fields and mixed attachments requires that tool calling support both structured field extraction and multi-format attachment parsing, to avoid missing key approval information. Real-time updated data sources require that tool calling be configured with real-time synchronized data source interfaces, and cannot rely on static cached data. The presence of water industry professional metering fields requires that tool calling parameter mapping match specialized units such as cubic meters and millimeters, to avoid field parsing errors. The multi-node circulation case structure requires that tool calling be triggered per approval node, to avoid mixing data across nodes.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to mixed structured extraction and attachment parsing tasks in application materials and case review |
| `functionCall` | Enabled | Supports custom tool calling logic triggered per approval node |
| Tool call timeout setting | 600 seconds | Matches the average time required for attachment parsing and data verification in water utility approval workflows |
| Attachment parsing switch | Enable all supported formats | Covers common approval attachment types such as water quality reports and pipeline drawings |
| Professional field mapping rules | Map according to water industry professional units | Matches parsing standards for specialized metering fields such as cubic meters and millimeters |
| Node trigger configuration | Call grouped by approval node | Avoid mixing case data across circulation nodes |

## Three common mistakes
- Issue: Custom code calling water utility approval data sources returns AggregateError Code: ETIMEDOUT. Cause: No timeout parameters configured for water utility data retrieval, leading to retrieval time for pipeline site and water quality data exceeding default limits.
- Issue: Adding a MySQL database tool call results in a 400 status code (no body) in responses. Cause: Incorrect connection permissions configured for the water utility business database, or failure to specify dedicated query fields for approval ledgers.
- Issue: When configuring a problem classification workflow, the model execution results returned by the API do not match expectations. Cause: Did not use `toolChoice` to specify the model's task type as application material classification, leading the model to perform general question answering tasks.

## How to confirm the configuration is correct
- Submit a simulated single application material request, and verify that the fields returned by the tool call cover all core information required for water utility approval.
- Check the tool call logs to confirm that the triggered tool tasks match the current approval stage.
- Upload common approval attachments, and verify that the tool call can correctly parse key content from the attachments.
