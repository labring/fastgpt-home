# Urban Water Utilities Application Materials and Case Review: Source Citation and Traceability

## What this category of data looks like
Urban water utilities application materials and case review data primarily originate from business operation systems of water utility operators, administrative approval platforms, and archived case repositories. The data includes main qualification documents, project drawings, payment vouchers for water supply installation applications and drainage permit declarations, as well as case records for law enforcement inspections and operation and maintenance rectification. The platform updates data in real time when applications are submitted, and archives and locks the data after the case closes. Documents combine structured forms and unstructured attachments. Fields include application number, project address, water usage scale, approval stage, and other relevant items. Units involved include cubic meters, square meters, working days, and similar units.

## What constraints these characteristics impose on the source citation and traceability link
Application materials and cases for urban water utilities have characteristics of both structured forms and unstructured attachments. Unstructured attachments are mostly project drawings and PDF approval records. The citation and traceability process must match both form fields and source identifiers of attachment content. The platform updates data in real time when applications are submitted, and archives and locks the data after the case closes. This requires the cited version to match the archived version of the current business stage. Fields include quantified information with units, such as water usage scale and pipe network length. Traceability must retain the correspondence between original units and numerical values. Cases are linked to multi-stage approval materials. Full traceability of the entire chain of source records from submission to case closure is required, to avoid missing supporting documents from intermediate stages.

## Three Common Misconfigurations
- The page viewing model context only displays 30 entries, but the actual number of cited entries is 310, and the number sent to the caller is also 310. The cause is incorrect configuration of the truncation logic for `quoteMaxToken`, leading to a mismatch between the front-end displayed context cache and the number of source data entries in actual calls.
- The generated reply cannot display the attachment storage path of the citation source. The cause is failure to enable the complete path return configuration for `responseData`, only returning field names without associating actual storage locations.
- The original unit information of water utility application material fields is lost in citations. The cause is failure to configure the traceability rule for unit retention, only extracting numerical content without associating original unit fields.

## How to Confirm Configurations Are Correct
- Submit a water utility application test material including multiple attachments and structured fields, and check whether the generated reply includes complete source paths and field identifiers.
- Adjust the value of `quoteMaxToken`, and verify whether the number of context entries displayed on the front end matches the number of source data entries in actual calls.
- Check whether quantified content in the generated reply includes original units, confirming that the unit retention configuration is active.
- Submit the same case material for different business stages, and verify that the cited version matches the archived version of the current business stage.
