# Urban Water Utility Application Materials and Case Review: Deployment and Upgrade

## What this category of data looks like
Data for urban water utility application materials and case review primarily comes from water intake and drainage permit application forms, daily inspection cases, water quality test reports, and other water utility operation ledgers. Data updates trigger alongside approval workflows. Single application materials are submitted once. Archived cases update by approval batch or monthly. Each document includes fields such as applicant identification, core water utility parameters (for example, average daily water supply, unit: cubic meters per day), approval node records, and attachment file links. Fields must match standard administrative approval formats for the water utility industry, and some fields require dedicated unit identifiers.

## What constraints these characteristics impose on deployment and upgrade
Data sources for this category are scattered and must align with industry approval standards. During deployment, support multi-format data source access and field unit mapping to avoid breaking compliance formats for water utility approvals. Data updates dynamically with approval workflows. Deployment and upgrade processes must ensure synchronization links remain uninterrupted, otherwise approval materials cannot be stored in a timely manner. Individual cases include attachment files. During deployment, configure parameters adapted for large file storage. During upgrades, retain original attachment access paths to prevent disruption of archived case access. Additionally, fields must strictly match fixed formats for water utility administrative approvals. Do not arbitrarily adjust field structures during upgrades, to avoid issues where approval materials cannot be recognized.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 records/minute | Adapts to batch import frequency for water utility cases, avoids overloading database connections |
| `STORAGE_S3_ENDPOINT` | Intranet access address adapted for local object storage | Ensures stable storage and cross-node access for large attachment cases in water utilities |
| `REDIS_URL` | Intranet access address with password authentication | Caches temporary status of approval workflows, avoids repeated calculation of approval node information |
| `FE_DOMAIN` | Official domain name of the water utility intranet approval system | Unifies front-end access paths, adapts to access rules for internal office networks |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Encrypts access tokens for case attachments, ensures access security for sensitive water utility data |
| `ROOT_KEY` | Configured per internal permission hierarchy rules | Restricts background management access scope, matches permission control requirements for water utility systems |

## Three common errors
- Issue: 403 or domain mismatch errors occur when accessing the application release interface. Cause: `FE_DOMAIN` is not configured as an intranet HTTPS domain, and an HTTP address is used instead, resulting in failure of normal voice function calls.
- Issue: Old version workflow applications cannot be imported after upgrade. Cause: The old application data directory corresponding to `MONGODB_URI` was not backed up and migrated in advance, resulting in loss of workflow metadata.
- Issue: Statistical charts for case review display errors after upgrading to FastGPT v4.17.0. Cause: Database indexes corresponding to `PG_URL` were not updated synchronously, and old query logic is incompatible with the new database structure.

## How to confirm configurations are properly set
- Run a batch import test for water utility cases, verify that database connection status matches the rules for `DB_MAX_LINK` configuration.
- Upload a water quality test report attachment, verify that the storage path can be accessed normally and complies with the configuration requirements of `STORAGE_S3_ENDPOINT`.
- Access the configured front-end domain name, confirm that the domain name of the application release interface matches `FE_DOMAIN`.
- Import a test workflow, verify that metadata can be loaded normally with no configuration conflicts.
