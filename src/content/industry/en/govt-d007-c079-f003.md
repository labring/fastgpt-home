# Urban Gas Application Materials and Case Review: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data sources include archived files from urban gas enterprises’ installation application systems, completion acceptance case libraries, and municipal public utility supervision platforms.
Application materials are added in real time as users submit them. Case review data is updated with each review milestone.
Document structure includes structured fields and attachments. Structured fields include applicant unit name, gas usage address, gas usage scale, application date, and review status.
Attachments are mostly PDF-format construction drawings and qualification certification documents. Units include cubic meters and date-type fields. Some individual attachments have large total content.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Since the data includes structured fields and multi-page attachments, multi-turn dialogue must clearly define core query fields to avoid redundant interactions.
The real-time addition of application materials requires prompts to automatically associate the latest submitted cases, preventing the use of outdated data.
The case review milestone update logic requires the dialogue flow to sync with review status. Approved cases do not need repeated requests for qualification materials.
Additionally, attachment formats vary. Prompts must explicitly require the large model to first extract structured information from attachments, then generate review results combined with user dialogue. Context length must be limited to avoid overflow.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Enable automatic sequential extraction | Adapts to application information gradually provided by users in multi-turn dialogue, reducing manual input costs |
| `chatId` | Bind to the current case ID | Ensures multi-turn dialogue is associated with the same application case, preventing context confusion |
| `messages` | Limit historical messages to 8 entries | Controls total context length, avoiding excessive resource usage |
| Maximum context length | 8000–12000 characters | Matches the total content length of a single case review material, preventing valid information from being truncated |
| Maximum single dialogue rounds | 8 rounds | Aligns with standard gas application review interaction workflows, preventing context chaos from overly long dialogues |
| Attachment processing toggle | Enable PDF text and image parsing | Adapts to text extraction and image association requirements for qualification documents and construction drawings |
| Keyword recall threshold | 0.75–0.85 | Filters low-relevance historical application data, improving review matching accuracy |

## Three Common Misconfigurations
- Symptom: Dialogue cannot display gas qualification document images from the knowledge base, only returning text descriptions. Cause: The prompt does not explicitly require the large model to identify and associate image information in attachments, and relevant rules for image index calls are not configured.
- Symptom: Extracted keyword variables (such as gas usage address, application date) do not match the actual input content, with field misalignment. Cause: The `variables` sequential extraction configuration is not enabled, and the prompt does not define priority for variable extraction, leading to confusion between historical dialogue and current query information.
- Symptom: Response timeout or empty results occur after multi-turn dialogue exceeds 8 rounds. Cause: Reasonable maximum context length or `messages` retention count is not set, exceeding system capacity limits causes valid context to be truncated, making it impossible to match corresponding case data.

## How to Verify Successful Configuration
- Initiate a multi-turn dialogue including gas usage address and application date, check that extracted `variables` match the input content.
- Upload a gas qualification PDF attachment, check that the dialogue response includes text and image association information from the attachment.
- Initiate an audit query dialogue with more than 8 rounds, check that the response is normal and no context truncation prompt appears.
- Check that `chatId` is bound to the current case ID, ensuring multi-turn dialogue is associated with the same application item.
- Adjust the keyword recall threshold, check that the matching degree of returned case data meets business requirements.

The values provided are common starting points, and should be evaluated against the reader’s own samples.
