# Urban Gas Application Materials and Case Review: Workflow Orchestration

## What this category of data looks like
Data for urban gas application materials and case review originates from gas operating enterprises’ business acceptance systems, safety inspection archive databases, and installation approval platforms. Business systems generate data in real time as work processes conclude, with tens to hundreds of pending review cases added each day. Each individual case includes two parts: structured fields and attachments. Structured fields cover gas usage address, installation capacity (unit: cubic meters per hour), applicant identity information, approval node records, and more. Most single field lengths range from 800 to 1200 characters. Attachments are mostly files in formats such as construction drawing PDFs and ID card scan JPEGs. ## What constraints these characteristics impose on workflow orchestration
The dual structure of structured fields and mixed attachments requires workflows to support both structured data extraction and file stream processing. Real-time business data updates mean workflows must bind to event triggers from business systems, with no reliance on scheduled polling. Fixed approval node sequences (initial review, recheck, archiving) require workflow node transitions to follow preset logic strictly, with no arbitrary adjustments. Fields have specific units such as cubic meters per hour, so workflows must configure basic verification rules to ensure extracted values comply with specifications.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Trigger Mode | Triggered by the submission event of the gas business system | Application materials are generated in real time, requiring immediate entry into the review process |
| Variable configuration `variables` | Preset three core variables: gas usage address, installation capacity, applicant ID number | The core fields of urban gas application materials are fixed and can be directly extracted from the business system |
| Node Transition Rules | Bind three nodes: initial review, recheck, archiving in sequence according to `nodeId` | Case review has a fixed approval link sequence, and transition logic must be strictly followed |
| File Processing Configuration | Support PDF and JPEG format file streams, maximum single file 1000 MB | Gas application attachments are mostly construction drawings and identification documents, and common formats and size ranges match this configuration |
| Node Timeout Setting | 600 seconds timeout for each review node | Case review requires sufficient time for manual recheck and document verification |

## Three common mistakes
- Phenomenon: The workflow returns an empty file or format error after executing an HTTP request node. Cause: The file stream receiving mode is not configured, and the default setting only processes text responses.
- Phenomenon: The workflow cannot trigger the user-selectable parameter popup. Cause: Optional parameter items are not configured in `variables`.
- Phenomenon: The workflow node transition sequence does not match the preset. Cause: The drag-and-drop order of workflow nodes was manually adjusted, and the fixed transition logic was not bound according to `nodeId`.

## How to confirm the configuration is correct
- Submit a simulated gas application material to check whether the workflow transitions through preset nodes in sequence.
- Upload a PDF attachment in the correct format to confirm that the workflow can normally read the file content.
- Configure optional parameters in `variables` to test whether a selection popup can be triggered on the frontend.
- Simulate a timeout scenario for a single review node to confirm that the workflow triggers a timeout alert.

The values provided are common starting points and should be evaluated against corresponding samples.
