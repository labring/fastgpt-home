# Urban Gas Utility Application Materials and Case Audit: Deployment and Upgrade

## What the data for this category looks like
Data for urban gas utility application materials and case audit originates primarily from submitted documents in business workflows including gas connection applications, transfers, and safety inspections. Update triggers run in real time when business orders are created, or via daily batch synchronization. Documents include structured forms with fields such as user name, gas usage address, and installation capacity, using units of cubic meters per hour and square meters. Files also include scanned PDFs and approval flow records. Structured data per individual case is approximately hundreds of characters, while unprocessed materials can reach tens of megabytes per file.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
This guide covers FastGPT v4.17.0. Data includes sensitive user information and large unstructured materials, so deployments require separate permission-isolated storage and database resources. Frequent business order updates demand vector databases and cache services with high concurrency processing capabilities, plus support for scanned document preprocessing. During upgrades, ensure migration compatibility of existing case metadata to avoid losing historical approval records due to configuration changes. Add domain verification for original material download links to prevent unauthorized access.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://gas_audit:new_password@db-host:27017/gas_audit_db?authSource=admin` | Stores structured case metadata and approval logs. Must bind to a dedicated gas business database and grant read/write permissions |
| `REDIS_URL` | `redis://:redis_pass@redis-host:6379/1` | Caches frequently queried approval status and material preview data. Cache validity period set to 600 seconds |
| `FILE_TOKEN_KEY` | `Randomly generated 32-digit hexadecimal string` | Encrypts access tokens for downloading original materials to prevent unauthorized access to sensitive gas user materials |
| `STORAGE_S3_ENDPOINT` | `https://gas-material-storage.example.com` | Stores uploaded scanned application materials and original PDF files. Adapts to a maximum storage requirement of 1000 MB per material |
| `FE_DOMAIN` | `https://gas-audit.example.com` | Configures frontend access domain for generating correct download links and callback addresses |
| `DB_MAX_LINK` | `800–1200 characters` | Limits the number of case entries returned per database query to adapt to single-page data volume of gas application materials |

## Three Common Misconfigurations
- Scenario: After deploying with Docker, modifying the database password results in container startup failure with an authentication error. Cause: Failed to synchronize the new password in `MONGODB_URI` and did not rebuild the container to load the latest configuration.
- Scenario: After configuring Nginx proxy, knowledge base original material download links return 404 errors. Cause: Did not set `FE_DOMAIN` to the full proxy domain name, causing token verification to fail.
- Scenario: After local deployment, the team invitation function is unavailable. Cause: Did not configure `ROOT_KEY` to generate administrator permissions, and did not enable necessary configuration items for team functions.

## How to Confirm Proper Configuration
- Run the docker-compose up command, then check container logs for no database connection or cache connection error messages.
- Access the configured `FE_DOMAIN`, upload a simulated gas application material, and confirm that the download link can be opened normally without permission interception.
- Use the administrator token generated with `ROOT_KEY` to call the interface to query the case list, and confirm that the returned data matches the stored metadata.
- After modifying the password in `REDIS_URL`, restart the corresponding container, and confirm that the cache function can still respond to query requests normally.

The values provided are common starting points and should be evaluated against the reader's own samples.
