# Urban Investment Platform Declaration Materials and File Review: HTTP Interfaces and External Systems

## What this type of data looks like
Data for urban investment platform declaration materials and case files mainly comes from internal project declaration systems, government approval platforms, and financial archives. Data is submitted in project batches, updated alongside daily file archiving, with no real-time high-frequency pushes. Each individual document is 1000 to 5000 characters long, containing structured fields such as project number, unified social credit code of the declaration entity, declaration amount (unit: ten thousand yuan), approval node records, and qualification document number. Some documents include text parsed from attached scanned files.

## What constraints these characteristics impose on HTTP interfaces and external systems
The batch submission, fixed structured fields, and parsed attached text features of urban investment platform declaration materials and case files impose multiple constraints on HTTP interfaces. Fixed fields such as unified social credit code and declaration amount (ten thousand yuan) require the interface to configure format verification rules to prevent invalid data from being passed in. Business scenarios with batch submissions require the interface to support receiving batch data, while returning the processing ID of each data item for local mapping. The requirement for parsed text from scanned attachments requires the interface to adapt to the multipart/form-data request format, supporting associated file and metadata uploads. The update rhythm of batch-based archiving requires the interface to support incremental synchronization identifiers to filter already processed case data.

## How to configure settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Request timeout | 300–600 seconds | Matches the parsing and transmission time of a single case file |
| Request header configuration | Fixed `Authorization` header parameter | Complies with the interface authentication specifications of external systems |
| Batch processing threshold | 50–100 items per request | Adapts to the batch size of a single declaration from urban investment platforms |
| Response data format | Return `responseData` structured field | Facilitates local system mapping of processing result IDs |
| Context variable binding | Map business fields to `variables` | Pass exclusive parameters such as declaration entity and project number |
| Retry count | 2 times | Addresses request failures caused by temporary network fluctuations |

## Three common configuration mistakes
- Phenomenon: After submitting declaration data in batches, the interface returns results without corresponding data IDs, making it impossible to complete mapping with the local system. Cause: The return rule for the `responseData` field is not configured, and the interface only returns the overall submission status without outputting the processing identifier for individual data items.
- Phenomenon: A 401 unauthorized error occurs when calling the interface, or the request is intercepted by the external system. Cause: The `Authorization` header parameter is not configured correctly, and the authentication key is not updated synchronously with the external system.
- Phenomenon: The volume of case data submitted in a single request is too large, causing the interface to time out or truncate the response. Cause: A reasonable batch processing threshold is not set, exceeding the single request bearing limit of the external system.

## How to confirm the configuration is correct
- Send a test request to the configured interface address of FastGPT v4.17.0, carry simulated declaration material fields, and check if the returned results contain the expected structured data.
- View the external system call logs of FastGPT, confirm that the `Authorization` header parameter is correctly carried, and there are no authentication failure records.
- Submit a small batch of test data, verify whether the local system can obtain the returned processing ID and complete the mapping.
- Simulate a temporary network interruption, check whether the interface automatically initiates retry requests according to the configured retry count.
