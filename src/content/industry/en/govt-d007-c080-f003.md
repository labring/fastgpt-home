# Urban Investment Platform Declaration Materials and Case File Review: Multi-turn Dialogue and Prompt Terms

## What the data for this category looks like
Data for urban investment platform declaration materials and case file review comes from four main sources: project declaration ledgers, land use approval archives, debt filing documents, and talent entry archives.
Data updates trigger in batches alongside project declaration cycles, and are synchronized weekly for daily operations.
Each individual case file document includes fields such as case file number, declaration subject, project category, submitted material details, and audit circulation records.
Talent information paragraphs include unique numeric identifiers.
Documents are archived per individual case file, with fields structured hierarchically according to audit stages.

## Constraints on multi-turn dialogue and prompt configuration
The hierarchical structure of case file data requires multi-turn dialogue to retain context linked to the corresponding case file number, to avoid mixing audit information from different projects.
The unique numeric identifier attached to talent information paragraphs requires prompt terms to precisely match target fields, to prevent non-specified talent data from appearing in search results.
The batch-update rhythm of declaration materials tied to project cycles requires context length to fit the content scale of batch searches, to avoid exceeding token limits.
Multi-turn interactions for audit circulation require retaining historical records of `messages` to ensure coherence of audit opinions. It also requires limiting `variables` to only pass exclusive parameters for the current case file, to prevent interference from cross-file data.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Fits the paragraph scale of individual declaration materials, avoids overly long single chunks that harm retrieval performance |
| Overlap Length | 150–200 characters | Retains contextual links for case file audit workflows, prevents breaks in cross-chunk information |
| Single Search Limit | Top 8 entries | Matches the number of core fields in a single-case-file declaration material, avoids redundant search results |
| Context Window Size | 8000 tokens | Fits the historical record length of multi-turn audit dialogues, aligns with the interaction scale of urban investment platform case files |
| Conversation ID Binding | Bind to current case file number | Ensures `chatId` corresponds one-to-one with case files, avoids context confusion across cross-file dialogues |
| Variable Filter Rule | Only pass current case file number | Prevents `variables` from including unrelated parameters, ensures precise search scope |

## Three Common Misconfigurations
- Symptom: Search results return talent information paragraphs with numeric identifiers, and redundant identifiers appear in the interface display. Cause: The prompt terms do not explicitly require filtering the unique numeric identifier field attached to paragraphs, causing knowledge base search results to carry extra identifiers directly.
- Symptom: The dialogue interface fails to display attached images from declaration materials, only showing blank placeholders. Cause: The knowledge base image parsing configuration is not enabled, or the uploaded image format is not compatible with the system.
- Symptom: Custom model response results differ between the dialogue interface and workspace. Cause: The historical context transfer rules for `messages` are not uniformly configured, leading to differences in dialogue context across the two scenarios.

## How to Verify Successful Configuration
- Initiate a multi-turn audit dialogue for a single case file, check whether returned talent information only includes text content with no extra numeric identifier markers.
- Upload a declaration material attachment containing images, verify whether images display normally in the FastGPT v4.17.0 dialogue interface.
- Pass the same case file parameters in both the dialogue interface and workspace, compare whether the logic and content of the two responses are consistent.
- Adjust the parameters passed to `variables`, check whether search results only match exclusive fields for the current case file, with no cross-file data mixed in.
