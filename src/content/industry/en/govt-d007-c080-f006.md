# Declaration Materials and File Review for Urban Investment Platforms: Citation Sources and Traceability

## What the Data for This Category Looks Like
The data for declaration materials and file review for urban investment platforms comes from internally approved and circulated project declaration documents, qualification verification archives, and audit trail files. Data updates are triggered along with individual project declaration workflows. Version iterations are completed within the cycle from submission to archiving of a single file. The document structure includes file number, unified social credit code of the declaring entity, project approval document number, list of supporting material attachments, and multi-level audit opinion fields. All fields are bound to unique business identifiers. The unit of archiving is one file. The length of a single declaration document varies with project scale, with no fixed upper limit.

## What Constraints These Characteristics Impose on the "Citation Sources and Traceability" Link
Because all data is bound to unique business identifiers, citation traceability requires precise matching of file numbers and declaring entity identifiers to avoid cross-project confusion. Data is updated dynamically along with project workflows. Knowledge base synchronization must be linked to business node timestamps to ensure that the referenced version corresponds to the correct audit stage. The presence of multi-level audit opinion fields requires that traceability outputs clearly mark the audit link and corresponding document location. The large variation in the length of single declaration documents requires adaptation to different lengths of document splitting and reference ranges to prevent truncation of key audit trail content.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of single declaration documents for urban investment projects, preventing truncation of key audit trail content |
| `responseData` | Return only matching knowledge base entries | Ensures outputs only link to archived declaration files and audit materials, and no content without sources is generated |
| `detail` | Enabled | Requires returning complete business fields of matched documents, including file numbers and audit link identifiers |
| Maximum number of recalled entries | Top 8 entries | Covers common combinations of multiple supporting materials for urban investment project declarations, avoiding omission of key attachments |
| Context synchronization window | Calibrated by project cycle | Links all archived documents of the corresponding declaration batch, ensuring traceability covers full-process materials |

## Three Common Misconfigurations
- Phenomenon: The interface displays cited source data but does not output the corresponding file number. Cause: The `detail` parameter is not enabled, and the business identifier field of the document is not requested to be returned
- Phenomenon: The configuration variable format is invalid, and non-knowledge base original content is output. Cause: The knowledge base dataset ID corresponding to the urban investment project is not correctly bound, or the `responseData` parameter to lock knowledge base sources is not enabled
- Phenomenon: The number of recalled results does not match the actual matched documents. Cause: The maximum number of recalled entries is set too low, failing to cover the multi-attachment scenario of urban investment declaration materials

## How to Confirm the Configuration Is Properly Set Up
- Enter the file number of an urban investment project, and check whether the output includes this number as a traceability identifier
- After triggering a question and answer, review the cited source list in the returned results to confirm that only uploaded declaration materials and audit files are included
- Adjust the `quoteMaxToken` parameter to verify that audit opinions in long documents are fully displayed without truncation
- Submit multi-level business queries to confirm that each recalled document is linked to the current project's business batch
