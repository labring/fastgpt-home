# Basic Chemicals Declaration Materials and Case Review: Vector Models and Indexes

## What this category of data looks like
The data for basic chemicals declaration materials and case review mainly comes from internal enterprise project declaration documents, safety supervision case files, environmental impact assessment filing documents, etc. The update rhythm includes batch updates during the project declaration phase and incremental updates during daily archiving. The document structure contains structured fields such as project number, declaration subject, capacity parameters, and long text bodies such as process flow diagram descriptions, raw material ratio lists. Most fields contain professional units including tons, cubic meters, megapascals, etc.

## What constraints these characteristics impose on the vector models and indexes link
The long text proportion of basic chemicals declaration materials and case files is high, and the token count of a single document easily exceeds the model limit, requiring reasonable adjustment of chunking parameters. Professional units and process parameters in structured fields will affect the semantic accuracy of vector matching, so field identifiers must be retained during chunking. The incremental data from batch archiving requires the index to support incremental synchronization to avoid resource consumption caused by full reconstruction. Some confidential case files need to use locally deployed vector models and cannot rely on cloud embedding services. These constraints directly determine the configuration direction of the vector models and indexes link, and parameters need to be adjusted targeted to adapt to business needs.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Chunk Length | 800–1200 characters | Adapt to the semantic integrity of long texts such as process descriptions and raw material ratios in basic chemicals declaration materials, avoiding semantic breaks caused by overly short single chunks |
| Overlap Length | 100–150 characters | Retain cross-chunk process parameters and field identifiers to prevent key information from being truncated during chunking |

| `maxToken` | 8192 | Support splicing of multiple chunks of text recalled in a single session, covering complete process review logic |
| Single Search Limit | Top 10 entries | Cover multi-dimensional associated parameters in declaration materials, ensuring comprehensiveness of recall results |

## Three common mistakes
- Phenomenon: The index task in the interface remains in a running state with no progress updates. Cause: No incremental index trigger rules are configured, and full scanning of batch archived data from basic chemicals takes too long.
- Phenomenon: A 503 status code is returned when calling the embedding interface, prompting that the model text-embedding is unavailable under the current group. Cause: A locally deployed vector model is not used, and the relied-upon cloud embedding service has network fluctuations or exhausted quotas.
- Phenomenon: Irrelevant raw material ratio entries appear in matching results, and target process parameters cannot be accurately matched. Cause: Field identifiers such as raw material types and units are not retained during chunking, causing the vector model to fail to distinguish parameter information from different production processes.

## How to confirm the configuration is correct
- Upload a typical basic chemicals project declaration document, check the text preview after chunking, confirm that the long text is properly truncated and key field identifiers such as project number and raw material proportion are retained.
- Call the embedding interface for testing, check that the returned vector dimension matches the configured `defaultToken` parameter, and no text truncation errors occur.
- Launch a recall test for case review, confirm that the similarity of the returned results falls within the preset threshold range, and no obvious irrelevant process entries are present.
- Submit a new test case file, confirm that the index task only synchronizes new files and does not trigger a full index reconstruction.

The values provided are common starting points and should be measured against appropriate local samples.
