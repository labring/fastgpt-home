# Basic Chemicals Declaration Materials and File Review: Model Access and Configuration

## What the data for this category looks like
Basic chemical declaration materials and review file data mainly come from internal enterprise approval workflow systems and local chemical regulatory authority filing archives. The data includes structured fields and unstructured technical descriptions. Structured fields cover project name, production scale, raw material ratio, safety evaluation number, and other items. Unstructured parts include environmental impact assessment reports, process flow diagram descriptions, compliance self-inspection documents, and other materials. Data updates align with declaration batches or quarterly filing cycles. The text length of a single file or declaration material varies widely, using standard units such as mass, pressure, and volume.

## What constraints these characteristics impose on model access and configuration
Declaration materials and review files for basic chemical scenarios contain a large amount of professional technical text and structured compliance fields. Model access and configuration should support long context processing, professional term matching, and accurate association of compliance fields. Long technical description texts increase the number of retrieval chunks and prolong overall response time, so context capacity parameters should be adjusted. Accurate matching of structured fields requires retrieval tools to prioritize association with fixed fields to avoid interference from irrelevant content. Supervision-related review logic should maintain a rigorous output style, and dedicated API nodes should be adapted to ensure data transmission compliance.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Basic chemical declaration materials often contain long process descriptions and multi-page files, requiring sufficient context capacity to associate professional parameters and review logic |
| `maxTokens` | 2000–3000 token | Audit responses need to cover compliance judgments and technical descriptions to avoid truncation of key conclusions or parameters |
| `quoteMaxToken` | 1500–2000 characters | File quotes must retain complete technical fragments to avoid splitting core professional information such as raw material ratios and pressure values |
| `toolChoice` | auto | Automatically trigger the file retrieval tool to accurately match compliance fields and review requirements in declaration materials |
| `temperature` | 0.1–0.3 | Audits must maintain a rigorous style, avoiding subjective judgments that deviate from compliance requirements |
| `AIPROXY_API_ENDPOINT` | Fill in dedicated nodes according to the deployment environment | Adapt to compliance data transmission requirements for basic chemical scenarios, reducing cross-region call latency |

## Three common misconfigurations
- Knowledge base search timeout (40 seconds): Phenomenon: Retrieval returns a timeout prompt or status code 504. Cause: The `maxContext` parameter is not adjusted to adapt to long documents, leading to too many chunks and prolonged retrieval time.
- OneAPI call parameters not taking effect: Phenomenon: The configured `temperature` parameter does not take effect, and responses still have random fluctuations. Cause: The dedicated `AIPROXY_API_TOKEN` is not correctly bound, and the default shared key is used.
- Inconsistent results between web debugging and Feishu integration: Phenomenon: Web debugging returns accurate compliance conclusions, while Feishu integration returns vague answers. Cause: The `toolChoice` parameter is not set to auto in the Feishu integration scenario, so the file retrieval tool is not automatically triggered.

## How to confirm the configuration is complete
- Upload a typical basic chemical declaration file, check if the retrieved reference fragments include complete structured fields such as raw material ratios and safety evaluation numbers.
- Initiate an audit request, check the FastGPT v4.17.0 call log to confirm that the actual `maxContext` call value falls within the configured range.
- Test response differences across different `temperature` parameters to confirm that the output style changes accordingly with the settings.
- Check the API call log to confirm that `AIPROXY_API_TOKEN` is correctly included in the request header.
