# Basic Chemicals Declaration Materials and File Review: Deployment and Upgrade

## What the data for this category looks like
Data for declaration materials and file review in the basic chemicals sector primarily comes from internal enterprise documents including production license declaration files, safety supervision filing records, raw material purchase declaration forms, and similar materials. Data updates follow a project-based model. Content is generated and submitted in bulk during a single declaration cycle. After a project is archived, only a small number of supplementary materials are added on a daily basis. Most documents are multi-page PDF or Word files, with fixed fields: project number, raw material usage values, associated production batch numbers, submission dates, and approval status. Units include kilograms, cubic meters, and batches. Date formats are used to mark submission and approval times. The length of individual documents varies widely, ranging from a few pages of supplementary materials to complete declaration files spanning hundreds of pages.

## What constraints these characteristics impose on deployment and upgrade
The data characteristics of basic chemicals declaration materials and file review create clear constraints for the deployment and upgrade process. Multi-page, long documents with varied formats require configuring multi-format parsing workflows during deployment to avoid losing field associations after splitting. The project-based bulk update model requires retaining compatibility for importing historical data during upgrades, to avoid interrupting ongoing declaration projects. Fixed fields with physical units require retaining field metadata during indexing, to support precise matching in subsequent review steps. During upgrades, stability of database connections must be maintained to prevent index interruptions or field loss during data migration.

## How to set the configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `DB_MAX_LINK` | 10–20 connections | Single-batch data volume for basic chemicals declaration files is large. Sufficient database connection pools are needed to support bulk indexing and queries |
| `MONGODB_URI` | For local deployment: `mongodb://localhost:27017/fastgpt`. For private cloud deployment: use the corresponding intranet address | Stores metadata and index vectors for declaration files, adapts to database paths across different deployment environments |
| `REDIS_URL` | `redis://:custom password@intranet address:6379/0` | Caches temporary parsing results of declaration documents to avoid repeated parsing of long files. Set cache validity to 3600 seconds |
| `STORAGE_S3_ENDPOINT` | Fill in according to the enterprise's private object storage address, for example `http://192.168.1.100:9000` | Stores original declaration PDF and Word files, adapts to the enterprise's internal storage architecture |
| `ROOT_KEY` | Generate a random 32-character string | Root key for the admin backend, ensures permission security for declaration configurations |

## Three common mistakes
- Importing old-version workflows fails after upgrade, with the interface prompting "configuration parameters are incompatible". The cause is that the basic chemicals declaration workflow includes custom field mapping rules. Naming rules for some old-version parameters changed after upgrade, and no adaptation migration was performed.
- Knowledge base indexing stays in a running state with no progress updates. The cause is that the value set for `DB_MAX_LINK` is too low. The connection pool is exhausted during bulk indexing, preventing parsing and storage of subsequent documents.
- After calling an HTTP orchestration node, the output result does not appear in the conversation. The cause is that `ROOT_KEY` permissions were not configured correctly. Returned results from the orchestration node are not allowed to be written to the conversation context.

## How to confirm the configuration is correct
- Run a database connection test to verify connectivity for the `MONGODB_URI` and `REDIS_URL` configurations, and confirm that the connection pool parameters match the current business data volume.
- Upload a typical basic chemicals declaration file to trigger the indexing process, and check that the parsed fields retain all core business information.
- After the upgrade is complete, import the old-version declaration workflow configuration, and verify that workflow nodes run normally with no parameter errors.
- Call an HTTP orchestration node, check that the returned result is correctly written to the conversation context, with no permission intercept prompts.
