# Declaration Materials and Case Review for Basic Telecommunications Operations: Workflow Orchestration

## What This Category of Data Looks Like
Data for declaration materials and case review in basic telecommunications operations primarily comes from government and enterprise customer declaration forms exported from business support systems, scanned qualification certificates, and business case archive files. Data updates follow the rhythm of government and enterprise customer declaration work orders, with batch submissions and daily updates for daily review work orders. Documents combine fixed-format structured forms and long-text business plans, including fields such as declaration number, customer entity information, business type, list of qualification documents, and review node records. Supported file formats include PDF, Word, and image formats converted from scanned documents.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The mixed structure of structured and unstructured documents requires workflows to include sequential nodes for format recognition, OCR transcription, and structured extraction, to ensure unified parsing of different material types. Batch-updated work order data requires workflows to support batch triggering and parallel review nodes, adapting to scenarios where multiple work orders are processed simultaneously. Fields that include review node records require configuring state transition rules between workflow nodes, associating review status variables in `variables` to enable automatic jumps between nodes. The need to handle multiple file formats requires configuring adaptation rules for file parsing nodes in workflows, to avoid parsing failures caused by format incompatibility.

## Configuration Guidelines
This document is written for FastGPT v4.17.0, with the following configuration items optimized for the basic telecommunications operation scenario:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Business plan documents for basic telecommunications are mostly long texts; this range balances parsing accuracy and context capacity |
| Overlap Length | 100–150 characters | Prevents key review information from being truncated after long text chunking, ensuring context continuity between chunks |
| Variable Configuration | Bind `variables` to fields such as declaration number, review status | Matches fixed fields in case review, enabling data transfer and status synchronization between different nodes |
| Node Trigger Rule | Bind predecessor node output by `nodeId` | Ensures review nodes are only triggered after preceding material parsing is complete, avoiding invalid execution |
| Single Trigger Work Order Count | 5–10 entries | Adapts to the batch scale of daily review work orders for basic telecommunications, avoiding excessive system load |
| Node Timeout | 600 seconds | Covers the reasonable time required for operations such as long text parsing and qualification verification |

## Three Common Mistakes to Avoid
- Phenomenon: An error message indicating call failure is returned when the workflow calls the file parsing tool. Cause: No multi-format adaptation rules for basic telecommunications declaration materials are configured, so non-standard format files such as PDFs and scanned documents cannot be processed.
- Phenomenon: The published workflow access link displays a localhost domain name. Cause: No system external access domain name parameters are configured during deployment, and the locally deployed local address is used by default.
- Phenomenon: Key review fields are lost after long document chunking. Cause: When using headings as delimiters, the multi-level heading structure nested in basic telecommunications case files is not adapted, leading to incorrect chunk boundaries.

## How to Verify Proper Configuration
- Submit a single test work order, check the execution logs of workflow nodes, and confirm that the output of each node matches the preset `variables` variables.
- Submit multiple test work orders in batches, verify the triggering and execution status of parallel nodes, and confirm that the batch processing adaptation configuration takes effect.
- Upload declaration materials in different formats, check the output results of the parsing node, and confirm that the format adaptation rules work normally.
- Publish the workflow and access the link using an external device, confirm that the domain name configuration is correct, and there is no local address redirection issue.
