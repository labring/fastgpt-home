# Declaration Materials and Case Review for Basic Telecommunications Operations: Tool Calling and Plugins

## What Data for This Category Looks Like
The declaration materials and case review data for basic telecommunications operations mainly comes from internal billing systems, network access work order systems, and customer archive databases. Data updates are triggered by service processing batches, and are synchronized after a single batch of work orders is completed. Documents include two categories: structured fields and attachments. Structured fields include user identity identifiers, service types, application material sizes, acceptance times, and review node statuses, with units being string, enumeration value, byte, date, and enumeration value respectively. Most attachments are scanned paper documents in PDF format, and the size of a single attachment is mostly under 100 MB.

## Constraints Imposed on Tool Calling and Plugins by These Characteristics
The mixed document structure of structured fields and attachments requires that tool calling must support both structured field extraction and unstructured attachment parsing, to avoid covering only a single data type. The rhythm of updates by service batches limits the trigger frequency of knowledge base synchronization; high-frequency full synchronization is not appropriate, and adjustments must be made to match the service processing cycle. The feature of large single attachment sizes requires that plugin calling must limit the content length read in a single call, to prevent context overflow. The multi-node review process data requires that tool calling must associate field information from historical review nodes, to ensure context coherence.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool Calling Switch | Enabled | Declaration material review requires structured field extraction and attachment parsing capabilities |
| `toolChoice` | auto | Adapts to automatic tool selection requirements for multiple data types |
| Single Tool Call Timeout | 120 seconds | Matches the time required for large attachment parsing and multi-field extraction |
| Attachment Parsing Character Limit | 8000–12000 characters | Limits content read in a single call to prevent context overflow |
| Context Association Count | First 3 review node records | Matches the multi-node association logic for case review |
| `functionCall` | Enabled | Supports precise function call extraction of structured fields |

## Three Common Misconfigurations
- Symptom: Insufficient number of tool call return results, logs show context was truncated. Cause: The attachment parsing character limit was not adjusted, and content was truncated because it exceeded the configured threshold.
- Symptom: Tool calls have no response when calling a locally deployed large language model, returning empty tool call results. Cause: The `functionCall` configuration was not enabled, and the local model did not enable function call support.
- Symptom: Timeout errors occur during concurrent calls, with a status code of 504. Cause: The single tool call timeout setting is too short, and does not match the actual time required for large attachment parsing.
