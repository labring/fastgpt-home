# Declaration Materials and Case Review for Basic Telecommunications Operations: Model Integration and Configuration

## What data for this category includes
Data for declaration materials and case review in basic telecommunications operations comes from internal business acceptance platforms, qualification management systems, and submission interfaces from superior regulatory authorities. Data updates align with business process progression. Materials for a single business are updated in real time at nodes such as acceptance, preliminary review, and re-review. Individual document lengths range from hundreds to thousands of characters. Fixed fields include the unified social credit code of the declaration entity, business permit number, approval node timestamp, and material attachment hash value. Some materials include scanned copies of qualification certificates.

## Constraints imposed on model integration and configuration
The wide range of document lengths requires model context window configurations to cover full business material content, avoiding truncation of critical review information. Fixed-format fields require models to support structured output, so mandatory output format constraints must be configured. Real-time updated business data requires interface calls to adapt to intranet deployment security requirements, preventing data leakage. Materials with scanned copies require models to have image text extraction capabilities, so visual processing configuration must be enabled. Demand for accurate fields such as qualification numbers and approval times requires reducing model output randomness to avoid format deviations.

## Configuration settings
The following are specific configuration recommendations for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Fill in the intranet access address of the internal large model service, such as `http://10.10.10.10:8000/v1` | Adapts to the intranet deployment requirements of basic telecommunications operation business data, preventing sensitive data from being transmitted over public networks |
| `AIPROXY_API_TOKEN` | Fill in the access key for the internal large model service | Used for interface identity verification to ensure the security of call permissions |
| `maxContext` | 8000–12000 token | Covers the length range of basic telecommunications operation declaration materials from hundreds to thousands of characters, avoiding context truncation |
| `temperature` | 0.1–0.3 | Reduces output randomness to ensure the accuracy of identifying key information such as qualification numbers and approval nodes |
| `toolChoice` | Forced structured output | Adapts to the fixed-format field extraction requirements in declaration materials, ensuring output complies with the parsing standards of the review system |
| `vision` | Enabled | Used to process scanned copies and qualification certificate images in declaration materials, extracting text information from images |

## Three common configuration errors
- Interface calls return a 403 status code, and the model cannot be called normally. The cause is that `AIPROXY_API_TOKEN` is not configured correctly, or the key permissions are insufficient to access the internal large model service.
- The configured model cannot be selected in the system. The cause is that the `maxContext` value exceeds the maximum context window supported by the currently deployed large model, causing the model to not be included in the available option list.
- An error occurs after adding a knowledge base, and initialization cannot be completed. The cause is that the `vision` configuration is not enabled, and the scanned attachments in the declaration materials cannot be parsed, causing a format incompatibility error during knowledge base loading.

## How to confirm configuration is complete
- Enter the FastGPT model management page, check if the configured large model is shown as available, and verify that the configuration content of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` matches the actual service.
- Upload a sample text of basic telecommunications operation declaration materials, initiate a review request, and check if the model can correctly extract core fields such as qualification numbers and approval nodes.
- Upload a declaration material containing a scanned copy, check if the model can successfully extract text information from the image, verifying that the `vision` configuration is effective.
- Adjust the `temperature` parameter and initiate a test, observe the randomness change of the output result, and confirm that the parameter configuration has taken effect.
