# Declaration Materials and Case Review for Basic Telecommunications Operations: Deployment and Upgrade

## What this category of data looks like
Declaration materials and case review data for basic telecommunications operations primarily originate from internal BSS/OSS business systems, online business application forms submitted by users, and electronic scans of offline paper declaration materials. Data is submitted in real time on a daily basis, with bulk archiving completed each day. Documents are split into two categories: declaration forms and case files. Declaration forms include fields such as user ID, business type, and attachment list. Case files include audit records, approval nodes, and unique archive numbers, among other content. Unique fields include a 12-digit business code, base station number, and package type. Attachment size is measured in megabytes (MB).

## What constraints these characteristics impose during deployment and upgrade
High-frequency declaration data submitted in real time requires configuring high-concurrency parsing nodes and cache services during deployment to avoid request backlogs. Large-volume attachments such as base station drawings and scanned case files require connecting to a dedicated object storage service, with configurations adapted for large file upload and storage. Industry-specific structured fields require updating custom extraction rules during upgrades to ensure the model can recognize unique business fields. Under state-owned enterprise and public sector compliance requirements, HTTPS access domains and security keys must be configured, and access permissions for sensitive interfaces must be restricted.

## Three common configuration errors
- Symptom: A NET::ERR_CERT_INVALID error appears when accessing the frontend page, and static resources fail to load. Cause: `FE_DOMAIN` is not configured as an HTTPS domain, and the configuration file for the corresponding SSL certificate is not mounted.
- Symptom: A 504 timeout error occurs when bulk importing monthly declaration case files. Cause: The batch refresh interval of the vector database is not adjusted based on real-time updated declaration data, resulting in backlogged index queues that cannot be processed in a timely manner.
- Symptom: Industry-specific fields such as base station number and package type are empty after structured extraction. Cause: Custom extraction rules are not configured for the document structure of basic telecommunications operations, and the default extraction model cannot recognize industry-specific field formats.

## How to verify a successful configuration
- Access the configured `FE_DOMAIN`, confirm that the HTTPS protocol is displayed in the browser address bar, and that the page loads normally.
- Upload a 500 MB PDF format declaration attachment, confirm that the upload is successful and the storage path points to the configured `STORAGE_S3_ENDPOINT`.
- Call the backend management interface with the correct `ROOT_KEY`, confirm that the interface returns normal permission verification results, and requests without the key are blocked.
- Submit a test declaration material containing a base station number, check the vector database index logs, and confirm that the parsed results include the preset industry-specific fields.
