# Declaration Materials and File Review for Infrastructure Construction: Workflow Orchestration

## What Data Looks Like for This Category
The data for declaration materials and file review in infrastructure construction is primarily sourced from paper and electronic archives across the full project lifecycle: project initiation, construction, and acceptance. This includes construction permit application forms, bills of quantities, qualification certification documents, progress reports, and more.

Data updates are triggered in batches according to project milestones. Initial declaration materials are submitted during the initiation phase. Progress files are updated synchronously during the construction phase. Final acceptance materials are archived during the completion phase.

Common document formats include multi-page PDFs, structured Excel spreadsheets, and scanned images. Fixed fields include project number, construction unit qualification level, budget amount (unit: ten thousand yuan), construction period (unit: days), material batch number, and others. Some scanned images require OCR recognition to convert to searchable text.

## Constraints Imposed on Workflow Orchestration
Multi-source, heterogeneous document formats require the workflow preprocessing step to support PDF parsing, structured Excel extraction, and OCR recognition. This prevents data loss caused by format incompatibility.

Batched project data updates require the workflow to support triggering per milestone. Audit processes only start when materials are submitted during the corresponding phase.

Fixed fields and unit requirements mean the workflow’s variable verification step must match preset field formats. This prevents audit failures caused by incorrect units.

Multi-level audit transfer logic requires the workflow to configure branch nodes. This implements permission isolation and transfer control in the order of preliminary review, recheck, and final review.

## Configuration Settings
These configurations apply to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Variable Definition | Preset `variables` according to declaration material fields | Matches the field format of structured data, ensuring the audit step can correctly read parameters |
| Node ID Configuration | Assign a unique `nodeId` to each audit phase | Enables precise triggering of branch transfers and log tracking |
| HTTP Request Timeout Setting | 600–900 seconds | Infrastructure audit often involves calls to external qualification verification interfaces, which take longer to complete |
| Loop Nesting Configuration | Support up to 3 nested HTTP requests | Batch review of infrastructure declaration materials typically does not exceed 3 rounds |
| Branch Trigger Rule | Trigger based on audit result fields | Differentiates between different transfer paths for approval, correction request, and rejection |
| Knowledge Base Call Binding | Associate the corresponding project archive knowledge base | Enables automatic compliance verification of declaration materials |

## Three Common Configuration Mistakes
- Calling an API to trigger a workflow with nested knowledge base assistants returns a null value. The cause is failure to correctly bind the knowledge base call input parameters in `variables`, leading to parameters not being passed to the corresponding node.
- A `quote type error` prompt appears when referencing knowledge base variables. The cause is that the passed variable format does not match the requirements of knowledge base retrieval, and structured data is not passed according to preset fields.
- The tool call node outputs both an AI reply and starts the next-level branch. The cause is failure to correctly configure the dependency conditions for branch triggering, leading to parallel execution of multiple paths.

## How to Verify a Complete Configuration
- Submit a single test declaration material, and check whether the workflow transfers to the corresponding audit node according to preset steps.
- Call the API to trigger the configured workflow, and check whether the returned result includes non-empty audit result fields.
- Trigger a knowledge base variable reference, and confirm that no `quote type error` prompt appears.
- Adjust the HTTP request timeout time to the set threshold, and verify whether the timeout handling logic is triggered after the duration is exceeded.

The values listed above are common starting points. Adjust them based on your own samples and operational requirements.
