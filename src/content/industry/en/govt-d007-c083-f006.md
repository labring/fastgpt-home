# Infrastructure Construction Declaration Materials and File Review: Citation Sources and Traceability
This document applies to FastGPT v4.17.0

## What This Category of Data Looks Like
Infrastructure construction declaration materials and file data mainly come from project initiation approval documents, construction progress ledgers, completion acceptance reports, bidding archive documents, and similar sources. The update rhythm follows project phases: the initiation phase updates early approval materials, the construction phase updates progress reports and material arrival reports, and the completion phase updates acceptance and settlement files.

Documents are mostly in multi-modal mixed formats, including structured engineering quantity tables, graphic and text descriptions, and qualification scan copies. Fields include project unique ID, construction unit qualification document ID, material inspection batch number, and engineering quantity calculation data. Units include square meters, cubic meters, tons, ten thousand yuan, and others.

## What Constraints These Characteristics Impose on the "Citation Sources and Traceability" Link
Infrastructure construction declaration file data is scattered across multiple channels such as project management systems, paper archive files, and bidding platforms, and is updated periodically with project milestones. The traceability link must cover multiple data entry points and support synchronization by milestone.

Single file documents are relatively long, containing structured tables and graphic and text descriptions. Precise positioning to the corresponding paragraph or chart traceability location is required to avoid generalized recall. Fields include unique identifiers such as project ID and qualification document ID, so specific field matching is needed for precise traceability. This ensures reviewers can quickly locate corresponding compliance basis.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `quoteMaxToken` | `1200–1800 token` | The valid content per segment of infrastructure construction declaration files is relatively long, requiring complete citation context to be covered and avoid truncation of key approval fields |
| `responseData` | Enabled | Need to return specific page numbers and paragraph locations of the original files for reviewers to verify the compliance of declaration materials |
| `detail` | Enabled | Need to display the original structured fields and units of the cited content, matching the engineering data characteristics of infrastructure construction files |
| Single citation source limit | Top 3 | The number of file types involved in a single declaration material is limited; too many citations will distract reviewers |
| Knowledge base synchronization cycle | Triggered by project milestones | Infrastructure construction files are updated with phases such as project approval, construction, and completion, requiring synchronization of the latest archive data at corresponding milestones |

## Three Common Mistakes
- Phenomenon: The returned citation link cannot be downloaded normally through the custom proxy path, showing a 404 status code. Cause: Archive files for infrastructure construction are stored in project-specific directories, and this directory is not included in the allowed access scope of proxy rules, resulting in failure of the traceability link to jump normally.
- Phenomenon: The API call returns an empty content value with no citation traceability content. Cause: The `responseData` switch is not enabled, or the `quoteMaxToken` setting is too low, resulting in valid content being truncated and unable to be returned.
- Phenomenon: Garbled characters or format confusion appear in citation display, and unit symbols of engineering tables are displayed abnormally. Cause: The `detail` switch is not enabled, and the original structured typesetting of the original files is not retained, resulting in abnormal formatting of engineering data during display.

## How to Verify Proper Configuration
- A test query is executed, a declaration review question for an infrastructure construction project is input, and the returned result is checked for traceability information such as original file page numbers and paragraph locations.
- Knowledge base synchronization logs are reviewed to confirm that the latest declaration file materials have been synchronized to the knowledge base after project milestone changes.
- The display format of cited content is reviewed to confirm that engineering fields and unit symbols do not have abnormal typesetting or garbled characters.
- Scenarios involving multiple files are tested to confirm that the number of returned traceability entries meets the set single citation source limit.

The values given here are common starting points and should be measured against the reader's own samples.
