# Infrastructure Construction Declaration Materials and File Review: Document Parsing and Chunking

## What this category of data looks like
Data for infrastructure construction declaration materials and file review comes from paper scans and electronic documents across project initiation, construction permit, and completion acceptance stages. Update frequency shifts based on project phase. Updates are concentrated during the initiation stage, and added as needed during construction and acceptance stages. Document types include multi-page PDF feasibility study reports, structured CSV material lists, and scanned documents with signatures and seals. Fields include project number, investment amount, construction period, name of participating construction units, and more. Some fields use dedicated units such as ten thousand yuan and days.

## Constraints on document parsing and chunking from these characteristics
Long PDF feasibility study reports have coherent content and closely linked chapters. Chunking must preserve semantic integrity, and avoid splitting cross-chapter approval opinions or investment details. Structured CSV files hold multiple columns of project material data. All valid columns must be identified accurately, or key field information will be lost. General OCR cannot directly parse scanned documents with signatures and seals accurately. Custom parsing services are required for these files. Project declaration materials update with project progress, and have inconsistent formats. Chunking logic must adapt to multiple document structures, while limiting parsing duration to avoid timeouts.

## How to set configurations

| Configuration Item | Recommended Value | Rationale for This Setting |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the chapter length of infrastructure feasibility study reports, and avoids splitting key approval content across chapters |
| `chunkSplitter` | Split by paragraph + title | Matches the chapter structure of infrastructure documents, and retains semantic connections between content |
| `customPdfParse` | Enabled | Processes scanned PDF files with signatures and seals, and improves parsing accuracy |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the upload requirements for single large-volume feasibility study reports, and avoids 413 errors |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Matches the actual time required for long document parsing, and avoids timeouts for custom parsing services |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking parameters for the special formats of infrastructure documents |

## Three common misconfigurations
- Uploaded file parsing triggers a 413 error. Cause: The `UPLOAD_FILE_MAX_SIZE` parameter was not adjusted, exceeding the default upload limit. For Docker deployments, the configuration file mounted by the container must be modified synchronously.
- Only the first two columns of content are displayed after importing CSV table data. Cause: The chunking logic's recognition rules for structured documents were not properly configured. The default chunking logic does not adapt to multi-column data structures, and only extracts the first two columns of fields.
- A timeout exception occurs after calling the custom parsing service. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted. The default timeout duration is insufficient to complete the parsing process for long infrastructure documents.

## How to confirm proper configuration
- Upload a single large-volume infrastructure PDF file, check if a 413 error is triggered, and confirm that the `UPLOAD_FILE_MAX_SIZE` parameter matches the file size requirements.
- Upload a structured CSV material list, check if all column data is fully displayed, and confirm that the chunking logic adapts to multi-column document structures.
- Call the custom parsing service to process a scanned document with a signature and seal, check if the parsed result includes the text content of the signature area, and confirm that `customPdfParse` is enabled.
- Wait for the parsing to complete, check if a timeout prompt appears, and confirm that the `PARSE_FILE_TIMEOUT_SECONDS` parameter matches the parsing duration.
