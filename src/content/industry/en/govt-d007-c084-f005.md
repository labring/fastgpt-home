# Commodity Trading Declaration Materials and File Audit: Tool Calling and Plugins

## What the data for this category looks like
Data sources for commodity trading declaration materials and file audits include customs clearance declaration forms, commodity quality inspection certificates, trade purchase and sales contracts, warehouse receipts, and transport bills of lading.
System updates trigger data changes when individual trade process nodes run. The update frequency for a single declaration material ties to the audit cycle.
Most document structures use multi-page mixed formats. They include structured fields such as goods name, quantity, unit price, and unstructured attachments such as scanned documents and PDF reports.
Field units include tons, cubic meters, USD/ton, customs declaration numbers, quality inspection numbers, and more. Some fields require matching against customs coding standards.

## What constraints these characteristics impose on tool calling and plugins
Multi-source, heterogeneous document structures require tool calling to support mixed format parsing. Tools must separately adapt to structured field extraction and unstructured content recognition.
Diverse field units require tools to support multi-unit conversion during parameter verification, to avoid matching errors.
Process node-triggered update rhythms require plugins to support on-demand calling. Plugins must adapt to node-triggered update logic, and reduce invalid requests.
File audits for individual trades require associating multiple documents. Tool calling must support aggregating data by declaration batch, to ensure coherent context for associated materials.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-tool linkage needs for commodity trading declaration materials, automatically select the tool matching the current task |
| Single tool call timeout | 600 seconds | Cover time required for multi-stage audits of large-value trade declaration materials, avoid mid-process interruptions |
| Tool call context retention | Retain the last 3 tool call results | Match multi-document associated audit logic for individual trade files, avoid context loss |
| Tool parameter verification switch | Enabled | Verify units of fields such as shipment volume and unit price in declaration materials, prevent format errors |
| Batch tool call execution order | Execute in declaration node order | Align with the audit process of commodity trading, ensure pre-verification is completed before calling subsequent tools |

## Three common mistakes
- Symptom: Context is cleared after multiple MCP tool calls, and the context window displays empty in the interface. Cause: `toolChoice` is not configured to auto mode, which causes each tool call to reset the context.
- Symptom: FastGPT-MCP server fails to start after upgrade, logs show port conflict. Cause: Default port configuration of the MCP server is not modified, overlapping with existing FastGPT service ports.
- Symptom: After submitting a declaration task, tools do not execute in the expected order, with parallel call confusion. Cause: Execution order for batch tool calls is not configured, and parallel mode is enabled by default.

## How to confirm the configuration is correct
- Submit a simulated commodity trading declaration task, check the tool call logs to confirm tools execute in declaration node order.
- Check the context window to confirm the last 3 tool call results are retained and not accidentally cleared.
- Submit test materials containing multi-unit fields, check whether the tool's returned verification results correctly match the field units.
- Call the public API of the FastGPT v4.17.0 application, confirm that the existing web application can normally initiate calls and obtain audit results.
