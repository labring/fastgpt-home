# Declaration Materials and Case File Review for Commodity Trading: Source Citation and Traceability

## What this category of data looks like
Declaration materials and case file data for commodity trading mainly come from full-process internal enterprise trade documents. These include customs declarations, ownership certificates, trade contracts, settlement statements, and customs clearance receipts.
Data is archived and updated per individual transaction. Each transaction’s case file includes structured fields and unstructured text. Structured fields cover commodity category, customs declaration number, bill of lading number, and settlement amount. Common units are tons, cubic meters, and RMB yuan. Unstructured text mostly consists of long documents transcribed from scanned contract copies.

## What constraints do these characteristics impose on source citation and traceability
Commodity trading declaration and case file data includes large volumes of long-text trade contracts, structured customs clearance documents, and unique identifier fields. These create multiple constraints for source citation and traceability.
Long-text contracts use significant tokens. The total content recalled in a single session must be strictly limited.
Unique identifier fields such as customs declaration numbers and bill of lading numbers are core traceability anchors. These fields must be prioritized for association during recall to bind to specific transaction case files and avoid cross-transaction data confusion.
Some documents use text transcribed from scanned copies, which may have formatting errors. Text integrity must be verified after recall to ensure traced content accurately matches original documents.

## How to configure settings
This page content is based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 6000–10000 token | Commodity trading case files include long-text contracts and multiple customs clearance documents. This parameter limits total recalled tokens per session to avoid exceeding large language model context limits |
| Single recall count | Top 6 entries | A single transaction case file typically links to 3 to 8 documents. Limiting recall count prevents context overload |
| `responseData` | Retain customs declaration number, bill of lading number, and commodity category fields | Core traceability identifiers for commodity trading are customs declaration numbers and bill of lading numbers. These fields must be retained to bind to specific transactions |
| `detail` | Enable full content display | Case file review requires verifying complete original document information. Enabling this setting returns full traced text and structured fields |
| Maximum context | No more than 15000 token | Combined with single recall count and individual content length, this parameter controls total context length to fit large language model input limits |

## Three common configuration mistakes
- Phenomenon: After calling the knowledge base module in a workflow, returned results lack associated traceability fields. Cause: Core business retention fields are not specified in the `responseData` configuration, so traceability information is filtered out.
- Phenomenon: Single retrieval takes too long, or a context overflow error occurs. Cause: `quoteMaxToken` is set to 50000 token, which exceeds the large language model and platform context capacity limits, leading to processing timeout or content truncation.
- Phenomenon: Recalled results do not match the target transaction case file, with document content from other transactions appearing. Cause: Unique identifier fields such as customs declaration numbers and bill of lading numbers are not bound in retrieval configurations, leading to recalled results mixing case file data from different transactions.

## How to verify correct configuration
- Trigger a case file review retrieval request, and check if returned results include preset traceability fields such as customs declaration number and bill of lading number.
- Check the total token count of retrieval results to confirm it stays within the `quoteMaxToken` setting.
- Run multiple retrieval requests for a single transaction case file, and confirm all recalled results come from documents linked to that transaction, with no cross-transaction content.
- Check the output of the knowledge base module in the workflow, and confirm traced content is correctly bound to the current transaction’s context.
