# Bulk Commodity Trade Declaration Materials and Case Review: Document Parsing and Chunking

## What the data for this category looks like
Data for bulk commodity trade declaration materials and case review primarily comes from customs declarations, trade purchase and sales contracts, warehouse receipts, quality inspection reports, transaction settlement documents, and similar sources.
Data updates follow trade project milestones. A single trade corresponds to a complete set of materials. Annual batch case files are updated by batch.
Supported document formats include fixed-layout PDF customs declarations, structured Excel warehouse receipt ledgers, Word review case files with annotations. Some scenarios also involve scanned paper documents.
Core fields include commodity category, transaction quantity, pricing unit, customs declaration number, and identifying information for both transaction parties. Common units include tons, cubic meters, USD per ton, standard containers, and other industry-specific identifiers.

## What constraints do these characteristics impose on document parsing and chunking
Mixed-format documents from multiple sources require the parsing process to adapt to different layouts and structures. Splitting must not break cross-page review-related information.
Document lengths vary significantly. A single contract may only span a few pages. Annual case files can reach dozens or hundreds of pages. Chunking logic must balance the integrity of short text fields and the semantic coherence of long texts.
Industry-specific units and field identifiers require the parsing process to retain original field associations. This prevents misalignment between units and numerical values.
Bulk imported Excel warehouse receipt files often use multi-level headers. Chunking must accurately identify the correspondence between header rows and data rows to prevent field misalignment.
Frequent project updates require the parsing process to trigger on demand. This avoids repeated parsing of unchanged historical materials.

## How to configure the settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Bulk commodity declaration materials often contain long paragraphs of contract terms and customs declaration details. This range preserves the associative integrity of units and fields |
| `chunkSplitter` | Split by paragraph + filter headers and footers | Adapts to structured headers and footers of customs declarations and case files, avoiding splitting that breaks cross-page review-related information |
| `customPdfParse` | Enabled | For fixed-layout customs declarations, enable custom parsing to accurately extract core fields such as customs declaration numbers and commodity categories |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports bulk packaged uploads of annual case files, adapting to batch review scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Prevents timeout interruptions when processing large Excel warehouse receipts or multi-page PDF case files |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types (declarations, contracts, case files) to adapt to multi-format data for bulk commodity trade |

## Three common configuration mistakes
- Parsing fails with a timeout status code after uploading annual case PDF files. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. Large documents exceed the default timeout limit.
- Some fields are empty after importing Excel-format warehouse receipt ledgers. The cause is failure to adapt to multi-level header structures. The parsing process mistakenly identifies header rows as data rows, leading to field misalignment.
- A full document parsing process is triggered when sending a conversation query, resulting in abnormal result counts. The cause is failure to distinguish the configuration boundaries between document parsing and conversation interaction. Conversation text was mistakenly included in the parsing queue.

## How to confirm the configuration is correct
- Upload a single-page customs declaration PDF. Check if the parsed text fully retains core fields such as customs declaration numbers and commodity categories. Confirm that the `customPdfParse` configuration is active.
- Upload an annual case PDF with more than 10 pages. Wait for parsing to complete. Confirm no timeout interruptions occur. Verify that the `PARSE_FILE_TIMEOUT_SECONDS` configuration is appropriate.
- Import a batch of Excel warehouse receipt files. Check if the fields of each entry match the original documents. Confirm that the `chunkSplitter` adapts to the table structure.
- Send a conversation query not associated with knowledge base documents. Confirm no document parsing process is triggered. Verify that the configuration boundaries are correct.

The values listed above are common starting points. They should be evaluated against the user's own samples.
