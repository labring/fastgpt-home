# Declaration Materials and Case Review for Commodity Trading: Deployment and Upgrade

## What the data for this category looks like
Data for declaration materials and case review in commodity trading mainly comes from enterprise trade document systems, customs clearance platforms, and warehouse management systems. It is generated and updated with each trade order. Single documents include fields such as information of trading parties, commodity HS codes, transaction quantity, unit price, customs declaration numbers, quality inspection reports, and approval workflow records. Units include tons, cubic meters, US dollars, pieces, and others. Most document structures combine structured forms and scanned attachments. A single case can have dozens of related documents. Some long-text attachments have wide ranges of character counts.

## Constraints on Deployment and Upgrade
The traits of multiple related documents, unique field units, and wide character count ranges for long-text attachments create three constraints for deployment and upgrade, plus an additional requirement for real-time data updates.
1.  Bulk storage for multiple related cases requires storage policies that support multi-file associations.
2.  Fields with unique units such as tons and US dollars need field mapping verification during data import to avoid unit recognition errors.
3.  Long-text attachments with wide character count ranges require sufficient chunking and indexing space, and must adapt to vector generation logic for different text lengths.
The real-time update feature tied to trade orders also requires that incremental synchronization links are not interrupted during upgrades, to maintain the timeliness of review data.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Intranet access address of the enterprise's dedicated S3 storage | Commodity trading cases include multiple large-volume attachments. S3 storage reduces local storage load, and intranet addresses improve file access speed |
| `REDIS_URL` | Intranet Redis instance address, set connection timeout to 30 seconds | Session cache and retrieval cache for case reviews require stable connections. A 30-second timeout balances response speed and retry fault tolerance |
| `DB_MAX_LINK` | 20–30 | A single case is associated with multiple documents. Database connection count must adapt to batch query needs to avoid connection exhaustion |
| `FILE_TOKEN_KEY` | 32-bit randomly generated secret string | Ensures the security of case file download links, preventing unauthorized access to sensitive trading data |
| `PG_URL` | Address of the enterprise's internal PostgreSQL instance | Structured fields such as commodity codes and customs declaration numbers have high query demands, adapting to retrieval operations for batch cases |

## Three Common Misconfigurations
- Phenomenon: After upgrading to a new version, case files migrated to S3 storage fail to upload, and the interface returns a storage connection error. Cause: The `STORAGE_S3_ENDPOINT` parameter is not configured correctly, or the access permissions of the S3 storage are not updated synchronously, resulting in inability to access the dedicated storage node.
- Phenomenon: After deployment, calling the packaged MCP tool returns an error prompt that only stdio processes are supported. Cause: The default process communication configuration of FastGPT v4.17.0 is not adapted, and the protocol adaptation logic of tool calls needs to be adjusted.
- Phenomenon: When importing cases in batches, some structured fields cannot be recognized normally, and the review task fails to trigger. Cause: Field mapping verification rules are not configured, and format adaptation for unique units such as tons and US dollars is not performed, resulting in field matching errors.

## How to Verify Correct Configuration
- Upload a standard commodity trading case attachment, check whether the file storage path matches the node pointed to by the configured `STORAGE_S3_ENDPOINT`.
- Connect to the configured Redis instance, check the connection status of the session cache and retrieval cache, and confirm that the connection parameters meet business requirements.
- Import test data containing unique unit fields, check whether field mapping is completed, and there are no format recognition errors.
- Call the packaged MCP tool, confirm that the process communication logic adapts to the requirements of the current deployment version.

The values provided are common starting points and should be measured against the reader's own samples.
