# Engineering Consulting Supervision Declaration Material and File Review: Tool Calling and Plugins

## What This Category of Data Looks Like
Data for engineering consulting supervision declaration material and file review primarily comes from submitted documents daily archived by supervision project teams, inspection materials submitted by construction parties, and project acceptance archives. Data update rhythm follows project milestones, with new data generated per approval batch, acceptance stage, and monthly archive cycle. Documents are mostly fixed-format approval forms, with attachments including test reports, image materials, and measurement lists. Single file archive size typically ranges from 50–200 MB, and includes fields such as project number, supervision unit name, submission date, material batch number, acceptance conclusion, and rectification list. Corresponding units for fields mostly use common engineering measurement units including square meters, tons, and ten thousand yuan.

## Constraints Imposed on Tool Calling and Plugin Workflows
Fixed-format approval forms require tool calling to use preset field mapping rules to avoid field misalignment during parsing. Multi-attachment document structures require plugins to support parallel parsing of multiple files and adapt to multiple attachment formats including PDF, images, and Excel. Data updated per project milestones requires tool calling to bind the unique project identifier as a query parameter to prevent cross-project data confusion. Fields with specific engineering measurement units require plugins to automatically verify unit matching after data extraction to avoid measurement errors. File review requires retrospective access to historical approval records, so tools must support pulling historical data within a time range to ensure complete review basis.

## Configuration Settings
This configuration applies to FastGPT v4.17.0. The core configuration parameters include `toolChoice` and `functionCall`, with values adjusted for the supervision scenario.

| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts to the tool calling logic for supervision approval scenarios, reducing manual configuration costs |
| `functionCall` | Enabled | Forces field validation and parameter binding to meet the structured review requirements for supervision materials |
| Tool calling timeout | 600 seconds | Supervision declaration materials include multiple attachment parsings, single batch processing takes longer time |
| Multi-file parsing concurrency | 2–4 | Avoids overloading system resources by parsing too many attachments simultaneously |
| Single historical data pull count | Top 15 | File review only requires the latest 15 historical approval records as review references |
| Required field validation | Enabled | Ensures required fields of supervision declaration materials (such as project number, submission date) are complete |

## Three Common Configuration Errors
- The symptom is empty tool calling return results. The cause is failure to bind the project ID as a query parameter, leading to cross-project data confusion and inability to match the declaration materials of the corresponding supervision project.
- The symptom is code running plugin execution failure, with an error prompt indicating missing third-party dependencies. The cause is failure to pre-declare commonly used data analysis libraries for the engineering supervision domain in the plugin configuration, and incomplete pre-installation of dependencies.
- The symptom is no conversation log generated after calling a configured review plugin in the workflow. The cause is failure to enable the plugin's log recording switch, or failure to correctly pass the workflow context to the plugin instance, resulting in logs unable to be associated with the corresponding review task.

## How to Verify Successful Configuration
- Submit a standard supervision declaration material test case, check if tool calling automatically identifies form fields and completes required field validation.
- View the plugin execution log to confirm that multi-attachment parsing is completed within the configured timeout period, with no timeout error prompts.
- Verify that a conversation log associated with the current review task is generated after the workflow calls the plugin, including all input parameters and return results.
- Adjust the project ID of the test case, confirm that the tool only returns historical approval data for the corresponding project, with no cross-project data mixed in.
