# Construction Machinery Declaration Materials and File Review: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for construction machinery declaration materials and file review mainly comes from complete machine ledgers, maintenance archives, quality inspection reports, bidding declaration documents, and project acceptance files. Data updates are triggered by project milestones. Materials for a single declaration project are submitted once, while routine files are updated during project initiation and acceptance phases. Document structures include fields such as equipment model, unique serial number, manufacturing date, cumulative operating hours, rated operating pressure, and declaration subject qualification documents. Field units include units such as unit, hour, MPa, mm, and others. The length of a single archive document usually ranges between 5000 and 15000 characters.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
The long-document characteristic of construction machinery declaration materials and files requires HTTP interfaces to adapt to single-file lengths of 5000 to 15000 characters, to avoid truncating key quality inspection and operating parameter information. The characteristic of multiple fields with dedicated units requires that interface request parameters strictly match preset field names and unit rules, and automatic compatibility with non-standard unit conversion is not supported. The requirement for docking multiple data sources requires the interface to support cross-system calls, and authentication parameters must be configured to adapt to the authentication logic of different external systems. When submitting in batches, the number of documents per single request must be controlled to prevent timeout errors caused by excessive single-request load.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Number of documents per single request | 5–8 | Adapt to the 5000–15000 character file length per document, avoid excessive request load |
| Timeout period | 600 seconds | Cover the time required for long document parsing and cross-system data retrieval |
| `Authorization` | Generate a Bearer token according to the key provided by the external system | Adapt to the authentication requirements of multi-data-source docking |
| `variables` | Pass preset fields such as equipment serial number, cumulative operating hours, rated pressure, and others | Ensure interface parameters strictly match fields in archive data |
| `responseData` | Verify the returned insertion success flag and document ID | Confirm that data synchronization is completed |
| File parsing format | Calibrate based on actual testing | Adapt to multiple archive file formats such as PDF and CAD exported text |

## Three common errors
- Phenomenon: An `Invalid` error is returned when calling the knowledge base insertion interface, with a 400 status code. Cause: The `variables` parameter is not passed in accordance with the field rules for construction machinery archives, causing the interface to fail to recognize the required equipment serial number field.
- Phenomenon: When submitting an archive file in PDF format, the interface returns an empty parsing result. Cause: pdf-marker has not been upgraded to the version compatible with FastGPT v4.17.0, so the /v2/parse/file interface cannot be called to complete file parsing.
- Phenomenon: A timeout error is triggered when inserting documents in batches. Cause: The number of documents submitted in a single request exceeds 8, and the time required for long document parsing exceeds the 600-second timeout threshold set for the interface.

## How to confirm the configuration is correct
- Call the interface and pass a test archive document of 5000 characters, check whether the insertion success flag returned in `responseData` is normal.
- After configuring the `Authorization` parameter, connect to the external ledger system related to construction machinery to retrieve equipment data, and confirm that the interface can normally obtain returned content.
- Pass the `variables` parameter with units, query the corresponding documents in the knowledge base, and verify that the fields and units match the original equipment data.
- Submit 8 test archive documents, confirm that the interface does not trigger a timeout error, and all documents are successfully inserted into the knowledge base.

The values provided here are common starting points and should be measured against the reader's own samples.
