# Construction Machinery Declaration Materials and File Review: Workflow Orchestration

## What the data for this category looks like
Construction machinery declaration materials and file review data mainly comes from three categories: factory inspection reports, equipment operation and maintenance archives, and qualification declaration documents. Data sources include production systems of equipment manufacturing enterprises, equipment operation and maintenance platforms, and government declaration portals.
Update rhythm is divided by equipment batches and operation and maintenance cycles. Basic archives for a single device are updated upon factory delivery. Operation and maintenance archives are updated monthly.
The document structure includes two categories: structured fields and attachments. Structured fields include device number, model, rated load, operating hours, and more. Units include unit, hour, megapascal (MPa), and others. Attachments are mostly PDF-format inspection reports and certificate scan copies.

## Constraints imposed on the "workflow orchestration" link
The mixed structure of structured fields and attachments for construction machinery declaration and files requires workflows to complete the attachment parsing node first, then match corresponding structured fields for verification.
The unit specificity of fields such as device number and rated load requires workflows to be configured with a field format verification node to prevent audit failure due to unit mismatch.
The update rhythm based on batches and cycles requires workflows to support configuration of triggering by device batch and synchronizing archive updates monthly.
The multi-node serial review logic requires that the transfer of `variables` in the workflow must be bound to the correct `nodeId` to ensure that the output of previous nodes can be correctly read by subsequent nodes.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Method | Triggered by device batch updates | Matches the rhythm of construction machinery archive updates by batch, avoids repeated execution of review processes |
| Global Variable Configuration | Bind device number and rated load fields in `variables` | Covers core structured data required for review, ensures that each node can read corresponding parameters |
| Node Dependency Binding | Bind the `nodeId` and all output branches of previous nodes | Ensures that the HTTP request node is triggered in all question classification branches, covers all review scenarios |
| HTTP Request Node Timeout | 3–5 seconds | Matches the actual time consumption of this module, avoids unnecessary timeout interruptions |
| Question Classification Node Timeout | 2–4 seconds | Matches the actual time consumption of this module, ensures rapid completion of classification logic |
| Error Retry Configuration | Retry up to 2 times, 10-second interval | Responds to temporary network fluctuations causing node failures, does not affect overall review efficiency |

## Three Common Mistakes
- Phenomenon: An error "Failed to get global variables" is returned when executing the workflow, or fields in the node are empty. Cause: Required fields such as the device number and rated load of construction machinery are not configured in `variables`, causing the corresponding parameters to fail to be read when the node is called.
- Phenomenon: After modifying the workflow logic, the review process published to the official channel is not updated. Cause: The updated workflow version is not republished to the corresponding release channel, and the channel still calls the old version logic.
- Phenomenon: After the question classification node completes execution, the HTTP request node is not triggered. Cause: The node dependency relationship is not correctly configured, and the HTTP request node is not bound to all output branches of the question classification, only the process of some branches is triggered.

## How to Confirm the Configuration Is Correct
- Manually trigger the test workflow, pass the preset construction machinery device number and inspection report attachment, check whether the fields in `variables` are correctly passed to each node.
- View the workflow running logs, confirm that the time consumption of each node meets the preset timeout settings, and no timeout errors occur.
- After modifying the node configuration of the workflow, republish it to the test channel, execute test cases to verify that the new logic takes effect normally.
- Simulate the scenario where the HTTP request node fails, confirm that the error retry mechanism triggers according to the configuration, and the process does not interrupt directly.
