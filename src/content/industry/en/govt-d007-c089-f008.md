# Declaration Materials and File Review for Construction Machinery: Document Parsing and Chunking

## What this category of data looks like
Data for construction machinery declaration materials and file review comes primarily from complete machine factory inspection reports, project procurement declaration forms, operation and maintenance files, and filing and approval documents. Update frequency follows project milestones. Single declaration materials are submitted in batches. Daily files are updated per project cycle. Most documents use a mixed text and graphics structure, including equipment parameter tables, technical description text, component drawings, and real-world photos. Core fields include rated lifting capacity, maximum working radius, emission standards, complete machine weight, and more. Common units are kN, m, kg, kW, and others.

## What constraints these characteristics impose on the document parsing and chunking link
The mixed text and graphics, parameter tables, and long text characteristics of construction machinery declaration materials and review files impose multiple constraints on document parsing and chunking. Mixed text and graphics structures can cause equipment parameter descriptions linked to images to be split or lost. Targeted measures are needed to retain the association between text and visual elements. The aligned structure of multi-column parameter tables can break the binding between fields and units with standard chunking logic. This leads to parameter matching failures during subsequent retrieval. Long technical specification text can create chunks that exceed model context limits, requiring precise splitting. Differences in formats across multiple documents submitted in batches can lead to inconsistent chunking. This affects subsequent associated retrieval of review files.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the average length of construction machinery parameter tables and technical text, avoids single chunks exceeding model context limits |
| `chunkSplitter` | Split by paragraph + table boundaries | Adapts to mixed text and graphics and multi-column parameter table structures, retains the binding relationship between fields and units |
| `customPdfParse` | Enabled | Processes equipment parameter tables and real photos in documents, avoids loss of parameter descriptions associated with images |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing duration of batch declaration materials, avoids parsing interruption of large multi-page documents |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for the special structure of construction machinery documents, adapts to the splitting needs of parameter tables and long text |

## Three Common Mistakes
- Only partial parameter data is captured after uploading a docx document. This occurs when the chunking logic split by table boundaries is not enabled, leading to incorrect splitting of multi-column parameter tables.
- A slow operation timeout error appears in the parsing log. This happens when the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default duration is insufficient for processing large batches of declaration materials.
- Equipment real photos inserted into a document cause parsing failure, returning an Invalid image file error. This is because the `customPdfParse` configuration is not enabled, so the image format or path in the document cannot be recognized.

## How to Confirm Proper Configuration
- Upload a single construction machinery inspection report containing parameter tables. Check the parsed chunk list to confirm the complete content of the parameter tables is not split.
- Upload a docx document containing multiple equipment photos. Confirm that the parameter description text associated with the images is retained in the parsing result without loss.
- Submit batch declaration materials. Check the parsing log to confirm there are no timeout errors and all documents have completed parsing.
- Adjust the `chunkSize` parameter, then re-upload a long-text technical description document. Verify that the single chunk length matches the expected configuration.

The values provided are common starting points and should be measured against the reader's own samples.
