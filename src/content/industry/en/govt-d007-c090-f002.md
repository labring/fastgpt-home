# Fuel Oil Sales Declaration Materials and File Review: Vector Models and Indexes

## What this category of data looks like
Data sources include daily inventory, sales, and procurement reports from gas stations, monthly compliance files, and verification templates from superior competent departments. Daily declaration data is updated in real time. Monthly file data is stored stably after archiving. Most documents are structured forms and semi-structured files, containing fields such as gas station number, fuel grade, sales volume, inventory surplus, and verification node. Units include liters, tons, yuan, and dates.

## Constraints These Characteristics Impose on Vector Models and Indexing
Daily incremental declaration data requires indexes to support low-latency incremental construction. This avoids time consumption growth caused by full reindexing.
Mixed semi-structured form and file data requires configuration of vectorization splitting rules adapted to multiple formats. This ensures consistent semantic extraction across different document types.
Structured data with multiple fields requires clear core vectorization fields. This prevents irrelevant information from diluting vector semantics and harming review matching accuracy.
Archived files with retained historical versions require indexes to include version association fields. This supports retrieval of historical files within a specified time range.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Fuel oil declaration materials are mostly short text passages. This range avoids overly fragmented chunks losing semantics, or overly long chunks triggering `maxToken` limit violations |
| Overlap Length | 100–200 characters | Connects semantic associations between adjacent chunks. Prevents cross-chunk review information from being broken |
| Similarity Threshold | 0.72–0.80 | Calibrated based on actual measurements. Distinguishes valid verification information from irrelevant text, adapting to the precise matching needs of file review |
| Single Search Limit | Top 10 entries | There are relatively few associated items for declaration materials and files. Excessive results increase the screening burden for review personnel |
| `maxToken` | 8192 token | Adapts to the context length limit of mainstream embedding models compatible with FastGPT v4.17.0. Prevents truncation of key review information |
| `defaultToken` | 4096 token | Meets context requirements for lightweight review scenarios. Balances retrieval accuracy and response speed |

## Three Common Misconfigurations
- Submitting duplicate review queries repeatedly results in no significant reduction in system response time. No query caching mechanism is configured, so each request triggers a full vector retrieval, wasting computing resources.
- Calling the knowledge base interface fails to trigger index construction after only using the collection data addition function. Batch index construction is not initiated by creating a training order. Adding data individually does not automatically start index tasks.
- Retrieving vectorized image files returns no relevant results. No metadata binding is configured between image vectorization and corresponding declaration text. Vectorizing only images alone does not establish an associated index.

## How to Verify Correct Configuration
- Submit 10 duplicate review queries. Observe changes in response time to confirm whether the caching mechanism operates as configured.
- Upload a single piece of declaration data. Check the index construction status to confirm whether the training order is normally triggered and index construction is completed.
- Upload file materials containing images. Perform a retrieval and check returned results to confirm whether text and image content are displayed in association.
- Switch the embedding model option. Confirm that the target model loads normally and completes the vectorization task, avoiding model selection restrictions.

The values provided are common starting points and should be measured against the reader's own samples.
