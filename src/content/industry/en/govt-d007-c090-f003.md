# Declaration Materials and Case File Review for Refined Oil Sales: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data mainly comes from gas station inventory and sales systems, oil quality inspection report ledgers, and government declaration and approval forms. Update frequency: daily updates for inventory and sales data, weekly updates for inspection reports and approval case files. Document structure includes fields such as declaration number, oil product grade, outbound volume, inspection number, approval status, and declaration date. Units include liters, tons, yuan, batch numbers, etc. The length of a single case file document is mostly 500 to 2000 characters, and some include scanned copies of oil product inspection reports.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Refined oil sales declaration data has many closely related fields. Multi-turn dialogue must retain already obtained information such as declaration number and oil product grade to avoid repeated inquiries. Scanned attachments in case files must support image content extraction, otherwise automatic verification of quality inspection information cannot be completed. Daily updated inventory and sales data require the dialogue to associate the latest inventory in real time. Prompts must clearly specify the time range of the data. Declaration material formats are inconsistent, so prompts must adapt to field extraction for multiple form structures.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `chatId` | Fixed session identifier, validity period set to 1200 seconds | Adapts to context continuation requirements of multi-turn approval dialogues, avoids session interruptions |
| `messages` | Retain the last 10 rounds of dialogue content, with each round’s content not exceeding 1500 characters | Adapts to long-text processing of refined oil declaration materials, avoids context overflow |
| `variables` | Bind core fields such as declaration number and oil product grade | Reduces repeated inquiries, improves interaction efficiency of multi-turn dialogues |
| Dialogue history retention duration | Calibrated based on actual testing, recommended range of 600 to 1800 seconds | Adapts to multi-step approval cycles of case file reviews, balances context usage and response speed |

## Three Common Mistakes
- A 503 error is prompted when uploading documents via the dialogue box, but the background shows the upload was successful. The cause is that the `messages` parameter does not correctly carry the temporary identifier after file upload, causing front-end verification logic to malfunction.
- A "answer not found" prompt is displayed when retrieving a knowledge base image address. The cause is that the prompt is not configured with guidance logic for image content extraction, and only supports text retrieval.
- The same declaration field is repeatedly asked during multi-turn dialogue. The cause is that core information already obtained is not bound to `variables`, leading to incorrect retention of session context.

## How to Confirm the Configuration Is Properly Set
- Upload a single refined oil quality inspection report, check whether the dialogue can automatically extract the oil product grade and inspection number fields.
- Initiate two consecutive questions, check whether `chatId` remains consistent and the context is not cleared.
- Trigger knowledge base retrieval of image content, check whether a description of the corresponding oil product detection parameters can be generated.
- View background logs to confirm that the `variables` parameter carries verified declaration data.
