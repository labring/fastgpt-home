# Declaration Materials and Case File Review for Refined Oil Sales: Tool Calling and Plugins

## What This Category of Data Looks Like
Declaration materials and case file review data for refined oil sales originates from gas station operation ledgers, oil inventory and sales reports, compliance filing documents, and approval case files.
Operation ledgers update daily, recording daily oil grade, sales volume, revenue, and similar details.
Inventory and sales reports update per batch, including inbound volume, outbound volume, and remaining stock levels.
Compliance filing documents such as hazardous chemicals operating permits and metrology certification certificates update annually.
Approval case files include fixed fields: declaration number, submitted material list, review opinions, and more. Field units are primarily liters, tons, and yuan. Standard oil grades include 92#, 95#, 0#, and other common categories.

## Constraints for Tool Calling and Plugins Workflows
Daily updated operation ledgers require tool calls to pull latest data in real time. Using stale information will reduce review accuracy, so its use must be avoided.
Fixed oil grades and unit fields require tool call parameters to strictly match preset formats. Generalized processing is not supported.
Batch and annually updated filing documents and case files require plugins to sync knowledge base cache regularly. This ensures review basis remains timely.
Diversified declaration scenarios require tool calls to use scenario-specific configuration rules. This prevents cross-scenario review logic confusion.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto-trigger, only call dedicated refined oil review tools | Focus on exclusive verification logic for declaration materials and case files, reducing irrelevant calls |
| Tool call shunting rules | Shunt by declaration scenario (retail filing / inventory and sales declaration) | Differentiate review standards for different business types, improving calling accuracy |
| Single tool call timeout | 15–20 seconds | Adapt to typical response duration of gas station inventory data and case file queries |
| Knowledge base recall count | Top 3 entries | Match the number of associated case files for a single declaration material, avoiding interference from redundant information |
| `functionCall` | Mandatory field verification enforced | Ensure core fields such as oil grade and declaration date are required when calling tools |
| Concurrent call limit | 1–2 calls per second | Adapt to interface current limiting thresholds of gas station business systems, reducing call failure probability |

## Three Common Misconfigurations
- Phenomenon: When concurrent call volume exceeds 2 calls per second, tool calls return empty values or 503 status codes. Cause: Interface current limiting rules of the gas station system are not matched, triggering call restrictions.
- Phenomenon: The large language model does not trigger tool calls and returns a generic response directly. Cause: `toolChoice` is not configured to auto-trigger mode, or no dedicated review tool is specified.
- Phenomenon: Case file information returned by tool calls does not match the declaration materials. Cause: Knowledge base recall count is set too high, mixing in inventory data from unrelated batches.

## How to Confirm Proper Configuration
- A standard refined oil retail declaration material is submitted, and system logs are reviewed to confirm specified tool calls are triggered.
- Concurrent call volume is adjusted to the preset limit, and tool calls are verified to return no empty values or errors.
- The declaration type parameter is manually modified, and tool call shunting to the knowledge base for the corresponding business is confirmed.
- `functionCall` mandatory field verification is checked, and a material with missing fields is submitted to trigger an error prompt.

The values listed are common starting points. Adjust them based on specific samples and operational requirements of the deployment environment.
