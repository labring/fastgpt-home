# Declaration Materials and Case File Review for Refined Oil Sales: Document Parsing and Chunking
## What data for this category looks like
The data used for declaration materials and case file review in refined oil sales primarily originates from fuel station inventory and sales ledgers, compliance approval forms, VAT invoice stubs, special inspection case files, and similar sources.
Data update frequency follows the declaration cycle: daily updates for daily retail declarations, while quarterly and annual compliance case files are archived after project completion.
Document formats include structured Excel spreadsheets (with multiple column fields) and PDF approval documents.
Fields cover oil product categories, sales volume, revenue amount, approval nodes, inspection results, and more.
Units include liters, tons, yuan, ten thousand yuan, and other standard industry units.

## What constraints these characteristics impose on document parsing and chunking
Multi-column structured Excel documents can cause field identification confusion. If chunking logic does not adapt to multi-column structures, cross-column data concatenation errors are likely to occur.
Nested tables and handwritten annotations in PDF approval forms increase parsing difficulty. If enhanced parsing is not enabled, key approval node information may be lost.
Batch documents updated according to the declaration cycle require chunking rules adapted to fixed field structures, to avoid retrieval matching failures caused by changes in field order.
Batch case files have large size differences. Reasonable parsing and chunking parameters must be set to prevent timeouts or incomplete chunking.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the mixed structure of multi-column tables and approval text in refined oil declaration materials, avoiding single chunks spanning pages or fields |
| `chunkSplitter` | Split by paragraph and table boundaries | Adapts to documents with both coherent approval descriptions and multi-column data tables, preserving data relevance |
| `customPdfParse` | Enable mineru enhanced parsing | Adapts to nested tables and handwritten annotations in PDF approval forms, improving structured field extraction accuracy |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to upload requirements for batch case files and large inventory and sales ledgers, preventing large file upload failures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing time for large case files, preventing task failure due to parsing timeout |
| `chunkSettingMode` | Manual configuration | Adapts to the mixed structure of refined oil documents, allowing flexible adjustment of chunking rules and parsing parameters |

## Three common misconfigurations
- Symptom: After uploading a multi-column structured Excel file, only the first two columns of data are identified, and remaining column fields are lost. Cause: The `chunkSplitter` is not configured to split by table boundaries. The default chunking logic only extracts continuous text and does not adapt to multi-column table structures.
- Symptom: After calling `customPdfParse` to enable mineru enhanced parsing, approval signature fields in the PDF cannot be correctly extracted. Cause: The access key for the mineru API is not configured in the system, causing the enhanced parsing function to fail to activate properly.
- Symptom: Parsed boolean-type fields become null values when passed to a conditional judgment component. Cause: Parsed boolean-type fields are not converted to a recognizable format during the data mapping stage. The component cannot read non-standard boolean values, resulting in field loss.

## How to confirm the configuration is correct
- Upload a typical refined oil inventory and sales Excel spreadsheet, review the parsed field list, and confirm all column fields are correctly identified.
- Upload a PDF approval form containing nested tables, check that all table content and approval node information are retained in the parsing results.
- Upload a large case file exceeding the preset size, confirm the parsing task completes within the preset timeout period, with no timeout errors.
- Configure a conditional judgment component to connect to the parsed boolean field, run a test case, and confirm the component can read and process the field value normally.
