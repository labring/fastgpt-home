# Building Construction General Contracting Project Declaration Materials and File Review: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
The declaration materials and file review data for building construction general contracting projects mainly comes from project management systems, housing and urban-rural development department filing platforms, design institute construction drawing documents, and on-site construction ledgers. The data includes two categories: structured review forms and unstructured attachments. Structured fields include project number, construction unit, construction scope, review amount, approval status, file number, and similar items. Unstructured attachments are mostly PDF-format construction drawings, CAD drawings, completion acceptance reports, and similar documents. The data update schedule follows project approval milestones, with updates triggered at each submission and review milestone.

## Constraints Imposed on HTTP Interfaces and External Systems
The characteristics of declaration materials and file review data for building construction general contracting projects impose three constraints on HTTP interface configuration. First, structured form fields change dynamically with approval milestones, so interfaces must support passing custom variables. Second, unstructured attachments vary widely in size, from tens of KB forms to hundreds of MB CAD drawings, so interfaces must support large file transfers. Third, file review requires associating historical submission materials, so interfaces must support carrying context identifiers to enable material association across requests. Data updates follow approval milestones, so interface trigger rules for scheduled synchronization must be configured to ensure the timeliness of review data.

## Three Common Misconfigurations
- Incorrect configuration of the `Authorization` parameter when calling the interface, returning `{"code":514,"statusText":"unAuthApiKey","message":"common:code_error.e"}`. The cause is failing to use a valid FastGPT-generated API key, or omitting the `Bearer ` prefix in the key format.
- Failing to pass the context identifier parameter, resulting in no associated project information displayed in the conversation log, and review results unable to be linked to historical submission materials. The cause is ignoring the requirement for associating past materials in construction project file review, and not carrying the corresponding variable in the request.
- Failing to adapt to the transmission characteristics of large-volume attachments, and not configuring reasonable chunking rules, resulting in interface request timeouts or transmission failures. The cause is not considering the transmission requirements for large-volume files such as CAD drawings and completion acceptance reports in construction projects, and not adjusting the interface's file processing configuration.

## How to Verify Successful Configuration
- Call the interface and check that the return status code is 200, and no errors related to `unAuthApiKey` appear, confirming that the authentication configuration is effective.
- View the conversation log in the FastGPT backend, confirming that variables such as project number and approval stage carried in the request are correctly identified.
- Upload a single large-volume attachment (such as a 100 MB PDF file), confirming that the interface can complete transmission and processing normally.
- Initiate two associated requests, confirming that the second request can associate with the session context of the first request and retrieve historical review records.
