# Building Construction General Contracting Declaration Materials and File Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Declaration materials and file data for building construction general contracting originate from official submission documents submitted by construction units. These include project initiation approval documents, construction drawing design files, budget statements, qualification certificates, construction permit applications, and internal files generated during each approval phase. The data updates in sync with project approval progress, covering the full process from project initiation to completion acceptance. The document structure mixes structured forms and unstructured PDFs. Core fields include project unique ID, construction unit qualification level, budget amount, and approval node status. Units of measurement involved include square meters, ten thousand yuan, and calendar days.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering workflow
The mixed format of structured forms and unstructured PDFs requires multi-turn dialogue to clearly separate interaction logic for structured field queries and unstructured content review. This avoids confusing retrieval scopes.
Data updates dynamically with project approval progress. Multi-turn conversations must anchor to the current approval node’s context to prevent retrieval of expired historical materials.
Core fields have specific units. Prompt engineering must define clear verification rules to avoid unit conversion errors.
Individual file materials can be lengthy. Context length must be limited to fit the large model’s processing window.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 8000–12000 characters | Individual submission documents for building construction projects often reach several thousand characters. Multi-turn dialogue needs to retain historical interaction content for 3-5 approval nodes |
| Question Optimization | Enabled, optimized progressively by approval node | Multi-turn interactions for declaration review accompany node iterations. Optimized prompts can accurately match file content for the current stage |
| Single Search Limit | Top 6–10 results | File materials are stored classified by approval node. Single retrieval does not require excessive redundant results |
| `variables` | Bind project ID and construction unit qualification level variables | Core fields of building construction submission materials need to be dynamically inserted into prompts to ensure accurate review |
| `messages` History Truncation Threshold | Retain the most recent 4 rounds of interactions | Context from early non-current nodes in multi-turn review can easily interfere with current judgments. Truncation improves retrieval efficiency |
| `chatId` Session Binding | Bind the project unique identifier | Ensure multi-turn interaction contexts for the same project are not confused, meeting the archiving requirements of submission files |

## Three Common Misconfigurations
- Symptom: Knowledge base retrieval returns no results during multi-turn dialogue, but the same keyword can recall corresponding content when tested separately in the knowledge base. Cause: The `messages` in the multi-turn session carry expired project context, causing valid documents for the current node to be filtered out during retrieval.
- Symptom: 404 Invalid URL (POST /api/chat/completions) error is returned. Cause: `chatId` is not correctly bound, causing session routing exceptions, or required session identification parameters are not included during interface calls.
- Symptom: The workflow interrupts after reaching the large model processing step, and subsequent processes cannot continue. Cause: The prompt sets an output word limit, but the truncation verification rule is not passed via `variables`, causing the workflow to terminate abnormally after the large model output exceeds the limit.

## How to Confirm Proper Configuration
- Initiate a single-round test, enter keywords for a specific project’s declaration materials, and confirm that the retrieval results include the exclusive field content of that project.
- Initiate multi-round interactions, submit questions for different approval nodes in sequence, and confirm that the session context does not mix expired historical project data.
- Trigger the error scenario, and verify that there are no 404 errors during interface calls after `chatId` is bound.
- After configuring the prompt to limit output word count, confirm that the workflow can complete subsequent archiving steps normally.
