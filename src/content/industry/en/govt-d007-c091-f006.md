# Construction General Contracting Project Declaration Materials and File Review: Citation Sources and Traceability

## What this category of data looks like
The declaration materials and file data for construction general contracting projects mainly originate from project approval documents, bidding documents, construction quality inspection reports, completion acceptance archives, and submission materials submitted to government supervision platforms. Data updates align with project milestones. Corresponding documents are added after each approval stage, and a complete archived package is created once the project is completed. The length of individual documents varies significantly: small projects have documents ranging from dozens of pages, while large projects can reach hundreds of pages. Fields include project unique identifiers, construction unit qualification numbers, sub-project engineering quantities, test report numbers, approval seal records, and more. Units of measurement include square meters, cubic meters, tons, and standard construction duration days.

## What constraints do these characteristics impose on the citation and traceability link
Construction general contracting project declaration materials and file data characteristics impose three core constraints on the citation and traceability link. First, the span of individual document length is large. Short documents use minimal context window space, while long documents may exceed the model’s token limit, requiring targeted adjustments to context truncation rules. Second, the data contains a large number of engineering-specific unique identifiers and qualification numbers. Traceability requires precise matching of field content to avoid traceability errors caused by generalized matching. Third, data is updated in stages alongside project milestones, and some sources come from external links on government supervision platforms. A stable synchronization mechanism and proxy rules must be configured to ensure the timeliness and accessibility of cited content.

## Three Common Mistakes
- Phenomenon: Citation source original links cannot be downloaded normally, with 403 or connection timeout status codes returned by the browser. Cause: Correct nginx proxy rules for external links on government supervision platforms are not configured, preventing FastGPT from accessing original documents.
- Phenomenon: Calling the FastGPT citation traceability API returns a 200 status code but no content field in the response body. Cause: The `responseData` switch is not enabled correctly, causing the API to not return traceability content.
- Phenomenon: Cited content appears garbled or has messy display formatting, including extra line breaks and markers. Cause: The display format for the `detail` parameter is not configured correctly, or the original document encoding does not match the encoding used by FastGPT for processing.
