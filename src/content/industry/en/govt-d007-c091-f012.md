# Construction General Contracting Project Declaration Materials and File Review: Deployment and Upgrade

## What the data for this category looks like
The data for construction general contracting project declaration materials and file review mainly comes from construction project management systems, housing and urban-rural development filing platforms, on-site visa forms, and cost accounting documents. Data updates are triggered by project review submission nodes. Single submission materials are mostly multi-page PDF or Word documents. They include fields such as project number, construction scope, cost details, and acceptance records. Units include square meters, ten thousand yuan, working days, and others. Single file review materials have a large volume, and often include multiple related attachments.

## Constraints on deployment and upgrade links
Large volumes of declaration materials with multiple related attachments impose requirements on storage service read and write performance. Deployments must use configurations adapted for large file storage. Data updates are triggered by project review submission nodes. Upgrade processes must ensure stable incremental synchronization logic, to avoid repeated or missed synchronization. Materials include multiple types of structured fields and unstructured text. After deployment, compatibility of format parsing must be verified. Upgrades must retain adaptability of original parsing rules. File review involves multi-link related data. The response efficiency of knowledge base associated queries must be ensured, to avoid single request timeouts.

## How to configure settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `DB_MAX_LINK` | 1000–1500 connections | Adapts to the link call requirements of multiple attachments in construction project files, avoiding link limit exceedance for single requests |
| `STORAGE_S3_ENDPOINT` | Intranet domain name adapted for local object storage | Construction materials are mostly large-volume files; intranet storage reduces upload and download latency |
| `REDIS_URL` | Intranet Redis connection address with password authentication | Used to cache frequently queried review rules and project metadata, reducing database pressure |
| `FE_DOMAIN` | Public or intranet domain name for deployed services | Used to generate valid domains for embedded pages, adapting to existing system integration requirements |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Used to sign file access tokens, ensuring access security for review materials |
| `ROOT_KEY` | Custom strong password string | Used to initialize platform administrator permissions, meeting security configuration requirements of state-owned enterprise and public sector systems |

## Three common configuration errors
- A 3005 status code is returned after startup, and large model interfaces cannot be called. The cause is incorrect configuration of `MONGODB_URI` or `REDIS_URL` connection parameters, leading to failed dependent service initialization.
- Embeddable frontend pages cannot be found after an upgrade. The cause is that the new version only exposes API services by default, and frontend static resources are not packaged by default. Manually configure `FE_DOMAIN` and deploy the frontend package.
- Database connection timeout errors occur during local deployment. The cause is that `PG_URL` is not configured with an intranet address. Public network access is restricted by firewall policies or network latency.

## How to confirm correct configuration
- Run the platform's built-in storage connectivity test to verify that the storage service configured with `STORAGE_S3_ENDPOINT` can upload and download test files normally.
- Initiate a simulated request for a small-scale file review, and confirm that link calls configured with `DB_MAX_LINK` do not trigger limit exceedance errors.
- Access the address configured with `FE_DOMAIN`, and confirm that the frontend page loads normally and loads review-related knowledge base content.
- Check system logs to confirm that there are no timeout or authentication failure records for connections to `REDIS_URL` and `MONGODB_URI`.

The values provided are common starting points, and should be evaluated against the reader's own samples.
