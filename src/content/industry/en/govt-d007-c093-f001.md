# Declaration Materials and File Review for Government and Enterprise Informatization Services: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
The declaration materials and file review data for government and enterprise informatization services mainly come from government service declaration portals and enterprise internal archive management systems. Data updates are completed with single declaration processes or daily archive batches, with no fixed high-frequency update rhythm. Each single data entry includes two parts: structured metadata and unstructured attachments. Structured fields include declaration subject identification, item category, file number, review node records, and other related fields. Unstructured attachments are mostly declaration documents and approval files in PDF and Word formats. Fields follow government data specifications, with fixed format and length constraints.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
The fixed format requirements for structured metadata mean HTTP interfaces must support field binding and format verification to prevent invalid data from being passed in. The diverse formats and size ranges of unstructured attachments mean interfaces must support multi-type file uploads and configure reasonable size limits. The characteristic that data updates follow declaration batches means interface call frequency must match business rhythms to avoid excessive calls consuming system resources. The sensitivity of government and enterprise data means interface authentication must use secure credential transmission methods to reduce data leakage risks. The requirement for review node circulation records means interfaces must support the transmission and synchronization of status fields, enabling external systems to track file progress. This document applies to FastGPT v4.17.0.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {government and enterprise exclusive service key}, valid for no more than 7 days` | Complies with government and enterprise data security specifications, reduces key leakage risks |
| `variables` | Bind metadata fields such as declaration subject unified social credit code and file number | Matches the structured metadata structure of declaration materials, facilitating subsequent classification and retrieval |
| `responseData` | Include three core fields: review status, attachment storage path, batch identifier | Matches the process tracking requirements of file review, enabling external systems to synchronize status |
| Request timeout setting | 300–600 seconds | Adapts to the parsing and review duration of government and enterprise declaration materials, preventing mid-process interruptions |
| Attachment upload limit | Single attachment no larger than 1000 MB, maximum 5 attachments per request | Complies with government declaration attachment upload specifications, controls interface load |

## Three Common Misconfigurations
- Calling a local file upload interface results in empty metadata fields. The cause is failure to correctly bind the metadata fields corresponding to `variables` in the request, leading to metadata not being properly passed to the system.
- Calling the chat interface does not hit the specified knowledge base, and the returned result is unrelated to the expected knowledge base. The cause is failure to configure the associated parameters for the corresponding knowledge base in the request parameters, leading the system to use the global knowledge base by default.
- Interface calls frequently trigger timeout errors. The cause is that the request timeout setting is too short, failing to adapt to the parsing and review duration of government and enterprise declaration materials.

## How to Confirm the Configuration Is Correct
- Call the authentication interface to verify credential validity. A 200 status code indicates correct authentication configuration.
- Initiate a test call to check if the returned data includes the preset review status, attachment storage path, and batch identifier fields.
- Upload a test declaration material to check if metadata is correctly bound and displayed in the corresponding knowledge base.
- Initiate a test call with the maximum allowed attachments to confirm the upload process is not blocked and attachments are parsed normally.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
