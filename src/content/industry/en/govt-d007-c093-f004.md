# Declaration Material and File Review for Government and Enterprise Informatization Services: Workflow Orchestration

## What the data for this category looks like
The data for declaration material and file review for government and enterprise informatization services originates from three main sources: government service submission portals, internal archive management systems, and self-service upload channels used by enterprises.
Data updates finish with each individual declaration batch. The update cycle per batch follows the actual declaration and transfer rhythm.
Each individual file includes structured declaration forms and unstructured attachments. Structured forms contain fields such as declaration subject, project number, and qualification verification items. Unstructured attachments include scanned documents, PDFs, Excel spreadsheets, and similar files.
The total size of materials per file usually does not exceed 1000 MB. Core identifying fields include file ID, review node, and transfer status.

## Constraints imposed on workflow orchestration
Mixed structured and unstructured file data requires splitting field parsing and attachment processing nodes in workflow orchestration. This prevents single-node processing loads from exceeding reasonable limits.
Multiple data input sources require configuring multiple adaptation nodes. These nodes support submission portal data in different formats.
The maximum 1000 MB size per file requires setting segmented processing rules in workflows. This prevents single requests from exceeding system carrying limits.
Review processes trigger based on node transfer. Workflows must bind `variables` to transfer file status parameters. This ensures context synchronization for each review link.

## Recommended Configuration Settings
For FastGPT v4.17.0, use the following configurations for workflow orchestration related to declaration material and file review for government and enterprise informatization services.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Workflow timeout duration | 1200 seconds | Adapt to the parsing and review duration of 1000 MB materials per file, avoid triggering the system's default 120-second termination rule |
| Variable transfer scope | Globally visible | Ensure parameters such as file ID and review node in `variables` are synchronized across all nodes in the full workflow |
| Node trigger rule | Trigger based on approval node completion status | Match the serial review logic of government and enterprise file transfer, ensure the process advances in order |
| File upload node | Supports both local path and URL input | Comply with self-service upload scenarios for enterprise submissions and background interface reception scenarios |
| Workflow retry count | 3 times | Address temporary interface call failures during a single review, prevent process interruption |
| Node ID | Assign `nodeId` based on file ID | Ensure unique identification for each transfer node, facilitate subsequent log troubleshooting and status tracking |

## Three Common Misconfigurations
- Workflows terminate automatically after running for more than 2 minutes, with a timeout error prompt displayed on the interface. The cause is failing to adjust the workflow timeout configuration, and using the system default 120-second threshold.
- The file ID parameter in `variables` cannot be referenced when calling the upload file node, and the variable options are empty in the tool call pop-up window. The cause is failing to enable the variable reference permission for the upload node, which prevents context parameters from being passed.
- The configured dedicated model does not appear in the drop-down list of workflow nodes. The cause is failing to bind the corresponding model to the usage permissions of the current workflow, only enabling the model at the account level.

## How to Verify Successful Configuration
- Test uploading materials with a size under 1000 MB per file, check whether the workflow can fully transfer to the final review node.
- Try referencing the file ID parameter in `variables` in the file upload node, confirm that the variable can load normally and pass to subsequent nodes.
- Enter the model configuration page, check whether the enabled models are associated with the usage permission scope of the current workflow.
- Trigger a complete process, check whether the running logs of each node include correct file status and `nodeId` identifiers.
