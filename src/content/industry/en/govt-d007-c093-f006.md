# Declaration Materials and Case Review for Government and Enterprise Informatization Services: Citation Sources and Traceability

## What this category of data looks like
Data for declaration materials and case review for government and enterprise informatization services originates from project declaration documents, approval cases, and supporting attachments from central state-owned enterprises and government departments. Updates are triggered by declaration submission, approval node activation, and regular synchronization after archiving. Document structures primarily use structured form fields, supplemented by attached text in PDF and Word formats. Fields include declaration subject, project number, submission time, review status, attachment content, and others. Units include characters, bytes, ISO timestamps, and more. The length of individual documents varies widely.

## What constraints these characteristics impose on citation sources and traceability
Structured fields of declaration materials and cases are closely linked to attached text. Citation and traceability require precise matching to specific fields and corresponding paragraphs of attached documents, to ensure accurate review basis. Document updates rely on node triggers. Index updates must be synchronized with approval workflows to avoid referencing outdated data. The length of individual documents varies widely. A reasonable chunking strategy must be used to prevent loss of key review node information. Government and enterprise data has strict compliance requirements. Traceability information must fully retain original source identifiers to ensure traceability to specific submitted case entries.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 2000–3000 token | Individual government and enterprise declaration case files have lengthy content, requiring sufficient context for precise traceability |
| `responseData` | Enabled | Original cited source data must be returned to ensure association with specific fields of declaration materials and attached content |
| `detail` | Full | Complete traceability information must be returned, including key identifiers such as case number and submission time |
| Single search limit | Top 5 entries | Relevant entries for government and enterprise declaration cases are concentrated in the top 5 entries. Excessive results will increase system latency |
| Chunk length | 1000–1500 characters | Covers core review node content, preventing loss of key associated information across chunks |
| Overlap length | 100–200 characters | Retains contextual association between chunks, preventing disruption to continuity of key review logic |

## Three common mistakes
- Issue: After configuring `quoteMaxToken`, the system process freezes with no response, and logs show timeout errors. Cause: The set token value exceeds the resource limit of the current deployment, or the single search limit is set too high.
- Issue: In workflow code run nodes, variables referenced from the knowledge base cannot be selected, and the first search result cannot be output. Cause: The `responseData` configuration is not enabled, or the chunk length setting does not match the document structure.
- Issue: Generated review replies do not link to the content of original declaration materials, and irrelevant content appears. Cause: The `detail` configuration is not set to full, only summary information is returned, making traceability to specific case fields impossible.
