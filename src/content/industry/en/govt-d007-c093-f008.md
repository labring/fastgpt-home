# Declaration Material and Case File Review for Government and State-owned Enterprise IT Services: Document Parsing and Chunking

## Data profile for this category
This data comes from project proposals, administrative law enforcement case files, and qualification application materials from the government and state-owned enterprise communication sectors. Updates are tied to individual projects or law enforcement process progress, with no fixed batch update cycle. Documents mostly use nested chapter structures, and include standardized tables, electronic signature pages, and multi-file packaged attachments. Fields include project ID, declaring entity, budget amount, law enforcement document number, and similar items. Common units are ten thousand yuan, units, and person-times.

## Constraints imposed on the document parsing and chunking link
The nested chapter structure and standardized tables require the parsing process to preserve content hierarchy, to avoid logical confusion caused by cross-chapter text splicing. Multi-file packaged attachment bundles must first undergo batch decompression and single-file parsing, otherwise attachment content may be omitted. Pages with electronic signatures may have text obscured by images, so parsing logic for non-text areas needs to be adapted. Fixed business fields such as project ID and law enforcement document number must be extracted accurately, and must not be interrupted by chunking, otherwise subsequent associated queries will be affected.

## Configuration settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Government and state-owned enterprise declaration materials are mostly long texts. This range preserves the integrity of individual business modules and avoids splitting critical business fields |
| `chunkSplitter` | Split by paragraph + title | Matches the nested chapter structure of documents and preserves logical connections between content |
| `customPdfParse` | Enabled | Adapts to the standardized signature and table layouts of government and state-owned enterprise PDFs, and optimizes text recognition for areas obscured by images |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Large case file PDFs take longer to parse, this avoids interrupting the parsing process due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports multi-attachment packaged bundles commonly included in government and state-owned enterprise declaration materials, meeting large file upload requirements |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for nested chapters, ensuring fixed business fields are not accidentally split |

## Three common errors
- Issue: Text missing or fields appearing empty after parsing some PDF files with electronic signatures. Cause: The `customPdfParse` configuration is not enabled. The default parsing engine cannot adapt to the special layouts of government and state-owned enterprise PDFs.
- Issue: Timeout errors returned when calling the document parsing tool in a workflow. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for parsing large case files.
- Issue: Only the main file is parsed after uploading a multi-attachment packaged declaration material. Cause: No batch decompression pre-process is configured, and the attachment parsing logic is not triggered.

## How to confirm configurations are correctly set
- Upload a single government and state-owned enterprise PDF file with an electronic signature, check if the parsed text includes business fields from the signature area, to confirm the `customPdfParse` configuration is active.
- Upload a case file larger than 100 MB, wait for parsing to complete and check for timeout errors, to confirm the `PARSE_FILE_TIMEOUT_SECONDS` value is appropriate.
- Manually adjust the `chunkSize` parameter, check if the chunking results preserve the integrity of individual business modules, to confirm the `chunkSettingMode` configuration meets requirements.
- Check if the `UPLOAD_FILE_MAX_SIZE` parameter matches the maximum declaration material bundle size in business scenarios, to confirm the upload limit aligns with actual business needs.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
