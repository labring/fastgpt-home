# Declaration Materials and Case Review for Government and Enterprise IT Services: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
This category of data is primarily sourced from internal government and enterprise declaration material templates, archived case libraries, annual policy documents, and review operation manuals. Data updates follow policy adjustments or declaration batch progress, with no fixed schedule but large single-update volumes. Most documents are a mix of structured and semi-structured content, including fields such as document numbers, declaration subject qualification requirements, material lists, review rules, case numbers, submission deadlines, and more. Most fields include unit information such as serial numbers, character counts, and page counts.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Since data updates have no fixed schedule and involve large single-update volumes, the retrieval link must support incremental synchronization configuration to avoid excessive system resource usage from full refreshes. Semi-structured documents contain multiple types of fields with associated units, so differentiated retrieval weights must be set for different fields to prevent irrelevant results from entering the review process. The text length of declaration materials and cases varies significantly, ranging from single-page instructions to dozens of pages of files, so long text chunking and recall logic must be adapted to avoid truncation of critical review clauses. Policy documents and review rules are updated frequently, so the latest version knowledge base content must be synchronized regularly to ensure retrieval results align with current review standards.

## Configuration Parameters
This configuration is based on FastGPT v4.17.0. Specific parameters are listed below:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.85–0.92` | Review requirements for declaration materials and cases are strict, so low-similarity irrelevant content must be filtered to avoid incorrect review judgments |
| `limit` | `Top 10 results` | Review staff need to quickly review core candidate results; too many entries increase screening costs |
| `searchMode` | `Semantic retrieval + full-text retrieval hybrid` | Documents contain structured fields and semi-structured text; hybrid mode balances semantic matching and precise keyword hits |
| `usingReRank` | `Enabled` | There are many long-text case files; re-ranking optimizes result sorting accuracy and improves review efficiency |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Declaration policies often include supplementary explanations; extended queries can cover more implicit review requirements |
| `collectionIds` | `Bind dedicated case and declaration material knowledge base collections with total size not exceeding 1000 MB` | Declaration data from different departments must be isolated to avoid cross-permission retrieval, while also controlling the single-library retrieval scope |

## Three Common Misconfigurations
- Symptom: No synchronized data appears in the knowledge base, and the interface displays a retrieval timeout. Cause: Cross-container network permissions for the Docker database were not configured, preventing FastGPT from connecting to the database to pull case and declaration material data.
- Symptom: Retrieval results include content with non-compliant semantic similarity or low full-text retrieval scores. Cause: The `similarity` threshold and retrieval filtering rules were not set correctly, or the `usingReRank` function for filtering low-quality results was not enabled.
- Symptom: Retrieval results remain stuck in the "Retrieving" state. Cause: The dedicated knowledge base collection was not bound correctly, leading the retrieval scope to cover excessive irrelevant data, or long text processing exceeded system limits and caused a timeout.

## How to Verify Configuration Correctness
- Execute a single test retrieval, input typical declaration material review keywords, and verify that the returned result set matches the bound `collectionIds`.
- Review the similarity scores of retrieval results, confirm they fall within the preset threshold range, and adjust the `similarity` parameter to correct discrepancies if needed.
- Submit a batch retrieval task, check if results are returned within a reasonable time frame, and confirm the retrieval logic adapts to the processing requirements of long-text case files.
- Trigger an incremental synchronization task, verify that newly added declaration cases are automatically synchronized to the knowledge base, and confirm the update logic is functional.

The values provided above are common starting points, and should be evaluated against the specific samples associated with the deployment.
