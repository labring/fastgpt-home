# Declaration Materials and Case Review for Government and Enterprise Informatization Services: Deployment and Upgrade

## What this type of data looks like
Data for declaration materials and case review in government and enterprise informatization services comes from internal government and enterprise declaration management systems and case archiving systems. Data update timelines follow project declaration cycles or case archiving batches, with no fixed daily update frequency. Document structures include structured fields and unstructured attachments. Structured fields include unified social credit codes, declaration project numbers, approval statuses, case numbers, and similar items. Unstructured attachments are mostly PDF and Word format declaration documents and scanned case materials. This data has multi-source heterogeneous characteristics. Some fields support custom enterprise extensions.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:securepass@internal-mongo:27017/archives?authSource=admin` | Connects to the internal government and enterprise case archiving document library, stores unstructured case scans and approval records |
| `PG_URL` | `postgresql://admin:securepass@internal-pg:5432/declare?schema=public` | Connects to structured data from the declaration system, stores declaration subject information and approval node data |
| `STORAGE_S3_ENDPOINT` | `https://gov-objectstore.enterprise.com:9000` | Adapts to internal government and enterprise object storage services, stores large-capacity declaration attachments and case materials |
| `FILE_TOKEN_KEY` | `64-bit random encryption string` | Encrypts file access tokens to prevent unauthorized access to sensitive declaration materials |
| `DB_MAX_LINK` | `25–35 connections` | Meets concurrent access requirements for bulk declaration materials, avoids exhausting database connections |
| `ROOT_KEY` | `Strong key generated per enterprise security specifications` | Configures super administrator permissions for background management of review process configuration and exception handling |

## Three common configuration errors
- Unable to access the FastGPT background management page, with the prompt "Invalid administrator key". The cause is an incorrect `ROOT_KEY` configuration, lost key, or failure to regenerate and synchronize updated configuration files.
- Bulk declaration material processing tasks time out, with database connection exhaustion errors shown in background logs. The cause is failure to adjust the `DB_MAX_LINK` value, where the default connection pool size is insufficient to support concurrent reads of bulk case data.
- Uploaded declaration attachments fail to load normally on the frontend, with the prompt "File access denied". The cause is an incorrect storage address specified in `STORAGE_S3_ENDPOINT`, or a mismatch between the `FILE_TOKEN_KEY` encryption key and the storage service.

## How to verify successful configuration
- Log in to the FastGPT background management page, enter the configured `ROOT_KEY`, and verify that the management interface loads successfully.
- Upload a test PDF format declaration attachment, verify that it is stored normally and loads on the frontend page, confirming that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Initiate a simulated declaration case review task, verify that database connections work normally, and check that read and write operations for `PG_URL` and `MONGODB_URI` succeed.
- View FastGPT background system logs, confirm that the `DB_MAX_LINK` configuration parameter is loaded correctly, and that no database connection-related error messages appear.

The values provided are common starting points and should be assessed against the target deployment’s own samples.
