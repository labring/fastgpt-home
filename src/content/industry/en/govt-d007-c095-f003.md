# New Energy Development Declaration Materials and Case Review: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data sources include filing materials submitted by new energy project declaration entities, and approval case archives from industry regulatory authorities. Update frequency follows the review process of individual projects. Document structure includes project basic information modules, resource survey data attachments, compliance certification documents, funding and operation plans. Fields include installed capacity (unit: MW), land scope (unit: hectare), approval document number, submission time, and others. The length of individual documents varies widely, and content includes multiple formats such as text, tables, and images.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The wide variation in document length and multiple attachment types require multi-turn dialogue context windows to adapt to material fragments of different lengths, to avoid truncating core compliance information. Specific unit fields require prompt engineering to automatically verify unit matching during review, to prevent review errors caused by unit mismatches. Multi-source data is scattered across declaration materials and approval cases. Multi-turn dialogue must retrieve corresponding data step-by-step according to review nodes, to ensure accurate context association. Dynamic updates to the review process require prompt engineering to support real-time synchronization of the latest case status, to avoid generating review conclusions based on outdated information.

| `variables` | Preset dedicated verification field set for new energy projects | Fix verification rules for required fields such as installed capacity (MW) and land area (hectare) |

| Maximum context length | 8000–12000 token | Adapt to the average length of new energy declaration materials, avoid truncating core compliance information |
| Dialogue history storage duration | 7 days | Match the standard review cycle for individual new energy projects |
| Single file upload limit | 1000 MB | Adapt to the size of declaration attachments containing multiple survey reports |

## Three Common Misconfigurations
- Fixed format rule trace symbols appear at the end of dialogue response results. Cause: The output format mandatory append switch in prompt engineering is not disabled, causing the system to automatically add preset review rule descriptions.
- Uploaded declaration material attachment images cannot be fully displayed in dialogue interactions. Cause: The parsing priority for multiple file types is not correctly configured in the `messages` parameter, leading to incomplete loading of image resources.
- Declaration material file streams cannot be correctly passed when calling the dialogue interface. Cause: The file upload field for the `variables` parameter is not bound in the request body as required, leading to the interface failing to recognize attachment content.

## How to Verify Proper Configuration
Initiate a single-turn review dialogue, input "Verify the installed capacity unit of a wind power project", and check whether the returned result automatically matches the MW unit to confirm that the field rules of the `variables` parameter are in effect.
Upload a declaration attachment containing images, check the parsing and display status of the attachment in the dialogue interface to confirm that the file processing logic is configured correctly.
Call the dialogue interface and pass the unique `chatId`, initiate two linked dialogue turns, and check whether the second dialogue retains the project context from the first dialogue to confirm that session binding is correct.
View the dialogue history list in the system backend, confirm that the dialogue records of the current test project can be retrieved within the preset duration to confirm that the storage rules are in effect.

The values provided are common starting points and should be measured against relevant project samples.
