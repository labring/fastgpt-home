# New Energy Development Declaration Materials and File Review: Workflow Orchestration

## What the data for this category looks like
Data sources for new energy development declaration materials and files include state-owned enterprise and central enterprise energy project filing systems, natural resource department land use approval portals, and grid company grid connection application platforms.
Data updates occur every 7 days during the project preparation phase for approval, and every 3 days after approval is granted.
Documents mix multi-page PDF declaration files and structured XML filing files.
Included fields are project filing number, installed capacity (unit: MW), land use range coordinates, environmental impact assessment approval document number, unified social credit code of the declaring entity, and grid connection plan attachment link.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources require workflow configuration to include cross-system call nodes, with `variables` used to pass unique identifiers and associate materials from different data sources.
Mixed document formats require configuring format adaptation nodes in the workflow to avoid field loss from unified parsing.
Numeric fields with units require adding verification nodes to validate the unit and value range of installed capacity.
Different update rhythms across project stages require configuring scheduled synchronization nodes to match the frequency of data pulling.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `variables` | Bind the project filing number as the core key | Used to pass unique identifiers across nodes, avoiding mixing materials from different data sources |
| Code execution node input | Only pass the current node context | Avoid validation failures triggered by passing global variables |
| Data source synchronization cycle | 3 days per use (after approval), 7 days per use (before approval) | Match the data update frequency across each stage of new energy project declaration |
| Document parsing rule | Automatically switch based on file suffix | Adapt to the mixed structure of PDF declaration materials and XML filing files |
| Permission verification node | Verify using the declaring entity's unified social credit code | Match the main identity field of declaration materials, ensuring audit permission compliance |

## Three common errors
- When configuring the code execution node to include global historical records in the input, parameter validation fails, and the workflow cannot proceed to the next step. Reason: The code execution node in FastGPT v4.17.0 has built-in validation rules that only allow use of the current node context. Passing global historical records triggers interception.
- Not binding the project filing number via `variables`, leading to subsequent data source calls failing to match the corresponding declaration materials. Reason: No core identifier transfer is configured, so cross-node data cannot be associated with the complete file of the corresponding project.
- Setting the synchronization cycle to daily updates, leading to frequent external system calls triggering interface rate limiting. Reason: The actual update rhythm of new energy project declaration data is not matched, and the data update frequency is low after approval.

## How to confirm the configuration is complete
- Trigger a workflow test, input a test project filing number, and check whether `variables` are correctly passed to all subsequent nodes.
- Upload mixed-format declaration materials, and confirm that the document parsing node correctly identifies PDF and XML content and extracts corresponding fields.
- Adjust the input range of the code execution node, and verify that no validation errors occur when global historical records are not included.
- View the data source synchronization log, and confirm that data pulling actions are triggered according to the preset cycle.
