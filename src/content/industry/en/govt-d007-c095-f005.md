# Declaration Materials and File Review for New Energy Development: Tool Calling and Plugins

## What This Category of Data Looks Like
Declaration materials and file data for new energy development projects mainly originate from central and state-owned enterprise energy project declaration systems, natural resources department filing documents, project feasibility study reports, and grid connection plan documents. Data updates follow project declaration batches, with only one update per declaration cycle. The document structure combines structured fields and unstructured text. Structured fields include project filing number, installed capacity, land area, grid connection voltage level, with corresponding units: filing number, megawatt (MW), hectare (hm²), kilovolt (kV). Unstructured content includes transcribed text from on-site survey photos, policy compliance explanations, and the like. A single complete file can reach a maximum size of 100 MB.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins Workflow
The mixed data structure requires tool calling to support both structured field extraction and non-standard text parsing; a single text matching approach cannot complete review tasks. The batch-based update feature requires plugins to regularly pull the latest filing data to avoid use of expired historical file content. The dedicated units for each field require tool calling to automatically complete unit conversion and verification to prevent review errors caused by capacity unit confusion. The large size of individual files requires tool calling to adapt to long-text processing to avoid call failures caused by context overflow.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the mixed content structure of new energy declaration materials, automatically triggers text parsing and structured field extraction |
| Plugin Timeout Duration | `120–180 seconds` | A single declaration file can be up to 100 MB, so long-text parsing requires sufficient processing time |
| Knowledge Base Retrieval Limit | `Top 8 entries` | New energy declaration materials involve multiple types of related documents including filings, feasibility studies, and grid connection plans, so sufficient related content must be covered |
| `functionCall` | `Enabled` | Requires calling tools to extract structured fields such as installed capacity and land area to improve review accuracy |
| Error Retry Count | `2 times` | Data sources occasionally have temporary fluctuations, retries can reduce call failures caused by temporary exceptions |
| Result Formatting Rule | Group output by declaration project fields | File review requires organizing data by project dimension to facilitate subsequent manual review |

## Three Common Misconfigurations
- When the basic chart plugin is used to generate a pie chart, the returned content cannot be rendered in Markdown format. This occurs because the correspondence between chart data and declaration fields is not specified, and raw text is passed directly, leading to format parsing failure.
- Review results returned by API calls differ significantly from those in online chat, with some structured fields empty or matched incorrectly. This occurs because the `toolChoice` parameter is not properly configured in the API call, so tool calling is not triggered, and only fuzzy matching from the knowledge base is used.
- Tool calling encounters timeout errors. This occurs because the large size characteristic of new energy declaration materials is not accounted for, and the plugin timeout duration is set too short to complete long-text parsing.

## How to Verify Proper Configuration
- A test new energy project declaration material is submitted, and tool calling is checked to confirm whether specified structured fields including project filing number and installed capacity are extracted.
- The same test prompt is sent to both online chat and the API interface, and returned results are compared to confirm consistency between field matching and tool calling.
- A temporary abnormal data source scenario is simulated to trigger a tool call failure, and checks are performed to confirm whether retries are executed according to the configured retry count, and whether results return to normal after retries.
- The basic chart plugin is called, and installed capacity and power generation data from the declaration material are passed in. The returned pie chart is checked to confirm whether it can be rendered normally in Markdown format.

The values provided here are common starting points and should be measured against the reader's own samples.
