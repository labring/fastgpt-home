# New Energy Development Declaration Materials and File Review: Citation Sources and Traceability

## What the Data for This Category Looks Like
New energy development declaration materials and project file data mainly come from official record documents and internal approval archives from stages such as project initiation, environmental assessment, and grid connection acceptance. Updates are synchronized in batches as projects progress. Most documents are multi-page PDFs or structured Word documents, and include fixed fields such as project number, record number, installed capacity, and land scope. Units include kilowatt, hectare, ten thousand yuan, and similar units. The length of individual documents varies widely, and file page counts differ significantly across projects.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
New energy development declaration materials and files have long document and fixed field attributes. This requires precise matching of official record fields during the citation traceability link, to avoid traceability failure caused by vague citations.
Batch updates require regular synchronization of the latest archived data, to prevent referencing expired approval documents.
Wide variation in individual document length requires limiting the token usage of each citation, to avoid context overflow that harms answer accuracy.
Official record attributes require traceability information to include clear archive numbers and times, to meet compliance requirements.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | The core citation content of new energy project files usually includes record numbers, installed capacity and other information. This range covers core information while avoiding context overflow |
| `responseData` | Return only core archive and approval information | Filter non-essential search process data to simplify traceability display |
| Single search limit | Top 5 entries | Associated record materials for new energy projects are usually concentrated within 5 entries. Too many entries will dilute core information |
| Reranking | Enabled | Long document chunked content needs to be sorted by relevance to ensure that record content directly related to declaration needs is recalled first |
| `detail` | Full | Traceability needs to display complete archive information, including project number and archive time, to meet compliance requirements |
| Maximum context | 4000–5000 token | Adapt to the chunked integration needs of multi-page project files, avoiding truncation of core approval process information |

## Three Common Configuration Mistakes
- Phenomenon: Errors appear when viewing knowledge base citations in chat responses, or the response displays knowledge base content unrelated to declaration requirements. Reason: The `quoteMaxToken` parameter is not configured correctly, causing citation content to exceed the context threshold and trigger errors, or no reasonable single search limit is set to filter non-core entries.
- Phenomenon: After calling via workflow tool, the response still displays the input and response citation fields of knowledge base search. Reason: The citation display switch is not turned off in the workflow node, or the `responseData` parameter is not configured correctly to filter non-essential output.
- Phenomenon: Recalled citation content does not match the specific project being declared, showing new energy project files from other regions. Reason: Reranking configuration is not enabled, or the single search limit is set too high, introducing non-core associated materials.

## How to Confirm the Configuration Is Correct
- A typical new energy project declaration file is uploaded, a query requesting the record number or project installed capacity is initiated, and the citation information displayed in the response is verified to include correct archive fields and time.
- The citation pop-up in the chat interface is viewed, to confirm there are no error prompts and only file content directly related to the query is displayed.
- Workflow call mode is switched, a query is initiated, and the response is checked to confirm the input and response fields of knowledge base search do not appear.
- The `quoteMaxToken` parameter is adjusted to different ranges, the length change of citation content is observed, and the parameter's effect is confirmed.

The values provided here are common starting points and should be evaluated against samples relevant to the specific use case.
