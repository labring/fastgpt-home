# Non-ferrous Metal Smelting Declaration Materials and File Review: HTTP Interfaces and External Systems

## What this category of data looks like
Non-ferrous metal smelting declaration materials and file review data comes from production process collection records, compliance approval and filing documents, and archived project files. The system updates data for each single declaration project based on its progress cycle. Document structures include structured declaration fields and linked inspection and compliance attachments. Fields include smelting furnace identifier, metal content value, unit energy consumption value, approval and filing number, and file archive number. Most data uses structured table and PDF original report formats.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Data sources cover three types of external systems: production, compliance, and archives. Interfaces must adapt to multi-source authentication. Configure the `Authorization` parameter to distinguish access permissions for different systems. Data includes structured fields and large-volume attachments. Interfaces must support multi-format data reception and chunked uploads. Declaration data updates by project batch. Interfaces must support pulling or pushing data using a batch identifier to avoid duplicate synchronization. Category-specific fields must strictly match business logic. Interfaces must add field validity checks to prevent synchronization failures caused by format incompatibility.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Set to the Bearer Token corresponding to the external system | Adapt to authentication requirements for multi-source external systems, and distinguish access permissions for production, compliance, and archive services |
| `variables` | Set to the unique identifier of the declaration batch | Pass batch parameters to ensure batch uniqueness for synchronized data |
| Single request data volume | 800–1200 characters (structured fields) + single attachment no larger than 1000 MB | Match the single-batch data scale of non-ferrous metal smelting declaration materials, and avoid interface overload |
| Request timeout | 600 seconds | Accommodate time required for large-volume inspection attachment uploads and multi-field validation |
| Data synchronization trigger timing | Triggered at the completion node of the declaration batch | Align with the declaration progress rhythm of smelting projects, and ensure data synchronization timing matches business processes |
| Field validation rules | Validate the uniqueness of smelting furnace identifiers and approval and filing numbers | Match category-specific business logic, and prevent duplicate entry or format errors |

## Three Common Mistakes
- The interface returns a 401 Unauthorized status code, and the external system fails to connect. The cause is missing independent `Authorization` parameters for different external systems, leading to authentication failure.
- Some fields are empty or have abnormal formats after interface synchronization. The cause is skipping validation of category-specific field validity, and directly receiving non-standard format data.
- Frequent duplicate synchronization triggers cause redundant data in external systems. The cause is configuring synchronization by fixed intervals instead of declaration batch completion nodes, which does not match business nodes.

## How to Confirm Proper Configuration
- Call the test interface, and check if structured fields in the returned `responseData` match the original data from the external system.
- Upload a test inspection attachment, and confirm the interface can normally receive and store large-volume files.
- Simulate a declaration batch completion node, trigger an interface call, and check if the external system receives data for the corresponding batch.
- View interface logs, confirm the `Authorization` parameter is correctly carried, and no authentication-related errors appear.
