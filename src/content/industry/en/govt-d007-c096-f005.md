# Declaration Materials and File Review for Non-Ferrous Metal Smelting: Tool Calling and Plugins

## What this type of data looks like
Data for declaration materials and file review in non-ferrous metal smelting originates from internal enterprise smelting production ledgers, local industry and information technology department filing receipts, customs import and export documents, and internal file management systems. Updates follow individual declaration batch and file archiving progress, with no unified fixed cycle. Document structures are mostly structured tables embedded in PDF files, or structured data from dedicated systems. Fields include batch identifiers, production node parameters, approval circulation records, and compliance inspection item numbers. Units involve tons, batch numbers, inspection report numbers, and similar metrics.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
The mixed structured and unstructured nature of the data requires tool calling to support both structured parameter reading and unstructured document parsing. The need for precise field matching to unique identifiers requires tool calling to bind batch numbers, inspection item numbers, and other unique identifiers, to avoid review errors caused by fuzzy matching. The non-fixed update rhythm requires tool calling to pull the latest data in real time, and disable overly long local caching. The multi-page long text attribute of documents requires tool calling to limit the text length processed in a single run, to prevent context overflow.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Adapts to the tool calling logic of FastGPT v4.17.0, and meets the multi-type data processing needs of declaration materials and files |
| Single tool call timeout | `120–180 seconds` | Declaration materials for non-ferrous metal smelting require retrieval of multiple sets of production ledgers and approval records, with higher time consumption than general scenarios |
| `functionCall` | Enable forced function calling | Ensure that mandatory fields such as batch numbers and inspection report numbers must be passed during tool calling, to avoid review failures caused by missing parameters |
| Context retention limit | `800–1200 token` | Matches the core data length of a single batch of declaration materials, prevents context interruption caused by long documents |
| Number of retrieved results to reorder | `Top 3` | File review prioritizes the most matching compliance inspection basis, to avoid redundant results interfering with model judgment |
| Maximum number of single retrieval results | `Top 6` | Covers all types of filing documents required for declaration materials, while controlling the load of tool calling |

## Three Common Misconfigurations
- Symptom: The model context is interrupted after calling an MCP tool, and logs show context length limit exceeded. Cause: Forced parameter validation via `functionCall` is not enabled. Unrelated content returned by the tool occupies core context space, leading to context truncation.
- Symptom: Multiple parameters cannot be supplemented when calling an MCP tool in a workflow, and content entered during the question-and-answer session cannot be mapped to the mandatory fields of the tool. Cause: No parameter mapping node is configured for the workflow, and user input is not bound to fields required by the tool such as batch numbers and production capacity values.
- Symptom: Excessively high model response delay occurs after calling an MCP tool, and the interface shows that tool calling takes longer than expected. Cause: The single tool call timeout is set too short, or the maximum number of retrieval results is set too high, causing the tool to pull excessive smelting ledger data and increasing data processing and return time.

## How to Confirm Correct Configuration
- Initiate a test call with a clear batch number, check whether the content returned by the tool matches the smelting ledger data of the corresponding batch, and confirm that parameter binding takes effect.
- Upload a long document declaration material, check whether the model triggers a reorder operation, and confirm that the reorder configuration takes effect.
- Check the tool calling configuration logs, confirm that the value of the `toolChoice` parameter matches the configured setting, with no abnormal switching.
- Simulate the multi-parameter question-and-answer process in the workflow, check whether the tool automatically receives all mandatory fields passed in by the workflow, and confirm that parameter mapping takes effect.
