# Declaration Materials and Case Review for Non-Ferrous Metal Smelting: Document Parsing and Chunking

## What this category of data looks like
Declaration materials and case review data for non-ferrous metal smelting mainly come from enterprise production ledgers, monthly quality inspection reports, environmental assessment declaration documents, government approval case files, and technical transformation plan documents. Data update rhythm falls into two categories: fixed cycle and temporary trigger. Fixed cycle refers to monthly declaration and quarterly case archiving. Temporary trigger corresponds to emergency technical transformation or special inspection declaration. Document types include three categories: structured tables, long-text process descriptions, and scanned PDF approval files. Fields include metal grade, production capacity, emission concentration, etc. Units are mostly percentage, tons/year, mg/m³. Some documents have cross-page continuous tables and nested chapter structures.

## What constraints these characteristics impose on document parsing and chunking
Fixed-cycle batch declaration materials and cross-page tables require parsing components to support batch task scheduling and cross-page table merging. Scanned PDF documents require OCR parsing to extract text from images. Long-text process descriptions are lengthy. Chunking must balance semantic completeness and retrieval granularity to avoid semantic fragmentation caused by over-splitting. Consistent units for specialized fields require retaining original unit identifiers after parsing. Otherwise, subsequent field matching will be affected. Temporary special declaration files may include oversized attachments. Larger file upload and parsing durations must be allowed.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Non-ferrous metal smelting declaration materials include long paragraph process descriptions and short-text tabular data. This range balances semantic completeness and chunk retrieval granularity |
| `chunkSplitter` | Split by title + paragraph | Declaration materials have clear chapter titles and process paragraphs. Splitting by title preserves the document's hierarchical structure |
| `customPdfParse` | Enabled | Some declaration materials are scanned PDFs. Enabling this triggers OCR parsing to extract text and tabular data from images |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | Large case archiving files may include multiple attachments and cross-page tables, requiring a higher file upload limit |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large environmental assessment declaration documents and technical transformation plan documents take longer to parse, avoiding task termination due to timeout |
| `chunkSettingMode` | Manual configuration | Declaration materials of different types have significantly different chunking requirements. Manual configuration adapts to different scenarios |

## Three Common Mistakes
- Phenomenon: The latter half of process descriptions or tabular data is missing from parsed documents. Causes: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too small, causing parsing to terminate before completion, or the table parsing switch in `customPdfParse` is not enabled, resulting in unextracted tabular data.
- Phenomenon: Table datasets cannot be selected as the parsing source on the knowledge base construction page. Causes: The table parsing sub-function in `customPdfParse` is not enabled, or the uploaded tabular file format is not supported by the system.
- Phenomenon: Semantic fragmentation occurs in chunked paragraphs, with unrelated content across chapters. Causes: `chunkSplitter` is not configured to split by title hierarchy, so chunking does not follow the document's natural chapter structure, merging content from different chapters.

## How to Verify Proper Configuration
- Upload a scanned environmental assessment declaration document with fewer than 100 pages. Check that the parsing task completes normally, with no timeout or file size limit errors.
- Review the parsed chunk results. Confirm that tabular data is fully extracted and retains its original format, with no missing fields or garbled text.
- Adjust `chunkSize` to 800 characters and 1200 characters separately. Compare the chunk results, confirm that semantic completeness is maintained and no over-splitting occurs.
- Upload a case archiving file larger than 1000 MB. Confirm that the upload succeeds and no file size limit is triggered.
