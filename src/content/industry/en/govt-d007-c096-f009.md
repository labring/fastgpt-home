# Declaration Materials and Case Review for Non-Ferrous Metal Smelting: Model Access and Configuration

## What the data for this category looks like
Data sources for declaration materials and case review records in this category include production execution system (MES) ledgers, test reports from third-party quality inspection institutions, declaration forms submitted to ecological environment departments, and safety supervision law enforcement cases. Data updates synchronize with each batch of smelting output. The update cycle for a single batch of declaration materials does not exceed 7 days. Documents fall into two categories: structured forms and unstructured attachments. Structured fields include smelting batch number, furnace number, target metal content value, unit energy consumption, and pollutant emission concentration value. Unstructured attachments include PDF-format quality inspection reports, monitoring screenshots, and approval circulation records.

## What constraints these characteristics impose on model access and configuration
Declaration materials and case records for non-ferrous metal smelting include structured values with specific units, multiple types of unstructured attachments, and short update cycles. These factors create multiple constraints for model access and configuration.
Adapt parsing support for multi-format attachments such as PDFs and screenshots to ensure the model can accurately identify quality inspection reports and monitoring materials.
Bind values to their corresponding units to avoid unit confusion during parsing.
Configure parameters optimized for short-cycle context to support efficient calls to the latest batch data, given the high data update frequency.
Reserve sufficient context reference space for case review, which requires comparison with historical batch data, to prevent key historical information from being truncated.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Accommodates structured fields and associated attachment summaries for a single batch of declaration materials, to avoid context overflow |
| `quoteMaxToken` | `3000–5000 token` | Case review requires comparing contents of up to 5 historical batch cases, reserving sufficient reference space |
| `vision` | Enabled | Parses PDF-format quality inspection reports and monitoring screenshot attachments |
| `temperature` | `0.1–0.3` | Declaration material review requires strict alignment with standard formats, reducing the probability of randomly generated content |
| `AIPROXY_API_ENDPOINT` | Fill in the privately deployed enterprise proxy address | Ensures data does not leave the enterprise intranet, complying with data security requirements for Chinese public sector and state-owned enterprise environments |
| `AIPROXY_API_TOKEN` | Use the unified authentication key allocated by the enterprise | Implements fine-grained access permission control |

## Three common errors
- Garbled text appears when parsing PDF quality inspection reports. Cause: The `vision` configuration is not enabled, or the visual parsing capability of the corresponding model is not configured.
- Uploaded DOC-format declaration attachments cannot be analyzed. Cause: Parsing support for DOC format is not enabled in the FastGPT v4.17.0 file upload configuration, or the associated model does not support document parsing.
- Model connection fails after configuring `AIPROXY_API_TOKEN`, returning a 401 status code. Cause: The authentication key has expired, or the access permission for the corresponding model is not bound.

## How to verify a successful configuration
- Upload a standard smelting batch declaration PDF, and confirm that the target metal content value and corresponding unit are correctly extracted in the parsing result.
- Submit a historical case comparison request, and confirm that the returned result includes the required historical batch reference content.
- Test uploading a DOC-format quality inspection attachment, and confirm that the parsed text content has no garbled characters and complete fields.
- Trigger a complete case review process, and confirm that the model output does not include redundant thinking process displays.
