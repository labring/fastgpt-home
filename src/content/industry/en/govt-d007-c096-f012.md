# Declaration Materials and Case Review for Non-Ferrous Metal Smelting: Deployment and Upgrade

## What Data for This Category Looks Like
Data mainly comes from quality inspection logs, environmental protection declaration documents, work safety case files, and raw material and product circulation records generated during the non-ferrous metal smelting process. Data is generated alongside business nodes. Regular declaration materials are updated quarterly, and case files are archived after each individual approval process. Most documents are structured tables and fixed-field documents, including fields such as smelting batch ID, raw material composition parameters, smelting temperature range, qualified quality inspection items, declaration document number, case number, submission date, and more. Field units include degrees Celsius, count, batch ID, and others. Some case files include scanned attachments, with no unified fixed format template.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Multi-source heterogeneous structured documents and scanned attachments require configuring mixed-format file parsing capabilities during deployment, and updating industry-specific parsing plugins during upgrades.
Quarterly updated declaration materials and irregularly archived case files require storage configurations that support automatic classification and archiving by business nodes, to avoid data redundancy and retrieval confusion.
Fields containing smelting-specific professional parameters require configuring semantic understanding adapted to professional terminology, and updating the embedding model version during upgrades to ensure retrieval accuracy.
Intranet access scenarios require reverse proxy configurations adapted to internal domain names and port rules, to avoid cross-domain access failures.
The deployment logic of FastGPT v4.17.0 must be adapted to these data characteristics, to prevent default configurations from failing to match the industry's data structure.

## Three Common Misconfigurations
- The symptom is a MongoDB connection error prompt after starting the container, with ECONNREFUSED shown in the logs. The cause is that the intranet IP, port, or authentication information configured in `MONGODB_URI` is incorrect, and does not match the actual configuration of the intranet MongoDB instance.
- The symptom is that after configuring the Ollama model channel, the model list cannot be loaded, and retrieval requests for case files cannot be initiated. The cause is that the intranet firewall has not opened the default Ollama port 11434, or the FastGPT container and Ollama instance are not in the same intranet network segment.
- The symptom is that after accessing via nginx reverse proxy, uploading scanned smelting case attachments fails, with a file upload failure prompt on the page. The cause is that the domain name configured in `FE_DOMAIN` does not match the domain name used by the nginx proxy, or the correct cross-domain rules for file upload have not been configured.

## How to Verify Proper Configuration
- Run the container log viewing command to confirm that there are no error logs for MongoDB, PostgreSQL, or Redis connections.
- Access the internal domain configured in `FE_DOMAIN`, log in to the system, and try uploading a structured smelting quality inspection log document to confirm that the file upload is successful and there are no authentication errors.
- After configuring the Ollama model channel, refresh the model list page to confirm that the locally deployed Ollama models can be loaded.
- Submit a retrieval request for smelting declaration materials to confirm that the returned retrieval results match the case file fields, with no irrelevant content included.
