# Declaration Materials and File Review for Nuclear Power Operations: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Data primarily comes from nuclear power plant safety management systems, reactor DCS logs, nuclear safety declaration and approval platforms, and internal file archiving systems. Temporary event files are updated in real time when event disposal is completed. Annual operation declaration materials are summarized and updated quarterly. Documents include structured fields and long-text attachments. Structured fields include reactor type, cumulative operating hours, event classification, and approval document number, with units corresponding to megawatt thermal power, hours, and event level (1 to 7). Long-text attachments are mostly multi-page PDFs or structured report files.

## Constraints Imposed by These Characteristics on the HTTP Interfaces and External Systems Link
The mixed data structure requires the interface to support both structured parameter passing and large file uploads. Multipart form-data request formats must be configured. Real-time updated temporary files and periodically updated declaration materials require the interface to support incremental pull logic, to avoid resource usage from full pulls. Nuclear power business data compliance requirements mandate that interface requests carry compliant identity credentials, transmission meets cybersecurity protection specifications, and returned fields strictly match preset nuclear power business fields to avoid missing or type errors. Differences in formats of various declaration materials require the interface to adapt to multiple input and output formats. For example, PDF attachments must have the correct Content-Type configured.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer Non-commercial API key (configure 7-day validity and 100 daily call limits)` | Nuclear power business data requires strict access control. Key restrictions prevent abuse after leakage, and comply with FastGPT v4.17.0 key configuration specifications |
| `variables` | Configure business variables such as reactor type and cumulative operating hours | Adapt to declaration material templates for different nuclear power units, reduce repeated configuration |
| `responseData` | Only return structured fields and file IDs of associated files | Simplify data processing logic for external systems, avoid redundant information |
| Request timeout | 600 seconds | Long response times are required for large file uploads and complex file review processing |
| Maximum single request file size | 1000 MB | Single attachments for nuclear power declaration materials typically do not exceed this size |
| Incremental pull filter field | Filter by file update timestamp | Accurately pull incremental data, avoid repeated processing of already reviewed files |

## Three Common Misconfigurations
- Scenario: The interface returns a 403 Forbidden status code, and audit logs show key call counts exceed preset limits. Cause: Time and usage limits were not enabled for the non-commercial API key in FastGPT configuration, leading to unrestricted abuse after key leakage.
- Scenario: External table data pulled via the API does not include the operating hour field required for nuclear power declarations. Cause: Required business fields were not configured in `variables`, so the interface only pulled default fields.
- Scenario: After the API calls the knowledge base chunking process, the returned chunk length exceeds the preset 1000-character requirement. Cause: No configuration parameters for chunking rules were passed in the interface request, so the default chunking logic was used.

## How to Confirm Successful Configuration
- Call the test interface, check if the returned `responseData` includes preset nuclear power business fields, and whether field types match business requirements.
- Upload a small nuclear power declaration PDF attachment, confirm the request completes normally with no timeout or format error prompts.
- Trigger the incremental pull interface, check if the returned files only include updated data within the specified time range, with no duplicate entries.
- Call the key verification interface, confirm that the validity period and usage limit settings for the non-commercial API key are in effect, and return corresponding errors when limits are exceeded.

The values given are common starting points and should be measured against the reader's own samples.
