# Nuclear Power Operation Declaration Materials and File Review: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Nuclear power operation declaration materials and file review data primarily comes from internal operation and maintenance management systems and nuclear safety regulatory reporting platforms.
Data update frequency adjusts based on project milestones.
Materials for a single declaration batch are uploaded in a concentrated batch.
Routine files are updated weekly.
Most documents are Word or PDF files with fixed structures, containing standardized fields such as unit number, safety level, approval node, and document number.
Professional measurement units include megawatts, operating hours, equipment sets, and other industry-specific terms.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Fixed standardized fields and professional measurement units require prompts to include clear field mapping rules. This avoids unprofessional generated expressions.
Concentrated batch uploads of large material volumes require multi-turn dialogue to support context association for batch documents. This prevents repeated parsing and data redundancy.
Update schedules tied to project milestones require dialogue contexts to be isolated by declaration batch. This stops cross-batch data confusion.
A single declaration file can exceed ten megabytes in size. The dialogue link’s document parsing must support long text processing. It is also necessary to control the context length of a single dialogue round to avoid exceeding model processing limits.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier per declaration batch | Isolates dialogue contexts for different batches, preventing cross-batch data confusion |
| `messages` | Limit to the first 20 dialogue rounds per single batch of materials | Matches the single-batch processing scale of nuclear power declaration materials, preventing context overflow |
| `variables` | Preset professional field variables such as unit number and safety level | Adapts to the mapping requirements of fixed document fields, improving prompt accuracy |
| Chunk length | 800–1200 characters | Adapts parsing and splitting of single ten-plus megabyte Word files, balancing context completeness and retrieval efficiency |
| Document parsing timeout | 600 seconds | Accommodates parsing time for large-volume files, avoiding mid-process interruptions |
| Question optimization switch | Enabled | Optimizes user questions for nuclear power professional terminology, adapting to domain expression habits |

## Three common configuration errors
- Phenomenon: After submitting a single 10-plus megabyte Word declaration file, the interface displays parsing timeout or progress stagnation. Cause: The document parsing timeout configuration is not adjusted. The default timeout duration is insufficient for the parsing process of large-volume nuclear power declaration materials.
- Phenomenon: When calling the dialogue interface, the returned result does not link to preset professional fields such as unit number and safety level. Cause: The `variables` parameter is not correctly configured. Professional fields are not bound to dialogue context variables.
- Phenomenon: Cross-batch data confusion appears during multi-turn dialogue. Cause: The `chatId` is not used to isolate dialogue contexts by declaration batch. Cross-batch context data is reused.

## How to verify correct configuration
- Upload a single 10-plus megabyte nuclear power declaration Word file. Check if parsing progress completes normally. Confirm the timeout configuration adapts to the file size.
- Submit a question containing nuclear power professional terminology. Check if the returned result automatically maps preset fields such as unit number and safety level. Confirm the `variables` parameter is configured correctly.
- Launch dialogue sessions for two declaration batches from different units. Switch the `chatId` and check if contexts are isolated. No cross-batch data is mixed in.
- Test multiple consecutive rounds of questions. Check if dialogue contexts are automatically truncated per preset rules. Confirm configurations take effect.
