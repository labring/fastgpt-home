# Nuclear Power Operation Declaration Materials and File Review: Workflow Orchestration

## What This Category of Data Looks Like
Declaration materials and file review data for nuclear power operations originates from internal management systems of nuclear power operation units, including reactor operation logs, equipment maintenance archives, safety inspection records, approval circulation forms, and more.
Data update rhythms include daily real-time submission and scheduled batch updates. Daily safety inspection records are updated each day. Major equipment change declaration materials are submitted in real time alongside the approval process. File review materials are updated in concentrated batches per review cycle.
Single documents include fields such as declaration number, reactor unit number, equipment model, submission time, review node, and attachment list. Most fields use fixed-format text and numeric types. Attachment sizes are measured in megabytes (MB). This content is based on the workflow orchestration feature of FastGPT v4.17.0.

## What Constraints These Characteristics Impose on Workflow Orchestration
Data sources for nuclear power operation declaration materials and file reviews are scattered across multiple internal systems. Workflows must be configured with multiple data source connection nodes to pull data across systems.
Data update rhythms vary significantly. Differentiated trigger rules must be set for different material types to avoid redundant execution or delayed processing.
Most document fields have fixed formats. Field validation nodes must be configured in workflows to ensure required fields are complete and format-compliant.
File review follows a fixed process flow. Workflows must be strongly bound to review statuses, with precise matching of trigger conditions for each review step.

## Recommended Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Mapping | Bind declaration number and reactor unit number fields | The unique identifier for nuclear power declaration materials and files is the declaration number, which must be associated with the corresponding `variables` configuration |
| `variables` | Configure grouping by review batch | Nuclear power file review is processed in batches, so variable scope must be divided by batch to adapt to parallel review scenarios for multiple reactor units |
| Timeout Duration | 600 seconds | Nuclear power review processes involve multi-stage compliance checks, requiring sufficient processing time |
| Chunk Length | 800–1200 characters | The body length of a single declaration material falls within this range, adapting to content splitting and retrieval needs |
| `nodeId` | Bind the unique identifier of the review node | Precise triggering of workflow nodes corresponding to each review link is required to avoid process confusion |
| Maximum Context | Previous 5 historical files | Review requires reference to past similar cases, limiting the number of contexts to avoid interference from redundant information |

## Three Common Mistakes
- Phenomenon: External links configured in workflows display as "Click to Ask Immediately" buttons in review results. Cause: The plain text output mode is not selected in the workflow's reply component, and session interactive link rendering is enabled by default.
- Phenomenon: Global variables are lost during multi-turn workflow conversations. Cause: Persistent storage for global variables is not configured in the workflow, causing variables to reset after context interruption.
- Phenomenon: Workflow execution results do not comply with review validation rules. Cause: Workflow input instructions are not set in accordance with nuclear power declaration compliance requirements, and required fields and validation logic are not restricted.
