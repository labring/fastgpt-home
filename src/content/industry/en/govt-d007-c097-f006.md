# Nuclear Power Operations: Declaration Materials and File Review - Citation Sources and Traceability

## What the data for this category looks like
Nuclear power operation declaration materials and file review data mainly comes from the safety declaration systems and archived file libraries of nuclear power operation units. Updates occur in real time with each individual declaration task submission. Archived files are bulk synced to the knowledge base every quarter.
Documents primarily use structured combinations, and include fields such as declaration number, nuclear power unit number, declaration item category, review progress, attachment file path, and review opinions. These fields correspond to string, Arabic numeral, classification tag, status enumeration, file path, and text format respectively. No extra unstructured redundant content is included.

## Constraints imposed by these characteristics on citation sources and traceability
The structured field features of nuclear power operation declaration materials require that citation traceability be bound to a unique declaration number as the traceability identifier. This prevents confusion between content from different declaration batches.
According to the update rhythm of declaration batches, the knowledge base sync must only incrementally pull newly submitted declaration files. This avoids repeated indexing of old data.
The presence of multi-format attachments requires that the traceability link support extracting structured fields and main text content from attachments such as PDF and Word.
The classification attributes of review progress and status fields require that citation results synchronously display the status of the corresponding review stage. This ensures complete traceability information.

## Three Common Configuration Mistakes
- Phenomenon: The interface displays that knowledge base content is cited, but the generated answer does not match the professional content of nuclear power declaration materials. Cause: Structured field matching for `responseData` is not enabled. Only general text recall is used, so association with nuclear power-exclusive fields cannot be completed.
- Phenomenon: Uploaded PDF-format nuclear power files are not recalled or cited. Cause: Chunk length is not configured to adapt to long documents, or attachment text extraction for `detail` is not enabled. This results in structured fields not being fully indexed.
- Phenomenon: Imported HTTP request response data is not used as a valid citation source. Cause: The response data is not converted to the structured format supported by FastGPT, or `responseData` is not configured to enable indexing of response content.

## How to Confirm Configuration Is Correct
- Upload a single nuclear power declaration file to the knowledge base. Check if the chunked text retains the declaration number and nuclear power unit number fields.
- Initiate a query targeting a nuclear power declaration item. Verify if the returned result displays the traceability information corresponding to the `detail` field.
- Call the workflow API with a test question. Confirm that the returned result includes the citation mark of the specified knowledge base and the corresponding declaration fields.
- Check the knowledge base sync log. Confirm that only newly submitted nuclear power declaration files are incrementally indexed, with no duplicate sync records.
