# Declaration Materials and File Review for Nuclear Power Operations: Document Parsing and Chunking

## What this category of data looks like
Data for nuclear power operation declaration materials and file review mainly comes from official declaration documents required by nuclear safety regulations, daily operation logs, maintenance records, and safety assessment files. There are two update cycles: daily special declarations are updated quarterly or per project milestones, and archived files are uploaded in one batch after project completion. Document types include fixed-format multi-column Excel declaration forms, PDF technical reports with embedded formulas and watermarks, and long-text safety analysis documents. Fields include equipment ID, radiation dose, operation parameters, and others, with units mostly being professional nuclear power units such as millisieverts, megapascals, and degrees Celsius.

## What constraints these characteristics impose on document parsing and chunking
The structured format of multi-column Excel declaration forms triggers adaptation limits in the default parsing logic, which only recognizes the first two columns of data, leading to loss of core fields. The professional content of long-text technical reports is highly correlated. Too short chunking will destroy the integrity of technical logic, while too long chunking will cause redundant retrieval context. Professional measurement units and fixed fields in nuclear power documents must be fully retained, and units and associated parameters cannot be randomly split during chunking. Single files of large archived PDF documents have large sizes, leading to long parsing times, and default timeout settings easily cause task interruptions. The frequent updates of daily declaration materials also put forward requirements for parsing efficiency.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Nuclear power declaration materials include long-text technical chapters and multi-column tables. This range preserves the integrity of single-segment professional content and avoids context breaks |
| `chunkSplitter` | Semantic chunking | Nuclear power documents contain a large number of professional terms and fixed-format technical parameters. Semantic chunking preserves content logical coherence |
| `customPdfParse` | Enable MinerU API | Nuclear power PDF documents often contain embedded formulas, multi-column tables and watermarks. MinerU API improves structured parsing accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large nuclear power archived PDF files have large sizes and long parsing times. This duration prevents mid-time timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Some nuclear power archived files can reach hundreds of megabytes per single file. Adjusting this upper limit supports complete uploads |
| `chunkSettingMode` | Manual configuration | For different types of declaration materials such as declaration forms and technical reports, manual configuration allows flexible adaptation of chunking rules |

## Three common mistakes
- After uploading a multi-column Excel declaration log, the knowledge base only recognizes the first two columns of data. Cause: No adjustment was made to the parsing configuration to adapt to the multi-column format. The default logic only recognizes standard two-column tables, leading to loss of core fields.
- After enabling PDF parsing, expected table content is not returned, and the task status shows timeout. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted. Parsing large nuclear power archived PDF files takes longer than the default threshold, and the task is forcibly interrupted.
- The conditional judgment component returns a null value after receiving the device status boolean parameter parsed via HTTP. Cause: The original data type was not preserved during the document parsing stage. Chunking converted the boolean value to a string, leading to format loss that cannot be properly recognized by the conditional judgment component.

## How to confirm the configuration is correct
- Upload a single multi-column Excel declaration log, check if the knowledge base parsing result includes all preset columns to confirm parsing integrity.
- Upload a single large nuclear power archived PDF file, check if the parsing task status is completed within the duration set by `PARSE_FILE_TIMEOUT_SECONDS` with no timeout errors.
- Test the retrieval effect after chunking, input professional terms or specific equipment parameters, and confirm that the matching degree between the retrieval results and the input content meets expectations.
- Check if the `customPdfParse` configuration item is enabled, and confirm that the MinerU API call record is displayed in the PDF parsing log.
