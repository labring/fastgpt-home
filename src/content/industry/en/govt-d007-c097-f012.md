# Nuclear Power Operation Declaration Materials and File Review: Deployment and Upgrade

## What this category of data looks like
Nuclear power operation declaration materials and file review data comes primarily from nuclear safety review declaration documents and annual operation file archive materials. Updates follow a single review cycle or annual archive cycle. Most documents are multi-page compliant PDFs and structured spreadsheet documents. They include fields such as reactor operation parameters, radiation dose records, and equipment calibration reports. Units include Celsius, days, pascals and other professional measurement standards.

## What constraints these characteristics impose on the deployment and upgrade phase
This data has large volume and long individual document length. The deployment phase must support large file storage and chunked processing logic. Fixed-cycle batch archive updates require database and cache configurations to handle high-concurrency batch writes. Many professional fields and strict measurement standards mean retrieval configuration must support precise professional term matching, and meet nuclear safety data storage compliance requirements. The upgrade phase must retain the association of original archive data. Version iteration must not cause historical file index failure, which would disrupt compliance review workflows.

## How to set configurations
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom password@dedicated cache server address:6379/1` | Nuclear power file retrieval frequency is high. Use database 1 for dedicated cache to avoid conflicts with other business caches and ensure retrieval stability |
| `STORAGE_S3_ENDPOINT` | Dedicated endpoint address of a domestic compliant cloud storage service | Nuclear power documents must meet data storage compliance requirements. Dedicated storage services ensure data security and traceability |
| `MONGODB_URI` | Database connection string with RBAC permission verification, specifying an independent business database | File data must be stored separately from other business data to ensure the independence of compliance review data |
| `DB_MAX_LINK` | `20–30` | Adapt to concurrent connection requirements during batch archiving. Avoid database overload caused by excessive connection count |
| `FE_DOMAIN` | Intranet or compliant public network domain name of the deployment instance | Unify the front-end access entry to ensure compliance of access paths for internal review personnel |

## Three common configuration mistakes
- Symptom: A `Connection refused` error appears in startup logs, and core services fail to load. Cause: Required `MONGODB_URI` or `REDIS_URL` parameters are not configured, resulting in failed database or cache connections.
- Symptom: Document chunks are lost during batch import of nuclear power files, and the import task terminates early. Cause: A reasonable `DB_MAX_LINK` connection count is not set. Concurrent writes exceed the database's carrying capacity, and some index data is not fully written.
- Symptom: The front-end interface prompts that the cache is not ready, and retrieval results are empty. Cause: The database number configured in `REDIS_URL` does not match the cache business database, resulting in the dedicated cache not being called normally.

## How to confirm the configuration is correct
- View service startup logs to confirm there are no connection errors related to `MONGODB_URI` or `REDIS_URL`. Correct the corresponding configuration based on the error content.
- Upload a single nuclear power declaration document for import testing. Check the generated number of document chunks against the source document content to confirm no abnormal loss.
- Initiate a file keyword search to verify the matching logic between returned results and source documents. Adjust relevant configurations based on retrieval performance.
- Check the file directory of the compliant storage service to confirm that imported file documents have completed upload and index binding.

The values provided are common starting points and should be measured against the reader's own samples.
