# Civil Aviation Airport Declaration Materials and Case Review: Vector Models and Indexes

## What this category’s data looks like
Civil aviation airport declaration materials and case review data originates primarily from airport operation approval systems, air traffic control declaration platforms, and safety supervision case databases. Data updates trigger with individual approval workflows. Submitted declaration materials update immediately after submission. Archived cases sync in quarterly batches. Most documents are official PDF files, including application forms, qualification certificates, flight schedules, safety emergency plans, and other related content. Fixed fields include declaration number, airport 3-letter code, application date, approval status, and attachment list. Some attachments contain unstructured content such as airport floor plans and equipment parameter sheets. Units include sorties, workdays, square meters, and other aviation-specific measurement standards. The vector model and index configuration for this scenario uses FastGPT v4.17.0.

## Constraints on the vector model and index workflow
The varied document lengths of civil aviation declaration materials create constraints. Qualification certificates may span only a few pages, while safety emergency plans cover dozens of pages. Some single pages contain thousands of characters. This requires a vector chunking strategy that adapts to mixed text structures. Data includes both structured metadata and unstructured attachments. The workflow must process both text content and image attachments such as bitmap-format airport floor plans. This creates requirements for compatibility with multimodal vector models. The instant update requirement of declaration workflows demands indexes that support incremental synchronization. This avoids unnecessary resource consumption from full index rebuilds. Fixed fields such as declaration number and airport code can serve as metadata filtering criteria. These fields must be bound to corresponding indexes during construction to narrow search ranges and improve review efficiency.

## Configuration settings
| Configuration Item | Recommended Values | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the mixed structure of civil aviation declaration materials, which include both short-text approval descriptions and long-text safety plans |
| Overlap Length | 100–150 characters | Prevents loss of contextual association when splitting long text into chunks |
| maxToken | 8192 | Meets the input upper limit requirements of multimodal vector models, and supports processing needs of long civil aviation declaration materials |
| Similarity Threshold | 0.72–0.80, calibrated via actual testing | Filters low-match irrelevant case content and improves review accuracy |
| Single Search Limit | Top 10 results | Matches the review volume scale of single-batch declaration materials, and avoids redundant results |
| defaultToken | Resource configuration reserved for the deployment environment | Controls resource usage of single-batch vector calculations, and adapts to hardware conditions of airport internal networks |

## Three common configuration errors
1.  Phenomenon: An error prompt for parameter values appears when configuring the vector model, and model binding cannot be completed. Cause: Image attachments in declaration materials were not processed according to the input format required by the model, and raw PDF files without extracted images were uploaded directly.
2.  Phenomenon: A large number of cross-airport irrelevant cases appear in search results, and the number of returned results exceeds the set limit. Cause: Metadata filtering rules were not configured, and search ranges were not limited by airport 3-letter code or declaration number.
3.  Phenomenon: Initial index construction takes too long and exceeds preset thresholds. Cause: Incremental index mode was not enabled, and repeated vector calculations were performed on full historical cases.

## How to confirm successful configuration
- A standard civil aviation airport flight schedule declaration PDF is uploaded, and the vector generation task status is checked for success.
- A simulated declaration review query is input, and returned search results are verified to only include materials from the same batch of declarations, with no irrelevant case content.
- Vector model call logs are reviewed, and the values of `maxToken` and `defaultToken` are confirmed to match the configured parameter values, with no abnormal error reports.
- A new declaration attachment is incrementally uploaded for testing, and the index is checked for automatic updates without triggering a full rebuild task.

The values listed above are common starting points, and should be evaluated against samples relevant to the target deployment.
