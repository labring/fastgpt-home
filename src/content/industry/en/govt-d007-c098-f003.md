# Civil Aviation Airport Declaration Materials and File Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data is sourced from airport operation management systems, civil aviation regional administration filing platforms, and internally archived approval files. Update frequency follows either archive update after a single declaration task is completed, or daily synchronization of new declaration batches. A single declaration file includes three structural categories: application forms, supporting qualification documents, and approval circulation records. Fields include declaration number, application date, approval status, involved flight sorties, usage time period, with corresponding units such as sorties, hours, square meters, and others.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Declaration files have multi-level document structures. Multi-turn dialogue must accurately distinguish declaration subject information, approval circulation nodes, and supporting document content to avoid context confusion. Fields have dedicated units. Prompt engineering must explicitly require calculation or verification results using corresponding units to prevent unit mismatches. Data from a single declaration batch is independent. Multi-turn dialogue must limit the current session to bound declaration numbers to avoid cross-batch data confusion. Supporting documents are mostly long text formats. The multi-turn dialogue context window must adapt to long text segment processing to ensure key approval node information is not lost.

## How to set configurations
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Context window upper limit | 8000–12000 characters | Adapts to the average text length of a single declaration file, avoids truncating key approval node information |
| `messages` context truncation rule | Retain the most recent 20 conversation turns | Focuses on multi-round communication content for the current declaration batch, filters irrelevant historical conversations |
| `variables` bound fields | Declaration number, flight sorties | Locks exclusive declaration data for the current session, avoids cross-batch call errors |
| `chatId` session isolation strategy | Create independent sessions per single declaration task | Ensures context from different declaration batches does not interfere with each other |
| Prompt template configuration | Calibrated based on actual testing | Adapts to exclusive terminology and approval processes for civil aviation airport declaration materials |
| Maximum waiting duration | 600 seconds | Adapts to time requirements for long document parsing and cross-system data retrieval |

## Three common mistakes
- Phenomenon: The Human field is empty in the API call response record preview. Cause: User conversation content is not correctly passed using the `messages` parameter format, causing the session context to fail to recognize user input.
- Phenomenon: Custom dialogue interface interaction is laggy, and response delay exceeds expectations. Cause: No reasonable context window upper limit is set, causing all historical file data to be loaded with each conversation.
- Phenomenon: Approval suggestions returned by the model do not match civil aviation exclusive terminology. Cause: Prompt engineering does not bind exclusive fields and processes for airport declarations, and does not inject scenario-based constraint parameters into `variables`.

## How to confirm configurations are set correctly
- One initiates a simulated declaration conversation, enters a known declaration number, and verifies that the returned content only includes file information corresponding to that number.
- One checks that the `chatId` parameter updates with each declaration task, ensuring that session contexts for different batches do not overlap.
- One reviews the `messages` field in the response record to confirm that user input content has been correctly identified and recorded.
- One adjusts the prompt template and initiates a test, verifying that the returned results include exclusive units and terminology for civil aviation airport declarations.
