# Civil Aviation Airport Declaration Materials and Case Review: Citation Sources and Traceability
## What the data for this category looks like
Data sources for civil aviation airport declaration materials and case review include flight guarantee declaration forms submitted by the airport operation command center, approved cases filed with civil aviation regulatory authorities, and safety assessment reports from various support departments.
Data updates are synchronized in real time upon completion of a single approval process. Archived historical cases are imported into the knowledge base in quarterly batches.
The document structure has two parts: structured metadata and unstructured attachments. Metadata fields include declaration number, airport three-letter code, associated flight number, submitting department, and approval node.
Unstructured attachments are mostly PDF format scans or electronic documents. The basic statistical units are individual declaration items and case numbers.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Link
The high proportion of structured metadata requires the traceability link to accurately match fields such as declaration number and flight number, to avoid matching irrelevant cases.
The structure where unstructured attachments are bound to metadata requires the traceability result to return both metadata and the access path of the corresponding attachment, to ensure reviewers can fully verify the original materials.
Real-time updated approval data requires the knowledge base synchronization frequency to align with the airport’s approval process cycle, to prevent referencing expired approval status data.
Quarterly archived historical cases require the traceability system to distinguish between online active data and archived cold data, to avoid confusing case versions from different periods.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | The length of a single civil aviation airport declaration material is mostly 500–1000 characters. This value can cover the citation content of a complete single material, avoiding truncation of key approval opinions |
| `responseData` | Include metadata and attachment paths | Airport declaration data includes structured metadata and unstructured attachments. Complete associated information must be returned for reviewer traceability |
| `detail` | Enabled | Specific details such as approval nodes and submitting departments of referenced materials must be returned to meet the traceability requirements of case review |
| Citation source display limit | Top 6 entries | A single batch of declarations involves up to 5 associated materials. This value can cover all associated sources, avoiding missing key basis |
| Knowledge base synchronization cycle | 15 minutes | Aligns with the real-time requirements of the airport’s approval process, ensuring referenced data matches the latest approval status |

This configuration guide applies to FastGPT v4.17.0.

## Three Common Misconfigurations
- The number of citation sources returned in Q&A is insufficient, only showing 2 entries. Cause: The `quoteMaxToken` value is set too small, which cannot carry the metadata and attachment information of multiple associated materials. The system automatically truncates sources exceeding the limit.
- Referenced attachments cannot be downloaded normally. Cause: The attachment path return configuration in `responseData` is not enabled, or the knowledge base synchronization does not associate the complete path of the attachment storage, resulting in reviewers being unable to obtain the original materials.
- Traceability results match expired approval status. Cause: The knowledge base synchronization cycle is set too long, which does not match the real-time update rhythm of the airport’s approval process, and outdated unupdated data is referenced.

## How to Verify Proper Configuration
- A reviewer initiates a test query targeting a specific declaration number, and checks whether the returned result includes the metadata and attachment path of the corresponding declaration form.
- After adjusting the `quoteMaxToken` value, a reviewer observes whether the number of returned citation sources matches the expected number of associated materials.
- A reviewer manually updates the approval status of a test declaration data, waits for the knowledge base synchronization, and checks whether the referenced result displays the latest status.
- A tester conducts an API call, and confirms that the returned related fields include complete citation source information.

The values provided are common starting points and should be measured against the user’s own samples.
