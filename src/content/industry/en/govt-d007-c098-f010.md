# Civil Aviation Airport Declaration Materials and File Review: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data sources for civil aviation airport declaration materials and file review include standardized declaration templates from airport operations management departments, air traffic control approval files, security inspection declaration forms, and flight support filing documents. Update cycles adjust based on new civil aviation policies, temporary control notices, or quarterly standard revisions. There is no fixed cycle, but knowledge base synchronization must complete within 24 hours after policy release. Documents mostly consist of structured forms paired with long-text support instructions. Fields include declaration number, flight number, takeoff and landing time, support requirements, and review node records. Units use civil aviation standard measurements for time, flight sorties, and tonnage.

## What constraints these characteristics impose on knowledge base retrieval and recall
The mixed document structure of structured forms and long text requires retrieval to balance precise field keyword matching and long-text semantic recall. Do not split content that would break support logic. The uniqueness of civil aviation fields such as declaration number and flight number requires pre-filtering unique identifiers during retrieval. Prevent confusion across flight results. Temporarily updated policy documents require the knowledge base incremental sync cycle to align with the tempo of temporary notice releases. Avoid recalling outdated content. The paragraph length of long-text support plans requires chunking to fit the chapter structure of civil aviation documents. Prevent truncation of key support information.

## Configuration settings
These configurations are based on the interface and parameter logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | 0.72–0.80 | Adapts to the keyword density and semantic matching accuracy of civil aviation declaration materials, avoids recalling irrelevant cross-flight files |
| `limit` | Top 8 entries | Matches the number of associated review files for a single flight declaration material, prevents context overload that reduces review efficiency |
| `searchMode` | hybrid | Combines keyword matching and semantic recall, adapts to mixed retrieval scenarios for structured fields and long-text support requirements |
| `usingReRank` | Enabled | Reorders recall results by the review priority of civil aviation files, prioritizes returning associated declaration materials for the current flight |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically adds synonymous extensions for civil aviation common terms such as "takeoff and landing time" and "support filing", improves recall rates for niche fields |
| `collectionIds` | Bind to the airport-specific declaration file library ID | Limits retrieval scope to only the current airport’s declaration materials and files, avoids interference from cross-airport data |

## Three common mistakes
- Associated civil aviation PDF files in retrieval results cannot be opened directly within the platform. This occurs because a file parsing plugin adapted to civil aviation-specific encrypted formats is not configured. Some declaration files with airline watermarks or encryption cannot be parsed normally.
- A single retrieval returns more than 10 irrelevant cross-flight files. This occurs because the `limit` parameter is set too high, or the `similarity` threshold is below 0.7, leading to insufficient semantic matching accuracy.
- Recall results include expired temporary control notices. This occurs because the knowledge base incremental sync task is not adjusted to the update frequency of civil aviation temporary policies, and expired file data is not cleaned in a timely manner.

## How to confirm configurations are correctly set
- Upload a test airport declaration PDF, initiate a retrieval, and check if the file links in the returned results can be previewed directly within the platform.
- Enter a query statement containing a specific flight number, confirm that the returned results only include associated files for that flight, with no cross-flight data included.
- Adjust the `similarity` parameter to 0.75, initiate the same retrieval again, compare the changes in the number of recalled entries and relevance to confirm the parameter takes effect.
- After enabling `usingReRank`, check if the order of returned results prioritizes matching the current query’s flight review node.

The values provided here are common starting points, and should be measured against the reader's own samples.
