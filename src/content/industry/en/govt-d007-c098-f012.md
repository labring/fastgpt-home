# Civil Aviation Airport Declaration Materials and File Review: Deployment and Upgrade

## What the Data for This Category Looks Like
Civil aviation airport declaration materials and file review data mainly comes from the airport operation management system, air traffic control declaration platform, and internal audit ledger. Daily declaration data is updated per daily flight batch, while special files are updated per project cycle. Bulk declaration data influx occurs during spring and autumn seasonal transition periods. Declaration materials use a format of structured metadata paired with multiple attachments. Metadata includes fields such as application number, flight number, takeoff and landing time, application category, and applying unit. Files include audit nodes, rectification opinions, approval document numbers, attachment list, and other content. Attachments are sized in megabytes (MB), and application category is a fixed enumeration type.

## Constraints on Deployment and Upgrade
The large-volume multi-attachment nature of civil aviation declaration data requires storage configurations adapted to intranet object storage to ensure data security, while sufficient storage space must be reserved to handle bulk declaration scenarios. Structured fields and peak concurrent query requirements require database connection configurations to balance resource usage and response speed. Cache services must adapt to fast read and write operations for temporary data. Compliance requirements for civil aviation data require restricting intranet access and file access scope through permission control configurations. Offline deployment scenarios must also adapt to intranet-isolated environments to avoid deployment failures caused by public network dependencies.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent database queries during peak flight hours, balancing connection resource usage and query response speed |
| `MONGODB_URI` | Intranet MongoDB cluster read-write separation connection string | Stores structured data of civil aviation declaration files, ensuring data transfer within the intranet complies with security specifications |
| `REDIS_URL` | Intranet Redis instance address with RDB persistence | Caches temporary declaration batch data, reducing repeated database query pressure during peak hours |
| `FILE_TOKEN_KEY` | 32-bit randomly generated key | Generates temporary access credentials for declaration attachments, allowing only authorized users to access files associated with review dossiers |
| `STORAGE_S3_ENDPOINT` | Airport intranet object storage service address | Adapts to storage needs for large-volume declaration attachments, avoiding insufficient local disk space |
| `FE_DOMAIN` | Airport intranet second-level domain name | Restricts service access to only intranet users, complying with civil aviation information security management requirements |

## Three Common Misconfigurations
Reference only; verify against the target FastGPT release and deployment documentation.
- Symptom: After the Docker container starts, a 500 Internal Server Error is returned when accessing via `curl`. Cause: The intranet address configured for `REDIS_URL` or `MONGODB_URI` cannot be connected, or the configuration parameters have format errors, preventing the service from initializing core dependencies.
- Symptom: Unable to load declaration dossier data exceeding the threshold after offline deployment. Cause: Offline deployment resource limits are not adjusted based on the actual total amount of airport declaration documents, or the local attachment storage directory is not correctly mounted, resulting in file reading failure.

- Upload a standard civil aviation declaration attachment, check whether it can be stored normally and that access verification can be completed using the generated temporary link.
- Simulate concurrent submission of declaration queries by multiple users, check whether the service response status is stable and free of abnormalities.
