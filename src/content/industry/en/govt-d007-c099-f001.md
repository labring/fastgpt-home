# Declaration Materials and File Review for Oil and Gas Exploration and Development: HTTP Interfaces and External Systems

FastGPT v4.17.0 supports interface configuration and business deployment for this scenario.

## What this category’s data looks like
Declaration materials and file review data for oil and gas exploration and development mainly comes from on-site exploration collection systems, drilling engineering databases, and reserve review archives. A single file includes exploration well ID, logging depth, core sample data, oil and gas reserve estimates, approval process node records, and other content. Updates are made in real time as single-well operations are completed. Batch archiving is performed when the project is finalized. Most data fields include physical units: logging depth is measured in meters, oil and gas reserve estimates are measured in ten thousand tons, and documents often include high-definition core scans or structured geological report attachments.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Multiple heterogeneous data sources require interfaces to support cross-system data pulling and multi-format adaptation, and compatibility with authentication rules of different business systems. The mixed real-time and batch update rhythm requires interfaces to support both single small-batch requests and batch task submission modes. Complex document structures and unit-attached fields require interface-level validation of field formats and unit consistency to prevent data transfer errors. Attached large-volume attachments require interfaces to support segmented upload and large-file transfer configurations to meet the storage needs of oil and gas exploration data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Authentication Method | Bearer Token authentication with `Authorization` header | Complies with internal security access specifications of oil and gas exploration systems, and protects interface call permissions |
| Request Timeout | 600 seconds | Adapts to the full processing cycle of a single file’s data, and prevents request interruptions caused by large data volumes |
| Single File Upload Limit | 1000 MB | Matches the common size range of attachments such as core scans and high-definition geological reports |
| Response Data Extraction Configuration | Extract core file data from the `responseData` field | Accurately obtains review result information required for business, and avoids redundant data transfer |
| Variable Mapping Configuration | Map the `variables` field returned by the interface to file approval status | Aligns interface data with fields of external approval systems |
| Cross-origin Whitelist Configuration | Add the domain name of the oil and gas exploration front-end business system | Allows specified business domain names to initiate cross-origin requests |

## Three common errors
- Phenomenon: A cross-origin intercept is triggered when calling the interface using the fetch API, and a CORS-related error is displayed in the console. Cause: The front-end domain name of the oil and gas exploration business system was not added to the cross-origin whitelist configuration, causing the request to be blocked by the browser.
- Phenomenon: A 400 error is returned when the uploaded file name exceeds 200 characters. Cause: The interface does not perform length verification or escape processing on uploaded file names, exceeding the character limit of operating system file paths.
- Phenomenon: The `responseData` field returned after calling the interface is empty, and file review results cannot be obtained. Cause: The response data extraction rule was not configured correctly, and no association was made with the core business fields of oil and gas exploration files.

## How to confirm configurations are correctly set
- A test request with the `Authorization` header is sent, and the response header is checked to confirm it contains the correct cross-origin allow header.
- Test files of different lengths are uploaded, and submissions are verified to be normal when the file name is within a reasonable range, with a clear error prompt returned when the limit is exceeded.
- The interface is called and the `responseData` field is viewed, confirming it contains oil and gas exploration-specific fields such as exploration well ID and logging depth.
- A callback address is configured, a file review process is triggered, and confirmation is made that the external system can receive the correct callback notification.

The values provided are common starting points and should be evaluated against the reader’s own samples.
