# Declaration Materials and File Review for Oil and Gas Exploration and Development: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes primarily from original documents such as drilling logs, reserve assessment reports, and administrative approval files generated during exploration operations. Updates follow exploration project milestones or annual reserve review cycles.
Each individual document includes geological parameters such as exploration block number, well ID, porosity, and permeability. It also includes process fields including declaration batch, review status, and approval opinions. Parameter units follow oil and petrochemical industry standards. Individual document lengths vary widely, with some special files reaching tens of thousands of characters.

## What constraints these characteristics impose on tool calling and plugins
Specialized units and field requirements for geological parameters require tool calling to include built-in industry standard parameter validation logic. This avoids review result deviations caused by unit mismatches.
The wide variation in document length requires plugins to support batch fetching of long text data. This prevents exceeding context limits in single calls.
Data sources are scattered across operation systems and approval files. Tool calling must adapt to multi-source data interface integration, and comply with state-owned enterprise internal data permission rules. Only authorized roles may trigger corresponding tools.
Additionally, the requirement for unique document versions means tools must validate the latest version identifier. This avoids calling expired data.

## Configuration Settings
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` or bound to the "Oil and Gas File Review" dedicated function | Supports automatic matching of tools required for review scenarios, or fixed calls to preset industry-specific tool functions |
| `functionCall` | `strict: true` | Forces the model to only call specified tools, avoids generating irrelevant content, and meets the strict requirements of oil and gas review |
| Tool call timeout | `300–600 seconds` | Oil and gas declaration materials typically include multiple long documents. Full fetching and validation require extended time, and this interval covers most conventional scenarios |
| Single call document count | First 3–5 | Avoids excessive data volume in single calls that causes interface exceptions, while ensuring sufficient file samples for review |
| Parameter validation switch | Enabled | Oil and gas industry parameters have fixed units and value ranges. Enabling validation intercepts incorrect data early |

## Three Common Errors
- Tool calling returns a 413 status code, with an interface prompt that the request body exceeds limits. Cause: Too many oil and gas file documents are fetched in a single call, or the length of a single declaration material exceeds the maximum request body size allowed by the interface.
- When using the qwen3 model, the model still generates non-tool-calling reasoning content after tool calling, and cannot restrict the model to only use tool calling mode. Cause: The strict mode of `functionCall` is not configured correctly, and the model's default reasoning priority is higher than the tool calling trigger rule.
- Intermediate steps of tool calling are directly displayed in the final review result without hiding. Cause: The tool calling process hiding configuration item is not enabled, or the configuration item value does not meet the scene requirements.

## How to Confirm Configuration is Correct
- Trigger a test review, check if the tool calling return result includes validation information for oil and gas-specific parameters, confirm that the parameter validation switch is active.
- Submit a declaration material that exceeds conventional length, check if tool calling triggers an exception, confirm that the timeout configuration matches the document processing needs of the current scenario.
- Switch to the qwen3 model for testing, confirm that tool calling only generates required function call instructions with no extra reasoning content, confirm that the tool calling mode configuration is active.
- Check the tool calling log records, confirm that the number of documents fetched in a single call matches the preset scene requirements, confirm that the call count configuration is active.

The values provided are common starting points and should be measured against the reader's own samples.
