# Declaration Materials and File Review for Oil and Gas Exploration and Development: Citation Sources and Traceability

## What this category of data looks like
Data for oil and gas exploration and development declaration materials and file review comes from exploration design reports, drilling construction records, reserve assessment files, and administrative approval application materials. The update rhythm follows project milestones, and the update cycle for single approval files varies widely. Document structures include fixed fields such as well number, exploration block coordinates, reserve calculation values, and approval level markings. Units cover professional measurement identifiers including meters, cubic meters, tons, and square kilometers. The text length of a single file ranges from thousands to tens of thousands of characters.

## What constraints do these characteristics impose on the citation sources and traceability link
The presence of professional fields and fixed units requires precise matching of corresponding field content during traceability to avoid traceability deviations caused by generalized matching. The large text span of single files will lengthen context window usage, so the character length of single traceability citations must be limited. The non-fixed update rhythm following project milestones requires the traceability link to support on-demand knowledge base synchronization, instead of using fixed-cycle synchronization. The multi-level approval associated file structure requires traceability to the original materials of the associated approval link, not limited to the single document currently submitted.

## Configuration Settings

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | The core professional content of oil and gas exploration and development declaration files mostly falls within this token range, adapting to long professional paragraphs |
| `responseData` | Enabled | Full field content of the original files must be returned to meet the needs of original data verification during traceability |
| `detail` | Enabled | The storage path and approval node information of the original materials must be displayed to clarify the traceability chain |
| Single search limit | Top 6 entries | There are many associated files for oil and gas exploration declaration, and the top 6 entries can cover core associated approval materials |
| Chunk length | 1500–2000 characters | Adapts to the professional paragraph length of single files, avoiding damage to field integrity by chunking |
| Knowledge base synchronization trigger method | Triggered by project milestone | Data updates follow the approval milestones of exploration projects, adapting to non-fixed update rhythms |

## Three Common Misconfigurations
- Phenomenon: If the value of `quoteMaxToken` is set too small, context insufficient errors will occur during responses, or the returned traceability content will be truncated. Cause: The professional content of oil and gas exploration files is relatively long, and an overly small token limit cannot fully carry core traceability information.
- Phenomenon: Knowledge base synchronization is set to fixed-cycle triggering, but synchronization is not triggered after project milestone updates, resulting in responses referencing outdated versions of file content. Cause: General fixed synchronization logic is used without adapting to the non-fixed update characteristics of oil and gas exploration data.
- Phenomenon: Knowledge base recall is configured in the workflow, but the final response does not associate recall results and only generates generic content. Cause: The `responseData` configuration item is not enabled, so the recalled original data is not included in the context window.

## How to Verify Proper Configuration
- Upload a test oil and gas exploration declaration file, check whether the fixed field information of the file is included in the knowledge base recall results.
- Initiate an audit query, check whether the associated traceability information of the original materials is displayed in the response.
- Adjust the value of `quoteMaxToken`, verify whether the length of the traceability content in the response changes with the configuration.
- Simulate a project milestone update, trigger knowledge base synchronization, verify whether the recall results include updated file content.

The values listed above are common starting points and should be evaluated against the reader's own samples.
