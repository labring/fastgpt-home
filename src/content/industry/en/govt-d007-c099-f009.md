# Declaration Materials and File Review for Oil and Gas Exploration and Development: Model Access and Configuration

## What this type of data looks like
Data for oil and gas exploration and development declaration materials and file reviews mainly comes from drilling logs of exploration projects, reserve assessment reports, environmental impact assessment approval documents, and well site survey data. The data update rhythm is adjusted according to project progress. Finalized updates are completed within a single declaration cycle, and no mandatory updates are required outside declaration periods. Most documents are multi-page PDFs, containing structured fields such as project number, well ID, exploration area coordinates, plus unstructured technical descriptions and chart attachments. Field units include meters (well depth), square kilometers (exploration area), ten thousand tons of oil equivalent (reserve estimates) and other industry standard units.

## What constraints do these characteristics impose on the model access and configuration step
The multi-page long document structure of oil and gas exploration and development declaration materials requires model access configuration to support long context processing, and avoid truncation of critical technical content. The mixed content format of structured fields and unstructured technical descriptions requires configuration to support simultaneous recognition of numerical units and professional terminology. The phased update rhythm of project-level data requires access configuration to support dynamic data source synchronization, and adapt to temporary modifications before declaration. Differences in file formats across different declaration stages require configuration to be compatible with multiple document import formats, and avoid format parsing failures. The requirement for accuracy of professional terminology and standard units requires configuring industry terminology matching rules for the model, to ensure audit results meet compliance requirements.

## How to set the configuration
The following configuration items are customized for the oil and gas exploration and development declaration audit scenario, based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Oil and gas exploration declaration materials are mostly multi-page long documents, which need to cover the full context of the entire file to avoid truncation of critical information |
| `maxTokens` | `2000–3000 token` | A single audit result needs to include complete compliance judgments and core detail descriptions, to meet the output requirements of audit reports |
| `quoteMaxToken` | `1500–2000 token` | Key quoted content such as reserves and well depth in declaration materials must be retained, to ensure the integrity of audit basis |
| `temperature` | `0.1–0.3` | Declaration materials and file review need to strictly match compliance standards; lower temperature values reduce subjective judgment deviations |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated access address according to the deployment environment | Adapt to local or cloud API access paths, to ensure connectivity for model calls |
| `AIPROXY_API_TOKEN` | Dedicated key generated according to authorization documents | Ensure the security of model access permissions, and avoid unauthorized access |

## Three common configuration mistakes
- Phenomenon: Inconsistent audit results returned by the model in the chat interface and workspace. Cause: Global model parameters and application-level model parameters are not unified, resulting in different model versions or parameter configurations being called in different scenarios.
- Phenomenon: `failed to get gpt-3.5-turbo token encoder` error occurs when accessing via a third-party proxy service. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not configured correctly, or the proxy service has not synchronized model permissions normally.
- Phenomenon: Long declaration materials are truncated after import, and complete review cannot be completed. Cause: The `maxContext` parameter value is too low, failing to cover the context length of the entire file.

## How to verify a successful configuration
- Upload a single typical oil and gas exploration declaration file, verify whether the imported document content is complete and not truncated, and adjust the corresponding context parameters based on the results.
- Initiate a single audit request, check whether the returned result includes compliance judgments for all key fields, and adjust the parameter configuration as needed.
- Test the access effect after dynamically updating the data source, confirm that the configuration supports synchronizing the latest declaration material content, and verify the validity of the access path.
- Initiate the same audit request in both the chat interface and workspace, confirm that the two returned results are consistent, and check the uniformity of global and application-level parameters.
