# Declaration Materials and File Review for Oilfield Engineering Services: HTTP Interfaces and External Systems

## What this category of data looks like
Declaration materials and file review data for oilfield engineering services mainly come from the internal oilfield engineering approval system, on-site construction record archive library, and enterprise qualification management platform. The data update rhythm follows the declaration cycle of individual projects, and updates are made according to material submission nodes during a single declaration cycle. Document structures are mostly combinations of multiple attachments, including construction plan PDFs, scanned qualification certificates, on-site visa forms, budget detail spreadsheets, and more. Core fields include project number, construction area code, qualification validity period, material submission date, and file review status. Most field formats are strings, date types, and enumeration values. There are no complex nested levels, but individual file sizes are generally large.

## What constraints these characteristics impose on HTTP interfaces and external systems
Declaration materials for oilfield engineering services are mostly large files. This requires interfaces to support multi-file upload and high-volume data transmission, and set relatively high timeout thresholds. Standardized transmission of multiple fields requires interface parameters to cover core business fields such as project identifiers and material types, to avoid parsing failures caused by missing fields. Data updates follow project cycles, so interface call frequency must match project declaration rhythms to avoid triggering external system current limiting rules due to excessive calls. Field parsing for file review status must accurately match the return format of oilfield systems. Specify the target extraction field via `responseData` to avoid redundant data interfering with subsequent processing.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {Oilfield System API Key}` | Matches the authentication rules of external systems for oilfield engineering services |
| `variables` | Pass in project ID, material type code, collection ID | Associate files with corresponding declaration files to enable precise queries |
| `responseData` | Extract review status, correction list, file-id | Focus on core business fields and filter redundant return content |
| Total file size per single request | No more than 1000 MB | Adapt to the conventional single package limit of oilfield engineering files |
| Interface timeout | 600 seconds | Cover the return time required for large file uploads and complex review data |
| Request frequency limit | No more than 3 times per 10 seconds | Comply with concurrent call constraints of oilfield systems |

## Three Common Mistakes
- Phenomenon: The expected file-id field is not returned in `responseData` after calling the interface. Cause: The collection ID parameter for the file was not passed in `variables`, so the association between the file and the declaration file cannot be established.
- Phenomenon: The interface call returns a 429 status code. Cause: The request frequency exceeds the concurrent limit of the oilfield system, and calls were not initiated according to the configured frequency threshold.
- Phenomenon: The review result field is missing from the interface return. Cause: The required extraction business fields were not specified in `responseData`, and only the default general return content was returned.

## How to confirm the configuration is correct
- Call the configured test interface, pass in a known valid project ID and a legal test file, and check if the expected file-id field is included in `responseData`.
- Upload a test file with a single size not exceeding the configured threshold, and confirm that no timeout error occurs in the interface.
- Initiate multiple requests at the configured frequency interval, and confirm that no 429 status code is returned.
- Check the configuration format of the `Authorization` header, and confirm that it meets the authentication requirements of the oilfield system.
