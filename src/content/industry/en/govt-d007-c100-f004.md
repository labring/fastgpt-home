# Declaration Materials and File Review for Oilfield Engineering Services: Workflow Orchestration

## What Data for This Category Looks Like
Oilfield engineering services declaration materials and file data mainly come from three sources: on-site construction records, qualification approval documents, and project acceptance forms. The data updates alongside the construction progress of individual projects, with 3 to 5 updates during a single project cycle. The structure of a single file document includes modules such as construction plans, safety disclosure records, wellsite operation logs, and acceptance forms. Core fields include operation well number, construction duration (unit: hours), qualification certificate number, and name of the party A's docking unit. Some documents include multi-page scanned materials and structured tables.

## What Constraints These Characteristics Impose on Workflow Orchestration
The total character count of a single file varies widely. Some files containing multi-page scanned transcript content may exceed general AI input limits. This requires the workflow to support context truncation or chunked processing. Core fields have dedicated units and fixed formats. Variable extraction must match specific rules such as well numbers and operation durations, to avoid field errors caused by generic extraction. File update frequency fluctuates with project progress. The workflow must adapt to dynamically triggered document pulling logic, while ensuring associated documents in the knowledge base sync with the current project progress. Additionally, combined review of multi-module documents requires the workflow to support serial invocation of multiple nodes, to avoid timeouts caused by processing too much content in a single pass.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Maximum Context Length | 8000–12000 characters | Adapts to the average character length of a single oilfield engineering file, avoiding exceeding the model's input limit |
| Business Field Extraction Rule | Match well number and operation duration format | Accurately extract core business fields from oilfield engineering declaration materials, adapting to subsequent review logic |
| Single Search Limit | Top 8 entries | Covers core associated construction records for the same project, avoiding redundant data interfering with review |
| Node Timeout Duration | 300 seconds | Adapts to the operation duration of batch retrieval of historical files, avoiding premature interruption |
| Variable Reference Configuration | Bind `variables` parameter | Dynamically pass extracted business fields, adapting to personalized review requirements for different projects |
| User Interaction Node Configuration | Bind `nodeId` | Implement workflow submission triggered by in-session buttons, matching user interaction needs |

This configuration applies to FastGPT v4.17.0.

## Three Common Misconfigurations
- An error "context exceeds model limit" occurs, and no valid review results are returned. The cause is that maximum context length filtering is not configured, and the entire file is directly passed to the AI chat node.
- Knowledge base search returns no results or incorrect matches. The cause is that the project well number is not bound as a variable to the knowledge base search, resulting in the search scope not being limited to the current operation project.
- No submit button appears in the session, or the workflow does not proceed after clicking the button. The cause is that the `nodeId` parameter is not correctly bound in the user interaction node, causing the button to fail to associate with the specified submission node.

## How to Confirm the Configuration Is Correct
- Upload a typical oilfield engineering declaration file with multi-page content, check whether the workflow automatically truncates overly long contexts or pops up an input limit interception prompt.
- Manually enter test operation well numbers and construction durations, confirm that the `variables` parameter can correctly extract and pass to subsequent nodes.
- Trigger the workflow process, check whether the preset submit button appears in the session interface, and confirm that the workflow proceeds normally to the next review node after clicking the button.
- Simulate batch retrieval of 3 or more associated files, confirm that the node timeout duration setting is sufficient to support the operation, and no premature interruption occurs.
