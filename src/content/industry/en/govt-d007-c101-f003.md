# Port and Shipping Declaration Materials and File Review: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Port and shipping declaration materials and file review data primarily comes from port operation management systems, maritime declaration platforms, and offline document scans submitted by ship agents. Data updates are triggered by individual declaration batches. Materials involved in a single review are synced to the platform immediately after declaration submission.
Individual declaration document fields include ship name, voyage number, cargo category, container count, declaration number, and other standard fields. File documents additionally include inspection records, penalty basis, rectification requirements, and other content. Most field units use shipping-specific units such as TEU, ton, meter, and others.

## What These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering Workflows
Professional fields and unit requirements for port shipping declaration materials require multi-turn dialogue to strictly bind to the current review’s file data, to avoid field confusion.
File data volume for multi-batch reviews is large. Limit the length and turn count of the `messages` context to prevent context overflow that causes dialogue interruptions.
Most declaration materials are PDF or XML format attachments. Complete attachment parsing and field extraction before starting dialogue. Therefore, trigger multi-turn dialogue only after attachment upload.
Declaration data from different sources has varying formats. Use `variables` configuration to set unified field mapping rules, to ensure consistency across dialogue links.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum dialogue turns | First 20 turns | Single-batch review dialogue rounds for port declaration files typically do not exceed 15 turns, with reasonable redundancy reserved |
| `messages` context length limit | 8000–12000 characters | Text length of a single declaration material is typically under 5000 characters, to avoid context overflow |
| `variables` field binding rules | Bind ship name, voyage number, declaration number variables | Ensure multi-turn dialogue always links to core data of the current review file |
| Attachment upload format limit | Only allow PDF and XML format files | Match standard submission formats for port declaration materials |
| `chatId` session persistence setting | Enable session persistence, retain for 7 days | File review typically spans multiple time periods, retaining sessions facilitates review progress tracking |
| Single dialogue response time | 600 seconds | Complex file review requires significant field verification and data comparison time, to avoid timeout errors |

This configuration is developed based on FastGPT v4.17.0.

## Three Common Misconfigurations
-  Prompt configuration placed in non-system prompt positions, causing model responses to deviate from review requirements. The symptom is that model output does not strictly follow declaration material verification rules. The cause is that the prompt is not loaded into the dialogue’s system context link.
-  `chatId` session persistence not enabled, causing inability to retrieve dialogue records after session interruption. The symptom is that historical dialogue content is lost after page refresh. The cause is that session persistence parameters are not configured.
-  Attachment upload format not restricted, causing non-standard port declaration files to fail parsing. The symptom is that the system returns parsing failure prompts after uploading attachments. The cause is that uploads are not limited to only PDF and XML format declaration materials.

## How to Confirm Correct Configuration
-  Launch a simulated declaration dialogue, input the field keywords bound by `variables`, confirm that the dialogue automatically associates corresponding information.
-  Send a declaration text exceeding 5000 characters, confirm that no context overflow error appears in the dialogue.
-  Upload a standard PDF format manifest file, confirm that the system normally parses and extracts relevant fields.
-  Interrupt the session and re-enter, confirm that historical dialogue content is still visible.
