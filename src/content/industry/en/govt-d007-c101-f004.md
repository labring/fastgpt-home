# Port and Shipping Declaration Document and File Review: Workflow Orchestration

## What This Category of Data Looks Like
Data for port and shipping declaration document and file review mainly comes from port operation management systems, maritime online declaration platforms, and container manifest systems. Data is generated in real time per single declaration. Each entry corresponds to a ship berthing or cargo import and export declaration process. The document structure includes two parts: structured fields and attachments. Structured fields include ship name, voyage number, bill of lading number, declaration number, cargo category, and loaded tonnage (unit: ton or standard container TEU). Attachments are mostly compliant files such as manifest scans, quarantine certificates, and customs declarations.

## What Constraints These Characteristics Impose on Workflow Orchestration
The real-time generation per single declaration feature requires the workflow to support single-instance triggering for each execution. Batch scheduling modes are not suitable. The requirement for multiple fields and specific units means the workflow needs precise variable mapping rules to ensure fields passed between nodes match the output format of port systems. Diverse attachment formats that require archiving mean the workflow must add format verification nodes to block non-compliant attachments. File review requires traceable records, so each node's execution status in the workflow must be written to associated variables for subsequent file archiving and querying. Dependence on cross-system interface calls means the workflow needs reasonable timeout and retry mechanisms to handle occasional system fluctuations.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `variables` | Map ship name, voyage number, bill of lading number, declarant name to fixed key names | Match the field output format of the port declaration system to ensure correct cross-node parameter passing |
| Node timeout period | 600–900 seconds | Port declaration review involves multiple system interface calls, single link takes relatively long time |
| Form validation rules | Enforce validation of bill of lading number format, cargo tonnage unit must be ton or TEU | Match the statutory field requirements for port and shipping declarations |
| `nodeId` branch triggering | Configure multi-branch access permissions based on preceding node IDs | Enable cross-link reuse of configured nodes, support multiple review scenarios calling the same node |
| Attachment format restrictions | Only allow PDF, JPEG, PNG format attachments | Adapt to archiving and parsing standards for file records |
| Node retry count | 2–3 times | Handle occasional fluctuations in port system interfaces, avoid process interruption caused by single call failure |

## Three Common Mistakes
- Symptom: When a workflow branch attempts to connect to a configured form review node, the execution status shows "Node unavailable". Cause: Multi-branch triggering permissions are not configured via `nodeId`, default nodes only support single-link binding.
- Symptom: API calls to the workflow return only the user ID, with no declarant name field. Cause: The declarant name mapping configuration is not added to `variables`, only the default user ID variable is called.
- Symptom: The login-free generated chat interface shows a default avatar and cannot be customized. Cause: No avatar mapping rule for login-free users is configured in the workflow, and no avatar field from corresponding `variables` is bound.

## How to Confirm the Configuration Is Correct
- Trigger test data for a single-port declaration, check if the fields in `variables` in the workflow correctly map core information such as ship name and bill of lading number.
- Call the API to trigger the workflow, verify that the returned results include the declarant name field with no null values.
- Configure multi-branch links, test whether different branches can correctly connect to existing form review nodes with normal execution status.
- Upload attachments in non-compliant formats, check if the workflow triggers a format verification error and blocks abnormal input.
