# Port Shipping Declaration Material and File Review: Source Citation and Traceability

## What this category of data looks like
Data for port shipping declaration materials and case files originates from port operation management systems, customs clearance declaration systems, and vessel dynamic reporting platforms. Data is updated either per single voyage or in daily batches. Each individual case file contains fields including vessel identification code, cargo load volume, declaration number, inspection receipt, and manifest details. Field units include deadweight tons, standard containers (TEU), and voyage numbers. Dates use China Standard Time (UTC+8). Most documents combine structured tables and unstructured attachments. This scenario’s configuration is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on source citation and traceability
Cross-system sourced declaration materials need a unique voyage-level association identifier to prevent citation confusion between different voyage case files. Batch-updated data must be linked to voyage ID as a traceability anchor, ensuring recalled citation content only belongs to the current review batch. The mixed structure of structured fields and unstructured attachments requires the traceability process to support both precise matching of structured fields and recall of text fragments from attachments. Fields with specific units must automatically validate unit consistency during traceability, to prevent incorrect citation of deadweight ton or container quantity data.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the text length of individual port case files to avoid truncation of key review information |
| `responseData` | Return only associated case file IDs and citation snippets | Reduces output redundancy and focuses on traceability content required for declaration review |
| `detail` | Enable full field traceability | Ensures recalled content includes core review fields such as vessel identification code and cargo details |
| Chunk length | 1000–1500 characters | Matches the paragraph structure of port declaration materials to improve recall accuracy |
| Single search limit | Top 6 results | Covers the number of common citation sources for a single case file to avoid excessive redundant results |

## Three common configuration errors
- Output includes forged citation IDs not associated with the current voyage. This occurs because voyage ID is not bound as a traceability anchor, leading to incorrect association of cross-batch case file data.
- Generated results retain the phrase "Citation Marker: [1]". This occurs because the rule to return only associated data via `responseData` is not configured, leaving the system’s built-in marker format intact.
- Recalled citation content includes case file information from a different review voyage. This occurs because recall results are not filtered by voyage ID, leading to cross-batch data confusion.

## How to confirm correct configuration
- Import a single port voyage case file, trigger the review process, and check if the output citation content only associates with the current voyage’s ID and corresponding fields.
- Review the output content to confirm that no system-built "citation marker" style phrases appear, and only associated case file snippets and IDs are retained.
- Adjust the `quoteMaxToken` parameter value, and verify that the length of the output citation snippets matches the set range.
- Import two case files from different voyages, trigger review for each, and confirm that recalled citation content does not mix across voyages.

The values provided are common starting points and should be measured against the reader's own samples.
