# Port and Shipping Declaration Material and File Audit: Deployment and Upgrade

## What this category of data looks like
Port and shipping declaration material and file audit data primarily comes from port operation systems, vessel declaration platforms, customs declaration ports, and container ledgers. Data is updated in batches per vessel voyage or daily. Each file typically includes structured declaration fields and attached documents. Structured fields include vessel name, voyage number, bill of lading number, declared cargo weight, container count, and more, with units corresponding to tons, TEU, voyage numbers, and others. Most attachments are PDF-format manifests, quarantine certificates, and similar documents.

## What constraints these characteristics impose on deployment and upgrade
The multi-source, batched update nature of port shipping declaration materials requires deploying task scheduling configurations for bulk data synchronization to prevent excessive single-sync load. Each file includes structured fields and multi-format attachments, so a parsing pipeline compatible with PDFs and manifest scans must be configured during deployment to ensure correct extraction of unstructured content. The data volume of files varies widely across voyages, so dynamically adjustable resource thresholds must be reserved during upgrades to prevent response delays during peak periods. Additionally, the standardization requirement for structured fields requires binding fixed field mapping rules in knowledge base configuration to avoid data parsing confusion. FastGPT v4.17.0 supports the bulk data processing logic for this scenario, reducing deployment adaptation costs.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | Adapts to the storage needs of multi-source structured port files, supports fast read/write of bulk voyage data |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches frequently accessed voyage declaration data to reduce high-frequency read/write load on the database |
| `STORAGE_S3_ENDPOINT` | `http://s3-port-ship:9000` | Stores PDF attachments and scanned copies of port files, adapts to bulk file upload and download requirements |
| `DB_MAX_LINK` | `200–300` | Adapts to concurrent connections for dozens of voyage files per batch, avoids service freezes caused by exhausted connection pools |
| `FE_DOMAIN` | `https://port-audit.xxx.com` | Configures the valid domain for frontend embedding, supports page integration with existing port business systems |
| `ROOT_KEY` | Determined through actual testing | Permission verification key for the admin backend, must match the security policy of the private deployment environment |

## Three Common Mistakes
- Phenomenon: Slow workflow response when deploying locally on an 8-core 32GB machine. Cause: Failure to adjust `DB_MAX_LINK` and Redis cache configuration based on the data volume of port bulk files, leading to exhausted database connections or high-frequency read/write delays.
- Phenomenon: Unable to call AI services via port 3005 after modifying Docker configuration, while port 3000 operates normally. Cause: Incorrect configuration of the connection password for `REDIS_URL`, or failure to synchronize port mapping updates to Docker startup parameters.
- Phenomenon: Unable to directly use embedded pages when integrating with existing port systems, requiring custom frontend development. Cause: Failure to correctly configure `FE_DOMAIN` to the valid domain name of the port system, resulting in browser blocking of the frontend embedding function.

## How to Confirm Configuration is Correct
- Execute a bulk voyage file synchronization task, check the connection count on the database monitoring panel, confirm it does not exceed the `DB_MAX_LINK` configuration threshold.
- Upload a standard port PDF manifest, run a knowledge base parsing test, confirm that attachment content can be correctly extracted and associated with structured declaration fields.
- Call the API interface to test AI service response via port 3005, confirm that the returned results include keyword matching content for declaration materials.
- Access the frontend address configured in `FE_DOMAIN`, confirm that the embedded component loads normally and displays the file audit interface.

The values provided are common starting points and should be measured against the reader's own samples.
