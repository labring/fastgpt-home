# Declaration Materials and Case Review for Refinery and Chemical Production: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Declaration materials and case review data for refinery and chemical production mainly originate from business scenarios such as device startup declarations, material balance cases, and environmental compliance declarations. Data updates follow monthly declaration cycles or quarterly case archiving rhythms, and are updated in real time after a single declaration is submitted. Documents include two parts: structured metadata and attachments. Structured metadata includes fixed fields such as device ID, declaration batch, material type, and review node. The material flow unit is cubic meters per hour. Approval status enumeration values include to be submitted, preliminary review passed, to be corrected, and final review completed. Attachments are mostly in PDF or Excel format. The structured data volume of a single case is usually 500–2000 characters, and attachment size does not exceed 1000 MB.

## Constraints for HTTP Interfaces and External Systems
Fixed fields in structured metadata require interface request parameters to strictly match the preset structure. Field order or unnecessary new parameters cannot be adjusted arbitrarily. Attachment size limits require interfaces to support chunked uploads, to avoid transferring oversized files in a single request. Enumeration values of review status must be synchronized to external case management systems, so interface calls must carry valid permission tokens. Monthly batch declaration scenarios require interface call frequency to match the declaration cycle, to prevent overload. Data updates must be synchronized to external systems in real time, so interface callback trigger logic must be configured.

## Three Common Misconfigurations
- The Human field is null in response record previews. The cause is that interface request input parameters were not correctly passed through variables, causing the system to fail to recognize user input content.
- Streaming SSE requests cannot be displayed normally on the frontend. The cause is that the streaming output switch was not enabled in FastGPT configuration, or the interface did not correctly adapt to the SSE response format.
- ACCESS_TOKEN configuration error. The cause is that an APIKey from a third-party platform was mistakenly entered directly, and the exclusive permission token of the refinery and chemical production declaration system was not used.

## How to Verify Successful Configuration
- Call the test interface to check whether the returned responseData field includes core business data such as audit status and correction opinions.
- View interface logs to confirm that the Authorization token carried in the request was correctly verified by the system.
- Submit a simulated declaration material to check whether the variables parameter was correctly passed in the preset order.
- Enable streaming output testing to confirm that the frontend can gradually receive content returned by the interface.
