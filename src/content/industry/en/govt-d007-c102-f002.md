# Declaration Materials and Case Review for Refinery Production: Vector Models and Indexes

## What Data for This Category Looks Like
Declaration materials and case review data for refinery production comes from internal production management systems, archive management platforms, and compliance declaration systems. It covers unit feed slips, process parameter logs, safety inspection reports, environmental assessment declaration documents, maintenance case files, and other types. Maintenance case files include special documents such as hot work permits and equipment flaw detection reports.
Update rhythm adjusts based on project progress. Bulk updates apply to single special declarations. Daily cases are archived monthly.
Most documents are multi-page PDFs, with structured fields including unit number, feed volume, and inspection time. They also include scanned unstructured content. Single documents may be up to hundreds of pages long.

## Constraints for Vector Models and Indexes
Multi-page long text and mixed structured and unstructured content require vector models to support encoding for both plain text and OCR-extracted content.
High-frequency call demands in bulk review scenarios require indexes to support low-latency retrieval.
Professional units and process parameters in fields require vector encoding to retain semantic details, and avoid loss of unit and value semantics.
Compliance scenario data security requirements prioritize deployment methods that meet regulatory standards, to prevent data leaks.

## Configuration Settings
This configuration applies to FastGPT v4.17.0. Specific parameters are as follows:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the long-text structure of refinery declaration materials, ensures complete semantics within a single chunk |
| Overlap Length | 100–150 characters | Connects semantics of adjacent chunks, avoids matching deviations caused by split long text |
| `maxToken` | `8192` | Matches input limits of mainstream vector models, meets encoding requirements for long documents |
| Similarity Threshold | 0.75–0.85 | Balances accuracy and recall rate for case review, adapts to professional scenario matching requirements |
| Single Search Limit | Top 20 entries | Balances bulk review efficiency and result coverage |
| Reranking | Enabled | Optimizes semantic relevance of retrieved results, reduces interference from irrelevant case files |

## Three Common Misconfigurations
1.  Unexpected number of results returned after configuring the vector model. The cause is failure to adjust the similarity threshold based on professional field characteristics of refinery case files, leading to false or missed recalls of historical cases.
2.  Empty parsed fields after uploading a PDF. The cause is failure to enable automatic OCR configuration for scanned documents. Most refinery declaration materials include scanned unstructured content, so valid text cannot be extracted directly.
3.  Interface errors triggered during bulk review. The cause is failure to adjust `defaultToken` to a value suitable for bulk requests, leading to exceeded token limits in single calls and request failures.

## How to Confirm Proper Configuration
- Upload a typical refinery feed slip PDF. Check if parsed text fully includes structured fields such as unit number and feed volume. Confirm the `maxToken` parameter of the vector model meets document encoding requirements.
- Initiate a single case matching test. Verify that similarity scores of returned results fall within the set threshold range.
- Simulate a bulk review scenario. Process 10 declaration materials at one time. Confirm response duration meets business requirements.
- Check system operation logs. Confirm no abnormal errors occur in vector model calls, and index retrieval process operates normally.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
