# Declaration Materials and Case Review for Refinery and Chemical Production: Multi-turn Dialogue and Prompt Words

## What data for this category looks like
Declaration materials and case review data for refinery and chemical production mainly come from enterprise production management systems, local emergency management department filing archives, equipment operation and maintenance ledgers, and process parameter records. Data updates follow production batches or monthly filing cycles. A single case document usually includes structured content such as declaration subject qualification documents, device operation parameter tables, safety inspection reports, and environmental assessment attachments. Document fields include device number, material flow rate, operating pressure, inspection date, and more. Units are mostly industrial standard units such as cubic meters per hour, megapascals, tons per day.

## Constraints Imposed by These Characteristics on the Multi-turn Dialogue and Prompt Words Link
The multi-source, dispersed nature of refinery and chemical production declaration materials requires multi-turn dialogue to guide users to submit corresponding content in the order of qualification, parameters, inspection, and environmental assessment modules. This avoids missing information.
Single case documents are lengthy and contain specialized industrial fields. Prompt words must limit the context interception range to prevent token usage from exceeding model limits.
Fields include dedicated industrial units. Prompt words must clearly require verification results that match standard units.
Declaration data updates follow production cycles. Multi-turn dialogue contexts must automatically filter expired batch information to prevent confusion between historical and current declaration content during review.

## How to Configure the Setup
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 token | Single case documents for refinery and chemical declarations are lengthy, adapting to long-text review requirements |
| Number of retained conversation contexts | Previous 12 turns of dialogue | Covers the full declaration process from qualification submission to parameter verification |
| Prompt word variable configuration | Bind device number, declaration batch | Matches dedicated industrial fields of cases to ensure accurate verification |
| Single interaction token limit | 3500 token | Controls the information scale of a single round of input to avoid model response timeouts |
| Context filtering rule | Automatically filter by declaration batch | Adapts to the feature of data updated per production cycle, preventing confusion with historical data |
| Question optimization switch | Enabled | Refines vague parameter descriptions from users to match standard terminology in the refinery and chemical industry |

## Three Common Misconfigurations
- Symptom: Multi-turn dialogue context is lost, and previously submitted device parameters cannot be referenced during review. Cause: `chatId` is not bound to a dedicated declaration project, causing conversation context to be overwritten by new sessions.
- Symptom: Parameter units in model output do not meet industrial standards, such as using cubic meters per hour for tons per day. Cause: The prompt word does not clearly require matching dedicated unit fields for the refinery and chemical industry, and verification rules are not bound via `variables`.
- Symptom: Single-turn dialogue times out or cannot receive uploaded inspection report files, returning a 504 status code or parameter error. Cause: The token input in a single interaction exceeds the preset limit, or allowed formats and size limits for file uploads are not configured.

## How to Verify Correct Configuration
- Initiate the first round of dialogue to submit qualification documents, then initiate the second round to submit device parameters. Check that the `messages` list fully retains both rounds of interaction content.
- Input a parameter description with non-standard units. Verify that the model output automatically corrects to standard units for the refinery and chemical industry.
- Switch to sessions for different declaration batches. Check that contexts bound to different `chatId` do not interfere with each other.
- Submit the text content of a single complete case document. Verify that no token overflow error appears in the model response.
