# Declaration Materials and Case Review for Refinery Production: Workflow Orchestration

## What this category of data looks like
Data for declaration materials and case review in refinery production draws from four core sources: enterprise ERP systems, equipment operation logs, quality inspection reports, and safety supervision filing documents.
Update frequency shifts with production batches and inspection cycles, with no fixed scheduled rhythm.
Declaration material documents have three standard structures: equipment parameter tables, safety compliance documents, and energy consumption accounting sheets. Case files include approval circulation forms, rectification records, and acceptance reports.
Fields include equipment number, raw material grade, energy consumption value (unit: tons of standard coal per ton of product), approval node status, and more. Some documents combine long-text compliance descriptions and structured parameters.

## How These Characteristics Constrain Workflow Orchestration
Decentralized data sources require cross-system pull nodes in the workflow to support unified access to multi-source data.
Complex document structures, mixing long-text and structured fields, require structured extraction and long-text processing nodes in the workflow to adapt to processing logic for different review content types.
No fixed update rhythm requires workflow triggers to bind to data update events to support non-scheduled update cycles.
Refinery declaration materials must meet safety supervision compliance requirements, so the workflow must embed compliance check nodes to ensure review content aligns with industry standards.
Fixed approval links for case files require workflow node sequences to strictly match internal enterprise approval hierarchies to avoid circulation order errors.

## Recommended Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind equipment number, raw material grade, approval node ID | Adapt to personalized review rules for different refinery equipment |
| Trigger Mode | Trigger on data update events, with a 600-second delay | Match batch data update rhythms in refinery production |
| Maximum Documents Processed Per Run | First 20 items | Align with typical volume of single-batch declaration materials |
| Context Window | 8000–12000 token | Accommodate long-text quality inspection reports and compliance documents |
| Node Timeout | 300 seconds | Match typical time required for refinery data pulling and verification |
| `nodeId` | Bind each review node ID sequentially according to the approval link | Ensure workflow circulation complies with internal enterprise approval processes |

## Three Common Configuration Mistakes
- Phenomenon: The workflow returns empty results directly after triggering, with no review steps executed. Cause: The `variables` binding for data source identifiers is not configured, so the workflow cannot identify the path of declaration materials to be processed.
- Phenomenon: Node operation logs show "no operation results", with no output from code block execution. Cause: The data input port is not configured in the workflow, so nodes cannot obtain original document data from refinery production.
- Phenomenon: Output is empty after calling the chart tool to generate an energy consumption comparison chart. Cause: Structured energy consumption data fields are not bound to the data source configuration of the chart tool, so the tool cannot obtain valid data.
