# Declaration Materials and File Review for Refinery Production: Tool Calling and Plugins

## What data for this category looks like
Data mainly comes from refinery unit operation logs, safety compliance declaration documents, quality inspection analysis reports, and file archive approval records. Sources include real-time collected data from production links and post-archive approval documents. Update frequency follows individual declaration cycles or monthly archive deadlines. Document structures include fields such as unit number, material batch, raw material consumption, product yield, safety inspection items, and approval process nodes. Most units use industrial standard measurement units including tons, cubic meters, hours, megapascals, and degrees Celsius.

## What constraints these characteristics impose on tool calling and plugins
Refinery production declaration materials and file data include multi-field industrial measurement units. Strict matching of preset field names and unit rules during tool calling is required to avoid parameter parsing errors. Data sources cover real-time collected operation data and archived approval documents. Plugins must support both real-time API calling and static document parsing modes. Single files or declaration materials can have long length. The `toolChoice` configuration can automatically adapt to long text processing requirements. Parsing rules must be configured separately for structured operation logs and semi-structured approval records.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the mixed scenario of structured operation logs and semi-structured approval records in refinery declaration materials, automatically selects appropriate tool calling logic |
| `functionCall` | Enabled | Requires tool calling to read log fields and file approval nodes, forces function calls to ensure the accuracy of parameter parsing |
| Tool call timeout | 300–600 seconds | Refinery data queries may involve multi-node log summarization, require sufficient response duration, adjust the interval based on actual measurements |
| Maximum number of tool call return entries | Top 10 entries | A single declaration material involves many log and file entries, limit return entries to avoid context overflow |
| Field matching threshold | 0.95 | Refinery field names have strong industrial standardization, require high matching accuracy to avoid mismatching key information such as material batches and energy consumption units |

## Three common errors
- Phenomenon: Tool calling returns empty results, or returned fields do not match the preset fields for the declaration material. Cause: Fails to match the exclusive field names of refinery declaration materials, only uses general field keywords for retrieval, resulting in failure to locate core content such as material batches and energy consumption data.
- Phenomenon: Tool calling returns a 400 status code, logs show parameter format verification failure. Cause: The request parameters carry units that do not comply with industrial measurement specifications, such as mistakenly writing "tons" as "liters", triggering interface verification rule interception.
- Phenomenon: The tool calling link in the workflow times out and interrupts, the interface displays a request timeout prompt. Cause: No timeout time adapted to long files is configured, multi-node data query for a single declaration material exceeds the default timeout limit.

## How to confirm the configuration is properly set
- Manually trigger tool calling, input a refinery declaration material sample with known fields, check whether the returned results include preset fields such as unit number and material batch.
- View tool calling logs, confirm that the units and field names in the request parameters comply with refinery industrial standards, with no format errors.
- Simulate the full process call of a single declaration, check whether the tool calling link can correctly connect the reading of log data and file approval records.
- Adjust the tool call timeout time, test whether the call for long text files can be completed normally without interruption errors.

The values provided are common starting points and should be measured against the reader's own samples.
