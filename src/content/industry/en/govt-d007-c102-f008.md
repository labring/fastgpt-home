# Declaration Materials and Case Review for Refinery and Chemical Production: Document Parsing and Chunking

## What This Category of Data Looks Like
Refinery and chemical production declaration materials and case review data mainly come from project establishment applications, safety and environmental protection review filings, production operation logs, and compliance case files. Data updates follow project progress or monthly compliance inspection cycles. A single declaration package may include dozens of pages of PDF feasibility study reports, Excel material balance sheets, scanned process drawings, and Word approval process documents. Document fields include unit number, material grade, emission limits, approval document numbers, and other items, with supporting industrial units such as tons, cubic meters, and megapascals.

## What Constraints Do These Characteristics Impose on the "Document Parsing and Chunking" Link
Mixed-format data sources require the parsing module to support PDF text, Excel tables, and scanned drawing OCR to avoid data loss from certain formats. Long documents and dense professional terminology require chunking to retain contextual associations, avoiding splitting critical information such as process descriptions and material parameters mid-sentence. Different declaration case files have large structural differences: some are arranged by chapter, others by approval items. This requires adapting flexible chunk triggering logic. In scenarios where multiple files are submitted in batches, parsing parameters must be unified to ensure consistency of chunking results.

## How to Set Configurations
| Configuration Item | Recommended Value | Basis for This Setting |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 characters` | Refinery declaration materials include long paragraphs of process descriptions and parameter tables. This range can retain the integrity of a single set of process logic |
| `chunkSplitter` | By chapter + semantic segmentation | Refinery case files are mostly arranged by approval chapters or process nodes. This chunking method matches the native structure of the documents |
| `customPdfParse` | Enabled | Some declaration materials are encrypted or watermarked PDFs. Custom parsing can adapt to the special layout of industrial documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Large feasibility study reports or multi-page drawings take a long time to parse. This duration covers most single-file parsing requirements |
| `chunkSettingMode` | Manual configuration | Document structures vary significantly across different declaration batches. Manual configuration allows flexible adjustment of chunking parameters |

## Three Common Misconfigurations
- Phenomenon: There are differences in chunking results between API uploads and platform direct uploads, with inconsistent splitting positions for some paragraphs. Cause: The `chunkSplitter` parameter was not unified. API calls use the default general chunking rules, while platform direct uploads allow manual adjustment of chunking modes.
- Phenomenon: No parsed data is returned after importing documents via custom URLs. Cause: `customPdfParse` was not enabled to adapt to the resource permission check of custom links, or the file format pointed to by the link is not supported by basic parsing.
- Phenomenon: After configuring the parsing node, the model cannot read uploaded files, and the logs show the file parsing status as timed out. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted. Parsing large refinery drawings or long documents exceeds the default duration, leading to parsing failure.

## How to Confirm Proper Configuration
- Use the FastGPT v4.17.0 platform, upload a single typical refinery declaration document, and review the parsed chunk list to confirm that process descriptions and parameter tables are not abnormally split.
- Upload the same document via both API and platform direct upload, compare the chunking results, and confirm that the `chunkSplitter` configuration is unified.
- Import industrial documents via custom links, and check if the parsed results include complete text and OCR content.
- Submit a large feasibility study report, review the time consumption record in the parsing logs, and confirm that the `PARSE_FILE_TIMEOUT_SECONDS` setting is sufficient to cover the parsing duration.

The values provided are common starting points and should be evaluated against the user’s own samples.
