# Declaration Materials and File Audit for Refinery Production: Deployment and Upgrade

## What this type of data looks like
Data for declaration materials and file audit in refinery production originates primarily from internal enterprise production ledgers, equipment maintenance archives, and safety compliance declaration documents. Updates follow fixed declaration batch schedules, typically monthly or quarterly bulk updates. Documents consist mainly of structured forms, with accompanying unstructured attachments including maintenance reports in PDF format, energy consumption reports in Excel format, equipment drawings in CAD format, and others. Core fields include equipment number, maintenance duration, declaration document number, approval status, and more. Units use industrial measurement standards such as hours, cubic meters, tons, and others.

## What constraints these characteristics impose on deployment and upgrades
Mixed structured and unstructured data formats require storage configurations adapted for multi-source data parsing during deployment. Scheduled bulk declaration updates create concurrent read and write pressure, so database connection parameters must be adjusted to avoid overload. Fixed field structures require retaining original field mapping logic during upgrades to prevent data loss from broken parsing rules. Large-volume equipment drawing attachments also require storage and transmission parameters optimized for large files to avoid upload or read timeouts. This configuration scheme is compatible with FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:yourpass@mongo-host:27017/fastgpt?authSource=admin` | Adapts to the structured storage needs of refinery declaration data, ensuring stability for multi-node concurrent read and write operations |
| `STORAGE_S3_ENDPOINT` | `http://your-oss-endpoint:8080` (enterprise self-built storage address) | Adapts to the storage needs of large-volume file attachments, supporting upload and download of bulk declaration materials |
| `DB_MAX_LINK` | `20–30` | Handles concurrent connection requests during monthly bulk declarations, preventing database connection exhaustion |
| `REDIS_URL` | `redis://:yourredispass@redis-host:6379/0` | Caches parsing results of declaration materials to reduce repeated calculation overhead |
| `FILE_TOKEN_KEY` | `32-bit randomly generated string` | Ensures upload authentication security for declaration attachments, preventing unauthorized file access |

## Three common misconfigurations
- Scenario: After upgrading to FastGPT v4.8.10, workflow orchestration configurations from version v4.6.7 cannot be imported, and the interface displays "configuration format incompatible". Cause: There are mapping differences between node parameter fields of older workflows and the new version, and no compatibility handling was implemented.
- Scenario: After source code deployment, MongoDB connection logs return a `connection refused` error, and the service cannot start. Cause: The host port specified in the `MONGODB_URI` configuration is not open, or the authentication username or password was entered incorrectly.
- Scenario: When uploading bulk refinery declaration files, some large-volume attachments fail to upload, and the interface returns "file size exceeds limit". Cause: The single-file upper limit parameter of the storage configuration was not adjusted, and the default value cannot accommodate large-volume attachments such as CAD drawings.

## How to confirm configurations are properly set
- Run a database connection test command to verify the connectivity of the `MONGODB_URI` configuration, confirming no connection errors.
- Upload a standard refinery maintenance report PDF attachment to verify that the storage configuration completes upload and reading normally.
- Import an older version workflow configuration file, check that all node parameters load completely with no missing fields.
- Initiate a bulk declaration test, monitor database connection counts, confirm they do not exceed the upper limit set by the `DB_MAX_LINK` configuration.
