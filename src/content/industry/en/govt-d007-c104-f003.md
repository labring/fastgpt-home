# Coal Chemical Industry Declaration Materials and Case Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for coal chemical industry declaration materials and case review include project establishment declaration documents, safety pre-assessment reports, pollution discharge permit application documents, safety supervision law enforcement case files, and similar materials. Data is updated in real time alongside approval progress during the project declaration phase, and stored statically after archiving.

Document structure is split into two categories: declaration materials and case files. Declaration materials include fixed fields such as project name, designed production capacity, actual investment amount, and core process route. Case files include fields such as inspection record number, rectification notice number, approval node timestamp, and law enforcement officer signature.

Field units follow coal chemical industry standards: production capacity is measured in ten thousand tons per year, and materials are measured in tons or cubic meters.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Fixed field requirements require multi-turn dialogue to guide users to complete missing information step by step per approval nodes, to avoid missing key parameters.
Real-time updated declaration data requires prompt engineering to limit interactions to the current project's latest status, and prohibit calling expired archived data.
Professional industry standards require prompt engineering to include built-in industry verification rules, to automatically correct non-standard unit expressions.
Unique case file number requirements mandate that `chatId` be bound to the corresponding case, to ensure unique context attribution for multi-turn dialogue and avoid cross-project confusion.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique case number | Coal chemical industry case numbers are unique, which can avoid context confusion in cross-project dialogues |
| `messages` | Limit context rounds to the first 8 rounds | Dialogues for declaration materials and case review follow step-by-step approval processes. Excessively long contexts may interfere with approval logic |
| `variables` | Bind preset fields such as project production capacity and investment amount | Match the fixed field requirements of declaration materials, and reduce redundant manual input operations |
| Maximum context | 8000–12000 characters | Adapt to the core content length of a single feasibility study report, and avoid context overflow |
| Supported file upload formats | PDF, DOCX, DWG | Cover common formats of coal chemical industry declaration materials, including process drawing files |
| Timeout threshold | 60 seconds | Match the daily waiting habits of approval personnel, and avoid session interruption caused by overly long waiting |

## Three common configuration errors
- Phenomenon: Calling the dialogue API returns "missing application ID parameter", and multi-turn dialogue cannot be initiated. Cause: The application creation API was not called correctly, or the application ID was not bound to the coal chemical project session, resulting in the session having no legal attribution.
- Phenomenon: After uploading a coal chemical industry process drawing, the dialogue interface prompts that the file format is not supported. Cause: The DWG format file upload whitelist was not configured, and coal chemical industry declaration materials often include CAD-drawn process drawings.
- Phenomenon: Different users using the same application key to initiate dialogues result in overlapping context content. Cause: `chatId` was not bound to a user's unique identifier or case number, leading to a lack of isolation between session contexts.

## How to confirm correct configuration
- Initiate a test dialogue, enter the production capacity parameter of a coal chemical project, and check whether `variables` automatically binds preset project fields.
- Upload a DWG format process drawing, confirm that the interface shows no format errors, and that the dialogue can normally read the annotation information in the drawing.
- Generate `chatId` using two different case numbers, initiate a dialogue, switch sessions, and confirm that contexts do not interfere with each other.
- Enable the streaming output switch, initiate a test dialogue, and check whether the dialogue returns content word by word.
