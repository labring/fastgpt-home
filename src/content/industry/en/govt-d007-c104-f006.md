# Coal Chemical Industry Declaration Materials and File Review: Source Citation and Traceability

## What this category of data looks like
Coal chemical industry declaration materials and file review data mainly comes from three sources: internal enterprise project approval systems, coal industry safety supervision filing platforms, and environmental impact assessment (EIA) document repositories. Data update rhythm adjusts according to project progress. Single declaration materials are archived once. Industry standard data updates monthly. Document formats include PDF EIA reports, Excel material consumption detail sheets, and Word approval application forms. Single document length varies widely. Data fields include project number, coal type, water consumption, approval node, and filing document number. Units include tons, cubic meters, ten thousand yuan, and other industry-specific units.

## What constraints these characteristics impose on the source citation and traceability link
The multi-source and dispersed nature of coal chemical industry declaration materials and files requires traceability systems to simultaneously associate data sources from internal approval systems and external industry standard libraries, to avoid confusion in source identification. Diverse document formats can cause field association information to be lost in split text chunks. For example, column headers and data blocks in Excel tables may be split, making it impossible to match corresponding coal type water consumption data during traceability. Irregular update rhythms require traceability systems to support incremental synchronization configuration, otherwise errors such as citing outdated filing document numbers may occur. Specialized fields and units require traceability systems to retain original metadata, to prevent reviewers from being unable to verify data compliance.

## Three common misconfigurations
- Phenomenon: Unrendered Markdown separators such as `|` appear in the context citation area. Cause: Format markers such as table separators in original documents are not filtered during the preprocessing stage, causing non-content symbols to be retained during chunk splitting.
- Phenomenon: No knowledge base file citations are returned after a query is initiated. Cause: Cross-source recall data source paths are not configured, or the recall upper limit is set too low, failing to match relevant content chunks of coal chemical industry declaration materials.
- Phenomenon: Cited content does not match the query, and field units are displayed incorrectly. Cause: Detailed traceability configuration is not enabled, and original document field metadata is not retained, causing confusion between water consumption data of different coal types during matching.

## How to verify correct configuration
- Upload a coal chemical industry EIA report in PDF format, initiate a query that includes "project filing document number", and check whether the returned cited content includes the complete document number and original document path.
- View the context citation area, confirm that Markdown format symbols have been correctly filtered, and only the original text content is displayed, with no remaining separators or markers.
- Adjust the maximum context value, initiate a query that includes multiple approval nodes, and check that the number of returned citations matches the set upper limit.
- Trigger an incremental synchronization of the knowledge base, upload updated coal chemical industry declaration materials, and confirm that new content can be normally recalled and traced.
