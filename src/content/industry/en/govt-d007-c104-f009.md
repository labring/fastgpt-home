# Coal Chemical Industry Declaration Materials and Case Review: Model Access and Configuration

## What this category of data looks like
Data for coal chemical industry declaration materials and case review comes primarily from internal corporate project initiation archives, safety pre-assessment reports, environmental approval cases, and capacity accounting ledgers.
Data is updated in two ways: bulk import of existing archives when a project launches, and real-time addition of single records when approval status changes.
Documents use a fixed standard template, with fields including project number, designed production capacity (unit: tons per year), environmental assessment approval document number, approval date, on-site inspection record attachments, and more.
Individual document word counts vary widely, ranging from hundreds of words of approval opinions to tens of thousands of words of complete project initiation cases.

## Constraints on model access and configuration
The numerous fields and specialized terminology in coal chemical industry declaration materials—such as gasifier model, coal consumption quota—require the model to accurately recognize relationships between specialized fields.
The wide variation in individual document length, from short approval opinions to long project initiation cases, requires configuration to adapt to context inputs of different lengths.
Real-time added approval records require the model to quickly pull the latest case data when calling tools, while avoiding context overflow caused by too many fields.
Format differences between individual cases are small, but attachment types are diverse. Configuration must support vector extraction of multiple attachment types to ensure full access to associated materials during review.

## Configuration settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Individual coal chemical industry cases can reach tens of thousands of words. Sufficient context must be retained to associate multiple approval materials with the current review task |
| `maxTokens` | `2000–3000 token` | Declaration material review outputs require detailed compliance judgments, while avoiding exceeding the model's output limit |
| `quoteMaxToken` | `1500 characters` | Key compliance clauses from cases must be extracted as reference basis. Control the length of referenced content to fit the model's input window |
| `toolChoice` | `auto` | The review process automatically calls the case retrieval tool to pull associated materials, without manual tool specification |
| `temperature` | `0.2–0.4` | Review requires strict judgment, avoiding overly random conclusion outputs |
| `AIPROXY_API_ENDPOINT` | Fill in according to the enterprise's internal model deployment address | Adapt to the large model interface for enterprise internal private deployment, ensuring data does not leave the internal network |

## Three common configuration mistakes
- Symptom: A 504 timeout error is returned when calling a tool, or an empty result stating "no associated cases found" is returned. Cause: `maxContext` is not adjusted to fit long cases, leading to context overflow that prevents correct retrieval of associated data.
- Symptom: All configured model parameters are lost after a Windows server restart. Cause: FastGPT's configuration file is not stored in a persistent directory outside the system disk. A system disk reset after restart causes configuration loss.
- Symptom: Review output content is truncated by the model, unable to fully display compliance judgment conclusions. Cause: A reasonable `maxTokens` value is not set, leading to output length exceeding the model's limit.

## How to verify a successful configuration
- Upload a standard coal chemical industry project initiation case, check whether the model can correctly identify core fields such as project number and designed production capacity.
- Submit a simulated review request, confirm that the tool automatically calls and pulls associated case results meet expectations.
- View the model's token usage statistics, confirm that the `maxTokens` upper limit is not triggered.
- Restart the deployment environment, check whether the configured parameters are fully retained.
