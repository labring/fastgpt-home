# Coal Transportation and Sales Declaration Material and File Review: Multi-turn Dialogue and Prompt Words

## What this category of data looks like
Data primarily originates from purchase and sales contracts, weigh slips, transportation documents, compliance approval files, and internal ledgers of coal transportation and sales enterprises. Updates are triggered synchronously when individual business processes are completed. A single declaration material usually contains 5 to 8 types of attachments. File review data consists of archived multi-node approval records. Documents are mostly in a mixed format of structured tables and unstructured scanned documents. Core fields include coal type, carried tonnage, transportation route, cargo right number, and approval node status. Units involve industry-standard metrics such as tons, kilometers, and yuan.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words workflow
Mixed-format documents and structured fields require multi-turn dialogue systems to support cross-format content parsing. This avoids missing key measurement information in scanned documents when only text data is extracted.
Multi-node approval files have large historical data volumes. Limiting the context window prevents overflow.
Strongly correlated fields such as coal type and tonnage require high accuracy. Prompt words must clearly specify field verification logic to prevent confusion across coal types.
Real-time updated individual business data requires the dialogue flow to bind the corresponding business ID. This prevents cross-order data misuse.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Context window | 8000–12000 token | Adapts to the total content volume of a single batch of declaration materials and files, to avoid context overflow |
| Bind business ID | Associate with the current session `chatId` | Ensures multi-turn dialogue only calls exclusive data for the current coal transportation and sales business, to prevent cross-order data misuse |
| Variable injection | Pass preset fields such as coal type and transportation tonnage | Reduces prompt word redundancy, and improves the accuracy of structured field extraction |
| Maximum number of attachments per dialogue | First 8 items | Matches the conventional number of attachments for a single declaration material, to avoid interface overload |
| Session timeout | 600 seconds | Adapts to the multi-round review interaction duration of approval files, to prevent mid-session disconnection |
| Question optimization | Enabled | Automatically breaks down long declaration questions, adapting to the multi-node review logic of complex files |

## Three common misconfigurations
- When performing long-text file review tasks, the interface shows the task completed normally but returns the error `The value of "offset" is out of range`. The cause is that the context window content length is not limited, resulting in exceeding the built-in index range when parsing long documents.
- When uploading multiple weigh slips and contract attachments, the dialogue interface returns a parameter error. The cause is that multi-file content is not nested according to the array format of the `messages` parameter, resulting in the interface being unable to recognize the multi-attachment request.
- When enabling custom skill nodes, dependencies must be reinstalled for each new session. The cause is that dependency packages are not packaged into the session image, resulting in temporary virtual machine instances being unable to reuse installed dependency files.

## How to confirm the configuration is correctly set
- Initiate a multi-round review dialogue for a single declaration material, check that the context window automatically truncates redundant content, and no errors are returned.
- Upload 3 or more attachments to initiate a dialogue, confirm that the interface can normally parse multi-attachment content, and no parameter error prompts are displayed.
- View the session log, confirm that the bound `chatId` matches the current business ID, and there is no cross-session data misuse.
- After enabling custom skills, initiate two consecutive sessions, confirm that the second session can run normally without reloading dependencies.
