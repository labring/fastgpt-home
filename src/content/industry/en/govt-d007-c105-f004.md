# Coal Transportation and Sales Declaration Material and File Review: Workflow Orchestration

## What This Category of Data Looks Like
Coal transportation and sales declaration material and file review data mainly comes from the purchase and sales contract system, weighing ledger, railway/road transport documents, and quality inspection report system. Data is generated and updated in real time as each single transaction is completed. A single file document usually includes fields such as contract number, coal type name, shipment tonnage, transport mileage, weighing time, and quality inspection indicators. Most field units are tons, kilometers, and yuan/ton. The length of a single file document ranges from 800 to 1500 characters.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Coal transportation and sales declaration data has decentralized sources. This requires workflow orchestration to support connecting multiple system nodes to pull cross-source data.
The real-time generation feature per single transaction requires the workflow to be configured with trigger-based startup logic to match the real-time data update rhythm.
Fields include specific units such as tons, kilometers, and yuan/ton. This requires the parameter verification link of the workflow to set rules matching unit formats.
The fixed length range of single file documents requires the context processing link of the workflow to adapt to this length, avoiding exceeding the context carrying threshold.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Triggered by document generation event | Coal transportation and sales declaration data is generated in real time with each single transaction, matching real-time update rhythm |
| Context Window | 1500–2000 characters | Single file document length is concentrated between 800–1500 characters, reserving sufficient processing space |
| Parameter Verification Rules | Match formats for tons, kilometers, yuan/ton | Adapt to specific unit requirements for coal transportation and sales data fields |
| `variables` | Bind core fields such as contract number, shipment tonnage | Cover core verification dimensions for file review |
| Node Timeout | 600 seconds | Reserve sufficient response time for pulling cross-source data across multiple systems |
| `nodeId` | Bind IDs of each system docking node | Precisely control execution order and data flow of workflow nodes |

## Three Common Mistakes
- Fields bound to `variables` are empty after the workflow runs. The cause is that cross-system data variable mapping is not completed before workflow startup, leading to core fields not being loaded correctly.
- Custom reference templates and prompt words cannot be used in the workflow. The cause is that the running FastGPT version is lower than v4.9.7. This function is available in v4.9.7 and above versions.
- Global variables are not updated after tool calls. The cause is that variable synchronization is not enabled in the tool node configuration, and nodes are not executed in the order specified by `nodeId`. This configuration takes effect in FastGPT v4.17.0 and above versions.

## How to Confirm the Configuration Is Correct
- Manually trigger a simulated transaction to confirm that the workflow starts automatically and pulls corresponding data.
- Check that the fields bound to `variables` are consistent with the coal transportation and sales data fields pulled from the system.
- View workflow node logs to confirm that each node returns data formats that comply with preset unit rules.
- Verify that the AI configuration page supports custom reference templates and prompt words.
