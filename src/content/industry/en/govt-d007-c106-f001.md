# Coal-fired power integration declaration materials and case review: HTTP interfaces and external systems

## What data for this use case looks like
Data for coal-fired power integration declaration materials and case review comes from mine production systems, power generation dispatch platforms, and official declaration templates from local energy regulatory authorities.
Two update modes are supported: monthly batch synchronization, and real-time trigger for individual declaration submissions.
Documents primarily use structured PDF files and Excel ledgers.
These documents include fields such as mine code, approved production capacity, unit operation parameters, environmental monitoring data, and approval circulation records.
Supported units include tons, kilowatt-hours, cubic meters, ten thousand yuan, and other industry-standard units.
This content is based on the interface configuration logic of FastGPT v4.17.0.

## What constraints do these characteristics impose on the HTTP interfaces and external systems workflow
The large number of structured fields with unique units requires interfaces to support field format verification and unit conversion.
Dual update modes (real-time individual declaration triggers and monthly batch synchronization) require compatibility with both synchronous calls and asynchronous callbacks.
Supported document formats include PDF and structured tables, so interface parameters must support multi-format parsing.
Real-time synchronization of approval circulation status changes to external management systems requires interfaces to support status push and breakpoint resumption.

## Three common misconfigurations
- After uploading coal power declaration materials via the HTTP interface, external systems cannot retrieve binary raw data. This occurs because the binary data return switch is not enabled in the interface configuration, and only file path information is returned.
- The interface call returns a 403 status code with an insufficient permissions error message. This occurs because the `Authorization` header is not configured correctly, and a non-team-specific authentication key is used.
- When batch submitting case review data, the number of interface return results does not match the volume of submitted data. This occurs because the field mapping limit for single requests is not adjusted, and the default parameter restricts the volume of returned data.

## How to verify correct configuration
- Call the configured interface, pass test mine codes and declaration materials, and check if the `responseData` field includes approval status data.
- Review interface logs to confirm that the `Authorization` header correctly carries the team-specific authentication secret key.
- Upload a single 800 MB test case to verify that the interface can complete transmission and parsing normally.
- Trigger a temporary declaration, and check if the external system receives approval circulation status change information in real time.
