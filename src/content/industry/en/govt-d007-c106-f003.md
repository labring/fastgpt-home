# Coal-Electric Integration Declaration Materials and Case Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Coal-electric integration declaration materials and case data primarily come from central and state-owned enterprise internal coal production capacity declaration, coal-electric project filing and approval archiving systems. Updates are triggered temporarily along individual project’s declaration cycles, and are also updated regularly via scheduled archiving on a routine basis. A single declaration material includes four core document types: main qualification documents, production capacity accounting forms, environmental impact assessment (EIA) approvals, and approval process node records. Fields include project number, approved production capacity, approval level, submission date, and more. Units involve professional measurement standards such as ten thousand tons per year, ten thousand kilowatt-hours, ten thousand yuan, and others.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
Single declaration materials are relatively lengthy. Multi-turn dialogue must retain multiple rounds of approval questions and historical responses to avoid context breaks. Fields include professional measurement units, so prompt engineering must accurately match corresponding rules to prevent review deviations caused by unit confusion. Data is updated temporarily alongside project progress, so the dialogue link must retrieve the latest archived content in real time, and cannot rely on static knowledge base caching. Multi-round review involves multiple approval nodes, so session identifiers must be used to distinguish different tasks to avoid cross-use of data from different projects.

## How to set up configurations
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Single coal-electric integration declaration materials often exceed 5000 characters, so multi-round approval questions and historical responses must be retained |
| Single Dialogue Timeout | 600 seconds | Case review requires retrieving multiple related documents, to avoid mid-process interruptions |
| `variables` binding | Bind project number and approved production capacity unit variables | Ensure automatic matching of field rules for the corresponding category during review, reducing manual input errors |
| Knowledge Base Retrieval Count | Top 6–10 entries | Declaration material related data is scattered, so coverage of three core document types (qualification, EIA, production capacity) is required |
| `chatId` configuration | Fixed binding to project session ID | Ensure context consistency across multi-turn dialogue, avoiding cross-project data confusion |
| Dialogue History Retention Rounds | Retain the most recent 10 rounds of dialogue | Cover complete questions and responses from multi-round approval, supporting process handover for subsequent review nodes |

## Three Common Mistakes
- The workflow terminates directly after the AI reply step, with no subsequent node triggered. The cause is that the `chatId` parameter is not bound, resulting in the loss of context session identifiers for multi-turn dialogue, and subsequent processes cannot associate the current review task.
- Frequent timeout errors occur in dialogue, with a 504 status code displayed. The cause is that the single dialogue timeout setting is lower than 600 seconds, which does not adapt to the time-consuming requirement of retrieving multiple related documents.
- The plugin only triggers during the first dialogue, and subsequent questions cannot call the plugin. The cause is that the dialogue history retention rule is not correctly configured, the `messages` content is not fully transmitted, and the plugin trigger conditions are not met.

## How to Verify Proper Configuration
- Initiate a query containing the project number, check whether the reply automatically matches the field rules of the corresponding category, such as the production capacity unit displayed as "ten thousand tons per year".
- Initiate two consecutive queries, check whether the complete `messages` content is retained in the dialogue history, with no context loss.
- Simulate a long review process, wait longer than the preset timeout period, confirm that the dialogue does not automatically interrupt.
- Test plugin triggering, initiate a second query, confirm that the plugin can be called normally.
