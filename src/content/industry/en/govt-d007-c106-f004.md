# Declarations and File Review for Coal-Power Integration Projects: Workflow Orchestration
This document is written based on FastGPT v4.17.0.

## What This Category of Data Looks Like
Data for coal-power integration project declarations and file review primarily comes from coal production ledgers, power dispatch systems, project approval documents, and on-site environmental protection test reports. The data update rhythm adjusts based on project progress milestones: during the project approval submission phase, new materials are synced daily. During the acceptance phase, archived documents are updated in batches. A single case file usually includes four core documents: project record form, generator set capacity calculation sheet, environmental protection test report, and power grid interconnection application form. Fields include mine number, generator set capacity (unit: MW), coal production capacity (unit: 10,000 tons/year), grid connection voltage level (unit: kV), as well as circulation timestamps and handler records for each approval stage.

## Constraints Imposed on Workflow Orchestration
Multi-source and scattered data sources require workflow configurations to include cross-system data pull nodes that connect to coal production ledgers, power dispatch systems and other data sources respectively. The dynamic data update rhythm tied to project milestones requires workflow trigger conditions to be bound to approval node status, with execution only starting during submission or acceptance phases. The mixed file structure of case files requires workflows to split and validate links by file type, separately verifying required fields for documents such as record forms and capacity calculation sheets. Fields with specific unit requirements require embedding unit validation logic in workflows to ensure that values such as generator set capacity and coal production capacity match their corresponding units.

| Node trigger conditions | Trigger based on approval node status, start after a 600-second delay | Adapts to the circulation time of project submission, reserves a buffer for material uploads |

| External MCP plugin access | Configure for on-demand triggering, connect to the coal production capacity calculation interface | Only call external tools during capacity validation links, reduces resource usage |
| `nodeId` | Bind to the unique identifier of the validation node | Accurately locate workflow execution links, facilitates log tracing and exception troubleshooting |

## Three Common Misconfigurations
- Phenomenon: The code execution node returns status code 500 after execution, with logs showing "parameter format mismatch". Cause: The capacity value of coal-power projects was not bound to its corresponding unit, causing the external calculation interface to fail to parse the field content.
- Phenomenon: No optional value list appears in the workflow variable selection interface, making it impossible to bind core case file fields. Cause: The fixed field template for coal-power integration projects was not pre-defined in the global variable configuration, so the system cannot load the corresponding optional parameters.
- Phenomenon: Calling the workflow via an external interface returns "invalid node identifier". Cause: The correct `nodeId` parameter was not used to bind the target execution node, causing the interface to fail to match the corresponding workflow link.

## How to Confirm Proper Configuration
- Manually trigger the workflow, check if each data pull node successfully obtains corresponding data from coal production ledgers and power dispatch systems.
- Submit a standard coal-power integration declaration case file, verify that the code execution node correctly parses the units and values of fields such as capacity and voltage level.
- Call the external MCP plugin interface, check if the coal production capacity calculation logic can be triggered normally, with no permission or timeout errors.
- View workflow logs, confirm that the `variables` parameter is correctly bound to the fixed field template for coal-power projects, and that the `nodeId` identifier matches the target node.
