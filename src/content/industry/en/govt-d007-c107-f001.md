# Declaration Materials and File Review for Coal Mine Production: HTTP Interfaces and External Systems

## What the data for this category looks like
Coal mine production declaration materials and file review data mainly comes from three sources: the coal mine safety production dispatching platform, mine safety supervision archive system, and local energy regulatory declaration portal. Data is synchronized in batches during a single declaration cycle, with routine archived data updated weekly. Most documents are scanned PDFs converted from images or edited Word files. They include structured fields such as mine number, mining face code, gas detection data, and approval circulation records. Units used include %, ton, cubic meter, and hour, among others.

## Constraints Imposed on HTTP Interfaces and External Systems Workflows
Most coal mine production declaration materials are scanned PDFs or edited documents with structured fields, and have large individual upload sizes. HTTP interfaces must support large file threshold configuration to accommodate this. Fixed fields such as mine number and safety supervision approval document number must be included with each request. Interfaces must support custom `variables` parameters to bind these business fields. Batch submission during declaration cycles requires interfaces to support batch request adaptation. Data involves safety production supervision, so interface authentication must strictly align with the enterprise’s internal system permission rules to ensure valid call legitimacy.

## How to Configure Settings
This document is written for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {token from the enterprise's internal safety supervision system}` | Matches the authentication rules of the coal mine's internal system to ensure valid interface call permissions |
| `variables` | `{"mineCode": "XXX", "workfaceCode": "XXX", "approvalId": "XXX"}` | Binds fixed business fields such as mine, working face, and approval document number to meet the structured requirements of declaration materials |
| `responseData` | `["code", "message", "data"]` | Adapts to the return format specifications of the coal mine's internal system to facilitate parsing of call results |
| Timeout Duration | `600 seconds` | Large file uploads and batch reviews require longer processing cycles to avoid premature interruptions |
| File Upload Size Limit | `1000 MB` | A single coal mine declaration file may include multiple test reports and drawings, resulting in large overall volume |

## Three Common Configuration Errors
- Phenomenon: The declaration interface returns `Invalid URL, code: 500`. Cause: The target interface’s domain name path is not configured correctly, or the enterprise’s internal system firewall blocks external call requests.
- Phenomenon: The interface returns empty fields when uploading PDF files directly. Cause: Structured business fields are not bound using the `variables` parameter, so the system cannot match the declaration material review rules.
- Phenomenon: HTTP toolset calls have no response or time out. Cause: The timeout duration configuration is not adjusted, and the processing cycle for large file uploads or batch reviews exceeds the default threshold.

## How to Confirm Proper Configuration
- Call the authentication interface of the enterprise’s internal safety supervision system to obtain a valid token, replace the `Authorization` parameter, send a test request, and check if the returned authentication status code is 200.
- Pass the preset `variables` parameter, send a test call for a single declaration material, and verify if the returned `responseData` contains expected business fields.
- Upload a single test PDF file not exceeding 100 MB, check if the interface accepts the file normally and returns processing progress.
- Review the enterprise’s internal system logs to confirm if the interface request’s source IP and authentication information are properly allowed.
