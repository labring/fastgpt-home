# Coal Mine Production Declaration Materials and Case Review: Workflow Orchestration

## What data for this use case looks like
Data sources for coal mine production declaration materials and case review include internal dispatching systems, underground monitoring terminals, and local safety supervision reporting platforms. Data is updated immediately after a single underground job is completed, and complete case files are archived in batches on a monthly basis. The document structure includes fixed fields such as working face number, gas/dust monitoring parameter values, approval circulation node records, and rectification feedback forms. Field units include ppm, cubic meters, hours, copies, and other standard units.

## What constraints these characteristics impose on workflow orchestration
Decentralized data sources require workflow configurations to use multiple parallel or serial nodes to call tools from different data sources, avoiding delays caused by single nodes pulling full datasets. The real-time data update requirement means workflow node execution intervals must match job rhythms. Overly long cache cycles should not be used, and latest monitoring data must be pulled in real time. The hierarchical approval logic of case files requires workflows to be arranged in node order, with the next node only triggered after the previous node’s verification passes. Fields with specific units require adding format verification nodes to the workflow to ensure consistent units during parameter transfer.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| Variable mapping | Bind working face ID, monitoring parameters, approval node ID as `variables` | Matches the fixed field structure of coal mine declaration materials, facilitating cross-node data transfer |
| Node trigger rules | Execute in `nodeId` order, trigger after the previous node’s verification passes | Aligns with the hierarchical approval logic of coal mine case reviews, preventing out-of-order operations |
| Knowledge base association | Bind coal mine safety regulations library, operation standards library | Covers core data source needs for compliance verification, matching the review scenario |
| Timeout threshold | 600 seconds | Adapts to network latency in underground data collection, calibrated based on actual measurements |
| Branch trigger conditions | Determine branch direction based on field compliance | Distinguishes qualified declaration materials from materials requiring rectification, enabling split processing |
| Tool call termination | Add a termination node at the end of the workflow | Clarifies the end marker of the process, avoiding repeated tool calls in loops |

## Three common configuration mistakes
- Failing to add a tool call termination node at the end of the workflow, resulting in repeated tool calls. This occurs because the end marker of the process is not clearly defined, causing the system to repeatedly trigger subsequent nodes.
- Failing to define custom input variables for HTTP modules in the `variables` format, resulting in errors where interface received parameters are empty. This occurs because FastGPT variable transfer rules are not followed.
- Failing to set knowledge base matching keyword thresholds, resulting in irrelevant queries triggering the corresponding knowledge base. This occurs because keyword verification for branch triggers is not configured, causing non-target knowledge bases to be called.

## How to confirm the configuration is complete
- Submit test coal mine job declaration materials, check whether each node executes in `nodeId` order.
- View `variables` variable transfer logs to confirm that fields such as working face ID and monitoring data have no format errors.
- Trigger irrelevant test queries, confirm whether the workflow jumps to the specified response according to the preset branches.
- Simulate a node timeout scenario, confirm the exception handling logic after the timeout threshold is triggered.
