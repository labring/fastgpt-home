# Declaration Materials and Case Review for Coal Mine Production: Model Access and Configuration

## What data for this category looks like
Data for coal mine production declaration materials and case review primarily comes from coal mine safety supervision systems, mine production scheduling ledgers, mine geological archive repositories, and administrative approval declaration forms. Data updates are conducted per single approval batch. The material update cycle for a single approval batch ranges from 1 to 7 days.
Single materials include structured fields such as mine number, mining scope coordinates, safety inspection report number, approval document number, and operating personnel qualification number. Units include meters, tons, cubic meters, hours, people, and other professional measurement standards. Some case files also contain unstructured content such as scanned mine layout diagrams and original safety inspection records.

## Constraints imposed on model access and configuration by these characteristics
Single materials can reach tens of thousands of characters. Configure a sufficiently large context window during model access to avoid truncating core review basis.
There are many specialized fields and units. Require the model to accurately identify and handle coal industry-specific terminology. Otherwise, review conclusion deviations may occur.
Some case files contain unstructured content in scanned format. Require the model to support visual understanding capabilities to extract information from diagrams and handwritten records.
Data update frequency is not fixed. Require vector database synchronization strategies that can be flexibly adjusted to adapt to material update rhythms of different batches.
The review process requires rigor and traceability. Require conclusions output by the model to be linked to original material fragments, avoiding vague judgments.

## How to set the configuration
| Configuration Item | Suggested Value | Basis for This Setting |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Single coal mine declaration material can reach tens of thousands of characters; requires complete context to conduct full review |
| `maxTokens` | 2000–3000 token | Case review requires detailed verification results; avoids truncating key conclusions due to output length limits |
| `quoteMaxToken` | 4000 characters | Requires quoting complete segments such as inspection reports and drawing annotations as review basis, to ensure quoted content is complete |
| `vision` | Enabled | Some cases contain scanned mine layout diagrams and safety inspection records; requires visual content recognition to complete review |
| `temperature` | 0.1–0.3 | Review requires rigor; reduces random output probability to avoid generating conclusions deviating from facts |
| `AIPROXY_API_ENDPOINT` | Locally deployed proxy forwarding address | When FastGPT v4.17.0 is deployed locally, proxy forwarding is required for external model invocation requests |
| `AIPROXY_API_TOKEN` | Authentication key assigned by the proxy | Ensures security of model interface calls, prevents unauthorized access |

## Three common mistakes
- Phenomenon: After locally deploying FastGPT v4.17.0, a new model is added, and testing returns a 403 status code (no body). Cause: `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` is not configured correctly, leading to interface authentication failure or invalid request address.
- Phenomenon: The model incorrectly identifies specialized units, for example, identifying "mine elevation +120 meters" as "120 tons". Cause: The model context configuration is not adjusted for the coal mine professional scenario, and industry-specific terminology prompts are not added, leading to insufficient recognition accuracy for specialized fields.
- Phenomenon: The prompt word of the conversation model in the workflow cannot identify space-separated fields, for example, "mine number 123" cannot be correctly extracted as an independent field. Cause: The prompt word does not explicitly specify space as the field separation rule, or the `temperature` setting is too high, leading to chaotic model output format.

## How to confirm the configuration is correct
- Upload a coal mine mining plan document with a length of approximately 10,000 characters, and test that the model output does not show context truncation-related prompts.
- Upload a case file containing scanned mine layout drawings, and test that the model can correctly identify the annotation information in the drawings and link it to the review conclusion.
- Call the model interface, confirm that the returned status code is 200, and the response content contains complete review results.
- Input test text containing specialized units, for example, "daily output 500 tons", and test that the model can accurately extract numerical and unit information.

The values provided are common starting points and should be measured against the reader's own samples.
