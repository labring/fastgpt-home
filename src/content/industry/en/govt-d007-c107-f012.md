# Declaration Materials and File Review for Coal Mine Production: Deployment and Upgrade

## What This Category’s Data Looks Like
Coal mine production declaration materials and file review data mainly comes from mine safety monitoring systems, production scheduling platforms, and official approval portals. Data updates trigger at approval workflow nodes. The update cycle for a single declaration material aligns with monthly or quarterly approval rhythms. File data syncs in real time alongside review progress.
Document structure includes fields such as mine number, approval item category, declaring entity information, safety compliance parameters, and attachment file list. Field units include tons, cubic meters, hours, batches, and others. Attachment types and volumes vary significantly for a single declaration material.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Multiple data sources require completing multi-system interface connection configuration during deployment to avoid data sync gaps. The mixed real-time and scheduled update rhythm requires retaining real-time sync links during upgrades to prevent loss of in-progress review file data. Fixed field structure requires completing field mapping configuration during deployment, and compatibility with old version field naming rules during upgrades to avoid parsing errors. A high share of large-volume attachments requires adjusting storage configuration thresholds during upgrades to support upload and indexing for large-capacity files.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://mine-user:mine-pass@host:27017/fastgpt_mine?authSource=admin` | Dedicated file database for connecting to coal mine safety monitoring systems, uses standard MongoDB port |
| `STORAGE_S3_ENDPOINT` | `http://minio.mine.local:9000` | Stores large-volume attachments such as drawings and test reports for coal mine declaration materials, compatible with intranet object storage deployment |
| `DB_MAX_LINK` | `20–30 connections` | Limits database connection count for single batch import of declaration materials to avoid overload |
| `REDIS_URL` | `redis://:redis-mine-pass@host:6379/0` | Caches real-time synced file review status to reduce database query pressure |
| `FILE_TOKEN_KEY` | `256-bit key, token validity period 3600 seconds` | Generates access tokens for declaration material attachments, complies with coal mine intranet security access rules |

## Three Common Mistakes
- Old-version workflow files fail to import after upgrade. The interface displays "unsupported workflow version". No prior conversion of old workflows to FastGPT v4.17.0 compatible format. Old node configurations conflict with new version field rules.
- MongoDB connection fails after source code deployment. Logs return "connection timed out" status code. Incorrect `MONGODB_URI` configuration. Docker container network mapping does not match local MongoDB instance port, preventing connection establishment.
- Some file data fails to sync normally during batch import of declaration materials. No reasonable value set for `DB_MAX_LINK`. Connection count exceeds database carrying limit, causing sync process interruption.

## How to Confirm Configuration Completion
- Run database connection test commands to verify that `MONGODB_URI` and `REDIS_URL` can establish connections compliant with intranet access permissions.
- Upload a single coal mine declaration material attachment to confirm that the `STORAGE_S3_ENDPOINT` configured storage path can normally read file contents.
- Import a small volume of test file data to check that the `DB_MAX_LINK` connection count limit takes effect, and that data sync has no abnormal interruptions.
