# Declaration Materials and Case Review for Power Grid Enterprises: HTTP Interfaces and External Systems

## What data for this category looks like
Data primarily comes from power grid enterprise marketing business application systems, project declaration management platforms, and internal case archiving repositories. Update cycles follow the submission deadlines of individual declaration projects and case archiving periods. A single declaration material document includes structured fields and attachment packages. Structured fields contain project number, declaring unit name, rated power supply capacity, approval status, and other items, with units uniformly following power industry standard units such as kilovolt-ampere and megawatt-hour. Case documents include audit circulation records, on-site inspection photos, and compliance verification reports. The text length of individual case documents varies widely, ranging from hundreds to thousands of characters.

## What constraints do these characteristics impose on the HTTP interfaces and external systems link
The standardized unit requirement for structured fields means interfaces must verify field formats and units during data synchronization, to prevent audit failures caused by unit mismatches. The presence of attachment packages in documents requires HTTP interfaces to support multipart/form-data requests for transmitting binary content such as qualification documents and inspection photos. The wide range of text lengths requires interfaces to be configured with reasonable timeout thresholds to avoid interruptions during long document transfers. The update cycle tied to project nodes requires interfaces to support incremental pull interfaces, reducing data interaction pressure between external systems and FastGPT. Additionally, the compliance requirements for power grid data mean interfaces must carry valid authentication parameters to meet industry security specifications.

## Three common mistakes
- An interface call returns a 514 status code, with an error message indicating permission verification failure. The cause is incorrect configuration of the `Authorization` parameter, or use of an expired internal power grid authentication key.
- The `responseData` field returned by the interface is empty. The cause is incorrect mapping of structured fields from power grid declaration materials, preventing FastGPT from extracting valid audit data.
- Interface request timeout. The cause is insufficiently configured timeout period, or transmission of an oversized attachment package exceeding the interface's carrying limit.

## How to confirm the configuration is correct
- Execute a curl command to call the configured HTTP interface, verify whether the returned `responseData` contains the expected power grid declaration material fields.
- Review interface authentication logs to confirm that the `Authorization` parameter was correctly verified and passed.
- Upload a test power grid declaration case document, verify whether the interface can normally pull and return structured data.
- Simulate an incremental pull request, confirm that only newly added declaration project data is returned.
