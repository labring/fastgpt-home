# Declaration Materials and Case Review for Power Grid Enterprises: Multi-turn Dialogue and Prompt Engineering

## Characteristics of This Type of Data
Power grid enterprise declaration materials and case review data primarily come from the marketing business application system, transmission operation and maintenance management system, and safety supervision and quality control management system. Data updates are triggered by project workflows. Declaration materials are updated when submitted. Cases are archived after review is completed.

Each document includes fields such as declaration subject qualification, project technical parameters, site inspection records, and review opinions. Many fields involve professional units, including voltage level (kV), equipment capacity (kVA), and approved working days. Document length varies widely, ranging from hundreds of characters to tens of thousands of characters.

## Constraints for Multi-turn Dialogue and Prompt Engineering Workflows
The professional fields and fixed formats of power grid declaration and case data impose specific requirements. Prompt engineering must clearly define field matching and format output rules. This prevents generation of content that does not comply with review specifications.

Multi-turn dialogue must be bound to a unique case identifier. Without this binding, context mixing may occur. This leads to review results associated with incorrect projects.

The wide span of data lengths means long case content may exceed dialogue context limits. Targeted context truncation strategies must be configured.

Declaration materials submitted in real time must be synchronized to the knowledge base. Otherwise, multi-turn dialogue will generate review opinions based on outdated data.

## Configuration Settings

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique case identifier as the session ID | Distinguish dialogue contexts for different declaration projects, avoid context mixing and incorrect case association |
| `messages` | Concatenate session history to no more than 8000 tokens | Adapt to the wide span of power grid case document lengths, avoid context overflow |
| `variables` | Inject fixed fields such as project number and unified social credit code of the declaration subject | Bind exclusive case data during multi-turn dialogue, ensure accurate review basis |
| Prompt template | Clearly require responses based on power grid declaration specifications and case archiving requirements, limit output to structured review opinions | Match the fixed formats and professional requirements of power grid reviews |
| Session timeout period | 600 seconds | Adapt to the time required for multi-round material verification, avoid session interruption mid-process |
| Context truncation rule | Retain the most recent 20 rounds of dialogue and core case fields | Filter redundant information, focus on valid data for the current review phase |

## Three Common Misconfigurations
- Symptom: Session ends abruptly mid-execution with no error prompt. Cause: Failure to bind `chatId` leads to lost context, and the workflow cannot associate subsequent case data.
- Symptom: Dialogue times out, with a session timeout prompt displayed on the interface. Cause: Session timeout period is set too short, not adapting to the time required for multi-round verification of power grid case reviews.
- Symptom: Subsequent questions in multi-turn dialogue do not reference previous review opinions, and the prompt only takes effect once. Cause: The `messages` parameter is not configured correctly, and historical dialogue context is not retained, leading to subsequent sessions being unable to associate previous review conclusions.

## How to Verify Proper Configuration
- Import a real power grid declaration case, initiate the first round of questions, and verify that the injected `variables` include case-specific fields.
- Initiate multiple consecutive rounds of questions, check whether the session retains historical dialogue content, and no context loss or mixing occurs.
- Simulate a long session process, verify that the session timeout period adapts to the required operation duration for review, and no mid-process interruption occurs.
- Adjust the prompt template, check whether the output content complies with the fixed format and professional requirements of power grid reviews.
