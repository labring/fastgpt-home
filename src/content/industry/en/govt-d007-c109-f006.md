# Power Grid Enterprise Declaration Materials and Case Review: Citation Sources and Traceability

## What this category of data looks like
Data for power grid enterprise declaration materials and case review comes from internal project declaration systems and case archive management systems. The system triggers updates when project declarations are submitted or reviews are completed. Daily archive volume fluctuates with business cycles.

Document structure includes structured metadata (declaration number, project category, declaring unit, review status) and unstructured attachments (project approval applications, qualification certification PDFs, energy consumption calculation Excel files, etc.). Each field has clear business meaning, and the declaration number is a globally unique identifier. Attachment sizes range from tens of KB to tens of MB. The text length of a single declaration material varies widely.

## What constraints these characteristics impose on the citation sources and traceability workflow
For structured metadata, traceability workflows must bind to a unique identifier field. Without this binding, teams cannot accurately distinguish declaration materials of different projects and avoid cross-project confusion.

Unstructured attachments come in diverse formats. Traceability configuration must support parsing and chunking of multiple formats such as PDF and Excel to ensure that attachment content can be properly retrieved.

Update triggers tie knowledge base synchronization directly to the review process. This prevents the system from synchronizing temporary materials that have not completed review.

The wide range of text lengths for single declaration materials requires citation token configurations to cover common length intervals. This avoids truncating key review basis.

## How to set the configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average text length of single documents for power grid declaration materials, avoiding truncation of key review basis and case details |
| `responseData` | Structured format with metadata fields | Power grid declaration materials need to be associated with business fields such as declaration number and review node. Structured return facilitates manual traceability and verification |
| `detail` | Enabled | Case review materials include multi-page attachments and table content. When enabled, complete source snippets can be displayed to meet on-site verification needs |
| Context recall upper limit | Top 6 entries | Power grid project declaration materials have strong relevance. Too many recalls will interfere with current question-and-answer logic, calibrated based on actual testing |

## Three common configuration errors
- The symptom is that citation sources display unrendered Markdown formatted text. The cause is that the document format parsing configuration is not enabled, so tagged content from original chunks is output directly.
- The symptom is that the corresponding case cannot be matched through the business identifier during traceability. The cause is that unique fields such as declaration number are not bound in the knowledge base configuration, leading to failure of source association.
- The symptom is that retrieved source snippets exceed the expected length. The cause is that the `quoteMaxToken` value is set too large, introducing irrelevant content from non-current project materials.

## How to confirm the configuration is correctly set
- Upload a standard power grid declaration material, initiate a question that includes "view the project declaration basis", and check the returned citation source snippets to confirm that the format is rendered normally.
- Extract the declaration number field from the citation source, and verify that it completely matches the corresponding metadata field of the uploaded document.
- Adjust the value of `quoteMaxToken`, and observe whether the length of the returned citation snippet meets the configuration expectations.
- Initiate a second related question to confirm that the context can still be associated with the correct declaration project case, and no cross-project confusion occurs.

The values listed above are common starting points and should be evaluated against your own samples.
