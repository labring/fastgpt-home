# Mining and Mineral Processing: Declaration Materials and Case Review — Multi-turn Dialogue and Prompt Engineering
This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Data for mining and mineral processing declaration materials and case review comes primarily from official documents required by natural resource and emergency management departments, including mining right applications, mineral processing production filings, safety compliance case records, plus internal enterprise production ledgers.
Data updates align with single declaration workflows or annual compliance checks, and are completed within a single declaration cycle.
Documents are mostly multi-page PDFs or structured tables. Core fields include mining right number, mineral processing throughput, and safety inspection record number. Common units are thousand tons, tons per day, and batches.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The long documents and multi-field professional nature of mining and mineral processing declaration materials and review cases require multi-turn dialogue context to cover complete material fragments for at least one single batch of declarations. This prevents loss of critical professional parameters.
The corresponding relationship between professional units and dedicated fields requires prompts to clearly bind the exclusive meanings of fields such as mining right number and mineral processing throughput. This prevents parameter confusion.
The data update rhythm within a single declaration cycle requires dialogue context to retain submission node information for the current batch. This ensures the review process can link batch records from historical cases.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `messages` | 8–12 previous conversation turns | Single batch mining review requires linking 3–5 case files. 8–12 turns can cover complete interactions of declaration explanations, case supplements, and review opinions, avoiding loss of professional parameters due to context overflow. |
| `chatId` | Bind to current declaration batch ID | Ensure multi-turn dialogue context only links to case files of the corresponding batch, aligns with batch management rules for mining and mineral processing declarations, preventing cross-batch data confusion that affects review accuracy. |
| Maximum context | 8000–12000 characters | Structured content of a single mining declaration case file is approximately 3000–5000 characters. This range can cover content from 2 complete case files plus declaration explanations, adapting to long document review needs. |
| `variables` | Bind to mining right number, mineral processing throughput fields | Pass enterprise-specific fields as global variables into prompts, ensuring review dialogues can accurately match historical case data for the corresponding mining right, avoiding field confusion. |
| Prompt template | Classification-based review check rules by declaration batch | Mining and mineral processing declarations must comply with exclusive compliance requirements for mining rights and mineral processing procedures. The template must bind check logic for professional fields, ensuring review results align with industry standards. |

## Three common mistakes
- Phenomenon: The number of chat records is set to 0 in the workflow, and multi-turn dialogue cannot link historical review opinions. Cause: The `messages` parameter is not used to pass historical dialogue context, only the content of the current single question is used, making it impossible to link previous case supplement explanations.
- Phenomenon: The review results returned after calling the interface do not match the current mining right number. Cause: Dedicated fields are not bound via `variables`, so the prompt cannot accurately locate declaration materials for the corresponding batch.
- Phenomenon: The text content extraction node in the workflow fails to obtain complete case file content. Cause: Insufficient context length is set, only the declaration summary of the first few pages is extracted, and core parameters such as mineral processing throughput are omitted.

## How to confirm the configuration is correct
- Initiate multi-turn questions containing historical review opinions, check whether the reply links to the previously mentioned case number.
- View the `messages` parameter log returned by the interface, confirm that the number of passed conversation history matches the configured value range.
- Test questions bound to dedicated fields, check whether the reply accurately matches the declaration materials corresponding to the mining right number.
- Check the context configuration in the workflow, confirm that no prompts indicating context length exceeding the preset range appear.
