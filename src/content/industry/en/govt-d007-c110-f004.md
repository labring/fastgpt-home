# Declaration Materials and File Review for Mineral Mining and Processing: Workflow Orchestration

## What This Category of Data Looks Like
Data mainly comes from mineral resource reserve verification reports, safety production license declaration documents, mineral processing production ledgers, and safety supervision filing files. It is updated and synced separately by mine technical departments, administrative office departments, and local supervision departments. Single-use declaration materials are generated on demand according to project milestones. File data is archived monthly. Documents include structured fields (mining license number, mining depth, mineral processing throughput) and unstructured attachments (on-site survey photos, process flow diagrams). The length of individual file documents varies widely, ranging from thousands to tens of thousands of characters.

## Constraints on Workflow Orchestration From These Data Characteristics
Mixed-structured documents require workflows to split parsing nodes. Handle structured field extraction and unstructured attachment parsing separately to avoid excessive load on single nodes.
The wide range of document lengths requires workflows to set context input limits. This adapts to input content of different lengths.
The update rhythm of on-demand declaration materials and monthly archived files requires workflows to support both manual and scheduled trigger modes. This adapts to different business scenarios.
The requirement for multi-source data synchronization requires workflows to configure data verification nodes. Check field consistency across submissions from different departments to avoid entry errors.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Trigger Mode | Manual trigger + scheduled trigger (daily 00:00 archive verification) | Adapts to the business rhythm of on-demand declaration material submission and monthly file archiving |
| Context Input Limit | 15000–20000 characters | Adapts to the wide length range of individual file documents, from thousands to tens of thousands of characters |
| Node Parallelism | Parallelize the first 2 nodes, serialize subsequent nodes | Avoids resource conflicts during multi-document parsing |
| `variables` Configuration | Bind fields such as mining license number and mineral processing throughput | Extract structured data for subsequent verification and flow transfer |
| `nodeId` Configuration | Assign a separate ID to the attachment parsing node | Distinguish structured and unstructured processing workflows |
| Timeout Threshold | 600 seconds | Adapts to the processing duration of long document parsing |

## Three Common Misconfiguration Issues
- Phenomenon: After an HTML output node configured in the workflow runs, there is no corresponding output content, and the workflow proceeds directly to the next branch. Cause: The HTML generation result is not bound to the `variables` parameter, so the content is not included in the workflow transfer link.
- Phenomenon: Workflow execution times out, and the system returns a timeout prompt. Cause: No reasonable timeout threshold is set, and the system default limit is exceeded during long document parsing or multi-node series connection.
- Phenomenon: After the tool call is completed, the output result includes redundant input and response log fields. Cause: No filtering rule to retain only business results is configured in the output node, and full workflow intermediate data is returned by default.

## How to Verify Successful Configuration
- Manually trigger the parsing workflow for a single declaration material, and check whether the extracted structured fields match the source document.
- Upload test documents of different lengths, and confirm that workflow nodes do not trigger interruptions due to input limit exceedance.
- Trigger manual tasks and scheduled tasks separately, and confirm that the workflow executes according to the preset rhythm.
- Run the tool call node, and check whether the output result retains only business answers, with no additional workflow log fields.
