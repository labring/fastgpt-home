# Mining and Mineral Processing Declaration Materials and File Review: Document Parsing and Chunking

## What This Category of Data Looks Like
Declaration materials and dossier data for mining and mineral processing primarily come from mining right application ledgers, geological exploration reports, mineral processing process design documents, monthly production Excel ledgers, and approval dossiers.
Data updates are triggered by project progress or quarterly approval batches, with no fixed daily update rhythm.
Documents include structured approval tables (with fields such as mining area turning point coordinates, mining scale, mineral processing recovery rate, and resource reserves), unstructured PDF exploration reports, and docx format process documents.
Most field units are tons, cubic meters, %, years, and grams per ton. Some documents contain cross-page tables and embedded formulas.

## Constraints Imposed on Document Parsing and Chunking
Cross-page splitting of structured approval tables can cause loss of association between fields like mining area coordinates and mining scale. Parsing logic must retain table structure.
Long-text geological exploration reports contain many technical terms and formulas. Chunking must avoid breaking professional paragraphs, or retrieval semantic accuracy will be compromised.
Multi-page approval dossiers have large single-file volumes, which can easily trigger default parsing timeout limits.
Excel production ledgers have cross-column classified data such as usage location, mining volume, and mineral processing grade. Parsing must retain column association, or retrieval cannot accurately match classified fields.
Docx format process documents have multi-level section headings. Chunking must associate headings with main text, or context information will be lost.

The following configurations are adapted for FastGPT v4.17.0.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of mining and mineral processing professional documents, avoids splitting technical term combinations |
| `chunkSplitter` | Split by title + paragraph | Matches the chapter structure of declaration materials, retains context association between titles and main text |
| `customPdfParse` | Enable table retention mode | Solves the problem of field loss in cross-page tables, meets the structured table requirements of exploration reports |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of multi-page approval dossiers, avoids timeout failures for large files |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types such as PDF, Excel, and docx, adapts to multi-format declaration data |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Allows uploading large exploration report PDF files, meets the submission requirements of project-level declaration materials |

## Three Common Configuration Errors
- Phenomenon: When retrieving Excel production ledgers, the number of matching results for overseas usage locations is far fewer than the actual entries in the source file. Reason: Parsing did not retain cross-column classified field association, causing the usage location field to be incorrectly split or filtered.
- Phenomenon: When uploading a single exploration report PDF with more than 150 pages, the parsing task triggers a timeout error. Reason: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted to a value suitable for multi-page dossiers, and the default timeout duration is insufficient.
- Phenomenon: Retrieval results for docx format mineral processing process documents do not include section heading information. Reason: The chunking configuration did not enable title-based splitting logic, only splitting by fixed character length, losing the association between sections and main text.

## How to Verify Correct Configuration
- Upload a single exploration report PDF with more than 100 pages, and confirm that the parsing task completion duration matches the setting of `PARSE_FILE_TIMEOUT_SECONDS`.
- Retrieve classified fields in the Excel ledger, and verify that the number of matching results matches the corresponding classified entries in the source file.
- View chunked document fragments, and confirm that section headings and corresponding main text are included in the same chunk.
- Upload a single large docx format process document, and confirm that the chunked results retain cross-paragraph professional content association.
