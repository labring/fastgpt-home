# Mineral Mining and Beneficiation: Declaration Materials and Case File Review — Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for mineral mining and beneficiation declaration materials and case file review comes primarily from mining right application documents, mineral processing production ledgers, safety supervision filing case files, reserve verification reports, and on-site acceptance records. Data updates follow project approval progress or annual production cycles. The document length of single declaration materials varies widely, ranging from hundreds-of-word preliminary review forms to hundreds-of-thousand-word comprehensive demonstration reports. Documents include fixed fields such as mining area scope coordinates, mineral processing recovery rate, safety facility acceptance number, and more. Units cover multiple measurement standards including tons, cubic meters, and percentage.

## What constraints these characteristics impose on knowledge base retrieval and recall
The wide range of document lengths creates challenges for chunking. Overlong case files must be split appropriately to avoid semantic fragmentation. Multiple measurement units require matching unit consistency during retrieval to prevent recall failures due to mismatched units. Data updated alongside project progress must be synchronized to the knowledge base regularly. Otherwise, outdated parameters will not match current declaration requirements. Standardized fixed fields require prioritizing precise field matches such as project numbers and mining area coordinates during retrieval, to improve recall targeting.

## Three common configuration mistakes
- `quote type error` appears, with an interface prompt indicating abnormal input variable format. The cause is that knowledge base field variables referenced in declaration materials are not wrapped per required rules, and do not match the system's required format.
- A query that exactly matches a knowledge base chunk content cannot recall results. Recalling works normally after creating a new identical knowledge base. The cause is that the original knowledge base's vector encoding has not been updated, or the old chunk's metadata tags are not configured correctly.
- New declaration material information cannot be added to the knowledge base in real time during a conversation. The cause is that the knowledge base's dynamic write permission is not enabled, or the incremental sync trigger condition for the corresponding scenario is not configured.

## How to confirm configuration is complete
- Submit a standard declaration query that includes mining area coordinates, and verify that all returned results originate exclusively from the mineral mining and beneficiation dedicated knowledge base.
- Adjust the `similarity` parameter value, and confirm that the relevance of recalled results changes as expected with the parameter.
- After enabling `usingReRank`, check that returned results are sorted to prioritize matching core declaration fields.
- Test adding a single case file entry dynamically, and confirm that the knowledge base can update in real time and participate in subsequent retrieval.
