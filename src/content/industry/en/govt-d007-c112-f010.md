# Grain Reserve Declaration Materials and File Review: Knowledge Base Retrieval and Recall

## What data for this category looks like
Data for grain reserve declaration materials and file review primarily comes from three sources: rotation declaration forms from grassroots grain depots, annual grain reserve inspection files, and policy-based grain purchase and storage vouchers. Data update cycles follow grain depot rotation plans and annual inspection schedules, with no fixed full update window. Incremental updates mostly consist of single-batch declaration documents or single archived files. Document structure includes two categories: structured fields and unstructured text. Structured fields include warehouse number (six-digit code), grain variety (wheat/rice/corn), storage volume (unit: ton), and declaration date. Unstructured text is content from scanned file pages recognized via OCR, with some garbled characters present.

## What constraints these characteristics impose on knowledge base retrieval and recall
The mixed format of structured fields and unstructured text requires retrieval to support both precise field matching and semantic recall. This avoids missed or false detections caused by relying solely on a single retrieval mode. The lack of a fixed full update window requires the knowledge base to support on-demand incremental synchronization. Frequent full index rebuilds should be avoided to prevent excessive computing resource usage. Garbled OCR text in documents requires the retrieval link to have result reranking capabilities, to filter semantically irrelevant recall results. The storage volume unit is fixed as tons, so retrieval must ensure unit matching to avoid invalid recalls caused by inconsistent units.

## How to configure
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Grain reserve declaration materials have fixed formats. This threshold filters irrelevant daily warehouse operation records while retaining valid declaration content with matching formats |
| `limit` | `Top 8–12 results` | A single declaration document typically involves no more than 10 warehouse numbers and grain varieties. Retrieving too many results will exceed the context window |
| `searchMode` | Hybrid retrieval | Balances structured field matching and semantic recall for unstructured OCR text, adapting to the mixed format data characteristics of this category |
| `usingReRank` | Enabled | Scanned file OCR text contains garbled formatting. Reranking filters semantically irrelevant recall results and improves retrieval accuracy |
| `datasetSearchUsingExtensionQuery` | Enabled | Declaration material field names are fixed. Extended queries support synonym matching, such as associating "rotation volume" with "outbound volume" |
| `collectionIds` | Bind dedicated grain reserve dataset ID | Restrict retrieval scope to only knowledge base content for this category, avoiding mixing data from other warehouse categories |

## Three common misconfigurations
- Issue: The `fail to create post presigned url` error occurs when uploading declaration material PDFs or CSVs. Cause: FastGPT S3 storage access credentials are not configured correctly, or the storage path for the corresponding dataset is not bound.
- Issue: Retrieval results include non-grain reserve warehouse data, making it impossible to accurately recall target content. Cause: The `collectionIds` parameter is not set, or an incorrect dataset ID is bound.
- Issue: In local deployment scenarios, after enabling enhanced PDF parsing, grain reserve warehouse bill scan documents cannot be parsed normally. Cause: The minerU service is not confirmed to be running properly and associated in the FastGPT backend, or `usingReRank` is not enabled to adapt to garbled OCR text.

## How to confirm the configuration is correct
- Upload a test grain reserve declaration CSV, check that the upload completes normally with no storage-related errors.
- Enter the test query "2024 Q3 wheat rotation declaration materials", check that recall results only include content from the bound dataset.
- After enabling `usingReRank`, enter a query containing garbled warehouse numbers, check that the semantic relevance of recall results has improved.
- View the dataset synchronization logs in the knowledge base backend, confirm that incremental update frequency matches the actual rhythm of depot declarations and archiving.

The values provided are common starting points and should be measured against the reader's own samples.
