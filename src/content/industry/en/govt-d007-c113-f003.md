# Declaration Materials and File Review for Shipbuilding: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Shipbuilding declaration materials and file data mainly come from shipyard construction departments, classification society review systems, and maritime supervision platforms. Data updates follow construction milestones. Batch updates trigger at key milestones including sectional construction, launching and sea trials, and completion acceptance. A single file typically includes documents such as declaration letters, hull parameter tables, weld inspection reports, and stability calculation books. Core fields include ship length (unit: meters), draft depth (meters), main engine rated power (kilowatts), declaration batch number, and classification society certification number. The core content of a single declaration document ranges from 800 to 1200 characters.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
First, core documents for a single file are lengthy. Limit context length for multi-turn dialogue to avoid exceeding model processing limits.
Second, fields use ship engineering-specific professional units. Include clear requirements in the prompt for the model to use specified units when outputting results to prevent format errors.
Third, construction data updates in real time with milestones. Sync the latest global variable values during multi-turn dialogue, do not rely on initialized static data.
Fourth, files must link to their corresponding construction batch. Bind exclusive context via `chatId` to avoid mixing declaration data from different batches.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current shipbuilding batch | Associate all historical dialogues for the same batch of declarations, avoid confusion of data from different batches |
| `messages` | Retain the most recent 20 rounds of dialogue content | A single ship declaration document can be up to 800 to 1200 characters in length; excessive context will exceed the model's token limit |
| `variables` | Update the latest declaration data of global variables in each round of dialogue | Ship construction milestone data is updated daily, so the latest parameters need to be synchronized in real time |
| Maximum context length | 12000 characters | The total of core fields and historical dialogues of a single file usually does not exceed this value |
| Temperature setting | 0.2-0.4 | Review scenarios require rigor, avoid generating content that deviates from facts |

## Three Common Misconfigurations
- Phenomenon: Global variable changes do not take effect in subsequent dialogues. Cause: The variable synchronization logic for each round of dialogue is not enabled in the `variables` configuration, and only the initial static value is loaded during initialization.
- Phenomenon: The content of a single round of dialogue cannot be identified independently. Cause: The round structure of the `messages` parameter is not correctly split, and multi-turn dialogues are processed as a single segment.
- Phenomenon: Dialogue response time exceeds 600 seconds. Cause: The number of retained rounds of `messages` is not limited, resulting in excessively long context that triggers model timeout.

## How to Verify Proper Configuration
- Initiate the first declaration parameter query, confirm that the fields and units of the initial global variables are displayed correctly.
- Initiate a dialogue to modify construction parameters, confirm that the updated variable values are correctly loaded in subsequent dialogues.
- View the dialogue log, confirm that the batch identifier bound by `chatId` matches the currently operated construction batch.
- Test three consecutive questions, confirm that each round of questions is independently identified and associated with the corresponding context.
