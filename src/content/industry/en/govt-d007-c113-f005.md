# Declaration Materials and File Review for Shipbuilding: Tool Calling and Plugins

## What the data for this category looks like
The data for declaration materials and file review in shipbuilding mainly comes from classification society inspection documents, ship construction process ledgers, design drawing approval records, and material incoming inspection submission forms. Data updates follow the single-ship construction cycle, with new content added in stages from launch filing to delivery acceptance. The document structure includes structured parameter sections and long-text record sections. Structured fields include hull steel number (unit: millimeter), main engine power (unit: kilowatt), and total tonnage (unit: ton). Long-text sections include process inspection reports, rectification notices, and similar content. Each file is bound to a unique ship inspection number as its identifier.

## What constraints these characteristics impose on the "tool calling and plugins" link
The single-ship exclusive nature of ship files requires tool calling to be bound to a unique ship inspection number to avoid cross-ship data confusion. The mixed document structure of structured fields and long text requires tool calling to support both structured field extraction and unstructured text parsing modes. General logic alone cannot handle all content. Fixed unit rules require tool calling plugins to include built-in unit verification logic to prevent parameter format errors. The staged update feature requires tool calling to dynamically match the file content of the current construction stage without loading full historical data.

## How to set the configurations
In FastGPT v4.17.0, tool calling and plugin configurations must match the characteristics of the shipbuilding scenario, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Enable structured field extraction mode | Matches the characteristic that ship files contain structured parameters such as hull steel number and main engine power |
| Maximum context per single tool call | 8000–12000 token | Adapts to the text length range of core declaration materials for a single ship, calibrated based on actual testing |
| Tool call timeout | 600 seconds | Meets the processing cycle requirements for complex inspection record parsing |
| Knowledge base association rule | Bind exclusive knowledge base by ship inspection number | Ensure only declaration and file data for the corresponding single ship is called |
| `toolChoice` | Fixed call of specified tools | Avoid repeated tool calls, matches the fixed verification process of ship file review |
| Result format verification | Enable unit consistency verification | Adapts to the fixed unit requirements for ship parameters, such as millimeter, kilowatt, ton |

## Three common errors
- Phenomenon: Tool call nodes execute repeatedly, with logs showing repeated triggering of the same verification logic. Cause: `toolChoice` is not set to fixed call mode, causing the workflow to repeatedly trigger tool calls.
- Phenomenon: Structured field extraction results are empty, with extraction failure displayed on the interface. Cause: The structured mode of `functionCall` is not enabled, and only general text parsing logic is used, which cannot match the fixed field rules of ship parameters.
- Phenomenon: Tool call times out, returning status code 504. Cause: The single call context is set too small and does not cover the text length of the complete single-ship declaration materials, resulting in unfinished parsing.

## How to confirm the configuration is correct
- Submit the single-ship inspection number as a variable to trigger the workflow, check that the tool call is executed only once.
- After extracting structured fields, verify that the units of parameters such as hull steel number and main engine power match the preset rules.
- Check the workflow logs to confirm that no timeout error is triggered for the configured tool call timeout setting.
- Verify that the knowledge base only associates file data for the current ship inspection number, with no cross-ship data mixed in.

The values provided here are common starting points and should be measured against the reader's own samples.
