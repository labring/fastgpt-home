# Rail Transit Equipment Declaration Materials and File Review: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Rail transit equipment declaration materials and file data originates from design output documents of equipment development units, third-party test reports, and internal approval files. Updates are completed alongside a single declaration batch, with no additional updates during the single declaration cycle. Most documents are structured PDFs and structured tables. They include fields such as project number, equipment model, key performance parameters, compliance check items, and approval circulation records. Most parameter units use common engineering units such as millimeters (mm), megapascals (MPa), and newtons (N). The length of a single document falls between 5000 and 15000 characters.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words workflow
The structured fields and specialized units in rail transit equipment declaration materials require consistent matching of field names in multi-turn dialogue prompt words, to avoid parameter identification errors. Single documents have substantial length, so the number of document chunks loaded per context round must be limited, to prevent exceeding the context window. Declaration batch updates have no fixed cycle, so support is required for dynamically calling documents from a specified knowledge base ID. File review requires tracing approval circulation nodes, so multi-turn dialogue must retain context of historical approval records, to avoid repeated checks of the same step.

## Three Common Misconfigurations
- Phenomenon: Historical declaration files are automatically loaded during multi-turn dialogue. Cause: `chatId` is not bound to the current declaration batch, so the system defaults to associating with global context.
- Phenomenon: An error occurs when setting a knowledge base ID variable. Cause: `variables` is not configured for global persistence, or the variable format does not meet system requirements.
- Phenomenon: Some dialogues do not retrieve the declaration material knowledge base, and return generic responses. Cause: The prompt words do not explicitly require calling the knowledge base, or the context window overflows, causing knowledge base recall to fail.

## How to Verify Correct Configuration
- Upload a single rail transit equipment declaration document, initiate the first dialogue, and confirm that returned results only link to the currently uploaded document.
- Initiate a multi-turn dialogue, enter a question containing specialized parameters, and confirm that the system correctly identifies fields corresponding to units such as millimeters (mm) and megapascals (MPa).
- Attempt to update a global variable, initiate a new dialogue, and confirm that the variable value is retained without being reset.
- Initiate a review request that relies on the knowledge base, and confirm that the system always calls the declaration material knowledge base, without returning generic responses.
