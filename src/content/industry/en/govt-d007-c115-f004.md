# Rail Transit Equipment Declaration Materials and File Review: Workflow Orchestration

## What the Data for This Category Looks Like
The data for rail transit equipment declaration materials and files primarily comes from four core sources: R&D design drawings, type test reports, production batch records, and compliance qualification certificates. It is updated in batches alongside individual declaration projects, with no fixed daily update schedule. A single file typically includes a fixed-structure declaration form, multi-page test data tables, and numbered qualification scan copies. Fields cover axle load, operating speed, certification validity period, production batch number, and similar items, with corresponding units of kilonewtons, kilometers per hour, year/month/day, and batch identification numbers.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
The mixed structure of multimodal and plain text data requires workflows to split processing nodes by data type to avoid redundant parsing. The strict constraints of fixed fields and units require workflows to include a parameter verification link to ensure declaration data meets standardized requirements. Batch declaration scenarios require workflows to support batch triggering and hierarchical node permissions, with nodes in different review links bound to corresponding approval roles. The combination of long documents and multimodal data also requires workflow context carrying capacity to adapt to the total data volume of a single file.

## Three Common Misconfigurations
- Failure to split multimodal and plain text processing nodes in the workflow leads to redundant multimodal parsing when plain text nodes call tools, resulting in unexpected final output. This occurs because branch logic is not configured based on input data type, and corresponding processing models are not bound via `nodeId`.
- When the workflow calls knowledge base search, the number of returned results does not match the global configuration. This occurs because the global knowledge base reference limit is incorrectly applied to workflow nodes, and the single search limit parameter within the workflow is not adjusted separately.
- Field truncation or unit recognition errors appear after parsing long declaration documents. This occurs because the chunk length is set too short, preventing complete associated recognition of cross-chunk fields and units.

## How to Verify Proper Configuration
- Upload a single complete declaration file, trigger the workflow, and check if the input and output data of each node match the preset field and format requirements.
- Pass a plain text declaration form and a multimodal drawing file separately, verify that corresponding nodes only process data of the matching modality.
- View workflow logs, confirm that frequent node timeout errors do not occur after the timeout period is set.
- Manually modify the unit field in the declaration material, verify that the variable verification node triggers an exception prompt.
