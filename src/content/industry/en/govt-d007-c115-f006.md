# Rail Transit Equipment Declaration Materials and File Review: Citation Sources and Traceability

## What this category of data looks like
Data for rail transit equipment declaration materials and file review primarily comes from enterprise R&D management systems, quality control platforms, and compliance declaration systems. Data updates follow individual project delivery cycles, with staged updates aligned with R&D progress. Document structures primarily include structured component parameter tables, long-form compliance descriptions, and test report attachments. Fields include component model, test batch, compliance number, and test values, with units such as mm, kN, km/h and other industrial standard units. Individual case files have a relatively high average text length.

## What constraints these characteristics impose on the citation sources and traceability link
Rail transit equipment declaration materials and case files have many structured fields and unique compliance numbers. This requires precise matching of fields and numbers during traceability to avoid errors caused by generalized extraction. A high proportion of long-form documents consumes significant context tokens. Total token volume for single-round citations must be limited to prevent context overflow. Data is updated by project batch, so the knowledge base must isolate data by project version to ensure traceability references valid documents from the corresponding batch. Unique compliance numbers serve as core identifiers, and must be prioritized for matching during citation traceability to ensure results align with the target project batch.

## Three Common Misconfigurations
- Phenomenon: Citation sources are not displayed on the official chat page, only visible on the debug page. Cause: The `responseData` configuration item is not enabled, and temporary citation data is only cached in debug mode.
- Phenomenon: The number of citations exceeds the preset upper limit but additional results are returned. Cause: `quoteMaxToken` was mistakenly interpreted as a limit on the number of citations, the citation number matching rule was not set correctly, or the configuration did not take effect in the workflow.
- Phenomenon: The text extraction component cannot extract structured fields from knowledge base citations. Cause: The `detail` configuration item is not enabled, and complete structured data of cited documents is not returned, preventing the component from reading target fields.

## How to Confirm Proper Configuration
- Initiate a test query targeting a project’s declaration materials, and verify whether the document name and compliance number of the citation source are displayed on the chat page.
- Review the original data fields of the response to confirm that they include the original document content and path information returned by `responseData`.
- Submit test text that exceeds the preset token threshold, and observe whether the number of returned citations is limited to the preset range.
- Call the text extraction component to verify that it can read structured fields such as component model and test batch from cited documents.

The values provided are common starting points and should be evaluated against the reader's own samples.
