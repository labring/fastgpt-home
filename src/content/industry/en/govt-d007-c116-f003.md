# Declaration Materials and File Review for Telecommunications Engineering Construction: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The declaration materials and file data for telecommunications engineering construction mainly originate from project approval documents, quantity submission reports, construction supervision logs, completion acceptance opinions, and similar materials. Data updates follow project node progress, with batch submissions from the project initiation phase through the acceptance phase. The document structure is fixed, including fields such as project number, budget amount, construction period, number of base stations, and link bandwidth. The corresponding units for these fields are none, ten thousand yuan, day, each, and Mbps respectively.

## Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
The phased update characteristic of telecommunications engineering declaration materials and files requires that multi-turn dialogue binds session context to track project progress. The feature that fields carry professional units requires that prompt engineering clearly specifies unit recognition rules to avoid unit deviations in extraction results. The fixed document structure requires that prompt engineering matches preset field extraction logic to reduce interference from unnecessary information. Batch-submitted materials must be clearly associated with the corresponding project batch during dialogue to avoid context confusion.

## Three Common Misconfigurations
- Symptom: Knowledge base reference fields returned by dialogue are empty, or format does not match the preset field list. Cause: Structured fields of declaration materials are not bound to the `variables` parameter, causing retrieval results to fail to correctly associate with context.
- Symptom: The second round of dialogue cannot read output content from the first round, and a context gap appears. Cause: Dialogue session is not bound via `chatId`, leading to context loss.
- Symptom: Streaming output stutters or terminates prematurely, with returned content incomplete. Cause: A reasonable timeout parameter is not configured, or the context window is not adjusted according to the document length of telecommunications engineering files.

## How to Verify the Configuration Is Correct
- A single telecommunications engineering project initiation material is uploaded, and dialogue extraction results for project number and budget amount are tested to confirm that fields match the document structure.
- Two consecutive dialogue turns are initiated, and the `chatId` is checked for consistency to confirm that context is not lost.
- An API call is made to initiate a streaming request, and the returned data stream is checked for segmented output according to dialogue turns.
- The `variables` variable is bound before initiating a dialogue, and professional units such as Mbps and ten thousand yuan are checked for correct identification and display.
