# Declaration Materials and File Review for Telecommunications Engineering Construction: Citation Sources and Traceability

## What This Category of Data Looks Like
Data for declaration materials and file review for telecommunications engineering construction originates from declaration documents and archived files across the full project cycle of project initiation, approval, construction, and acceptance. Updates follow project progress phases: feasibility study and budget materials are submitted during the project initiation phase, progress reports are added during the construction phase, and final inspection materials are archived during the acceptance phase. Documents include structured fields such as project number, construction scope, budget amount, approval document number, and construction qualification certificates. Some documents include unstructured attachments such as engineering point coordinates and cable routing diagrams. Unit types include ten thousand yuan, number of base stations, kilometers, and other relevant units.

## Constraints Imposed by These Characteristics on Citation and Traceability
The declaration materials and files for telecommunications engineering construction have two core characteristics: phased updates, and a mix of structured and unstructured fields. These impose multiple constraints on the citation and traceability process. First, phased updated materials must be linked to the correct version corresponding to the project cycle, to avoid using expired initiation materials for acceptance review. Second, structured fields such as project number and approval document number must act as core traceability identifiers, ensuring that citations point to original materials from specific approval nodes. Third, unstructured engineering drawing attachments must be processed into text and linked to corresponding structured metadata, to avoid losing original drawing-based evidence when only text content is matched during traceability.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Reference Token Count | 800–1200 token | Matches the average text length of a single declaration material, adapts to the text truncation rules of FastGPT v4.17.0, and avoids truncating core approval documents |
| Reference Data Source Scope | Only the knowledge base associated with the current project | Limits traceability scope to the corresponding engineering files, avoids referencing unrelated materials across projects |
| `quoteMaxToken` | 600–1000 token | Adapts to the single-segment text recall length during file review, ensuring coverage of complete approval opinions and budget details |
| `responseData` | Enable structured metadata return | Extracts core identifiers such as project number and approval document number, improving traceability accuracy |
| `detail` | Enable detailed traceability display | Shows specific paragraphs or attachment locations of original documents, improving review credibility |
| Single Recall Result Count | Top 3–5 entries | Matches the number of associated supporting materials for a single project’s declaration, avoiding excessive redundant information interfering with review |

## Three Common Misconfigurations
- Phenomenon: Search results show that file materials are cited, but the generated review opinion does not include the approval document number content from the knowledge base. Cause: The `responseData` configuration is not enabled, and structured metadata is not extracted as an associated basis, resulting in generated content that cannot match the original fields.
- Phenomenon: Only text-based declaration materials are recalled, and the textized content of engineering drawing attachments is not cited. Cause: No text preprocessing is performed on unstructured attachments, or recall rules for associated metadata are not configured, resulting in drawing data not being correctly identified.
- Phenomenon: After calling the API and passing the workflow, the knowledge base of the specified project is not associated, and global knowledge base content is called instead. Cause: The knowledge base identifier corresponding to the project is not bound in the workflow parameters, resulting in the default use of the global knowledge base scope.

## How to Verify Proper Configuration
- Submit a test question containing a known approval document number, check whether the generated content includes the document number, and the citation source marks the project number of the corresponding file.
- Upload an engineering drawing attachment and perform text processing, initiate a relevant search, and confirm that the recall results include the text content of the attachment.
- View the data source binding item in the workflow configuration, confirm that only the knowledge base associated with the current project is selected, and the global knowledge base option is not checked.
- View the return results of the `detail` configuration, confirm that each citation marks the specific paragraph or attachment location of the original document.
