# Declaration Materials and File Review for Telecommunications Engineering Construction: Document Parsing and Chunking

## What this category of data looks like
Data for declaration materials and file review in telecommunications engineering construction mainly comes from documents such as project approval applications, site survey records, bills of quantities, and acceptance reports. Update frequency aligns with project phases: initial declaration materials are submitted during the approval phase, and complete files are generated during the acceptance phase.
Most documents are multi-page PDFs, containing multi-column layout bills of quantities, engineering topology diagrams, site survey photos, and other content. Fields include project number, budget amount, construction qualification level, communication link parameters, and some documents contain visual drawings exported from CAD.

## What constraints do these characteristics impose on the document parsing and chunking link
Multi-column layout bills of quantities can cause cross-column data association loss when split by the default chunker, so targeted adjustments to chunking rules are needed.
Documents with a large number of engineering topology diagrams and site photos will lose visual business information if image parsing configuration is not enabled.
For long documents with cross-page tables and parameter descriptions, the default chunking logic will break the association between parameters and their corresponding tables, making it impossible to match complete business units during retrieval.
Fields with specific engineering units must retain contextual association during splitting, to avoid separation of units and values, which affects the accuracy of subsequent parameter retrieval.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Telecommunications engineering declaration materials often contain cross-page tables and parameter descriptions. This range preserves complete business units associated with a single page or cross-page content |
| `chunkSplitter` | Split by page paragraphs + table boundaries | Avoid incorrect splitting of multi-column bills of quantities, and retain the association between tables and their corresponding descriptions |
| `customPdfParse` | Enabled | Adapt to documents with multi-column layouts and embedded topology diagrams, retain the positional association between images and text |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Telecommunications engineering files often contain a large number of high-definition site photos and CAD exported files, requiring support for large file uploads |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Long document parsing requires sufficient time to complete multi-page merging and image OCR, avoiding mid-process timeouts |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different types of declaration materials such as approval applications and acceptance files, to adapt to differentiated document structures |

## Three common mistakes
- Column data misalignment or merging appears in parsed multi-column bills of quantities. Cause: The chunking rule split by table boundaries is not used. The default chunker splits by rows, leading to loss of cross-column data association.
- Engineering topology diagrams or site photos in the PDF are not extracted in the parsing results. Cause: The `customPdfParse` configuration is not enabled. The default PDF parsing does not extract embedded image content.
- The parsing task returns a `408 Request Timeout` status code. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a threshold suitable for long documents. Long document parsing time exceeds the preset setting.

## How to confirm the configuration is correct
- Upload a test document containing a multi-column bill of quantities, check whether the parsed table column data is complete and free of misalignment, to confirm that the chunking rule takes effect.
- Upload a PDF document containing embedded topology diagrams, check whether the parsed results include text descriptions and visual information corresponding to the images, to confirm that the image parsing configuration takes effect.
- Upload a single test file that meets the maximum size of the business scenario, confirm that the upload and parsing process is not interrupted, and confirm that the file size configuration value meets business requirements.
- Check the parsing task logs, confirm that the chunking duration does not exceed the preset `PARSE_FILE_TIMEOUT_SECONDS` threshold, and confirm that the timeout configuration value meets the requirements for long document parsing.
