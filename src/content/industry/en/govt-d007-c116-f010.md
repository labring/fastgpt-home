# Telecommunications Engineering Construction Declaration Materials and Case Review: Knowledge Base Retrieval and Recall

## What this category of data looks like
Telecommunications engineering construction declaration materials and case review data mainly comes from project approval documents, construction drawings, equipment procurement lists, acceptance reports, construction unit qualification certificates, and similar materials. Data is uploaded in batches according to project progress. Pre-construction materials are uploaded after project approval. Progress documents are updated synchronously during the construction phase. Finalized files are archived after acceptance is completed. Most documents are multi-page PDFs or structured Word files. They include fields such as project number, construction location, budget amount, construction scope, and qualification level. Common units include ten thousand yuan, kilometers, square meters, number of ports, and others.

## What constraints these characteristics impose on knowledge base retrieval and recall
Telecommunications engineering construction declaration and case review data includes large volumes of structured technical parameters and qualification-related text. Long documents make up a high proportion of the total, and update frequency fluctuates with project progress. The need for precise matching of structured fields means retrieval cannot rely solely on semantic recall. Keyword matching must also be incorporated. Long documents require appropriate chunking and context splicing strategies to prevent content truncation or overflow. Fluctuating update frequencies require regular refreshes of the knowledge base index. This ensures the latest qualification and acceptance data can be retrieved. Case reviews often require access to similar historical projects. As such, recall results must cover sufficient historical data while limiting the context length of single-round retrieval. This avoids exceeding model context limits.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75-0.85 | Telecommunications engineering documents contain clear qualification and technical parameters. A threshold that is too low will mix in irrelevant documents. A threshold that is too high may miss key case content with slightly lower matching accuracy |
| `limit` | Top 10 entries | Declaration material review needs to balance similar historical projects and current details. Too many results will exceed the model context window and reduce review efficiency |
| `searchMode` | Hybrid mode | Balances keyword matching for structured fields and semantic recall for unstructured content, adapting to the multi-type information in telecommunications engineering documents |
| `usingReRank` | Enabled | Telecommunications engineering documents have many technical details. Reranking improves the sorting priority of key parameters and qualification content, enhancing review accuracy |
| `datasetSearchUsingExtensionQuery` | Enabled | The telecommunications industry has a large number of abbreviated terms. Extended queries cover matches for full names and abbreviations, avoiding missed detections of relevant documents |
| `collectionIds` | Bind exclusive telecommunications engineering construction case knowledge base collection | Restrict the retrieval scope to avoid mixing irrelevant documents from other categories, ensuring retrieval results accurately match business needs |

## Three common errors
- When calling the knowledge base with a thinking model, garbled text is returned. The cause is that after enabling `datasetSearchUsingExtensionQuery`, the extended query text becomes too long. This exceeds the model context window limit and triggers a decoding exception.
- In a local deployment environment, uploaded telecommunications engineering CAD drawings and construction photos cannot be indexed. The cause is that an OCR parsing plugin adapted to engineering drawing formats is not deployed. Text embedded in images cannot be extracted without this plugin.
- Retrieval results include non-telecommunications engineering documents. The cause is that `collectionIds` is not configured to restrict the retrieval set. This allows the retrieval scope to cover knowledge base data from other categories.

## How to confirm the configuration is correct
- Manually upload a telecommunications engineering construction general contracting qualification certificate document. Run a retrieval query containing the keyword "telecommunications engineering construction general contracting". Verify whether the number and relevance of returned results meet expectations.
- View index logs in the FastGPT v4.17.0 knowledge base backend. Confirm all uploaded documents, including CAD drawing images, have completed parsing and vectorization.
- Switch to a non-thinking model to run the same retrieval. Compare the consistency of returned results to confirm the garbled text issue has been resolved.
- Check that the `collectionIds` configuration only includes knowledge base collections related to telecommunications engineering construction. This prevents cross-category retrieval from interfering with results.
