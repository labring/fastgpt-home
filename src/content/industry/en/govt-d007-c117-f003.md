# Declaration Materials and Case Review for Communication Towers and Infrastructure: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for declaration materials and case reviews of communication towers and infrastructure originates from communication tower operation and maintenance management platforms, project approval archives, and on-site survey electronic documents. Update cadence follows centralized submission for single project declarations, with routine case files updated monthly. Document structure includes project basic information forms, material verification lists, on-site image metadata, and audit circulation records. Fields include tower height (unit: meters), floor area (unit: square meters), declaration number, survey longitude and latitude coordinates. Some documents include structured attachments and unstructured scanned files.

## Constraints introduced by these characteristics for the multi-turn dialogue and prompt engineering workflow
The mixed structured and unstructured document structure requires prompts for multi-turn dialogue to adapt separately to structured field verification and unstructured image content review. For field requirements of specific entities, prompts must enforce unit matching rules to avoid unit deviations in extraction results. The centralized submission update cadence requires multi-turn dialogue to support splitting context by batches, preventing context overflow caused by long documents. Cross-stage audit circulation records require the `messages` parameter to retain each round of audit opinions, ensuring completeness for retrospective verification.

## How to Configure Settings
These configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `messages` | Append by audit round, retain 8–12 rounds of historical dialogue | The standard number of rounds for communication tower case review is 8 to 12. Full retention ensures consistent audit logic |
| `variables` | Bind dedicated field variables such as tower height and floor area, match values to industry specification thresholds | Fields in this category must strictly align with industry standard units and numerical ranges to avoid extraction deviations |
| `chatId` | Generate a unique identifier for each individual declaration project | Ensures multi-turn audit dialogues for the same project are linked to the same context, preventing cross-project confusion |
| Maximum context length | 8000–12000 token | The total length of single-batch documents for communication tower declaration materials typically falls within this range, avoiding context overflow |
| Question Optimization | Enabled, calibrated via actual testing | There are many specialized communication industry terms in declaration materials; optimization improves model understanding accuracy |
| Single search limit | Top 3 results | Case review only requires accessing core compliance references; excessive results will interfere with audit judgments |

## Three Common Configuration Mistakes
- Phenomenon: Context overflow error occurs when processing long declaration documents in multi-turn dialogue, with status code 413 returned. Cause: The number of historical rounds for the `messages` parameter is not limited, causing context length to exceed the model's supported upper limit.
- Phenomenon: When configuring model selection for the multi-turn dialogue module, the optional list only includes general large models, and connected communication industry-specific models are not displayed. Cause: Access configurations for industry-specific models are not synchronized to the model selection pool of the multi-turn dialogue module, causing the module to only load the default configured model pool.
- Phenomenon: Extracted tower height fields do not include units, or units do not match industry specifications. Cause: The prompt does not explicitly bind the verification rule for field units, leading to deviations in model extraction results.

## How to Verify Correct Configuration
- View the configuration logs for the `messages` parameter, confirm that historical records for each round of audit dialogue are correctly appended and the specified number of rounds are retained.
- Upload a standard communication tower declaration material to trigger the multi-turn audit process, check whether the model's returned results include field unit verification logic.
- View the model management interface, confirm that industry-specific models have been added to the optional list of the multi-turn dialogue module.
- Generate a unique `chatId` and initiate more than two rounds of audit dialogue, check whether the context is correctly linked to the same declaration project.

The values provided here are common starting points, and should be evaluated against the sample data from the actual deployment.
