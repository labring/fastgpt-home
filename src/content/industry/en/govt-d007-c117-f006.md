# Submission Materials and Case Review for Communication Towers and Infrastructure: Source Citation and Traceability

## What the Data for This Category Looks Like
Submission materials for communication towers and infrastructure include base station site survey reports, project budget documents, and property right certification files. Case files consist of approval circulation records at all levels, on-site inspection photos, and compliance checklists.
Data is primarily sourced from tower operation and maintenance management systems, project approval ledgers, and on-site inspection archives. It is updated in real time during an individual project’s submission cycle, and archived once the project is completed.
Document structure centers on structured forms, paired with PDF and image attachments. Fields include project ID, tower type, construction location, declaring unit, approval status, tower height, load-bearing parameters, and more. Supported units include meters, kilowatts, square meters, and others.

## Constraints on Source Citation and Traceability
Since data includes structured forms and multiple types of attachments, traceability must match both structured fields and attachment content. Retrieving only partial information must be avoided.
Real-time updated approval data requires retrieval of the current latest version. Archived old data must not be called.
Professional fields such as tower height and load-bearing parameters require precise matching. Fuzzy matching may cause traceability results to deviate from compliance requirements.
Multi-node case circulation records must fully display the approval chain. Only showing the final approval result cannot meet reviewers’ traceability needs.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 8 entries | Communication tower submission case files include multi-node approval records, need to cover all key circulation information |
| Maximum Context | 4000–6000 characters | Matches the total length of single-project submission materials and case files, avoids truncating core compliance content |
| `quoteMaxToken` | 1200 token | Matches the typical length of a single core document such as a survey report or inspection checklist, to ensure complete citation |
| `detail` | Enable detailed traceability | Displays inspection data and responsible person information for approval nodes, to meet compliance traceability requirements |
| Sort Order | Sort by approval time in ascending order | Restores the circulation order of case files, making it easier for reviewers to trace submission progress by timeline |

## Three Common Misconfigurations
- Phenomenon: After creating a plugin, referencing and executing code in a workflow results in an "input parameter mismatch" error. Cause: Failed to correctly map the structured fields of communication tower submission materials, and did not specify the return data format via the `responseData` parameter.
- Phenomenon: When setting the number of cited entries, only 100 or 900 options are available, and custom values around 300 cannot be selected. Cause: Did not enable the advanced setting for custom citation limits in FastGPT v4.17.0. Fixed optional ranges are displayed by default.
- Phenomenon: The referenced inspection checklist content is truncated, and complete load-bearing parameters cannot be displayed. Cause: The `quoteMaxToken` value is lower than the actual token count of a single inspection document, causing content to be truncated prematurely.

## How to Confirm Configuration Is Correct
- Upload a real communication tower submission case file, trigger a traceability query, and check if returned results include complete approval node times and inspection data.
- Call the configured plugin, pass a simulated project ID parameter, and check if the returned `responseData` includes structured field information for the corresponding project.
- Adjust the `quoteMaxToken` value, verify that the length of cited content changes with the parameter, and confirm that the configuration takes effect.
- View workflow run logs to confirm that no missing parameter or context overflow error messages appear.

The values given are common starting points and should be measured against the reader's own samples.
