# Document Parsing and Chunking for Communication Tower and Infrastructure Declaration Materials and Case Review

## What This Category of Data Looks Like
Data for communication tower and infrastructure declaration materials and case files originates from project approval applications, on-site survey records, operation and maintenance case files, and acceptance materials for communication tower construction projects. These materials are generated irregularly as projects progress. Most documents are multi-page PDFs, including fixed-format approval forms, parameter pages with clear units (such as tower height in meters, load capacity in kilowatts), on-site photo attachments, and approval process sheets. Some materials contain nested structured forms and free-text paragraphs, with standardized fields including project number, longitude and latitude coordinates, approval document numbers, and other standard content.

## Constraints Imposed on Document Parsing and Chunking
Multi-page long documents require the parsing process to adapt to large files, preventing timeouts or parsing interruptions. Fixed-format approval forms and parameter fields with units require chunking to retain the association between fields and units, and avoid splitting related content across parameter blocks. Irregularly updated template formats require parsing configurations to be flexible enough to adapt to format differences across batches of materials. Nested structured forms and free text require chunking logic to balance paragraph integrity and retention of structured information, avoiding disruption of contextual associations in approval processes.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents include long paragraphs of survey records and parameter forms. This range avoids splitting complete content associated with key parameters |
| `chunkSplitter` | Split by header, footer, and paragraph | Case files include approval document numbers with fixed headers. This setting retains the association between document numbers and their corresponding approval content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | A single declaration material can have hundreds of pages, and standard parsing duration exceeds the default configuration |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Some declaration materials include high-definition tower foundation photo attachments, leading to large single-file sizes |
| `customPdfParse` | Enabled | Case files have fixed-format approval forms. Custom parsing retains the association between fields and units |
| `chunkSettingMode` | Manual configuration | Chunking parameters must be adjusted for different material types, such as project approval applications and acceptance case files |

## Three Common Misconfigurations
- The symptom is a timeout error when parsing hundreds of pages of PDFs. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter, using the default short-duration configuration.
- The symptom is an undefined field error when calling the custom PDF parsing tool. The cause is failure to adapt to the unique tower foundation parameter field template in the case files, resulting in the parsing logic failing to match the fixed-format form.
- The symptom is duplicate approval document number content after chunking. The cause is failure to configure splitting by header anchors, resulting in adjacent chunks repeatedly capturing header information.

## How to Verify the Configuration
- Upload a typical hundred-page declaration material, check the completion status of the parsing task, and confirm that no timeout error is triggered.
- Randomly extract text fragments from the chunked results, and verify that fields with units such as tower height and load capacity are not split across different chunks.
- Adjust the `chunkSize` parameter, compare the contextual integrity of the chunked results, and confirm that key approval process paragraphs are not truncated.
- Check the enabled status of `customPdfParse`, and confirm that the parsing rules for form fields are bound to the corresponding templates.

The values provided are common starting points and should be evaluated against the reader's own samples.
