# Declaration Materials and File Review for Metal Material Processing: HTTP Interfaces and External Systems
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Declaration materials and file review data for metal material processing mainly comes from internal enterprise quality inspection systems, ERP production management modules, and upstream raw material inventory ledgers. Data is updated per production batch. Declaration materials for a single batch of materials include fields such as furnace number, batch number, chemical composition percentage, mechanical performance parameters, and process flow records. Files are a combination of structured forms and scanned documents. Field units are mostly percentage, megapascal, kilogram, etc. The total data size of structured data and scanned document indexes for a single file usually falls within the 500-1500 character range.

## What constraints do these characteristics impose on the HTTP interface and external system link
The production batch-driven data update rhythm requires HTTP interfaces to support precise pulling of single-batch declaration data by furnace number and batch number, to avoid excessive bandwidth usage caused by full synchronization. The requirement for consistent units of structured fields means interfaces must carry standard unit identifiers in return parameters, or return values in fixed preset units. The multi-document combined file structure requires interfaces to return a list of associated file IDs for subsequent separate pulling of scanned document content, and support mixed transmission of structured forms and binary files.

## How to set configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `Authorization` | Carry Bearer-type internal system access token, valid for 7 days | Matches authentication rules of metal material processing enterprise quality inspection systems, ensures interface access permissions |
| `variables` | Set to `{"batchNo": "example value", "furnaceNo": "example value"}` | Pass batch number and furnace number parameters to enable precise pulling of declaration material data per production batch |
| `responseData` | Extract structured fields and associated file ID array under `$.data.list[0]` | Adapts to the multi-document combined file structure, directly extracts usable review data and scanned document indexes |
| Interface timeout period | 300 seconds | Covers transfer time for large-volume scanned documents, prevents call failures from mid-connection disconnects |
| Retry times | 3 times | Addresses interface call failures caused by enterprise intranet fluctuations, ensures data pulling stability |
| Data sync trigger rule | Trigger per production batch | Matches production rhythm of metal material processing, avoids invalid full sync requests |

## Three common errors
- A 401 unauthorized error occurs after calling the interface, caused by incorrect configuration of the `Authorization` parameter or use of an expired internal system access token.
- The interface test returns an empty result, caused by failure to correctly pass the batch number or furnace number in the `variables` parameter, leading to the interface being unable to match the corresponding batch of declaration material data.
- A timeout error occurs after calling the interface, caused by failure to set the interface timeout period to a sufficiently long duration, unable to cover transfer time for large-volume files such as scanned documents.

## How to confirm the configuration is correct
- Fill in real furnace number and batch number parameters in FastGPT's interface debugging panel, initiate a call, and check if the returned structured fields include expected content such as chemical composition and mechanical properties.
- View the file ID array returned by the interface, attempt to pull scanned document content via the associated interface, and confirm that file IDs can be parsed normally.
- Simulate a single large-volume scanned document pull request, and check if the interface call completes within the preset timeout period.
- Initiate 3 consecutive calls with the same parameters, check the consistency of interface return results, and confirm that the retry mechanism is active.
