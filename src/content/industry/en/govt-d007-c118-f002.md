# Declaration Materials and File Review for Metal Material Processing: Vector Models and Indexes

## What this category of data looks like
Declaration materials and review files for metal material processing originate primarily from quality inspection reports, processing work orders, qualification declaration documents, and internal approval files of steel enterprises. Data updates mostly use bulk uploads during project declaration, with incremental files generated during daily approval processes. Documents include both structured fields and unstructured content. Structured fields include material grade, furnace number, yield strength, tensile strength, and similar items, with units mostly MPa and %. Unstructured content includes process descriptions, on-site inspection photos, and approval node records. Single declaration materials range from hundreds of characters to complete files spanning dozens of pages.

## Constraints on vector models and indexing
The requirement for exact matching of structured fields means critical parameters cannot be split during chunking, to avoid losing associated parameter information during vector retrieval. The presence of long files requires the vector model to support a sufficient token limit to prevent truncation of core process description content. Bulk and incremental update scenarios require the indexing system to support bulk vectorization and incremental synchronization, to eliminate repeated manual upload operations. Declarations for multiple batches of materials with the same grade often produce similar datasets, so a reasonable similarity threshold must be configured to distinguish different batches, and a deduplication mechanism must be supported to avoid duplicate index entries.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the field length of metal material processing declaration materials, avoids cutting critical structured information such as mechanical property parameters |
| Overlap Length | 100–150 characters | Prevents chunk truncation of continuous process descriptions, ensures complete parameter context can be associated during vector retrieval |
| Similarity Threshold | 0.72–0.80 | Distinguishes declaration materials of different batches with the same grade, avoids misjudging different batches with similar parameters as the same content |
| Single Search Limit | Top 8 entries | Adapts to the scenario of comparing multiple similar declaration materials during file review, covers common bulk review needs |
| `maxToken` | 4096 token | Supports vectorization of long files spanning dozens of pages, prevents truncation of core process description content |
| `defaultToken` | 1024 token | Balances vectorization accuracy and computing resource consumption for short single declaration materials |

## Three common configuration errors
- Phenomenon: After uploading an Excel-format declaration material, the unit of mechanical property parameters is lost in the vectorization result, and the index matching result does not match expectations. Cause: No column mapping rule for Excel tables is configured, resulting in incorrect splitting of structured fields and failure to correctly extract unit information.
- Phenomenon: A single declaration material shows 8 chunks during upload for indexing, and later the interface displays 13 chunks with duplicate vector entries. Cause: Automatic deduplication configuration is not enabled, and the chunk overlap length is set too small, causing overlapping parts of adjacent chunks to be repeatedly identified as independent content.
- Phenomenon: After upgrading to FastGPT v4.17.0, previously retrievable old file content can no longer be matched. Cause: The default vector model parameters are changed after the upgrade, and batch vectorization update is not performed for historical files, resulting in inconsistent vector spaces between new and old indexes.

## How to verify correct configuration
- Upload a standard metal material declaration Excel file, check that the number of vectorized chunks matches expectations, and there are no duplicate entries.
- Submit a file query containing multiple batches of materials with the same grade, confirm that the similarity of retrieval results falls within the preset threshold range.
- Perform a batch indexing operation, verify that all uploaded declaration materials have completed vectorization and their status is displayed normally.
- Modify the `maxToken` parameter, upload a long file, confirm that key process parameters are not truncated.

The values provided above are common starting points, and should be evaluated against the user's own samples.
