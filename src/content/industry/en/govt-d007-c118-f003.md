# Declaration Materials and File Review for Metal Material Processing: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The declaration materials and file review data for metal material processing mainly comes from production ledgers, raw material quality inspection reports, project declaration files, and finished product outbound documents. Data is updated per single declaration batch or archived monthly. A single file document usually includes fields such as declaration number, material grade, batch number, mechanical performance parameters, approval circulation records, etc. Units involve physical quantities such as tons, megapascals, millimeters, and some files contain mixed content of scanned documents and structured forms.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Metal material processing declaration files often mix structured forms and scanned documents. Multi-turn dialogue needs to accurately distinguish between structured field extraction and unstructured content parsing, so prompts must clearly define field mapping rules and unit requirements. The data update rhythm for a single declaration batch is fixed, so multi-turn dialogue must bind the context of the same batch via `chatId` to avoid mixing data across batches. Fields such as mechanical performance parameters have specific physical units, so prompts must enforce that output results include standard units to prevent unit mismatches during review. Single file documents are relatively long, so the context window for multi-turn dialogue must be limited to a reasonable range to avoid redundant data interfering with current review logic.

## Configuration Settings
Configuration references for FastGPT v4.17.0 are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to declaration batch number | Ensure multi-turn dialogue is associated with the file context of the same batch, avoiding data mixing |
| `messages` | Append historical interactions in conversation order | Retain complete circulation records of approval opinions and questions, supporting multi-turn context reuse |
| `variables` | Preset material grade and batch number variables | Quickly call knowledge base retrieval data for the corresponding batch, simplifying review question logic |
| Maximum context length | 8000–10000 characters | Match the average document length of a single file, preventing context overflow that causes dialogue interruption |
| Single search limit | Top 6 results | Cover common associated quality inspection data and material parameters in files, avoiding interference from redundant results |
| Streaming output | Enabled | Enable segmented return of dialogue content, adapting to real-time verification needs for file review |

## Three Common Mistakes
- Phenomenon: The returned review result lacks clear unit annotations. Cause: The prompt does not enforce inclusion of physical units exclusive to metal materials such as tons and megapascals, resulting in incomplete structured field extraction.
- Phenomenon: Previous round approval opinions are not correctly referenced in multi-turn dialogue. Cause: `messages` content is not appended in conversation order, leading to loss of historical interaction records and preventing context reuse.
- Phenomenon: Streaming output stops after returning only a single segment of content. Cause: Streaming output parameters are not configured correctly, or single search results exceed the preset limit leading to content truncation.

## How to Verify Proper Configuration
- Launch a test dialogue targeting a single declaration file, check if `chatId` is bound to the correct batch number, and confirm that the context only associates with data from the current batch.
- Submit a review question that includes units, verify that the returned result includes physical units exclusive to metal materials, and confirm that the prompt configuration is effective.
- Enable streaming output and launch a dialogue, observe if the interface returns review content segment by segment, and confirm that the streaming configuration is working properly.
- Submit two consecutive review questions, check if historical dialogue content is correctly appended to `messages`, and ensure that multi-turn context is complete.
