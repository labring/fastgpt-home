# Declaration Materials and Case Review for Metal Material Processing: Workflow Orchestration

## What this category’s data looks like
Data for this category comes primarily from quality inspection ledgers, raw material inbound slips, process transfer slips, and administrative approval declaration forms of metal material processing enterprises.
Data updates trigger with each production batch or approval workflow node.
Content falls into two main categories: structured fields and attachments.
Structured fields include furnace number, batch number, processing technology parameters, test result values, and units such as MPa and mm.
Attachments are mostly unstructured files like metallographic micrographs and composition test report PDFs, which require linked parsing with associated fields.

## Constraints on workflow orchestration from these data characteristics
The coexistence of structured and unstructured data requires workflows to include both structured field reading and unstructured file parsing nodes.
The dynamic data update per production batch requires workflow `variables` to bind furnace number and batch number as dynamic parameters, to avoid cross-batch data confusion.
Fixed test units require workflows to have built-in unified numerical validation rules, to prevent audit errors caused by unit mismatches.
Approval workflow node triggers must be bound to business flow, and cannot rely on fixed time scheduling.

## Configuration settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global Variables | Bind furnace number and batch number as `variables` | Match dynamic data update per batch to avoid cross-batch data confusion |
| Database Connection Timeout | 600 seconds | Adapt to complex processes including metal material test report parsing and multi-field reading |
| Single Search Result Limit | Top 5 entries | Match the number of test data entries per batch to avoid redundant loading |
| Node Trigger Condition | Trigger based on approval node status change | Align with business flow logic to reduce invalid workflow execution |
| Context Call Scope | Only current workflow instance | Prevent interference between context data from different batches |
| Global Variable Update Timing | After each batch data load | Ensure use of latest batch parameters to adapt to dynamic update characteristics |

## Three common configuration errors
- The database connection node returns an Access denied error. The cause is failure to correctly bind enterprise-exclusive database access permissions to batch parameters in workflow `variables`, leading to failed permission verification.
- The workflow cannot load global variables saved in historical conversations. The cause is failure to specify `nodeId` as the storage association node for historical variables, leading to incorrect variable invocation.
- Workflow execution does not generate customized guide text, and only displays the system default suggested questions. The cause is failure to add an independent guide text generation node in the workflow, directly relying on system default configuration.

## How to verify correct configuration
- Submit a single batch of test declaration materials, check the return results of the database connection node to confirm that permissions and `variables` parameter configurations are correct.
- Manually trigger an approval node status change, check if the workflow executes automatically to confirm that the node trigger condition configuration is correct.
- Call a workflow instance from a historical batch, check if the global variables for that batch can be loaded to confirm that the `nodeId` association configuration is effective.
- Check the output content after AI reply, confirm that the preset customized guide text is displayed to verify that the guide text generation node configuration is correct.
