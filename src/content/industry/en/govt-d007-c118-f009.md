# Declaration Materials and Case Review for Metal Material Processing: Model Access and Configuration

## What the data for this category looks like
Data is primarily sourced from production ledgers, factory quality inspection reports, project declaration forms, and regulatory case files of metal material processing enterprises.
Update frequency aligns with production batches or declaration cycles. Individual document lengths vary widely: from basic declaration items of a few hundred characters to complete quality inspection and rectification case files totaling tens of thousands of characters.
Document fields include batch number, alloy composition proportion, yield strength, reduction of area, approval node records, and more. Units follow industrial standard specifications such as MPa, %, ton, and millimeter.

## What Constraints These Characteristics Impose on Model Access and Configuration
The wide range of document lengths in declaration and case data for metal material processing requires model access to adapt to context inputs of varying lengths, to avoid truncating critical quality inspection data.
Specialized industrial fields and units require embedded models to support industrial text semantic understanding. Without this support, field matching deviations will occur.
The update frequency that shifts with production batches requires configuration to match the data update cycle, to prevent a disconnect between indexes and real-time data.
Multi-node approval records in individual case files require the recall link to accurately associate relevant documents for the corresponding batch, to avoid irrelevant content interfering with review results.
The configuration logic of FastGPT v4.17.0 must adapt to these multi-dimensional data characteristics.

## How to Set Configuration Values

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to full context input for long case files, avoiding truncation of critical quality inspection and approval data |
| `maxTokens` | 2000–3000 token | Controls the output length of a single review round, ensuring clear and complete case conclusions |
| `quoteMaxToken` | 1500 characters | Limits the length of recalled referenced documents, focusing on core material content for the current declaration batch |
| `temperature` | 0.1–0.3 | Reduces randomness in review results, ensuring consistency of professional judgments |
| `AIPROXY_API_ENDPOINT` | Enterprise-internal deployed large model service address | Adapts to professional text processing needs for metal material processing, ensuring enterprise data security |
| `AIPROXY_API_TOKEN` | Exclusive token generated per enterprise permissions | Restricts model access permissions, preventing data leakage risks from unauthorized calls |

## Three Common Misconfigurations
- Phenomenon: GPU power consumption remains below 30% during large model calls, and single-core CPU utilization stays at 100%. Cause: No GPU-accelerated model call parameters are configured, and CPU inference is used by default, leading to unbalanced resource allocation.
- Phenomenon: Alloy composition unit matching errors appear in review results, such as replacing % with ppm. Cause: The embedded model is not adapted for industrial professional fields, and cannot correctly recognize the association between standard units and values for metal materials.
- Phenomenon: Some documents are not recalled during batch declaration material review. Cause: The `maxContext` parameter is set too small, truncating critical batch information in long case files, causing the model to fail to associate complete declaration data.

## How to Verify Proper Configuration
- Check the resource monitoring panel of the large model service to confirm that GPU utilization stays within a reasonable range, and that single-core CPU utilization does not reach full load.
- Import a standard metal material quality inspection case file to verify that the review result correctly identifies the units and values of professional fields such as yield strength and reduction of area.
- Submit declaration materials from multiple batches to confirm that all recalled referenced documents belong to the current declaration batch, with no irrelevant case files included in the context.
- Check the FastGPT log panel to confirm that all model calls use the configured `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, with no failed call records.
