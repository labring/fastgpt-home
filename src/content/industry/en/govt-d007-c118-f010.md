# Submission Materials and File Review for Metal Material Processing: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data sources include internal production process cards, raw material quality inspection records, submission project files, and third-party test reports. Update rhythm syncs with production batches and submission projects, with no fixed cycle. Document lengths vary significantly. Short documents only contain core parameters, while long documents can include full approval workflows and multiple batches of test data. Document fields include batch number, material grade, mechanical performance indicators, processing technology parameters, and approval node records. Most units are megapascals, millimeters, kilograms per cubic meter, and similar units.

## How These Characteristics Create Constraints for the Knowledge Base Retrieval and Recall Link
The characteristics of submission and file data for metal material processing impose multiple constraints on the retrieval and recall process. The wide span of document lengths requires balancing the integrity of short documents and retention of key fields in long documents during chunking. Fields include specialized mechanical performance parameters and specific units. Retrieval must support exact field matching to avoid generic searches returning irrelevant results. Data updates sync with production batches and submission projects. The knowledge base must support incremental update mechanisms to ensure retrieval results use the latest valid documents. File review often requires linking multiple documents from the same batch. Retrieval must support batch associated recall to meet cross-document review needs.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Higher precision is required for matching metal material professional parameters. This range filters low-relevance results while retaining a valid recall scope |
| `limit` | Top 8–12 results | File review requires linking multiple relevant documents. A single recall volume covers key associated items and avoids overloading the context with too many results |
| `usingReRank` | Enabled | Chunked long documents are prone to semantic drift. Reranking optimizes result sorting and improves matching accuracy for professional content |
| `searchMode` | Semantic + keyword hybrid mode | Must match both specialized parameter keywords and semantic context, balancing precise retrieval and generalized coverage |
| `datasetSearchUsingExtensionQuery` | Enabled | Submission materials often include industry abbreviation terms. Extended queries can cover more relevant documents and reduce missed detections |
| `collectionIds` | Specify the knowledge base collection ID corresponding to metal material processing submission files | Isolate data from unrelated categories, improve retrieval accuracy and avoid interference from cross-category results |

This configuration is based on FastGPT v4.17.0.

## Three Common Configuration Mistakes
- Phenomenon: Retrieval results are empty or return unrelated chunks after enabling `usingReRank`. Cause: The `similarity` threshold was not adjusted. Initial recall results have insufficient relevance, and no valid results remain after reranking filtering.
- Phenomenon: Retrieval results include expired production batch documents. Cause: No incremental update mechanism was configured. The knowledge base did not sync the latest submission and quality inspection data.
- Phenomenon: The same long document is recalled multiple times as multiple chunks, leading to context fragmentation. Cause: The long document chunking rules were not adapted. Chunk overlap rate was set unreasonably, causing repeated recalls.

## How to Confirm Proper Configuration
- Upload a known metal material quality inspection document, perform targeted retrieval, and verify that the returned results include the key fields of the target document.
- Check the retrieval log to confirm that the `similarity` values of the recall results fall within the preset range, and the sorted results follow professional relevance.
- Submit a query containing an expired batch number, and confirm that the retrieval results do not return archived expired documents.
- Test multi-document associated retrieval, and confirm that quality inspection records and submission files from the same batch are recalled simultaneously.

The values provided are common starting points and should be measured against the reader's own samples.
