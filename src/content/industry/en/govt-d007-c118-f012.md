# Declaration Materials and Case File Review for Metal Material Processing: Deployment and Upgrade

## What data for this category looks like
Declaration and case file data for this category comes primarily from metal material processing production ledgers, quality inspection reports, administrative approval declaration forms, and regulatory case files. Pull data from internal enterprise production systems and electronic documents uploaded by quality control departments. Sync updates immediately after each batch of processing is completed. Complete monthly bulk archiving. Each document includes fields such as batch identifier, furnace number, processing step records, quality inspection parameter items, and approval workflow nodes. Use industry-standard physical units for fields. Do not use custom non-standard identifiers.

## What constraints these characteristics impose during deployment and upgrade
Multi-source data has both immediate and bulk update rhythms. Configure stable database and cache connections to support concurrent multi-source data synchronization. Periodic high-concurrency write operations create database connection pressure. Adjust connection pool parameters to match peak load. Fields use industry-standard physical units. Preset standardized parameter parsing rules during deployment to avoid index failures caused by non-standard fields. A high proportion of long-text case files require compatibility with legacy document storage formats. Maintain compatibility during upgrades to prevent format corruption or loss during data migration. This document is written for FastGPT v4.17.0.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300 connections` | Accommodates concurrent connection needs for multi-batch data synchronization, prevents connection exhaustion during peak load |
| `MONGODB_URI` | Intranet connection address with read-write permission authentication | Ensures access security and low latency for internal production and case file data |
| `STORAGE_S3_ENDPOINT` | Access domain name of enterprise intranet object storage | Meets large-capacity storage needs for long-text case files |
| `REDIS_URL` | Local cache connection address with password authentication | Accelerates response speed of document parsing and retrieval, reduces database pressure |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit secure string | Secures access permissions for uploaded quality inspection reports and case documents |
| `ROOT_KEY` | Configured per enterprise internal permission control rules | Controls access scope of the platform's highest permissions, prevents unauthorized operations |

## Three common misconfigurations
- Symptom: The service container runs after startup, but accessing the specified port shows a database connection failure. Logs display `MONGODB connection failed`. Cause: Incorrect authentication configuration for `MONGODB_URI`, or intranet firewall restrictions on outbound access to the database port.
- Symptom: Clicking test after configuring a model displays an error, but the model returns normal results during actual execution. Cause: Permission check rules differ between the test interface and the official runtime interface, or the test timeout threshold is set too short.
- Symptom: After adding a local index model, the page displays a configuration error and document indexing cannot be completed. Cause: Incorrect configuration of `REDIS_URL` or `DB_MAX_LINK`, leading to exhausted cache or database connections during index construction.

## How to confirm correct configuration
Run a database connection test command to verify that `MONGODB_URI` and `PG_URL` can establish normal connections. Ensure the connection count does not exceed the preset `DB_MAX_LINK` threshold.
Upload a standard metal material quality inspection report document to verify that parsed fields match preset industry standard parameters, with no missing or abnormal fields.
After starting the service, access the address specified by `FE_DOMAIN` to confirm that the page loads normally with no permission errors.
Trigger a batch document indexing task to verify that `STORAGE_S3_ENDPOINT` can store parsed index data normally with no storage errors.

The values provided are common starting points and should be measured against the reader's own samples.
