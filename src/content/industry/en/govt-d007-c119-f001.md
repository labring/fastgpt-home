# Declaration Materials and Case Review for Iron and Steel Smelting: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Data for declaration materials and case review in the iron and steel smelting industry comes primarily from internal enterprise production management systems, quality inspection department test records, and declaration template documents from local industry and information technology departments.
Updates to this data are triggered by individual declaration tasks, with no fixed scheduled update rhythm.
Document structures include structured metadata fields and associated attachments such as scanned documents and test reports.
Core fields include production batch identifiers, smelting process parameter records, compliance test item identifiers, and approval circulation node records.
Fields have no unified mandatory units, and must match the custom identification rules of the declaration entity.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Because the data includes structured metadata and large-volume attachments, HTTP interfaces must support both structured parameter transmission and large file uploads. This prevents request failures caused by mismatched data types.
Because data updates are triggered on demand by declaration tasks, interface calls must support on-demand triggering. Fixed scheduled task synchronization cannot be relied upon.
Because approval circulation node records exist, interfaces must support status callback capabilities. This synchronizes audit progress to external systems.
Because fields must match the custom rules of the declaration entity, interface request bodies must strictly follow the field naming and format requirements of the internal enterprise system. General templates cannot be used directly.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication method | Set to Bearer token format with `Authorization` header, token validity period is `7200 seconds` | Matches the authentication policy of internal iron and steel enterprise systems, ensuring interface access security |
| Global variable binding | Bind production batch number and smelter number as `variables` global variables, value range is `1–20 alphanumeric combinations` | Matches the core identification fields of declaration materials, enabling cross-system data synchronization |
| Return field filtering | Only extract approval status, circulation nodes, and approval number fields from `responseData`, filter out irrelevant attachments | Adapts to the core data requirements of case review, simplifying external system parsing |
| Timeout setting | Set timeout to `300–600 seconds` | Adapts to the process cycle of iron and steel declaration review, avoiding early interface interruption |
| File upload limit | Configure single file upload upper limit as `1000 MB` | Adapts to the attachment size requirements of iron and steel test reports and process documents |

## Three Common Errors
- A `400 Bad Request` response is returned when calling the interface, with a prompt that the file format is not supported. Cause: PDF, CAD, and other common formats for iron and steel industry test reports and process documents are not added to the allowed upload whitelist, triggering format verification interception.
- Global variables in the workflow are not correctly bound to declaration batch information, resulting in missing interface request parameters. Cause: The batch identification field returned by the production management system is not associated in the `variables` configuration, and variable mapping is not completed.
- Approval status returned by the interface is not correctly parsed after the call, resulting in the external system being unable to synchronize audit results. Cause: The returned fields are not mapped to the enumeration values supported by the external system, causing data parsing failure.

## How to Confirm Configuration is Complete
- Call the test interface with a valid authentication token, verify that the returned status code is `200 OK`.
- View the global variable panel of the FastGPT workflow, confirm that fields such as production batch number and smelter number are correctly bound and display valid values.
- Upload a common PDF test report from the iron and steel industry, verify that the interface reports no format errors and the file uploads successfully.
- Simulate a single declaration task to trigger an interface call, confirm that the external system can correctly receive and parse audit status information.
