# Declaration Materials and File Review for Iron and Steel Smelting: Workflow Orchestration

## What the Data for This Category Looks Like
Declaration materials and file review data for iron and steel smelting mainly come from the production MES system, quality inspection center test reports, environmental protection filing database, and internal project approval archives. Daily quality inspection data updates by shift. Batch declaration materials are submitted per project cycle. Files for some large projects may contain dozens of related documents.
Documents include structured Excel ledgers (with furnace number, smelting cycle, alloy addition amount), unstructured PDF quality inspection reports, and Word declaration documents. Fields include smelting batch number, element content, energy consumption per ton of steel, and approval document number. Common units are mg/m³, hours, and tons.

## What Constraints These Characteristics Impose on Workflow Orchestration
Declaration materials for iron and steel smelting include structured ledgers and unstructured quality inspection reports. Most fields involve professional physical and chemical indicators. Workflows must first verify field format and unit compliance.
Data from multiple systems must be pulled across sources. Workflows must configure multi-node data source call logic.
Single project declaration files have large volume. Workflows must set batch processing nodes to avoid timeouts.
Approval process steps are fixed. Workflows must arrange verification, submission, and review nodes in a fixed order, with no arbitrary adjustments.
Data update frequency is tied to project cycles. Workflows must support on-demand triggering to adapt to declaration rhythms of different projects.

This page’s configuration recommendations apply to FastGPT v4.17.0.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `variables` | Bind core fields such as smelting batch number, energy consumption per ton of steel, emission concentration | Match the fixed field structure of iron and steel smelting declaration materials to enable automatic compliance verification |
| Data source call timeout | 600 seconds | Single batch of parsed data from iron and steel smelting files has large volume, to avoid process interruption from waiting timeout |
| Workflow node order | Fixed sequence of verification → parsing → submission → archiving | Match the statutory step logic of iron and steel smelting approval processes |
| Global variable configuration | Store application access token | Support cross-node call permission transfer to meet multi-link collaboration requirements |
| Plugin call retries | 2 times | Address occasional network fluctuations in iron and steel smelting data sources to avoid failure from a single call |
| Batch processing limit | First 8 pieces of data | Adapt to the conventional data volume of single-batch declaration materials to avoid node resource overload |

## Three Common Errors
- Phenomenon: Database connection plugin execution time increases significantly. Execution duration of new workflows is noticeably longer than old workflows. Cause: No reasonable data source call timeout threshold set, and no batch processing node configured. Large-volume smelting data pulled all at once causes blocking.
- Phenomenon: The classify module in the workflow editing interface cannot select an AI model, but the published workflow can complete classification normally. Cause: Model selection cache in the editing interface does not sync with global configuration. The system default model is only read during the publishing stage, causing abnormal display during the editing phase.
- Phenomenon: Unable to pass the application token to global variables. Permission verification fails during cross-node calls. Cause: Global variable configuration is not bound to dynamic application parameters. Only static initial values are loaded, making real-time token transfer impossible.

## How to Confirm the Configuration Is Correct
- Trigger a simulated declaration process, check whether the fields bound to `variables` are automatically extracted and verified.
- View execution logs of each workflow node, confirm that data source call duration meets the preset threshold requirements.
- After publishing the workflow, test whether cross-node token transfer works normally, with no permission verification errors.
- Adjust the single-batch processing data volume, confirm that node resource occupancy matches the current running requirements of the workflow.
