# Declaration Materials and Case Review for Iron and Steel Smelting: Tool Calling and Plugins

## What the data for this category looks like
Data for iron and steel smelting declaration materials and case review comes primarily from enterprise production management systems, quality inspection center databases, environmental protection department filing systems, and internal administrative case libraries.
Two update rhythms apply:
Monthly declaration materials are updated in batches each natural month.
One-time completed administrative cases are updated in real time once the approval process finishes.
Single documents include the main declaration text, original test data attachments, and OCR-transcribed text from scanned qualification certificates.
Core fields include smelting batch number, ton steel energy consumption (unit kgce/t), environmental emission concentration (unit mg/m³), approval document number, and case number.
Some documents include text fragments split from multi-page scanned attachments.

## How these characteristics create constraints for tool calling and plugins
The multi-source and dispersed nature of iron and steel smelting declaration materials and cases requires tool calling plugins to connect production, quality inspection, and administrative data sources simultaneously. This avoids information gaps from cross-system queries.
The requirement for fields to have specific units means tool parameters must include preset unit verification logic. This prevents deviations in review results caused by unit conversion errors.
The structure of single documents containing split multi-page text requires plugins to support aggregating and associating text fragments by document ID. This avoids missing associated data during review.
The real-time updated case data requires the data source synchronization interval for tool calls to match the business rhythm. This prevents calling outdated filing information.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to the multi-type tool calling needs of iron and steel smelting declaration materials. No manual specification of specific tools is required, and this aligns with the default calling logic of FastGPT v4.17.0 |
| `functionCall` | `enabled` | Forces the model to generate tool calling instructions that follow the required format. This adapts to the structured case review field verification needs |
| Data source synchronization interval | `10–30 minutes` | Matches the update rhythm of monthly declaration materials, while ensuring the real-time performance of case data and avoiding information lag |
| Unit verification switch | Enabled | The units of iron and steel smelting data (such as kgce/t, mg/m³) are core verification items for reviews. Unit legitimacy of parameters must be forcibly verified |
| Tool calling timeout duration | `600 seconds` | Queries across multiple data sources require sufficient time to obtain complete quality inspection and administrative data. This prevents review process interruptions caused by timeouts |

## Three common misconfigurations
- The symptom is an error pop-up when calling the database connection plugin: "Workflow verification failed. Please check for missing or empty values, and whether connections are properly configured". The cause is that no field mapping rules for iron and steel smelting-specific data sources have been configured. This prevents the plugin from recognizing dedicated fields such as batch numbers and energy consumption values.
- The symptom is a `504 Gateway Timeout` status code returned by the tool call. The cause is that the set timeout duration is shorter than the actual time required for cross-multiple data source queries. This fails to match the query complexity of iron and steel smelting data.
- The symptom is the model generating review results directly without triggering tool calls. The cause is that the `functionCall` configuration is not enabled. This prevents the model from recognizing the tool calling needs for structured reviews.

## How to verify a successful configuration
- Send a simulated declaration material review request. Check if the tool calling log shows connections to production, quality inspection, and administrative data sources.
- Submit test data containing incorrect units. Confirm that the plugin triggers a unit verification error.
- View the system configuration panel. Confirm that the `toolChoice` and `functionCall` parameters are enabled as preset.
- Wait 15 minutes, then send a query. Confirm that the latest case data after data source synchronization has been called.
