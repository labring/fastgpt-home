# Declaration Materials and File Review for Iron and Steel Smelting: Citation Sources and Traceability

## What This Category of Data Looks Like
Declaration materials and file review data for iron and steel smelting primarily comes from production ledgers, composition test reports, project establishment declaration documents, and environmental protection filing files from steelmaking and rolling processes. Data updates per production batch. Each batch file includes 10 to 20 attachments, covering structured database fields and unstructured documents. Structured fields include furnace number, smelting duration, raw material batch, test project name, approval circulation node, and other related items. Unstructured documents are mostly PDF or Excel format test reports and approval signature pages. Data update rhythm aligns with production cycles, and archiving and synchronization finish after each batch is finalized.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
The mixed structured and unstructured data feature requires traceability to match both dedicated fields and text fragments, to avoid generic search results deviating from specific smelting batches. The batch-based update feature requires knowledge base synchronization to support incremental updates, preventing old batch data from mixing into the traceability scope of the current review. The feature of long individual attachment length requires retrieval and citation links to adapt to long document parsing, avoiding truncation of key approval nodes or test data. The existence of dedicated fields requires retrieval keywords to be bound to identifiers such as furnace number and smelting duration, improving the accuracy of traceability results.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 800–1200 characters | Adapts to the average length of single attachments for iron and steel smelting files, avoiding truncation of key test and approval content |
| `quoteMaxToken` | 1200–1800 token | Ensures cited traceability content fully covers production ledgers and approval circulation records |
| Number of single recall results | Top 5 | Covers all declaration and file materials related to the same furnace number, avoiding omission of associated information |
| `responseData` | Structured metadata + unstructured fragments | Returns both dedicated fields such as furnace number and smelting duration and corresponding text content |
| `detail` | Enabled | Displays the specific source document path and page number of cited content, facilitating traceability for review personnel |
| Knowledge base synchronization trigger rule | Triggered per production batch | Aligns with the batch-based update rhythm of iron and steel smelting data, avoiding redundant synchronization |

## Three Common Misconfigurations
- Phenomenon: A red error prompt appears after referencing the global variable datasetid when configuring the knowledge base retrieval node. Cause: The datasetid is not bound to the ID of the dedicated iron and steel smelting knowledge base in the workflow's variable configuration, causing the retrieval node to fail to recognize the target data source.
- Phenomenon: Only the first query in the workflow triggers knowledge base citation, and no retrieval results are returned for subsequent queries. Cause: The context automatic reset rule is not configured. The citation context from the previous query occupies all available tokens, preventing subsequent queries from loading new retrieval content.
- Phenomenon: Retrieved cited content does not associate with dedicated fields such as furnace number and smelting cycle, only displaying generic text fragments. Cause: Structured fields are not used as binding conditions for retrieval keywords, and retrieval is only based on unstructured text, resulting in traceability results that cannot match specific smelting batches.

## How to Verify Proper Configuration
- Initiate a query targeting the smelting declaration materials of a specific furnace number, check whether returned results include the source document path and page number corresponding to the `detail` parameter.
- View the knowledge base synchronization log, confirm that only the current batch of smelting data is synchronized to the retrieval library, with no redundant data from old batches.
- Test multiple consecutive queries, confirm that each query triggers knowledge base retrieval and returns corresponding cited content.
- In FastGPT v4.17.0, the binding status of the global variable datasetid can be verified through the workflow's variable debugging panel, confirming that the retrieval node can normally reference this variable.
