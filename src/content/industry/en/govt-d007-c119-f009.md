# Declaration Materials and File Review for Iron and Steel Smelting: Model Integration and Configuration

## What the data for this category looks like
Data for iron and steel smelting declaration materials and file review comes from internal enterprise ERP systems, quality management platforms, and compliance archiving systems. The data includes two core content types: structured declaration documents such as capacity project approval applications, raw material purchase ledgers, and quality inspection certificates; and long-text case materials such as production process logs, compliance inspection records, and acceptance archiving documents. Document structures mix tables and paragraph text, with fields including smelting grade, batch number, single furnace output, unit energy consumption, compliance item number, and others. Units include tons, kilowatt-hours, cubic meters and other industrial standard units. Updates are completed per individual declaration project or monthly file archiving cycle.

## Constraints on model integration and configuration
The mixed-format data and specialized field characteristics of the iron and steel smelting scenario impose clear constraints on model integration and configuration. The combination of long-text production logs and structured tables may exceed the default context length of general-purpose models, requiring adjustment of context-related parameters. The precise identification requirement for industrial specialized units and compliance fields requires reducing the randomness of model output. Some case files include image-based quality inspection reports, requiring enabling visual analysis capabilities. When deploying industrial specialized models locally, correct configuration of exclusive interface information is required to avoid authentication or path errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the total length of a single declaration material (including long logs) to avoid truncation of key compliance fields |
| `maxTokens` | 2000–3000 token | Controls the length of the model's single audit result output, adapting to the one-by-one judgment requirements of file review |
| `quoteMaxToken` | 1500 token | Limits the length of quoted source text to ensure complete display of fields in structured tables |
| `temperature` | 0.1–0.3 | Reduces output randomness to ensure consistency of industrial compliance judgments |
| `AIPROXY_API_ENDPOINT` | HTTP service address of locally deployed models (e.g., http://192.168.1.100:8000/v1) | Connects to models deployed via locally distilled deepseek or xinference |
| `vision` | Enabled | Supports parsing image-based quality inspection reports, furnace condition photos and other materials in case files |

## Three Common Mistakes
- Phenomenon: After configuring `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, the distilled deepseek model still cannot be called, and the log prompts interface authentication failure. Cause: The model interface path is not configured with the exclusive routing suffix for the distilled version, or the exclusive API key of the corresponding model is not used.
- Phenomenon: In FastGPT v4.8.14, after uploading long log documents for iron and steel smelting, the parsing result is empty. Cause: The default `maxContext` parameter is set too small, truncating key structured fields of the document and causing the model to fail to recognize valid content.
- Phenomenon: During workflow operation in FastGPT v4.9.0, an error log for uncalled gpt-4o-mini appears. Cause: The workflow retains deleted GPT model node configurations, or the default model call template is not correctly replaced with a scenario-specific model.

## How to Confirm Configuration Is Complete
- Submit a standard iron and steel smelting declaration material, check whether the model output completely covers all compliance items, and confirm there are no context truncation prompts.
- Call the configured model interface to verify that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations can normally return model responses without connection or authentication errors.
- Upload a quality inspection report containing images, confirm that the `vision` function can normally parse text and detection data in the images.
- For FastGPT v4.17.0, check the compatibility between the configured parameters and the current scenario via the system model management page.
