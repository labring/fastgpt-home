# Declaration Materials and File Audit for Iron and Steel Smelting: Deployment and Upgrade

## What this category of data looks like
Iron and steel smelting declaration materials and file audit data mainly come from production ledgers, raw material quality inspection reports, environmental approval dossiers, and project establishment declaration documents. Data sources cover the entire smelting process. Production ledgers are updated per production shift. Approval dossiers are updated irregularly with project progress. Declaration materials are generated centrally during the declaration phase. Most documents combine structured tables and long text, and include fields such as project number, smelting batch, raw material composition ratio, furnace temperature parameters, and energy consumption per ton of steel. Some fields use units exclusive to the iron and steel industry.

## What constraints these characteristics impose on deployment and upgrade
Reference only; verify against the target FastGPT release and deployment documentation.
Multi-source heterogeneous data access requires adaptation to data sources in different formats, including ledgers and approval documents. Connection parameters for multiple storage types must be configured.
The mixed structure of long-text dossiers and structured fields requires adjustment of text processing adaptation logic during deployment.
Large gaps in data update rhythms require support for on-demand incremental synchronization. This avoids resource consumption caused by full synchronization.
Production environments require offline deployment. This means configuring local storage and offline vector retrieval capabilities to avoid reliance on public network resources.

## Three Common Mistakes
- Phenomenon: No valid results from text content extraction after offline deployment. Fields display empty on the interface. Cause: File parsing dependencies for the intranet environment are not configured, or local document parsing tools are not included in the offline deployment package. This prevents reading structured table content from iron and steel smelting declaration materials.
- Phenomenon: Search results are empty during debugging. Zero items return per search. Cause: A local search source accessible via the intranet is not configured, or the `DB_MAX_LINK` parameter is not adjusted to match intranet concurrency limits. This prevents normal initiation of search requests.
- Phenomenon: Restarting has no effect after modifying code inside a Docker container. Dependency conflicts may also occur. Cause: Directly modifying files inside the container without mounting a local code directory. Volume mapping is not used to synchronize local development and the container. This means modified content cannot be persisted.

## How to Confirm the Configuration Is Complete
- Perform data source connectivity testing in the intranet environment. Check the connection status of configurations such as `MONGODB_URI` and `REDIS_URL`. Ensure test smelting ledger data can be read.
- Upload a standard iron and steel smelting declaration material. Trigger the text extraction process. Verify that parsed fields include exclusive content such as smelting batch and energy consumption parameters.
- Adjust the `DB_MAX_LINK` parameter to different values. Observe the running status of concurrent processing tasks. Confirm the connection pool does not become exhausted.
- Restart the container and verify access to the front-end page `FE_DOMAIN`. Ensure intranet audit personnel can log in to the platform normally.
