# Railway Operations: Declaration Materials and Dossier Review - Workflow Orchestration
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Railway operations declaration materials and dossier review data primarily comes from three sources: freight waybill systems, passenger declaration platforms, and safety inspection ledgers. Updates are synced in real time or daily based on train schedules or business batches. Documents include structured fields and unstructured attachments: structured fields include declaration number, affiliated line, carrier unit, and review node identifier, with units being alphanumeric combinations, line codes, unified social credit codes, and node numbers respectively. Unstructured attachments are mostly PDF waybill scans and safety inspection reports, with individual file sizes typically ranging from 10–500 MB.

## What constraints these characteristics impose on workflow orchestration
The multi-source nature of railway operation declaration materials requires workflows to support multi-data source pull configuration, to avoid duplicate data entry. The large size of individual attachments requires workflow nodes to support HTTP upload and download interfaces for large files, while also limiting the number of attachments processed per node. The hierarchical structure of review nodes (preliminary review, secondary review, final review) requires workflows to configure transfer permissions per node, so that only corresponding roles can trigger the next stage. The real-time business update rhythm requires workflow trigger rules to be bound to business events, using trigger methods other than fixed scheduled execution, to avoid delayed processing.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind declaration numbers and line codes from `variables` | Match the unique identifiers of structured fields, to facilitate locating corresponding files during transfer stages |
| File Upload Node | Configure to support single file uploads of 10–500 MB | Align with the typical size range of railway declaration attachments |
| Workflow Trigger Rule | Trigger by business event | Match the real-time business update rhythm, to avoid delayed processing |
| Node Transfer Permission | Configure corresponding role permissions by `nodeId` | Align with the hierarchical review node requirements for railway operations |
| Timeout Setting | 600 seconds | Adapt to the waiting duration for large file processing and multi-stage review |
| Issue Optimization | Enable context association optimization | Retain the association logic of historical review records, to avoid losing context |

## Three common mistakes
- Workflow runs display AI thinking content, manifested as the interface returning results containing `[SOI]think...[EOI]` fragments. The cause is that the code run node only processes the text part of the conversation output, and does not cover the thinking tag segment automatically appended by the workflow.
- The workflow issue optimization node fails to retrieve historical records, manifested as the node returning empty fields. The cause is that the binding parameter for historical records is not configured in `variables`, causing the node to fail to read context data from the transfer process.
- Agents do not appear after restoring project backups, manifested as no corresponding entries in the knowledge base list. The cause is that the backup only restored the project configuration file, and did not synchronize the associated knowledge base files. Manually rebind the knowledge base path to resolve this.

## How to confirm the configuration is complete
- Trigger the test business event, check whether the workflow starts automatically and pulls the dossier data corresponding to the declaration number.
- Upload a single test attachment of 500 MB, confirm that the file upload node has no errors and the download link can be accessed normally.
- Configure role permissions for the corresponding review node, switch to a non-authorized role, and check whether the transfer to the next stage cannot be triggered.
- View the workflow logs, confirm that the timeout setting does not trigger a timeout error, and the issue optimization node returns associated historical review records.
