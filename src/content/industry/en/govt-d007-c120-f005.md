# Railway Operations: Declaration Materials and File Review - Tool Calling and Plugins

## What the data for this category looks like
Data sources include the internal passenger declaration system, freight file management platform, and scheduling log library of railway operations. Update frequency is grouped by business batches. Temporary passenger declarations are generated alongside daily train trips. Freight files are updated synchronously with each batch of consignment processes. Each document includes fields such as declaration number, corresponding train number or consignment number, applicant qualifications, list of material attachments, and audit node records. Some fields have dedicated codes. Units include train numbers, tons, kilometers, pieces, and other relevant units.

## What Constraints These Characteristics Impose on Tool Calling and Plugin Workflows
Dedicated code fields require precise matching identification parameters to be passed during tool calling. Corresponding file information cannot be retrieved using only fuzzy search. Batch-updated business data requires that plugin triggers be bound to the corresponding business batch identifier, to prevent cross-batch data confusion. Multi-format attachment materials require plugins to support multiple parsing formats including PDF and scanned documents, and to return explanatory text corresponding to audit node status codes. For passenger declaration data with high real-time requirements, plugins must be configured with call intervals that align with business rhythms, to avoid data delays that disrupt review processes.

## Configuration Settings
This page applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` and bound to review-type tools | Adapts to the multi-step review logic of railway declaration materials, automatically matches file parsing and data retrieval tools |
| `functionCall` | Enable mandatory parameter validation | Ensures that fields such as declaration numbers and business batch identifiers passed during tool calls comply with format requirements |
| Historical conversation transfer configuration | Carry the context of the first 3 rounds of review conversations | Matches the multi-round verification process of railway review scenarios, avoids repeated submission of the same materials |
| Authentication configuration | Use identity credentials in MCP format | Complies with the authentication specifications of internal railway systems, ensures interface access security |
| Call timeout threshold | 600 seconds | Matches the average processing duration of railway file reviews, avoids early termination of long-process reviews |
| API format adaptation | Compatible with Claude-format call requests | Adapts to the interface standards of existing tool chains, reduces secondary development costs |

## Three Common Misconfigurations
- Phenomenon: An error "missing context parameter" is returned when calling the review tool, or historical conversations are not read by the tool. Cause: The historical conversation transfer rule is not configured, or the number of transferred conversation rounds is set too low to cover the multi-round verification logic of railway reviews.
- Phenomenon: A 403 status code is returned when calling the MCP authentication interface. Cause: Authentication parameters are not configured in MCP format, or the credential format does not comply with the verification rules of internal railway systems.
- Phenomenon: An incompatibility prompt is returned when calling a Claude-format API. Cause: The API format adaptation configuration is not enabled, or the configuration item does not correctly point to the Claude-format request standard.

## How to Verify Successful Configuration
- Navigate to the tool call configuration page, check if the `toolChoice` parameter is set to `auto` and bound to review-type tools.
- Initiate a simulated declaration material review request, verify that the returned result contains the context information of the first 3 rounds of conversations.
- Call the MCP authentication interface, confirm that the returned status code is 200 to verify that the authentication configuration takes effect.
- Submit a Claude-format test request, confirm that the interface can normally receive and process the request content.
