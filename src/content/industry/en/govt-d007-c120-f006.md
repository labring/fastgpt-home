# Railway Operations Declaration Materials and File Review: Source Citation and Traceability

## What This Category of Data Looks Like
Data for railway operations declaration materials and file review mainly originates from passenger and freight declaration systems, train dispatch archives, safety inspection ledgers, ticket settlement records, and other business systems.
Two update rhythms apply: daily operation declaration materials are generated in real time, while closed files are archived monthly.
Document structure includes structured fields and unstructured text.
Structured fields include job number, train number, approver, review time limit, and other items.
Unstructured text includes declaration descriptions, rectification reports, review opinions, and other content.
Field formats follow fixed rules: train numbers use a G/D/C prefix plus digits, timestamps use the YYYY-MM-DD HH:MM:SS format, and file numbers use fixed-segment coding.

## What Constraints Do These Characteristics Impose on the "Source Citation and Traceability" Link
Railway operation data has a high proportion of structured fields. Precise matching of field information is required during traceability to avoid incorrect cross-train or cross-file associations.
Real-time updated declaration materials require the knowledge base to support incremental synchronization.
Archived files must retain version records to ensure original data from the corresponding time point can be retrieved during traceability.
The text length of individual declaration materials and files varies widely. Long text may exceed default citation limits, requiring configuration adjustments to preserve content integrity.
Multi-level review processes generate multiple rounds of associated data. During traceability, documents must be linked according to process nodes to avoid confusion between materials from different stages.

## Three Common Mistakes
- Phenomenon: The question-and-answer interface displays that source data is cited, but the returned content does not include the original file or declaration form text. Cause: The return source data configuration is not enabled, or `quoteMaxToken` is set too small, truncating the source data content.
- Phenomenon: When multi-level progressive review queries are initiated, the conversation process stalls with no response. Cause: The single recall limit is not set, or `quoteMaxToken` uses an excessively large value, leading to excessive system resource occupancy and timeout.
- Phenomenon: The content returned by review queries does not match the original question-and-answer pair text stored in the knowledge base, with additional rewriting present. Cause: The automatic question optimization switch is not disabled, or `detail` is not set to return only source data, leading the model to process the original text.

## How to Verify the Configuration Is Correct
- A properly formatted railway passenger and freight declaration form is uploaded, a review query is initiated, and the returned result is checked for complete source document fields and text content.
- Multi-level progressive review questions are initiated, and the conversation process is confirmed to proceed normally without timeouts or unresponsive states.
- System logs are reviewed, and each query is confirmed to correctly recall source data for the corresponding train number or file, with no missing or duplicate recalls.
- Standard question-and-answer pairs stored in the knowledge base are tested, and the returned content is confirmed to exactly match the original text, with no additional semantic processing or rewriting.
