# Declaration Materials and Case Review for Expressway Operations: HTTP Interfaces and External Systems

## What constraints these characteristics impose on HTTP interfaces and external systems
Most expressway operation declaration cases include scanned attachment files with large individual volumes. This requires HTTP interfaces to support large-volume request transmission to avoid triggering request length limits. Structured metadata fields are fixed and use dedicated units, so the interface request body must strictly match preset field names and formats. Otherwise, the review system fails to parse the data. Declaration of real-time traffic events requires synchronous interface calls, so interfaces must support low-latency responses. When submitting batch cases, systems must adapt to batch transmission rhythms to avoid overloading single requests. Additionally, state-owned enterprise and public sector systems require interfaces to carry compliant identity credentials to ensure data transmission security.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {state-owned enterprise and public sector exclusive API token}` | Complies with the identity verification requirements of state-owned enterprise and public sector systems, and ensures the legality of interface calls |
| `variables` | `{"allowed_attachment_types": ["pdf", "jpg"], "max_attachment_count": 3}` | Matches the attachment type and quantity limits for expressway operation declaration materials, and filters invalid requests |
| `responseData` | `{"include_attachments": false, "return_raw_data": true}` | Only returns the metadata required for structured review, reducing unnecessary transmission overhead |
| Request timeout | `600 seconds` | Adapts to the processing duration of batch case review, avoiding timeout errors for single requests |
| Batch submission threshold | `First 50 cases` | Avoids excessive single request volume, aligns with daily declaration batch sizes |
| Attachment size limit | `2000 MB` | Matches the typical volume of scanned attachments for expressway operation cases, avoiding 413 Request Entity Too Large errors |

## Three common errors
- An interface call returns a 413 Request Entity Too Large error. The total size of case attachments submitted in a single request exceeds the interface’s configured limit, and the request was not split per the batch submission threshold.
- An interface call returns an empty audit result. The allowed field list was not configured in `variables`, so the review system cannot recognize incoming metadata fields.
- Frequent identity verification failures occur during interface calls. A compliant `Authorization` credential was not used, or the token configuration format does not comply with state-owned enterprise and public sector system verification rules.

## How to confirm correct configuration
- Call the test interface to submit a single standard case. Check if the returned `responseData` includes expected audit status fields to verify that the field parsing configuration works.
- Upload an attachment of typical volume. Confirm the interface does not trigger a 413 error to verify that the attachment size configuration matches actual scenarios.
- Submit batch cases. Check if the interface splits requests per the preset threshold to verify that the batch submission configuration is reasonable.
- View interface logs. Confirm the `Authorization` credential was carried correctly to verify that the identity verification configuration complies with regulations.
