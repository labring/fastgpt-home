# Business Process Guidance for 12345 Citizen Hotline Work Order Handling: HTTP Interfaces and External Systems

## What the data for this category looks like
Core data for this category comes from the 12345 citizen hotline platform, contractor business systems, internal knowledge bases, follow-up evaluation data, and local hotline management regulations. Daily circulated documents include request registration forms, dispatch records, handling responses, follow-up records, extension applications, return instructions, and knowledge base entries. Data updates occur daily, covering all work orders and associated business information circulated on the same day. Data fields include work order unique identifiers, request content, contracting units, handling status, response content, follow-up scores, and more. There is no unified mandatory format, and configurations must match the field requirements of each contractor’s business system.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
Since data sources cover multiple independent business systems, interfaces must be compatible with varying system field formats and authentication rules. The daily update frequency requires interface call frequencies to align with work order circulation rhythms, to avoid excessive calls that increase system load. Multiple types of business documents require interfaces to support multi-dimensional work order parameters, for process guidance verification and triggering. Data circulation directly ties to public request closure loops; interface errors may lead to work order overdue or response rejection, so retry and timeout handling mechanisms must be configured. Unlike administrative licensing scenarios, this category does not require legal approval-related parameters, only business data related to requests and handling.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {API key assigned by the platform}` | Complies with general HTTP interface authentication standards and adapts to the interface authentication requirements of the 12345 citizen hotline platform |
| `variables` | Map core work order fields, for example `{"work_order_id":"example value", "appeal_content":"example value"}` | Pass work order data from external systems into FastGPT workflows to match parameter requirements for business process guidance |
| `responseData` | Extract core business fields from responses, for example `{"reply_content":"$.data.reply", "feedback_score":"$.data.score"}` | Synchronize work order handling data returned by the interface into the context for process verification and guidance |
| Request timeout | `30–60 seconds` | Aligns with standard 12345 work order handling circulation durations, to avoid work order overdue caused by timeouts |
| Retry count | `2 times` | Address temporary network fluctuations or temporary unavailability of contractor systems, reducing the probability of work order circulation failure |

## Three common misconfigurations
- Work order fields returned empty after interface calls: The root cause is failure to correctly map external system work order fields via `variables`, preventing FastGPT from retrieving request content or work order unique identifiers.
- Interface call errors after upgrading FastGPT to v4.17.0: The root cause is failure to synchronously update the format of the `Authorization` parameter or adapt to the interface path rules of the new version.
- Failure to extract work order data after configuring a database connection: The root cause is failure to map work order table fields in the database to FastGPT process guidance variables, preventing matching of business data.

## How to confirm the configuration is complete
- Call a test interface with simulated work order data, verify that `responseData` correctly extracts returned response content and follow-up score fields.
- View FastGPT workflow run logs to confirm that work order parameters configured in `variables` have been correctly passed to the context.
- Simulate temporary network interruption, verify that the interface triggers the preset retry mechanism without direct termination.
- Compare daily document fields from the 12345 citizen hotline to confirm that configured parameters fully match fields from request registration forms and dispatch records.
