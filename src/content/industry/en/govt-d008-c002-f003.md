# Business Process Guidance for "One Thing Handled Efficiently" Joint Handling: Multi-turn Dialogue and Prompt Engineering

## What this category of data consists of
This category of data is primarily sourced from the national integrated government service platform’s "One Thing" special zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. Data is updated daily. Daily associated documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts. Data fields cover cross-departmental item association relationships, application material lists, processing node circulation status, and no custom special field units are used.

## Constraints imposed on the multi-turn dialogue and prompt engineering link
Discrepant fields from cross-departmental data sources require multi-turn dialogue to gradually align material formats and submission methods required by each department.
Daily updated joint handling item lists require dialogue context to call latest data in real time, to avoid using expired processing rules.
Multiple associated documents require prompts to precisely limit call scope, to prevent confusion between individual administrative licensing and joint handling item processing requirements.
Cross-departmental processing node tracking needs require multi-turn dialogue to guide users to supplement materials or confirm circulation status at each process stage, to prevent items from becoming stuck at a single department.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the exclusive session ID of the joint handling item | Ensure multi-turn dialogue context for the same item is not confused with other items |
| `messages` | Retain the first 20 rounds of dialogue content | Cover the complete circulation process from application to completion for joint handling items |
| `variables` | Bind document IDs of joint handling item lists and one-time notice sheets | Allow prompts to precisely call exclusive business data for this category |
| Maximum context window | 800–1200 characters | Adapt to the spliced length of multi-department materials for joint handling items |
| Prompt template | Preset guidance prompts categorized by joint handling item type | Match the process breakdown needs for cross-departmental processing |
| Maximum documents per single call | Top 6 | Avoid excessive documents interfering with core rule matching for joint handling items |

## Three common misconfigurations
- Phenomenon: User-uploaded joint handling application material files cannot be included when calling the dialogue interface; only the front-end interface supports uploads. Cause: The file ID uploaded by the front-end is not bound in `variables`, so the dialogue context cannot pass file-related parameters.
- Phenomenon: Prompts in multi-turn dialogue mix individual approval and joint handling item rules, leading to incorrect guidance steps. Cause: The exclusive list document for joint handling items is not bound via `variables`, and the prompt does not limit the call scope.
- Phenomenon: The front-end dialogue page displays output content from multiple modules at the same time, making it impossible to distinguish exclusive guidance information for joint handling items. Cause: The session corresponding to the joint handling item is not bound via `chatId`, resulting in mixed output content from different items.

## How to confirm correct configuration
- Initiate a test dialogue, enter keywords for the joint handling item, and check whether the returned guidance content matches the exclusive rules of the joint handling item.
- View the document ID list bound in `variables`, confirm that it only includes daily documents related to the joint handling item, and no business data from other categories is mixed in.
- Initiate a multi-turn dialogue, submit material information from different departments in sequence, and check whether the `messages` context fully retains each round of interaction content and node status.
- Call the FastGPT v4.17.0 dialogue interface, carry the test `chatId`, and confirm that the content returned by the interface only relates to the current joint handling item, with no interfering information from other sessions.
