# Business Process Guidance for "One Thing Done Efficiently" Joint Handling: Tool Calling and Plugins

## What this category of data looks like
The data for this category primarily originates from the "One Thing" special zone of the National Government Service Platform, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. The update frequency is daily. Daily associated documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts. Core fields include item combination names, associated department lists, reusable material entries, processing node timelines, status flow identifiers, and other relevant items.

## How these characteristics impose constraints on tool calling and plugin workflows
Multi-source, heterogeneous data sources require tool calling to adapt to the interface formats of different departmental systems. The daily update frequency requires plugin configurations to include scheduled tasks for synchronizing joint handling item lists and processing statuses. Diverse associated document structures require tools to support parsing application materials and circulation documents in multiple formats. The core challenge of cross-departmental combined handling requires plugins to accurately identify pre- and post-item associations and material reuse rules during process orchestration. Exception branch processing logic must also be configured to prevent joint handling processes from stalling due to abnormal responses from a single department.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `functionCall` | Mandatory enable | Joint handling processes must strictly call specified tools to obtain departmental approval status, and avoid generating irrelevant responses |
| `toolChoice` | Bound to exclusive joint handling tool group | Only call tools related to cross-departmental handling, exclude non-government affairs functions |
| Single tool call timeout duration | 30-60 seconds | Adapt to the typical interface response duration of local government platforms, avoid process lag |
| Tool call failure retry count | 2 times | Address temporary network fluctuations or brief departmental interface abnormalities, reduce the probability of process interruption |
| Plugin context cache duration | 1200 seconds | Retain material and node information for joint handling processes, support cross-step tool call association |
| Maximum number of tool return results displayed | Top 10 entries | Adapt to the typical number of associated departments for joint handling items, avoid information overload |

## Three common configuration errors
- Phenomenon: After the tool call returns departmental approval results, the interface still displays natural language responses generated by the model, and does not only display tool call results. Cause: The mandatory `functionCall` mode is not enabled, causing the model to continue generating conversational content after tool calls.
- Phenomenon: When the joint handling process is arranged to the final node, the completed status is returned directly without triggering a tool call. Cause: No tool call termination logic is configured in the final link of the process node chain, causing the process to end without completing full departmental verification.
- Phenomenon: Custom joint handling material cards cannot be displayed in the conversation interface. Cause: The material preview interface of the government platform is not encapsulated via a plugin, and the trigger rules for card rendering are not configured.

## How to verify successful configuration
This documentation applies to FastGPT v4.17.0.
- Initiate a joint handling item query request, verify that the model only calls the bound exclusive joint handling tools, with no additional natural language responses, to confirm that the `functionCall` and `toolChoice` configurations are effective.
- Simulate a departmental interface timeout scenario, verify that the tool call triggers exception branch processing after the specified number of retries, to confirm that the timeout duration and retry count configurations are reasonable.
- Orchestrate a complete joint handling process, trigger a tool call at the final node, verify that the process automatically terminates after completion, to confirm that the node timeline configuration is complete.
- Test a custom material query request, verify that the conversation interface displays the government material cards encapsulated by the plugin, to confirm that the plugin rendering rules are configured correctly.

The values provided are common starting points and should be measured against the reader's own samples.
