# Joint "Efficiently Complete One Task" Initiative Business Process Guidance: Model Access and Configuration

## What this category of data looks like
Data for this category mainly comes from the national integrated government service platform "One Task" special zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. The update frequency is daily. Documents processed daily include joint service item lists, one-time notification sheets, joint service application forms, material circulation forms, parallel approval opinions, and completion receipts. Document structures typically include fields such as cross-departmental item association relationships, material reuse rules, and processing node circulation requirements. There is no unified fixed format, and some fields need to adapt to the exclusive coding rules of government systems.

## How these characteristics impose constraints on model access and configuration
Decentralized data sources with daily updates require model access to support scheduled synchronization configuration for multi-source data, to avoid lagging process guidance content. Diverse document types and government-exclusive fields require configuring parsing rules adapted to different document formats to ensure accurate extraction of core information. A large amount of cross-departmental joint service process association information requires reserving sufficient context processing space to prevent loss of key node information. Government scenarios have high requirements for content rigor, so the free generation space of the model must be limited to avoid non-standard guidance content.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Joint service items involve multi-department associated processes, requiring sufficient context to fully present cross-departmental processing logic |
| `maxTokens` | 2000–3000 token | Used to generate standardized business process guidance, balancing output length and information coverage |
| `quoteMaxToken` | 1500 characters | Matches material reuse rules in joint service item lists, ensuring referenced government document content is accurate and does not exceed context limits |
| `toolChoice` | auto | Automatically selects whether to call tools to query real-time joint service node status, adapting to dynamic query needs for cross-departmental data |
| `temperature` | 0.3–0.5 | Maintains rigor of process guidance, avoiding personalized content that does not comply with government regulations |
| `AIPROXY_API_ENDPOINT` | Fill in the corresponding node according to the deployment environment | Adapts to network access restrictions of the government intranet, ensuring normal invocation of the model interface |
| `AIPROXY_API_TOKEN` | Fill in the authorization key obtained during deployment | Completes identity verification for the model interface, ensuring compliance of call permissions |

## Three common configuration mistakes
- Issue: Unable to call the specified large language model after deployment, with interface returning connection timeout or permission errors. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not configured correctly, or access to the model interface from the government intranet is not permitted.
- Issue: The model cannot process uploaded joint service item documents, returning empty content or errors. Cause: Document parsing rules were not reconfigured after deployment update, or the `maxContext` parameter was set beyond the model's supported upper limit, causing content truncation.
- Issue: No image index related configuration options are displayed when creating a new knowledge base. Cause: The `vision` configuration switch for the corresponding model is not enabled, or the current deployment version does not adapt to image parsing requirements for government scenarios.

## How to confirm configuration is complete
- Manually call the model to generate process guidance for joint service items, with returned content containing accurate cross-departmental processing nodes and material reuse rules.
- Upload a joint service item list document, and the model can correctly extract core fields such as associated departments and processing nodes, with no obvious parsing errors.
- View the knowledge base configuration page, confirm that the `vision` switch is enabled if image-based government documents such as scanned completion receipts need to be processed.
- Verify the scheduled synchronization task, confirm that the latest joint service item data can be pulled from the government platform daily, with no synchronization failure logs.
- Check the deployment logs of FastGPT v4.17.0, with no abnormal errors in model calls or data synchronization.
