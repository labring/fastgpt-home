# Cross-Departmental "Efficiently Complete One Task" Business Process Guidance: Forms and Interactions

## What This Category of Data Looks Like
Data is primarily sourced from the national integrated government service platform's "One Task" special zone, local integrated government service platforms, electronic certificate repositories, and various departmental approval systems. The update frequency is daily. Daily associated documents include cross-departmental task lists, one-time notice sheets, cross-departmental application forms, material circulation forms, parallel approval opinions, and completion receipts. Common data fields include the pre- and post-relationship of cross-departmental tasks, reusable material lists, identification of each department's processing nodes, and the framework for cross-departmental commitment time limits. Specific legal processing days or amount standards are not included.

## Constraints Imposed on the "Forms and Interactions" Link
Daily updated data sources require forms to synchronize the latest cross-departmental task scope in real time, to avoid users selecting tasks not included in the collaboration. The multi-department document structure requires forms to support integrated display of cross-departmental fields, and implement material reuse interaction logic to reduce repeated user input. The complex pre- and post-relationship of cross-departmental tasks requires forms to guide users step-by-step according to the process, to avoid users filling in too much content at one time. Data sources involve multiple systems, so it is necessary to ensure that the field formats submitted by forms are compatible with those of each department's approval systems, to prevent data conversion errors.

## How to Configure
FastGPT v4.17.0's forms and interactions component supports the following configurations:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Bind reusable material fields from cross-departmental application forms, and associate data from the electronic certificate repository | Enable automatic filling of existing certificate materials, reducing repeated user input operations |
| `formInput` | Set required field validation rules to cover core information items of cross-departmental applications | Prevent users from omitting key information, avoiding process blocking after submission |
| `userSelect` | Display processing role options grouped by department, limit the selectable scope to departments involved in cross-departmental collaboration | Clarify the processing authority of each department, ensuring clear responsibility division for cross-departmental processes |
| Form block settings | Split into 3-5 step blocks according to the pre- and post-relationship of tasks, display 800-1200 characters of guidance content per block | Align with the step-by-step logic of government service processing, reducing the cognitive burden of user input |
| Error prompt trigger | Trigger automatic save prompt after 120 seconds of inactivity during filling | Adapt to the longer duration of government service processing, preventing accidental loss of user data |
| Multi-result selection | Enable the multi-select mode of `userSelect`, support selecting the top 2 or more search results | Meet the business requirement of passing multiple search contents to the large model for processing |

## Three Common Misconfigurations
- Phenomenon: After filling all input items in the workflow, running it displays 'Cannot convert undefined or null to object'. Cause: Required field validation for `formInput` is not configured, causing empty fields to be passed to the processing logic.
- Phenomenon: The form can only pass a single search result to the large model, and cannot select top 2 or more contents for processing. Cause: The multi-select mode of `userSelect` is not enabled, and only single-select logic is configured.
- Phenomenon: After the user submits the cross-departmental application, the task gets stuck in a single department. Cause: Node jump logic is not configured according to the cross-departmental process, and the status field of the material circulation form is not updated synchronously.

## How to Confirm Successful Configuration
- Upload test materials, check whether existing data from the electronic certificate repository is automatically reused, and no repeated filling of corresponding fields is required.
- Select multiple search results, verify that the selected content can be passed to the large model for processing at the same time.
- Trigger submission with empty required fields, check whether error prompt information matching government service scenarios is displayed.
- Leave the page after filling part of the form, return to check whether the filled content is automatically saved.

The values provided here are common starting points, and should be evaluated against the user's own samples.
