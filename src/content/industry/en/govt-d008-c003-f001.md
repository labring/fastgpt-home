# Business Process Guidance for Real Estate Registration: HTTP APIs and External Systems
This documentation applies to FastGPT v4.17.0.

## What this category of data looks like
Data for this category originates from real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. Daily processed documents include registration applications, ownership certificates, survey results, tax payment vouchers, real property rights certificates, and real estate registers. Data is available in two formats: structured business fields and electronic files. Data updates occur daily. Core business fields cover real estate location, rights subjects, ownership status, and more. Field formats vary slightly across source systems, so unified standardization via APIs is required.

## What constraints these characteristics impose on the HTTP APIs and External Systems link
Access to multi-source cross-department systems requires APIs to support multiple authentication methods and return formats, to prevent call failures due to system differences. Daily updated data volume fluctuates, so APIs must support dynamic adjustment of request concurrency to handle peak traffic. The accuracy of core business fields directly affects registration results, so APIs must strictly verify the completeness and compliance of returned data. Cross-system data comparison requires real-time synchronization, and API call delay must meet business processing time requirements to avoid blocking workflows. Different document types require corresponding API parameters; structured data and electronic files need separate request header and transmission configurations.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {unified cross-system authentication token}` | Complies with authentication standards for multiple source systems, avoids repeated configuration of keys for different systems |
| Request timeout | `30–60 seconds` | Response times across cross-department systems fluctuate; this interval covers most normal call scenarios |
| `responseData` validation rules | Verify that core business fields exist and their formats are compliant | Missing core fields or incorrect formats will cause business verification failures; abnormal returns must be intercepted in advance |
| `variables` configuration | Bind the interface address whitelist of the real estate registration system | Restrict legitimate call sources to prevent unauthorized interface access to sensitive business data |
| Pagination parameter configuration | Match the pagination logic of the corresponding system | Pagination rules vary across systems; this avoids duplicate or missing data |

## Three Common Mistakes
- Scenario: The interface returns completely identical data when different pageNum parameters are passed. Cause: The pagination interface logic of the corresponding real estate registration system is not matched, fixed query parameters are incorrectly reused, and the pagination offset is not correctly passed.
- Scenario: The interface call returns a `401 Unauthorized` error. Cause: The `Authorization` parameter is configured incorrectly, the unified cross-system authentication token is not used, or the token has expired and not been updated.
- Scenario: The `responseData` returned by the interface lacks the survey results field. Cause: The return permission for the corresponding field is not enabled in the interface configuration, or the data source system has not opened the access interface for this field.

## How to Confirm Successful Configuration
- Call the test interface, pass different pageNum parameters, and check whether the returned data changes with the parameters.
- Call the authentication verification interface to verify that the `Authorization` parameter can pass the authentication of the target system normally.
- Check the return structure of `responseData` to confirm that all core fields required by the configuration exist and their formats are correct.
- Initiate multiple consecutive calls, and observe whether the interface response conforms to the preset timeout configuration rules.
