# Workflow Guidance for Real Estate Registration Services: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for this category include real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. Update frequency is daily. Documents processed daily include registration applications, ownership certificates, survey results, tax payment vouchers, real property certificates, and real estate registers. Data fields include real estate location, right holder identity information, ownership type, right restriction status, survey area, and other relevant fields. Units include standard real estate registration units such as square meters and number of parcels.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Link
Since data comes from multiple heterogeneous systems, tool calling must support connection to multi-source data interfaces to complete cross-system data comparison. Daily updated data requires tool calling to be configured with real-time synchronization logic, to avoid using expired ownership or survey data. Diverse document types require plugins to adapt to parsing files in different formats, including registration applications and ownership certificates. Data verification errors can cause registration mistakes and property rights disputes, so the tool calling link must add steps for field integrity and compliance verification. Cross-departmental collaborative data sources require plugins to be compatible with interface authentication methods of different systems, to ensure compliance with data pull permissions.

## Configuration Settings
This page’s configuration is based on FastGPT v4.17.0.

| Config Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Supports the model to independently select appropriate tool calls, adapting to complex multi-source data verification scenarios |
| `functionCall` | `["query_property_status", "compare_survey_data", "verify_tax_info"]` | Covers three core business links: ownership status verification, survey data comparison, and tax information verification |
| Tool call timeout | `600 seconds` | Cross-system data pulling requires sufficient response time to prevent business process interruption from timeout |
| Number of tool call results | `Top 3` | Real estate registration data requires precise matching. Excessive results will increase verification burden and reduce business handling efficiency |
| Data synchronization cycle | `1 day` | Matches the daily update frequency of data sources, ensuring tool calls always use the latest business data |
| Plugin trigger node | Triggered according to business link nodes | Tools must be called during ownership verification and data comparison links, to avoid invalid calls consuming system resources |

## Three Common Misconfigurations
- The symptom is that the tool calling module cannot be found in the interface, with no corresponding configuration entry. The cause is that the tool calling function switch has not been enabled in the application settings.
- The symptom is that tool calls return empty data or missing fields, making ownership verification impossible. The cause is that interface permissions for the corresponding real estate registration system have not been configured, or call parameters do not match the field format of the data source.
- The symptom is that the model does not trigger preset tool calls, and directly returns general text results. The cause is that the `toolChoice` parameter is set to `none`, or the correct list of tool functions has not been bound to the model.

## How to Confirm Proper Configuration
- Enter the application’s tool configuration page, confirm that custom tools such as real estate registration data query and survey data comparison have been added.
- Initiate a simulated business handling request, check the tool calling log, confirm that the corresponding interface has been triggered and returns valid business data.
- Check the `functionCall` parameter configuration, confirm that all tool functions required for the business links have been bound.
- Test abnormal input scenarios, confirm that tool calls will trigger field verification logic and return clear prompts.
