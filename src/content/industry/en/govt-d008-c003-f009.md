# Business Process Guidance for Real Estate Registration: Model Integration and Configuration

## What the Data for This Category Looks Like
Data sources for this category include real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. The update frequency is daily. Daily processed documents cover registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real property right certificates, and registration books. Data fields focus on real estate right ownership, ownership restriction status, real estate surveying and mapping matching information, and similar topics. All data is generated around real estate right confirmation and registration processes, with no redundant general business fields.

## Constraints Imposed on Model Integration and Configuration
Multi-source data docking requires models to support cross-system tool calls. Corresponding parameters must be configured to adapt to interface formats of different business systems. Daily updated data requires limiting context length to avoid expired information that reduces ownership verification accuracy. Diverse business document types require models to accurately identify professional field semantics. Parameters must be adjusted to balance general understanding and professional scenario adaptation. The high-risk nature of ownership verification requires improving tool call accuracy. Relevant configurations must be optimized to reduce failure probabilities and prevent registration errors or property right disputes.

## How to Set the Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Covers registration data and historical application materials returned by multi-source systems, avoiding truncation of key ownership information |
| `toolChoice` | `auto` | Automatically calls tools from cadastral, tax, housing and construction systems to complete verification, no manual specification of call items required |
| `temperature` | `0.2–0.4` | Business process guidance requires strict logical consistency, avoiding generated guidance content that is vague or deviates from registration processes |
| `maxTokens` | `1500 token` | The amount of business data returned by a single round of tool calls is limited, limiting output length to ensure response efficiency |
| `AIPROXY_API_ENDPOINT` | Exclusive node specified according to the deployment environment | Adapts to compliance data transmission requirements for real estate registration scenarios, avoiding cross-region data leaks |
| `vision` | `false` | The core of business process guidance is structured data processing, no image recognition capability required |

## Three Common Misconfigurations
- Phenomenon: Tool calls cannot be triggered when using the Gemini model, and returned results do not include expected system interaction instructions. Cause: The `toolChoice` parameter is not set to `auto` or specified as `function`, so the model does not enable tool call capabilities.
- Phenomenon: The large model returns empty results or missing fields after calling tools, causing the verification process to stall. Cause: The `maxTokens` value is not optimized for real estate registration professional fields, leading to truncation of surveying and mapping and tax data returned by tools.
- Phenomenon: After deploying FastGPT on a Windows system and restarting, configured model and application information is lost. Cause: Configuration data is not mounted to a persistent storage directory, and temporarily stored configurations are cleared after system restart.

## How to Verify Configurations Are Correct
- Initiate a real estate registration process consultation test using FastGPT v4.17.0. Confirm that the model automatically calls preset tool interfaces, and verify that tool call configurations take effect.
- Upload complete registration application materials. Check whether the process guidance covers all required links and document requirements, and verify the rationality of context and temperature parameters.
- Restart the deployment environment. Confirm that saved model and application configurations are not lost, and verify that persistent configurations are correct.
- Trigger a tool call exception scenario. Confirm that the system executes retry logic according to configurations, and verify the adaptability of call parameters to exception handling.
