# Business Process Guidance for Real Estate Registration: Deployment and Upgrade

## What the data for this category looks like
Core data for real estate registration business includes registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates and registers, etc. Data sources include real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. Data update frequency is daily. Core fields include owner information, real estate location, right type, restriction status, etc. Surveying and mapping data includes unstructured drawing files and structured area parameters.

## What constraints these characteristics impose on the deployment and upgrade link
Data sources requiring integration with multiple systems mean cross-service network access permissions must be configured during deployment, to avoid data synchronization failures caused by cross-domain issues or firewall interception. The daily update frequency requires deploying incremental synchronization tasks, to avoid excessive system resource usage from full-volume data pulling. The high compliance requirements for core data mean government-compliant storage and database instances must be used, and data verification logic must be configured during deployment, to prevent erroneous data from entering the process guidance link. The feature that errors lead to serious consequences means a full data backup must be performed during the upgrade process, to avoid business interruptions caused by upgrade failures.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale for This Value |
| --- | --- | --- |
| `DB_MAX_LINK` | 150-200 | The daily data increment of real estate registration business is large, reserving sufficient connection counts can avoid concurrent query timeouts |
| `PG_URL` | Address of a PostgreSQL instance connected to the real estate registration information system via dedicated line | Core ownership data and register information are stored in PostgreSQL databases |
| `MONGODB_URI` | Address of a MongoDB instance connected to the cadastral survey database via dedicated line | Unstructured data such as surveying and mapping results are stored in MongoDB |
| `REDIS_URL` | Local Redis cluster address | Cache temporary material verification results and user session information to improve the response speed of process guidance |
| `FILE_TOKEN_KEY` | Random 32-character string | Protect the security of material download links during business processing |
| `STORAGE_S3_ENDPOINT` | Government cloud storage service endpoint address | Meet the compliance requirements for government data storage |

## Three common mistakes
- The database inside the container fails to start after a power outage, manifested as `PG_URL` associated instance connection rejection and MongoDB connection timeout logs. The cause is that container data volume persistent storage is not configured, the database file directory is lost after a power outage, and the original data cannot be loaded after restarting.
- Executing the initialization interface during upgrade returns HTML format content, manifested as the interface response status code being 500 and the content containing web page tags. The cause is that the upgrade script does not adapt to the pre-permission verification of government systems, and does not carry a valid access token, resulting in a redirect to the login page.
- Requests remain in a loading state after the number of concurrent users exceeds the threshold, manifested as the interface not responding for a long time when more than 7 users initiate process guidance requests. The cause is that the `DB_MAX_LINK` configuration value is too low, which cannot support concurrent database query requests.

## How to confirm the configuration is complete
- Run `docker logs fastgpt` to view container logs, confirm that there are no error messages for database connections and storage service initialization.
- Upload a standard ownership certificate document to trigger process guidance verification, confirm that the system returns matching business processing nodes and step instructions.
- Call the FastGPT v4.17.0 health check interface `GET /api/health`, confirm that the return status code is 200 and the database connection field shows normal.
- Test restarting the container after a power outage, confirm that the database service can recover automatically without connection error messages.
