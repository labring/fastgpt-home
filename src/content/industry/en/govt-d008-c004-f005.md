# Business Process Guidance for Proactive Public Disclosure and Policy Publication: Tool Calling and Plugins

## What this category of data looks like
Data sources include government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. The update frequency is daily.
Daily documents include policy documents, policy interpretation drafts, disclosure directories, information release approval forms, press releases, and website column update records.
Most document structures mix structured tables and rich text. Fields include disclosure attribute flags, secrecy review status, publication time limit, column affiliation, and content verification marks. No additional custom statistical units are used.

## Constraints on tool calling and plugins
Data sources are scattered across multiple internal systems and public platforms. Tools must adapt to access control rules for data sources with different permission levels.
The daily update frequency requires low-latency tool calling pipelines. This avoids synchronization delays that disrupt publication timeliness.
Documents contain sensitive classified fields. An attribute verification step must be added before tool calling to prevent sensitive information leaks.
Multi-column synchronization needs require plugins to support batch target site configuration. This eliminates repetitive manual operations.
Structured disclosure directory requirements mean tools must automatically extract fields like publication time limit and column affiliation from documents. This ensures uniform data format that meets government disclosure archiving standards.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts to multi-document tool calling needs for proactive public disclosure scenarios, no manual tool type specification required |
| `functionCall` | `enabled` | Enforces structured output, ensuring extracted fields for policy documents and disclosure directories comply with government disclosure specifications |
| Tool calling timeout | `600 seconds` | Accommodates latency from multi-data source pulls, prevents task failure due to slow internal system responses |
| Batch sync target site count | `first 10` | Balances sync efficiency and server load, aligns with actual daily column update requirements |
| Sensitive information pre-verification | `enabled` | Prevents classified or sensitive information leaks via tool calling pipelines, complies with government disclosure secrecy requirements |

## Three common configuration errors
- Phenomenon: When using a custom URL to configure a document parsing tool, the interface shows no errors but returns no data. Cause: Corresponding government website cross-domain access permissions were not enabled in data source permission configuration, and URL compliance was not verified.
- Phenomenon: After a workflow runs, no properly formatted policy interpretation document is generated. Cause: The `functionCall` configuration was not enabled, resulting in unstructured model output that cannot be recognized by the document generation tool.
- Phenomenon: A database query plugin call fails. Cause: The access whitelist for government databases was not configured, or the query statement did not match the field specifications of the disclosure directory.

## How to verify correct configuration
- Initiate a single-document parsing test, upload a sample disclosure directory document, check if fields like disclosure attribute and publication time limit are correctly extracted, to verify that the `toolChoice` and `functionCall` configurations are active.
- Configure 1 to 2 test sites, initiate a batch sync task, check if sync completes according to the set target quantity, to verify the rationality of the batch sync configuration.
- Upload a test document marked with sensitive attributes, check if the tool triggers a sensitive information verification block, to verify the effectiveness of the sensitive information verification switch.
- Call the database query plugin, enter a standard disclosure directory query statement, check if matching structured data is returned, to verify the correctness of the database access configuration.

The values provided are common starting points and should be measured against the reader's own samples.
