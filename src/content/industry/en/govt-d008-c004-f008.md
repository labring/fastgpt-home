# Business Process Guidance for Proactive Public Disclosure and Policy Publication: Document Parsing and Chunking

## What this category of data looks like
Data sources include government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. Update frequency is daily. Daily documents cover policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Documents include fixed metadata fields such as public attribute identifiers, issuing authorities, effective dates, and main body content. Some policy interpretation drafts are accompanied by image and text materials. Some structured documents such as approval forms include fixed process node fields.

## What constraints do these characteristics impose on the document parsing and chunking step?
Since data sources cover multiple systems, document formats include structured approval forms, unstructured policy text, and mixed image-text interpretation drafts. The parsing process must support metadata extraction for multiple formats. The daily update requirement means the parsing workflow must support incremental synchronization. This avoids repeated processing of full datasets. Documents include sensitive fields such as public attribute identifiers. Chunking must retain contextual connections. This prevents attributes from being separated from main body content after splitting. Some documents include accompanying images and text. Parsing must synchronously link images to their corresponding main body paragraphs. This ensures publication integrity.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to standard paragraph lengths of policy document main bodies, avoiding damage to complete context of policy clauses and approval processes after splitting |
| `chunkSplitter` | Split by title hierarchy + paragraph | Matches the title hierarchy structure of government documents, ensuring retention of policy publication logical hierarchy after chunking |
| `customPdfParse` | Enabled | Adapts to government PDF documents with approval seals and embedded metadata, accurately extracting main body content and key fields such as public attribute identifiers |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Addresses parsing time requirements for batch policy documents and mixed image-text interpretation drafts, preventing interruptions during large file parsing |
| `chunkSettingMode` | Auto-adapt by document type | Distinguishes between structured approval forms, public disclosure directories, and unstructured policy text, adjusting chunking rules to ensure consistent parsing across all document types |

## Three Common Misconfigurations
- Symptom: After calling the knowledge base creation interface, real-time parsing status feedback is unavailable. Only a waiting status appears. Cause: Parsing status callback is not configured, or synchronous parsing mode is not enabled. This prevents real-time retrieval of parsing, ready, and failed statuses.
- Symptom: After uploading a policy interpretation PDF containing images, the parsing result only returns text content and does not associate corresponding image materials. Cause: The image-text synchronous extraction configuration for `customPdfParse` is not enabled, causing image metadata to not be bound to main body content.
- Symptom: When batch uploading public disclosure directory documents, some files fail to parse and return timeout errors. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to the value range suitable for batch processing, causing timeouts for large files or batch tasks.

## How to Verify Correct Configuration
- Upload a policy PDF document with an approval seal. Check whether the parsing result completely extracts main body content and public attribute identifiers, to verify that the `customPdfParse` configuration takes effect.
- Upload a policy interpretation draft with supporting images. Check whether the chunking result associates corresponding image materials, to confirm that the image-text synchronous extraction function works properly.
- Submit a batch document parsing task. Check whether the parsing status is updated in real time, to verify that the timeout configuration adapts to batch processing requirements.
- Adjust `chunkSize` to different ranges. Upload a public disclosure directory document with short paragraphs. Check whether the chunking result matches the expected length.

The values provided are common starting points and should be measured against the reader's own samples.
