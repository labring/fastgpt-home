# Business Process Guidance for Property Rights, Assets and State-Owned Capital Management: HTTP Interfaces and External Systems
This document is written based on FastGPT v4.17.0.

## What data in this category looks like
Data in this category mainly comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, appraisal firm reports and financial statements. Daily associated business documents include property registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements and asset disposal approval documents.
Data is updated on a monthly basis. Fields cover asset ownership information, appraisal results, transaction progress, approval status and other content. There are no unified standard units, so it is necessary to directly connect to the native field formats of each system. Typical connecting entities include property rights divisions of state-owned assets supervision institutions, central enterprise asset management departments, property rights trading institutions and appraisal firms.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
Heterogeneous multi-source data sources require interfaces to adapt to authentication rules and return formats of different systems. Interfaces must support structured data and binary file-style responses.
The monthly update rhythm eliminates the need for high-frequency calls. Set reasonable request intervals and caching strategies to avoid triggering rate limits of state-owned assets systems.
Transmission of complex business documents requires interfaces to support large-volume data transfer. Errors in state-owned asset-related business carry serious consequences. Interface error handling must cover scenarios such as authentication failures, incorrect data formats and transmission interruptions, to quickly identify transaction risks.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Configure Bearer Token or static key as required by the connected system | Adapt to the unified authentication specifications of state-owned assets systems, and ensure the legality of interface calls |
| Request timeout | 600 seconds | Cover the transmission cycle of large-volume data such as asset disposal approval documents and asset appraisal reports |
| `responseData` | Select binary stream or structured parsing mode based on response type | Adapt to multi-format return content such as property rights transfer plans and on-site transaction announcements |
| `variables` | Map asset IDs and transaction batch numbers to interface input parameters | Match dynamic business identifiers in the business handling process, and accurately trigger corresponding process guidance |
| Retry count | 2 times | Balance interface call stability and rate limit rules of state-owned assets systems, and avoid the risk of accountability triggered by repeated calls |
| Response cache duration | 720 hours | Match the monthly data update rhythm, and reduce repeated call overhead |

## Three common mistakes
- Phenomenon: After calling the HTTP interface to return a pptx format file, the result cannot be directly delivered to the end user, or the file cannot be associated with a business identifier after storage. Cause: `responseData` is not configured as binary stream mode, and the default structured field parsing causes the file content to be lost.
- Phenomenon: The token consumed by interface calls does not match the external system billing log. Cause: Redundant business fields are not filtered via `variables`, causing the request body to carry unnecessary data and increasing token consumption.
- Phenomenon: A "Failed to fetch" error is returned when calling an external system interface. Cause: The cross-domain authentication rules of the state-owned assets system are not adapted, or the timeout period is set too short, causing large-volume data transmission to be interrupted.

## How to confirm the configuration is complete
- Call the test interface to verify that the returned asset ownership data can be correctly parsed and mapped to business process guidance nodes.
- Check whether the `Authorization` configuration item matches the authentication requirements of the connected system. This can be confirmed by temporarily calling an unauthorized interface to trigger an error.
- Trigger an interface call for a large-volume asset appraisal report to verify whether the timeout setting meets transmission requirements.
- Simulate an interface call failure scenario to confirm whether the retry mechanism and error logs are generated normally.
