# Business Process Guidance for Property Rights, Asset and State-owned Capital Management: Deployment and Upgrade

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
Data for this category comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, appraisal agency reports and financial statements. The update frequency is monthly. Daily processed documents include property rights registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements and asset disposal approval forms. These documents contain core fields such as asset ownership identifiers, appraisal conclusions and transaction approval workflows. Data is linked to business information across multiple systems, so consistency and timeliness of data from all sources must be maintained.

## What constraints these characteristics impose on deployment and upgrade
The monthly update rhythm requires configuring incremental data synchronization trigger logic during deployment, to avoid excessive system resource usage from full pull operations. The need to access multiple heterogeneous data sources requires configuring adaptation rules compatible with different system interface formats during deployment. The variety of business document types requires pre-configuring parsing and preprocessing rules for multi-format documents, to adapt to different document structures such as property rights registration forms and asset appraisal reports. The requirement to link core fields to ownership and transaction status requires configuring field mapping and verification rules during deployment, to ensure that the information in process guidance matches business logic. The strict requirements for state-owned assets require configuring a pre-verification link for data auditing after deployment, to prevent incorrect data from triggering processes.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Connection address of the database linked to the state-owned assets system, calibrated based on actual testing | Core asset ledger data for this category is stored in the MongoDB database of the state-owned assets supervision system, so the connection configuration must match the corresponding data source |
| `PG_URL` | Connection address of the database for financial statements and asset ledgers, calibrated based on actual testing | This category requires linking financial statement and asset ledger data, and stores linked information via a PostgreSQL database |
| `REDIS_URL` | Redis instance address for caching sessions and temporary data, set to 600-second expiration time | Business process guidance requires caching asset status information from user inquiries. A 600-second expiration balances response speed and data freshness |
| `FE_DOMAIN` | Domain name for internal office networks or external services, configured based on the actual deployment environment | This category serves state-owned assets supervision institutions and property rights trading institutions, so the deployment domain name must be matched to enable cross-system access |
| `STORAGE_S3_ENDPOINT` | Endpoint address of the enterprise's internal object storage service, calibrated based on actual testing | This category requires storing documents such as asset appraisal reports and property rights transfer plans, so configuration must adapt to internal S3-compatible storage |
| `DB_MAX_LINK` | 100–150 connections | When accessing multiple system data sources simultaneously, the number of database connections must be limited to avoid resource exhaustion, to adapt to the concurrent requirements of monthly incremental data synchronization |

## Three common configuration errors
- Symptom: The management interface cannot be accessed after Docker deployment, and logs indicate a database connection failure. Cause: The `MONGODB_URI` or `PG_URL` parameters are not configured correctly, and the address and permissions of the database linked to the state-owned assets system are not matched.
- Symptom: The deployed service page displays a blank screen when accessed via an iOS device, but works normally on Mac and Windows devices. Cause: The `FE_DOMAIN` parameter is not configured, or the domain name does not adapt to cross-domain rules for mobile browsers, resulting in failed loading of front-end resources.
- Symptom: The asset information returned by the process guidance does not match the actual ledger, with missing or incorrect fields. Cause: Field mapping rules are not configured, and the association relationship between multi-source data is not verified, resulting in mismatched fields across different systems.

## How to confirm the configuration is complete
- Run the database connection test script to verify the connectivity of the `MONGODB_URI` and `PG_URL` parameters, and confirm that asset ledger data from the state-owned assets system can be read.
- Access the configured `FE_DOMAIN` domain name, and test page loading across different terminal devices, to confirm that front-end resources load normally.
- Upload an asset appraisal report document, test the parsing and field extraction function, and confirm that core information that meets business requirements can be extracted.
- Trigger an incremental data synchronization task, confirm that the data update frequency meets the monthly requirement, and that there are no abnormal interruptions.
