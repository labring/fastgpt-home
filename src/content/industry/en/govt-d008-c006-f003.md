# Business Process Guidance for Infectious Disease Information Reporting and Monitoring: Multi-turn Dialogue and Prompt Words

## What Data for This Category Looks Like
This category's data comes from the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily documents include infectious disease report cards, epidemic situation analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. The document structure centers on core case information, report process nodes, and monitoring statistical fields. It includes fixed fields such as case diagnosis information, reporting time limits, correction status, and clustered epidemic scale. There are no large numbers of custom extended fields.

## What Constraints Do These Characteristics Impose on the "Multi-turn Dialogue and Prompt Words" Link
Daily updated data requires the dialogue system to synchronize the latest disease control rules and case data to avoid referencing expired information. Differences across multiple types of documents require prompt words to clearly define the call priority for different documents, such as giving priority to real-time corrected case records. The fixed field structure requires prompt words to limit the dialogue to only calling predefined case fields, and prohibit generating unfiled information. At the same time, the core business links of verifying case time limits and correcting duplicate reports require guiding users to supplement key node information step by step according to the business process during multi-turn dialogue, to avoid missing required items specified by business requirements.

## Three Common Misconfigurations
- Knowledge base retrieval returns no results during dialogue, but independent testing of the knowledge base can correctly match content. The symptom is a blank reply returned by the dialogue, and background logs show 0 retrieved records. The cause is that the session context carries unspecified filter conditions, causing the retrieval scope to exceed the target document library.
- Dialogue returns a 404 Invalid URL (POST /api/chat/completions) error. The symptom is that the interface or API returns the specified status code and error message. The cause is that the FastGPT dialogue API access address is not configured correctly, or API access permissions are not enabled.
- Workflow terminates immediately after reaching the AI answer step, with no response from subsequent nodes. The symptom is that the dialogue ends after the AI generates a reply, without triggering subsequent workflow steps. The cause is that the `messages` parameter is not passed correctly during multi-turn dialogue, causing the workflow to fail to recognize subsequent interaction logic.

## How to Verify Successful Configuration
- Simulate a disease control business dialogue, enter the diagnosis information of a specific case, and verify whether the retrieval results include the same-day updated case correction records.
- Call the dialogue API, check whether the returned `chatId` parameter matches the current session's business identifier.
- Configure prompt words to limit the answer scope, enter questions related to epidemiological investigation reports, and verify whether the generated content only calls predefined disease control document fields.
- Simulate a timeout scenario, enter an ultra-long text question, and verify whether the system completes the response and returns results within 600 seconds.
