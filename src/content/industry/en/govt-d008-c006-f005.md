# Business Process Guidance for Infectious Disease Information Reporting and Monitoring: Tool Calling and Plugins

## What This Category's Data Looks Like
This category's data sources include the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily generated documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Document fields cover basic case information, diagnosis results, reporting time limits, correction notes, testing data, and more. Data is mainly a mix of structured forms and unstructured documents, with no additional custom statistical fields.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
Multi-source data docking requires tool calling to adapt to the interface formats of different systems to avoid data synchronization exceptions. The daily update frequency requires tools to support scheduled pulling or incremental synchronization mechanisms to ensure data timeliness. Mixed-format documents require targeted parsing plugins to ensure accurate extraction of structured fields. Statutory reporting rules require tool calling to have built-in verification logic to automatically check reporting time limits, duplicate or incorrect cards, and other content. Failure to do this may trigger regulatory notifications. At the same time, data volume fluctuates with epidemics. Tool calling must have elastic adaptation capabilities to avoid interface overload during peak periods.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | auto | Adapt to different types of business documents, automatically select the corresponding tool to complete parsing or verification |
| Document Parsing Plugin | pdf-marker v2 (must be deployed under FastGPT v4.17.0) | Supports field extraction of multi-format unstructured documents such as epidemiological investigation reports and epidemic analysis reports |
| Plugin Call Timeout Setting | 600 seconds | Center for Disease Control report data volume is large, processing takes a long time, avoid task interruption due to timeout |
| Maximum Parallel Tool Calls | First 3 entries | Avoid calling multiple systems simultaneously leading to interface current limiting, ensure calling stability |
| Maximum Data Returned per Tool Call | 1000 entries | Adapt to the single-time data volume requirements of Center for Disease Control reports, avoid excessively large interface return data |
| `functionCall` | Force specify the report verification tool | Ensure that core case diagnosis verification and time limit verification links call dedicated tools to improve accuracy |
| Plugin Log Storage Limit | 100 MB | Store daily Center for Disease Control report parsing logs, avoid disk space overflow |

## Three Common Misconfigurations
- A 404 error is returned when calling the `/v2/parse/file` interface. The cause is that the pdf-marker v2 open-source plugin is not deployed correctly, or the plugin directory configuration does not point to the correct path.
- When using the markdown to docx plugin to process Center for Disease Control reports, the output format is disorganized. The cause is that the plugin parameters are not adjusted for scenarios such as table alignment and field line breaks in the reports, and the fixed format requirements of the documents are not matched.
- A compliance prompt is triggered when using the open-source version of FastGPT for commercial scenarios. The cause is that the commercial use scope of the open-source license is not clearly defined, or the open-source statement is not retained as required.

## How to Confirm Configuration Is Complete
- Upload a standard infectious disease report card to trigger the tool calling process. Check whether the pdf-marker v2 plugin is correctly called to complete document parsing.
- View the plugin call logs. Confirm that the timeout setting is in effect, and there are no task failure errors that have not been completed within 600 seconds.
- Create two independent applications, configure different API keys respectively, call the same model interface, and check whether the returned results are associated with the key configuration of the corresponding application.
- Submit case data that exceeds the reporting time limit. Check whether the tool triggers the verification logic and returns an abnormal prompt.

The values provided are common starting points and should be measured against the reader's own samples.
