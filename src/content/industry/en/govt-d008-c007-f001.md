# Workflow Guidance for Petition Matter Handling: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data originates from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. Daily generated documents include fixed-format files such as petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-examination applications, and resolution plans.
The data update frequency is daily. Typical users include petition bureaus, departmental petition offices, subdistrict and township offices, and responsible unit offices.
Data fields are designed around the full process of petition matter acceptance, circulation, handling, and re-examination. Formats are unified and bound to statutory handling links.

## What constraints these characteristics impose on the HTTP interfaces and external systems link
Data sources cover multiple government systems. Interfaces must support authentication, data formats, and field naming rules for different systems.
The daily update frequency requires interface call schedules to align with batch export or push windows of government systems. Frequent calls must be avoided to prevent excessive system load.
Fixed-format business documents require interfaces to strictly map specified fields. Extraction rules cannot be adjusted freely.
Petition matter handling outcomes are linked to risks such as repeated petitions and petitions submitted beyond the authorized hierarchy. Interfaces must ensure data integrity and timeliness during transmission. Field missing or transmission delays must be avoided.

## How to Configure
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {API key assigned by the petition system}` | Complies with general government interface authentication specifications, and adapts to the security verification requirements of petition systems |
| `variables` | `{"required_docs": ["petition registration form", "acceptance notice"], "max_call_per_hour": 10}` | Limits the types of extracted business documents, and controls interface call frequency to avoid exceeding the carrying capacity of government systems |
| `responseData` | `Only retain petition matter number, applicant information, and handling status fields` | Matches core data requirements of petition business, and reduces invalid data transmission |
| Retry count | 3 times | Adapts to temporary fluctuation scenarios of government interfaces, and prevents business interruptions caused by single call failures |
| Interface timeout | 600 seconds | Matches the time requirements of batch data processing in petition systems, and prevents early request termination |

## Three Common Configuration Errors
- Symptom: Interface calls return a 401 unauthorized error, and logs show missing authentication parameters. Cause: The `Authorization` parameter is not configured correctly, and an unfiled key from the petition system is used.
- Symptom: Webhook-pushed petition data fields are empty, and acceptance notices cannot be generated. Cause: Required extraction business fields are not specified via the `variables` configuration, so original data returned by the interface is not effectively mapped.
- Symptom: Interface calls frequently trigger timeouts, and daily data synchronization cannot be completed. Cause: A reasonable interface timeout is not set, or call frequency exceeds the carrying capacity of government systems.

## How to Verify Successful Configuration
- Initiate a single test call, and check if the returned `responseData` includes core fields such as petition matter number, applicant information, and handling status.
- View interface call logs, and confirm that the `Authorization` parameter format is `Bearer {valid key}` with no format errors.
- Simulate a daily data update scenario, and verify that interface call frequency does not exceed the configured 10 calls per hour limit.
- Trigger a webhook push, and confirm that the receiving end can correctly parse fixed-format fields of petition business documents.

The values provided are common starting points, and should be assessed against local deployment samples.
