# Business Process Guidance for Petition Matter Handling: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data is sourced from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives, with updates occurring daily. Daily processed documents include petition registration forms, acceptance notices, transfer and assignment letters, handling opinion letters, review and re-review applications, resolution plans, and other related materials. Document fields cover request subjects, matter types, handling progress, review results, and other relevant details. There are no unified fixed format requirements; adaptation to form specifications of petition agencies at different levels is required.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Data is updated daily and sourced from multiple channels, so multi-turn dialogue context must sync the latest petition matter status to avoid referencing expired handling information. Document types cover full-process handling materials, so prompts must adapt to the field logic of different documents. For example, distinguish the acceptance scope of acceptance notices from the response content of handling opinion letters. Petition matters must strictly follow legal handling procedures; multi-turn dialogue must accurately identify whether a matter falls within the acceptance scope, and must not exceed legal boundaries. Calls to historical archives must match the time range of the current request to avoid confusing different batches of petition matters.

## How to configure settings

| Configuration Item | Recommended Setup | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique code of the petition matter | Ensure each round of dialogue is associated with the exclusive context of the corresponding petition matter, avoiding cross-matter confusion |
| `messages` | Retain the last 10 rounds of interaction content | Cover key dialogue nodes from request submission to handling opinion feedback, meeting the context requirements for process guidance |
| `variables` | Auto-fill petition matter type and handling status | Adapt to the fixed fields of petition documents, ensuring accurate business data calls for prompts |
| Dialogue timeout threshold | 60 seconds | Match the real-time response requirements of petition business, avoiding user waiting timeouts |
| Streaming output configuration | Enabled, push in segments every 300 characters | Gradually display handling guidance steps, aligning with the progress notification logic of petition matter handling |

## Three common misconfigurations
- Streaming output links fail to jump to new pages, and only update content within the current page. The cause is that no page jump rules for dialogue interactions are configured; content is only updated within the current dialogue container, and adaptation to the external jump requirements of petition matter handling is missing.
- Dialogue log details do not match the actual response content, and initial content is still displayed after multiple dialogues. The cause is that `chatId` is not correctly bound to the petition matter code, resulting in context not updating with dialogue and always loading initial session data.
- Non-petition acceptance scope matters are mistakenly included in the guidance process during multi-turn dialogue. The cause is that no acceptance scope identification rules are configured in the prompt, and no legal acceptance boundary data of petition matters is called for verification.

## How to verify configurations are correct
- Initiate a simulated petition request dialogue, check whether `chatId` is automatically generated and bound with the petition matter code.
- View the dialogue log, confirm that the `messages` field updates with each round of dialogue, and historical content is complete without repeated loading.
- Test streaming output, confirm that content is pushed in segments and links can normally jump to the corresponding handling document page.
- Input a request that falls outside the petition acceptance scope, check whether the dialogue triggers an identification prompt and does not enter the handling guidance process.
