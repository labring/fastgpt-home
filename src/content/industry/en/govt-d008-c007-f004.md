# Business Process Guidance for Petition Matter Handling: Workflow Orchestration

## What this category's data looks like
This category's data comes primarily from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. The data updates daily. Core documents used in daily operations include the petition registration form, acceptance notice, transfer and assignment notice, handling opinion, review and recheck application, and resolution plan. Core fields include requester information, matter category, handling node status, review and recheck result, and others. The data structure binds tightly to statutory handling procedures, with no extra custom statistical fields.

## What constraints these characteristics impose on the workflow orchestration link
Data sources cover multiple government systems. Workflow orchestration must configure cross-system data pull nodes to ensure consistent data synchronization across all links. Daily updated data sources require scheduled trigger synchronization nodes to avoid data lag. Multiple types of statutory documents have fixed structures. Workflow orchestration must add field validation nodes to block process flow with missing key information. To avoid duplicate petitions and petitions filed beyond the authorized jurisdiction level, the acceptance scope screening node must be set as a mandatory starting link of the process. Subsequent links must bind branch processing logic for review and recheck.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind petition matter ID and requester phone number | Used to pass unique business identifiers across nodes, and associate historical archives with the current handling process |
| User selection | Set two options: "Whether it falls within the acceptance scope" and "Whether review is required" | Matches statutory diversion nodes for petition handling, and reduces manual judgment errors |
| Form input | Limit input character count to 200–1000 characters | Adapts to standard filling requirements of the petition registration form, and avoids overly long content affecting process flow |
| API call | Set timeout to 600 seconds | Aligns with interface response times of connected government systems, and avoids process interruptions due to timeouts |
| `nodeId` | Bind the unique ID of the acceptance notice generation node | Ensures accurate triggering of the statutory document generation link during process jumps |

## Three common configuration mistakes
- Phenomenon: Importing a workflow from version 4.6.7 to FastGPT version 4.17.0 causes field loss in node configurations. Cause: The `variables` parameter structure changes across versions, and no adaptive conversion is performed.
- Phenomenon: Using form input components in workflows published via API calls fails to trigger interaction prompts. Cause: The interactive wake-up switch for `variables` passing is not enabled in the API configuration, so the front end cannot trigger the input pop-up window.
- Phenomenon: Passing a knowledge base ID variable while configuring a form input component causes an error. Cause: The knowledge base ID variable is not bound to the form's data source association item, so the component cannot recognize valid parameters.

## How to confirm correct configuration
- Trigger the process start node, verify automatic pulling of historical archive data for the corresponding petition matter, and confirm the data source node configuration is valid.
- Submit form input content, check triggering of preset field validation rules, and confirm the form configuration meets business requirements.
- Call the API to access the published workflow, confirm the interactive component pops up normally and receives user input, and confirm the API configuration is correct.
- Switch to the process branch node, verify triggering of the corresponding handling link based on the selected option, and confirm the branch logic configuration is correct.
