# Business Process Guidance for Petition Matter Handling: Document Parsing and Chunking

## What the data for this category looks like
This category’s data originates from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives.
The system updates this data daily.
Commonly processed documents include standardized materials such as petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-examination applications, and resolution plans.
Most of these documents combine structured forms and policy statements. Some materials include associated information for historical petition cases.

## What constraints these characteristics impose on the "document parsing and chunking" link
Daily updated batch data requires an efficient, stable parsing process. Parsing delays must be avoided to prevent disruptions to business processing progress.
Standardized documents and non-standardized historical archives exist side by side. The parsing logic must adapt to both structured field extraction and free text splitting.
Data from multiple sources may have inconsistent formats. Parsing parameters need to be flexibly adjusted to cover different types of petition materials. Key processing link information must not be missed.
Failure to meet these requirements may lead to problems such as repeated petitions or petitions submitted at a level higher than the authorized hierarchy.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Petition-related documents contain structured fields and policy statements. Setting the chunk size too long will lose context. Setting it too short will disrupt the logic of the processing flow. This range is determined based on actual testing. |
| `chunkSplitter` | Split by paragraph + title | Petition documents have clear titles for processing links. Splitting by titles preserves the integrity of the processing flow. |
| `customPdfParse` | Enable structured parsing | Most petition-related PDFs are standardized forms. Structured parsing can extract fields to avoid missing information. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | A single petition archive PDF may contain multiple historical materials. Sufficient timeout time is required to complete parsing. |
| `chunkSettingMode` | Manual configuration | Parameters for chunking need to be adjusted for different types of petition documents. This adapts to differences between acceptance notices and handling opinions. |

## Three common misconfigurations
- When uploading an Excel petition registration form, some fields appear empty. The symptom is that table column data is missing after parsing. The cause is that custom table parsing configuration is not enabled. The default parsing logic does not adapt to the structured field format of the petition registration form.
- Parsing timeout occurs during batch import of historical petition archive PDFs. The symptom is that the task status shows a timeout failure. The cause is that the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. A single archive containing multiple historical materials causes parsing time to exceed the default threshold.
- Images inserted into PDFs cannot be parsed. The symptom is that the parsed result after upload does not include image content. The cause is that the image extraction switch for `customPdfParse` is not enabled. The default PDF parsing only extracts text content.

## How to verify correct configuration
- A single standardized PDF of a petition handling opinion is uploaded. The parsed result is checked for complete processing link descriptions and policy explanation content.
- An Excel petition registration form is uploaded. The parsed data fields are verified to be consistent with the original table, with no missing or misaligned content.
- The `chunkSize` parameter is adjusted. The paragraph splitting in the chunk preview interface is checked to preserve the complete logic of the processing flow.
- 10 historical petition archives are batch uploaded. All parsing tasks are confirmed to be completed within the time set by `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided here are common starting points and should be evaluated against the specific samples being used.
