# Workflow Guidance for Petition Matter Handling: Forms and Interactions

## What This Category of Data Looks Like
This category of data is primarily sourced from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. The update frequency is daily. Commonly involved documents include petition registration forms, acceptance notice letters, transfer and assignment notices, handling opinion letters, review and re-examination applications, and resolution plans. Data fields include requesting party information, details of requested matters, handling process nodes, responsible unit identifiers, review and re-examination status, and other process-related structured information. No additional statistical quantitative fields are included.

## Constraints Imposed on Forms and Interactions
Multi-source data sources require forms to configure cross-system field mapping rules. This ensures that petition data imported from different platforms can be uniformly adapted to interaction logic.
Daily update frequency requires interaction links to support real-time pulling of the latest handling status. This prevents information lag.
Multiple document structures require forms to preset field templates corresponding to different document types. This allows handling staff to quickly call required templates.
The time-consuming link of verifying acceptance scope requires forms to include standardized selection options. This assists in rapid validation of request legality and reduces manual verification costs.
Potential errors from review and correction require forms to set mandatory validation for key fields such as handling opinions and review applications. This prevents missing critical information that causes process exceptions.

## Configuration Settings
This configuration applies to FastGPT v4.17.0. The specific settings are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable multi-field grouping, with each group corresponding to one type of petition document | Petition work includes multiple document types; grouping improves filling efficiency |
| `userSelect` | Preset 12 fixed options including petition responsible units and request categories | Reduces manual input errors and adapts to standardized handling processes |
| Timeout Threshold | 600 seconds | Adapts to the time required for multi-source data synchronization; calibrated based on actual testing |
| Context Window Configuration | 8000–12000 token | Adapts to the average length of petition documents and ensures complete information |
| Form Template Switching | Support quick switching by handling link | Matches document format requirements for different handling stages |
| Form Field Character Limit | 1000–2000 characters | Adapts to the typical length of petition matter descriptions |

## Three Common Misconfigurations
- When configuring `userSelect`, preset standardized options are not included. Invalid field prompts appear on the interface. This occurs because options are not configured using the fixed list of responsible units and request categories for petition work, so the system cannot recognize valid inputs.
- A timeout error occurs after form submission, with a 504 status code. This happens because the configured timeout threshold is lower than the actual time required for multi-source data synchronization, and reasonable values were not calibrated via actual testing.
- Existing fields are not cleared when switching document templates, leading to field conflicts. This occurs because no field reset logic is configured when switching templates, causing overlapping fields from different documents to trigger exceptions.

## How to Confirm Successful Configuration
- Import a historical petition registration form. Verify that the form automatically matches the corresponding fields and fills in content.
- Select different handling links. Confirm that the form template switches correctly and displays the required fields for the corresponding document.
- Enter an option not preset in `userSelect`. Check that the system displays a valid input verification prompt.
- Simulate form submission. Confirm that submission time does not exceed the preset timeout threshold, and no error messages are shown.

The values listed above are common starting points. They should be evaluated against the user’s own samples.
