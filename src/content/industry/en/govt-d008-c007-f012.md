# Business Process Guidance for Petition Matter Handling: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes primarily from the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. The update frequency is daily. Documents processed daily include petition registration forms, acceptance notices, transfer and assignment notices, handling opinions, review and re-examination applications, and resolution plans. Data fields cover requester subjects, matter content, handling progress, review results, and more. There is no fixed unified unit, as values vary by document type. Processing entities are mostly petition bureaus, departmental petition offices, subdistrict and township offices, and responsible unit offices.

## Constraints on Deployment and Upgrade
Multi-source data access requires configuring parsing rules compatible with multiple system data formats during deployment, to prevent import failures caused by data format differences. The daily update frequency requires configuring a stable incremental synchronization mechanism after deployment, to ensure real-time petition data and avoid disconnects between handling processes and latest data. Diverse document types with significant structural differences require retaining compatibility with original document parsing rules during upgrades, while supporting adaptation for new document types, to ensure normal reading of historical petition archives. Legal handling processes for petition matters are linked to data verification, so the deployment phase must ensure data field integrity verification logic meets business requirements, to avoid handling process errors caused by configuration oversights. Additionally, storage of sensitive petition data requires configuring compliant access controls to prevent unauthorized access to sensitive handling materials.

## Configuration Settings
These configuration items apply to FastGPT v4.17.0, and are adapted to the deployment and upgrade needs of the petition matter handling scenario.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_letter` | Adapt to the unstructured document storage needs of the petition matter handling scenario, supporting persistent storage of documents such as petition registration forms and handling opinions |
| `REDIS_URL` | `redis://:password@host:6379/0` | Used to cache frequently accessed petition acceptance scope judgment rules and handling process templates, reducing resource consumption from repeated calculations |
| `DB_MAX_LINK` | `800–1200 requests/minute` | Match the daily batch synchronization upper limit of petition data, avoiding task interruptions caused by exceeding database connection limits during synchronization |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit encrypted string` | Used to encrypt download links for sensitive petition documents, preventing unauthorized access to materials such as acceptance notices and review and re-examination applications |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the official address of the local storage or object storage service provider` | Adapt to the long-term storage needs of petition archives, supporting batch upload and download of multiple types of documents |
| `FE_DOMAIN` | `Official domain name of the petition matter handling guidance page` | Configure the service access entry, ensuring business personnel can access the process guidance tool via the specified address |

## Three Common Configuration Errors
- Symptom: After starting the service, historical petition archive data fails to load, and the console displays a database connection timeout error. Cause: Access permissions for `MONGODB_URI` or `PG_URL` are not correctly configured, preventing connection to the original petition system data source.
- Symptom: After updating the service to the latest version, field missing occurs in the parsing results of original acceptance notices. Cause: Compatible configurations for legacy document parsing were not retained during the upgrade, making it impossible to recognize non-standard field structures of original documents.
- Symptom: Memory overflow error occurs during batch synchronization of daily petition data. Cause: A reasonable upper limit for `DB_MAX_LINK` is not set, causing excessive database connection resource usage during synchronization and triggering service exceptions.

## How to Verify Configurations Are Correct
- Run the preset data synchronization script, check whether daily updated data from the national petition information system can be pulled normally, and verify that the number of pulled data matches system statistics.
- Access the domain configured in `FE_DOMAIN`, test whether the petition matter process guidance page can normally load preview content of documents such as acceptance notices and handling opinions.
- Use the permission interface corresponding to `ROOT_KEY` to test whether new or modified petition matter acceptance scope judgment rules can be added, verifying that the configuration takes effect.
- Check the service logs to confirm that the cache service corresponding to `REDIS_URL` is connected normally, with no frequent disconnection error messages.
