# Business Process Guidance for Public Data Catalog and Opening: Vector Models and Indexes

## What data in this category looks like
Data in this category primarily originates from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is once per month. Daily documents include public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Core fields cover data item names, opening scope, desensitization methods, interface addresses, update cycles, and similar items. Most content uses structured fields, with a small volume of unstructured interface description documents as supplementary material.

## What constraints these characteristics impose on the vector models and indexes workflow
The monthly update frequency eliminates the need for high-frequency incremental indexing. Configure periodic full synchronization to cover data changes. The high share of structured fields requires distinguishing field types during chunking, to avoid mixing desensitization rules with data item content during chunking. The large number of data items requires adjusting the index recall upper limit to cover the full catalog content. The lengthy unstructured content in interface documents requires adapting a reasonable chunk length to retain complete semantics. Additionally, desensitization rule fields must be filtered before indexing, to prevent sensitive data from being leaked after being encoded by the vector model.

## How to set configurations
| Config Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the structured field length of public data catalogs and the unstructured content of interface documents |
| Overlap Length | 100–200 characters | Prevents loss of cross-chunk process steps and associated data item information |
| Similarity Threshold | 0.75–0.85 | Balances the accuracy and coverage of catalog content recall |
| Single Search Upper Limit | Top 20 entries | Adapts to the large number of data items in this category, avoids returning redundant results |
| `defaultToken` | 4096 | Adapts to the maximum encoding length of a single catalog document |
| `maxToken` | 8192 | Adapts to the total length requirement after splicing retrieval context |

## Three common configuration errors
- Search results display unsensitized data item details. Cause: Failed to filter sensitive fields associated with desensitization rules during the chunking phase, resulting in sensitive content being encoded into the vector index.
- The catalog after index update does not match the actual open data. Cause: Did not configure the index trigger cycle according to the monthly update frequency, resulting in the index failing to synchronize the latest open data items or update rules.
- The search interface returns a 504 timeout error. Cause: The single search upper limit is set too high, exceeding the inference load threshold of the vector model.

## How to verify the configuration is correct
- Upload a sample public data catalog document, check that the chunked content filters desensitization rule fields and retains valid data item information.
- Trigger an index construction task, check that the system log shows synchronization completed according to the set cycle, with no abnormal errors.
- Initiate a retrieval request containing a specific data item name, check that the similarity score of the returned results falls within the set threshold range.
- If an external index model is configured, call the test interface to confirm the return status code is 200, and the result matches the local index result.

The values provided are common starting points and should be measured against the reader's own samples.
