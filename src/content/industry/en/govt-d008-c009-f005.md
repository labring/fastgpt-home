# Business Process Guidance for Public Data Catalog and Opening: Tool Calling and Plugins

## What data in this category looks like
Data in this category is primarily sourced from local public data opening platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Updates occur once per month. Daily maintained documents include public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Data fields include data item name, opening scope, desensitization requirements, interface address, update cycle, authorization boundary, and other items. Units are mostly structured identifiers such as items, times, MB, and similar. No general fields for semi-structured or unstructured text are included.

## What constraints these characteristics impose on tool calling and plugins
Fixed monthly updated data sources require tool calling to adapt to periodic data synchronization verification. This prevents calling expired data. Multi-source structured data requires plugins to support multi-interface aggregated calling, matching request parameters by data item category. Fixed document types require tools to prioritize loading the latest interface documents and desensitization rules during calls. This ensures requests comply with opening conditions. The structured nature of fields requires plugin parameters to strictly match the field names and units of data items. This avoids calling failures caused by format incompatibility. Additionally, configuration of `toolChoice` and `functionCall` must adapt to the calling characteristics of government affairs interfaces. This prevents requests from being intercepted due to improper parameter configuration.

## How to set configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the needs of calling multiple types of interfaces in public data catalogs, automatically matching corresponding tools |
| `functionCall` | `strict: true` | Enforces matching structured fields in public data catalogs, avoiding parameter incompatibility |
| Single tool call timeout | 30–60 seconds | Adapts to the typical response delay cycle of government affairs interfaces |
| Single return data count | Top 10 items | Aligns with the typical range of single-opening data volume in public data catalogs |
| Tool call context cache duration | 1800 seconds | Matches the business processing window duration within the monthly update cycle |

## Three Common Misconfigurations
- Symptom: A 400 InternalError.Algo.InvalidParameter error is returned during calling, prompting that tool parameters do not match. Cause: The strict mode of `functionCall` is not enabled, and field parameters not defined in the public data catalog are passed in.
- Symptom: The plugin call returns empty results or a number of entries that do not match expectations. Cause: A reasonable single return data count is not set, exceeding the single return limit of government affairs interfaces.
- Symptom: Plugins created online cannot trigger calls in business processes. Cause: The corresponding data opening interface document is not bound in the tool configuration, causing the process to fail to recognize the plugin trigger condition.

## How to Confirm Successful Configuration
- Pass standard data item parameters from the public data catalog to call the test interface, check whether the fields and count of the returned results meet the configuration requirements.
- View tool call logs to confirm that no error messages about parameter mismatch or timeout appear.
- Simulate a monthly data update scenario, check whether the plugin can automatically load the latest interface documents and desensitization rules.
- Simulate a government affairs interface delay scenario, verify whether the tool call is completed within the set timeout period.

The values provided are common starting points and should be measured against the reader's own samples.
