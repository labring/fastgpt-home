# Business Process Guidance for Public Data Catalog and Publishing: Model Integration and Configuration

## Constraints Imposed on Model Integration and Configuration
The characteristics listed above impose multiple constraints on the model integration and configuration link. Decentralized data sources and fixed update frequencies require configurations to support periodic synchronous refresh of multi-source data. Documents include structured catalogs and unstructured rules, so configurations must balance precise matching of structured data and context support for unstructured text. Data involves anonymization rules and access boundaries, so configurations must ensure model calls do not disclose non-open data content. The monthly update feature also requires configurations to include trigger logic for periodic index updates, to avoid inconsistencies between the catalog and actual data.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Public data catalogs include multiple lists, interface documents, and rule explanations. Sufficient context is needed to carry complete business process information |
| `maxTokens` | `4000–6000 token` | Single data item descriptions or interface documents have moderate length, to avoid exceeding the model’s single-processing limit |
| `quoteMaxToken` | `2000–3000 token` | Sufficient original catalog entry content must be retained for rule reference verification during business process guidance |
| `toolChoice` | `auto` | Business process guidance requires the model to autonomously select between data query tools and rule explanation tools |
| `temperature` | `0.1–0.3` | Process guidance must accurately match catalog rules, and excessive divergence that deviates from actual requirements should be avoided |
| `AIPROXY_API_ENDPOINT` | Fill in the address of the deployed private proxy service | Adapt to local or privately deployed large language model call links, and ensure secure data transmission |

## Three Common Configuration Mistakes
- A `function call not supported` error returns when calling the large language model. This occurs because the `toolChoice` parameter is not configured correctly, or the proxy service does not support tool calling protocols.
- Results from triggered process guidance queries omit some data item descriptions. This occurs because `maxTokens` is set too low, truncating complete catalog entry content.
- A `401 Unauthorized` error returns when calling the proxy service. This occurs because `AIPROXY_API_TOKEN` is configured incorrectly, or the proxy service’s secret key is not synchronized properly.

## How to Confirm Proper Configuration
- Manually trigger a business process guidance query for the public data catalog, and check if returned results include complete open data item names and corresponding rules.
- Review model call logs to confirm the `toolChoice` parameter takes effect, and that tool call request formats meet expected standards.
- Adjust the `temperature` parameter and run another query, to verify that changes to results align with expected behavior.
- Test proxy service connectivity, to confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` can be used to normally call the large language model.

The values provided here are common starting points, and should be validated against individual deployment samples.
