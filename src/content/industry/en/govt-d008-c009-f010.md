# Public Data Catalog and Opening: Business Process Guidance - Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
Data in this category primarily comes from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is once per month. Daily documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, update frequency explanations, and similar items. The structure is primarily composed of structured fields, with core information such as data item name, open conditions, interface address, desensitization status, and update cycle. No additional unstructured government promotional content is included.

## Constraints on Knowledge Base Retrieval and Recall
Once-monthly update frequency requires the knowledge base to adapt to fixed-cycle full synchronization tasks, to avoid mismatches between stored data and actual open assets. The mostly structured document structure requires retrieval to precisely match field information, and cannot rely solely on semantic fuzzy matching. Multiple source document types require distinguishing different business scenarios such as data item descriptions and interface documents, and adjusting the priority of retrieval matching. Decentralized data sources require limiting the retrieval scope to the exclusive dataset for this category, to avoid mixing other government documents that interfere with results. The large number of data items requires the retrieval recall upper limit to adapt to full data coverage needs, to avoid missing core business content.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Setting |
|---|---|---|
| `similarity` | 0.75–0.85 | Adapts to the matching accuracy of structured data fields, balances recall coverage and relevance, avoids too low values causing irrelevant data to be included, and avoids too high values leading to insufficient recall of core data items |
| `limit` | Top 10 entries | Covers the full data entry range of monthly updates, ensures business process guidance can obtain sufficient relevant documents, and avoids missing core steps |
| `searchMode` | vector_only | Prioritizes matching semantic associations of structured data, avoids interference from unstructured text introduced by mixed retrieval, and improves recall accuracy for professional data documents |
| `usingReRank` | Enabled | Rearranges initial recall results by business relevance, optimizes the sorting order of documents such as data open conditions and interface descriptions |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms for business process questions, for example, expanding "data open application" to relevant content such as application processes and interface permissions for the corresponding catalog |
| `collectionIds` | Fill in according to the actually bound public data catalog dataset | Limits the retrieval scope to only exclusive documents of this category, avoids mixing other government documents that interfere with results |

## Three Common Configuration Mistakes
- Phenomenon: Retrieval results do not include locally bound public data catalog documents, and referenced fields are empty. Cause: Incorrect `collectionIds` configuration, failed to correctly specify the corresponding dataset ID, resulting in the retrieval scope exceeding the target category documents.
- Phenomenon: Retrieval response time exceeds the 30-second business waiting threshold. Cause: Unreasonable `limit` parameter setting, recalling too many low-relevance documents, increasing subsequent processing and model inference overhead.
- Phenomenon: Rearranged results do not prioritize interface documents or desensitization rules. Cause: `similarity` threshold set too high, leading initial recall to fail to cover core business documents, and reranking cannot correct initial sorting bias.

## How to Confirm Proper Configuration
- View the dataset binding list, confirm that `collectionIds` only includes exclusive documents of this category such as public data catalogs and data open lists.
- Initiate a test retrieval, input "data open application process", and check if the returned results include core content such as application steps and interface permission explanations for the corresponding catalog.
- Adjust the `similarity` parameter to 0.8, verify that the relevance of retrieval results meets business expectations, no excessive irrelevant content is mixed in, and the test retrieval response time is controlled between 5–10 seconds.
- Enable the streaming response switch for Feishu bots in FastGPT v4.17.0, test if returned results are displayed step by step in segments, adapting to the interaction needs of real-time business guidance.
