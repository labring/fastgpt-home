# Business Process Guidance for Public Data Catalog and Opening: Forms and Interactions

## Data Profile for This Category
Data under this category comes from local public data opening platforms, integrated big data platforms, departmental business databases, and electronic credential repositories. The update frequency is once per month.
Daily supporting documentation includes public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documentation, and update frequency explanations.
Data fields cover data item identifiers, opening scopes, desensitization requirements, call interface addresses, update cycles, and more. All fields use structured or standardized formats, and must strictly match entries published in official catalogs.

## Constraints for Forms and Interactions
The monthly update requirement means form interactions must support regular synchronization of catalog data, and avoid using expired entries.
Multi-source data requires distinguishing attribution fields such as data owning department and opening platform within forms, to prevent confusion.
The `formInput` field must use a preset fixed format to match the structured documentation requirements of official catalogs, reducing format errors from custom input.
Desensitization rules and interface documentation must serve as associated reference items for forms, automatically linking corresponding verification logic when users submit applications.
The update frequency of data items must be displayed in forms, to help handling staff verify the timeliness of currently available data.

## Configuration Settings
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Preset standard fields for public data catalogs, with input length limited to 800–1200 characters | Matches the structured catalog documentation format published by official sources, reducing format errors from custom input |
| `userSelect` | Limit optional data sources to local public data opening platforms and integrated big data platforms, pin the top 3 popular options | Matches the core source channels for data in this category, preventing users from selecting unauthorized data sources |
| `formInput` | Configure parameter escape rules to filter special characters | Prevents special characters in variables from damaging interface call formats, resolves parameter execution errors |
| Synchronization Frequency Settings | Auto-sync once per month, set synchronization timeout threshold to 600 seconds | Matches the monthly update frequency of data in this category, avoiding synchronization of expired data or synchronization timeouts |
| Verification Rule Binding | Associate desensitization rules and interface document fields, verify input content in real time | Prevents submission of applications that do not match actual data, avoiding subsequent exceptions in interface calls |

## Three Common Configuration Errors
- Phenomenon: After configuring the `userSelect` data source selector, an error "No valid data source selected" appears during submission. Cause: The data source option is not set as a required verification item, or the preset optional data sources do not cover core official channels.
- Phenomenon: Passing data application parameters via variables fails, while manual input of parameters runs normally. Cause: The `formInput` field is not configured with parameter escape rules, causing special characters in variables to damage interface call formats.
- Phenomenon: Public data catalog entries displayed in the form do not match those on the official platform. Cause: The synchronization frequency setting is not configured according to the monthly update cycle, and the automatic synchronization task is not executed regularly, resulting in untimely data updates.

## How to Verify Successful Configuration
- Manually fill in the preset form fields, and verify that they match the entry format of the official public data catalog.
- Test the `userSelect` selector, and confirm that the optional data sources only include the core allowed sources for this category.
- Trigger the automatic synchronization task, and verify that the data displayed in the form matches the latest entries on the official platform.
- Submit a test application, and confirm that all required field verification logic triggers normally, with no format error prompts.
