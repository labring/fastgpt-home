# Public Data Catalog and Opening: Business Process Guidance - Deployment and Upgrade

## What this category of data looks like
This category covers publicly shareable or open structured data assets. Core documents include public data resource catalogs, data opening lists, data item descriptions, anonymization rules, API documentation, and update frequency notes. Data sources cover local public data opening platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update cycle is natural months. Each data entry includes fields such as data item name, opening scope, anonymization rules, API address, update frequency, and authorization conditions. Units match the data type: for example, API addresses use URL format, and update frequency uses natural months as the unit.

## What constraints this category imposes on the deployment and upgrade phase
Data sources for this category are scattered, update cycles are fixed, and anonymization and authorization rules must be strictly followed. This creates multiple constraints during the deployment and upgrade phase. The monthly update frequency requires configuring scheduled synchronization tasks during deployment to ensure consistency between the catalog and actual data. Multi-source data must complete format alignment and field mapping during the deployment phase to avoid data mismatches in subsequent guidance. Anonymization rules and authorization boundaries must be embedded in deployment configurations to prevent data leakage risks. During upgrades, catalog documents and API configurations must be updated simultaneously to avoid inconsistencies between the catalog and actual open data. At the same time, sufficient configuration space must be reserved to adapt to public data opening standards of different regions, ensuring that the guidance process complies with local business requirements.

## How to set configurations
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://10.0.0.5:6379/1` | Used to cache public data catalog metadata, reducing API call frequency for multi-department data queries |
| `STORAGE_S3_ENDPOINT` | `https://oss.gov-example.com` | Stores anonymized public data files and catalog documents, ensuring the data can be called by the business guidance process |
| `FE_DOMAIN` | `https://data.xxx.gov.cn` | Binds the domain for business process guidance, generating valid API and data item links that can be properly redirected |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent connection requirements for multi-department data synchronization, avoiding connection pool exhaustion during synchronization tasks |
| Data synchronization trigger rule | Execute at 3:00 AM on the 1st of each month | Matches the monthly update frequency of this category of data, ensuring the catalog is synchronized with actual data updates |

## Three common errors
- Symptom: The business process guidance plugin returns empty results. Cause: `REDIS_URL` is not configured correctly, causing the catalog metadata cache to fail and unable to match data items queried by users. This issue was reported by some users in FastGPT v4.17.0.
- Symptom: Cross-department data synchronization tasks time out and fail. Cause: The `DB_MAX_LINK` parameter value is too low, with insufficient concurrent connections leading to connection pool exhaustion.
- Symptom: Generated guidance links cannot be redirected properly. Cause: `FE_DOMAIN` is configured incorrectly, with the generated link domain not matching the business system domain.

## How to confirm the configuration is correct
- Navigate to the storage configuration page in the FastGPT system, test the connectivity of `STORAGE_S3_ENDPOINT`, and confirm that catalog files in the storage bucket can be listed normally.
- Manually trigger a data synchronization task, check the task log to confirm synchronization is successful and the number of entries matches the current catalog documents.
- Test generating a business process guidance link, and confirm that the redirected domain exactly matches the `FE_DOMAIN` configuration.
- Enter the Redis monitoring panel, verify that the instance configured with `REDIS_URL` can normally read and write cached catalog metadata.

The values provided are common starting points and should be measured against the reader's own samples.
