# Business Process Guidance for Highway Maintenance and Road Property Rights Management: Tool Calling and Plugins

## What the data for this category looks like
Daily documents for this category include maintenance plans, patrol logs, defect disposal orders, road construction permits, and road damage compensation forms. Data is sourced from highway maintenance management systems, bridge and tunnel monitoring systems, road patrol systems, and traffic flow monitoring data. Updates occur daily. A single data entry typically includes fields such as section identifier, facility type, defect level, disposal time limit, and involved party information. Some documents also link spatial coordinates and traffic statistics values. Data is stored as a combination of structured forms and log text.

## Constraints Imposed on Tool Calling and Plugin Workflows by These Data Characteristics
The daily data update requirement means tool calls must pull patrol and maintenance data generated that same day in real time. Using expired data will reduce the accuracy of process guidance. Documents include both structured forms and unstructured logs. Tool calls must support both structured field extraction and unstructured text parsing to adapt to queries for different types of business data. Business processes involve cross-system approval and disposal status queries. Tool calls must connect to internal road administration and maintenance system interfaces, and adapt to parameter formats across different systems. A single data entry includes spatial coordinates. Tool calls must support geographic information-related parameter passing and matching to ensure query results are accurately linked to the corresponding road section.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically match available tools for the current business scenario, adapting to dynamic calling needs for process guidance |
| `functionCall` | Enable forced call mode | Ensure business process guidance only calls preset tools, avoiding responses that do not comply with business specifications |
| Single tool call timeout | `300 seconds` | Internal highway maintenance system interfaces typically respond within 5 minutes, adapting to delays for standard business data queries |
| Tool call context entries | `Previous 8–12 entries` | Business processes require linking recent patrol and work order information. Excessive historical data increases interface call load and delay |
| Tool result cache duration | `1 day` | Data for this category updates daily. Caching same-day data reduces repeated calls |
| Tool call parameter format | Match structured form fields | Daily documents primarily use structured forms, requiring strict matching of field names and data types |

## Three Common Mistakes
- Calling a MySQL tool returns a 400 status code with no response body. The cause is incorrect configuration of the tool's database connection parameters, or a mismatch between field formats and database table structures.
- Calling the FastGPT workflow API fails to retrieve context information, even when context settings are enabled for the workflow. The cause is the API request parameters not including a session ID, or the context cache expiration duration being set too short.
- Passing the `model` parameter in an API call fails to clarify the corresponding task type. The cause is not binding a mapping relationship between the model and business tasks in the tool call configuration, leading to confusion of model tasks.

## How to Verify Proper Configuration
- Initiate test calls for road property queries and defect disposal work order queries, and confirm that the tool returns patrol logs or disposal order data for the corresponding road section.
- Review tool call logs to confirm that the matching result of the `toolChoice` parameter matches the preset tool group.
- Check that API requests include a session ID, and verify that context information is properly passed to the workflow.
- Simulate cross-system interface calls, and confirm that the tool call timeout setting does not trigger abnormal interruptions.

The values given are common starting points and should be measured against the reader's own samples.
