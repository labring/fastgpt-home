# Business Process Guidance for Highway Maintenance and Road Property Rights Management: Model Access and Configuration
This document is written for FastGPT v4.17.0.

## What this category of data looks like
This category of data primarily originates from highway maintenance management systems, bridge and tunnel monitoring systems, road administration patrol systems, and traffic flow monitoring data, with a daily update frequency. Daily documents involved include maintenance plans, patrol logs, defect disposal forms, road-related construction permits, and road property damage compensation forms. Most document fields are associated with road facility numbers, maintenance cycles, disease types, road-related project scopes, and similar attributes. Units used follow road-related measurement standards such as kilometers, square meters, and cubic meters.

## What constraints do these characteristics impose on the "model access and configuration" link
This category of data updates daily and includes multiple types of structured documents and unstructured images. Configure models to adapt to context loading for high-frequency incremental data, to avoid process interruptions caused by context overflow. For the multi-field associated document structure, define clear information extraction boundaries for the model during configuration, to prevent cross-field confusion. For compliance verification requirements of road-related documents, adjust the model's output rigor parameters. For processing image-based disease data, configure access parameters for corresponding visual models to ensure accurate identification of disease features on roads and bridges/tunnels.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `vision` | Enable and configure for general image recognition | This category includes image-based patrol data of road and bridge/tunnel diseases, requiring visual capabilities to extract disease features |
| `maxContext` | 8000–12000 token | Adapt to the context of multiple documents such as daily updated patrol logs and road-related permits, to avoid overflow when loading incremental data |
| `maxTokens` | 2000–3000 token | Limit the length of single-round model output, to avoid overly long process guidance text being generated |
| `temperature` | 0.2–0.4 | Road-related business requires rigorous output, reduce random generation probability to ensure accurate extraction of information from work orders and permits |
| `AIPROXY_API_ENDPOINT` | Fill in the local proxy address or compliant node address | Adapt to the domestic network environment for accessing large models, to avoid failures caused by cross-border access |
| `toolChoice` | Set to auto | Automatically call tools to handle structured data extraction and compliance verification, adapt to multi-link business process guidance |
| `quoteMaxToken` | 1500 token | Limit the length of quoted document fragments, ensure extracted information from maintenance plans and patrol logs is accurate and not redundant |

## Three Common Misconfigurations
- A 400 error is returned when testing model availability, with the interface displaying request parameter abnormalities. The cause may be an incorrect `AIPROXY_API_TOKEN` configuration, or `AIPROXY_API_ENDPOINT` not pointing to a compliant proxy node.
- Road surface disease images cannot be correctly identified, and the extracted disease type does not match the actual patrol record. The cause is that the `vision` configuration is not enabled, or the model's recognition accuracy is not adjusted for road facility images.
- A context overflow error occurs during process execution, and the task terminates directly. The cause is that the `maxContext` setting value is too small, failing to adapt to the total length of multiple types of documents such as newly added daily patrol logs and road-related permits.

## How to Confirm Proper Configuration
- Initiate a test request including road surface disease images, and verify whether the model correctly outputs disease type and location description to confirm the `vision` configuration takes effect.
- Import a single maintenance plan and patrol log, and test whether the fields extracted by the model match the document content to confirm that the `maxContext` and `temperature` parameters fit the business needs.
- Review proxy logs, and confirm that there are no format errors in the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations, and no network interception occurs.
- Trigger the automatic tool call process, and verify whether the model can automatically associate road-related permits and maintenance work orders to confirm that the `toolChoice` configuration is correct.
