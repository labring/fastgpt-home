# Business Process Guidance for Pension, Work Injury, and Unemployment Benefit Verification: HTTP Interfaces and External Systems

## What This Category’s Data Entails
This category covers public service operations in the human resources and social security domain. Data is sourced from social insurance handling systems, personal rights and interests records, labor relations and work injury identification systems, and the electronic social security card platform. Data is updated daily. Commonly associated documents include benefit application forms, payment period certificates, retirement approval forms, work injury identification materials, and unemployment benefit application materials. Data fields include payment period (measured in years or months), benefit calculation standard (measured in yuan per month), applicant identity identifier, work injury identification number, and other fields, all focused on benefit verification eligibility and amount.

## Constraints for HTTP Interfaces and External Systems
Multiple data sources require interfaces to be compatible with different return formats and field naming conventions. Pre-docking adaptation must be completed first. The daily update frequency means interface cache durations should not be overly long, to avoid returning delayed benefit calculation data. Diverse associated document types require interfaces to support both structured application forms and unstructured proof materials. The most time-consuming steps of calculating payment periods and reviewing materials require interfaces to allocate sufficient response time. All fields have clear units, so interface parameter verification must align with unit rules for payment periods and benefit standards. This prevents issues including incorrect or missing benefit payments and fund recovery.

## Three Common Misconfigurations
- An `Error: write EPROT` response is returned when calling the interface. This occurs due to incorrect configuration of the `Authorization` parameter leading to identity verification failure, preventing the external system from establishing a secure connection.
- Non-streaming requests disconnect automatically after 180 seconds. This occurs because the interface timeout setting was not adjusted; the default threshold does not cover the full business process time for this category.
- The intelligent agent returns handling procedures that lack guidance for specific materials. This occurs because the corresponding business number parameter was not passed in `variables`, so the intelligent agent cannot match the corresponding document content.

## How to Confirm Proper Configuration
- Call the interface with a test applicant ID parameter, and check if `responseData` returns the corresponding benefit verification process steps.
- Simulate submission of complete business documents, and confirm the interface completes the response within the preset timeout range with no identity verification errors.
- Review the intelligent agent’s running logs, and confirm that the business fields in the `variables` parameter are correctly loaded and used for process guidance.
- Test uploading different types of associated documents, and confirm the interface can correctly identify and associate corresponding material content.
