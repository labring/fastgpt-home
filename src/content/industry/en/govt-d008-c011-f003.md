# Business Process Guidance for Pension, Work Injury, and Unemployment Benefit Verification: Multi-turn Dialogue and Prompt Engineering

This configuration is based on FastGPT v4.17.0.

## What the data for this category looks like
Data for this category originates from social insurance handling systems, personal entitlement records, labor relations and work injury identification systems, and the electronic social security card platform. It is updated daily. Daily business documents include benefit application forms, payment period certificates, retirement approval forms, work injury certification materials, and unemployment benefit application materials. Each document includes fixed business fields such as payment duration, insured period, disability level, and application qualification flag. Data must be associated across systems to support benefit calculation and review.

## Constraints on multi-turn dialogue and prompt engineering workflows
Multi-source data association requires dialogue to gradually guide users to provide required scenario-specific fields, to avoid missing key information. Daily updated data requires prompts to call the latest data source, to ensure accurate calculation results. The variety of daily business documents requires dialogue to first distinguish between pension, work injury, and unemployment scenarios, then match the required fields of the corresponding documents. The strict requirements of benefit verification require dialogue to verify the completeness of submitted fields, to prevent errors in subsequent calculations caused by missing information.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` binding rule | Associate with user's unique identity identifier | Isolate historical conversations of different users, avoid confusion of session data |
| `variables` preset variables | Include "business type" and "user insured location" | Distinguish pension, work injury, unemployment scenarios, bind corresponding data sources and business document templates |
| `messages` initial prompt | Include scenario guidance and required material list for the corresponding business | Match field requirements of daily business documents, reduce user omission of information |
| Session timeout period | 1800 seconds | Adapt to the processing duration of multi-step material submission for benefit verification |
| Question optimization switch | Enabled | Simplify colloquial user expressions, align with standard terminology specifications for social security business |
| File upload permission | Enabled and restricted to material types | Allow users to upload certification materials related to benefit applications, match business handling needs |

## Three common configuration mistakes
- Phenomenon: Clicking the preset shortcut button in the conversation opening screen does not trigger the corresponding guidance question. Reason: The trigger logic of the shortcut button is not bound to the initial session configuration of `messages`, causing the button to not be associated with a valid session instruction.
- Phenomenon: Unable to receive materials uploaded by users for benefit applications when calling the conversation API. Reason: The file upload permission for the conversation scenario is not enabled, or the whitelist restriction for material types is not configured, causing illegal files to be blocked.
- Phenomenon: Different test users can view each other's historical conversation records after logging in. Reason: `chatId` is not bound to the user's unique identity identifier, resulting in no user-level isolation of session data.

## How to confirm the configuration is complete
- Initiate a test conversation, select the corresponding business type, and check if the initial prompt lists the required business documents and fields for that scenario.
- Switch to two different test users to initiate conversations, and check historical records to confirm that only the current test user can view their own session content.
- Upload certification materials for the corresponding business, and check if the system can correctly identify the material type and guide the next operation.
- Wait 1800 seconds and check the session status, confirm that no abnormal errors occur and the session closes normally.
