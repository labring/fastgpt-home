# Business Process Guidance for Pension, Work-related Injury, and Unemployment Benefit Verification: Workflow Orchestration

## What the Data for This Category Looks Like
This category's business data originates from social insurance handling systems, personal entitlement records, labor relations and work-related injury identification systems, and the electronic social security card platform. The update frequency is daily. Commonly used documents include benefit application forms, payment duration certificates, retirement approval forms, work-related injury identification materials, and unemployment insurance benefit application materials. These documents contain fields such as participant identity identifiers, payment cycles, identification grades, and benefit calculation parameters. Document structures fall into two categories: structured forms and unstructured certificates. Field extraction rules must be adjusted for different business scenarios.

## Constraints on Workflow Orchestration
Multiple data sources require workflows to be configured with cross-system connection nodes to centrally aggregate business data from all systems. The daily update frequency requires workflows to align with data synchronization rhythms and regularly pull the latest entitlement records. Multiple types of business documents require workflows to be configured with differentiated processing rules to adapt to the parsing of structured forms and unstructured certificates separately. The complexity of benefit calculation requires workflows to split into sub-nodes such as calculation, review, and adjustment, set reasonable execution sequences and exception branches, and prevent single-node execution timeouts.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `variables` | Aggregate fields such as participant identity, payment duration, and benefit calculation parameters | Unify the input format of cross-system data sources and adapt to shared parameters for multiple categories of businesses |
| `nodeId` | Assign unique identifiers to calculation nodes, review nodes, and exception branch nodes | Facilitate location of process execution logs and troubleshooting of exceptions |
| Node timeout setting | 600 seconds | Match the average time required for social insurance business data pulling and calculation, avoid process blocking |
| Global variable trigger timing | After daily data synchronization is completed | Align with the daily update frequency of business data, ensure the workflow uses the latest entitlement records |
| Document processing rules | Enable field validation for structured forms, enable text extraction for unstructured certificates | Adapt to multiple types of business documents such as benefit application forms and work-related injury identification materials |
| System version adaptation | FastGPT v4.17.0 | Using the workflow orchestration function of this version provides complete exception handling and parameter verification capabilities |

## Three Common Misconfigurations
- The `variables` field returned by the workflow has overlapping content. The symptom is that the output of the last node contains all results from previous nodes. The cause is that temporary `variables` storage is not cleared after node execution completes, leading to continuous data accumulation.
- Workflow configuration cannot be exported. The symptom is that the export button is grayed out or the exported JSON file is empty. The cause is that there are unconfigured data source nodes in the workflow that fail to pass the system's built-in validation rules.
- Assigning values to global variables via an API access link fails. The symptom is that global variables do not update after the API is called, and a 400 status code is returned. The cause is that request parameters do not correctly match the field definition format of `variables` and do not carry required business parameters.

## How to Confirm Successful Configuration
- Trigger workflow execution, view the `variables` field in the process log, and confirm that the output of each node only contains relevant data for the current business, with no abnormal accumulated content.
- Click the workflow export button, and confirm that the exported file can be downloaded normally, with complete process configuration information included in the file content.
- Use a test API request to pass specified parameters, check the update status of global variables, and confirm that the parameters have been correctly synchronized to the workflow.
- Enter the exception branch configuration page of the workflow, confirm that the trigger rules for each exception scenario match the business validation logic, and that the workflow can normally jump to the corresponding processing node.
