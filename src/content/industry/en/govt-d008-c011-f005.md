# Business Process Guidance for Pension, Work Injury, and Unemployment Benefit Verification: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from social insurance handling systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. This data updates daily. Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury identification materials, and unemployment benefit application materials. These documents fall into two broad categories: structured forms and unstructured proofs. Covered fields include payment duration, benefit calculation base, qualification determination results, application batches, and more. Units include months, yuan, years, and others.

## What constraints these characteristics impose on the tool calling and plugins link
Multi-source data access requires tool calling configurations to include multiple cross-system integration plugins, to ensure synchronized access to information from different sources such as payment records and work injury identification results. Daily updated data sources require reasonable cache validity settings for tool calling, to avoid returning outdated benefit calculation data. Mixed structured and unstructured document types require plugins to support both form field extraction and unstructured text recognition, to adapt to business materials in different formats. Benefit calculation and review are core time-consuming steps. Tool calling must split complex calculations into independent nodes, to reduce information load per round of context.

## How to set configurations
This document is based on FastGPT v4.17.0 configuration instructions.

| Configuration Item | Suggested Setting | Rationale for This Setting |
| --- | --- | --- |
| Tool calling mode | `functionCall` | The business logic for this category is clear, and fixed calls to benefit calculation and qualification review tools are required. `functionCall` can enforce calling specified tools |
| Single tool call timeout | 600 seconds | Benefit calculation requires retrieving data from multiple systems, which takes a long time. 600 seconds covers most cross-system query scenarios |
| Maximum number of tool return results | First 5 entries | Business review only requires core key data such as payment records and identification conclusions. Excessive results increase context load |
| Context cache refresh cycle | 24 hours | Matches the daily update frequency of data sources, ensuring that called business data is the latest version |
| Plugin call permission scope | Only social insurance business-related plugins | Avoid calling unrelated tools, protect business data security, and comply with permission control requirements of government affairs systems |

## Three common misconfigurations
- The symptom is a 429 Request rate increased too quickly error returned by tool calling. The cause is failure to set a reasonable call rate threshold in accordance with the interface rate limit rules of the social insurance system, triggering frequent cross-system queries that exceed limits.
- The symptom is chaotic format and missing fields in business data returned by plugins. The cause is failure to configure extraction rules for exclusive documents such as benefit application forms and work injury identification materials for this category; general plugins cannot accurately parse government affairs form structures.
- The symptom occurs when multiple applications share a model API key: the configuration of a new application overwrites the settings of an existing application. The cause is failure to bind an independent plugin call key pool for each application, leading to key configuration conflicts.

## How to confirm configurations are correct
- Submit a simulated pension benefit verification application, check the tool call log, and confirm that the three specified plugins for payment duration query, benefit calculation, and qualification review are called correctly.
- Check the business data fields returned by the tool, confirm that core content such as payment duration, benefit calculation base, and qualification determination results are included, and match the data source update frequency.
- Test multiple consecutive simulated calls, confirm that no request rate too high error is triggered.
- Verify that in multi-application scenarios, plugin call configurations for different applications take effect independently and do not overwrite each other.
