# Business Process Guidance for Pension, Work Injury, and Unemployment Benefit Verification: Document Parsing and Chunking

## What this type of data looks like
Data sources include social insurance management systems, personal benefit records, labor relations and work injury determination systems, and electronic social security card platforms. The update frequency is daily. Commonly processed documents include benefit application forms, payment period certificates, retirement approval forms, work injury determination materials, and unemployment benefit application materials. Most documents contain structured tables and numeric fields such as cumulative payment months, disability level, and unemployment registration number. Field units include months, levels, identification numbers, and others. Supported formats include PDF, electronic forms, and other types.

## Constraints on the document parsing and chunking link
Documents contain large numbers of structured tables and associated fields. Chunking must avoid splitting associated data across fields, to ensure that core information for benefit calculation and qualification review is not separated. Daily updated data requires the parsing link to quickly process incremental documents, to maintain the timeliness of business handling. Documents from multiple sources have inconsistent formats, so chunking logic must be adapted to different structures. Errors in benefit-related fields can lead to serious consequences. Therefore, the parsing and chunking links must retain information integrity and relevance, avoiding field confusion or missing data.

## Configuration recommendations
For FastGPT v4.17.0, refer to the following configuration items and recommended values:
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of long text descriptions and structured table fragments in benefit verification documents, avoiding splitting core calculation fields |
| `chunkSplitter` | Paragraph + semantic chunking | Matches the natural paragraph logic of benefit application processes and qualification conditions in documents, retaining contextual relevance |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for single 10–20 MB work injury determination materials and payment period summary PDFs, preventing timeout errors |
| `customPdfParse` | Enable structured table parsing | Retains the integrity of table fields in payment period certificates and benefit calculation forms, avoiding disordered table content after parsing |
| `UPLOAD_FILE_MAX_SIZE` | 20 MB | Adapts to the upper limit of multi-page PDF documents uploaded by street social security windows, preventing upload restrictions from being triggered due to oversized files |

## Three Common Misconfigurations
- Uploading a ~15 MB PDF of unemployment benefit application materials triggers a timeout error, with the interface displaying `timeout of 360000ms exceeded`. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter to a value suitable for large file parsing.
- Long paragraphs of benefit calculation instructions in chunking results are forcibly split, causing policy descriptions and application conditions in the same paragraph to be separated. The symptom is incomplete retrieval results. The cause is failure to enable automatic merging logic for long paragraphs, and the `chunkSplitter` configuration only relies on hard separators.
- After importing a preset question-and-answer pair knowledge base document, the answer content in the parsing result is split into multiple chunks, failing to guarantee the integrity of the original reply. The cause is failure to set `chunkSettingMode` to chunk by question-and-answer pair boundaries, or setting `chunkSize` beyond a reasonable length for question-and-answer pair replies.

## How to Verify Correct Configuration
- Upload a single ~15 MB benefit verification document, check whether timeout errors exist in the parsing log, to verify that the `PARSE_FILE_TIMEOUT_SECONDS` parameter is effective.
- Randomly select a payment period certificate PDF, check the parsed chunking results, confirm that table fields are not split, and long text paragraphs retain complete context.
- Import a preset question-and-answer pair document, retrieve the corresponding question, confirm that the returned result is the original reply of the question-and-answer pair in the knowledge base, and has not been rewritten by AI.
- Upload a document bound with a custom parsing script, confirm that the parsing result includes custom fields processed by the script, to verify that the `customPdfParse` configuration is effective.

The values provided here are common starting points, and should be evaluated against the user’s own samples.
