# Business Process Guidance for Pension, Work-related Injury, and Unemployment Benefit Verification: Forms and Interactions

## What This Category of Data Looks Like
Data for this category originates from social insurance management systems, personal social insurance contribution and benefit records, labor relations and work-related injury identification systems, and electronic social security card platforms. The update frequency is daily. Daily business documents include benefit application forms, payment period certification forms, retirement approval forms, work-related injury identification materials, and unemployment insurance benefit application materials. Fields covered include applicant identity information, payment duration, work-related injury identification grade, unemployment insurance participation duration, and similar items. Corresponding units include years, months, yuan, and similar units. All fields must strictly match data from official business systems.

## What Constraints These Characteristics Impose on the Forms and Interactions Link
Multi-system data sources require forms to support integration with multiple official interfaces to pull real-time data, to avoid using cached data that causes outdated information. The daily update frequency requires form fields to synchronize the latest payment and identification records in real time, and long cache cycles should not be used. Diverse business documents require forms to be configured with modular file upload components to adapt to upload requirements for different materials. Fixed-format fields require forms to have built-in format verification rules to block invalid input, and must strictly match the unit requirements of official fields to avoid benefit calculation deviations caused by unit errors.

## Configuration Settings
The following configurations are formulated based on FastGPT v4.17.0:
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Bind social insurance field formats and required verification rules | Social insurance-related fields have fixed format requirements, which can block invalid input in advance |
| `userSelect` | Associate with social insurance handling system and personal benefit record data sources | Data for this category comes from official business systems, which ensures data accuracy |
| Single interaction timeout | 300 seconds | Business processing requires checking multiple materials, so the timeout must cover the full verification process |
| Context window length | 4000–6000 characters | Multiple application materials and historical calculation records need to be loaded, to avoid information truncation |
| File upload format restrictions | Support PDF, JPG, PNG; single file no larger than 10MB | Matches common social insurance business material formats and storage standards |
| Number of results displayed | Top 3 | Focus on core benefit calculation results, to avoid interface information overload |

## Three Common Misconfigurations
- Calling the application via an interface returns empty parameters. Cause: Required verification rules for social insurance business fields are not bound in the `formInput` configuration, and empty field submissions trigger system verification exceptions.
- No data is displayed when selecting a web link. Cause: The data source interface of the social insurance handling system is not associated via `userSelect`, so benefit-related information awaiting verification cannot be pulled.
- The workflow code execution stage fails verification due to including historical records. Cause: An appropriate context window length is not configured, and the input historical material text exceeds the limit range, causing verification failure.

## How to Verify a Complete Configuration
- Navigate to the application configuration page for FastGPT v4.17.0, and check if the `formInput` configuration binds the format and required verification rules for social insurance fields.
- Test the `userSelect` component to confirm that relevant data from the social insurance handling system and personal social insurance benefit records can be pulled normally.
- Submit a simulated benefit application form to verify that the system can correctly block input with format errors or missing required items.
- View the result display area of the interaction interface to confirm that only the preset number of core benefit calculation results are displayed.
