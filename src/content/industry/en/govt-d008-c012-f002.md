# Business Process Guidance for Elderly Care Service Institution Supervision: Vector Models and Indexes

## What the Data for This Category Looks Like
Daily documents for this category include elderly care institution registration materials, operation subsidy application materials, service quality inspection reports, safety hazard rectification ledgers, elderly admission files, and similar items. Data is primarily sourced from elderly care service information platforms, civil affairs statistics systems, fire inspection records, and institution operation ledgers. Updates occur on a monthly basis. Each individual document includes fields such as institution name, registration number, bed count, inspection date, rectification items, subsidy application details, and other related fields. Some documents contain content that mixes structured numerical values and unstructured text.

## Constraints These Characteristics Impose on Vector Models and Indexes
Monthly updated data has a relatively stable scale but arrives in concentrated batches. This requires index construction processes that support bulk imports. Mixed structured and unstructured document content requires indexes to support associative retrieval for both numerical fields and text semantics. Business fields for elderly care supervision have strong correlations. For example, registration numbers and bed count data must be retrieved together. Indexes must retain field-level association capabilities. Supervision data has high accuracy requirements. Index recall results must cover all associated business items to avoid missed detections that lead to supervision errors.

## How to Set Configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to supervision documents that mix text and structured fields, avoids single chunks spanning cross-business associated items |
| Overlap Length | 100–150 characters | Retains business association information across chunks, such as preceding and following rectification steps in rectification ledgers |
| Similarity Threshold | 0.75–0.85 | Matches the strong semantic association requirements of supervision business, avoids incorrect recall of unrelated institution data |
| Single Search Limit | Top 10 results | Covers the retrieval needs for multiple associated items in supervision business, such as simultaneously matching registration and subsidy information |
| `defaultToken` | 8192 | Adapts to embedding processing for long documents, supports complete semantic extraction of registration materials |
| `maxToken` | 4096 | Limits the length of single-round retrieval context, avoids index loading timeouts |

## Three Common Configuration Mistakes
- A 404 error is returned after configuring the baidu embedding-v1 interface. The root cause is that the interface path and authentication parameters of oneAPI are not correctly matched.
- Index addition fails after deploying the m3e vector model without a GPU environment. The root cause is that the container did not open the model access port and was not configured to run in CPU mode.
- Some fields are missing from retrieval results for monthly bulk imported elderly care institution data. The root cause is that the chunk overlap length is set too short, leading to incomplete extraction of associated information for structured fields.

## How to Confirm Configurations Are Properly Set
- Import a single elderly care institution registration document, check the text integrity after index chunking, and confirm that the chunk length and overlap length settings match the length characteristics of the business documents.
- Initiate a retrieval request that includes the institution registration number and bed count, confirm that the recall results include associated subsidy application and rectification ledger information, to verify the configuration effect of field-level association.
- View the index logs of FastGPT v4.17.0, confirm that no timeout errors occur during monthly bulk data import, to verify the rationality of the `defaultToken` and `maxToken` configurations.
- Adjust the test range of the similarity threshold, compare recall results across different thresholds, and confirm that the settings meet the precise retrieval requirements of supervision business.
