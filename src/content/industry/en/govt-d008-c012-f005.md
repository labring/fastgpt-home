# Business Process Guidance for Elderly Care Service Institution Supervision: Tool Calling and Plugins

## What this category of data includes
Daily documents for this category include elderly care institution filing materials, operation subsidy application files, service quality inspection checklists, safety hazard rectification ledgers, elderly admission records, and other related items. Data is primarily sourced from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institution operation ledgers. Updates occur on a monthly basis. Data fields cover institution qualifications, bed quantities, service records, safety rectification status, and other related items. Common units include institutions, beds, person-times, rectification item counts, and similar units. This data must support structured verification and batch processing requirements for supervision scenarios.

## Constraints imposed on tool calling and plugin workflows
Monthly updated data requires regular synchronization. Tool calling must adapt to batch verification scenarios to avoid timeouts caused by single request overload. Multi-source cross-system data needs unified format validation. Plugins must support connections to interfaces from multiple departments including civil affairs and fire safety, and handle field differences. Most document fields are structured, but cross-system naming inconsistencies exist. Tool calling must configure field mapping rules to ensure passed parameters match fields in supervision ledgers. Audit tasks must retain operation logs. Plugins must support writing results back to the supervision system for subsequent traceability. Errors in supervision scenarios must be quickly located. Tool calling must add exception capture mechanisms to address the consequences of errors in scenarios such as subsidy distribution and safety supervision.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Tool calling trigger mode | Triggered by process node | Matches the sequential logic of business handling, avoids invalid calls consuming resources |
| `toolChoice` | `auto` | Adapts to supervision scenarios where multiple tools are called on demand, automatically selects the appropriate tool to handle tasks such as filing, subsidy applications, and inspections |
| Plugin request timeout | 600 seconds | Adapts to delay scenarios in cross-department data synchronization, prevents task failure due to slow system responses |
| Single tool call return count | Top 20 entries | Matches the processing scale of monthly batch verification, avoids context overflow caused by excessive returned data |
| Plugin parameter validation rules | Configured per document field mapping | Matches the structured characteristics of elderly care supervision data, ensures passed parameters match ledger fields |
| Exception retry count | 3 times | Adapts to unstable scenarios in cross-system calls, reduces task failure caused by temporary network fluctuations |

## Three common misconfigurations
- Tool calls return empty fields when using multiple tools. This occurs because field mapping rules between plugins and supervision documents are not configured, leading to mismatched passed parameters and actual data.
- Tool call timeouts trigger task failure. This occurs because a reasonable timeout period is not set, and cross-department data synchronization takes longer than the configured threshold.
- Tools do not return a response after uploading elderly care institution safety inspection videos. This occurs because parameter transfer rules for file type variables are not configured, preventing video files from being correctly passed to plugin interfaces.

## How to verify correct configuration
- Submit a simulated filing material verification request. Check if the tool automatically calls the appropriate plugin to pull institution filing data from the civil affairs system.
- View tool calling logs in FastGPT v4.17.0. Confirm that timeout and retry count configurations are active, with no direct failure records triggered by exceptions.
- Upload a test rectification ledger file. Confirm that the plugin can correctly receive file parameters and complete format validation.
- Cross-check fields returned by the plugin. Confirm that field mapping rules for supervision documents are correctly configured, with no missing fields.
