# Business Process Guidance for Elderly Care Service Institution Supervision: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Normally, business data for this category comes from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and institution operation ledgers. Daily processed documents include elderly care institution filing materials, operation subsidy application materials, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. The data update cycle is generally monthly. Core processing steps involve verifying institution filing and bed data, inspecting service quality and safety hazards, and reviewing subsidy and rectification materials. Fields involved are mostly supervision-related content such as institution name, number of beds, inspection date, and rectification requirements.

## What constraints these characteristics impose on the "knowledge base retrieval and recall" link
Data from multiple sources must be associated with multiple datasets for simultaneous retrieval, to avoid missing cross-departmental supervision information. Document structures vary widely, so adaptation is required for different chunking needs such as long paragraphs in filing materials and short entries in inspection forms. The monthly update frequency requires regular knowledge base synchronization refreshes to ensure retrieval results align with the latest supervision data. There is a high demand for precise matching of core fields, which requires preventing irrelevant documents from being mixed into retrieval results while covering variant queries of professional supervision terminology.

## How to set the configuration
This configuration is based on FastGPT v4.17.0. The specific parameter settings are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Document matching for supervision business requires high precision, to avoid mixing irrelevant elderly admission files into filing query results |
| `limit` | Top 5 entries | Reduce result filtering costs for review staff, and focus on core matching content |
| `usingReRank` | Enabled | Perform secondary ranking on retrieval results from multiple sources, to distinguish semantic priority between fire safety inspection records and operation subsidy applications |
| `datasetSearchUsingExtensionQuery` | Enabled | Cover variant professional terms in supervision business, such as expanding "bed verification" to "elderly care institution bed inspection" |
| `collectionIds` | Bind three datasets: filing materials, operation subsidies, and safety inspections | Accurately associate document collections for core supervision business |

## Three common mistakes
- Phenomenon: Retrieval results do not return image content within documents. Cause: The knowledge base image extraction function is not enabled, or the retrieval configuration does not include image recall rules.
- Phenomenon: The source document corresponding to the answer text is not marked in the response. Cause: The document source display switch is not configured, or the metadata information of the bound dataset is not correctly associated.
- Phenomenon: Uploaded knowledge base content cannot be retrieved when calling the `/api/v1/chat/completions` interface. Cause: The `collectionIds` parameter is not correctly filled in the request, or the bound dataset does not contain business documents of this category.

## How to confirm the configuration is complete
- Upload a test document of elderly care institution filing materials, initiate a query containing "filing process", and check whether the returned results include the core content of this document.
- After initiating a query, check whether the source document name and corresponding paragraph position are displayed below the answer.
- If the test document contains images, check whether the corresponding image content is returned in the retrieval results.
- Call the `/api/v1/chat/completions` interface, pass in the correct `collectionIds` and supervision-related query text, and confirm that the returned results are not empty and the matching degree meets expectations.
