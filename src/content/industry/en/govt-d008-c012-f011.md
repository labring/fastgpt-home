# Business Process Guidance for Elderly Care Service Institution Supervision: Forms and Interactions

All configurations below are written for FastGPT v4.17.0, and are adapted to the business scenario requirements of elderly care service institution supervision.

## What the data for this category looks like
Daily documents for this category include filing materials, operation subsidy applications, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. Data sources cover elderly care service information platforms, civil affairs statistics systems, fire inspection records, and institution operation ledgers. Common data fields include institution qualification information, bed count, inspection results, and rectification items. The update frequency is monthly. The overall data structure primarily uses structured forms and ledgers, covering collaborative supervision data from multiple departments including civil affairs, fire rescue, and market regulation.

## What constraints these characteristics impose on the forms and interactions link
Multi-source cross-system data sources require forms to support cross-data source field linkage and pulling. This avoids manual entry of duplicate and error-prone cross-department data.
Monthly update frequency requires form data source synchronization cycles to match business rhythms. This ensures the latest monthly supervision data is used for calls.
Diverse daily document types require interactions to support switching between different form structures and field mapping. This meets submission requirements for different business scenarios.
The pain point of time-consuming manual data verification requires forms to have built-in field consistency check rules. This reduces the workload of repeated verification.
The serious consequences of safety-related errors require interactions to add secondary confirmation steps for key operations. This avoids supervision mistakes caused by incorrect submissions.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable input box persistence, retain already filled content | Elderly care supervision forms have many fields and take a long time to fill. This avoids data loss after user operation interruptions |
| Data source synchronization cycle | Set to 30 days | Matches the monthly update frequency of business data, ensures the data source called by the form is the latest monthly data |
| Field check rules | Enable cross-source data consistency checks. Check fields include institution filing number and bed count | Reduces time spent manually verifying filing and operation data, avoids supervision errors |
| `userSelect` | Limit selectable entities to civil affairs elderly care department, elderly care institutions, and regulatory collaboration departments | Matches typical business entity scope, prevents unauthorized entities from submitting forms |
| Key operation secondary confirmation | Enable confirmation pop-ups for subsidy application and rectification material submission links | Avoids incorrect submissions caused by misoperations, reduces supervision error risk |

## Three common mistakes
- When configuring `formInput`, do not enable persistence. This causes filled content to disappear after page refresh or navigation. The cause is failing to match the business scenario where elderly care form filling takes a long time, and the default input box retention function is turned off.
- When configuring `userSelect`, do not bind the corresponding data source. This causes no available institution or regulatory entity data when selecting via web links. The cause is failing to connect to the entity data interface of the elderly care service information platform, and only an empty optional list is configured.
- Code run node inputs containing historical record fields fail validation in the workflow. The cause is failing to perform format cleaning on cross-source imported historical data, leading to field formats that do not match system validation rules.

## How to confirm the configuration is complete
- Access the form editing page, fill in a portion of fields manually, then refresh the page. Verify that already filled content is not lost, confirming the `formInput` persistence configuration takes effect.
- Access the entity selection component, and check if the optional list includes typical business entities such as the civil affairs elderly care department and elderly care institutions. Confirm the `userSelect` entity scope configuration is correct.
- Submit a simulated subsidy application form, and check if the system displays a secondary confirmation pop-up. Verify the key operation secondary confirmation configuration takes effect.
- Manually trigger data source synchronization, and check if the bed count data loaded by the form matches the previous month's statistical data from the elderly care service information platform. Confirm the data source synchronization cycle configuration matches the business rhythm.
