# Business Process Guidance for Internal Control Evaluation, Audit and Rectification: Deployment and Upgrade

## What This Category of Data Looks Like
This category of data comes primarily from enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems, with an annual update frequency. Daily involved documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. The documents contain mixed content of structured fields and unstructured text. Structured fields include issue number, rectification responsible person, rectification time limit, closure status, and other items. Unstructured text includes issue descriptions, rectification measures, and other content.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
The data sources for this category are scattered across multiple internal business and management systems. During the deployment phase, unified access configuration for multi-source data must be adapted. Since the data update frequency is annual, low-frequency batch full synchronization tasks can be configured during deployment, and high-frequency incremental update logic is not required. The documents contain mixed structured and unstructured content, so adaptation rules for structured data extraction and unstructured text parsing must be configured separately during deployment and upgrade. In addition, sensitive business data such as rectification ledgers and closure certificates requires additional configuration of data access permissions and storage encryption rules during deployment.

## Configuration Settings
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 connections` | This category needs to connect to multiple internal systems such as internal control, audit, and finance at the same time. A reasonable connection pool size can avoid resource exhaustion |
| `MONGODB_URI` | Fill in according to the connection string of the enterprise internal audit document storage repository | Unstructured documents such as audit working papers and rectification ledgers of this category are mostly stored in MongoDB-type databases |
| `REDIS_URL` | `600-second cache expiration time` | The data of this category is updated annually, so an overly long cache period is not needed, which can balance query efficiency and resource usage |
| `STORAGE_S3_ENDPOINT` | Fill in according to the endpoint of the enterprise internal object storage service | Rectification closure certificates and self-evaluation report attachments of this category need to be uniformly stored in enterprise internal object storage |
| `FILE_TOKEN_KEY` | Set based on actual testing | Used to generate document access tokens, and must match the enterprise internal file access permission rules |
| `PG_URL` | Fill in according to the connection string of the enterprise structured business data storage repository | Structured data such as issue lists and rectification ledgers of this category are mostly stored in relational databases |

## Three Common Configuration Mistakes
- Symptom: A permission error or 404 status code is returned when testing a third-party model in FastGPT. Cause: The model call permission key is not configured correctly, or the IP of the deployment node is not added to the whitelist of the enterprise internal model service.
- Symptom: Connection timeout occurs when batch synchronizing audit data. Cause: The `DB_MAX_LINK` configuration value is lower than the actual required number of connections, leading to connection pool exhaustion during multi-data-source synchronization.
- Symptom: Attachments cannot be accessed normally when downloading. Cause: The `STORAGE_S3_ENDPOINT` or `FILE_TOKEN_KEY` configuration is incorrect, and does not match the enterprise internal object storage access rules.

## How to Verify Successful Configuration
- Execute a batch data synchronization task, and check whether the data access status of each internal system is normal.
- Upload a rectification closure certificate document to verify that the document storage and access configuration takes effect.
- Initiate a model call test to confirm that the permission configuration and external link connection are working properly.
- Check the system cache status to confirm that the `REDIS_URL` expiration time configuration matches the expected setting.

The values provided are common starting points and should be measured against the reader's own samples.
