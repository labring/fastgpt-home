# Business Process Guidance for Medical Insurance Fund Supervision and Audit: Forms and Interactions

## What data for this category looks like
Data for this category comes from the medical insurance intelligent monitoring system, fund supervision rule base, medical insurance settlement data, drug and consumable traceability codes, and report clues. Daily processed documents include audit notices, inspection work papers, suspicious item lists, interview records, handling decisions, and rectification reports. The data structure balances structured fields and unstructured text, and includes core fields such as inspection scope, suspicious type, and involved subjects. The update frequency is monthly, and the data volume changes dynamically with the monthly audit task volume.

## What constraints these characteristics impose on the forms and interactions link
Since the data sources include structured settlement details exported from multiple systems and unstructured report clues, forms must support mixed-type input. Monthly updated batch data requires interactions to support batch submission to avoid overly low efficiency from single-entry submissions. Missing identification fields for core documents will block subsequent audit processes, so mandatory field validation must be strengthened. At the same time, audit scenarios have high requirements for data accuracy, so interactions must reduce manual input errors and adapt to selection needs for fixed subjects.

## How to configure
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `formInput` | Enable mixed input mode, bind structured fields and unstructured content | This category of data includes structured settlement details and unstructured report clues; mixed input supports multi-type data entry |
| `userSelect` | Preset audit subject option library, including designated medical institutions, medical insurance handling institutions, etc. | Typical audit subjects are fixed; preset options reduce input errors |
| Single submission limit | 50 items per submission | Adapt to the processing load of monthly batch data and avoid system overload |
| Mandatory field validation | Enable verification of suspicious item number and inspection period | Missing core document identification fields will block subsequent audit processes |
| Timeout threshold | 600 seconds, calibrated based on actual testing | Multi-data source retrieval requires a long response time, matching the waiting expectation of the business scenario |

## Three common misconfigurations
- Phenomenon: After uploading audit-related documents, the page keeps refreshing and the specified page cannot be selected. Cause: The multi-page structured format of medical insurance documents is not adapted, and the system cannot correctly parse page metadata.
- Phenomenon: Images uploaded in the `formInput` component cannot be bound to structured fields. Cause: The image binding configuration for mixed input is not enabled, and only plain text input is supported.
- Phenomenon: After submitting a batch of suspicious item lists, the number of returned results does not match expectations. Cause: The single submission limit exceeds the system's carrying capacity, causing some data to be truncated.

## How to verify a successful configuration
- Upload a standard audit notice document, check whether the system can correctly parse and bind fields such as inspection unit and inspection period.
- Enter audit subject keywords, verify that the preset subject options pop up correctly.
- Submit 50 simulated suspicious item lists, check whether the system can normally receive and complete preliminary verification.
- Upload a single image to the `formInput` component, verify that it can be associated with structured suspicious item fields.

The values provided are common starting points and should be measured against the reader's own samples.
