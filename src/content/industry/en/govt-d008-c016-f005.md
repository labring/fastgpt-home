# Business Process Guidance for Medical Insurance Expense Settlement Audit: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from the national medical security information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-provincial medical treatment settlement platform. The update frequency is daily. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Core fields cover diagnosis and treatment item and drug consumables codes, expense amounts, insured person identity identifiers, rejection reasons, and reconciliation information. The data structure varies slightly based on the interface specifications of different handling entities.

## What constraints these characteristics impose on the tool calling and plugins link
Daily updated data sources require tool calling to be configured with scheduled synchronization tasks to ensure the timeliness of the coding library and settlement data. Mixed input of multiple types of structured documents requires tool calling to automatically identify document types and match corresponding processing logic. Time-consuming steps such as matching diagnosis and treatment item codes and reviewing expense consistency with medical records require calling external medical insurance catalog interfaces to complete verification. For batch processing scenarios, the parameter rules of batch calling interfaces must be adapted. Errors are tied to fund safety and handling efficiency, so tool calling must include exception capture and retry mechanisms.

## How to set the configuration

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum single tool call count | First 3 entries | Matches the processing scale of single or bulk settlement audits, avoids interface overload |
| Timeout wait time | 600 seconds | Adapts to the standard response duration of medical insurance interfaces, covers the processing cycle of bulk data |
| Tool calling trigger rule | Trigger based on medical insurance document type | Only start tool calling when target documents such as settlement lists and prescriptions are identified, reducing invalid calls |
| `toolChoice` | Auto | Allow the large model to independently select tools matching medical insurance audits, improving matching accuracy |
| `functionCall` | Enabled | Force tool calling format to comply with the parameter specifications of medical insurance interfaces, avoiding return format errors |
| Maximum context length | 800-1200 characters | Adapts to the standard length of a single medical insurance document, avoiding context overflow |

## Three common configuration errors
- The model returns an empty response, and the log displays "chat：llm—model—response-empty". This occurs when the trigger rule for medical insurance documents is not configured. The large model cannot identify the target business scenario and does not call the corresponding tool.
- Both tool calling results and AI conversation outputs are displayed, with redundant raw tool calling content shown in the interface. This happens when the raw log display switch for tool calling is not disabled, or the option to only return AI-sorted audit results is not configured.
- Interface calls time out during bulk settlement audits. This is caused by a timeout wait time set too short, which does not adapt to the processing cycle of bulk data.

## How to confirm the configuration is correct
- Upload a single medical insurance settlement list, trigger tool calling, and check if the log automatically identifies the document type and starts the corresponding tool.
- Review the tool calling return results to confirm they include core content such as diagnosis and treatment item code matching and expense consistency review.
- Simulate a bulk settlement data call, and verify if the interface response duration meets the set timeout threshold.
- Confirm that only AI-sorted audit results are output after tool calling, with no redundant raw tool calling content.
