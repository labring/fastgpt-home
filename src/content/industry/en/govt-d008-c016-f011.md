# Business Process Guidance for Medical Insurance Expense Settlement Audit: Forms and Interactions

## What the data for this category looks like
Data for this category comes from the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical settlement platform. The update frequency is daily. Documents processed daily include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. The data includes standardized coding fields, expense value fields, business document number fields, and insured person-related information fields. All fields comply with unified medical insurance business specifications. This page is compatible with FastGPT v4.17.0.

## What constraints these characteristics place on the forms and interactions link
Since data sources involve multiple medical insurance-related interfaces, use the `formInput` component in the forms and interactions link to fully align input fields with connected medical insurance interface fields. This prevents business exceptions caused by field mismatches.
Because data updates daily, support refreshing pulled business data at a fixed rhythm in the interactions link. This stops audits from using expired information.
Since processed documents include multiple business document types, let the form display different business field types in separate modules. Add built-in coding matching verification logic to avoid inconsistent expenses and medical record prescriptions.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind core fields of medical insurance settlement lists | Match the standardized document structure of business data |
| `userSelect` | Preset medical insurance catalog coding options | Meet the data source requirements of the connected medical insurance coding library |
| Data refresh frequency | Trigger daily | Match the daily update rhythm of business data |
| Verification rule configuration | Enable coding consistency verification | Avoid business risks of inconsistent expenses and medical record prescriptions |
| Batch import limit | Top 50 entries | Adapt to the daily business scale of single-batch processing |
| Timeout threshold | 600 seconds | Match the time consumption requirements of cross-medical insurance interface calls |
| Input character limit | 800-1200 characters | Adapt to the content length of a single settlement document |

## Three common mistakes
- An "input information duplicate" error pops up after running the workflow. The form configuration binds the same data source field repeatedly, resulting in redundant submitted content.
- Only a small number of optional models appear in the tool call panel. The permission scope for model calls is not configured, or the full model selection entry is not enabled in form interactions.
- A field empty verification failure triggers when batch importing settlement documents. Required fields of connected medical insurance interfaces are not aligned, so the form cannot match business data.

## How to confirm the configuration is complete
- Import a single medical insurance settlement list, and verify that the form automatically fills in the corresponding preset fields.
- Trigger the data refresh operation, and confirm that the form content matches the medical insurance interface data updated on the current day.
- Select a preset medical insurance coding option, and confirm that the drop-down list matches the public specification content of the medical insurance catalog library.
- Simulate batch import of 50 settlement documents, and confirm that the system does not trigger timeout-related errors.
