# Business Process Guidance for Medical Institution Supervision and Public Health Inspection: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category comes from health supervision information systems, medical institution electronic registration systems, complaint reporting platforms, and law enforcement inspection records. The update frequency is monthly. Commonly processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Data fields include institution unified social credit codes, practice license numbers, inspection items, rectification requirements, penalty document numbers, and others. Some documents include on-site captured image files, with no unified fixed unit.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Multi-source data access requires interfaces to be compatible with return formats from different systems, to avoid data parsing errors. The monthly update feature means interface synchronization frequency should not be too high, reducing redundant requests and system load. Diverse document types require interfaces to support mixed transmission of structured data and binary files, adapting to different business scenarios. Transmission of large-volume files such as images and documents requires interfaces to be configured with reasonable timeouts and file size limits. Sensitive law enforcement-related data must also pass permission verification mechanisms, ensuring only authorized entities can access it.

## How to configure the settings

| `Authorization` | Carry a compliant access token in Bearer format | Complies with permission control requirements for health data, ensuring only authorized entities can access sensitive law enforcement data |
| `variables` | Bind institution unified social credit code and inspection cycle parameters | Accurately pull business data such as institution qualifications and supervision inspection records updated monthly |
| `responseData` | Split structured fields and binary file streams | Adapts to the unified return format for multiple types of documents such as supervision inspection forms and scanned copies of practice licenses |
| File upload size limit | 1000 MB | Supports transmission of large-volume files such as high-definition on-site law enforcement images and complete penalty case files |
| Interface timeout period | 600 seconds | Adapts to actual time consumption requirements for multi-system data aggregation and large file transmission |
| Streaming response switch | Enabled | Supports segmented return of long-text law enforcement documents, avoiding single-request timeouts |

## Three common mistakes
- Symptom: Interface returns 413 status code, unable to upload multiple images or PDF files. Cause: File upload size limit that meets document volume requirements is not configured, and requests are intercepted because they exceed the preset threshold.
- Symptom: Pulled supervision data fields are empty or incomplete. Cause: Correct business parameters are not bound via `variables`, causing the interface to return data from non-target cycles or non-target institutions.
- Symptom: Streaming response has no segmented return, and the request times out and is interrupted. Cause: The streaming response switch is not enabled, so long-text law enforcement documents cannot be transmitted in segments, and the request is terminated after exceeding the interface timeout period.

## How to confirm the configuration is complete
- Call the test interface, carry a valid `Authorization` token and business parameters, and check whether the returned structured data and binary files meet the expected format.
- Upload a single large-volume document, confirm that the interface reports no errors and completes the transmission, and adjust the upload limit configuration based on actual document volume.
- Initiate a request for a long-text law enforcement document, check whether streaming data is returned in segments, and confirm that the response is not interrupted prematurely.
- Pull monthly updated institution qualification data, and verify whether the returned fields include content corresponding to the preset business parameters.
