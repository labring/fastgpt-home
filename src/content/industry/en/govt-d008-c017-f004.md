# Business Process Guidance for Medical Institution Supervision and Public Health Inspection: Workflow Orchestration

## What the Data for This Category Looks Like
Source systems for this category’s data include health supervision information systems, medical institution electronic registration systems, complaint reporting platforms, and law enforcement inspection records.
Processed daily documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files.
The system updates data monthly. Core fields include institutional unified social credit codes, practice license scope, compliance status of inspection items, rectification completion status, and additional relevant fields. Each source system uses a unique data structure, so targeted adaptation is required.

## Constraints Imposed on Workflow Orchestration
This category draws data from scattered sources, and each source uses a non-uniform structure. Workflow orchestration tools must include multi-source data format adaptation nodes to align fields across documents exported from different systems.
The monthly data update cycle requires workflows to use monthly scheduled trigger nodes to avoid redundant execution.
Law enforcement document compliance rules mandate embedding log retention links in workflows to record the operating subject and time of each processing step.
Splitting core time-consuming workflow steps requires flexible orchestration of sub-processes such as qualification verification and rectification tracking, to adapt to adjustments for different inspection scenarios.

| `variables` | A variable group associated with core fields such as medical institution practice licenses and inspection records | Matches core data fields for this category to enable stable data flow within workflows |
| Trigger Node Type | Monthly scheduled trigger | Adapts to the monthly data update frequency of this category, aligns with business processing cycle rhythms |
| Multi-source Data Adaptation Node | Field mapping rules calibrated through actual testing | Resolves the inconsistent data structure issue for this category, completes format alignment across documents from different systems |
| Log Retention Node | Retain 180 days of operation logs | Meets compliance traceability requirements for law enforcement documents, preserves necessary operation records |
| `nodeId` | Assign a unique identifier to each core workflow node | Facilitates workflow debugging and error location, meets workflow orchestration management needs |
| Document Upload Node Permissions | Only open to internal accounts of health supervision institutions | Ensures confidentiality of law enforcement data, prevents sensitive information leaks |

## Three Common Configuration Errors
- Phenomenon: Workflow logs cannot be associated with specific law enforcement inspection tasks, and the corresponding processing user or institution cannot be identified. Cause: No association variable between `nodeId` and task number is bound to each execution instance in the workflow, making specific task tracing impossible.
- Phenomenon: Workflow runs return empty fields, and medical institution practice license information cannot be matched. Cause: No data source association rule is configured for `variables`, causing the workflow to fail to read structured data from the corresponding system.
- Phenomenon: Document upload operations cannot be triggered in the workflow, and the upload entry is unavailable in the interface. Cause: The permission range of the document upload node is not correctly configured, and the account permission rules of health supervision institutions are not matched.

## How to Verify Correct Configuration
- Manually trigger the workflow once, check whether returned fields include core data such as medical institution practice license scope and compliance status of inspection items, to confirm that the `variables` association configuration takes effect.
- View the workflow log retention node, confirm that corresponding execution records have been generated, and check whether the log retention duration meets business compliance requirements.
- Test document upload node access with accounts of different permission levels, confirm that only authorized accounts can trigger upload operations, to verify the correctness of permission configuration.
- Adjust the trigger frequency to a single test run, confirm that the workflow triggers according to the preset monthly scheduled rules, to verify the accuracy of scheduling configuration.
