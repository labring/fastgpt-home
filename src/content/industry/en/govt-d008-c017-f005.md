# Business Process Guidance for Medical Institution Supervision and Public Health Inspection: Tool Calling and Plugins

## What the data for this category looks like
The core data for this category comes from the health supervision information system, medical institution electronic registration system, complaint reporting platform, and law enforcement inspection records. Daily business documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. The data update frequency is monthly. Structured and unstructured documents from multiple systems must be synchronized. Data fields cover institutional qualifications, personnel practice qualifications, on-site inspection items, rectification requirements, penalty results, and more. There is no unified fixed unit. Corresponding fields must be matched based on the specific document type.

## What constraints these characteristics impose on the "tool calling and plugins" link
Synchronization of multi-system data sources requires plugins to have cross-system docking capabilities. The monthly update frequency means the caching and synchronization cycle of tool calls must match this rhythm to avoid outdated data. Diverse business document types require plugins to support structured field extraction and unstructured content parsing. There is no unified unit for data fields. Tool call return results must match the field rules of the corresponding document. The most time-consuming qualification verification and on-site inspection links require tool calls to return accurate data quickly. Errors are directly linked to institutional penalties and practice risks. Strict result verification and failure retry mechanisms must be configured.

## How to set the configuration
This document is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports flexible multi-tool calls in supervision business, automatically matches scenarios including qualification verification and inspection item validation |
| Tool call timeout duration | `600 seconds` | Cross-system docking has high synchronization delay, reserves sufficient time to complete cross-data source retrieval |
| Maximum number of results returned per tool call | `top 10 entries` | Matches the standard number of entries in law enforcement inspection records and supervision inspection forms, avoids redundant data interfering with model inference |
| `functionCall` | `enabled` | Enables standard function call format, ensures that returned document fields such as rectification notices and practice licenses meet business requirements |
| Plugin data source binding | Bind health supervision information system, medical institution electronic registration system | Uses official compliant data sources to ensure data authenticity and timeliness |
| Field format verification threshold | `1000 characters` | Matches the standard field length of business documents, filters invalid short text or overly long redundant content |
| Plugin data synchronization cycle | `月度` | Matches the update frequency of data for this category, avoids calling outdated business data |

## Three common configuration errors
- The image URL returned by tool calls on the interface is not rendered as a visible image. The cause is that the plugin's resource access permission is not configured, preventing cross-domain loading of external image addresses.
- The locally deployed MCP service cannot be successfully called by the plugin, returning a connection timeout error. The cause is that the access port and network permissions of the local service are not opened in the FastGPT plugin configuration.
- The reasoning model does not output a thinking process after tool calls are completed. The cause is that when `toolChoice` is set to forced call mode, the model optimizes the output structure and only returns tool call results and final conclusions.

## How to verify a successful configuration
- Submit a test request containing a medical institution name, verify that the tool call successfully returns the practice license information of the corresponding institution.
- View the plugin call log, confirm that the fields of the returned supervision inspection form and rectification notice match the preset business document structure.
- Test the bound data source synchronization, confirm that the data update frequency meets the monthly requirement.
- Adjust `toolChoice` to `auto`, verify that the model can automatically select the appropriate tool to complete the call based on the test request.
