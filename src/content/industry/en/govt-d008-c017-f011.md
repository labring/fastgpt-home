# Business Process Guidance for Medical Institution Supervision and Public Health Inspection: Forms and Interactions

## Data Sources and Structure for This Category
The data sources for this category are the health supervision information system, medical institution electronic registration system, complaint reporting platform, and law enforcement inspection records. The update frequency is monthly. Daily involved documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Fields include institution name, practice license number, license scope, personnel qualifications, rectification items, inspection results, and others. Some fields are enumeration types, some are free text, and there are no unified fixed units.

## Constraints Imposed on Forms and Interactions
The monthly update frequency of this category’s data requires form data sources to sync on a regular basis, to avoid referencing expired institution qualification or rectification information. Multiple types of business documents require forms to support multi-field grouping, to match the structures of different documents such as supervision inspection forms and rectification notices. Verification of core fields such as practice license number and rectification items takes a long time, so form configuration must include a real-time verification mechanism to reduce subsequent manual verification costs. Decentralized data sources require variable references in forms to be limited to datasets from specified systems, to prevent field errors caused by referencing irrelevant data. Errors in law enforcement links have serious consequences, so interaction processes must add confirmation steps to stop accidental submission of critical data.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Enable multi-field grouping, with each group bound to the corresponding business document | This category includes multiple types of business documents, and grouping matches the structures and fields of different documents |
| `userSelect` | Preset options for medical institution categories and supervision items, support manual supplementation | Qualification verification of institutions is required, preset options reduce manual input errors and match the classification of the health supervision information system |
| Single submission limit | 5 records per submission | Law enforcement inspection records usually have a limited volume for single submission, avoiding timeouts caused by loading too much data at once |
| Form verification trigger timing | Verify when leaving a field | Core fields such as practice license number and rectification items require real-time verification, to avoid discovering errors after submission |
| Copied content format | Retain native line breaks and markdown structure | Penalty case files require complete format retention, matching typesetting requirements of business documents |
| LLM temperature parameter | 0.3-0.7 range | Generating supervision opinions requires a balance between accuracy and flexibility, matching the generation requirements of law enforcement documents |

## Common Configuration Mistakes
- When binding the `userSelect` variable to the LLM using the conversation component, no temperature parameter is configured, leading to deviations in the format of generated supervision opinions. The cause is failure to adjust LLM generation parameters based on business scenarios, and failure to clarify the reasonable value range of temperature.
- In Google Chrome, clicking the form copy button pops up a prompt to manually select text, and the generated markdown content has no carriage returns and line breaks. The cause is failure to configure the copied content format parameter, and failure to retain the native line break structure.
- When passing the `any` parameter to the text content extraction module to extract code blocks, the complete response shows the code block as undefined. The cause is failure to bind the `formInput` module to the dataset corresponding to the law enforcement inspection record, leading to empty extracted data sources.

## How to Verify a Complete Configuration
- Open the form configuration page of FastGPT v4.17.0, check whether the `formInput` module binds corresponding fields in groups according to business document types.
- Test the preset options of the `userSelect` component, confirm that core categories such as medical institution categories and supervision items are included.
- Submit a simulated supervision inspection data record, verify whether form verification triggers when leaving core fields.
- Click the copy button, check whether the generated content retains native line breaks and markdown format.
- Check whether the LLM temperature parameter is set within the 0.3-0.7 range.
