# Business Process Guidance for Social Insurance Registration and Premium Verification: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category originates from social insurance management systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily. Daily business documents include social insurance registration forms, payment base declaration forms, personnel adjustment forms, social insurance premium verification forms, and personal benefit records. All documents use structured form formats. Core fields cover personal identity identifiers, labor relationship continuation status, payment base ranges, unified social credit codes of employing units, and similar items. No additional unstructured redundant content is included.

## Constraints on the "multi-turn dialogue and prompt engineering" link
Multi-system data sources require dialogue to support cross-source data verification. This prevents inconsistent identity or payment information.
Daily update frequency requires prompt engineering to prompt users to use real-time processing data. This prevents reference to expired information.
Structured document format requires multi-turn dialogue to guide field filling in form order. This reduces missed or incorrect entries by users.
Rigor of core fields requires dialogue to add identity verification steps. This lowers error probability and avoids underpayment, missed payments, or incorrect benefit records.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Dialogue Context Window (associated with `chatId`) | Previous 8 rounds of dialogue + 1200 characters of history | Social insurance registration requires verification of multi-step personnel and payment information. Associating session history via `chatId` and retaining the last 8 rounds covers core business fields. 1200 characters can carry complete data for a single batch of declarations. |
| `variables` Binding | Bind real-time data interfaces of social insurance management and tax systems | Data sources come from multiple systems. Injecting real-time verification data via `variables` ensures dialogue uses the latest processing information. |
| Question Optimization | Enable splitting guidance by form fields | Daily documents are structured forms. Splitting guides users to fill in fields one by one, improving information completeness. |
| Single Recalled Document Count | Top 3 matched documents | Documents in this category have fixed structures. 3 documents cover common declaration scenarios for social insurance registration and premium verification. |
| Timeout Setting | 60 seconds | Cross-system data queries require reserved response time. 60 seconds covers multi-source data retrieval and verification. |
| Initial Prompt (built based on `messages`) | Fixed script including identity verification and field guidance | Pass initial guidance script via the `messages` parameter, clearly defining the business boundaries of the dialogue, and preventing users from deviating from the social insurance registration and premium verification process. |

## Three Common Mistakes
- No business guidance question returned after dialogue starts: User receives only an empty reply or generic prompt after initiating dialogue. The cause is that initial guidance script based on `messages` is not configured, or the dialogue context window is set too small, causing initial instructions to be truncated.
- Failed to parse uploaded declaration files during API call: An error prompt indicating file parsing failure is returned, or the parsing result is empty. The cause is that parsing adaptation rules for the corresponding form documents are not enabled, or the uploaded file size exceeds the 5 MB limit.
- Inconsistent results between platform testing and API call: Platform test answers are accurate, but API call returns missing or incorrect content. The cause is that the API request does not correctly pass the `variables` parameter, or the associated knowledge base version is not specified.

## How to Confirm Correct Configuration
- Initiate an initial dialogue, check whether guidance questions split by social insurance registration and premium verification fields are returned.
- Call the API with a test `variables` parameter, verify whether the returned result includes real-time bound social insurance management or tax system data.
- Upload a standard social insurance registration form, check whether the parsing result extracts core business fields such as personal identity and payment base.
- Compare returned content between FastGPT v4.17.0 platform testing and API calls, confirm that the two results are consistent.

The values given are common starting points and should be measured against the reader's own samples.
