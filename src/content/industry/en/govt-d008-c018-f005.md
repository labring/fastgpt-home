# Business Process Guidance for Social Insurance Registration and Premium Verification: Tool Calling and Plugins

## Data Profile for This Category
Data for this category originates from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. It updates once daily.
Daily business documents include social insurance registration forms, payment base declaration forms, personnel adjustment forms, social insurance premium verification forms, and personal benefit records.
Fields cover personnel identity identifiers, unified social credit codes of units, payment bases, insurance status, and other related items.
Single record sizes typically range from hundreds to thousands of bytes. Most data structures use structured tables. Some fields rely on cross-system shared identity and operational data.

## Constraints for Tool Calling and Plugins
This category of data is shared across multiple systems and updates daily. Tool calling must prioritize fetching the latest cross-system synchronized data. It must avoid using expired personnel identity or payment information.
Fixed fields in structured business documents require plugin parameters to strictly match preset field names. This prevents call failures caused by field mismatches.
Single record size ranges require tool calling to limit the number of records returned per call. This prevents context overload.
Cross-system dependencies require plugins to configure cross-data source access permissions. This ensures associated data from social insurance handling and tax collection systems can be retrieved simultaneously.
The time-consuming nature of identity verification can be simplified using pre-built identity verification plugins via tool calling. Parameters must fully correspond to identity identifier fields.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | Set to `auto`. Specify as `["identityCheck", "paymentCalc"]` only when calling identity verification or payment calculation plugins | Matches the need for on-demand tool calls in business processes, and avoids unnecessary tool calls |
| Plugin data sources | Bind two data sources: social insurance handling system and tax social insurance premium collection system | Covers core data sources for this category, and ensures complete retrieved data |
| Parameter priority | Prioritize variables passed from the workflow. Use plugin default values when variables are not retrieved | Adapts to scenarios where parameters such as personnel numbers and payment bases are dynamically passed in business processes |
| Number of results per single call | Top 20 entries | Matches single record size ranges, and prevents context overload |
| Timeout setting | 600 seconds | Covers average cross-system data retrieval time, and avoids process interruptions caused by timeouts |
| `functionCall` | Enable strict field matching mode | Ensures call parameters fully correspond to structured fields in business documents, and reduces format errors |

## Three Common Configuration Mistakes
- Phenomenon: A "data source not authorized" error is returned when calling a cross-system plugin. Cause: The required social insurance handling system and tax social insurance premium collection system data sources are not bound. Only a single data source is configured.
- Phenomenon: Empty field results are returned after calling a tool in a workflow. Cause: Strict field matching mode for `functionCall` is not enabled. Passed parameters do not correspond to business document field names.
- Phenomenon: Plugins use preset default values directly instead of personnel number variables passed from the workflow. Cause: Parameter priority logic is not configured correctly. Workflow variables are not set to take priority over plugin default values.

## How to Verify Correct Configuration
- Manually trigger tool calling. Check if returned results include core fields from social insurance registration forms and payment base declaration forms.
- Pass a non-existent parameter value. Verify that the plugin correctly uses preset default values.
- Check the plugin configuration's data source list. Confirm that the social insurance handling system and tax social insurance premium collection system are included.
- Review workflow logs. Confirm that tool call parameters fully match variables passed from the workflow.
