# Business Process Guidance for "Double Random, One Public" Regulatory Inspections: Workflow Orchestration

## What the data for this category looks like
The typical business data for this category comes from the "Double Random, One Public" regulatory platform, enterprise credit information disclosure system, and law enforcement officer directory. The update frequency is monthly. Daily documents include inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result disclosures. Core fields include the unified social credit code of inspection targets, law enforcement officer ID numbers, inspection item entries, rectification completion status, and others. The format aligns with the standard interfaces of the corresponding regulatory platforms, with no additional custom fields.

## What constraints do these characteristics impose on the workflow orchestration link
Monthly updated data sources require workflows to be configured with fixed synchronization cycles, avoiding overly short pull intervals that waste system resources. Integrating data from multiple sources requires checking for duplicates and compliance to prevent non-compliant extraction of regulatory targets. Dynamic matching of inspection targets and law enforcement officers requires pulling the latest directory data in real time, otherwise task allocation errors will occur. The inspection result disclosure link must be bound to official disclosure channel interfaces to ensure automatic data synchronization is triggered after the process ends, avoiding missed disclosures.

| Search Result Limit | Take the top 20 entries, calibrated based on actual testing | Filter redundant inspection target data to improve workflow operation efficiency |

## Three common configuration mistakes
- Variable reference causes configuration entry to disappear. Phenomenon: After using `variables` to bind business data in a workflow, the model parameter settings button cannot be displayed. Cause: The model parameter configuration was not completed before variable binding, or variable references overwrite the parameter configuration entry.
- Running data is empty after interface call. Phenomenon: After calling the workflow to generate inspection results, no corresponding execution records appear in the conversation log. Cause: The workflow log storage switch is not enabled, or the data source node is not correctly mounted to the main workflow.
- Sub-workflow does not execute completely. Phenomenon: After the main workflow calls the sub-workflow for generating rectification notices, the process terminates early with no error reported. Cause: The sub-workflow is not configured with a result return node, and the main workflow ends without waiting for the sub-workflow to complete execution.

## How to confirm the configuration is correct
- Trigger a simulated inspection process, and verify whether the workflow log includes variable reference data for the inspection target list and law enforcement officer information.
- View the timeout settings of workflow nodes, and confirm that the single execution duration matches the reasonable execution cycle of the business process.
- After calling the sub-workflow, check whether the main workflow receives the rectification notice data generated by the sub-workflow.
- Verify the update frequency of the data source node, and confirm that it matches the monthly update rhythm of business data.
