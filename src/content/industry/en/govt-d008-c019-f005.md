# Business Process Guidance for "Double Random, One Public" Regulatory Inspections: Tool Calling and Plugins

## What the data for this category looks like
Typically, core data for this category comes from the "Double Random, One Public" regulatory platform, enterprise credit information disclosure system, industry regulatory systems, and law enforcement officer directory. The update frequency is once per month. Daily documents include random inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and random inspection result announcements. Most of these are structured tables or standardized text. Fields include unified social credit codes for regulatory targets, law enforcement officer numbers, inspection item codes, rectification time limits, and more. Unlike penalty case file documents, most inspection results do not automatically enter penalty procedures. They only need to be publicly announced, with no additional custom non-standard fields.

## What constraints these characteristics impose on the tool calling and plugins link
The monthly updated data source requires tools to support regular synchronization of core data such as inspection target libraries and inspection item lists, to avoid using outdated information. The presence of multiple structured documents requires tool calls to adapt to table parsing for different formats, to ensure accurate field extraction. The need for precise matching in the law enforcement officer directory requires that accurate law enforcement officer number parameters be passed during tool calls. Otherwise, incorrect task assignment will occur. The compliance requirement for random inspection result announcements requires that results generated by tool calls have no omissions, to avoid missed public announcements. At the same time, the characteristic that most inspections do not require penalty procedures means that tool calls do not need to be linked to penalty-related business modules. They should focus on random inspection and public announcement processes.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapt to the need for dynamically calling regulatory business-specific tools, no need to manually specify the called tool |
| `functionCall` | Enabled, limit calls to two types of tools: random inspection plan generation and inspection target matching | Focus on core business processes, avoid calling irrelevant tools that interfere with business guidance |
| Tool call timeout period | 600 seconds | Adapt to scenarios where cross-system regulatory data retrieval takes time, avoid process interruptions due to timeout |
| Maximum number of results returned per call | First 5 entries | Avoid returning too much regulatory data that causes context overflow, align with the concise needs of business guidance |
| Custom tool variable optional setting | Enabled, allow passing null values | Match changes to the monthly updated inspection item library, support dynamic adjustment of passed parameters |
| History record filtering | Enabled, exclude tool call logs | Avoid historical memory interfering with the contextual accuracy of business guidance |

## Three common configuration errors
- When calling cross-system regulatory tools, connection wait timeout is returned with status code 504. The cause is that the tool call timeout period is not set to a duration suitable for cross-system data retrieval, and the default timeout is too short.
- Custom tool variables are not set as optional. This causes tool call failure when passing a null inspection target list ID, with an error returned indicating an empty field. The cause is that the variable optional configuration is not enabled.
- History records carry logs from specified reply plugins. This causes confusion in business guidance context, and random inspection plans cannot be generated correctly. The cause is that the history record filtering configuration is not enabled, and tool call logs are not excluded.

## How to confirm the configuration is correct
- Trigger the random inspection plan generation process, check if the matching inspection target library tool is automatically called and a correctly formatted inspection target list is returned.
- Manually pass a null inspection item ID, verify that the tool can correctly handle null values for optional parameters without throwing errors.
- View tool call logs, confirm that the history records do not carry redundant content from plugin calls, and only retain conversations related to business guidance.
- Wait one month, then trigger the data synchronization operation, verify that the tool can automatically pull updated regulatory target and inspection item data.
