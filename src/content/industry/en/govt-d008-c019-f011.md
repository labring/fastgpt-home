# Business Process Guidance for "Double Random, One Public" Regulatory Inspections: Forms and Interactions

## What the data for this category looks like
The core data for this specific category comes from the Double Random, One Public regulatory platform, enterprise credit information disclosure system, law enforcement officer directory, and industry regulatory system.
Daily documents include inspection plans, inspected entity lists, inspection item lists, on-site inspection records, rectification notices, and inspection result public notices.
Data is updated on a monthly basis.
Common fields include the unified social credit code of inspected entities, law enforcement officer qualification number, inspection item category, rectification completion status, and others.
Fields must align with corresponding business documents. There are no fixed uniform unit identifiers.

## Constraints imposed by these characteristics on forms and interactions
Monthly updated data requires forms to support regular synchronization with external data sources. Static fixed options must not be used.
Complex field structures corresponding to multiple document types require forms to support group configuration and linkage verification. This reduces filling errors.
Field differences across multiple data sources require forms to have flexible field mapping capabilities. This adapts to entry requirements for different business documents.
Compliance requirements for inspection result public notices require forms to configure mandatory verification and operation logging mechanisms. This prevents missed entries or missed public notices.

## How to set up configurations
This document is written for FastGPT v4.17.0. The following are form interaction configuration recommendations for this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable multi-field linkage verification, bind business variable prefix | The inspection item list includes multi-dimensional fields. Linkage verification is required for mandatory items and variable mapping |
| `userSelect` | Bind department and qualification screening rules from the law enforcement officer directory | Law enforcement officers must be screened by their affiliated regulatory department and law enforcement qualification. This prevents cross-departmental calls |
| Data source synchronization frequency | Full synchronization once per month | Industry data is updated monthly. High-frequency synchronization is not needed to reduce system load |
| Form field grouping | Group by inspection plan, inspected entity, law enforcement configuration, and result entry | Daily documents are categorized into inspection plans, inspected entity lists, and other types. Grouping simplifies filling |
| File upload permission | Enable single file upload up to 100 MB, support PDF and JPG formats | On-site inspection records and rectification notices often include attachments. This adapts to common document formats |
| Result public notice verification | Inspection results and rectification status are mandatory fields | Errors may include missed public notices of inspection results. Mandatory verification prevents omissions |

## Three common mistakes
- Phenomenon: The business variable bound to the `formInput` component is not properly passed to the form. Fields are empty after submission. Cause: The variable binding switch is not enabled in the configuration, and the associated business data field is not specified.
- Phenomenon: The form input box cannot upload attachment files for inspection records. No file information is present after submission. Cause: The form's file upload permission is not enabled, and a valid path for file storage is not configured.
- Phenomenon: When filtering the knowledge base by inspected entity type, only the default knowledge base can be called. Business data from corresponding categories cannot be matched. Cause: Judger configuration for knowledge base call logic corresponding to different inspected entities is not completed. Knowledge base groups are not properly associated.

## How to confirm the configuration is complete
- Manually trigger the data source synchronization task. Check if the form's dropdown options include the latest inspection item list content.
- Submit a test form. Verify that variables bound to the `formInput` component are correctly passed to subsequent knowledge base search steps.
- Attempt to upload a compliance-format inspection record attachment. Confirm that the file can be stored normally and associated with the form record.
- Filter by different law enforcement officer categories. Verify that the screening results of the `userSelect` component fall within the scope of their affiliated regulatory departments.
