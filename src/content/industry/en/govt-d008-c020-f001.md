# Business Process Guidance for Territorial Spatial Planning Compilation and Implementation Evaluation: HTTP Interfaces and External Systems

## What data for this category looks like
The data for this category mainly comes from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics data, and remote sensing images. Daily generated documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data is updated annually. Document structures include spatial coordinate fields, planning constraint indicators, population and economic statistics items, and regional layout descriptions. Most field units use standard spatial and statistical units such as hectares, ten thousand people, and square meters.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
The annual update requirement limits interface call frequency to a reasonable low level. A single request must carry multi-source spatial and text data, so configure the interface timeout threshold to adapt to large-volume data transmission. Format differences across multi-source data sources require the interface to support request parameters of varying structures. Complete identity verification via the `Authorization` parameter to ensure the security of natural resource data. Planning documents include spatial coordinate and statistical indicator fields, so the interface must support request bodies carrying corresponding fields to avoid process delays caused by data parsing errors.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface timeout period | 600–900 seconds | A single request needs to transmit multi-source spatial and text data, adapting to the transmission time of large-volume files |
| `Authorization` | Configure a Bearer format token as required by the platform | Ensure access permission verification for sensitive natural resource data |
| `variables` | Pass planning document type, data source identifier, with single parameter length not exceeding 2000 characters | Distinguish processing logic for different categories of planning data to match business scenarios |
| File upload format | Support all parsable formats by default, with a single file maximum size of 1000 MB | Adapt to upload needs for multi-source planning documents, prevent integration issues caused by format restrictions or exceeded volume limits |
| `responseData` | Extract core fields of planning indicators and spatial coordinates | Filter invalid data to improve interface response and processing efficiency |
| Token key configuration | Fill in the complete key content | Match interface verification rules to avoid token verification failures |

## Three Common Configuration Mistakes
1. Calling a graphic and text request sample interface returns an empty result. The cause is that the field structure of the request body is not configured according to the planning business scenario, causing the interface to fail to recognize valid business data.
2. An error is reported when calling after adding a third-party token, prompting an empty key. The cause is that the key content is not fully filled, or the key format does not meet the interface verification rules.
3. Only fixed formats are supported during file upload, or over-limit files are intercepted. The cause is that default support for all parsable formats is not configured, or a reasonable single file volume limit is not set.

## How to confirm the configuration is correct
1. In FastGPT v4.17.0, initiate an interface request and check the `responseData` return field to confirm that it contains data related to planning indicators and spatial coordinates.
2. Upload a planning document in any format, confirm that the interface can normally receive and complete preliminary parsing.
3. Fill in the complete `Authorization` token and initiate a request, confirm that the return status code is 200.
4. Configure the `variables` parameter to pass the planning type, confirm that the interface returns processing results for the corresponding category.
