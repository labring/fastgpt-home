# Business Process Guidance for Territorial Spatial Planning Compilation and Implementation Evaluation: Workflow Orchestration

## What the Data for This Category Looks Like
Data sources include the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics datasets, and multi-temporal remote sensing images. The update frequency is annual.
Documents produced and used daily include territorial spatial overall planning texts, detailed planning results, special planning plans, planning implementation evaluation reports, and public participation opinion summary forms.
Data fields include spatial coordinate boundaries, constrained indicator values, population and economic statistics fields, and image interpretation results. Most units are spatial and statistical related units such as hectares, ten thousand people, and meters.

## What Constraints Do These Characteristics Impose on the "Workflow Orchestration" Link
The annual update feature requires configuring regularly triggered data source synchronization nodes to avoid using outdated spatial and statistical data.
Multi-source heterogeneous data sources require setting up multi-node file import, format conversion, and verification links to adapt to inputs in different formats such as remote sensing images, statistical tables, and text reports.
Diverse document types require configuring dedicated parsing rules for different documents, distinguishing structured indicator extraction from overall planning texts and unstructured summary of public opinions.
Manual approval branches must be set up for key nodes to avoid subsequent approval delays caused by constrained indicator deviations.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Data source refresh cycle | 360 days | Matches the regular annual update rhythm of territorial spatial planning data, ensuring the workflow uses the latest business data |
| Multi-source file import concurrency | 4 parallel nodes | Adapts to resource requirements for parallel import of multi-format files such as remote sensing images, statistical tables, and planning texts |
| `variables` configuration | Includes three types of fields: spatial boundaries, constrained indicators, public opinions | Corresponds to the core data dimensions of the category, enabling accurate binding and transfer of process variables |
| `nodeId` binding rules | Bind dedicated node IDs by document type | Differentiates processing flows for different planning documents, avoiding node logic confusion |
| Workflow timeout setting | 1200 seconds | Adapts to time requirements for multi-source data aggregation and format conversion, avoiding unexpected workflow interruptions |
| Manual approval trigger threshold | Triggered when one or more constrained indicator deviations occur | Addresses core risk points in planning compilation, enabling early intervention and coordination to avoid subsequent delays |

## Three Common Misconfigurations
- Phenomenon: Drag-and-drop lag and operational delay appear in the front-end interface when selecting spatial data fields in the workflow `variables` configuration. Cause: The number of `variables` fields is not limited, and loading too many spatial data fields causes excessive front-end rendering pressure.
- Phenomenon: Uploaded planning documents and remote sensing images cannot be located in the workflow. Cause: A dedicated storage directory for territorial spatial planning workflows is not configured, and files are stored in the default general directory, making retrieval difficult.
- Phenomenon: After importing a workflow case, the corresponding JSON configuration source code cannot be obtained. Cause: The source code export option is not enabled in the workflow configuration, or the dedicated document parsing template for the corresponding category is not bound.

## How to Confirm the Configuration Is Successful
- Manually trigger the data source refresh node, check whether the latest territorial spatial basic information platform data is successfully pulled, and confirm that the refresh cycle configuration takes effect.
- Upload multi-format test files (remote sensing images, statistical tables, planning texts), confirm that multi-source file import nodes can process in parallel without format errors.
- Simulate test data with one constrained indicator deviation, confirm that the manual approval node is automatically triggered and the flow jumps to the approval link.
- View the workflow storage directory, confirm that uploaded business files are automatically categorized into the dedicated territorial spatial planning workflow directory.
