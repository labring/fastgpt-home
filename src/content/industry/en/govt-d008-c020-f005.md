# Business Process Guidance for Territorial Spatial Planning Compilation and Implementation Evaluation: Tool Calling and Plugins

## What the Data for This Category Looks Like
The data for this category primarily originates from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistical results, and remote sensing image data. Its update frequency is annual. Commonly processed documents include territorial spatial overall planning, detailed planning, special planning texts, planning implementation evaluation reports, and public opinion summary forms. Data fields include spatial coordinate ranges, binding indicators, population and economic statistical values, remote sensing image interpretation results, and others. Some fields require adaptation based on spatial scale, and there are no unified fixed units.

## Constraints Imposed on the Tool Calling and Plugins Workflow
Annual updated data sources require tool calling to be configured with scheduled synchronization tasks. This prevents expired data from being used, which could reduce planning accuracy.
Multi-source heterogeneous spatial data formats, including vector, raster, and statistical tables, require plugins to support parsing and format conversion for multiple formats. This adapts to data import from different sources.
Unstructured public opinion and planning report texts require calling multimodal tools to extract content and perform structured conversion. This meets the requirements of subsequent coordinated analysis.
Cross-departmental spatial layout coordination work requires passing precise spatial coordinate parameters via tool calling. This ensures consistency of data across departments.
In addition, data processing errors may cause delays in planning approval. The tool calling link must therefore be configured with error retry and log retention mechanisms.

## Configuration Specifications
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting
| --- | --- | --- |
| Tool Calling Mode | Set `toolChoice` to `auto`, enable mandatory validation for `functionCall` | Adapt to the needs of automatic tool selection and structured output for multi-source planning data
| Scheduled Trigger Cycle | 365 days | Match the fixed annual update rhythm of data sources
| Supported Data Formats | shp, tif, csv | Cover common spatial and statistical data types used in planning compilation
| Error Retry Count | 2–3 times | Address network fluctuations or temporary exceptions of data interfaces
| Timeout Threshold | 600 seconds | Adapt to loading time for large-volume remote sensing images and spatial data
| Single Call Data Limit | 1000 MB | Prevent call failures caused by excessive data volume

## Three Common Configuration Errors
- Symptom: Calling the remote sensing image parsing interface returns Failed to fetch, or prompts that the image file cannot be downloaded. Cause: The timeout threshold adapted for spatial data is not configured, or access permissions for the corresponding image data source are not enabled.
- Symptom: Workflow tool calls do not trigger, or pulled planning data is the previous year's old version. Cause: The scheduled trigger cycle is configured incorrectly, and does not match the fixed annual update rhythm of data sources.
- Symptom: Calling a multimodal tool to parse a planning report results in missing binding indicator fields in the output. Cause: Mandatory parameter validation for `functionCall` is not enabled, so structured data returned by the tool does not meet the field requirements of planning documents.

## How to Verify Successful Configuration
- Manually trigger a tool call to check if the latest territorial spatial basic information platform data can be pulled.
- Simulate a network exception scenario to view tool call logs, and confirm that the error retry mechanism triggers normally and generates retry records.
- Verify the automatic selection logic of `toolChoice`, and confirm that the corresponding parsing plugin is matched when calling multi-source data.
- Check plugin permission configurations to confirm that only access to specified territorial spatial data interfaces is allowed, with no unauthorized access permissions.

The values provided are common starting points and should be measured against the reader's own samples.
