# Business Process Guidance for Centralized Treasury Payment and Reimbursement Review: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Consists Of
Data for this category originates from centralized treasury payment systems, unified budget management systems, electronic invoice platforms, and contract management systems, and is updated daily. Commonly used documents include payment applications, fund use plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers. Each document includes fields such as budget indicators, economic classifications, ticket information, contract terms, acceptance results, and approval workflows. A single business transaction is linked to multiple types of business documents, requiring field consistency across multiple systems to be matched.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering by These Characteristics
Multi-system data sources require dialogue to associate fields from platforms including centralized treasury payment and unified budget management, to ensure cross-system matching of indicators, ticket information and other data. The daily update frequency requires dialogue to pull the latest daily budget indicator data in real time, avoiding expired information. Multiple types of business documents require prompts to clearly distinguish verification logic for different documents such as payment applications and reimbursement approvals, guiding users to submit corresponding materials per process link. The characteristic that a single fund transaction is associated with multiple documents requires multi-turn dialogue to gradually collect complete contract, acceptance, and approval chain information, preventing missing items. Compliance verification logic must also be embedded to mitigate risks such as payment returns and incorrect fund disbursement.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window size | 8000–12000 token | Adapt to the field length of various business documents, avoid truncating key budget indicator and contract term information |
| Variable binding | Bind budget indicator ID and invoice number in `variables` | Associate real-time data across multiple systems, ensure the document information referenced in dialogue is accurate, and comply with FastGPT v4.17.0 variable call specifications |
| Dialogue history call | Enable full `messages` recording | Fully retain return and correction records during the review process, facilitating business process traceability |
| Plugin call logs | Enable log storage, retain for 7 days | Match the daily update cycle of business documents, facilitate verification of payment and reimbursement execution records |
| Maximum dialogue turns | First 10 turns | Cover the complete process from fund use plan to payment voucher, avoid invalid long dialogues |
| Dialogue trigger rule | Match by document type entered by the user | Correspond to verification rules for different business documents, guide users to submit materials by process link |

## Three Common Configuration Errors
- When calling a plugin associated with an electronic invoice platform, the dialogue log fails to record invoice verification results. The plugin call log binding configuration is not enabled, causing the `chatId` to not be associated with the plugin execution context.
- The form input node dialog box in nested workflows always displays. The dialog box hiding rule for external calls is not set in the nested configuration, leading to inconsistency with trigger logic within a single workflow.
- Attempting to render web pages or generate image content in dialogue results in no response. Node parameters that allow rich media rendering are not configured, and call permissions for the corresponding model are not bound.

## How to Verify Successful Configuration
- Initiate a simulated payment application dialogue, check whether the dialogue history module fully records each round of interaction and document information.
- Call the plugin associated with the electronic invoice platform, check whether the log module generates corresponding verification records.
- Configure and trigger a nested workflow, confirm that the form dialog box only displays when triggered within a single workflow, and hides during nested calls.
- Submit a dialogue containing complete contract terms, check that no content truncation prompt appears, confirming that the context window configuration takes effect.
