# Business Process Guidance for Land Use Rights, Mining Rights, and State-owned Property Rights Transactions: Vector Models and Indexes

## What Data for This Category Looks Like
Daily documents for this category include transfer announcements, transaction notices, bid application forms, margin vouchers, transaction confirmation letters, listing result announcements, and property rights transfer specifications. Data sources include the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. Updates occur daily. Most documents contain subject ownership information, bidding rules, amount and area parameters, and application process steps. Fields include land area, margin amount, transaction subject number, and others. Structural differences between documents are primarily determined by transaction type: land, mining, or property rights.

## Constraints Imposed on Vector Models and Indexes by These Characteristics
The volume of daily updated documents fluctuates with transaction frequency. Incremental indexing must be supported to avoid excessive time spent on full reindexing. Documents include numerous precise fields such as ownership details, amounts, and areas. Vector models must prioritize aligning semantic associations for these high-value information points. Chunk length must be adjusted to fit long paragraphs of transaction rule descriptions. Data exported from multiple sources has inconsistent formats. Parsing support for excel, pdf, and multi-dimensional document formats is required. The index’s recall scope must cover exclusive document fields for different transaction types. This ensures business process guidance accurately matches core links such as ownership verification and bidding processes.

## Three Common Misconfigurations
- Index creation fails, and the interface displays "index task timed out". Causes: Incremental indexing logic is not configured for daily incremental updates. Full indexing processing a large number of historical documents exceeds the host machine’s resource limit. Vector computation takes too long without a GPU environment.
- Embedding model call errors occur, and document vectors cannot be generated. Causes: A dedicated embedding model is not configured separately. Dependent third-party API call frequency exceeds the limit, or the key configuration is incorrect. The model-specific call channel is not enabled.
- No valid index entries appear after importing excel or multi-dimensional documents. Causes: The parsing switch for the corresponding format is not enabled. Structured fields in the document are not correctly extracted as associated information for vector indexing, resulting in no valid semantic content after chunking.

## How to Verify Correct Configuration
- Upload a standard document from this category, such as a transfer announcement. Check if chunked content covers core ownership and process information, with no obvious truncation.
- Manually trigger an incremental indexing task. Check for vector generation records for the corresponding document in task logs, with no timeout errors.
- Enter a query related to business processes, such as "What materials are required for a bid application". Confirm that recalled document fragments match query semantics, with no irrelevant content.
- Check update frequency settings on the index configuration page. Confirm that daily incremental synchronization is enabled, matching the update rhythm of business data.
