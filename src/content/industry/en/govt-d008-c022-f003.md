# Guide to Business Processing Workflows for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Multi-Turn Dialogues and Prompt Words

## What this category's data looks like
Business data for this category typically comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. The update frequency is daily. Daily business documents include transfer announcements, trading guidelines, bid application materials, margin vouchers, transaction confirmation documents, listing result announcements, property right transfer descriptions, and similar items. Document fields usually include transaction subject ownership information, valuation standards, margin amounts, process node descriptions, and more. The structure and field focus vary across different documents. Some business tasks require cross-verification using multiple materials.

## What constraints do these characteristics impose on the multi-turn dialogues and prompt words link
The multi-source and scattered nature of business data requires multi-turn dialogues to maintain unified context association. This avoids cross-session information confusion. The daily update frequency requires the dialogue link to synchronize the latest announcements and process requirements in real time. This ensures the timeliness of guidance content. The diversity of document structures and fields requires prompt words to adapt to different types of business documents. This allows accurate extraction of core fields. The serious consequences of errors in transaction links require multi-turn dialogues to filter redundant information. This focuses efforts on core transaction nodes and avoids misleading users. At the same time, the continuity of business processing requires dialogues to retain historical context. This supports users in advancing process inquiries step by step.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to a unique business session ID | Ensure dialogue context links to the current transaction process, avoid session interference |
| `messages` | Retain only the last 3 valid dialogues | Adapt to the long length of business documents, avoid context overflow that affects response speed |
| `variables` | Bind ownership type and transaction subject type variables | Accurately match different process rules for land, mining rights, and state-owned property |
| Dialogue context retention duration | 24 hours | Match the daily update frequency of business data, avoid loading expired transaction information |
| Number of results returned per single dialogue | Top 3 | Focus on core transaction nodes, avoid information overload |
| Prompt template update frequency | Sync daily | Match latest transfer announcements, trading guidelines, and other business documents in real time |

## Three common misconfigurations
- Phenomenon: The AI response only displays in the sidebar pop-up window, and does not appear directly in the main dialogue interface. Cause: `chatId` is not bound to the current business session, so the dialogue context is not linked to the main dialogue window.
- Phenomenon: A new dialogue session is created each time business consultation is initiated, and historical process inquiries cannot be continued. Cause: The session `chatId` is not fixed. The system generates a new ID by default each time, which interrupts process continuity.
- Phenomenon: The AI output automatically includes Markdown syntax markers, such as headings and list formats. Cause: The prompt words do not explicitly specify disabling non-plain text output, or output format constraints are not configured in `variables`.

## How to confirm the configuration is complete
- Launch a simulated transaction consultation, ask multiple process nodes consecutively, and check whether the dialogue retains historical context and no new sessions are created.
- Enter business-related questions, and check whether the response is displayed directly in the main dialogue area without triggering a sidebar pop-up.
- After configuring output format constraints, verify that the response does not contain Markdown syntax markers and only contains plain text content.
- After binding business variables, check that the dialogue automatically identifies and associates fields such as ownership type and subject type.
