# Business Process Guidance for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Tool Calling and Plugins

## What This Category of Data Looks Like
The business data for this category typically comes from the national public resource trading platform, natural resource trading systems, property right exchange systems and state-owned asset supervision systems, and is updated daily. Daily documents include transfer announcements, trading notices, bid application documents, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications. Data fields cover transaction subject ownership information, subject type, margin amount, bidding rules, transaction confirmation clauses and more. The field structures vary across different document types.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Workflow
Multiple data sources and daily updates mean tool calling must support integration with multiple heterogeneous systems and scheduled synchronization of the latest data. Diverse document types and varying field structures mean tools must adapt to chunking and field extraction rules for different documents. Core operations such as ownership verification and bidding calculation are involved in the transaction process, so tool calling must accurately match business scenarios. Severe consequences of errors require adding pre-verification steps to tool calling to avoid invalid transactions or asset disputes caused by incorrect data.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically select the tool matching the current transaction processing link, such as ownership verification or bidding calculation |
| `functionCall` | `enabled` | Enable the tool calling function to extract key fields such as ownership and margin from transaction documents |
| Query Optimization | Enabled, for transaction-related queries | Transaction queries often involve professional terminology; optimization improves the accuracy of understanding ownership and bidding rules |
| Maximum Context Window | `8000 token` | Carry long text content such as multiple transaction announcements and application materials to avoid truncation of key information |
| Single Search Limit | `Top 6 entries` | Among the daily updated transaction data, the top 6 latest results can cover the conventional needs of current processing |
| Tool Calling Timeout | `300 seconds` | Reserve sufficient interface response time when querying ownership information by connecting to multiple systems |

## Three Common Mistakes
- Phenomenon: Tool calling returns `messages is empty`. Cause: The corresponding transaction data source is not bound in the tool calling configuration, causing the tool to fail to obtain basic data related to ownership or bidding.
- Phenomenon: Fields extracted from the transaction confirmation letter are missing. Cause: Chunking rules for property right transfer specifications are not configured; after long documents are truncated, key ownership restriction clauses are not fully extracted.
- Phenomenon: Tool calling returns a timeout error. Cause: The tool calling timeout period is not adjusted, and the time spent querying subject information by connecting to the state-owned asset supervision system exceeds the default threshold.
