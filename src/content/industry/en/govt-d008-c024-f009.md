# Business Process Guidance for Student Aid and Subsidy Review: Model Access and Configuration

## What this category of data looks like
This category of data mainly comes from the National Student Aid Management Information System, school student status systems, civil affairs low-income and special hardship data, and fiscal payment systems, and is updated centrally each semester. Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, distribution lists, and publicity materials. Core fields include student recipient identity information, family economic status, student status, aid amount and disbursement account information. All fields come from official standard forms, with no custom non-standard fields.

## What constraints do these characteristics impose on the model access and configuration link
This category of data is updated centrally each semester. The knowledge base synchronization cycle configured in the model access link must match the semester schedule to avoid review deviations caused by expired data. Data from multiple system sources requires configuration of multi-data source association rules to ensure consistency verification of cross-system information such as student status, low-income status, and fiscal payment. Documents include standardized forms and publicity materials, so field extraction logic for different document structures must be adapted. Since errors directly relate to student rights and audit compliance, authorization verification and result traceability configuration must be strengthened during the access link.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `AIPROXY_API_TOKEN` | Fill in the exclusive API token generated by the FastGPT platform | Used for identity verification, ensuring access permissions are legitimate and aligned with the compliance review requirements of this category |
| `AIPROXY_API_ENDPOINT` | Fill in the privately deployed proxy service address | Used to specify the forwarding path for model requests, adapting to the network environment of multi-system data access |
| `maxContext` | `8000–12000 token` | Must accommodate cross-data source information from multiple systems, ensuring complete associated data such as student status and family status can be called during review |
| `quoteMaxToken` | `1500–2000 token` | Used to limit the length of referenced content, preventing long documents such as publicity materials and distribution lists from exceeding the context threshold, while ensuring referenced information is complete |
| `temperature` | `0.2–0.4` | This category requires strict consistency of review results. A lower temperature value reduces the randomness of model output, improving the stability of review judgments |
| `maxTokens` | `2000–3000 token` | Controls the output length of a single round of responses, ensuring content such as review opinions and process descriptions is clear and complete, meeting the format requirements of business documents |

## Three common configuration mistakes
- Symptom: An unauthorized access error still appears after configuring `AIPROXY_API_TOKEN`. Cause: The generated API token is not bound to the authorization scope of the current application, or the token has expired and not been renewed.
- Symptom: After increasing the `quoteMaxToken` parameter, the model output does not reference any retrieved document content. Cause: The total context length exceeds the threshold set by `maxContext`, and the retrieved referenced content is automatically truncated, so the model cannot obtain valid reference basis.
- Symptom: Reference links for long publicity materials are not displayed normally in the output. Cause: The value of `quoteMaxToken` has not been adjusted for this category of long documents, resulting in referenced content being truncated or formatting lost.

## How to confirm configuration is complete
- Initiate a test query for a student aid application form, check whether the authorization prompt displayed on the interface disappears, confirming that the `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` configurations are valid.
- Submit a test request containing cross-system associated data, check whether the context coverage range of the model output meets business requirements, confirming that the `maxContext` parameter configuration takes effect.
- After adjusting the `temperature` parameter, initiate the same review test query multiple times, check whether the consistency of the output results meets expectations, confirming that the parameter configuration is stable.
- Submit a test query for long publicity materials, check the completeness and format of the referenced content, confirming that the `quoteMaxToken` and `maxTokens` parameter configurations are reasonable.
