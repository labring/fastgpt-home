# Business Process Guidance for Student Financial Aid and Subsidy Review: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data sources for this category include the national student financial aid management information system, school student registration system, civil affairs low-income and special hardship data, and fiscal payment system. Daily business documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, distribution lists, and public notice materials. Data is updated once per semester. Core content includes student identity identifiers, family economic status information, review process records, fund distribution details, and other key content. Cross-system data requires consistent field alignment.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The data characteristics of this category create multiple constraints for the retrieval and recall process. First, multi-system data sources require retrieval to support associated matching of fields across different systems, to prevent mismatches between identity information and aid materials. Second, the once-per-semester update frequency requires the knowledge base to run full synchronization on a regular basis, to avoid data lag that impacts review efficiency. Third, documents contain sensitive fund distribution and personal information. Retrieval and recall must strictly control permission scope, while ensuring result accuracy to prevent complaints or audit issues caused by incorrect or missed distributions. Finally, the verification link in the business process has a long duration. Retrieval must quickly return complete associated information to reduce manual verification workload.

## Configuration Settings
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Aid data requires high matching precision to avoid recalling application materials for non-corresponding students, ensuring review accuracy |
| `limit` | Top 8 entries | A single recall must cover multiple document types including certification, review, and distribution, to avoid increased manual verification costs caused by incomplete single-item information |
| `usingReRank` | Enabled | In multi-source heterogeneous data scenarios, re-ranking improves the display priority of core business information and optimizes the readability of retrieval results |
| `datasetSearchUsingExtensionQuery` | Enabled | Supports extended queries for cross-system fields such as student registration and low-income status, meeting the needs of multi-dimensional information verification in business processes |
| `searchMode` | Hybrid vector retrieval + keyword search | Balances precise matching of structured fields and semantic understanding of unstructured documents, adapting to multiple types of business documents |
| `collectionIds` | Bind to the exclusive dataset ID for student financial aid | Isolates business data from other categories, preventing unrelated content from mixing into retrieval results and ensuring data security |

## Three Common Misconfigurations
- Symptom: Knowledge base training tasks get stuck in the "training in progress" status, and no call records appear in invocation logs. Cause: Cross-system data import permissions are not configured correctly, or document formats do not meet platform requirements, preventing training tasks from starting or proceeding normally.
- Symptom: Retrieval results automatically remove directory structures or display duplicate content. Cause: The knowledge base's default automatic cleaning rules are enabled, and configurations for automatic directory deletion and deduplication are not disabled, resulting in accidental deletion of structural information and duplicate associated content from business documents.
- Symptom: When migrating a knowledge base from a development environment to a production environment, the exported file cannot be downloaded, and a server error is prompted. Cause: Temporary file storage permissions for the production environment are not configured, or the exported file size exceeds the quota limit of the production environment, causing the download task to fail.

## How to Verify Proper Configuration
- A test query is executed with the input "student financial aid application review process for a certain grade". The `similarity` score of the returned results is checked to confirm it falls within the configured range, and that the content includes core information of the corresponding documents.
- Dataset synchronization logs are reviewed to confirm that the full data synchronization task for each semester is completed normally, with no failed or timed-out records.
- A cross-system associated query is executed with the input "student name + family economic hardship certification result". Associated student registration, low-income status, and fiscal distribution data are checked to confirm they can be recalled.
- The `collectionIds` configuration is reviewed to confirm that only the exclusive dataset ID for student financial aid is bound, with no datasets from other categories mixed in.

The values provided are common starting points and should be evaluated against the applicable samples.
