# Workflow Guidance for Student Aid and Subsidy Review: Forms and Interactions

## What this category of data looks like
Data sources include the national student aid management information system, school student status system, civil affairs low-income and special hardship data, and fiscal payment system. Daily handling documents include the family economic hardship certification form, aid application form, scholarship and grant review form, disbursement list, and public notification materials. Data updates follow a semester cycle. The core fields of documents are student identity identifier, family economic status, student status, and bank card information. Cross-document association verification relationships exist, and cross-document data consistency must be maintained.

## What constraints these characteristics impose on the forms and interactions link
Cross-system calls from multiple data sources require form interactions to support multi-source data pulling and real-time verification, to prevent errors from manual entry. The semester-level update frequency requires form configurations to adapt to phased processing cycles, supporting batch import and export operations to fit the scale of centralized processing during a semester. The association verification of core fields requires the interaction flow to trigger corresponding rules as the user fills out each step, reducing subsequent manual verification time. The consistency between the disbursement list and public notification materials requires that after form submission, the verification logic for associated data is synchronized, ensuring that output content complies with business notification and fund disbursement specifications.

## How to set up configurations
The following configurations are based on FastGPT v4.17.0 logic.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Load in batches, with no more than 15 fields loaded at a single time | The business documents have a large number of fields, avoiding an overly lengthy single-page form that negatively impacts the filling experience |
| `userSelect` | Associate multi-data source verification, bind student status and civil affairs data fields for single selection | It is necessary to pull student identity and economic status data from multiple official systems to ensure the authenticity and validity of information |
| Single submission timeout | 120 seconds | The verification link needs to call multiple system interfaces, reserving sufficient interface response time |
| Form submission confirmation prompt | Include disbursement list verification instructions | Match the business link that requires public notification and verification, and inform users of subsequent processes in advance |
| Batch import limit | No more than 500 records imported at a single time | Adapt to the scale of semester-level batch processing, avoiding excessive system load |

## Three Common Misconfigurations
- Symptom: The same form guidance prompt pops up multiple times after configuration. Cause: The single-trigger logic of `formInput` is not correctly bound, causing the form to reload with every conversation.
- Symptom: Empty field errors appear after submitting the form. Cause: No verification rules for required fields are configured in `userSelect`, and incomplete submission operations are not intercepted.
- Symptom: The exported disbursement list is inconsistent with the submitted data. Cause: No synchronized field mapping associated with the fiscal payment system is configured, resulting in missing key fund information in the exported content.

## How to verify successful configuration
- Fill in the required and non-required fields of a test form, and check if corresponding field verification prompts trigger after submission.
- Call the configured data source interface to confirm that `userSelect` can successfully pull associated data from student status, civil affairs, and other systems.
- Initiate a single submission flow, and confirm that only one form guidance prompt appears, with no repeated triggers.
- Review system operation logs to confirm there are no error records for field verification failures or interface timeouts.
