# Business Process Guidance for Safety Production Hazard Inspection and Governance: Workflow Orchestration

## What this type of data looks like
Data is sourced from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. Updates occur daily.
Daily business documents include hazard inspection lists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders.
Core fields include unique hazard identifiers, inspection entities, rectification responsible persons, rectification deadlines, review results, and other key fields. These documents cover full-process records from hazard inspection through to archiving.

## Constraints on workflow orchestration
Daily updated data requires workflows to support high-frequency scheduling and real-time data pulling. This prevents process disconnects caused by data delays.
Multiple types of business documents require workflows to adapt to different node types. For example, form nodes correspond to rectification notice filling, and knowledge base nodes correspond to queries for major accident hazard judgment standards.
Multi-source data access requires the workflow's `variables` configuration to support structured mapping. This unifies input formats across different systems.
Hazard inspection, rectification tracking, and review and archiving are the most time-consuming steps. Workflows must be split into independent nodes. Failure handling branches must also be configured to address exceptions such as failed inspections or overdue rectifications. This stops severe consequences from occurring.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `variables` | A structured variable set mapped from business document fields, including fields such as hazard ID, rectification responsible person, rectification deadline, formatted as `{"hazard ID":"string","rectification responsible person":"string","rectification deadline":"date"}` | Daily business documents include multiple core fields. Unified variable formats are required to adapt to full-process nodes |
| `nodeId` | Configure a unique identifier string for each reusable node, for example `"node_review_001"` | Supports reusing configured nodes across branches, prevents link identification conflicts |
| Variable reference rules | Wrap variable names with double curly braces, for example `example value`. Variable names may only contain Chinese, English, and underscores | Prevents `quote type error` errors, strictly matches variable naming specifications |
| Tool call branch settings | Configure as single-branch execution mode, only execute the currently selected node branch | Avoids parallel issues where tool calls and AI replies execute simultaneously |
| Workflow timeout threshold | Set to 600 seconds | Adapts to time requirements for multi-source data pulling and business processing, prevents process interruptions |
| Trigger mode configuration | Configure as dual mode: daily scheduled trigger + manual trigger. Set the scheduled trigger time to 00:00 daily | Matches the daily data update frequency, covers daily scheduling and emergency handling scenarios |

## Three Common Misconfigurations
- Symptom: The workflow fails to jump to the target node when reusing a form fill node across branches. Cause: No unique `nodeId` identifier is configured for the node, or duplicate node IDs cause link identification conflicts.
- Symptom: Workflows that call knowledge base assistants via API nesting return empty values. Cause: Context parameters are not passed correctly via `variables`, or the link update logic is not adapted when using FastGPT v4.8.10 (not included) and above versions.
- Symptom: A `quote type error` pop-up appears when using variable references. Cause: Variables are not wrapped with double curly braces, or variable names contain unescaped special characters that do not match preset variable naming rules.
- Symptom: Tool calls and AI replies execute simultaneously, triggering multi-branch parallel execution. Cause: Single-branch execution configuration is not enabled, and the restriction to only execute the currently selected node branch is not applied.

## How to Verify Correct Configuration
- Use the FastGPT v4.17.0 platform, manually trigger a test workflow, submit a simulated hazard data entry, and check if nodes jump as expected and cross-branch reusable nodes are called normally.
- Call the API to trigger the workflow, check if the returned results include expected hazard processing node outputs, and no empty values are returned.
- Input test text with variables, check if a `quote type error` pop-up appears, and if variable references are parsed correctly.
- Configure a tool call node and trigger the workflow, check if only a single branch executes with no parallel execution observed.

The values provided here are common starting points. They should be evaluated against the reader's own sample data.
