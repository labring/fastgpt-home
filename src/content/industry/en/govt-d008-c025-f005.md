# Business Process Guidance for Safety Production Hazard Inspection and Governance: Tool Calling and Plugins

## What This Category of Data Looks Like
Data for this category comes from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily involved documents include hazard inspection checklists, hazard governance ledgers, rectification notices, review records, and major hazard supervision and rectification notices. Data fields include hazard level, rectification responsible entity, rectification deadline, review result, and others. There are no unified fixed units. Some fields must match the format of corresponding business forms. Data processing must cover closed-loop records of the entire inspection, rectification, and review process, to support full-link verification of hazard governance.

## Constraints Imposed on Tool Calling and Plugins by These Characteristics
Since data sources include multiple business systems, tool calling must adapt to multi-source interface call formats and permission verification rules. The daily update frequency requires tool calling synchronization logic to match the daily data refresh rhythm, to avoid data lag. The need to process multiple types of business documents requires tool calling to support configuration of extraction and mapping rules for different fields. The closed-loop process of hazard inspection and rectification requires that tool calling results be associated with corresponding business ledgers, to ensure complete data links. The high-risk consequences of errors require tool calling to have state verification and abnormal interception capabilities, to prevent erroneous data from flowing into subsequent links.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | Set to `auto`, allow calling designated hazard inspection-related tools | Adapt to scenarios where dynamic selection of inspection, rectification, and review tools is required in business |
| `functionCall` | Enabled | Support structured extraction of fields from hazard ledgers and rectification notices, to meet business data flow requirements |
| Concurrent call limit | 3–5 calls/second, calibrated based on actual testing | Adapt to interface call frequency limits of safety production business systems, to avoid triggering rate limiting |
| Retry count | 2 times | Address call failures caused by temporary network fluctuations or interface rate limiting |
| Tool call timeout | 60 seconds | Match the average processing duration of business links such as hazard inspection and rectification verification |
| Maximum context length | 8000–12000 token | Accommodate complete content of multiple business documents, to avoid truncation of critical hazard information |

## Three Common Configuration Mistakes
- Trigger interface rate limiting errors, returning 429 status code. The cause is that no reasonable concurrent call limit is configured, and concurrent requests exceed the interface limits of safety production business systems.
- Tool calling results cannot be passed to the next round of conversation modules. The cause is that the structured output switch for `functionCall` is not enabled, resulting in non-standard text results that cannot be parsed by subsequent modules.
- Global variable updates do not take effect, and old values are still used during tool calling. The cause is that the scope of global variables is not bound in the tool calling configuration, resulting in variable updates only applying to the current conversation context and not being synchronized to the tool calling link.

## How to Confirm the Configuration Is Correct
- View the tool calling logs in FastGPT v4.17.0, confirm that the value of the `toolChoice` parameter matches the configured setting, with no abnormal switching.
- Initiate a hazard inspection tool calling request, check whether the returned results include structured hazard fields that match the preset business document format.
- Simulate concurrent requests, observe interface return statuses, confirm that no rate limiting errors are triggered, adjust the concurrent limit to meet business system requirements.
- Modify a global variable, then trigger a tool calling request, check whether the calling parameters use the updated variable values.
