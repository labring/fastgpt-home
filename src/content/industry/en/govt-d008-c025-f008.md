# Business Process Guidance for Work Safety Hidden Danger Investigation and Governance: Document Parsing and Chunking

## What data belongs to this category
This category of data originates from work safety supervision systems, enterprise hidden danger self-inspection systems, law enforcement inspection records, and accident statistics systems. Updates occur daily. Commonly processed documents include hidden danger investigation checklists, hidden danger management ledgers, rectification notices, review records, and major hidden danger listing and supervision orders. Most documents contain structured content such as hierarchical investigation items, rectification requirements, responsible parties, and time limit requirements. Some documents also include unstructured elements like on-site photos and signature pages.

## What constraints do these characteristics impose on document parsing and chunking?
Batch documents updated daily require parsing processes to support efficient batch handling, to avoid delaying hidden danger investigation timelines. Hierarchical investigation items and rectification process documents require context retention during chunking, to avoid breaking rectification logic. Unstructured signature pages and photos may disrupt text extraction, requiring targeted filtering or annotation. Variations in fields across different document types require chunking rules to match each document’s structural traits, ensuring subsequent retrieval accurately matches hidden danger investigation business keywords.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Aligns with the length of individual hidden danger descriptions in hidden danger investigation checklists and rectification notices, avoiding breaking rectification logic during chunking |
| `chunkSplitter` | Split by paragraph + title | Matches the structure of hierarchical documents, preserving context association between investigation items and rectification requirements |
| `customPdfParse` | Enable built-in parser | Replaces external parsers to avoid parsing failures caused by incorrect configuration of external keys, and adapts to batch document processing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Addresses parsing time for single large rectification ledgers, avoiding timeout interruptions to batch processing workflows |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to the maximum single-file size limit for batch-uploaded law enforcement inspection records and accident statistics documents |

## Three Common Configuration Errors
- Phenomenon: When using an external PDF parsing tool, parsing fails and logs indicate the corresponding key was not found. Cause: The associated key for the external parser was not correctly filled in the system configuration page of FastGPT v4.17.0, causing the parsing module to fail to call external services.
- Phenomenon: After uploading documents in a multi-level directory, only the content of the top-level directory is parsed, and content in subdirectories is not retrievable. Cause: The default chunking rule does not adapt to the hierarchical structure of multi-level directories, and does not automatically traverse subdirectory content.
- Phenomenon: When using marker parsing, logs prompt split-related errors. Cause: The `chunkSize` configuration value does not match the paragraph length in the document, leading to abnormal truncation during chunking.

## How to Verify Correct Configuration
- Upload a single hidden danger investigation checklist document. Confirm the parsed text content includes all investigation items and rectification requirements, and that key information is not broken during chunking.
- Navigate to the system configuration page. Verify the configured values for `PARSE_FILE_TIMEOUT_SECONDS` and `UPLOAD_FILE_MAX_SIZE` meet batch document processing requirements.
- Upload a test document with a multi-level directory. Confirm the parsing result covers all subdirectory content, and that the chunking rule adapts to the hierarchical structure.
- Trigger a batch parsing task. Check logs for timeout or parsing failure errors, and confirm the configured timeout parameter supports document processing timelines.

The values provided are common starting points and should be evaluated against the specific samples used in the target deployment.
