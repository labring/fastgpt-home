# Business Process Guidance for Engineering Construction Project Approval: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data is sourced from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform, with a daily update frequency. Daily documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. Data fields cover basic project information, participating construction unit qualifications, approval node status, material verification results, and more. All fields correspond to standardized approval items from the housing and urban-rural development department, with no additional custom units.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
The daily data update requirement means the dialogue module must connect to official approval systems in real time to obtain the latest node information, and avoid using expired cached data. Daily documents have varied formats, so prompts must clearly guide users to submit materials compliant with housing and urban-rural development department standards. Corresponding fields must match the standard document structures for construction permit applications, construction drawing review qualification certificates, and similar items. Participating construction unit qualifications must be verified against information from the enterprise qualification database and credit platform. Multi-turn dialogue must gradually guide users to upload qualification documents, and avoid missing verification items. The feature of multiple parallel approval nodes requires the dialogue system to track the status of multiple approval links simultaneously, and prompt users to follow up on corresponding tasks.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `messages` | Split multi-turn context by approval phase, retain only necessary user input and system responses for the current phase in each turn, total length not exceeding 8000 characters | Engineering approval-related documents have many fields, overly long context will interfere with prompt matching for the current phase, and this aligns with the phased processing logic of housing and urban-rural development department approval workflows |
| `variables` | Bind preset variables such as project number and participating construction unit name, obtain variable values via synchronization from the engineering approval management system | Data sources include the engineering approval management system, daily updated project information can be automatically synchronized to reduce manual input errors |
| `chatId` | Bind unique project identifier, each approval application corresponds to an independent `chatId` | This is required to distinguish approval processes for different construction units, avoid context confusion, and align with the independent processing requirements of approval business |
| Context retention limit | First 10 turns of dialogue | Engineering approval processes have many phases, excessive historical dialogue will increase prompt load, retaining core phases is sufficient to cover processing needs |
| Prompt triggering rule | Trigger corresponding templates based on the document type uploaded by the user, for example, trigger the qualification verification template after uploading a construction drawing review qualification certificate | Daily document types are fixed, triggering by type can improve guidance accuracy |

## Three Common Misconfiguration Issues
- A call to the dialogue guidance interface returns the `unAuthChat` error, even though the apikey is filled correctly. Cause: The exclusive interface access permission for the engineering approval management system is not configured, or the correct system authorization parameters are not bound in `variables`.
- The AI dialogue response contains line breaks, causing the JSON request to fail. Cause: The prompt is not configured with rules to escape line breaks, and no preprocessing is performed for line breaks in user input and system responses during multi-turn dialogue, resulting in abnormal request body format.
- An error is returned when uploading any approval document, but the text input dialogue function works normally. Cause: The parsing rules for the corresponding document type are not configured, or the file upload interface is not associated with the storage permission of the engineering approval system, causing the file to fail to be read properly.

## How to Verify Successful Configuration
Based on the features of FastGPT v4.17.0, configuration can be verified through the following actions:
- Initiate a simulated dialogue, enter questions related to construction permit applications, and verify that the `messages` context only retains necessary information for the current phase, with no redundant historical content.
- Upload a construction drawing review qualification certificate, and verify that the system triggers the corresponding prompt template to guide users to supplement participating construction unit qualification information.
- Call the interface to test the `chatId` binding logic, confirm that dialogue contexts for different simulated projects are independent of each other, with no information confusion.
- Check that the project information bound to `variables` matches the synchronized data from the engineering approval management system, with no manual input errors.
