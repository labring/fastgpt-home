# Business Process Guidance for Engineering Construction Project Approval: Workflow Orchestration

## What this category of data looks like
Data for this category is sourced from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. Updates occur daily. Commonly processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. Data fields include approval node identifiers, participating unit qualification numbers, material submission verification status, credit rating identifiers, and more. The character count of individual data entries ranges from tens to hundreds.

## Constraints imposed on workflow orchestration
This category of data originates from multiple independent systems. Workflow orchestration must configure cross-system data pull nodes to ensure real-time synchronization of approval materials and qualification information. Daily data updates require workflows to include scheduled synchronization steps to prevent data lag. Multiple types of approval documents require workflows to support parsing and verification rules tailored to each document type. Parallel approval node business logic requires workflows to support parallel branch orchestration, while tracking completion status for each branch to align overall process progress.

## Configuration Settings
The following configuration items are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Include approval node ID, participating unit qualification number, material verification rules | Match core fields of engineering construction project approval data to ensure precise parameter matching to business needs during tool calls |
| `nodeId` | Assign unique identifiers in the order of approval process nodes | Ensure clear calling and jump logic for workflow nodes, avoiding process interruptions caused by node confusion |
| Scheduled synchronization frequency | Once every 24 hours | Aligns with the daily update frequency of this category of data, ensuring timeliness of synchronized data meets business requirements |
| Parallel branch count | First 3 approval branches | Covers common parallel approval links in engineering approval, adapting to parallel processing needs of core business processes |
| Loop body termination condition | Trigger when material verification passes | Adapts to business scenarios of cyclic verification of approval materials, meeting actual requirements for loop termination |
| Single tool call parameter | Match the q field to the material requirements of the current approval node | Resolves issues of precise parameter matching during tool calls, avoiding invalid calls or return of irrelevant content |

## Three Common Misconfigurations
- Symptom: Tool calls return irrelevant approval material information, or fail to match the material requirements of the current node. Cause: Fields in `variables` are not accurately mapped to the `q` parameter used in tool calls, resulting in inaccurate parameter matching.
- Symptom: Workflows run normally in the preview environment, but experience node jump errors or data pull failures after publishing the login-free window. Cause: Global unique identifier rules for `nodeId` are not configured, leading to chaotic node mapping relationships post-deployment.
- Symptom: The loop body fails to terminate when specified conditions are met, and continues executing verification logic. Cause: The trigger rules for the loop body termination condition are not set correctly, or the corresponding data verification node is not bound.

## How to Verify Successful Configuration
- Review the workflow's node mapping relationship to confirm each `nodeId` corresponds to a unique approval link, with no duplicates or omissions.
- Trigger the scheduled synchronization task, and verify that the pulled data fields match the preset `variables`.
- Simulate the cyclic verification process to confirm whether the loop body terminates normally when material verification passes.
- Publish the login-free window, simulate calls for different approval nodes, and confirm that tool call parameters match accurately.
