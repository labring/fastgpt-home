# Business Process Guidance for Engineering Construction Project Approval: Tool Calling and Plugins

## What data looks like for this category
Data for this category comes from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. The update frequency is daily. Daily documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. All are form-based documents associated by project ID. Fields include participating unit qualification numbers, project approval document numbers, approval node status, acceptance record numbers, and more. The structure adjusts slightly based on the approval stage.

## What constraints these characteristics impose on the "tool calling and plugins" link
Multiple data sources require tool calling to support interfacing with multiple heterogeneous systems, to avoid data silos.
The daily update frequency requires tool calling to be configured with a scheduled synchronization mechanism, to ensure access to the latest approval status and qualification information.
The professionalism and diversity of document fields require parameter passing to strictly match the field names of the corresponding system, to avoid call failures caused by parameter mismatches.
Severe consequences of approval process errors require adding pre-verification steps in the tool calling link, to filter invalid or incorrect data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match the corresponding tool for different approval stages, covering the entire process of project approval, construction permit application, completion acceptance, and more |
| `functionCall` | Allow calling all registered approval-related plugins | Ensure access to all types of tools including qualification verification, document parsing, system docking, and more |
| Tool call timeout period | 600 seconds | Reserve sufficient response time for cross-system cross-domain interactions involved in the approval process |
| Number of results returned per single call | Top 8 entries | Core approval information is concentrated in a small number of items, avoiding redundant data interfering with the process |
| Batch processing limit | 5 projects per call | Avoid overloading government systems caused by too much data in a single call |
| Log retention period | 30 days | Comply with compliance requirements for government data storage |

## Three common mistakes
- Symptom: Empty results returned when calling the enterprise qualification database plugin. Cause: The unified social credit code required by the approval system was not used as the query parameter; the enterprise name field was used incorrectly, and parameter passing did not meet the system requirements.
- Symptom: No conversation log generated after calling other approval applications in the workflow. Cause: The log recording configuration for plugin calls was not enabled, or logs were not synchronized to the government data storage node, failing to meet compliance traceability requirements.
- Symptom: Third-party dependency libraries cannot be loaded when running code plugins. Cause: The installation path of the corresponding dependency was not configured in the plugin runtime environment, or the dependency version was incompatible with the government system runtime environment, causing dependency loading failures.

## How to confirm the configuration is complete
- Execute a simulated construction permit application tool call process, and check whether the returned results include the project approval document number field returned by the engineering construction project approval management system.
- View the plugin call logs in FastGPT v4.17.0, and confirm that the parameters and returned results of each tool call are fully recorded.
- Test the code running plugin, load the specified enterprise qualification verification dependency library and execute the verification code, and confirm that there are no loading errors.
- Set `toolChoice` to `auto`, trigger the completion acceptance filing process, and verify that the system automatically calls the completion acceptance record form parsing plugin.
