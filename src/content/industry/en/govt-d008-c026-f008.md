# Business Process Guidance for Engineering Construction Project Approval: Document Parsing and Chunking

## What the data for this category looks like
Data for this category originates from engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases and credit platforms, with a daily update frequency. Commonly processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, completion record forms and similar items. Most documents combine structured forms and formatted technical instructions. Fields include participating unit qualification numbers, project approval document numbers, approval node status and other items. Some documents are in scanned format, with handwritten annotations or non-standard layouts.

## What constraints these characteristics impose on the document parsing and chunking link
Dispersed data sources lead to inconsistent document formats, with mixed scanned and electronic documents. This requires the parsing link to support multi-format adaptation and OCR capabilities. High-frequency daily updated data requires the parsing process to have stability, to avoid timeouts that impact approval circulation efficiency. Documents contain key associated fields such as qualification numbers and approval document numbers. Chunking must retain the contextual association of fields to avoid splitting that damages information integrity, which would affect the accuracy of subsequent process guidance. Some documents have annotation content, which must be retained during chunking to ensure no missing information when matching subsequent approval nodes.

## How to configure
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of engineering documents, avoids splitting key approval fields |
| `chunkSplitter` | Split by paragraph + title | Matches the hierarchical structure of approval nodes and qualification information in documents |
| `customPdfParse` | Enabled | Enables OCR capability for scanned PDF documents, adapts to scanned documents such as construction drawing review qualification certificates |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Matches the parsing time of large completion record forms, avoids process interruption due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Adapts to scenarios where multiple approval materials are uploaded in a package, meets single batch submission requirements |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking rules for different types of approval documents, adapts to differences between qualification documents and project documents |

## Three common errors
- The `customPdfParse` parameter is not correctly specified when calling the file collection creation API, resulting in failed parsing of scanned PDF documents, returning empty content or garbled formatting. The cause is that the corresponding configuration item is not included in the API request, and OCR parsing capability for scanned document formats is not enabled.
- The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted to a reasonable range, triggering a timeout error when parsing large completion record forms, returning a 504 status code. The cause is that the default timeout duration is insufficient to cover the parsing process of large documents, leading to task interruption.
- Chunking rules are not configured to distinguish multi-file parsing results, resulting in mixed fields from different approval materials, making it impossible to accurately match corresponding approval nodes. The cause is that file-level chunking isolation is not enabled, leading to chaotic contextual association of parsing results.

## How to confirm the configuration is correct
- A single scanned PDF document is uploaded. The parsing result is checked for complete drawing numbers, review opinions and other key fields to confirm that the OCR parsing capability is active.
- A large completion record form is uploaded. Parsing time is monitored to confirm it falls within the preset range, with no timeout error prompts.
- Multiple different types of approval documents are uploaded. The correspondence between file identifiers in the parsing results and the original uploaded files is verified to confirm that chunking results are distinguished by file.
- The API for creating a file collection is called. The request parameters are checked to confirm they include the specified chunking and parsing configurations, with no parameter missing prompts in the returned results.
