# Business Process Guidance for Engineering Construction Project Approval: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
The data sources for this category include the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. The update frequency is daily. Documents processed daily include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, completion record forms, and similar items. Document structures include fields such as approval nodes, application material lists, participating unit information, and compliance verification requirements. Some documents use structured form formats, while others are process description texts.

## Constraints on Knowledge Base Retrieval and Recall From This Category’s Data Characteristics
The data characteristics of this category impose multiple constraints on the retrieval and recall process. Mixed-format documents from multiple systems require the retrieval system to support unified recall logic for structured forms and unstructured process texts. The daily update frequency requires the retrieval process to support incremental synchronization configuration, ensuring recalled content aligns with the latest approval data. Documents are centered around approval process nodes, requiring retrieval results to precisely match the needs of the current processing stage, and avoiding irrelevant qualification materials or expired documents. Approval-related content has strict compliance requirements, so results that do not meet current process verification rules must be filtered out.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the precision requirements for engineering approval documents, avoiding recall of irrelevant qualification materials or expired documents |
| `limit` | Top 8 entries | Controls the volume of single-recall results, adapting to the short-context display needs of approval process guidance |
| `searchMode` | Semantic search | Adapts to structured fields and process logic of approval documents, improving recall relevance across document formats |
| `usingReRank` | Enabled | Performs secondary ranking on recall results, prioritizing content that matches the current approval node |
| `datasetSearchUsingExtensionQuery` | Enabled | Adds synonymous expressions related to approval processes, such as expanding "construction permit" to "construction project construction permit application", to expand query coverage |
| `collectionIds` | Bind to engineering approval-specific datasets | Limits retrieval scope, avoiding inclusion of public resource or other category documents |

## Three Common Configuration Errors
- Retrieval results return a large number of irrelevant enterprise qualification documents. The cause is failure to correctly configure `collectionIds` to limit the specific dataset, resulting in inclusion of data sources from other categories.
- An abnormal error is displayed after triggering knowledge base training. The cause is failure to configure incremental synchronization tasks according to the daily update frequency; full synchronization exceeds the system's single-processing limit.
- Attempting to delete all content from a specified knowledge base only clears some documents. The cause is failure to select the "Associate all version documents" option, resulting in deletion of only content from the current active version.

## How to Verify Correct Configuration
- Enter a typical approval query in the FastGPT v4.17.0 test interface, such as "What materials are required for a construction permit application", and verify that returned results only include the engineering approval-specific collection.
- Trigger an incremental synchronization task, check that the update time in the synchronization log matches the daily update frequency of the data source, confirming that the incremental synchronization configuration is effective.
- Enter a nested query, such as "Processing requirements for parallel approval nodes", verify that associated documents for the corresponding approval node are recalled, confirming that the nested search function operates correctly.
- Call the `usingReRank` function, compare the order of retrieval results before and after reranking, confirming that the secondary ranking logic is effective.
