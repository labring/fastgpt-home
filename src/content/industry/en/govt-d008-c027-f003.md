# Business Process Guidance for Engineering Construction Project Bidding and Tendering: Multi-turn Dialogue and Prompt Words

## What this category’s data consists of
Data for this category comes from national public resource trading platforms, local public resource trading platforms, project approval systems, and bidding supervision systems. Update frequency is daily. Documents handled daily include tender announcements, pre-qualification documents, bidding documents, bid documents, bid evaluation reports, successful candidate announcements, and winning result announcements. Data fields include section division, qualification requirements, bill of quantities, bid evaluation expert records, objection and complaint content, and more. Document structure primarily mixes structured forms and unstructured text.

## Constraints imposed on multi-turn dialogue and prompt words
This category’s data is updated daily and sourced from scattered locations. Multi-turn dialogue must link in real time to the latest trading documents, and prompt words must explicitly specify prioritizing access to the latest data from local public resource trading platforms. The mixed structured and unstructured document structure requires multi-turn dialogue to gradually guide users to clarify document types, avoiding confusion between pre-qualification and bidding document clauses. There are many detailed fields such as section division and qualification requirements. Multi-turn dialogue must split questions by processing link, avoiding context confusion caused by overload from single-round input. Winning result announcements have high timeliness requirements. Multi-turn dialogue must respond promptly to user progress query requests, avoiding cases where prompt words do not link to the latest announcement data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Conversation context window | First 20 turns of dialogue content | This category has many document fields and large per-round information volume. Limiting context avoids redundant interference. FastGPT v4.17.0 supports truncating context by turn count |
| `variables` variable binding | Bind 1 local public resource trading platform data source | Ensures multi-turn dialogue calls the latest bidding data for the corresponding region |
| `messages` historical message management | Truncate old conversations by processing link | Avoids expired bidding document information interfering with current queries |
| Prompt template configuration | Split into three links: tendering, bid evaluation, objection | Matches the core processing flows of this category |
| Call timeout setting | 600 seconds | Handles parsing and data pulling for long documents such as bid evaluation reports and winning result announcements |
| Single input length limit | 8000 characters | Adapts to long text inputs like bidding documents and bid evaluation reports for this category |

## Three Common Misconfigurations
- Phenomenon: Cannot retrieve independent content of a single question in multi-turn dialogue, with context confusion occurring. Cause: Did not correctly use `chatId` to bind conversation sessions, leading to merged contexts from different questions.
- Phenomenon: Errors occur after configuring the database connection plugin, and dialogue cannot normally pull bidding documents. Cause: Did not correctly configure data source access permission parameters in `variables`, causing the plugin to fail connecting to the public resource trading platform database.
- Phenomenon: Dialogue response time exceeds 600 seconds, but the model call group count is only 1. Cause: Did not set a reasonable call timeout limit. Long document parsing and data pulling exceed the default threshold, leading to session suspension.

## How to Confirm Proper Configuration
- Initiate a query related to tendering, and verify that the conversation context only retains content from the current processing link, with no expired information.
- Call the database connection plugin, and verify that the latest bidding document data for the corresponding local area can be pulled.
- Submit a long-text bidding document, and check that the dialogue correctly identifies and extracts core fields such as sections and qualification requirements.
- View session logs, and confirm that `chatId`-bound sessions have no context confusion.
