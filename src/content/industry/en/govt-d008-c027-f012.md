# Business Process Guidance for Engineering Construction Project Bidding: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from the national public resource trading platform, local public resource trading platforms, engineering approval systems, and bidding supervision systems. The update frequency is daily. Commonly processed documents include bidding announcements, qualification pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements. Document structures include dedicated business fields such as qualification requirements, performance thresholds, bill of quantities, and construction periods. Data volume grows as the number of projects accumulates, and the number of documents synchronized in a single batch fluctuates.

## What constraints these characteristics impose on deployment and upgrade
The daily updated data requires the system to be configured with a stable incremental synchronization mechanism to avoid excessive resource usage from full synchronization. Documents of multiple types with large structural differences require deployment to adapt parsing rules for different documents, ensuring extraction accuracy for core fields such as qualifications and bill of quantities. Processing dedicated business fields requires configuring targeted matching logic to avoid deviations from general parsing. Additionally, errors in the bidding process have serious consequences, so deployment must ensure system stability, and consideration must be given to storage and interface access restrictions in intranet environments to avoid deployment failures caused by public network dependencies.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Intranet-accessible S3-compatible storage endpoint | Meets the cumulative storage needs of engineering bidding documents while ensuring intranet data security |
| `REDIS_URL` | Redis connection address for nodes with 8 GB or more memory | Used for high-frequency caching of process status, user sessions, and other data to ensure system response speed |
| `DB_MAX_LINK` | 200–300 | Handles daily batch synchronization document reading requirements and avoids database connection exhaustion |
| Incremental synchronization frequency | Every 24 hours | Matches the daily update frequency of data for this category, avoiding data lag from overly long synchronization intervals |
| File storage quota | 1000 GB | Meets the long-term cumulative storage needs of bidding documents |
| `ROOT_KEY` | Key only accessible to the operations team | Ensures the security of system root permissions and avoids unauthorized operations |

## Three common configuration errors
- Symptom: Rule traceability display symbols appear at the end of conversation response results. Cause: After upgrading to FastGPT v4.9.13 or later versions, the traceability display configuration is enabled by default.
- Symptom: MinIO storage connection fails, returning public network access permission errors. Cause: FastGPT v4.10.0 and later versions modified the storage dependency requirements of the plugin system, requiring storage endpoints to be accessible via the public network. An error is triggered when the intranet deployment environment cannot meet this requirement.
- Symptom: Bill of quantities fields in bidding documents cannot be accurately extracted. Cause: Parsing rules adapted to engineering document structures have not been configured, resulting in insufficient field matching accuracy.

## How to verify a complete configuration
- Run an incremental synchronization task, check whether updated bidding documents for the current day can be normally pulled, with no errors and document numbers matching expected values.
- Upload a standard bidding document to the system, check whether core fields such as qualification requirements and bill of quantities can be correctly parsed and extracted.
- Access the configured `FE_DOMAIN` address, confirm that the frontend page loads normally and there are no permission or connection errors.
- For FastGPT v4.17.0, additionally check whether the plugin system's storage configuration meets the current version's requirements, and test that storage endpoint read and write functions operate properly.
