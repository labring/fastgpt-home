# Business Process Guidance for Market Entity Registration and Licensing: Model Integration and Configuration

## What data for this category looks like
Daily business documents for this category include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and similar materials. Fields cover core business content such as entity name, residence address, shareholder information, and license type. Data sources include the full-process electronic enterprise registration system, the National Enterprise Credit Information Publicity System, the electronic business license system, and the residence information database. Data updates occur daily. Document formats include forms, resolutions, certificates, and other types. There is no single unified standard format. Input must support multiple text structures.

## Constraints these characteristics impose on model integration and configuration
The multi-source data and non-uniform format characteristics require the model integration link to support parsing multiple document structures such as forms, resolutions, and certificates. This avoids core field extraction failures due to format mismatches. The daily updated data requirement means the configuration link must support real-time or incremental synchronization of business data. This prevents use of outdated market entity information. The high time-consuming nature of core business links requires the model to accurately call tools for tasks such as name verification and residence check. It also requires limiting output length to maintain readability of the business guidance process. The serious consequences of errors mean configuration must prioritize accuracy of field extraction and rule judgment.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Daily business documents are often multi-page combined materials. Full business context must be covered to ensure field extraction accuracy |
| `maxTokens` | 4000–6000 token | Business process guidance must output complete step prompts and verification instructions. This prevents output content from being truncated |
| `temperature` | 0.1–0.3 | Output consistency must be maintained for tasks such as name verification and residence check. This reduces random deviations |
| `toolChoice` | auto | Supports the model to autonomously call tools for core business links such as name verification and residence information check |
| `AIPROXY_API_ENDPOINT` | Local Ollama-deployed Qwen2.5 API endpoint | Adapts to needs of self-developed large model deployments. Meets requirements for local processing of business data |
| `AIPROXY_API_TOKEN` | Access token corresponding to the Ollama deployment | Completes identity verification for large model access. Ensures legitimacy of API calls |

## Three common mistakes
- Symptom: Tool calls do not respond. The interface displays a "tool not triggered" log. Cause: `toolChoice` is not set to auto, or API connection fails due to incorrect configuration of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`.
- Symptom: Large model output is chaotic. Core fields such as residence and shareholder information cannot be extracted accurately. Cause: Business documents are not passed in structured format, or `maxContext` parameter is not set appropriately, leading to context overflow. The model cannot fully read business material content.
- Symptom: Recalled business documents after configuration do not match current processing needs. Irrelevant historical registration materials are returned. Cause: Recall scope is not limited to market entity registration data, or matching logic is not adjusted based on field characteristics of business documents.

## How to confirm configuration is complete
- Initiate a name verification test. Upload simulated enterprise name application materials. Check whether the model can accurately call tools to return judgment results on name availability status.
- Upload complete establishment registration application and articles of association materials. Check whether the model's output business process guidance covers all required fields and verification points.
- View FastGPT v4.17.0 API call logs. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured correctly. No connection timeout or identity verification failure errors will appear.
- Test built-in time tool call functionality. Submit a query for "current time". Confirm that the tool can return results normally. Verify that the tool call link configuration is complete.
