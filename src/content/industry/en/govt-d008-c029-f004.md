# Business Process Guidance for Urban Sanitation and Urban Management Law Enforcement Cases: Workflow Orchestration
This page is compatible with FastGPT v4.17.0

## What the data for this category looks like
Data for this category typically comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance systems, and public complaint tickets. The update frequency is daily. Daily generated documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and case closure reports. Common data fields include case number, incident location, responsible entity, violation type, and disposal progress. There are no fixed standardized units, and fields vary by document type.

## Constraints imposed by these characteristics on workflow orchestration
Format differences across multiple data sources require workflows to include unified data preprocessing nodes. These nodes align field structures returned by different platforms.
The daily update frequency requires scheduled trigger nodes. These nodes synchronize incremental case data.
Diverse document types (text records, photos, notices) require workflows to support cross-format node calls.
Splitting core time-consuming links requires separating evidence collection and positioning, violation judgment, and rectification tracking into independent nodes. This enables separate debugging and exception handling.
The risk of law enforcement disputes from insufficient evidence requires workflows to include key field verification links. These links ensure completeness of core materials such as on-site photos and case filing information.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind case number and responsible entity as global variables | Used to pass core business identifiers of urban management law enforcement cases across nodes, simplifying data flow between multiple nodes |
| Database connection node timeout | 600 seconds | Adapt to the response delay of urban management law enforcement platform interfaces, avoiding case process interruptions caused by data pull timeouts |
| Single-choice variable binding | Associate enumerated values of global variables | Used for selection of violation type and disposal status, matching fixed options for business handling |
| Context loading node | Load the first 5 historical case conversations | Used to track historical disposal records of similar cases to assist judgment for responsible entities |
| `nodeId` | Mark evidence collection and positioning, violation judgment nodes with independent IDs | Facilitate separate debugging of abnormal nodes and locate process interruption points |

## Three common errors
- Symptom: Single-choice variables in node selection cannot receive enumerated values passed by global variables, and the interface displays empty fields. Cause: Global variables are not correctly bound to the option data source of single-choice variables, and variable mapping rules are not configured.
- Symptom: Database connection node returns an Access denied error, and the process is interrupted. Cause: The dedicated access key for the urban management law enforcement platform is not configured, or the key permissions do not cover the query scope of case data.
- Symptom: When calling the API via workflow, preset context configuration cannot be loaded, and historical case data is not brought in. Cause: The context trigger identifier is not carried in the API request, or the context binding condition of the workflow does not match the current business scenario.

## How to confirm the configuration is complete
- Check the binding configuration of the global variable `variables`, confirm that core business fields have been correctly mapped to the input parameters of corresponding nodes.
- Trigger a test process to verify that the database connection node can normally pull case data from the urban management law enforcement platform without permission errors.
- Simulate a single-choice variable selection scenario, confirm that the enumerated values of global variables can be normally passed to node options.
- Call the workflow API to verify that the context configuration has been correctly loaded, and historical case data can be normally called.
