# Business Process Guidance for Urban Sanitation and Urban Management Law Enforcement Cases: Tool Calling and Plugins

## What This Category of Data Looks Like
The data for this category mainly comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance, and public complaint work orders. The update frequency is daily. Associated daily documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and case closure reports. Common data fields include inspection locations, problem types, responsible entities, rectification status, etc. Some associated unstructured data such as on-site images are included. Overall, the data is mainly a combination of structured case ledgers and semi-structured submission materials.

## What Constraints Do These Characteristics Impose on the "Tool Calling and Plugins" Link
Because data sources are scattered, the tool calling link must support integration with multiple third-party APIs to cover data pulling from law enforcement platforms, grid platforms, and work order systems. Since unstructured data such as on-site photos is included, plugins must adapt to unstructured content parsing. The daily data update feature requires that the tool calling trigger logic matches the business inspection cycle to avoid calling outdated data. At the same time, to prevent insufficient case evidence, tool return results must verify the completeness of core fields to ensure that associated information for links such as case filing and rectification is complete.

## How to Set Configurations

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to scenarios where multiple-step tool calling is required for urban management cases, automatically select matching law enforcement-related tools |
| Plugin call trigger timing | Within 10 seconds after case submission | Match the immediate processing needs after grid staff reports, avoid delays affecting law enforcement progress |
| `functionCall` | Enable mandatory field verification | Ensure that case data returned by tools includes core law enforcement fields such as inspection locations and responsible entities |
| Single tool call timeout | 30 seconds | Cover the conventional time required for on-site positioning and cross-platform data pulling, avoid excessive waiting |
| Global variable initialization | Preset basic values for law enforcement scenarios | Unify general parameters such as case number prefixes and responsible entity classifications, reduce repeated configuration |
| Workflow start trigger | Grid work order push event | Integrate with real-time submission channels of urban operation platforms, enable immediate case triggering |

## Three Common Misconfigurations
- Phenomenon: Tools return empty content, or timeout errors occur around 10 seconds after triggering. Cause: No reasonable single call timeout is configured, or the connected third-party API has no retry logic set, resulting in request timeouts or no valid returns.
- Phenomenon: Initial plugin values do not take effect, and global variable updates are not synchronized to workflow nodes. Cause: The global variable initialization configuration is not correctly bound to the workflow start node, or the variable scope is set incorrectly, resulting in parameters not being passed.
- Phenomenon: The workflow reports an error directly after starting, and does not enter the tool calling link. Cause: The workflow trigger event is not correctly configured, or the connected third-party API authentication parameters are filled incorrectly, resulting in failure of the pre-request.

## How to Verify Correct Configuration
- Trigger a simulated urban management case submission, check whether the workflow automatically starts and calls the preset tool node.
- Check the tool calling log to confirm that the returned fields include core law enforcement-related information such as inspection locations and problem types.
- Adjust the preset values of global variables, verify whether the variables in the workflow node are synchronously updated to the new configuration values.
- Simulate a third-party API timeout scenario, confirm whether the workflow triggers the preset exception handling logic such as retries or alerts.
