# Business Process Guidance for Urban Environmental Sanitation and Urban Management Law Enforcement Cases: Forms and Interactions

## What this category’s data looks like
Data for this category primarily originates from urban management law enforcement platforms, urban operation grid platforms, video surveillance systems, and public complaint work orders. Update frequency is daily. Associated daily documents include inspection records, case filing approval forms, on-site photos, rectification notices, penalty decisions, and case closure reports. Core fields cover case numbers, violation locations, responsible parties, violation types, rectification requirements, and additional relevant items. Entry and storage requirements for multiple document types must be supported.

## Constraints on forms and interactions
Diverse data sources with daily updates require form interactions to support rapid entry and real-time validation for multi-channel data. Rich associated document types require forms to support attachment uploads and combined entry of multiple fields. On-site evidence positioning and violation type judgment are the most time-consuming steps, so forms must preconfigure common options to reduce independent judgment costs. Data errors can lead to law enforcement disputes or administrative reconsideration, so forms must set required fields and real-time validation rules to ensure accuracy and compliance of entered data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `formInput` | Preconfigure 10-15 core fields including case number, violation location, and responsible party, calibrated based on actual testing | Match standard entry items for urban management law enforcement cases, reduce errors from free-form input |
| `userSelect` | Preconfigure 12-18 violation type options covering common scenarios such as unauthorized street vending, unauthorized debris stacking, damage to urban environmental sanitation facilities, etc., calibrated based on actual testing | Cover main violation types identified in daily inspections, reduce law enforcement staff’s independent judgment costs |
| Single conversation prompt count | 1 | Avoid repeated prompts disrupting law enforcement staff’s entry process |
| Attachment upload limit | 5 files per single record | Adapt to daily needs for submitting multiple documents such as on-site photos and rectification documents |
| Field validation rules | Enable real-time format validation for case number and violation location fields | Ensure entered data complies with field specifications of urban management law enforcement platforms, reduce subsequent data synchronization issues |

## Three Common Configuration Errors
- Symptom: Trigger count is not limited when configuring `userSelect`, resulting in repeated prompt requests during conversations that reduce entry efficiency. Cause: Interaction trigger logic is not configured correctly, and the usage habit of one prompt per conversation is not followed.
- Symptom: Submitted case attachments cannot be synchronized to the law enforcement platform, and the system prompts a format error. Cause: Upload validation rules adapted to urban management law enforcement document formats are not set, resulting in incompatible files being blocked.
- Symptom: Background knowledge retrieved by the large language model includes irrelevant data from non-current cases, interfering with violation type judgment. Cause: The scope of context retrieval is not limited, resulting in cross-category data being included as reference.
