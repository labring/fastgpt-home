# Business Process Guidance for Construction Engineering Quality and Safety Supervision: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Core data for this category comes from the engineering quality and safety supervision system, on-site construction real-name management platform, supervision logs, and test reports. The update frequency is weekly.
Daily business documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Document structures include fields such as project identification, supervision subject information, inspection items, rectification requirements, and completion status. Data circulates across the entire process of on-site construction quality and safety supervision.

## Constraints for Multi-turn Dialogue and Prompt Words
Support regular context refreshing for weekly updated data sources. This prevents referencing expired rectification completion status or latest inspection records.
Clearly distinguish applicable scenarios for different document types in prompt words. This avoids confusion between the field logic of hidden danger rectification notices and completion acceptance supervision reports, as multiple business documents circulate in mixed workflows.
Enable associated retrieval of real-time on-site inspection information for project sites. This matches the on-site attributes of construction data.
Limit historical dialogue context length. This prevents model output deviations caused by excessive redundant records.
Specify data call priorities in prompt words. This ensures returned information complies with housing and urban-rural development quality and safety supervision station business specifications, as data sources cover multiple platforms.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum context length | 800–1200 characters | Adapts to the average length of multiple business document types, and complies with the context processing limit of FastGPT v4.17.0 |
| Question optimization switch | Enabled | Optimizes semantic understanding of user questions for mixed document workflows, reducing ambiguity |
| Dialogue history storage duration | 7 days | Matches the weekly update frequency of data sources, ensuring dialogue context stays synchronized with latest data |
| `variables` binding rules | Bind project ID, inspection date | Retrieves project-specific data from the engineering quality and safety supervision system, improving query accuracy |
| Maximum dialogue turns per session | Previous 5 rounds of history | Limits redundant historical input, preventing model interference from excessive old records |
| `chatId` identification rules | Generate using project + supervision batch | Distinguishes dialogue contexts across different projects, avoiding cross-project data confusion |
| Dialogue history call field | Call the `messages` field | Complies with FastGPT's standard dialogue history call format, ensuring correct context reading |

## Three Common Configuration Errors
- Symbols for tracing display rules appear at the end of dialogue. This occurs when the rule tracing switch in prompt words is not disabled, causing the model to forcibly attach system preset display logic.
- Empty results are returned during high-concurrency calls. This happens when the dialogue concurrency threshold is not adjusted. Insufficient system resources cannot support requests under high concurrency, leading to call failures.
- Multi-turn dialogue context is overwritten across projects. This results from incorrect configuration of `chatId` generation rules, leading to mixed dialogue contexts between different projects.

## How to Verify Correct Configuration
- Initiate a multi-turn dialogue for a single project. Confirm returned document information matches the project’s supervision plan and inspection records.
- Adjust the number of dialogue turns. Verify that context is truncated per the set maximum length, and does not exceed the preset turn limit.
- Initiate multiple concurrent requests. Observe for empty results or timeouts, then adjust concurrency configuration to meet business needs.
- Wait 7 days and check dialogue history. Confirm old records are automatically cleaned up or archived.
