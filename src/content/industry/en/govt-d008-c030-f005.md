# Business Process Guidance for Construction Engineering Quality and Safety Supervision: Tool Calling and Plugins

## What the data for this category looks like
Data for this category mainly comes from engineering quality and safety supervision systems, on-site real-name management platforms, supervision logs, and test reports. The update frequency is weekly. Daily generated documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports.
Each document contains on-site verification data for the corresponding business link, rectification closed-loop requirements, and acceptance judgment fields. There are no extra custom statistical fields. The data structure is tightly bound to the business process.

## What constraints do these characteristics impose on the tool calling and plugins link
Dispersed data sources require tool calling to support multi-source plugin linkage, to pull business data from different systems separately.
The weekly update rhythm means tool triggering must match the weekly business processing cycle, to avoid high-frequency invalid calls.
The fixed document field structure requires plugin parameters to adapt to preset field extraction, with no need for extra adaptation to custom fields.
For the most time-consuming links of checking materials and tracking rectification closed-loop, tools must support batch pulling of inspection records and automatic verification of rectification status, to reduce manual repetitive operations.
Severe error consequences require adding a result verification link to tool calling, to prevent incorrect data from entering the business process.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to dynamic calling needs for multi-source data pulling, automatically matches field extraction logic for different business documents |
| Single tool call limit | Top 3 entries | Matches the regular number of single-category business documents updated weekly, avoids overload from single calls |
| Tool call timeout period | 120 seconds | Adapts to network latency for cross-system data pulling, ensures complete acquisition of multi-source data |
| Context window size | 8000 token | Matches the content length of a single completion acceptance supervision report, ensures complete information is passed to the model |
| Plugin trigger timing | Within 10 minutes after process starts | Matches the pre-process data preparation link of business handling, avoids excessive waiting that affects process efficiency |

## Three common configuration errors
- The plugin editing page always displays "Unsaved" status, even after clicking the save button. The cause is that the auto-save trigger logic for the plugin is not configured correctly, leading to front-end status not syncing to back-end storage.
- A `connect ECONNREFUSED 172.23.0.2:3001` error occurs during tool calling. The cause is that the target service address configured in the plugin is not running normally, or network policies block port access.
- The number of results returned by tool calling does not match the regular number of weekly business documents. The cause is that the single tool call limit is not set correctly, leading to exceeding the threshold for regular business document quantities.

- Check the fields returned by tool calling, confirm that they fully match the preset fields of documents in this category such as supervision plans and hidden danger rectification notices.
