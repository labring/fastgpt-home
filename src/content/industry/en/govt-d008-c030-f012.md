# Workflow Guidance for Construction Engineering Quality and Safety Supervision: Deployment and Upgrade

## What Data for This Category Looks Like
This category of data supports business processes for housing and urban-rural development quality and safety oversight stations, construction units, supervision units, and project owners. Daily business documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Data sources include the engineering quality and safety supervision system, construction site real-name platform, supervision logs, and test reports. The update frequency is weekly. Data fields are configured around core workflows such as on-site quality and safety inspections, hidden danger rectification closure, and completion acceptance condition verification. Only original business data for matching business scenarios is linked, with no additional processed statistical content.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Multiple data sources including the engineering quality and safety supervision system, construction site real-name platform, and other business systems and collected data require deployment to adapt to multi-source data access formats and permission verification rules. The weekly update frequency requires that deployed incremental synchronization tasks match this rhythm, to avoid excessive synchronization occupying resources. The need to parse multiple types of business documents requires configuring preprocessing rules for corresponding documents during deployment. Since business errors lead to quality safety accidents or acceptance suspension, high availability configuration must be enabled during deployment. Upgrade operations must retain consistency verification logic for historical data to avoid data loss or exceptions. Additionally, the business feature centered on on-site supervision requires retrieval logic to link the corresponding relationship between on-site points and business links.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://redis:6379/0` (local deployment) or `redis://<cloud Redis instance address>:6379/0` | The update frequency of this category's business data is weekly. Redis is used as cache and session storage. The default port 6379 ensures basic connection stability. Database index 0 is used to isolate business cache from other data. |
| `MONGODB_URI` | `mongodb://<mongodb-host>:27017/fastgpt` | The number of category business documents grows with project progress. Use MongoDB to store unstructured business documents. The default port 27017 is used, and specifying the database name as fastgpt isolates business data from other system data. |
| `DB_MAX_LINK` | `20–30 connections` | Weekly data sync tasks require stable database connection counts. This value balances connection usage and concurrent processing capability, calibrated based on actual testing. |
| `FILE_TOKEN_KEY` | Custom 32-character random string | Used to generate access tokens for business documents, ensuring access security for sensitive documents such as hidden danger rectification notices and completion acceptance supervision reports. |
| `STORAGE_S3_ENDPOINT` | Fill in according to the endpoint provided by the cloud storage service provider | Used to store large files such as test reports and completion acceptance supervision reports, matching the storage requirements of category business documents. |

## Three Common Configuration Errors
- Phenomenon: `pull access denied for redis` or image pull timeout error occurs when executing `docker compose up`, and the log shows that the specified image cannot be pulled. Cause: The redis image source in `docker-compose.yml` is not configured correctly. When using Alibaba Cloud mirror, the correct image repository address prefix is not added.
- Phenomenon: Database connection timeout occurs when executing business data sync tasks, with status code 500 returned. Cause: The value of `DB_MAX_LINK` exceeds the maximum connection limit of the database server, and does not match the concurrent requirements of the category business.
- Phenomenon: The FastGPT root account password of the local deployment automatically resets to 123456 approximately every 1 day. Cause: The persistent storage of `ROOT_KEY` is not configured correctly. The key is not mounted to a persistent volume during deployment, so the key resets after each restart, triggering the default password logic.

## How to Confirm Proper Configuration
- Execute the `docker compose ps` command to confirm that the status of dependent containers such as redis and mongodb is Up.
- Upload a test supervision inspection record document to verify that the document can be parsed normally and stored to the specified storage path.
- Restart the service after modifying the root account related configuration, confirm that the configuration parameters take effect persistently, and no automatic reset occurs.
- Trigger an incremental data sync task, check the sync log to confirm that the task completes execution according to the preset rhythm.

The values provided are common starting points and should be measured against the reader's own samples.
