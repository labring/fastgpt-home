# Business Process Guidance for Construction Project Environmental Impact Assessment Approval: Vector Models and Indexes

## What this category’s data looks like
Data for this category comes from four official sources: the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data.
Daily documents include environmental impact assessment report books, report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approvals. Their structure covers modules such as basic project information, pollution analysis, prevention and control measures, and approval opinions. Standardized fields including project code, EIA level, and approval document number are included.
Data update frequency is irregular. Content is dynamically added or modified alongside construction project declaration and approval progress.

## Constraints imposed on vector models and indexes
Multi-source heterogeneous data sources require indexes to support unified vectorization and retrieval of cross-system data. This prevents retrieval deviation caused by fragmented data sources.
Document lengths vary widely. Some reports contain thousands of characters, while approval documents contain hundreds. Chunking strategies must balance semantic completeness for long documents and information concentration for short documents.
Core matching items for EIA approval include precise fields such as project category and EIA level. Indexes must prioritize linking to these high-weight information items. They must also filter non-EIA cross-source data to prevent irrelevant content from being returned.
Irregular updates require indexes to support incremental synchronization. This avoids performance losses caused by full index reconstruction.

| Overlap Length | 100–200 characters | Retains core fields such as project code and EIA level across chunks, ensures semantic coherence during retrieval |

| `maxToken` | 16000 | Supports integrating complete context from multiple technical assessment opinions and approval documents |

## Three common configuration mistakes
- Search returns content unrelated to EIA. The interface displays retrieved results including irrelevant entries from pollution discharge permit or monitoring data sources. This occurs because index filtering rules for exclusive EIA data sources are not configured, and non-EIA cross-source data is not excluded.
- Index is not ready to trigger retrieval. The interface permanently displays the index building status. This occurs because reasonable incremental update trigger rules are not set, full index shard loading is not completed, or automatic synchronization logic for data sources is not configured.
- Directly uses full table columns as index sources. Search results contain large amounts of redundant information from non-core fields. This occurs because high-weight fields such as project category and EIA level are not extracted as index keywords, and irrelevant non-business fields are not filtered.

## How to confirm correct configuration
- Upload one EIA report form and one non-EIA document. Test searching for questions related to "construction project EIA approval process". Confirm that only EIA-related content is returned.
- View the FastGPT index status interface. Confirm that the status is ready, with no shard failure or timeout error prompts.
- Adjust the similarity threshold. Test retrieval requests with different precision requirements. Confirm that the matching degree of retrieved results meets business expectations.
- Upload an updated approval application document. Confirm that the index completes incremental synchronization automatically, without requiring manual full index reconstruction.
