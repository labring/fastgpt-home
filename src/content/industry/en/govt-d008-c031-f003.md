# Business Process Guidance for Construction Project Environmental Impact Assessment (EIA) Approval: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Covers
This category covers documents generated by all parties involved in the full process of construction project EIA approval, including environmental impact assessment reports or report forms, approval applications, public participation statements, technical assessment opinions, EIA approval replies, and more. Data sources include the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Updates are released on an irregular basis. Data fields include project category, EIA level, pollution prevention measures, public participation status, and other items, which are strongly tied to the pre-commissioning approval links for construction projects.

## Constraints on Multi-turn Dialogue and Prompt Engineering
The data sources for this category are scattered, and updates follow no fixed cycle. Multi-turn dialogue processes must be able to dynamically call the latest ecological environment zoning control, monitoring, and other system data. Document structures differ noticeably across scenarios, so prompts must adapt to field extraction logic for different document types including environmental impact assessment reports and report forms. Verifying project category and EIA level is a core time-consuming step. Multi-turn dialogue must guide users to supplement basic project information step by step to avoid overloading single input submissions. Approval errors have serious consequences, so dialogue processes must embed compliance verification logic. This logic must match compliance requirements of data sources in real time to prevent incorrect submissions that lead to subsequent accountability.

## Configuration Settings

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Conversation ID binding rule | Bind the project declaration number as `chatId` | Match the project number from the national unified construction project EIA declaration system to bind conversations to specific approval projects |
| Maximum retained rounds of conversation history | 8–12 previous rounds | The EIA approval process includes multiple links. Excessive history will consume computing resources, while insufficient history will lose key approval information |
| `variables` initialization | Preset project category, EIA type fields | Match the core verification fields for EIA approval to reduce repeated input of basic information by users |
| `messages` system prompt template | Guide users to upload documents and supplement project information step by step | Adapt to the step-by-step processing logic of EIA approval, lowering the operational threshold for non-technical users |
| Conversation timeout threshold | 600 seconds | Uploading and parsing EIA-related documents takes a long time, so reserve sufficient time for data loading and verification |
| Tool call output rule | Hide tool call logs | Avoid technical terms in the approval process interfering with reviewers’ reading, and focus on content related to approval |

## Three Common Mistakes
- Phenomenon: Unparsed tool call logs appear in dialogue response results, interfering with reviewers’ reading. Cause: The output hiding rule for tool calls is not configured correctly, and no filtering prompt is added to the `messages` template.
- Phenomenon: The latest ecological environment zoning control data cannot be retrieved during multi-turn dialogue, leading to incorrect verification of project categories. Cause: No dynamic data call logic is set up, only static knowledge base data is used, and no real-time interface of the national unified construction project EIA declaration system is connected.
- Phenomenon: Chinese and English bilingual dialogue opening lines cannot be configured in the same workflow. Cause: The `messages` template is not split for different usage scenarios, and no language parameter is bound via `variables` to enable switching.

## How to Verify Successful Configuration
- Launch a simulated dialogue, input basic project information, and check whether the dialogue guides the supplement of EIA-related fields according to preset steps.
- Upload a test environmental impact assessment report form document, and confirm that the dialogue can correctly extract the preset core field content.
- Trigger a tool call action, and check whether the returned results only contain approval-related content with no tool call logs.
- Adjust the preset field values in `variables`, and confirm that the dialogue process can call updated parameter content in real time.
