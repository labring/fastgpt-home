# Business Process Guidance for Construction Project Environmental Impact Assessment (EIA) Approval: Tool Calling and Plugins

## What this category of data looks like
This category of data is sourced from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and environmental monitoring data.
Daily processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents. Most documents are multi-chapter compliance texts, with fields such as project category, EIA level, pollution prevention measures, and public participation status.
Data updates follow no fixed cycle, and are synchronized with project declaration and approval progress.

## Constraints imposed on the tool calling and plugins workflow
This category of data has scattered sources and no fixed update rhythm. Tool calling must support connecting to multiple external system interfaces to obtain real-time declaration, control, and monitoring data.
Daily processed documents have complex structures and inconsistent field standardization. Plugins must adapt to parsing and field extraction for EIA documents of different formats.
Approval errors for projects have serious consequences. Tool calling workflows must include built-in parameter verification and failure retry logic to prevent approval process disruptions caused by data errors.
Additionally, the fields returned by tool calls must strictly match the core fields required for EIA approval, to avoid irrelevant information interfering with approval judgments.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the variable tool calling scenarios in EIA approval, no need to manually specify specific tools |
| `functionCall` | `enabled` | Enables tool calling capabilities, supports obtaining cross-system EIA-related data |
| Plugin timeout threshold | `600 seconds` | EIA data requires queries across multiple systems, which takes a long time; prevents process interruption due to timeout |
| Plugin retry count | `2 times` | Addresses temporary network fluctuations or interface response delays, reduces the probability of call failures |
| Number of items returned per tool call | Top 5 items | Avoids excessive redundant data affecting model processing efficiency, focuses on core EIA data |
| Tool return field filter | Retain project category, EIA level, and pollution prevention measures fields | Only extracts core data required for EIA approval, reduces interference from irrelevant information |
| Context window length | `8000 token` | Adapts to the processing needs of long texts such as EIA reports, retains complete approval-related context |

This document applies to FastGPT v4.17.0.

## Three common configuration errors
- A plugin call returns a 402 status code, and the interface prompts insufficient balance. The cause is that the API key quota verification logic for external plugins is not configured correctly. When the preset call quota is exceeded, no automatic retry or alert mechanism is triggered.
- Tool call returns empty fields, and the log shows no matching data. The cause is that the field naming rules for EIA documents are not adapted, and the extraction rules do not match the actual document structure.
- Tool call times out, and the system pops up a request timeout prompt. The cause is that the plugin timeout threshold is set too short, which cannot cover the time required to obtain EIA declaration and zoning control data across systems.

## How to verify correct configuration
- A manual tool call may be triggered, and returned data can be checked for core fields such as project category and EIA level.
- Cross-system interface call delays may be simulated, and the preset retry mechanism can be verified for activation.
- System configuration logs may be viewed, and the `toolChoice` and `functionCall` parameters can be confirmed to have taken effect per the set values.
- Test EIA application data may be submitted, and the format of tool call return results can be checked against approval requirements.

The values provided here are common starting points, and should be evaluated against applicable local samples.
