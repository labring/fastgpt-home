# Business Process Guidance for Construction Project Environmental Impact Assessment (EIA) Approval: Forms and Interactions

## What this category of data looks like
Data for this category comes from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permission platform, and monitoring data. Update frequency is irregular. Daily documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents. The document structure mainly uses structured fields paired with large blocks of descriptive text. Fields cover project category, EIA level, pollution prevention measures, public participation status, and similar items. There are no unified fixed units, and some fields need to match regional ecological environment control requirements.

## Constraints imposed by these characteristics on the "forms and interactions" link
Multi-source and irregularly updated data sources require form interactions to support automatic verification and associated filling of multi-source data. The mixed structure of structured fields and large blocks of text requires forms to support segmented input and format verification rules. Fields that need to match regional ecological environment control requirements require built-in basic verification logic in the interaction link to prevent submission of non-compliant content for zoning control. Differences in responsibilities and authorities across different entities require forms to support role permission division, restricting editing and viewing scopes for different accounts. Moving the most time-consuming verification link to the filling stage requires forms to include built-in matching verification between project category and EIA level, reducing manual effort for subsequent review.

## Three common configuration errors
- A `failed to create post` error appears when uploading EIA-related text datasets. This occurs because multi-source data association rules are not configured correctly, causing the form verification logic to fail to match the data source format of the national unified EIA declaration system.
- Speech input interaction for the form cannot be triggered in the browser. This occurs because FastGPT speech input adaptation configuration is not enabled, and the currently used FastGPT version is lower than v4.17.0.
- Knowledge base retrieval time increases noticeably. This occurs because the input character length limit for the `formInput` component is not set, causing large sections of EIA report text to be excessively loaded into the context window.

## How to verify successful configuration
- Submit a test EIA project information filling request, and confirm that the form triggers preset field verification logic.
- Switch between preset role accounts to verify that permission division for components aligns with responsibility and authority requirements for different entities.
- Upload an EIA-related text file to confirm that no error prompts appear during dataset creation.
- Initiate a test query for EIA approval, and confirm that the matching degree of retrieval results meets business expectations.

All configuration values listed are common starting points. Adjustments should be made based on specific samples and operational requirements.
