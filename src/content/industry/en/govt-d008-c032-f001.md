# Business Process Guidance for Investment Project Approval and Post-Evaluation: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data originates from the State-owned Assets Supervision and Administration Commission investment supervision system, enterprise ERP and project management systems, industry market data, audit and financial statements. Updates occur quarterly. Common associated documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset evaluation reports, and post-investment evaluation reports. Data fields include project unique identifiers, investment scale, project initiation approval nodes, post-evaluation indicators, and others. Data is stored in layers across the full project lifecycle, with distinct documents corresponding to data from specific business phases.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link?
The quarterly update frequency means interfaces do not require high-frequency calls. Scheduled synchronization tasks can be configured to reduce external system load. Multi-source data access requires unified authentication logic to adapt to authentication formats of different systems, preventing data synchronization failures due to authentication incompatibility. Access to multiple types of business documents requires interfaces to support filtering by document category and time range, to meet needs of different retrieval scenarios. Since data aligns with state-owned assets supervision requirements, interfaces must retain complete request and return logs to facilitate subsequent audit tracing.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {enterprise unified authentication token}` | Adapts to the unified authentication standard of state-owned assets systems, complies with data security requirements, and follows the FastGPT v4.17.0 interface specification |
| `variables` | `{"doc_type": ["project initiation report", "post-evaluation report"], "time_range": "last 1 quarter"}` | Matches the quarterly updated document categories and update rhythm of this category, narrows retrieval scope to improve accuracy |
| `responseData` | Return only project ID and associated document list | Streamlines returned content, reduces external system data processing load, and aligns with core data requirements of the business scenario |
| Single search limit | Top 10 entries | Matches the core project quantity requirement for single retrieval in this category, avoids returning excessive irrelevant data |
| Timeout period | 600 seconds | Large feasibility study reports take longer to retrieve and call interfaces, prevents task failure due to mid-process interruption |

## Three Common Misconfiguration Scenarios
- Symptom: The `responseData` field is empty after calling the interface. Cause: The document type and time range parameters corresponding to this category are not specified in `variables`, leading to a retrieval scope that does not match target business documents.
- Symptom: The interface returns a 401 Unauthorized status code. Cause: The `Authorization` format required by the state-owned assets system is not used, or the authentication token has expired and was not updated in a timely manner.
- Symptom: Documents inserted into the knowledge base cannot be retrieved via the retrieval interface. Cause: Documents are not synchronized in batches according to the quarterly update rhythm, or the `variables` parameter is not configured in the insert interface to associate the project unique identifier, leading to documents not being bound to the corresponding business scenario.

## How to Verify Correct Configuration
- Call the test interface, check if `responseData` includes expected project-related fields, and verify that the fields match the business document identifiers of this category.
- View interface logs, confirm that the `Authorization` parameter format complies with the authentication requirements of the external system, with no format errors.
- Insert a single standard document of this category, then use the retrieval interface to verify that it can be retrieved normally, and check that the `variables` parameter is effective.
- Simulate a quarterly data update scenario, call the batch synchronization interface, and check that the data received by the external system is consistent with the data from the source system.
