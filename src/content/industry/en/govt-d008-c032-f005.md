# Business Process Guidance for Investment Project Approval and Post-Evaluation: Tool Calling and Plugins

## What the data for this category looks like
Data sources for this category include State-owned Assets Supervision and Administration Commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. The update frequency is quarterly.
Commonly processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Most document structures contain fields such as basic project information, feasibility study calculation data, post-investment operation indicators, and approval node records. There is no fixed unified format, so adaptation to multi-source heterogeneous business document structures is required.

## What constraints do these characteristics impose on the tool calling and plugins workflow
The multi-source heterogeneous document structure of this category requires tool calling to adapt to interface formats and data fields of different systems, and avoid hard-coding fixed parsing rules.
The quarterly update data frequency means tool calling does not need a high-frequency trigger schedule. Trigger calls according to business nodes instead.
Business data related to state-owned assets requires additional compliance verification. Tool plugins must include basic compliance verification logic.
Post-investment data collection takes a long time, so tool calling must support incremental pulling of historical post-investment data to reduce repetitive manual organization work.
At the same time, configure `toolChoice` to trigger according to business nodes, and enable `functionCall` to ensure structured data is returned. This adapts to the standardized field mapping requirements of investment project documents.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | Trigger according to business nodes, such as approval feasibility study check, post-investment data summary | Adapt to the requirement of triggering tool calling according to business process nodes for this category, and avoid invalid calls |
| `functionCall` | Enable structured output mode | Ensure that fields returned by tool calling can be directly mapped to standardized fields of investment project documents |
| Retry count | 3 times | Address occasional fluctuations in state-owned assets supervision system interfaces, balance call success rate and overall time consumption |
| Timeout period | 600 seconds | Adapt to the time consumption requirements of multi-source data pulling and complex feasibility study analysis |
| Data pulling scope | Business data from the last 3 quarters | Match the quarterly update data frequency of this category, avoid redundant data loading |
| Compliance verification switch | Enable | Perform basic compliance verification on state-owned assets-related data returned by calls, comply with the compliance plugin configuration specifications of FastGPT v4.17.0 |

## Three Common Misconfigurations
- Custom parameters cannot be passed to the HTTP request component during plugin calling, and the `Request failed` error is returned. Cause: Parameters are not mapped to the HTTP request body or request header, so the target interface cannot recognize the incoming business fields.
- The result of tool calling still appears in the conversation interface and is not hidden as expected. Cause: The output truncation rule after tool calling is not configured correctly, or the end node is not bound to the correct branch of the tool calling chain.
- Pulled post-investment data fields do not match expectations, with missing fields or format errors. Cause: The heterogeneous data structures of multi-source systems are not adapted, and fixed field mapping rules are hard-coded, causing fields from some systems to fail to match correctly.

## How to Confirm the Configuration Is Properly Set
- Trigger a tool calling during the project approval phase, use the FastGPT v4.17.0 debugging tool to view HTTP request logs, and confirm that correct business parameters are included.
- View the tool calling return result, confirm that the returned fields match the standardized fields of investment project documents.
- Simulate an interface fluctuation scenario, check whether the tool automatically retries according to the configured retry count and returns to normal operation.
- Trigger test data containing non-compliant fields, confirm that the compliance verification switch intercepts the data and generates corresponding prompts when enabled.
