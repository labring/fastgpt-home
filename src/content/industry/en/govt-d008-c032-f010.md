# Business Process Guidance for Investment Project Approval and Post-Evaluation: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category comes primarily from the state-owned asset supervision and administration investment supervision system, enterprise ERP and project management systems, industry market data, and audit and financial statements. Data is updated quarterly. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Content covers project approval nodes, investment calculation parameters, post-evaluation quantitative indicators, and related information. Fields include project number, investment scale, construction period, evaluation score, and others. Units include ten thousand yuan, year, percentage, and similar units.

## What constraints do these characteristics impose on the knowledge base retrieval and recall workflow
Quarterly data updates require retrieval and recall workflows to support incremental synchronization, avoiding resource overhead from full database scans. The mixed structure of multiple document types requires support for cross-document field association recall, such as matching financial calculation data from feasibility study reports against actual completion indicators in post-investment evaluation reports. Documents related to state-owned asset supervision contain sensitive content, so recall results must strictly limit access scope and filter non-investment unrelated documents. Individual documents are lengthy, so recalled segment lengths must be controlled appropriately to avoid exceeding context window limits. Keywords tied to business workflows including project approval, investment decision-making, and post-evaluation must be matched accurately.

## How to configure the settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Adapt to the density of professional terminology in state-owned asset investment documents, balance retrieval precision and coverage, calibrated based on actual testing |
| `limit` | 8 entries | Match the multi-document reference requirement of investment review meeting materials, avoid excessive redundant content occupying context space |
| `searchMode` | `vector` | Prioritize semantic matching of professional terminology, adapt to long-text scenarios of feasibility study and post-evaluation reports |
| `usingReRank` | Enabled | Perform secondary ranking on recall results, correct deviations from single vector matching, and improve the ranking priority of highly relevant documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Expand relevant business keywords based on user questions, for example, associating "project approval" with "project proposal" and "feasibility study report" to cover more relevant documents |
| `collectionIds` | Bind to investment project-specific collections | Limit retrieval scope to exclusive collections such as annual investment plans and project documents, avoid mixing in non-investment data |

## Three Common Misconfigurations
- Symptom: When asked to repeat the content of an uploaded XLSX-format project data file during a conversation, a prompt indicating that the file cannot be read is returned. Cause: The extended retrieval configuration for table files is not enabled, or the collection ID of the table dataset is not correctly associated.
- Symptom: Retrieval results only return a small number of document fragments and do not cover the complete core data of project post-evaluation. Cause: The `similarity` threshold is set too high, filtering out relevant but low-match critical document fragments.
- Symptom: When building a knowledge base using an exported dataset.csv file, business data cannot be imported correctly. Cause: The template format exported from the dataset is mistakenly used as available data, and the correct original business file upload process is not followed.

## How to Verify Correct Configuration
- Upload a test feasibility study report, initiate a query containing "financial calculation parameters", and check whether the returned results include relevant content fragments from this document.
- View retrieval records to confirm that the scope of recalled documents only covers investment project-specific collections.
- Initiate a query containing business terminology, confirm that the ranking of results is more aligned with business relevance after `usingReRank` is enabled.
- Test the extended query configuration to confirm that retrieval results cover more relevant associated documents.

The values provided are common starting points and should be measured against the reader's own samples.
