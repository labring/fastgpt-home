# Business Handling Process Guidance for Investment Project Approval and Post-Evaluation: Deployment and Upgrade

## What data for this category looks like
Data for this category originates from the State-owned Assets Supervision and Administration Commission investment supervision system, enterprise ERP and project management systems, industry market data, audit and financial statements. Standard processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data updates occur quarterly. Fields cover project approval review, investment decision meeting minutes, post-launch operation data and additional relevant dimensions. The data exists as a multi-source heterogeneous mixed format, with two core content types: structured tables and unstructured documents.

## What constraints these characteristics impose on the deployment and upgrade phase
Multi-source heterogeneous data sources require support for multiple database connections and fine-grained permission isolation during deployment. The quarterly update frequency requires adaptive parameters for scheduled synchronization tasks to ensure timeliness and consistency of data updates. Coverage of multiple document types including reports, tables and structured data requires storage and index configurations compatible with multiple formats. Data involves state-owned asset-related content, so deployment environments must comply with internal network isolation and permission control compliance requirements. During upgrades, consistency of existing project data must be maintained to prevent historical document index failure from version updates. Deployments must also adapt to interface changes from existing connected systems.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `DB_MAX_LINK` | `10–15 concurrent connections` | Adapts to concurrent demands of multi-system data synchronization and multi-document indexing, prevents database connection overflow |
| `MONGODB_URI` | Internal MongoDB instance address for enterprise use | Meets compliance requirements for internal storage and access of state-owned data, prevents data leaks |
| `REDIS_URL` | `Internal Redis instance on port 6379` | Caches session information and retrieval results, improves response speed of business handling process guidance |
| `STORAGE_S3_ENDPOINT` | Internal endpoint of enterprise-built object storage | Stores project documents and appraisal reports, complies with state-owned asset data storage specifications |
| `FILE_TOKEN_KEY` | Calibrated via actual testing | Controls access permissions for project documents, prevents unauthorized access to sensitive data |
| `FE_DOMAIN` | Internal access domain name for enterprise use | Configures frontend access address, ensures normal access and permission verification for internal users |

## Three common mistakes
- The symptom is a database connection failure prompt during service startup, with status code `ECONNREFUSED`. The cause is incorrect configuration of `MONGODB_URI` pointing to a database instance that is not running or has insufficient permissions.
- The symptom is timeout interruption during bulk import of quarterly updated project data. The cause is failure to adjust the concurrent connection count for `DB_MAX_LINK`, exceeding the maximum connection limit of the database.
- The symptom is failure of the startup script execution during non-Docker deployment, with a prompt indicating missing Node.js runtime dependencies. The cause is failure to complete basic environment installation and configuration per official documentation.
