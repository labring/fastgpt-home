# Business Process Guidance for Tendering and Procurement Compliance Management: Workflow Orchestration

## What this category of data looks like
This category of data originates from enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases, with daily updates. Daily associated documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials. Data fields cover procurement methods, budget basis, scoring methods, supplier qualification requirements, performance acceptance standards, and other relevant content. It must adapt to internal regulations of central state-owned enterprises and group centralized procurement rules, while meeting state-owned asset supervision requirements.

## Constraints Imposed on Workflow Orchestration
Data sources are scattered and updated daily. Workflows must support connecting to multiple system interfaces to pull real-time data, avoiding manual entry errors in procurement information. Document types are diverse with significant field differences. Workflows must configure multiple components to adapt to parsing and verification logic for different documents. Compliance requirements for state-owned enterprises are strict. Workflows must embed verification nodes from the audit issue database to pre-block compliance risks in the procurement link. The most time-consuming verification links must be completed via workflow automation, while retaining traceable node logs for internal audits and external inspections.

## Configuration Settings
| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| Global variable configuration | Include procurement budget, supplier database list, audit risk rules and other `variables` | Adapt to multi-scenario verification, ensure core business data can be called in real time during the process |
| Node ID binding | Bind a unique `nodeId` for each verification node | Facilitate log traceability and anomaly location, meet audit traceability requirements |
| Data pull trigger timing | Trigger full synchronization at 0:00 daily, trigger incremental pull 10 minutes before node execution | Match the daily data update frequency, balance real-time performance and system load |
| Verification node threshold | Calibrate based on actual testing, cover procurement method matching, qualification review, scoring method verification | Adapt to the multi-dimensional compliance verification needs of this category |
| Exception alert configuration | Push to the connected discipline inspection and audit system within 5 minutes after triggering | Meet the requirements of state-owned enterprises for rapid response to compliance risks |
| Workflow export | Support storage in standardized formats | Facilitate version management and cross-department collaboration |

## Three Common Mistakes
- Phenomenon: When modifying workflow component parameters, custom parameters fail to take effect, and configurations are lost after saving. Cause: The scope of custom parameters is not declared in `variables`, so the component cannot read the configuration content.
- Phenomenon: When clicking the data panel button to obtain global variables, empty values or uninitialized status are returned. Cause: The variable assignment node executes after the button trigger node, and the global variable assignment operation is not completed.
- Phenomenon: A "Dangerous behavior" error pops up when running a workflow in FastGPT v4.17.0. Cause: The workflow contains unauthorized cross-system call configurations, or node parameters have security risks that fail system verification.

## How to Confirm Proper Configuration
- Trigger the initial node of the workflow, verify that the latest data from the corresponding data source can be pulled as configured.
- Click the button component in the data panel, confirm that the assigned global variables can be obtained.
- Simulate non-compliant process instances, check whether the verification node can trigger interception actions.
- Export the workflow configuration, confirm that the exported file can be saved and shared normally.
