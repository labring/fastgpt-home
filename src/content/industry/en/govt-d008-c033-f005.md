# Business Process Guidance for Tendering and Procurement Compliance Management: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases. The update frequency is daily. Commonly used documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials. Data fields include procurement methods, budget basis, supplier qualification requirements, bid evaluation scores, performance acceptance status, and more. Some data is structured forms. Some data is unstructured text. Format varies based on business stage.

## What constraints these characteristics impose on tool calling and plugins
Daily updated multi-source data requires tool calling to support scheduled synchronization of cross-platform data sources. This prevents data lag from disrupting compliance verification. Multi-format business documents require plugins to support parsing of structured forms and unstructured text. This adapts to input types for different business stages. State-owned and public enterprise hierarchical management and audit rules require tool calling to bind permission checks. Only users from matching departments can call compliance verification plugins. Business attributes with severe error consequences require pre-verification steps for tool calls. This prevents invalid calls from creating compliance risks.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto`, specify compliance verification plugin ID | Automatically select tools matching the tendering and procurement compliance scenario, no manual intervention required |
| `functionCall` | Enabled, limit call scope to procurement compliance verification and data comparison tools | Avoid irrelevant tool calls disrupting compliance processes, focus on core business links |
| Tool call timeout | `120–180 seconds` | Cross-platform pulling of tendering and procurement data takes longer, prevents process interruption due to timeout |
| Maximum results per tool call return | `Top 10 entries` | Prevents redundant data from exceeding context window, improves tool calling efficiency |
| Plugin permission binding | Assign corresponding tool permissions based on the user's department | Aligns with state-owned and public enterprise hierarchical management and audit requirements, controls tool call scope |
| FastGPT version compatibility | FastGPT v4.17.0 | This version optimizes multi-plugin linkage and cross-data source call logic |

## Three common configuration errors
- Accidentally setting `toolChoice` to `none` during configuration. This prevents tool calls from triggering the compliance verification process. No tool call records appear in logs. Cause: No clear tool call strategy matching the tendering and procurement scenario is specified. Tools are not called by default.
- In FastGPT v4.17.0, the workflow panel does not show connection options for compliance verification tools. Cause: The exclusive plugin for this category was not enabled in the plugin marketplace in advance. Connection configuration items do not load.
- Not configuring the tool call timeout. This causes a 504 timeout error when pulling supplier database data across platforms. Cause: No reasonable timeout threshold is set based on the actual time required to pull tendering and procurement data.

## How to confirm configuration is complete
- Initiate a simulated tendering and procurement process request. Check the tool call log to confirm that the compliance verification plugin is triggered.
- Enter the workflow configuration panel. Verify that the `toolChoice` parameter is set to a value adapted to the tendering and procurement scenario.
- Test cross-data source pulling of procurement plan and contract data. Confirm that tool calls can return corresponding results normally.
- Switch to test accounts from different departments. Confirm that only authorized users can call compliance verification tools.

The values provided here are common starting points. They should be evaluated against individual deployment samples.
