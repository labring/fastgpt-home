# Business Process Guidance for Tendering and Procurement Compliance Management: Forms and Interactions

## What this category of data includes
This category of data covers the full procurement process for state-owned enterprises and local state-owned enterprises. Data sources include enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases. The update frequency is daily.

Daily processed documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials. Structured fields cover procurement methods, budget amount, supplier qualifications, scoring rules, and similar items. Units include ten thousand yuan, item, batch, and similar units. Field structures vary significantly across different documents. The system must support processing of both unstructured text and structured information.

## What constraints these characteristics impose on the forms and interactions link
Multiple data sources with daily updates require forms to support connection to multi-platform data sources and real-time synchronization of latest information. Diverse document types and field structures require compatibility with both unstructured file upload and structured field entry. Core data involves serious risks such as bid rigging and audit rectification, so input verification and permission control must be strengthened.

The most time-consuming compliance review link requires quick verification of core fields such as procurement methods, budget basis, and supplier qualifications. Therefore, forms must include high-frequency compliance check items to reduce manual repetitive operations.

| Maximum recall count | Top 8 entries | Compliance review needs to cover core associated data; too many entries will distract review attention |

## Three common misconfigurations
- Unstructured files such as uploaded bidding documents and bid evaluation records are not included in the compliance review process. Only structured field verification results are returned after form submission. Cause: Multi-file association parsing is not enabled in the `formInput` configuration, and only the structured input module is bound.
- Request timeout occurs when connecting to enterprise procurement platforms, with status code 504 returned. Cause: The timeout threshold is set too short, and does not match the actual time required for multi-data source pulling.
- Preset options for supplier qualification check items do not match actual business requirements, resulting in empty field errors. Cause: The option group configured in `userSelect` does not cover the unique supplier qualification review requirements of this category, and compliance rules for centralized group procurement have not been updated synchronously.

## How to verify correct configuration
- Upload a standard bidding document and structured procurement plan, check whether the form parses both unstructured text and structured fields.
- Trigger data pulling from the connected enterprise procurement platform, confirm that the time taken falls within the preset threshold range.
- Adjust the option group in `userSelect`, submit a procurement application with special qualification requirements, check whether the verification logic takes effect.
- Upload a compliance clause exceeding 1200 characters, check whether it is fully retained or truncated according to the configuration.
