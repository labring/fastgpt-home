# Business Process Guidance for Tendering and Procurement Compliance Management: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue repositories. The update frequency is daily. Daily documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials. Data fields cover procurement methods, budget basis, supplier qualification requirements, bid evaluation scoring standards, performance acceptance clauses, and more. Some documents include structured numbering and amount-related fields.

## What constraints these characteristics impose on the deployment and upgrade phase
Daily updated procurement and contract data requires a stable incremental synchronization mechanism to be configured during deployment. This avoids excessive system resource usage from full-volume data pulling.
Multi-source and heterogeneous compliance documents have significant structural differences. The upgrade process must support parsing rules for newly added bidding documents, bid evaluation records, and other templates.
Sensitive data such as supplier qualifications and audit rectification records requires permission-isolated storage nodes to be configured during deployment. This prevents unauthorized access.
The tendering and procurement process involves core enterprise business matters. The upgrade process must ensure controllable service downtime and complete, omission-free data migration.
Adapt to the version features of FastGPT v4.17.0. Storage and database expansion plans must be planned in advance before deployment.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 records per second` | Adapts to the default connection pool configuration of FastGPT v4.17.0, meets daily incremental procurement and contract data synchronization requirements, and avoids connection pool exhaustion |
| `STORAGE_S3_ENDPOINT` | Self-built enterprise object storage node address | Stores large-volume compliance documents such as bidding documents and bid evaluation records, ensures local data storage, and complies with enterprise data security requirements |
| `REDIS_URL` | Local private Redis instance address, configured with `600 seconds` expiration time | Caches frequently queried supplier qualification and procurement method rules, reduces database access pressure, and improves process guidance response speed |
| `FILE_TOKEN_KEY` | Key consistent with the enterprise's internal authentication system | Verifies the permissions of uploaded procurement documents, prevents unauthorized files from accessing the compliance management process guidance service |
| `FE_DOMAIN` | Internal enterprise tendering business system domain name | Configures front-end access whitelists, restricts external access, and ensures internal usage permissions for compliance management processes |

## Three common misconfigurations
- When uploading a PDF bidding document larger than 100MB, an "Offset out of range" error appears after the upload progress reaches 90%. This occurs because chunk upload rules optimized for large documents are not configured, resulting in offset errors during file fragment assembly.
- Frequent network errors occur during daily incremental procurement data synchronization. This is caused by inappropriate configuration of the `DB_MAX_LINK` value, leading to database connection pool exhaustion and failure to establish synchronization requests normally.
- The locally deployed Ollama model cannot be called normally after an upgrade. This is caused by failing to associate the correct `REDIS_URL` in the configuration, causing the session cache for model calls to fail to read and write properly.

## How to confirm the configuration is complete
- Upload a PDF bidding document larger than 100MB, confirm that the upload process has no errors and the file can be parsed normally.
- Manually trigger an incremental data synchronization task, check the system logs, and confirm that there are no database connection exception errors.
- Access the configured front-end domain name, confirm that the process guidance page for tendering and procurement compliance management can be accessed normally.
- Call the interface of the bound local Ollama model, confirm that normal compliance check return results can be obtained.
