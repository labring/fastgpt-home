# Business Process Guidance for Enrollment and Student Academic Status Management: Workflow Orchestration

## What the Data for This Category Looks Like
Data sources for this category include the national primary and secondary school student academic status information management system, local enrollment platforms, household registration and real estate data platforms, and school academic affairs systems. Update frequency is daily.
Daily processed documents include enrollment application forms, student academic status information forms, transfer applications, enrollment plans, admission rosters, and student academic status change approval forms.
Data fields cover student identity identifiers, household registration and real estate verification information, student academic status change records, enrollment plan quotas, and similar items. No additional custom statistical numeric fields are included.
This category centers on student identity and enrollment eligibility, focuses on services related to academic status transfer, and differs from student financial aid public service categories.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multi-source data integration requires workflows to support cross-system API calls and data aggregation, to ensure consistency of academic status, household registration, enrollment plan and other data.
The daily update rhythm requires workflows to be configured with incremental synchronization logic, to avoid full-volume repeated processing of historical data.
Approval document routing requires setting node-level approval trigger conditions, to ensure every status change or admission operation undergoes verification.
Long-duration household registration and real estate verification, student academic status change processing links must split workflow nodes to avoid single-execution timeout risks.
Unique data field requirements must be configured with duplicate verification logic, to prevent duplicate or missing student records.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Trigger Mode | Triggered upon form submission completion | Matches the business logic of starting a workflow after a user submits an application in the enrollment process |
| Timeout Setting | 600–1200 seconds | Covers the maximum execution duration of long-duration links such as household registration and real estate verification, student academic status change processing |
| `variables` | Bind fields from enrollment application forms and student academic status information forms | Enables automatic transfer of form data to workflow nodes, no manual entry required |
| `nodeId` | Bind the ID of the preceding approval node | Ensures links such as student academic status change and admission verification only start after preceding verification passes |
| Retry Strategy | Retry 2 times after failure, with a 120-second interval | Addresses temporary network fluctuations during cross-system calls, reduces the probability of single-execution failure |
| File Handling | Pass uploaded files as variables | Supports batch or single transfer of documents such as enrollment materials and real estate certificates |

## Three Common Misconfigurations
- Workflow execution returns status code 504 or displays execution timeout. The cause is failure to split long-duration nodes for household registration and real estate verification, student academic status change processing. Single execution duration exceeds system limits.
- Workflow nodes cannot read uploaded enrollment material files. The cause is failure to correctly bind the output parameters of the file upload component via `variables`.
- Workflow starts with empty form fields. The cause is setting the workflow to trigger upon form load completion, without limiting triggering to after form submission completion.

## How to Confirm Proper Configuration
- Simulate submitting a complete enrollment application form, check whether the workflow starts automatically after form submission completion.
- Upload enrollment materials or real estate certificate files, check whether the workflow `variables` include the file access path and metadata.
- Simulate a long-duration household registration verification link, check whether the workflow splits nodes for execution and does not trigger timeout alerts.
- Enter a duplicate student ID number, check whether the workflow triggers duplicate verification logic and blocks subsequent processes.
