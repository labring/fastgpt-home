# Business Process Guidance for Enrollment and Student Record Management: Document Parsing and Chunking

## What the data for this category looks like
This category covers end-to-end content related to enrollment and student record management. Data sources include the national primary and secondary school student record information management system, local enrollment platforms, household registration and property data, and school academic affairs systems. Updates occur daily. Commonly processed documents include enrollment application forms, student record information forms, transfer applications, enrollment plans, admission rosters, student record change approval forms, and more. These documents exist in two format categories: structured forms and unstructured policy texts. Core fields center on student identity, admission eligibility, and student record transfer status. No additional funding subsidy-related data is included.

## What constraints do these characteristics impose on the document parsing and chunking stage
The multi-source nature of category data requires document parsing to support export files in different formats, including structured table documents exported from systems, official PDF policy texts, and similar materials. Daily updated batch data requires parsing processes to have high processing efficiency, to avoid parsing delays that affect business process progress. The core fields focus on student identity and student record transfer, which requires the chunking stage to accurately retain single student information entries or single policy items, to avoid field breaks or information loss caused by incorrect splitting. Additionally, documents with a high proportion of structured forms require parsing tools to fully retain table formats, to prevent key data such as student record information and admission rosters from being incorrectly split.

## How to configure settings
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Category documents contain single student record information entries, enrollment policy items, and similar content. This length can fully cover core information units and avoid splitting breaks |
| `chunkSplitter` | `markdown+table` | Daily documents contain a large number of structured tables (student record information forms, admission rosters). This chunker can retain table structures and avoid chaotic field splitting |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Parsing batch student record data or multi-page enrollment plan documents requires a longer cycle. This interval can cover the complete processing flow |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Batch student record data exported from local enrollment platforms may contain multiple batches of student information. Larger file uploads must be supported |
| `customPdfParse` | Enabled | Official published PDF enrollment plans and transfer approval forms often contain redundant content such as headers and footers. Custom parsing can accurately extract core fields from forms |
| `chunkSettingMode` | Manual configuration | Category data has large format differences (structured tables, unstructured policy documents). Manual configuration allows flexible adjustment of chunking rules to adapt to different document types |

## Three common configuration mistakes
- Symptom: After uploading an Excel document with student record information, the returned result has misaligned table columns and scattered fields. Cause: `chunkSplitter` is not configured as `markdown+table`. The default chunker does not retain table structures, leading to incorrect splitting of structured data.
- Symptom: After calling the knowledge base creation interface, no parsing status feedback is obtained. Cause: The corresponding status query interface is not called, or parsing callback notifications are not configured, so real-time synchronization of parsing progress is not possible.
- Symptom: After uploading a PDF enrollment application form containing student ID photos, the parsed result does not include content associated with the images. Cause: Image recognition configuration is not enabled, or image extraction rules are not configured for `customPdfParse`, leading to loss of image information.

## How to confirm correct configuration
- Upload a single student record information form document, and check if the chunked result fully retains core fields without splitting breaks.
- Call the knowledge base creation interface, poll the parsing status query interface, and confirm that three types of status feedback are obtainable: parsing in progress, ready, and failed.
- Upload a batch enrollment plan PDF document, and check that parsing time meets expected requirements with no timeout errors.
- Test uploading an enrollment application form containing images, and confirm that the parsed result includes text descriptions or image content associated with the images.

The values provided are common starting points and should be measured against the reader's own samples.
