# Business Process Guidance for Pollution Discharge Permit Management: Document Parsing and Chunking

## What the data for this category looks like
The documents covered in this category include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, permit copies, and others. Data sources include the national pollution discharge permit management information platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems. Data is updated quarterly. Each individual document contains fixed business fields such as permit limits, monitoring periods, and emission boundaries. Some documents have structured tables and long text paragraphs, with common formats including PDF, Excel, and structured Word files.

## What constraints do these characteristics impose on the document parsing and chunking link
Diverse document types with fixed structures require retaining the integrity of core business fields such as permit limits and ledger numbers, to avoid breaking business logic due to chunking. Data from multiple sources has significant format differences, so adaptation to different parsing formats such as PDF layouts and Excel tables is needed. Large volumes of documents uploaded in quarterly batches require support for large-file parsing and batch processing. Business errors are directly linked to compliance supervision, so parsing accuracy must meet the basic requirements of compliance audits, and key information omission is unacceptable.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the information density of pollution discharge permit implementation reports and ledger records, avoid splitting core business fields such as permit limits and monitoring data |
| `chunkSplitter` | Separate by paragraph + heading + line break | Retain the chapter structure of application forms and implementation reports, ensure logical connections of business processes can still be reflected after chunking |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Meet the time consumption requirements for batch parsing large annual implementation report collections, avoid parsing interruptions due to timeouts |
| `customPdfParse` | Enabled | Adapt to the encrypted PDF format exported from the national pollution discharge permit management information platform, accurately extract fixed fields such as permit number and validity period |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Support batch upload requirements for quarterly ledgers and annual implementation report collections submitted by enterprises |

## Three common mistakes
- Phenomenon: After passing in a link, the parsing result only shows the link text with no document content. Cause: The `customPdfParse` configuration is not enabled, so the exclusive encrypted PDF format exported from the national pollution discharge permit management information platform cannot be recognized.
- Phenomenon: Unrendered Markdown tags appear in context references, and document formats cannot be displayed normally. Cause: The automatic format conversion switch during document parsing is not turned off, resulting in unprocessed format tags being retained during chunking.
- Phenomenon: After switching the vector model, the original chunked data cannot be indexed correctly. Cause: Documents are not re-parsed according to the original chunking configuration. Differences in chunking logic between models lead to mismatched chunk structures, making associated retrieval impossible.

## How to confirm the configuration is set correctly
- Use the document parsing tool of FastGPT v4.17.0, upload a single PDF of the pollution discharge permit application form, check if the parsed chunks include core fields such as permit number and issuing authority, with no split omissions or format errors.
- Upload a quarterly ledger collection that meets the `UPLOAD_FILE_MAX_SIZE` limit, confirm that the parsing process has no timeout errors and the progress completes normally.
- Before switching the vector model, re-parse all documents according to the current configuration, and verify after import that context references can correctly associate with corresponding business fields with no format abnormalities.
- Manually adjust `chunkSize` to different values within the range, upload an implementation report document, check that the complete permit limit table content is retained after chunking, with no fields split into different chunks.
