# Business Process Guidance for Pollution Discharge Permit Management: Model Access and Configuration

## What the data for this category looks like
This category's data primarily originates from the national pollution discharge permit management information platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems, with a quarterly update cycle. Daily processed documents include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data fields cover emission limits, monitoring frequencies, permit item change records, and similar content. There are no unified fixed units, so matching the measurement rules of corresponding business documents is required.

## What constraints these characteristics impose on the "model access and configuration" workflow
The scattered data sources, fixed update cycle, and diverse document types for this category impose three core constraints on model access and configuration. First, format differences across multi-system data sources are significant, so access logic adapted to multi-source data must be configured. Second, the quarterly update frequency requires the knowledge base synchronization cycle to align with the business rhythm, preventing data lag that impacts process guidance. Third, professional fields such as emission limits and permit change items have high rigor requirements, so the model's output rigor parameters must be adjusted.

## How to Configure Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the average length of pollution discharge permit-related documents, covering core content of multiple types of business documents such as application forms and implementation reports |
| `temperature` | `0.1–0.3` | Ensures the rigor of output for professional fields such as emission limits and permit items, avoiding content inconsistent with business specifications |

| `toolChoice` | `auto` | Allows the model to automatically select tools based on the needs of the business process, adapting to the guidance logic of multiple links |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed model service address | Connects to locally deployed large model services, ensuring compliant and stable data transmission paths |
| `AIPROXY_API_TOKEN` | Fill in according to the actually generated key | Ensures the security of identity verification for model access, preventing unauthorized access |

## Three Common Configuration Errors
- Phenomenon: When adding a model configuration with the same name, the original configuration is overwritten, and the ability to access multiple models cannot be retained. Cause: The model identifier is not distinguished according to FastGPT's configuration rules, and only the model name is used as the unique identification field.
- Phenomenon: The model output content includes the phrase "citation mark: [1]". Cause: The automatic splicing logic of knowledge base citation marks is not turned off, causing system marks to be mixed into the guidance text.
- Phenomenon: Data is not updated in a timely manner after the knowledge base is synchronized, affecting the accuracy of business process guidance. Cause: The knowledge base update cycle is not configured to match the quarterly update rhythm of business data, resulting in data lag.

## How to Verify Successful Configuration
- Check whether the model access address and key match the deployed service, and verify whether the basic connection is normal.
- Trigger a business process guidance test to check whether the output content does not include redundant citation marks.
- Manually trigger the knowledge base update, and check whether the number of updated documents matches the current business data volume.
- After adjusting the `temperature` parameter, verify that the output of professional fields remains rigorous with no obvious deviations.
