# Business Process Guidance for Government Service Item Catalog and Service Guide Maintenance: Workflow Orchestration

## What Data This Category Covers
This category maintains data sourced from the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases. Update frequency is monthly. Daily maintained documents include basic government service item catalog, implementation list, service guide, standard material directory, flow chart, and frequently asked questions. Data fields cover standardized item identifiers, acceptance conditions, application material lists, process nodes, and more. Some fields must match unified specifications from higher-level catalogs. Field units include terms compliant with government service standardization such as "link" and "item".

## What Constraints These Characteristics Impose on Workflow Orchestration
The monthly update frequency requires scheduled trigger synchronization tasks to be configured for workflows to prevent data from lagging behind official update schedules. Structural differences across multiple document types require workflows to adapt to different parsing and field extraction nodes. Field consistency between higher-level catalogs and local implementation lists must be verified, so field validation nodes must be configured. Maintenance of core fields such as acceptance conditions and application material lists requires configured validation steps to prevent non-compliant content. Item data passed in workflows must be stored in isolated `variables` to avoid cross-request data mixing, which meets task isolation requirements for government item maintenance.

## How to Configure
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable storage | Use `variables` to store data by item unique identifier, with lifecycle bound to a single workflow instance | Prevents cross-request data mixing, meets task isolation requirements for government item maintenance |
| Field validation rules | Configure required validation for acceptance condition and application material fields | Ensures core fields are complete, complies with service guide specification requirements |
| Scheduled trigger configuration | Trigger at 00:00 on the 1st of each month, set timeout threshold to `600 seconds` | Matches monthly update frequency, prevents synchronization tasks from timing out and interrupting |
| Single-document processing limit | Set to `first 50 entries` | Adapts to total monthly update documents, prevents single-task overload |
| Judger matching rules | Use "contains" and "ends with" as matching conditions | Adapts to text matching scenarios for item names and process node descriptions |
| Node ID configuration | Assign a unique `nodeId` to each workflow node | Facilitates locating nodes with execution exceptions, speeds up log troubleshooting |

## Three Common Configuration Errors
- Symptom: When "equals" or "starts with" are used as judgment conditions, the workflow always triggers the ELSE branch. Cause: Matching logic of the judger is not correctly understood, and matching rules do not match the format of field content.
- Symptom: Item data across workflow instances becomes mixed, and field content is overwritten. Cause: The lifecycle of `variables` is not bound to a single workflow instance, leading to data sharing.
- Symptom: Workflows cannot obtain synchronized data from higher-level catalogs, and fields are empty. Cause: System-side parameters are not obtained via correct context or variable transfer methods, and incorrectly rely on unconfigured global variables.

## How to Verify Correct Configuration
- Verify global variable configuration, confirm data binding rules meet single workflow instance isolation requirements.
- Run a test workflow, trigger the field validation step, confirm required field validation logic works correctly.
- Validate judger matching rules, confirm text matching logic adapts to business scenarios.
- Review workflow execution logs, confirm node ID tags are correct, allowing quick location of problematic links during exceptions.
