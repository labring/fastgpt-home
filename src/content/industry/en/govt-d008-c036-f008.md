# Business Process Guidance for Government Service Item Catalog and Service Guide Maintenance: Document Parsing and Chunking

## What the data for this category looks like
The daily documents for this category include basic government service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, frequently asked questions, and more. Data sources are the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases. Update frequency is usually once per month. Most documents use structured formats, with fixed fields including item name, acceptance conditions, application materials, processing flow, and others. Some documents include tables and visualized flowcharts. There is no unified fixed unit field, and field content changes with adjustments to local government service items.

## What constraints do these characteristics impose on the document parsing and chunking link
The structured nature of government documents requires that chunking preserves field relevance, and avoids splitting associated content such as acceptance conditions and application materials into different chunks. The monthly update frequency creates demand for batch parsing, requiring support for single large file uploads and long-duration parsing. Official documents from multiple sources have inconsistent formats, requiring compatibility with PDF parsing that includes tables and flowcharts. High requirements for field integrity mean chunking results must facilitate subsequent verification work comparing upper-level catalogs and local implementation lists, while ensuring that frequently asked question entries are not truncated, to avoid impacting subsequent business guidance calls.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Government documents mostly have structured fields. A single chunk must cover complete item descriptions or material lists, to avoid splitting associated content of acceptance conditions and application materials |
| `chunkSplitter` | Split by title + paragraph | Government documents have clear item titles and chaptered structures. Splitting by title preserves the independent integrity of each field, facilitating subsequent field verification |
| `customPdfParse` | Enabled | Government service guides mostly include standard material catalogs in table form. Custom PDF parsing can extract structured data from tables, avoiding missing application material lists |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Single provincial government service item catalog PDFs may exceed 500 MB, requiring adaptation to batch upload and large single file requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large government documents takes a long time, avoiding interrupting the parsing process due to timeout |
| `chunkSettingMode` | Manual configuration | Government documents have fixed structures. Manually adjusting chunking parameters can match the length requirements of business fields, avoiding field splitting errors caused by automatic chunking |

## Three common configuration mistakes
- When uploading large PDF files, an "offset out of range" error appears at 90% progress. The cause is failure to adjust `UPLOAD_FILE_MAX_SIZE` or `PARSE_FILE_TIMEOUT_SECONDS`. Parsing exceptions are triggered due to memory limits or timeout during file parsing.
- Direct chunking fails to recognize table content in service guides. The cause is failure to enable `customPdfParse`. The default parsing logic cannot extract structured application material fields from tables.
- Files uploaded via the create file collection API have inconsistent chunking with files uploaded directly on the platform. The cause is inconsistent `chunkSettingMode` configurations. The manual chunking mode is not specified during API calls, and default parameters differ from platform manual configurations.

## How to confirm the configuration is correct
- Upload a local test provincial service guide PDF, check the parsed chunking results, and confirm that associated content such as acceptance conditions and application materials are not split into different chunks.
- Upload a single 500 MB government service item catalog file, check that the upload progress completes normally, with no offset-related errors.
- Call the create file collection API to upload the same test file, compare the chunking results with manually uploaded files on the platform, and confirm that the chunking logic is consistent.
- Wait for parsing to complete, check that standard material catalog content from tables is extracted, with no key fields missing.
