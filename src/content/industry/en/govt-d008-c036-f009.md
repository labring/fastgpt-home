# Business Process Guidance for Government Service Item Catalog and Service Guide Maintenance: Model Access and Configuration

## What the data for this category looks like
Core data for government service item catalog and service guide maintenance typically comes from official data sources such as the national basic catalog of government service items, administrative licensing item list, local government service item database, etc. Daily maintained documents include the basic catalog of government service items, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. The data update frequency is monthly. The document structure includes standardized fields such as item name, acceptance conditions, application material list, service process, etc. All fields must comply with the unified specifications for government service items.

## What constraints do these characteristics impose on model access and configuration
The data characteristics of government service item catalog and service guide maintenance impose clear constraints on model access and configuration. Monthly updated data sources require configuring a regular synchronization mechanism to ensure that the catalog data used for model calls matches the latest official version. The complex structure of multiple types of documents requires the model to accurately identify the field boundaries of different documents, avoiding confusion between item information and process descriptions. The standardized requirements of official data sources require limiting the flexibility of model-generated content to ensure that outputs are consistent with government service specifications. Additionally, the work of comparing local implementation lists with higher-level catalogs requires the model to handle cross-level catalog data comparison logic.

## How to set the configuration
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Service guide documents are usually lengthy, requiring space to accommodate complete item rules and historical catalog comparison data |
| `maxTokens` | `2000–3000 token` | Ensure that the generated service process guidance content is complete and complies with the word count specifications of government documents |
| `temperature` | `0.1–0.3` | Maintain the rigor of service guidance, avoiding flexible expressions that do not comply with government requirements |
| `AIPROXY_API_ENDPOINT` | Model service address accessible via the government intranet | Used to access compliant large model interfaces, ensuring the security of government data transmission |
| `AIPROXY_API_TOKEN` | Exclusive key bound to the deployed model service | Verify interface call permissions and prevent unauthorized access to government-related data |

## Three Common Misconfigurations
1.  The `do_request_failed` error appears, with logs showing request failure or connection timeout. The cause is that `AIPROXY_API_ENDPOINT` is not correctly configured as the model service address accessible via the government intranet, or a valid `AIPROXY_API_TOKEN` is not configured, leading to permission verification failure.
2.  Missing fields or incomplete process nodes in the generated service guide content. The cause is that the `maxContext` value is too small, causing the model to fail to fully read the comparison data between the local implementation list and the higher-level catalog, resulting in truncation of key information.
3.  The expressions of acceptance conditions or application materials are too casual. The cause is that the `temperature` value is too high, causing the model-generated content to deviate from the standardized requirements of government services and use non-official expressions.

## How to Confirm Correct Configuration
1.  Import a local service guide document, initiate a model call test, and check whether the returned results include core fields such as complete item name and acceptance conditions, with no truncation or missing content.
2.  Verify the `AIPROXY_API_TOKEN` configuration, initiate a test request, and confirm that the returned status code is 200, with no permission-related errors.
3.  Compare the generated results before and after adjusting the `temperature` parameter to confirm that the rigor of the output content complies with the specification requirements of government documents.
4.  Configure a monthly synchronization task, and check whether the catalog data after automatic synchronization matches the latest version of the official data source.
