# Business Process Guidance for Government Service Item Catalog and Service Guide Maintenance: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The core data for this category includes basic government service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, and related materials. Data is primarily sourced from the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases. The standard update frequency is once per month. Each individual document includes fixed fields such as item code, item name, acceptance conditions, application material list, and handling process. Some documents require matching corresponding entries between superior catalogs and local implementation lists, and field standards must remain consistent across entries.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The fixed monthly update frequency of data for this category requires that the knowledge base retrieval and recall link support full data synchronization on a fixed cycle to prevent mixing old and new data. Each individual document contains multiple standardized fields and requires matching between superior and local corresponding entries. This means retrieval must accurately match field dimensions to avoid returning irrelevant item entries. Data standard consistency directly impacts online and offline service experiences, so recalled results must strictly correspond to the latest maintained entries, with no missing fields or standard deviations. Additionally, daily maintenance involves comparing large numbers of entries, so the retrieval link must return matching results efficiently to reduce manual verification workload.

## Configuration Settings
The following configurations are formulated based on the interface and parameter logic of FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | The data fields for this category have a high degree of standardization, requiring filtering of low-correlation irrelevant item entries. This range balances recall accuracy and coverage |
| `limit` | `Top 8–12 entries` | Individual service guide entries are numerous, and excessive results will exceed the 4096 token context length limit. This range covers core matching entries |
| `usingReRank` | Enabled | This category requires strict matching of item fields. Reranking corrects initial recall order deviations and ensures the most relevant entries are returned first |
| `searchMode` | `vector` | For structured fields and standardized entries, vector retrieval accurately matches semantic and field associations, outperforming keyword retrieval |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands relevant item keywords based on user queries to help match similar service entries across different names |

## Three Common Misconfigurations
- Phenomenon: Returned results are not the top entries sorted by initial similarity. Reason: After enabling the reranking function, the system reorders results based on semantic relevance, and initial high-similarity entries may have their order adjusted by the reranking logic.
- Phenomenon: Old version service guide entries still appear after knowledge base synchronization. Reason: No fixed-cycle full synchronization trigger rule is set, only incremental synchronization is performed, and all data from monthly updates is not covered.
- Phenomenon: Retrieval results only return a small number of entries and fail to cover required items. Reason: The `similarity` threshold is set too high, filtering out some semantically relevant entries with slightly lower similarity.

## How to Verify Proper Configuration
- Manually trigger a full data synchronization, check the synchronization log for the latest monthly update entries to confirm data timeliness.
- Submit a test query containing specific item names and fields, verify whether the sorting of returned results meets business expectations, and confirm the configuration effects of reranking and similarity threshold.
- Check the synchronization cycle in the retrieval configuration, set it to approximately 30 days to match the monthly update frequency of this category and avoid data update delays.
- Review the knowledge base dataset association configuration, confirm that all item document sets for this category have been bound to avoid missing data sources.
