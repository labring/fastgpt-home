# Business Process Guidance for Government Service Item Catalog and Service Guide Maintenance: Forms and Interactions

## What the Data for This Category Looks Like
The data maintained in this category comes from the national basic catalog of government service items, administrative licensing item list, power and responsibility list, and local government service item databases. The update frequency is monthly. Daily processed documents include the basic catalog of government service items, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. The data structure includes standardized fields such as basic item information, acceptance conditions, application material lists, and handling processes. There are slight differences in field mapping relationships across different documents, so the entry format for multiple types of documents needs to be adapted.

## What Constraints These Characteristics Impose on the Forms and Interactions Link
The monthly update frequency requires the form to support bulk import and bulk editing to reduce repetitive operations for single-item maintenance. The need to compare data from multiple sources requires the form to have built-in field consistency check rules to avoid field deviations between the superior catalog and the local implementation list. The structural differences across multiple types of documents require the form to support custom field mapping to adapt to the entry formats of different documents such as service guides and implementation lists. Missing core fields will lead to inconsistent online and offline service handling standards, so the form must set required fields and logical checks to intercept invalid entries in advance.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable field required validation, set `Item Name`, `Acceptance Conditions`, `Application Materials` as required fields, set validation interval to `300 milliseconds` | Match the core field requirements for government service items, quickly provide feedback on entry errors, avoid invalid submissions |
| `userSelect` | Enable bulk selection mode, allow selecting 10–20 entries to be maintained per single operation | Adapt to the monthly bulk update workflow, reduce time spent on single-item operations |
| Form Import Limit | Import 500–1000 entries per single operation | Match the monthly update data scale, avoid import timeouts or excessive system load |
| Field Mapping Rules | Automatically match corresponding fields by document type, support manual adjustment | Adapt to structural differences across different documents such as service guides and implementation lists |
| Validation Trigger Timing | Trigger in real time after entry is completed | Detect missing fields or logical conflicts in advance, reduce later comparison costs |

## Three Common Mistakes
- Symptom: When importing government service item documents, the page pages continuously refresh and target entries cannot be selected. Cause: Bulk import pagination validation rules for `formInput` are not configured, so the system cannot identify pagination nodes for large documents.
- Symptom: Submitted service guide fields do not match the superior catalog, and no error prompt is triggered. Cause: Field linkage validation is not enabled, only single-field required validation is performed.
- Symptom: Some item handling process fields are empty after bulk import. Cause: Document type field mapping rules are not configured, so the system cannot automatically match process fields.

## How to Confirm Proper Configuration
- Import a test government service item basic catalog document, check if a corresponding prompt pops up when required fields are missing.
- Select 15 entries to be maintained, confirm that the bulk editing function loads normally.
- Manually modify the acceptance conditions field, check if real-time validation triggers feedback.
- Import a service guide document, confirm that the system automatically maps the process fields and item code.
