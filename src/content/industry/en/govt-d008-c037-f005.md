# Business Process Guidance for Government Information Application Disclosure: Tool Calling and Plugins

Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Data for this category comes from government information disclosure platforms, official agency archive systems, document management systems, and departmental business ledgers, with irregular update frequencies. Daily processed documents include government information disclosure application forms, correction notification letters, third-party consultation letters, reply letters, service receipt forms, and administrative reconsideration response materials. Processing centers on individual requests from specific applicants, requiring retrieval, attribute judgment, and document drafting around the targeted information scope. There is no fixed rhythm for unified batch processing, and the volume of documents processed per single case fluctuates with request complexity.

## What constraints do these characteristics impose on the "tool calling and plugins" link
Scattered data sources and irregular update frequencies require the tool calling module to support connection to multiple heterogeneous system interfaces, pulling the latest archive, document, or business ledger data on demand. Diverse daily document types require dedicated field extraction and validation rules for different documents such as application forms and reply letters. Since errors directly relate to administrative remedy risks, tool calling must include built-in result validation logic to prevent incorrect information from entering the processing flow. At the same time, individualized request characteristics require tool calling to only retrieve within the context of the current application, avoiding irrelevant data interfering with flow judgment.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapt to multi-step processing scenarios, automatically schedule tools such as retrieval and document generation to complete process guidance |
| Third-party interface timeout | 600 seconds | Adapt to the average response delay of government system interfaces, avoid mid-process interruptions |
| Single tool call return count | Top 3 entries | Limit retrieval scope, focus on information directly related to the current application |
| `functionCall` | Strict mode | Ensure tool return parameters comply with the standardized format requirements of government information disclosure documents |
| Workflow nested call configuration | Allow passing context variables | Support splitting processing links, assign tasks such as retrieval and drafting to independent workflows |
| Plugin output validation | Enabled | Validate field completeness of returned documents such as application forms and reply letters |

## Three common mistakes
- Phenomenon: After a custom plugin runs, the output download address keeps jumping, and the final result is returned after a delay of several seconds. Cause: The plugin is not configured with synchronous call mode, and uses asynchronous callback logic by default, causing status jumps during the front-end waiting for the callback.
- Phenomenon: When workflow A calls workflow B, workflow B cannot execute the complete process. Cause: The call configuration does not pass the context variables of the current application, and workflow B lacks necessary basic application information to complete subsequent steps.
- Phenomenon: An Error: write EPROT error is returned when calling a third-party government system interface. Cause: The SSL certificate verification rule of the interface is not configured correctly, or the request header does not carry authentication parameters required by the government system.

## How to confirm the configuration is correct
- Submit a simulated government information disclosure application, observe whether the tool automatically schedules the retrieval plugin to pull archive data from the corresponding system.
- Configure workflow nested calls, after triggering the main workflow, confirm that the sub-workflow can execute all preset steps completely and return results.
- Call a third-party plugin bound to a government system, check that the returned document fields are complete and have no format errors.
- View the tool call logs, confirm that the timeout setting meets expectations, and no records of interruptions due to timeout appear.

The values listed above are common starting points, and should be evaluated against local samples.
