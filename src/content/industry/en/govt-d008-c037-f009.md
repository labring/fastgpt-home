# Business Process Guidance for Government Information Application Disclosure: Model Integration and Configuration

## What Data for This Category Looks Like
Business data for this category comes from government information disclosure platforms, agency archive systems, document management systems, departmental business ledgers, and relevant regulations of the Government Information Disclosure Regulations. Update frequency is irregular, with new business documents generated for specific application items. Daily processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, response letters, service receipts, and administrative reconsideration response materials. Each document has clear business fields: for example, application forms include applicant information and application items, while response letters include relief path descriptions. Processing entities include government offices, departmental government affairs disclosure offices, legal affairs departments, archives offices, and other relevant units.

## What Constraints Do These Characteristics Impose on the Model Integration and Configuration Link
Dispersed data sources covering multiple systems require the configuration link to support document retrieval from multiple data sources, to avoid missing documents caused by only connecting to a single platform. Diverse document types with obvious field differences require adaptation to the structural characteristics of different documents, to ensure the model can accurately identify business fields and content. Business processing links involve long-text retrieval and generation, requiring the model configuration to support sufficient context and generation length. Irregular data update cycles require support for dynamically loading the latest business documents and regulatory content, to prevent the model from using outdated information. In addition, the consequences of business errors are clear, so the configuration must ensure call stability and reduce the probability of timeouts or error responses.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `maxTokens` | 8000–12000 token | Adapts to the generation and processing requirements of long documents such as response letters and administrative reconsideration response materials |
| `temperature` | 0.2–0.4 | Ensures the standardization of generated content, meeting the rigor requirements of government documents |
| `maxContext` | 15000–20000 token | Accommodates complete content of multiple related business documents, such as application forms and supplementary notice letters |
| `toolChoice` | auto | Automatically selects whether to call tools to complete information retrieval and document matching links |
| `AIPROXY_API_ENDPOINT` | Fill in according to the actual address of the deployed proxy service | Adapts to proxy forwarding configuration for multi-model calls |
| `AIPROXY_API_TOKEN` | Valid token matching the proxy platform | Completes permission verification and identity recognition for model calls |

## Three Common Misconfigurations
- The interface displays "No available model" or the call returns a null value. The cause is that `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` is not configured correctly, or the token is not bound to the call permission of the corresponding model.
- The model-generated response content is incomplete or truncated. The cause is that the `maxTokens` setting value is smaller than the actual required length of the generated content.
- Government documents required for business cannot be retrieved. The cause is that the corresponding document retrieval path is not configured according to the data source, and data sources such as government information disclosure platforms and agency archive systems are not connected.

## How to Confirm the Configuration is Successful
- On the model management page of FastGPT v4.17.0, verify that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations exactly match the deployment parameters.
- Initiate a test call, enter simulated government information disclosure application content, and check whether the model can return a normal response without error prompts.
- Import a sample government document, and verify whether the model can correctly identify core business fields in the document, such as applicant information and application items.
- View the model call log to confirm that parameters such as `maxTokens` and `maxContext` are loaded correctly, with no missing or abnormal parameters.
