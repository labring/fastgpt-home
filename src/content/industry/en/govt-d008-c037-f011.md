# Government Information Application-Based Disclosure Business Process Guidance: Forms and Interactions

## What data for this category looks like
Data sources for this category include government information disclosure platforms, agency archive systems, document management systems, and departmental business ledgers. Data updates occur irregularly, synchronized with the progress of government information disclosure application processing. Daily processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, response letters, delivery receipts, and administrative reconsideration response materials. Document fields include applicant basic information, application content, information usage purpose, delivery method, and more. There is no unified fixed length, as differences exist based on the complexity of the application-based disclosure matters.

## What constraints these characteristics impose on the forms and interactions link
Decentralized data sources require forms to support multi-source data calls, allowing existing business data to be pulled from agency archive systems and document management systems to reduce repeated filling by applicants. Irregular updates require form fields to support dynamic adjustment to adapt to field updates after policy or business changes. Clear and standardized document fields require forms to strictly match preset business fields to avoid information deviations. Individual cases targeting specific applicants require forms to support personalized configuration to adapt to special handling requirements of different departments. Consequence of errors requires forms to be configured with strict validation rules to avoid missing required fields or format errors, reducing subsequent handling risks.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind applicant name, ID number, application content, and delivery method fields | Match the standard required fields of government information disclosure application forms |
| `userSelect` | Preset 20 common government department options, support custom additions | Cover most application scenarios while adapting to the special needs of niche departments |
| Form validation rules | Perform format validation on ID number and contact phone fields; required fields cannot be empty | Ensure collected applicant information complies with business specifications and avoid invalid applications |
| Batch corpus processing limit | Top 15 entries | Avoid occupying excessive system resources during batch processing, while covering conventional testing scenarios |
| Single input character limit | 800–1200 characters | Match the standard expression length of government information disclosure application content |
| Single uploaded document size limit | 1000 MB | Match the conventional storage size of government documents and avoid upload failures |
| Global variable data type | Enumeration or text type | Adapt to the value range of knowledge base selection variables and ensure correct variable storage format |

## Three common mistakes
- Phenomenon: The application content entered in the form cannot be accurately identified, and key information extracted by the model is missing. Cause: The field binding rules for `formInput` are not configured correctly, causing the model to fail to associate with preset business fields.
- Phenomenon: After batch uploading test documents, only the first dozen entries are processed normally, and subsequent entries have no response. Cause: The batch corpus processing limit is not set, and truncation is triggered after exceeding the system default threshold.
- Phenomenon: When text is imported into the input box via an embedded iframe, the send button becomes grayed out and cannot trigger submission. Cause: The input box content synchronization trigger logic is not configured, and the system does not detect valid input content.

## How to confirm the configuration is complete
- Fill in the standard government information disclosure application form fields, then check whether the model can correctly extract key data such as applicant information and application content after submission
- Upload test documents containing more than 15 entries, check that all entries are processed normally with no truncation or error prompts
- In the iframe embedding scenario, import preset test text into the input box, check whether the send button returns to a clickable state
- Configure the global variable as a knowledge base selection type, manually adjust the variable value, and check whether it conforms to the preset enumeration range
