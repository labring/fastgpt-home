# Business Process Guidance for Government Procurement Projects: HTTP Interfaces and External Systems

## What this category of data looks like
Data sources for this category include the China Government Procurement Network, local government procurement websites, fiscal integration systems, purchaser budget systems, and supplier credit records. The update frequency is daily. Daily processed business documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and question responses. Data links four types of entities: purchaser units, the government procurement supervision division of the finance department, procurement agencies, and procurement expert reviewers. Fields cover project identifiers, participating entity information, process node status, and result content.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The data sources for this category are scattered and involve official regulatory systems. Interface calls must adapt to multi-source authentication logic. The daily update feature requires interfaces to support incremental synchronization mode, to avoid excessive resource usage caused by full pull requests. Field differences across multiple types of business documents require configuration items to map the structural parameters of different documents. Errors in business processes can lead to invalid bids, regulatory penalties, and other consequences. Interfaces must be configured with complete exception capture and retry mechanisms to ensure the stability of data transmission and processing.

## How to Set Up Configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `Authorization` | Configure Bearer Token or API key according to the requirements of the connected system, with a value range of 16-64 characters | Adapt to the authentication specifications of official government procurement systems to ensure the legality of interface access |
| `variables` | Map procurement document fields, with values including business fields such as project number, supplier name, bid evaluation results | Match the structural differences of multiple types of business documents to achieve accurate extraction and circulation of data |
| `responseData` | Configure return field filtering rules according to business nodes, retain core business identifiers and status fields | Reduce invalid data transmission and improve interface processing efficiency |
| Interface timeout period | 60-120 seconds | Adapt to the response delay characteristics of government procurement systems to avoid process interruptions caused by timeouts |
| Retry count | 2-3 times | Respond to network fluctuations or temporary system freezes to ensure the reliability of data transmission |
| Incremental synchronization switch | Enabled | Match the daily update data frequency to reduce resource consumption from interface calls |

## Three Common Mistakes
- The interface returns a 200 status code, but image links in the business system cannot be accessed, with a timeout of approximately 60 seconds. The base64-encoded image data format is not handled correctly, resulting in character truncation during transmission.
- The interface call returns a 401 unauthorized error. The `Authorization` parameter is configured incorrectly, and the authentication key required by the official system is not used.
- Some required fields are missing from the synchronized winning bid announcement data. The `variables` mapping configuration does not cover all required business fields, resulting in incomplete data extraction.

## How to Verify the Configuration Is Correct
- Call the test interface and check whether the fields returned by `responseData` include the core business identifiers and status information required by the business.
- Simulate an incremental synchronization scenario and verify whether the number of data returned by the interface matches the number of newly added business documents on the day.
- Trigger a simulated network interruption test to confirm that the interface can automatically execute the retry logic after the interruption is restored.
- Check the authentication parameter configuration and confirm that the `Authorization` parameter format complies with the specifications of the connected system.
