# Business Process Guidance for Government Procurement Projects: Workflow Orchestration

## What the data for this category looks like
This category's data originates from the national government procurement website, local government procurement websites, the fiscal integration system, the procurer's budget system, and supplier credit records. The update frequency is daily. Commonly involved documents include procurement requirements, procurement plans, invitation to bid documents, bid documents, bid evaluation reports, winning bid announcements, procurement contracts, and responses to inquiries. Data fields cover procurement entity information, project budget, supplier qualifications, evaluation results, and more. No unified fixed format exists, and field extraction rules must be adapted to different business scenarios.

## Constraints imposed by these characteristics on the "workflow orchestration" link
Under FastGPT v4.17.0, the data characteristics of this category impose the following constraints on workflow orchestration:
- Daily updated data requires the workflow to be configured with a scheduled synchronization node to ensure real-time matching between business documents and system data.
- Multiple types of business documents require the workflow to adapt to field extraction rules for different formats to avoid parameter parsing failures.
- The strong regulatory attribute of the procurement process requires the workflow to retain complete operation logs to facilitate tracing of inquiry and complaint handling processes.
- The most time-consuming links such as requirement compilation and qualification verification need to be split via workflow nodes to reduce single-link operational pressure. At the same time, error consequences are severe, so verification rules must be configured at key nodes to prevent bid invalidation or regulatory penalties.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |

| `variables` | Bind 6 core business fields including procurement requirements and supplier credit records | Match the core data structure of daily business documents of this category to ensure complete parameters when the workflow is invoked |

| Maximum context length | 8000 tokens | Adapt to the total content after splicing multiple documents of this category to avoid content truncation |
| Scheduled synchronization interval | 24 hours | Match the daily update frequency of this category's data to ensure real-time synchronization of business data |
| Node retry count | 3 times | Avoid workflow interruption caused by a single call failure, and adapt to the rigor of government procurement processes |

## Three common configuration errors
- Invoking the workflow triggers the `Key is error` prompt. The cause is mixing account keys and application keys, and not using the app key of the corresponding workflow.
- The workflow fails to trigger normally. The cause is incorrect `nodeId` configuration, which causes the system to fail to locate the target execution node.
- Core parameters are empty during workflow operation. The cause is that `variables` are not bound to the corresponding business document fields, and global parameter configuration is not completed.

## How to verify a successful configuration
- The workflow test interface is invoked to check whether the returned result contains the preset `variables` bound fields.
- The `nodeId` configuration of the workflow is checked to confirm that it matches the identifier of the target execution node.
- The progress of procurement project nodes is simulated to verify whether the workflow triggers as expected.
- Workflow operation logs are reviewed to confirm that there are no parameter missing or timeout errors.
