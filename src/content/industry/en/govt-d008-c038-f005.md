# Government Procurement Project Business Process Guidance: Tool Calling and Plugins

## What This Category’s Data Looks Like
Data for this category comes primarily from the China Government Procurement Network, local government procurement networks, fiscal integration systems, purchaser budget systems, and supplier credit records. Updates occur daily.
Commonly processed documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and question responses.
Data fields cover procurement entity information, project budget, supplier qualifications, evaluation criteria, contract terms, and more. No unified fixed unit field exists. Unit rules must align with the business scenario corresponding to the document type.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
Data sources for this category are scattered and require daily synchronization. Tool calling plugins must support integration with multiple official systems and internal business systems to prevent data lag from disrupting business process pace.
Multiple document types are used daily, with each type corresponding to distinct business fields. Tool calling must adapt to the format and field extraction rules of all supported document types.
Errors directly lead to bid invalidation and regulatory penalties. Parameter verification and result review for tool calling must be more rigorous.
Business processes must comply with relevant government procurement regulatory requirements. Tool calling trigger logic must match the key nodes of business handling.

## Configuration Settings
The following configurations are based on the tool calling system of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | Set to `auto`, only trigger for government procurement-related business | Adapt to the business boundaries of segmented scenarios, avoid unrelated calls |
| `functionCall` | Enable, limit calls to document parsing and qualification verification tools | Match the tool requirements of the core business links of this category |
| Tool calling timeout | 600 seconds | Government procurement-related documents are usually large in size, and data verification requires longer processing time |
| Context window size | 8000–12000 token | Cover the complete content of multiple document types such as procurement requirements and bidding documents |
| Single tool calling parameter length | 4096 characters | Adapt to the field length limit of government procurement documents, avoid parameter truncation |
| Cross-domain whitelist configuration | Add domain names of government procurement-related systems | Resolve browser compatibility issues for iframe embedding |

## Three Common Configuration Mistakes
- The iframe-embedded application interface has no images or avatars, and only loads correctly on some browsers. Cause: Browser-compatible cross-domain plugin parameters are not configured. Some browsers' security policies block resource loading from non-official domains.
- Tool calling outputs both AI replies and next-level branch execution content, and the content is printed. Cause: The result echo switch for tool calling is not disabled, and the mutual exclusion rule between branch execution trigger conditions and echo logic is not configured.
- The tool calling function of Qwen2.5 cannot be enabled. Cause: `functionCall` support for the corresponding model is not enabled on the platform, and the binding configuration between the model and tool calling is not completed.

## How to Confirm the Configuration Is Correct
- Trigger a simulated business request for a government procurement project, check whether tool calling only triggers when matching relevant documents.
- View tool calling logs, confirm that the tool types called by `functionCall` match the configuration.
- Simulate abnormal data input, check whether the tool calling verification logic takes effect.
- Test the iframe embedding effect across different browsers, confirm that the cross-domain configuration meets the requirements.
