# Business Process Guidance for Government Procurement Projects: Model Access and Configuration

## What data for this category looks like
This category uses data from China Government Procurement Network, local government procurement networks, fiscal integration systems, procurer budget systems, and supplier credit records. The data updates daily.
The platform handles documents including procurement requirements, procurement plans, bidding documents, bid submissions, bid evaluation reports, winning bid announcements, procurement contracts, and responses to inquiries.
Data flows between four groups: procurers, the government procurement supervision department of the finance department, procurement agencies, and evaluation experts.
Each document maps to a different stage of the procurement process. All fields must comply with standardized formats under the government procurement system.

## What constraints these characteristics impose on model access and configuration
This category’s data is scattered across multiple sources and updates daily. The model access link must support batch synchronization configuration for multiple data sources. This prevents data lag from disrupting real-time process guidance.
Document types cover all procurement process stages. Different documents vary widely in length and field structure. Context and token limit parameters adapted to different text lengths must be configured.
Sensitive data such as supplier credit records requires strict access permission verification rules to ensure data compliance.
Document flow between process stages must match the guidance logic of the corresponding stage. Model call rules bound to the corresponding document type must be configured.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0, adapted to the process guidance scenario for government procurement projects:

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Government procurement-related documents are generally long in single-copy length, and need to accommodate the context of multiple related documents |
| `maxTokens` | 2000–3000 token | The output of process guidance needs to clearly cover the handling steps, avoiding excessive information redundancy |
| `quoteMaxToken` | 1500–2000 token | Limit the length of referenced documents to avoid context overflow affecting model responses |
| `temperature` | 0.2–0.4 | Ensure the accuracy and standardization of process guidance, reducing deviations from random generation |
| `AIPROXY_API_ENDPOINT` | Intranet access address of the deployment node | Adapt to the security requirements of intranet deployment of fiscal systems, avoiding public network exposure of sensitive data |
| `toolChoice` | Force binding of process step decomposition tool | Ensure that model output strictly corresponds to the standardized steps of government procurement handling processes |

## Three common configuration errors
- A configured model cannot be selected in workflow nodes, manifested as an empty model list or no corresponding entries. The cause is that the corresponding relationship between `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` is not correctly configured, or channel binding does not enable this model.
- A model call returns a 404 or 500 status code, manifested as a process node error. The cause is incorrect filling of the API endpoint address, or the key permission does not open the call permission for the corresponding model.
- The process steps output by the model do not comply with government procurement specifications, manifested as missing steps or incorrect rules. The cause is that `toolChoice` is not configured to force binding the process guidance tool, causing the model to generate content that does not meet regulatory requirements.

## How to confirm the configuration is correct
- Enter the model management page, confirm that the status of the configured model is "enabled", and the bound API endpoint and key match the current deployment environment.
- Create a new process node, call this model, input a fragment of a government procurement bidding document, and check whether a response content can be returned normally.
- View the system log, confirm that the status code of the model call request is 200, with no error messages.
- Test calling the process step decomposition tool bound by the configured `toolChoice`, verify that it can decompose standard step content compliant with the procurement process.

Note: The configuration values listed above are common starting points. They should be evaluated against samples from the actual use case.
