# Business Process Guidance for Government Procurement Projects: Forms and Interactions

## What This Category of Data Looks Like
This category of data comes from the national government procurement website, local government procurement websites, the fiscal integration system, the purchaser budget system, and supplier credit records, with a daily update frequency. Commonly processed documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and question responses. Fields cover project numbers, procurement content, budget amounts, supplier qualifications, evaluation results, and more. All fields follow standard government procurement document formats, with no additional custom field units.

## What Constraints Do These Characteristics Impose on the "Forms and Interactions" Link
The data sources for this category are scattered and updated daily, so form interactions must support real-time synchronization verification of multi-source data. There are various document types processed daily, and their fields follow government procurement standard formats, so preconfigured form templates adapted to different document types are required. The process involves multiple parties including purchasers, fiscal regulatory departments, procurement agencies, and evaluation experts, so interactions must distinguish operation permissions for different roles. Errors directly affect project compliance, so forms must add required field verification, automatic format correction, and exception prompts to reduce compliance risks.

## Three Common Configuration Mistakes
- After configuring `userSelect` data source binding, the reference variable dropdown displays no selectable values. This occurs when the public government procurement-related data interface is not correctly associated, or the interface permission is not enabled, resulting in failure to pull field data.
- After enabling form interactions, knowledge base retrieval time exceeds the preset threshold. This happens when the scope of multi-source data pulling is not restricted, and multiple scattered government procurement data source APIs are called simultaneously, leading to superposed request delays.
- The voice input button in the form cannot be properly invoked in some browsers. This is due to failure to adapt to browser voice input API compatibility, and no plain text input fallback option is provided.

## How to Verify That the Configuration Is Complete
- Open the form configuration page, verify that the preset fields include the core items of government procurement standard documents, and confirm that the field matching degree meets business requirements.
- Trigger the `formInput` verification rule, enter non-compliant formatted content, and confirm that the prompt message pops up in a timely manner with a delay within the expected range.
- Switch between different types of form templates, and confirm that the interface correctly loads the field configuration corresponding to the procurement scenario.
- Test the `userSelect` data source binding, confirm that public data interface content can be pulled normally, with no null values or error reports.
