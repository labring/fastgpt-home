# Business Process Guidance for Legal Compliance and Major Risk Management: Workflow Orchestration

## What the data for this category looks like
This category's data comes from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. Daily generated documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation results. Data is updated monthly. Core fields cover risk level, review status, violation clue details, and processing progress. Data is stored as standard text or structured tables, with no custom special units.

## What constraints these characteristics impose on the workflow orchestration link
The monthly data update requirement means workflows must support regular synchronization mechanisms to avoid using expired compliance clauses or risk lists. Multi-source heterogeneous document formats require workflows to adapt to both structured tables and free text input types, ensuring unified parsing of data from different sources. Core time-consuming links must be assigned independent node resources in workflows to prevent process blocking. Features with severe potential error consequences require workflows to be configured with mandatory audit trail nodes to ensure every review operation is traceable. Additionally, workflows must support standardized document formats submitted by external law firms to ensure data consistency for cross-entity collaboration.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `variables` | Global variable array, assigned in the format `["riskList", "auditOpinion", "reportContent"]` | Matches the core document fields of this category, facilitating transfer of compliance-related data within workflows |
| Scheduled trigger cycle | Monthly | Aligns with the monthly data update frequency, ensuring workflows use the latest compliance data |
| `nodeId` | Assign unique identifiers to the risk identification, contract review, and clue investigation nodes separately | Facilitates locating the execution status of time-consuming links in workflows and troubleshooting exceptions |
| API call timeout period | 600 seconds | Covers time-consuming business links such as compliance review and clue investigation |
| Global variable assignment trigger | Passed via API request parameters | Supports synchronizing business data from external systems to workflow variables |
| Workflow export format | Structured PDF + JSON dual format | Meets the dual needs of legal department archiving and system integration |

## Three common mistakes
- Incorrect global variable array assignment format: The symptom is field parsing failure when calling `variables` in the workflow, with the interface prompting "invalid variable format". The cause is failure to use the standard array format, mixing in non-string elements, or omitting comma separators.
- Variable content overlap after API calls: The symptom is that the final variable value in the workflow output includes all text from previous variables. For example, the result for variable B overlaps with the content of variable A. The cause is failing to turn off the variable inheritance switch in node configuration, causing variables from previous nodes to not be reset.
- Workflow export failure: The symptom is no file generation after clicking the export button, or a prompt of "insufficient export permissions". The cause is failing to configure archiving node permissions for the workflow, or selecting an unsupported non-standard type for the export format.

## How to confirm the configuration is complete
- Trigger a monthly scheduled workflow once, check the workflow logs in FastGPT v4.17.0, confirm that the `variables` parameter includes the preset compliance-related fields, with no parsing errors.
- Call the API with test parameters, check whether global variables are correctly assigned, with no content overlap.
- Export the workflow configuration, confirm that the exported file includes complete node configurations and variable definitions, with a format that meets preset requirements.
- Simulate a violation clue submission process, verify whether the review node corresponding to `nodeId` triggers normally and generates audit trail records.
