# Business Process Guidance for Legal Compliance and Major Risk Management: Tool Calling and Plugins

This configuration applies to FastGPT v4.17.0.

## What this category of data looks like
Data for this category originates from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. Updates occur monthly. Daily processed documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation reports. Most document structures include three core fields: subject information, issue content, and review result. No unified fixed unit exists. Fields adjust based on document type. Data formats vary across different sources.

## Constraints imposed on tool calling and plugins by these characteristics
Monthly updated data sources require tool calling cache periods to align with the update rhythm, to avoid using expired compliance data. Documents from multiple sources with varying structures require plugins to adapt to field parsing rules for different documents, to ensure consistent input and output. Compliance data has extremely high accuracy requirements. Tool calling must strictly verify the compliance of returned results to prevent incorrect content from being introduced. Documents involving major issues require strict access control. Permission tiered configuration for tool calling must match internal enterprise compliance management requirements.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `Fixed binding to compliance plugins` | Legal compliance processes require calling designated data source tools, to prevent unauthorized tools from being involved |
| `functionCall` | `Only allow calling compliance-related functions` | Strictly control the scope of tool calling, to prevent irrelevant operations from triggering compliance risks |
| Single tool call timeout | `300 seconds` | Compliance data queries involve cross-system coordination, so sufficient response time must be reserved |
| Plugin data cache period | `30 days` | Data source update frequency is monthly; match the cache period to the update rhythm to avoid using expired data |
| Input field mapping rules | `One-to-one mapping according to compliance document fields` | Different compliance documents have large structural differences, so precise matching of input fields is required to avoid parsing errors |
| Maximum number of returned results | `Top 10` | Compliance review only requires core reference data; too many results will increase review burden |

## Three common configuration mistakes
- Issue: Cannot select preset variables in the JSON input box, and fields are empty after submission. Cause: The variable binding switch for the plugin input box is not enabled, or variable substitution support is not declared in the plugin configuration.
- Issue: SQL statement execution error occurs when calling the data link tool, with returned parameter format error. Cause: The SQL syntax specifications of the compliance data source are not followed, and failing to limit the query scope leads to returned data overload.
- Issue: The returned result after tool calling does not match the compliance document, and irrelevant content appears. Cause: The `toolChoice` parameter is not bound to the designated compliance plugin, and an unauthorized tool is called.

## How to confirm the configuration is properly set up
- Trigger a compliance review process, and check if the tool calling is only bound to the designated compliance plugin.
- Submit a structured compliance document, and confirm that input fields are correctly mapped to the plugin input box.
- Wait for the tool calling to complete, and check if the returned result format complies with the preset verification rules.
- View the plugin calling logs, and confirm that no timeout errors or permission exceptions are triggered.

The values provided are common starting points and should be measured against the reader's own samples.
