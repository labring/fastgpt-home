# Business Process Guidance for Legal Compliance and Major Risk Management: Forms and Interactions

## What the data for this category looks like
The data sources for this category are enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. Documents processed daily include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation reports. The data update frequency is monthly. Document structures include structured tables, long-text descriptions, and categorized option fields. Core fields include compliance risk level, contract number, violation description, handling opinions, and others. There is no unified fixed unit system, and adaptation must be done based on the actual fields of individual business documents.

## What constraints these characteristics impose on the "forms and interactions" link
Data from multiple system sources must enable cross-source linkage within forms to ensure that entered compliance information matches existing stock data in the enterprise’s systems, preventing information inconsistencies. Monthly updated business data requires that synchronization rules configured for forms align with the update cycle, avoiding the use of outdated compliance review materials. The diverse document structure means forms must support multiple field types to accommodate structured table and long-text entry needs. Omitting core compliance fields can lead to serious consequences, so forms must enforce mandatory field checks to prevent compliance risks caused by missing core information.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Supports multi-line text and field format validation, maximum input length 8000 characters | Documents such as compliance review opinions have long content and need to accommodate complete compliance description information |
| `userSelect` | Supports single or multiple selection, options linked by compliance risk category | Matches the classification logic of compliance risk lists and associatively displays corresponding review key points |
| Form timeout setting | 300 seconds | Compliance business processing requires cross-system data queries, reserve sufficient operating time |
| Mandatory field validation | Configured according to the core fields of business documents | Prevents omission of key compliance review information and reduces error risks |
| Data synchronization interval | Refreshed monthly | Aligns with the monthly update frequency of business data |
| API call configuration | Enable API adaptation mode for interactive components | Supports access to forms and user selection functions via API channels |

## Three common mistakes
- When calling the API to access published `formInput` or `userSelect` components, there is no user input prompt and the returned interaction fields are empty. The cause is that the API call adaptation configuration for the component was not enabled in the workflow.
- When importing a multi-column compliance risk list Excel file, the automatic segmentation results are chaotic and cannot split each row as an independent segment. The cause is that the minimum segmentation unit was not specified as rows.
- The form input component cannot pass preset variables from the business system. The cause is that the variable binding configuration item for the component was not enabled.

- Upload a test multi-column compliance document Excel file and check whether the automatic segmentation results are split by row, conforming to the expected segmentation rules.
- Test the variable binding function of the form input component and confirm that preset business system variables can be passed successfully.
