# Business Process Guidance for Special Equipment Safety Supervision: Workflow Orchestration

## What data for this category looks like
Data sources for this category include the special equipment safety supervision system, inspection and testing institution system, user account ledgers, and operator credential database. Daily business documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator credentials. Core fields include equipment number, equipment type, inspection cycle, maintenance unit qualification, operator certificate number, hidden danger rectification status, and others. The data update frequency is monthly. All system data must be regularly synchronized to a unified supervision account book.

## What constraints these characteristics impose on the "workflow orchestration" link
Monthly updated data requires the workflow's data source synchronization cycle to match the monthly rhythm, to avoid excessive system load from frequent pulls. Multiple data source systems require the workflow to configure cross-system data pull nodes, to ensure each link can obtain complete supervision data. Diverse business document types require workflow nodes to adapt to parsing logic for different documents, covering the full process of registration, inspection, maintenance, rectification, and other links. The uniqueness requirement of core fields requires binding fixed-field variables in the workflow, to ensure accurate data calls. At the same time, the most time-consuming verification link must be split into independent nodes, to facilitate process optimization and anomaly location.

## Configuration Guidelines
This document applies to FastGPT v4.17.0. The following are specific configuration items for workflow orchestration:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Data Source Binding | Bind the monthly synchronization interfaces of the special equipment safety supervision system and inspection and testing institution system | Match the monthly update frequency of business data, ensuring the timeliness of pulled data |
| `variables` | Define equipment number, inspection cycle, and operator certificate number as global variables | Cover core fields of business processing, facilitating cross-node calling and unified management |
| `nodeId` | Set a unique identifier for each business link node | Facilitate log tracking and anomaly location, quickly identify faulty process nodes |
| HTTP Request Timeout | Configure as 60 seconds | Adapt to network latency of cross-system data pulls, avoiding process interruption due to timeout |
| Exception Retry Mechanism | Set up to 2 retries for data verification nodes, with a 30-second retry interval | Respond to temporary exceptions in multi-system data synchronization, reducing the probability of process interruption |
| Workflow Trigger Timing | Trigger according to business processing nodes | Align with the fixed processing flow of special equipment supervision, ensuring accurate link triggering |

## Three Common Configuration Mistakes
- After adding a custom supervision data plugin to the workflow, no input or output parameters are displayed. The business fields required by the plugin are not declared in `variables`, causing the node to fail to recognize parameters.
- An uncaught exception occurs when calling the AI chat component. In private deployment scenarios, the configuration file is not correctly bound to the interface permissions of the special equipment system, or the data source address configured in `variables` is incorrect.
- When looping through the operator certificate array, the loop body cannot read array elements. The array parameters are not correctly mapped to the input items of the loop node, resulting in no valid data being passed when the loop triggers.

## How to Confirm Correct Configuration
- Check whether `variables` includes core business fields such as equipment number and inspection cycle, and that the field names match the data fields of the business system.
- Trigger a simulated business processing process, view the workflow node logs, and confirm that each link can correctly pull data from the corresponding system.
- Test exception scenarios, such as disconnecting a system interface, and confirm that the workflow can trigger preset retry or termination logic.
- Configure a loop node to process the operator certificate array, verify that the loop body can read array elements one by one and execute corresponding operations.
