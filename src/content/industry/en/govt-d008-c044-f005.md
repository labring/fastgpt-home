# Business Process Guidance for Environmental Law Enforcement and Monitoring Supervision: Tool Calling and Plugins

## What the data for this category looks like
This category includes data from ecological environment law enforcement systems, automatic pollution source monitoring platforms, third-party test reports, and on-site inspection records. Daily documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. These documents cover on-site operating conditions, sampling information, monitoring results, illegal determination details, and law enforcement document content. The system updates the latest content from online monitoring and law enforcement systems daily. The data structure mixes structured tables and unstructured text.

## What constraints these characteristics impose on the tool calling and plugins link
Multi-source, heterogeneous data sources require tool calling to adapt to the interface formats of different systems, and independent authentication rules must be configured per data source. The mixed structured and unstructured document structure requires plugins to support field extraction and format verification to ensure the accuracy of law enforcement data. The daily update frequency requires the calling cycle to match the data synchronization rhythm to avoid repeated data pulling or delayed processing. Strict requirements for law enforcement data require tool calling to record a complete link for subsequent traceability and verification.

## How to Configure
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` and bind a dedicated tool for law enforcement data | Automatically matches the calling requirements of online monitoring and law enforcement systems to avoid omissions from manual selection |
| Tool call timeout | 600–1200 seconds | Covers the typical duration of multi-source data pulling, sampling comparison, and document generation tasks |
| Plugin authentication method | Configure a dedicated KEY per data source | Complies with permission isolation requirements of different law enforcement systems to prevent unauthorized access |
| Maximum tool call times | First 8 calls | Adapts to the sampling analysis, data comparison, document generation and other links required for a single law enforcement process |
| Single tool call result limit | First 20 entries | Matches the monitoring data volume of a single law enforcement process to avoid overload |
| `functionCall` | Enable mandatory format verification | Ensures that fields in generated law enforcement documents comply with specifications and prevent data errors |

## Three Common Misconfigurations
- A 403 Forbidden error is returned when initiating a tool call. The cause is using a general authentication KEY instead of a dedicated authentication configured per data source, which violates the permission isolation requirements of the law enforcement system.
- Workflow execution times out after exceeding 1200 seconds and returns a timeout status code. The cause is not setting a reasonable timeout threshold and not splitting the time-consuming sampling data comparison link.
- No calling log entries appear on the model provider page. The cause is not enabling the tool call logging function, making it impossible to trace the calling link of law enforcement data.

## How to Verify Successful Configuration
- Initiate a simulated call for a single sampling data record to verify that the authentication KEY only allows access to the interface of the corresponding data source.
- View the workflow execution log to confirm that the time taken by the timeout link does not exceed the configured threshold range.
- Check the fields of the generated law enforcement documents to confirm that they comply with the preset format specifications.
- Enter the model provider page to confirm that a log entry exists for this tool call.

The values provided here are common starting points and should be evaluated against the reader's own samples.
