# Business Process Guidance for Environmental Law Enforcement and Monitoring Regulation: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from the ecological environment online monitoring platform, pollution source automatic monitoring system, law enforcement business system, and reports submitted by third-party testing institutions. Daily processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Fields covered include inspection points, pollutant concentrations, law enforcement document numbers, rectification requirements, and more. Data is updated daily, covering real-time operating conditions, monitoring results, and law enforcement progress information. Most data sources are intranet-deployed business systems and monitoring equipment.

## Constraints on Deployment and Upgrade
Since most data sources are intranet-deployed business systems and monitoring equipment, deployment must support HTTP proxy configuration with identity authentication. This meets the need to access external dependencies in intranet environments. Massive daily updated monitoring and law enforcement data require sufficient database connection pool and storage capacity to be configured during deployment. This avoids performance bottlenecks during concurrent access. Mixed types of law enforcement documents require adaptation to different format parsing rules. Compatibility of parsing logic must be ensured during upgrades. Law enforcement evidence data has compliance requirements. Data encryption and permission control mechanisms must be configured during deployment and upgrade to prevent sensitive information leakage.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 connections` | Adapt to concurrent access demands of daily updated monitoring data and law enforcement documents, avoid database connection exhaustion |
| `MONGODB_URI` | `Intranet MongoDB service address with authentication parameters added` | Store unstructured documents such as law enforcement records and monitoring reports, adapt to intranet deployment scenarios |
| `REDIS_URL` | `Intranet Redis service address with access password configured` | Cache real-time law enforcement data and session information, ensure response speed for daily high-frequency updates |
| `FILE_TOKEN_KEY` | `32-bit randomly generated string` | Encrypt access tokens for law enforcement documents, ensure storage security of monitoring data and law enforcement documents |
| `STORAGE_S3_ENDPOINT` | `Intranet object storage service address` | Store large files such as sampling records and monitoring reports, adapt to intranet storage requirements |

## Three Common Misconfigurations
- Symptom: Unable to access external dependent resources during intranet deployment. Logs show connection timeout. Cause: Only proxy IP and port were configured. No authentication username and password were added, so proxy identity verification fails.
- Symptom: After upgrading to FastGPT v4.17.0, the custom large model configured in the application is reset to the default model. Specified configurations cannot be saved. Cause: Original configuration files were not backed up during the upgrade. System parameters are overwritten and reset.
- Symptom: A database connection failure prompt pops up when entering the workflow editor. Cause: The `DB_MAX_LINK` configuration value is set too low. The database connection pool is exhausted during concurrent access to law enforcement data.

## How to Verify Proper Configuration
- Run the proxy configuration test script to verify that external dependent resources can be accessed via the authenticated proxy in the intranet environment.
- Upload a sampling record document to verify that the system can parse it normally and store it in the specified object storage location.
- Check the database connection pool monitoring panel to confirm that the current active connection count does not exceed the threshold set by the `DB_MAX_LINK` configuration.
- Log in to the system administrator backend to verify that the `ROOT_KEY` permission can normally access the configuration management page.

The values provided are common starting points and should be evaluated against the reader's own samples.
