# Business Process Guidance for Land Pre-examination and Planning Permit: HTTP Interfaces and External Systems

## What the Data for This Category Includes
Data related to land pre-examination and planning permit business originates from the national land and space planning unified map, project approval and supervision platform, current land use database, and ecological protection red line data. The update frequency is irregular. Daily business documents include land pre-examination and site selection opinion, construction land planning permit, construction project planning permit, red line drawing, and planning conditions. Document structures cover fields such as project subject information, site selection range coordinates, land scale parameters, and planning control clauses. Field units include planning-specific units such as hectares and square meters.

## Constraints Imposed on HTTP Interfaces and External Systems
Since data sources involve multiple government service platforms, interfaces must adapt to identity verification rules across systems to prevent cross-source authentication failures. The diversity of document types and fields requires interfaces to support multi-format parameter transmission and field mapping, ensuring that information from different business documents can be correctly extracted. The irregular data update cycle requires interface configurations to support incremental synchronization to adapt to non-fixed data update schedules. Business handling errors carry serious consequences, so interfaces must be configured with failure retry and exception alert mechanisms to maintain process stability.

## Configuration Settings
| Configuration Item | Recommended Practice | Basis for This Practice |
| --- | --- | --- |
| `Authorization` | Carry the fixed secret key of the government service account with each request | Identity verification requirements for connecting to external systems of natural resources authorities |
| `variables` | Pass business-specific parameters such as project number and site selection range coordinates | Match personalized request requirements for land pre-examination and planning permit business |
| `responseData` | Extract compliant data by mapping business document fields | Ensure returned content aligns with the field structure of planning permit-related documents |
| Single request timeout duration | 600 seconds | Adapt to average time requirements for cross-multiple-data-source queries |
| Incremental synchronization switch | Enabled | Match the irregular data update business rhythm |
| Number of error retries | 3 times | Balance interface stability and system resource consumption |

## Three Common Configuration Mistakes
- The interface returns a `401 Unauthorized` error. The cause is that the `Authorization` parameter does not correctly carry the service account secret key, or the secret key has expired and become invalid.
- The interface receives two duplicate requests, and the `Authorization` parameter of the second request is incorrect. The cause is that request idempotency is not configured, and the external system does not retain correct authentication information during retries.
- The planning control clause field in the returned `responseData` is empty. The cause is that the field mapping configuration does not match the actual naming rules of the business document.

## How to Verify Successful Configuration
- Initiate a test request, check whether the `Authorization` parameter is correctly included in the request header, and confirm that the returned status code is 200.
- Pass a preset project number parameter, confirm that business parameters in `variables` are correctly parsed and used for data query.
- Review the content returned by `responseData`, confirm that it includes core business required fields such as land scale and site selection range.
- Simulate an interface timeout scenario, confirm that the system triggers the preset retry mechanism and no abnormal data accumulates.
