# Business Process Guidance for Land Pre-examination and Planning Permit: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data related to land pre-examination and planning permit is sourced from the national land and spatial planning one-map platform, project approval and supervision platform, land use status database, and ecological protection redline data. Update frequency is irregular. Daily business documents include land pre-examination and site selection opinion, construction land planning permit, construction engineering planning permit, redline drawings, and planning conditions. Core fields include project site selection scope, land scale, control redline coordinates, pre-approval conditions, etc. The data structure is dynamically adjusted along with project approval stages.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" capability area
Since data sources are multiple and update frequency is irregular, multi-turn dialogue must remind users to confirm the timeliness of the data being used in each interaction, to avoid referencing expired control redline or approval data. Daily documents include unstructured content such as visual redline drawings and planning conditions. Multi-turn dialogue must guide users to upload or clearly reference the field information of corresponding documents. Core approval stages require verification of multi-dimensional content such as site compliance, land scale, and preconditions. Multi-turn dialogue must split interaction steps according to approval nodes, to avoid asking users to provide too much information at one time.

## Three common mistakes
- Symptom: Documents uploaded by users during dialogue, such as redline drawings and planning conditions, are not automatically stored in the knowledge base. Cause: The `variables` binding for document fields to be stored in the knowledge base is not configured, and the automatic storage trigger rule for dialogue content is not enabled.
- Symptom: Token consumption statistics data for the dialogue cannot be viewed. Cause: The global token statistics switch is not enabled, and the statistics display is not turned on in the chat page corresponding to `chatId`.
- Symptom: Approval data obtained after workflow SQL query cannot be correctly displayed in the AI dialogue box. Cause: The SQL query result is not bound to the `messages` context, and the prompt word for result formatting is not configured.

## How to confirm the configuration is correct
- Initiate a test dialogue, upload a planning condition document, and check whether a matching entry is added to the corresponding knowledge base.
- Enter the conversation details page, view the token consumption statistics data, and confirm that the statistics logic is running normally.
- Configure the SQL query workflow, execute a test query, and check whether the result is correctly rendered on the dialogue interface.
- Send an approval prompt in Markdown format to the test account, and check whether the format meets expectations.
