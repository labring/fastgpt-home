# Business Process Guidance for Land Pre-examination and Planning Permit: Tool Calling and Plugins

## What the data for this category looks like
This category of data primarily comes from the national land spatial planning unified map, project approval and supervision platform, land use status database, and ecological protection redline data. Update frequency is irregular. Commonly generated and used documents include land pre-examination and site selection opinions, construction land planning permits, construction project planning permits, redline diagrams, and planning conditions. Most data fields relate to project site location, land scale, planning control boundaries, and pre-approval associated information. Compliance verification requires matching multi-source spatial and approval data.

## What constraints do these characteristics impose on the "tool calling and plugins" link?
Multi-source heterogeneous data sources require plugins to support integration with different types of approval and spatial data interfaces, and adapt to parsing unstructured documents and spatial graphic data. Irregular update frequency means the tool calling link cannot rely on static caching. It must pull the latest land spatial planning and approval data in real time to avoid verification errors caused by outdated data. Documents include spatial image files such as redline diagrams, so support for rendering and verification of base64-encoded formats is required. This ensures project units can intuitively view site selection boundaries. The need for cross-departmental pre-condition verification requires plugins to link with multiple external approval data sources such as development and reform, housing and urban-rural development, and ecological protection. This completes automatic verification of land scale and planning control. Data verification errors will prevent project approval or construction. Therefore, tool calling must be configured with clear failure retry and exception reporting logic, to allow operation and maintenance personnel to quickly locate issues. The `toolChoice` parameter must be used to limit the scope of tool calling, only triggering tools related to natural resource approval. The number of tool call failure retries must be set to `2–3 times`, to avoid process interruption caused by a single failed call.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or specify the land pre-examination verification plugin | Adapt to the required tool calling scope, only trigger tools related to natural resource approval, avoid irrelevant calls interfering with the process |
| `functionCall` | `enabled` | Enable structured tool calling to ensure parameters meet the format requirements for land pre-examination and planning permit verification |
| Single tool call timeout | `30–60 seconds` | Spatial data pulling and multi-source verification require reasonable time, avoid overly long waiting that affects user operation experience |
| Maximum number of plugin return results | `Top 3–5 entries` | Only require core planning control and redline conflict verification data, avoid redundant information interfering with business judgment |
| base64 image rendering configuration | Enable markdown rendering adaptation | Adapt to base64-encoded display of spatial documents such as redline diagrams, meeting the document viewing needs of business scenarios |
| Stop sequences | Configure as `Verification completed, Verification conflict, Timeout` | Clear termination conditions for tool calling, avoid invalid execution or timeout waiting |

## Three Common Mistakes
- Phenomenon: The base64-encoded redline diagram fails to render normally in the chat interface, only displaying text identifiers. Cause: The spatial document rendering configuration adapted to base64 format is not enabled, or the plugin does not support parsing graphic files of this encoding type.
- Phenomenon: Tool calling continues to execute without terminating, exceeding the preset waiting duration. Cause: No clear termination conditions are configured for the stop sequence, and verification completed, verification conflict, or timeout are not included in the trigger rules.
- Phenomenon: Land control data returned by tool calling does not match the latest requirements. Cause: The plugin is configured to use static cached data, and the function of pulling data from sources such as the national land spatial planning unified map in real time is not enabled.

## How to Confirm Proper Configuration
- Initiate a query related to land pre-examination, verify that the base64-encoded redline diagram can be rendered normally in the chat interface.
- Trigger tool calling, observe whether it automatically terminates when preset conditions are met, in line with the stop sequence configuration rules.
- Compare the planning data returned by the tool with the latest content from the official national land spatial planning unified map, confirm data timeliness.
- Check the number of tool call return results, confirm it matches the preset maximum result count configuration.
