# Business Process Guidance for Land Pre-examination and Planning Permit: Document Parsing and Chunking

## What the Data for This Category Looks Like
Daily documents for this category include land pre-examination and site selection opinions, construction land planning permits, construction engineering planning permits, red line drawings, and planning conditions. Data sources include the national integrated land and space planning map platform, project approval and supervision platform, current land use database, and ecological protection red line dataset. Update frequency is irregular.

Document structures mix text descriptions, structured tables, and spatial coordinate parameters. Core fields include land scale, control indicators, approval document numbers, and others. Some documents carry official formats and stamped elements. The data covers full-process approval materials for projects from site selection to permitting.

## Constraints Imposed on Document Parsing and Chunking by These Characteristics
Daily documents mix text, tables, and spatial parameters. Parsing and chunking must retain the integrity of different content types, and avoid damaging table associations or the continuity of coordinate parameters.

Data comes from multiple official systems, so formats have some variability. Parsing and chunking must support complexly formatted PDFs and spreadsheets.

Irregular update frequency means bulk processing of approval materials from different cycles is required. Chunking rules must cover key easily missed information such as core control requirements and preconditions. Failure to do this will reduce the accuracy of subsequent process guidance.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Daily documents contain multiple content types such as approval descriptions and red line parameters. This range covers core information while avoiding overloading individual chunks |
| `chunkSplitter` | Split by paragraph + table boundaries | Documents mix text and structured tables. Splitting by boundaries retains row and column associations for tables and the logical integrity of paragraphs |
| `customPdfParse` | Enabled | Official PDFs have complex formats and stamped elements. Enabling custom parsing preserves text hierarchy and table structure |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Parsing large red line drawings and multi-page planning permit PDFs takes significant time. This duration covers processing needs for most business documents |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Supporting multi-layer red line drawings and historical approval archive files that come with projects requires this upper limit for complete uploads |
| `chunkSettingMode` | Manual configuration | Different document types such as planning conditions and site selection opinions require adjusted chunking rules to adapt to differentiated content structures |

## Three Common Mistakes
- Symptom: Custom PDF parsing component fails to start after deployment. The interface prompts that the parsing service is not ready. Cause: Environment variables associated with `customPdfParse` are not configured correctly, so the parsing engine cannot load normally.
- Symptom: Large red line drawing files fail to parse and terminate due to timeout after upload. Cause: The value set for `PARSE_FILE_TIMEOUT_SECONDS` is lower than actual parsing time, and insufficient processing time is reserved.
- Symptom: Fields in XLSX-format project approval tables are scrambled after chunking. Cause: Splitting is not done by table boundaries. The default chunking logic breaks the row and column associations of tables, causing core approval fields to be scattered.

## How to Verify Proper Configuration
- Upload a single typical document, such as a construction land planning permit PDF. Verify that the parsed text has no garbled characters and that table content is complete.
- Check the `PARSE_FILE_TIMEOUT_SECONDS` configuration item to confirm that the value matches the average document parsing time in the current environment.
- Upload the largest volume file that fits the business scenario. Confirm that the upload and parsing processes do not terminate abnormally.
- Trigger a chunking operation. Check that the chunked content covers key information such as core control requirements and preconditions.
