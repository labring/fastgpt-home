# Business Process Guidance for Land Use Preliminary Examination and Planning Permit: Deployment and Upgrade

## What the data for this category looks like
This category's data mainly comes from the national land and spatial planning one-map system, project approval and supervision platform, current land use database, and ecological protection redline data. Update schedules are irregular. Daily associated documents include land use preliminary examination and site selection opinion, construction land planning permit, construction engineering planning permit, redline drawings, and planning conditions. Core fields cover project site selection scope, land use scale, planning control requirements, pre-approval conditions, and more. The data structure is strongly bound to the spatial attributes of natural resource management. There is no standardized field format for general business documents.

## What constraints these characteristics impose on the deployment and upgrade phase
Because data sources are scattered and updates have no fixed cycle, the incremental synchronization logic for multi-source heterogeneous data must be adapted during deployment. This avoids excessive server resource usage from full data pulls. Daily documents include spatial attribute-heavy redline drawings, planning conditions, and other materials. Knowledge base index rules that support spatial data association must be configured. This ensures that spatial and text information can be matched jointly during retrieval. Pre-approval conditions vary significantly across different projects. Flexible rule configuration entry points must be reserved during deployment. This adapts process guidance logic for different scenarios. Business handling errors can lead to project failure to initiate or start construction, permit revocation, illegal land use and construction, and other consequences. Data verification links must be strengthened during the deployment phase. This prevents incorrect data from entering the knowledge base and harming guidance accuracy.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Calibrated based on business data volume; single instance storage must not exceed 1000 GB | This category’s business data includes spatial layers and approval documents. Single data entry size is large, so sufficient storage capacity must be reserved |
| `REDIS_URL` | Configured as session cache with 600-second expiration | Business handling processes require retaining user interaction context. 600 seconds covers the single consultation cycle for most project approvals |
| `DB_MAX_LINK` | First 20 entries | This category’s retrieval requires associating multi-source data. 20 entries can cover the core associated results for a single retrieval, avoiding resource overload |
| Single search upper limit | Calibrated based on actual testing; range is 10–15 entries | Balance retrieval efficiency and information integrity. Avoid returning excessive redundant data that disrupts business guidance |
| `FILE_TOKEN_KEY` | Aligned with the file authentication key of the business system | Ensure secure retrieval of business documents such as redline drawings and planning conditions. Prevent unauthorized access |

## Three common mistakes
- Symptom: A permission error is returned after executing the version query command. The currently deployed FastGPT version cannot be viewed. Cause: `ROOT_KEY` was not filled correctly in the deployment configuration. This causes permission verification to fail, and the version query operation cannot be executed.
- Symptom: Conversation logs are lost. Previous business consultation records of users cannot be retrieved. Cause: Persistent storage for `REDIS_URL` was not configured, or the expiration time was set too short. This causes the session cache to be automatically cleared.
- Symptom: The number of returned results from the knowledge base search module is fixed. It cannot be adjusted via configuration. Cause: The `DB_MAX_LINK` parameter was not set correctly, or the configured value was not synchronized to the running environment. This locks the retrieval upper limit to the system default value.

## How to confirm the configuration is complete
- Execute the version query command. Confirm that the returned FastGPT version is v4.17.0, and no permission errors appear.
- Upload a test redline drawing document. Check that the knowledge base indexing progress is normal, and the document content can be matched via retrieval.
- Initiate a simulated business consultation. Check that the conversation context is retained normally within the preset cycle, and no log loss occurs.
- Adjust the `DB_MAX_LINK` parameter. Verify that the number of results returned by retrieval matches the configured value.

The values provided here are common starting points. They should be evaluated against samples tailored to the actual deployment.
