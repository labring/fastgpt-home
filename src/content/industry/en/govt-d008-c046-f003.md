# Business Process Guidance for Social Assistance and Minimum Living Allowance Review: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The data for this category is primarily sourced from the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-departmental shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update frequency is once per month.
Daily business documents include minimum living allowance application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. The core fields of these documents focus on family income and property, member relationships, and assistance eligibility. There is no unified fixed format template, and content must be filled in accordance with the requirements of each processing link.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Decentralized cross-departmental shared data sources require multi-turn dialogue to gradually guide users to supplement scattered verification information, avoiding asking for too much content at once and causing resistance.
The monthly update frequency means dialogue must support eligibility verification based on the latest monthly data, and monthly data snapshots must be included in the context window.
Diverse business document types require prompts to adapt to field extraction logic for different materials, distinguishing information capture rules for scenarios such as application forms and verification reports.
Family income and property, as well as member relationships, are core verification fields. Multi-turn dialogue must confirm these fields step-by-step in accordance with the verification process, avoiding missing key verification items.

| `chatId` | Bind to the unique work order ID of the assistance application | Ensure multi-turn dialogue context is bound to the corresponding business application, avoiding context confusion between different applications |

## Three common misconfigurations
- Issue: Subsequent rounds of multi-turn dialogue cannot call the family income verification results generated in the previous round as input, leading to repeated inquiries or missing verification items. Cause: `chatId` is not correctly bound, or the `messages` content from the previous round is not fully passed into the current dialogue context.
- Issue: Clicking a business document link in streaming output only overwrites the current page, and cannot jump to a new page. Cause: Interactive rules for streaming output are not configured, only plain text links are returned, and no jumpable interactive identifiers are added.
- Issue: Dialogue requests return a timeout, with status code 504, and cannot obtain verification results from cross-departmental shared data. Cause: The delay characteristic of cross-departmental data queries is not considered, and a reasonable request waiting duration is not set.

## How to confirm the configuration is correct
- Initiate a simulated assistance application dialogue, check whether the dialogue context updates synchronously with the bound work order ID.
- Call the API to initiate a multi-turn dialogue, verify whether the output content from the previous round is correctly included in the context parameters of the current round.
- Trigger streaming output, click the returned link, and confirm that the jump behavior meets expectations.
- Simulate a cross-departmental data query scenario, check whether the dialogue can complete verification based on the preloaded monthly data snapshot.
