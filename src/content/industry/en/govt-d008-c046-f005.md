# Business Process Guidance for Social Assistance and Minimum Living Security Review: Tool Calling and Plugins

## What the data for this category looks like
Data sources for this category include the low-income population dynamic monitoring platform, resident family economic status verification system, and shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax and other departments. The update frequency is once per month. Daily business documents include minimum living security application forms, family economic status verification reports, household surveys, democratic appraisal records, public notice materials, and assistance approval forms. Data fields cover family income, total property, member relationships, verification results, approval status and more. Most are structured forms or semi-structured documents.

## What constraints these characteristics impose on the "tool calling and plugins" link
Cross-departmental data sources require tool calling to support multiple interface connections. This avoids only obtaining information from a single data source in a single call. The monthly update frequency means the scheduled trigger rhythm for tool calling must match the business data update cycle. It should not be too frequent. The existence of multiple types of business documents requires plugins to adapt to parsing and extraction of various formats such as forms and PDF reports. Data accuracy requirements are very high. Results returned by tool calling must undergo verification. Otherwise, compliance issues such as incorrect or missed security benefits may occur. The difference from other civil affairs public service categories is that the core relies on cross-departmental property verification. Therefore, tool calling must give priority to connecting to the verification system and cross-departmental shared data platform.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to tool calling requirements of different business links, and automatically select corresponding tools such as family economic verification and data pulling |
| `functionCall` | `Force call specified tools` | Minimum living security review must strictly call preset cross-departmental verification tools. Avoid automatic calling of non-business-related tools |
| Tool call timeout duration | `600 seconds` | Cross-departmental data pulling requires a long response cycle. This matches the business time consumption of multi-data source aggregation. FastGPT v4.17.0 supports this duration configuration |
| Number of items returned per tool call | `Top 10 items` | Covers core verification fields such as family income, property and member relationships. Avoids truncation of key information |
| Tool call result verification switch | `Enabled` | Ensures the integrity and accuracy of returned data. Complies with compliance requirements for minimum living security review |
| Scheduled trigger frequency | `Once per month` | Matches the rhythm of monthly business data updates. Avoids ineffective repeated calls |

## Three common errors
- Phenomenon: Tool calls in the workflow run normally in debug mode, but an error occurs after switching to runtime mode. Cause: The permission mapping of cross-departmental data sources is not correctly configured in runtime mode. The service cannot access the resident family economic status verification system interface.
- Phenomenon: Connection failure occurs when calling the family economic status verification report parsing tool. Cause: The locally deployed parsing tool container did not correctly expose ports. Or the network policy between the container and FastGPT service restricts communication.
- Phenomenon: Error logs indicating no configured model appear during workflow operation, such as gpt-4o-mini call failure. Cause: The default automatic model call switch in the workflow is not turned off. The system attempts to call a model that was not pre-configured.

## How to confirm the configuration is correct
- Manually trigger the tool call process. Check whether cross-departmental shared data and verification system results can be successfully pulled.
- View tool call logs. Confirm that the returned data fields match the core information required for minimum living security review such as family income and property.
- Simulate a monthly data update scenario. Verify whether the scheduled tool call executes normally at the preset frequency.
- Test abnormal data input. Confirm that the tool call result verification switch can normally intercept non-compliant returned content.
