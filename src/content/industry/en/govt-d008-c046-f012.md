# Business Process Guidance for Social Assistance and Minimum Living Standard Guarantee Audit: Deployment and Upgrade

## What the data for this category looks like
Business data for social assistance and minimum living standard guarantee audit is primarily sourced from the low-income population dynamic monitoring platform, resident family economic status verification system, and shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities.
Update frequency for this data is monthly.
Daily processed documents include minimum living standard guarantee application forms, family economic status verification reports, household survey forms, democratic review records, public notice materials, and assistance approval forms.
Data fields cover family income, property status, member relationships, approval progress, and other relevant items.
There are no unified fixed units; values vary based on specific business fields.

## What constraints these characteristics impose on the deployment and upgrade phase
Cross-departmental multi-source data access is required. Configure connection parameters for multiple data sources during deployment. This ensures accurate data synchronization.
Monthly update frequency requires setting trigger configurations for scheduled synchronization tasks. This avoids data lag.
Sensitive business document storage requires configuration of internal network storage paths. This prevents data leakage.
Error consequences are severe. Strengthen authentication and failure retry configurations. This prevents mass petitions or fund recovery issues caused by incorrect or missed guarantee approvals.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom password@internal Redis address:6379/0` | Stores session cache and permission verification credentials, adapts to the internal network deployment environment of civil affairs systems to ensure session security |
| `MONGODB_URI` | `mongodb://username:password@internal MongoDB address:27017/fastgpt?authSource=admin` | Stores business process data and document indexes, meets monthly updated data storage requirements |
| `STORAGE_S3_ENDPOINT` | `internal object storage address:9000` | Connects to civil affairs system internal network storage to prevent sensitive documents such as minimum living standard guarantee applications and verification reports from being leaked externally |
| `FILE_TOKEN_KEY` | Random 32-character generated string | Generates file access authentication tokens to prevent unauthorized personnel from accessing documents related to assistance business |
| `FE_DOMAIN` | Internal network deployed FastGPT frontend address | Configures frontend access domain name, adapts to civil affairs system internal network access scenarios |

## Three common mistakes
- After deploying FastGPT v4.17.0 locally, an error `Cannot read properties of undefined` occurs when using pdf-marker to process minimum living standard guarantee application forms. The cause is incorrect configuration of `FILE_TOKEN_KEY`, leading to failed file reading permission verification.
- After deployment, monthly low-income population dynamic monitoring platform data cannot be synchronized. The cause is incorrect access permission configuration for `MONGODB_URI`, leading to database connection timeout or rejection.
- After configuring a knowledge base sharing link, it can be accessed arbitrarily without identity authentication. The cause is incorrect disabling of the default identity verification logic, which does not comply with civil affairs business security specifications.

## How to confirm the configuration is correct
- Use the redis-cli tool to connect to `REDIS_URL`, test whether cache data can be written and read normally to confirm the session cache configuration takes effect.
- Try to connect to the database using `MONGODB_URI`, insert a test business process record to confirm data can be stored and read normally.
- Upload a minimum living standard guarantee application form document, use the generated `FILE_TOKEN_KEY` access link to confirm only authorized users can view the document normally.
- Check scheduled synchronization task logs to confirm monthly cross-departmental data synchronization tasks can be triggered and executed normally.

The values provided are common starting points and should be evaluated against the user's own samples.
