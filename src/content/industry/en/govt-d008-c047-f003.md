# Business Process Guidance for Administrative Penalty Case Handling: Multi-turn Dialogue and Prompt Engineering

## What data falls under this category
Data for this category comes from administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information public disclosure system, and departmental supervision databases of law enforcement agencies including market supervision, ecological environment, transportation, emergency management, and urban management. The update frequency is daily. Daily documents include on-site inspection records, interrogation records, evidence lists, administrative penalty prior notice letters, hearing notice letters, penalty decision letters, and service receipts. The core focus is forming a traceable evidence chain around illegal facts and penalty decisions, to meet compliance requirements for case review.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
Fixed document formats and compliance requirements for law enforcement cases require multi-turn dialogue to be accurately bound to the context of the current case, to avoid interference from cross-case information. The daily update property of the data requires the knowledge base synchronization mechanism to match the daily update rhythm, ensuring that the latest case information can be called during dialogue. The limited scale of core evidence and documents means that the recall range must be strictly limited to the documents of the current case. Irrelevant accumulation of historical dialogue content must be avoided to prevent performance degradation. In addition, compliance requirements require prompts to clearly guide the model to reference content that complies with law enforcement norms, and avoid expressions that do not meet discretionary benchmarks.

## How to configure the setup
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind the unique identifier of the currently handled case, use a fixed session ID | Ensure multi-turn dialogue only associates with the context of the current administrative penalty case, to avoid confusion from cross-case information |
| Maximum context length | 800–1200 characters, calibrated via actual testing | The length of core documents for administrative penalty cases falls within this range. Excessive length will introduce irrelevant historical interference, while insufficient length will lose key record information |
| `variables` | Pass two fixed variables: case number and law enforcement subject type | Accurately match knowledge base documents corresponding to the target case, and avoid recalling content from non-current law enforcement scenarios |
| Single search limit | Top 5 results | The number of core evidence and documents for law enforcement cases is limited. Excessive recall will distract the model |
| Context clearing rule | Trigger clearing when a case completion identifier appears in `messages` | Avoid historical dialogue from completed cases interfering with new case handling guidance |

## Three common configuration errors
- Question and answer performance degrades after multiple consecutive dialogue turns, shown as reduced recall accuracy of case details and deviant model responses. The cause is failure to bind a fixed case context via `chatId`, with irrelevant information from historical dialogue interfering with the recall logic for the current request.
- The context clearing logic fails to trigger, or partial historical dialogue remains after triggering. The cause is failure to associate the status field in `messages` as the trigger condition, or incorrect trigger condition setup.
- Attempts to disable knowledge base references in dialogue result in retained knowledge base document snippets or links. The cause is failure to explicitly prohibit referencing knowledge base content outside the current case in the prompt, or the configuration not taking effect.

## How to confirm the configuration is correct
- Start a new case handling dialogue, enter the target case’s number, and check whether the model only recalls documents corresponding to that case.
- Conduct multiple consecutive inquiries about the case, and check whether the model can consistently reference record details or evidence information mentioned in earlier dialogue.
- Trigger the case completion identifier, check whether the context is cleared, and newly initiated dialogue no longer associates with historical information from the old case.
- Attempt to call relevant information from a non-current case, and check whether the model fails to recall the content or explicitly indicates that the content cannot be obtained.
