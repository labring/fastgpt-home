# Administrative Penalty Case File Handling: Business Process Guidance - Tool Calling and Plugins

## What the data for this category looks like
This category's data originates from administrative law enforcement case handling systems, law enforcement recorder footage, the National Enterprise Credit Information Publicity System, and departmental supervision databases. The update frequency is daily. Commonly processed documents include on-site inspection records, questioning transcripts, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, delivery receipts, and more. Core fields include illegal fact descriptions, discretionary benchmark matching results, legal clause citations, legal review status, and delivery and archiving markers. The character count per document varies widely, ranging from hundreds to tens of thousands of characters.

## What constraints do these characteristics impose on the tool calling and plugins link
Multi-source data sources include unstructured law enforcement footage, semi-structured transcript documents, and structured supervision database entries. Configure tool calling to adapt to multi-source data format parsing. This ensures correct extraction of all data types. Daily updated supervision data requires tool calling to have real-time synchronization capabilities, preventing use of expired enterprise credit information. The wide character count range per document means tool calling context length must adapt to case file content of varying sizes. Ensure extraction accuracy for fields related to penalty decisions, avoid omission of key markers such as legal review status, and prevent case file review failure issues.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `"auto"`, trigger condition: no matching results in the knowledge base | Prioritize using the internal law enforcement knowledge base to generate guidance content, call external tools only when no relevant data is available |
| `functionCall` | Enable forced tool calling mode, only allow calling preset law enforcement data query plugins | Ensure tool calling only targets legitimate supervision data sources, preventing unauthorized tool calls |
| Global variable configuration | Bind law enforcement agency code and case handling date as fixed global variables | Match the department-specific supervision database for this category's data sources, avoiding cross-agency data confusion |
| Single tool call timeout | Set to `60 seconds` | Adapt to real-time data query response requirements in law enforcement scenarios, avoiding excessive waiting that affects case handling efficiency |
| Knowledge base recall upper limit | Set to `top 3` | Focus on core law enforcement-related data, avoiding redundant information interfering with penalty decision generation |
| Tool call result caching | Enable daily caching mechanism | Match the daily update frequency of this category's data, reducing resource consumption from repeated calls |

## Three common mistakes
- Symptom: No preset global variables are included during tool calling, resulting in incorrect cross-agency supervision data being queried. Cause: Agency-specific parameters such as law enforcement agency code were not bound in the global variable configuration, so the corresponding data source cannot be automatically matched during tool calling.
- Symptom: After enabling the specified reply configuration, the tool still automatically generates non-preset natural language replies, and does not perform tool calling as configured. Cause: The `toolChoice` parameter was not correctly set to forced calling mode, allowing the AI to independently select the reply logic.
- Symptom: After calling the reranking plugin, GPU video memory quickly grows to 6-7G and multiple cards are occupied simultaneously. Cause: The number of documents called per single run was not limited, and too many case file segments loaded by the plugin caused video memory resource overflow.

## How to confirm the configuration is correct
- Log in to the FastGPT v4.17.0 backend, initiate a simulated case handling request, and check whether preset global variable parameters are automatically included during tool calling.
- Trigger a query with no matching knowledge base, confirm that only preset specified replies are output, and no tools are called.
- View the tool calling logs, confirm that only preset law enforcement data query plugins are called, and no unauthorized tools are triggered.
- Start the reranking plugin and initiate a batch query, monitor GPU video memory usage, and confirm no rapid growth occurs.
