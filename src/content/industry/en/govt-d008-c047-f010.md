# Business Process Guidance for Administrative Penalty Case File Handling: Knowledge Base Retrieval and Recall

## What this category of data looks like
The data for this category comes from administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information publicity system, and departmental supervision databases. The update frequency is daily. Daily documents include on-site inspection records, interrogation records, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, and service receipts. Core fields cover illegal fact determination, discretionary benchmark application, and penalty decisions. Each document links to the corresponding law enforcement subject, case number, and law enforcement personnel information. The structure is fixed and must comply with case file archiving specifications.

## What These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Data sources are scattered, and formats vary. Retrieval systems must support structured case handling system data and unstructured law enforcement footage transcribed text, which requires multi-source adaptation capabilities. The daily high-frequency update demand requires retrieval links to have low latency, avoiding disruptions to case handling workflows. Documents center on penalty decisions, so systems must accurately retrieve content linked to illegal facts and legal provisions. Retrieval results must comply with case file compliance rules to avoid referencing invalid or expired law enforcement bases. Case files must form a complete evidence chain, and retrieval results must be traceable back to original document sources to meet legal review traceability requirements.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, adapted to the retrieval needs of administrative penalty case file handling.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the rigor requirements for law enforcement documents, avoids retrieving irrelevant non-penalty law enforcement documents |
| `limit` | Top 8 entries | Balances retrieval result comprehensiveness and case handling personnel reading efficiency, aligns with the single reference volume for case file review |
| `searchMode` | Hybrid retrieval | Covers both semantically related discretionary benchmarks and full-text matched specific law enforcement provisions, adapts to multi-dimensional retrieval needs for penalty case files |
| `usingReRank` | Enabled | Performs secondary ranking on initially retrieved results to ensure evidence and documents most relevant to the current case appear first |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands retrieval terms based on core elements of the current case, covering colloquial expressions from law enforcement recorder footage transcriptions |
| `collectionIds` | Bind to dedicated knowledge base collections corresponding to law enforcement jurisdictions | Isolates case file data from different law enforcement agencies to avoid interference from cross-departmental retrieval |

## Three Common Mistakes
- Symptom: A "Connection error" error appears during retrieval. Cause: Knowledge base and vector database connection parameters are not configured correctly, or the vector database instance is offline.
- Symptom: Fewer than the preset number of results return in a single retrieval. Cause: The `similarity` threshold is set too high, filtering out eligible associated law enforcement documents.
- Symptom: More than 30 knowledge bases cannot be added. Cause: pgvector is used as the vector storage engine, which has default configuration limits. Adjust database connection parameters or change the storage configuration.

## How to Verify Configurations Are Correct
- Upload a standard interrogation record document, initiate a retrieval, and verify that associated documents such as on-site inspection records and evidence lists of the same case type can be retrieved.
- Check the source field of retrieval results to confirm each result links to the preset law enforcement knowledge base collection, with no cross-departmental irrelevant data.
- Adjust similarity-related configurations, observe changes in retrieval result quantity, and confirm configuration parameters take effect.
- Simulate a high-frequency update scenario to verify retrieval link response speed meets case handling workflow requirements.

The values provided are common starting points and should be measured against the reader's own samples.
