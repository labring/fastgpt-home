# Business Process Guidance for Administrative Penalty Case Handling: Deployment and Upgrade

## What the data for this category looks like
The data for this category comes from administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information public disclosure system, and departmental supervision databases. The update frequency is daily. Commonly processed documents include on-site inspection records, interrogation records, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, and service receipts. This covers unstructured text, images, and structured associated information throughout the law enforcement process. Data is organized with case as the core unit, including fixed fields such as law enforcement subject, illegal facts, and penalty basis.

## What constraints these characteristics impose on the deployment and upgrade phase
The multi-source heterogeneous data sources, high-frequency update rhythm, and strict case handling compliance requirements of this category impose multiple constraints on the deployment and upgrade phase. Multi-source system docking requires cross-source data permission verification to prevent unauthorized access to law enforcement sensitive data. Daily updated law enforcement data requires incremental synchronization tasks to ensure data timeliness. Diverse document types require adapted mixed storage and parsing strategies for text and images. Errors in case handling data will lead to serious consequences such as penalty revocation. Deployment and upgrade must reserve gray release windows to avoid disrupting normal case handling workflows.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Point to a dedicated instance storing case text and law enforcement image metadata | Used to store unstructured case documents and law enforcement data, adapting to the storage needs of this category's multi-source heterogeneous data |
| `PG_URL` | Point to a dedicated instance storing structured fields such as law enforcement subject and case number | Used to associate structured law enforcement information, ensuring consistent querying of fields such as case number and law enforcement subject |
| `REDIS_URL` | Configure as a local private Redis cluster, set an expiration time of `600 seconds` | Used to cache frequently queried law enforcement baseline data, reducing access pressure on multi-source systems |
| `STORAGE_S3_ENDPOINT` | Point to a local object storage endpoint, configure a single-file upper limit of `1000 MB` | Adapts to the storage needs of law enforcement recorder footage and complete case files |
| `FILE_TOKEN_KEY` | Configure as a randomly generated 32-bit key | Used to sign file access tokens, ensuring secure access permissions for internal case handling personnel |
| `FE_DOMAIN` | Configure as the internal domain name of the law enforcement agency | Restricts front-end access scope, ensuring compliance with internal usage of case handling data |

## Three Common Mistakes
- Symptom: A `permission denied while trying to connect to` error occurs during local deployment. Cause: Access permissions for the corresponding database or storage service are not configured, or the startup user lacks file read/write permissions.
- Symptom: The front-end page fails to load properly in older browsers such as 360 Extreme Browser. Cause: The compilation target version is not adjusted. The default compilation output is compatible with ES2020 and above standards, which older browsers cannot parse.
- Symptom: Uploaded law enforcement case files cannot be found in the specified path, or a public network transmission risk prompt appears. Cause: `STORAGE_S3_ENDPOINT` is not configured to point to local storage. Using a public storage service by default may lead to data leakage, or the file storage root directory is not specified correctly.

## How to Confirm the Configuration is Complete
- Run the database connection test script to verify that the instances specified by `MONGODB_URI` and `PG_URL` can read and write data normally.
- Upload a simulated on-site inspection record file, and check whether the corresponding file is generated in the storage path pointed to by `STORAGE_S3_ENDPOINT`.
- Access the front-end address configured in `FE_DOMAIN`, and verify that the page loads normally in older browsers such as 360 Extreme Browser.
- View the Redis cache log to confirm that the cache expiration time of frequently queried law enforcement baseline data matches the configured value.

The values provided are common starting points and should be measured against the reader's own samples.
