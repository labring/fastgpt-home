# Administrative Licensing and Approval Business Process Guidance: HTTP Interfaces and External Systems

## What this category of data includes
This category of data is sourced from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository. Data is updated daily. Daily associated documents include service guides, application forms, acceptance notices, correction notifications, administrative licensing approval decisions, and license certificates.

Data uses statutory administrative licensing items as core entries. Each entry includes structured fields: item unique identifier, handling conditions, application material list, approval process nodes, and electronic certificate association identifier. No additional custom extended fields are included.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multi-source data updated daily requires HTTP interfaces to support integration with multiple external approval systems and government service platforms. Configure scheduled pull tasks at the daily synchronization frequency to avoid data lag.

Data is bounded by statutory licensing items. Interface requests must carry the item unique identifier as a core parameter. This ensures returned content strictly matches the statutory handling conditions and material list for the corresponding item.

Fixed structured fields require `responseData` to be configured to return only necessary fields. This prevents material verification errors caused by field mismatches.

Ensure interface call stability to avoid interruptions to cross-departmental certificate retrieval and material verification links due to call failures.

## How to configure settings
The following configurations are based on the interface settings of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication Configuration | `Bearer {FastGPT-assigned API key}` | Complies with standard authentication specifications for government service interfaces, ensuring secure external system calls |
| Variable Binding | `{"target_approval_item": "{item code}", "required_materials": "{material list field}"}` | Matches structured data fields of administrative licensing items to accurately locate the corresponding approval item |
| Response Filtering | Return only item handling process nodes, material verification rules, and certificate association identifiers | Filters irrelevant data to reduce external system processing load, following the minimum necessary principle for government data sharing |
| Interface Call Timeout | 600 seconds | Cross-departmental administrative licensing data retrieval takes extended time. 600 seconds covers most conventional scenarios; adjust based on actual measurements |
| Retry Strategy | Retry 2 times after failure, 30 second interval | Addresses temporary call fluctuations in government systems, preventing process interruptions from single failed calls |
| Maximum Response Data Length | 1000 characters | Prevents oversized returned data from causing external system processing timeouts, adapting to transmission limits of government interfaces |

## Three common misconfigurations
- The interface returns an empty result, and the external system's material verification link cannot start. The cause is incorrect binding of the item code parameter in `variables`, so the interface cannot locate the corresponding approval item.
- Interface calls continue to time out, with the page showing a loading state with no response. The cause is an overly short timeout configuration that fails to cover the actual time required for cross-departmental electronic certificate retrieval.
- Returned response data includes irrelevant internal approval logs. The cause is missing response filtering rules, so all content returned by the interface is forwarded directly.

## How to confirm the configuration is correct
- Call the interface with a test administrative licensing item code, and verify that returned process nodes match the public service guide for the corresponding item.
- Review interface call logs to confirm the `Authorization` parameter is correctly carried with the authentication configuration, with no authentication failure errors.
- Simulate an interface call timeout scenario, and confirm the system triggers the configured retry mechanism without direct failure.
- Compare the external system's field mapping table to confirm returned interface fields fully match the external system's receiving fields.
