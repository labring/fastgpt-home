# Administrative Licensing and Approval Business Process Guidance: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The core data for this category comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate database, and is updated daily. Daily documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision letters, and license certificates. Data is bounded by statutory licensing items, including fields such as item codes, handling conditions, and application material lists. The document structure for each item strictly matches the official published handling process.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
Since the data for this category is updated daily, the prompts for multi-turn dialogue must be synchronized with the latest administrative licensing item lists and service guides to avoid using expired handling rules. The data includes multiple types of official documents, so the dialogue must accurately identify content submitted by users such as application materials and correction notification letters, and cross-check them one by one against the preset material list. Since licensing results are directly linked to statutory handling time limits and compliance requirements, the dialogue must strictly match the handling conditions and statutory basis for the item, and must not deviate from statutory rules. At the same time, electronic certificate data retrieved across departments must have their legality verified in real time during the dialogue, to ensure the entire guidance process complies with government service compliance requirements.

## Configuration Settings

| Context window size | First 1500–2000 characters | Covers multi-turn dialogue content for administrative licensing handling, including user-submitted material descriptions and historical consultation records |
| `messages` processing logic | Retain the most recent 8 turns of content in dialogue chronological order | Filters expired irrelevant dialogue, focusing on core needs of the current handling stage |
| `variables` injection timing | Bind the current item during dialogue initialization | Ensures prompts always call the latest administrative licensing item data, matching the daily updated data source |
| Maximum retry count | 3 times | Corresponds to the conventional number of correction notifications, avoiding overly long wait times that impact government service handling efficiency |
| Multi-turn trigger condition | Trigger based on handling keywords in user input | Matches step-by-step consultations for administrative licensing handling, avoiding false triggers |
| Question optimization switch | Enabled | Corresponds to vague user material descriptions, automatically completing standardized expressions compliant with service guides |

## Three Common Mistakes
- Phenomenon: A 400 invalid image error is returned when using multi-modal dialogue to process user-uploaded application material images. Cause: Multi-modal input format verification is not properly configured, and non-compliant image formats or sizes are not filtered.
- Phenomenon: The orchestrated workflow works normally in debug preview, but only responds to the first round of dialogue after connecting to an external dialogue interface. Cause: The persistence logic for `chatId` is not properly configured, resulting in a new session ID being generated for each round of dialogue, making it impossible to continue the context.
- Phenomenon: After connecting to a locally deployed large model, the model is automatically switched to another preset model during dialogue. Cause: The bound large model parameter is not locked in the configuration, causing the system to call the default third-party model.

## How to Confirm Proper Configuration
- Initiate a simulated consultation, input the material list for an administrative licensing item, and check whether the reply includes the latest handling requirements for that item.
- Submit a multi-turn dialogue, check whether the context retains the previously submitted material information, with no content loss.
- Check whether `variables` in the configuration are bound to the exclusive data of the current item, confirming that the injection timing is correct.
- In the debug interface of FastGPT v4.17.0, upload a compliant application material image, and check whether the corresponding handling guidance steps can be triggered normally.
