# Administrative Licensing and Approval Business Process Guidance: Deployment and Upgrade

## What the Data for This Category Looks Like
The data for this category mainly comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository. The update frequency is daily. Commonly processed documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision documents, and license certificates. The data is bounded by statutory licensing items, requiring matching of legal basis and handling conditions item by item, linking cross-department approval processes and certificate information. Only standard business process and result fields are retained, with no extra custom statistical fields.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Since data sources cover cross-department government systems and update daily, configure a stable cross-department data source synchronization link during deployment to avoid process guidance failure due to data source interruption. Daily document types are diverse and need to strictly match legal basis, so reserve sufficient field verification configuration space during deployment to ensure one-to-one correspondence between input materials and list fields. Calling the electronic certificate repository must comply with government data security specifications; during upgrade, synchronously update permission verification rules to prevent data leaks. At the same time, the risk of overdue completion of approval requires configuring timeout alerts and process tracking nodes during deployment to ensure traceability of each link and avoid compliance issues.

## How to Configure the Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Configuration | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Government cloud exclusive cluster address, set maximum connection pool size to 50 | Stores administrative licensing item lists and approval records, needs to ensure high availability and security of government data |
| `REDIS_URL` | Government intranet cache node address, set cache validity period to 86400 seconds | Caches daily updated item database data to reduce cross-source call frequency, adapts to the daily update rhythm |
| `FE_DOMAIN` | Secondary domain name bound to the government service portal | Deployed within the government portal to ensure user access paths comply with government platform specifications |
| `FILE_TOKEN_KEY` | Key string using the national cryptographic SM4 algorithm | Encrypts temporary links for uploaded service materials to ensure data security during electronic document transmission |
| `STORAGE_S3_ENDPOINT` | Intranet address of the government cloud object storage service | Stores electronic certificates and documents during the approval process, complies with government data storage compliance requirements |

## Three Common Mistakes
- Cannot access the process guidance configuration interface after startup, with interface request timeout prompt. Cause: `MONGODB_URI` is not configured, or the address points to a non-government cloud cluster, resulting in failure to normally load item database data.
- Configuration error occurs after adding a third-party model, unable to call it normally. Cause: `FILE_TOKEN_KEY` is not aligned with the encryption rules of the model key, or the key configuration is not written to the environment variable file.
- Cannot access the oneAPI management page after local deployment. Cause: Dependency installation and static resource compilation were not completed through the officially specified deployment process, and the front-end packaging step was missing when directly starting with pnpm d.

## How to Confirm the Configuration Is Complete
- Access the path bound to `FE_DOMAIN`, check whether the initial list of administrative licensing items can be loaded.
- Run the environment variable verification script to confirm that configuration items such as `MONGODB_URI` and `REDIS_URL` have been correctly written to the running environment.
- Upload a standard service guide document, check whether the matching logic of the process guidance can be triggered, and return the corresponding handling steps and material requirements.
- Call the oneAPI model test interface to confirm that the configured model key and service address can normally return responses.
