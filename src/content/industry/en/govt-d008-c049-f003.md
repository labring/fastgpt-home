# Business Process Guidance for Legality Review of Regulatory Documents: Multi-turn Dialogue and Prompts

## What this category of data looks like
This category of data is primarily sourced from regulatory and rule databases, higher-level law databases, departmental policy document databases, and administrative regulatory document filing systems, with irregular update frequencies. Daily processed documents include draft regulatory documents, drafting explanations, legality review opinions, summaries of solicited comments, filing reports, and similar materials. The length of a single document typically ranges from 1000 to 5000 characters. Core fields include article numbers, issuing entities, rights and obligation clauses, comment feedback entries, and similar items. There are no unified fixed unit-type fields, and the core focus is on the authority, procedures, and article content of policy formulation.

## What constraints do these characteristics impose on the "multi-turn dialogue and prompts" link
Data sources are scattered and updates have no fixed cycle, so the latest content from different databases must be dynamically called during multi-turn dialogue. Prompts must clearly define the retrieval scope to avoid calling unauthorized data sources. The span of document lengths and diverse structures require step-by-step guidance to upload or specify corresponding document types during multi-turn dialogue, to avoid confusion between drafts and review opinions. Core review links involve article comparison and opinion aggregation. Multi-turn dialogue must break down tasks step-by-step according to review procedures, avoid inputting content that exceeds context limits in one go, and retain historical review records for compliance traceability.

The following configurations are based on FastGPT v4.17.0 and are adapted to the business characteristics of this category.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 1000–1500 characters | Matches the average length of regulatory document articles, avoids excessively long single chunks that affect retrieval accuracy |
| Context Window Upper Limit | 8000–12000 token | Adapts to the storage needs of multi-turn review dialogues and multiple documents, reserving sufficient space for tool call results |
| `variables` | Bind preset data source IDs of regulatory databases and filing systems | Ensures accurate calling of authoritative data sources for this category during multi-turn dialogue, avoiding retrieval scope deviations |
| `messages` | Split historical messages according to review procedures, only retain context for the current link per turn | Reduces model response delays caused by long contexts and improves dialogue efficiency |
| `chatId` | Assign independent session IDs for each single review task | Ensures dialogue contexts of different review tasks do not interfere with each other, facilitating subsequent compliance traceability |
| Session History Cleanup Threshold | Retain review dialogue logs from the past 30 days | Meets compliance archiving requirements of administrative departments while controlling storage space usage |

## Three common mistakes
- Phenomenon: After uploading a Markdown format attachment of a draft regulatory document, embedded images cannot be displayed properly. Cause: Attachment processing rules are not configured, and the image domain name is not bound to `variables` in the dialogue context, resulting in loss of domain name information for image links.
- Phenomenon: After triggering the higher-level law comparison tool during multi-turn dialogue, the output content includes original requests and response logs of the tool call. Cause: The log output switch for tool calls is not turned off, causing non-review content to be mixed into the final review result.
- Phenomenon: After uploading multiple draft regulatory documents, the dialogue response times out or content is truncated. Cause: A reasonable context window upper limit is not set, and long documents are not chunked, resulting in exceeding the context length supported by the model.

## How to confirm the configuration is correct
- A test draft regulatory document is uploaded, and whether the dialogue interface automatically recognizes the document type and loads the corresponding review steps is verified.
- The higher-level law comparison tool is triggered, and it is confirmed that the output content only includes legality review conclusions, with no original logs of tool calls.
- A document exceeding the default context length is uploaded, and whether the system automatically triggers chunking and prompts chunking information is verified.
- Two independent review tasks are created, and whether the session management interface displays two non-overlapping `chatId`s, with dialogue contexts not interfering with each other, is verified.

The values provided are common starting points and should be measured against the reader's own samples.
