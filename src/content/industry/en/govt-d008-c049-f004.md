# Business Process Guidance for Legality Review of Regulatory Documents: Workflow Orchestration

## What This Category of Data Entails
Data processed in this category primarily comes from regulatory and rule repositories, higher-level law databases, departmental policy document repositories, and administrative regulatory document filing systems. Update frequency is irregular. Documents circulated daily include regulatory document drafts, drafting explanatory statements, legality review opinions, solicited comment summaries, and filing reports. Processing entities include judicial administrative departments, departmental legal affairs offices, and policy and legal affairs positions in government offices. This data focuses on legality review for the formulation of abstract policy rules, and differs from case-by-case administrative law enforcement process handling.

## What Constraints These Characteristics Impose on Workflow Orchestration
Data sources are scattered and updates have no fixed cycle. Workflows must support dynamic mounting of multiple data source nodes to adapt to document retrieval from different sources.
Daily document types are diverse. Field mapping rules must be configured to ensure review parameters from different documents can be accurately passed.
Core review links account for a high proportion of total processing time. Workflows must be split into independent nodes such as higher-level law comparison, rights and obligations review, and opinion summary, to support manual intervention for verification.
Errors directly affect policy release and implementation. Workflows must include pre-check and exception alert nodes to block non-compliant process steps.

## Configuration Settings
All configurations below are implemented using the workflow feature of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Data source node configuration | Mount separately for regulatory and rule repositories and filing systems | Data sources are scattered, requiring precise connection to different official data channels |
| Variable mapping rules | Bind the `variables` field to match document fields | Daily circulated document types are diverse, requiring accurate transfer of parameters required for review |
| Manual review node | Set as a post-node for higher-level law comparison and opinion summary links | Core review links require manual intervention for verification to ensure legality |
| Exception alert trigger | Push notifications when the node with `nodeId` set to exception verification is triggered | Process errors can affect policy release, requiring timely response to exceptions |
| Single request timeout threshold | 600-900 seconds | Time consumption for data retrieval and comparison links fluctuates, with a reasonable range calibrated based on actual testing |
| Single file upload limit | 1000 MB | Regulatory document drafts and attachments typically fit this size range, aligning with business norms |

## Three Common Misconfigurations
- A `Failed to create post presigned url` error occurs when uploading files via the workflow. The cause is incorrect configuration of permission parameters for the file storage node, which prevents generation of upload pre-signed URLs.
- Variable references in the knowledge base search module do not take effect. The cause is failure to bind the `variables` field to corresponding fields of the review document, which prevents correct transfer of parameters to the search module.
- Process nodes get stuck during flow. The cause is failure to set trigger conditions for manual review nodes, which prevents core review links from entering manual verification steps.

## How to Confirm Configurations Are Correct
All verification steps below are implemented using the workflow feature of FastGPT v4.17.0.
- Test retrieving documents from different sources to confirm that data source nodes can connect normally and read corresponding data.
- Upload a regulatory document draft to confirm that the file upload node can complete upload successfully, with no pre-signed URL errors.
- Trigger the exception verification node to confirm that the system can push alert notifications.
- Advance the core review link to confirm that the manual review node can trigger normally and proceed to the next link.
