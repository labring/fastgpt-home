# Business Process Guidance for Legality Review of Regulatory Documents: Tool Calling and Plugins

## What This Category of Data Looks Like
This category of data originates from regulatory and rule repositories, higher-level law databases, departmental policy document repositories, and administrative regulatory document filing systems. Update frequency is irregular. Daily processed documents include regulatory document drafts, drafting explanatory notes, legality review opinions, solicited comment summaries, and filing reports. Most documents use clause-based or paragraph-based text formatting. Some supporting materials include scanned attachment files. Data fields include document number, issuing authority, clause content, basis for drafting authority, and similar items. No unified fixed unit measurement fields are included.

## Constraints Imposed on Tool Calling and Plugins Workflows
Data sources are scattered, and updates follow no fixed schedule. Tool calling must adapt to access formats for multi-source heterogeneous data, and support configuration logic for on-demand pulling or scheduled synchronization. Daily processed documents include plain text and scanned attachment images. Tool calling must support both text parsing and multimodal visual analysis capabilities. Core review steps require comparison against higher-level laws and authority bases. This means tool calling must accurately match clause content and drafting authority rules, and limit the relevance scope of calling results. Since errors directly impact policy release and filing progress, tool calling failure handling must include retry and abnormal alert mechanisms to avoid delaying review workflows.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multi-type tool calling requirements, no manual specification of specific tools needed, aligns with flexible calling requirements for multi-source data comparison in review scenarios |
| Tool Call Timeout | 300-600 seconds | The default value for this configuration item in FastGPT v4.17.0 is 120 seconds. Regulatory document review requires comparison across multiple scattered data sources, so single call duration is longer. This interval covers most data pulling and comparison workflows |
| `functionCall` | `enabled` | Requires calling external regulatory database interfaces. Enabling function calls enables parameterized precise data requests, improving review matching accuracy |
| Attachment Image Parsing Configuration | Enable multimodal visual model, 10 images per call maximum | Daily review materials often include a small number of attached scanned documents. This configuration adapts to conventional attachment parsing needs and avoids overloading single calls |
| Tool Call Result Filtering | Sort by content relevance, return top 3-5 entries | Regulatory document review needs to focus on core higher-level laws and authority bases. Excessive redundant results increase review burden. This range focuses on valid content |
| Abnormal Alert Trigger Condition | Trigger when data pulling failure errors occur | This type of error mostly stems from data source or interface anomalies, requiring timely notification of review personnel to troubleshoot issues |

## Three Common Misconfiguration Issues
- Symptom: Multimodal model returns `Failed to fetch` error when parsing attached images. Cause: Access permissions or data source whitelisting for image pulling are not configured, so the tool cannot download target image files from the filing system or local storage.
- Symptom: Tool call returns more results than expected. Cause: Result filtering rules are not set correctly, or configuration item values do not match review scenario requirements, leading to redundant data being included in the review workflow.
- Symptom: External regulatory database interface call returns no matching results. Cause: The `functionCall` parameter is not enabled, or call interface permissions and parameter formats are not configured correctly, so the tool cannot complete precise data requests.

## How to Verify Correct Configuration
- Submit test regulatory document drafts and supporting attachments, check image parsing records in tool call logs to confirm image pulling permission configurations are active.
- Trigger a tool call, verify that the number of returned results matches the preset filtering logic to confirm result filtering configurations are active.
- Manually call the configured external regulatory database interface, check if matching regulatory bases are returned to confirm function call related configurations are active.
- Simulate a data pulling failure scenario to confirm whether the abnormal alert mechanism triggers properly, confirming alert configurations are active.

The values provided are common starting points and should be measured against the reader's own samples.
