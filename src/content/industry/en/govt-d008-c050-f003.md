# Business Process Guidance for Fiscal Expenditure Performance Evaluation: Multi-turn Dialogue and Prompt Engineering

## Data Profile for This Category
Core data for this category comes from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Commonly processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Most documents are structured tables with dedicated fields such as project name, performance indicators, fund amount, and completion status. Handling entities include fiscal bureau performance departments, budget units, third-party evaluation institutions, and competent departments. Core handling links require associating data from multiple sources to verify the correspondence between fund expenditure and performance targets.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The annual update feature requires dialogue contexts to be bound by project cycles to avoid confusion across annual data. The fixed fields of structured documents require prompts to clearly guide the extraction of dedicated performance indicators, ensuring returned content aligns with business requirements. The verification need for multi-source data requires multi-turn dialogue to gradually guide users to provide different types of supporting materials, avoiding excessive one-time loading of content that causes interaction lag. Hierarchical differences among handling entities require dialogue to filter data by permissions, ensuring different roles can only access performance documents corresponding to their permissions. The splitting of core handling links requires dialogue to advance step-by-step through the processes of collecting supporting materials, verifying correspondence, and drafting rectification suggestions, simplifying user operations.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `messages` | Stored grouped by annual project, retain the last 15 dialogue contexts | Fiscal performance projects are archived annually to avoid confusion across project contexts, and control single-session load |
| `variables` | Bind two system variables: budget unit ID and project year | Data comes from the unified budget management system, accurately filter associated documents by unit and year |
| Maximum context length | 8000–12000 characters | Total character count of performance-related documents for a single year falls within this range, avoiding loading redundant content |
| Maximum matching documents per request | Top 3 | There are many supporting materials, prioritize returning content most closely aligned with performance targets and fund usage |
| `chatId` | Bind unique project identifier | Each performance project has an independent session, ensuring dialogue context only associates with the current project |
| Session timeout | 3600 seconds | Ensure dialogue for a single project handling process is not accidentally interrupted, adapts to typical handling cycles |

## Three Common Configuration Mistakes
- A 503 error appears when uploading documents via the dialogue box, but backend logs show the file upload was successful. Cause: The `chatId` bound to the session context is not associated with the current project's storage path, causing the uploaded file to fail to match the session storage correctly and triggering server verification failure.
- Dedicated fields from performance target forms cannot be extracted during dialogue. Cause: The prompt does not explicitly require extracting dedicated fields such as project name, performance indicators, fund amount, causing the model to return generic content.
- Context overflow occurs after multiple rounds of dialogue. Cause: The number of retained `messages` is not limited, causing historical dialogue to occupy excessive system resources and triggering content truncation or errors.

## How to Verify Correct Configuration
- Initiate a test dialogue, input "Please extract the performance targets for this project", confirm the returned content includes dedicated fields from the performance target form.
- Upload single-year performance supporting materials, confirm they load normally and match the dialogue context, with no 503 error.
- Initiate 10 consecutive dialogue rounds, confirm the `messages` context only retains the specified number of recent entries, with no overflow.
- Adjust the `variables` parameter for different budget units, confirm returned documents only associate with performance data from the corresponding unit.

The values provided are common starting points and should be measured against the reader's own samples.
