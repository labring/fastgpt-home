# Business Process Guidance for Fiscal Expenditure Performance Evaluation: Workflow Orchestration

## What this category of data looks like
Data for this category comes from the integrated budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Daily processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Data fields include performance target setting items, fund usage association records, supporting material association identifiers, evaluation scoring items, and rectification requirements. There are no uniform fixed unit requirements, and some fields must match the format specifications of the corresponding business systems.

## What constraints these characteristics impose on the "workflow orchestration" link
The annual update feature requires workflows to be configured with fixed-cycle trigger scheduling, with no need for high-frequency operation. Multi-source data requires orchestrating the order of cross-system data pull nodes to ensure budget data, payment records, and supporting materials are accessed sequentially per business logic. Multiple types of business documents require configuring differentiated parsing nodes to adapt to field extraction rules for different documents. The most time-consuming collection and verification link needs parallel processing nodes to simultaneously schedule verification processes for multiple supporting materials. The verification node must be linked to performance target and fund expenditure data to ensure accurate matching. If not, a preset exception handling branch will trigger.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow Trigger Mode | Scheduled trigger + manual trigger | Matches the annual data update feature, and accommodates temporary verification needs |
| `variables` | Bind project ID, performance target ID, fund payment order number | Used to associate multi-source business data and ensure context consistency |
| Parallel Processing Node Count | First 5 entries | Shortens the time spent on the collection and verification link, adapting to parallel processing of multiple supporting materials |
| Context Window | 8000–12000 characters | Accommodates the complete content of multiple annual business documents |
| Cross-system Timeout Threshold | 600 seconds | Adapts to the reasonable time required for cross-system data pulling |
| `nodeId` | Configure a unique identifier for each cross-system node | Facilitates workflow debugging and log tracking |

## Three common errors
- Phenomenon: The workflow runs normally in the runtime preview page, but returns no results when called from the chat page. Cause: The binding logic between the chat context and workflow input parameters is not configured, causing the chat page to fail to pass necessary business data.
- Phenomenon: When using a model that does not support function call, the workflow cannot automatically initiate a search combined with context, and the recalled business data is missing. Cause: No search trigger node adapted to non-function call models is set in the workflow, resulting in ineffective use of context information.
- Phenomenon: When there are many nodes in the workflow canvas, dragging operations experience significant lag with a response delay of several seconds. Cause: The installed FastGPT version is lower than v4.17.0, and the canvas rendering performance is not optimized, resulting in excessive resource consumption from rendering calculations for a large number of nodes.

## How to confirm the configuration is correct
- Manually trigger the workflow, pass single-year test business data, and check whether the execution order of each node and data flow conforms to business logic.
- Check the binding configuration of `variables`, confirm that core business fields such as project ID and performance target ID have been associated, to ensure correct association of multi-source data.
- Simulate a verification failure scenario, and check whether the error branch triggers a preset reminder or rollback process.
- View the node identifiers of the workflow, confirm that `nodeId` has been configured with a unique identifier for each cross-system node to facilitate debugging and log tracking.
