# Business Process Guidance for Fiscal Expenditure Performance Evaluation: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category comes from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Commonly processed documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Document fields include project identifiers, fund usage details, performance indicator items, supporting material association information, rectification feedback content, and more. The scale and format of individual documents vary, and some supporting materials may include multi-format attachments.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
The annual update frequency of data for this category means tool calls do not need to be triggered frequently, and long-cycle scheduled synchronization tasks can be configured. The requirement to integrate data from multiple sources means plugins must support connections to multiple external data sources such as the unified budget management system and business ledger systems, and adapt to the interface formats of different systems. The requirement to process multiple types of documents means plugins must have the ability to parse files in different formats, covering scenarios such as performance evaluation reports and supporting material lists. The strong association between document fields means key fields such as project identifiers and performance indicators must be accurately passed during tool calling to avoid data matching deviations. The closed-loop tracking requirement for rectification reports means plugins must link with business systems to update rectification status and synchronize feedback results.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to multiple tool calling scenarios, no manual specification of specific tools is required, and the appropriate performance data acquisition method can be automatically selected |
| `functionCall` | Enabled | Requires precise calling of external tools to obtain performance-related data, avoid generalized responses, and ensure results align with the business logic of fiscal expenditure performance evaluation |
| Tool call timeout | `600 seconds` | Reserve sufficient request response duration for integration with multiple system interfaces, adapt to the batch pulling requirements of annually updated data |
| Number of returns per tool call | `Top 3` | Focus on core performance indicators and supporting materials, avoid context overload that affects the model's judgment of performance data |
| Plugin format adaptation | Calibrated based on actual testing | Interface formats of different external systems vary, adjust configurations according to the actually connected unified budget management system, business ledger systems, and other systems |
| Plugin access permissions | Only allow access to performance-related data sources | Comply with fiscal data security specifications, limit the access scope of tool calls, and avoid leakage of sensitive fiscal data |

## Three Common Mistakes
- When calling a custom code plugin, AggregateError Code: ETIMEDOUT is returned. The cause is that a reasonable timeout period is not configured, or the external system response delay exceeds the preset threshold.
- Tool calls do not return expected performance data. The cause is that the project identifier field was not accurately passed, leading to deviations in cross-project data matching, which affects subsequent evaluation processes.
- The model cannot trigger the tool call flow. The cause is that the `functionCall` configuration is not enabled, so the model cannot recognize external tool call instructions.

## How to Confirm Proper Configuration
- Trigger the tool call flow, check whether project data from the corresponding system is successfully pulled, and verify the accuracy of field matching.
- Simulate a scenario where the external system has delayed responses, test the timeout logic of tool calls, and confirm that processing works normally after the `600 seconds` threshold is triggered.
- Check whether the `toolChoice` parameter is set to `auto`, verify that the model can automatically select the appropriate tool to complete performance data verification.
- Upload a performance self-assessment form, confirm that the plugin can correctly parse the performance indicator items in the document and associate corresponding supporting materials.

The values provided are common starting points and should be measured against the reader's own samples.
