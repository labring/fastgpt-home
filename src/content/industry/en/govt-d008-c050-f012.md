# Business Process Guidance for Fiscal Expenditure Performance Evaluation: Deployment and Upgrade

## What this category of data looks like
This category of data originates from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Commonly processed documents include performance target forms, self-evaluation forms, performance evaluation reports, supporting material lists, and rectification reports. Data fields cover project numbers, fund amounts, performance indicator completion values, supporting material association relationships, and more. There is no fixed unified unit; field units are adjusted based on the actual situation of each project.

## What constraints do these characteristics impose during deployment and upgrade
The annual update rhythm only supports low-frequency batch data import, eliminating the need for high-frequency real-time synchronization and reducing system resource usage. The requirement to process multiple types of government documents demands file storage and parsing configurations that adapt to various formats of official documents. The need to connect data from multiple systems requires flexible configuration of database, cache, and other connection parameters to ensure stable cross-system data reading. Additionally, data processing deviations may lead to low project scores, budget cuts, or accountability. Deployments must include fault tolerance and exception alert capabilities to avoid errors in critical links.

## Three Common Configuration Mistakes
- Phenomenon: An abnormal prompt appears every 30 minutes after Docker deployment, and the service recovers after restarting. Cause: Persistence parameters for `REDIS_URL` are not configured correctly, leading to failure to read cached data after expiration.
- Phenomenon: The system version still shows the old version number after running the upgrade script. Cause: The version file directory of the container image is not mounted correctly, so the upgrade script cannot overwrite the old version configuration.
- Phenomenon: After importing performance supporting materials, the model cannot generate evaluation conclusions based on the material content. Cause: The correct key for `FILE_TOKEN_KEY` is not configured, so vector data parsed from files cannot be properly associated with the knowledge base.

## How to Verify Successful Configuration
- Execute the database connection test command to verify that the configurations for `MONGODB_URI` and `PG_URL` can connect normally.
- Upload a performance self-evaluation form document to check whether the `STORAGE_S3_ENDPOINT` configuration can store and read files normally.
- Review system logs to confirm that there are no timeout errors for `REDIS_URL` connections.
- Access the business process guidance page corresponding to `FE_DOMAIN` to confirm that the page loads without path errors.
