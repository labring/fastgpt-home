# Business Process Guidance for Road Transport Operation Licensing: Tool Calling and Plugins

This document applies to FastGPT v4.17.0.

## What this category of data looks like
The data for this category mainly comes from road transport administration systems, the national public service platform for dynamic information of road transport vehicles, and vehicle and practitioner databases. The update frequency is daily. Commonly involved documents include operation license application materials, vehicle technical files, driver qualification materials, work safety management system documents, and road transport operation license certificates. Data fields include the unified social credit code of the operating entity, vehicle license plate number, practitioner qualification level, safety management system entries, and other items. There are no unified fixed units, and some fields must match the qualification coding rules preset by government service systems.

## What constraints these characteristics impose on the "tool calling and plugins" link
Most data sources are government systems. Follow interface permission verification rules when calling these systems. Daily updated data sources require setting a reasonable synchronization period for tool calls, to avoid frequent requests exceeding government interface rate limits. There are various document types. Configure corresponding parsing rules for different documents. Extract specific qualification fields from vehicle technical files, driver materials, and other documents. The verification link relies on cross-verification of multi-source data. Tool calls must support retrieving information from multiple data sources at the same time, to ensure the completeness of verification. Use the `functionCall` configuration to enforce verification of the field format returned by tools, to ensure extracted qualification information meets approval requirements. Tool call failures directly relate to licensing approval results. Trigger a clear retry mechanism and exception alert when tool calls fail, to avoid impacting the approval process.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically match tools required for road transport operation licensing verification, adapting to multi-data-source retrieval scenarios |
| `functionCall` | Enable forced verification mode | Ensure fields returned by tool calls strictly meet the format requirements of approval materials |
| Batch execution tools | `2 parallel tasks` | Retrieve three types of data sources (vehicle qualifications, practitioner qualifications, safety systems) simultaneously, balancing efficiency and interface rate limits |
| Variable updates | Set a `5 times` call limit per category | Record verification call times for different qualification materials, avoiding repeated requests to the same data source |
| Streaming response configuration | Enable direct output of thinking content, set context window to `800–1200 characters` | Directly output model thinking process and final results, without waiting for a complete response before pushing |
| Tool call retries | `3 retry attempts` | Handle occasional request failures in government interfaces, ensuring continuity of the verification process |

## Three common mistakes
- Phenomenon: API call results do not include model thinking content, only display the final approval conclusion. Cause: The direct output of thinking content switch in streaming response configuration is not enabled, resulting in responses only returning final generated content.
- Phenomenon: Batch execution tools do not complete multi-data-source retrieval as expected, and the number of returned results is insufficient. Cause: The number of parallel tasks exceeds the rate limit threshold of government interfaces, causing some requests to be blocked.
- Phenomenon: Variable update tools do not automatically update category call times, and corresponding fields show empty. Cause: The trigger conditions for variable updates and the mapping rules for corresponding categories are not configured, causing call records to fail to be written correctly.

## How to confirm the configuration is correct
- A simulated road transport operation licensing application verification request is initiated, and whether the corresponding tool is automatically matched in the tool call log is verified.
- Variable update records are reviewed to confirm whether call times for different qualification categories are written to corresponding fields as expected.
- Streaming response content is reviewed to confirm whether both thinking process and final approval conclusion are included.
- Parallel calls of batch execution tools are tested to confirm that the number of returned results matches the number of expected retrieved data sources.

The values provided here are common starting points, and should be measured against the reader's own samples.
