# Road Transport Business License Application Process Guidance: Deployment and Upgrade

## What this category of data looks like
Data for this category is sourced from the road transport administration system, the national road transport vehicle dynamic information public service platform, and the vehicle and personnel database. It is updated daily. Documents processed daily include road transport business license applications, vehicle technical files, driver qualification materials, safety management systems, and road transport business licenses. Data fields focus on operating entity qualifications, transport vehicle compliance, personnel qualifications, safety management requirements, and license status. All fields are sourced from official government systems, with no custom non-standard fields.

## Constraints During Deployment and Upgrade
Most data for this category comes from official government systems, is updated daily, and involves core business license qualifications. Stability and compliance of data synchronization must be ensured during deployment. Multiple types of business documents have significant structural differences, so targeted knowledge base reading and chunking rules must be configured to avoid parsing errors. Errors in license processing directly affect enterprise operations, so space must be reserved for error retries and alert configurations during deployment. During upgrades, compatibility with original government data must be maintained. Version updates must not cause data synchronization interruptions or field parsing exceptions, and must comply with government system security and compliance requirements.

## How to Configure Settings
| Config Item | Recommended Value | Basis for This Value |
| --- | --- | --- |
| `MONGODB_URI` | Full connection address of a government-compliant MongoDB instance | Business data of this category must be stored in a database meeting government security requirements to prevent leakage of qualification data |
| `REDIS_URL` | Government intranet Redis cache address, timeout set to 300 seconds | High-frequency business data synchronized in daily batches requires caching to improve query efficiency; intranet deployment ensures transmission security |
| `FE_DOMAIN` | Official service domain name accessible via the government external network | Ensures the business process guidance page can be properly accessed by users through government service channels |
| `DB_MAX_LINK` | 10–15 | Adapts to the number of connections for daily batch synchronized business data, avoiding service interruptions caused by exceeding database connection limits |
| `STORAGE_S3_ENDPOINT` | Intranet endpoint address of the government cloud storage service | Stores large-volume business documents such as vehicle files and safety systems, complying with government data storage compliance requirements |
| `FILE_TOKEN_KEY` | Access key consistent with the government file system | Ensures uploaded business documents can be properly parsed and associated with corresponding business processes |

## Three Common Configuration Errors
- Configuring `FE_DOMAIN` with a local intranet address leads to a white screen when accessed via government external network devices, with the console showing resource load failures. The cause is failure to distinguish between government intranet and extranet domain configurations, and failure to expose the service to the government external network boundary.
- Failing to adjust the default value of `DB_MAX_LINK` results in a 503 Service Unavailable error during batch synchronization of vehicle files, with logs showing database connection limits exceeded. The cause is that the default connection number is insufficient to support daily batch data synchronization tasks.
- Failing to configure `FILE_TOKEN_KEY` to be consistent with the government file system leads to empty file content displayed in the knowledge base after uploading driver qualification materials. The cause is key mismatch preventing reading of uploaded business documents.
