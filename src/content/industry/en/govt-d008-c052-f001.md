# Business Process Guidance for Department Final Accounts and Financial Reports: HTTP APIs and External Systems

## What data in this category looks like
Data in this category comes from the integrated budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency follows an annual cycle. Daily output documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Data fields cover actual revenue and expenditure, assets and liabilities, and budget execution difference explanations. There are no additional non-standard custom fields. All data must meet the fixed format requirements of official reports.

## What constraints these characteristics impose on HTTP APIs and external systems
The annual update frequency means interface calls do not require frequent polling. Synchronization can be triggered at the end-of-year node. Multiple data sources require the interface to connect to multiple external systems, so unified authentication rules and data return formats must be implemented. The fixed document structure and coverage of multiple report items means interface request parameters must strictly match the required fields of the reports, avoiding field missing that leads to returned reports. Data verification failures can trigger audit risks, so the interface must include complete parameter verification and error capture logic to ensure data accuracy.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Interface timeout period | 600 seconds | Adapts to the average response duration of fiscal system interfaces, avoids interrupting data pulling due to timeout |
| Authentication configuration | `Bearer {external system API key}` | Complies with authentication specifications of most fiscal external systems, ensures interface access security |
| Request parameter template | `variables: {"year": "202X", "reportType": "final"}` | Matches the end-of-year data query requirements for department final accounts, clarifies the business scope of interface requests |
| Data return filtering | Extract only required report fields | Adapts to the field requirements of department final account documents, reduces redundant data processing overhead |
| Failure retry strategy | Retry 2 times, 30-second interval | Addresses occasional network fluctuations in fiscal systems, ensures data pulling stability |

## Three common errors
- Symptom: Calling an external interface returns a 404 status code, prompting that the interface path does not exist. Cause: Failed to correctly match the official interface path of the fiscal system, and mistakenly configured the test environment path as the production path.
- Symptom: Using the FastGPT application's API key to call the interface prompts unauthorized access. Cause: The API key is not bound to the access permissions of the corresponding fiscal system, or the key format in the authentication configuration is incorrect.
- Symptom: The interface returns missing data fields, causing the department final account report to fail verification. Cause: The complete business scope is not specified in the request parameters, or the data filtering rule configuration is incorrect, and required report fields were mistakenly blocked.

## How to confirm the configuration is correct
- Call the configured interface, check if the returned HTTP status code is 200, confirming the authentication configuration takes effect.
- Compare the interface returned data with the original data exported from the fiscal system, check field completeness and format matching, confirming the data filtering rules are correct.
- Simulate an interface call failure scenario, verify whether the retry mechanism triggers as configured, confirming the timeout and retry strategies take effect.
- Check the application logs in FastGPT v4.17.0, confirm the interface request parameters match the configured template, confirming the request parameter configuration is correct.
