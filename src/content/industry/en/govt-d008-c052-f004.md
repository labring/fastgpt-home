# Business Process Guidance for Department Final Accounts and Financial Reports: Workflow Orchestration

## What the Data for This Category Looks Like
This category serves financial departments of budget units, treasury departments of finance bureaus, and financial divisions of competent authorities. Data is sourced from the unified budget management system, treasury centralized payment system, accounting system, and asset management system. The update cycle is annual. Daily processed documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. These documents cover standardized fields such as budget execution details, revenue and expenditure surplus, and asset and liability details. The base unit of measurement is yuan. Some reports require aggregating data submitted by subordinate units according to administrative hierarchy.

## Constraints Imposed on Workflow Orchestration by These Characteristics
The annual update cycle requires workflows to support batch annual data processing, and avoid frequent triggering of non-periodic tasks.
Multi-system data sources require workflows to support dynamic access via multiple `variables`, to match output formats from different systems.
Complex document structures require workflows to preset multi-node parsing processes, to separately process statements and explanatory documents.
Time-consuming account statement verification steps require workflows to add automatic verification nodes, to reduce manual verification workload.
Severe error consequences require workflows to set exception interception links, to prevent erroneous data from entering aggregation and reporting stages.
Hierarchical aggregation requirements require workflows to support automatic collection and verification of subordinate unit data.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Knowledge Base Selection | Bind the dedicated department final account knowledge base for the corresponding year | Match annual updated data characteristics, avoid cross-year data interfering with search results |
| `variables` | Configure two dynamic variables: treasury payment data and bookkeeping accounting data | Match multi-system data source access requirements, support dynamic parameter calls |
| Single Document Upload Limit | 1000 MB | Adapt to batch document storage and parsing requirements for final account statements and explanatory documents |
| Workflow Node Trigger Condition | Trigger based on document upload completion status | Ensure data enters parsing and verification links only after full upload |
| Exception Interception Node | Calibrate based on actual testing with account statement difference thresholds | Prevent erroneous data from entering subsequent aggregation and reporting links |
| Export Configuration | Bind Word export format, trigger when workflow completes | Meet official standardized export requirements for final account reports |

## Three Common Misconfigurations
- Workflow execution returns no matching documents in knowledge base search, with empty results displayed in the interface. The cause is failure to associate the system data configured via `variables` with the bound knowledge base during dynamic parameter passing, resulting in search scope not covering target business data.
- Workflow execution times out and terminates, with execution timeout status code returned in logs. The cause is failure to adjust node execution timeout settings. Batch parsing and verification of final account documents takes a long time, and default timeout settings cannot cover the full processing cycle.
- Node configurations fail after migrating workflows from an older version, and the export link cannot be triggered. The cause is failure to migrate node identifiers corresponding to `nodeId` according to version update notes, as node configurations from older versions are incompatible with new version node rules.

## How to Verify Successful Configuration
- Upload a single annual final account statement document, trigger the workflow, and check if knowledge base search results match keywords and business fields from the uploaded document.
- Configure `variables` for dynamic parameter passing, input simulated treasury payment data and bookkeeping accounting data, and check if workflow nodes correctly receive parameters and perform matching verification.
- After triggering workflow completion, check if the conversation interface generates a downloadable Word format report link.
- View workflow execution logs to confirm all nodes executed normally, with no abnormal error messages.
