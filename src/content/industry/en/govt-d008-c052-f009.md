# Business Process Guidance for Department Final Accounts and Financial Reports: Model Access and Configuration

## What this category of data looks like
Data for this category comes from the integrated budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency follows an annual cycle. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Most document structures rely on structured table fields, including income and expenditure amounts, asset and liability balances, budget execution difference explanations, and similar fields. The unit is mostly RMB yuan. Some fields must be bound with budget unit hierarchy and annual identifiers.

## Constraints on model access and configuration
Full annual one-time updated data requires batch processing. This requires configuring model call logic adapted for long context windows. Heterogeneous data from multiple system sources needs unified field alignment. Preset field mapping rules must be configured when accessing models. Audit traceability requirements for final account data require enabling binding association between model output and original data. The annual update rhythm requires configuring full index and model verification processes that support periodic triggering. This prevents expired data from affecting business handling.

## How to set configurations
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapt to batch processing requirements for full annual department final account documents, avoid context overflow |
| `temperature` | 0.1–0.3 | Ensure rigor in final account data processing, reduce output deviation |
| `toolChoice` | auto | Allow models to call built-in tools as needed to complete cross-system data verification |
| `AIPROXY_API_ENDPOINT` | Exclusive interface address for deployed models | Implement private cloud access for models, ensure fiscal data security |
| `maxTokens` | 2000–3000 token | Control the length of single model output, adapt to writing requirements for final account explanation documents |
| `quoteMaxToken` | 1500 token | Bind the length of original data references, meet business requirements for audit traceability |

## Three common misconfigurations
- Vector index tasks show an "unfinished" status with no progress updates: No appropriate `maxContext` parameter is configured for annual batch data, causing context overflow that triggers index blocking. This corresponds to the common vector index stagnation issue in related business scenarios.
- Models cannot call built-in tools to complete account statement verification: `toolChoice` is set to a disabled state. The model is not allowed to call system tools to obtain cross-system data, so account statement and treasury payment data verification cannot be completed.
- Numerical deviation appears in model-generated final account explanations: The `temperature` value is outside the reasonable range, causing generated content to deviate from the rigor requirements of original data, leading to audit risks.

## How to confirm the configuration is correct
- Submit a single-year department final account sample data, check the execution status of index tasks and result generation.
- Initiate a test request for account statement difference verification, confirm that the model can call preset tools to complete cross-system data verification.
- Generate a single final account explanation draft, check whether the output content is associated with the original data source.
- Adjust the `temperature` parameter and compare output results, verify the control effect of the parameter on output rigor.

The values provided here are common starting points, and should be evaluated against the user's own samples.
