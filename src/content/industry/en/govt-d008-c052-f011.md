# Business Process Guidance for Department Final Accounts and Financial Reports: Forms and Interactions
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
This category of data originates from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. The update frequency follows an annual cycle. Daily generated documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Fields cover income and expenditure details, asset and liability balances, budget execution difference explanations, and more. Common units are yuan, ten thousand yuan, and other general financial units. Document structures follow fiscal specifications with hierarchical divisions, including summary reports and subordinate unit detail reports.

## What constraints these characteristics impose on the "forms and interactions" link
The annual update feature requires forms to support bulk import of historical cross-system data to reduce duplicate entry operations. The need to integrate multi-source data requires forms to include built-in cross-data source validation rules, automatically matching account statements with corresponding fields from treasury payment and accounting systems. The hierarchical document structure requires forms to support tiered reporting interfaces, distinguishing entry points for summary reports and subordinate unit detail reports. The rigor of financial fields requires setting format and required validation for amount and difference explanation fields to prevent submission of invalid data.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Enable bulk data import mode, single import limit of 1000 entries | This category of documents includes subordinate unit detail reports; bulk import reduces single-entry workload |
| `userSelect` | Pre-set reporting role options, including budget unit financial post, treasury review post, and competent department review post | Adapt to the typical post division of subjects in this category, simplifying user selection workflows |
| Form field validation | Retain two decimal places for amount fields, difference explanation fields are required | Comply with general financial data specifications, ensuring data format compliance |
| Cross-data source validation | Automatically match treasury payment data with report income and expenditure fields, pop up prompts when validation fails | Covers the most time-consuming verification link in this category; automated verification improves reporting efficiency |
| Auto-save configuration | Auto-save report content every 300 seconds | Annual data volume is large, avoiding loss of report progress due to unexpected interruptions |

## Three common mistakes
- Phenomenon: The model selection dropdown box continuously refreshes and jumps, unable to fix the target model. Cause: No fixed option range is configured for `userSelect`, causing the frontend to repeatedly pull unauthorized model lists during rendering.
- Phenomenon: Imported final account report data displays field mismatch errors. Cause: No form validation rules are set to match the unified field names of the finance department, causing format incompatibility when importing data across systems.
- Phenomenon: Audit requests are submitted without completing form filling. Cause: No required field validation and submission trigger conditions are configured for `formInput`, and the submit button is not restricted to only activate after all required fields are filled.

## How to confirm the configuration is complete
- Import test subordinate unit final account detail data, confirm the single import limit of the bulk import function matches the configured requirement.
- Fill in some required fields and attempt to submit, check if corresponding validation prompts appear.
- Switch the pre-set reporting role options, confirm the displayed content of `userSelect` matches the configuration.
- Wait for the auto-save cycle to end, check if the current draft report is stored normally.
