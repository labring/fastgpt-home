# Business Process Guidance for Department Final Accounts and Financial Reports: Deployment and Upgrade

## What this category’s data looks like
Data for this category comes from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual cycle. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The structure covers modules such as income and expenditure details, asset and liability details, and budget execution difference explanations. Fields cover actual income and expenditure amounts, asset stock, liability status, and relevant explanatory content. There is no fixed unified single-document format, and adaptation is required for parsing needs of multiple types of financial accounting documents.

## What constraints do these characteristics impose on the deployment and upgrade link
This category of data is updated annually in a concentrated manner and originates from multiple systems. During the deployment phase, it is necessary to adapt to multi-data source connection configuration to avoid format incompatibility or loss during cross-system data synchronization. The document structure includes reports, detailed tables and explanatory text. Parsing rules that support multi-format documents must be configured to ensure that different types of financial documents can be correctly read and split. The data verification link is time-consuming and the consequences of errors are serious. During deployment, sufficient computing resources must be reserved for account statement verification and difference analysis. During the upgrade phase, traceable configuration of historical data must be retained to avoid loss of annual data or caliber changes affecting subsequent processes.

## How to set the configurations
The configurations here apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:yourpass@mongodb-host:27017/fastgpt?authSource=admin` | Stores full documents and metadata for annual final accounts and financial reports, requires correct authentication information and database target configuration |
| `PG_URL` | `postgresql://admin:yourpass@pg-host:5432/fastgpt?sslmode=disable` | Stores process guidance configuration rules, user interaction logs, and process node data, supports fast query of structured data |
| `REDIS_URL` | `redis://:yourpass@redis-host:6379/0` | Caches frequently called report parsing results and process node data to shorten response time for business processing |
| `DB_MAX_LINK` | `20–30` | Handles concentrated annual data synchronization and query requests, avoids service interruptions caused by exhausted database connections |
| `STORAGE_S3_ENDPOINT` | Fill in according to the interface address of the object storage service provider used for deployment | Stores large-volume final account report attachments and historical archived data to ensure long-term storage of annual documents |
| `ROOT_KEY` | Custom key string with a complexity of no less than 16 characters | Configures system administrator permissions to ensure that core process guidance configurations cannot be modified by unauthorized accounts |

## Three common misconfigurations
- Model channel is shown as unavailable in the interface, while One API channel test passes. The cause is that the model connection key or call address is not correctly filled in the FastGPT configuration, or the channel is not bound to the corresponding process guidance application.
- An invalid token error occurs during conversation. The cause is that the token generated when connecting to One API is not bound to the corresponding model permission, or the configured `FILE_TOKEN_KEY` does not match the token of One API, resulting in request interception.
- The process guidance page fails to load normally after source code deployment. The cause is that `FE_DOMAIN` is not configured as the public network access address of FastGPT, resulting in cross-domain issues during front-end resource loading.

## How to verify successful configuration
- Run the database connection test script to verify the connectivity of `MONGODB_URI`, `PG_URL` and `REDIS_URL`, and confirm that there are no connection timeout or authentication failure prompts.
- Upload a sample annual final account report, check whether the parsing result includes the income and expenditure details and explanatory text in the report, verify that the attachment storage function of `STORAGE_S3_ENDPOINT` is normal, and the uploaded files can be downloaded normally.
- Log in to the system using an administrator account, modify the process guidance node configuration, verify that the `ROOT_KEY` permission takes effect, and unauthorized accounts cannot access the configuration modification page.
- Call the model connection interface, use a valid token of One API to initiate a test request, confirm that the channel status is displayed as normal, and there are no errors of invalid token or insufficient permissions.
