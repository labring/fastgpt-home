# Department Budget Preparation Business Process Guidance: HTTP APIs and External Systems

## What this category of data looks like
Department budget preparation data typically originates from the unified budget management system, department staff establishment system, prior-year final accounts, project library, and Ministry of Finance budget preparation notices. The update frequency is annual.
Daily processed documents include department budget drafts, project declaration forms, performance target forms, personnel expense calculation forms, and budget approvals.
Most fields relate to staff establishment counts, project expense amounts, performance indicators, and similar items. Units include ten thousand yuan, person, project number, and others.
The core use case is annual fund declaration and allocation.

## Constraints Imposed on HTTP APIs and External Systems by These Characteristics
The annual update characteristic means API call frequency is low, but single requests must handle multi-source heterogeneous data, which places high compatibility requirements on APIs.
Multi-data source docking needs require APIs to support cross-system data pulling and format conversion, and adapt to field specifications of different fiscal systems.
Complex document structures and core field requirements mean customized parsing rules must be passed in API requests to avoid loss of key budget information.
Additionally, the sensitivity of budget data and the consequences of errors require APIs to have user-level session isolation capabilities, preventing data interference between different budget units, and ensuring data security and audit accuracy.

## Configuration Setup
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Bearer-formatted API key, rotated every 7 days | Ensures access security for budget data, complies with sensitive data management requirements of fiscal authorities |
| `variables` | Pass budget fiscal year, unit code, and project type; limit the number of parameters to 3-5 | Adapts to budget preparation scenarios for different departments, reduces redundant requests, and improves API call efficiency |
| `responseData` | Return structured budget fields, including core items such as personnel expenses and project amounts | Matches field verification requirements for budget audits, simplifies subsequent data processing and audit workflows |
| User session binding | Distinguish chat context by user unique identifier; single context length is 800–1200 characters | Prevents interference from historical records of different budget units, meets actual needs of multi-user management |
| Request timeout setting | 600-second timeout threshold | Handles large-scale budget data calculation and aggregation steps, avoids process blocking caused by interrupted requests |

## Three Common Configuration Errors
- Symptom: When calling the `/api/v1/chat/completions` API, the returned business guidance does not match the specific requirements of department budget preparation. Cause: No customized budget preparation prompt is passed via the `variables` parameter, only the default generic prompt is used.
- Symptom: Chat history records of different budget units interfere with each other, and users cannot view their own exclusive budget calculation processes. Cause: No session context binding rule by user unique identifier is configured, and session storage does not implement user-level isolation.
- Symptom: After uploading a department budget draft PDF, the converted Markdown format loses table fields and project numbers. Cause: No adjustment is made to document parsing parameters for the complex table structure of budget documents, leading to omission of key fields.

## How to Verify Successful Configuration
- Call the `/api/v1/chat/completions` API, pass a customized department budget preparation prompt, and verify that the returned result includes exclusive budget process guidance content.
- Switch different test user IDs to initiate requests, and verify that chat history only displays the current user’s session content, with no cross-user data interference.
- Upload a department budget draft PDF, convert it via the document parsing service, and verify that core fields such as project number and expense amount are fully retained.
- Check the `responseData` field returned by the API, confirm that the preset core budget preparation fields are included, with no missing items or format errors.
