# Business Process Guidance for Departmental Budget Preparation: Multi-turn Dialogue and Prompt Engineering

## Data Profile for This Category
Data related to departmental budget preparation typically originates from the unified budget management system, departmental staffing system, prior-year final accounts, project repository, and Ministry of Finance budget preparation notices. Update frequency is annual. Commonly processed documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. Common document fields include staffing base, project funding amount, performance target indicators, and more. Units of measurement include ten thousand yuan, person, number of projects, and others.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
The annual update requirement for data means multi-turn dialogue workflows must regularly sync the latest Ministry of Finance budget preparation rules and project repository information to avoid using outdated standards. Data from multiple sources must gradually guide users to provide fields corresponding to each system during dialogue, rather than requesting excessive information at once that exceeds user input capacity. For complex document structures, prompts must clearly distinguish filling requirements for different document types to prevent confusion between personnel expense and project expenditure calculation logic. When consolidating subordinate units' budgets, multi-turn dialogue must gradually collect data from each unit to avoid data omissions or inconsistent formats, reducing the risk of subsequent audit failures.

The following configurations are developed for FastGPT v4.17.0.
## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind unique identifier for the current budget preparation session | Used to associate multi-turn dialogue context, ensuring context isolation between different departmental budget preparation tasks |
| `messages` | Retain the most recent 15 rounds of dialogue content | Departmental budget preparation processes have clear steps; excessive historical dialogue will dilute the prompt weight of the current phase |
| `variables` | Preset core variables such as staffing base, project funding amount | Reduce repeated input of standardized fields by users, improving dialogue interaction efficiency |
| Maximum context length | 8000–12000 characters | Adapt to the content volume of documents related to departmental budget preparation, retaining necessary historical information while avoiding redundancy |
| Query Optimization | Calibrate based on actual testing | Adapt to professional terminology habits in the fiscal field, optimizing vague expressions in user input |

## Three Common Configuration Errors
- Issue: Departmental budget preparation dialogue records are not saved to the database after the client closes the SSE connection directly. Cause: No unique `chatId` is bound and no persistent storage logic is configured, resulting in incomplete retention of session context.
- Issue: Budget data output by the model in Markdown table format is truncated, with `...[hide X char` displayed at the end. Cause: The context window for `messages` is not restricted, causing long text output to be forcibly truncated by the system.
- Issue: The dialogue returns the error message `insufficient_quota upstream load of the current group is saturated, please try again later`. Cause: No concurrent request threshold is configured for the session, triggering upstream service rate limiting when multiple users initiate budget preparation queries simultaneously.

## How to Verify Correct Configuration
- Initiate a test dialogue, input the initial departmental budget preparation request, and confirm that a unique session identifier is generated and bound to the current task.
- Initiate multiple rounds of budget-related dialogue, and confirm that the context window only retains the specified number of historical rounds, with no redundant information interfering with the current phase.
- Upload fragments of departmental budget preparation documents, and confirm that preset variables automatically match or prompt users to supplement missing standardized fields.
- Simulate concurrent requests from multiple users, and confirm that no upstream rate limiting prompts are triggered, ensuring the concurrent configuration meets business scenario requirements.
