# Business Process Guidance for Department Budget Preparation: Workflow Orchestration

## What this category of data looks like
Data sources for this category include the budget management integrated system, department staff establishment system, prior-year final accounts, project repository, and Ministry of Finance budget preparation notices. Update frequency is annual, aligned with the annual work cycle of department budget preparation. Documents processed daily include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. Fields include unit code, project name, performance indicators, expense amount (unit: ten thousand yuan), number of staff establishment, and others. The data volume per document increases as the competent administrative level rises.

## What constraints these characteristics impose on the "workflow orchestration" link
Annually updated data sources require the workflow to adapt to the latest Ministry of Finance budget preparation rules each year. Configure quickly adjustable rule nodes.
Add cross-system data verification links to the workflow orchestration for multi-source data access. This prevents exceptions caused by inconsistent field formats across systems.
Split the most time-consuming calculation, review, and aggregation links into independently orchestratable nodes. This enables step-by-step adjustment and verification.
Add pre-verification and rollback nodes to the workflow to mitigate severe error consequences. This reduces the probability of budget being returned.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Global variables | Configure `variables` to include budget year, unit code, and competent department level | Aligns with core business fields of department budget preparation, enabling unified calling by workflow nodes |
| Node ID binding | Set a unique `nodeId` for each business process node | Ensures accurate targeting of target nodes during cross-branch calls, resolving link reuse issues |
| Data verification threshold | Use the first 5 verification hits | Matches the conventional verification scope of budget preparation reviews, avoiding excessive invalid data interfering with the process |
| Timeout setting | Set to 600 seconds | Adapts to the actual scenario of large department budget preparation data volume and multiple processing steps, preventing process interruption |
| Context call limit | Use the top 10 historical data entries | Balances process response speed and reference value of historical data, conforming to the review logic of budget preparation |

## Three common configuration errors
- Attempting to connect a form filling node to another branch causes link blocking. Cross-branch reuse becomes impossible. The cause is failure to correctly configure the cross-branch reference rule for `nodeId`. Non-initial links cannot call the node.
- Global variables only return the user ID. The user's name cannot be extracted. The cause is failure to enable user information collection configuration in `variables`. The user name field is not included in the global variable scope.
- Large differences between project structures with no clear guidance lead to low configuration efficiency. The cause is failure to reference the official standard workflow template. Self-built processes do not follow the general orchestration logic of budget preparation.

## How to confirm proper configuration
- Check if the `variables` configuration includes core business fields such as budget year and unit code. Ensure all workflow nodes can call these fields normally.
- Test calling a node bound to the same `nodeId` across different branches. Verify that the link can jump normally.
- Simulate input of budget data with incorrect formats. Confirm that the data verification rule triggers an interception prompt.
- Run a test process including multiple links. Confirm that the total processing time does not exceed the 600-second timeout threshold.
