# Business Process Guidance for Department Budget Preparation: Tool Calling and Plugins

## What the data for this category looks like
Data sources for this category include the budget management integrated system, department staff establishment system, prior year final accounts, project library, and Ministry of Finance budget preparation notices. Update frequency is annual.
Daily documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and similar materials. Common data fields cover staff establishment counts, project expenditure details, performance target indicators, annual budget quotas, and other relevant fields. Units include ten thousand yuan, person, project item, and similar units.

## Constraints imposed by these characteristics on the "tool calling and plugins" link
Data sources span multiple cross-departmental systems. Tool calling must adapt to different system return formats to enable linked pulling of multi-source data.
Annual update frequency allows tool calling cache policies to refresh on an annual cycle, reducing invalid requests.
Daily documents use mixed table and text structures. Tool calling must adapt to diverse document parsing logic.
Fields cover personnel, project, and performance dimensions. Tool calling parameters must match field mappings across multiple data types to ensure accurate data association.

## Configuration settings
Configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Multiple tool calling scenarios are involved in department budget preparation. Automatically selecting adapted tools aligns with business requirements |
| `functionCall` | `enabled` | External data source interfaces must be called to obtain budget-related data. Enabling function calls enables data pulling and associated processing |
| Tool call timeout setting | `300–600 seconds` | Pulling budget data across multiple systems requires processing time. This interval covers most data pulling scenarios, calibrated based on actual testing |
| Tool call retry count | `2 times` | Budget data interfaces may have occasional fluctuations. Limited retries reduce call failure probability and avoid excessive requests |
| Document parsing format adaptation | Supports mixed table and text structures | Daily documents for department budget preparation include table-based files such as personnel expense calculation forms and text-based files such as budget approvals. Mixed adaptation enables complete data parsing |

## Three common mistakes
- Phenomenon: When calling tools related to budget data, the model returns the error message `chat:llm-model-response-empty`. Cause: The `functionCall` configuration is not enabled correctly, the tool calling link is not triggered normally, and the model cannot obtain the required budget data.
- Phenomenon: When generating department budget preparation process guidance, the generated flowchart has missing nodes or abnormal styles. Cause: Parsing rules adapted to mixed-format documents are not configured, so key fields in personnel expense calculation forms and project application forms cannot be fully extracted.
- Phenomenon: After tool calling is completed, the final result includes the original request and response logs of the tool call. Cause: The default output configuration for tool calling logs is not turned off, causing non-business-related log content to be included in the final result.

## How to confirm the configuration is complete
- Initiate a test query for department budget preparation, and verify that tool calling is triggered according to the configuration and returns corresponding business data.
- Check the tool calling return results to confirm that only AI-generated process guidance content is included, with no additional tool calling log information.
- Simulate a data source exception scenario, and verify that tool calling is processed according to the configured retry rules.
- Upload different types of budget documents, and verify that the parsing results adapt to mixed-format document structures.
