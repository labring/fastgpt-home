# Business Process Guidance for Departmental Budget Preparation: Document Parsing and Chunking

## What Data for This Category Looks Like
Departmental budget preparation-related data typically originates from the budget management integrated system, departmental staffing establishment system, prior year final accounts, project library, and Ministry of Finance budget preparation notices. The update cycle is annual. Daily processed documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. These documents contain fields such as project codes, expenditure amounts, staffing headcounts, and performance target values. Some documents use structured tables to display data.

## Constraints Imposed on the Document Parsing and Chunking Link
The annual update cycle of departmental budget documents requires parsing and chunking rules to include flexibility, to adapt to annual format adjustments. Documents from multiple sources have wide format variations, from plain text descriptions to complex nested tables. Accurate table boundary identification is required to prevent data misalignment. Core data has clear logical links: for example, project codes must be tied to corresponding expenditures and performance targets. Chunk operations cannot split these associated fields. Single-year summary documents have large file sizes. Balancing upload and parsing time limits is necessary to avoid process interruptions caused by improper configuration.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Departmental budget documents contain multi-field associated content, to avoid losing associations between projects and performance targets after splitting |
| `chunkSplitter` | Split by title + paragraph + table block | Adapt to the structured chapters and table layouts of budget documents, reduce parsing misalignment |
| `customPdfParse` | Enabled | Adapt to the parsing needs of complex nested tables in budget documents, resolve table misalignment issues from native parsing |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Cover the upload needs of single-year multi-department budget summary files, prevent files from being blocked due to excessive size |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Adapt to the parsing time of large budget documents, avoid parsing failures due to timeouts |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for the special structure of budget documents, adapt to format changes across different document batches |

## Three Common Configuration Mistakes
- Table content displays misalignment after uploading budget documents. When `customPdfParse` is not enabled, native parsing cannot accurately identify nested table structures in budget documents, leading to misalignment of data rows and columns.
- Parsing fails after uploading a file during a conversation. Improper configuration of `UPLOAD_FILE_MAX_SIZE` or `PARSE_FILE_TIMEOUT_SECONDS` causes the file to be blocked or parsing to time out due to exceeding configured thresholds.
- Core fields are split after chunking, such as project codes and corresponding expenditure amounts being placed in different chunks. A too-small `chunkSize` setting splits originally associated field groups, damaging data integrity.

## How to Confirm Proper Configuration
- Upload a typical single budget document, check that the parsed tables are complete and free of misalignment, and verify that the chunked content includes complete project and performance target association information.
- Upload a test file close to the configured `UPLOAD_FILE_MAX_SIZE` value, confirm that the upload and parsing processes have no errors.
- Adjust `chunkSize` to different ranges, compare chunking results, and ensure that core fields are not split.
- In FastGPT v4.17.0, use API connection testing to confirm that parsing results returned after file upload meet expectations, with no timeout errors.
