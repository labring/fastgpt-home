# Department Budget Preparation Business Process Guidance: Forms and Interactions

## What the data for this category looks like
Data for this category is typically generated around the annual department budget preparation process. Core documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and similar items. Data is mainly sourced from the unified budget management system, department personnel establishment system, prior-year final account data, project repository, and the national finance department's annual budget preparation notice. The update frequency is once per year. Data fields include unit code, project code, number of personnel establishments, performance indicator values, expense amounts, and more. Common units are ten thousand yuan, person, item, and similar units.

## Constraints for forms and interactions
The annually updated data source requires forms to support static bulk import and regular refresh configuration. This avoids frequent external API calls. Multiple document types correspond to complex field structures. Forms must support block-based display and dynamic field loading to adapt to different filling scenarios. Multi-source data dependencies require forms to have cross-system field verification capabilities. This ensures consistency between filled data and data sources such as the unified budget management system and personnel establishment system. The most time-consuming calculation and review links require forms to support segmented saving and batch verification. This reduces the rate of filling errors. The serious consequences of errors require forms to have pre-verification and error prompt functions. This reduces the probability of budget return requests.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind to the unified budget management system interface, enable field verification, set input timeout to 30 seconds | Adapt to fixed data source requirements for department budget preparation; the timeout setting avoids excessively long wait times that reduce filling efficiency |
| `userSelect` | Preset supervisor department and budget unit role options, limit selectable range to the hierarchy of the currently logged-in user | Comply with permission hierarchy management requirements for budget preparation, prevent cross-hierarchy unauthorized filling |
| Form bulk import | Support importing CSV-formatted data for personnel expense calculation forms and project application forms, single import limit of 500 rows | Match conventional annual budget data scale, avoid import timeouts or data overflow |
| Form block display | Divide into blocks by personnel expenses, project expenditures, and performance targets; each block contains no more than 15 fields | Align with structured characteristics of budget preparation documents, reduce cognitive load for single filling sessions |
| Verification trigger timing | Trigger verification after form filling is completed | Avoid frequent verification interrupting the filling process, align with segmented filling usage habits |

## Three common configuration errors
- When configuring database connection nodes, the port number cannot be entered. The cause is that the multi-parameter editing mode of `formInput` is not enabled, and only preset fixed fields are allowed to be filled.
- Form input content cannot be properly passed to Feishu collaboration tools. The cause is that cross-system field mapping rules are not configured, resulting in mismatched submitted data formats.
- API calls cannot obtain form configuration information during application initialization. The cause is that API query permissions for form metadata are not enabled. Only the filling interface is open by default.
