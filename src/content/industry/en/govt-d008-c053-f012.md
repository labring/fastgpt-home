# Business Process Guidance for Department Budget Preparation: Deployment and Upgrade

## What this category’s data looks like
Daily data for department budget preparation mainly comes from the unified budget management system, department staff establishment system, prior-year final accounts, project library, and the Ministry of Finance’s annual budget preparation notice. Update frequency is annual. Daily processed documents include department budget drafts, project application forms, performance target forms, staff expenditure calculation forms, and budget approvals. Data fields include unit code, staff establishment number, project expenditure amount, performance target value, and more. Most data units are ten thousand yuan and person. The field association relationship for a single document is relatively complex.

## What constraints these characteristics impose on deployment and upgrades
Department budget preparation follows an annual update rhythm. This requires configuring periodic data synchronization tasks during deployment to adapt to annual data switching logic. Data originates from multiple system sources. Multiple database connection parameters must be configured to ensure consistency of cross-system data pulling. Diverse daily processed document types require parsing rules adapted to different formats to be configured during deployment. High data association complexity requires retaining the association logic between historical data and current preparation tasks during upgrades. This avoids interruptions to the budget preparation process.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Department budget preparation has a large data volume, so connection count and server load must be balanced |
| `MONGODB_URI` | Configure a dedicated connection string according to business system integration requirements | Non-structured documents such as department budget drafts and performance target forms must be stored |
| `PG_URL` | Database address connected to the unified budget management system | Core budget preparation data is stored in relational databases |
| `REDIS_URL` | Local cache address with a cache duration of `7200 seconds` | Commonly used staff establishment and project library data must be cached to reduce repeated queries |
| `STORAGE_S3_ENDPOINT` | Configure according to the endpoint provided by the enterprise cloud storage service provider | Annual budget application documents and approval files must be stored |

## Three common misconfigurations
- Issue: Cannot locate the API key configuration entry when configuring the model. Cause: Operations are not performed under the permissions corresponding to `ROOT_KEY`, or the FastGPT v4.17.0 version has not been upgraded.
- Issue: Calling the budget data query interface returns a 400 error. Cause: The `PG_URL` connection parameter is not configured correctly, resulting in mismatched database field validation.
- Issue: The code running step does not display in the workflow orchestration debug interface. Cause: Plugin configurations relied on by the workflow have not been reloaded after an upgrade, or the advanced options for debug mode have not been enabled.

## How to confirm the configuration is complete
- Perform a database connection test to verify that the connection count set in `DB_MAX_LINK` adapts to the current business data volume.
- Upload a standard department budget draft document to confirm that the parsed data fields match business requirements.
- Trigger a temporary data synchronization task to check whether cross-system data pulling is successful.
- Enter the system settings page to confirm that the model configuration entry exists and can save configurations normally.
