# Business Process Guidance for Flood Control, Disaster Prevention and Emergency Duty: Tool Calling and Plugins

## What Data for This Category Includes
The data for this category comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Daily documents include duty records, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data updates daily. Some real-time monitoring items update more frequently. Document fields typically include rainfall and water level values, warning levels, affected area ranges, material stock and allocation quantities, and the number of people transferred and resettled. Supported units include millimeters, cubic meters per second, and people.

## Constraints Imposed on Tool Calling and Plugins
Decentralized data sources, fast update cycles, and strict unit requirements for document fields create multiple constraints for the tool calling and plugins workflow. Teams must integrate with multiple heterogeneous system APIs. Tool calling must adapt to return formats and parameter rules of different systems. Real-time monitoring data updates frequently. Tool triggering must align with the rapid pace of business response to avoid delayed data impacting decision-making. Document fields must strictly match unit requirements for rainfall, water conditions, and materials. Plugins must include built-in field verification logic to prevent invalid parameters from causing response errors. In cross-departmental scheduling scenarios, tool calling must support permission isolation to ensure sensitive data only circulates within authorized scopes.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or bound to the dedicated flood control emergency tool set | Adapt to multi-source data calling requirements, avoid the model calling irrelevant external tools |
| `functionCall` | Force calling the specified tool group | Target fixed business process handling, ensure accuracy of tool calling |
| Tool call timeout duration | `300–600 seconds` | Match the real-time update rhythm of emergency data, avoid prolonged waiting that delays response |
| Maximum return entries per tool call | `Top 3–5 entries` | Prioritize displaying high-priority rainfall, water condition and disaster data, prevent information overload |
| Log output level | Detailed mode | Facilitate troubleshooting of tool call format errors and interface anomalies |

## Three Common Misconfigurations
- Symptom: The tool call node returns an `Invalid JSON: Bad control character` error. Cause: Rapid disaster reports and consultation minutes containing line breaks or special symbols are not escaped, corrupting the generated JSON format.
- Symptom: Tool call nodes cannot add connection lines, and no connection circles appear in the interface. Cause: The workflow has not completed basic configuration saving, or the node type is not correctly set as a tool call node.
- Symptom: MCP-assisted model task processing duration exceeds expectations. Cause: Tool call retry limits and single timeout duration are not configured, causing the model to repeatedly attempt abnormal interfaces or wait excessively.

## How to Verify Correct Configuration
- Trigger a simulated flood control business process. Check if tools call specified meteorological and hydrological data sources per configurations. Confirm the `toolChoice` configuration takes effect.
- View workflow operation logs. Confirm tool call parameter formats comply with JSON specifications, with no unescaped line breaks or special symbols.
- Validate the tool call timeout logic. Confirm the timeout threshold matches the rapid pace of emergency response requirements.
- Enable detailed log collection for the MCP service. Confirm complete call links and return data details are accessible.

The values provided are common starting points and should be measured against the reader's own samples.
