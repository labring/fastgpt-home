# Business Process Guidance for Flood Control, Disaster Prevention and Emergency Duty: Knowledge Base Retrieval and Recall

## What data for this category looks like
The core data for this category comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. It is updated daily. Daily processed documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Duty logs include duty periods and handling entries. Warning notices include warning levels and effective ranges. Rapid disaster reports include affected locations and preliminary loss descriptions. Material allocation slips include material categories and allocation quantities.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Data sources are scattered and mostly real-time business systems. The retrieval link must quickly synchronize the latest hydrological and meteorological data to avoid recalling outdated information. Document types cover structured forms and unstructured minutes. The system must adapt retrieval logic for different content formats. Since the core process uses real-time emergency response, the system must return recall results within a short time. It must also cover multi-source data required for cross-departmental scheduling. At the same time, the system must ensure the accuracy of recalled content to avoid handling errors caused by information deviations. Mass documents updated daily require efficient indexing to avoid retrieval delays that affect emergency response speed.

## Configuration Settings
These configurations are designed for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | Emergency scenarios require balancing retrieval precision and coverage. Avoid incorrectly recalling irrelevant disaster information, while ensuring that content related to core response actions is recalled. |
| `limit` | `Top 8–12 entries` | Emergency response requires quickly accessing key information. Too many results increase screening costs for frontline duty personnel. Too few results may miss important reference materials. |
| `searchMode` | Hybrid retrieval | Must match both keywords and semantics to cover the exact matching needs of structured forms and semantic matching needs of unstructured minutes. |
| `usingReRank` | Enabled | Results recalled from multiple sources need to be reranked to prioritize highly relevant core content such as consultation minutes and warning notices. |
| `datasetSearchUsingExtensionQuery` | Enabled | User queries in emergency scenarios may omit technical terms. Extended queries cover synonyms and industry-specific expressions to improve recall coverage. |
| `collectionIds` | Bind corresponding emergency business datasets | Isolate business data from different departments to avoid recalling unrelated content across permissions, ensuring the retrieval scope only covers documents required for the current emergency scenario. |

## Three Common Mistakes
- Phenomenon: A query containing an affected location fails to recall the target rapid disaster report on the first input, but works normally on the second input. Cause: The extended query is not triggered during the first retrieval, or the similarity threshold is set too high, filtering low-scoring but relevant historical consultation minutes.
- Phenomenon: Manually uploaded warning notice documents disappear from the dataset index list several hours later. Cause: No scheduled incremental synchronization task is configured, or dataset permission settings cause temporary indexes to not persist.
- Phenomenon: Retrieval results include non-emergency daily office documents such as administrative notices. Cause: The retrieval scope is not limited via `collectionIds`, and content from unrelated datasets is mixed in.

## How to Confirm the Configuration is Correct
- Upload a test rapid disaster report document, initiate a query containing a specific affected location, and verify whether the recalled results include this document.
- Adjust the `similarity` parameter to the interval boundaries, and verify whether the number of recalled results changes as expected with the threshold.
- After enabling `usingReRank`, compare the order of results before and after reranking to confirm that highly relevant content such as consultation minutes and warning notices is returned first.
- Check the dataset binding configuration to confirm that only the specified emergency business datasets are included in the retrieval scope.

The values provided are common starting points and should be measured against the reader's own samples.
