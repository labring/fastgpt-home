# Workflow Guidance for Flood Prevention, Disaster Mitigation and Emergency Duty: Forms and Interactions

## What the data for this category looks like
Core data for this category comes from weather warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance, and is typically updated daily. Documents processed daily include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Most fields include rainfall and water condition values, the number of transferred personnel, material categories and quantities, with units such as millimeters, cubic meters, persons, tons, and more. Data dimensions cover meteorology, hydrology, personnel, materials and other categories.

## What constraints these characteristics impose on the forms and interactions link
Real-time updates from multiple data sources require forms to quickly pull data from external systems to avoid manual entry errors. Multiple fields with dedicated units require forms to be configured with unit validation rules to prevent data format errors. Cross-departmental dispatch business scenarios require forms to associate role permissions to limit the operation scope of different departments. Batch processing requirements for document data require forms to support multi-file upload and batch parsing, adapting to time-consuming links such as consultation material drafting.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Form input component | `formInput` bound to multi-field template | Supports batch entry of multi-dimensional data such as rainfall, water condition, and personnel information |
| User selection component | `userSelect` associated with department role groups | Adapts to permission verification requirements for cross-departmental dispatch |
| File upload limit | Single upload no more than 500 MB, maximum 10 files per batch | Adapts to upload scenarios for documents such as rapid disaster reports and material allocation slips |
| Input validation rules | Bind unit validation per field, e.g., rainfall unit is millimeters, material unit is tons | Avoids unit errors during data entry |
| Streaming reply configuration | Enable segmented output with 100-300 millisecond interval | Adapts to real-time information transmission in emergency scenarios |
| Timeout threshold | 600 seconds | Addresses time-consuming scenarios of pulling data from multiple systems |

In FastGPT v4.17.0, the above configuration items can be set directly in the workflow and form editor.

## Three common misconfigurations
- Phenomenon: After configuring a file upload node in the workflow, calling the document parsing tool returns an error. Cause: The local storage path of the uploaded file is not correctly bound, or the file access permission of the internal knowledge base is not configured.
- Phenomenon: After adding a custom plugin, the workflow editing interface does not display input and output parameters. Cause: The plugin configuration does not declare input and output parameter fields, or parameter loading fails due to version compatibility issues.
- Phenomenon: After voice input, the recognition result deviates significantly from the actual content. Cause: The professional thesaurus is not configured to adapt to flood prevention specialized terms, or the ASR service is not optimized for local scenarios.

## How to confirm the configuration is complete
- Upload a standard rapid disaster report document, confirm that the file can be parsed normally and synchronized to the internal knowledge base.
- Configure the `userSelect` component to associate the department role group, attempt to access the form using an unauthorized account to verify that permission verification takes effect.
- Initiate a voice input test, confirm that the recognition result can be correctly converted to the preset form field content.
- Trigger the streaming reply, confirm that the reply content is output in segments, with no full one-time return.
