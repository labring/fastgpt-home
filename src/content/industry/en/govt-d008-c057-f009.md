# Business Process Guidance for Food Safety Supervision and Sampling: Model Access and Configuration

## What the Data for This Category Looks Like
Data sources include food safety sampling monitoring systems, the State Administration for Market Regulation sampling results query system, laboratory LIMS, and enterprise account books. The update frequency is monthly. Daily documents involved include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control notices. Each document has dedicated business fields: sampling slips include sampling location, sample name, and production batch number; inspection reports include inspection items and judgment results; disposal reports include rectification requirements, recall progress, and other relevant content. The overall document structure is diverse, with concentrated professional fields.

## Constraints Imposed on Model Access and Configuration
The monthly update requirement means model indexing does not need high-frequency refreshes. A reasonable synchronization cycle can be configured. The multi-source, multi-type document structure means model access configuration must adapt to text parsing for different formats. This prevents process guidance errors caused by field recognition deviations. Professional inspection documents require the model to recognize terms related to food sampling and inspection. They also require limiting the rigor of generated content. Cross-system data sources require independent proxies and keys to ensure call security and avoid permission confusion.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of multiple spliced sampling documents, avoids context overflow |
| `maxTokens` | 2000–3000 token | Meets the long text generation requirements for inspection reports and disposal reports |
| `quoteMaxToken` | 1500 characters | Limits the length of referenced sampling document fragments, ensures compliance with model input limits |
| `temperature` | 0.2–0.4 | Maintains the rigor of business responses, avoids generating non-standard process content |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated address according to the deployment node | Adapts to independent proxy configuration for multi-system access |
| `AIPROXY_API_TOKEN` | Dedicated key bound to the proxy | Ensures security of cross-system calls |

## Three Common Misconfigurations
- Symptom: A 404 body not found error is returned when calling the model. Cause: `AIPROXY_API_ENDPOINT` is not configured as a dedicated proxy node, or `AIPROXY_API_TOKEN` does not match the bound proxy.
- Symptom: AI-generated sampling process guidance includes missing fields or incorrect professional terms. Cause: Models for different scenarios are mixed, with no unified adaptation for the structure and professional content of food sampling documents.
- Symptom: Knowledge base search returns content that cannot be recognized as valid JSON format. Cause: `quoteMaxToken` is not set to limit referenced fragment length. Spliced returned content exceeds the model's processing limit, causing format errors.

## How to Verify Proper Configuration
- Check the configuration of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`. Initiate a test call, and confirm a normal response is returned.
- Import a sampling plan document. Test whether the model can accurately extract core fields such as sampling points and inspection items.
- Enable the knowledge base search function. Verify that returned results conform to preset structured formatting requirements.
- Adjust the `temperature` parameter to the 0.2–0.4 range. Test whether the generated process guidance remains consistent and rigorous.

The values provided are common starting points, and should be measured against the samples in use.
