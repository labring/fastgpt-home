# Warehouse and Logistics Business Process Guidance: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Business process guidance data for warehouse and logistics is primarily sourced from internal warehouse management systems, transportation dispatch logs, inbound and outbound electronic documents, and job operation manuals. Data update cycles are split into real-time and scheduled. Inbound and outbound operation data is synced to the knowledge base in real time. Scheduling plans and general process specification data are updated daily.

Document structure includes both structured fields and unstructured instructions. Structured fields include location code, SKU number, inbound and outbound time, and process node ID. Units use logistics-specific measures such as piece, cubic meter, ton, and hour. The unstructured section contains operation details and exception handling instructions for each process node.

## Constraints imposed on knowledge base retrieval and recall
The structured fields for warehouse and logistics are numerous, with diverse units. Retrieval must support precise filtering by fields like location code and SKU number to avoid returning mismatched process content. Real-time updated inbound and outbound data requires an incremental indexing mechanism, to prevent retrieval results from lagging behind the latest business status.

Process documents vary widely in length. Short operation prompts may only be tens of characters long, while long exception handling instructions can span thousands of characters. This demands adaptable chunking strategies for different lengths, to ensure recalled content fully covers business nodes.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.80 | Matches the precision of professional terms in warehouse and logistics processes, preventing low-relevance general process content from being included in recall results |
| `limit` | Top 8 entries | Covers all process nodes of a single business handling, while controlling the total context length to avoid exceeding model input limits |
| `searchMode` | hybrid | Combines keyword retrieval and semantic retrieval to adapt to the mixed retrieval needs of structured fields and unstructured operation instructions |
| `usingReRank` | Enabled | Re-sorts initially recalled results by business node relevance, fixing the disordered return issue of semantic retrieval |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonyms related to processes, such as expanding "inbound" to "goods inbound" and "material warehouse entry", covering multiple naming scenarios in warehouse and logistics |
| `collectionIds` | Bound by specified warehouse area | Limits the retrieval scope to only process documents of the corresponding business area, avoiding returning irrelevant content across areas |

## Three common misconfigurations
- Phenomenon: The order of process nodes returned via API calls is chaotic, while the order returned via online chat aligns with business logic. Cause: The `usingReRank` configuration is not enabled for API calls, so only disordered results from initial semantic retrieval are returned. Online chat enables the reranking function by default.
- Phenomenon: Retrieval results include irrelevant SKU category processes, without filtering the specified location. Cause: The `collectionIds` or metadata filtering rules are not configured correctly, and the dataset collection for the corresponding warehouse area is not bound.
- Phenomenon: Retrieval results omit the latest inbound and outbound process adjustment content. Cause: The incremental indexing update mechanism is not enabled, so the knowledge base has not synchronized the latest business process change data.

## How to verify successful configuration
- Initiate both API calls and online chat, then compare the number and order of returned process nodes to confirm the reranking function is active.
- Input a query containing a specific location code, then check if returned results only include process content for that corresponding location, to confirm metadata filtering rules have been loaded.
- Submit the latest updated process document, wait for index synchronization to complete, then initiate a query to confirm returned content includes the latest business details.
- In FastGPT v4.17.0, adjust the `similarity` parameter value, observe changes in retrieval result relevance, to confirm the parameter configuration has been successfully loaded.

The values provided here are common starting points and should be evaluated against the reader's own samples.
