# Survey and Design Business Process Guidance: HTTP Interfaces and External Systems

## What the data for this category looks like
Survey and design data originates from internal BIM systems, survey report documents, and project approval forms. Updates trigger with project approval nodes. Coverage includes initial design, construction drawing, and completion acceptance stages.
Data structure includes fields such as project number, survey point latitude and longitude, design load parameters, processing link name, current approval status, and update time.
Longitude and latitude use decimal degrees as the unit. Design load uses kilonewtons per square meter as the unit. Update time uses ISO 8601 format.
Single data volume varies with the number of drawings. The range spans from tens of MB to hundreds of MB.

## Constraints imposed on HTTP interfaces and external systems
Survey and design data has strict field format specifications. HTTP interfaces must support validity checks for longitude and latitude formats and load units. This prevents invalid data from entering the system.
Data updates on demand with approval nodes. Interfaces must support trigger-based calls to adapt to the business node trigger logic of external systems.
Data volume varies significantly. Interfaces must adapt to large-volume drawing attachment transfers to avoid request truncation.
Approval status is an enumerated value. Interfaces must support precise matching of status parameters. This ensures the accuracy of business process guidance.
Data comes from internal enterprise systems. Interfaces must be compatible with internal enterprise authentication mechanisms. This ensures data transmission security.

## Configuration Settings
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${internal enterprise service access token}` | Adapts to the authentication requirements of survey and design project internal systems, complies with standard HTTP authentication formats |
| Request timeout | 600 seconds | Survey and design data includes large-volume drawing attachments, requires sufficient time for transfer and processing |
| Request body size limit | 1000 MB | Matches the maximum transfer volume of a single survey report or design drawing |
| `variables` | Map external system fields by project ID | Ensures interfaces can accurately match corresponding data for survey and design projects |
| Return data format | JSON | Facilitates external systems to parse structured approval status and parameter data |
| `responseData` | Extract core business fields | Filters redundant information to adapt to the calling requirements of business process guidance |

## Three Common Configuration Mistakes
- Phenomenon: A 401 Unauthorized status code is returned after calling the interface. Cause: The token format of the `Authorization` header is not correctly configured, and valid access credentials for the internal enterprise system are not provided.
- Phenomenon: The interface request times out, returning a 504 Gateway Timeout status code. Cause: The request body is too large or the timeout setting is too short, failing to match the transfer requirements of survey and design drawings.
- Phenomenon: The obtained knowledge base file list is empty. Cause: The `variables` mapping rule is not configured by project ID, causing the interface to not associate file data for the corresponding survey and design project.

## How to Verify Correct Configuration
- Call the authentication interface to verify the validity of the `Authorization` header. A 200 OK status code indicates the authentication configuration is correct.
- Upload a standard survey and design drawing attachment. Check that the request body size does not exceed the preset 1000 MB limit, with no transfer errors.
- Initiate a request to obtain project data. Check that the fields returned in `responseData` match the project parameters of the external system.
- After configuring the `variables` mapping rule, trigger a business process node update. Check that the approval status returned by the interface matches the actual status of the internal system.
