# Survey and Design Business Process Guidance: Forms and Interactions

## What This Category of Data Looks Like
Survey and design data mainly comes from project survey reports, construction drawings, approval documents, and on-site measurement records. The update rhythm follows project phase progression, with synchronized updates at key nodes such as preliminary design and construction drawings. Document structures typically include fields such as project unique ID, survey point coordinates, structural load parameters, and material specifications. Most field units are professional engineering units such as meters, kPa, square meters, and cubic meters. The length of single documents varies widely: small project documents are only hundreds of characters, while large project drawing files can reach hundreds of megabytes.

## What Constraints These Characteristics Impose on the "Forms and Interactions" Link
There are many specialized fields with strict unit requirements, so forms must split input items by professional modules to prevent non-professional personnel from entering invalid formats. Data updates are frequent and phased, so forms must support real-time validation of input legality to prevent submission of expired or non-phase-appropriate data. The size of single documents varies widely, so the interaction link must support large file upload and chunked processing, while adapting to knowledge base retrieval logic for documents of different lengths. Multi-dimensional project classification requires forms to provide precise filter options, to ensure the associated knowledge base range matches the current business scenario.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `formInput` | Group by professional fields, associate each group with the corresponding professional knowledge base | Survey and design data is categorized by disciplines such as survey, structure, and electromechanical. Grouping improves the accuracy of knowledge base retrieval, and complies with the group association rules of FastGPT v4.17.0 |
| `userSelect` | Preset survey phase and project type options, limit the optional range to 3–8 items | Reduces invalid classification input, avoids result deviation caused by calling the full knowledge base, and aligns with the conventional classification logic of survey and design projects |
| Custom input items | Add coordinate format and load value validation rules, limit units to meters, kPa | Matches the unit requirements of professional fields in survey and design, prevents invalid input from causing abnormalities in subsequent processes |
| Single submission limit | 1000 MB | Adapts to the single-batch submission requirements of large construction drawing files, avoids submission failure due to excessive file size |
| Timeout period | 600 seconds | Covers the processing cycle of large file uploads and multi-knowledge base retrieval, ensures normal completion of the process |

## Three Common Mistakes
- When the stream parameter is set to true when calling the interface, only segmented data is received and the complete result cannot be assembled. The cause is that the streaming result receiving logic of `formInput` is not correctly configured, and the returned content is not aggregated according to the event stream rules.
- After the form is submitted, the knowledge base retrieval results do not match the project type. The cause is that the knowledge base range is not limited via `userSelect`, and the global knowledge base is called directly, resulting in retrieval of non-professional data.
- Custom input items cannot synchronize global variables. The cause is that the mapping relationship between variables and form fields is not declared in the `formInput` configuration, causing variable assignment to not take effect.

## How to Confirm the Configuration Is Correct
- Open the form configuration page, verify that the validation rules and preset units for each professional field match the professional requirements of survey and design data.
- Select the preset project type and survey phase, trigger a knowledge base retrieval test, and check whether the returned content matches the currently selected business scenario.
- Test the interface call in stream mode, confirm that segmented data can be received and aggregated into a complete result according to the event stream.
- Fill in the form fields and trigger variable synchronization, check whether the global variables update normally along with the input content.
