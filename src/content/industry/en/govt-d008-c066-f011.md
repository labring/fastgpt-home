# Workflow Guidance for Chemical New Materials Business: Forms and Interactions
This document is written for FastGPT v4.17.0.

## What the data for this category looks like
Data related to chemical new materials business processing mainly comes from internal enterprise production management systems, raw material purchase ledgers, downstream customer order forms, and compliance filing documents from local emergency management departments. Data update cycles cover three categories: real-time (order and batch information), daily (raw material inventory), and quarterly (compliance test reports). Document structures include fields such as raw material grade, batch number, safety test items, business process nodes, and approval authority fields. Field units are mostly tons, kilograms, batch numbers, and test report numbers. Some fields must match the format of national chemical industry standards.

## Constraints for Forms and Interactions
The multiple update cycles of chemical new materials business data require forms to support dynamic loading of data sources with different timeliness. Real-time order data must pull the latest inventory remaining at submission to prevent over-ordering. The presence of multiple fields with industry standard units requires forms to configure unit prompts and format validation rules for each field. For example, batch numbers must match the fixed format of "letters + numbers + date", and weight fields must automatically identify and convert to a unified unit of measurement. Fields related to compliance filings must force an associated attachment upload entry to ensure that compliance materials such as test reports are submitted alongside the form. Complex process node fields must support step-by-step collapsed display to avoid operational errors caused by excessive content on a single form page.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | Single-field input length limit: 800–1200 characters | Covers conventional long-text input needs such as chemical material test descriptions and process parameter descriptions |
| `userSelect` | Preset options displayed in pagination, 10–15 items per page | There are many optional values for chemical raw material grades, approval roles, and similar items. Pagination optimizes interaction experience |
| Input box timeout | 600 seconds | Chemical business processing requires uploading large-volume test report attachments or filling out multi-step forms. This duration prevents normal operations from being interrupted |
| Attachment upload limit | Single file maximum: 1000 MB | Chemical compliance test reports are mostly multi-page PDFs or scanned documents. This size covers conventional document needs |
| Form step-by-step expansion | Expand grouped by process nodes | Chemical business processing forms have many fields. Grouping reduces operational complexity |
| Required field validation | Real-time validation before submission | Avoids process rollbacks caused by missing required fields, and aligns with compliance requirements for chemical businesses |

## Three Common Mistakes
- Phenomenon: The `userSelect` component for selecting raw material grades shows no optional data after loading. Cause: The dynamic pull rule for the corresponding data source is not configured, or the data source update frequency does not match the form loading timing.
- Phenomenon: The input box does not automatically reset after form submission, and retains the previous input content. Cause: The post-submission clear configuration for `formInput` is not enabled, or no input box reset node is added in the workflow.
- Phenomenon: The code run node fails during execution, with a prompt containing historical record fields. Cause: Historical session data in workflow input is not filtered, and is directly passed to the code run node, triggering the parameter validation rule.

## How to Verify Correct Configuration
- Navigate to the form editing page, select any `formInput` field, and verify that the input length limit prompt displays normally.
- Access the `userSelect` component configuration page, test triggering data source pull, and confirm that the optional list loads normally.
- Submit a test form, check whether the input box automatically clears after submission, and confirm that the attachment upload function triggers normally.
- Simulate input containing historical records, trigger the code run node validation, and confirm that the validation rule takes effect normally.

The values provided are common starting points and should be evaluated against the samples relevant to the specific deployment.
