# Business Process Guidance for Advanced Chemical Materials: Deployment and Upgrade

## What the data for this category looks like
Business process data for advanced chemical materials comes primarily from internal enterprise production scheduling systems, ERP work order systems, compliance test reports, and industry technical standard documents. Data update rhythms fall into three categories: production batch work orders are synced and updated daily, compliance test reports are archived after each production batch is completed, and business process documents are revised as needed. Each individual document includes fields such as work order number, material brand, production batch, test item parameters, approval nodes, and processing time limits. Parameter units cover industrial standard units including tons, kilograms, MPa, degrees Celsius, and others. Some business documents exceed 5000 characters in length.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | Work order and test data for advanced chemical materials has high concurrent volume, requiring sufficient database connection pools to support concurrent retrieval |
| `MONGODB_URI` | `Replica set mode, reserve 2000 MB of free space for storage nodes` | Business documents and historical work orders have large storage requirements; replica set mode improves storage reliability |
| `PG_URL` | `Configure as an instance that supports parallel queries, set connection timeout to 600 seconds` | Retrieval of chunked long documents requires stable database connections to avoid timeout interruptions |
| `REDIS_URL` | `Enable persistent storage, set memory quota to 800 MB` | High-frequency read/write operations for session caching and retrieval caching require sufficient memory resources |
| `FE_DOMAIN` | `Bind to a business subdomain that complies with internal enterprise domain specifications` | Adapt to internal business system unified domain management requirements |
| `STORAGE_S3_ENDPOINT` | `Use internal enterprise object storage endpoints, enable version control` | Meet version tracing and secure storage requirements for business documents |

## Three Common Mistakes
- The symptom is vector database connection failure after deployment, with logs returning connection timeout errors. The cause is failure to configure an internal enterprise network HTTP proxy in the connection address for `MONGODB_URI` or `PG_URL`.
- The symptom is model output only in Chinese, even when an English prompt and English knowledge base are configured. The cause is failure to adjust the default language adaptation configuration, with Chinese-first word segmentation rules forcefully enabled.
- The symptom is insufficient number of business process guidance search results after private deployment startup. The cause is a too-low `DB_MAX_LINK` configuration value, leading to database connection pool exhaustion and inability to handle concurrent retrieval requests.

## How to Verify Proper Configuration
- Run the `docker ps` command to confirm all containers are running normally with no abnormal restart records.
- Access the address bound to `FE_DOMAIN`, navigate to the business process guidance test page, enter a known work order number, and verify that search results return correct processing nodes and parameters.
- Upload a compliance test document for advanced chemical materials, confirm that chunked vector storage succeeds, and that the corresponding content is matched during retrieval.
- Modify the `DB_MAX_LINK` configuration value, monitor database connection counts, and confirm that connection counts fluctuate within the configured range.

The values provided are common starting points and should be measured against the reader's own samples.
