# Business Process Guidance for Fertilizer and Pesticide Services: HTTP APIs and External Systems

## What the Data for This Category Looks Like
The business data for fertilizers and pesticides mainly comes from three sources: the national pesticide registration information database, ERP systems of agricultural input production enterprises, and local agricultural and rural department supervision platforms. Data updates follow two rhythms: production license and registration certificate information is synchronized monthly, while business data such as inventory and sales is updated daily. The structure of a single data record includes fields such as registration certificate number, active ingredient content, applicable crops, recommended dosage, and compliance check status. The unit for active ingredient content is g/L or mg/kg, and registration certificate numbers use a fixed 16-character format.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer-format dedicated token for agricultural input systems, valid for 7 days | Matches the identity verification rules of agricultural input supervision platforms |
| `variables` | Bind preset business fields such as registration certificate number and applicable crops | Dynamically generate accurate business process query conditions |
| `responseData` | Only return compliance status and processing progress fields | Filter redundant data to improve API transmission efficiency |
| Request timeout | 30 seconds | Adapts to the average response duration of agricultural input system APIs |
| Request retries | 2 times | Addresses temporary fluctuations in agricultural input systems |
| Knowledge base sync frequency | 2:00 AM daily | Matches the daily update rhythm of agricultural input data |

## Three Common Configuration Mistakes
- When calling the business process API, reference entries from the fertilizer and pesticide knowledge base appear first in the response body. This happens when the context reference switch for business scenarios is not disabled in the FastGPT configuration.
- A 504 gateway timeout status code is returned after calling the API, or the response duration exceeds 10 seconds. This happens when the number of agricultural input data entries queried per request is not limited, causing the API to pull a large amount of redundant data.
- A 401 unauthorized status code is returned, or an identity verification failure prompt is displayed. This happens when the `Authorization` parameter does not carry the correct dedicated token for the agricultural input system.

## How to Verify a Correct Configuration
- Send a test request, check that the response body only includes the compliance status and processing progress fields required for business processing.
- View the API logs, confirm that the token carried in the `Authorization` parameter conforms to the requirements of the agricultural input system.
- Simulate a business process query, confirm that the API response speed meets the expected 30-second threshold.
- Trigger a manual knowledge base sync, check that the data update time conforms to the preset 2:00 AM daily rule.
