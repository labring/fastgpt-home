# Business Process Guidance for Fertilizer and Pesticide: Tool Calling and Plugins
This document is written based on FastGPT v4.17.0

## What the data for this category looks like
Business data related to fertilizers and pesticides mainly comes from the account books of agricultural materials manufacturing enterprises, the Ministry of Agriculture and Rural Affairs Pesticide Registration Management Platform, and third-party quality inspection institution reports. The data update rhythm varies by business type: production batch data is updated with production cycles, filing information is synchronized monthly, and inspection reports are updated with inspection batches. The standard document structure for a single data entry includes fields such as product common name, registration certificate number, manufacturer, active ingredient content, applicable crops, recommended application dosage, shelf life, and storage conditions. Active ingredient content is mostly marked in g/L or percentage, and application dosage mostly uses mu application rate or hectare application rate as units.

## Constraints for Tool Calling and Plugins
The data fields include specialized chemical parameters and agricultural scenario fields. Tool calling must accurately match field names and units to avoid call failures caused by format errors. Businesses such as agricultural materials inspection and compliance review often involve image/PDF file streams, such as inspection reports and product packaging labels, so support for binary stream parsing capabilities is required. Some official regulatory interfaces require identity authentication, so secure identity verification parameters must be configured for tool calling. There are differences in data update frequencies, so trigger rules for scheduled synchronization plugins must be set to ensure the timeliness of called data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Allows the system to automatically match tools related to fertilizer and pesticide business, reducing manual configuration costs |
| `functionCall` | `enabled` | Forces structured tool calling to ensure returned data conforms to preset field formats |
| Tool call timeout | `300 seconds` | Agricultural materials data interfaces mostly involve batch queries and file parsing, requiring sufficient response time |
| File stream processing mode | Parse as binary stream | Adapts to image/PDF file stream formats such as agricultural materials inspection reports and product packaging labels |
| Environment variable call permission | Only allow calling preset variables | Avoids leakage of sensitive configuration information from agricultural materials enterprises |

## Three Common Misconfigurations
- Phenomenon: When calling the agricultural materials inspection interface and returning an image stream, the workflow output is empty. Cause: The file stream parsing mode is not configured, and only text content is attempted to be parsed.
- Phenomenon: After configuring custom environment variables, the workflow call fails and the log shows that the variable was not found. Cause: The environment variable call permission is not enabled, or the variable name does not fully match the workflow configuration.
- Phenomenon: The application test works normally but the API call returns an empty response. Cause: The `toolChoice` parameter is not set correctly, causing automatic tool calling to not trigger.

## How to Verify Successful Configuration
- Pass a query text containing product name and active ingredients, initiate a tool call, and check whether the returned structured data includes preset fields.
- Upload an agricultural materials inspection image file stream, verify whether the workflow can correctly parse and extract product-related information.
- Call a tool node bound to environment variables, check whether the variables can be loaded normally and participate in calculations.
- Initiate an API call, compare whether the return result of the application test interface is consistent with the API return content.

The values provided are common starting points and should be measured against the reader's own samples.
