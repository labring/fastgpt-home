# Business Process Guidance for Fertilizer and Pesticide: Document Parsing and Chunking

## What Data for This Category Looks Like
Documents for fertilizer and pesticide business processing mainly come from agricultural and rural affairs department filing documents, agricultural materials business license archives, pesticide registration certificates, fertilizer formula reports, and similar materials. Document updates follow the rhythm of industry filing and business license review. Documents contain structured tables such as ingredient content tables and application dosage tables, long-form compliance descriptions, standardized business process nodes, and similar structural elements. Fields include agricultural-specific parameters such as active ingredient content, registration certificate number, and application dosage unit. Some documents include multilingual compliance notes.

## Constraints Imposed on Document Parsing and Chunking
Fully extract all fields from structured tables, and avoid splitting parameter content that spans multiple cells.
Retain logical coherence for long-form compliance descriptions and process nodes, and do not split consecutive business steps into different chunks.
Bind agricultural-specific units to their corresponding parameters, and do not split these bindings across chunks.
Set reasonable timeout and file size limits for bulk-parsed filing documents with large file sizes, to avoid parsing failures.

## Configuration Settings
The following configuration logic applies to FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the combined length of long compliance paragraphs and structured tables in fertilizer and pesticide documents, avoiding splitting content across key fields |
| `chunkSplitter` | Split by paragraph + title | Matches the document structure divided by chapters and process nodes, retaining logical coherence of business processing workflows |
| `customPdfParse` | Enable table extraction mode | Targets the large volume of structured content such as ingredient tables and dosage tables in documents, ensuring full extraction of table fields |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to the typical file size of single agricultural materials filing documents, avoiding exceeding parsing limits |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses loading time for compliance description sections during long document parsing, ensuring complete parsing |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking rules to meet industry-specific requirements for unit and parameter binding |

## Three Common Configuration Mistakes
- Extracted documents lack table fields, and no ingredient content or dosage information displays in the knowledge base. This occurs because the table extraction mode of `customPdfParse` is not enabled, and the default parsing logic does not fully capture structured table content.
- Some files in bulk parsing prompt timeout, and the task status shows failed. This occurs because the value of `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted, and parsing time for long filing documents exceeds the default setting.
- Chunked content spans business process nodes, such as splitting "submission of application materials" and "on-site inspection" into different chunks. This occurs because `chunkSize` is set too small, and the chunking rule of splitting by title + paragraph is not used.

## How to Verify Correct Configuration
- Upload a single pesticide registration certificate document containing an ingredient table. Check whether all table fields in the parsing result are fully extracted, and confirm that the configuration of `customPdfParse` takes effect.
- View the bulk parsing task logs. Confirm that parsing time for all files does not exceed the set value of `PARSE_FILE_TIMEOUT_SECONDS`, and no timeout errors occur.
- Randomly sample chunked content. Check whether it is divided by document titles and paragraphs, and no cross-business process splitting occurs.
- Adjust the value of `chunkSize` and re-parse the test document. Observe whether the length of chunked content meets expectations, and confirm that `chunkSettingMode` is in manual configuration status.
