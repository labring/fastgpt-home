# Business Process Guidance for Fertilizers and Pesticides: Deployment and Upgrade

## What the Data for This Category Looks Like
Data for fertilizer and pesticide business process guidance comes primarily from production ledgers of agricultural input manufacturers, the Ministry of Agriculture and Rural Affairs’ agricultural input filing database, and application materials from local government service platforms. Update frequency aligns with enterprise production cycles and policy filing requirements. Documents submitted for a single application are mostly structured business forms and third-party compliance test reports, including fields such as registration certificate number, active ingredient content, production batch number, applicable crop scope, and safe application dosage. Units include common agricultural measurement standards such as grams per liter, kilograms, hectares, and mu.

## Constraints Imposed on Deployment and Upgrade
Structured data fields for fertilizer and pesticide business include professional measurement parameters. During deployment, ensure the system accurately matches form fields to business process nodes to avoid deviations in process guidance. Data updates adjust with production and filing cycles. During deployment, reserve flexibly configurable data source connection logic to adapt to non-fixed-cycle data synchronization. Single applications involve multi-page compliance reports and attachments. During deployment, configure storage and indexing rules that support batch parsing of multiple files. During upgrade, support format changes for filing data across different batches to avoid interrupting ongoing business processes.

## Configuration Settings
This configuration rule applies to FastGPT v4.17.0. Specific configuration items are listed below:

| Configuration Item | Suggested Setting | Rationale |
| ---- | ---- | ---- |
| `STORAGE_S3_ENDPOINT` | Intranet access address corresponding to the enterprise’s self-built object storage | Most fertilizer and pesticide filing documents are compliance attachments; intranet access improves parsing speed and data security |
| `PG_URL` | Connection address and authentication parameters for the business processing database | Business processing workflows need to associate historical application data, requiring a stable PostgreSQL database connection |
| `REDIS_URL` | Address of a locally deployed Redis service, with memory quota no less than 2048 MB | Session data for business processing and parsed document fragments must be cached to ensure real-time process guidance |
| `DB_MAX_LINK` | 300–500 | Concurrent volume of fertilizer and pesticide business processing fluctuates with busy farming cycles; reasonable connection count prevents database connection exhaustion |
| `FILE_TOKEN_KEY` | Custom 32-character random string | Ensures security of upload and download permissions for business processing attachments |
| `ROOT_KEY` | Key only known to internal operation and maintenance personnel | Restricts modification permissions for core configurations to avoid operational errors affecting business processes |

## Three Common Errors
- When deploying Qwen3 series models using VLLM, valid active ingredient content fields cannot be extracted from business process documents parsed from PDFs. Extraction works normally when using Qwen2.5-14B. The cause is that the Qwen3 series models have not adapted their context association logic for professional agricultural measurement fields to the structured matching rules of business process forms. Adjust the association configuration for model calls to resolve the issue.
- The PostgreSQL container starts with the error "FATAL: role \"postgres\" does not exist". The cause is that the default PostgreSQL database role was not initialized after upgrading the version. Execute the initialization script to complete basic configuration.
- Connection timeout errors occur when connecting to the Qwen3-Embedding-8B model deployed via VLLM. The cause is that the correct model access port and intranet security group rules were not configured, preventing the FastGPT service from establishing a stable connection with the locally deployed model service.

## How to Confirm Successful Configuration
- Run the docker-compose ps command to confirm all deployed containers have a status of Up.
- Upload a fertilizer and pesticide compliance test report PDF to test the document parsing function, and confirm that specified fields such as registration certificate number and active ingredient content can be extracted.
- Call the test interface for the business process guidance function to simulate user application submission, and confirm that session data can be written to the Redis cache normally.
- Modify the core configuration item `ROOT_KEY`, and confirm that unauthorized users cannot access the system backend configuration page.

The values provided are common starting points and should be evaluated against the reader’s own samples.
