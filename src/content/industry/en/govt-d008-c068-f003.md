# Business Process Guidance for Pharmaceutical Distribution: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Pharmaceutical distribution business data primarily originates from four categories: pharmaceutical business license archives, purchase and sales ledgers, cold chain transportation monitoring records, and medical insurance settlement vouchers. Data is updated per purchase and sales batch. Each batch of data includes fields such as purchase and sales order number, generic drug name, production batch number, expiration date, circulation node, handler, and cold chain temperature record. Most fields use string or date formats, and complete circulation information must be associated using batch numbers.

## Constraints Imposed by These Characteristics on the "Multi-turn Dialogue and Prompt Engineering" Link
The large number of data fields and the requirement to associate data by batch mean multi-turn dialogue must continuously track the current session's batch number to avoid mixing data across batches. Data is updated at a high frequency, so real-time retrieval of the latest ledger or cold chain data is required during dialogue, and expired cached context cannot be used. There are many professional terms, so prompts must clearly limit the dialogue scope to the current business handling process to prevent the introduction of irrelevant historical data. Tool call parameters must strictly match the current session's fields to avoid errors caused by parameter mismatches.

## Configuration Settings
The following configuration items apply to FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Store current purchase and sales batch number, cold chain node ID | Associate pharmaceutical circulation data across different stages of multi-turn dialogue to avoid mixing across batches |
| `messages` | Splice context according to session history | Ensure complete transmission of context for multi-turn dialogue without loss of critical information |
| Maximum context per single dialogue | 1200–1500 characters | Cover the complete process nodes of a single business handling process, avoid context truncation |
| Tool call timeout | 600 seconds | Match the typical time required for cold chain verification and qualification review in pharmaceutical distribution business |
| Maximum tool call count | 5 times | Prevent resource consumption caused by unrestricted tool calls |
| Historical session binding | Bind current session via `chatId` | Ensure coherent dialogue context for the same business handling process, avoid interference from cross-session data |

## Three Common Misconfigurations
- Phenomenon: A 400 status code (no body) is returned when calling the MySQL tool. Cause: Required fields for database connection are not configured in `variables`, resulting in missing request parameters.
- Phenomenon: Previously saved global variables cannot be loaded in a new dialogue. Cause: Variables storage for the corresponding session is not bound via `chatId`, resulting in failure to associate context.
- Phenomenon: Mixing of pharmaceutical data across batches occurs during multi-turn dialogue. Cause: The prompt does not explicitly require filtering data based on the batch number in the current session's `variables`.

## How to Verify Proper Configuration
- Initiate a simulated pharmaceutical purchase and sales business handling dialogue, check whether the cold chain transportation data of the current batch is automatically brought out during the dialogue.
- Trigger a tool call, verify that the returned results match the preset pharmaceutical distribution business fields, with no additional irrelevant data.
- Switch the session ID, confirm that the previous global variables are not loaded by the new session to ensure context isolation.
- View the tool call logs, confirm that the timeout setting meets the expected business time consumption, and there are no frequent timeout errors.

The values provided here are common starting points, and should be evaluated against the user's own samples.
