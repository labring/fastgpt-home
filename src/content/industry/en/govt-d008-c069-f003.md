# Hazardous Chemical Storage and Transportation Business Process Guidance: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Business data for hazardous chemical storage and transportation originates from four internal enterprise sources: inbound and outbound inventory ledgers, transportation dispatch logs, safety supervision compliance documents, and container inspection reports. Data update frequency varies by business type. Inbound and outbound inventory ledgers are updated daily. Compliance documents are synchronized quarterly or annually. Individual documents include fields such as work ticket number, hazardous chemical name, CAS number, storage location, transportation vehicle information, approval status, and expiration date. Field units include tons, cubic meters, liters, hours, and other standard units. Some documents contain long-text approval process instructions spanning multiple pages.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
The multi-field structure of hazardous chemical storage and transportation data requires dialogue to gradually guide users to provide accurate business information. This prevents process interruptions caused by missing fields. Frequently updated inventory ledgers and dispatch logs require prompt engineering to regularly sync the latest safety supervision compliance requirements. This stops outdated handling rules from being returned. The presence of long-text approval documents requires multi-turn dialogue to filter redundant information. It focuses instead on core approval nodes and field verification. Field unit specificity requires dialogue to actively prompt users to confirm unit matching. This prevents handling errors caused by unit confusion.

## Three Common Misconfigurations
- An API call returns a file parsing failure error with status code 400. This occurs because the default chunking rules do not adapt to the long-field structure of hazardous chemical storage and transportation documents, truncating core business fields such as CAS numbers and approval ticket numbers.
- The dialogue answers generated by the platform test do not match the results from the API call. This occurs because the API request does not correctly pass the historical dialogue context for the `messages` parameter, preventing the system from connecting prior handling steps.
- No matching storage and transportation process content loads after the floating dialog box is triggered. This occurs because the dedicated knowledge base data source for hazardous chemical storage and transportation is not associated, and only a general question-answering model is called.
