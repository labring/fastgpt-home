# Hazardous Chemicals Storage and Transportation Business Process Guidance: Workflow Orchestration

## What the data for this category looks like
The data for hazardous chemicals storage and transportation mainly comes from the internal enterprise storage and transportation management system, the local emergency management department’s filing ledger, and transportation dispatch logs. The data update rhythm is daily synchronization of same-day inbound and outbound records, and weekly updates of compliance filing information. The document structure includes fields such as storage and transportation order number, general chemical name, CAS registry number, storage area number, transportation route latitude and longitude, approval node status, operator ID and contact information. Most field units are physical or process units such as tons, cubic meters, kilometers, and hours.

## What constraints these characteristics impose on the "workflow orchestration" link
Decentralized data sources mean that the workflow must be configured with multiple data source connection nodes, which connect to the internal enterprise system, filing platform, and dispatch log respectively to avoid missing data from a single source. Fields include dedicated numbers and physical units, so the workflow must add a `variables` verification link to match the field format and unit requirements stored in `variables`. Daily updated inbound and outbound data must be bound to a scheduled trigger node, while weekly updated filing data requires a weekly-level synchronization task to avoid data lag affecting process guidance. The status transition of approval nodes must match business rules, and the execution order of each node must be specified via `nodeId` to ensure correct process logic.

## How to set the configurations
| Configuration Item | Recommended Setting | Basis for This Setting |
| --- | --- | --- |
| Scheduled trigger node | Trigger at 02:00 daily and 03:00 every Monday | Matches the rhythm of daily updates for hazardous chemicals inbound and outbound data and weekly updates for filing data |
| Variable verification | Verify the CAS number format and storage volume unit of the `variables` field | Corresponds to the dedicated fields and unit requirements for hazardous chemicals data |
| Node execution order | Specify the trigger order of each data source node via `nodeId` | Ensures logical consistency for multi-data source access |
| Data source access order | Prioritize connecting to the internal system, then the filing platform, and finally the dispatch log | Prioritize obtaining enterprise-owned data, supplemented by external filing and dispatch information |
| Node timeout setting | 600-second timeout retry | Adapts to the average response duration of cross-system data pulling |
| Branch jump rule | Jump to the corresponding guidance link based on the approval node status | Matches the node transition logic of the business handling process |

## Three common mistakes
- An error occurs when calling `localStorage.getItem('userId')` in the workflow, with the prompt `localStorage is not defined`. The reason is that the FastGPT workflow running environment is server-side, which does not support browser-side localStorage APIs.
- Attempting to directly obtain the shared application URL address in the workflow fails and returns a null value. The reason is that no global variable or data source node is configured to obtain application metadata, and the workflow cannot directly read front-end page parameters.
- Custom reference templates and prompt word configuration cannot be used in FastGPT v4.8.22. The reason is that this function is not available in this version. Upgrade to FastGPT v4.9.7 or a later version to use this function.

## How to confirm the configuration is complete
- Trigger the scheduled node and check whether the corresponding data source has pulled the same-day/weekly hazardous chemicals data.
- Simulate input of an incorrectly formatted CAS number or storage volume unit to verify whether the `variables` verification link intercepts abnormal data.
- Manually trigger the workflow and check whether the branch jump matches the preset approval node status.
- View the workflow logs to confirm that the response duration of all nodes does not exceed 600 seconds.
