# Hazardous Chemical Storage and Transportation Business Process Guidance: Deployment and Upgrade

## What the data for this category looks like
Business process data for hazardous chemical storage and transportation comes from the enterprise's internal hazardous chemical storage and transportation management system and compliance guidance documents publicly released by the local emergency management department. The data update rhythm is daily updates of storage and transportation ledger data, and monthly synchronization of the latest business process policy documents. The document structure includes fields such as hazardous chemical name, UN number, storage bin number, approval process node, processing time limit, required material list, and operator qualification requirements. Field units include tons, cubic meters, calendar days, qualification level numbers, etc. Some fields must comply with national hazardous chemical compliance standard formats.

## What constraints these characteristics impose on deployment and upgrade
Hazardous chemical storage and transportation data comes from two sources, and its fields include professional compliance requirements. This imposes three constraints on deployment and upgrade. First, configure multiple database connections to adapt to heterogeneous data sources, corresponding to the `MONGODB_URI` and `PG_URL` parameters, to avoid data docking conflicts. Second, the data fields have fixed format verification rules. When upgrading, retain the original field mapping logic to prevent errors in the preprocessing link. Third, the data update frequency is high and involves compliance content. During deployment, pre-set scheduled synchronization tasks. During upgrade, ensure that the synchronization service runs without interruption, and configure data encryption parameters to protect sensitive information security. ## How to Set Configuration Values

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/fastgpt_chemical?authSource=admin` | Adapt to hazardous chemical storage and transportation ledger data storage, support multiple collections to store different types of business documents |
| `PG_URL` | `postgresql://[username]:[password]@[host address]:[port]/chemical_approval` | Connect to the compliance approval database of the local emergency management department, store approval process node data |
| `REDIS_URL` | `redis://:[password]@[host address]:[port]/0` | Cache frequently queried hazardous chemical compliance information to reduce database concurrency pressure |
| `DB_MAX_LINK` | `20–30` | The concurrent query volume of hazardous chemical storage and transportation data is relatively high, avoid service exceptions caused by connection pool exhaustion |
| `STORAGE_S3_ENDPOINT` | Fill in according to the actual address of the enterprise's internal object storage | Store electronic material attachments required for hazardous chemical approval, comply with compliance data storage requirements |
| `FE_DOMAIN` | `https://[internal enterprise hazardous chemical service domain name]` | Configure the access address of the business process guidance page, adapt to the enterprise's internal office scenario |

## Three Common Misconfigurations
- After executing the upgrade trigger command, a POST /api/admin/initv4818 404 status code is returned, and the log indicates the request cannot locate the corresponding interface. The cause is that the `ROOT_KEY` parameter is not configured correctly, which prevents the backend from verifying the permissions of the upgrade request and intercepts legitimate upgrade calls.
- Garbled characters or omissions appear in the voice consultation session of the business process guidance page. The cause is that the `FILE_TOKEN_KEY` parameter is not configured during deployment, causing the storage verification of the voice recognition result file to fail and unable to properly read the recognition content.
- A storage error occurs during scheduled synchronization of hazardous chemical data, and the synchronized ledger data cannot be saved. The cause is that the `STORAGE_S3_ENDPOINT` parameter is not configured, making it impossible to connect to the enterprise's internal object storage service, resulting in data persistence failure.

## How to Confirm Configuration Completion
- Execute `curl -X POST http://[backend deployment address]/api/admin/initv4818 -H "Authorization: Bearer ${ROOT_KEY}"` and confirm that the returned status code is 200.
- Access the business page configured in `FE_DOMAIN`, try to query the processing process of a certain type of hazardous chemical, and confirm that the page loads without timeout and the data is fully displayed.
- Upload a test electronic material, confirm that the corresponding file can be found in the object storage service corresponding to `STORAGE_S3_ENDPOINT` via the storage path.
- Check the cache service log corresponding to `REDIS_URL` and confirm that frequently queried hazardous chemical compliance information has been normally cached.
