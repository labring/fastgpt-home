# Business Handling Process Guidance for Power Generation Equipment Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Power generation equipment manufacturing business handling data mainly comes from equipment factory technical documents, on-site maintenance records, and business handling work order forms. Factory documents are statically updated and adjusted with equipment model iterations. Maintenance records are updated monthly based on maintenance cycles. Business work orders dynamically adjust along with handling processes. Data document structures are categorized by equipment model, and include fields such as equipment number, rated power, maintenance cycle, and consumable model. Units involve professional industrial units such as kilowatts, hours, and megapascals. The length of individual documents varies widely.

## How These Characteristics Impose Constraints on Multi-turn Dialogue and Prompt Engineering
Power generation equipment manufacturing business data includes a large number of professional industrial fields, and document lengths vary widely. This requires multi-turn dialogue to accurately bind exclusive equipment parameters to avoid confusing context across different work orders. Static factory technical documents and dynamic maintenance records coexist. Prompt engineering must distinguish data timeliness and prioritize calling the latest maintenance records. Business handling processes have many nodes. Multi-turn dialogue must ask for missing handling materials in sequence according to the process, and cannot obtain all information at one time. In addition, individual documents are long. Teams must limit context window length to prevent exceeding system processing limits.

## How to Set Configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context window | First 8 turns of dialogue, total characters not exceeding 1200 | Adapt to the varying length of power generation equipment business documents and avoid exceeding system processing limits |
| `variables` binding rule | Bind equipment number and work order ID fields | Accurately match exclusive business data of corresponding equipment and avoid context confusion |
| `messages` format configuration | Splice in the format of "user question - system prompt - equipment data" | Ensure that prompt engineering can call exclusive business data and clarify the boundaries of dialogue context |
| Multi-turn follow-up trigger condition | Triggered when more than one handling material is missing | Adapt to the multi-step confirmation logic of business handling processes |
| Maximum follow-up question count | Maximum 3 items | Avoid outputting too much professional industrial information at one time and match the rhythm of business handling |
| `chatId` binding rule | Bind equipment handling work order ID | Ensure that dialogue context for the same work order is not disturbed by cross-work order calls |

## Three Common Misconfigurations
- All replies from multiple AI dialogue nodes in the workflow appear in the chat window. No filtering rule for `messages` is configured, and the system does not specify retaining only output content from the current session link.
- Only single questions are supported, and multi-turn business guidance cannot be completed. No dynamic field extraction rule for `variables` is bound, and subsequent confirmation triggered by process nodes is not set.
- Irrelevant historical equipment data appears in the dialogue. `chatId` is not correctly bound to the equipment handling work order ID, resulting in cross-work order context being called.

## How to Confirm Proper Configuration
- Initiate a simulated business handling query to verify that the system asks for missing handling materials or equipment parameters.
- Configure multiple AI dialogue nodes, initiate a complete work order process, and check that only replies from the current link display in the chat window.
- Switch between different equipment work orders to verify that dialogue context does not get confused across work orders, and only retains dialogue content for the current work order.
- Input dialogue content exceeding the set length to check that the system automatically truncates old dialogue context and retains the latest session content.
