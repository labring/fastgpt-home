# Business Process Guidance for Power Generation Equipment Manufacturing: Workflow Orchestration

## What the data for this category looks like
Business data for power generation equipment manufacturing mainly comes from equipment operation and maintenance logs, production work orders, quality inspection reports, supply chain documents, and other sources. Data sources include real-time equipment operating parameters, offline work order records, cross-department collaboration documents, and similar types. Update frequencies fall into three categories: real-time (equipment operating data), daily (work order summary reports), and monthly (production capacity statistical reports). The document structure includes structured fields and unstructured content. Structured fields include equipment number, rated power (unit: kW), operating hours (unit: h), fault code, and others. Unstructured content includes on-site operation and maintenance notes, fault troubleshooting records, and similar content.

## How these characteristics constrain workflow orchestration
The multi-type data characteristics of power generation equipment manufacturing create multiple constraints for workflow orchestration. Real-time operating data requires workflow node trigger intervals to not exceed a preset duration, to prevent data lag from impacting process timeliness. Multi-field structured work orders require workflows to bind different fields via `variables` to automatically inject parameters. Unstructured operation and maintenance notes require a classification node to be connected first before proceeding to subsequent processing flows, adding pre-configuration steps. Field mapping for cross-department documents requires fixed variable binding to avoid process execution errors caused by parameter confusion.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind equipment number, fault code, operating hours | Match core structured fields of power generation equipment manufacturing work orders to enable automatic import of process parameters |
| `nodeId` | Assign different node IDs based on fault severity | Differentiate processing branches for faults of varying severity levels, to adapt to multi-scenario business processes |
| Session submission button | Configure in the work order confirmation step, with display text set to "Submit Processing Result" | Align with the operating habits of on-site operation and maintenance personnel, and clearly define the interactive trigger point |
| Mermaid call configuration | Call the specified MCP Server interface, set timeout to 30 seconds | Generate fault handling flowcharts to support business review needs |
| Maximum loop count | Set to 8 | Limit retry attempts to avoid invalid loops consuming system resources |

## Three common configuration errors
- Phenomenon: The knowledge base search returns empty fields, and workflow nodes cannot retrieve correct parameters. Cause: Exclusive fields of power generation equipment work orders are not bound in `variables`, so variable references fail to match the corresponding data source.
- Phenomenon: The submission button does not appear in the session interface, preventing users from triggering process submission. Cause: The submission button is configured on a non-interactive node, and the session interaction switch is not enabled.
- Phenomenon: Calling the MCP Server to generate a flowchart fails, returning a timeout error. Cause: A reasonable timeout period is not set, or the interface address is configured incorrectly, preventing the request from completing normally.
