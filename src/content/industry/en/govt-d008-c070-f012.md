# Business Process Guidance for Power Generation Equipment Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
Business process guidance data for power generation equipment manufacturing originates from real-time operation and maintenance logs, production work order systems, quality inspection archived documents, and spare parts requisition ledgers. The data uses three update schedules: real-time pushed equipment operation status logs, daily archived work orders and quality inspection reports, and on-demand updated spare parts inventory ledgers. Each document follows a fixed structure, including a unique equipment identifier, operation and maintenance timestamp, fault classification, disposal process, and associated spare parts number. Field units adhere to industrial standard formats, with no custom non-standard units.

## What Constraints These Characteristics Impose on the Deployment and Upgrade Phase
Real-time operation and maintenance logs have high concurrent write demand. Database connection parameters must be adapted to industrial-grade read and write pressure during deployment to avoid connection exhaustion.
Multi-update-frequency data modes are used. Upgrades must support both incremental synchronization and full data completion to prevent data gaps.
Field structures and units are fixed. Field mapping configurations during upgrades must strictly match the original document format to prevent parsing failures.
Equipment and process data are frequently associated. A caching mechanism must be configured during deployment to reduce repeated database query pressure.

## How to Configure the Settings

| `DB_MAX_LINK` | 120–180 connections | Adapts to the concurrent write demand of real-time operation and maintenance logs for power generation equipment manufacturing, avoiding connection pool exhaustion |
| `MONGODB_URI` | Cluster connection address with read-write separation suffix | Supports high-concurrency work order and log data storage, ensuring read-write separation performance |

| `FILE_TOKEN_KEY` | String generated following enterprise unified encryption rules | Ensures the security of document access tokens, preventing unauthorized downloads |

## Three Common Configuration Errors
- Phenomenon: After connecting a custom vector model, the process guidance call returns `400 Bad Request`, with a prompt that the model input dimension does not match. Cause: The input parameters of the vector model were not adjusted according to the fixed field structure of power generation equipment documents, resulting in inconsistent embedding results and stored data formats.
- Phenomenon: After upgrading to FastGPT v4.17.0, the knowledge base page fails to load, and the interface displays a blank screen. Cause: The cluster authentication configuration for `MONGODB_URI` was not updated synchronously during the upgrade, resulting in failure to connect to the original business data storage.
- Phenomenon: The conversation page for business process guidance crashes when loading a large volume of work order data. Cause: The concurrent connection limit for `DB_MAX_LINK` was not enforced, resulting in excessive memory usage that triggers process exit.

## How to Confirm Proper Configuration
- Check database connection pool monitoring to confirm that the current active connection count does not exceed the `DB_MAX_LINK` configuration value, and adjust the configuration as needed to match actual concurrent volume.
- Submit a simulated power generation equipment operation and maintenance work order to verify that the process guidance correctly returns the corresponding disposal steps and associated spare parts information, confirming that data parsing is functioning normally.
- Check cache hit logs to confirm that frequently queried equipment status data is correctly cached, verifying that the `REDIS_URL` configuration is effective.
- Access the business entry configured via `FE_DOMAIN` to confirm that the process guidance page can jump normally and load internal system data, verifying that the domain name configuration is correct.
