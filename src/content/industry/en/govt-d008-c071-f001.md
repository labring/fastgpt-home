# Business Process Guidance for Power Generation Groups: HTTP Interfaces and External Systems

## What this category of data looks like
Business process data for power generation groups primarily comes from internal production operation systems, work order approval platforms, and offline business registration ledgers. Data is synced in real time when a business is submitted or a node transitions. Each individual business document includes fields such as a unique process identifier, current processing node, required submission material list, processing time limit, and responsible team information. The processing time limit field uses hours as the unit. The material list uses a multi-text array format. The process identifier uses a fixed-length alphanumeric combination.

## What constraints these characteristics impose on HTTP interfaces and external systems
Real-time updated business data with a multi-field structure requires HTTP interfaces to support array format for the material list field, to avoid parsing failures caused by missing fields. Processing time limits use hours as the unit. Interfaces must convert these uniformly to time units recognizable by downstream systems, with no additional format conversion required. The process identifier is a fixed-length alphanumeric combination, so interfaces must validate the field format and filter invalid characters. Internal group systems have strict permission check requirements. Interface calls must carry a valid `Authorization` parameter to ensure data access complies with internal security specifications. Business node transitions occur frequently, so interfaces must support high-frequency calls. A reasonable timeout configuration is needed to maintain continuous process guidance.

## How to set configurations
This guidance is written for FastGPT v4.17.0.

| `Authorization` | Use the group's internal API key prefixed with `Bearer ` | Complies with the permission check specifications of the power generation group's internal systems, ensuring compliance of interface call access permissions |
| `variables` | Bind the two core variables: unique process ID and current processing node | Adapts to the dynamic field characteristics of the power generation group's business data, enabling parameter transfer for different business scenarios |
| `responseData` | Extract the three fields: process node, required material list, and processing time limit | Filters redundant business data, improving interface response and parsing efficiency |
| Interface timeout | 600 seconds | Matches the typical time required for power generation group business node transitions, preventing process guidance interruptions from timeouts |
| Request body format | JSON format | Compatible with the interface data transmission standards of the power generation group's internal systems, ensuring correct field parsing |

## Three common configuration errors
- After calling the interface, the return result is empty, and the FastGPT log shows the `responseData` field did not match business data. This occurs when the core fields of the power generation group's business data are not correctly extracted, and the interface's configured extraction range does not match the actual business document structure.
- The interface call returns a 403 permission error, and the interface prompts that access is not allowed. This occurs when the `Authorization` parameter does not use the group's internal compliant key format, failing to pass the internal system's permission check.
- Calling a workflow via API does not trigger a user input prompt. This occurs when dynamic parameters related to form input are not bound in `variables`, causing the workflow to fail to identify nodes that require collecting user information.

## How to verify a correct configuration
- Call the configured HTTP interface, check if the returned `responseData` includes the preset core business fields, and confirm the field format matches the power generation group's business data structure.
- Simulate the scenario of internal power generation group business node transitions, call the interface to verify that the permission check takes effect, and confirm the interface returns normally when the `Authorization` parameter is compliant.
- Trigger the form input node in the workflow, call via API to verify that the user input prompt appears normally, and confirm the `variables` parameters are bound correctly.
- View the interface call logs, confirm the timeout configuration meets the business scenario requirements, and that frequent timeout errors do not occur.
