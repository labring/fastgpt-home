# Business Handling Process Guidance for Power Generation Groups: Tool Calling and Plugins
This document is written for FastGPT v4.17.0.

## What the Source Data Looks Like
The business handling data of power generation groups mainly comes from internal production management systems, fuel dispatching systems, and government approval platforms. Data update timing is triggered by business nodes: real-time updates occur when work orders are completed or approvals pass, while non-real-time data is synchronized in daily batches. Each business document is a structured form containing fields including business number, generator set number, handling node, required material list, and handling time limit. Field units include "unit", "ten thousand kilowatts", and "working days". Some fields are linked to the group's internal standard coding system.

## Constraints for Tool Calling and Plugins
The structured nature of power generation group business data requires tool calls to match internal standard codes; otherwise, correct association with business work orders cannot be achieved. Real-time updated business node data requires plugin calls to synchronize and pull the latest status when business processes trigger, to avoid returning outdated information. The feature of multiple fields linked to the internal standard system requires tool parameters to preset the enumeration value range corresponding to the codes, reducing the probability of format verification failures. Additionally, business handling processes have multiple node levels, so tool calls must be triggered step by step according to process nodes, to avoid loading excessive redundant data in a single call and affecting context processing efficiency.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Tool call trigger timing | Triggered by business node | Power generation group business processes advance by node; triggering by node accurately matches the data required for the current handling link |
| `functionCall` enable status | Enabled | Internal business system interfaces must be called to pull structured work order data; enabling this parameter forces specification of the target tool to call |
| Single tool call timeout period | 30 seconds | Internal business system interface responses typically complete within 20 seconds; buffer time is reserved to avoid timeout failures |
| Tool return data filtering rules | Retain fields related to the current node | Power generation group business documents contain redundant fields across multiple nodes; filtering compresses context length |
| `toolChoice` configuration | Automatically select matching tools | Adapts to tool calling requirements for multiple business types in power generation groups, no manual tool switching required |

## Three Common Configuration Errors
- Calling a tool returns the error "You need to use the app key rather than the account key", and business data cannot be pulled normally. The app-level app key was not used for the call; the account key was mistakenly used, leading to permission verification failure.
- Calling the text-to-SQL tool returns empty results or format errors. No corresponding SQL mapping rules were configured for the structured fields of power generation group business, so the generated SQL cannot match the internal business table structure.
- Image links are not automatically replaced after calling the file processing tool. The access address of the target file server was not specified in the plugin configuration, so the tool cannot complete image upload and link replacement operations.

## How to Verify Correct Configuration
- Trigger a tool call for the corresponding business node, check system logs to confirm the called tool matches the current business node.
- After calling the tool, check the returned business data to confirm only fields related to the current node are included, with no redundant content.
- Input a test business question to confirm the tool call correctly pulls the latest status data of the corresponding work order.
- Switch to test scenarios of different business types to confirm `toolChoice` automatically matches the corresponding tool.

The values provided are common starting points and should be evaluated against the reader's own samples.
