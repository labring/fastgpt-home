# Business Process Guidance for Power Generation Groups: Deployment and Upgrade

## What this category of data looks like
The business process guidance data for power generation groups primarily comes from internal OA systems, power business handling platforms, and latest power regulatory policy documents.
Data is divided into multiple modules by business type, including grid connection application, electricity installation application, qualification review, and others.
Each module includes fields such as handling steps, required material lists, handling time limits, consultation channels, and additional relevant details.
Data update cycles are triggered by policy adjustments or business process optimizations.
A single update covers all documents for the corresponding business module.
Documents are mainly structured text, with some including attachment format instructions.
Fields uniformly use standard power industry terminology.
Handling time limit units are working days.
Material lists note format requirements for submitted items.

## Constraints imposed on deployment and upgrade
Power generation group business data contains a large number of power-specific terminology and structured fields.
During deployment, adapt proxy configuration for the internal network environment to ensure updated policy documents can be retrieved.
Data update frequency fluctuates with business adjustments.
During upgrade, retain custom terminology library configurations to avoid deviations in professional term recognition.
Field differences in structured documents will affect the vector database index structure.
Before deployment, verify existing data against the field mapping rules of the new FastGPT version.
Sensitive business data storage must comply with power industry data security regulations.
Corresponding storage configurations must meet encryption requirements.

| `FILE_TOKEN_KEY` | `32 randomly generated characters` | Used for token signature of file uploads, ensures security of attachment access |

## Three Common Misconfigurations
- Internal network environments cannot retrieve external policy documents, and the interface shows connection timeout. No HTTP proxy with username and password is configured, preventing access to the internet via proxy to obtain the latest business data.
- After upgrading to FastGPT v4.17.0, the custom power professional terminology library becomes invalid, and recognition of professional terms in business guidance deviates. Configuration files from the deployment phase are not backed up and restored, resulting in configuration reset after upgrade.
- After saving the large model configuration, the model called during chat does not match the set values. Administrator permissions are not properly verified, resulting in failed writing of configuration to the system, and default model parameters are used.

## How to Verify Successful Configuration
- Run the `docker ps` command to check the running status of FastGPT-related containers, confirm all containers are in normal running state.
- Access the domain name configured for `FE_DOMAIN` in the internal network environment, verify that the system homepage can be opened normally and business documents can be loaded.
- Upload a structured document for power business handling, verify that the vector database can correctly generate indexes and complete word segmentation.
- Attempt to modify administrator configurations, verify that the configuration can be successfully saved and take effect, with no error prompts.

The values provided here are common starting points, and should be evaluated against the user's own samples.
