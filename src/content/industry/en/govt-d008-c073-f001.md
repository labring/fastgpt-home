# Business Process Guidance for State-owned Industrial Funds: HTTP Interfaces and External Systems

## What this category of data looks like
Business process data for state-owned industrial funds mainly comes from three systems of the state-owned capital investment and operation platform: project declaration ledger, approval node records, and fund allocation archives. Data updates are triggered along with the processing flow of individual businesses, and corresponding business entries are updated in real time after each approval node is completed. The document structure of a single piece of business data is in structured JSON format, including fields such as project ID, full name of the declaration subject, applied amount (unit: ten thousand yuan), current approval node status, operator account, and submission time (format: YYYY-MM-DD HH:mm:ss). The approval node status uses fixed enumeration values.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
State-owned industrial fund business data is sourced from dispersed systems, requiring integration with multiple external systems. Interface authentication must adapt to identity verification rules of different systems, and valid service keys must be carried via the `Authorization` parameter to complete verification. Strict structured data requirements are in place: only predefined enumeration and numeric fields are allowed. Therefore, the `responseData` returned by the interface must accurately filter non-business fields to avoid breaking the field mapping logic of process guidance. High real-time data update requirements mean the response time of a single interface call must be controlled within a reasonable range. At the same time, global variable assignment must strictly match the field path configured in `variables` to ensure the business process correctly obtains the latest approval status and fund information.

## How to set the configurations
This page’s configuration rules are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {service access key allocated by the state-owned assets supervision platform}` | External business systems connected for state-owned industrial funds use OAuth2 authentication, requiring valid service keys for identity verification |
| `variables` | `Map to projectId, applyAmount, approvalStatus, operator` | State-owned industrial fund business data includes core business fields such as project ID, applied amount, approval status, and operator |
| `responseData` | `Only extract top-level structured business fields, filter system-level metadata` | External interface return data contains redundant system logs, call links and other non-business fields, requiring accurate extraction of valid data |
| Interface timeout setting | 30 seconds | Single interface response for state-owned industrial fund business processing must be controlled within a reasonable range to avoid process blocking |
| Global variable trigger rule | Trigger only when the interface returns a 200 status code | Ensure global variables of the business process are updated only after a successful interface call |

## Three common mistakes
- Phenomenon: Workflow global variables fail to correctly obtain business data returned by the interface, with empty field values or incorrect formats. Cause: The correct field path is not specified according to the mapping rules of the `variables` configuration item, and non-business nested fields returned by the interface are incorrectly extracted.
- Phenomenon: Interface call returns a 400 status code, prompting that the image format is not supported. Cause: The format of the uploaded business attachment is not verified, and file types that do not meet the requirements of state-owned industrial fund services are submitted.
- Phenomenon: The associated new knowledge base conversation interface call fails, and the corresponding business project cannot be bound. Cause: The knowledge base ID returned by the interface is not correctly assigned to the global variable, causing the conversation process to fail to match business data.

## How to confirm the configuration is correct
- Call the test interface, check whether the returned `responseData` only includes the configured business fields and has no redundant system-level metadata.
- Manually verify the validity of the key configured in `Authorization`, complete the verification by calling the authentication interface and returning a 200 status code.
- Trigger a simulated business process, check whether the global variable panel correctly maps the project ID, applied amount and other fields returned by the interface.
- Simulate a 30-second interface delay scenario, confirm that the process does not experience blocking or timeout errors.
