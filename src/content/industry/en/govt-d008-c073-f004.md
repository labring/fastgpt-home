# Business Process Guidance for State-Owned Industrial Funds: Workflow Orchestration

## What this category of data looks like
This category of data originates from the state-owned asset supervision platform filing repository, fund manager project management systems, post-investment operation ledgers, and local fiscal disbursement vouchers. Filing data is updated monthly. Post-investment operation data is synchronized daily. Project declaration data is updated in real time when submitted. Each data entry includes fields such as project entity name, fund subscribed scale, paid-in amount, declaration material status, current approval node, and submission time. The units for subscribed scale and paid-in amount are 100 million yuan. Declaration material status uses fixed enumeration values. Current approval node refers to the specific link name of the corresponding process.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Mode | Trigger on new project declaration data submission events; set filing data synchronization to trigger at 00:00 on the 1st of each month | Match the real-time nature of project declarations and the monthly update rhythm of filing data |
| Conditional Branch Node | Set 3 branches corresponding to pending review, rejected, and approved statuses | Adapt to process jumps for enumerated declaration material statuses |
| `variables` Binding | Bind the current approval node field to session variables | Pass dynamic node information to subsequent links in real time |
| File Transfer Node | Enable binary stream transfer mode; set single transfer limit to 1000 MB | Adapt to transfer requirements for TXT-format declaration materials |
| `nodeId` Configuration | Assign a unique fixed ID to each approval node | Facilitate process tracking and log correlation |

## Three Common Misconfigurations
- Failure to correctly bind `variables` when calling APIs in workflows causes actual business parameters to not be passed to the backend, resulting in parameter missing errors from API responses. The cause is failure to map business fields to session variables, and directly using static parameters to call APIs.
- Failure to enable binary stream mode when configuring file transfer nodes causes TXT-format declaration material transfer failures, returning a 400 status code. The cause is that the default text transfer mode cannot handle binary file streams.
- Failure to distinguish update rhythms of different data sources, and setting the same trigger frequency for filing data and declaration data causes outdated existing data updates or repeated process triggers. The cause is failure to match the update characteristics of the data itself, and configuring trigger rules uniformly.

## How to Confirm Proper Configuration
- Trigger a new project declaration data submission, check if the workflow starts automatically and completes node jumps.
- View the log collection panel, confirm that the `variables` are correctly bound to current approval node information, with no null value errors.
- Call the test interface, upload TXT-format declaration materials, check if the backend can receive them normally and return corresponding processing results.
- Trigger the monthly scheduled synchronization task, check if filing data has completed updating and been synchronized to workflow nodes.
