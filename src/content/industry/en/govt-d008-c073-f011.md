# Business Process Guidance for State-owned Industrial Funds: Forms and Interactions

## What Data for This Category Looks Like
State-owned industrial fund business data is primarily sourced from the state-owned assets supervision comprehensive platform, internal project ledgers of fund managers, and standardized electronic materials submitted by declaring entities. Data update cadence follows quarterly declaration batches or monthly review cycles, and single update data volume fluctuates with the number of declared projects. Document structure is divided into three categories: declaration forms, project review forms, and fund allocation slips. Core fields include the declaring entity’s unified social credit code (18 characters), project investment amount (unit: ten thousand yuan), fund subscribed scale (unit: hundred million yuan), review status, allocation progress, and others. All fields must strictly match the standardized format requirements of state-owned assets systems.

## What Constraints Do These Characteristics Impose on the "Forms and Interactions" Link
State-owned industrial fund business data has strict format and compliance requirements. For example, the unified social credit code must be verified for 18-character format, and amount fields must be restricted to positive real numbers. As such, form interactions must add targeted input verification rules. Data update cadence is fixed, and single submitted data volume is large, so long processes must be split into multi-step submissions to avoid single request timeouts. Project classification and fund pool information are relatively fixed, so options can be loaded via fixed data sources without frequent updates. At the same time, qualification information of declaring entities must be aligned with state-owned assets systems in real time, so interaction links must support data synchronization verification to ensure submitted data matches records in state-owned assets systems.

## Three Common Misconfigurations
- Phenomenon: The required unified social credit code field is empty after form submission, and a format error is triggered during review. Cause: No required verification and 18-character format verification rules are added to the `formInput` component, allowing invalid data to pass submission.
- Phenomenon: No available project classification options load after the user selection component is opened, or options do not match actual fund classifications. Cause: No fixed data source for state-owned fund classifications is bound, or data source update frequency does not match quarterly declaration update cadence.
- Phenomenon: The user selection node fails to load the pre-configured declaring entity list, and a parameter missing prompt appears during submission. Cause: Global variables are not correctly bound to the data source parameters of the `userSelect` component, causing the component to fail to obtain preset option data.

## How to Confirm Proper Configuration
- Test data with a compliant 18-character unified social credit code is submitted, and input verification prompts are confirmed to trigger normally, with corresponding prompts displayed for format errors.
- The user selection component is opened, and the option list of state-owned fund project classifications is confirmed to load, with the most recently updated classification selected by default.
- A submission with an amount field containing non-numeric characters is tested, and the numerical verification rule is confirmed to take effect, blocking submission of invalid data.
- Streaming response logs are reviewed, and block reception is confirmed to function normally, with response data rendered incrementally in 200–500 character blocks, with no lag or truncation.
