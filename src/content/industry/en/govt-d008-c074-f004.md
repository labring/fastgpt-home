# Business Process Guidance for State-owned Asset Management Companies: Workflow Orchestration

## Data Structure for This Category
Business data for state-owned asset management companies comes from three primary sources: state-owned asset supervision reporting systems, internal asset ledgers, and business application work orders. Data updates trigger as business process steps advance. A single business workflow, from application through archiving, generates multiple associated data records. Each individual data record includes fields such as unique asset identifier, asset category, affiliated operating entity, application item, and approval node status. Common units for these fields include ten thousand yuan, square meters, and count of processed items.

## Constraints for Workflow Orchestration
Multi-source data access requires workflows to include cross-system parameter pulling logic. This prevents node execution interruptions caused by differences in data source formats. Real-time updated data requires workflow node trigger timing to align with business update rhythms. This avoids reading outdated data. The large number of closely linked field dimensions requires clear mapping relationships for parameter transfer between workflow nodes. This prevents missing fields. Complex approval transfer chains require nested workflow execution durations to match business approval cycles. This prevents timeout interruptions.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Map unique asset ID, application item, and approval node status to global variables | Match core business data fields to enable cross-node parameter transfer |
| `nodeId` | Assign a unique identifier to each approval node | Precisely locate execution nodes in nested workflows to avoid call confusion |
| Workflow Timeout Threshold | 180–300 seconds | Align with standard approval transfer durations for state-owned asset management businesses, to prevent automatic disconnections |
| Parameter Transfer Rule | Automatically map node output fields to downstream nodes | Reduce manual configuration errors, and adapt to multi-field business data structures |
| Debug Log Switch | Enable full-link log recording | Facilitate troubleshooting of incomplete nested workflow execution |

## Three Common Misconfigurations
- Symptom: Nested workflow B fails to complete all steps, and logs show node execution timeout. Cause: No timeout threshold matching the business approval cycle was configured. The default duration is insufficient, causing execution interruption.
- Symptom: The code execution node produces output, but the downstream specified reply node cannot retrieve this result. Cause: `variables` mapping was not configured correctly. The code execution output was not transferred to the parameter variables of the downstream node.
- Symptom: The tool call node outputs redundant AI reply content. Cause: The AI reply switch after tool call was not disabled. Additional content is mixed into the business process guidance information.

## How to Verify Proper Configuration
- Submit a simulated asset disposal application work order to trigger the configured workflow. Check whether each node executes in the preset order.
- View workflow operation logs to confirm that `variables` parameters have been correctly transferred to each associated node.
- Trigger a nested workflow call. Verify that the execution duration does not exceed the preset threshold, and no automatic disconnections occur.
- Test the tool call node. Confirm that only business-required execution results are output, with no redundant AI reply content.
