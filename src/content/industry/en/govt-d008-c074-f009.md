# Business Process Guidance for State-owned Asset Management Companies: Model Access and Configuration

## What the data for this category looks like
Data related to business processes for state-owned asset management companies primarily comes from the state-owned asset supervision comprehensive platform, internal asset ledger systems, property registration archives, business approval documents, and asset evaluation reports. Data update rhythm falls into two categories: daily asset ledgers and process records are updated in batches weekly or monthly, while real-time businesses such as asset transfers and evaluation changes are updated immediately when triggered. Document structures include structured asset cards (with fields such as asset number, book value, ownership number, etc.) and unstructured approval files. Field units mostly use standard state-owned asset management units such as ten thousand yuan, square meters, and pieces. A single approval file can reach several thousand characters in length.

## What constraints these characteristics impose on the "model access and configuration" link
There are many structured fields and strict requirements for uniform units. Models must accurately match field definitions during calls to avoid format deviations. Unstructured approval files have long text lengths, so models need to support long context input to prevent truncation of key approval rules. Real-time change data must be pulled immediately, so model call interfaces need reasonable timeout settings. State-owned asset business processes have clear compliance requirements, so the randomness of model generation must be limited to ensure outputs align with internal management specifications.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| temperature | 0.1–0.3 | State-owned asset management business must strictly follow compliance processes. A low temperature parameter reduces the randomness of model-generated content, ensuring outputs align with internal rules |
| maxContext | 8000–12000 token | Adapts to the multiple fields of structured asset cards and long-text approval files, preventing key information from being truncated |
| AIPROXY_API_ENDPOINT | Internal compliant model access address for state-owned assets | Adapts to the intranet access restrictions of state-owned asset management companies, ensuring data transmission complies with security specifications |
| AIPROXY_API_TOKEN | Exclusive token generated via internal authentication | Completes identity verification for model calls, meeting the security audit requirements of state-owned asset systems |
| toolChoice | auto | Allows models to automatically call internal asset query tools based on business process needs, improving the accuracy of process guidance |
| maxTokens | 1500 token | Limits the length of single model outputs, ensuring business process steps are clear and traceable, complying with state-owned asset document archiving requirements |

## Three common errors
- Business process steps returned after model calls do not match internal state-owned asset rules. The cause is an excessively high temperature parameter, leading model-generated content to deviate from compliance requirements.
- Uploading a 3MB state-owned asset approval PDF triggers an error. When using qwen-plus as the text understanding model, verification failure occurs because the `maxContext` parameter is not adjusted, and long text input exceeds the context limit.
- After docker deployment, access to external models remains in the indexing state. The cause is that `AIPROXY_API_ENDPOINT` is configured as a public network address, failing to adapt to intranet access restrictions and causing interface call timeouts.

## How to confirm the configuration is complete
- Submit a simulated asset transfer business consultation, verifying that the process nodes in the model output match the steps in internal management documents.
- Upload state-owned asset approval PDF documents, confirming no upload errors occur and the indexing status updates from "indexing" to "ready".
- Check the FastGPT v4.17.0 model call logs, confirming that authentication token verification passes, with no 401 or network connection error reports.
- Test the tool call function, confirming that the model can correctly trigger the internal asset ledger query interface and return structured data for corresponding assets.
