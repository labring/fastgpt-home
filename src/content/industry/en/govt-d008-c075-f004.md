# Business Process Guidance for State-owned Capital Investment Companies: Workflow Orchestration

## What this category of data looks like
The business process data of state-owned capital investment companies mainly comes from internal state-owned assets supervision platforms, investment project ledgers, property right registration archives, and monthly operating reports. Data update rhythms vary by type: core approval node data is synchronized in real time, daily business ledgers are updated daily, and quarterly supervision reports are updated at the end of each natural quarter. Each individual business document contains 7 core fields: project unique identifier, full name of investment entity, approval node sequence, processing time limit (unit: working days), project amount (unit: ten thousand yuan), current processing status, and responsible department. All fields use structured text or numerical types.

## What constraints do these characteristics impose on workflow orchestration
The data characteristics of state-owned capital investment companies impose three constraints on workflow orchestration. First, data sources are scattered and update rhythms differ significantly. Workflows must configure multi-data source trigger rules via `variables` to distinguish real-time, daily, and quarterly data pull timings. Second, business documents contain fixed-sequence approval node fields. Workflow orchestration must strictly match node order via `nodeId` to avoid approval process misalignment. Third, fields uniformly use working days and ten thousand yuan as units. The workflow’s numerical verification component must preset verification logic for the corresponding units to prevent cross-unit data confusion.

## How to Configure
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `variables` | Group and configure real-time, daily, and quarterly pull variables by data source type | Match the multi-update rhythm characteristics of state-owned capital investment company data |
| `nodeId` | Bind `nodeId` sequentially according to the approval node sequence, with order matching the approval node field of the business document | Avoid approval process misalignment, adapt to business requirements for fixed node sequences |
| Text content extraction | Specify exact matching rules for project number and processing time limit fields, limit extraction range to 800–1200 characters | Adapt to precise extraction needs of structured fields, prevent cross-field mismatches |
| Loop call configuration | Set a single loop interval of 60 seconds, with a loop upper limit of 10 times | Adapt to conventional approval cycles of state-owned capital investment company businesses, avoid invalid resource occupation |
| Numerical verification | Set processing time limit verification range to 1–30 working days, amount verification range to 10,000–10,000,000,000 yuan | Match conventional numerical ranges for this category of business, filter abnormal data |
| History record call | Specify to only pull approval node records from the past 7 days | Filter redundant historical data, improve workflow operation efficiency |

## Three Common Misconfigurations
- Symptom: The text content extraction component returns an empty JSON result. Deleting and reconfiguring a component with identical parameters allows normal content retrieval. Cause: The data source variable in `variables` was not correctly associated during initial configuration, so the component failed to load corresponding business data.
- Symptom: Historical records of workflow global variables do not include the output content of the specified component. Cause: The output recording option was not enabled in the workflow node configuration, so historical variables failed to synchronize the return results of this component.
- Symptom: Timeouts or duplicate requests occur when the workflow loops calls HTTP interfaces. Cause: Reasonable loop interval and upper limit parameters were not set, so the interface request frequency exceeded the bearing threshold of the business system.

## How to Confirm the Configuration Is Complete
- Manually trigger the workflow, verify whether the data source variables in `variables` pull corresponding data according to the configured update rhythm.
- Check whether the `nodeId` order of workflow nodes matches the approval node sequence of the business document.
- Run the text content extraction component, confirm that the extraction result matches the specified field content of the business document.
- View the workflow log records, verify that the loop call interval and upper limit parameters meet the preset configuration.
