# Business Process Guidance for State-owned Capital Investment Companies: Tool Calling and Plugins

## What this category of data looks like
Data is primarily sourced from business ledgers submitted via the state-owned assets supervision platform, internal project approval archives, and offline process trace records. Update frequency syncs with regular monthly business archiving and major project completion milestones. Documents use structured form format, including project unique identifier, applicant entity, approval sequence, processing time limit, investor approval fields, and more. Most fields are string or numeric types. The approval sequence field must match state-owned assets business standard codes. Processing duration units use hours and days uniformly. This page is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on the tool calling and plugins workflow
The large number of structured fields and requirement to match state-owned assets business standard codes means tool calling requires strict validation of incoming parameter formats and coding rules to prevent call failures from field mismatches. Business data updates are not real-time, so plugin calls must limit cache validity periods to avoid using expired approval node data. Business process steps follow a fixed order, so tool calls must trigger in the approval sequence. Cross-step calls are not allowed, as they will cause process guidance errors. For fields related to investor approvals, tools must connect to external state-owned assets supervision interfaces, requiring additional permission validation logic to prevent unauthorized access.

## Three common errors
- Returns a parameter format error prompt when calling the OpenApi chat interface, with status code 400. The `functionCall` parameter format is not configured according to state-owned assets business field standards, resulting in tool call parameters that do not meet requirements.
- Returns full results directly for short business queries, without triggering streaming output. The automatic judgment logic of `toolChoice` is not configured correctly, resulting in the streaming interaction mode not being enabled.
- Custom model interfaces cannot be called in content extraction nodes. The custom model adaptation option is not enabled in plugin configuration, causing the node to only support built-in model calls.

## How to confirm configuration is complete
- Initiate a test request containing state-owned assets business fields, check whether the parameters returned by tool calls comply with the field requirements of internal documents.
- View plugin call logs to confirm that tool calls are triggered in accordance with the business process sequence, with no cross-step calls occurring.
- Verify the cache validity period configuration, check whether business data is automatically refreshed after the set duration has elapsed.
- Test the scenario where `toolChoice` is set to `required`, confirm whether the tool forces plugin calls.
