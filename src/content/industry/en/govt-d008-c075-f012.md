# Business Process Guidance for State-owned Capital Investment Companies: Deployment and Upgrade

## What this type of data consists of
Business process guidance data for state-owned capital investment companies primarily comes from internal state-owned assets supervision systems, business work order platforms, and approval node ledgers.
Update frequencies fall into two categories: real-time (for work order submission and approval status changes) and scheduled (for monthly state-owned assets reports and quarterly item list updates).
Each single business handling item forms the core data unit. Fields include item code, handling entity, approval hierarchy, submission material list, and handling time limit.
Field units include pieces, working days, copies, and items, among others. Fields vary across different business types, so field mapping adaptation is required for specific items.

## Constraints during deployment and upgrade
Business handling data for state-owned capital investment companies has multiple sources and inconsistent formats.
During deployment, configure connection parameters for multiple data sources. Do not use hard-coded field mapping rules. Hard-coded rules will prevent business data from importing correctly into the knowledge base.
Real-time updated work orders require incremental synchronization tasks during deployment. During upgrades, keep these tasks running without interruption. Interruptions will cause work order data loss and disrupt business handling continuity.
Scheduled state-owned assets reports require scheduled scheduling tasks. During upgrades, verify task trigger logic and execution results. This prevents abnormal updates to report data.
The multi-field document structure requires pre-configured field mapping relationships during deployment. During upgrades, maintain compatibility with older version field formats. This avoids knowledge base import failures or data disorder.

Correct authentication source and dedicated database name are required. |
| `PG_URL` | `postgresql://state-owned assets supervision account:password@intranet host:5432/state-owned assets business database?sslmode=require` | Structured state-owned assets supervision data (such as item lists and approval nodes) is mostly stored in PostgreSQL. Enable SSL to secure data transmission. |
| `REDIS_URL` | `redis://:cache password@intranet host:6379/1` | Used to cache business handling session IDs and temporary approval statuses. Use an independent database to avoid interference with other business data. |
| `DB_MAX_LINK` | `20–30 connections` | Business handling concurrency for state-owned capital investment companies is moderate. Excessive connections will consume database resources, while insufficient connections will cause request queuing. |
| `STORAGE_S3_ENDPOINT` | `http://intranet object storage address:9000` | Business handling material files must be stored in intranet object storage to keep data within the internal network. |
| `FE_DOMAIN` | `https://state-owned assets business handling platform.[enterprise intranet domain]` | Configure a dedicated domain for frontend access, ensuring internal users access the service through the specified address. |

## Three common configuration errors
- Phenomenon: After upgrading from FastGPT v4.9 to v4.12.2, existing business session data is lost. Cause: The database mount volumes corresponding to `REDIS_URL` and `PG_URL` were not retained during the upgrade, and the data directory was overwritten directly. This cleared session records and business data.
- Phenomenon: When initiating a business process guidance conversation, the previous AI reply's conversation record ID cannot be retrieved. Cause: The database index for `REDIS_URL` was not configured correctly, so session data cannot be read normally.
- Phenomenon: File upload fails during bulk import of business materials, with a connection timeout to object storage prompted. Cause: The intranet access permission for `STORAGE_S3_ENDPOINT` was not configured correctly, so the service cannot connect to the internal object storage system.

## How to confirm correct configuration
- Run `docker compose up -d` to start the FastGPT v4.17.0 service, then check container logs to confirm no error messages appear for `MONGODB_URI` and `PG_URL` connection statuses.
- Submit a simulated business handling request, verify that a conversation record ID is generated normally and stored in the Redis cache.
- Access the frontend page through the configured `FE_DOMAIN`, confirm the page loads normally and the business process guidance module displays correctly.
- Upload a test business material file, confirm the file is stored normally in the specified object storage path and can be read and previewed normally.
