# Business Process Guidance for State-owned Capital Operation Companies: HTTP Interfaces and External Systems

## What the data for this category looks like
State-owned capital operation company business data mainly comes from state-owned assets supervision and reporting systems, internal property right transaction ledgers, and budget execution management platforms. There are two data update rhythms. Data for property right transfer and equity change categories is updated in real time as business nodes change. Data for budget declaration and performance appraisal categories is updated on a natural monthly basis.
A single business document includes fields such as unique business identifier, handling subject name, required material list, statutory handling time limit, current process node, and approver information. Standard government units such as working days, pieces, and ten thousand yuan are uniformly used for field units.

## What constraints these characteristics impose on HTTP interfaces and external systems
Business data comes from multiple internal government systems. HTTP interfaces must adapt to the authentication rules of different systems to avoid cross-system call conflicts.
Differences in update rhythms across business types require interfaces to support flexible configuration of pull timing. Real-time business requires enabling short-cycle polling. Scheduled business can be configured to synchronize on a natural cycle.
Business documents include multi-dimensional government affairs fields. Parameter validation for interface requests and returns must strictly match field formats to prevent process guidance exceptions caused by missing fields.
State-owned capital operation business involves sensitive state-owned assets data. Interface transmission must rely on dedicated internal network links. Public network exposure is prohibited.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0. Specific parameters are as follows:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Dedicated internal network JWT token, valid for 7 days | Complies with state-owned assets system authentication specifications, prevents public network leakage of sensitive data |
| `variables` | Bind two core variables: unique business identifier and handling subject name | Matches core fields of business documents to enable accurate process node matching |
| `responseData` | Only return three fields: business ID, current process node, and statutory handling time limit | Reduces transmitted data to lower internal network bandwidth usage and parsing costs |
| Interface timeout period | 600 seconds | Adapts to the long approval cycle of state-owned assets business to avoid premature interruption of valid requests |
| Automatic retry count | 2 times | Addresses occasional fluctuations in internal network environments to reduce the probability of interface call failures |
| Polling interval | 10-30 minutes (scheduled business), 1 minute (real-time business) | Matches update rhythms of different business types, balances data timeliness and resource consumption |

## Three Common Misconfigurations
- Scenario: Interface returns 304 status code, and no updated data appears on the process guidance page. Cause: Interface caching policy is not configured correctly. Caching in the internal network environment is not invalidated in a timely manner, resulting in return of old data.
- Scenario: Interface call prompts Access denied error. Cause: Dedicated internal network authentication token is not used, or token validity period is configured too short, which does not comply with state-owned assets system authentication rules.
- Scenario: FastGPT server deployed on the internal network cannot access external APIs, and model responses cannot be obtained. Cause: Dedicated internal network proxy link is not configured, or proxy rules do not cover the target API address, resulting in failure to communicate across internal network services.

## How to Confirm the Configuration Is Complete
- Initiate an interface call, and check whether the returned `responseData` includes preset core business fields, and whether the field format matches the internal document definition.
- Simulate an authentication request in the internal network environment, verify that the `Authorization` token can pass system authentication, and no Access denied error occurs.
- Adjust the polling interval parameter, and observe whether the business data update frequency matches the preset business type, with no abnormal timeouts or repeated calls.
- Trigger an interface exception scenario, and verify that the automatic retry mechanism takes effect, and valid data can be obtained normally after retries.
