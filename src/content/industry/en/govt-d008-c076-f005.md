# Workflow Guidance for State-owned Capital Operation Companies: Tool Calling and Plugins

## What the Data for This Category Entails
Data comes primarily from the state-owned assets supervision comprehensive platform, internal property right transaction management system, and financial accounting database. Two update rhythms apply: Property right transaction and personnel appointment/removal data sync in real time. Financial budget and operational report data update monthly or quarterly. Document structure follows standardized state-owned assets business forms. Forms include processing link code, material list, approval level, and time limit for completion fields. Most field units are working days, ten thousand yuan, or person-times. Some associated fields must match unified state-owned assets supervision coding rules.

## Constraints for Tool Calling and Plugins
Unified state-owned assets supervision coding rules require tool calling to first verify incoming enterprise codes and transaction target codes for format compliance. Non-compliant codes trigger data matching failures. Differences in multi-source data update rhythms require differentiated caching strategies for plugin configurations. Real-time business data should not use long caching durations. Periodic report data can use longer caching periods. Most business fields use state-owned assets-specific terminology. Plugin parameter mapping must match dedicated fields. General business fields cannot be used directly. Additional terminology conversion is required. Cross-system data aggregation requires tool calling to support parallel requests across multiple data sources and format alignment.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Enabled forcibly | Ensure tool calls return structured workflow step parameters to meet business process guidance requirements |
| Caching Duration | 300 seconds for real-time business data, 86400 seconds for periodic report data | Match different update rhythms of state-owned assets data, reduce proportion of invalid requests |
| Parameter Validation Switch | Enabled | Validate the format of incoming state-owned assets enterprise codes and transaction target codes, filter invalid requests |
| Multi-source Data Source Call Limit | Top 3 data sources | Adapt to the conventional data scale of cross-system collaboration for state-owned assets business, avoid request overload |
| Timeout Threshold | 60 seconds | Adapt to the conventional response duration of cross-state-owned assets supervision systems, avoid blocking of process guidance |
| Terminology Mapping Configuration | Bind state-owned assets business field mapping table | Convert general parameters to state-owned assets-specific fields, ensure accuracy of data matching |

## Three Common Misconfigurations
- Phenomenon: No response after clicking the plugin. Background logs show parameter format error. Cause: Parameter validation switch not enabled. Incoming state-owned assets enterprise code does not meet unified coding rules. The plugin cannot parse the request.
- Phenomenon: Tool call returns empty result. Logs show timeout. Cause: Timeout threshold set too short. Data requests to cross-state-owned assets supervision systems do not complete response within the threshold.
- Phenomenon: Background logs show continuous call requests generated at midnight. Balance consumption is abnormal. Cause: Differentiated caching strategy not configured. Tool calls for real-time data have no caching set. Repeated invalid requests are initiated.

## How to Verify Proper Configuration
- Submit a simulated state-owned assets business processing request. Check whether parameters returned by tool calls conform to preset state-owned assets business field formats.
- View plugin caching logs. Confirm that caching durations for real-time data and periodic data match preset rules.
- Trigger cross-system data aggregation requests. Check whether returned results include expected multi-source business data fields.
- View system intercept logs. Confirm that requests with non-compliant formats are blocked by the parameter validation switch.

These values are common starting points. They should be evaluated against the deployer’s own operational samples.
