# Business Process Guidance for State-owned Capital Operation Companies: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data related to business handling for state-owned capital operation companies comes from internal business process manuals, compliance guidelines issued by state-owned assets supervision departments, property right transaction operation specifications, internal approval node descriptions, and employee operation guides.
Core process documents are adjusted annually as needed. Regulatory policy documents are updated immediately per regulatory requirements.
Most document structures include process steps, required materials, approval authority, processing time limits, and responsible departments. Fields include process name, node number, processing subject, required material list, processing time limit (unit: working days), and consultation channel. The documents contain both structured operation guidance and unstructured policy interpretation.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
Business process handling has high compliance requirements. Retrieval results must accurately match the operational requirements of specific nodes, with no deviations allowed.
Regulatory policy data updates have no fixed cycle, so incremental synchronization and temporary update mechanisms must be supported.
Documents include both structured node information and unstructured policy interpretation, so both semantic recall and keyword matching capabilities are needed.
Handling subjects and time limit requirements vary significantly across different business lines. Retrieval must support targeted recall of relevant documents by business type.

## Configuration Settings
These configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the accuracy requirements for business process matching, filters irrelevant policy interpretation content, and ensures returned results are highly relevant to the query |
| `limit` | Top 10 entries | Covers all nodes of a complete business process, while controlling context length to avoid excessive response latency |
| `searchMode` | hybrid | Balances structured node fields and unstructured policy interpretation, adapting to mixed-format document data |
| `usingReRank` | Enabled | Re-ranks recall results by business relevance, ensuring core process steps are displayed first to improve user search efficiency |
| `datasetSearchUsingExtensionQuery` | Disabled | Business process guidance must strictly match original document content, avoiding unnecessary additional supplementary information generated by the model |
| `collectionIds` | Bound by business category | Targetedly recalls knowledge base documents for the corresponding business line, avoiding interference from irrelevant cross-business content in retrieval results |

## Three Common Mistakes
- Phenomenon: Knowledge base retrieval response times out, and the interface displays a 504 status code. Cause: A reasonable `limit` parameter is not configured for the volume of business documents, and too many entries are recalled, leading to excessive processing time.
- Phenomenon: Retrieval results only return 1 entry, which cannot cover a complete business process. Cause: The `similarity` threshold is incorrectly set too high, filtering out relevant step node documents, and the hybrid search mode of `searchMode` is not enabled.
- Phenomenon: Retrieval results include additional supplementary content generated by the model, which does not comply with business process handling compliance requirements. Cause: The `datasetSearchUsingExtensionQuery` parameter is enabled, causing the system to perform unnecessary expansion of retrieval results.

## How to Verify Proper Configuration
- Upload a business process document for a state-owned capital operation company, initiate a query for the corresponding node, and check whether the `similarity` score of the returned results falls within the 0.75–0.85 range.
- Initiate a query covering multiple process nodes, and check whether the number of returned results matches the setting of the `limit` parameter.
- Check that retrieval results only contain original document content, with no additional generated supplementary information, confirming that the `datasetSearchUsingExtensionQuery` parameter is disabled.
- Test queries for different business types, check that only knowledge base documents for the corresponding business category are recalled, confirming that `collectionIds` are correctly bound.

The values provided are common starting points and should be measured against the reader's own samples.
