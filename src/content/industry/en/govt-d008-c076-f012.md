# Business Process Guidance for State-owned Capital Operation Companies: Deployment and Upgrade

## What the Data for This Category Looks Like
Business process data for state-owned capital operation companies originates primarily from business ledgers on the state-owned assets supervision platform, internal approval process archives, and property right transaction registration systems. Update frequency follows daily incremental synchronization or weekly full synchronization. Each business process document includes structured fields: unique business item identifier, processing node sequence, required submission material list, responsible entity, legal processing time limit, and others. All fields use text or enumeration values, with no complex nested formats. The full dataset must comply with state-owned assets supervision storage specifications.

## What Constraints These Characteristics Impose During Deployment and Upgrade
Structured business fields must align with database index rules to ensure fast queries for enumeration values and unique identifiers, and prevent timeout exceptions after deployment. Daily incremental business data updates require scheduled synchronization tasks, with corresponding server resources reserved. The standardized structure of business documents requires presetting vector database field mapping rules during deployment to avoid format errors during embedding. The regulatory requirements for state-owned capital operation businesses mandate enabling local storage and encrypted transmission configurations during deployment, prohibiting external anonymous call permissions, and reserving storage paths for audit logs.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/gic_business?authSource=admin` | Matches the naming specification of the business database for state-owned capital operation companies, specifies the authentication source to ensure connection legitimacy |
| `DB_MAX_LINK` | `50–80 connections` | Adapts to the concurrent connection requirements of daily incremental synchronization, avoiding query timeouts caused by connection pool exhaustion |
| `FE_DOMAIN` | `https://internal-gic-portal.com` | Matches the official domain name of the internal business processing system to ensure compliance of front-end access |
| `FILE_TOKEN_KEY` | `Random 32-bit encrypted string, temporary file quota of 1000 MB` | Ensures encrypted storage of temporary files generated during business processing and prevents unauthorized access |
| `ROOT_KEY` | `Exclusive key generated according to internal permission management procedures` | Controls super administrator account permissions, avoiding security risks caused by using default keys |
| `STORAGE_S3_ENDPOINT` | `Internal network address of the internal object storage service` | Meets the local storage requirements of confidential business files, avoiding the use of external public storage services |

## Three Common Misconfigurations
- Symptom: When executing the local development startup command, a database connection timeout is displayed, and the error message contains `ECONNREFUSED` or `ETIMEDOUT`. Cause: The host address and authentication information in the `MONGODB_URI` configuration are incorrect, or the local database service is not started normally.
- Symptom: The front-end access page cannot switch to the HTTPS protocol, and the browser prompts an insecure connection. Cause: The `FE_DOMAIN` configuration is not set to the HTTPS format, and no SSL certificate is deployed in the reverse proxy service.
- Symptom: A large number of temporary logs and cache files are generated after Docker deployment, exceeding disk space limits. Cause: No automatic cleanup rule for temporary files is configured, or the system log automatic rotation policy is not enabled.

## How to Verify Successful Configuration
- Execute the database connection test command to verify that the database configured via `MONGODB_URI` can read and write business data normally.
- Access the configured `FE_DOMAIN` address to confirm that the page loads normally and uses the HTTPS protocol.
- View the access logs of the internal object storage service to confirm that the storage service configured via `STORAGE_S3_ENDPOINT` can upload and download business files normally.
- Log in to the system super administrator backend to verify that the key configured via `ROOT_KEY` can normally obtain management permissions.
