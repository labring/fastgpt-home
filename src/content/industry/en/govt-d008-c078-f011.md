# Business Process Guidance for Urban Water Services: Forms and Interactions

## What the data for this category looks like
Urban water service business process data primarily comes from internal business systems such as water service groups’ operation charging systems and application and repair platforms. Updates trigger when business process nodes advance, including application submission, audit approval, payment completion, and similar stages.
Document structure includes structured business fields and unstructured attachments. Structured fields include user name, ID number, water use address, water meter number, application type, and more. Water use address is stored in the format of house number plus street name. ID numbers follow the 18-digit standard format. Water meter numbers are 12-digit numeric strings.
Unstructured attachments mostly include construction drawings, property certificates, payment vouchers, and similar materials. Supported formats include PDF, JPG, CAD, and others.

## What constraints these characteristics impose on the "forms and interactions" link
Structured fields for urban water services are numerous and have strict format requirements. Form interactions must support format validation for fixed fields to prevent invalid data submissions.
Unstructured attachments have clear type and size limits. Interaction links must restrict uploaded file formats, per-file size, and total file size.
Business data has high real-time update requirements. After form submission, business system data must be updated synchronously. Interactions must support real-time data validation and synchronous feedback after submission.
Multi-field form structures often lead to user fatigue during filling. Displaying fields in groups reduces user cognitive load.

## Configuration Guidelines
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `formInput` field grouping | Split by business process into 3 groups: basic information, application content, attachment upload | Adapts to the multi-field filling logic of water services, reduces user entry barriers |
| Form field validation rules | Preset regular expressions for 18-digit ID numbers and 12-digit water meter numbers | Matches standard data format requirements for water services, reduces invalid submissions |
| Single attachment upload limit | 10 files, maximum 50 MB per file | Adapts to common attachment types and size limits for water service application and repair businesses |
| Interaction timeout threshold | 300 seconds | Prevents session expiration due to user mid-process pauses, ensures complete filling workflow |
| `userSelect` business options | Preset 4 categories: water supply application, drainage permit, water fee inquiry, repair request | Reduces manual input error rates, improves interaction efficiency |
| Real-time validation trigger timing | Triggered after each field is completed | Provides timely feedback on format errors, prevents users from discovering issues only after filling all fields |

## Three Common Mistakes
- Phenomenon: Submitting a water service form returns a "failed to create post" error, and backend logs show data write failure. Cause: Synchronization interface with the water service group's business system is not configured. Structured data submitted via the form cannot be synchronized to the business database.
- Phenomenon: The bot cannot proactively push business process progress updates to users, and can only respond when users initiate questions. Cause: Active push configuration for `formInput` is not enabled. Only passive question-and-answer interaction logic is configured, which cannot trigger progress reminder messages.
- Phenomenon: Voice input of water service terminology (such as "water meter application", "drainage permit") cannot be correctly recognized, and cannot match the corresponding business options. Cause: A dedicated water service terminology knowledge base is not loaded. The text after speech transcription does not match the preset `userSelect` options.

## How to Confirm Configuration Is Complete
- Fill out a test dataset that meets water service format requirements, submit it, and verify if the data is synchronized to the business system in the backend.
- Set up a test account to receive push notifications, trigger a business process node update, and check if the corresponding progress reminder is received.
- Speak water service terminology, and confirm if the transcribed text matches the preset `userSelect` options.
- Upload a test file sized 50 MB, confirm that the upload progress works normally and no error messages appear.
