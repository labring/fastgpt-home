# Business Process Guidance for Urban Gas Utilities: Workflow Orchestration

## What the data for this category looks like
Data for urban gas business process guidance comes from local urban gas operation enterprise business management systems and handling specifications archived in offline business halls. Update rhythm follows immediate synchronization after process adjustments, or daily batch updates. Each data entry corresponds to a specific service, such as account opening and installation, ownership transfer, gas shutoff and restoration, and others. Fields include item name, handling conditions, required materials (including format requirements), handling steps, legal time limit, consultation contact information. Common units include workdays, copies, square meters, and similar.

## What constraints these characteristics impose on the workflow orchestration link
The sub-item data structure for urban gas business handling requires workflows to pass the specific business type consulted by the user via `variables` to accurately match the corresponding handling specification documents. The linear handling process requires workflow nodes to be arranged in the order of consultation guidance, material verification, and progress query. Node order cannot be adjusted arbitrarily. Clear requirements for material format and quantity require embedding format verification nodes in the workflow to filter submitted content that does not meet requirements. The high data update frequency requires configuring a timed knowledge base synchronization node in the workflow to ensure handling specification timeliness meets business needs.

## Three Common Misconfigurations
- Phenomenon: Returns "missing parameter" error when invoking the workflow, logs show the `variables` field is empty. Cause: Global variable binding is not configured in the workflow invocation node, and the business type entered by the user is not passed to the workflow.
- Phenomenon: Workflow node execution order is chaotic, with material verification occurring before consultation guidance. Cause: Serial trigger rules are not set according to `nodeId`, and nodes are mistakenly set to parallel execution.
- Phenomenon: Uploaded business materials cannot be processed by the backend, returning a format not supported prompt. Cause: Corresponding format and size limits are not configured in the file upload node, and conventional requirements for gas business materials are not matched.

## How to Confirm Proper Configuration
- Trigger the workflow and pass preset business type parameters, verify that corresponding handling specification document content is matched.
- Trigger workflow nodes sequentially according to node order, confirm that execution order aligns with the business handling process.
- Upload test files that meet preset format and size requirements, confirm that the verification node passes normally.
- View log collection results, confirm that node triggers, parameter passing, and return results are all fully recorded.
