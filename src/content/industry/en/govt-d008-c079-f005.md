# Business Handling Process Guidance for Urban Gas Utilities: Tool Calling and Plugins

## What the Data for This Category Looks Like
The data for urban gas business handling process guidance primarily originates from the gas operation system under the local urban investment group and the gas business module of the government service platform. Full synchronization of all business node data is completed every day at midnight. Each data entry is in structured JSON format, containing fields such as the unique identifier of the handling item, item name, stepped process steps, required material list, legal handling time limit, and current handling node status. The time limit unit is working days, the handling volume statistics unit is pieces, the outlet address field is accurate to the street house number, and there are no redundant nested levels.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
The exclusive local data source requires that a dedicated access key for the corresponding gas operation system must be configured when calling the tool, and general government service interfaces cannot be reused. The daily synchronization update rhythm requires that the cache validity period for tool calls be set to no more than 24 hours to avoid returning expired handling node data. The fixed fields of structured JSON require that the parameter parsing logic of tool calls strictly match the preset field names. The `functionCall` must be used to ensure that the return format meets the requirements, and mapping rules cannot be adjusted arbitrarily. The handling time limit is in working days, and the plugin must automatically convert numbers into expressions that conform to user cognition, and cannot directly return the original numbers.

## Three Common Mistakes
- The symptom is a MongoServerError pop-up when confirming the plugin, prompting that the $ symbol prefix is invalid. The cause is that the gas business data contains field names with $ symbols, and when connecting to the mongo:4.4.29 version database, the field names are not escaped, triggering the database syntax validation rules.
- The symptom is that when calling the MCP tool to query enterprise patent information, no records are returned, but the tool can return results normally during the test phase. The cause is that the enterprise unified social credit code parameter is not correctly passed when calling the tool, only the enterprise name is passed, resulting in failure to match the corresponding data.
- The symptom is that the upload file failed when using the Markdown to file plugin. The cause is that the step text of the gas business handling process contains a large number of line breaks and special symbols, and the text is not cleaned up first, causing the plugin to fail to generate a valid Markdown file.
