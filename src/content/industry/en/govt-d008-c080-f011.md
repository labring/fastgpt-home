# Business Process Guidance for Urban Investment Platforms: Forms and Interactions

## What the data for this category looks like
Business process data for urban investment platforms comes primarily from internal project management systems, the integrated government service platform, and offline submitted application materials. Data updates follow the progress of individual project processing workflows. Status is updated once a project is completed. Routine data is synchronized in batches once per week. Documents use a structured table format, with fields including application ID, project type, processing stage, required material name, material quantity, processing time limit (working days), and current status. All fields have clear business attributes and units. For example, the unit for material quantity is "copies", and the unit for processing time limit is "working days".

## What constraints these characteristics impose on the forms and interactions link
Because the data includes multiple fixed processing stages and structured fields, forms must be split and displayed by stage. This avoids overwhelming users with too many fields loaded at once. Fields have clear units and type requirements. Forms must include built-in format validation to reduce invalid input. Data comes from multiple integrated systems, so forms must support automatic backfilling of existing information. This lowers the cost of repeated data entry. Business workflows are relatively fixed, so interactive components must bind to the transfer logic of the corresponding stage. This ensures normal workflow progression after submission.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `formInput` | Split field groups by processing stage, only display fields required for the current node per group | Urban investment business processing workflows have multiple fixed stages. Splitting reduces user input complexity |
| `formInput` | Set numeric fields such as material quantity and processing time limit to only allow positive integer input | Business data field types are clearly defined, which prevents invalid input |
| `userSelect` | Predefine 10 to 15 high-frequency business options for urban investment platforms, such as project establishment application and facility operation and maintenance report | Urban investment business types are relatively fixed. Predefined options reduce input errors |
| `formInput` | Enable automatic backfilling, connect to the internal project management system API | Urban investment business scenarios involve repeated entry of application information. Automatic backfilling improves efficiency |
| `formInput` | Set submission timeout to 30 seconds | Internal system interface responses typically take 10 to 20 seconds. 30 seconds covers normal network fluctuations |

## Three common mistakes
- When calling an API to access a published workflow, the front end does not display the form or user selection component, and the interactive fields returned by the API are empty. The cause is that the trigger conditions for `formInput` or `userSelect` are not configured in the workflow, causing the process to skip the interactive link directly.
- A "field format error" prompt pops up after form submission. The cause is that input format restrictions are not set for numeric fields, and users have entered non-numeric characters or negative numbers.
- Automatically backfilled information such as application ID and project name does not match the actual data in the internal project management system. The cause is that the update frequency of the connected internal system interface does not match the synchronization frequency configured for the form. For example, the interface updates once per week but the form is set to real-time synchronization.

## How to confirm the configuration is complete
- Enter the workflow editing page of FastGPT v4.17.0, click the `formInput` or `userSelect` component, and confirm that the field groups match the current processing stage.
- Call the test API to simulate form submission, and check whether the returned parameters include all configured fields.
- Enter non-numeric characters into a numeric field, and check whether a format error prompt pops up.
- View the system log to confirm that interface data synchronization works normally after form submission.
