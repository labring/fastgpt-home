# Business Process Guidance for Basic Chemical Industry: Model Access and Configuration

## What This Category of Data Looks Like
Data related to basic chemical industry business processing comes primarily from manufacturing execution systems, safety and environmental protection logs, equipment maintenance records, and administrative licensing documents. Data updates follow three schedules: real-time production data syncs hourly, log data updates daily, and administrative licensing documents update on demand. Document structure includes fields such as work order number, unique equipment identifier, process parameters, operation timestamp, and approval node status. Most units use industrial standard units including MPa, ℃, m³/h, and some documents contain long-text approval opinions and process descriptions. FastGPT v4.17.0 can adapt to the access format of this type of data.

## Constraints Imposed on Model Access and Configuration
Basic chemical industry business data has strict real-time requirements, so model call latency must be controlled to avoid impacting the immediacy of process guidance. Long-text approval opinions and process descriptions increase context length, so reasonable limits must be set for context and output token quotas. The field characteristics of industrial standard units and unique equipment identifiers require the model to have professional term recognition capabilities to avoid parameter parsing errors. Administrative licensing documents that update on demand require configuration of a dynamic data synchronization mechanism to ensure that the data source accessed by the model matches the latest business status.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Approval documents and process descriptions in the basic chemical industry are mostly long text, so sufficient business context must be covered |
| `maxTokens` | `2000–3000 token` | Business process guidance requires clear step-by-step instructions, to avoid excessive truncation that affects readability |
| `quoteMaxToken` | `3000–4000 token` | Sufficient equipment parameters and work order data must be referenced as a basis for process guidance |
| `temperature` | `0.1–0.3` | Business processes must remain rigorous, to avoid generating guidance steps that are vague or deviate from industrial standards |
| `AIPROXY_API_ENDPOINT` | Fill in the proxy address deployed on the enterprise intranet | Most basic chemical industry data is sensitive intranet data, so an intranet proxy must be used to ensure data security |
| `AIPROXY_API_TOKEN` | Fill in the exclusive business key assigned | Distinguish call permissions for different business scenarios, to avoid unauthorized access to sensitive business data |

## Three Common Configuration Errors
- An error "incorrect API Key used" is returned during calls. This occurs because the global universal key and exclusive business key are confused, and the exclusive key assigned for process guidance is not used.
- The first token return time for online models and total runtime for offline models cannot be used to unify latency metrics. This occurs because the timing logic for model calls is not uniformly configured, and long-text data from the basic chemical industry increases the loading duration of offline models.
- The generated process guidance contains incorrect process units. This occurs because the `temperature` value is set too high, causing the model to generate parameter descriptions that do not comply with industrial standards.

## How to Verify Successful Configuration
- Initiate a single test call, check whether the returned process guidance content matches the fields and units in the local business documents, and adjust related configuration items until they match.
- View the model call logs to confirm that the actual usage quotas of `maxContext` and `maxTokens` do not exceed the configured thresholds, and adjust the value range based on the length of business data.
- Verify that process guidance is triggered for different types of business work orders, and confirm that the steps returned by the model comply with the approval node requirements of the corresponding process.
- Check the unified configuration of model timing parameters, and confirm that the latency statistics logic for online and offline models remains consistent.
