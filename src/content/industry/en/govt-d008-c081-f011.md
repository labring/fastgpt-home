# Business Process Guidance for Basic Chemical Industry: Forms and Interactions
This document is written based on FastGPT v4.17.0.

## What This Category's Data Looks Like
Business process data for the basic chemical industry mainly comes from enterprise production logs, safety and environmental protection filing forms, material purchase declaration forms, and equipment inspection records.
Data update cycles vary by type: production operation parameters are synchronized in real time, material filing information is updated every quarter, and annual compliance reports are updated according to the calendar year.
The document structure consistently includes these fields: material code, batch number, designed production capacity, safety threshold, and compliance level.
Common units follow industrial measurement standards such as ton, cubic meter, pascal, and degree Celsius.

## Constraints on Forms and Interactions
The multi-type update cycles of basic chemical industry business data require form interactions to distinguish between real-time pull and static cache data sources. This prevents expired compliance threshold or production capacity data from being returned.
Multi-disciplinary measurement fields require forms to preset unit dropdown options, and automatically associate valid input ranges for corresponding fields. This reduces manual input errors.
The material code, as a unique identifier field, must trigger real-time verification when a user inputs a value. It must match valid codes in the enterprise internal material library to avoid invalid submissions.
The compliance level field must link to prior approval nodes. It automatically verifies whether the corresponding approval status meets requirements before the form is submitted.

## Three Common Configuration Errors
- Phenomenon: Business process guidance content generated by calling an LLM has no connection to submitted basic chemical industry form data. Cause: Business data such as material code and safety threshold collected by the form is not injected into the model context, resulting in generated content that deviates from the business scenario.
- Phenomenon: A 400 status code is returned when a query containing professional numerical values is entered. Cause: The form does not bind unit verification rules for the corresponding field, and the incoming numerical value does not match the preset measurement standard, triggering parameter verification failure.
- Phenomenon: Cross-system compliance verification is not triggered after the form is submitted. Cause: Dependency linkage logic for `userSelect` is not configured, so the compliance level field is not included in the submission verification scope.

## How to Verify Configuration Completion
- Manually enter a test data set that complies with basic chemical industry business specifications, and check whether the form automatically verifies unit and value range requirements.
- Submit the test form, and confirm whether the system pulls the latest production or filing data for the corresponding material.
- Trigger the LLM to generate guidance content, and check whether the output is associated with the submitted business fields.
- Simulate abnormal input, such as a numerical value with a mismatched unit, and confirm whether the system returns clear verification prompts.
