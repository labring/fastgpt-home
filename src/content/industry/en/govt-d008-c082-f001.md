# Business Process Guidance for Basic Telecommunications Operations: HTTP Interfaces and External Systems

## What this category of data looks like
Data for business process guidance in basic telecommunications operations comes from carrier internal business support systems (BSS) and operations support systems (OSS). It includes fields such as user business processing work order ID, processing status, step nodes, package remaining quota, required application materials, and more.
Data update schedule: Work order progress updates in real time, package remaining quota synchronizes every 15 minutes, and processing material documentation updates on a fixed daily basis.
Document structure has a maximum nested level of 3 layers. Fields include string-type business code, numeric status code, quota value measured in GB, and ISO-formatted processing timestamp.

## What constraints these characteristics impose on HTTP interfaces and external systems
These data characteristics create four core requirements:
1. Data originates from internal carrier business systems. Interfaces must use `Authorization` authentication, and keys must be rotated regularly per carrier requirements.
2. Real-time work order progress data requires reasonable interface timeout settings, to prevent data fetch failures caused by network fluctuations or delayed interface responses.
3. The limited nested document structure requires correct extraction of business fields from `responseData`, and binding of pagination parameters via `variables` to ensure correct pagination queries.
4. Telecommunications business data includes sensitive fields. Non-essential fields must be filtered to mitigate data leakage risks.

## How to set configurations
These settings apply to FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Interface Authentication | `Bearer {carrier API key}` | Meets internal carrier interface authentication requirements |
| Request Timeout | 30 seconds | Telecommunications business interfaces typically have high response delays, avoid early request termination |
| Response Data Parsing | Extract `responseData` field | Carrier interfaces usually encapsulate business data under this field |
| Request Variable Binding | Pass pagination parameters via `variables` | Dynamically bind business processing parameters such as pageNum, pageSize |
| Retry Count | 2 times | Address interface call failures caused by network fluctuations |
| Sensitive Field Filtering | Filter user phone number and ID number fields | Complies with telecommunications industry data security requirements |

## Three common configuration errors
- Passing different pageNum parameters returns identical business processing data. Cause: Pagination parameters are not correctly bound in `variables`, or pageNum parameters are not passed to the external interface, resulting in the interface always returning first-page data.
- After uploading javadoc-generated HTML interface documents, the knowledge base has no parsed content. Cause: Response data parsing rules are not configured, and the `responseData` field is not specified for extraction, so structured data in the HTML is not recognized.
- After enabling file upload in the frontend, the conversation interface cannot receive uploaded file streams. Cause: File upload parameters for the external interface are not configured, and variable mapping for file parameters is not bound.

## How to verify correct configuration
- Call the test interface, pass different pageNum parameters, and check if the work order list in returned data changes with the parameters.
- Upload javadoc-formatted HTML interface documents, and confirm that interface fields and descriptions in the documents are retrievable in the knowledge base.
- After configuring `Authorization` authentication, call the interface and receive a 200 status code, with no authentication-related errors.
- Test the file upload interface, upload a test file, and confirm the conversation interface can normally receive and process the file content.

The values provided are common starting points and should be measured against the reader's own samples.
