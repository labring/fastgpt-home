# Business Handling Process Guidance for Basic Telecommunications Operations: Tool Calling and Plugins

## What this category of data looks like
Business handling data for basic telecommunications operations comes from in-house business support systems, offline outlet handling ledgers, and online business hall interaction logs. Two update rhythm categories apply: real-time updates for handling progress and material verification status, and daily synchronization of business rule and tariff standard change information. The structure of a single data document includes business handling type, handling node sequence, required material list, handling time limit requirements, and current handling status fields. Field units mostly use general telecommunications service expressions such as working days, copies, and yuan/month.

## What constraints these characteristics bring to the tool calling and plugins workflow
The business handling process for basic telecommunications operations has a strictly fixed node sequence. Tool calling must strictly follow the order of pre-verification, material submission, and progress query. Execution order cannot be adjusted flexibly. Real-time updated handling progress data requires plugin calls to adapt to the interface response characteristics of operator systems. Timeout thresholds must match the conventional response duration of telecommunications business systems to avoid interrupting ongoing handling guidance. Daily updated business rules require plugins to be configured with a scheduled synchronization mechanism. This ensures that the latest tariff and handling time limit requirements are used when calling. Structured multi-field data requires clear mapping rules. This prevents tools from extracting information from non-target handling links.

## How to configure the settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `toolChoice` | `auto` mode, trigger `functionCall` as needed | Fixed nodes exist in basic telecommunications business processes. Automatic mode matches node-triggered tool calling to adapt to strict process characteristics |
| Plugin call timeout setting | 60 seconds | Conventional response duration of operator business system interfaces ranges from 30 to 60 seconds. Timeouts will cause handling guidance interruptions |
| `functionCall` field mapping rules | Strictly match the three core fields of business handling type, node, and progress | Structured business data requires precise mapping to avoid extracting redundant or incorrect information from non-target handling links |
| Plugin scheduled synchronization frequency | Every 24 hours | Business rules are updated once daily. Synchronization frequency matches the update rhythm to ensure the latest configuration is used when calling |
| Tool calling trigger condition | Triggered by handling node | Fixed execution order exists in the business process. Node triggering ensures tool calling timing matches actual process nodes |

## Three common misconfigurations
- Calling the business query plugin returns a 401 status code. The interface authentication key for the operator system is not configured correctly, or the key permissions do not cover the target business interface.
- Tool calling does not trigger queries for the corresponding business node. `toolChoice` is not set to a trigger mode adapted to the business process, leading to a mismatch between tool calling timing and actual handling nodes.
- The material list returned by the plugin does not match actual handling requirements. The field extraction rules for `functionCall` are not configured correctly, leading to redundant or missing business fields being extracted.

## How to confirm the configuration is correct
- Submit a business query request for a known handling status, and check whether tool calling is triggered at the corresponding handling node.
- Review plugin call logs to confirm there are no abnormal errors in the returned authentication status codes.
- Compare the business data returned by the plugin with the actual business rules of the operator system to confirm accurate field mapping.
- Wait 24 hours, then submit a business query, and check whether the latest business rule data is used.
