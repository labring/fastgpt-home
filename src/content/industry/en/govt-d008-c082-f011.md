# Business Process Guidance for Basic Telecommunications Operations: Forms and Interactions

## What this category's data looks like
Business data for basic telecommunications operations is sourced from internal business handling systems and both historical and real-time business data from online service portals. Data updates follow a near-real-time schedule, with synchronization occurring every hour. Documentation is organized per single business handling item, including fields such as user identity identifier, business type, handling request, and associated device number. Field types include character, date, and enumeration types, with no additional nested levels. Most field units use standard formats: ID numbers use 18-character strings, contact telephone numbers use 11-digit numeric strings, and some businesses require the associated device number field.

## What constraints do these characteristics impose on the forms and interactions link?
Basic telecommunications operations have standardized business fields with no nested levels. Form interactions must adapt to fixed enumeration business options. This prevents data format errors caused by non-standard input.
Near-real-time data synchronization requires immediate field validity checks after form submission. Examples include format checks for ID numbers and contact telephone numbers. This stops invalid data from entering backend systems.
The fixed business field structure does not need complex grouping. A single-page linear layout can be used. The system can pull default values from a user's historical business data. This reduces repeated input steps.
Some businesses require uploading device-related attachments. Form components must support file upload configuration. This meets the need for submitting device photos in scenarios like broadband repair and device transfer.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `userSelect` option configuration | Bind to the operator business handling enumeration interface | Basic telecommunications business types are fixed enumerations with no frequent dynamic changes |
| `formInput` format verification | Configure ID number and contact telephone number regular expression verification rules | Basic telecommunications businesses require verification of user identity and contact information validity |
| Default value filling rule | Associate with user historical business data fields | Reduce repeated input of standardized business information by users |
| File upload component | Open upload permissions for ID card front and back sides and device photos | Adapt to business scenarios such as broadband repair and device transfer |
| Submission timeout threshold | `30 seconds` | Adapt to the conventional interface response duration of operator business systems under FastGPT v4.17.0 |
| Submission trigger method | Trigger via click confirmation button | Aligns with conventional operational habits for business handling, to avoid accidental submission |

## Three common configuration mistakes
- Phenomenon: When a workflow is called through the API release channel, no user interaction prompt appears during the form input stage. Cause: The external interaction trigger rule for the `formInput` component is not configured. The rule only takes effect during internal workflow circulation. The interaction node is not exposed to external calling channels.
- Phenomenon: The form cannot upload device photos or ID files required for business. Cause: File upload permission configuration is not enabled. The default form component only supports text input and does not adapt to the attachment submission requirements of basic telecommunications businesses.
- Phenomenon: When switching the knowledge base based on the business type entered by the user, this can only be achieved through a judgment node. Cause: The `userSelect` component is not used to bind business enumeration options. Knowledge base matching is triggered directly through free text input, requiring additional screening of the corresponding business knowledge base through a judgment node.

## How to confirm the configuration is complete
- Enter the workflow editing page. Select the `userSelect` component. Verify that the option list includes core basic telecommunications business types, such as card application, package change, and broadband repair.
- Open the configuration panel of the `formInput` component. Confirm that format verification rules for ID numbers and contact telephone numbers have been added. The verification rules can be customized and adjusted according to business scenarios.
- Test the form submission process. Upload ID card photos or device photos. Confirm that the file upload function is enabled normally with no upload restriction prompts.
- Call the API interface to trigger the workflow. Confirm that the corresponding form or selection items pop up, with no blank or no interaction prompt situations.
