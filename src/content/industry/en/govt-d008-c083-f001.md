# Business Process Guidance for Infrastructure Construction: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Data for infrastructure construction business comes from four types of systems: project management systems, construction progress monitoring platforms, government approval platforms, and material ledger systems.
Data update frequency differs by type: project progress data updates daily, government approval data updates in real time, and material ledger data updates daily.
Single business data includes fields such as project code, construction node name, approval status, material code, budget amount, and completion progress. Field units include days, ten thousand yuan, cubic meters, percentage, and others. The full data volume for a single large project can reach thousands of entries.

## What Constraints These Characteristics Impose on the HTTP Interfaces and External Systems Link
Decentralized data sources require integration with multiple external systems. Independent `Authorization` permission configurations must be set up for each system.
Fixed field formats require parameter validation logic to be included in requests, to avoid interface call failures due to format mismatches.
Large data volumes require setting pagination parameters to adapt to the return limit of a single interface.
Approval data with high real-time requirements need shortened request intervals. Static material data can be updated daily, so different request frequencies must be configured separately.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer token exclusive to the business system, valid for 7 days | Adapt to the permission control requirements of government and state-owned enterprise systems, avoid cross-project permission leaks |
| `variables` | Pass business parameters such as project ID, construction node code, etc. The parameter value length must not exceed 1000 characters | Match the field length limits of infrastructure construction business data, simplify interface call logic |
| `responseData` | Only extract core fields such as approval status, progress completion rate, material inventory count, etc. | Reduce invalid data transmission, adapt to FastGPT's context processing limits |
| Timeout setting | 600 seconds | Adapt to the time-consuming cycle of large-scale infrastructure project approval processes |
| Pagination parameters | Pagination with 100 data entries returned per interface | Match the default pagination limit of interfaces for most infrastructure external systems |
| Retry mechanism | Retry 2 times when a 5xx status code appears, with a 30-second interval | Address occasional network fluctuations or service restarts in infrastructure systems |

## Three Common Misconfigurations
- Only initial conversation content is returned after calling an external interface, and results cannot be updated based on subsequent business parameters. The cause is that dynamic business parameters are not passed in `variables`, only fixed initial variables are used.
- The HTTP module returns a 401 Unauthorized error. The cause is that the `Authorization` token has expired or is not bound to the operation permissions of the corresponding project.
- Extracted business data fields are empty. The cause is that the correct field mapping path is not specified in `responseData`, and target data cannot be extracted from the interface return results.

## How to Confirm the Configuration Is Complete
- In the FastGPT v4.17.0 debugging interface, pass a real project code, check the HTTP interface request logs, and confirm that the `variables` parameters are carried correctly.
- Check the validity period of the `Authorization` token, confirm that it has not expired and the permission range matches the current business scenario.
- After calling the interface, check the return results, confirm that the fields specified in `responseData` have been correctly extracted and passed to subsequent workflow nodes.
- Simulate an interface timeout or 5xx status code scenario, confirm that the retry mechanism has triggered as configured.
