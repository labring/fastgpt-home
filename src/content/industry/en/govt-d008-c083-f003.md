# Business Process Guidance for Infrastructure Construction: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Business process data for infrastructure construction comes from approval, construction, and acceptance ledgers across the full project lifecycle. This includes project approval documents, construction permit records, site visa forms, progress weekly reports, and more. Data updates trigger at business nodes: updates happen immediately after approval completes, and progress-related data syncs weekly. Documents use a structured single-project, multi-node format. Each node includes fields such as project identifier, node number, handling requirements, required material list, and approval time limit. Field units include square meters, working days, batches, and other standard engineering units.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
The structured multi-node nature of infrastructure construction business process data requires multi-turn dialogue to bind the current project’s handling node using `chatId`. This avoids confusion across node guidance. Fields with specific units require prompts to enforce matching those units in outputs, preventing statements that do not align with engineering specifications. The high data update frequency means the dialogue process must pull the latest ledger each time it runs, and cannot rely on expired cached data. The multi-node process logic requires prompts to automatically recognize the current handling phase from historical dialogue in `messages`, and adjust the focus of guidance wording. This page’s configuration uses FastGPT v4.17.0.

## How to Configure the Settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `chatId` | Bind project unique identifier + current handling node ID | Ensure multi-turn dialogue tracks the current project’s handling progress, and avoid session confusion |
| `messages` | Retain the first 15–20 rounds of dialogue content | Cover the multi-step process history of infrastructure construction projects, while controlling context load |
| `variables` | Pass project number, current node number, material list template | Provide structured business data for prompts, ensuring guidance content matches actual project requirements |
| Maximum Context | 8000–12000 token | Adapt to the dialogue length of long-cycle projects, and avoid truncating key process information |
| Question Optimization | Enabled | Convert vague user questions into clear process node queries, and improve guidance accuracy |

## Three Common Configuration Mistakes
- Phenomenon: Users cannot distinguish between context returned by dialogue nodes and AI reply functions, leading to confusion in their usage scenarios during configuration. Cause: Context is not clearly defined for tracking session history and business nodes, and replies are only used for directly outputting guidance content. The two are not configured separately by responsibility.
- Phenomenon: Content returned after calling the knowledge base does not match the user’s business process query, and instead outputs general engineering knowledge. Cause: The prompt does not limit use to only the current project’s structured ledger data, and does not clearly filter non-target documents.
- Phenomenon: When configuring prompts in a workflow, global variables are not correctly replaced, and the prompt still displays original variable placeholders. Cause: Key-value pairs of global variables are not passed in the `variables` parameter, causing the prompt to fail variable replacement.

## How to Verify Correct Configuration
- Initiate a simulated user query, check if `chatId` carries the current project and node identifier, and confirm the session context correctly associates the target project.
- Trigger a complete process dialogue, check if the AI reply only uses the current project’s structured data, and no irrelevant general engineering content appears.
- After configuring global variables, insert variable placeholders in the prompt, run the workflow, and check if the placeholders are correctly replaced with actual business values.
- View the dialogue history record, confirm that the `messages` parameter retains necessary historical dialogue, and no key process information is truncated.
