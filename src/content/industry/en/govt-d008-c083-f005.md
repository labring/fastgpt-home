# Business Process Guidance for Infrastructure Construction: Tool Calling and Plugins

## What the Data for This Category Looks Like
Infrastructure construction business process data primarily originates from internal project management systems, housing and urban-rural development department filing platforms, and construction log ledgers. Data is updated per individual project’s approval nodes, with a daily synchronization frequency. Most data uses structured fields. Core fields include project unique identifier, approval link name, processing time limit, required material list, and current progress status. The "construction permit number" uses an 18-character format. "Budget amount" uses ten thousand yuan as the unit. "Material submission deadline" uses standard date format.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Infrastructure construction business process data uses mostly structured fields and has dispersed sources. Tool calling must precisely match fixed field names to avoid data extraction failures caused by field mismatches. Data is updated per approval nodes and on a daily frequency. Plugin cache duration should align with node update rhythms. Excessively long cache durations lead to data lag. Processes involve multi-department system integration. Plugins should support calling multiple heterogeneous interfaces simultaneously and aggregating returned results. Some fields have fixed format requirements. Input parameter formats should be validated before tool calling to ensure compliance with system receiving rules.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports multi-tool calling scenarios, automatically matches tools required for infrastructure construction processes |
| `functionCall` | `strict: true` | Enforces validation of incoming parameter formats to match fixed rules for business fields |
| Tool calling timeout | `300 seconds` | Cross-department interface interactions for infrastructure construction take relatively long, this duration covers response requirements for most scenarios |
| Plugin data source cache duration | `86400 seconds (1 day)` | Business data is updated once daily, this duration ensures data timeliness |
| Multi-tool calling sequence | Follow approval node order | Infrastructure construction processes have strict link dependencies, tools should be triggered in process sequence |
| Parameter validation switch | Enabled | Business fields have fixed format requirements, validation reduces invalid calling requests |

## Three Common Misconfigurations
- Symptom: When calling an MCP tool packaged with the SSE protocol, the interface displays "Currently only stdio processes are supported". Cause: FastGPT v4.17.0 has limited support for MCP tool transmission protocols in its current version, and does not support the SSE method.
- Symptom: After successfully calling an HTTP interface, specified fields from the interface output cannot be extracted, and the corresponding fields in the returned result are empty. Cause: Extraction rules that fully match business fields have not been configured, or the strict mode of `functionCall` has not been enabled, and parameter format validation has not been performed.
- Symptom: A timeout error occurs when calling after publishing as an API interface, with a returned status code of 504. Cause: The timeout configuration has not been adjusted based on the interaction duration of cross-department systems, and the default timeout duration cannot cover the time required for multi-system integration.

## How to Verify Proper Configuration
- Test calling a single tool. Check if the returned result includes the structured fields required for the business. Verify that field formats comply with infrastructure construction requirements.
- Simulate a multi-link process call. Confirm whether tools are triggered in the preset approval node order. Confirm that the returned result aggregates data from multiple interfaces.
- Adjust the timeout configuration. Test cross-department interface calls. Confirm that no timeout errors occur. Confirm that response duration meets business scenario requirements.
- Enable the parameter validation switch. Pass test parameters that do not comply with formats. Confirm that the tool intercepts invalid requests and returns validation prompts.
