# Business Process Guidance for Infrastructure Construction: Deployment and Upgrade

## What the data for this category looks like
The business process guidance data for infrastructure construction comes from official process forms and project ledgers such as construction permit approval, progress reporting, and completion acceptance. Data updates are triggered based on project node changes, and synchronized when approval links are adjusted or material supplement notices are released. Each document includes fields such as project number, construction area, approval link, required materials, and processing time limit. Field units are mostly square meters, working days, items, and similar. Some documents include structured process step lists and construction drawing attachments.

## Constraints imposed by these characteristics during deployment and upgrade
The data sources for infrastructure construction business process guidance are scattered, with significant field differences. During deployment, parsing rules for multi-source structured forms must be adapted to avoid field mapping errors. Data updates have no fixed cycle. During upgrade, an incremental synchronization mechanism must be configured to ensure real-time synchronization of process information. Each document includes multi-step processes and large-volume attachment materials. During deployment, sufficient storage and context processing capacity must be reserved. Some process materials contain sensitive construction data. After upgrade, the security of access permission configuration must be verified.

## Configuration settings
This configuration rule applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Point to an independently deployed replica set instance that includes authentication information | Infrastructure construction project data volume continues to grow as projects progress. A replica set ensures read/write stability and fault recovery capabilities |
| `REDIS_URL` | Configure as a dedicated instance with memory no less than 8 GB | A large number of real-time statuses of approval nodes and user session contexts need to be cached to ensure the response speed of process guidance |
| `STORAGE_S3_ENDPOINT` | Adapt to the access endpoint of the local object storage service, bind a dedicated storage bucket | Infrastructure construction projects include a large number of large-volume attachments such as construction drawings and acceptance reports. Local object storage reduces storage costs |
| `DB_MAX_LINK` | Set to 200–300 | When multiple projects are processed in parallel, the number of database connections must cover concurrent process queries and data write requests |
| `FE_DOMAIN` | Configure as a dedicated secondary domain name | It is convenient to distinguish process guidance pages for different infrastructure projects and improve access security |
| `FILE_TOKEN_KEY` | Generate a 32-bit random string | Used to encrypt access tokens for process attachments to prevent unauthorized access to sensitive construction materials |

## Three common configuration errors
- After upgrade, refreshing the chat page displays new conversations, and historical records are empty. The cause is that the session cache directory associated with `REDIS_URL` was not retained during upgrade, or the configured `REDIS_URL` points to an empty instance.
- After configuring `STORAGE_S3_ENDPOINT`, construction drawing attachments cannot be loaded. The cause is that the access permissions of the storage bucket were not correctly configured, or the connection string does not include the storage bucket name and path prefix.
- The number of returned results from process queries is insufficient. The cause is that `DB_MAX_LINK` is set too low, and the database connection pool is exhausted, causing some query requests to be rejected.

## How to verify successful configuration
- Access the process guidance page bound to `FE_DOMAIN`, submit a basic process query request, and check that there are no connection timeout error messages in the background database logs.
- Upload a construction drawing attachment, verify that a corresponding file was generated in the storage bucket corresponding to `STORAGE_S3_ENDPOINT`, and that the attachment can be downloaded normally on the page.
- Initiate multiple concurrent process query requests, check that the memory usage of `REDIS_URL` does not exceed the threshold, and that no expiration exceptions occur in the session cache.
- After executing the version upgrade script, check that there are no configuration loading failure error messages in the background startup logs, and confirm that all parameters have taken effect.

The values provided are common starting points and should be measured against the reader's own samples.
