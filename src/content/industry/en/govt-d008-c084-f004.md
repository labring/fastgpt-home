# Business Process Guidance for Commodity Trading: Workflow Orchestration

## What the data for this category looks like
Commodity trading data mainly comes from internal business systems of state-owned and central enterprise trade and logistics sectors, including purchase and sales contracts, warehouse receipts, logistics waybills, settlement vouchers, and more. Data updates trigger with business nodes: core fields are synchronized after contract signing, and related information is updated in real time after goods are outbound and settlement is completed. Documents are primarily structured forms, containing fields such as product category, specification model, transaction quantity, unit price, waybill number, storage address, and others. Units mostly use industry-standard measurements like ton, cubic meter, CNY/ton, and kilometer. This page is written for FastGPT v4.17.0.

## What constraints these characteristics impose on workflow orchestration
The large number of structured fields and varied unit types requires precise field mapping rules for each business node during workflow orchestration, to avoid extracting invalid or incorrectly formatted data. The characteristic that data updates follow business nodes requires workflow trigger conditions to be bound to status changes of corresponding business nodes, ensuring alignment with data update timing. Cross-business system data sources require configuring multi-node MCP service connections in the workflow, to ensure real-time synchronization of data across links. Additionally, the diversity of measurement units requires the workflow parameter verification link to enforce matching the unit rules of corresponding fields, preventing unit incompatibility issues in transferred data.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `variables` | Bind one-to-one with business fields, match core fields such as product name and transaction quantity | Commodity trading data primarily uses structured fields; precise mapping avoids invalid data extraction |
| `nodeId` | Bind the unique identifier of business nodes such as warehouse receipt generation and settlement submission | Data updates trigger with business nodes; precise node IDs ensure workflow trigger timing aligns with business processes |
| Unit verification switch | Enable, enforce matching the measurement rules of corresponding fields | Commodity trading uses multiple measurement units such as ton, cubic meter, CNY/ton, which prevents unit incompatibility issues in transferred data |
| MCP service log retention period | 7 days | Business process logs must be retained until settlement completion; 7 days covers regular troubleshooting cycles |
| Model call timeout | 120 seconds | Commodity trading business data has a large volume; a longer timeout avoids workflow interruptions caused by incomplete data retrieval |
| Context variable limit | 8000 token | Multiple contracts and waybill data need to be carried in business processes; sufficient context ensures the model correctly understands business logic |

## Three common mistakes
- Phenomenon: The model ID currently in use cannot be found in the workflow configuration panel, and no corresponding identifier is displayed when clicking component details. Cause: The model ID display switch for workflow components has not been enabled, or the model ID has not been included in the visible fields of the `variables` configuration.
- Phenomenon: After an MCP service call fails, only a generic error message "call exception" is displayed, and detailed request and response logs cannot be queried. Cause: No MCP service log retention rules have been configured, or the retention period has been set too short, causing logs to not be stored correctly.
- Phenomenon: The same business task takes significantly longer to execute in the workflow than in separate debugging. Cause: The workflow binds cross-system data retrieval and verification links across multiple nodes, while separate debugging only calls single-node interfaces and does not include the time cost of the full process.

## How to confirm the configuration is complete
- Enter the workflow `variables` configuration panel, check whether the bound business fields match the fields in actual business data, and ensure the mapping relationship is correct.
- Trigger a test business node, view the workflow running logs, confirm that MCP service call logs are fully retained, and there are no unit mismatch errors.
- Manually modify the measurement unit of test data, verify whether the workflow unit verification switch correctly intercepts abnormal data.
- View the workflow trigger configuration, confirm that the bound `nodeId` fully matches the node identifiers of the business system, and ensure the trigger timing is correct.
