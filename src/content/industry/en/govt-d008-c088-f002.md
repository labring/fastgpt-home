# Engineering Consulting Supervision Business Process Guidance: Vector Models and Indexes

## What this category of data looks like
Engineering consulting supervision business process data primarily comes from project supervision logs, on-site inspection records, sub-project acceptance reports, engineering change visa forms, and similar documents. Data update frequency adjusts based on project progress nodes. Update frequency increases after sub-project acceptance, and daily supervision logs are archived weekly. Each document has a fixed structure, including fields such as project number, supervision unit, inspection items, rectification requirements, rectification time limit, acceptance results, and other fields. Some documents include numeric unit fields like project area and duration days. Most text content consists of process descriptions and on-site issue records.

## What constraints do these characteristics impose on vector models and indexing
The multi-field structured documents of engineering consulting supervision require the indexing process to preserve field associations, to avoid breaking business context during chunking. Long text content from on-site issue records requires vector models to support long text input, to prevent truncation of critical process descriptions. The incremental update rhythm based on project nodes requires indexes to support incremental rebuilding triggered by project batches, to avoid full regeneration. The presence of numeric unit fields requires the indexing process to add vectorization adaptation for numeric features, or associate corresponding text descriptions for joint indexing.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the typical length of single-paragraph process descriptions and rectification requirements in supervision documents, avoids destroying the integrity of business context |
| Overlap Length | 100–150 characters | Preserves the association of front and back steps of supervision processes across chunks, prevents critical process nodes from being split |
| Similarity Threshold | 0.72–0.85 | Balances recall accuracy and completeness for business process guidance, adapts to the semantic similarity distribution of supervision records |
| Single Search Limit | Top 8 entries | Matches the number of associated supervision records involved in a single business process, avoids excessive redundant information entering the context |
| `maxToken` | 8192 | Adapts to the maximum token limit of mainstream embedding models for FastGPT v4.17.0, covers the total length of chunks from long supervision documents |
| Reranking | Enabled | Optimizes search result ranking by combining business field matching, corrects deviations from relying solely on semantic similarity |

## Three common mistakes
- Swapping the embedding model causes the imported knowledge base to fail normal retrieval, shown as empty search results or semantic matching deviations. The cause is that the original index was generated based on the vector space of the old model, and vector features were not updated synchronously.
- An error occurs when ada 002 is not selected, shown as the interface popping up the "undefined model must match "^(text" error message. The cause is that some embedding models require dedicated interface permissions or version adaptation to be configured in advance; model verification fails if pre-configuration is not completed.
- Semantic retrieval scores are high but matching results are irrelevant, shown as search results meeting score requirements but not matching core requirements of the business process. The cause is that reranking is not enabled; relying solely on semantic similarity easily confuses process descriptions with unrelated on-site records.

## How to confirm configurations are set correctly
- Import a single typical supervision document, check the chunk preview interface, confirm that chunk lengths fall within the preset range and no critical rectification requirements are truncated.
- Trigger a knowledge base incremental update, check the batch range in the update log, confirm that index rebuilding is only performed for documents from specified project nodes.
- Launch a test query for business process guidance, check the sorting logic of search results, confirm that the reranking function is active and result priorities meet business expectations.
- After swapping the embedding model, manually trigger a full index rebuild, verify that there is no significant deviation in the semantic matching degree of retrieval results.

The values provided are common starting points and should be measured against the reader's own samples.
