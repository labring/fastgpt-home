# Business Process Guidance for Engineering Consulting Supervision: Multi-turn Dialogue and Prompt Words

## What the Data for This Category Looks Like
Data for engineering consulting supervision originates primarily from archived documents of construction projects, including supervision logs, inspection application forms, sub-project acceptance reports, and similar materials. Data is updated per individual project cycle, with continuous production from project initiation through completion. Single documents typically include fields such as project number, supervision unit, time nodes, rectification requirements, and acceptance standards. Units follow standard engineering measurement methods, including square meters, ten thousand yuan, and working days.

## Constraints Imposed on Multi-turn Dialogue and Prompt Word Configuration
The high volume of specialized fields in engineering consulting supervision and continuous document accumulation over project cycles create multiple constraints for multi-turn dialogue and prompt word configuration. Project-related variables must be used to lock corresponding supervision data, preventing cross-project data mixing. Mappings between specialized terminology and fixed fields must be clearly defined in prompt words to avoid generating guidance that violates supervision specifications. Long-term accumulated supervision documents consume model context, so document slice length per single dialogue turn must be limited to stay within model supported ranges. Multi-turn dialogue must track project progress nodes, with `chatId` used to associate the current project session and ensure coherent context.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind two variables: project number and supervision phase, with values being the unique identifier of the project associated with the current session and the progress node | Lock the supervision data for the corresponding project to avoid confusion from cross-project calls |
| `chatId` | Bind project + session timestamp, using the format `project number_YYYYMMDDHHMM` | Ensure context independence for different sessions of the same project, avoid confusion across multiple project sessions |
| Chunk Length | 800–1200 characters | Adapt to the paragraph length of engineering documents, balance context call volume and information completeness |
| Overlap Length | 150–200 characters | Retain context connection information between chunks, prevent misunderstanding caused by specialized terms being split |
| Max Context | First 4000 characters | Adapt to the basic context limits of general large models, avoid exceeding the model's processing threshold |
| `messages` | Add supervision professional rule prompts to the initial `messages` | Clarify that dialogue must follow the acceptance and rectification process standards of engineering supervision |

## Three Common Configuration Errors
- Issue: Bilingual Chinese and English dialogue opening prompts cannot be configured in the same workflow. Root cause: No language parameter bound via `variables`, and no language-triggered branch rules defined in prompt words.
- Issue: Image links are missing domain names when importing supervision documents in Markdown format. Root cause: Domain name auto-completion was only configured during the Word document conversion phase, with no corresponding configuration enabled during the Markdown document import step.
- Issue: Truncation errors occur after multi-turn dialogue context exceeds the model's supported range. Root cause: No document slicing rules configured, and no limit set on total document length called per single dialogue turn.

## How to Verify Successful Configuration
- Launch a test session, select `variables` with different project numbers, and confirm that dialogue only calls supervision data for the corresponding project.
- Upload a Markdown-format supervision document that includes images, check that images display correctly in dialogue, and confirm domain names are automatically completed.
- Trigger a tool call process, and confirm that output only includes AI-organized process guidance with no tool execution logs.
- Upload an extremely long supervision document, confirm that no context truncation errors appear in dialogue, and verify that slicing configurations are active.

The values provided are common starting points and should be measured against the reader's own samples.
