# Business Process Guidance for Engineering Consulting Supervision: Tool Calling and Plugins

## What the data for this use case looks like
The data source for engineering consulting supervision includes project documents such as on-site inspection records, sub-item acceptance reports, progress control ledgers, and cost review documents. Updates are triggered per project construction phase, for example, after concealed work acceptance and before completion acceptance. The document structure includes fields such as project unique ID, full name of supervision unit, acceptance item name, rectification item list, rectification completion rate, and corresponding construction section. Some fields have attached specific units, such as square meters, duration days, and number of rectification items. The length of a single document varies widely, from hundreds of characters to tens of thousands of characters.

## What constraints these characteristics impose on tool calling and plugins
The fields of supervision data are closely related. Tool calling must strictly match the preset field order, otherwise parsing results will be misaligned. Data is updated per project phase, so plugin trigger timing must be bound to the corresponding construction phase to avoid invalid calls. Document formats are diverse, including PDF, Excel, Word, etc., so plugins must support multi-format parsing adaptation. Fields have attached specific units, so a unit verification step must be added after tool calling to ensure data compliance.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Plugin Trigger Timing | Bind to project concealed acceptance and completion acceptance phases | Matches the rhythm of supervision data updated per project phase |
| Input Field Mapping Rule | Map fields sorted by project ID, acceptance content, and rectification status | Matches the fixed field structure of supervision documents |
| Single Tool Call Data Limit | No more than 4000 characters | Prevents call timeouts caused by large-volume supervision files |
| `toolChoice` | Auto-match | Adapts to automatic parsing requirements for different format supervision documents |
| Result Field Verification | Enable unit legality verification | Matches the unit specifications of supervision data such as square meters and duration days |

## Three Common Misconfigurations
- Phenomenon: After adding a custom supervision plugin to the workflow, the input and output parameter fields are empty, and no error logs are displayed. Cause: The standard field mapping rules for supervision data are not bound in the plugin configuration, so the system cannot recognize the parameter structure.
- Phenomenon: Response timeout occurs when calling the tool, and the log shows the request duration exceeds 60 seconds. Cause: The supervision data volume for a single tool call is not limited, and large-volume progress ledger files cause excessive model loading time.
- Phenomenon: After uploading a supervision PDF document, the parsing result is empty, and rectification item information cannot be extracted. Cause: The parsing adaptation switch for PDF format files is not enabled, so the document cannot be read correctly.

## How to Verify Successful Configuration
- Enter the workflow editing page of FastGPT v4.17.0, add the configured supervision plugin, and confirm that preset fields such as project ID and acceptance content are displayed in the input and output parameter fields.
- Upload a standard supervision acceptance report, trigger the plugin call, and check whether the returned result includes correct fields such as rectification items and acceptance status.
- Simulate the project concealed acceptance phase to trigger the plugin, confirm that the plugin automatically executes the call, and there is no manual trigger exception.
- View the tool call log, confirm that the single call data volume does not exceed the preset limit, and there are no timeout errors.
