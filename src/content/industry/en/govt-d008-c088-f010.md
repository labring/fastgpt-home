# Workflow Guidance for Engineering Consulting Supervision: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Engineering consulting supervision business data mainly comes from four core document types: project supervision plans, on-site supervision records, sub-project acceptance reports, and supervision implementation detailed rules. Data updates follow project progress rhythms. On-site records are updated in daily inspection batches, and acceptance reports are uploaded synchronously after the corresponding project node is completed. The document structure is fixed, including project number, professional engineering category, execution node, original clause text, and supervision signature section. Fields include rectification time limit (unit: working days), acceptance qualification judgment items, and associated construction process number. The length of a single document ranges from hundreds to thousands of characters.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Engineering consulting supervision data is stored classified by professional category and execution node. Corresponding ranges must be limited during retrieval to exclude cross-professional irrelevant results. The length of single documents varies widely, and the clause-style structure easily leads to truncated key rectification requirements in chunks. Chunking logic must be adjusted to adapt to clause splitting. Fields include rectification time limit with working day unit and associated process number. Unit information must be retained during retrieval to accurately match user query requirements. Data is dynamically updated with project nodes. Incremental synchronization trigger rules must be configured to avoid excessive computing resource usage from full updates.

## How to set the configurations
This configuration is formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the density of professional terminology in supervision documents. Avoids introducing irrelevant construction content if set too low, and misses key rectification clauses if set too high |
| `limit` | Top 6 entries | The number of single-batch retrieval results for supervision documents should not be too high, to avoid context overflow affecting generation logic |
| `searchMode` | semantic | Matches semantic associations of professional terminology, adapts to the clause-style logic of supervision guidelines. Keyword-based matching cannot cover professional semantic associations |
| `usingReRank` | Enabled | Re-ranks initial retrieval results by relevance, corrects deviations from semantic retrieval, and ensures core rectification requirements are displayed first |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands professional synonyms for user queries. For example, expands "on-site supervision" to "on-site inspection records", adapting to the terminology habits of the supervision industry |
| `collectionIds` | Collection IDs grouped by project specialty | Limits the retrieval scope to the supervision documents of the corresponding specialty, avoiding cross-professional results interfering with the current task |

## Three common mistakes
- Phenomenon: Phrases like "Citation Mark: [1]" appear in the generated results. Cause: The automatic attachment configuration for retrieval result citation identifiers is not disabled. The number of the retrieval entry is directly written into the generation context.
- Phenomenon: Retrieval results include cross-professional construction documents that are irrelevant to the current supervision task. Cause: The `collectionIds` parameter is not used to limit the retrieval scope of professional document sets, triggering a full knowledge base retrieval.
- Phenomenon: Too many results are returned in a single retrieval, leading to context overflow. Cause: The `limit` parameter is not adjusted, and the default high entry limit is used.

## How to confirm the configuration is complete
- Enter the knowledge base configuration page, confirm that `collectionIds` is bound to the professional document set corresponding to the current supervision project.
- Enter a test query containing supervision professional terminology, check that the number of returned results matches the value set by the `limit` parameter.
- View the generation result preview, confirm that there are no redundant phrases like "Citation Mark: [1]".
- Trigger an incremental synchronization task, verify that the retrieval results can synchronously cover the latest acceptance report content after data update.

The values provided here are common starting points and should be measured against the reader's own samples.
