# Engineering Consulting Supervision Business Process Guidance: Forms and Interactions

## What the Data for This Category Looks Like
Engineering consulting supervision data originates from on-site engineering supervision weekly reports, sub-project acceptance records, engineering change negotiation documents, and on-site supervision ledgers. Update frequency aligns with project progress. Individual document lengths vary significantly. Core fields include project ID, supervision section, acceptance milestone, rectification requirements, and rectification completion deadline. Standard engineering units such as square meters, workdays, and ten thousand yuan are used. Each document is linked to a unique project identifier.

## What Constraints These Characteristics Impose on Forms and Interactions
Supervision data is stored split by project section and acceptance milestone. Form interactions must support filtering associated data by section and milestone to prevent cross-project data confusion. The rectification requirements field must include a time input control. Optional dates must not be earlier than the project's start date. Individual supervision document lengths vary widely. The form's content entry area must adapt to long text input. It must also limit the character range of single entry content to avoid subsequent processing errors. Specialized engineering fields must have preset standard unit options to reduce manual input errors.

| Single Associated Data Limit | Top 6 entries | Matches the number of historical supervision records that need to be called for a single business process, avoids information overload |

## Three Common Mistakes
- Phenomenon: Invalid array length error pops up after selecting question-answering splitting mode, occurs consistently. Cause: Knowledge base data is not split by project section, leading to abnormal array length during chunking.
- Phenomenon: Token validation failed error pops up during voice input in the chat interface. Cause: Long text length of form input is not limited, leading to token overflow.
- Phenomenon: Image-based supervision document content cannot be recognized after configuring question-answering splitting. Cause: No image upload associated field is added to the form, so the knowledge base cannot capture image information.

## How to Confirm Configuration Is Complete
- Enter a standard supervision acceptance record. Check if the form automatically fills preset fields and if unit options comply with engineering industry standards.
- Enter a project ID. Verify that `userSelect` can quickly filter knowledge base content for the corresponding project.
- Adjust the chunk length parameter. Enter a long-text supervision document. Check if the chunk results fall within the expected range.
- Submit a form with required fields left blank. Check if corresponding validation prompts are triggered.
