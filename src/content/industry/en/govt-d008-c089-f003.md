# Business Process Guidance for Construction Machinery: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Business process data for construction machinery is sourced primarily from equipment operation and maintenance manuals, factory parameter ledgers, on-site work process specifications, and archived after-sales work orders. Data updates follow a monthly baseline schedule. Equipment ledgers are updated in sync with firmware upgrades, while work process specifications are updated quarterly to align with industry standard adjustments. Individual document structures are fixed, containing equipment model identifiers, step-by-step work processes, fault troubleshooting nodes, and core parameter thresholds. Fields include equipment number, operation duration, and fault code. Units include hours, unit counts, millimeters, and other standard units.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Fixed fields and unit requirements for construction machinery data require multi-turn dialogue prompts to explicitly specify that outputs must match corresponding units, to avoid parameter confusion.
Differences in data update rhythms require the dialogue system to support periodic knowledge base refreshes, to ensure the timeliness of work processes and parameter thresholds.
Standardized document structures require multi-turn dialogue to guide users to provide key information in the order of equipment model, work scenario, and fault type, reducing invalid input.
The correlation between historical work orders and operation and maintenance data requires the dialogue system to retain context information within the `messages` parameter, associating previously mentioned equipment numbers and work records.

## Three Common Misconfigurations
- Historical dialogue logs appear empty in the conversation interface. The cause is that the `chatId` session identifier is not bound, so the system cannot associate the session context for the corresponding equipment, resulting in failure to archive logs.
- Workflow dialogue displays a failure, but model testing operates normally. The cause is that required fields for construction machinery are not bound in `variables`, so prompts cannot match corresponding business data, resulting in workflow interruption.
- Historical dialogue information cannot be retrieved when calling business guidance. The cause is that `messages` context is not concatenated in reverse chronological order of conversation time, so the system cannot identify previously mentioned equipment numbers and work scenarios.

## How to Confirm Proper Configuration
- Initiate a simulated business conversation, enter an equipment number and work scenario, and check if the system can recall the operation and maintenance documents for the corresponding equipment.
- View the session log, confirm that the `messages` context includes the most recent user questions and system replies, with no redundant historical information.
- Check that `variables` are bound to the required fields for construction machinery business processing, to ensure prompts can correctly call corresponding data.
- Trigger a workflow call, confirm that the session log can normally record conversation content, with no empty logs or abnormal error reports.
