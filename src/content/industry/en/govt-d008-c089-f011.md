# Business Process Guidance for Construction Machinery: Forms and Interactions
This guide is written based on FastGPT v4.17.0, and explains the form and interaction configuration for business processing scenarios in the construction machinery field.

## What Data for This Category Looks Like
Data for construction machinery business processing mainly comes from internal ERP systems of manufacturing and leasing enterprises, maintenance management platforms, and on-site operation terminals. Data is stored in structured form format. Core fields include the 17-digit VIN number of equipment, cumulative operating hours (unit: hours), fault codes, maintenance consumable models, lease start and end dates, and more. There are two types of data update rhythms: form data is submitted in real time during a single business processing, and daily operation data is synchronized to the business system once per day. Document formats are mainly standardized CSV or structured database tables, with no complex nested levels.

## What Constraints Do These Characteristics Impose on the "Forms and Interactions" Link
The uniqueness requirement of the 17-digit VIN number requires the form to be configured with fixed format validation. This limits the input length to 17 characters and only allows alphanumeric combinations, to prevent invalid data submission. The operating hours field, which uses hours as the unit, needs to be configured with non-negative integer validation, while limiting the reasonable range of single input to prevent abnormal data entry. In scenarios with many structured fields associated with business system data, the form must load fields step by step according to the business process to reduce the amount of content on a single page, adapting to the small-screen interaction of on-site operation terminals. At the same time, the form must connect to the offline caching capability of the equipment terminal to ensure that form data can be temporarily stored locally when the network is interrupted, and automatically synchronized after the network is restored.

## How to Configure the Settings
| Configuration Item | Recommended Approach | Basis for This Setup |
| --- | --- | --- |
| `formInput` | Configure `^[A-HJ-NPR-Z0-9]{17}$` format validation for the VIN number field, and limit the operating hours field to `0–240 hours` | Adapt to the 17-digit VIN code standard format for engineering machinery equipment to avoid invalid equipment identifier entry; limit duration input according to the reasonable daily operating range |
| `userSelect` | Bind the internal enterprise equipment ledger data source, set the number of selectable devices to `1 device` | Ensure that business processing is only associated with a single device to avoid confusion between multiple devices, and synchronize the enterprise's existing equipment ledger as the data source |
| Form step-by-step loading | Display in 3 steps according to "Device Confirmation → Job Details → Business Confirmation" | Reduce the number of form fields on a single page, adapt to the small-screen interaction of on-site operation terminals, and reduce input errors |
| Offline caching function | Enable it, set the cache limit to `1000 MB` | Adapt to the weak network environment of on-site operations, ensure that form data can be temporarily stored locally when the network is interrupted, and automatically synchronized after the network is restored |
| Submission timeout threshold | Set to `30 seconds` | Match the average interface response duration of the internal enterprise business system to avoid submission failures caused by network fluctuations |
| Field unit locking | Enable unit locking for fields such as operating hours and consumable quantities | Prevent users from randomly modifying units to cause data format confusion, which meets the standardized requirements of construction machinery business |

## Three Common Mistakes
- Phenomenon: A "device number format error" prompt appears when submitting the form, but the entered VIN code complies with the 17-digit rule. Cause: Full-width/half-width character validation is not configured, and the user entered full-width letters or numbers, resulting in failed format validation.
- Phenomenon: The file upload component associated with the form returns "file address parsing failed" after submission. Cause: The linkage logic between the form and the document parsing tool is not configured, and the automatic parsing process is not triggered after the file is uploaded directly, causing the system to fail to recognize the file content.
- Phenomenon: A large number of irrelevant historical device entries appear when selecting a device, making it impossible to quickly locate the current operating device. Cause: The data source of devices within the current operating scope of the enterprise is not bound, and the full historical device ledger is incorrectly pulled, resulting in low user selection efficiency.

## How to Confirm the Configuration Is Complete
- Manually enter a VIN code that complies with the 17-digit standard format to confirm that the input validation rule triggers normally, and a corresponding prompt pops up when characters that do not comply with the rule are entered.
- Disconnect the network environment, fill in the form data and try to submit, then restore the network and confirm that the system automatically synchronizes the submitted form data to the business system.
- Try to modify the preset units of fields such as operating hours and consumable quantities to confirm that the unit locking function takes effect, and the preset units cannot be modified.
- Open the device selection drop-down list to confirm that only device entries within the current operating permission range are displayed, with no irrelevant historical devices.
