# Business Process Guidance for Refined Oil Sales: Workflow Orchestration

## What the data for this category looks like
Data mainly comes from gas station POS terminals, oil inventory and sales management systems, and member transaction systems. Data updates fall into two categories: real-time transaction data and daily summary data. Real-time data is synchronized within 10 seconds after a transaction completes. Summary data is updated daily at midnight. A single transaction document includes fields such as oil product code, fuel volume (liters), settlement unit price (yuan/liter), transaction time, member identifier, and payment channel. Some cross-station transfer data also includes additional fields like warehouse site number and transport batch number.

## What constraints these characteristics impose on workflow orchestration
The synchronization delay requirement for real-time transaction data means workflow node response times must not exceed 15 seconds. Otherwise, transaction data may be missed. Multi-field transaction documents require mapping and validation of `variables` in the workflow to prevent process interruptions from missing fields. The batch number field for cross-station transfer data uses a special format, so a pre-check node must be configured in the workflow to verify the field format. Oil product code formats exported by different systems have minor differences, so the workflow needs a unified data format processing step to avoid matching errors in subsequent stages. In FastGPT v4.17.0, node configuration for this type of workflow must adapt to format difference requirements for multi-source data.

## How to set configurations
| Configuration Item | Recommended Practice | Basis for This Practice |
| --- | --- | --- |
| Variable Mapping | Bind the `variables` field of the transaction document | Match the multi-field structure of refined oil transactions to ensure accurate data transfer |
| Node Identifier Naming | Name according to the `nodeId` rule as pos_trade, stock_sync | Facilitate workflow debugging and quick node location |
| Database Connection Timeout | 10 seconds | Adapt to the synchronization delay requirement of real-time transaction data |
| Pre-check Configuration | Verify the format of fuel volume and oil product code fields | Adapt to field format differences across different systems |
| Global Variable Configuration | Store payment channel enumeration values | Unify parameter references across nodes and avoid hardcoding errors |

## Three common errors
- Individual plugin export fails, prompting missing dependent fields. The cause is that associated parameters required by the plugin are not configured in `variables`, leading to incomplete data being unreadable during export.
- Database connection node response times out, with a single execution taking more than 10 seconds. The cause is that no reasonable timeout parameter is set, which cannot meet the synchronization requirements of real-time transaction data.
- The classify module cannot select a model, but runs normally after publishing. The cause is that the model selection cache in the workflow editing interface is not refreshed in time, and the correct model configuration is automatically loaded during publishing.

## How to confirm the configuration is complete
- Trigger simulated transaction data, review the workflow running logs, and confirm all `variables` fields are correctly mapped
- Check the running duration of the database connection node, and confirm a single call takes no more than 10 seconds
- Manually modify the oil product code to an abnormal format, trigger the process check, and confirm the pre-check node intercepts abnormal data
- After publishing the workflow, verify that global variable parameters can be properly referenced in all nodes

The values provided here are common starting points and should be measured against the reader's own samples.
