# Business Process Guidance for Refined Oil Product Sales: Tool Calling and Plugins

## What the data for this category looks like
Refined oil product sales business processing data mainly comes from offline gas station POS terminals, enterprise ERP inventory and sales management systems, and member management systems. Data is updated in two rhythms: real-time transaction data, which is synced after each fueling, top-up, or invoicing operation is completed, and daily inventory check data, which is updated after the day’s business closes. The structure of a single business document includes fields such as oil product code, oil product category, transaction time, transaction amount, fuel volume in liters, transaction channel, and business type (fueling, top-up, invoicing, card application). Units involved include liters, yuan, tons, and transaction counts.

## What constraints these characteristics impose on tool calling and plugins
The real-time nature and field complexity of refined oil product sales business data create multiple constraints for the tool calling and plugins workflow. Real-time transaction data requires plugin calling delay to stay under 2 seconds, otherwise counter processing progress cannot be synced. Business documents with multiple fields require specifying optional parameter ranges (such as oil product category and business type) during tool calling to prevent the model from generating invalid parameters. Daily updated inventory check data requires passing a query date range when calling plugins to avoid returning expired inventory information. For fields involving member privacy, enable permission verification in plugin configuration, only allow authorized accounts to call, and mitigate data leakage risks.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `functionCall` | Mandatory specification | Adapt to the structured calling requirements of multi-parameter refined oil business, avoid the model generating unexpected parameters |
| `toolChoice` | Automatic selection | Adapt to the flexible calling requirements of conventional business processing, balance parameter accuracy and calling efficiency |
| Plugin timeout | 1.5–2 seconds | Match the synchronization delay requirement of real-time transaction data, prevent counter processing timeout |
| Parameter verification switch | Enabled | Filter invalid oil product code and business type parameters, avoid calling failures |
| Data time range limit | Current day + previous 7 days | Adapt to the update rhythm of daily inventory checks and real-time transactions, only return data within valid time ranges |
| Permission verification configuration | Bind to internal enterprise account system | Comply with privacy compliance requirements for member and transaction data in refined oil business |

## Three Common Mistakes
- A 401 status code is returned when calling the plugin. The cause is that the permission verification rules for internal enterprise accounts are not configured correctly, causing FastGPT to fail identity verification.
- The tool call returns an empty result. The cause is that the data time range is not specified, and the plugin returns expired inventory check data or fails to match the current day's transaction information.
- The business parameters generated by the model do not match the actual business. The cause is that the `functionCall` mandatory mode is not enabled, and the model autonomously generates non-existent oil product category parameters.

## How to Confirm the Configuration Is Correct
- Call the test business processing interface, pass the known oil product code and business type, check whether the plugin returns corresponding data.
- View the plugin calling logs in FastGPT v4.17.0, confirm that the returned parameters match the passed configuration items, and there are no invalid parameters.
- Simulate a timeout scenario, check whether the plugin returns results within 1.5–2 seconds, and no timeout error occurs.
- Verify the permission verification function, use an unauthorized account to call the plugin, confirm that an identity verification failure prompt is returned.
