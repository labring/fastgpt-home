# Business Process Guidance for General Contracting of Housing Construction Projects: HTTP Interfaces and External Systems

## What the data for this category looks like
The business processing data for general contracting of housing construction projects comes from two sources: the enterprise's internal general contracting project management platform, and the engineering approval and record system of the local housing and urban-rural development department. Data updates synchronize with the progress of individual processing flow nodes. It pulls the latest status only when the flow is triggered. The document uses a structured table format. It includes project unique identifier, section information, processing link name, current progress, required submission material items, and legal processing time limit. Fields include project number (string type), processing status (enumeration type), time limit field measured in working days, and material items as a multi-line text array.

## Constraints for HTTP Interfaces and External Systems Posed by These Characteristics
Multiple data sources require interfaces to support cross-system authentication and field mapping. This adapts to format differences between internal project data and external approval data. Structured fixed fields require interfaces to return business data in preset formats. Without this, the display logic for flow nodes cannot function. On-demand data updates require interfaces to support real-time calls triggered by individual processing tasks. This enables immediate data pulling when a flow starts. Enumeration status and unit fields require interfaces to return standardized status values and time limit units. This prevents display errors in process guidance. Most external approval systems used for housing construction business use header-based authentication. Interface configuration must match the corresponding authentication rules.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `Authorization` | `Bearer {application-level API key}` | Most external approval systems for general contracting of housing construction projects require passing authentication information via request headers, to avoid exposing sensitive parameters in URLs |
| `variables` | `{"projectCode": "${external.project_code}", "currentStage": "${external.current_stage}"}` | Matches core identification fields for housing construction business processing, enabling dynamic matching and display of flow nodes |
| `responseData` | `{"status": "approval_status", "materials": "need_submit", "timeLimit": "legal_period"}` | Maps standard structured fields for housing construction business data, ensuring process guidance information aligns accurately |
| Request timeout setting | `300 seconds` | Response delays for local housing construction approval systems typically fall within the 180-240 second range, with buffer time reserved based on actual measurements |
| Retry strategy | Retry 2 times after failure, interval `60 seconds` | External interfaces for housing construction business processing may be temporarily unavailable due to network fluctuations or system maintenance, and retries reduce call failure rates |

## Three Common Configuration Mistakes
- Phenomenon: An error `Key is error. You need to use the app key rather than the account key` is returned when calling the external approval interface. Cause: The `Authorization` header is not correctly used to carry the application-level API key, and the user account key is mistakenly used as the authentication parameter.
- Phenomenon: The material list displayed on the process guidance page is empty or does not match actual requirements. Cause: Material item fields for housing construction business are not correctly mapped via `responseData`, so the original data returned by the interface is not properly extracted.
- Phenomenon: Interface calls time out, and the process guidance fails to load. Cause: The request timeout setting is shorter than the actual response duration of the housing construction approval system, and the timeout parameter has not been adjusted based on actual measurements.
