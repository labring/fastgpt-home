# Business Process Guidance for General Contracting of Building Construction Projects: Workflow Orchestration

## What the data for this category looks like
Business data for general contracting of building construction projects is primarily sourced from project management platforms, housing and urban-rural development department filing systems, on-site construction logs, and material ledgers. Data is updated synchronously with project construction nodes, and refreshes after core nodes such as foundation excavation and main structure topping are completed. Each individual project document includes fields such as unique project number, section scope, construction process list, approval node configuration, and material consumption details. Field units are mostly standard engineering units including square meters, cubic meters, working days, and tons.

## What constraints these characteristics impose on the "workflow orchestration" link
Business data for general contracting of building construction projects is scattered across multiple systems. Workflow orchestration must configure cross-system data pull nodes to prevent process interruptions caused by missing single data sources. Data updates with construction nodes, so workflow trigger timing must be bound to project progress nodes to align with data update rhythms. Fields contain specialized engineering units, so workflow must include a variable validation step to verify the legality of units such as square meters and cubic meters. Multi-level approval nodes must be configured with serial flow and parallel countersignature branches to fit the multi-level approval logic of general contracting projects.

## Three Common Configuration Errors
- After workflow runs, it returns "No matching results for tool call". The cause is that the building construction project-specific knowledge base is not bound in the tool call module, so corresponding approval documents cannot be pulled.
- Workflow node times out without automatic retry. The cause is that the node retry mechanism is not configured, and the retry trigger condition corresponding to `nodeId` is not set.
- Code execution module fails to import engineering calculation libraries. The cause is that the corresponding dependency packages are not installed in the Python environment of the FastGPT container, and installation must be completed via container configuration.

## How to Confirm Correct Configuration
- The workflow is manually triggered, and the data source node’s ability to pull core fields including project number and construction process is verified.
- A test variable with an illegal engineering unit is input, and the variable validation rule’s interception of abnormal input is verified.
- A node timeout scenario is simulated, and whether the preset retry mechanism is triggered is checked.
- The tool module is called, and confirmation is made that only matching results from the building construction project approval knowledge base are returned.
