# Business Process Guidance for General Contracting of Building Construction Projects: Tool Calling and Plugins

## What this category of data looks like
The business data for general contracting of building construction projects mainly comes from the housing and urban-rural development department project filing system, the general contractor's internal construction ledger, on-site supervision logs, and electronic materials submitted to administrative examination and approval windows. Data update frequency varies by type: project filing information is synchronized weekly, construction logs are updated daily, and contract approval ledgers are updated monthly. A single project document includes fields such as project number, section division, construction node list, approval process nodes, required material list, handling time limit, etc. Most field units use engineering standard units such as calendar days, RMB yuan, cubic meters, and tons.

## What constraints do these characteristics impose on the "tool calling and plugins" workflow
Dispersed data sources and inconsistent formats require cross-system field mapping before tool calling. This unifies project numbers and node names from different data sources into standard formats to avoid parameter matching failures. Differing data update frequencies require specific data calls based on use case: use daily updated supervision logs for real-time construction node queries, and weekly updated filing system data for approval process queries. Fields include engineering-specific units. Tool calling must automatically match unit expressions in user questions, converting "day" to "calendar day" or "working day" as specified in the document to prevent unit ambiguity in returned results. Project document structures are fixed. Tools must preload indexes for specified fields to reduce invalid matching ranges during retrieval.

## Three Common Misconfigurations
- Issue: When calling tools, the `q` parameter only passes part of the query content, and key information such as the project number is not extracted. Cause: The query optimization link is not configured, and engineering term extraction and field mapping are not performed for user queries.
- Issue: Clicking the plugin configuration button has no response, and tool addition cannot be completed. Cause: Plugin management permissions are not enabled in FastGPT v4.17.0, or the plugin configuration path does not match the preset modules for engineering scenarios.
- Issue: The unit of the tool returned result does not match the user's query, for example, returning "working day" instead of "calendar day". Cause: Engineering unit standardization mapping is not configured, and unified conversion of unit fields in the document is not performed.

## How to Verify Successful Configuration
- Initiate a query that includes a specific project number, and check whether the `q` parameter extracted during tool calling includes the project number and core business question.
- Enter the plugin management page, confirm that the engineering process query tool has been bound and enabled, and check whether the values of configuration items comply with preset rules.
- Simulate queries with different unit expressions, and check whether the units of the tool returned results match the standard units in the document.
- View the tool calling logs, confirm that the parameters of each call match the building construction project data of the current query.
