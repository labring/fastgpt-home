# Business Process Guidance for General Contracting of Building Construction Projects: Model Access and Configuration

## What the Data for This Category Looks Like
The business data for general contracting of building construction projects mainly comes from project approval documents, on-site construction logs, sub-item acceptance reports, subcontract cooperation agreements, and progress payment applications. Data update frequency is adjusted according to project progress milestones, with higher update rates at core milestones such as earthwork excavation, main structure topping, and completion acceptance. A single business document usually includes fields such as project number, project location, progress milestone, approval status, material consumption, planned construction period, and other fields. Field units include engineering standard units such as square meters, cubic meters, working days, and ten thousand yuan.

## What Constraints Do These Characteristics Impose on the "Model Access and Configuration" Link
The business data for general contracting of building construction projects contains a large number of engineering professional terms and specialized units, requiring the accessed model to have semantic understanding capabilities in the field of construction engineering. The length of business documents increases gradually as the project progresses, and a single knowledge base document may reach several thousand characters, which puts requirements on the context window capacity of the model. The business process involves multi-node approval and data verification, requiring the model to support tool calling to complete structured data extraction and process judgment. Some business scenarios need to process non-text data such as construction drawings and acceptance photos, so visual-related model access parameters need to be configured.

## Three Common Misconfigurations
- Phenomenon: When testing a visual model for processing construction drawings, the interface upload button cannot be triggered, and the log shows that the image was uploaded successfully but there is no response. Cause: The `vision` configuration item is not enabled correctly, or the accessed visual model does not adapt to FastGPT's interface format.
- Phenomenon: An offline access rerank model returns a `rerank error`, and the log contains a prompt that the `detail` field is empty. Cause: The correct local deployment path of the rerank model is not configured, or the model file is incompatible with the FastGPT version.
- Phenomenon: After adding models such as Zhipu and Qianwen 2 through a third-party channel, the corresponding model options do not appear in the knowledge base and application creation pages. Cause: The `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters are not filled in correctly, or the channel configuration has not been synchronized to the application backend.

## How to Confirm the Configuration is Complete
- Enter the model management page, check the list of accessed models, confirm that the target model is displayed normally, and manually select it to initiate a test.
- Upload a building construction project construction log document, initiate a process guidance test, and check whether the reply includes correct milestone steps and professional terms.
- Upload a construction drawing or on-site acceptance photo, trigger the visual verification function, and confirm that the model can normally return analysis results.
- After setting `toolChoice` to auto, initiate a test involving structured data extraction, and check whether the tool can be automatically called to complete data verification.
