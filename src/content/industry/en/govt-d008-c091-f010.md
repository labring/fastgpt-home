# Business Process Guidance for General Contracting of Residential Construction Projects: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data sources for general contracting of residential construction projects mainly include full-cycle construction management documents, residential construction regulations released by housing and urban-rural development authorities, project bidding documents, site visa records, and completion acceptance materials. Update rhythm is adjusted with project progress, with immediate updates when project nodes change. Most documents use a long-text structure, with wide character count ranges per single document. Fields include project section number, construction node, acceptance standards, material specifications. Units involve professional engineering units such as square meters, cubic meters, man-days, tons, and other similar units.

## What constraints these characteristics impose on the "knowledge base retrieval and recall" link
The long-document structure of general contracting for residential construction projects means multiple independent construction nodes exist within a single document. During retrieval, irrelevant content across nodes must be avoided to ensure results accurately match the construction segment specified in user queries. The presence of specialized fields and units requires retrieval matching to associate field semantics and unit characteristics, reducing false recalls. Irregularly updated data sources require the recall link to support incremental synchronization, ensuring the latest site visa and change content is prioritized. Differences in authority across multi-source documents require recall to distinguish the weight between official regulations and on-site execution documents.

## How to configure the settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Semantic similarity threshold for matching residential construction terminology, to avoid false recalls of irrelevant construction nodes |
| `limit` | Top 8 entries | Adapts to the multi-node distribution of single-project documents, covering core construction segment content |
| `searchMode` | Semantic search | Matches the specialized semantic associations of residential construction projects, improving recall accuracy |
| `usingReRank` | Enabled | Re-sorts recall results by query relevance, correcting local semantic deviations caused by long-document chunking |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands query terms to cover residential construction professional synonyms, such as expanding "concrete" to "concrete" and "cast-in-place concrete" |
| `collectionIds` | Bind the section number of the corresponding residential construction project as the dataset ID | Isolates knowledge bases of different residential construction projects, avoiding interference from cross-project content |

## Three common configuration mistakes
- Uploading long documents for residential construction projects returns the `fail to create post presigned url` error. The cause is that the object storage key and bucket permissions for FastGPT are not configured, leading to pre-signed URL generation failure due to storage verification failure for large-volume engineering documents.
- Retrieval recalls knowledge base content from non-current projects, with results outside the expected scope. The cause is that the `collectionIds` parameter is not correctly configured, and the exclusive project dataset is not bound, leading to false recalls of cross-project construction documents.
- Importing CSV files of residential construction project material lists returns the `datasetId is required for S3 files` error. The cause is that the target dataset ID is not specified. CSV files for residential construction projects must be stored by section, and failure to bind a dataset prevents association with the storage path.

## How to verify the configuration is complete
- Upload a single construction organization design document for a residential construction project, check that the upload status shows completed, with no pre-signed URL related errors.
- Initiate a query including "concrete usage for a certain floor", check that the recall results only include content from the currently bound project dataset, with no cross-project documents.
- After enabling `usingReRank`, check that the order of recall results matches the query semantics as expected, with core construction segment content displayed first.
- Import CSV-format material lists, check that there are no `datasetId is required` related errors, and the import progress proceeds normally.
