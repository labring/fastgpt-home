# Business Process Guidance for General Contracting of Residential Construction Projects: Forms and Interactions

This scenario's interaction configuration is implemented based on FastGPT v4.17.0.

## What the data for this category looks like

Residential construction general contracting business data mainly comes from the housing and urban-rural development department project filing system, internal review ledgers of general construction contractors, subcontract contracts and material review documents. Data updates follow project node progress. Daily updates of corresponding forms and progress information occur during the review phase, and data is converted to static storage after completion and archiving. The document structure uses a project unique code as the core index field, and includes three types of fields: project basic information (construction area, contract amount, start date), review node forms, and acceptance material list. Field units uniformly follow housing and urban-rural development ministry specifications: construction area is measured in square meters, contract amount is measured in ten thousand yuan, and review materials are measured in copies.

## What constraints do these characteristics impose on the "forms and interactions" link

Fixed field format requirements for housing construction project data require that form interactions must be configured with targeted input verification rules to avoid submitting information that does not meet coding and numerical range requirements. The characteristic that data updates with business nodes requires interactions to support loading corresponding forms according to current process nodes, and cross-node submission of uncompleted materials is not recommended. The multi-dimensional combination of business fields requires forms to support nested grouping interactions, while also adapting to attachment upload requirements of different review links to ensure consistency between data and business processes. In addition, the requirement that data must be synchronized to the housing and urban-rural development supervision platform requires that input content in the interaction link must strictly match the field format of the supervision system, otherwise synchronization will fail.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Form input verification | Configure according to housing and urban-rural development ministry field rules | Match the fixed format requirements of housing construction project data, ensure submitted content complies with supervision system specifications |
| User selection scope | Bind review node data of the current project | Avoid selecting options beyond the current business link, comply with the logical order of general contracting processes |
| Context window | Calibrate based on actual testing | Adapt to the content length of a single review form, avoid exceeding interaction content limits |
| Single submission limit | 1 time per business node | Prevent repeated submission of review materials for the same link, comply with the single process requirements of business handling |
| Timeout waiting | Calibrate based on actual testing | Adapt to the interface response duration of the housing and urban-rural development supervision platform, avoid submission request interruptions |
| Attachment upload limit | Configure according to conventional specifications of business materials | Match the size and quantity requirements of housing construction review materials, ensure smooth upload process |

## Three common mistakes

- Setting the context window too large, which causes token limit exceeded errors on the interface display or truncated returned content. The cause is that the conventional content length of housing construction review forms is not matched, and a window size beyond the reasonable range is set.
- Not configuring the `formInput` verification rule, which causes the system to return field format error prompts or data that cannot be synchronized to the supervision platform. The cause is that verification logic is not set for the exclusive field format of housing construction projects.
- Not limiting the optional scope of `userSelect`, allowing selection of review forms for completed nodes, leading to abnormal process status display and inability to enter the next link. The cause is that review node data of the current project is not bound, resulting in optional options exceeding the current business scope.

## How to confirm the configuration is complete

- Enter information that conforms to the exclusive field format of the project, check whether the `formInput` verification logic triggers corresponding prompts normally
- Select optional options within the business process, check whether the `userSelect` scope only covers current and uncompleted business links
- Upload files that conform to conventional specifications of business materials, check whether the upload limit rules take effect
- Initiate a submission request, check whether the timeout waiting setting adapts to the conventional duration of system response
