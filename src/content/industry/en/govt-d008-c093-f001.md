# Business Process Guidance for Government and Enterprise Informatization Services: HTTP Interfaces and External Systems

## What the data for this category looks like
Business process guidance data for government and enterprise informatization services is primarily sourced from internal business handling systems, service guides and process configuration documents on public government service platforms. Data updates trigger synchronously with business policy adjustments or process optimizations, with no fixed cycle. A single data document has four core fields: item classification, handling step sequence, required material list, and completion time limit. The field types are classification tag, ordered numeric sequence, text description, and numerical value measured in days.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data is stored split by individual handling items, and steps are ordered sequences. HTTP interfaces must support precise retrieval of matching process data using an item’s unique identifier, to avoid returning full redundant information. Data updates have no fixed cycle, so interfaces must allow configuration of adjustable cache expiration times to adapt to temporary business changes. Fields include completion time limits with units, so interface responses must retain these units and must not strip or alter them. Long text material lists and step descriptions require interfaces to support a maximum response body of at least 10,000 characters, to prevent content truncation.

## Three common mistakes
- Calling the knowledge base association interface returns a 400 status code, with the prompt "missing associated parameters". The cause is that parameters matching the knowledge base ID and business item ID are not included in the request body, so the interface cannot locate the corresponding process data.
- Interface responses time out after running the upgrade script. The cause is that the request was not initiated from the specified terminal as required by the documentation, or `example value` was not correctly replaced with the actual key value from the environment variables.
- The handling step order displayed on the front end is disordered. The cause is that the ordered numeric identifier of the step sequence in `responseData` was not preserved, disrupting the step order when the interface returns data.

## How to confirm the configuration is correct
- Send a test HTTP request and verify the response status code is 200 OK.
- Check that the response data includes the item name, handling steps, completion time limit, and required materials, and that the step order matches the actual business process.
- Send three identical consecutive requests and confirm there is no significant delay in the response data after the cache takes effect.
- Enter an invalid item ID and confirm the interface returns a clear error prompt, with no internal service error messages.
