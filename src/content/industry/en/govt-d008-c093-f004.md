# Business Process Guidance for Government and Enterprise Informatization Services: Workflow Orchestration

## What the data for this category looks like
Business data for government and enterprise informatization services comes from internal government and enterprise business processing systems, communication operation work order databases, and government service platforms.
Data updates are triggered by business processing nodes. Daily synchronization frequency is no less than once per day.
Content primarily uses structured fields, including `nodeId`, business processing link name, required material list, processing time limit, consultation script template, exception handling rules, and other fields. Field units include "item", "day", "unit", and others.
Single document content usually does not exceed 1500 characters.

## What Constraints These Characteristics Impose on Workflow Orchestration
Structured government and enterprise business data requires workflows to accurately bind corresponding fields in `variables` to avoid parameter misalignment.
Update rhythm triggered by business nodes means workflows cannot rely on scheduled pulls. Workflows must bind business node events as trigger conditions.
Multi-source data characteristics require workflows to configure cross-system call nodes, and handle field mapping logic.
Presence of exception handling rules requires workflows to preset exception branches covering common business exception scenarios such as missing materials and timeouts.

## Configuration Settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Trigger node type | Triggered by business node events | Government and enterprise business data updates with processing links, real-time access to latest data for the current link is required |
| Variable binding rule | Bind business fields corresponding to `nodeId` in `variables` | Government and enterprise business data uses structured fields, precise matching of link parameters is required |
| Knowledge base reference verification | Configure large model to verify matching degree between reference content and current business fields | Guidance content must comply with compliance requirements for the current processing link |
| Exception branch configuration | Bind exception nodes such as missing materials and timeouts | Multiple exception scenarios exist in business processing workflows, processing logic must be covered |
| Node timeout setting | 600 seconds | Government and enterprise business processing links usually have clear response time limits, must match conventional business requirements |
| Variable reference limit | First 8 business fields | Avoid context overload, aligns with the structured characteristics of government and enterprise data |

## Three Common Misconfiguration Issues
- Phenomenon: API calls return `variables` parameter missing errors, with status code 400. Cause: Corresponding business field of `nodeId` is not bound, and empty parameters are passed directly.
- Phenomenon: Guidance content returned by the large model does not match the current business link, and irrelevant knowledge base content is referenced. Cause: Verification rule bound to `variables` is not configured, and the large model directly references global knowledge base content.
- Phenomenon: The drop-down menu only shows a single variable option, and multiple business fields cannot be selected. Cause: Multi-variable binding configuration is not enabled, and only single-variable binding mode is activated.

## How to Verify Correct Configuration
- Trigger a simulated business node event, check whether the workflow automatically pulls business data corresponding to `nodeId`.
- Call the API with test `variables` parameters, check whether the returned guidance content matches the current business link.
- After configuring multi-variable binding, check whether the drop-down menu displays multiple selectable business fields.
- Trigger an exception scenario such as missing materials, check whether the workflow jumps to the corresponding exception handling branch.
