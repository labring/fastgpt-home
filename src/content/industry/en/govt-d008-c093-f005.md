# Business Handling Process Guidance for Government and Enterprise Informatization Services: Tool Calling and Plugins

## What Data for This Category Looks Like
Government and enterprise informatization services (communications category) data sources include internal business handling specification documents, communications service ticket systems, and handling guidelines from the integrated government service platform. Data updates are synchronized with business process adjustments, with no fixed cycle. Document structures mostly follow step-by-step operation instructions, required material lists, and handling time limit descriptions. Fields include handling node name, preconditions, required materials, and consultation channels. Common units are "steps", "items", and "working days".

## Constraints Imposed by These Characteristics on the Tool Calling and Plugins Link
Data centers on step-by-step handling processes. Tool calling must be strictly bound to the context of the current handling node, and only call parameter acquisition tools for that node. Cross-node calling must be avoided to prevent process confusion. Fields include structured content such as preconditions and required materials. Plugins must support structured parameter extraction, and cannot rely solely on unstructured text matching. Otherwise, handling qualification cannot be accurately verified. Data updates are synchronized with business adjustments. Tool calling configurations must support regular synchronization of data sources to avoid calling outdated process guidelines.

## How to Configure Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapt to dynamic node calls for government and enterprise processes, no manual tool specification required |
| Parameter completion trigger threshold | When 2 or more required parameters are missing | Government and enterprise business handling requires clear material information, to avoid call failures due to insufficient parameters |
| Tool call timeout period | 30-60 seconds | The response cycle of government and enterprise business handling processes is usually long, to prevent context interruption from timeout |
| Context retention length | 8000-12000 token | Government and enterprise process documents are lengthy, sufficient context must be retained to ensure smooth node handoffs |
| Reranking | Enabled | When retrieved knowledge base process documents are overly long, reorder core node information to ensure accurate model calls |
| `functionCall` | Force matching current node tools | Government and enterprise processes have strong node correlation, to avoid calling irrelevant tools and disrupting handling progress |

## Three Common Misconfigurations
- The symptom is that after each MCP tool call, the model context has a gap, and subsequent responses cannot associate with the current handling node. The cause is that the context retention switch is not enabled in the configuration, or `toolChoice` is set to force tool switching which causes context reset.
- The symptom is that when a workflow calls an MCP, missing multiple parameters cannot be supplemented through question and answer, leading to call failure. The cause is that the parameter completion trigger logic is not configured, and only fixed parameters are passed during the first call.
- The symptom is that after the knowledge base retrieves overly long content, the model does not call the reranking tool to sort the content, causing core process nodes to be overlooked. The cause is that the reranking configuration item is not enabled, or the reranking trigger threshold is set too high.

## How to Verify Successful Configuration
- Initiate a simulated business handling request, and confirm that tool calls only associate with functions of the current handling node, with no cross-node calls.
- Submit a handling request with some required parameters missing, and confirm that the system triggers the parameter completion question and answer process.
- Retrieve process documents with lengths exceeding conventional thresholds, and confirm that the system triggers reranking operations to organize content order.
- Test the response duration of tool calls, and confirm that it meets the response requirements of the business scenario.

The values provided here are common starting points, and should be validated against samples specific to the intended use case.
