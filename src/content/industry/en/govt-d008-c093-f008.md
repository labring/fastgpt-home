# Business Process Guidance for Government and Enterprise IT Services: Document Parsing and Chunking

## What the data for this category looks like
Business process documents for government and enterprise IT services mainly originate from internal business process manuals, government public service guidelines, approval form templates, and offline paper archived files. The update rhythm is triggered irregularly alongside policy adjustments and process optimizations. Documents for some high-frequency items are updated synchronously every quarter. Most documents have a fixed structure, including modules such as application conditions, required materials, processing steps, and consultation channels. Some cross-department collaborative process documents are lengthy, with fields including item name, processing time limit, number of materials, charging standards, and the like. Common units include working days, copies, yuan, and others.

## What constraints these characteristics impose on the document parsing and chunking link
The fixed chapter structure requires that chunking must retain module integrity, avoid splitting continuous content across processing steps, and ensure logical coherence of process guidance. Long cross-department documents require controlling chunk granularity to prevent excessively long single chunks that cause context overflow. Content with clear units in fields must be fully retained during parsing to avoid missing parameters in subsequent process guidance. Irregularly updated documents require real-time parsing configuration to prevent use of expired cached content. Some business documents in scanned format require additional OCR parsing configuration to ensure complete text extraction.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the chapter length of government and enterprise business documents, avoids single chunks that are too long or too short |
| `chunkSplitter` | Split by semantic segments | Retains logical coherence of business processes, aligns with the chapter structure of service guidelines |
| `customPdfParse` | Enabled | Adapts to scanned PDF formats common in government and enterprise documents, supplements OCR parsing capabilities |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the upload requirements of large cross-department process manuals, aligns with the size characteristics of government and enterprise documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses the time consumption requirements of long document parsing, avoids parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking parameters for different types of business documents, adapts to diverse government and enterprise document structures |

## Three common mistakes
- Phenomenon: PDF parsing tasks return timeout errors, or parsing status stays in processing for a long time. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted, and the default timeout duration is insufficient for large government and enterprise business documents.
- Phenomenon: Uploaded files are not directly passed to the large model, and are still parsed into text by the system default process before being sent. Cause: The relevant node parameters for `customPdfParse` were not configured, and the default parsing process was not skipped.
- Phenomenon: When calling the knowledge base file collection creation API, the PDF parsing parameters do not take effect, and the parsing result is still in the default format. Cause: The corresponding parsing configuration items were not correctly specified in the API request, and the parameter names or value formats do not meet requirements.

## How to confirm the configuration is complete
- Upload a typical government and enterprise business document, check whether the parsed text content retains the chapter structure and unit information.
- View the parsing task logs to confirm that the `customPdfParse` parameter has been enabled, and the default parsing process was not triggered.
- Call the knowledge base creation API, pass the specified PDF parsing configuration, and verify that the request parameter format and values meet the requirements.
- Adjust the `chunkSize` parameter, upload the same document again, compare the length changes of the chunked results, and confirm that the configuration has taken effect.

The values provided are common starting points and should be measured against the reader's own samples.
