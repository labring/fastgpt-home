# Business Process Guidance for New Energy Development: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Business process data for new energy development comes from energy and power project management systems used by state-owned and central government enterprises. It covers full process nodes including project initiation, environmental impact assessment approval, grid connection acceptance, and more. Data is stored individually per project, with updates aligned to project node progress. One update is made after each approval node is completed. The document structure includes fields such as project number, node type, submitted material list, processing time limit, approval status, and others. Most field types are string, date, or file list. Units include working days, copies, items, and similar units.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Since new energy development business data is stored individually per project, multi-turn dialogue must bind a unique identifier to associate with the corresponding project. This prevents context mixing across different projects. Data updates alongside node progress. Dialogue contexts must not retain expired node information. Redundant history must be cleared when nodes switch. Field types are diverse and include file-based materials. Prompts must clearly guide extraction of information for each corresponding field. This ensures large model-generated guidance content complies with business requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Set to the unique number of the new energy project | Ensure multi-turn dialogue associates with the corresponding project and avoid context mixing |
| Maximum context length | Retain the most recent 15–20 `messages` | Align with the node progression rhythm of business processing, avoid interference from redundant history |
| `variables` | Include project node and material list fields | Allow the large model to accurately call business fields to generate guidance content |
| History cleanup trigger | Automatically truncate old messages when project nodes switch | Adapt to the node-updating characteristic of new energy development projects, prevent expired information from causing misdirection |
| Prompt template association | Bind the business processing document for the current node | Ensure each dialogue call uses the processing requirements of the current node |
| User input validation | Match preset material submission fields | Guide users to provide corresponding information in accordance with business requirements |

## Three common configuration errors
- After calling the multi-turn dialogue interface, returned results do not carry the cite reference ID field. Cause: The reference identifier of the business document is not bound in `variables`, causing the system to fail to generate corresponding reference information.
- Cross-project context mixing occurs during multi-turn dialogue. Cause: The unique identifier of the corresponding new energy project is not bound using `chatId`, causing dialogue data from different projects to be loaded together.
- Expired project node information appears in the dialogue. Cause: No history cleanup rule is set for node switching, causing processing requirements from old nodes to be retained and interfere with current responses.

## How to verify successful configuration
- Initiate a test dialogue bound to a project number, and check if returned results associate with the node information of the corresponding project.
- Switch to a different business node, and verify if the dialogue context automatically clears redundant content from the previous node.
- Submit a query related to business fields, and confirm if the reply content accurately calls the preset `variables` parameters.
- Check the background logs of FastGPT v4.17.0, and confirm if the interface returns expected business process guidance content.
