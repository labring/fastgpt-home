# Business Process Guidance for New Energy Development: Workflow Orchestration

## What the data for this category looks like
Business data for new energy development mainly comes from three types of systems: project filing systems, grid connection approval platforms, and on-site survey ledgers. Each project initializes its data at launch. Each approval node updates the data synchronously after completing processing. A single data entry includes fields such as a unique project identifier, land scale (unit: hectare), installed capacity (unit: MW), approval node list, current processing status, and associated grid interface information. The approval node list includes subfields such as node name, submitted material list, and processing time limit (unit: working days).

## What constraints these characteristics impose on workflow orchestration
Decentralized data sources increase cross-system data synchronization requirements. Workflows require cross-node variable sharing configurations.
Update rhythms triggered by approval nodes require workflows to bind node identifiers to trigger processes, avoiding non-sequential execution.
Structured storage of approval node lists requires workflows to support loop traversal configuration for individual nodes.
Requirements for associated grid interface fields require integrating HTTP request nodes in workflows to call external interfaces and obtain grid connection verification results.

## How to set the configuration
This configuration applies to FastGPT v4.17.0. Details are as follows:

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Trigger Condition | Triggered by the completion status of the approval node bound to `nodeId` | New energy project approvals proceed in a fixed order. Only after the current node is completed will the next link be triggered, ensuring process compliance |
| Global Variables | Bind project filing data and grid interface parameters to `variables` | Cross-node sharing of core data such as project number and installed capacity is required, reducing duplicate requests and data inconsistency risks |
| Loop Body Configuration | Traverse the approval node list, process 1 node per single loop | Each approval node has independent material requirements and verification logic. Single-node processing avoids resource overload and process confusion |
| HTTP Request Timeout | 600 seconds | Grid interface verification may take a long time, preventing process interruption due to mid-run timeout |
| Result Output Configuration | Write the processing result of each node to the global `variables` | Subsequent nodes need to reference previous approval status, ensuring process traceability and rollback capabilities |

## Three Common Misconfigurations
- Symptom: The HTTP request node’s return result does not appear in conversation outputs. Cause: The output of the HTTP request node is not mounted to the global `variables`, so the context does not retain this result.
- Symptom: The loop body fails to fully traverse the approval node list. Cause: The approval node list is not correctly bound to the traversal source of the loop body, or the loop trigger condition is set incorrectly.
- Symptom: The trigger order of workflow nodes does not match the order of approval nodes. Cause: The trigger dependency relationship of nodes is not bound according to `nodeId`, causing non-sequential nodes to execute prematurely.

## How to Confirm the Configuration is Correct
- Execute a test project, view the execution logs of workflow nodes, and confirm that the trigger timing of each node matches the order of approval nodes.
- Open the global `variables` panel, confirm that project filing data and HTTP request results have been correctly written to the corresponding variables.
- Simulate the completion operation of an approval node, confirm that subsequent associated nodes are automatically triggered and the status is synchronized.
- Export the workflow configuration file, check that the binding relationships and variable references of all nodes conform to the preset logic.
