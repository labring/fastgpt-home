# Business Process Guidance for New Energy Development: Tool Calling and Plugins

## What the Data for This Category Looks Like
The business process data for new energy development mainly comes from internal state-owned and public enterprise energy project approval, grid connection acceptance, environmental impact assessment filing, and other business systems. Data is aggregated per individual project, with updates triggered by project progress milestones. For example, approval status updates after a project establishment application is submitted, and acceptance results update after grid connection acceptance is completed. Each individual business data entry includes fields such as project ID, project type, approval stage, required material list, processing time limit, responsible department, and others. Field units mostly use structured formats like strings, working days, items, with no semi-structured free text redundant content. This document is written based on FastGPT v4.17.0.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
The new energy development business process data is split per project and uses fixed fields, requiring tool calls to precisely match the fields corresponding to the current project’s approval stage to avoid calling irrelevant data. Data updates depend on business node triggers, so plugins must synchronize the latest business status on a regular basis, and cannot rely on fixed-cycle full pulls. Additionally, business data involves the strict requirements of government affairs processing, so parameter validation for tool calls must cover all required fields to prevent call errors caused by missing parameters. Furthermore, fields vary significantly across different approval stages, so tool calls must support dynamically switching parameter templates to adapt to business needs at different stages.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool Calling Mode | Set to `functionCall` | Adapt to the structured data calling requirements of new energy business processing, ensuring the AI strictly triggers tools according to preset parameters |
| Tool Selection Mode | Set to `toolChoice` | Allow the AI to independently select matching tools, adapting to multi-stage business processes |
| Tool Calling Timeout | 300–600 seconds | Pulling new energy project data involves multi-system interface linkage, so reserve sufficient response time |
| Function Call Parameter Validation | Enable required field validation | Prevent call failures caused by missing core fields such as project ID and approval stage |
| Number of Returned Entries per Single Tool Call | First 3 entries | New energy business processing data is aggregated per project, avoiding excessive redundant information interfering with AI judgment |
| System Prompt Template Binding | Bind the field list for the current approval stage | Allow the AI to clearly identify the core parameters required by the currently called tool |

## Three Common Misconfigurations
- Symptom: The interface displays "Tool calling not triggered, AI returns a standard response directly". Cause: The `functionCall` parameter is not configured correctly, causing the AI to fail to recognize the rules for triggering tools and instead generate unstructured responses.
- Symptom: The fields returned by the tool call do not match the current approval stage. Cause: The exclusive field list for the current approval stage is not bound, and the plugin calls an incorrect data table or field set.
- Symptom: The tool call returns a "504 Gateway Timeout" status code. Cause: The tool calling timeout is set too short, failing to adapt to the multi-interface linkage delay of new energy project data pulling.

## How to Confirm Proper Configuration
- Submit a test project ID, check whether the tool automatically pulls the business data of the corresponding approval stage, and verify that the returned fields match the preset required fields.
- Trigger a tool call, check whether it strictly triggers according to the configured parameters, and return structured tool call results.
- Input test parameters missing required fields, check whether parameter validation errors are triggered, confirming that the validation rules are in effect.
- View the plugin operation logs, confirm that the pulled data update time is synchronized with the current business node, with no expired data.
