# Business Process Guidance for New Energy Development: Model Access and Configuration

## What data looks like for this category
Business processing data for new energy development originates from official approval documents including project establishment approval, grid connection approval, land pre-examination, environmental impact assessment filing, and technical ledgers from project site surveys. Data updates follow approval node progress, and sync after each approval stage completes. Documents mix structured forms and unstructured technical reports, with fixed fields such as project number, installed capacity (unit MW), land area (hectares), and planned grid connection time. Some approval documents use a multi-page nested attachment structure.

## What constraints do these characteristics impose during model access and configuration
Mixed structured and unstructured multi-attachment data from new energy development business will significantly consume model context token quotas. Adjust upper limits for context-related parameters during model access. Data includes technical fields with fixed units. Require the model to strictly match unit formats in output to avoid parameter parsing errors. Approval nodes receive updates in phases. Configure data source synchronization logic to match project progress, and ensure called approval data uses the latest current version.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the multi-attachment context length of new energy development project approval documents, avoids truncation of key approval parameters |
| `maxTokens` | 2000–3000 token | Adapts to the response length required for business process guidance, ensures complete output of approval step instructions |
| `quoteMaxToken` | 3000–4000 token | Covers the core reference snippet length of new energy project technical ledgers and approval documents |
| `temperature` | 0.1–0.3 | Reduces random output probability, ensures format consistency of fixed units such as MW and hectare |
| `toolChoice` | auto | Triggers tool calls as needed, supplements real-time status information of project approval nodes |
| `AIPROXY_API_TOKEN` | Valid token generated by the platform | Meets the call authentication requirements of domestic large models, adapts to OneAPI relay scenarios |

## Three common configuration errors
- Symptom: Invalid token error when calling domestic large models. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or the token permissions of the OneAPI relay interface do not allow calls to the corresponding large model.
- Symptom: Context is truncated, key approval parameters such as installed capacity and land area are lost. Cause: `maxContext` parameter is not adjusted to the range suitable for multi-attachment documents.
- Symptom: Unit conversion errors appear in responses, such as MW being written as kW. Cause: `temperature` parameter value is too high, causing the model to randomly alter fixed field formats.

## How to confirm the configuration is correct
The following verification actions work with FastGPT v4.17.0.
- Upload a single new energy project approval document. Check if the model’s response includes complete approval step instructions with no truncation.
- Enter a query with fields that have units, such as installed capacity or land area. Confirm the unit format in the response matches the source data.
- Replace the OneAPI relay token and interface address. Verify calls work normally with no errors.
- Trigger a tool call test. Confirm the model returns the latest project approval node information as needed.

The values provided are common starting points and should be measured against the reader's own samples.
