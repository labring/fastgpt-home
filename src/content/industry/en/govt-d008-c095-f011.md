# Business Process Guidance for New Energy Development: Forms and Interactions

## What the data for this category looks like
Business data for new energy development comes primarily from the land use planning filing database of natural resources departments, the access technical specification database of power grid companies, and internal project approval ledgers of state-owned and central enterprises. The update schedule is: synchronize filing information in real time during the project initiation phase, and update based on the approval results of each node during the approval phase. The document structure is split into three modules: project filing, land use approval, and grid connection. Fields include project unique ID, land area (unit: hectare), installed capacity (unit: MW), current approval status, responsible department, and other core fields, with no redundant non-business fields.

## What constraints these characteristics impose on forms and interactions
Professional fields use specific industry units, so forms must include built-in unit validation rules to block input of values that do not meet industry standards. Multi-source data linkage requirements mean forms must support automatic loading of associated data via core fields such as project ID, to reduce duplicate data entry. The dynamic nature of approval nodes requires dropdown options to update in real time based on the current project status, only displaying currently executable and subsequent actionable links. Frequently updated data requires a short form cache duration, to avoid displaying expired approval information.

## Three common mistakes
- Phenomenon: A connection error prompt appears after submitting a model conversation, and recovery fails even if the network proxy is enabled. Cause: The model access channel that meets compliance requirements is not configured, and the dependent external network link has access restrictions.
- Phenomenon: When selecting a knowledge base, variable references cannot correctly pull project-specific fields for new energy projects. Cause: Project-specific fields are not configured as referenceable global variables, or the variable binding scope does not cover the current form scenario.
- Phenomenon: The workflow does not automatically trigger form validation or tool calls. Cause: The trigger rules for `formInput` are not correctly configured, causing the interaction link to not fire corresponding logic per business nodes.

## How to confirm the configuration is complete
- Enter 1500 MW as the installed capacity, check if the corresponding compliance error prompt pops up.
- Select an already entered project ID, check if associated fields such as land area and installed capacity automatically load.
- Switch the project approval status, check if the dropdown options update in real time to the approval nodes for the corresponding link.
- Call the configured variables in the model conversation, check if project-specific business data is correctly pulled.
