# Business Process Guidance for New Energy Development: Deployment and Upgrade

This document applies to FastGPT v4.17.0.

## What this category of data looks like

The business process guidance data for new energy development comes from official documents covering the entire process of project approval, land pre-examination, environmental impact assessment approval, grid connection acceptance and other stages. Updates are synchronized with the progress of approval nodes, and are usually completed within 1 to 2 working days after each node is finished. The document structure includes project main information, approval step list, required material list, and compliance verification standards. Fields include project code, approval status, material submission deadline, and compliance item requirements. Units include working days, square meters, kilowatts and other business-specific measurement standards.

## What constraints these characteristics impose on deployment and upgrade

Documents for new energy development businesses are generally large in size and updated frequently. They also include both structured approval fields and unstructured compliance documents. This requires deployments to support large storage capacity and high-frequency synchronization capabilities. Because the data involves government compliance requirements, the deployment environment must be located in an isolated intranet or access external services through a compliant proxy. When upgrading, a rolling update strategy must be used to avoid interrupting business process guidance. In addition, multi-node approval processes require that the context retrieved by the knowledge base must match step granularity, to avoid redundant information interfering with guidance accuracy.

## How to set configurations

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Configure to the cloud service provider's S3-compatible endpoint, such as `https://s3-cn-south-1.mycloud.com` | New energy development businesses contain a large number of large-volume compliance documents, requiring high-speed object storage services |
| `REDIS_URL` | Use the value `redis://default:your_password@redis-host:6379/1`, set the connection timeout to `30 seconds` | High-frequency updated approval data requires low-latency caching to ensure real-time response for business process guidance |
| `DB_MAX_LINK` | Use a value of `15–20` | New energy project approval steps usually do not exceed 15, retrieving too many will cause context overload and affect the accuracy of guidance |
| `MONGODB_URI` | Configure as a cluster connection string with read-write separation | Business data is updated frequently with approval nodes, requiring stable read-write performance |
| `FILE_TOKEN_KEY` | Generate a 32-bit random string as the key | Access permissions for uploaded project documents must be secured |
| `FE_DOMAIN` | Use the official domain name of the internal business system | The business process guidance interface must be embedded in the enterprise portal to ensure compliance of the access link |

## Three common mistakes

- Symptom: Vector database connection failure, with the console returning `500 Internal Server Error`. Cause: No network proxy configured for `STORAGE_S3_ENDPOINT`. The internal storage network segment of the new energy development business is isolated from external vector database services. Without a proxy, business documents cannot be synchronized.
- Symptom: The business process guidance reply only outputs Chinese, even when an English prompt and English compliance knowledge base are configured. Cause: The model's output language parameter is not specified. The default loaded Chinese embedding model preferentially matches Chinese corpus, causing the English prompt to fail to trigger the expected English output.
- Symptom: Uploaded project construction logs fail to parse, with the interface displaying `File parsing failed`. Cause: No valid key is set for `FILE_TOKEN_KEY`, causing uploaded documents to fail permission verification and cannot be read and parsed by the system.

## How to confirm the configuration is correct

- Access the business process guidance interface corresponding to `FE_DOMAIN`, upload a small new energy project document, and check whether it can be parsed normally and display the material list for the corresponding approval step.
- Check the system background logs to confirm that the `REDIS_URL` and `DB_MAX_LINK` configuration parameters have taken effect, with no connection timeout or parameter over-limit errors.
- Send an English prompt to test the model's output, confirm that the reply language matches the prompt requirements, and conforms to the English compliance document matching logic of the knowledge base.
- Run the built-in database connection test tool to verify that the read-write permissions of `MONGODB_URI` are normal, and can synchronously update the status data of the business process.
