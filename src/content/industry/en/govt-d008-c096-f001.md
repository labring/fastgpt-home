# Business Process Guidance for Non-Ferrous Metal Smelting: HTTP Interfaces and External Systems

## What the data for this category looks like
Non-ferrous metal smelting business data originates from internal production systems including Manufacturing Execution System (MES), Energy Management System (EMS), and Quality Management System (QMS). Real-time process parameters such as smelting temperature and furnace pressure update every 10 seconds. Batch quality inspection data updates synchronously upon completion of each smelting batch. Monthly production ledgers are synced to the knowledge base daily. Each data entry includes batch ID, material code, process node name, collected value, collection time, and test result. Field units include degrees Celsius, kilopascals, cubic meters per hour, tons, and milligrams per kilogram.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
The high-frequency updates of real-time process parameters require interface call intervals to match the collection frequency, to avoid displaying lagging data during business process guidance. Heterogeneous data sources from multiple systems require the interface to support filtering queries by batch and process node, to reduce invalid data transmission. Fields with non-standard units require the interface to return data with standard unit identifiers, to facilitate matching between the knowledge base and business terminology. The strong association of batch data requires the interface to support batch associated queries, to reduce the number of external system calls and improve the overall efficiency of process guidance.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {Enterprise-specific API key}` | Non-ferrous metal smelting production data is sensitive business data. Bearer tokens must be used for authentication to ensure data transmission security |
| `variables` | `{"batchId": "Target smelting batch number", "queryNodes": ["batching", "smelting", "casting"]}` | Filter data by smelting batch and process node, accurately match the query needs of business process guidance, and reduce invalid returned data |
| `responseData` | `Return only collected value, collection time, and unit fields` | Reduce the size of interface returned data, lower the parsing load of the knowledge base, and improve the response efficiency of process guidance |
| Interface timeout period | `60 seconds` | Associated data needs to be pulled across multiple production systems. A longer timeout period can avoid call interruptions caused by network fluctuations |
| Maximum number of returned entries per request | `First 100 entries` | The amount of collected data for a single smelting batch is large. Limiting the number of returned entries avoids interface overload and ensures call stability |

## Three common mistakes
- Issue: Interface returns 401 Unauthorized error. Cause: The `Authorization` parameter is not configured correctly, or an expired API key is used.
- Issue: Business data returned after calling the interface does not match the actual process. Cause: The correct smelting batch number or process node is not specified via the `variables` parameter, resulting in returned data from unrelated batches.
- Issue: Interface call times out. Cause: The interface timeout period is not set reasonably, and concurrent optimization is not performed for multi-system data pulling, leading to overly long request waiting time.

## How to confirm the configuration is correct
- Invoke the test interface. Verify the returned HTTP status code is 200, and confirm the authentication configuration is effective.
- Review the returned `responseData` field. Confirm only the preset collected value, collection time, and unit fields are included, with no redundant data.
- Submit a known smelting batch number. Verify the batch ID of the returned data matches the `variables` parameter entered, and confirm the filtering logic is effective.
- Invoke the interface three consecutive times. Check that the response time stays within the range required by the business, and confirm the timeout configuration is reasonable.
