# Business Process Guidance for Non-Ferrous Metal Smelting: Vector Models and Indexing

## What this category of data looks like
The business process handling data for non-ferrous metal smelting comes primarily from internal MES production systems, process archives from OA office systems, and on-site sensor-collected node operation data. Data update follows two patterns: real-time collected process node data updates every 10 seconds, while work order data is archived after each production shift. Each document includes fields such as handling link ID, link name, prerequisites, required material list, handling window address, and consultation phone number. Units include hours, copies, furnace numbers, and similar units, with no additional statistical percentage content.

## What constraints these characteristics impose on the vector models and indexing link
The mixed structure of real-time and archived data requires the indexing system to support hot and cold data tiered storage, to prevent full indexing from consuming excessive resources. The hierarchical association of process links requires retaining context from preceding and following steps during chunking, to avoid breaking the descriptive logic of prerequisites. The coexistence of structured fields and unstructured text requires separate vectorization rules for each data type during indexing, to prevent confusion between professional terminology and general text. Frequently updated real-time data needs an incremental synchronization mechanism, to reduce how often full indexing triggers.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale for this value |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the typical length of a single smelting process link description, avoids breaking business logic by chunking across links |
| Overlap Length | 100–200 characters | Retains the preceding and following association information of process nodes, ensures that prerequisites descriptions are not cut off by chunking |
| Similarity Threshold | 0.7–0.9 | Filters low-match non-smelting process content, adapts to semantic matching accuracy for professional terminology |
| Single Search Limit | Top 8 entries | Adapts to the single information volume requirement of business process guidance, avoids returning excessive redundant results |
| `defaultToken` | 4096 | Matches the input token limit of mainstream domestic embedding models, adapts to the vectorization requirements of long process documents |
| Maximum Context | 6000 characters | Retains the complete handling process chain, ensures that AI can output coherent step-by-step guidance |

## Three common configuration errors
- The knowledge base remains in the indexing state for an extended period after importing the smelting process dataset. This occurs when incremental index synchronization rules are not configured, and full indexing processes a large volume of historical work order data, leading to long run times.
- Search returns abnormally high similarity values outside the 0-1 range. This happens when no similarity threshold filtering is applied, and raw model output results are used directly for matching.
- Key links are missing from returned process guidance. This occurs when chunk length is set too short, splitting complete process steps into multiple unrelated text chunks.

## How to confirm correct configuration
- Import a typical smelting business handling work order test document, wait for indexing to finish, and confirm the interface shows indexing status as completed.
- Enter a specific smelting business handling query, check that returned similarity scores fall within the 0-1 range, and that matching results align with business logic.
- Adjust the chunk length parameter, reindex a small batch of test data, and verify that chunked text retains complete process link descriptions.
- In the FastGPT v4.17.0 configuration panel, confirm all setting values match the preset plan.
