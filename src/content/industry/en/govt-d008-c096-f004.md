# Business Process Guidance for Non-Ferrous Metal Smelting: Workflow Orchestration

## What the data for this category looks like
Non-ferrous metal smelting business data mainly comes from the internal enterprise manufacturing execution system (MES), warehouse management system (WMS), and quality inspection laboratory system. Data update rhythms fall into two categories: real-time production parameters refresh every 2-10 minutes, batch quality inspection reports are generated upon completion of smelting batches, and equipment operation logs are generated in real time based on operation records. Data is stored in structured table format with fixed fields: smelting batch ID, raw material ratio (unit: kilograms per furnace), smelting temperature (unit: degrees Celsius), output metal ingot weight (unit: kilograms), equipment operating duration (unit: hours). There are no unstructured redundant fields.

## What constraints these characteristics impose on the "workflow orchestration" link
Different data sources have different update rhythms, requiring differentiated trigger rules for workflow node configuration. Real-time production data nodes use short polling cycles, and batch quality inspection data nodes bind to batch completion event triggers. The fixed fields of structured data mean variable extraction rules in the workflow must match preset field names to avoid matching failures. A single batch has an upper data processing limit, so the workflow splits processing units to prevent single execution timeouts. Minor data format differences exist across systems, so format conversion steps are added during workflow orchestration to unify field units and types.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Interval | 2-10 minutes | Matches the refresh rhythm of real-time production data |
| `variables` extraction rules | Match preset smelting batch ID and raw material ratio fields | Adapts to the fixed field structure of structured data |
| Batch Processing Unit Size | 50 items per execution | Avoids exceeding system resource limits in a single execution |
| Debug Node Display Toggle | Enabled | Meets the debugging function requirements of FastGPT v4.17.0 |
| `nodeId` mapping rules | Retain the original node ID of the imported workflow | Ensures correct node call logic for nested workflows |

## Three common mistakes
- Symptom: After the workflow is executed, the global Number type counter does not increment as expected, and there is no change after variable updates. Cause: The update trigger logic for `variables` is not configured correctly, and only the variable reading node is called without binding the update operation.
- Symptom: In the FastGPT v4.17.0 workflow debugging panel, the code running node shows no content. Cause: The debug node display toggle is not enabled, or the workflow has not saved the latest configuration.
- Symptom: The output of the nested called sub-workflow meets expectations, but the field values in the intermediate steps do not match the parameters passed in by the parent workflow. Cause: The `variables` mapping rules of the sub-workflow are not correctly bound to the output fields of the parent workflow, resulting in misplaced parameter transmission.

## How to confirm the configuration is correct
- Manually trigger the workflow once, and check whether the extracted variable results in the log completely match the fields of the data source.
- Adjust the trigger interval to different ranges, and verify whether the workflow triggers the updated data of the corresponding data source according to the set rhythm.
- Execute the nested workflow call, and check whether the input parameters of the sub-workflow match the output fields of the parent workflow.
- Enable debug mode, and confirm that the execution logs of the code running node are normally displayed in the debugging panel.
