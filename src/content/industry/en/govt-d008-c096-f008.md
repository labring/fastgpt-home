# Business Process Guidance for Non-Ferrous Metal Smelting: Document Parsing and Chunking

## What the data for this category looks like
Documents related to business processing for non-ferrous metal smelting come primarily from three sources: production logs, quality inspection reports, process specifications, and approval process documents. Data is updated per production shift or daily. Monthly summary documents can reach tens of thousands of characters. Document structures include multi-column material ratio and energy consumption statistics tables, embedded process flow charts, and on-site quality inspection photos. Some log documents for business processing workflows include HTTP interface response messages. Fields include smelting batch number, metal grade, unit energy consumption, emission indicators, with corresponding units such as %, kilowatt-hours per ton, milligrams per cubic meter, and others.

## What constraints do these characteristics impose on the document parsing and chunking link
Multi-column table structures cause default chunking to split cell content across columns, breaking the binding between materials and their corresponding grade or energy consumption values. Large-capacity long documents require longer parsing timeouts, otherwise parsing interruptions may occur. The binding between embedded images and their text descriptions cannot be fully extracted by default parsing, leading to separation of business process step descriptions and corresponding process diagrams. For documents containing HTTP response messages, default parsing does not perform structured extraction for Set-Cookie and other response header fields, so complete business approval interface interaction information cannot be retained. High-frequency documents updated daily require fast parsing configurations to avoid impacting real-time guidance of business processing workflows.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 1000–1500 characters | Matches the single-batch data block length of monthly smelting reports, avoids splitting associated content of process steps |
| `chunkSplitter` | By paragraph + table boundary | Adapts to the structure of multi-column material ratio tables, retains the binding relationship of data between columns |
| `customPdfParse` | Enabled | Extracts associated text descriptions of embedded process flow charts and on-site quality inspection photos in PDFs, enabling image-text binding |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Adapts to the parsing time of large-capacity monthly production summary documents, avoids timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Supports complete upload of single-batch monthly production logs, covering complete business data |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for multi-column tables and long documents, matches the step association logic of business processing workflows |

## Three common errors
- When attempting to parse the Set-Cookie field of HTTP interface response messages, the field content is empty or cannot be extracted. The cause is that default document parsing does not perform structured processing for response header fields, and the code execution module cannot directly call external interfaces to obtain complete messages.
- After uploading a document with a multi-column material ratio table, the parsed result shows disordered column data. The cause is that the chunking rule by table boundary is not configured, and default chunking splits cell content associated across columns.
- After uploading a PDF, the parsed images do not include storage location descriptions, making it impossible to obtain the corresponding storage path of the images. The cause is that the `customPdfParse` configuration is not enabled, and default parsing only extracts plain text content without recording image storage association information.

## How to confirm the configuration is properly set
- Upload a test document containing a multi-column material ratio table, and check whether the parsed chunks retain the column-associated data of each row
- Upload a test document containing HTTP interface response messages, and check whether the complete content of the Set-Cookie field is extracted in the parsed results
- After enabling `customPdfParse`, upload a test PDF with a process flow chart, and check whether both the image and its corresponding text description are displayed in the parsed results
- Upload a test document with a capacity of 400 MB, and check whether parsing completes within 180 seconds without timeout errors

The values listed above are common starting points and should be evaluated against the user's own samples.
