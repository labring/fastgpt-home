# Business Process Guidance for Non-Ferrous Metal Smelting: Model Access and Configuration

## What the Data for This Category Looks Like
Data mainly comes from smelting production execution systems, material management systems, and output files from quality inspection and testing equipment. Update frequency is per shift or per day. Documents are primarily structured tables and industrial database records, containing fields such as smelting batch number, process temperature, material weight, quality inspection indicator values, and operation timestamps. Most field units are degrees Celsius, tons, hours, milligrams per liter, and similar units. Some supporting process documents are fixed-format PDF files, with content covering full-process operation specifications for a single batch of smelting.

## Constraints Imposed on Model Access and Configuration
This document is written based on FastGPT v4.17.0.
Many structured data fields use diverse units. Configure parameters compatible with multi-unit recognition during model access to avoid parsing errors.
Data updates occur frequently. Model calls must support real-time or near-real-time data source pulling, which sets clear requirements for interface timeout settings.
Some supporting process documents use fixed formats and have long lengths. The model context window must support long-text processing. Configure reasonable context truncation rules to prevent exceeding the model's capacity limits.
Smelting data from different batches has strong correlation. Configure parameters to retain batch-related context during model calls to avoid gaps in process guidance.

## How to Set the Configuration
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | After combining smelting process documents and batch data, the context length for a single batch falls mostly within this range, and it is compatible with the context windows of most mainstream models |
| `maxTokens` | `2000–3000 token` | Process guidance replies must include complete steps, while avoiding excessive length that causes interface timeouts |
| `temperature` | `0.2–0.4` | Process guidance must maintain rigor, avoiding randomly generated step deviations |
| `quoteMaxToken` | `4000 token` | Retain sufficient quality inspection data and process parameters as reference basis to ensure the accuracy of process guidance |
| `AIPROXY_API_ENDPOINT` | Fill in the official access address of the corresponding model proxy | Establish a correct call link between FastGPT and the model proxy platform |
| `AIPROXY_API_TOKEN` | Fill in the valid proxy key obtained through application | Complete identity verification and pass the model access verification process |

## Three Common Misconfigurations
- The symptom is that the model works normally when tested on a third-party proxy platform, but an error occurs when testing a newly created application in FastGPT. The cause is that `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is not configured correctly, preventing FastGPT from completing valid identity verification with the proxy platform.
- The symptom is that knowledge base queries prompt "no matching content" or similar truncation errors. The cause is that the configured embedding model does not match the actually called model, or model access parameters are not configured correctly, leading to failure to properly parse smelting data field information.
- The symptom is an error of the type "KokoroModel object has no attribute mode" during TTS model testing. The cause is that the `toolChoice` parameter is not adjusted for TTS-type models, or the correct model type is not specified during model access, causing the framework to fail to recognize the corresponding model's call logic.

## How to Confirm Successful Configuration
- Navigate to the FastGPT model management page, view the configured model access information, and check whether `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the information provided by the proxy platform.
- Initiate a process guidance test for a single smelting batch data set, and check whether the returned result includes complete processing steps and no parameter parsing errors.
- Upload a standard smelting process document, test the linkage effect between knowledge base recall and process guidance, and confirm that the referenced content matches the actual data.
- Adjust the `temperature` parameter and initiate multiple tests, observe the consistency of the reply content, and confirm that the parameter configuration takes effect.

The values provided here are common starting points, and should be evaluated against the samples relevant to the specific deployment.
