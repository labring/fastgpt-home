# Non-ferrous Metal Smelting Business Process Guidance: Forms and Interaction

## What this category of data looks like
Non-ferrous metal smelting business data comes from three types of systems: production DCS control systems, raw material warehouse ledgers, and finished product quality inspection reports. Production process parameters are updated every 15 minutes. Batch quality inspection data is updated synchronously with each furnace run. The standard document structure includes fields such as raw material batch identifier, smelting temperature, smelting duration, target finished product metal content, energy consumption record, and circulation node number. Temperature is measured in degrees Celsius, duration in hours, metal content in grams per kilogram, and energy consumption in kilowatt-hours.

This configuration guide applies to FastGPT v4.17.0.

## Constraints imposed by these characteristics on forms and interactions
Real-time updated process parameters require forms to dynamically load the latest reasonable range reference values, and static fixed options must not be used. Batched circulation data requires forms to bind a unique batch identifier field to prevent cross-batch data confusion. Fields with professional units need built-in unit validation capabilities to avoid invalid data caused by incorrect user input. Multi-node circulation processes require forms to support node status checkbox selection, which matches the multi-stage approval logic of smelting business.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Form input validation rules | Bind field units and reasonable data ranges, e.g., smelting temperature limited to 800-1600 degrees Celsius | Smelting process parameters have fixed reasonable ranges to avoid invalid inputs |
| Variable binding settings | Associate raw material batch number and quality inspection report ID | Smelting data circulates by batch, unique identifiers must be bound to avoid data disorder |
| Input box type selection | `formInput` with unit suffix, `userSelect` for circulation node selection, date input boxes for time node recording | Professional fields require unit validation, circulation nodes require fixed options to reduce errors, time nodes require standardized date formats |
| Submission timeout setting | 600 seconds | Smelting batch data volume is large, batch submission requires longer response time |
| Batch submission limit | First 10 entries | Matches single furnace or single batch processing scale, avoids exceeding system processing limits |

## Three Common Mistakes
- Phenomenon: Some required fields prompt as empty after submission. Cause: Required validation for core fields such as batch number and process parameters was not configured, leading users to miss key identifiers for the smelting process.
- Phenomenon: System variables cannot be inserted into the JSON input box. Cause: The input box was not configured as the `formInput` type that supports variable calls, or variable insertion permission was not enabled.
- Phenomenon: The date input box cannot automatically fill in planned dates. Cause: The variable data source of the production plan was not bound, leading to manual date entry and increased format error risk.

## How to Verify Proper Configuration
- Manually enter content that does not match the set unit, check if the corresponding validation prompt pops up.
- Try inserting preset batch variables into the JSON input box, confirm they can be called normally and generate valid JSON format.
- Click the date input box, select a preset planned date, check if the correct formatted date content is automatically filled.
- Submit a single test data entry, check if the returned result correctly associates the corresponding batch identifier and process parameters.
- Submit batch data exceeding the set limit, check if the system triggers the submission limit prompt message.

The values provided here are common starting points and should be measured against the reader's own samples.
