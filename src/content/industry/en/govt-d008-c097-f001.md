# Business Process Guidance for Nuclear Power Operations: HTTP Interfaces and External Systems

## What this category of data looks like
Nuclear power operation business process data is mainly sourced from on-site operation logs, safety approval documents, equipment inspection ledgers, and business work order systems. Data updates are triggered along business process nodes, and synchronized once a single process is completed. The document structure includes fields such as process node number, process step serial number, required declaration material list, approval authority scope, and processing time limit requirements. Field units are mostly digital serial numbers, hours, days, MB, etc., with no deeply nested complex structures.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
The node-triggered update feature of nuclear power operation business data requires HTTP interfaces to support on-demand pull requests, to avoid redundant requests occupying system resources. Data includes approval authority and processing time limit fields. Interface requests must carry authority verification parameters, and timeout settings must match the conventional time limits of business processes. The standardized structure of document fields requires interface request parameters and response fields to strictly correspond to preset business node fields, to avoid field parsing errors. Business material storage requirements require interfaces to support MB-level file transfer configurations.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authorization | Bearer {custom secret} | Matches the authority verification requirements of nuclear power business data, to prevent unauthorized access |
| variables | Includes node number, approver authority | Corresponds to the field requirements of business process guidance, enabling on-demand pull |
| responseData | Extract the first 10 process step entries | Adapts to the conventional number of steps in a single nuclear power business process, reducing invalid data transfer |
| Interface timeout period | 300–600 seconds | Matches the conventional approval time limits of nuclear power business processes, avoiding early timeout interruptions |
| Single request data volume | Within 1000 MB | Adapts to the conventional storage size of business materials, meeting file transfer requirements |
| Request trigger method | Triggered by business node events | Matches the node update feature of nuclear power data, avoiding invalid pull requests |

## Three Common Mistakes
- Interface request timeout errors, with status code 504 or requests being actively interrupted. Cause: The default timeout setting is 300 seconds, which does not match the actual time limit requirements of nuclear power business processes.
- Response field parsing returns empty, and business process step data cannot be obtained. Cause: The variables parameter is not correctly bound to the business node number, resulting in the interface pulling an incorrect data set.
- Custom retrieval quantity configuration does not take effect, and the number of retrieval results does not meet expectations. Cause: The return data quantity limit in the external system interface is not adjusted synchronously, resulting in the configuration not being actually applied.

## How to Confirm Configuration Is Complete
- Call the configured HTTP interface, check whether the request header contains correct Authorization verification information.
- Pass the preset business node number as the variables parameter, check whether the returned responseData includes the step data of the corresponding process.
- Extend the timeout period to 600 seconds, initiate a simulated business process request, and confirm that the request is not interrupted early.
- Adjust the single request data volume limit, upload a test file, and confirm that the transfer is not truncated or reports errors.
