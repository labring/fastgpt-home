# Business Process Guidance for Nuclear Power Operations: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Nuclear power operation business process data is mainly sourced from on-site operation instructions, business process regulations, equipment ledgers and approval forms. Data updates occur alongside annual compliance revisions, major technical transformation completions, or business process optimization adjustments. Documents are split into chapters by business nodes, and include process number, responsible post code, approval time limit, compliance clause number, and other fields. The unit for approval time limits is working days, and process numbers use a fixed format combining letters and numbers.

## Constraints Imposed by These Characteristics on the Multi-turn Dialogue and Prompt Engineering Link
Nuclear power business documents contain dense professional terminology and are split into chapters by node. Multi-turn dialogue tracks the current process node to avoid off-step guidance. Data update frequency is not fixed, and the knowledge base synchronizes after revisions. Prompt engineering incorporates version verification logic to ensure the latest content is called. Fields that bind post codes to exclusive processes require dialogue context to match the permission scope of the current operating post. Individual chapter documents are lengthy, so total context length is limited to avoid exceeding the model's processing upper limit.

## Three Common Misconfigurations
- When calling the API to initiate a dialogue, the system returns the prompt "no answer found", but an image document containing process steps has been uploaded to the knowledge base. The cause is that OCR parsing rules for image content have not been configured, and only text content is retrieved, resulting in matching failure.
- The system displays the error "no permission to operate this dialogue record" during the session. The cause is that the permission identifier of the current operating post has not been bound via `chatId`, and non-authorized session data is called across posts.
- Consecutively sending two dialogue requests with a very short interval results in the latter request not receiving an immediate response. The cause is that the number of concurrent sessions has not been limited, and system queuing processing causes delays.

## How to Verify Proper Configuration
- Upload an image document containing nuclear power business process steps, initiate a query for the corresponding content, and verify that matching process guidance information is returned.
- Use accounts of different posts to initiate queries for the same process, and verify that only authorized posts can view exclusive data for the corresponding process.
- Send 2 to 3 consecutive dialogue requests, and verify that each request receives an immediate response with no obvious queuing delay.
- Review dialogue-generated content, and verify that the referenced regulation version matches the latest updated version of the knowledge base.
