# Business Process Guidance for Nuclear Power Operations: Tool Calling and Plugins

## What the Data for This Category Looks Like
Business process data for nuclear power operations originates from nuclear power operation management systems, equipment operation ledgers, and business approval platforms. Updates are delivered in real time or synchronized at minute-level intervals. Each individual data entry includes fields for business number, operator employee ID, processing time, approval node, associated equipment ID, and current status. Units include counts, units, hours, minutes, and similar standard units. Data is formatted as structured JSON, and some fields must follow standardized coding rules for the nuclear power industry.

## Constraints These Characteristics Impose on Tool Calling and Plugins
Real-time or minute-level updated data requires that tool calling response times stay within a reasonable range, to prevent data lag from reducing the accuracy of business guidance. Structured fixed fields require that plugins preset standard parsing rules for nuclear power business processes, and cannot directly adapt to general business field templates. Linear multi-node business processes require that tool calls be triggered in process order, and cross-node calls are not permitted. Standardized coding rules require that plugins automatically complete field formats when calling external interfaces, to prevent call failures caused by coding mismatches.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapt to dynamic node changes in nuclear power business processes, and automatically trigger corresponding tools |
| `functionCall` | Allow multiple consecutive rounds of calls | Match the coherent guidance requirements for multi-step business processing |
| Timeout Setting | 600 seconds | Cover the average processing duration of nuclear power business processes |
| Plugin Trigger Frequency | 1 time per 30 seconds | Match the minute-level data update rhythm |
| Context Window | 8000–12000 token | Accommodate complete business records and process node information |
| Plugin Name Synchronization | Fill the display name according to the code identifier | Avoid inconsistent names between the management interface and the calling end |

## Three Common Configuration Mistakes
- Symptom: Parameter parsing failure is returned when calling `functionCall`, and logs show field format mismatch. Cause: The field coding rules of the nuclear power industry are not followed, and standard prefixes are not added to the passed equipment ID or business number.
- Symptom: The display name shown on the plugin management list page and in the system plugin is inconsistent. Cause: Only the code identifier was filled when configuring the plugin, and the display name was not set synchronously.
- Symptom: Business guidance does not call the knowledge base to return historical process data. Cause: The automatic call switch for `toolChoice` is not enabled, and only basic question-and-answer logic is used to generate guidance content.

- Trigger a timeout test scenario, and confirm that the call response duration meets the configured 600 second threshold.
