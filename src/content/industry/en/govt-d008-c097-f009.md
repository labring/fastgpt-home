# Nuclear Power Operations Business Process Guidance: Model Access and Configuration

## What the data for this category looks like
Data sources for this category include nuclear power operation work orders, on-site work procedures, approval process ledgers, and compliance inspection records.
Update schedule: Work order data is synced in real time. Procedure documents are updated quarterly or as required by compliance regulations.
Document structure includes structured work order fields (process ID, node name, approval time limit, responsible team) and unstructured procedure text (step descriptions, safety requirements).
Field units are typically hours, items, copies, team numbers, and similar. There are no vague fields common to general business scenarios.

## What constraints these characteristics impose on model access and configuration
The above data characteristics impose multiple constraints on model access and configuration.
Structured work order data requires clear field mapping rules to avoid deviations in process node matching.
Unstructured long procedure text needs sufficient context processing capability to prevent key steps from being truncated.
Frequently updated work order data requires configured scheduled synchronization tasks to ensure real-time data source availability for model calls.
Nuclear power business compliance requirements strictly limit model output deviations, while ensuring sensitive data is not leaked.
Fixed business process nodes require models to prioritize matching preset process logic when called, to adapt to standardized handling processes.

## Three common configuration mistakes
- Symptom: A "context limit exceeded" error is returned when running the process guidance workflow, with status code 413 displayed on the interface. Cause: The `maxContext` parameter was not adjusted for nuclear power long documents, and the default value is too small to accommodate complete business procedure fragments.
- Symptom: The semantic retrieval matching score of the knowledge base is 0.77, but the model prompts that no relevant information is available. Cause: The `quoteMaxToken` setting is too short, and the retrieved procedure fragments are truncated, making them unrecognizable as valid matching content by the model.
- Symptom: The workflow response times out. Cause: The `maxTokens` setting is too large, exceeding the default time limit of API calls, and does not match the real-time response requirements of nuclear power business.
