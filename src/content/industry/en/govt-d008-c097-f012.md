# Business Handling Process Guidance for Nuclear Power Operations: Deployment and Upgrade

## What this category of data looks like
The business handling process guidance data for nuclear power operations comes from nuclear power production operation management systems, operation duty logs, and work order systems. It updates synchronously every 8-hour shift. Data is categorized by business domains such as reactor operation, fuel management, and maintenance approval. Each individual data entry includes fields including work order unique identifier, business type, handling node sequence, responsible position, legal handling time limit, and more. Time limit fields use hours as the unit. Work order status is marked with fixed enumeration values. The entire dataset is stored in a structured format, with all fields matching nuclear industry business specifications.

## What constraints these characteristics impose on the deployment and upgrade phase
The business domain classification attribute of nuclear power operation business data requires that knowledge base classifications be configured as independent modules such as reactor operation and fuel management during deployment. This prevents cross-domain data confusion. Following the 8-hour shift update rhythm, the trigger cycle of scheduled synchronization tasks must be aligned with the shift schedule. This avoids data synchronization delays or repeated data pulling that occupies resources. Fields include industry-specific fields such as legal handling time limits. During deployment, mapping configuration between system fields and business data fields must be completed. This ensures the process guidance can read compliant time limit parameters. At the same time, nuclear power business data has high sensitivity. During deployment, storage endpoints that meet cybersecurity classification protection requirements must be specified. This avoids data leakage risks.

## Three Common Mistakes
- A configuration error prompt displays when entering the workflow, and business node data fails to load. The cause is incorrect configuration of `STORAGE_S3_ENDPOINT` or insufficient storage permissions, resulting in failure to properly read process documents.
- After deployment, login to the system fails, with a prompt of incorrect username or password. The cause is incorrect setup of `ROOT_KEY` or incorrect account password configuration in the database connection parameter `MONGODB_URI`, resulting in permission verification failure.
- When deploying on Mac devices, a path error occurs after starting the container with Docker Desktop. The cause is that the Docker Desktop file mount path does not match the configuration path inside the container. Use OrbStack to complete container deployment and mounting.

## How to Confirm Configuration is Complete
- Run the database connection test command to verify that the configurations of `MONGODB_URI` and `REDIS_URL` can establish normal connections.
- Access the address bound to `FE_DOMAIN` to confirm that the page loads normally and no permission error prompts appear.
- Trigger a business data synchronization task, and check that there are no connection exhaustion or permission abnormality prompts in the synchronization log.
- Upload a nuclear power business process document to verify that the storage service configured with `STORAGE_S3_ENDPOINT` can normally receive files.
