# Business Process Guidance for Civil Aviation Airports: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Business process guidance data for civil aviation airports is sourced from internal airport flight display systems, check-in scheduling systems, security queue systems, and terminal guidance platforms.
Core flight information updates in real time.
Activation statuses for check-in counters and security lanes sync based on daily flight batches.
Terminal guidance point data updates at fixed daily intervals.
Data is formatted as structured JSON. It includes fields such as flight number, takeoff and landing time, current operational status, corresponding service point number, and estimated queue duration.
Time fields use the ISO 8601 standard format.
Queue duration is measured in minutes.
Point numbers use the string data type.

## Constraints for HTTP Interfaces and External Systems
The real-time update nature of flight data requires HTTP interfaces to use reasonable response timeout thresholds. This prevents guidance information from lagging behind actual flight status changes.
Fixed structured JSON fields require all preset mandatory fields to be included in interface responses. Missing fields will cause breaks in the process guidance logic.
Service point data synced per daily flight batches requires interface requests to include flight date as a core query parameter. This ensures accurate retrieval of available resources for the target time period.
Guidance point data updated at fixed daily intervals can be cached to reduce interface call frequency. This lowers the load on internal airport systems.

## How to Set Configurations
This page applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {airport internal API key}` | Internal airport business interfaces typically use Bearer token authentication to ensure legitimate call permissions. |
| `variables` | Include business parameters such as flight date and passenger type | Align with the query logic of airport systems to accurately retrieve service data for the target time period. |
| `responseData` | Return only a subset of fields including flight number, queue duration, and gate number | Reduce invalid data transmission and speed up interface response times. |
| Cache period | 600 seconds (real-time flight data), 86400 seconds (point data) | Match the update rhythm of airport data, balancing information timeliness and system load. |
| Timeout threshold | 300 seconds | Prevent business process lag caused by interface delays, calibrated based on actual testing. |
| Data format validation | Strictly match the JSON structure agreed upon by airport interfaces | Avoid call failures caused by mismatched field types. |

## Three Common Mistakes
- Phenomenon: An interface call returns a 401 Unauthorized status code, and business data cannot be retrieved. Cause: The `Authorization` parameter is not configured correctly in Bearer format, or the key has expired or become invalid.
- Phenomenon: Business form fields rendered by external platforms are empty or use incorrect formatting. Cause: Request parameters are not passed in accordance with the JSON structure agreed upon by the airport interface. This leads to failed parsing of the guidance data returned by the interface.
- Phenomenon: Queue duration data in the business process guidance does not match the actual terminal situation. Cause: The cache period is set incorrectly, and does not match the update rhythm of real-time flight data from the airport.

## How to Verify Successful Configuration
- Call the configured HTTP interface, and verify that the returned JSON data includes all preset core business fields.
- Compare the queue duration data returned by the interface with actual on-site airport conditions, and adjust the cache period to fit business requirements.
- Simulate requests with different flight dates and passenger types, and confirm that the interface returned data matches the request parameters.
- Check whether the authentication parameter format complies with the requirements of internal airport systems, to avoid unauthorized errors.
