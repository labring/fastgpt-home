# Civil Aviation Airport Business Process Guidance: Forms and Interactions

## What the data for this category looks like
Terminal check-in systems, flight operation control platforms, and public service terminal databases provide business process data for civil aviation airports. Two update schedules apply: flight dynamic information synchronizes every 5 minutes, and general processing process rules update daily. The document structure splits by processing scenarios. It includes fields such as processing type, corresponding flight information, required verification materials, processing node sequence, and estimated waiting time. Common field units include minutes, passenger count, document type identifiers, and other standard units.

## What constraints these characteristics impose on forms and interactions
The forms and interactions link must support dynamic data source pulling to handle real-time flight dynamic data updates. Fixed static options cannot be used. Differences in general processing scenarios require interaction components to support custom node configuration. This adaptation supports varying processing rules across terminals and airlines. Variations in units across multiple fields require form input components to support different data formats. Duration fields must restrict input to numeric values. Document type fields must provide preset options and support expansion. The interaction link must synchronously display updated estimated waiting time information to prevent lag.

## Three common mistakes
- Phenomenon: A user inputs the text "share", and after invoking the tool, the returned text is an incorrect character sequence. Reason: Automatic correction or word segmentation rules for input text have not been configured, leading to character recognition deviation during text flow.
- Phenomenon: When selecting a knowledge base in custom input, options appear empty or cannot be selected. Reason: Data source pull permissions and update cycle have not been correctly configured, causing the knowledge base list to fail to load properly.
- Phenomenon: After entering parameters in the prompt word code block of the "text content extraction" module, the returned result shows the code block as undefined. Reason: The variable from the `formInput` input has not been correctly bound to the parameter entry of the extraction module, resulting in the parameter not being passed normally.

## How to confirm the configuration is complete
- Submit simulated form data, check whether the interaction component displays the corresponding input box or selection options as preset.
- Manually trigger data source pulling, confirm that the returned flight information matches the real-time data from the airport operation system.
- Test the document type selection function, confirm that the preset options cover commonly used travel documents.
- Enter test text, check whether the returned result matches the input content after tool invocation.
