# Business Process Guidance for Oil and Gas Exploration and Development: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Data sources for oil and gas exploration and development include seismic survey acquisition data, well logging operation data, real-time drilling site data, and reservoir simulation reports.
Update frequency follows project phases. Updates occur every few days during the exploration phase, and daily on demand during the development phase.
Documents contain both structured fields and unstructured text. Structured fields include well ID, logging depth, and acoustic interval transit time. Units include meters, ohm-meters, microseconds per meter, and others. Some data uses binary format, such as SEG-Y seismic data. Unstructured text includes long-form content such as drilling logs and well test reports.

## Constraints on Multi-turn Dialogue and Prompt Configuration
Oil and gas exploration and development data has both structured and unstructured formats, uses specialized units and binary formats, and updates based on project phases. These traits create multiple constraints for multi-turn dialogue and prompt configuration.
Structured fields require explicit unit and value range specifications in prompts to avoid ambiguity between units for fields such as depth and resistivity.
Binary seismic data cannot be directly embedded into dialogue context. Prompts must guide calls to document parsing tools to transcode data and extract metadata.
Phase-based data updates require adding time range validation in multi-turn dialogue. This ensures only valid data for the current project phase is used.
Business process guidance requires step-by-step collection of key parameters such as well ID and operation type. Prompts must use layered guidance logic to avoid requesting too much information at once.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Window | `8000–12000 token` | Single blocks of oil and gas exploration and development documentation are lengthy. This range retains sufficient multi-turn dialogue history while staying within FastGPT v4.17.0 model limits |
| Question Optimization | Enabled | Exploration data fields are complex. Optimization enables more accurate extraction of key information such as well IDs and depths from user inputs |
| Single Recalled Entries | `Top 6` | Exploration data has high relevance. Too many recalled entries increases context burden, while too few may miss critical information |
| `variables` | Predefine business variables such as well ID and operation type | Oil and gas exploration and development business processes require fixed core parameters. This reduces repeated questions during multi-turn dialogue |
| `chatId` | Bind to project ID | Dialogues for the same exploration project must share context to avoid mixing data across projects |
| `messages` | Retain the most recent 10 dialogue turns | Exploration business processes have multiple steps. This retains previously confirmed parameter information |

## Three Common Misconfigurations
- Symptom: SEG-Y seismic data or drilling logs uploaded via the dialogue interface cannot be read, but the same files uploaded to the knowledge base backend can be retrieved normally. Cause: Files uploaded via the dialogue interface do not use dedicated document parsing configuration for oil and gas exploration and development. Generic parsing logic cannot recognize binary seismic data.
- Symptom: Well logging data can be retrieved normally in knowledge base tests, but retrieval results are empty in dialogue. Cause: The project scope parameter in `variables` is not correctly bound during multi-turn dialogue, so the filter condition does not take effect during retrieval.
- Symptom: Calling the dialogue interface returns 404 Invalid URL (POST /api/chat/completions). Cause: The FastGPT API gateway port is not correctly configured during local deployment, or the request path does not match the deployed service address.

## How to Verify Proper Configuration
- Upload a binary seismic data file from an exploration project to the dialogue interface, and check if it can be parsed normally and metadata can be extracted.
- Enter a query that includes a well ID and depth range, compare the consistency between the knowledge base backend retrieval results and the dialogue return results, and adjust the recalled entries configuration as needed.
- Initiate a multi-turn dialogue for parameter confirmation, and check if the project ID bound to `chatId` always associates with the same context.
- Call the official test interface to verify that the `/api/chat/completions` path can respond to requests normally.

The values provided here are common starting points and should be evaluated against the reader’s own samples.
