# Business Process Guidance for Oil and Gas Exploration and Development: Workflow Orchestration
This document is written based on the workflow orchestration features of FastGPT v4.17.0. It organizes specific configurations, parameters, and failure handling rules for the business process guidance scenario in the oil and gas exploration and development field.

## What This Category of Data Entails
Oil and gas exploration and development data mainly comes from seismic exploration acquisition files, real-time data uploaded by logging tools, drilling operation logs, and development dynamic monitoring reports.
There are two types of data update rhythms: real-time drilling data is synchronized each time an operation is completed. Seismic processing data is updated in batches after a project phase is finished.
Most documents use structured formats, with fields including well ID, logging depth, porosity, permeability, operation timestamp, and more. Depth is measured in meters, permeability in millidarcys, and timestamps use UTC format.

## Constraints Imposed by These Data Characteristics on Workflow Orchestration
The characteristics of oil and gas exploration and development data impose multiple constraints on workflow orchestration:
- The high-frequency synchronization of real-time drilling data requires workflow trigger intervals to align with the operation rhythm. This avoids long polling cycles that prevent timely data synchronization.
- The large number of structured fields with dedicated units requires the variable extraction step in the workflow to accurately match field names and units. This prevents calculation errors caused by unit conversion.
- The need to batch process large-volume seismic data files requires the workflow to be configured with reasonable memory and timeout thresholds. This avoids node execution interruptions.
- The multi-source data updated in project batches requires the workflow to support grouping and routing by project ID. This prevents cross-project data confusion.

## Configuration Settings
The following table lists configuration items, recommended values, and their rationales:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Node Trigger Interval | 150–300 seconds | Matches the update rhythm of real-time drilling data, avoiding data lag or resource waste |
| `variables` Configuration | Bind field mappings such as well ID and logging depth | Aligns with structured field naming conventions for oil and gas exploration data to ensure accurate extraction |
| File Processing Memory Threshold | 1000 MB | Meets processing requirements for large-volume seismic data, avoiding node execution interruptions |
| Timeout Period | 600 seconds | Accommodates processing time for large-volume data, preventing automatic node termination |
| Workflow Grouping Rule | Group by project ID | Adapts to batch update characteristics of multi-project data, preventing cross-project data confusion |
| `nodeId` Configuration | Bind dedicated operation nodes | Distinguishes workflow instances for different exploration operations, avoiding node conflicts |

## Three Common Misconfigurations
- Phenomenon: Images generated after the workflow calls a charting tool appear empty, only returning the image URL. Cause: The workflow's result rendering node is not configured. Only the URL is returned as text, and the front-end rendering component is not called.
- Phenomenon: A 400 status code is returned when the workflow calls an exploration data interface. Cause: Parameters are not passed in accordance with the field format of oil and gas exploration data. For example, failing to specify the correct well ID or depth unit triggers interface verification failure.
- Phenomenon: After the AI chat node returns empty or an error, the workflow terminates directly with no follow-up processing. Cause: No exception branch node is configured for the workflow. No capture handling is performed for empty results or error statuses.

## How to Verify Correct Configuration
- View the workflow's trigger logs to confirm that the node trigger interval matches the preset adaptation rhythm.
- Test the variable extraction function by inputting structured exploration data, and verify that field mappings and unit matching are correct.
- Upload a large-volume seismic data file, and check the memory usage and timeout status of the file processing node.
- Trigger an exception branch test, simulate a scenario where the large language model returns empty, and verify whether the workflow executes the preset error handling process.
