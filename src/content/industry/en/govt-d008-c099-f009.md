# Business Process Guidance for Oil and Gas Exploration and Development: Model Integration and Configuration

## What the data for this category looks like
Oil and gas exploration and development business process data mainly comes from drilling construction logs, reservoir analysis reports, trial production process records, project approval ledgers, and similar sources. Data update rhythms are adjusted based on on-site construction progress, with batch updates when new wells are put into production or processes are iterated. A single business document typically includes fields such as well location coordinates, formation physical property parameters, construction step lists, and approval node information. Fields have clear units, such as porosity (%), well depth (meters), and permeability (millidarcy). Some process documents also mark time limit requirements for handling nodes. This article is written for FastGPT v4.17.0.

## What constraints these characteristics impose on the "model integration and configuration" link
Professional fields and unit requirements in oil and gas exploration and development require models to have domain term recognition capabilities to prevent parameter parsing errors. Long documents such as complete drilling logs may contain step descriptions spanning thousands of characters, which places demands on the model's context handling capacity. Data updates do not follow a fixed cycle, so on-demand vector library synchronization configuration must be supported to avoid old data compromising the accuracy of process guidance. The multi-node approval logic in process documents requires models to accurately match current handling nodes with the association relationships of subsequent steps. The recall range of context must be clearly defined during configuration to prevent missing key process nodes.

## How to set configuration values
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Adapt to the total length of a single complete drilling log or process ledger, avoiding truncation of key approval node information |
| `maxTokens` | `2000–3000 token` | Control the output length of a single round of interaction, ensuring complete display of process steps without overflowing the interface |
| `quoteMaxToken` | `1500 characters` | Limit the length of recalled business document fragments, matching the conventional length of single-segment process descriptions in exploration data |
| `temperature` | `0.1–0.3` | Maintain the accuracy of process guidance, avoiding random rewriting of professional terms |
| `toolChoice` | `auto` | Automatically select whether to call the process retrieval tool based on user input, adapting to the needs of different business handling scenarios |
| `AIPROXY_API_ENDPOINT` | Intranet-deployed FastGPT proxy address | Adapt to intranet deployment scenarios, ensuring data transmission security |

## Three common configuration errors
- Phenomenon: Segmentation errors occur when importing exploration data after Docker deployment, and recalled document fragments are incomplete. Cause: Context-related parameter values are not adjusted, and the default segmentation length does not adapt to the professional field structure of long documents.
- Phenomenon: When configuring the model in Config.json, the non-streaming return logic is not set correctly, resulting in out-of-order content from streaming returns during interaction. Cause: Corresponding parameter configuration items are not adjusted according to official documentation, and the triggering rules for streaming and non-streaming modes are confused.
- Phenomenon: A 504 timeout error is returned when calling the model during intranet deployment, and process guidance cannot be completed. Cause: `AIPROXY_API_ENDPOINT` is configured incorrectly, and the address does not point to the correct intranet proxy, resulting in interface call failure.

## How to confirm a successful configuration
- Upload a standard drilling log document, trigger a process guidance query, and check whether the recalled document fragments contain complete construction steps and parameter information.
- Initiate multiple rounds of interaction, confirm that the process steps returned by the model have no professional term errors and comply with business logic.
- Test model calls in the intranet environment, confirm that no timeout errors occur, and the interface returns normally.
- Adjust the `temperature` parameter to 0.2, verify whether the generated guidance content remains professional and rigorous, without random rewriting.

The values provided here are common starting points and should be evaluated against the reader's own samples.
