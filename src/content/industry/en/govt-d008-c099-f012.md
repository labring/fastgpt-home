# Business Process Guidance for Oil and Gas Exploration and Development: Deployment and Upgrade

## What the Data for This Category Looks Like
Business data for oil and gas exploration and development comes from sources including drilling operation logs, trial production monitoring reports, regional exploration reports, compliance approval documents, and more. Data update frequency varies by operation phase: updated daily during the exploration phase, and updated per single-well commissioning cycle during the trial production phase. Document structures include structured tables (such as well location coordinates, operation duration, pressure parameters) and unstructured PDF reports. Fields include well ID, operation link, approval status, timeliness requirements, and more. Units cover professional measurement standards such as meters, cubic meters, hours.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Multi-source heterogeneous data structures require support for multi-format parsing and metadata mapping configurations during deployment, to avoid storage conflicts between structured data and unstructured documents. Frequently updated operation data requires a cache mechanism configured for real-time synchronization, to prevent data delays from affecting the accuracy of business process guidance. The size of individual documents varies widely (small logs are a few KB, regional reports can reach tens of MB), so storage configurations must support large file uploads and sharded storage. Professional field and unit matching requires pre-configuring metadata rules for the knowledge base during deployment, to ensure correct association with business process nodes during retrieval.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://explore_user:secure_pass@db-host:27017/exploration?authSource=admin` | Stores multi-source data including unstructured exploration reports and approval logs, requires specifying the authentication source and exclusive database name |
| `PG_URL` | `postgresql://explore_db_user:db_pass@pg-host:5432/exploration_ops?sslmode=require` | Stores structured well location parameters and operation node data, enables SSL to protect sensitive operation data security |
| `REDIS_URL` | `redis://:redis_pass@cache-host:6379/0`, set cache validity period to 300–600 seconds based on actual testing | Caches frequently accessed operation process node information, adapts to the real-time update requirements of the exploration phase |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` (or corresponding cloud service provider storage endpoint) | Stores regional exploration reports up to tens of MB in size, requires configuring a storage endpoint adapted for large file uploads |
| `FE_DOMAIN` | `https://exploration-guide.internal-enterprise.com` | Binds the exclusive domain name of the internal enterprise office network, adapts to the access rules of the business process guidance page |
| `ROOT_KEY` | A randomly generated complex string of 32 or more characters | Configures the administrator access key to ensure background management security after deployment |

## Three Common Misconfigurations
- Symptom: When deploying locally on Windows, running the docker startup command results in a port binding failure log, or port 3000 cannot be accessed via the internal network. Cause: The local port 3000 was not released in advance, or the port configured in `FE_DOMAIN` does not match the actual container mapping port, leading to incorrect frontend access paths.
- Symptom: Calls to the self-built business process guidance application API interface return insufficient permissions or resource does not exist. Cause: `ROOT_KEY` was not correctly configured as the administrator key, or API access permissions were not enabled in the application configuration, resulting in interface calls being blocked.
- Symptom: Imported regional exploration reports cannot be fully retrieved. Cause: `STORAGE_S3_ENDPOINT` was not configured to adapt to large file storage, resulting in incomplete file uploads, and the knowledge base cannot read complete document content.

## How to Verify Correct Configuration
- Access the domain configured in `FE_DOMAIN` to confirm the frontend interface of the business process guidance page loads normally.
- Run the `docker logs container_name` command to view container startup logs, confirm that the connection status of `MONGODB_URI`, `PG_URL`, and `REDIS_URL` all show normal.
- Upload a small drilling operation log file, confirm that the file can be successfully imported into the knowledge base and vector parsing is completed.
- Use the configured `ROOT_KEY` to call the administrator interface, confirm that basic configuration information of the application can be obtained normally.
