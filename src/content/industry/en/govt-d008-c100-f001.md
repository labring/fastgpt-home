# Business Process Guidance for Oilfield Engineering Services: HTTP Interfaces and External Systems

## What the data for this category looks like
Business data for oilfield engineering services comes from internal platforms including job scheduling systems, on-site operation terminals, and materials management systems. There are two types of data update schedules: real-time push for single-job step changes, and daily batch synchronization for daily operation and maintenance data. The structure uses structured JSON format, with fields including job order number (string), job type (enumeration: drilling, cementing, fracturing), construction coordinates (longitude and latitude string), current processing step (enumeration: material approval, on-site preparation, job execution, acceptance), associated equipment number (string), update time (ISO 8601 format), and no additional statistical values.

## What Constraints These Characteristics Impose on the "HTTP Interfaces and External Systems" Link
Oilfield engineering service data is scattered across multiple internal systems. Interfaces must adapt to authentication and format conversion for multi-source data. The real-time update requirement means interfaces must support low-latency callbacks or short polling to avoid data lag that reduces the accuracy of process guidance. Fields include enumerated job steps and coordinate information, so interface request parameters must match fixed formats and enumerated values to reduce data parsing errors. Single job data volumes are large, so interface pagination return parameters must use a reasonable per-page data limit to avoid overloading FastGPT’s processing chain. Polling intervals must match the data update schedule to avoid excessive system resource usage from frequent calls.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication Method | Use the `Authorization` request header with a Bearer format token | Matches the universal API authentication rules of oilfield internal systems, ensuring secure data transmission |
| Context Variables | Pass job order ID and construction step type as custom `variables` | Dynamically specifies the business data scope for interface queries, accurately matching the guidance needs of the current processing workflow |
| Response Data Format | Extract the `responseData` field as model input | Adapts to the structured characteristics of oilfield engineering data, reducing the workload of subsequent data cleaning |
| Interface Timeout | 30–60 seconds | Matches the average response duration for pulling oilfield engineering data, avoiding session interruptions for process guidance due to timeouts |
| Single Query Limit | Top 10 entries | Controls the data volume returned by the interface, avoiding overloading FastGPT’s processing chain and internal business systems |
| Polling Interval | 15–30 seconds | Matches the real-time update schedule for oilfield engineering job step changes, avoiding excessive system resource usage from frequent calls |

## Three Common Mistakes
- Issue: Calling the `/api/v1/chat/completions` interface returns a 514 status code. Cause: The token permissions in the `Authorization` header are not configured correctly, or the interface call frequency limit of the oilfield internal system has been exceeded.
- Issue: After configuring the knowledge base, uploaded oilfield engineering job data cannot be retrieved. Cause: Business restriction parameters such as job order ID are not passed in `variables`, so the retrieval scope does not cover the target business data.
- Issue: The number of conversation records obtained through the interface does not match the actual sessions. Cause: Filter conditions are not set by job order dimension, so irrelevant cross-business conversation data is returned.

## How to Confirm Configuration Effectiveness
Based on the interface specifications of FastGPT v4.17.0, configuration effectiveness can be confirmed via the following actions:
- Initiate an interface call with a correct `Authorization` header, and check if the returned `responseData` field contains structured data for oilfield engineering jobs.
- Pass a known job order ID in `variables`, initiate a retrieval request, and confirm that the returned results match the relevant process information for that job order.
- Initiate multiple interface calls, and check that response durations stay within the 30–60 second range with no frequent timeouts.
- Filter conversation records by job order dimension, and confirm that returned sessions are only associated with the current job’s processing workflow.
