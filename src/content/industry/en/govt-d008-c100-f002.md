# Business Process Guidance for Oilfield Engineering Services: Vector Models and Indexes

## What the Data for This Category Looks Like
Oilfield engineering services business process-related data originates primarily from four core document types: engineering construction logs, equipment operation and maintenance records, business approval forms, and site survey reports.
Data update cadence falls into two categories. Archived documents for single construction projects are updated in bulk after project acceptance. Daily operation and maintenance inspection records are synchronized daily.
The structure of individual documents includes fields such as operation area number, construction process steps, approval node flow, responsible team, and equipment operating parameters. Units include engineering-specific units such as hours, cubic meters, and megapascals. Some long documents contain multi-page process detail descriptions.

## Constraints on the Vector Model and Indexing Process
These data characteristics impose three constraints on the vector model and indexing process.
First, documents contain a large number of petroleum and petrochemical professional terms and long-text process descriptions. Vector models must adapt to industry corpora to avoid loss of professional semantics.
Second, data update cadence includes both bulk and real-time types. Indexes must support both incremental synchronization and bulk rebuilding modes to ensure consistency between new and old data.
Third, core fields include associated information such as operation area and approval nodes. Vector chunking must retain contextual associations between fields to avoid loss of business logic during retrieval.

## How to Set Configuration Values
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Matches the average length of individual process descriptions to retain complete business logic |
| Overlap Length | 100–150 characters | Connects contextual content between adjacent chunks to prevent process steps from being truncated |
| Similarity Threshold | 0.75–0.85 | Filters irrelevant non-business retrieval results to ensure accuracy of core process matching |
| Single Search Limit | Top 20 results | Adapts to the number of nodes in business process guidance to avoid returning excessive redundant results |
| Maximum Context | 4000 tokens | Aligns with the average length of oilfield engineering documents to meet contextual recall requirements during retrieval |
| `defaultToken` | Calibrated based on actual measurements | Adapts to the token consumption limit of current hardware and business data |

## Three Common Misconfigurations
- An on-screen error prompt stating "This token does not have permission to use the model" occurs because an embedding model adapted for petroleum and petrochemical professional scenarios has not been configured, or the calling API key is not bound to the usage permission of the corresponding model.
- Knowledge base search response exceeds the preset threshold, because the chunk length is set too large and the single search limit is too high, causing the vector matching calculation load to exceed hardware capacity.
- Retrieval results do not include newly submitted business approval forms, because incremental index updates have not been enabled, resulting in new business data not being synchronized to the vector database.
