# Business Process Guidance for Oilfield Engineering Services: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Oilfield engineering service business handling data mainly comes from on-site operation procedures, client business requirement documents, equipment operation and maintenance manuals, and approval process ledgers. Data updates are triggered by operation standard revisions, new equipment launches, or regional business adjustments. The update cycle ranges from quarterly to half a year. Documents are split by operation link, with each document containing fields such as operation number, affiliated block, approval node, and required qualification materials. Approval time limits are measured in working days, and material lists include qualification document numbers and validity requirements.

## Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Oilfield engineering service operation data is split by operation link and block. Retrieval must accurately match the corresponding document set by business scenario to avoid incorrect guidance for cross-block operations. Data update cycles are long, but there are no fixed trigger nodes. Full refresh of knowledge base embedding vectors must be performed regularly to prevent expired procedures from being recalled. Documents contain fields with units such as operation number and approval time limit. Semantic association of fields must be retained during retrieval to avoid mixing approval requirements using non-working day units into results. Each document focuses on a single operation link. Recall results must cover all nodes of the current handling process to avoid missing process guidance.

## Configuration Settings
| Configuration Parameter | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the density of professional terms in oilfield engineering service operation procedures to avoid recalling irrelevant cross-block documents |
| `limit` | Top 6 entries | Single operation procedure documents have long content; limiting recall entries avoids context overflow |
| `searchMode` | Semantic retrieval | Matches professional expressions of oilfield engineering service operation links to avoid fuzzy matching errors of professional terms from keyword retrieval |
| `usingReRank` | Enabled | Reorders recall results by business relevance to prioritize returning process documents for the current operation block |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonyms related to business handling, such as expanding "cementing" to "oil well cementing operation" |
| `collectionIds` | Collection ID configured by operation block | Filters documents from non-current operation blocks to ensure accurate retrieval scope |

## Three Common Misconfigurations
- Phenomenon: Retrieval results do not filter documents for the specified operation block, mixing operation procedures from other regions. Cause: The `collectionIds` parameter is not configured, so the retrieval scope covers the full knowledge base collection.
- Phenomenon: Retrieval only returns a single expanded question, without displaying associated results for the original business question. Cause: The parameter validation for `datasetSearchUsingExtensionQuery` is not correctly enabled, or the version configuration is abnormal.
- Phenomenon: The retrieved process steps lack key approval nodes. Cause: Documents are not split by operation link, or the `limit` parameter value is too high, causing long documents to be truncated, so key approval node content is not fully recalled.

## How to Confirm Configuration Is Correct
- In the retrieval logs of FastGPT v4.17.0, check the collection to which the returned documents belong. Confirm that all documents belong to the operation block collections currently configured, and verify the filtering effect of `collectionIds`.
- Test retrieval results for different business questions. Check whether professional synonyms are automatically expanded, and verify that `datasetSearchUsingExtensionQuery` is enabled.
- Check the number of recalled results. Confirm that it matches the value of the `limit` parameter, and verify the retrieval upper limit configuration.
- Compare the result order before and after reordering. Confirm that the `usingReRank` configuration takes effect, and prioritize returning documents related to the current business.

The values given are common starting points and should be measured against the reader's own samples.
