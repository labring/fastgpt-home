# Business Process Guidance for Oilfield Engineering Services: Forms and Interactions

## What the data for this category looks like
Business data for oilfield engineering services mainly comes from construction work order systems, equipment operation and maintenance ledgers, and safety record databases. Updates are synchronized with construction milestones, and occur each time an approval is submitted or an operation is completed. The document structure includes fields such as construction area (oilfield block, well number), equipment ID, operation type (cementing, fracturing, well testing, etc.), safety record number, estimated construction duration, etc. The safety record number is a fixed-format combination of letters and numbers, the duration unit is days, the equipment ID is a 12-digit string, most single-field content lengths fall between 200 and 800 characters, and operation type is a fixed enumeration value.

## What constraints these characteristics impose on the "forms and interactions" link
The hierarchical structure of construction areas requires the form to support cascading selection interactions, to avoid users entering incorrect block and well number correspondences. The fixed format of the safety record number requires the form to be configured with format verification rules, to reduce manual review costs. Different operation types correspond to exclusive parameter fields, requiring the form to support dynamic switching of field groups to avoid redundant information display. The rhythm of data updates according to construction milestones requires that associated work order data be synchronized in real time after form submission, to ensure consistency of process data. If a user sends a new message to interrupt the interaction mid-process, a timeout reset mechanism must be configured to prevent the process from getting stuck.

| `formInput` format verification | Configure regular matching rules for safety record numbers | Match the fixed format of oilfield engineering service record numbers |
| Cascading selection data source | Load in the hierarchy of oilfield block → well number | Match the hierarchical data structure of construction areas |

The configuration values listed above are common starting points, and should be evaluated against the reader's own specific samples.

## Three common mistakes
- Symptom: The safety record number field fails verification after form submission, displaying a format error prompt. Cause: No `formInput` format verification rule is configured for the safety record number, causing users to enter content that does not match the fixed format of oilfield record numbers.
- Symptom: The user sends a new message without completing the `userSelect` selection or form filling, and the process gets stuck and cannot proceed. Cause: No interactive timeout interruption and status reset mechanism is configured, no timeout callback logic for `userSelect` is bound, and the scenario where the user sends a message mid-interaction is not handled.
- Symptom: The form fields do not update after switching operation types, and the parameter group of the original operation is still displayed. Cause: No dynamic field trigger logic after operation type change is configured, and exclusive parameter data sources for different operation types are not associated.

## How to confirm the configuration is complete
- Manually enter a safety record number that does not meet the format requirements, check whether a format verification prompt is triggered, and confirm that the `formInput` verification rule configuration is effective.
- Switch the operation type, check whether the form fields automatically switch to the parameter group corresponding to the target operation, and confirm that the dynamic field trigger configuration is correct.
- Simulate a user sending a new message without completing the interaction, check whether the process triggers a timeout reset, and confirm that the `userSelect` timeout mechanism configuration is in place.
- Submit a test form, check whether the associated work order data is synchronized and updated, and confirm that the post-submission synchronization configuration is effective.
