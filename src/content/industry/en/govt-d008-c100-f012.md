# Business Process Guidance for Oilfield Engineering Services: Deployment and Upgrade

## What the Data for This Category Looks Like
Oilfield engineering services business process data primarily originates from on-site construction logs, equipment operation and maintenance ledgers, project approval documents, and cross-department collaboration work orders.
Data is submitted and updated in individual project batches.
Update cycles are adjusted flexibly based on project progress.
Single submissions typically include core fields such as project number, construction phase, approval node, responsible person, and time limit requirements.
Some equipment-related data includes working condition parameters and detection values.
Field units use standard engineering domain units such as hours, days, and unit counts.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
Batch-based data submission for oilfield engineering services requires deployments to support knowledge base sharding by project dimension, to avoid single-library data overload.
Flexible update cycles require the system to support both manual trigger incremental synchronization and scheduled automatic synchronization modes, to adapt to the progress rhythms of different oilfield projects.
The mixed multi-field document structure requires the vector model configured during deployment to support vectorization processing of multiple field types, to avoid loss of semantic information for numerical parameters.
Cross-node flow of cross-department collaboration work orders requires post-deployment process guidance tools to synchronously call approval status interfaces from multiple departments, to ensure real-time performance of process nodes.
The upgrade process must retain the configuration of original project shards, to avoid invalidation of historical data indexes, while being compatible with new engineering field parsing rules.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 1000–1500 connections | Adapts to the document link limit for single-batch projects in oilfield engineering services, to avoid database connection overflow |
| `MONGODB_URI` | Exclusive address of the oilfield intranet MongoDB instance | Stores structured data of project approval work orders and construction logs, uses intranet address to ensure data security |
| `REDIS_URL` | 192.168.xxx.xxx:6379?password=Custom strong password | Caches real-time approval status of process nodes, uses password to ensure access security |
| `STORAGE_S3_ENDPOINT` | Address of the oilfield internal object storage service | Stores large files such as drawings and videos during construction, adapts to intranet storage requirements |
| `FE_DOMAIN` | Intranet domain name of the oilfield engineering services business system | Configures the frontend access address of the process guidance tool, to ensure only internal networks can access |
| `ROOT_KEY` | Highest permission key customized by the oilfield operation and maintenance team | Manages core configuration permissions of the system, only accessible to authorized dedicated operation and maintenance personnel |

## Three Common Misconfigurations
- Symptom: Code run steps do not display in the workflow orchestration and debugging interface. Cause: `ROOT_KEY` permissions were not correctly configured during deployment, leading to failed permission verification for code run nodes, so the nodes are hidden.
- Symptom: The knowledge base selection box is empty after importing oilfield engineering service project documents. Cause: `MONGODB_URI` was not pointed to the correct project work order database during configuration, so the system cannot read uploaded knowledge base association information.
- Symptom: Reranker model call fails, returning an invalid parameter error. Cause: The ACCESS Token for the oilfield internal model service was not correctly obtained, or the Token configuration was not synchronized to the environment variables of the deployment instance.

## How to Confirm Configuration is Complete
- Log in to the FastGPT backend, view the values of core configuration items, and confirm they match oilfield internal operation and maintenance specifications.
- Manually trigger an incremental synchronization of project documents, check if approval work orders and construction logs for the corresponding project are automatically loaded in the knowledge base.
- Start a workflow debug for a test project, confirm that the code run node displays normally and can be executed, with no permission-related errors.
- Call the Reranker model interface, check if return results can be obtained normally, with no Token or permission-related errors.
