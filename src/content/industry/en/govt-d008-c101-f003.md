# Port and Shipping Business Process Guidance: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Port and shipping business handling data comes from terminal operation systems, port EDI declaration platforms, and vessel dynamic supervision systems. The system updates data in real time based on business handling nodes. Documents for a single handling process include fields such as business type, handling node, approval requirements, required documents, and processing time limit. Field units include TEU, ton, hour, working day, and others. The document structure varies significantly across different business types. For example, required fields for container loading and unloading operations differ from those for vessel berthing operations.

## Constraints on Multi-turn Dialogue and Prompt Engineering
The structural differences, real-time update features, and specialized units of port and shipping business data create multiple constraints for multi-turn dialogue and prompt engineering configurations. Required fields and process logic vary widely across different business types. Prompts guide users to confirm their current business category first to avoid cross-business confusion. The real-time update feature requires the dialogue system to verify the timeliness of identifiers like user-provided business numbers and vessel IMO numbers, to prevent use of expired data. Fields include specialized units, so prompts clearly require users to provide parameters with matching units. For example, prompts must specify TEU for container quantities and ton for cargo weight.

## Three Common Misconfigurations
- Workflow execution becomes unresponsive or terminates early after reaching the AI dialogue stage. Cause: Business identifier fields are not passed in the `variables` parameter, so the system cannot match knowledge base content for the corresponding port and shipping business, leading to process interruption.
- API calls cannot implement streaming output, and the front end cannot gradually display reply content. Cause: The streaming output switch in dialogue configuration is not enabled, and chunked return data for the `messages` field is not processed correctly.
- The dialogue log annotation function cannot be associated with specific business nodes. Cause: Business node ID variables are not bound during the dialogue process, so annotations cannot match corresponding process steps, resulting in annotations with no actual business association.

## How to Confirm Proper Configuration
- Initiate a simulated vessel berthing business dialogue, and check whether the system first guides confirmation of the business type, then sequentially asks for unit-attached parameters such as berthing time and total vessel tonnage.
- Call the API to initiate a dialogue, and check whether the returned `chatId` and `messages` fields fully record context information for multi-round interactions, confirming that the context length does not exceed the preset threshold.
- Test the timeout scenario: check whether the system triggers a timeout prompt and retains collected business information when input is not completed within 600 seconds.
- View dialogue logs, confirm that the annotation function allows selection of specific business handling nodes, and that annotation content can be properly associated with corresponding interaction steps.
