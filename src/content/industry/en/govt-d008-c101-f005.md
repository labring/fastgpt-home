# Port and Shipping Business Process Guidance: Tool Calling and Plugins

## What Data for This Category Looks Like
Port and shipping business processing data is primarily sourced from structured ledgers of port authority EDI systems, vessel scheduling platforms, and offline business acceptance systems.
Data synchronization follows two rhythms: real-time sync after individual business completion, and daily updates for batch data.
Document structure uses business type as the first-level classification, including fields such as business code, processing link sequence, required materials list, processing time limit, and acceptance channel.
Most fields are enumeration types or structured arrays. Processing time limits are uniformly measured in working days. The materials list includes sub-items such as material name, submission form, and quantity requirements.

## What Constraints Do These Characteristics Impose on the "Tool Calling and Plugins" Link
Structured enumeration fields require that only compliant enumeration values are passed when calling tools, otherwise valid business information cannot be returned.
Real-time updated business data requires plugins to use real-time pull logic, to avoid returning expired processing nodes or material requirements.
The multi-field nested document structure requires tool call parameter parsing logic to support array-type materials list fields, and extract required content by hierarchy.
Unified unit specification requires plugins to automatically convert processing time limits to easy-to-understand expressions when returning results, and avoid outputting pure numbers without units.
The uniqueness of business codes requires binding a unique business identifier when calling tools, to ensure returned data fully matches the inquired business.

## Three Common Misconfigurations
- A 502 status code is returned when calling the port authority business interface. This occurs when the correct proxy address is not configured, or the interface domain name is not added to the allowlist, causing the request to be blocked.
- Only partial optional models are displayed in the tool call popup. This happens when the port and shipping business-specific model is not added to the available model list, or the model permission is not correctly bound.
- Missing business processing flow nodes in returned results. This occurs when the passed business code does not comply with the enumeration specifications of the port authority system, causing the interface to fail to match the corresponding business data.

## How to Verify Successful Configuration
- Initiate a tool call with a real business code, and check if the returned result includes complete processing links and materials list.
- View the plugin running logs, and confirm that the request parameters fully match the configured parameter rules, with no invalid fields.
- Simulate real-time data update after a business is completed, and check if the plugin can pull the latest processing status.
- Switch between different business types, and confirm that tool calls can correctly adapt to the enumeration field requirements of different businesses.
