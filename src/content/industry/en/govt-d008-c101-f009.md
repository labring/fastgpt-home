# Business Process Guidance for Port and Shipping: Model Access and Configuration

## What Data Looks Like for This Category
Reference only; verify against the target FastGPT release and deployment documentation.

## Constraints Imposed by These Characteristics on Model Access and Configuration
Real-time port business data requires the model’s context window to adapt to the length of multi-stage historical data, preventing critical information from being truncated. Multi-field business documents require the model to strictly match business process rules, so generated content must meet high accuracy standards. Some business scenarios use multimodal information such as container photos and berth operation videos to complete guidance, so the platform must support multimodal model access. At the same time, process guidance tools automatically call internal functions such as voyage query and customs status query, and cannot rely solely on the model’s built-in knowledge.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `vision` | Enabled | Port and shipping business often needs to recognize multimodal information such as container photos and berth operation videos to identify cargo status and operation scenarios |
| `maxContext` | 8000–12000 token | Needs to link multi-stage historical data such as voyage schedules, customs clearance, and berth scheduling to avoid context truncation that causes loss of critical business information |
| `toolChoice` | auto | Needs to automatically call built-in tools such as voyage query and customs status query based on user queries, without mandatory specification of tool types |
| `temperature` | 0.2–0.4 | Business process guidance needs to accurately match process rules, avoiding generated guidance that is vague or deviates from specifications |
| `quoteMaxToken` | 2000–3000 characters | Needs to reference long text content such as port operation logs and customs clearance documents to ensure complete referenced business information |
| `AIPROXY_API_TOKEN` | Exclusive token assigned by the platform | Used for identity verification during model calls, ensuring that call permissions meet the compliance requirements of port business |

## Three Common Misconfigurations
- Symptom: Initiating a business query reveals no intermediate tool call execution steps. Cause: `toolChoice` is not set to auto, or the corresponding tool is not bound, so the model does not trigger the tool call process.
- Symptom: Configuring `AIPROXY_API_TOKEN` triggers a red numeric error popup on the page. Cause: The token’s bound domain does not match the address set in `AIPROXY_API_ENDPOINT`, or the token has expired.
- Symptom: Uploading a container photo results in the model failing to identify details such as container number and seal number in the image. Cause: The `vision` configuration item is not enabled, or the uploaded image format does not match the types supported by the platform.

## How to Verify Successful Configuration
- Initiate a test request that includes a vessel berth query, and confirm the model automatically calls the corresponding tool to retrieve real-time business data.
- Upload a container appearance photo, and confirm the model extracts key identification information from the photo.
- Enter a query that includes multiple segments of historical voyage information, and confirm the model does not truncate context and fully links historical data.
- Check that the `AIPROXY_API_ENDPOINT` configured address matches the token’s bound address, to eliminate connection errors.

The values provided here are common starting points and should be measured against the reader's own samples.
