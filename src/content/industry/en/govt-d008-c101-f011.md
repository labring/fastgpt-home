# Port and Shipping Business Process Guidance: Forms and Interactions

## What the data for this category looks like
Port and shipping business processing data mainly comes from three core sources: port operation management systems, maritime declaration platforms, and shipping company manifest systems. Vessel schedule forecast data is updated daily. Real-time port operation data is updated at the minute level. Business processing form fields include vessel name, IMO number, container number, operation type, berth number, list of declaration materials, and more. The IMO number follows a 7-digit numeric format, and the container number follows the international standard 11-character alphanumeric combination. Data is stored in structured JSON format, with each record corresponding to the full process of a single business handling.

## What constraints these characteristics impose on the "forms and interactions" link
Since data sources involve multiple heterogeneous systems, field format requirements are strict. Forms must configure precise validation rules for exclusive fields to avoid invalid data submissions. Real-time operation data is updated at a high frequency, so dynamic options in forms such as berth number and available vessel types need to be synchronized and updated regularly to ensure options match the current port operation status. There are many business processing links and a large number of fields, so forms must be split and displayed according to processing links to reduce user filling burden. At the same time, some fields have fixed validation logic, which must provide real-time feedback during user input to reduce the probability of subsequent review rejection.

## How to configure settings
The following configurations are based on FastGPT v4.17.0 version
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Configure regular expression validation rules for IMO number and container number fields, set single-field input timeout to `30 seconds` | Match the fixed format requirements of port business exclusive fields, prevent invalid data from entering subsequent processes |
| `userSelect` | Preset vessel type and operation type options, set the option update cycle to `1 day` | Adapt to the relatively stable classification options in port business, while allowing regular synchronization of the latest operation requirements |
| `formInput` | Split form steps according to business processing links, display `2-4` fields per step | Reduce the amount of information on a single-page form, lower the probability of user filling errors |
| `userSelect` | Enable post-selection session locking function, set the lock validity period to `8 hours` | Match the average time required for a single port business processing, avoid process reset mid-flow |

## Three common misconfigurations
- Symptom: An InvalidParameter error is returned after submitting the form, prompting a field format error. Cause: Regular expression validation rules are not configured for port-exclusive fields such as IMO number and container number, so the system cannot recognize valid input content.
- Symptom: The selected berth number and vessel type options are not updated in time, and outdated scheduling information appears. Cause: The option update cycle is set too long, which does not adapt to the high-frequency change characteristics of port berth scheduling.
- Symptom: The process is reset mid-conversation, and the user needs to reselect the business processing type. Cause: The session locking function is not enabled, or the lock validity period is set too short to cover the full duration of a single business processing.

## How to confirm the configuration is properly set
- Submit an IMO number that does not meet the format requirements, and verify that the preset error prompt text appears.
- Access the system configuration page to view the update cycle of the user selection component, and confirm that it matches the synchronization frequency requirements of port business.
- Initiate a test conversation, select the business processing type, switch to other topics and return, and confirm that the conversation is not reset.
- Submit a complete test form, and verify that the system returns a successful response without format errors.
