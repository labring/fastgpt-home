# Business Process Guidance for Refinery and Chemical Production: HTTP Interfaces and External Systems

## What data for this category looks like
Business processing data for refinery and chemical production comes from the plant DCS control system, production scheduling logs, and business work order systems. Real-time operating parameters are synchronized every 10 minutes. Material consumption and work order processing data are updated daily. Data documents use structured field packages, including plant code, material type, processing node ID, current progress, operator identifier, and completion timestamp. Units uniformly use standard refinery and chemical industry units such as tons, cubic meters, and hours. No additional custom unit fields are included.

## What constraints these characteristics impose on HTTP interfaces and external systems
The requirement for real-time operating parameters to update every 10 minutes means interface polling intervals must not exceed 10 minutes. Otherwise, the system cannot provide the latest progress reference for business processing. The daily update rhythm of work order and material data fits scheduled daily batch pull interface calls. Data fields include exclusive identifiers such as plant code and material type. Interface requests must carry corresponding parameters to accurately return matching business processing data. The refinery and chemical industry’s unified unit system requires interface responses to include standard units for numerical fields. This avoids cross-system conversion errors. Business processing process node status must be synchronized in real time, so interfaces must support querying progress by node ID.

## How to configure the system
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${Enterprise-specific API key}` | External systems for refinery and chemical production typically require enterprise-level key authentication to prevent unauthorized access |
| Request timeout | `30–60 seconds` | Refinery data interfaces usually have measurable delays. An overly long timeout blocks business processes. An overly short timeout causes normal requests to fail |
| `variables` | Bind plant ID and work order ID as global variables | Precise matching of business processing data for corresponding refinery and chemical plants is required to avoid returning irrelevant results |
| `responseData` | Extract progress fields and completion timestamp | Business process guidance only needs core status data. Omitting redundant fields reduces transmission load |
| Polling interval | `8–12 minutes` | Matches the update rhythm of real-time parameters. Avoids excessive frequency that consumes external system resources |

The above configuration items are designed for FastGPT v4.17.0.

## Three common configuration mistakes
- The symptom is delayed output of business guidance text by more than 10 seconds after calling the interface, leading to process freezes. The cause is an overly short polling interval, where frequent calls trigger external system interface rate limiting.
- The symptom is empty business node data returned by the interface. The cause is missing plant ID or work order ID parameters in the request, so the corresponding refinery and chemical business data cannot be matched.
- The symptom is a 403 status code returned by the interface call. The cause is the `Authorization` parameter not carrying a valid enterprise key, so external system authentication fails.

## How to confirm the configuration is correct
- Call the configured interface and check if the `responseData` includes the business processing progress field and plant code.
- Request the interface again 10 minutes later and check if the returned completion timestamp updates to match the data update rhythm.
- Replace the valid enterprise key and check if the `Authorization` parameter passes authentication normally.
- Simulate a business work order node change and check if the progress status returned by the interface updates synchronously.
