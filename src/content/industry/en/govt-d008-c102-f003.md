# Business Handling Process Guidance for Refinery and Chemical Production: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Business handling data for refinery and chemical production mainly comes from the enterprise manufacturing execution system (MES), equipment operation and maintenance logs, safety compliance manuals, and administrative approval process libraries. Data update rhythms are divided into real-time and scheduled types: equipment operation parameters and safety thresholds are updated in real time; monthly production reports and approval node configurations are updated daily. The document structure centers on structured process nodes, including fields such as equipment unit ID, operating pressure, temperature, handling time limit, and approval authority. Units uniformly adopt refinery and chemical production standard specifications: for example, pressure units are megapascals (MPa), and temperature units are degrees Celsius (℃). This document is written based on FastGPT v4.17.0.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
The structured characteristics of refinery business handling data require multi-turn dialogue to strictly match field formats and standard units, to avoid parameter mismatch issues. Real-time updated equipment operation parameters require that dialogue context limits the number of historical turns, to prevent the use of expired data to guide processes. Multi-node handling processes require dialogue to progress step by step, with each interaction focusing only on information collection and verification for the current node, to avoid interference from redundant cross-node information. At the same time, field permission constraints require dialogue to accurately identify operable fields for the current handling link, to prevent unauthorized guidance.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Turns | Previous 8 turns of dialogue | Refinery business handling processes typically include 5-7 nodes; 8 turns can cover the complete handling chain and avoid context redundancy |
| `variables` | Bind equipment unit ID and operating pressure threshold fields | Ensure business data called during dialogue matches the currently handled refinery and chemical production unit |
| `messages` | Only retain historical interactions for the current handling process | Filter irrelevant historical messages and focus on guidance for the current business link |
| Input Length Limit | 1200-1500 characters | Block input requests exceeding the large model's processing limit and avoid triggering errors |
| Prompt Template | Include unit verification rules | Mandate the use of refinery and chemical production standard units (MPa, ℃) during dialogue |
| `chatId` | Bind single business handling session ID | Ensure multi-turn dialogue is associated with the context of the same handling process |

## Three common mistakes
- Phenomenon: After submitting a business request exceeding 1200 characters, the interface shows no response or an error. Cause: No input length limit rule is configured, and ultra-long input is directly submitted to the large model, triggering context overflow.
- Phenomenon: Multi-turn dialogue fails to remember previously mentioned equipment parameters, leading to deviations in subsequent guidance. Cause: `variables` binding for historical parameters is not enabled, or the context turn setting is too low, causing historical parameters to be cleared.
- Phenomenon: Returned business guidance results do not carry reference identifiers for associated documents. Cause: The prompt does not explicitly require returning document association fields, or variable binding for the reference relationship of the business data source is not configured.

## How to confirm the configuration is complete
- Submit a business handling request exceeding 1200 characters, and confirm that the system triggers an input length interception prompt.
- Open two different refinery and chemical production unit handling sessions, submit interaction content separately, and confirm that the contexts of the two sessions do not interfere with each other.
- Input parameters with non-standard units into the dialogue, and confirm that the system returns a unit verification prompt or correction suggestion.
- Check the dialogue log, and confirm that the `chatId` of each interaction matches the ID of the current handling process.
