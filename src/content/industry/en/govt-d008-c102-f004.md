# Business Process Guidance for Refinery and Petrochemical Production: Workflow Orchestration

## What data for this category looks like
Data for refinery and petrochemical production comes from distributed control systems (DCS), device shift logs, equipment operation and maintenance ledgers, and quality inspection center test reports. Update rhythms fall into three categories: real-time (process temperature, pressure, and flow parameters, updated every second to minute), daily (shift output and energy consumption reports), and periodic (equipment maintenance records, quarterly quality inspection summaries). Document structures include fields such as unique device identifiers, process parameter values and corresponding units, quality inspection indicator values, and equipment runtime duration. Field naming follows petroleum and petrochemical industry standards, with units mostly degrees Celsius, megapascals, cubic meters per hour, milligrams per cubic meter, and similar standard units.

## What constraints do these characteristics impose on workflow orchestration
Highly real-time process parameters require workflow trigger nodes to match high-frequency update rhythms. Too low a trigger frequency will cause data lag. Multi-source heterogeneous data requires configuring multiple data source nodes, and `variables` must be used to strictly bind corresponding fields to avoid cross-data source parameter misalignment. File-type data such as quality inspection reports has large volume, so the upload link needs to adapt to a longer timeout threshold. Industry standard field naming requires workflow variable mapping to strictly follow established rules, and field names cannot be arbitrarily customized.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` mapping rule | Strictly match data source field names and workflow variables | Prevent process execution exceptions caused by parameter misalignment |
| Trigger frequency | `10–60 seconds` (calibrated based on actual testing) | Match the update rhythm of real-time process parameters for refinery and petrochemical production |
| `nodeId` bound trigger node | Bind timed trigger or device status change nodes | Trigger business process handling as needed |
| File upload node timeout | `300 seconds` | Adapt to the upload time of large-volume files such as refinery quality inspection reports |
| Workflow retry count | `2–3 times` | Handle temporary network fluctuations or data source response delays |
| Associated knowledge base scope | Only bind the refinery and petrochemical process standard library | Filter irrelevant business data and improve process accuracy |

## Three common mistakes
- When uploading refinery and petrochemical quality inspection reports in the workflow, the prompt "Failed to create post presigned url" appears. The cause is that the cross-domain access rules of the object storage are not configured, or the signature expiration time is set shorter than the actual file upload time.
- The fields bound by `variables` in the workflow are empty, resulting in missing key process data in the process output. The cause is that mapping is completed directly without verifying the field integrity returned by the data source.
- The workflow trigger frequency is set lower than 10 seconds, causing high-frequency requests to exceed the response limit of the device DCS system and leading to workflow execution failure.

## How to confirm the configuration is correct
- Manually trigger the workflow once, check the `variables` bound fields in the process output, and confirm they match the values returned by the data source.
- Upload a standard refinery and petrochemical quality inspection report, confirm that the file upload node has no errors and the file is successfully stored in the specified storage path.
- Observe the workflow operation logs for 1 consecutive hour, confirm that the trigger frequency matches the set value and there are no repeated errors.
- Adjust the trigger frequency range to verify whether the workflow automatically executes according to the set rhythm.
