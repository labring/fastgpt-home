# Business Process Guidance for Refinery and Chemical Production: Tool Calling and Plugins

## What the data for this category looks like
Business processing data for refinery and chemical production mainly comes from the enterprise manufacturing execution system (MES), distributed control system (DCS), equipment operation and maintenance logs, and safety management platform. Data update rhythms fall into three categories: real-time equipment condition data syncs every second, production daily reports update daily, and overhaul plans and work approval processes update when nodes are triggered. Each individual business document includes equipment ID, process parameters (temperature, pressure, flow), processing node name, approval status, handler, and associated work order ID. All fields are standardized enumerations or numeric types, bound to fixed units, with no free text fields.

## What constraints these characteristics impose on the tool calling and plugins link
Business data for refinery and chemical production strongly relies on standardized fields and real-time operating conditions, so tool calling must strictly match preset field names, and cannot support fuzzy parameter matching. Calls for real-time operating condition data must control the duration of a single request to avoid timeouts that interrupt processes. Multi-node business processing workflows need to call corresponding plugins based on work type; different tasks such as hot work, maintenance correspond to exclusive compliance verification and process advancement tools. The mapping relationship between plugins and business nodes must be configured in advance. Sensitive production data must pass the permission verification link of the plugin, and only authorized roles are allowed to call related tools.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call trigger rule | Trigger by business node | Refinery business processing workflows are divided by different work nodes; triggering by node avoids invalid calls |
| Single tool call timeout duration | 30–60 seconds | Matches the sync cycle of refinery real-time data, avoids long waits that disrupt process advancement |
| Plugin input parameter verification mode | Strict field name matching | Refinery business data fields are standardized; strict verification prevents call failures caused by parameter misalignment |
| Maximum number of call retries | 2 times | Balances call success rate and process wait time, avoids repeated calls consuming system resources |
| `toolChoice` | Force specified tool | For standardized business workflows, forcing tool selection prevents the large language model from choosing the wrong tool independently |
| Maximum context length | 800–1200 characters | Adapts to the context processing rules of FastGPT v4.17.0, matches the typical length of single refinery business workflow documents |

## Three common mistakes
- Phenomenon: Tool calls return an insufficient number of results, or do not return expected equipment condition data. Cause: The mapping relationship between plugin input parameters and refinery business fields is not strictly configured, causing the passed parameters to fail to match the field names of the data source.
- Phenomenon: The large language model does not trigger tool calls, or the trigger frequency is unstable. Cause: `toolChoice` is not set to force specified mode; when the large language model selects tools independently, it does not match the exclusive tool configuration of the business node, leading to invalid or fluctuating calls.
- Phenomenon: Images such as process flow diagrams returned by tool calls are not fully displayed. Cause: The plugin's image return size limit is not configured, or the image resolution parameter is not specified in the input parameters, causing the returned image size to exceed the front-end rendering threshold.

## How to confirm the configuration is correct
- Submit a simulated hot work processing request, verify that the tool call triggers the corresponding compliance verification plugin, and that the input parameters include standardized fields such as equipment ID and work time.
- Check the tool call logs to confirm that the duration of a single request is within the preset timeout range, and there are no timeout errors.
- Test sending an abnormal request with non-standardized field names, and confirm that the plugin returns a clear prompt of parameter verification failure.
- Trigger a tool call and view the returned images, confirm that the images are not truncated and the dimensions meet front-end rendering requirements.
