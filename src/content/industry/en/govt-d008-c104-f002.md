# Business Process Guidance for Coal Chemical Industry: Vector Models and Indexes

## What the data for this category looks like
Coal chemical business process-related data is mainly sourced from internal standardized work instructions, on-site operation and maintenance records, safety production filing documents, and cross-department collaborative work orders. Data updates are synchronized with adjustments to business processes, equipment retrofits, or compliance requirements. There is no fixed update cycle, but the scope of each single update is clear. The document structure includes four core fields: process nodes, responsible entities, compliance basis, and exception handling. Field units cover general industrial units such as production tonnage, operating hours, and pressure in MPa.

## What constraints these characteristics impose on the vector model and indexing stage
Coal chemical business documents often contain long process steps and specialized industrial parameters. Individual documents can reach thousands of characters in length, and there are many exclusive terms and unit abbreviations. This places requirements on the context processing accuracy of the vector model. Business work orders are updated frequently in line with production rhythms. The index must support incremental synchronization to avoid performance losses caused by full reconstruction. Cross-department collaborative documents have multi-field nested structures, so the index must support precise recall by field dimensions. Compliance filing documents need to be associated with the latest version, so the index must retain version traceability capabilities to ensure recalled content aligns with current valid requirements.

## Three common mistakes
- Symptom: No selectable options appear in the index model dropdown menu in the interface, or an error is reported after selection and save. Cause: The access key and interface address for the local or third-party vector model have not been configured, so the system cannot load the available model list.
- Symptom: The number of index recall results does not match the set single search limit, and complete steps of some long process documents are not recalled. Cause: The chunk length is set too small, causing long documents to be split into too many chunks, so only partial chunk content is returned during index recall.
- Symptom: When calling a third-party model using a custom transit interface, an interface error is prompted after saving the index configuration. Cause: The exclusive key of the vector model has not been correctly bound in the transit interface, or the interface address does not carry the correct version path.

## How to confirm the configuration is complete
- Upload a coal chemical business process document, check the chunk preview results, confirm that the chunk length falls within the preset range, with no severe semantic breaks.
- Initiate a business process guidance query, check the number of recall results, confirm that it matches the set single search limit.
- Check the index logs, confirm that incremental update tasks can be triggered normally, with no redundant prompts for full reconstruction.
- Compare recall results under different matching degrees, adjust the similarity threshold to meet the accuracy requirements of the business scenario.
