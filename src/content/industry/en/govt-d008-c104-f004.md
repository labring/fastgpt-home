# Coal Chemical Industry Business Process Guidance: Workflow Orchestration

## What the data for this category looks like
Coal chemical industry business data mainly comes from the enterprise's internal DCS control system, material management system, safety compliance ledger, and process parameter database. Data update rhythms vary: real-time process parameters are synchronized every 15 seconds, material ledgers are updated daily, and compliance data is updated when on-site inspection nodes are triggered. A single data document includes fields such as node ID, material code, process threshold, operation steps, and compliance check items. Units include degrees Celsius, megapascals, tons, hours, etc. The structure is fixed and must strictly match process specifications.

## What constraints these characteristics impose on the "workflow orchestration" link
The multi-source and decentralized nature of coal chemical industry business data requires workflow orchestration to configure multiple nodes to pull data sources from different systems, avoiding data silos. Data sources with different update rhythms need to be set with differentiated polling intervals to prevent verification errors caused by unsynchronized data. Fields include strict process units, requiring the variable verification link to match the corresponding units to avoid format errors. The process has a strict compliance sequence, requiring the workflow to bind identifiers according to linear nodes, and skipping steps is prohibited, ensuring that the business process complies with safety specifications.

## Three common misconfigurations
- The symptom is that the outputs of multiple variable update nodes cannot be aggregated into a single AI reply, and the interface displays the "variable not synchronized" error. The cause is that the `variables` of all update nodes are not configured in the global variable pool, so the AI cannot obtain integrated business data.
- The symptom is that calling the workflow API returns status code 400, prompting "opening statement parameter missing". The cause is that the `nodeId` of the opening statement node is not configured in the workflow orchestration, so external calls cannot trigger the initial business guidance.
- The symptom is that timeouts or excessive resource occupation occur when the workflow is called concurrently, and the log shows "call time exceeds threshold". The cause is that reasonable timeout thresholds and concurrency limits are not set, and the time-consuming characteristics of coal chemical industry data pulling are not matched.

## How to confirm the configuration is correct
- Check the global variable configuration items, confirm that all coal chemical industry business fields have been included in the `variables` pool, and verify that the fields and units are consistent with the internal process database.
- Traverse all workflow nodes, confirm that `nodeId` is bound in the order of the business process, with no duplicate or missing node identifiers.
- Initiate a single test call, view the variable update log, and confirm that the variables of all nodes have been synchronized to the global variable pool.
- Adjust the concurrency test parameters, observe the call status, and confirm that the timeout and concurrency settings meet the actual time-consuming requirements of the business.
