# Coal Transportation and Sales Business Process Guidance: Workflow Orchestration

## What this category of data looks like
Data for coal transportation and sales comes from the enterprise's internal transportation and sales management system, weighing system, and railway/road shipping ledger. Data is synced in real time immediately after each batch shipment is completed. Each data document is 800 to 1500 characters long, and includes fields such as cargo category, shipment volume (unit: ton), shipment time, carrier information, settlement amount (unit: yuan), and approval status. Field types cover string, numeric, and timestamp, with no deeply nested complex structures.

## How these characteristics impose constraints on workflow orchestration
Coal transportation and sales batch data is bound to a unique shipment ID. Workflows must bind batch context using `nodeId` to prevent variable conflicts between different batches. Numeric shipment volume and settlement amount fields require form input components in workflows to perform numeric range checks that match standard intervals for their respective units. Data from multiple systems requires basic format conversion between workflow nodes to unify field names for subsequent processing. Real-time updated ledger data requires workflow triggers to align with shipment nodes to ensure data timeliness.

## How to set configurations
This document applies to FastGPT v4.17.0, and the following configurations are formulated based on this version.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global variable storage | Enable `variables` persistence | Retain global data for coal transportation and sales batches, prevent loss due to conversation resets |
| Form input validation rules | Numeric range 0-120000 tons | Match standard intervals for single-batch coal shipment volumes, calibrated via actual testing |
| Workflow node timeout | 120 seconds | Adapt to response latency for pulling transportation and sales ledger data across systems |
| Trigger condition configuration | Trigger based on approval status field | Align with node transfer logic of transportation and sales processes |
| Node context binding | Bind `nodeId` as current batch ID | Ensure workflow context is associated with the corresponding shipment batch |

## Three common configuration errors
- Form input components cannot extract shipment volume values from `variables`: Symptoms include logs showing empty fields and no response after interface input. The cause is that global variable persistence is not enabled, causing variables to reset between conversations.
- Knowledge base search returns no results: Symptoms include workflow node status as failed and a prompt indicating no matching results. The cause is that no fallback logic is configured for empty search results, and no local transportation and sales ledger data is bound as a standby data source.
- Workflow node timeout error: Symptoms include return status code 504. The cause is that no timeout duration adapted for cross-system data pulling is configured; the default timeout is too short to complete ledger data retrieval.

## How to confirm proper configuration
- Initiate a simulated shipment batch process, check if batch ID, shipment volume and other data are retained in global `variables` and not reset.
- Trigger the knowledge base search node, enter a non-existent keyword, check if the preset fallback logic is triggered and returns associated data from the local ledger.
- Simulate cross-system ledger data pulling operation, check if node response latency matches the preset timeout settings and no timeout errors occur.
- Submit a form input for shipment volume value, check if the preset validation rules are triggered and corresponding prompts are given when the value exceeds the range.

The values given are common starting points and should be measured against the reader's own samples.
