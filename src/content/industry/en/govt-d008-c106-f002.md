# Business Process Guidance for Coal-Power Integration: Vector Models and Indexes

## What the Data for This Category Looks Like
Coal-power integration business process data comes from production scheduling logs, cross-department collaboration work orders, power grid connection approval documents, and equipment maintenance records. Business nodes trigger data updates. Work order data updates in real time as processing progresses. Production logs synchronize per shift. Each document includes fields such as process node sequence, responsible department, processing time limit, and required material list. Time limit units use working days, material quantity units use copies, and scheduling parameter units use tons and megawatts.

## What Constraints These Characteristics Impose on Vector Models and Indexes
Business data updates in real time as processing nodes change, requiring indexes to support incremental synchronization and avoid service freezes from full index rebuilding. The multi-field mixed document structure requires vector models to adapt to semantic associations between structured numerical values and unstructured text, rather than relying solely on general text embedding logic. The feature that field units bind to business attributes requires index construction to retain field metadata associations, to avoid confusion between processing time limits and material requirements from different business scenarios during retrieval. Cross-department collaboration process documents require the index's recall logic to prioritize matching the current node's context, only recalling content relevant to the current processing stage.

## Configuration Settings
This document is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the paragraph length of process nodes in single business documents, to avoid splitting that breaks process context |
| Overlap Length | 100–200 characters | Retains semantic associations between adjacent process nodes, preventing breaks in cross-block process logic |
| `maxToken` | 8192 token | Adapts to the average length of coal-power business documents, meeting the embedding requirements for complete process nodes |
| `defaultToken` | 1024–4096 token | Adapts to embedding short fields such as processing time limits and material quantities, avoiding token overflow |
| Single Search Limit | Top 8 results | Balances recall accuracy and retrieval efficiency, covering relevant information for core processing nodes |
| Reranking | Enabled | Sorts recall results by business relevance, prioritizing matching the current processing stage's needs |

## Three Common Configuration Errors
- Symptom: The retrieval service fails to respond for an extended period after startup, and logs show index construction timeouts. Cause: No incremental index strategy is configured for real-time update data from coal-power business, triggering full index rebuilding which causes excessive resource usage.
- Symptom: After configuring the index model, language model call parameters are lost, and process guidance content cannot be generated normally. Cause: The association between the index model and language model is not bound in the system configuration, causing the index construction to overwrite the language model's default configuration.
- Symptom: Irrelevant equipment maintenance data appears in retrieval results, and cannot match the process nodes of the current business processing. Cause: Non-business processing documents are not filtered in the index configuration, leading to an overly large recall scope.

## How to Verify Correct Configuration
- View index construction logs to confirm that incremental synchronization tasks trigger according to business update rhythms, with no duplicate records of full index rebuilding.
- Test embedding coal-power business process documents, and check that the token count of vector outputs does not exceed the configured `maxToken` limit.
- Retrieve keywords for a specific processing node, and verify that the recall results include corresponding fields such as responsible department and processing time limit.
- After switching the index model, verify that the language model can still be called normally, with no parameter loss.
