# Business Process Guidance for Coal-Electric Integration: Multi-turn Dialogue and Prompting

## What the data for this category looks like
Coal-electric integration business data originates from three core systems: mine mining scheduling systems, power production monitoring platforms, and cross-unit business approval systems.
Data update rhythms are split into two categories: real-time and scheduled. Scheduling and monitoring data updates in real time as business operations occur. Business approval report data synchronizes daily on a scheduled basis.
The document structure includes three types: structured business forms, unstructured approval attachments, and process node description documents.
Core fields include mine number, mining volume, power generation volume, approval status, and processing time limit. Corresponding units are tons, kilowatt-hours, and days respectively.

## Constraints imposed by these characteristics on the multi-turn dialogue and prompting link
The mixed data feature of structured forms and unstructured documents requires multi-turn dialogue to first clarify the business type. It then guides users step-by-step to provide corresponding field parameters. This avoids asking for too much information at once, which can cause interaction interruptions.
Real-time updated scheduling data requires limiting the effective duration of conversation context. This prevents expired data from being called, which affects the accuracy of process guidance.
Multi-node process description documents require prompts to match the current processing node in sequence. This ensures each dialogue round only outputs operation requirements for the current step, avoiding confusion between process nodes in multi-turn history.

## How to set configurations
Configurations under FastGPT v4.17.0 are listed below:

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk length | 800–1200 characters | Adapt to the paragraph length of coal-electric business documents, avoiding splitting that breaks complete process node descriptions |
| Overlap length | 150–200 characters | Retain cross-block process association information, ensuring coherent process logic during multi-turn dialogue |
| Single search limit | Top 5 entries | Match the number of associated approval documents common in coal-electric business, filtering out irrelevant content interference |
| Maximum context length | 4000–6000 tokens | Cover the full multi-turn dialogue history for a single business processing task, preventing context overflow |
| User session timeout | 1800 seconds | Match the average processing time of coal-electric business, avoiding premature session termination |
| `variables` binding | Map by business fields | Bind exclusive fields such as mine number and power generation volume, ensuring accurate data calls during dialogue |

## Three common errors
- The conversation API returns a 422 status code. Cause: The `messages` parameter format is non-compliant. Examples include missing the role field, empty content, or `variables` not binding required business fields.
- Conversation records and data are mixed across different users. Cause: `chatId` is not used correctly to distinguish independent sessions, or a shared key is not bound to a user-specific context identifier.
- Process steps returned by the dialogue lack key nodes. Cause: Chunk length is set too short, splitting complete process node descriptions and leading to loss of key information in the context.

## How to confirm the configuration is correct
- Enter required coal-electric business fields, such as mine number and processing type, and check if the dialogue correctly retrieves corresponding business data.
- Initiate a multi-turn dialogue, then continue interacting after a 10-minute interval, and check if the session has not been terminated prematurely.
- View interface logs, and confirm that the `variables` parameter has correctly passed the bound business fields.
- Test different business scenarios, and check if the returned process steps cover all complete processing nodes.
