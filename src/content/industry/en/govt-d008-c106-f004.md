# Business Process Guidance for Coal-Electric Integration: Workflow Orchestration

## What This Category of Data Looks Like
Coal-electric integration business data primarily comes from group-level business management platforms, mine production scheduling systems, power plant operation logs, and safety supervision approval systems. Data updates are triggered as business nodes progress, and are updated in real time after approval passes or materials are submitted.

## Constraints Imposed on Workflow Orchestration by These Characteristics
The structured characteristics of coal-electric integration business data impose clear constraints on workflow orchestration.
First, node sequences are defined by `nodeId`. Workflow nodes must be configured in strictly ascending `nodeId` order. Random reordering will cause process misalignment.
Second, the processing time limit field requires workflows to configure timeout trigger mechanisms to cover temporary delay scenarios.
Third, material list and approval authority fields require workflows to embed corresponding verification tools to complete material integrity and permission legitimacy verification at corresponding nodes.
Fourth, real-time updated business data requires workflows to use event-triggered modes, with no need for scheduled polling.

## How to Configure Settings

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind business code, processing time limit, and material list fields | Match the structured fields of coal-electric integration business data to enable automatic synchronization of process variables |
| `nodeId` | Configure node order in ascending order | The node sequence of business data is defined by `nodeId`, strict adherence is required to avoid process misalignment |
| Timeout Threshold | `300–600 seconds` | Matches the average processing duration of conventional coal-electric integration business nodes, covers temporary delay scenarios |
| Tool Call Node | Embed material verification and permission verification tools | Business data includes material list and approval authority fields, verification must be completed at corresponding nodes |
| Workflow Trigger Mode | Event-triggered | Business data is updated in real time as approval nodes progress, no scheduled polling required |

## Three Common Mistakes
- Phenomenon: The workflow calls the material verification tool and returns a 400 error. Cause: The material list field bound in `variables` was not correctly passed to the tool parameters, resulting in interface verification failure.
- Phenomenon: The workflow-generated process guidance chart is empty. Cause: Nodes were not configured in `nodeId` order, causing the chart node sequence to not match the business data, preventing valid view generation.
- Phenomenon: The workflow returns an image URL but cannot be rendered in the question-and-answer interface. Cause: No image rendering node was configured, only the original URL was returned, and no interface rendering tool was called to process the image link.

## How to Confirm Proper Configuration
- Review the workflow node list to confirm the node order matches ascending `nodeId` order.
- Trigger a test business data update to check whether the workflow starts automatically and progresses according to nodes.
- When invoking the tool node, verify that fields bound in `variables` are correctly passed to tool parameters.
- After configuring the image rendering node, submit a test request to confirm the interface can normally display images. Returning only the original URL does not meet expected results.
