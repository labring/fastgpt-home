# Business Process Guidance for Coal-Power Integration: Tool Calling and Plugins

## Data Profile for This Category
Business process data for coal-power integration is sourced from internal enterprise production scheduling systems, coal procurement ledgers, power plant operation logs, and government approval forms. Two update rhythms apply:
- Production and operation data is updated hourly or in real time
- Approval process data is updated when a business node is triggered

Documentation is split into three sub-libraries by business module: coal transportation, power generation scheduling, and approval work orders. Fields include coal type (unit: large calories per kilogram), power generation (unit: megawatt-hours), approval number, processing duration (unit: hours), and others. The structure is clear and tightly aligned with business requirements.

## Constraints Imposed on Tool Calling and Plugins
The multi-source, scattered data sources require tool calling to connect to multiple independent plugins, to avoid missing business information in a single call. Frequently updated production data requires that tool calling cache durations not be overly long, to prevent returning outdated coal consumption or power generation data. Professional fields and units require built-in unit conversion logic for tool calling, to ensure the professionalism and accuracy of guidance content. Node-based business processes require tool calling to trigger only at process nodes, to avoid calling redundant data unrelated to the current node. Additionally, compliance requirements for government approval data require tool calling to bind to a dedicated permission plugin, to ensure data access aligns with internal security specifications for Chinese public sector and state-owned enterprises.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling trigger timing | Trigger according to business process nodes | Coal-power business processes are divided into independent nodes such as coal transportation, power generation scheduling, and approval. Triggering by node can avoid redundant calls |
| `toolChoice` | `auto` | Coal-power business data is scattered across multiple sources. Automatic tool selection can adapt to data source requirements of different nodes, and is compatible with the tool calling logic of FastGPT v4.17.0 |
| Number of data items returned per single call | Top 3 | Single coal transportation data has large information volume. Excessive data will exceed the context window. This value is determined based on actual testing |
| Timeout setting | 600 seconds | Coal procurement approval process involves cross-department verification, so sufficient interface response time must be reserved |
| `functionCall` | Enabled | Professional plugins are required to call business logic such as coal consumption calculation and power generation prediction. Enabling this allows binding of preset business plugins |
| Knowledge base association scope | Only associate the dedicated knowledge base for coal-power business processing | Avoid interference from irrelevant data to ensure the accuracy of business process guidance |

## Three Common Misconfigurations
- Symptom: API call returns `messages is empty` error. Cause: No coal-power business-specific knowledge base and plugins are bound in the tool calling configuration, so the system cannot retrieve valid context data.
- Symptom: Coal consumption data returned by tool calling does not match actual ledger records. Cause: Tool calling is not configured to trigger by business nodes, resulting in calls to outdated cross-period data.
- Symptom: Thought chain output omits the plugin calling process. Cause: Log output configuration for `functionCall` is not enabled, so the system does not record the full tool calling workflow.

## How to Verify Correct Configuration
- Access the FastGPT application debugging interface, trigger a simulation node for coal-power business processing, and check if the tool calling log shows correct plugin and knowledge base association information.
- Submit a query containing coal-power professional terminology, and confirm that the called tool matches the current business node.
- Review the API return log, confirm that the `messages` field contains valid context data with no null value errors.
- Enable the thought chain output configuration, and confirm that the returned result includes a full record of the tool calling process.
