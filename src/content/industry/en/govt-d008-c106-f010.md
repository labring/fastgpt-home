# Coal-Electric Integration Business Process Guidance: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Coal-electric integration business process data draws from four core sources: internal enterprise mine production ledgers, thermal power unit operation procedures, cross-departmental business approval manuals, and compliance review documents. Two update schedules apply: core business process documents sync and update quarterly, while real-time work order and approval status data syncs daily. Documents split by business node. Each document includes fields such as business node ID, handling subject, required material list, approval time limit, and compliance check requirements. Units use business-specific measures including working days, copies, and sets.

## What constraints these characteristics impose on knowledge base retrieval and recall
Coal-electric integration business data characteristics create three constraints for retrieval and recall:
1. The document structure split by business node requires retrieval to support filtering recall scope by node ID, preventing irrelevant content from cross-business nodes from being included.
2. The daily sync schedule for real-time work order and approval status data requires vector database update frequency to match the daily sync cycle, preventing outdated approval status information from being recalled.
3. Business-specific compliance check fields require retrieval to prioritize documents with compliance requirements, ensuring guidance content aligns with state-owned enterprise and public sector compliance standards.
Additionally, cross-departmental collaborative business processes require recall results to cover documents for upstream and downstream associated nodes, preventing incomplete guidance information.

## How to set the configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the professional terminology density of coal-electric business processes, to avoid recalling irrelevant equipment operation and maintenance documents |
| `limit` | Top 8 entries | Covers documents for multiple links such as associated approvals and material requirements for a single business node |
| `searchMode` | hybrid | Combines keyword and vector retrieval, adapting to structured business process fields |
| `usingReRank` | Enabled | Re-ranks recalled process documents by business node relevance, to avoid low-relevance content appearing first |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands business terminology, such as expanding "grid connection approval" to "power grid connection process approval" |
| `collectionIds` | Bound to coal-electric business process exclusive dataset | Isolates documents from other categories, to avoid mixing irrelevant content during retrieval |

## Three common configuration errors
- Phenomenon: Question answering throws an error after adding a knowledge base, even though knowledge base search tests run normally. Cause: `collectionIds` is not bound to the coal-electric business process exclusive dataset. Retrieval mixes invalid documents from other categories, triggering an error for exceeded context length limits.
- Phenomenon: No progress displays and switching back to the original vector model fails after switching the knowledge base vector model. Cause: The `collectionIds` scope is not restricted. The model loads all enterprise documents during loading, exceeding system resource thresholds and failing to complete loading.
- Phenomenon: The same question returns different answers. Cause: `usingReRank` is disabled and the `similarity` threshold is set too low. Retrieval recalls multiple irrelevant process documents, creating context conflicts and generating inconsistent guidance results.

## How to confirm the configuration is correctly set
- Access the knowledge base retrieval test page in FastGPT v4.17.0, enter a question related to coal-electric grid connection approval, and verify that returned results only include coal-electric business process documents.
- Open the configuration panel, confirm that `usingReRank` and `datasetSearchUsingExtensionQuery` are both enabled.
- Manually adjust the `similarity` threshold to 0.75, and check whether retrieval result relevance changes as expected.
- Wait 300 seconds after switching the vector model, confirm the progress bar completes and the original configuration parameters can be restored.
