# Coal-Electric Integration Business Handling Process Guidance: Deployment and Upgrade

## What the data for this category looks like
Coal-electric integration business data sources include mine production monitoring systems, power generation dispatching platforms, cross-regional coal transportation ledgers, equipment operation and maintenance inspection reports, and more. Update frequencies fall into three categories: real-time (such as power generation load and gas concentration data), daily (such as production daily reports), and monthly (such as energy consumption statistical reports). Document structures include structured business documents (with fields like mine number, dispatch order number, coal consumption rate) and unstructured reports (inspection documents with images and tables). Field units include megawatt-hours, tons, cubic meters, and others.

## What constraints these characteristics impose on the deployment and upgrade phase
Structured data for coal-electric integration business is mostly stored in relational databases. Unstructured files are large in size and mostly deployed in internal network environments. Real-time data update frequency is high. Therefore, priority must be given to connecting to internal network databases and storage services during deployment. During upgrade, the database connection pool configuration must be adapted synchronously to avoid stuttering of the business handling process guidance function caused by insufficient connection count. Attention must also be paid to internal network access permission configuration to prevent the system from blocking internal business requests. Different versions of FastGPT have different requirements for plugin dependencies, so the compatibility of file processing plugins must be verified during upgrade.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://coal_user:secure_pass@internal-db:5432/coal_power` | Coal-electric integration business approval documents and dispatching ledgers are mostly stored in PostgreSQL databases. The internal business database must be connected to obtain process handling data |
| `REDIS_URL` | `redis://:redis_auth@internal-cache:6379/0` | Real-time power generation load and mine monitoring data must be cached to reduce database query pressure and ensure the response speed of process guidance |
| `DB_MAX_LINK` | `100–150` | Coal-electric business real-time data request frequency is high. The database connection pool scale must be controlled to avoid overload and ensure stability when multiple users initiate process queries simultaneously |
| `STORAGE_S3_ENDPOINT` | `http://internal-s3:9000` | Large unstructured files such as inspection reports and equipment operation and maintenance documents must be stored. Internal network nodes can ensure file loading speed and security |
| `FILE_TOKEN_KEY` | `Exclusive key generated by the business system encryption algorithm` | Access tokens must be generated for sensitive files in the business handling process to prevent unauthorized access to process-related documents |

## Three common errors
- Phenomenon: After upgrading FastGPT v4.17.0, an error `cannot fetch internal url` is prompted when creating a knowledge base using an internal business system URL. Cause: The internal network access whitelist is not configured, or `FE_DOMAIN` is not bound to the internal business domain name, causing the system to block internal requests.
- Phenomenon: The background log shows that the file processing plugin cannot be found. Cause: The plugin dependency package was not updated synchronously during upgrade, or the `STORAGE_S3_ENDPOINT` configuration is incorrect, causing the plugin to fail to load the storage configuration.
- Phenomenon: An error occurs when testing with Alibaba Cloud Bailian or Ollama models, and the image was pulled on the same day. Cause: The permission scope of the model API key is not configured correctly, or the authentication parameters such as `ROOT_KEY` are not loaded correctly in the locally deployed environment variables.

## How to confirm the configuration is correct
- Submit the business system URL in the internal network environment, create a knowledge base, and verify that structured documents and unstructured documents can be pulled normally.
- Enter the background plugin management page, confirm that the file processing plugin status is enabled, and there are no abnormal error prompts.
- Submit a query request containing complex engineering formulas, and verify that the results can be parsed and returned normally.
- Check the database connection logs, confirm that there are no timeout or disconnection errors in the connection pool configured by `PG_URL` and `REDIS_URL`.

The values provided are common starting points and should be measured against the reader's own samples.
