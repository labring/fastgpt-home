# Business Process Guidance for Coal Mine Production: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
Core data for coal mine production business process guidance is sourced from underground work order systems, safety supervision reporting platforms, and production scheduling ledgers. It covers all business handling scenarios including work application, on-site verification, approval, completion, and more. Data is updated when business nodes are triggered, with no fixed cycle, and fully aligns with the actual progress of business handling. The data structure uses standardized JSON format, including fields such as work order ID, processing node, handler, approval status, and associated equipment number. The equipment number is a 12-digit numeric string, and processing nodes are fixed enumeration values.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
The structured JSON format and enumeration field requirements of coal mine business data require HTTP interfaces to strictly match parameter formats and field enumeration values. Failure to do so will cause data parsing failures. The real-time data update feature triggered by business nodes requires interfaces to support real-time callbacks or short-interval polling to ensure the timeliness of business guidance. The fixed-length format of associated equipment numbers requires interfaces to add parameter verification logic to filter invalid requests. The long duration of typical business approval processes requires interface timeout settings to adapt to actual business durations, preventing interruptions to the guidance process.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer coal mine-specific API key` | Adapts to the Bearer token authentication specification for external coal mine systems, ensuring interface call security |
| `variables` | `{"workOrderId": "{{work order ID variable}}", "deviceCode": "{{equipment number variable}}"}` | Matches core query fields for coal mine business handling, unifying parameter mapping rules |
| `responseData` | `$.data[0]` | Adapts to the single work order return data structure of most coal mine production systems, quickly extracting target business information |
| Interface timeout duration | 600 seconds | Covers the average processing duration of coal mine approval processes, avoiding timeout errors triggered by prolonged approval times |
| Request retry count | 3 times | Responds to temporary network fluctuations in coal mine systems, ensuring the stability of business process guidance |
| Parameter verification switch | Enabled | Verifies the format compliance of work order IDs and equipment numbers, filtering invalid requests |

## Three Common Misconfigurations
- The interface returns a 401 Unauthorized error, and the interface prompts authentication failure. The cause is that the `Authorization` parameter is not configured correctly, and an expired coal mine system API key is used.
- Pulled business node data is empty, and the work order status remains unchanged. The cause is that the correct path for `responseData` is not matched, and non-business data fields from the outer layer are incorrectly extracted.
- Interface calls frequently trigger timeouts, and business guidance stalls. The cause is that the interface timeout duration is set to 120 seconds, which does not cover the average duration of coal mine approval processes.

## How to Verify Successful Configuration
- In the FastGPT v4.17.0 environment, call the configured HTTP interface, pass a real coal mine work order ID, and check if the returned business node data matches the coal mine system ledger.
- View the FastGPT interface call logs to confirm that the `Authorization` parameter is correctly carried, with no authentication failure records.
- Simulate a business process node trigger, check if the system can automatically pull the latest approval status and update the guidance process.
- Test passing an equipment number that is not 12 digits, confirm that the interface returns a format error prompt, and verify that the parameter verification switch is active.
