# Business Process Handling Guidance for Coal Mine Production: Multi-turn Dialogue and Prompt Engineering

## What This Category’s Data Looks Like
Business process data for coal mine production mainly comes from internal approval systems, dispatching operation logs, safety operation regulations, and post operation guidance manuals. Two update schedules apply: dispatching-related data is synchronized and updated daily; regulation-related data is adjusted on demand alongside policy or operation standard changes. Documents are organized by business type, and include fields such as work ticket number, approval node, completion time limit, and hidden danger level. Common units are hours, items, and articles.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The classified attributes of business data require multi-turn dialogue to first identify the current business type being processed, to avoid confusion between approval processes and safety inspection processes. The specific units and exclusive identifiers of fields require prompts to clearly guide extraction of compliant fields such as work ticket numbers and approval time limits, preventing generation of content that violates coal mine operation specifications. Frequently updated dispatching data requires the valid duration of dialogue context to match the data update cycle, avoiding use of expired information. The strict compliance requirements of safety-related business require multi-turn dialogue to verify consistency between generated content and current regulations.

## Configuration Guidelines
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | First 8 turns of dialogue + current query | Matches typical node flow steps for coal mine business processing, avoids interference from redundant historical content |
| Single Dialogue Token Limit | 8000 token | Covers complete node descriptions and regulation content for a single work approval ticket |
| `variables` Binding Rules | Bind work ticket number, hidden danger level | Adapts to exclusive field formats for coal mine business |
| `chatId` Association Configuration | Bind the unique ID of the current work ticket | Enables associated tracking between dialogue and business documents |
| `messages` Format Validation | Mandatory inclusion of business type identifier | Avoids confusion between approval and safety inspection processes |
| Context Refresh Threshold | Clean up non-core history every 3 dialogues | Prevents expired dispatching data from impacting current judgments |

## Three Common Misconfigurations
- Connection error after submitting dialogue. Cause: Model API call link is not correctly configured, and coal mine intranet network access restrictions are not accommodated.
- Images returned by the knowledge base cannot be displayed in dialogue. Cause: The prompt does not explicitly require the large model to label image reference paths or placeholder identifiers.
- Variables such as operation date and hidden danger level in dialogue cannot be accurately extracted. Cause: Variable extraction rules are not configured for exclusive fields of coal mine business, and the prompt does not clearly specify field format requirements.

## How to Confirm Configuration is Active
- Simulate a business dialogue, verify the returned historical context includes the most recent 8 turns of dialogue content, confirming the context length configuration is active.
- Submit a query containing work ticket number and hidden danger level, verify the returned result correctly extracts corresponding variables, confirming the `variables` binding rules are active.
- Initiate a multi-turn dialogue across nodes, check for connection errors, confirming network configuration and API link are correct.
- Submit a query containing image references, verify the large model labels image paths as required by the prompt, confirming image display configuration is active.
