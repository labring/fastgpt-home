# Business Process Guidance for Coal Mine Production: Forms and Interactions
Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Coal mine production business processing data mainly comes from internal production scheduling systems, safety supervision ledger databases, and business approval form systems. Data is updated in real time as business triggers occur. Monthly safety inspection data is updated in batches on a natural day basis. Documents use structured form format, with core fields including work ticket number, work type, work location, approval chain node, and completion deadline. Some associated fields have attached units: work duration is measured in hours, equipment numbers are 6-digit underground mining codes, and work locations must match preset roadway area codes.

## What constraints these characteristics impose on forms and interactions
Structured fields and preset unit requirements mean form interactions must strictly match preset formats, to prevent non-standard input from making data unable to be associated. Real-time updated business data requires that form submissions are immediately synchronized to the backend system, to avoid data lag. Fixed configuration of approval chain nodes means the interaction process must strictly follow preset approval levels, and node order cannot be adjusted arbitrarily. Preset roadway area codes require that auto-complete options are provided during input, to prevent business flow abnormalities caused by incorrect area codes. Unit binding for associated fields requires that the form automatically fills in unit information, to reduce manual input errors.

## Three common mistakes
- Phenomenon: A "field format mismatch" error is returned after submitting the form, and no auto-complete options are displayed for the work location field. Cause: The roadway area code library is not loaded as an auto-complete data source, causing input to fail to match preset rules.
- Phenomenon: Retrieval cannot be completed when multiple knowledge bases are selected, or the retrieval result is empty. Cause: The multi-data source binding configuration of `formInput` is not enabled, and only the data source of a single knowledge base is bound.
- Phenomenon: Variables cannot be inserted into the JSON input box, and a "parameter format error" is returned after submission. Cause: Variable insertion support for `formInput` is not enabled, causing the input box to fail to recognize variable syntax.

## How to confirm the configuration is complete
- Manually enter a work ticket number that conforms to the preset format, check whether the unit information of the associated field is automatically filled.
- Select the work location field, verify that a preset list of roadway area code auto-complete options pops up.
- Submit a test form, check whether the backend system receives the submitted data in real time.
- Trigger the approval node selection, verify that only preset approval chain node options are displayed.
