# Business Application Process Guidance for Power Grid Enterprises: Forms and Interactions

## What the data for this category looks like
Data comes primarily from power grid marketing business systems, electricity consumption collection platforms, and offline service work order libraries. The update schedule falls into two categories: real-time submitted power service applications, and existing business archives synchronized daily. The document structure includes user identity identifiers, electricity usage addresses, business types (new installation, capacity increase, electricity usage change, etc.), application material lists, and processing progress fields. Field units include kilovolt-ampere (kVA), household number codes, status identifiers, and more. Some fields must match the unified power grid business coding rules.

## What constraints these characteristics impose on the forms and interactions link
Business types cover more than ten compliant scenarios, so forms must split interaction modules by business category to avoid excessive fields disrupting users. Fields must match the unified power grid business coding rules, so `formInput` requires configuration of format verification rules to limit input length and character types. Real-time submitted power service applications must prevent duplicate submissions, so the interaction link must add submission debounce logic. Application materials must comply with power grid archiving specifications, so forms must limit uploaded file formats and single-file size.

## Configuration settings
The following configurations apply to FastGPT v4.17.0

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `formInput` | Configure format verification according to power grid business fields, such as 10-digit numbers for household numbers, electricity capacity 0-10000 kVA | Match the unified power grid business coding and field specifications to avoid invalid inputs |
| Business category dropdown options | Preset options including new installation, capacity increase, electricity usage change, and account transfer according to the official power grid business list | Cover all compliant business types and reduce manual input errors from users |
| Submission debounce duration | 3000 milliseconds | Prevent duplicate work order creation caused by frequent duplicate submissions, and adapt to the audit delay characteristics of power grid businesses |
| File upload restrictions | Maximum 10 MB per file, formats supported: PDF, JPG, PNG | Match the specification requirements of power grid archived materials and control storage and transmission costs |
| `userSelect` | Bind verified user household number lists | Reduce errors from manual input of identity information by users and improve processing efficiency |
| Progress query entry configuration | Automatically generate a dedicated query link after form submission | Facilitate real-time tracking of processing status by users and meet the transparency requirements of power grid services |

## Three common misconfigurations
- Symptom: Form submission prompts field format errors but does not indicate the error location. Cause: Precise `formInput` verification rules are not configured for power grid business-specific fields, only general length limits are set.
- Symptom: Multiple duplicate work orders are generated after form submission. Cause: Submission debounce duration is not configured, or the debounce duration is set too short to adapt to the audit response delay of power grid businesses.
- Symptom: Input over-limit prompt is triggered when entering long text in the form. Cause: The maximum input token length of `formInput` is not configured, and it does not match the text length requirements of power grid business application materials.

## How to confirm the configuration is complete
- Manually enter field values that do not comply with power grid business specifications. The verification prompt should accurately point to the incorrect field and format requirements.
- Quickly click the submit button repeatedly to confirm that only one work order is generated, and the debounce logic takes effect.
- Upload compliant files and long text to confirm that the form can be submitted normally without over-limit prompts.
- Switch between different business types to confirm that associated form fields are automatically updated and the linkage logic works properly.
