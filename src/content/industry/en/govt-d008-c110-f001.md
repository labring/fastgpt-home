# Mining and Mineral Processing Business Handling Process Guidance: HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data is sourced from underground production monitoring platforms, mineral processing DCS control systems, and mining right and approval management systems. Production-related data updates every 10 seconds. Approval process data updates when a business handling node is triggered. Data is packaged in JSON format, with core fields including mining face number, raw ore grade (unit: grams per ton), mineral processing throughput (unit: tons per hour), approval link status, and handling time limit (unit: working days). Field names fully match internal mine business ledgers, with no redundant nested levels.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Production-related data updates at high frequency. Interfaces must support low-latency responses.
The timeout period for a single request must match the data update cycle. This prevents lagging process guidance information caused by timeouts.
Field names must align with internal mine ledgers. Interface request and response parameters must strictly follow the mine system’s field specifications. Field names or units cannot be adjusted arbitrarily.
Approval process data updates when a node is triggered. Interfaces must support event callback mode. This ensures real-time synchronization of business handling status.
The JSON data structure requires the interface to use a fixed Content-Type of application/json. This avoids parsing errors.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {mine system exclusive API key}` | Matches the standard authentication rules of internal mine systems to ensure interface access security |
| `variables` | Bind the three core fields of mining face, raw ore grade, and approval status | Enables dynamic replacement of process guidance content to fit actual business scenarios |
| `responseData` | Extract the current approval process handling node and remaining time limit | Filters non-core data to shorten the FastGPT processing chain |
| Interface timeout period | 5 seconds | Matches the update cycle of mine production data to avoid lagging guidance information |
| Request retry count | 2 times | Addresses temporary request failures caused by mine network fluctuations to ensure call stability |
| Maximum response data size | 1000 KB | Adapts to the production data volume returned by the mine system in a single call to avoid memory overflow |

## Three common errors
- Phenomenon: The interface call returns a 429 Too Many Requests status code, and the process guidance is interrupted. Cause: No request interval and retry strategy are set. High-frequency calls trigger the current-limiting rules of the internal mine system.
- Phenomenon: The approval status displayed in the business handling process does not match the actual node. Cause: The approval system is connected using only fixed-period pull requests instead of event callback mode, resulting in delayed status updates.
- Phenomenon: FastGPT cannot parse the production data returned by the interface, and the guidance content is empty. Cause: The field naming specifications of the mine system are not strictly followed, causing `variables` to fail to bind data fields correctly.

## How to confirm the configuration is complete
- Call the configured interface, check whether the returned JSON data fully aligns with the ledger fields of the mine system, and adjust the extraction rules of `responseData` according to business needs.
- Simulate high-frequency interface requests, check whether current-limiting errors are triggered, and adjust the request interval and retry count based on the current-limiting threshold of the mine system.
- Trigger a business handling node change, confirm that FastGPT can obtain the latest approval status in real time, and verify the configuration effectiveness of the event callback mode.
- Check the interface logs of FastGPT v4.17.0 to confirm that the `Authorization` authentication field is correctly carried, with no authentication failure errors.
