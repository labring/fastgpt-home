# Business Process Guidance for Mining and Mineral Processing: Knowledge Base Retrieval and Recall

## What this category of data looks like
Business processing data for mining and mineral processing comes primarily from production scheduling systems, mineral processing workshop process logs, safety compliance archives, and business approval forms. Data update frequencies cover real-time (equipment operating parameters), daily (production daily reports), and on-demand (approval process documents). Most documents combine structured tables and long text, with fields including mining area, shift output, equipment load, hidden trouble inspection items, and others. Units involve professional industrial parameters such as tons, cubic meters, hours, and megapascals.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The high volume of structured parameters and dense professional units in mining and mineral processing requires retrieval to prioritize precise field matching, focusing on alignment between professional parameters and process steps. Real-time updated equipment operating data requires the recall link to support low-latency refresh, preventing the return of outdated parameters. Long-text production reports and approval documents require reasonable text chunk splitting, avoiding overly long single chunks that impact semantic matching. Additionally, business process steps are bound to fixed fields, so retrieval results must be associated with corresponding process nodes to avoid irrelevant content interfering with guidance.

The following configurations are adapted for FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the precision requirement for matching mining and mineral processing terminology, avoids introducing irrelevant parameters if set too low, and avoids missing valid process steps if set too high |
| `limit` | Top 8 entries | Business process guidance needs to cover all steps, recall sufficient process nodes and parameter records in a single pass, avoiding incomplete guidance caused by too few results |
| `searchMode` | Hybrid retrieval | Balances structured field matching and full-text semantic recall, adapting to the document structure of mining and mineral processing that includes both parameter tables and process text |
| `usingReRank` | Enabled | Reorders recall results by business process relevance, prioritizing earlier approval and operation steps |
| `datasetSearchUsingExtensionQuery` | Enabled | Optimizes current queries based on historical processing records, resolving reference resolution issues for process steps |
| `collectionIds` | Bind three dedicated knowledge base collections: mining, mineral processing, and compliance | Precisely limits the retrieval scope, avoiding interference from cross-category documents on business process guidance |

## Three common mistakes
- Phenomenon: Knowledge base API calls return ambiguous process steps that cannot be associated with specific mining areas from historical processing records. Cause: The `datasetSearchUsingExtensionQuery` configuration is not enabled, and current queries are not optimized based on historical records.
- Phenomenon: GPU resources do not start after initiating knowledge base retrieval, and tasks remain unresponsive for extended periods. Cause: `collectionIds` is not limited to the dedicated mining and mineral processing collection, and the retrieval scope covers irrelevant documents, causing abnormal resource occupation.
- Phenomenon: Retrieval configuration reverts to default values after being saved, and custom parameters cannot be retained. Cause: The collection binding status is not confirmed on the knowledge base management page, and the configuration is not synchronized to the corresponding dataset.

## How to confirm the configuration is set correctly
- Access the knowledge base retrieval debugging page, input a query containing a mining area number, and verify that returned results are associated with process steps for the corresponding mining area.
- View the GPU resource monitoring panel, confirm that GPU load shows corresponding fluctuations after retrieval is initiated, with no abnormal idle state.
- Save the custom configuration, exit the page, re-enter the configuration interface, and verify that parameters are retained as the custom values.
- Input a query containing only professional units, and verify that returned results include records of corresponding industrial parameters.

The values provided are common starting points and should be measured against the reader's own samples.
