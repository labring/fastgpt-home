# Business Process Guidance for Mining and Mineral Processing: Deployment and Upgrade

## What the data for this category looks like
Business data for mining and mineral processing originates from mine production ledgers, mineral processing process parameter records, mining right approval archives, and compliance inspection documents. Production ledgers update daily. Approval documents update at each processing node. Compliance archives undergo quarterly reviews. Most documents are structured forms and process descriptions, with fields including application number, processing link, submitted material list, responsible department, actual output tonnage, equipment runtime, and more. Units include tons, hours, cubic meters, and other standard units.

## What constraints these characteristics impose on the deployment and upgrade phase
The structured forms and multi-source data characteristics of mining and mineral processing require plugin configurations adapted to multi-format document parsing during deployment. Daily updated production data needs scheduled synchronization tasks configured to prevent data lag from affecting the accuracy of process guidance. Field differences across processing links are significant, so field mapping rules must be sorted out in advance. During upgrades, the logic of old version fields must be compatible to prevent missing fields in process guidance. Additionally, single-batch business data volume is large, so cache configurations for storage components must be adjusted to avoid read timeouts and ensure smooth business process guidance.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom password@deployed server IP:6379/0` | Session caching for mining and mineral processing business requires stable connections. This configuration defines the cache service address to ensure uninterrupted sessions for process guidance |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-North China 1.aliyuncs.com` (or local storage node address) | Documents and production data for mining and mineral processing have large volume. This configuration sets a S3-compatible storage endpoint to ensure data storage and reading efficiency |
| `DB_MAX_LINK` | `20–30 connections` | Single-batch business data volume is large. This parameter controls the maximum number of database connections to avoid process guidance lag caused by exhausted connections |
| Chunk length | `800–1200 characters` | Process documents for mining and mineral processing mostly contain long paragraph step descriptions. This length fully covers core information of a single step to avoid chunk breakage |
| Single search limit | `Top 8 results` | Reference documents for business process guidance are mostly categorized by link. This limit covers all reference materials for a single link to avoid missing key steps |
| File upload size limit | `1000 MB` | Compliance documents and production ledgers for mining and mineral processing are mostly large scanned files or spreadsheet files. This limit adapts to common document sizes |

## Three common mistakes
- After deployment, accessing the business guidance page returns a 503 status code. Page loading times out, and process step content fails to load. The cause is an incorrect `REDIS_URL` configuration. The cache service cannot connect normally, so session status cannot be read.
- After upgrade, guidance content for some process nodes is missing. Uploaded documents in the knowledge base cannot be retrieved. The cause is that field mapping rules were not configured in advance. The upgraded knowledge base parsing logic is incompatible with old version fields, so documents cannot be indexed normally.
- After initiating a business process query, no results are returned, and an empty list is displayed. The cause is that `DB_MAX_LINK` is set too low. Database connections are exhausted, so process document data cannot be read.

## How to confirm the configuration is correct
- Log in to the FastGPT admin backend, check the filled content of configuration items such as `REDIS_URL` and `STORAGE_S3_ENDPOINT`, and confirm they match the actual deployed cache and storage service addresses.
- Upload a mining and mineral processing process document, perform a retrieval test, and confirm that matching process step content can be retrieved.
- Initiate a simulated business process query, check if the returned guidance content contains complete process node information, and confirm there are no missing fields or content breakages.
- View system logs, confirm that database connection counts do not show continuous peaks, and there are no error reports about exhausted connections.
