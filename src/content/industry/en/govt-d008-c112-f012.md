# Grain Reserve Business Process Guidance: Deployment and Upgrade

## What the data for this category looks like
Grain reserve business process data comes from internal grain depot business management systems and submitted data from local grain and material reserve departments. The update rhythm is immediate sync after a single business transaction is completed, and daily batch report updates. The document structure is divided into two categories: structured process fields and unstructured attachments. Structured fields include approval number, depot ID, grain category, storage quantity, processing node, etc. Units include tons and batch numbers, and the date format is YYYY-MM-DD. Unstructured attachments include quality inspection reports, outbound vouchers, and other business materials.

## What constraints these characteristics impose on deployment and upgrade
Structured fields are numerous and have strict requirements for unit standardization. Configure field validation rules during deployment to avoid retrieval chaos caused by non-standard data access. Unstructured attachments account for a large proportion. Maintain compatibility with original file storage paths during upgrades to prevent existing attachment retrieval links from failing. Business data updates follow two rhythms: immediate and batch. Configure both incremental sync and full sync modes during deployment to adapt to data update needs of different scenarios. Process node fields are fixed. Knowledge base chunking must match the document structure of process nodes to avoid a disconnect between chunking logic and business processes.

## How to set the configurations

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 connections` | Grain reserve business includes structured fields and unstructured attachments. The connection pool upper limit must adapt to multi-task sync requirements, and is calibrated based on actual testing |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/grain_reserve` | Stores structured process fields and historical retrieval logs. Requires an independent database instance to ensure data isolation |
| `PG_URL` | `postgresql://user:pass@host:5432/grain_flow` | Stores status change records of process nodes. Relational databases adapt to structured query requirements |
| `REDIS_URL` | `redis://:pass@host:6379/0` | Caches validated field data and temporary sync task status to reduce database access pressure |
| `STORAGE_S3_ENDPOINT` | `http://s3-grain-reserve.example.com` | Stores unstructured attachments such as quality inspection reports and outbound vouchers, adapting to the file storage requirements of grain reserve business |
| `ROOT_KEY` | `32-character random string` | Used as an access token for encrypting sensitive business data to ensure data security |

## Three common mistakes
- Phenomenon: The container returns a `ROOT_KEY` verification failure error after startup, and the management backend cannot be accessed. Cause: No valid random string is generated as the root key, and using the default configuration directly causes identity verification failure.
- Phenomenon: Inconsistent inventory data with mixed units of "tons" and "kilograms" appears in retrieval results. Cause: No unit standardization validation rule is configured during data access, and the unit format of structured fields is not standardized, leading to inconsistent knowledge base content.
- Phenomenon: Scheduled sync tasks time out, and some process data fails to complete sync. Cause: The `DB_MAX_LINK` parameter is not adjusted to adapt to the concurrency requirements of batch sync, and the database connection pool is exhausted, causing task interruption.

## How to confirm the configuration is complete
- Check container startup logs to confirm there are no errors such as database connection failures or `ROOT_KEY` verification failures.
- Upload test unstructured attachments to verify that files can be normally obtained from the corresponding storage path.
- Trigger a simulated business data sync task to confirm that structured records matching the preset format are generated in the database.
- Log in to the management backend to view field mapping configurations, and confirm that the standard process fields of the grain reserve business have been associated.
