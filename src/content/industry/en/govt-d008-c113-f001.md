# Business Process Guidance for Shipbuilding: HTTP Interfaces and External Systems

## What the data for this category looks like
Shipbuilding business process data primarily comes from internal production chain systems including production management systems, material requirements planning systems, and block quality inspection systems. Data updates trigger based on production batches. Daily process progress updates occur during the construction cycle of a single ship block. Weekly overall status updates happen during the full ship delivery cycle. The data document structure includes fields such as ship type code, block ID, process number, material code, completion status, inspection time, and responsible person. Units cover industrial standard units including meters, tons, hours, and batch numbers. Fields have high correlation, so precise filtering via business dimension parameters is required.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The multi-system source of shipbuilding business data and high field correlation require HTTP interface requests to carry precise business dimension parameters. Without these parameters, valid production data cannot be returned. The batch-based update rhythm requires interfaces to support dynamic parameter input to adapt to query needs across different construction stages. Industrial standard fields and units require interface returned data to strictly match preset field names. This avoids errors in business guidance information caused by format incompatibility. Internal systems of shipbuilding enterprises usually have strict identity verification rules. HTTP interface identity verification configurations must align with internal permission systems.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {Enterprise Internal API Key}` | Matches the identity verification rules of shipbuilding enterprise internal systems to ensure lawful interface access permissions |
| `variables` | Pass `ship type code, block ID, process type` | Matches the core query dimensions of the business process to accurately locate corresponding production data |
| `responseData` | Only return `process status, completion progress, inspection result` | Reduces invalid data transmission and adapts to the lightweight information needs of business guidance |
| Timeout | `30 seconds` | Multi-system linked queries in shipbuilding usually take moderate time, and 30 seconds covers most conventional scenarios |
| Maximum Returned Entries | `Top 20` | The volume of process data for a single batch of ship blocks is usually limited, avoiding redundant returned information |
| Semantic Matching Threshold | `0.75–0.85` | Calibrated through actual testing, meeting the semantic similarity requirements for shipbuilding professional terminology |

## Three Common Mistakes
- Empty fields return after calling the interface: Cause: The shipbuilding-specific block ID or ship type code parameter was not passed in `variables`, causing the system to fail to match corresponding production data.
- Interface call failure prompt appears in the interface, but external testing tools return normal results: Cause: The `Authorization` configuration does not carry the specific prefix required by the enterprise internal system, or the key permission does not cover the corresponding business module.
- Knowledge base search node in the workflow cannot read the passed knowledge base variables: Cause: The variable was not configured as a global variable allowed to be passed by external APIs, causing parameters to fail to transfer between nodes.
