# Business Process Guidance for Shipbuilding: Tool Calling and Plugins

## What this category of data looks like
Shipbuilding business processing data mainly comes from shipyard production scheduling systems, ship classification society inspection and filing systems, and on-site construction work order libraries. Data updates are triggered by job nodes. Construction work orders are synced in real time. Inspection reports are updated within 24 hours after a single inspection is completed. Document structures include fields such as work order unique identifier, ship model, work link code, material code, inspection status, and planned completion duration. Field units include tons, pieces, hours, and days. Enumerated fields are fixed to four categories: pending, in progress, completed, and rejected.

## What constraints these characteristics impose on the tool calling and plugins workflow
The multi-source heterogeneous nature of shipbuilding business data requires plugins to connect to APIs of multiple systems including production scheduling and inspection filing systems, and adapt to different API authentication rules and return formats. Real-time updated business nodes require tool calling timeout thresholds to match job response rhythms, to avoid process blocking caused by overly long waits. Fixed-format fields such as 12-digit material codes and enumerated inspection statuses require plugin input parameters to have built-in format validation rules, automatically filter invalid inputs, and reduce invalid requests to downstream systems.

| Result display format | Display associated materials and inspection status grouped by work order ID | Business processing scenarios require quick access to associated information; grouped display aligns with operator viewing habits |

## Three common configuration errors
- Phenomenon: Image URLs returned by plugins cannot be displayed directly in the interface. Cause: Media field mapping is not enabled in plugin configuration, and the image URL field is not marked as a renderable type.
- Phenomenon: Predefined context variables cannot be selected in the JSON input box. Cause: The plugin's variable binding permission is not enabled, or the JSON input box is not configured to support variable insertion format.
- Phenomenon: Plugins cannot be successfully published to the community marketplace. Cause: Scene category tags are not filled in accordance with specifications, and relevant information about the shipbuilding business scenario is not labeled.

## How to confirm the configuration is correct
- Initiate a simulated call, pass a work order ID and material code that meet format requirements, and check whether the returned result includes associated inspection status and material information.
- Check the plugin's parameter validation rules, input an illegally formatted material code, and confirm whether the system triggers a format error prompt.
- View the tool calling logs, confirm that the timeout setting matches the conventional response rhythm of the business system, and no frequent timeout errors occur.
- Verify the variable binding function of the JSON input box, insert a predefined context variable, and confirm that the input box can correctly parse the variable value.

The values listed above are common starting points and should be evaluated against the user's own samples.
