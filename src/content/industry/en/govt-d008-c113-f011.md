# Business Process Guidance for Shipbuilding: Forms and Interactions
This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Shipbuilding business process data primarily originates from shipyard production execution systems, classification society compliance approval systems, and material supply chain management systems. Production process data is updated in real time alongside on-site job nodes. Approval data is synchronized after each individual process node is completed. Material data is synchronized in daily batches. The document structure includes fields such as ship identification number, block number, process code, material specification, approval status, and processing time limit. Units include engineering standard units such as meters, tons, hours, and vessels. The number of fields per single data entry stays consistently between 15 and 20.

## What constraints do these characteristics impose on the forms and interactions link
The multi-source and heterogeneous nature of shipbuilding business data requires form interactions to support mapping and adaptation of fields from multiple systems, to avoid redundant fields disrupting the processing flow. Real-time updated production process data requires form input content to be validated against real-time data from the current job node, to prevent process status conflicts. The node-based characteristics of approval processes require forms to be split and displayed according to processing links, only loading fields required for the current link, to reduce user cognitive load. The fixed unit requirement for material specification fields requires preset unit options in the form, to reduce manual input errors and validation costs.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable field format validation, match engineering unit rules | Shipbuilding forms contain a large number of specification parameters with units, which requires avoiding unit input errors |
| `userSelect` | Preset classification society approval node options | Business process nodes are fixed, preset options can reduce manual input errors |
| Block rendering length | 800–1200 characters | Business process forms mostly contain process descriptions and material lists, block length adapts to the information volume of a single link |
| Timeout wait duration | 60 seconds | Connecting to multiple systems for data validation requires reserving sufficient interface response time |
| Global variable binding scope | Current business process node | Adapts to the node-based approval process of shipbuilding businesses |
| Data synchronization interval | 1 time per day | Matches the batch synchronization rhythm of material data |

## Three common configuration mistakes
- Phenomenon: Form nodes are displayed as plain text in the conversation interface, and are not rendered as input controls or preset option lists. Cause: The interactive rendering rules of the `formInput` configuration item are not correctly enabled.
- Phenomenon: Single-choice options cannot bind global variable values, and an error indicating an empty field appears after submission. Cause: The scope of the global variable is not configured as the current business process node.
- Phenomenon: Field validation fails after form submission, with a prompt indicating unit mismatch. Cause: No preset validation rules for engineering units are configured, allowing free input of content without standardized units.

## How to confirm the configuration is complete
- Enter the test conversation for the corresponding business process, initiate a form call, and check whether the interface is rendered as an input control or preset option list.
- Enter content that does not comply with engineering unit rules, and check whether a format validation prompt is triggered.
- Call the global variable binding function, verify whether single-choice options can correctly read global variable values.
- After submitting the form, check whether the system synchronizes real-time data from the current job node for validation.
