# Business Process Guidance for Rail Transit Equipment: Tool Calling and Plugins

## What the data for this category looks like
Rail transit equipment business process data mainly comes from manufacturing BOM systems, operation and maintenance inspection ledgers, and on-site work order systems. There are two data update schedules: inspection records are synchronized daily, while BOM and standard process documents are updated weekly. Individual documents primarily use structured fields, including equipment number, fault type, process node, required spare parts, processing time limit and other fields. Units include sets, hours, times, pieces and others. Some fields require association with the unique equipment identifier for verification.

## What constraints these characteristics impose for the tool calling and plugins link
The structured nature of rail transit equipment business data requires that tool calls strictly match preset field names, to avoid data misalignment caused by fuzzy queries. The difference in update schedules between different data types requires that tool calls distinguish between real-time pull and cached call scenarios. Inspection-related data must be synchronized in real time with each call, while standard process documents can be cached periodically. The unique equipment identifier is a core associated field, so tool call parameters must carry a valid equipment number, otherwise corresponding business process information cannot be returned. The ordered arrangement of process nodes requires that tool calls obtain processing steps in sequence according to node numbers, and skipping preceding nodes to generate guidance content is not allowed.

## Configuration Settings

| `toolChoice` | `auto` | Adapts to dynamic calling requirements matching user questions, no need to force tool enabling or disabling |
| `functionCall` | `required` | Business process guidance must rely on tools to obtain real-time data, and content cannot be generated solely based on context |
| Tool call timeout threshold | `60 seconds` | Queries for rail transit equipment business data are usually completed within 30 seconds, with a reasonable buffer period reserved |
| Tool call parameter validation | Enable mandatory equipment number validation | Equipment number is a core associated field; missing it will result in failure to return corresponding business process information |
| Number of entries returned per tool call | `Top 3` | The number of relevant documents for business processing workflows is limited; too many entries will cause context overload |
| Workflow trigger condition | User mentions business processing keywords | Trigger tool calls only when users ask about processing workflows, to avoid invalid calls |

## Three Common Mistakes
- Symptom: Tool call returns empty data. Cause: Required equipment number parameter is not included, and parameter validation configuration is not enabled.
- Symptom: Tool call times out. Cause: Timeout threshold is set too short, and buffer period for rail transit equipment business data queries is not reserved.
- Symptom: When a workflow is used as a tool call, uploaded files cannot be passed as parameters. Cause: The workflow is not configured to receive file link type parameters, and the file upload field is not mapped in the tool call configuration.

## How to Confirm the Configuration Is Correct
- Manually input a test question containing a valid equipment number, and verify whether the tool call returns corresponding business process data.
- Adjust the tool call timeout threshold to simulate a slow query scenario, and verify whether the timeout logic takes effect.
- Upload a test file to trigger a workflow call, and verify whether the file link is correctly passed to the workflow parameters.
- Configure the keyword trigger condition, input a question unrelated to business processing, and verify whether the tool call is not triggered.
