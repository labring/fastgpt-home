# Business Process Guidance for Telecommunications Engineering Construction: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Business process data for telecommunications engineering construction primarily comes from documents such as project approval documents, construction drawings, acceptance specifications, and operation manuals. Update frequency adjusts based on project progress or industry standard revisions. Single project documents include structured fields like project number, construction location, construction unit, and approval document number, as well as unstructured content such as construction process descriptions, equipment parameters, and engineering drawings. Field units use professional engineering units including kilometers, square meters, days, and ten thousand yuan. Individual document lengths range from hundreds to thousands of characters.

## What constraints these characteristics impose on knowledge base retrieval and recall
The presence of structured fields and professional units requires retrieval to match field semantics and unit consistency, to avoid invalid recall caused by unit mismatches. Unstructured engineering drawings and long text content increase vector embedding computation load, so the number of recall results must be controlled. Separate project documents require retrieval to limit the scope to the corresponding project’s dataset, to avoid interference from irrelevant cross-project content. Frequent use of abbreviations and professional terms requires retrieval to support expanded queries, covering complete professional expressions. Image document links must be fully retained to avoid truncation during recall.

## Three Common Mistakes
- Phenomenon: The knowledge base returns incomplete image links, with some characters truncated. Cause: Image links in imported documents contain unescaped special characters. The knowledge base recall process does not perform full encoding on links, leading to truncation during output.
- Phenomenon: When testing a workflow, only the first question can associate knowledge base content, and subsequent similar questions have no knowledge base references. Cause: The workflow is not configured with session context passing. Subsequent requests do not carry the correct `collectionIds` parameter, resulting in an empty retrieval scope.
- Phenomenon: After importing bilingual documents, the large language model does not call knowledge base content when encountering Chinese questions. Cause: Multilingual retrieval configuration is not enabled. The vector model only generates embeddings for single-language text, causing Chinese queries to fail to match Chinese bilingual document fragments.

## How to Confirm the Configuration is Correct
- Upload a test document containing a project number and construction location, initiate a query that includes the number, and check if the corresponding document fragment is included in the recall results.
- Initiate a query that includes a professional abbreviation, such as "FTTH construction process", and check if content containing "fiber to the home" is recalled.
- Import an engineering drawing with a complete link, initiate a query that includes drawing keywords, and check if the returned image link is complete and not truncated.
- Initiate 3 consecutive business questions for the same project, and check that each request’s returned results include knowledge base content for the corresponding project.
