# Business Process Guidance for Telecommunications Engineering Construction: Deployment and Upgrade

## What the data for this category looks like
The business process data for telecommunications engineering construction mainly comes from the project approval management system, on-site survey ledger, and construction progress reporting platform. It is updated according to the approval nodes of individual projects. Core documents include fields such as project unique identifier, construction coverage area, approval link list, material submission requirements, handling time limit requirements, etc. Most field units are engineering standard units such as meters, days, square meters, and pieces. The data volume of a single document fluctuates with project scale, and there is no unified fixed format template.

## What constraints do these characteristics impose on the "Deployment and Upgrade" phase
The scattered data sources require multi-source data connection adaptation to be configured during the deployment phase, to avoid cross-system field mapping deviations. The rhythm of updates according to project nodes requires reserving interface space for dynamic expansion of approval links during upgrades, to adapt to new engineering approval types. The feature that engineering fields come with dedicated units requires presetting unit conversion and verification rules during deployment, to prevent data entry and matching errors. The characteristic that single document data volume fluctuates with project scale requires adjusting storage sharding thresholds during upgrades, to avoid large-volume data loading timeouts.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Telecommunications engineering data has large single-batch pull volumes, which needs to match the connection pool limit of FastGPT v4.17.0 |
| `REDIS_URL` | Local Redis instance address, default port 6379 | Business process guidance requires high-frequency caching of approval node data. Local deployment reduces access latency |
| `STORAGE_S3_ENDPOINT` | Enterprise internal object storage endpoint address | Telecommunications engineering data contains a large number of drawings and survey files, which needs to adapt to the enterprise's own storage service |
| `FE_DOMAIN` | Enterprise internal office domain name | Used to generate shared links for process guidance pages, adapting to internal network access rules |
| `FILE_TOKEN_KEY` | Key string consistent with the enterprise OA system | Used to verify access permissions for process guidance pages, preventing unauthorized access to engineering confidential data |

## Three common misconfigurations
- Shared process guidance pages fail to respond normally, and the interface returns a 403 status code. The cause is that `FE_DOMAIN` is not configured as the enterprise internal office domain name, resulting in cross-domain request interception.
- Approval link data on the process guidance page fails to load, and the backend log shows that the database connection pool is exhausted. The cause is that the `DB_MAX_LINK` configuration value is too low, which cannot support simultaneous data pulling for multiple projects.
- Engineering drawing attachments cannot be previewed normally, and the page prompts that the file format is not supported. The cause is that the MIME type whitelist for engineering drawings is not configured in the storage service corresponding to `STORAGE_S3_ENDPOINT`.

## How to verify that the configuration is complete
- Log in to the deployment server, execute the Redis connection test command, and confirm that the instance configured with `REDIS_URL` can connect normally.
- Initiate access to the shared link of a single project's process guidance page, verify that the page can load approval link data normally without cross-domain errors.
- Upload an engineering CAD drawing file, confirm that it can be previewed normally on the process guidance page without format errors.
- View the database connection pool monitoring panel, confirm that the current number of connections does not exceed the threshold configured by `DB_MAX_LINK`.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
