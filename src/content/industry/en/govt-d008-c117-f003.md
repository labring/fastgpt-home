# Business Process Guidance for Communication Towers and Infrastructure: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data is primarily sourced from communication tower operation and maintenance management systems and base station registration platforms. Operation status is synchronized daily. Registration information is updated weekly. Data documents contain fields including tower unique ID, latitude and longitude coordinates, tower height, floor area, registration status, and current operation and maintenance node. The ID follows an 11-digit pure numeric format. Latitude and longitude use decimal coordinates. Tower height is measured in meters. Floor area is measured in square meters. Registration status uses three enumerated options: pending review, approved, rejected.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering Workflows
Fixed-format tower IDs require multi-turn dialogue to include built-in 11-digit pure numeric validation rules. This prevents invalid input from disrupting subsequent processes. Enumerated registration status fields require the dialogue to only offer preset options for user selection. Free text input is not supported. Daily updated operation data requires the dialogue to prompt users to provide the latest registered tower IDs first. This avoids calling expired information. Multi-field document structures require multi-turn dialogue to collect required fields in the order of registration, operation and maintenance, and approval. This ensures complete matching of information for each stage.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Session ID Binding | Bind `chatId` to associate a single user's single processing flow | Ensures tower business processing progress is only retained within the current session, preventing cross-user data confusion |
| Dialogue Message Order | Trigger nodes in `messages` order | Matches the fixed business processing flow, ensuring users submit required fields sequentially |
| Global Variable Configuration | Bind `variables` field for node-based grouping | Manages variables separately across registration, operation and maintenance, and approval nodes, preventing field conflicts |
| Maximum Context Length | 1200–1500 characters | Adapts to the multi-field requirements of tower business, avoiding excessive context interference with field validation |
| Dialogue Timeout Setting | 300 seconds | Reserves sufficient time for users to gradually input tower-related location, ID, and other information |
| Prompt Template Length | 600–800 characters | Clearly lists required fields and format requirements, avoiding information overload |

## Three Common Misconfiguration Issues
- Phenomenon: Form input node dialog boxes in nested workflows remain visible, while those in main workflows are hidden. Cause: The `chatId` of nested nodes is not bound to the main workflow, resulting in separated session contexts.
- Phenomenon: Custom web pages or text-to-image results cannot be rendered in dialog boxes. Cause: The rich text rendering switch for dialogue content is not enabled, and a dedicated image generation node is not configured.
- Phenomenon: Global variable options are missing in FastGPT v4.9.10. Cause: This version adjusted the variable management interface layout. Required variables must be manually added on the global variables page of application settings.

## How to Verify Proper Configuration
- Initiate a business processing test. Input the 11-digit tower ID, latitude and longitude coordinates, and tower height data sequentially. Check if the `variables` field correctly collects and passes data to subsequent approval nodes.
- Switch between nested and main workflow scenarios. Confirm that form dialog boxes are hidden on demand only in non-nested main workflow scenarios, and display normally in nested scenarios.
- Check that the prompt template contains all required business fields, clearly marks field format requirements, and contains no ambiguous guidance content.
- Verify that after a session timeout and re-entry into the process, the processing progress associated with the `chatId` is not lost, and previous input steps can be resumed.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
