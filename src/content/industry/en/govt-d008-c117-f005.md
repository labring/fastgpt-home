# Business Process Guidance for Communication Towers and Infrastructure: Tool Calls and Plugins

## What this category's data looks like
Data for communication towers and infrastructure originates from the communication tower operation and maintenance management platform, base station power and environment monitoring system, and project approval archive repository. Real-time operation and maintenance data updates every 1 minute. Project documents are updated on demand per project construction milestones, and approval data updates in real time as workflows progress. Documents use structured formatting, including fields such as base station unique identifier, deployment location, device model, current load, associated approval order number, and maintenance record number. Deployment location uses decimal longitude and latitude format, current load is measured in kilowatts, and maintenance record number uses a string format.

## What constraints do these characteristics impose on the "tool calls and plugins" workflow
The minute-level real-time update requirement for category data means tool calls must balance timeliness and resource usage. Overly long polling intervals will cause data to become outdated. The structured field system requires tool calls to accurately match field names; fuzzy matching or omission of core identification fields is not permitted. The real-time circulation feature of approval data means plugins must connect to real-time system interfaces, and cannot rely on static caching. The base station unique identifier, as the core positioning field, requires verification rules during the tool call link to prevent invalid requests from occupying system resources.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Fixed binding to two types of tools: base station operation and maintenance, approval query | Avoid mismatches between parameters and category data during automatic tool selection, and adapt to the tool binding rules of FastGPT v4.17.0 |
| Plugin interface timeout | 15-20 seconds | Adapt to interface response durations across operation and maintenance and approval systems, preventing timeout interruptions |
| `functionCall` | Enable strict parameter verification | Ensure incoming fields fully match the category data structure, avoiding parsing errors |
| Required parameter verification | Verify that base station ID and approval order number fields have valid formats | Match the structured field requirements of category data, filtering invalid requests |
| Result cache duration | No more than 1 minute | Adapt to the minute-level update rhythm of real-time operation and maintenance data, ensuring data timeliness |
| Tool call polling interval | 5 minutes | Balance data timeliness and system resource usage |
| Number of results returned per single call | Top 3 entries | Match the single-page display habit of category data |

## Three common configuration mistakes
- Calling the operation data tool returns an error stating "missing required parameter". The cause is that base station ID was not added as a required verification item in the tool call configuration, so the request does not carry the core identification field of the category data.
- Calling the approval progress query plugin returns an empty result. The cause is that the plugin was not configured to connect to the real-time approval system interface, and static cached data was used. Approval progress updates in real time with workflows, so cached data has expired.
- Calling the chart tool to generate an operation load report results in an empty chart. The cause is that the unit of the incoming load data field was not verified, so the numerical value does not match the expected unit, and the chart rendering engine cannot parse the data correctly.

## How to confirm the configuration is correct
- Initiate a tool call request with a valid base station ID, check whether the returned data includes the latest operation status fields.
- Trigger an approval workflow node change, call the corresponding plugin, check whether the returned result updates to the latest node status synchronously.
- Enable the tool call debug log, check for prompts of failed required parameter verification, confirming that the verification rules are active.
- Adjust the tool call polling interval, observe the balance between data update timeliness and system resource usage.
