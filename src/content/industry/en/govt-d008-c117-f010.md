# Business Process Guidance for Communication Towers and Infrastructure: Knowledge Base Retrieval and Recall

This explanation follows the configuration rules for FastGPT v4.17.0.

## What data in this category looks like
Data in this category mainly comes from operation and maintenance ledgers, base station inspection archive files, and business process specification documents. Data updates are adjusted based on business handling rhythms. Core process documents are synchronized and revised every quarter. Most documents are chaptered process descriptions that include application conditions, submission material lists, handling nodes, feedback time limits, and other details. Some documents contain fields such as base station number, tower height, rental period, and application number, using basic units like meters, days, and individual units. Some documents organize process nodes in table format.

## What constraints these characteristics impose on knowledge base retrieval and recall
Structured process documents in this category impose retrieval constraints:
When chunking content, retain context links between process nodes to avoid losing step coherence after splitting. Documents include unique identification fields such as base station number and application number. Relying only on semantic recall may not accurately match the handling process for a specific base station. Combine field-level retrieval as an aid.
Data updates follow no fixed schedule. Sync datasets regularly to prevent recalling outdated business handling rules.
Some documents include process node tables. Correct table structure parsing during import is required, otherwise the corresponding relationship between nodes and their requirements will be lost.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.65–0.75` | Semantic similarity threshold for matching process-related text. Avoids recalling irrelevant non-process documents while covering core handling steps |
| `limit` | `Top 8–12 entries` | Communication tower business handling processes have multiple nodes. A single recall that covers the full process chain avoids excessive results that disrupt retrieval experience |
| `searchMode` | `Semantic + full-text hybrid` | Balances process semantic association and precise field matching for items like base station number and application number. Adapts to the structured characteristics of category documents |
| `usingReRank` | `Enabled` | Semantic similarity calculations for process-related text are easily disrupted by redundant descriptions. Re-ranking prioritizes returning handling nodes most relevant to user queries |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Business handling questions often use abbreviated phrasing. Extended queries supplement implicit process keywords to improve recall completeness |
| `collectionIds` | `Bind exclusive tower business process dataset` | Isolates documents from other categories to prevent irrelevant business content from being recalled. Ensures retrieval results only cover data from this category |

## Three Common Configuration Errors
- After importing documents, the page count continues to refresh and pages cannot be selected. This occurs when the document contains a large number of nested tables or multi-level list structures, and a pagination index cannot be generated correctly during parsing.
- Tool calls cannot be linked to knowledge base searches. This happens when the exclusive communication tower business process dataset is not bound. The retrieval scope covers irrelevant documents, leading to matching failure.
- Semantic retrieval fails to recall target content, but full-text retrieval succeeds. This is because process nodes in the document use industry-specific abbreviations, and the semantic model does not cover these terms, resulting in semantic matching failure.

## How to Verify Correct Configuration
- Upload a single communication tower business process document, initiate a query containing handling node keywords, and confirm whether retrieval results include core content from the document.
- Enter a query term containing a base station number or application number, and confirm whether retrieval results match the detailed description of the corresponding process.
- Disable the `datasetSearchUsingExtensionQuery` configuration, initiate a retrieval, and compare the differences between the two results to confirm whether the extended query function works.
- Import updated process documents, wait for dataset synchronization to complete, then initiate a query to confirm whether retrieval results include the latest handling rules.
