# Business Process Guidance for Communication Towers and Infrastructure: Forms and Interactions

## What the data for this category looks like
The business process data for communication towers and infrastructure comes from the tower operation and maintenance management system, base station resource scheduling platform, and operator base station archive library. Data is fully synchronized once per day. The document structure includes fields such as base station unique identifier, tower type parameters, construction height, load power, maintenance cycle, and approval node status. Fields are paired with clear physical units: tower height is measured in meters, load power in kilowatts, and maintenance cycle in days. The approval node status field is an enumeration type with three fixed values: pending review, approved, and rejected.

## What Constraints These Characteristics Impose on Forms and Interactions
There are many data fields with strong dependencies. Tower type parameters directly determine the optional load range, so forms must be configured with field linkage logic to prevent users from selecting invalid combinations. Data is updated once daily, so forms must display the last data update time to prompt users to prioritize the most recently obtained data. Fields have clear physical units, so forms must support automatic unit matching or mandatory validation to block input without units or with incorrect units. The base station unique identifier uses a fixed format, so forms must be configured with format validation rules to ensure input conforms to system recognition standards. The enumeration-type approval node status field must have preset fixed options, and custom user input is prohibited.

## Configuration Settings
This page is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `formInput` | Enable format validation, limit input to "TC" prefix + 6 digits | The base station unique identifier uses a fixed format to ensure accurate system recognition |
| `userSelect` | Enable linkage between tower type and load parameters, only display optional load values corresponding to the current tower type | Tower type and load parameters have strong dependencies to avoid invalid selections |
| Data timeliness prompt | Display the last data update time, prompt that synchronization occurs every 24 hours | Data is fully synchronized once daily, so users must be reminded to use the latest data |
| Automatic unit matching | Automatically fill the corresponding unit for fields, for example, tower height defaults to meters, power defaults to kilowatts | Fields have clear physical units to reduce user input errors |
| Field required rules | Mark base station ID, tower type, and maintenance cycle as required | These three are core required information for business processing |
| Error retry threshold | Allow 3 input errors before triggering the manual verification channel | Avoid invalid submissions occupying system processing resources |

## Three Common Misconfigurations
- The symptom is an input error popup when executing a code node after referencing a plugin, with the prompt "Parameter not bound". The cause is that the `formInput` field required by the plugin was not correctly associated with the workflow input node in the form configuration.
- The symptom is that the load parameter list shows no matching items after a user selects a tower type. The cause is that the linkage configuration for `userSelect` was not enabled, causing options to not be filtered by tower type.
- The symptom is that submitted form data does not match the latest data in the system. The cause is that the data timeliness prompt was not configured, and the user submitted old data that has not been updated for more than 24 hours.

## How to Verify Successful Configuration
- Fill in the base station ID in the format "TC" prefix + 6 digits, confirm that the format validation prompt displays normally.
- Select any tower type, confirm that the load parameter list automatically updates to the optional values for that tower type.
- Check the last update time prompt at the bottom of the form, confirm that it matches the daily synchronization cycle.
- Submit a test form, confirm that there are no parameter not bound type error messages.
