# Business Process Guidance for Metal Material Processing: HTTP Interfaces and External Systems

## What the data for this category looks like
Business data for metal material processing primarily comes from internal enterprise systems: ERP, MES manufacturing execution systems, quality management systems, and order management systems. Data update cadence falls into three categories:
- Order data is updated in real time. The status and process progress of each processing order change synchronously as the workflow advances.
- Quality inspection data is updated per production batch. A complete quality inspection report is generated after each batch of processing is completed.
- Material master data is updated once daily. It includes basic parameters such as material grade, specification, and density.

Single business documents contain fields including order number, material grade, processing procedure, quality inspection result, and delivery status. Units use common industrial standards such as millimeters, tons, and hours.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
The characteristics of metal material processing business data create multiple constraints for HTTP interface configuration.
First, interfaces for real-time order data must support high-frequency calls to avoid delaying real-time business process guidance due to request latency.
Second, quality inspection data is generated per batch and may include binary format report files. Interfaces must support parsing of multiple types of response content.
Third, business processes with multiple system linkages require interfaces to be compatible with multiple sets of parameter validation. This ensures that incoming parameters such as order numbers and material grades meet internal enterprise format specifications.
Fourth, differences in data update frequencies require interfaces to differentiate configurations for real-time requests and batch requests, preventing resource waste or data lag.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {Enterprise-specific API key}` | Most ERP and MES interfaces for metal material processing enterprises use Bearer token authentication to secure business data transmission |
| `variables` | `{"orderNumber": "", "materialSpec": "", "workProcedure": ""}` | Bind core parameters required for business processing to adapt to multi-node validation requirements of processing workflows |
| `responseData` | `Extract by mapping business fields` | Metal processing data includes multi-dimensional fields such as order number, material grade, and quality inspection result. Precise extraction is required for process guidance |
| Timeout setting | `600 seconds` | Interface responses for large metal processing orders may take a long time. This prevents premature workflow interruption |
| Single request data volume | `800–1200 characters` | Business data volume for processing workflows is moderate. This prevents overload from single requests |

## Three common mistakes
- Symptom: Interface returns status code 403, and processing order data cannot be retrieved. Cause: The `Authorization` parameter is not configured correctly, and an expired or unauthorized API key is used.
- Symptom: Long text received by the workflow is not properly split, leading to errors in subsequent processing. Cause: No reasonable single request data volume threshold is set, and long text is not processed in segments.
- Symptom: Quality inspection data fields returned by the interface are empty. Cause: Correct business parameters are not bound in `variables`, so the interface cannot match the corresponding data.

## How to confirm the configuration is complete
- Trigger a test request and check if the returned `responseData` includes expected metal processing business fields.
- Call the authentication test interface to verify that the `Authorization` configuration passes the authentication check of the external enterprise system.
- Simulate a complete business processing workflow and check if data returned by the external system can be correctly mapped to process guidance nodes.
