# Business Process Guidance for Metal Material Processing: Vector Models and Indexes

## What Data for This Category Looks Like
Business process data for metal material processing comes primarily from internal enterprise production process manuals, equipment operation and maintenance specifications, business approval forms, quality inspection reports, and order documents. Updates are triggered on demand when new orders are placed, processes are revised, or equipment is upgraded, with no fixed cycle. Each document includes fields such as process steps, responsible departments, required materials, approval nodes, and quality inspection metrics. Quality inspection metrics often use professional units such as MPa and HRB. Some documents contain long-form process descriptions and drawing annotations.

## Constraints Imposed on Vector Models and Indexing
Metal material processing business data includes specialized terminology and fixed units, so vector models must understand the semantic meaning of industry-specific terms. Long-form process descriptions and drawing annotations require proper splitting to prevent semantic loss from overly long individual chunks. The on-demand update feature requires indexes to support incremental triggers, avoiding excessive resource use from full reindexing. The linear logic of business processes means retrieval results must prioritize content related to process nodes, filtering out irrelevant quality inspection data. Field differences across documents also require index configurations to adapt to retrieval rules for multiple data types.

## How to Set Configurations

| Chunk Length | 800–1200 characters | Adapts to the length of single sections in metal material processing process documents, avoiding semantic breaks |
| Overlap Length | 100–200 characters | Ensures contextual continuity between adjacent chunks, covering the associated information before and after process nodes |

| Single Search Limit | Top 10 results | Matches the number of core nodes in business process guidance, avoiding redundant results |
| `defaultToken` | 4096 token | Adapts to the input length limit of local vector models, aligns with FastGPT v4.17.0 parameter requirements |
| `maxToken` | 8192 token | Limits the total length of context spliced after retrieval, ensuring stability during model calls |

## Three Common Mistakes
- The index task in the interface remains continuously running with no progress updates. This happens when incremental index trigger conditions are not configured, and full reindexing is used for frequently updated business process data.
- A 503 status code is returned during calls, with a prompt that no available embedding model exists under the default group. This occurs when the local vector model is not added to the default group, or the `defaultToken` setting for the model API exceeds the model's supported limit.
- Key business process nodes are not included in retrieval results. This happens when chunk length is set too large, leading to loss of critical information when dense technical process paragraphs are split.

## How to Verify Correct Configuration
- Upload a single metal material processing process document, view the preview of split chunks, and confirm the chunk length matches the preset value.
- Test calls to the embedding interface, check that the returned vector data format is normal, and no `defaultToken` over-limit error is present.
- Enter a query related to business processing, confirm that the number of retrieval results matches the single search limit setting.
- Trigger an incremental index task, check that the index progress bar advances normally, with no continuous hanging status.
