# Business Process Guidance for Metal Material Processing: Workflow Orchestration

## What the Data for This Category Looks Like
The business data for metal material processing mainly comes from production execution systems (MES), warehouse management systems (WMS), and quality inspection report documents of state-owned and public enterprises in the steel and non-ferrous metals sector. Data updates occur either immediately after each production batch is completed, or via a scheduled full update every day. The document structure includes two parts: structured fields and attachments. Structured fields include furnace number, batch number, material grade, hardness value, yield strength, and others. The units for hardness and yield strength are MPa, and the unit for batch quantity is tons. Most attachments are PDF-format quality inspection reports that contain detailed records of the production process.

## What Constraints Do These Characteristics Impose on the Workflow Orchestration Link
The characteristics of metal material processing business data impose three constraints on workflow orchestration. First, structured fields include numerical values with units and fixed-format identifiers. Variable configuration must strictly match the field type and unit to avoid node failures caused by format incompatibility. Second, data is updated according to production batches. Trigger nodes must be bound to the batch number variable to ensure the process triggers only when the corresponding batch is completed, avoiding repeated processing or missed tasks. Third, most quality inspection reports are PDF attachments. A dedicated file processing node must be configured to adapt to the parsing duration of large-volume documents, while connecting to internal system authentication interfaces to ensure data security.

## How to Set the Configurations

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Map to business fields: furnace number, batch number, material grade, hardness value (unit MPa) | Match the structured data fields of metal material processing to ensure workflow nodes can accurately read the corresponding parameters |
| `nodeId` | Bind the batch processing node ID, with the trigger condition set to the production batch completion event | Align with the update rhythm of production batches to avoid repeated triggering or missed processes for corresponding batches |
| File parsing parameters | Retain PDF text + structured field extraction, single file processing duration not exceeding 60 seconds | Adapt to the conventional size of quality inspection report PDFs to avoid process interruption due to timeout |
| Timeout duration | 300 seconds | Cover the reasonable execution duration of cross-system interface requests and large file parsing |
| Retry count | 2 times | Address temporary network fluctuations or interface jitters, reducing the probability of process interruption |

## Three Common Mistakes
- Symptom: The speech synthesis node in the workflow fails to execute, and the console reports "input parameter format error". The cause is that structured data such as material grade and hardness value of metal material processing are not correctly mapped to the `variables` of the speech node, resulting in the passed content not meeting the format requirements of speech synthesis.
- Symptom: The HTTP request node returns a 400 status code, prompting "missing required parameter". The cause is confusing the role of the file link variable, using the local file name as the body parameter name, and failing to configure the correct parameter key according to the interface requirements.
- Symptom: The expected base64 encoded result is not generated after the process is executed. The cause is that no file reading node is added to the workflow, and directly calling the external script interface results in failure to obtain the image files on the local desktop.

## How to Confirm the Configuration Is Properly Set Up
- Trigger a simulated production batch completion event, check the workflow execution log, and confirm that all business fields in `variables` are correctly read and passed to subsequent nodes.
- Call the HTTP request node, pass a test file link, and check whether the returned body parameters match the format agreed in the interface documentation.
- Start the speech synthesis node, pass the preset quality inspection data text, and confirm that the node executes successfully with no error prompts.
- Simulate a temporary network fluctuation, trigger the HTTP request node, and confirm that the process automatically retries the specified number of times before continuing execution or terminating.
