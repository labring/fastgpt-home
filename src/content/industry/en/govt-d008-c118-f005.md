# Business Process Guidance for Metal Material Processing: Tool Calling and Plugins

## What the data for this category looks like
Metal material processing business data mainly comes from internal enterprise ERP, MES systems and quality inspection laboratory systems. Production process parameter data is updated in real time for each processing batch. Order contract data is updated daily. Quality inspection report data is updated after each furnace batch is processed. The document structure is divided into three categories:
- Process cards include fields such as grade, specification, hardness, tolerance, with units of millimeters and megapascals.
- Order contracts include fields such as customer name, delivery cycle, batch size, etc.
- Quality inspection records include fields such as furnace number, tensile strength, yield strength, etc., using industry standard units uniformly.

## What constraints these characteristics impose on the "tool calling and plugins" link
The mixed real-time and batched data update rhythm requires tool calling to distinguish the call timing of static documents and dynamic data sources, to avoid pulling expired data. The standard units for professional fields require that the parameter parsing logic must be unified during tool calling, to prevent business processing errors caused by unit mismatches. The need to access data sources from multiple systems requires plugins to be configured with multiple sets of authentication and interface call rules to adapt to the access protocols of different systems. The batch association attribute of data requires that tool calling must filter returned results by furnace number or order number, to ensure that the returned content is strongly related to the current business being processed.

## How to set the configurations

| `toolChoice` | Set to `auto` | Automatically match the tools required for business processing, adapting to multi-data-source call scenarios |
| `functionCall` | Enable strict validation | Force the parameters returned by tools to conform to the field format for metal material processing, reducing parsing errors |
| Data source configuration | Bind dedicated plugins for ERP, MES and quality inspection systems | Cover all order, production and quality inspection data required for business processing |
| Parameter accuracy verification | Calibrate based on actual measurements, retain 3 significant digits | Adapt to the process parameter accuracy requirements of metal material processing |
| Timeout threshold | 600 seconds | Adapt to the delay of cross-system data pulling, avoiding request interruptions |
| Plugin call limit | Top 3 matching tools | Avoid excessive tool calls leading to slow response, aligning with the rhythm of business processing processes |

## Three common errors
- Tool call returns results containing irrelevant knowledge base content, failing to accurately match process parameters for metal material processing. The cause is that strict validation mode for `functionCall` is not enabled, causing unstructured data from the general knowledge base to be mixed in during tool calls.
- A 514 status code is returned when calling external system APIs. The cause is that the cross-system adaptive timeout threshold is not configured, and the request waiting time exceeds the limit of the target system.
- Attempting to use a general internet plugin to obtain metal material data without binding dedicated data source plugins. The cause is that correct data source docking items are not configured, causing the called plugin to fail to return accurate business processing data.

## How to confirm the configuration is complete
- Submit a simulated business processing request, check the tool call logs, and confirm that the triggered plugins are the bound ERP, MES and quality inspection system plugins.
- Check the parameter fields returned by the tool, confirm that they include professional fields required for metal material processing such as grade, thickness, tensile strength, etc., and that the units match.
- Simulate a timeout scenario, confirm that the request completes the response within the configured timeout threshold.
- Test the `functionCall` strict mode, input parameters that do not conform to the format, and confirm that the tool call returns a validation failure prompt.
