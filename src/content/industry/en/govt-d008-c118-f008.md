# Business Process Guidance for Metal Material Processing: Document Parsing and Chunking

## What this category of data looks like
This category of data is primarily sourced from production process cards, quality test reports, equipment operation logs, and business approval workflow documents of metal material processing enterprises. Data is updated in real time alongside production task assignments or synced in daily batches. Most documents use a mixed format of structured and semi-structured content, including fields such as material grade, processing procedure parameters, test indicators, and approval opinions. Common units include MPa (for strength indicators), mm (for sheet thickness), tons (for processing capacity), and others. The length of individual documents varies widely, from a few hundred characters to complete processing workflow documents totaling tens of thousands of characters.

## Constraints imposed by these characteristics on document parsing and chunking
The data characteristics of this category impose multiple constraints on the document parsing and chunking stage. Mixed-format documents contain tables, text paragraphs, and other types of content, so targeted parsing rules must be configured to fully extract parameter and unit association information. The wide range of individual document lengths means long workflow documents are prone to context breaks, so flexible chunk boundaries must be supported. Professional fields include dedicated units, so the binding relationship between parameters and units must be retained during chunking to prevent loss of indicator meaning after splitting. Real-time updated data requires the parsing stage to support incremental recognition, to avoid repeated processing of already parsed historical documents.

## How to set the configurations
The following configurations are formulated based on standard parameter items for FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the professional parameters and context length of metal material processing documents, avoiding overly fragmented or overly long single chunks |
| `chunkSplitter` | Split by semantic segments | Adapts to the structure of mixed-format documents, preserving the semantic integrity of process parameters and test indicators |
| `customPdfParse` | Enable table parsing mode | Fully extracts structured data from tables in quality test reports and process cards |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the upload requirements of large processing workflow documents, avoiding upload failures caused by oversized files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of long documents, avoiding parsing process interruptions due to timeouts |
| `chunkSettingMode` | Manual configuration | For documents with many professional fields, flexibly adjust chunking parameters to retain business association information |

## Three common misconfigurations
- Phenomenon: After calling the API to upload an image or image address, the parsing result is empty or returns a parsing failure status code. Cause: `customPdfParse` is not correctly configured to adapt to the image parsing mode, or parameters are not passed in the format required by the interface.
- Phenomenon: Timeout errors occur when parsing long processing workflow documents, or field missing appears in the parsing result. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a value adapted to long documents, or the `chunkSize` setting is unreasonable leading to abnormal chunking logic.
- Phenomenon: After locally deploying MinerU, it cannot be connected to FastGPT, and parsing image or PDF files returns a failure. Cause: The MinerU API address is not correctly configured to the FastGPT parsing node, or the port is not open leading to connection timeout.

## How to confirm the configuration is correct
- Upload a single typical quality test report document, and check whether the parsing result completely extracts material grade, test indicators and their corresponding units.
- Adjust the `chunkSize` parameter, and check whether the length of the chunking result meets expectations, with no overly fragmented or overly long chunks.
- Test uploading a large processing workflow document, confirm that the parsing process does not trigger a timeout error, and that the `UPLOAD_FILE_MAX_SIZE` configuration does not restrict file uploads.
- When calling the parsing API, check whether the returned parameters contain complete business fields, with no missing or incorrectly associated unit information.

The values provided are common starting points and should be measured against the reader's own samples.
