# Business Process Guidance for Metal Material Processing: Forms and Interactions

## What the Data for This Category Looks Like
The business data for metal material processing mainly comes from enterprise ERP systems, production work orders, raw material inbound documents, and quality inspection reports. Data update frequencies fall into three categories:
- Real-time (production process flow updates)
- Daily (inventory and quality inspection data updates)
- Weekly (monthly processing report updates)

The document structure includes fields such as raw material grade, specifications (thickness, diameter, etc.), batch number, processing procedures, quality inspection indicators (tensile strength, elongation rate, etc.), and circulation status. Fields have fixed units, such as millimeters (mm), megapascals (MPa), and percentage (%). The batch number is a unique string identifier.

## Constraints for Forms and Interactions
The fixed format requirements for raw material grade and specification fields mean forms must provide preset options or strict input validation. This prevents manual input errors for units or values.
The uniqueness of batch numbers requires forms to connect to existing enterprise systems for duplicate validation. This stops duplicate submission of processing applications.
Fixed ranges for multiple processing procedures and quality inspection indicators require forms to set interval limits for numerical fields. Processing procedure options must align with the enterprise’s ERP fixed procedure library to avoid process disconnects.
The multi-source nature of data requires form interactions to support step-by-step filling. This adapts to the multi-link logic of business handling.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Set unique value validation and format validation for batch number and production date fields | Matches the uniqueness requirements of metal processing batch management, avoiding duplicate submissions |
| `userSelect` | Bind preset raw material grade and processing procedure option sets | Aligns with fixed business options in the enterprise ERP system, reducing manual input errors |
| Input validation rules | Limit numerical fields to units and reasonable intervals (e.g., thickness 1-500mm, tensile strength 100-2000MPa) | Fits conventional metal material specifications and quality inspection indicator ranges, blocking invalid inputs |
| Form step-by-step configuration | Split into three links: raw material registration, procedure declaration, and quality inspection confirmation | Adapts to multi-step business handling processes, reducing the complexity of single-session filling |
| Submission timeout setting | 30 seconds | Fits typical response durations for enterprise ERP interfaces, avoiding excessive user waiting |

This configuration was validated using FastGPT v4.17.0.

## Three Common Mistakes
- Phenomenon: For the same processing business that requires multiple LLM calls, multi-round question results cannot be automatically merged, or only content from a single round of questions is returned. Cause: Context linkage logic is not configured via `formInput`, so each query uses only single-time input content and does not associate previous business data.
- Phenomenon: A format error prompt appears after form submission, or field values are automatically cleared. Cause: Unit validation is not configured for numerical fields, so input specifications or quality inspection indicators do not match preset unit rules.
- Phenomenon: An interface timeout error triggers after submission. Cause: The submission timeout setting is too short, not adapting to the actual response duration of the enterprise ERP interface.

## How to Confirm the Configuration Is Complete
- For each numerical field, manually enter non-compliant content (e.g., enter 1000cm for thickness, 5000MPa for tensile strength), then check for the corresponding validation prompt.
- Select a preset raw material grade or processing procedure option, submit the form, and confirm the corresponding data is recorded in the synchronized system of the test environment.
- Fill out the form step by step, refresh the page midway, and confirm already filled data from completed links is not lost.
- Simulate submitting multiple processing applications with different batches, and confirm submission requests for duplicate batches are correctly blocked.
