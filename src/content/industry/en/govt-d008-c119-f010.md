# Business Process Guidance for Iron and Steel Smelting: Knowledge Base Retrieval and Recall

## What data for this category looks like
The business data for iron and steel smelting mainly comes from internal process specifications, equipment inspection logs, safety operation manuals, quality inspection reports, and smelting batch records. The data covers the entire production process, and its update rhythm is adjusted according to business needs: process specifications are updated synchronously with technology iterations, inspection logs are archived daily, and safety specifications are revised quarterly. Most documents are a mix of structured and semi-structured content, including fields such as process parameters (such as temperature, pressure), operation steps, and exception handling procedures. Parameters are attached with clear units, and some documents are associated with business identifiers such as furnace number and workshop.

## What constraints do these characteristics impose on knowledge base retrieval and recall
Process parameters are attached with precise units and business identifiers, which requires retrieval to support parameter range matching and field restriction to avoid mixing irrelevant results. Daily updated inspection logs and frequently iterated process specifications require the knowledge base to support incremental synchronization and real-time update configuration. Long documents account for a large proportion, and context association must be retained after chunking to prevent out-of-context misinterpretation. Emergency safety procedure documents need to be recalled first, which requires retrieval to support configurable weight rules. Smelting processes vary significantly across different workshops, which requires retrieval to allow scope restriction by business domain.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Matches the precision requirements for iron and steel smelting process parameters, filters low-relevance retrieval results |
| `limit` | Top 8 entries | Covers the main stages of a single furnace smelting process, avoids exceeding context window limits |
| `searchMode` | semantic + keyword | Balances semantic matching of process descriptions and exact matching of keywords such as furnace number and parameters |
| `usingReRank` | Enabled | Rearranges recall results by relevance, prioritizes displaying documents containing target process parameters |
| `datasetSearchUsingExtensionQuery` | Disabled | Iron and steel smelting terminology is precise, avoids semantic drift caused by extended queries |
| `collectionIds` | Specified by workshop/furnace number | Restricts the retrieval scope to the smelting workshop knowledge base set corresponding to the current business |

## Three common configuration mistakes
- Enabling tool calling prevents knowledge base results from being retrieved. The symptom is that retrieval returns an empty list or the interface prompts that no matching documents are found. The cause is that the tool calling mode prioritizes calling external tools by default, and the knowledge base retrieval permission is not enabled synchronously.
- Retrieval results include smelting documents from other workshops. The symptom is that process specifications for non-target furnace numbers appear in the results. The cause is that the `collectionIds` configuration for restricting the retrieval scope is not set correctly.
- Retrieval results do not hit exact process parameters. The symptom is that returned documents only contain vague descriptions and do not match target temperature or pressure values. The cause is that the keyword matching mode of `searchMode` is not enabled, and only semantic retrieval is used.

## How to confirm configuration is correct
- View the retrieval configuration panel in FastGPT v4.17.0, confirm that the values of parameters such as `similarity` and `limit` match the preset configuration.
- Enter a test query containing a specific furnace number and process parameters, verify that the document sources of the recalled results are within the specified workshop collection.
- Enable the tool calling mode and initiate a knowledge base retrieval request at the same time, confirm that both functions can be triggered normally and return results.
- Compare the sorting of retrieval results with `usingReRank` enabled and disabled, confirm that the reranking function has taken effect.
