# Business Process Guidance for Steel Smelting: Deployment and Upgrade

## What the data for this category looks like
The business process guidance data for steel smelting comes primarily from production scheduling systems, enterprise ERP platforms, on-site work order libraries, and safety inspection records. Data update cycles fall into three categories: on-site work orders are generated in real time, production scheduling data is synchronized hourly, and ERP ledger data is updated daily. A single business document typically includes fields such as work order number, process node sequence, handling time limit, responsible position, material code, and energy consumption parameters. The unit for process duration is minutes, material codes are 18-digit numeric strings, and energy consumption parameter units are kilowatt-hours.

## What constraints these characteristics impose during deployment and upgrade
Steel smelting business data has dispersed sources and widely varying update cycles. During the deployment phase, multiple data sources must be configured for docking and adaptation. `MONGODB_URI` must be specified for storing unstructured inspection records, and `PG_URL` for storing structured ERP and work order data, to avoid data source conflicts. Data fields include specific units and coding rules, so field mapping rules must be preset during deployment to ensure matching unit and coding formats during retrieval. Data volume accumulates continuously as operations run, so the storage expansion strategy must be adjusted during the upgrade phase to prevent service interruptions caused by insufficient single-library storage limits. The incremental synchronization logic must also be verified to adapt to data sources with different update frequencies.

## Three common errors
- Symptom: After upgrading to FastGPT v4.17.0, the text processing node of the original business process guidance cannot be called. Older workflow executions return the error "function not defined". Cause: The new version adjusted the configuration path of the text processing module, and does not support the node reference logic of older workflows.
- Symptom: When deploying in an offline environment, the local PostgreSQL container configured via `PG_URL` fails to start. Logs show "connection refused" or "database not found". Cause: The database initialization script required for steel smelting business data was not mounted in advance in the offline environment, or the database name in `PG_URL` does not match the initialization script.
- Symptom: After directly upgrading across multiple major versions, field mismatches or data loss occur in business search results. Cause: Upgrades were not performed step-by-step in version iteration order, and intermediate version database migration scripts were skipped, resulting in incompatibility between the storage structure of steel smelting business data and the new version.

## How to confirm the configuration is complete
- Log in to the FastGPT backend data source management page, verify that the data source connection status configured with `PG_URL` and `MONGODB_URI` is normal.
- Import a sample steel smelting business work order, trigger process guidance retrieval, and confirm that the returned process nodes and parameter units match the original document.
- Simulate multi-user concurrent access, check that the connection number configured with `DB_MAX_LINK` is not exhausted, and database load meets business expectations.
- Perform a version upgrade rollback operation, confirm that older business workflows can run normally.
