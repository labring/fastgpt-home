# Business Process Guidance for Expressway Operations: Tool Calling and Plugins

## What this category of data looks like
Three sources provide business handling data for expressway operations: toll audit systems, road network operation ledgers, and offline window service records.
Data update rhythms fall into two categories: real-time and daily.
Real-time data includes processes such as real-time toll reduction applications and abnormal passage complaints.
Daily data consists of archived business completion ledgers.
Each individual business document includes fields including handling number, handling type, associated toll station ID, applicant identification number, handling status, handling duration, and others.
Handling status uses fixed enumerated values.
Handling duration is measured in minutes.
Associated road section ID uses a numeric string format.

## Constraints Imposed on Tool Calling and Plugins by These Data Characteristics
Expressway operation business data characteristics impose clear constraints on tool calling and plugin configuration.
Real-time business data updates at high frequency. Tool calling settings require short timeout thresholds to avoid retrieving expired data.
Enumerated handling status fields require plugin return results to strictly match preset enumerated values. This prevents generation of non-compliant business status descriptions.
The numeric format of associated toll station IDs requires plugins to automatically associate with toll station name mapping tables during queries. This converts IDs to text information recognizable by business staff.
Batch business ledger queries need plugins to support pagination parameter passing. This avoids returning content that exceeds context length in a single request.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling switch | Enabled | Matches real-time interaction requirements of business process guidance |
| `toolChoice` | Auto-select | Adapts to varied query and operation needs in business handling, compatible with FastGPT v4.17.0 plugin calling logic |
| Function call timeout | 60 seconds | Matches real-time road network data update rhythm, avoids wait timeouts |
| Plugin parameter validation | Enable enum validation | Matches fixed enum field requirements for handling status, prevents invalid status returns |
| Pagination query limit | Top 20 entries | Adapts to single query scale of business ledgers, avoids context overflow |
| Toll station ID mapping | Enable built-in mapping plugin | Automatically converts numeric IDs to readable toll station names, aligns with business staff usage habits |

## Three Common Misconfigurations
- Scenario: SQL syntax error is returned when executing multiple INSERT and SELECT statements. Cause: Plugin parameters for multi-row query support are not configured, only single SQL statement execution is allowed.
- Scenario: No corresponding road network business data is obtained after calling online tools. Cause: No dedicated data source plugin for expressway operations is bound, general online plugins cannot access internal business interfaces.
- Scenario: A 500 error is returned when importing business ledger documents. Cause: The field structure of business documents is not adapted, generic chunking rules are used directly, leading to abnormal parsing of the associated toll station ID field.

## How to Verify Proper Configuration
- Initiate a test request containing multiple SQL statements, check if the plugin executes normally and returns expected results.
- Enter a query request containing a toll station ID, check if the returned result automatically converts to the toll station name.
- Submit a query request for real-time business handling, check if the response time meets the preset timeout threshold.
- Import a business ledger document, check if fields can be parsed normally and corresponding vector data is generated.
