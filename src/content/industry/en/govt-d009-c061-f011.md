# Party Building Learning Assistant for Meeting Spirit Summaries: Forms and Interactions

## What the data for this category looks like
In FastGPT v4.17.0, data for meeting spirit summaries primarily comes from official press releases of special party building meetings, live audio transcription files, and official minutes compiled after meetings. The data update rhythm follows the holding cycle of individual party building meetings; summary data for a single meeting is only updated after that meeting’s official release. The fixed document structure includes three core modules: meeting theme, key discussion points, and work deployment requirements. Fields include meeting name, holding time, organizing unit, key memorable quotes, etc. Common units are natural paragraphs, item count, and character count.

## What constraints these characteristics impose on forms and interactions
The fixed document structure of meeting spirit summaries requires form interactions to preset input guidance for core fields, to prevent users from missing key information such as meeting theme and core discussions. The requirement for long-text source file input means the form must support pasting or uploading content with large character volume, while also providing format verification rules to filter non-party building meeting text. The data characteristic that updates per individual meeting cycle requires the interaction link to support dynamic binding of the exclusive knowledge base for the currently processed meeting, to avoid confusion between cross-meeting knowledge base content. The structured field requirement means the form must provide quick fill options for preset fields, to reduce manual input errors.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `formInput` | `8000–12000 characters` | This is the typical length range for party building meeting press releases or transcription files, and fits input needs for most scenarios |
| User-selected knowledge base | Bind exclusive variables for the current meeting | Meeting spirit summaries must match the exclusive knowledge base content of the corresponding meeting, to avoid confusion between cross-meeting data |
| `userSelect` | Top 3 recall results | Core discussions of party building meeting spirits are usually concentrated in a small number of related documents; too many results will cause redundancy |
| Input format verification | Enable meeting text recognition rules | Filter non-party building meeting input content, to ensure the targeted nature of processed data |
| Timeout threshold | `600 seconds` | Long text transcription and knowledge base recall require sufficient time; this threshold covers most conventional processing workflows |

## Three Common Mistakes
- Symptom: When dynamically specifying a knowledge base, the reference variable dropdown has no selectable options. Cause: The exclusive knowledge base variable for the current meeting was not defined in the workflow in advance, so the interaction link cannot obtain binding options.
- Symptom: Form submission fails after pasting a long meeting manuscript. Cause: The character limit configuration for `formInput` was not adjusted, exceeding the system's default input limit.
- Symptom: The generated summary contains non-meeting related content. Cause: Input format verification rules were not enabled, and irrelevant text was mixed in, leading to deviations in knowledge base recall.

## How to Confirm Configuration Is Complete
- Access the form configuration interface, verify whether the character limit for `formInput` is set to the `8000–12000 characters` range.
- Trigger the dynamic knowledge base selection operation, confirm that the reference variable dropdown can load preset exclusive knowledge base options for the meeting.
- Paste a non-party building meeting text into the form, check whether the system intercepts this type of input.
- Input a long meeting manuscript, submit and wait for a response, confirm that no timeout error occurs.
