# Party Building Learning Assistant for Meeting Spirit Summaries: Deployment and Upgrade

## What the data for this category looks like
The data sources for meeting spirit summaries include official meeting bulletins released by Party and government authorities, raw transcripts from on-site meeting recordings, and meeting minutes submitted by participating units. Update frequency matches meeting cycles. The text length of individual tasks varies widely. The document structure includes fixed fields such as meeting topic, holding time, core deployments, participant scope, and follow-up implementation requirements. There are no mandatory unified units for the fields, and content is segmented naturally based on the material.

## What constraints these characteristics impose on the deployment and upgrade phase
The diverse data sources, wide range of text lengths, and fixed structure of meeting spirit summary data impose multiple constraints on the deployment and upgrade process. During deployment, the system must support multi-format input, and allow access to content from different sources such as official bulletins, recorded transcripts, and meeting minutes. It must also be configured with processing parameters adapted to long texts, to prevent processing failures caused by overly long text. During upgrade, the system must support newly added transcript formats and field structures, while optimizing long text splitting and synchronization logic, to ensure stable task processing across different meeting cycles.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@localhost:27017/fastgpt?authSource=admin` | Stores structured data for meeting texts and summaries; requires correct authentication and database target configuration |
| `REDIS_URL` | `redis://:yourpassword@localhost:6379/0` | Caches chunked meeting text results and retrieval indexes, to enable fast access |
| `DB_MAX_LINK` | `300 seconds` | Adapts timeout limits for long text processing, covering processing durations for most meeting texts |
| `STORAGE_S3_ENDPOINT` | Set based on actual testing | Stores original recorded meeting files and generated summary files; must be adapted to local or cloud storage configurations |
| `ROOT_KEY` | `32-bit random string` | Highest authority authentication for the admin backend, to ensure deployment security |
| `FE_DOMAIN` | `https://your-domain.com` | Access domain name for the frontend page, to ensure cross-domain validity of interface calls |

## Three common errors
- Symptom: An `Error response from daemon` related error is returned when executing `docker compose up -d`. Cause: Connection parameters for `MONGODB_URI` or `REDIS_URL` are not configured correctly, causing the container to fail to start dependent services.
- Symptom: A `TypeError: Cannot read properties of undefined` error appears after upgrading to FastGPT v4.17.0. Cause: The configuration value for `FILE_TOKEN_KEY` was not updated synchronously, causing key verification failure in the file processing stage.
- Symptom: Meeting spirit summary generation speed is too slow, and individual tasks time out. Cause: The timeout parameter for `DB_MAX_LINK` was not adjusted, or overly long meeting texts were not pre-split, leading to processing timeout.

## How to confirm the configuration is complete
- Execute `docker compose ps`, confirm that all dependent services and application containers are in a running state.
- Access the domain name configured for `FE_DOMAIN`, log in to the admin backend, and verify that the permission configuration for `ROOT_KEY` takes effect.
- Upload a test meeting text, trigger a summary generation task, and confirm that the task completes normally without errors.
- Check the storage bucket corresponding to `STORAGE_S3_ENDPOINT`, confirm that the generated meeting summary files have been uploaded correctly.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
