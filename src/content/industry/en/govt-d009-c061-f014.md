# Party Building Learning Assistant for Meeting Spirit Summaries: Conversation Logs and Auditing

## What the Data for This Category Looks Like
Meeting spirit summary data comes from transcribed audio recordings of Party building meetings, on-site shorthand notes, and officially published formal meeting documents. A corresponding summary is generated once a single meeting concludes, with no fixed batch update cycle. Documents are stored as structured text, including fields such as meeting theme, holding time, participating entities, core spirit summary, follow-up learning requirements, and more. Each summary uses a unique meeting association identifier to distinguish learning content for different meetings.

## Constraints Imposed by These Characteristics on the "Conversation Logs and Auditing" Link
Since data is bound to a unique meeting association identifier, conversation logs must record both user interaction context and the corresponding meeting’s unique identifier. This prevents confusion between summaries from different meetings. Structured fields include core spirit, learning requirements, and other content. Auditing requires verifying the integrity of these fields to ensure no necessary Party building learning content is omitted. Data is generated after a single meeting, with no batch repeated updates. Auditing of conversation logs must verify each individual meeting entry one by one, using sequential verification. Since data comes from official formal documents, the auditing link must retain the original document’s traceability identifier to ensure content can be traced.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current Party building learning session | Ensure each meeting spirit summary’s interaction log associates with the corresponding learning session, avoiding cross-session data confusion |
| `detail` | Enable full field output | Retain complete structured information such as meeting theme and holding time, meeting content verification needs during auditing |
| `responseChatItemId` | Bind the unique response identifier generated for each summary | Facilitate precise positioning of individual summary generation and call records during auditing |
| Conversation log storage period | 180 days | Comply with Party building learning material archiving specifications, while controlling long-term storage resource consumption |
| Session retrieval limit | Top 20 session records | Limit auditing retrieval scope to improve query response speed |
| Log export format | Structured JSON format | Enable batch parsing and content verification by subsequent auditing tools |

## Three Common Errors
- Phenomenon: The associated `chatId` field is empty in conversation logs for meeting spirit summaries. Cause: The configuration did not bind the unique identifier of the current Party building learning session, so the log cannot establish an association with the corresponding learning session.
- Phenomenon: Auditing cannot retrieve specified meeting summary interaction records. Cause: The `detail` configuration item was not enabled, so key identifier fields such as meeting theme and holding time are not stored in the log, making filtering by meeting dimension impossible.
- Phenomenon: Operational data is empty in exported conversation logs. Cause: `responseChatItemId` was not bound to record each summary’s generation and call link, so no corresponding call metadata exists for auditing.

## How to Confirm Proper Configuration
- Enter the FastGPT session management page, select the corresponding Party building learning session, and check if the log contains the bound `chatId` and `responseChatItemId` fields.
- Trigger the generation and call of a meeting spirit summary, and verify that the log fully stores structured information such as meeting theme and holding time.
- After configuring auditing trigger rules, run a simulated auditing operation to confirm that log retrieval and export functions work normally.
- Check the log storage period configuration, and confirm that the system’s automatic expired log cleanup time matches preset requirements.
