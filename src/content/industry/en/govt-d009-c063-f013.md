# Party Building Material Retrieval and Party Study Assistant: Sharing and Embedding

## What the data for this use case looks like
The data sources for party building material retrieval are publicly available study materials released by party organizations at all levels, official historical party publications, latest party building policy documents, and standardized study courseware.
Data updates are adjusted according to the rhythm of party building work deployment, with no fixed cycle. Updates are completed when new policies are released or important study nodes occur.
Each individual document includes five core fields: title, issuing unit, release date, main text, and topic classification tags. Some documents also have attachment links and study notes fields.
Document length varies widely, ranging from hundreds of words of study points to tens of thousands of words of special topic reports.

## What constraints these characteristics impose on sharing and embedding
The data sources for party building material retrieval include clear topic classifications and issuing entities. Classification tags and issuing information must be retained during sharing and embedding to ensure search results match the precision required for study scenarios.
Data updates have no fixed cycle. Embedded search results must match the update rhythm to avoid displaying outdated content.
Document length varies widely. Embedding long documents requires correctly passing metadata to support segmented retrieval. Short documents require avoiding redundant loading.
Additionally, party building study scenarios have requirements for interface formality. Interface elements for sharing and embedding must comply with relevant specifications, and overly casual designs must not be used.

## Three common mistakes
- Embedded windows that do not require login fail to load when opened in Internet Explorer (Trident kernel). The interface displays a blank screen or error prompt. The cause is that the embedded code does not comply with the rendering standards of older browsers, and no compatible configuration items are added.
- Custom icons in the sharing interface do not take effect. The default style is still displayed after modification. The cause is that an icon file that meets the size specifications was not uploaded, or the page cache was not refreshed for the configuration to take effect.
- After embedding into a business system, business user identities cannot be associated with the FastGPT platform. A permission error is returned when a workflow request is initiated. The cause is that the identity binding logic was not configured correctly, and the business system user identifier was not passed to the embedded interface.

- Copy the generated share link, open it in different browsers including older IE kernel browsers, and verify that the page loads normally and displays the correct party building material retrieval interface.

- Initiate a retrieval request, check the background logs, and confirm that the business system user identifier has been correctly passed to the FastGPT interface.
- Wait for the cache duration to expire, then verify that the retrieval results have been updated to the latest party building material content.
