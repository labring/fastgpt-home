# Party Building Learning Assistant for Theoretical Learning Q&A: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for party building theoretical learning Q&A mainly comes from authoritative documents, intra-party regulations, learning outlines, special party lecture materials released by central and local party committees, as well as internal party building training documents. The data update rhythm is adjusted synchronously with the release of authoritative documents. Internal documents are updated as needed, usually with one synchronization per week or month. Most documents are formal manuscripts with a fixed chapter structure, including fields such as title, main text, citations, and signature. Some present learning content in Q&A format, and the length of individual documents varies widely.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
The high credibility requirement of authoritative materials means retrieval must prioritize recalling officially released documents and avoid mixing in non-authoritative content. Documents have a fixed structure and wide length variation, so chapter logic must be retained during chunking to prevent disruption to the coherence of theoretical expressions. Update frequency is not fixed, so both incremental synchronization and full refresh modes must be supported. Some documents include external learning links. Link format and access permissions must be handled correctly during recall to ensure users can access them normally. Most user questions focus on policy interpretation and theoretical terms, so core concepts must be matched accurately to avoid irrelevant general content.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Ensure retrieved party building theoretical content matches the core of the question and avoids mixing in irrelevant content |
| `limit` | Top 6–8 results | Cover core theoretical points while keeping total context length within model input limits |
| `usingReRank` | Enabled | Party building content often has logical hierarchies, and re-ranking improves the ranking priority of highly relevant documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Convert colloquial user questions into standard theoretical expressions to improve retrieval accuracy |
| `collectionIds` | Bind to the exclusive party building knowledge base ID | Isolate other business data to ensure only documents related to party building learning are retrieved |
| `searchMode` | Semantic search | Adapt to the semantic matching needs of theoretical learning Q&A |

## Three common mistakes
- Symptom: Calling the knowledge base interface returns document URLs, and clicking to access prompts "Only support .txt". Cause: Imported party building documents contain external links in non-text formats, or the knowledge base configuration does not enable access permissions for the corresponding document types.
- Symptom: Retrieval results have low matching degree with theoretical questions and cannot accurately answer learning doubts. Cause: A reasonable `similarity` threshold is not set, or `datasetSearchUsingExtensionQuery` is not enabled to optimize question expressions, resulting in retrieved content deviating from core theoretical points.
- Symptom: A "Request failed with status code 400" error appears when uploading knowledge base documents. Cause: Correct application permissions are not configured when synchronizing from the Feishu knowledge base, or documents contain unescaped special characters that cause parsing failure.

## How to confirm the configuration is complete
- Enter a typical party building theoretical question and check whether retrieval results prioritize recalling authoritative documents released by central and local party committees.
- Check the ranking of retrieval results, confirm whether highly relevant content is ranked first to verify that `usingReRank` is effective.
- Import a test party building document and confirm that core content can be correctly retrieved during retrieval to verify that the `similarity` threshold is set appropriately.
- View the knowledge base configuration page and confirm that `collectionIds` is bound to the exclusive party building knowledge base to isolate other business data.
