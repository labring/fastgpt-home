# Party Building Learning Q&A for 12345 Citizen Hotline Work Order Processing: Document Parsing and Chunking

## Data profile for this category
This category of data typically comes from the 12345 citizen hotline platform, contractor business systems, official knowledge bases, citizen return visit evaluation data, and local hotline management-related documents. Daily processed documents include request registration forms, dispatch records, handling responses, return visit records, extension applications, return instructions, and knowledge base entries. Data is updated daily. Core fields include request number, contracting unit, handling deadline, citizen request content, response wording, and more. Some documents are structured tables, while others are unstructured text, with no unified fixed format.

## Constraints imposed on document parsing and chunking
Multi-source and heterogeneous data sources require the parsing module to support parsing of both structured tables and unstructured text, to adapt to work order documents of different formats. Daily batch-updated data requires controlling the parsing duration of individual files to avoid blocking the overall workflow. Differences in fields across different documents require the chunking logic to adapt to content structure. For example, request registration forms should be split by request and dispatch information, while response documents must retain the contextual association of complete response wording. Work order data has strong relevance; chunking must retain associated information such as the responsible unit and handling progress of adjacent work orders, to avoid losing key content after splitting, which affects the contextual accuracy of party building learning Q&A.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the length of a single citizen request or response in work order documents, avoiding splitting that breaks key information |
| `chunkSplitter` | By paragraph + semantic boundary | Adapts to unstructured response text and structured registration form fields, preserving content logical integrity |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Matches the processing duration of daily batch work order documents, avoiding timeouts for small files or insufficient processing for large files |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Compatible with the upload needs of batch exported work order summary tables and multi-page response documents |
| `customPdfParse` | Enable OCR mode | Required for text recognition of PDF documents converted from scanned paper work orders, adapting to non-editable PDF scenarios |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different types of work order documents (tables/text) to meet the contextual association requirements of party building learning Q&A |

## Three common misconfigurations
- When uploading an Excel-format request registration form, parsing results may have missing or empty fields. The cause is that structured table parsing adaptation rules are not enabled, and the default chunking logic fails to identify the correspondence between table columns and rows, resulting in incomplete data extraction.
- After uploading a batch work order summary document, the interface shows a request failure, and the parsing duration exceeds 2 minutes. The cause is that the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default timeout duration is insufficient, causing large-volume files to be terminated before parsing is complete.
- After uploading a knowledge base entry document, some response wording content is missing from the training data. The cause is that `chunkSize` is set too small, splitting a complete response into multiple independent chunks, causing contextual information such as associated responsible units and handling deadlines to be split into different chunks, and losing association relationships during training.

## How to confirm the configuration is correct
- Upload a single Excel-format request registration form, check if the parsed text contains complete fields such as request number, contracting unit, citizen request content, to confirm that structured parsing is effective.
- Upload a multi-page PDF response document under 500 MB, check if the parsing progress is completed within the duration set by `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout error prompts.
- Adjust `chunkSize` to different ranges, upload the same response document, compare the chunking results to confirm that adjacent chunks retain associated responsible units and handling progress information.
- Check the backend upload settings of FastGPT v4.17.0, confirm that `UPLOAD_FILE_MAX_SIZE` is greater than the maximum document volume to be uploaded, with no file size limit error.
