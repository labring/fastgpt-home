# "One-stop One Thing Completion" Joint Handling Party Building Learning Q&A: Knowledge Base Retrieval and Recall

## What Data This Category Contains
This category’s data typically comes from the national integrated government service platform’s One-stop One Thing Completion special zone, local integrated government service platforms, electronic document repositories, and departmental approval systems. The update frequency is daily.
Managed documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation forms, parallel approval opinions, and completion receipts.
Documents cover fields like cross-departmental item associations, pre-approval conditions, material lists, and handling procedures. There is no unified fixed format. Some documents are structured lists. Others are unstructured policy explanations.

## Constraints for Knowledge Base Retrieval and Recall
Cross-departmental, multi-source data requires retrieval to cover multiple independent associated knowledge base sets. Retrieving only a single department’s approval system data leads to missing complete joint handling item information.
The daily update frequency requires the retrieval link to support incremental synchronization. This ensures daily updates—such as adjustments to joint handling item lists and changes to material requirements—are included in the retrieval scope promptly.
Diverse document types require retrieval to balance structured field matching and semantic understanding. Relying on a single retrieval mode fails to adapt to both structured list documents and unstructured policy explanations.
Business logic like front and back approval relationships for joint handling items and material reuse rules requires recalled results to be sorted by business priority. This lets users quickly access core joint handling information.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches cross-departmental association descriptions of joint handling items, filters irrelevant individual government approval content with low similarity, and ensures recalled results focus on joint handling business |
| `limit` | Top 8 entries | Covers cross-departmental associated approval documents, material lists and other content, avoids missing core cross-departmental joint handling information due to too few entries |
| `searchMode` | hybrid | Combines keyword retrieval and semantic retrieval, adapts to structured joint handling item lists and unstructured policy explanation documents, and improves retrieval coverage |
| `usingReRank` | Enabled | Reorders recalled results based on the front and back approval relationships of joint handling items, prioritizes returning core business documents such as pre-approval requirements and material reuse rules |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically optimizes question expressions related to party building learning, matches policy basis corresponding to joint handling items, and improves retrieval accuracy in party building scenarios |

## Common Misconfigurations
- Calling the retrieval interface returns an error message containing {"code":514,"statusText":...}. This occurs when the associated knowledge base `collectionIds` is not configured correctly, or no valid authentication parameters are included in the interface call.
- Recalled results only return approval documents from a single department, and do not cover full cross-departmental joint handling content. This occurs when `searchMode` is set only to semantic retrieval, and hybrid retrieval mode is not enabled. This prevents matching structured joint handling item list fields.
- Party building learning-related questions cannot recall corresponding joint handling policy basis. This occurs when `datasetSearchUsingExtensionQuery` is not enabled, so questions are not optimized to match government policy expression logic.
