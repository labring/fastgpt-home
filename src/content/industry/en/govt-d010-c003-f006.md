# Real Estate Registration Party Building Learning Q&A: Citation Sources and Traceability

## Data Overview for This Category
Data sources for this category include real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. Update frequency is daily.
Commonly involved documents include registration applications, ownership certificates, survey results, tax payment vouchers, real property rights certificates, and real estate registers.
Data fields cover right subject information, real estate location, right type, ownership restriction status, and more. Single document size ranges from several pages to dozens of pages. Core fields must strictly match the statutory elements of ownership registration.

## Constraints for Citation Sources and Traceability Workflow
Daily updated data sources require citation traceability to refresh associated knowledge base data synchronously. This prevents delayed ownership information issues.
Multi-system aggregated data sources require clear labeling of the original system source for each citation. This prevents confusion between ownership data from different channels.
Wide variation in document size requires traceability to adapt to content fragments of different lengths. It also requires association with the unique identifier of the corresponding registration business. This ensures traceability can locate specific registration files.
Citation of sensitive fields such as ownership restriction status must strictly match the field content of the original voucher. This prevents information deviation.

## Configuration Settings

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Adapts to the fragment length of real estate registration documents, avoiding truncation of core ownership information |
| `responseData` | Includes citation ID and original source path | Meets the business requirement of tracing back to specific registration files in party building learning Q&A |
| `detail` | Enable full content return | Ensures citation content includes key fields such as complete right subject information and location |
| Single recall upper limit | Top 5 entries | Matches the number of associated data sources for real estate registration business, avoiding redundant information interfering with Q&A accuracy |
| Maximum return character count | 1000–1500 characters | Adapts to the output length requirements of party building learning Q&A, avoiding overly long content |
| Synchronous update cycle | 1 time per day | Matches the daily update frequency of real estate registration data, ensuring timeliness of citation content |

## Three Common Configuration Errors
- Tool call modules in workflows fail to output citation content after connecting to the knowledge base. The cause is that the `detail` configuration item is not enabled, so returned content does not associate with the citation identifier of the original document.
- Citation symbols appear garbled in conversation output, eventually displaying as standard quotation marks. The cause is incorrect configuration of the `responseData` return format, leading to failure to correctly parse the encoding of citation markers.
- Knowledge base retrieval returns citation fragments even when the query has no matching content. The cause is that the automatic generation logic when no matches are found is not disabled, and the restriction to only recall citation sources within the matching range is not applied.

## How to Confirm Correct Configuration
- Initiate a test conversation with a clear real estate ownership query. Check if the output content includes a traceable citation identifier at the end.
- Review the `responseData` field in the interface return. Confirm that it includes citation ID and original source path information.
- Input a query that does not exist in the knowledge base. Verify that no citation fragments are returned.
- Adjust the value of `quoteMaxToken`. Test whether long document fragment citations are fully retained or reasonably truncated.

The values listed here are common starting points and should be evaluated against the reader's own samples.
