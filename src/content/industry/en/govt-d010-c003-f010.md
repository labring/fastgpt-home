# Real Estate Registration Party Building Learning Q&A: Knowledge Base Retrieval and Recall

## What this category’s data looks like
The data sources for this category are the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate repository. The update frequency is daily. Daily documents include registration application forms, ownership certificates, survey results, tax payment vouchers, real estate property rights certificates, and registration books. Data fields center on core information such as real estate right ownership, location, right type, and restriction status, with no custom statistical units added.

## Constraints Imposed on Knowledge Base Retrieval and Recall by These Data Characteristics
This category’s data covers heterogeneous documents from multiple systems, with significant format differences. This requires the knowledge base retrieval to adapt to chunking and indexing rules for different document structures. The daily updated data volume is stable, so the recall link must support incremental synchronization to ensure data timeliness. Core data focuses on key information such as real estate right ownership and restriction status. Retrieval must prioritize matching high-weight fields to avoid irrelevant results interfering with the accuracy of party building learning Q&A. Additionally, incorrect recall may trigger administrative risks, so the proportion of low-similarity recall results must be strictly controlled.

## Three Common Mistakes
- Symptom: Re-ranking results return false, and the interface shows re-ranking is not effective. Cause: The corresponding re-ranking model is not bound in the global configuration, or the `usingReRank` configuration item is not enabled.
- Symptom: No optional values appear for knowledge base variable references, and the target dataset cannot be selected in the workflow. Cause: The real estate registration-specific knowledge base collection is not configured as a referenceable public collection, or dataset permissions are not enabled in the workflow node.
- Symptom: The number of knowledge base files uploaded in a single operation exceeds the limit, and upload fails. Cause: The file upload upper limit has not been adjusted according to the locally deployed server storage configuration, or large-volume documents have not been split into chunks that comply with chunking rules.

## How to Confirm Proper Configuration
- Submit a test query such as "Real estate registration ownership verification process", and check if the retrieval results include documents related to real estate property rights certificates and registration application forms.
- View the retrieval log to confirm that the `usingReRank` configuration is active, and re-ranking score sorting meets expectations.
- Check the variable reference options in the workflow node, and confirm that the real estate registration-specific knowledge base collection appears in the optional list.
- Simulate a daily incremental update task, and confirm that the knowledge base can automatically synchronize the latest registration data without synchronization failure error reports.
