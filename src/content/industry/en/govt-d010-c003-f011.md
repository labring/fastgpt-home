# Party Building Learning Q&A for Real Estate Registration: Forms and Interactions

## What the data for this category looks like
Real estate registration data is sourced from the real estate registration information system, cadastral survey database, housing transaction online signing system, tax system, and electronic certificate library. Data updates occur daily.
Commonly used documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and registers. Fields cover real estate location, right holder information, ownership source, restriction status, surveying and mapping area, and more.
All fields follow standard government affairs system formats, with no custom units or additional fields.

## What constraints do these characteristics impose on forms and interactions
Data sources are scattered and updated daily. Form interactions must support real-time pulling of the latest registration information and ownership status. This prevents registration errors caused by expired data.
There are various types of daily documents. Forms must adapt to the field formats of different documents. For example, area entry for surveying and mapping results and number verification for ownership certificates require differentiated input rules for each document type.
Registration errors can lead to property rights disputes or administrative litigation. Forms must add a pre-verification link to provide real-time prompts for required fields and non-compliant input.
As a core link in confirming real estate rights, form interactions must focus on core Q&A content such as ownership source and restriction status. This avoids irrelevant information interfering with the accuracy of party building learning Q&A.

## Three common mistakes
- Symptom: A `quote type error` error occurs when configuring variable references for party building Q&A, and a format error prompt pops up on the interface. Cause: Variables are not defined according to the field naming specifications of real estate registration. For example, mistakenly writing `{Real Estate Ownership Certificate Number}` as `{Certificate Number}`, causing the system to fail to recognize the valid reference type.
- Symptom: When configuring large model calls for forms, the available models do not match the official introduction, and GPT4 or Claude 3.5 cannot be selected. Cause: The access permissions for the corresponding large models have not been enabled in the system backend, and the key configuration and interface connectivity testing for custom channels have not been completed.
- Symptom: After enabling the form reranking function, the recall results are not sorted according to core ownership information, and irrelevant content appears first. Cause: The reranking trigger conditions are not configured correctly, or the core fields for reranking are not specified as real estate registration core data such as ownership source and restriction status.

## How to confirm that the configuration is complete
- Enter test real estate location and right holder information, check whether the linked verification configured in `formInput` is triggered, and there are no format error prompts.
- Initiate a real estate ownership Q&A related to party building, check whether the recall results prioritize displaying core fields such as ownership source and restriction status.
- View the system log to confirm that no `quote type error` errors occur in variable references, and interface calls are normal.
- Simulate a multi-source data recall scenario, confirm that information pulled from the cadastral survey database and tax system is synchronously updated in the Q&A results.
