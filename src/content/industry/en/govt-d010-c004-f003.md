# Party Building Learning Q&A for Proactive Public Disclosure and Policy Release: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data primarily comes from government portal websites, document management systems, government information disclosure directories, policy document repositories, and press conference materials. Daily documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Some documents include approval process records. Data is updated daily. Each individual document includes fields such as public disclosure attribute, confidentiality level, release time limit, and affiliated column.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
Data is updated daily, so dialogue context must filter expired policy documents to avoid returning outdated content. Documents include public disclosure attribute and confidentiality review fields. Prompt engineering must embed verification logic to prevent the output of confidential or undisclosed information. This category does not require waiting for individual applications. Multi-turn dialogue follow-up questions must be linked to the current column context to accurately match public disclosure directory entries, and avoid returning irrelevant content across columns. At the same time, the scope of returned content must be strictly controlled to prevent situations where information that should be disclosed is not disclosed, or is disclosed in error.

## Configuration settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | A variable group that includes public disclosure attribute and confidentiality level fields | Matches the core fields of documents in this category, used to verify content compliance during dialogue |
| `messages` | Bind initial dialogue frames linked to department public disclosure columns | Provides a fixed contextual basis for multi-turn dialogue, linking the public disclosure rules of the corresponding column |
| Single search limit | `Top 5` | The public disclosure directory entries for this category are moderately sized. Limiting the number of entries improves response speed |
| Context window length | `8000–12000 characters` | Adapts to the typical length of policy documents and interpretation drafts, avoiding truncation of key content |
| Response timeout threshold | `120 seconds` | Adapts to the typical response requirements of government public disclosure scenarios |
| `chatId` | Bind the unique identifier of the corresponding public disclosure column | Distinguishes dialogue contexts for different columns, ensuring returned content matches the corresponding column |

## Three common configuration errors
- Incorrect number of returned dialogue results: The returned number of policy document entries exceeds the preset quantity. This happens when the single search limit is not configured, or the limit value exceeds the actual number of entries in the public disclosure directory.
- Slow dialogue response speed: Timeouts occur after multi-round follow-up questions. This happens when the context window length is not limited, leading to loading excessive historical policy documents and outdated data.
- Unresponsive opening shortcut buttons: Clicking the preset shortcut keys does not load initial dialogue content. This happens when the initial dialogue frame configuration corresponding to the shortcut keys is not correctly bound in `messages`.

## How to confirm the configuration is correct
- Upload a test policy document, initiate a dialogue that includes a public disclosure attribute query, and check whether the returned content matches the public disclosure attribute field of the document.
- Initiate multi-round follow-up questions, verify that `chatId` is bound to the correct column context, and check whether returned content only relates to public information from the current column.
- Trigger sensitive information verification, check whether preset interception rules are triggered, and verify that the compliance verification logic is active.
- Click the opening shortcut button, verify that the preset initial `messages` content is loaded, and confirm that the shortcut key binding is correct.
