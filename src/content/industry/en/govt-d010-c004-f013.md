# Party Building Learning Q&A for Proactive Public Disclosure and Policy Publication: Sharing and Embedding

## What This Category of Data Looks Like
This category of data is primarily sourced from government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials, with a daily update frequency. Daily processed documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Data fields include document numbers, release times, public disclosure attributes, secrecy levels, associated interpretation content, and other relevant items. All data must comply with compliance requirements for government public disclosure, with no additional custom units.

## Constraints Imposed on the "Sharing and Embedding" Workflow
The high-frequency daily updated data requires embedded components to support real-time synchronization of the latest policy content, to avoid content lag. The multi-type document structure requires embedded tools to adapt to different formats of policy documents, interpretation drafts, public disclosure directories and other content, and be compatible with both text and structured data. The public disclosure attributes and secrecy review requirements for government data mean that the embedding link must strictly filter content that has not passed public approval, to prevent sensitive information leaks. The proactive public release attribute for the general public requires that sharing and embedding functions support cross-platform distribution, adapting to scenarios such as government portals and new media accounts.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `shareId` | Bind the unique identifier of the corresponding proactive public disclosure policy knowledge base | Ensure the embedded Q&A tool is associated with specified government public disclosure content, avoiding confusion across knowledge bases |
| User avatar settings | Use the official government uniform avatar template, or hide the default avatar | Comply with government visual specifications, avoiding public misunderstanding caused by non-official avatars |
| Iframe loading timeout threshold | 10–15 seconds | Adapt to the general access speed of government networks, avoiding excessively long wait times that impact user experience |
| Session persistence configuration | Enable session binding, associate with user access identifiers | Support locating to the previous chat window after page refresh, conforming to common usage habits |
| Content filtering rules | Enable public attribute verification, filter content that has not passed approval | Comply with government secrecy and public review requirements, preventing sensitive information leaks |
| Embedded domain name restriction | Restrict to registered government website domain names | Prevent unauthorized platforms from using public Q&A content, ensuring publishing compliance |

## Three Common Misconfigurations
- Phenomenon: The embedded interface fails to display user avatars and application images, and some browsers fail to load. Cause: A compliant avatar resource path is not configured, or the embedded code does not adapt to the security policy restrictions of government browsers.
- Phenomenon: A new chat window is recreated after page refresh, and previous session content cannot be retained. Cause: Session persistence configuration is not enabled, or session loss occurs because user access identifiers are not bound.
- Phenomenon: The embedded Q&A tool returns undisclosed policy content. Cause: Public attribute verification rules are not enabled, or the configured `shareId` is associated with knowledge base content that has not passed secrecy review.

## How to Verify Successful Configuration
- The government website page with the embedded Q&A tool is accessed, and the interface is checked to confirm whether standard-compliant avatars or no default avatars are displayed.
- The embedded page is refreshed, and verification is performed that the chat window retains previous conversation content without recreating a new session.
- Questions related to undisclosed policies are submitted, and confirmation is obtained that the tool cannot return corresponding content and only displays disclosed policy information.
- The sharing link is copied, and access is attempted from an unregistered domain name. Verification is made that the link fails to load normally or is blocked.
