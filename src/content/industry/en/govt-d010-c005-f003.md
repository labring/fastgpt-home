# Party Building Learning Q&A for Property Rights, Assets and State-owned Capital Management: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Data for this category originates from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, valuation agency reports, and financial statements. The update frequency is monthly.
Commonly processed documents include property rights registration forms, asset valuation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval forms.
Included fields cover asset ownership numbers, evaluation baseline values, transaction approval status, disposal process nodes, and similar items. Units include monetary measurement, area, quantity, and other types.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Data for this category comes from multiple dispersed sources and uses a fixed update cycle. Multi-turn dialogue must link context such as asset ownership and transaction progress across different systems, to avoid confusing asset numbers and disposal nodes across sessions.
Monthly updated asset ledgers require prompts to regularly sync the latest compliance rules and data versions, to ensure Q&A content matches currently valid information.
Documents contain professional valuation terminology and approval process fields. Multi-turn dialogue must retain key asset identifiers from historical interactions, to prevent Q&A deviations caused by lost context.
Additionally, Q&A related to asset disposal must strictly anchor to compliance processes. Prompts must limit Q&A scope to party building learning and state-owned asset compliance categories, to avoid exceeding business boundaries.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 8000–12000 characters | Adapts to the long text requirements of property rights documents and multi-turn dialogue history storage |
| Number of Conversation History Rounds to Retain | First 10 rounds | Covers multi-turn interaction scenarios for the full asset disposal process |
| Prompt Variable Binding | Bind `variables` to asset ownership fields | Ensures exclusive information such as the current session's associated asset number is automatically included in Q&A |
| Multi-turn Dialogue Session Identifier | Bind `chatId` to the unique session identifier | Distinguishes dialogue contexts for different asset projects, avoiding cross-session confusion |
| Conversation History Passing | Carry complete historical interaction content via `messages` | Ensures complete context transfer during multi-turn dialogue |
| Reference File Display Toggle | Enable or disable based on business scenarios | Meets the requirement of not displaying source files in party building learning scenarios |
| Maximum Response Timeout | 60 seconds | Adapts to processing time for complex asset data queries |

## Three Common Misconfigurations
- Phenomenon: Unconfigured source file reference content is displayed at the bottom of the dialogue. Cause: The reference file display switch was not adjusted in system settings, causing the system to automatically attach source file links.
- Phenomenon: Historical context is lost after multi-turn dialogue exceeds the preset number of rounds. Cause: The `chatId` parameter was not correctly bound, resulting in session context not being persistently stored, and cross-turn interactions cannot be linked to historical asset information.
- Phenomenon: The question classification module matches incorrect asset disposal processes. Cause: The prompt was not bound to category-specific document fields, causing the model to fail to distinguish between different process rules for property rights transfer and asset disposal.

## How to Verify Correct Configuration
- Initiate a first round of questions containing an asset number, then initiate a second follow-up question associated with that asset. Verify that the dialogue context is not lost.
- Adjust the reference file display switch, then initiate a question and check whether the corresponding source file is displayed at the bottom of the reply to confirm that the switch takes effect.
- Configure `variables` to bind to asset ownership fields, then initiate a question and verify that preset exclusive asset information is automatically included in the reply.
- Initiate a dialogue that exceeds the preset number of rounds, then verify that the session still retains key asset identifiers from historical interactions.

The values provided are common starting points and should be measured against the reader's own samples.
