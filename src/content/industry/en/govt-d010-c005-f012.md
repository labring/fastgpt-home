# Party Building Learning Q&A for Property, Asset and State-owned Capital Management: Deployment and Upgrade

## What the data for this category looks like
Data for this category primarily comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, valuation firm reports and financial statements. Daily processed documents include property rights registration forms, asset valuation reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval slips. Data fields include asset number, ownership status, appraised value, transaction progress, and others. The data update frequency is monthly, with no requirement for real-time high-frequency updates. Document structures cover structured forms and semi-structured reports, requiring integrated association of data across multiple internal systems.

## What constraints these characteristics impose on the deployment and upgrade phase
Deploy scheduled synchronization tasks to meet the monthly update frequency requirement and avoid frequent data pulls that consume system resources. Adapt to different database types for multi-source data, and configure corresponding connection parameters separately. Configure targeted parsing rules to handle diverse document structures and adapt to asset documents of different formats. Implement context-aware associated storage during deployment to support cross-document associated information extraction during Q&A. Configure failure alerts and rollback mechanisms to ensure data security, as errors in state-owned asset-related data have serious consequences.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | MongoDB connection string connected to the property rights exchange system | Property transaction data is typically stored in MongoDB, so the data source type must be matched |
| `PG_URL` | PostgreSQL connection address for the state-owned assets supervision information system | State-owned assets supervision systems commonly use PostgreSQL to store asset registration and approval data |
| `REDIS_URL` | Configure the connection address for the local Redis service, set cache timeout to 7200 seconds | Cache common matching results for party building Q&A to reduce database load |
| `DB_MAX_LINK` | Set to 8-12 | Adapt to concurrent data access requirements of state-owned assets systems |
| `STORAGE_S3_ENDPOINT` | Fill in the endpoint address of the enterprise's internal object storage, set single file limit to 1000 MB | Store large documents such as asset valuation reports and property rights transfer plans |
| `ROOT_KEY` | Generate a random string in accordance with internal permission management rules | Configure platform super administrator permissions to restrict unauthorized access |

## Three common mistakes
- After uploading asset-related documents, the error "File parsing failed" is returned, and the log shows that the file storage path is empty. Cause: `STORAGE_S3_ENDPOINT` is not correctly configured to point to the internal compliant storage, causing files to fail to upload normally to the system.
- Regular users can access the super administrator configuration page, and permission verification fails. Cause: `ROOT_KEY` is not correctly set, or `FE_DOMAIN` is not configured to restrict front-end access domain names.
- Scheduled sync tasks time out and fail to complete monthly asset data updates. Cause: The configuration value of `DB_MAX_LINK` is not adjusted, resulting in insufficient concurrent connections and blocked data pulls.

## How to confirm the configuration is complete
- Run a database connection test to verify that `MONGODB_URI` and `PG_URL` can normally pull test data.
- Upload a standard property rights registration form to confirm that the file can be parsed and stored normally to the specified storage location.
- Configure test users and administrator users to verify that permission divisions meet expectations.
- Trigger a scheduled sync task to confirm that data update progress is normal and no timeout errors occur.
