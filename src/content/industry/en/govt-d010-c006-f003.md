# Party Building Learning Q&A for Infectious Disease Information Reporting and Monitoring: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
The data sources for this category are the Chinese Center for Disease Control and Prevention Information System, medical institution HIS and infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Data fields cover basic case information, diagnosis results, reporting time limits, correction status, and more. Relevant content must be processed in strict accordance with legal infectious disease reporting rules. The data structure centers on case reporting and monitoring and early warning, and differs from daily hospital diagnosis and treatment management data.

## What Constraints Do These Characteristics Impose on the "Multi-turn Dialogue and Prompt Engineering" Link
The high-frequency daily updated data requires limiting the scope of historical messages in multi-turn dialogue, to avoid loading expired or redundant content that interferes with judgment. The field differences across multiple document types require prompts to clearly distinguish processing logic for different documents. For example, distinguish verification rules between infectious disease report cards and epidemiological investigation reports. Integrated data sources across multiple systems require prompts to specify associated fields, to ensure accurate information matching. Legal reporting rules require multi-turn dialogue to retain a verification link. This ensures case diagnosis, reporting time limits, and other content comply with regulatory requirements, while limiting the scope of sensitive information in dialogue outputs. In addition, requirements for time-consuming links such as correcting duplicate cards and summarizing abnormal signals require multi-turn dialogue to support step-by-step guidance for users to supplement information. This avoids model understanding deviations caused by too much content input in a single turn.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | First 8 turns of dialogue + 3 latest documents of the day | Adapt to the daily updated data rhythm, avoid loading expired and redundant content |
| `messages` | Truncate to within 12000 characters | Limit the context length of a single dialogue to prevent model processing overload |
| `variables` | Bind case ID and reporting time limit fields | Ensure prompts accurately call the exclusive data fields of this category |
| Question Optimization | Calibrate based on actual testing | Adapt to field differences across multiple types of documents, optimize question understanding accuracy |
| Single Input Limit | 1000 characters | Match the daily information input habits of verification and correction work |
| Rerank Recall | Top 5 matching results | Focus on core monitoring and reporting data, avoid irrelevant information interfering with dialogue logic |

## Three Common Misconfigurations
- Symptom: After uploading an infectious disease report card file via the dialogue interface, the associated data fields returned by the interface are empty. Cause: The binding variable for file upload is not configured in `variables`, causing the prompt to fail to recognize the incoming document content.
- Symptom: When using a prompt to call an MCP tool, the displayed epidemiological investigation report image is incomplete. Cause: The display range of image loading is not limited, or the prompt does not specify that only image fragments related to monitoring and early warning should be extracted.
- Symptom: After upgrading to FastGPT v4.17.0, a symbol tracing the display rules appears at the end of the dialogue return result. Cause: The default rule trace output is not disabled in the prompt configuration, causing the model to automatically attach regulatory explanation content.

## How to Confirm the Configuration Is Correct
- Initiate a multi-turn dialogue containing past case information, check whether the model can accurately call the documents updated on the day, and confirm that no expired data is loaded in the context.
- Upload an infectious disease report card, test whether the dialogue interface can correctly recognize the incoming file content, and verify that the `variables` configuration takes effect.
- Trigger an MCP tool call, check whether the displayed epidemiological investigation report image only contains core monitoring-related fragments, and confirm that the image display rule configuration is correct.
- Initiate a test dialogue containing rule tracing, check whether no additional rule symbols appear at the end of the return result, and confirm that the prompt configuration meets the requirements.
