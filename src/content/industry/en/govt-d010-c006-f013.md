# Infectious Disease Information Reporting and Monitoring Party Building Learning Q&A: Sharing and Embedding

## What this category of data looks like
This category of data originates from the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems. It is updated daily. Daily processed documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Data fields cover basic case information, diagnosis results, reporting time limits, correction notes, and monitoring early warning signals. No additional statistical figures or unauthorized regulatory details are included.

## Constraints on the Sharing and Embedding Workflow
Multi-source data with daily updates requires embedded Q&A systems to regularly sync the latest documents to ensure content timeliness. Documents contain legally reported sensitive case information, so privacy fields must be strictly filtered during embedded sharing to avoid data leaks. Business processes have strict requirements for reporting time limits and early warning timeliness, so the response speed of shared links must match the timeliness standards of disease control work. Access permissions for management pages and sharing services must also be separated to prevent unauthorized access to internal management interfaces.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Sharing Port | Separate from the management page port, such as `8081` | Prevent unauthenticated shared links from accessing the FastGPT management login page, and adapt to port separation requirements for offline deployments |
| Sharing Link Identifier | Use the system-generated `shareId` | Ensure uniqueness and traceability of embedded links, facilitating permission control |
| Context Sync Cycle | 2:00 AM to 4:00 AM daily | Match the daily update frequency of this category of data, ensuring embedded Q&A content syncs with the latest monitoring data |
| Sensitive Field Filtering | Hide fields such as case ID numbers and residential addresses | Comply with public health data privacy protection requirements and prevent sensitive information leaks |
| Recommended Question Trigger Delay | Return within `10 seconds` | Guide users to narrow their question scope, adapting to the interaction logic of Party Building learning Q&A |
| Interface Timeout Threshold | `30 seconds` | Match the response timeliness requirements of disease control business, avoiding long waits that disrupt work processes |

## Three Common Configuration Mistakes
- Symptom: Unauthenticated shared links can directly navigate to the FastGPT management login page. Cause: The sharing service and management page use the same port, and no permission isolation configuration is set.
- Symptom: Embedded Q&A results include unanonymized case privacy information. Cause: No sensitive field filtering rules are configured, and original business document content is pushed directly.
- Symptom: Embedded recommended questions do not match the infectious disease monitoring and Party Building learning scenarios. Cause: No category-specific document library is bound, and a general Q&A knowledge base is used.

## How to Confirm Successful Configuration
- The generated shared link is accessed, and verification confirms it cannot navigate to the FastGPT management login page.
- A test question containing case privacy information is submitted, and verification confirms no sensitive field content appears in the returned results.
- After the daily sync cycle completes, a question involving the day's updated data is submitted, and verification confirms the returned content includes the latest monitoring information.
- The embedded recommended question button is clicked, and verification confirms the returned questions focus on topics related to infectious disease monitoring or Party Building learning.
