# Infectious Disease Information Reporting and Monitoring Party Building Learning Q&A: Conversation Logs and Auditing

## What This Category of Data Looks Like
This category of data originates from the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems, with daily updates. Daily documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Data fields include case identifiers, reporting time limits, diagnostic information, correction status, and more. All data must adhere to legally required reporting format standards, with no additional custom non-standard fields.

## What Constraints These Characteristics Impose on Conversation Logs and Auditing
The daily update frequency of this category of data requires conversation logs to be archived and retained per natural day. This enables full workflow review of daily epidemic-related Q&A.
The rigor of legally required reporting documents requires the auditing link to fully record each Q&A’s context, call parameters, and associated specific document entries. This prevents missing operational traces for key links such as case correction and reporting time limit verification.
In multi-source data access scenarios, logs must also associate call identifiers from different source systems. This ensures matching of corresponding data sources and update statuses during audits.
Additionally, the potential consequences of errors in legally required reporting require audit logs to support quick retrieval via fields like case identifiers and reporting time. This facilitates locating abnormal operations.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Log Retention Period | 180 days | This category of data is updated daily, and legally required reporting-related documents must be retained for a sufficient duration to support compliance auditing |
| `chatId` Association Configuration | Enabled | Must bind unique conversation identifiers to enable full-process tracing of individual conversation links |
| `detail` Log Recording Switch | Enabled | Must fully record Q&A context, call parameters, and associated document entries to support audit tracing |
| `responseChatItemId` Binding Switch | Enabled | Must associate unique identifiers for each reply, to ensure that specific conversation reply content can be matched during auditing |
| Log Batch Write Limit | First 50 entries | Avoid excessive log writes in a single operation causing storage pressure, and adapt to the daily updated data volume of this category |

## Three Common Misconfigurations
- A 503 error is displayed on the conversation page when uploading a document, but background logs show the file upload was successful. The cause is inconsistent permission configurations between the log storage module and the file upload module, leading to frontend requests being blocked while background writes proceed normally.
- When configuring variable update records to count the number of Q&A calls, the count fails to update. The cause is that the `detail` log recording switch is not enabled, so the system cannot capture trigger parameters and counting conditions for Q&A calls.
- After upgrading to FastGPT v4.17.0, conversation records disappear when refreshing the conversation page, and a new conversation is displayed. The cause is that persistent storage configuration for `chatId` is disabled by default after the version upgrade, and the unique identifier of the original conversation is not retained.

## How to Verify Successful Configuration
- Run a Q&A related to infectious disease report cards. Check if background logs include the `chatId`, `responseChatItemId`, and `detail` fields to confirm complete log recording.
- When retrieving logs, enter a case identifier or reporting time. Confirm that the corresponding conversation record can be located quickly, matching the retrieval dimensions of this category of data.
- View the log retention directory. Confirm that archived files are generated per natural day, aligning with the daily update rhythm of this category of data.
- Test permission control logic. Confirm that unauthorized subjects cannot access conversation logs containing sensitive case data.
