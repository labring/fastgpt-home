# Party Building Learning Q&A for Petition Matter Handling: Document Parsing and Chunking

## What the data for this category looks like
Service subjects for this category include petition bureaus, departmental petition offices, sub-district and township offices, and responsible unit offices. Data sources include the national petition information system, local petition systems, the 12345 citizen hotline platform, grassroots governance platforms, and historical petition archives. The update frequency is daily.
Commonly processed documents include petition registration forms, acceptance notices, transfer and assignment letters, handling opinions, review and re-examination applications, and resolution plans. Most documents have fixed fields such as requester details, matter details, handling procedures, and policy basis. Some historical archives have inconsistent formatting.

## What constraints do these characteristics impose on the document parsing and chunking link
Daily updated batch documents create steady demand for parsing throughput. Inconsistently formatted historical archives require adaptable multi-type parsing logic.
Fixed fields and legally required handling process content in petition documents must not have their integrity broken by chunking. If integrity is broken, accurate answers to handling procedures in subsequent party building learning Q&A will be affected.
If batch large-file parsing does not use queue control, task failures caused by resource preemption are likely to occur. Additionally, overly long single files carry timeout risks. Parsing and chunking parameters need targeted adjustments.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Petition documents contain fixed fields and process descriptions. This range preserves key information integrity within a single chunk and avoids splitting legally required handling steps |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 seconds | Single petition archives may contain multiple pages. This range adapts to long document parsing time and avoids processing interruption due to timeout |
| `customPdfParse` | Enable locally deployed pdf-marker | Adapts to complex formats such as tables and stamps in petition documents, improving parsing accuracy |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatible with batch-imported historical petition archive packages, meeting the need to upload multiple documents in one batch |
| `chunkSplitter` | Split by paragraph + title | Most petition documents have clear matter titles and paragraph divisions. This splitting method preserves the logical structure of the document |

## Three common mistakes
- Long periods with no return after calling the parsing tool, with the interface showing a timeout status. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. The default value is insufficient for parsing multi-page petition archives.
- Missing fields or format disorder in post-parsing chunk results. The cause is failure to enable the `customPdfParse` configuration. The default parsing tool cannot adapt to special formats such as stamps and tables in petition documents.
- Some files are not processed when batch uploading multiple petition documents. The cause is no queue mechanism configured. Concurrent requests exceed system processing limits, leading to some tasks being discarded.

## How to confirm the configuration is correct
- Upload a petition archive PDF with more than 50 pages, and check if parsing progress completes within the set `PARSE_FILE_TIMEOUT_SECONDS` range.
- Import a petition handling opinion document containing tables, and verify that post-parsing chunks retain table content and original format.
- Upload a petition archive package larger than 500 MB, and confirm the system does not prompt upload size limit exceeded.
- Randomly select chunk results, and confirm that core handling process content is not split into different chunks.

The values provided are common starting points and should be measured against the reader's own samples.
