# Public Data Catalog and Open Party Building Learning Q&A: Citation Sources and Traceability

## What this category of data looks like
The data sources for this category include local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is once per month. Daily maintained documents cover public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Data fields include structured content such as data item names, open scope, desensitization requirements, interface addresses, and update cycles. Some documents include interface call permission descriptions and usage restrictions.

## Constraints on citation sources and traceability
The monthly update feature requires the citation and traceability process to synchronously match the data update cycle to avoid citing expired data. Structured catalog and list data require precise matching of field identifiers to locate specific data items during traceability. Multi-source data assets need a unified traceability chain to distinguish ownership between data provided by departments and data integrated by platforms. Interface document data must retain call permission association information to verify usage compliance during traceability. The desensitization rule field must also be displayed during traceability to prevent leakage of unsensitized original data content.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Matches the average length of public data catalog documents to ensure complete citation of the full description and interface information for a single data item |
| `responseData` | Enabled | Required to return original data fields and source identifiers to meet traceability requirements for data provenance in party building learning Q&A |
| `detail` | Full mode | Displays all associated information for data items, including desensitization rules, update frequency, and open conditions, which meets the detailed requirements of traceability |
| Single recall count | Top 20 items | Covers the full range of data items updated monthly to avoid missing newly opened data resources |
| Context cache duration | 7 days | Matches the monthly update cycle to ensure that catalog data from the corresponding cycle can be associated during traceability |

## Three common misconfigurations
- Phenomenon: The number of model context items shown on the interface does not match the number actually sent to the calling interface. Cause: The monthly update cycle configuration of the public data catalog was not aligned, leading to the recall of expired data entries.
- Phenomenon: A citation upper limit of 1500 tokens was set, but knowledge base data blocks exceeding this length were still included in citations. Cause: Chunking rules were not adjusted for this category’s structured documents, and content was not split by data item granularity.
- Phenomenon: Cited party building Q&A content cannot be linked to a specific public data source identifier. Cause: The original data return configuration was not enabled, and only processed summary information was returned.
