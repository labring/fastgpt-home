# Public Data Catalog and Open Party Building Learning Q&A: Knowledge Base Retrieval and Recall

## What this type of data looks like
Public data catalog and open data are sourced from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Update frequency is monthly. Daily maintained documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Core fields cover data item names, open entities, open conditions, desensitization methods, interface addresses, update cycles, and more. Most content is structured tabular text, with a small number of interface description documents attached.

## Constraints on knowledge base retrieval and recall
These characteristics impose the following constraints on the knowledge base retrieval and recall link:
The monthly update requirement means the retrieval system must support regular full or incremental data synchronization to ensure recalled content uses the latest version. The large number of structured fields means retrieval must support field-level precise filtering, otherwise it cannot match specific conditions such as usage location or open conditions. The existence of desensitization rule documents means recalled results must strictly filter sensitive content to prevent data leaks. Data from different departments is stored in separate collections, so retrieval scope must be isolated by scenario to avoid cross-department data interfering with the accuracy of party building learning Q&A.

## How to set configurations
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `limit` | Top 10 entries | Public data catalog documents have a large volume. Limiting the number of returned entries avoids redundant output and meets the concise needs of party building learning Q&A |
| `similarity` | 0.75–0.85 | Balances precision and recall rate, suitable for public data documents that have both text descriptions and structured fields |
| `searchMode` | vector+keyword | Combines semantic matching from vector recall and precise field matching from keyword retrieval, suitable for retrieval needs of multiple document types |
| `usingReRank` | Enabled | Re-ranks initial recalled results to prioritize matching party building learning-related query intent |
| `collectionIds` | Bind dedicated party building learning collections | Isolates public data collections from different departments, ensuring retrieval scope only covers data relevant to party building learning |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands the user's party building-related query expressions to improve matching with public data documents |

## Three common configuration mistakes
- Symptom: When retrieving data items in the public data catalog with a foreign usage location, the number of returned results is far fewer than the actual entries in the source Excel file. Cause: Mixed retrieval mode for `searchMode` is not enabled. Relying only on vector recall cannot match the precise filtering conditions for structured fields.
- Symptom: When querying the data open list for a specific department, returned content includes documents from other departments. Cause: The `collectionIds` parameter is not configured correctly, and the dedicated dataset collection for the target department is not bound.
- Symptom: Duplicate public data catalog entries appear in the knowledge base. Cause: Deduplication verification is not performed before monthly data updates, and related configurations for automatic knowledge base deduplication are not enabled.

## How to confirm configurations are set correctly
- Enter the name of a data item that belongs exclusively to the party building learning collection, and check if returned results only include documents from this collection.
- Enter a query that includes structured field conditions, and verify that the number of returned results matches the number of matching entries in the source files.
- After uploading new monthly updated data, run the same query to confirm that new data has been included in the recall scope.
- After enabling the `usingReRank` function, check if the order of returned results prioritizes matching party building learning-related query intent.

The values provided are common starting points and should be measured against the reader's own samples.
