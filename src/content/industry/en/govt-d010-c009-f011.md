# Public Data Catalog and Opening Party Building Learning Q&A: Forms and Interactions

## What data in this category looks like
Data sources for this category include local public data opening platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Daily maintained documents cover public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. The update frequency is once per month.
Data fields include data item codes, opening subjects, opening scopes, interface addresses, desensitization methods, update cycles, and more. Units are mostly pieces, times, and MB, with no additional custom unit requirements.

## What constraints these characteristics impose on the forms and interactions link
The monthly data update requirement means the forms and interactions link must support regular synchronization of the latest public data catalogs and opening lists, to avoid using expired data.
Differences in fields across multiple document types require the interaction module to split form groups by document type, to prevent field confusion.
Since data sources involve multiple departmental databases, the `userSelect` module must display selectable data items categorized by department, to reduce user selection complexity.
Data leakage risks require adding desensitization rule checks in form interactions, to ensure submitted configurations meet data security requirements.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `formInput` timeout setting | 600 seconds | Matches the monthly update synchronization rhythm of the data catalog, avoids short timeouts interrupting unfinished form processes |
| `userSelect` grouping configuration | Display categorized by department | Adapts to the characteristics of multiple departmental data sources, simplifies user selection operations |
| Form required field validation | Data item code, interface address are required | Ensures core fields are complete, avoids inconsistencies between the catalog and actual data |
| Interaction guidance copy | 800–1200 characters, prompt in blocks by document type | Matches the structure of multiple types of documents such as public data catalogs and desensitization rules, guides users to fill out accurately |
| `userSelect` item limit | Top 20 items | Controls the amount of data loaded at one time, avoids interface response delays |
| Data item size limit | 1000 MB | Adapts to the transmission restrictions of public data interfaces, avoids transmission failures |

## Three common mistakes
- Phenomenon: The form submits and triggers subsequent processes without completing required field validation, resulting in errors for empty fields. Cause: No required field validation rules are configured, leading to missing core data item information.
- Phenomenon: Sending a new message before completing selection in the `userSelect` module, causing the conversation flow to interrupt and become unrecoverable. Cause: No interaction guidance is set after timeout interrupts, and non-expected user input interrupting the flow is not handled.
- Phenomenon: Attempting to jump from another workflow branch to a form node, and form interaction cannot be triggered. Cause: Cross-branch jump node linkage configuration is not enabled, causing the workflow chain to fail to connect.

## How to confirm the configuration is complete
- Trigger the `formInput` module, intentionally leave required fields blank, verify that the interface displays a prompt for missing corresponding fields.
- Send a new message before completing selection in the `userSelect` module, verify that the system displays a prompt to guide completion of the interaction.
- Set the `formInput` timeout to 600 seconds, initiate a data catalog synchronization request, confirm that no timeout errors occur.
- Jump from another workflow branch to a form node, verify that the form module loads normally and can be filled out normally.

The values provided are common starting points and should be validated against relevant sample datasets.
