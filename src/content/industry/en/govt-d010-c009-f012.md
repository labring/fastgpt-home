# Public Data Catalog and Open Party Building Learning Q&A: Deployment and Upgrade

## Data Profile for This Category
This category consists of structured public government affairs assets. Sources include local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Daily maintained documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions.
Data updates occur once per month. Core fields include data item name, open scope, desensitization requirements, interface address, update cycle, and others. Only structured data assets that can be shared or openly distributed are included. Unstructured content from general government public disclosure is excluded. Authorization boundaries for data sharing and openness are clearly marked.

## Constraints Imposed on Deployment and Upgrade
Since data sources involve multiple government affairs platforms, deployment requires adaptation to different databases and storage interfaces. Corresponding data connection parameters must be configured in advance.
The monthly update rhythm requires upgrade support for incremental synchronization configuration. This avoids full data re-import that would occupy excessive government affairs server resources.
Fixed field specifications for structured data require the knowledge base import process to match preset field formats. Otherwise, missing data items or matching errors may occur.
Binding of desensitization rules and interface documents requires synchronization of data verification logic during deployment. This prevents unsensitized sensitive data from flowing into the party building Q&A process.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://<username>:<password>@<host>:<port>/fastgpt?authSource=admin` | Stores conversation history and knowledge base metadata for party building Q&A, adapts to access formats for government intranet databases |
| `PG_URL` | `postgresql://<username>:<password>@<host>:<port>/fastgpt` | Stores structured public data catalog metadata, supports complex field queries and filtering |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to the upper limit of the database connection pool during monthly batch updates of public data catalogs, avoiding excessive occupation of government affairs server resources |
| `STORAGE_S3_ENDPOINT` | `Intranet object storage address` | Stores desensitized public data documents and interface document attachments, complies with security requirements for government data storage |
| `REDIS_URL` | `redis://<password>@<host>:<port>/0` | Caches high-frequency query results of public data catalogs, reduces database access pressure |
| `ROOT_KEY` | `Configured per enterprise intranet security rules` | Manages the platform root key, ensures access permission security for configurations and knowledge bases |

## Three Common Configuration Errors
- A `connection refused` error occurs after startup, and the database cannot be created. The cause is an incorrectly configured `MONGODB_URI`, the database pointed to by `PG_URL` has not been initialized, or the database has not opened access permissions for the corresponding port.
- Party building Q&A cannot return relevant content from public data open platforms. The cause is that the whitelist or proxy for intranet access to public data open platforms has not been configured, preventing the Q&A system from obtaining public data.
- Executing the `docker build -f ./projects/` command fails in a Windows 11 environment, with the prompt `no such file or directory`. The cause is an incorrect Dockerfile path being specified, or the project directory structure does not match the deployment script.

## How to Verify Successful Configuration
- Access the FastGPT v4.17.0 management backend, navigate to the database connection configuration page, run connection tests for `MONGODB_URI` and `PG_URL`, and confirm the test results pass.
- Import a standard public data resource catalog document, check that the imported knowledge base data items fully match the fields and content of the original document.
- Initiate a party building learning Q&A that includes public data queries, confirm that the returned results include correct desensitized data item descriptions and interface addresses.
- Trigger an incremental synchronization task, check that the updated public data catalog is normally synchronized to the knowledge base, and the update time matches the actual update cycle.

The values provided are common starting points and should be measured against the reader’s own samples.
