# Public Data Catalog and Opening: Party Building Learning Q&A - Sharing and Embedding

## What data in this category looks like
This category of data mainly comes from local public data opening platforms, integrated big data platforms, departmental business databases and electronic certificate libraries. It has a monthly update frequency. Daily maintained documents include public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documents and update frequency descriptions. Data fields include data item name, opening permission, desensitization status, call interface address, update cycle, etc. The scope of opening and authorization boundary must be clearly marked. This is structured public data assets.

## What constraints do these characteristics impose on the sharing and embedding workflow
The monthly update feature of this category of data requires that shared and embedded Q&A content regularly synchronize the latest catalog and interface information. This prevents inconsistencies between the catalog and actual data. Structured fields and clear authorization boundaries require strict matching of opening permissions during embedding configuration. This stops unauthorized calls to unopened data. Multi-source data assets require shared links to be associated with the corresponding department's data source configuration. This ensures the Q&A calls compliant interface documents and desensitized data. At the same time, the embedded interface must clearly display data item opening conditions and update cycles. This meets the public transparency requirements of party building learning.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Shared link validity period | `7 days` | Matches the monthly update frequency of this category, balances access convenience and data timeliness, and avoids expired links affecting party building learning Q&A usage |
| Embedding permission verification | According to the bound department authorization identifier | This category of data has clear opening permission boundaries. The embedding scenario must be restricted to only access compliant data items |
| Reference link display | Enabled and display the complete interface document address | This category of data includes interface documents and desensitization rules. Displaying reference links allows users to clarify data sources and compliance |
| User database identifier passing | Attach the `shareId` parameter to the embedded link | Different usage scenarios of data sources must be distinguished, to ensure that the public data catalog of the corresponding department is called |
| Call timeout setting | `10–15 seconds` | The response delay of public data interfaces is usually higher than that of general documents. An overly short timeout will cause Q&A failures |

## Three common mistakes
- Phenomenon: After embedding, the AI reply content cannot trigger local system jump, and the interface shows that the jump link is invalid. Cause: The jump callback address of the local system is not bound in the embedding configuration, causing the Q&A system to fail to receive jump instructions.
- Phenomenon: The reference interface document link is not displayed in the login-free shared link, only plain text replies are shown. Cause: The reference link rendering configuration is not enabled, or the correct interface document data source is not associated.
- Phenomenon: Inconsistent data appears when the embedded page calls data, and some data items are not updated. Cause: The shared link is not set for regular synchronization, or the configured data source is an old version of the public data catalog that has not synchronized the content after the monthly update.

## How to confirm the configuration is complete
- Open the generated shared link, check whether the expected user database identifier parameter is included, and confirm that the parameter transfer is normal.
- Initiate a party building learning query related to the public data catalog on the embedded page, and check whether the associated interface document reference link is displayed in the reply.
- Wait for at least 7 days, initiate the same query again, and confirm that the returned data items are consistent with the latest monthly updated catalog.
- Simulate an unauthorized access scenario, check whether access is blocked and unopened data items cannot be called.

The values given are common starting points and should be measured against the reader's own samples.
