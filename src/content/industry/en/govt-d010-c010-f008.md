# Party Building Learning Q&A for Highway Maintenance and Road Property Rights Management: Document Parsing and Chunking

This configuration is written for FastGPT v4.17.0.

## What this category's data looks like
Daily documents for this category include maintenance plans, patrol logs, disease disposal forms, road-related construction permits, road property damage compensation forms, and similar items. Data is sourced from highway maintenance management systems, bridge and tunnel monitoring systems, road patrol systems, and traffic flow monitoring data, with an update frequency of once per day. Most documents contain fields such as facility number, patrol period, disposal measures, permit items, and compensation details, and involve units including mileage, area, and time limit.

## What constraints do these characteristics impose on the document parsing and chunking link
High-frequency daily updates create demand for batch parsing, and scenarios with large differences in single-document length must be supported. Road-related construction permits and road property damage compensation forms have fixed-format fields, so associated information must be avoided being split during chunking. Disease descriptions in patrol logs are mostly unstructured text, so text segments of varying lengths must be supported. Documents from multiple systems have inconsistent formats, so the parsing link must be compatible with different layout structures and ensure that key fields are not lost.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the text length of patrol logs and disease disposal forms, avoid splitting key disposal steps |
| `chunkSplitter` | Prioritize by paragraph | Match the structure of daily documents which are mostly segmented records, preserve semantic integrity |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Adapt to the parsing duration of a single large maintenance plan document, avoid timeout interruptions |
| `customPdfParse` | Enabled | Compatibility with PDF document formats exported from multiple systems, ensure content extraction for non-standard layouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodate batch-imported monthly maintenance data documents, adapt to batch processing needs |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types, adapt to fixed-format documents such as road administration permits |

## Three common mistakes
- Phenomenon: After importing a Word-format patrol log, the knowledge base can recognize images, but the question and answer function cannot call the image content. Reason: The image parser is not configured to link to the chunking link. Only document text parsing is completed, and semantic information associated with the image is not extracted.
- Phenomenon: When configuring a document parsing task, the Playwright MCP service connection fails, while Amap MCP can be called normally. Reason: The access path and permissions for the Playwright MCP service are not configured on the platform, causing the parsing service to fail to start properly.
- Phenomenon: A manual copy prompt pops up when clicking to copy chunked content. Reason: The platform's cross-origin whitelist is not configured, triggering the browser's same-origin restriction, causing the automatic copy function to fail.

## How to confirm the configuration is complete
- Upload a single disease disposal form document, check the parsed chunked results, and confirm that key fields are not split.
- Import a batch of patrol logs, check the completion status of the parsing task, and confirm that no timeout errors occur.
- After configuring the image parser, import a road-related construction permit document containing images, and verify that the question and answer function can associate image content.
- Test copying chunked content, confirm that the automatic copy function triggers normally, and no manual copy prompt appears.
