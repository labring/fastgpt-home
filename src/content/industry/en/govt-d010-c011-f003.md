# Party Building Learning Q&A for Pension, Work Injury, and Unemployment Benefit Verification: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The core data for this category comes from social insurance handling systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. The update frequency is daily. Daily documents include structured benefit application forms, payment period certificates, and retirement approval forms, as well as unstructured work injury identification materials and unemployment benefit application materials. Fields cover personal social insurance enrollment information, payment records, qualification certification materials, and more. Corresponding parameters must be matched based on specific verification scenarios, and there are no unified fixed general units. The data structure mainly combines form fields and certification documents, and cross-system integration is required to complete the complete benefit verification process.

## Constraints Imposed by These Characteristics on the "Multi-turn Dialogue and Prompt Engineering" Link
Cross-system data sources require multi-turn dialogue to clearly distinguish fields from different data sources, avoiding confusion between different types of information such as payment periods and work injury identification results. The daily updated data feature requires limiting the effective scope of dialogue context to prevent expired enrollment or identification records from being included. The combination of structured and unstructured document types requires multi-turn dialogue to guide users to supplement missing certification material fields, while adapting to document parsing of different formats. In addition, the rigor of benefit verification requires verifying the field integrity of the current link in each dialogue, preventing verification errors caused by missing context.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum Context Window | First 10 turns of dialogue or 4000 characters | Matches the field verification requirements of multi-turn dialogue for this category, avoiding overly long contexts that confuse different batches of benefit verification data |
| `chatId` configuration | Bind the unique identifier of the current session | Ensures that multi-turn dialogue context is associated with the same user's benefit verification application, preventing session interference |
| Question Optimization Switch | Enabled, calibrated based on actual testing | Optimizes user questions for social security professional terminology, matching standard field names of social insurance systems |
| `variables` configuration | Bind variables for payment period, benefit type, and identification status | Accurately extract core fields required for verification in this category, reducing interference from invalid information |
| Number of Single Recalled Documents | Top 3 entries | Matches the core document types of this category, avoiding redundant non-essential materials that disrupt dialogue logic |
| `messages` parameter configuration | Only retain the output context of the last dialogue turn | Ensures the workflow only displays final verification-related replies, aligning with user viewing needs |

## Three Common Misconfigurations
- Phenomenon: All results from multiple AI dialogue nodes in the workflow are displayed. Cause: The context truncation rule for the `messages` parameter is not configured, and the requirement to only retain the output of the last dialogue turn is not enforced.
- Phenomenon: Returned content when connecting to external dialogue channels contains a large number of punctuation marks such as # and *. Cause: The format cleaning configuration for dialogue content is not enabled, and non-displayable Markdown syntax symbols are not filtered.
- Phenomenon: No referenced knowledge base information identifier is returned when calling the dialogue interface. Cause: The knowledge base source field bound to the `variables` parameter is not configured, and associated output of session logs is not set up.

## How to Confirm Successful Configuration
- Initiate a multi-turn dialogue containing multiple questions related to social security benefit verification, check that only the last AI-generated reply content is displayed.
- Connect to an external dialogue channel, verify that the returned dialogue content has no unnecessary punctuation marks such as # and *.
- Call the dialogue interface, check that the returned results include associated identifier information from the knowledge base source.
- Test the fields bound to the `variables` parameter, verify that core verification information such as payment period and benefit type can be accurately extracted during the dialogue.
