# Party Building Learning Q&A for Pension, Work Injury, and Unemployment Benefit Verification: Citation Sources and Traceability

## What this category of data looks like
Data for this category originates from social insurance handling systems, personal benefit records, labor relations and work injury verification systems, and the electronic social security card platform. The update frequency is daily.
Daily documents include benefit application forms, payment period certificates, retirement approval forms, work injury verification materials, and unemployment benefit application materials. Fields cover insured person identity information, payment periods, benefit calculation standards, qualification review criteria, and more. Units involve specific business dimensions such as payment months, benefit calculation base, and application amounts. The core content length of a single document mostly ranges between 800 and 1500 characters.

## Constraints on citation sources and traceability
This category has scattered data sources and frequent updates. The traceability process must accurately match the latest document fragments from corresponding systems. This stops the use of expired or incorrect handling data.
Daily documents have complex structures with multi-dimensional business fields. Traceability must link complete business context. This ensures cited content fully reflects the core logic of benefit verification.
Errors in this category directly affect public benefit payments and fund security. Traceability must specify exact document entries. This provides verifiable basis for policy implementation Q&A during party building learning.

## Three common mistakes
- A red numerical error appears in the interface, and the reply cannot associate knowledge base content. The cause is failure to correctly enable the `responseData` configuration, which prevents extraction of knowledge base document identifiers and metadata information.
- Traceability results only display scattered text fragments, with no complete document association information. The cause is failure to set `detail` to full mode, which only returns chunked text content without linking complete business fields from the original document.
- No traceability content is returned after associating the knowledge base. The cause is an excessively small `quoteMaxToken` configuration value, which fails to match valid chunked content from business documents in this category.
