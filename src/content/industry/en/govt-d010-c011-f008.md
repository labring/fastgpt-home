# Party Building Learning Q&A for Pension, Work Injury, and Unemployment Benefit Verification: Document Parsing and Chunking

## What data for this category looks like
Data for this category comes from social insurance management systems, personal benefit records, labor relations and work injury verification systems, and the electronic social security card platform. The update frequency is daily.
Commonly processed documents include benefit application forms, payment duration certificates, retirement approval forms, work injury verification materials, and unemployment benefit application materials. Most are structured forms or electronic scanned documents.
Fields cover payment duration, eligibility judgment items, benefit calculation parameters, and other related content. There is no fixed unified format. Some documents contain handwritten annotations or stamp areas.

## What constraints do these characteristics impose on the document parsing and chunking link
Diverse document structures and the presence of some scanned documents require the document parsing link to support high-precision OCR and structured extraction. This avoids splitting key eligibility judgment fields and associated content.
Daily high-frequency updated data requires chunking rules to support fast processing of incremental documents, while remaining compatible with format differences from different source exports.
Some documents have handwritten annotations or stamp areas. Parsing must retain text integrity for key areas, and prevent chunking from truncating core information related to benefit calculation.
Fields involve associated items such as payment duration and benefit parameters. Chunking must not split logical connections between fields, and ensure each chunk contains a complete business logic unit.

## Configuration settings
These settings apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of business logic units in this category of documents, avoids splitting associated fields such as payment duration and benefit standards |
| `chunkSplitter` | By paragraph + semantic boundary | Adapts to the text structure after parsing structured forms and scanned documents, retains business logic coherence |
| `customPdfParse` | Enable high-precision mode | Improves OCR recognition accuracy for stamped scanned documents common in this category |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers parsing time for large benefit approval materials, prevents parsing failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Compatible with the size limit for batch uploading multiple benefit application file sets |
| `chunkSettingMode` | Manual configuration | Adapts to format differences exported from different sources, allows flexible adjustment of chunking rules |

## Three common misconfigurations
- Phenomenon: OCR Error is displayed in the interface, and key stamp area text is missing from parsed documents. Cause: High-precision mode for `customPdfParse` is not enabled, so content such as stamps and handwritten annotations in scanned documents cannot be correctly recognized.
- Phenomenon: FastGPT reports file parsing timeout, and the parsing service log shows the parsing process has completed. Cause: The configured value of `PARSE_FILE_TIMEOUT_SECONDS` is less than the actual parsing time, and does not cover the processing duration of large work injury verification approval materials.
- Phenomenon: Some uploaded structured forms are split into multiple text chunks with no logical connection. Cause: `chunkSize` is configured only with a fixed character count, and chunking rules by semantic boundary are not enabled, splitting the field connections within the form.

## How to confirm correct configuration
- Upload a scanned copy of work injury verification material, verify whether the parsed result includes text from the stamp area to confirm the `customPdfParse` configuration is active.
- Upload a large benefit approval file set, verify whether the parsing time meets expectations to confirm the timeout configuration is reasonable.
- Extract chunked content, verify whether payment duration and corresponding benefit standards are located in the same text chunk to confirm the chunking rules retain business logical connections.
- Upload multiple documents exported from different sources, verify whether the parsing format is compatible to confirm the flexibility of the `chunkSettingMode` configuration meets requirements.

The values provided here are common starting points, and should be measured against the reader's own samples.
