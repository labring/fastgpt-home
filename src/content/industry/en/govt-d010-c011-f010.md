# Party Building Learning Q&A for Pension, Work-related Injury, and Unemployment Benefit Verification: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The typical users of this category are social security handling agencies, human resources and social security bureau business departments, and street social security service windows. Daily processed documents include benefit application forms, payment period certificates, retirement approval forms, work-related injury recognition materials, and unemployment insurance benefit application materials. Data sources cover social security handling systems, personal benefit record systems, labor relations and work-related injury recognition systems, and electronic social security card platforms. Data is updated daily. Documents include structured form fields and unstructured proof text, covering core content such as payment periods, benefit calculation rules, and eligibility determination conditions. There is no fixed uniform single document length.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Daily updated data means the retrieval system's knowledge base synchronization frequency must match the update rhythm, to avoid using expired benefit calculation rules or eligibility conditions. Documents from multiple sources must be stored classified by business scenarios. Retrieval scope must be strictly limited during retrieval to prevent mixing in content from other social security categories such as insurance registration. The mixed structured and unstructured document structure requires retrieval to balance semantic matching and precise keyword recall, ensuring that core fields such as payment periods and eligibility conditions are identified first. Errors in this category are directly linked to public benefits and the safety of social security funds. Retrieval and recall results must have high accuracy to avoid missing key proof materials or policy clauses.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Documents in this category involve eligibility determination and benefit calculation, requiring high semantic matching accuracy to filter low-relevance results |
| `limit` | Top 8 entries | This category requires association with multiple proof materials. Too many single recalls increase context pressure, while too few may miss key content |
| `searchMode` | Semantic + keyword hybrid retrieval | Balances keyword matching for structured fields and semantic understanding for unstructured text, covering different types of documents |
| `usingReRank` | Enabled | Further filters low-relevance results and prioritizes the ranking of core content such as payment periods and eligibility conditions |
| `datasetSearchUsingExtensionQuery` | Enabled | Covers implicitly associated expressions in user questions in party building learning scenarios, expanding retrieval coverage |
| `collectionIds` | Bind the knowledge base collection ID corresponding to the category | Limits the retrieval scope to avoid mixing in documents from other social security categories such as insurance registration |

## Three common mistakes
- Retrieval results include non-benefit verification documents. The cause is failure to limit the retrieval knowledge base collection via the `collectionIds` configuration, leading to cross-category recall of irrelevant content.
- A worker terminated due to reaching memory limit error occurs during retrieval. The cause is failure to limit `collectionIds` and using an overly high `limit` parameter value, loading an excessive number of documents beyond the instance memory threshold.
- No payment period-related content is matched in retrieval results. The cause is failure to enable `datasetSearchUsingExtensionQuery`, which cannot cover the implicit field association requirements in user questions.

## How to confirm the configuration is complete
- The knowledge base configuration page of FastGPT v4.17.0 is reviewed to confirm that the `collectionIds` parameter has been filled with the collection IDs of the corresponding benefit verification documents.
- A test question "What materials are required for unemployment benefit verification" is submitted, and the returned results are checked to confirm they only include category-specific documents such as unemployment insurance benefit application materials and payment period certificates.
- The ranking of retrieval results is reviewed to confirm that highly relevant content such as eligibility conditions and calculation rules appears first, verifying that the `usingReRank` and `similarity` configurations are active.
- The `limit` parameter is adjusted to Top 5 entries and Top 10 entries, the number of returned results is checked to confirm it meets expectations, and the parameter configuration is verified to be working properly.
