# Party Building Learning Q&A for Pension, Work Injury, and Unemployment Benefit Verification: Forms and Interactions

This configuration is based on FastGPT v4.17.0.

## What data for this category looks like
Data for this category originates from social insurance handling systems, personal benefit records, labor relations and work injury determination systems, and the electronic social security card platform. The update frequency is daily. Daily associated documents include benefit application forms, payment period certificates, retirement approval forms, work injury determination materials, and unemployment insurance benefit application materials. Data fields cover payment periods, benefit calculation parameters, qualification review conditions, and more. There is no unified fixed unit; matching measurement standards for the corresponding business scenario are required.

## What constraints these characteristics impose on the forms and interactions link
Multiple data sources and daily updates require form interactions to link to the latest business data in real time, to avoid calling outdated information. Diverse associated document types require forms to support combined entry of multiple fields, to match material submission requirements for different business scenarios. Qualification review and benefit calculation rely on accurate fields. The interaction link must strictly verify input formats, to prevent subsequent calculation deviations caused by missing fields or format errors. Additionally, the daily data update frequency requires periodic refreshing of the form interaction context cache, to ensure users obtain the latest policies and business rules when entering information.

## Three common mistakes
- Issue: When a default value reference variable is configured for the `formInput` node, the field is empty at runtime. Cause: The variable context from the social insurance handling system is not correctly bound, or the variable scope configuration is incorrect.
- Issue: In the no-login scenario, after voice input, the conversation interface is unresponsive or the long-press input duration always shows 00:00. Cause: The voice recognition interface has no reasonable timeout threshold configured, or there is an abnormality in the front-end rendering logic.
- Issue: After enabling input guidance and configuring the business lexicon, the conversation interface does not display the expected prompt content. Cause: The lexicon loading order is incorrect, or the input guidance trigger condition does not match the current business scenario.

## How to confirm the configuration is complete
- Manually enter test fields, verify whether the `formInput` node triggers format validation prompts, and confirm that the field rules match business requirements.
- Call the preset `userSelect` options, confirm that the conversation interface correctly displays classification options matching the current business scenario.

- Wait for the cache duration to expire, then call data again, confirm that the context cache has been refreshed, and the latest business data is obtained.
