# Party Building Learning Q&A for Internal Control Evaluation, Audit and Rectification: Document Parsing and Chunking

## What does the data for this category look like?
Data for this category comes from enterprise internal control systems, ERP, financial sharing systems, audit management systems, and procurement contract project systems. The update frequency is annual. Daily documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Most document structures include fields such as hierarchical titles, business entries, and associated supporting reference numbers. There is no unified fixed format, and there are slight differences depending on the export rules of the affiliated system.

## What constraints do these characteristics impose on the document parsing and chunking step?
Multiple data sources lead to heterogeneous document formats, so parsing needs to adapt to multiple formats including docx, pdf, excel, etc. Document types are diverse and focus on three core contents: issues, rectification, and supporting materials. When chunking, business context association must be retained to avoid separating individual rectification records from their corresponding supporting materials. Annual updated batch documents often have large individual file sizes, so parsing duration and upload limits need to be controlled. Most fields are non-standardized business descriptions, so over-chunking that causes semantic loss must be avoided.

## How to set the configurations?
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the length of single business entries in rectification ledgers and issue lists, avoid separating rectification requirements from their associated supporting materials |
| `chunkSplitter` | Grade by paragraph + title | Adapt to the hierarchical structure of audit working papers and internal control self-evaluation reports, retain document logical context |
| `customPdfParse` | Enabled | Supports replacing the default PDF parsing tool, adapts to audit notices and rectification closure certificates with many embedded images, retains the binding relationship between embedded images and text |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Address batch parsing needs for multiple documents in a single batch, avoid parsing timeout for large files |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapt to annual batch uploads of internal control self-evaluation reports and audit working paper collections |
| `chunkSettingMode` | Customize by document type | Adapt to structural differences across document formats, for example, chunk excel ledgers by table rows, chunk PDF reports by titles |

## Three common mistakes
- Phenomenon: After uploading a PDF-format audit notice, the parsing result cannot display embedded images, only plain text is retained. Cause: The `customPdfParse` configuration is not enabled. The default parsing logic only extracts plain text and does not retain the association between images and context.
- Phenomenon: When uploading an excel-format rectification ledger, a single complete rectification record is split into multiple independent chunks. Cause: The `chunkSize` setting value is lower than the actual character length of a single rectification record, causing logical association to be forcibly split.
- Phenomenon: When batch uploading annual internal control self-evaluation report collections, the parsing task returns a timeout error. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` setting value is lower than the actual duration required for parsing a single batch of documents, failing to adapt to the processing needs of large-volume batch documents.

## How to confirm the configuration is correct?
- Upload a single PDF of audit working papers that includes embedded images, and verify whether the parsing result retains the original document's title hierarchy and image-associated text.
- Upload an excel-format rectification ledger, and verify that the chunking result uses a single complete rectification record as the minimum unit.
- Upload an internal control self-evaluation report collection of around 100 MB, and check whether the parsing task completes within the preset duration without errors.
- Enter the knowledge base configuration panel of FastGPT v4.17.0, and confirm that target configuration items such as `customPdfParse` and `chunkSettingMode` have been enabled according to the preset values.
