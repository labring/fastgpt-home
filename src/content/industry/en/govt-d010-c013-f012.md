# Party Building Learning Q&A for Internal Control Evaluation, Audit and Rectification: Deployment and Upgrade

The following configuration and operation instructions apply to FastGPT v4.17.0.

## What data for this category looks like

Data for this category comes from enterprise internal control systems, ERP systems, financial sharing systems, audit management systems, and procurement contract project systems. Daily documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates.

Data update frequency is annual. Core processing steps include business sample and voucher extraction, formation of audit issues and rectification requirements, rectification evidence tracking and closure. Each document field is configured around enterprise internal audit process nodes. There are no unified universal fields. Field mapping must be completed according to the enterprise’s own audit standards.

## Constraints imposed by these characteristics during deployment and upgrade

Data sources are scattered and rely on existing enterprise internal systems. The deployment phase requires adapting to multi-system interface docking to avoid data synchronization conflicts. The annual update frequency means frequent incremental synchronization is not needed. Batch full update tasks can be configured.

Core processing steps rely on structured document fields. Deployment requires presetting field mapping rules to ensure key data such as audit issues and rectification ledgers can be accurately identified. Upgrades must retain original system docking logic to avoid interrupting archiving and calling of annual audit data. Rectification closure certificates and other supporting materials are mostly in attachment form. Deployment requires configuring corresponding file storage paths to ensure associated retrieval during searches.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://admin:pass@mongodb-host:27017/fastgpt_audit?authSource=admin` | Adapts to storage needs for structured annual audit data of this category, supports creating independent document collections by audit year, compatible with MongoDB 6 and MongoDB 7 versions |
| `REDIS_URL` | `redis://:redis-pass@redis-host:6379/0` | Caches frequently called audit issue lists and rectification ledger data, reduces system response latency, adapts to batch data processing scenarios |
| `STORAGE_S3_ENDPOINT` | Configured according to the enterprise’s internal object storage service address | Stores attachment files such as rectification closure certificates, adapts to the enterprise’s existing storage specifications, ensures attachments can be retrieved associatedly |
| `DB_MAX_LINK` | `10–15 connections` | This category processes a limited number of audit documents per single operation, avoids exhausting database connection pools, and ensures stable operation of batch import tasks |
| `FILE_TOKEN_KEY` | Set based on actual measurement | Generates access tokens for attachment files, ensures only authorized users can retrieve rectification supporting materials, complies with enterprise data security requirements |

## Three common errors

- Phenomenon: After starting the container, a database connection failure prompt or MongoDB version incompatibility error appears. Cause: The authentication source parameter in `MONGODB_URI` is not configured correctly, or compatibility with MongoDB 7 versions was not tested.
- Phenomenon: After Docker deployment, system plugins fail to load, and registration configuration files cannot be found. Cause: The local plugin directory was not mounted to the container’s `/app/packages/plugins` path, or the plugin initialization command was not executed.
- Phenomenon: After batch importing rectification ledger data, search results are empty or have very low matching accuracy. Cause: Correct field mapping rules were not configured, so core fields such as audit issues and rectification requirements were not correctly identified as search keywords.

## How to confirm configuration is successful

- Execute the built-in database connectivity test script to verify that `MONGODB_URI` and `REDIS_URL` configurations can connect normally.
- Upload a rectification closure certificate attachment, and verify that it can be retrieved and displayed normally through the file management module.
- Import a single audit working paper document, trigger a search test, and verify that matching audit issue keywords can be returned.
- Check the container mount directory, confirm that the plugin directory has been correctly mapped, and system plugin configurations can load normally.

The values provided here are common starting points and should be measured against the reader's own samples.
