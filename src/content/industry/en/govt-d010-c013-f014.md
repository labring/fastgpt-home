# Party Building Learning Q&A for Internal Control Evaluation, Audit and Rectification: Conversation Logs and Audit

## What the data for this category looks like
This category of data mainly comes from enterprise internal control systems, ERP, financial sharing systems, audit management systems, and procurement contract project systems. Daily processed documents include internal control self-evaluation reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification cancellation certificates. Data updates occur once per year. Data fields include audit issue number, rectification responsible entity, rectification completion status, supporting material path, and more. Most documents use standard official document formats, with units of characters, page numbers, and copies.

## What constraints these characteristics impose on the conversation logs and audit link
Data sources are scattered across multiple internal enterprise systems. Conversation logs must accurately distinguish call requests from different sources to avoid log confusion. Annual concentrated data updates result in large data volumes. Log storage must support batch archiving. Documents vary in type and are tied to audit process nodes. Logs must link to the unique identifier of the corresponding document for precise traceability. Audit rectification requires closed-loop tracking. Full records of upload and review for rectification supporting materials must be kept to ensure every operation is traceable. Audit issues may repeat. Logs must record associated historical audit results to enable subsequent cross-comparison.

This configuration rule applies to FastGPT v4.17.0.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Log storage period | 1825 days (5 years) | Adapts to the archiving requirements of annually updated audit data for this category, and conforms to enterprise file retention conventions |
| `chatId` association rule | Bind enterprise system code and audit process ID | Accurately distinguish conversation requests from different sources such as internal control systems and ERP to avoid log confusion |
| `detail` field configuration | Enable full recording | Retain call parameters, return results, and associated document information for each step in the audit process to meet traceability requirements |
| `responseChatItemId` association rule | Bind rectification ledger number | Ensure each log corresponds to a unique audit rectification link to facilitate closed-loop tracking |
| Concurrent call threshold | 1-2 calls per second | Adapts to the scale of daily processed documents for this category to avoid exceptions caused by excessive concurrency |
| Log alert configuration | Trigger when `responseChatItemId` is empty | Detect abnormal situations where call returns are missing in a timely manner |

## Three common configuration mistakes
- Phenomenon: Call requests from different sources cannot be distinguished in logs, and field contents are duplicated. Cause: `chatId` is not correctly bound to enterprise system identifiers, resulting in logs from different systems being unrecognizable.
- Phenomenon: `responseChatItemId` returns empty when concurrent call volume exceeds the threshold. Cause: No reasonable concurrent call limit is set, and excessive concurrency causes session identifiers to be lost.
- Phenomenon: After circularly concatenating rectification content, the concatenated text is not fully recorded in logs. Cause: Full recording of the `detail` field is not enabled, resulting in content from intermediate concatenation steps not being retained.

## How to confirm the configuration is complete
- View the log list to confirm that each log carries `chatId` and enterprise system identifiers, and logs from different sources can be manually filtered.
- Simulate concurrent calls to observe whether `responseChatItemId` is generated normally, and adjust the concurrent threshold to match actual business scale.
- Trigger abnormal call scenarios to confirm that the log alert function works properly, and notifications are sent promptly when the `detail` field is empty.
- Search for audit issue numbers to confirm that corresponding logs can be quickly located, verifying that the log index configuration takes effect.
