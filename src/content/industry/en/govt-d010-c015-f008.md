# Party Building Learning Q&A for Medical Insurance Fund Supervision and Audit: Document Parsing and Chunking

## What data for this category looks like
Core data for this category comes from medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and report clues. Daily processed documents include audit notices, inspection work drafts, suspicious point lists, interview records, handling decision documents, and rectification reports. These cover multiple formats such as official documents, inspection records, and table lists.
Data updates occur monthly. All audit matters handled in the current month must be covered. Single aggregated documents have a large scale, and contain multiple types of structured and semi-structured field information.

## What constraints do these characteristics impose on the "document parsing and chunking" link
The monthly updated data scale requires the parsing link to efficiently process batch documents. It also requires unified chunking rules across the same cycle.
Multi-format documents mean parsing tools must adapt to both paragraph-style official documents and table-style lists. This avoids losing key information during splitting.
Core documents such as suspicious point lists and interview records carry violation clues. Chunking must accurately correspond to single suspicious points or single inspection records. This prevents mixed content across segments that hinders subsequent clue retrieval.
Documents exported from large-value settlement data take a long time to parse. Sufficient processing time must be reserved.

## How to set the configuration
This document adapts to the document parsing and chunking functions of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single inspection items or violation suspicious points in audit-related documents, avoiding splitting key clues across chunks |
| `chunkSplitter` | Split by paragraph + table row | Daily documents include both paragraph-style official documents and table-style lists. This setting adapts to the splitting logic for both formats |
| `customPdfParse` | Enabled | PDF documents such as handling decision documents and interview records require retention of original formatting. This prevents content misalignment that would hinder retrieval |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large monthly aggregated documents take a long time to parse. This setting reserves sufficient timeout time to avoid parsing interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploading of monthly audit aggregated documents, adapting to the data scale of this category |
| `chunkSettingMode` | Custom rules | Allows setting differentiated chunking for different document types. For example, split suspicious point lists by single suspicious point |

## Three common mistakes
- Uploading an Excel-format suspicious point list fails to return search results. The cause is that the table parsing mode is not enabled. The default split only by text paragraphs causes table content to be filtered out.
- An analysis timeout error appears after uploading a file. The cause is that `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to 600 seconds. The parsing time of large-value settlement data files exceeds the default threshold.
- After enabling `customPdfParse`, the corresponding parsing switch is not turned on in the knowledge base settings page. This causes parsing failure of PDF-format handling decision documents, and the interface displays abnormal parsing status.

## How to confirm the configuration is complete
- Upload a single audit notice PDF, view the parsed chunk list, confirm that the length of each chunk falls within the 800–1200 character range.
- Upload an Excel file of the suspicious point list, check whether the parsed chunks are split by single suspicious point entries, with no mixed content across entries.
- Enter the search test page of the knowledge base, enter the keyword "violation fee identification", confirm that the chunked content of the corresponding inspection work draft can be retrieved.
- Upload a monthly aggregated document within 1000 MB, wait for the parsing to complete, confirm that the status is successful with no timeout errors.
