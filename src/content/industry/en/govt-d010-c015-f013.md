# Party Building Learning Q&A for Medical Insurance Fund Supervision and Audit: Sharing and Embedding

## What the data for this category looks like
The data sources for this category include medical insurance intelligent monitoring systems, fund supervision rule bases, medical insurance settlement data, drug and consumable traceability codes, and report clues. The update frequency is monthly. Daily produced documents include audit notices, inspection work drafts, suspicious item lists, interview records, handling decisions, and rectification reports. Fields include violation types, involved matters, rectification requirements, handling agency information, and others. The content length of individual documents varies widely, and some audit records include multiple pages of paper or electronic attachments.

## What constraints these characteristics bring to the "sharing and embedding" workflow
Monthly updated data must be regularly synchronized to the knowledge base. Sharing and embedding scenarios must ensure that the latest supervision rules and settlement data are retrieved when accessed, to avoid using expired content. In scenarios with mixed document types, embedded Q&A must accurately match the field logic of audit-related documents to prevent confusion between settlement data and rectification report content. For audit records with multiple-page attachments, the context length of embedded Q&A must be limited to avoid loading timeouts or redundant content. At the same time, sharing targeted at medical insurance supervision personnel must adapt to the permission requirements of different entities. Embedding scenarios must support directional access control to ensure that sensitive data is only visible to authorized personnel. Incorrect sharing configurations may lead to sensitive data leaks, triggering risks such as fund losses, recovery of overpayments, protocol suspension, or administrative penalties.

## How to set the configurations
This page applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Share link validity period | `7–30 days` | Matches the monthly data update frequency, ensuring links remain valid during the data refresh cycle |
| Login-free access control | Only internal specified IP ranges | Adapts to the sensitivity of medical insurance data, restricting unauthorized access |
| Embedded Q&A context limit | `800–1200 characters` | Matches the single-paragraph content length of audit documents, avoiding loading redundant information |
| `shareId` binding scope | Bind to specified application knowledge base | Ensures shared Q&A only links to medical insurance supervision-specific documents and data sources |
| Sharing language configuration | Chinese | Adapts to the usage habits of target users, avoiding adaptation issues with the default English setting |
| Login-free link quantity limit | Set based on actual testing (team edition can be adjusted to 100) | Adapts to the sharing needs of daily team use, avoiding the hassle of frequently creating links |

## Three common configuration mistakes
- Symptom: Login-free sharing links in the workspace disappear after restarting the Docker container. Cause: Persistent storage for sharing link configurations is not enabled, so locally cached link data is lost when the container restarts.
- Symptom: A prompt appears stating the 10-link limit has been reached when creating a login-free sharing link. Cause: The default link quantity limit for the team edition has not been adjusted, with the default limit set to 10.
- Symptom: The embedded Q&A page displays the English interface by default. Cause: The sharing language was not specified as Chinese in the configuration, so the system's default English setting was used.

- Attempt to create multiple login-free sharing links, confirm the quantity limit matches the expected configuration.
- Embed the link into an internal test page, verify that the Q&A can retrieve medical insurance supervision-related documents and data.
