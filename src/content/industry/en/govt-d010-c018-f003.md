# Party Building Learning Q&A for Social Insurance Registration and Premium Verification: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
The data for this category comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. It is updated daily. Daily documents include social insurance registration forms, payment base declaration forms, staff change forms, social insurance premium verification forms, and personal benefit records. Fields include personnel identity identifiers, insured unit information, premium verification base, collection status, and more. Units include number of people, yuan, monthly premium amount, and more. The data structure is mainly structured forms with no complex nested content.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Cross-system data sources require multi-turn dialogue to coherently link insured units, personnel information, and different stages of premium verification. Context length must adapt to multi-step queries. The daily data update feature requires prompts to call the latest system data, avoiding expired information. Structured daily documents require prompts to accurately extract key fields from forms, preventing omission of core information. The risk of errors affecting personal benefit applications requires that the verification link in multi-turn dialogue clearly checks key fields, avoiding generation of incorrect verification suggestions.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Split variables by insured unit unified social credit code, personnel ID number, and payment cycle; values are synchronized from social insurance handling system APIs | Adapt to cross-system data association and ensure accurate variable transfer during multi-turn dialogue |
| `messages` | Retain the first 15 rounds of dialogue context, filter non-business prompt information | Multi-turn queries for social insurance registration and premium verification typically do not exceed 10 rounds; retaining sufficient context avoids interruptions |
| `chatId` | Bind the insured unit's unified social credit code as the session identifier | Ensure that multi-turn dialogue contexts for the same unit are not confused, aligning with human resources and social security department unit management logic |
| Temperature | 0.1–0.3 | Social insurance registration and premium verification require precision and compliance; low temperature ensures answer consistency and avoids generating uncertain content |
| Maximum Context Length | 8000–12000 characters | Adapt to the context length of multi-step queries and avoid exceeding model processing limits |

## Three Common Misconfigurations
- Symptom: After configuring variable references, the temperature setting button disappears, and the dialogue temperature cannot be adjusted. Cause: The parameter exposure switch was not enabled in the variable reference context configuration, causing the temperature configuration item to be hidden.
- Symptom: Multi-turn dialogue-generated Markdown content has no line breaks, and the copy button prompts that copying is not possible. Cause: The Markdown format rendering switch for dialogue content was not enabled, causing line breaks to be filtered, and the copy function was not bound to the correct DOM node.
- Symptom: After calling a workflow to obtain social insurance verification data, the running data in the dialogue log is empty. Cause: The workflow's output fields were not mapped to variables in the dialogue context, causing data to not be correctly passed to the log module.

## How to Verify Successful Configuration
- Initiate a multi-turn query that includes insured unit and personnel information, check whether variables in the dialogue correctly associate with the latest data from the corresponding system.
- After configuring variable references, check whether the temperature setting button remains on the interface, attempt to adjust the temperature value and verify changes in the consistency of dialogue responses.
- Generate a test Markdown-formatted response, click the copy button, and check whether the content contains correct line breaks.
- Call a workflow to obtain simulated social insurance verification data, check whether the corresponding running data fields are displayed in the dialogue log.
