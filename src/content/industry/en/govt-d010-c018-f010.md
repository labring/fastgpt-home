# Party Building Learning Q&A for Insurance Registration and Payment Verification: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
Data comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and public security and civil affairs shared data. The update frequency is daily. Daily documents include insurance registration forms, payment base declaration forms, personnel adjustment forms, social insurance premium verification forms, and personal benefit records. Most document fields involve personal identity identifiers, unit unified social credit codes, payment bases, and verified amounts. Some documents use structured form formats, while others use semi-structured business report formats. There is no unified fixed layout.

## Constraints on Knowledge Base Retrieval and Recall
This category of data spans multiple business systems and requires association with shared data sources. Knowledge base retrieval must support joint recall of multiple datasets to avoid business logic breaks caused by data isolation. Data updates daily, so recall processes must be configured with incremental synchronization trigger rules to ensure retrieval result timeliness. Daily documents use both structured form and semi-structured business report formats. Retrieval and recall processes must adapt to different fragment extraction and matching logic types. The data includes sensitive information such as personal identities and payment amounts. Recall results must strictly match permission scopes. Since errors directly affect insurance benefits, accuracy screening standards for recall results must be improved.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | This category of data involves sensitive and high-impact fields. Low-match results need to be filtered. This range balances recall volume and accuracy |
| `limit` | `Top 8 entries` | Too many single-batch recall results increase context pressure. Too few fail to cover complete business scenarios. 8 entries is a reasonable range adapted to business data volume |
| `searchMode` | `Hybrid retrieval` | Daily documents include structured forms and semi-structured reports. Hybrid retrieval matches both keywords and semantic features |
| `usingReRank` | `Enabled` | This category of data has strong field relevance. Re-ranking further filters irrelevant results and improves business relevance of returned fragments |
| `datasetSearchUsingExtensionQuery` | `Enabled` | In the party building learning Q&A scenario, business terms need to be associated with party building-related expressions. Extended queries cover cross-scenario matching needs |
| `collectionIds` | `Bind specified collections by business domain` | Isolate insurance payment and party building learning datasets. Only recall document fragments from the corresponding business domain to ensure data security |

## Three Common Configuration Mistakes
- Retrieval results cannot be linked to the original file's online preview. Phenomenon: Clicking a fragment shows no jump or displays "file does not exist". Cause: No external link mapping rule for knowledge base documents is configured, or the accessible path of the original file was not retained during import.
- Valid text fragments are not extracted after uploading a PDF document. Phenomenon: Retrieval results have no corresponding content or only return blank fragments. Cause: The pdf-marker plugin and FastGPT are not properly associated, or the plugin deployment path is not mapped within the container.
- Slow loading of the agent editing page. Phenomenon: The interface becomes unresponsive or loads for a long time after entering the editing page. Cause: The bound dataset contains oversized files that have not been split, or the `limit` value is too high, causing context overload after retrieval and triggering front-end rendering blocking.

## How to Verify Successful Configuration
- Log in to the FastGPT v4.17.0 backend, enter the settings page of the corresponding knowledge base, and confirm that the incremental synchronization switch is enabled.
- Enter a test question that combines party building learning and insurance payment, and check whether the fragment source of the retrieval results is the specified business collection.
- Check the retrieval log to confirm that the number of returned results matches the configured `limit` value.
- Try uploading a semi-structured personnel adjustment form, and confirm that the retrieval result can extract personal identity and change information.

The values provided are common starting points and should be evaluated against the reader's own samples.
