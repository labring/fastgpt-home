# Party Building Learning Q&A for Double Random, One Public Regulatory Inspections: Sharing and Embedding

## What this category of data looks like
This category of data primarily comes from the Double Random, One Public regulatory platform, enterprise credit information publicity system, industry regulatory systems, and law enforcement officer directory. Updates occur monthly. Daily generated documents include inspection plans, inspection target lists, inspection item lists, on-site inspection records, rectification notices, and inspection result public notices. Most data fields include the unified social credit code of regulatory targets, law enforcement officer numbers, inspection ratios, and inspection item entries. The content of a single document ranges from several inspection items to dozens of regulatory target information entries.

## What constraints these characteristics impose on the sharing and embedding link
This monthly updated dataset for this category includes multiple types of structured regulatory documents. Some content involves privacy information of regulatory targets. Three constraints must be met during sharing and embedding.
First, configure a regular synchronization mechanism. This ensures the party building learning Q&A content on the embedded page stays consistent with the latest inspection plans and inspection result public notices.
Second, limit the context call scope of the embedded window. This avoids page loading timeouts caused by loading excessive regulatory target information.
Third, connect to the internal identity authentication system. This prevents unauthorized access to confidential regulatory data.

The following configurations are based on FastGPT v4.17.0.
## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Share link authentication | Enable internal account authentication | This category of data contains privacy information of regulatory targets, so unauthorized access must be restricted |
| `shareId` bound knowledge base | Bind the exclusive regulatory party building knowledge base | Ensure that Q&A content only associates with exclusive documents of this category, such as inspection plans and inspection results |
| Embedded window timeout duration | 600 seconds | Single documents for this category have relatively large content, so sufficient loading time must be reserved |
| Context recall count | Top 8 entries | Balance Q&A accuracy and page loading performance, avoiding resource occupation from excessive data |
| Synchronization frequency | 1 time per month | Match the monthly update rhythm of data for this category |
| Share link validity period | 30 days | Prevent inconsistencies between the data and latest regulatory content caused by long-term valid links |

## Three common errors
- The embedded page opens a new chat window after refreshing, and cannot retain the original session. This happens when the session persistence parameter bound to `shareId` is not configured, which generates a new session each time the page loads.
- The share link does not have authentication enabled. External users can view confidential regulatory data. This occurs when internal account authentication is not enabled, and public access permission is directly activated.
- The embedded page times out while loading and shows empty results. This happens when the timeout duration is not adjusted. The large volume of documents for this category causes loading time to exceed the default threshold.

## How to confirm configurations are set correctly
- Open the embedded page, refresh it, and confirm the session is not reset and previous conversation content is retained.
- Use an unauthorized account to access the embedded page. Confirm that regulatory Q&A content cannot be viewed.
- Wait for one monthly synchronization cycle to end. Confirm the content displayed on the embedded page matches the latest regulatory data.
- Check the embedded page’s loading status. Confirm no timeout errors appear.
