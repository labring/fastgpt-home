# Party Building Learning Q&A for Territorial Spatial Planning Compilation and Implementation Evaluation: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category is primarily sourced from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics, and remote sensing images. Updates occur once per year. Daily documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Documents contain fields such as spatial coordinates, constraint indicators, planning time limits, and implementation progress. Common units are square kilometers, percentage, and year. The length of individual documents varies widely.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
The data for this category has a low update frequency, wide variation in document length, and includes multi-source spatial fields. These factors create multiple constraints for multi-turn dialogue and prompt engineering configurations.
First, the annual update feature requires prompts to be fixed based on the current annual planning baseline to avoid introducing outdated data.
Second, mixed calls of multi-source documents require prompts to clearly mark data source types to prevent confusion of constraint indicators from different planning documents.
Third, the expression of special fields such as spatial coordinates requires multi-turn dialogue context to retain field units and definitions to avoid ambiguity.
Fourth, individual documents have large length, so the content scale recalled per single dialogue turn must be limited to prevent context overflow.

## How to set the configurations
This configuration is based on FastGPT v4.17.0. Specific configuration items and their rationales are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` binding | Bind planning year and project ID | Adapt to the annual update data feature and fix the dialogue baseline |
| `messages` truncation | Retain the last 10 dialogue messages | Avoid context overflow caused by overly long message queues |
| Maximum context length | 8000–12000 characters | Adapt to the wide variation in individual document length for this category |
| Single recall limit | Top 3 entries | Match the recall priority of multi-source documents and reduce interference from irrelevant content |
| Question optimization switch | Enabled | Optimize questions for unstructured content such as public opinion summaries |
| `chatId` filtering | Associate with the current planning project identifier | Accurately retrieve dialogue history for the corresponding project |

## Three common configuration mistakes
- Phenomenon: Only one prompt configuration is triggered per single dialogue turn, and preset rules are not applied in subsequent turns. Cause: Dialogue context is not bound via `chatId`, causing prompt parameters to reset with each request.
- Phenomenon: Dialogue automatically introduces non-planning knowledge base content and returns irrelevant general Q&A results. Cause: The prompt does not clearly limit the data source to territorial spatial planning-related documents, or the global default knowledge base association is not disabled.
- Phenomenon: Dialogue times out or returns empty results. Cause: The number of recalled documents per single turn or context length is not limited, causing excessive content loading to exceed system processing limits.

## How to confirm the configuration is correct
- Manually initiate a test dialogue, enter a question that includes planning time limits, and verify that the returned results are fixed based on the current year.
- Switch to a different `chatId` to initiate a dialogue, and verify that dialogue contexts for different projects are independent and no content confusion occurs.
- Submit a question that includes spatial coordinates, and verify that the returned results retain field units and definitions with no ambiguity.
- Trigger multi-turn dialogue, and verify that each round of replies continues the planning project context from the previous round with no context loss.
