# Party Building Study Q&A for Land Spatial Planning Compilation and Implementation Evaluation: Sharing and Embedding

## What data looks like for this category
Data for this category typically comes from the national land spatial basic information platform, natural resource survey and monitoring data, population and economic statistics, and remote sensing imagery. It is updated once per year.
Daily documents include overall land spatial plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries.
Most documents contain fields such as spatial coordinates, construction land scale, and ecological protection red line scope. Some documents include attached geospatial layers.
Data volumes are typically large. A single planning report can cover tens of thousands of words and multiple spatial layers.

## What constraints these characteristics impose on the sharing and embedding workflow
Fixed annual update frequency requires that shared or embedded links point to the latest released planning data that matches the current knowledge base version.
Multi-source spatial data and large-volume documents increase resource usage when embedded pages load. The context data loaded per page must be limited to avoid performance issues.
The party building study Q&A scenario requires data to be shared only within authorized scope. The embedding workflow must distinguish access permissions between internal staff and external supervisors.
Documents contain spatial fields. Embedded Q&A must accurately associate spatial information with policy text. Shared links must retain the spatial association attributes of data to prevent information misalignment.

| Authentication configuration | Assign access permissions by role | Differentiates Q&A permissions between planning compilers and supervisors, adapts to the hierarchical access requirements of party building study scenarios |

## Three common configuration errors
- Symptom: Embedded page redirects to a new chat window after refresh, and cannot retain the previous conversation position. Cause: Session persistence configuration is not enabled, or `shareId` is not bound to a fixed session identifier.
- Symptom: Shared links open without identity verification to access planning data. Cause: Authentication rules are not configured, or access scope is not limited to internal department network segments.
- Symptom: Embedded page Q&A results do not include spatial planning-related field information. Cause: Embedded configuration context length is set too small, failing to load document paragraphs containing spatial coordinates or planning indicators, or the bound knowledge base version is outdated.

## How to verify successful configuration
- Open the embedded page, initiate a Q&A, then refresh the page. Check if the chat session position and content are retained to confirm session persistence configuration is active.
- Use a device from an unauthorized network segment to access the embedded link. Check if the page fails to load or a permission verification prompt appears to confirm authentication configuration is active.
- Submit a query containing category-specific keywords such as "ecological protection red line" or "construction land scale". Check if the returned results include content from this category’s documents to confirm the knowledge base is bound correctly.
- Wait for the embedded page to finish loading, check if a load timeout prompt appears to confirm the timeout period configuration adapts to the current data volume.
