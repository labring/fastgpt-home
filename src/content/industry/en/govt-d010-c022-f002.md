# Party Building Learning Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Vector Models and Indexes

## What the Data for This Category Looks Like
Data for this category typically comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned assets supervision systems. The update frequency is daily. Daily documents include transfer announcements, trading notices, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer specifications, and more. Most data fields relate to trading target ownership, restriction conditions, margin rules, transaction processes, and similar details. Some documents contain both structured target parameters and unstructured rule descriptions.

## What Constraints Do These Characteristics Impose on the Vector Models and Indexes Link
Daily updated data requires indexes to support high-frequency incremental refreshes, avoiding performance losses from full reconstruction. Documents mixing structured parameters and unstructured rules require vector models to adapt to encoding consistency for both short fields and long texts. Differences in document formats across multiple sources require the indexing process to include unified text cleaning logic, ensuring content exported from different systems has a consistent format before vectorization. The length of a single vectorized segment must not exceed the `maxToken` limit to avoid encoding failures. Content related to ownership is the core query scenario, so indexes must prioritize retaining the vector weight of such segments, preventing non-core content from interfering with retrieval results.

## Three Common Misconfigurations
- Phenomenon: After importing documents, the exported knowledge base file only contains the `index` field and no `content` field. Cause: The content storage configuration after text chunking was not enabled correctly, resulting in only vector index metadata being retained and original text segments being lost.
- Phenomenon: Timeout errors occur when calling vector models in an intranet deployment environment. Cause: The intranet-accessible vector model service address was not configured, or request parameters for the intranet environment were not adapted.
- Phenomenon: When default chunking parameters are used, long transaction announcements are over-chunked, causing ownership-related information to be split across multiple segments. Cause: The default chunking parameters do not adapt to the content structure of long documents in this category, and reasonable chunk length and overlap ratios were not set.
