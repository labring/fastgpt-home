# Party Building Learning Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data for this category typically comes from national public resource trading platforms, natural resource trading systems, property right exchange systems and state-owned assets supervision systems, with a daily update frequency. Daily documents include transfer announcements, trading instructions, bid application documents, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications. Core fields involve transaction subject ownership, restriction conditions, margin amount, transaction confirmation information and similar content. Document structure changes dynamically with trading stages, and clear differences exist in document fields across different stages.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
Daily updated trading documents require multi-turn dialogue to real-time associate newly released announcements and results, avoiding use of expired information. The differentiated structure of multiple types of trading documents requires prompt engineering to accurately identify different document scenarios and extract core information in a targeted manner. The accuracy of ownership, transaction confirmation and other content directly affects trading results, requiring multi-turn dialogue to retain complete context to ensure each round of queries is based on previously confirmed subject information. At the same time, fields in trading documents are highly professional, requiring prompt engineering to limit retrieval scope and avoid redundant information interfering with core judgments.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier per session | Distinguish multi-turn dialogue contexts to avoid cross-session trading data confusion |
| `messages` | Retain the first 15–20 rounds of dialogue content | Cover multi-round trading query scenarios including bid application, ownership verification, and transaction confirmation |
| `variables` | Bind trading subject number, announcement release date | Accurately match trading documents of this category and narrow retrieval scope |
| Maximum context length | 8000–12000 characters | Accommodate complete information from multi-turn dialogues and multiple trading documents |
| Single return match limit | Top 3 documents | Focus on core query content such as ownership, margin, and transaction confirmation to avoid information overload |

## Three Common Misconfigurations
- Symptom: A 503 error is prompted when uploading documents on the dialogue page, but backend logs show the file upload was successful. Cause: The context refresh logic for `messages` is not configured correctly, causing session cache usage to exceed service thresholds and triggering current limiting mechanisms.
- Symptom: Newly released listing result announcements from the current day cannot be associated in multi-turn dialogue. Cause: The announcement release date variable in `variables` is not bound, causing the retrieval scope to cover expired historical trading documents.
- Symptom: Prompt engineering-generated responses omit ownership restriction conditions for trading subjects. Cause: Session contexts are not isolated via `chatId`, causing irrelevant cross-session trading data to interfere with the current query.

## How to Confirm Proper Configuration
- Initiate a first-round query that includes a specific trading subject number, and verify whether the returned results match the transfer announcement or trading instruction documents for this category.
- Initiate consecutive multi-round queries, verify whether `chatId` remains consistent, and whether each round of replies is based on previously confirmed subject information.
- Upload trading documents updated on the current day, and verify that the dialogue can correctly associate the latest listing results or transaction confirmation information.
- Test uploading different types of trading documents, and verify whether the returned results focus on core fields of this category such as ownership and margin.
