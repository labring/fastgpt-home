# Party Building Learning Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Citation Sources and Traceability

## What Data for This Category Looks Like
Core data for this category originates from the national public resource trading platform, natural resource trading systems, state-owned asset supervision systems, and property right exchange systems. Updates occur daily.

Daily documents include transfer announcements, trading guidelines, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, property right transfer descriptions, and similar items. Individual document lengths vary widely. Some listing announcements can reach several thousand characters.

Data fields include trading object ownership information, margin amount, trading time, bidding rules, transaction confirmation clauses, and additional relevant fields. There are no unified fixed units. Adjustments must be made based on specific trading objects.

## What Constraints Do These Characteristics Impose on the Citation Sources and Traceability Workflow
The daily update nature of category data requires the citation traceability function to support real-time synchronization of knowledge base content. This prevents cited content from mismatching the latest trading information.

The structure of long documents and multiple fields requires precise matching of specific trading clauses during chunking and retrieval. This prevents traceability content from deviating from core trading information.

The strict nature of trading documents requires traceability links to point to original public documents. Cited fragments must fully correspond to original text clauses. This avoids misunderstandings of key information such as ownership and bidding rules caused by truncation or misalignment.

## Configuration Guidelines
This page provides configuration instructions based on FastGPT v4.17.0. Specific configuration items and recommendations are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the typical paragraph length of category documents, avoids including too many unrelated trading clauses in a single chunk |
| `quoteMaxToken` | 1500–2000 tokens | Covers the length of core trading clauses in a single category document, ensures cited fragments are complete |
| `responseData` | Enabled | Requires the API to return full response data including citation details |
| `detail` | Enabled | Displays detailed content of the original document corresponding to the cited fragment |
| Overlap Length | 100–150 characters | Prevents chunk truncation of key information at the start and end of trading clauses, ensures traceability content is coherent |
| Single Search Limit | Top 5 entries | Matches the number of associated information for category trading objects, avoids retrieving irrelevant redundant content |

## Three Common Configuration Errors
- Citation sources do not appear in terminal replies. This occurs because the `responseData` related configuration is not enabled, causing the API to not return citation fields.
- Cited fragments are incomplete, only showing partial trading clauses. This occurs because the token count set for `quoteMaxToken` is insufficient to cover the full target clause content.
- Traceability links fail to open the corresponding original document. This occurs because the public access address of the document is not correctly associated, or the configured link does not match the actual document storage path.

## How to Verify Successful Configuration
- Call the Q&A API, check if the returned results include the `detail` field and citation source information.
- Input a test question about the category's trading guidelines, verify if the returned cited fragments correspond to specific clauses in the document.
- Click the traceability link in the reply, confirm it can open the original public document for the corresponding category.
- Manually update a trading document in the knowledge base, initiate the Q&A again, confirm the cited content is synchronized to the latest version.
