# Party Building Learning Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Deployment and Upgrade

## What this category of data looks like
Data typically comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with a daily update cycle. Daily documents include transfer announcements, trading notices, bid application materials, margin vouchers, transaction confirmation documents, listing result announcements, and property right transfer specifications. Most documents contain fields such as ownership information, target parameters, and trading process descriptions, and some documents include amount and time limit units.

## What constraints these characteristics impose on deployment and upgrade
This page applies to the deployment and upgrade workflow of FastGPT v4.17.0. Daily updated data sources require scheduled synchronization tasks to avoid data lag affecting the timeliness of party building Q&A. The large differences in document structures across categories require adapted chunking and parsing rules. Sensitive fields such as ownership information and amounts require adjusted permission configurations to ensure data security. When parsing batch documents, the total volume per batch is large, so concurrency and storage configurations need to be adjusted to avoid resource exhaustion. Additionally, during the upgrade process, the original data source connection configurations must be retained to prevent data synchronization interruptions.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15 connections` | Adapt to concurrent database access during bulk parsing of multiple types of trading documents to avoid connection pool exhaustion |
| `ROOT_KEY` | `strong random string of 32–64 characters` | Used for configuring system highest permission verification to ensure management security after deployment |
| `STORAGE_S3_ENDPOINT` | `Connect to internal public resource transaction storage gateway` | Adapt to the storage path and permission requirements of category documents to ensure compliant document reading |
| `MONGODB_URI` | `Independent business database instance address` | Separate party building Q&A data from core data of trading systems to ensure data security isolation |
| `REDIS_URL` | `Local Redis instance address on port 6379` | Used for caching sessions and parsing progress to support status tracking for bulk document parsing |
| `FILE_TOKEN_KEY` | `Generate exclusive key based on internal document authentication rules` | Used to access permission-controlled trading documents to prevent unauthorized access |

## Three common mistakes
- Issue: Parsing interruptions occur when bulk uploading trading documents, and parsing progress cannot be restored after restarting the Docker container. Cause: Persistent storage for `REDIS_URL` is not configured, resulting in loss of sessions and parsing progress, making task resumption impossible.
- Issue: Trading document content cannot be retrieved after enabling the party building Q&A function. Cause: `STORAGE_S3_ENDPOINT` or `FILE_TOKEN_KEY` is not configured correctly, and the internal document authentication and storage rules are not adapted.
- Issue: Data source synchronization for party building Q&A fails after upgrading the version. Cause: The original `MONGODB_URI` and data synchronization script configurations are not retained, resulting in data source connection interruption.

## How to confirm configurations are correct
- Perform bulk upload of multiple standard documents of this category, check that parsing progress updates normally and no interruption-related errors occur.
- Test queries for questions related to ownership and trading processes, confirm that returned content matches the actual fields of category documents.
- Check database connection monitoring, confirm that the number of connections does not exceed the configured `DB_MAX_LINK` limit.
- Verify the highest permission key verification logic, confirm that only authorized users can access the system management module.

The values provided are common starting points and should be measured against the reader's own samples.
