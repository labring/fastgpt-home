# Party Building Learning Q&A for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Sharing and Embedding

## What data for this category looks like
The data for this category typically comes from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. The update frequency is daily. Daily documents include transfer announcements, trading notices, bid application materials, margin vouchers, transaction confirmation documents, listing result announcements, and property right transfer specifications. Common data fields include transaction object ownership number, object type, listing price, margin amount, bid qualification requirements, etc. Units include square meters, units, ten thousand yuan, and others.

## What constraints do these characteristics impose on the "Sharing and Embedding" link
The data sources for this category are scattered and updated daily. This requires the shared knowledge base to match the update rhythm of the corresponding systems to avoid lagging Q&A content. Transaction-related documents involve sensitive information such as ownership and funds. Embedding scenarios need strict configuration of identity authentication rules to prevent unauthorized access. Individual documents have long content and professional fields. Embedded Q&A components need to limit the context length to avoid loading timeouts or content overflow. Additionally, party building learning Q&A needs to be linked to the compliance requirements of transaction scenarios, and shared links need to be bound to the access permissions of corresponding institutions.

## How to set up configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `shareId` | Bind the exclusive `shareId` of the corresponding category knowledge base | Ensure shared Q&A only links to transaction and party building documents of this category, avoiding confusion across knowledge bases |
| Sharing authentication method | Enable organization-level authentication and bind institutional account systems | Transaction data involves state-owned assets, so access permissions must be strictly controlled to prevent unauthorized access to sensitive information |
| Embedded component context length | 800–1200 characters | Individual transaction documents have long content. Limiting context length avoids loading timeouts while ensuring Q&A links to valid data |
| Knowledge base synchronization cycle | Automatic synchronization every day in the early morning | The category data is updated daily. Matching the synchronization cycle to the data update rhythm ensures the timeliness of Q&A content |
| Mobile adaptation configuration | Enable responsive layout | Adapt to mobile office scenarios and ensure interactive experience across different devices |

## Three common misconfigurations
- The symptom is that the identity authentication option does not appear on the sharing configuration page. The cause is that the sharing permission module was not enabled in the advanced settings of the corresponding knowledge base.
- The symptom is that after an iframe is embedded, the user's session automatically logs out after logging into the FastGPT backend. The cause is that the session domain of the embedded page and the FastGPT backend do not match, and cross-domain trust was not configured.
- The symptom is that the embedded Q&A component cannot expand the input box normally on mobile devices. The cause is that the responsive adaptation configuration was not enabled, and the component did not adapt to the mobile viewport.

## How to confirm the configuration is successful
- Copy the generated sharing link and access it with an unauthorized account, verify that an identity authentication prompt pops up.
- Deploy the iframe embedding code to a test page, maintain a stable session after logging in, verify that there is no automatic logout.
- Open the embedded page on a mobile device, verify that the Q&A component can normally expand the input box and complete interactions.
- Manually trigger the knowledge base synchronization, wait one hour then submit relevant transaction-related questions, verify that the Q&A content includes the latest transaction announcements.
