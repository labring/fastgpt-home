# Student Financial Aid and Subsidy Review Party Building Learning Q&A: Knowledge Base Retrieval and Recall
This document is written based on the configuration logic of FastGPT v4.17.0. It supports knowledge base retrieval and recall requirements for student financial aid and subsidy review in party building learning Q&A scenarios for state-owned enterprises, government, and public service sectors.

## What the data for this category looks like
Data sources for this category include the National Student Financial Aid Management Information System, school student status systems, civil affairs low-income and special hardship data, and fiscal payment systems.
The update cycle is each semester.
Daily processed documents include family economic hardship certification forms, financial aid application forms, scholarship and grant review forms, distribution lists, and public notification materials.
Data forms include two types: structured forms and semi-structured public notification text.
Fields cover identity identifiers, family economic status, funding qualification judgment basis, and fund distribution-related information.

## What constraints these characteristics bring to the knowledge base retrieval and recall link
Multi-source heterogeneous data sources require the retrieval link to support cross-dataset association matching. This avoids missed qualification judgments caused by isolated data sources.
The semester-level update cycle requires the knowledge base synchronization strategy to balance incremental updates and full verification. It balances data timeliness and system load.
The mixed data feature of structured forms and semi-structured public notification text requires retrieval configuration to adapt to field matching rules for different formats.
At the same time, errors in this category directly relate to student rights and government credibility. This requires recall results to accurately cover all core fields required for qualification judgment.

## How to configure the settings
| Configuration Item | Recommended Setting/Value Range | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Adapts to the mixed matching needs of structured forms and semi-structured text, balances accuracy and recall coverage |
| `limit` | Top 10 entries | Covers retrieval needs for multi-batch data such as review and distribution lists, avoids missing core judgment basis from single-batch results |
| `searchMode` | Full-text search + field matching | Adapts to document types mixing structured fields and text descriptions, supports dual recall via keywords and field values |
| `usingReRank` | Enabled | Improves the sorting priority of high-confidence results, ensures key materials required for qualification judgment are returned first |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands policy expressions related to party building learning, matches associated retrieval needs in party building learning Q&A scenarios |
| `collectionIds` | Specified by funding-related document collections | Limits retrieval scope to exclusive datasets related to student financial aid, avoids irrelevant content interfering with retrieval results |

## Three common configuration errors
- Symptom: Retrieval process returns permission denied errors, or fails to load details of specified documents. Cause: Failed to correctly configure `collectionIds` to limit retrieval scope, or dataset access permissions have not been granted to the calling principal of the current workflow.
- Symptom: Retrieved recall snippets cannot be linked to the online preview entry of the original document. Cause: Failed to collect the metadata storage path of the document, or failed to configure the jump logic for original file preview in the workflow.
- Symptom: Structured form documents are not correctly recalled, or matching results have low relevance to keywords. Cause: `searchMode` was not switched to the matching mode adapted for structured fields, only using full-text search causes field matching to fail.

## How to confirm the configuration is complete
- Enter test queries containing keywords such as family economic hardship certification, scholarship and grant distribution. Check whether returned results include the core document types of this category.
- Adjust the value range of `similarity`. Confirm through multiple rounds of testing that the accuracy and coverage of recall results meet business verification needs.
- View the metadata of retrieval results. Confirm whether they are linked to the storage path of the original document, supporting subsequent original file viewing operations.
- Test retrieval scope limited by `collectionIds`. Confirm that only funding-related documents of this category are included in the recall results.
