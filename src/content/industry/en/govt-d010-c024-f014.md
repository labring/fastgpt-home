# Party Building Learning Q&A for Student Aid and Subsidy Review: Conversation Logs and Auditing

## What This Category’s Data Looks Like
Data for this category comes from the national student aid management information system, school student status system, civil affairs subsistence and special hardship assistance data, and fiscal payment system. The update cycle is per semester.
Daily documents include family economic hardship assessment forms, aid application forms, scholarship and grant review forms, distribution lists, and public notice materials.
Core fields include student identity information, hardship assessment level, aid amount, distribution status, bank card information, and more. Data is generated around the core nodes of subsidy qualification review and fund distribution, and linked to synchronization results across multiple systems.

## Constraints Imposed on Conversation Logs and Auditing
Cross-module data association requirements from multiple system sources mandate that conversation logs fully record specific document fields involved in user queries and system call results, to avoid data gaps during audits.
The semester-level update frequency requires logs to be retained long-term and archived by semester, to align with annual audit requirements.
Document types include sensitive materials such as review notices and distribution lists, so logs must distinguish access permissions for public query and internal review scenarios.
Errors in student aid data directly impact student rights and interests, so the audit link must fully capture interaction details to ensure every aid-related Q&A is traceable.

## Configuration Guidelines
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Log retention period | 18 months | Meets cross-cycle traceability requirements for this category’s semester updates and annual audits |
| Sensitive data desensitization rule | Only show the last 4 digits of bank card numbers | Complies with privacy protection requirements for student aid data |
| Core log field collection | Collect `chatId`, `responseChatItemId`, `detail` | Fully covers audit traceability requirements for the entire interaction chain |
| Permission control granularity | Distinguish log access permissions by role | Separates access scope between internal review staff and external query users |
| Archiving trigger rule | Automatically archive by semester | Matches the semester update frequency of this category’s data |
| Log storage limit | 1000 MB, calibrated based on actual testing | Adapts to the volume of log data generated by multi-system synchronization |

## Three Common Configuration Errors
- Symptom: Logs indicate the Q&A was uploaded successfully, but the interface cannot trigger subsequent review processes. Cause: Failed to correctly associate the document ID in the `detail` field with the data source configuration of the aid review node, causing logs to be unreadable by workflows.
- Symptom: Sensitive fields such as student bank card numbers are missing from audit logs. Cause: Sensitive data desensitization configuration is not enabled, or the desensitization rule does not cover exclusive fields of aid-related documents.
- Symptom: Historical Q&A cannot be associated with the corresponding review batch via `chatId`. Cause: Log archiving rules are not configured by semester, and cross-cycle data is automatically cleaned, leading to traceability failures.

## How to Verify Successful Configuration
- Initiate a Q&A that includes a query for the family economic hardship assessment form, and confirm the log contains complete content of the `chatId`, `responseChatItemId` and `detail` fields.
- Switch between different role accounts, and confirm only authorized roles can access log content related to corresponding aid reviews.
- Wait for a test cycle, and confirm logs have been archived and retained according to preset rules.
- Simulate a sensitive data query, and confirm sensitive fields in logs have been desensitized according to configured rules.
