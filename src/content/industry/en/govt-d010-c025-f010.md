# Party Building Learning Q&A for Safety Production Hazard Inspection and Governance: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data sources include safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily documents include hazard inspection checklists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Common document fields include hazard number, inspection time, responsible entity, rectification deadline, rectification status, review result, and other standard fields. No custom units are used. Only classification labels such as inspection items and rectification items are marked based on business scenarios.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Daily updated data sources require the retrieval link to support incremental synchronization, to avoid full re-scanning that consumes system resources. Mixed multi-type document structures require matching field characteristics of different forms, to avoid confusing the content logic of hazard inspection checklists and rectification notices during retrieval. Hazard inspection-related content has high recall precision requirements. Irrelevant non-hazard documents must be filtered to ensure the accuracy of inspection basis. Law enforcement records and accident statistics data have strong timeliness. Recently updated entries must be recalled first, to avoid using expired hazard determination reference content.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirements for hazard inspection, filters low-relevance non-hazard documents |
| `limit` | Top 10 entries | Adapts to the number of entries in a single inspection document, avoids context overload that affects inspection judgments |
| `searchMode` | Keyword + semantic hybrid | Covers structured fields such as hazard number and rectification deadline, as well as semantic content of hazard descriptions |
| `usingReRank` | Enabled | Performs secondary sorting on recall results, prioritizes high-priority content related to major hazards |
| `datasetSearchUsingExtensionQuery` | Enabled | Based on the party building learning Q&A scenario, expands synonymous expressions of questions, covers colloquial questions from grassroots staff |
| `collectionIds` | Bound by business category | Only retrieves the knowledge base dedicated to hazard inspection and governance, avoids mixing in content unrelated to party building |

## Three Common Misconfigurations
- Phenomenon: A parameter error is returned when calling the chat interface, with a prompt that the knowledge base ID format is invalid. Cause: The knowledge base ID is not bound to the valid value range of the conversation variable, or the variable is not authorized and configured on the knowledge base management page.
- Phenomenon: The updated dataset cannot be exported after modifying the knowledge base, with a prompt that the file has not been updated. Cause: The incremental synchronization process of the knowledge base is not triggered, or the export operation only grabs the initially uploaded file version.
- Phenomenon: A large number of non-hazard documents are mixed in the retrieval results, and the number of recalled entries exceeds expectations. Cause: `collectionIds` is not configured to limit the retrieval scope, leading to cross-knowledge-base recall of irrelevant content from party building learning or other categories.

## How to Verify Successful Configuration
- Upload a test hazard inspection checklist document, initiate a question containing the keyword "major hazard", and verify that returned results only contain hazard-related content.
- View the synchronization log on the FastGPT v4.17.0 knowledge base management page, confirm that the daily incremental update task has been executed normally with no failed records.
- Configure conversation variables to bind the specified knowledge base ID, initiate a question, and check that the context returned by the interface only contains content from this knowledge base.
- After enabling `usingReRank`, compare the recall result sorting before and after enabling, confirm that highly relevant hazard rectification records are returned first.

The values provided here are common starting points, and should be measured against the reader's own samples.
