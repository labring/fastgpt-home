# Party Building Learning Q&A for Safety Production Hazard Investigation and Governance: Forms and Interactions

## What the data for this category looks like
Data sources for this category include safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Commonly used documents include hazard investigation checklists, hazard management ledgers, rectification notices, review records, and major hazard listing and supervision notices. Data fields include hazard ID, investigation subject, hazard location, rectification responsible person, rectification deadline, review status, and others. There is no unified fixed single-document format; corresponding field sets must be matched based on different business scenarios.

## What constraints these characteristics impose on the "forms and interactions" link
Multiple data sources require forms to support mapping and association of fields from multiple systems, to avoid duplicate data entry. Different types of business documents require forms to provide dynamically switching field templates to adapt to collection needs for different scenarios. The daily data update frequency requires forms to support real-time or scheduled synchronization to ensure collected data matches supervision system data. For time-consuming workflows including standard-based investigation, rectification tracking, and review and archiving, forms need built-in standard options and validation rules to reduce manual operation errors. They must also retain complete operation logs to support subsequent compliance inspections.

## Three common configuration mistakes
- After enabling the voice input function, the entered hazard description cannot be correctly recognized and returns empty fields. The cause is that voice input adaptation rules for `formInput` are not configured, and the professional term thesaurus for this category is not linked.
- When calling the associated LLM model, the returned rectification suggestions are irrelevant to the current hazard content, and a status code 400 is returned. The cause is that exclusive documents of this category are not bound as a knowledge base, or the model call context is not linked to business data.
- Parameter verification fails when submitting the form, and submission cannot be completed. The cause is that `formInput` validation rules are configured incorrectly, and the required field format for documents of this category is not correctly matched.

## How to verify a correct configuration
- Navigate to the FastGPT form configuration page, and check whether three dedicated field templates exist for hazard investigation checklists, rectification notices, and review records.
- Trigger the `formInput` voice input function, enter a description containing hazard location and type, and confirm that fields can be normally filled and saved.
- Select a hazard type option from the `userSelect` component, and confirm that the option library includes classification items that comply with major accident hazard judgment standards.
- Submit a test form, and confirm that it can be normally synchronized to the associated business system without error returns.
