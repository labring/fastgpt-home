# Party Building Learning Q&A for Engineering Construction Project Approval: Document Parsing and Chunking
This document applies to FastGPT v4.17.0.

## What this category of data looks like
Data comes from engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases, and credit platforms. The update frequency is daily.
Documents processed daily include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion acceptance record forms.
These documents contain fixed fields such as participating construction unit names, approval nodes, license numbers, and application dates. Some documents are structured PDFs that include tabular approval materials.

## Constraints imposed on the document parsing and chunking link
The multi-source integration feature of engineering construction project approval documents requires chunking logic to adapt to mixed-format text and table content, and avoid losing key information associated across systems.
The fixed approval node structure requires that chunks cannot split core paragraphs of a single permit document. Otherwise, the accuracy of subsequent Q&A will be affected.
Daily updated approval data requires chunking configurations to have dynamic adaptability, so that new approval documents can be processed without frequent adjustments.
If table content in structured PDFs is not parsed correctly, key information such as participating construction unit qualifications cannot be extracted in the party building learning Q&A.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the conventional length of single approval node paragraphs in approval documents, avoiding splitting core permit information |
| `chunkSplitter` | Custom delimiter + line break | Preserves paragraph integrity of approval documents already segmented by business logic, adapting to preset segmentation rules |
| `customPdfParse` | Enabled | Extracts tables and text content from structured PDFs such as construction drawing review qualification certificates, avoiding information loss caused by format confusion |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing time of long documents such as large completion acceptance record forms, avoiding parsing failure due to timeout |
| `chunkSettingMode` | Manual mode | Adjusts chunking rules for the fixed structure of approval documents, avoiding automatic chunking destroying logical coherence of approval nodes |

## Three common mistakes
- Phenomenon: After setting a custom delimiter, chunking results either merge multiple approval node paragraphs or split the content of a single permit document. Cause: The matching logic between the `chunkSize` value and the custom delimiter is not aligned, and the natural segmentation boundary of long paragraphs in approval documents is not considered.
- Phenomenon: An error is reported when processing approval-related PDF documents after deploying Marker via Docker, and a parsing failure prompt is returned. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not configured correctly to adapt to the parsing duration of large PDF documents, or the environment variable is not correctly linked to FastGPT's file parsing link.
- Phenomenon: When batch processing approval documents, some files have empty chunking results or missing key fields such as participating construction unit qualifications. Cause: The `customPdfParse` configuration is not enabled, causing tabular content in structured PDFs to be recognized as pure images and unable to extract text.

## How to confirm the configuration is correct
- Upload a single construction permit application PDF, check if the chunking results retain complete paragraphs of core fields such as application unit and license date.
- Adjust `chunkSize` to different ranges, verify that the chunk length meets expectations, and no cross-approval-node merging or splitting occurs.
- Run a batch parsing test, confirm that the parsing time of all documents does not exceed the set value of `PARSE_FILE_TIMEOUT_SECONDS`, and no timeout errors occur.
- View the parsing log, confirm that the `customPdfParse` configuration has taken effect, and table text in PDFs is not missed or misrecognized.

The values provided are common starting points and should be evaluated using local test samples.
