# Party Building Learning Q&A for Engineering Construction Project Bidding and Tendering: Deployment and Upgrade

## What the data for this category looks like
This category covers full-process documents for engineering construction bidding and tendering, including tender announcements, pre-qualification documents, bidding documents, bid documents, bid evaluation reports, successful bid candidate notices, successful bid result announcements, and supporting industry policy documents related to party building learning. Data sources include the national public resource trading platform, local trading platforms, engineering approval systems, and bidding and tendering supervision systems, with daily updates. Documents include core fields such as section division, qualification requirements, bid evaluation rules, and successful bid results; some documents involve special content such as bill of quantities and construction period.

## What constraints these characteristics impose on the deployment and upgrade process
This guide is written for FastGPT v4.17.0. Data for this category comes from multiple dispersed sources and is updated daily. During deployment, storage configuration must be adapted to support multi-platform data access to ensure the stability of daily incremental synchronization. There are diverse document types with significant structural differences, so matching indexing rules must be preset for different documents to avoid retrieval deviations. Since errors in the bidding and tendering process directly affect project progress and compliance risks, rollback nodes must be reserved during deployment and upgrade, and data verification logic must be configured to ensure the integrity of fields in accessed documents. Additionally, party building learning Q&A needs to be associated with party building requirements in the bidding and tendering field, so a dedicated association path for the knowledge base must be separately configured to avoid confusion with general business data.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Fill in the connection string for the read-only instance corresponding to public resource trading data | Used to store structured documents for bidding and tendering and party building knowledge bases; the read-only instance avoids write risks |
| `REDIS_URL` | Configure the connection address of the local cache instance, set the cache validity period to 86400 seconds | Data sources updated daily require cache refresh every day to avoid reading expired data |
| `DB_MAX_LINK` | Set to 15–20 concurrent connections | Adapts to the request volume of daily incremental synchronization across multiple platforms, avoiding connection pool exhaustion |
| `STORAGE_S3_ENDPOINT` | Fill in the endpoint of the corresponding cloud storage service provider | Used to store binary files of bidding documents and party building learning materials |
| `FE_DOMAIN` | Fill in the external access domain name of the platform | Used to generate jump links for knowledge base retrieval results, adapting to access paths for internal office scenarios |

## Three common mistakes
- The interface prompts that pnpm version 9.0 or higher is required, and the deployment script fails to run. This occurs when the pnpm environment of the required version is not configured in advance, or the system default low-version pnpm is used to run the deployment command.
- After deploying the open-source re-ranking model, retrieval results are empty. This occurs when the model's loading path and port mapping are not configured correctly, or the re-ranking function is not enabled in the knowledge base configuration.
- After upgrading, the backend management page cannot be accessed, and a permission error is displayed. This occurs when the original configuration value of `ROOT_KEY` is not retained, causing the administrator key to be reset after upgrading, which prevents login permission verification.

## How to confirm the configuration is complete
- Run the daily incremental synchronization script, check whether the backend log shows that the synchronization task is successfully completed, and verify that the number of synchronized documents matches the data source update volume.
- Submit a party building-related question containing bidding and tendering-specific terminology, confirm that the retrieval results return the corresponding associated policy and business documents, and verify that the knowledge base association logic is effective.
- Modify the `FE_DOMAIN` configuration, access the platform front-end page, and check whether all jump link domain names are updated to the newly configured value.
- After restarting the service, check whether the cache instance corresponding to `REDIS_URL` establishes a normal connection, and there are no connection timeout error messages.
