# Party Building Learning Q&A for Engineering Construction Project Bidding and Tendering: Sharing and Embedding

## What the data for this category looks like
Entities involved in this category include development and reform departments, industry competent departments such as housing and urban-rural development, transportation, water conservancy, public resource trading centers, and bidding agencies. Daily documents cover bidding announcements, pre-qualification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements. Data sources are national public resource trading platforms, local trading platforms, engineering approval systems, and bidding and tendering supervision systems, with an update frequency of once per day. Most documents contain structured fields such as bid section division, qualification requirements, bid evaluation records, and successful bid information, and the main formats are standardized official texts or structured tables released by relevant authorities.

## What constraints these characteristics impose on the "Sharing and Embedding" workflow
Daily updated bidding and tendering data requires the embedded party building learning Q&A application to be configured with a timed synchronization mechanism, to avoid reduced Q&A accuracy caused by data lag. Multiple types of structured business documents require limiting the retrieval scope in sharing configuration, only associating party building-related bidding and tendering policy Q&A and compliance documents, to prevent irrelevant business documents from interfering with the learning scenario. For sensitive business data such as bid evaluation and successful bid results, permission control rules must be configured during embedding to prevent unauthorized access or disclosure of sensitive information. Meanwhile, differences in usage scenarios across different entities require session isolation mechanisms to adapt to access permissions for different identities.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Share link validity period | `7 days` | Adapt to daily updated bidding and tendering data, avoid sensitive content disclosure caused by long-term exposure of links |
| Embedded iframe permissions | Only allow same-origin site embedding | Prevent malicious sites from stealing sensitive bidding and tendering documents, comply with public resource trading compliance requirements |
| Markdown export function | Disabled | Avoid unauthorized export of sensitive information-containing bidding and tendering documents, align with business compliance requirements |
| Session persistence configuration | Isolate sessions by user identity | Ensure that different users can only view their own party building learning Q&A records, prevent unauthorized data access |
| `shareId` binding | Associate with exclusive bidding project identification | This configuration is supported in FastGPT v4.17.0, which can accurately match the party building Q&A dataset of the corresponding project |
| Retrieval result limit | `Top 8 results` | Control retrieval load, adapt to structured retrieval needs of bidding and tendering documents, avoid excessive content interfering with the learning scenario |

## Three common configuration mistakes
- Phenomenon: The Markdown export button appears on the login-free window of the embedded page. Cause: The export function switch was not disabled in the sharing configuration, allowing unauthorized users to export sensitive bidding and tendering documents.
- Phenomenon: Different anonymous users share the same iframe session and can view each other's Q&A records. Cause: The parameter for isolating sessions by user identity was not configured, resulting in no permission binding for session persistence.
- Phenomenon: The embedded application fails to load within the timeout period or retrieves empty results. Cause: A reasonable data source synchronization cycle was not configured, leading to retrieval of a large number of expired or unsynchronized bidding and tendering documents and increased system load.

## How to confirm the configuration is complete
- Access the embedded iframe page, check whether the Markdown export button is displayed, and confirm that the function entry is not present.
- Use two different anonymous identities to initiate party building learning Q&A separately, check that each user's session records are invisible to each other, and verify that the session isolation configuration takes effect.
- Check the validity period of the share link, confirm that it is within the preset 7 days, and that the application cannot be accessed normally after the link expires.
- Submit a party building question containing bidding and tendering related keywords, verify that the retrieval results only associate with party building-related bidding and tendering policies and compliance Q&A content, with no irrelevant documents interfering.
