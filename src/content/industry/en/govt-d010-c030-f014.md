# Party Building Learning Q&A for Construction Engineering Quality and Safety Supervision: Conversation Logs and Auditing

## What data for this category looks like
Data sources for this category include engineering quality and safety supervision systems, on-site construction real-name registration platforms, supervisor logs, and inspection reports. The update frequency is weekly. Daily documents cover supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Each document contains core fields such as supervision entity, inspection date, hidden danger location, rectification requirements, and acceptance conclusion. Data is associated with specific on-site construction projects. There is no uniform fixed unit, and markings are applied based on actual project scenarios.

## What constraints these characteristics impose on conversation logs and auditing
Data is updated on a weekly basis. Conversation logs must be synchronized and linked to weekly updated engineering documents, to ensure that the latest supervision records can be matched during audits. Daily documents contain multiple project-related fields. Logs must store associated identifiers such as corresponding project numbers and hidden danger rectification notice numbers, to facilitate traceability. Conversations from different supervision entities must be separately distinguished by source, to avoid cross-mixing of logs. In concurrent call scenarios, context must be isolated by project dimension, to prevent cross-project data interference. At the same time, dialogue content must fully record interactions related to rectification closed-loop, to ensure that the rectification process can be traced during audits.

## How to set configurations
These configurations are developed based on the logs and auditing function of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` binding rule | Generated using "supervision entity + project number" | Distinguish conversations of different supervision entities and projects, match business data association logic |
| Log storage fields | Include the `detail` field | Fully record dialogue content and associated engineering document identifiers, meet audit traceability requirements |
| Concurrent call threshold | 1-2 calls per second | Adapt to the weekly update rhythm of engineering data, avoid exceeding the system's carrying capacity |
| Feishu Webhook trigger configuration | Triggered after splicing the results of loop nodes | Adapt to batch scenarios of rectification notice push, match the batch update rhythm of daily documents |
| `responseChatItemId` association rule | Bound to hidden danger rectification notice number | Ensure each reply is bound to a specific rectification task, facilitate quick positioning during audits |
| Log storage period | 180 days | Meet basic archive management requirements for the housing and urban-rural development sector, comply with measured compliance periods |

## Three common errors
- Symptom: Dialogue reply content is not saved to the history record, and the automatic reply is empty when the conversation is reopened. Cause: The `chatId` binding rule is not configured correctly, and the supervision entity and project number are not associated, causing the log to fail to match the corresponding context.
- Symptom: When the concurrent call volume reaches 2-3 calls per second, the workflow returns an empty value. Cause: A reasonable concurrent call threshold is not set, exceeding the system's carrying limit, causing blocking in the log storage and call link.
- Symptom: Feishu Webhook cannot send the spliced loop node content. Cause: The trigger timing is not configured according to the batch update rhythm of project documents, causing the spliced content to exceed the single-send limit, or the trigger fails because the corresponding hidden danger rectification notice number is not associated.

## How to confirm the configuration is complete
- Generate a test conversation associated with a specified supervision entity and project number, check whether the corresponding `chatId` identifier is included in the log.
- Simulate concurrent calls, check whether all interaction content is fully recorded in the log, with no loss or blocking.
- Trigger Feishu Webhook to push the spliced rectification content, check whether it can be normally sent to the specified channel, and the corresponding hidden danger rectification notice number is associated.
- View the log storage period configuration, confirm that it meets compliance requirements, and adjust according to actual audit needs.
