# Party Building Learning Q&A for Construction Project EIA Approval: Vector Models and Indexing

## What the data for this category looks like
This category addresses Party Building learning Q&A needs for the construction project environmental impact assessment (EIA) approval domain. Core data comes from the national unified EIA declaration and approval system for construction projects, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. It covers daily documents of four types of entities: ecological environment department EIA offices, administrative examination and approval bureaus, construction units, and EIA institutions. These documents include environmental impact assessment reports or report forms, approval applications, public participation descriptions, technical evaluation opinions, and EIA approval documents. Data updates have no fixed cycle. Document structures include modules such as project basic information, technical analysis, and approval conclusions. There is no unified fixed field format, and some documents are long text paragraphs.

## What constraints do these characteristics impose on the "vector models and indexing" link
This category's Party Building learning Q&A requirement requires retrieval results to match both the business logic of EIA approval and the policy relevance of Party Building learning. Data sources are scattered and formats are inconsistent, requiring the indexing link to support multi-data source field mapping and format compatibility. Long-text EIA reports require appropriate chunking rules to avoid truncation of key technical content. The feature of no fixed update cycle requires the indexing link to support incremental update mode to reduce resource consumption from full reconstruction. Documents need to accurately match project categories and approval stages, so the retrieval link needs to limit the relevance threshold of recall results to avoid interference from irrelevant documents.

## How to configure the settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the long paragraph structure of EIA reports to avoid forced truncation of core technical content |
| Overlap Length | 100–200 characters | Retain contextual association between adjacent chunks to prevent loss of association information between project categories and approval requirements after chunking |
| Similarity Threshold | 0.75–0.85 | Filter low-relevance non-EIA documents to ensure retrieval results focus on approval materials for corresponding construction projects |
| Single Search Limit | Top 10 results | Match the multi-document verification needs of EIA approval to avoid excessive redundant results affecting manual review |
| `defaultToken` | 8192 | Adapt to vector embedding requirements after long-text chunking to meet token limits for single-batch processing |
| Maximum Context | 4096 tokens | Control the length of spliced context after retrieval to adapt to the call parameter limits of external APIs |

## Three common mistakes
- Index creation fails, with the interface displaying "index build timeout", on an 8c16G non-GPU virtual machine host. The cause is failure to reduce chunk length or enable incremental indexing mode, resulting in single-process data volume exceeding memory thresholds.
- After connecting vector models and language models via external API, request timeouts occur on ARM soft router deployments. The cause is failure to lower the `maxToken` parameter, resulting in total token volume of a single request exceeding the soft router's processing capacity.
- Importing Excel files and multi-dimensional documents from Feishu folders fails to generate indexes. The cause is failure to enable parsing plugins for corresponding file formats, and failure to configure chunking rules for table documents, resulting in chaotic parsed text format that cannot be embedded into vectors.

## How to confirm correct configuration
- Upload a standard environmental impact assessment report form, check if the chunked text fully covers core chapters such as project basic information and pollution prevention measures, with no obvious sentence breaking errors.
- Initiate a retrieval request for the EIA level of a specific construction project, check if the returned results include the approval application and technical evaluation opinions for the corresponding project.
- View the index build log to confirm that multi-data source field mapping has been completed, with no missing fields or format incompatible error messages.
- Test the single-call delay of the external API to confirm that requests do not exceed the preset timeout threshold, with no continuous error reports.
