# Party Building Learning Q&A for Construction Project Environmental Impact Assessment Approval: Multi-turn Dialogue and Prompt Engineering

## What data does this category use?
This category’s data is primarily sourced from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Daily processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approvals. These cover the full process of construction projects from declaration to approval. Service subjects include EIA departments of ecological environment authorities, administrative examination and approval bureaus, construction units, and EIA institutions. The data structure is dynamically adjusted based on project type and approval stage.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering?
The data characteristics of this category impose multiple constraints on the multi-turn dialogue and prompt engineering link. Multi-source data sources require prompts to clearly distinguish document permissions and formats across different systems to avoid cross-data-source call errors. The irregular update feature requires the dialogue system to support dynamic synchronization of the latest data, preventing use of expired policies or project information. The complex document structure requires multi-turn dialogue to follow approval stages sequentially: first verify project category and EIA level, then review pollution prevention measures and public participation content to avoid missing key links. Additionally, the high-stakes nature of errors requires strict isolation of dialogue contexts, ensuring that dialogue information for one project does not interfere with approval Q&A for other projects.

## How to configure the system?
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier using the EIA approval document number | Ensure context isolation for individual projects and prevent confusion of cross-project approval information |
| `messages` | Append content by dialogue turn, retain the first 20 rounds of historical dialogue | Cover multi-turn communication needs for a single project’s full approval process and prevent loss of key historical information |
| `variables` | Inject project category, affiliated region, and approval stage variables | Enable prompts to accurately match document rules for the corresponding category and call matching data sources |
| Maximum context length | 8000–12000 characters | Adapt to the long-form nature of EIA documents and avoid truncation of critical approval information |
| Context recall limit | Top 10 historical messages | Balance dialogue fluency and information integrity, and avoid redundant information interfering with Q&A results |
| Prompt template update frequency | Align with the adjustment cycle of approval policies | Adapt to irregularly updated EIA policies and data sources, ensuring Q&A matches the latest rules |

## Three Common Misconfigurations
- Symptom: A 503 error appears when uploading EIA documents on the dialogue page, and backend logs show the file was uploaded successfully. Cause: The file storage path variable in `variables` is not correctly bound, leading to abnormal front-end request routing.
- Symptom: Contexts from different EIA projects are mixed during multi-turn dialogue. Cause: No unique `chatId` is assigned to each dialogue, so the system cannot distinguish dialogue content for different projects.
- Symptom: The EIA level returned by the prompt does not match the project’s actual category. Cause: The project category `variables` variable is not injected, so the prompt cannot accurately recall document rules for the corresponding category.

## How to Verify Correct Configuration
- Initiate a test dialogue, enter the approval document number of an EIA project, and check whether `chatId` matches the project’s unique identifier.
- Upload a single environmental impact assessment report, then initiate multiple rounds of questions to verify that historical dialogue content is not accidentally truncated or confused across projects.
- After injecting project category and affiliated region variables, ask "What is the EIA level of this project" and confirm the returned result matches the document rules for the corresponding category.
- View backend logs to confirm that the routing of the file upload request matches the configured `variables` storage path.
