# Party Building Study Q&A for Construction Project EIA Approval: Forms and Interaction

## What data for this category looks like
This category’s data comes from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular.
Daily business documents include environmental impact assessment report books, environmental impact assessment report forms, approval applications, public participation explanations, technical assessment opinions, and EIA approval documents.
Data fields cover project category, EIA level, pollution prevention measures, public participation status, approval status, and other items. Some fields must match local ecological environment zoning control requirements. There are no unified global units for these fields.

## What constraints these characteristics impose on forms and interactions
Multiple cross-system data sources and irregular updates require form interactions to support real-time calls to multiple data sources for verification. This avoids information lag caused by static cached data.
Complex business document structures require forms to support multi-segment content upload and field split entry. This reduces error rates for long document submissions.
Core fields such as project category and EIA level must link to regional ecological environment zoning control results. Option linkage verification rules must be set to ensure input content meets local control requirements.
Party building study Q&A interactions must be embedded in key nodes of the approval form. This guides relevant personnel to synchronously learn corresponding policy requirements, while avoiding interference with the normal form submission process.

The following configurations are based on FastGPT v4.17.0.

## Three common configuration errors
- No response after voice input: The voice transcribe button shows no feedback when clicked, or the transcribe result is empty. This occurs when voice input adaptation parameters for `formInput` are not configured, causing voice data to fail to correctly flow into the RAG process.
- MySQL connection failure: An error "connection refused" or "database not found" appears when the form calls business data. This happens when database connection address, port, and permissions are not correctly configured, and the data source format of the EIA approval system is not matched.
- HTTP request parameter error: A 400 status code is returned after form submission, or approval data is not correctly pulled. This occurs when the parameter name and value corresponding to `userSelect` are not clearly defined, and a file link is mistakenly passed as the parameter value.

## How to verify a correct configuration
- Submit test basic information for an EIA project, check whether form fields dynamically display ecological environment zoning control requirements for the corresponding region.
- Upload a segment of an environmental impact assessment report fragment, verify whether `formInput` supports segmented parsing and content verification.
- Initiate a voice input test, confirm that the transcribe result can be correctly synchronized to the form's Q&A interaction module.
- Check system logs to confirm that HTTP request parameter names and values match the preset `userSelect` configuration item.
