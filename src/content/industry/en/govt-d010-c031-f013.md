# Party Building Learning Q&A for Construction Project Environmental Impact Assessment (EIA) Approval: Sharing and Embedding

## What the data for this category looks like
Data for this category originates from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permission platform, and monitoring data. Update frequency is irregular.
Daily documents include environmental impact assessment reports (books or forms), approval applications, public participation explanations, technical assessment opinions, and EIA approval documents. Each document contains fields such as project category, EIA level, pollution prevention measures, public participation status, and approval document number. There are no unified fixed units. Corresponding business fields must be matched based on the document type.

## What constraints these characteristics impose on the sharing and embedding workflow
Multiple data sources and irregular update cycles require binding a dedicated EIA approval party building Q&A knowledge base using `shareId` after embedding. This ensures Q&A content aligns with the latest approval data.
Diverse daily document types and fields that change based on business scenarios require embedding components to support dynamic matching of field rules for different documents. This prevents Q&A content from deviating from business logic.
Error consequences relate to project construction start and approval validity. Embedding links must strictly limit content display scope to avoid calling unrelated or incorrect information.
Most deployments for this category run within government systems or professional institutions. Embedding code must adapt to loading rules of mainstream front-end frameworks.

## Three common configuration errors
- Embedded pages display a "parameter error" prompt. Cause: `shareId` is not configured correctly, or a non-target application identifier parameter is used.
- Embedded components display the default non-login popup. Cause: The login mode was not switched to WeChat QR code login, and the default configuration was retained.
- Embedded pages still display referenced source content. Cause: The display referenced content switch was not turned off, and the default enabled state was mistakenly retained.

- Submit questions related to project categories and approval requirements. Confirm that the answer content matches the corresponding document data.
- Verify that the login process redirects to the WeChat QR code page. Confirm that the login mode configuration takes effect.
- Check that the interface does not display referenced source content. Confirm that the display switch is configured correctly.
