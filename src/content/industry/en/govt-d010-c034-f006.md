# Party Building Learning Q&A for Enrollment and Student Status Management: Citation Sources and Traceability

## What This Category's Data Looks Like
Data for this category covers the full lifecycle of student enrollment and student status. Daily documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Data sources include the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. Data is updated daily. Data fields focus on student identity identifiers, enrollment qualification verification information, and student status change records. Only structured identity, qualification, and change-related content is included, with no extra statistical numeric fields.

## What Constraints Do These Characteristics Impose on the Citation Sources and Traceability Link?
Scattered data sources across multiple government and academic affairs systems require the traceability link to associate metadata tags from different systems. This prevents cross-source reference confusion. The daily update frequency requires the knowledge base sync frequency to match the update rhythm. This stops expired student status or enrollment information from being referenced. Fields focus on identity, qualification, and change records. The traceability link must accurately bind the corresponding document field identifiers to ensure referenced content matches the business scenario. Errors in student status and enrollment data can trigger enrollment disputes. The traceability link must retain complete citation chains to facilitate subsequent verification and problem troubleshooting.

## How to Set Up Configurations
This document is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | Matches the content length of single documents in this category, to avoid truncating critical student status or enrollment information |
| `responseData` | Enable citation list return | Meets the business requirement to verify citation sources, and facilitates checking the origin of enrollment policies or student status rules |
| `detail` | Enable detailed traceability mode | Retain metadata of referenced documents, including source system, update time and other fields |
| Knowledge base chunk length | 800–1200 characters | Adapts to the content density of single documents in this category, to avoid losing critical associated information during chunking |
| Single recall limit | Top 6 entries | Covers the number of reference documents for common enrollment and student status questions, to avoid interference from redundant information |

## Three Common Misconfigurations
- Phenomenon: After calling the Q&A API, the citation list is returned first, but the answer body does not associate the corresponding business content. Cause: The association binding logic for the `responseData` parameter is not configured. Only the citation list return is enabled, but the referenced content is not embedded in the answer.
- Phenomenon: After local deployment, the citation list displays correct student status document entries, but the answer body does not include this document content. Cause: The `detail` parameter is not enabled to retain field associations of referenced documents, so the question cannot be matched with the document content.
- Phenomenon: The number of citations returned by the Q&A result is far less than the configured recall limit. Cause: The `quoteMaxToken` parameter is not adjusted to adapt to document length, causing some long documents to be truncated and unable to be recalled.

## How to Verify Correct Configuration
- Initiate a question related to student status changes, check if the returned citation list includes corresponding transfer application or student status change approval form documents.
- View the `responseData` field in the API return, confirm that it includes metadata information such as the source system and update time of the referenced documents.
- After triggering the Q&A, check if the answer body matches the content of the entries in the citation list, with no disconnect.
- Simulate the daily update scenario, resync the knowledge base, then initiate the same question, confirm that the referenced documents are the latest version.
