# Party Building Learning Q&A for Admissions, Enrollment and Student Records Management: Sharing and Embedding

## What Data for This Category Looks Like
Data sources for this category include the National Primary and Secondary School Student Records Management System, local enrollment and admission platforms, household registration and property data, and school academic affairs systems. Data updates occur daily. Daily documents include enrollment application forms, student records information forms, transfer applications, enrollment plans, admission rosters, and student records change approval forms. Data fields include student identity identifiers, household registration and property information, student record numbers, change types, approval status, and more. Most fields use text or enumeration data types, with no complex statistical units.

## What Constraints These Characteristics Impose for Sharing and Embedding
This category’s data contains sensitive student identity and household registration information, and updates daily. Strictly control access permissions during sharing and embedding to prevent unauthorized data access. Most daily documents are structured forms and approval files. Match context recall for embedded applications to exclusive fields such as student record numbers and change types, to ensure Q&A content aligns with business scenarios. Scattered data sources require knowledge base updates to synchronize across multiple systems. After embedded deployment, regularly verify data consistency to avoid Q&A deviations caused by delayed data.

## Three Common Misconfigurations
- Phenomenon: The iframe embedded page displays a blank screen, but the external network address loads normally. Cause: The iframe embedded domain whitelist is not configured, or the whitelist does not include the filed domain name of the current embedded page.
- Phenomenon: Workflow runs normally during preview, but no valid Q&A results are returned after publishing the guest access window. Cause: The guest access configuration is not linked to the correct `shareId`, or the latest enrollment and student records data in the knowledge base has not been synchronized.
- Phenomenon: Q&A results returned by the embedded application omit content related to student record changes or enrollment plans. Cause: The context recall limit is set too low, failing to cover the field information of core business documents.

## How to Verify Successful Configuration
- Directly access the sharing link generated via `shareId`, confirm that the Party Building Learning Q&A loads normally and returns corresponding enrollment and student records related content.
- Load the sharing link in the iframe of the embedded page, confirm that the page has no blank screen and can normally initiate and submit Q&A.
- Modify a test student record change data, wait for the data synchronization cycle, then query the data in the embedded application, confirm that the result has been updated.
- Check the domain whitelist configuration, confirm that the domain name of the embedded page has been added to the whitelist.
- Confirm that the current deployment environment is FastGPT v4.17.0, to avoid configuration failure due to version differences.
