# Party Building Learning Q&A for Pollution Discharge Permit Management: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category comes from the national pollution discharge permit management information platform, enterprise environmental protection account books, online monitoring systems, and environmental statistics systems. The data update frequency is quarterly. Daily documents include pollution discharge permit application forms, implementation reports, self-monitoring plans, account book records, change applications, and permit copies. Documents contain fields such as permit limits, discharge outlet locations, monitoring frequencies, and implementation status. No additional statistical content is included.

## Constraints for Knowledge Base Retrieval and Recall
Multiple scattered data sources require retrieval to support associated recall across cross-system datasets. This avoids missing information gaps across platforms.
The quarterly update rhythm requires the knowledge base to use a regular incremental synchronization mechanism. This ensures data timeliness.
Diverse document structures require retrieval to adapt to field matching rules for different document types. This distinguishes content such as application forms and implementation reports.
Time-consuming links such as checking permit limits and auditing account books require retrieval to prioritize recalling content from related fields. This improves accurate matching rates.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| --- | --- | --- |
| `similarity` | 0.75–0.85 | Pollution discharge permit data has high strictness requirements, and precise matching of core fields such as permit limits and account books is needed |
| `limit` | Top 10 entries | Avoid recalling too many non-core documents, and control context length to comply with model input limits |
| `searchMode` | `keyword+embedding` | Combine keyword matching to accurately locate permit limit content, while supporting semantic generalization for party building learning-related questions |
| `usingReRank` | Enabled | Filter low-relevance account book records, and improve the sorting accuracy of retrieval results |
| `datasetSearchUsingExtensionQuery` | Enabled | Expand the query scope to cover generalized question matching related to party building learning |
| `collectionIds` | Bind the dataset ID corresponding to pollution discharge permit management | Accurately recall document data exclusive to this category, and avoid mixing content from irrelevant datasets |

## Three Common Configuration Mistakes
- Phenomenon: The system directly refuses to answer when no party building-related questions are matched, and cannot perform generalized reasoning. Cause: `datasetSearchUsingExtensionQuery` is not enabled, and extended query logic is not configured. This prevents the generation of reasonable responses.
- Phenomenon: The number of retrieval results exceeds expectations, including a large number of non-core account book records. Cause: The `limit` parameter is not set, or its value is too large. This recalls too much redundant content that exceeds the model context limit.
- Phenomenon: Retrieval results have low relevance, and non-permit limit content is recalled first. Cause: The `similarity` threshold is set too low, and `usingReRank` is not enabled for reranking and filtering. This leads to low-relevance content receiving higher scores.

## How to Confirm Correct Configuration
- Input a question that includes permit limits. Check if the returned results contain the corresponding document field content. Verify that the `similarity` threshold falls within the set range.
- Input a generalized question related to party building learning. Check if extended query is triggered. Verify that `datasetSearchUsingExtensionQuery` is enabled.
- View the dataset synchronization log. Confirm that quarterly updated documents have been synchronized to the knowledge base. Verify that the dataset bound by `collectionIds` is correct.
- Test questions that do not have direct matches. Check if reasonable responses are generated. Verify that the `searchMode` configuration meets expectations.
