# Party Building Learning Q&A for Government Service Item Catalog and Service Guide Maintenance: Deployment and Upgrade

## What the data for this category looks like
The core data for this category comes from the national basic catalog of government service items, administrative licensing item list, power and responsibility list, and local government service item databases. The update frequency is usually once per month. Daily processed documents include the basic catalog of government service items, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions. Data fields cover item names, acceptance conditions, application materials, processing procedures, and more. Some documents contain both structured fields and unstructured text, requiring synchronization and verification support for multi-format data.

## What constraints do these characteristics impose on deployment and upgrade
Due to multiple data sources and fixed update frequency, an interface that can regularly synchronize external catalog databases must be configured during deployment. During upgrades, compatibility with new government data field formats must be maintained. Multi-format mixed data requires the deployment link to support parsing and vectorization of multiple documents such as PDF and Word. The high-frequency need for field verification requires retaining or adding field integrity check logic during upgrades. At the same time, compliance requirements for government data require that deployment and upgrade processes adapt to the storage and network environment of government clouds to avoid data leakage risks.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `1000–1500 entries` | Adapts to the average number of associated items linked to government service item documents, meeting the batch synchronization needs of monthly updated data |
| `REDIS_URL` | `Government cloud cache instance address with persistent configuration` | Caches verified service guide field data to avoid repeated comparison between superior catalogs and local implementation lists |
| `STORAGE_S3_ENDPOINT` | `Access address corresponding to government cloud object storage` | Complies with compliance requirements for government data storage, ensuring secure storage and access to service guide attachments |
| `FILE_TOKEN_KEY` | `32-bit random encrypted string` | Enables identity authentication for service guide sharing links, preventing unauthorized personnel from accessing sensitive government documents |
| `ROOT_KEY` | `Key known only to internal operation and maintenance personnel` | Restricts access to the FastGPT management backend, preventing unauthorized personnel from modifying government data configurations |
| `MONGODB_URI` | `Exclusive database instance address for government clouds` | Stores structured data of government service items and vectorization results, ensuring compliance of data storage |

Reference only; verify against the target FastGPT release and deployment documentation.

## Three common mistakes
- Generated government service guide attachment sharing links have no identity verification, and can be directly accessed by unauthorized personnel. This is caused by not configuring the `FILE_TOKEN_KEY` parameter and not enabling the link authentication logic.
- Embedding model loading fails, with an error message of insufficient video memory returned in the logs. This is caused by not connecting to GPU resources allocated by GPUStack, and not matching the video memory requirements of the bge-m3 model.
- The marker container fails to start, and cannot parse PDF attachments of government service guides. This is caused by not correctly building the marker Docker image, or omitting necessary system dependency packages.

## How to confirm the configuration is complete
- Log in to the FastGPT management backend, check whether parameters such as `STORAGE_S3_ENDPOINT`, `REDIS_URL`, and `MONGODB_URI` match the configurations of corresponding government cloud services.
- Upload a test government service guide PDF, trigger a vectorization task, and check whether there are error messages such as insufficient video memory or model loading failure in the running logs.
- Generate a sharing link for a service guide, click the link to verify that unauthorized users cannot access the document, confirming that the authentication logic is effective.
- Manually trigger a comparison task between the superior catalog and the local implementation list, check whether there are field missing alarm prompts after the task is completed, confirming that the verification logic is running normally.

The values provided here are common starting points and should be measured against the reader's own samples.
