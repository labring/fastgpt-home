# Party Building Learning Q&A for Government Service Item Catalog and Service Guide Maintenance: Sharing and Embedding

## What this category of data looks like
Data mainly comes from the national basic catalog of government service items, administrative licensing item list, power and responsibility list, and local government service item databases, with a monthly update frequency. Daily maintained documents include the basic catalog of government service items, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions. Core fields include item codes, acceptance conditions, application material lists, etc. There is no fixed unified unit format, and corresponding specifications need to be matched according to item categories.

## What constraints these characteristics impose on the "sharing and embedding" link
The business data of government service item catalogs and service guides is updated monthly. The embedded Q&A content needs to regularly synchronize the latest maintained item information to avoid inconsistent service standards between online and offline channels. The data includes multi-dimensional business fields, so embedding configuration needs to limit the recall scope to prevent irrelevant content from interfering with Q&A accuracy. Since the data involves internal government rules, the embedding scenario needs to restrict access permissions to prevent unauthorized scenarios from calling sensitive business content. At the same time, the maintenance work of this category involves item verification. The embedded answers must fully match the latest item information, otherwise business rectification risks may arise.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `shareId` | Exclusive identifier corresponding to the government service item knowledge base | Used to locate the exclusive Q&A knowledge base, ensure that shared content matches the currently maintained business data, and avoid cross-category calls |
| Embedded window height | 600–800 pixels | Adapt to the conventional layout of government document pages, accommodate item lists and Q&A interaction areas, and avoid page overflow that affects reading |
| Context recall count | Top 3–5 items | Government data has many fields, limiting the recall count can avoid interference from irrelevant content and focus on core business fields such as item codes and acceptance conditions |
| Answer cache duration | 7200 seconds (2 hours) | Government data is updated monthly. The cache duration is shorter than the update cycle to ensure that embedded content does not lag behind the latest maintained item information for a long time |
| Authentication mode | Internal domain whitelist | Government data belongs to internal sensitive business content. Restricting embedded domains prevents unauthorized scenarios from calling, ensuring business data security |

## Three common mistakes
- Symptom: The top title of the embedded host page is forcibly modified and cannot be restored. Cause: The title override configuration of the embedded template is not disabled, and the FastGPT page title is synchronized to the host page by default.
- Symptom: The shared link has no identity authentication, and external users can freely access internal government item data. Cause: The permission verification switch corresponding to `shareId` is not enabled, and the Q&A knowledge base containing sensitive business catalogs is directly shared publicly.
- Symptom: The backend cannot obtain the answer content returned by the model. Cause: The callback interface after embedding is not configured, or the message event listener of the iframe is not correctly bound, and the interaction data from FastGPT is not received.

## How to confirm the configuration is correct
- Open the embedded page, enter government service item questions related to party building, and check that the returned content matches the latest maintained item catalog.
- Access the embedded link from a non-authorized domain, and confirm that the Q&A content cannot be loaded normally or a prompt of insufficient permissions is displayed.
- Check the title of the host page, and confirm that it is not forcibly modified to the FastGPT default title.
- Listen to the message event of the host page, and confirm that the answer data returned by the model can be received after triggering the Q&A interaction.
