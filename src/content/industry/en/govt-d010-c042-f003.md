# Party Building Learning Q&A for Legal Compliance and Major Risk Management: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data for this category comes from enterprise contract management systems, compliance risk databases, law and regulation repositories, case management systems, and reporting platforms.
Daily documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation results.
Data updates occur monthly.
Documents contain fields such as risk category, review opinion, and investigation conclusion.
No unified fixed unit exists. Corresponding information only matches specific business scenarios.

## Constraints on multi-turn dialogue and prompt engineering
Data is stored across multiple business systems. Multi-turn dialogue must support cross-source associated retrieval of compliance documents from different sources.
Monthly update frequency requires prompt configurations to adapt to regularly synchronized latest regulations and risk data.
Diverse document types require multi-turn dialogue prompts to distinguish calling logic for different documents, such as compliance risk lists and contract review opinions. This ensures the retrieval scope matches the current question.
Errors may involve major legal risks. Truncation and filtering of multi-turn context must strictly match the sensitivity level of compliance data.

## How to set configurations
This document uses FastGPT v4.17.0. The following is the multi-turn dialogue and prompt engineering configuration plan for this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to business department-specific identifiers | Achieve session isolation for legal compliance conversations to avoid cross-department data confusion |
| `messages` | Retain the first 20 rounds of dialogue context | Compliance issues often involve historical review records. Sufficient context improves association accuracy |
| `variables` | Pass document classification tags and update time | Allow the model to prioritize calling compliance data updated in the current month. This adapts to the monthly update rhythm |
| Single recalled document count | Top 3–5 entries | Compliance data requires precise matching. Too many results introduce irrelevant risk information |
| Timeout setting | 600 seconds | Cross-system retrieval of compliance data requires sufficient time to complete calls |
| Question optimization | Enabled | Optimized professional compliance expressions improve retrieval matching accuracy |

## Three common misconfigurations
- Phenomenon: Returns format error prompts when calling the interface, or generated compliance analysis results do not match the preset structure. Cause: Failed to pass correct document classification parameters via `variables`, causing the prompt to fail to match the format requirements of the corresponding data.
- Phenomenon: The online conversation interface displays "Searching knowledge base" for a long time with no results returned. Cause: No reasonable timeout threshold configured. Cross-system retrieval of compliance data exceeds the system response limit without terminating the request.
- Phenomenon: Redundant compliance risk entries appear repeatedly in multi-turn dialogue, and results deviate from the current question. Cause: Did not limit the context rounds of `messages`, causing irrelevant information from historical conversations to be repeatedly included in the model context.

## How to confirm configurations are correctly set
- Initiate a compliance question that includes historical conversation context. Check whether the returned results are associated with the latest compliance data from the corresponding business system.
- Verify that conversations with different session identifiers cannot access each other's context data. This ensures the session isolation configuration takes effect.
- Simulate a cross-system retrieval scenario. Confirm that requests are correctly terminated after timeout, and adjust the threshold according to the response speed of business systems.
- Check whether the generated compliance analysis results match the preset document structure. Perform format adjustments according to prompt rules.

The values provided are common starting points and should be measured against the reader's own samples.
