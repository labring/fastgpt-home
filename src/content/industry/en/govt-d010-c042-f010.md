# Party Building Learning Q&A for Legal Compliance and Major Risk Management: Knowledge Base Retrieval and Recall

## What data looks like for this category
Data for this category originates from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms. The update frequency is monthly. Daily documents include compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation reports. Data fields cover compliance risk level, review opinion number, reporting clue number, case progress status, and similar attributes. No additional statistical units or percentage data are included.

## What constraints these characteristics impose on knowledge base retrieval and recall
Monthly updated data sources require knowledge base synchronization tasks to run monthly. This ensures retrieval content aligns with the latest compliance documents, and prevents outdated data from affecting judgments. Multi-type documents have widely varying text lengths, from short lists to long opinions. Chunking and recall matching logic must be adjusted to adapt to text features of different lengths. Data from multiple systems must undergo pre-filtering using compliance document-specific fields to avoid invalid recall. Since errors may lead to major legal disputes or administrative penalties, retrieval and recall accuracy must be strictly controlled to reduce misrecalled content.

## How to set configurations
These configurations are based on FastGPT v4.17.0, and are adapted to the characteristics of compliance documents for this category.
| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Compliance documents have high semantic similarity requirements to avoid irrelevant content with low matching degrees being recalled |
| `limit` | Top 5–8 entries | Compliance content requires precision. Excessive results increase context processing burden, while covering core relevant documents |
| `searchMode` | Hybrid semantic retrieval + full-text retrieval mode | Compliance documents contain both professional terms requiring semantic matching and clear clause numbers requiring full-text matching. The hybrid mode balances both requirements |
| `usingReRank` | Enabled | Relevance ranking of compliance documents needs higher precision to avoid semantically similar but business-irrelevant content entering final results |
| `datasetSearchUsingExtensionQuery` | Enabled | In the party building learning Q&A scenario, questions require expansion with compliance-related content to improve recall coverage |
| `collectionIds` | Specify knowledge base collection IDs related to compliance and party building | Isolate knowledge bases of different businesses to prevent irrelevant data from mixing into compliance retrieval results |

## Three common misconfigurations
- Phenomenon: Semantic retrieval and full-text retrieval tools return "Connection error" errors. Cause: Access permissions for multi-system data sources are not configured correctly, or the monthly synchronization task has not completed interface docking with the compliance database.
- Phenomenon: The number of knowledge base recall results is far lower than the set upper limit. Cause: The `limit` parameter is not set correctly, or `collectionIds` only binds some compliance document collections and does not cover all data sources.
- Phenomenon: Output content cannot be traced back to specific knowledge base documents. Cause: Traceability configuration is not enabled, or the retrieval logic is not bound to document source fields, making association with original compliance documents impossible.

## How to confirm correct configuration
- Perform a single retrieval test, input a compliance risk-related question, and verify that the document types of returned results match the compliance document list for this category.
- Trigger the monthly synchronization task, check the knowledge base update log, and confirm that documents from the data source have completed synchronization as planned.
- Enable the traceability function, input a compliance-related question for party building learning, and verify that each returned result displays the corresponding original document source.
- Adjust the `similarity` parameter range, and verify that the matching degree of recalled results meets the precision requirements for compliance content.

The values provided here are common starting points and should be measured against the reader's own samples.
