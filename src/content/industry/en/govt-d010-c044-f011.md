# Party Building Learning Q&A for Environmental Law Enforcement and Monitoring Regulation: Forms and Interaction

## What this category's data looks like
Data sources include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Update frequency is daily. Daily documents include on-site inspection records, sampling records, monitoring reports, order for rectification decisions, and administrative penalty decisions. Each document has a different field structure:
On-site inspection records include inspection time, law enforcement officer ID, location name, and operating condition data.
Sampling records include sampling location, sampling time, and sampling personnel information.
Monitoring reports include pollutant concentration, detection method, and determination result.
Law enforcement documents include illegal facts, penalty basis, and other content.

## What constraints these characteristics impose on the forms and interaction link
Multiple data sources lead to differences in field formats. Forms must support data import and mapping from different systems.
High-frequency daily updates require forms to have real-time interaction to avoid data inconsistency caused by cache expiration.
Complex document structures require forms to support custom field binding and template adaptation to meet the needs of different law enforcement scenarios.
Severe consequences of errors require forms to have a pre-verification mechanism to intercept abnormal data and misoperations.
The embedded requirement for party building learning Q&A requires that party building-related prompts and confirmation links be integrated into form interactions to ensure that law enforcement procedures comply with party building requirements.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `formInput` | Bind the first 8 core fields of on-site inspection records and sampling records | This category has a large number of document fields. Prioritize binding core fields frequently used in law enforcement and monitoring, which complies with the form binding rules of FastGPT v4.17.0 |
| `formInput` | Set to automatically verify field formats during data import | This category has severe consequences of data errors, and automatic verification can intercept import content with abnormal formats in advance |
| `userSelect` | Set to automatically execute the default process after waiting 120 seconds | Law enforcement personnel usually need to briefly confirm detection data during on-site law enforcement procedures, and 120 seconds conforms to conventional operating rhythm |
| `userSelect` | Enable user confirmation pop-ups | Avoid mis-triggering key operations such as generating law enforcement documents and sending rectification notices, which meets the rigor requirements of law enforcement procedures |
| Single interaction timeout | 600 seconds | On-site sampling and data comparison may take a long time, and 600 seconds can cover the time requirements of conventional law enforcement and monitoring procedures |
| Context length | 8000 characters | Adapt to the average length of documents in this category, ensuring complete contextual information for party building learning Q&A |

## Three common mistakes
- Phenomenon: After configuring the `userSelect` module, if the user sends a new message without making a selection, the process cannot proceed normally. Cause: No timeout automatic skip or default selection mechanism is set, resulting in interaction interruption.
- Phenomenon: After binding fields with `formInput`, a large number of empty fields appear when importing third-party test reports. Cause: No cross-system field mapping rules are configured, and the format consistency of imported data is not verified.
- Phenomenon: After configuring the result rearrangement function, the corresponding model cannot be selected, and tool calls fail. Cause: The call permission of the rearrangement model is not correctly configured in the system configuration, or the model parameters do not match the document field length of the current category.

## How to verify the configuration is complete
- Import a simulated on-site inspection record, check whether `formInput` correctly binds core fields such as inspection time and law enforcement officer ID.
- Trigger the `userSelect` module, wait 120 seconds to see whether the subsequent process is automatically executed or whether a timeout prompt pops up.
- Simulate tool call to extract parameters, check whether a user confirmation pop-up appears, and confirm whether subsequent operations are performed normally after confirmation.
- Import a simulated data with abnormal format, check whether an automatic verification prompt is triggered to confirm that the verification mechanism is effective.
