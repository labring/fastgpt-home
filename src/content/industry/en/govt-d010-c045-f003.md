# Party Building Learning Q&A for Land Pre-examination and Planning Permit: Multi-turn Dialogue and Prompt Terms

## What the data for this category looks like
Data sources for land pre-examination and planning permit related content include the national land and space planning one-map platform, project approval and supervision platform, current land use database, and ecological protection red line data. Updates occur on an irregular basis. Daily business documents include land pre-examination and site selection opinions, construction land planning permits, construction engineering planning permits, red line drawings, and planning conditions. Data fields cover project site selection scope, land use scale, planning control requirements, pre-approval conditions, and other relevant details. Some documents contain mixed content of drawings and tables.

## What constraints these characteristics impose on multi-turn dialogue and prompt terms
Data sources for this category are scattered, and updates have no fixed cycle. Multi-turn dialogue systems must support regular synchronization of the latest planning and approval data to avoid returning outdated control requirements. Document formats vary, including plain text approval files and red line drawings with integrated tables. Prompt terms must adapt to context calls for different formats, and guide dialogue to gradually clarify specific project details. Business errors directly affect project approval and construction startup. Multi-turn dialogue must verify that returned content matches official data sources. It must also guide users to gradually supplement pre-approval information for relevant areas such as development and reform, and housing and urban-rural development, to ensure full coverage of all approval processes.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `messages` | Retain the most recent 20 dialogue turns, with no more than 1500 characters per turn | Documents for land pre-examination and planning permit are lengthy. Excessive historical content will occupy context space. The 1500-character limit balances context completeness and call efficiency, and adapts to the context processing rules of FastGPT v4.17.0 |
| `variables` | Bind two variables: project approval number and red line drawing number, synchronize by default from workspace data | Core data of this category is associated with approval numbers and red line scope. | Maximum context length | 8000–12000 characters | Documents of this category include long texts such as planning control requirements and red line data. Sufficient context supports accurate verification of the match between projects and planning |

## Three common misconfigurations
- Phenomenon: After uploading XLSX format red line drawing data for land pre-examination, the system prompts that the file content cannot be recognized when starting a dialogue, or the returned result does not include the red line data in the file. Cause: The XLSX file is not configured as a supported knowledge base upload format, or the table fields in the file are not correctly bound via `variables`.
- Phenomenon: When calling the dialogue interface, the returned user question field is empty, or the entered question content cannot be obtained. Cause: The user question variable is not correctly configured to be bound via `variables`, or the variable name does not conform to system requirements.
- Phenomenon: After debugging and previewing the dialogue, the historical records of a specified project cannot be cleared via the workspace, or full historical records occupy too much storage space. Cause: The rule for automatically clearing historical sessions by `chatId` is not configured, or the option to retain full historical records is accidentally enabled.

## How to confirm the configuration is correct
- Upload a test XLSX file for land pre-examination, initiate a question including "Check whether the red line of this project conforms to the ecological protection red line", and confirm that the dialogue returned content includes the red line scope data in the file.
- Initiate more than two rounds of dialogue related to the same project, check whether `chatId` remains consistent, and whether the `messages` list retains the dialogue context content from previous rounds.
- View the application configuration page in the workspace, confirm that `variables` have been bound to exclusive fields such as project approval number and red line drawing number, and that the configuration items have been saved and take effect.
- Trigger the historical dialogue clearing operation, enter the `chatId` of the specified project, and confirm that the corresponding session records have been completely deleted.
