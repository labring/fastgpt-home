# Party Building Learning Q&A for Land Pre-examination and Planning Permit: Citation Sources and Traceability

## What the data for this category looks like
Core data for this category comes from the national land spatial planning unified map, project approval and supervision platform, current land use database, and ecological protection redline data. Daily produced documents include land pre-examination and site selection opinion, construction land planning permit, construction project planning permit, redline map, and planning conditions. Documents contain fields such as project subject, land scope, planning control requirements, and approval nodes. Data update frequency is irregular, and synchronization rhythm changes with project approval progress and land spatial planning adjustments.

## What constraints do these characteristics impose on the citation sources and traceability link
The scattered data sources require the traceability link to associate metadata from multiple official platforms, to ensure that cited approval documents fully match original system records. Diverse document types and inconsistent structures require configuring differentiated citation anchor rules for different documents, to avoid confusing field information between redline maps and planning conditions. Irregular data updates require verifying the latest synchronization status of data sources before each Q&A, to prevent citing expired planning control data. Additionally, errors in this category directly affect project approval, so the traceability link must retain a complete citation trail to facilitate subsequent verification.

## Three common misconfigurations
- Setting too small a value for `quoteMaxToken` results in truncated approval document citations, with the "incomplete cited content" error displayed in the interface. This occurs because the average length of single documents in this category is not matched, and insufficient token space is reserved to carry complete land scope and planning indicator information.
- Failing to filter redundant metadata for the party building learning scenario results in internal interface fields of the project approval and supervision platform appearing in responses. This occurs because non-essential `responseData` sub-items are not disabled, exposing internal system information.
- Not configuring citation hiding rules in workflow calls results in original content of knowledge base search input and response being displayed in answers. This occurs because rules for only displaying final answers and compliant citations are not set, and intermediate tool call information is retained by mistake.

- Initiate a land pre-examination related question for party building learning, check if the citation list at the end of the response includes the corresponding document type and source platform name.
