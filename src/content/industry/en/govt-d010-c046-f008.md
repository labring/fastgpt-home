# Party Building Learning Q&A for Social Assistance and Minimum Living Security Review: Document Parsing and Chunking

## What This Category of Data Looks Like
Data sources for this category include the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-departmental shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Update frequency is monthly.

Daily documents include minimum living security application forms, family economic status verification reports, household investigation forms, democratic appraisal records, public notice materials, and assistance approval forms. Data fields focus on family economic status, member relationships, and assistance eligibility. Some documents are non-editable PDFs scanned after offline completion, some are structured Excel files, with no unified standard formatting.

## Constraints Imposed on Document Parsing and Chunking
Monthly batch-updated data requires the parsing process to support batch task processing, to avoid timeouts caused by loading excessive data in a single run. Mixed structured data from cross-departmental sharing and unstructured offline-scanned documents requires parsing logic adapted to different formats.

Fields related to family economic status have strong interconnections. Chunking must retain context association between fields to avoid losing complete information required for eligibility judgment after splitting. Offline-scanned documents may have messy formatting, missing characters, and other issues. Basic OCR parsing adaptation is required to ensure accurate extraction of core fields.

## Configuration Settings
The following configurations are based on the functional logic of FastGPT v4.17.0, adapted to the document characteristics of this category:

| `chunkSettingMode` | Manual configuration | Customizes chunking rules based on the field characteristics of documents in this category, adapts to the requirement of retaining context related to family economic status |

## Three Common Misconfigurations
- Phenomenon: After uploading an Excel-format family economic status verification report, the data processing section shows empty. Cause: Excel structured parsing configuration is not enabled, or file column fields do not match system preset rules.
- Phenomenon: Parsing tasks time out and fail during batch import of monthly summary data. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is set too low, not adapted to the overall processing duration of batch data.
- Phenomenon: Vectorization processing speed is slow. Cause: `chunkSize` is set too large, or batch parsing queue is not enabled, leading to excessive load on single-task processing.

## How to Verify Proper Configuration
- Upload a single minimum living security application form PDF, check if the parsed text blocks retain complete context of applicant information and family income fields.
- Batch import monthly summary Excel data, confirm that there are no empty field errors in the data processing section, and that the number of imported records matches the actual count.
- Adjust the `chunkSize` configuration, test whether the length of chunked text meets the information density requirements of business documents.
- Trigger a parsing task, confirm that the `PARSE_FILE_TIMEOUT_SECONDS` configuration does not trigger a timeout error.

The values provided are common starting points and should be evaluated against local sample data.
