# Party Building Learning Q&A for Social Assistance and Minimum Living Security Review: Model Access and Configuration

## What data for this category consists of
This category covers standardized documents related to civil affairs assistance and cross-department shared data. Daily documents include minimum living security application forms, family economic status verification reports, household survey forms, publicity materials, and similar items. Data sources are the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data. The update frequency is once per month. Data fields include family income and property status, family member information, and content related to application eligibility. The structure aligns with standardized civil affairs business processes.

## What constraints these characteristics impose on model access and configuration
Access to cross-department multi-source data requires adaptation to unified format standards, to avoid model recognition errors caused by differences in data fields. The monthly data synchronization requirement means configuration items must support regular incremental or full update rules. Standardized civil affairs documents and scanned materials require the model to have text and visual recognition capabilities, to ensure the accuracy of material review. Strict requirements for family privacy and assistance eligibility mean the randomness of model output must be limited, to ensure the compliance and consistency of judgment results.

## Three common configuration mistakes
- Phenomenon: The interface cannot select domestic large models such as Tongyi Qianwen, or returns an error that the model does not exist during calls. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not configured correctly, or the permissions of the corresponding model are not bound in the platform.
- Phenomenon: After uploading a scanned household survey form, the model returns empty recognition results. Cause: The `vision` configuration item is not enabled, or the required image transmission format is not used.
- Phenomenon: The minimum living security eligibility judgment generated by the model has deviations, and the family income field is incorrectly matched. Cause: The `temperature` value is too high, or the `maxContext` setting is insufficient, and complete cross-department shared data is not loaded.

## How to confirm successful configuration
- Initiate a test call to verify the configuration of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, and confirm that the interface returns normal model responses.
- Upload a standard minimum living security application form scan to verify whether the `vision` configuration takes effect, and whether the model can correctly extract core fields from the form.
- Import a monthly updated family economic status data set to test whether the `maxContext` and `quoteMaxToken` configurations can fully load and process long-text content.
- Adjust the `temperature` parameter to 0.2, initiate multiple calls for the same question, and confirm that the consistency of the output results meets expectations.
