# Party Building Learning Q&A for Social Assistance and Minimum Living Security Review: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Core data for this category comes from the civil affairs system’s internal low-income population dynamic monitoring platform and resident family economic status verification system. It also includes cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax authorities, and other relevant departments.
Daily business documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms.
Data is updated monthly. Fields focus on family economic status, member relationships, and assistance eligibility.
No unified standardized units are used. Corresponding fields must be matched using cross-department data sources.

## What constraints these characteristics impose on knowledge base retrieval and recall
Differences in cross-department shared data field formats require precise multi-source field matching in knowledge base retrieval.
Monthly updated assistance policies and verification rules need regular knowledge base synchronization to prevent outdated content from being retrieved.
Documents related to family economic status and member relationships include structured and semi-structured content. Differentiated retrieval matching rules must be set for these.
Non-standardized text from household surveys and public notice materials requires fuzzy matching and context-aware recall adaptations.
Assistance eligibility review has high-risk attributes. Retrieval results must have traceable source references to avoid irrelevant content interfering with judgment.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Precise matching of policy clauses is required for family economic status verification, to avoid low-confidence results interfering with assistance eligibility review |
| `limit` | `Top 10` | Assistance review requires covering multi-dimensional verification rules; excessive recall results increase the processing burden of grassroots staff |
| `searchMode` | `Semantic + keyword hybrid retrieval` | Cross-department data contains structured fields and non-standardized business text; hybrid mode balances precise matching and context-aware recall |
| `usingReRank` | `Enabled` | Multi-source recall results must be sorted by relevance to improve visibility of key policies and verification requirements |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Grassroots staff questions may use simplified phrasing; optimization enables matching more precise knowledge base content |
| `collectionIds` | `Bound to dedicated knowledge base collections containing party building learning and civil affairs assistance content` | Must cover civil affairs assistance-related policies and business documents from party building learning, to prevent irrelevant content from being included in retrieval results |

## Three common errors
- Symptom: Knowledge base retrieval returns empty results, the interface displays no matching content and no fallback prompt. Cause: No fallback logic for the `similarity` threshold is configured. When all retrieval results have a similarity score lower than the set value, no default return or prompt is triggered.
- Symptom: In the same conversation window, subsequent questions do not trigger the knowledge base retrieval link. Cause: Forced retrieval configuration is not enabled, or the conversation context is not correctly associated with the current knowledge base collection, causing the workflow to skip the retrieval step.
- Symptom: After initiating multiple rounds of questions in the conversation window, knowledge base retrieval latency increases significantly. The same question runs faster in a new window. Cause: The storage length of conversation context is not limited, or automatic cleanup of session cache is not enabled, causing each retrieval to load excessive historical context and redundant data.

## How to confirm the configuration is complete
- Upload dedicated documents related to civil affairs assistance and party building learning to the corresponding knowledge base collection, initiate a query containing keywords related to minimum living security verification or party building-related civil affairs policies, and confirm that retrieval results only include content from this collection.
- Adjust the `similarity` threshold to 0.6, initiate a query with low matching accuracy, and confirm whether empty results or preset fallback prompts are triggered.
- After enabling `usingReRank`, compare the order of retrieval results before and after enabling, and confirm that high-priority policy and verification requirement content is displayed first.
- Initiate consecutive multiple rounds of questions, monitor retrieval latency, and confirm there is no continuously increasing delay.
