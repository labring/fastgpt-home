# Administrative Licensing and Approval Party Building Learning Q&A: Multi-turn Dialogue and Prompt Words

## What This Category of Data Looks Like
The data for the administrative licensing and approval scenario comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate database. The update frequency is daily. Commonly involved documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision letters, license certificates, etc. The document structure is centered on statutory licensing items, including standardized fields such as item name, legal basis, handling conditions, process steps, and there are no additional custom non-statutory fields.

## What Constraints Do These Characteristics Impose on the "Multi-turn Dialogue and Prompt Words" Link
The official sources and daily update frequency of the data require the dialogue system to synchronize the latest licensing item list to avoid referencing expired clauses. The standardized document structure requires multi-turn dialogue to strictly match statutory basis and handling conditions, and cannot arbitrarily expand non-statutory content. Electronic certificate data retrieved across departments must be accurately associated with the corresponding approval items during dialogue, while ensuring that the context of each round of dialogue does not exceed the boundaries of the current approval item, preventing confusion of handling requirements for different licensing items. In addition, the consequences of errors are linked to administrative compliance, requiring that dialogue results must be supported by clear statutory basis.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk length | 800–1200 characters | Matches the paragraph length of documents such as service guides and legal basis, avoiding splitting the complete logic of statutory clauses |
| Overlap length | 100–200 characters | Retains cross-chunk handling condition and process association information to ensure coherent context during multi-turn dialogue |
| Single search limit | Top 5 entries | Aligns with the limited statutory basis scope of administrative licensing items, filtering redundant information interference |
| Maximum context | 4000–6000 tokens | Adapts to the length of approval process history records during multi-turn dialogue, avoiding exceeding model context limits |
| Reference content template | Spliced in the format of "item name + basis clause + handling requirements" | Matches the statutory verification logic of administrative licensing approval, ensuring answers closely follow compliance requirements |
| `messages` | Append system prompts and user questions by dialogue turn | Ensures each round of dialogue carries the latest approval item context, conforming to the interaction logic of multi-turn dialogue |

## Three Common Misconfiguration Issues
- Phenomenon: Significant differences between online dialogue and API call return results. Cause: The historical dialogue context of the `messages` parameter is not correctly carried in the API request, or the specified administrative licensing knowledge base is not bound
- Phenomenon: Answers deviate from compliance requirements due to confusion between prompt word and knowledge base reference template configuration. Cause: The distinction between prompt word role settings and reference content format specifications is not clearly defined, resulting in reference data not being spliced according to the approval scenario
- Phenomenon: Newly created administrative licensing knowledge base cannot be associated. Cause: The association relationship of the corresponding knowledge base is not bound in the dialogue configuration, or the binding configuration between the knowledge base and the application is not completed via the API

## How to Confirm Successful Configuration
- Initiate a single-turn dialogue, enter a question about a specified administrative licensing item, and check whether the returned content includes service guides or statutory basis clauses from the knowledge base
- Initiate a multi-turn dialogue, add subsequent related questions, and check whether the system retains the previously mentioned approval item context without context loss
- Call the API interface, pass the `messages` parameter carrying historical dialogue records, and check that the returned result is consistent with the output of the online dialogue
- View the knowledge base synchronization log, confirm that the latest administrative licensing item data has been synchronized at the daily update frequency, with no synchronization failure records
