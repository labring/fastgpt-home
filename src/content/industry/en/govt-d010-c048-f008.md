# Administrative Licensing and Approval Party Building Learning Q&A: Document Parsing and Chunking

## What the data for this category looks like
Data for the administrative licensing and approval scenario comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate repository. The update frequency is daily. Daily documents include service guides, application forms, acceptance notices, correction notifications, administrative licensing decision documents, and license certificates. The structure includes fields such as legal item number, handling conditions, legal basis, and handling procedures. All fields follow standardized legal formats, with no custom units.

## What constraints do these characteristics impose on the "document parsing and chunking" link?
High-frequency daily updated data requires the parsing link to maintain a stable and efficient processing rhythm, to avoid data delays affecting approval progress. Standardized legal document structures require that chunking must fully retain core fields such as legal basis and handling conditions, and must not split and damage legal logic. Documents from multiple sources include multiple types such as HTML, PDF, and structured text. Some non-standard formats may not be recognized by the default parsing engine, requiring targeted configuration. Electronic certificate packages retrieved across departments may have large file sizes, requiring sufficient time for parsing and chunking.

## How to set the configurations
The following configuration items are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting/Rationale Input | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Core content such as legal basis and handling conditions in administrative licensing documents has concentrated length. This range can fully retain the complete logic of a single legal clause |
| `chunkSplitter` | Split by title + paragraph | Administrative licensing documents have clear title hierarchies such as item number and handling conditions. Splitting by title ensures coherent chunking logic |
| `customPdfParse` | Enabled | Most PDF documents for administrative licensing are official layouts. Enabling custom parsing retains document structure and legal fields |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Electronic certificate packages retrieved across departments and batch service guide documents require sufficient parsing time to avoid timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch upload of electronic certificate packages, avoiding interception due to excessive file size |
| `chunkSettingMode` | Manual mode | Manual adjustment of chunking parameters is required to meet the legal logic chunking requirements for administrative licensing documents |

## Three common misconfigurations
- Uploading a Java interface document with a renamed file extension (changed to txt format) results in no parsing result. The default parsing engine only recognizes legal document formats in the administrative licensing scenario, and renamed code files cannot be correctly matched and parsed.
- After using chunk mode to call the pushdata API for upload, the interface keeps showing indexing. `PARSE_FILE_TIMEOUT_SECONDS` is set too short, or `chunkSize` is too large, causing chunking timeout and incomplete indexing.
- Uploading an HTML interface document generated by Javadoc results in no parsing result. The default HTML parsing engine does not recognize the structured interface document structure in the HTML, only parses plain text content, and cannot extract interface fields.

## How to confirm the configuration is correct
- Upload a standard administrative licensing service guide PDF, review the parsed chunked content, and confirm that core fields such as legal basis and handling conditions are fully retained in a single chunk.
- Upload a service guide summary renamed to txt format, review the number of parsing results, and confirm it meets expectations.
- Use chunk mode to call the pushdata API to upload a test document, confirm that the indexing status is completed within 600 seconds, with no timeout errors.
- Upload an HTML interface document generated by Javadoc, review whether the parsing result includes interface fields, and confirm that the custom parsing configuration is effective.

The values provided are common starting points and should be measured against the reader's own samples.
