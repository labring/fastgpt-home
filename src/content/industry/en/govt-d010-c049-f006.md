# Party Building Learning Q&A for Legality Review of Regulatory Documents: Citation Sources and Traceability

## What Data for This Category Looks Like
The data for this category comes from the regulatory rule database, higher-level law database, departmental policy document database, and administrative regulatory document filing system, with an irregular update frequency. Daily processed documents include regulatory document drafts, drafting explanations, legality review opinions, solicited opinion summaries, and filing reports. The length of individual documents varies widely, from hundreds of characters to tens of thousands of characters. Each document contains fixed fields such as document number, drafting unit, review process records, and solicited opinion entries. There is no unified fixed word count standard for individual documents, and they must be imported completely in accordance with the original file format.

## Constraints on the Citation Sources and Traceability Link
Data sources are scattered and updates are irregular. The citation traceability link must ensure each retrieval matches the latest version of the filed document. This avoids citing expired drafts or review opinions.
Document lengths vary widely. Retrieval must distinguish between draft text and supporting explanatory documents. This prevents mistakenly using drafting explanations as legality review basis.
Each document has fixed fields. These fields provide a unique identifier for traceability. Field matching must confirm the authenticity of the cited document. This prevents cross-category document confusion.
Errors directly affect policy release and filing compliance. The traceability link must clearly mark the original source database and document number for each cited entry. This supports subsequent verification.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific configuration items are listed below:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Adapt to the average length of individual regulatory document files, to ensure complete citation of the original review basis text |
| `responseData` | Enable source field return | Extract identifiers such as the cited document number and source database, to complete traceability labeling |
| `detail` | Enable detailed traceability mode | Display the original file path and review node information for each cited content |
| Single recall limit | Top 6 entries | Cover the number of higher-level law and policy basis required for a single review, avoid redundant retrieval |
| Chunk overlap length | 200–300 characters | Match the paragraph structure of regulatory document articles, prevent chunk breaks across articles |
| Document type filter | Only retain drafts and review opinion documents | Exclude non-review-related documents such as solicited opinion summaries, narrow the retrieval scope |

## Three Common Misconfigurations
- Phenomenon: Some imported regulatory documents do not generate Q&A pairs. They are stored directly in the knowledge base as original text chunks. Cause: Automatic Q&A generation configuration for long documents is not enabled. The system only completes text chunking without generating associated Q&A pairs.
- Phenomenon: An error is prompted when testing after configuring the model. The formal retrieval link works after forced ignoring. Cause: The test interface does not support long context input for compliance documents. Only the formal retrieval link is compatible with long text calls.
- Phenomenon: Only one citation result is returned when retrieving in the workspace. The system prompts "Knowledge Base Citation (1 item)". Cause: The single recall limit is set to 1, or the traceability switch for multi-document associated matching is not enabled.

## How to Confirm Proper Configuration
- Import a standard regulatory document draft. Check the knowledge base chunk list. Confirm chunks are split by article, with no broken chunks across articles.
- Launch a Party Building Learning Q&A query. Check the citation traceability module below the answer. Confirm each cited content is labeled with the document number, source database, and specific paragraph location.
- Adjust the single recall limit to 6. Launch a query involving multiple higher-level law and policy basis. Confirm the number of returned citation results matches the configured value.
- Test Q&A generation after importing a long document. Confirm generated Q&A pairs match the core review basis content of the original text, with no key information missing.

The values listed above are common starting points, and should be evaluated against the reader’s own samples.
