# Party Building Learning Q&A for Regulatory Document Legality Review: Forms and Interactions

## What this category's data looks like
The data for this category primarily comes from the regulatory and rule repository, higher-level law database, departmental policy document repository, and administrative normative document filing system. Updates occur at irregular intervals.
Daily processed documents include normative document drafts, drafting explanations, legality review opinions, solicited opinion summaries, and filing reports. A single document usually includes title, document number, drafting entity, main body content, and related attachment fields. There is no unified fixed unit field.
Core content focuses on the authority, procedures, and text legality of policy formulation. This data serves legal government construction-related Q&A scenarios in party building learning.

## Constraints on the forms and interactions link
Data sources for this category are scattered, and updates follow no fixed schedule. The forms and interactions link must support uploading the latest regulations, filing data, and documents awaiting review at any time. This adapts to real-time learning needs for policy legality in party building learning.
Daily processed document types are diverse. The interaction interface must distinguish input fields for different document types, such as normative document drafts and solicited opinion summaries. This matches their respective content structures.
The core review link requires comparing higher-level laws with documents awaiting review. The form must support associated upload and parameter binding for both types of files.
Errors directly affect policy release and implementation. The interaction must add required field validation and content format prompts. This prevents missing core review materials.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Single upload limit of 10 files, maximum single file size of 200 MB | Administrative normative document filing systems typically have single-file capacity limits; multi-file upload adapts to batch submission of review materials |
| `userSelect` | Preset drafting unit and review post options, supports manual supplementation | Daily processed documents always include the drafting entity field; preset options reduce repeated data entry and format errors |
| Input component type | Supports multi-file upload + custom field collection | Daily processed documents cover multiple types, requiring collection of additional information such as document number and drafting unit |
| Context window length | 8000–12000 token, calibrated via actual testing | The main body of a single normative document draft is usually lengthy, requiring adaptation for context transmission of complete text |
| Maximum return results | Top 8 matching results | Core review prioritizes matching core provisions of higher-level laws; limiting results focuses on effective review information |
| Timeout setting | 600 seconds | The link comparing higher-level laws and summarizing public opinions takes a long time, requiring sufficient processing time reserved |

## Three Common Configuration Mistakes
- Phenomenon: The uploaded normative document draft does not appear in the context preview area of the large model conversation. The model cannot complete legality review using the uploaded file. Cause: The `formInput` component is not bound to the conversation's context input channel. Only form collection is configured, and no model call parameters are associated.
- Phenomenon: Matching results returned after form submission include many irrelevant policy documents unrelated to higher-level laws. Cause: The matching data source range for `userSelect` is not restricted. No exclusive regulatory and rule repository or higher-level law database is bound. This leads to irrelevant content being recalled.
- Phenomenon: The uploaded solicited opinion summary file cannot be fully parsed. The system prompts that the content is too long. Cause: A reasonable input character limit is not configured. Automatic chunking processing is not enabled. Long text cannot be fully transmitted to the model.
