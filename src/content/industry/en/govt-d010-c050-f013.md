# Party Building Learning Q&A for Fiscal Expenditure Performance Evaluation: Sharing and Embedding

## What the data for this category looks like
This category's data originates from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. Daily documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports. Data is updated annually. Each individual document contains both structured and unstructured content such as performance indicators, fund usage details, and output effect records. Most fields are directly related to fiscal fund usage and project outputs.

## Constraints for the "Sharing and Embedding" Workflow
The annual update frequency means the embedded knowledge base only needs to trigger synchronization once per year, with no need for frequent updates. Differences in structure across multiple document types mean the embedding configuration must use differentiated chunking rules for different documents such as performance reports and self-assessment forms. For data sourced from cross-system platforms, the embedded page’s call permissions must match the original data permissions during sharing. For the party building learning Q&A scenario, the embedded Q&A robot must strictly limit retrieval to the exclusive data of fiscal expenditure performance evaluation to prevent irrelevant output.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Embedded page permission settings | Only accessible via internal IP, or bound to specified department user groups | Fiscal performance data involves sensitive information, so access scope must be strictly controlled |
| `shareId` binding scope | Only bound to the exclusive knowledge base for fiscal expenditure performance evaluation | Ensure Q&A only retrieves business data for this category, meeting the targeted requirements of party building learning Q&A |
| Knowledge base update trigger cycle | Once per year, triggered after the annual performance report is submitted | Match the annual data update frequency to avoid redundant synchronization |
| Retrieval result matching threshold | 0.75–0.85, calibrated via actual testing | Balance retrieval accuracy and recall rate, adapting to the precision requirements of performance-related queries |
| Context window length | 8000–12000 token | Accommodate the full content of long documents such as performance reports and self-assessment forms, ensuring coherent Q&A logic |

## Three Common Configuration Errors
- No Q&A robot displays on the embedded page, and the console reports that the `shareId` field is empty. This occurs because the `shareId` parameter for the corresponding knowledge base was not correctly bound, or key characters were omitted during parameter copying.
- Q&A responses include non-fiscal performance-related party building content. This occurs because the `shareId` binding scope was not restricted, and a general party building knowledge base was incorrectly combined with the performance knowledge base in the configuration.
- Structured data per row is split across multiple paragraphs after automatic chunking. This occurs because the row-by-row chunking rule was not configured for Excel-format performance documents, and the default automatic segmentation logic was used instead.

## How to Verify the Configuration Is Correct
- Access the embedded page and check if the Q&A input box and historical conversation area load normally.
- Enter a query related to fiscal expenditure performance evaluation, and confirm that the returned results only contain business data for this category.
- Trigger the knowledge base update operation, and check if synchronization completes according to the preset cycle without abnormal errors.
- Test unauthorized access to confirm that users without bound permissions cannot use the Q&A function on the embedded page.
