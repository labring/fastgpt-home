# Party Building Learning Q&A for Department Final Accounts and Financial Reports: Source Citation and Traceability

## What data in this category looks like
Data in this category comes from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. The update cycle is annual. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Fields include income and expenditure details, asset and liability balances, budget execution difference explanations, and more. Units are mostly ten thousand yuan or yuan. Document structure strictly follows unified formatting standards set by fiscal departments.

## What constraints these characteristics impose on source citation and traceability
The annual update cycle requires the knowledge base to complete full data synchronization each year, to avoid mixing cross-period data. The multi-system source characteristic requires traceability to link original data identifiers from different systems, ensuring citations can be traced to specific systems and submission nodes. Unified document structure with detailed fields requires precise chunking by report unit or paragraph, to avoid cross-document citation misalignment. Many fields involve sensitive content such as income and expenditure, assets, so traceability must clearly mark corresponding document types and specific entries to ensure citation compliance.

## How to set the configuration
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Department final account documents have high information density per paragraph, need to control cited content length to avoid exceeding LLM context limits |
| `responseData` | Enable traceability mode | Party building learning Q&A requires clear marking of data sources to meet fiscal information compliance requirements |
| `detail` | Display original document identifier | Need to link specific submission nodes from sources such as the budget management integrated system to ensure traceability |
| Single recall limit | Top 3–5 entries | Department final account documents have unified structure, relatively few accurately matched related entries, excessive citations will interfere with Q&A accuracy |
| Context length | 4000–6000 characters | Need to retain association information between Q&A context and cited documents to ensure traceability logic is coherent |

## Three common errors
- Citation documents are not displayed in the official chat interface, only visible in the debug page. Cause: The traceability display switch corresponding to `responseData` is not enabled, or traceability detail display at the `detail` level is not enabled in the configuration.
- The number of citations exceeds the expected value, and results are not returned per the set single recall limit. Cause: Recall rules are not configured correctly, or the LLM automatically adds irrelevant context content.
- Cited content is misaligned with original text fields. Cause: Chunking is not done per fiscal document report units or fixed paragraphs, leading to cross-entry information being combined in citations.

## How to confirm configuration is complete
- Navigate to the debug page, submit party building-related department final account questions, and check whether returned results include cited document identifiers and source information.
- Adjust the single recall limit value, verify if the number of returned citation entries matches the set value.
- Trigger annual data synchronization, check if the knowledge base includes the latest department final account documents.
- Check the token consumption of LLM returned content, confirm it does not exceed the `quoteMaxToken` configuration limit.
