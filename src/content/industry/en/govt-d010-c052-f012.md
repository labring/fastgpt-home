# Party-building study Q&A for department final accounts and financial reports: Deployment and Upgrade

## Data characteristics of this category
Data for this category comes from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. The update frequency follows an annual cycle. Daily documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Data fields include unit identifiers, income and expenditure details, assets and liabilities items, budget execution difference explanations, and other related items. Data units must align with the measurement rules of the corresponding source system. There is no universal unified data unit.

## Constraints for deployment and upgrade processes
Annual update frequency requires reserving configuration space for historical data archiving and batch import during deployment, to avoid storage overflow during annual data updates. Multiple system data sources require verifying the connectivity and permission configuration of each system interface during the deployment phase. Upgrades must maintain compatibility with legacy system docking logic. Diverse document structures require setting differentiated parsing rules for different document types such as final account statements and explanations. Upgrades must retain parsing compatibility logic for legacy documents. No unified data unit requires configuring unit mapping rules during deployment, to prevent measurement ambiguity during Q&A. Additionally, requirements linked to party-building study Q&A require building association indexes between financial data and the party-building knowledge base during deployment.

## Configuration guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `DB_MAX_LINK` | 800–1200 items | Aligns with the association index requirements for annual batch financial documents, avoids overly long single query chains |
| `MONGODB_URI` | Configured using the intranet address of the deployment environment | Stores vectors and metadata for annual financial documents, adapts to batch data writing requirements |
| `PG_URL` | Configured using the database address connected to the financial system | Stores unit mapping rules and historical archived data, ensures data consistency |
| `REDIS_URL` | Configured using the intranet cache service address, timeout set to 600 seconds | Caches temporary data from cross-system interface calls, shortens response time during annual data updates |
| `STORAGE_S3_ENDPOINT` | Configured using the intranet object storage address | Stores original files of annual final account documents, ensures data security and access efficiency |
| `ROOT_KEY` | Configured according to deployment permission rules | Restricts access permissions for administrator upgrade operations, ensures system security |

## Three common configuration errors
- Phenomenon: When the upgrade trigger script runs, the POST /api/admin/initv4818 request returns a 404 status code, with a duration of 76ms. Cause: The `ROOT_KEY` permission was not configured correctly during deployment, or the upgrade script’s interface path does not match the current FastGPT version.
- Phenomenon: Token consumption exceeds expectations when party-building study Q&A links financial data. Cause: The `DB_MAX_LINK` limit on association link length was not set, leading to bulk loading of redundant financial document data.
- Phenomenon: When connecting funasr for financial document speech transcription, tool interface calls fail. Cause: Intranet access permissions were not enabled in the `STORAGE_S3_ENDPOINT` configuration, preventing the tool from reading original document files.

## How to verify successful configuration
- After the upgrade script is executed, the system backend’s interface logs are reviewed, the `/api/admin/initv4818` request is confirmed to return a normal status code, and the upgrade configuration is verified to take effect.
- After a single annual final account document is imported, a party-building-related Q&A query is initiated, the returned results are confirmed to not include redundant data, and the `DB_MAX_LINK` configuration is verified to be reasonable.
- The cross-system data docking interface is called, the unit mapping rules are checked for normal effectiveness, and the `PG_URL` configuration is verified to be correct.
- The frontend address corresponding to `FE_DOMAIN` is accessed, the system interface is confirmed to normally load associated content between financial documents and the party-building knowledge base, and the frontend configuration is verified to be correct.

The values given are common starting points and should be measured against the reader's own samples.
