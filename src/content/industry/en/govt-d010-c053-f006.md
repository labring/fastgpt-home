# Party Building Learning Q&A for Department Budget Preparation: Citation Sources and Traceability

## What Data for This Category Looks Like
Typical entities include finance bureau budget offices, budget unit finance departments, and similar roles. Daily generated documents include department budget drafts, project application letters, performance target forms, personnel expense calculation forms, budget approvals, and more. Data mainly comes from the unified budget management system, department staff establishment system, prior-year final accounts, project library, and budget preparation notices issued by the Ministry of Finance. The update frequency is annual. Most documents are in structured table format, containing fields such as budget code, project name, expenditure amount, and performance target. There are slight differences in data formats across different sources.

## Constraints Imposed on Citation Sources and Traceability
The annual update frequency requires the knowledge base to perform full data synchronization on a regular basis, to avoid mismatches between old data and the latest policies. The structured document format requires the retrieval step to accurately match field information, to prevent vague retrieval from causing cited content to deviate from business scenarios. Multi-source data requires clear identification of source types, to distinguish internal business system data from official notice content during traceability. Additionally, individual documents are relatively long, so the total amount of retrieved context must be controlled. This prevents exceeding the large model's token limit, which would affect the completeness and accuracy of responses.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | Department budget preparation documents are relatively long per copy; sufficient context must be retained to cover complete budget project information, while avoiding exceeding the model's context limit |
| Retrieval result upper limit | Top 6 entries | The core document count for this category is concentrated; too many retrieval results will increase the large model's processing burden and easily lead to redundant citations |
| Similarity threshold | 0.75–0.85 (calibrated via actual testing) | Balance retrieval relevance and completeness; avoid missing key budget data due to an overly high threshold, or introducing irrelevant content due to an overly low threshold |
| `responseData` | Enabled | Citation sources must be bound to specific fields of the original document, to ensure direct positioning of the corresponding document during traceability |
| `detail` | Enabled | Core fields of the cited document must be displayed in the response, to facilitate verification of content rationality and accuracy |

## Three Common Mistakes
1. The number of returned cited documents far exceeds expectations. Failure to configure the retrieval result upper limit, or setting the similarity threshold too low, retrieves a large number of non-core budget calculation forms.
2. The response does not use the top-ranked content from the knowledge base. Failure to enable the reranking function, or failing to sort retrieval results by document update time, causes old data to be displayed first.
3. Unable to verify the rationality of cited content. Failure to enable the `responseData` configuration item, failing to bind citation sources to fields such as budget code and project name of the original document, prevents extraction of specific information for verification.
