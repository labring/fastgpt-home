# Party Building Learning Q&A for Flood Prevention, Disaster Mitigation and Emergency Duty: Citation Sources and Traceability

## What Data for This Category Looks Like
This category's core data comes from two types of channels. First, emergency management-related systems: weather warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Second, party building learning-related documents: emergency duty party building study manuals, flood prevention and disaster mitigation party building presentation materials, and similar materials. The data update frequency is daily.

Daily generated documents include duty records, warning notices, consultation minutes, rapid disaster reports, emergency response plans, material allocation slips, and party building learning-style emergency duty standard documents. Each document has exclusive dedicated fields: warning notices include warning level and effective time fields; material allocation slips include allocation order number and material quantity fields; party building learning documents include learning topic and issuing unit fields. All data is stored as natural language text or structured fields, with no unified fixed format.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Link
Multi-source and heterogeneous data sources require the traceability link to clearly mark the data category and system, and distinguish emergency business data from party building learning materials to avoid confusion.

The daily update frequency requires citations to prioritize the latest warning, disaster data, and latest party building learning content, to prevent outdated information from affecting learning and decision-making.

The diverse document types and large field differences require the traceability link to distinguish the exclusive fields of different documents, such as the issuing unit of party building learning documents and the allocation order number of emergency material allocation slips, to ensure accurate traceability information.

The real-time requirement in emergency scenarios requires cited content to be concise, transmit valid information within a limited length, while meeting the content integrity requirements of party building learning.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `quoteMaxToken` | 800–1200 characters | Matches the average length of a single valid segment of emergency and party building learning documents, avoids overflowing the conversation window with spliced content |
| `responseData` | Return all associated data sources | Covers both emergency business and party building learning data sources, meets the traceability needs of party building learning Q&A |
| `detail` | Enabled | Displays exclusive document fields, such as the issuing unit of party building learning documents and the effective time of emergency warnings, improving traceability accuracy |
| Single recall citation count | Top 3–5 entries | Adapts to the information conciseness requirements of party building learning and emergency duty scenarios, avoids excessive citations interfering with core judgment |
| Citation similarity threshold | ≥0.7 | Filters low-relevance non-emergency and non-party building content, ensures cited content highly matches the query |
| Source system marking switch | Enabled | Clearly marks the data category and system, helping users quickly distinguish between emergency business and party building learning sources |

## Three Common Misconfigurations
- Phenomenon: The number of citations returned in a conversation exceeds the set upper limit. Cause: The `quoteMaxToken` parameter is not configured correctly, causing the system to not limit the length of spliced citation content, or the recall logic does not truncate results according to the configuration.
- Phenomenon: Non-emergency and non-party building citation content is returned during mixed retrieval. Cause: No data source classification filtering rules are configured, causing the recall scope to exceed the preset emergency and party building learning data sources.
- Phenomenon: Citation sources are still displayed when there are no matching emergency or party building learning documents locally. Cause: The default citation display for empty results is not turned off, or unused general knowledge base data sources are retained.

## How to Verify Correct Configuration
- Import a test emergency warning notice document and a party building emergency duty study manual. Launch a query including "latest flood prevention warnings and party building duty standards" in the FastGPT v4.17.0 environment, and verify that the returned citations are marked with the source system and issuing unit respectively.
- Adjust the `quoteMaxToken` parameter to 600 characters. Launch a query containing long-text emergency content, and verify that the returned citation content does not exceed the set character length.
- Disable the hydrological monitoring system data source. Launch a query including "hydrological monitoring data", and verify that citations from the disabled data source are not returned.
- Launch a query with no matching emergency or party building learning content, and verify that no citation sources are displayed, or empty result prompts are displayed according to the configuration.
