# Party Building Learning Q&A for Flood Prevention, Disaster Mitigation and Emergency Duty: Document Parsing and Chunking

## What the data for this category looks like
Typical data sources for this category include meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance.
Daily documents cover duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips.
The update frequency is daily.
Document structures vary significantly. Duty logs mostly contain single duty entries. Warning notices include structured fields such as warning level and effective time period. Material allocation slips include clear unit information such as material name, quantity, and allocation location.

## What Constraints Do These Characteristics Impose on Document Parsing and Chunking?
Heterogeneous documents from multiple sources require parsing logic to adapt to different formats. Mixed imports of structured Excel and semi-structured PDF need accurate identification of entry boundaries to avoid content sticking together.
High daily update frequency means bulk fast import support is required. File size limits and parsing timeout settings must match business bulk import requirements.
Documents with clear fields and unit information require that chunking does not destroy key information units. For example, do not split material names and their corresponding quantities into different chunks. This will affect the accuracy of subsequent Q&A.

## Configuration Settings
The following configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density and information length of flood prevention-related documents, avoiding splitting that disrupts key units such as warning levels and response measures |
| `chunkSplitter` | Custom delimiters (line breaks, "Warning", "Consultation Minutes", and other identifiers) | Adapts to the feature that documents in this category are mostly segmented by event/entry, solving issues of single-line merging in Excel and paragraph sticking in PDF |
| `customPdfParse` | Enabled | Adapts to multi-source PDF format warning notices and consultation minutes, retaining original typesetting structure to reduce parsing errors |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the upper limit requirements for batch files such as rapid disaster reports and material allocation slips imported in a single batch |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for long-duration consultation minutes and multi-page rapid disaster reports, avoiding mid-process interruptions |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types (such as Excel, PDF, plain text) to adapt to the differentiated structures of emergency-related documents |

## Three Common Configuration Mistakes
- Phenomenon: Multiple lines of content are merged into a single chunk after Excel import, making one-entry-per-line impossible. Cause: `chunkSplitter` is not configured to use line breaks, and the default chunking logic does not identify single-line entry boundaries.
- Phenomenon: A specific knowledge base cannot retrieve chunks that exactly match the queried content, but a newly created knowledge base works normally. Cause: Parsing fails for some specially formatted rapid disaster reports when `customPdfParse` is not enabled, resulting in loss of key matching fields.
- Phenomenon: Information from individual PDF documents cannot be extracted separately after multiple PDFs are uploaded. Cause: `chunkSettingMode` is not set to split by document, and the default logic merges all document content, making it impossible to distinguish individual document entries.

## How to Verify Proper Configuration
- Upload a single structured Excel test file. Check if each cell corresponds to an independent chunk, and verify that chunk boundaries meet expectations.
- Upload a specially formatted PDF warning notice. Check if the parsed text retains key information such as original warning level and effective time period.
- Import batch documents. Check the timeout logs of parsing tasks to confirm there are no timeout errors.
- Enter a test query that exactly matches chunk content. Verify that the retrieval results include the target content.

The values provided here are common starting points and should be evaluated against the reader's own samples.
