# Party Building Learning Q&A for Flood Prevention, Disaster Mitigation and Emergency Duty: Model Access and Configuration

## Data Profile for This Category
Data sources include meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance.
Processed daily documents include duty records, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. These documents contain fields such as rainfall and water level values, warning levels, response time limits, material categories and quantities.
Data updates daily. Some real-time early warning data updates more frequently.
Data supports real-time emergency response. Its structure adjusts to fit specific scenarios. It must include core information required for cross-department scheduling.

## Constraints on Model Access and Configuration
Multi-source heterogeneous data sources require configuration to support multiple interface connections and format conversions. This prevents parsing failures caused by field differences across systems.
Diverse document types require context window configuration to cover varying lengths of consultation minutes, rapid disaster reports and other content. This prevents core response information from being truncated.
Daily data updates require setting reasonable synchronization cycles in configuration. This avoids data lag impacting early warning responses.
Real-time emergency response scenarios require model call response speeds to match emergency timelines. Configuration must also restrict tool call scope. This prevents unrelated operations from interfering with core processes.

## How to Set Configurations
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Meets length requirements for multiple document types including consultation minutes and rapid disaster reports, prevents core response information from being truncated |
| `maxTokens` | 2000–3000 token | Satisfies generation length needs for emergency consultation materials and early warning notices, while controlling response time per single call |
| `temperature` | 0.3–0.5 | Balances standardization for party building learning Q&A and accuracy of emergency information, reduces probability of generating irrelevant content |
| `toolChoice` | auto | Automatically adapts to multi-source data call requirements, supports on-demand retrieval of rainfall and water level, material allocation and other information |
| `AIPROXY_API_ENDPOINT` | Fill in the actual deployed proxy address | Ensures model requests are forwarded through compliant proxies, adapts to internal network access restrictions |
| `AIPROXY_API_TOKEN` | Valid key bound to the proxy platform | Ensures identity verification security for interface calls, prevents unauthorized access |

## Three Common Configuration Mistakes
- A `Tool call Parser n` error occurs during calls. The cause is that reasoning content is wrapped in think tags and placed in the content field. This does not comply with FastGPT tool call format requirements.
- Long error codes appear when forwarding model requests via aiproxy. The cause is incorrect configuration of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`. This leads to proxy connection failure or failed identity verification.
- A `chat: llm—model—response-empty` error appears when calling the workflow. The cause is that the model does not return valid response content. This may be due to excessively low `maxTokens` setting causing content truncation, or insufficient context window configuration triggering an exception.

## How to Confirm Configuration Is Complete
- Test calls for flood control emergency questions related to party building learning. Verify that returned content includes correct warning levels, response processes and other information.
- Check parsing results after multi-source data access. Confirm that fields from different systems are correctly identified and integrated.
- Simulate tool calls in emergency scenarios. Verify that the model can on-demand retrieve rainfall and water level, material allocation and other relevant information.
- Review proxy logs. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations are working correctly, with no connection errors.
