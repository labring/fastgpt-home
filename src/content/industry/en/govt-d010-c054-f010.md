# Party Building Learning Q&A for Flood Prevention, Disaster Mitigation and Emergency Duty: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data for this category mainly comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Daily documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Most fields contain rainfall and water level values, warning levels, response time limits, material quantities and units, and other information. The data update frequency is daily. Some real-time warning documents have higher update frequencies.

## Constraints imposed by these characteristics on the knowledge base retrieval and recall link
Multi-source heterogeneous data sources require the retrieval chain to support associated recall of cross-system data, avoiding information silos. The wide range of document types, from short warning notices to thousands-word response plans, requires adaptation to different length text chunking and recall logic. The daily update frequency requires the knowledge base synchronization mechanism to have real-time performance, ensuring retrieval results include the latest warning and response information. Fields contain numerical values and units, so precise matching of units and numerical ranges is required during retrieval to prevent scheduling errors caused by parameter mismatches. In the party building learning Q&A scenario, both emergency business documents and party building-related duty specifications must be recalled to meet dual retrieval needs.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the precise matching requirements of flood prevention data, avoiding false recall of irrelevant rainfall and water level information |
| `limit` | Top 8 entries | Covers multi-department collaborative emergency documents while controlling context length |
| `usingReRank` | Enabled | Optimizes the relevance of recall results for multi-source heterogeneous warning and response documents |
| `datasetSearchUsingExtensionQuery` | Calibrated based on actual testing | Adapts to the mixed retrieval needs of party building and emergency business, balancing recall scope and precision |
| `collectionIds` | Exclusive ID corresponding to the emergency duty party building knowledge base | Limits retrieval scope to avoid mixing documents from unrelated categories |

## Three common errors
- Phenomenon: Empty results or permission errors are returned when pulling the document library via API. Cause: `collectionIds` is not correctly specified as the ID of the corresponding emergency duty party building knowledge base, causing the retrieval scope to exceed the preset boundary.
- Phenomenon: After upgrading FastGPT v4.17.0 in a private deployment, clicking the knowledge base file details displays the "Invalid dataset file key" error. Cause: The storage key associated with the dataset was not updated synchronously during the upgrade, so the system cannot match the original file's storage path.
- Phenomenon: When using paragraph chunking and enabling model recognition, the relevance of recall results to party building learning questions is insufficient. Cause: The `similarity` threshold is set too low, resulting in a large amount of irrelevant hydrological monitoring raw data being mixed in, or `datasetSearchUsingExtensionQuery` is not optimized for party building semantics, failing to associate emergency and party building content.

## How to confirm the configuration is correct
- Initiate a test retrieval, input emergency duty-related questions about party building, and check whether the recall results cover emergency documents and party building learning materials.
- View the knowledge base synchronization logs to confirm that daily updated warning and consultation documents have been successfully synchronized to the retrieval library.
- When calling the API interface, check whether the `collectionIds` in the returned results match the preset knowledge base ID.
- Adjust the `similarity` threshold and compare retrieval results to confirm that the relevance of recall results meets business requirements.

The values provided are common starting points and should be measured against the reader's own samples.
