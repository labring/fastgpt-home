# Party Building Learning Q&A for Flood Prevention, Disaster Mitigation and Emergency Duty: Sharing and Embedding

## What this category of data looks like
The party building learning Q&A for flood prevention, disaster mitigation and emergency duty scenarios processes daily documents including duty records, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources cover meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Data updates typically occur daily. Some real-time early warning data is pushed synchronously. Data fields include millimeter-level rainfall values, wind speed in meters per second, transferred and resettled population counts, material allocation tons, early warning levels, and more. Data formats vary across sources: some are structured reports, others are unstructured text records.

## What constraints these characteristics impose on the sharing and embedding link
Data sources involve multiple business systems, and the data includes sensitive information such as real-time early warnings and scheduling. The sharing and embedding link requires strict identity authentication mechanisms to prevent unauthorized access. The daily data update feature requires the embedded Q&A knowledge base to match the update rhythm. This ensures returned content is up to date. Differences in document formats and data fields require the embedded Q&A system to support retrieval and integration of multiple data types. It must also adapt to the need for rapid access to key information in emergency scenarios. Errors in emergency duty scenarios directly affect personnel safety and resource scheduling. This makes session stability and mobile adaptation requirements for the embedding link more prominent. Binding a dedicated knowledge base via `shareId` effectively isolates Q&A data across different business scenarios.

## How to set the configurations

## Three common mistakes
- Issue: After configuring the sharing link, no identity authentication related settings are found, and authentication cannot be enabled. Cause: The sharing authentication switch was not enabled on the dedicated knowledge base management page bound via `shareId`. Configuring only in global settings without binding a specific knowledge base will not work.
- Issue: After embedding FastGPT backend via iframe, the login status frequently expires or logs out directly. Cause: No same-origin site whitelist was configured, cross-domain requests cause session tokens to be cleared, or the session validity period was set too short and does not match the actual usage duration of emergency scenarios.
- Issue: The embedded Q&A robot fails to display the input box properly or has layout disorder on mobile devices. Cause: The mobile adaptation configuration was not enabled, and no viewport adaptation parameters were set, leading to abnormal page scaling that cannot adapt to mobile device screen sizes.

## How to confirm configurations are complete
- Copy the generated sharing link, access it without logging in, check if an identity authentication popup appears. Verify that normal access to Q&A content is possible after entering valid identity information.
- Deploy the iframe embedding code to an internal test site. Keep the session logged into FastGPT backend, refresh the page or switch function modules, check if the login status remains stable.
- Use a mobile device to access the page with the embedded Q&A robot, check if the Q&A input box adapts to the screen width, and if reply content is properly formatted without overlapping.
- View the knowledge base sync logs, confirm that the daily automatic sync task at 2:00 AM has completed without abnormal errors, and that the returned updated data matches the business system data.
