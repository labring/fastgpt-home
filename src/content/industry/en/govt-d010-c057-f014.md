# Food Safety Supervision Sampling Party Building Learning Q&A: Conversation Logs and Auditing

## What This Category’s Data Looks Like
Data for this category primarily comes from food safety sampling monitoring systems, the national market supervision administration sampling result query system, testing institution LIMS, and food producer and operator ledgers. Update frequency is monthly. Core documents include sampling plans, sampling slips, inspection reports, unqualified food verification and disposal reports, and risk control announcements. Data uses sampling tasks as the only associated dimension. It includes fixed fields such as sampling location, inspection items, and disposal results. No extra custom statistical numbers are included.

## Constraints on Conversation Logs and Auditing
Monthly updated data sources require auditing cycles to align with the monthly sampling rhythm. Teams must retain full process conversation records.
The document structure that uses sampling tasks as the only associated dimension requires logs to bind unique identifiers such as `chatId`. This allows linking to core evidence like sampling slips and inspection reports.
Mixed calls of multi-source data require audit logs to cover original input and output for all conversation links. This prevents missing key content related to unqualified food disposal.
The strict consequences of unqualified food disposal require audit logs to have traceability. They cannot be modified or deleted arbitrarily.

## Configuration Settings
These configurations follow the rules of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chatId` | Bind to sampling task number | Matches the category's core association logic centered on sampling tasks. Can directly link to documents such as sampling slips and inspection reports |
| `responseChatItemId` | Bind to inspection report number | Corresponds to the unique identifier of the category's core evidence. Facilitates quick location of conversations related to unqualified food disposal during audits |
| `detail` | Enable full log recording | Covers full process conversation content including sampling plan formulation, sampling, inspection, and disposal. Meets audit traceability requirements |
| Conversation log storage period | 30 days | Matches the monthly update frequency. Meets traceability requirements for monthly audits |
| High-risk conversation audit filter count | Top 5 entries | Focuses on conversations related to unqualified food disposal. Improves audit efficiency |
| Single conversation log character limit | 1200 characters | Adapts to the average length of sampling-related documents. Prevents log overflow |

## Three Common Misconfigurations
- Symptom: Console logs from workflows cannot be viewed in front-end checks. Only the conversation log panel shows no corresponding records. Cause: Workflow logs are not synchronized to the audit storage module. Only temporary front-end caching is retained.
- Symptom: When multiple users use the application, they cannot view their own exclusive historical conversations. All logs are displayed merged together. Cause: The user-associated sampling task identifier is not bound via `chatId`. Permission isolation rules are not configured.
- Symptom: Conversations created via API have empty Human fields in the response preview. Cause: Full field recording for the `detail` parameter is not enabled. Original user input content is not correctly passed.

## How to Verify Configurations
- Initiate a conversation related to a sampling plan. Check if the bound sampling task number is included in the logs. Verify that the `chatId` configuration takes effect.
- Use different accounts to initiate conversations. Confirm that each account can only view its own initiated conversation records. Verify permission isolation configuration.
- Call the API to create a conversation. Check if the Human field in the response preview contains the original input content. Verify the `detail` parameter configuration.
- View the audit panel. Confirm that the log storage duration matches the set 30-day period. Verify storage configuration.
- Initiate a conversation containing content related to inspection report association. Check if the inspection report number bound by `responseChatItemId` is included in the logs. Verify that this configuration takes effect.
