# Survey and Design Industry Party Building Learning Q&A: Model Access and Configuration

## What this category of data looks like
Data sources include learning materials archived in the internal party building management system, policy documents released by the party committee office, and branch study records. Updates are triggered synchronously with superior party building work requirements. Daily study updates are compiled and released quarterly. Most documents are structured long texts, with fields including title, issuing entity, release date, core study points, and applicable scope. Each document covers topics combining party building theory and industry compliance requirements.

## What constraints these characteristics impose on model access and configuration
The structured long text format of the data requires model access to support long context processing, to avoid truncating key points that combine party building theory and industry compliance. The non-fixed update schedule requires configuring a knowledge base synchronization process that supports both manual triggers and quarterly scheduled updates. Multi-field metadata requires associating metadata with main content in the model, to improve the accuracy of Q&A matching. The normative requirements for party building content require constraining the rigor of model output wording, to align with the style of official party building documents.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Party building documents for survey and design units often combine industry compliance requirements, with relatively long content. A sufficient context window is needed to cover complete learning materials and associated metadata to avoid truncating key information |
| `temperature` | `0.1–0.3` | Party building Q&A needs to align with official expressions, reducing generation randomness to ensure rigorous and standardized outputs |
| `quoteMaxToken` | `2000–3000 token` | Sufficient original content must be retained as the basis for Q&A to ensure that the referenced party building document content is complete and accurate |
| `toolChoice` | `auto` | Some party building Q&A needs to associate industry party building cases or policy documents. Automatic tool calling can improve matching efficiency |
| `AIPROXY_API_ENDPOINT` | Unit-specific proxy address | Ensure internal party building data is not leaked externally, complying with data security and compliance requirements for state-owned enterprises and public sector entities |
| `AIPROXY_API_TOKEN` | Token configured according to unit key management rules | Verify legitimate access permissions and prevent unauthorized interface calls |

## Three common misconfigurations
- Symptom: After configuring the MCP plugin in the workflow, no tool call results are returned when triggering party building Q&A. Cause: Tool call permission is not enabled in the `toolChoice` configuration, or the MCP plugin is not associated with the corresponding workflow node.
- Symptom: The classification accuracy of party building questions is low, and party building questions combined with industry compliance cannot be recognized. Cause: The model prompt has not been adjusted for party building-specific issues in the survey and design industry, or scenario-appropriate classification parameters have not been configured.
- Symptom: After enabling the speech recognition function, the interface prompts that the browser does not support speech input. Cause: The correct voice service proxy has not been configured in FastGPT v4.17.0, or the browser has not been granted microphone permissions.

## How to confirm the configuration is complete
- Upload a long party building document containing industry compliance content, initiate a Q&A to verify that the model does not truncate core content, and confirm that the `maxContext` configuration takes effect.
- Initiate a question combining industry party building requirements, verify that the model output aligns with official expressions, and confirm that the `temperature` configuration takes effect.
- Configure the MCP plugin and associate it with the workflow, initiate a party building question that requires tool calls, and verify that the tool call results return normally.
- Test speech input in a browser that supports microphone permissions, and verify that the interface prompt indicating the browser does not support speech input disappears.
