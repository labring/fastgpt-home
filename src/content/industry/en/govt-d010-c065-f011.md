# Party Building Learning Q&A for Survey and Design: Forms and Interactions

## What this category of data looks like
Party building learning data in the survey and design field comes primarily from daily learning records of temporary project party branches and institutional party branches, as well as superior party building documents.
Data updates follow a monthly cycle, with monthly archiving of that month’s branch learning records.
A single document includes these fields: affiliated project number, branch name, learning topic, learning time, participant employee ID, learning duration, original learning content, and sign-in screenshot link.
Field units include "person", "hour", and "copy".
The platform supports uploading files in formats such as Excel sign-in sheets and PDF learning minutes.

## Constraints on Forms and Interactions
The affiliated project number field must link to the project management library. The form must support dropdown selection to prevent project number mismatches from manual input.
Participant employee IDs must sync with internal personnel system data. The form must integrate single sign-on for associated data retrieval to reduce manual entry errors.
Uploaded sign-in sheets and learning minutes require format and size restrictions. This adapts to scenarios where a single survey and design ledger includes multiple pages of sign-in records.
The learning duration field needs numeric validation and unit locking to block non-numeric input.
The form must also support filtering associated branches by project to fit decentralized party building across multiple projects.

## Configuration Settings

| --- | --- | --- |
| `formInput` | Configured for the fields: affiliated project number, learning topic, learning time, participant employee ID, learning duration, sign-in screenshot link | Adapts to the fixed field structure of survey and design party building ledgers |
| `userSelect` | Linked to internal personnel system to synchronize employee ID list | Avoids errors in manual entry of participant information |
| Upload file size limit | 100–200 MB | Adapts to scenarios where a single ledger contains multiple pages of sign-in screenshots and long minutes |
| Batch import toggle | Enable batch upload mode | Adapts to centralized archiving requirements for monthly multi-branch learning records |
| Form field validation | Lock learning duration to numeric type, with unit fixed to hour | Ensures data format compliance |
| Submission trigger condition | Trigger after all required fields are completed | Ensures no missing archived data |

## Three Common Configuration Mistakes
- Phenomenon: Uploaded Excel sign-in sheets are not read by the large language model for statistical summarization. Cause: File parsing binding for `formInput` is not enabled, causing uploaded files to only be stored as attachments and not integrated into the conversation context.
- Phenomenon: The conversation window becomes unresponsive after party building learning data entered in the form exceeds the threshold. Cause: The input character limit for `formInput` is not configured, or the limit is set too low to adapt to long ledger content.
- Phenomenon: Pre-filled form field content is lost after resizing the browser window. Cause: Local cache configuration for the form is not enabled, so pre-filled input content is not restored during page redraw.

## How to Verify Successful Configuration
- Fill out a test party building learning record. After submission, check if form fields automatically validate format, for example, whether learning duration only allows numeric input.
- Upload a test file containing multiple pages of content, check if upload progress and file size match the preset limits.
- Attempt to batch import a test Excel file, check if fields are automatically recognized and batch submission is completed.
- Resize the browser window, check if pre-filled form content remains intact and is not lost.
