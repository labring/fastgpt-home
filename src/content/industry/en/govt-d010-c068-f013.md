# Party Building Learning Q&A for Pharmaceutical Distribution: Sharing and Embedding

## What the data for this category looks like
Party building learning data in the pharmaceutical distribution field comes from three main sources: industry party building policy documents issued by higher-level party committees, internal party building work minutes of enterprises, and party building learning question banks related to pharmaceutical distribution compliance. The data update rhythm is weekly synchronization of higher-level policy updates, and monthly updates of internal learning activity records and question banks. The document structure follows standard official document formats, including fields such as document number, issuing unit, release date, and applicable scope. The size of a single document mostly falls within the 100–500 KB range. Each entry in the question bank contains three core fields: question, standard answer, and associated policy number. This page’s configuration instructions are written based on FastGPT v4.17.0.

## What constraints do these characteristics impose on the sharing and embedding link
The formal nature and industry-specific attributes of pharmaceutical distribution party building learning data impose clear constraints on the sharing and embedding link. First, the data contains party building compliance content exclusive to the pharmaceutical distribution industry, so the knowledge base scope must be limited during embedding to avoid disclosure of unauthorized information. Second, documents and question banks have clear metadata fields, so embedded pages must synchronously display information such as issuing unit and release date to ensure content traceability. Third, data updates follow a fixed weekly or monthly schedule, so shared links must support syncing the latest content to avoid outdated information. Fourth, most pharmaceutical distribution party building content is used for internal sharing scenarios, so enterprise internal identity authentication must be bound to prevent access by unrelated external personnel.

## Three Common Misconfigurations
- Phenomenon: The main application console reports an error after iframe embedding, prompting that the iframe actively interrupted execution. Cause: The main application domain name was not added to FastGPT's cross-origin whitelist, and the cross-origin policy blocked the embedding request.
- Phenomenon: The AI and user avatars in the login-free window cannot be modified. Cause: The custom avatar permission was not enabled in the sharing configuration, or the uploaded avatar file size exceeded the 1000 KB limit.
- Phenomenon: After embedding the FastGPT backend via iframe, the user logs out immediately after logging in. Cause: The cross-origin session sharing function was not enabled, or the main application's session domain name does not match the FastGPT embedding domain name, resulting in session invalidation.
