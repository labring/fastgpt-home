# Party Building Learning Q&A for Power Generation Groups: Citation Sources and Traceability

## What this use case’s data looks like
All data sources for party building learning Q&A in power generation groups come from the group’s internal official party building documents. These include policy documents released by the Party Committee Propaganda Department, grassroots party building work records, and annual study plan compilations. The data updates on a fixed schedule, and adjusts synchronously with the release of new party building policies and updates of internal group study materials. Documents follow standard official document format, with fixed fields including document number, issuing department, release date, and main text. The length of individual documents varies widely. Some policy interpretation documents can reach tens of thousands of characters.

## What constraints these characteristics impose on the citation sources and traceability link
The official document attribute of party building documents requires the traceability link to accurately bind metadata. This avoids disconnecting cited content from its source. The fixed update schedule requires knowledge base synchronization configuration to match the release cycle. This ensures recalled content uses the latest version. Document fields such as document number and issuing department must be fully retained in the traceability link. This meets compliance requirements for party building studies. The structural characteristics of long documents require the citation link to reasonably control single-segment citation length. This avoids truncation of key policy expressions. It also requires recalled chunked content to cover complete knowledge points.

## How to set the configurations
The following table lists configuration items, recommended settings, and their rationales:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.6–0.8 | Filter irrelevant interfering content while retaining valid recall results related to party building policies |
| Maximum Number of Recalls per Request | Top 8 entries | Cover common multi-knowledge point needs in party building Q&A, avoid excessive redundant recalled content |
| `quoteMaxToken` | 1200–1500 token | Accommodate key policy paragraphs of single party building documents, avoid truncating core expressions |
| `responseData` | Bind document number, issuing department fields | Fully retain metadata to meet traceability compliance requirements for party building studies |
| `detail` | Enable format rendering | Automatically render markdown format into readable display effects, align with standard usage habits |

The above configurations are based on FastGPT v4.17.0.

## Three Common Configuration Mistakes
1. Phenomenon: After initiating a party building Q&A, the source list only displays content fragments, without metadata such as document number and issuing department. Cause: The `responseData` binding for imported metadata fields is not configured, leading to lost traceability information.
2. Phenomenon: After adjusting the maximum number of recalls per request parameter, the number of recalled content entries does not change and remains fixed. Cause: Knowledge base chunking rules do not match the chapter boundaries of party building documents, so the system cannot recall more independent valid chunks.
3. Phenomenon: Output content appears as markdown source code, without being rendered into normal typesetting. Cause: The format rendering configuration for the `detail` parameter is not enabled, or the prompt word does not clearly specify rendering requirements.

## How to Confirm Configuration Is Complete
- Initiate a Q&A related to party building policies, check the source list at the end of the reply, and confirm that each source includes metadata such as document number and issuing department.
- Adjust the similarity threshold to different ranges, observe whether recalled source content changes with the threshold, and verify that the parameter takes effect as expected.
- Check the knowledge base synchronization log, confirm that fields such as document number and release date of party building documents have been correctly imported and bound to the index.
- Check the configuration status of the `detail` parameter, confirm that the format rendering switch is enabled, and verify that the output format meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
