# Party Building Learning Q&A for Power Generation Groups: Document Parsing and Chunking

## What the data for this category looks like
Data for power generation group party building learning Q&A comes from internal party building work documents, records of three regular party branch meetings and one party lecture session, study materials for themed party day activities, documents conveying superior party building policies, and compilations of party members' study reflections. Update frequency follows party building work milestones. Monthly learning plans are added each month, special party building reports are updated quarterly, and important policy releases are synchronized immediately. Document formats are mainly PDF and Word, with some structured tables. Fixed fields include document title, issuing department, release date, and content theme. Individual document lengths range from a few pages to dozens of pages.

## What constraints these characteristics impose on document parsing and chunking
Party building documents contain a large number of specialized terms and fixed phrases, such as three regular party branch meetings and one party lecture session, themed party day activities, and two core party leadership safeguards. Chunking must avoid splitting complete phrases. A high share of documents are long, with individual files exceeding 100 pages. Parsing processes often face timeout issues. Some documents include structured tables and hierarchical headings. Parsing must retain the original structure to preserve content relevance. Data updates happen frequently, so the system must support fast parsing and synchronization of batch documents. It must also avoid content fragmentation during Q&A matching caused by improper chunking rules.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Aligns with the paragraph length of party building documents, avoids splitting specialized terms or complete policy entries |
| `chunkSplitter` | Paragraph + semantic segmentation | Matches the chapter structure of party building documents, retains content relevance |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for long party building reports, prevents mid-process interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatibility with large documents such as group-level party building manuals |
| `customPdfParse` | Enable structured parsing | Retains title hierarchy and table content in PDFs, avoids garbled text or format loss |
| `trainingType` | Q&A pair matching mode | Ensures retrieval results return original content from the knowledge base |
| `chunkSettingMode` | Manual configuration | Supports adjustment of chunking rules for party building specialized terms |

## Three common mistakes
- Symptom: Parsing result is empty or shows garbled text after uploading a party building PDF. Cause: Structured parsing via `customPdfParse` is not enabled. The default parsing cannot recognize the exclusive header, footer, or table format of group party building documents.
- Symptom: Parsing fails after uploading a document, and the system returns a timeout prompt. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. Parsing time for long party building reports exceeds the default threshold.
- Symptom: Unable to customize post-parsing JS methods to adapt to the exclusive format requirements of party building documents. Cause: The custom parsing script function is not enabled in system configurations, or the script file path is not correctly associated.

## How to confirm the configuration is complete
- Upload an internal group party building policy PDF, check whether the title hierarchy and table content in the parsing result are fully retained.
- Manually adjust the `chunkSize` parameter, upload a test document containing specialized terms such as three regular party branch meetings and one party lecture session, confirm that the chunking result does not split complete phrases.
- Upload a preset party building Q&A pair document, verify that the retrieval result fully matches the original content, with no additional generated content.
- Upload a maximum-specification party building manual file, confirm that the upload and parsing process does not trigger file size limits or timeout errors.
