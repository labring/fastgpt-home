# Party Building Learning Q&A for State-owned Asset Management Companies: Knowledge Base Retrieval and Recall

## What this category of data looks like
Party building learning Q&A data for state-owned asset management companies comes primarily from normative documents issued by the group’s party committee, learning records from subsidiary company branches, party building guidance manuals released by the State-owned Assets Supervision and Administration Commission, and internal party member learning archives.
Data updates follow a fixed schedule: important policy documents are updated in a concentrated batch once per month. Temporary learning materials are added to the repository immediately upon release.
Each individual document uses a standardized structure: title, issuing entity, release date, main content, plus a classification tag field. Some documents include supporting learning interpretation attachments. Attachment fields are uniformly standardized into three categories: document number, applicable hierarchy, and core theme.

## Constraints on Knowledge Base Retrieval and Recall
Official party building policy sources require retrieval to prioritize official documents issued by the State-owned Assets Supervision and Administration Commission and the group’s party committee, and avoid non-standard internal materials.
The monthly update cycle requires vector database synchronization to align with the update frequency, to ensure recalled content stays timely.
The applicable hierarchy field on documents requires retrieval to support filtering results by group or subsidiary level, to eliminate cross-level invalid content.
Individual documents may include long main content and interpretation attachments. Retrieval must automatically associate attachment content, while supporting filtering by document type.
Standardized classification tags narrow retrieval scope and improve result accuracy.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | `0.75–0.85` | Party building content is rigorous and standardized, requiring a high matching threshold to filter irrelevant content and ensure the relevance of recalled results |
| `limit` | `Top 8–12 entries` | Party building Q&A needs to cover multi-dimensional policy basis, while controlling the total context length to avoid exceeding model limits |
| `searchMode` | `vector+keyword` | Party building content includes both professional terminology and fixed keywords. Hybrid retrieval balances semantic matching and accurate keyword recall |
| `usingReRank` | Enabled | In scenarios with long documents and multiple classification tags, re-ranking corrects initial sorting bias from vector retrieval, improving the rationality of result priority |
| `datasetSearchUsingExtensionQuery` | Enabled | Party building questions often include policy abbreviations. Extended queries can match full-name documents and formal expressions, improving recall coverage |
| `collectionIds` | Specify exclusive party building knowledge base collection ID | Isolate party building data from other business data, avoiding interference from irrelevant content on retrieval results |

## Three Common Configuration Mistakes
- Phenomenon: Retrieval results include non-party building business documents, or invalid entries with empty fields. Cause: The `collectionIds` setting to specify an exclusive party building knowledge base collection is not configured, so retrieval spans irrelevant business data.
- Phenomenon: Generated responses only summarize the question, and do not reference specific retrieved policy clause content. Cause: `datasetSearchUsingExtensionQuery` is not enabled. Complete document main text fragments are not recalled, only chunked short summaries are used.
- Phenomenon: Single retrieval response takes over 20 seconds on hardware with 8 cores, 64GB memory, and an RTX2070 GPU. Cause: `limit` is set too high, or the initial vector recall count is not controlled, leading to hardware resource overload.

## How to Verify Proper Configuration
- Submit party building-related test questions. Check if the source collection of retrieval results matches the preset party building knowledge base, to confirm `collectionIds` is active.
- Review generated responses to confirm they include specific clause content from retrieved documents. This verifies the combined effect of `datasetSearchUsingExtensionQuery` and chunking configuration.
- Submit the same test question multiple times. Confirm consistent sorting of retrieval results, to verify stability of the `similarity` threshold and re-ranking function.
- Record single retrieval response times, and compare against the conventional response range for the current hardware configuration. Confirm retrieval efficiency meets expectations.
