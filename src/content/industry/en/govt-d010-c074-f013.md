# Party Building Learning Q&A for State-owned Asset Management Companies: Sharing and Embedding

## What the Data for This Category Looks Like
The party building learning data for state-owned asset management companies mainly comes from internal party building archive systems, official documents issued by higher-level party committees, and monthly learning records and reflections from each party branch. The data update rhythm is: higher-level party committee documents are updated synchronously upon release, and branch learning records are collected and archived every quarter. A single document includes five core fields: title, issuing unit, release time, main body, and applicable scope. The units of the fields are character, full name, year-month-day, MB, and department scope respectively. The length of document main bodies varies widely, ranging from hundreds of characters to thousands of characters.

## What Constraints These Characteristics Impose on Sharing and Embedding
The multi-source and decentralized nature of party building data requires sharing links to be linked with identity authentication, to prevent unauthorized users from accessing internal-only party building content. The monthly/quarterly update rhythm requires that the cache duration for embedded pages not be too long, otherwise content lag will occur. Documents include the applicable scope field. Department-based filtering of recall results must be configured in the embedding setup, to ensure that employees from different branches can only access party building materials within their corresponding scope. The wide variation in document lengths requires that context truncation parameters be adapted to documents of different lengths, to avoid context overflow or redundancy issues.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Sharing link authentication method | Enable identity authentication, bind to the company's internal account system | Party building data has internal permission levels, and access by unauthorized users must be restricted |
| `shareId` binding scope | Bind to the exclusive party building knowledge base of the corresponding party branch | Party building data for each branch of state-owned asset management companies is independent, and access permissions must be isolated by department |
| Embedded cache duration | 600 seconds | Party building documents are updated monthly, this duration balances timeliness and page loading speed |
| Mobile adaptation switch | Enable adaptive layout | Employees mostly use mobile devices for learning in party building learning scenarios |
| Context recall limit | Top 8 matching results | Party building documents have a standardized structure, and excessive redundant context will interfere with learning |

## Three Common Misconfigurations
- Symptom: The identity authentication option does not appear in the sharing configuration interface. Cause: The permission control switch for the corresponding knowledge base has not been enabled in the FastGPT backend, or the used FastGPT version is lower than v4.17.0.
- Symptom: The iframe embedded page logs out automatically after login. Cause: The embedded page's domain name has not been added to the allowed cross-origin list, or the cross-domain configuration of the authentication cookie has not been enabled.
- Symptom: The embedded Q&A robot cannot display the input area normally on mobile devices. Cause: The mobile adaptive layout configuration has not been enabled, or custom styles have overridden responsive display rules.

## How to Verify the Configuration is Complete
- Copy the generated sharing link, access it with an unauthorized account, check whether a permission verification prompt pops up or access is directly denied.
- Open the embedded page on a mobile device browser, check whether the input box and reply area of the Q&A robot adapt to the screen size, with no horizontal scrolling or element overlap.
- Wait for the configured cache duration, then refresh the embedded page, check whether the latest party building document content is loaded.
- Open the sharing management page in the FastGPT backend, check whether the configuration status of the corresponding `shareId` is displayed as enabled.
