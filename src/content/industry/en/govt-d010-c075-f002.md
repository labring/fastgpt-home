# Party Building Learning Q&A for State-owned Capital Investment Companies: Vector Models and Indexes

## What the data for this category looks like
The party building learning data for state-owned capital investment companies mainly comes from internal party building resource libraries, policy documents issued by superior party committees, daily branch study records, party member study ledgers, and other sources. Document structures include fixed fields such as document title, issuing unit, release date, main body content, affiliated branch or management unit. Common units of measure are pieces, articles, and characters. The data update rhythm is irregular: bulk new content is added when new policies are issued or quarterly study plans are updated, and scattered study notes and notification documents are also supplemented on a daily basis.

## What constraints these characteristics impose on the vector models and indexing link
Multi-source heterogeneous party building documents with structured metadata require vector indexes to bind metadata fields, enabling precise traceability during subsequent Q&A. Irregular bulk updates and scattered new additions require support for incremental index updates, avoiding resource consumption caused by full reindexing. Some policy documents have long lengths, so a long-text chunking strategy must be adapted to prevent individual chunks from exceeding the encoding limit of the vector model. Fixed fields such as issuing unit and branch can be used as recall filtering conditions to narrow the search scope and improve Q&A efficiency.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the typical length of party building documents for state-owned capital investment companies, preventing individual chunks from exceeding the vector model encoding limit |
| Overlap Length | 100–200 characters | Ensures semantic coherence between adjacent text chunks, preventing loss of contextual association after long document chunking |
| Similarity Threshold | 0.75–0.85 | Meets the rigor requirements of party building Q&A, filters low-correlation recall results, and ensures answers align with the question topic |
| Single Search Limit | Top 5 results | Controls the number of returned context chunks, avoiding exceeding the `maxToken` limit while ensuring sufficient information for answers |
| Maximum Context | 4000 token | Matches the input limit of mainstream vector models, ensuring recalled text chunks can be fully embedded into the Q&A context |
| Default Token Count | Set `defaultToken` to 2000 | Reserves reasonable context space for non-core Q&A scenarios, balancing resource usage and answer completeness |

## Three common mistakes
- Search results cannot be linked to metadata such as original document title and issuing unit. Cause: The metadata binding function is not enabled in the index configuration, and vectors are only generated for the main body content, resulting in loss of structured field information of the document.
- Interface errors occur when calling the Doubao-embedding model. Cause: The model's authentication key and interface address are not correctly filled in the vector model configuration, preventing normal vector generation.
- Errors occur due to Q&A context exceeding the model limit. Cause: Reasonable `maxToken` and single search limit are not set, and the total length of recalled text chunks exceeds the model's input limit, making encoding impossible.

## How to confirm the configuration is correct
- Upload a party building policy document in the FastGPT v4.17.0 interface, check whether the length of chunked text chunks falls within the 800–1200 character range, and whether adjacent chunks have 100–200 character overlap.
- Launch a party building-related question, check whether the returned answer is linked to metadata of the original document, such as document title, release date, and other information.
- Test calling the Doubao-embedding model, confirm that the vector generation interface returns normally, with no connection timeout or authentication failure errors.
- Adjust the similarity threshold, observe changes in the correlation of recall results, and confirm that the configuration takes effect.
