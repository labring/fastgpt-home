# Party Building Learning Q&A for Urban Public Transport: Deployment and Upgrade

## What the data for this use case looks like
Urban public transport party building learning Q&A data mainly comes from party building work ledgers of public transport operating enterprises, monthly centralized branch study records, policy documents issued by superior party organizations, and monthly ideological reports from drivers and management personnel.
Data update rhythm is adjusted according to party building work arrangements. Superior policy documents are updated quarterly in batches. Branch study records are archived monthly. Ledger content is supplemented dynamically with daily study activities.
Document structure includes fields for title, publisher, publish time, main body, and study requirements. Single document word count varies widely, with no fixed format template.

## What constraints these characteristics impose on deployment and upgrade
Party building data sources are scattered and formats are inconsistent. During deployment, support for importing multi-source unstructured data is required, and preset fixed field mapping rules should be avoided.
Data update rhythm is flexible. During upgrade, incremental sync configuration must be supported to avoid occupying excessive intranet resources with full re-import.
Single document word count varies widely. During deployment, reserve sufficient text processing buffer to prevent parsing failures for long documents.
Some bus depots have offline deployment requirements. During upgrade, support for dependency package distribution and version verification in offline environments must be included.

## Configuration Guidelines
This document is written based on FastGPT v4.17.0. All following configuration items are compatible with the deployment logic of this version.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Intranet-accessible MongoDB instance connection string | Stores knowledge base and conversation data for party building Q&A, ensures sensitive content is not exposed to the public internet |
| `REDIS_URL` | Intranet-deployed Redis instance, memory configuration no less than 2048 MB | Caches Q&A context and search results, adapts to high-frequency call scenarios at bus depots |
| `DB_MAX_LINK` | 10–15 | Limits the number of database connections per session, avoids occupying excessive public transport intranet database resources |
| `STORAGE_S3_ENDPOINT` | Intranet object storage service address, such as a local MinIO endpoint | Adapts to file storage requirements for offline deployment scenarios, no reliance on public internet storage services |
| `ROOT_KEY` | Randomly generated 32-character string | Ensures access security of FastGPT backend management interfaces, prevents unauthorized operations |
| `FILE_TOKEN_KEY` | Randomly generated 16-character string | Ensures access security of file upload interfaces, prevents unauthorized file uploads |

## Three Common Configuration Mistakes
- Phenomenon: Text content extraction fails after offline deployment, but works normally in online environments. Cause: Local file parsing dependency packages are not installed in the offline environment, or `STORAGE_S3_ENDPOINT` is configured with a non-intranet storage address, causing access failures.
- Phenomenon: Search results are empty or insufficient in quantity, with no clear error message during debugging. Cause: `DB_MAX_LINK` is set too low, causing the database connection pool to be exhausted, or `REDIS_URL` is configured incorrectly, causing the cache to fail to load normally.
- Phenomenon: Restarting the Docker container takes no effect after modifying code inside the container. Cause: The local code volume is not mounted to the container, or the image is not rebuilt, so modifications are not packaged into the deployment package.

## How to Verify Successful Configuration
- Run the built-in database connectivity test script, verify the connection status of `MONGODB_URI` and `REDIS_URL`, and check the returned connection success indicator.
- Upload a party building study document, check the system-generated text chunks and vector storage results, confirm that no exception error is triggered by the `DB_MAX_LINK` limit.
- Test document import and Q&A calls in the offline environment, confirm there are no error messages related to public internet dependencies, and verify that `STORAGE_S3_ENDPOINT` is configured correctly.
- Access the management interface corresponding to `FE_DOMAIN`, use `ROOT_KEY` to log in to the backend, confirm that the permission verification logic takes effect.
