# Party Building Learning Q&A for Urban Water Utilities: Deployment and Upgrade

## What data for this category looks like
Data sources for urban water utility party building learning Q&A include internal party building ledgers of urban water investment enterprises, study guidelines issued by higher-level party committees, internal party lesson courseware, and records of daily party building activities. Update frequency: core study points are updated weekly, while activity archives and meeting minutes are updated monthly. Document structure includes section titles, embedded images such as party lesson site photos and scanned study notes, and standardized fields: issuing unit, release time, document type, content summary. Units include bytes, days, items, and others.

## Constraints imposed during deployment and upgrade
Embedded images in the data require configuring a file storage path during deployment, otherwise resources cannot load properly. The high update frequency requires retaining historical knowledge base versions during upgrades, to avoid business interruptions caused by full reconstruction. Standardized fields require associating the corresponding database during deployment, to ensure field matching for accurate retrieval. For offline deployment scenarios, local storage resources must be configured in advance to avoid reliance on external cloud services. Additionally, the fixed field structure of documents requires matching database indexes during deployment, to prevent field mismatch errors during retrieval.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Internal compliant cloud storage endpoint or local file storage path | Data includes embedded images such as party lesson site photos and scanned study courseware, so storage path must be configured to ensure resources are accessible to the frontend |
| `MONGODB_URI` | MongoDB connection string adapted to the standardized fields of party building documents | Party building study data includes fixed fields such as issuing unit and release time, so the corresponding database must be associated for storage to support accurate retrieval |
| `REDIS_URL` | Cache connection configuration with 600–1800 second expiration time | Party building knowledge points are queried frequently, caching reduces database pressure, and expiration time is determined based on actual testing |
| `DB_MAX_LINK` | 20–30 concurrent connections | The party building knowledge base of water utilities has medium data volume, to avoid connection exhaustion or resource waste |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Protects access permissions for embedded document resources, preventing unauthorized access to internal party building materials |
| `FE_DOMAIN` | Enterprise internal portal domain name | Ensures that the frontend page can properly load linked party building study resource links |

## Three Common Misconfigurations
- Symptom: After deployment, embedded party lesson photos in the knowledge base fail to load, and the frontend displays broken image icons. Cause: `STORAGE_S3_ENDPOINT` or the local file storage path is not configured, causing image resources to not be mounted to a directory accessible by the service.
- Symptom: A "request error" prompt pops up during model testing, and curl testing shows no response from the reranked model. Cause: `REDIS_URL` is not configured correctly during offline deployment, causing session cache failure, or the `MONGODB_URI` connection string does not match the current database version.
- Symptom: After upgrading FastGPT v4.17.0, historical party building knowledge base query results have no organized output. Cause: The `tmbId` field of old version documents in MongoDB was not retained during the upgrade process, causing the system to fail to associate the corresponding knowledge base version.

## How to Confirm Configurations Are Correct
- Upload an image of a party building study courseware to the knowledge base, and preview the document to confirm the image displays properly.
- Run a curl command to test the `MONGODB_URI` connection, and confirm that a connection success prompt is returned.
- Enter the application historical version page, and check whether old version documents include the `tmbId` field.
- Initiate a party building knowledge point query, and confirm that the returned results include associated document fields and image resources.
