# Party Building Learning Q&A for Urban Gas Utilities: Citation Sources and Traceability

## What the data for this category looks like
The data sources for party building learning of urban gas enterprises include internal party building archives, learning documents issued by superior state-owned assets commissions and party committees, and electronic documents compiled from offline party lectures. The update rhythm is synchronizing the latest learning notifications weekly and updating fixed party lecture courseware monthly. Most documents are standardized texts with hierarchical headings, containing three fixed fields: publishing entity, publishing date, and core learning points. The length of a single document ranges from 1000 to 5000 characters, stored in bulk megabyte-level file packages.

## What constraints do these characteristics impose on the "citation sources and traceability" link
The fixed publishing metadata of party building data requires that the traceability link must associate the publishing entity and publishing date to ensure the authority of cited content. The weekly/monthly update rhythm requires that the traceability link supports incremental synchronization verification to avoid returning expired learning materials. The hierarchical heading document structure requires that citations can accurately locate the paragraph corresponding to the core learning points, associating specific paragraphs instead of broadly linking the entire document. The bulk file package storage format requires that the traceability link supports automatic metadata mapping during bulk import to prevent missing citation source fields.

| `detail` | Configure per scenario | Enable detailed traceability as needed to display publishing entity and publishing date |

## Three common mistakes
- Phenomenon: The returned answer has no connection to the knowledge base citations, and the cited content is not a party building learning-related document. Cause: The similarity threshold filter for non-party building gas operation data was not configured, leading to the recall of irrelevant content.
- Phenomenon: The citation source field is empty, and the original text details cannot be viewed. Cause: The publishing entity and publishing date fields were not mapped when bulk importing party building documents, leading to missing traceability metadata.
- Phenomenon: Citation display cannot be turned off for some scenarios in the workflow. Cause: The trigger conditions for the `detail` parameter were not differentiated, leading to all scenarios enabling detailed traceability uniformly.

## How to confirm the configuration is correct
- Initiate a party building-related question, check whether the returned content only associates party building learning documents with no irrelevant gas operation content.
- View the citation area below the answer, confirm that each citation includes metadata fields such as publishing entity and publishing date.
- In the system log of FastGPT v4.17.0, verify that the number of recalled citations each time matches the configured single search limit.
- Switch the Q&A configuration for different scenarios, verify that the `detail` parameter can be individually turned on or off to meet scenario requirements.
