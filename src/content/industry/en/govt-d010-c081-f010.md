# Party Building Learning Q&A for Basic Chemical Industry: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Basic chemical industry state-owned and state-owned enterprise party building learning data mainly comes from internal materials archived by party committees, policy documents issued by superior party committees, internal party course slides, monthly learning plans and ledgers. Updates follow a schedule of monthly new policy documents and quarterly updated learning summary compilations. Most documents are long text in PDF or Word formats. Some are structured Excel ledgers with fields including document number, issuing unit, release date, and learning theme. Units of measurement are pieces, copies, and standard date format.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Long-text party course slides and policy documents require proper chunking to avoid cross-paragraph context breaks that reduce semantic recall accuracy. Structured Excel ledgers contain multiple permission-related columns, so retrieval must support filtering by issuing unit to match resource access permissions for different subsidiaries. A large volume of official script texts has a concentrated semantic similarity distribution, which can cause original retrieval ranking deviations. An additional re-ranking step is needed to correct these deviations. Large files uploaded in batches can easily trigger index timeouts, so adjust the single-batch upload data volume threshold.

## Three Common Mistakes
- Knowledge base upload status stays in indexing for a long time. The index progress bar shows no change for more than 10 minutes. The cause is that most basic chemical industry party building documents are long PDFs or multi-column Excel ledgers uploaded in batches, with a single batch data volume exceeding the default index processing threshold.
- Retrieval result ranking is abnormal, with low-score results appearing first. For example, an entry with a `similarity` score of 0.5208 ranks before an entry with a score of 1.2717. The cause is that the `usingReRank` re-ranking function is not enabled. Most basic chemical industry party building texts are standardized official scripts, and original semantic similarity calculations are prone to misjudgments.
- Unable to import Excel format files or CSV column count exceeds limits. An error prompts unsupported format when uploading Excel files, and only the first two columns are indexed when uploading CSV files. The cause is that parsing rules supporting multi-column structured data are not configured. Basic chemical industry party building learning ledgers usually contain multiple columns such as learning date, attendees, and learning theme, and the default CSV parsing only supports two columns of data.

## How to Confirm the Configuration Is Correct
- Upload a single 10-page party building PDF document, check that the index status completes within 5 minutes with no timeout error prompts.
- Enter a party building-related question, verify that the returned result ranking logic prevents low `similarity` score results from ranking higher than high score results.
- Upload a multi-column CSV format party building learning ledger, confirm that all fields are correctly indexed and can be filtered for retrieval by field.
- After configuring `collectionIds`, only content from the specified party building knowledge base is retrieved, excluding non-party building data from other business sections.
