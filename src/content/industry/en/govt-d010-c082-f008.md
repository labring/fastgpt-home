# Party Building Learning Q&A for Basic Telecommunications Operations: Document Parsing and Chunking

## What the data for this category looks like
Party building learning Q&A data for basic telecommunications operations comes primarily from study manuals exported from the enterprise’s internal party building management system, official documents issued by superior party committees, monthly branch study records and meeting minutes.
Data updates align with the release schedule of superior documents. Most uploads are completed within 1 to 3 days after documents are issued. There is no fixed update cycle, but single-batch document upload volumes are large.
Most documents are in docx or pdf format, and some contain embedded images, tables and formulas. Their structure includes clear chapter titles, body paragraphs and annotated footnotes. Fields include document number, issuing unit and release date, with the basic statistical units being "article" and "copy".

## What constraints these characteristics impose on document parsing and chunking
Party building documents contain embedded images, tables and complex chapter structures. The parsing link must support complete extraction of multi-format content, and avoid losing image-text association information.
Large volumes of documents uploaded in batches require the parsing link to have stable concurrent processing capabilities, preventing timeout failures.
Clear chapter titles and hierarchies within documents require chunking logic to prioritize matching chapter boundaries, avoiding semantic fragmentation from cross-chapter splitting.
Some documents contain internal annotations. Parsing must retain original metadata fields to ensure information traceability for subsequent Q&A.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Party building documents use formal written language. This chunk length range covers complete semantic units, and avoids over-splitting or overly long chunks |
| `chunkSplitter` | Split by chapter titles | Party building documents have clear chapter hierarchies. Splitting by chapters preserves semantic integrity |
| `customPdfParse` | Enabled | Party building documents often contain embedded images and tables. Enabling custom parsing enables complete extraction of image and text content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large documents uploaded in batches takes a long time. This setting avoids timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Party building documents for basic telecommunications operations often include multi-page image and text materials. This setting supports large single-file uploads |
| `chunkSettingMode` | Manual configuration | Chunking logic must be adjusted for the chapter structure of party building documents to fit the business scenario |

## Three common mistakes
- After uploading a docx file that contains images, the returned results show invalid file prompts in place of images. The cause is that the `customPdfParse` configuration is not enabled. The default parsing logic cannot fully extract embedded image association information.
- Timeout errors occur when parsing large party building documents, with a 504 status code. The cause is that the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for large file parsing.
- Chunk results are spliced across chapters, leading to semantic confusion during Q&A. The cause is that the `chunkSplitter` configuration uses the default character-based splitting method, rather than splitting by chapter titles.

## How to confirm the configuration is correct
- Upload a single party building document that contains embedded images. Check that the parsed results fully display image placeholders and associated text.
- Upload a batch of large-volume documents. Check the completion status of parsing tasks to confirm there are no timeout errors.
- Randomly select a document with a chapter structure. Check that chunk results are split by chapter boundaries, with no cross-chapter splicing.
- View parameter items on the configuration page. Confirm that values for configuration items such as `customPdfParse` and `chunkSplitter` match the preset plan.
