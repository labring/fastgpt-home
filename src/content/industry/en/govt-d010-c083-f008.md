# Infrastructure Construction Party Building Learning Q&A: Document Parsing and Chunking

## What data in this category looks like
Party building learning data in the infrastructure construction sector comes from multiple sources: daily learning materials of project temporary party branches, policy documents issued by higher-level party committees, electronic versions of on-site party building bulletin boards, monthly learning ledgers, and temporary meeting minutes.
Update rhythm is irregular. Higher-level party policy documents are released per party building work requirements. Project learning ledgers are updated monthly. Temporary meeting minutes are generated when on-site meetings are held.
Document formats include official PDF documents, Word meeting minutes, plain text learning reflections, and scanned electronic files. Fields include document number, issuing unit, release date, learning topic, attendees, learning duration, and others. Some documents have fixed-format headers and footers.

## What constraints these characteristics impose on document parsing and chunking
Diverse document formats require the parsing link to support PDF, Word, plain text, and other types. This avoids losing key content due to unsupported formats.
Irregular update rhythm requires the chunking system to support incremental parsing and batch uploads. No fixed-cycle synchronization tasks are needed.
Metadata fields in documents, such as document number and learning duration, are bound to main text content. Chunking must not split across fields. Otherwise, metadata and corresponding main text will not match during retrieval.
Some documents use formal official document format headers and footers. Chunking must retain these format associations to avoid semantic incompleteness from splitting.

## How to set configurations

| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Party building documents contain both long sentences from original policy texts and short entries from meeting minutes. This range covers most semantic blocks, avoiding splitting policy clauses or meeting topics |
| `chunkSplitter` | Split by title + paragraph | Party building documents often have clear learning topics and meeting agenda titles. Splitting by title preserves semantic integrity and avoids mixing content across titles |
| `customPdfParse` | Enabled | Infrastructure construction party building documents are mostly formal official formats. Enabling custom PDF parsing preserves key metadata such as document numbers and main receiving organs, avoiding loss of format and field information during parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Large project party building ledgers may contain multiple independent documents. This timeout range allows complete parsing of batch documents, avoiding parsing failure due to timeout |
| `chunkSettingMode` | Manual configuration | Different types of party building documents (policy documents, meeting minutes, learning reflections) require differentiated chunking parameters. Manual configuration adapts to diverse document structures |

## Three common mistakes
- Phenomenon: Unrendered Markdown format characters appear in context references, or metadata fields such as document number are empty. Cause: The `customPdfParse` configuration is not enabled, causing PDF format party building documents to lose format markers and metadata fields during parsing.
- Phenomenon: Parsing timeout errors occur when uploading a party building ledger compressed package containing multiple documents. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is lower than 120 seconds, which cannot complete the complete parsing process of batch documents.
- Phenomenon: Content from the same learning topic is split into multiple discontinuous chunks after chunking. Cause: `chunkSettingMode` is set to automatic mode, and the system automatically splits across the boundary between title and main text, destroying semantic integrity.

## How to confirm the configuration is correct
Reference only; verify against the target FastGPT release and deployment documentation.
- Upload a party building official document PDF with an official document number. Check if the parsed document retains metadata fields such as document number and main receiving organs.
- Upload a project party building meeting minutes document with more than 10 pages. Check if the parsing time is within the configured `PARSE_FILE_TIMEOUT_SECONDS` range.
- Test the chunked content. Confirm that content from the same learning topic is not split across title boundaries, and that adjacent chunks have coherent semantics.
- Upload party building documents in different formats (Word, plain text) to verify consistency of parsing and chunking results.

The values provided are common starting points and should be measured against the reader's own samples.
