# Party Building Learning Q&A for Infrastructure Construction: Deployment and Upgrade

## What this category of data looks like
Party building learning Q&A data in the infrastructure construction field mainly comes from monthly learning points issued by party committees of construction enterprises, project branch meeting minutes, party member learning ledgers, and industry party building standard documents. Updates are mostly monthly regular updates, paired with on-demand updates for documents generated from temporary party building activities. Each document includes fields such as title, body, issuing unit, release date, and applicable project number. Supported formats include PDF, Word, and internal structured tables. Field units are mostly characters, date strings, and project number identifiers, with no unified fixed length requirement.

## What constraints these characteristics impose on deployment and upgrade
The multi-source and multi-format nature of party building data requires the deployment phase to adapt to permission docking with internal document systems, to avoid cross-system access restrictions. The rhythm of monthly regular updates and temporary on-demand updates means the upgrade phase must support incremental index synchronization, without full vector database reconstruction, to reduce upgrade time. Documents include structured fields such as applicable project number, so database configuration must support filtering queries by business fields, to adapt to permission isolation requirements for project-level party building learning. The storage demand for large-volume documents also places higher capacity and bandwidth requirements on object storage configuration.

| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:securepass@internal-db:27017/fastgpt?authSource=admin` | Adapts to structured storage of party building data, supports permission filtering queries by applicable project number |
| `STORAGE_S3_ENDPOINT` | `https://s3.internal.construction.com` | Party building documents are mostly in PDF and Word formats, with a maximum size of 500 MB per file, requiring adaptation to large file storage needs |
| `REDIS_URL` | `redis://:redispass@internal-cache:6379/0` | Caches frequently accessed party building learning points to reduce database query pressure; cache validity period is set to 3600 seconds based on actual measurements |
| `DB_MAX_LINK` | `800 links` | Internal associated links per party building document typically do not exceed 600, reserving reasonable buffer space |
| `FE_DOMAIN` | `https://fastgpt.party.construction.com` | Deployed on the internal domain of construction enterprises, adapting to internal employee access permissions |

## Three common mistakes
- Phenomenon: Timeout or "image not found" prompt when pulling FastGPT images. Cause: Enterprise internal image repository not configured, pulling official images directly is restricted by internal network.
- Phenomenon: Party building Q&A fails to return the latest learning content after upgrading from 4.9.0 to 4.12.3. This document is written based on FastGPT v4.17.0. Cause: Incremental index synchronization operation not performed, old vector database does not load newly imported documents.
- Phenomenon: Uploaded party building document parsing result lacks release date field. Cause: `FILE_TOKEN_KEY` configuration does not match the signature key of the internal document system, causing some metadata to not be extracted correctly.

## How to verify the configuration is correct
- The `docker ps` command is run to confirm that all relevant FastGPT containers are in running state.
- A test project party building learning document is uploaded, and the parsed result is checked to confirm it includes complete metadata such as title, issuing unit, applicable project number.
- A test question such as "What are the monthly learning points issued by the party committee?" is submitted, and the returned documents are confirmed to be within the permission scope.
- The object storage console is logged into to confirm that the uploaded party building documents have been successfully stored in the specified bucket.

The values provided are common starting points and should be measured against the reader's own samples.
