# Party Building Learning Q&A for Infrastructure Construction: Sharing and Embedding

## What the data for this category looks like
This category of data mainly comes from party building archives at infrastructure construction project sites, standardized learning documents issued by superior party organizations, meeting minutes and learning attendance records of project temporary party branches. The fixed document structure includes five core fields: learning topic, launch date, participants, core learning content, and follow-up rectification requirements. The units of the fields are characters, date, person-times, paragraph, and text respectively. The data update rhythm is adjusted synchronously with the project construction progress. It has no fixed cycle but is tied to the frequency of on-site party building activities.

## What constraints these characteristics impose on sharing and embedding
Documents include project-related fields. The project number must be passed as a context parameter during embedding, otherwise the corresponding party building learning content cannot be matched. Data updates have no fixed cycle. Sharing links must enable real-time synchronization configuration to avoid displaying outdated learning records. Fields include content with units such as person-times and study hours. The embedded iframe must reserve sufficient width to fully display unit information. In login-free sharing scenarios, if custom variables such as project numbers need to be passed, login-free links cannot carry them directly. Adjust the setup to use `shareId` to bind preset project context instead.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `shareId` | Bind the exclusive ID of the corresponding project party building knowledge base | Ensure shared content is only associated with the current project's party building learning data, avoiding cross-project content confusion |
| Embedded iframe width | 800–1200 pixels | Adapt to the field length of party building documents, fully display unit information such as person-times and study hours |
| Real-time synchronization configuration | Enabled | Match the rhythm of data updates along with project progress, ensuring shared content is always the latest learning records |
| Login-free sharing mode | Bind preset project context | Avoid the issue where login-free links cannot carry custom variables, ensuring correct association of party building data |
| Load timeout threshold | 60 seconds | Allow sufficient loading time for large party building documents, avoiding loading failure due to overly long content |
| Markdown rendering switch | Retain native format | Fully retain formats such as titles and lists in party building documents, without losing structural information of learning records |

## Three common mistakes
- Phenomenon: The login-free shared party building Q&A page fails to display the learning content of the specified project, and the corresponding fields are empty. Cause: The project number is mistakenly added as a custom variable to the login-free link, but login-free links cannot carry custom parameters.
- Phenomenon: The party building document format in the embedded iframe is disordered, with titles and unit information mixed together. Cause: No suitable iframe width is set, causing field content to be truncated and destroying the document's layout structure.
- Phenomenon: The number of results returned by the shared Q&A link does not match the actual knowledge base content. Cause: `shareId` is not correctly bound, causing the shared content to be associated with the wrong party building knowledge base.

## How to confirm configurations are set correctly
- Open the sharing link, check if the current project's party building learning topic is displayed at the top of the page, confirming that `shareId` is bound correctly.
- Adjust the browser window width, check if the unit information of the party building document is fully displayed, confirming that the iframe width setting is reasonable.
- Upload a new party building learning record, refresh the sharing link, confirming that the content is updated synchronously and the real-time synchronization configuration is effective.
- Check the browser console of the embedded page, confirm that there are no load timeout errors, confirming that the load timeout threshold setting meets actual scenario requirements.
