# Party Building Learning Q&A for Refined Oil Sales: Model Access and Configuration

## What Data for This Category Looks Like
Party building learning data in the refined oil sales sector primarily comes from learning documents issued by superior party committees, party day activity archives from various sales stations, party member learning check-in records and experience reports.
Data sources are divided into standardized courseware issued on a regular basis and real-time updated frontline station records.
Update rhythm follows: superior documents are synchronized quarterly, station records are updated monthly.
Document formats include PDF courseware, Word activity ledgers, and plain text experience reports.
Structurally, all entries have fixed fields including learning topic, attendees, learning duration (unit: hours), and assessment score. Some courseware include activity site photos and promotional posters.

## Constraints Imposed on Model Access and Configuration
Party building learning data includes multi-format documents and mixed structured and unstructured content. This requires models to support multi-source data parsing and precise field matching.
Courseware with images needs models to have multimodal recognition capabilities, to ensure Q&A can associate image content.
Station data is scattered across storage nodes at different levels. Access must adapt to cross-source data pull logic.
The standardization of fixed fields requires models to precisely match fields such as topic and duration during recall, to avoid confusing non-party building business data.
The monthly and quarterly update rhythm requires configuring regular synchronization trigger rules, to ensure the timeliness of Q&A data.

## How to Set Configurations
| Configuration Item | Recommended Setting | Basis for This Setting |
| ---- | ---- | ---- |
| `vision` | Enabled | Party building courseware often includes activity photos and promotional posters. Models need to recognize image content to fully answer related questions |
| `maxContext` | 8000–12000 token | Party building learning Q&A needs to associate multiple courseware and activity records. Retain sufficient context to ensure answer coherence |
| `maxTokens` | 2000–3000 token | Party building Q&A needs to output detailed explanations, while avoiding excessive length that causes API call timeouts |
| `quoteMaxToken` | 4000 token | Need to recall sufficient party building document fragments as reference basis, to ensure answers meet the rigor requirements of party building content |
| `temperature` | 0.2–0.4 | Party building Q&A needs to remain rigorous and accurate. Avoid excessive divergence to prevent deviation from official content |
| `AIPROXY_API_ENDPOINT` | Fill in the proxy address deployed internally | Adapt to the internal network environment of state-owned enterprises and public institutions, forward API requests via proxy |
| `AIPROXY_API_TOKEN` | Fill in the exclusive token assigned by the proxy | Verify legitimate permissions for API calls, ensure secure access to internal data |

## Three Common Misconfigurations
- After restarting the FastGPT service, API channel and token configurations are lost. The cause is that configurations were not stored to the local persistent directory, and were only temporarily saved in memory.
- After uploading a party building PDF containing images, the model cannot recognize the image content. The cause is that the `vision` configuration item was not enabled, or a model that does not support multimodal capabilities was used.
- AI conversation output content cannot be secondarily processed by other workflow modules and displayed back in the dialog box. The cause is that the output forwarding rule of the workflow was not configured, and only the direct output of the native AI conversation was enabled.

## How to Confirm Configurations Are Properly Set
- Upload a party building courseware PDF containing activity photos, initiate a query about the image content, and check whether the model can correctly describe the image details.
- Initiate a query related to a party building topic, check whether the output content includes corresponding document fragment references, to confirm that the recall logic is effective.
- Restart the FastGPT v4.17.0 service, check whether the API proxy endpoint and token configurations are still retained, to confirm that persistence is effective.
- Adjust the `temperature` parameter, initiate a query, observe whether the rigor of the answer changes with the parameter, to confirm that the configuration is effective.
