# Building Engineering General Contracting Party Building Study Q&A: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like

Party building study related data for building engineering general contracting projects mainly comes from three meetings and one lesson records of the project party branch, party building guidelines from the superior state-owned assets supervision and administration commission, internal party building training materials of the group, and temporary party building study briefs of the project.

Update rhythm includes fixed cycle updates and temporary updates. Superior policy documents are updated quarterly on a fixed schedule. Branch activity records are updated monthly. Temporary study materials are uploaded synchronously when released.

Document formats are mostly PDF meeting minutes and Word training materials. A small number of structured CSV records are used. Fields include study topic, holding time, number of attendees, study duration, and speaker.

## Constraints Imposed on Knowledge Base Retrieval and Recall

Mixed-format party building documents require the retrieval system to support multi-format text extraction.

Incorrect custom delimiter configuration for CSV files can cause line separation errors.

Structured record fields contain content with clear units such as study duration and number of attendees. Retrieval must avoid recall bias caused by unit ambiguity.

Coexistence of fixed quarterly-updated superior policy documents and monthly-updated branch activity records requires batch synchronization rules to prevent data version confusion.

Some long documents, such as quarterly party building training materials, are overly lengthy. Proper chunking is needed to avoid context breaks that reduce semantic recall accuracy.

## Configuration Settings

This document is written based on FastGPT v4.17.0. The following are configuration recommendations for knowledge base retrieval and recall for this scenario.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Filters low-correlation content, adapts to the semantic matching requirements of party building text |
| `limit` | Top 6 entries | Controls the context length of a single round of Q&A to avoid exceeding conversation window limits |
| `searchMode` | Keyword + semantic hybrid | Balances precise keyword matching for party building policies and semantic recall for study materials |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results to improve the accuracy of content relevance sorting |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonymous expressions related to party building, such as expanding "three meetings and one lesson" to "branch committee meeting, general meeting of party members, party lesson" |
| `collectionIds` | Bind the knowledge base collection ID of the current project party branch | Limits the retrieval scope, only calls party building-related documents of the current project |

## Three Common Configuration Mistakes

- Phenomenon: The knowledge base content referenced in Q&A does not match the expected format, with redundant markers or missing content. Cause: Confused the configuration logic between prompt words and knowledge base reference templates, and failed to correctly set the output format of referenced content.
- Phenomenon: Line content of uploaded party building record CSV files is incorrectly merged or split. Cause: Failed to correctly configure custom delimiters, using the default delimiter cannot recognize comma-separated fields in the records.
- Phenomenon: Search node authentication does not take effect, unauthorized users can access party building knowledge base content. Cause: Failed to configure correct authentication rules in the search node, or the bound knowledge base collection did not enable permission verification.

## How to Verify Correct Configuration

- Upload a test party building record CSV file, check if line separation meets expectations, and verify that the custom delimiter configuration takes effect.
- Submit a party building-related question, check if the retrieval results only include party building documents of the current project, and verify that the `collectionIds` configuration is correct.
- Adjust the `similarity` threshold, observe changes in the relevance of retrieval results, and confirm that the threshold setting meets current business requirements.
- After enabling `usingReRank`, compare the order of initial recall results and reranked results, and verify that the reranking function works properly.
- Check the configuration logic of the knowledge base reference template and prompt words, ensure that the format of referenced content meets Q&A requirements, and verify that the template configuration is correct.
