# Party Building Learning Q&A for General Contracting of Residential Construction Projects: Forms and Interactions

## What the data for this category looks like
Party building learning data for general contracting of residential construction projects mainly comes from the party building management systems of state-owned enterprises affiliated to the project, party building guidance documents for the construction industry released by the housing and urban-rural development system, and learning ledgers of the project’s temporary party branch. The update rhythm follows monthly updates of superior party building deployment requirements, and quarterly updates of project-specific learning materials. The document structure includes learning topic, associated project section number, issuing unit, issuing date, learning content, and supporting assessment requirements. The fields include "learning topic", "study hour requirement (unit: hour)", and "applicable team scope". The length of a single document is mostly between 800 and 2000 characters.

## What constraints do these characteristics impose on the "forms and interactions" link
The characteristic that party building data is associated with project section numbers requires the form to be configured with input items linked to project section numbers, to enable accurate retrieval of exclusive party building materials for the corresponding section. The quarterly update cycle for documents requires a manually triggered material library refresh button in the interaction flow, to prevent calling expired content. The relatively long length of single documents requires the form to support segmented loading of learning content, to avoid interface lag caused by loading excessive data at one time. The presence of study hour requirement fields requires adding study hour confirmation selection items in the interaction, to align with the process requirements of learning assessment.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Project section number, learning topic keyword | Matches the associated section and topic fields of party building data, to achieve accurate retrieval of corresponding materials |
| `userSelect` | Study hour range, team type | Covers the study hour requirement and applicable team fields of party building data, simplifying user input |
| Material refresh trigger | Manually click the button, interval no less than 30 minutes | Matches the monthly and quarterly update rhythm, avoiding frequent refreshes that occupy system resources |
| Content segmented loading | 800-1200 characters per segment | Adapts to the average length of single documents, optimizing interface loading and reading experience |
| Learning confirmation item | Radio button group including "Completed learning", "Not completed" | Aligns with the process requirements of party building learning assessment, collecting learning completion status |

## Three common mistakes
- Phenomenon: The form is displayed as a plain text list in the conversation interface, and selection interaction cannot be triggered. Cause: The rendering rules of `userSelect` are not configured correctly, the system does not enable interactive component rendering, and only outputs text content.
- Phenomenon: Expired content is returned when calling party building materials, and the latest quarterly learning materials are not updated. Cause: The refresh interval for materials is not set, and the system defaults to caching materials for more than 7 days without updates.
- Phenomenon: No response after submitting the form, and loading lag appears on the interface. Cause: The form input items are configured with fields that do not exist in the party building data, causing the system to fail to match and retrieve corresponding materials.

## How to confirm the configuration is complete
- Open the conversation debugging interface of FastGPT v4.17.0, enter the project section number and learning topic keyword, and confirm that the form is correctly rendered as interactive input boxes and selection items.
- Manually trigger the material refresh operation, confirm that the system prompts that the refresh is complete, and that the subsequently called materials include the latest quarterly updated content.
- Submit the form and select the learning confirmation item, confirm that the system can correctly receive the form data and associate it with the corresponding party building learning content.
- Test long document loading, confirm that the content is displayed in segments according to the set character length, with no obvious lag.
