# Party Building Learning Q&A for Government and Enterprise Information Services: Citation Sources and Traceability

## What the data for this category looks like
Party building learning Q&A data for government and enterprise information services mainly comes from official party building publications, internal training courseware, latest policy documents, and industry standard documents.
The data update rhythm adjusts with policy release cycles. Core policy documents are synchronized every quarter. Internal training documents are updated alongside training plans.
Each single document includes four core fields: title, main text paragraphs, issuing authority, and release date. Content uses standardized written text exclusively, with no multimedia attachments. Field units follow standard character counts and standard date formats.

## What constraints these characteristics impose on the "citation sources and traceability" workflow
The official source attribute of party building learning data requires citation traceability to link to issuing authority and release date. This ensures content authority.
Fixed update cycles mean the traceability system must regularly synchronize latest metadata. This prevents citing expired documents.
The structured field design of documents demands precise matching of field dimensions during retrieval. Do not rely only on text similarity. Doing so may mix in unrelated categorized party building content.
The standardized text structure of single documents lets chunked citation paragraphs directly correspond to chapter positions in the original document. This provides clear positioning basis for traceability.

## How to set the configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Similarity Threshold | 0.75–0.85 | Matches the specialized terminology density of party building materials, filters low-relevance generic content |
| Single Search Limit | Top 3–5 results | Party building materials have clear classifications. Too many results increase information complexity for traceability |
| `quoteMaxToken` | 800–1200 token | Covers core citation paragraphs of single party building documents, avoids truncating key policy content |
| Reranking | Enabled | Most party building materials are policy texts. Reranking prioritizes matching the core needs of the query |
| `detail` | Enabled | Requires returning complete metadata of cited documents, including issuing authority and release date |
| `responseData` | Return only results with traceability fields | Filters redundant data, ensures traceability information is complete and meets compliance requirements |

## Three common configuration mistakes
- Phenomenon: Citation results only show a single document, and cannot cover multi-paragraph content involved in the question. Cause: The single search limit is set too low, failing to match the multi-chapter citation needs of party building materials.
- Phenomenon: Cited content does not carry the issuing authority or release date field, making traceability unable to verify authority. Cause: The `detail` configuration is not enabled, so the system does not return complete metadata.
- Phenomenon: Answers to new questions do not link to citation sources of historical questions, resulting in off-topic responses. Cause: Context-linked traceability configuration is not enabled, so the metadata association logic of historical citations is not retained.

## How to confirm the configuration is properly applied
- Launch a test question containing party building policy keywords. Check if the issuing authority and date of cited documents are displayed at the end of the answer to confirm complete metadata.
- Adjust the value of `quoteMaxToken`. Observe if the length of citation paragraphs changes with the configuration to verify the parameter takes effect.
- After enabling the reranking configuration, compare the sorting of two retrieval results to confirm the reranking function operates normally.
- Check if returned response data only includes content with traceability fields, with no irrelevant redundant information. This verifies the `responseData` configuration takes effect.
