# Party Building Learning Q&A for New Energy Development: Citation Sources and Traceability

## What this category of data looks like
Party building learning Q&A data for new energy development draws from three main sources:
Internal party building training documents for the new energy sector of state-owned and state-owned enterprises,
industry policy documents that guide new energy projects through party building,
and learning materials released by enterprise party committees.

Data updates align with monthly party building learning plans and quarterly policy adjustments.
Each document contains 1000 to 5000 characters of structured content, including fields such as document number, issuing unit, affiliated new energy project sector, and release date.
Some documents include official citation annotations.

## Constraints on citation sources and traceability
The source attributes of new energy development party building learning data require traceability to match internal document numbers and issuing units. This ensures cited content comes from authorized internal state-owned and state-owned enterprise materials.
Data updates follow monthly party building plans and quarterly policy adjustments. Traceability must verify document release dates to avoid citing expired content.
Documents have built-in structured source fields that can be directly extracted as traceability references. However, document formats vary slightly across different new energy project sectors. Unified field matching standards are therefore necessary.
Single document character volume is moderate, so excessive splitting is unnecessary. But traceability must link back to the original issuing entity.

## Three common misconfigurations
- Symptom: Knowledge base retrieval nodes in workflows cannot reference the global variable datasetid. A prompt stating the variable is not bound appears in the interface. Cause: The global variable’s scope is not set to cover the knowledge base retrieval node, or the variable name does not match the parameter name in the retrieval node configuration.
- Symptom: Citation results include red error text with the prompt "Traceability data is invalid". Cause: The `responseData` configuration is not enabled, and required traceability fields are not extracted. This makes verification of citation source legitimacy impossible.
- Symptom: Only the first question in a workflow triggers knowledge base citation. Subsequent questions have no citation results. Cause: The knowledge base retrieval node is not set to be reusable, or retrieval parameters are not rebound in subsequent processes. This leads to context or configuration being reset.

## How to verify successful configuration
- Submit a test question related to new energy party building, and check whether the returned result includes traceability fields such as document number and issuing unit.
- Review the knowledge base retrieval node configuration, and confirm that the `quoteMaxToken` value matches the current document’s character range.
- Verify that the global variable datasetid is correctly bound to the retrieval node, and that its scope covers the current workflow.
- Trigger multiple consecutive test questions, and confirm that traceability information is returned normally for each result.
