# Party Building Learning Q&A for New Energy Development: Document Parsing and Chunking

This page configuration guide is based on FastGPT v4.17.0.

## What this category of data looks like
Party building learning data in the new energy development field mainly comes from internal party building work platforms, branch activity archives supporting new energy projects, policy documents issued by superior party committees, and internal documents from collaboration tools such as Feishu and Yuque. The data update rhythm is monthly updates of branch activity records, quarterly updates of standardized study manuals, and irregular synchronization of the latest party building policies. Document types include learning courseware with embedded images, membership fee ledgers with statistical tables, plain-text study reflections, and multi-dimensional documents for party member development progress tracking. Fields include document title, release date, affiliated project branch, event participation count, with units such as person-times, quarters, and yuan.

## Constraints on document parsing and chunking
Party building documents for new energy projects include courseware with embedded images, multi-column ledger tables, and cross-platform collaboration links. Parsing workflows must support image text extraction, multi-format file parsing, and valid data source identification. Long-text project party building study materials and large ledger files increase parsing time and chunking difficulty. Adjust chunking rules to preserve semantic completeness. Variations in format across data sources require parsing configurations to adapt to multiple input types, including Yuque public links and Feishu multi-dimensional documents. This prevents parsing failures or content loss.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 1000–1500 characters | Party building documents in this category mostly contain long text with policy clauses and activity records. Chunk sizes that are too long break context connections. Chunk sizes that are too short increase token consumption. This range is calibrated based on field testing of the average structure of documents in this category. |
| `chunkSplitter` | Split by paragraph + heading | Party building documents have clear chapter headings and paragraph divisions. Splitting by paragraph preserves semantic completeness and supports precise matching for subsequent Q&A needs. |
| `customPdfParse` | Enable OCR mode | Some party building courseware are scanned documents or use embedded image formats. Enabling OCR extracts text from images, preventing loss of party building learning information contained in images. |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | New energy party building documents may include large Excel ledgers or multi-dimensional spreadsheet files. Raising the upload upper limit supports complete import of full business and party building associated data. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large multi-dimensional spreadsheets or long documents takes significant time. Setting 600 seconds prevents parsing from being interrupted mid-process due to timeout. |
| `chunkSettingMode` | Manual configuration | Special structures in new energy party building documents, such as embedded images and multi-column tables, require adjusted chunking rules. Manual configuration offers more flexible adaptation to scene requirements than automatic mode. |

## Three common configuration errors
- Symptom: The parsed knowledge base does not include text content from embedded images. The large language model cannot access party building learning information contained in images. Cause: OCR mode for `customPdfParse` is not enabled, and only plain text content from the document is extracted.
- Symptom: After uploading a publicly shared Yuque document link, parsing fails, and no knowledge base entry is generated. Cause: The link is not a publicly accessible single-document link, or the link points to a team space homepage, folder, or other non-document address.
- Symptom: After importing a Feishu multi-dimensional document, some columns of party building statistical data are not indexed. Cause: Multi-dimensional document parsing permissions for the Feishu knowledge base are not enabled, or chunking rules do not adapt to the multi-column structure of multi-dimensional spreadsheets.

## How to confirm correct configuration
- Upload a party building courseware PDF with embedded images. Verify that the parsed text content includes text information from the images.
- Paste a publicly accessible Yuque document link. Confirm that the parsing status shows success and a corresponding knowledge base entry is generated.
- Upload a small Feishu multi-dimensional spreadsheet file. Verify that all columns of party building-related data are correctly indexed.
- Upload an Excel party building ledger of approximately 100 MB. Confirm that no timeout prompt appears during the parsing process.

The values provided are common starting points and should be evaluated against the user's own samples.
