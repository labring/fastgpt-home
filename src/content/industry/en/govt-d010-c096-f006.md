# Party Building Learning Q&A for Non-Ferrous Metal Smelting: Citation Source and Traceability

## What the data for this category looks like
Party building learning data in the non-ferrous metal smelting field mainly comes from three sources: industry Party building guidance documents issued by local State-owned Assets Supervision and Administration Commission (SASAC), monthly learning materials released by smelting enterprise Party committees, and special Party lesson courseware from superior Party committees.
1 to 2 batches of learning documents are added each month. Most individual documents range from 5000 to 20000 characters in length.
Document structures include fixed fields such as document number, issuing authority, release date, learning theme, and main text. Some internal documents are marked with access permission scopes.

## What constraints do these characteristics impose on the citation source and traceability link?
The long length of individual documents requires the traceability link to adapt to large chunk retrieval results. It must avoid truncating key metadata.
The presence of fixed fields requires traceability to accurately extract identifying content such as document number and issuing authority. This ensures citation sources can be quickly verified.
The presence of access permission markings requires the traceability link to automatically identify and filter document fragments without access permissions. Sensitive information is hidden in public scenarios.
The update rhythm of different batches requires the traceability link to associate the latest document versions. Outdated learning materials are not cited.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |

| `quoteMaxToken` | 1200-1800 token | Adapts to retrieval results of 5000-token chunks, retains sufficient context for traceability while complying with response length limits |
| `responseData` | Return document number, issuing authority, release date | Matches the fixed field structure of this category's data, fully displays core information required for traceability |
| `detail` | Enabled | Displays the full content of retrieved document fragments, preventing missing traceability information |
| Single search limit | Top 3-5 results | Relevant retrieval results for non-ferrous metal smelting Party building learning data per batch mostly fall within this range, avoiding excessive token usage from too many results |
| Metadata display | Show document source path | Adds source address-related traceability information to meet user needs for accurate positioning of citation sources |

## Three common mistakes
- Phenomenon: Cited document fragments in the response are truncated, and complete metadata such as document number and issuing authority are not displayed. Cause: The value of `quoteMaxToken` is not adjusted according to document length, resulting in truncation of key information required for traceability.
- Phenomenon: A 5000-token chunk document that meets the conditions is retrieved, but content is still missing in the response after setting `quoteMaxToken` to 1500. Cause: The token proportion of the chunk itself is not considered. The 1500-token limit is insufficient to cover the complete chunk context, leading to loss of traceability information.
- Phenomenon: No citation source-related information is displayed in the response. Cause: The `responseData` or metadata display configuration is not enabled, and fields required for traceability are not included in the returned content.

## How to verify the configuration is correctly applied
- Initiate a Party building-related query, verify whether traceability information such as document number and issuing authority is displayed at the bottom of the response.
- Review the length of cited fragments in the response to confirm they do not exceed the set value of `quoteMaxToken`.
- Test retrieval of documents marked with access permissions, confirm that sensitive information is not publicly displayed.
- Adjust the value of `quoteMaxToken`, observe changes in the length of response fragments to verify that the configuration takes effect.

Note: The configuration values provided are common starting points and should be evaluated against samples specific to the actual use case.
