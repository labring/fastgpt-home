# Party Building Learning Q&A for Non-Ferrous Metal Smelting: Knowledge Base Retrieval and Recall

## What This Category’s Data Looks Like
Data mainly comes from internal party building learning materials of non-ferrous metal smelting enterprise party committees, party building guidance documents released by industry regulatory authorities, and archived materials of internal party building activities. The update rhythm follows a monthly schedule for newly added learning materials and activity records. Most documents are in PDF or Word format, with structures including title, main body paragraphs, issuing unit, and issuing date fields. Some files include branch affiliation tags and topic classification identifiers.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
First, the presence of branch affiliation tags requires retrieval to support filtering documents by specified scope. This prevents irrelevant cross-branch content from interfering with learning Q&A.
Second, documents contain many professional terms and fixed policy statements. Retrieval must retain accuracy for term matching, and should not overly relax matching rules.
Third, the monthly update rhythm requires the knowledge base synchronization cycle to align with the update frequency of party building materials. This ensures retrieval results include the latest learning materials.
Fourth, some documents use long text formats. Semantic dispersion after chunking requires optimization of recall result priority via a re-ranking step.
Finally, party building topics often include derivative expressions. Retrieval must support extended queries to cover related synonymous content, improving recall coverage.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Party building Q&A requires accurate matching of policy originals, to avoid low-similarity irrelevant content being included, while covering related derivative expressions |
| `limit` | `Top 10` | Party building learning Q&A usually requires a small number of precise reference documents. Too many entries will exceed the context window and reduce answer accuracy |
| `searchMode` | Precise matching | Non-ferrous metal smelting party building materials contain many professional terms and fixed policy statements. Precise matching avoids inaccurate recall of irrelevant content |
| `usingReRank` | Enabled | Chunking of long text documents may cause semantic dispersion. Re-ranking reorders recall results, improving the priority of core content |
| `datasetSearchUsingExtensionQuery` | Enabled | Party building topics often include derivative expressions. Extended queries cover retrieval needs for synonymous related content such as "safety production party building" and "team building" |
| `collectionIds` | Populate with the collection ID of the branch to which the current conversation belongs | Party building learning materials of each branch of non-ferrous metal smelting enterprises are archived independently. Filtering by collection returns precise internal party building content for the target branch |

## Three Common Misconfigurations
- Phenomenon: Retrieval results include party building documents from non-target branches, and returned results do not match the learning needs of the current branch. Cause: The `collectionIds` parameter is not configured correctly, and the knowledge base collection ID corresponding to the current branch is not specified, resulting in recall of all documents.
- Phenomenon: A large number of duplicate document fragments appear in retrieval results. Cause: Duplicate file filtering configuration is not enabled, or imported documents are not deduplicated, resulting in multiple versions of the same content being recalled simultaneously.
- Phenomenon: Retrieval results cannot match the latest monthly party building learning materials. Cause: The knowledge base synchronization cycle does not align with the update rhythm of party building materials, and incremental knowledge base synchronization is not performed monthly, resulting in newly released learning materials not being included in the retrieval scope.

## How to Verify the Configuration Is Correct
- Initiate a retrieval targeting a branch-specific party building topic, and check whether all returned documents belong to the collection corresponding to the currently configured `collectionIds`.
- Import a duplicate party building document, perform retrieval, and check whether only one valid fragment of the document is returned.
- Upload a latest monthly party building learning material, run the synchronization operation, then initiate retrieval, and check whether the newly uploaded document can be recalled.
- Enter a search term containing professional terms, check whether the relevance of the returned results meets expectations, and confirm that the `searchMode` and `usingReRank` configurations are active.

Note: The configuration values listed above are common starting points. Adjust them based on your own specific samples and use cases.
