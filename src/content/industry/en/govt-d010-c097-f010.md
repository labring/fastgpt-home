# Party Building Learning Q&A for Nuclear Power Operations: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Party building learning data for nuclear power operation scenarios comes from internal enterprise party building information platforms, superior party building guidance documents, and study records and meeting minutes uploaded voluntarily by party branches.
Update schedule: Superior policies are synced in real time, monthly study materials are updated at the start of each month, typical cases combining party building and nuclear power operations are updated quarterly, and temporary study tasks are added as needed.
Each single document includes a title, party building theme classification, associated nuclear power production operation link tags, release date, and main body. Fields include theme classification, associated operation links, and releasing unit. Some documents include a study assessment key points field.

## What Constraints Do These Characteristics Impose on the "Knowledge Base Retrieval and Recall" Link?
Party building data includes tags associated with nuclear power production operation links. This requires the retrieval link to support filtering recall results by operation link, to avoid returning generic party building content unrelated to nuclear power operation scenarios.
Real-time synchronization of superior policy requirements means the retrieval system must support incremental knowledge base updates, to reduce the time and resource consumption of full rebuilds.
Documents are categorized by party building theme. This requires the retrieval link to support limiting the recall scope by classification, narrowing the search space and improving accuracy.
Some documents include clear study assessment key points. This requires recall results to prioritize content related to the assessment corresponding to the user's question, to meet the assessment-oriented needs of party building learning Q&A.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Nuclear power party building content contains many professional terms and scene-specific expressions. A threshold that is too low will recall irrelevant generic party building content, while a threshold that is too high will miss valid results that fit the scene. Calibrated based on actual testing. |
| `limit` | Top 10 entries | Nuclear power party building documents have relatively long individual lengths. Too many recall results will exceed the context window limit. 10 entries can cover core relevant content. |
| `searchMode` | `keyword+vector` | Balances keyword matching for party building policies and semantic recall for professional content, adapting to the mixed retrieval needs of party building combined with production scenarios in nuclear power. |
| `usingReRank` | Enabled | There are many synonymous expressions in nuclear power party building content. Reranking can correct sorting deviations from initial recall and improve accuracy. |
| `datasetSearchUsingExtensionQuery` | Enabled | Can expand the user's party building learning question into a query term that includes nuclear power production scenarios. For example, expand "three meetings and one lesson" to "three meetings and one lesson in nuclear power operation scenarios" to improve recall relevance. |
| `collectionIds` | Bind exclusive collections for party building + nuclear power operations | Limit the retrieval scope to only nuclear power operation-related party building knowledge bases, avoiding recall of irrelevant data from other categories. |

## Three Common Misconfigurations
- Phenomenon: Empty results are returned after retrieval, with the interface showing no matching content. Cause: `collectionIds` is not limited to the exclusive nuclear power party building collection, and irrelevant knowledge base data from other categories is recalled, leading to matching failure.
- Phenomenon: The number of retrieval results exceeds the configured `limit` value. Cause: The `limit` parameter is not set correctly, or extended queries without configured filter conditions are enabled, recalling redundant content that exceeds the context window limit.
- Phenomenon: The generated response exceeds the scope of the knowledge base content, introducing external knowledge. Cause: The retrieval scope is not strictly limited, or the configuration to only use knowledge base content for response generation is not enabled, leading the large model to use external training data.

## How to Confirm Configurations Are Correctly Set
- Upload a test document exclusive to nuclear power party building, enter a question corresponding to the theme, and check whether the retrieval results include the content of this document.
- Adjust the `similarity` parameter to 0.75, enter a fuzzy matching question, and confirm that the number of recall results meets expectations.
- View the retrieval log to confirm that `searchMode` is `keyword+vector` and `usingReRank` is enabled.
- Enter a question outside the scope of the knowledge base, and check whether a preset custom response is returned.

The values provided are common starting points and should be measured against the reader's own samples.
