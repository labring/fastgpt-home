# Party Building Learning Q&A for Civil Aviation Airports: Conversation Logs and Auditing
This page provides configuration instructions based on FastGPT v4.17.0.

## What Data for This Category Looks Like
The data sources for civil aviation airport party building learning Q&A include official learning documents issued by the airport party committee, party member learning ledgers from each work team, and standardized content synced from the superior party building platform. The data update rhythm is adjusted per the deployment of the superior party committee: official learning documents are updated quarterly, and team learning records are synced weekly. The structure of a single data document includes topic name, publishing entity, effective date, learning text, assessment knowledge points, and applicable job tags. All fields are in text format, with no multi-unit combination fields.

## What Constraints Do These Characteristics Impose on the "Conversation Logs and Auditing" Link
The data for civil aviation airport party building learning Q&A comes from multiple sources and has irregular update rhythms. This requires that conversation logs must be associated with the version of the party building document used in the Q&A, to avoid confusion in audit basis caused by document updates. Party members in different positions correspond to different applicable learning content, so logs must also record the job tag of the asking user, to ensure that the corresponding learning scope can be matched during auditing. At the same time, compliance requirements for airport party building content are strict, so logs must fully retain the question, answer, and called data source identifiers, to meet the audit verification requirements of the superior party committee.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |

| `chatId` Session Identifier | Automatically generated globally | Ensure each conversation is bound to a unique session, enabling audit tracing by conversation dimension |
| `responseChatItemId` Answer Item Binding | Enable single-round binding | Accurately associate the output content of each round of Q&A, avoiding confusion in multi-round conversations |
| `detail` Full Log Switch | Enabled | Retain complete information of questions, answers, and called data sources |
| Log Storage Period | 365 days | Meet the compliance retention requirements for party building content of civil aviation state-owned enterprises |
| Log Write Latency | ≤5 seconds | Ensure latest conversation content can be quickly retrieved during real-time auditing |
| Audit Field Configuration | Include job tags, data source version | Match the job adaptation and version tracing requirements of civil aviation airport party building learning |

## Three Common Misconfigurations
- Phenomenon: Calling the log interface returns a 403 status code, or prompts `common:code_error.error_message.403`. Cause: The permission verification rule for log access is not configured, or the permission scope does not cover the exclusive access path of the civil aviation airport party building application.
- Phenomenon: The output content of the specified Q&A component is not displayed in the workflow history record. Cause: The `detail` full log switch is not enabled, or `responseChatItemId` is not bound to the corresponding Q&A component, resulting in incomplete recording of output content.
- Phenomenon: Historical records generated in debug preview cannot be cleaned up by the specified application. Cause: The application and session are not associated via `chatId`, resulting in missing binding relationship between historical records and the application.

## How to Confirm Successful Configuration
- View the application's log configuration panel, confirm that the `chatId`, `responseChatItemId`, and `detail` configuration items are all enabled.
- Initiate a party building learning Q&A session, check whether the log details include complete question content, answer content, data source version, and user job tag.
- Verify the log storage period configuration, confirm that it meets the retention requirements for civil aviation party building audit compliance.
- Test cleaning the historical records of the specified application, confirm that only the session logs of this application are successfully cleaned.
