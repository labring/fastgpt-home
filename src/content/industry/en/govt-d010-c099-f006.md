# Party Building Learning Q&A for Oil and Gas Exploration and Development: Citation Sources and Traceability

## What the Data in This Category Looks Like
Party building learning data for the oil and gas exploration and development sector mainly comes from internal group party building databases, party building ledgers for exploration and development projects, and industry party building policy documents. Updates follow a monthly rhythm for party building policies issued by the group, and quarterly updates for project party building files of each exploration block.
Document structure includes fields such as document title, publishing entity, publishing date, main body content, associated exploration block number, and project phase identifier. Core identifiers are well numbers, blocks, and project cycles. Some documents include remarks linked to project progress.

## What Constraints These Characteristics Impose on the "Citation Sources and Traceability" Link
Party building learning data has exclusive fields tied to specific exploration blocks and project phases. The traceability link must display associated well numbers, block numbers and other identifiers. Otherwise, it cannot match the actual work scenarios of business personnel.
The monthly and quarterly update rhythm requires the traceability system to support filtering source data by update time. This avoids citing expired old policies or outdated project party building content.
Documents do not have a unified standard format, and some are lengthy. The traceability link must accurately locate the original text position of the cited fragment. This avoids truncating key content linked to the project.
Metadata fields for publishing entity and date require the traceability chain to be fully retained. This allows business personnel to trace the issuing hierarchy and publishing time of the document.

## Three Common Misconfigurations
- Issue: Citation content is returned even when the citation data return switch is not enabled. Cause: In FastGPT v4.17.0, citation caching is enabled by default in some scenarios. Historical citation data will still be displayed if the switch is not manually turned off.
- Issue: Incorrect format is used when configuring knowledge base association parameters, preventing the specified dataset from loading. Cause: The standard variable format required by FastGPT is not used, and non-standard key-value pair structures are incorrectly nested.
- Issue: The knowledge base has imported Q&A pairs, but the returned content is not the original text answer. Cause: The "force use knowledge base original text" switch is not enabled, or the configured maximum cited fragment length is too short to fully match the original text content of the Q&A pair.

## How to Confirm Successful Configuration
- Launch a party building learning question related to a specific exploration block. Check whether the returned content includes metadata such as publishing entity, publishing date, and associated block.
- Turn off the citation data return switch. Launch a test question, and confirm that no citation content is displayed.
- Adjust the maximum number of citations to 1. Launch a test question, and confirm that only 1 citation entry is returned.
- Import a party building document with an exploration block identifier. Launch a question linked to that block, and confirm that the cited content includes the corresponding block information.

The values provided are common starting points and should be measured against the reader's own samples.
