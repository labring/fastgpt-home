# Party Building Learning Q&A for Port and Shipping Industry: Citation Sources and Traceability

## What the data for this category looks like
Party building learning data in the port and shipping sector comes from four main sources: internal party building ledgers, study minutes of the Party Committee Central Group, records of the "three meetings and one lesson" of Party branches, and superior party building work notices.

Data updates follow two rhythms: important work notices are updated immediately upon synchronization, while monthly learning materials are updated in batches each month.

Individual documents range from 500 to 1500 characters. Each document consistently includes five core fields: document title, issuing unit, release time, affiliated port area, and content body. No additional custom unit fields exist.

## Constraints on citation sources and traceability
The fixed field structure of port party building data requires traceability processes to associate metadata such as issuing unit and affiliated port area. This avoids confusion between party building content from different port areas.

The differentiated update rhythm of the data requires configuring two update modes: immediate pulling and scheduled synchronization. This ensures the timeliness of cited content.

The moderate length of individual documents requires careful citation fragment configuration. Fragments cannot be too short, or they will lose key information. Fragments cannot be too long, or they will occupy too much context window space.

The internal source attribute requires traceability displays to match the original data’s storage path or ledger number. This meets compliance requirements.

## Three common configuration errors
- Phenomenon: The citation limit configuration item cannot be saved or modified on the interface. Cause: The operation was not performed on the edit page of the port party building-specific knowledge base, or the configuration mode of the corresponding knowledge base was not activated.
- Phenomenon: The large language model response only provides summarized content, and does not display original text fragments from the associated data source. Cause: The return associated metadata configuration was not enabled, and original fields returned by the database or knowledge base were not included in the citation scope. This corresponds to a missing `responseData` configuration.
- Phenomenon: Citation fragments are truncated, and key traceability information such as release time and affiliated port area is lost. Cause: The maximum citation fragment length was set too small, and it was not adapted to the typical length of individual port party building documents.

## How to verify correct configuration
- Submit a question targeting port party building content. Check the citation section at the end of the response, and confirm that metadata such as issuing unit and release time is displayed.
- Adjust the single search citation limit to 2 entries. Submit a question, and verify that the number of returned citations matches the set value.
- Check the knowledge base configuration logs. Confirm that the citation fragment length parameter has taken effect, and no truncation error messages appear.
- Test calling the associated internal data source. Confirm that the original text fragment content returned by the data source is displayed in the response.

The values listed above are common starting points, and should be evaluated against the user's own samples.
