# Party Building Q&A for Port and Shipping: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data sources for port and shipping party building learning come from official policy documents issued by the group’s party affairs department, party activity logs from frontline terminal party branches, and party building guidance materials from superior transportation authorities.
Update cycles follow a monthly schedule for that month’s key learning points, and a quarterly schedule for typical party building cases and team learning records.
Document structures include policy texts with numbered chapters, standardized Q&A manuals, and supporting audio courseware.
Fields include release document number, affiliated party branch, applicable positions, and effective date.
Units include characters for text content, and minutes for audio content.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Clear publishing entities and applicable positions for party building data require permission filtering during retrieval. This prevents sensitive content leaks across party branches.
Monthly and quarterly update cycles require the knowledge base synchronization cycle to not exceed the update cycle. This ensures content timeliness.
The mixed structure of long-text policy documents and short Q&A manuals requires chunking strategies adapted to different content lengths. This prevents excessive chunking that causes semantic breaks in long texts.
Specialized terminology such as berth scheduling party building linkage and quayside crane operation team learning requires optimized semantic matching accuracy for retrieval. This ensures correct recognition of specialized expressions.

## How to Configure Settings
This page’s configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Aligns with the rigor of party building Q&A, filters low-relevance non-policy content |
| `limit` | Top 8 entries | Balances comprehensiveness of party building content and context length, avoids exceeding model window limits |
| `searchMode` | hybrid | Combines keyword and semantic retrieval, covers matching needs for policy document numbers and specialized terminology |
| `usingReRank` | Enabled | Re-ranks initial retrieval results, corrects semantic matching deviations, ensures key party building content appears earlier |
| `datasetSearchUsingExtensionQuery` | Enabled | Optimizes extended queries for party building questions, maps simplified expressions to complete specialized terminology |
| `collectionIds` | Configured with the exclusive port party building knowledge base ID | Isolates non-party building data, ensures retrieval scope only covers port and shipping party building content |

## Three Common Misconfigurations
- Phenomenon: No matching knowledge base results are returned when calling the chat API, but the debug preview works normally. Cause: `collectionIds` is not correctly configured in request parameters. The knowledge base is only specified in the debug interface, and production requests do not carry the corresponding parameter.
- Phenomenon: Importing party building materials in web link format fails, and logs show permission errors. Cause: No login credentials for web crawling are configured in advance. This prevents access to internal party building document links that require permissions.
- Phenomenon: Non-party building port operation data is mixed in retrieval results. Cause: The `collectionIds` parameter is not set correctly. The retrieval scope includes other business knowledge bases.

## How to Confirm the Configuration Is Correct
- Initiate a test query with the input "Key party building learning points for this branch this month. Check that returned results only include port party building related content, with no business operation data.
- Adjust the `similarity` parameter to 0.7, verify that low-similarity irrelevant content is filtered. Adjust the parameter to 0.9, verify that some compliant content is excluded. Confirm the threshold fits the current scenario.
- After enabling `usingReRank`, check the order of retrieval results. Confirm that key party building policy documents appear earlier.
- Call the API with the correct `collectionIds` parameter. Check that all retrieval result sources in the API response all come from the target party building knowledge base.
