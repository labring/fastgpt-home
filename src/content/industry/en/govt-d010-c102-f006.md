# Party Building Learning Q&A for Refinery and Chemical Production: Source Citation and Traceability

## What the data for this category looks like
Party building study data in the refinery and chemical production field mainly comes from monthly study outlines released by internal party committees, team party building study ledgers, and party building guidelines for production scenarios issued by superior party committees. The data update rhythm follows syncing with superior official documents monthly, and updating exclusive study cases for teams combined with refinery and chemical production quarterly. Document structure includes issuing unit, release date, study topic, production scenario adaptation note, and main content. Data is stored as plain text or structured documents, with no exclusive industry-specific unit fields. The length of single documents varies widely.

## What constraints do these characteristics impose on the "source citation and traceability" link
The mixed structured and unstructured nature of refinery and chemical party building study data requires the traceability link to accurately associate the document's issuing entity and version time. This prevents confusion between party building materials across plant areas and cycles. The monthly updated superior documents and quarterly updated team cases require the traceability chain to sync knowledge base indexes. This ensures returned sources are up-to-date and valid. Some documents include production scenario adaptation notes. Traceability displays must include this field. This helps users verify content matching current production tasks. The wide range of document lengths requires the traceability link to limit the character count per returned source. This avoids disrupting the main conversation flow.

## How to Configure Settings
This configuration is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Matches the typical paragraph length of refinery and chemical party building documents, prevents single sources from taking up excessive space in the main conversation |
| `responseData` | Enabled | Required to return structured fields such as issuing unit and date, to meet traceability requirements |
| `detail` | Basic mode | Only displays core source information, avoids redundant content interfering with quick verification in production scenarios |
| Single recall limit | Top 3 entries | Party building content in refinery and chemical scenarios has strong relevance. Too many sources will distract users; 3 entries cover key reference materials |
| Conversation context cache duration | 600 seconds | Matches the single discussion cycle of team party building studies, ensures traceability content aligns with current conversation logic |

## Three Common Misconfigurations
- Phenomenon: Party building content returned in conversations has no source fields, and no issuing unit, date or other information appears at the end of replies. Cause: The `responseData` configuration item is not enabled, so structured source data is not returned.
- Phenomenon: The release date of party building documents returned via traceability is earlier than the current monthly update cycle, and the content is outdated. Cause: The knowledge base index is not synced according to the monthly/quarterly update rhythm, and old stored content is called.
- Phenomenon: In non-tool call mode, party building Q&A does not return study content matching the current refinery and chemical production scenario. Cause: The `detail` mode is not configured correctly, and the scenario-associated recall logic is not triggered. This leads to generalized recall scope.

## How to Verify Correct Configuration
- Initiate a party building study-related question. Confirm that source fields such as issuing unit and date are attached at the end of the reply.
- Check the release date of the returned source documents. Confirm that they match the current monthly/quarterly update cycle.
- Adjust the value of `quoteMaxToken`. Observe whether the display length of single sources meets expectations.
- Initiate a party building question that includes a production scenario. Confirm that the returned source documents carry the production scenario adaptation note field.

The values provided are common starting points and should be measured against the samples relevant to the respective use case.
