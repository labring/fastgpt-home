# Coal Chemical Industry Party Building Learning Q&A: Deployment and Upgrade

## What this category of data looks like
Data sources include party building policy documents issued by superior coal industry party committees, internal enterprise party building training courseware, monthly team learning plans, and archived materials of party member learning ledgers.
Superior policy documents are synchronized in real time with their release dates. Internal enterprise learning materials are updated once per month.
Document structure primarily uses structured text. Each document includes a title, issuing entity, release date, and main content. Some documents include PDF-format team learning courseware.
Fields include document number, applicable team scope, and learning duration requirement. Units involved include characters, page count, and learning hours.

## What constraints these characteristics impose on deployment and upgrade
These characteristics impose clear constraints on the deployment and upgrade process:
First, data sources include documents from superior industry party committees and internal enterprise team learning materials. Update rhythms combine real-time synchronization and monthly batch updates. Deployments must configure a dual-source synchronization mechanism. Upgrades must add incremental scheduled trigger logic to avoid excessive storage and computing resource usage from full synchronization.
Second, some documents include PDF-format team learning courseware with structured text and embedded attachments. Deployments must adapt to PDF parsing plugins. Upgrades must support multi-column PDF layout formats commonly used in coal chemical enterprises.
Third, fields include subdivided attributes such as applicable team scope and learning duration requirements. Deployments must configure vector database metadata filtering rules. Upgrades must add automatic mapping logic for metadata fields.

## How to set configurations

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://admin:encrypted-pwd@mongodb-host:27017/mol_dm?authSource=admin` | Stores party building knowledge base metadata and user interaction logs. Binds to state-owned enterprise exclusive database instances to ensure data compliance. |
| `REDIS_URL` | `redis://default:encrypted-redis-pwd@redis-host:6379/0` | Caches vector retrieval results and session contexts. Adapts to monthly incremental synchronization tasks. Sets cache validity period to 3600 seconds. |
| `STORAGE_S3_ENDPOINT` | `https://s3.mol-enterprise.com` | Stores PDF team learning courseware and archived documents. Configures a 1000 MB single-file upload limit. |
| `DB_MAX_LINK` | `50–80` | Adapts to concurrent access demands of coal chemical industry party building knowledge bases. Prevents database connection pool overflow. |
| `ROOT_KEY` | `Randomly generated 32-character string with no special characters` | Verifies highest permissions for the admin backend. Only accessible to dedicated party building project administrators. |
| `FE_DOMAIN` | `https://dm.mol-enterprise.com` | Configures frontend access address. Adapts to cross-domain rules of internal enterprise office networks. |
| `FILE_TOKEN_KEY` | `Signature key bound to STORAGE_S3_ENDPOINT` | Generates download links for PDF courseware. Adapts to access paths behind Nginx proxies. Prevents link expiration. |

## Three common mistakes
- Issue: After configuring an Nginx proxy, download links for knowledge base PDF courseware return a 404 status code. Cause: Failed to correctly configure the signature rules between `FILE_TOKEN_KEY` and the Nginx proxy, leading to failed download link signature verification.
- Issue: After deployment, party building Q&A results are never generated. Returns empty content with no clear error message. Cause: Failed to correctly fill in the database authentication information for `MONGODB_URI`. Unable to read knowledge base metadata and trigger retrieval processes.
- Issue: After starting via docker-compose, configured environment variables do not take effect. Cause: Failed to correctly declare environment variables in the docker-compose.yml file, and failed to rebuild containers to load new configurations. This issue requires explicit configuration via corresponding fields in FastGPT v4.17.0.

## How to confirm configurations are correct
- The frontend address configured in `FE_DOMAIN` is accessed to verify normal login of the admin backend and validate the permissions of `ROOT_KEY`.
- A PDF courseware for coal chemical industry team party building learning is uploaded to check upload progress and storage path, and to verify correct configuration of `STORAGE_S3_ENDPOINT`.
- An incremental synchronization task is executed to check knowledge base update logs and verify normal connections for `MONGODB_URI` and `REDIS_URL`.
- A test question related to party building is generated to check if Q&A results return matching learning materials, and to verify effective configuration of vector retrieval and metadata filtering.
