# Coal-Electric Integration Party Building Learning Q&A: Knowledge Base Retrieval and Recall

## Data Profile
The data sources for coal-electric integration party building learning Q&A primarily come from party building management systems of central and local state-owned enterprise coal sectors. The main document types include Word-format party lecture materials, PDF-format superior party building documents, and Excel-format party member learning attendance and statistical ledgers. There are two update schedules: Official party building learning materials are updated monthly alongside group policies. Temporary learning notices and overseas project team party building ledgers are updated incrementally weekly. Document fields include file title, issuing unit, release date, applicable scenario, learning duration, participant count, and more. Units include hours, counts, MB, and others. Some Excel ledgers include structured applicable region fields.

## Constraints on Knowledge Base Retrieval and Recall
Mixed-format data sources require the retrieval system to support cross-format semantic matching and structured field filtering. Failing to support multiple document formats will result in missed Excel data. The applicable scenario field requires retrieval to accurately match detailed conditions such as domestic or overseas projects. Otherwise, overseas party building data will have insufficient recall rates. Data sources with different update schedules need flexible incremental synchronization rules. These rules prevent old data from overwriting new content, and prevent new data from failing to enter the database in a timely manner. The coexistence of long and short documents requires a retrieval chunking strategy tailored to different content lengths. This ensures complete semantic recall.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Matches the semantic similarity range for party building content, filters low-relevance non-party building results |
| `limit` | Top 10 entries | Matches the single-recall quantity for party building learning Q&A, ensures context length meets conversation scenario requirements |
| `searchMode` | Exact match | Addresses the precise retrieval need for structured fields such as applicable scenarios, prevents irrelevant results from being included via fuzzy matching |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, improves the accuracy of relevance ranking for party building content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonyms related to party building for queries. For example, expands "three meetings and one class" to branch meetings, party lecture learning, and other related terms, covering more semantic scenarios |
| `collectionIds` | Specify coal sector party building collection IDs | Limits the retrieval scope, prevents non-party building documents from other business sectors from being included |

## Three Common Misconfigurations
- Phenomenon: When retrieving overseas project party building data in Excel, the number of returned results is far fewer than the valid entries in the Excel file. Cause: `datasetSearchUsingExtensionQuery` is not enabled, or `searchMode` is set to fuzzy matching, which cannot accurately match the structured field of "applicable region: overseas".
- Phenomenon: When calling the FastGPT interface for self-built system integration, an `Error: write EPROT` error is returned. Cause: HTTPS security certificates are not configured correctly, or requests do not carry valid API authentication keys.
- Phenomenon: Knowledge base retrieval returns a `Query read timeout` error. Cause: The `limit` setting is too high, causing the total data volume of a single retrieval to exceed the system timeout threshold, or `usingReRank` is not configured properly, leading to excessive time spent in the ranking phase.

## How to Verify Configuration Validity
- Upload a party building attendance Excel file marked "applicable region: overseas", run the retrieval keyword "overseas project party building learning", and check whether the corresponding entry of this file is included in the returned results.
- View the knowledge base configuration page in the FastGPT backend, confirm that `collectionIds` only selects coal sector party building-related collections, and no other unrelated collections are included in the retrieval scope.
- Run a retrieval for a long-format party lecture material, check whether the returned results are sorted according to the relevance priority of party building content, and confirm that `usingReRank` is active.
- Call the FastGPT knowledge base retrieval API, check whether the `similarity` value of the returned results falls within the 0.75–0.85 range, and confirm that the configuration parameters are effective.
- Confirm that the current FastGPT version is v4.17.0 to avoid parameter configuration incompatibility.
