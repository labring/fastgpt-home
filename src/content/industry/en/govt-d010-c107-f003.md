# Party Building Learning Q&A for Coal Mine Production: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
The data for coal mine production party building learning Q&A mainly comes from internal party building archives of state-owned enterprises, records of "three meetings and one lesson", party member learning ledgers, and special party building documents combined with coal mine safety production. Data updates are synchronized with the release of new learning materials, with at least one update per month. Most documents are in structured format, including fields such as document ID, issuing unit, applicable positions, release date, and main content. The length of a single document is mostly 5000–10000 characters, and special learning materials will be split into paragraphs of no more than 2000 characters per segment.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words link
The position restriction field in coal mine party building data requires multi-turn dialogue to retain the current dialogue's position context, otherwise retrieval cannot match the learning materials corresponding to the target position. The structured fields of the document require prompt words to extract information such as the user's party branch and position to narrow the retrieval scope. Since data updates have no fixed cycle, each dialogue must trigger knowledge base retrieval to avoid generating outdated content. The relatively long length of single documents requires the multi-turn dialogue context window to balance the retention of historical information and retrieval load.

## How to set configurations
This document applies to FastGPT v4.17.0. The following configuration items are formulated based on the characteristics of the coal mine party building scenario:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window size | 8000–12000 token | Coal mine party building documents contain long-paragraph learning materials, requiring retention of position and topic context across multi-turn dialogue |
| `variables` parameter configuration | Pre-set three fixed global variables: party branch, position, and learning cycle | Coal mine party building learning needs to be bound to specific positions and party branches to improve retrieval accuracy |
| `messages` parameter configuration | Retain the context of the most recent 10 dialogue turns | Multi-turn party building Q&A needs to track learning progress to avoid repeated questions and loss of context |
| Forced retrieval switch | Enabled, triggered for every dialogue | Coal mine party building content must match the latest learning materials to avoid deviations from generated content without retrieval |
| `chatId` parameter configuration | Bind session ID to associate with global variables | Ensure that multi-turn dialogue under the same party branch shares preset variables without repeated input |
| Retrieval timeout threshold | 60 seconds | Balance retrieval efficiency and content integrity, avoiding excessive waiting time for a single dialogue turn |

## Three common misconfigurations
- Phenomenon: When configuring knowledge base ID binding variables, the interface pops up a parameter error prompt, and the variable field shows empty. Cause: The scope of the variable is not correctly declared in the `variables` parameter, causing the dialogue engine to fail to recognize the bound knowledge base ID.
- Phenomenon: Some dialogues do not trigger knowledge base retrieval, and the response content does not match the party building learning theme. Cause: The forced retrieval trigger rule is not set, or the context retained by the `messages` parameter exceeds the preset length, causing the retrieval logic to be skipped.
- Phenomenon: As the number of question rounds increases in multi-turn dialogue, response latency increases significantly, and a single retrieval takes more than 60 seconds. Cause: The number of context rounds retained by the `messages` parameter is too high, leading to excessive context splicing and matching load during knowledge base retrieval.

## How to verify successful configuration
- Initiate a query that includes party branch and position information, check whether the returned content matches the party building learning materials corresponding to the target position.
- Initiate 3 consecutive related queries, check whether the global variables bound by the `variables` parameter are always retained and not automatically cleared.
- Initiate a query without prior context, check whether knowledge base retrieval is forcibly triggered, and no unsupported generated content appears.
- Initiate 3 consecutive queries, check whether the response latency is stable, with no obvious delay as the number of rounds increases.

The values listed above are common starting points and should be evaluated against the user’s own samples.
