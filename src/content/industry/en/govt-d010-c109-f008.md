# Party Building Learning Q&A for Power Grid Enterprises: Document Parsing and Chunking

This document is written based on FastGPT v4.17.0.

## What this category of data looks like
The data sources for power grid enterprise party building learning Q&A mainly include internal party building management systems, policy documents issued by superior party organizations, three meetings and one lesson meeting minutes, study manuals, and internal training PPTs. The document update rhythm is not fixed: superior policy documents are updated irregularly with work deployments, and internal study materials are updated in batches quarterly or monthly. Documents include formal official document formats with titles, document numbers, issuing units, and release dates. Meeting minutes are mostly speech-to-text content, and study ledgers often record data such as study duration (unit: hours) in Excel tables.

## What constraints do these characteristics impose on the document parsing and chunking link
Redundant information such as headers, footers, and document numbers in formal official documents will interfere with text extraction, so precise filtering is required. Speech-to-text meeting minutes have colloquial sentence breaks, so context semantic association must be retained during chunking. Excel-format study ledgers contain structured table data, so table parsing rules must be adapted to extract cell content. Irregular batch uploads of large documents require the parsing process to have sufficient fault tolerance and timeout handling capabilities. Metadata such as issuing units and release dates attached to documents must be bound to text chunks for subsequent traceable display of search results.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Power grid party building documents include both long paragraphs of formal official documents and short entries of study key points. This range balances context integrity and search accuracy |
| `chunkSplitter` | By title + paragraph | Party building documents have clear chapter titles and paragraph structures. Following this rule for chunking preserves semantic integrity |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | Party building learning materials uploaded by power grid enterprises may include multi-page PDFs and large PPT collections. This upper limit covers most business scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Parsing large multi-page party building documents takes a long time. This range avoids parsing failures caused by timeouts |
| `customPdfParse` | Enabled | Power grid party building PDF documents often contain redundant information such as headers, footers, and document numbers. Enabling custom parsing allows precise extraction of main text content |

## Three common misconfigurations
- Phenomenon: After uploading an Excel-format party building study ledger, the parsing result is empty or only extracts the header. Cause: Table file parsing adaptation is not enabled, and the default parsing rules do not cover structured table-style party building documents.
- Phenomenon: Large party building PDF document parsing tasks show a timeout, with a status code of 504. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default timeout threshold is insufficient to support the parsing process for large documents.
- Phenomenon: Search return results do not include metadata such as issuing units and release date for the chunks. Cause: Metadata binding rules are not configured, only the main document text is extracted, and document attribute fields are not associated.

## How to confirm configurations are correctly set
- Upload a typical power grid party building PDF document, view the parsed chunk content, and confirm that chapter titles and main text paragraphs are correctly split.
- Upload an Excel-format party building study ledger, verify that the parsing result includes table cell content with no empty values or missing fields.
- Submit a test query, check that the returned results include metadata such as the document's issuing unit and release date.
- Adjust the `chunkSize` parameter, re-upload the test document, and confirm that the chunk length matches the expected setting.
