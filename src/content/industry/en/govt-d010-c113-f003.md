# Party Building Learning Q&A for Shipbuilding: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Shipbuilding industry party building learning Q&A data primarily comes from internal enterprise party building ledgers, industry party building guidance documents issued by the group party committee, learning records of branch parties in each workshop, and annual party building assessment archives. Data updates follow a set rhythm: synchronize the group’s latest party building requirements monthly, and update frontline branch learning cases quarterly. Most documents are formal, chaptered manuscripts with fields including document number, issuing unit, release date, applicable branch scope, and units such as "branch", "learning hours", and "document page number".

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The data characteristics of shipbuilding party building Q&A create clear constraints for multi-turn dialogue and prompt configuration. First, data is divided by branch scope. Prompts must guide conversations to stay within the applicable content for the corresponding branch, preventing recall of irrelevant documents across scopes. Second, the monthly and quarterly update cycle requires the dialogue system to align with the knowledge base synchronization schedule to ensure returned content is timely. Third, the formal document structure requires prompts to focus on single-chapter content, avoiding information overload from vague questions. Finally, scattered frontline branch learning records require multi-turn dialogue to retain context and link to prior learning topics, ensuring question coherence.

## Configuration Guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind a unique identifier to each session, reuse within 7 days of the session being active | Party building learning for shipbuilding branches is mostly a coherent scenario, requiring retention of context links to avoid repeated dialogue initialization |
| `messages` | Retain the first 10 rounds of conversation context, maximum 8000 tokens | Party building documents are formal in content; overly long context will dilute core learning information and affect matching accuracy |
| `variables` | Pass two variables: `{applicable branch type}`, `{current learning topic}` | Party building requirements vary across branches in different workshops, requiring precise limitation of retrieval scope to match exclusive learning content |
| Maximum context length | 800–1200 characters | Single-chapter content of party building documents is concentrated; overly long context will interfere with recall and matching of core information |
| Question Optimization | Enabled | Frontline workers often use colloquial expressions when asking questions; optimization can match the formal expressions of internal party building documents and improve recall accuracy |
| Single Search Limit | Top 3 matching results | Party building learning Q&A needs to focus on core content, avoiding excessive redundant information interfering with learning judgment |

## Three Common Misconfigurations
- The first question takes over 3 seconds to respond, while subsequent responses work normally. This happens because the vector index for the shipbuilding party building-specific knowledge base loads on first use, and no preheating cache mechanism is configured.
- After switching question topics during a conversation, the previous learning workflow cannot be reused. This occurs because `chatId` is not bound to reuse session context, so the dialogue state resets with each new question.
- After configuring automatic questioning in a workflow, retrieval matching party building documents does not trigger. This is because the preset learning topic parameter is not passed in `variables`, leaving the retrieval scope without clear limits.

## How to Verify Proper Configuration
- Initiate a first question, check that the response duration meets expectations, and confirm the preheating cache mechanism is active.
- Submit three consecutive related questions, check that the conversation context retains the prior learning topic, and confirm `chatId` is bound correctly.
- Pass the `variables` parameter and limit the branch type, check that recalled documents only include learning content for the corresponding branch.
- Configure automatic questioning in a workflow, check that retrieval of party building documents triggers automatically and matching results are returned.
