# Party Building Learning Q&A for Shipbuilding: Deployment and Upgrade

## What the data for this category looks like
Party building learning Q&A data for state-owned shipbuilding enterprises is sourced from internal party building archive materials, regularly updated party lesson slides, and industry party building policy documents. The update cycle runs monthly, and is also triggered when major policy documents are released.
Most documents are long PDFs or Word files with hierarchical headings, with fixed fields including document title, issuing unit, release date, and main content. Single document length varies widely, with no unified fixed character limit. Some supporting audio transcription documents include timestamp fields.

## What constraints these characteristics impose during deployment and upgrade
The high proportion of long documents requires configuring support for large file indexing during deployment, to avoid single-document load timeouts or truncated retrieval content.
The fixed monthly update cycle requires reserving incremental sync configuration entries during upgrades, so full re-import of all party building documents is not required each time.
The document structure with multiple fixed fields requires presetting field mapping rules during deployment, to ensure imported party building documents can correctly associate metadata for precise retrieval.
The presence of timestamp fields in some documents requires supporting indexing logic for new fields during upgrades, to prevent metadata loss for historical documents.

| `FILE_TOKEN_KEY` | Custom random 32-character string | Verifies the legitimacy of uploaded party building documents, prevents unauthorized file imports, and complies with internal deployment security requirements |
| `ROOT_KEY` | Custom complex string | Manages the highest permissions for the FastGPT backend, only used for configuration modifications during deployment and upgrades, to avoid accidental operations by users with standard permissions |

## Three Common Misconfigurations
- Scenario: Attempting to process long PDF documents for shipbuilding party building using the Marker tool results in a "file processing failed" prompt in the interface, with a 500 status code returned in backend logs. Cause: The `DB_MAX_LINK` value was not adjusted, leading to database connection pool exhaustion during large file import.
- Scenario: After upgrading FastGPT, the number of context split fragments for party building Q&A is lower than in the previous version, and retrieved content is incomplete. Cause: The knowledge base indexing rules were not reconfigured after the upgrade, and default parameters from the old version were retained.
- Scenario: After adding a locally deployed large model, importing the party building knowledge base triggers a connection timeout error. Cause: `STORAGE_S3_ENDPOINT` was not configured correctly, leading to failure to load knowledge base files normally during model inference.

## How to Verify Successful Configuration
- Run the docker-compose ps command to confirm all FastGPT-related containers are in a running state.
- Upload a test shipbuilding party building document to confirm successful import and index generation.
- Submit a test Q&A related to party building to confirm matching document fragments and answers are returned.
- Access the domain configured via `FE_DOMAIN` to confirm the backend management interface can be logged into normally and the knowledge base running status can be viewed.
