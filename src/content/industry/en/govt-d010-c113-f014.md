# Party Building Learning Q&A for Shipbuilding: Conversation Logs and Auditing

## What the data for this category looks like
Data for shipbuilding sector Party building learning Q&A comes from internal Party building intranet documents of state-owned shipbuilding enterprises, monthly learning guidelines issued by industry Party committees, and learning records from each workshop and team. Updates occur on a weekly sync schedule, aligned with workshop weekly learning plans.

Document structure includes fields such as title, issuing unit, release date, main content, and applicable workshop (e.g., hull workshop, engine workshop). Release dates use the YYYY-MM-DD format. Single document character counts range from 2000 to 8000. Single file sizes mostly fall between 0.5 and 2 MB.

## What constraints these characteristics impose on conversation logs and auditing
Documents include the applicable workshop field, so conversation logs must be linked to specific teams to avoid mixing cross-workshop learning records.
The weekly update rhythm requires audit cycles to align with weekly learning plans, ensuring all weekly learning Q&A are fully covered.
Longer single document character counts require logs to fully record conversation context, preventing loss of critical information during traceability.
The internal nature of Party building materials requires logs to have hierarchical access permissions, allowing only compliant personnel to view sensitive content.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` binding rule | Bind to the exclusive ID of the shipbuilding workshop team | Match the scenario where Party building learning is carried out by teams, avoid cross-team log mixing |
| `responseChatItemId` recording switch | Enable full recording | Cover the complete process from question to answer, meet audit traceability requirements |
| `detail` log field configuration | Include issuing unit and applicable workshop fields | Match the structured characteristics of Party building documents, facilitate audit filtering by dimension |
| Log retention period | 90 days | Meet the conventional cycle requirements of state-owned enterprise Party building audits |
| Log query timeout | 30 seconds | Avoid retry limit exceeded issues when associating knowledge base documents |
| Log export format | Package in CSV format | Facilitate subsequent import into audit systems for batch verification |

## Three common configuration mistakes
- Phenomenon: Party building learning conversations carry previous team learning records without triggering context association. Cause: The `chatId` is not bound to the exclusive identifier of the corresponding team, leading to incorrect classification of historical sessions.
- Phenomenon: Audited exported logs do not include the applicable workshop field of the document. Cause: The recording of the corresponding structured field is not enabled in the `detail` configuration, resulting in missing critical classification information.
- Phenomenon: "Reached the max retries" error occurs when auditing and querying knowledge base records. Cause: A reasonable log query timeout parameter is not set, leading to exceeded request timeout counts when associating knowledge base documents.

## How to confirm the configuration is correct
- Log in to the FastGPT v4.17.0 backend, initiate a Party building learning conversation for the corresponding team, and check if the `chatId` in the conversation list matches the preset team exclusive identifier.
- Export a conversation log and check if it includes the issuing unit and applicable workshop information configured in the `detail` field.
- Test initiating a question with historical records to confirm that the context association function works properly.
- View the container runtime logs to confirm that there are no error messages related to log writing or query timeouts.
