# Party Building Learning Q&A for Rail Transit Equipment: Citation Sources and Traceability

## What This Category of Data Looks Like
The data for Party Building learning activities at rail transit equipment manufacturing enterprises comes from the enterprise’s internal Party Building work platform, standardized learning documents issued by the superior party committee of the State-owned Assets Supervision and Administration Commission, and monthly learning minutes from each branch. The update schedule is one learning courseware update per week, and one official party committee document update per month. Documents use a unified structured format with five fixed fields: title, main text, issuing entity, release date, and associated policy number. All fields are plain text or follow the standard YYYY-MM-DD date format, with no nested attachments or unstructured content.

## Constraints for Citation Sources and Traceability
The fixed issuing entity and policy number fields for Party Building learning documents require the traceability process to display these non-main-text pieces of information, to ensure the traced content fully matches the original document. The weekly and monthly update schedule requires the traceability link to automatically label the document’s latest release date, to avoid returning outdated learning materials. The plain-text structured document format requires that fields extracted during traceability exactly match the original document’s fields, with no alterations or missing content. Additionally, most Party Building documents for rail transit equipment enterprises are stored on internal private networks, so traceability links must adapt to internal network access permissions to ensure authorized users can directly jump to the original document.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 3000–5000 token | Most single Party Building documents for rail transit equipment enterprises are 1000–3000 characters long; this range reserves sufficient tokens to fully extract all document fields and main text |
| Single search limit | Top 3 results | Meets the precision requirements for Party Building learning Q&A, avoiding excessive redundant documents that interfere with traceability judgments |
| `responseData` | Include title, issuing entity, release date, associated policy number | Matches the fixed document structure, ensuring the fields displayed in traceability exactly match the original document |
| Traceability link generation rule | Bind the enterprise’s internal network access domain name | Adapts to the enterprise’s internal private network access permissions, ensuring authorized users can normally jump to the original document |
| `detail` | Enable full field display | Supplement non-main-text information such as issuing entity and policy number, enhancing the credibility of traceability |
| Context window limit | 8000–10000 token | Adapts to the total length of spliced multiple documents, avoiding truncation of critical traceability information |

## Three Common Configuration Errors
- Phenomenon: The number of citations configured in the workflow only returns 2 results, which is far below the knowledge base search limit. Cause: Failure to distinguish between the default `quoteMaxToken` parameters for knowledge base search and workflows; the workflow default value is lower.
- Phenomenon: Only the main text is displayed in traceability results, with no issuing unit or policy number shown. Cause: `responseData` was not configured to extract specified fields, only plain main text content was returned.
- Phenomenon: Clicking the traceability link fails to access the original document. Cause: The enterprise’s internal network domain name was not adapted, and a public network link format was used to generate the traceability address.

## How to Verify Configuration Success
- Initiate a Party Building learning-related query, check whether the returned results include the required fields such as document issuing entity and release date as configured.
- View the configuration panel of the workflow or knowledge base node, confirm that the `quoteMaxToken` value matches the document length of the current scenario.
- Click the traceability link, verify that it can normally access the original document in the enterprise internal network environment.
- Compare the number of traceability results from different queries, confirm that the single search limit configuration has taken effect.
