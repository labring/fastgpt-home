# Party Building Learning Q&A for Rail Transit Equipment: Document Parsing and Chunking

## What the Data for This Category Looks Like
Party building learning data for rail transit equipment enterprises mainly comes from policy documents issued by the enterprise party committee, monthly learning records from workshop teams, annual party building ledgers, and study notices from superior party organizations. Update frequency follows: policy documents are updated quarterly, monthly learning materials are updated monthly, and ledgers are archived annually. Document types include official policy PDFs, Word-format study reflection templates, and Excel-format attendance and study hour statistics tables. Fields include document number, issuing unit, study topic, attendees, study hours, and more. Units are mostly hours and person-times. Document number format follows the pattern: [Party Issue] (Year) XX.

## Constraints Imposed on Document Parsing and Chunking
Multi-type formats of party building documents require parsing tools to support PDF, Word, and Excel simultaneously. This avoids content loss caused by single parsing rules.
Long text and hierarchical structures in policy documents require retaining the association between titles and main text during chunking. Forced splitting by fixed character count must be avoided.
Multi-field associations in Excel tables require retaining corresponding relationships between cells during parsing. Extracting isolated content alone will damage data integrity.
Some PDF files include irrelevant headers and footers such as enterprise logos and workshop addresses. These must be filtered before chunking to prevent irrelevant content from interfering with retrieval.
Large monthly bulk imported material packages require adapting to higher file upload and parsing timeout thresholds. This avoids task interruptions.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific parameters are listed below:
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the single-block content length of policy texts and study reflections in party building documents, avoiding splitting key sentences |
| `chunkSplitter` | Split by paragraph + title | Match the hierarchical structure of party building documents, retaining the logical association between study topics and main text |
| `customPdfParse` | Enable header and footer filtering | Remove irrelevant content such as enterprise logos and document numbers from PDF files of rail transit equipment enterprise party building materials, improving parsing accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Address the long parsing time of lengthy policy documents, avoiding timeout failures |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Comply with bulk imported monthly party building study material packages |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different types of party building documents (policy/table/reflection) to adapt to scenario requirements |

## Three Common Misconfigurations
- Phenomenon: A large number of garbled Chinese characters appear when OCR parsing PDF files of workshop party building bulletin boards. Cause: The Chinese-adapted document parsing mode is not enabled, leading to incorrect recognition of printed Chinese characters.
- Phenomenon: After importing Excel-format party building study attendance sheets, the knowledge base retrieval results cannot match the corresponding relationship between attendees and study hours from the original table. Cause: No field binding rules are configured for table datasets; the default chunking only extracts single-cell content, losing associated relationships.
- Phenomenon: When retrieving chunked party building policy texts, only isolated sentences are recalled, and the reference annotations of superior documents are not associated. Cause: `chunkSplitter` is configured to split by fixed character count, without retaining the document's hierarchical structure and reference associations.

## How to Confirm Successful Configuration
- Upload a single party building policy PDF file, check if the parsed text has filtered out enterprise logos and document numbers from headers and footers, confirming that the `customPdfParse` configuration takes effect.
- Import an Excel-format study attendance sheet, check if each chunked content in the knowledge base contains complete associated fields such as attendees and study hours, confirming that the table mapping rules are configured correctly.
- Generate a test retrieval request, input "2024 Party Building Study Plan", check if the recalled results include corresponding study topics and main text, confirming that `chunkSplitter` retains the document's hierarchical structure.
- Upload a single party building material package with a size of 400 MB, check if the parsing task is completed within the time set by `PARSE_FILE_TIMEOUT_SECONDS`, confirming that the timeout configuration is reasonable.
