# Party Building Learning Q&A for Telecommunications Engineering Construction: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Telecommunications engineering construction sector party building learning data primarily comes from party building documents issued by superior party committees, on-site party member activity records from project sites, party building demonstration site materials for engineering sections, and specialized learning documents tailored to telecommunications engineering scenarios.
The update rhythm is uneven: superior documents are updated quarterly, on-site activity records are updated monthly, and specialized documents are synced with project progress milestones.
Document structures include main text, images such as party building activity photos and engineering party building signage images, and attachment courseware. Fields include document number, issuing unit, affiliated engineering area, topic category, and associated section number. Some documents include multimedia attachments measured in megabytes (MB).

## Constraints imposed by these characteristics on knowledge base retrieval and recall
A large number of documents include images. Plain text retrieval cannot recognize party building key points within images, leading to missed visual engineering party building content in recall results.
Documents are associated with exclusive fields such as engineering sections and regions. Retrieval requires targeted matching based on these fields, otherwise accurate recall of party building materials for the corresponding engineering scenario is not possible.
Uneven update rhythms require flexible configuration of incremental synchronization rules to avoid retrieval data lagging behind on-site party building activities.
Some documents have lengthy content. Combined with project progress and party building requirements, context association must be retained during chunking to avoid semantic fragmentation that affects retrieval accuracy.

This configuration is based on FastGPT v4.17.0.
## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | 0.72–0.80 | Telecommunications engineering party building documents contain technical terms and engineering-specific content. A threshold that is too low will introduce irrelevant general party building content, while a threshold that is too high will miss party building materials associated with engineering sections. This value is calibrated based on actual testing. |
| `limit` | Top 8 entries | Single party building documents are associated with engineering information. Too many results will exceed the context window, while too few will fail to cover the party building needs of multiple sections. |
| `searchMode` | hybrid | Adapts to documents with mixed text and image metadata. Combines full-text and vector retrieval capabilities to cover more associated content. |
| `usingReRank` | Enabled | There are many entries with similar topics in party building documents. Reranking can prioritize recalling party building content tied to engineering scenarios. |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands party building keywords related to engineering to match specialized learning materials and expand retrieval recall scope. |
| `collectionIds` | Knowledge base collection bound to engineering sections | Targeted retrieval of party building documents for corresponding sections to avoid irrelevant content across sections. |

## Three common mistakes
- Phenomenon: Retrieval results do not include image-related party building key points from the document, only text content is returned. Cause: Image parsing extension capabilities are not configured, or `datasetSearchUsingExtensionQuery` is not enabled, so image metadata within the document cannot be recognized.
- Phenomenon: A locally deployed knowledge base cannot retrieve data, or a prompt indicates data has expired. Cause: The local storage mount path of the knowledge base is not correctly configured, data was cleared due to expired subscription, or file encryption rules and retrieval engine compatibility settings are not confirmed.
- Phenomenon: The number of retrieval return results does not match the configured `limit` parameter, with excess or insufficient results. Cause: The value range of the `limit` parameter is not correctly set, or different retrieval logics are mixed, leading to parameter conflicts.

## How to confirm the configuration is correct
- Upload an engineering party building document with images, perform a party building question retrieval that includes the engineering section number, and check if the results include image-related associated content.
- View the retrieval log to confirm that the number of returned results matches the configured `limit` parameter.
- Check that the `collectionIds` parameter is bound to the knowledge base collection corresponding to the current engineering section to avoid retrieving irrelevant content across sections.
- Check the storage directory configuration of the local knowledge base to confirm that the retrieval engine can access the document files in the corresponding path.

The values provided are common starting points and should be evaluated against the reader's own samples.
