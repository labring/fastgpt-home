# Party Building Learning Q&A for Communication Towers and Infrastructure: Citation Sources and Traceability

## What This Category of Data Looks Like
Data comes primarily from internal party building learning libraries of communication tower and infrastructure enterprises. It includes study documents issued by higher-level party committees, branch activity records, party building knowledge question banks, and industry party building compliance documents. Sync official latest policy documents monthly. Document formats are mostly Markdown and PDF. Single document lengths vary widely. Fields include document title, issuing unit, release time, document category, and main text. No unified mandatory unit applies. Some documents include attachment links.

## Constraints These Characteristics Impose on Citation Sources and Traceability
Document sources include internal organized materials and materials issued by higher-level authorities. Accurately match the issuing unit and release time fields during traceability to ensure cited content has proper authority. Configure regular sync tasks to follow the fixed monthly update rhythm, keeping cited content synchronized with official latest policies. Support parsed text blocks from both Markdown and PDF formats to avoid losing formatted content that would make traceable text incomplete. Some older documents lack standardized category fields, so add fuzzy matching rules to cover traceability needs for more historical documents.

## Three Common Errors
- Phenomenon: The citation list returned when calling the chat interface is empty, and the answer is not associated with any document. Cause: The `detail` configuration item is not enabled, or the knowledge base sync task did not execute normally, and party building documents were not loaded into the vector database.
- Phenomenon: When configuring a knowledge base search node in a workflow, the specified knowledge base cannot be referenced via variables. Cause: Variable reference permission is not enabled in the workflow node, or the incoming knowledge base variable format does not meet FastGPT requirements.
- Phenomenon: Parsing errors occur when using {{}} format to reference variables in an HTTP node. Cause: The variable format is not adjusted according to the FastGPT recommended calling method, and continued use of the {{}} format causes compatibility issues.

## How to Confirm Proper Configuration
- Submit a party building-related test question, then check if associated document titles, release times and other traceability information appear at the end of the answer.
- Enter the knowledge base management page, check if the sync log shows the most recent sync task completed successfully with no error records.
- In the workflow debugging interface, pass a custom knowledge base variable, verify if the knowledge base search node correctly calls the specified knowledge base.
- Check the `responseData` field returned by the chat interface, confirm it contains the expected citation source content.
