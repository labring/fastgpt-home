# Party Building Learning Q&A for Metal Material Processing: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data mainly comes from internal party building learning archives of metal material processing enterprises, party building study guidelines issued by industry party committees, and compliance training documents combined with production processes. The update frequency is once per month, adding special content that combines the current month's party building study key points with production processes. The structure of each single document includes three fields: topic, main body, and associated process node. The topic field has no fixed unit. The character count of the main body ranges from 800 to 3000 characters. The associated process nodes are based on production process sequence numbers.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The monthly data update requirement means the retrieval link must support incremental synchronization to avoid resource consumption caused by full reconstruction. The wide span of main body text length requires setting reasonable chunking rules, to avoid semantic fragmentation from overly long chunks or missing information from overly short chunks. The associated process nodes are based on process sequence numbers, so retrieval must prioritize matching the process association field bound to party building questions in the document, to avoid recalling generic party building content disconnected from production scenarios. Document sources are scattered, so recall weights must be set separately for internal archives and industry guidelines, to ensure the Q&A aligns with the party building study needs of metal material processing.

## How to set the configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Semantic relevance range for matching metal material processing party building documents, filters low-correlation content |
| `limit` | `Top 6 entries` | Controls total character count of retrieved content within the 1200–1800 character range, complies with token usage specifications |
| `usingReRank` | Enabled | Targeting the field characteristics of associated process nodes, reranking can improve the recall priority of party building content bound to production scenarios |
| `datasetSearchUsingExtensionQuery` | Disabled | Ensures party building learning Q&A only uses internal knowledge base data, avoids introducing irrelevant external content |
| `collectionIds` | `Bind the exclusive dataset ID for metal processing party building` | Separates generic party building data from industry-specific data, narrows the recall scope |
| `searchMode` | `Semantic retrieval` | Adapts to the long text structure of party building documents, improves recall accuracy of key knowledge points |

## Three common mistakes
- Phenomenon: A large amount of idle chat content unrelated to party building learning is included in the retrieval results, and the associated process node field is empty. Cause: The `similarity` threshold is not configured, or the threshold value is set too low, resulting in misrecall of low-correlation content.
- Phenomenon: An online search request is automatically triggered after the knowledge base matches no results. Cause: The `datasetSearchUsingExtensionQuery` configuration is enabled, and no interception rule is set for empty results, causing the system to call external search.
- Phenomenon: The total character count of a single retrieval result exceeds the context window limit, and the reply is truncated. Cause: The `limit` value is not adjusted based on the length characteristics of metal material processing party building documents, resulting in too many recalled entries.

## How to confirm the configuration is correct
- Upload a special metal material processing party building document, initiate a corresponding question retrieval, and check whether the recalled results include the core content of this document.
- Initiate a retrieval for an unrelated idle chat question, and check whether the recalled results are filtered by the `similarity` threshold, with no valid matching content.
- View the retrieval log, confirm that only internal knowledge base data is called, and no external online search request is triggered.
- Adjust the `limit` value, check that the number of returned result entries matches the preset value, and the total character count meets the context window requirements.

The values provided are common starting points and should be measured against the reader's own samples.
