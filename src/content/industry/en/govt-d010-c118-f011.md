# Party Building Learning Q&A for Metal Material Processing: Forms and Interactions

## What this category of data looks like
Party building learning Q&A data for the metal material processing field comes from internal party building knowledge bases of Chinese state-owned enterprises and public sector entities. It covers categorized content including thematic education, clean government construction, party affairs workflows, and other topics. Data is updated once per month. Documents are stored as structured text, with fields including document ID, category tags, release date, source unit, and more. The character count per individual document ranges from 1000 to 5000 characters, and most individual file sizes fall between 1 and 5 MB.

## What constraints these characteristics impose on forms and interactions
The characteristics of party building data in the metal material processing field impose multiple constraints on the forms and interactions workflow. The wide range of character counts per document requires configuring appropriate content truncation rules in the interaction workflow to avoid exceeding the context window. Data is archived by category tags, so forms must support filtering retrieval scope by party building themes to narrow matching scope. The data updates once per month, so the interaction workflow must regularly sync the knowledge base update status to avoid returning expired content. Most individual file sizes fall between 1 and 5 MB, so form attachment uploads must limit individual file sizes to prevent upload timeouts.

## How to configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Multi-line mode, maximum 2000 characters | Adapt to the long-text question requirements of metal material processing party building Q&A |
| `userSelect` | Preset three options: thematic education, clean government construction, party affairs workflows | Match the category tag structure of party building data in this field |
| Single search limit | Top 3 results | Control the number of results returned per round to avoid information overload |
| Knowledge base sync cycle | Once per month | Match the monthly data update rhythm to ensure the timeliness of retrieved content |
| File upload limit | Maximum 5 MB per file | Adapt to the size range of individual documents to prevent upload timeouts |

This configuration applies to FastGPT v4.17.0.

## Three common misconfigurations
- Phenomenon: The knowledge base reference option does not appear in the variable selection panel of the code running node. Cause: The corresponding party building knowledge base is not bound in the form configuration, so this data source is not loaded into the context.
- Phenomenon: The chat window displays the prompt "No knowledge base selected". Cause: The default bound party building knowledge base is not configured in the interaction form, or the bound knowledge base has not completed initialization synchronization.
- Phenomenon: The number of returned search results does not match the configured single search limit. Cause: The filter condition for `userSelect` is not correctly configured, causing the retrieval scope to exceed the preset categories and match irrelevant data.

## How to confirm the configuration is correct
- Open the form configuration page, check that `formInput` is set to multi-line mode with a maximum input length of 2000 characters.
- Click the knowledge base sync button, confirm that the sync cycle is displayed as once per month and the sync status is completed.
- Enter a party building-related question in the test chat window, check that the number of returned results matches the preset single search limit, and that the category tags match the preset options.
- Upload a test document of 5 MB, confirm that the upload progress proceeds normally with no error prompts.
