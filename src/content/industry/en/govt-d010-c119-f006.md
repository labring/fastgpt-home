# Party Building Learning Q&A for Iron and Steel Smelting: Citation Sources and Traceability

## What This Category of Data Looks Like
The data source for Party Building learning Q&A in the iron and steel smelting field is internal exclusive Party Building documents of the enterprise, including annual Party committee study plans, branch three meetings and one lesson records, superior Party Building guidance documents, compiled Party member study reflections, and other materials. The update rhythm is to synchronize newly issued study materials weekly, and update branch study ledgers monthly. The structure of each single document includes title, issuing unit, release date, main content, and affiliated workshop/department tag. Fields include document unique identifier, file format, character count, associated Party Building activity number. Units uniformly use standard Gregorian dates, character count, and file size (MB).

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
Internal Party Building documents are stored classified by workshop and branch. When conducting citation traceability, it is necessary to associate the corresponding department tag, ensuring that responses only reference study materials from the questioner’s own branch to avoid confusion of cross-department content. Documents contain clear issuing unit and date fields. When displaying traceability, these metadata must be fully extracted; only displaying file names cannot meet compliant traceability requirements. The update frequency is relatively high, so an incremental synchronization mechanism must be configured to avoid redundant traceability results caused by repeated indexing of old documents. The character count of single documents varies widely. Long documents must be properly chunked while retaining metadata associations, ensuring that traceability can accurately match specific paragraphs of the original document. At the same time, Party Building learning Q&A must support follow-up questions about associated content of branch study ledgers, and the context must retain the associated information from previous questions to prevent responses from deviating from the current branch’s study theme.

## How to Set the Configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Single search limit | Top 6 entries | Party Building documents for iron and steel smelting are classified by department, and the number of documents per department is moderate. The top 6 entries can cover core study materials and avoid redundant results |
| `quoteMaxToken` | 800–1200 token | Party Building documents are mostly formal writings. 800–1200 token can fully extract the original quoted paragraphs and avoid truncating key information |
| `responseData` | Enabled | Document metadata must be returned for traceability, to ensure that compliant fields such as issuing unit and date can be displayed |
| `detail` | Enabled | The association between original text paragraphs and metadata must be displayed, to meet the compliant traceability requirements of Party Building studies in iron and steel enterprises |
| Context window size | 1500–2000 characters | Party Building Q&A for iron and steel enterprises needs to associate branch study ledgers. The context window can cover continuous study content and support follow-up questions |
| Incremental synchronization interval | 24 hours | Matches the weekly update rhythm of Party Building documents. Synchronizing every 24 hours can obtain the latest study materials in a timely manner |

This configuration applies to FastGPT v4.17.0.

## Three Common Mistakes
- Phenomenon: No citation content is displayed at the end of the answer paragraph. Cause: The `responseData` and `detail` configuration switches are not enabled, and document metadata and original text paragraph associations are not extracted, resulting in missing traceability information.
- Phenomenon: The second question receives off-topic answers and cannot associate context. Cause: The context window is configured too small, and the Party Building study context from previous questions is not retained, making it impossible to associate continuous content of branch study ledgers.
- Phenomenon: Citation traceability requests return timeout errors. Cause: The single search limit is configured too high, and a large number of cross-workshop Party Building documents are retrieved at the same time, exceeding the system processing threshold and causing request timeouts.

## How to Confirm the Configuration Is Properly Set
- Enter the FastGPT test conversation interface, input a Party Building-related question, and check whether metadata such as document issuing unit and date is displayed at the end of the answer.
- Initiate two consecutive Party Building study-related questions, confirm that the second question can associate the context of the previous question, and the response content conforms to the current branch’s study theme.
- Check the knowledge base index log, confirm that only the latest Party Building documents from the past 7 days have been synchronized, and there are no records of repeated indexing of old documents.
- Adjust the single search limit to an excessively high value, initiate batch questions, confirm that the system returns a timeout error, and verify that the configuration takes effect.
