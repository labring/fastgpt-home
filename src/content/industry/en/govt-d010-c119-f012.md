# Party Building Learning Q&A for Steel Smelting: Deployment and Upgrade

## What the data for this category looks like
Party building learning data in the steel smelting field comes from the internal archive of the enterprise's party and mass work department, including annual party committee study plans, records of branch three regular meetings and one party lecture session, party members' ideological reports, industry party building demonstration cases, and other materials. The update frequency is syncing the latest policy documents monthly, and updating branch study ledgers quarterly. Most documents are in PDF and Word formats, with some being structured ledger tables. The fields include document title, publishing entity, publishing date, study topic, and core requirements. The length of individual documents varies widely.

## What constraints these characteristics impose on deployment and upgrade
Mixed document formats require that the deployment phase adapts to the parsing capabilities of PDF, Word, and structured tables. The upgrade phase must add extraction rules for ledger-style structured data.
The high-frequency update feature requires configuring scheduled sync tasks during deployment, and ensuring the compatibility and stability of the sync link during upgrade.
Most steel enterprises use intranet deployment environments. This requires configuring intranet database and storage parameters during deployment, and adapting to the access restrictions of intranet firewalls during upgrade.
The wide variation in document length requires adjusting the chunking strategy during deployment to accommodate long document processing, and optimizing the index construction efficiency for long documents during upgrade.

## Configuration Settings
These configuration items apply to FastGPT v4.17.0.

| --- | --- | --- |
| `PG_URL` | `postgresql://fastgpt:securepass@internal-pg:5432/fastgpt?sslmode=disable` | Adapts to the intranet PostgreSQL database deployment of steel enterprises, disables SSL for intranet environments without certificates |
| `REDIS_URL` | `redis://:@internal-redis:6379/0` | Used to cache high-frequency questions and index results for party building Q&A, adapts to intranet Redis deployment |

| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Ensures the security of file upload and access, prevents unauthorized access |
| `ROOT_KEY` | `Generated during initial deployment, retain the original value during upgrade` | Maintains consistency of system administrator permissions, avoids permission failure after upgrade |

## Three Common Mistakes
- Symptom: Knowledge base index construction fails, with logs returning `connection timeout` or `invalid database url`. Cause: The `PG_URL` parameter is not configured correctly, or the firewall rules of the intranet PostgreSQL database restrict access permissions for FastGPT containers.
- Symptom: Model calls have no response or return `404 Not Found`. Cause: The `/v1` suffix is not added to the API address configuration, or the model access address is not correctly mapped in the docker compose configuration file.
- Symptom: The triggering rules for party building Q&A do not take effect as expected. Cause: The original model configuration parameters were overwritten during the upgrade process, or the triggering condition settings from the deployment phase were not correctly synchronized.

## How to Confirm Successful Configuration
- Run the built-in database connection test tool to verify that the `PG_URL` and `REDIS_URL` parameters can establish normal connections.
- Upload a party building learning document from a steel smelting enterprise, check whether the system completes parsing and generates a valid index.
- Submit a test question related to party building, confirm that the model call process is normal and the returned results meet expectations.
- View the docker compose running logs, confirm that all services corresponding to the configuration items have no startup failures or connection exceptions.
