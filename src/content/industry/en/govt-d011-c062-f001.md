# Meeting Minutes Organization Document Assistant: HTTP Interfaces and External Systems

## What this category of data looks like
Data sources for meeting minutes organization mainly include meeting audio transcription text, handwritten on-site notes, and archived online meeting chat content. A single document is generated per single meeting. Updates follow an event-triggered rhythm, with no fixed batch update cycle.
Single document length typically ranges from hundreds to thousands of characters. Core fields include meeting topic, attendees, discussion topics, resolution items, follow-up items, and other key fields. There is no mandatory unified format. The data unit is based on "single meeting minute". This guide applies to FastGPT v4.17.0 and later versions.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The event-triggered single-meeting nature requires interface calls to bind the unique identifier of a single meeting, to avoid mixing up processing results from different meetings.
The long text input feature requires the interface to support large character volume request bodies, to avoid automatic truncation of valid content.
The non-fixed structured fields require the interface to support flexible field extraction and mapping, to adapt to format requirements of different downstream document systems.
The single-generation update rhythm means the interface does not need scheduled pulling. Only a single call triggered after the meeting is completed completes processing.

## How to set up the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {pre-configured FastGPT API key}` | Follow HTTP interface authentication specifications to ensure legitimate call permissions |
| `variables` | `{"meeting_unique_id": "{{incoming meeting ID}}", "raw_transcript": "{{uploaded meeting transcription text}}"}` | Bind the unique identifier and raw data of a single meeting to avoid mixing up processing results from different meetings |
| Single input text limit | `8000–12000 characters` | Adapt to the conventional length of single meeting minutes, avoid interface truncation triggered by overly long text |
| Concurrent call limit | `3 concurrent requests` | Adapt to FastGPT's interface current limiting rules, avoid triggering current limiting errors |
| `responseData` | `Only extract content with fields "Resolution Items" and "Follow-up Tasks"` | Match core business fields of meeting minutes, simplify the receiving logic of downstream document systems |
| Timeout threshold | `600 seconds` | Adapt to the processing duration of long text transcription and organization, avoid mid-process interruption |

## Three common errors
- Phenomenon: After calling the interface and passing in meeting transcription text, the returned organized result is empty or core fields are missing. Cause: Failed to correctly map the incoming variable of the original transcription text in `variables`, causing the processing engine to not obtain valid input data.
- Phenomenon: When submitting multiple meeting minute interface calls in batches, a 429 status code is returned. Cause: Did not set a reasonable single-call concurrency threshold, exceeding FastGPT's interface current limiting rules.
- Phenomenon: When uploading pre-processed structured meeting minute files via the HTTP interface, the downstream document system cannot correctly parse the corresponding relationship between discussion topics and resolutions. Cause: Did not specify the field mapping rules for structured data in the interface configuration, causing the incoming field format to not meet the parsing requirements of the external system.

## How to confirm the configuration is correct
- Call the test interface with a short single meeting minute text, check if the returned result includes the organized core meeting content.
- View the interface call log, confirm that the `Authorization` authentication field is correctly carried, with no authentication failure errors.
- After connecting to the external document system, pass in test data, confirm that the system can normally receive and parse the meeting minute content returned by the interface.
- Adjust the input text length to close to the preset upper limit, check if the interface can process normally without truncation.

The values provided are common starting points and should be measured against the reader's own samples.
