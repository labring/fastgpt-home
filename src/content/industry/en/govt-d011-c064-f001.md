# Document Format Review Assistant: HTTP Interfaces and External Systems

## What this category of data looks like
Data for document format review comes from official documents of state-owned enterprises and government departments, including standardized format files such as upward official documents and downward official documents. Updates are triggered by the official document circulation process. It supports real-time single-document upload or batch import. The document structure is fixed into three parts: header, main body, and footer. Core fields include document number, title, receiving authority, main text, date of issuance, seal position, and more. Content is primarily Chinese characters, with a small number of punctuation marks, numbers, and format markers.

## Constraints on HTTP Interfaces and External Systems
The fixed structure of official documents requires HTTP interfaces to parse request parameters according to standard fields, to avoid misjudgment of unstructured data. For real-time circulation scenarios, the interface must support low-latency responses to meet instant verification needs for single documents. For batch import scenarios, the interface must support pagination or batch submission parameters to avoid request timeouts. The verification logic for core fields must be directly bound to interface return results, so external systems can directly read verification results for fields such as document number and date of issuance. Different document types have different format rules. The interface must support passing a document type parameter to match the corresponding verification logic.

## How to Configure
This configuration method applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {API Key}` | Complies with HTTP interface authentication standards, and adapts to the authentication requirements of most document format verification services |
| `variables` | `{"doc_type": "upward document", "check_fields": ["document number", "date of issuance"]}` | Specifies the document type and core fields for verification, narrows the verification scope, and improves interface response speed. Values can be adjusted based on actual verification needs |
| `responseData` | `Top 3 verification results` | Core issues with document format verification usually focus on key errors in the header, main body, and footer. Returning the top 3 results meets the alarm and correction needs of external systems, avoiding redundant data transmission |
| Request timeout | `30–60 seconds` | Single-document format verification requires parsing the complete document structure. An overly long or short timeout will affect verification stability. This interval is suitable for most scenarios |
| Batch request limit | `10 documents per request` | When submitting in batches, balance interface load and transmission efficiency. 10 documents per request avoids timeouts or failures caused by excessive data volume in a single request |
| Interface address | `Fill in the actual deployed verification service address` | Adapts to verification services in different deployment environments, ensuring that requests can correctly reach the target interface |

## Three Common Misconfigurations
- Phenomenon: The interface request returns a 403 Forbidden status code, and a permission error is reported during FastGPT testing. Cause: The `Authorization` parameter is not configured correctly, or the passed API key has expired or has insufficient permissions.
- Phenomenon: Cross-origin blocking occurs for interface requests, and the console prompts a Cross-Origin Resource Sharing error. Cause: The external system's interface has not configured cross-origin rules allowing the FastGPT domain name, resulting in request interception.
- Phenomenon: Request timeouts occur frequently when submitting documents in batches. Cause: The number of documents submitted in a single request exceeds the interface's supported limit, or the request timeout is set too short and does not adapt to the time required for document parsing.

## How to Confirm Successful Configuration
- Call the configured HTTP interface, pass in a standard official document with compliant formatting, and check whether the interface returns verification results showing no errors.
- View the FastGPT interface call log, confirm that the `Authorization` parameter is correctly carried, and that the request parameters match the configured items.
- Push the verification results to the external system, and check whether the external system can normally receive and parse the returned `responseData` content.
- Submit a simulated official document with format errors, confirm that the interface returns the corresponding error fields and prompt information, and verify that the verification logic is effective.

The values provided are common starting points and should be measured against the reader's own samples.
