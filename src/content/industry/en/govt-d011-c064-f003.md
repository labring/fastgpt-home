# Document Format Review for Document Assistance: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for document format review comes from official documents released by state-owned enterprises and government departments at all levels, with updates synchronized to the official issuance schedule of documents. Single documents have a fixed structure, consisting of three modules: header, main body, and footer. Fields include document number, issuance date, confidentiality level, font and font size, line spacing, page margins, and exclusive format fields for some classified documents. Document length varies widely, ranging from short notices with hundreds of characters to comprehensive reports with tens of thousands of characters.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
The fixed structure of document formats requires prompts for multi-turn dialogue to accurately align with exclusive verification rules for each of the header, main body, and footer modules, to avoid verification omissions caused by generalized descriptions. Multiple fields with dedicated units require prompts to clearly distinguish format requirements for different fields such as document number, font and font size, and page margins, to avoid confusion. The wide variation in document length requires multi-turn dialogue to fully retain context information, ensuring subsequent verification links can carry over the verification scope from prior dialogue. Exclusive format fields for classified documents require built-in permission checks in the dialogue flow, to prevent leakage of sensitive format information.

This configuration guide is compatible with FastGPT v4.17.0.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` Session Identifier | Bind to the unique number of the current document | Ensure multi-turn verification dialogues for the same document can be linked to a unified context, avoiding session confusion |
| `messages` Context Count | First 12 entries | Document format verification covers multi-module steps; retaining the first 12 dialogue entries fully supports verification needs when switching modules |
| `variables` Format Rule Injection | Bind to the format library corresponding to the current document type | Dynamically load exclusive format requirements for different document types such as notices, reports, and requests, improving verification accuracy |
| Context Retention Duration | 7200 seconds | Covers the full duration of a complete single document verification process, preventing loss of dialogue context mid-process |
| Maximum Character Count per Interaction | 2000 characters | Adapt to verification input for long document fragments, preventing response anomalies caused by overly long single inputs |

## Three Common Mistakes
- Phenomenon: After calling an external verification plugin, the dialogue log field is empty, making it impossible to trace the complete verification process for this document. Cause: The session identifier was not bound via the `variables` parameter, causing the external plugin to fail to link to the corresponding dialogue context.
- Phenomenon: When viewing historical verification records without logging in, the associated format sample images fail to load. Cause: The session identifier was not persistently bound, causing the image loading request to fail to match the context of the corresponding document.
- Phenomenon: When switching verification modules during multi-turn dialogue, subsequent prompts do not carry over the context requirements of the prior verification. Cause: The `messages` context count was set too low, causing the verification rules from prior dialogue to be truncated.

## How to Confirm the Configuration is Correct
- Initiate two rounds of verification dialogue for the same document, check that the session identifier is consistent, confirming the context has not been reset.
- After calling an external verification plugin, check that the dialogue log contains the input content and output results of this verification, confirming log recording is functioning properly.
- Input document fragments of different lengths, verify that interactive input is not abnormally truncated, confirming the maximum character count per interaction setting meets requirements.
- Switch document types, check that the prompt automatically loads the format rules for the corresponding document, confirming the rule library bound via `variables` is effective.
