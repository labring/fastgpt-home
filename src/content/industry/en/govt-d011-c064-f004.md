# Document Format Verification: Document Assistance - Workflow Orchestration
This document is written for FastGPT v4.17.0.

## What this category of data looks like
Data for document format verification comes from officially circulating documents of state-owned enterprises, government and public service sectors, including red-headed documents, requests, reports, notifications, and others. The update rhythm follows the document circulation cycle. Each single document is processed once after submission, with no fixed batch update frequency.

Document structures include fixed fields: document serial number, receiving body, main text, attachments, completion date, seal position, and more. Units of measurement are characters and pages. Fields must comply with mandatory norms for party and government official document formats. For example, the year part of the document serial number must use hexagonal brackets, and the completion date must use Arabic numerals for year, month, and day.

## What constraints these characteristics impose on workflow orchestration
Document format verification has many fixed fields and strict format requirements. Dedicated verification rules must be configured for each field in the workflow, so multiple nodes must be split to correspond to the verification logic of different fields.

The length of single documents varies widely, from hundreds of characters to dozens of pages. The workflow must adapt to input content of different lengths to avoid node timeouts caused by overly long content. The trigger timing of document circulation is not fixed, so global variables must be used to pass verification context to ensure state synchronization across nodes.

Additionally, different document types have different format requirements. The workflow must support binding verification templates corresponding to the document type.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Pass global tokens and document metadata required for verification | Meet the need to pass context across MCP tools, resolve the issue where global variables cannot be passed |
| `nodeId` | Bind the unique identifier of the format verification tool node | Accurately locate the verification execution node, avoid node confusion in the workflow |
| Tool automatic trigger condition | Trigger based on the completion status of the document upload node | Enable automatic start of the verification process without manual intervention |
| Node timeout setting | 300–600 seconds | Adapt to the time range required for single document verification, calibrated based on actual testing |
| Input content limit | 1000–2000 characters | Adapt to the main text length of most documents, avoid node lag caused by overly long content |
| Verification rule binding | Match the format template of the current document type | Align with the exclusive format requirements of different documents |

## Three common mistakes
- An error reporting `token field is empty` is returned when calling the MCP tool. The cause is that the transfer path of global variables is not configured via the `variables` parameter, and the tokens required for verification are not stored in the workflow global variables.
- The format verification node remains in the pending execution state, and the verification process does not start automatically. The cause is that the tool call trigger based on the completion status of the document upload node is not set, causing the process to get stuck in the upload stage.
- No verification result notification is received via the DingTalk webhook. The cause is that the output result of the format verification node is not bound to the input parameters of the DingTalk webhook tool, so the verification content cannot be passed.

## How to confirm the configuration is complete
- Enter the workflow variable management page, confirm that the `variables` parameter has been configured with the tokens and document metadata to be passed.
- Upload a test document, check whether the workflow node status automatically transitions to the format verification link.
- View the MCP tool call logs, confirm that the input parameters include the content of the global variables.
- Check the DingTalk webhook tool configuration, confirm that the verification result has been passed to the corresponding tool as an input parameter.
