# Government Document Format Checking: Government Document Assistance - Tool Calling and Plugins

## What the data for this category looks like
Data for government document format checking comes from official government document drafts and official government document format specification documents from state-owned enterprises and public service sectors. Data is updated alongside new government document issuance requirements, with update cadence aligned with official document issuance standards. Each single document has a fixed structure, including three core modules: header, main body, and footer. It includes standardized fields such as document number, confidentiality level, urgency level, title, main text, and issuance date. Fields must comply with official format requirements. Content is mostly plain text, with a small number of basic formatting markers.

## What constraints these characteristics impose on the tool calling and plugins link
Fixed document structure requires tool calling to accurately match the module verification logic for the header, main body, and footer, without using generalized processing. Data updated alongside official standards requires tool plugins to support regular synchronization of the latest format rules, to prevent verification logic from becoming outdated. Mandatory verification of standardized fields requires that tool calling nodes configure verification rules for each individual field, to ensure all mandatory verification items are covered. Content that is mostly plain text requires that plugin calls prioritize processing text fields, to avoid interference from non-text content during verification. Strict order requirements for government document formats require that verification steps in tool calling match the official document typesetting order, without disrupting the verification logic.

## How to configure settings
This page applies to the tool calling and plugin configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `{"type": "function", "function": {"name": "gov_document_format_check"}}` | Explicitly specify the dedicated tool for government document format checking, to prevent the model from generating irrelevant responses |
| `functionCall` | Enable forced calling mode, only return verification results | Focus on verification result output, which meets usage requirements without additional AI responses |
| HTTP toolset interface configuration | Fill the official verification API address as the target interface address, set the timeout period to 30 seconds | Adapt to the network environment of public service scenarios, the timeout duration matches the execution cycle of the verification logic |
| Verification field range | Select the 18 standardized fields specified by official regulations | Ensure coverage of all mandatory verification format requirements, avoid missing key verification items |
| Rule update frequency | Synchronize the latest official standards once per month | Adapt to the update cadence of official government document format standards, to ensure the timeliness of verification logic |

## Three Common Misconfigurations
- Phenomenon: The HTTP toolset call returns `message: Invalid URL, code: 500`. Cause: The target interface address of the toolset is not configured correctly, or the interface address does not adapt to the access restrictions of the public service network.
- Phenomenon: The tool calling node returns empty verification results or no valid fields. Cause: The `toolChoice` parameter is not configured for the standardized fields of the government document, causing the verification tool to not be triggered correctly.
- Phenomenon: Truncated error message `Multimodal file size is` is returned after calling. Cause: The uploaded government document exceeds the single-file size limit allowed by the tool, and size filtering was not performed on the uploaded file in advance.

## How to Confirm the Configuration Is Complete
- Test calling a single government document that complies with official standards, check whether the verification results for the corresponding fields are returned.
- View the tool calling log, confirm that the `toolChoice` parameter correctly specifies the verification tool, and no irrelevant model response outputs are present.
- Trigger the rule update synchronization action, check whether the tool can pull the latest official format standard configuration.
- Simulate calling a government document that does not meet the size requirements, confirm that the tool triggers the corresponding abnormal prompt.
