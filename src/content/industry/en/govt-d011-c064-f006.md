# Official Document Format Review and Assistance: Citation Source and Traceability

## What the data for this use case looks like
The data sources for official document format review primarily come from standardized documents for party and government official document formats, internal official document templates of state-owned enterprises and public institutions, and official incoming and outgoing documents. The data update rhythm follows minor adjustments to official document specifications, usually synchronizing the latest version requirements once a year. The structure of a single document is fixed, including standard fields such as document number, title, main recipient, main text, attachment note, date of completion, seal position, etc. All fields have clear format requirements, with units mainly based on character count, line count, and paragraph count. The length of single documents varies widely, ranging from a few hundred characters to tens of thousands of characters. Some attachment-type official documents also include additional format review rules.

## What constraints these characteristics impose on the "citation source and traceability" link
Because official document data includes fixed format fields, traceability requires precise matching of source documents corresponding to the fields, rather than relying solely on vague paragraph matching. The data sources include official specifications and official business documents, so traceability requires distinguishing between specification documents and business document source types, and prioritizing matching authoritative sources corresponding to the business scenario. The data update rhythm is stable, so the knowledge base must synchronize the latest specification versions, and traceability results must mark version information to ensure compliance. The length of single documents varies widely, and overly long citation fragments will exceed the model's context limit, so the citation length must be controlled reasonably. Most citation scenarios for official documents are compliance reviews, so traceability results must clearly mark core identifiers such as document numbers to facilitate verification of source authenticity.

## How to set the configuration
This configuration rule applies to FastGPT v4.17.0. Specific parameters can be adjusted based on model capabilities.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | Matches the length of most official document main text paragraphs, avoiding exceeding the model's context limit |
| `responseData` | Include document number and date of completion fields | The core identifier for official document traceability is the document number, so structured fields must be included in returned results |
| `detail` | Enabled | Must return the complete context of the citation fragment to facilitate verification of official document format compliance |
| Single search limit | Top 3 results | Official document citations mostly come from authoritative specifications or superior documents, so excessive redundant results are unnecessary |
| Knowledge base chunk length | 800–1200 characters | Matches the natural paragraph division of official document sections, preserving the association between fields and documents |

## Three common mistakes
- The symptom is that the knowledge base document is matched during search, but only the citation link is returned without content fragments. The cause is that the `responseData` configuration is not enabled, and structured fields are not extracted, resulting in an inability to associate specific content.
- The symptom is that a context limit error is returned after calling the tool. The cause is that the value of `quoteMaxToken` exceeds the maximum context length supported by the model, resulting in overly long citation fragments.
- The symptom is that the traceability result cannot correspond to the official document number. The cause is that the association between the document number and the main text paragraph is broken during knowledge base chunking, leading to a disconnect between fields and content.

## How to confirm the configuration is correct
- Upload a standard-format party and government official document to the knowledge base, initiate a format review request, and check whether the returned results include structured fields such as document number and date of completion.
- View the returned citation source list, confirm that each result is associated with a specific document fragment and corresponding field information.
- Adjust the value of `quoteMaxToken` to verify whether the length of the returned citation fragments matches the expected setting.
- Trigger abnormal input tests, such as uploading non-standard official documents with incorrect formats, and confirm that the error messages conform to the expected logic after configuration.

The values provided are common starting points and should be measured against the reader's own samples.
