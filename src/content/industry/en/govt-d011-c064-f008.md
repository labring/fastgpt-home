# Document Assistant for Official Document Format Review: Document Parsing and Chunking

This configuration applies to FastGPT v4.17.0.

## What this category of data looks like
Data originates from official circulating documents of central state-owned enterprises, government agencies, and public service institutions. Types include notices, requests, reports, replies, and other similar documents. Updates are triggered via official document circulation workflows. A single upload can include one or multiple documents. Documents follow fixed standardized structures, containing standard fields such as document number, issuing authority header, title, recipient body, main text, attachment note, date of issuance, seal position, and cc recipients. Core measurement units for content are characters, page numbers, and line counts.

## What constraints these characteristics impose on document parsing and chunking
The fixed structure of official documents requires the parsing step to accurately identify exclusive fields such as document numbers and titles, to avoid chunking that breaks the integrity of key information. Official documents have a wide range of lengths, from several hundred characters to tens of thousands of characters. Chunking must adapt to main text paragraphs of different lengths, to prevent semantic fragmentation after splitting. Official documents often include structured content such as tables and attachments. The parsing step must extract such content separately, to avoid mixing with the main text. In batch upload scenarios, consistent parsing of multiple documents must be ensured, to avoid cases where some documents fail to parse.

## How to set the configuration

| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | The main text paragraphs of official documents are of moderate length. Splitting them preserves complete semantic units, and avoids damaging the logical connection between titles and paragraphs |
| `chunkSplitter` | Split by paragraph + title | Official documents have clear hierarchical title structures. Splitting by title preserves the logical hierarchy of the document, which facilitates subsequent format review |
| `customPdfParse` | Enabled | Official document PDFs mostly follow standard government or state-owned enterprise formatting. Enabling custom parsing can accurately extract exclusive elements such as headers, footers, and seal positions |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large documents or batch document parsing takes a long time. Setting a longer timeout threshold can prevent mid-parsing interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000–2000 MB, calibrated via actual testing | Supports batch upload of multiple large official documents, to meet daily office batch processing needs |

## Three common mistakes
- Symptom: No response from the parsing node after uploading an official document, with slow operation-related errors shown in logs. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` value is set too short. The parsing time for large official documents exceeds the threshold, triggering a timeout interruption.
- Symptom: Key official document fields such as document numbers and titles are missing from the parsed chunked results. Cause: `customPdfParse` is not enabled. The default parsing mode does not adapt to the standard formatting structure of official documents, leading to failure to extract exclusive fields.
- Symptom: Only some documents are successfully captured and parsed when multiple official documents are uploaded in batch. Cause: The `UPLOAD_FILE_MAX_SIZE` value is set too low. Documents exceeding the limit are not included in the parsing scope.

## How to confirm the configuration is properly set
- Upload a standard-format official document, and check whether the parsed text completely extracts core fields such as document number, title, main text, and date of issuance.
- Check the parsing logs to confirm that no timeout errors or slow operation-related prompts appear.
- Check the chunked results to confirm that each chunk contains a complete paragraph or title hierarchy, with no content truncation or semantic fragmentation.
- Test batch upload of multiple official documents of different types, to confirm that all documents are successfully parsed and corresponding chunked content is generated.

The values provided are common starting points, and should be evaluated against the reader's own samples.
