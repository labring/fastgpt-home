# Document Assistance for Work Brief Compilation: Multi-turn Dialogue and Prompts

## What the data for this category looks like
Work brief compilation data originates from special progress updates, weekly or monthly work summaries submitted by various functional departments and subordinate units within central and state-owned enterprises. Update frequency follows the submission cycle, typically once per week or per month. Each individual document has a fixed structure, including fields such as title, submitting unit, submission date, core progress, pending coordination matters, and next steps. The length of each document typically ranges from 500 to 1500 characters. There is no unified unit field, and specific content is presented only in natural paragraphs.

## What constraints these characteristics impose on the multi-turn dialogue and prompts link
The fixed document structure requires multi-turn dialogue to accurately match field extraction logic, to avoid missing key information such as submitting unit and date. The irregular update frequency requires dialogue context to support refreshing with the latest submitted data, and cannot rely on fixed historical corpus. The moderate individual document length but large total length during batch compilation requires the multi-turn dialogue context window to adapt to long text processing, to avoid truncating core content. The decentralized sources from multiple departments require dialogue to support filtering context by submitting unit, and also requires clear prompt settings to distinguish work content from different departments.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Preset opening prompt variables | `{{department}}, {{reportCycle}}` | Adapts to the submitting unit and cycle fields of briefs, to quickly guide users to input specific compilation requirements |
| Message history retention length | First 20 dialogue turns | Matches the typical length of a single brief, to avoid overly long context that causes the model to confuse core information |
| `variables` configuration | Fixed list of common submitting units | Helps the model identify brief content from different departments, to avoid mixing work content across departments |
| Context window size | 8000-12000 token | Adapts to the total text length during batch compilation, to prevent key progress or plans from being truncated |
| `chatId` association rule | Bound to a single compilation task | Ensures coherent context for multi-turn dialogue within the same task, to avoid data loss after session interruption |
| `messages` parameter configuration | Include source document metadata | Supports the function of viewing source original text in dialogue interface responses, to meet traceability requirements. Supported in FastGPT v4.17.0 |

## Three Common Misconfigurations
- The page displays "No available index model detected" after refresh. This occurs because the brief compilation corpus is not associated with the index configuration of the current dialogue agent, or the deployment status of the index model is abnormal.
- The dialogue returns a 404 status code (no body). This occurs because the `chatId` parameter is not carried correctly, or the permission configuration of the session interface does not open the corresponding access path.
- The preset multiple guiding questions are not displayed in the dialogue opening. This occurs because the preset question list is not correctly configured in `variables`, or the prompt settings are not bound to the corresponding variable parameters.

## How to Confirm Successful Configuration
- Test the preset opening prompt, input different submitting units and cycles, confirm that the prompt settings can automatically match the corresponding fields to generate guiding questions.
- Launch a multi-turn dialogue, submit 3 to 5 different compilation requirements consecutively, confirm that the context associated with `chatId` is not reset, and the dialogue logic is coherent.
- Call the dialogue interface, check whether the historical context records of the `messages` parameter are included in the returned results, to confirm that the session status is normal.
- Verify the index configuration, refresh the page and check whether the brief compilation corpus can be loaded normally, with no error prompts.
