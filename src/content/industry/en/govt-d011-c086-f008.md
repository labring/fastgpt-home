# Work Brief Compilation: Document Parsing and Chunking for Administrative Document Assistance

## What This Category of Data Looks Like
Data for work brief compilations comes from special, weekly, or monthly work briefs submitted by departments at all levels. Updates follow fixed submission cycles or on-demand aggregation. Most documents use PDF or DOCX formats. Some include Excel work statistics attachments. A single compilation document typically contains multiple independent briefs. Each independent brief includes fixed fields: submitting entity, submission date, core work content, phased results, and pending tasks. There is no unified standard layout across these documents.

## Constraints for Document Parsing and Chunking
Disparate briefs from multiple sources have inconsistent formats. These include scanned PDFs and DOCX files with complex tables. Parsers must support multi-format recognition and OCR text extraction. Batch compilation documents have large file sizes. Each document contains multiple independent briefs. Chunking tools must avoid breaking the semantic integrity of individual briefs. Some briefs include Excel statistical attachments. Structured table data must be fully preserved. Otherwise, subsequent question-and-answer association accuracy drops. Fixed fields in briefs require chunking to split by submission unit or paragraph first. This preserves contextual links for core information.

## Configuration Settings
| Configuration Parameter | Recommended Value | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Core content of a single work brief paragraph typically runs to hundreds of characters. This avoids splitting complete work progress paragraphs |
| `chunkSplitter` | Split by paragraph + line break | Brief content uses mostly paragraph structure. This preserves semantic integrity |
| `customPdfParse` | Enable OCR recognition mode | Adapts to scanned brief documents. Extracts text embedded in images |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Reserves sufficient parsing time for large batch compilation documents. Prevents timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to compilation brief scenarios with multiple attachments for batch uploads |
| `chunkSettingMode` | Manual configuration mode | Allows adjustment of chunking rules for different brief formats. Fits multi-source data scenarios |

## Three Common Misconfigurations
- Uploading a scanned PDF returns parsing output with limited text or empty content. This happens when OCR recognition mode via `customPdfParse` is not enabled. Embedded image text is not extracted.
- Uploading an Excel brief attachment leads to failed accurate association of table statistical data during question-and-answer. This happens when `chunkSplitter` is not configured to split by table area. Table content is split into scattered unstructured text chunks.
- Batch uploading multiple large brief documents causes timeout errors during parsing. This happens when `PARSE_FILE_TIMEOUT_SECONDS` is set too low. Insufficient parsing time is reserved.

## How to Verify Correct Configuration
This verification process uses FastGPT v4.17.0.
- Upload a scanned brief document. Check if parsed text includes handwritten or printed text from images. Confirm OCR mode is active.
- Upload a brief with an Excel attachment. Check if parsed text retains table row and column structure and data integrity. Confirm chunking rules adapt to structured data.
- Upload a single compilation brief larger than 500 MB. Check if parsing completes normally. Confirm timeout settings match document size requirements.
- View the chunk preview interface. Confirm each chunk contains a complete work progress paragraph. No core content is split incorrectly.

These values are common starting points. They should be evaluated against specific sample datasets.
