# Administrative Document Assistance for Work Brief Compilation: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for work brief compilation comes from daily work briefs and special summary materials submitted by various functional departments. Updates follow fixed submission cycles. Individual documents have a standardized structure, including fixed fields such as submitting entity, submission date, core work progress, pending issues, and follow-up work plans. Involved units use general administrative office metrics including project count, number of participants, and funding amount.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The standardized fixed field structure requires retrieval to accurately match information associated with core business fields, to avoid irrelevant content interfering with retrieval results. The fixed submission cycle update rhythm requires the knowledge base to support incremental synchronization by cycle, to avoid reindexing old data. The multi-department submission source characteristic requires retrieval to support initial filtering by submitting entity, to ensure recalled content aligns with the calling entity's permission scope. When compiling multiple briefs in batches, total content volume is large, so retrieved and recalled results must be properly contextually cropped to avoid exceeding model input limits.

## How to set configurations
This document is written based on FastGPT v4.17.0. The following configuration items are adapted to the business requirements of work brief compilation:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Matches the precision requirement for core business fields in work briefs, to avoid recalling irrelevant brief content |
| `limit` | `Top 8 entries` | The total amount of reference information integrated for a single brief compilation is moderate, to avoid context overload |
| `searchMode` | `vector` | Adapts to standardized structured fields and fixed business semantics, prioritizes vector recall for accurately matched content |
| `usingReRank` | `Enabled` | For multiple briefs compiled in batches, reranking can filter low-relevance recalled results |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Performs extended queries for professional terms or abbreviations in briefs, to supplement associated past work content |
| `collectionIds` | `Configured by submitting department grouping` | Divides knowledge base collections by department permissions, to ensure recalled content aligns with the calling entity's access scope |

## Three Common Misconfigurations
- Symptom: Retrieval results do not include target brief content within the knowledge base, and generated content deviates from the preset reference scope. Cause: The `similarity` threshold is set too high, filtering eligible recalled results.
- Symptom: Knowledge base information extracted in the workflow is empty. Cause: `collectionIds` is not configured to specify the knowledge base collection for the corresponding department, leading to incomplete retrieval scope.
- Symptom: Multiple recalled briefs have highly similar semantics, failing to provide differentiated references for compilation. Cause: Only relying on vector recall without combining keyword retrieval dimensions leads to repeated hits of similar content.

## How to Confirm Configurations Are Correct
- Manually submit a retrieval request for a single work brief, verify whether the number and content of recalled results align with the preset department scope.
- Adjust the `similarity` threshold and compare changes in recalled results, confirm that the threshold matches the business precision requirement.
- After enabling `usingReRank`, view the sorted results after reranking, confirm that low-relevance content is effectively filtered.
- Check the knowledge base call node in the workflow, confirm that `collectionIds` is bound to the knowledge base collection for the corresponding department.

The values provided are common starting points and should be measured against the reader's own samples.
