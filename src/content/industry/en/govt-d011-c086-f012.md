# Work Brief Compilation Document Assistance: Deployment and Upgrade

## What the data for this category looks like
The data for work brief compilation comes from periodic work materials submitted by government, state-owned enterprise (SOE) internal business lines, and grassroots units. The update rhythm primarily follows weekly and monthly fixed submission schedules, with temporary emergency submissions also supported. Each individual brief document has a fixed structure, including five core fields: submitting entity, submission date, core work progress, matters requiring coordination, and next-phase plan. The word count per brief ranges from 800 to 1500 characters, with all fields using structured text and a small number of numerical annotations.

## What constraints these characteristics impose on deployment and upgrades
The fixed fields and fixed update rhythm of work brief compilation require structured field mapping rules to be configured during deployment, to ensure submitted data can be accurately stored in the knowledge base. Multi-source submitted data requires deployment to support multiple access paths including OA systems and shared folders, while adapting to the dual update logic of fixed-period synchronization and manual triggers. The word count range per single document requires vector storage chunking parameters to match the 800-1500 character length interval, to avoid overly fragmented or overly long chunks that reduce retrieval accuracy. The sudden nature of temporary submissions requires that manual trigger synchronization interfaces be retained during upgrades, to prevent disruption to emergency data entry.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `PG_URL` | `postgresql://username:password@host:5432/fastgpt_brief` | Structured fields of work brief compilation must be stored in a relational vector database. `PG_URL` specifies the connection address for pgvector, adapting to structured storage and vector indexing requirements for multiple fields |
| `DB_MAX_LINK` | `20–30 connections` | The retrieval concurrency after chunking single briefs is moderate. 20–30 connections balances database resource usage and query speed |
| `REDIS_URL` | `redis://:password@host:6379/0` | Used to cache retrieval results and synchronization task status, adapting to temporary storage and quick access requirements for multi-source data |
| `STORAGE_S3_ENDPOINT` | Fill in according to the actual address of the internal object storage | Used to store original brief files and chunked vector caches, adapting to storage requirements for large-capacity documents |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Used to encrypt access tokens for brief attachments, ensuring access to internal documents is only available to authorized users |
| `ROOT_KEY` | Set based on actual testing | Used to configure system administrator permissions, only set during initial deployment to avoid permission conflicts during subsequent upgrades |

## Three Common Errors
- Symptom: The compose file fails to start during deployment, with logs showing database connection timeout or username/password verification failure. Cause: `PG_URL` and `MONGODB_URI` were not configured for the structured storage requirements of work brief compilation, and incorrect connection parameters for a generic vector database were used, leading to failed database verification.
- Symptom: Scheduled synchronization tasks cannot execute normally after upgrade, and temporary submitted briefs cannot be stored in the knowledge base. Cause: The original configuration mapping for scheduled synchronization and manual triggers was not retained during upgrade, leading to overwriting of the update logic.
- Symptom: Retrieved briefs have very low matching with query keywords, and the number of results does not meet expectations. Cause: Vector storage chunking parameters were not adjusted based on the 800-1500 character length of single work briefs, leading to unreasonable semantic chunking and reduced retrieval accuracy.

## How to Confirm Proper Configuration
- Use the FastGPT v4.17.0 deployment package, run the database connection test script to verify that `PG_URL`, `MONGODB_URI`, and `REDIS_URL` can establish normal connections, and the number of connections does not exceed the value set by `DB_MAX_LINK`.
- Upload a work brief that meets the standard format, trigger a manual synchronization task, and confirm that the document can be successfully stored in the knowledge base and the corresponding vector index is generated.
- Access the frontend address `FE_DOMAIN`, log in with the administrator account, and check the synchronization task configuration list to confirm that both the scheduled synchronization and manual trigger options are enabled.
- View the file list of the corresponding storage service, confirm that the uploaded original brief files have been stored in the storage location corresponding to `STORAGE_S3_ENDPOINT` according to the configured path.
