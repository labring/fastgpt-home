# Official Document Assistance for Speech and Report Drafting: Document Parsing and Chunking

## Data Profile for This Category
This category of data primarily originates from internal office system archives, original meeting minutes, official documents issued by superior authorities, and collections of past report materials. Updates are triggered on demand, typically generated during meeting preparation or quarterly/annual report cycles. Most documents use structured layouts, including titles, salutations, segmented body text, and signatures. Some documents include data tables, attachment lists, and referenced document numbers. Fields include submission document numbers, responsible units, report topics, execution cycles, and more. Business-specific measurement identifiers such as person-times, ten-thousand yuan, and percentages are used in relevant units.

## Constraints for Document Parsing and Chunking
Structured document layouts and specialized business fields require parsing processes to retain metadata associations, to avoid losing critical information such as submission document numbers and responsible units during splitting. The combination of multi-paragraph body text and embedded tables requires parsing components to accurately identify cross-page paragraphs and table boundaries, preventing content fragmentation. Batch documents generated on demand require parsing and chunking workflows to adapt to multi-scenario layouts within a single file, while also supporting compatibility with differences in report formats across different organizational levels. The presence of business-specific measurement identifiers requires parsing processes to retain original text formatting, avoiding errors in unit identification.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 1000–1500 characters | Ensures contextual coherence for long paragraphs and embedded tables in speeches and report materials, avoiding overly fragmented or overly long single chunks |
| `chunkSplitter` | Split by paragraph + title hierarchy | Matches the structured layout of documents, retaining the binding relationship between titles and their corresponding body text |
| `customPdfParse` | Enabled | For official document PDFs with embedded tables and complex layouts, enable custom parsing to retain original formatting and metadata |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Meets the upload requirements for batch report materials, preventing parsing failures caused by overly large single files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Addresses parsing time for long documents and multi-table files, preventing interruptions due to timeout |
| `chunkSettingMode` | Manual configuration | Adapts to format differences across different report materials, allowing adjustment of chunking parameters for individual files |

## Three Common Misconfigurations
- Only the first portion of a document is returned after parsing, with remaining content not extracted. This occurs because `PARSE_FILE_TIMEOUT_SECONDS` is set to an overly small value, and full parsing of long-form report materials is interrupted before completion.
- Table content cannot be properly extracted after parsing, or table data cannot be selected in the dataset list. This occurs because the `customPdfParse` parameter is not enabled, and the default parsing logic does not adapt to the layout structure of embedded tables in official documents.
- Content under the same report topic is split into multiple discontinuous chunks after chunking. This occurs because `chunkSplitter` is configured to split by fixed character counts, without retaining the binding relationship between titles and their corresponding body text.

## How to Confirm Successful Configuration
- Upload a typical report material PDF, check the parsed text preview, and confirm that the binding relationship between tables, titles, and body text is intact.
- Check the parsing logs to confirm that no timeout errors or file size limit prompts appear, matching the set values of `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS`.
- View the post-chunking result list, confirm that each chunk contains complete paragraphs or title-body combinations, with no cross-module concatenation.
- For a single document with tables, adjust `chunkSettingMode` to manual configuration and re-parse, compare the coherence differences of the chunking results, and confirm that the configuration takes effect.

The values provided here are common starting points, and should be validated against the relevant samples.
