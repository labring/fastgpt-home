# Document Drafting and Report Material Writing: Document Assistant - Deployment and Upgrade

## What the data for this category looks like
The data for this category primarily comes from past speeches and report materials archived in internal OA systems, as well as meeting minutes and business reports linked to pending drafting tasks. Updates are triggered on demand, with the material update frequency linked to a single drafting task ranging from 1 to 7 days. Document structure includes a header, main recipient, body modules (core data, implementation measures, expected outcomes), signature and date. Fields include report topic, meeting attendees, required report duration, issuing unit. Units involved include character count, number of attendees, and minutes.

## What constraints these characteristics impose on deployment and upgrades
Since most data comes from internal classified or sensitive business systems, deployment requires configuring internal data source connection permissions and data desensitization rules to prevent sensitive information leaks. Document structure includes multi-module hierarchies. During upgrades, ensure the chunking logic adapts to the body module divisions to avoid damaging semantic integrity. The on-demand update rhythm requires deployment to support dynamic data synchronization configuration, without relying on fixed scheduled tasks. The requirement for association between multiple fields and units requires retaining field metadata in the vector database configuration to facilitate subsequent precise matching of business scenarios.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `REDIS_URL` | `redis://:custom password@internal IP address:6379/0` | Adapts to the long text caching requirements of FastGPT v4.17.0, uses internal addresses to avoid public network exposure, database index 0 is used for caching sessions and temporary data |
| `MONGODB_URI` | `mongodb://username:custom password@internal IP address:27017/fastgpt?authSource=admin` | Stores metadata and vector indexes for long-text speeches and report materials, internal deployment ensures data security |
| `STORAGE_S3_ENDPOINT` | `http://internal storage node IP address:9000` | Stores generated official documents and uploaded business materials, uses internal storage to meet classified scenario requirements |
| `FILE_TOKEN_KEY` | `32-character random string` | Generates file access tokens to restrict unauthorized access to internal official documents |
| `FE_DOMAIN` | `https://internal office domain` | Configures the frontend access address to adapt to the internal office network environment |

## Three common errors
- An OCI runtime create failed error appears when starting the container, and logs show insufficient memory quota. The cause is that speeches and report materials fall under long-text processing scenarios, and the default container memory configuration is insufficient to load the large language model and vector model, without adjusting the memory quota for long-text tasks.
- Pulling the image linked to `REDIS_URL` fails, even if a network proxy is configured. The cause is using a Redis image required by a new version without specifying a compatible image version, or not configuring an internal image source to replace public network pulling.
- Model loading fails when deployed in an Ascend 910B environment. The cause is not adapting to the Ascend architecture dependency packages, and not preinstalling the corresponding version of AI acceleration components, resulting in failure to properly call the vector model and generation model.

## How to confirm the configuration is complete
- Access the frontend address corresponding to `FE_DOMAIN` to confirm the page loads normally with no resource loading failure prompts.
- Call the internal data source connection interface to test data synchronization, confirming that metadata from past speeches and report materials can be retrieved.
- Upload a test business material to generate a simulated speech draft, confirming that the generated file can be accessed normally via the link generated using `FILE_TOKEN_KEY`.
- Check the service logs corresponding to `REDIS_URL` and `MONGODB_URI` to confirm no connection timeout or permission errors exist.

The values provided are common starting points and should be measured against the user's own samples.
