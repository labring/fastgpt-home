# Internal Office and Employee Services for 12345 Citizen Hotline Work Order Processing: Forms and Interactions

## What this category of data looks like
Data sources for this category include the 12345 citizen hotline platform, contractor business systems, internal knowledge bases, follow-up and evaluation data, and local hotline management-related regulations. The data update frequency is daily. Documents processed daily include request registration forms, dispatch records, handling responses, follow-up records, extension applications, return explanations, and knowledge base entries. Core fields cover request number, request type, responsible unit, handling node, response content, follow-up results, and more. The field formats of different documents must be adapted to the synchronization requirements of business systems.

## What constraints do these characteristics place on the forms and interactions link
The scattered data sources require the forms and interactions link to support mapping configuration for fields across multiple systems. This ensures work order data automatically populates corresponding form items after synchronization from various platforms. The daily update rhythm requires the knowledge base associated with forms to adapt to newly added work order data each day, preventing recall of outdated content. The diverse document types require the interaction link to switch displayed fields based on work order status. For example, an extension reason field must be displayed additionally when an extension application is submitted. The multi-turn input mode of the `formInput` component supports segmented submission of requests, avoiding overly long input in a single session. The pain point of time-consuming request type judgment requires built-in auxiliary tools in the form to quickly match responsible units and response templates, reducing manual verification costs. The risk of errors such as overdue work orders requires the form to be configured with an overtime reminder mechanism to provide early warning of handling node risks.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale for This Setting |
|---|---|---|
| `formInput` | Set to multi-turn input mode, with a single input limit of 800–1200 characters | Adapts to the typical content length of request registration forms, preventing input content from being truncated |
| `userSelect` | Preset 15 common request type options, with support for custom additions | Covers common request types such as inquiries, complaints, and requests for help on the 12345 hotline, enabling quick classification |
| Single search limit | Top 5 entries | Work order response references typically focus on the latest similar cases; too many results will interfere with handling staff judgment |
| Overtime threshold | 600 seconds | Matches the typical response duration for work order handling, triggering reminders after timeout to avoid overdue processing |
| Context length | 1000 token | Adapts to the response reference content length for work order handling, preventing exceeding the model’s processing limit |
| Field mapping rules | Calibrated based on actual testing, adapted to the fields of contractor business systems | Ensures data submitted via the form can be synchronized to various business systems, avoiding field incompatibility |

The above configurations are based on FastGPT v4.17.0.

## Three common mistakes
- Symptom: An SSL error occurs when calling the speech-to-text link, with a connection failure prompt on the interface. Cause: A valid HTTPS domain certificate is not configured, causing cross-domain requests to be blocked and preventing normal use of the speech input function.
- Symptom: A concurrency exception occurs when the `userSelect` component triggers tool selection, returning a 400 error. Cause: The number of concurrent triggers for the component is not limited; simultaneous calls across multiple nodes exceed the interface’s carrying limit, resulting in request failure.
- Symptom: Some work order fields are empty after form submission, and cannot be synchronized to the contractor business system. Cause: Correct field mapping rules are not configured, and form items are not bound to the exclusive fields of 12345 work orders.

## How to confirm the configuration is complete
- Import a simulated request registration form, check whether the form automatically populates corresponding business fields, and verify that the field mapping rules take effect.
- Trigger the `userSelect` component, verify that the preset request type options can be selected normally, and that custom addition of new types is supported.
- Simulate an unsubmitted state exceeding 600 seconds, check whether an overtime reminder is triggered, and verify that the overtime threshold configuration takes effect.
- Call the speech input function, confirm that no SSL error occurs, and verify that the HTTPS configuration is correct.
