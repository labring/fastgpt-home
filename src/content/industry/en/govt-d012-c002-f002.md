# Internal Office and Employee Services for "Efficiently Complete One Matter" Joint Handling: Vector Models and Indexes

## What the Data for This Category Looks Like
Data for this category originates primarily from the national government service platform’s "One Matter" special zone, local integrated government service platforms, electronic certificate repositories, and departmental approval systems. Updates occur daily. Daily documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions, and completion receipts. Data fields include item number, associated department name, processing node, material list, and circulation status. Document formats vary across submitting departments. Some documents include clear temporal association information.

## Constraints Imposed on Vector Models and Indexing
Daily updated data sources require incremental indexing support, to avoid reprocessing historical data via full indexing. Documents from multiple sources with inconsistent formats need unified chunking rules, to ensure effective vectorization of joint handling documents across formats. Documents with item association and temporal information require retention of contextual links during indexing, to prevent damage to cross-departmental item logical relationships after chunking. Structured data from electronic certificate repositories and unstructured text from approval opinions require chunking strategies tailored to different document types.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Joint handling item documents are mostly structured text. Excessive length will lose contextual associations of cross-departmental items, while insufficient length will damage the logical integrity of items |
| Overlap Length | 100–150 characters | Retain pre- and post-item relationships across chunks and temporal information of material circulation, to avoid broken associations after chunking |
| Similarity Threshold | 0.75–0.85 | Distinguish between similar joint handling item lists and matching results for different items, filter low-relevance redundant data |
| Single Search Limit | Top 10 entries | Joint handling items involve multiple departments. A small number of accurate results can meet the query needs of internal office and employee services |
| `defaultToken` | 4096 | Adapt to the conventional context length of multi-document joint handling items, meet summary queries for parallel approval opinions |
| `maxToken` | 8192 | Process full associated documents for complex joint handling items, cover complete context of multi-department approval workflows |

## Three Common Configuration Mistakes
- After importing the joint handling item dataset into the knowledge base, the index status remains "indexing" for an extended period. This occurs because the incremental index trigger rule is not configured. The daily updated dataset is not synchronized incrementally, resulting in excessively long full index processing times.
- Abnormal search results appear after using the m3e embedding model. This occurs because the calling channel for the m3e model is not correctly added, preventing the model from loading normally and generating vectors.
- Abnormally high similarity values are returned in search results. This occurs because no similarity threshold filter is set, resulting in repeated matching between associated documents of the same item and their own text.

## How to Verify Proper Configuration
- Check the dataset's index status, confirm it transitions from indexing to ready, and daily incremental update tasks trigger normally at preset times.
- Enter joint handling item keywords to run a search, verify that associated fields in returned results match corresponding departments, processing nodes, and material lists.
- View console logs, confirm there are no error messages for embedding model calls, and the vector generation process completes normally.
- Verify configuration parameters, confirm that chunk length, overlap length, `defaultToken`, `maxToken` and other parameters match the current structure of joint handling documents.

The values provided here are common starting points, and should be evaluated against applicable local samples.
