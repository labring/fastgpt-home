# Internal Office and Employee Services for "Efficiently Complete One Matter" Joint Handling: Tool Calling and Plugins

## What the data for this category looks like
This category of data mainly comes from the "One Matter" special zone of the National Government Service Platform, local integrated government service platforms, electronic certificate repositories, and approval systems of various departments, and is updated daily. Commonly involved documents include joint handling item lists, one-time notice sheets, joint handling application forms, material circulation sheets, parallel approval opinions and completion receipts. Data fields include cross-departmental item association relationships, application material reuse rules, processing node circulation status, approval progress identifiers of each department, etc. There is no unified fixed unit, and it dynamically adjusts according to item type, department attributes, and processing procedures.

## What constraints these characteristics impose on the "Tool Calling and Plugins" workflow
Daily updated cross-departmental government data requires tool calling to support real-time retrieval of the latest item lists and approval statuses, to prevent joint handling process stagnation caused by expired data. Structured processing requirements for multiple government document types require plugins to adapt to parsing files in various formats, such as application forms and circulation sheets, to ensure accurate information extraction from application materials and approval opinions. Cross-departmentally associated fields require tool calling to accurately match pre- and post-relationships between items, to avoid process interruptions from incorrect splitting. Fields for material reuse rules require plugins to extract and verify reuse conditions for application materials, to reduce duplicate submissions.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Basis for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the dynamic tool calling requirements for cross-departmental items, automatically select approval plugins for corresponding departments |
| `functionCall` | Enabled according to item type | For clear cross-departmental approval nodes, enable specified function calls to simplify processes |
| Single tool call timeout | 600 seconds | Matches the average time consumption of cross-departmental parallel approval, avoids call failures caused by slow responses from departmental systems |
| Upper limit of plugin call batches | First 8 items | Aligns with the conventional range of the number of departments involved in joint handling items, prevents excessive parallel calls from exceeding system load |
| Context retention length | 1200–1500 characters | Covers core information such as application materials and circulation records of joint handling items, ensures the integrity of context for tool calling |

## Three common mistakes
- Phenomenon: Tool calling returns an empty result, and logs show no match for the corresponding department plugin. Cause: The joint handling item list was not synchronized to the plugin configuration library, so cross-departmentally associated tools cannot be identified.
- Phenomenon: Single tool call times out, with status code 504 returned. Cause: The set timeout period is shorter than the average response duration of cross-departmental approval, and does not match the time consumption characteristics of joint handling scenarios.
- Phenomenon: Multimodal materials cannot be parsed correctly. Cause: Multimodal data processing configuration was not enabled, causing the plugin to be unable to process non-text materials such as certificate scan copies.

## How to confirm the configuration is correctly set
Import a local joint handling item list, and test whether tool calling automatically matches approval plugins for corresponding departments.
Simulate a cross-departmental circulation scenario, and verify whether the tool calling timeout period matches actual response rhythms.
Upload multimodal certificate files, and check whether the plugin correctly extracts key information from them.
Review plugin call logs, and confirm that the batch upper limit does not exceed the preset number of calls.

The values provided are common starting points and should be measured against the reader's own samples.
