# Internal Office and Employee Services for Real Estate Registration: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Core data for this category is sourced from real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories, with a daily update frequency. Daily processed documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and registers. Document fields mostly include structured and semi-structured content such as real estate unit numbers, right holder information, ownership sources, and restriction statuses. A single document may contain extensive detailed information related to ownership rights.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
Data from multiple systems requires multi-turn dialogue to cross-verify information consistency across data sources, preventing conflicts in ownership statuses. Daily updated data sources require dialogue to pull the latest data in real time, ensuring accurate verification results. Large-volume documents and multi-field content increase context processing pressure, so targeted resource allocation for the dialogue link is needed. Ownership verification and surveying and mapping comparison are core time-consuming steps. Prompts must focus on the verification logic of key fields, while strictly controlling the rigor of output content to avoid registration errors or property rights disputes.

## How to set configurations
Configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapt to the field density of real estate registration documents, avoid splitting single-block information, and ensure the integrity of key content such as ownership rights and surveying and mapping results |
| Overlap Length | 150–200 characters | Retain associated content such as real estate unit numbers and right holder information across chunks, ensuring coherent context connection during multi-turn dialogue |
| Single Recall Entry Count | Top 6 entries | Cover core data types required for daily verification such as ownership certificates, surveying and mapping results, and tax payment vouchers, balancing recall efficiency and information coverage |
| File Upload Limit | 1000 MB | Support uploading and parsing large-volume business files including 100,000-character Chinese Word documents and 15,000-row Excel files |
| `chatId` Configuration | Bind to registration business work order ID | Associate with specific business processes, enable binding between multi-turn dialogue and work orders, and facilitate backtracking and verification |
| `messages` Parameter Management | Limit historical dialogue turns to the first 10 turns | Control context overload, avoiding excessively long dialogue output times |

## Three Common Mistakes
- Phenomenon: Images fail to display fully when calling MCP, with only partial content shown in returned results. Cause: The prompt does not clearly specify the complete associated path of the image resource, or the image index parameter is not configured in `variables`, leading to incomplete resource loading.
- Phenomenon: The returned result is empty after uploading a file via the dialogue interface, with no valid business information. Cause: `chatId` is not correctly bound to the business identifier of the uploaded file, preventing the system from associating the file data with the current dialogue context.
- Phenomenon: AI dialogue output is slow after searching the knowledge base, and timeout errors occur. Cause: The historical dialogue length of the `messages` parameter is not limited, resulting in context overload and system processing time exceeding the threshold.

## How to Confirm Configuration is Complete
- Upload a 100,000-character Chinese Word document and a 15,000-row Excel file, and verify that they load normally and participate in multi-turn dialogue.
- Initiate multi-turn questions involving ownership verification and surveying and mapping comparison, and confirm that returned results are associated with the latest data from corresponding systems.
- Pass the `chatId` parameter when calling the dialogue interface, and check that the interface return is bound to the correct business work order identifier.
- Adjust context-related configurations, and verify that historical dialogues of different lengths can be processed normally without timeout errors.
