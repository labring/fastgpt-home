# Internal Office and Employee Services for Real Estate Registration: Tool Calling and Plugins

This documentation is written based on the tool calling and plugin features of FastGPT v4.17.0.

## What this category of data looks like
Data sources for this category include real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories.
The update frequency for this data is daily.
Daily processed documents include registration application forms, ownership certificates, survey results, tax payment vouchers, real estate ownership certificates, and real estate registers.
Data fields cover real estate location, right type, right holder identity information, survey area, registration number, restriction status, and more.
Units of measurement include square meters, parcel counts, and others.
Data formats from different sources have both structured and unstructured variations.

## Constraints these characteristics impose on tool calling and plugins
Multi-source heterogeneous data sources require tool calling to adapt to interface specifications and permission verification rules of different systems. This prevents data pull failures caused by format incompatibility or insufficient permissions.
Daily update frequency requires tool calling to set reasonable cache and synchronization cycles. This ensures the timeliness of called data.
Diverse document types and fields require plugins to support parsing of structured and unstructured documents and accurate field extraction. This meets core needs for ownership verification and data comparison.
Additionally, errors may lead to administrative liability or property rights disputes. Tool call return results must include complete verification fields to facilitate manual review and traceability.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to flexible scenarios of multi-source system calls, automatically matches corresponding business tools for execution |
| `functionCall` | Enabled | Forces generation of structured tool call parameters, which meets the format requirements of real estate registration data verification |
| Tool call timeout period | 600 seconds | Adapts to the total time required for multi-system data pulls, prevents call interruptions caused by response delays from individual systems |
| Number of returned entries per call | Top 5 | Controls the volume of returned data to avoid exceeding the context window, while covering key information required for core ownership verification |
| Plugin cache validity period | 24 hours | Matches the daily data update frequency, ensures the timeliness of called data |

## Three common misconfigurations
- Symptom: Tool call returns empty results, and the interface shows missing tool response fields. Cause: Multi-source system permission verification parameters are not configured, so valid data from cadastral or tax systems cannot be pulled.
- Symptom: Tool call times out, returns status code 504. Cause: The set timeout period is too short, and does not adapt to the total time required for multi-system data pulls.
- Symptom: Generated parameter format does not meet target system requirements after `functionCall` is enabled. Cause: Parameter mapping rules are not adjusted for real estate registration field specifications, leading to extracted fields that do not match the target system.

## How to confirm correct configuration
- Trigger a tool call request, and check if the returned tool call parameters include core fields required for real estate registration, such as right type, real estate location, and restriction status.
- Simulate multi-system data pulls, and verify that the update time of cached data matches the configured validity period.
- Manually trigger a timeout test, and confirm that calls will interrupt as expected and return a prompt when system responses exceed the set duration.
- Check if the automatic selection logic of `toolChoice` can correctly switch to tools for corresponding business scenarios, such as calling the cadastral database plugin during ownership verification.
