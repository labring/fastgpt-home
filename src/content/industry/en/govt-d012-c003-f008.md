# Internal Office and Employee Services for Real Estate Registration: Document Parsing and Chunking

## What Data Looks Like for This Category
Data for this category comes from real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. The update frequency is daily. Daily processed documents include registration applications, ownership certificates, surveying and mapping results, tax payment vouchers, real estate ownership certificates, and real estate registers. Most document structures are standardized forms and structured register entries. Some surveying and mapping results include associated data. Ownership certificates and real estate ownership certificates contain fixed fields such as rights subject, location, and rights type.

## Constraints Imposed on Document Parsing and Chunking
Daily updated batch business documents require parsing tools that support high-frequency, stable processing. Standardized forms and structured register entries need precise chunking to preserve the integrity of core fields such as rights subject and location. Documents from multiple systems have format differences, so parsing logic must adapt to different document structures. Associated data in surveying and mapping results must avoid chunking that breaks data association. Long text entries in real estate registers require reasonable chunk length control to ensure complete expression of rights status.

The following configurations are based on FastGPT v4.17.0.
## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the structured field length of real estate registers and ownership certificates, avoid splitting core information such as rights subject and location |
| `chunkSplitter` | Switch based on document type | Use paragraph-based chunking for standardized forms, use region-based chunking for surveying and mapping results, adapt to different document structures |
| `customPdfParse` | Enabled | Adapt to the standardized PDF layout of real estate ownership certificates and registration applications, preserve original layout and field positions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Support uploading single large-volume surveying and mapping results or batch packaged documents, match the large file requirements in daily business |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Cover the parsing time of large-volume surveying and mapping results, avoid timeout errors |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules separately for documents from different sources, adapt to format differences of multi-system data |

## Three Common Mistakes
- Timeout error prompt when uploading a 10+ MB PDF for parsing: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted. The default timeout duration is insufficient to cover the parsing process of large-volume surveying and mapping results.
- Some DOCX documents fail to parse: The `customPdfParse` was not enabled to adapt to non-standard standardized document layouts, or the corresponding chunking rules were not switched to process form structures.
- Some tables in the knowledge base cannot be chunked: The `chunkSplitter` was not configured to split by table regions, and the general chunking logic was used instead, causing table content to be split and lose association relationships.

## How to Confirm Proper Configuration
- Upload a single 100 MB-sized surveying and mapping result PDF, check if the parsing task completes within the preset duration without timeout errors.
- Import a standardized registration application DOCX file, check if the parsed chunked content completely retains core fields such as applicant and application matters, with no missing content.
- Import a long text document from the real estate register, check if the chunked content does not split core rights status entries, and field associations are complete.
- Upload batch packaged documents, confirm that the system supports batch parsing and has no format errors.

The values provided are common starting points and should be measured against the reader's own samples.
