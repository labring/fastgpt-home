# Internal Office and Employee Services for Real Estate Registration: Model Access and Configuration

## What Data for This Category Looks Like
Data sources for this category include real estate registration information systems, cadastral survey databases, housing transaction online signing systems, tax systems, and electronic certificate repositories. The update frequency is daily. Daily processed documents include registration applications, ownership certificates, survey results, tax payment vouchers, real estate property right certificates, and real estate registration books. Data fields cover right subject information, real estate location, area parameters, right types, and ownership restriction status. Corresponding measurement standards must match the document type. No unified fixed unit exists.

## Constraints Imposed by These Characteristics for Model Access and Configuration
Multi-source heterogeneous data sources require model access links to support cross-system data format compatibility and permission verification. This prevents cross-library call conflicts. Daily updated data requires configurations to adapt to real-time or near-real-time inference requests. This avoids information lag caused by cache expiration. Rich document types include text and structured forms. Some documents include survey drawings and ownership certificate images. This requires multi-modal processing capabilities. Ownership verification is the core time-consuming step. The model’s context length must cover complete ownership source materials and comparison data. At the same time, limit the output length of a single inference to avoid exceeding business processing thresholds.

## Configuration Guidelines
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `vision` | `true` | Adapt to the recognition needs of image documents such as survey results and ownership certificates, matching scenarios where real estate attached drawings need to be processed in business |
| `maxContext` | `8000–12000 token` | Cover complete ownership source materials, comparison data and registration book information, meeting context requirements for the verification link |
| `maxTokens` | `2000–3000 token` | Limit the output length of a single inference, avoid exceeding business processing thresholds, and prevent process interruption due to overly long output |
| `quoteMaxToken` | `1500 token` | Limit the maximum number of tokens for referenced business documents, ensuring complete comparison data during verification without occupying too much context space |
| `toolChoice` | `auto` | Adapt to multi-tool invocation scenarios such as verification and comparison, allowing the model to independently select appropriate tools to complete ownership verification |
| `temperature` | `0.3–0.5` | Reduce output randomness, ensure the accuracy of ownership verification results, and meet the rigor requirements of administrative office scenarios |

## Three Common Configuration Mistakes
- Enabling the `vision` configuration and uploading an image for recognition results in the model returning that it cannot provide image content. This occurs when the multi-modal model access endpoint is not configured correctly, or image upload permission is not enabled in the conversation node, preventing the model from obtaining image input.
- An error occurs when connecting an embedding model deployed via VLLM. This is because the address configured for `AIPROXY_API_ENDPOINT` does not include the correct embedding model call path, or `AIPROXY_API_TOKEN` is not configured with call permission for the corresponding model.
- Output interruption occurs when the model calls a tool. This is because `maxTokens` is set too small, or `maxContext` exceeds the support limit of the currently accessed model, causing the inference process to be forcibly terminated.

## How to Verify Successful Configuration
- Upload a real estate survey drawing to the conversation node, trigger model inference, and check whether key information such as location and area in the drawing is correctly identified.
- Submit a test request containing ownership source materials and comparison data, and check whether the model automatically calls tools to complete ownership verification and status comparison.
- Review system operation logs to confirm that parameters such as `maxContext` and `maxTokens` during model invocation match the configured values.
- Test cross-system data retrieval, verifying that documents retrieved from the real estate registration information system and tax system can be normally read and processed by the model.

The values provided are common starting points and should be measured against the reader's own samples.
