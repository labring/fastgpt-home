# Internal Office and Employee Services for Proactive Public Disclosure and Policy Publication: Vector Models and Indexes

## What data for this category includes
Data for this category originates from government portals, document systems, government information disclosure directories, policy document libraries, and press conference materials.
Daily processed documents include policy files, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records.
Data updates occur daily. This supports internal office workflows for groups including government offices, policy and legal affairs departments, and website operation and maintenance teams.
Documents contain fields such as public attribution, security classification, publication deadline, and column assignment.

## Constraints imposed on vector models and indexing workflows
High-frequency daily updated data requires indexes to support incremental synchronization. This avoids full reindexing that consumes excessive system resources.
Mixed multi-type document scenarios require indexes to adapt to text splitting for different formats, including structured directories and unstructured files.
Public attribution and security classification fields must be embedded in index metadata. This ensures retrieval can filter non-public content by permissions.
Policy consistency requirements demand that index recalled content be tied to the latest published version. This prevents internal staff from accidentally using outdated information for public release.

## Configuration Settings
This page is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the information density of single sections in policy documents and interpretation drafts, avoiding semantic breaks within chunks |
| Overlap Length | 100–150 characters | Preserves contextual connections across chunks, ensuring complete transmission of policy messaging |
| `maxToken` | 4096 token | Aligns with the input limit of mainstream vector models, preventing truncation of critical policy content |
| Similarity Threshold | 0.75–0.85 | Filters low-relevance public disclosure directories or approval forms, focusing on core policy content |
| Single Search Limit | Top 10 results | Controls the volume of retrieval results, adapting to the quick review needs of internal office work |
| `defaultToken` | 2048 token | Sets a basic context length, meeting standard retrieval scenarios for policy interpretations |

## Three Common Misconfigurations
- Non-public approval forms or internal column update records appear in retrieval results, and the number of returned entries exceeds the preset limit. This happens because public attribution and security classification are not embedded as index metadata, and permission filtering rules are not configured.
- No retrieval results appear after custom index configuration, and test queries cannot match target policy files. This occurs because chunk length is set too large, causing core semantic content in policy interpretation drafts to be split and lost, or overlap length configuration is not enabled to preserve contextual connections.
- Interface errors occur when connecting to a specified vector model, and index construction fails. This is because request parameters are not configured according to the model’s requirements, or public directory fields are not correctly mapped to metadata fields for model input.

## How to Verify Correct Configuration
- Upload a test policy file and public disclosure directory, check if the index generation status shows success.
- Enter a query term related to policy content, verify that returned document types match expectations, and no non-public internal documents are included.
- Adjust the similarity threshold or single search limit, observe if the number of retrieval results changes according to configuration logic.
- Trigger an incremental update task, check if the system only synchronizes newly added policy files and column update records from the current day, and does not reprocess historical data.

The values listed here are common starting points. They should be validated against your own sample data.
