# Internal Office and Employee Services for Proactive Public Disclosure and Policy Publishing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for this category include government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. The update frequency is daily.

Daily documents cover policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Document structures include fields such as issuing authority, document number, release date, disclosure attribute, secrecy level, and main content. Single document lengths vary widely, ranging from hundreds-of-word notices to tens of thousands-of-word full policy texts.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
The daily data update requirement means tool calling must support switching between incremental sync and full refresh to avoid reprocessing old data.

Varied document structures require plugins to adapt to different field extraction rules. For example, extract disclosure attribute and secrecy level from information release approval forms, and extract document number and release date from policy documents.

The wide range of single document lengths requires tool calling to support dynamic adjustment of content truncation thresholds to avoid exceeding context limits.

The presence of secrecy level and disclosure attribute fields requires plugins to complete sensitive information verification before calling external publishing interfaces. This prevents accidental disclosure of classified or sensitive information.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to processing needs for different documents such as policy files and approval forms, automatically determines whether to call external tools |
| Document content truncation length | `800–1200 characters` | Matches the core content length of most policy documents and interpretation drafts, avoids exceeding context limits |
| `functionCall` parameter verification | Enabled | Ensures fields such as secrecy level and disclosure attribute are correctly verified, prevents sensitive information from being leaked |
| Incremental sync trigger interval | `24 hours` | Matches the daily data update frequency, avoids excessive consumption of system resources |
| External publishing interface timeout | `30 seconds` | Adapts to the typical response speed of government office system interfaces, prevents long-term blocking of workflows |
| Number of documents processed per call | `First 5 entries` | Avoids timeouts caused by processing too much data in a single call, aligns with daily publishing batch requirements |

## Three Common Misconfigurations
- Symptom: Passing a local document path via API call returns empty fields. Cause: Adaptation logic for referencing public documents via URLs is not configured, and tools that only support local uploads are not enabled in API mode.
- Symptom: Tool connection fails. Navicat can connect normally but API calls have no response. Cause: The API access whitelist for tool calling is not opened in FastGPT configuration, or interface permissions do not match the access rules of government office systems.
- Symptom: Tool call returns that the document cannot be accessed. Cause: The document pointed to by the URL does not have public access permissions, or the path contains unescaped special characters leading to parsing failure.

## How to Confirm Configuration Is Complete
- Initiate an API call, pass the URL of a document from the government public disclosure directory, check if the returned results include correct document fields and core content.
- Trigger an incremental sync task, check if the tool calling log only processes documents updated on the current day, with no duplicate processing records.
- Configure the secrecy verification logic, pass an information release approval form containing a secrecy level field, check if the corresponding interception rule is triggered.
- Call the external publishing interface, check if the response is completed within the configured timeout period, with no blocking or timeout errors.

The values provided are common starting points and should be measured against the reader's own samples.
