# Internal Office and Employee Services for Proactive Public Disclosure and Policy Publishing: Deployment and Upgrade

## What the data for this category looks like
Data for this category revolves around the full workflow of government proactive public disclosure. Daily documents include policy documents, policy interpretation drafts, public disclosure directories, information release approval forms, press releases, and website column update records. Data sources cover government portals, document management systems, government information disclosure directories, policy document repositories, and press conference materials. The update frequency is daily. Data fields include public attribute tags, confidentiality review status, release column affiliation, release time limit, and more. Overall, it covers full-link documents and process records from policy generation to public release.

## What constraints these characteristics impose on deployment and upgrade
The daily update frequency requires deploying incremental synchronization mechanisms to avoid excessive resource consumption from full synchronization. Multiple document types, including long-text policy documents and process-related approval forms, require configuring parsing rules adapted to different document structures. Multi-source data access demands support for connecting to multiple data sources such as document management systems and government portals. The data includes a confidentiality review status field, requiring configuration of sensitive information verification trigger logic during deployment. The need to synchronize multiple website columns and new media accounts requires configuring linkage parameters for multi-channel publishing to ensure consistent synchronized public content.

## Three common configuration mistakes
- Symptom: A Redis image pull timeout error occurs when running docker-compose up -d. Cause: The domestic mirror address is not configured to pull the Redis image, and access to the official mirror repository is blocked due to network restrictions.
- Symptom: The vector index fails to load after upgrading the PgVector plugin, and empty results are returned when querying policy documents. Cause: Database connection parameters were not updated according to the upgrade documentation, resulting in incompatibility between the new plugin version and existing configurations.
- Symptom: After creating a channel model in FastGPT v4.17.0, the configured large language model cannot be selected in the application settings page. Cause: The visibility scope of the model was not correctly configured in the channel management page, preventing internal office scenarios from calling the corresponding model interface.

## How to confirm the configuration is complete
- Run the docker-compose ps command to confirm that all dependent services are running normally.
- Upload a test policy document to verify whether the system can complete the public attribute recognition and public disclosure directory synchronization process.
- Trigger a daily incremental synchronization task and check that the synchronization result matches the updated content of the source data.
- Access the configured FE_DOMAIN to confirm that the internal office page can normally load public disclosure directory and policy document data.
