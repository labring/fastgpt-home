# Internal Office and Employee Services for Property, Asset, and State-owned Capital Management: HTTP Interfaces and External Systems

## What data for this category includes
This category covers data such as asset ownership registration information, asset appraisal results, property rights transfer plans, on-site transaction announcements, and asset disposal approval documents. Data sources primarily include state-owned asset supervision information systems, enterprise asset management systems, property rights exchange systems, appraisal agency reports, and financial statements. Data is updated on a monthly basis. Document structures include both structured forms and unstructured reports. Fields cover asset identifiers, ownership status, appraisal parameters, transaction approval nodes, and more, with units such as monetary amounts, area, and quantity.

## Constraints for HTTP interfaces and external systems
Monthly updated data sources require interface call frequency to align with business rhythms, to avoid triggering external system rate limits from high-frequency calls. Access to multi-source heterogeneous data requires a unified authentication mechanism to adapt to the `Authorization` configuration rules of different systems. Transmission of unstructured documents such as asset appraisal reports requires interfaces to support file-type parameters, to meet data transmission needs for batch synchronization scenarios. The large number of data fields and the sensitive nature of state-owned asset information require precise field filtering of `responseData` to reduce data transmission volume and avoid sensitive information disclosure risks. Additionally, since errors have serious consequences, interface call exception capture and retry mechanisms must align with business compliance requirements.

## How to configure settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `Authorization` | Configure according to the authentication rules of the connected system, for example `Bearer {token}` or basic authentication format | Adapt to authentication standards of different external systems to ensure the legality of interface calls |
| `variables` | Preset business variables such as asset numbers and transaction batches, use fixed field names required by the connected system | Simplify dynamic parameter passing and adapt to batch data synchronization scenarios |
| `responseData` | Filter core fields including asset ownership and appraisal results, for example `["asset_id", "ownership_status", "evaluation_value"]` | Reduce data transmission volume and avoid sensitive information disclosure risks |
| Timeout period | `300–600 seconds` | Adapt to the transmission and processing duration of large asset appraisal reports to avoid mid-transaction interruptions |
| Retry count | `2–3 times` | Address temporary network fluctuations or external system response delays to ensure data synchronization success rate |
| File upload size limit | `1000 MB`, adjustable based on actual testing | Meet transmission requirements for large asset appraisal reports and property rights transfer plans |

## Three common configuration errors
- Phenomenon: External interface calls fail after private deployment, with connection timeout or `401 Unauthorized` errors displayed in the interface. Cause: The `Authorization` parameter is not configured correctly, or the authentication key for the connected system is entered incorrectly.
- Phenomenon: When using form-data to upload asset reports in a workflow, file parameters fail to send normally. Cause: The parameter type is not set to file type, or the file field name does not match the requirements of the connected system.
- Phenomenon: External interface calls fail when using the Safari browser. Cause: Cross-origin request rules for the Safari browser are not adapted, resulting in blocked interface calls.

## How to confirm configuration is complete
- Call the test interface, check if the returned `responseData` includes the preset core business fields to confirm that the field filtering configuration is effective.
- Upload a small test file and send it via form-data parameters in the workflow to confirm that file transmission operates normally.
- Check if the format of the `Authorization` parameter meets the authentication requirements of the connected system, and verify successful authentication using an interface debugging tool.
- Simulate a long-duration data transmission scenario to confirm that the interface does not interrupt prematurely, and verify that the timeout period configuration is reasonable.
