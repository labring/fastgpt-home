# Internal Office and Employee Services for Property Rights, Asset and State-owned Capital Management: Workflow Orchestration

## What this category of data looks like
Data comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, appraisal agency reports, and financial statements. The update frequency is monthly. Daily documents include property rights registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval slips. The document structure includes both structured forms and unstructured reports. Fields involve asset numbers, ownership status, appraised value, number of transaction targets, and similar items. There is no unified fixed format, and parsing rules must be adjusted based on the source system.

## What constraints these characteristics impose on the "workflow orchestration" link
Multi-source heterogeneous data sources require workflow configuration with multi-node data source access rules, to unify the field formats of different systems. The monthly update frequency requires the workflow scheduling cycle to match the business synchronization rhythm, avoiding frequent resource calls. Diverse document types require workflow nodes to support multi-format input parsing, adapting to different processing logic for structured forms and unstructured reports. Sensitive business fields require workflow configuration of permission control nodes to limit the access scope of sensitive data. Time-consuming verification links require workflow setup of automatic verification nodes to reduce manual verification workload, and configure a failure alert mechanism to respond to possible ownership verification errors.

## How to set the configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `variables` | Map fields such as asset numbers, ownership status, and appraised value, use the standard field names of connected systems | Adapt to the data formats of multi-source heterogeneous systems, unify workflow input parameters |
| `nodeId` | Assign unique identifiers to asset ownership verification nodes and transaction material review nodes | Facilitate workflow debugging and abnormal node location, adapt to process splitting for multi-link approval |
| Scheduled trigger cycle | Set to `30 days`, calibrated based on actual testing | Match the monthly update frequency of business data, avoid ineffective synchronization |
| Exception alert configuration | Set the node timeout threshold to `600 seconds`, push alerts after trigger failure | Errors in state-owned asset processes have serious consequences, requiring timely response to exceptions |
| Multi-format input parsing | Prioritize processing the first `3` core approval documents, support parsing of structured forms and unstructured reports | Daily document types are diverse, focusing on core approval materials improves efficiency |

## Three common mistakes
- Phenomenon: When configuring an asset disposal approval link in the workflow, the front end displays a "Click to Ask Immediately" button. Cause: The link rendering rule of the reply component was not configured correctly, and the link was mistakenly passed as a session instruction parameter.
- Phenomenon: The multi-source data synchronization workflow fails to execute, and the field mapping is empty. Cause: Unified field mapping rules were not configured via `variables`, and the native field names of connected systems were used directly.
- Phenomenon: The workflow execution times out, returning status code 504. Cause: No reasonable timeout threshold was set, and the time taken by the node to process multiple asset appraisal reports exceeded the preset limit.

## How to confirm the configuration is complete
- Call the workflow test interface of FastGPT v4.17.0, pass in simulated property rights registration form data, and check whether `variables` are correctly mapped to a unified field format.
- Trigger the configured exception node, verify whether alert information is pushed according to the rules, and confirm that the timeout threshold meets the actual needs of the business scenario.
- Upload multiple types of documents (asset appraisal reports, on-site transaction announcements) and check whether the workflow correctly identifies and processes input content of different formats.
- View the workflow log, confirm that the node execution status corresponding to `nodeId` is normal, with no abnormal error messages.
