# Internal Office and Employee Services for Property Rights, Asset and State-owned Capital Management: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from state-owned assets supervision information systems, enterprise asset management systems, property rights exchange systems, and appraisal agency reports. The update frequency is monthly. Daily documents include property rights registration forms, asset appraisal reports, property rights transfer plans, on-site transaction announcements, and asset disposal approval forms. Most data structures combine structured fields with explanatory text. Fields include asset identifiers, ownership subjects, financial values, approval nodes, and more. Some documents include multi-column structured tables. It is necessary to maintain consistency between data ownership and financial records.

## What constraints these characteristics impose on deployment and upgrade
The need to synchronize multi-system data in monthly batches requires configuring a stable cross-system data pull link during deployment, to avoid connection interruptions during synchronization. The need to verify multi-source heterogeneous data requires backing up all full business data before upgrading, to prevent data loss from configuration changes. The compliance requirement for intranet deployment limits the scope of image pulling and data transmission, and public network resources cannot be relied on. The mixed feature of structured documents and long text requires the RAG chunking logic to adapt to different document types, to ensure retrieval accuracy. Additionally, the business characteristics related to state-owned assets require strictly following internal approval procedures during the upgrade process, to avoid unauthorized configuration modifications.

## Three common mistakes
- Symptom: Unable to log in after version upgrade, the interface returns a 502 status code. Cause: The service was not restarted after modifying the `MONGODB_URI` configuration, or the database connection failed due to incorrect configuration file format.
- Symptom: Upgrade command execution fails in the intranet environment, with a prompt that the image cannot be pulled. Cause: The intranet image repository address was not configured, and pulling timed out due to reliance on public network image sources.
- Symptom: After uploading a multi-column asset Excel file, RAG retrieval results are chaotic and cannot match business data by row. Cause: Segmentation by row was not specified, and the default automatic chunking logic caused semantic breaks in asset entries.

## How to confirm configuration is complete
- Run the database connection test command, verify whether the `MONGODB_URI` configuration takes effect, and confirm that existing asset data can be read.
- Trigger the monthly data synchronization task, check that the `DB_MAX_LINK` configuration does not trigger connection exhaustion errors.
- Upload a property rights registration form Excel file, test the RAG chunking effect, and confirm that the segmentation meets the structural requirements of business documents.
- Run the FastGPT v4.17.0 upgrade script in the intranet environment, confirm that installation packages from the local image repository can be pulled, with no public network access dependencies.
