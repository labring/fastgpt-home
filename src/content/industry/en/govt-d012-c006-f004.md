# Internal Office and Employee Services for Infectious Disease Information Reporting and Monitoring: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include the Chinese Center for Disease Control and Prevention Information System, hospital HIS systems, infectious disease reporting systems, and laboratory testing systems. The update frequency is daily.
Daily produced documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports.
Data fields must comply with legal infectious disease reporting rules. Standardized fields include case classification, onset date, diagnosing institution, reporting time limit, and similar. Common units are date formats, case counts, test result values, and other similar metrics.

## What constraints these characteristics impose on workflow orchestration
Daily updated data sources require workflows to be configured with scheduled trigger nodes to match data synchronization rhythms.
Standardized reporting fields required by regulations require workflows to include parameter verification links to ensure reported data complies with Center for Disease Control and Prevention specifications.
Multi-system data sources require workflows to integrate cross-system data pull nodes to unify output formats across different systems.
Time-consuming manual verification links require workflows to be configured with automated verification nodes to replace manual checks of case diagnoses, reporting time limits, and similar content.
Severe consequences of processing errors require workflows to be configured with failure alert nodes to promptly notify abnormal situations.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable binding configuration | Bind legally required reporting fields from `variables` | Ensure parameters called by the workflow comply with Center for Disease Control and Prevention reporting standards |
| Scheduled trigger node | 2:00 to 4:00 AM daily | Avoid business peak hours and match the daily data update synchronization rhythm |
| File type validation | Only allow jpg, png format medical images and pdf format report files | Distinguish compliant reporting files from unrelated files |
| HTTP request timeout | 300 seconds | Adapt to data pull response delays across Center for Disease Control and Prevention and hospital systems |
| Failure alert configuration | Bind internal office group bots | Promptly notify workflow execution abnormalities to avoid missed or delayed reports |
| Node execution order | Arrange HTTP request, verification, and AI analysis nodes in sequence according to `nodeId` | Ensure the workflow executes along the preset link and avoid disordered node order |

## Three Common Misconfigurations
- The HTTP request is not triggered during workflow execution, and the workflow proceeds directly to the AI chat link. This occurs because the node orchestration order is incorrect, with the AI chat node placed before the HTTP request node, and the workflow does not run along the configured execution link.
- Uploaded files cannot be correctly distinguished between images and other files. This occurs because no file type validation rules are configured, or the validation rules do not match the standard suffixes of Center for Disease Control and Prevention reporting files.
- HTTP request body parameters are not correctly mapped to workflow variables. This occurs because corresponding fields of the request body are not bound in `variables`, causing parameters to fail to be passed to downstream nodes.

## How to Verify Correct Configuration
- Trigger a test workflow, view node execution logs, and confirm that the body parameters of the HTTP request node have been correctly loaded as bound `variables` fields.
- Upload a jpg format test report image, a pdf format epidemic analysis report, and a txt format unrelated file, verify that the system only allows compliant files to pass validation.
- Adjust the HTTP request timeout to 100 seconds to simulate cross-system delay scenarios, confirm that the workflow triggers the internal office group bot alert after timeout.
- View the workflow running status panel in FastGPT v4.17.0, confirm that the daily scheduled trigger node starts execution at the set time.
