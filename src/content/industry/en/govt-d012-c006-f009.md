# Internal Office and Employee Services for Infectious Disease Information Reporting and Monitoring: Model Integration and Configuration

## What this category of data looks like
Data for this category originates from China’s National Center for Disease Control and Prevention Information System, hospital HIS systems, infectious disease reporting systems, and laboratory testing systems, with daily updates. Documents processed daily include infectious disease report cards, epidemic analysis reports, case correction records, clustered outbreak reports, and epidemiological investigation reports. Data fields include basic case information, diagnosis results, reporting timelines, correction status, laboratory test results, and more. Each document links to a unique case identifier and report number. The data structure must comply with legal infectious disease reporting format requirements.

## What constraints do these characteristics impose during model integration and configuration?
The daily data update requirement requires configuring context processing parameters adapted to single-day data volume to avoid losing daily summary information due to context overflow.
Differences in structure across multiple document types require presetting matching recall rules for different documents to ensure core fields such as case diagnosis and reporting timeline are accurately identified.
Multiple internal system data sources require aligning permission configurations during model integration with access rules of each system to avoid data pull failures.
Legal reporting mandatory requirements limit the field range of model output, only retaining content compliant with reporting specifications, to prevent non-compliant fields from being included in final submitted reports.

## How to set configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Adapt to the total length of multiple daily summary infectious disease report documents, avoid context overflow |
| `maxTokens` | `2000–3000 token` | Match the core content length of a single infectious disease report card or epidemiological investigation report, ensure complete generation of analysis segments |
| `quoteMaxToken` | `1500 token` | Limit the total length of recalled and cited document fragments, avoid redundant information interfering with case verification |
| `temperature` | `0.1–0.3` | Reduce randomness of generation results, ensure core fields such as case diagnosis and reporting timeline comply with the rigor requirements of legal reports |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated access address according to the deployment environment, such as the local deployment address of qwen3-embedding-8b or the dedicated address of Azure OpenAI | Adapt to model call paths for different cloud environments or private deployments, ensure normal request routing |
| `AIPROXY_API_TOKEN` | Fill in according to the rules corresponding to the key and model ID provided by the model service provider | Complete identity verification for model calls, ensure data transmission security |

## Three common configuration errors
- Phenomenon: The model fails to recall the reporting timeline field of case information, making the generated epidemic analysis report unable to be submitted. Cause: `quoteMaxToken` is not configured to limit the length of cited fragments, causing core fields to be truncated.
- Phenomenon: The model call returns a 401 status code, and the request cannot be completed. Cause: `AIPROXY_API_TOKEN` is filled incorrectly or has expired, and identity verification is not completed.
- Phenomenon: Single-day data processing times out, and the task fails. Cause: `maxContext` is set too small, unable to load all daily summary documents, causing insufficient context to trigger a timeout.

## How to confirm the configuration is correct
- Import a single infectious disease report card document, check whether the recalled reference fragments of the model include basic case information, diagnosis results and reporting timeline fields, confirm that the field coverage meets requirements, and check the running status of each FastGPT storage component to confirm normal data reading and writing.
- Submit a single-day summary data test task, check the task execution log, confirm that the response time of the model call request meets expectations, and no context overflow error occurs.
- Simulate the operation of correcting case information, check whether the generated correction report complies with the legal report format requirements, and no non-compliant fields are included.
- Replace the test epidemiological investigation report document, confirm that the recall rules of the model for different types of documents take effect normally.

The values provided are common starting points and should be measured against the reader's own samples.
