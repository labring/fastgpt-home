# Internal Office and Employee Services for Infectious Disease Information Reporting and Monitoring: Forms and Interactions

## What this category of data looks like
This category of data originates from the Chinese Center for Disease Control and Prevention Information System, medical institution HIS systems, infectious disease reporting systems, and laboratory testing systems. The update frequency is daily. Daily documents include infectious disease report cards, epidemic analysis reports, case correction records, clustered epidemic reports, and epidemiological investigation reports. Data fields include basic case information, diagnosis results, reporting time limits, correction notes, clustered event association information, and more. These must strictly match the fixed format requirements of legal reports, with no additional custom units.

## What constraints these characteristics impose on the forms and interactions link
Multi-data source access requires forms to support cross-system field linkage verification, to avoid format errors from manual entry. Fixed-format document requirements mean forms must pre-set mandatory fields for legal reports, restricting modification of non-authorized fields. The daily update rhythm requires interactions to support real-time synchronization of daily monitoring data, reducing repeated entry work. Legal reporting rules require forms to include built-in fixed verification logic for disease types, reporting time limits, and other items, to avoid underreporting and delayed reporting risks. This setup also adapts to frequent daily operations for disease control personnel, including verification, correction, and summary work. It simplifies repeated entry steps.

## Three common mistakes
- A token validation failed error appears after voice input. Cause: No valid token verification rule for voice input is configured, or the token has expired and not been refreshed.
- A 400 error is returned when a workflow calls a tool. Cause: No concurrency limit for tool calls is set, or the incoming report card field format does not comply with legal verification logic.
- Concurrent execution results appear during tool calls. Cause: No exclusive trigger rule for tool selection is configured, causing multiple tools to start simultaneously.

## How to confirm the configuration is complete
- Check the form editing interface to confirm all core legal report fields are set as mandatory items.
- Verify the tool selection pop-up window to confirm the optional range only includes the legal infectious disease classification list.
- Simulate multi-data source synchronization operations to confirm no timeout interruption prompts appear.
- Test the voice input function to confirm no token validation failed errors occur.
