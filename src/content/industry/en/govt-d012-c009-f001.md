# Internal Office and Employee Services for Public Data Catalog and Opening: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data originates from local public data opening platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is once per month. Daily supporting documents include public data resource catalogs, data opening lists, data item descriptions, desensitization rules, interface documents, and update frequency explanations. Data fields include data item unique identifiers, names, desensitization processing methods, open permission scopes, update cycles, external interface addresses, and other structured, callable data assets.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
The fixed monthly update feature requires interfaces to support periodic data synchronization and verification to avoid inconsistencies between the catalog and actual data. Data from multiple sources requires unified format conversion, and interfaces must adapt to the return structures of different data sources. Desensitization rules require automatic filtering of sensitive fields during interface transmission, and corresponding desensitization strategies must be bound in the configuration. Differences in open permissions require interfaces to verify call permissions through the `Authorization` parameter, with data from different departments corresponding to different authorization scopes. The standardization level of interface documents affects the docking efficiency of external systems, and it is necessary to ensure that interface parameters completely match the documents.

## How to configure the settings
The following configurations are formulated based on FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | `Bearer {API key assigned by the platform}` | Complies with security verification requirements for public data opening, ensuring the legitimacy of the calling subject |
| Data desensitization switch | Enabled, execute according to the desensitization rules bound to the data item | Matches the desensitization requirements in the public data catalog, preventing sensitive data leakage |
| Synchronization cycle | `720 hours` (once per month) | Matches the monthly update frequency of this category of data, ensuring synchronization between the catalog and actual data |
| `responseData` field mapping | Map return fields from public data interface documents to system variables | Unify the format of multi-source data, adapting to the calling logic of internal office systems |
| `variables` permission binding | Configure call permissions according to the departmental data opening list | Complies with the authorization boundaries of public data opening, preventing unauthorized access to data |
| Timeout threshold | `300 seconds` | Adapts to the average time consumed by multi-source data format conversion, avoiding mid-task failure of synchronization jobs |

## Three common configuration errors
- Symptom: Returns 404 Not Found status code during calls, prompting that the interface does not exist. Cause: Fails to match the official interface address in the public data catalog, and mistakenly uses document example addresses or internal test addresses as call addresses.
- Symptom: Prompts missing parameters when executing the data synchronization script, and fails to load the local data path. Cause: Fails to configure local path mapping parameters in `variables` according to the public data interface document, causing the system to fail to recognize the data source.
- Symptom: Synchronization tasks time out and fail, returning 504 Gateway Timeout status code. Cause: Fails to set a reasonable timeout threshold, or fails to adapt to the format conversion time of multi-source data, causing the request to exceed system limits.

## How to confirm the configuration is successful
- Call the test interface to check whether the returned `responseData` field matches the data item description in the public data catalog.
- Check whether the authorization request header `Authorization` carries a valid key, and verify that data without permissions cannot be called normally.
- After running the synchronization task, check whether the number of data entries displayed in the internal office system matches the number of entries in the public data opening list.
- View the system operation logs to confirm that there are no records of field parsing errors or permission verification failures in synchronization tasks.
