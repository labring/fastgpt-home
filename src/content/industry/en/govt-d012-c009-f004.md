# Internal Office and Employee Services for Public Data Catalogs and Open Data: Workflow Orchestration

## What the data for this category looks like
This category of data originates from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. The update frequency is once per month. Commonly encountered documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. Data fields include data item unique identifiers, open scope, desensitization processing methods, external interface addresses, update cycles, authorization conditions, and more. The primary formats are structured tables, JSON interface documents, and PDF description documents.

## What constraints these characteristics impose on workflow orchestration
The monthly update frequency requires workflow configurations to include timed synchronization nodes. This prevents discrepancies between data and actual open assets. Data from multiple sources requires adaptation to different import formats. Separate configuration of database connection, API pull, file upload, and other node types is needed. Desensitization rules must be embedded in process nodes to complete compliance processing before data is opened. Authorization conditions for data items must be passed as dynamic parameters to subsequent nodes, to control access scope for different roles. Different document types require matching parsing configurations: structured catalogs use table parsing nodes, and interface documents use text chunking nodes.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Bind to metadata fields of public data catalogs | Adapt to dynamic delivery requirements for multi-source data, support cross-node data transfer to the `variables` parameter |
| `nodeId` | Associate with dynamic knowledge base node IDs | Enable the function of switching a specified public data knowledge base during the conversation flow; the `nodeId` must be bound to the interaction node |
| Manually select knowledge base nodes | Allow conversation users to select the first 5 available knowledge bases | Match the open scope restrictions of the public data catalog to avoid unauthorized access |
| SQL variable validation | Filter valid SQL statements with lengths between 1000 and 1500 characters | Avoid injection risks, comply with the call specifications of public data interfaces |
| File parsing timeout | 600 seconds | Adapt to the parsing duration of large public data catalog documents |
| File chunk length | 800-1200 characters | Match the typical paragraph length of public data description documents |

## Three Common Configuration Mistakes
- Document parsing nodes return empty content after running, and uploaded public data catalog files cannot be read. The cause is that the path of the uploaded file is not bound to the `variables` parameter, causing the node to fail to locate the target file.
- A parameter error is triggered when a SQL statement is passed via variables for the database connection node, but manually entering the same SQL statement executes normally. The cause is that no format validation is performed on variables passed via `variables`, causing statements containing invalid characters to be submitted.
- The workflow cannot display the knowledge base selection interface during the conversation flow. The cause is that the `nodeId` is not configured to associate with dynamic knowledge base nodes, and the interaction switch for manual selection is not enabled.

## How to Verify Proper Configuration
- Run a test workflow, upload a sample public data catalog file, and check that the content returned by the parsing node matches the original file.
- Enter a SQL statement with valid variables, verify that the database connection node returns query results normally, and there are no parameter errors.
- Trigger the conversation flow, confirm that the interface displays a selectable knowledge base list, and the list only includes knowledge bases corresponding to the configured public data catalogs.
- View the workflow node logs, confirm that the `variables` parameter has correctly passed the corresponding metadata fields, and the node associated with `nodeId` triggers normally.
