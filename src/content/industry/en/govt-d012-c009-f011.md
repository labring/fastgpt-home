# Internal Office and Employee Services for Public Data Catalogs and Open Data: Forms and Interactions

## What Data in This Category Looks Like
Data for this category originates from local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Update frequency is monthly. Daily output documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions.
Data fields primarily include structured entries such as data item unique identifier, open subject, authorized usage scope, desensitization processing standards, call interface address, and update cycle. Some entries are accompanied by supporting interface call instruction documents.

## Constraints on Forms and Interactions
The monthly update frequency requires form interactions to synchronize data item update information regularly, avoiding inconsistencies between catalogs and actual data.
Multi-source data collection requires forms to support cross-departmental data item association verification, ensuring submitted catalog data meets format and content requirements of each source.
Fixed attributes of structured fields require forms to preset standardized field templates, reducing arbitrary employee input and improving catalog data standardization.
Supporting interface documents and desensitization rules require forms to embed or link viewing entrances for corresponding documents, helping submitters verify compliance.
Permission control in internal office scenarios requires form interactions to distinguish operating permissions for different positions, preventing unauthorized personnel from modifying public data catalogs and avoiding data leakage risks.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` field validation | Required fields include data item identifier, open scope, and desensitization rules. Character length limit is within 2000 characters | Matches structured field requirements of public data catalog documents, avoids content exceeding limits |
| `userSelect` permission scope | Limited to department data administrators and government data operation posts | Adapts to hierarchical control rules for public data, prevents unauthorized personnel from modifying catalog data |
| Question optimization configuration | Context window set to 800–1200 characters, calibrated based on actual testing | Adapts to content length of data catalogs and interface documents, optimizes question understanding accuracy during interactions |
| Single search limit | Return top 8 results | Controls information output volume during internal employee queries, avoids result overload |
| Update reminder trigger | Automatically push update prompts on the 5th of each month | Matches the monthly update frequency requirement for this category, ensures timeliness of catalog data |
| Interface address validation | Enforce HTTPS protocol format verification | Complies with security call standards for public data interfaces, reduces data leakage risks |

## Three Common Configuration Mistakes
- Issue: Permission selection boxes in data catalog forms flicker continuously, and selected items cannot be fixed. Cause: The permission data source is not locked in interaction configuration. Repeated pulling of permission lists during each page load causes rendering exceptions.
- Issue: An "invalid interface address" error appears when submitting a data open list update form. Cause: No interface address format validation rule is configured for the `formInput` field. Non-HTTPS addresses submitted by employees are not blocked.
- Issue: Pre-submission approval conclusions from form submissions are not carried over to prompt words for subsequent interactions. Cause: Context association configuration is not enabled, resulting in results from prior processes not being passed to the current interaction chain.

## How to Verify Proper Configuration
- Submit a test data catalog form, and confirm if required fields trigger corresponding validation prompts.
- Switch test accounts with different permissions, and confirm if the `userSelect` configured permission scope takes effect. Unauthorized accounts cannot access form editing permissions.
- Manually trigger the monthly update reminder, and confirm if update prompts are pushed to corresponding operation posts.
- Submit an interface address using a non-HTTPS protocol, and confirm if a format validation error is triggered.
