# Internal Office and Employee Services for Public Data Catalog and Opening: Deployment and Upgrade

## What this category’s data looks like
Data sources for this category include local public data open platforms, integrated big data platforms, departmental business databases, and electronic certificate repositories. Regularly produced documents include public data resource catalogs, data open lists, data item descriptions, desensitization rules, interface documents, and update frequency descriptions. The data update cycle is monthly. Fields cover data owning department, open permission, desensitization requirements, interface address, update frequency, and more. All fields follow standardized government data governance specifications, with no custom non-standard units.

## What constraints do these characteristics impose on deployment and upgrade
This category’s data characteristics impose multiple constraints on the deployment and upgrade process. Monthly updated data sources require configuring periodic synchronization tasks during deployment to keep metadata synchronized with actual public assets. Multi-source heterogeneous data sources require compatibility with different database types, and correct configuration of connection parameters such as `PG_URL` and `MONGODB_URI`. Data documents contain sensitive information such as desensitization rules and interface permissions. Permission verification logic must be configured during deployment to avoid data leakage risks caused by unauthorized access. Data fields are standardized and numerous, so a catalog classification index structure must be preset before deployment to reduce time spent on subsequent sorting work.

## How to set the configurations
| Configuration item | Recommended value | Rationale for this value |
| --- | --- | --- |
| `PG_URL` | `postgresql://username:password@host:5432/datacatalog` | Adapts to PostgreSQL databases commonly used in government scenarios for storing catalog metadata |
| `MONGODB_URI` | `mongodb://username:password@host:27017/opendata?authSource=admin` | Used to store unstructured text data such as interface documents and desensitization rules |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches frequently accessed catalog indexes and permission verification results to reduce database load |
| `DB_MAX_LINK` | `20–30 connections` | Matches concurrent connection requirements during monthly batch synchronization to avoid exhausting database connections |
| `FE_DOMAIN` | Intranet access domain name or mapped external domain name | Used to generate external links for catalog documents and permission verification callback addresses |
| `FILE_TOKEN_KEY` | Custom 32-bit random string | Used to encrypt download links for catalog documents to prevent unauthorized access |

## Three common mistakes
For FastGPT v4.17.0 deployment and upgrade, three common errors occur:
- Incorrect path configuration for `PG_URL` or `MONGODB_URI`, resulting in database connection timeout errors displayed on the interface. This happens when the authentication port and permission account for the government database are not filled correctly, or when the database whitelist is not configured to allow access from the deployment server.
- Blank iframe embedded page after external network mapping, while direct access to the domain name functions normally. This occurs when `FE_DOMAIN` is not correctly configured as the mapped external network address, or when cross-origin restrictions for login-free verification are not disabled.
- Audio processing function failure after version upgrade, with a prompt of POST /v1/audio/transcriptions HTTP error. This happens when tool interface paths or dependent package versions change after the upgrade, and associated tool configurations in catalog documents are not updated synchronously.

## How to confirm the configuration is complete
- Run the built-in database connection test tool to verify that configurations for `PG_URL`, `MONGODB_URI`, and `REDIS_URL` can establish normal connections.
- Manually trigger a full synchronization task to check whether catalog metadata has been synchronized from the specified data source to the knowledge base, and that the update frequency field displays correctly.
- Generate a download link for a catalog document, verify that access is denied without the `FILE_TOKEN_KEY`, and that the document opens normally with a valid token.
- Access the configured `FE_DOMAIN` to check that the page loads normally and the public data catalog list displays correctly.

The values provided are common starting points and should be measured against the reader's own samples.
