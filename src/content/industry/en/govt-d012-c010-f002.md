# Internal Office and Employee Services for Highway Maintenance and Road Property Rights Management: Vector Models and Indexes

## What the data for this category looks like
Entities responsible for highway maintenance and road property rights management typically obtain daily data from multiple business systems, including highway maintenance management systems, bridge and tunnel monitoring systems, and road administration patrol systems. Daily documents include maintenance plans, patrol logs, road defect disposal forms, road-related construction permits, and road property damage compensation forms. Some documents include structured fields such as mileage, defect level, and disposal time limit. Data updates occur daily. The data structure includes text records, structured tables, and monitoring values. Individual document lengths vary widely.

## What constraints these characteristics impose on the vector models and indexing stage
Heterogeneous data sources from multiple systems require the indexing stage to support unified parsing and embedding of multi-format documents, to avoid format adaptation errors. The daily data volume and update frequency require configuring automatic trigger rules for incremental indexing, to reduce resource consumption from full indexing. Structured numerical fields contained in documents require vector models to adapt to embedding of mixed data types, to ensure unified expression of semantic and numerical information. The wide variation in individual document length requires adjusting chunking parameters to balance embedding accuracy and indexing efficiency, to avoid token overflow caused by overly long chunks or destroyed semantic integrity from overly short chunks.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the typical content length of patrol logs and road defect disposal forms, avoids overly fragmented chunks or lost semantic connections |
| Overlap Length | 50–100 characters | Retains context information between adjacent chunks, ensures coherence of road defect descriptions and construction permit clauses |
| `defaultToken` | 8192 | Matches the maximum input token limit of the Qwen3-Embedding-8B model, meets the embedding needs of most single documents |
| `maxToken` | 16384 | Covers the total token limit for a single batch of indexing tasks, adapts to the total volume of multi-system data added daily |
| Similarity Threshold | 0.72–0.85, calibrated via actual testing | Distinguishes road defect records for similar road sections, prevents accidental recall of documents from non-target areas |
| Single Search Limit | Top 10 results | Matches the rapid query needs of road administration law enforcement and maintenance scheduling, filters redundant results |

## Three common configuration errors
- Phenomenon: Indexing tasks remain in the "Indexing" state for a long time, with no progress updates or error reports. Cause: Local embedding model access ports and authentication parameters are not configured correctly, or the `defaultToken` setting exceeds the model's supported limit.
- Phenomenon: After adding a new embedding model, the configuration of the original model with the same name is automatically overwritten. Cause: Only the model name is used as the unique configuration identifier, and no suffix is added to distinguish different deployment instances.
- Phenomenon: Irrelevant road defect records from cross-road sections are included in recall results. Cause: The similarity threshold is set too low, causing documents with similar semantics but different road section information to be matched.

## How to confirm the configuration is correct
- Upload a single standard patrol log document, check whether the indexing status in FastGPT v4.17.0 updates to "Completed" within 1 minute.
- Input a query statement containing a specific road section number and time, verify that the recall results only include business documents from the corresponding area.
- View the embedding model's running logs, confirm that the `maxToken` parameter is loaded correctly, and there are no error reports related to token overflow.
- On the platform's model configuration page, confirm that the added embedding model names are unique, with no duplicate configuration entries.
