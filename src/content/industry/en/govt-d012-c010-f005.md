# Internal Office and Employee Services for Highway Maintenance and Road Property Rights Management: Tool Calling and Plugins

## What the data for this category looks like
It typically covers daily office data from transportation bureaus, highway development centers, maintenance units, and road law enforcement agencies. Data sources include highway maintenance management systems, bridge and tunnel monitoring systems, road patrol systems, and traffic flow monitoring data, with a daily update frequency. Daily documents include maintenance plans, patrol logs, disease disposal orders, road construction permits, and road property damage compensation documents. Document fields include disease location (kilometer stake marks), disposal time limits, permit numbers, compensation amounts, and no fixed unified numerical standards exist.

## What constraints these characteristics impose on the tool calling and plugins link
Data from multiple systems requires tool calling to support connections to heterogeneous data sources, avoiding data fragmentation. The daily update feature requires tool calling to adapt to real-time or scheduled synchronization logic, ensuring data timeliness. The presence of multiple document types requires the file upload tool to support multiple formats, and the text extraction tool to support matching category-specific fields. The most time-consuming links of patrol identification, work order arrangement, and road-related processing require tool calling to automatically complete document parsing, work order generation and other operations, reducing manual intervention.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0, formulated for the core parameters `toolChoice` and `functionCall` of tool calling and plugins, combined with the characteristics of this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to office scenarios with parallel tool calls, no need to manually specify a single tool function |
| `functionCall` | `enabled` | Supports custom plugin function calling logic, adapts to complex operations such as road work order generation |
| Default file upload format | All supported formats | Adapts to batch upload requirements for multiple types of documents including maintenance plans and patrol logs |
| Single file upload limit | 1000 MB | Adapts to large-volume documents such as patrol videos and bridge and tunnel monitoring data |
| Global variable transfer rule | Bind external interface input parameters | Meets the requirement for external platforms to pass dynamic parameters such as work order numbers and patrol dates after the workflow is published |
| Text extraction tool field matching | Map according to preset fields of maintenance documents | Accurately extract category-specific document fields such as disease location and disposal order number |
| Tool call retry count | 2-3 times | Addresses call failures caused by temporary delays in data synchronization |
| Maximum tool call wait duration | 600 seconds | Adapts to temporary delays in maintenance data synchronization, avoids long-term blocking of workflows |

## Three common misconfigurations
- Symptom: The file upload tool fails to recognize maintenance documents, and an "unsupported format" prompt appears during MCP connection. Cause: The default file upload format is not set to all supported formats, only some document types are selected.
- Symptom: The model returns empty results or an "empty parameter" error when called. Cause: The token key generated by the third-party platform is not correctly bound, or the API address configured for the model is filled incorrectly.
- Symptom: The text content extraction tool prompts field extraction failure after running. Cause: The extraction mapping rules are not configured according to the preset fields of maintenance documents, and general field matching logic is used incorrectly.

## How to confirm the configuration is complete
- Upload one maintenance plan and one patrol log, check whether the document content can be recognized and extracted normally.
- After configuring the model key of the third-party platform, initiate a simple text question and answer call to confirm that there is no empty parameter error.
- Edit the text extraction tool, select the preset fields of maintenance documents, run a test extraction, and confirm that the field extraction results are correct.
- Publish the workflow interface with global variables, use external tools to pass dynamic parameters, and check whether the interface return contains the passed parameter values.
