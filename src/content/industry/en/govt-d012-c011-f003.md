# Internal Office and Employee Services for Pension, Work Injury, and Unemployment Benefit Verification: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data sources for this category include social insurance handling systems, personal benefit records, labor relations and work injury identification systems, and the electronic social security card platform. Data is updated and synchronized daily. Daily business documents cover benefit application forms, payment period certificates, retirement approval forms, work injury identification materials, and unemployment insurance benefit application materials. These documents include structured form fields and unstructured identification text. Data fields include identity identifiers, payment records, benefit calculation parameters, and identification material numbers. Corresponding data sources must be called step by step according to business links.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The multi-source data nature requires multi-turn dialogue to associate field variables from different systems, to avoid data inconsistency across links. Daily updated data sources require prompts to direct calls to the latest synchronized records, ensuring timeliness of benefit calculation. Diverse document types require multi-turn dialogue to differentiate verification logic for structured forms and unstructured materials, and gradually check key fields. The most time-consuming calculation and review links require multi-turn dialogue to proceed step by step per business processes, preventing logical confusion from loading excessive information at once.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` | Retain the first 20 context entries within a dialogue turn | Adapts to the step-by-step verification logic of benefit verification, avoids overly long context interfering with calculation judgments |
| `variables` | Bind real-time fields from social insurance handling systems and personal benefit records | Ensures dialogue calls use daily updated official business data |
| `chatId` | Bind the unique identifier of the current benefit verification work order | Associates dialogue logs with specific business work orders, facilitating subsequent review and traceability |
| Maximum context | 8000–12000 token | Calibrated through actual testing, covers verification and calculation needs for multiple materials in multi-turn dialogue |
| Question optimization | Enable and set to decompose questions by business link | Matches the step-by-step review process of pension, work injury, and unemployment benefit verification, adapts to FastGPT v4.17.0 configuration rules |
| Single search limit | Top 6 entries | Prioritizes recalling the most relevant payment records and identification material data, reduces interference from redundant information |

## Three Common Misconfigurations
- Workflow terminates after reaching the AI dialogue step, and the interface displays empty context fields. Cause: Failed to correctly bind `variables` to real-time data fields of the social insurance system, resulting in missing data sources for dialogue calls.
- No streaming output occurs after API calls, and the front end cannot display calculation results step by step. Cause: Did not enable streaming return configuration for multi-turn dialogue, only used synchronous return mode.
- Dialogue log annotation function cannot associate the corresponding material number. Cause: Did not bind the unique identifier field of the material document in `variables`, resulting in annotations failing to match specific business data.

## How to Confirm Proper Configuration
- Launch a test dialogue containing a payment period query, and check whether returned results include the latest synchronized personal benefit record data.
- Call the API to launch a multi-turn dialogue, and check whether context is retained by turn and the benefit calculation process proceeds step by step.
- View dialogue logs, and confirm that each annotation can be associated with the corresponding benefit application material or payment record field.
- Test a query missing key material numbers, and check whether the dialogue prompts for necessary supplementary business information.
