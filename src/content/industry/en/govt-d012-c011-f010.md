# Internal Office and Employee Services for Pension, Work Injury, and Unemployment Benefit Verification: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category originates from social insurance management systems, personal benefit records, labor relations and work injury recognition systems, and electronic social security card platforms. The update frequency is daily. Daily processed documents include benefit application forms, payment period certification forms, retirement approval forms, work injury recognition materials, and unemployment insurance benefit application materials. Data fields include benefit type identifiers, payment period records, qualification review results, material verification status, and others. Some documents are linked to unique business numbers. There is no fixed unified format, and fields need to be split according to business scenarios.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Multi-source data access requires the retrieval pipeline to support cross-system data association, to avoid incomplete recall caused by missing single-source data. The daily update frequency requires configuring incremental synchronization mechanisms to ensure that knowledge base content is aligned with management system data in real time. Diverse business document formats require document splitting before retrieval to adapt to different structures, avoiding truncation of key calculation information in long texts. Fields linked to business numbers require binding corresponding business context during retrieval to prevent confusion of benefit data among different insured individuals. At the same time, the core calculation link relies on accurate policy basis, requiring that retrieved content strictly matches the rule requirements of the current verification scenario.

## How to set configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Accurately match policy clauses and business materials for benefit verification, filter low-relevance interfering content |
| `limit` | Top 3–5 entries | Internal office scenarios require quick location of core basis; too many entries increase the information screening burden of review personnel |
| `searchMode` | `vector+keyword` | Balance semantic matching and precise keyword hits, adapt to mixed retrieval needs of fixed business fields and policy texts in benefit verification |
| `usingReRank` | Enabled | Rerank initial retrieved results to improve the ranking priority of high-relevance content, adapt to mixed multi-document retrieval scenarios |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expand retrieval terms to cover common synonymous expressions in benefit verification, such as the association between "pension benefit" and "retirement benefit" |
| `collectionIds` | Bind the IDs of corresponding business collections | Limit the retrieval scope to the exclusive knowledge base collection for pension, work injury, and unemployment benefit verification, avoiding interference from irrelevant content in retrieval results |

## Three common configuration mistakes
- Embedded business document images in retrieval results cannot be displayed properly. The cause is that the accessible path of images was not correctly extracted during knowledge base import, or the image external link adaptation rule was not enabled in the configuration.
- Knowledge base retrieval response time exceeds 10 seconds. The cause is failing to limit the retrieval collection scope, leading to full knowledge base retrieval, or the `similarity` threshold is set too low, recalling too many low-relevance content which increases processing time.
- Only 1 result is returned per retrieval. The cause is the `limit` parameter being incorrectly set to 1, or not enabling multi-mode mixed retrieval, using only a single retrieval logic which fails to cover all business scenarios.

## How to confirm the configuration is correctly set
- Initiate a test query related to pension benefit verification, check that the number of retrieval results matches the preset `limit` value range.
- Upload a test work injury recognition material, verify whether the retrieval results include the associated policy basis for this material.
- View the knowledge base synchronization log, confirm that the daily incremental synchronization task is executed normally, with no data omission or error prompts.
- Compare the sorting of retrieval results before and after enabling `usingReRank`, verify whether the priority of high-relevance content has been improved.

The values provided here are common starting points and should be measured against the reader's own samples.
