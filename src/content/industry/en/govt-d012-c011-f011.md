# Internal Office and Employee Services for Pension, Work Injury, and Unemployment Benefit Verification: Forms and Interactions

## What Data for This Category Looks Like
Data for this category comes from social insurance handling systems, personal benefit records, labor relations and work injury verification systems, and the electronic social security card platform. The update frequency is daily. Commonly associated documents include benefit application forms, payment period certificates, retirement approval forms, work injury verification materials, and unemployment benefit application materials. Data fields include payment period, benefit calculation base, verification number, applicant identity information, and more. Units include year, month, yuan, entry, and others. The data volume of a single document fluctuates with business complexity.

## Constraints for Forms and Interactions
Cross-system data sources require forms to support linked loading of associated fields. Entering identity information automatically pulls corresponding payment period, verification materials, and other data. Multiple document types use differentiated fields, so conditional rendering separates form modules for pension, work injury, and unemployment benefit verification. Inconsistent data units require adding unit conversion prompts in forms to prevent entry errors. Daily updated data sources require forms to run latest data verification before submission, avoiding expired information use. Strict potential consequences require forms to include multiple layers of required field validation to reduce missing or incorrect entry risks.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | Trigger delay set to `800 ms`, linked interface timeout set to `10 seconds` | Social insurance data interface responses typically take 5-10 seconds; this delay setting avoids frequent interface calls |
| User selection node | Group options by benefit type, expand the pension benefit module by default | The three business scenarios have large differences; grouping reduces user search effort |
| Form validation rules | Identity information field validation for 18-character length, payment period field value range `0–120 years` | Complies with standard ranges for social insurance handling identity information and payment periods |
| Input content limit | Single field input limit set to `2000 characters` | Adapts to the standard length of benefit application description content |
| Workflow variable configuration | Allow API to pass knowledge base ID as an input parameter variable | Adapts to the need to call corresponding social security policy knowledge bases for different handling scenarios |

## Three Common Configuration Mistakes
- Phenomenon: After passing a knowledge base variable when calling a workflow, the knowledge base search node cannot read the variable content. Cause: The variable was not configured as a workflow input parameter, or the variable scope does not cover the knowledge base search node.
- Phenomenon: After workflow A calls workflow B, all nodes after the `userSelect` node in workflow B stop executing. Cause: The default submission action for the `userSelect` node was not set, or the child workflow did not correctly receive context parameters passed by the parent workflow.
- Phenomenon: An error is triggered when entering benefit application description content, prompting that the content exceeds the limit. Cause: The form input content limit configuration was not adjusted, and the default small character limit was used.

## How to Confirm Configuration is Complete

- Switch the benefit type option, check whether the form module switches display correctly according to the selection.
- Call the API to pass the knowledge base ID variable, check whether the knowledge base search node can correctly read the variable content.
