# Internal Office and Employee Services for Elderly Care Facility Supervision: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Core data for this category comes from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and facility operation ledgers. Updates occur on a monthly basis. Daily processed documents include elderly care facility filing materials, operation subsidy application documents, service quality inspection forms, safety hazard rectification ledgers, and elderly admission files. Most data fields are entity-type content such as facility ID, number of beds, inspection date, and subsidy application status.

## What constraints these characteristics impose on knowledge base retrieval and recall
Monthly updated data requires retrieval and recall timeliness to fit low-frequency update scenarios, with no need for frequent index refreshes. Document formats vary widely across multiple sources, including structured tables, scanned files, and plain text files. This requires adapting chunking and recall rules for multi-source data. Supervision-related data involves facility qualifications and safety information. Retrieval results must ensure precise matching to avoid irrelevant content interfering with supervision judgments. Multiple document types such as filings, inspections, and subsidies must be linked. Recall must support cross-document associated retrieval to meet the needs of supervision personnel verifying multi-dimensional information.

## Three common configuration errors
1.  Symptom: After uploading scanned PDF documents, no matching text content is returned in retrieval results. Cause: The document OCR recognition function is not enabled, and text extraction and index construction have not been completed for scanned files.
2.  Symptom: When calling the chat API, returned results do not carry referenced knowledge base ID information. Cause: The request parameter for returning knowledge base metadata is not configured, or the output switch for reference information is not enabled.
3.  Symptom: After manually or via API adding knowledge base files, newly added content is not included in retrieval results in a timely manner. Cause: Knowledge base index refresh is not triggered, or the index update cycle does not match the business update rhythm.

## How to confirm the configuration is correct
- Upload a test document of elderly care facility filing materials, perform keyword retrieval, and verify that retrieved results include the document’s content.
- Enable API debug mode, send a request containing supervision scenario keywords, and confirm that returned results carry knowledge base ID and reference source information.
- Upload a scanned safety inspection record form, verify that retrieval results can extract inspection items and rectification requirements from the table.
- Adjust the `similarity` parameter range, verify that the relevance of retrieval results changes as expected.
