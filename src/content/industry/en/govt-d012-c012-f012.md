# Internal Office and Employee Services for Elderly Care Facility Supervision: Deployment and Upgrade

## Data for this category
Core data comes from elderly care service information platforms, civil affairs statistics systems, fire safety inspection records, and facility operation ledgers. Updates occur monthly.
Daily processed documents include elderly care institution filing materials, operation subsidy application forms, service quality inspection checklists, safety hazard rectification ledgers, and elderly admission files.
Data fields cover institution qualifications, bed counts, service records, and rectification progress. It must match the exclusive business dimensions of supervision scenarios, with no universal fixed fields. Adapt processing based on the original format of each data source.

## Constraints during deployment and upgrade
Monthly updated business data requires deployments to include a stable long-connected database. This prevents connection interruptions during synchronization cycles that would damage supervision data integrity.
Processing multiple types of business documents requires storage configurations that support different formats of filing and rectification materials. This ensures all document types can be uploaded and retrieved normally.
Supervision data errors can lead to incorrect subsidy distribution and safety accidents. Upgrade processes must include a pre-configured version rollback mechanism, and a full data backup must be completed before upgrading to reduce change risks.
Cross-department data docking requires clear permission configurations for each data source during deployment. This prevents data synchronization abnormalities from harming cross-department collaboration efficiency.

## Recommended configuration parameters
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 connections` | Adapts to the concurrent connection requirements of monthly batch data synchronization, prevents connection pool exhaustion from causing synchronization interruptions |
| `MONGODB_URI` | Fill in the exclusive MongoDB connection address for elderly care supervision data, with authentication parameters | Isolates supervision business data from other system data, ensures the security of sensitive supervision information |
| `REDIS_URL` | Configure an independent Redis instance, set a `600 second` cache expiration time | Caches institution filing and bed data updated monthly, reduces the pressure of high-frequency database queries |
| `STORAGE_S3_ENDPOINT` | Connect to the internal compliant object storage service address of the institution | Uniformly stores business documents such as filing materials and rectification ledgers, meets the compliance storage requirements of internal supervision |
| `FE_DOMAIN` | Fill in the exclusive internal access domain name of the supervision system | Isolates the access paths of internal office and external services, ensures the security of internal operations |

## Three common mistakes
- An `Error response from daemon: error from registr` error occurs during upgrade. The cause is a failed container image pull during the upgrade process or a conflict with locally cached image versions, and old version images were not cleaned up in advance.
- After upgrading to the specified version, the frontend displayed version number does not match the actual deployed version. The cause is that the frontend static resources were not rebuilt and deployed, and the frontend files inside the container were not updated synchronously.
- MongoDB database connections are interrupted after several days of operation. The cause is that a reasonable threshold for `DB_MAX_LINK` was not configured, the connection pool was exhausted and not automatically released, or network policy changes temporarily blocked database port access.

## How to confirm configuration is complete
- Run the database connection test command to verify that the addresses configured in `MONGODB_URI` and `REDIS_URL` can establish normal connections, with no timeout or authentication failure prompts.
- Upload a filing material document, complete upload and download via the storage service configured in `STORAGE_S3_ENDPOINT`, confirm that the storage path and permissions are normal.
- Trigger a simulated monthly data synchronization task, check the connection pool usage, confirm that the `DB_MAX_LINK` configuration does not cause connection exhaustion.
- Access the domain name configured in `FE_DOMAIN`, check that the frontend page loads normally and the version number matches the deployed FastGPT v4.17.0 version, confirm that the frontend configuration is effective.
