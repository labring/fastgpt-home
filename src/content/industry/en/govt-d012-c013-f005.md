# Internal Office and Employee Services for Internal Control Evaluation, Audit and Rectification: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data sources for this category include enterprise internal control systems, ERP systems, financial shared services systems, audit management systems, and procurement contract project systems.
Daily documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closing certificates.
Data fields include issue number, responsible department, rectification status, rectification completion deadline, and other items. There are no uniform mandatory units; values vary based on document type.
Data is updated annually. A single update covers all archived content related to audit and rectification within the full cycle.

## Constraints Imposed on Tool Calling and Plugin Workflows
Heterogeneous data sources across multiple systems require tool calling to adapt to interface formats and permission rules of different systems. This prevents cross-system calling conflicts.
Annual update frequency means tool calling does not need high-frequency triggering. It can run on a fixed schedule or manually.
Diverse document types with large structural differences require plugins to support parsing multiple formats. These include structured ledgers, semi-structured working papers, and non-standard rectification certificates.
The most time-consuming link of extracting business samples and vouchers requires direct access to raw data from backend systems via tool calling. This reduces manual entry costs.
Standardized output required for audit issues and rectification requires tool calling to return structured data. This meets archiving and review needs.

## Three Common Misconfigurations
- Knowledge base retrieval content that is too long will not trigger the reordering model for sorting, and results will not be sorted by the importance of audit documents. Cause: Long text reordering configuration is not enabled, or the reordering trigger threshold is set too high, causing long-document retrieval results to not undergo reordering processing.
- A `400 Messages with role 'tool' must be a response to a preceding message` error is returned when calling tools. Cause: The context of the tool calling message is not correctly associated with the preceding user question, or the tool return message is not assembled in accordance with conversation format requirements.
- Plugin calling failure does not trigger retries, causing interruptions in audit rectification data synchronization. Cause: The tool calling retry mechanism is not configured, or the retry count is set to 0, which cannot handle temporary fluctuations in enterprise internal systems.

## How to Confirm Correct Configuration
- Upload a complete audit working paper, trigger tool calling, and check whether issue entries can be automatically extracted and associated with rectification ledger data.
- Construct a retrieval request for an ultra-long text audit issue list, and verify whether the reordering model re-sorts the retrieval results.
- Simulate a scenario where an enterprise internal system interface is temporarily unavailable, and check whether the tool calling triggers the retry mechanism and completes data synchronization after the interface recovers.
- View the tool calling log, and confirm that the configuration values of the `toolChoice` and `functionCall` parameters match the preset values.

The values provided here are common starting points. They should be measured against the reader's own samples.
