# Internal Office and Employee Services for Internal Control Evaluation, Audit and Rectification: Forms and Interactions

## What data for this category looks like
Data comes from enterprise internal control systems, ERP, financial shared services systems, audit management systems, and procurement contract project systems. The update frequency is annual. Daily documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closing certificates. Document fields cover issue identifiers, rectification status, supporting material association items, and other fields. There is no unified fixed unit, and values vary based on the specific document type. Cross-system data must undergo format alignment before being included in unified form processing workflows. Archived historical data from annual batches must support bulk import and retrospective query functions.

## What constraints these characteristics impose on the "forms and interactions" link
The annual update frequency requires forms to support bulk import of historical data and historical version retrospective queries, to avoid re-entering annual archived content. Multi-system data sources require forms to be configured with cross-system field mapping rules, to adapt to data format differences across systems and ensure extracted business samples and voucher data match accurately. Diverse document types require forms to support switching between multiple templates, to meet field requirements for different business scenarios such as internal control self-assessment and audit rectification. The most time-consuming extraction and rectification tracking links require forms to support bulk task triggering and status tracking, while also configuring an operation logging mechanism to mitigate the risk of repeated audit issues.

## Configuration guidelines
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` bulk import | Import according to the annual archived data template | Adapts to the annual update data characteristics of this category, matches the import requirements for bulk documents such as internal control self-assessment reports |
| `userSelect` permission grouping | Divide by internal control, audit, and rectification positions | Aligns with role permission divisions for internal office work in Chinese state-owned enterprises and public sector entities, prevents unauthorized access to sensitive data such as rectification ledgers |
| Single submission limit | Top 50 entries | Adapts to the sample size for single-batch processing such as audit working papers, avoids system overload |
| Cyclic task triggering | Trigger according to rectification batches | Matches the bulk processing requirements for rectification tracking, adapts to business scenarios for processing array elements in bulk |
| Timeout threshold | 600 seconds | Adapts to the time required for cross-system data pulling, avoids task interruptions caused by multiple data sources |
| Template switching | Preset according to document type | Matches diverse daily document types, quickly switches to match field requirements and interaction logic |

## Three common misconfigurations
- When configuring cyclic tasks, no response occurs when the AI session is called in the loop body after passing an `array<string>` array. The cause is that field mapping for array elements was not configured in `formInput`, causing the loop body to fail to correctly identify the processing object.
- After configuring a third-party endpoint, the corresponding model is not displayed in the interface. The cause is that the synchronization rule for the model list was not configured in `userSelect`, causing the endpoint configuration and model display to be unbound.
- When enabling the ollama model, the preset system prompt does not take effect. The cause is that the system prompt trigger condition was not bound in the initial form interaction configuration, causing the system prompt to not be loaded into the conversation context.

## How to confirm configurations are correct
- After importing annual archived data, check if the form fields match the preset template, adjust the field mapping rules until the match is complete.
- After triggering a cyclic task, view the task log to confirm that each array element has been processed correctly, adjust the cyclic trigger configuration until it aligns with the business process.
- After configuring a third-party endpoint, manually trigger the model list refresh, confirm that the models displayed in the interface correspond to the entered baseURL, adjust the permission configuration until they match.
- After submitting the system prompt configuration, initiate a test conversation, confirm that the initial conversation prompt matches the preset system prompt, adjust the binding rules until it takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
