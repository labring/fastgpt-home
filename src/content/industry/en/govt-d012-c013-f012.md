# Internal Office and Employee Services for Internal Control Evaluation, Audit and Rectification: Deployment and Upgrade

## What data falls under this category
The data for this category mainly comes from enterprise internal control systems, ERP, financial sharing systems, audit management systems, and procurement contract project systems, with an annual update frequency. Daily processed documents include internal control self-assessment reports, audit notices, audit working papers, issue lists, rectification ledgers, and rectification closure certificates. Most document structures include fields such as issue number, rectification responsible person, rectification deadline, supporting material links, and progress status. There is no fixed unified unit field, and adaptation must be carried out according to the native fields of the associated business systems.

## What constraints do these characteristics impose during deployment and upgrade
Since data sources involve multiple internal enterprise systems, configure docking parameters for each system in advance during deployment to ensure compatibility of data extraction.
Since the update frequency is annual, there is no need to adjust incremental synchronization cycle parameters during upgrade, and focus can be placed on optimizing the stability of full synchronization.
Since documents include multiple business types, configure parsing rules adapted to different document structures during deployment to avoid failure to correctly identify some business documents.
Since the rectification process involves multi-link association, configure data association verification logic during deployment to ensure the accurate correspondence between issues and rectification ledgers, and avoid deviations in subsequent audit processes.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | Stores data from audit management systems and rectification ledgers, adapts to persistence requirements for multi-source business data |
| `PG_URL` | `postgresql://username:password@host:port/dbname` | Connects to structured business data from ERP and financial sharing systems, supports complex cross-table associated queries |
| `REDIS_URL` | `redis://:password@host:port/0` | Caches frequently accessed rectification issue lists and audit working paper summaries, improves query response speed for internal office scenarios |
| `DB_MAX_LINK` | `100–200` | Adapts to concurrent connection requirements during annual full synchronization, prevents synchronization failures caused by exhausted database connections |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` (or enterprise self-built object storage address) | Stores unstructured documents such as rectification closure certificates and audit working papers, supports internal permission control |
| `FE_DOMAIN` | `https://internal-audit.your-company.com` | Configures the access domain name of the internal office portal, adapts to access rules for internal offices of state-owned enterprises |

## Three Common Misconfigurations
- Phenomenon: A `connection refused` error occurs when executing `docker-compose up`, and the service container fails to start. Cause: The `REDIS_URL` or `PG_URL` parameters are not configured correctly, resulting in failed connections to the database or cache service.
- Phenomenon: Front-end code changes cannot be synchronized to the deployed instance, and the page does not update. Cause: The `FE_DOMAIN` is not configured to point to the correct static resource storage path, or the front-end container is not restarted to load updated code.
- Phenomenon: Audit issues and rectification ledgers cannot be automatically associated, resulting in a large number of empty matching results. Cause: The `DB_MAX_LINK` value is not set reasonably, leading to insufficient connection count during cross-table queries and invalid association logic.

## How to Verify Successful Configuration
- In FastGPT v4.17.0, execute the `docker-compose ps` command to confirm that all service containers are running and no exceptions have exited.
- Log in to the FastGPT backend, enter the data connection management page, and verify that the connection status of `MONGODB_URI` and `PG_URL` shows normal.
- Upload a rectification ledger document, perform a parsing test, and confirm that the issue number and rectification responsible person fields in the document are correctly extracted.
- Initiate an annual full synchronization task, check the synchronization log, and confirm that there are no prompts for data extraction failures or association errors.

The values provided are common starting points and should be measured against the reader's own samples.
