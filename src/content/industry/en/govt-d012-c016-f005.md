# Internal Office and Employee Services for Medical Insurance Expense Settlement Audit: Tool Calling and Plugins

## What Data for This Category Looks Like
The data processed in this category comes from the national medical security information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical treatment settlement platform, and is updated daily. Daily processed documents include medical insurance settlement lists, expense details, medical record homepages, prescriptions, rejection lists, and settlement reconciliation statements. Core fields include diagnosis and treatment item/drug consumable codes, expense amounts, insured person information, and diagnosis and treatment dates. Verification must be completed strictly in accordance with the national unified medical insurance coding rules.

## Constraints Imposed on Tool Calling and Plugins by These Characteristics
Since data is updated daily and must comply with national unified coding rules, tool calling must automatically match corresponding tools via the `toolChoice` configuration, and pull the latest medical insurance catalog library in real time to avoid fund risks caused by coding matching errors. When processing settlement documents in batches, interfaces must be called to complete consistency verification for multiple documents. The tool calling context must adapt to long-text settlement lists and detailed data. When handling rejection reconciliation, multi-source data (settlement records and rejection lists) must be associated. Plugins must support cross-data source field linkage queries, and the response time of a single call must meet the time requirements of the handling process to avoid delaying reconciliation progress. At the same time, field verification for single-item audits must strictly align with medical insurance data specifications; otherwise, payment rejection disputes or delayed payments may occur.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts automatic tool selection for multiple types of medical insurance documents, covering core scenarios such as coding matching and data verification |
| Maximum number of single tool calls | First 8 entries | Matches the daily batch processing volume of documents, avoiding resource overload from a single call |
| Tool call timeout period | 600 seconds | Adapts to response delays from cross-medical insurance platform interfaces, ensuring batch audit processes are not interrupted |
| `functionCall` | Enable mandatory field verification | Ensures returned fields such as codes and amounts comply with medical insurance data specifications, avoiding invalid results |
| Plugin data source binding | Bind the two core sources: medical insurance catalog library and HIS interface | Matches the data source requirements of this category, enabling real-time verification of codes and expenses |
| Batch processing batch size | 100 entries per time | Adapts to the daily batch processing scale of medical insurance handling, balancing efficiency and resource usage |

## Three Common Configuration Errors
- The URL image address returned by the plugin cannot be displayed on the interface. The cause is that the content rendering rules for tool calls are not configured, and the image links are not converted into displayable formats.
- Locally created MCP services cannot be called. The cause is that the access port permissions for local services are not enabled in the platform configuration, and the correct service address format is not specified.
- The coding matching result returned after tool calling is incorrect. The cause is that mandatory verification for `functionCall` is not enabled, causing the LLM to return codes that do not match the latest medical insurance catalog library data.

## How to Verify Proper Configuration
- Upload a single medical insurance settlement list, trigger tool calling, and check whether the returned coding matching result matches the medical insurance catalog library.
- Test batch plugin calls to verify whether reconciliation data for multiple rejection lists can be pulled normally.
- Check the tool call logs to confirm that the response time of each call does not exceed the preset timeout threshold.
- Simulate a local MCP service call to verify whether the plugin can normally receive and process returned medical insurance data.
