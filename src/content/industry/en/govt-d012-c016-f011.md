# Internal Office and Employee Services for Medical Insurance Reimbursement Settlement Review: Forms and Interactions

## What does the data for this category look like?
This category processes data from the national medical insurance information platform, hospital HIS and medical insurance interfaces, medical insurance catalog and coding library, and cross-regional medical treatment settlement platform. The update frequency is daily. Documents processed daily include medical insurance settlement lists, expense details, medical record homepages, prescriptions, denial lists, and settlement reconciliation statements. Core fields cover diagnosis and treatment item codes, pharmaceutical and consumable codes, expense amounts, insured person identity identifiers, settlement status, and more. All data must be matched against the official medical insurance coding library for verification, with no additional custom fields.

## What constraints do these characteristics impose on forms and interactions?
Data sources for this category are scattered and require daily updates, so forms must support batch import from multiple data sources and real-time verification. Core documents contain multiple types of structured fields that must strictly match the official medical insurance coding library, so forms must include built-in field format verification logic. The business characteristics of single or batch processing require the interaction interface to support switching between single work order and batch work order operations. At the same time, the permission isolation requirement for internal office work requires forms to limit operating roles to exclusive positions such as medical insurance handling and review, to prevent unauthorized operations.

## How to configure settings?
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable multi-field linkage verification | Required fields such as diagnosis and treatment item codes and expense amounts must be verified to avoid invalid data entering the review process |
| `userSelect` | Limit review roles to medical insurance handling positions | Differentiate different permissions for internal office work, in line with the post responsibilities and requirements of medical insurance review |
| Batch import upper limit | 500 entries per time | Match the batch processing rhythm of daily updated data to avoid interface timeouts |
| Field verification rules | Match the medical insurance catalog coding library | Ensure that the entered codes are consistent with the official library, reducing subsequent review errors |
| Knowledge base selection trigger | Automatically bind upon work order creation | Associate the exclusive knowledge base corresponding to the settlement data to avoid confusion across folders |
| Single search upper limit | Top 10 entries | Adapt to the number of associated document retrievals for a single settlement form, avoiding information overload |
| Timeout threshold | 600 seconds | Adapt to the average response duration of multi-data source interface calls |

## Three common configuration mistakes
- The knowledge base drop-down menu on the interface has no options matching the current settlement data: The variable assignment logic linked to `formInput` is not configured, causing the knowledge base binding to be disconnected from the work order data, and unable to dynamically associate documents in the corresponding folder.
- A field format error is returned when batch importing settlement lists: The required field verification of `formInput` is not enabled, and invalid data without valid diagnosis and treatment item codes is not filtered, resulting in interface verification failure.
- Unable to reuse previous configurations when performing denial reconciliation operations: The fixed workflow node triggered by the work order is not bound in `userSelect`, causing parameters to need to be reconfigured for each operation and unable to be fixed in the workflow.

## How to confirm the configuration is complete?
- Create a new test settlement work order, check whether the form field automatically loads verification prompts for the corresponding medical insurance catalog codes
- Batch import 50 test settlement lists, confirm that the import progress is normal and no format errors occur
- Select an already created work order, check whether the fixed data analysis operation appears in the workflow node list
- When retrieving associated documents, confirm that only the knowledge base content in the folder to which the current settlement data belongs is displayed
