# Internal Office and Employee Services for Medical Institution Supervision and Public Health Inspection: Tool Calling and Plugins

## What this category of data looks like
Data for this category is collected from the health supervision information system, medical institution electronic registration system, complaint reporting platform, and law enforcement inspection records. It is updated once per month. Daily processed documents include supervision inspection forms, medical institution practice licenses, rectification notices, supervision opinions, and penalty case files. Data fields include institution main body name, license number, inspection items, rectification requirements, and penalty-related information. All fields use government-compliant standard formats, with no custom units.

## Constraints for Tool Calling and Plugins
Since this category of data updates monthly, tool calling cache validity must match this cycle. This prevents returning expired core information such as institution qualifications and rectification status.
Government documents use standardized formats, so tool calling must strictly align with official field names. This avoids call failures caused by parameter mismatches.
Multi-source data requires tools to support cross-system retrieval. Tools must integrate information from platforms including health supervision and medical institution registration systems. Data source compliance must also be verified to ensure call result authority.
On-site law enforcement has real-time requirements. Tool calling response speed must adapt to network fluctuations in field work scenarios.

## Configuration Settings
The following configurations are designed for FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Automatically adapts to multi-source data call scenarios, no manual tool specification required |
| Tool call timeout duration | 30–60 seconds | Adapts to network fluctuations in field law enforcement environments, calibrated via actual measurements |
| Number of results returned per call | Top 3–5 entries | Focuses on core government information such as institution qualifications and rectification status, avoiding result overload |
| Context window size | 2000–3000 token | Supports complete document content including law enforcement records and rectification notices |
| `functionCall` verification mode | Strict mode | Ensures call parameters strictly align with standard fields of government documents |
| Plugin authorization scope | Only internal government system domain names | Ensures compliance of data calls, prevents unauthorized access |

## Three Common Misconfigurations
- Phenomenon: Tool calls return `{"result": "Failed to get the VQD for query \"<query>\"."}`. Cause: Non-compliant query keywords are not filtered for health supervision scenarios, and content unrelated to government business triggers the tool.
- Phenomenon: A `400 <400> InternalError.Algo.InvalidParameter` error is received. Cause: The strict verification mode for `functionCall` is not enabled, and passed parameters do not match the standard field format of government documents.
- Phenomenon: No response occurs after a chat application calls a plugin. Cause: The plugin’s authorized access scope is not configured, preventing external networks from calling internal government system interfaces.

## How to Confirm Successful Configuration
- Submit a test request for medical institution qualification queries, and confirm that tool-returned fields match the standard format of the health supervision information system.
- Trigger a tool call, and verify that the number of returned results falls within the preset range to confirm the single-call configuration is active.
- Submit a test query, and check that the tool call response time stays within the preset timeout range to confirm the timeout configuration is active.
- Review the plugin’s authorization configuration, and confirm that only internal government system domain names are allowed to initiate calls to ensure compliance.

The values listed above are common starting points, and should be evaluated against the user’s own samples.
