# Internal Office and Employee Services for Social Insurance Enrollment Registration and Payment Verification: Forms and Interactions

## What This Category of Data Looks Like
Data for this category comes from social insurance handling systems, tax social insurance premium collection systems, market entity registration information, and shared public security and civil affairs data. The update frequency is daily.
Commonly used business documents include enrollment registration forms, payment base declaration forms, personnel change forms, social insurance premium verification notices, and personal benefit records. Fields include personnel identity identifiers, labor relationship certification material numbers, payment bases, unified social credit codes of units, and more. Payment bases are denominated in yuan. Personnel numbers use a fixed-length character format.

## Constraints Imposed on Forms and Interactions by These Characteristics
Multiple data sources require forms to support cross-system data pulling and verification, to avoid errors from manual entry. Daily update frequency requires form interactions to have real-time synchronization capabilities, to ensure data timeliness. Diverse business documents require forms to support modular configuration, to quickly switch field combinations for different business forms. Time-consuming links that require verifying personnel identity and labor relationships require forms to have built-in field verification rules, to intercept non-compliant input formats early. The need to reconcile data with tax collection systems requires forms to support cross-system data linkage, to reduce manual reconciliation workload.

## Configuration Guidelines
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind to multi-source data interfaces, enable field required validation | This category has multiple data sources, need to ensure entered fields are complete and meet cross-system format requirements |
| `userSelect` | Preset optional value ranges for personnel identity and labor relationship, restrict input formats | Need to quickly verify personnel identity and labor relationship, avoid invalid input |
| Form submission timeout setting | 600 seconds | The reconciliation link takes a long time, need to reserve sufficient time for cross-system data interaction |
| Batch submission data limit | First 20 entries | Matches the conventional batch processing scale of personnel change forms |
| Model input token length configuration | 8000–12000 token | Adapts to long-text forms and data query needs of social insurance business |
| Form auto-save interval | 300 seconds | Adapts to the periodic save needs of daily updated data, avoids loss of entered content |

## Three Common Misconfigurations
- The symptom is a "field format mismatch" error returned after form submission. The cause is that verification rules aligned with public security and civil affairs data were not configured for the personnel identity field.
- The symptom is no connection option for the corresponding data source in the tool call panel. The cause is that multi-source linkage configuration for `userSelect` was not enabled correctly.
- The symptom is a timeout error triggered when submitting forms in batch. The cause is that the set timeout period is shorter than the actual time required for cross-system reconciliation.

## How to Verify Configurations Are Correct
- Submit a test piece of personnel identity data, verify whether a format-specific validation popup is triggered.
- Enter the tool call configuration panel, confirm that `userSelect` is associated with the data source interface of the social insurance handling system.
- Simulate batch submission of 20 personnel change data entries, confirm that the submission process does not trigger a timeout error.
- Manually edit the form, wait 300 seconds, check whether the edited content was automatically saved.
