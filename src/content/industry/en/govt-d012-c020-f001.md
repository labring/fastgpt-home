# Internal Office and Employee Services for Territorial Spatial Planning Formulation and Implementation Evaluation: HTTP Interfaces and External Systems

## What data looks like for this category
The data for this category primarily comes from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics, and remote sensing images. The update frequency is once per year. Daily produced documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data fields include spatial coordinates, constraint indicators, population and economic parameters, etc. Units include hectares, square kilometers, population counts, etc. Most formats are multi-source heterogeneous spatial and text mixed formats.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multi-source heterogeneous spatial and text mixed data requires interfaces to support multi-format requests, and must adapt to different input types such as remote sensing image files and statistical table texts. The annual update frequency means interfaces do not need frequent polling, and a long request interval can be set. Spatial data has a large volume, so interfaces must configure a reasonable request size threshold to avoid transmission timeouts. Field differences across document types require interface parameters to flexibly match the data structures of different business scenarios, ensuring planning data can be correctly parsed and subsequently stored.

## How to set configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting Range | Rationale |
| --- | --- | --- |
| Request timeout duration | 600–1200 seconds | Adapts to large file transfer and complex parsing time for spatial data |
| `Authorization` | Bearer {custom secret} | Ensures interface call security and prevents unauthorized access |
| Request body size limit | 1000–2000 MB | Meets transmission requirements for large-volume spatial data such as remote sensing images |
| `variables` | Map core fields including spatial coordinates and constraint indicators | Ensures planning data passed in by external systems can be correctly parsed |
| `responseData` | Split returned results by planning document type | Facilitates subsequent classified storage and processing by internal office systems |
| Maximum request token count | 8000–12000 tokens | Adapts to long text parsing requirements for planning documents |

## Three common mistakes
- Symptom: Interface calls return a 403 status code, or the interface prompts authentication failure. Cause: The `Authorization` parameter is not configured correctly, and the secret format or permission range does not meet the requirements of the target interface.
- Symptom: Interface calls return an empty `responseData` field, or the internal office system cannot parse the returned content. Cause: The `variables` parameter is not mapped correctly, and fields passed in by the external system do not match the core parameters of the planning data.
- Symptom: Interface errors occur after uploading remote sensing images, or red numeric error codes are returned. Cause: Configured authentication parameters do not comply with target interface rules, leading to call failure.

## How to confirm configurations are correct
- Call the test interface, check if the returned `responseData` field includes core planning data fields such as spatial coordinates and constraint indicators.
- Upload a typical remote sensing image file, confirm the request is not blocked due to volume limits, and the interface returns a normal status code.
- Verify the validity of the `Authorization` parameter, ensure requests without the correct secret cannot call the interface.
- After configuring the `variables` mapping, pass in test planning data, check if the internal office system can correctly receive and parse the returned results.
