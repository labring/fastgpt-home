# Internal Office and Employee Services for Territorial Spatial Planning Compilation and Implementation Evaluation: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The data for this category primarily comes from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistical data sources, and remote sensing imagery. Daily output documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Data updates occur annually. Most document structures include spatial coordinate fields, constraint indicator items, regional population and economic statistical values. Units include hectares, square kilometers, ten thousand people, and others.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The annual updated data scale is relatively fixed but large in volume. Multi-turn dialogue must limit the context window to avoid loading redundant historical data that reduces response efficiency. Explicit format requirements for exclusive fields such as spatial coordinates and constraint indicators must be included in prompts to prevent the model from generating non-compliant planning content. The association between public opinion summaries and multi-source spatial data must be sorted out step-by-step through multi-turn dialogue. Prompts must guide the model to integrate information step-by-step according to document structure. The rigor of planning documents requires retaining original data reference identifiers during multi-turn dialogue to prevent the model from tampering with core constraint indicators.

## How to configure settings
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique code of the planning project | Isolate conversations for different planning projects and avoid cross-project context reuse |
| `messages` | Retain the most recent 8–12 rounds of conversation content | Control total context length to match the single-section text volume of planning documents |
| `variables` | Link to the territorial spatial basic information platform data interface | Enable dynamic calling of multi-source planning data and real-time updates during multi-turn dialogue |
| Maximum context length | 800–1200 characters | Match the standard single-section word count of planning documents and avoid exceeding model context limits |
| Context cache duration | 3000–4200 seconds | Align with the single-day work cycle of planning compilation and avoid dialogue interruptions due to cache expiration |
| Number of data returns per request | Top 5 entries | Prevent timeouts caused by loading excessive remote sensing images or statistical data |

## Three common configuration errors
- Phenomenon: Incorrect return results appear when calling the "get conversation record list" interface after configuring the offset parameter. Cause: The starting counting rule for the offset was not clarified, leading to misplaced data interception.
- Phenomenon: Different employees in the shared application view the same conversation history. Cause: `chatId` was not bound to the unique code of the planning project, resulting in different sessions reusing the same ID.
- Phenomenon: Global variable modifications do not take effect in real time during the same conversation. Cause: The prompt did not explicitly require synchronizing variable updates to the current conversation context, so variables only load in subsequent new conversations.

## How to verify successful configuration
- Call the "get conversation record list" interface and check whether the order of user questions and AI replies in the returned `messages` array is consistent.
- Log in to the shared application with different employee accounts, initiate conversations on the same topic, and confirm that each user can only see their own initiated conversation history.
- Modify the global variable value during the same conversation and verify whether the updated variable content can be called in subsequent conversation steps.
- Set the maximum context length to 800–1200 characters, initiate a conversation containing multiple sections of planning documents, and confirm that no context truncation error occurs in the response.
