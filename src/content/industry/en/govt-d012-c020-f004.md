# Internal Office and Employee Services for Territorial Spatial Planning Compilation and Implementation Evaluation: Workflow Orchestration

## What the data for this use case looks like
The data for this use case mainly comes from the national land spatial basic information platform, natural resources survey and monitoring data, population and economic statistics results, and remote sensing images. Daily output documents include comprehensive territorial spatial planning, detailed territorial spatial planning, special territorial spatial planning, planning implementation evaluation reports, and public opinion summaries. The data update frequency is annual. Most document structures contain spatial coordinate fields, constraint indicator items, regional scope parameters, and multi-source data comparison results. Field units include spatial and statistical units such as square kilometers, population count, and percentage. The text content of a single planning document can reach several thousand characters.

## What constraints do these characteristics create for workflow orchestration
Multiple scattered data sources require configuring multiple workflow nodes to pull different data types sequentially, to avoid excessive load on a single node. The annual update frequency requires the workflow to adapt to periodic data refreshes, and a scheduled trigger node must be configured to ensure data timeliness. Documents contain spatial coordinates and statistical data, so a data validation node must be set up to prevent process interruptions caused by format errors. For time-consuming links such as aggregating multi-source spatial data, coordinating the layout of three zones and three lines, and sorting public opinions, parallel processing and permission transfer nodes must be configured to adapt to cross-department collaborative office processes. If a process fails, it will cause delays in planning approval, project implementation conflicts and other consequences, so a failure retry and alert mechanism must be configured.

## How to set configurations
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset global variables including territorial spatial indicators and regional scope | Adapt to unified calling of fixed fields for planning documents, reduce duplicate configurations |
| Node trigger rules | Trigger based on the completion status of project nodes | Match the linear approval process of planning compilation, ensure each link executes in order |
| Knowledge base selection | Bind to the national land spatial basic information platform knowledge base | Match the use case-specific data source, ensure the accuracy of retrieved data |
| `nodeId` | Bind to the document parsing and data validation node IDs | Precisely control the execution order of workflow nodes, avoid data confusion across nodes |
| Failure retry count | 3 retries, 60-second interval | Address temporary network fluctuations when pulling remote sensing images and spatial data |
| Single data pull limit | Top 100 spatial records | Adapt to the single-batch data processing scale of planning documents, avoid node overload |

## Three common mistakes
- Issue: The document parsing node returns a 404 error and cannot read uploaded files in a server environment. Cause: No globally accessible variable for the file storage path is configured. Relative paths from local environments do not work in server environments.
- Issue: The workflow cannot call external applications to start. Cause: No permission and path parameters for application calls are configured via `variables`. The workflow only supports preset tool calling rules.
- Issue: Global variables cannot be passed to downstream nodes after being assigned. Cause: No variable assignment trigger timing is bound to the workflow entry node. Variables are not synchronized to subsequent links as the process runs.

## How to confirm the configuration is complete
- Test file uploads in both local and server environments, check if the document parsing node can read file content normally, confirm that the global variables for path configurations have taken effect.
- Trigger the workflow, check the node execution logs, confirm that the preset territorial spatial indicator parameters in `variables` have been correctly called by downstream nodes.
- Simulate a data pull failure scenario, check if the workflow triggers failure retries and alerts as configured, confirm that the retry rules and intervals have taken effect.
- Check the knowledge base binding configuration, confirm that retrieval results only include exclusive documents related to territorial spatial planning, with no irrelevant data mixed in.
