# Internal Office and Employee Services for Territorial Spatial Planning Formulation and Implementation Evaluation: Tool Calling and Plugins

## What the data for this category looks like
Daily documents for this category include overall territorial spatial plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Teams collect data primarily from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics data, and publicly available remote sensing images. Data updates occur once per year. Most document structures include spatial coordinate fields, constraint indicator items, regional scope parameters, and records of inter-departmental coordination opinions. Field units use standard natural resource industry formats such as hectares, square kilometers, and ten thousand people. Some documents include approval process node information for cross-departmental collaboration.

## What constraints do these characteristics create for the tool calling and plugins workflow
Data sources for this category are scattered, and include multi-source information of spatial and statistical types. Tool calling must adapt to format validation for cross-source data to avoid spatial coordinate drift or inconsistent statistical standards. The annual update frequency requires tool calling to configure plugins triggered on a fixed schedule, to regularly pull the latest remote sensing images and population and economic statistics data. Documents contain multiple content types, so tool calling must support structured parsing to distinguish between text-based public opinions and spatial layer data. The special nature of field units requires plugins to automatically complete unit matching and conversion during data integration, to avoid unit conflicts across documents that affect final planning evaluation results.

## Three common mistakes
- Symptom: Tool calling results embedded via iframe cannot display images and user avatars in some browsers, and only load correctly in specific browsers. Cause: Cross-origin resource sharing rules for plugins are not configured, so security policies in some browsers block loading non-same-origin image and avatar resources.
- Symptom: In a two-tier nested tool calling workflow, the first-tier AI returned content is printed out and cannot be hidden. Cause: The log output switch for tool calling nodes in the workflow is not turned off, so all tiered calling results are printed synchronously.
- Symptom: The tool calling module outputs AI reply content and triggers the next-level branch execution at the same time, and only one of the two actions cannot be executed. Cause: Execution link rules for tool calling are not configured, the default setting triggers both result output and branch flow, and the logic for result display and process branch triggering is not differentiated.

## How to confirm configurations are correct
- Trigger a tool call, check if the returned results include spatial data parsing content corresponding to the planning document, and verify that the data source and update time meet preset requirements.
- View plugin logs, confirm that the tool calling retry attempts and timeout duration configurations match the preset values, and there are no abnormal retries or timeout errors.
- Verify cross-origin resource sharing configurations, test tool calling results embedded via iframe in different browsers, and confirm that images and avatars load correctly.
- Check the function call whitelist, confirm that only tools related to core business can be called, and no unrelated tools are triggered.
