# Internal Office and Employee Services for Territorial Spatial Planning Compilation and Implementation Evaluation: Model Access and Configuration

## What Data This Category Uses
This category's data mainly comes from territorial spatial basic information platforms, natural resource survey and monitoring data, population and economic statistical results, and public remote sensing images. Daily processed documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries.
Data is updated annually. Fields include spatial coordinates, constraint indicators, population and economic statistical values, and other related content. Document structures typically include modules such as planning goals, spatial layout, and implementation evaluation. Overall data volume increases as planning coverage expands.

## Constraints for Model Access and Configuration
Annually updated data requires regular synchronization. Model access must adapt to parsing logic for batch spatial data.
Format differences between multi-source heterogeneous data require reserving data format adaptation parameters in configurations. Long text structures of planning documents require adjusting context window parameters to avoid truncating core planning indicators.
Unstructured text from public opinion summaries requires adapting the model’s semantic understanding configuration. Configuration items for multi-key management must be reserved to distinguish call permissions of different departments.
Error consequences are linked to approval delays and resource conflicts. A stable error capture and retry mechanism must be configured.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Adapt to the long text structure of planning documents, avoid truncating core indicators and spatial layout content |
| Maximum output token count | 2000–3000 token | Control single-round output length, meet the segmented generation requirements of planning evaluation reports |
| Temperature coefficient | 0.2–0.4 | Balance the rigor and semantic coherence of planning content, reduce the risk of random output |
| Tool call mode | auto | Automatically adapt to tool call requirements for spatial data parsing and planning logic deduction |
| API proxy key | Assign independent keys by department | Distinguish call permissions of different business departments, avoid configuration conflicts |
| API proxy address | FastGPT proxy address at deployment location | Adapt to resource paths for internal network access |

## Three Common Configuration Errors
- Existing configuration is overwritten after creating a new model configuration: When a new configuration is added under the same API model, the keys and parameters of the old configuration are lost. This occurs because multi-key independent maintenance mode is not enabled, and the global configuration overwrites existing settings by default.
- Tool call node returns 429 status code: Frequent prompts of excessive request rates appear during model calls. This occurs because reasonable request intervals and retry thresholds are not configured, and rate limits for batch calls of planning data are not adapted.
- Configured body parameters cannot be fully deleted and reappear: After a body parameter is deleted, the field still exists when the configuration page is re-entered. This occurs because front-end cache is not cleared, or the default parameter template is not updated.

## How to Confirm Configuration Completion
This guide applies to FastGPT v4.17.0.
- Test multi-department key switching: Use API proxy keys from different departments to initiate calls. Verify that respective configuration parameters take effect and do not interfere with each other.
- Trigger rate limit scenario: Initiate batch planning data parsing requests. Observe whether the preset error capture and retry mechanism is triggered.
- Verify long text adaptation: Import a complete territorial spatial overall plan document. Check that the model output does not truncate core content.
- Check body parameter status: Delete a body parameter, exit the configuration page, and re-enter to confirm the field does not reappear.
