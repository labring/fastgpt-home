# Internal Office and Employee Services for Territorial Spatial Planning Compilation and Implementation Evaluation: Forms and Interactions

## What data for this category looks like
Data for this category comes from the territorial spatial basic information platform, natural resource survey and monitoring data, population and economic statistics data, and remote sensing image data. Daily produced documents include territorial spatial overall plans, detailed plans, special plans, planning implementation evaluation reports, and public opinion summaries. Common data fields include spatial scope coordinates, constraint indicators, department opinion entries, and others. The update frequency is annual. Data volume varies widely, ranging from tens of megabytes per single report to hundreds of megabytes for remote sensing images. The configuration logic compatible with FastGPT v4.17.0 covers the data processing needs of this category.

## What constraints do these characteristics impose on the forms and interactions link
The data sources for this category are scattered, the update cycle is long, and the volume varies widely. This requires the forms and interactions link to support classified upload and verification of multi-source data. Document structures include spatial data and text content, so different types of input components must be distinguished. Errors may lead to delays in planning approval, so forms must strictly verify required fields and data formats. Additionally, collaboration scenarios involving multiple departments require forms to have permission-isolated interaction logic to prevent unauthorized access to sensitive planning data.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Split into text input, spatial file upload, multi-field linkage | Adapt to the mixed input scenario of text reports and spatial data for category documents |
| `userSelect` | Preset permission groups by department, associate exclusive knowledge bases | Adapt to permission isolation requirements for multi-department collaboration, prevent unauthorized access to sensitive planning data |
| File upload size limit | 1000 MB | Cover the common volume range of remote sensing images and large planning reports |
| Form verification rules | Required field verification, spatial format verification | Avoid delays in subsequent planning links caused by data errors |
| Context window length | 800–1200 characters | Adapt to the length requirements of single core segments of planning documents |
| Timeout threshold | 600 seconds | Adapt to the processing duration of multi-source data aggregation |

## Three common misconfigurations
- When calling the API with stream set to true, only partial fragments are returned and the complete result is not obtained. The cause is failing to configure the result splicing logic after the stream ends as required by the documentation, and not waiting for the stream termination event to trigger.
- When uploading spatial files in SHP or TIFF format, a prompt indicates unsupported format. The cause is failing to add the common file type whitelist for this category in the `formInput` configuration.
- The knowledge base search variables associated with the form do not take effect, and exclusive data from the territorial spatial basic information platform cannot be retrieved. The cause is failing to correctly select the associated knowledge base variable in the `userSelect` configuration, and not binding the category-exclusive data source.

## How to confirm the configuration is complete
- Upload a common SHP format remote sensing image file for this category, check whether it can be recognized normally and loaded into the form.
- Enable stream API calls, wait for the stream transfer to complete, check whether the complete parsed result of the planning document is obtained after splicing.
- Switch between different test accounts, check whether only knowledge base content within the preset department permission range can be accessed.
- Submit a form containing the required spatial scope field, check whether a verification prompt is triggered, and confirm that the required field verification takes effect.
