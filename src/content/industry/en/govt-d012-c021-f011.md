# Internal Office and Employee Services for Centralized Treasury Payment and Reimbursement Audit: Forms and Interactions

## What the data for this category looks like
Core data involved in this category comes from centralized treasury payment systems, unified budget management systems, electronic invoice platforms, and contract management systems. The update frequency is daily. Documents that circulate daily include payment applications, fund appropriation plans, invoices, contracts, acceptance receipts, reimbursement approval forms, and payment vouchers. Data fields include budget indicator codes, economic classification codes, payment amounts, approval node status, and more. Most units are Renminbi yuan and natural days. Some fields must match the unified coding rules of fiscal systems.

## Constraints imposed by these characteristics on the forms and interactions link
Multi-system data sources require forms to support cross-source field linkage verification, to prevent manually entered codes from differing from fiscal system codes. The daily update frequency requires form dropdown options and available budget indicator lists to sync the latest data daily, to prevent use of expired indicators. Multiple document types and complex fields require forms to be displayed in blocks by business node, splitting payment application, reimbursement audit and other links into separate interaction modules, to reduce page complexity. Compliance requirements for single fund payments require forms to have built-in real-time verification rules, to block input content that does not meet financial regulations.

## Configuration Guidelines
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | 800 millisecond delay for required field verification | Avoid frequent verification triggers that disrupt input experience, while blocking incorrect input in a timely manner |
| `userSelect` | Top 10 candidate results | The user group involved in this category has a relatively fixed size, and a small number of candidates covers common approval and handling scenarios |
| Form field grouping | Split by business link (budget indicator section, voucher section, approval node section) | Documents in this category circulate along business chains, and grouping makes it easier for auditors to check each link step by step |
| Context sync threshold | 1200–1500 characters | The core information length of a single payment application or reimbursement form mostly falls within this range, and full sync improves interaction continuity |
| Error prompt trigger rule | Pop up prompt immediately when field verification fails | This category has strict field compliance requirements, and timely prompts reduce subsequent audit rejections |

## Three Common Misconfigurations
- Symptom: An upload failure prompt pops up when uploading attachments such as payment applications or invoices, while text conversation functions work normally. Cause: The association rules between the form's attachment upload module and the fiscal system storage path are not configured correctly, leading to abnormal file circulation.
- Symptom: The user selection dropdown box in the form only displays old approval position lists, with no latest personnel information. Cause: The daily sync configuration for `userSelect` is not enabled, so candidate data is not updated as fiscal system personnel changes occur.
- Symptom: No linkage verification is triggered after entering a budget indicator code, and no prompt for code mismatch is displayed. Cause: No field linkage rules are set for `formInput`, and the coding verification interface of the unified budget management system is not connected.

## How to Confirm Configurations Are Correct
- Access the form editing page of FastGPT v4.17.0, select the budget unit payment application template, upload a properly formatted invoice attachment, and verify that the upload process completes normally.
- Input a budget indicator code that does not comply with fiscal coding rules in the form, and check whether a compliance prompt is triggered.
- Open the candidate list for `userSelect`, and confirm that it includes current on-duty user roles such as financial audit positions and budget unit handlers.
- Review the form's field grouping layout, and confirm that it has been split into separate interaction blocks by business link.
