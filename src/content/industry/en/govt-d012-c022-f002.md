# Internal Office and Employee Services for Land Use Rights, Mining Rights, and State-owned Property Rights Transactions: Vector Models and Indexing

## Data Overview for This Category
Typical entities include natural resource departments, state-owned assets supervision institutions, property rights trading institutions, and public resource trading centers. Daily generated documents include transfer announcements, trading guidelines, bid application documents, margin payment vouchers, transaction confirmation documents, listing result announcements, and property rights transfer specifications. Data sources include the national public resource trading platform, natural resource trading systems, property rights exchange systems, and state-owned asset supervision systems, with a daily update frequency. Documents contain specific fields such as ownership number, trading target type, margin amount, and transaction time. Document structures vary across different types.

## Constraints for Vector Models and Indexing
Daily updated data requires indexes to support incremental synchronization, eliminating resource consumption and time loss from full index reconstruction. Differences in multi-type document structures require vector models to adapt to text content of varying lengths, while requiring unified preprocessing rules to ensure consistent retrieval. Specific fields such as ownership identifiers and monetary amounts require indexes to prioritize matching business-relevant keywords during retrieval, improving retrieval accuracy. Attributes with severe business impact from errors require vector retrieval accuracy and recall rates to meet business compliance requirements, reducing transaction risks caused by incorrect matches.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |

| `maxToken` | `16384 token` | Covers the context requirements of the longest batch indexing tasks, adapting to the daily incremental update data volume |
| Chunk Length | 800–1200 characters | Matches the average length of documents such as transfer announcements and trading guidelines, balancing vector generation accuracy and indexing efficiency |

| Incremental Index Switch | Enabled | Adapts to the daily updated data frequency, reducing resource usage from full reconstruction |
| Similarity Threshold | Calibrated via actual testing | Adjusted based on the strictness of ownership matching in business, avoiding transaction risks caused by mismatches |

## Three Common Misconfigurations
- Old vector database data cannot load properly after upgrading to a new version, leading to empty retrieval results. This occurs when incremental index configuration migration is not completed for daily updated data formats, resulting in incompatibility between old data and the vector model in the new environment.
- Some documents fail to generate vectors after running a reindex task, making them unretrievable for documents like bid applications and margin payment vouchers. This happens when chunk length is not adjusted to fit short text documents, leaving some content unable to be properly chunked for vector generation.
- Index interface calls return a 400 status code with no response body. This is caused by request parameters not matching the value requirements of `defaultToken`, which blocks vector generation requests.

## How to Verify Proper Configuration
- Review daily incremental index task execution logs to confirm newly uploaded transfer announcements and listing result announcements have successfully generated vectors.
- Retrieve specific ownership numbers or trading target types, and verify returned results match expected business criteria.
- Check server resource monitoring dashboards to confirm indexing task memory and CPU usage stay within preset thresholds.
- Run a vector database migration test to confirm transaction document vectors from the old environment can be correctly imported into the new FastGPT v4.17.0 environment.
