# Internal Office and Employee Services for Land Use Rights, Mining Rights, and State-Owned Property Rights Transactions: Multi-Turn Dialogue and Prompt Engineering

## What this category's data looks like
Data for this category typically originates from national public resource trading platforms, natural resource trading systems, property right exchange systems, and state-owned assets supervision systems. The update frequency is daily. Daily documents include transfer announcements, trading guidelines, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications, among others. Most fields cover subject ownership information, trading restriction conditions, margin amount, bidding rules, transfer requirements, and similar content. There are no unified fixed units, and values vary based on subject type.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering link
Data sources for this category are scattered and updated daily. This requires that multi-turn dialogue contexts must be linked to the latest trading data to avoid calling outdated information. Daily document structures vary, so prompt engineering must adapt to field extraction logic for different document types. Core fields such as ownership and trading restriction conditions are the focus of dialogue. Multi-turn dialogue must focus on this information to avoid straying from the core of transactions. The high data update frequency requires limiting the context window length to prevent loading redundant old data from affecting judgment.

## How to Configure
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context Window | First 8–12 turns of dialogue + latest 2 trading documents | Data for this category is updated daily. An overly long context can easily include outdated information. Limiting the number of turns and documents ensures timeliness |
| `messages` | Preset roles categorized by trading document type | Different documents (such as transfer announcements, property right transfer specifications) require matching different field extraction logic. Categorized presets improve accuracy |
| Single Recall Count | First 3–5 entries | Core trading fields are concentrated in a small number of documents. Too many recalls will introduce irrelevant redundant information |
| `variables` | Bind core fields such as subject ownership and margin amount | Standardized data from existing trading systems can be directly called, without repeated inquiries to users |
| `chatId` | Bind session identifiers from the user's system | Used to distinguish different users' dialogue histories, supporting data isolation per user |
| File Upload Configuration | Limit single file size to 20 MB | Core documents for this category are mostly announcements and vouchers with moderate file sizes. Limiting size prevents loading timeouts |

## Three Common Misconfigurations
- Phenomenon: Clicking quick buttons at the start of a dialogue results in no response, or sent content does not match preset settings. Cause: Quick buttons are not bound to the preset roles in the `messages` parameter, or preset content does not match the document types for the trading scenario.
- Phenomenon: After uploading a file via the dialogue API, returned results do not link to the uploaded trading documents. Cause: File chunking and recall matching rules are not configured, or the recall range is not restricted to documents for the current trading subject.
- Phenomenon: In a login-free scenario, test accounts can view other users' historical dialogue records. Cause: Session history storage is not bound to `chatId` or the user system's unique identifier, resulting in missing identity verification.

## How to Verify Proper Configuration
This document is based on FastGPT v4.17.0. Configuration effects can be verified through the following actions:
- Initiate a multi-turn dialogue containing keywords related to trading subjects, check that the context only includes the most recent trading documents and dialogue turns.
- Click preset quick buttons, check that sent content matches preset trading scenario prompts.
- Use a test account to initiate a dialogue, exit and re-enter the session, check that previous dialogue history can be loaded.
- Upload a property right transfer specification, check that returned results extract core fields such as subject ownership and restriction conditions.
