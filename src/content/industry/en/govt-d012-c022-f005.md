# Internal Office and Employee Services for Land Use Rights, Mining Rights, and State-owned Property Rights Transactions: Tool Calling and Plugins

## What the data for this category looks like
Core data for this category comes from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems. The update frequency is daily. Daily documents include transfer announcements, trading instructions, bid application materials, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications. Fields cover ownership numbers, trading target types, margin amounts, bid qualification requirements, and more. Units include exclusive resource and asset measurement methods such as mu, ten thousand yuan, and transaction instance. The core fields of a single document are concentrated and have high relevance.

## Constraints for Tool Calling and Plugins
The need to access multiple data sources requires plugins to adapt to the API formats and permission rules of different systems. The daily data update frequency requires tool calling to use scheduled synchronization logic, to avoid using expired transaction data. Diverse document structures require tool calling to adapt to parsing rules for different documents, to accurately extract core fields such as ownership and bidding information. Exclusive fields and units require tool calling parameter verification to cover compliance rules related to resources and assets, to ensure data accuracy and consistency.

## Three Common Misconfigurations
- Symptom: Tool calling returns the `messages is empty` error. Cause: The historical conversation context is not properly populated in the request body, especially system prompt words related to ownership query and bidding are not included.
- Symptom: Tool call results lack core fields such as ownership number or margin amount. Cause: API parameter verification for the corresponding data source is not configured, and redundant non-transaction data is not filtered.
- Symptom: Tool calling frequently triggers timeout errors. Cause: The tool call timeout period is set too short, which does not match the actual time consumption of connecting multiple system data sources.

## How to Confirm Proper Configuration
- Submit a test request containing land ownership query, check the system logs, confirm that the `toolChoice` parameter is correctly triggered and the tool calling link operates normally.
- Review the tool call return results, confirm that core document fields for this category are included, such as trading instructions, ownership number, and margin amount.
- Simulate a daily data synchronization scenario, confirm that tool calling can pull the latest listing result announcement data on schedule.
- Submit multiple consecutive test requests, confirm that no `messages is empty` or timeout errors occur.
