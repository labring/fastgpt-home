# Internal Office and Employee Services for Land Use Rights, Mining Rights, and State-Owned Property Transactions: Model Access and Configuration

## What the Data for This Category Looks Like
The core data for this category typically originates from the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with updates occurring daily. Teams process documents including transfer announcements, trading notices, bid applications, margin vouchers, transaction confirmation letters, listing result announcements, and property right transfer specifications each day. Most documents are structured text with fixed fields such as trading subject ownership information, bidding rules, margin amounts, and transaction confirmation clauses. No unified unit specification exists, and some fields require confirmation based on regional trading rules.

## What Constraints Do These Characteristics Impose on the "Model Access and Configuration" Link
Access to multiple data sources requires the configuration to support connections to API endpoints of multiple heterogeneous systems, preventing data pulling exceptions. The wide variety of document types and inconsistent fields requires context configuration to adapt to text content of different lengths, stopping key ownership and bidding information from being truncated. Daily updated data requires consistent vector database synchronization to ensure the model uses the latest transaction information during calls. Transaction scenarios have extremely high accuracy requirements: any incorrect ownership judgment or process description may lead to invalid transactions or state-owned asset disputes, so model parameters must prioritize rigor.

## How to Set the Configuration

| `AIPROXY_API_TOKEN` | Fill in the docking key assigned by the system | Used for identity verification to ensure normal pulling of transaction data |

## Three Common Misconfigurations
- When batch uploading documents such as bid applications and margin vouchers, only the first dozen entries process normally, with no results returned for subsequent entries. This happens because `maxContext` is not adjusted to adapt to the context limit for multi-document batch input, causing later documents to exceed the threshold and be truncated.
- After configuring `toolChoice` as `auto`, the function calling effect of Qwen2-72B-Instruct-Int8 is poor, and generated calling parameters have deviations. This happens because `temperature` is not set below 0.3, leading to excessive randomness in the model's generated content.
- When attempting to access Casdoor identity verification, `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not filled correctly, causing identity verification to fail. This happens because the docking key and endpoint are not configured according to system requirements, and the identity verification process cannot be completed.

## How to Confirm the Configuration is Complete
- Import a single transfer announcement document, and verify that the ownership description, bidding rules, and other content output by the model match the original text.
- Call tools for testing, confirm that the model can automatically extract core fields such as margin amount, trading subject type, and transaction confirmation clauses.
- Check the connectivity of `AIPROXY_API_ENDPOINT` to confirm that the latest transaction system data can be pulled normally.
- Adjust `temperature` to a reasonable range, generate outputs for the same scenario multiple times, and confirm that result consistency meets business requirements.
