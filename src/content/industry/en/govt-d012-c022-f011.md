# Internal Office and Employee Services for Land Use Rights, Mining Rights and State-owned Property Rights Transactions: Forms and Interactions

## What Data for This Category Looks Like
Typical entities for the land use rights, mining rights and state-owned property rights transactions category include natural resource departments, state-owned asset supervision institutions, public resource trading centers, and similar organizations. Daily office documents include transfer announcements, trading instructions, bid application documents, margin vouchers, transaction confirmation documents, listing result announcements, and property rights transfer specifications. Data sources are the national public resource trading platform, natural resource trading systems, property right exchange systems, and state-owned asset supervision systems, with a daily update frequency. Common fields include subject ownership information, transaction restriction conditions, margin amount, transaction number, bidder qualification requirements, and similar items. Units involved include square meters, ten thousand yuan, and lots.

## What Constraints These Characteristics Impose on Forms and Interactions
Multi-source data synchronization requirements mean forms must support cross-system data pulling to avoid ownership information errors caused by manual entry. Frequently updated transaction data requires that form data sources can be synchronized in real time to ensure submitted information matches the latest transaction status. A wide range of document types and fields requires forms to support custom grouping and field configuration to adapt to filling requirements for different transaction stages. Severe consequences of errors require forms to have built-in format verification and permission controls to prevent invalid transactions or state-owned asset disputes caused by incorrect submissions.

| `userSelect` | Restrict selectable roles to transaction specialists and ownership auditors | Internal office scenarios only allow specific post personnel to submit or edit transaction-related forms |
| Single submission data volume | Batch submission of up to 10 entries | Daily transaction processes usually handle no more than 10 subjects per time, avoiding excessive system load |
| Timeout threshold | 600 seconds | Cross-system pulling of ownership data requires a certain response time, with a reasonable waiting duration set based on actual measurements |
| Form block configuration | Split into bid application, ownership audit, and transaction confirmation blocks | Aligns with daily transaction processes and improves employee form filling efficiency |

## Three Common Errors
- When uploading files, only general formats are supported, and exclusive document formats such as bid applications and transaction confirmation documents cannot be automatically matched. The cause is that the allowed upload file list is not preset based on the common document types of this category.
- After adding a custom model API, a call error occurs with an empty value prompt. The cause is that the model's request parameters are not configured correctly, and only the token is passed without supplementing the necessary interface address and authentication header.
- Knowledge base references cannot be selected in the code running node, and the first search result fails to output. The cause is that the knowledge base data source corresponding to the public resource trading platform is not bound in the node configuration, resulting in inability to obtain relevant transaction data.

## How to Confirm Configuration Is Complete
- Submit a test form containing margin amount and transaction number, verify whether a format error prompt is triggered, and confirm that the `formInput` verification rules take effect.
- Upload a 500 MB transaction confirmation document, confirm that the upload is successful and there are no format restriction errors, and verify the file upload configuration.
- Log in with the transaction specialist role, confirm that only this role can edit ownership audit-related forms, and verify the `userSelect` role restriction.
- Trigger cross-system data pulling, confirm that subject ownership information is returned within 600 seconds, and verify the timeout threshold configuration.
