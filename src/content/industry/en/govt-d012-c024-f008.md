# Internal Office and Employee Services for Student Aid and Subsidy Review: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category comes from the national student aid management information system, school student registration systems, civil affairs low-income and extremely impoverished household data, and fiscal payment systems. Data updates occur once per semester.
Daily processed documents include family economic hardship certification forms, aid application forms, scholarship and grant review forms, distribution lists, and public notification materials. Most documents are structured forms or list-style files.
Fields cover student identity information, family economic status, aid eligibility, distribution amounts, bank card information, and more. Some schools use custom document formats.

## Constraints Imposed by Data Characteristics on Document Parsing and Chunking
Structured forms and list-style documents must not split across student entries or core fields. Splitting in this way prevents subsequent verification from associating complete information for the corresponding student.
Data from multiple sources has format differences. Document formats custom created by some schools require parsing tools to adapt. Without adaptation, field misalignment or content loss may occur.
Files imported in batches each semester usually include multiple pages of distribution lists or review materials. Single files may have large size. Sufficient parsing resources and time must be reserved. Chunk granularity must be controlled to ensure accurate subsequent retrieval.
Field accuracy directly affects aid distribution and audit results. Chunking must retain the integrity of key information. Associated fields such as family economic status and student registration status must not be split apart.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of a single aid application form or single student aid information, avoids splitting core associated fields |
| `chunkSplitter` | Split by form fields | Adapts to the field structure of structured documents, avoids chunking chaos across students or fields |
| `customPdfParse` | Enabled | Adapts to certification forms and public notification materials in custom formats used by schools, retains correspondence between tables and fields |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to semester batch-imported review summary packages and distribution list files, avoids large files being blocked |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Reserves sufficient parsing and conversion time for processing large files with multiple pages of content |
| `chunkSettingMode` | Manual mode | Adjusts chunking rules for structured documents in this category, adapts to the field relevance of aid data |

## Three Common Misconfigurations
- After uploading a custom-format aid certification form, parsing results show field misalignment or content loss. The cause is that `customPdfParse` is not enabled. The tool cannot recognize the custom document layout rules used by the school.
- A request error triggers when uploading a batch distribution list file. The cause is that the value set for `UPLOAD_FILE_MAX_SIZE` is smaller than the actual size of the imported file. The file is blocked as a result.
- When querying parsed knowledge base content, mixed information across multiple students appears. The cause is that `chunkSplitter` is set to split by page number, without splitting by student entry or form field.

## How to Confirm Proper Configuration
- In the FastGPT v4.17.0 environment, upload a single family economic hardship certification form. Check if the parsing result splits into independent modules according to fields such as family situation and student registration information.
- Upload a distribution list file with more than 10 pages. Confirm that the parsing process has no timeout errors, and that parsing time matches the value set for `PARSE_FILE_TIMEOUT_SECONDS`.
- Check the system upload limit prompt. Confirm that the size of the batch imported file matches the value set for `UPLOAD_FILE_MAX_SIZE`, and there are no prompts about blocked files.
- Import public notification materials in custom format. Confirm that the parsed content retains the row and column structure of the original table and the correspondence between fields, with no content loss.
