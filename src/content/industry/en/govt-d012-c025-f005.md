# Internal Office and Employee Services for Safety Production Hazard Inspection and Governance: Tool Calling and Plugins

## What this category's data looks like
This category’s data primarily originates from safety production supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. Data updates daily.
Daily documents include hazard inspection lists, hazard governance ledgers, rectification notices, review records, and major hazard supervision order forms. Data fields include hazard unique ID, inspection subject, rectification responsible person, rectification deadline, review result, supervision level, and similar items. Units are mostly dates, employee IDs, level identifiers, and other similar values. No unified standardized numerical units exist.

## What constraints do these characteristics impose on the "tool calling and plugins" workflow
Data sources for this category are scattered. Plugins connect multiple systems such as safety production supervision systems and enterprise self-inspection systems to pull data. Tool calling must support multi-source interface adaptation configuration.
Data updates daily. Tool calling must set reasonable timeout thresholds. This avoids delays that disrupt daily inspection processes.
Daily document fields include specific formatted content such as hazard unique ID and rectification deadline. Tool calling must configure field mapping rules. This ensures data format matching.
Error consequences relate to safety production responsibilities. Tool calling must add a result verification link. This prevents incorrect data from triggering subsequent rectification processes.

## How to configure settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Suggested Value | Basis for This Value |
| --- | --- | --- |
| Tool calling timeout duration | 600 seconds | This category has a large volume of inspection data pulled in a single call. An overly short timeout results in incomplete data pulling. An overly long timeout delays daily inspection processes |
| `toolChoice` | auto | Automatic selection between built-in tools and external plugins occurs based on scenarios such as hazard inspection and rectification tracking. This adapts to multi-source data pulling requirements |
| Plugin retry times | 2-3 times | Some external supervision system interfaces experience temporary fluctuations. Retries reduce the probability of single call failure |
| `functionCall` | Enable parameter format verification | Field formats of hazard ledgers and rectification notices must be strictly matched. This prevents entry of incorrect data |
| Plugin context carrying limit | Top 10 latest inspection records | This category of data updates daily. Only carrying latest data avoids context overload. This also covers reference information from the latest inspection cycle |

## Three common misconfigurations
- When an external supervision system plugin is called, specified fields return empty. No field mapping rules are configured, so exclusive field formats of hazard inspection lists and rectification notices cannot be matched.
- Tool calling returns a request timeout prompt. The set timeout duration is too short, and does not adapt to the volume of multi-system data pulled in a single call for this category.
- A patent query plugin called via the tool calling component returns no corresponding records. The plugin test interface returns normal results. The enterprise unified social credit code parameter was not correctly passed in the tool calling configuration, resulting in mismatched query conditions.

## How to confirm the configuration is correct
- A tool call is triggered manually. Returned hazard data fields are verified to match those in the local inspection list.
- Plugin call logs are reviewed. Retry times are confirmed to not exceed the configured threshold, and no continuous timeouts occur.
- A rectification notice entry scenario is simulated. The `functionCall` verification is triggered, and format errors are confirmed to be intercepted.
- Multi-source plugin simultaneous calls are tested. The `toolChoice` automatic switching logic is confirmed to meet current scenario requirements.
