# Internal Office and Employee Services for Work Safety Hazard Inspection and Governance: Document Parsing and Chunking

## What data is included in this category
Data for this category comes from work safety supervision systems, enterprise hazard self-inspection systems, law enforcement inspection records, and accident statistics systems. Data is updated daily. Daily processed documents include hazard inspection checklists, hazard management ledgers, rectification notices, re-inspection records, and major hazard supervision order forms. Most documents contain fixed fields: specific hazard description, rectification responsible party, rectification time limit, re-inspection conclusion, supervision level, and others. Some documents use structured table formats, while others use standard official document formats.

## What constraints do these characteristics impose on document parsing and chunking?
The structured and standardized nature of daily documents requires that parsing and chunking preserve field associations and document logic, and avoid splitting that breaks the integrity of key information such as rectification time limits, re-inspection conclusions.

Daily updated batch documents require stable parsing speed to prevent task failure due to timeout.

Large format differences across documents require adaptation to different layout logics such as heading levels and table structures.

Encrypted PDF documents with digital signatures may not extract complete content via the default parsing logic, requiring additional configuration for adaptation.

This page’s configuration applies to FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Matches the length of single records in hazard ledgers, preserves the integrity of key fields such as rectification time limits, re-inspection conclusions, and avoids key information being split into different chunks |
| `chunkSplitter` | Split by paragraph + heading | Adapts to the heading hierarchy structure of rectification notices and supervision order forms, avoids splitting that breaks the logical coherence of documents |
| `customPdfParse` | Enabled | Adapts to encrypted PDF documents with digital signatures, bypasses signature verification to extract complete text content, and resolves issues where encrypted documents cannot be recognized |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Handles daily updated batch documents, avoids timeout errors caused by excessive parsing time, and ensures the completion rate of batch tasks |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to batch scanned copies or long documents from law enforcement inspection records, meets single upload capacity requirements, and avoids interception due to oversized files |

## Three common mistakes
- Phenomenon: Calling the Doc2x tool returns a file read error, with an error prompt similar to "Only support .txt, .m". Cause: The uploaded file format is not supported, or the file is corrupted or encrypted, causing parsing pre-check failure.
- Phenomenon: After uploading a PDF with a digital signature, the parsing result is empty or fails to recognize valid content. Cause: The `customPdfParse` configuration is not enabled, the default parsing logic cannot bypass the encryption restrictions of digital signatures, resulting in text extraction failure.
- Phenomenon: The API returns a knowledge base reading link, but clicking it results in a page error, or the large model output does not include the image content of the uploaded file. Cause: Correct file parsing parameters are not configured, resulting in unextracted image metadata, or the link access permission is not generated correctly.

## How to confirm the configuration is correct
- Upload a single hazard rectification notice PDF, check if the parsing result retains complete paragraphs of headings, rectification requirements, and re-inspection opinions, with no garbled characters or field splitting errors.
- Upload an encrypted PDF document with a digital signature, verify that the parsing result contains complete text content, with no null values or missing key fields.
- Upload batch documents, check if the parsing task completion time is within the preset `PARSE_FILE_TIMEOUT_SECONDS` range, with no timeout failure records.
- Test the reading link returned by the API, verify that the page can be accessed normally, and the large model can extract the text content in the document.

The values provided are common starting points and should be measured against the reader's own samples.
