# Internal Office and Employee Services for Work Safety Hazard Inspection and Governance: Forms and Interactions

## What this category’s data looks like
Data for this category comes from work safety supervision systems, enterprise self-inspection hazard systems, law enforcement inspection records, and accident statistics systems. The update frequency is daily. Daily documents include hazard inspection checklists, hazard management ledgers, rectification notices, review records, and major hazard suspension and supervision orders. Core fields include hazard ID, inspection subject, hazard level, rectification responsible person, rectification deadline, and review status. All fields correspond to standard business items in the supervision and rectification process, with no additional custom statistical values.

## What constraints these characteristics impose on the forms and interactions link
The requirement for daily data updates means forms must support real-time incremental saving to prevent data loss from high-frequency entry. Multi-source business data requires forms to associate with personnel and ledger data from existing safety management systems, reducing duplicate entry. For multiple document types such as hazard inspection checklists and rectification notices, forms must support switching field groups to adapt to different business scenarios. Because the consequences of errors are severe, forms must enforce mandatory verification of core field completeness. For example, rectification responsible person, rectification deadline, and review result cannot be empty. Forms must also support batch import of standardized documents to match the daily updated inspection data rhythm.

## How to set configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` component | Configured as multi-field group mode, with each group corresponding to one type of business document | Adapt to the entry requirements of multiple standardized documents such as hazard inspection checklists and rectification notices |
| `userSelect` component | Bound to preset safety management department and responsible person datasets, limiting selection scope | Quickly call existing personnel information and avoid manual input errors |
| Real-time save trigger | Auto-save after completing one field group entry, set timeout to 30 seconds | Match the high-frequency daily business data update rhythm and prevent data loss |
| Batch import limit | Maximum 200 entries per single import | Adapt to the batch entry scale of daily inspection data and avoid system overload |
| Core field verification | Enable required field verification, covering rectification responsible person, rectification deadline, and hazard level | Prevent rectification process interruptions caused by missing fields |

## Three common mistakes
- Symptom: The form cannot accept the specific hazard location or model entered by the user, and the corresponding field is empty after submission. Cause: The user input permission of the `formInput` component is not enabled, or the binding rules between the corresponding field and business data are not configured.
- Symptom: The rectification deadline entered by the user cannot be combined with the inspection time to generate review reminder rules. Cause: Multi-field association logic is not configured, and the key parameters entered by the user are not bound to prior process data.
- Symptom: When importing a third-party model, the ChatGLM2 that has been started via container and connected to OneAPI cannot be selected in the model list. Cause: The third-party model access path is not correctly added in the system configuration, or the matching model adaptation rules for the corresponding version are not configured.

## How to confirm the configuration is complete
- Open the corresponding form page, try entering the specific hazard location, and confirm that the entered content can be saved to the corresponding field normally.
- Select a preset safety management responsible person, and confirm that the preset personnel data can be loaded normally in the drop-down list.
- Upload an Excel file of a standard-format hazard inspection checklist, and confirm that the system can parse and import data normally.
- Leave the rectification responsible person field blank and submit the form, and confirm that the system will pop up a corresponding verification prompt.

The values provided here are common starting points and should be measured against the reader's own samples.
