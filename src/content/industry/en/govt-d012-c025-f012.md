# Internal Office and Employee Services for Work Safety Hidden Danger Investigation and Governance: Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category is primarily sourced from work safety supervision systems, enterprise hidden danger self-inspection systems, law enforcement inspection records, and accident statistics systems, with a daily update frequency. Commonly processed documents include hidden danger investigation checklists, hidden danger governance ledgers, rectification notices, review records, and major hidden danger listing and supervision orders. Data fields include hidden danger identifiers, investigation subjects, rectification responsible persons, rectification time limits, review conclusions, and more. A standard format common to government affairs and work safety fields is used, with no custom special units.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The daily update frequency of data for this category requires deploying scheduled synchronization scripts to ensure real-time synchronization of hidden danger data to the platform, preventing disconnection between investigation and rectification workflows. Differentiated formats across multiple types of structured documents require configuring targeted document parsing rules to ensure accurate extraction of key fields such as hidden danger numbers and rectification time limits. Compliance requirements in government affairs scenarios require enabling data encryption storage configurations to prevent unauthorized access to sensitive documents such as hidden danger governance ledgers. Format differences across multiple data sources require configuring unified field mapping rules to integrate heterogeneous data from supervision and self-inspection systems, avoiding investigation errors caused by data chaos.

## How to Set the Configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Configure to the address of a local enterprise-grade MongoDB instance, set the maximum connection pool size to 50 | This category processes hundreds of hidden danger-related documents daily; a 50-connection pool meets concurrent read/write requirements and avoids connection timeouts |
| `REDIS_URL` | Configure to the address of a local Redis instance, set the cache expiration time to 3600 seconds | Hidden danger investigation data requires frequent queries; a 1-hour cache reduces database pressure and ensures retrieval response speed |
| `STORAGE_S3_ENDPOINT` | Configure to the access endpoint of the enterprise internal object storage service | Documents such as rectification notices and review records processed for this category must be stored in compliant internal storage to meet government affairs data storage requirements |
| `FE_DOMAIN` | Set to the domain address of the internal office system | Ensures the employee service module is only accessible within the internal office network, complying with government intranet security specifications |
| `DB_MAX_LINK` | Set to 60 | Matches the MongoDB connection pool configuration to avoid exhausting database connection resources |

## Three Common Configuration Errors
- Phenomenon: The custom PDF parsing service cannot be invoked after configuration, and logs show a connection timeout. Cause: The parsing service address was not configured to the corresponding environment variable, or internal network policies restrict communication between services.
- Phenomenon: No new user registration entry is visible after deployment, and the interface displays a blank registration page. Cause: The public registration switch for the open-source version was not enabled, or the registration function was disabled by default during internal deployment.
- Phenomenon: No edit button appears in knowledge base search results, and index configuration cannot be adjusted directly. Cause: The content management page of the target knowledge base was not accessed, and the search test page was mistakenly used as the index adjustment entry.

## How to Verify Successful Configuration
- Access the configured `FE_DOMAIN` address, and confirm that the internal office interface loads normally with no network errors.
- Upload a hidden danger rectification notice document, and confirm that key fields such as rectification responsible person and rectification time limit are correctly extracted after parsing.
- Run a scheduled synchronization task for hidden danger data, and confirm that that day's investigation records have been added to the database with no data loss.
- Check the cache instance associated with `REDIS_URL`, and confirm that frequently queried hidden danger data has been cached, with query response times meeting expectations.

The values provided are common starting points and should be evaluated against the user's own samples.
