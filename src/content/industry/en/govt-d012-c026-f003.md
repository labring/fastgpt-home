# Internal Office and Employee Services for Engineering Construction Project Approval: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data is sourced from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform. Updates occur daily. Daily documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion acceptance record forms. Each document corresponds to a single approval link. Each has exclusive fields and no universal format. Fields focus on project numbers, participating unit qualifications, approval nodes, and material compliance. The data structure is tightly bound to housing and urban-rural development construction approval workflows.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering Links
Multi-source data updated daily requires multi-turn dialogue to associate context from different systems' `messages`. This ensures real-time access to the latest qualification and approval node data during conversations. Fixed-format approval documents require prompts to accurately match the fields of the corresponding link, avoiding generalized queries. The most time-consuming links include consolidating materials, verifying qualifications, and tracking nodes. Multi-turn dialogue must guide users to provide information by link. It must also verify the compliance of input fields to prevent compliance issues in subsequent approvals.

## Configuration Settings
The following configurations are formulated based on the FastGPT v4.17.0 version specification.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique number of the current approval project | Ensure multi-turn dialogue context for the same project is not confused, and match the unique identification rules for housing and urban-rural development projects |
| `messages` | Retain the last 10 rounds of dialogue content | Cover the full process context of material submission, qualification verification, and node tracking during the approval process, avoiding context overflow |
| Maximum context character count | 8000–12000 characters | Limit the length of response content per round of dialogue to avoid page loading lag |
| `variables` | Preset three types of variables: project number, participating unit qualification type, and approval link | Quickly access qualification database and approval management system data for corresponding systems, reducing repeated queries |
| Question optimization | Calibrated based on actual testing, covering three scenarios: material verification, qualification verification, and node tracking | Optimize question understanding for exclusive links of engineering approval to improve dialogue accuracy |
| Number of single-match documents | Top 3 | Approval materials are mostly in fixed formats, and a small number of accurate matches meets employee query needs |
| Response timeout threshold | 60 seconds | Ensure employees do not wait excessively and obtain approval-related information in a timely manner |

## Three Common Configuration Errors
- The symptom is no response after clicking the dialogue opening quick button. The cause is failure to bind the preset approval scenario dialogue prompts to the corresponding `chatId` context.
- The symptom is failure to load approval material images in dialogue history without a login status. The cause is failure to configure the persistent storage path for the `messages` context, resulting in inability to properly read session data.
- The symptom is deviation in the qualification verification results of participating units during multi-turn dialogue. The cause is failure to preset the participating unit qualification field via `variables`, resulting in the prompt being unable to accurately match enterprise qualification database data.

## How to Verify Successful Configuration
- Initiate a new approval dialogue, enter the project number, and check if the preset `variables` content is automatically loaded.
- Test submitting approval materials across multiple rounds, and confirm that returned matching documents are exclusive to the current link.
- Switch the `chatId` for different projects, and verify that dialogue context does not mix across projects.
- Click the dialogue opening quick button, and check if the preset approval process guidance prompts appear.
