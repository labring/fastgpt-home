# Internal Office and Employee Services for Engineering Construction Project Approval: Tool Calling and Plugins
This document is based on FastGPT v4.17.0.

## What the Data for This Category Looks Like
Typical data sources for this category are engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases, and credit platforms. Data updates occur once daily. Daily processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, completion record filing forms, and similar items. Data fields include project ID, participating unit qualification information, approval node status, application material lists, and more. All fields follow unified government system specifications, with no custom special units.

## Constraints on Tool Calling and Plugins
Multiple independent government systems serve as data sources, so tool calling must support multi-interface integration and adapt to each system’s authentication rules. Daily data updates require tool calling to pull latest data on a scheduled basis, preventing use of expired information. Fixed-format approval documents and standardized fields mean tool calling parameters must strictly match government system field requirements, cutting down format verification costs. Fixed sequential approval workflow logic requires tools to run in node order, ensuring no approval steps are missed.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-tool parallel calling scenarios, automatically match the tool types required for the approval workflow |
| Tool Execution Order | Serial according to approval node sequence | Match the fixed workflow logic of engineering construction project approval |
| Tool Timeout Setting | 300–600 seconds | Adapt to the time required for pulling materials and querying qualifications across government systems |
| `functionCall` | Enable field verification | Ensure the format of incoming project ID and participating unit qualification information complies with regulations |
| Single Query Result Count | Top 5 entries | Match the default return limit of government system interfaces |
| Parallel Calling Limit | No more than 2 | Avoid triggering current limiting policies when calling multiple government interfaces simultaneously |

## Three Common Configuration Mistakes
- Symptom: Some tools fail to execute or their execution order is disorganized. Cause: The tool execution order is not configured according to approval nodes, or the serial execution mode is not enabled.
- Symptom: The MCP service of a specific government system cannot be parsed, while other third-party MCP services can be called normally. Cause: Exclusive request headers or proxy parameters are not configured for the government system interface, resulting in authentication failure.
- Symptom: Non-streaming calls fail, and the Agent node behaves abnormally. Cause: The compatibility between the model calling mode and FastGPT streaming requests is not confirmed, resulting in the model output format not meeting tool calling requirements.

## How to Verify Proper Configuration
- A simulated approval workflow should be triggered, and tool calling logs checked to confirm that all configured tools execute in the expected order.
- The qualification query tool should be called to verify that the returned result format matches the public data of the government system.
- A timeout request should be simulated to check whether the timeout handling logic of tool calling takes effect as configured.
- The parameter verification switch for tool calling should be checked to confirm that the format of incoming project fields complies with requirements.

The values provided here are common starting points and should be measured against the reader's own samples.
