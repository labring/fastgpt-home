# Internal Office and Employee Services for Engineering Construction Project Approval: Model Integration and Configuration

## What this category of data consists of
This category of data is sourced from the engineering construction project approval management system, construction drawing review system, enterprise qualification database, and credit platform, with a daily update frequency. Commonly processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. Document fields cover project numbers, participating construction unit qualifications, personnel qualifications, approval node status, and more. The data uses the national unified government approval standard format, with no custom special units.

## What constraints apply during the model integration and configuration phase
Data sources are scattered and updated daily. Ensure that the latest approval management system and qualification database data is synchronized during model integration, to prevent expired government information from disrupting approval workflows. Document structures are standardized but use fixed fields. During configuration, adapt to the fixed field extraction rules for government approval documents, and do not arbitrarily adjust field mapping rules. Fields such as participating construction unit qualifications and personnel qualifications must be matched precisely. Model calls must strictly align with government data formats to avoid parsing errors caused by field mismatches. Parallel node tracking in approval processes relies on real-time data. The response delay of model integration must meet the real-time requirements of government office work.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Government approval-related documents are generally long, and need to accommodate the context of multiple approval materials to avoid truncation of critical approval information |
| `maxTokens` | `4000–6000 token` | Single approval materials have moderate content length. Control the token consumption of a single call to adapt to the concurrent call scenarios of government office work |
| `quoteMaxToken` | `1000–1500 token` | The extracted approval material fragments need to maintain complete semantics, while not occupying too much context space, to avoid affecting subsequent model inference |
| `toolChoice` | `auto` | Need to automatically select whether to call tools to obtain real-time qualification and credit data based on specific approval tasks, adapting to dynamically changing approval processes |
| `temperature` | `0.2–0.4` | Government approval scenarios require the output content to remain rigorous, avoiding generating approval suggestions that do not comply with government regulations |
| `AIPROXY_API_ENDPOINT` | Fill in the proxy address deployed on the government intranet | Government data must be transmitted securely on the intranet to prevent data leakage |

## Three common mistakes
- The symptom is an "incorrect API Key" error returned during a call. The cause is confusing the globally universal API Key with the application-specific API Key. The globally universal Key cannot directly call application conversations.
- The symptom is abnormal model running time display. Online models only display the first token time, while offline models display total time. The cause is not unifying the time statistics rules for government office scenarios, and not adjusting the display logic during integration.
- The symptom is that the expected unique identifier cannot be obtained when calling the workflow. The cause is not configuring the public call permission of the workflow in FastGPT v4.17.0, or not correctly binding the application's unique ID parameter.

## How to confirm the configuration is complete
- Submit a standard construction permit application document to the test interface, and confirm that the returned content accurately extracts government fields such as participating construction unit qualifications and approval node status.
- Review the FastGPT model call logs to confirm that the `maxContext` parameter does not trigger a context truncation alert, and that the context length meets the configured requirements.
- Validate the API Key call permissions, ensure that the application-specific Key can normally trigger the workflow, and that the global Key cannot directly call the application.
- Check the data synchronization task running records to confirm that the daily updated enterprise qualification database and credit platform data can be properly pulled by the model, with no expired data returned.
