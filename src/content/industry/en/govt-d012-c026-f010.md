# Internal Office and Employee Services for Engineering Construction Project Approval: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for this category comes from engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases, and credit platforms. The update frequency is daily. Commonly processed documents include construction permit application materials, construction drawing review qualification certificates, quality and safety supervision procedures, completion record forms, and similar items. Most documents are structured forms and compliance texts, with fields including project number, participating unit qualifications, approval node status, and no additional custom statistical fields.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Multi-system sourced data requires the retrieval pipeline to support unified vector mapping for cross-source data, preventing retrieval bias caused by field mismatches. The daily update frequency requires the incremental synchronization mechanism to adapt to high-frequency data refreshes, stopping recalled content from lagging behind the latest approval status. The structured form and compliance text document structure requires the retrieval model to prioritize matching professional approval terminology and fixed fields, adapting to the retrieval needs of structured documents. Core approval process links including material integration, qualification verification, and node tracking require recalled results to be strictly associated with project approval nodes, reducing irrelevant content interference.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | `0.75–0.85` | Approval text must match professional approval terminology and compliance requirements. A value that is too low will introduce irrelevant approval materials, while a value that is too high will miss compliance-related content |
| `limit` | `Top 10` | The approval process requires integrating multiple core materials. A single retrieval must cover key related documents; too few results cannot support the material integration link |
| `searchMode` | `Paragraph First` | Commonly processed documents such as construction permit applications and completion record forms are mostly long texts. Splitting by paragraph first preserves the contextual logic of the approval process |
| `usingReRank` | Enabled | Recalled results must be reordered by approval relevance to improve retrieval accuracy for links such as participating unit qualification verification and parallel approval node tracking |
| `datasetSearchUsingExtensionQuery` | Enabled | Approval-related queries must supplement exclusive fields such as project number and participating unit qualifications to optimize the coverage of retrieval and recall |
| `collectionIds` | Configured by approval business group | Knowledge base collections must be divided by project type and approval node to avoid interference from irrelevant data across categories |

## Three Common Misconfigurations
- Phenomenon: When calling the interface to create a text collection, the `searchMode` parameter is not passed correctly, resulting in an unexpected splitting mode. Cause: The official parameter description for FastGPT v4.17.0 was not referenced, and non-specified parameter names or values were used incorrectly.
- Phenomenon: After synchronizing files to the corporate knowledge base, the corresponding file content is not included in retrieval results. Cause: No cross-system data incremental synchronization task was configured, so the local knowledge base did not synchronize the latest file data from the source system.
- Phenomenon: After uploading files to the knowledge base via an external interface, newly uploaded files do not appear in retrieval results. Cause: The knowledge base vector reconstruction task was not triggered, so newly uploaded files were not processed for vectorization.

## How to Confirm Proper Configuration
- Manually enter approval-related query terms, and check whether the document types of recalled results match business links such as construction permits and qualification verification.
- View the knowledge base synchronization logs to confirm that the daily data update task is running normally with no error records.
- Call the retrieval interface to verify that the `similarity` score of returned results matches the configured range and the number of recalled results meets the preset requirements.
- Upload a test completion record form document, and confirm that the document appears in the retrieval results after searching.
