# Internal Office and Employee Services for Engineering Construction Project Approval: Deployment and Upgrade

This document applies to FastGPT v4.17.0 deployment configurations, focused on internal office and employee service workflows for engineering construction project approval scenarios.

## What the data for this category looks like
The core data for this category comes from engineering construction project approval management systems, construction drawing review systems, enterprise qualification databases, and credit platforms, with a daily update frequency. Commonly processed documents include construction permit applications, construction drawing review qualification certificates, quality and safety supervision procedures, and completion record forms. Data fields focus on approval process nodes, participating construction unit qualifications, personnel information, and material compliance. There is no unified external standard format, so deployment must adapt to the field definitions of each source system.

## What constraints these characteristics impose on the deployment and upgrade phase
Dispersed data sources requiring daily synchronization require cross-system data pull adaptation parameters to be configured during deployment, to prevent synchronization task blocking. Unstandardized document formats mean knowledge base configurations must match the field structures of each approval material, to ensure retrieval accuracy. Data linking participating construction unit qualifications and approval nodes requires permission verification parameters to be configured during deployment, to prevent unauthorized access to sensitive information. Upgrades must maintain compatibility with original approval process field mapping rules, to avoid interrupting internal office services.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:securepass@192.168.1.100:27017/fastgpt?authSource=admin` | Adapts to the database instance associated with the engineering approval system, ensuring stable storage and read/write operations for approval materials and qualification data |
| `DB_MAX_LINK` | `20–30` | Matches the daily read/write request volume of synchronized approval data and qualification information retrieval, preventing database connection exhaustion |
| `REDIS_URL` | `redis://:redispass@192.168.1.101:6379/0` | Caches approval node status and user session information, ensuring real-time response of internal office systems |
| `FE_DOMAIN` | `http://internal.zhujianju.gov.cn` | Adapts to the access path of the internal office system, preventing cross-origin blocking from affecting employee access |
| `FILE_TOKEN_KEY` | Generate a 32-bit random string per internal security policies | Secures download permissions for approval material files, preventing unauthorized access to sensitive engineering data |

## Three common mistakes
- Symptom: After starting the service, the console outputs a database connection failure log, prompting `connect ECONNREFUSED` or `Authentication failed`. Cause: The host address, authentication information, or authentication source in `MONGODB_URI` was not filled correctly, and the actual configuration of the database associated with the engineering approval system was not matched.
- Symptom: The frontend page loads blank or is unresponsive, and the browser console shows cross-origin request blocking. Cause: `FE_DOMAIN` was not correctly configured to the actual access domain name of the internal office system, causing frontend resources to fail to load properly.
- Symptom: A parameter error prompt pops up during workflow debugging, and approval material process configuration cannot be completed. Cause: The knowledge base chunking was not configured according to the field structure of the engineering approval documents, causing retrieval results to fail to match the material fields required for approval.

## How to confirm the configuration is complete
- Run a database connection test command to verify that the database instance configured with `MONGODB_URI` supports normal read and write operations.
- Access the frontend address configured in `FE_DOMAIN` to confirm that the page loads normally and there are no cross-origin errors.
- Trigger a data synchronization task to check whether the latest approval material data can be pulled.
- Debug a workflow that includes qualification verification to confirm that matching participating construction unit qualification data can be retrieved normally.
