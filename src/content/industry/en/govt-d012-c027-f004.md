# Internal Office and Employee Services for Construction Project Bidding: Workflow Orchestration

## What This Category of Data Looks Like
Data sources for this category include national public resource trading platforms, local trading platforms, project approval systems, and bidding supervision systems. The update frequency is daily. Documents processed daily include bidding announcements, pre-qualification documents, bidding documents, submission documents, evaluation reports, successful candidate announcements, and successful result announcements. These documents include exclusive fields such as section division, qualification requirements, performance thresholds, bill of quantities, and construction period, covering the entire bidding process for construction projects.

## Constraints Imposed on Workflow Orchestration
Data sources for this category are scattered and updated daily. Workflows must be configured with multiple data source synchronization nodes to match the trigger rhythm of business nodes. Document types are diverse with significant structural differences, so workflows must support custom parsing rules to adapt to different document formats. Exclusive fields such as section division, qualification thresholds, and bill of quantities must be accurately mapped via the `variables` parameter to avoid missing fields during workflow execution. Additionally, errors in the bidding process directly impact project progress, so workflows must add pre-check links to block abnormal data. This document is written for FastGPT v4.17.0.

## How to Configure
| Configuration Item               | Recommended Approach                                                                 | Rationale                                                                 |
|----------------------------------|--------------------------------------------------------------------------------------|---------------------------------------------------------------------------|
| `variables`                      | Map to `bidding number`, `section division rules`, `evaluation expert pool ID`, using the actual content of the corresponding fields | Match exclusive bidding fields to ensure accurate data during workflow execution |
| Trigger node cycle               | Daily 08:00–10:00, set based on actual measurements                                  | Match the update rhythm of daily bidding documents from business departments, avoid repeated triggers |
| File parsing node                | Support PDF, Word, Excel formats, enable field extraction switch                      | Adapt to structural differences across multiple types of bidding documents for this category |
| Input upper limit interception   | Set trigger threshold to `8000 token`, return custom error copy when exceeded         | Prevent AI chat nodes from interrupting the workflow due to exceeded input limits |
| `nodeId`                         | Bind unique identifiers for the evaluation report node and objection handling node     | Ensure accurate jump logic across all workflow links |
| Knowledge base variable binding  | Associate the `variables` parameter of the current workflow                           | Align knowledge base retrieval content with exclusive fields of the current bidding project |
| Single document upload limit     | 1000 MB                                                                              | Adapt to storage and transmission requirements for large bidding documents |

## Three Common Configuration Mistakes
- Scenario: Workflow file upload nodes fail to load bidding documents, with the interface displaying "File format not supported". Cause: Parsing rules for PDF, Word, and Excel formats are not configured, and only general document format support is enabled.
- Scenario: AI chat nodes cannot read attached JPG files from uploaded evaluation reports, returning empty results. Cause: The image text extraction function for the file parsing node is not configured in the workflow, and only plain text document parsing is supported.
- Scenario: AI chat nodes return an "Input content exceeds limit" error and interrupt the workflow when processing long evaluation reports. Cause: No input upper limit interception configuration is set, and no pre-check is performed for input content exceeding the threshold.

## How to Confirm Configuration Is Correct
- Check the mapped fields of the `variables` parameter to confirm that exclusive fields for this category such as bidding number and section division are included.
- Trigger a test workflow to verify that the file parsing node can correctly extract core fields from bidding documents.
- Simulate input content exceeding the threshold to confirm that the custom interception prompt is triggered.
- Check the `nodeId` configuration to confirm that the jump logic of each workflow node matches the sequence of the bidding process.
