# Internal Office and Employee Services for Engineering Construction Project Bidding: Model Access and Configuration

## What the data for this category looks like
This category of data mainly comes from the national public resource trading platform, local trading platforms, engineering approval systems, and bidding supervision systems, with a daily update frequency. Commonly processed documents include bidding announcements, qualification prequalification documents, bidding documents, tender documents, bid evaluation reports, successful bid candidate notices, and successful bid result announcements. Most document structures include fields such as section division, qualification requirements, bill of quantities, and bid evaluation rules. Some documents have complex formats such as nested tables and multi-page attachments.

## What constraints these characteristics impose on the model access and configuration link
Data sources updated daily require that model call frequency be adapted to business rhythms to avoid interface current limiting caused by high-frequency requests. Multiple types and formats of bidding documents require configuration that supports adaptive text splitting and reading logic to avoid long text truncation or format parsing errors. Exclusive business fields such as sections, qualifications, and bill of quantities require the model to have accurate recognition capabilities, so output parameters need to be adjusted to ensure the accuracy of key information. Document structures with multi-page attachments and nested tables require sufficient context length to fully read associated content and prevent omission of core information related to bid evaluation or successful bids.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the long text characteristics of bidding documents with multiple sections and multiple attachments, avoiding truncation of core bid evaluation information |
| `temperature` | 0.3–0.5 | Reduces random output probability to ensure accurate recognition of key fields such as qualifications and bill of quantities |
| `quoteMaxToken` | 1500–2000 characters | Matches the length of quoted content in documents such as successful bid notices and bid evaluation reports, ensuring complete associated information |
| Single recall limit | Top 8 entries | Covers associated data from multiple sources such as bidding announcements and tender documents, avoiding incomplete information caused by too few recalls |
| Reranking function | Enabled | Improves the sorting priority of core content such as bid evaluation rules and qualification conditions, matching business review logic |

## Three common mistakes
- Existing configurations are overwritten after configuring models with the same name. Cause: Unique identifiers are not set for differently deployed models, and the system automatically overwrites existing configurations according to the name uniqueness rule.
- Output content includes the phrase "citation mark: [1]". Cause: The automatic citation mark generation configuration is not turned off, or the filtering rules for quoted content are not configured.
- Key information is lost after long text splitting. Cause: The `maxContext` configuration value is too small and does not adapt to the long text structure of bidding documents.

## How to confirm the configuration is complete
- Upload a single bid evaluation report document, initiate a test question related to qualification review, check whether the model output fully includes core review content, and confirm that the context length configuration adapts to the document size.
- Import multiple different types of bidding documents, test whether the model can accurately identify exclusive business fields such as section division and bill of quantities, and verify that the parameters adapt to business document characteristics.
- Initiate a test question that requires citation, check whether the output only retains the associated content required for the business without redundant marks.
- Simulate the daily incremental data import process, confirm that the system can normally read updated documents, and verify that the data source configuration is compatible.

The values provided are common starting points and should be measured against the reader's own samples.
