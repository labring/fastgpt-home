# Internal Office and Employee Services for Construction Project Bidding: Forms and Interactions

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
Data for this category mainly comes from national public resource trading platforms, local trading platforms, project approval systems, and bidding supervision systems. The update frequency is daily. Commonly involved documents include bidding announcements, qualification prequalification documents, bidding documents, bid documents, bid evaluation reports, bid winner candidate announcements, and bid result announcements. Data fields include section information, qualification requirements, bill of quantities, bid evaluation expert records, bid results, and others. There is no unified fixed unit; fields must be matched according to the document type.

## What constraints these characteristics impose on the forms and interactions link
The daily updated data source requires forms to support real-time synchronization of the latest trading data, and avoid using expired fields. Multiple types of bidding documents correspond to differentiated form fields, so forms must support switching structure by document category. Cross-system data sources require form configurations to be compatible with imported fields of different formats. Time-consuming business links such as section splitting and bid evaluation record verification need form optimization interactions like preset field groups and batch editing to improve operational efficiency.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |

## Three common mistakes
- Phenomenon: Some fields are empty after importing a qualification prequalification document into the form, and automatic matching fails. Cause: The preset field group corresponding to the document is not configured using `formInput`, and the general form template is directly applied without adapting to the exclusive field structure of documents in this category.
- Phenomenon: No matching results are displayed when selecting bidding documents via variable reference. Cause: The data source range is not clearly configured, and the parameter filling rules for variable reference are not specified, resulting in failure to associate documents from the corresponding trading platform.
- Phenomenon: A timeout error occurs after submitting a bid evaluation record form. Cause: The form timeout threshold is set lower than 600 seconds, and the actual operating time of the bid evaluation verification link is not adapted.

## How to confirm the configuration is complete
- Import a qualification prequalification document, and check whether the fields automatically matched by the form are consistent with the document content.
- Switch between different business roles, and test whether bidding documents within the corresponding permission range can be accessed.
- Submit a simulated bid evaluation record form, verify whether the operation response meets business requirements, and adjust the timeout threshold as needed.
- Configure variable reference rules, and test whether documents of the corresponding section can be accurately filtered.
