# Internal Office and Employee Services for Market Entity Registration and Licensing: Deployment and Upgrade

## What this category's data looks like
Daily processing documents for this category include establishment registration applications, articles of association, shareholder resolutions, residence certificates, business licenses, food business license applications, and more. Data is sourced from the enterprise registration full electronic system, the national enterprise credit information public disclosure system, the electronic business license system, and the residence information database. It updates automatically each day. Data fields include entity name, residence address, shareholder information, license type, and more. A single document spans hundreds to thousands of characters. Cross-source data from multiple systems must be associated to complete verification and validation.

## What constraints do these characteristics impose on deployment and upgrade
The business characteristics of this category create the following constraints for deployment and upgrade:
- Daily updated cross-source data requires a stable multi-data source synchronization link during deployment. This prevents data delays that cause verification failures.
- Structural differences across multiple document types require compatibility with parsing adaptations for different formats during upgrades. This prevents failed field extraction for some documents.
- Frequent verification operations require sufficient computing resources to be reserved. This avoids timeouts during processing peaks.
- Cross-system associated field verification requires precise field mapping rules. This prevents data matching errors that lead to registration rejection.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | This category stores multi-system synchronized enterprise registration data. The standard MongoDB connection format supports multi-source data storage |
| `REDIS_URL` | `redis://:password@host:port/0` | Daily updated cross-source data requires caching verification results to reduce repeated query overhead |
| `STORAGE_S3_ENDPOINT` | `Storage endpoint configured according to cloud service provider region` | Scanned documents such as business licenses and residence certificates need to be stored. S3-compatible object storage supports large file uploads |
| `DB_MAX_LINK` | `20–30 connections` | Stable database connection pool is required when synchronizing data across multiple systems. This avoids service interruptions caused by exhausted connections |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Access tokens need to be generated for uploaded license application documents to ensure file access security |
| `PG_URL` | `postgresql://username:password@host:port/database` | Structured registration process logs need to be stored. PostgreSQL supports efficient querying of structured data |

## Three common misconfigurations
- Issue: After deployment, processing a business license scanned document shows `ocr error` in logs. Cause: The dependency environment for the image understanding model is not configured, or the image parsing switch is not enabled in the knowledge base.
- Issue: A newly deployed environment prompts a database connection failure after startup. Cause: Connection parameters for `MONGODB_URI` or `PG_URL` are not filled correctly, preventing access to the storage database.
- Issue: No image understanding model option appears when creating a new knowledge base. Cause: The dependency package for the corresponding model was not installed during deployment, or the model loading configuration was not enabled in the environment variables.

## How to confirm configurations are correct
- Run the built-in database connection test tool to verify that the configurations for `MONGODB_URI` and `PG_URL` can establish normal connections.
- Upload a standard establishment registration application document to confirm that parsed fields can be extracted normally and stored in the corresponding database.
- Manually trigger a cross-source data synchronization task to check whether data updates follow the preset daily synchronization schedule.
- View system logs to confirm that the cache service corresponding to `REDIS_URL` has no connection exceptions or timeout errors.
