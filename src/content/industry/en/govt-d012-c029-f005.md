# Internal Office and Employee Services for Urban Sanitation and Urban Management Law Enforcement Cases: Tool Calling and Plugins

## What data for this category looks like
Data for this category typically originates from urban management law enforcement platforms, urban operation grid platforms, video surveillance systems, and public complaint work orders. The update frequency is daily.
Daily documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and case closure reports.
Common data fields cover event location coordinates, violation types, responsible party information, rectification status, and related supporting material numbers. Most content is semi-structured or unstructured, with no unified mandatory format.

## What constraints these characteristics impose on the tool calling and plugin workflow
This category’s data comes from heterogeneous sources as semi-structured and unstructured content, and requires daily synchronization. The tool calling workflow must adapt to authentication and format conversion requirements across multiple platform interfaces. The `toolChoice` parameter can be configured to support multi-scenario access.
Access to unstructured data such as on-site photos requires plugins to support multimedia parsing parameter configuration.
Case processing has strict requirements for evidence integrity. Tool calling must complete core field verification during the parameter extraction phase, to prevent law enforcement disputes caused by missing key information.
Daily high-frequency case flow requires plugins to support batch calling capabilities, to match the volume of new cases added each day.

## How to configure settings
The following configurations are based on FastGPT v4.17.0, and are adapted to the business characteristics of this category:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | This category covers multiple case scenarios including inspection discoveries and complaint transfers. Automatic tool selection adapts to dynamic business needs |
| Plugin call timeout | 60 seconds | Urban management law enforcement on-site response requires timely results. Excessive timeout will reduce on-site case handling efficiency |
| Tool call parameter verification trigger condition | Extract both location coordinates and violation type fields | Core evidence for this category’s cases is on-site information. Missing these fields will lead to insufficient law enforcement basis |
| Batch plugin call limit | 50 items per request | Matches the regular processing scale of daily new cases, avoids resource overload from single requests |
| `functionCall` | Enable mandatory parameter verification | This category’s cases require clear responsible parties and rectification requirements. Mandatory verification reduces invalid calls |
| Parameter extraction confidence threshold | 0.8–0.9, calibrated based on actual testing | Ensures recognition accuracy for responsible parties and violation types, avoids law enforcement disputes caused by misjudgments |

## Three common configuration mistakes
- Symptom: After configuring a custom plugin, calls return the "corresponding plugin not found" error. Cause: The plugin’s key configuration and permission binding were not completed on the FastGPT plugin management page, so the application cannot call the custom plugin.
- Symptom: Calls to the knowledge base query interface return a parameter error. Cause: The application key was used directly to call a non-public interface, and parameters were not passed through the platform’s built-in plugin calling link, violating interface authentication rules.
- Symptom: No user input confirmation step is triggered after tool calling. Cause: The parameter verification trigger condition was not configured, or the trigger condition does not cover the core field verification logic for this category’s cases, causing the system to directly execute the plugin.

## How to confirm correct configuration
- Navigate to the FastGPT plugin management page, confirm that the authentication information and interface addresses for added urban management law enforcement-related plugins are correct.
- Simulate typical inputs such as inspection records and complaint work orders, trigger the tool calling workflow, check that the corresponding tool is automatically selected and core parameter verification is completed.
- Trigger a batch call test, confirm that the number of cases per single call does not exceed the configured batch limit, and that returned results meet expectations.
- View tool calling logs, confirm that the parameter extraction confidence falls within the preset threshold range, with no abnormal errors.
