# Internal Office and Employee Services for Urban Sanitation and Urban Management Law Enforcement Cases: Knowledge Base Retrieval and Recall

## What data in this category looks like
Core data for this category comes from urban management law enforcement platforms, urban operation grid platforms, video surveillance systems, and public complaint work orders. The update frequency is daily.
Daily documents include inspection records, case filing approval forms, on-site photos, rectification orders, penalty decisions, and closing reports. Typical data fields include case number, law enforcement subject, incident location, violation type description, rectification requirements, and execution status. Some documents are linked to multimedia materials. Overall data combines structured case information with unstructured law enforcement documents and on-site images.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Daily updated data requires the retrieval link to support incremental synchronization configuration, to avoid full index reconstruction consuming computing resources.
Multiple types of combined documents (structured case information, law enforcement documents, on-site images) require the retrieval pipeline to adapt to feature extraction logic for mixed-format data, to avoid losing key information from single-feature extraction methods.
Cases originate from daily inspections, grid reports, and public complaints. This requires the recall logic to prioritize matching precise fields related to on-site disposal, focusing on core business scenarios such as on-site evidence collection and violation type judgment.
Law enforcement process documents follow standardized formats. This requires retrieval results to be linked to accurate case stage information, to avoid confusion between law enforcement materials from different stages such as filing, rectification, and closing.

## How to set the configuration
These settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches the precision requirements for urban management law enforcement cases, and avoids mixing low-relevance non-law enforcement content into results |
| `limit` | Top 6 entries | Covers the number of core related documents for a single case, and avoids excessively long context affecting response speed |
| `usingReRank` | Enabled | Performs secondary sorting on recall results, to improve the ranking priority of content related to on-site evidence collection and violation type judgment |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates extended queries based on the original question, to match hidden associated information in inspection records and complaint work orders |
| `searchMode` | vector_search | Prioritizes vector search for semantic content matching, adapting to the unstructured text characteristics of law enforcement documents and inspection records |

## Three common configuration errors
- Phenomenon: Custom directory structures in the knowledge base are automatically deleted, or duplicate text is cleaned up. Cause: Automatic document formatting and deduplication configurations are not disabled. The default logic removes directory markers and merges duplicate text blocks.
- Phenomenon: Question and answer pair extraction tasks remain stuck in training for a long time, no call records appear in invocation logs, or a server error indicating failed download is reported during knowledge base export. Cause: Incremental sync trigger rules for the dataset are not configured, or the dataset ID is not correctly mapped when migrating to a production environment, causing tasks to fail to start normally or export links to malfunction.
- Phenomenon: Retrieval results cannot fully match law enforcement document content in the knowledge base. Cause: The `datasetSearchUsingExtensionQuery` configuration is not enabled, or the `similarity` threshold is set too high, filtering out some precise content that matches semantically.

## How to confirm the configuration is properly set
- Upload a test inspection record and penalty decision, perform a retrieval query, and verify that returned results include associated law enforcement document content.
- View the dataset sync log, confirm that the daily incremental update task is triggered normally with no error messages.
- Adjust configuration items such as `similarity` and `limit`, compare retrieval results across different parameter settings, and confirm that matching precision meets business requirements.
- Export part of the test dataset, verify that the exported file is complete with no abnormal errors.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
