# Internal Office and Employee Services for Construction Engineering Quality and Safety Supervision: Workflow Orchestration

## What This Category of Data Looks Like
This category of data mainly originates from the engineering quality and safety supervision system, construction site real-name platform, supervision logs, and test reports. The update frequency is weekly. Core documents generated daily include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Each document contains fixed fields such as supervision subject, project basic information, on-site inspection items, rectification requirements, and acceptance conclusions. No additional custom non-standard fields are included, and the data structure is relatively unified.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The data of this category is multi-source and scattered, with fixed update cycles and unified document structures, which imposes multiple constraints on workflow orchestration. First, multi-data source connection nodes must be configured, and the interface formats of each system must be adapted one by one to avoid format mismatches during data aggregation. Second, the workflow scheduling cycle must match the weekly data update rhythm, while supporting manual triggering to adapt to emergency inspection scenarios. In addition, the fixed document structure requires that text extraction nodes in the workflow preset field mapping rules to ensure that extracted content corresponds one-to-one with the fields of business documents. Finally, the supervision process has a strict sequence, so node dependency rules must be configured for the workflow to prevent supervision loopholes caused by process skipping.

## How to Set the Configurations
This document is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data source node configuration | Bind each system's open interface one by one, enable the data verification switch | This category of data comes from multiple independent systems, and one-by-one connection is required to ensure data accuracy. The verification switch can filter invalid fields |
| Workflow scheduling cycle | Trigger weekly, support manual temporary triggering | Business data is updated weekly, and weekly scheduling matches the daily supervision work rhythm. Manual triggering adapts to emergency inspection scenarios |
| Global variable configuration | Bind core fields such as project number and rectification deadline, enable the `variables` parameter to pass to each business node | Core business fields need to be reused globally. `variables` can uniformly manage and pass parameters to each node, adapting to multi-project switching scenarios |
| Node ID configuration | Assign a unique `nodeId` to each business node | Facilitates subsequent node calls or workflow exception troubleshooting, and accurately locates failed execution links |
| Text extraction node | Match the fixed field mapping of supervision inspection records | Daily document structures are fixed, and field mapping can avoid extracted content mismatches and improve data extraction efficiency |
| Log retention configuration | Enable full-node log retention | Supervision processes require traceability. Log retention can be used for post-event verification and problem location |

## Three Common Mistakes
- Phenomenon: After a question-and-answer node is added to the workflow, associated supervision log data cannot be obtained. Cause: The data source node and the `variables` parameter of the question-and-answer node are not bound, causing the question-and-answer context to fail to load business data.
- Phenomenon: Text processing nodes in existing workflows disappear after an upgrade, causing field extraction failures for supervision inspection records. Cause: Some old functional nodes are integrated in the new version, and the original configuration is not automatically migrated.
- Phenomenon: Attempting to bring global variables into the URL parameter of a shared link fails to switch to the supervision process of the corresponding project. Cause: The URL parameter configuration switch for global variables is not enabled, so the parameters are not recognized by the workflow.

## How to Confirm the Configuration Is Complete
- Manually trigger the workflow one time. Verify the execution status of each node for normality. Troubleshoot corresponding configuration items for any abnormal nodes.
- Import a standard supervision inspection record document. Verify whether the field mapping of the text extraction node is accurate, and match the field structure of the business document.
- Test the URL parameter transfer of global variables. Verify whether the workflow can correctly load the business data of the corresponding project.
- View the full-process logs. Confirm that the execution results of each node are correctly recorded, with no missing or abnormal fields.
