# Internal Office and Employee Services for Construction Engineering Quality and Safety Supervision: Tool Calling and Plugins

## Data overview for this category
The data for this category mainly comes from the engineering quality and safety supervision system, construction site real-name platform, supervision logs, and test reports. The update frequency is weekly. Daily documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Each document is associated with the corresponding project number and information of on-site construction participants, and records on-site quality and safety inspection items, rectification requirements, acceptance verification results, and other content.

## Constraints imposed by these characteristics on tool calling and plugins
Data sources are scattered and cover the entire project process. Tool calling must support pulling associated data across multiple systems. Document updates occur at a fixed weekly frequency, so plugin trigger cycles must match this rhythm to avoid frequent calls that consume resources. A single document contains multiple fields and complex associated business logic. Tool calling must accurately match document fields with business actions, such as verifying the closed-loop status of hidden danger rectification notices. Inspecting on-site materials and tracking rectification closed loops are core time-consuming steps. Tools must support batch pulling of multiple record data to reduce manual verification costs.

## How to configure settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to diverse tool calling scenarios including multi-system data pulling and hidden danger rectification verification, without fixed binding to a single tool |
| Single tool call timeout | 600 seconds | Matches the average time required for pulling engineering materials and verifying acceptance conditions, preventing call interruptions due to large data volume |
| Context window size | 8000–12000 token | Accommodates complete text of multiple supervision inspection records and rectification notices, ensuring full business context is available during tool calls |
| `functionCall` | Triggered by fixed business actions | Corresponds to standardized business actions such as confirming closed-loop rectification of hidden dangers and verifying completion acceptance conditions, improving calling accuracy |
| Plugin trigger cycle | 1 time per week | Matches the weekly update frequency of data for this category, reducing invalid calls and server resource usage |
| Tool result verification threshold | Calibrated based on actual testing | Adapts to quality and safety judgment standards for different engineering projects, avoiding misjudgment or missed judgment |

## Three common configuration errors
- Symptom: A `connect ECONNREFUSED 172.23.0.2:3001` error is returned when calling a plugin. Cause: The backend service address bound to the plugin cannot be connected normally, or container network policies restrict cross-service access.
- Symptom: The plugin editing interface always displays the "Unsaved" prompt at the top, regardless of whether the save operation is completed. Cause: The front-end interface status update logic is not synchronized with the back-end save interface return logic, or browser caching causes abnormal interface status.
- Symptom: Supervision record data returned by tool calls is incomplete, with some historical inspection items missing. Cause: The configured context window is not large enough to accommodate multiple document contents, or the tool call recall range does not cover all associated data.

## How to confirm successful configuration
- Manually trigger a tool call, and verify that the returned fields match the standard structure of documents such as supervision inspection records and rectification notices for this category.
- View plugin running logs to confirm that configuration items including call timeout and trigger cycle match the preset values.
- Compare the weekly update rhythm of the data, and verify that the plugin can normally pull the latest associated data after the update node.
- After completing plugin editing, confirm that the save status prompt on the interface disappears.
