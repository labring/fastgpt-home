# Internal Office and Employee Services for Construction Engineering Quality and Safety Supervision: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
The data for this category comes primarily from the engineering quality and safety supervision system, construction site real-name management platform, supervision logs, and test reports. The update frequency is weekly. Daily documents include supervision plans, supervision inspection records, hidden danger rectification notices, quality problem handling forms, and completion acceptance supervision reports. Most documents contain fields such as project number, project name, inspection date, hidden danger description, rectification requirements, and closed-loop status. The content of a single document covers all process nodes of on-site supervision. There is no unified fixed template, and some documents are in table format.

## Constraints on Knowledge Base Retrieval and Recall
Data sources are scattered, and most documents are unstructured or semi-structured files exported from business systems. Retrieval must cover associated fields across multiple systems. The weekly update frequency requires that retrieved and recalled content matches the latest supervision plans and rectification closed-loop status, to avoid calling expired data. Documents have no unified template, mixing plain text and tables. Content splitting and retrieval must adapt to different formats. Daily documents mostly focus on on-site hidden dangers and acceptance links. Retrieval needs center on content related to hidden danger rectification basis and acceptance standards. Precise recall of historical records for corresponding links is required.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. Specific parameter values can be adjusted based on actual business scenarios:
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Matches the semi-structured characteristics of documents in this category, filters low-relevance non-on-site supervision content |
| `limit` | Top 10 entries | Covers the number of associated records for a single supervision inspection, avoids context overload |
| `searchMode` | Semantic Retrieval | Adapts to semantic matching requirements for multi-template documents, meets precise recall needs for on-site supervision content |
| `usingReRank` | Enabled | Optimizes the ranking accuracy of recall results for documents from scattered sources |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements associated retrieval for exclusive fields such as project number and project name, covers cross-system data association |
| `collectionIds` | Configured by business system grouping | Distinguishes data sources such as supervision systems and real-name management platforms, accurately limits retrieval scope |

## Three Common Misconfigurations
- Symptom: Retrieval result similarity scores are generally higher than 0.9, but the content does not match actual supervision needs; Cause: `datasetSearchUsingExtensionQuery` is not enabled, and associated retrieval for exclusive fields such as project number and project name is not supplemented, leading to generalized matching that hits irrelevant documents.
- Symptom: An error occurs when calling knowledge base variables, and directly filling in the knowledge base ID returns fixed results; Cause: The variable binding logic for the `collectionIds` parameter is not configured correctly, or the variable scope does not cover the current internal office scenario.
- Symptom: After importing Excel-format test reports, hidden danger rectification items in the table cannot be accurately recalled; Cause: Structured splitting adaptation is not performed for table datasets, causing table content to be treated as plain text and losing column association relationships.

## How to Verify Proper Configuration
- Upload a single supervision inspection record, retrieve "hidden danger rectification requirements", and check whether the recall results include historical rectification records for the same project.
- Adjust the `similarity` parameter range, observe changes in the relevance of recall results, and confirm that the value range covers the matching accuracy of documents in this category.
- After enabling `usingReRank`, compare the result ranking before and after reranking to confirm that the sorting logic adapts to on-site supervision content.
- Bind the `collectionIds` variable grouped by business system, and verify that the retrieval scope only includes documents from the specified data sources.

The values provided here are common starting points and should be evaluated against the reader's own samples.
