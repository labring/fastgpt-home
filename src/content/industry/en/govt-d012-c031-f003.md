# Internal Office and Employee Services for Construction Project Environmental Impact Assessment (EIA) Approval: Multi-turn Dialogue and Prompt Engineering

## What the data for this use case looks like
Data for this use case originates from the national unified construction project EIA declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Daily processed documents include environmental impact assessment reports/statement forms, approval applications, public participation explanations, technical evaluation opinions, and EIA approval documents. Document structures include fields such as basic project information, pollution prevention measures, public participation content, and approval status. Data updates occur irregularly, with no fixed update cycle.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering link?
EIA-related data comes from multiple dispersed sources. Multi-turn dialogue must gradually guide users to verify project information across different systems to avoid mixing data from different sources. Individual EIA documents are lengthy, so prompts must limit the context scope to prevent redundant information from interfering with core approval processes. Data updates have no fixed cycle, so dialogue must prompt users to verify the latest ecological environment zoning control data to ensure valid approval basis. Core approval processes require verification of project category and EIA level. Multi-turn dialogue must split steps to gradually confirm key fields and avoid omissions.

## How to set configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Maximum context length | 8000–12000 characters | Individual EIA documents can reach several thousand characters. This range covers complete context related to project approval and avoids information overflow |
| Single-turn dialogue recall count | Top 3–5 entries | EIA data comes from multiple sources with clear fields. Limiting recall count avoids redundant information interference and focuses on core approval-related data |
| Dialogue timeout setting | 600 seconds | Retrieving EIA declaration and monitoring data across systems takes a long time. This threshold covers most data retrieval scenarios |
| Chunk length | 1000–1500 characters | EIA documents have complex structures. This chunk length balances recall accuracy and context length to facilitate precise matching of approval process needs |
| `variables` configuration | Bind project code and approval status variables | EIA approval requires dialogue based on project-specific information. Binding variables enables personalized session matching |
| `chatId` binding configuration | Bind the current session's exclusive ID | Achieve context isolation for different project sessions and avoid data mixing between multi-turn dialogues |
| Multi-turn dialogue message format | Pass context in accordance with the `messages` parameter standard format | Complies with FastGPT multi-turn dialogue interaction specifications and enables the system to accurately parse context information |

## Three common configuration mistakes
- A request timeout error pops up during dialogue. This occurs because a reasonable timeout threshold is not configured for cross-system EIA declaration data retrieval, causing data retrieval to fail to complete within the specified time limit.
- Form input content configured in the workflow cannot be displayed in the dialogue interface. This occurs because the `variables` parameter is not correctly associated, causing the dialogue context to fail to load the exclusive fields corresponding to the form.
- EIA data from different projects is mixed in multi-turn sessions. This occurs because `chatId` binding is not used to implement session isolation, causing context from different projects to be incorrectly reused.

## How to verify that configurations are correctly set
- Launch a multi-turn dialogue for a single EIA project, and check that the context only includes data related to the current project, with no information from other unrelated projects.
- After configuring the `variables` parameter, trigger a form call in the dialogue, and confirm that form fields load and display normally.
- Start a dialogue process that retrieves data across systems, and confirm that no request timeout errors occur and that relevant data returns normally.
- Switch sessions for different projects, and confirm that `chatId` binding takes effect, with contexts from different projects not interfering with each other.
