# Internal Office and Employee Services for Construction Project Environmental Impact Assessment Approval: Forms and Interactions

This page provides configuration guidance based on the features available in FastGPT v4.17.0.

## What the data for this category looks like
This category of data mainly comes from the national unified construction project environmental impact assessment (EIA) declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and environmental monitoring data. Daily circulating documents include environmental impact assessment reports or report forms, approval application materials, public participation explanations, technical evaluation opinions, and EIA approval documents. Data fields cover project category, EIA level, pollution prevention measures, public participation feedback status, and more. There is no fixed update cycle, and the latest information from each source system is synced on demand. Most documents are a combination of structured forms and non-technical explanatory text.

## What constraints these characteristics impose on the "forms and interactions" link
Multi-source data sources require forms to support real-time verification and pulling of cross-system data, to avoid duplicate errors from manual entry. The mixed document structure requires the interaction link to distinguish different interaction logics for structured field entry, unstructured text, and attachment upload. There are many professional fields that need to match the latest ecological environment zoning control results, so forms need to preset a compliant option library and support dynamic updates. The lack of a fixed update frequency requires the interaction link to sync the latest data from each source system on demand, while supporting hierarchical view and edit permission configuration for form content by each node in the approval process.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Support mixed entry of structured professional fields and multiple types of attachments, with field verification matching the EIA terminology library | EIA forms include professional fields such as project category and pollution prevention measures, and require uploading attachments such as reports and approval documents |
| `userSelect` | Preset optional value lists for project category and EIA level, support dynamic updates | Need to match the latest ecological environment zoning control results to avoid entering non-compliant project classifications |
| Form permission configuration | Assign hierarchical view and edit permissions by approval node, core fields can only be edited by the EIA department | There are multiple collaboration nodes in the EIA approval process, which requires ensuring the compliance of content modifications |
| Data synchronization configuration | Trigger cross-system data pulling on demand, set synchronization interval based on actual testing | Data updates have no fixed cycle, and it is necessary to obtain the latest information from the national EIA declaration system and zoning control results on demand |
| Attachment upload limit | Single file maximum 1000 MB, support uploading PDF and Word format documents | The volume of daily circulating EIA documents varies greatly, and needs to adapt to different types of approval materials |

## Three common mistakes
- Phenomenon: An Invalid array length error occurs when configuring form fields, and the form interface cannot be rendered normally. Cause: The structured field array of `formInput` is not correctly defined, resulting in the parameter format not meeting the requirements.
- Phenomenon: Unable to create interactive buttons for users to independently select options at the specified position of the form. Cause: The custom option configuration of `userSelect` is not enabled, or the trigger logic of the button is not bound to the corresponding form link.
- Phenomenon: The approval process selected after the conversation starts cannot take effect continuously in this session, and it needs to be reselected for each reply. Cause: The session-level process persistence setting is not configured, resulting in the session state not being retained correctly.

## How to confirm the configuration is complete
- Open the form configuration page, check whether the field list of `formInput` includes professional EIA required fields such as project category and EIA level, and whether the attachment upload configuration matches daily circulating document types.
- Test whether the preset options of `userSelect` load normally, and confirm that it supports dynamic updates of the latest ecological environment zoning control results.
- Trigger cross-system data synchronization, confirm that the form can normally pull the latest data from each source system without error prompts.
- After configuring the session process persistence, start a conversation and select an approval process once, verify whether subsequent interactions use the selected process.
