# Internal Office and Employee Services for Construction Project Environmental Impact Assessment Approval: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category include the national unified construction project environmental impact assessment declaration and approval system, ecological environment zoning control results, pollution discharge permit platform, and monitoring data. Update frequency is irregular. Daily processed documents include environmental impact assessment reports or report forms, approval applications, public participation explanations, technical assessment opinions, and environmental impact assessment approvals. Each document covers fields such as project category, environmental impact assessment level, pollution prevention measures, and public participation status. There is no fixed unified unit, and structured processing must be completed by matching actual project parameters.

## What constraints these characteristics impose on the deployment and upgrade link
Most data sources come from government affairs systems, so interface permissions and format requirements are strict. Compatibility configuration for cross-system data synchronization must be adapted during deployment. Irregularly updated environmental impact assessment policies and project data require that compatible logic for historical data migration be retained after upgrades, to avoid interrupting approval processes. The need for structured processing of multiple types of documents requires reserving sufficient storage and computing resources. Differences in permission division between entities (environmental impact assessment institutions, approval departments, construction units) require fine-grained role configuration during the deployment phase, to prevent subsequent upgrades from damaging the existing permission system.

## How to set the configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–200` | In environmental impact assessment approval scenarios, multiple users initiate project processing requests simultaneously. This parameter controls the maximum number of connections in the database connection pool, ensuring stability for concurrent access |
| `STORAGE_S3_ENDPOINT` | Configured according to the endpoint provided by the government cloud storage service provider | Environmental impact assessment data belongs to government-sensitive information, and must be stored in a compliant government cloud environment, matching the access address of the corresponding storage service |
| `REDIS_URL` | Use a dedicated Redis instance for the government intranet, with a memory specification of 2048 MB | Caches temporary sessions and document metadata for environmental impact assessment projects, improving data access security through intranet isolation |
| `FILE_TOKEN_KEY` | `64-bit random string` | Used to sign temporary tokens for file uploads, ensuring the security of upload processes for documents such as environmental impact assessment reports, and preventing unauthorized access |
| `ROOT_KEY` | `32-bit random string` | Used to configure the system's highest-privilege access key, ensuring the security of permission control for the internal office backend |
| `FE_DOMAIN` | Configured as a secondary domain name of the internal office system | Adapts to internal employee access paths, unifying system entrances for internal office work and environmental impact assessment approval |

## Three common errors
- A `Failed to create post presigned url` error occurs when uploading files such as environmental impact assessment report forms via the workflow. The cause is that the `FILE_TOKEN_KEY` and storage service configuration parameters were not rematched after the upgrade, resulting in failure to generate temporary upload tokens.
- Historical environmental impact assessment approval documents fail to load after deployment. The cause is that `MONGODB_URI` or `PG_URL` was not configured correctly, with insufficient database connection permissions or incorrect address configuration.
- Internal employees cannot access the system backend management interface. The cause is that the permission scope of `ROOT_KEY` was not set correctly, resulting in role division that does not meet the permission control requirements of internal office work.

## How to confirm the configuration is complete
- Perform a database connection test to verify that the number of connections configured for `DB_MAX_LINK` can support simultaneous environmental impact assessment project processing requests.
- Upload a small test environmental impact assessment report form to confirm that the file upload and storage processes work normally, with no errors related to token generation.
- Access the configured internal office domain name to confirm that the address configured for `FE_DOMAIN` can normally redirect to the system frontend interface.
- Check the Redis instance monitoring to confirm that the instance configured for `REDIS_URL` can normally store temporary sessions and document metadata.
