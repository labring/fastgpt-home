# Internal Office and Employee Services for Investment Project Approval and Post-Evaluation: HTTP Interfaces and External Systems

## What Data Looks Like for This Category
Core data for this category follows the full lifecycle of investment projects. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, post-investment evaluation reports, and similar materials. Data sources include the state-owned assets supervision commission’s investment supervision system, enterprise ERP and project management systems, industry market data, audit reports, and financial statements. Data is updated quarterly. Data structures include fields such as basic project information, investment amount, progress milestones, and compliance review results. Some documents are unstructured long text, while others are structured data exported from internal systems.

## Constraints for HTTP Interfaces and External Systems
Data sources for this category cover multiple internal and external systems. HTTP interfaces must adapt to authentication rules and data formats of different systems, and support cross-system data pulling and synchronization. Quarterly data updates require interface batch synchronization frequencies to match the quarterly cycle. This prevents excessive API calls or delayed synchronization. A high share of unstructured long text documents requires interfaces to support chunked upload or batch submission of large files. This stops single requests from exceeding processing limits. Data also aligns with state-owned asset management requirements. Interfaces must include strict authentication and logging capabilities to ensure traceable operations.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {Enterprise internal unified authentication token} | Matches the authentication specifications of internal systems for state-owned enterprises and public institutions, ensuring secure interface calls |
| Maximum number of documents per single request | 5 | Adapts to the total volume of documents updated per quarter, avoids interface timeouts and excessive resource usage, and complies with the interface processing limits of FastGPT v4.17.0 |
| Request timeout period | 600 seconds | Matches the processing duration of long documents such as complete feasibility study reports, aligns with the processing rhythm of business data |
| `responseData` | Includes project ID, processing status, progress fields | Facilitates callback verification for integration with ERP and supervision systems, ensuring traceable data synchronization results |
| `variables` | Preset investment project type, subordinate state-owned assets supervision commission jurisdiction variables | Adapts to business screening logic for different entities, accurately matching project classification rules |
| Batch synchronization interval | 90 days | Matches the quarterly data update frequency, reducing unnecessary interface call overhead |

## Three Common Configuration Errors
- Interfaces return a `401 Unauthorized` status code, and project data cannot be pulled normally. The root cause is incorrect configuration of the `Authorization` parameter. Failure to use the enterprise’s internal unified authentication token leads to authentication failure.
- Interface response times far exceed initial test results, reaching several minutes. The root cause is failure to adjust the request timeout period. Submitting too many long documents such as complete feasibility study reports in a single request exceeds system processing limits, causing queuing delays.
- No corresponding index data is generated after calling the create training order interface. The collection add data interface cannot upload complete feasibility study reports. The two interfaces have different applicable scenarios. The create training order interface handles batch processing of large-volume business documents. The collection add data interface only supports single short text entries. The wrong interface is selected based on document type.

## How to Verify Correct Configuration
- Call the `Authorization` authentication interface. A valid token is returned with no authentication failure prompts. This confirms the authentication configuration is active.
- Submit a single quarterly updated feasibility study report to the interface. Confirm the processing progress field returned in `responseData` updates normally. This verifies the data processing flow works correctly.
- Configure preset `variables` for investment project type and subordinate jurisdiction. Call the interface to filter project data for the corresponding jurisdiction. Confirm returned results match expected business classification rules. This verifies the variable configuration is active.
- Review interface call logs. No timeout errors appear, and processing duration stays within the preset 600 second threshold. This confirms the timeout configuration is reasonable.

The configuration values listed above are common starting points. They should be evaluated against the specific samples and operational conditions of the relevant deployment.
