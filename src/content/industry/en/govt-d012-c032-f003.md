# Internal Office and Employee Services for Investment Project Approval and Post-Evaluation: Multi-turn Dialogue and Prompt Engineering
This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
The data for this category mainly comes from the national state-owned assets investment supervision system, enterprise ERP and project management systems, industry market data, audit and financial statements. Updates occur quarterly. Daily processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Most documents combine structured reports and long-form text reports, and contain fields such as project number, investment amount, construction period parameters, and post-investment operation data. There are no unified fixed units, and values adjust dynamically based on document type and business requirements.

## What constraints do these characteristics bring to the multi-turn dialogue and prompt engineering link
Data for this category comes from multiple systems and updates quarterly. Multi-turn dialogue must bind full-link business data for the corresponding project to avoid context breaks. Long-text feasibility study and post-evaluation reports make up a large share of processed documents, so prompts must limit the context window to stay within the model's processing limit. Document fields change dynamically by type, so teams must adapt to the parameter naming rules of different documents to ensure accurate field calls during dialogue. Cross-system data consistency requires multi-turn dialogue to synchronously verify project data from different sources to avoid deviations.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Maximum context length | 8000–12000 characters | Core feasibility study reports for this category are mostly 5000-10000 characters per single document, with reserved space for multi-turn dialogue history messages |
| `chatId` binding rule | Bind full-cycle dialogue context by project number | Projects in this category have long cycles, requiring association with data from all stages including approval, feasibility study, and post-evaluation |
| Number of recalled documents per single call | Top 6 | This category needs to call financial, market, and compliance data simultaneously; 6 entries can cover core dimensions without redundancy |
| `variables` dynamic loading rule | Automatically match field mappings by document type | Document fields for this category change based on types such as investment plans and feasibility study reports, requiring dynamic parameter adaptation |
| Streaming output toggle | Enabled | Long-text report generation requires gradual content display to improve interactive experience |
| Maximum quoted content length | 1500 characters | Matches the typical paragraph length of post-investment evaluation reports for this category, ensuring complete quoted content |

## Three common misconfigurations
- Phenomenon: After adjusting the single quotation limit to 2000 characters, the large model response does not reference any recalled content, and the recall log shows that document paragraphs were successfully obtained. Cause: The reference trigger rule is not clearly defined in the prompt, or the quotation limit configuration does not match the prompt instructions, leading to the large model being unable to recognize the reference conditions.
- Phenomenon: Embedded project document images cannot be displayed in the dialogue box. Cause: The image rendering toggle for the dialogue interface is not enabled, or the image format uploaded to the knowledge base is not supported by the system, causing images to fail to load in the dialogue flow.
- Phenomenon: Talent information paragraphs returned from knowledge base retrieval include paragraph ID fields. Cause: The ID attachment toggle during knowledge base export is not turned off, causing retrieval results to carry metadata fields that are not necessary for business purposes.

## How to verify correct configuration
- Initiate a multi-turn dialogue targeting a single feasibility study report, check whether `chatId` automatically associates all historical dialogue and document data for that project.
- Adjust the number of recalled entries per single call and the context length, verify that the generated response covers the three core data types of finance, market, and compliance, and does not exceed the configured length limit.
- Upload a project document with images, confirm that the dialogue interface can normally display image content.
- Retrieve knowledge base paragraphs, confirm that the returned results do not include unnecessary ID fields.
