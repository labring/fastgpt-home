# Internal Office and Employee Services for Investment Project Approval and Post-Evaluation: Workflow Orchestration

## What this category’s data looks like
Data for this category primarily comes from State-owned Assets Supervision and Administration Commission (SASAC) investment supervision systems, enterprise ERP and project management systems, industry market data, audit and financial statements. The update frequency is quarterly. Daily processed documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. These cover the full process from project pre-approval preparation to post-investment evaluation. Data fields are organized around core investment dimensions such as project investment amount, implementation cycle, risk level, and revenue expectations.

## Constraints on workflow orchestration from these characteristics
Data sources for this category are scattered. Cross-system data pull nodes must be configured for workflow orchestration to uniformly connect designated supervision, ERP and other data sources. The quarterly update frequency requires embedded knowledge base synchronization tasks to trigger quarterly to ensure the timeliness of retrieved data. Multiple types of documents cover the full process from approval to post-evaluation. Differentiated retrieval trigger rules must be configured for different documents. The circulation requirement for core investment dimension fields requires binding `variables` nodes in the workflow to achieve automatic data transfer, avoiding manual entry errors. At the same time, project risk constraints require configuring verification nodes in the workflow to ensure the accuracy of core data circulation.

## Three common configuration mistakes
- Phenomenon: After configuring the AI chat module, irrelevant results are returned, and the interface prompts that the number of retrieval results is 0. Cause: The scope of questions is not limited to content related to investment project approval and post-evaluation, or the dedicated knowledge base ID of the corresponding category is not bound.
- Phenomenon: When the workflow runs, the global variable is empty, and project data cannot be automatically pulled. Cause: The `variables` node is not bound to the project fields of the ERP system, or the assignment rule does not match the data source of this category.
- Phenomenon: Knowledge base retrieval call fails, prompting that the specified knowledge base cannot be found. Cause: A general knowledge base ID is mistakenly entered, and the dedicated investment project-related knowledge base ID of this category is not used.

## How to confirm configuration is complete
- Trigger a test workflow, check whether the `variables` node automatically displays the preset core project field values, and verify that the fields match the project data in the ERP system.
- Run the knowledge base retrieval node, verify that the returned results only include documents of this category such as annual investment plans and feasibility study reports, with no irrelevant content.
- Simulate a call failure scenario, confirm that the workflow triggers the retry node specified by `nodeId`, and the process can proceed normally after retries.
- View the workflow logs, confirm that all data pull nodes come from designated data sources such as the SASAC investment supervision system and enterprise ERP systems.
