# Internal Office and Employee Services for Investment Project Approval and Post-Evaluation: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Central enterprise strategic investment departments, project companies, state-owned assets supervision authorities, and external consulting and evaluation institutions provide the core data for this category. Daily documents include annual investment plans, project proposals, feasibility study reports, due diligence reports, asset evaluation reports, post-investment evaluation reports, and other related materials.
Data sources include state-owned assets supervision commission investment supervision systems, enterprise ERP and project management systems, industry market data, audit reports, and financial statements. Data is updated quarterly.
Documents contain both structured project parameters and unstructured analysis content. Fields cover project cycle, investment amount, compliance requirements, and more. There is no fixed unified format, with variations across project types.

## What Constraints Do These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
This category’s data characteristics create three core constraints for the retrieval and recall link.
First, multi-source heterogeneous data sources require retrieval to cover both structured fields and unstructured text. Matching logic must balance system-exported data and report-style documents.
Second, the quarterly update frequency requires regular incremental updates. This prevents retrieval results from lagging behind the latest investment plans and post-evaluation data.
Third, project-specific document scopes require precise limitation of the retrieval set. This stops cross-project data from interfering with investment decision material review and post-evaluation analysis.
Additionally, large volumes of documents generated in core time-consuming links require control of retrieval result scale. This avoids overly long contexts that disrupt subsequent processing.

## Three Common Misconfigurations
- Issue: Retrieval results include documents from non-current approval projects, and the interface returns result sets without filtering prompts. Cause: The `collectionIds` parameter is not configured correctly, and the knowledge base collection exclusive to the current project is not bound, resulting in cross-project data being recalled.
- Issue: Retrieval requests time out, and the system returns a 504 status code. Cause: The `limit` parameter is not adjusted according to the quarterly updated document scale, and the number of recalled entries is set too high, causing the context length to exceed the platform's processing limit.
- Issue: Uploaded video attachments from due diligence reports cannot be retrieved, and no corresponding content appears in retrieval results. Cause: The video content parsing module is not configured, only chunking and recall of text documents are supported, and non-text format attachment data cannot be processed.

## How to Verify Proper Configuration
- Manually input a core calculation data fragment from a project's feasibility study report as a query term, verify that the returned results only include related documents for this project, with no investment materials from other projects.
- Check the sorting order of retrieval results, confirm that core documents such as post-investment evaluation reports and asset evaluation reports rank in the top three results.
- Upload an industry market data document updated in the current quarter, trigger an incremental update, then use relevant keywords for retrieval, confirm that the newly uploaded document is normally recalled.
- After enabling `datasetSearchUsingExtensionQuery`, input simplified query terms such as "project approval", confirm that annual investment plan documents that would normally require full vocabulary matching can be recalled.
