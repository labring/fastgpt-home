# Internal Office and Employee Services for Investment Project Approval and Post-Evaluation: Deployment and Upgrade

## What Data for This Category Looks Like
Data sources for this category include the state-owned asset supervision and investment regulatory system, enterprise ERP and project management systems, industry market data, audit and financial statements. Daily processed documents cover annual investment plans, project proposals, feasibility study reports, due diligence reports, asset appraisal reports, and post-investment evaluation reports. Data is updated on a quarterly basis. Core fields focus on project investment-related parameters, progress milestones, and post-investment management data. Different documents have dedicated fields: for example, feasibility study reports include technical demonstration content, and post-investment evaluation reports include operational tracking data.

## Constraints Imposed by Data Characteristics on Deployment and Upgrade
For FastGPT v4.17.0 deployments, the data characteristics of this category create the following constraints. Data sources for this category are scattered and involve state-owned asset regulatory systems. Deployments must support integration with multi-source heterogeneous data, and database connection parameters must be clearly configured. The quarterly data update rhythm requires scheduled synchronization tasks to avoid data lag that impacts business decisions. The need to process multiple types of specialized documents requires configuring parsing rules adapted to different document structures, and sufficient storage capacity must be reserved. Because errors may lead to serious issues such as loss of state-owned assets, deployment links must include permission control and complete log retention mechanisms to ensure operational traceability. Additionally, the multi-department collaborative office scenario requires configuring reasonable concurrent connection parameters to avoid system lag.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `jdbc:postgresql://<host>:5432/investment_project?currentSchema=public` | Standard PostgreSQL connection format for integrating enterprise ERP and project management systems, adapted to structured business data storage for this category |
| `MONGODB_URI` | `mongodb://<user>:<pass>@<host>:27017/investment?authSource=admin` | Meets unstructured document storage requirements for integrating the state-owned asset supervision and investment regulatory system, supports metadata management for multiple types of reports |
| `STORAGE_S3_ENDPOINT` | `https://s3.<region>.cloud.com, reserved storage capacity of no less than 1000 MB` | Adapts to storage of large volumes of specialized documents updated quarterly, must configure object storage endpoints compliant with enterprise compliance requirements |
| `REDIS_URL` | `redis://:<pass>@<host>:6379/0, set timeout to 600 seconds` | Caches parsed results of project documents and temporary data from investment review meeting materials to improve access efficiency |
| `ROOT_KEY` | `Randomly generated 32-bit string` | Ensures permission security for background system operations, prevents unauthorized access to state-owned asset-related business data |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent access demands from multiple departments accessing project data, avoids exhausting database connections |

## Three Common Configuration Mistakes
- Symptom: After installing the Doc2X system plugin, a permission verification failure error is returned, and professional investment documents cannot be parsed. Cause: File parsing-related keys are not configured, or parameters do not match, leading to failed file parsing permission verification.
- Symptom: Pulling the specified version of the Docker image fails, and deployment or upgrade cannot be completed. Cause: Correct image repository access permissions are not configured, or the network environment cannot access the official image source, leading to image pull timeout.
- Symptom: The project material page shared without login on the overseas SaaS version does not respond properly. Cause: Correct frontend access domain name is not configured, leading to failure to load frontend resources and inability to render the page normally.

## How to Verify Configuration Is Successful
- Run a database connection test command to verify whether the `PG_URL` and `MONGODB_URI` configurations can successfully connect to the business system.
- Upload a standard feasibility study report to check whether file parsing works normally, and confirm that the `STORAGE_S3_ENDPOINT` storage configuration is effective.
- Attempt to create a background operation session to verify whether the `ROOT_KEY` permission configuration is effective, preventing unauthorized access.
- After adjusting the `DB_MAX_LINK` configuration, simulate concurrent access by multiple users to confirm that database connections do not experience abnormal exhaustion.
