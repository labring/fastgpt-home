# Internal Office and Employee Services for Tendering and Procurement Compliance Management: Tool Calling and Plugins
This document applies to FastGPT v4.17.0.

## What Data for This Category Looks Like
Data sources for this category include enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue repositories. Data updates occur daily.
Common daily documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance documents, and supplier complaint materials.
Corresponding fields for each document include procurement method, budget amount, scoring method, supplier qualification conditions, and performance acceptance standards. There are no unified format requirements. The system must adapt to different data structures exported from multiple systems.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Decentralized data sources and inconsistent formats require tool calling to adapt to interface formats of multiple data sources. This prevents verification failures caused by data structure differences.
Daily updated data sources require tool calling to support real-time pulling of the latest compliance basis. This ensures verification results align with current requirements.
The most time-consuming compliance verification step involves comparing fields across multiple documents. Tool calling must automatically pull key fields from corresponding documents. This reduces manual verification workload.
Sensitive compliance data requires strict access restrictions. Plugin calling must only access specified internal data sources. This avoids data leakage risks.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapts to needs of automatically matching tools for tendering and procurement scenarios, such as compliance verification and supplier qualification review. No manual tool specification is required. |
| `functionCall` | enabled | Requires pulling field data from compliance-related documents including procurement plans and bidding documents via function calls. This completes automatic verification. |
| Tool call timeout | 600 seconds | Tendering and procurement compliance verification requires pulling historical data from multiple systems. A longer timeout prevents verification failures caused by incomplete data pulls. |
| Tool call result count limit | Top 8-12 entries | Must cover major compliance basis documents. Too many results increase context load. Too few results fail to cover complete verification logic. |
| Plugin call data source scope | Specified internal data sources including enterprise procurement platforms and public resource trading platforms | Tendering and procurement compliance data is internal sensitive information. Restricting data source scope prevents data leakage. |
| Parameter extraction verification | Enabled | Parameters such as procurement method and budget amount for tendering and procurement must strictly match preset rules. This avoids compliance risks caused by extraction errors. |

## Three Common Configuration Errors
- When calling a custom compliance verification plugin, the response returns "plugin configuration not found". The cause is that the interface address and permissions for the corresponding plugin have not been uploaded or configured on the FastGPT platform. The plugin registration process has not been completed.
- When calling a compliance data interface with an application key, a 403 permission error is returned. The cause is that the data source access permissions for the plugin have not been configured. Or the application key is not bound to access permissions for the corresponding procurement system. This violates internal data security rules.
- The procurement method parameter pulled via tool calling is empty. The cause is that the parameter extraction verification configuration has not been enabled. Or the pulled field does not match the corresponding field in the procurement plan document. This prevents valid data from being obtained.

## How to Verify Configuration Completion
- Upload a simulated bidding document in the test environment. Trigger the tool calling flow. Confirm that the compliance verification tool is automatically matched.
- Call the plugin to pull procurement plan data. Confirm that the returned results include preset fields such as budget and procurement method. Verify that the results comply with data source scope restrictions.
- Adjust the tool call timeout. Simulate a large data pull scenario. Confirm that the return is completed within the preset time. No timeout errors occur.
- Enable the parameter extraction verification function. Input parameters that do not comply with procurement rules. Confirm that a verification prompt is triggered. This meets compliance requirements.
