# Internal Office and Employee Services for Tendering and Procurement Compliance Management: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes primarily from enterprise procurement platforms, public resource trading platforms, supplier databases, contract management systems, and audit issue databases. Update frequency is daily.
Daily processed documents include procurement plans, requirement specifications, bidding documents, bid evaluation records, contracts, acceptance receipts, and supplier complaint materials.
Core fields cover procurement methods, budget basis, scoring methods, supplier qualification requirements, and contract performance clauses.
The data structure is built to support compliance review needs across the full tendering and procurement workflow, covering procurement initiation, bid evaluation, performance, and audit stages.

## Constraints imposed during deployment and upgrade
Decentralized daily data sources require interface connection configuration adapted to multiple systems, to ensure stable data synchronization.
Diverse daily document formats require pre-configured parsing rules, to avoid parsing failures disrupting compliance review workflows.
Compliance check logic for core fields must align with the enterprise’s existing procurement regulations.
During upgrades, compatibility with original check rules must be maintained, to prevent interruptions to existing compliance workflows from version updates.
For multi-department collaboration scenarios, multi-account permission tiering must be configured to meet access requirements for roles including procurement centers, bidding offices, business departments, and audit and discipline inspection teams.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Dedicated instance address for connecting to the enterprise’s internal compliance procurement database | Isolate sensitive tendering and procurement data, avoid mixed storage with other business data |
| `PG_URL` | Address of the PostgreSQL instance used to store compliance check rules | Store static compliance rules such as procurement methods and scoring methods, to support fast retrieval |
| `DB_MAX_LINK` | Set to 150–200 concurrent connections | Adapt to daily high-frequency compliance data query requests, avoid connection exhaustion |
| `REDIS_URL` | Redis instance deployed in the internal private network, with cache duration set to 86400 seconds | Cache daily updated supplier database and public trading data, reduce repeated query overhead |
| `STORAGE_S3_ENDPOINT` | Access address for the enterprise’s internal object storage service | Store large compliance documents such as bidding documents and bid evaluation records, meet data retention requirements |
| `FILE_TOKEN_KEY` | Encryption key aligned with the internal document system | Ensure data security for uploaded procurement documents during transmission and storage |

## Three Common Mistakes
- After upgrading to FastGPT v4.17.0, the speech transcription function prompts a POST /v1/audio/transcriptions HTTP error. The cause is that the default audio processing module configuration was reset after the version upgrade, and the access parameters for the original Whisper model were not retained.
- The multi-account login function for local deployments cannot function properly, and only administrators can access the knowledge base upload function. The cause is that access rules for corresponding permission tiering were not configured, and the single-account permission restriction mode was enabled by default.
- The import and export application function encounters an exception where fields are empty. The cause is that the upgrade process did not maintain compatibility with the application configuration structure from older versions, resulting in the loss of configuration items for some compliance rules.

## How to Confirm Configuration Is Complete
- Access the domain configured via `FE_DOMAIN`, log in, and check the synchronization status of compliance data to confirm that daily updated supplier database data has loaded normally.
- Initiate a simulated procurement plan check request to verify whether the compliance rule library configured via `PG_URL` can correctly return matching results for procurement methods and budget basis.
- Upload a bidding document to the system to check whether the storage service configured via `STORAGE_S3_ENDPOINT` can receive and store the document normally.
- Attempt to use a super administrator account to modify compliance rules to verify whether the key configured via `ROOT_KEY` can restrict unauthorized modification operations.
