# Internal Office and Employee Services for Student Enrollment and Student Status Management: Vector Models and Indexing

## What Data Looks Like for This Category
Service entities include basic education departments of education bureaus, school academic affairs offices, enrollment examination institutions, and street community collaborative windows. Data is sourced from the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic affairs systems. The update frequency is daily. Daily processed documents include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, and student status change approval forms. Core data fields center on student identity identifiers, household registration and residence information, admission eligibility, and student status change status.

## What Constraints These Characteristics Impose on Vector Models and Indexing
Daily updated data requires indexes to support incremental synchronization, avoiding performance loss and resource usage caused by full reconstruction. Mixed multi-type document scenarios require adapting chunking rules for structured table fields and unstructured text, avoiding splitting critical identity information. Fields centered on student identity and household registration eligibility require vector models to prioritize encoding relevant text, ensuring retrieval matching accuracy. Time-consuming household registration and property verification, student status change processing links correspond to retrieval latency requirements, requiring a balance between recall efficiency and result completeness.

## How to Configure Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the text length of student status tables and application materials, avoids losing critical identity information during chunking |
| Overlap Length | 100–150 characters | Covers student status change descriptions across chunks, ensures relevant content is not missed during retrieval |
| `defaultToken` | 8192 | Adapts to long-text encoding of enrollment policy documents, meets context requirements of general large models |
| `maxToken` | 4096 | Limits the context length of a single retrieval result, avoids excessive resource usage by indexes |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Meets accuracy requirements for matching student identity fields, filters low-correlation household registration and property data |
| Single Search Limit | Top 10 entries | Balances retrieval efficiency and recall completeness, adapts to daily office verification scenarios |

## Three Common Misconfigurations
- Vector retrieval scores are completely identical with no differing results after Docker image deployment. The vector database persistent storage directory was not correctly mounted in the image, causing index files to fail to load properly, and only default empty vector matching is used.
- Index construction tasks remain stuck on processing the final set of documents with no progress updates. The breakpoint resume mechanism for incremental indexing was not configured, and recovery fails after an out-of-memory interruption during full processing of large-volume student status data.
- Hybrid retrieval response time exceeds 10 seconds, with no clear timeout error for single requests. Full recall was enabled for both full-text and vector retrieval, and the number of returned entries for single-modal retrieval was not limited, leading to excessive computing resource usage.

## How to Verify Successful Configuration
- Upload a single student status information form, perform vector retrieval, and verify that returned results include the target student's identity fields, confirming chunking and encoding rules are active.
- Simulate daily incremental update document uploads, check that indexes only synchronize new entries with no full reconstruction log prompts, confirming incremental configuration is active.
- Initiate a retrieval containing household registration and student status keywords, check that response time meets expected thresholds, confirming similarity threshold and single search limit configurations are reasonable.
- Check the Docker deployment container's mounted directory, confirm that vector index files exist and are not cleared, confirming persistent configuration is active.
