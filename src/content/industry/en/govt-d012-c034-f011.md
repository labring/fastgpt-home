# Internal Office and Employee Services for Enrollment and Student Status Management: Forms and Interactions

## What the data for this category looks like
Daily documents for this category include enrollment application forms, student status information forms, transfer applications, enrollment plans, admission rosters, student status change approval forms, and more. Fields cover student identity identifiers, residence certificate numbers, student status numbers, change application types, and other items. Data sources are the National Primary and Secondary School Student Status Management System, local enrollment platforms, household registration and property data, and school academic administration systems, updated once daily. Most document structures are structured templates with fixed fields; some require cross-system data splicing to complete filling.

## What constraints these characteristics impose on the forms and interactions link
Cross-system data sources require forms to support multi-data source linkage verification to avoid manual entry errors. The daily update frequency means form cached data must be synchronized daily to ensure information timeliness. Fixed-field document structures require forms to pre-configure required fields and format verification rules to prevent missing entries or format errors. The high severity of business errors requires adding duplicate verification and approval confirmation steps in the interaction link to avoid duplicate or missing student status records. Additionally, this category focuses on the core of student status flow, so forms and interactions must avoid irrelevant fields and focus on the business logic linking identity and student status.

## How to set configurations
All following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` field verification rules | Bind format verification for ID numbers and student status numbers | Match the format requirements for identity and student status identifier fields in daily documents |
| Data source linkage configuration | Link interfaces of the National Primary and Secondary School Student Status Management System and local enrollment platforms | Connect specified data sources to complete real-time verification |
| Interaction timeout setting | 30–60 seconds | Adapt to the response duration of cross-system data retrieval |
| `userSelect` option set | Pre-set three scenarios: enrollment application, student status change, policy consultation | Match the core business scenarios of daily office work |
| Multi-turn context limit | First 2–4 rounds of dialogue | Avoid redundant data occupying context space, focus on current business processes |
| Push trigger configuration | Trigger when form submission is completed or student status change approval is passed | Match the node requirements of business processes |

## Three common configuration mistakes
- Active push message failure and inability to connect subsequent question-and-answer interaction: The interface shows no response after push is triggered, and question-and-answer interaction is interrupted. The cause is failure to configure linkage trigger rules for `userSelect` scenarios and failure to bind push logic for business nodes.
- Error when uploading structured documents: The interface pops up `failed to create post p` type error. The cause is failure to perform field splitting preprocessing on documents such as enrollment application forms and student status information forms, leading to abnormal text block generation.
- Unable to complete information entry when the browser does not support voice input: Form fields cannot be filled via voice. The cause is failure to add text quick input options in the `formInput` configuration and failure to adapt to non-voice input scenarios.

## How to confirm the configuration is complete
- Test `formInput` field verification: Enter an ID number or student status number that does not meet the format requirements, confirm that the interface pops up a format error prompt.
- Test data source linkage: Enter a known student status number, confirm that the system automatically pulls associated information from the corresponding enrollment platform.
- Test push trigger: Complete a transfer application submission, confirm that the corresponding employee account receives a push message.
- Test `userSelect` options: Select the policy consultation scenario, confirm that the system returns question-and-answer content corresponding to enrollment policies.
