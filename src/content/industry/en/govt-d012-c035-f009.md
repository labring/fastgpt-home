# Internal Office and Employee Services for Pollution Discharge Permit Management: Model Access and Configuration

## What the data for this category looks like
The data for this category mainly comes from the national pollution discharge permit management information platform, corporate environmental protection ledgers, online monitoring systems, and environmental statistics systems. The update frequency is quarterly. Daily processed documents include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. These documents contain professional fields such as permit limits, discharge port codes, monitoring frequencies, and pollutant types. Units include environmental monitoring-specific units such as mg/L, cubic meters per hour, and tons per year.

## Constraints imposed on model access and configuration
Multiple heterogeneous data sources require models to adapt to different document formats and interface data. Quarterly data updates require configuring sufficient context windows to cover complete historical quarterly data. Diverse document structures require adjusting content parsing logic for different types of permit documents. Professional environmental fields require models to understand industry terminology to avoid compliance judgment deviations. The most time-consuming daily tasks, such as verifying industry technical specifications and reviewing ledgers, require models to efficiently call tools for automated processing. Strict regulatory requirements for pollution discharge permit management also require configuring reliable tool calling and result verification mechanisms to ensure data processing accuracy.

## How to set configurations
This document is based on the FastGPT v4.17.0 configuration specification.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the total length of quarterly updated multi-source documents, avoids truncating key permit limits and ledger data |
| `temperature` | 0.1–0.3 | Ensures consistency in professional terminology interpretation and compliance judgments, reduces compliance judgment deviations |
| `toolChoice` | auto | Automatically triggers tool calls to handle ledger verification, data extraction and other tasks, adapts to multi-link audit requirements for pollution discharge permits |
| `AIPROXY_API_ENDPOINT` | Configured per deployment node | Adapts to internal network access permissions, ensures data transmission complies with data security requirements of ecological environment authorities |
| `AIPROXY_API_TOKEN` | Assigned based on role permissions | Differentiates calling permissions between management and execution positions, complies with internal office permission control requirements |

## Three common configuration errors
- Incomplete response when parsing pollution discharge permit ledger Excel files. Cause: Insufficient context window configured for professional long texts in pollution discharge permit documents, leading to truncation of key permit limits and ledger data.
- Locally deployed models cannot be used after being added. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to point to the access address of the locally deployed node, or a valid `AIPROXY_API_TOKEN` for identity verification is not configured.
- Gemini models cannot trigger tool calls. Cause: `toolChoice` is not set to auto, or function call rules compliant with the model requirements are not specified, resulting in the model not automatically calling ledger verification tools to complete audits.

## How to confirm correct configuration
- Upload a single copy of the pollution discharge permit copy document, check whether the field extraction results returned by the model cover core information such as permit limits and discharge ports. Adjust the value range of relevant parameters based on extraction accuracy.
- Call the configured model interface, verify that the configurations of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` can establish a normal connection, with no timeout or permission error prompts.
- After setting `toolChoice` to auto, submit a query containing multiple ledger data sets, check whether the model automatically triggers tool calls to complete data verification, with no unresponsive or error prompts.
- Import a quarterly updated multi-source document package, check whether `maxContext` can load all content completely, with no text truncation.
