# Internal Office and Employee Services for Pollution Discharge Permit Management: Knowledge Base Retrieval and Recall

## What this category of data includes
This category of data covers full lifecycle documents related to pollution discharge permit management. These include pollution discharge permit application forms, implementation reports, self-monitoring plans, ledger records, change applications, and permit copies. Data sources include the national pollution discharge permit management information platform, enterprise environmental protection ledgers, online monitoring systems, and environmental statistics systems. Updates occur on a quarterly basis.

The platform organizes documents into modules such as permit clauses, implementation limit requirements, ledger filling specifications, and change processes. Documents include dedicated fields like emission concentration limits, monitoring frequencies, and ledger retention periods. No universal standard units apply to these fields. Some fields must align with the technical specification standards of the corresponding industry.

## Constraints on knowledge base retrieval and recall
The characteristics of this category of data impose multiple constraints on retrieval and recall workflows. Multi-source and heterogeneous data sources include real-time online monitoring data, quarterly updated ledgers, and static permit documents. This requires support for mixed recall across multiple scenarios.

Quarterly batch-updated documents need incremental deduplication logic. This logic prevents redundant data from occupying storage. Documents are organized into modules such as permit clauses and implementation requirements. This organization must match the scenario-based search intentions of personnel in relevant positions.

Dedicated fields have no universal units. This requirement avoids result deviations caused by fuzzy matching. The high-risk nature of compliance audits demands that recall results have sufficient accuracy to support decision-making.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0. They are adapted to the exclusive data characteristics of pollution discharge permit management.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.6–0.7 | Pollution discharge permit data has many dedicated fields. This threshold filters low-relevance results and avoids interference from invalid information during compliance audits. |
| `limit` | Top 8–12 entries | Single permit documents have large content volumes. Too many results will exceed context limits, while this range ensures coverage of compliance requirements across different modules. |
| `searchMode` | `vector+keyword` | The data includes structured fields and unstructured documents. Mixed retrieval balances semantic matching and precise keyword recall. |
| `usingReRank` | Enabled | Recall results from multi-source data require secondary sorting. This raises the priority of high-compliance-relevant content. |
| `datasetSearchUsingExtensionQuery` | Enabled | Searches from personnel in relevant positions may use colloquial expressions. Expanded queries match standard expressions in documents. |
| `collectionIds` | Divide collections by document type, such as "permit copies", "implementation reports", "ledger templates" | This allows targeted retrieval of documents for corresponding business scenarios and narrows the recall scope. |

## Three Common Configuration Errors
- Interface search test results do not display the target self-monitoring plan document. The cause is either the `similarity` threshold set too high, or `datasetSearchUsingExtensionQuery` not enabled. This prevents matching colloquial search terms with standard expressions in documents.
- Duplicate pollution discharge permit copy entries exist in the knowledge base. The cause is failure to enable deduplication verification during batch import of quarterly updated data. This leads to repeated storage of multiple versions of the same document.
- Retrieved results do not match the query intent. The cause is either `usingReRank` not enabled, or `searchMode` only using vector retrieval without combining keyword matching for structured permit limit fields.

## How to Confirm Proper Configuration
- Run a single compliance query, such as verifying emission limits for a specific industry. Check if recall results include documents with the corresponding permit clauses.
- After importing quarterly updated ledger documents, verify the change in document count in the knowledge base. Confirm that only newly added, previously unstored versions are included, and that deduplication logic is active.
- Adjust the `similarity` threshold. Compare recall results across different thresholds to confirm alignment with accuracy requirements for the business scenario.
- View retrieval logs to confirm that mixed retrieval mode and reranking function have triggered normally, with no error prompts.
