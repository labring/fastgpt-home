# Internal Office and Employee Services for Government Service Item Catalog and Service Guide Maintenance: Model Access and Configuration

## What the data for this category looks like
The national basic directory of government service items, administrative licensing item list, power and responsibility list, and local government service item databases supply daily data for government service item catalog and service guide maintenance. Data updates occur monthly. Daily documents include the basic directory of government service items, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions. Data fields contain standardized official content such as item codes, implementation levels, acceptance conditions, application material lists, and service processes, with no custom non-official fields.

## What constraints these characteristics impose on the "model access and configuration" link
Official standardized directories provide all data for government service item catalogs and service guide maintenance. Model outputs must strictly align with official fields, and no arbitrary addition or modification of content is allowed. The monthly update frequency mandates that configurations support scheduled knowledge base synchronization tasks to ensure models use the latest government data. Diverse document types and lengthy content require adaptation of long context processing capabilities to avoid truncating key fields such as item codes and implementation levels. Comparison and verification are core time-consuming links, so configurations require stable, accurate model calls to reduce manual revision workload.

## How to set the configuration
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the long context comparison requirements of government documents, avoids truncating key fields such as item codes and implementation levels. FastGPT v4.17.0 supports this parameter configuration |
| `maxTokens` | 2000–3000 token | Used to generate service guide verification results, ensuring the output includes complete field verification items and comparison conclusions |
| `quoteMaxToken` | 1500 token | Matches standard material directory fragments of government documents, ensuring the integrity and accuracy of referenced content |
| `temperature` | 0.1–0.3 | Reduces random output deviations, ensuring item comparison results are consistent with official directories, avoiding the risk of inconsistent service standards |
| `toolChoice` | auto | Automatically selects tools to handle tasks such as field verification and directory comparison, adapting to complex processing requirements for multiple types of government documents |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployment environment | Adapts to API access paths for local or cloud deployments, ensuring normal model calls |

## Three common configuration errors
- DingTalk robot publishing prompts message address verification failure: The cause is that the public network access address of the FastGPT deployment was not correctly filled in the callback configuration of the DingTalk robot, resulting in verification failure.
- The Deepseek model is configured for the application but Qianwen is actually called: The cause is that the binding parameters of the model channel did not correctly override the default configuration, or there was an error in the association between the API key and the endpoint.
- An error occurs when calling the model with a locally deployed Ollama: The cause is that the model call endpoint and key were not correctly configured, or the chunk parameters do not match the model input length limit of Ollama.

## How to confirm the configuration is complete
- Call the model to test the item comparison task, check whether the output fields are consistent with the official directory with no random deviations.
- View the model call logs to confirm that the actual values of parameters such as `maxContext` and `maxTokens` meet the configuration requirements.
- Test the callback interface of the DingTalk robot to verify whether the message address verification passes with no connection errors.
- After completing the monthly government catalog data synchronization, check whether the verification report generated by the model includes complete field verification items and comparison conclusions.
