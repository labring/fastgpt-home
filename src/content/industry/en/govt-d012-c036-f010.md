# Internal Office and Employee Services for Government Service Item Catalog and Service Guide Maintenance: Knowledge Base Retrieval and Recall

## What Data for This Specialized Category Looks Like
Daily documents for this specialized category include basic government service item catalogs, implementation lists, service guides, standard material directories, flowcharts, and frequently asked questions.
This data primarily comes from the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases. The update frequency is typically once per month.
Most documents consist of structured field content, including standardized fields such as item code, implementing entity, acceptance conditions, application material list, handling process, and more. There are no additional custom non-standard fields. Some documents have cross-level hierarchical association relationships.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
The data characteristics of this category impose multiple constraints on retrieval and recall.
The authority of official data sources requires retrieval results to match the latest released government item versions. Strict association with monthly updated official database sources is required, and expired data must be avoided.
The monthly batch update rhythm requires the knowledge base synchronization process to adapt to fixed-cycle full or incremental imports, reducing unnecessary resource consumption.
There are many structured fields and hierarchical associations. Retrieval must support precise filtering by fields such as item code and implementing entity, while avoiding accidental recall of irrelevant cross-level content.
The consistency requirement for standardized fields ensures that returned entries include complete core fields such as acceptance conditions and application materials. This prevents internal operational deviations caused by missing key information.

## Three Common Mistakes
- Phenomenon: Custom-split service guide document chunks are automatically deduplicated by the system. The original index order does not match the order of returned retrieved chunks. Cause: The knowledge base's default duplicate document filtering function is not disabled, or the unique identifier field is not retained when splitting documents. This causes the system to disrupt chunk order when deduplicating via content hash.
- Phenomenon: After deploying FastGPT from source code and connecting to a Docker-deployed database, knowledge base entries are not displayed synchronously. Cause: Correct database connection parameters are not specified in the configuration file, or the database initialization script is not executed to synchronize existing data. This causes the system to fail to read knowledge base content from the database.
- Phenomenon: Retrieval results return irrelevant entries with semantic similarity lower than the preset range or abnormal full-text search scores, such as results containing non-local-level government service items. Cause: The `similarity` threshold is not adjusted according to the standardized fields of government service items, or `searchMode` is not configured as hybrid mode. This causes a single retrieval dimension to fail to filter low-correlation content.

## How to Confirm Proper Configuration
- View the knowledge base configuration interface of FastGPT v4.17.0. Confirm that `collectionIds` only associates with the dedicated government service item catalog dataset, and no cross-category data is mixed in.
- Initiate a single test retrieval request, such as "Application material list for handling enterprise establishment registration". Check whether the `similarity` score of returned results meets the preset range, and whether entries include standardized fields.
- Trigger the monthly data update process. Confirm that the knowledge base automatically synchronizes the latest national government service catalog content, and no expired entries remain.
- Enable retrieval logs. Check whether the number of returned results matches the preset `limit` parameter value, and confirm that the single-round retrieval upper limit is not exceeded.
