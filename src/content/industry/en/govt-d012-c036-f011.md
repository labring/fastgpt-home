# Internal Office and Employee Services for Government Service Item Catalog and Service Guide Maintenance: Forms and Interactions

## What the data for this category looks like
The core documents for this category include basic government service item catalogs, implementation lists, service guides, standard material catalogs, flowcharts, and frequently asked questions. Data is typically sourced from the national basic government service item catalog, administrative licensing item list, power and responsibility list, and local government service item databases, with a monthly update frequency. Each individual item document includes standardized fields such as item code, item name, acceptance conditions, application material list, and handling process. Some fields must match the unified coding rules of the superior catalog, and the material list must clearly specify the form, quantity, and submission requirements for each material.

## What Constraints These Characteristics Impose on Forms and Interactions
The cross-level nature of data sources requires forms to support multi-source data comparison and verification, to avoid inconsistencies between local-level items and superior catalog codes. The monthly update rhythm requires forms to support batch import and incremental updates, reducing the workload of repeated manual entry. The standardized field requirements mandate mandatory verification for core fields such as acceptance conditions and application materials, to ensure the completeness of service guide fields. At the same time, item documents from different departments have minor field differences, so forms must support custom field mapping to adapt to the local management needs of each entity. FastGPT v4.17.0 form configuration can adapt to the above constraints.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Form input validation rules | Enforce validation for item codes and application material quantities; codes must match the format of 6-digit administrative division code + 8-digit sequence code | Based on the unified specifications of national government service item coding, to ensure item uniqueness |
| Batch import template | Preset standard template, maximum 1000 entries per import, support custom field expansion | Adapt to the batch data import requirements of monthly updates, reduce format errors |
| Field mapping configuration | Map superior catalog fields to local management fields, retain the default 1:1 mapping option | Resolve field differences between data at different levels |
| `formInput` timeout setting | 600 seconds | Adapt to long-text entry for acceptance conditions and service guide content |
| `userSelect` multi-select limit | Top 10 entries | Limit the number of superior catalog items or associated knowledge base entries selected in a single operation, avoid overload from batch operations |
| Form submission validation | Trigger field completeness verification and return a list of failed items | Ensure submitted item documents meet basic format requirements |

## Three Common Configuration Mistakes
- After entering long text in a form, page zoom causes content loss. The symptom is that the displayed text content on the interface is cleared with no error prompt. The cause is that the local caching mechanism for `formInput` is not configured, so user-entered long text is not retained when page zoom triggers redraw.
- Field completeness verification is not enabled, resulting in submission of incomplete item data. The symptom is that the submission only prompts a successful save, but acceptance conditions or application material fields are missing. The cause is that the mandatory validation rules for the form are not enabled, so incomplete entered content is not intercepted.
- Multiple associated knowledge bases cannot be selected for item verification. The symptom is that only a single knowledge base can be selected when configuring verification rules, and multiple superior catalog knowledge bases cannot be associated in batches. The cause is that the multi-select limit configuration for `userSelect` is not adjusted, limiting the number of associated knowledge bases.

## How to Verify Successful Configuration
- Manually enter an acceptance condition text exceeding 500 characters, zoom the page, and check if the text is fully retained.
- Submit a test item missing the application material field, and check if specific prompts for missing fields are returned.
- Set the `userSelect` multi-select limit to top 10 entries, attempt to select 11 superior catalog knowledge bases, and check if a quantity limit prompt is triggered.
- Import a correctly formatted test item template, and check if the imported data fully matches the preset field mapping rules.

The values provided are common starting points and should be evaluated against your own specific samples.
