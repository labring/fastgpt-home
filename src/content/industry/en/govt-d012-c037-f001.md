# Internal Office and Employee Services for Government Information Application-Based Disclosure: HTTP Interfaces and External Systems

## Data Details for This Category
This category’s data sources include government information disclosure platforms, agency archive systems, document management systems, departmental business ledgers, and government information disclosure-related specifications. Updates occur irregularly, synchronized with the processing progress of individual applications. Daily processed documents include government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, reply letters, service receipts, and administrative reconsideration response materials. Each document carries fields such as a unique business identifier, applicant information, required information description, reply opinion, and processing status. Individual documents serve as the basic statistical unit.

## Constraints for HTTP Interfaces and External Systems
Scattered data sources and irregular update cycles require HTTP interfaces to support on-demand pulling of data from multiple systems. This adaptation supports temporary application processing scenarios. Business documents of different types have large field differences, so interfaces must support flexible field mapping rules to match various document return formats. Links such as retrieving requested information and judging disclosure attributes take significant time. Interfaces must reserve sufficient response time to avoid processing delays from timeouts. Interfaces must also include reliable identity authentication capabilities to secure access to government data.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {government internal system API key}` | Complies with government system identity authentication specifications to ensure interface access security |
| `variables` | `{"applyId": "example value", "deptCode": "example value"}` | Passes the unique identifier of the current application and the processing department code to accurately match corresponding business data |
| `responseData` | `Only return core fields of application forms and reply letters` | Reduces data transmission volume to meet lightweight call requirements of internal office systems |
| Timeout period | `600 seconds` | Processing application-based disclosure requires cross-system data retrieval, so reserve sufficient response time |
| Maximum data per single request | `First 20 items` | The number of documents associated with a single application is limited to avoid loading redundant data |
| Response data format | `JSON format` | Adapts to FastGPT's context parsing logic for easy subsequent processing |

## Common Configuration Mistakes
- AI answers do not show document sources after interface calls. The symptom is missing archive numbers or application numbers from document sources in the answer. The cause: The document source field returned in `responseData` is not bound to context variables, so source information cannot be added to the answer.
- Interface calls frequently time out. The symptom is returning a 504 status code or timeout error. The cause: A reasonable timeout period is not set, and the default duration is insufficient for cross-system data retrieval.
- Authentication fails. The symptom is returning a 401 Unauthorized status code. The cause: The `Authorization` parameter uses an incorrect format, and the Bearer token format required by government internal systems is not used.

## How to Confirm Correct Configuration
- Call the test interface, check that the request header carries the `Authorization` parameter in the correct format, and confirm a 200 return status code.
- Review fields returned in `responseData`, confirm they include the current application’s unique identifier and core reply letter content matching the test application number.
- Verify that the `variables` parameter passes the correct department code, and confirm the interface returns business data for the corresponding department.
- Simulate a long-duration request, confirm the interface returns valid data within `600 seconds` without timeout errors.

The values provided are common starting points and should be measured against the reader's own samples.
