# Internal Office and Employee Services for Government Information Disclosure Upon Application: Tool Calling and Plugins

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
Data for this category originates from daily operations of government offices, government disclosure offices, legal affairs divisions, archives departments, and similar entities. It includes standardized documents such as government information disclosure application forms, supplementary notice letters, third-party opinion solicitation letters, reply letters, service receipts, administrative reconsideration response materials, and more. Fields cover applicant information, application content, basis for judging public attribute, description of relief channels, and related content. Data sources include government information disclosure platforms, official archive systems, document management systems, departmental business ledgers, and government disclosure-related specifications. The update frequency is irregular; new data is generated when individual application cases are processed, with no fixed batch update cycle.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The multi-source, scattered data sources require tool calling to pull information across multiple internal systems, to avoid incomplete data caused by relying solely on a single knowledge base. The individualized application documents and dynamic update nature mean tools must accurately match fields based on specific application content, as general-purpose templates cannot cover all scenarios. The most time-consuming steps of retrieving application information, judging public attributes, and drafting reply letters must be automated via tool calling to reduce manual operation costs. At the same time, errors are directly linked to administrative reconsideration and judicial correction, so tool calling must include failure retry and exception reporting mechanisms to avoid process interruptions that lead to overdue deadlines.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Sorted by business priority | Adapts to the business logic of information retrieval, compliance verification, and reply generation, ensuring tool calling order follows government service procedures |
| Single tool call timeout | 600 seconds | Adapts to cross-system response delays common in government organizations, avoiding call failures due to slow system responses |
| Context retention length | 8000–12000 token | Covers complete business context including application materials, historical replies, compliance basis, and other critical content, preventing loss of key information |
| `functionCall` | Forced sequential calling | Ensures application-related information is retrieved first, followed by public attribute verification, and compliant reply letters are generated last |
| Tool call retry count | 2 times | Addresses temporary network fluctuations or system busy periods during cross-system calls, reducing process interruptions caused by single call failures |
| Multi-tool call mode | Calibrated based on actual testing | Adapts to system connection complexity across different departments, flexibly adjusting parallel or serial tool calling logic |

## Three common configuration mistakes
- Phenomenon: Context is cleared after tool calling, making application materials and historical data unavailable. Cause: Context retention rules are not configured correctly, causing conversation context to reset each time a tool is called.
- Phenomenon: Tool calling order is chaotic, with reply letters generated before application information is retrieved. Cause: `toolChoice` is not set to sort by business priority or use forced sequential calling, causing tool calling logic to deviate from government service procedures.
- Phenomenon: FastGPT service fails to start. Cause: Service address and port parameters for the plugin configuration are not updated synchronously after upgrading FastGPT-MCP-Server, preventing the system from connecting to the plugin service normally.

## How to confirm the configuration is complete
- Submit a simulated government disclosure application, check tool calling logs to confirm retrieval, compliance verification, and reply generation tools are triggered in the preset order.
- Check the conversation context panel to confirm key business data such as application materials, historical replies, and compliance basis is fully retained.
- Simulate a tool call failure scenario to verify the system triggers the retry mechanism and that retry counts match the configured value.
- Verify plugin connection status to confirm required documents can be pulled from specified data sources including official archive systems and document management systems.
