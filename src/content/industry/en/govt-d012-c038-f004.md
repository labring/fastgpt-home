# Internal Office and Employee Services for Government Procurement Projects: Workflow Orchestration

## What the Data for This Category Looks Like
This category's data primarily originates from national government procurement websites, local government procurement websites, the fiscal integration system, the purchaser’s budget system, and supplier credit records. The update frequency is daily.
Daily processed documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and responses to objections. Each single document contains structured fields such as project numbers, supplier qualifications, and evaluation criteria, alongside unstructured text content, covering all stages of the full procurement lifecycle.

## Constraints Imposed on Workflow Orchestration by These Characteristics
The data for this category comes from scattered sources and is updated daily. This requires workflows to be configured with multiple system connection nodes to synchronize the latest procurement documents and supplier credit information.
Daily processed document types are diverse and have significant structural differences. Dedicated parsing and chunking rules must be configured for different document types such as procurement requirements and bid evaluation reports.
Core business links are time-consuming, and the consequences of errors are severe. Workflows must include verification nodes to intercept abnormal data and avoid bid invalidation or regulatory penalties.
Supplier credit records need to be obtained in real time. Timed-triggered data source synchronization nodes must be configured to ensure the timeliness of qualification information.

## How to Set the Configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Single search limit | Top 30 entries | Government procurement-related documents have large text volumes per file. This setting controls the redundancy of recall results and avoids context overflow |
| Maximum context length | 8000–12000 characters | Matches the average text length of government procurement documents, ensuring core evaluation and contract information is fully included |
| Node timeout period | 600 seconds | Reserves sufficient time for data pulling and parsing when connecting to external interfaces such as the fiscal integration system |
| `variables` configuration | Bind procurement project number and budget amount fields | Enables automatic data transfer and verification across all stages of the procurement workflow |
| Reranking toggle | Enabled | Sorts recalled government procurement documents by relevance, prioritizing display of core evaluation and qualification information |

## Three Common Misconfigurations
- Phenomenon: When calling the knowledge base search in a workflow, the number of returned results does not match the configured value, and the interface shows limited context length. Cause: The single search limit configuration was not adjusted for the long text characteristics of government procurement documents, and default parameters restrict the effective length of recalled results.
- Phenomenon: After the orchestrated application is published, returned business fields are empty when called via API. Cause: Core fields such as procurement project number were not bound in the `variables` configuration, causing the data source to fail to accurately match document data for the corresponding project. Some node `nodeId` values do not match the call parameters.
- Phenomenon: After uploading procurement-related image or PDF files, the workflow cannot read or parse the content. Cause: The corresponding format processing switch of the file parsing node was not enabled, and file reading permission rules were not configured, causing external API calls to fail to obtain file content.

## How to Verify Successful Configuration
- Manually trigger the knowledge base search node in the workflow, check the number of returned results, and confirm it matches the configured single search limit.
- Connect to the fiscal integration system interface, test the data pulling duration, and confirm it does not exceed the configured node timeout period.
- Call the API test interface, check whether the returned business fields match the bound fields configured in `variables`, and verify that the node `nodeId` values match the call parameters.
- Upload a standard procurement requirement document, and verify that the workflow can correctly parse and extract core procurement-related information.
