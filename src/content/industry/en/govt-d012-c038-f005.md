# Internal Office and Employee Services for Government Procurement Projects: Tool Calling and Plugins

## What the data for this category looks like
Core data for this category comes from the national government procurement website, local government procurement websites, the fiscal integration system, the purchaser’s budget system, and supplier credit record databases. The update frequency is daily. Daily processed documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning announcement notices, procurement contracts, and question and reply responses. Four core stakeholders are involved: purchaser units, the government procurement supervision department of the finance department, procurement agencies, and evaluation experts. Data fields cover key information across the entire procurement process: procurement categories, budget amounts, supplier qualifications, evaluation criteria, and more. Single document length varies by project scale, with no fixed standard.

## What constraints these characteristics impose on the "tool calling and plugins" link
Data sources are scattered and require integration with multiple government systems. Plugins must support unified calling of multiple interfaces and permission verification to prevent cross-system data leaks. The daily update frequency requires tools to pull the latest announcements and credit data on a scheduled basis, ensuring that information used in evaluation and contract links uses the most recent version. The diversity and compliance requirements of document fields require tool calling to strictly match the exclusive fields of procurement projects, avoiding the introduction of irrelevant data that could cause regulatory issues. At the same time, errors can lead to serious risks such as bid invalidation or upheld complaints. Tool calling failure handling must have clear retry and alert mechanisms to ensure that abnormal situations can be intercepted in a timely manner.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `Specify tool whitelist` | Government procurement scenarios require fixed calls to compliance tools such as qualification verification, announcement pulling, and contract verification, to avoid regulatory risks from calling irrelevant tools |
| `functionCall` | `Force matching preset output format` | Documents related to government procurement must meet the format requirements of regulatory authorities. Tool return results must be directly organized into the fields of bid evaluation reports or announcement templates |
| Number of items returned in a single tool call | `Top 6` | The evaluation link only needs to verify the qualifications and credit records of core participating suppliers. Excessive data will increase processing burden |
| Tool call timeout period | `240 seconds` | Interface responses from data sources such as the government procurement website have fluctuations. Sufficient time must be reserved for data pulling and verification |
| Result field filtering | `Only retain fields specified in procurement requirements` | Redundant data unrelated to the current procurement project must be blocked to ensure that output content meets procurement compliance requirements |

## Three common errors
- Phenomenon: HTML format chart content returned by tool calling cannot be displayed normally on the MCP host, and the returned fields are empty. Cause: The format verification rule for `functionCall` is not enabled in the tool configuration, causing FastGPT to fail to correctly identify valid fields of HTML content and unable to transfer them to the MCP host.
- Phenomenon: Supplier credit records obtained through tool calling are directly output to users without desensitization processing. Cause: The result field filtering configuration is not enabled, causing credit records containing sensitive information to be returned directly, which violates government procurement data confidentiality requirements.
- Phenomenon: The AI attempts to call unauthorized tools, the returned results do not meet expectations, and valid knowledge cannot be transferred to the target model. Cause: The tool whitelist is not specified through the `toolChoice` configuration, causing the AI to call irrelevant tools, and the returned invalid data cannot be effectively absorbed by the target model.

## How to confirm that the configuration is correct
- Enter the tool configuration page of FastGPT v4.17.0, check whether `toolChoice` is set to only include tools related to government procurement, and confirm that no irrelevant tools are added to the whitelist.
- Initiate a simulated procurement requirement compilation request, check whether the results returned by tool calling only include the preset procurement project fields, and whether the format meets the basic requirements of regulatory documents.
- Initiate a simulated supplier qualification verification request, confirm that the tool call is completed within 240 seconds, and the number of returned supplier credit records meets the preset top 6 requirement.
- Manually trigger a tool call failure scenario, confirm that the system triggers the preset alert and retry logic, and abnormal situations can be recorded in a timely manner.

The values listed above are common starting points and should be evaluated against the reader's own samples.
