# Internal Office and Employee Services for Government Procurement Projects: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from the national government procurement website, local government procurement websites, the fiscal integration system, the purchaser’s budget system, and supplier credit records. The update frequency is daily. Daily processed documents include procurement requirements, procurement plans, bidding documents, tender documents, bid evaluation reports, winning bid announcements, procurement contracts, and question-and-answer responses. Document fields include project number, supplier unified social credit code, bid evaluation score, contract amount, and similar items. Common units are project items, copies, and yuan.

## What constraints these characteristics impose on deployment and upgrades
Configure a stable incremental sync link during deployment, to handle daily updated data and avoid excessive government cloud resource usage from full pull operations. Adapt parsing rules for different formats to support multiple types of government documents. Maintain the original document parsing logic during upgrades, to prevent parsing failures for critical documents such as bid evaluation reports and procurement contracts. Open corresponding interface permissions during deployment, as data sources involve multiple government systems. Verify connectivity for each data source after upgrades. Large procurement and tender documents extend vector storage and retrieval durations. Adjust related configurations to adapt to high-load scenarios.

## How to set configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Configure a dedicated instance connection string accessible via the government private network | Government procurement data must be stored in a compliant government cloud environment to avoid public network leakage risks |
| `REDIS_URL` | Configure a dedicated cache instance with memory no less than 2000 MB | Supports caching and session synchronization for daily incremental data, adapting to high-frequency access across multiple departments |
| `STORAGE_S3_ENDPOINT` | Configure the access endpoint of the government cloud object storage service | Stores large-volume documents such as procurement files and bid evaluation reports, complying with government data storage specifications |
| `DB_MAX_LINK` | `100–150` | Adapts to concurrent access demands for procurement documents across multiple departments, avoiding connection pool exhaustion |
| `FILE_TOKEN_KEY` | Generate a key in accordance with unified government system encryption rules | Ensures security of procurement document download links, complying with government data encryption requirements |

## Three common errors
- Symptom: A `timeout of 60000ms exceeded` error occurs when deleting a folder with a large number of procurement documents in the knowledge base. Cause: The batch operation timeout threshold is not adjusted for large-volume government documents. The default timeout duration is insufficient to complete batch document cleanup and index updates.
- Symptom: Packaging errors occur during local deployment, with a prompt about dependency package version conflicts. Cause: A basic image adapted to the government environment is not used. Direct use of a generic image may cause dependency compatibility issues, leading to deployment failure.
- Symptom: Data synchronization from the fiscal integration system is interrupted after an upgrade. Cause: Original data source configuration parameters are not retained during the upgrade. This leads to failure of interface connectivity with government systems, and inability to pull updated procurement data for the current day.

## How to confirm configuration is complete
- Access the configured `FE_DOMAIN` and verify that the FastGPT management backend can be logged in normally.
- Manually trigger an incremental sync task, and check whether updated procurement documents for the current day can be pulled from the specified government data source.
- Upload a test procurement requirement document, and confirm that the parsing and vector storage processes run without exceptions.
- Check database connection count monitoring, and confirm that the connection count does not exceed the configured limit of `DB_MAX_LINK`.

The values listed here are common starting points, and should be evaluated against individual specific use cases.
