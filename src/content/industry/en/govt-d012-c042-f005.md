# Internal Office and Employee Services for Legal Compliance and Major Risk Management: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from enterprise contract management systems, compliance risk databases, legal and regulatory repositories, case management systems, and reporting platforms linked to central enterprise legal compliance departments and chief compliance officer offices.
Daily processed documents cover compliance risk lists, contract legal review opinions, major issue legal opinions, compliance review forms, and violation report investigation results.
Data is updated monthly. Most documents include structured fields and unstructured attachments, and must be classified and processed according to the business attributes of each individual document.

## What constraints these characteristics impose on tool calling and plugins
Plugins must support API connections to enterprise-owned internal systems to accommodate multi-source internal data sources, ensuring secure data transmission.
Monthly data updates require tool calling to use incremental synchronization logic, reducing resource consumption from full data pulls.
Diverse document types with large attachments require tool calling to support large file uploads and multi-format parsing.
Serious error consequences in compliance work require tool calling to include failure retry and result verification mechanisms, ensuring calling stability.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Automatically match the compliance toolset | Adapt to the needs of multi-tool linkage in compliance scenarios, reduce manual intervention |
| `functionCall` | Bind calling rules by document type | Match exclusive processing logic for different compliance documents, improve calling accuracy |
| Single tool call timeout | 600 seconds | Compliance review requires pulling data from multiple sources, sufficient execution time must be reserved |
| Upload file size limit | 800–1200 MB | Match the characteristics of compliance documents that include large numbers of attachments and scanned files |
| Tool call retry count | 3 times | Address occasional fluctuations in internal systems, reduce the probability of calling failures |
| Custom variable reference switch | Enabled | Support passing business variables such as compliance document numbers and risk levels during tool calls |

## Three common configuration mistakes
- Uploaded file parameters in custom workflows cannot reference variables; only upload links are supported. This happens when the variable reference switch is not enabled, or the corresponding variable field is not bound in the tool configuration.
- File upload size limit exceeded errors occur during compliance tool calls. This happens when upload limit configurations during container startup are not adjusted, as the default limit cannot support large compliance documents.
- Compliance risk identification results are not returned after tool calling. This happens when `toolChoice` matching rules are not configured correctly, or the compliance risk database data source is not linked.

## How to confirm configuration is complete
- Upload a compliance test document, trigger tool calling, and check if interface-returned results match preset compliance review logic.
- Review tool calling logs to confirm whether `functionCall` triggers the corresponding tool based on document type, and that variable parameters are passed correctly.
- Check the MinIO storage directory to confirm uploaded compliance document copies are saved correctly, and verify file integrity via the storage console.
- Simulate internal system interface calls to verify whether the tool call timeout configuration takes effect, and confirm retry logic triggers after timeout.

The values provided are common starting points and should be measured against the reader's own samples.
