# Internal Office and Employee Services for Special Equipment Safety Supervision: Forms and Interactions

## What data for this category looks like
The data for this category comes from the special equipment safety supervision system, inspection and testing institution system, user account books, and operator certificate database. Daily documents include use registration certificates, periodic inspection reports, maintenance records, hidden danger rectification notices, accident reports, and operator certificates. Fields include unique device identifiers, inspection validity periods, maintenance qualification numbers, operator certificate numbers, rectification closed-loop status, and others. The data update frequency is monthly. Most data takes the form of a combination of structured account books and formatted reports. Fields must match the device lifecycle nodes in the supervision process.

## What constraints these characteristics impose on forms and interactions
Since data sources are scattered and the update frequency is monthly, the forms and interactions link must support scheduled synchronization configuration for cross-system data pulling. This avoids delays caused by manual entry. There are various types of daily documents, so forms must adapt to field mapping rules for different documents. This ensures that extracted device numbers, inspection validity periods and other information accurately match supervision requirements. The core time-consuming link is verifying multiple types of data. The interactions link must support batch field verification and auto-completion, to reduce repetitive operations. At the same time, since the consequences of errors include device shutdown and administrative penalties, forms must add required field verification and data consistency checks.

## How to set configurations
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` field mapping | Map the three core fields: device number, inspection validity period, maintenance qualification number | Match the core data items of daily documents, and fit the verification needs of the supervision process |
| Text content extraction trigger timing | Trigger after field verification is completed before form submission | Ensure extracted content is verified valid input, and avoid invalid data entering the process |
| Extraction failure preset reply | Pre-set "Please supplement the inspection cycle or qualification information of the corresponding device" | Match common information gap types in supervision scenarios, and guide users to supplement valid content |
| Reranking model configuration | Set based on actual measurement, adapt to structured text scenarios | Address extraction needs for multiple types of structured account books and reports, and improve field recognition accuracy |
| Single interaction waiting duration | 600 seconds | Cover the conventional time required for pulling monthly data across systems, and avoid interaction interruptions |
| `userSelect` option range | Limit to two categories: operator qualifications and device inspection cycles | Match the verification needs of the core time-consuming link, and reduce interference from invalid options |

## Three common mistakes
- Phenomenon: Text content extraction fails to obtain core fields such as device number or inspection validity period. The workflow does not pause to wait for user input after triggering the specified reply. Cause: The waiting trigger rule for `formInput` is not configured correctly, causing the workflow to directly complete the current node jump.
- Phenomenon: After the reranking model processes structured documents, it only returns a single result. This cannot cover the extraction needs of multiple core fields. Cause: The option range for `userSelect` is not configured, and it is incorrectly bound to a single result that only matches the highest similarity.
- Phenomenon: Interaction timeout occurs when pulling monthly data across systems, and the form process is interrupted. Cause: A reasonable single interaction waiting duration is not set, and the retry prompt logic after timeout is not configured.

## How to confirm the configuration is correct
- Submit a test form, intentionally omit the device inspection validity period field. Confirm that the system triggers the preset specified reply and pauses to wait for user input.
- Call the reranking model to process a structured periodic inspection report document. Confirm that the number of returned results matches the preset option range of `userSelect`.
- Check the field mapping configuration of `formInput`. Confirm that it only includes the three core fields: device number, inspection validity period, and maintenance qualification number.
- Simulate the scenario of pulling data across systems. Confirm that the interaction waiting duration conforms to the preset configuration, and the corresponding prompt is triggered after timeout.

The values given are common starting points and should be measured against the reader's own samples.
