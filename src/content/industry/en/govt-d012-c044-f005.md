# Internal Office and Employee Services for Environmental Law Enforcement and Monitoring Supervision: Tool Calling and Plugins

## What this category's data looks like
Data for this category mainly comes from the ecological environment online monitoring platform, pollution source automatic monitoring system, internal law enforcement system, and reports submitted by third-party testing institutions. Daily generated documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Document fields include law enforcement location, sampling time, pollutant concentration, rectification requirements, and some fields have standard units such as mg/m³. The data update frequency is once per day, covering on-site law enforcement and monitoring data from the current day.

## What constraints these characteristics impose on the "tool calling and plugins" link
The daily data update feature requires tool calling to regularly pull the latest online monitoring and law enforcement system data to avoid using expired information. Differences in data formats across multiple sources require plugins to unify field verification logic to ensure field matching for sampling records and monitoring reports. Document preparation for on-site law enforcement and monitoring needs to associate multi-source data, so tool calling must support cross-system data aggregation. The serious potential consequences of errors require tool calling to be configured with failure retry and log retention mechanisms to ensure the integrity of law enforcement evidence.

## How to configure settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the automatic selection needs of multiple types of law enforcement and monitoring tools |
| `functionCall` | mandatory | Ensure tool calling strictly follows the preset law enforcement document generation logic |
| Tool call timeout period | 600 seconds | Cover the time required for full online monitoring data pull and law enforcement document generation |
| Tool call retry count | 2 times | Address single call failures caused by network fluctuations |
| Context window size | 8000–12000 token | Accommodate complete law enforcement records and monitoring report content |
| Tool result cache duration | 1 day | Match the daily data update frequency to avoid using expired cached data |

## Three common mistakes
- Symptom: The monitoring data fields returned by tool calling are empty. Cause: Field verification logic is not configured, so non-standard format data returned by the law enforcement system cannot be matched.
- Symptom: Tool calling triggers a timeout error. Cause: The set timeout period is shorter than the actual time required to pull online monitoring data.
- Symptom: MCP tool calling has no interactive feedback. Cause: The interactive mode configuration of `functionCall` is not enabled, so real-time input requests from on-site law enforcement personnel cannot be received.

## How to confirm the configuration is complete
- Initiate a request that includes querying the day's monitoring data, and check whether the tool can pull the latest data from the online monitoring platform.
- Test calling the law enforcement document generation tool, and check whether it can automatically associate corresponding fields between sampling records and online monitoring data.
- View the tool call logs to confirm that the retry mechanism is triggered when simulating network fluctuations.
- Verify that the `toolChoice` configuration automatically selects the tool type matching the current request.

The values given are common starting points and should be measured against the reader's own samples.
