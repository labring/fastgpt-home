# Internal Office and Employee Services for Environmental Law Enforcement and Monitoring Supervision: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
Data sources for this category include online monitoring platforms, automatic pollution source monitoring data, ecological environment law enforcement systems, and third-party test reports. Daily generated documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Data is updated daily. Most individual documents contain structured fields such as law enforcement location number, sampling time, testing items, concentration value, rectification requirements, and illegal facts. Some test reports include attached original sampling images or record attachments. Data fields have clear exclusive identifiers and corresponding units for law enforcement and monitoring scenarios.

## Constraints for Knowledge Base Retrieval and Recall
Data sources for this category are scattered and follow fixed update frequencies. The knowledge base retrieval link must support synchronization of multi-system data, with synchronization cycles matching the daily update rhythm. This prevents data lag that harms the timeliness and accuracy of law enforcement judgments. Documents contain exclusive fields such as law enforcement locations, detection values, and illegal facts. Retrieval logic must be optimized for these fields to ensure recall results are strongly relevant to law enforcement and monitoring scenarios. Some documents include attachments related to original sampling. Retrieval must associate attachment content to supplement supporting information. Law enforcement documents have high requirements for factual accuracy. Recalled text blocks must accurately correspond to specific law enforcement scenarios, avoid irrelevant content interference, and prevent issues such as insufficient penalty evidence and unaddressed excessive emissions.

## Configuration Guidelines
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the accuracy requirements for law enforcement and monitoring documents, avoids recalling irrelevant general environmental data |
| `limit` | Top 3–5 entries | Law enforcement scenarios require quick access to core evidence. Controlling the number of single-recall results improves response speed |
| `searchMode` | Semantic + keyword hybrid retrieval | Balances precise keyword matching (e.g., law enforcement number) and semantic understanding (e.g., excessive emission condition descriptions) for law enforcement scenarios |
| `usingReRank` | Enabled | Re-ranks initial recall results to prioritize text blocks strongly relevant to law enforcement scenarios |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval queries, supplements synonyms and industry terms related to law enforcement and monitoring, improving recall coverage |
| `collectionIds` | Fill in the IDs of law enforcement and monitoring-specific knowledge base collections as per actual deployment | Precisely limits the retrieval scope, avoids mixing in knowledge base data from other categories |

## Three Common Misconfigurations
- Phenomenon: Retrieval results only return 1 text block, making it impossible to obtain multiple law enforcement or monitoring-related supporting materials. Cause: The `limit` parameter value was not adjusted, or the `similarity` threshold was set too high, filtering out other eligible text blocks.
- Phenomenon: Retrieval results mix non-law enforcement and monitoring general environmental documents, failing to accurately match business scenarios. Cause: The `collectionIds` parameter was not configured to limit the retrieval scope, or the `searchMode` did not enable keyword matching logic.
- Phenomenon: Knowledge base synchronization is delayed, and daily updated data from online monitoring platforms and law enforcement systems is not updated to the knowledge base on time. Cause: Synchronization tasks matching the daily data update rhythm were not set, and the synchronization trigger cycle does not match the data update frequency.

## How to Confirm Proper Configuration
- Perform a keyword search targeting a law enforcement location number, verify whether the recall results include the content of the corresponding law enforcement document.
- Check the knowledge base synchronization logs to confirm that daily online monitoring platform and law enforcement system data has completed synchronization updates.
- Adjust the retrieval query, test different law enforcement scenario keywords, and verify whether the number of recall results meets expectations.
- Check the configuration item values, confirm that `collectionIds` is limited to the knowledge base collection for this category.
