# Internal Office and Employee Services for Environmental Law Enforcement and Monitoring Supervision: Forms and Interactions

## What this category of data looks like
Typical subjects of this category include ecological environment law enforcement detachments, monitoring stations, pollutant discharge units, and third-party testing institutions. Daily documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Data sources cover online monitoring platforms, automatic pollutant source monitoring data, ecological environment law enforcement systems, and third-party test reports. Update frequency is daily. Data fields include on-site operating condition parameters, sampling point coordinates, monitoring concentration values, law enforcement document numbers, rectification requirements, and others. Most units are standard environmental monitoring units. The number and format of fields per document are fixed, and must comply with law enforcement compliance requirements.

## What constraints these characteristics impose on forms and interactions
Data sources for this category are scattered and require daily updates. Form interactions must support fast association with multi-source external data, to reduce manual entry errors. Daily documents have fixed field structures. Forms must strictly match the format and mandatory requirements of corresponding fields, to ensure compliance of documents such as law enforcement instruments and monitoring reports. Timeliness requirements for data association are high. The form's time selection component must default to binding the current day's time interval. This ensures that retrieved online monitoring data matches the on-site law enforcement time. Data errors can lead to consequences such as unaddressed excessive emissions and insufficient penalty evidence. Forms must add verification rules, and perform mandatory verification on fields such as values and units. This reduces error risks.

## How to Configure the Setup
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Bind the 12 core fields of on-site inspection records and sampling records, with field formats matching corresponding document requirements | This category of daily documents has fixed field structures, to ensure data compliance |
| `userSelect` | Preset optional lists for law enforcement personnel and third-party testing institutions, support fuzzy search | Data sources include third-party test reports and law enforcement subject information, to quickly associate corresponding subjects |
| Form verification rules | Set range verification for concentration values, force units to mg/m³ or mg/L | Monitoring data has standard unit requirements, incorrect units will lead to law enforcement judgment deviations |
| Data source association configuration | Associate the daily updated data interface of the online monitoring platform, set the pull time range to 0:00 of the current day to the current time | Data update frequency is daily, to ensure the timeliness of retrieved data |
| History record call configuration | Limit the number of history records called in a single session to the first 10 | Law enforcement documents are mostly single-batch data, excessive history records will interfere with current form filling |
| Variable initialization configuration | Set the initial value of the law enforcement document number variable to the current year + law enforcement sequence prefix | Law enforcement documents must be numbered by year, to simplify manual filling process |

## Three Common Misconfigurations
- Selecting a web link to bind form fields results in no data loading. The symptom is that no data appears in the corresponding form position after clicking the associated web link. The cause is that data source access permissions are not configured, so daily updated data from the online monitoring platform or ecological environment law enforcement system cannot be retrieved.
- Workflow code running node input fails verification when containing history records. The symptom is that a verification failure prompt appears when submitting the workflow, and further workflow editing is not possible. The cause is that the number of history records called by `formInput` is not limited, and the input content exceeds the single-batch data limit allowed by the system.
- After adding the Whisper speech model, the browser still prompts that speech input is not supported. The symptom is that a speech input permission abnormality prompt appears on the page, and speech recording cannot be enabled. The cause is that the page's speech input permission switch is not enabled, or the voice trigger logic of `userSelect` is not correctly bound.

## How to Confirm the Configuration Is Complete
- Manually fill in the core fields of the form. After submission, check whether the data is synchronized to the associated law enforcement system document template.
- Test the code running node by inputting a history record snippet. Confirm that verification passes and corresponding data can be called normally.
- Enable the speech input function, use the microphone to record content. Confirm that the content can be correctly converted into form text.
- Check the initial value of the global variable. Modify the variable value, and confirm that the form field can synchronously update the variable content.
