# Internal Office and Employee Services for Environmental Law Enforcement and Monitoring Supervision: Deployment and Upgrade

## What the data for this category looks like
This category of data mainly comes from online monitoring platforms, automatic pollution source monitoring data, ecological and environmental law enforcement systems, and third-party test reports. Daily processed documents include on-site inspection records, sampling records, monitoring reports, order for correction decisions, and administrative penalty decisions. Data is updated daily. Each individual document contains content such as on-site operating condition records, monitoring data, law enforcement process nodes, rectification tracking information, etc. Data formats vary across different sources. Some data must be pulled in batches via system interfaces, while other data must be entered manually.

## What constraints these characteristics impose on deployment and upgrade
Daily updated data requires stable database connection and caching configurations during deployment, to prevent data synchronization interruptions from affecting daily law enforcement scheduling. Multi-source data docking needs support for flexible data source access configurations. Expansion space for adapting different interfaces must be reserved during deployment, to meet data pull requirements from multiple sources including online monitoring platforms and law enforcement systems. Law enforcement and monitoring documents in different formats require the storage system to support indexing and retrieval of multiple file types, to ensure retrieval efficiency for subsequent tasks such as law enforcement document preparation and rectification tracking. At the same time, the processing flow for law enforcement-related data must be bound to internal office processes. During upgrades, the original business link must remain uninterrupted, to avoid impacting core work such as on-site law enforcement and monitoring report issuance.

## How to configure the settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 30–50 connections | Matches the concurrent connection needs of daily batch-pulled law enforcement and monitoring data, to avoid connection exhaustion |
| `MONGODB_URI` | Configure as a dedicated monitoring document storage connection string | Used to store unstructured law enforcement-related documents such as on-site inspection records and monitoring reports |
| `PG_URL` | Configure as the structured data connection string for the ecological and environmental law enforcement system | Used to store structured business data such as law enforcement process nodes and rectification tracking information |
| `REDIS_URL` | Configure as the local cache cluster connection address | Caches daily updated online monitoring data to reduce resource consumption from repeated pulls |
| `STORAGE_S3_ENDPOINT` | Configure as the internal file storage platform endpoint | Used to store archived files such as sampling records and administrative penalty decisions |
| `FE_DOMAIN` | `https://internal office system exclusive domain` | Matches the domain rules for internal employee access, to ensure page access legitimacy |

## Three common misconfigurations
- Symptom: Slow response after Docker deployment, with database connection timeouts displayed in logs. Cause: The `DB_MAX_LINK` configuration was not adjusted, and insufficient concurrent connections caused data pull delays.
- Symptom: 404 error occurs when accessing third-party test reports. Cause: `STORAGE_S3_ENDPOINT` was not configured correctly, and the file storage endpoint cannot match the access path of the internal system.
- Symptom: Custom monitoring data models fail to load after online deployment. Cause: Permission verification via the `ROOT_KEY` configuration was not completed, causing loading permissions for custom models to be blocked.

## How to verify successful configuration
- Run the daily data synchronization script, check whether structured business data is properly written to the PG database, and whether unstructured documents are stored to the storage endpoint specified by `STORAGE_S3_ENDPOINT`.
- Access the internal office domain configured in `FE_DOMAIN`, verify that the page loads normally and the document retrieval function has no errors.
- View the cache cluster monitoring panel corresponding to `REDIS_URL`, confirm that the cache hit count for daily online monitoring data meets expectations.
- Use the key generated via `ROOT_KEY` to test access permissions for custom law enforcement documents, verify that the encryption rules take effect.

The values provided are common starting points and should be measured against the reader's own samples.
