# Internal Office and Employee Services for Land Pre-examination and Planning Permit: Forms and Interactions

## What the data for this category looks like
This category uses data from the national land spatial planning unified map, project approval and supervision platform, current land use database, and ecological protection redline data. The data is updated on an irregular basis. Daily circulated documents include land pre-examination and site selection opinions, construction land planning permits, construction project planning permits, redline drawings, and planning conditions. Data fields cover project site selection scope, land scale, control indicators, pre-approval node status, spatial coordinates, and area values. Most documents are structured approval forms and vector files with spatial attributes.

## What constraints these characteristics impose on forms and interactions
Multiple data sources and irregular updates require forms to pull the latest spatial and approval data in real time for verification. This prevents the use of expired information. Daily circulated documents include spatial vector files and structured approval forms. This requires the interaction link to support multi-format attachment upload and field linkage verification. Pre-approval requires coordinating data across multiple departments. Forms must add node status synchronization fields. This lets handlers in each link view pre-approval progress. Fields such as land scale and site selection scope must bind to spatial data verification rules. This prevents input values from conflicting with existing database data.

## How to configure settings
The following configurations are set based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Bind land scale and pre-examination number fields, set numerical and character range verification, with values of `0-99999 hectares` and `10-20 characters` | Match the spatial data unit and pre-examination number format of the current land use database to avoid input conflicts |
| `userSelect` | Configure as single-select mode, with optional pre-approval departments, values are Development and Reform, Housing and Urban-Rural Development, Ecology, Natural Resources, Administrative Examination and Approval, Project Unit | Adapt to business processes that require coordinating multi-department pre-conditions, reducing handler selection costs |
| Attachment upload limit | Allow uploading documents such as redline drawings and planning conditions, maximum single file size is `500 MB` | Match the size range of daily circulated documents, adapt to storage requirements for spatial vector files |
| Data pull timeout | Set value to `30 seconds` | Adapt to response time for pulling multi-source data, avoid long-term blocking of form submission |
| Form verification trigger | Set to automatically execute before form submission | Obtain the latest land spatial planning data in real time, ensure accurate verification results |

## Three common configuration errors
- Phenomenon: The `userSelect` single-select component fails to load the preset department list. The field is empty after submission. Cause: The global variable is not set as the optional value source for `userSelect`. Only fixed options are manually entered.
- Phenomenon: Calling the FastGPT form interface via an external API returns no form configuration content. The form cannot display on third-party platforms. Cause: The form's API public permission is not enabled. Or the form's API call parameters are not correctly configured.
- Phenomenon: Spatial data verification does not trigger after form submission. Land scale values conflict with existing database data. Cause: The data pull and verification trigger rules before form submission are not set. Locally cached expired data is used.

## How to confirm successful configuration
- Open the form configuration page. Verify that bound fields match the fields of business circulation documents.
- Test the optional value loading status of the `userSelect` component. Confirm that preset approval node options are included.
- Upload a test spatial document. Confirm that the attachment upload function operates correctly.
- Simulate form submission. Check whether preset verification rules trigger and generate corresponding feedback.
