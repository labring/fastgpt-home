# Internal Office and Employee Services for Social Assistance and Minimum Living Security Review: HTTP Interfaces and External Systems

## What data falls under this category
The daily documents involved in this category include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, assistance approval forms, and others. Data sources include low-income population dynamic monitoring platforms, resident family economic status verification systems, and shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. The update frequency is monthly. Core data fields cover family income, property status, member relationships, and other items, requiring cross-departmental integration and synchronization.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Interface calls must use low-frequency batch retrieval rhythms to avoid high-frequency requests that occupy cross-departmental data interface resources, per the monthly update frequency requirement. Connecting to cross-departmental data sources requires interfaces to support multiple authentication rules for different external systems. Many core fields have complex associations, so interface input parameters must strictly match field definitions in business documents to prevent data misalignment. The serious consequences of incorrect or missed assistance require interface calls to be configured with complete failure retry and exception alert mechanisms to ensure data synchronization accuracy.

## How to configure settings

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Authentication Method | Configure according to the requirements of the connected system, such as carrying a static token in the `Authorization` header | Most cross-departmental data interfaces use token authentication to protect sensitive data security |
| Request Variables | Limit to core fields such as family income, property status, member relationships, with no more than 20 variables per single request | Match the core fields in business documents to avoid invalid data transmission |

| Timeout Setting | 300–600 seconds | Adapt to network latency and data calculation time required for cross-departmental data synchronization |
| Retry Count | 2–3 times | Address request failures caused by temporary network fluctuations, avoiding repeated triggering of cross-departmental interface rate limits |
| Synchronization Frequency | Configure according to the monthly update rhythm, with no more than 1000 pieces of data retrieved in a single batch | Match the monthly update frequency of data sources to avoid occupying interface resources |

## Three common configuration mistakes
- Phenomenon: The HTTP interface fails to correctly load configured input parameter variables. The interface displays empty input parameter fields or fields that do not match business documents. Cause: Core fields such as family income and member relationships are not added to the `variables` configuration item, causing the interface to fail to obtain necessary business data.
- Phenomenon: The external system interface returns empty content with no business data after being called. Cause: Authentication rules for cross-departmental systems are not adapted, and the `Authorization` header is configured incorrectly or does not carry a valid token.
- Phenomenon: Interface calls frequently trigger timeout errors. Cause: The synchronization frequency is set too high, exceeding the rate limit threshold of cross-departmental data interfaces, or the timeout setting is too short to adapt to data calculation time.

## How to confirm that the configuration is complete
- Initiate a single test call, and check whether the `responseData` returned by the interface includes the configured core business fields.
- Simulate temporary network interruptions to verify whether the interface triggers the preset retry mechanism and alerts.
- Compare the single-retrieved data volume with the configured synchronization scope to confirm that the system limit is not exceeded.
- Check the interface call frequency against the update rhythm of the data source to confirm that it matches the business cycle.
