# Internal Office and Employee Services for Social Assistance and Minimum Livelihood Guarantee Audit: Vector Models and Indexes

Reference only; verify against the target FastGPT release and deployment documentation.

## What the data for this category looks like
Core data for this category comes from daily office work and business systems of entities including civil affairs bureau assistance sections, sub-district and township civil affairs offices, community neighborhood committees, and verification centers. Documents included are minimum livelihood guarantee application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms.
Data mainly originates from low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax authorities, and other departments. Update frequency is monthly.
Core data centers on family economic status, member relationships, and assistance eligibility, covering structured fields and unstructured supporting materials.

## Constraints imposed on vector models and indexes
Multi-source cross-department data sources result in heterogeneous document formats. Index configurations must adapt to different types of business documents.
Monthly update frequency requires indexes to support scheduled full or incremental update scheduling mechanisms.
Core data involves sensitive information such as family income and property. Index storage and calls must comply with data security specifications.
Document lengths vary widely, spanning short forms to long reports. Chunking and retrieval strategies must balance context completeness and retrieval efficiency.
Error consequences directly relate to incorrect or missed guarantee coverage and public petitions. The accuracy of index retrieval must strictly match business judgment logic.

## Configuration settings
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the content density of typical documents in this category, balancing context completeness and retrieval accuracy |
| Overlap Length | 100–150 characters | Prevents truncation of cross-chunk key information such as family member relationships and income details |
| Similarity Threshold | 0.72–0.80 | Adapts to eligibility judgment relevance requirements in minimum livelihood guarantee audit scenarios, calibrated based on actual testing |
| `maxToken` | 8000 token | Covers the complete context of a single approval document, meeting the context call requirements of audit logic |
| Single Search Limit | Top 10 results | Balances retrieval efficiency and recall coverage, avoiding excessive irrelevant data interfering with audits |
| `defaultToken` | 4096 token | Adapts to the basic context length of daily retrieval, reducing resource consumption for model calls |

## Three common misconfigurations
- When exporting index data, only overall knowledge base files can be retrieved, and separate export by business category such as minimum livelihood guarantee applications or verification reports is not supported. Reason: No layered knowledge base directory is configured for multi-category documents in this category. Export granularity is only set for the overall knowledge base.
- After connecting an external vector model, arm soft router deployments experience inference timeouts or freezes. Reason: The `defaultToken` parameter has not been adjusted based on the category's data volume, or the maximum context length for single retrieval has not been restricted.
- After importing Feishu multi-dimensional documents, family income fields in tables cannot be indexed correctly. Reason: The parsing switch for structured documents has not been enabled, so table fields are not extracted as indexable text.

## How to verify successful configuration
- Run a full index task, check whether all document types in this category are successfully parsed in the index progress log.
- Input a simulated family income or member relationship query, verify whether the number and matching degree of retrieval results comply with the preset similarity threshold rules.
- Test the external model call link, confirm whether the response time on the target architecture device meets business operation requirements.
- Export index data for a specified business category, confirm that the exported file contains document content corresponding to this category.
