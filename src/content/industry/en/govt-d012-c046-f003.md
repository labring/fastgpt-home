# Internal Office and Employee Services for Social Assistance and Minimum Living Allowance Review: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Typical entities include civil affairs bureau assistance sections, sub-district and township civil affairs offices, community committees, and verification centers. Daily official documents processed include minimum living allowance application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notification materials, and assistance approval forms. Data sources include the low-income population dynamic monitoring platform, resident family economic status verification system, and cross-department shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, and tax authorities. Update frequency is monthly. Core data fields focus on family economic status and member relationships, including key information such as income, property, household registration, and living situation.

## What Constraints Do These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
Cross-department shared data updated monthly requires that multi-turn dialogues be bound to a unique family identifier to avoid cross-session data confusion and repeated pulling. Multiple types of review documents must be called step-by-step according to the process, and prompts must guide employees to sequentially verify core links such as income, property, and member relationships to prevent missing key review information. Cross-department data sources are scattered and have different formats, so the calling scope of corresponding data must be clearly specified in the dialogue to avoid redundant information interfering with review judgments. Family economic status verification is the core link of review, and multi-turn dialogues must support reviewing historical application records to ensure consistency across different batches of reviews for the same family. The consequences of errors are directly linked to incorrect or missed insurance coverage, recovery of assistance funds, and public feedback, so a data verification link must be added to the dialogue to ensure the accuracy of each round of verification results.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0, and are adapted for the multi-turn dialogue and prompt engineering scenario of civil affairs assistance review.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Max Context | 12–18 prior conversation turns + historical review records for the corresponding family | Must cover the full application process dialogue and data for the family to avoid context loss |
| Single Search Limit | 6–10 matched documents per retrieval | Matches the average number of daily review documents, filters redundant information |
| `variables` | Bind family verification number and application batch number variables | Associate unique identifiers for cross-department shared data to ensure accurate data matching |
| `chatId` | Bind the regional code of the sub-district to which the session belongs | Call low-income population monitoring data for the corresponding region by jurisdiction |
| `messages` | Split according to the review process, with each round focusing on only one verification item | Guide employees to sequentially complete verification of income, property, and member relationships |
| Max Response Character Count | 800–1200 characters | Adapt to the single-round output length of review reports, avoid content overflow |

## Three Common Misconfigurations
- The symptom is that session response transmission takes far longer than model call duration, for example, the call is grouped as 1 group but transmission takes over 600 seconds. The cause is that the unique family verification number is not bound in `variables`, causing multi-turn dialogues to repeatedly pull full cross-department shared data.
- The symptom is a permission error triggered after configuring the database connection plugin. The cause is failure to adapt to the cross-department data interface verification rules of the civil affairs system, and failure to pass the internal identity authentication process.
- The symptom is that specified collection verification report documents cannot be searched in the dialogue. The cause is that the identifier of the corresponding document collection is not clearly specified in the prompt, causing the search scope to cover the full knowledge base.

## How to Confirm Proper Configuration
- Initiate a simulated minimum living allowance application dialogue, check that the family verification number in `variables` is automatically filled with the session, and no null values or incorrect regional codes appear.
- Review the dialogue history, confirm that each round of `messages` focuses on only one verification item, and no redundant cross-department irrelevant data appears in the context.
- Test the database connection plugin, verify that low-income population monitoring data for the specified community can be pulled normally, with no permission or connection errors.
- Copy the Markdown content generated by the dialogue, check that correct carriage return and line break formats are present, and content paragraphs meet the typesetting requirements of review documents.
