# Internal Office and Employee Services for Social Assistance and Minimum Living Allowance Review: Workflow Orchestration

## What the data for this category looks like
Data for this category comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and shared data from public security, human resources and social security, medical insurance, housing construction, and tax authorities. The update frequency is monthly. Daily business documents include the minimum living allowance application form, family economic status verification report, household survey form, democratic appraisal records, public notice materials, and assistance approval form. Fields cover family income, property status, member relationships, approval progress, and more. Standardized fields from cross-department shared data must be strictly matched.

## What constraints do these characteristics impose on the "workflow orchestration" link?
Since data sources involve multiple departments and cross-systems, workflow orchestration must set up data verification rules between nodes to ensure consistency between cross-department data fields and business document fields. Data updates occur monthly, so a scheduled trigger node must be configured to trigger the dynamic review link on a periodic basis. There are many types of business documents with strict field requirements, so nodes corresponding to different documents must be grouped, and clear field mapping rules defined. Errors may lead to incorrect or missed allowance payments, so multi-layer approval nodes must be set up to verify data accuracy at each stage. The workflow must focus on the family economic status verification and household survey links, matching the category-specific process logic.

## Three common mistakes
- Attempting to import a workflow from v4.6.7 into v4.8.10 triggers the "node configuration incompatible" error. Cause: The old version's `variables` binding rules do not match the new version.
- When accessing a published workflow via API, the frontend has no interactive prompts for form input or user selection. Cause: The return prompt parameter for interactive nodes was not enabled in the API request configuration.
- Attempting to pass a knowledge base ID as a variable triggers a parameter verification error. Cause: The knowledge base ID was not correctly bound to the `variables` field, and an undefined variable name was used directly.

## How to confirm the configuration is complete
- Check that the `variables` bound fields of each node in the workflow correspond one-to-one with the fields of the business documents.
- Trigger a test workflow to verify that the form input and user selection nodes follow the preset actions for flow transfer.
- Call the API to trigger the workflow, confirm that the returned content includes interactive prompt information.
- View the return logs of the cross-department data call node, confirm that the data source and the preset verification system return normal data.
