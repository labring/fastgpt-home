# Internal Office and Employee Services for Social Assistance and Minimum Living Security Review: Tool Calling and Plugins

## What this category of data looks like
This category of data primarily comes from the low-income population dynamic monitoring platform, resident family economic status verification system, and shared data from public security, human resources and social security, medical insurance, housing and urban-rural development, tax and other departments. The update frequency is once per month. Daily office documents include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Core fields cover family income, total property, member identity and relationship, and application qualification-related information. Data is aggregated by household, and cross-source information from multiple departments is associated.

## What constraints these characteristics impose on tool calling and plugin workflows
The monthly update frequency of cross-department shared data requires that tool calling must adapt to batch monthly verification tasks, and support batch pulling of cross-source structured data by household. The field differences across multiple types of office documents require that plugins must be able to recognize standardized fields of different documents to avoid format parsing errors. The core process relies on cross-department property and member relationship verification, which requires tool calling to support serial or parallel calls of multiple interfaces, while also verifying the consistency of cross-source data. Since errors may lead to incorrect or missed security assistance, fund recovery and other consequences, tool calling must have basic parameter verification and result traceability capabilities to reduce invalid calls.

## How to set the configuration

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically matches the two core tools of cross-department data pulling and document parsing, adapting to batch verification scenarios |
| Single tool call timeout | 300–600 seconds | Adapts to the average response time of cross-department shared data, avoiding task interruptions due to network fluctuations |
| Tool call batch limit | First 15–25 households | Matches the regular business scale of street-level verification, avoiding overload of single requests |
| `functionCall` | Enabled | Ensures the structured format of tool output aligns with the field standards of family economic status verification reports |
| Parameter verification switch | Enabled | Intercepts call parameters that do not meet business field rules, reducing the probability of invalid verification |

## Three common configuration mistakes
- Interface returns "The tool call is not supported" error. Cause: Tool calling function is not enabled in the configuration, or a cross-department data interface that was not pre-configured is called.
- Tool call returns 400 <400> InternalError.Algo.InvalidParameter error. Cause: The format of parameters such as family income and member relationship does not meet the field rules required by the tool, and the parameter verification switch is not enabled.
- Tool call task times out with no return result. Cause: A reasonable timeout period is not set, or network fluctuations occur when pulling cross-department data, leading to response timeout.

## How to confirm the configuration is correct
- Initiate a single-household family economic status verification test, check whether the tool can correctly pull shared data fields from the corresponding department
- Trigger a batch call task, confirm that the tool call batch limit meets the current business scale requirements, and no overload errors occur
- Submit a test request with abnormal parameters, confirm that the parameter verification switch can intercept invalid calls
- View tool call logs, confirm that the structured format output by `functionCall` aligns with office document fields
