# Internal Office and Employee Services for Social Assistance and Minimum Livelihood Guarantee Review: Document Parsing and Chunking

## What this category's data consists of
Data in this category originates from daily office documents of civil affairs bureau assistance departments, sub-district and township civil affairs offices, community committees, and other relevant entities. These include standardized forms such as minimum livelihood guarantee application forms, family economic status verification reports, household survey forms, and democratic appraisal records.
Data also comes from low-income population dynamic monitoring platforms, resident family economic status verification systems, and cross-department shared structured data.
Data update frequency is monthly. Core fields include family income, property details, member relationships, basis for assistance qualification determination, and similar items. Some documents include scanned or handwritten supporting materials.

## Constraints on document parsing and chunking
The data characteristics of this category impose multiple constraints on the document parsing and chunking stage.
First, document types cover standardized forms, cross-department structured data, and offline handwritten or scanned supporting materials. Parsing rules must support multiple formats.
Second, core fields involve cross-department unified data and non-standard content filled out offline. Parsing must accurately retain associations between fields.
Third, monthly updated batch data requires parsing processes to be repeatable and stable.
Fourth, the risk of incorrect or missed assistance determinations requires that parsing and chunking do not omit key basis for qualification determination such as family income and member relationships. Chunk content must retain integrity and contextual association.

## Configuration Settings
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents in this category include long-text family income verification details and household survey records. This range retains contextual association and avoids splitting key information |
| `chunkSplitter` | Split by title + paragraph | Documents in this category have standardized chapter structures. Splitting by title retains the association between chapter titles and corresponding body text, making it easier to locate complete business scenarios during subsequent retrieval |
| `customPdfParse` | Enable structured parsing | Most PDF documents in this category are standardized forms. Structured parsing accurately extracts fixed fields in forms and avoids missing key information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Cross-department shared batch data files may be large. This timeout range ensures complete parsing of all content and avoids mid-process interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets monthly updated batch cross-department data upload requirements, and supports storage and parsing of single-batch files |
| `chunkSettingMode` | Manual configuration | Document structures in this category vary widely. Manual configuration allows flexible adjustment of chunking rules to adapt to different types of business documents |

## Three Common Mistakes
- Phenomenon: Local environments can normally parse uploaded docx or pdf files. After deploying the project to a server and uploading the same file, the document parsing node returns a 404 error. Cause: The server side has not configured the correct file storage path, or the front-end upload request does not carry access credentials that meet server permission requirements.
- Phenomenon: After enabling `customPdfParse`, some family income fields in standardized forms are not correctly extracted. Cause: Some forms in this category have non-standard field naming. The preset template for structured parsing does not match the actual field format.
- Phenomenon: After uploading a multi-chapter household survey form, the chunking result loses the association between democratic appraisal records and corresponding applicant information. Cause: `chunkSize` is set too small, splitting associated information in the same paragraph into different chunks and causing contextual breaks.

## How to Confirm Configurations Are Correct
- Upload a standardized minimum livelihood guarantee application PDF, and check if the parsing result includes preset core fields such as family address, income details, and member relationships.
- Upload a multi-chapter household survey form, and verify that the chunking result retains the association between chapter titles and corresponding body text, with no contextual breaks.
- Upload a cross-department shared data file of approximately 800 MB, and confirm that the parsing process does not trigger a timeout error and all content is correctly extracted.
- View the parsing logs of the file collection, and confirm that there are no error records of 404, missing fields, or timeouts.

The values given are common starting points and should be measured against the reader's own samples.
