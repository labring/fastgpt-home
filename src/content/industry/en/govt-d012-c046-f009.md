# Internal Office and Employee Services for Social Assistance and Minimum Living Security Review: Model Integration and Configuration

## What this category of data looks like
Typical documents for this category include minimum living security application forms, family economic status verification reports, household survey forms, democratic appraisal records, public notice materials, and assistance approval forms. Data sources include the low-income population dynamic monitoring platform, resident family economic status verification system, and shared data from public security, human resources and social security, medical insurance, housing construction, and tax authorities. The update frequency is monthly. Data fields include family income and property details, family member relationships, household survey records, approval information, and more. Common units are monetary amounts, headcounts, dates, and similar metrics. This is cross-departmental heterogeneous structured and semi-structured data.

## Constraints on model integration and configuration
Cross-departmental heterogeneous data requires model integration to adapt to multi-source data formats. Configure model calls that support multiple data sources. Monthly update frequency does not require ultra-high-frequency context refresh, so context update intervals can be limited. Complex fields require accurate extraction of core information such as family economic status and member relationships, which places high demands on model output confidence. The most time-consuming verification link requires configuring tool call capabilities to support automatic cross-departmental data verification. The consequences of errors are severe, so strict control of model output accuracy is necessary to avoid incorrect or missed assistance approvals.

## Configuration guidelines
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapt to the total length of documents related to family economic verification |
| `temperature` | `0.1–0.3` | Ensure high confidence in verification results and avoid subjective bias |
| `toolChoice` | auto | Support automatic calling of cross-departmental data verification tools |
| `maxTokens` | `1000–2000 token per rerank task` | Limit the input length of the rerank model to avoid GPU memory overflow |
| `quoteMaxToken` | `2000–3000 characters` | Retain original fragments of core verification reports for review |
| `AIPROXY_API_ENDPOINT` | Deployed internal API address | Connect to internal model channels |
| `AIPROXY_API_TOKEN` | Authentication key assigned by the platform | Complete identity verification for model channels |

## Three common configuration mistakes
- Issue: No available channels appear on the OneAPI page, and the channel list is empty. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not configured correctly, or the configuration content has format errors.
- Issue: GPU memory remains occupied after the rerank model runs, eventually exhausting all available memory. Cause: No `maxTokens` limit is set for the input length of rerank tasks, and GPU memory automatic recycling configuration is not enabled.
- Issue: The model selection dropdown is unavailable in the workflow text extraction node, with no selectable options. Cause: Connected models are not correctly bound to workflow nodes, or the `toolChoice` configuration does not meet the model access requirements of the node.

## How to confirm successful configuration
- Access the OneAPI page of FastGPT v4.17.0, confirm that the configured model channel appears in the channel list.
- Upload a minimum living security application form document, run a parsing task, and check whether extracted fields such as family economic status and member relationships are complete.
- Start a rerank model test task, confirm that GPU memory usage does not continue to rise after running, and remains within a reasonable range.
- Enter the workflow editing page, open the model selection dropdown of the text extraction node, and confirm that the configured models are selectable.
