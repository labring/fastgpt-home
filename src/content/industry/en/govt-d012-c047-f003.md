# Internal Office and Employee Services for Administrative Penalty Case Handling: Multi-turn Dialogue and Prompt Engineering

## What this category's data looks like
Typical entities for this category include law enforcement agencies such as market supervision, ecological environment, transportation, emergency management, and urban management. Daily documents include on-site inspection records, interrogation transcripts, evidence lists, administrative penalty prior notice letters, hearing notice letters, penalty decisions, and service receipts.
Data sources include administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information publicity system, and departmental supervision databases. Update frequency is daily synchronization.
Single case data includes fixed evidence materials, discretion basis, document templates, service records, and more. Fields cover illegal subject information, law enforcement node status, evidence association identifiers, and more. Data has no unified standardized format and must be isolated per individual case.

## Constraints for multi-turn dialogue and prompt engineering
Due to multi-source, heterogeneous data sources and the requirement to isolate per individual case, multi-turn dialogue must bind a unique identifier to prevent context from crossing cases. Daily updated data sources require the knowledge base to support incremental synchronization to avoid old data interfering with current case handling.
Core case handling steps rely on accurate matching of evidence and documents. Prompts must guide calls to documents within the target case to avoid generating content disconnected from evidence. Strict law enforcement compliance requirements also apply: dialogue must restrict generation of unaudited content, and only call stored law enforcement documents.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Max Context Length | 8000–12000 characters | Adapt to the total length of multiple documents in a single case to avoid truncating key evidence content |
| Single Search Limit | Top 6 entries | Match the number of core documents for a single case to avoid introducing irrelevant cross-case materials |
| `chatId` Binding Rule | One-to-one correspondence with case handling ID | Ensure multi-turn dialogue only associates exclusive documents and context for the current case |
| `variables` Configuration | Bind law enforcement subject type and case status variables | Guide prompts to adapt to document generation rules for different law enforcement scenarios |
| `messages` History Retention | Retain up to 20 rounds of dialogue for the current case | Avoid overly long context interfering with prompt logic for current case handling steps |
| Question Optimization Switch | Enabled | Assist in sorting out vague questions from law enforcement personnel to accurately match corresponding law enforcement documents |

## Three common configuration mistakes
- Phenomenon: The answer returned by the API differs from the output of the platform test interface. Cause: The `chatId` and current case handling ID are not bound in the API request, resulting in unisolated dialogue context and calling knowledge base content from non-target cases.
- Phenomenon: Generated penalty documents omit key evidence content. Cause: The single search limit is not configured, introducing irrelevant cross-case documents, causing prompts to confuse evidence information from different cases.
- Phenomenon: The floating dialog box embedded in the webpage cannot load historical conversation records. Cause: Historical conversation content for the `messages` parameter is not passed correctly, resulting in failure to load context normally.

## How to verify correct configuration
This verification is based on the feature logic of FastGPT v4.17.0.
- Initiate a platform test conversation, input the name of the illegal subject for the current case, and confirm returned content only associates uploaded documents for that case.
- Include the `chatId` parameter when calling the API, compare the answers from the platform test interface and the API to confirm consistent results.
- After embedding the floating dialog box, send multiple consecutive questions to confirm historical conversation content is correctly retained and associated with the current case.
- Check the `variables` configuration to confirm law enforcement scenario variables are bound, and verify the prompt guides calls to corresponding law enforcement document templates.
