# Internal Office and Employee Services for Administrative Penalty Case File Handling: Tool Calling and Plugins

## What This Category’s Data Looks Like
The data for this category comes from administrative law enforcement case handling systems, law enforcement recorder footage, the national enterprise credit information publicity system, and departmental supervision databases, and is updated daily. Daily documents include on-site inspection records, questioning transcripts, evidence lists, prior administrative penalty notification letters, hearing notification letters, penalty decisions, and service receipts. The core focuses are illegal facts and penalty decisions, requiring the formation of traceable evidence chains and complete document chains. Fields cover law enforcement subjects, involved subjects, illegal circumstances, discretion basis, document numbers, and more.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Workflow
Data sources are scattered and include unstructured law enforcement recorder footage, which requires tool calling to support multi-source data pulling and format conversion. Various law enforcement documents have fixed structures but strict field requirements, so tools must accurately match preset field extraction rules. Daily updated law enforcement data requires high-frequency synchronization, so tool calling must adapt to high-frequency request scenarios. Consistency between penalty decisions and evidence chains must be ensured, tool outputs must be traceable, field missing or logical contradictions must be avoided, and differences in document formats across different law enforcement departments must be accommodated.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to scenarios where tools are called on demand across multiple links, covering different office needs such as transcript generation, legal provision matching, and case file review |
| Single tool call timeout | 60 seconds | Matches the standard response duration for law enforcement document generation, avoiding long-term blocking of internal office workflows |
| Tool return field extraction rules | Configure mapping according to law enforcement document fields | Corresponds to fixed document structures such as on-site inspection records and penalty decisions, ensuring extracted content accurately matches business requirements |
| Plugin request concurrency limit | Top 3 requests | Adapts to the interface rate limiting rules of most law enforcement systems, avoiding triggering access restrictions |
| Context window size | 8000–12000 token | Accommodates content from multiple law enforcement transcripts, evidence lists, and other materials, supporting tool calling analysis for complete case files |

The configurations on this page apply to FastGPT v4.17.0

## Three Common Misconfigurations
- An internal server error prompt appears when importing a custom plugin. The cause is that the interface address configured for the plugin does not adapt to the intranet access rules of the law enforcement system, or the request header does not carry valid identity verification parameters.
- A prompt stating only stdio processes are supported appears when calling an MCP tool. The cause is that the current version does not enable tool calling adaptation for the SSE protocol; version compatibility must be confirmed.
- Extracted interface fields are empty after tool calling. The cause is that no extraction rules matching the law enforcement document fields have been configured, making it impossible to locate target content.

## How to Confirm Configurations Are Correct
- After importing the plugin, use a simulated law enforcement interface to initiate a test request, and check whether the return status code is 200.
- Set `toolChoice` to auto, initiate a test that includes multi-link requirements, and confirm that the tool can automatically call corresponding functions on demand.
- After configuring the field extraction rules, upload a standard on-site inspection record, and check whether extracted fields such as law enforcement subject and illegal time match the preset rules.
- Initiate consecutive test requests, and confirm that no interface rate limiting or timeout errors are triggered.
