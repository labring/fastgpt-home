# Internal Office and Employee Services for Administrative Licensing and Approval: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Typical entities for this category include government service centers, administrative approval bureaus, and industry authority approval departments. Daily generated documents include service guides, application forms, commitment letters, acceptance notices, correction notices, administrative licensing decision documents, and license certificates. Data sources cover the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate database. Data is synced daily for updates. Document structures include both structured fields and unstructured text. Structured fields include item code, handling conditions, and application material list. Unstructured text includes service process descriptions and approval opinion templates. Each document corresponds to a single legal licensing item.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
The daily updated data source requires the recall logic to sync with the latest item lists and electronic certificate data, to avoid using expired licensing bases. The structure where a single item maps to multiple document types requires retrieval to adapt to matching rules for both structured fields and unstructured text. Administrative licensing requires strict matching with legal bases and handling conditions, so retrieval accuracy demands are high, and irrelevant recall results must be filtered. Cross-departmental certificate data sources require recall to support associated queries across multiple data sources, letting approval staff quickly retrieve required electronic certification materials. Additionally, the verification step in the approval process relies on accurate material matching, so recall results should be sorted to prioritize the most relevant licensing bases and application material lists.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Administrative licensing items require precise matching of handling conditions and application materials. This range filters irrelevant recall results and avoids mismatched legal licensing items |
| `limit` | Top 5–8 entries | The number of materials and basis items to verify in a single approval scenario is limited. This range controls the context length to avoid exceeding the model's processing limit |
| `searchMode` | Hybrid retrieval | Balances structured item list fields and unstructured service guide text to meet different types of business query needs |
| `usingReRank` | Enabled | Performs secondary sorting on recall results to correct deviations from single vector retrieval, ensuring the most relevant licensing basis is returned first |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands query terms, supplements legal names and aliases of items, to cover expression habits of different staff positions |
| `collectionIds` | Bind exclusive approval knowledge base collection | Isolates data related to administrative licensing such as service guides and certificate libraries, to avoid confusion with other business knowledge bases |

## Three Common Configuration Mistakes
- Phenomenon: After uploading a multi-column Excel format application form or item list, the automatic segmentation result disrupts the original row structure, and it is impossible to treat each row as an independent segment. Reason: The adaptive setting for row-wise chunking of structured table files is not enabled, and the default automatic segmentation logic merges adjacent row data based on content semantics.
- Phenomenon: Expired licensing item documents have been deleted from the local knowledge base, but the corresponding content is still returned as a reference during retrieval. Reason: The vector index cache of the knowledge base has not been refreshed, and old data remains in the recall vector database.
- Phenomenon: Retrieval results exceed the preset reference upper limit, and low-relevance non-licensing content is returned first. Reason: The `similarity` threshold is not set or is set too low, and the re-ranking function to filter irrelevant results is not enabled.

## How to Verify Proper Configuration
- Upload a test multi-column administrative licensing application form Excel file, check whether the segmentation results treat each row of content as an independent block without cross-row merging.
- Manually enter a low-relevance non-licensing query term, verify that retrieval results are filtered by the `similarity` threshold, with no irrelevant entries returned.
- After enabling `usingReRank`, compare the recall sorting results before and after enabling, confirm that the most relevant licensing basis and handling conditions are ranked first.
- Check the knowledge base collection binding configuration, confirm that only administrative licensing-related datasets are selected, with no other irrelevant business data mixed into the recall scope.
- Trigger a knowledge base update sync, verify that the retrieval results include the latest administrative licensing item data.

The values given are common starting points and should be measured against the reader's own samples.
