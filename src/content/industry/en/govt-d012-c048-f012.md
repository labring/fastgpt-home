# Internal Office and Employee Services for Administrative Licensing and Approval: Deployment and Upgrade

## What Data for This Category Looks Like
The core data for this category comes from the national integrated government service platform item database, administrative licensing item list, departmental business approval systems, and electronic certificate database, and is updated once daily. Daily involved documents include service guides, application forms, commitment letters, acceptance notices, correction notification letters, administrative licensing decision documents, and various license certificates. Structured documents such as application forms include subject information and application item fields. Unstructured documents such as approval decision documents include legal basis and approval opinion fields. Certificate documents include unified identification numbers and subject association information.

## What Constraints These Characteristics Impose on the Deployment and Upgrade Phase
This category’s data sources cover multiple departmental business systems and government item databases, with daily updates, and include both structured and unstructured documents. Approval processes must strictly match legal basis. This requires that the deployment phase must support multi-source data access, and the upgrade phase must ensure data synchronization is not interrupted. Administrative licensing items must be accurately associated with legal setting basis, so knowledge base retrieval must be bound to precise entries in the item database, and a fixed item database synchronization node must be configured during deployment. At the same time, storage of approval documents and certificates must comply with government data security specifications, so encryption storage configuration must be enabled during deployment, and a data verification window must be reserved during upgrades to avoid abnormal document field parsing caused by version updates.

## How to Configure Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Intranet-compliant government cloud MongoDB instance address, set `DB_MAX_LINK` to `20–30` | Adapts to daily multi-source approval data synchronization and retrieval volume, avoids connection exhaustion |
| `REDIS_URL` | Intranet-exclusive Redis cache instance address, set cache expiration time to `86400 seconds` | Caches daily updated item database data, matches data synchronization frequency |
| `STORAGE_S3_ENDPOINT` | Government cloud object storage intranet endpoint | Stores approval documents and certificates, complies with government data storage compliance requirements |
| `FILE_TOKEN_KEY` | Custom high-strength encryption key | Encrypts stored uploaded documents such as application forms and decision documents |
| `FE_DOMAIN` | Intranet domain exclusive to internal office systems | Restricts frontend access scope, ensures access security for internal office scenarios |
| `ROOT_KEY` | Exclusive key only authorized for operation and maintenance personnel | Controls platform highest permissions, prevents unauthorized personnel from modifying approval knowledge base configurations |

## Three Common Mistakes
- Symptom: A `400 Bad Request` error occurs when configuring large model tool calls, and the built-in workflow test tool cannot be triggered. Cause: No model access whitelist is configured in the intranet environment, and the correct tool call workflow is not bound.
- Symptom: After executing the Docker upgrade command, dependent services fail to start, and approval knowledge base synchronization is interrupted. Cause: Dependent services were not stopped in advance, and directly overwriting the image caused configuration file conflicts.
- Symptom: Knowledge base retrieval returns more document chunks than the preset reference limit. For example, when the chunk size is set to 5000 tokens, content exceeding 1500 tokens is still returned. Cause: The reference limit verification logic is not enabled in the retrieval configuration, and the chunk parameter is not matched and associated with the reference limit.

## How to Confirm the Configuration Is Complete
- Run an intranet connectivity test to verify that the service instances corresponding to `MONGODB_URI` and `REDIS_URL` can be accessed normally
- Upload an administrative licensing decision document, check that the document storage path conforms to the `STORAGE_S3_ENDPOINT` configuration, and that normal retrieval is possible
- Initiate an item database synchronization task, confirm that synchronization time matches the `86400 seconds` cache expiration configuration, and no data loss occurs
- Attempt to trigger a tool call test, verify that the built-in workflow tool can be called normally, with no errors returned
