# Internal Office and Employee Services for Fiscal Expenditure Performance Evaluation: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The data for this category comes from the unified budget management system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys. The update frequency is annual. Daily documents include performance target forms, self-evaluation forms, performance evaluation reports, supporting material lists, and rectification reports. Fields cover project numbers, fund amounts, performance indicators, completion status, supporting material numbers, and other items. Units are mostly yuan, items, and person-times. Data must link fund payments with performance target completion status. No temporary supplementary cross-year data exists.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering Workflows
The annual update requirement means multi-turn dialogue contexts must be bound to the current year’s project pool. This avoids interference from cross-year data. The mixed structure of multiple document types requires prompts to clearly distinguish between performance targets, self-evaluation results, and supporting materials. This guides conversations to focus on corresponding types of information. The requirement to link fund and performance fields means conversations must clarify project dimensions. This avoids result deviations from vague queries. The low data update frequency means there is no need to frequently refresh the full index. Annual vector database resources can be fixedly linked to reduce system load.

## Common Configuration Mistakes
Three frequent configuration errors are listed below:
- Phenomenon: After refreshing the page, the interface displays the prompt "No available index model detected". Cause: The vector database for annual performance data is not bound to the current `chatId`. The index resource linked by the session context has expired or not been initialized.
- Phenomenon: Conversation response results do not include the associated identifier or path of the source original text. Cause: The prompt does not explicitly require associating document information of corresponding supporting materials. Source tracing configuration is not enabled.
- Phenomenon: After a multi-turn dialogue is interrupted and restarted, the previous performance project query logic cannot be continued. Cause: The `chatId` is not saved or bound. The context is lost after restarting the session, making it impossible to link to the previous project dimension.

## How to Verify Successful Configuration
- Initiate a single-project performance self-evaluation query. Check whether the returned results include the corresponding year’s performance indicators and fund data.
- View the conversation history. Confirm that the session context bound to `chatId` is not lost after page refresh.
- Trigger the source tracing function. Confirm that the returned results include the identifier information of the corresponding supporting materials.
- Initiate a query after injecting the annual variable. Confirm that the conversation content strictly follows the current year’s performance evaluation standards.
