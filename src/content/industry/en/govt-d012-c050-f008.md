# Internal Office and Employee Services for Fiscal Expenditure Performance Evaluation: Document Parsing and Chunking

## What data for this category looks like
Typical data for this category comes from daily work documents of fiscal bureau performance offices, budget units, and third-party evaluation institutions. These documents include performance target forms, self-assessment forms, performance evaluation reports, supporting material lists, and rectification reports.
Data sources cover the budget management integration system, project declaration materials, fund payment data, business system ledgers, and satisfaction surveys.
Data is updated on an annual basis. Single-year materials include associated documents for multiple projects.
Supported formats include tables, long text, and list-style files. Some data is exported across systems, resulting in differences in layout and encoding.

## What constraints these characteristics impose on document parsing and chunking
The annual update requirement means chunking logic must adapt to both batch historical documents and single-year new materials, without requiring high-frequency real-time processing.
The presence of multiple document types means parsing tools must simultaneously support table-style performance forms, long-text evaluation reports, structured lists, and other formats. This avoids truncating table content or breaking semantic coherence in long text.
Differences in format from cross-system exported data means parsing logic must have appropriate compatibility to adapt to files with different encodings and layouts.
Collecting supporting materials is the most time-consuming step. Chunking must accurately associate performance indicators with their corresponding supporting materials. Failing to preserve business logic during chunking will reduce the accuracy of subsequent performance scoring.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of performance evaluation reports and the length of individual entries in supporting materials, avoiding semantic fragmentation |
| `chunkSplitter` | Split by title + paragraph | Matches the chapter structure of performance targets, self-assessment status, rectification suggestions, and other sections in documents, preserving complete business semantic integrity |
| `customPdfParse` | Enabled | Adapts to complex layouts such as tables, headers, and footers in performance reports, extracting accurate structured text |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Single-year performance material packages may include multiple associated documents, reserving sufficient parsing time |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Covers the total size of materials for all projects in a single year, preventing upload interruptions |

## Three common mistakes
- Console error `Cannot redefine property: toString`: A custom PDF parsing script redefines the global `toString` method twice, or existing scripts conflict with built-in parsing logic after upgrading to FastGPT v4.17.0.
- Total number of knowledge base chunks exceeds 3000, making indexing impossible: Annual performance materials are not split into single-project documents, and `chunkSize` is set too low, causing the number of chunks per file to exceed system limits.
- The same CSV file fails to chunk correctly after a version upgrade: Default CSV parsing encoding changes after a version update, and the encoding format of the originally exported file is not adapted, leading to parsing failure.

## How to confirm configurations are set correctly
- Upload a single performance evaluation report, view the chunk preview interface, and confirm that each chunk contains complete performance indicators or corresponding supporting material entries.
- Upload an annual project material package, check the total chunk count preview, and confirm that abnormally high chunk counts do not appear.
- Test parsing effects for different format documents (Excel performance forms, PDF rectification reports, CSV fund payment data), confirm that table content is not truncated, and text extraction is complete.
- View system parsing logs, confirm that `Cannot redefine property`-type errors do not appear, and parsing processes do not trigger timeouts.
