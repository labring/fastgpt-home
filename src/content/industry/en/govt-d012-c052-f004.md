# Internal Office and Employee Services for Department Final Accounts and Financial Reports: Workflow Orchestration
This document is written for FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system. The update frequency is annual. Daily produced documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Each document contains fields such as income and expenditure details, asset and liability balances, budget execution difference explanations, and more. Units are mostly ten thousand yuan and person-times. Reports must be filled out strictly in accordance with unified fiscal standards.

## What Constraints These Characteristics Impose on Workflow Orchestration
The fixed annual update frequency requires workflows to adapt to batch annual data processing and avoid single-run timeouts. Data from multiple systems must be pulled across systems and aligned in format within the workflow, and targeted verification nodes must be configured. Structural differences across multiple document types require workflows to configure different field extraction rules per document type to ensure uniform reporting standards. Cross-level unit report summary tasks require setting node timeouts and retry mechanisms to address system response delays across different units.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` binding | Bind annual final account cycle and unit code parameters | Adapt to annual triggers and multi-unit data differentiation |
| `nodeId` mapping | Bind corresponding node IDs by document type | Match exclusive processing flows for each report |
| Node timeout settings | 600–1200 seconds | Address delays from cross-system data pulling and multi-unit report summarization |
| Data format verification | Configure field verification rules per report type | Match uniform reporting standards for each document |
| Retry mechanism | Retry 2 times after failure, 120-second interval | Address temporary system interface fluctuations |
| Long text splitting | 800–1000 characters per segment | Adapt to segmented sending of long documents such as final account explanations |

## Three Common Mistakes
- Incorrect configuration of workflow judgment node rules results in all match results falling into the ELSE branch. The cause is failing to clarify the correspondence between judgment conditions and branches, and binding equal-to and prefix-matching rules to the ELSE branch.
- Parameters passed by the system are not correctly identified, resulting in empty global variables. The cause is failing to configure system parameter binding items in the workflow trigger node, and failing to complete parameter passing via `variables`.
- Long text returned by the HTTP API is not segmented per rules, resulting in single-node sending limit violations. The cause is failing to configure specific rules for long text splitting, and failing to split sent content by document length.

## How to Confirm Proper Configuration
- Trigger the workflow with the annual cycle parameter, check the match between trigger time and final account year, and confirm that the `variables` bound parameters are correct.
- Run the cross-system data pulling node, check the consistency between data formats returned by each system and preset verification rules, and confirm that the data format verification configuration is effective.
- Call the HTTP API to obtain long text data, test the segmented sending function, and confirm that each segment's text length meets the transmission requirements of business documents.
- Simulate a node failure scenario, check the trigger and execution status of the retry mechanism, and confirm that the timeout and retry configuration is active.
