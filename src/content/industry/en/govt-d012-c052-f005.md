# Internal Office and Employee Services for Department Final Accounts and Financial Reports: Tool Calling and Plugins

## What This Category’s Data Consists Of
All data for this category comes from the budget management integrated system, centralized treasury payment system, accounting system, and asset management system. The update cycle is annual. Daily output documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. Document fields cover income and expenditure details, asset and liability balances, budget execution difference explanations, and more. Units are primarily yuan and ten thousand yuan. Some reports require aggregating subordinate unit data across hierarchy levels.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
The annual update cycle eliminates the need for frequent tool calls. A fixed annual data source range can be bound. Heterogeneous data sources across multiple systems require plugins to support cross-system data pulling and format standardization. Complex multi-document structures require tool calls to support parsing specified report fields by module, and completing field and unit mapping. The need to aggregate subordinate unit data requires plugins to have hierarchical data aggregation capabilities. Set a data volume limit for single calls to avoid timeouts.

## Configuration Settings
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set based on actual testing | Adapt to the need for multi-tool collaborative calling in department final account scenarios, supports automatic matching or specifying corresponding tools |
| `functionCall` | Force enable | Ensure tool calls strictly follow preset rules, adapt to field extraction and mapping requirements for structured reports |
| Tool call timeout | 600 seconds | Cross-system pulling of annual aggregated data takes a long time, reserve sufficient processing time |
| Single tool call data limit | First 800–1200 entries | Control the volume of data returned per call to avoid exceeding context window limits |
| Tool call retry count | 2 times | Balance data pulling success rate and overall processing duration, adapt to the processing rhythm of annual batch data |

## Three Common Misconfigurations
- When calling a chart tool to generate a visual chart for final account statements, the output is empty. The cause is that the income and expenditure detail fields of final account data are not correctly mapped to chart display dimensions, so the tool cannot obtain valid data.
- A 400 error is returned when selecting a tool in a workflow. The cause is that the configured tool call parameters do not match the format requirements of department final account data, or the single call data volume exceeds system limits.
- An error is triggered when using a non-Qwen series model to call tools. The cause is that some models have differing support for the `functionCall` format, and do not adapt to the calling rules for department final account structured data.

## How to Confirm Proper Configuration
- Initiate a single tool call to pull core fields of a single department final account statement, and check whether the returned data matches the source system data.
- Test the cross-system data pulling process to confirm that corresponding data can be obtained from both the budget management integrated system and the accounting system.
- Trigger the tool call retry logic to verify that the system will automatically retry the configured number of times after a single call fails, and complete data aggregation.
- View tool call logs to confirm that parameters in the `functionCall` format are correctly parsed, with no format errors.

The values provided are common starting points and should be evaluated against the target deployment’s own sample datasets.
