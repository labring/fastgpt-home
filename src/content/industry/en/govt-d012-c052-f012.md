# Internal Office and Employee Services for Department Final Accounts and Financial Reports: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from the unified budget management system, centralized treasury payment system, accounting system, and asset management system, with an annual update frequency. Daily processed documents include department final account statements, balance sheets, income and expenditure final account statements, final account explanations, and government financial reports. The overall structure primarily consists of structured reports paired with unstructured explanation documents. Data fields must match the unified standardized format of the finance department. Units include common fiscal measurement standards such as yuan and ten thousand yuan. Budget units at different levels have a nested hierarchy in their report fields.

## What constraints these characteristics impose on deployment and upgrade
The annual centralized data processing, multi-source system association, and strict document format requirements for this category create multiple constraints for deployment and upgrade. First, annual centralized final account data imports require stable concurrent connections to avoid resource exhaustion during batch processing. Second, multi-source data association requires configuring connection permissions for multiple systems during deployment, and compatibility with data format differences across systems. Third, strict document structure requirements require presetting parsing templates that match fiscal standards during deployment, and avoiding accidental overwriting of templates during upgrades. Fourth, the severity of potential errors requires completing a full data backup before upgrades, and reserving sufficient rollback windows.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15` | Matches concurrent database connection requirements during department final account batch imports, prevents connection pool exhaustion |
| `MONGODB_URI` | Set based on actual testing | Used to store unstructured documents of historical final account reports, must match the authentication and permission configuration of the existing MongoDB cluster |
| `PG_URL` | `postgresql://{username}:{password}@{host}:{port}/{database name}` | Used to associate structured data from the centralized treasury payment system, must match the configuration of the associated PostgreSQL instance |
| `REDIS_URL` | `redis://:{password}@{address}:6379/0` | Used to cache report parsing results and user sessions, default port 6379 complies with general deployment specifications |
| `STORAGE_S3_ENDPOINT` | Configured using the internal object storage service address | Used to store attachment documents for annual final accounts, must adapt to the access permissions of the existing storage architecture |
| `ROOT_KEY` | 32-character random string | Used to secure access to system backend interfaces, must be generated through the internal key management system |

## Three common mistakes
- Only entering the host address without specifying a port when configuring `PG_URL`, leading to database connection failure. This occurs because the PostgreSQL instance associated with department final accounts uses a non-default port, and the port information is not added to the connection string.
- After upgrading to FastGPT v4.17.0, the previously configured voyage index returns a 400 status code with no response body. This occurs because the new version updates the validation logic for index parameters, and the previously configured index dimensions do not match the default requirements of the new version.
- Failing to migrate old vector database data after upgrading to a new version, leading to loss of search functionality for historical final account reports. This occurs because full migration and incremental synchronization configuration for the vector database are not completed in advance according to the annual data update cycle.

## How to confirm proper configuration
- Run a database connection test to verify that structured data from the treasury payment system can be retrieved normally.
- Upload a single department final account report to confirm that the parsed data fields match the document structure specified by fiscal standards.
- Enable backend service log collection to check whether connection errors for `REDIS_URL` and `STORAGE_S3_ENDPOINT` have been resolved.
- Configure a vector generation task for a single report to observe whether the task completes normally without errors.
