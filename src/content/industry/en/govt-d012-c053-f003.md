# Internal Office and Employee Services for Department Budget Preparation: Multi-turn Dialogue and Prompt Engineering

## What Data Does This Use Case Involve?
The data for this use case typically comes from the unified budget management system, departmental staffing establishment system, prior-year final account data, project repository, and annual budget preparation notices issued by the national finance authority. Daily output documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approval documents, and similar materials. Fields mostly involve staffing counts, project expense amounts, performance indicator values, and similar metrics. Units include ten thousand yuan, person, item, and similar units. Data updates occur annually, with only one core update completed per budget preparation cycle.

## What Constraints Do These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering?
The annual update requirement requires multi-turn dialogue to be tied to clear cycle context to avoid mixing cross-year data. Multiple heterogeneous data sources require prompts to clearly distinguish field rules across different systems, such as differentiating project codes from the unified budget management system and application numbers from the project repository. Diverse document types require prompts to adapt to different format requirements, such as matching the per-person standard for the personnel expense calculation form to on-staff count data from the departmental staffing establishment system. The process of consolidating subordinate unit budgets requires multi-turn dialogue to pass data hierarchically, ensuring that calculation results from lower-level units can be called by higher-level units. Fixed business variables must also be clearly passed during dialogue to avoid data matching errors caused by missing parameters.

## How to Configure Settings
The following configurations are based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Context Window Limit | 8000–12000 token | Accommodates the total length of multiple budget documents and prevents truncation of core calculation data |
| `chatId` binding rules | Generate a unique identifier based on budget unit + year | Isolates dialogue contexts across different units and cycles to prevent interference from cross-cycle data |
| `variables` binding parameters | Budget year, unit hierarchy, project repository source | Fixes business variables to ensure prompts call the correct data sources and field rules |
| `messages` format requirements | Store complete history in alternating user/assistant format | Complies with standard parsing logic for multi-turn dialogue, ensuring the model can reuse previous round calculation results |
| History cleanup trigger | Triggered at the end of the annual budget cycle | Matches data update frequency and avoids redundant data occupying storage space |
| Maximum number of turns per dialogue | 15–20 turns | Adapts to the multi-step review process of budget preparation and prevents model confusion caused by overly long context |

## Three Common Misconfigurations
- Phenomenon: Cross-year budget data appears in dialogue history, leading to incorrect calculation results. Cause: `chatId` is not bound by budget unit + year, causing contexts from different cycles to be mixed.
- Phenomenon: Multi-turn dialogue cannot reuse previous round calculation results as input basis for the current round. Cause: Complete dialogue history is not stored in alternating user/assistant format in `messages`, so the model cannot access historical conclusions.
- Phenomenon: Dialogue history generated during debug preview cannot be cleaned in batches, occupying workspace storage space. Cause: No history cleanup rule triggered by the annual budget cycle is configured, only manual deletion of single records is supported.

## How to Verify Correct Configuration
- Create a test dialogue, input cross-year budget data queries, and check that returned results only include the dataset bound to the current year.
- Initiate two consecutive calculation dialogues, and check that the second dialogue can automatically call the project expense calculation results generated in the first dialogue.
- Enter the dialogue management page of the workspace, trigger the cleanup rule for the end of the annual budget cycle, and check that historical records from the corresponding cycle are deleted in batches.
- View the `variables` parameter configuration page, confirm that fixed business variables such as budget year and unit hierarchy are bound, with no missing items.
