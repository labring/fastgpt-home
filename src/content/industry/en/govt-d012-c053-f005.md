# Internal Office and Employee Services for Department Budget Preparation: Tool Calling and Plugins

## What the data for this category looks like
Department budget preparation-related data primarily originates from the unified budget management system, department staff establishment system, prior-year final accounts, project library, and Ministry of Finance budget preparation notices. Data is updated annually, aligning with the annual capital application and allocation cycle. Daily output documents include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approvals. Fields include unit codes, staff establishment numbers, project expense amounts, performance indicator values, etc., using standard fiscal formats such as ten thousand yuan, persons, and project numbers.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Annual updated data sources require tool calling cache cycles to match the fiscal year schedule, preventing cross-year data mixing. Plugins must connect to separate internal systems for multiple heterogeneous data sources. Each system’s interface format and field rules differ, so targeted field mapping logic must be configured. The large volume of documents and strict field standards mean tool calls must accurately extract specified fields from target documents. Budget submissions may be returned for revision if extraction is inaccurate. When batch processing subordinate unit budget data, limit the number of units per call to avoid interface overload disrupting the overall workflow.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call timeout | `600 seconds` | Department budget data interfaces typically pull data from multiple sources, resulting in longer response times |
| `toolChoice` | `auto` | Supports automatic selection of tools suited for budget data processing, covering query, extraction, aggregation and other scenarios |
| `functionCall` | `Bind budget toolset` | Limits call scope to avoid unrelated tools interfering with budget preparation workflows |
| Plugin batch call limit | `First 10 entries` | The number of budget units reported by subordinate units in a single submission typically does not exceed 10, adapting to regular office scenarios |
| Context window size | `8000 token` | Must accommodate multiple budget documents and complete data returned by systems to ensure contextual integrity for tool calls |
| Field mapping rules | `Configure per budget document standards` | Ensures extracted fields comply with department budget specification formats and match audit requirements |

## Three common mistakes
- An "only stdio processes are supported" prompt when calling MCP tools: Cause: Used an MCP configuration wrapped with SSE protocol, which does not match the process types supported by FastGPT.
- Successful interface calls but extracted budget fields are empty: Cause: No field mapping rules configured, and no specified fields to extract from department budget documents.
- Call timeout after publishing as an API: Cause: Tool call timeout configuration was not adjusted; the default timeout duration is insufficient for pulling multi-source budget data.

## How to confirm configurations are correct
- Trigger a tool call and check if the configured budget-related toolset was called.
- Call the test interface to verify that the returned results include specified fields from department budget drafts and personnel expense calculation forms.
- Simulate a batch submission scenario to check if tool calls comply with the set batch limit.
- View plugin operation logs to confirm that connected system interfaces can normally pull data.
