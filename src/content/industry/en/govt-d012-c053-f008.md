# Internal Office and Employee Services for Department Budget Preparation: Document Parsing and Chunking

## What this category of data looks like
Typical entities for this category include finance bureau budget departments, budget unit finance departments, and similar roles. Documents handled daily include department budget drafts, project application forms, performance target forms, personnel expense calculation forms, budget approvals, and similar materials. Data sources mainly include the budget management integrated system, department staff establishment system, prior-year final accounts, project library, and Ministry of Finance budget preparation notices. Update frequency follows annual centralized updates. Most documents contain structured tables and hierarchical text. Fields include project number, amount, number of staff, and similar items. Units include ten thousand yuan, person, project cycle, and similar items.

## What constraints do these characteristics impose on the document parsing and chunking step
The annual centralized update feature leads to a sharp increase in file uploads during budget season. Large-volume aggregate files account for a high proportion, so support for large file parsing and chunking is required. A large number of structured tables and numeric fields in documents require that chunking preserves field correspondence to avoid breaking data associations. Data from multiple sources may have format differences, so compatibility with document formats exported from different systems is needed. Additionally, errors in budget preparation will lead to audit failure. Chunking must accurately cover core business fields to ensure no key information is lost in subsequent retrieval and audit links.

## How to Configure
These configurations are based on FastGPT v4.17.0.

| Configuration Option | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Budget documents contain many tables and numeric fields. This range balances context completeness and chunk granularity, avoiding broken field relationships |
| `chunkSplitter` | Mixed chunking by table + paragraph | Budget documents have both structured tables and explanatory text. Mixed chunking preserves both table structure and text logic |
| `customPdfParse` | Enable structured table parsing | Documents such as performance target forms and personnel expense calculation forms contain many hierarchical numeric fields. Structured parsing preserves field correspondence |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Annual budget drafts may include multi-department aggregated data, with large file sizes. This supports large file upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large budget documents require processing multiple tables and data relationships. This duration covers standard parsing time |
| `chunkSettingMode` | Manual configuration | Budget document formats are fixed but field weights vary. Manual configuration accurately matches business parsing needs |

## Three Common Mistakes
- Phenomenon: Vectorization errors occur after chunking files larger than 10 MB. Retrying multiple times restores normal function. Cause: Temporary cache is not released promptly during large file parsing, leading to abnormal chunk metadata. Retrying resets the cache state.
- Phenomenon: Feishu online tables imported into the knowledge base have empty fields and cannot be retrieved normally. Cause: Budget tables contain many nested levels and formula references. Default parsing rules cannot recognize cross-table associated data.
- Phenomenon: The exported dataset.csv is a question-and-answer format template and cannot be directly used to generate a corresponding knowledge base. Cause: Structured data from budget documents is not correctly extracted as question-and-answer pairs. Only original text blocks are retained during export.

## How to Confirm Correct Configuration
- Upload a single annual budget draft file under 1000 MB. Check if core business fields such as project number and amount are retained in the chunk list.
- Test importing a Feishu online table. Confirm that the row and column structure of the imported table matches the source file, with no missing fields.
- Adjust the `chunkSize` parameter to the 800–1200 character range. Upload a test file and check if the chunk length matches the set value.
- View parsing logs. Confirm that the `PARSE_FILE_TIMEOUT_SECONDS` threshold is not triggered, and the parsing status shows completed.

The values given are common starting points and should be measured against the reader's own samples.
