# Internal Office and Employee Services for Department Budget Preparation: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The core data for this category comes from the unified budget management system, departmental staffing system, prior-year final accounts, project repository, and budget preparation notices issued by the Ministry of Finance. Daily produced documents include departmental budget drafts, project application forms, performance target forms, personnel expense calculation forms, and budget approval documents. The data update cycle is annual, with full updates completed only during the annual budget preparation period. Most document structures include fields such as project code, expense amount, performance indicators, and preparation instructions. Units of measurement mostly use ten thousand yuan and person-months.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The annual update requirement means the knowledge base must only perform incremental synchronization during the preparation period, to avoid redundant storage and cross-cycle data interference. Mixed structured and unstructured data from multiple sources requires the retrieval link to adapt to both table fields and natural language text, ensuring accurate matching of policy standards and expense criteria. For scenarios where subordinate unit budgets are aggregated, precise recall of historical budget data from the same level or lower-level units is needed, to prevent cross-departmental data from being included. Field differences across documents—such as coding rules for the project repository and policy standards in budget notices—require recall results to strictly match valid policy documents from the current preparation cycle. Unlike final account work that checks already disbursed funds, this link only covers the preliminary work of annual fund application and allocation. Therefore, the retrieval scope must be strictly limited to valid data within the annual preparation cycle, to prevent audit failures.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches policies and data related to budget preparation. Prevents irrelevant content from being retrieved if the value is too low, and avoids missing accurate entries if the value is too high. |
| `limit` | Top 8 entries | Adapts to the need for multiple document references in department budget preparation, while controlling context length. |
| `searchMode` | Semantic Retrieval | Adapts to mixed structured and unstructured budget documents, and aligns with semantic matching requirements for policy standards. |
| `usingReRank` | Enabled | Re-ranks initially retrieved results by relevance, improving sorting accuracy for long documents such as performance target forms and project application forms. |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms, adding synonyms related to budget preparation—for example, associating "personnel expenses" with "public expense calculation". |
| `collectionIds` | Specify the exclusive knowledge base ID for the current preparation cycle | Avoids interference from redundant cross-year or cross-department data, and accurately matches the data source for the current workflow. |

## Three Common Misconfigurations
- When `datasetSearchUsingExtensionQuery` is disabled, and custom knowledge base variables are passed dynamically, retrieval results cannot match accurate policy entries, and the returned results have no cited documents. This occurs because extended retrieval is not enabled, so synonyms or supplementary business terms cannot be associated.
- When the text understanding model list is empty during knowledge base creation, the configuration interface dropdown menu has no selectable options. This occurs because the corresponding model access key is not configured in the system backend, or the model version has not completed synchronization.
- When calling knowledge base retrieval, a timeout occurs or an empty result is returned, shown as a 504 status code in the interface response or zero results returned. This occurs because `collectionIds` is not limited to the current cycle's knowledge base, and retrieval of massive cross-year old data causes a timeout.

## How to Confirm Proper Configuration
- Trigger a budget preparation retrieval, check the cited sources of the returned results, and confirm that they include the current cycle's budget notices and project repository data.
- Check the configured value of `similarity`, and verify whether the relevance of the retrieval results meets business expectations.
- View the knowledge base synchronization logs, and confirm that only the current year's budget documents have completed index updates.
- Test passing different knowledge base variables dynamically, and confirm that the retrieval results change as the variables switch.

The values provided are common starting points and should be measured against the reader's own samples.
