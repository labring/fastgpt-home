# Internal Office and Employee Services for Flood Control, Disaster Prevention and Emergency Duty: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Daily documents for this category include duty logs, early warning notifications, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Data sources include meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Data updates daily. Some real-time monitoring data has shorter update intervals. Common document fields include duty periods, early warning levels, disaster-affected locations, material categories, and allocation quantities. Units include millimeters, cubic meters, number of people, and other units specific to emergency scenarios.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Decentralized data sources require multi-turn dialogue to retrieve information across systems. Integrate real-time data from different sources in chronological order within `messages`. Pass batch parameters via `variables` for daily updated batch documents to avoid overloading single-turn dialogue. Real-time requirements in emergency scenarios limit the maximum context window length. Prioritize retaining consultation minutes and rapid disaster reports from the last 24 hours. Clearly map specialized fields from different documents in prompts to prevent scheduling errors caused by field identification deviations. Divide dialogue records by duty teams to meet cross-departmental scheduling needs, and facilitate subsequent tracing and collaboration.

## Configuration Settings
The following configurations follow the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Group parameters by daily emergency data batches, with no more than 10 documents per group | Adapt to daily updated batch documents, avoid overloading single-turn dialogue parameters |
| `messages` | Retain dialogue and data records from the last 24 hours in the context window | Match real-time response needs in emergency scenarios, filter expired historical data |
| `chatId` | Assign independent conversation IDs by duty team | Differentiate duty dialogue records across teams, facilitate internal tracing and collaboration |
| Conversation opening quick buttons | Preset three options: flood control patrol, disaster situation reporting, material scheduling | Align with high-frequency operation scenarios in emergency duty, reduce manual input |
| Knowledge base answer citation display | Disable end citations by default, enable as needed | Adapt to the concise output requirements of internal office scenarios |

## Common Misconfigurations
- When configuring `variables`, do not group parameters. This leads to loading too many documents in a single-turn dialogue, and the interface displays "No permission to operate this conversation record". The cause is failing to limit the number of documents passed via `variables`, which exceeds the system's default context carrying limit.
- Enable end citations for knowledge base answers. This makes it impossible to hide citation content in internal office scenarios. The cause is failing to turn off the citation display switch in configurations, so citation identifiers remain by default.
- Do not preset high-frequency emergency operation buttons for conversation openings. This leads duty personnel to manually input repeated questions. The cause is failing to configure quick options aligned with high-frequency scenarios such as duty logging and disaster situation reporting.

## How to Verify Successful Configuration
- Initiate a simulated rapid disaster report query. Check that the dialogue response only includes relevant data from the last 24 hours, to confirm the `messages` context filtering configuration works.
- Click the preset quick buttons in the conversation opening. Confirm that the interface directly loads responses to corresponding questions, to confirm the opening quick configuration works.
- View the `chatId` identifier of dialogue records. Confirm that dialogue records from different duty teams use independent IDs, to confirm the team division configuration works.
- Initiate a knowledge base query. Check that no additional citation identifiers appear at the end of the response, to confirm the citation display configuration meets internal office needs.
