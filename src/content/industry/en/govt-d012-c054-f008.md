# Internal Office and Employee Services for Flood Prevention, Disaster Mitigation and Emergency Duty: Document Parsing and Chunking

## What Data Belongs to This Category
Data for this category typically comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Updates occur daily. Daily processed documents include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Some documents contain structured fields such as longitude and latitude, water level values, rainfall units, and personnel counts. Others are unstructured text with tables and flowcharts. Document formatting varies across different sources.

## How These Characteristics Impact the Document Parsing and Chunking Stage
Multi-source data updated at high frequency daily requires the parsing stage to support batch rapid processing, to avoid delays in warning and emergency response. Structured fields and mixed-format documents require retention of field relevance, so associated data such as water levels and rainfall must not be split apart during chunking. Multi-format documents generated through cross-departmental scheduling have significant formatting differences, so the parsing stage must automatically adapt to formats from different sources. The timeliness requirements of rapid disaster reports and emergency plans mean that key information must be quickly located after parsing and chunking, and core disposal process paragraphs should not be overly split.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to rapid disaster reports and consultation minutes that include structured fields, avoid splitting core disposal paragraphs |
| `chunkSplitter` | Split by paragraph + title | Retain document structural relevance, making it easier to locate key modules such as rainfall and water conditions later |
| `customPdfParse` | Enabled | Adapt to emergency response plans and material allocation slips with complex tables and flowcharts, restore document formatting |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Support batch upload of large files such as hydrological monitoring reports and video surveillance screenshots |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Address parsing time for large, multi-page documents, avoid mid-task interruptions |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types, adapt to mixed-format emergency documents |

## Three Common Configuration Errors
- Calling an external parsing tool returns a file read error, and the interface displays file parsing failure. This occurs because port mapping for the locally deployed parsing tool is not correctly configured, blocking FastGPT from accessing the parsing service.
- After uploading a multi-page rapid disaster report, the chunking result omits structured data from table cells. This occurs because the `customPdfParse` configuration is not enabled, and the default parsing logic cannot recognize complex table fields.
- When batch uploading daily hydrological monitoring data, parsing tasks time out and stop. This occurs because the `PARSE_FILE_TIMEOUT_SECONDS` setting is lower than the actual parsing time, failing to adapt to the processing pace of large-volume files.

## How to Verify Configurations Are Properly Set
- Upload a material allocation slip that includes complex tables, check whether the parsing result fully retains fields such as material names, quantities, and allocation units within the table.
- View parsing task logs for FastGPT v4.17.0, confirm that the `PARSE_FILE_TIMEOUT_SECONDS` setting does not trigger a timeout error, and the task completes normally.
- Manually adjust `chunkSize` to different ranges, compare the paragraph integrity of chunking results, and confirm alignment with business requirements.
- Test HTTP requests for calling external parsing tools, confirm that FastGPT can normally receive the returned results and complete chunking.
