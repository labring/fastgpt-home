# Internal Office and Employee Services for Flood Control, Disaster Prevention and Emergency Duty: Model Access and Configuration

## What data for this category looks like
The data for this category mainly comes from meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Data updates occur daily. Core business documents include duty records, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Document fields cover rainfall, flow, danger level, number of transferred people, material category and quantity, with corresponding units of millimeters, cubic meters per second, level, person, piece, or ton. The information density of a single document increases as the emergency event level rises.

## What constraints these characteristics impose on the "model access and configuration" link
Multi-source data updated at high frequency daily requires the model to quickly process recalled documents. The context window configuration must therefore meet the summary needs of multiple daily business documents. The presence of multiple document types and specific business fields requires configuring rules for adapted field extraction when accessing the model, to prevent invalid information from interfering with core emergency judgments. Cross-department scheduling business processes also require the model to call tools to retrieve data from multiple systems. Tool call configuration must align with the real-time requirements of emergency response, to avoid delays that reduce disposal efficiency.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Meets the context summary requirements of multiple daily emergency documents, avoiding information loss from exceeding model window limits |
| `maxTokens` | 2000–3000 token | Meets the length requirements for generating rapid disaster reports and consultation minutes, preventing output content from being truncated |
| `quoteMaxToken` | 1500 characters | Retains reference details of core early warning and disaster data, balancing recall accuracy and context load |
| `toolChoice` | auto | Adapts to cross-system data retrieval needs, automatically selecting tools to process real-time data such as rainfall and water conditions |
| `temperature` | 0.3–0.5 | Maintains the accuracy of emergency information, avoiding vague or uncertain disposal suggestions in generated content |
| `AIPROXY_API_ENDPOINT` | `http://localhost:8000/v1` | Adapts to the network configuration requirements of localized models, ensuring FastGPT can connect to local model services |
| `AIPROXY_API_TOKEN` | Fill in the exclusive key generated during deployment | Ensures access permissions for localized model calls, preventing unauthorized access |

## Three common configuration mistakes
- The first issue is a port 500 occupancy error when deploying a local model. The cause is that the port of the local model service is not correctly bound, causing FastGPT to fail to establish a valid connection.
- The second issue is that core business fields are missing from emergency documents generated by the model. The cause is that context recall rules are not configured for specific fields such as rainfall and danger level, causing the model to fail to extract key data.
- The third issue is service unavailability when calling a third-party proxy model. The cause is that the valid key of the proxy service is not updated, causing access permissions to expire and making normal model calls impossible.

## How to confirm the configuration is complete
- Submit a combined document of historical duty records and early warning notices, check whether the model can correctly extract core business fields such as rainfall and danger level.
- Call the model to generate a brief rapid disaster report, confirm that the output length matches the `maxTokens` setting, with no truncated content.
- View the model call log, confirm that tool call triggers align with the `toolChoice` configuration, and that multi-system data can be retrieved normally.
- Test the connectivity of the localized model, confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured correctly, with no connection errors.

The values provided are common starting points and should be measured against the reader's own samples.
