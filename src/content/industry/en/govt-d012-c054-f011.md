# Internal Office and Employee Services for Flood Prevention, Disaster Mitigation and Emergency Duty: Forms and Interactions

## What the data for this category looks like
Data for this category mainly comes from meteorological warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Documents processed daily include duty logs, warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips.
Data update frequency is daily. Some real-time monitoring data syncs at high frequency.
Most document fields include quantitative indicators with units: rainfall in millimeters, water levels in meters, number of personnel, material categories, allocation quantities, and similar items. Some unstructured text needs to be linked to specific disaster scenarios.

## Constraints on forms and interactions from these characteristics
Multi-source data access requires forms to support quick association with external system fields, reducing manual entry errors.
The dual rhythm of daily updates and real-time monitoring requires interaction components to support both immediate submission and batch import modes.
Most document fields have quantitative units, so forms need preset unit options to avoid non-standard input.
In cross-departmental dispatch scenarios, forms need to support permission-level configuration. Only personnel in corresponding positions can fill specific fields, and circulation status synchronization is supported.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Form input components | Bind mandatory fields such as rainfall, water level; preset "millimeter" and "meter" unit options | Enable quick entry of quantitative data with units and avoid manual input errors |
| User selection components | Preset options including "Red Rainstorm Warning", "Orange Flood Warning", "General Danger Situation"; support single selection | Adapt to classification selection needs for consultation minutes and response plans |
| Submission validation rules | Enable mandatory field validation, set timeout threshold to 30 seconds | Ensure timeliness and completeness of entered data |
| Permission-level configuration | Divide filling scope by position; only allow duty positions to fill duty logs | Adapt to permission control requirements for cross-departmental dispatch |
| Batch import configuration | Support CSV format import, match preset field mappings | Adapt to daily aggregation needs for large numbers of duty logs and allocation slips |

## Three Common Misconfigurations
- When calling an API to access interaction components in a workflow, no user input popup appears. The cause is that the "Trigger interaction on API call" switch is not enabled in the workflow configuration.
- Form input components cannot pass preset global variables. The cause is that variables are not correctly bound to the default value configuration item of the form field.
- When importing multi-column Excel files, field matching is misaligned. The cause is that the import mapping is not configured according to the document field order, resulting in data not corresponding to fields.

## How to Verify Successful Configuration
- Enter the workflow test page of FastGPT v4.17.0, trigger the form input component, and check whether preset units and options load correctly.
- Call the configured API interface to submit test data, and check whether the validation rule is triggered and correct validation results are returned.
- Log in to the system with an account from an unauthorized position, and check whether sensitive fields of the specified form are inaccessible.
- Import a test Excel file, and check whether the field mapping fully matches the preset configuration.
