# Internal Office and Employee Services for Flood Prevention, Disaster Mitigation and Emergency Duty: Deployment and Upgrade

## What the data for this category looks like
Data for this category originates primarily from meteorological early warning systems, hydrological monitoring systems, emergency command platforms, grassroots disaster reporting systems, and video surveillance. Daily processed documents include duty logs, early warning notices, consultation minutes, rapid disaster reports, emergency response plans, and material allocation slips. Fields and their associated units include rainfall (millimeters), water level (meters), early warning levels, material stock (pieces/tonnes), number of transferred people, and more. Data updates occur daily. Some real-time monitoring data uses shorter synchronization intervals. Core business documents must be updated dynamically alongside disaster conditions and scheduling work.

## What constraints these characteristics impose on deployment and upgrade
Multi-source heterogeneous data sources, dynamically updated business documents, and strict timeliness requirements create multiple constraints for the deployment and upgrade process.
Multi-source data access requires pre-configuring compatible storage and parsing rules. This prevents data synchronization failures that disrupt core time-sensitive processes such as rainfall and water level summary.
Business documents have numerous closely linked fields. Upgrades must retain original field mapping logic to avoid parsing errors that cause failures in duty material generation.
High-frequency real-time monitoring data requires deployed databases and cache services to have stable throughput capabilities. Upgrades must use gray release methods to avoid interrupting emergency duty workflows.

## Recommended Configuration Values
This guide applies to the deployment and upgrade process for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | Stores unstructured business documents including rapid disaster reports and consultation minutes. Requires a stable document database connection. |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches real-time hydrological and meteorological monitoring data. Reduces query latency for multi-source data. |
| `DB_MAX_LINK` | `200–300 connections` | Meets concurrent connection requirements for simultaneous data reports from multiple departments. Prevents connection exhaustion. |
| `STORAGE_S3_ENDPOINT` | Configured according to local storage or actual cloud service provider addresses | Stores early warning notice attachments and on-site video footage. Adapts to multi-scenario storage needs. |
| `ROOT_KEY` | Random 32-character string | Serves as the platform super administrator key. Ensures post-deployment permission security. |
| `FE_DOMAIN` | Public network domain name or internal IP address of the deployment server | Configures the frontend access address. Ensures normal navigation for internal office systems. |

## Three Common Configuration Errors
- Symptom: Frontend page inaccessible after deployment. Logs indicate domain name resolution error. Cause: `FE_DOMAIN` not configured to the actual deployment access address. This leads to failed frontend resource path parsing.
- Symptom: Multi-source monitoring data fails to load normally after version upgrade. Queries return empty results. Cause: Original cache key prefix configuration for `REDIS_URL` not retained during upgrade. This prevents access to existing cached data. New configuration connection validity not verified.
- Symptom: Local code changes do not take effect after syncing to the online service. Page does not update. Cause: Modified code not packaged, uploaded, and replaced in the online deployment directory. Or service not restarted to load new code files.

## How to Verify Successful Configuration
- Run a database connection test script to verify normal connection status for `MONGODB_URI` and `REDIS_URL`.
- Upload a test rapid disaster report document to confirm the storage path matches the `STORAGE_S3_ENDPOINT` configuration. Confirm the file can be read normally.
- Send 3-5 concurrent simulated data upload requests to check that concurrent connections for `DB_MAX_LINK` meet test requirements. No connection errors should appear.
- Access the configured `FE_DOMAIN` address to confirm the frontend page loads normally. Confirm the page displays test monitoring data and business documents.

The values provided are common starting points and should be assessed against local deployment samples.
