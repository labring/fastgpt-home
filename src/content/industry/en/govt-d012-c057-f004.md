# Internal Office and Employee Services for Food Safety Supervision and Sampling Inspection: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include the food safety sampling inspection monitoring system, the State Administration for Market Regulation sampling results query system, the laboratory information management system (LIMS) of inspection institutions, and the account books of food producers and operators. The data update frequency is monthly. Core daily documents cover sampling inspection plans, sampling slips, inspection reports, non-compliant food verification and disposal reports, and risk control notices. Each document includes fields such as sampling location, inspection items, non-compliance item judgment, and disposal measures. The inspection report must match the unique identification number of the sampling slip to ensure full-process data traceability.

## How these characteristics impose constraints on workflow orchestration
The monthly updated data source requires the workflow to support batch monthly data import and verification links to avoid overloading single processing runs. The field differences across multiple document types require workflow nodes to support field mapping by document type, for example, automatically associating task items from a sampling inspection plan with execution nodes on a sampling slip. The strong association requirement between inspection reports and verification and disposal reports requires setting cross-node data verification rules in the workflow to ensure that the disposal process for non-compliant items fully matches the inspection results. The hierarchical data flow between grassroots supervision institutes and municipal bureaus requires the workflow to support graded approval node configuration, adapting to the operation permissions of different entities.

| Field mapping rule | Automatically match sampling inspection plan and sampling slip fields by document type | Adapt to the processing needs of multiple document types, simplifying node configuration |

## Three common mistakes
- Symptom: The downstream workflow node cannot read the `variables` global variable configured upstream, and the field displays as empty. Cause: Cross-node variable authorization was not completed on the global variable configuration page, or the variable scope is limited to the current node.
- Symptom: When calling an MCP tool, the authentication parameters passed by the workflow cannot be obtained, and a permission error is returned. Cause: Authentication parameters were not bound to the workflow `variables` global variable, and the parameter mapping rules during tool call were not configured.
- Symptom: The workflow does not automatically trigger tool calls and requires manual execution of the node. Cause: The trigger condition for tool calls was not configured, or the trigger condition does not match the business logic.

## How to confirm the configuration is correct
- Manually trigger the workflow, upload a single sampling slip and inspection report, and check whether the global variables are automatically passed to the downstream verification and disposal node.
- Configure a simulated non-compliant inspection result, submit test data, and verify whether the tool call node starts automatically.
- Check the node binding relationship to confirm whether the association between the inspection report node and the verification and disposal node takes effect.
- View the workflow logs to confirm that no timeout or data loss occurs in the context cache during monthly data import.
