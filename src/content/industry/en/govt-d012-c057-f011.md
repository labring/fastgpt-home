# Internal Office and Employee Services for Food Safety Supervision and Sampling: Forms and Interactions

## What data looks like for this category
This category of data covers core documents including sampling plans, sampling sheets, inspection reports, and non-compliant food verification and disposal reports. Data sources include the food safety sampling and monitoring system, the State Administration for Market Regulation’s sampling result inquiry system, the inspection institution’s LIMS, and the food producer or operator ledger. Data is updated on a monthly basis. Core fields include sampling point number, inspection project parameters, non-compliance judgment basis, and more. Data must be transferred across departments and systems.

## What constraints these characteristics impose on the "forms and interactions" link
Monthly updated bulk data requires forms to support bulk import and format verification, to avoid efficiency losses from single-entry input. Field differences across multiple document types require forms to support dynamic field switching, to adapt to required and optional field differences for different documents such as sampling plans and sampling sheets. The high-risk nature of non-compliant disposal requires multiple confirmation steps in the interaction link, to prevent regulatory risks caused by data entry errors. The decentralized usage scenario of grassroots supervision institutes requires forms to support lightweight loading in low-bandwidth environments, to ensure stability for cross-region usage.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Form input component | Enable `formInput`, configure dynamic field linkage | Adapt to field difference requirements for different types of sampling documents |
| User selection component | Enable `userSelect`, pull all associated data sources | Cover all institutions and personnel options involved in sampling work |
| Bulk import verification | Enable field format verification, set timeout threshold to 120 seconds | Adapt to the import verification requirements of monthly bulk sampling data |
| Interaction trigger logic | Configure multi-level confirmation before submission, set popup interval to 3 seconds | Avoid accidental submission of non-compliant disposal data |
| Loading optimization | Enable lightweight rendering, set single-page resource limit to 800 KB | Adapt to low-bandwidth usage scenarios of grassroots supervision institutes, implemented based on FastGPT v4.17.0 |
| Permission configuration | Divide data access scope by department, only open corresponding task editing permissions | Ensure the security of data transferred across departments |

## Three common mistakes
- The symptom is that the knowledge base reference count configuration item in the form only shows fixed preset options, and cannot select values in the middle range. The cause is that the configuration item has preset limited options, and the custom input function is not enabled.
- The symptom is that only a small number of optional models are visible when calling tools, and all available models cannot be selected. The cause is that cross-system model permission synchronization is not configured, and only the model list of the current workspace is pulled.
- The symptom is that tool calls are not triggered after the form is submitted, and the AI directly generates a response. The cause is that the `formInput` component is not bound to the tool call link, and the form data is not correctly passed to the call link.

## How to confirm the configuration is complete
- Enter the form configuration page, check whether the `userSelect` component pulls user and institution options from all associated systems, and verify that the permission scope matches departmental responsibilities.
- Upload a batch of monthly sampling data, verify whether the bulk import verification is completed within the preset timeout threshold, and whether field error prompts accurately correspond to document requirements.
- Simulate the submission process of a non-compliant disposal report, check whether multi-level confirmation popups are triggered, and confirm whether data is normally transferred to subsequent links after confirmation.
- Open the form in a low-bandwidth test environment, check whether the page loading meets the preset resource limit, with no obvious lag or loading failures.
