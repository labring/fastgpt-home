# Internal Office and Employee Services for Survey and Design: HTTP Interfaces and External Systems

## What data for this category looks like
Core data for survey and design originates from CAD construction drawings, BIM model files, geotechnical survey reports, project progress ledgers, and design change notices. Data update rhythm shifts with project phases: updates daily with point detection results during the survey phase, updates weekly with version iterations during the design phase, and updates immediately when changes occur.

Documents include structured fields and unstructured content. Structured fields include project number, survey point coordinates, geotechnical compressive strength, and version number. Unstructured content includes survey site descriptions and design optimization notes. Field units follow industry standards: coordinates use decimal degrees, strength unit is MPa, and version number uses the `YYYYMMDD-sequence number` format.

## What constraints these characteristics impose on HTTP interfaces and external systems
Single files of large BIM models and CAD construction drawings can reach hundreds of MB. This requires interfaces to support large request body transfers and chunked upload logic.

Structured fields have strict unit standards. Interfaces must perform format and unit validation on parameters such as coordinates and strength to prevent invalid data from entering the system.

Data update frequency fluctuates with project phases. Interfaces must support incremental synchronization or short polling mechanisms to adapt to high-frequency change scenarios.

Interfaces must also support mixed text and binary response formats to meet the simultaneous transmission needs of structured ledgers and visual models.

## How to configure settings
Configurations under FastGPT v4.17.0 must be adjusted for survey and design business scenarios, as detailed below:

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Interface timeout period | 600 seconds | Survey and design file transfer and data processing take a long time; prevents request interruption due to timeout |
| Maximum request body limit | 1000 MB | Adapts to transfer needs for BIM models and large CAD drawings |
| Global variable passing | Passed via interface call parameters | Matches the business scenario where external platforms pass project numbers and version numbers |
| Authentication method | Fixed secret verification | Adapts to unified authentication rules for internal office systems |
| Response data parsing | Extract in JSON format | Compatible with structured project ledgers and parameter data |
| Retry count | 3 times | Addresses interface call failures caused by temporary network fluctuations |

## Three common mistakes
- Calling an interface after configuring authentication information returns empty data or a 401 status code. The cause is failure to correctly match the authentication format of the internal office system, such as omitting the secret prefix or not using the `Authorization` header to pass the token.
- External platforms cannot obtain global variables when calling external interfaces. The cause is failure to enable the `variables` parameter passing switch in the interface configuration, causing the orchestrated workflow to fail to receive externally passed project numbers.
- Interface errors occur when uploading large BIM models. The cause is failure to adjust the maximum request body limit parameter, causing requests to be blocked due to exceeding the system default threshold.

## How to confirm configuration is complete
- Invoke the test interface, verify whether the returned data includes the core fields of survey projects, and confirm that parameter verification and data parsing take effect.
- Simulate an external platform passing global variables, confirm that the interface correctly receives and uses the variable in the workflow, and verify the global variable passing configuration.
- Upload test files of varying sizes, confirm that the request body size limit adapts to business needs, and verify that the transmission logic operates normally.
- View interface logs, confirm that the `Authorization` header and `responseData` parsing rules are correctly applied, and verify the authentication and data processing configurations.
