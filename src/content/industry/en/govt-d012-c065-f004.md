# Internal Office and Employee Services for Survey and Design: Workflow Orchestration
This page content is based on FastGPT v4.17.0

## What the data for this category looks like
The core data for survey and design comes from original project survey records, design drawing metadata at each stage, project progress ledgers, and change request forms. Data updates are synced in real time as projects progress. Survey point data and design change content submitted in a single batch are updated immediately. A single document includes fields such as project number, survey coordinates, design phase, review status, and associated drawing number. Units mostly use engineering standard units such as meters, square meters, and workdays.

## What constraints do these characteristics impose on workflow orchestration
Survey and design data includes structured engineering fields and unstructured drawing text. This requires workflows to support both structured field extraction and unstructured content parsing. Real-time updated project data requires workflow trigger nodes to be bound to project status change events, using real-time trigger logic. Multi-stage review and transfer logic requires workflows to configure branch nodes. These nodes implement different transfer paths based on the review status field. Engineering-specific unit formats require workflow variable processing steps to retain unit information such as meters and square meters to avoid format loss.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| Trigger Mode | Bound to project status change events | Matches the real-time update rhythm of survey and design data, avoids invalid scheduling |
| Variable Configuration | Extract project number and survey coordinate fields from `variables` | Core identification fields for survey and design documents, used to associate upstream and downstream processes |
| Branch Node Rules | Split flows based on review status field | Adapts to the transfer needs of multi-stage reviews, aligns with the approval logic of survey and design projects |
| Single-Processing Limit | Top 10 pending tasks | Matches the task scale of single batches in engineering projects, avoids node overload |
| Timeout Threshold | 600 seconds | Covers the conventional time required for survey report parsing and drawing metadata extraction, calibrated based on actual measurements |
| Knowledge Base Retrieval Filter | Associate project tags | Limits the retrieval scope to the knowledge base content of the current project, improves matching accuracy |

## Three common mistakes
- Double thinking process occurs during workflow debugging. Phenomenon: Two rounds of thinking processes display simultaneously in the debug log of the tool call node. Cause: The input parameter range of the trigger node is not limited via `nodeId`, and core fields are not extracted from `variables`. This causes the system to repeatedly trigger thinking logic.
- Code running component throws errors while the code itself has no issues. Phenomenon: Code component execution fails in a local deployment environment, returning a generic error status code. Cause: Local running permissions for workflow nodes are not configured, preventing access to the local storage path of engineering data.
- Knowledge base retrieval does not filter results by tags. Phenomenon: Retrieved content includes documents not from the current project. Cause: Project tags are not bound to the filter rules of the retrieval node, and tag fields from `variables` are not associated.

## How to confirm the configuration is correct
- Trigger a project status change event, check whether the workflow starts automatically and transfers to the corresponding node.
- Check whether the project number and survey coordinate fields extracted from `variables` fully match the source data.
- Simulate inputs with different review statuses, verify whether the workflow transfers to the corresponding branch according to the rules.
- Submit a test task, confirm that the timeout threshold does not trigger node interruption, and that retrieval results include content matching the project tags.
