# Internal Office and Employee Services for Survey and Design: Model Access and Configuration

## What the Data for This Category Looks Like
Survey and design data primarily originates from project survey reports, architectural design drawings, BIM model files, and industry specification documents. Data updates in real time alongside project design iterations, with updates completed after a single plan adjustment. Document structures include structured metadata (such as project number, survey point coordinates), chaptered text descriptions, and drawing fragments with dimension parameters. Fields include engineering units like length, area, and volume, plus professional term annotations. Some data is nested within BIM model attribute panels.

## Constraints Imposed on Model Access and Configuration
The long documents and multi-source heterogeneous data characteristics of survey and design work impose clear constraints on model access configuration. Long text reports and complete drawing content require sufficient context capacity to avoid truncating key professional parameters. Multi-format input (text reports, BIM attributes, drawing images) demands configuration of models with multimodal recognition capabilities to adapt to different types of design data. The presence of professional fields and engineering units requires models to preset industry term mapping rules to avoid parameter parsing deviations. Frequent project iteration updates require configuration items to support rapid adjustment of context thresholds, adapting to real-time updated design content.

## How to Configure Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the long text content of survey and design reports and drawings, avoids truncating key professional information |
| `maxTokens` | 2000–3000 token | Meets output length requirements for professional drawing parsing and plan descriptions |
| `quoteMaxToken` | 1500 characters | Limits the length of referenced design document fragments to avoid context overload |
| `toolChoice` | auto | Allows models to independently select tool calls, adapting to multi-step office processes in survey and design work |
| `vision` | Enabled | Supports recognition and parsing of drawing images, adapting to multimodal input requirements for survey and design |
| `temperature` | 0.3–0.5 | Maintains accuracy of professional content, avoids generating content that does not comply with engineering specifications |

## Three Common Configuration Errors
- Symptom: The model fails to trigger preset office tool calls, returns an empty tool call field, or directly generates a text result. Cause: The `toolChoice` parameter is incorrectly configured to fixed calls of a specified tool, which does not align with flexible tool call requirements in survey and design office processes.
- Symptom: After uploading a drawing image, the model cannot recognize content or returns meaningless recognition results. Cause: The `vision` configuration item is not enabled, or the installed FastGPT version is lower than v4.17.0, which does not support multimodal file parsing.
- Symptom: A connection timeout or 401 Unauthorized error is returned when calling the model. Cause: The `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` configuration is incorrect, preventing normal identity verification or request routing.

## How to Verify Successful Configuration
- Upload a text fragment of a survey report, check that context loads completely with no truncated content.
- Upload a design drawing image, verify that the model can recognize dimension annotations and professional annotations in the drawing.
- Submit a test question that requires a tool call, confirm that the model triggers the corresponding tool.
- Review the model's thinking process, confirm that configuration item values comply with preset rules.

The values provided above are common starting points, and should be evaluated against the user’s own samples.
