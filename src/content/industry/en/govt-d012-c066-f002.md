# Internal Office and Employee Services for Advanced Chemical Materials: Vector Models and Indexes

## What the Data for This Category Looks Like
Core data sources for internal office and employee services for advanced chemical materials include enterprise internal R&D archives, production process specifications, safety and compliance manuals, employee service documents (such as attendance policies, training materials), and equipment maintenance records.

Update frequency varies by document type:
- R&D archives are updated in real time as projects progress
- Process specifications are updated after process iterations
- Compliance documents are updated alongside national or industry policy changes
- Employee handbooks are updated once per year

Document structures include long text paragraphs, structured entries, and numbered process descriptions. Fields include unique document identifiers, document classification tags, effective dates, associated production batch numbers, safety compliance levels, with some fields using numeric codes and unit identifiers.

## What Constraints These Characteristics Impose on Vector Models and Indexes
The real-time update nature of R&D archives and maintenance records requires indexes to support incremental synchronization, avoiding resource usage and time delays caused by full reindexing. The mixed structure of long-text process specifications and compliance documents requires chunking strategies adapted to different content types, preventing splitting that breaks complete process steps or policy clauses. The presence of multiple classification tags and safety level metadata requires vector indexes to support filtered retrieval based on metadata, to limit valid access scopes. Structured fields such as batch numbers and equipment IDs require vector models to encode both text and structured metadata, ensuring accuracy of associated retrieval.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to long text paragraphs in advanced chemical material process specifications and R&D archives, avoiding semantic fragmentation during splitting |
| Overlap Length | 100–150 characters | Preserves semantic connections between adjacent chunks, preventing loss of context when long processes are split |
| `defaultToken` | 8192 | Matches the token limit of mainstream vector models such as bge-m3, meeting encoding requirements for chunks from long documents |
| `maxToken` | 16384 | Adapts to context stitching requirements for multi-turn question answering, meeting context filling needs after long document retrieval |
| Similarity Threshold | 0.65–0.75, calibrated via actual testing | Adapts to semantic similarity judgment for chemical documents, distinguishing process similarity from irrelevant content |
| Single Search Limit | Top 10 results | Controls the number of returned results, avoiding redundant information interfering with retrieval efficiency in employee service scenarios |

## Three Common Misconfigurations
- Scenario: After completing index configuration for a new vector model, retrieval returns "retrieval failed" or status code 500. Cause: The token limit parameter for the model was not configured, causing long document chunks to exceed the model's encoding limits.
- Scenario: When reviewing the PostgreSQL storage table, only vector fields are present, with no original document text content. Cause: The index configuration option to retain original documents was not enabled, and only vector embedding results were synchronized.
- Scenario: When using the bge-m3 vector model, semantic retrieval returns similarity scores that are consistently higher than the reasonable range. Cause: The similarity threshold was not adjusted for structured fields in chemical documents, leading to abnormal scores due to overly high weight assigned to numeric encoding.

## How to Verify Proper Configuration
- Upload a typical chemical process specification document, confirm that chunked paragraphs retain complete process steps with no obvious semantic fragmentation.
- Run a retrieval test, check that returned results include original document metadata such as classification tags and safety levels.
- Adjust the similarity threshold, verify that retrieval result relevance changes appropriately as the threshold is modified.
- Submit an updated R&D document, confirm that the index completes incremental synchronization automatically, without requiring manual full reindexing.
