# Internal Office and Employee Services for Pharmaceutical Distribution: Tool Calling and Plugins

## What the data for this category looks like
Internal office data for pharmaceutical distribution mainly comes from inventory and sales management systems, GSP compliance traceability systems, logistics delivery ledgers, and employee attendance and reimbursement systems. Data update rhythms fall into three categories: order and delivery data is updated in real time, inventory and compliance ledgers are updated daily, and financial and personnel data is updated monthly.
Document structures include fields such as drug SKU codes, batch numbers, inventory quantities, delivery addresses, approval statuses, expiration dates, and test report numbers. Units include boxes, cases, pieces, yuan, days, and other units. Some fields must comply with GSP compliance requirements.

## What constraints these characteristics impose on tool calling and plugins
The multiple update rhythms of pharmaceutical distribution data require tool calling workflows to adapt to different caching strategies. Real-time data cannot use caching. Daily and monthly data can be configured with fixed cache durations. Many data fields have compliance requirements, so plugins must support custom field validation rules to avoid returning results that do not meet GSP standards. A large number of SKUs leads to excessive data volume in single requests, so tool calling must limit the number of returned items to prevent interface overload. For tool calls involving employee personnel and financial data, additional permission verification logic must be configured to ensure data security.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling mode | `auto` | Adapt to automatic selection of multiple tools, matching multi-type tool calling needs such as orders, inventory, and personnel in pharmaceutical distribution scenarios |
| Function calling switch | `enabled` | Enable structured function calling to ensure accurate parsing and return of pharmaceutical compliance fields |
| Single tool call limit | Top 8 items | Pharmaceutical distribution has a large number of SKUs, limiting returned items avoids excessive data volume per request |
| Tool call timeout | 30 seconds | Adapt to fast response requirements for real-time order and delivery data |
| Cache validity period | 0-86400 seconds, calibrated according to data update rhythm | Set real-time data to 0 seconds to disable caching, set daily data to 86400 seconds, matching update frequencies of different data types |
| Sensitive data permission verification | Enabled | Cover call permission control for sensitive data such as employee attendance and financial reimbursement |

## Three common mistakes
- Phenomenon: No results appear in the dialog box after tool calling completes. Results display after re-entering the session, but no return mark for the tool calling process is attached. Cause: Session context persistence configuration is not enabled, so temporary tool call results are not written to session storage, and are only read from the backend cache during reload.
- Phenomenon: No file processing plugins are displayed in the plugin marketplace, and no corresponding installation entry is available. Cause: The corresponding plugin dependency package is not installed, or the current FastGPT version is lower than v4.17.0.
- Phenomenon: After calling the basic chart plugin, "none" is returned, and no chart URL is generated. Cause: The passed drug inventory data field is empty, or the parameter format does not match the JSON structure required by the plugin, so the plugin cannot parse and generate the chart.

## How to confirm proper configuration
- Initiate a test request that includes a drug SKU query, check whether tool calling is triggered and returns inventory, batch and other data for the corresponding SKU.
- Check the sensitive data verification switch status on the plugin configuration page, attempt to call tools related to employee attendance with an unauthorized account, and verify whether permission interception takes effect.
- Call tools for real-time order data and monthly financial data separately, check whether the cache operates according to the configured validity period.
- View the tool call log, confirm that the format of returned results conforms to preset structured parsing rules.

The values provided are common starting points and should be evaluated against the reader's own samples.
