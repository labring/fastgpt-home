# Internal Office and Employee Services for Hazardous Chemicals Storage and Transportation: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Core data for hazardous chemicals storage and transportation comes from internal enterprise storage and transportation ledgers, tank area inspection logs, safety supervision filing documents, and transportation dispatch orders.
Ledgers include fields such as tank number, stored category, current inventory, temperature threshold, inbound and outbound times, with units of cubic meters, tons, and degrees Celsius.
Inspection logs are real-time data updated per shift. Filing documents are updated quarterly with fixed formats. Dispatch orders are generated for each transportation task.
Single document length ranges from 500 to 1500 characters. Fields must strictly match compliance requirements, with no complex nested formats.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words link
Storage and transportation data fields must strictly match compliant units. Prompt words for multi-turn dialogue must require output content to match specified field formats and units, to avoid non-standard numerical descriptions.
High-frequency updates of real-time inspection data require dialogue context to retain the most recent retrieval scope, preventing calls to expired data.
Different update rhythms for document types require prompt words to clearly specify the target document type, avoiding confusion between filing documents and real-time dispatch data.
Core parameters such as tank number and stored category must be traced during multi-turn interactions. The `messages` sequence must fully transmit historical interaction content to avoid context loss.

## How to set configurations
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Retain the first 15 turns of dialogue + the most recent 3 knowledge base retrieval results | Hazardous chemicals storage and transportation data needs to be associated with historical operating parameters; overly long context will dilute core information |
| `messages` sequence | Fully transmit interaction history between users and assistants | Ensure core parameters such as tank number and stored category can be traced during multi-turn dialogue, avoiding repeated inquiries |
| Single Search Limit | Top 8 retrieval results | There are many entries of hazardous chemicals data; too many results will interfere with accurate matching of core fields |
| Chunk Length | 800–1200 characters | Single record length in storage and transportation ledgers falls within this range, avoiding overly fragmented or overly large chunks |
| `variables` binding | Synchronize the output field to the dialogue output | Ensure return content from HTTP orchestration nodes can be displayed on the dialogue interface |
| `chatId` allocation | Generate a unique identifier for each independent session | Prevent dialogue contexts of different employees from interfering with each other |

## Three common misconfigurations
- Repeatedly asking for already provided tank numbers or stored categories during multi-turn dialogue. This occurs because prompt words do not clearly require retaining context for acquired core fields, or the `messages` sequence fails to correctly transmit historical interaction content.
- Output content not displayed on the dialogue interface after calling an HTTP orchestration node. This occurs because the output field in `variables` is not bound to the dialogue output node, or the output synchronization option is not enabled in the configuration.
- Context interference between different sessions in one-to-many dialogue scenarios. This occurs because no independent `chatId` is assigned to each session, resulting in shared session contexts.

## How to verify correct configuration
- Initiate a multi-turn query that includes tank number and stored category. Check if the assistant can associate subsequent inventory and temperature threshold data without repeated inquiries for basic information.
- Call an HTTP orchestration node. Check if the dialogue interface synchronously displays the output content returned by the node.
- Open two independent sessions, use the same query keywords. Check that the contexts of the two sessions do not interfere with each other.
- Adjust the maximum context length. Verify that old interaction content is no longer retrieved or used after exceeding the set number of turns.
