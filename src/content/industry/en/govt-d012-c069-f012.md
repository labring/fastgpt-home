# Internal Office and Employee Services for Hazardous Chemicals Storage and Transportation: Deployment and Upgrade

## What the data for this category looks like
Business data for hazardous chemicals storage and transportation primarily comes from enterprise warehouse management systems, inspection terminals, ERP systems, and operator logs. Data covers four categories: storage ledgers, inbound and outbound documents, shift inspection records, and equipment operating parameters.

Update rhythms fall into three types: storage ledgers are updated monthly alongside hazardous chemicals inbound and outbound operations, inbound and outbound documents are generated in real time with business activities, and shift inspection records and equipment operating parameters are updated per shift or in real time.

Standard fields for a single data entry include hazardous chemical ID, storage bin ID, ambient temperature and humidity, stored weight, inspector ID, and anomaly flag. Temperature and humidity are measured in degrees Celsius, stored weight is measured in kilograms, and inspection time is accurate to the second.

## What constraints these characteristics impose on deployment and upgrade
Hazardous chemicals storage and transportation data has high real-time performance and includes sensitive business fields. Data security and access stability must be prioritized during deployment and upgrade.

Real-time generated inspection records create high-frequency database access. Sufficient connection pool resources must be configured to handle concurrent requests. Data formats vary across multiple sources. Field validation rules must be preset during deployment to prevent abnormal data from entering the system.

Storage ledger data updated monthly has a large volume. Sufficient database migration time must be reserved during upgrades. Sensitive fields must be stored using private storage nodes. Key configuration validity must be verified synchronously during upgrades to prevent data leakage risks.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | High-frequency database connections are generated by real-time inspections and business documents for hazardous chemicals storage and transportation. This value covers concurrent access requirements |
| `REDIS_URL` | `redis://internal IP:6379` | Used to cache real-time inspection status and user sessions. Internal deployment reduces latency and security risks |
| `STORAGE_S3_ENDPOINT` | Enterprise private storage node address | Hazardous chemicals data is sensitive business data. Storing it on enterprise-owned nodes ensures data security |
| `FE_DOMAIN` | Enterprise internal domain name or mapped external domain name | Adapted to internal office and employee service access scenarios. Supports both internal and external access modes |
| `FILE_TOKEN_KEY` | 32-character random string | Used to verify the legitimacy of file upload requests. Ensures upload security of attachments such as inspection photos and device logs |
| `PG_URL` | Dedicated PostgreSQL instance address | Structured storage ledgers and operator logs are suitable for storage in relational databases to ensure data query efficiency |

## Three common mistakes
- Symptom: Plugin deployment path cannot be found. Cause: The plugin management module is not enabled in system configuration, causing the corresponding menu to fail to load.
- Symptom: Embedded iframe page displays blank, direct access to the address works normally. Cause: The token generated by the login-free window does not carry correct cross-domain configuration parameters, causing the browser to block the cross-domain request.
- Symptom: Audio transcription service reports POST /v1/audio/transcriptions error after upgrading to FastGPT v4.17.0. Cause: The environment dependency version of whisper is not updated synchronously during the upgrade, causing interface call incompatibility.

## How to confirm configurations are set correctly
- Access the address corresponding to `FE_DOMAIN`. After logging into the system, check if the plugin management page loads normally to confirm that the plugin deployment function is available.
- Submit a test inspection record. Check if a corresponding record is generated in the database corresponding to `PG_URL` or `MONGODB_URI` to confirm that data storage is working properly.
- Attempt to upload a test image. Confirm that the file upload interface returns normally, and the file is correctly stored in the storage node corresponding to `STORAGE_S3_ENDPOINT`.
- Check system logs. Confirm that the number of connections for `DB_MAX_LINK` does not exceed the configured threshold, and there are no database connection abnormality errors.

The values provided are common starting points and should be measured against the reader's own samples.
