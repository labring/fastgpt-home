# Internal Office and Employee Services for Power Generation Equipment Manufacturing: Workflow Orchestration

## What the data for this category looks like
Data sources include power generation equipment operation logs, operation and maintenance work order ledgers, spare parts inventory records, and employee attendance and training archives.
Operation logs are collected in real time by sensors, including equipment ID, operating temperature, pressure, timestamp, and alarm status.
Work orders are submitted by frontline employees, including work order number, reporting department, fault type, and processing progress.
Spare parts inventory records are updated daily, including spare part code, inventory quantity, and usage records.
The document structure mainly consists of structured tables and long-text operation and maintenance manuals, with field units unified to industry standard units such as degrees Celsius, megapascals, pieces, and hours.

## What constraints these characteristics impose on the "workflow orchestration" link
Power generation equipment manufacturing has high real-time equipment data collection frequency and many fields per log entry. Workflow input nodes must limit the amount of data pulled at one time to avoid processing overload.
The circulation status of operation and maintenance work orders is strongly bound to equipment alarms. Workflow trigger logic must match status change nodes.
Long-text operation and maintenance manuals must be chunked to adapt to the hierarchical classification of equipment models and fault scenarios. Accurate association with workflow tasks cannot be achieved otherwise.
The update frequency of employee training archives is bound to the scheduling cycle. Scheduled tasks for workflow data calls must align with the scheduling rhythm.

## How to set configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Variable set | Split by business module into three categories: equipment data, operation and maintenance work orders, and inventory archives. A single category of `variables` shall not exceed 10 subfields | Avoid field conflicts and adapt to the data structure of multiple business lines in power generation equipment manufacturing |
| Workflow node timeout | 600 seconds | Equipment data queries require waiting for sensor feedback, and conventional operations do not exceed 10 minutes |
| Number of equipment data pulled in one go | First 20 entries | Adapt to real-time collected data volume and avoid workflow overload |
| File upload storage path | Bind to a dedicated folder for power generation equipment operation and maintenance. Single file maximum size 50 MB | Distinguish internal office files from business documents to facilitate accurate workflow calls |
| Workflow trigger mode | Trigger by work order status change | Match the circulation logic of operation and maintenance work orders to ensure automatic task startup |
| `variables` nesting level | No more than 3 levels | Simplify field call logic and reduce front-end rendering pressure |

## Three common errors
- Phenomenon: Front-end lag occurs when dragging workflow nodes, and normalcy is restored after deleting the `variables` configuration. Cause: The `variables` nesting level is too deep or there are too many subfields in a single workflow, resulting in excessive front-end rendering load.
- Phenomenon: Uploaded power generation equipment operation and maintenance manuals cannot be read by the workflow. Cause: The file storage path is not bound to the dedicated business folder, and the workflow call path does not match the actual storage location.
- Phenomenon: Workflow execution times out, returning status code 504. Cause: The workflow node timeout period was not adjusted, and the equipment data query time exceeded the default threshold.
