# Internal Office and Employee Services for Power Generation Equipment Manufacturing: Forms and Interactions

## What the data for this category looks like
Data sources include real-time operation logs of power generation equipment, spare parts inventory ledgers, regular maintenance work orders, and employee attendance and scheduling records.
Data update cadence: Real-time operation logs sync with device operating status. Spare parts inventory updates after daily stocktakes. Maintenance work orders update in real time when workflow nodes are submitted.
Documents use structured forms, with fields including equipment number, operating power, oil pressure, maintenance duration, spare parts model, and others. Fields include standard units such as kW, MPa, hours, and pieces.

## What constraints these characteristics impose on forms and interactions
Professional fields and units for equipment operating parameters require preset validation rules in forms to prevent invalid input.
Real-time operation data must support automatic pull and sync for forms, removing the need for manual data entry.
Spare parts and maintenance personnel options have large volumes, so search and filtering must be supported to avoid page freezes caused by full loading.
Maintenance work orders include multiple business links, so form pages must be split to optimize interaction experience.
Multi-user collaboration scenarios require support for multi-person selection and permission validation to ensure process compliance.

## How to configure the settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Form input box validation rules | Preset units and numerical ranges per field | Power generation equipment data has fixed professional units and reasonable ranges, preventing invalid input |
| User selection component | Enable search matching mode, limit loading of the first 20 items at a time | Spare parts and personnel options have large volumes, avoiding page freezes |
| Form submission timeout | 600 seconds | Equipment maintenance processes take a long time, needing adaptation for long-cycle submissions |
| Multi-page form splitting | Split form pages by business nodes | Maintenance work orders include multiple links: device information, spare parts requisition, acceptance confirmation. Splitting makes interactions clearer |
| `formInput` real-time sync | Enable real-time validation | Equipment operating parameters require real-time compliance verification |
| `userSelect` concurrency limit | Limit a single user to opening 6 interaction pages at the same time | Adapt to the concurrency call limit of internal network interfaces, avoiding triggering rate limiting |

## Three common misconfigurations
- A connection error prompt appears after submitting a form. Cause: The device data interface associated with the form does not have a correct timeout threshold configured, and does not adapt to access restrictions within the power generation equipment internal network.
- More than six interaction pages related to a single device are opened at the same time. Cause: The concurrent request limit for the `userSelect` component is not set, leading to frequent calls to the internal network interface that triggers rate limiting.
- Variable references fail during knowledge base search. Cause: The trigger timing for variable binding is not configured in the form, causing variables to not sync with form input updates.

## How to confirm the configuration is complete
- Test each form field's input validation one by one, confirm it matches the preset units and numerical ranges.
- Simulate multiple users opening form interaction pages at the same time, confirm no interface rate limit error is triggered.
- Test variable references during knowledge base search, confirm variables sync with form input updates.
- Submit a long-cycle form, confirm no timeout error occurs.
