# Internal Office and Employee Services for Power Generation Groups: HTTP Interfaces and External Systems

## What the data for this category looks like
The data sources for internal office and employee services of power generation groups include internal group OA systems, employee attendance platforms, power generation equipment operation and maintenance ledgers, and salary calculation systems. Update frequencies vary by scenario: attendance data syncs daily, work orders push in real time, and salary data updates monthly. The data uses structured JSON format, with fields including employee ID, department code, job title, work order number, equipment rated power (unit: megawatt), operation timestamp, and more. There are no overly nested layers, making direct parsing via interfaces straightforward.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
Structured fixed fields require content returned by HTTP interfaces to strictly match preset key names. Missing or extra fields will cause parsing failures. Different update frequencies require differentiated timeout and retry policies: real-time operation and maintenance scenarios need short timeouts, while monthly salary scenarios allow more relaxed settings. The power field for power generation equipment uses megawatt as the fixed unit. Interface calls must verify unit consistency to avoid direct use of cross-unit data. Internal system permission control requires interfaces to carry valid tokens via the `Authorization` parameter, and only allow calls from group intranet IPs to prevent unauthorized access. FastGPT v4.17.0’s interface configuration module can be configured to address these constraints.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {pre-generated group intranet token} | Complies with permission verification specifications of internal group systems, matches HTTP standard authorization header format |
| Context Variable Configuration | `{"dept_code":"","device_power_unit":"megawatt"}` | Passes power generation group-specific business parameters via the `variables` parameter, adapts to structured data field requirements |
| Response Data Extraction | Only retain content under the `responseData` root node | Filters non-business metadata returned by the interface, only extracts core fields related to employees and operation and maintenance |
| Interface Timeout Period | 30–60 seconds | Adapts to real-time work order synchronization scenarios, avoids task interruptions caused by network delays |
| Retry Trigger Threshold | Trigger retry after 2 consecutive timeouts | Addresses temporary intranet network fluctuations, reduces the impact of single call failures |
| Request Frequency Limit | No more than 10 times per second | Complies with traffic control rules of internal group systems, avoids triggering current limiting interception |

## Three Common Misconfigurations
- Phenomenon: Interface calls return a 403 Forbidden status code, and internal system data cannot be obtained. Cause: No valid intranet token complying with group specifications is carried in the `Authorization` parameter, or the request IP is not added to the whitelist of the internal group system.
- Phenomenon: After preset keywords are triggered, the custom external interface is not called, and the default answer is returned directly. Cause: The keyword interception rule is not bound to the HTTP interface call action, and only basic interface parameters are configured.
- Phenomenon: Extracted equipment power data units are mixed, with kilowatt and megawatt used together. Cause: No unit verification configuration is passed via the `variables` parameter, and no unit conversion verification is performed on the power field returned by the interface.

## How to Confirm Configuration is Complete
- Call the test interface, check whether the `Authorization` parameter is correctly carried, and whether the response header contains valid permission verification results.
- View the context variable transfer log, confirm whether the business fields in the `variables` parameter are consistent with the field names of the power generation group's internal system.
- Trigger the preset keyword interception scenario, check whether the custom external interface call is triggered, and whether the response data is correctly extracted from the `responseData` node.
- Simulate an intranet IP to initiate a request, confirm that the interface will not be blocked by current limiting, and the timeout setting meets the current business scenario requirements.
