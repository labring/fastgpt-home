# Internal Office and Employee Services for Power Generation Groups: Tool Calling and Plugins
This document is written for FastGPT v4.17.0.

## What the data for this category looks like
Data for internal office and employee services at power generation groups primarily comes from internal OA systems, production management ERP, employee attendance and reimbursement platforms, and station operation work order systems.
Data update frequencies cover real-time, daily, and monthly. Real-time data includes station equipment operating status and employee clock-in records. Daily data includes reimbursement approval progress and work order circulation status. Monthly data includes salary calculation reports.
Document structures primarily use structured forms, including fields such as employee ID, work order ID, associated equipment number, approval node, and processing duration. Common field units include pieces, hours, days, and MB.

## What constraints do these data characteristics impose on tool calling and plugins
The data characteristics of internal office and employee services for power generation groups impose multiple constraints on the tool calling and plugin link.
Real-time operating and clock-in data require plugin call response delays to meet business timeliness requirements, to avoid impacting station operation and maintenance and attendance processing.
Multi-source heterogeneous data sources require plugins to adapt to authentication and interface specifications of different systems, covering multiple authentication methods such as OAuth and static keys.
Monthly salary and calculation data have large volume, so plugins must limit the data range and number of returned entries per call to prevent interface timeouts.
Calls involving employee privacy fields must strictly follow permission control rules, only allowing authorized roles to trigger plugin calls for corresponding data.
The `toolChoice` configuration can be used to specify the called tool type, adapting to the calling logic of different businesses.

## How to set the configurations

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Tool call timeout period | 120–180 seconds | Adapt to the average response duration of internal system interfaces for power generation groups, avoid interrupting work order processing |
| Number of data entries returned per call | Top 20 entries | Match the conventional pagination limit for internal work order and approval data, prevent interface overload |
| Upload file size limit | 500–1000 MB | Adapt to the common file sizes of operation and maintenance logs and equipment inspection reports for power generation groups |
| Plugin authentication method | Match by system type | Cover the authentication specifications of different internal systems such as OA and ERP, ensure data access security |
| `functionCall` mode | Enable mandatory verification | Ensure that the parameter format of tool calls meets the interface requirements of internal systems, reduce call failure rates |
| `toolChoice` mode | Enable per scenario | Adapt to the tool call triggering logic of different businesses, improve call accuracy |

## Three common mistakes
- Phenomenon: A "File size exceeds limit" error occurs when calling a locally deployed tool, with status code 413 returned. Cause: The corresponding file size limit item is not configured in the container startup parameters, and the default 2 MB threshold is used, which cannot adapt to the common size of operation and maintenance logs for power generation groups.
- Phenomenon: Preset variables cannot be called when uploading files in a custom workflow, only external links can be entered. Cause: The variable reference switch for tool calling is not enabled, so the upload component only opens the static link input channel, and cannot bind file path variables from internal systems.
- Phenomenon: A connection failure error occurs when calling minio storage, and uploaded inspection reports cannot be saved. Cause: The access key and storage path of minio are not configured correctly, so the plugin cannot establish a stable storage link.

## How to confirm the configuration is correct
- Trigger a tool call for work order query, check if the returned data fields include preset employee ID, work order ID and associated equipment number, verify that the field structure matches the requirements of internal systems.
- Upload a test file that matches the business size, check if the plugin can receive and parse the file normally, confirm that the file size limit configuration takes effect.
- Call the locally deployed tool container, check if the container logs include authentication success records, confirm that the authentication link between the plugin and internal systems is normal.
- Trigger a file upload call with variables, check if the upload path correctly binds the preset internal system variables, confirm that the variable reference function works normally.
