# Internal Office and Employee Services for Power Generation Groups: Model Integration and Configuration

## Data Overview for This Category
Data for internal office and employee services at power generation groups primarily comes from group OA systems, ERP platforms, operation log databases, employee handbooks, and meeting minutes. Structured data includes process forms and operation reports. Fields cover station numbers, unit models, power generation load, approval status, and more. Common units are MW, hours, and person-times. Unstructured data consists of long-text meeting minutes and technical specification documents. Update frequencies range from real-time (for operation logs) to quarterly (for employee handbooks). Significant differences exist across document structures, so parsing rules must be adapted for multiple data types. This page is written based on FastGPT v4.17.0.

## Constraints for Model Integration and Configuration
The multi-type structure and specialized field requirements of internal office data for power generation groups first require model access configuration to adapt to structured data field mapping rules. This prevents generic parsing from causing recognition errors for specialized fields such as station numbers and power generation load. Real-time updated operation logs and high-frequency employee consultation needs require configuration items to support dynamic data synchronization and reasonable context length limits. This prevents context overflow during parsing of long-text meeting minutes. Static documents such as quarterly updated employee handbooks require configuration adjustments to the length of recalled text fragments. This ensures information accuracy during question answering.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to long-text meeting minutes and operation reports from power generation groups, retains sufficient context to avoid loss of critical business information |
| `maxTokens` | `2000–3000 token` | Matches the standard reply length for employee service-related question answering, avoids exceeding model call limits |
| `quoteMaxToken` | `4000 token` | Recalls sufficient structured process data and operation log fragments to support accurate business question matching |
| `temperature` | `0.3–0.5` | Meets the rigor requirements of internal office scenarios, reduces randomness in model replies |
| `AIPROXY_API_ENDPOINT` | Fill in the actual deployed model service address | Points to an available model access endpoint, adapts to OneAPI or locally deployed model services |
| `AIPROXY_API_TOKEN` | Fill in the generated authorization token | Completes identity verification for model services, ensures security of the access link |

## Three Common Configuration Mistakes
- Incorrect model service address entered when configuring `AIPROXY_API_ENDPOINT`, resulting in 404 errors. This occurs when the actual deployed model endpoint is not matched, or the authorization token does not match the endpoint.
- Setting `temperature` too high, leading to excessive variation in classification results. This happens when the model's randomness is too high, making it unable to stably match the standardized classification rules for internal office work.
- Failing to set a reasonable `maxContext` length, leading to context overflow when processing long-text operation logs, which triggers model call failure.

## How to Confirm Successful Configuration
- Call the model test interface, enter typical internal office questions for power generation groups, and check if returned results include correct specialized fields such as station numbers and process nodes.
- View the model call log, confirm that the verification status of `AIPROXY_API_TOKEN` is passed, with no 401 or 404 errors.
- Test question answering for long-text meeting minutes, and check that returned results do not show context truncation or overflow prompts.
- Adjust `temperature` to the 0.3–0.5 range, and verify that the consistency of classification results meets expectations.
