# Internal Office and Employee Services for Power Generation Groups: Forms and Interactions

## What the data for this category looks like
The data sources for internal office and employee services for power generation groups mainly come from the group's own OA system, production scheduling management platform, ERP financial system, and employee attendance management module.
Data update rhythm falls into two categories: production-related work orders and power data are updated hourly. Office-related application and approval data are updated daily.
Single data documents use structured JSON format, and contain fixed fields such as business number (e.g., device numbers with GE prefix), team ID, approval node ID, power parameters (unit: 10,000 kWh), and application item code. Different business forms correspond to different field subsets.

## What constraints these characteristics impose on the "forms and interactions" link
Fixed formats and unit requirements for production-related fields require forms to be configured with targeted format validation rules to prevent invalid data submissions.
Decentralized cross-system data sources require forms to support dynamic pulling of associated fields, rather than using hardcoded fixed values.
Node linkage logic of approval processes requires form selection options to update synchronously with the status of superior forms.
Large-volume work order attachment upload requirements require forms to support reasonable upload capacity limits.
Production data forms with high real-time requirements need to avoid data staleness caused by local caching.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `formInput` field validation rules | Customized per business field: validate GE prefix + 12-digit length for device numbers, validate 0-100 10,000 kWh range for power fields | Matches the fixed format and unit requirements of production-related fields for power generation groups |
| `userSelect` linkage configuration | Associate with superior work order status per approval node | Adapts to the node linkage logic of internal group approval processes |
| Form submission timeout period | 300 seconds | Covers the time required for large work order completion and cross-system data pulling |
| Form field cache duration | 15 minutes | Balances employee operational continuity and data real-time performance |
| Attachment upload limit | 100 MB | Meets the conventional storage requirements for internal group work order attachments |
| Error prompt template | Customized per business scenario, e.g., "Work order number format is incorrect, please check the prefix and length" | Matches the terminology habits of daily employee office work |

## Three Common Mistakes
- Phenomenon: An error "Cannot convert undefined or null to object" is thrown in the console after form submission. Cause: Required field validation for `formInput` is not configured, causing empty fields to be passed to the workflow.
- Phenomenon: Associated approval node data fails to load after form submission. Cause: Linkage refresh for `userSelect` is not enabled, and status changes of superior forms are not synchronized.
- Phenomenon: The number of processing results returned after form submission does not match expectations. Cause: The input character limit for `formInput` is not set, causing abnormal processing after ultra-long content is truncated.

## How to Confirm the Configuration is Correct
- Fill in a test data set that conforms to business formats, submit it, and check the workflow logs in FastGPT v4.17.0 for no error messages.
- Modify the approval status of a superior work order, and check whether the `userSelect` options of the subordinate form are synchronously updated to the corresponding optional values.
- Enter content that exceeds the preset length, and check whether an error prompt corresponding to the business scenario pops up.
- Upload an attachment larger than 100 MB, and check whether an upload capacity limit prompt is triggered.
