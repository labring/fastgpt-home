# Internal Office and Employee Services for State-Owned Industrial Funds: Tool Calling and Plugins

## What the data for this category looks like
Data for state-owned industrial funds primarily comes from state-owned assets supervision and filing systems, internal investment research ledgers, and project management platforms. The data includes fields such as fund subscribed scale, paid-in amount, post-investment project list, individual project investment amount, and investor entity information. The units are 100 million yuan and 10,000 yuan respectively. Filing-based basic information is updated quarterly. Post-investment project updates are synchronized weekly. Internal operation ledgers are updated daily. The number of entries per record fluctuates based on the number of managed funds.

## What constraints these characteristics impose on tool calling and plugins
The data fields of state-owned industrial funds have complex associations, including cross-entity subscribed, paid-in, and post-investment information. Tool calling must support nested parameter passing to meet cross-entity, multi-dimensional query requirements. The update rhythms of different data sources vary significantly. Plugins must distinguish and configure pull cycles to avoid resource occupation caused by high-frequency pulling of daily-updated internal ledgers. Field units include different magnitudes such as 100 million yuan and 10,000 yuan. Plugins must have built-in unit conversion logic to ensure the returned data format matches the display requirements of internal office systems. Post-investment project data is dynamically adjusted. Tool calling must support incremental pulling to reduce bandwidth consumption from full data transfers.

## How to configure
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Manually set to `functionCall` | Adapts to multi-parameter nested tool calling scenarios for industrial funds |
| Data source pull cycle | Configure separately by data source type: set internal ledgers to 1 hour, filing data to 24 hours | Matches the update rhythms of different data sources and reduces invalid requests |
| JSON input box variable binding | Enable the variable mapping toggle | Supports directly injecting variables such as internal OA project IDs and fund codes into JSON parameters |

## Three common configuration mistakes
- Symptom: Cannot select preset variables in the JSON input box, and fields show as empty after parameter submission. Cause: The variable mapping toggle for the JSON input box is not enabled, so the system cannot recognize the injected variable placeholders.
- Symptom: Connection timeout error is returned when calling a local MCP service. Cause: The intranet access whitelist for the local service is not configured, or the plugin's network request does not point to the correct local port.
- Symptom: URL image addresses returned by the plugin cannot be displayed in the internal office system. Cause: The domain name of the image URL is not added to the plugin's whitelist configuration, or cross-domain access support for image resources is not enabled.

## How to confirm a configuration is correct
- Submit a test call and check if the fields and units of the returned data match the format of the internal ledger.
- Check the tool calling logs to confirm that variables have been correctly injected into the parameters of the JSON input box.
- Simulate pull requests for different data sources to verify that the pull cycle matches the preset configuration.
- Call project data with restricted permissions to confirm that the returned results only include information within the authorized scope.
