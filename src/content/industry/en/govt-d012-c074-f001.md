# Internal Office and Employee Services for State-Owned Asset Management Companies: HTTP Interfaces and External Systems

## Data Structure for This Category
Data is primarily sourced from the state-owned asset supervision reporting system, internal asset ledger, employee attendance system, and office approval workflow.
Asset-related data includes fields such as asset number, storage location, book value, and management responsible person. Book values are measured in ten thousand yuan, and change information is updated in real time.
Employee-related data includes employee ID, affiliated department, job rank, and monthly attendance duration. Attendance duration is measured in hours, and data is synced daily.
Office approval data includes application number, application item, current node, and approval status. Data is updated in real time as submissions and workflows progress.
Overall data is stored in structured table format. Some associated data must be pulled via cross-system interfaces.

## Constraints for HTTP Interfaces and External Systems
Numerous structured fields and cross-system associations require request parameters to use the `variables` configuration field to set mapping rules, ensuring field matching between external systems and FastGPT.
Asset book values use ten thousand yuan as the unit. Interfaces must verify unit consistency of incoming values to avoid data deviations.
Employee attendance data is synced daily. Interface call frequency must adapt to the sync rhythm to avoid pulling redundant unupdated data.
Office approval statuses are fixed enumeration values. Interface return fields must strictly match preset enumerations; otherwise, external systems cannot correctly parse the data.
When pulling associated data across systems, the `Authorization` header must be configured to complete permission verification and ensure data access security.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {FastGPT assigned API key}` | Complies with FastGPT v4.17.0 interface authentication specifications to ensure request legitimacy |
| `variables` | `asset number → asset_id, employee ID → staff_id` | Matches core business fields of state-owned asset management companies to avoid mapping errors |
| `responseData` | `return only asset status, approval progress, attendance duration` | Slims returned content to adapt to the lightweight data needs of internal office work |
| Interface timeout setting | `600 seconds` | Cross-system queries for asset data may be required, reserving sufficient response time |
| Interface call frequency | `no more than 100 calls per hour` | Adapts to the sync rhythm of employee attendance and asset data to avoid redundant requests |
| Unit verification switch | `enabled` | Prevents unit mismatch issues for fields such as book value and attendance duration |

## Three Common Mistakes
- A 403 Forbidden status code is returned when calling the create application interface. The cause is that the `Authorization` header does not correctly fill in the API key assigned by FastGPT, resulting in authentication failure.
- After calling the knowledge base upload interface, the specified knowledge base does not include the incoming title and content. The cause is that the mapping relationship between the title, content and knowledge base fields is not configured via `variables`, and field mismatch causes data to fail to be written.
- After starting an offline-deployed Docker container, the interface returns an error when accessed via curl, and the log shows a request to the external network cl100k.tiktoken. The cause is that the local tokenizer file is not mounted, and the interface attempts to pull external resources by default, resulting in failure.

## How to Confirm Configurations Are Correct
- The authentication interface is invoked. The returned `responseData` is checked for a valid session token, and the `Authorization` configuration is confirmed to take effect.
- Test asset numbers and employee IDs are passed to the interface. The returned fields are checked to match the configured `variables` mapping rules, and field mapping is confirmed to be correct.
- Cross-system data pulling is simulated. The interface response time is checked to meet the preset timeout settings, and the timeout configuration is confirmed to be reasonable.
- The unit verification switch is enabled. Test data that does not comply with unit specifications is passed to the interface. The interface is checked to return a verification failure prompt, and the verification function is confirmed to take effect.
