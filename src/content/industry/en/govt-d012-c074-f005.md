# Internal Office and Employee Services for State-owned Asset Management Companies: Tool Calling and Plugins

## What the Data for This Category Looks Like
The internal office data of state-owned asset management companies mainly comes from state-owned asset supervision systems, internal financial ledgers, asset ownership certification documents, and daily operation records. Data update rhythms fall into two categories: monthly dynamic updates (such as asset allocation and disposal) and annual comprehensive inventory updates. The document structure is mainly structured ledgers. A single asset card includes fields such as asset number, recording date, book value, using department, storage location, and ownership status. Book value is measured in ten thousand yuan, and service life is measured in years. Bulk asset lists are mostly in Excel or CSV format.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Asset data includes sensitive fields such as ownership status and book value. Tool calling must limit the list of accessible fields to prevent unauthorized access to sensitive information. There are different update rhythms for monthly dynamic updates and annual inventory checks. Plugins must support incremental synchronization configuration, only pulling updated asset entries to avoid excessive system resource usage from full pulls. Structured ledgers have many fields and fixed formats. Tool calling must support precise field matching to avoid generalized queries returning irrelevant data. Bulk asset operation scenarios are common. Plugins must support execution of multi-line SQL statements, while restricting the permission scope of modification statements to ensure data security.

## How to Set Configurations
These configurations are designed based on the FastGPT v4.17.0 plugin system, adapted for internal office scenarios of state-owned asset management companies:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Meets the demand for automatic multi-tool selection in state-owned asset scenarios, no manual tool specification required |
| `functionCall` | `Enabled` | Forces the model to generate formatted tool calling requests, avoiding unstructured results |
| Database connection timeout | `300 seconds` | State-owned asset database queries usually involve multi-table joins, so sufficient response time must be reserved |
| Bulk query upper limit | `Top 20 entries` | Returning too much data in a single query will exceed the context window, while adapting to the conventional needs of state-owned asset bulk inventory |
| Sensitive data desensitization switch | `Enabled` | Fields such as asset ownership and book value are sensitive information, which must be automatically desensitized before tool return results |
| Tool calling retry count | `2 times` | Network fluctuations or temporary database lag may cause call failures, limited retries can improve success rate |

## Three Common Mistakes
- Phenomenon: Asset data fields returned by tool calling are missing or formatted incorrectly. Cause: No field access whitelist is configured, the model attempts to access unauthorized sensitive fields, or no fixed result parsing format is specified.
- Phenomenon: An error occurs when executing multi-line SQL queries, and insert and select statements cannot be run simultaneously. Cause: The multi-line statement execution switch is not enabled for the database plugin, or permission restrictions that only allow single statement execution are configured.
- Phenomenon: Tool calling results are unstable, and some queries return null values. Cause: No incremental synchronization mechanism is configured, expired cached data is used, or no reasonable retry count is set, and no automatic retry is performed after a single call fails.

## How to Verify Successful Configuration
- Initiate a bulk query request for asset ledgers, and check whether the returned fields match the configured whitelist.
- Execute a test request containing multi-line SQL statements, confirm that there are no permission errors and the results meet expectations.
- Simulate a tool calling failure scenario, confirm that the system automatically triggers the retry mechanism and returns normal results after retries.
- After enabling the sensitive data desensitization switch, view the tool return results, confirm that sensitive fields have been properly processed.
