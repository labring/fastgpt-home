# Internal Office and Employee Services for State-owned Asset Management Companies: Forms and Interactions

## What Data Looks Like for This Category
Internal data for state-owned asset management companies originates from state-owned asset supervision and reporting systems, internal asset full-life-cycle management platforms, and employee service ticket systems. Core asset ledgers are synced incrementally on a daily basis. Employee service forms are submitted and updated in real time. Documents fall into three categories: asset basic information cards, cross-department approval flow sheets, and employee appeal tickets. Fields include asset unique codes, using departments, book values, handler employee IDs, approval node identifiers, and some fields must comply with state-owned asset supervision reporting specifications.

## Constraints for Forms and Interactions
Daily incremental sync of core asset ledgers requires form data sources to support scheduled incremental data pulls. This avoids overloading system resources from full data pulls.
State-owned asset supervision reporting specifications require forms to have preset mandatory compliance fields. Field rules cannot be deleted or modified arbitrarily.
Multiple document structures require interactive components to support dynamic switching of form templates. This adapts to different business scenarios such as asset declaration, expense reimbursement, and appeal submission.
Field level associations require form interactions to automatically match departments and approval nodes. This reduces manual configuration costs.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Form data source refresh interval | 15 minutes | Matches the daily incremental update rhythm of state-owned asset ledgers, balancing data timeliness and system load |
| `formInput` component default value configuration | Automatically fill based on the department to which the currently logged-in user belongs | Adapts to the business requirement of binding using departments for asset declaration, reducing manual input operations |
| `userSelect` component data pull scope | Employee lists of the current department and direct superior departments, pull the first 20 entries | Narrow the range of approver selection, matching the hierarchical approval process of state-owned asset management companies |
| Form mandatory field validation rules | Comply with state-owned asset supervision reporting specifications | Meet mandatory requirements for internal compliance and external supervision reporting |
| Interactive feedback popup duration | 3 seconds | Avoid interrupting employees' daily operation processes, ensuring smooth interactive experience |

## Three Common Configuration Mistakes
- When the `formInput` component is bound to a global variable, the node prompts that the variable input is empty during runtime. The cause is that the automatic sync global variable switch was not enabled in the component configuration, causing the variable to not be correctly passed to downstream nodes.
- When the temperature parameter is configured for the chat node, the generated results do not adjust logical rigor as expected. The cause is that the temperature parameter was not bound via variable reference; the directly entered value was not recognized by the large model call.
- When clicking the form copy button, a prompt to manually select text pops up, and the generated markdown content has no line breaks. The cause is that the automatic formatting of copied content configuration item was not enabled, causing format markers to not correctly parse line break logic.

## How to Verify Configurations
- Log in to the test account, submit an asset declaration form, check if mandatory field validation triggers corresponding prompts, confirm compliance with preset supervision reporting specifications.
- Trigger a manual refresh of the form data source, check if the `userSelect` component dropdown list displays the latest department and employee data, confirm that the refresh interval configuration is effective.
- Initiate a chat test, check if the generated results include the configured thought process, confirm that large model parameters and component configurations are synchronized.
- Click the form copy button, check if the generated content includes correct line break formatting, confirm that the formatting configuration is enabled.
