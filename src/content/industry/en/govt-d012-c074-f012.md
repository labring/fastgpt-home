# Internal Office and Employee Services for State-owned Asset Management Companies: Deployment and Upgrade
This document is written based on FastGPT v4.17.0.

## What this category of data looks like
State-owned asset management companies’ internal office and employee service data mainly comes from state-owned asset supervision ledger systems, internal OA office systems, financial accounting systems, and employee file repositories. State-owned asset data focuses on full life cycle information of assets, including fixed fields such as asset number, book value, using department, storage location, and similar details. Common units include ten thousand yuan, square meters, and sets (units). Data is synchronized on a monthly or quarterly basis. Internal office data covers employee attendance, approval workflows, meeting arrangements, and similar content, and is updated in real time daily. Document structures are mostly standardized forms and structured reports.

## What constraints these characteristics impose on deployment and upgrade
The fixed fields of state-owned asset data and compliant storage requirements mean that storage and database mapping rules meeting state-owned asset supervision standards must be configured in advance during deployment. Field structures cannot be adjusted arbitrarily during upgrades to avoid damaging existing data associations. Reasonable cache service configuration is required during deployment, and session continuity must be maintained during the upgrade process. Asset documents have large individual file sizes. Upgrades must be compatible with storage configurations for large file uploads, and existing asset data must be backed up in advance to prevent data loss during the upgrade.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300 connections` | Matches the concurrent connection demands of daily asset ledger queries and office system interactions for state-owned asset management companies |
| `STORAGE_S3_ENDPOINT` | Exclusive access address provided by the state-owned cloud storage service provider | Meets compliance requirements for state-owned asset data storage |
| `REDIS_URL` | Internal dedicated cache cluster connection address | Ensures stability of internal office sessions and asset caches |
| `FILE_TOKEN_KEY` | `32-bit random encrypted string` | Prevents malicious tampering of file upload requests |
| `FE_DOMAIN` | Company internal office subdomain | Restricts valid domain ranges for frontend access |
| `ROOT_KEY` | Key set according to internal permission control rules | Ensures permission security for administrator operations |

## Three common mistakes
- Model vendor icon loading failure after upgrade. The symptom is that model vendor logos fail to display on the frontend page, and the console prompts that the resource path does not exist. The cause is that the deployment path configuration of frontend static resources was not synchronized and updated during the upgrade, resulting in failure to correctly load vendor icon resources.
- `fail to create post presigned url` error when adding attachments during conversation. The symptom is that this error pops up after clicking the add attachment button, and file upload cannot be completed. The cause is that `STORAGE_S3_ENDPOINT` is configured incorrectly, or the access permission of the S3 storage bucket is not open, resulting in failure to generate a valid pre-signed upload link.
- RAG file upload error after migrating S3 storage. The symptom is that the file upload progress stalls or fails directly, and background logs show storage connection exceptions. The cause is that `DB_MAX_LINK` was not adjusted to adapt to the increased file upload concurrent requests, resulting in exhausted database connections and inability to process upload requests.

## How to confirm configurations are correct
- Log in to the FastGPT backend monitoring panel, check the database connection count metric, and confirm that the current connection count does not exceed the configured `DB_MAX_LINK` upper limit.
- Upload a test file that conforms to the state-owned asset document format, verify that the pre-signed link is generated normally and the file can be successfully uploaded to the specified storage location.
- Access the company internal office domain, open the FastGPT frontend page, and verify that all static resources load normally without error prompts.
- Use the configured `ROOT_KEY` to perform an administrator permission test, confirm that system configuration modification operations can be executed normally, and permission verification takes effect.
