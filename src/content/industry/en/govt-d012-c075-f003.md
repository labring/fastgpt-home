# Internal Office and Employee Services for State-owned Capital Investment Companies: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Internal office and employee service data for state-owned capital investment companies comes from group OA systems, ERP management platforms, state-owned assets supervision reporting systems, employee handbooks, and investment project archives.
Structured data such as state-owned assets statistical reports is updated quarterly. Unstructured data such as internal notifications and project feasibility study reports is updated in real time based on business nodes. Employee salary and performance data is updated monthly.
Documents include structured fields and units, such as total foreign investment (100 million yuan) and number of subordinate enterprises (units). They also contain long-text unstructured documents. The full data set covers business and administrative scope for group headquarters and subsidiaries at all levels.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Internal data sources are scattered and have mixed structures. Multi-turn dialogue must maintain context boundaries for different systems in `messages` to avoid cross-system data confusion.
Some data is updated quarterly. Prompts must clearly mark data validity periods to prevent returning outdated state-owned assets statistical information.
The data includes sensitive undisclosed investment and financial fields. Prompts must restrict unauthorized disclosure of classified content during dialogue.
Employee data is divided by hierarchy. Multi-turn dialogue must pass the user's hierarchy through `variables` to match corresponding data access permissions.
The share of long-text documents is high. The context length of `messages` must be controlled to avoid token overflow that disrupts dialogue fluency.

## Three Common Mistakes
- Phenomenon: Returns invalid parameter error when calling a Java interface, prompting that `appId` is not configured. Cause: Mistook the application ID for the calling secret key. The actual required value is the API key allocated by the platform, and it must be bound to the corresponding dialogue application.
- Phenomenon: Dialogue directly returns text fragments retrieved from the knowledge base, without AI organization and format optimization. Cause: Did not connect the AI dialogue module in the dialogue process, only called the knowledge base retrieval interface, and did not complete intent understanding for multi-turn dialogue.
- Phenomenon: After uploading state-owned assets-related files, the dialogue cannot retrieve content within the files. Cause: Did not configure the file parsing module in the dialogue process, or did not explicitly require calling file content in the prompt.

## How to Confirm Proper Configuration
- Initiate a test dialogue with multi-turn context, input questions from employees of different hierarchies, and check whether returned results match the data scope of corresponding permissions.
- Adjust parameter values passed through `variables`, verify whether dialogue results change with the parameters, and confirm that the parameters take effect.
- Upload internal documents related to state-owned assets, initiate relevant questions, and check whether retrieved content includes key information in the documents.
- Switch the prompt language parameter, verify whether the dialogue prompt updates synchronously, and confirm that multi-language configuration takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
