# Internal Office and Employee Services for State-owned Capital Investment Companies: Tool Calling and Plugins

## What the data for this category looks like
Internal office data mainly comes from the company’s own OA system, human resource management platform, project management system, and state-owned assets supervision reporting ledger. The update rhythm follows two schedules: real-time synchronization of approval workflows and employee attendance data on working days, and daily batch updates of financial reimbursement and project budget data. Documents primarily use structured fields. Core fields include employee ID, department code, approval order number, budget amount (unit: ten thousand yuan), project execution cycle (unit: days), and attendance check-in duration (unit: hours). Field enumeration values cover fixed classification items such as approval status and job level.

## What constraints do these characteristics impose on the tool calling and plugins link
Internal office data is multi-source heterogeneous with layered update rhythms. This requires tool calling to distinguish between real-time and batch data sources, and configure different trigger logic for each. Structured fields contain sensitive information required by state-owned assets supervision regulations. Add a field legitimacy check before tool calling to avoid unauthorized calls of classified data. Most internal systems use custom deployments, so plugins must adapt to private authentication protocols, and cannot directly rely on authentication specifications for general third-party interfaces. Data related to employee services involves personal privacy. Tool calling must strictly follow data desensitization rules, and only return field information within the authorized scope.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to multi-plugin parallel calling scenarios, automatically matches the internal office tools required for the current conversation |
| Tool calling timeout | 30 seconds | The response delay of internal custom systems generally falls between 10 and 25 seconds. 30 seconds covers most normal calling scenarios |
| `functionCall` parameter validation | Enabled | Enforces matching validation between structured input parameters and plugin-defined fields to avoid invalid calls |
| Plugin authentication method | Private CA certificate authentication | Meets security compliance requirements for internal systems of state-owned capital investment companies, and aligns with state-owned asset data security specifications |
| Batch tool calling interval | 5 minutes | Internal data for daily batch synchronization updates once per day. A 5-minute interval avoids repeated requests occupying system resources |
| Context window limit | 8000 token | Internal office conversations usually include multi-round approval process descriptions. 8000 tokens covers complete conversation context |

## Three common mistakes
- Phenomenon: When no tool calling termination node is added in workflow orchestration, the session waits continuously and triggers a timeout error with a 504 status code. Cause: Without a configured termination node, the system cannot determine whether the tool calling workflow is completed, and continuously occupies session resources until the timeout threshold is triggered.
- Phenomenon: When calling a preset tool, unexpected results are returned, with empty fields or abnormal formats. Cause: The `functionCall` parameter validation switch is not enabled, and input parameters that do not conform to the plugin definition are not filtered, causing the tool to fail to correctly parse the request.
- Phenomenon: When trying to display a custom card via a plugin, no card content loads on the interface. Cause: Structured output mode is not enabled in the plugin configuration, and the JSON data returned by the plugin is not correctly recognized by the system as a renderable card format.

## How to confirm the configuration is complete
All verification actions must be completed on FastGPT v4.17.0.
- Initiate a test conversation involving internal approval queries, and check whether the tool calling parameters in the conversation log match the plugin-defined fields.
- Trigger a batch synchronization tool task for employee data, and verify that the calling interval in the system execution log conforms to the preset configuration.
- Input parameters that do not conform to the plugin definition, and confirm whether the system triggers parameter validation interception and returns compliance prompts.
- Call the state-owned assets supervision report query tool, and verify that the returned results include only fields within the authorized scope, with no sensitive data leakage.
