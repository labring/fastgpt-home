# Internal Office and Employee Services for State-owned Capital Investment Companies: Deployment and Upgrade

## What the data for this category looks like
Data sources for internal office and employee services of state-owned capital investment companies include internal office OA systems, personnel management platforms, state-owned assets supervision reporting systems, employee service ledgers, meeting minute document libraries, and more.
Update cycles cover daily, weekly, monthly, and other periods, corresponding to different types of content such as employee attendance changes, office asset inventory, and state-owned assets reporting data.
Document structures include structured fields and unstructured content. Structured fields typically include employee ID numbers, department codes, state-owned asset numbers, budget amounts, and similar items. Unstructured content mainly consists of office documents, feedback tickets, and meeting minutes, with formats including PDF, Word, and structured tables.

## What constraints these characteristics impose on deployment and upgrades
Dispersed data sources and diverse formats require configuring multiple types of data source connections during deployment, and adapting separate storage for structured and unstructured data.
Differing data update frequencies require adjusting incremental synchronization trigger rules during upgrades, to avoid synchronization delays or repeated data loading.
Fields include content dedicated to state-owned assets supervision. Deployments must retain the original field structure to ensure data compliance.
Internal service access requires scope restrictions. Deployments must configure secure domain names and permission controls to prevent unauthorized access to internal data.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `150-250 connections` | Adapts to concurrent requests from multiple departments, avoids database connection pool overflow |
| `MONGODB_URI` | `mongodb://gc-invest:pass@internal-db:27017/fastgpt?authSource=admin` | Stores unstructured office documents and employee feedback data, adapts to high-concurrency read/write operations |
| `PG_URL` | `postgresql://gc-invest:pass@internal-pg:5432/gc_invest?sslmode=require` | Stores structured state-owned assets and personnel data, ensures data consistency |
| `REDIS_URL` | `redis://:gc-pass@internal-redis:6379/0` | Caches sessions and high-frequency requests, improves response speed for internal services |
| `STORAGE_S3_ENDPOINT` | `http://s3-internal.gc-invest.gov.cn:9000` | Uses internal compliant object storage to store original documents, meets security requirements |
| `FE_DOMAIN` | `https://oa.gc-invest.com` | Binds to internal office domain names, restricts access scope to ensure data security |

## Three Common Mistakes
- Symptom: All model calls fail, and the interface displays "Database connection failed". Cause: The connection parameters for `MONGODB_URI` or `PG_URL` were not filled correctly during Docker deployment, resulting in failure to load business data.
Reference only; verify against the target FastGPT release and deployment documentation.
- Symptom: Teams cannot be created and members cannot be added to use the deployed application. The interface prompts "No permission to access". Cause: The `ROOT_KEY` was not configured correctly to generate initial administrator permissions, and permission configuration for team members was not completed.

## How to Confirm the Configuration is Complete
- Run the docker-compose ps command to confirm that all service containers are in a running state, with no abnormally exited logs.
- Access the internal address bound to `FE_DOMAIN`, log in to the backend, enter the data source configuration page, and perform a connection test to confirm that the connection status of `MONGODB_URI` and `PG_URL` is normal.
- Upload an internal office document, check whether the storage service corresponding to `STORAGE_S3_ENDPOINT` successfully receives and stores the file, and that the parsed text is displayed normally on the retrieval page.
- Create a test team, add a test member account, confirm that the member can log in and access the shared office Q&A application, with no permission error prompts.
