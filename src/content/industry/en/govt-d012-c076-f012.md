# Internal Office and Employee Services for State-owned Capital Operation Companies: Deployment and Upgrade

## What this category’s data looks like
Data for internal office and employee services at state-owned capital operation companies primarily comes from internal heterogeneous systems including state-owned assets supervision systems, employee attendance platforms, financial reimbursement systems, and party committee work portals. Data update rhythms cover two categories: real-time updates (such as reimbursement submission and attendance check-in) and daily batch synchronization (such as employee changes and budget execution). Document structures include structured business forms (with fields such as state-owned assets supervision number, employee ID, affiliated subsidiary, and others), unstructured meeting minutes, and policy documents. Field units include common business units such as person-times, yuan, and days, with no unified standardized format.

## What constraints these characteristics impose on deployment and upgrade
Since data sources involve multiple sets of heterogeneous internal systems, configure multiple data source connections during deployment. This prevents service interruptions caused by exhaustion of a single connection pool. Adjust vector library synchronization frequency to match real-time data business peaks. Adjust scheduled task cycles for batch synchronized data. Adapt different document parsing rules for mixed structured and unstructured data formats. During deployment, isolate core data from test environments to meet state-owned assets data compliance requirements. Configure dedicated storage and permission control. During the upgrade process, maintain the integrity of data backup and rollback mechanisms.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `DB_MAX_LINK` | 10–20 concurrent connections | Adapt to concurrent access needs of multi-system data sources, avoid connection pool exhaustion |
| `MONGODB_URI` | Dedicated replica address connecting to state-owned assets supervision data | Isolate core business data from test data, comply with state-owned assets data security specifications |
| `PG_URL` | Configure structured data connection strings for employee systems and reimbursement systems | Support reading and parsing of multi-source structured business data |
| `STORAGE_S3_ENDPOINT` | Access the compliant cloud storage endpoint specified by the state-owned assets system | Meet compliance requirements for state-owned asset data storage |
| `FILE_TOKEN_KEY` | Configure an encrypted token with a 7-day validity period | Adapt to the temporary access cycle of internal office files |
| `ROOT_KEY` | Encrypted key held only by deployment administrators | Control modification permissions for background core configurations, prevent unauthorized operations |

## Three common errors
- Phenomenon: The iframe embedded in the internal office system still displays the Markdown export button, and this function cannot be disabled. Reason: The export configuration in the iframe embedding module of the front-end source code has not been modified, and the related rendering logic has not been disabled.
- Phenomenon: When deploying on an arm64 architecture server, pulling the image fails, and an error indicating image architecture incompatibility occurs. Reason: The default deployment image only supports amd64 architecture, and the image address of the arm64 version has not been specified.
- Phenomenon: When upgrading from version v4.9.10 fix2, a docker daemon error occurs, prompting an image registry error. Reason: The local old version image cache does not match the new version repository verification rules, and the old image has not been cleaned or the correct repository address has not been replaced.

## How to confirm the configuration is complete
- Use the FastGPT v4.17.0 deployment package to execute the `docker ps` command. Confirm that all deployment containers are in running status, and there are no abnormal exit records.
- Access the configured `FE_DOMAIN` address, log in, test the connection to multi-source data sources, and check whether business data loads normally.
- Upload an internal policy document, test whether the document parsing and vector database import process completes normally.
- Log in to the backend with a non-administrator account, verify that core configuration items related to `ROOT_KEY` cannot be modified.

The values given are common starting points and should be measured against the reader's own samples.
