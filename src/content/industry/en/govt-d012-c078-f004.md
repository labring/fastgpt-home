# Internal Office and Employee Services for Urban Water Utilities: Workflow Orchestration

## What the data for this category looks like
Business data for urban water utilities comes from pipe network monitoring devices, water plant operation logs, customer repair work orders, water quality test reports, employee inspection records, and similar sources. Data update frequencies vary: pipe network monitoring data updates in real time at minute-level intervals, repair work orders and inspection records are submitted in real time, and water quality test reports update daily or weekly in batches. Data document structures include fields such as device ID, timestamp, parameter values (e.g., turbidity, water pressure, residual chlorine), work order number, processing progress, and employee ID. Some fields have specific units: turbidity uses NTU, water pressure uses MPa.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources require workflows to support aggregating different types of business data across multiple nodes, to avoid data gaps. Different update frequencies require workflows to adapt to diverse triggering methods: support real-time event triggering for high-frequency monitoring data, and scheduled triggering for periodic reports. Fields with specific units require workflow variable configurations to strictly match the unit definitions of corresponding parameters, to prevent parameter parsing errors. Large file data with significant size variations, such as large-scale pipe network CAD drawings and complete water quality test reports, require workflow file processing nodes to support flexible size adaptation and chunked processing.

## Three common configuration errors
- Setting the chat history limit to 1 in the workflow still returns multiple historical records. The cause is failing to bind the context window to the history variable in `variables`, resulting in the system calling the global context configuration.
- Uploading a file fails when calling the workflow via API, with the prompt Failed to create post presigned url. The cause is failing to configure correct storage path permissions in the workflow's file upload node, or the file size exceeding the preset threshold.
- Passing file parameters via the API call plugin results in no response. The cause is failing to correctly bind the file variable to the plugin's input parameters, resulting in mismatched parameter formats.

## How to confirm the configuration is correct
- Trigger the workflow by passing a simulated water utility work order data, check if the work order number and corresponding field values are correctly extracted in `variables`.
- Upload a small water quality test PDF file, confirm that the workflow can normally parse and extract text content.
- Adjust the trigger node to event trigger, simulate device data reporting, check if the workflow executes automatically.
- View the workflow execution logs, confirm that the retry count and timeout duration configurations take effect during execution.
