# Internal Office and Employee Services for Urban Water Utilities: Model Integration and Configuration

## What the data for this category looks like
Business data for urban water utilities comes primarily from pipeline monitoring sensors, water plant central control systems, water quality testing laboratories, and internal work order systems. Real-time data such as pipeline pressure and flow is updated every second. Water quality testing reports are synced daily. Monthly operation work orders are summarized each month.

Data documents are divided into three categories: structured monitoring tables, semi-structured work order records, and unstructured testing reports. Structured fields include point ID, detection time, value, and corresponding unit. Work order records include repair request number, processing status, associated area, and other information.

## What constraints these characteristics impose on the model integration and configuration step
High-frequency updates of real-time monitoring data require model integration to support short-interval synchronization or streaming context, to prevent context overflow. Structured data includes dedicated fields and units such as pressure kPa and flow m³/h. Clear field mapping rules must be defined in configuration to avoid unit confusion. Unstructured testing reports have a high proportion of long text, so a per-input token limit must be set. The associated area field in work order systems requires precise matching, so context recall matching rules must be adjusted to ensure accurate associated information. The multi-source heterogeneous data characteristic also requires configuration to support a unified access format for multiple data sources, to avoid data format conflicts between different systems.

## How to set up configuration
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length after splicing multi-source data in water utility scenarios, avoids exceeding the model's capacity limit |
| `maxTokens` | 2000–3000 token | Single-round replies need to cover content such as water quality analysis and work order processing suggestions, avoids truncating key information |
| `quoteMaxToken` | 4000 token | Recalled reference content such as monitoring data and work order records needs to fully retain core fields such as point IDs and values |
| `temperature` | 0.3–0.5 | Water utility scenarios require precise technical suggestions, excessive randomness should be avoided |
| `AIPROXY_API_ENDPOINT` | Actual access address for deployed model services, e.g., http://B machine IP:11434/v1 | Specifies the correct API access path when connecting to externally deployed model services |
| `AIPROXY_API_TOKEN` | Token value matching the model service | Verifies access permissions between FastGPT and the model service, ensures valid calls |

## Three common configuration errors
- Symptom: Model calls return token verification failure, with OneAPI logs showing the token as "fastgpt". Cause: The `AIPROXY_API_TOKEN` configured in FastGPT does not match the token set in OneAPI, leading to permission verification failure.
- Symptom: Cross-machine deployment causes model connection timeout, with no model response obtained. Cause: Network permissions for the model service port are not opened, or the IP address or port filled in `AIPROXY_API_ENDPOINT` is incorrect, leading to network connectivity failure.
- Symptom: Model replies truncate key values or point information of water utility data. Cause: The values set for `maxTokens` or `quoteMaxToken` are too small, causing reference data or reply content to be truncated.

## How to confirm successful configuration
- Verify that the configuration values of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` exactly match the address and token of the target model service.
- Initiate a test query targeting water utility work orders or water quality analysis, and confirm whether the model can correctly recall associated monitoring data and work order records.
- Adjust parameters such as `temperature`, and observe whether the randomness of model replies meets scenario requirements.
- Check FastGPT's model call logs, and confirm there are no abnormal prompts such as token errors or connection timeouts.
