# Internal Office and Employee Services for Urban Water Utilities: Forms and Interactions

## What the data for this category looks like
Business data for urban water utilities comes from pipeline monitoring sensors, smart water meter metering systems, operation work order platforms, and water quality testing laboratories. Real-time sensor data such as pipeline pressure and flow updates every second. Operation work orders are submitted immediately as processing nodes advance. Water quality test reports update daily or weekly per sampling batch. Document structures include pipeline node archive tables, operation work order record tables, and water quality testing ledger tables. Fields include device ID, pipe diameter, installation date, work order ID, processing status, sampling point, turbidity (unit NTU), pressure value (unit kPa), and more. Fields are bound to specific business units, with no generic vague fields.

## What constraints these characteristics impose on forms and interactions
The second-by-second update rhythm of real-time sensor data such as pipeline pressure and flow requires form input controls to support real-time verification of the match between input values and current monitoring thresholds. The presence of specific business units such as kPa, NTU, and m³/h requires forms to automatically bind corresponding units, to avoid unit confusion caused by manual input. The need for parallel calls of multi-source data requires that form dropdown options support associating data sources from different business systems. Local static options cannot cover the call needs of multi-system data. For regional-bound operation work order scenarios, form controls need to support linked filtering of selectable content by administrative region and pipeline section, to narrow the selection range and improve entry efficiency.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind a business unit prefix, such as "Pressure Value (kPa):" | Match the exclusive business units of urban water utilities, to avoid manual input unit errors |
| `userSelect` | Filter selectable personnel by pipeline section, limit the scope to the current section's operation team | Adapt to the business logic of water utility operations assigned by section, narrow the selection range |
| Real-time verification threshold | 800–1200 milliseconds | Match the update rhythm of real-time sensor data, ensure verification takes effect promptly |
| Bulk import limit | 50 entries per batch | Adapt to the conventional batch size of single sampling for water quality testing ledgers |
| Pop-up trigger rule | Hide dialog box only when triggered at the top level of the current workflow | Resolve abnormal pop-up display issues in nested workflow scenarios |
| Data source refresh interval | 30 seconds | Adapt to the conventional update rhythm of operation work orders, avoid frequent interface calls |

## Three Common Misconfigurations
- Phenomenon: A form input node nested in another workflow always displays a dialog box. Cause: The pop-up trigger rule was not configured correctly. Only the hidden logic for the top-level workflow was adapted, and the trigger conditions for nested scenarios were not handled.
- Phenomenon: Single-choice or multiple-choice controls configured via `formInput` or `userSelect` have empty field values or values that do not match expectations after submission. Cause: The exclusive data source fields of urban water utility business were not bound, and parameter passing did not match the field structures of pipeline, water quality testing and other businesses.
- Phenomenon: No status prompt appears after form submission, making it impossible to confirm the submission result. Cause: The feedback logic after form submission was not configured, and the submission status interface of the water utility operation work order system was not associated.

## How to Confirm Proper Configuration
- Open the form editing interface, check whether the input controls are bound to the corresponding business units, such as kPa displayed next to pressure values.
- Simulate a nested workflow call scenario, confirm that the dialog box display logic matches the expected configuration.
- Submit a test form, verify that the field values are correctly associated with the water utility business data sources, and that status feedback is provided after submission.
- Test the bulk import function, confirm that the limit logic of the import limit matches the configured requirements of the business batch size.

The values listed above are common starting points, and should be evaluated against actual deployment samples.
