# Internal Office and Employee Services for Urban Gas Utilities: Multi-turn Dialogue and Prompt Engineering

## What the data for this use case looks like
Internal office data for urban gas utilities primarily comes from pipeline inspection systems, customer service ticket platforms, gas meter measurement systems, safety inspection archives, and employee management systems. Data update frequencies cover real-time (for tickets and inspection reports), daily (for meter reading data and shift schedule updates), and monthly (for training assessment archives). Each document includes fields such as station code, operation time, hidden danger level, and processing status. Units for indicators such as pressure and leakage volume are kPa and m³/h. Employee-related documents include information such as employee ID, position, and shift cycle.

## Constraints imposed by these characteristics for multi-turn dialogue and prompt engineering
Fields and units for pipeline inspection, ticket, and other data follow industry-specific specifications. Prompts for multi-turn dialogue must explicitly require uniform use of legal units such as kPa and m³/h to avoid confusion between different measurement standards. Data sources are scattered and have large differences in update frequencies. Multi-turn dialogue must use `variables` to bind knowledge base permissions for corresponding data sources, allowing only the document subset matching the current session user’s position to be called. Individual documents have lengthy content, so the context window length must be limited to avoid exceeding the model’s processing limit. At the same time, prompts must specify that only field information relevant to the current question be extracted.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window length | 800–1200 characters | Matches the average length of individual business documents for urban gas utilities, avoiding exceeding the model’s processing limit |
| `chatId` binding rule | Bind employee ID and affiliated station | Ensures multi-turn sessions only call station data within the employee’s permissions, complying with internal data security requirements |
| `messages` history retention rounds | Last 6 rounds | Balances context coherence and model processing efficiency, adapting to the typical number of question rounds for single sessions in gas utility business |
| Prompt variable binding | Pass position type via `variables` | Automatically filters documents unrelated to the current position, accurately matching scenarios such as inspections and tickets |
| Markdown output control | Disabled | Adapts to the concise reading needs of internal office work, avoiding format interference |
| Session reuse configuration | Enable same-session continued chat | Avoids creating new sessions each time, adapting to employee usage habits of continuously consulting the same business |

## Three Common Misconfigurations
- Symptom: Dialogue results only display in the side panel, with no content in the main dialog box. Cause: The "directly output session results" configuration is not enabled, causing results to be directed to the side panel.
- Symptom: A new session is created for each dialogue, and continued chat is not possible. Cause: The same-session reuse setting is not enabled, or `chatId` is not correctly bound to the current employee session, causing the system to default to creating a new session.
- Symptom: Output content includes Markdown formatting tags, which do not meet the concise reading needs of internal office work. Cause: The prompt template does not explicitly specify disabling Markdown formatting, or the plain text output configuration item is not enabled.

## How to Verify Proper Configuration
- Initiate a business question matching the current position, and check whether the output content only includes station data within the permitted scope, with no cross-position document information.
- Launch 3 consecutive themed consultation questions, and confirm that the session is not automatically recreated, and the context retains previous dialogue content coherently.
- Test the output content, and confirm that there are no Markdown formatting tags such as headings or lists, only plain text information is displayed.
- Switch employee accounts and launch a consultation, and confirm that the called document range is updated synchronously to the permission content of the current account.

The values provided are common starting points and should be measured against the reader's own samples.
