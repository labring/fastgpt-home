# Internal Office and Employee Services for Urban Gas: Model Integration and Configuration

## What the Data for This Category Looks Like

Urban gas internal office data mainly comes from SCADA monitoring systems, business hall payment systems, handheld inspection terminals, and station IoT sensors. Data is divided into two categories: structured and semi-structured. Structured data includes inspection point numbers, pipeline pressure values, user payment records. Most fields use fixed codes and numeric types, with units including kPa, hours, yuan, and other standard units. Semi-structured data includes operation logs, alarm work orders, and formats vary slightly by work order type. Data update frequencies fall into three categories: real-time (leak alarm data), daily (payment and operation daily reports), monthly (pipe network pressure statistical reports). No bulk archived unstructured documents are included.

## What Constraints These Characteristics Impose on Model Integration and Configuration

Differences in fields and units across multi-source structured data require clear field mapping rules during model integration, to avoid models confusing similar metrics from different data sources. High-frequency updates of real-time alarm data require configuring reasonable timeout parameters for model call interfaces, to prevent request backlogs and response delays. Flexible formats of semi-structured operation logs require adjusting model randomness parameters to adapt to non-standard content parsing. Decentralized data sources require configuring exclusive permissions for proxy interfaces, to ensure transmission security and compliance of internal data. FastGPT v4.17.0's model integration framework must adjust configuration items to adapt to urban gas internal office scenarios.

## How to Set the Configuration

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Covers context-related information from multi-source historical work orders and inspection records, meets cross-data query needs for internal office work |
| `maxTokens` | `2000–3000 token` | Adapts reply lengths for internal office scenarios, covers routine content such as operation suggestions and work order processing workflows |
| `quoteMaxToken` | `1500 token` | Limits single reference length of inspection reports and alarm logs, avoids excessive total token usage |
| `temperature` | `0.3–0.5` | Reduces randomness of model output, ensures accuracy of internal process guidance and data parsing |
| `AIPROXY_API_ENDPOINT` | `exclusive proxy address deployed on domestic compliant nodes` | Adapts transmission compliance requirements for gas internal data, ensures low-latency real-time data calls |
| `AIPROXY_API_TOKEN` | `access token bound with exclusive permissions` | Restricts only internal office systems to call model interfaces, prevents sensitive data leakage risks |

## Three Common Configuration Mistakes

- Configuring `AIPROXY_API_ENDPOINT` as a public proxy address results in 404 errors during calls. Reason: No internal data source whitelist for the exclusive proxy address is configured, or the token permission scope does not cover access to the corresponding data source.
- Unable to call the specified voice model after enabling voice function, returning a model not supported prompt. Reason: No access configuration for the corresponding voice model is added in FastGPT's model channels, or the supported voice model list is not selected.
- Question classification recognition is inflexible, and input gas work order types cannot be correctly categorized. Reason: No question classification background knowledge format is configured per industry standards, or the prompt does not clearly define work order classification field rules for the gas industry.

## How to Confirm the Configuration Is Successful

- Submit simulated gas inspection work order data, verify that the model's returned parsing results correctly match fields and units.
- View model call logs to confirm that the interface response time meets preset low-latency requirements.
- Verify the permission scope of `AIPROXY_API_TOKEN` to confirm that only internal office systems can initiate calls.
- After enabling voice function, initiate a voice interaction test to confirm that the voice model can normally generate and play replies.
