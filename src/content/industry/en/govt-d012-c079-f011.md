# Urban Gas Utility Internal Office and Employee Services: Forms and Interactions

## What the data for this category looks like
The data used for urban gas utility internal office work comes from pipeline inspection terminals, gas work order systems, remote gas meter collection systems, and user installation registration databases. Data update cycles are split into real-time (for work order routing and meter readings) and daily (for inspection point summaries). Each document includes fields such as work order ID, inspection point code, medium pressure value, inspection time, and processing status. Pressure values use kilopascals (kPa) as their unit. Inspection point codes follow a six-digit numeric format. The installation scale field uses cubic meters per hour as its unit.

## Constraints imposed on forms and interactions
The large number of pipeline inspection points and inconsistent field units require forms to have field format validation rules configured. These rules restrict non-numeric content from being entered into pressure value fields, and enforce that point codes match the six-digit numeric format. Real-time updated work order and meter data requires form interactions to trigger backend data synchronization immediately after submission, to avoid data lag. For bulk inspection record import scenarios, set a character limit for single-batch imported documents to prevent errors triggered by overly large input content. When users select inspection personnel or points, the corresponding preset fields must load dynamically, to reduce manual input errors.

## How to set configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Single field input limit of 800–1200 characters | Matches the typical input length of urban gas inspection records and work order notes, to avoid errors triggered by overly large content |
| `userSelect` | Preload the first 20 point codes in dropdown options | Covers the point range for most daily inspections, to reduce page load delay |
| Field format validation | Restrict pressure value fields to numeric values between 0–1000 kPa | Matches the pressure range for normal operation of urban gas pipelines, to prevent submission of invalid data |
| Trigger synchronization after submission | Execute synchronization after a 300-second delay | Balances data real-time performance and processing load on backend systems |
| Bulk import limit | Import 50 documents per batch | Adapts to the typical scale of daily inspection bulk submissions, to lower the probability of import failures |

## Three common configuration mistakes
- Symptom: After installing FastGPT, the installed version does not match the downloaded selected version, and the `formInput` configuration item fails to load properly. Cause: The image or source code was not pulled using the officially specified version tag, and locally cached dependency packages overwrote the specified version files.
- Symptom: After a workflow calls a sub-workflow, there is no execution log after the `userSelect` node. Cause: The `userSelect` node in the sub-workflow is not configured with variable return parameters, so the main workflow cannot receive execution signals, interrupting subsequent processes.
- Symptom: An overly large content error is triggered when submitting inspection forms in bulk. Cause: The single field input limit for `formInput` is not set, or the set limit value exceeds the system's default parsing threshold, causing input content to not be processed normally.

## How to confirm the configuration is complete
- Open the form configuration page, check the input limit setting for `formInput`, and confirm it matches the input length of the business scenario.
- Enter the `userSelect` node configuration page, verify that the preloaded number of dropdown options matches the point coverage range for daily inspections.
- Submit a test work order, check the backend synchronization log, and confirm that the data synchronization process triggers normally after submission.
- Import 50 test inspection documents, check whether the import process completes smoothly without abnormal errors.
