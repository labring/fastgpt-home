# Internal Office and Employee Services for Urban Investment Platforms: Workflow Orchestration

## Data Profile for This Category
The internal office data for urban investment platforms originates from in-house OA systems, personnel attendance modules, project approval ledgers, and fixed asset management systems. Two update schedules apply: approval documents sync in real time after submission. Attendance and asset inventory data update in daily batches. Most documents use structured forms, with fields including application number, applicant employee ID, affiliated urban investment operation zone, approval node sequence, associated attachment size, submission timestamp. Some processes include PDF-format project supporting materials.

## Constraints Imposed on Workflow Orchestration
Real-time synced approval documents require workflow trigger nodes to support real-time event responses, eliminating delays from scheduled polling. Daily batched attendance and asset data require workflows to support batch parallel processing nodes, preventing overload on single nodes. Multiple structured field requirements mean workflow `variables` configuration must support multi-field mapping and validation, adapting to field differences across processes. Fixed approval node sequences (zone specialist → department manager → risk control post) require workflow orchestration to lock node order, avoiding process logic confusion.

## Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger by submission event, do not use scheduled polling | Adapt to real-time synced approval documents, avoid delays |
| Batch Processing Nodes | Enable parallel execution, set maximum parallel count to the first 10 entries | Adapt to daily batched attendance and asset data processing, improve efficiency |
| `variables` configuration | Map fields such as application number, affiliated zone, add required validation | Adapt to process requirements for multiple structured fields, ensure data integrity |
| Node Sequence Configuration | Orchestrate in fixed approval node order, lock node sequence | Adapt to fixed approval process logic for urban investment platforms |
| Attachment Size Limit | Limit single attachment to no more than 1000 MB | Adapt to common storage limits for urban investment project supporting materials |
| Timeout Setting | Set to 600 seconds | Adapt to time requirements for cross-department approval and large attachment uploads |

## Three Common Configuration Mistakes
- Symptom: The evaluator cannot select a custom-type global variable selected for the knowledge base as a condition. Cause: Verifiable permission for this global variable was not enabled in the `variables` configuration, so the evaluator cannot read variable attributes.
- Symptom: After the workflow runs to the AI reply node, subsequent nodes receive no trigger signal, and the conversation ends directly. Cause: Output variable transfer for the AI reply node was not configured, so subsequent nodes cannot access context data from the preceding process, triggering an interruption.
- Symptom: The workflow fails to trigger normally after being published to the Feishu bot. Cause: The exclusive `nodeId` identifier of the Feishu bot was not bound in the workflow configuration, so the platform cannot identify the receiving end.

## How to Verify Successful Configuration
- Review the workflow trigger configuration, confirm the trigger mode matches the data update schedule, with no scheduled polling enabled.
- Submit a set of simulated batch data, test the parallel processing nodes, confirm no execution blockages occur.
- Check the `variables` configuration items, confirm all fields involved in the process have completed mapping and validation settings.
- Trigger a complete test process, view node operation logs, confirm all nodes execute successfully in the preset order.
