# Internal Office and Employee Services for Urban Investment Platforms: Document Parsing and Chunking
This document is configured for FastGPT v4.17.0.

## What Data Looks Like for This Category
Internal office documents for urban investment platforms mainly originate from internal OA systems, Feishu shared folders, DingTalk shared folders, and Yuque knowledge bases. They include project approval forms, operational weekly reports, project feasibility study reports, employee attendance ledgers, and other types. Document update schedules follow office workflows: daily approval documents are generated in real time, while monthly and quarterly operational reports are updated on a fixed cycle. Some documents contain on-site project photos and approval flow diagrams, as well as structured fields such as project number, region code, budget amount, and employee ID. Some tables use fixed units of measurement.

## What Constraints These Characteristics Impose on Document Parsing and Chunking
Long documents for urban investment platforms, such as project feasibility study reports and annual operational reports, require consistent context during chunking to avoid losing cross-paragraph logical connections. Embedded on-site project photos and approval flow diagrams must be separately extracted, annotated, or linked to associated text. Without this step, the large language model cannot access the information carried by the images. Structured ledger tables include fields with units, such as budget amount (ten thousand yuan). The binding relationship between fields and their units must be retained during chunking to prevent data failure after splitting. Non-public Feishu and Yuque shared documents cannot be parsed directly via public links, so adaptation to the platform’s permission verification logic is required. Parsing a single large project document takes significant time, which can trigger timeout limits.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the logical paragraph length of long documents for urban investment platforms, avoiding splitting cross-page project descriptions |
| `chunkSplitter` | Split by paragraph + heading | Matches the hierarchical structure of office documents, retaining logical groupings of project nodes and approval processes |
| `customPdfParse` | Enabled | For PDF project reports with embedded images, enable custom parsing to extract image captions and OCR content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of large feasibility study reports, avoiding timeout interruptions of the parsing process |
| `chunkSettingMode` | Manual configuration | For structured table documents for urban investment platforms, customize chunking rules to retain the binding relationship between fields and units |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the upload requirements of large urban investment project archives, supporting import of large-volume documents |

## Three Common Mistakes
- Symptom: After parsing an urban investment project PDF report with embedded images, the large language model cannot access the information carried by the images. Cause: The `customPdfParse` configuration is not enabled. The default parsing process only extracts plain text, and does not associate image captions or perform OCR to extract text within images.
- Symptom: When importing a publicly shared Yuque link as a knowledge base data source, a parsing failure prompt appears. Cause: The Yuque link is not set to publicly accessible, or the link format includes additional tracking parameters that prevent the parsing process from recognizing it.
- Symptom: When calling an HTTP tool, the parameter parsing log shows normal status, but the tool does not execute. Cause: No matching chunking rules are configured, so the parsed document is not associated with the trigger conditions for tool calls, and the tool cannot be invoked.

## How to Confirm the Configuration Is Valid
- Upload an urban investment project PDF document that includes embedded images, and check if the parsed text blocks include image captions or OCR-extracted content to confirm whether the configuration takes effect.
- Import a publicly shared office document link from Yuque, check if the parsing progress completes normally without failure prompts, to confirm that the link permissions and format meet requirements.
- Upload a large urban investment operational report, check if the parsing time falls within the preset range without timeout errors, to confirm that the timeout configuration is reasonable.
- Import a multi-dimensional Excel document from a Feishu folder, check if the parsed fields fully retain units and structured formats, to confirm that the chunking rules adapt to table structures.
