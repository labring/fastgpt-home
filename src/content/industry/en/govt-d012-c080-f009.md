# Internal Office and Employee Services for Urban Investment Platforms: Model Integration and Configuration

## What the Data for This Category Looks Like
Office and employee service data for urban investment platforms mainly comes from OA systems, financial reimbursement systems, project ledgers, employee attendance systems, and internal meeting minutes. Daily office data such as attendance and reimbursement updates daily. Project documents such as feasibility study reports and operation logs update when project milestones trigger. The data includes two categories: structured fields and unstructured text. Structured fields include employee ID, department name, approval amount (unit: yuan), project number, and other items. Unstructured text mostly consists of dozens of pages of project reports and operation records.

## Constraints Imposed by These Characteristics During Model Integration and Configuration
Office data for urban investment platforms is scattered across multiple internal systems. It includes both structured fields and long unstructured documents. Model integration must support unified connection of multi-source data. Daily office data updates in real time. Project documents update when project milestones trigger. Configured context length must adapt to content with different update rhythms. Structured fields have clear units and unique identifiers. When calling the model, field definitions must be accurately matched to avoid parsing errors. Long-text project documents account for a large proportion. The model's context and output token limits must be adjusted to ensure core content is not truncated.

## How to Configure
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the needs of long documents such as project feasibility studies and multi-system context splicing for urban investment platforms, avoiding truncation of core content |
| `maxTokens` | 2000–3000 token | Meets the needs of long-text output such as approval process descriptions and project progress reports, while controlling the cost of a single call |
| `quoteMaxToken` | 1500 token | Matches the length of structured data fields and referenced documents for urban investment platforms, ensuring referenced content is complete |
| `temperature` | 0.3–0.5 | Adapts to the rigor requirements of office scenarios, avoiding overly casual approval suggestions or project interpretations |
| `AIPROXY_API_ENDPOINT` | Enter the full interface address of the internal private model, such as `http://192.168.xx.xx:3000/v1` | Urban investment platforms mostly use internally privately deployed models, so internal proxy addresses are required to connect to private models |
| `AIPROXY_API_TOKEN` | Enter the access token generated by the private model platform | Used for identity verification to ensure the security of internal model calls |

## Three Common Misconfigurations
- 404 status code returned when calling a privately deployed model. Cause: The full path of `AIPROXY_API_ENDPOINT` is not filled correctly, or the interface path of the private model does not match the path configured in FastGPT, such as omitting the `/v1` suffix.
- Streaming output cannot be implemented when an external model is called via the workflow code module. Cause: The correct streaming response receiving logic is not configured in the code module, the model's streaming output switch is not enabled, or the FastGPT streaming data format is not matched.
- An error occurs when importing urban investment project documents after the vector model is configured. Cause: The vector library index fields are not aligned with unique fields such as employee IDs and project numbers of the urban investment platform, resulting in failed index construction.

## How to Confirm Successful Configuration
- Enter the FastGPT model testing page, enter a typical office question for urban investment platforms, such as "View employee Zhang San's October 2024 reimbursement records", and check that the interface returns a 200 status code with no error messages.
