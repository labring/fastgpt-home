# Internal Office and Employee Services for Basic Chemical Industry: HTTP Interfaces and External Systems

## What the data for this category looks like
Business data for the basic chemical industry mainly comes from production control systems, material management systems, equipment inspection terminals, and batch quality inspection reports. It covers full-process internal office data from production, warehousing to quality inspection. Data update rhythms include three categories: real-time collection, daily sync, and batch update. Real-time process parameters such as reactor temperature and pipeline pressure update every 15 minutes. Material ledgers such as raw material inventory and finished product output sync daily. Batch quality inspection reports update immediately after a production batch is completed. Document structures mainly use structured fields, including material code, batch number, process parameter value, detection time, equipment number, etc. Units include degrees Celsius, megapascals, kilograms, cubic meters, etc. Some unstructured data such as inspection photos and quality inspection report attachments are stored as binary streams.

## Constraints imposed on HTTP Interfaces and External Systems by these characteristics
The multi-source, multi-update rhythm data characteristics of the basic chemical industry impose multiple constraints on HTTP interface and external system configuration. Real-time process parameters require low-latency transmission, so interface timeout settings must match collection intervals to avoid data delays disrupting internal office workflows. Batch-level material and quality inspection data has large volume, so chunked upload and pagination requests must be supported to prevent timeout interruptions. The mixed document structure of structured fields and unstructured attachments requires interfaces to support both JSON format parameters and binary stream submissions, adapting to different types of business data transmission. Differences in update frequencies across data sources require differentiated trigger rules to adapt to scenarios including real-time sync, daily bulk sync, and batch-triggered sync. This document applies to FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface authentication configuration | Set `Authorization` parameter to `Bearer ${appKey}` | Complies with header authentication specifications of external systems, prevents account secret leakage |
| Request variable configuration | Define `variables` as `{"materialCode": "{{input.materialCode}}", "batchNo": "{{input.batchNo}}"}` | Matches core business fields of basic chemical industry materials and batches |
| Response data parsing | Configure `responseData` as `$.data.list` | Adapts to nested return structures of most chemical data sources |
| Interface timeout setting | 30–60 seconds | Adapts to collection intervals of real-time process data, avoids frequent timeouts |
| Request body format | multipart/form-data | Supports uploading unstructured attachments such as inspection photos and quality inspection reports |
| Trigger rule configuration | Set sync frequency according to business scenarios | Adapts to different data update rhythms of real-time, daily, and batch-level scenarios |

## Three common configuration errors
- An error `Key is error. You need to use the app key rather than the account key` is returned when calling an interface. The cause is that an account login secret was filled in the authentication configuration instead of the application-specific app key.
- A connection failure occurs when connecting to an external interface with header authentication. The cause is that custom header parameters were not correctly added in the interface configuration, leading to failed authentication verification.
- A parameter mismatch error is returned when uploading files to the knowledge base. The cause is that request parameters were not configured according to the field structure of basic chemical industry material data, leading to missing core fields or incorrect formats.

## How to confirm the configuration is correct
- Call the configured interface, check if the returned response data includes expected basic chemical industry business fields such as material code and batch number.
- Submit a request containing unstructured attachments, confirm that the interface can normally receive and process binary stream data.
- Trigger a scheduled sync task, verify whether the number of synced data matches the actual number of data in the data source.
- Check whether the format of the `Authorization` parameter complies with the Bearer token specification to avoid authentication failures.
