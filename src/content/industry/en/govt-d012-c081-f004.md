# Internal Office and Employee Services for Basic Chemicals: Workflow Orchestration

## What this category's business data looks like
Basic chemical business data mainly comes from production DCS systems, equipment inspection logs, ERP material management modules, and safety compliance archives. Update rhythms vary significantly: real-time production data refreshes every 15 seconds, inspection records are archived daily, ERP material data syncs daily, and compliance documents are updated quarterly. Most document structures are structured tables or text with fixed fields, including equipment number, batch number, raw material consumption, output tonnage, abnormal alarm level and other fields. Common units include tons, cubic meters, hours, ppm, etc.

## What constraints these characteristics impose on workflow orchestration
Basic chemical data is multi-source heterogeneous, with significantly varying update rhythms. First, workflows must support mixed trigger modes, covering real-time production data pulling and scheduled sync for ERP and compliance documents. Second, structured data fields use multiple units such as tons, ppm, and hours. The workflow’s `variables` extraction node needs preset unit matching rules to prevent mismatched values and units. Third, unstructured content in long compliance documents requires workflows to integrate text segmentation and keyword extraction nodes, to support long document processing. Fourth, batch archiving for equipment inspection records requires workflows to support batch data import and verification nodes, to ensure single-batch data integrity.

## Configuration settings
| Configuration Item | Suggested Approach | Rationale |
| ---- | ---- | ---- |
| Trigger Mode | Set according to production data refresh frequency (15 seconds / 1 hour / daily) | Match the update rhythms of different data sources for basic chemicals, avoid invalid triggers |
| `variables` configuration | Preset field variables such as equipment number, batch number, tonnage, ppm | Match the standard field structure of business data, ensure accurate variable extraction |
| Knowledge base association | Associate multiple business knowledge bases | Cover multiple scenarios of internal office and employee services, meet the need for referencing multiple knowledge bases |
| Batch import threshold | Import 100-500 records per single time | Adapt to batch archiving scenarios for inspection records and production logs, avoid overloading single batch data |
| Error retry count | 2-3 times | Adapt to common scenarios such as network fluctuations or temporary data reading failures |
| `nodeId` configuration | Name by node function (such as inspection data extraction node ID) | Facilitate workflow debugging and cross-node variable transfer |

## Three common mistakes
- Phenomenon: The workflow displays a "data format mismatch" error during runtime, and model configuration checks show no abnormalities. Cause: No variable conversion rules are configured for multi-unit fields (such as tons and kilograms) in basic chemicals, leading to mismatched values and units.
- Phenomenon: The keyword extraction node returns empty values, and professional field information cannot be obtained from inspection records or office application text. Cause: No preset keyword matching rules for basic chemical business fields are used, only general keyword models are deployed, which cannot identify professional fields such as equipment numbers, ppm values, and batch numbers.
- Phenomenon: The configured global batch number variable cannot be called in the downstream data verification node. Cause: The data source of the global variable is not correctly bound in the workflow start node, or the variable scope does not cover the downstream node.

## How to confirm the configuration is complete
- Trigger a test run of the workflow in FastGPT v4.17.0, check whether the preset `variables` field values are correctly extracted in the node logs, and confirm that the variable matching rules take effect.
- Import a single batch of simulated data, check whether the batch import node processes normally without overload errors.
- Manually modify the trigger frequency, verify whether the workflow triggers according to the set rhythm, and match the update cycle of the corresponding data source.
- Call cross-node variables, confirm that the node corresponding to `nodeId` can normally obtain parameters passed from the upstream node.

The values provided are common starting points and should be measured against the reader's own samples.
