# Internal Office and Employee Services for Basic Telecommunications Operations: Workflow Orchestration

## What the data for this category looks like
The internal office data sources for basic telecommunications operations include operation and maintenance monitoring systems, billing and settlement systems, customer service ticket platforms, and employee attendance systems. Data update rhythms are divided into multiple tiers: real-time base station operating status is minute-level, billing statements are updated daily, and customer service tickets and employee attendance are updated hourly.
The document structure includes structured fields and unstructured content. Structured fields include ticket ID, base station number, user phone number, and fault type, with units being numeric string, 11-digit numeric string, 11-digit mobile phone number, and enumerated value respectively. Unstructured content includes fault troubleshooting logs and call transcription texts, with a wide span in the length of single text entries.

## What constraints these characteristics impose on the workflow orchestration link
Differences in update rhythms across multi-source data require workflow nodes to match the refresh cycle of their corresponding data. Real-time operation and maintenance data requires minute-level trigger nodes. Daily updated billing data requires daily scheduled trigger nodes. This avoids invoking expired or unupdated data sources.
The fixed format of structured fields requires adding parameter verification links in the workflow. These links match the formats of fields such as base station number and user phone number to filter invalid inputs.
The wide length span of unstructured content requires configuring dynamic context truncation nodes in the workflow. These nodes adjust the volume of text passed to the large model based on single content length, preventing exceeding context limits.

## How to Configure Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Map according to data source fields, retain core fields such as ticket ID, base station number, and user phone number | Match the structured field requirements of basic telecommunications operation data, reduce invalid data input |
| Trigger Timing | Configure per node: real-time operation and maintenance nodes run every minute, billing nodes run daily at 2 AM | Match the update rhythms of different data sources, ensure calls use the latest data |
| Parameter Verification Rules | Configure 11-digit numeric verification for base station number and user phone number fields | Filter inputs with incorrect formats, avoid invalid workflow execution |
| Context Truncation Threshold | 800–1200 characters | Adapt to the length span of unstructured log texts, prevent exceeding large model context limits |
| Node Timeout Duration | 600 seconds | Match the call delay characteristics of basic telecommunications operation data, avoid workflow interruptions caused by slow data retrieval |
| `nodeId` | Assign a unique identifier to each data source node, sort according to business links | Facilitate workflow debugging and anomaly location, quickly identify corresponding data nodes |

## Three Common Configuration Errors
- Phenomenon: When multiple variable references are configured in a workflow, the dropdown menu only displays a single variable option, and multiple associated fields cannot be selected. Cause: The multi-variable binding switch for the workflow is not enabled, and only the single-variable reference mode is enabled by default.
- Phenomenon: When calling a workflow via API, the field is empty after assigning global variables, and a parameter verification failure is returned. Cause: Parameters are not passed in accordance with the field format of basic telecommunications operation data, and the format requirements for 11-digit base station numbers and user phone numbers are not matched.
- Phenomenon: After the workflow runs, the knowledge base reference content output by the large model does not match the original ticket data, and no prompt for unreasonable reference is generated. Cause: No knowledge base reference verification node is added to the workflow, and no consistency comparison is performed between the reference content and the original operation and maintenance or ticket data.

## How to Confirm Correct Configuration
- Trigger the workflow node corresponding to the data source, check if the pulled data fields match the configured `variables`.
- Simulate input with incorrect format (such as a non-11-digit base station number), confirm that the workflow triggers the parameter verification link and intercepts invalid requests.
- Submit unstructured log texts of different lengths, confirm that the context truncation node automatically adjusts the text volume passed to the large model.
- View the workflow running logs, confirm that the trigger timing of each node matches the configured trigger rules.
