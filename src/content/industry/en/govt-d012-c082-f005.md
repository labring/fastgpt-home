# Internal Office and Employee Services for Basic Telecommunications Operations: Tool Calling and Plugins
This document is written based on FastGPT v4.17.0.

## Data characteristics of this category
The internal office data for basic telecommunications operations mainly comes from operation and maintenance monitoring systems, billing and settlement platforms, customer service ticket systems, and base station status collection terminals. Data update rhythms cover real-time, daily, and monthly. Real-time data such as base station operating parameters updates every second. Daily data such as user bills generates the next day. Monthly data such as operation analysis reports archives each month. Single documents include fields such as base station ID, user number, ticket number, fault duration, and billing amount. Some documents have nested subfields, such as base station inspection records associated with tickets. Units include milliseconds, yuan, entries, and others.

## Constraints on tool calling and plugins
High-frequency updates of real-time base station data require tool calls to match the data update rhythm. This avoids calling outdated operating parameters. Multi-field nested ticket and billing documents require tool call input parameters to cover core fields. Otherwise, the corresponding business logic cannot be triggered. Data with different update frequencies must be classified and bound to different tool trigger rules. Real-time data uses real-time call tools. Monthly report data uses scheduled call tools. When the data volume is large, the number of single return entries for tool calls must be adapted to the system's processing capacity. This avoids timeouts caused by too much data in a single batch.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to dynamic business scenarios, automatically select whether to call tools based on input |
| `functionCall` | Only include base station ID and user number fields | Match the core fields of basic telecommunications operation documents, reduce redundant parameters |
| Tool call timeout | 300 seconds | Match real-time data update intervals, avoid calling outdated content |
| Tool call batch limit | First 20 entries | Adapt to the conventional processing scale of single-batch tickets or base station data |
| Tool parameter validation rules | Validate required fields | Ensure input parameters are valid, avoid invalid calls |
| Tool call retry count | 2 times | Address single call failures caused by network fluctuations |

## Three common configuration errors
- Phenomenon: Tool calls return both AI-generated content and tool execution results. Cause: No blocking rule between tool calls and native generation logic is configured, and the automatic reply switch is not turned off after the tool is triggered.
- Phenomenon: Fields returned by tool calls are missing, and some business parameters are empty. Cause: No tool parameter validation rules are configured, and required fields such as base station ID and user number are not validated, resulting in invalid input parameters being passed.
- Phenomenon: Results returned by tool calls do not match preset business logic. Cause: The `functionCall` configuration includes redundant fields, and does not match the structure of basic telecommunications operation documents, resulting in the tool being unable to correctly parse input parameters.

## How to verify correct configuration
- Submit test data containing core business fields, check whether the input parameters of the tool call fully match the configured validation rules.
- Simulate data with different update frequencies to trigger tool calls, confirm whether the call logic conforms to the preset classification rules.
- Switch the linkage scenario between knowledge base matching and tool calls, verify whether the trigger conditions meet business requirements.
- View tool call logs, confirm that the fields of the returned results match the document structure, with no redundant or missing content.

The values provided are common starting points and should be evaluated against the reader's own samples.
