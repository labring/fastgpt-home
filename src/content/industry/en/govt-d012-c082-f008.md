# Internal Office and Employee Services for Basic Telecommunications Operations: Document Parsing and Chunking

## What the data for this category looks like
Internal office documents for basic telecommunications operations mainly originate from operation and maintenance logs, ticketing systems, employee handbooks, annual operation reports, and network fault reports. Update frequencies cover three categories: real-time (operation and maintenance logs updated hourly), per submission cycle (tickets updated daily), and annual (operation reports). Document structures mix structured and unstructured content. Structured fields include ticket ID, fault level, bandwidth utilization (Mbps), processing duration (hours), and others. Unstructured content includes fault descriptions, operation and maintenance steps, and policy text.

## What constraints these characteristics impose on the document parsing and chunking link
The mixed structured and unstructured document structure requires the parsing process to distinguish between fields and free text, and avoid splitting structured fields into unrelated chunks. Real-time updated operation and maintenance logs and large-volume operation reports require parsing nodes to accommodate longer processing durations and larger file limits, to avoid timeouts or upload failures. Numeric fields with fixed units require retaining the binding between values and units during chunking, to prevent information loss after splitting. Documents with dense professional terminology require chunking to retain contextual associations, and avoid forced splitting of terminology that leads to semantic loss.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents for basic telecommunications operations contain professional terminology and structured fields. This range retains context while avoiding overly long chunks |
| `chunkSplitter` | Split by paragraph + semantic split | For mixed structured and unstructured documents, splitting by paragraph retains field integrity, and semantic splitting avoids splitting professional terminology groups |
| `customPdfParse` | Enable field mapping mode | Telecommunications documents have fixed fields such as ticket ID and fault duration. Enabling this mode allows accurate extraction of structured information |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Operation and maintenance log packages and annual reports for basic telecommunications operations have large volumes. This value covers common large-file upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large-volume documents take longer to parse. This duration avoids interruptions due to timeout |
| `chunkSettingMode` | Manual configuration | Chunking requirements vary significantly across different document types (tickets, logs, reports). Manual configuration adapts to detailed scenarios |

## Three common mistakes
- Phenomenon: After uploading a file in a server environment, the document parsing node returns a 404 error, and parsing works normally in a local environment. Cause: The server side has not configured read/write permissions for the file storage directory, or the upload path is not mapped to the parsing node directory of FastGPT.
- Phenomenon: When parsing telecommunications ticket documents, extracted structured fields (such as ticket ID and fault duration) are empty or have incorrect formatting. Cause: The field mapping mode of `customPdfParse` is not enabled, causing structured information to be mixed into unstructured chunks.
- Phenomenon: After parsing a long document, professional terminology such as "OLT uplink bandwidth" is split into two separate chunks. Cause: The value of `chunkSize` is too small, and the semantic splitting chunk mode is not enabled, causing forced splitting of terminology.

## How to confirm the configuration is correct
- Upload a typical telecommunications operation and maintenance log document, and check if the parsed chunks retain complete professional terminology and structured fields.
- Upload a test file larger than 500MB, and confirm that the parsing process does not trigger timeout or upload failure prompts.
- Adjust the value of `chunkSize`, compare parsing results across different chunk lengths, and confirm that the results meet the context retention requirements of the document.
- View the FastGPT backend logs, and confirm that the file upload and parsing request paths match the configured storage directory.

The values provided are common starting points and should be measured against the reader's own samples.
