## Constraints Imposed on HTTP Interfaces and External Systems by These Characteristics
The data characteristics of this category impose multiple constraints on the HTTP interface link. First, large volumes of attachment data (such as construction photos, CAD drawings) require interfaces to support multipart form uploads, and must adapt to size limits for different file formats. Second, structured fields include multiple engineering-specific units. Interfaces must clarify unit mapping rules for fields to avoid cross-system unit conversion errors. Third, mixed update frequencies of real-time and non-real-time data require interfaces to support both synchronous invocation and asynchronous callback interaction modes, adapting to timeliness requirements of different business scenarios.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |

| Request timeout | 300 seconds | Matches average time required for engineering data uploads (such as large BIM files) and interface responses |

| File upload size limit | 1000 MB | Meets upload requirements for large CAD drawings, high-definition construction videos, and other attachments |
| Retry trigger rules | Retry 2 times after failure, 60-second interval | Addresses network fluctuations or temporary interface failures, ensuring stability of engineering data transmission |

## Three Common Misconfigurations
- Symptom: Calling the image upload interface returns empty parameters, or parsing results do not meet expectations. Cause: Upload parameters are not configured according to the naming rules or format requirements for engineering images, and image metadata fields are not correctly mapped.
- Symptom: Interface invocation succeeds, but specified field return values cannot be extracted. Cause: The extraction path for `responseData` is not correctly configured, or the JSON structure hierarchy of the interface return is not matched, leading to field mapping failure.
- Symptom: File upload fails, but template import functions work normally. Cause: File upload size limit configuration is not adjusted, or multipart form upload mode is not enabled, preventing large engineering files from being transmitted normally.

## How to Confirm Successful Configuration
- Call the test interface and obtain structured data, then check whether the fields bound by `variables` exactly match the engineering ledger fields.
- Upload a test engineering attachment (such as a small construction photo), confirm that the interface returns an upload status code of 200 and no error messages.
- Simulate an interface exception scenario (such as temporary network disconnection), confirm whether the retry mechanism triggers as configured and restores normal invocation.
- Extract specified fields from the interface return, check whether field values exactly match the units and formats of the source data.
