# Internal Office and Employee Services for Infrastructure Construction: Tool Calling and Plugins

## What the data for this category looks like
The data for this category mainly comes from project site construction logs, staff attendance systems, equipment operation ledgers, and material requisition records. Data update frequencies are split into two groups: daily-updated construction logs and attendance data, and ledger and consumable data updated per project milestone. Documents use structured formats, including fields such as project number, construction area, equipment serial number, employee ID, working hours, and consumable usage. Units include hours, cubic meters, counts, kilograms, and other relevant units.

## What constraints do these characteristics impose on tool calling and plugins workflows
This category has multi-source heterogeneous data. Tool calling must adapt to API formats of different data sources, including attendance systems, equipment operation platforms, and material management systems. It must also support custom field mapping rules.
Differences in data update frequencies require plugins to support both incremental pull and full synchronization modes. This meets update needs for daily attendance data and quarterly project ledgers.
The variety of fields and units requires pre-configured field conversion logic during tool calling. This avoids unit mismatches for fields such as working hours and consumable usage.
On-site data has timeliness requirements. These impose clear constraints on tool calling response latency.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Allows the model to independently select required tools, adapting to multi-source data calling scenarios |
| `functionCall` | Set to `[{"name":"get_construction_log"},{"name":"get_staff_attendance"},{"name":"get_material_usage"}]` | Limits the range of callable tools, preventing the model from calling unauthorized data sources |
| Timeout setting | 600–900 seconds | Adapts to network latency and data volume during construction data pulling, avoiding timeouts caused by large data volumes |
| Field mapping rules | Set based on actual measurements | Matches custom fields such as on-site project equipment numbers and working hours, ensuring consistent data formats |
| Incremental synchronization switch | Enabled | Adapts to daily updated attendance and construction log data, reducing resource consumption from repeated pulls |
| Maximum return count | Top 20 entries | Controls the data volume returned per call, avoiding memory overflow and slow responses |

This configuration applies to FastGPT v4.17.0.

## Three common configuration mistakes
- Tool calls return empty content, with logs showing no matching data. Cause: No field mapping rules configured for the target project, preventing the tool from recognizing on-site data field names.
- API calls return errors, but the application test process works normally. Cause: The data source key configured via environment variables was not passed correctly during API calls, or the environment variables were not loaded properly during deployment.
- The m3e model fails to call after upgrading the platform version. Cause: The model adaptation configuration for tool calling was not updated synchronously, leading to a mismatch between the model and tool interaction formats.

## How to confirm the configuration is complete
- Manually trigger a tool call, verify that the returned data fields match those in the on-site ledgers, and adjust the mapping rules based on actual business requirements.
- Call data sources with different update frequencies, confirm that the trigger logic for incremental synchronization and full synchronization aligns with the data update rhythm.
- Simulate an API call scenario, check that the keys in the environment variables and configuration items are read correctly.
- Check that the `toolChoice` and `functionCall` configurations match the currently available tool list, to avoid calling unauthorized tools.
