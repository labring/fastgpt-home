# Internal Office and Employee Services for Infrastructure Construction: Deployment and Upgrade

## What the data for this category looks like
Data sources for internal office operations in infrastructure construction include construction logs, staff attendance records, equipment operation and maintenance ledgers, material requisition documents, on-site inspection images, and more. Update frequency is adjusted based on construction progress: real-time synchronization during peak construction periods, daily or weekly updates during shutdown phases.

Document structure includes structured fields and unstructured content. Structured fields cover equipment numbers, attendance duration, material batches, and similar items, with units such as hours, pieces, batches, and others. Unstructured content includes on-site photos, voice inspection records, construction plan documents, with single-item lengths ranging from tens of characters to dozens of pages.

## What constraints these characteristics impose on deployment and upgrade
Dispersed data sources and multi-format content require deployment to support multi-source data access and format compatibility. Configure `STORAGE_S3_ENDPOINT` to adapt to self-built intranet object storage services.

Real-time updated inspection and attendance data require caching services with low-latency characteristics. Adjust the caching policy of `REDIS_URL`.

Network environments may experience fluctuations in construction scenarios, so deployment must support offline caching and resumable uploads.

Upgrade processes must avoid disrupting on-site office work. Adopt a gray release model. Back up structured staff and equipment ledger data before upgrading to prevent data loss.

## How to set configurations
This page is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom password@intranet IP:6379/0` | Used to cache real-time inspection data and employee sessions. Intranet deployment ensures data security. Database 0 is dedicated to business caching |
| `STORAGE_S3_ENDPOINT` | `http://self-built object storage intranet domain:9000` | Stores large files such as construction photos and inspection videos. Intranet access reduces transmission latency and meets offline storage needs on construction sites |
| `DB_MAX_LINK` | `200-300` | Simultaneously supports multiple businesses including construction log queries, employee attendance system docking, knowledge base retrieval, and more, to avoid database connection exhaustion |
| `PG_URL` | `postgresql://username:password@intranet IP:5432/fastgpt` | Stores structured staff and equipment ledger data. Relational database ensures data consistency and query efficiency |
| `ROOT_KEY` | `Randomly generated 32-bit string` | Serves as the super administrator initial key, only used for initial deployment. Can be modified via the backend management interface later to improve system security |
| `FE_DOMAIN` | `https://enterprise internal office domain` | Binds the exclusive domain name of the enterprise internal office system, ensuring only intranet access, meeting security and compliance requirements for public-sector and state-owned enterprise entities |

## Three common mistakes
- Phenomenon: After deploying on a Linux server, the service fails to start within the timeout period, and the frontend page cannot be accessed. Cause: Failure to adjust `DB_MAX_LINK` and the cache duration of `REDIS_URL` based on the hardware configuration of the construction site, resulting in excessive system resource occupation.
- Phenomenon: When deploying with the Zilliz edition, the vector database connection fails, and a proxy error is prompted. Cause: Failure to add intranet proxy parameters to the `MONGODB_URI` or `PG_URL` configuration. Restricted on-site network prevents connection to external dependent services.
- Phenomenon: After deployment, the model only outputs Chinese content, even if an English prompt and English knowledge base are preset. Cause: Failure to load the vector index of the multilingual model during initial configuration. Only the Chinese corpus is loaded, causing the model to fail to recognize English input.

## How to confirm the configuration is complete
- Access the internal domain configured in `FE_DOMAIN`, verify that the frontend page loads normally without 404, 502, or 503 errors.
- Run the built-in database connection test tool, verify the connection status of `MONGODB_URI` and `PG_URL`, confirm that structured and unstructured data can be read and written normally.
- Upload a construction log document, verify that the storage service configured with `STORAGE_S3_ENDPOINT` can normally receive, store, and download the file.
- Initiate a knowledge base retrieval request, enter construction-related keywords, verify that the recall results include the configured data sources, and the number of returned results meets business requirements.
