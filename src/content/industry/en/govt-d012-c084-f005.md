# Internal Office and Employee Services for Commodity Trading: Tool Calling and Plugins

## What the data for this category looks like
Internal office data for commodity trading primarily comes from enterprise ERP systems, port dispatch platforms, commodity spot trading market APIs, and internal contract management systems. Spot market data updates every 15 minutes. Customs declaration and inventory data update daily. Contract documents sync based on signing milestones.

Data documents include fields such as product category, specification model, batch number, inventory quantity, customs declaration number, transaction counterparty, and settlement amount. Units include tons, yuan per ton, cubic meters, number of containers, and more. Structured data is stored in JSON format. Unstructured contract documents are mostly in PDF or Word format.

## Constraints imposed by these characteristics on tool calling and plugins
Differences in data update frequencies require tool calling caching strategies to match the update rhythm of corresponding data sources. This avoids using expired market or inventory data.

Diversity in fields and units requires tool calling parameters to strictly match the field names and units of data sources. This prevents call failures caused by parameter mismatches.

Requirements for decentralized integration of multiple data sources necessitate configuring call order and permissions for multiple plugins. This ensures logical coherence of business processes.

The large length of unstructured contract documents requires adapting to the model's context window limits during tool calling. This prevents content truncation from affecting call results.

## How to set the configuration
This configuration applies to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling mode | Set `toolChoice` to automatic mode | Adapts to the flexible needs of multi-type tool calling for commodity trading |
| Function call switch | Enable `functionCall` | Ensures tool calls return structured parameter formats for subsequent business processing |
| Plugin call timeout | 30-60 seconds | Matches the typical response duration of commodity trading-related APIs |
| Multi-tool call order | Market query first, then inventory query, finally settlement calculation | Aligns with the standard execution logic of commodity trading business processes |
| Context window adaptation | 8000-16000 token | Adapts to the processing needs of long documents for commodity trading |
| Error retry count | 2 retries | Addresses temporary call failures caused by API fluctuations |

## Three common misconfigurations
- Content returned by the inference model wrapped in a think tag and placed in the content field triggers a `Tool call Parser` error. The cause is that FastGPT's tool call parsing logic does not support content fields wrapped in think tags, leading to failure to parse structured parameters.
- Calling tools with an API key forwarded via aiproxy returns a long error code. The cause is that request headers or parameter formats were not correctly passed during forwarding, resulting in unfiltered error stack information being returned by the upstream model.
- A cross-origin error occurs when calling the `api/v1/chat/completions` API. The cause is that no cross-origin whitelist was configured on the FastGPT server, triggering browser same-origin policy blocking.

## How to confirm the configuration is complete
- Initiate a test conversation with a commodity trading tool calling requirement, check if the returned result includes structured tool calling parameters.
- Enter the plugin management page, confirm that the configured commodity trading-related plugins are in normal running status.
- Simulate a browser-side call to the `api/v1/chat/completions` API, verify that no cross-origin related console errors appear.
- View tool calling logs, confirm that no `Tool call Parser` related parsing errors exist.
- Check that the `toolChoice` and `functionCall` configurations meet the preset requirements.
