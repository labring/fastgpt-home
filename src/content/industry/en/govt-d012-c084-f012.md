# Internal Office and Employee Services for Commodity Trading: Deployment and Upgrade

## What the data for this category looks like
The internal office data for commodity trading mainly includes trade contracts, warehouse receipts, logistics documents, real-time quotation sheets, employee service application forms, and other types. Data sources cover internal enterprise ERP systems, scanned copies of offline paper documents, and transaction messages pushed by partners.

Update rhythms vary significantly: trade contracts are updated after signing, warehouse receipts are updated in real time when goods are moved in or out of storage, real-time quotation sheets are updated daily, and employee service application forms take effect immediately upon submission.

Document structure includes fields such as product name, specification model, quantity, unit price, delivery date, carrier information, customs declaration number, and payment terms. Most quantity units use tons and kilograms, while the currency unit uses Chinese yuan. Some documents contain long text clauses, and others have semi-structured field information.

## Constraints on deployment and upgrade from these data characteristics
The data characteristics of commodity trading create multiple constraints for deployment and upgrade. Documents include long text clauses and scanned files, so sufficient file storage capacity and upload bandwidth must be configured during deployment. Different file parsing formats must also be adapted.

Data update frequencies differ, so incremental synchronization must align with the update rhythms of different business scenarios. During the FastGPT v4.17.0 upgrade process, the incremental synchronization logic of older versions must not interrupt current business operations.

Internal office scenarios require integration with internal enterprise ERP and OA systems. Correct database connection parameters must be configured during deployment to ensure data synchronization security and stability.

When deploying on ARM architecture servers, select an image package adapted to this architecture to avoid deployment failures caused by image incompatibility. During upgrades, confirm that the image version matches the current server architecture.

Workflows must handle unique fields such as customs declaration numbers and delivery dates. Corresponding field extraction rules must be configured, and these rules must be preserved without modification during upgrades.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `STORAGE_S3_ENDPOINT` | Intranet address of the enterprise's internal object storage | Files such as warehouse receipts and contract scans for commodity trading have large sizes. Using intranet storage reduces upload latency and meets the access speed requirements of internal office scenarios |
| `FILE_TOKEN_KEY` | Random string of 32 or more characters | Used to encrypt signatures for file uploads, preventing unauthorized access to internal trade document storage |
| `DB_MAX_LINK` | 200–300 connections | Employees in commodity trading initiate a large number of concurrent requests. Setting a reasonable connection pool upper limit avoids database connection exhaustion and ensures stable system operation |
| `MONGODB_URI` | Connection string for intranet MongoDB, configured with read-write separation addresses | Stores trade records and employee service conversation logs for commodity trading. Intranet connections ensure the security of data access |
| `REDIS_URL` | Intranet Redis connection address, configured with a memory limit of 8 GB | Used to cache real-time quotations and inventory data, reducing database query times and improving response speed |
| `FE_DOMAIN` | Domain name of the enterprise's internal office system | Used to generate front-end access addresses, adapting to internal employees accessing the FastGPT front-end interface via intranet or VPN |

## Three common errors
- Phenomenon: A `Failed to create post presigned url` error occurs when uploading files via workflows. Cause: The `FILE_TOKEN_KEY` parameter is not configured correctly, or the storage service pointed to by `STORAGE_S3_ENDPOINT` does not have intranet access permissions enabled, making it impossible to generate signature links for file uploads.
- Phenomenon: Image pulling fails during deployment on ARM architecture servers, with a prompt indicating image architecture incompatibility. Cause: An image package adapted to the ARM architecture is not selected, or the correct image source is not configured, making it impossible to normally pull the image files required for deployment.
- Phenomenon: Historical trade document data fails to load after an upgrade. Cause: The `PG_URL` or `MONGODB_URI` parameters were not updated during the upgrade, or the database connection authentication rules for the new version were not adapted, making it impossible to normally connect to the internal business database.

## How to confirm configurations are properly set
- Upload test files: Upload a PDF of a commodity trading contract, verify that the upload process has no errors and the file can be properly stored in the configured storage service.
- Test database connections: Use the configured `MONGODB_URI` or `PG_URL` parameters to perform database read and write tests, confirming that historical trade document data can be normally accessed and read.
- Verify workflow field extraction: Configure a test workflow to extract fields such as product name and delivery date from the contract, verifying that the extraction results meet expectations.
- Check front-end access: Access the FastGPT front-end interface via the configured `FE_DOMAIN` address, confirming that the interface loads normally with no network or permission errors.
