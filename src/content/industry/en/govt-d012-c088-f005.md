# Internal Office and Employee Services for Engineering Consulting Supervision: Tool Calling and Plugins

## What the data for this use case looks like
The business data for engineering consulting supervision comes primarily from on-site inspection ledgers, material inspection approval forms, progress payment settlement forms, and on-site supervision records from project supervision departments. Data sources include on-site mobile inspection systems, project management platforms, and electronically archived paper documents. Single inspection records are updated in real time as the approval process completes. Inspection logs are archived and synchronized daily. Document structure is grouped by project sections. Each entry includes fields for section number, inspection date, rectification item content, rectification completion deadline, and closed-loop status. Field units include items, days, square meters, ten thousand yuan, and similar units.

## What constraints do these data characteristics impose on the tool calling and plugins workflow
The characteristics of engineering consulting supervision business data create multiple constraints for the tool calling and plugins workflow. The combination of rich-text rectification items and multi-unit fields requires tool calling to support multi-field parsing and unit labeling. This avoids data parsing distortion. Real-time updated inspection approval forms and inspection logs require tool triggering to be bound to project approval nodes. Fixed timed triggering cannot match the latest process status. The data structure grouped by project sections requires tool calling to support filtering the call scope by section ID. This prevents cross-section data confusion.

## How to configure the workflow
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios for supervision work, automatically selects the tool matching the current business |
| Tool calling timeout | 600 seconds | The supervision form approval process usually has a long review cycle, this setting avoids mid-process timeout interruptions |
| Number of returned entries per single tool call | Top 3–5 entries | Daily inspection records for a single project section usually do not exceed 5 entries. Too many entries increase the context load |
| `functionCall` | `enabled` | Supports parallel multi-tool calling, adapting to multiple supervision businesses such as rectification item verification and progress settlement |
| Data source filtering rules | Match by section ID | Supervision data is grouped by project sections. The call scope must be limited to avoid interference from cross-section data |
| Data cache period | 7 days | Supervision data is archived monthly. A 7-day cache is sufficient to meet real-time calling needs |

## Three common configuration errors
- The issue is that after a tool call completes, redundant AI-generated replies are displayed alongside the tool results. Only supervision business-related data cannot be retained separately. The cause is incorrect configuration of the `toolChoice` parameter and context display rules. Full conversation content is retained by default.
- The issue is that only a single tool node can be added when orchestrating a workflow. Intermediate steps for step-by-step processing cannot be configured. The cause is that the multi-tool parallel calling switch is not enabled. Only single-tool calling mode is active.
- The issue is that when calling the material verification tool, no data is returned. Only the default prompt is displayed. The cause is that the data source filtering rule by section ID is not configured. Invalid cross-section data is called.

## How to verify a correct configuration
- Initiate a test request involving rectification item verification. Check whether the tool return fields include supervision-specific fields such as section number and rectification deadline.
- Trigger a tool call bound to an approval node. Check whether the call timing is synchronized with the approval completion node, with no delayed or premature triggering.
- View the tool call logs. Confirm that the unit labels in the returned results match the field units of the supervision data.
- Test parallel multi-tool calling. Confirm that the rectification item verification and progress settlement tools can be triggered simultaneously.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
