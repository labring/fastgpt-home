# Internal Office and Employee Services for Engineering Consulting Supervision: Document Parsing and Chunking

## What the data for this category looks like
Core documents for engineering consulting supervision come from on-site paper scans, structured reports and unstructured text files exported from the supervision system. These include supervision logs, on-site witness records, acceptance inspection forms, contract handover documents, and engineering drawing attachments.
Document update schedules adjust with project progress. Basic log files update daily, while acceptance-related files update upon completion of node acceptance.
Document structures contain fixed fields: project number, supervision section, acceptance location, rectification closed-loop status. Units use standard engineering units such as square meters, ten thousand yuan, and man-hours. Single document length ranges from several pages to dozens of pages.

## What constraints do these characteristics impose on the document parsing and chunking link?
Mixed-source documents include scans and structured reports, so parsing workflows must support custom configuration to adapt to different engineering file formats.
The wide range of single document lengths requires differentiated chunking strategies for short logs and long acceptance reports.
Engineering-specific terms such as "on-site witness", "inspection batch", and "closed-loop rectification" require retaining contextual association during chunking, to avoid semantic breaks from term splitting.
Frequently updated project documents require controlling parsing timeout to meet real-time response needs for internal office work.

## How to configure the settings
These configurations apply to FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `customPdfParse` | Enabled | Adapts to mixed formats of scanned documents, structured reports, and drawing attachments in engineering documents, avoiding loss of engineering-specific layout and field information from default parsing |
| `chunkSize` | 800–1200 characters | Adapts to the length range of both short log snippets and long acceptance clauses in supervision documents, balancing semantic integrity and retrieval accuracy |
| `chunkSplitter` | Split by paragraph + heading | Retains heading hierarchies such as "on-site witness record" and "acceptance location" in engineering documents, preventing cross-block splitting of specialized terms |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of long acceptance reports, avoiding interruption of large document processing flows due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Accommodates upload requirements for single large final acceptance reports and attached drawings, aligning with the volume limit of engineering documents |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different types of supervision documents (such as log-type and acceptance-type) to adapt to parsing needs for specific scenarios |

## Three common configuration errors
- Phenomenon: The PDF parsing link returns an error, and the console shows a parsing engine call failure. Cause: The specified parsing configuration for `customPdfParse` is not consistently enabled, and the default engine update cannot adapt to the special format of engineering documents.
- Phenomenon: The input file at the node is not directly read by the large model, and only the default parsed text fragment is returned. Cause: `customPdfParse` is not configured to skip the default text parsing process, and the logic of directly binding the original file to the node does not take effect.
- Phenomenon: When calling the knowledge base file collection creation API, the specified PDF parsing parameters do not take effect. Cause: The `customPdfParse` parameter field is not correctly carried in the API request, and the default parsing logic is still used.

## How to confirm the configuration is correctly applied
- Upload a typical supervision log PDF, view the parsed text content, and confirm that specialized terms such as "on-site witness" and "inspection batch" are not incorrectly split.
- Check the file upload and parsing logs, and confirm that the parsing process does not trigger timeout errors, matching the configured duration of `PARSE_FILE_TIMEOUT_SECONDS`.
- Call the knowledge base file collection creation API, pass in the `customPdfParse` parameter, and verify whether the parsing logic conforms to the preset configuration.
- Generate a chunking result preview, and confirm that the single block text length falls within the set interval of `chunkSize`.

The values provided are common starting points and should be measured against the reader's own samples.
