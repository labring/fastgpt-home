# Internal Office and Employee Services for Engineering Consulting Supervision: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Engineering consulting supervision data mainly comes from project supervision logs, on-site patrol records, sub-project acceptance reports, standard supervision contract templates, industry specification documents, and project ledgers. Data updates align with project progress timelines. Daily patrol records are updated daily. Acceptance reports and contract archives are completed according to project milestones. Most documents have mixed structures, including standardized fields such as project number, supervision engineer signature section, and acceptance time, plus unstructured on-site problem descriptions and rectification requirements. Some specification documents are fixed-format clause texts, using engineering standard units such as item, time, and square meter.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The daily update feature of project supervision logs requires the knowledge base index to support incremental synchronization, to avoid performance overhead caused by full reconstruction. Mixed structure documents contain both standardized fields and unstructured descriptions, so retrieval logic must be configured to balance field matching and full-text semantic recall. Precise matching of engineering professional terms such as "on-site supervision" and "rectification closure" is required, so the retrieval link must avoid generalized recall of irrelevant content. Different documents have different fields—for example, project ledger numbers and specification clause numbers—so differentiated retrieval weights must be set to ensure that core business fields are recalled first.

This document applies to FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Semantic similarity range for matching engineering professional texts, to avoid recalling irrelevant general documents or overly broad supervision content |
| `limit` | Top 10 entries | Common context length for single retrieval of supervision projects, to control redundancy of returned results |
| `searchMode` | hybrid | Balances structured field matching and unstructured semantic recall, adapting to mixed-structure supervision documents |
| `usingReRank` | Enabled | Performs secondary sorting of initial recall results by semantic relevance, to optimize the accuracy of professional term matching |
| `datasetSearchUsingExtensionQuery` | Disabled | Engineering professional terms do not require additional query expansion, to avoid introducing irrelevant general industry content |
| `collectionIds` | Configured by project group | Binds knowledge base collections corresponding to supervision projects, to avoid interference from cross-project retrieval |

## Three Common Misconfigurations
- Phenomenon: Extra AI-completed information still appears after `datasetSearchUsingExtensionQuery` is disabled. Cause: The system default extension query switch was not turned off synchronously, or the configuration did not take effect and requires a service restart.
- Phenomenon: When deploying the PG database via Docker, knowledge base index creation fails, and file upload shows no progress. Cause: The host machine with 8 cores and 16 GB configuration did not reserve enough memory for vector index construction, or the Docker mount directory has insufficient permissions.
- Phenomenon: No results are returned after calling the retrieval plugin. Cause: The `similarity` threshold is set too high, making it impossible to match and recall professional texts, or `collectionIds` is bound to an empty knowledge base collection.

## How to Verify the Configuration
- Upload a supervision log document, perform a retrieval test, and check whether the relevance of returned results meets business expectations.
- View the retrieval log to confirm that configuration parameters such as `similarity` and `limit` have been correctly loaded, and there are no configuration conflict prompts.
- Switch between different retrieval modes, compare the differences in returned results, and verify that the `searchMode` configuration takes effect.
- After turning off the extension query switch, check whether the retrieval results do not introduce additional non-business related content.

The values given are common starting points and should be measured against the reader's own samples.
