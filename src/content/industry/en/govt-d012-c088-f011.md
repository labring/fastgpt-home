# Internal Office and Employee Services for Engineering Consulting Supervision: Forms and Interactions

## What the data for this category looks like
Engineering consulting supervision internal office data mainly comes from three sources: on-site inspection records, project supervision inspection reports, and material test reports. Data update rhythm follows project process nodes, with the corresponding form updated each time a construction step is completed. Each document matches a single supervision business form, containing structured fields and unstructured attachments. Structured fields include project ID, supervision engineer ID, inspection batch, and test parameter values. Unstructured attachments include on-site photos and scanned paper forms. Common units for test parameter values include millimeters, cubic meters, construction hours, and work days.

## What constraints these characteristics impose on the forms and interactions workflow
The above data characteristics require forms and interactions to adapt to the exclusive scenarios of supervision business. Structured test parameters need to support unit validation to avoid incorrect value entry. The feature of updating by process nodes requires interactions to support batch submission of forms by project batch. The diversity of unstructured attachments requires forms to support large file uploads and batch submission of multiple files. The permission hierarchy of supervision teams requires interactions to support field visibility control by role, for example only the chief supervision engineer can modify the acceptance opinion field. Offline scenarios for on-site inspections require forms to support offline form filling and automatic synchronization.

## How to set up the configuration
These configurations apply to FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Set numeric validation rules to match engineering test units, such as `mm`, `m³`, `h` | Meet the unit requirements for test value fields on supervision forms |
| `userSelect` | Group selectable by project roles, including supervision intern, professional supervision engineer, chief supervision engineer | Match the permission hierarchy and approval workflows of supervision teams |
| Form field grouping | Classify by inspection process, such as reinforcement works, concrete works | Simplify filling long forms and reduce operational errors |
| Attachment upload limits | Single file maximum `500 MB`, maximum `10 files per submission` | Meet file size requirements for on-site photos and test reports |
| Offline sync configuration | Enable, sync interval `300 seconds` | Adapt to on-site inspection scenarios without network access |
| Batch submission toggle | Enable | Support batch submission of inspection reports by project batch, improve office efficiency |

## Three common misconfigurations
- Symptom: When configuring the active push feature, it only responds to @ mentions in groups, and cannot actively push form links to designated supervision project groups. Cause: The active push permission configuration for `formInput` is not enabled, only passive interaction trigger rules are bound.
- Symptom: When uploading a TXT file of supervision logs, the error `failed to create post p` is displayed. Cause: The text encoding format validation for `formInput` is not configured, the default encoding is incompatible with the GBK format log files exported on-site.
- Symptom: When opening the form page in a browser, the voice input feature is unavailable, and inspection records cannot be entered via voice. Cause: Microphone permission is not enabled in browser settings, or the form's voice input interaction rules are not adapted.

## How to confirm the configuration is properly set up
- Fill out a simulated supervision inspection report to verify that the numeric input box only accepts values with preset units, and input without units will trigger a format prompt.
- Try sharing the form with an unauthorized role account, verify that the account cannot see the acceptance opinion field.
- Disconnect the local network, fill out the form, reconnect to the network, and verify that data is automatically synchronized to the project backend.
- Test actively pushing form links to designated project groups, verify that push messages are received without needing an @ mention.
