# Internal Office and Employee Services for Construction Machinery: HTTP Interfaces and External Systems

## What This Type of Data Looks Like
Construction machinery internal office and employee service data primarily comes from on-board sensors, equipment operation and maintenance management systems, enterprise ERP, and employee attendance systems.
Device operation data such as oil temperature and operating duration updates at a second-level to minute-level frequency. Operation work orders and employee attendance data updates at an hour-level to day-level frequency.
Single data documents include fields such as device unique identifier, operating parameter value and corresponding unit, work order number and status, employee ID, and clock-in time. Some fields require additional metadata like associated device model and operation and maintenance team.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
High-frequency device operation data requires interfaces to use short timeout settings. This prevents request backlogs that block external systems.
Multi-source heterogeneous data access requires interfaces to support flexible field mapping rules. This adapts to differences in parameter formats returned by different systems.
Numeric fields with units require clear parameter unit specification during interface requests. Alternatively, convert units to standard values during response parsing to avoid data parsing errors.
Transmission of employee sensitive data requires authentication parameters. This ensures the security of interface calls.
Batch operation work order synchronization needs to support paginated requests. This prevents single request data volume from exceeding interface limits.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `Authorization` | `Bearer ${Enterprise-specific API_TOKEN}` | Adapts to the common Bearer authentication specification for external construction machinery systems, ensuring call legitimacy |
| Interface timeout period | 30–60 seconds | Matches the high-frequency update rhythm of device operation data, avoiding short request timeouts and long request system blocking |
| `variables` dynamic binding | `{"device_id": "Device unique identifier", "staff_id": "Employee ID"}` | Adapts to batch interface calls for multiple devices and employees, reducing duplicate configurations |
| Batch request pagination rule | Split by 100 items per page | Adapts to the single data volume of operation work orders, avoiding exceptions triggered by excessive returned data |
| `responseData` parsing rule | Extract the content of the `data` field in the response body | The standard response format of most construction machinery operation and maintenance systems is `{"code":200,"data":[...]}`, making it easy to directly obtain valid data |
| Field unit mapping | Match parameter units by device model | Adapts to parameter unit differences across different model construction machinery devices, ensuring accurate data parsing |

## Three Common Errors
- Symptom: A `URIError: URI malformed` error appears when calling the login interface. Cause: Parameters with special characters such as construction machinery device IDs and employee IDs are not URL-encoded, leading to incorrect request URI formatting.
- Symptom: The interface returns a 413 Request Entity Too Large status code. Cause: The volume of operation work order data in a single request exceeds the interface limit, and requests were not split by 100 items per page.
- Symptom: A prompt indicates that `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` configurations are missing during local deployment. Cause: The proxy interface access address and authentication token are not configured in environment variables, preventing forwarding of external system requests.

## How to Verify Correct Configuration
- Initiate a single device data request, and check if the response body includes expected fields such as device operating parameters and corresponding units.
- Configure a batch work order request, and verify that the number of returned data items matches the preset pagination rule.
- Simulate an interface call for employee attendance data, and confirm that authentication parameters take effect with no permission errors.
- Check the interface logs in FastGPT v4.17.0, and confirm that the request timeout period matches the configured value with no abnormal errors.
