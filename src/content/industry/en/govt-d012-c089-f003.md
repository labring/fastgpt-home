# Internal Office and Employee Services for Construction Machinery: Multi-turn Dialogue and Prompt Settings

## What Data for This Category Looks Like
Teams working with construction machinery source data from equipment operation logs, maintenance work orders, internal operation manuals, and employee service process documents. Equipment operation logs update hourly or in real time. Maintenance work orders sync in real time when submitted. Internal documents update monthly. Structured data includes fields such as equipment number, operating duration (unit: hours), fault code, maintenance time, and others. Unstructured documents are mostly PDF-format operation guides and training materials, with individual lengths ranging from hundreds to thousands of characters.

## Constraints for Multi-turn Dialogue and Prompt Settings
Real-time updated equipment operation logs require limiting dialogue context length, to avoid response delays from loading excessive historical data. Fixed units and encoding formats for structured fields require prompts to clearly specify value formats and units, to prevent large models from returning non-compliant content. Multi-turn dialogue requires linking information across different data sources. For example, when connecting equipment faults to corresponding maintenance processes, use historical dialogue context to anchor the specific equipment model and work order status under discussion. This ensures responses accurately match the business scenario.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 800–1200 characters | Matches the single-segment content length of multi-source documents for construction machinery, avoids truncating critical parameters |
| Number of Historical Messages to Retain | First 10 dialogue turns | Balances context relevance and response speed, adapts to multi-turn equipment repair request and inquiry scenarios |
| `variables` Binding | Bind dedicated variables by equipment number and work order ID | Ensures that the current business object is anchored during multi-turn dialogue, avoids confusing issues across different equipment |
| `messages` Management | Automatically clean expired historical messages | Reduces invalid context usage, improves dialogue response efficiency |
| `chatId` Generation | Bind the combination of equipment number + work order ID | Ensures each dialogue anchors to a unique business scenario, avoids context confusion |
| cite Reference ID Switch | Enabled | Returns structured reference identifiers for each dialogue, resolves issues where reference IDs are missing |
| Thought Process Display | Hidden based on dialogue scenario | Avoids redundant content interfering with employee user experience |
| Prompt Template Update Frequency | Once per month | Adapts to the monthly update rhythm of internal documents |

## Three Common Misconfigurations
- Phenomenon: After sending a dialogue request, the interface return result does not include the cite reference ID field. Cause: The cite reference ID switch is not enabled, so the system does not generate the corresponding identifier.
- Phenomenon: After sending two consecutive dialogue requests, the second reply does not link to the equipment model or work order issue mentioned in the first request. Cause: `variables` are not bound, or enough historical `messages` are not retained, leading to lost context.
- Phenomenon: After configuring the AIProxy proxy, the dialogue history interface displays the large model's thought process. Cause: The thought process display switch is not configured as hidden based on the scenario, or the proxy configuration does not sync this setting.

## How to Verify Successful Configuration
The configuration verification steps for FastGPT v4.17.0 are as follows:
- Send a test dialogue that includes a specific equipment number, check whether the interface return or on-screen display result carries the cite reference ID field.
- Send two consecutive dialogue requests. Mention a fault code for a specific equipment in the first request, then ask about the corresponding maintenance process in the second request, check whether the second reply anchors to the maintenance requirements of the current equipment.
- Configure the AIProxy proxy and send a dialogue, check whether the dialogue history interface does not display the large model's thought process content.
- Check whether the variables bound to `chatId` update automatically with the dialogue, confirm that the business objects linked by the context are accurate.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
