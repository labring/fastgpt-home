# Internal Office and Employee Services for Refined Oil Product Sales: Workflow Orchestration

## What the data for this category looks like
The internal office data for refined oil product sales originates from four primary sources: fuel station POS transaction systems, tank level monitoring systems, employee attendance and scheduling systems, and inventory ledgers. POS transaction data is generated in real time, and includes fuel grade, transaction volume (unit: liters), transaction amount (unit: yuan), transaction time, and operator employee ID. Tank level data updates every hour, and includes tank number, remaining fuel volume (unit: liters), and update time. Employee data updates daily, and includes employee ID, job position, and scheduling period. Most documents use structured table formats, while some compliance management documents use long text formats. Field naming conventions vary slightly across different business systems.

## What constraints these characteristics impose on workflow orchestration
Differences in field naming across multiple data sources require workflow configurations to include unified mapping rules. For example, the "transaction amount" field from the POS system must be mapped to the "sales revenue" field in the inventory ledger. High-frequency updates of real-time transaction data require trigger nodes that support minute-level frequency adjustments, to avoid business process delays caused by data synchronization lags. Bulk uploaded tank level data requires configured bulk processing nodes, to prevent execution interruptions caused by excessive load on a single node. The daily update characteristic of employee scheduling data requires configured scheduled trigger nodes, to pull the latest scheduling information daily for attendance verification and employee services. Cross-system data interactions require clear authentication parameters, to ensure only authorized employees can access corresponding business data.

## How to set the configurations
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale for This Setting |
|---|---|---|
| Trigger node frequency | 10-30 seconds during peak hours, 5 minutes during off-peak hours | Transaction peaks for refined oil product sales occur primarily at 7-9 AM, 11 AM–1 PM, and 5–7 PM. Real-time transaction data requires timely synchronization |
| Bound knowledge base | Employee handbook library, product compliance library, inventory knowledge base | Covers internal office needs for job operations, compliance requirements, and business data query needs |
| Variable configuration | `variables` binds employee ID, tank number, transaction order ID | Used to accurately match corresponding business data in workflows and enable personalized services |
| Node timeout threshold | 600 seconds | Reserve sufficient time for network requests and data processing when pulling tank level and POS transaction data across systems |
| Single batch processing volume | First 100 entries | Avoid workflow execution lag caused by overly large batch data, and align with daily data scales at fuel stations |
| AI model invocation | Calibrated based on actual testing | Adapt to specialized terminology and internal document formats for refined oil product sales, and improve response accuracy |

## Three common configuration errors
- Phenomenon: Knowledge base search nodes return permission denied errors, or unauthorized employees can access sensitive business data. Cause: Employee ID is not bound as an authentication parameter in `variables`, and no permission verification rules are configured for the node.
- Phenomenon: No optional values appear in the variable reference dropdown menu for knowledge base search. Cause: Required business fields such as employee ID and tank number are not predefined in the `variables` configuration of the workflow.
- Phenomenon: The custom comment logic of the AI chat component does not execute after the reply is completed. Cause: The comment node is not mounted on the stream reply end branch of the AI chat node, and is incorrectly configured to trigger during the stream reply process.

## How to confirm the configuration is complete
- Trigger a test workflow, view the node execution logs, and confirm that the `variables` parameter correctly carries bound fields such as employee ID and tank number.
- Simulate an unauthorized employee identity to invoke the knowledge base search node, and confirm that a permission verification failure prompt is returned.
- Send a test prompt to trigger the AI chat, wait for the stream reply to finish, and check whether the preset comment logic is triggered.
- Submit batch test data, view the workflow execution records, and confirm that the single processing volume does not exceed the preset threshold.
