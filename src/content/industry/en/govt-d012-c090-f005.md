# Internal Office and Employee Services for Refined Oil Product Sales: Tool Calling and Plugins

## What the data for this category looks like
The internal data for refined oil product sales mainly comes from gas station POS terminals, oil tank level monitoring equipment, the enterprise ERP inventory system, and the employee attendance management system. There are two types of data update schedules: transaction data is synced every hour, while inventory and attendance data are updated daily. The data documents use structured formats, including fields such as fuel nozzle number, fuel grade, fuel volume, transaction amount, employee ID, shift, and inspection time. The unit of fuel volume is liters, the unit of transaction amount is yuan, and time fields use natural days or hours as the unit.

## What constraints these characteristics impose on the tool calling and plugins link
The data characteristics of refined oil product sales impose multiple constraints on the tool calling and plugins link. The real-time differences between multi-source data require that the time range parameter for data pulling be clearly specified during plugin calls, to avoid statistical bias caused by mixing hourly transaction data and daily inventory data. The enumeration rules for fields such as fuel grade and fuel volume are fixed, so valid parameter enumerations must be preset during plugin calls to prevent execution failures caused by passing invalid parameters. Employee service-related data involves job permissions, so plugin calls must be bound to the access scope of the corresponding role to avoid unauthorized access to sensitive information. The transaction data volume for a single station is relatively large, so the number of records returned by a single plugin call must be limited to prevent interface timeouts.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` or `functionCall` | Adapts to structured data calling requirements; `functionCall` can enforce the preset inventory query or employee scheduling tool |
| Single call timeout period | 30–60 seconds | Adapts to the delay of multi-source data pulling, avoids call failures caused by slow POS system responses |
| Maximum number of tool return records | First 20 records | Limits the return volume of single-station transaction data to prevent excessive interface load |
| Context window size | 8000–12000 token | Context window range compatible with FastGPT v4.17.0, adapts to long context processing requirements for inspection records and scheduling tables in employee services |
| Permission binding configuration | Grouped by employee roles | Differentiates the available tool calling scope for different positions, ensuring secure access to sensitive data |

## Three common mistakes
- A 400 status code with no response body is returned when calling a MySQL tool plugin. The database connection address, port, or access permission parameters are not configured correctly, causing the request format to not meet interface requirements.
- Context information cannot be obtained when calling a workflow API with a configured context. The session identifier parameter is not carried in the API request, or the context binding logic of the workflow is not associated with the current session.
- Execution fails when calling a tool with a non-compliant fuel grade parameter. Valid parameter enumerations are not preset, allowing parameters that do not meet industry standard grades to be passed.

## How to confirm the configuration is complete
- Initiate a test call, check if the returned tool execution results include the preset business data.
- View the tool call logs to confirm that the configuration items in the request parameters match the preset values.
- Initiate calls with different roles to verify that only authorized roles can access the functions of the corresponding tools.
- Simulate passing invalid parameters, check if the system returns a parameter error prompt to confirm that the verification logic is effective.
