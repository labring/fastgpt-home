# Internal Office and Employee Services for Refined Oil Product Sales: Deployment and Upgrade

## What the data for this category looks like
Internal office data for refined oil product sales primarily comes from gas station transaction systems, fuel card management platforms, employee attendance systems, and store inspection ledgers.
Transaction data is generated in real time, and includes fields such as order number, fuel grade, fuel volume (liters), actual received amount (yuan), and transaction time. Inventory data is updated daily, and records fuel stock remaining (tons), purchase batches, and delivery order numbers. Employee-related data is updated per shift, and includes job number, store ID, shift period, and service duration. Most data takes the form of structured tables and semi-structured logs, and field units follow petroleum and petrochemical industry metrology standards uniformly.

## What constraints these characteristics impose during deployment and upgrade
High concurrent writes of real-time transaction data require adjusting database connection limits during deployment to avoid service outages caused by exhausted connections. Daily batch-updated inventory data requires scheduled synchronization scripts. Temporary data synchronization links must be retained during upgrades to prevent historical data loss. The large number of structured fields with unified units requires vector model preprocessing to adapt to fixed field formats and avoid parsing errors. For multi-store distributed deployment scenarios, upgrades must use rolling update strategies to ensure that single-store upgrades do not disrupt services during overall operating hours.

## How to set the configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–150 connections | Adapts to concurrent write demands of multi-store real-time transaction data, prevents connection pool exhaustion |
| `MONGODB_URI` | Cluster connection address with read-write separation suffix | Separates read and write requests for transaction data, improves real-time query performance |
| `REDIS_URL` | Primary-secondary cluster address, set 600-second expiration time | Caches frequently queried employee scheduling and inventory surplus data to reduce database load |
| `FE_DOMAIN` | Enterprise internal office domain name | Restricts front-end access sources, meets internal office security requirements for state-owned enterprises and public institutions |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Encrypts file upload tokens, prevents unauthorized access to sensitive documents such as inspection reports and fuel card details |
| `STORAGE_S3_ENDPOINT` | Enterprise internal object storage service address | Stores large-volume inspection videos and monthly report files, complies with internal data storage specifications |

## Three common errors
- Phenomenon: Uncaught exceptions appear in simple applications after running the v4.8.20 upgrade script. Cause: The `DB_MAX_LINK` configuration was not adjusted, and concurrent writes of real-time transaction data exceeded the default connection pool limit.
- Phenomenon: An error is returned when parsing incoming file addresses after enabling workflow file upload functionality. Cause: `FILE_TOKEN_KEY` or `STORAGE_S3_ENDPOINT` was not configured, making it impossible to access internally stored document resources.
- Phenomenon: Excessively high response latency occurs when external platforms call the chat interface. Cause: Redis caching for frequently queried data was not enabled, and each request directly queries the database, resulting in excessive resource usage.

## How to verify correct configuration
- Access the system monitoring page within the FastGPT backend, review the active connection count of the database connection pool, and confirm the value falls within the configured `DB_MAX_LINK` range.
- Upload a structured inspection log document to verify the file can be properly uploaded to internal storage and read by the document parsing tool.
- Call the chat interface from an external test platform, initiate a request for employee scheduling query, and confirm the response time meets the expected threshold.
- Run the rolling upgrade script, review service running logs, and confirm no uncaught database connection or file access exceptions are present.

The values provided are common starting points and should be evaluated against the reader's own samples.
