# Internal Office and Employee Services for Building Engineering General Contracting: HTTP Interfaces and External Systems

## What Data Looks Like for This Use Case
Data for internal office and employee services in building engineering general contracting mainly comes from project schedule management systems, labor attendance systems, material in-and-out warehouse systems, and internal OA platforms. Data update rhythms fall into three categories:
- Labor attendance data is synchronized in real time daily
- Project progress ledgers are updated weekly
- Material inventory and expense reimbursement data are updated daily

Data documents use structured table formats, with fields including project number, labor employee ID, attendance time, material code, inventory quantity, reimbursement amount, and more. Units include person-times, days, cubic meters, yuan, and more. There is no unstructured content with complex nested levels.

## Constraints Imposed on HTTP Interfaces and External Systems
The multi-source heterogeneous data characteristics of building engineering general contracting impose three types of constraints on HTTP interface configuration:
1. Labor attendance data has high real-time requirements, so a sufficiently long interface timeout period must be set to avoid process interruptions from short system delays.
2. Large volumes of material inventory data are pulled in batches, so pagination request parameters must be configured to avoid exceeding system load limits with a single request.
3. Minor differences exist in field naming across multiple systems, so unified field mapping rules must be configured before interface calls to ensure data can be correctly parsed and used.

Most internal systems use Token-based authentication, so a unified authentication configuration logic must be adapted.

## Recommended Configuration Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Timeout Period | 600 seconds | Cross-system interface calls for building projects usually involve multi-stage data pulling, with long single-request execution times. This avoids process interruptions from timeouts |
| Retry Count | 3 times | Addresses temporary network fluctuations or brief internal system freezes, reducing call failures caused by occasional exceptions |
| Authentication Method | `Authorization` header carrying Bearer Token | Complies with security authentication specifications for most Chinese state-owned enterprise and public sector internal systems, and aligns with existing internal system access requirements |
| `responseData` Parsing Rules | Map to specified fields | Matches the structured data format returned by building systems, ensuring business processes can obtain required attendance or material data |
| `variables` Default Value Configuration | Set default values for empty fields | Ensures subsequent business processes can trigger normally when external systems return empty data |
| Interface Request Pagination | Pull 100 entries per page | Adapts to pagination limits of building system batch data interfaces, avoiding excessive data volume in a single request |

## Three Common Configuration Mistakes
- No response after calling the interface, with a `connection refused` error in logs. This occurs because a correct internal system domain name or port is not configured, or a firewall blocks outbound requests from the FastGPT-hosted server.
- Tool call parameters parse correctly but no actual operation is performed. This occurs because the `responseData` return verification rules are not properly configured, causing the system to consider the interface call incomplete.
- Interface returns empty data but the preset exception process is not triggered. This occurs because `variables` default values are not configured, so subsequent business processes cannot trigger normally when external systems return empty fields.

## How to Verify Correct Configuration
- Manually trigger an interface call in the FastGPT tool debugging panel, and check if the returned response content matches the actual data from the external system.
- Simulate high-frequency call scenarios in building engineering projects, and observe if the interface response time meets the preset timeout configuration.
- Initiate a call with an invalid authentication Token, and confirm the system returns the corresponding permission error prompt.
- Trigger a call containing empty parameters, and confirm the system handles abnormal situations according to the configured rules.
