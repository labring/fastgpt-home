# Internal Office and Employee Services for General Contracting of Building Construction Projects: Tool Calling and Plugins

## What the Data for This Category Looks Like
The internal office data for general contracting of building construction projects primarily originates from project management systems, labor attendance terminals, material inbound and outbound ledgers, and on-site progress reporting tools. Data update cycles cover three dimensions: real-time, daily, and weekly. Material inbound and outbound data updates in real time with operations. Labor attendance data is synchronized daily. Progress weekly reports and employee change records are updated weekly and monthly. Documents are stored as structured tables, including fields such as project unique identifier, team number, material code, attendance days, material weight, and node completion duration. Common field units are person, ton, day, and square meter.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Since the data includes real-time updated material and attendance information, tool calling must support pulling the latest data in real time to avoid returning outdated project status. Multi-dimensional structured fields require that tool calling parameters strictly match preset field names. Fuzzy matching cannot automatically adapt to preset field formats. Data volume increases with project scale. The single-call return limit must adapt to the number of fields for different projects, preventing call timeouts caused by data overload. Sensitive attributes of employee files require that plugin calls include permission verification parameters. Only authorized roles can access corresponding data.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to parallel tool calling scenarios for building construction projects, automatically matching tools for corresponding data types |
| `functionCall` | `enabled` | Supports structured parameter transfer, enabling direct mapping to the field format of project ledgers |
| Single tool call timeout | 60 seconds | Adapts to on-site network fluctuation scenarios, preventing call failures from network delays |
| Tool recall result limit | Top 8 entries | Balances data completeness and call efficiency, adapting to the multi-dimensional data structure of building construction projects |
| Tool call retry count | 2 times | Addresses temporary on-site network interruptions, reducing the need for manual intervention |
| Permission verification switch | Enabled | Prevents unauthorized access to sensitive employee attendance and material data |

## Three Common Misconfigurations
- The API call returns a connection timeout or 403 status code. This occurs because regional adaptation rules are not configured, and network routes in some regions have access restrictions.
- When using streaming output, clicking a link only overwrites the current page and fails to open a new window. This occurs because the front-end rendering logic does not have a new window trigger rule configured.
- Conversation log details do not match the actual answer content. This occurs because the tool call cache is not updated with the conversation, reusing fixed results from historical calls.

## How to Verify Successful Configuration
- Send a test request that includes a material query, and check if the returned results contain the latest material code and weight data for the current project.
- Call the tool interface and verify that the returned parameters strictly match the preset structured field format.
- Review the conversation log to confirm that the tool parameters for each call match the actual request, with no fixed reused results.
- Test permission restrictions: use an unauthorized role to submit an employee data query, and confirm that the returned result is empty or displays an insufficient permissions prompt.
