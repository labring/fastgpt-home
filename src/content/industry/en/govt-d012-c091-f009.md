# Internal Office and Employee Services for General Contracting of Residential Construction Projects: Model Access and Configuration

## What the Data for This Category Looks Like
Internal office data for general contracting of residential construction projects mainly comes from structured ledgers in the project management system, attendance records from the labor management platform, inbound documents from the material procurement system, on-site construction images, scanned visa forms, and meeting minutes. Data updates follow the project execution schedule: daily attendance is updated daily, progress reports are updated weekly, and settlement documents are archived monthly. Documents include structured fields such as project number, number of labor team members, material model and unit price, with units including square meters, man-days, yuan, and others. A large number of unstructured PDFs, CAD drawings and scanned documents also exist, with significant differences in single-document length: some visa forms only have a few lines of text, while some construction plans can reach dozens of pages.

## What Constraints Do These Characteristics Impose on the Model Access and Configuration Link
Structured ledgers have high field standardization but cover many dimensions, so the model must accurately match exclusive fields such as project number and number of labor team members to avoid data confusion. The length of unstructured documents varies significantly: some visa forms only have a few lines, while some construction plans reach dozens of pages, so the context processing capability for long and short texts must be adapted to avoid truncating long documents or wasting too many resources on short documents. On-site construction images and scanned documents require visual understanding capabilities, so corresponding visual-related parameters must be configured. Data updated according to project nodes requires call timeliness, so the context range of a single call must be limited to avoid loading expired historical data. Format differences across multiple data sources require unified access standards, so interface parameters adapted to different systems must be configured to ensure stable data synchronization.

## How to Configure the Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Range/Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | The document lengths for residential construction projects vary significantly, so the context must cover multiple construction plans, attendance ledgers, and settlement documents to avoid truncation of key business information |
| `maxTokens` | 2000–3000 token | Internal office scenarios mainly focus on question answering and document summarization, so single output does not need to be too long to avoid wasting model call resources |
| `quoteMaxToken` | 4000 token | Sufficient quoted document content must be retained to ensure the integrity of references to core business data such as visa forms and progress reports |
| `vision` | Enabled | On-site construction images, scanned drawings and visa forms must be processed, so support for extraction and understanding of visual information is required |
| `temperature` | 0.3–0.5 | Internal office requires accurate and compliant information output to avoid generating random content that does not conform to project specifications |
| `AIPROXY_API_ENDPOINT` | Fill in the project-specific proxy interface address | Isolate internal office data from public network call links to ensure access security of project sensitive data |

## Three Common Misconfigurations
- Symptom: The interface prompts that no available model channels are available, and the logs show 403 or 502 status codes. Cause: `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` is not configured correctly, or the proxy service has not been restarted, resulting in failed verification of the model call link.
- Symptom: Some PDF files show empty content after upload, and text cannot be extracted. Cause: The `vision` parameter is not enabled, or the uploaded PDF is in pure scanned image format, and the visual recognition process is not triggered, resulting in failure to parse text in the image.
- Symptom: Sending a message does not trigger a call to the associated knowledge base by default, only returning general answers without combining internal project data. Cause: The `toolChoice` parameter is not configured to the automatic knowledge base call mode, or the knowledge base association configuration is not bound to the current application, resulting in the model not triggering the retrieval process.

## How to Confirm the Configuration Is Successful
- Initiate a query targeting project labor data, and check whether the returned results include the content of the configured associated knowledge base to confirm that the model call link is working properly.
- Upload a scanned PDF of a construction visa form, and check whether the system can normally parse the text in the image to verify that the visual recognition function is active.
- Check the system operation logs to confirm that there are no unexpected model call records during the hourly peak period, to verify that the scheduled tasks and warm-up configuration have been processed correctly.
- Initiate a query that requires referencing material ledgers, and check whether the returned results accurately match the project-specific fields to confirm that the context configuration meets the requirements.
