# Internal Office and Employee Services for Residential Construction General Contracting: Forms and Interactions

## What the data for this category looks like
Internal office data for residential construction general contracting projects mainly comes from project management platforms, labor attendance systems, material entry ledgers, and construction progress reports. The data covers four categories: labor personnel information, material purchase details, on-site construction milestones, and office approval workflows.
Update frequencies fall into three types: real-time (material warehousing, attendance check-ins), daily (team daily reports), and weekly (progress weekly reports).
Document structures uniformly include project unique identifier, business module classification, operator ID, and submission time fields. Some core fields have fixed attached units, such as number of personnel, material weight, construction area, and approval duration.

## What constraints these characteristics impose on forms and interactions
Multi-source data requires forms to support cross-system data pulling and automatic filling, to avoid repeated manual data entry.
Business data with different update frequencies requires forms to switch between real-time and historical data call modes, to adapt to scenarios including real-time labor attendance reporting and regular submission of progress weekly reports.
Core fields with units need fixed units labeled next to input boxes, to prevent mismatches between input values and units.
Mandatory binding of project unique identifiers requires forms to load project data associated with the currently logged-in user by default, to narrow selection scopes.
Associated fields for office approval workflows need to be configured in sync with approval nodes in the internal office system, to ensure correct circulation paths after submission.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Configure corresponding input components for each business field and add unit prompts | Adapt to the numeric, enumeration, and text attributes of residential construction business fields, ensuring input complies with business specifications |
| `userSelect` | Limit selection to internal employees and teams associated with the current project | Bind the project unique identifier, narrow selection scopes, and avoid cross-project data confusion |
| Form default loaded data range | Use historical business data from the past 7 days | Cover common data ranges for daily office work, reducing user retrieval costs |
| Input value verification | Restrict value ranges and unit matching, such as setting material weight to 0-1000 tons and number of personnel to 1-50 people | Prevent incorrect input values and unit mismatches, improving data accuracy |
| Automatic circulation after submission | Associate preset approval nodes for the current project | Sync with approval workflows in the internal office system, ensuring correct circulation paths after submission |

## Three common misconfigurations
- Phenomenon: Unable to select the SenseVoiceSmall model when configuring speech recognition functionality, with no corresponding option in the interface. Cause: Failed to enable permissions for segmented scenario speech models in system settings, or the current FastGPT v4.17.0 version does not support calling configuration for this model.
- Phenomenon: The chart plugin associated with the form outputs "none" with no expected chart URL. Cause: Failed to correctly configure the data source parameters for `formInput`, causing the plugin to fail to obtain valid business data.
- Phenomenon: The file input function in system settings cannot properly receive uploaded material ledger files. Cause: Failed to configure file upload format restrictions and size thresholds, causing non-compliant files to be blocked.

## How to verify successful configuration
- Open the form page, check whether the input components and unit prompts for each business field match the preset configuration.
- Select employees or teams associated with the current project, confirm that the optional scope of `userSelect` only includes the target group.
- Submit a test data entry, check whether it automatically circulates to the preset approval node, and that no unit or value errors appear in the data.
- Upload a test file that complies with business formats, confirm that the file input function can properly receive and store data.
