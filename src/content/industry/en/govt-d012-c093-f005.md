# Internal Office and Employee Services for Government and Enterprise Informatization Services: Tool Calling and Plugins

## What this category of data looks like
Data for internal office and employee services for government and enterprise informatization services mainly comes from internal enterprise business systems such as OA, attendance systems, financial reimbursement platforms, and employee file databases. Data updates follow scheduled daily synchronization as the primary rhythm; some real-time interactive data such as attendance check-in and reimbursement approval status are updated on demand. Documents are stored in structured table or standardized JSON format, with fields including employee ID, affiliated department, job rank, business processing status, associated approval order number, and more. Units mostly use business-specific identifiers such as person-times, yuan, calendar days, and approval order number serials.

## What constraints these characteristics impose on the "tool calling and plugins" link
The structured data characteristics of internal office and employee services require that target fields and business identifiers must be clearly specified during tool calling, to avoid result deviations caused by fuzzy matching. Internal system permission control requires that plugins must integrate the enterprise unified identity authentication system, allowing only authorized accounts to call business interfaces with corresponding permissions. The daily scheduled data update rule requires that the cache validity period of tool calls must match the synchronization cycle, to avoid returning expired employee status or approval information. Internal business interface call frequency limits require that plugins must configure reasonable request intervals, to prevent triggering the system current limiting mechanism.

## How to set the configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or `none` | Adapts to multi-tool calling needs of internal office work. `auto` automatically matches the corresponding business tool, and `none` is used for fixed calling of a specified plugin |
| `functionCall` | Enabled | Adapts to field mapping of structured business data, ensuring tools can accurately extract specified fields from internal systems |
| Request timeout period | 30–60 seconds | Matches the conventional response duration of internal system interfaces, avoiding call failures caused by internal network delays |
| Cache validity period | 1 day | Matches the daily synchronization update rhythm of government and enterprise data, avoiding returning expired employee status or approval information |
| Maximum request concurrency | Up to 2 requests per second | Adapts to current limiting rules of internal business interfaces, preventing system interception |
| Single call data volume | No more than 1000 entries | Avoids exceeding the interface data transmission limit of internal systems in a single request |

## Three common mistakes
- A preset error message is returned when calling the OpenApi chat interface. Cause: The `toolChoice` or `functionCall` parameters are not configured correctly, causing the tool calling logic to not take effect, and the interface cannot match the expected business request format.
- The content extraction node cannot call the self-built model interface. Cause: The `functionCall` adaptation mode is not enabled, or the correct model access permissions are not configured, causing the node to fail to recognize the interface format of the self-built model.
- Network-connected plugins cannot work properly in a domestic environment. Cause: No domestic available proxy or mirror address is configured, causing the plugin to fail to access external network resources and triggering a connection timeout error.

## How to confirm the configuration is complete
- Check whether the `toolChoice` and `functionCall` parameters on the plugin configuration page match the preset values.
- Initiate a simulated call to check whether the returned results include structured business data from internal systems.
- Check the interface logs to confirm that the request timeout period and maximum concurrency have not triggered the current limiting rules of the internal system.
- Wait for one synchronization cycle, call the tool again, and check whether the returned data is the latest updated content.

The values given are common starting points and should be measured against the reader's own samples.
