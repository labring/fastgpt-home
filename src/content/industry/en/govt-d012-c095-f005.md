# Internal Office and Employee Services for New Energy Development: Tool Calling and Plugins
This document is written based on FastGPT v4.17.0.

## What the data for this category looks like
Core data sources for new energy development include station operation logs, project progress ledgers, material inventory systems, and operation and maintenance inspection records. Real-time operation data such as unit speed, power generation, and ambient temperature is updated every second. Project progress and material inventory are updated daily or on demand.

Each data entry includes station number, unit ID, timestamp, operation parameter value, and abnormal alarm flag. Fields use industry standard units: speed in rpm, power generation in kW·h, temperature in ℃. Data structure has minor differences based on station construction time. Some older stations lack certain custom fields.

## Constraints imposed on tool calling and plugins by these characteristics
Multi-source heterogeneous data features of new energy development require tool calling to accurately match the permission scope of data interfaces, to avoid unauthorized access to cross-station data.

Real-time second-level updated operation parameters require the timeout threshold for tool calling to be set to a short interval, to prevent process blocking due to data delay.

Multi-field structured data requires tool calling to specify core fields to be extracted, to avoid redundant information returning and occupying context space.

Differences in custom fields across stations require tool calling to support dynamic adaptation of data source field mapping rules, to reduce secondary development costs.

Lightweight display requirements in internal office scenarios require tool calling return results to be simplified, to avoid excessive non-core information interfering with employee use.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `toolChoice` | Dynamically switch based on data source | Adapt to custom field rules of different stations, avoid calling redundant data |
| `functionCall` | Only specify core fields to be extracted | Reduce return content volume, adapt to lightweight display requirements of internal office |
| Single call timeout | 10–30 seconds | Match the update frequency of real-time operation data, prevent process blocking |
| Result cache duration | 5–15 minutes | Adapt to the daily update rhythm of project ledgers and material inventory, reduce repeated calls |
| Number of returned results | Top 3–5 entries | Focus on core operation and maintenance or project data, avoid information overload |
| Plugin permission scope | Bind the data source ID of the corresponding station | Comply with internal data security specifications of Chinese state-owned enterprises and public institutions, prevent unauthorized access |

## Three Common Misconfigurations
- Only the output of the final node is displayed after a tool calling chain runs, and processing results from intermediate steps are not retained. This happens because the result pass-through rule for `functionCall` is not configured, so the output of intermediate nodes is not written to the context.
- Empty results or permission errors are returned when calling internal data sources. This happens because the correct data source mapping rule is not specified via `toolChoice`, so the tool cannot match the interface permissions of the corresponding station.
- Tool calling cannot be triggered after a custom secret key is configured. This happens because permission binding for the secret key is not completed in the plugin settings, so the call request is intercepted by security verification.

## How to Verify Successful Configuration
- Initiate a simulated call, check that the returned results only include preset core fields to confirm the `functionCall` configuration is active.
- View the tool calling log, confirm the timeout time falls within the preset 10–30 second interval, with no frequent timeout errors.
- Check the display name on the third-party integration interface, confirm it has been replaced with the custom internal office application name.
- Test cross-station data calling, confirm only data sources within the bound permissions are accessible to verify the plugin permission scope configuration is active.

The values provided are common starting points and should be measured against the reader's own samples.
