# Internal Office and Employee Services for New Energy Development: Forms and Interactions

## What Data for This Category Looks Like

Internal office data for new energy development comes from four main sources: project operation and maintenance systems, human resources modules, material procurement ledgers, and on-site inspection terminals. Data updates follow three schedules:
- Project progress ledgers are synchronized daily
- On-site inspection records are uploaded in real time
- Employee attendance and reimbursement data are aggregated per calendar day

Document structures primarily use structured forms. Core fields include project numbers with region and year prefixes, device longitude and latitude coordinates, inspection duration, power readings, and submitter IDs. Common units include kilowatt-hours, hours, meters, and other standard engineering and office units.

## Constraints Imposed on Forms and Interactions

The region and year prefix requirement for project numbers requires configuring format validation rules for `formInput`. The rules must restrict input to match the preset prefix and number combination, to prevent invalid data entry.

The professional format requirement for longitude and latitude coordinates requires enabling input guidance. This restricts input to degrees-minutes-seconds or decimal formats, reducing manual entry errors.

The need for cross-departmental workflow across multiple links requires form nodes to support calls from multiple upstream link nodes. This adapts to jump requirements for different business branches, such as inspection reports, operation and maintenance applications, and equipment repair requests.

The large number of structured fields and clear unit requirements require forms to automatically bind corresponding units. This avoids repeated data entry and confusion.

## Configuration Guidelines

These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` format validation | Match the pattern WD-202[0-9]-[0-9]{4} and decimal longitude and latitude format (±180.0000, ±90.0000) | Adapts to the fixed specifications for new energy project numbers and inspection coordinates, filters invalid input |
| `userSelect` optional scope | Internal employee role groups (operation and maintenance/finance/administration) | Limits form submission permissions, ensures submitters belong to corresponding business departments |
| Input guidance | Enabled | Provides format example prompts for professional fields, reduces entry difficulty for non-technical employees |
| Variable reference binding | Associate existing fields from project ledgers and inspection records | Reuses existing data in the system, reduces repeated entry operations |
| Link call permission | Allow up to 5 upstream nodes to call | Adapts to multi-business branch jump requirements, covers scenarios such as inspection reports and equipment repair requests |

## Three Common Misconfigurations

- Issue: Form nodes cannot be called by multiple upstream link nodes, and workflow errors occur after jumping. Cause: Link call permissions are not configured. The default setting only allows a single upstream node to connect.
- Issue: An error prompt appears in the debug preview interface after enabling input guidance and configuring a custom thesaurus address. Cause: The custom thesaurus address does not point to a valid internal thesaurus, or the thesaurus format does not meet system requirements.
- Issue: A `quote type error` error appears during variable reference. Cause: The referenced variable is not bound to a corresponding structured field, or the variable format does not match the preset field type of the form.

## How to Verify Successful Configuration

- Submit a test data set that matches the preset format, and check if the form accepts the data normally and passes validation.
- Jump to the form node from two different upstream business nodes, and confirm that workflow transfer has no errors.
- Reference existing structured fields in the system as variables, and check if submitted data is automatically synchronized to the corresponding business module.
- View the form's permission configuration, and confirm that only authorized role groups can initiate form submission operations.

The values listed here are common starting points. They should be evaluated against sample data from the actual deployment.
