# Internal Office and Employee Services for Non-Ferrous Metal Smelting: Workflow Orchestration

## What the data for this category looks like
Business data for non-ferrous metal smelting mainly comes from production PLC control systems, manufacturing execution systems (MES), laboratory testing equipment, employee attendance systems, and material management systems. Furnace temperature and feeding volume data from production processes update every 1 to 5 minutes. Metal grade and material composition data from laboratory testing generate with each testing batch. Attendance data completes daily summary updates in the early morning. Material inventory data updates immediately after each batch is put into or taken out of storage. Data documents include fields such as furnace number, shift, testing batch number, employee ID, and material code. Corresponding value units include degrees Celsius, hours, kilograms, cubic meters, and others.

## What constraints these characteristics impose on workflow orchestration
High-frequency production data updates require workflows to support minute-level scheduled triggers or device state event triggers, to avoid delayed responses to production abnormalities. Batched testing and material data require workflows to bind unique identifiers such as furnace number and batch number as the basis for query and transfer, to ensure accurate data association. Office processes tied to daily-updated attendance data only need daily scheduled triggers to complete summary and abnormality reminder tasks. Cross-system calls of multi-source data require reasonable setup of parameter transfer rules between nodes in workflow orchestration, to avoid data loss caused by field mismatches.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Trigger Mode | Trigger by production events (1-5 minute interval) or daily scheduled trigger | Matches the update rhythm of production and attendance data |
| Variable Binding | Bind furnace number, batch number, and employee ID as `variables` parameter | Ensures accurate cross-node data association, aligns with the batched characteristics of smelting business |
| Node Timeout | 60-120 seconds | Adapts to real-time query response requirements for production data, avoids process blocking |
| Result Filtering | Retain the first 3-5 matching results | Focuses on core business data, reduces interference from redundant information on workflows |
| Notification Configuration | Bind DingTalk webhook node to push results | Adapts to real-time notification needs for internal office work, covers production teams and employees |
| Node ID | Specify the `nodeId` of the corresponding business node | Ensures accurate calling and transfer between workflow nodes |

This configuration rule applies to FastGPT v4.17.0.

## Three common mistakes to avoid
- Execution logs for the DingTalk webhook node in the workflow show failure, or no push message is received. The cause is failure to correctly fill in the webhook address of the DingTalk robot, and failure to configure pushed text content in `variables`.
- After the HTTP node returns a BLOB object, no download link appears in the dialog box. The cause is failure to add a file download node to the workflow, or failure to correctly associate the storage path of the BLOB object.
- Advanced orchestration nodes cannot be dragged to the workflow canvas, or no response occurs after clicking. The cause is failure to enable advanced orchestration function permissions in system settings, or the trigger mode configured for the node does not meet system requirements.

## How to confirm the configuration is complete
- View the workflow trigger log to confirm the trigger mode matches the configured interval or event.
- Test parameter transfer between nodes, input the bound `variables` fields, and confirm subsequent nodes can normally obtain corresponding values.
- Manually trigger the workflow once, check whether the DingTalk webhook node generates a push record, or whether the BLOB object generates a downloadable link.
- View the configuration panel of the advanced orchestration node, confirm the `nodeId` is filled correctly and there are no red error prompts.
