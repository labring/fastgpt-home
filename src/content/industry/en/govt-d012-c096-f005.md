# Internal Office and Employee Services for Non-Ferrous Metal Smelting: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category primarily comes from production site PLC control systems, quality inspection laboratory management systems, and energy management platforms. Real-time production parameters such as furnace temperature and operating current update every 10 seconds. Daily total energy consumption and material feeding volume are summarized and updated at midnight each day. Monthly production ledgers are synchronized on the first day of each month.
Data is stored in structured format. Each entry includes fields such as production batch number, furnace temperature (unit: ℃), operating current (unit: kA), daily energy consumption (unit: kWh), material feeding volume (unit: tons), quality inspection component content (unit: mg/kg). Every entry is bound to a unique production batch identifier.

## Constraints Imposed on Tool Calling and Plugins
High-frequency updates of real-time parameters require configuring reasonable request intervals for tool calls. This prevents triggering interface rate limits by sending too many requests in a short period.
The structure with multiple fields and units requires plugins to preset field parsing rules. These rules automatically adapt to numerical conversion for different units such as ℃, kA, kWh, reducing manual processing costs.
The feature of binding production batches requires passing the corresponding batch number as a filter parameter during tool calling. Accurate data cannot be returned otherwise.
The large data volume of monthly ledgers requires plugins to limit the number of data entries in a single batch request. This avoids interface response timeouts or overly large returned content.
Permission control for internal office work of central state-owned enterprises requires tool calls to adapt to internal system identity verification logic. This prevents unauthorized access to sensitive production data.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-tool calling scenarios, automatically select appropriate tools to handle smelting data queries |
| `functionCall` | `enabled` | Support structured data return, facilitating parsing of multi-field parameters for non-ferrous metal smelting |
| Plugin request timeout | 30 seconds | Match the update interval of real-time production parameters, avoid data expiration due to long waiting times |
| Single request data count | First 100 entries | Adapt to the data volume of monthly ledgers, avoid interface response timeouts |
| Field parsing rules | Preset unit conversion | Uniformly handle fields with different units such as furnace temperature and current, reduce parsing error rates |
| Identity verification configuration | Bind internal OA identity | Adapt to permission control requirements for internal office work of central state-owned enterprises |

## Three Common Mistakes
- A 401 status code is returned when calling a self-built smelting data interface. The internal office system identity verification configuration is not correctly bound, causing the request to fail permission verification.
- The results returned by tool calling are not output in structured format. The `functionCall` parameter is configured incorrectly, and the structured calling function is not enabled.
- Attempting to use a Google plugin to retrieve external industry data online fails to load. Domestic network environment restrictions prevent direct access to Google-related services.

## How to Confirm Configuration Is Complete
- Initiate a test request, pass the preset production batch identifier, check if the returned fields include preset content such as furnace temperature and current from the configuration.
- View the running logs of tool calling, confirm that the request timeout configuration matches the set value, and no timeout-related errors occur.
- Initiate a request using the test account of the internal office system, confirm that the identity verification configuration takes effect, and production data for the corresponding batch can be obtained normally.
- Initiate different types of query requests, verify the automatic selection function of `toolChoice`, confirm that the matching results of tool calling meet the expected scenarios.

The values listed above are common starting points. They should be evaluated against the reader's own samples.
