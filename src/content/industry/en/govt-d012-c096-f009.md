# Internal Office and Employee Services for Non-Ferrous Metal Smelting: Model Integration and Configuration

## What This Category of Data Looks Like
Core data for non-ferrous metal smelting comes from real-time collection ledgers of production central control systems, team patrol logs, batch quality inspection reports, and energy consumption statistical reports. Data update rhythms fall into three categories:
- Device parameters collected in real time by the central control system refresh every second
- Team patrol logs update once every 8 hours
- Batch quality inspection reports generate after each furnace smelting is completed

Each document includes fields such as device number, detection time, detection parameters, anomaly flag, and corresponding furnace batch number. Most parameter units use industrial standard units including degrees Celsius, megapascals, amperes, and cubic meters per hour.

## What Constraints These Data Characteristics Impose on Model Integration and Configuration
High-frequency real-time collected industrial parameter data uses large amounts of context tokens. Limit the total context length per dialogue during model integration to avoid exceeding model support limits.

Structured data with multiple fields and units requires the model to accurately identify parameters and their corresponding units. Do not set too high a randomness parameter.

Batch-bound quality inspection reports and furnace batch data require the model to accurately match furnace batch numbers during recall. Adjust the matching accuracy of context recall.

Differences in update rhythms across data sources require matching corresponding data synchronization cycles in model configuration. This prevents calling outdated smelting production data.

## How to Set Configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 tokens | Adapts to the context carrying requirements of multi-field structured data for non-ferrous metal smelting, avoids truncating key furnace batch numbers and parameter information |
| `maxTokens` | 2000–3000 tokens | Limits token consumption per reply, adapts to short instructions and data query requirements in internal office scenarios |
| `quoteMaxToken` | 1500–2000 characters | Ensures recalled document content such as smelting ledgers and quality inspection reports is complete, while avoiding redundant information interfering with model reasoning |
| `temperature` | 0.2–0.4 | Reduces randomness of replies, ensures accurate recognition of key information such as structured parameters and furnace batch numbers |
| `AIPROXY_API_ENDPOINT` | Corresponding deployed model service address | Adapts to locally deployed or private cloud model call links, complies with data non-exfiltration requirements for state-owned enterprises and public sector entities in China |
| `toolChoice` | auto | Allows the model to independently choose whether to call tools to process structured data queries, adapts to multi-type request scenarios in internal office work |

## Three Common Misconfigurations
- Phenomenon: A 404 status code is returned when calling the model, and the embedding model or large language model cannot be loaded normally. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to point to the privately deployed model service address, or `AIPROXY_API_TOKEN` does not match the verification key for model deployment.
- Phenomenon: Classification results in the workflow have large fluctuations, and classification results for the same type of smelting anomaly are inconsistent. Cause: The set `temperature` value is too high, leading to excessive randomness during model reasoning, which prevents stable recognition of structured anomaly parameter features.
- Phenomenon: Response delay in the problem classification link is significant, failing to meet real-time office query requirements. Cause: The values of `maxTokens` and `maxContext` are not limited, causing the model to process excessive context data per call and extending reasoning time.

## How to Confirm Configuration Is Complete
- Initiate a query that includes a smelting furnace batch number and device parameters, verify that the content returned by the model accurately matches the input fields and units.
- View the model call logs in FastGPT v4.17.0, confirm that the returned token consumption does not exceed the preset configuration limits.
- Simulate multiple repeated queries for the same type of smelting anomaly, verify that the consistency of classification results meets expectations.
- Test calling smelting data from different data sources, confirm that the model can correctly recall quality inspection reports and patrol logs corresponding to the furnace batch.

Note: The configuration values listed above are common starting points. Adjust them based on your own specific samples and use cases.
