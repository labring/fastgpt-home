# Internal Office and Employee Services for Non-Ferrous Metal Smelting: Forms and Interactions

## What the Data for This Category Looks Like
Data sources include production site sensor-collected data, production ledgers from the enterprise’s ERP system, equipment operation and maintenance logs, human resource management modules, and administrative reimbursement systems. Real-time production data updates every minute. Equipment ledgers and employee work schedules update daily. Administrative documents are generated immediately upon submission.

Documents are divided into three categories:
- Production documents include workstation number, collection time, material weight, and energy consumption value
- Personnel documents include employee ID, job title, and work shift period
- Administrative documents include application reason and approval node

All fields have clear physical or business units, with no ambiguous descriptions.

## Constraints Imposed by These Characteristics on the "Forms and Interactions" Link
Minute-level updates for production data require forms to support high-frequency, short-interval data entry, and avoid overly long wait timeouts. Clear units for material weight and energy consumption values require built-in unit matching components in the interaction flow to prevent unit confusion from free text input. Fixed approval transfer logic for personnel and administrative forms requires limiting the number of custom fields to avoid process configuration chaos. When batch entering production data, strictly match preset fields; otherwise, data misalignment will occur and normal processing will fail. Real-time collected values require real-time verification in the form to prevent abnormal inputs exceeding equipment ranges from entering the system.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable value range verification, bind preset units | Match fixed fields and units of non-ferrous metal smelting production data to prevent free input errors |
| `userSelect` | Preset approval node options, limit the number of custom options | Adapt to the fixed approval flow of smelting office processes to avoid process chaos |
| Single submission limit | 10 entries | Adapt to batch production data entry scenarios, avoid timeouts caused by too much data in a single submission |
| Input timeout threshold | 30 seconds | Adapt to high-frequency real-time entry scenarios, prevent submission failures caused by network delays |
| Form field verification | Enable required field verification, match preset fields | Ensure complete required information for administrative and personnel forms, comply with internal office specifications |

## Three Common Mistakes
- When batch uploading smelting production documents, the first dozen entries process normally, but subsequent entries have no response. The root cause is that the form does not have batch submission field matching rules configured, leading to subsequent data field misalignment that the system cannot identify.
- After embedding an application via iframe, the send button appears gray when clicking text to insert it into the input box. The root cause is that the text entered in the form does not trigger the verification event of `formInput`, so the system does not recognize it as valid input.
- When entering long smelting-related text in an AI conversation node, an error is returned directly with no response. The root cause is that no input upper limit interception logic is configured, and no pre-verification is performed after exceeding the model input threshold.

## How to Confirm Proper Configuration
- Open the form configuration page of FastGPT v4.17.0, and verify whether the value verification rules of `formInput` match the fields and units of smelting data.
- Submit a single production data entry, and check whether the input box automatically matches the preset unit and intercepts abnormal values exceeding the range.
- Attempt to batch upload multiple smelting documents, and confirm that all entries can properly match the preset fields and complete submission.
- Trigger the form interaction embedded via iframe, and confirm that the send button activates normally after inserting text.
