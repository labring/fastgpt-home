# Internal Office and Employee Services for Non-Ferrous Metal Smelting: Deployment and Upgrade

## What this category of data looks like
Data sources for non-ferrous metal smelting include real-time production collection systems, ERP material management systems, equipment inspection logs, and employee attendance and training records. Data update frequencies cover three categories: real-time (smelting temperature, shift output), daily (material consumption ledger), and monthly (production reports). Document structures include structured work orders and indicator tables, as well as unstructured inspection image and text reports. Most fields have dedicated units, such as smelting temperature (℃), material batch weight (tons), and equipment runtime (hours).

## What constraints do these characteristics impose during deployment and upgrade
Deployments must support multiple data source connection configurations to accommodate scattered, diverse data sources. Resource capacity for databases and file storage must be planned in advance.
Synchronization strategies must be matched to data with different update frequencies. Trigger cycles for data synchronization tasks must be adjusted during upgrades.
Structured data with dedicated units must retain field metadata to prevent information loss during vector retrieval.
Database connection pool configurations must be optimized to avoid blocking, as real-time production data has high concurrent read/write volumes.
Offline deployments require preconfigured local storage and database instances to work in environments without external network access.

## How to set configurations
The following configurations are formulated for FastGPT v4.17.0, and are adapted to the deployment needs of internal office and employee services for the non-ferrous metal smelting industry.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 15–20 connections | Non-ferrous metal smelting production data has high concurrent read/write volumes, matching concurrent connection requirements |
| `STORAGE_S3_ENDPOINT` | Local mount path or intranet object storage address | Required to store large-volume unstructured files such as inspection reports and production ledgers |
| `MONGODB_URI` | Intranet MongoDB instance address, configured with read-write separation | Used to store semi-structured data such as employee work orders and inspection records |
| `PG_URL` | PostgreSQL address with connection pool parameters | Used to store structured production indicator data with dedicated units |
| `REDIS_URL` | Intranet Redis cluster address, set to 1800-second expiration time | Used to cache real-time production data and reduce frequent read/write pressure on databases |
| `FE_DOMAIN` | Intranet access domain name or local IP:port | Used for resource loading and callback requests for internal office pages |

## Three common mistakes
- Phenomenon: The download address keeps jumping after a custom plugin runs, and the final result is returned after several seconds of delay. Cause: Temporary download link generation timed out due to incorrect `FILE_TOKEN_KEY` configuration, or cache invalidation caused by abnormal `REDIS_URL` connection.
- Phenomenon: Startup fails during local non-Docker offline deployment, with a database connection error popup. Cause: `MONGODB_URI` or `PG_URL` does not point to a locally deployed database instance, or `DB_MAX_LINK` value is too low, causing connection pool exhaustion.
- Phenomenon: Models connected to external model platforms have no response or return empty results. Cause: Permission verification failed because `ROOT_KEY` was not configured, or callback failed because `FE_DOMAIN` was not set to an internally accessible address.

## How to confirm configurations are correct
- Run the built-in database connection test tool to verify that the connection number set in `DB_MAX_LINK` can support the configured concurrent read/write volume, and confirm that instances pointed to by `MONGODB_URI` and `PG_URL` can read and write data normally.
- Upload a smelting inspection report file, and verify that the file can be accessed and downloaded normally through the storage path corresponding to `STORAGE_S3_ENDPOINT` to confirm that the file storage configuration takes effect.
- Start the internal office service, access the address corresponding to `FE_DOMAIN`, and confirm that the page loads normally without resource loading errors.
- Trigger a real-time production data synchronization task, confirm that data can be written to the database normally, and that cache updates comply with the expiration rules configured in `REDIS_URL`.

The values provided here are common starting points, and should be measured against the reader's own samples.
