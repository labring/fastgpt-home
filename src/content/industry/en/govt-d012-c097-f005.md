# Internal Office and Employee Services for Nuclear Power Operations: Tool Calling and Plugins

## What the data for this category looks like
Internal data for nuclear power operations comes from equipment inspection logs, reactor operation parameter records, employee attendance and scheduling systems, and safety operation procedure documents. Structured data includes fields such as equipment number, inspection time, exception code, and core temperature, with units including ℃, minutes, and sets. Unstructured data includes long-text safety regulations, training courseware, and video-format inspection records.

Data update cycles vary significantly: real-time inspection parameters update every 15 minutes, attendance and scheduling data updates daily, and safety regulation documents update every quarter. Data is categorized by department and equipment ID. Most single structured records range from 100 to 500 characters, while single video files can reach hundreds of MB.

## What constraints these characteristics impose on tool calling and plugins
Fixed fields and units for structured data require that tool calls must precisely match parameter names and units, otherwise data cannot be parsed correctly. Real-time updated inspection parameters require tool call response speeds to match the update frequency, to avoid obtaining outdated data.

Large file size of video-format inspection records requires plugins to support large file upload and parsing, otherwise content analysis cannot be completed. Coexistence of multiple data types (equipment, employee, safety regulations) requires tool calls to support automatic adaptation to multiple scenarios, to avoid a single tool failing to cover all needs. Processing long-text safety regulations requires plugins to have long-context parsing capabilities, to ensure complete reading of document content.

## Three common mistakes
- Incorrect parameter format when calling tools, manifested as a 400 status code returned by the interface, with a prompt about parameter unit mismatch. The cause is failure to transmit parameters in accordance with the fixed field units of nuclear power data (such as ℃, minutes), leading to the model being unable to correctly parse structured operation data.
- Failure to correctly specify the field name of the file variable when calling plugins via the API, manifested as the plugin failing to receive the uploaded inspection video file and returning empty results. The cause is failure to follow the platform's file parameter transfer rules, and failing to bind the file to the specified field.
- Failure to limit the valid function list when configuring `functionCall`, manifested as an error triggered when calling an unregistered nuclear-power-specific tool. The cause is failure to register the required tools in the platform in advance, leading to the model being unable to identify valid call targets.

## How to confirm the configuration is correct
- Initiate a test call, pass a simulated equipment ID parameter, and check whether the returned results include the inspection records and exception codes of the corresponding equipment.
- Upload a test video file under 500 MB, confirm that the plugin can normally receive and return parsed text results.
- View the tool call log, confirm that the parameter format complies with the field requirements of nuclear power data, with no prompts about unit or name mismatch.
- Adjust `toolChoice` to auto mode, verify that automatic selection across multiple tool scenarios meets business requirements.
