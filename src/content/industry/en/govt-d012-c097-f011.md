# Internal Office and Employee Services for Nuclear Power Operations: Forms and Interactions

## What this type of data looks like
Nuclear power operation internal office and employee service data mainly comes from production ledger systems, equipment inspection terminals, employee attendance modules, and office approval process libraries. There are two categories of data update frequencies: equipment inspection records are submitted in real time alongside on-site operations, while attendance and office approval documents are updated each calendar day or at process nodes. Most documents are structured forms, including fields such as equipment number, inspection time, defect level, processing deadline, employee ID, and more. Units cover professional engineering units such as unit, hour, count, millimeter, megapascal. Some historical archived data consists of unstructured paper scans, which require OCR conversion to a processable format.

## Constraints on forms and interactions
The professional fields and unit requirements for nuclear power operations mean form interactions must match fixed input rules for engineering scenarios. The presence of multiple professional units requires form input controls to bind corresponding unit prompts by default to avoid input errors. The high proportion of structured fields in document structures requires forms to be split into modules by business scenario, with each module preset with fixed fields and validation rules to reduce manual configuration errors. The need to tie real-time inspection data to approval processes requires forms to automatically trigger subsequent workflow nodes upon submission, without manual redirection. The presence of unstructured archived data requires forms to support multi-format attachment uploads and include basic OCR parsing capabilities to automatically extract key field information.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Configure independent components for equipment inspection, office approval, and employee attendance respectively, with preset fixed fields and validation rules | Matches the high proportion of structured fields in nuclear power operation documents, reducing input errors |
| Attachment upload limit | Single file maximum 1000 MB, supports PDF, JPEG, PNG formats | Adapts to scenarios where large attachments such as inspection reports and equipment drawings need to be uploaded for nuclear power operations |
| `userSelect` | Limit the optional range to internal employee IDs and department lists, enable automatic ID completion | Ensures the responsible subject of office processes is accurately matched, avoiding approval permission errors |
| Unit binding prompts | Bind corresponding unit prompts for pressure, temperature, and duration fields, such as megapascal, degrees Celsius, hour | Matches the professional engineering unit usage habits of nuclear power operations, reducing input errors |
| Workflow trigger timing | Automatically trigger subsequent nodes after form submission is complete, set the timeout period to 600 seconds | Adapts to the response requirements of real-time office processes, avoiding process stagnation |
| Form block configuration | Split into 3 blocks by business scenario, with a maximum of 12 fields per block | Avoids operational confusion caused by too many fields on a single-page form, improving filling efficiency |

## Three Common Errors
- Symptom: Form input components fail to load in the conversation interface, and the interaction content is blank. Cause: The output node of the `formInput` component is not correctly bound in the workflow, resulting in the context not being passed to the conversation rendering module.
- Symptom: Subsequent workflow is not triggered more than 600 seconds after form submission, and the interface displays a timeout error. Cause: The workflow trigger timeout configuration value is set too small, not matching the time required to fill out complex forms for nuclear power operations.
- Symptom: Attachments cannot be parsed by OCR after upload, and form fields are not automatically filled. Cause: The OCR parsing switch for the corresponding format is not enabled, or the uploaded file exceeds the preset 1000 MB limit.
