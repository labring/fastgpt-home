# Internal Office and Employee Services for Civil Aviation Airports: Multi-turn Dialogue and Prompt Engineering

## What this category's data looks like
Data for civil aviation airport internal office and employee services comes primarily from in-house business systems: flight scheduling, ground crew scheduling, baggage operations, and logistics support.
Data update frequencies fall into three groups:
- Real-time: flight status, temporary scheduling notices
- Daily: employee shift schedules, daily operation logs
- Weekly: supplies inventory, site usage reports
Individual documents include fields such as flight number, takeoff and landing times, ground crew position codes, employee ID numbers, and equipment serial numbers. Units used include hours, person-times, item counts, square meters, and others. Some documents require linked cross-system collaborative data.

## What constraints these characteristics impose for multi-turn dialogue and prompt engineering
High-frequency real-time flight data updates require limiting multi-turn dialogue context retention duration to avoid calling outdated business information.
Documents with multiple fields and units require prompts to clearly specify target fields and their units. This prevents responses that violate business specifications.
Cross-system linked data requirements demand that multi-turn dialogue gradually guides users to provide associated parameters. This avoids single requests exceeding system compatibility limits.
Daily updated shift schedules and logs require dialogue processes to trigger real-time data pulls. This ensures returned content matches current business status.
Some cross-system data has a 1-2 second pull delay. Reserve a reasonable response buffer for multi-turn dialogue.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context retention duration | 600–1200 seconds | Matches real-time flight data update cycles, avoids calling outdated business information |
| Single dialogue timeout threshold | 30 seconds | Meets instant response needs of airport internal office work, prevents long waits from disrupting employee use |
| `variables` binding scope | Only bind employee ID number and position code for the current session | Complies with permission isolation rules for internal airport data, prevents cross-session data leaks |
| `messages` history count | First 10 dialogue turns | Controls context load, adapts to dialogue complexity across multiple airport business scenarios |
| Prompt template field requirements | Mandatorily specify flight number, position type, and equipment number fields | Aligns with standard field structures of internal airport documents, ensures responses meet business specifications |
| `chatId` binding rule | Bind the unique identifier of the current session | Ensures context consistency for multi-turn dialogue, avoids session confusion |

## Three common misconfigurations
- Phenomenon: Tool call results do not appear in the dialogue box. They only display after re-entering the session. Cause: The `chatId` parameter is not correctly bound. The session context fails to associate with tool call return data consistently.
- Phenomenon: The iframe-embedded dialogue box shows an English interface. Cause: No language adaptation parameters are configured. The system loads the default general English template.
- Phenomenon: Request Time errors occur during dialogue. Cause: The single dialogue timeout threshold is set too short. The system cannot complete cross-system data pulling and processing.

## How to confirm the configuration is correct
- Initiate a continuous multi-turn dialogue that includes flight status queries and ground crew schedule consultations. Verify returned content includes accurate business fields and their corresponding units.
- Re-enter the same session. Confirm the dialogue context is not lost, and tool call results display normally in the dialogue box.
- Initiate a long-duration cross-system data query. Confirm no timeout errors occur, and responses meet preset duration requirements.
- Check the language of the iframe-embedded interface. Confirm it has switched to the adapted Chinese interface.
