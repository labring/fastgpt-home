# Internal Office and Employee Services for Civil Aviation Airports: Document Parsing and Chunking

## What the Data for This Category Looks Like
Document sources for civil aviation airport internal office and employee services include internal policy compendiums, flight operation support manuals, monthly operation logs, employee training slides, terminal safety specifications, and similar materials. Update cadence varies by document type: policy documents are updated quarterly, operation logs are archived on a natural day basis, and seasonally adjusted support manuals are updated every six months.

Document structures include long-text process descriptions, structured tables such as shift schedules and equipment parameter tables, and graphic-aided emergency response guides. Fields include flight number, stand number, operation number, safety level, and similar items. Units include hours, person-times, meters, kilograms, and similar units.

## Constraints for Document Parsing and Chunking
The multi-type structure of civil aviation internal documents creates clear requirements for chunking logic. Long-text operation procedures must avoid splitting key operation nodes, as this will reduce the accuracy of employee training and execution. Documents with many nested tables will suffer broken data integrity if chunking logic is improper, leading to failed subsequent retrieval. Operation logs archived by timestamp must retain contextual connections between adjacent entries to support event process review. The file sizes of large single archived documents vary widely, so parsing and chunking workflows must adapt to different file sizes to avoid interruptions or incomplete results.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Aligns with the logical unit length of process steps and equipment parameters in civil aviation documents, avoiding splitting critical information |
| `chunkSplitter` | Split by paragraph + heading | Matches the chapter hierarchy and process sections of civil aviation documents, preventing splitting of complete operation instructions |
| `customPdfParse` | Enabled | Preserves nested tables and watermark formatting in civil aviation PDF documents, avoiding breakup of table content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for large operation archive documents, preventing task timeout and mid-process interruption |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatibility with the file size of single annual operation archive documents for civil aviation |
| `chunkSettingMode` | Manual mode | Allows adjustment of chunking rules for different document types such as policies, logs, and training slides |

## Three Common Misconfigurations
- Issue: Some tables cannot be chunked correctly, and parsed table content is split into multiple independent chunks. Cause: `customPdfParse` is not enabled. The default parsing engine cannot recognize the nested table structure in civil aviation documents, leading to tables being split by text.
- Issue: Out-of-memory errors or GPU recognition failures occur when parsing PDF documents. Cause: The deployed PDF parsing plugin does not match the local CUDA version, or GPU acceleration configuration is not enabled, resulting in resource usage exceeding thresholds.
- Issue: Image links are lost after Word documents are converted to Markdown and imported, and images cannot be loaded in conversations. Cause: The complete domain name of external link resources is not retained during document parsing, leading to truncated image links.

## How to Verify Proper Configuration
- A single civil aviation operation procedure PDF containing nested tables may be uploaded, and parsed chunk results reviewed to confirm tables are fully retained within a single chunk.
- An annual operation archive document larger than 100 MB may be uploaded, with confirmation that the parsing task has no timeout errors and chunk results cover all document content.
- Deployment logs of FastGPT v4.17.0 may be reviewed to confirm GPU model and video memory information are correctly identified, with no errors related to video memory overflow.
- A Word document of employee training slides with embedded images may be uploaded, and chunked Markdown content reviewed to confirm complete domain names are retained in image links.
