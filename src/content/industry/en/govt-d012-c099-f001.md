# Internal Office and Employee Services for Oil and Gas Exploration and Development: HTTP Interfaces and External Systems

## What data for this category looks like
Data for oil and gas exploration and development originates from field exploration collection devices, real-time monitoring systems on drilling platforms, and analytical equipment in geological laboratories. Data update rhythms fall into three categories: real-time collected drilling working condition data, daily generated logging report data, and monthly summarized geological reserve data. A single data entry includes fields such as well location identifier, collection timestamp, physical parameter value, and associated equipment number. Most physical parameters have clear physical units. Some data take the form of binary format logging files, and individual entries have large volume.

## What constraints these characteristics impose on HTTP interfaces and external systems
Real-time collected drilling working condition data has high interface latency requirements, so limit the response duration of single requests. Large-volume binary logging files raise higher requirements for the maximum size of HTTP request bodies. Structured parameters with multiple fields require precise retrieval of target data via identifier parameters. Data with different update rhythms correspond to different call frequencies, which must match the call quotas of external interfaces. The unit consistency of physical parameters must be clearly defined in interface agreements to prevent subsequent data parsing errors.

## How to set configurations
This guidance is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface Timeout | 30–60 seconds | Matches the low latency requirements of real-time exploration data, avoids connection interruptions caused by long waiting periods |
| Request Header `Authorization` | Fixed Bearer token format, obtain the key from the dedicated API gateway | Complies with identity verification specifications for external systems, ensures controllable interface call permissions |
| Context Variable `variables` | Pass well ID, device ID, and data type parameters | Accurately filters target exploration data, avoids pulling irrelevant redundant information |
| Response Data Parsing `responseData` | Extract physical parameters and timestamps by field path | Adapts to the structured format of exploration data, quickly extracts core business fields |
| Request Body Size Limit | 1000 MB | Adapts to the transmission requirements of single-well binary logging files |
| Call Frequency Quota | Calibrated based on actual measurements | Matches the call restrictions of external APIs and the update rhythm of exploration data |

## Three common errors
- Symptom: Calling an external API returns a 404 status code, and the interface prompts that the path is invalid. Cause: The dedicated path for oil and gas exploration data interfaces is not used, and a general API address is mistakenly selected.
- Symptom: The data fields returned by the interface are empty, and exploration parameters cannot be parsed. Cause: Filter parameters such as well ID are not passed through `variables`, leading to the retrieval of unrelated empty data.
- Symptom: The request times out, and the interface displays connection interruptions. Cause: The interface timeout setting is too short, failing to adapt to the transmission duration of large-volume binary logging files.

## How to confirm configurations are set properly
- Call the test interface, check if the returned response body includes preset exploration data fields.
- Check if the format of the `Authorization` header is Bearer plus a valid key, with no format errors.
- Verify that the parameters passed through `variables` correctly match the exploration data of the target well location.
- View the interface call log, confirm that the response duration falls within the preset 30–60 second range.

The values provided here are common starting points and should be measured against the reader's own samples.
