# Internal Office and Employee Services for Oil and Gas Exploration and Development: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data is primarily sourced from drilling operation logs, seismic exploration result files, oil test reports, and formation analysis documents. Data updates follow job node timelines: single-well operation data is updated in bulk after well completion, and regional exploration reports are released per project phase. Most documents combine structured tables and unstructured text, containing fields such as well ID, operation time, formation depth, pressure value, fluid production volume, and more. Units include professional measurement standards such as meters, megapascals, and cubic meters.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Single files such as drilling logs and regional exploration reports can reach tens of thousands of characters. Multi-turn dialogue must limit the context window to avoid overflow. There are many structured fields with complex units, so prompts must clearly specify field extraction rules to prevent confusion between pressure, production, and other parameters from different well IDs. Operation data is updated per node, so the dialogue system must bind the dataset corresponding to the project cycle using `chatId` to avoid calling expired regional exploration reports. Employee questions often involve parameter comparisons across multiple well IDs, so multi-turn dialogue must retain well ID identifiers from historical context to ensure each reply’s parameters match the current session’s operation scope and avoid mismatched data errors.

## Configuration guidelines
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Maximum context length | 8000–12000 characters | Matches the typical length of a single exploration report, avoids dialogue interruptions caused by long text overflow |
| Dialogue record retention period | 30–90 days | Adapts to the average cycle of exploration projects, meets cross-timeframe historical query and review needs |
| `chatId` binding rule | Bind to the current operation project ID | Associates the dataset for the corresponding cycle, avoids calling expired regional exploration reports or drilling data from non-current projects |
| Historical message recall limit | Top 10 session messages | Retains core context such as well ID and operation time, reduces interference from redundant information on dialogue processing |
| `variables` permission binding | Divide permission tags by project team | Ensures employees can only access exploration data for their assigned areas, complies with relevant requirements for classified information management |
| `messages` filtering rule | Remove duplicate well ID parameter information | Streamlines context content, improves dialogue processing efficiency and accuracy |

## Three common misconfigurations
- The "The value of 'offset' is out of range" error occurs during long text tasks. This is caused by failing to limit the number of recalled `messages`, leading to the context window exceeding the system’s maximum allowed length and triggering an index offset exception.
- Dialogue record retention period settings do not match the project cycle, making it impossible to trace cross-week exploration parameter queries. This is caused by failing to adjust the retention threshold based on the average cycle of exploration projects, and only using the default short-term retention configuration.
- Knowledge base access permissions are not divided by project team, leading to non-assigned employees accessing classified drilling data. This is caused by incorrectly configuring the `variables` permission binding rule and failing to associate project-specific permission tags.

## How to confirm correct configuration
- An exploration log of 10000 characters is uploaded, a multi-turn parameter query is initiated, and no context overflow error appears in the reply.
- The dialogue settings page is accessed, and `chatId` is confirmed to be bound to the unique identifier of the current operation project.
- Test accounts from different project teams are used to initiate queries, and only exploration documents within the corresponding permission range are accessible.
- The prompt is edited to add the <FilesContent> tag, a specified exploration document is uploaded, and the dialogue correctly extracts formation parameters and operation data from the document.
