# Internal Office and Employee Services for Oil and Gas Exploration and Development: Workflow Orchestration

## What the data for this category looks like
Data for oil and gas exploration and development mainly comes from wellsite sensors, seismic acquisition equipment, drilling operation logs, geological exploration reports, and project management systems. Structured data includes well coordinates, drilling speed, formation pressure, and other metrics, with units mostly meters, kilonewtons, and megapascals. Unstructured data includes seismic profile images, on-site operation recordings, and PDF-format exploration analysis reports.
Update rhythms vary significantly: wellsite real-time data updates every second, seismic batch data updates per acquisition cycle, and project reports are submitted in batches after phase acceptance. Document structures primarily combine structured fields and nested attachments, with a single complete project document reaching hundreds of megabytes.

## Constraints These Characteristics Impose on Workflow Orchestration
The high-frequency updates of wellsite real-time data require workflows to support trigger-based operation, and need to adapt to access logic for multiple data source types. The mixed structured and unstructured data feature requires workflow nodes to distinguish between different configurations for structured parameter parsing and unstructured document processing.
The large size of single documents will increase the runtime of some nodes, so reasonable timeout thresholds must be preset. Cross-department approval office processes such as exploration plan review require workflows to support configuring node permissions by role, to prevent unauthorized users from modifying process nodes.

## How to Configure Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global Variables | Add a "Knowledge Base Selection" variable, with values of "General Exploration Knowledge Base, Drilling Operation Knowledge Base, Seismic Interpretation Knowledge Base" | Match the multi-scenario data classification needs of oil and gas exploration and development |
| `variables` | Configure employee ID as the associated field | Used to associate conversation logs with specific operating employees, meeting internal audit requirements |
| Node timeout setting | 600–1200 seconds | Adapt to long-running tasks such as seismic data parsing and drilling parameter calculation |
| Knowledge base recall limit | Top 8 entries | Balance data completeness and workflow response speed |
| Document upload size limit | 1000 MB | Adapt to the storage specification of single seismic profile files |
| `nodeId` | Name nodes by wellsite number | Facilitate quick location of workflow instances corresponding to specific wellsites |

## Three Common Configuration Mistakes
- The conversation log does not display associated employee information after the workflow runs. The cause is that the user identification field was not configured in `variables`, so the association between the log and the operator cannot be established.
- The number of results after the query and merge module in the workflow executes abnormally. The cause is that a reasonable recall limit parameter was not set, causing redundant data to interfere with the merge logic and preventing valid results from being output.
- The imported contract review process cannot upload documents. The cause is that document upload permission configuration was not enabled in workflow nodes, restricting file submission operations.

## How to Confirm Configuration Is Complete
- Trigger a test workflow, check whether the conversation log includes the user identification field configured in `variables`, and confirm the association relationship is normal.
- Upload a document that meets specifications, check whether the workflow node normally receives and parses the file content with no error prompts.
- Simulate a long-running task, confirm that the workflow node does not trigger a timeout error, and the running duration falls within the preset 600–1200 second range.
- Adjust the value of the Knowledge Base Selection variable, verify whether the workflow automatically switches to the retrieval results of the corresponding knowledge base, and the data source meets expectations.
