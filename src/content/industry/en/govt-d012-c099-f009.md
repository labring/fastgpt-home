# Internal Office and Employee Services for Oil and Gas Exploration and Development: Model Integration and Configuration

## What Data for This Category Looks Like
Data for oil and gas exploration and development comes primarily from on-site and laboratory-generated materials including real-time drilling logs, seismic exploration acquisition files, reservoir simulation reports, and well site inspection records.
Data update cycles include real-time (parameter collection during drilling), daily (daily well condition summaries), and monthly (reservoir dynamic analysis reports).
Document structures fall into two categories: structured fields and unstructured text.
Structured fields include well ID, well depth (unit: meter), porosity, permeability (unit: mD), and similar items.
Unstructured content includes on-site work logs, professional analysis documents, and supporting text for seismic interpretation images.
The length of individual data entries varies widely, ranging from a few lines of real-time logs to dozens of pages of comprehensive analysis reports.

## What Constraints These Characteristics Impose on Model Integration and Configuration
Data contains a large number of oil and gas-specific technical terms and standardized units. Confirm that the target model supports domain adaptation or can guide professional semantic understanding via prompts during model integration.
The wide span of data length requires flexible configuration of context and output tokens. This avoids wasting resources on short data or truncating long data.
Real-time updated data requires API timeout settings to adapt to data pull delays. This prevents task failure due to waiting timeouts.
The mixed structured and unstructured data format requires the model's tool call configuration to automatically adapt based on query type. This balances the needs of structured field parsing and natural language responses.
Some professional tasks require strict output formats. Adjust the temperature parameter to match task requirements. This avoids generating irrelevant or inaccurate professional conclusions.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–16000 token | The context length of combined oil and gas exploration reports and logs usually covers multiple sets of professional data. This range can fully carry the historical data required for single-well analysis |
| `maxTokens` | 2000–4000 token | For tasks such as reservoir analysis and drilling plan generation, professional responses need sufficient detail. This range covers typical output lengths |
| `quoteMaxToken` | 1000–2000 characters | The length of exploration logs and drilling data fragments to be referenced is moderate. This setting balances reference completeness and context occupancy |
| `toolChoice` | auto | Automatically select whether to call professional data parsing tools based on user queries. This adapts to the processing needs of mixed structured and unstructured data |
| `temperature` | 0.2–0.4 | Oil and gas field professional tasks require strict output. A lower temperature reduces irrelevant information generation and ensures result accuracy |
| `AIPROXY_API_ENDPOINT` | Fill in the exclusive access address provided by the service provider | Bind the access path of the corresponding model to ensure correct request routing |
| `AIPROXY_API_TOKEN` | Fill in the key generated by the service provider | Used for identity authentication to prevent unauthorized access to the model interface |

## Three Common Configuration Mistakes
- Symptom: Empty response returned after calling the model, with the log showing "model stream response is empty". Cause: `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is not configured correctly, causing the request to fail to reach the model server normally.
- Symptom: The curl test can normally obtain model responses, but there is no result when calling within FastGPT. Cause: In FastGPT v4.17.0, the streaming response format of the current model is not adapted, or the `maxContext` setting is too small, causing an exception after the context is truncated.
- Symptom: The professional model cannot be called correctly after upgrading the version. Cause: The default configuration of `temperature` or `toolChoice` has changed in the new version, and the parameters have not been recalibrated for oil and gas field professional tasks.

## How to Confirm Proper Configuration
- Execute a curl command to call the model interface, verify that basic connectivity and response format meet the adaptation requirements of FastGPT v4.17.0.
- Import a single set of oil and gas exploration log data, test whether the `maxContext` and `maxTokens` settings can fully carry the input and generate valid responses.
- Adjust the `temperature` parameter, observe whether the rigor of the generated results meets the needs of professional tasks.
- Check the validity period and permission scope of `AIPROXY_API_TOKEN`, ensure that no expiration or insufficient permission issues occur.

The values provided are common starting points and should be measured against the reader's own samples.
