# Internal Office and Employee Services for Oil and Gas Exploration and Development: Forms and Interactions

## What data for this category looks like
Data sources for oil and gas exploration and development include field exploration collection terminals, drilling platform automatic control systems, and ground production monitoring platforms. Data falls into two categories: real-time operating condition data and batch exploration reports. Update frequencies range from second-level (for drilling operating conditions) to day-level (for regional exploration reports). Document structures include fields such as well ID, logging depth, porosity, permeability, and fluid density. Units include meters, megapascals, cubic meters per day, grams per cubic centimeter, and others. Some documents are formatted exploration log PDFs or structured CSV files.

## What constraints do these characteristics impose on forms and interactions
Oil and gas exploration and development data includes real-time operating condition data and batch exploration reports. Single documents have multiple fields with professional units. Some data comes from batch exports of sensor terminals. This requires forms to support multi-field linkage validation, such as matching well IDs with corresponding depth ranges. Forms must include preset professional unit options to avoid input errors. Forms must support large file chunked uploads to accommodate batch exploration report submissions. Forms must include debounce handling for real-time data to prevent duplicate submissions. Forms must also distinguish update logic between temporary draft saving and formal submission, to fit the update rhythms of different data types.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `formInput` | 800–1200 characters | Accommodate single-paragraph text input length for exploration reports, avoid exceeding system default limits |
| `userSelect` | Top 10 optional values | Match common exploration parameter options for single wells, reduce user input costs |
| File upload limit | 1000 MB chunked upload | Accommodate upload requirements for batch seismic exploration data |
| Submission debounce duration | 30 seconds | Avoid duplicate submissions of real-time operating condition data |
| Form field validation | Preset by professional unit | Match field unit specifications for oil and gas exploration data |
| Draft saving interval | 600 seconds | Accommodate interruptions during long-form filling, avoid data loss |

## Three Common Misconfigurations
- Phenomenon: A prompt about exceeding character limits appears when submitting an exploration report form, making submission impossible. Cause: The character count configuration for `formInput` was not adjusted, and the system default smaller limit value was used.
- Phenomenon: Professional unit options or long text content are lost after the published form page is scaled. Cause: The form component did not have fixed layout adaptation enabled, or minimum width constraints were not set.
- Phenomenon: Multiple selections are not available when selecting an associated knowledge base, or the specified exploration data knowledge base cannot be matched. Cause: The selection rules for knowledge base variables were not configured correctly, and the multi-knowledge base selection function was not enabled.

## How to Confirm Proper Configuration
- Upload an exploration data CSV file under 1000 MB, confirm that the chunked upload function triggers normally, and no upload failure prompt appears.
- Fill in the well ID field of the form, confirm that linkage validation for the corresponding depth range triggers normally, and non-standard input is blocked.
- Scale the form page to different proportions, confirm that all fields, options and text content display normally, with no loss.
- After submitting the test form, check the backend logs of FastGPT v4.17.0, confirm that the submitted character count does not exceed the preset `formInput` limit value.
