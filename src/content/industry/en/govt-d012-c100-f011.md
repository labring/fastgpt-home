# Internal Office and Employee Services for Oilfield Engineering Services: Forms and Interactions

## What data for this category looks like
Data for oilfield engineering services mainly comes from on-site construction logs, equipment inspection ledgers, material requisition documents, and attendance records of on-site workers. Data updates follow two main rhythms: real-time submission after completion of a single job, and daily bulk aggregation. A single document usually includes fields such as job section number, equipment serial number, job duration, material consumption volume, and personnel attendance information. Most fields are structured numerical values or fixed enumeration items, with units including cubic meters, hours, sets, person-times, and other engineering standard units.

## What constraints these characteristics impose on forms and interactions
This category has many structured fields and enumeration items, which requires forms to support preset fixed enumeration options to avoid inconsistent formats caused by free input. The demand for real-time submission of on-site job data requires forms to support offline cache submission, with sync upload after network recovery. For multi-section job scenarios, forms need to support section-level linked selection to avoid cross-section data confusion. Some material consumption volumes need to match unit verification rules associated with equipment models, so automatic unit matching logic must be embedded in forms to reduce input errors.

| Offline Cache Configuration | Cache duration of 72 hours, maximum cached data size of 500 MB | Network signals are unstable at oilfield sites, so support for long-term offline data storage is required |

## Three common configuration mistakes
- Form submission fails to sync files to backend storage, with the prompt "unsupported file format". This occurs when CAD and construction log PDF formats commonly used for oilfield engineering services are not added to the file upload settings, and only general formats are enabled.
- Knowledge base references cannot be selected in the code run node, and the variable dropdown list is empty. This occurs when the knowledge base data source is not bound in the global configuration first, or trigger parameters associated with the knowledge base are not configured in the form.
- A prompt "no knowledge base selected" appears after entering a query, even though the corresponding knowledge base is bound in the chat window. This occurs when the knowledge base call permissions are not bound to the current form's interaction session, and the session context is not associated with the specified knowledge base.

## How to verify correct configuration
- Upload a CAD construction drawing commonly used for oilfield engineering services, confirm that it can be submitted normally and stored to the specified location.
- Select a job section, confirm that the equipment model dropdown options automatically update to the available models for the corresponding section.
- Disconnect the network, fill in form data, restore network connectivity, and confirm that the data is automatically synced to the backend system.
- Trigger the code run node, confirm that bound knowledge base reference options appear in the dropdown list.
