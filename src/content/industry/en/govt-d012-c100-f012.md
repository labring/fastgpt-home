# Internal Office and Employee Services for Oilfield Engineering Services: Deployment and Upgrade

## What the data for this category looks like
Oilfield engineering service data mainly comes from on-site operation terminals, equipment sensors, employee inspection logs, project progress documents and external cooperation records. Data update rhythms are divided into three categories: real-time (such as downhole operation condition data), daily (such as team attendance and material consumption records), and weekly (such as project settlement logs). Single documents are mostly structured tables or semi-structured operation reports, containing fields such as operation number, equipment ID, inspection point, working condition parameters and operation duration. Most working condition parameters carry physical units, such as pressure (MPa), temperature (℃), and displacement (m³/h).

## What constraints these characteristics impose on deployment and upgrade
Multi-source heterogeneous data of oilfield engineering services, including real-time sensor streams and offline structured logs, requires deployment to support both batch data import and real-time data stream access. Therefore, resource reservation for containerized deployment must be higher than that of general office scenarios. The characteristic that data fields carry physical units requires retaining unit verification logic for parameter parsing during upgrades, to avoid unit conversion errors caused by version iterations. The offline data synchronization requirement of on-site operation scenarios requires configuring an edge node caching mechanism during deployment, to ensure temporary data storage and subsequent synchronization when the network is interrupted. The permission layering requirement for cross-regional team operations requires compatibility with the migration of the original role system during upgrades, to avoid permission configuration failure. The FastGPT v4.17.0 deployment package has optimized adaptation logic for such scenarios, but configuration adjustments must still be made based on on-site data characteristics.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300` | Oilfield engineering service data includes real-time sensor streams and offline logs, requiring support for high-concurrency database connections |
| `MONGODB_URI` | Replica set address mounted to local SSD storage | Operation reports and inspection records are mostly unstructured documents; replica sets ensure data read and write stability |
| `REDIS_URL` | Cluster address configured with 10 GB memory | Used to cache real-time working condition data and employee session context, reducing database query pressure |
| `STORAGE_S3_ENDPOINT` | Endpoint address adapted to oilfield intranet object storage | Video and log files generated by on-site operations must be stored in intranet compliant storage media |
| `FE_DOMAIN` | Secondary domain name of the oilfield internal office system | Ensures internal employees access the application only through the intranet domain name, complying with information security requirements |

## Three common mistakes
- The symptom is that the basic chart plugin outputs "none" after inputting correct parameters. The cause is that `FILE_TOKEN_KEY` is not configured, causing the plugin to fail to generate a valid chart access token.
- The symptom is that a network error is prompted when deleting the application after deploying via Ubuntu + Docker. The cause is that the database permission configured in `PG_URL` is insufficient to perform the database write operation for application deletion.
- The symptom is that the system settings - file input function is unresponsive. The cause is that `STORAGE_S3_ENDPOINT` is not configured with the intranet storage endpoint, causing file upload requests to fail to reach the compliant storage media.

## How to confirm the configuration is correct
- Run `docker logs fastgpt` to view the startup log, confirm that there are no error reports for database connections, Redis connections and storage endpoints.
- Upload a test file conforming to the oilfield operation report format, confirm that the file can be uploaded normally and an access link is generated.
- Create a test application containing a basic chart plugin, input valid working condition parameters, confirm that the plugin returns a valid chart URL.
- Attempt to delete the test application, confirm that the operation can be completed normally without network errors.
