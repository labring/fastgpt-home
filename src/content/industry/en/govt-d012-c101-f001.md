# Internal Office and Employee Services for Port and Shipping: HTTP Interfaces and External Systems

## What the data for this category looks like
Port and shipping internal office and employee service data primarily comes from terminal operation management systems, crew scheduling systems, vessel berthing and unberthing management platforms, and port logistics scheduling systems.
There are two data update cycles: real-time operation data is synchronized every 10 minutes. Personnel scheduling and qualification data is updated daily.
Data is stored in structured JSON format. Core fields include vessel IMO number, berth number, operation duration, crew employee ID, and shift type. Their corresponding data types are character string, numeric, minutes, numeric, and fixed optional enumeration values respectively.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
The synchronization frequency of real-time operation data must match the 10-minute update cycle. Interface request intervals should not be too long. Otherwise, latest berthing, unberthing, and operation status information cannot be obtained.
Parsing of structured fields must strictly correspond to preset field names. Otherwise, core business information such as vessel numbers and operation duration cannot be extracted.
Enumeration shift fields must limit the range of optional values. This prevents parsing failures caused by unexpected content returned by interfaces.
Internal port systems deployed on intranets need to be configured with trusted access policies. Identity verification must use dedicated tokens to prevent unauthorized access.

## How to configure settings
The following configurations are written based on the interface integration module of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `Authorization` | `Bearer Port Intranet Dedicated Verification Token` | Matches the identity verification rules of internal port systems to ensure access legitimacy |
| `variables` | `{"shipImo": "", "berthId": "", "workDate": ""}` | Passes query parameters such as vessel IMO number, berth number, and operation date to adapt to structured data query logic |
| `responseData` | `Only retain core business fields` | Reduces returned content to improve subsequent data processing efficiency |
| Timeout Setting | `600 seconds` | Adapts to the response delay of intranet port systems to avoid request timeouts caused by network fluctuations |
| Pagination Parameters | `100 entries per page` | Adapts to the thousands of operation data entries per batch to avoid excessive returned interface data |

## Three common configuration mistakes
- An interface returns a 403 Forbidden error, or the intranet system returns an identity verification failure prompt. This occurs when the port intranet dedicated `Authorization` token is not used, or the token configuration is incorrect, causing the internal system to reject access.
- Business fields returned after calling the interface are empty, or a prompt for no matching data appears. This happens when the query parameters passed in `variables` do not match the field names of the internal system, so valid data cannot be matched.
- A 404 Not Found error is returned when testing the interface, or a prompt indicates the interface address does not exist. This is caused by incorrect configuration of the internal system's interface address, or the intranet domain name not being added to the access whitelist.

## How to confirm the configuration is complete
- Manually call the configured HTTP interface to check if the returned `responseData` contains expected business fields.
- View FastGPT's interface call logs to confirm that the `Authorization` parameter is correctly carried, with no identity verification failure prompts.
- Simulate the scenario of employees querying operation data to check if the number of returned results matches the preset pagination configuration.
- Verify that the interface response duration does not exceed the preset timeout threshold, with no timeout errors.
