# Internal Office and Employee Services for Port and Shipping: Tool Calling and Plugins

## What the data for this category looks like
Data for internal office and employee services in port and shipping comes primarily from port operation dispatching systems, vessel dynamic management platforms, crew attendance systems, and internal OA office systems. Update frequencies vary significantly: real-time vessel location and berth occupancy status are updated every second. Crew attendance and monthly performance data are updated daily. Voyage operation documents are updated as each individual document is generated.

Document fields include voyage number, berth number, crew ID, cargo tonnage, and operation duration. Units include industry-specific measures such as tons, meters, hours, and person-times.

## What constraints these characteristics impose on tool calling and plugins
The varied update frequencies, specialized fields, and unique units of port and shipping data create multiple constraints for tool calling and plugin configuration.

Real-time vessel dynamic data requires tool calling response windows to match its update frequency, to avoid returning outdated data. Documents with multi-dimensional fields need plugins configured with precise parameter mapping rules, to prevent misalignment of core fields such as voyage number and cargo tonnage. Industry-specific units require plugins to include built-in basic conversion logic, to avoid unit mismatches in returned results. Voyage operation documents generated per order require plugins to support precise query conditions using voyage numbers and operation order numbers, to improve calling efficiency.

## How to set the configuration
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Tool call timeout | `30–60 seconds` | Matches the update frequency of real-time port data, avoids blocking internal office workflows |
| Parameter mapping rules | Use voyage number and berth number as core association fields | Core identifiers for port operation data are voyage number and berth number, enabling precise matching of query conditions |
| Concurrent call limit | `5–8 concurrent` | Prevents high-frequency calls from overwhelming internal port operation systems |
| `toolChoice` | `auto` | Adapts to multi-type tool calling scenarios for ports, automatically matches corresponding plugins |
| functionCall trigger condition | Trigger when the query includes voyage number or operation order number | Precisely trigger tool calls, reduces invalid requests |
| Unit conversion switch | Enabled | Unifies the unit format of returned data, meets the display requirements of internal office systems |

## Three common configuration mistakes
- Symptom: Returned results after calling a tool do not include the target data's dataId field. Cause: The association extraction logic for dataId was not configured in the parameter mapping rules, so the tool did not return this identifying field.
- Symptom: The plugin cannot enable the PDF enhanced parsing function. Cause: The document parsing enhancement switch was not turned on in the plugin configuration, or the PDF file to be parsed is encrypted or damaged.
- Symptom: A 504 timeout status code appears when calling the workflow API externally. Cause: The tool call timeout was set too long, exceeding the response tolerance threshold of the internal port operation system.

## How to confirm the configuration is correct
- Initiate a test query that includes a voyage number, verify if the expected dataId field is included in the returned results.
- Upload a port operation PDF document, confirm if the plugin enables enhanced parsing normally and returns structured data.
- Conduct multiple concurrent test calls, observe the resource usage of the internal system, and adjust the concurrent call limit to a reasonable range.
- Verify that the units of the returned data match the display requirements of the internal office system, confirming that the unit conversion switch is active.
