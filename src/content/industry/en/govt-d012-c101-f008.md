# Internal Office and Employee Services for Port and Shipping: Document Parsing and Chunking
This document is written based on FastGPT v4.17.0.

## What the data for this category looks like
Internal office documents for port and shipping operations mainly originate from vessel scheduling systems, cargo handling ledgers, crew management systems, berth allocation platforms, and operation archive libraries. Update cycles include real-time (such as berthing scheduling logs), daily updates (such as cargo packing lists), weekly updates (such as crew schedules), and monthly updates (such as annual maintenance reports). Document types include structured tables, long-form professional reports, and mixed documents with vector graphics. Fields and units include unique identifiers such as voyage number, container number, ton, TEU, and berth number. No unified fixed layout format exists across these documents.

## What constraints these characteristics impose on document parsing and chunking
Structured table documents break the corresponding relationship between container numbers, weights, and destinations when split as regular paragraphs. Original table structures must be retained during parsing. Long-form professional reports contain numerous shipping-specific terms. Chunking must avoid truncating these term combinations. Real-time updated scheduling documents require fast parsing, otherwise subsequent office workflows are disrupted. Vector graphics and annotated images in mixed documents must retain their original positions and descriptions, otherwise job scene information is lost. Large-volume archive document collections consume more parsing resources. Requirements for large file upload and parsing duration must be accommodated.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | `800–1200 characters` | Balances semantic integrity between structured short fields in port documents and long-form professional reports, and adapts to different types of business documents |
| `chunkSplitter` | Split by paragraph + heading hierarchy | Adapts to the multi-chapter, titled layout structure of port documents, and retains document logical hierarchy |
| `customPdfParse` | Enabled | Retains tables, vector annotations, and professional layouts in port PDF documents, and avoids post-parsing format confusion |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Adapts to parsing duration of large vessel maintenance reports and berthing scheduling collections with more than 50 pages, and prevents task timeout failures mid-process |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Supports upload of multi-document collections for port operation archives, and meets parsing requirements for batch job documents |
| `chunkSettingMode` | Manual configuration | Adapts to the large structural differences of port documents, and allows adjustment of chunking rules for different document types |

## Three common misconfigurations
- After importing a Word-format crew schedule, the parsed Markdown content only retains local relative paths for image links, and does not bind the intranet domain name. This occurs because custom parsing image path replacement rules are not configured, and only the local path information from the original document is retained.
- When uploading a large vessel maintenance report, the post-parsing chunking results truncate professional term combinations such as "main engine lubricating oil pressure" and "speed calibration value". This occurs because the `chunkSize` setting is too small, and does not meet the semantic integrity requirements for long professional term paragraphs.
- When accessing the parsing service page from other devices on the local area network, a `net::ERR_INCOMP`-class request error occurs. This occurs because the service is only started bound to the local IP address, and no intranet domain name is configured. Request parameters are incomplete during cross-device access.

## How to confirm the configuration is correct
- Upload a typical port packing list PDF. Check if the parsed document retains the table structure and the corresponding relationship between fields such as container numbers and weights. Adjust the `chunkSplitter` configuration based on the results.
- Upload a vessel maintenance report with more than 30 pages. Check if the parsing task completes within the preset duration. Adjust the value of `PARSE_FILE_TIMEOUT_SECONDS` based on actual elapsed time.
- Import a Word document with a berth layout diagram. Check if image links include the intranet domain name. Configure custom parsing path replacement rules as needed.
- Adjust the value of `chunkSize`. Verify whether the chunking results truncate professional terms or retain complete paragraph semantics. Adjust the granularity based on the structure of business documents.

The values listed above are common starting points. They should be evaluated against the reader's own samples.
