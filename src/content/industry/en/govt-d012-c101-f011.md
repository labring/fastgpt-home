# Internal Office and Employee Services for Port and Shipping: Forms and Interactions

## What This Category's Data Looks Like
Data sources for internal office and employee services in port and shipping include terminal operation systems, crew scheduling platforms, vessel dispatch systems, and material management ledgers. Data update frequencies fall into three categories: real-time (berthing, loading/unloading progress), daily (scheduling, inventory changes), and monthly (cost accounting). Document structures include structured work orders (containing vessel name, berth number, cargo type, tonnage), scheduling sheets (shift, position, number of on-duty personnel), and material ledgers (material code, inventory quantity, issue time). Some documents contain long-text work logs, with fields that use dedicated units such as tons, hours, and berth numbers.

## Constraints for Forms and Interactions
Real-time updated data requires forms to support rapid synchronization with data sources, and avoid using static data cached for extended periods. Fields sourced from multiple systems need forms to perform format verification and mapping, to ensure fields such as berth numbers and loading/unloading tonnage comply with port business specifications. When long-text work logs are used as input, forms must adapt to conventional single-paragraph text lengths, and avoid exceeding processing limits. Operators in different roles require access to different visible form fields, to implement permission-isolated interaction designs.

## Configuration Guidelines
This configuration reference is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| Form input component | `formInput` type | Adapts to structured field entry for port work orders, reduces manual input errors |
| Option selection component | `userSelect` type | Used to preset fixed options such as vessels and berths, matches standardized data from port business operations |
| Context window | 800–1200 characters | Adapts to conventional single-paragraph text lengths for port work logs |
| Number of results displayed | Top 5 entries | Matches the scale of associated data for a single batch of port operations |
| Interaction timeout | 60 seconds | Adapts to the daily operation response rhythm of on-site port operators |
| Variable trigger timing | After form submission | Matches the node trigger logic of port work processes |

## Three Common Configuration Mistakes
- Symptom: Knowledge base associated fields are empty after form submission. Cause: The `userSelect` component was not used to preset knowledge base options related to port business, resulting in users being unable to accurately select the corresponding knowledge base.
- Symptom: Global variables are not fully assigned. Cause: The output of the `formInput` component was not used as the data source for variable assignment, and the logic linking form submission and variable triggering was not bound.
- Symptom: Stream mode interaction returns incomplete results. Cause: A reasonable interaction timeout was not set, resulting in timeout interruption during real-time stream reception.

## How to Verify Successful Configuration
- Open the form editor, check that the `formInput` and `userSelect` components cover the core fields of port operations.
- Submit a test form, verify that the selected knowledge base can load associated data for the corresponding vessel or berth.
- Trigger stream mode interaction, check that all returned result fragments can be received completely.
- View the global variables panel after submitting the form, confirm that variables have been assigned as configured.
