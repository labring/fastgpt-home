# Internal Office and Employee Services for Port and Shipping: Deployment and Upgrade

## What Data for This Category Looks Like
Port and shipping internal office and employee services data sources cover vessel dynamic systems, berth scheduling systems, crew management systems, work order systems, and material inventory ledger systems. Data update rhythms fall into three categories: real-time vessel dynamics updated every 10 seconds, crew schedules and work orders generated in real time, and inventory ledgers and monthly reports updated daily.

The document structure includes structured relational data and unstructured content. Structured data fields include IMO number, berth number, draft depth (unit: meters), work duration (unit: hours), crew employee ID, and similar fields. Unstructured content includes on-site work voice transcription records, scanned paper work orders, and similar materials.

## Constraints for Deployment and Upgrade
Real-time scheduling data for port and shipping operations requires the system to support high concurrency and low-latency responses. The deployment phase must prioritize high-availability configuration for databases and cache services.

Multi-source heterogeneous data access requires the system to adapt to different data formats. The upgrade phase must avoid damaging existing data parsing logic.

Intranet deployment restricts external network access. Intranet-specific storage and domain names must be configured.

Port operations run non-stop. Upgrade processes must use rolling update strategies to avoid interrupting real-time scheduling workflows.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:portpass@mongo1:27017,mongo2:27017,mongo3:27017/admin?replicaSet=port-rs` | Real-time port operation data requires a replica set to ensure high availability, preventing data loss and service interruptions |
| `REDIS_URL` | `redis://:redispass@redis-host:6379/0`, connection pool size calibrated via actual testing | High-frequency query of port operation status requires Redis caching to improve response speed; intranet deployment requires a dedicated access address |
| `DB_MAX_LINK` | `200` | Covers concurrent work order and vessel dynamic query requests, preventing service lag caused by exhausted connections |
| `STORAGE_S3_ENDPOINT` | `http://s3-internal.port.com:9000` | Most port operation files are intranet-sensitive content; intranet object storage must be used to ensure data security |
| `FE_DOMAIN` | `https://internal-port-fastgpt.port.com` | Internal office systems must be bound to intranet domain names to restrict external access and protect internal data security |
| `ROOT_KEY` | Random string of at least 32 characters | Ensures access security for backend management interfaces, preventing unauthorized operations |

## Three Common Misconfigurations
- Phenomenon: After offline deployment, the text content extraction function returns empty results, and the interface returns status code 400. Cause: The offline environment does not load local vector model dependency packages, and `STORAGE_S3_ENDPOINT` is not configured to point to intranet file storage, resulting in failure to read pending work documents.
- Phenomenon: Searching for berth operation data occasionally returns 0 results. Cause: The `DB_MAX_LINK` configuration value is too low, exhausting the database connection pool and failing to pull the latest operation data in a timely manner.
- Phenomenon: After modifying code inside a container and restarting the service, configurations do not take effect and code reverts to its initial state. Cause: Modified code is not mounted to the container's persistent directory, and the container image reverts to its initial built state after restart.

## How to Verify Proper Configuration
- Run the FastGPT built-in connectivity test script to verify the connection status of `MONGODB_URI` and `REDIS_URL`, confirming that a connection successful prompt is returned.
- Upload a structured CSV file of port berth operation data to trigger the text extraction workflow, confirming that extracted fields include preset fields such as berth number and work duration.
- Access the intranet address bound to `FE_DOMAIN`, log in to the backend management interface, and complete verification using `ROOT_KEY`, confirming that knowledge bases and data sources can be created normally.
- Initiate 100 concurrent operation data query requests, observe the system monitoring dashboard, confirming that database connection pool usage does not exceed the configured `DB_MAX_LINK` value.
