# Internal Office and Employee Services for Refinery and Petrochemical Production: Vector Models and Indexes

## Data Characteristics of This Category
Data sources primarily include device operation and maintenance logs, process operation specifications, safety inspection records, employee training documents, attendance and scheduling systems, and similar resources. Update rhythms vary significantly: device operation and maintenance logs are updated in real time or near real time; process operation specifications and safety standards are updated quarterly; employee training documents and attendance data are updated daily or monthly.
Data includes structured and unstructured types. Structured data contains fields such as device ID, operating temperature, and pressure, with units mostly MPa and ℃. Unstructured data mostly consists of long-text inspection reports and transcribed training slides, with no fixed field formats.

## Constraints on Vector Models and Indexing
Mixed structured and unstructured data requires separate processing of structured fields and unstructured text during vector modeling to prevent semantic confusion. Real-time device logs require incremental indexing mechanisms; full indexing frequencies cannot match their update speed. Long-text process specifications and inspection reports need appropriate chunking strategies to preserve complete semantic units. Structured fields with clear units must retain unit information during embedding, otherwise similarity matching will produce incorrect associations due to missing units. Enumeration fields such as safety levels must be embedded with contextual information to avoid matching deviations caused by isolated enumeration values.

## Configuration Guidelines
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | Matches the average semantic unit length of long-text documents for refinery and petrochemical production, avoids breaking context associations with overly short chunks |
| Overlap Length | 100–150 characters | Retains overlapping information between adjacent chunks to resolve semantic fragmentation after long-text chunking |
| `maxToken` | 8192 token | Adapts to the maximum input limit of the text-embedding-v3 model, matches the average length of refinery and petrochemical production documents |
| Similarity Threshold | 0.72–0.80 | Meets high-precision matching requirements for refinery device logs and safety specifications, reduces false match probability |
| Single Search Limit | Top 10 results | Focuses on core needs of internal office retrieval, avoids redundant results interfering with employee queries |
| `defaultToken` | Calibrated via actual testing | Adapts to token allocation quotas for different deployment environments, ensures model call stability |

## Three Common Configuration Errors
- Phenomenon: A 503 error indicating "No available channels under the current default group" is returned when calling text-embedding-v3. The cause is failure to configure channel permissions for the corresponding model, or exhausted resource quotas for the default group.
- Phenomenon: No index configuration edit button appears on the retrieval results page. Index parameters must be adjusted by entering the knowledge base content page. The cause is an interface adjustment in FastGPT v4.17.0: the retrieval results page only displays query results, and the configuration entry has been moved to the index settings module in knowledge base management.
- Phenomenon: The document parsing and index enhancement functions cannot be enabled. The cause is that the current deployment is the open-source version; this function is only supported in the commercial version.

## How to Verify Successful Configuration
- Upload a typical refinery device log document, and check whether chunked text fragments meet preset chunk length and overlap length requirements.
- Submit a retrieval request for process specifications or device logs, and verify that the similarity scores of returned results fall within the preset threshold interval.
- Submit a real-time generated device operation and maintenance log, and confirm that the index is automatically synchronized and updated without manually triggering a full rebuild.
- View model call logs, and confirm that the text-embedding-v3 call channel is normal, with no 503-type error messages.
