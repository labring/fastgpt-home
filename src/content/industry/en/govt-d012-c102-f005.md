# Internal Office and Employee Services for Refinery and Chemical Production: Tool Calling and Plugins

Reference only; verify against the target FastGPT release and deployment documentation.

## What this category of data looks like
Data sources for refinery and chemical production include real-time monitoring databases, manufacturing execution systems (MES), equipment operation and maintenance ledgers, and employee patrol record systems. Data update frequencies cover minute-level real-time sampling data, daily summarized production reports, and monthly updated equipment archives. Most documents use structured fields, including equipment number, operating temperature, pressure value, work order number, patrol time, processing status, and more. Units include degrees Celsius, megapascals, hours, counts, and others. Some unstructured data consists of scanned handwritten patrol notes.

## What constraints these characteristics impose on tool calling and plugins
The minute-level update of real-time monitoring data requires that tool calling response delay be controlled within a reasonable range. Otherwise, rapid response to abnormal alerts cannot be supported. The large number of structured fields with dedicated units requires that tool calling parameters strictly match business field names and unit formats. Parameter mismatches will cause query failures. Monthly updated equipment archives have a large data volume. Tool calling must limit the number of items returned per single call to prevent interface timeouts caused by data overload. Employee patrol records are bound to employee IDs via work order data. Tool calling must associate corresponding business identifiers to ensure returned data aligns with permission scopes.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the need for parallel multi-tool calling in refinery and chemical production scenarios, automatically matches different business tools such as production data query and work order processing |
| Timeout setting | 30 seconds | Matches the response requirements of real-time refinery production data, avoids delaying production alert processing due to excessive latency |
| Number of items returned per single call | First 20 items | Limits returned data volume to prevent interface overload, aligns with the conventional data scale of single queries in refinery and chemical business |
| Tool calling retry count | 2 times | Addresses occasional network fluctuations in refinery and chemical systems, prevents business interruptions caused by single call failures |
| Maximum context length | 8000 token | Adapts to the conversation requirement of multi-field concatenation in refinery and chemical business, ensures complete transmission of tool calling parameters |
| `functionCall` | Specified by tool ID | When calling specific refinery and chemical business tools, directly specify the unique identifier of the target tool |

## Three common configuration errors
- Scenario: A 429 status code is returned when tool calling concurrency is high, and production data cannot be obtained normally. Cause: No reasonable tool calling concurrency limits and retry strategies are set, leading to frequent interface calls to the refinery and chemical production system triggering rate limiting.
- Scenario: Tool calling returns empty query results, and device parameter information cannot be matched. Cause: Business field names and unit formats are not strictly matched. For example, pressure parameters are not submitted using megapascals as the unit, causing the system to fail to recognize the query condition.
- Scenario: Tools called via a login-free window cannot obtain permission data for the corresponding employee. Cause: No user identifier transmission logic is configured for the login-free channel. The user identity from the channel source is not bound to the tool calling request, causing returned data to exceed permission scopes.

## How to verify successful configuration
- Initiate a single tool calling request, check whether the returned fields and units comply with refinery and chemical business specifications.
- Simulate a multi-concurrency calling scenario, observe whether interface return status codes align with preset rate limiting rules.
- After configuring the login-free user identifier transmission, initiate a call and check whether returned data matches the permission scope of the corresponding employee.
- Check system logs to confirm that the configured `toolChoice` or `functionCall` parameter values are correctly carried in tool calling requests.

The values provided here are common starting points and should be measured against the reader's own samples.
