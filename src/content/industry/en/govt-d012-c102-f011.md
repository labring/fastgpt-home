# Internal Office and Employee Services for Refinery and Chemical Production: Forms and Interactions

## What data for this category looks like
Business data for refinery and chemical production comes from real-time production databases, equipment inspection systems, equipment ledger management systems, and work order systems. Data update frequencies cover three categories: real-time (such as pipeline pressure, tank temperature and other inspection parameters), daily (such as equipment runtime statistics), and weekly (such as maintenance plans). Each document is based on a single business record, and includes fields such as unique equipment ID, collection time, parameter value, abnormality flag, and handler. Parameter fields use industry-specific units: pressure in MPa, temperature in ℃, flow rate in m³/h.

## What constraints these characteristics impose on the forms and interactions link
High-frequency updates of real-time parameters require form controls to pull the latest data dynamically, to avoid delays from manual entry. Industry-specific units and value ranges require form configurations to preset validation rules, to block non-compliant input. Scattered data from multiple sources requires forms to support binding data sources from different systems, mapping corresponding fields directly to form input items. Complex business processes (such as inspection work orders, equipment maintenance) require forms to support nested sub-items and conditional display, to adapt to interaction logic across different scenarios.

## How to set configurations
| Configuration Item | Suggested Approach | Basis for This Approach |
| --- | --- | --- |
| Form input controls | Map to business fields, e.g., equipment ID, inspection pressure value | Match the exclusive data fields and units of refinery and chemical production |
| Single-select and multi-select controls | Bind system data sources, preset enumerated values like equipment type, work order status | Adapt to fixed and frequently updated business enumerated items |
| Field validation rules | Pressure range 0–10 MPa, temperature range 0–500 ℃, mark required fields | Align with conventional value ranges of industry parameters |
| Submission trigger timing | Auto-validate 3 seconds after form completion | Avoid invalid submissions, adapt to the update rhythm of real-time data |
| `formInput` load timeout | 10 seconds | Adapt to network delays for real-time data pulling |
| `userSelect` data source refresh | Every 10 seconds | Ensure real-time performance of inspection parameters |

## Three common mistakes
- Phenomenon: Single-select and multi-select controls only display fixed static options, and cannot update dynamically with the equipment list. Cause: Did not use `userSelect` to bind system data sources, only manually entered fixed options, and did not adapt to dynamic changes in equipment and work order types in refinery and chemical production.
- Phenomenon: Data is not synchronized to the production system after form submission, and some fields are empty or have incorrect formats. Cause: Did not correctly map form fields to API parameters of the production system, and did not configure post-submission callback validation.
- Phenomenon: Knowledge base search results cannot match the target equipment ID entered in the form. Cause: Did not enable the variable reference function of `formInput`, and did not pass form fields as search parameters, resulting in search scope that cannot cover data of the target equipment.

## How to confirm configurations are complete
- Open the form editor in FastGPT v4.17.0, select the form for the corresponding business scenario, and check whether input controls are mapped to preset exclusive fields such as equipment ID and pressure value.
- Enter test parameters, trigger single-select and multi-select controls, confirm that options update dynamically with bound data sources, and validation rules block input outside the preset range.
- Submit the test form, check background logs to confirm that data is synchronized to the corresponding production system fields, with no format errors.
- Call the variable reference function, confirm that form fields can be correctly called by knowledge base search, and return relevant data matching the target equipment.
