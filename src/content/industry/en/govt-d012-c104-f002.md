# Internal Office and Employee Services for Coal Chemical Industry: Vector Models and Indexes

## What data looks like for this category
The data for internal office and employee services in the coal chemical industry primarily comes from enterprise OA systems, shift operation logs, safety operation procedures, employee training manuals, equipment maintenance records, and meeting minutes. Update cycles cover real-time (shift daily reports, equipment inspection records), scheduled (safety procedure revisions, employee manual updates), and on-demand (special meeting minutes). Documents include long texts (full process procedures), short texts (inspection items), and semi-structured data (equipment parameters with units such as pressure and temperature). Most fields include affiliated workshop, record time, equipment number, safety level, and other attributes. Professional terms focus on production links such as gasification, purification, and synthesis.

## What constraints these characteristics impose on the vector model and index workflow
The multi-type characteristics of coal chemical industry data impose multiple constraints on the vector model and index workflow. Documents with long texts and dense professional terms require chunking strategies that balance term integrity and contextual coherence, to avoid semantic loss from splitting professional phrases. For semi-structured data with numerical and unit fields, additional field-level index rules must be configured to ensure accurate matching for parameter-based queries. Real-time updated inspection records require support for incremental indexing to reduce duplicate computation overhead. Scheduled updates to procedure documents require matching resource quotas for full indexing. The wide range of document lengths also requires the model’s token processing capability to adapt to a broader scope.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Ensures coherence of professional terms in long coal chemical industry documents such as full process procedures, and prevents phrases like gasification and purification from being split |
| Overlap Length | 100–150 characters | Retains contextual connections across chunks, and prevents equipment operation procedures and process steps from being truncated |
| `maxToken` | 8192 | Adapts to the maximum input token limit of Qwen3-Embedding-8B, and matches the average length of coal chemical industry documents |
| `defaultToken` | 4096 | Configures the default token quota for general indexing, balancing single-document indexing speed and server resource usage |
| Similarity Threshold | 0.72–0.78 | Distinguishes semantic similarity of coal chemical industry professional terms, and prevents mismatched operation parameters for different equipment |
| Single Search Limit | Top 8 entries | Covers the number of results for frequent queries such as shift daily reports and equipment logs, and ensures comprehensive retrieval |

## Three Common Mistakes
- File status remains "Indexing" and does not update to "Completed" within a reasonable time frame. The cause is that the configured `maxToken` value is smaller than the total token count of the target document, resulting in chunk processing timeout or failure to complete vectorization.
- After adding the Qwen3-Embedding-8B model, the configuration of the original model with the same name is overwritten. The cause is that no unique identifier is added for different deployment instances in the model management interface, and the model name is directly reused as the configuration key.
- A large number of irrelevant equipment parameter entries appear in retrieval results. The cause is that the similarity threshold is set too low, matching document fragments with similar semantics but belonging to different production scenarios.
