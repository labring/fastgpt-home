# Internal Office and Employee Services for Coal Chemical Industry: Forms and Interactions

## What the Data for This Category Looks Like
Coal chemical industry internal office and employee service data primarily originates from production inspection logs, equipment maintenance records, employee attendance systems, and office approval workflow systems. Two update rhythms apply:
Production-related inspection and maintenance data updates in real time or hourly based on inspection frequency. Attendance and office approval data updates immediately after submission or workflow trigger.
Most document structures are structured forms, containing fields such as equipment ID, inspection point, pressure value, temperature value, exception level, processing duration, and more. Common field units include MPa, ℃, hours, person-times, and others.

## What Constraints Do These Characteristics Impose on Forms and Interactions
Coal chemical industry forms have many structured fields with specialized units. Form interactions must preset fixed fields and unit options to avoid manual input errors.
Real-time updated production data requires form interactions to support immediate synchronous verification, preventing entry of outdated data.
Multi-department collaborative approval workflows require forms to support role permission division, where different positions can only view or edit corresponding fields.
Some equipment parameter value ranges follow clear industry specifications. Form interactions must include built-in value range verification, and provide clear prompts when values exceed the range.
Long-text exception description fields must support paragraph input and format verification to adapt to on-site inspection recording habits.

## Three Common Misconfigurations
- Symptom: A "Cannot convert undefined or null to object" error pops up when running a workflow. Cause: No validation rules configured for required fields in `formInput`, empty submissions fail to generate valid interaction objects.
- Symptom: No prompt appears after entering a value in the equipment pressure field of the form. Cause: No form value verification rules configured, so values exceeding industry specifications are not blocked.
- Symptom: Regular employee accounts can modify all form field content. Cause: No job permission scope configured via `userSelect`, role permission division is missing.

## How to Verify Successful Configuration
- Fill all required form fields, submit the form, and confirm that corresponding validation prompts are triggered to verify the validation rules for `formInput` are active.
- Switch test accounts with different job positions, check the editable form field range, and confirm that the permission configuration for `userSelect` is correct.
- Enter equipment parameter values exceeding industry specifications, and confirm that a validation prompt pops up to verify field validation rules are configured.
- Fill in long-text exception description content, check the input length limit, and confirm that the long text input configuration is active.
