# Internal Office and Employee Services for Coal Transportation and Sales: Multi-turn Dialogue and Prompt Engineering

## What this type of business data looks like
Coal transportation and sales business data covers internal transportation and sales management systems, weighbridge tickets, railway/road shipment dispatch logs, purchase and sales contract ledgers, and monthly settlement reports. Data updates are divided into three categories: real-time updates (per-vehicle weighing, shipment confirmation), daily updates (same-day revenue, inventory statistics), and monthly updates (full-cycle settlement data). A single business document typically includes fields such as contract number, shipment origin, vehicle number, actual shipped tonnage, shipment time, settlement unit price, and total amount. Units include tons, yuan, vehicle trips, and vehicle trip sequence numbers.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The share of real-time business data in coal transportation and sales is high. Multi-turn dialogue must limit the context window length to prevent result deviations caused by loading expired weighing or shipment data. There are many business fields with differing units, so prompts must clearly specify the fields to extract and their corresponding units to avoid confusion between actual shipped tonnage and settlement amount. The update rhythm of monthly settlement data differs from that of real-time vehicle trip data, so multi-turn dialogue must differentiate prompt logic between historical queries and real-time queries to prevent calling incorrect data ranges. Additionally, the unique identifier for per-vehicle data (such as vehicle number plus shipment time) must be passed accurately in dialogue context to prevent cross-session data misuse.

## How to configure the settings
The following configurations are formulated based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 characters | Matches the total length of a single monthly settlement document and 10 real-time vehicle trip data entries |
| `messages` context truncation rule | Keep the most recent 20 dialogue messages | Avoids confusing business data by loading expired historical dialogue |
| `variables` dynamic loading scope | Bind the current session's `chatId` and the current day's date | Ensures only real-time business data for the current user is called |
| Single-turn dialogue timeout | 60 seconds | Adapts to the query response rhythm of real-time weighing data |
| Prompt template cache duration | 24 hours | Matches the daily update cycle of business rules |

## Three common configuration mistakes
- Phenomenon: A version update notice pops up automatically every time a new session is started. Cause: The trigger logic for the version update pop-up was not disabled in the session initialization configuration.
- Phenomenon: Tool call results are not displayed in the dialogue box during the first call, but become visible after re-entering the session. Cause: The dialogue history writing rule for the `messages` parameter was not configured correctly, causing tool return results to not be synchronized to the current session context.
- Phenomenon: Prompts cannot dynamically load specified business documents from the knowledge base. Cause: The filter fields for business documents were not bound via the `variables` parameter, causing the loading scope to cover irrelevant coal purchase, sales or inventory data.

## How to confirm the configuration is correct
- Open a new session and observe whether a version update notice pops up, to confirm whether the configuration meets expectations.
- Initiate a real-time weighing data query, wait for the tool call to complete, then check the dialogue history to confirm that the tool return results are directly displayed on the dialogue interface without delay or omission.
- Call the prompt loading function to verify that the loaded documents only include the business scope bound to the current session, with no irrelevant cross-user data appearing.
- Extend the number of dialogue turns to more than 20, confirm that the context truncation rule takes effect as preset, and the earliest dialogue content is automatically cleared.
