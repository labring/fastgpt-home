# Internal Office and Employee Services for Coal Transportation and Sales: Forms and Interactions

## What this category’s data looks like
Business data for coal transportation and sales comes from coal mine internal dispatching systems, sales and transportation ledgers, weigh-in slips, and delivery approval forms.
Data updates follow three rhythms: real-time weigh-in data syncs every 15 minutes, daily shipment summaries update each day, and monthly settlement ledgers are generated at the end of each month.
Document structures primarily use structured forms, with scanned copies of paper documents attached.
Fields include coal type identifiers, shipment tonnage, receiving entities, weigh-in times, and freight accounting items.
Units include ton, yuan per ton, and hour.

## What constraints these characteristics impose on the forms and interactions category
Dispersed data sources require forms to connect to multiple internal system interfaces, syncing information from modules including weigh-in, inventory, and finance.
Some fields include numerical items with specific units. For example, tonnage must be accurate to 0.01 ton, so form input boxes must restrict numerical formats and automatically adapt to units.
Differences in update rhythms across multiple sources require forms to support dynamic option loading, preventing option errors caused by expired caches.
Some business scenarios require association with paper document attachments, so forms must support multiple file uploads and limit single file size.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Supports date, numerical, and text types; numerical input limits decimal places to 2 | Adapts to input requirements for fields such as coal tonnage and weigh-in time |
| `userSelect` | Binds to internal customer/coal type database; refreshes options every 15 minutes | Syncs the latest registered data, matching the weigh-in data update rhythm |
| Attachment upload limit | Maximum 100 MB per file; up to 5 attachments total | Adapts to the size of scanned weigh-in slips and delivery approval forms |
| Field validation rules | Marks shipping location, tonnage, and weigh-in time as required fields | Covers core business required fields, reducing process loopholes |
| Linkage logic configuration | Automatically pulls the benchmark freight unit price after tonnage is entered | Reduces manual accounting steps and improves input efficiency |

## Three common mistakes
- Phenomenon: The form does not display a date input box, only showing a standard text box. Cause: The `formInput` configuration is not set to date type, only the default text format is used.
- Phenomenon: After the workflow HTTP request node returns a result, the extracted JSON field is empty. Cause: The JSONPath extraction rule is not configured correctly, or the variable transfer switch is not enabled.
- Phenomenon: Knowledge base retrieval returns inconsistent results. Cause: The form note content entered by employees is too long and not truncated, causing context overflow.

## How to confirm the configuration is complete
- Submit a test form, and check whether a validation prompt pops up when required fields are left empty.
- Manually modify coal inventory data, wait 15 minutes, then check whether dropdown options are updated synchronously.
- In FastGPT v4.17.0, configure an HTTP request node and test JSONPath extraction, verify whether fields can be correctly passed to downstream nodes.
- Upload a file larger than 100 MB, and check whether an upload limit prompt is triggered.
