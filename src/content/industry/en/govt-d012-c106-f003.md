# Integrated Coal and Power Internal Office and Employee Services: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data sources for integrated coal and power include coal mining systems, power plant operation monitoring systems, internal enterprise office OA systems, equipment operation and maintenance archives, employee personnel systems, and more. Update frequencies are divided into three categories: real-time data (such as equipment operating conditions, grid load) updated at millisecond intervals, attendance and reimbursement data updated daily, and financial report data updated monthly. Document structures include structured forms (such as approval sheets, attendance sheets, equipment inspection records) and unstructured documents (such as operation and maintenance logs, safety regulations, technical manuals). Fields include equipment numbers, operating parameters, employee IDs, approval status, energy consumption values, and more. Units include kilowatts, tons, person-times, yuan, ℃, and more.

## What Constraints Do These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
The mixed data structure of integrated coal and power systems requires prompt engineering to clearly separate extraction logic for structured form fields and unstructured operation and maintenance logs, preventing confusion between equipment parameters and approval status. Real-time operating condition data updates at millisecond intervals require multi-turn dialogue contexts to retain recent conversation interactions and latest collected values, stopping expired data from being called. Employees across multiple departments have different business scenarios, so `variables` must bind permission fields for each department to limit the data the dialogue can access. Approval data updated per process nodes requires prompt engineering to specify matching the current conversation’s process status, avoiding incorrect data calls across processes.

## How to Set Up Configurations

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `messages` | Retain the last 20 rounds of conversation context, limit single-round content to no more than 800 characters, calibrated based on actual testing | Operation and approval dialogues for integrated coal and power are mostly short interactions but require linking to historical processes; 20 rounds can cover complete business workflows, and the single-round length limit avoids context overload |
| `variables` | Bind three types of exclusive variables: equipment numbers, employee IDs, and approval order numbers; set a value range of no more than 100 characters for each variable | Internal office work at coal and power enterprises requires precise matching of business objects; exclusive variables prevent the dialogue from confusing different equipment, employees, or processes |
| `chatId` | Generate a unique identifier using employee ID + conversation creation time, set validity period to 7 days | Employee conversations at coal and power enterprises are mostly linked to individual business permissions and historical processes; a unique `chatId` ensures conversation context isolation, and the 7-day validity period fits regular business processing cycles |
| Temperature parameter | 0.2–0.6, calibrated based on actual testing | Internal office and employee services require stable instruction execution results; a lower temperature avoids deviations in prompt and variable references |
| Text content extraction prompt | Clearly specify the unit and data source of the extracted fields, for example: "Extract equipment number and operating temperature (unit: ℃) from operation and maintenance logs" | Integrated coal and power data includes fields with multiple units; clear prompts prevent extraction errors |

## Three Common Configuration Mistakes
- Symptom: After modifying the dialogue configuration to enable variable references, the temperature setting button disappears, and the temperature parameter cannot be adjusted. Cause: The configuration logic for variable references overrides the temperature parameter binding area, and the independent configuration entry for temperature settings is not retained.
- Symptom: After calling the workflow interface, the operating data field in the conversation log is empty. Cause: The mapping relationship of workflow return parameters is not configured via `variables`, so the system cannot capture and store operating data.
- Symptom: Add an any parameter in code block format to the prompt of the text content extraction module, and the extracted result shows that the code block is undefined. Cause: The prompt does not clearly specify the parsing rules for code blocks, so the system cannot recognize the extraction target corresponding to the any parameter, leading to parsing failure.

## How to Confirm Configuration Is Complete
- Initiate a test conversation that includes variable references, check whether the temperature parameter is normally displayed and adjustable.
- After calling the workflow interface, view the conversation log and confirm that the operating data field has been populated with content.
- Input an any parameter in code block format into the text content extraction module, check whether the extraction result correctly recognizes the code block content.
- Generate a unique `chatId` to initiate a conversation, confirm that subsequent conversations will not be confused with the conversation contexts of other employees.
