# Coal-electric Integration Internal Office and Employee Services: Workflow Orchestration

## What the category’s data looks like
Business data for coal-electric integration comes primarily from coal mine production ledgers, power plant operation logs, internal collaborative approval systems, and material inbound and outbound documents. Data update frequency varies by business phase: production-related data syncs hourly, while approval-related data updates in real time when a process node is completed.

Each document includes fields such as equipment ID, work shift, energy consumption value, approval number, and handler. The energy consumption field uses kilowatt-hour as its unit. Material fields use ton or piece as their unit. Approval number fields use string format.

## Constraints imposed on workflow orchestration
The multi-source, heterogeneous data characteristics of coal-electric integration require workflow orchestration to adapt to data sources with different update frequencies. Real-time production data needs scheduled trigger nodes to avoid data lag from single triggers. Differences in fields across business modules require workflows to support custom field mapping rules, to align parameters with inconsistent naming between coal mines and power plants. The approval process context must bind information from historical nodes including handlers and approval opinions. Complete process chain data must be retained to prevent context loss. Numerical fields with units need unit verification nodes in the workflow, to stop calculation errors from mixed units when data is used across modules.

## Configuration settings
The following configuration items are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Scheduled trigger per business node, 15-60 minute interval | Adapt to the hourly update rhythm of coal-electric production data and avoid data lag |
| `variables` binding rules | Bind three field types: equipment ID, energy consumption value, approval number | Match core data fields of coal-electric integration business, covering production and office scenarios |
| Cross-workflow component reuse | Enable component copy permissions | Support rapid building of similar approval or data synchronization processes, reduce repeated configuration |
| `nodeId` association rules | Bind the node ID of the corresponding business system | Enable precise data interaction between workflows and external systems |
| Context retention duration | Retain 7 days of process context | Cover the conventional approval cycle of coal-electric integration business, meet historical review needs |
| Error retry configuration | Retry 2-3 times, 30 second interval | Address call failures caused by temporary fluctuations in external systems |

## Three common configuration errors
- Symptom: Unable to drag or copy workflow components to other workflows, with an interface prompt of no permission or invalid operation. Cause: Cross-workflow component reuse configuration is not enabled, preventing component calls across processes.
- Symptom: Tool call node returns error `Invalid JSON: Bad control chara`, logs show returned content contains line breaks or invisible characters. Cause: Text cleaning node is not configured to filter illegal control characters from raw data.
- Symptom: Some business field context is lost after workflow node transitions across stages, preventing subsequent approval verification. Cause: Complete core fields are not bound in the `variables` configuration, only temporary parameters are retained.

## How to confirm the configuration is complete
- Trigger test: Manually trigger the workflow once, verify returned data includes preset core business fields, with field units matching business documents.
- Component reuse test: Copy a node from the current workflow, paste it into a new blank workflow, confirm component configuration is complete and not lost.
- Context verification: Complete a full process node transition, check that `variables` parameters in downstream nodes include core data from all historical nodes.
- Error retry test: Simulate a temporary external system failure, observe if the workflow triggers the retry mechanism as configured.
