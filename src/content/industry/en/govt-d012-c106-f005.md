# Internal Office and Employee Services for Coal-Electric Integration: Tool Calling and Plugins

## What the data for this category looks like
The business data sources for coal-electric integration cover coal mine fully mechanized mining monitoring systems, power plant operation ledger databases, material supply management platforms, and internal human resources systems. Production operation data updates at minute-level intervals, and includes fields such as device ID, operating duration, power generation, and coal consumption rate, with units corresponding to megawatt-hours, hours, and tons of standard coal per megawatt-hour. Employee attendance and reimbursement data updates daily, with fields including employee ID, department, scheduling time, and reimbursement amount, with units in yuan and days. Equipment ledger and material inventory data updates on demand, including fields such as material code and inventory quantity. The overall data structure covers three core business scenarios: production scheduling, employee services, and material management.

## What constraints these characteristics impose on the "tool calling and plugins" link
Minute-level updated production data requires that tool calling delays be controlled within a reasonable range to avoid returning outdated data that disrupts scheduling decisions. Structured data with multiple fields requires precise matching of business fields during plugin calls to prevent redundant data from exceeding context window limits. Internal permission controls for state-owned enterprises and public institutions require that plugins be bound to user group identity verification to prevent unauthorized access to sensitive production or human resources data. Heterogeneous internal system interfaces must be configured with docking addresses via custom tool variables individually to meet tool calling needs for multiple data sources.

## How to Set Up Configurations
The following are recommended tool calling and plugin configurations for the coal-electric integration scenario in FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Adapts to the automatic decision-making needs of production scheduling and employee service scenarios, covering most daily business |
| Single call timeout | 15–20 seconds | Matches the minute-level update rhythm of production data, avoiding excessive waiting that leads to outdated data |
| Plugin permission verification | Enabled and bound to internal user groups | Complies with permission control requirements for internal data access in state-owned enterprises and public institutions, preventing unauthorized calls |
| `functionCall` | Only forcibly enabled during equipment fault query and material inventory check | Ensures accuracy of tool calling in key business scenarios, avoiding deviations from model autonomous decision-making |
| Custom tool variables | Configured as coal mine scheduling interface address, power plant ledger storage path | Docks with exclusive internal business systems, avoiding maintenance issues caused by hardcoding |
| Result return limit | Top 3–5 entries | Controls the amount of data returned by a single tool call, adapting to context window limits |

## Three Common Errors
- Phenomenon: "403 Insufficient Permissions" is returned when calling a custom internal plugin. Cause: Plugin permission verification is not enabled, or the corresponding internal user group is not bound, causing the plugin to fail identity verification through the internal system.
- Phenomenon: The model does not trigger tool calling when querying employee attendance or reimbursement, and returns vague estimated results. Cause: `functionCall` is not forcibly enabled in key employee service scenarios, so the model ignores the precise query requirements for structured data during autonomous decision-making.
- Phenomenon: Tool calling returns empty results. Cause: The internal system address configured for the custom tool variable is incorrect, causing the plugin to fail to connect to the coal-electric integration production or human resources database.

## How to Confirm the Configuration Is Complete
- Initiate an equipment fault query request, and check whether tool calling is triggered and returns the ledger data of the corresponding device.
- Call the custom plugin to query employee attendance information, and confirm that the returned results only include data within the permission scope of the currently logged-in user.
- View the tool calling log, and confirm that the time taken for a single call does not exceed the set 15–20 second threshold.
- Test the custom tool variable configuration, and verify that the plugin can normally connect to the preset internal production system address.
