# Integrated Coal and Power Internal Office and Employee Services: Forms and Interactions

## What this category of data looks like
Data for integrated coal and power internal office and employee services comes primarily from coal mine production scheduling systems, power plant operation logs, human resource management platforms, and material procurement databases. Data updates are completed per production shift (8 hours per shift) or daily. Some real-time work order data updates every 15 minutes. The document structure uses a multi-table association pattern, and includes core table entries such as the employee basic information table, post scheduling table, equipment maintenance work order table, and material requisition application table. Fields include professional attributes such as post number (unit: post number), equipment ID (unit: unit), work order duration (unit: hours), and material requisition quantity (unit: ton/piece). No universal standardized field formats are used.

## What constraints these characteristics impose on the forms and interactions link
The multi-table associated data structure requires forms to support cross-table linked queries. For example, selecting an employee’s post must automatically bring up the scheduling information for the corresponding team. The data update rhythm based on shifts or real-time updates requires that internal system data updates are triggered synchronously after form submission, to avoid data lag. The unit attributes of professional fields require the interaction interface to enforce unit matching verification for input content, to prevent business exceptions caused by unit errors. The shift-based employee structure requires the form’s time selection component to support quick entry of cross-period scheduling, adapting to the work habits of frontline employees.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable field verification and automatic unit matching | Integrated coal and power data uses professional units; automatic matching reduces input errors and fits professional internal office scenarios |
| `userSelect` | Filter selectable personnel by post group | Internal employees are managed by post groups; group filtering improves personnel selection efficiency and reduces selection errors |
| Form submission timeout | 30 seconds | Coal and power systems have large data interaction volume; 30 seconds covers most data synchronization scenarios, calibrated via actual testing |
| Form block receiving configuration | 800–1200 characters per block | Splitting long form content reduces loading pressure, adapting to complex form scenarios for internal office work |
| Global variable binding rule | Support assigning global variables to radio variables | Reuse global data such as employee posts and teams, reducing repeated configuration steps |

## Three common misconfigurations
- Phenomenon: Form nodes are displayed as plain text in the conversation interface, and interactive input is not possible. Cause: The interactive rendering switch for the `formInput` configuration is not enabled, causing the form to not be correctly parsed as an interactive component.
- Phenomenon: When trying to assign a global variable value to the radio variable of the `userSelect` node, the variable does not take effect. Cause: The mapping binding rule between the global variable and the radio variable is not configured, so data transfer cannot be completed.
- Phenomenon: Form interaction experiences loading lag or timeout errors in a local deployment environment. Cause: The rendering cache threshold of `formInput` is not adjusted, causing excessive system resource usage when loading large amounts of form data.

## How to confirm the configuration is complete
- Enter the conversation interface of FastGPT v4.17.0, open the form component, and verify whether the fields automatically match the corresponding professional units.
- Select an employee’s post, and verify whether the selectable personnel list only includes employee information for that post.
- After submitting the form, check whether the data of the internal associated systems is updated synchronously.
- Try assigning a preset global variable value to the radio variable, and verify whether the variable is successfully bound and takes effect.
