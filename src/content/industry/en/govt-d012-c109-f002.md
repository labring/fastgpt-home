# Internal Office and Employee Services for Power Grid Enterprises: Vector Models and Indexes

## What the Data for This Category Looks Like
Power grid enterprise internal office and employee service data mainly comes from internal OA system documents, operation and maintenance work order systems, employee training courseware, team operation logs, and other sources. The data update rhythms vary: operation and maintenance work orders are generated and updated in real time with field operations, documents are released as per approval workflows, and training courseware is updated on a quarterly basis. Document structures include fields such as title, body, publishing department, publishing time, affiliated team, and equipment number. Some professional documents also include power-specific units and term fields such as voltage level and line name.

## What Constraints These Characteristics Impose on the Vector Model and Indexing Link
Multiple data sources and differentiated update rhythms require vector models and indexes to adapt to different update frequencies. High-frequency real-time work orders need incremental indexing to avoid full indexing blocking. Long-text operation logs and documents contain a large number of professional terms. When splitting vector chunks, term context must be retained to prevent semantic fragmentation. The presence of multi-field metadata requires enabling metadata filtering capabilities, to support recall of relevant content by dimensions such as team and equipment number. Power-specific units and terms in some documents require embedding models to adapt to semantic features in the energy and power sector, to prevent semantic loss of professional content.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the text length of power grid documents and operation and maintenance work orders, avoid splitting that destroys the integrity of professional terms |
| Overlap Length | 100–150 characters | Retain professional term context of adjacent chunks, prevent cross-chunk semantic fragmentation |
| Similarity Threshold | 0.75–0.85 | Match the semantic similarity range of internal power grid documents, filter low-relevance non-business content |
| defaultToken | Calibrated based on actual measurements | Adapt to the enterprise's internal token permission rules, avoid errors from unauthorized model calls |
| maxToken | 8192 token | Adapt to the maximum input length of bce-embedding-v1, meet the embedding needs of long power grid documents |
| Single Search Limit | Top 10 entries | Balance recall efficiency and content coverage, match the information retrieval scenario of internal office work |

## Three Common Misconfigurations
- Phenomenon: After calling the `pushdata API` to upload chunk mode data, the interface continuously displays the indexing status.
  Reason: The incremental index trigger rule is not configured, and blocking occurs when full indexing processes a large amount of real-time operation and maintenance work order data.
- Phenomenon: The console returns the error "This token does not have permission to use the model: text-embedding-3-large".
  Reason: The `defaultToken` parameter is not configured correctly, and an access token without corresponding model permissions is used.
- Phenomenon: A large number of old, non-current business-related documents are mixed in the search results.
  Reason: The similarity threshold is not set, or the threshold is set unreasonably, and content with low semantic matching is not filtered.

## How to Confirm the Configuration Is Correct
- Upload a single operation and maintenance work order document of around 1000 characters, check the completion time of the embedding task, and confirm that the indexing speed meets business expectations.
- Search for the keyword "10kV line", verify whether the returned result metadata includes corresponding team and equipment number fields, and confirm that the metadata filtering configuration takes effect.
- View the model call log, confirm that the token corresponding to `defaultToken` has permissions covering the currently used embedding model, and no permission errors are present.
- Adjust the similarity threshold, search for the same keyword, observe the change in the relevance of the returned results, and confirm that the threshold configuration meets business needs.

The values provided here are common starting points and should be measured against the reader's own samples.
