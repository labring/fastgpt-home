# Internal Office and Employee Services for Power Grid Enterprises: Tool Calling and Plugins

## What Data in This Category Looks Like
Power grid enterprise internal office and employee service data mainly comes from internal OA systems, power equipment operation and maintenance logs, employee attendance systems, work order repair platforms, and team patrol logs. Data update rhythm falls into two categories: equipment logs and team patrol records are updated daily, while active work orders and attendance data are synced in real time. Each document includes fields such as work order ID, equipment number, fault type, processing progress, responsible person, and report time. Field units follow standard formats: timestamps use ISO 8601, and duration is measured in minutes.

## Constraints Imposed on Tool Calling and Plugin Configuration
The multi-source heterogeneous nature, real-time updates, and specialized field features of power grid enterprise internal office data impose multiple constraints on tool calling and plugin configuration. Multi-data sources require configuration of multiple linked plugins. Each plugin needs separate field mapping rules to match naming differences across systems. Real-time data requires the `toolChoice` and `functionCall` parameters to adapt to interface response times and avoid workflow interruptions. Specialized power terminology fields need to specify only returning designated fields in call parameters to reduce redundant content. Some sensitive data requires identity verification parameters to be configured during plugin calls, ensuring only authorized users can trigger corresponding tools.

| Field mapping rules | Map according to system-preset power operation and maintenance fields | Unifies field naming differences across different data sources, ensuring consistent format of tool call return content |
| Identity verification switch | Enabled | Adapts to permission control requirements for internal data, only allowing authorized users to trigger corresponding plugins |
| Terminology adaptation configuration | Enable professional term mapping | Converts professional power terms to general expressions to adapt to large model understanding logic |

## Three Common Errors
- Phenomenon: AI output includes unparsed reference markers such as [1]. Cause: No reference marker filtering logic is configured in the tool call result processing link, and original content retrieved from the knowledge base is directly spliced.
- Phenomenon: No response from the bound custom interface after a user inputs specified keywords. Cause: No keyword matching rule is set in the tool call configuration, or the rule's trigger condition is not correctly associated with the custom plugin.
- Phenomenon: A parameter missing error message is returned when calling a workflow. Cause: Corresponding parameters are not passed according to the input field requirements preset in the workflow, or parameter names do not match the workflow configuration.

## How to Confirm Configuration Is Correct
- Trigger the work order query tool call, and check if the returned result only includes the core fields specified in the configuration to confirm the field extraction rule is active.
- Input keywords containing internal permission identifiers, and verify that unauthorized users cannot trigger the corresponding plugin to confirm the identity verification configuration is active.
- Submit a real-time work order query request, and check if the tool call response time falls within the preset timeout threshold range to confirm the timeout configuration is reasonable.
- Trigger keywords bound to the custom interface, and check if the external interface is correctly called and corresponding content is returned to confirm the trigger rule is active.
