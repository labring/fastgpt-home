# Internal Office and Employee Services for Power Grid Enterprises: Document Parsing and Chunking

## What the data for this category looks like
Documents related to internal office and employee services for power grid enterprises come from sources including internal operation and maintenance logs, safety work procedures, employee training manuals, power grid dispatch records, and repair work order documents. Update frequency aligns with business process updates, regulatory specification revisions, or monthly archiving.
Document structures include structured text with fixed business fields, long-form procedure documents, and operation and maintenance reports with tables. Fields include work order number, voltage level, maintenance duration, and similar items. Units include kilovolts, hours, person-times, and similar units.

## What constraints these characteristics impose on document parsing and chunking
Long-form procedures and dispatch records require chunking that retains complete business semantics. Avoid splitting content that breaks logical connections of individual work items or procedures.
Operation and maintenance reports with tables require the parsing stage to retain original layout and field correspondence. Otherwise, subsequent retrieval loses data associations.
Large annual log-style documents have large file sizes, raising higher requirements for upload and parsing limits.
Multiple document types exist together, requiring flexible adjustment of chunking rules to adapt to different document structures.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Power grid internal procedures and work order documents are mostly long-form text. This range retains complete semantics of individual work items or procedures. |
| `chunkSplitter` | Split by paragraph + heading | Power grid documents mostly have hierarchical headings and structured paragraphs. This preserves business logical connections. |
| `customPdfParse` | Enabled | Power grid internal documents are mostly compliant PDFs with tables and annotations. Enabling this retains original layout and field information. |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Large documents such as annual operation and maintenance logs may exceed standard upload limits. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Long document parsing requires longer processing time to avoid mid-process timeouts. |
| `chunkSettingMode` | Manual configuration | Power grid documents have large type differences. Manual configuration adapts chunking requirements for different scenarios. |

## Three Common Mistakes
- Symptom: A boolean parameter returned by the HTTP component becomes empty after being received by the conditional judgment component. Cause: The parsing format of returned data was not explicitly specified in the HTTP component, causing the boolean value to be incorrectly converted or have its type lost.
- Symptom: Parsing timeout errors occur when parsing large power grid operation and maintenance documents. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration was not adjusted based on document length. The default duration is insufficient for long document parsing.
- Symptom: The number of chunks per file after knowledge base splitting exceeds the threshold, making storage into the knowledge base impossible. Cause: The original file was not split in advance according to document content logic, or the chunking configuration was not adjusted to adapt to the chunk count limit for large documents.
