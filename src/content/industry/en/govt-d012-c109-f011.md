# Internal Office and Employee Services for Power Grid Enterprises: Forms and Interactions

## What the data for this category looks like
Data for internal office and employee services at power grid enterprises mainly comes from internal OA, ERP, operation and maintenance logs, personnel management systems, and other sources. Data update frequency varies by scenario. Operation and maintenance work order data updates in real time. Personnel report data syncs on a weekly basis. Documents primarily use structured fields including device number, work order ID, rated capacity, operation and maintenance duration, and more. They also include enumerated classification fields such as team and inspection route. Some fields have professional units such as kilovolt-ampere and hour.

## How these characteristics impose constraints on forms and interactions
Structured fields and enumerated classifications require forms to support configurations like linked dropdown menus and required validation to prevent invalid input.
Real-time updated operation and maintenance data requires form data sources to support real-time pulling or scheduled synchronization to avoid using expired data.
Professional unit fields require the interaction interface to clearly display unit prompts to lower the risk of input errors.
Multi-node process forms need to be split into step-by-step modules to prevent interface lag caused by loading too many fields on a single page.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind fields such as device number and work order ID, enable required validation | Meet the required field requirements for work order forms |
| `userSelect` | Pre-set enumerated options for team and inspection route | Match the fixed classification of internal organizational structure |
| Step-by-step form configuration | Split into 3 nodes according to the work order process | Avoid loading delays caused by too many fields on a single page |
| Conversation context linkage | Enable cross-node data transfer | Support using previous form data as input for subsequent AI conversations |
| Retrieval result call | Call the top 3 retrieval results | Adapt to the short-text retrieval scenario of operation and maintenance logs |
| Timeout setting | 120 seconds | Match the average response time of internal system interfaces |

## Three common configuration errors
- The symptom is that the input field of the second AI conversation is empty. The cause is that cross-node data transfer is not enabled correctly, and the previous `formInput` field is not bound to the subsequent conversation node.
- The symptom is that only 1 retrieval result is returned. The cause is that the upper limit of the number of retrieval result calls is not configured correctly, and only a single result is called.
- The symptom is that the code running node triggers an error, prompting that the input format does not match. The cause is that the professional units of the form fields are not converted to the standard format recognizable by the plugin.

## How to verify correct configuration
- Submit a test work order, check whether the validation prompt for required fields is triggered normally.
- Initiate multi-round conversations, confirm whether the `formInput` data from the previous form is automatically brought into subsequent conversation nodes.
- Trigger a retrieval operation, confirm that the number of returned results matches the preset call upper limit.
- Call the associated plugin, check whether the input parameter format of the code running node matches the preset requirements.
