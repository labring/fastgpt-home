# Internal Office and Employee Services for Power Grid Enterprises: Deployment and Upgrade

## What the Data for This Category Looks Like
Data for internal office and employee services of power grid enterprises mainly comes from the enterprise's internal OA system, operation and maintenance work order platform, employee service portal, and training management system. The document structure includes work order number, affiliated operation and maintenance team, problem category, processing status, associated transmission/distribution equipment code, submission and completion timestamps. The associated equipment code field uses an alphanumeric mixed format, and time-related fields use the ISO 8601 format. Update rhythm is triggered by business events: work orders are submitted in real time, attendance data is synced daily, training archives are updated weekly, and there is no fixed bulk sync cycle.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
This category of data includes associated equipment fields with mixed codes, multiple timestamp fields, and diverse update trigger scenarios. During deployment, ensure that the database connection strings `MONGODB_URI` or `PG_URL` point to the enterprise's internal exclusive database to avoid field matching conflicts with other business data. Real-time submitted work orders generate high concurrent requests, so configure `DB_MAX_LINK` to set a reasonable upper limit for the database connection pool to prevent connection exhaustion. Training documents and work order attachments generated by employee services require configuring the enterprise internal object storage endpoint via `STORAGE_S3_ENDPOINT` to reduce public network transmission latency. During upgrades, retain the original field mapping rules to avoid abnormal reading of associated data.

## How to Configure Settings
Reference only; verify against the target FastGPT release and deployment documentation.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Exclusive connection string for the enterprise's internal MongoDB instance, including database authentication information | This category's data requires associated equipment code fields. Using an exclusive database avoids confusion with other business data |
| `DB_MAX_LINK` | 100–150 connections | Real-time submission of internal work orders causes high concurrency. Sufficient database connection pool capacity must be maintained |
| `STORAGE_S3_ENDPOINT` | Access endpoint for the enterprise's internal object storage | Training documents and work order attachments generated by employee services must be transferred via internal storage to reduce transmission latency |
| `FE_DOMAIN` | Enterprise internal exclusive domain name, such as `https://fastgpt.energy-grid.com` | Restrict internal access domain names to comply with enterprise network security specifications |
| `REDIS_URL` | Connection string for the enterprise's internal Redis cache instance | Cache employee sessions and work order status to improve response speed for internal access |
| `ROOT_KEY` | Random string generated in accordance with enterprise internal security specifications | Used for highest privilege verification of the management backend to ensure system security |

## Three Common Configuration Mistakes
- Phenomenon: After the container starts, the front-end page keeps loading and eventually returns a 502 status code. Cause: `FE_DOMAIN` and the back-end service port mapping are not correctly configured, causing the front end to fail to connect to the back-end API.
- Phenomenon: Unable to access all applications via the `/fastgpt` context path. Cause: The path rewrite rules of the front-end reverse proxy are not correctly configured, or `FE_DOMAIN` does not include the specified context path.
- Phenomenon: After the service is restarted, the data writing process takes more than 2 hours to complete. Cause: The upper limit of `DB_MAX_LINK` connection count is not adjusted, leading to database connection exhaustion and blocking of data writing threads.

## How to Verify Correct Configuration
- Access the path configured for `FE_DOMAIN` to confirm the front-end page loads normally, with no loading failures or error prompts.
- Submit a test work order, fill in the associated equipment code field, and check whether the field content can be stored and read normally in the database.
- Log in to the enterprise's internal object storage console, check the storage bucket corresponding to `STORAGE_S3_ENDPOINT`, and confirm that the uploaded test file has been successfully written.
- View the database connection pool monitoring panel to confirm that the current active connection count does not exceed the configured upper limit of `DB_MAX_LINK`.

The values provided are common starting points and should be measured against the reader's own samples.
