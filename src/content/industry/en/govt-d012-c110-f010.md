# Internal Office and Employee Services for Mineral Mining and Processing: Knowledge Base Retrieval and Recall
FastGPT v4.17.0

## What the data for this category looks like
Business data sources for mineral mining and processing include underground operation records, mineral processing process ledgers, equipment maintenance archives, safety operation procedures, internal office documents, and employee training materials. Update frequencies vary by data type:
- Underground operation records are updated in real time per shift
- Mineral processing process ledgers are updated daily
- Safety operation procedures are revised annually
- Internal office documents are updated on demand

Document structures include structured parameter tables, semi-structured process documents, and long-text training materials. Fields cover equipment numbers, work shifts, detection values, and more. Units include tons, kilowatt-hours, and hours.

## What constraints these characteristics impose on knowledge base retrieval and recall
The presence of structured parameter tables requires retrieval to support both precise field matching and full-text semantic matching. This prevents missing professional parameter recalls caused by relying solely on vector similarity.
Real-time updated operation records require the retrieval system to support incremental data synchronization. This avoids recalling outdated content.
Long-text training and procedure materials require a reasonable chunking strategy. This preserves contextual connections to ensure the completeness of retrieval results.
Mixed multiple types of data require flexible retrieval range restrictions. This prevents mixing irrelevant office documents.
Professional terms and unique identifiers require targeted semantic expansion. This improves retrieval accuracy.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Adapts to the retrieval scenario of mineral mining and processing, which mixes structured parameters and long text, filters low-match results |
| `limit` | Top 6–10 results | Balances recall coverage and single-round context length, adapts to the average length of mineral mining and processing documents |
| `usingReRank` | Enabled | Corrects biases based on vector similarity, performs secondary screening for semantic matching of professional terms |
| `searchMode` | Hybrid Retrieval | Matches structured fields and full-text content simultaneously, meets retrieval needs for operation logs and procedure documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands the retrieval scope of professional terms, such as associating "grinding fineness" with similar process expressions |
| `collectionIds` | Bind collection IDs of operation logs and procedure documents | Restricts the retrieval scope to avoid mixing irrelevant internal office documents |

## Three common configuration errors
- Phenomenon: API calls return a 422 status code, and individual knowledge base retrieval works normally. Cause: Failed to correctly configure the parameter binding of `datasetSearchUsingExtensionQuery`, leading to format verification failure during extended queries.
- Phenomenon: API calls only return model responses, with no cited document details or sources. Cause: Did not enable the context-carrying configuration for retrieval results, and did not specify the logic for returning citation fields.
- Phenomenon: AI fails to recall professional term content about mineral processing processes in the knowledge base. Cause: Did not enable `usingReRank` or set `searchMode` to pure full-text retrieval, ignoring the matching needs of structured professional fields.

## How to confirm the configuration is correct
- Submit a test retrieval request containing professional terms and structured parameters. Verify that the matching degree of returned results meets business needs, and adjust the value range of `similarity` as needed.
- Call the published API interface. Check whether the returned results include cited document sources and content fragments, and confirm that the context-carrying logic of the retrieval configuration takes effect.
- Simulate precise retrieval of equipment numbers or operation parameters. Verify that corresponding structured content can be recalled, and confirm that the hybrid retrieval configuration of `searchMode` is correct.
- View system operation logs. Confirm that there are no parameter verification failure errors, and verify that all configuration item binding relationships are correct.

Note: The configuration values listed above are common starting points. They should be evaluated against the reader's own specific samples.
