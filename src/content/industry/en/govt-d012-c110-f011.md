# Internal Office and Employee Services for Mineral Mining and Beneficiation: Forms and Interactions

## What the data for this category looks like
Mineral mining and beneficiation data mainly comes from downhole sensing equipment, production scheduling systems, equipment ledger databases, and employee attendance systems. Real-time data includes equipment operating current and tunnel ventilation volume. Daily updated data covers equipment maintenance records and team shift schedules. Monthly updated data includes mineral processing recovery reports. Most document structures are structured forms, with fields including equipment number, inspection time, hazard level, and processing status. Common units include ton, meter, hour, and piece. The forms also include personnel-related fields such as employee ID and team affiliation.

## What constraints these characteristics impose on the forms and interactions link
High-frequency updates of real-time sensing data require forms to pull the latest field values in real time, avoiding cached outdated data. The high proportion of structured fields means free input items must be limited, and preset option components should be prioritized. Associated fields such as employee ID and team need to connect to existing attendance system interfaces to ensure input values match internal enterprise data. Uploading large mineral processing report documents requires adaptation to large file sizes, avoiding single loading timeout. It must also support chunked upload to reduce failure probability.

## How to set the configurations

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `userSelect` | Bind to enterprise attendance system interface, load top 5 matching options | Mining and beneficiation employee IDs and teams are fixed associated fields, avoid free input errors, comply with FastGPT v4.17.0 component rules |
| `formInput` | Limit input length to 0–2000 characters | Text content such as inspection records and hazard descriptions does not require long input, reduce page loading pressure |
| Single submission timeout | 600 seconds | Large mineral processing report upload or multi-field submission requires longer response time |
| File upload size limit | Within 1000 MB | Monthly reports and equipment ledger files for mineral mining and beneficiation have large file sizes |
| Form step-by-step display | Split forms by inspection type | Mineral mining and beneficiation forms have many fields, splitting reduces filling complexity |
| Input validation rules | Match equipment number format (e.g., letter + number combination) | Equipment number is a fixed format field, avoid invalid input |

## Three common mistakes
- Phenomenon: Uploading any mineral mining and beneficiation related documents triggers a file upload failure prompt, while the text conversation function works normally. Cause: No large file upload adaptation parameters configured for this category, or the upload interface timeout threshold is set too low.
- Phenomenon: The employee options loaded by the `userSelect` component in the form are empty, and invalid prompts are displayed for employee ID or team fields when submitting. Cause: Failed to correctly connect to the enterprise attendance system interface, or the interface return data format does not match the component preset.
- Phenomenon: Submission has no response after filling out the multi-field form, and a timeout error is displayed after waiting for a period of time. Cause: No sufficiently long submission timeout time set, or chunked upload configuration not enabled when uploading large documents.

## How to confirm the configuration is complete
- Open the form page, check if the `userSelect` component loads internal enterprise employee ID and team options, confirm the interface connection is normal.
- Upload a large volume document matching the category characteristics, check if upload and submission can be completed normally.
- Fill in the free input items of the form, check if they comply with the preset input length limit and format validation rules.
- Trigger the form submission operation, confirm that the waiting time matches the set timeout threshold, and no unresponsive or timeout error occurs.
