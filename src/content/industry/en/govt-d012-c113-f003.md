# Internal Office and Employee Services for Shipbuilding: Multi-turn Dialogue and Prompt Engineering

## What the Use Case Data Looks Like
Internal office data for shipbuilding comes from production management system work orders, equipment maintenance ledgers, internal OA office documents, crew attendance system records, and hull design drawing files.
Update cadence:
- Production work orders are synced in real time
- Maintenance records are archived and updated within 1 hour after job completion
- Design drawings are synced with version iterations
Document structure includes two categories:
1.  Structured work order data, including fields such as work order ID, ship type, process, and responsible person
2.  Unstructured maintenance reports and office documents, with fields using exclusive units such as working hours, tonnage, and batch count

## Constraints for Multi-turn Dialogue and Prompt Engineering
Structured work order data and maintenance records contain exclusive fields like ship type, process, and working hours. In multi-turn dialogue, fields must be accurately linked to their corresponding ship types to avoid parameter confusion.
Unstructured design drawings and maintenance reports can be tens of thousands of characters long, which will fill the dialogue context window. Total context volume per single-round call must be limited.
The real-time update feature of production work orders requires multi-turn dialogue links to sync the latest status; static cached data cannot be used.
Production processes vary significantly across ship types. Prompts must be dynamically adjusted to match rules based on ship type to improve dialogue accuracy.

## Three Common Configuration Mistakes
- Phenomenon: Markdown-formatted equipment parameter tables fail to render correctly in dialogue, with content truncated.
  Cause: No appropriate context truncation threshold is configured for long parameter lists in shipbuilding, causing table content to exceed the single-round reply token limit.
- Phenomenon: The error `insufficient_quota Current group upstream load is saturated, please try again later` is returned.
  Cause: Single-turn dialogue token limit is not set. Long document parsing combined with multi-turn context superposition causes the request load to exceed the current group threshold.
- Phenomenon: Dialogue records are not saved to the database after the client closes the SSE connection.
  Cause: Real-time disk persistence configuration for `chatId` session persistence is not enabled. Automatic writing after request completion is relied on, so the writing process is not completed after interruption.

## How to Verify Proper Configuration
- Initiate a multi-turn test dialogue containing ship work order fields and maintenance report snippets, confirm the `messages` context retains the last 10 valid rounds of content.
- Trigger a long document parsing request, check that the reply is complete with no content truncation or error prompts.
- Close the SSE connection and check the database, confirm dialogue records have been written normally.
- Adjust ship type parameters, confirm fields bound by `variables` are dynamically updated with the ship type.
