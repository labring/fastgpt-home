# Internal Office and Employee Services for Shipbuilding: Workflow Orchestration

## What the data for this category looks like
Internal office data for shipbuilding comes from four main sources: ship design drawings, production work orders, equipment maintenance records, and crew scheduling sheets.
Design drawings are structured documents. They include fields such as drawing number, version number, component size, and material specification. Most units are millimeters and tons.
Production work orders include fields such as order ID, associated ship number, process, responsible person, and deadline. They are updated in real time according to production rhythm.
Maintenance records are generated per equipment maintenance cycle. They include fields such as equipment number, maintenance time, and fault description. Most units are hours.
The update rhythms of these data vary significantly: design drawings are updated with revisions, production work orders are added in real time, and maintenance records are generated in batches per cycle.

## Constraints on workflow orchestration
The multi-source, heterogeneous data traits of shipbuilding create multiple constraints for workflow orchestration.
Production work orders are linked to multiple core identifiers such as ship number and component number. Workflows must support binding multiple fields as input parameters. This avoids retrieval bias caused by a single parameter.
Design drawings are updated frequently with new versions. When workflows call knowledge bases, they must support filtering recall results by version number and component type. This ensures matching documents used in current production.
Real-time generated production work orders require workflows to support real-time event triggering. This aligns with the real-time submission rhythm of work orders.
Structured fields in maintenance records must strictly match the input format of workflow nodes. This prevents execution interruptions caused by format incompatibility.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind order ID, associated ship number, and component number to the `variables` parameter | Shipbuilding work orders are linked to multiple core identifiers; binding multiple fields avoids retrieval bias |
| Knowledge Base Filter Conditions | Filter by drawing version number and component type | Ship design drawings are updated frequently with new versions; precise matching of documents used in current production is required |
| Single Recall Count | Top 8 entries | Shipbuilding has many component types; too many recall entries increases context length |
| Node ID Setting | Bind the `nodeId` of the corresponding work order processing node | Ensures correct execution order of workflow nodes and avoids abnormal process jumps |
| History Record Binding | Bind the first 3 rounds of conversation content | Shipbuilding-related issues are mostly linked to current work orders; overly long history will interfere with retrieval accuracy |
| Node Timeout Setting | 600 seconds | Shipbuilding document retrieval requires loading large-volume design drawings; sufficient time must be reserved |

## Three Common Mistakes
- Phenomenon: The workflow automatically terminates after reaching the knowledge base search node, with no return results or error messages. Cause: No drawing version number filtering condition is bound, so design documents for the current production version cannot be recalled, leading to process interruption.
- Phenomenon: Historical conversation content cannot be selected as an input parameter in the workflow configuration interface. Cause: Historical conversation binding permission is not enabled in the `variables` configuration, so historical content cannot be passed to workflow nodes.
- Phenomenon: After filling in all input items and running the workflow, the error "Cannot convert undefined or null to object" is displayed. Cause: Required fields such as order ID or ship name are not bound to `variables`; empty runtime parameters cause the error.
