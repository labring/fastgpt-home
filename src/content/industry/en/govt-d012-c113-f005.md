# Internal Office and Employee Services for Shipbuilding: Tool Calling and Plugins

## What This Category of Data Looks Like
The data for internal office and employee services in shipbuilding comes primarily from three types of systems. These are ship construction design drawing libraries, production scheduling and equipment maintenance systems, and office OA and crew management systems.

Data update frequency varies by scenario. Design drawings are updated during project initiation and modification phases. Equipment maintenance records are synced in real time when work orders are submitted. Attendance and scheduling data is updated daily.

Document structure includes drawing metadata, maintenance work orders, and office documents. Drawing metadata includes ship type, gross tonnage GT, and construction number. Maintenance work orders include equipment number, fault level, and processing progress. Office documents include department training materials and policy documents. Most fields use shipbuilding industry standard units and exclusive identifiers.

## What Constraints These Characteristics Impose on Tool Calling and Plugin Configuration
The data characteristics of shipbuilding impose four constraints on tool calling and plugin configuration.

First, individual design drawing documents have large file sizes. Plugins must limit the range of document blocks read per call. This prevents interface timeouts.

Second, fields such as equipment numbers and ship type parameters follow shipbuilding industry standard formats. Plugins must support matching fields according to standard rules. Without this, plugins cannot associate maintenance work orders with their corresponding equipment.

Third, internal office and crew management data involves production progress and personnel privacy. Plugins must configure permission verification logic when called. This restricts unauthorized access to sensitive fields.

Fourth, data sources are scattered across multiple systems. Plugins must support configuration of multiple data source connections. They must also handle differences in field mapping across different systems.

## How to Configure the Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the need for parallel plugin calls across multiple shipbuilding scenarios, automatically selecting matching tools |
| Single tool call timeout | 120–180 seconds | Matches the loading duration of ship design drawings and maintenance work orders, preventing failures when reading large documents |
| Historical interaction context count | First 8–12 entries | Adapts to scenarios with parallel processing of multiple work orders, avoiding overload of the context window |
| Field matching verification rules | According to classification society standard formats | Ensures accurate association of industry-specific fields such as equipment numbers and construction numbers |
| Sensitive data permission toggle | Enable filtering | Protects sensitive office data such as crew credentials and production progress |

## Three Common Configuration Errors
- Symptom: Database connection plugin calls fail after installation. The interface displays a server internal error. Cause: Database table field mapping for shipbuilding scenarios was not configured correctly. Format requirements for industry-specific fields such as equipment numbers and construction numbers were not addressed.
- Symptom: MinIO storage plugin cannot write or read data normally. Storage status cannot be confirmed. Cause: Storage bucket access permissions were not configured correctly. Or, insufficient space was reserved for storing large documents such as ship drawings and maintenance work orders.
- Symptom: Tool calls fail to return dataId. The corresponding field is empty in the returned result. Cause: Tool call result return configuration was not enabled. Or the context window was set too small, leading to incomplete capture of tool returned data.

## How to Verify Correct Configuration
- Manually trigger a tool call. Check whether the returned result includes correct industry-specific fields such as equipment numbers and construction numbers.
- Call the MinIO storage plugin. Upload a small ship design drawing. Check whether the corresponding file exists in the storage bucket with no permission errors.
- View plugin call logs. Confirm that the `toolChoice` parameter is active. Check that no timeouts or field parsing errors have occurred.
- Attempt to call the database connection plugin. Query a known maintenance work order. Confirm that the returned result matches the data in the database.
