# Internal Office and Employee Services for Shipbuilding: Forms and Interactions

## What the data for this category looks like
Internal office data for shipbuilding originates primarily from shop floor manufacturing execution systems (MES), ship operation and maintenance logs, personnel attendance systems, and material management systems. Data update frequency varies by business scenario: production work orders are generated and synced in real time, equipment maintenance records are updated after each maintenance task, and personnel attendance data is synced in batches monthly. The structure of individual documents includes fields such as ship name, workstation number, fault type, processing duration, and material requisition list. Field units include units, sets, hours, kilowatts, and others. Some fields must comply with standardized coding rules common in the shipbuilding industry.

## Constraints imposed on forms and interactions by these characteristics
The multi-source, heterogeneous data characteristics of shipbuilding require forms to support linked loading across multiple data sources, to avoid manual duplicate entry. Real-time updated production work orders require that form interaction response delays be controlled within a reasonable range, otherwise workshop scheduling efficiency will be affected. Standardized coding fields must include industry-specific validation rules to prevent input of content that does not meet shipbuilding specifications. The multi-item structure of material requisition lists requires forms to support dynamic addition and deletion of rows, to adapt to differences in material requirements across different work orders. Fields for equipment maintenance records must be linked to the unique ship identification, to ensure data traceability back to the corresponding hull.

## Three common mistakes
- Phenomenon: Concurrent submission requests occur when configuring multi-tool selection, causing the backend to return a 400 error. Cause: The submission timing of the `userSelect` component is not restricted, allowing multiple tool invocation requests to be triggered simultaneously.
- Phenomenon: An SSL error pop-up appears when using the voice input function. Cause: The secure communication protocol for the form is not configured, resulting in encryption verification failure during data transmission.
- Phenomenon: Users cannot select whether to skip the knowledge base retrieval step. Cause: The corresponding enumeration option is not configured in the `userSelect` component, and the trigger logic for the corresponding variable is not bound.

## How to confirm the configuration is complete
- Enter a shipbuilding industry-specific code, check if the built-in field rule prompt is triggered.
- Try adding or deleting entries in the material list, confirm that the form can dynamically adjust the number of rows.
- Trigger the voice input function, verify that data transmission completes normally without errors.
- After configuring user selection options, test whether the logical branch of the corresponding variable can be triggered correctly.
