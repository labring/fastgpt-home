# Internal Office and Employee Services for Telecommunications Engineering Construction: Multi-turn Dialogue and Prompt Engineering
## What the data for this category looks like
Internal office data for telecommunications engineering construction primarily comes from project management systems, construction log ledgers, material inventory systems, staff attendance records, and operation and maintenance inspection reports. Data is updated per single construction node or daily. Most documents are structured tables containing fields such as project ID, construction section, material specification, operation duration, and acceptance status. Units include meters, cubic meters, work hours, calendar days, and others. Some unstructured data consists of on-site construction photos and handwritten inspection records.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
The clear field structure of structured data requires prompt engineering to specify fixed field extraction rules, to avoid ambiguous outputs from the large model. Unstructured on-site photos and inspection records require multi-turn dialogue to gradually guide users to supplement context, to avoid overloading single inputs. Node-updated data requires specifying the current session’s associated project ID and construction section during dialogue, to ensure the called knowledge base data is the latest content for the corresponding period. The context of multi-turn dialogue must be limited to the current project’s construction cycle, to avoid mixing historical data from other projects that could interfere with results.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind project ID and construction section fields | Used to accurately associate exclusive project data for the current session, avoiding interference from cross-project data |
| `messages` | Retain the first 10 core conversation turns | Telecommunications engineering construction processes follow linear steps; excessive historical dialogue will disrupt the prompt engineering logic for current tasks |
| `chatId` | Bind to the current project’s session ID | Ensures multi-turn dialogue context only associates with the current project, without mixing data from other sessions |
| Maximum context length | 8000–12000 token | Project documents for telecommunications engineering often include long construction logs and material lists, requiring sufficient retention of historical dialogue and knowledge base recall content |
| Session context expiration time | 24 hours | Internal office scenarios mostly use single-day project operations as dialogue cycles; automatic cleanup of historical context after expiration avoids redundancy |
| Maximum input character count per dialogue | 5000 characters | Unstructured records from on-site inspections are often long texts, allowing full input before multi-turn processing |

## Three common configuration mistakes
- Phenomenon: After calling uploaded project construction logs in a dialogue, the results do not include content from the specified section. Cause: The `variables` for the current session’s construction section field are not bound, so the large model cannot accurately match the corresponding knowledge base data.
- Phenomenon: Dialogue response lags for more than 600 seconds after calling a local large model. Cause: The matching relationship between maximum context length and session context expiration time is not adjusted, leading to repeated loading of excessive historical data.
- Phenomenon: When attempting to display uploaded construction photos in a dialogue, no images appear in the interface. Cause: Association fields and display rules for images are not specified in the prompt engineering, so the large model does not trigger the image rendering logic.

## How to confirm the configuration is complete
- The session’s configuration panel is opened. The `variables` are checked to confirm they are bound to the current project’s exclusive fields, and that the bound fields match the fields of the project data.
- A test question including historical dialogue is initiated. The system’s ability to correctly recall project data from the corresponding period is verified, and the `messages` truncation rule is confirmed to take effect.
- A test construction material ledger is uploaded. A request to extract content from specified fields is initiated, and the system is confirmed to correctly include the uploaded data in the dialogue context.
- 24 hours are waited, then the same session is initiated again. The system’s automatic cleanup of historical context is verified, and the session expiration time configuration is confirmed to take effect.
