# Internal Office and Employee Services for Telecommunications Engineering Construction: Document Parsing and Chunking
This document is written for FastGPT v4.17.0.

## What the data for this category looks like
Internal office documents for telecommunications engineering construction mainly come from daily submissions by project teams, including project approval forms, construction logs, equipment ledgers, and acceptance reports.
Data update rhythm follows project milestones: construction logs are updated weekly, while acceptance reports and annual ledgers are updated monthly or per project milestone.
Documents include fixed structured fields such as project number, construction team, material specification, and acceptance date, paired with free-form on-site record paragraphs.
Engineering-specific units such as meters, kilovolts, and man-hours are used. Some documents include vector-format construction drawing PDFs and multi-sheet Excel ledgers.

## What constraints do these characteristics impose on the document parsing and chunking link
The mixed structure of documents in this category requires parsing logic to adapt to both structured fields and long-form content.
If chunking rules disrupt the context of structured fields, subsequent retrieval will fail to accurately match project information.
Large engineering drawing PDFs and multi-sheet ledgers increase parsing time. Insufficient timeout limits will cause parsing failures.
Frequently updated documents require stable and reliable parsing processes to avoid repeated parsing errors caused by improper configuration.
Document formats vary across different projects. Fixed chunking rules cannot cover all document types, requiring flexible adjustment of chunking logic.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the mixed structure of telecommunications engineering documents, balances single-chunk context length and retrieval granularity, and avoids single chunks exceeding model processing limits |
| `chunkSplitter` | Separate by paragraph + heading | Matches the chapter-based layout of documents, preserves the integrity of logical blocks in construction logs and acceptance reports, and avoids splitting paragraphs containing structured fields |
| `customPdfParse` | Enabled | Adapts to vector drawings, annotations, and marked information attached to engineering PDFs, and avoids loss of key engineering parameters from default parsing |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Compatible with large files such as large construction drawing PDFs and annual equipment ledger Excel files, meeting the upload requirements of documents in this category |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for long documents and large files, avoids parsing task failure due to timeout |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for different document types, adapting to the diverse format characteristics of documents in this category |

## Three common mistakes
- Symptom: Raw engineering files passed during node calls are not parsed, and the large language model cannot recognize the file content. Cause: The document parsing process of FastGPT is not enabled, raw files are directly passed as variables to the node, and the parsing and chunking steps are not completed.
- Symptom: Parsing errors occur after uploading engineering PDFs, returning `504 Gateway Timeout`. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration is not adjusted, and the default timeout duration is insufficient for parsing large construction drawing PDFs.
- Symptom: Calling the API to create a file collection does not include the `customPdfParse` parameter, resulting in lost drawing annotations and equipment number information in the parsed document. Cause: Custom parsing is not enabled for the complex format of telecommunications engineering PDFs, and the default parsing logic cannot adapt to vector marked content.

## How to confirm configurations are set correctly
- Upload a single engineering PDF over 100 MB, confirm that the upload progress completes normally, with no timeout or format errors.
- Call the API to create a file collection, include the `customPdfParse` parameter, and verify that the returned parsing status is successful.
- Review the parsed document chunks, confirm that each chunk contains a complete construction paragraph or structured field, with no key information forcibly split.
- Adjust `chunkSize` to 1000 characters, parse a long document, and check that the chunk length matches the expected range.

The values provided are common starting points and should be measured against the reader's own samples.
