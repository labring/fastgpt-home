# Internal Office and Employee Services for Telecommunications Engineering Construction: Deployment and Upgrade

## What the Data for This Category Looks Like
Data for telecommunications engineering construction internal office and employee services primarily originates from construction work order management systems, equipment inspection ledgers, employee attendance systems, and on-site operation and maintenance logs. Data update frequencies cover three categories: real-time for operation work order submission, daily for inspection record archiving, and monthly for construction progress ledger summarization. Document structures are divided into two types: structured and unstructured. Structured data includes fields such as work order ID, construction point longitude and latitude, equipment model, and processing duration, with units of degrees and hours. Unstructured data includes on-site inspection photos, voice logs, and scanned paper work orders.

## Constraints Imposed on Deployment and Upgrade
The multi-source heterogeneous data characteristics of telecommunications engineering construction impose clear constraints on FastGPT deployment and upgrade. Structured data must adapt to both relational and document databases, so `PG_URL` and `MONGODB_URI` must be correctly configured. Unstructured inspection photos and logs have large file sizes, so `STORAGE_S3_ENDPOINT` must be configured to connect to enterprise object storage services. Data concurrent access volume fluctuates with construction peak seasons, so `DB_MAX_LINK` must be set appropriately to avoid connection exhaustion. During cross-version upgrades, historical work order and employee data must retain structural compatibility. Intermediate version upgrade scripts cannot be skipped. Some deployment scenarios are located in remote construction sites, so extra attention must be paid to permission configuration issues after Docker container restarts. All these constraints are formulated based on the deployment logic of FastGPT v4.17.0.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `DB_MAX_LINK` | 10–20 connections | Adapt to concurrent work order access demand during construction peak seasons, avoid database connection exhaustion |
| `STORAGE_S3_ENDPOINT` | Fill in according to the object storage endpoint of the deployment region, such as `https://s3-cn-north-1.example.com` | Used to store unstructured engineering data such as inspection photos and construction logs |
| `PG_URL` | postgresql://<db_user>:<db_pass>@<db_host>:5432/comm_construction | Stores relational data such as structured work orders and employee ledgers |
| `REDIS_URL` | redis://:<redis_pass>@<redis_host>:6379/0 | Caches real-time work order status and employee online information to reduce database access pressure |
| `ROOT_KEY` | Random string generated by the enterprise security team | Configures the administrator permission key for the FastGPT platform to ensure internal access security |
| `FE_DOMAIN` | Enterprise internal office domain name, such as `https://comm-office.enterprise.com` | Configures the front-end access domain name to adapt to access rules for internal office scenarios |

## Three Common Misconfigurations
- Symptom: Model stream response is empty when calling internal tools such as getting current time. Cause: `REDIS_URL` is not correctly configured, causing session cache failure and failure to properly pass tool call context.
- Symptom: SQL permission error occurs after restarting Docker container. Cause: The permission of the local database mount directory was not configured to 755 during deployment; the container process cannot access the mounted data files on Ubuntu systems.
- Symptom: Some historical work order data cannot be loaded after cross-version upgrade. Cause: Intermediate version upgrade scripts were skipped, and data structure compatibility migration operations were not performed, resulting in mismatched data formats between new and old versions.

## How to Verify Proper Configuration
- Access the configured `FE_DOMAIN` to confirm that the front-end page loads normally with no domain resolution or cross-domain access errors.
- Run the built-in database connection test tool to verify the validity of connections configured via `PG_URL` and `MONGODB_URI`.
- Upload a test inspection photo to confirm that the storage service configured via `STORAGE_S3_ENDPOINT` can normally write and read files.
- Restart the Docker container and check the container logs to confirm there are no error messages related to database connections or storage permissions.

The values provided are common starting points and should be evaluated against local deployment samples.
