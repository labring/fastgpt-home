# Internal Office and Employee Services for Communication Towers and Infrastructure: Document Parsing and Chunking

## What Data for This Category Looks Like
Teams source core data for communication towers and infrastructure from daily operation and maintenance logs, quarterly inspection reports, asset ledgers, and maintenance work orders. Data sources include base station operation and maintenance systems, handheld inspection terminals, and asset management platforms.
Update frequencies fall into three categories: real-time updates for fault reports and temporary inspections, daily updates for ledger synchronization, and monthly updates for operation and maintenance report generation.
Most documents use structured tables and semi-structured text. Fields include tower number, tower height, load power, inspection time, fault level, and processing result. Common units are meters, kilowatts, hours, and counts.
Single-document size varies widely. Small inspection reports span tens of pages, while large monthly operation and maintenance reports can reach hundreds of pages.

## Constraints on Document Parsing and Chunking
The document characteristics of this category create multiple constraints for the parsing and chunking process.
A large share of content uses structured tables. Chunking must retain the associated integrity of entire row fields, and avoid splitting cross-column asset information.
Semi-structured text has clear chapter divisions and fixed fields. Chunking must match chapter boundaries to prevent disruption of operation and maintenance workflows.
Real-time updated fault work order texts are short, but batch uploads include high volumes of these documents. Administrators must control the document volume per parsing batch.
Large monthly reports have many pages and long parsing times. Adjust timeout thresholds to avoid parsing interruptions.
Document formats vary widely. Parsing rules must support PDF, Word, Excel, and other common formats.

## How to Set Configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 1000–1500 characters | Matches the single-paragraph text length of inspection reports and work orders, and avoids splitting complete fault handling workflows |
| `chunkSplitter` | Segment by headings and line breaks | Adapts to chapter divisions in semi-structured documents, and retains contextual associations for fields such as tower numbers and fault types |
| `customPdfParse` | Enable table structured parsing | Adapts to multi-column tables in asset ledgers and inspection reports, and extracts complete field information |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Matches the maximum size of single monthly operation and maintenance reports, and avoids upload timeouts |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Adapts to parsing time for multi-page PDF documents, and prevents interruptions during long document parsing |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for structured documents, and adapts to different types of operation and maintenance documents |

## Three Common Misconfigurations
- Parsing results are empty after uploading an inspection PDF. The cause is that the table structured parsing switch for `customPdfParse` is not enabled, which prevents correct extraction of multi-column tables.
- Fault handling workflows in maintenance work orders are split after chunking. The cause is that `chunkSize` is set too small, and does not match the text length of a complete single workflow.
- Parsing times out and interrupts when uploading large asset ledgers. The cause is that `PARSE_FILE_TIMEOUT_SECONDS` is set lower than actual parsing time, and does not adapt to processing time for multi-page documents.

## How to Verify Configurations Are Correct
- Upload a single 10-page structured inspection report, and check if the parsing result includes complete table fields and continuous text paragraphs.
- Upload a monthly operation and maintenance report under 500 MB, and confirm no error messages appear after the upload progress bar completes.
- Adjust `chunkSize` to 1200 characters, and test if chunking results do not split continuous fault handling descriptions.
- Check system logs to confirm parsing time does not exceed the set value of `PARSE_FILE_TIMEOUT_SECONDS`.

The listed values are common starting points. They should be evaluated against the user’s own samples.
