# Internal Office and Employee Services for Communication Towers and Infrastructure: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Communication towers and infrastructure data sources include operation and maintenance inspection records, base station equipment ledgers, supporting power maintenance manuals, regional base station layout documents, and internal operation and maintenance process specifications.
Daily inspection records sync in real time or daily after each inspection finishes.
Equipment ledgers sync quarterly when equipment is installed or decommissioned.
Process documents update irregularly when operation and maintenance regulations change.
Single documents include structured fields such as equipment number, longitude and latitude, maintenance cycle, and troubleshooting steps.
Units include dBm, watts, meters, hours, and other professional operation and maintenance units.
Some layout documents have multi-paragraph text-and-image explanatory content.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link?
Inspection records update in real time, so the retrieval pipeline must support near-real-time data recall. This prevents returning expired operation and maintenance information.
Equipment ledgers use structured fields, so retrieval must prioritize exact field matches. This avoids result deviations from fuzzy matching.
Professional operation and maintenance units appear in data, so retrieval must retain original field units. Do not convert or truncate units arbitrarily.
Long layout documents use text-and-image structures, so chunking must preserve field integrity. This avoids losing key associated information after splitting.

## How to set the configurations
| Configuration Item | Suggested Value | Basis for This Setting |
|---|---|---|
| `similarity` | 0.75–0.85 | Matches professional terminology and structured fields of tower operation and maintenance documents, filters low-relevance retrieval results |
| `limit` | Top 8 entries | Number of documents returned per retrieval round, adapts to the information carrying capacity of a single employee query, avoids excessive results interfering with judgment |
| `searchMode` | Exact match | For structured fields such as equipment number and longitude and latitude, prioritize returning exact matched equipment operation and maintenance data |
| `usingReRank` | Enabled | Reranks unstructured text such as inspection records, improves sorting accuracy of results related to troubleshooting |
| `datasetSearchUsingExtensionQuery` | Disabled | Most operation and maintenance documents have structured fields, no need to expand queries to avoid introducing irrelevant non-operation and maintenance content |
| `collectionIds` | Bound by operation/ledger/layout classification | Limits retrieval scope to knowledge base collections exclusive to communication towers, prevents cross-category content from being mixed in |

## Three common misconfigurations
- Phenomenon: Retrieval results include content unrelated to communication tower operation and maintenance. Cause: Failed to bind the exclusive knowledge base collection via `collectionIds`, so the retrieval scope covers irrelevant documents.
- Phenomenon: An error occurs when creating a new knowledge base after deploying FastGPT v4.17.0, and the interface prompts a field format exception. Cause: Failed to adjust the chunking rules for tower equipment ledger structured fields, resulting in long fields being truncated and unable to be parsed normally.
- Phenomenon: Unable to dynamically select a specified regional tower knowledge base via variables. Cause: Failed to correctly configure the variable binding logic for `collectionIds`, and did not map variables to the knowledge base collection IDs of corresponding regions.

## How to confirm the configuration is properly set
- Enter the knowledge base retrieval test interface, enter a specific equipment number, verify that the returned results only include operation and maintenance and ledger documents for the corresponding base station.
- Adjust the `similarity` parameter to 0.8, enter a troubleshooting keyword, check whether the sorted results follow fault priority.
- View the knowledge base import log, confirm that all tower-related documents have been successfully stored in the database, with no field format error reports.
- Test dynamic variable binding, enter keywords for different operation and maintenance regions, verify that the retrieval scope automatically switches to the knowledge base collection of the corresponding region.
