# Internal Office and Employee Services for Metal Material Processing: Vector Models and Indexes

## What This Category’s Data Looks Like
The internal office data for metal material processing comes from several sources: workshop operation logs, incoming material quality inspection reports, process specification documents, employee operation training materials, and incoming material inspection Excel files and multi-dimensional workshop capacity statistics documents in Lark or WeChat Work. The update rhythm varies widely: process specifications are updated quarterly or during process iterations, operation logs are generated in real time as equipment runs, and quality inspection reports are synced per production batch. Documents include structured tables with unit-labeled fields such as component proportion and hardness value, long-text operation instructions, multi-sheet Excel attachments, and multi-dimensional documents with nested chapters.

## Constraints Imposed on the Vector Model and Indexing Link
The multi-type data characteristics of metal material processing create multiple constraints for the vector indexing process. Structured tables contain unit-labeled process and quality inspection fields. When chunking data, retain field association relationships to avoid breaking parameter logic after splitting. Real-time generated operation logs need high-frequency incremental indexing configuration to prevent data synchronization delays. Multi-sheet Excel files and multi-dimensional documents with nested chapters require the indexing and parsing process to support cross-structure content extraction, to avoid missing associated data across pages and sheets. Documents that mix long-text operation instructions and short tables need a moderate chunk length. This ensures the semantic integrity of single chunks while adapting to the token limit of the vector model.

## How to Set Configurations
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Ensures semantic integrity for long-text operation instructions and structured tables in metal material processing documents, avoiding overly fragmented single chunks |
| Overlap Length | 100–150 characters | Retains cross-chunk process parameter associations, preventing key technical instructions from being truncated after chunking |
| `defaultToken` | 8192 | Matches the token limit of mainstream embedding models, adapting to vector generation after chunking long documents |
| `maxToken` | 4096 | Limits the token consumption of a single index vector, adapting to the memory resource limit of 8c16G GPU-free virtual machines |
| Single Search Limit | Top 10 entries | Covers the recall scope for common workshop process and quality inspection queries, balancing retrieval efficiency and recall rate |
| Reranking | Enabled | Optimizes semantic sorting after chunking long documents, improving result matching accuracy for employee inquiries |

## Three Common Misconfigurations
- Phenomenon: Multi-sheet Excel files imported from Lark or multi-dimensional documents with nested chapters only parse and index the first sheet or chapter, with some fields empty. Cause: The cross-sheet and cross-chapter content parsing switch is not enabled, resulting in incomplete extraction of incoming material inspection and capacity statistics data.
- Phenomenon: When deploying a PG database via Docker, indexing establishment times out, and host memory usage approaches the 16G threshold. Cause: The `maxToken` parameter is not restricted, leading to excessive memory consumption during vector generation from long document chunks, exceeding the resource limit of GPU-free virtual machines.
- Phenomenon: Embedding model calls report errors, and index vectors cannot be generated normally. Cause: The indexing model is not configured separately, and the global conversation model is mistakenly used as the indexing model, causing call conflicts.

## How to Confirm Proper Configuration
- Upload a multi-sheet incoming material inspection Excel file and a multi-dimensional document with nested chapters, and verify that all sheets and chapters are included in the index list.
- Submit a test query containing process parameters, and verify that the number of retrieved results matches the configured single search limit.
- View the vector model call logs, confirm that the indexing model and conversation model use different interface configurations, with no call conflicts.
- Simulate uploading a single real-time operation log, and verify that the incremental indexing synchronization status updates normally.

The values provided are common starting points and should be measured against the reader's own samples.
