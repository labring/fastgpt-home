# Internal Office and Employee Services for Expressway Operations: Deployment and Upgrade

## What the data for this category looks like
Data mainly comes from expressway toll systems, road patrol terminals, service area operation ledgers, and employee attendance systems. Update frequencies cover real-time (lane traffic, toll data), daily (attendance, patrol summaries), and on-demand generation (work order closure records). Documents primarily use structured table and JSON formats, with fields including lane number, patrol point ID, attendance duration, toll amount, and others. Their units are none, count, minutes, and yuan respectively. Some patrol files include images or videos, which must be transferred via object storage links.

## What constraints these characteristics impose during deployment and upgrade
Real-time traffic and toll data requires configuring a high-concurrency database connection pool during deployment to avoid connection exhaustion during peak hours. Multi-source heterogeneous data integration requires presetting storage configurations compatible with multiple data sources. Compatibility with existing data synchronization links must be retained during upgrades. Employee attendance and operation ledger data contains sensitive information, so a dedicated encryption key must be configured during deployment. A large volume of small file data from patrol points requires adapting batch read/write configurations for object storage. Data synchronization tasks must not be interrupted during upgrades, to prevent impacts on frontline operations.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `50–80 connections` | Adapt to the high-concurrency access requirements of real-time toll data |
| `MONGODB_URI` | Point to a local dedicated database cluster | Store patrol records and work order closure data to ensure read/write stability |
| `REDIS_URL` | Configure as a dedicated cache instance with 16 GB of memory | Cache lane traffic status data for frequent queries to reduce database load |
| `STORAGE_S3_ENDPOINT` | Adapt to the access address of the local object storage | Store images and video files from a large number of patrol points |
| `FILE_TOKEN_KEY` | 32-bit randomly generated encryption string | Encrypt access tokens for employee attendance files to ensure sensitive data security |
| `ROOT_KEY` | Key generated separately per deployment environment | Manage the highest permission verification for the platform to avoid cross-environment permission leaks |

## Three common mistakes
- A `version mismatch` error occurs after running the upgrade script. The cause is skipping versions that include upgrade scripts in between, and not following the sequential version upgrade process.
- Database connection timeouts appear frequently in background logs. The cause is failing to adjust the `DB_MAX_LINK` configuration, leading to connection pool exhaustion during high concurrency, which prevents processing real-time data requests.
- Employee attendance files cannot be downloaded normally or prompt permission denied. The cause is failing to configure `FILE_TOKEN_KEY` or the key generation does not meet requirements, leading to token verification failure.

## How to confirm the configuration is correct
- Run the version query command to confirm that the currently deployed FastGPT version is v4.17.0, which matches the target upgrade version.
- Access the database monitoring panel in the platform backend to confirm that the database connection count is within the preset range of `50–80 connections`.
- Upload a test employee attendance file to verify that an encrypted token is normally generated during download, with no access errors.
- Trigger a real-time lane data synchronization task to confirm that data can be written to the database normally, with no timeout or packet loss errors.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
