# Employee Service Desk for IT Service Management: HTTP Interfaces and External Systems

## What this category’s data looks like
Data sources for IT service desk employee service desk data are enterprise internal IT service management (ITSM) systems, office OA platforms, and employee self-service repair portals. Update frequency is real-time or near real-time, with synchronization completed within 1 to 5 minutes after a ticket is submitted. Each single data entry uses a ticket as the basic unit, and includes fields such as ticket ID, submitter account, problem category, current status, handler, response duration, and submission time. Ticket ID uses a string format. Response duration is measured in seconds. Status uses fixed enumeration values. The length of a single data entry is typically between 200 and 800 characters. Total data volume grows dynamically with the size of the enterprise’s employee base.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources are mostly heterogeneous internal enterprise systems, so interfaces must support different authentication mechanisms. Strict configuration of authentication parameters such as `Authorization` is required. Real-time update requirements mean interface timeout settings must match the typical ticket processing cycle to avoid interrupting synchronization due to timeouts. Fields contain employee privacy information, so interface requests and responses must strictly comply with data desensitization requirements. Sensitive content such as employee accounts and contact information must not be disclosed. Fixed field structures require interface parameters to be strictly aligned with the fields of the enterprise’s ITSM system to avoid data synchronization failures due to field mismatches.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {Enterprise Internal ITSM System API Key}` | Complies with the OAuth2 authentication specification of the enterprise’s internal system, ensuring lawful interface access permissions |
| Request timeout | `600 seconds` | Matches the typical response cycle for IT service desk ticket processing, avoiding synchronization interruptions due to timeouts |
| `variables` | `{"work_order_status": ["submitted", "in progress", "completed"]}` | Matches the standard enumeration values of the enterprise's ITSM system ticket status, used to filter valid ticket data |
| `responseData` | `$.data.records` | Adapts to the API response structure of most enterprise ITSM systems, accurately extracting ticket list data |
| Response field mapping | `{"work order ID": "id", "submitter": "creator", "issue category": "category"}` | Maps native fields of the enterprise's ITSM system to standardized fields recognizable by FastGPT |

## Three common configuration errors
- An interface call returns the `messages is empty` error. The cause is that required conversation context parameters are not configured in `variables`, resulting in missing necessary content fields in the request body.
- The interface returns a `401 Unauthorized` status code. The cause is that the `Authorization` parameter is not configured correctly, and the key format does not meet the authentication requirements of the enterprise’s ITSM system.
- Synchronized ticket data lacks the handler field. The cause is that the correct field extraction path is not specified in `responseData`, resulting in failure to match the handler data returned by the enterprise’s ITSM system.

## How to confirm configuration is complete
- Send a test request in the FastGPT v4.17.0 API debugging tool, and check if the returned HTTP status code is 200.
- View the synchronized employee service desk ticket data list, and confirm that required fields such as ticket ID, submitter, and problem category are included.
- Simulate submitting a test ticket, and check if the interface can correctly receive and synchronize relevant information for that ticket.
- Check that the request header carries the `Authorization` parameter in the correct format, with no extra spaces or formatting errors.
