# Employee Service Desk for IT Service Desks: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
IT service desk data originates from enterprise internal IT operation and maintenance ticket systems, device asset ledgers, employee IT help records, and official IT policy documents. Data updates follow three rhythms: tickets and help records update in real time after submission, device ledgers sync to the operation and maintenance platform daily, and policy documents update on demand. A single data entry includes fields including ticket ID, submitter identifier, device model, problem description, processing status, solution, and asset number. Time-consuming fields use minutes as their unit, and identifier fields use string format.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
Dispersed storage of tickets and help records requires multi-turn dialogue to associate historical context in `messages` to track employee help progress and ticket status. The multi-field structure of device ledgers requires prompt engineering to explicitly specify target extraction fields, avoiding confusion with irrelevant information. Real-time updated ticket data requires dynamic pulling of latest information during dialogue; static caching cannot be used. Spontaneous employee problem descriptions require the dialogue module to include automatic optimization functions, improving matching accuracy with the knowledge base.

The following configurations are based on the interface and parameter logic of FastGPT v4.17.0.
## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `messages` context window | 8000–12000 token | Covers complete conversation history and ticket information for IT service desk multi-turn interactions |
| Single recall result cap | Top 3 entries | Focuses on common IT failures, avoiding redundant information interfering with dialogue judgment |
| `variables` data source trigger | Update after each dialogue turn | Synchronizes the latest ticket status and device ledger data in real time |
| `chatId` storage duration | 7 days | Matches the typical processing cycle for IT help requests |
| Problem optimization toggle | Enabled | Corrects colloquial IT problem descriptions from employees, improving matching accuracy |

## Three common misconfigurations
- Symptom: When executing long-text tasks, the interface shows the task completed normally but throws the `The value of "offset" is out of range` error. Cause: The length of the `messages` context window is not limited, causing the loaded historical conversation and ticket data to exceed the token limit supported by the model, triggering an offset exception.
- Symptom: Operational information for a specified device cannot be retrieved during dialogue. Cause: Correct data source association rules are not configured in `variables`, making it impossible to match key fields such as the asset number mentioned by the employee.
- Symptom: Dialogue does not reference all uploaded document content after multiple files are uploaded. Cause: Context associated with multiple files is not passed according to the parameter specifications of the dialogue interface, causing some files to not be loaded into the dialogue reference scope.

## How to confirm configurations are properly set
- Initiate a simulated IT help request conversation, verify that the latest ticket status and device information are automatically synchronized during the dialogue.
- Enter a lengthy IT problem description, confirm that no offset exception-related errors are triggered.
- Upload multiple IT operation and maintenance related documents, initiate an associated query, confirm that the dialogue covers the content of all uploaded files.
- Access the corresponding conversation again after 7 days, confirm that historical context information cannot be retrieved for the conversation.
