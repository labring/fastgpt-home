# Employee Service Desk within IT Service Desk: Workflow Orchestration

## What the Data for This Category Looks Like
The data sources for an IT service desk fall into three main categories: internal enterprise IT ticketing systems, hardware asset ledgers, and IT operation and maintenance knowledge bases.
Ticketing system data holds real-time submitted fault requests. It includes fields such as ticket ID, submitter, device model, fault description, priority, and processing status. Updates are synchronized immediately after submission.
Asset ledger data contains static or periodically updated information for enterprise IT equipment. Fields include device number, work station location, and maintenance period. Updates are synchronized after daily inventory.
The IT operation and maintenance knowledge base includes structured fault troubleshooting manuals and hardware parameter documents. Updates are released after on-demand revision.
Data fields are mostly text and enumeration values. Units include tickets, devices, and characters (for fault descriptions). There are no unified binary or floating-point fields.
This scenario is compatible with the workflow orchestration feature of FastGPT v4.17.0.

## Constraints Imposed by These Characteristics on Workflow Orchestration
Decentralized data sources require workflows to use multiple nodes to pull data from different systems. A single data source node cannot provide full input.
Real-time updated ticketing data needs workflows to support session-based triggering. This avoids data lag.
The multi-field ticketing structure requires the workflow's `variables` parameter to map multiple core fields. Each processing node must obtain complete request information.
The enumeration-type priority field requires conditional branches in the workflow. Different priorities assign different processing nodes. Exceptions for empty fields must be handled to prevent process interruptions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Map ticket ID, device model, fault description | Bind core input fields of IT service desk tickets to cover basic fault handling requirements |
| Trigger Method | Auto-trigger on session open | Adapt to the usage scenario where the employee service desk does not require active message input |
| `nodeId` | Bind priority judgment node ID | Schedule different processing branches based on ticket priority, matching the scheduling rules of the IT service desk |
| Node Timeout Setting | 600 seconds | Cover the normal processing duration of IT fault troubleshooting to avoid early process termination |
| Knowledge Base Reference Validation | Enable content validity check | Verify whether the IT document content referenced by the large model complies with current operation and maintenance specifications |
| Single Reference Count | Top 3 entries | Control context length to avoid exceeding the model's processing limit |

## Three Common Misconfigurations
- No automatic response after session open: No initial reply is sent after the employee service desk window is opened. The root cause is that the workflow node configured to auto-trigger on session open is not set up.
- Abnormal global parameter assignment during API calls: Empty fields or parameter mismatches are returned by the interface. The root cause is that the `variables` parameter is not bound to the actual field structure of the IT service desk ticket.
- Invalid knowledge base reference content: Fault solutions returned by the large model reference outdated hardware maintenance documents. The root cause is that the knowledge base content validity check step in the workflow is not enabled.

## How to Verify Proper Configuration
- Manually open the employee service desk session window. Confirm that the workflow triggers automatically and returns an initial reply matching the ticket fields.
- Call the corresponding API interface. Pass test field values from the IT service desk ticket. Check that the returned result matches the configured priority branch logic.
- Submit a simulated test ticket. Confirm that the workflow node pulls ticket data correctly and verifies the compliance of knowledge base reference content.
- Check that the configured `variables` parameter binds all required IT service desk fields, with no missing or incorrect mappings.
