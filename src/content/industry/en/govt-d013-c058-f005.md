# Employee Service Desk for IT Service Desks: Tool Calling and Plugins

## What the data for this category looks like
The data sources for IT service desks come from three main categories: internal enterprise IT asset management systems, employee ticket submission platforms, and desktop operation and maintenance log libraries.
Ticket submission data syncs in real time. Asset inventory data updates in batches every early morning. Operation and maintenance logs archive hourly.
A single data document includes six core fields: ticket unique identifier, submitting employee ID, problem classification tag, associated device number, submission timestamp, and current processing status.
Each field uses a specific unit: string, numeric ID, enumerated classification, device serial number, ISO format time, and status enumerated value respectively.

## What constraints these characteristics impose on the tool calling and plugins workflow
The number of real-time submitted tickets fluctuates with office hours. Tool calling must adapt to concurrency limits for peak requests to avoid triggering rate limiting rules of source systems.
For daily updated asset data, set plugin pull frequency to no more than once per day. Higher frequency will repeatedly occupy synchronization resources of source systems.
The association between tickets and devices requires that the device number field must be included in tool calling input parameters. Otherwise, status queries for associated devices cannot be completed.
For operation and maintenance logs archived hourly, plugins must support specifying time range parameters. Plugins should only query data from the corresponding time period to reduce transmission overhead.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `auto` | Adapt to the automatic scheduling needs of multiple types of tools for IT service desks |
| `functionCall` | Enable forced mode | Ensure that tool calling input parameters strictly match core ticket fields |
| Plugin request timeout threshold | 300 seconds | Adapt to the fast response requirements of real-time tickets |
| Asset data pull frequency | 1 time per day | Match the daily update rhythm of asset data |
| Input parameter validation switch | Enable strict validation | Avoid calling failures caused by missing fields |
| Time range adaptation rule | Automatically set according to the ticket submission time period | Adapt to the hourly archiving feature of operation and maintenance logs |

## Three Common Misconfigurations
- Calling a Zhipu multi-modal tool returns a parameter error, while calling the OneApi interface via the OpenAI protocol works normally. The cause is that the input parameter format of the multi-modal tool is not adapted to the `functionCall` forced mode requirements of FastGPT, resulting in a mismatched parameter structure.
- The plugin editing page always displays "Unsaved", and the prompt does not disappear after clicking save. The cause is that in FastGPT v4.17.0, the associated fields in the plugin configuration are not correctly bound to the ticket system, and the successful save verification status is not triggered.
- Calling the reranker plugin returns false. The cause is that the plugin's access whitelist is not configured, causing the source system to reject the request, or the text length of the plugin input parameters exceeds the preset threshold.

## How to Verify Successful Configuration
- Submit a test ticket to trigger tool calling, and check whether the query plugin for the corresponding IT asset is automatically matched.
- View the plugin calling log to confirm that the input parameters include the core ticket fields, and the timeout time does not exceed 300 seconds.
- Check the execution record of the asset data pull task to confirm that the update is completed automatically every early morning.
- Enter the plugin editing page, save the configuration, and check whether the top page prompt disappears.
