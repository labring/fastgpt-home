# Employee Service Desk for IT Service Management: Document Parsing and Chunking

## What Data for This Category Looks Like
Enterprise internal IT ticket archives, device operation and maintenance manuals, account permission application process documents, common problem FAQ repositories, and Excel-formatted fault classification statistics tables are the primary sources of data for IT service desk employee service desks.
Data synchronizes in real time with ticket closure.
FAQ repositories are updated weekly.
Operation and maintenance manuals are iterated monthly.
Documents include structured fault classification tables, bulleted FAQs, and long-text operation guides.
Fields cover fault number, impact scope, resolution steps, and associated systems.
Units include hours, counts, and number of devices, among others.

## Constraints for Document Parsing and Chunking
Splitting structured fault classification tables by fixed length directly breaks row and column associations. Identify table structures first before splitting content.
Real-time updated ticket data requires low-latency parsing processes. Avoid timeouts that reduce synchronization efficiency.
Chunk long-text operation guides while retaining logical links between steps. Do not split content so thoroughly that the full operation process cannot be restored.
Split short FAQ text sparingly. Retain complete question-and-answer pair associations. Excessive splitting lowers retrieval matching accuracy.

## Configuration Settings
This article applies to the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to mixed-structure documents for IT service desks, balances contextual association and embedding accuracy, and covers the content length of common fault steps and FAQs |
| `chunkSplitter` | Semantic segmentation | Adapts to bulleted and step-based IT service desk documents, avoids rigid splitting that destroys logical associations |
| `customPdfParse` | Enable structured parsing | Adapts to complex layouts such as tables and flowcharts in operation and maintenance manuals, retains original document structure information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 seconds | Adapts to the fast parsing requirements of real-time ticket data, avoids synchronization failures caused by timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Covers the upload requirements of large operation and maintenance manuals and batch ticket archives, avoids file interception |
| `chunkSettingMode` | Manual configuration | Supports adjusting chunking rules separately for structured tables and long-text guides, adapting to multi-type document scenarios |

## Three Common Configuration Mistakes
- Observation: After uploading a PDF document containing images, the parsed result lacks text content from the images. Cause: The image OCR parsing switch for `customPdfParse` is not enabled, so only plain text content is extracted.
- Observation: Chunking splits question-and-answer pairs, reducing matching accuracy. Cause: `chunkSplitter` is set to fixed-length splitting instead of semantic segmentation, breaking complete FAQ question-and-answer logic.
- Observation: After uploading a large Excel fault classification table, parsed fields are misplaced. Cause: Structured table parsing mode is not enabled. Direct row-by-row splitting loses cross-row and cross-column associated information.

## How to Verify Correct Configuration
- Upload a PDF operation and maintenance manual containing images. Verify the parsed result includes text content from the images.
- Upload an Excel-formatted fault classification table. Confirm the parsed content retains the row and column association structure of the original table.
- Test uploading an archived ticket file under 100 MB. Confirm no timeout errors occur during the upload and parsing process.
- Submit a segment of FAQ text. Confirm the chunking result retains complete question-and-answer pairs without rigid splitting.
