# Employee Service Desk for IT Service Desk: Model Access and Configuration

## What the data for this category looks like
The data source for the employee service desk of an IT service desk is internal enterprise IT tickets submitted by employees. This includes equipment repair requests, account permission applications, software installation requests, troubleshooting records, and more.
Data updates occur in real time or on an hourly basis. A single request may carry multi-turn historical conversations and attachment content.
The document structure includes fields such as ticket ID, submitter account, problem description, classification tags, processing status, and submission timestamp. Ticket ID uses a string format, problem description is a free text block, and timestamps follow the ISO 8601 standard.

## What constraints these characteristics impose on model access and configuration
IT service desk ticket data includes both structured fields and unstructured free text. Update frequency is high, and single requests may carry multi-turn history. Context window limits must be implemented to avoid overflow.
Some tickets include screenshots or audio attachments. Configure model access parameters that support multimodal parsing.
Call parameter formats for locally deployed large models and online APIs must be consistent. Inconsistent formats cause call interruptions.
When accessing third-party models, confirm version compatibility to avoid call failures caused by dependency conflicts.

## How to set the configurations
These configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to multi-turn history and long problem descriptions of IT tickets, avoids context window overflow |
| `maxTokens` | `2000–3000 token` | Limits single model output length, adapts to detailed reply needs for ticket processing, prevents mid-output interruptions |
| `quoteMaxToken` | `500–800 token` | Limits the length of referenced context fragments, avoids redundant information interfering with the model's judgment of the core ticket problem |
| `toolChoice` | `auto` | Allows the model to independently select calling tools to handle tasks such as ticket classification and permission query, improving processing efficiency |
| `vision` | `enabled` | Supports parsing screenshots attached to tickets and content converted from audio to text, covering common attachment scenarios for IT service desks |
| `temperature` | `0.3–0.5` | Reduces output randomness, ensuring the accuracy and standardization of ticket replies |

## Three common configuration mistakes
- Phenomenon: The model stops outputting mid-process, returning truncated replies or empty tool call results. Cause: The `maxTokens` setting is too small, exceeding the single output limit of the model, or the context window `maxContext` is overloaded, causing the request to be terminated early.
- Phenomenon: After uploading an audio file, the speech-to-text process cannot be triggered, and the interface displays an unsupported file format. Cause: The `vision` parameter is not enabled, or the access permission for the corresponding speech-to-text model is not configured.
- Phenomenon: A version incompatibility error or 404 status code is returned when calling a third-party model. Cause: The specified version of the model dependency is not installed, or the API endpoint configuration is incorrect.

## How to verify the configuration is complete
- Submit a test ticket that includes a text problem and a screenshot attachment, verify the model can correctly parse the attachment content and generate an expected reply.
- Call the locally deployed large model and the online API separately, initiate test requests using the same parameters, verify the returned output length and context consumption match expectations.
- Check the model call logs to confirm `AIPROXY_API_TOKEN` verification is passed, with no permission errors or link abnormality prompts.
- Upload an audio file, verify it can be successfully converted to text and included in the model's processing context.

The values provided here are common starting points and should be measured against the reader's own samples.
