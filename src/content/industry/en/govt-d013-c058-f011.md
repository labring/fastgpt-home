# Employee Service Desk for IT Service Management: Forms and Interactions

## What the data for this category looks like
The employee service desk data for IT service management primarily comes from internal IT ticketing systems, asset ledgers, permission management systems, and employee repair records within Chinese state-owned enterprises and public sector organizations. Data update cycles fall into three categories: ticketing submissions are updated in real time, asset inventory data is updated daily, and permission change records are updated weekly. Documents primarily use structured forms, including fields such as ticket ID, applicant department, device model, fault type, submission time, and processing status. Field types include strings, numbers, and enumeration values, with units including characters, minutes, and entries. There is no large volume of unstructured free-form content.

## What constraints these characteristics impose on forms and interactions
The high proportion of structured fields requires forms to pre-set enumeration options to reduce manual input errors from employees. Real-time updated ticketing data requires the interaction layer to support real-time validation, avoiding submission of outdated or invalid information. Daily updated asset data requires the form's device selection component to regularly pull the latest data source, preventing eliminated devices from remaining selectable. Permission hierarchy requirements within state-owned enterprises and public sector organizations require form fields to be configured for visibility based on roles: regular employees can only view and fill in fields related to their own department, while administrators can access all configuration items.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Enable required field validation, limit input length to 200–500 characters | Adapt to the reasonable length of fault descriptions, application reasons and other content for IT service desk tickets, avoiding overly long content that hinders subsequent retrieval |
| `userSelect` | Enable department-level option filtering, set pull frequency to once per day | Match the daily update cycle of asset and permission data in state-owned enterprises and public sector organizations, ensuring options remain consistent with the latest data sources |
| Form preset options | Preset options based on IT service desk standard classifications, including hardware fault, software error, permission application, and device repair | Reduce classification errors from manual employee input and improve ticket routing efficiency |
| Attachment upload limit | Set to within 1000 MB, with individual files not exceeding 500 MB | Adapt to the conventional needs of employees in state-owned enterprises and public sector organizations when uploading device photos, system logs and other attachments |
| Session process locking | Enable fixed process after single selection | Ensure that after an employee initiates a service request, subsequent interactions always use the same processing link to avoid process confusion |

## Three Common Misconfigurations
- Symptom: An InvalidParameter error is returned when calling `userSelect`, prompting that the specified parameter is not configured. Cause: The associated data source for department-level filtering is not configured, resulting in an empty parameter that triggers parameter validation failure.
- Symptom: An Invalid array length error occurs when configuring form question and answer splitting. Cause: The content length of the form input exceeds the preset 200–500 character limit, causing abnormal array length during content splitting.
- Symptom: After selecting a process at the start of a conversation, subsequent interactions still require re-selecting the process type. Cause: The session process locking configuration is not enabled, causing the process selection state to reset with each interaction.

## How to confirm successful configuration
- Submit a test ticket, fill in a fault description exceeding 500 characters, and confirm that the system pops up an input limit exceeded prompt
- Switch test accounts from different departments, check whether the device options in `userSelect` only display asset content corresponding to the respective department
- Initiate two rounds of conversation: select the hardware fault process in the first round, confirm that the second round of conversation does not require re-selecting the process type
- Upload an attachment exceeding 1000 MB, confirm that the system blocks the upload and prompts that the attachment size exceeds the limit
