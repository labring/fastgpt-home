# Employee Service Desk for Personnel Policy Q&A: Workflow Orchestration

## What the data for this category looks like
Personnel policy Q&A data comes from officially issued internal personnel management documents of central state-owned enterprises and public service institutions. These include attendance and leave policies, rank promotion rules, salary calculation standards, and similar content. The update schedule follows official policy adjustments, typically once per year or quarter. Documents are structured by chapters and clauses, with fields such as clause number, effective date, applicable groups, and core rules. The length of a single document ranges from hundreds to thousands of characters, with no unified fixed format.

## What constraints these characteristics impose on workflow orchestration
The exclusive internal data source requires the workflow to bind to a specified internal personnel policy knowledge base, to avoid calling irrelevant external content. The chapter-and-clause structured documents require workflow configuration to precisely match clause retrieval logic, and excessive content splitting should be avoided. The effective date field requires the workflow to add a time filtering step, to only return currently effective policy content. The long single-entry content requires the workflow to limit the total length of content recalled in one pass, to avoid exceeding the model context limit.

## How to set configurations
These configurations apply to FastGPT v4.17.0

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Data Source Binding | Bind to the exclusive internal personnel policy knowledge base | Ensure only officially released personnel policy content is recalled, exclude irrelevant data |
| Context Window Limit | 800–1200 characters | Match the typical length of single personnel policy content, avoid exceeding the model context limit |
| `variables` configuration | Include the effective date and applicable position variables | Used to filter the effective status and applicable scope of policies, achieve precise recall |
| Node Timeout Setting | 600 seconds | Allow sufficient runtime for complex knowledge base queries and rule verification |
| `nodeId` configuration | Bind the unique identifier of the knowledge base query node | Ensure the workflow calls the specified personnel policy data source node |
| Single Recall Count | Top 3 entries | Avoid excessive content causing context overload, while covering core policy clauses |

## Three common configuration mistakes
- Phenomenon: The workflow returns policy content that includes expired clauses. Cause: No effective date filtering rule is configured in the workflow, and all historically stored documents are recalled directly.
- Phenomenon: Global variables do not update as expected after tool calls. For example, the set effective date variable value does not change. Cause: The fields returned by the tool are not correctly mapped to the corresponding variables in the `variables` configuration, resulting in the variables not being assigned values.
- Phenomenon: The knowledge base connection node reports an error, returning results related to "Access denied". Cause: No correct internal knowledge base access key is filled in the data source configuration, or the workflow node is not granted permission to access the corresponding knowledge base.

## How to confirm the configuration is complete
- Manually trigger the workflow, enter a test question containing specific personnel policy keywords, and check whether the returned content only includes currently effective policy clauses.
- View the workflow run logs, confirm that the variables configured in `variables` have been correctly updated according to the tool call results.
- Check the `nodeId` configuration, confirm that the workflow calls the corresponding node bound to the personnel policy knowledge base.
- Test a query containing expired policy keywords, confirm that the returned result is empty or prompts that the policy has expired.
