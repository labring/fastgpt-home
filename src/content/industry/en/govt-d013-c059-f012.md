# Employee Service Desk for Personnel Policy Q&A: Deployment and Upgrade

## What the data for this category looks like
Personnel policy Q&A data is sourced from internal personnel management documents of state-owned enterprises, government and public service institutions. These documents include employee handbooks, compensation management measures, leave and attendance regulations, job promotion rules, and more. They are presented in structured chapter format, with fields such as policy number, effective date, target audience, specific clauses, and exception notes. Effective dates are marked using the standard YYYY-MM-DD format.

Update frequency aligns with policy adjustments. Regular updates occur quarterly or annually as a concentrated batch. Temporary policy changes trigger real-time updates. Single document word counts vary widely, ranging from hundreds of words for temporary notices to thousands of words for complete management measures.

## What constraints these characteristics impose on deployment and upgrades
The internal origin of personnel policy data requires configuring an internal network document synchronization channel during deployment to prevent sensitive data leaks. The structured nature of documents demands retaining clause integrity during retrieval, so chunking rules must be adjusted during deployment to avoid splitting individual policy clauses.

The effective date field requires automatic filtering of expired policies during retrieval. Retrieval logic time filtering parameters must be updated synchronously during upgrades. The high-frequency update feature requires configuring an incremental synchronization mechanism during deployment to avoid excessive server resource usage from full synchronization.

This configuration logic is compatible with FastGPT v4.17.0.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://10.0.0.20:6379/1` | Retrieval results for personnel policy Q&A need caching. An internal network Redis instance ensures access speed and data security. Select database 1 to isolate business data. |
| `STORAGE_S3_ENDPOINT` | `http://10.0.0.15:9000` | Used to store policy document attachments and historical versions. Internal network object storage reduces cross-network transmission latency. |
| `DB_MAX_LINK` | `15` | Concurrent request volume for personnel policy Q&A is moderate. This setting prevents database connection exhaustion and ensures service stability. |
| Maximum context length | `8000–12000 characters` | Single personnel policy documents have relatively long length. This configuration retains complete clause context to improve answer accuracy. |
| Document synchronization frequency | `Daily incremental synchronization` | Adapts to the regular update rhythm of personnel policies, synchronizing the latest policy content in a timely manner. |

## Three common mistakes
- Phenomenon: A Markdown export button is displayed in the embedded iframe, and it cannot be closed via configuration. Cause: The document export function is not disabled in the front-end configuration items, or the corresponding rendering logic is not commented out in the source code.
- Phenomenon: Only XML or JSON code blocks are returned after calling the MCP plugin, and AntV charts are not rendered. Cause: The rendering template for the MCP plugin is not configured, or the front-end code block automatic rendering switch is not enabled.
- Phenomenon: Pulling the arm64 version image fails during docker deployment upgrade, or an image repository error occurs. Cause: The image tag for the arm64 version is not specified, or correct image repository access permissions are not configured.

## How to confirm the configuration is complete
- Access the internal network deployed employee service desk address, retrieve common personnel policy clauses, confirm that the returned results include policy effective date and target audience information.
- Upload a new version of the personnel policy document, wait for synchronization to complete, then perform a retrieval, confirm that the new policy content appears normally in the returned results.
- Check the background monitoring panel, confirm that the database connection count does not exceed the `DB_MAX_LINK` configuration value, and there are no abnormal service runtime errors.
- Execute the docker upgrade command, use the specified arm64 version image address to pull the image, confirm that there are no image pulling or startup errors.
