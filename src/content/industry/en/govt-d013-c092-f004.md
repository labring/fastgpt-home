# Employee Service Desk for Reimbursement Rule Q&A: Workflow Orchestration

## What Data for This Category Looks Like
Reimbursement rule Q&A data comes from internal enterprise financial system documents, reimbursement guideline manuals, and special policy notices. The update schedule follows adjustments to enterprise financial policies, with no fixed cycle.
Documents are categorized by reimbursement scenario, covering travel expenses, office supplies procurement expenses, entertainment expenses, and other categories. Each category includes fields such as maximum limit (unit: yuan), voucher type requirements, approval hierarchy, and effective date.
Some documents include special case explanations, such as extra subsidies for cross-regional business trips. Field types include three categories: numerical values, text, and enumeration values.

## Constraints on Workflow Orchestration
The multi-scenario classification feature of reimbursement rule data requires the workflow to first use a scenario matching node to filter corresponding rules. This avoids interference from irrelevant rules on retrieval results.
Amount fields with units require the workflow to add a variable verification step. This ensures extracted values match their units, preventing format errors.
The non-fixed update schedule requires the workflow to support manually triggered or event-triggered knowledge base synchronization nodes. This avoids use of outdated rule data.
The scattered multi-source document sources require the workflow to integrate inputs from multiple document upload nodes. It then uniformly organizes these inputs into retrievable knowledge base entries.

## How to Set Up Configurations
The following configuration recommendations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Form Input Node | Enable "Auto Extract Variables", bind the `variables` parameter | Reimbursement Q&A requires receiving reimbursement scenario, amount and other information submitted by employees. The `variables` parameter can directly reuse variables defined within the workflow |
| Document Upload Node | Only allow uploading PDF and Word format files, single upload limit is 100 MB | Reimbursement rule documents are mostly official office documents. This format covers common release formats, and 100 MB can accommodate complete annual reimbursement guidelines |
| DB Node | Enable automatic parsing of query results | When reimbursement rules are stored in a database, query results are mostly structured data. Automatic parsing reduces subsequent code processing steps |
| Variable Reference Configuration | Reference variables corresponding to the `nodeId` of the form input | Avoid hardcoding parameters, ensuring that reimbursement amount and scenario from form input can be transferred to the rule verification step in real time |
| Timeout Setting | 600 seconds | Reimbursement rule retrieval involves multi-document sharding and database queries. 600 seconds can cover the complete rule matching process |
| Concurrency Throttling Setting | Limit single node concurrency to 2 times/second | Avoid exceeding service bearing limits during high-concurrency calls |

## Three Common Configuration Mistakes
- Phenomenon: The default value of the form input node cannot retrieve content after referencing the `variables` parameter. Cause: The corresponding variable was not defined in advance during the workflow initialization phase, or the variable scope does not cover the current node.
- Phenomenon: The DB node returns empty results after querying reimbursement rules. Cause: No correct database query conditions were configured, or rule data was not synchronized to the target database.
- Phenomenon: High-concurrency calls to the MCP node return none, and the corresponding logs show request timeout or rejection. Cause: No concurrency throttling parameter was configured for the node, exceeding the service bearing limit causing requests to be discarded.

## How to Confirm the Configuration Is Complete
- Manually trigger the workflow, enter test reimbursement scenarios and amounts, check whether the variable output of each workflow node correctly matches preset rules.
- Upload a test reimbursement rule document, confirm that the document upload node can normally parse and synchronize to the knowledge base, with no format error prompts.
- Simulate concurrent requests at 2-3 times per second, check whether the return results of the MCP node are stable, with no null values.
- View the workflow execution logs, confirm that the execution status of all nodes is successful, with no error messages.
