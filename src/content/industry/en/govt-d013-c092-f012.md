# Employee Service Desk for Reimbursement Rule Q&A: Deployment and Upgrade

## What the data for this category looks like
The data for reimbursement rule Q&A is sourced from officially released internal financial reimbursement management measures, departmental supplementary rules, and annual policy adjustment notices from Chinese public sector and central state-owned enterprise entities. Data updates are triggered by financial policy adjustments, typically occurring every six months or after a single policy revision.
The structure of each individual rule document is fixed, with four core modules: applicable scope, reimbursement category limits, approval processes, and voucher requirements. Fields include applicable job levels, maximum reimbursement amounts, application frequency limits, and compliant voucher types. Units are mostly yuan, times, and calendar months.

## What constraints these characteristics impose during deployment and upgrade
The data source consists of internal private documents, so local private vector databases must be used during deployment. Calling public external knowledge base services is prohibited.
Update cycles are triggered by policy adjustments, so the upgrade process must support quick replacement of full or incremental vector datasets. No fixed periodic synchronization is required.
Fixed document structure requires configuring chapter-level chunking rules during deployment. This ensures precise matching of corresponding rule modules during retrieval.
Fields include clear numerical values and units, so unit matching verification must be enabled during deployment. This prevents Q&A failures caused by unit conversion errors.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://[username]:[password]@[local IP]:27017/fastgpt?authSource=admin` | Historical records and vector indexes for reimbursement rule Q&A require persistent storage. Use a private MongoDB instance for local deployments |
| `REDIS_URL` | `redis://:[password]@[local IP]:6379/0` | Used to cache frequently queried reimbursement rule results, reducing redundant computation overhead |
| `STORAGE_S3_ENDPOINT` | `http://[local MinIO IP]:9000` | Required to store uploaded reimbursement rule PDF/Word documents. Use an S3-compatible private storage service for local deployments |
| `DB_MAX_LINK` | `20–30 connections` | Concurrent query volume for reimbursement rule Q&A is typically low. Avoid excessive connections consuming local server resources |
| `FILE_TOKEN_KEY` | Configure with a custom random string | Used to verify the legitimacy of requests to upload reimbursement rule documents, preventing unauthorized access |

## Three common mistakes
- The symptom is a 503 status code returned when calling the reimbursement rule Q&A interface. The cause is an excessively low `DB_MAX_LINK` configuration, which exhausts the database connection pool and prevents new requests from being processed.
- The symptom is no output from workflow node runs after local deployment, with a prompt indicating no running results. The cause is incorrect configuration of `FILE_TOKEN_KEY`, which prevents uploaded reimbursement rule documents from being correctly read and parsed.
- After upgrading to FastGPT v4.17.0, locally deployed reimbursement rule Q&A cannot call local vector models. The cause is incompatibility between the new vector library protocol and the old index format. Full rule vector datasets must be regenerated.

## How to confirm proper configuration
- Run the built-in database connectivity test to verify that `MONGODB_URI` and `REDIS_URL` can establish normal connections.
- Upload a properly formatted reimbursement rule test document to confirm that `STORAGE_S3_ENDPOINT` can store the document normally and return a valid file access path.
- Submit a test query matching preset rules to verify that the returned Q&A results exactly match the rule content.
- Adjust the `DB_MAX_LINK` value and observe database connection status under concurrent requests to confirm that the configuration fits the actual concurrent scale of the business.
