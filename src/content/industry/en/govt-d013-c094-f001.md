# Employee Service Desk for New Hire Onboarding: HTTP Interfaces and External Systems

## What the data for this category looks like
Data mainly comes from enterprise HR systems, onboarding approval workflow tools, and enterprise contact directory platforms. Full batch synchronization is completed 1 to 3 days before onboarding. When temporary information such as job position adjustments or workstation changes occurs on the onboarding day, it is pushed in real time via interfaces. A single data entry includes fields including name, employee ID, department, job position, onboarding date, office workstation, and mentor employee ID. The main field types are text, date, and integer, with no multi-level nested structures.

## What constraints these characteristics impose on HTTP interfaces and external systems
Batch synchronization requires the interface to support paginated pulling or batch data receiving, to avoid timeouts caused by excessive data volume in a single request. Real-time updated temporary information requires the interface to support low-latency pushing or callback mechanisms to ensure information synchronization timeliness. The standardized field structure with no multi-level nesting requires the request body to strictly match preset field names, and no undefined fields can be added. For data security requirements in central government-owned enterprise scenarios, the interface must carry valid authentication credentials via the `Authorization` parameter, and reject unauthorized requests. The fixed number of fields per data entry eliminates the need for dynamic adaptation to field changes, reducing the complexity of interface parameter verification, but strict verification of field format validity is required. ## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {internal enterprise authentication token}` | Complies with central government-owned enterprise interface authentication specifications, ensuring the security and validity of new hire onboarding data transmission |
| `variables` | `{"employee_id": "${external_data.employee_id}", "entry_date": "${external_data.onboarding_date}"}` | Maps core new hire data passed by external systems to globally available variables, for precise calls in onboarding guidance scripts |
| Interface timeout setting | `60 seconds` | The volume of single new hire onboarding data is small, 60 seconds is sufficient to complete the request and response process, avoiding timeout interruptions |
| `responseData` | `Extract fields: employee ID, name, department, mentor employee ID` | Only retain core fields required for onboarding guidance, reduce invalid data transmission, and improve interface processing efficiency |
| Batch request limit | `Maximum 50 entries per request` | Adapts to the batch export restrictions of enterprise HR systems, avoiding interface rate limiting triggered by excessive data volume in a single request |

## Three common mistakes
- Phenomenon: The interface returns a `401 Unauthorized` status code, and the interface prompts that the token is invalid. Cause: The valid authentication token in Bearer format is not carried according to the requirements of the `Authorization` parameter, or the token has expired and has not been updated.
- Phenomenon: The onboarding guidance script cannot read externally passed new hire information. Cause: The fields of the external system are not correctly mapped via the `variables` parameter, or the variable name referenced in the script does not match the configured variable name.
- Phenomenon: The interface request is interrupted during batch synchronization of onboarding data. Cause: The number of new hire data entries in a single request exceeds the configured batch limit, or the request frequency exceeds the interface rate limiting rules.

## How to confirm the configuration is complete
- Call the test interface, check if the returned `responseData` only contains the core fields specified in the configuration, with no extra data.
- View the interface authentication log, confirm that the token format carried by the `Authorization` parameter meets the requirements, with no format errors.
- Trigger variable calls in the onboarding guidance application, confirm that the script can correctly read externally passed new hire information.
- Initiate a single batch request, check if the interface can normally receive and process new hire data that meets the configured limit.
