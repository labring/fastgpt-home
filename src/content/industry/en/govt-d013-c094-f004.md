# Employee Service Desk for New Hire Onboarding: Workflow Orchestration

## What the data for this use case looks like
Organizations source new hire onboarding data from enterprise HR management systems, onboarding approval workflow forms, and scanned copies of offline onboarding documents. The update cadence follows two patterns: full batch synchronization of all employee information 1 to 3 days before onboarding, and one-time synchronization of updated details such as new hires' assigned contacts and workstation assignments on the day of onboarding. The document structure is a collection of structured fields, including employee name, employee ID, department, position, onboarding date, contact information of assigned contact, and other fields. Most field types are text and date enumeration values, with no complex nested unstructured content. This page is compatible with FastGPT v4.17.0.

## What constraints do these characteristics impose on workflow orchestration
The structured data of new hire onboarding requires teams to prioritize clear field mapping rules when building workflows. No additional processing is needed for unstructured content chunking and extraction. The dual update cadence means workflows must support both scheduled and event triggering. This adapts to batch preparation and real-time synchronization scenarios. The fixed field set lets teams preset general templates for workflow node parameters. It also supports dynamic replacement of `variables` field values to fit personalized information for each employee. The limited number of entries per batch allows setting a low concurrency limit for workflows. This avoids redundant resource occupation.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Mode | Scheduled trigger 1 day before onboarding date + event trigger on onboarding day | Matches the batch preparation and real-time synchronization requirements of new hire onboarding |
| Variable Mapping | Bind `variables` fields synchronized from the HR system | Ensures employee information read by the workflow is consistent with enterprise HR data |
| Node Timeout | 300-600 seconds | Adapts to the processing duration of single-batch new hire onboarding data |
| Retry Count | 2 times | Prevents workflow execution failure caused by temporary network fluctuations |
| `nodeId` Binding | Bind the `nodeId` of the corresponding approval node | Ensures workflow node execution order matches the onboarding guidance process |
| Global Variable Presets | Preset default values for fixed fields such as employee ID and department | Adapts to temporary data scenarios where some fields are not synchronized |

## Three Common Mistakes
- Issue: Workflow calls return the error `Key is error. You need to use the app key rather than the account key`. Cause: Teams fail to use the application-level key, and mistakenly use the account key to initiate the workflow call.
- Issue: The number of global variables available for selection in the workflow frontend is insufficient, and cannot match all fields of onboarding information. Cause: Teams fail to correctly configure the synchronization fields for the `variables` parameter in the FastGPT backend, resulting in incomplete loading of selectable variables in the frontend.
- Issue: API consumption exceeds expectations when calling the workflow via the login-free window. Cause: Teams fail to configure the call permission scope for the workflow, resulting in users consuming the global API quota through their calls.

## How to Confirm the Configuration Is Complete
- View the workflow trigger configuration page, confirm that the scheduled trigger time and event trigger type match the onboarding guidance process nodes.
- Initiate a test call, pass simulated employee information, and check whether the field values output by the workflow match the passed `variables` parameters.
- Verify the workflow node configuration, confirm that the node order bound by `nodeId` matches the approval and notification process of the onboarding guidance.
- Call the login-free test link, check whether the API consumption record matches the expected quota for a single call.

The values provided are common starting points and should be measured against the reader's own samples.
