# Employee Service Desk for New Hire Onboarding: Model Access and Configuration

## What the data for this category looks like
The data for new hire onboarding mainly comes from onboarding lists exported from the enterprise internal HR system, office system configuration guidance documents, onboarding process specifications released by the compliance department, and department-specific contact person information tables. The data update rhythm changes with new hire onboarding batches, with exclusive information updated 1 to 3 days before each batch’s onboarding, and annual compliance documents updated quarterly. The document structure includes structured fields and unstructured text. Structured fields include employee ID, affiliated department, contact person name, workstation number, and onboarding deadline, with units of alphanumeric combinations, full department names, Chinese names, alphanumeric combinations, and date formats respectively. Unstructured text includes department function introductions, training course outlines, and system operation guides.

## What constraints these characteristics impose on the model access and configuration link
The mixed data structure of structured and unstructured data requires that model access must support combined calls for field extraction and full-text retrieval. The high-frequency updates of exclusive information require that the knowledge base synchronization frequency matches the update rhythm of new hire batches to avoid returning expired content. The need for precise matching of multiple fields requires that parameter extraction rules be clearly defined during configuration to ensure the model can accurately associate employee exclusive information with corresponding knowledge base content. The seriousness of compliance documents requires limiting the model’s creative output to avoid fictionalized process or permission information.

## How to configure
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | New hire onboarding data includes multiple documents, which need to accommodate complete onboarding processes, exclusive information, and compliance requirements to avoid context truncation |
| `maxTokens` | `4000–6000 token` | When answering onboarding-related questions, complete permission descriptions, process steps, and deadlines need to be covered to ensure no information is omitted |
| `temperature` | `0.1–0.3` | Onboarding information must remain highly accurate, reducing the model’s random creativity to avoid returning content that does not match actual conditions |
| `toolChoice` | `auto` | Automatically call knowledge base retrieval for the latest onboarding data and exclusive information, without manually specifying tools |
| Knowledge base synchronization frequency | 1 time per day | Match the update rhythm of exclusive information to ensure returned content is always the latest version |

## Three common configuration mistakes
- Phenomenon: The model does not reference the specified new hire onboarding manual file, instead returning general onboarding process content. Cause: The target file was not added to the knowledge base group bound to the application, or the configuration item for forced use of the bound knowledge base was not enabled.
- Phenomenon: The deployed reranking model request has no response, returning a 500 status code. Cause: The custom request address does not include the complete API route path, or the correct authentication token was not filled in the configuration.
- Phenomenon: After a new hire asks a question, the answer truncates key workstation allocation information. Cause: The `maxTokens` setting value is too small to accommodate complete permission and workstation description content.

## How to verify successful configuration
- Upload a test onboarding document containing unique information, submit a question that includes this unique information, and confirm that the answer directly references the content within this document.
- Fill in the test reranking model address and authentication information, submit a test request, and confirm that the returned result includes reranked sorting markers.
- Adjust the `temperature` parameter to 0.2, submit 3 identical onboarding question requests, and confirm that the answer content is consistent without deviations.
- Submit a test request through the official API call interface, and confirm that the returned result meets the preset format and field requirements.

The values provided are common starting points and should be measured against the reader's own samples.
