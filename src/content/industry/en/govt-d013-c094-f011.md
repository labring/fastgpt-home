# Employee Service Desk for New Hire Onboarding: Forms and Interactions
Reference only; verify against the target FastGPT release and deployment documentation.

## What the Data for This Category Looks Like
The data source for new hire onboarding primarily comes from employee onboarding files in the HR management system, unified company onboarding process templates, and department-specific docking documents.
Data is updated in batches by HR 1 to 3 days before onboarding. Single incremental updates trigger on the onboarding day if there are temporary job adjustments, equipment application changes, or similar situations.
The document structure is fixed into four modules: onboarding instructions, department docking checklist, equipment application form, and permission activation process.
Fields include employee ID, affiliated department, onboarding date, contact person name and ID. Employee IDs are pure numeric strings. Dates use the YYYY-MM-DD format.

## What Constraints These Characteristics Impose on the Forms and Interactions Link
Since the data source comes from structured HR system data, the forms and interactions link must first automatically pull already synchronized employee ID, department, and other fields. This prevents new hires from re-entering existing information.
Temporary incremental data updates require forms to support real-time refresh of dynamic content such as contact persons and equipment application items. This stops outdated information from being displayed.
The fixed four-module document structure requires the form’s interaction modules to correspond one-to-one with the document structure. Module order cannot be adjusted arbitrarily, and optional fields cannot be added or removed.
Fixed format requirements for fields mean forms must include built-in format validation rules. These rules block input content that does not meet specifications.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | Enable auto-fill mode | Matches structured employee data synchronized from the HR system, reduces duplicate data entry |
| `formInput` | Bind to HR system employee file interface | Ensures auto-filled fields match the employee’s actual onboarding information |
| Input character limit | 2000 characters | Adapts to the needs of long text input for onboarding instructions and process descriptions |
| `userSelect` | Enable dynamic refresh of options | Adapts to temporarily updated department contact persons and equipment lists on the onboarding day |
| Form submission timeout threshold | 30 seconds | Adapts to the response duration of HR system interfaces in an intranet environment |
| Single retrieval limit | Top 5 entries | Matches the information density requirement for single-round onboarding process guidance |

## Three Common Misconfigurations
- Phenomenon: The onboarding knowledge base associated with the form returns empty results, or returns documents unrelated to the current employee. Cause: The knowledge base call triggered by the form is not limited to the dedicated new hire onboarding guide knowledge base. The `userSelect` component is not used to bind the current employee’s department tag to filter the retrieval scope.
- Phenomenon: Only a single static result is received after submitting the form, and no streaming update progress prompt is displayed. Cause: Streaming output configuration for the interaction link is not enabled. Chunked returned content is not processed correctly.
- Phenomenon: Auto-filled fields such as employee ID and department are empty in the form. Cause: The data source binding rules for `formInput` are not configured correctly. The HR system employee onboarding file interface is not associated.

## How to Verify Proper Configuration
- Open the form preview page, enter a test employee ID, check if affiliated department, onboarding date, and other fields are auto-filled.
- Simulate a temporary modification to department contact person information, refresh the form page, check if contact person options are updated synchronously.
- Enter an employee ID that does not meet format requirements (such as containing letters), check if a format error prompt appears.
- Submit the test form, check if streaming returned progress prompts and final process guidance results are received.
