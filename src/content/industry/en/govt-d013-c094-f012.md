# Employee Service Desk for New Hire Onboarding: Deployment and Upgrade
This document applies to FastGPT v4.17.0.

## What the data for this category looks like
Data for new hire onboarding comes from basic employee files in the enterprise HR management system. It also comes from onboarding process specification documents from the administrative department, job guidance manuals from each department, and office resource checkout lists.
The update cadence follows two steps. First, batch import full materials 1 to 3 days before onboarding. Second, synchronize real-time changes such as assigned contacts and workstation assignments on the first day of onboarding.
The document structure includes structured fields and unstructured materials. Structured fields include employee ID, affiliated department, job type, onboarding date, assigned contact name and contact information. Unstructured materials are PDF-format job descriptions and office equipment usage guides.
Field units: employee ID is a string with no unit identifier, job type is an enumerated value, checkout quantity uses "piece(s)", training duration uses "hour(s)".

## What constraints do these characteristics impose on deployment and upgrade workflows?
The mixed structured and unstructured data characteristics of this category create three constraints for deployment and upgrade.
First, connect to structured employee data from the HR system. Configure stable database connection parameters to ensure reliable batch synchronization and real-time updates.
Second, the category includes PDF-format unstructured onboarding guidance documents. Configure appropriate file storage endpoints to ensure normal upload and parsing of large files.
Third, data is divided by department, with significantly different update cadences. Reserve vector database sharding adjustment space during upgrades. This prevents confusion between onboarding content from different departments.
Additionally, real-time changes to assigned contact information require reserved adjustment room for cache parameters during deployment. This stops synchronization delays from affecting service response.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Enter the connection string of the enterprise self-built MongoDB, including authentication information and database name | Store structured data of employee files and onboarding processes, requires guaranteed connection stability |
| `PG_URL` | Enter the connection address of the enterprise PostgreSQL database, configure read-write separation permissions | Store vector indexes and historical conversation records, adapts to complex queries of structured data |
| `REDIS_URL` | Configure as `redis://:password@address:port/database number`, set connection pool size to 20–30 | Cache real-time synchronized assigned contact information and workstation assignment data, reduces call pressure on HR systems |
| `STORAGE_S3_ENDPOINT` | Enter the endpoint address of the enterprise object storage, configure a dedicated storage bucket for onboarding documents | Store unstructured materials such as PDF-format onboarding guidance and equipment usage guides |
| `DB_MAX_LINK` | Set to `100–150` | Adapt to database concurrent connection requirements during batch onboarding, avoid connection exhaustion |
| `FILE_TOKEN_KEY` | Generate a 32-bit random string as the key | Sign temporary tokens for file uploads, ensure access security of unstructured materials |

## Three Common Errors
- Phenomenon: After deployment, uploaded onboarding documents cannot be recognized by the system. No attachment parsing results appear in the conversation window, and no error logs are generated. Cause: `STORAGE_S3_ENDPOINT` is not configured correctly, or the storage bucket has insufficient permissions. This causes files to fail to upload normally to the storage node.
- Phenomenon: Partial employee files are lost during batch onboarding data synchronization. Database connection timeout error messages appear. Cause: The `DB_MAX_LINK` parameter is not adjusted. The concurrent connection count exceeds the database upper limit, causing synchronization tasks to interrupt.
- Phenomenon: Real-time updated assigned contact information cannot be displayed in a timely manner. Conversation response delay exceeds 10 seconds. Cause: `REDIS_URL` is not configured, or cache parameter settings are too small. This prevents caching of real-time changing data, causing each request to call the HR system interface.

## How to Confirm the Configuration is Complete
- Log in to the FastGPT backend. Enter the database configuration page in system settings. Verify the connection status of `MONGODB_URI` and `PG_URL`, and check whether the connection normal status is displayed.
- Upload a test onboarding guidance PDF. Check whether the file can be uploaded normally and displayed in the storage node. Check whether the parsed text content can be retrieved in the knowledge base.
- Initiate a simulated new hire query, such as "Where is my onboarding workstation?". Check whether the system can return workstation assignment information for the corresponding department, and that the response time meets expectations.
- View the system monitoring panel. Confirm that the database connection count does not exceed the set value of `DB_MAX_LINK`, and there are no frequent connection timeout alerts.

The values provided are common starting points and should be measured against the user's own samples.
