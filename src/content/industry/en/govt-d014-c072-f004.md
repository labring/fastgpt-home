# Hotline Knowledge Base and Ticket Assistance for Follow-Up Record Summaries: Workflow Orchestration

This configuration guide applies to FastGPT v4.17.0

## What the data for this category looks like

Follow-up record summary data originates from government hotline and state-owned enterprise customer service follow-up ticket systems, and is updated synchronously when the corresponding follow-up ticket is completed. Each single document contains six fixed fields: ticket associated ID, follow-up object number, follow-up initiation time, core communication content summary, customer feedback items, and preliminary processing suggestions. All fields are natural language text, and there is no unified fixed character length limit for a single document.

## What constraints do these characteristics impose on the workflow orchestration link

Since the data comes from the ticket system and is updated synchronously when the ticket is completed, the workflow must be configured with a trigger timing of after the corresponding ticket status changes to completed. There is no unified character length for a single document, so the workflow's context window configuration must adapt to widely varying text inputs to avoid truncating core communication content. The fixed six-field structure requires the workflow to predefine field extraction rules to ensure each field is correctly identified and passed. For content primarily in natural language, the workflow must be configured with a text preprocessing node to filter redundant expressions and improve subsequent processing quality.

## How to Configure the Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Configure the ticket associated ID as the incoming parameter | Enable data linkage between the workflow and the ticket system to accurately pull corresponding follow-up records |
| `nodeId` | Configure as the unique identifier of the core extraction node | Ensure accurate invocation of the specified node in the workflow |
| Trigger Timing | After the ticket status changes to completed | Match the characteristic that follow-up record summaries are updated synchronously when the ticket is completed, to avoid invalid triggers |
| Context Window | 800–1200 characters | Adapt to the character span of a single follow-up record summary to avoid truncating core communication content |
| Single Pull Quantity | 1 | Match the processing requirements of a single follow-up record |
| Timeout Threshold | 300 seconds | Prevent workflow failure due to waiting for ticket data or processing timeout |
| Field Extraction Rules | Configure via preset field mapping | Match the fixed field structure of follow-up record summaries to ensure each field is correctly identified and passed |
| Cache Duration | 24 hours | Adapt to the update rhythm of follow-up records |

## Three Common Misconfigurations

- Code running steps not displayed in the workflow debugging panel: The code node visibility setting in the workflow orchestration interface was not enabled, causing corresponding steps to be hidden during debugging.
- Unexpected intermediate results of nested workflows: Non-core nodes were not filtered when importing external workflows, leading to redundant nodes interfering with data flow, which matches the abnormal intermediate result issues reported by the community.
- Unable to call the workflow in chats after configuration is complete: The workflow was not bound to the question-and-answer plugin of the corresponding knowledge base, or the workflow call permission for the plugin was not enabled.

## How to Verify the Configuration is Correct

- Trigger a test ticket, check whether the complete fields of the corresponding follow-up record summary can be pulled correctly.
- View the workflow running logs to confirm there are no error prompts about context truncation or timeout.
- Test the call of the nested workflow, confirm that the intermediate result only contains the output content of the core extraction node.
- After binding the workflow to the knowledge base plugin, initiate a test query for the corresponding ticket, confirm that the workflow triggers normally.
