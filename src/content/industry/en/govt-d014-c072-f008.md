# Hotline Knowledge Base and Ticket Assistance for Follow-Up Record Summaries: Document Parsing and Chunking

## What the data for this use case looks like
This guide is written based on FastGPT v4.17.0. Data for follow-up record summaries comes from hotline ticket follow-up sessions at state-owned enterprises, government agencies, and public service providers, generated by extracting core content from transcribed calls. Updates are triggered by the closed-loop process of the corresponding ticket. Each document corresponds to one follow-up ticket.

Document structure includes structured metadata and unstructured summary content. Fields include follow-up number, follow-up time, contact personnel, user requests, processing result, satisfaction score, and more. Some fields have units: for example, call duration is measured in minutes, and satisfaction score uses a 100-point scale. Unstructured content consists of colloquial dialogue excerpts.

## What constraints these characteristics impose on document parsing and chunking
Each document corresponds to one follow-up ticket, with a mixed structure of structured metadata and unstructured summary content. Chunking must retain the association between metadata and corresponding summaries to avoid losing contextual association after splitting.

Structured content with clear units in fields requires identifying field boundaries to avoid splitting field values from their units. Unstructured content is colloquial excerpts, so chunking must adapt to semantic boundaries to avoid breaking semantic coherence with fixed-character splitting.

Update timing is triggered by tickets, so the parsing process must adapt to rapid response requirements. Excessive parsing time must be avoided to prevent impact on ticket processing efficiency.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | The unstructured content of follow-up record summaries is mostly colloquial dialogue excerpts. This range retains complete semantic units and avoids semantic breaks |
| `chunkSplitter` | Split by semantic clauses | Adapts to the semantic boundaries of colloquial content, avoids breaking dialogue logic by splitting with fixed characters |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–90 seconds | Parsing time for a single follow-up record summary is short. This range covers normal parsing durations and avoids timeout failures |
| `chunkSettingMode` | Manual configuration | Parameters must be adjusted for the mixed structure of individual tickets to adapt to splitting rules for structured fields and unstructured content |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Single follow-up record summary files are small in size. This upper limit meets batch import needs and avoids resource waste |

## Three Common Errors
- Structured fields and unstructured content are split in post-parsing chunking results. This manifests as inability to associate corresponding content during retrieval. The cause is failure to configure `chunkSplitter` to split by semantic clauses, using only fixed-character splitting which breaks semantic association.
- Incorrect configuration of `trainingType` prevents tool calls from triggering. This manifests as logs showing successful parameter parsing but no tool execution. The cause is failure to set `trainingType` to the correct type for this scenario. This issue corresponds to common community feedback about tool call exceptions.
- Parsing fails after uploading a follow-up record summary file, shown as a prompt that the file cannot be opened. The cause is failure to enable the `customPdfParse` configuration, which prevents recognition of structured field formats. This issue corresponds to common community feedback about document parsing failures.

## How to Verify Correct Configuration
- Upload a single follow-up record summary document, check that parsed structured fields are fully retained without splitting or loss.
- Adjust the `chunkSize` configuration, check the semantic integrity of chunking results, confirm no semantic breaks occur in individual chunks.
- Test parsing time for a single document, confirm no timeout error is triggered.
- Batch import multiple follow-up record summaries, confirm all parsing tasks are completed with no abnormal failure records.

The values provided here are common starting points and should be measured against the reader's own samples.
