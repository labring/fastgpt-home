# Hotline Knowledge Base and Ticket Assistance for Ticket Automatic Classification: Tool Calling and Plugins

## What this category of data looks like
The data for this category comes from the ticket archive library and real-time call transcription stream of government hotline systems. Each entry corresponds to one independent ticket. The document structure includes ticket unique identifier, user call transcription text, initial classification suggestion, processing status, and associated request fields. There is no fixed batch update cycle. Data updates in real time as tickets are created, their status changes, or they are routed. The minimum storage unit is a single ticket. All fields are text or enumeration types, with no complex nested structures.

## What constraints do these characteristics place on tool calling and plugins
Ticket text is mostly colloquial transcription content with inconsistent formats. This requires tool calling to support adaptive input processing. Ticket data routes in real time along service workflows. This requires tool calling to support low-latency triggering, and to bind the ticket unique identifier as call context to avoid data mixing. Government tickets involve sensitive public information. This requires tool calling configurations to include permission verification and sensitive information filtering rules. Classification tags are pre-defined government service enumeration values. This requires tool calling return results to match the official classification system, and no custom tags can be returned.

## Configuration Instructions
This document is written based on FastGPT v4.17.0. The following are the configuration notes for tool calling and plugins:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Adapts to the colloquial, non-standard input format of ticket text |
| `functionCall` | Bind the government hotline pre-defined classification tag set | Ensures return results match the official classification system |
| Call trigger timing | Within 10 seconds after ticket creation | Meets the real-time response requirements of hotline services |
| Context binding fields | Ticket ID, call transcription text | Ensures tool calling is associated with the correct ticket data |
| Call timeout threshold | `300 seconds` | Balances real-time performance and tool calling success rate |
| Sensitive information filtering switch | Enabled | Complies with government data security compliance requirements |

## Three common configuration errors
- Symptom: Classification results returned after tool calling do not match pre-defined tags, and fields are empty. Cause: The government hotline official classification tag set was not bound in the `functionCall` configuration, resulting in no compliance check for return results.
- Symptom: The variable update tool does not automatically update classification call count statistics. Cause: Result statistics binding was not enabled in the tool calling configuration, or the variable update trigger condition was not associated with the tool execution completion event.
- Symptom: Tool calling times out, returning status code 504. Cause: The call timeout threshold was set too short, or the ticket transcription text is too long, exceeding the tool's single-processing limit.

## How to verify successful configuration
- Import a test ticket, trigger tool calling, and check if the returned results match the pre-defined classification tag set.
- View tool calling logs, and confirm that the context binding fields (ticket ID, call transcription text) were correctly passed.
- Manually trigger a tool call, and check if the variable update record generates a corresponding classification call count entry.
- After enabling the sensitive information filtering switch, input test sensitive content, and confirm that the filtering rules take effect.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
