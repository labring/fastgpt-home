# Hotline Knowledge Base Maintenance: Hotline Knowledge Base and Ticket Assistance - Citation Source and Traceability

## What the Data for This Category Looks Like
This category's data primarily comes from standard question-and-answer libraries compiled by frontline customer service staff, standardized reply texts after ticket closure, and archived high-frequency user inquiries. Data updates are triggered on demand. When customer service staff add or revise a Q&A pair, the content is synced to the repository immediately. Ticket-related records are updated when the associated ticket is closed.
The document structure of a single data entry includes standard question text, official reply text, affiliated business segment tag, and associated ticket number. Most field types are string and date types. There is no fixed character limit for reply texts, and adjustments are made flexibly based on business scenarios.

## Constraints on Citation Source and Traceability From Data Characteristics
The data characteristics of this category impose clear constraints on the citation source and traceability process.
First, the data includes an associated ticket number field. During traceability, this number must be extracted as a source credential to ensure traceability to specific ticket closure records.
Second, reply texts are standardized official content. After recall, the original text must be returned directly, and no generative model rewriting is allowed.
Third, data updates are triggered on demand with no fixed synchronization cycle. Therefore, index refresh must support both manual trigger and short-cycle automatic synchronization modes to match the flexible update rhythm of the knowledge base.
Fourth, reply text lengths vary widely. The context processing logic must adapt to different lengths to avoid truncating critical business information.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific parameter settings are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `responseData` | Set to return only source data | Ensure the system returns the original knowledge base text directly, avoiding generative rewriting of content |
| `quoteMaxToken` | 1500–2000 token | Adapt to the common length of hotline reply texts, avoiding truncation of critical business information |
| `detail` | Enable and include associated fields | Meet traceability requirements, enabling direct association with specific ticket closure records |
| Index refresh trigger method | Manual trigger + daily automatic synchronization | Match the on-demand update rhythm of the hotline knowledge base, while balancing timeliness |
| Recall result limit | Top 3 entries | Control context length, ensuring returned source data is the most matching standard Q&A pairs |

## Three Common Misconfigurations
- Phenomenon: Returned reply content does not match the standard knowledge base text, with rewritten or added content. Cause: The `responseData` configuration is not set to return only source data mode, and the system calls generative logic to process recalled content.
- Phenomenon: Associated ticket number does not appear in traceability information, making business closure traceability impossible. Cause: The source data detail return function of the `detail` configuration item is not enabled, and associated fields are not included in traceability output.
- Phenomenon: Index refresh takes an extended period of time to respond or the task gets stuck. Cause: No reasonable `quoteMaxToken` upper limit is set, leading to excessive resource usage from processing lengthy reply texts, causing blockages.

## How to Verify Successful Configuration
- Submit a standard question already included in the knowledge base, and check if the returned reply exactly matches the knowledge base original text.
- Check the traceability fields in the returned results to confirm whether associated ticket numbers and other source data identifiers are included.
- Manually trigger a knowledge base index refresh, wait for the task to complete, and check if the latest Q&A pairs have been recalled.
- Adjust traceability-related parameters to verify whether the reply text processing logic matches business requirements.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
