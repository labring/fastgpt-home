# Hotline Knowledge Base and Ticket Assistance for Hotline Knowledge Base Maintenance: Deployment and Upgrade

## What the data for this category looks like
The data mainly comes from ticket texts archived by hotline agents, original records of user incoming calls, official policy documents and service specifications. Update rhythms are adjusted based on business changes. New daily questions are synchronized in real time after being entered. Policy updates are imported in batches quarterly. The document structure uses a single question-and-answer pair as the basic unit. It includes four core fields: original question text, standard reply, associated ticket number, and service scenario tag. There are no nested hierarchies. The length of a single document ranges from 100 to 500 characters.

## What constraints these characteristics impose on deployment and upgrade
Since the data centers on short-text question-and-answer pairs and update frequencies fluctuate greatly, configure a storage engine that supports batch reading and writing of small files during deployment. This avoids excessive storage overhead for single data entries. The upgrade process must support incremental synchronous updates to prevent service interruptions caused by full reconstruction. Since documents include business fields such as associated ticket numbers, reserve a field mapping interface during deployment. This ensures compatibility with the fields of existing ticket systems. The length of a single document falls within a fixed range. The upgraded retrieval model must adapt to this length to avoid reduced retrieval accuracy. Hotline services require continuous operation, so use a gray release mode for upgrade operations. Gradually switch traffic to avoid impacting external services.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `STORAGE_S3_ENDPOINT` | Configure using the dedicated S3-compatible endpoint provided by the cloud service provider | Adapt to small-file batch storage needs for the hotline knowledge base, ensuring upload and retrieval stability |
| `MONGODB_URI` | Copy the read replica set connection address of the production environment | Share read and write pressure on the primary database, adapting to large-volume, frequent read/write knowledge base data |
| `REDIS_URL` | Configure as a dedicated cluster address on port 6379 | Cache frequently retrieved question-and-answer pairs to reduce database query latency |
| `FILE_TOKEN_KEY` | Set to a random string longer than 32 characters | Secure the file upload interface and prevent unauthorized access |
| `ROOT_KEY` | Configure as a strongly random string accessible only to internal operations | Restrict access to the platform backend to avoid misoperations |
| `FE_DOMAIN` | Fill in the public network access domain name of the deployment platform | Ensure domain name matching between the frontend interface and backend interface, avoiding cross-domain request failures |

## Three common mistakes
- Phenomenon: After upgrading to FastGPT v4.17.0, RAG file upload returns a Failed to parse URL error. Interface logs show the `/model/getProviders` path failed to parse. Cause: `MONGODB_URI` or `REDIS_URL` was not configured correctly. This prevents the service from loading dependent configuration items during startup.
- Phenomenon: After migrating S3 storage, hotline knowledge base file upload fails, but the template import function operates normally. Cause: `STORAGE_S3_ENDPOINT` was not configured correctly, or the S3 storage bucket permissions were not granted to the FastGPT service account.
- Phenomenon: Uploading a text dataset in the conversation window fails, prompting a parameter format error. Cause: `FILE_TOKEN_KEY` was not set correctly, causing identity verification failure for the upload interface.

## How to confirm configuration is complete
- Execute the FastGPT built-in health check interface. Confirm that `/api/health` returns a 200 status code, and the storage and database modules show normal status.
- Upload a test short-text question-and-answer pair. Check whether it can be successfully stored in the knowledge base and return matching results during retrieval.
- Access the frontend interface corresponding to `FE_DOMAIN`. Try logging in to the backend with an administrator account, and confirm the configuration item page loads normally.
- Trigger an incremental update task. Check whether the knowledge base update log shows successful synchronization with no abnormal errors.
