# Hotline Knowledge Base and Ticket Assistance for Response Template Recommendation: HTTP Interfaces and External Systems

This document applies to FastGPT v4.17.0.

## What This Category of Data Looks Like
Response template recommendation data draws from historical closed hotline tickets, approved standard response libraries, and common user consultation question libraries. Data automatically syncs to the interface data source within 24 hours after a ticket is closed. Administrators can manually trigger full or incremental updates as well.
A single data entry’s document structure includes consultation question text, standard response text, ticket category tags, closing time, and user satisfaction score fields. Response text is counted in characters, ticket entries in units, and update cycles in days.

## Constraints Imposed on HTTP Interfaces and External Systems
The data includes ticket category tags, so the interface must support receiving category parameters to accurately recall matching response templates. The 24-hour update cycle requires the interface cache validity period to not exceed this duration, to avoid returning expired data. Single response text lengths vary, so the interface must support returning response bodies with large character volumes. The data includes satisfaction score fields, so the interface must allow configuration of whether to return this field for subsequent filtering. External systems must pass relevant context parameters for the current ticket when calling the interface. These characteristics together define the specific rules and verification logic for interface configuration.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Interface Timeout | 600 seconds | Response template recall requires associating historical ticket data, leading to a long query chain. This setting avoids mid-query timeout interruptions |
| Cache Validity Period | 1440 minutes | Matches the 24-hour automatic update cycle of matching data, ensuring the timeliness of recalled data |
| Authorization Configuration | Carry a token via the `Authorization` header | Complies with HTTP interface standard authorization specifications, ensuring the security of the call chain |
| Return Field Filtering | Only return the question and standard response fields in `responseData` | Reduces unnecessary data transmission, adapting to the lightweight call requirements of external systems |
| Global Variable Passing | Pass ticket category tags via the `variables` parameter | Supports accurate matching of corresponding response templates based on the current ticket’s category |

## Three Common Misconfigurations
- When calling a published interface, global variables are not correctly passed, and the interface returns no matching response results. Cause: Ticket category tags and other global variables are not passed via the `variables` parameter, so the interface cannot filter matching response templates per preset rules.
- Calling the interface after configuring authorization parameters returns a 401 status code. Cause: The token value for the `Authorization` header is not spliced in standard format, or valid token content is not provided.
- Calling the interface returns far fewer response entries than expected. Cause: A reasonable recall upper limit parameter is not set, or the cache validity period is set too long, leading the interface to return expired old data.

## How to Verify Successful Configuration
- Call the interface with a valid `Authorization` token, and check that the returned HTTP status code is 200.
- Pass preset ticket category tags to the `variables` parameter, and check that the returned results include standard response content for the corresponding category.
- Compare the fields returned by the interface with the configured filtering rules, and confirm that only the expected question and standard response fields are included.
- Wait longer than the cache validity period, then call the interface again, and check whether the returned data has been updated to the latest response templates.
