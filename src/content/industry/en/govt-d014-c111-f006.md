# Hotline Knowledge Base and Ticket Assistance for Reply Template Recommendation: Source Citation and Traceability

## What this category of data looks like
Reply template recommendation data is sourced from historical interaction records of hotline tickets, official public policy documents, and internal business knowledge base entries. The update schedule is as follows: historical ticket replies are synced to the knowledge base in real time, while policy documents are updated weekly. The document structure includes matching intent tags, standardized reply text, source type identifier, update time, and affiliated classification fields. The length of a single reply text mostly falls within the 200–800 character range. The source field includes specific file paths or ticket numbers. The content on this page is based on the functional logic of FastGPT v4.17.0.

## What constraints do these characteristics impose on the source citation and traceability link
Data sources for this category are scattered, and update schedules vary significantly. This requires the traceability link to accurately distinguish between historical ticket replies and policy document source types, to avoid confusion of authority levels. Real-time sync configuration must adapt to the timeliness requirements of different sources, to ensure that traceability points to the latest version of content. The matching intent tags in the document structure require the traceability link to associate source entries corresponding to the relevant intent, to ensure that the reply and source matching logic strictly corresponds. The length range of a single reply text requires the traceability link to control the displayed content length, to avoid information overload.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapt to the length range of single reply texts, to avoid context window overflow |
| `responseData` | Enabled | Extract complete metadata of source fields, to support traceability verification |
| `detail` | Full | Retain all fields of source documents, including update time and source path |
| Single recall limit | Top 5 entries | Control the number of displayed sources, to avoid interfering with agent judgment |
| Timeout threshold | 60 seconds | Adapt to response timeliness requirements in hotline scenarios |
| Source sorting rule | Sort by authority | Prioritize displaying authoritative sources such as policy documents |

## Three Common Mistakes
- Context citations fail to render Markdown formatting. Cause: `detail` is not set to Full, only plain text fragments are returned, and formatting markers are lost.
- Some questions cannot be associated with knowledge base files. Cause: The `responseData` configuration is not enabled, and the system only calls internal historical ticket replies without associating official knowledge base entries.
- Context citations are accidentally removed. Cause: The `responseData` configuration is incorrectly disabled, causing all source identifiers to be hidden.

## How to Confirm the Configuration Is Complete
- Submit a hotline-related query, check whether source identifiers and update times are displayed below the reply.
- Enter the configuration page, confirm that the `responseData` switch is in the enabled state, and complete source metadata can be extracted from the logs.
- Adjust the `quoteMaxToken` configuration, submit a long-text reply query, and check that the reply is not truncated.
- View the source sorting rule, confirm that the configuration has taken effect, and authoritative sources are displayed first.

Note: The values listed above are common starting points, and should be evaluated against the reader's own samples.
