# CDN and Edge Acceleration Configuration Code and Change Review Assistance: Multi-Turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category comes primarily from CDN consoles, DNS resolution records, access logs, and monitoring alerts. Daily produced documents include domain access forms, cache rule configuration tables, refresh and preheating operation records, and fault analysis reports. Data fields include domain names, cache TTL, edge node IP addresses, peak access bandwidth, alarm trigger thresholds, and more. Update frequency is daily or real-time when configuration changes are made.

## Constraints Imposed on Multi-Turn Dialogue and Prompt Engineering by These Characteristics
Data for this category originates from multiple sources and updates in real time following configuration changes. This requires multi-turn dialogue to retain the last 3 configuration change contexts to avoid referencing expired data. Fixed fields in daily documents require prompt engineering to explicitly specify extraction of core fields such as domain names, cache TTL, and node status, to reduce interference from invalid information. The unstructured nature of access logs and alert data requires the dialogue link to be configured with targeted recall rules for log fields, to ensure rapid association of historical records for abnormal nodes during reviews.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to unique session identifier | Retain configuration change history within a single session, ensuring context consistency for multi-turn reviews |
| `messages` | Retain the last 5 rounds of dialogue content | Adapt to short-cycle multi-turn interactions for CDN reviews, avoiding context overload |
| `variables` | Bind to domain name and cache TTL fields | Automatically populate core business variables for review scenarios, reducing repetitive input |
| Maximum context length | 8000–12000 characters | Adapt to the content length of single-batch cache rule documents, avoiding truncation of critical configurations |
| Single search limit | Top 5 entries | Match the number of node records and alert items that need verification in daily reviews, controlling information density |

## Three Common Misconfigurations
- After configuring input prompts and the word bank, preset guide questions do not display in the dialogue interface. This occurs because the session initialization guide trigger switch is not enabled, or the word bank is not associated with the current application's knowledge base.
- After uploading an XLSX-format cache rule document, the dialogue interface cannot read the file content. This occurs because the parsing rule for table documents is not configured, or the table content extraction function is not enabled during knowledge base import.
- In multi-turn review dialogues, the large language model does not reference the latest configuration change records. This occurs because the number of retained context rounds or context length is not restricted, causing old data to overwrite the latest changes.

## How to Confirm Configuration Is Complete
- The application configuration interface in FastGPT v4.17.0 may be accessed to check if `chatId` is bound to a unique session identifier.
- A test dialogue may be initiated, with the input "Query the cache rules for the target domain", to verify that the large language model automatically populates preset business variables.
- A cache rule XLSX document may be uploaded, with the question "Repeat the cache configuration in the document" initiated, to confirm that the large language model can read field information within the table.
- More than two rounds of configuration change questions may be initiated, to verify that the dialogue interface retains context information from the previous round.
