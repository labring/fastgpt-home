# Code and Change Review Assistance for CDN and Edge Acceleration Configuration: Tool Calls and Plugins

## What the data for this category looks like
This category of data primarily comes from CDN consoles, DNS resolution records, edge node access logs, and monitoring alert systems. Daily associated documents include domain name access forms, cache rule configuration forms, refresh and preheating operation records, and fault root cause analysis reports. Data updates occur either in daily summaries or in real time when configuration changes are made. Fields include domain names, cache validity periods, edge node IP addresses, access traffic, alert trigger thresholds, and more. There is no unified fixed statistical caliber. Data is only archived per single change or cycle. The content of this page is compatible with FastGPT v4.17.0.

## Constraints imposed by these characteristics on the tool calls and plugins workflow
Data for this category is scattered across multiple sources, with highly varied update rhythms. Tool calls must adapt to API authentication and format requirements of different data sources, including CDN consoles, DNS resolution, and access logs. Real-time synchronization delays following configuration changes must be addressed. Daily associated documents are centered around the domain name dimension. Plugins must bind domain name context to complete rule validation and change checks. High-frequency time-consuming tasks such as cache rule debugging and abnormal node troubleshooting require tool calls to encapsulate standardized operation interfaces. The change review phase must also validate the legality of fields such as cache TTL and refresh volume, to prevent access exceptions caused by parameter errors.

## How to configure
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the need for automatic multi-tool calls in CDN scenarios, no manual tool type specification required |
| `functionCall` | `enabled` | Supports structured parameter returns, making it easier to extract core fields such as cache rules and domain name information during change reviews |
| Tool call timeout | `300 seconds` | CDN consoles and edge node interfaces typically respond within 200 seconds; this value covers most normal call scenarios |
| Maximum number of items returned per tool call | `Top 10 items` | Limits the return volume of CDN access logs and alert data to prevent content truncation caused by exceeding the context window |
| MCP authentication configuration | Custom Header | Adapts to the authentication requirements of most enterprise CDN interfaces, meets the access needs of authenticated SSE interfaces |
| Tool call trigger timing | Automatically triggered after change submission | Validates configuration legitimacy early during the review phase, reducing the time spent manually checking domain name filings and cache rules |

## Three common misconfigurations
- Symptom: 401 unauthorized error returned when calling SSE-type CDN interfaces with Header authentication. Cause: Custom authentication Header fields were not correctly added in the MCP configuration, or the field values did not match the API keys from the CDN console.
- Symptom: After enabling `functionCall` configuration, the cache rule parameters returned by the model are still in natural language format and cannot be directly used for change validation. Cause: `toolChoice` was not set to `auto`, or the correct tool call template was not specified, causing the model to not return parameters in structured format.
- Symptom: When attempting to call the Mermaid MCP Server to generate flowcharts, valid image links cannot be obtained in the workflow. Cause: The callback address of the MCP Server was not configured in the tool call settings, or access permissions for the corresponding port were not opened, causing generated images to not be accessible normally.

## How to confirm the configuration is properly set up
- Submit a test domain name change configuration, trigger automatic tool calls, and check if existing cache rules and filing status for that domain name can be retrieved.
- Initiate a simulated call to verify that the custom Header authentication is working, and confirm that the returned CDN access log data format meets expectations.
- Check the workflow logs to confirm that the `functionCall` and `toolChoice` configurations have been correctly loaded, with no missing parameters or format errors.
- Test the Mermaid MCP Server call, and confirm that the generated flowchart link can be previewed normally in the FastGPT chat interface.
