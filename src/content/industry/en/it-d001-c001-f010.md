# Code and Change Review Assistance for CDN and Edge Acceleration Configuration: Citation Sources and Traceability

## What This Category of Data Looks Like
Daily documents typically include domain access forms, cache rules, refresh and preload records, and fault analysis reports. Data sources include CDN consoles, DNS resolution records, public network access logs, and node monitoring alerts. Update frequency is daily or following any configuration change. Data fields include filing numbers, origin server IP addresses, cache TTL values, refresh task IDs, access status codes, bandwidth thresholds, and other relevant fields. Some fields use standard network operation and maintenance units such as seconds, Mbps, and entries. All data centers on public network content distribution and cache configuration, and differs from the data dimensions of other cloud service categories.

## Constraints for Citation Sources and Traceability
Data sources are bound exclusively to CDN-specific consoles and logs. Traceability data sources must only connect to CDN-related APIs or exported files, and cannot directly reuse data source configurations from other cloud services. Update frequency triggers with configuration changes. Traceability workflows must associate change timestamps to ensure that only the currently active configuration version is referenced, and prevent expired data from being used. Daily documents include standardized operation and maintenance fields. Traceability must preserve the original units and identifiers of these fields, such as the second-based cache TTL values and access log status codes, and must not allow arbitrary conversion or omission. All data relates to public network distribution scenarios. Citation traceability must link specific domain names and node information to ensure that the effective scope of the target configuration can be located during review.

## How to Set the Configuration
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | Matches the average length of CDN configuration documents, avoids truncating key parameters |
| `responseData` | `Include complete fields of console logs and refresh records` | Covers all change and operation data required for traceability |
| `detail` | Enabled | Displays specific change nodes and timestamp information |
| Single recall limit | Top 6 entries | Matches the typical display count of CDN change records |
| Context time range | `600 seconds of change records` | Aligns with the effective cycle of CDN configurations |
| Problem optimization configuration | Enabled | Aligns with common review language used in CDN operation and maintenance |

## Three Common Configuration Errors
- Phenomenon: After adjusting `quoteMaxToken` to above 2000, the large model generation results have no citation sources, and only knowledge base content can be recalled. Reason: The threshold for context splicing was not adjusted synchronously, causing the reference data to exceed the token limit that the model can process, and the citation marker cannot be output.
- Phenomenon: Local testing shows normal citations, but no citation content is returned when calling via external API. Reason: The `detail` configuration was not enabled in the API request parameters, only summary results were returned, and no detailed source information required for traceability was included.
- Phenomenon: After cache rules are changed, the documents referenced by traceability do not match the actual changed content. Reason: The data source was not filtered by change timestamp, and old versions of cache rule documents were referenced.

## How to Confirm the Configuration Is Properly Set
- Submit test documents including cache rules and refresh records, check whether the generated results come with the corresponding source document ID or task number.
- Adjust `quoteMaxToken` to different values, verify the completeness of the referenced content, and confirm that no key parameters are truncated.
- When calling an external API, check whether the request parameters include the enabled configurations for `responseData` and `detail`.
- Check the FastGPT v4.17.0 system logs to confirm that the time range of traceability data matches the update frequency of change records.
