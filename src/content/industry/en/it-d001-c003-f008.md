# Code and Change Review Assistance for IT Asset Inventory: Workflow Orchestration

## What the data for this category looks like
IT asset inventory data comes from four types of systems: asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Four types of documents are produced daily: asset ledgers, inventory lists, requisition and return slips, and scrap application forms. Core fields include asset ID, user, storage location, ownership status, and purchase date. Units are primarily sets, units, and pieces. Data update frequency aligns with inventory cycles, with bulk updates performed monthly, quarterly, or annually. A single update covers all or a specified range of asset entries.

## What constraints these characteristics impose on the "workflow orchestration" link
Multi-source data access requires the workflow to configure multiple cross-system pull nodes to ensure unified alignment of asset data from different sources. The low update frequency means the workflow trigger timing must match the inventory cycle to avoid high-frequency ineffective execution. The multi-field document structure requires `variables` to accurately define asset-related parameters to ensure the accuracy of cross-node data transmission. Time-consuming links such as account-physical verification and user confirmation require inserting manual approval nodes into the workflow to reduce error rates. Severe error consequences such as asset loss or audit issues require the workflow to configure failure alerts and retry mechanisms to ensure execution stability.

## How to set the configurations
This document applies to FastGPT v4.17.0 and above.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Define asset ID, user, and storage location fields | Match the standard field structure of asset ledgers to ensure accurate cross-node data transmission |
| Workflow trigger timing | Trigger according to inventory cycle (monthly/quarterly/annually) | Align with data update frequency to avoid ineffective execution |
| HTTP request timeout | 600–1200 seconds | Adapt to the time consumption of multi-system data pulling, resolving the issue of overly short default timeout |
| Branch execution rule | Single-branch serial execution | Avoid execution conflicts caused by multiple branches triggering simultaneously during tool calls |
| Loop nesting configuration | Allow nested HTTP request nodes | Support batch processing of inventory data for multiple assets |
| Failure retry | Retry 2 times, interval 30 seconds | Respond to system interface fluctuations and improve execution stability |

## Three common mistakes
- When nesting knowledge base assistant calls in a workflow, the API returns a null value. The cause is that correct asset-related parameters are not configured in `variables`, preventing the knowledge base assistant from obtaining valid retrieval context.
- A `quote type error` occurs when referencing knowledge base variables. The cause is that the passed variable format does not meet requirements, and data is not transmitted according to the field types of the asset ledger. For example, passing a numeric asset ID in string format.
- The tool call module prints AI replies and executes the next-level branch at the same time. The cause is that the branch execution rule is not configured as serial triggering, leading to parallel execution of multiple branches.

## How to confirm the configuration is correct
- Trigger a test workflow, check whether the `variables` parameters correctly pass the field values of the asset ledger, with no format errors.
- Call the workflow API, check whether the returned results include the expected asset inventory data, with no null values returned.
- Simulate a system interface timeout scenario, confirm that the workflow triggers the failure retry mechanism, and the number of retries meets the configured requirements.
- Adjust the branch execution rule, verify that only the specified next-level branch is executed after the tool call, with no parallel execution.
