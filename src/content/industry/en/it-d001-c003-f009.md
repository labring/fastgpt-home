# Code and Change Review Assistance for IT Asset Inventory: Tool Calling and Plugins

## What this category of data looks like
IT asset inventory data sources include asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Daily generated documents include asset ledgers, inventory lists, requisition and return forms, and scrap applications. Fields cover asset number, asset name, storage location, user, ownership status, procurement cycle, scrap progress, and more. Data update frequency is monthly, quarterly, or annually. The volume of data updated in a single batch fluctuates with the inventory cycle, and there is no fixed unified single-batch data size.

## What constraints do these characteristics impose on the tool calling and plugin link
The need to access multiple data sources requires plugins to support interface protocols of different systems and adapt to field parsing for multiple document formats such as asset ledgers and inventory lists. The relatively low data update frequency means tool call trigger frequency should not be too high, to avoid repeatedly pulling redundant data. Core time-consuming links such as account-actual reconciliation and user confirmation require tool calls to accurately match asset fields, prevent reconciliation errors caused by field mismatches, and ensure tool return results can be directly used for verification in the review link.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-data-source asset data pulling scenarios, automatically match corresponding tools |
| `functionCall` | Select according to asset ledger field types | Accurately trigger document parsing and data pulling for corresponding formats |
| Single tool call return limit | Top 20 entries | Match the conventional data volume of monthly inventory lists, avoid interface overload |
| Tool call timeout | 600 seconds | Adapt to time-consuming scenarios of pulling asset data across systems |
| Hide tool call results | Enabled | Prevent exposure of original request data during the review process |

## Three common mistakes
- Symptom: Tool call node execution stalls, the interface displays "No valid data obtained", and the log returns empty fields. Cause: Interface permissions and parameters for connecting to the asset management system are not correctly configured, so valid asset data cannot be pulled.
- Symptom: The chat window displays the original request and return content of the tool call, including interface addresses and parameter details. Cause: The tool call result hiding setting is not enabled, so internal data during process execution is not blocked.
- Symptom: The API call only returns model responses, without attached referenced asset document details and field information. Cause: `functionCall` is not bound to the document reference field for asset inventory, and the reference data return configuration is not enabled.

## How to confirm the configuration is correct
- In FastGPT v4.17.0, initiate a single tool call test, check whether the returned results include the core fields of the asset ledger, and verify the matching degree between the fields and the configuration.
- Trigger the complete change review process, check that the chat window does not display the original request and return content of the tool call.
- View the system log to confirm that no timeout or empty field errors occur in the tool call node.
- Call the published API interface to verify that the returned results include both model responses and reference details of asset documents.

The values given are common starting points and should be measured against the reader's own samples.
