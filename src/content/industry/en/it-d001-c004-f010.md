# Code and Change Review Assistance for IT Procurement and Supplier Management: Citation Sources and Traceability

## What This Category's Data Looks Like
The typical data for this category comes from enterprise procurement systems, supplier quotation documents, budget spreadsheets, and contract systems. Daily associated documents include procurement requisitions, price comparison records, formal contracts, and acceptance documents. Data is updated per order or monthly. Each procurement-related document includes fixed fields such as procurement order number, supplier name, contract terms, budget amount, and acceptance node. There is no unified cross-system field format, so the procurement order number must be used as the unique association identifier to match full-lifecycle data.

## What Constraints Do These Characteristics Impose on Citation Sources and Traceability
Because data is scattered across multiple heterogeneous systems and must be associated with full-lifecycle documents via the procurement order number, the traceability link requires precise matching of cross-system association fields to avoid introducing irrelevant data. The per-order update rhythm requires that the traceability scope be limited to documents associated with the current procurement order, to avoid redundant retrieval. Differences across multiple document types require configuring different citation weights to ensure higher traceability priority for key documents such as contract terms and price comparison records. At the same time, the returned citation content must be linkable to the specific location in the original document, to allow reviewers to quickly verify information.

## How to Configure
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | Adapt to long-text citation content such as procurement contracts and price comparison records, avoid truncating key terms and fields |
| `responseData` | Include procurement order number, supplier name | Match the unique identifier of the current review procurement order, quickly locate full-lifecycle associated documents |
| `detail` | true | Display specific locations and source paths of cited content, meet traceability verification requirements |
| Recall Scope Limit | Current procurement order associated documents | Avoid introducing irrelevant historical procurement data, improve traceability accuracy |
| Model Parameter Configuration | MaxToken 1200–1800, Temperature 0.3–0.5 | Constrain the length and rigor of output content, adapt to compliance review requirements for procurement documents |

## Three Common Misconfigurations
- Fail to obtain the associated ID of the knowledge base citation after calling the chat interface, only returning plain text content. This occurs because the `responseData` parameter is not configured, and no unique identifier fields such as procurement order number are specified for return.
- Fail to set `detail` to true, resulting in inability to obtain specific fragments and source paths of cited documents, making contract term traceability verification impossible. This occurs because detailed return configuration is not enabled, and key information required for traceability is lost.
- Only configure the AI model name without setting MaxToken and temperature parameters, causing output content to exceed the compliance scope of procurement documents. This occurs because model parameter configuration is not completed, and the length and rigor of output cannot be constrained.

## How to Confirm Proper Configuration
- Initiate a code review assistance request for the current procurement order, check whether the returned result includes fields such as associated procurement order number and supplier name.
- View the detailed information of the returned result, confirm whether it includes specific fragments and source paths of cited documents.
- Adjust the `quoteMaxToken` parameter value, verify whether the returned citation content adjusts its truncation logic along with parameter changes.
- Call the interface and check whether the returned data includes the unique identifier of the knowledge base source, confirm that the association configuration is effective.

The values provided are common starting points and should be measured against the reader's own samples.
