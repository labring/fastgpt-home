# Code and Change Review Assistance for Issue Triage and Response: Tool Calling and Plugins

## What this category of data looks like
The data for this category primarily comes from GitHub or Gitee Issues, code repository version logs, user-submitted environment information, and problem reproduction instructions. Daily maintained documents include Issue templates, label rules, historical response records, and problem reproduction documentation. Data update frequency is daily or weekly, triggered by new community-submitted issues and repository code changes. Data fields include problem titles, descriptions, submitter information, labels, associated code modules, priority levels, and reproduction steps. There are no unified mandatory units, and adjustments are made according to community rules.

## What constraints do these characteristics impose on the tool calling and plugin workflow
Data sources are scattered across code hosting platforms and local repositories, requiring tool calling to adapt to multi-source data pulling logic, and support for calling GitHub or Gitee official APIs to obtain Issue data. The data update frequency is daily or weekly, so plugins must configure scheduled synchronization tasks to avoid exceeding interface rate limits from high-frequency calls. Issue documents include custom labels and templates, so tools must recognize community-preset label rules and template structures to complete problem classification matching. There are no unified units for fields, so plugins must offer custom field mapping configurations to adapt to differences in Issue fields across different communities. Additionally, tools must support associating code repository information to mark responsible modules, aligning with core daily operation and maintenance needs.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data source synchronization cycle | 2:00 to 4:00 AM daily | Matches low-volume periods for community Issue submissions, reducing interface call conflicts |
| Label matching rules | Bind community preset label libraries | Aligns with daily maintenance label rule documentation to ensure classification accuracy |
| Custom field mapping | Configure according to repository Issue templates | Adapts to Issue field structures across different repositories, supporting multi-repository access |
| `toolChoice` | auto | Allows tools to autonomously select appropriate calling logic, adapting to varied Issue scenarios |
| `functionCall` | enabled | Supports tools calling external APIs to pull code association information and complete responsible module marking |
| Timeout threshold | 600 seconds | Covers information pulling and analysis durations for complex Issues, preventing mid-process interruptions |

## Three common configuration mistakes
- A database connection error occurs when starting the synchronization plugin, but the MongoDB visualization tool can connect normally. The cause is that the database connection parameters configured for the plugin do not match the community operation and maintenance environment variables, and are inconsistent with the local configuration of the visualization tool.
- The classification results returned after tool calling do not match the community preset labels. The cause is that the community preset label library is not bound, and the plugin uses the default general classification rules.
- No response is received for a long time after the plugin is triggered. The cause is that the timeout threshold is not adjusted, and the default threshold is insufficient to cover the information pulling and analysis process for complex Issues.

## How to confirm successful configuration
- Manually trigger a data source synchronization, and check whether the latest Issue data for the corresponding repository is pulled in the synchronization log.
- Submit a test Issue that matches the community preset labels, and check whether the tool automatically completes classification marking.
- After configuring `functionCall`, trigger the tool to call an external API, and check whether code association information can be obtained normally.
- View the plugin operation status panel to confirm that configurations such as synchronization cycle and timeout threshold have taken effect.
