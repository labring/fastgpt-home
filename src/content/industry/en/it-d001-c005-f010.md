# Code and Change Review Assistance for Issue Triage and Response: Citation Sources and Traceability

## What the data for this category looks like
Data for this category primarily comes from GitHub or Gitee Issues, code repository version logs, user environment information, and commit records. Daily maintenance documents include Issue templates, label rules, historical reply records, and problem reproduction instructions.
The data update frequency is daily or weekly. Core fields include Issue number, title, problem description, associated tags, priority, submitter information, associated code change links, and more.
The data structure centers on the issue itself, prioritizing user-reported problem details and community operation classification rules.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Data sources cover both Issue platforms and code repositories. Traceability links must associate Issue metadata and code commit records to avoid information loss from relying solely on a single data source.
Daily or weekly update frequency requires configurations to support incremental pull logic, reducing resource consumption from full synchronization.
The document structure centered on Issue templates and label rules requires traceability results to match preset classification fields and template formats, ensuring triage results comply with operational standards.
The core time-consuming steps are problem classification and completing reproduction information. Traceability links must quickly locate associated historical replies and code changes to lower manual processing costs.
Errors can easily lead to problem backlogs. Traceability results must have high accuracy to avoid invalid processing caused by incorrect associations.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Issue content typically includes problem descriptions, associated tags, and code snippets. This range covers typical context without exceeding the window limits of common models |
| `responseData` | `Only return associated Issue and code commit metadata` | This category only requires tracing the Issue itself and associated code changes. No irrelevant knowledge base or non-associated content should be returned |
| `detail` | `Enabled` | Complete details such as Issue creation time, submitter information, and associated PR links are needed to complete accurate traceability and classification |
| Single recall count | `Top 5 entries` | The volume of Issue data for this category is typically at the daily or weekly level. The top 5 associated results cover the traceability needs of most common problems |

## Three common mistakes
- Phenomenon: Unnecessary citation markers are included in generated triage results. Cause: The `responseData` parameter is not configured correctly, causing returned content to include unnecessary knowledge base citation markers.
- Phenomenon: Environment variable missing error occurs when the workflow starts. Cause: `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy admin token, consistent with the AI Proxy server configuration and non-empty) are not configured on the App/Admin server, failing the startup verification requirements for versions v4.17.0 and above.
- Phenomenon: Traceability results do not include complete associated code snippets. Cause: The `quoteMaxToken` parameter is not set reasonably, causing context truncation and preventing matching of complete code association records.

## How to confirm the configuration is correct
- Check the environment variable configuration on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy admin token, consistent with the AI Proxy server configuration and non-empty) are correctly configured and not empty.
- Trigger an Issue triage workflow, check if the returned results only include associated Issue metadata and code commit information.
- Adjust the `quoteMaxToken` parameter, verify that the number of recalled associated code snippets meets expectations.
- Confirm that the `detail` parameter is enabled, check if the results include necessary fields such as Issue creation time and submitter information.
