# Code and Change Review Assistance for Pull Request Reviews: Context and Token

## What This Category's Data Looks Like
The data for this category primarily comes from code repositories, CI pipelines, linked Issue links, and contributor submission records. Commonly stored documents include PR description text, code review comments, CI execution results, and merge operation logs. Data update frequency is typically daily or weekly, with real-time or periodic updates aligned with code commits and review workflows. Data fields include changed code snippets, review comment details, CI status indicators, contributor information, merge status, and more. Fields and units adjust based on specific repository configurations, with no unified fixed standards.

## Constraints on Context and Token Workflows
The varying lengths of code change snippets create challenges: long files may exceed per-round token limits, requiring reasonable context range restrictions. Multi-source data (code, CI, Issues) has inconsistent formats, which requires format alignment during context integration to avoid wasted token usage. Daily-updated real-time data generates context increments, so the retention duration of historical context must be controlled to prevent excessive token consumption. PR data volume varies significantly across different repositories, so context recall volume must be adapted to different scales to avoid single-round token consumption exceeding model limits. Additionally, PR review context must link code change intentions and related issues. If the context recall range is too wide, irrelevant data will be introduced, leading to token waste. If too narrow, key information required to confirm change intentions will be missing.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` (calibrated via actual testing) | Adapts to the per-round token limits of most large models, while covering the total code and linked information volume of typical PRs |
| `quoteMaxToken` | `2000–4000 token` | Limits token consumption for a single linked PR code or document, preventing overall context overflow |
| Context recall count | Top 3–5 linked PRs and Issues | PR reviews typically only require recent or highly relevant historical changes; excess entries will consume additional tokens |
| Context retention duration | 7 days (adjust based on repository scale) | Daily-updated PR data only requires retaining recent changes; longer retention leads to context redundancy |
| Multi-source format alignment | Enabled | Adapts to the different formats of code, CI, and Issue data, reducing wasted token usage |

## Three Common Configuration Errors
- Phenomenon: After increasing the context range in configuration, PR reviews still fail to link historical change information, leading to deviated results. Cause: The context token limit was not adjusted synchronously, or multi-source data linking rules were not enabled, resulting in newly added contexts not being actually loaded.
- Phenomenon: Single PR review returns truncated content or an error indicating token limit exceeded. Cause: The `quoteMaxToken` value was not restricted, leading to token consumption from long code files exceeding the model's per-round limit.
- Phenomenon: Review results do not link CI pipeline results, and the test status of changes is not included as a reference. Cause: The multi-source data linked recall logic was not configured, so only code snippets were recalled without linking CI data.

## How to Verify Correct Configuration
- The context configuration panel in FastGPT v4.17.0 can be accessed, and the values of `maxContext` and `quoteMaxToken` confirmed to fall within the preset ranges.
- A test PR including linked Issues and CI records can be imported, and the number of recalled linked data checked to match the preset context recall count.
- A complete PR review workflow can be simulated, the token consumption statistics reviewed, and consumption confirmed to not exceed the model's per-round limit.
- Review results before and after configuration adjustments can be compared, and confirmation made that linked code, CI, and Issue information is correctly included in the context.

The values listed above are common starting points and should be measured against the reader's own samples.
