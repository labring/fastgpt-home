# Code and Change Review Assistance for Pull Request Reviews: Citation Sources and Traceability

## What this category’s data includes
Data for this category primarily comes from code repositories, CI pipelines, Issue links, and contributor submission records. Commonly associated documents include PR descriptions, code review comments, CI execution results, and merge records.
Data update rhythm is typically daily or weekly. Core fields include changed code scope, commit hash, review comment ID, merge status, and associated Issue number. There are no unified fixed units; values vary based on the configuration of the corresponding repository and pipeline.

## What constraints do these characteristics impose on the traceability and citation sourcing workflow?
The multi-source, decentralized nature of data requires the traceability link to simultaneously associate unique identifiers of code repositories, CI systems, and Issues to avoid cross-data source confusion.
The daily or weekly update rhythm requires traceability to match the latest commits and review records within the corresponding time window, preventing the use of expired data.
The decentralized document structure requires traceability to aggregate associated information by PR dimension, ensuring full change sources can be quickly located during review.
The high time cost of change intent confirmation also requires traceability to quickly trace original commits and review comments, reducing the cost of repeated verification.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | Adapts to the total length of code snippets and associated documents in PR reviews, avoiding truncation of critical traceability information |
| `responseData` | Includes code repository address, CI execution ID, Issue link | Covers all traceability data sources required for PR reviews, ensuring complete change chains can be associated |
| `detail` | Enable full metadata mode | Retains all details of review comments and submission records, facilitating quick location of change sources |
| Single recall limit | Top 10 associated records | Controls the volume of information returned by traceability, avoiding overload that impacts review efficiency |
| Time window matching | Filter 7 days before and after PR creation | Ensures only associated data within the PR’s cycle is recalled, excluding expired information |

## Three Common Misconfigurations
- Only citation content is returned after configuration, with no code review assistance analysis content. The cause is that the `responseData` configuration only enables data source return, without binding corresponding generation logic, resulting in only traceability information being displayed without analysis.
- Non-current PR submission records appear in traceability results. The cause is that no time window matching based on PR creation time is set, leading to recall of expired cross-cycle data.
- Some PRs’ traceability information lacks CI execution results. The cause is that no recall rule for CI results is added to the `responseData` configuration item, resulting in incomplete data source coverage.

## How to Confirm Configuration is Correct
- Access the corresponding PR review workflow configuration page in FastGPT v4.17.0, verify that the `quoteMaxToken` configuration value falls within the 8000–12000 token range.
- Trigger a test PR review, check that the returned traceability information includes code repository, CI result, and Issue link three types of data.
- Verify the time window configuration: manually input a date earlier than the PR creation time, confirm that the system does not recall irrelevant data from that time period.
- Check if the `detail` configuration is enabled, confirm that complete metadata of commit hash and review comments is displayed in the review results.

All configuration values listed here are common starting points. Adjustments should be made based on specific samples and use cases.
