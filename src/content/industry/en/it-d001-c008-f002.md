# Code and Change Review Assistance for Special Event Operations: Context and Token

## What the data for this use case looks like
Daily documents for special event operations include event plans, resource slot schedules, event page copy, and post-event review reports. Data sources include content libraries, event backends, traffic metrics, and user feedback. Updates follow a weekly cadence, with frequent adjustments around holidays. Data fields typically include event cycles, resource slot IDs, copy word counts, and traffic conversion metrics. The content length of individual documents varies widely, ranging from several-hundred-word schedule tables to tens-of-thousand-word post-event review reports.

## What constraints do these characteristics impose on the context and token workflow
The wide range in document lengths, such as event plans and post-event review reports, leads to significant differences in context token usage. This requires adapting context recall for content of varying lengths. The weekly update cadence and frequent adjustments around holidays require a context synchronization mechanism that aligns with this update rhythm, to avoid recalling outdated event schedules or copy. Multi-source data includes precise fields like event cycles and resource slot IDs, which increases the complexity of context filtering. This requires defining clear matching dimensions between recalled context and the current change review task. Additionally, code associated with change reviews must correspond to specific event resource slots and copy. Context must be accurately linked to event identifiers to avoid mixing data from different event cycles.

## How to configure the settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the wide range of lengths for event plans and post-event review reports, avoiding exceeding the large model context limit |
| `quoteMaxToken` | 2000–3000 token | Limits token usage for single quoted content, balancing recalled information volume and context load |
| Single recall quote limit | Top 6 entries | Matches the multi-document association characteristics of special event operations, covering multiple content types including schedules, copy, and metrics |
| Context matching threshold | 0.72–0.85 | Accurately filters event documents relevant to the current change review, filtering out irrelevant historical event data |
| Chunk overlap length | 100–150 characters | Preserves context coherence for event copy and schedule tables, avoiding critical information being split across chunks |
| Knowledge base sync frequency | Every 12 hours | Aligns with the weekly update cadence, balancing timeliness and deployment resource consumption |

## Three common misconfigurations
- An error occurs when calling an offline-deployed embedding model, with a prompt stating that the cl100k.tiktoken file cannot be found. This happens because the offline-deployed model package does not include the default tokenizer file. Manually download the corresponding file and configure the correct file path.
- After setting the single recall quote limit to 3000, context fails to send normally to the large model. This occurs because the total context token count exceeds the threshold set by `maxContext`, and the system automatically truncates or skips passing the context.
- After setting a fixed token generation rate and concurrency limit for the large model, request timeouts or response interruptions occur. This happens because hardware resources do not match the concurrency and rate settings, leading to insufficient computing power to handle requests.

## How to verify the configuration is correct
- Use the FastGPT v4.17.0 knowledge base sync log function to check that the most recent sync time matches the configured sync frequency.
- Submit a change review request, and view the number of recalled documents in the context preview interface to confirm it matches the set single recall quote limit.
- Test inputting event copy of varying lengths, confirming that context token usage does not exceed the range set by `maxContext`.
- Simulate a call to an offline-deployed embedding model, confirming that the tokenizer file path is configured correctly with no error returns.
