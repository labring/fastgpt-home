# Code and Change Review Assistance for Special Event Operations: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Daily documents for special event operations include activity plans, resource slot schedules, activity page copy, and post-event review reports. Data sources include content libraries, event backends, traffic metrics, and user feedback.
Data update frequency follows a weekly cycle, or is adjusted temporarily for holidays. Document fields typically include activity cycle, resource slot ID, traffic metrics, user feedback tags, and similar items. All core fields are linked to a unique activity identifier, with no universal data fields shared across multiple activities.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
All documents and data for special event operations are tied to a unique activity identifier. Multi-turn dialogue must accurately link to the context of the corresponding activity to avoid cross-activity data interfering with review results.
Data update frequency follows a weekly cycle, or is adjusted temporarily for holidays. Prompt engineering must support dynamic loading of the latest event schedules and copy, and cannot rely on fixed static knowledge bases.
Core workflows involve resource slot coordination and post-event data review. Prompt engineering for multi-turn dialogue must limit validation scope to only the document fields of the current activity, preventing missed or out-of-bounds review content.

## How to configure settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Knowledge base reference scope | Limited to content libraries and event backend data linked to the current activity | Data for special event operations only comes from the exclusive content library and backend of the current activity, avoiding redundant information from other activities |
| Maximum context length | 800–1200 characters | Adapts to the single-page content length of activity documents, ensuring multi-turn dialogue can carry core activity information without exceeding system capacity limits |
| Number of multi-turn dialogue history entries to retain | First 3 entries | The decision-making chain for special events is short, only requiring retention of key context such as activity cycle, resource slots, and core copy |
| `variables` binding | Bind activity ID and activity cycle fields | All documents for special events are linked to a unique activity identifier, enabling precise calling of the data source for the corresponding activity |
| Prompt engineering validation rules | Only validate fields within activity plans and resource slot schedules | Prevent reviews from exceeding the document scope of the current activity, avoiding resource waste or low event participation outcomes |
| Context truncation trigger | Triggered by cumulative character count | Adapts to weekly or temporarily updated activity data, clearing redundant historical context in a timely manner |

## Three common configuration mistakes
- Symptom: Multi-turn code review results omit resource slot schedule information. Cause: The knowledge base reference scope is not limited to the exclusive data of the current activity, introducing schedule content from other activities.
- Symptom: The top title of the embedded dialogue page is unexpectedly modified. Cause: The page title parameter is not locked in the embedded configuration, causing front-end rendering to overwrite the preset value.
- Symptom: Review content generated by prompt engineering exceeds the preset scope, involving fields unrelated to the activity. Cause: The prompt engineering does not explicitly limit the validated document scope, causing the dialogue to generate irrelevant content.

## How to confirm the configuration is complete
- Input test questions to verify that returned review results only include the plan, schedule, and copy content of the current activity, with no irrelevant cross-activity information.
- View the `messages` field in the dialogue history to confirm only 3 rounds of context content related to the current activity are retained.
- Bind the activity ID parameter in `variables` to test whether the exclusive data source for the corresponding activity is automatically linked during calls.
- Modify the title parameter in the page embedded configuration to verify that the preset title is not unexpectedly overwritten and remains fixed.
