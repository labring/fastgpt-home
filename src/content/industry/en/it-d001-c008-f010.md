# Code and Change Review Assistance for Special Event Operations: Citation Sources and Traceability

## What This Category of Data Looks Like
Content libraries, event backends, traffic data platforms, and user feedback channels provide core data for special event operations. Four document types are produced daily: event plans, resource slot schedules, event page copy, and post-event review reports. Fields include unique event identifiers, resource slot numbers, traffic statistics, user feedback tags, and more. Data updates follow a weekly cadence, with temporary additions around holidays. The effective content length of individual documents stays relatively fixed.

## Constraints for Citation Sources and Traceability
Documents and data tied to special event operations are explicitly linked to specific event cycles. Citation traceability must be limited to the time range of the corresponding event, to avoid cross-cycle referencing of irrelevant historical event data. The multi-source data characteristic requires the traceability link to associate entries from multiple sources including content libraries and event backends, to ensure matching between event plans and resource slot schedules during reviews. The weekly update cadence means traceability configurations must adapt to temporary data changes, to prevent referencing expired schedules or copy content.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | The core documents for special event operations have an effective content length of 600–1000 characters per piece. This token volume aligns with context length limits, avoids truncating key information, and matches the context processing logic of FastGPT v4.17.0. |
| `responseData` | Only associate data sources from the current event cycle | Special events have clear cycles. This setting limits the citation range to event backend and content library data from the corresponding cycle, excluding irrelevant historical content. |
| `detail` | Enable full traceability annotation | Event operation documents require marking resource slots and traffic data sources. Full traceability allows matching the relationship between event schedules and user feedback. |
| Single retrieval limit | `Top 4 entries` | The number of core data sources for special event operations is limited. Excessive citations will disrupt review logic and reduce change review efficiency. |
| Context refresh frequency | `Every 7 days` | This matches the weekly update cadence of event data, adapts to the update cycles of resource slot schedules and traffic data, and ensures the timeliness of referenced content. |

## Three Common Configuration Mistakes
- The symptom is a configuration error prompt during testing, but citation content can be generated during formal operation. The cause is that data source permissions for the event cycle are not correctly bound, and the test call does not trigger complete context association logic.
- The symptom is that only 1 knowledge base document is returned per retrieval. The cause is that the single retrieval limit was incorrectly set to 1, which does not adapt to the multi-source schedule and copy data requirements of special event operations.
- The symptom is that the knowledge base is empty after import, and the target data source must be manually selected. The cause is that preset data source tags for the event cycle are not configured, so the content library and event backend data of the corresponding event cannot be automatically associated.

## How to Verify Correct Configuration
- Submit a code review request, check if the returned citation sources include corresponding entries for event plans and resource slot schedules, and confirm the association range is correct.
- Adjust the `quoteMaxToken` parameter, check if the token consumption of the referenced content matches the set range, and verify that the parameter takes effect.
- Switch the event cycle, confirm that the citation range automatically updates to the data sources of the corresponding cycle, and verify that the cycle binding logic works properly.
- Trigger a test call, confirm that there is no configuration error prompt, and that the number of returned citation entries matches the set single retrieval limit.

The values provided are common starting points and should be measured against the reader's own samples.
