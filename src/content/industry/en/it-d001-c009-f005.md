# Code and Change Review Assistance for Personal Information Protection Compliance: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category of data is generated from materials related to identifiable natural person information processing. Data sources include business systems, App permission lists, privacy policies, and user request records. Daily associated documents include personal information lists, processing rules, impact assessment reports, and user authorization texts. Updates occur quarterly or when each product version is changed. The core data structure centers on natural person information processing scenarios, permission configurations, and compliance judgment fields. No additional statistical numerical fields are included. Only information flow and permission mapping content required for compliance review are covered.

## What constraints do these data characteristics impose on the multi-turn dialogue and prompt engineering link
The data characteristics of this category create clear constraints for multi-turn dialogue and prompt engineering configurations. Since data updates trigger quarterly or during product changes, historical compliance review context must be retained in conversations to avoid repeated checks of old rules. Document types are diverse and focused on natural person information, so prompts must explicitly limit the review scope to identifiable natural person information processing links to prevent exceeding category boundaries. The most time-consuming scenario sorting and legitimacy confirmation links require gradual breakdown of review nodes through multi-turn dialogue, guiding input of corresponding document fragments to reduce manual repetitive sorting work. At the same time, judgment logic must be made more rigorous to avoid compliance oversights caused by lost context.

## Three common misconfigurations
- Phenomenon: When calling the `/api/v1/chat/completions` interface, the compliance review result does not match the preset rules. Cause: The document fragments required for compliance review are not injected via the `variables` parameter, and the prompt does not explicitly limit the review scope.
- Phenomenon: When using a global key to initiate multi-turn compliance review conversations, context from different sessions becomes mixed, leading to incorrect reuse of historical review conclusions. Cause: The `chatId` parameter is not bound, and session context isolation is not implemented.
- Phenomenon: When importing documents such as personal information lists, the domain names of embedded images are automatically lost, and image resources cannot be loaded normally during the review process. Cause: No image domain name binding rules are configured during the document conversion stage, and the prompt does not cover the verification requirements for resource links.

## How to confirm the configuration is correct
- Initiate a test conversation, input a compliance review-related query, and check whether the returned results cover the preset document fragment content.
- Initiate two independent compliance review sessions, and check that the historical context of the two sessions does not interfere with each other.
- Import a document containing image links, and check whether the image links retain the preset domain name information.
- View the interface call logs of FastGPT v4.17.0, and confirm that the `chatId`, `messages`, and `variables` parameters are all correctly passed.
