# Code and Change Review Assistance for Personal Information Protection Compliance: Tool Calling and Plugins

## What data belongs to this category
This category's data mainly comes from business systems, App permission lists, privacy policies, and user request records. Update frequency is quarterly or after each product change. Core daily documents include personal information inventories, data processing rules, impact assessment reports, and user authorization texts. Each document must correspond to fields such as natural person information processing scenarios, legal basis, and storage period. There are no unified fixed units. Field requirements must match specific business scenarios. This document is written based on FastGPT v4.17.0.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources are scattered and update rhythms are unstable. Plugins must support batch pulling and incremental synchronization of multi-source heterogeneous documents to avoid repeated processing of old data. Document types are diverse and must strictly match compliance requirements. Tool calling must adapt to parsing lists and report texts in different formats, and accurately identify fields related to personal information. Single processing involves many fields and requires traceability. Tool calling input length per single call must be limited. At the same time, call logs and parameter configurations must be recorded to facilitate subsequent compliance audits. In addition, processing results of compliance data must be associated with corresponding change scenarios. Plugins must support context binding for change reviews.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapt to scenarios where multiple tools parse compliance documents in parallel, automatically matching corresponding plugins |
| `functionCall` | Specify compliance parsing tools as needed | For compliance documents with fixed formats, fixed tool calling can improve efficiency |
| Maximum call timeout | 300 seconds | Covers time consumption for most long document parsing and multi-source data integration, calibrated based on actual testing |
| Incremental sync switch | Enabled | Matches the update rhythm of quarterly data or post-product change updates, reducing repeated processing costs |
| Log storage period | 90 days | Meets traceability requirements for compliance audits, corresponding to the quarterly update frequency |
| Single-batch processing limit | First 20 items | Avoids overload during single calls, adapting to batch processing scenarios for multi-source documents |

## Three common mistakes
- Symptom: Tool calling returns empty results, and no compliance document data is pulled. Cause: The incremental sync switch is not enabled, resulting in failure to sync the latest personal information inventory and permission inventory data.
- Symptom: Calling `toolChoice` returns an error that the model is not supported. Cause: The currently used model's tool calling function is not confirmed to be supported. Some lightweight models do not adapt to this configuration.
- Symptom: Tool calling forcibly relies on large model inference, and local knowledge bases cannot directly parse compliance documents. Cause: The plugin link for pure local knowledge base calling is not configured. All tool calls are mistakenly bound to the large model context.

## How to confirm configurations are properly set
- View tool calling logs to confirm that the latest compliance documents such as personal information inventories and processing rules have been pulled.
- Trigger a change review scenario for testing, verifying that tool calling executes parsing according to the configured `toolChoice` mode.
- Check API call return results to confirm that compliance data fields have been correctly extracted and associated with corresponding change scenarios.
- Confirm that the log storage period meets current business audit requirements, and retention duration can be adjusted as needed.

The values listed here are common starting points. They should be evaluated against the reader's own samples.
