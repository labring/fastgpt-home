# Code and Change Review Assistance for Personal Information Protection Compliance: Citation Sources and Traceability

## What data for this category looks like
Core data for this category comes from four sources: business systems, App permission lists, privacy policies, and user request records. Associated daily documents include personal information inventories, processing rules, impact assessment reports, and user authorization texts.
Data updates are triggered by product changes or occur on a quarterly basis. Document structures contain both structured fields (such as information type, processing purpose) and unstructured text (such as policy clauses, authorization content).
Field differences across documents are significant. For example, personal information inventories include structured information classification fields, while privacy policies consist of unstructured clause text. Overall fields cover the full process of identifiable natural person information processing, with no unified cross-document field standard.

## Constraints imposed by these characteristics on citation sources and traceability
Dispersed multi-source data requires citation traceability to support pulling and matching across systems and document types. This prevents missing personal information processing records from different channels.
Non-uniform document structures and field differences require the traceability link to adapt to content in different formats. Fixed keyword matching rules cannot be relied on, so custom field association logic must be supported.
Update rhythms tied to product changes require traceability to support dynamic synchronization of the latest data. This avoids using expired personal information inventories or authorization texts.
Strict accuracy requirements in compliance scenarios require that each citation can be accurately linked to the original data source. This prevents compliance risks caused by mismatching irrelevant content.

## How to configure the system
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Adapts to the length of single-block compliance content related to personal information, to avoid truncating key identifiable natural person information fields |
| Citation source matching threshold | `0.75–0.85` | Distinguishes the relevance of identifiable natural person information, to avoid incorrectly recalling irrelevant business system log fragments |
| `responseData` | Only return metadata and associated fragments of matching sources | Compliance reviews require clear traceability sources, avoid returning redundant irrelevant content, and simplify the verification process for reviewers |
| `detail` | Enabled | Displays the context of citation fragments and the original document location, to verify the accuracy of compliance associations |
| Single citation source recall limit | Top 3–5 entries | Focuses on core associated personal information processing records, to avoid too many distractions diverting reviewer attention |
| Source data synchronization trigger rule | Triggered by product changes + full quarterly synchronization | Adapts to the rhythm of business data updates alongside product iterations, covers regular updates for static inventory-style documents |

## Three common configuration errors
- Unlinked privacy policy fragments appear in review results. This occurs when the value range of `quoteMaxToken` is not restricted, leading to recall of irrelevant content outside the compliance scope.
- Matching results for user authorization texts cannot be obtained after configuring citation traceability. This occurs when user request records are not included as a data source in the recall scope, blurring the boundary between compliance-related documents and general business logs.
- Citation content templates are incorrectly bound to prompt templates in interface configuration. This causes review results to forcibly attach irrelevant citations, making it impossible to cancel unnecessary knowledge base associations as needed.

## How to confirm proper configuration
- Import a test personal information inventory and App permission list, trigger a code review, and check that returned citation fragments only link to the imported documents.
- View the review logs in FastGPT v4.17.0, confirm that each citation includes the source document name, update time, and specific matching fragment.
- Simulate a product change, update the test processing rule document, trigger a review, and check that the latest version of the content is recalled.
- Adjust the value of `quoteMaxToken` to `500 token`, verify that the length of returned citation fragments matches the set range.
