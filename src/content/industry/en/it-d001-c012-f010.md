# Code and Change Review Assistance for Cloud Network and Load Balancing Configuration: Citation Sources and Traceability

## What this category of data looks like
This data originates from cloud platform consoles, network topology diagrams, traffic monitoring reports, and customer architecture design documents. Daily maintained documents include VPC planning plans, security group rule lists, load balancing configuration files, and change approval forms.
Data update frequency follows the single change workflow. A new version is generated each time a configuration adjustment or change approval is completed.
Data fields include network segment ranges, port mapping rules, health check thresholds, backend server group configurations, and more. No universal fixed units exist. Match corresponding parameters to specific configuration items.

## Constraints Imposed on Citation Sources and Traceability
Data for cloud network and load balancing configurations updates frequently and is generated dynamically alongside change workflows. Citation traceability must bind to the latest change versions and approval records. This prevents the use of outdated configuration content.
Data sources are scattered across multiple consoles and document systems. A unified association mechanism is required to link configuration entries from different sources to the same review task.
Field types vary widely and have no fixed units. Citations must precisely match field names and configuration content. Broad associations are not permitted.
Configuration errors directly impact network connectivity. The traceability workflow must retain complete citation sources and modification trails to support post-hoc troubleshooting.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Citation Token Count | 800–1200 token | Matches the average length of a single cloud network configuration document. Prevents truncation of critical rules or fields |
| Return Data Format | Return original text fragments only | Ensures cited content comes directly from original configuration documents. No model-generated rewritten content is added |
| Detailed Metadata Toggle | Enabled | Retains change numbers, update times, and associated change form information for configurations. Facilitates linking to approval records during traceability |
| Single Citation Limit | Top 5 entries | Aligns with the typical number of configuration items in a single change review. Prevents information overload that would reduce review efficiency |
| Citation Matching Threshold | 0.85 | Calibrated via real-world testing. Ensures matched configuration content aligns closely with review requirements. Reduces irrelevant citations |

## Three Common Misconfigurations
- Red error prompts appear in review results, indicating invalid citation sources. Troubleshooting steps include:
  Incorrect configuration of server-side environment variables `AIPROXY_API_ENDPOINT` (AI Proxy service root address) or `AIPROXY_API_TOKEN` (AI Proxy admin token) causes App/Admin service startup verification failure. This prevents normal service operation.
  Failure to bind the cloud network configuration dataset to workflow nodes prevents matching to real configuration entries during traceability.
- Only the first review node displays knowledge base citations in the workflow. Subsequent nodes show no citation content. Troubleshooting steps:
  The cloud network configuration dataset ID is not correctly bound in workflow node configurations, and citation traceability is not enabled in subsequent nodes.
- AI-generated citation content includes processed text not present in the original configuration. This occurs when the return data format is not set to return original text fragments only. The model summarizes or rewrites citation content in this scenario.

## How to Confirm Correct Configuration
- Start the FastGPT v4.17.0 App/Admin service. Check startup logs for errors indicating missing `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` environment variables. Confirm both variables are correctly configured.
- Create a new cloud network configuration review workflow. Add a knowledge base retrieval node. Input a real load balancing port mapping rule. Verify that retrieval results match the corresponding original document fragments.
- Trigger a full change review workflow. Check that citation sources in review results show correct document paths, change form numbers, and update times.
- Review workflow node configuration items. Confirm that parameters such as maximum citation token count and return data format are set to the predefined values.
