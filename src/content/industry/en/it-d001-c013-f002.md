# Code and Change Review Assistance for Cloud Billing and Cost Accounting: Context and Token

## What the data for this category looks like
The data for this category comes primarily from cloud billing systems, tag data, order systems, and resource monitoring systems. Core daily output documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Data update frequency is typically daily or monthly. Fields include billing cycle, resource ID, cost amount, tag key-value pairs, allocation ratio, and more. Units cover basic metrics such as yuan, GB, and hours. Field formats vary across different data sources.

## Constraints on context and token processing
Differences in data formats across multiple sources require field unification before context concatenation. Without this, invalid token usage increases. Daily or monthly update frequency means context caches must be refreshed regularly. This prevents expired billing or allocation data from being used. The total token count for core documents per batch is relatively high. Failing to limit total context length can exceed model support limits. Tag attribution verification and abnormal expense troubleshooting are core steps. Context must prioritize recalling highly matching associated records. Otherwise, it leads to wasted token usage and reduced review accuracy.

## Recommended Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `maxContext` | `8000–12000 token` | The total token count for core documents for cloud billing and cost accounting per batch typically falls within this range, preventing exceedance of model context limits |
| `quoteMaxToken` | `2000–3000 token` | The effective information token count for a single core business document (such as a monthly resource utilization report) typically does not exceed this range, ensuring recalled content is complete |
| Context recall count | Top 3–5 entries | Associated items for cloud billing (such as tag attribution, expense allocation) are usually concentrated in a small number of highly matching records. Too many recalled entries will increase token usage |
| Context update cycle | Refresh daily | The update frequency for this category of data is daily or monthly. Refreshing daily ensures the context includes the latest billing details and optimization suggestion sheets |
| Field matching threshold | Match score ≥0.7 | Fields such as cloud billing tags and resource IDs have consistent formats. This threshold effectively filters irrelevant data and reduces invalid token usage |

## Three Common Configuration Mistakes
- Symptom: A 422 error is returned during calls, with the prompt “Messages token length must”. Cause: The values for `maxContext` or `quoteMaxToken` are not restricted. The total sum of concatenated context and request tokens exceeds the model's supported limit.
- Symptom: Context is lost during multi-turn sessions in workflows. Cause: Core business data (such as cost allocation tables) is not included in persistent context storage, or the context cache is not refreshed daily.
- Symptom: A large number of irrelevant resource monitoring logs are mixed into retrieval results. Cause: No field matching threshold is set. Recalled historical records are unrelated to the current billing review, leading to wasted token usage.

## How to Verify Configurations Are Correct
- Upload a single month's billing detail document. Test whether the number of recalled retrieval entries falls within the 3–5 range. Confirm that the context recall configuration is active.
- Initiate two or more linked review sessions. Check whether the context retains the previous round's cost allocation data and tag information. Verify that the context update cycle configuration functions as intended.
- View the FastGPT v4.17.0 call logs. Confirm that the total token count for a single request does not exceed the values set for `maxContext` and `quoteMaxToken`. Verify that the token limit configuration is active.
- Simulate an abnormal expense troubleshooting scenario. Check whether retrieval results only include tag data and billing records related to the current review. Confirm that the field matching threshold configuration is active.
