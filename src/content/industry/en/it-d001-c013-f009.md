# Code and Change Review Assistance for Cloud Billing and Cost Accounting: Tool Calling and Plugins

## What the data for this category looks like
Data primarily comes from cloud billing systems, tag datasets, order systems, and resource monitoring tools. Update cycles are divided into daily and monthly. Regularly produced documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Fields cover resource identifiers, expense details, tag attribution, allocation rules, and resource utilization metrics. Field formats vary across different cloud service providers, so data parsing logic must be adjusted based on specific billing calculation standards.

## What constraints these characteristics impose on the tool calling and plugins workflow
Decentralized data sources mean plugins must connect to multiple types of system interfaces, and independent authentication and data parsing rules must be configured for different systems. Update cycles are divided into daily and monthly, so tool calling needs to distinguish trigger conditions for incremental pulling and full pulling to avoid repeatedly pulling expired data. Document structures have no unified format, so plugins must adapt to field differences in bills and allocation tables across cloud service providers, increasing fault tolerance requirements for data parsing. The tag attribution verification and abnormal expense troubleshooting links require associating multi-source data, so the context for tool calling needs to preset logical templates for associating data from multiple systems.

## How to configure settings
The following configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Plugin Authentication Configuration | Configure cloud service provider API keys and signature verification rules | Meet the authentication requirements of cloud billing systems |
| `toolChoice` | Set to `auto` | Support automatic selection of appropriate tool calling strategies |
| Data Pull Cycle | Configure as daily or monthly | Match the daily or monthly update frequency of cloud billing data |
| Result Parsing Fault Tolerance | Enable automatic completion mode for missing fields | Adapt to field differences in bills across cloud service providers |
| `functionCall` | Limit to cost data pulling and association tools | Focus the tool calling scope for the current scenario |
| Single Data Pull Volume | Configure as `1000 entries` | Balance interface call efficiency and data processing load |

## Three Common Configuration Errors
- A tool call returns `internal server error` and the interface prompts that the plugin failed to import. The cause is that the port configured for the plugin is not open or has insufficient permissions in a private deployment environment, and it does not match the plugin loading verification rules of FastGPT v4.14.1.
- After setting the `stream` parameter to `true`, complete billing data results cannot be obtained. The cause is that the closing verification logic for streaming results is not configured, resulting in only partial segmented data being received.
- The tag data returned by the tool call does not match the actual bill. The cause is that the difference in tag field naming across cloud service providers is not adapted, leading to matching errors during parsing.

## How to Verify Correct Configuration
- Manually trigger a tool call, check if the returned billing data includes core fields from the cloud billing system.
- View plugin logs to confirm that authentication requests are successful and the data pull cycle matches the preset configuration.
- Compare the cost allocation results returned by the tool with locally exported manual reports to verify data consistency.
- Adjust the `toolChoice` parameter to confirm that the tool only calls the target plugins preset for the current scenario.

The values provided are common starting points and should be measured against the user's own samples.
