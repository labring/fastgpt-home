# Code and Change Review Assistance for Cloud Billing and Cost Accounting: Citation Sources and Traceability

## What the data for this category looks like
The core data for the cloud billing and cost accounting category comes from cloud billing systems, resource tagging systems, order systems, and resource monitoring platforms. Data update frequency is typically daily or monthly. Regularly generated documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestions. Data fields include billing item codes, resource IDs, attribution tags, cost amounts, and usage duration. Units are mostly yuan, hours, GB, and other common units. Field formats vary slightly across different cloud service providers.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Link
The multi-data-source structure requires that the traceability link clearly mark the original system for each citation, to avoid mixing billing data from different cloud service providers. The daily or monthly update frequency requires verifying the data generation time during traceability, to prevent referencing expired data that causes review errors. The complex document structure and multi-field design requires matching corresponding field identifiers during traceability, such as the correspondence between resource IDs and cost amounts, to ensure accurate verification of attribution and amounts during reviews. The core link of tag attribution verification requires associating specific resource tag configurations during traceability, to ensure cited cost data is correctly attributed and avoid customer billing disputes.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Cloud billing data includes multi-field details. This parameter controls the token limit for cited content, to avoid exceeding model context limits |
| `responseData` | `Only return billing details and cost allocation fields | Filter non-essential monitoring or order data, focus on cost-related content required for code and change reviews |
| `detail` | `Enabled` | Display original field details of cited data, to facilitate reviewers verifying key information such as resource IDs and attribution tags |
| Single recall citation count | `Top 3–5 entries` | Avoid excessive citations interfering with the review process, focus on high-relevance core cost data |
| Traceability data cache duration | `6–12 hours` | Match the daily update rhythm of cloud bills, balance data freshness and query efficiency |
| Citation source display toggle | `Enabled` | Clearly mark the original data source for each citation, meet compliance review and traceability requirements |

*Note: This page is based on FastGPT v4.17.0 configuration*

## Three Common Configuration Errors
- Scenario: Cited cost data in review results does not have an original data source label, or the labeled system does not match the actual source. Cause: The citation source display toggle is not enabled, or the `detail` parameter is not correctly configured to display original field information.
- Scenario: The citation list returned by the interface includes non-cloud billing content, or the number of entries exceeds the preset range. Cause: The `responseData` parameter is not set to filter target fields, or the single recall citation count is set too high.
- Scenario: Variables passed via API in the workflow cannot be correctly associated with the target knowledge base, resulting in traceability failure. Cause: No mapping rule between variables and the knowledge base is configured in the workflow node, and no validation of variable legality is performed.

## How to Confirm the Configuration Is Correct
- Log in to the FastGPT backend, enter the knowledge base search node configuration page for the corresponding workflow, and check whether configured parameters such as `quoteMaxToken`, `responseData`, and `detail` comply with preset rules.
- Trigger a test review process, check whether the returned citation content includes preset cloud billing fields, and whether each citation is labeled with the corresponding original data source.
- Call the workflow API and pass custom variables, confirm that the target knowledge base can be correctly matched, and that the returned cost data matches the range specified by the variables.
- Check system logs to confirm that the traceability data cache duration matches the configuration, and that no data expiration or duplicate citation issues occur.
