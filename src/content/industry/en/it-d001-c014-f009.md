# Code and Change Review Assistance for Cloud Resource Compliance Audit: Tool Calling and Plugins

## What this category of data looks like
Cloud resource compliance audit data comes from cloud audit logs, IAM permission systems, CMDB resource inventories, and security baseline scanning tools.
Daily output documents include compliance checklists, permission audit reports, resource inventories, and rectification tracking sheets.
These documents support cloud resource compliance verification during code review, and configuration compliance checks before change submissions.
Data update frequency is monthly or quarterly.
Resource inventories include resource ID, region, and configuration status fields.
Permission audit reports include role binding records and abnormal permission entries.
Compliance checklists include baseline items and check results.
Rectification tracking sheets include rectification status and completion deadlines.

## Constraints for tool calling and plugins
The need to pull data from multiple sources requires tool calls to execute in the order of CMDB, IAM, and security baseline scanning. This avoids data dependency errors.
The monthly or quarterly update frequency requires tool calls to be configured with a scheduled trigger cycle that matches the data update rhythm.
The complex document structure requires tool calls to specify return fields to reduce redundant data transmission.
Serious error consequences require configuring an error retry mechanism to handle temporary network fluctuations or data source anomalies.
The code and change review scenario requires tool calls to be embedded in the review process. Compliance checks automatically trigger when code is submitted or a change is initiated.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Specify calls in the order of CMDB, IAM, and security baseline scanning | Matches the multi-data source dependency logic of cloud resource compliance audits, ensuring correct data pull order |
| `functionCall` | Only return resource ID, compliance check result, and rectification tracking status fields | Focuses on core audit fields to reduce data transmission overhead |
| Tool call timeout | 600 seconds | Adapts to typical cloud resource data pull durations, avoiding mid-process interruptions |
| Tool call retry count | 2 times | Addresses call failures caused by temporary network fluctuations |
| Trigger timing | Monthly scheduled trigger | Matches the monthly update frequency of cloud resource compliance audit data |

## Three common configuration mistakes
- Symptom: A 400 status code is returned when calling the compliance audit tool, with a parameter format error prompt. Cause: Valid return fields are not specified according to the `functionCall` requirement, and field names outside the compliance audit data scope are passed.
- Symptom: An empty response is returned after calling the tool. Cause: The `toolChoice` configuration is not enabled, so the model does not trigger the plugin execution flow.
- Symptom: When calling a compliance audit sub-workflow from a parent workflow, the sub-workflow stops executing after the user selection node. Cause: Input parameter passing for tool calls is not configured, so the sub-workflow cannot receive context data from the parent workflow.

## How to confirm configuration is complete
- Navigate to the tool configuration page in FastGPT v4.17.0, and verify that `toolChoice` is configured correctly according to the data source order.
- Manually trigger a tool call, and check that the returned compliance data only includes the specified configured fields.
- Wait for the scheduled trigger cycle to elapse, and confirm that compliance data matching the update frequency is successfully pulled.
- Simulate a tool call failure scenario, and check that the configured retry mechanism activates.
