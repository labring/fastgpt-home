# Code Review and Merge Management: Code and Change Review Assistance - Multi-turn Dialogue and Prompt Engineering

## What This Category’s Data Includes
Core data for this category originates from Git repositories, CI pipelines, static scanning reports, and defect databases. Daily associated documents include merge requests, code review comments, commit records, and branch strategy descriptions. Data fields cover merge request unique identifiers, commit hashes, review statuses, static scanning alert counts, associated branch names, and more. Data updates occur daily or per commit; every commit or review operation triggers data synchronization.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Scattered data sources tied to specific code change contexts require multi-turn dialogue to link to the unique identifier of the corresponding merge request, preventing context mixing. Frequent data updates mean dialogue must pull the latest review comments and commit records in real time to ensure the model’s information matches the current state. Threaded review communications make up most daily documents, so prompts must splice historical messages in interaction order to retain core communication content. Fields include both technical and business information, so prompts must clearly define rules for extracting corresponding fields to stop the model from confusing unrelated data.

## How to Configure
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `messages` | Splice in the order of the merge request's review thread, retain the most recent 20 interactions | Merge request review communications typically focus on the most recent 20 rounds; excessive length will exceed FastGPT v4.17.0's default context limit |
| `variables` | Inject the current PR ID, associated commit hash, and total static scanning alerts | Allow the model to access core business and technical context fields for the current review |
| `chatId` | Bind to the unique identifier of the current merge request | Ensure dialogue context for the same PR does not mix with other PRs |
| Single dialogue response limit | Top 5 associated review records | Calibrated via actual testing; excessive results will distract the model's judgment of core changes |
| Context retention duration | 7 days | The standard review cycle for development teams does not exceed 7 days; history beyond this period has no reference value |

## Three Common Misconfigurations
- No corresponding question results returned after dialogue: Failed to inject current PR's associated review data into `variables`, leaving the model without available context to support responses.
- Failed to parse uploaded code files during dialogue: Did not configure access permissions for the Git repository, making it impossible to pull code files associated with the PR for analysis.
- Mixed dialogue contexts across merge requests: Did not use `chatId` to bind the unique identifier of the corresponding PR, causing dialogue contexts from different PRs to interfere with each other.

## How to Verify Successful Configuration
- Initiate a test dialogue, input "Please summarize the change content of the current merge request", and confirm the returned results include the core change points of the current PR.
- View the dialogue log to confirm that the `messages` parameter contains the most recent 20 review interaction records.
- Confirm the `variables` parameter has injected the current PR's ID, associated commit hash, and static scanning alert count.
- Switch to another merge request to initiate a dialogue, and confirm the returned results only associate context information for the current PR.

The values provided are common starting points and should be measured against the reader's own samples.
