# Code and Change Review Assistance for Enterprise Software License Management: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data is sourced from software asset management systems, procurement systems, terminal scan results, and vendor authorization documents. Daily maintained documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. The data update cycle is monthly or quarterly. Core fields include software name, authorized quantity, installed node count, authorization validity period, and vendor information. Units are mostly devices, sets, and calendar days. This category focuses on matching and verifying software authorization and installation usage, and differs from general IT asset inventory.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering capability area
Because data sources are scattered and the update cycle is long, multi-turn dialogue must prioritize calling already synchronized local ledger data to avoid delays caused by repeated pulling from external systems. Core fields include authorized quantity, installed node count, and others. Prompts must clearly define field matching rules to avoid confusing the differences between IT asset inventory and license verification. The data update cycle is monthly or quarterly, so session context must retain the most recent ledger batch identifier to ensure consistent data version references during the session. Documents related to compliance audits must strictly restrict access scope, and prompts must block sensitive contract details and only return compliance verification results.

## Configuration settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to the asset batch ID of the enterprise software asset management system | Ensure sessions always associate with the same batch of license ledger data, avoid cross-batch data confusion, and comply with FastGPT v4.17.0 session management rules |
| `messages` | Retain the most recent 3 rounds of conversations related to license verification | The data update cycle is monthly/quarterly; excessive history will introduce expired data to interfere with verification results |
| `variables` | Preset three business variables: authorized quantity, installed node count, and authorization validity period | Match the fixed fields in daily documents, reduce repeated descriptions in prompts |
| Maximum context length | 800–1200 characters | Core business fields are limited, avoid context overflow leading to failed field matching |
| Session timeout period | 1800 seconds | Compliance verification may require cross-document checks, reserve sufficient processing time |

## Three common mistakes
- Phenomenon: An `invalid chatId` error is returned when calling the interface. Cause: The asset batch ID of the enterprise software asset management system is not bound, and the default session ID is used directly, resulting in failure to associate the corresponding license data.
- Phenomenon: An additional AI generation step is triggered after starting a conversation, and structured verification results cannot be returned directly. Cause: The `variables` variable mapping rules are not configured correctly, the automatic generation link is not skipped, and the general conversation process is forcibly called.
- Phenomenon: After modifying the prompt to English, fields from domestic software asset management systems cannot be matched. Cause: Preset variables are not synchronized to English identifiers, resulting in failed field mapping.

## How to confirm configurations are complete
- Initiate a test call, pass the `chatId` bound to the enterprise software asset management system asset batch ID, and verify whether the returned result is associated with the corresponding batch of license data.
- After configuring preset business variables, initiate a test conversation to confirm that the returned result can correctly extract the values of the preset fields.
- Initiate a compliance verification request to confirm that the returned result only includes content related to authorization verification, and does not include unauthorized sensitive document details.
- Initiate a multi-turn conversation test to confirm that the session retains the most recent 3 rounds of history messages related to license verification, and no context overflow error is triggered.
