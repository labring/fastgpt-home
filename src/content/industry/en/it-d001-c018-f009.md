# Code and Change Review Assistance for Enterprise Software License Management: Tool Calling and Plugins

## What this category of data includes
Data for this category originates from software asset management systems, procurement systems, terminal scanning tools, and vendor authorization files. Updates occur monthly or quarterly. Daily processed documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Data fields include software name, authorized quantity, authorization validity period, number of installed terminals, and vendor authorization identifier. Corresponding units include units, calendar days, copies, and others. Data must support matching verification between actual terminal installation status and vendor authorization, and serve as core basis for compliance audits.

## Constraints imposed on tool calling and plugin workflows
Scattered data sources and long update cycles require tool calling to support batch pulling of multi-system data sources, to avoid occupying system resources from too many single-trigger requests.
Multiple document processing needs require plugins to support parsing files in different formats, such as Excel-format ledgers and PDF-format procurement contracts.
Precise matching requirements for core fields require tool calling parameters to clearly specify field mapping rules, to ensure consistency of key data such as authorized quantity and number of installed terminals.
Monthly update frequency requires scheduled tool calling triggers to adapt to this rhythm, to reduce the number of invalid calls.

## Three Common Misconfigurations
- Symptom: Tool calling cannot automatically connect to MCP, only supports a small number of preset file formats. Cause: Full file format support is not enabled, and default upload formats are not set to cover all types.
- Symptom: Tool calling returns empty values for the authorized quantity field. Cause: Field mapping rules are not properly configured, and core data fields of this category such as authorized quantity and number of installed terminals are not bound.
- Symptom: Tool calling returns a timeout error after triggering. Cause: Scheduled trigger frequency is set too high, exceeding system call limits, and not adapted to the monthly update rhythm of this category.

## How to Verify Proper Configuration
- Upload a standard Excel-format license ledger file, check whether the tool can automatically identify and extract core fields such as software name and authorized quantity.
- Manually trigger a tool call, check whether the returned results include all data required for compliance verification as specified by this category.
- View plugin call logs, confirm that the `toolChoice` parameter is set to `auto` and the trigger rule matches the configured once-per-month frequency.
- Simulate a compliance verification scenario, check whether the results conform to the preset verification logic, with no abnormal errors.
