# Code and Change Review Assistance for Enterprise Software License Management: Citation Sources and Traceability

## What Data for This Category Looks Like
Data for this category originates from software asset management systems, procurement systems, endpoint scanning tools, and vendor authorization documents. Regularly maintained documents include license ledgers, software usage inventories, procurement contracts, and compliance audit reports. Data updates occur monthly or quarterly. Core fields include authorization number, authorization scope, number of installed nodes, and expiration date, with units of string, classification tag, count, and days respectively. Data is generated exclusively to map the relationship between software authorization, installation, and usage, and does not include non-authorization-related system operation logs.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Link
Scattered data sources and fixed update schedules mean citation traceability must prioritize matching ledger data updated monthly or quarterly, and cannot rely on temporary data from real-time endpoint scans. Document structures include multiple associated file types, so traceability requires linking authorization clauses in procurement contracts and verification results from compliance audit reports, and cannot rely solely on a single data source. Field units and definitions strictly align with authorization management logic. For example, the number of installed nodes must match the authorized quantity listed in the ledger. During traceability, field unit consistency must be verified to avoid confusion with data from other IT categories. Additionally, data only covers authorization-related content, and non-authorization system logs must be excluded.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum Context Window | 8000–12000 token | Matches the context capacity limit of FastGPT v4.17.0, and adapts to the total character count of license-related documents |
| `quoteMaxToken` | 1500–2000 token | Limits the length of a single citation, adapts to the single-page content length of license documents, and avoids truncating core authorization clauses |
| Maximum Knowledge Base Citations | Top 3–5 entries | Matches the monthly updated ledger data volume, and avoids introducing redundant non-authorization-related data |
| `responseData` | Include citation source fields | Forces return of authorization document numbers and storage paths, meeting audit requirements for compliance traceability |
| `detail` | Enabled | Displays specific fields of cited content, such as the correspondence between the number of installed nodes and authorized quantity |
| Maximum Response Tokens | 4000–6000 token | Balances the content length of compliance descriptions and citation displays, adapting to information display needs for review scenarios |

## Three Common Misconfigurations
- Phenomenon: After configuring `quoteMaxToken`, cited license authorization clauses are truncated, and the full authorization scope cannot be displayed. Cause: The single-citation token count was set too low, without matching the single-page content length of license documents.
- Phenomenon: Returned results contain a large number of non-authorization-related redundant citations, which reduces code review efficiency. Cause: The number of knowledge base citations was not limited, and temporary endpoint scan data not updated monthly was introduced.
- Phenomenon: After configuring Maximum Response Tokens, the model returns timeouts or errors for empty fields. Cause: The response token count was not set based on the content length of compliance audit reports, so the count cannot cover complete traceability explanations.

## How to Verify Correct Configuration
- Manually import a monthly license ledger, trigger the code review assistance process, and check whether the returned citations include the authorization number and expiration date from the ledger.
- Check the returned content of the `responseData` configuration item, and confirm whether it includes association identifiers for procurement contracts and compliance audit reports.
- Adjust the value range of configuration items, verify that the citation length matches the single-page content of license documents, with no truncation or overflow.
- Simulate a change review scenario, confirm that the units of returned citation fields and ledger fields are consistent, with no unit mismatch issues.

The values provided are common starting points and should be evaluated against individual deployment samples.
