# Code and Change Review Assistance for Crowdsourced Labeler Management: Workflow Orchestration

## What This Category’s Data Looks Like
Data for this category primarily comes from crowdsourcing platform backends, annotation quality spot-check records, annotator training exam results, and financial settlement systems. Daily maintained documents include personnel access rules, standardized training materials, monthly performance reports, and settlement statements.
Data update frequencies are split into daily and monthly updates. Daily updated data includes daily annotation task completion volumes and quality spot-check results. Monthly updated data includes full-cycle performance rankings and settlement details.
Data fields include unique personnel identifiers, access assessment scores, task completion rates, quality pass rates, settlement amounts, and additional relevant fields.

## How These Characteristics Impact Workflow Orchestration
The scattered data sources and varying update cycles for this category require workflow orchestration to support integration with multi-source system interfaces. This enables data synchronization across crowdsourcing platforms, quality data systems, and financial systems.
Data sources with different update frequencies need corresponding scheduled trigger rules. Daily updated data maps to workflow nodes that run daily. Monthly updated data maps to monthly-triggered batch processing nodes.
Access to multiple types of business documents requires workflow support for unified parsing of structured and unstructured data. A validation step must be embedded to avoid errors during personnel screening and settlement verification.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Cycle | Daily, Monthly | Matches the update rhythm of daily and monthly data |
| Cross-Source Data Pull Timeout | 600 seconds | Adapts to differences in interface response times across crowdsourcing platforms and financial systems |
| `variables` Scope | Global | Supports sharing core data such as personnel performance and settlement details across nodes |
| Loop Body Input Type | Array<string> | Adapts to scenarios involving batch processing of personnel lists and task batches |
| Error Retry Count | 3 times | Prevents task interruptions caused by temporary network fluctuations or interface jitter |
| Workflow Node Permissions | Quality inspection leads only | Aligns with access control requirements for quality data |

## Three Common Configuration Mistakes
- Custom plugins added to workflows do not display input or output parameters. The cause is failure to correctly bind `variables` parameter mappings in plugin configurations, which prevents the workflow from recognizing the plugin’s input and output parameter definitions.
- Using the HTTP module to send annotation data fails to retrieve complete file parameters. The cause is failure to preconfigure a temporary storage path for file uploads in the workflow’s `variables`, which prevents the node from reading user-uploaded file information.
- Workflow loops do not correctly iterate over the target array. The cause is failure to set the loop body input type to match the array element format, which prevents the loop node from identifying the personnel or task list to process.

## How to Verify Successful Configuration
- Manually trigger a workflow, and check if node logs correctly pull personnel lists from the crowdsourcing platform and settlement data from the financial system.
- Verify that the input parameters of the loop body node match the preset array format, and confirm that each element is correctly passed to downstream nodes during iteration.
- Validate that the input and output parameters of custom plugins display normally in the workflow editing interface, and confirm that parameter binding relationships are correctly configured.
- Export a test version of the workflow, and confirm that the export function properly generates reusable configuration files that include all core nodes and parameter settings.
