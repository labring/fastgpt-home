# Code and Change Review Assistance for Crowdsourced Labeler Management: Tool Calling and Plugins

## What Data Does This Category Include
This category’s data mainly comes from crowdsourced platform personnel ledgers, sampling results of annotation quality, training exam records of labelers, and settlement details from financial systems. Daily maintained documents include personnel access rules, post-training materials, monthly performance sheets, and quarterly settlement lists.
Data update frequencies are mostly daily (for on-duty status and same-day annotation quality) or monthly (for performance summaries and settlement data). Core fields include unique personnel identifiers, access review status, training qualification levels, single-batch annotation accuracy, settlement cycles and amounts, and more.

## What Constraints Do These Characteristics Impose on Tool Calling and Plugins
Since data sources are scattered, tool calling must support connecting to multi-source APIs of crowdsourced platforms, annotation quality systems, and financial systems. Pre-configured field mapping rules are required to unify data formats.
As data update cycles split into daily and monthly, tool triggering must distinguish scheduled task execution frequencies: use daily sync for daily updated data, and monthly bulk pull for monthly updated data.
Daily documents include access rules and performance sheets. Tool calling must support reading specified-format documents to extract review conditions for automatically generating personnel review logic.
To avoid quality fluctuations and settlement errors, tool calling must add field validity checks to prevent incorrect payments caused by parameter errors.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | This scenario requires automatically matching tools adapted for crowdsourced labeler management, no manual specification of call targets needed |
| `functionCall` | Enabled | External interfaces need to be called to pull labeler performance and settlement data; enabling function call enables parameterized data acquisition |
| Tool call timeout | `600 seconds` | Bulk data pulls from crowdsourced platforms usually take a long time; 600 seconds covers most conventional synchronization scenarios, calibrated based on actual tests |
| Document reading format | Tables, PDF text | Daily maintained personnel access rules and performance sheets are mostly in table or PDF formats, so support for reading structured content is required |
| Scheduled trigger cycle | Daily, Monthly | Data update frequencies are divided into daily updates (on-duty status, same-day quality) and monthly updates (performance summary, settlement), corresponding to different synchronization cycles |

## Three Common Mistakes
- Phenomenon: Tool calls throw timeout errors with a 504 status code returned. Cause: No reasonable timeout period is configured, and the default timeout duration is insufficient to complete the pull of bulk labeler data.
- Phenomenon: Tool calls return empty fields, unable to obtain labeler performance data. Cause: Incorrect parameter mapping for `functionCall` is not configured, and the personnel ID field of the crowdsourced platform is not associated, leading to incorrect interface request parameters.
- Phenomenon: Review results returned by the tool are plain text with no structured format. Cause: No return format is specified, and structured output is not enabled, leading to monotonous display after front-end parsing.

## How to Confirm the Configuration Is Complete
- Manually trigger a tool call, check if the returned labeler data includes core business fields, and verify that the field mapping matches the configuration.
- View the tool call logs to confirm that the timeout period configuration is in effect, with no frequent timeout errors.
- Check the scheduled task execution records to confirm that daily and monthly updated data have completed synchronization according to the preset cycles respectively.
- Call the test interface to verify that the `toolChoice` automatic tool selection logic adapts to the current scenario requirements, and confirm that the returned content is in structured format.
