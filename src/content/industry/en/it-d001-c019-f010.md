# Code and Change Review Assistance for Crowdsourced Annotator Management: Citation Sources and Traceability

## Data Profile for This Category
Data for this category comes primarily from crowdsourcing platform backends, annotation quality inspection records, annotator training exam archives, and financial settlement systems. Daily management documents include personnel access rules, training materials, monthly performance sheets, and settlement lists.
Annotation completion status data syncs daily (within 24 hours). Performance and settlement data updates follow a natural monthly cycle.
Data fields include unique personnel identifiers, access review status, training assessment scores, single-annotation accuracy, monthly settlement amounts, and more. There is no unified standardized format, with minor variations based on platform configuration.

## Constraints on Citation Sources and Traceability
The multi-source, decentralized data structure of this category requires traceability links to support cross-system association verification. This avoids information bias from single data sources.
Diverse document types require field matching rules tailored to different structures. For example, link monthly score fields in performance sheets to assessment records in training materials.
Daily updated annotation quality data requires traceability links to support real-time synchronous verification. Monthly settlement data requires historical version traceability capabilities.
The lack of unified field naming increases citation matching complexity. Flexible field mapping rules must be configured to adapt to field differences across sources.
Traceability results must directly link to specific annotators and corresponding business links. This prevents issues such as incorrect or missed payments, or quality judgment deviations.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Traceability data for crowdsourced annotations includes personnel archives, quality inspection records, and settlement details. Single traceability content is lengthy. Reserve sufficient tokens to accommodate multi-source associated information, and adjust based on actual measurements |
| `responseData` | `Field set including personnel ID, annotation accuracy, and settlement amount; maximum association of 3 data sources` | Core traceability objects for this category are annotator business data. Clearly return corresponding business fields, and support associated display of multi-source data. This meets quality inspection and settlement verification needs |
| `detail` | `Enabled; return historical traceability records from the last 30 days` | Return specific source document paths, update times, and associated personnel information for traceability data. This supports cross-verification of personnel performance and settlements, aligning with core business verification requirements |
| Multi-source association switch | Enabled | Adapt to the multi-system, decentralized data characteristics of this category. Enable traceability association across platforms and document types, avoiding information bias from single data sources |
| Field mapping matching threshold | Adjust based on actual measurements | Adapt to the lack of unified field naming for this category. Flexibly adjust the matching threshold to associate fields from different sources, ensuring accuracy of traceability associations |

## Three Common Misconfigurations
- Phenomenon: API calls return traceability results that only show content fragments, without cited file names. Cause: The `detail` configuration item is not enabled, or file name and document path fields are not specified in `responseData`.
- Phenomenon: Traceability results return business data from highly ranked but non-target personnel, without linking to specific annotators. Cause: Cross-source association field mapping rules are not configured, causing matching logic to incorrectly associate archive information from other personnel.
- Phenomenon: Multiple types of document data cannot be cited as traceability sources simultaneously. Only a single document can be selected via dropdown. Cause: Multi-source field mapping configuration is not enabled, and multi-data source association trigger logic is not built into the workflow.

## How to Verify Proper Configuration
- Initiate a test call for annotator performance verification. Check if returned results include fields specified in `responseData`, to confirm field completeness.
- View detailed traceability results. Confirm that document paths, update times, and historical record ranges enabled by the `detail` configuration item are included, to verify traceability link integrity.
- Simulate a cross-source data association scenario. Enter a specified personnel ID, check if returned results only associate corresponding business data for that personnel, to verify field mapping rule accuracy.
- Adjust the value of `quoteMaxToken`. Test return integrity for long-content traceability, to confirm token reservation meets business requirements.

The values listed are common starting points, and should be evaluated against the reader's own samples.
