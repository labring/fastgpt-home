# Code and Change Review Assistance for Supplier and Equipment Arrival Management: Multi-turn Dialogue and Prompting

## What the data for this category looks like
Core data for this category originates from ERP systems, supplier shipping documents, logistics information, and equipment manufacturer backends. It supports the full equipment arrival process for integration projects, and covers change reviews for equipment configuration code and arrival acceptance logic code.
Daily processed documents include purchase orders, arrival acceptance sheets, serial number lists, and invoice materials. Data is updated per order or weekly.
Core fields include purchase model, equipment serial number, arrival quantity, acceptance status, and more. Fields across different documents have cross-correlations. For example, the model on a purchase order must match the equipment model on the serial number list. Code changes must comply with validation rules for these fields.

## What constraints these characteristics impose on multi-turn dialogue and prompting workflows
Data for this category is distributed across multiple systems and updated per order. It also covers change reviews for equipment configuration code and arrival acceptance logic. This requires multi-turn dialogues to accurately link single-batch business documents and code change content.
The cross-correlation of core fields requires prompts to clearly define field mapping rules. This prevents mismatches between models and serial numbers, and validates whether code changes meet procurement parameter requirements.
Single-batch data has a moderate volume but diverse field types. Dialogue context must limit the loaded scope to prevent irrelevant historical data from disrupting current verification and review workflows.
Errors in this category directly impact project delivery. Prompts must break down time-consuming steps including model verification, arrival acceptance, and serial number registration. This guides step-by-step confirmation of code change compliance and reduces manual oversights.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the arrival acceptance sheet | Isolate dialogue context per order to avoid confusion from cross-order code change review data |
| `messages` | Load the first 3 historical dialogues of the current batch | Single-batch data has a moderate volume; limiting historical loading scope reduces inference latency |
| `variables` | Bind to purchase order number and equipment serial number fields | Lock core business parameters for the category, allowing prompts to accurately identify exclusive data and code validation rules |
| Maximum context length | 1000–1500 characters | Match the number of fields in single-batch documents and code changes, avoiding resource usage from overly long context |
| Code change validation switch | Enabled | Validate whether the equipment model configuration in code changes matches the purchase order |
| Online retrieval permission | Enabled | Synchronously call logistics information and supplier shipping documents to verify arrival status and compliance of code logic |

## Three common misconfigurations
- Issue: Unable to match purchase models during code change reviews. Cause: Failed to bind core business fields for the category via `variables`, so prompts cannot identify model parameters from purchase orders.
- Issue: Unable to clear historical dialogue records after local deployment with Docker Compose. Cause: Failed to isolate dialogue storage per order; cross-order historical data was not cleaned or isolated.
- Issue: Abnormal code change review results after switching AI models. Cause: Failed to bind the arrival acceptance sheet identifier via `chatId`. Context and model switching were not linked, resulting in disorganized review logic.

## How to verify successful configuration
- Enter a purchase order number, and check if bound `variables` field data is automatically loaded in the dialogue interface.
- Submit equipment configuration code change content, and check if prompts automatically link purchase model parameters for validation.
- After switching AI models, check if the current dialogue context remains consistent with the current acceptance sheet, with no critical historical information lost.
- Trigger online retrieval, and check if verification results for corresponding logistics information or supplier shipping documents are returned.
