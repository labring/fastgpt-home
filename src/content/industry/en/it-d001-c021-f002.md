# Code and Change Review Assistance for Supply Chain Security and Open Source Dependency Governance: Context and Token

## What this category of data looks like
This category serves security teams, developer productivity teams, and open source governance offices. Data is primarily sourced from package managers, code repositories, public vulnerability databases, and license databases. Update frequency is daily or when each software version is released.
Daily deliverables include SBOM lists, dependency risk reports, license compliance lists, and vulnerability repair tickets. Data fields cover component name, version number, license type, vulnerability CVE ID, repair status, and more. Common units are component entries, version numbers, and risk level identifiers.

## What constraints do these characteristics impose on the context and token workflow
Data from this category comes from multiple external sources, with significant differences in field formats. Precise matching of context fragments is required to complete dependency identification and risk correlation.
Update frequency is daily or per version release, requiring timely context synchronization to prevent use of expired dependency data.
Daily documents include multiple component entries. Token consumption per processing increases with the number of components, requiring reasonable limitation of context scale.
Vulnerability repair tickets are associated with code changes and dependency risks. Token allocation must be prioritized for highly relevant change and risk fragments to avoid invalid token usage.

## How to configure settings
These configuration options are optimized for FastGPT v4.17.0:

| Configuration Item | Suggested Range | Rationale |
| ---- | ---- | ---- |
| Max context length | 8000–12000 token | Adapts to the scale of multiple component entries in SBOM lists and dependency reports, avoids token overlimit errors |
| Maximum token count per quoted segment | 1500–2000 characters | Matches the full information length of a single dependency component, ensures complete risk descriptions |
| Chunk overlap length | 200–300 characters | Prevents cross-chunk splitting of dependency components, preserves contextual continuity for version and risk correlations |
| Single recall limit | Top 10 entries | Focuses on high-priority dependency risk entries, controls overall token consumption |
| `maxContext` | Calibrated based on actual testing | Adapts to hardware resources and business concurrency for private deployments |
| `quoteMaxToken` | 1200–1800 token | Aligns with standard length of a single vulnerability report or license detail |

## Three common misconfigurations
- Phenomenon: Token overlimit errors or request timeouts occur when `maxContext` is set too large. Cause: Context length is not adjusted based on the number of components in the SBOM, leading to token usage exceeding platform limits.
- Phenomenon: Dependency matching results are missing after importing dependency lists in Excel format. Cause: Chunk overlap length is set too small, causing cross-chunk dependency version and risk correlation information to break.
- Phenomenon: Data conflict-related errors appear after running dependency identification tasks consecutively. Cause: Single recall entry count is not limited, leading to repeated loading of information for the same dependency component in the context and causing duplicate data issues.

## How to verify correct configuration
- Import a standard SBOM list, check that the number of component entries loaded in the context matches the original list.
- Trigger a change review task, view token consumption statistics, confirm it does not exceed the preset `maxContext` limit.
- Compare matching results from dependency risk reports, confirm that associated information for high-risk components is complete and not truncated.
- Run dependency identification tasks consecutively three or more times, check that no duplicate data conflict errors occur.

The values provided are common starting points and should be measured against the reader's own samples.
