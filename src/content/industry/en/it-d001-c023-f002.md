# Code and Change Review Assistance for IT Budget and Project Portfolio Management: Context and Token

## What the data for this category looks like
The core data for this category comes from financial systems, project management systems, contract ledgers, and business department requirements. Regularly produced documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment review reports. Data update cycles are mostly monthly, quarterly, or annual. A single input document includes fields like budget amount, project duration, project approval status, and revenue forecast. Units include yuan, calendar days, and others. Data formats vary across different sources, and some fields use non-standard naming conventions.

## What constraints do these characteristics create for context and token processing
The multi-source and non-standard nature of this category's data requires field normalization before context concatenation, otherwise invalid token consumption will occur. Monthly or quarterly update cycles mean high-frequency context cache refreshes are not necessary, but a single review may involve multiple cross-system documents, and the total token count may exceed model limits. The need for precise matching of core fields requires context retrieval to prioritize key information such as budget priority and project revenue, to avoid irrelevant data occupying token quotas. Ultra-long annual budget documents may cause single-task token limit violations, leading to timeout or truncation issues.

## How to Configure
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum context token count | `8000–12000 token` | Adapts to general large model output limits, prevents review results from being truncated |
| `quoteMaxToken` | `3000–5000 token` | Matches the key content length of a single core document, avoids loading redundant data |
| Similarity threshold | 0.5–0.7 | Filters low-relevance non-budget data, reduces invalid token consumption |
| Number of single retrieval results | Top 6 | Adapts to the monthly updated project data volume, avoids context overload |
| `maxContext` | 14000 token | Reserves sufficient space for concatenated content of multiple cross-system documents; supported in FastGPT v4.17.0 |
| Reranking switch | Enabled | Prioritizes retrieval of core fields such as budget priority and project duration, improves context accuracy |

## Three Common Misconfigurations
- Task execution timeout: The symptom is an error return indicating timeout before the task completes. The cause is failing to lower the context cache refresh interval based on the category data update frequency, leading to excessive concatenation of historical budget data.
- Output truncation: The symptom is the large model output stopping at 12288 tokens with a prompt indicating the reply limit was exceeded. The cause is the `maxContext` setting not matching the large model's 16384 token output limit, and failing to filter redundant fields in contract ledgers.
- Core content retrieval failure: The symptom is failure to retrieve target budget entries or project proposal information. The cause is a similarity threshold set too low that introduces irrelevant data, or failing to enable reranking which prevents core fields from being prioritized for retrieval.

## How to Verify Proper Configuration
- Upload an annual budget sheet, view the context concatenation preview, and confirm that core fields are not truncated or omitted.
- Initiate a project portfolio review task, check the token consumption value in the task log, and confirm it does not exceed the preset `maxContext` configuration.
- Adjust the similarity threshold, verify that the retrieved project data matches the core review requirements of the business department.
- Simulate an ultra-long task execution, check for timeout or truncation errors, and confirm the configuration meets scenario requirements.
