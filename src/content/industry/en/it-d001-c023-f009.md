# Code and Change Review Assistance for Informatization Budget and Project Portfolio Management: Tool Calling and Plugins

## What data for this category looks like
Data for this category mainly comes from financial systems, project management systems, contract ledgers, and business department requirements. Regularly produced standard documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment review reports. Data update cycles are typically monthly, quarterly, or annual. Fields covered include budget amount, project cycle, priority, revenue forecast, and others. Corresponding units include ten thousand yuan, calendar days, project numbers, and more.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category are scattered, with significant format differences. Plugins must support APIs for multiple heterogeneous systems to avoid limitations from single data sources. Data update cycles are slow, so tool calling triggers do not need high-frequency execution, and can adapt to monthly or quarterly fixed update cycles. Document structures include multi-dimensional fields, so tool calling requires configured field extraction rules to only capture core information such as budget and priority, reducing interference from invalid data. Plugins must also adapt to the visual output format of project portfolio dashboards to meet display needs for review scenarios.

## How to configure settings
For FastGPT v4.17.0, configure tool calling and plugin parameters using the following rules:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts to tool calling requirements for multi-system data pulling and field extraction |
| `functionCall` | Bind budget and project field extraction functions | Accurately grabs core business fields from annual budget sheets and project proposal documents |
| Single call data limit | Top 20 entries | Matches the core project count normally displayed on project portfolio dashboards |
| Timeout threshold | 600 seconds | Fits the average time required to pull data across financial and project management systems |
| Trigger execution timing | Monthly/quarterly nodes | Aligns with the monthly, quarterly, or annual data update cycles for this category |

## Three common configuration errors
- Phenomenon: After referencing a plugin in a workflow and connecting a code running node, an error occurs when clicking the input trigger. Cause: The `functionCall` binding for corresponding business field extraction rules is not configured, so the plugin cannot recognize the input format of budget and project data.
- Phenomenon: After calling the search plugin, only simple information is returned, and complete content of the target webpage cannot be obtained. Cause: The plugin's webpage content pulling configuration is not enabled, only keyword search logic is configured.
- Phenomenon: Only a small number of optional models are visible in the tool configuration interface, and the full list of models cannot be selected. Cause: Global model visibility permission is not enabled in the plugin configuration, only a preset small number of adapted models are bound.

## How to confirm the configuration is complete
- A plugin call is triggered, and the returned data is checked for core business fields such as budget amount and project priority.
- The call duration is verified to be less than 600 seconds, confirming the timeout threshold configuration is active.
- The output format is checked to match the display structure of the project portfolio dashboard, adapting to display needs for review scenarios.
- The trigger timing is confirmed to align with monthly or quarterly budget update nodes, verifying the scheduled task configuration is correct.
