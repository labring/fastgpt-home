# Code and Change Review Assistance for Information Flow Ad Creative Testing: Tool Calling and Plugins

## What Data for This Category Looks Like
The data for this category comes primarily from ad delivery platforms, enterprise material libraries, user interaction data backends, and conversion data reports. Regularly synced documents include creative scripts, material test sheets, delivery data reports, and iteration checklists. Data updates occur daily or weekly. Core fields include material unique identifiers, creative combinations (image/video/copy variants), delivery time periods, impressions, click-through rates, and conversion costs. Field dimensions adjust dynamically based on the test cycle, with no unified fixed field structure.

## What Constraints These Characteristics Impose on Tool Calling and Plugin Workflows
Data sources for this category are scattered, update rhythms are inconsistent, and field dimensions are flexible. These factors create multiple constraints for tool calling and plugin configuration. First, connections to multiple types of heterogeneous interfaces such as ad platforms, material libraries, and data reports are required. Plugins must adapt to different authentication protocols and return formats. Second, data updates primarily occur daily or weekly. The trigger frequency of tool calls must match this rhythm to avoid triggering interface rate limits from high-frequency calls. Third, core fields adjust dynamically based on the test cycle. Plugins must support custom field mapping rules to adapt to parameter extraction for different test scenarios. Finally, creative review requires association with multi-dimensional delivery data. Tool call parameters must cover indicators such as impressions, clicks, and conversions, and parameter integrity must be verified during the change review phase.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatically matching tools for the current review scenario, no manual specification of call items required |
| `functionCall` | `["query_material", "get_ad_metric", "calc_conversion"]` | Specifies core tools to call for the current scenario, covering three types of needs: material query, delivery indicator acquisition, and conversion calculation |
| Tool call timeout | `600 seconds` | Matches the average response delay of daily delivery data, prevents review task failures caused by interface fluctuations |
| Bulk data limit | `Top 10 creative combinations` | Controls the amount of data returned per call, adapts to the lightweight verification needs of reviews |
| Field mapping rules | Determined based on actual testing | Adapts to dynamic field requirements for different test scenarios, covers core indicators such as impressions, clicks, and conversions |
| Change review trigger condition | Triggered upon submission of creative iteration checklists | Matches the daily creative iteration process nodes, ensures all change items are included in the review scope |

## Three Common Misconfigurations
- Phenomenon: An MCP tool call prompts that only the stdio process is supported, and tools packaged with the sse protocol cannot be used. Cause: The appropriate communication protocol was not correctly selected in the FastGPT v4.17.0 plugin configuration. The default enabled stdio mode is incompatible with sse packaging.
- Phenomenon: The interface call succeeds, but the extracted output fields are empty. Cause: No field mapping rules matching the interface return format were configured, so target fields in the returned data cannot be identified.
- Phenomenon: Tool call times out, returning a 504 status code. Cause: The set timeout period is shorter than the average interface response delay, or the number of creative combinations called in bulk exceeds the interface's carrying limit.

## How to Confirm Configuration is Complete
- Check the communication protocol options on the plugin configuration page, confirm that the mode matching the tool packaging method is selected.
- Submit a test creative change, check whether the tool call return results include preset core indicator fields.
- Simulate a bulk call scenario, verify that the tool call response time meets expectations.
- Check the change review trigger logs, confirm that the tool call process is automatically triggered after the iteration checklist is submitted.
