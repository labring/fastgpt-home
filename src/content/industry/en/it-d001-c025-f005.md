# Code and Change Review Assistance for Duty Scheduling and Handover: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data for this category originates from internal enterprise scheduling systems, fault ticket libraries, monitoring alert platforms, and organizational contact directories. Daily maintained documents include periodically updated duty schedules, on-duty handover records, escalation contact lists, and daily duty reports. Data fields include duty time periods, unresolved fault items, contact information, alert trigger times, and additional relevant details. Updates occur daily or weekly, with real-time or scheduled synchronization aligned to duty rotations and fault workflow transitions.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Data sources for this category are scattered, with inconsistent update rhythms. Multi-turn dialogue must retrieve information from distinct data sources such as scheduling systems and fault tickets in sequential steps. Prompts must clearly define retrieval scopes to avoid redundant content. Field structures of duty schedules and handover records vary widely. Multi-turn dialogue must guide users to explicitly specify required document types and corresponding fields. Time-consuming pain points in handover and scheduling coordination require prompts to prioritize core scenarios including unresolved item confirmation and conflict resolution, to minimize interference from irrelevant information. Real-time data updates also require prompts to adapt to document timeliness across different cycles, ensuring retrieved content matches current duty status.

## Three Common Misconfigurations
- Phenomenon: API calls return results inconsistent with online dialogue, and handover record fields are missing. Cause: Corresponding business variables are not configured in the API request's `variables`, preventing the prompt from matching exclusive document fields for this category.
- Phenomenon: Scheduling system retrieval is triggered multiple times during multi-turn dialogue. Cause: Context rounds are not limited in `messages`, leading to repeated calls of old retrieval requests and increased system load.
- Phenomenon: No response occurs after the AI reply comment is triggered in the workflow. Cause: The `chatId` parameter is not configured correctly, so the system cannot associate the current conversation context and fails to trigger subsequent comment logic.

## How to Verify Successful Configuration
- Launch a simulated duty handover conversation, check that the conversation history retains recent interactions, and confirm the `messages` configuration is active.
- Call the API or test the prompt online, check that returned results only include documents of this category such as duty schedules and handover records, and confirm the retrieval scope configuration is correct.
- Trigger the AI reply comment node in the workflow, check that comments are normally triggered after the conversation completes, and confirm the `chatId` parameter configuration is correct.
- Adjust the conversation context round parameter, verify that key handover information is not lost during multi-turn dialogue, and confirm the configuration matches business requirements.
