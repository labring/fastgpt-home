# Code and Change Review Assistance for Duty Scheduling and Handover: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category comes from scheduling systems, fault work orders, monitoring alerts, and organizational contact directories. Update frequency is daily or weekly. Daily output documents include duty schedules, handover records, escalation contact lists, and daily duty reports. Fields cover duty time periods, unresolved pending items, emergency contact information, alert response priorities, etc. Only clear person-item association information is recorded, with no additional statistical quantitative fields.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Workflow
Since data for this category comes from multiple independent systems, tool calling requires configuring multi-source parameter mapping to avoid information loss caused by field mismatches. The data update frequency is daily or weekly, so plugin triggers do not need high-frequency polling, and daily synchronization trigger rules can be set. Daily documents have a fixed structure, so plugins must adapt to clear fields such as duty time periods and unresolved pending items, and cannot flexibly adapt to non-standard custom fields. Additionally, the handover process needs to associate fault work order status, so tool calling must support linked queries of unresolved work order items to ensure complete handover information.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic selection of tools adapted for duty scheduling and handover scenarios, no manual specification of call targets required |
| Plugin Trigger Frequency | `Daily at 00:00` | The data update frequency for this category is daily or weekly. Daily synchronization covers daily duty update requirements |
| Multi-source Parameter Mapping Rules | Map fields one-to-one according to scheduling systems, fault work orders, and organizational contact directories | Data sources for this category are scattered. Clear mapping prevents field misalignment between different systems |
| Field Matching Validation | Enable required field validation | Daily documents include fixed required fields. Validation prevents key information from being omitted during handover |
| Timeout Setting | `300 seconds` | Tool calling needs to synchronize queries across multiple systems. Reserve sufficient response time to cover multi-source data retrieval |
| Number of Results Returned | `Top 10` | Duty-related information does not require excessive entries. Focusing on core pending items and contacts meets scenario requirements |

## Three Common Mistakes
- Phenomenon: Tool calling returns results that take longer than the preset threshold, and the interface displays a timeout status code. Cause: The timeout setting was not adjusted based on the multi-system data source of this category, causing multi-source query wait times to exceed the reserved duration.
- Phenomenon: Only some parameters are obtained when calling the plugin, and the remaining required fields are empty. Cause: No automatic question-and-answer parameter completion process was configured, and no parameter completion step was triggered before tool calling.
- Phenomenon: Duty information retrieved from the knowledge base is too long, and the rearrangement logic is not triggered. Cause: Field matching validation was not enabled, or the number of results returned was set too high, resulting in failure to filter valid information by core fields.

## How to Confirm Proper Configuration
- Manually trigger plugin calls, check whether duty personnel information from the scheduling system and contact information from the organizational contact directory can be correctly retrieved.
- View tool calling logs to confirm that the multi-source parameter mapping rules have taken effect and that there are no field misalignments.
- Wait for the daily scheduled plugin task, check whether a daily duty report and handover records that conform to the format are generated.
- Simulate a parameter missing scenario, check whether the question-and-answer process for parameter completion is triggered.

The values provided are common starting points and should be measured against the reader's own samples.
