# Code and Change Review Assistance for Duty Scheduling and Handover: Citation Source and Traceability
This page is compatible with FastGPT v4.17.0.

## What the data for this category looks like
The core data for this category comes from internal scheduling systems, fault ticket systems, monitoring alert platforms, and organizational contact directories. Update frequency is daily or weekly. Daily produced documents fall into four categories:
- Duty schedules divided by date, including fields for duty personnel, contact information, and responsible time slots
- Handover records, including fields for pending items, follow-up status, and handover personnel
- Escalation contact lists, including fields for job roles and emergency contact information
- Daily duty reports, including fields for daily alerts and processing progress
The field structures and update rhythms of various documents vary significantly, and most are structured internal team records.

## What constraints do these characteristics impose on the citation source and traceability process
The scattered data sources require the traceability link to support cross-system associated queries, ensuring that duty schedules, handover records, and escalation contact information can be retrieved simultaneously. The daily or weekly update frequency requires configuration to support regular index refreshes, preventing the use of expired duty arrangements or handover items. The differences in field structures across documents require traceability to match corresponding fields by document type: extract duty personnel contact information from duty schedules, and extract pending item details from handover records. The most time-consuming duty scheduling conflict coordination and handover links require traceability results to quickly locate records for corresponding time slots. The risk of unaddressed issues and timeouts from errors requires the traceability link to ensure the completeness and timeliness of cited data, and avoid missing key fields.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average text length of documents such as duty schedules and handover records, preventing truncation of core information like pending items and responsible time slots |
| Single search limit | Top 6 entries | Matches the total number of documents within a weekly duty cycle, covering complete duty arrangements and handover records |
| `responseData` | Include document type and update time fields | Facilitates confirming data category and timeliness during traceability, avoiding use of expired duty information |
| `detail` | Enable full field display | Shows key content such as pending items and emergency contact information, meeting the needs of scheduling conflict coordination and handover confirmation |
| Maximum context | Calibrated via actual testing | Adapts to the content length after splicing multiple data sources, avoiding exceeding model processing limits |

## Three common mistakes
- Phenomenon: The number of knowledge base citation entries returned does not meet expectations, only 2 entries are displayed. Cause: The single search limit configuration value is set too low, failing to cover all document records within the weekly duty cycle.
- Phenomenon: The citation results do not show update time and document type fields. Cause: The return fields for `responseData` are not configured correctly, making it impossible to confirm data timeliness and category during traceability.
- Phenomenon: Long-text handover records are truncated, and complete pending item descriptions are not displayed. Cause: The `quoteMaxToken` configuration value is too small, truncating text content that exceeds the threshold.

## How to confirm the configuration is correct
- Upload a sample document set of a weekly duty schedule and handover records, trigger a search, and check the number of returned citation entries to confirm they match the configured single search limit.
- Check the displayed content of each citation result to confirm that document type and update time fields are included, verifying that the `responseData` configuration takes effect.
- Input a long-text handover record containing pending items, check whether the returned citation content fully displays all details, verifying that the `quoteMaxToken` configuration is appropriate.
- Simulate an update to duty information in the scheduling system, trigger index refresh again, and perform another search, confirming that the citation results are updated to the latest duty arrangements, verifying that the configuration adapted to daily/weekly update frequencies takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
