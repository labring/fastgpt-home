# Code and Change Review Assistance for Level Content Creation: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data sources include level editors, art resource libraries, player test data, and defect systems. Daily produced documents include level design drafts, resource requirement sheets, test feedback sheets, and version submission records.
Common fields include level ID, path node coordinates, resource reference paths, test pass rate, defect severity, and repair status. Update frequency follows weekly or per version release cycles. Core level path and resource placement data syncs in real time with editing operations. Test feedback sheets are updated with each round of testing.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering workflows
The above data characteristics impose multiple constraints on multi-turn dialogue and prompt engineering workflows. First, structured coordinate and resource path fields require conversation contexts to retain precise associations, to avoid repeated requests for the same level data. Second, update frequency varies with version cycles, so the validity period of conversation contexts must match version rhythms to prevent referencing expired resource paths or test data. Third, defect severity fields require prompts to guide dialogue to focus on reviewing high-priority defects. The `messages` parameter must splice review interactions and tool return results in chronological order to ensure complete review process traceability. Additionally, `variables` must pass the current level ID and version number to avoid mixing review data across levels.

## How to configure settings

| Conversation context window | Retain the most recent 20 interactions | Matches the review rhythm of level content creation, avoids redundant history interfering with current reviews |

## Three common configuration errors
- Tool call results are not displayed in the dialogue box in real time. Results are only visible after re-entering the page, and no tool return result indicator is present. The cause is that the `messages` parameter does not correctly append tool call return content, leading to context loss.
- The iframe-integrated dialogue box displays an English interface and cannot be switched to Chinese. The cause is that the language parameter is not specified in the initialization configuration, or the passed `variables` do not include a language configuration item.
- Frequent request timeout errors occur in the local deployment environment. The cause is that the timeout threshold is set lower than the actual tool call time, or `chatId` does not correctly distinguish between local and cloud environments, leading to abnormal request routing.

## How to confirm configuration is complete
- Initiate a review dialogue, check if the `messages` parameter log output includes the current level's interaction history and tool return results.
- Switch to different levels to initiate a dialogue, confirm that the identifier bound to `chatId` only corresponds to the currently open level, with no cross-level data mixing.
- Initiate a tool call, wait for the corresponding duration, and check if the dialogue box displays return results in real time, with no delays or data loss.
- Copy the dialogue URL, check if the parameters include the current level's associated identifier to ensure correct parameter association.
- View the iframe-embedded page, confirm that the interface language matches the configured target language.
