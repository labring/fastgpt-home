# Code and Change Review Assistance for Level Content Creation: Tool Calling and Plugins
This page is compatible with FastGPT v4.17.0

## What the data for this category looks like
The data for this category mainly comes from level editors, art resource libraries, player test data, and defect systems. Daily produced documents include level design drafts, resource requirement sheets, test feedback forms, and version submission records. Fields cover path node coordinates, resource mounting paths, player feedback tags, defect IDs, and more. The update rhythm follows weekly or per-version iteration cycles. The data is centered on specific maps and task implementations, differing from game numerical design categories that focus on rule-based quantification.

## What constraints these characteristics impose on tool calling and plugin workflows
Data for this category is scattered across multiple systems and tied to specific maps and tasks. This requires tool calls to accurately associate exclusive resources and feedback data for the corresponding level. The update frequency is high, so plugins must support fast retrieval of the latest version submission records and test data. Daily document fields have diverse types, so plugin inputs must support multi-format parameters including coordinates, paths, and tags. Errors will directly impact level delivery, so tool calls must be configured with clear failure retry and alert mechanisms. Calls to resource data from unrelated categories must be avoided, with focus only on art and test content for the current level.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `toolChoice` | `auto` | Supports automatically selecting the appropriate tool to handle level data calling requirements |
| `functionCall` | Allow forced tool specification | Can forcibly call the corresponding tool when processing resource requirement sheets or defect forms with fixed formats |
| Plugin trigger timing | Within 10 minutes after version submission | Matches the weekly or per-version update rhythm of this category, enabling timely retrieval of the latest submission records |
| Input parameter validation rules | Validate formats of fields such as coordinates and resource paths | Daily documents contain multiple types of fields, so invalid parameter calls must be avoided |
| Failure retry count and interval | 2 retries, 30-second interval | Reduces the impact of tool call failures caused by network fluctuations, adapting to scattered data sources |
| Maximum context length | 8000–12000 token | Needs to process multiple documents including level design drafts and test feedback, providing sufficient capacity for associated data |

## Three common mistakes
- Symptom: Preconfigured level path variables cannot be selected in the JSON input box; the input box only supports manual entry of raw strings. Cause: Variable binding compatibility configuration for the plugin was not enabled, causing the JSON format input box to fail to recognize platform built-in variables.
- Symptom: In non-tool calling mode, the model output does not include player test data obtained via web search, while search endpoint logs show results were returned. Cause: The system prompt did not explicitly require referencing external search results in non-tool calling scenarios, causing the model to ignore this type of data.
- Symptom: Uploaded custom plugins cannot be found in the community plugin marketplace, and no error prompts appear during the submission and publishing process. Cause: Category tags and compatible versions for the plugin were not filled out in accordance with platform requirements, causing the plugin to fail classification indexing.

## How to confirm proper configuration
- Trigger a tool call, check if the returned data includes the latest resource paths and test feedback for the current level, and verify that the data source and update time match the configured rhythm.
- Input test parameters including coordinates and resource paths into the plugin, confirm that the input box can correctly recognize and parse the formats without error prompts.
- Simulate a tool call failure scenario, confirm that the system triggers the preset retry count and alert mechanism in line with the configured requirements.
- Check if the plugin can be found in the plugin list for the corresponding category, confirming that the publishing process has completed classification indexing.
