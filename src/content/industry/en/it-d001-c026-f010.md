# Code and Change Review Assistance for Level Content Creation: Citation Sources and Traceability

## What Data Looks Like for This Category
Data for this category primarily comes from level editors, art resource libraries, player test data, and defect systems. Daily produced documents include level design drafts, resource requirement sheets, test feedback sheets, and version submission records. Data updates occur weekly or per version release cycle.
Data fields include level unique identifiers, resource file paths, test case numbers, submitter accounts, version numbers, and more. Some resource-related data includes unit information such as file size and resolution.

## Constraints Imposed on Citation Sources and Traceability
Level content creation data is tied to specific map nodes and resources. Traceability requires linking to exact level IDs and resource paths, and cannot rely solely on generic keyword matching. Weekly or per-version update cycles require traceability systems to quickly locate version-specific submission records, preventing cross-version data confusion.
Test feedback sheets and defect system data are mostly unstructured text, requiring precise matching to corresponding level debugging steps. Resource file paths and size information also require traceability results to clearly display file storage locations and version details. This ensures reviewers can directly locate original resources.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1000 token | Matches the average content length of a single level design draft page, avoids truncating core rule descriptions |
| `responseData` | 5 records associated with the current level ID | Adapts to the volume of weekly updated historical records, reduces redundant data interference with reviews |
| `detail` | Full resource path and version number | Meets the need to quickly locate original art resources or test data |
| Chunk length | 800–1200 characters | Covers complete design content for a single level, avoids splitting critical information |
| Reordering rule | Sorted by level version number | Ensures the latest version review content is displayed first, facilitating version comparison |
| Maximum context | 1500 token | Covers complete resource requirements and test feedback information for a single level |

## Three Common Configuration Errors
- Phenomenon: API calls using FastGPT v4.17.0 return results that do not include cited resource file names. Cause: The full resource path display item for the `detail` parameter is not configured. Only text matching fragments are returned, and original file metadata is not associated.
- Phenomenon: When configuring citation rules, only a single variable can be selected to associate level data, and resource paths and test feedback content cannot be referenced simultaneously. Cause: Multi-variable association configuration is not enabled. The system defaults to limiting the number of variables referenced in a single request, resulting in failure to cover full-link traceability requirements.
- Phenomenon: The citation content displayed in review results is not the highest-matching historical record. Cause: Reordering is not grouped by level ID, resulting in mixed matching results from different levels, disrupting priority, and failing to prioritize content relevant to the current scenario.

## How to Confirm Proper Configuration
- Submit a test request containing a specific level ID and resource path, verify that the returned results include corresponding traceability information
- After configuring multi-variable association rules, confirm that the number of selectable variables in the drop-down menu meets requirements
- Trigger the citation validity verification workflow, input test feedback containing contradictory content, verify that corresponding exception prompts are generated
- Check FastGPT v4.17.0 system logs, confirm that returned citation data matches the current level's version information
