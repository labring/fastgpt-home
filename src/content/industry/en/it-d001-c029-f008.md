# Code and Change Review Assistance for Content Copyright and Authorization Management: Workflow Orchestration

## What the data for this category looks like
This category’s data is sourced from contract systems, copyright registration records, code content repositories, and complaint inboxes. Update frequency is per order or monthly. Daily processed documents include authorization contracts, copyright ledgers, take-down notices, and infringement complaint materials.
Authorization contracts include authorization subject, authorization scope, and authorization duration fields. Copyright ledgers include copyright ID, authorization status, and expiration date fields. Infringement complaint materials include infringement link and complainant information fields. Code content repositories include copyright statements for new code and open source component reference records. Document structures vary widely, with no unified standardized format.

## What constraints these characteristics impose on the "workflow orchestration" link
As part of the code and change review assistance process, scattered data sources require the workflow to connect to multiple data source nodes such as code repositories and contract systems. Each node pulls code change content, contract authorization information, and copyright registration data separately.
Large differences in document structures require the workflow to support flexible field mapping rules to adapt to content extraction from different documents. The per-order or monthly update frequency means the workflow does not need high-frequency triggering. It is suitable for triggering per order after code change submission.
The most time-consuming tasks include authorization scope verification, expiration reminders, and infringement material organization. These tasks need to be embedded as automated processing nodes in the workflow. This reduces manual operation steps and meets the fast feedback requirements of code reviews.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `variables` | Include authorization subject, authorization scope, expiration date fields | Adapt to field extraction requirements for authorization contracts and copyright ledgers |
| Node trigger condition | Trigger per order submission, interval no less than 24 hours | Match per-order or monthly update frequency, avoid invalid calls |
| LLM response timeout threshold | 60 seconds | Address delays from multi-data-source pulls, align with standard interface response cycles |
| Single recall content count | Top 3 entries | Adapt to fast feedback requirements for code change reviews, avoid excessive redundant data |
| `nodeId` | Bound to infringement complaint material extraction node | Accurately locate the node identifier for the infringement material organization step |
| Global variable scope | Workflow-level | Cover authorization status synchronization needs across the entire process |

## Three common errors
- Phenomenon: Authorization scope field is empty after workflow execution. Cause: No mapping rule for authorization scope configured via `variables`, so the corresponding field cannot be extracted from authorization contracts or code copyright statements.
- Phenomenon: No return result when referencing global variables in prompts. Cause: Global variable scope not set to workflow-level. Variables only take effect within a single node.
- Phenomenon: LLM node returns `chat:LLM_model_response_empty`. Cause: No reasonable timeout threshold configured. LLM calls trigger before multi-data-source pulls complete, so no valid input is available.

## How to confirm configuration is complete and correct
- Call the test interface `http://localhost:3000/api/core/chat/chatTest`, pass test authorization contract and code change data, check if returned results include preset authorization-related fields.
- View global variable configuration in the workflow editing interface of FastGPT v4.17.0, confirm scope is set to workflow-level so variables can be called across all nodes.
- Simulate a single code change data entry to trigger the workflow, check that node status transitions normally with no timeout or error prompts.
- View workflow execution logs, confirm that the infringement material extraction node bound to `nodeId` executes normally, with no missing fields or failed call records.
