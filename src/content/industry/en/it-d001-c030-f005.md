# Code and Change Review Assistance for Internal Network and WiFi Operations: Multi-turn Dialogue and Prompt Engineering

## Data Overview for This Category
The data for this category originates primarily from switch consoles, wireless controllers, monitoring systems, and user trouble reporting channels. Updates occur daily or after each completed change. Daily associated documents include network topology diagrams, change tickets, fault records, and wireless coverage inspection forms. Fields covered include port numbers, VLAN configurations, signal strength, fault reporting time, and similar metrics. Common units are unnumbered values, percentages, meters, and others. In processing workflows, fault point location, port and VLAN verification, and coverage blind spot troubleshooting are the most time-consuming steps. Data is updated synchronously after being linked to change actions.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data sources are scattered and tied to individual changes. Multi-turn dialogue must load context in the order of change tickets, topology diagrams, and fault records to avoid interference from invalid data across changes. Document types vary, so prompts must adapt to different input formats, and recognize dedicated fields such as port mappings in topology diagrams and signal thresholds in inspection forms. Update frequency is triggered by changes, so context window size must be limited to prevent loading expired switch configuration data that causes verification errors. The time-consuming fault location steps require multi-turn dialogue to support step-by-step problem breakdown, with each round focusing on only one verification item to avoid context overload that slows response speed.

## Configuration Settings
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to the unique identifier of the current operational change | Ensure multi-turn dialogue context is tied to a single change, avoiding context confusion across changes |
| `messages` | Retain the most recent 20 conversations and 3 associated core documents (topology diagrams, change tickets, fault records) | Match the core document types and change association logic of this category, control context length |
| `variables` | Preset port ranges, VLAN segments, and signal threshold variables | Adapt to fixed operational parameters for this category, reduce repeated input |
| Maximum context window | 8000 token | Balance context completeness and response speed, adapt to daily updated operational data volume |
| Single file upload limit | No more than 100 MB | Match the typical size of documents such as network topology diagrams and inspection forms |

## Three Common Misconfigurations
- After connecting third-party models such as GLM via One API, the model selection list in the dialogue module only displays GPT series models, and third-party models cannot be selected. The cause is that multi-model adaptation is not enabled in the system configuration, and the third-party model identifier is not bound to the dialogue module's selection list.
- When configuring support for both image and file dialogue, front-end upload works normally but the interface returns parsing failure. The cause is that document parsing format rules are not configured correctly, and the processing logic for images and text files is not split into `variables`.
- After orchestrating multi-turn dialogue in a workflow, only the final model result is returned, and intermediate steps cannot be processed step-by-step. The cause is that context caching for `messages` is not set, and processing data from intermediate steps is not retained, preventing subsequent steps from calling prior results.

## How to Verify Correct Configuration
- Initiate a change review dialogue, upload the corresponding topology diagram and change ticket, and verify that port numbers and VLAN configurations are automatically extracted in the dialogue.
- Call the model selection list, confirm that connected third-party models appear in the options.
- Trigger multi-turn dialogue, submit three consecutive different fault troubleshooting questions, and confirm that context retains prior change ticket information.
- Upload a test file larger than 100 MB, and confirm the system returns a file size limit exceeded prompt to verify that the upload limit configuration is active.

The values provided are common starting points and should be evaluated against the reader's own samples.
