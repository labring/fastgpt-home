# Code and Change Review Assistance for Internal Network and WiFi Operations: Citation Sources and Traceability

## What data does this category include?
This category of data mainly comes from switch consoles, wireless controllers, monitoring systems, and user trouble report channels. Daily generated documents include network topology diagrams, change tickets, fault records, and wireless coverage inspection forms. Each document contains fields such as port numbers, VLAN configurations, signal strength, and inspection time.
Data update frequency is either daily or synchronized with individual network changes. The size of a single data entry ranges from tens of bytes to several megabytes. There is no unified standard format, and the export structure of corresponding operation and maintenance tools must be matched.

## What constraints do these characteristics impose on citation sources and traceability?
Dispersed data sources and inconsistent formats mean that field mapping rules for multiple data sources must be adapted during citation and traceability, and standardized indexing logic cannot be directly reused.
Update frequency is triggered by changes. Indexes must be synchronized immediately after change submission, otherwise traceability results will lag behind the latest configurations.
Wide variation exists in single document size. If citation length or chunking rules are not set reasonably, context window limits will be exceeded.
Document fields differ significantly across different operation and maintenance scenarios. Citation data source fields must be accurately matched to avoid traceability results being misaligned with current operation and maintenance needs.

## How to configure settings
The following configurations are based on FastGPT v4.17.0 logic.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average single-block length of internal network operation and maintenance documents to avoid context overflow |
| `responseData` | Enabled | Used to display citation sources for change tickets and topology diagrams, aligns with traceability requirements for operation and maintenance reviews |
| `detail` | Recall top 3 entries | Covers core information of typical fault records and change tickets, balances recall volume and context usage |
| Single retrieval limit | Top 5 entries | Limits the number of data sources per round of retrieval to avoid response timeouts |
| Field mapping rules | Adapt to the export structure of operation and maintenance tools | Adapts to different export fields of switches and wireless controllers, ensuring traceability accuracy |

## Three common configuration mistakes
- Symptom: Retrieval results do not link to corresponding source data, or source data fields are empty. Cause: Field mapping rules are not configured, and export formats of switches and wireless controllers are not adapted, resulting in failure to match citation fields.
- Symptom: Timeouts or lag occur in the change review assistance workflow. Cause: The single retrieval limit is not set, and too many large network topology diagram data entries are recalled, exceeding context window or system processing capacity.
- Symptom: After enabling source data citation, the output content does not reuse preset question-and-answer pair text from the knowledge base. Cause: Strict matching logic is not enabled, causing the system to call general generation logic instead of directly calling source data content.

## How to verify correct configuration
- Submit a simulated network change ticket, check whether the review result links to corresponding source data files such as change tickets and topology diagrams.
- Trigger fault location retrieval, verify that returned source data fields match current operation and maintenance scenario requirements, such as port numbers, VLAN configurations, etc.
- Adjust the value of `quoteMaxToken`, verify that the context window can accommodate the target document content without truncation or overflow prompts.
- After enabling strict matching logic, submit preset knowledge base question-and-answer pairs, confirm that the output content is completely consistent with the original text.
