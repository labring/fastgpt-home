# Code and Change Review Assistance for Creator Onboarding and Verification: Workflow Orchestration

## What the data for this category looks like
Core data for this category comes from the creator backend, enterprise credit information query API, account historical behavior database, and contract management system. Daily circulated documents include onboarding application forms, scanned identity qualification documents, certification audit records, and cooperation agreements. Data updates trigger with the application process. The full-link data update frequency for a single application is daily or per application. A single application record includes fields such as account identifier, qualification verification status, audit node flow records, and more. Qualification materials are stored as binary streams or file hashes. Audit records include operator, operation time, and verification conclusion.

## Constraints on Workflow Orchestration From These Data Characteristics
Core data is scattered across multiple heterogeneous systems. Workflow orchestration must configure cross-data source node call rules. This ensures each link pulls qualification and audit data from corresponding systems. Data updates trigger with the application process. The workflow must bind the status trigger logic of `variables`, only running subsequent verification when the application node status changes. Qualification documents and contract binary data exist. The workflow must pre-configure a file format verification node to filter non-compliant uploaded materials. Manual intervention nodes exist in the audit link. The workflow must set the manual approval hook corresponding to `nodeId` to ensure process flow aligns with audit rhythm. A context processing node must be embedded to adapt to repeated account reference issues in onboarding applications during code review scenarios.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context optimization toggle | Enabled, bound to the top 10 historical record windows | Adapt to reference resolution needs for account information in onboarding applications, reducing repeated inquiries |
| `variables` global variable configuration | Preset application ID, account type, qualification file size threshold | Reuse core application data across nodes, avoiding repeated pulls of information from different systems |
| `nodeId` manual approval node binding | Bound to the failure branch of the qualification verification node | Trigger manual intervention, adapting to non-standard verification scenarios in the audit link |
| Single file upload limit | 1000 MB | Match conventional storage sizes for qualification materials and cooperation agreements |
| Workflow output filtering rule | Only retain the output of the final audit conclusion node | Prevent content from intermediate AI conversation nodes from mixing into the final result |
| Cross-data source call timeout | 600 seconds | Adapt to API response delays for enterprise credit information queries |

## Three Common Mistakes
- Symptom: Content from intermediate AI conversation nodes appears in the final output result. Cause: The workflow output filtering rule is not configured, and the output content of the specified node is not specified to be retained.
- Symptom: Core application data cannot be reused across node calls, requiring repeated pulls of information from different systems. Cause: `variables` global variables are not correctly configured, and core parameters such as application ID and account type are not preset.
- Symptom: Knowledge base search results cannot adapt to the historical context of onboarding applications, leading to ambiguous account references. Cause: The context optimization toggle is not enabled, and the historical record window is not bound to limit the context scope.

## How to Confirm the Configuration Is Complete
- Enter the workflow editing page, check whether the `variables` global variables include core parameters such as application ID and account type.
- Trigger a test application, verify that the final output result only includes the final audit conclusion, with no intermediate AI conversation content.
- Submit a qualification file with non-compliant format, confirm that the workflow triggers the file verification node and blocks the process.
- Confirm that the current FastGPT version is v4.17.0 or higher to ensure compatibility of all configuration items.
