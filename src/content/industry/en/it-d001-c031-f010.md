# Code and Change Review Assistance for Creator Onboarding and Verification: Citation Sources and Traceability

## What the data for this category looks like
The core documents for this category fall into four types: creator onboarding applications, identity qualification materials, verification audit records, and cooperation agreements. Data sources cover creator backends, enterprise credit information platforms, account history databases, and contract management systems. Data updates are triggered by application workflows. Full-link data updates for a single application are triggered per submission. Daily batch verification data is synchronized once daily. Document fields include applicant identifiers, qualification types, audit nodes, associated cooperation numbers, and more. The field length of individual qualification materials varies widely, with no unified fixed maximum single-document size.

## What constraints these characteristics impose on citation sources and traceability
The multi-source data nature of this category requires citation traceability to be bound to a unique application identifier, to avoid mixing audit data from different creators. The update rhythm tied to application submissions requires traceability links to support real-time association with the context of the current audit process, and must not rely on fixed-cycle batch synchronization. The wide variation in field lengths requires that traceability configurations retain the complete field information of the original citation, and must not forcibly truncate unstructured qualification material content. Additionally, the potential consequences of fraudulent verification require that traceability data not be modified arbitrarily. Original source addresses and call timestamps of citations must be retained to ensure traceability during audit workflows, avoiding qualification verification errors and cooperation disputes caused by missing traceability records.

## Configuration Guidelines
These configurations apply to FastGPT v4.17.0 and later.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Max Citation Token Count | 800–1200 token | The field lengths of qualification materials and audit records for this category vary widely, so this range must cover the token consumption of most single citation contents |
| Response Data Format | Only retain original source fields and citation markers | Avoid redundant information interfering with audit workflows, only retain core data that supports traceability |
| Traceability Detail Level | Full Mode | Audit workflows for this category require retaining complete citation links to facilitate subsequent dispute resolution |
| Citation Binding Identifier | Unique Application ID | Traceability data must be bound to creator applications to avoid mixing data from different audit workflows |
| Traceability Trigger Timing | Qualification Verification, Audit Approval Nodes | Match the update rhythm of this category's data tied to application submissions, ensuring traceability is synchronized with audit workflows |

## Three Common Misconfigurations
- The symptom is that after the workflow calls the tool, the input and response citation content from knowledge base search still appear in the reply. The root cause is that the response data format was not configured correctly, and non-essential tool call logs and citation markers were not filtered out.
- The symptom is that service startup verification fails, with a prompt that `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is missing or invalid. Troubleshooting steps: Verify whether the required environment variables `AIPROXY_API_ENDPOINT` (AI Proxy service root address, for example http://aiproxy:3000, do not append paths such as /v1) and `AIPROXY_API_TOKEN` (AI Proxy administrator Token, must match the server configuration and be non-empty) were not configured on the App/Admin server, or whether they were incorrectly filled in workflow global variables or application API request headers.
- The symptom is that the original source of qualification materials cannot be traced during audits. The root cause is that the correct citation binding identifier was not configured, and traceability data was not associated with the unique application ID.

## How to Confirm Proper Configuration
- Log in to the App/Admin server backend, check that the server environment variable configuration includes `AIPROXY_API_ENDPOINT` (AI Proxy service root address, for example http://aiproxy:3000, do not append paths such as /v1) and `AIPROXY_API_TOKEN` (AI Proxy administrator Token, must match the server configuration and be non-empty), and that both are non-empty valid values.
- Submit a test creator onboarding audit request, check whether the returned results include the unique application ID and citation markers for the original source.
- Check the response data format in the workflow configuration, confirm that only core traceable fields are retained, with no redundant tool call logs.
- Trigger a qualification verification node, check whether the traceability link is updated synchronously with the workflow, with no delays or omissions.
