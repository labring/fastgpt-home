# Code and Change Review Assistance for Creator Incentive Settlement: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Typical users of this category are creator operations, financial operations, and data operations personnel. They handle four types of documents daily: incentive rules, settlement details, appeal records, and payment lists. Data sources include content data, advertising revenue sharing systems, financial systems, and account backends. Update frequency is typically monthly or after a single campaign ends. Settlement detail documents contain fields such as creator ID, revenue items, accounting calibers, and payable amounts. Incentive rule documents specify campaign cycles, revenue sharing thresholds, and exception judgment standards. Appeal records and payment lists respectively link information like appeal numbers, processing progress, and payment batches. The overall data structure follows the full settlement workflow.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data comes from multiple heterogeneous systems with inconsistent update schedules. Multi-turn dialogue must accurately bind field mappings across different systems to avoid cross-system data confusion. Document structures vary significantly. Call logic for rule documents and detail documents must be separated. Prompts require dedicated trigger conditions configured for each document type. Monthly or campaign-level update frequencies require regular refreshing of dialogue contexts. This prevents expired settlement rules or detail data from being used. Errors in settlement-related operations directly impact creator rights and interests. Each interaction in a multi-turn dialogue must verify field accuracy. This prevents settlement disputes or incorrect or missed payments caused by parameter deviations.

## Configuration Guidelines
This page is written for FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Context window length | 8000–12000 token | Matches single loading needs for long documents including settlement details and incentive rules, calibrated via actual testing |
| `variables` binding rules | Bind creator ID, settlement cycle, payment batch | Matches core data fields of the category, enables precise association between dialogue context and target settlement data |
| `messages` history truncation threshold | Retain the most recent 3 turns of dialogue | Avoids non-active period old data interfering with current settlement verification, reduces context load |
| `chatId` identification rules | Bind settlement order number + campaign ID | Enables isolation of dialogue context for single settlement batch, prevents cross-batch data confusion |
| Prompt template update frequency | Sync updates with monthly campaigns | Matches the data update rhythm of the category, ensures prompts align with latest incentive rules and settlement calibers |

## Three Common Misconfigurations
- Phenomenon: Dialogue returns a parameter error prompt. Cause: Core fields such as creator ID and settlement cycle in `variables` are not bound as required, causing prompts to fail to match corresponding settlement data.
- Phenomenon: Interface calls fail to retrieve dialogue records for a specified settlement batch. Cause: The `chatId` identifier set to settlement order number + campaign ID is not passed, causing the system to fail to locate the target dialogue context.
- Phenomenon: Professional field recognition deviation occurs in multi-turn dialogue. Cause: Prompt templates are not configured separately for settlement rules and detail data. Generic models are used, leading to insufficient recognition accuracy for incentive calibers and settlement fields.

## How to Verify Proper Configuration
- Manually bind creator ID and settlement cycle in `variables`, initiate a test dialogue, and verify that returned settlement data matches the target creator’s details.
- Pass the specified `chatId` parameter set to settlement order number + campaign ID, call the dialogue record interface, and confirm that historical interaction content for the corresponding batch is returned.
- Configure knowledge base association rules, pass the creator ID retrieval condition from `messages`, and verify that the knowledge base returns documents containing the creator’s settlement details.
- Adjust the `messages` history truncation threshold, test whether the multi-turn dialogue retains the most recent 3 turns of valid context, and confirm no outdated non-active period data is introduced.
