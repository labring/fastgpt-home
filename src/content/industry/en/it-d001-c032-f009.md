# Code and Change Review Assistance for Creator Incentive Settlement: Tool Calling and Plugins

## What this category of data looks like
Daily documents for this category include incentive rules, settlement details, appeal records, and payment lists. Data is sourced from content data, advertising revenue sharing systems, financial systems, and account backends. Update frequency is monthly or aligned with the corresponding activity cycle. Common data fields include creator ID, revenue amount, settlement cycle, appeal status, and others. Units include yuan, number of people, calendar days, and more. These documents are maintained daily by creator operations, financial operations, and data operations roles.

## What constraints these characteristics impose on tool calling and plugins
Data sources are scattered, and most are native data from business systems. Tool calling must adapt to the interface formats of different systems. Cross-source calling permission verification rules must be configured.
The update frequency is monthly or aligned with the activity cycle. Tool calling must support scheduling based on fixed cycles or event triggers, to avoid repeatedly pulling redundant data.
The business logic of document fields is complex. Tool calling must accurately match exclusive fields of different documents such as incentive rules and settlement details, to prevent field confusion.
The payment information verification step must call external verification interfaces. It must handle field format exceptions and call rate limiting scenarios. A retry mechanism must be implemented after call failures, to avoid impacting the settlement process.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` or a specified settlement-related tool set | Matches the tool calling scenario for creator incentive settlement, automatically selects appropriate tools, and avoids calling irrelevant plugins |
| `functionCall` | `["get_settlement_detail", "check_payment_info"]` | Limits called tools to settlement detail retrieval and payment information verification, which fits the business scenario |
| Tool call timeout | `30–60 seconds` | The time required to pull settlement data across systems usually falls within this range. Excessive timeout will reduce overall workflow efficiency |
| Maximum number of items returned per call | `Top 200 items` | The volume of settlement detail data usually matches the single batch volume of monthly settlements, to avoid excessive returned data causing context overflow |
| Plugin call failure retry count | `2 times` | Addresses temporary network fluctuations or short-term system rate limiting. Too many retries will extend the settlement cycle |

## Three Common Mistakes
- Symptom: Tool call returns 514 status code. Cause: Cross-system calling permission verification is not configured, or the call frequency exceeds the rate limiting threshold of the target system.
- Symptom: Settlement detail fields returned by tool calls are empty. Cause: Document fields and tool input parameters are not accurately matched, and the field definitions of incentive rules and settlement details are confused.
- Symptom: Variables passed into the workflow cannot be correctly recognized by tool calls. Cause: The variable scope is not configured for cross-workflow calls, or the variable format does not meet the requirements of tool input parameters.

## How to Verify Correct Configuration
- Trigger a test workflow, check the tool call logs, and confirm that the returned settlement detail data matches the local test data.
- Simulate a call frequency exceeding the limit scenario, and check whether the retry mechanism and alert process are triggered.
- Pass a custom variable as the knowledge base identifier, and verify whether the tool call can correctly match the specified knowledge base.
- Open the plugin management page of FastGPT v4.17.0, and confirm that the enabled tools match the configured `toolChoice` parameter.
