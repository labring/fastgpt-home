# Code and Change Review Assistance for Creator Incentive Settlement: Citation Sources and Traceability

## What the data for this category looks like
Core data for creator incentive settlement originates from content data, advertising revenue sharing systems, financial systems, and account backends. Update frequency follows a monthly cadence or per single activity cycle. Daily associated documents include incentive rules, settlement details, appeal records, and payment lists. Fields include creator unique identifiers, revenue calculation metrics, settlement cycles, payment status, and more. Units include yuan, items, person-times, and others. The data structure is updated with each activity cycle. Settlement detail entries for a single activity are numerous, requiring association with multi-system data to complete verification and traceability.

## What constraints do these characteristics impose on the citation sources and traceability workflow
Multi-data source access requires that traceability configurations associate identification fields from content, finance, account, and other systems. This ensures every settlement record can be traced back to its original generation node. Monthly or activity-level update cycles require citations to lock document versions from the target period, preventing cross-cycle data confusion. Differences in document structures—such as incentive rules as text descriptions and settlement details as structured tables—require traceability configurations to support content extraction from varied formats. Errors are linked to settlement disputes and creator attrition, so traceability information must be non-forgeable and enable rapid location of abnormal entries.

## How to Configure the Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Settlement documents contain structured content with multiple fields, requiring sufficient token to carry complete citation and traceability information |
| `responseData` | Return only matching settlement detail and payment list fields | Focus on core business data, avoiding irrelevant content occupying context space |
| `detail` | Enable full-field traceability | Cover all business fields including creator ID, revenue amount, settlement cycle, etc., to meet code review and verification needs |
| Single search limit | Top 5 entries | Control the number of returned results, avoiding redundant information interfering with code review logic |
| Timeout threshold | 600 seconds | Cross-system queries for financial and content data take a long time, reserving sufficient response time |

## Three Common Misconfigurations
- After selecting and applying variables for the knowledge base search node, there are no selectable options in the citation variable dropdown menu. The cause is that dynamic variable items bound to the target knowledge base have not been configured in the global variable management, causing the system to fail to recognize callable knowledge base options.
- Logs cannot distinguish settlement data from different sources. The cause is that no data source identification field has been added to the traceability configuration, and source tags for content data and financial system data have not been embedded in citation information.
- The large model outputs forged citation IDs. The cause is that no real data sources such as incentive rules and settlement details have been bound, and citation markers are generated only using virtual content generated by the large model, without associating actual business documents.

## How to Confirm Successful Configuration
- Trigger the code review process, check whether the citation markers in the output results correspond to real settlement document IDs and data source identifiers.
- Test the function to dynamically specify a knowledge base, confirm that the corresponding cycle's incentive rules or settlement detail documents can be loaded after selecting a variable.
- View system logs, confirm that business data from different sources has been correctly tagged and associated with corresponding citation entries.
- Verify the large model output content, confirm that no automatically generated citation markers are present, and only the configured traceability links and field information are retained.
