# Code and Change Review Assistance for Frontend Application Development: Context and Token

This document is compatible with FastGPT v4.17.0. It targets the code and change review assistance scenario for frontend application development. Below is a detailed breakdown of context and token configuration for this scenario.

## What Data for This Category Looks Like

Data for this category comes from code repositories, interface management platforms, design draft files, and browser compatibility databases.
Daily associated documents include interface documentation, component usage instructions, joint debugging records, and version release lists.
Data updates happen daily or synced with version iterations.
Fields include lines of code, interface parameters, design draft dimensions, compatible versions, and more. There is no unified fixed format. Adjustments are made based on project tech stacks and team norms.

## Constraints for Context and Token Workflows

Code file sizes in repositories grow as projects iterate. Context recall must match the association between frontend components and interface call logic. This avoids redundant token consumption.
Interface documentation and joint debugging records update frequently. Recalled context must be the latest version. Outdated context leads to review result deviations.
Design drafts and compatibility data have large format differences. Context splitting rules must adapt to multiple data sources. This prevents token limit exceedance or mismatched recalled content.
Frontend review context must cover page state and terminal adaptation details. Context length constraints must match the total token limit for single-page code and associated resources.

## How to Configure Settings

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 8000–12000 characters | Corresponds to the `maxContext` parameter, matches the total length of core single-page frontend code and associated documentation to avoid exceeding the model context window |
| Number of Recalled Context Items per Attempt | First 3–5 items | Covers components, interfaces, and joint debugging records involved in current review changes, controls total token consumption |
| Single Reference Token Limit | 1500–2000 token | Corresponds to the `quoteMaxToken` parameter, adapts to the average length of frontend code snippets and document paragraphs, prevents truncation from exceeding single-segment content limits |
| Context Matching Threshold | 0.75–0.85 | Filters low-relevance historical joint debugging records and compatibility data, improves review accuracy |
| Context Update Frequency | Synced with version iterations | Matches frontend project version release rhythms, ensures recalled content is the latest version |

## Three Common Misconfigurations

- Setting maximum context length beyond the model's native window limit. This triggers model token limit exceeded errors or returns incomplete review content. The cause is failure to adjust parameters based on total single-page frontend code and associated documentation size, and blindly pulling full historical data.
- Failing to limit recalled context scope. Only full historical joint debugging records and compatibility data are returned. Search results become unrelated to current code changes, and cannot assist reviews. The cause is failure to configure a context matching threshold, and failure to associate the current change's code repository path and interface documentation, covering commonly asked context association configuration questions.
- Failing to set a single reference token limit. Long code snippets or design draft descriptions are truncated. Key page state implementation details are missing from reviews. The cause is failure to adapt to average frontend code snippet length, and failure to properly split context.

## How to Confirm Successful Configuration

- Check context recall logs in the FastGPT backend. Verify recalled document types and quantities match the current review's associated scope. Adjust configuration items until they match.
- Test with a question about a frontend code change. Check if returned review content includes associated interface documentation, component instructions, and joint debugging records. Confirm the context association logic is active.
- Simulate a review scenario for long code snippets. Check if returned content is fully recalled without truncation. Confirm the single reference token limit configuration is reasonable.
- Check data source update records. Confirm recalled context content is the latest version of current documents, matching the project's iteration rhythm.
