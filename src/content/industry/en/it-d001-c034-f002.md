# Code and Change Review Assistance for Office System Process Configuration: Context and Token

## What Data for This Category Looks Like
Data for this category primarily comes from enterprise OA systems, organization directories, internal policy documents, and frontline user feedback. Daily produced documents include process configuration sheets, approval node tables, form field descriptions, and change records. Data updates are triggered by process changes, with a full validation update completed at least once per month. Data fields cover approval node permissions, transfer path rules, and form validation logic. Most units are business-specific expressions such as node serial numbers, permission scopes, and execution cycles, with no standardized technical units.

## What Constraints Do These Characteristics Impose on the Context and Token Link
Process configuration data has strong business relevance. A single configuration sheet may be associated with multiple approval nodes and permission rules. The context window must cover the complete associated logic chain to avoid truncating critical transfer paths. Data update frequency fluctuates with changes; knowledge bases must be updated synchronously when processes are added or adjusted, otherwise the context will retrieve expired rule fragments. Most fields use business-specific expressions, requiring precise matching of details such as node names and permission scopes. Token consumption increases with the number of associated nodes. Some change records only retain key node adjustments; context retrieval must distinguish valid changes from invalid notes to reduce invalid token usage.

## How to Configure Settings
This configuration scheme is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context Window | 8000–12000 token | Single documents for office system process configuration typically include multiple approval nodes and associated rules, requiring coverage of the complete business logic chain |
| `maxContext` | 20% above the average token count of business documents | Adapts to the associated complexity of process configuration data, avoiding truncation of critical node permission information |
| Number of Recalled Context Entries | Top 3–5 entries | Associated rules for process configuration are mostly concentrated within 3 node groups; excessive recall increases token consumption |
| `quoteMaxToken` | 1500–2000 token | Core rule fragments of a single process configuration typically fall within this range, preventing redundant content from occupying context space |
| Automatic Segment Length | 800–1000 characters | Matches the description length of single nodes in process configuration sheets, ensuring complete logic within each segment |

## Three Common Misconfigurations
- Approval rule matching deviations occur after configuration, with outdated process nodes returned. The cause is failure to synchronously update process configuration data in the knowledge base, leading the context to retrieve expired change record fragments.
- System prompts context overflow, with per-request token limits exceeded. The cause is failure to restrict the `maxContext` window size, directly loading full process documents which causes excessive token consumption.
- Node logic breaks after segmentation, with permission descriptions truncated. The cause is setting automatic segment length using token units, while most fields in process configuration are character-based business descriptions, leading to segments truncating complete permission explanations.

## How to Confirm Proper Configuration
- Upload a single complete process configuration sheet, check whether the context retrieval results include currently active approval nodes and permission rules.
- Simulate a change review request, verify whether the returned token consumption value falls within the configured `maxContext` range.
- Compare segmented fragment content, confirm that each segment contains complete single-node or associated rule logic with no truncation.
- Upload an expired process change record, verify that retrieval results prioritize matching the latest version of configuration data.
