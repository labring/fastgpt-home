# Code and Change Review Assistance for Prototyping and Interaction Design: Citation Sources and Traceability

## What the Data for This Category Looks Like
Core users of this category include product designers, interaction designers, and front-end product teams. Daily deliverables include interactive prototypes, page flowcharts, component specifications, and review records.
Data sources primarily consist of Figma or Axure design files, internal team design systems, user feedback, and usability test records. Update frequency is typically weekly or per product version.
Core content focuses on page structure, operation paths, and component properties. Some files include visualized interaction flows and state transition descriptions. Non-standard fields may adjust based on project requirements. Most data is structured design assets, which differ significantly from plain-text requirement documents.

## What Constraints These Characteristics Place on the Citation Sources and Traceability Link
Prototype and interaction design documents rely on visual design files and real-time updated design assets. Traceability workflows must accurately link to specific page nodes, component versions, and file update times to avoid citing expired or mismatched design content.
Since documents center on operation paths and page structure, citations must retain original formatting and details. Arbitrary simplification or rewriting will lead to misalignment between R&D teams’ understanding of design intent.
Data sources are scattered across multiple files and systems. Traceability workflows must support cross-source association, covering design systems, prototype files, review records, and other asset types. This ensures complete traceability of design basis during code change reviews.
Uncertain update frequencies require traceability workflows to regularly refresh source data in the knowledge base, avoiding cached outdated design content.

## Configuration Settings
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Max Citation Token | `800–1200 token` | Core content of a single page for prototyping and interaction design typically falls within this range. This avoids truncating critical operation paths and component specifications, while controlling token consumption per request |
| Original Text Output Mode | Full Output | Directly return the original design document content stored in the knowledge base, retain original formatting and fields, to meet traceability requirements for design details during code reviews |
| Traceability Detail Display | Enabled | Display the file path, update time, and version number of the citation source, to allow reviewers to verify the timeliness and accuracy of design content |
| Number of Associated Knowledge Bases | 2–3 | Design assets for this category typically come from design systems, prototype files, and review records. Associating 2-3 corresponding knowledge bases covers complete traceability needs |
| Source Data Sync Cycle | 7-day automatic sync | Matches the regular update frequency of this category, ensuring design assets in the knowledge base remain consistent with the latest versions |

## Three Common Misconfigurations
- Phenomenon: Returned design content is simplified or rewritten, and original interaction flow descriptions are not retained. Cause: Original text output mode is not set to Full Output, and the default content compression logic is enabled, leading to loss of critical design details.
- Phenomenon: Cited prototype file versions are expired, and do not match the latest design for the current project. Cause: Automatic source data sync is not configured, cached outdated knowledge base data is used, and latest design assets are not updated in a timely manner.
- Phenomenon: Single query response times out, or returned content exceeds expected length. Cause: Max Citation Token value is not restricted, and a value exceeding the system's processing limit is set, leading to large sections of prototype content being pushed to the large language model in one go.

## How to Verify Correct Configuration
- Upload a test Axure prototype file to the corresponding knowledge base, initiate a query that includes "view the current page operation path", and check if the returned result contains complete original design content.
- View the traceability display area of the query result, confirm that detailed information such as file path, update time, and version number is displayed.
- Adjust the Max Citation Token value, initiate multiple identical queries, and verify that the length of the returned content matches the set value.
- Associate 2-3 different types of design knowledge bases, initiate a cross-source query, and confirm that design documents from different sources can be cited simultaneously.

The values provided are common starting points and should be measured against the reader's own samples.
