# Code and Change Review Assistance for Release Management and Version Acceptance: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data primarily comes from CI pipelines, change management systems, test reports, and monitoring dashboards. Daily associated documents include release plans, launch checklists, acceptance reports, and rollback plans. Core fields cover release version numbers, change item details, test pass rates, rollback trigger thresholds, and more. Data updates occur weekly or once per version release cycle. Single-update content mostly consists of new changes, test results, and monitoring metrics for the current release, with no scattered high-frequency real-time writes.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
First, data updates per version cycle. Multi-turn dialogue must limit context to documents associated with the current version to avoid mixing cross-version data.
Second, core fields include version numbers, change items, and others. Prompts must clearly specify rules for extracting corresponding fields to prevent retrieval of irrelevant historical data.
Third, unlike code review and merge management categories, this category focuses on control across the full release workflow. Dialogue must support filtering data sources by version. Additionally, since update frequency is low, full refreshes do not need to be triggered frequently, and the current version's knowledge base set can be fixed for retrieval.
Fourth, errors may result in launch failures. Dialogue must add verification steps at critical links to ensure retrieved data is accurate.

## How to set configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset current version number and rollback trigger threshold as global variables | Category data updates per version; global variables do not need to be reset for each dialogue, reducing repeated input |
| `chatId` | Bind to the unique ID of the current review session | Isolate dialogue contexts across different versions to avoid cross-version data confusion |
| Single retrieval limit | Top 6 matching results | Covers the typical number of core change items and acceptance report fields for this category, avoiding interference from redundant information |
| Context window length | 1000–1500 characters | Adapts to the average length of documents associated with a single version, retaining key review information |
| `messages` | Limit context to the most recent 2 dialogue turns and the current version knowledge base | Category data updates infrequently; retaining excessive historical dialogue is unnecessary, reducing retrieval latency |

## Three common misconfiguration issues
- Issue: Parameter error prompts appear when configuring knowledge base binding variables. Cause: Failed to follow the category rule of binding knowledge bases by version, incorrectly passing the knowledge base ID of a historical version, causing the system to fail to match the current version's data source.
- Issue: Retrieval response time increases significantly for subsequent questions in the same dialogue window. Cause: Failed to limit the `messages` context window length, with excessive accumulated historical dialogue leading to an overly large retrieval scope and increased knowledge base matching time.
- Issue: Global default variables cannot be fixed for use, with variables reset after each question. Cause: Global variables were not configured as preset values for the `variables` parameter, and were instead passed temporarily during each dialogue, causing variables to expire after the session ends.

## How to confirm configurations are correct
- Initiate a question about change items for the current version, check that retrieval results only include documents such as the current version's release plan and launch checklist, with no historical version content.
- Launch 3 consecutive related questions, observe that response times do not fluctuate significantly, and no delays exceeding 60 seconds occur.
- Save the session, re-enter it, and check that preset global variables remain in the variable list of the dialogue input box.
- Trigger a rollback condition confirmation question, confirm that the system correctly extracts the preset rollback trigger threshold field, with no missing or incorrect matches.
