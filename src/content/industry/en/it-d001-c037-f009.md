# Code and Change Review Assistance for Release Management and Version Acceptance: Tool Calling and Plugins

## What data this category includes
Data for this category typically originates from CI pipelines, change management systems, test reports, and monitoring dashboards. Update frequency follows weekly intervals or each version release cycle. Associated daily documents include release plans, launch checklists, acceptance reports, and rollback plans. Document fields cover release item names, change IDs, test pass rates, monitoring metric thresholds, and similar details. No uniform fixed units apply, and fields are updated dynamically alongside version release rhythms. This data centers on end-to-end control from build to production release, and differs from code quality validation in code merge review workflows.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources are scattered and linked to multiple systems. Tool calling must adapt to multi-source data pull permissions, and cross-system data sync trigger rules must be configured. Update frequency fluctuates with version cycles. Tool calling must support triggering aligned with version rhythms to adapt to non-fixed update schedules. Daily document fields have no uniform format. Tool calling must support custom field mapping rules to adapt to each team’s unique release document structure. Failures directly impact production environments. Tool calling must include failure rollback and alert trigger logic to enable rapid response during exceptions. Launch window coordination relies on cross-team information. Tool calling must support permission validation and multi-node data aggregation.

## How to configure the setup
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling trigger timing | Trigger at version release nodes | Matches the data update pattern aligned with version cycles, avoids invalid calls |
| `toolChoice` | auto | Adapts to scenarios where multiple tools are called on demand, supports automatic selection of tools matching release management workflows |
| `functionCall` | Only bind release management and change review tools | Limits call scope, prevents unrelated tools from interfering with release processes |
| Field mapping rules | Custom map release plan and launch checklist fields | Adapts to the lack of uniform formats for documents in this category |
| Failure retry count | 3 times | Covers occasional call failures in CI pipelines, adjust based on actual testing |
| Alert trigger threshold | Trigger after 600 seconds of call timeout | Matches time requirements for responding to production environment exceptions |
| Single data pull limit | Top 100 entries | Adapts to data volume returned by CI pipelines in single calls, prevents system overload |

## Three common misconfigurations
- Symptom: Cross-domain related errors are returned when calling third-party APIs, with CORS keywords included in the status code. Cause: The cross-domain access whitelist for the FastGPT platform has not been configured, and the calling domain name of the target API has not been allowed.
- Symptom: Advanced orchestration tool calls fail to automatically match target tools, with a prompt indicating no available execution tools. Cause: The `toolChoice` parameter has not been set to auto mode, or the call permissions for the corresponding tools have not been bound.
- Symptom: Release document data associated with workflow calls is empty, and retrieval or validation cannot be completed. Cause: Custom field mapping rules have not been configured, causing fields from CI pipelines and change management systems to fail to transfer correctly to the tool calling workflow.

## How to verify the configuration is complete
- A simulated version release workflow is initiated, and tool call logs are checked to confirm correct pulling of corresponding data from CI pipelines and change management systems.
- The advanced orchestration tool configuration page is reviewed to confirm the `toolChoice` and `functionCall` parameters are set as required.
- A call failure scenario is simulated, and preset alert and rollback logic is checked for activation.
- Cross-domain configuration is verified by directly calling the target API via a browser, with the return result confirmed as normal.

The values provided here are common starting points, and should be measured against the reader’s own samples.
