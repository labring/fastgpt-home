# Code and Change Review Assistance for Change Management and Release Windows: Source Citation and Traceability

## What the data for this category looks like
This category’s data originates from change management systems, CI pipelines, business monitoring data, and enterprise business calendars. Daily generated documents include change request forms, risk assessment reports, launch window plans, and rollback plan documents. Data updates are triggered by a single change or synced weekly. Fields include change unique identifiers, window start and end times, associated code commit hashes, risk rating levels, approval node records, and more. Most fields are character-based identifiers and enumeration values, with no additional custom statistical fields.

## Constraints imposed by these characteristics on the "source citation and traceability" workflow
Data sources are scattered and linked to multiple systems. Traceability must associate both code commit hashes and approval records from the change management system. This avoids record bias from a single data source.
Update frequency triggers per individual change. Traceability context must bind the time window of the corresponding change. This prevents mixing historical data across cycles.
Daily document structures are fixed. Precise matching is required for specific document types such as change request forms and risk assessment reports. Generalized retrieval of non-specified category documents is not supported.
Fields use enumeration properties. Traceability results must strictly match preset enumeration values like risk ratings and approval nodes. Non-standard custom fields are not compatible.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Matches the total length of code and documents associated with a single change, to avoid truncating critical traceability information |
| `responseData` | Return only change ID, code hash, and approval node records | Aligns with the fixed document structure of this category, to reduce interference from irrelevant data |
| `detail` | Display full source document snippets | Meets the detail verification needs of risk assessment and approval coordination processes |
| Maximum Context | 24 hours to 7 days | Adapts to the update frequency of weekly or single changes, to avoid mixing in cross-cycle data |
| Single Search Limit | Top 3 associated records | Matches the scattered but limited associated items of data sources in this category, to avoid redundant results |
| Reranking | Sort by change timestamp | Follows the time sequence of business processes, to quickly locate the latest change information |

## Three Common Configuration Errors
- Phenomenon: Reference file links automatically append to the end of responses, and unnecessary traceability information cannot be hidden. Cause: The `responseData` parameter is not adjusted to filter redundant reference metadata, and the default appended link logic remains active.
- Phenomenon: Historical data not associated with the current change appears in search results, and some associated fields are empty. Cause: The change time window is not bound as a context filter condition, leading to recall of cross-cycle data.
- Phenomenon: Code commits and change request forms cannot be correctly associated, and traceability results lack associated hash values. Cause: The `detail` parameter is not configured to enable full document snippet display, and only summary information is recalled, resulting in lost associated fields.

## How to Verify Correct Configuration
- Submit a simulated change request, search for associated code commits and approval records, and confirm the returned results only include the document fields specified for this category.
- Adjust the `quoteMaxToken` parameter, upload the full set of documents for the corresponding change, and verify the search results do not have truncated content.
- Trigger a change review query, and confirm the returned results do not include historical data beyond the current change cycle.
- Check the response content, and confirm the display mode of reference links can be adjusted as needed to meet business scenario requirements.

The values provided are common starting points and should be measured against the reader's own samples.
