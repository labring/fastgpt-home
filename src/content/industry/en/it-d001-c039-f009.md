# Code and Change Review Assistance for Backend Service Development: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category primarily comes from code repositories, API gateway logs, databases, and configuration centers. Updates occur daily or when a version is released. Documents generated daily include interface design documents, database change sheets, code review records, and release notes.
Interface design documents contain fields such as interface paths, request parameters, and response formats. Database change sheets record schema modification content. Code review records include review comments and change markers. Most data fields focus on backend-specific content, including interface contracts, transaction boundaries, and exception log IDs.

## Constraints on Tool Calling and Plugins Workflow
Data sources for this category are scattered, and update schedules vary. Tool calling must adapt to access permissions and parsing formats for multiple data types, including code repositories and API gateway logs. Daily document structures differ widely. Plugins must support field extraction from different file types, such as interface design documents and database change sheets.
Unlike front-end application development, backend service development prioritizes business rules, data consistency, and service stability. Therefore, tool calling parameters must match backend-specific fields like interface contracts and transaction boundaries to avoid conflicts between calling logic and core backend service constraints. Frequent updates also require tool calling results to stay synchronized with the latest data, preventing deviations in review basis.

## Configuration Settings
The following configuration rules apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to parallel multi-tool calling scenarios in backend service development, automatically selecting the appropriate tool based on task type |
| `functionCall` | No more than 3 functions per single call | Avoids exceeding backend service interface concurrency limits in a single request, reducing call failure risk |
| Tool call timeout threshold | 300 seconds | Matches general backend service interface timeout standards, preventing tasks from being forcibly terminated due to excessive waiting time |
| Data source scope | Code commits and change records from the past 7 days | Focuses on content within the current review cycle, aligning with code review timeliness requirements |
| Context length | 8000 token | Adapts to long document parsing needs in backend service development, such as complete interface design and change description documents |

## Three Common Misconfigurations
- A custom code call throws an `AggregateError Code:ETIMEDOUT`. This occurs because the timeout threshold matching the backend service is not configured, causing external dependency call wait times to exceed system limits.
- After adding a MySQL database tool call, a 400 status code is returned with no response body. This occurs because database connection permission and address parameters are not correctly configured, preventing the tool from establishing a valid connection.
- When configuring `functionCall`, the number of called functions exceeds the limit, causing interface contract verification to fail. This occurs because the per-call function quantity configuration rules are not followed.

## How to Verify Correct Configuration
- Initiate a simulated tool call request for code change review, and check whether the returned result includes expected interface contract verification content.
- View tool call logs to confirm that the data source scope only includes backend service-related data within the specified period.
- Test the custom code call timeout scenario, and verify whether the error-triggering duration complies with preset threshold rules.
- Check the `functionCall` configuration quantity, and confirm that the number of functions per single call does not exceed the preset limit.

The values provided are common starting points and should be measured against the reader's own samples.
