# Code and Change Review Assistance for Pre-Sales Technical Proposals: Context and Token

This document is written for FastGPT v4.17.0.

## What the Data for This Category Looks Like
Core data for this category comes from customer interview records, public tender documents, vendor product materials, and historical project proposals. Daily output documents include technical proposals, customer requirement survey forms, quotation lists, and demo scripts. Each document’s core modules include technical route descriptions, implementation boundary definitions, detailed quotation items, and demo process designs.
Data updates follow individual pre-sales project cycles, typically updated per project or weekly. Document structures and fields share commonalities across different projects, but core content must align with the specific current customer requirements.

## Context and Token Constraints
Data sources for this category are scattered and contain duplicate content. Precise context filtering is required to avoid redundant information consuming token quotas.
The core content of a single pre-sales document typically ranges from thousands to tens of thousands of characters. Excessively long context will exceed token limits, leading to truncation of critical information and reduced review accuracy.
Data updates are adjusted on demand within individual project cycles. Cross-project context does not need to be retained long-term. Session-level context management can reduce token resource waste.
Core document fields focus on technical routes and implementation boundaries. Context recall must prioritize matching these fields to avoid irrelevant content interfering with review logic.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | The core content of a single pre-sales technical proposal typically ranges from 6000–10000 characters. This setting aligns with token limits to avoid truncation of critical review information |
| `quoteMaxToken` | `3000–5000 token` | Individual referenced historical proposal fragments should not be overly long, to avoid context overload that reduces review efficiency |
| Single recall limit | Top 6 entries | Reference materials for pre-sales proposals typically do not exceed 6 core historical proposals and vendor documents. Excessive recall will consume excessive token resources |
| Context refresh trigger rule | Triggered on demand changes | Pre-sales proposals are only updated when customer requirements adjust, so frequent context refreshes are unnecessary |
| Context retention duration | 7 days | Individual pre-sales project cycles typically do not exceed 7 days. Automatic cleanup will release token resources once the period expires |
| Global token quota adjustment | Dynamically allocated via function calls | Meets the needs of flexible token quota adjustment for the open-source edition, matching resource usage scales of different pre-sales projects |

## Three Common Misconfigurations
- Symptom: Service restarts frequently after offline intranet deployment, with logs showing `failed`. Cause: Local token allocation for `maxContext` was not adjusted for the offline environment. The default token threshold exceeds the memory quota of the offline container.
- Symptom: After configuring a custom OpenAPI token, knowledge base search and question optimization still incur charges. Cause: Token calls associated with context were not bound to the custom token quota. The default platform public call quota is used instead.
- Symptom: Session context information cannot be cleared. Cause: No trigger conditions for automatic context cleanup were set, leading to ongoing token resource occupation by session cache without release.

## How to Verify Correct Configuration
- Upload a single complete pre-sales technical proposal document, confirm that the returned code and change review results do not truncate content related to core technical routes or implementation boundaries, to verify that the `maxContext` configuration is active.
- Import 3 or more historical project proposals of the same type, confirm that the length of recalled reference fragments aligns with the `quoteMaxToken` setting, to verify that the reference token limit is active.
- Modify core fields in the customer requirement survey form, confirm that the context updates per the configured trigger rule, to verify that the context refresh configuration is active.
- Wait for the configured context retention duration to elapse, confirm that session cache is automatically released, to verify that the context cleanup rule is active.
