# Code and Change Review Assistance for Pre-Sales Technical Proposals: Citation Sources and Traceability

## What Data for This Category Looks Like
Typical data for this category consists of pre-sales technical proposal-related documents, including four core types: technical proposal documents, customer requirement surveys, quotation lists, and demo scripts. Data sources include customer interview records, public bidding documents, vendor product materials, and historical project proposal libraries. Update frequency is typically per order or weekly, adjusted based on customer needs or project progress. Document structures generally include fields such as technical route descriptions, implementation boundary definitions, and quotation configuration items. Citations within a single document often point to specific vendor parameters, customer requirement items, or implementation details from historical projects.

## Constraints Imposed by These Characteristics on the Citation Sources and Traceability Link
Data sources for this category are scattered and updated frequently. This requires the traceability link to accurately match the latest version of the original data source, to avoid using outdated content. The modular structure of documents requires traceability results to correspond to specific sections of the proposal, ensuring consistency between cited content and contextual logic. A single document contains a large number of citations, so the redundancy of recall results must be controlled to avoid overly verbose proposal content. At the same time, the deliverable of a pre-sales technical proposal directly affects bid scoring, and the accuracy of the traceability link is directly related to project outcomes. Strict assurance of citation source traceability is required.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Citation Token Count | `800–1200` | Matches the length limit for single-paragraph citations in pre-sales technical proposals to avoid truncating critical content |
| Response Data Format | Include source field | Requires structured data containing the original citation source to adapt to the traceability needs of proposal documents |
| Detail Output Level | Full Mode | Retains complete details of cited fragments to meet the accuracy requirements for citations in technical proposals |
| Source Matching Threshold | `0.85–0.90` | Calibrated based on actual testing | Filters low-correlation source fragments to avoid invalid citations in proposals |
| Single Recall Limit | Top 6 entries | Matches the citation needs of single sections in pre-sales proposals to avoid excessive redundant content |
| Call Timeout | `600 seconds` | Adapts to the time consumption requirements of multi-data-source recall for pre-sales proposals to avoid call interruptions |

## Three Common Errors
- Phenomenon: Generated pre-sales proposals do not display citation source annotations, or the citation field is empty. Cause: The response data format is not configured to include the source field, so the system does not return the raw data required for traceability.
- Phenomenon: Generated citation fragments exceed the typesetting requirements of the proposal document, or are truncated. Cause: The maximum citation token count is not adjusted, resulting in returned fragments that are too long or too short.
- Phenomenon: FastGPT service fails to start, and the traceability function cannot be enabled normally. Cause: The required FastGPT server environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, format example: http://aiproxy:3000, do not append paths such as /v1 or /chat/completions, non-single-model service address) or `AIPROXY_API_TOKEN` (AI Proxy administrator Token, must match the AI Proxy server configuration and cannot be empty, cannot be used for application API call authentication or replace model vendor keys) are not configured, or the parameter format does not meet requirements, which will trigger startup verification failure.

## How to Verify Correct Configuration
- Check the server startup logs for FastGPT v4.17.0 or later to confirm that there are no errors indicating missing or incorrectly formatted required `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` environment variables.
- Generate a test pre-sales technical proposal and check whether the generated result includes clear citation source annotations and corresponding fragments.
- Adjust the value of the source matching threshold to verify whether the relevance of the generated citation fragments meets expectations.
- Compare the generated citation fragments with the content of the original data source to confirm that the matching degree meets the set requirements.

The values given are common starting points and should be measured against the reader's own samples.
