# Code and Change Review Assistance for Security Incident Response: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data is sourced from SIEM, EDR, firewall logs, and host images. Updates occur in real time or per triggered event. Documents used and produced daily include incident response reports, forensics records, disposal plans, and notification materials. Data fields include attack source identifiers, disposal timestamps, evidence file hashes, and notification numbers. There are no uniform fixed units; values adjust based on document type and usage scenario.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
This category of data updates in real time or per event. Multi-turn dialogue contexts must sync the latest log fragments. Prompts must explicitly limit calls to data sources associated with the current event, to avoid referencing expired information. Daily document types vary. Prompts must distinguish field formats for different documents such as incident response reports and forensics records, and guide models to organize results per corresponding structures. Attack path reconstruction and evidence chain organization are core time-intensive steps. Multi-turn dialogue must support segmented follow-up questions. It must also limit the number of data entries returned per single dialogue, to prevent information overload that disrupts disposal efficiency. Additionally, error consequences directly relate to business security. Prompts must have strict scope configurations, to avoid generating content beyond disposal authority.

## How to set configurations
All configurations below are explained based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the single-section content length of incident response reports and forensics records, avoids breaking critical information within chunks |
| Chunk Overlap Length | 100–200 characters | Ensures cross-chunk attack path and log association information is not lost, connects dispersed forensics fragments |
| Single Recall Limit | Top 6 entries | Restricts the number of log entries returned per single request, prevents information overload that disrupts incident response disposal efficiency |
| Context Retention Duration | 3600 seconds | Matches the average disposal cycle of a single security incident, retains complete multi-turn dialogue context |
| Session Binding Parameter | `chatId` | Fixes the dialogue session, avoids context loss during multi-turn dialogue, accurately associates all data for the current event |
| Variable Configuration | `variables` bound to event ID | Accurately filters SIEM and EDR logs associated with the current event, avoids cross-event data interfering with analysis results |

## Three common misconfigurations
- Preset input guidance questions do not display in the dialogue interface. This occurs if the application's global input guidance switch is not enabled, or the configured thesaurus is not bound to the current dialogue scenario.
- Dialogue cannot repeat the contents of an uploaded XLSX file. This occurs if the corresponding file parsing plugin is not configured, or table field information from the XLSX file was not correctly extracted during knowledge base import.
- Context loss or abnormal session switching occurs during multi-turn dialogue. This occurs if `chatId` is not correctly bound to fix the dialogue session, or the context retention duration is set too short, preventing new questions from associating with prior dialogue content.

## How to verify correct configuration
- Upload a single incident response report document, submit a query to extract the attack source IP, and check if the returned result includes the corresponding field information from the document.
- Enable the input guidance switch, check if the dialogue interface displays preset question options, and confirm the thesaurus configuration is active.
- Submit three consecutive follow-up questions asking for attack path details, check if the dialogue interface retains context information from prior questions.
- Bind the event ID variable, submit a query to filter logs for a specified event, and check if the returned result only includes data related to the target event.

The values provided are common starting points, and should be evaluated against the reader's own samples.
