# Code and Change Review Assistance for Security Incident Emergency Response: Tool Calling and Plugins

## What data looks like for this category
Data for this category comes from SIEM, EDR, firewall logs, and host images. Updates occur in real time or are triggered per incident. Daily produced documents include emergency response reports, forensic records, disposal plans, and notification materials. Data fields include incident unique identifiers, attack source addresses, disposal execution times, evidence chain hash values, and other relevant fields. Only structured records from the original collection and disposal processes are retained. No additional aggregated statistical fields are included.

## Constraints for tool calling and plugins workflows
Data updates in real time, and single-incident volume grows as the disposal process progresses. This requires tool calling to support dynamic triggering and incremental data pulling. Documents must match fixed formats for forensics and reports, so plugins must support structured output transcription. Most data sources are security device logs, so tool calling must adapt to API authentication rules of different devices. Errors during the disposal phase can cause severe consequences. Tool calling must include execution status feedback and interruption mechanisms to prevent misoperations from expanding impact scope.

## How to set configurations
These configurations are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or specified tool name | Adapts to scenarios where SIEM/EDR tools are called on demand during emergency response, automatically selecting matching tools based on incident type |
| Tool execution timeout | 300 seconds | Matches the real-time update cycle of security logs, prevents excessive tool waiting from occupying system resources |
| Plugin execution retry count | 2 times | Addresses temporary API jitter from security devices, prevents repeated execution from causing disposal conflicts |
| `functionCall` | Enable structured output | Ensures tool return results comply with the format requirements of emergency response reports, facilitating automatic organization of evidence chains |
| Context window limit | 8000 token | Adapts to the average length of single-incident forensic records, prevents context overflow from interrupting tool calls |

## Three common misconfigurations
- Tool execution is suddenly interrupted with a `504 Gateway Timeout` status code. This occurs because no reasonable timeout period was configured, causing tool execution to exceed the preset threshold and be forcefully terminated.
- Sending a termination command to an actively running MCP server-side tool results in no response. This happens because the plugin does not implement interrupt signal listening logic, so it cannot receive or respond to termination instructions.
- Calling a local application plugin returns no output content. This is because the plugin’s execution permissions and target application path were not configured, preventing the application from starting normally or preventing output from being returned to the workflow.

## How to verify correct configuration
- Manually trigger a tool call, check if the returned result matches the preset structured format, and verify that the `functionCall` and output format verification configurations are active.
- Simulate a tool execution timeout scenario, confirm that the tool automatically terminates and returns a timeout prompt after 300 seconds, and verify that the timeout configuration is correct.
- Send a termination instruction to an actively running tool, confirm that the tool process stops and returns a termination status, and verify that the interruption mechanism configuration is active.
- Import the maximum single-incident volume of forensic records, confirm that no context overflow error occurs during tool calls, and verify that the context window limit configuration is reasonable.

The values given here are common starting points and should be measured against the reader's own samples.
