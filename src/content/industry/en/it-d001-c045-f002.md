# Code and Change Review Assistance for Security Training and Phishing Drills: Context and Token

## What Data for This Category Looks Like
Daily documents for this category include training slides, drill plans, phishing email templates, and drill result reports. Data is sourced from employee directories, email gateways, training platforms, and click statistics systems. Update frequency is typically quarterly or annually. Fields cover drill group identifiers, email sending records, click markers, training completion status, and other relevant fields. Document structures vary significantly. Training slides primarily use chapter-based content. Drill reports include statistical fields and concluding text.

## Constraints on Context and Token Workflows
Data sources for this category are scattered. Integrating multi-source information for review assistance increases context token consumption.
Update frequency is low. Frequent context cache refreshes are not needed. Token quota validity periods can be adjusted to match this pattern.
Document structures vary widely. Token proportions differ across document types. Context priority must be differentiated to avoid overflow.
The most time-consuming review steps use multiple data types. Context must cover associated information for group filtering, template design, and review results. Total token count for associated data must be controlled appropriately.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Covers total token count of training slides, drill plans, and historical review data required for a single round of review |
| `quoteMaxToken` | `2000–3000 token` | Limits token proportion of referenced phishing email templates and drill result reports to avoid context overflow |
| Context recall count | Top 5 associated data sets | Matches associated data volume for the most time-consuming group filtering and template design steps |
| Context cache validity period | 90 days | Matches quarterly or annual update frequency of category data |
| Single document chunk length | 1200–1500 characters | Matches single-paragraph content length of training slides and drill plans |

## Three Common Configuration Errors
- Observation: A 422 error is returned during calls, with the message “Messages token length must”. Cause: `quoteMaxToken` is not restricted. Referenced phishing email templates and drill report tokens exceed the single-round context limit allowed by the model.
- Observation: Online models show excessive first-token latency. Offline models show abnormal total runtime. Cause: A reasonable `maxContext` value is not configured. Excessive context data causes abnormal model token loading latency. Differences in latency statistics logic across models amplify this issue.
- Observation: Global variables cannot persist across contexts in multi-turn sessions. Cause: The context cache validity period is not set, or global variables are not included in the scope of `maxContext`. Variables are lost after session interruption.

## How to Verify Proper Configuration
- View model call logs in FastGPT v4.17.0. Confirm total referenced document token count does not exceed the configured `maxContext` value.
- Simulate multi-turn code and change review sessions. Check that contexts include the latest drill plans and training slide content.
- Trigger a phishing email template reference check. Confirm single referenced document token count does not exceed the configured `quoteMaxToken` value.
- Test session interruption and restart. Check that global variables are retained within the current context scope.

The values provided are common starting points and should be measured against the reader's own samples.
