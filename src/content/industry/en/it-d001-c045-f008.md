# Code and Change Review Assistance for Security Training and Phishing Drills: Workflow Orchestration

## What data for this category looks like
This category of data primarily comes from employee contact directories, enterprise email gateways, internal training platforms, and phishing drill click statistics systems. Daily produced documents include standardized training courseware, customized phishing drill plans, bulk email templates, and drill result review reports. Data update frequency is usually quarterly or annually. Core fields include drill crowd identifiers, email send times, user click behavior tags, rectification completion status, and more. There is no fixed unified unit standard, and it adjusts based on specific drill scenarios.

## Constraints These Characteristics Impose on Workflow Orchestration
The data sources for this category are scattered. Rules for pulling employee contact directory, email gateway data, and click statistics results across nodes must be configured in the workflow to avoid errors from manual splicing. There are diverse daily document types, requiring the workflow to support dynamic invocation of different training courseware, drill plan, and email template nodes. Data update frequency is low but single processing scale may be large, so reasonable batch processing thresholds must be set to prevent node timeouts. Fields have no unified standard, so a field mapping link must be configured to adapt to the output formats of different drill scenarios.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind data sources such as employee contact directory ID and email gateway address | Adapt to cross-system data pulling requirements for this category |
| Node timeout duration | 600–900 seconds | Address time consumption fluctuations when pulling statistics data across systems |
| `nodeId` | Configure unique identifiers for each template node | Facilitate invocation and debugging between workflows |
| Dynamic template invocation rules | Trigger corresponding template nodes based on drill scenario type | Adapt to diverse daily document types |
| Field mapping rules | Preset field correspondence based on drill scenario | Resolve the lack of unified field standards |
| Batch processing limit | First 200 entries | Control the crowd size processed by a single workflow to avoid timeouts |

## Three Common Misconfiguration Scenarios
- Workflow runs timeout or returns empty results: The cause is failure to correctly configure the cross-system data sources bound by `variables`, resulting in nodes being unable to pull necessary employee or statistics data.
- Global variable display items are missing or abnormal: The cause is failure to correctly configure the AIPROXY_API_ENDPOINT and AIPROXY_API_TOKEN environment variables for the App/Admin server.
- Authentication failure prompt Key is error: The cause is confusion between the application API Key and the AI Proxy administrator Token, with model vendor keys being mistakenly used for authentication.

## How to Verify Correct Configuration
- Check that the AIPROXY_API_ENDPOINT and AIPROXY_API_TOKEN environment variables for the App/Admin server have been correctly configured, and no path suffixes such as /v1 or /chat/completions are appended.
- Trigger a test workflow to verify that preset employee contact directory data and email template content can be successfully pulled.
- View workflow operation logs to confirm that data transfer and field mapping between nodes comply with preset rules.
- Use the correct application API Key for authentication when calling the workflow API; do not use the AI Proxy administrator Token.
