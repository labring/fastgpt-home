# Code and Change Review Assistance for Security Baseline Checks: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category originates from server configurations, middleware configurations, security device policies, and output results from baseline tools. Update frequency is monthly or quarterly. Daily associated documents include baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. Document fields include configuration item number, compliance status, verification time, rectification responsible person, exception approval number, and others. Some configuration items require matching organizational security baseline values based on device model.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Dispersed data sources linked to multiple system configurations require multi-turn dialogue to support cross-data-source summary queries for configuration items. Prompts must explicitly limit calls to only baseline-related configuration verification data. Low update frequency means dialogue context must retain historical verification records and exception approval information to avoid repeated questions about already confirmed exception reasons. Most document fields are structured configuration items and status identifiers, so prompts must clearly specify extraction field formats to prevent returning unstructured irrelevant content. Additionally, the dialogue flow must distinguish between compliant configurations, non-compliant configurations, and exception approval items to keep each dialogue turn focused on content to confirm in the current verification stage.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Fixed to the current baseline verification session | Ensures multi-turn dialogue links to the context of the same verification task, avoiding session confusion |
| `messages` | Retain the most recent 20 dialogue turns | Covers the full workflow of a single baseline verification while controlling context resource usage |
| `variables` | Inject the baseline template ID and device list for the current verification project | Quickly loads baseline requirements for corresponding configuration items, reducing repeated input |
| Maximum Context | Calibrated via actual testing, no more than 8000 tokens | Adapts to bulk content loading from baseline verification documents, avoiding exceeding model context limits |
| Question Optimization | Enabled | Automatically organizes user configuration verification queries to focus on core compliance judgment content |
| Single Dialogue Limit | Top 10 configuration items | Avoids excessive information volume in a single dialogue, reducing processing latency |

## Three Common Misconfigurations
- The `variables` option in the dialogue configuration interface only displays two preset values, and custom injection of baseline template IDs is not supported. This occurs because the advanced variable configuration feature is not enabled in FastGPT v4.17.0, resulting in a simplified available variable list.
- The configuration item status returned by the dialogue does not match actual verification records, and non-baseline-related system configurations are included. This occurs because the prompt does not explicitly limit calls to only exclusive data sources such as baseline checklists and configuration verification records, causing the model to read irrelevant data.
- Response timeouts occur after more than 20 turns of multi-turn dialogue. This occurs because the number of dialogue turns retained by the `messages` parameter is not restricted, resulting in overly long context that exceeds the model's processing limits.

## How to Verify Successful Configuration
- Initiate a single-turn query for baseline configuration items, and confirm the returned content only includes configuration item information for the current verification project.
- Initiate consecutive multi-turn dialogues, and confirm historical questions and answers are retained in the context without content loss.
- Check that custom variables can be properly injected into the dialogue, and confirm parameters such as the baseline template ID and device list are correctly loaded.
- Test scenarios where a large number of configuration items are loaded in a single turn, and confirm the response does not experience abnormal interruptions.
