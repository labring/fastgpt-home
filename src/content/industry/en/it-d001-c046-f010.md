# Code and Change Review Assistance for Security Baseline Checks: Citation Sources and Traceability

## What this category of data consists of
This category of data originates from server configurations, middleware configurations, security device policies, and baseline tool output results. It updates monthly or quarterly. Daily generated documents include baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. Document fields cover configuration item numbers, current configuration values, compliance judgment results, exception reasons, and approval information. All content focuses on configuration compliance. There are no additional quantitative statistical fields. All data is structured or semi-structured configuration-related content.

## Constraints on citation sources and traceability
This category of data has scattered sources covering multiple types of system configurations. Citation traceability requires precise association with unique identifiers from different data sources such as servers, middleware, and security devices. This avoids confusing configuration items with identical names. The update frequency is monthly or quarterly. The knowledge base sync cycle must match this rhythm to ensure cited content aligns with the latest configurations. Structured baseline checklists and approval forms require binding configuration item number fields during traceability to quickly locate original verification records. Configuration verification and exception confirmation take significant time. The traceability chain must fully retain full lifecycle change traces for configuration items to support audit review requirements.

## Configuration guidelines
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Security baseline data mostly consists of structured configuration descriptions. This range fully covers the verification records and associated explanations for a single configuration item, avoiding truncation of critical compliance information |
| `responseData` | Return the top 3 matching results | The number of security baseline configuration items is relatively fixed. A small number of matching results reduces information filtering costs during reviews, focusing on core compliance basis |
| `detail` | Enable full field display | Traceability requires viewing complete information such as configuration item numbers, current configuration values, and compliance judgment results. Full field display presents all necessary content directly in citations |
| Knowledge base sync cycle | Once per month | The update frequency of this category of data is monthly or quarterly. Monthly sync covers regular update needs, ensuring cited content matches the latest configurations |
| Data source association rule | Bind unique configuration item numbers | Data sources for this category are scattered. Binding unique numbers avoids confusion between configuration items with the same name across different systems, improving traceability accuracy |
| Exception approval form association | Enable approval form field citation | Compliance reviews require confirmation of approval basis for exception situations. Citing this field quickly traces the approval process for exception configurations |

## Three common misconfigurations
- Symptom: After submitting a relevant query, cited traceability content does not include complete verification fields for configuration items. Cause: The `detail` full field display configuration is not enabled. This causes key compliance judgment or configuration value information to be missing from cited data.
- Symptom: Non-matching configuration records are returned even when the query is unrelated to configuration items. Cause: No reasonable matching filtering rules are set. This leads to low-correlation results being returned, which does not meet actual review needs.
- Symptom: Cited configuration records lack exception approval form association information. Cause: The exception approval form field citation configuration is not enabled. This makes it impossible to trace approval basis for exception configurations, affecting audit review workflows.

## How to confirm successful configuration
- Review cited traceability content to confirm inclusion of core fields such as configuration item numbers and current configuration values. This verifies that the `detail` configuration is active.
- Submit a query related to a known matching configuration item. Check returned result count against review needs. This verifies that the `responseData` configuration is properly set.
- View knowledge base sync logs to confirm sync cycle matches data update rhythm. This verifies that sync configurations are correct.
- Test configuration items with identical names from different system sources. Confirm traceability results associate with correct unique numbers. This verifies that the data source association rule is active.
