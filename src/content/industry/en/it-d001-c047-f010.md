# Code and Change Review Assistance for Security Vulnerability Disclosure Handling: Citation Sources and Traceability

## What this category of data looks like
This category of data originates from private vulnerability reports, code repositories, CVE numbering authorities, and official release channels. Daily documentation includes security advisories, vulnerability reports, repair patches, and CVE application materials. Each entry includes fields such as CVE number, vulnerability impact scope, patch submission records, and disclosure coordination timeline. Updates are triggered by individual vulnerability events, with no fixed cycle. Most data is structured text, while some patch code snippets are unstructured content that require association with corresponding repository submission records to achieve full traceability.

## Constraints on the citation sources and traceability link
Private vulnerability reports are only visible to authorized project members. This requires the citation and traceability link to support fine-grained permission verification to prevent sensitive information leaks. Two-way association must be established between patch snippets in code repositories and structured documents, to ensure that the corresponding relationship between submission records and vulnerability reports can be quickly located during traceability. CVE numbers must be integrated with official authority data sources to ensure referenced vulnerability identifiers are compliant and valid. The event-driven update rhythm requires configuration that supports loading the latest data on demand; fixed scheduled synchronization cannot adapt to event-driven update requirements. Data sources are dispersed, so multi-source recall capability must be configured to cover all content from private reports, repository code, and official release channels.

## Configuration guidelines
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the typical text length of vulnerability reports and patch code, avoiding exceeding context window limits |
| `responseData` | Structured text + unstructured code snippets | Supports recall of both structured content such as security advisories and CVE materials, and unstructured snippets of patch code |
| `detail` | Enabled | Recalls supplementary information such as associated CVE numbers and repository submission records to improve traceability links |
| Multi-source recall limit | Top 5 entries | Controls the number of data sources recalled in a single operation to avoid information overload during review |
| Timeout threshold | 600 seconds | Adapts to the batch processing rhythm of vulnerability events, avoiding interruption of the review process due to prolonged data loading |

## Three common misconfiguration issues
- Symptom: After setting `responseData` to plain text format, patch code snippets cannot be properly cited, and only structured security document content is displayed. Cause: The recall logic does not support unstructured code snippets, and only supports parsing and association for structured text.
- Symptom: After enabling permission verification, citation results for private vulnerability reports are empty. Cause: Access permissions for the corresponding project are not configured for the current workflow, so content from private data sources cannot be pulled.
- Symptom: Recalled vulnerability information does not match the currently reviewed code changes, and the number of results exceeds expectations. Cause: A reasonable multi-source recall limit is not set, leading to batch recall of redundant data sources.

## How to confirm the configuration is valid
- Submit a test vulnerability report, and check whether the citation and traceability module in the code change review interface recalls the patch submission records and associated CVE number information of the corresponding code repository.
- Check the value of the `quoteMaxToken` configuration item to confirm that the current context window can accommodate all recalled text content.
- Verify the status of the permission verification switch to confirm that unauthorized users cannot view cited content from private vulnerability reports.
- Check the FastGPT v4.17.0 version identifier to confirm that the current environment supports the activation logic for all configuration items.
