# Code and Change Review Assistance for Security Monitoring and SOC Duty: Tool Calling and Plugins

## What Data for This Category Looks Like
This category’s data originates from SIEM, EDR, NDR, and third-party threat intelligence sources, with updates delivered in real time or daily. Documents routinely created and used include alert disposal sheets, duty logs, threat intelligence briefings, and daily/weekly reports. Data fields include alert unique identifier, disposal status, associated code change number, threat level, and disposal duration, among others. All fields are fixed for this business scenario.

## Constraints Imposed by These Characteristics on the "Tool Calling and Plugins" Workflow
Data comes from multiple sources with varying update rhythms. Tool calling must support both real-time API calls and scheduled batch pulling to avoid single-interface timeouts or data lag. Documents such as alert disposal sheets have fixed field structures. Plugins must accurately match field extraction rules to prevent invalid data from entering the context. The analysis time for real-time alerts directly impacts response efficiency. Tool calling must prioritize pulling the latest review records for associated code changes to reduce manual retrieval workload.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | This configuration item functions stably in FastGPT v4.17.0, supports automatic routing for multi-source tool calls, and aligns with the multi-data-source docking requirements of SOC duty workflows |
| `functionCall` | Enabled | Supports structured extraction of key fields from alert disposal sheets and code change reviews |
| Tool call timeout | 600 seconds | Adapts to interface response delays from data sources like SIEM, preventing single call interruptions |
| Batch pull interval | 300–600 seconds | Matches the synchronization schedule for daily-updated threat intelligence briefings |
| Field matching rules | Match by alert ID and associated change number | Accurately extracts core associated data from alert disposal sheets |
| Maximum context length | 8000–12000 token | Accommodates full content for multiple alerts and change reviews, avoiding truncation of critical information |

## Three Common Misconfigurations
- Symptom: No response following a tool call, with session status showing timeout. Cause: No reasonable tool call timeout parameter set, failing to account for response delays across multiple data sources.
- Symptom: Output retains the phrase "Citation Mark: [1]". Cause: Automatic output configuration for knowledge base citation marks not disabled, causing attached marks to be included with knowledge base-associated content returned by tool calls.
- Symptom: Custom interface calls cannot be triggered using user keywords. Cause: No tool call trigger rules configured, with keyword matching not bound to tool calls.

## How to Verify Configurations Are Correct
- Submit a test request containing an alert ID, verify whether the tool automatically pulls the corresponding code change review record.
- Generate test output, confirm that phrases such as "Citation Mark: [1]" are not present.
- Enter preset keywords, verify whether custom interface calls are triggered and corresponding content is returned.
- Review tool call logs, confirm that the `toolChoice` and `functionCall` configurations are correctly loaded.

The values given are common starting points and should be measured against the reader's own samples.
