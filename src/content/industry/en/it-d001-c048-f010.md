# Code and Change Review Assistance for Security Monitoring and SOC Duty: Citation Sources and Traceability

## What this category of data looks like
This category of data comes from SIEM, EDR, NDR, and threat intelligence sources, with updates occurring in real time or daily. Daily processed documents include alarm disposal sheets, duty logs, threat intelligence notifications, and daily and weekly reports. Documents related to code and change review contain fields such as alarm ID, associated code change ID, disposal time, associated threat tags, and disposal results. Some documents must be associated with multi-source alarms and code change records, and the field format is mostly a mix of structured text and semi-structured logs.

## Constraints on citation sources and traceability
Multiple data sources and mixed formats require the traceability link to accurately match anchor fields such as data source identifiers and code change IDs to avoid cross-source confusion. Real-time updated alarms and code change data require traceability to support low-latency queries, otherwise change review and alarm analysis will be delayed. Multiple types of daily documents need to be associated with corresponding data sources based on scenario. If traceability rules are not bound to document types, the citation source may not match the actual disposal basis. Structured fields such as associated code change IDs must be used as traceability anchors. If field mapping is not configured, it will be impossible to quickly locate original code change records, increasing time spent on false positive troubleshooting and change review.

## How to set up configurations
This document is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1000 token | Adapts to the content length of alarm disposal sheets and code change review records in SOC scenarios, avoiding truncation of critical traceability information |
| `responseData` | Enable full original field return | Meets analysts' need to view original fields such as alarm ID, code change ID, and disposal time, aligning with daily analysis and review workflows |
| `detail` | Display grouped by data source and change ID | Facilitates quick differentiation of traceability data from different sources such as SIEM, EDR, and NDR, and associates corresponding code change records |
| Single citation limit | Top 4 entries | Matches scenarios where multi-source alarms are associated with code changes, avoiding excessive redundant information interfering with core analysis |
| Traceability query timeout threshold | 50 seconds | Adapts to the rhythm of real-time alarms and code change reviews, ensuring traceability results are synchronized with current tasks |

## Three common misconfigurations
- Issue: Citation results do not include the completion reason field for code change reviews, making them unavailable for subsequent review sessions. Cause: The full original field return for the `responseData` parameter was not enabled, and the original values of required fields were not retained.
- Issue: MySQL code change data retrieved via Function CALL is not displayed as a citation source, and is only restated in natural language. Cause: The `responseData` parameter was not configured to bind the original data source, and query results were not included in the traceability link.
- Issue: Traceability data from different sources is displayed mixed together, making it impossible to distinguish between SIEM alarms and code change records. Cause: The grouped display rule for the `detail` parameter was not configured, and classification was not performed by data source and change ID.

## How to confirm correct configuration
- Submit a test alarm data set that includes a code change ID, and check if the citation traceability module displays the original fields and code change records from the corresponding SIEM and EDR.
- Adjust the value of `quoteMaxToken`, and verify that the length of the returned traceability content matches the set value, with no truncation of critical information.
- Submit a multi-source associated alarm and code change request, and confirm that the traceability results are displayed grouped by data source and change ID.
- Submit a simulated real-time alarm, and check that the traceability query response time meets the set timeout threshold, with no timeout errors occurring.

The values provided are common starting points and should be measured against the reader's own samples.
