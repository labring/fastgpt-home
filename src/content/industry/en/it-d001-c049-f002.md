# Code and Change Review Assistance for Customer Training and Usage Manuals: Context and Token

## What Data for This Category Looks Like
Daily documents for this category include four types: training slides, user manuals, training attendance sheets, and question and answer lists. Data sources are the product help center, customer organizational structure, training recording videos, and ticket system. Document update frequency is typically once per order or per version. Core content focuses on three areas: role permission explanations, operation step demonstrations, and post-session question organization. The data structure primarily uses structured operation steps, unstructured recording video text, and ticket entries. There are no fixed, uniform field units. Processing logic must be adjusted based on the actual length of individual documents.

## Constraints on Context and Token Workflows
The multi-source nature and high unstructured proportion of category data require context recall to cover content from help centers, tickets, and recording videos. It also requires alignment with the update rhythm of each order or version to avoid recalling outdated invalid data. Individual document lengths vary widely. Training slides and user manuals may reach several thousand characters. Tickets and attendance sheets are mostly short text. The total token count for a single context must be limited to avoid exceeding model limits. Additionally, content from core areas has higher priority. The recall weight of role permission explanations and operation steps must be higher than other data. Otherwise, review assistance results will deviate from real user needs, leading to a subsequent surge in tickets.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of combined documents such as training slides and user manuals, prevents context overflow |
| `quoteMaxToken` | 2000–3000 token | Adapts to the core content length of a single user manual or operation step document, ensures complete key information |
| Context recall upper limit | Top 5 entries | Limits the number of question and answer lists and ticket entries recalled in a single call, reduces unnecessary token consumption |
| Context update trigger timing | Within 1 hour after version release | Aligns with the document update rhythm for this category per version, ensures timeliness of recalled content |
| Matching similarity threshold | 0.75–0.85 | Differentiates matching accuracy for different document types such as role permission explanations and operation steps, prevents irrelevant content from being included |

## Three Common Configuration Mistakes
- The interface displays the `AIPROXY_API_ENDPOINT or AIPROXY_API_TOKEN is not set` error. This occurs when the `AIPROXY_API_ENDPOINT` (AI Proxy service root address) and `AIPROXY_API_TOKEN` (AI Proxy administrator token) environment variables are not configured in the App/Admin server, causing service startup verification to fail.
- Recalled context content does not match the current code change being reviewed, and the number of results is far lower than expected. This happens when the context recall trigger timing is not adjusted based on the update frequency of category documents, resulting in the use of outdated training slides or ticket data.
- Token consumption per review exceeds expectations, leading to billing anomalies. This occurs when the upper limit of `maxContext` values is not restricted, and redundant training recording video and attendance sheet data is included in the context.

## How to Verify Successful Configuration
- Navigate to the FastGPT v4.17.0 system configuration page, check whether the values of `maxContext` and `quoteMaxToken` fall within the preset ranges, and confirm that changes were saved successfully.
- Upload a new version of the user manual, initiate a code change review assistance call, and check whether the returned context content includes the latest operation steps and role permission explanations.
- Review model call logs to confirm that token consumption statistics match the preset `maxContext` values, with no abnormal overconsumption.
- Trigger an update of training documents, confirm that recalled context content is automatically synchronized to the latest version.

The values provided are common starting points and should be evaluated against samples from the respective use cases.
