# Code and Change Review Assistance for Customer Training and Usage Manuals: Multi-turn Dialogue and Prompt Engineering

## What this category's data looks like
This category’s data originates from the product help center of code review tools, the organizational structure of customer development teams, recorded code review training videos, and ticket systems. Updates occur once per customer order or per code review tool version update.

Daily documents include code review training slides, code review tool user manuals, training attendance sheets, and lists of code review question answers. Training slides mark applicable roles and version ranges. User manuals include numbered code review operation steps. Attendance sheets record information of participating developers. Answer lists organize frequent customer questions related to code review.

Data fields are adjusted synchronously with updates, with no fixed unified statistical caliber.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering link
The multi-source update nature of category data requires regular filtering of older version code review tool document content from multi-turn dialogue contexts. This avoids passing outdated review rules to developers.

The diversity of document types requires prompts to distinguish usage scenarios for different documents. For example, when calling user manuals, focus on code review operation steps. When calling training slides, focus on permission allocation for review roles.

The existence of high-frequency time-consuming links requires preset prompt templates to cover two core scenarios: role permission explanations and operation step demonstrations. This reduces the probability of developers asking repeatedly.

The customer-specific nature of data requires strict isolation of dialogue contexts. This ensures code review training content from different customers is not mixed.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` association rule | Bind to current customer order ID | Ensure isolation of code review training dialogue contexts for each customer, complying with data privacy requirements |
| `messages` context window | First 10 turns of dialogue | Match the typical turn length of code review training-style dialogues, avoiding overly long contexts interfering with core Q&A |
| `variables` variable injection | Inject current code review tool version number, customer team role tags | Adapt to the update frequency and role field characteristics of category data, ensuring accurate reply content |
| Quick send button configuration | Preset 3-5 high-frequency questions, such as "How to view review permissions" "Code submission review steps" | Cover the two most time-consuming category scenarios: role permission explanations and operation step demonstrations |
| Historical dialogue storage limit | Calibrated based on actual testing | Adapt to the single-customer training cycle length of category data |

## Three common configuration mistakes
- Issue: Cross-customer code review-related dialogue reference content is displayed in the interface. Cause: `chatId` is not bound to the customer order ID, leading to mixing of dialogue contexts for different customers' code review training sessions
- Issue: Preset code review-related questions are not triggered after clicking the quick send button. Cause: No associated instructions for quick buttons are injected via `variables`, so the prompt cannot match the preset code review reply logic
- Issue: Code review training document files cannot be uploaded when calling the dialogue API. Cause: Document-associated API upload configuration is not enabled in FastGPT v4.17.0, resulting in the interface not supporting file input

## How to confirm the configuration is complete
- Initiate a test dialogue, generate a `chatId` using different customer identifiers, check that no cross-customer content leakage occurs in code review-related dialogue contexts
- Click the preset quick send buttons, confirm that the system quickly returns corresponding replies matching code review training documents
- Refresh the page in a non-login scenario, check that the code review dialogue history stored in `messages` is retained normally
- Call the dialogue API to upload a code review training slide file, confirm that the interface can normally receive and process the file content
