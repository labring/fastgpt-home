# Code and Change Review Assistance for Client Training and Usage Manuals: Tool Calling and Plugins

## What this category of data looks like
Typical users of this category are customer success managers, training instructors, and product operations teams. Daily produced documents include training slides, user manuals, training attendance sheets, and problem resolution checklists. Data sources mainly include product help centers, customer organizational structures, training recording videos, and ticket systems. Update frequency is per order or per version. Document structures cover operation guides, permission descriptions, resolution records, and other types, with no unified fixed fields. Data volume fluctuates with customer order count and version iterations.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources for this category are scattered and updated frequently, requiring tool calling to support integration with multiple data types, including static documents, dynamic tickets, and recording video data. There is no unified format for document structures, so tool plugins must adapt to different input parsing rules. The high-frequency update feature requires the tool calling chain to support scheduled synchronization of the latest training and ticket data, to avoid using expired content for review assistance. Additionally, the core time-consuming links of this category focus on permission explanations and step demonstrations. Tool calling must prioritize associating knowledge base entries corresponding to these scenarios to improve assistance efficiency.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapt to the automatic tool selection required for multi-type content in client training documents |
| `functionCall` | Enabled | Support structured calls to MCP services to complete code review-related queries and data retrieval |
| Tool call timeout threshold | 600 seconds | Match the batch processing duration of training recording videos and ticket data |
| Knowledge base recall limit | Top 10 entries | Adapt to the single-batch data volume of client training documents |
| Context window size | 8000–12000 token | Accommodate complete user manuals and review code snippets |

## Three common mistakes
- No tool trigger after initiating a code review-related query, with the interface displaying "Tool not enabled". The cause is failing to set `toolChoice` to `auto` or specify the corresponding tool type.
- Content returned after calling the tool is irrelevant to the current training manual question, with cross-category general resolution content appearing. The cause is failing to limit recalled knowledge bases to the exclusive data source for client training and usage manuals.
- A locally deployed model returns a connection timeout error (error code 504) when calling the MCP service. The cause is that the locally deployed model is not configured with whitelist rules allowing calls to external tools.

## How to confirm the configuration is complete
- Initiate a query containing code review keywords, and check whether corresponding records are generated in the FastGPT v4.17.0 tool call logs.
- Check whether the tool call return results include content related to client training documents, such as permission descriptions, operation steps, etc.
- Verify that there are no connection errors when a locally deployed model calls the MCP service, confirming that the tool call chain is working properly.
- Adjust the query keywords to non-training-related content, confirming that the tool will not trigger irrelevant knowledge base recalls.
