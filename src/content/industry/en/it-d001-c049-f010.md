# Code and Change Review Assistance for Customer Training and Usage Manuals: Citation Sources and Traceability

## What Data for This Category Looks Like
Data for this category typically comes from product help centers, customer organizational structures, training recordings, and ticketing systems. Update frequency follows per order or per version. Daily documents include training slides, user manuals, training attendance sheets, and question and answer lists. Most document structures center on operation steps, role permissions, and common Q&A. Fields cover operation nodes, permission scopes, Q&A keywords, and more. There is no unified mandatory format, and adjustments are made based on the customer’s actual scenario.

## What Constraints These Characteristics Impose on Citation Sources and Traceability
Data sources for this category are scattered, and formats are inconsistent. During citation sources and traceability processing, it is necessary to adapt to multi-source heterogeneous content, and configure cross-source retrieval rules to cover different data sources such as product help centers and customer organizational structures. Data update frequency changes with customer orders or versions. Ensure cited content is synchronized with the current version to avoid outdated operation instructions. Daily documents mostly revolve around operation steps and role permissions. Citations must accurately match the context, otherwise Q&A deviations are likely to occur. Unstructured data from ticketing systems and training recordings requires additional parsing rules to complete full traceability associations.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the single-paragraph content length of training slides and user manuals, avoiding truncation of key operation steps and permission descriptions |
| `responseData` | Return only specified knowledge base entries | Ensures traceability content only comes from data sources of this category such as product help centers and ticketing systems, filtering out irrelevant content |
| `detail` | Return full document metadata | Includes document source and update time fields, used to verify consistency between cited content and the current version |
| Single search limit | Top 6 entries | Covers the number of associations for common Q&A lists and operation step content, avoiding returning redundant information |
| Maximum context | 1500–2500 characters, calibrated via actual testing | Adapts to the length of training documents for different customers, avoiding context overflow that affects retrieval accuracy |
| Retrieval timeout | 300 seconds, calibrated via actual testing | Adapts to the parsing duration of unstructured data from training recordings and ticketing systems, avoiding retrieval interruptions |
*This configuration is based on FastGPT v4.17.0*

## Three Common Misconfigurations
- Setting `quoteMaxToken` to too small a value results in complete operation step content being truncated, and the citation source field displayed as empty on the interface. The cause is failure to adapt to the length requirement of single-paragraph operation steps in training slides, and failure to adjust parameters according to the characteristics of category data.
- Not enabling the specified data source filter for `responseData` results in retrieval results including non-training-related content, and returning results even when the question is unrelated to user manuals and Q&A lists in the knowledge base. This corresponds to the problem of retrieving irrelevant content in actual scenarios.
- Not configuring `detail` to return metadata results in inability to verify the update time of cited content, leading to use of outdated training recording content. The cause is ignoring the feature that category data updates with versions, and failing to enable the metadata verification link.

## How to Confirm the Configuration Is Correct
- Upload a typical piece of training slide content, check after retrieval whether the returned citation sources only come from the specified data sources of this category, to confirm that the `responseData` configuration is effective.
- Test a long piece of operation step description, check whether the cited content is complete and not truncated, to confirm that the `quoteMaxToken` value adapts to the characteristics of category data.
- Retrieve a question related to role permission explanations, check whether the returned results include the document update time field, to confirm that the `detail` configuration is effective.
- Adjust the value of the single search limit, check whether the number of returned associated entries meets expectations, to confirm that the retrieval rule configuration is correct.

The values provided are common starting points and should be measured against the reader's own samples.
