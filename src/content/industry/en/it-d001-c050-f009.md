# Code and Change Review Assistance for Customer Onboarding and Tenant Initialization: Tool Calling and Plugins

## What the data for this category looks like
This category's data primarily originates from CRM systems, contract order databases, identity management systems, and product backends. The update frequency is per order or daily. Associated daily documents include customer onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation forms. Core fields include customer unique identifier, tenant ID, permission configuration scope, onboarding status, and delivery milestone. The data structure adjusts dynamically based on the different stages of the customer onboarding process.

## What constraints these characteristics impose on the tool calling and plugins workflow
Since the data comes from multiple independent systems, tool calling must support cross-system interface integration. Authentication parameters and field mapping rules for each system must be configured in advance. The update frequency of per order or daily means tool trigger timing must be tied to individual tenant onboarding process nodes. Core documents include multiple types of forms, so tool calling must accurately extract corresponding fields to avoid missing critical information such as permission configurations and account lists. Errors will prevent customers from logging in or cause delivery delays, so failure retry and alert mechanisms must be configured to ensure process traceability. The content on this page is based on the tool calling and plugins functionality of FastGPT v4.17.0.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts to the hybrid mode of tool calling and large model generation, suitable for multi-system integration scenarios |
| `functionCall` | `{"name":"sync_tenant_config","parameters":{"required":["tenant_id","admin_accounts"]}}` | Matches the required fields of tenant configuration sheets and administrator account lists |
| HTTP plugin authentication configuration | API key + request header formatted as application/json | Meets the HTTP interface integration requirements for external CRM and identity management systems |
| Tool calling trigger timing | 10 seconds after tenant configuration submission | Aligns with the milestone rhythm of individual tenant onboarding processes, avoiding conflicts with other concurrent processes |
| Number of failure retries | 3 times, 60-second interval | Addresses temporary exceptions in single interface calls, ensuring process continuity |
| Log collection switch | Enabled | Used to track detailed tool calling processes, meeting the acceptance requirements of delivery confirmation forms |

## Three common misconfigurations
- Phenomenon: Application call return results are directly output to the conversation interface. Cause: Tool return results are not configured as large model context input items, and only direct output mode is enabled.
- Phenomenon: No valid return is obtained when calling the workflow via API. Cause: The target function and parameters for `functionCall` are not specified in the configuration, preventing the tool from triggering.
- Phenomenon: Tool calling records inside the application cannot be viewed in the conversation details page. Cause: The tool calling log collection configuration is not enabled, so logs are not persistently stored.

## How to verify successful configuration
- Submit a test customer onboarding application form, check whether the corresponding system interfaces are called according to the configuration.
- View the tool calling logs, confirm that the returned tenant configuration data is correctly passed to the large model context.
- Call the API interface bound to this configuration, check whether the returned status code matches the expected result.
- Complete the test tenant initialization process, verify whether correct administrator accounts are generated in the corresponding identity management system.
