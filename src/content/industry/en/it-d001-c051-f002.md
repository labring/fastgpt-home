# Code and Change Review Assistance for Customer Data Import and Migration: Context and Token

## What data for this category looks like
Data for this category primarily comes from customer legacy systems, CSV or Excel templates, database export results, and product import logs. Daily maintained documents include data templates, migration plans, field mapping tables, and migration verification reports. Primary users are implementation consultants, data implementation engineers, and customer IT liaisons. Data update frequency is per order or irregular. Core processing steps include field mapping confirmation, dirty data cleaning, and post-import sampling verification. Most involved fields are business data fields, with no unified fixed units.

## Constraints imposed on the "context and token" link by these characteristics
Data for this category has diverse sources and large format differences. Multiple documents must be associated to complete operations such as field mapping and dirty data cleaning. This leads to significant fluctuations in context token consumption.
The field mapping link needs to load multiple sources such as field mapping tables, migration plans, and customer historical data at the same time. This easily exceeds the preset context window limit.
Token usage for ultra-long import tasks grows linearly with data volume. This easily triggers timeout restrictions.
Dirty data cleaning requires retaining the full context of verification logic. This further compresses available token space and increases the complexity of context configuration.

## How to Set Configurations

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8192–16384 token | Adapts to the multi-source document association needs of most customer data import tasks, matches the basic context limit of FastGPT v4.17.0 |
| `quoteMaxToken` | 2048–4096 token | Covers core verification and mapping logic for single-batch imported data, prevents single segments from occupying too much context |
| Context loading timeout | 300–600 seconds | Adapts to the processing duration of dirty data cleaning and multi-source document association, avoids early timeout for ultra-long tasks |
| Context recall count | Top 3–5 entries | Focuses on core migration documents, reduces token consumption from irrelevant content |
| Multi-source document merge threshold | Calibrated based on actual measurements | Adjust according to the total character count of migration plans and field mapping tables, ensures complete loading of associated content |

## Three Common Misconfigurations
- The symptom is that ultra-long import tasks are truncated when reaching 12288 token, displaying an out-of-reply-limits error. The cause is failure to adjust the `maxContext` parameter to match the total token consumption of the task; the default context window is insufficient to carry multi-source associated migration data.
- The symptom is that token consumption cannot be counted by application dimension. The cause is failure to enable application-level context token tracking configuration; only the token usage of single-round questions and answers is counted by default.
- The symptom is that even after setting a similarity threshold of 0.4 and a reference upper limit of 10000 token, the required field mapping content still cannot be recalled. The cause is failure to adjust `quoteMaxToken` based on the total character count of migration documents, resulting in valid associated content not being loaded.

## How to Verify Correct Configuration
- Import a test batch of data, check the context token usage in the system log, and adjust the configuration until the usage matches the task requirements.
- Trigger the field mapping verification process, confirm that the returned content covers the core business content of migration plans and field mapping tables.
- Run a dirty data cleaning task, confirm that the task execution duration does not exceed the preset timeout limit.
- Count token consumption across multiple rounds of import tasks of different scales, verify that the configuration can adapt to import scenarios with different data volumes.

The values provided are common starting points and should be measured against the reader's own samples.
