# Code and Change Review Assistance for Customer Data Import and Migration: Workflow Orchestration

## What This Category of Data Looks Like
Data sources for this category include customer historical system exports, CSV or Excel data templates, database backup files, and log files generated by product imports. Daily supporting documents include data templates, migration plans, field mapping tables, and migration validation reports.
Data update frequency is per order or irregular, with no fixed cycle. Data fields include customer identifiers, business attributes, numerical units, and more. Field structures differ across customers, so alignment via mapping tables is required.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Multiple data sources require workflows to support connecting different format data source nodes, and avoid hardcoding for single file types. Irregular update rhythms mean workflows cannot rely on fixed timed triggers. They must support manual triggering or event triggering based on mapping table updates.
Diverse supporting documents require workflows to bind associated file variables, so configurations such as field mappings and validation rules can be read dynamically.
Time-consuming field mapping and dirty data cleaning steps require workflows to place validation nodes upfront, and configure failure retry and rollback logic to prevent overall process interruption.

## Configuration Guidelines
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Trigger Timing | Trigger manually or via field mapping table update events | Matches the irregular update business characteristics of data import and migration |
| `variables` | Bind file IDs of data templates and field mapping tables | Enables parameter passing for multi-source data and configuration files |
| Node Timeout | 600–1200 seconds | Covers the typical time required for dirty data cleaning and field validation |
| Retry Count | 2–3 times | Addresses temporary network fluctuations or transient data format exceptions |
| `nodeId` | Bind the ID of the import log node | Links the trace path for failure logs, facilitating problem troubleshooting |
| Failure Callback | Push to a pre-configured receiving address | Meets the notification needs of implementation consultants and customer IT contacts |

## Three Common Misconfigurations
- Workflow conversation logs are empty after invocation. Cause: Uploaded file resources are not bound to workflow nodes via `variables`, so the process cannot read target data.
- Workflow dialogs show failure in Docker-deployed FastGPT, but model backend has response logs. Cause: `nodeId` is not configured to associate node status validation, so the process does not correctly capture node execution results.
- Workflow node prompts do not execute as expected. Cause: Trigger timing of node prompts is not clearly defined, so data processing logic is not executed after field mapping validation.

## How to Verify Successful Configuration
- Upload a test CSV file, check if the workflow's `variables` correctly bind the file's upload ID.
- Manually trigger the workflow, verify if node logs include field mapping validation results.
- Simulate a dirty data scenario, confirm if the workflow's retry node triggers as configured.
- Verify that failure callbacks can be correctly pushed to the specified receiving address.

The values provided are common starting points and should be measured against the reader's own samples.
