# Code and Change Review Assistance for Customer Data Import and Migration: Tool Calling and Plugins

## What Data in This Category Looks Like
This category’s data sources include content exported from legacy customer systems, custom CSV/Excel templates, offline database backups, and product interface import logs. Supporting daily documents include data templates, migration plans, field mapping tables, and migration validation reports. Data updates occur per order or irregularly. Single migration data volumes vary widely. Core content covers business fields, mapping rules, validation thresholds, and some custom fields lack unified format standards.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Workflow
Multiple data sources require tool plugins to support adaptability. Plugins must handle CSV parsing, database connections, log extraction, and other tool call types. Irregular update cycles let the tool calling workflow adjust mapping rules flexibly without repeated configuration initialization. Complex field mapping logic requires tool calls to carry full mapping parameters to prevent field misalignment. Wide data volume variations require tool calls to have configurable timeout and retry mechanisms to fit migration tasks of all scales. Migration errors can cause severe business harm, so tool calls must retain complete execution logs for issue tracing.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically match the tools required for the current migration workflow, and adapt to parsing needs for multiple data sources |
| `functionCall` | `[{"name":"parse_source_data"},{"name":"match_field_mapping"},{"name":"run_import_check"}]` | Define the tool calling sequence according to the standard step-by-step process of customer data migration |
| Single tool call timeout threshold | `600 seconds` | Adapt to the time required for large-volume data parsing, field validation, and import operations |
| Tool call retry count | `2 times` | Avoid migration failures caused by temporary network fluctuations or temporary resource shortages |
| Tool call log retention period | `30 days` | Support subsequent migration validation, issue troubleshooting, and compliance tracing |

## Three Common Mistakes
- Phenomenon: Only some of the multiple tools configured in the workflow are executed, and triggers do not follow the preset order. Cause: The parameter sequence of `functionCall` is not configured correctly, so the execution order of tool calls does not follow the migration process definition.
- Phenomenon: CSV-format migration data returns empty results after parsing, and field mapping validation fails. Cause: The adaptation rules for `toolChoice` are not adjusted for customer custom fields, so the tool cannot recognize non-standard template content.
- Phenomenon: Large-scale data import tasks terminate early, and the interface returns a timeout error prompt. Cause: The tool call timeout threshold is not adjusted, and sufficient time is not reserved for parsing and import operations, causing the task to terminate before completion.

## How to Confirm the Configuration Is Correct
- Review the tool call configuration list to confirm that each migration step’s corresponding tool has been added to the calling sequence.
- Upload a small-volume test data template to trigger the tool calling workflow, and check that each tool’s execution logs are complete and free of errors.
- Verify the automatic adaptation effect of the `toolChoice` parameter, and confirm that parsing tools for different data sources can be called normally.
- Simulate an abnormal scenario of temporary network interruption, and check whether the tool’s retry mechanism triggers according to the configured rules.
