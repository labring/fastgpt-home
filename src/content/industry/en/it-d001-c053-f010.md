# Code and Change Review Assistance for Customer Requirement Pool Management: Citation Sources and Traceability

## What the data for this category looks like
This category's data typically originates from ticketing systems, customer interview records, CRM systems, and product roadmaps. Its update frequency is weekly or per release cycle. Daily produced documents include requirement pool lists, requirement evaluation forms, customer feedback records, and version planning descriptions. Fields include requirement ID, associated customer identifier, feedback content, priority tags, and version association items. Most data is structured text; some includes unstructured content from customer speech transcripts. The data usually does not include research and development code itself, and only focuses on business information related to requirements.

## What constraints these characteristics impose on the "citation sources and traceability" link
Because data sources are spread across multiple systems, citation traceability must support cross-data source association verification. This ensures requirement entries correspond one-to-one with original feedback and work order records. Data updates occur frequently, so automatic synchronization mechanisms must be configured to prevent the use of outdated citations. Different documents have varying field formats, so citation path rules must be adapted for different document types including requirement pool lists and customer feedback records. This category handles merged feedback from multiple customers, so traceability must distinguish associated records for different customers to avoid confusion. For users without technical backgrounds, traceability logic must balance accuracy and ease of use, and avoid overly complex configuration steps.

## How to configure settings
This configuration is based on the interface logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Maximum Context | 8000–12000 token | Adapts to the average content length of requirement pool documents, avoiding truncation of key requirement information |
| Maximum Knowledge Base Citations | Top 6 entries | Matches the range of associated feedback quantity for a single review, controlling information density |
| Maximum Response Tokens | 2000–3000 token | Covers the full output requirements for requirement evaluation and traceability descriptions |
| `quoteMaxToken` | 1200–1800 characters | Limits the display length of a single citation, avoiding information overload on the page |
| `responseData` | Enabled | Retains structured identifiers for citation sources, facilitating subsequent traceability verification |
| `detail` | Enabled | Displays core fields of citation sources, such as associated customer identifier and work order number |

## Three Common Configuration Errors
- Symptom: Returned results forcefully include citation sources and cannot be hidden on demand. Cause: The switch status of the `responseData` parameter was not configured correctly, resulting in forced output of citation identifiers.
- Symptom: Red error prompts appear in returned results after configuration. Cause: The association verification rules for multiple data sources in the requirement pool were not adapted, and traceability failed to match original work orders or customer feedback records.
- Symptom: Citation content is too long during requirement review, causing interface overflow. Cause: The value of `quoteMaxToken` was set too high, failing to limit the display length of a single citation.

## How to Confirm Configuration Is Complete
- Import a typical requirement pool list document, trigger the review process, and verify that citation sources are associated with corresponding work orders or customer feedback records.
- Adjust the value range of configuration items, and confirm that the length of returned content and the number of citations match the needs of the current review scenario.
- Check the citation mark format displayed on the interface, and confirm that it aligns with the field rules of the requirement pool document.
- Simulate an update to the requirement pool data, and verify that traceability information is synchronized to the latest version content.
