# Code and Change Review Assistance for Container Platform Operations: Citation Sources and Traceability

## What data for this category looks like
Core data for container platform operations comes from Kubernetes API, image registries, monitoring systems, and CI pipelines. Update frequency is daily or upon completion of each cluster change. Daily produced documents include cluster change tickets, namespace quota tables, deployment records, and fault reports. Data fields include cluster identifiers, Pod running status, image version numbers, change execution times, and more. The character count of individual documents fluctuates with cluster scale. Data entries take single clusters and single changes as their basic units.

## Constraints on citation sources and traceability
Unlike cloud host delivery categories, container platform operation data centers on cluster orchestration units. As a result, traceability requires associating multi-dimensional cluster configuration fields. Data sources are scattered and update frequency is high, so citation traceability must clearly distinguish permissions and timeliness of different data sources. This prevents referencing expired monitoring metrics or ineffective CI configurations. Document structures include multi-dimensional operation and maintenance fields. Field names must be matched precisely to ensure traceability accuracy. Otherwise, errors may occur in resource quota adjustment, Pod exception troubleshooting, and other links. Operational errors directly relate to business interruptions. Therefore, the traceability link must fully retain the association relationships of original data. Fields cannot be simplified or key information truncated.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | First 8000 tokens | Matches the average character count of a single cluster change ticket, avoids truncating key configuration fields |
| `responseData` | Return only Kubernetes API and image registry fields | Filters irrelevant data sources outside monitoring systems and CI pipelines, ensures traceability covers category-specified data sources |
| `detail` | Enable full field display | Retains core fields such as Pod status, change time, and quota values, enabling cross-verification |
| Maximum recall count | First 10 entries | Adapts to the number of daily operation and maintenance document entries, avoids redundant information interfering with review logic |
| Context refresh interval | Every 30 seconds | Matches data update frequency, ensures cited content aligns with real-time cluster status |

## Three common configuration errors
- The number of model context entries displayed on the page does not match the number actually sent to downstream systems. For example, 30 entries are displayed but 310 are actually sent. This occurs because the matching rules between `quoteMaxToken` and recall limits are not correctly configured, causing the context truncation logic to not take effect.
- Specified citation content cannot be removed. This occurs because custom citation filtering configuration is not enabled, and the global citation switch is mistakenly confused with single-data-source filtering.
- Citation variables cannot be correctly embedded into the body of change review documents. This occurs because data source fields are not mapped to document template variables, causing variable replacement to fail.

## How to confirm configurations are set correctly
- Submit a review request for a cluster change ticket, check that returned citation sources only include specified data sources such as Kubernetes API and image registries.
- View the model context panel, verify that the displayed number of entries matches the number sent to downstream systems.
- Test the variable replacement function, confirm that fields such as namespace quotas and Pod status can be correctly embedded into review document bodies.
- Adjust the `quoteMaxToken` parameter to a smaller value, verify that citations of long documents are truncated according to the configured rules.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
