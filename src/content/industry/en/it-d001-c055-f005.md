# Code and Change Review Assistance for Capacity Planning and Resource Scaling: Multi-turn Dialogue and Prompt Engineering

## What this type of data looks like
Core data for this category comes from cloud billing, monitoring systems, business forecast reports, and stress test results. Daily produced documents include capacity planning reports, scaling application forms, resource utilization reports, and budget calculation sheets. Document fields include resource type, configuration specification, application quota, budget amount, and similar items. Update frequency is usually weekly or monthly. Typical users are SREs, cloud platform operation and maintenance personnel, and architects. Data focuses on resource configuration and cost calculation for production environments, and does not include non-operation business interaction data.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
The multi-source nature of category data requires multi-turn dialogue to call content from different data sources in stages. This avoids processing timeouts caused by loading full data at once. The fixed field structure of documents requires prompt engineering to preset calling rules for corresponding fields. This ensures the dialogue can accurately extract the approval status of scaling application forms and quota information from budget calculation sheets. The weekly or monthly update frequency requires limiting the dialogue context window to the most recent report cycle. This prevents expired data from affecting review accuracy. Scenarios combined with code change review require the dialogue to associate with specific PR identifiers and resource configuration applications. This ensures review content corresponds one-to-one with code changes.

The following configurations apply to FastGPT v4.17.0.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Dialogue context window | Previous 3 report cycles (approximately 21-30 days) | Matches the weekly or monthly update frequency of category data, avoids loading expired historical data |
| `variables` configuration | Bind resource utilization and peak forecast fields | Matches resource utilization reports and peak forecast data included in daily category documents, ensures prompts can call corresponding fields |
| `messages` field filtering | Only retain review-related context from the last 7 days | Matches the short-cycle nature of code and change review, filters redundant content not related to the current review |
| Multi-turn dialogue round limit | No more than 5 rounds | Matches the number of conventional approval nodes for capacity planning reviews, avoids redundant dialogue consuming resources |
| `chatId` binding | Associate with the unique identifier of the current PR | Matches code and change review scenarios, binds dialogue to specific code changes, avoids context confusion |

## Three common misconfiguration errors
- Symptom: AI dialogue node results inserted in the workflow are appended to the final output. Cause: No filtering rules are configured for the `messages` field, causing intermediate dialogue context to be included in the final output.
- Symptom: Timeout error occurs during dialogue execution, with status code 504. Cause: The loading range of dialogue context is not limited, and full historical report data is called, exceeding processing limits.
- Symptom: The dialogue cannot extract quota information from budget calculation sheets. Cause: `variables` are not bound to the correct data source, causing prompts to fail to call budget-related data corresponding to the category.

## How to confirm configurations are properly set
- Initiate a code change review dialogue, check that the returned results only include changes from the current PR and corresponding capacity planning data.
- View dialogue logs, confirm that `chatId` is bound to the unique identifier of the current PR.
- Test intermediate AI dialogue nodes in the workflow, confirm that their output is not appended to the final result.
- Verify that in multi-turn dialogue, the context of each round only includes data from the most recent report cycle.
