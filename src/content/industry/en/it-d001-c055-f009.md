# Code and Change Review Assistance for Capacity Planning and Resource Scaling: Tool Calling and Plugins

## What the data for this category looks like
The core data for this category comes from cloud billing systems, monitoring systems, business forecasting models, and stress test reports. Daily produced documents include capacity planning reports, scaling application forms, resource utilization reports, and budget estimation sheets. Data is updated weekly or monthly.

Data fields and units vary across sources: cloud billing uses yuan and GB-hour as units, monitoring systems collect metrics such as CPU utilization and request QPS, stress test reports record response time data in milliseconds, and budget estimation sheets count procurement costs in ten thousand yuan.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multiple heterogeneous data sources require tool calling to support multi-interface routing and format conversion, to avoid review errors caused by mismatched field units. The weekly or monthly update frequency means tool calling should not use overly short trigger intervals, to prevent repeated pulling of invalid data. The multi-table structure of documents requires plugins to support parsing different input and output formats, to adapt to different review scenarios such as capacity planning reports and scaling application forms. Additionally, data validation logic differs across sources, so validation rules must be configured separately for cloud billing and monitoring metrics to ensure the accuracy and reliability of data entering the review stage.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic routing for multi-source data interfaces |
| `functionCall` | Enable batch mode | Supports batch pulling of cloud billing and monitoring metric data |
| Maximum single data pull count | 10000 entries | Matches the statistical granularity of weekly capacity reports |
| Data timeout threshold | 300 seconds | Aligns with the average response time of multi-source APIs |
| CSV format validation switch | Enabled | Ensures imported resource utilization data meets format requirements |
| Field mapping rules | Convert per original data units | Unifies field unit standards for the review stage |

## Three Common Mistakes
- Symptom: The set of CSV files created via API calls does not match the data generated in the interface. Cause: The target interface for `toolChoice` was not explicitly specified, and the tool automatically called an outdated legacy data interface.
- Symptom: The plugin preview retrieves resource data, but the final review output is empty. Cause: The result mapping logic for `functionCall` was not configured, and pulled raw data was not converted to the field format required for the review form.
- Symptom: When using chunk mode to call the pushdata API to upload data, the interface always shows indexing in progress. Cause: A reasonable batch submission batch size was not set, and the single upload data volume exceeded the platform's default limits.

## How to Confirm Configuration Is Complete
- Run a single data pull test, verify that the returned fields exactly match those in the capacity planning report.
- Submit a batch call task, check that the task completes within the preset duration with no timeout errors.
- Import CSV-format resource utilization data, confirm that the statistical results displayed in the interface match the raw data.
- View the plugin debug logs for FastGPT v4.17.0, confirm that the `toolChoice` and `functionCall` parameters are parsed correctly.

The values provided here are common starting points, and should be validated against the reader's own samples.
