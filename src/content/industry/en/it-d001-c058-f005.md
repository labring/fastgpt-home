# Code and Change Review Assistance for Advertising Compliance Traceability: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category originates from advertising platform backends, customer qualification documents, contract systems, and publicly available regulatory rules. The update frequency is once per active campaign per month. Commonly processed documents include advertising review forms, qualification attachments, delivery records, and rectification notices.
Advertising review forms include fields for delivery time periods and compliance identifiers. Qualification attachments mark validity periods and issuing authorities. Delivery records record delivery nodes and compliance check results. Rectification notices link to problem entries from corresponding review batches.

## Constraints for Multi-turn Dialogue and Prompt Engineering
This category’s data has a low update frequency, but the volume of documents linked to a single active campaign is not fixed. Multi-turn dialogue must limit the context window to avoid redundant information interfering with core compliance checks.
There are multiple document types, so prompts must adapt to the field formats of different documents. This prevents confusion between extraction logic for advertising review forms and qualification attachments.
Compliance traceability requires strict retention of evidence chains. The `messages` from multi-turn dialogue must be archived in interaction order, and intermediate steps cannot be truncated arbitrarily.
Evidence required by regulations must be matched precisely. Prompts must explicitly specify extraction fields to prevent omission of key information such as compliance identifier numbers.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum Context | First 15 turns of dialogue or 8000–12000 characters | Adapts to the volume of documents linked to a single active campaign, avoids context overflow affecting compliance checks |
| Variable Binding | Bind `variables` to the set of compliance fields | Accurately extracts specified compliance fields from advertising review forms and qualification attachments |
| Session Association | Bind `chatId` to the review batch number | Links multi-turn dialogue to corresponding compliance traceability batches, facilitating subsequent archiving and traceability |
| Prompt Splitting | Call dedicated templates by document type | Adapts to different extraction and check logic for advertising review forms and rectification notices |
| Timeout Setting | 600 seconds | Adapts to delays when retrieving qualification documents and contract data across systems |

## Three Common Mistakes
- Phenomenon: Compliance rule trace display symbols appear at the end of multi-turn dialogue results. Cause: No instruction to disable trace output was added to the prompt, and FastGPT v4.17.0 enables this display function by default.
- Phenomenon: Images in qualification attachments are not fully displayed when calling prompts to generate compliance traceability content. Cause: No complete reference path for image resources was added to `messages`, causing the conversation context to fail to load full attachment information.
- Phenomenon: Request timeouts or failures occur when processing compliance review batches in bulk. Cause: Concurrency configuration was not adjusted based on the number of documents linked to a single active campaign, causing system concurrent requests to exceed carrying capacity.

## How to Verify Proper Configuration
- Manually initiate a compliance review dialogue. Check whether redundant rule trace symbols exist in the returned results. Adjust prompt instructions if such symbols are present.
- Upload a qualification attachment document, initiate a multi-turn dialogue, and confirm that all key fields of the attachment are included in the returned content, with no omissions or truncations.
- Simulate initiating dialogues for 3 to 5 review batches in bulk. Observe whether the system experiences request timeouts or abnormal errors. Adjust concurrency configuration to achieve a stable state.
- Check whether `chatId` in the session list corresponds one-to-one with review batch numbers. Confirm that the association between sessions and compliance traceability batches is correct.

The values given are common starting points and should be measured against the reader's own samples.
