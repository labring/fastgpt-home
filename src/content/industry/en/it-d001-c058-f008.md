# Code and Change Review Assistance for Advertising Compliance Audit Trail: Workflow Orchestration

## What the Data for This Category Looks Like
Data for this category originates from advertising platform backends, customer qualification records, contract systems, and publicly released regulatory rules. Update frequency follows either per campaign or monthly cycles. Daily generated documents include advertising review forms, qualification attachments, delivery logs, and rectification notices. Advertising review forms contain compliance check items and delivery time window fields. Qualification attachments mark expiration dates and qualification identification numbers. Delivery logs track delivery stages and trigger events. Rectification notices link corresponding compliance issues and rectification statuses. Data fields have no unified statistical unit, with formats matched only to specific business scenarios.

## Constraints on Workflow Orchestration
Data sources for this category are dispersed. Multiple nodes must be configured in the workflow to pull compliance data from different systems individually, to prevent overloading a single node. Update frequencies vary. The workflow must support two trigger modes: campaign-initiated or scheduled, to align with different business rhythms. Document types are diverse. Nodes must be configured to handle multiple compliance document formats including tables and attachments, to ensure accurate data parsing. Code change reviews require linking to compliance data. The workflow must connect the full process of change submission, compliance verification, and audit trail archiving. It must trigger alerts when errors occur, to prevent missing compliance audit trail records.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Global Variables | Bind advertising review form numbers and qualification validity period fields | Adapt to fixed compliance data field requirements of this category |
| Node Trigger Conditions | After new delivery campaign submission, 00:00 on the 1st of each month | Match the per-campaign or monthly update frequency of this category |
| `variables` | Include compliance check results and code change association IDs | Used for compliance check matching during code change reviews |
| `nodeId` | Bind data pull nodes and review nodes | Ensure accuracy of data flow in the workflow |
| Timeout Threshold | 300-600 seconds | Adapt to time differences for pulling compliance data from multiple systems |
| Variable Storage Path | Store in a dedicated compliance audit trail directory | Facilitate subsequent qualification archiving and rectification evidence organization |

## Three Common Configuration Errors
- Workflow runtime displays `gpt-4o-mini call failed` logs, but no corresponding AI call node is configured. This occurs when redundant legacy node configurations are not cleaned up, or unused AI call nodes are imported along with a workflow template.
- Global variable history records cannot be modified, preventing compliance data updates from syncing to the workflow. This happens when edit permissions for global variables are not enabled, or a read-only variable storage type is used.
- The compliance attachment field linked to the code change review node is empty, and qualification attachment data cannot be retrieved. This occurs when no attachment storage path mapping is configured in `variables`, or the `nodeId` binding for the data pull node is incorrect.

## How to Verify a Complete Configuration
- Manually trigger the workflow once, and verify that global variables include the preset compliance data fields
- Review the `nodeId` binding relationships of workflow nodes, and confirm that data pull nodes and review nodes are correctly linked
- Validate the effectiveness of the timeout threshold, and adjust it to a range that matches actual data pull time consumption
- Check the variable storage path, and confirm that compliance documents can be correctly archived to the specified directory

The values provided are common starting points and should be measured against actual operational samples.
