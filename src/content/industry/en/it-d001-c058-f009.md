# Code and Change Review Assistance for Advertising Compliance Logging: Tool Calling and Plugins

## What the data for this category looks like
The data for this category comes primarily from advertising platform backends, customer qualification systems, contract management systems, and publicly available regulatory rules. Four types of documents are produced regularly: advertising review forms, qualification attachments, delivery records, and rectification notices. Data updates trigger per individual advertising campaign or monthly cycle. Document structures include basic identification fields, associated business fields, and compliance verification fields. The character count of individual documents varies widely, from dozens of characters for audit identifiers to thousands of characters for delivery records. No additional statistical supplementary fields are included.

## What constraints these characteristics impose on the tool calling and plugins workflow
The data sources for this category are scattered, involving multiple independent systems such as advertising platforms, customer qualification systems, and contract systems. The tool calling link must support configuration of multi-source access credentials to pull corresponding data. Document types are diverse, including structured tables, unstructured text, and image attachments. Tools must adapt to parsing logic for different formats. Data update cycles trigger per individual advertising campaign or monthly cycle. Tool calling must support on-demand triggering. The character count of individual documents varies widely. Tools must adapt to content processing for different lengths. At the same time, the accuracy of compliance logging is directly linked to regulatory inspection results. Execution logs and return results of tool calls must be fully retained.

## Three Common Misconfiguration Issues
- Symptom: Tool calls return a `Failed to fetch` error with a status code of 500 or 404. Troubleshooting steps: Check whether the server environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy admin token) are not correctly configured, or if the configured address includes a path suffix such as `/v1`.
- Symptom: Qualification attachment data pulled via tool calls is missing or has abnormal formatting. Cause: Corresponding parsing tools are not configured for different document types such as images and PDFs, or multi-source credential configuration errors prevent complete pulling of data from customer qualification systems.
- Symptom: Compliance logging logs are not generated after tool call execution. Cause: The tool call result retention configuration is not enabled, or the retention configuration only saves some execution steps and does not cover complete input and return content.

## How to Verify Successful Configuration
- Log in to the server deployment log page in the FastGPT backend, check whether there are missing alarms for `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy admin token), and confirm that the environment variables are correctly configured.
- Manually trigger a tool call, check whether the return result includes delivery records and qualification attachment data for the corresponding advertising campaign, and verify that the data source matches the business scenario.
- View the tool call execution logs, confirm that the call inputs, execution processes, and return results are fully saved, meeting the retention requirements for compliance logging.
- Test tool calls for different types of compliance documents, such as PDF qualification attachments and structured delivery records, and confirm that the parsing results match the expected format.
