# Code and Change Review Assistance for Advertising Material Audit: Tool Calling and Plugins

## What the data for this category looks like
The data sources for advertising material audit include advertising placement platforms, landing page URLs, product qualification documents, and advertising law compliance clauses. Data updates occur daily or in real time, covering the full lifecycle information of a single placement material. Daily processed documents include advertising material copy, landing page screenshots, audit opinion forms, and modification operation records. Core fields include material content identifiers, placement channel types, violation type tags, modification operation timestamps, and audit conclusions.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
Multi-source and real-time updated data requires tool calling to support frequent pulling of the latest material, landing page, and compliance clause information, to avoid audit deviations caused by expired caches. Diverse document types require plugins to adapt to different input formats such as text, image links, and structured forms, to ensure all types of audit data can be correctly parsed. The audit process for a single material must match real-time pace, so tool calling timeout and concurrency settings must adapt to business peaks. At the same time, the scope of tool calling must be strictly limited to prevent irrelevant operations from triggering compliance risks.

## How to Configure Settings
These configurations are written based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to scenarios where multiple tools are called on demand during advertising material audit, avoiding forced binding to fixed tools |
| `functionCall` | Preset tool list based on audit scenario | Limits the scope of calls to prevent compliance risks from invoking irrelevant tools |
| Single tool call timeout | 15-30 seconds | Matches the real-time data pulling rhythm for updated material data, avoiding audit process blocking due to excessive waiting time |
| Tool call result cache duration | 10-60 seconds | Adapts to daily or real-time updated data sources, balancing data freshness and call efficiency |
| Tool call result verification switch | Enabled | Ensures returned material compliance check results meet advertising law clause requirements |
| Maximum number of tools per single call | Top 5 items | Matches the number of routine check items for single material audit, avoiding slowing down the process by calling too many tools |

## Three Common Misconfigurations
- Phenomenon: The results returned by the application are displayed directly in the conversation interface, and are not passed to the large model as context materials. Cause: The `toolChoice` parameter is not correctly configured to suppress direct output mode, or the associated settings for passing result context are not bound.
- Phenomenon: The chatId carried in API calls cannot be persistently passed in subsequent processes, leading to loss of audit context. Cause: The chatId field is not correctly carried in API request parameters, or the context persistence configuration is not enabled.
- Phenomenon: Detailed internal execution steps and parameter records cannot be displayed in the application call's view details page. Cause: The debug log switch is not enabled, or the detailed execution record collection function is not enabled in the configuration.

## How to Verify Correct Configuration
- Submit a test request containing a single advertising material copy, check whether tool calls are triggered according to preset rules.
- Enter the details page of the application call, confirm that the internal execution steps fully match the configured settings.
- Submit an API call carrying the chatId parameter, check whether subsequent associated audit requests reuse this context identifier.
- View the conversation interface, confirm that the results returned by tool calls are only passed to the large model as context, and are not displayed directly in the conversation.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
