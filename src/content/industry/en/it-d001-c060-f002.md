# Code and Change Review Assistance for Ad Account Opening Audit: Context and Token

## What the Data for This Category Looks Like
Core data for this category comes from ad platform backends, national enterprise credit information public disclosure systems, qualification materials submitted by clients, and industry access rules. Unlike ad material review categories, this category prioritizes data collection focused on advertising subjects and industry qualifications. Daily processed documents include account opening application forms, scanned business licenses, qualification documents for corresponding industries, and historical account opening audit records. Data is updated via daily batch synchronization or real-time submission with individual account opening applications. Document fields associated with each audit include subject name, qualification number, applied industry, audit status, and other items. There are no unified standardized unitized fields. Information is only recorded according to audit process nodes.

## What Constraints Do These Characteristics Impose on the Context and Token Workflow
Document types for ad account opening audits vary widely. They include structured application form fields, as well as unstructured qualification scans and rule text. Differences in data format across sources can cause formatting errors during context concatenation. If the `maxContext` parameter is not configured properly, it is easy to exceed the model's context window limit. The number of materials associated with a single audit is not fixed, ranging from 1 to multiple copies. If token consumption is not reasonably limited, token usage issues will worsen. Qualification data updated in real time requires quick synchronization to the knowledge base. If context recall fails to match the latest data, audit judgment deviations will occur. Industry access rule text is lengthy. If appropriate context segments are not split, token usage will become too high, reducing audit efficiency.

## How to Configure the Settings
This document is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the context window limits of most large models, and adapts to the need for multi-material concatenation in account opening audits |
| `quoteMaxToken` | 1500–2000 characters | Limits token usage for a single qualification or rule text, preventing individual content from exceeding the allocated context quota |
| Context recall limit | Top 6 entries | Controls the number of recalled audit histories and rules, preventing total token usage from exceeding limits |
| Knowledge base real-time sync toggle | Enabled | Adapts to daily or real-time updated qualification data, ensuring context recall uses the latest information |
| Similarity matching threshold | 0.75–0.85 | Filters low-match historical audit records, reducing invalid token consumption |

## Three Common Misconfigurations
- After adjusting the context recall limit, audit results do not associate with the corresponding client's historical account opening records. The `quoteMaxToken` parameter is not configured, causing recalled historical content to be truncated. Complete context association information cannot be delivered.
- Updated industry access rules in the knowledge base are not included in the context recall scope. The real-time sync configuration is not enabled, so recalled content uses outdated rule text. This leads to delayed audit judgment basis.
- After a single audit task is triggered, the system returns a token limit exceeded prompt. The token length of single references is not restricted. Qualification materials with multiple long texts are concatenated, causing total token consumption to exceed the model's context window limit.

## How to Confirm the Configuration Is Properly Set
- View context recall logs. Verify that the number of recalled documents matches the configured recall limit. Confirm that the latest qualification and rule data is included.
- Test uploading long-text qualification materials. Check for token limit exceeded errors. Confirm that the token length of single references meets the configured requirements.
- Simulate a single account opening audit process. Verify that the audit result associates with the corresponding client's historical account opening records. Confirm that context transfer is working normally.
- View knowledge base sync records. Confirm that the real-time sync configuration is active. Ensure that the latest data is included in the recall scope.
