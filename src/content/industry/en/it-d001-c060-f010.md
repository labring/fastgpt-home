# Code and Change Review Assistance for Ad Account Opening Audit: Citation Sources and Traceability

## What the data for this category looks like
Daily processing documents for this category include account opening application forms, business license scans, industry qualification certificates, and account opening audit records. Data sources cover ad platform backends, the National Enterprise Credit Information Publicity System, materials actively submitted by customers, and public industry access rules.
Data updates occur daily or synchronously with each account opening application. Fields for a single audit material include main entity name, unified social credit identifier, industry category, application time, and audit status. Document length and field count adjust dynamically based on submitted materials, with no unified fixed standard.

## What Constraints Do These Characteristics Impose on Citation Sources and Traceability
Mixed use of multiple data sources requires traceability tools to accurately distinguish information from different sources, and prevent confusion between customer-submitted materials and automatically verified data from platform backends.
Dynamic data updates require traceability to support pulling latest data on demand, ensuring timeliness of qualification verification.
Diverse document structures require traceability to adapt to materials in different formats, accurately match field information, and limit data volume to avoid slowing audit processes.
Errors in this category directly impact account opening compliance, so traceability accuracy and traceability requirements are high. Full display of information source paths and update times is necessary.

## Three Common Configuration Mistakes
- Phenomenon: After exporting a workflow and related configurations, importing to another environment causes the traceability plugin to prompt that the specified data source cannot be found. Cause: Associated data source permission configuration was not selected synchronously during export, so the imported environment cannot recognize call permissions for the corresponding data source.
- Phenomenon: A "No permission to operate this conversation record" prompt appears when displaying traceability content. Cause: No access permission rules for traceability content were configured, and the account opening audit specialist's role group was not added to the accessible list.
- Phenomenon: Line breaks entered in the traceability prompt copy do not work, and are displayed as plain text. Cause: The platform-supported rich text line break format was not used, or line breaks entered in plain text mode were not parsed correctly.

## How to Verify Successful Configuration
- Initiate a simulated account opening audit request, check if the traceability result links to the correct data source such as query results from the National Enterprise Credit Information Publicity System, and adjust the maximum citation source token count to fit materials of different lengths.
- Verify that specialists with different roles can access traceability content normally, adjust the access range configuration based on actual role permissions.
- Test the line break effect of the traceability prompt copy, confirm that entered line breaks render correctly as visible line breaks.
- Check the plugin status after importing the workflow, confirm all associated data source configurations were loaded correctly with no error prompts.
