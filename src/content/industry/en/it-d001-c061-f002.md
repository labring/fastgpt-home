# Code and Change Review Assistance for Performance Testing and Capacity Assessment: Context and Token

## What Data for This Category Looks Like
This category of data primarily comes from stress testing platforms, APM monitoring systems, database slow logs, and production traffic baselines. Daily deliverables include stress testing plans, capacity assessment reports, stress testing data records, and optimization suggestion sheets. Data is typically updated once per month or alongside major version releases. Data fields include metrics such as throughput rate, latency values, and resource occupancy rates, with units mostly being QPS, milliseconds, and percentage. Document structures usually center around core modules: metric lists, bottleneck analysis, and capacity conclusions.

## Constraints on Context and Token Processing
Stress testing data comes from multiple dispersed sources, and individual metric datasets are large. This leads to redundant context recall, so token consumption must be limited. Daily document structures are fixed, with key content concentrated in the bottleneck analysis and capacity conclusion modules. If the context recall range is too broad, irrelevant stress testing plan details will be included. Production traffic baselines update alongside business fluctuations, so the time range of the context must be controlled to avoid loading outdated data. Additionally, associated content between optimization suggestion sheets and stress testing reports must be precisely matched to prevent non-core fields from consuming token quota.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Covers total token consumption for a single stress testing report, capacity assessment report, and associated optimization suggestions |
| `quoteMaxToken` | 2000–3000 token | Matches the length of a single quoted content block, preventing single quotes from exceeding model processing limits |
| Keyword splitting control | Retain full content per document module | Avoid splitting key paragraphs such as stress testing metrics and capacity conclusions, ensuring complete context semantics |
| Context recall range | Recent 1 month of stress testing data | Matches data update frequency, filtering outdated historical stress testing records |
| Single search quote limit | Top 6 entries | Core associated entries for stress testing-related documents typically do not exceed 6, reducing redundant token usage |

This configuration applies to FastGPT v4.17.0.

## Three Common Configuration Errors
- Symptom: After setting `quoteMaxToken` to 2000 token, a single response still exceeds 3000 token. Cause: The total upper limit of `maxContext` was not adjusted synchronously. The cumulative token of single quotes exceeds the overall context limit.
- Symptom: Context is lost during continuous conversations, and prior stress testing metric discussions cannot be associated. Cause: Context retention configuration was not enabled, or `maxContext` was set too small, causing early content to be automatically cleared.
- Symptom: Key stress testing metric paragraphs are split, leading to broken context semantics. Cause: Keyword splitting rules were not configured. The system splits all document content by default, breaking the association between metrics and conclusions.

## How to Verify Correct Configuration
- Upload a complete stress testing report and associated optimization suggestion sheet, check the range of context content recalled by the system, and confirm it matches the preset recall range.
- Trigger a simulated code change review request, check the token consumption of the returned content, and confirm it does not exceed the preset `maxContext` upper limit.
- Check the splitting results of key documents in the knowledge base, confirm that core paragraphs such as stress testing metrics and capacity conclusions were not split.
- Initiate a continuous conversation, verify that prior stress testing metric discussions are correctly associated by the system, and confirm that the context retention configuration is active.

The configuration values provided are common starting points, and should be validated against local samples.
