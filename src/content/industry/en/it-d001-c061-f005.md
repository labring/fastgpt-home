# Code and Change Review Assistance for Performance Testing and Capacity Evaluation: Multi-turn Dialogue and Prompt Engineering

## What data for this category includes
Data for this category primarily comes from pressure testing platforms, APM monitoring systems, database slow logs, and production traffic baselines. Daily produced documents include pressure testing plans, capacity evaluation reports, pressure testing data records, and optimization suggestion sheets. Data update frequency is monthly or when major versions are released. Typical fields include throughput rate, latency, resource usage rate, capacity margin, and more. Corresponding units are typically TPS, milliseconds, percentage, core count, and various storage capacity units.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
Data sources are scattered and include multiple types of professional metrics. Multi-turn dialogue is required to gradually align review data from different sources. Update frequency is relatively fixed, but latest pressure testing results must be synchronized promptly after changes. Prompts must support regular pulling of updated document content. Document structures are scattered and include professional terminology. Multi-turn dialogue is needed to sort out the logical relationships between different documents. Fields have specific units. Prompts must explicitly require retaining units to avoid indicator confusion. The review process focuses on pressure testing model design, bottleneck identification, and conclusion review. Multi-turn dialogue must guide engineers to gradually break down these core steps.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Documents related to performance testing and dialogue history are typically long. They need to cover complete review context and adapt to the context processing logic of FastGPT v4.17.0 |
| `variables` | Bind up to 5 core indicator variables | Avoid excessive variables causing confusion in dialogue logic. Focus on core review indicators such as throughput and latency |
| `messages` | Retain the last 10 rounds of dialogue history | Dialogue for code and change review typically covers the complete review process within 10 rounds |
| Prompt thesaurus matching | Enable and import the pressure testing terminology thesaurus | Improve recognition accuracy for professional terms such as TPS and latency thresholds |
| Input guidance configuration | Preset "Please analyze the impact of changes combined with pressure testing data and capacity reports" | Clarify dialogue direction and guide alignment of review goals |
| `chatId` | Bind the exclusive ID of the review session | Distinguish review dialogues for different changes and avoid context confusion |

## Three Common Mistakes
- Phenomenon: When calling the API to generate review results, the last variable value in the output will overlay the calculation result of the previous variable. Cause: The variable scope of different rounds is not isolated in the `variables` configuration, causing the dialogue context to not be reset correctly.
- Phenomenon: After configuring input guidance and a professional thesaurus, the preset guidance question does not appear in the dialogue interface. Cause: The enable switch for input guidance is not turned on, or the thesaurus is not correctly associated with the current application's prompt configuration.
- Phenomenon: After uploading an XLSX format pressure testing data file to the knowledge base, the dialogue cannot repeat the table content in the file. Cause: The structured parsing plugin for XLSX files is not enabled, or the prompt does not explicitly require reading table data.

## How to Confirm Configuration is Correct
- Initiate a test dialogue, input "Please sort out the pressure testing impact of this change", check if the reply automatically associates preset thesaurus terms.
- View the application's configuration page, confirm that the indicator variables bound by `variables` match the current review scenario.
- Upload a test XLSX pressure testing file, initiate a dialogue requesting repetition of the content, check if table fields can be read correctly.
- View the workflow run log, confirm that the historical rounds of `messages` do not exceed the preset retention limit.
