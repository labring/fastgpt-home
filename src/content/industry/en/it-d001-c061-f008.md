# Code and Change Review Assistance for Performance Testing and Capacity Evaluation: Workflow Orchestration

## What the data for this category looks like
The data for this category mainly comes from stress testing platforms, APM monitoring tools, database slow query logs, and production traffic baselines. Daily produced documents include stress testing plans, capacity evaluation reports, stress testing data records, and optimization suggestion sheets. The data update frequency is once per month or after each major software version release. Fields include throughput (unit: tps), request latency (unit: milliseconds), server resource usage rate, capacity thresholds (unit: GB or cores), and other metrics. Consistency of field mapping must be maintained across different documents.

## What constraints these characteristics impose on the "workflow orchestration" link
Since data sources cover multiple types of heterogeneous systems, workflow orchestration requires configuring multiple data source pull nodes and unifying field mapping rules to avoid indicator statistical deviations. The data update frequency is not high, so the workflow must support versioned configuration to adapt to data source changes after monthly cycles or major version updates. The document structure includes multiple types of reports, so the workflow must associate document storage and retrieval nodes to extract key performance indicators for verification. At the same time, core links take a long time, so the workflow must add manual review nodes to ensure the accuracy of capacity conclusions.

## Three Common Misconfigurations
- Symptom: When editing a workflow in FastGPT v4.17.0, a parameter verification failure prompt pops up after saving. Cause: The threshold format for `variables` is not configured correctly, and non-numeric content is used.
- Symptom: When running the workflow, the tps statistics result for stress testing data is empty. Cause: The production traffic baseline data source is not bound, so no baseline tps can be obtained as a comparison reference.
- Symptom: When invoking an advanced orchestration workflow, preset performance indicator thresholds are not loaded. Cause: The configured `variables` parameters are not saved to the workflow's global variables, causing subsequent nodes to fail to read them.

## How to Confirm the Configuration is Complete
- Check the configuration of all data source nodes to confirm that the stress testing platform, APM monitoring, and other corresponding data sources have been bound.
- View the workflow's global variable list to confirm that performance indicator thresholds and production traffic baseline data have been preset in `variables`.
- Run the workflow's debug mode to verify that the output data of each node matches the expected stress testing indicators.
- Trigger the scheduled task to confirm that the workflow automatically executes according to the set cycle and generates a capacity evaluation report.
