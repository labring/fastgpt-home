# Code and Change Review Assistance for Performance Testing and Capacity Evaluation: Citation Sources and Traceability

## What data for this category looks like
Data for this category primarily comes from pressure testing platforms, APM monitoring systems, database slow logs, and production traffic baselines. Update frequency is typically monthly or after major version releases. Daily deliverables include pressure testing plans, capacity evaluation reports, pressure testing data records, and optimization suggestion sheets. Data fields include dedicated performance metrics such as throughput (tps), request latency (milliseconds), and server resource utilization (percentage). Field formats and units are consistent across different documents to support cross-document correlation analysis.

## What constraints these characteristics impose on the citation sources and traceability process
Because data sources are scattered and update cycles are long, citations must be accurately linked to the corresponding batch of pressure testing records and monitoring data to avoid mixing data across cycles. The category-specific performance metric fields require that traceability information retains both field names and units, otherwise bottleneck identification and capacity conclusion reviews during reviews cannot be supported. Additionally, due to large data volume and fixed structure, citation quotas must adapt to the total length of single-batch pressure testing data, otherwise critical indicators may be truncated and affect review accuracy.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Adapts to the total character count of a single batch of pressure testing reports and associated monitoring data, preventing critical performance metrics from being truncated |
| `responseData` | Includes tps, latency, and resource utilization fields | Ensures returned citation data only contains category-specific performance metrics, filtering out irrelevant content |
| `detail` | Enable full traceability mode | Retains the original document ID, generation time, and source platform information for cited data to meet traceability requirements |

## Three Common Mistakes
- Symptom: The number of performance data citations in review results is insufficient, and some critical metrics are missing. Cause: The `quoteMaxToken` configuration was not adjusted based on the category’s data volume, leading to insufficient token quota and truncated data.
- Symptom: After re-uploading pressure testing data records, duplicate historical pressure testing entries still appear in knowledge base citations. Cause: Deduplication checks were not enabled in the knowledge base synchronization process, leading to duplicate associations between old and newly uploaded data.
- Symptom: The original pressure testing platform and generation time for cited data cannot be traced in review logs. Cause: The `detail` parameter was not configured to enable full traceability, and only simplified content fragments were returned.

## How to Confirm Proper Configuration
- Start the FastGPT v4.17.0 App/Admin server. Check that the environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, formatted as http://aiproxy:3000, do not append paths like /v1) and `AIPROXY_API_TOKEN` (AI Proxy admin token, must match the AI Proxy server configuration and be non-empty) are correctly configured, with no startup validation errors.
- Send a dialogue request for performance review, and verify that the returned results include the performance metric fields specified in `responseData`.
- Review the traceability information for each cited data entry, confirming that all include the original document ID, generation time, and source platform identifier.
- Adjust the value of `quoteMaxToken` and verify that the number of returned cited data entries changes with the configuration.
