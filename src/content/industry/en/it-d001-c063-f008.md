# Code and Change Review Assistance for Campaign Setup: Workflow Orchestration

## What the Data for This Category Looks Like
This category's data typically comes from advertising platform APIs, user profile databases, internal budget spreadsheets, and attribution tools. Daily produced documents include campaign plans, targeting setting rules, budget scheduling tables, and conversion tracking configuration items. Fields cover targeted audience identifiers, budget values, conversion event codes, delivery time parameters, and more. Data update frequency is mostly daily refresh, or triggered by the launch of a single advertising campaign. Documents are primarily presented as structured tables and configuration item lists.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Decentralized data sources and flexible update rhythms require the workflow to support parallel pulling of multiple data source nodes, adapting to response delays of different interfaces. The structured nature of documents requires workflow configuration field validation nodes to verify the legality of core fields such as targeting, budget, etc., to prevent invalid configurations from entering the review phase. The most time-consuming links of audience targeting, budget allocation, and conversion verification need to be split into independently reviewable nodes, ensuring that each link can block anomalies individually. There is no fixed mandatory cycle for data updates, so the workflow must support dual configuration logic of event-triggered and scheduled triggering. At the same time, failure rollback and alert nodes must be configured to address issues such as budget waste and failed campaign launch.

## How to Set the Configuration
This configuration is written based on the workflow orchestration feature of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Condition | Event launch time + daily scheduled triggering | Matches the campaign cycle and daily update rhythm of category data |
| Context Window Size | Previous 3 historical configuration records | Fits the fast and concise review scenario of campaign plan documents |
| Node Timeout Threshold | 600 seconds | Covers the time requirements of multi-data source pulling and verification |
| Variable Mapping Rule | Bind data source fields via the `variables` field | Ensures accurate correspondence between configuration items and actual business data |
| Review Node Trigger Logic | Trigger when budget field is empty | Block invalid campaign plan configurations |
| Maximum Retry Count | 2 times | Prevent workflow interruptions caused by temporary interface fluctuations |

## Three Common Mistakes
- Attempting to configure external page jump logic directly in workflow nodes, which causes workflow execution interruptions. This is because workflow orchestration only supports data processing and review node configuration, and does not support front-end page interaction operations.
- Setting the context count to 0 in the workflow, which causes the review node to fail to obtain historical configuration comparison references and leads to configuration deviations. This is because the role of the context window for passing historical review references is not understood.
- Not configuring timeout handling logic for workflow nodes. When an advertising platform interface has response delays, a timeout error is triggered, causing workflow execution interruptions. This is because a timeout threshold and retry mechanism are not set for the time-consuming scenario of multi-data source pulling.

## How to Confirm the Configuration Is Correct
- Trigger a test workflow, and check whether budget, targeting, and other data source fields are correctly pulled in the node logs.
- Submit a test campaign plan containing invalid budget values, and verify whether the review node can correctly block the plan and trigger an alert.
- Check the workflow's trigger configuration to confirm that it matches both the event launch time and daily scheduled triggering conditions.
- Review the binding relationship of the `variables` field to confirm that the mapping between business data and configuration items is accurate.

All provided configuration values are common starting points, and should be evaluated against the reader's own samples.
