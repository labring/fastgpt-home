# Code and Change Review Assistance for Campaign Setup: Citation Sources and Traceability

## What the Data for This Category Looks Like
Core data for campaign setup work comes from advertising platform APIs, user profile datasets, offline budget scheduling tables, and attribution tool logs. Data update cycles typically refresh daily, or trigger updates with individual campaign launches. Daily produced documents include campaign summary sheets, targeting setting details, budget scheduling breakdowns, and conversion tracking configuration tables. Fields include audience package unique identifiers, budget amounts, conversion event codes, and delivery time intervals. There is no unified cross-document field naming convention.

## How These Characteristics Impact Traceability and Citation Requirements
The multi-source data nature requires the traceability link to associate unique identifiers across different data sources. For example, map audience package IDs returned by advertising platforms to package identifiers in user profile datasets, to avoid field confusion across sources. Daily or campaign-level update cycles require the traceability time range to match the active period of the current campaign. Expired historical configurations cannot be traced. The diversity of document structures requires citations to explicitly specify corresponding document field mappings. For example, distinguish between the amount field in budget scheduling tables and the event field in conversion tracking tables. Configuration errors can lead to budget waste or failed campaign launches. Therefore, traceability must ensure every cited content accurately links back to the original document and data source.

## How to Configure Settings
These configurations are compatible with FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average single-page content length of campaign setup documents, to avoid truncating critical targeting or budget configuration fields |
| `responseData` | Return only knowledge base matching results | Ensures output content comes entirely from the original text of knowledge base question-answer pairs, with no AI-generated supplementary content |
| `detail` | Enabled | Retains traceability-required data source identifiers, document paths, and field mapping information, to facilitate linking back to original campaign setup documents |
| Single search limit | Top 3 results | Matches the number of valid data sources updated daily, to avoid introducing irrelevant historical campaign configurations |
| Maximum context | 600 seconds | Matches the execution cycle of a single campaign, to align with campaign-level data update rhythms |

## Three Common Configuration Mistakes
-  When configuring `responseData`, fail to enable the return-only-matching-results rule. The symptom is that output content includes AI-generated statements outside the knowledge base. The interface displays results without citation markers for matching documents. The cause is incorrect restriction of the return scope, allowing the model to generate additional content.
-  Fail to enable the `detail` parameter. The symptom is that output results lack traceability metadata such as data source identifiers or document paths. It is impossible to link back to original campaign setup documents via identifiers. The cause is failure to retain necessary traceability field information.
-  Set the single search limit beyond the valid data range of the current campaign. The symptom is that output results include expired historical configuration content, such as decommissioned audience package IDs. The cause is failure to match the daily or campaign-level data update rhythm, introducing invalid data not tied to the current campaign.

## How to Verify Proper Configuration
-  Initiate a test query containing specific campaign setup configurations. Check whether output content comes entirely from the original text of knowledge base question-answer pairs, with no extra generated statements.
-  Review the metadata area of the output results. Confirm that it includes traceable field information such as data source identifiers and document paths.
-  Adjust the single search limit to a smaller value. Verify that output results only match campaign setup data within the current campaign range.
-  Test queries for long-text campaign setup content. Confirm that the `quoteMaxToken` setting does not truncate critical configuration fields.

The values provided here are common starting points. They should be evaluated against the applicable samples for the specific use case.
