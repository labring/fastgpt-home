# Code and Change Review Assistance for Tender Document Preparation: Workflow Orchestration

## Data for This Category
The core documents for this category are tender documents, qualification certificates, commercial deviation tables, and technical deviation tables. Data sources include tender announcements, tender documents, enterprise qualification databases, and supplier quotations. The update frequency is once per tender. Data fields adjust dynamically based on tender requirements, and include bid section information, qualification levels, quotation details, clause response items, and other content. There is no fixed unified global structure, and data must be generated and validated in accordance with the specific requirements of each tender task.

## Constraints on Workflow Orchestration
Since data sources and content change dynamically for each tender task, workflows must support one-time temporary orchestration, and cannot reuse fixed templates. Document structures have no unified standards, so workflow nodes must adapt to different types of tender documents, and require parameter binding to implement differentiated processing. Data validation links directly relate to bid rejection risk, so workflows must be configured with mandatory validation nodes to ensure that qualifications, clauses, and other content meet tender requirements. Additionally, single-task data volume is limited, so workflow node chains should not be overly long to avoid timeouts or resource waste.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Clause paragraph lengths of tender documents mostly fall within this range, adapting to the splitting needs of item-by-item clause responses |
| Single Search Limit | Top 5 entries | The number of valid qualification entries in tender announcements is limited, too many entries will increase review burden |
| Maximum Context | 15000 token | Total character count of a single tender document corresponds to this token range, avoiding context overflow |
| `variables` Trigger Rule | Trigger based on the bid section field of the tender announcement | Tender requirements vary across different bid sections, use `variables` to bind bid section parameters for differentiated orchestration |
| Validation Node Timeout | 600 seconds | Qualification material verification requires traversing enterprise qualification database data, reserving sufficient query time |
| `nodeId` Mapping Rule | Bind node IDs by document type | Distinguish processing nodes for qualification certificates and deviation tables to avoid logical confusion |

## Three Common Configuration Mistakes
- After private deployment, the workflow editing interface fails to open, and a client application error is displayed. The cause is that local network permissions restrict the loading path of workflow front-end resources for FastGPT v4.17.0, and intranet port mapping is not enabled.
- Using Qwen2.5 (deployed via Ollama) cannot implement tool calling, and the workflow test asking for the current time has no response. The cause is that the workflow node is not correctly bound to the `variables` parameter, and the model's tool calling permission is not configured.
- After classifying by question in the workflow, different knowledge base results cannot be processed uniformly, and subsequent logic cannot be reused. The cause is that a unified processing node is not bound via `nodeId`, causing classified branches to not point to the same logic module.

## How to Verify Correct Configuration
- Launch the FastGPT v4.17.0 workflow test, upload the tender document for the corresponding bid section, and check whether nodes trigger different branches based on bid section parameters.
- Simulate the qualification material verification link, and check whether the wait or error prompt is triggered according to the configured timeout period.
- Trigger the workflow context clearing operation, and verify that branches after the classification node uniformly call the same processing logic.
- Access the workflow editing interface in the intranet environment, and confirm that no client error pop-ups appear.
