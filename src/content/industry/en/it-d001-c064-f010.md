# Code and Change Review Assistance for Tender Document Preparation: Citation Sources and Traceability

## What data for this category looks like
Data for this category comes from tender announcements, tender documents, enterprise qualification databases, and supplier quotations. The update frequency is once per order. Daily output documents include tender documents, qualification certificates, business deviation tables, and technical deviation tables. Core fields include tender clause number, qualification validity period (unit: day), quotation amount (unit: yuan), response content, and more. Fields must strictly match the format specified by the tenderer. No universal standardized fields exist, and matching rules must be adjusted for each round of tendering.

## What constraints do these characteristics impose on the citation sources and traceability link?
Data updates per order and must strictly match the tenderer’s format. Citation traceability must accurately link specific clauses of the current tender to their corresponding data sources. General traceability rules from historical orders cannot be reused. When calling multiple data sources simultaneously, source identifiers for qualification databases, quotation data, and tender documents must be clearly distinguished. This avoids mixing content from different suppliers or tender clauses. The lack of universal standard fields requires the traceability link to support custom field matching. Traceability results must directly correspond to specific paragraphs of the original document to meet bid rejection risk prevention requirements.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the token calculation rules of FastGPT v4.17.0 and the average length of single clauses in tender documents, to avoid truncating valid traceability content |
| `responseData` | Return fields including source document ID and paragraph position | Enables quick location of corresponding paragraphs in original tender or qualification documents, facilitating subsequent verification |
| `detail` | Enabled | Returns full context of traceability content, enabling reviewers to verify the accuracy of clause responses |
| Single search limit | Top 3–5 results | Controls the number of recalled results to avoid excessive redundant information interfering with clause review |
| Maximum context | `5000–7000 characters` | Carries core clauses of the current tender and key content from corresponding data sources, to avoid exceeding model context limits |
| Reranking | Calibrated based on actual testing | Optimizes the sorting priority of recalled results for clause similarity matching in tender documents |

## Three common configuration mistakes
- Variable reference with no selectable values during knowledge base search: The dropdown menu has no variable options for tender document fields. This occurs because category-specific tender document field variables are not defined in system variable configuration or upstream node outputs.
- Runtime error: Cannot redefine property: toString: A specified error message appears on the interface. This occurs because the toString method is repeatedly defined in a custom code block, conflicting with FastGPT’s built-in logic.
- Unexpected number of traceability results: Returned traceability content is fewer or more than the preset quantity. This occurs because the `quoteMaxToken` configuration value is unreasonable, causing recalled content to be truncated or exceed context limits.

## How to confirm proper configuration
- Manually input a specific clause from the current tender. Returned results are checked for clear source annotations, including the name and paragraph position of the corresponding document.
- Access the knowledge base search configuration interface. The variable reference dropdown is checked for exclusive field options for data sources such as tender documents and enterprise qualification databases.
- Review FastGPT runtime logs. Traceability information returned in the `responseData` field is verified as complete, with no missing or truncated content.
- Submit a traceability request for a single qualification material. Results are verified to link to corresponding entries in the enterprise qualification database, with no field mismatch issues.
