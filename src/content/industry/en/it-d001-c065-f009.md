# Code and Change Review Assistance for Interface Integration and Data Docking: Tool Calling and Plugins

## What data for this category looks like
Data for this category primarily comes from customer system interfaces, API documentation, test data, and integration logs. Four types of documents are maintained regularly: interface lists, integration records, field mapping tables, and issue tracking tables.
Interface lists include interface endpoints, request methods, parameter fields, and return formats. Integration records track call sequences, response codes, and latency. Field mapping tables correspond to differences in field definitions between the two systems. Issue tracking tables record exceptions and repair solutions encountered during integration.
Data update frequency is daily or full synchronization before each phase delivery, and is adjusted dynamically alongside integration progress.

## What constraints do these characteristics impose on the tool calling and plugins workflow
Data sources for interface integration and data docking are scattered and updated dynamically as integration progresses. This requires tool calling to pull the latest interface metadata and integration logs to avoid using expired data.
Field mapping tables have significant differences in field definitions, so plugins must support extracting and aligning fields across multiple systems, and tool calling must bind the mapping rules for the current integration phase.
Integration logs have strong temporal correlation, so tool calling must associate troubleshooting links via request IDs, and the context scope must be limited to documents from the current phase to avoid introducing irrelevant data.
Additionally, data updates occur daily or per phase, so the tool calling cache period must match the update rhythm to ensure data timeliness.

This configuration applies to FastGPT v4.17.0.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call timeout | 300–600 seconds | A single interface integration troubleshooting session typically includes multiple rounds of request and response, this duration covers complete link analysis |
| `toolChoice` | auto | Automatically adapts to the current integration's interface types and calls corresponding validation plugins automatically |
| `functionCall` | Bind specified toolchain | Lock the current phase's interface list and field mapping table plugins to avoid calling irrelevant tools |
| Plugin context scope | Past 1 day of integration logs + current interface list | Limit data source scope to avoid outdated integration records |
| Field extraction precision | Calibrate based on actual testing | Adapt to different customer system return formats and accurately extract target field parameters |
| Retry count | 2–3 times | Handle temporary exceptions in interface calls and avoid terminating the integration flow due to a single failure |

## Three common errors
- Symptom: No output appears in the dialog after tool calling completes, results are only displayed after refreshing the page, and no structured tool call data is returned. Cause: Mandatory binding for `functionCall` is not configured, so tool call results are not synchronized to the current conversation context.
- Symptom: When using the code running plugin, specified fields cannot be extracted from interface-returned JSON, and Python runtime support is not provided. Cause: Plugin language adaptation rules are not configured, only the JavaScript runtime environment is bound.
- Symptom: After entering correct chart generation parameters, the basic chart plugin outputs `none` and does not generate the expected chart URL. Cause: The plugin context scope does not include integration test data, and the data source required for chart generation is missing.

## How to confirm the configuration is correct
- Initiate a simulated interface call and check if the tool call result is displayed directly in the chat window without refreshing the page.
- Configure the Python runtime environment, attempt to extract specified fields from interface-returned JSON, and verify that the plugin supports the target language.
- Enter valid chart generation parameters and check if the plugin returns a URL result in the correct format.
- View the tool call log to confirm that the called tool matches the toolchain for the current integration task.

The values provided here are common starting points and should be evaluated against samples relevant to the specific deployment.
