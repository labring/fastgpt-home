# Code and Change Review Assistance for Interface Integration and Data Docking: Citation Sources and Traceability

## What the data for this category looks like
The core data for this category comes from client system interfaces, API documentation, test data, and integration logs. Daily maintained documents include interface lists, integration records, field mapping tables, and issue tracking tables. Interface lists contain fields such as interface identifiers, request paths, and parameter rules. Integration records mark call times and return codes. Field mapping tables record the correspondence between business fields and interface fields. Data update frequency is mostly daily or per project phase. Data structure is dynamically adjusted with interface iterations.

## What constraints these characteristics impose on the citation sources and traceability link
Since data sources are scattered and formats are inconsistent, the traceability link must accurately match identifier fields across different data sources to avoid confusing call records from different interfaces. Data update frequency is not fixed, so the update time of data sources must be marked synchronously to ensure traceability accuracy. The field structures of daily documents vary, so dedicated association rules must be set for different document types such as interface lists and integration logs. Additionally, this category involves ongoing inter-system interaction, so traceability must cover the complete call chain. A single result fragment is insufficient to support troubleshooting needs.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `quoteMaxToken` | 1000–1500 token | Adapts to the length of parameters, logs, and mapping table content in interface integration scenarios |
| `responseData` | Enabled | Required to fully retain raw interface return data for exception troubleshooting and alignment of data specifications |
| `detail` | Full | Covers all details of call chains, field mappings, and return codes |
| Traceability Association Scope | Interface lists, integration logs | Matches the core data sources maintained daily for this category |
| Source Update Tag | Daily / Per Phase | Aligns with the actual data update rhythm of this category |

## Three common configuration mistakes
- Symptom: Variable references fail after selecting a knowledge base in the knowledge base search card. Cause: The dedicated data source for the interface integration scenario (such as interface lists, integration logs) is not associated, and only the general knowledge base is called.
- Symptom: An error occurs when viewing knowledge base citations in chat responses. Cause: The `responseData` configuration is not enabled, so the raw interface return data cannot be traced, resulting in a broken reference link.
- Symptom: Knowledge base search reference content is forcibly included in responses. Cause: Unnecessary general data source associations are not disabled, and irrelevant document libraries are incorrectly bound.

## How to confirm the configuration is correctly applied
- Import dedicated data sources such as interface lists and integration logs, and check whether citation sources automatically associate the identifier fields of corresponding documents.
- Initiate a simulated interface call, and check whether the traceability information of the returned result includes key fields such as call time and return code.
- Adjust the `quoteMaxToken` parameter, and verify whether long content references are fully retained or truncated according to rules.
- Confirm that the currently used FastGPT version is v4.17.0 to ensure configuration items are compatible with the current system version.
