# Code and Change Review Assistance for Search Ad Keyword Management: Context and Token

## What the data for this category looks like
Core data for search ad keyword management comes from search ad backends, search term reports, bid ranking data, and landing page data. Daily processed documents include keyword lists, negative keyword tables, bid records, and search term reports. Data fields include keyword text, match type, bid amount, search volume, conversion cost, and more. Some documents exist as bulk structured tables. Data updates occur daily or weekly. SEM optimizers, agency operations staff, and brand marketing personnel maintain these documents daily. These documents support core tasks including keyword expansion, negative keyword screening, and bid matching adjustments.

## What constraints do these characteristics impose on context and token workflows
The structured bulk data characteristics of the search ad category require context and token configurations to adapt to multi-field text length and high-frequency update properties. A single keyword or search term record, plus metadata, uses a fixed amount of tokens. Bulk recalled historical data quickly consumes context quotas. Without proper control, model context limits will be exceeded, leading to review failures. Data updates occur at a high frequency. Context must synchronize the latest bid and negative keyword information regularly. Using outdated data for reviews produces inaccurate results. Category data has strong professional specificity. Irrelevant general knowledge can interfere with review results. It is necessary to strictly limit the recall scope of context to avoid invalid token usage.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Max context token count | 8000–12000 token | Adapts to the total length of search ad bulk documents, avoids exceeding the model context limit of FastGPT v4.17.0 |
| Max single reference token | 300–500 token | Matches the length of a single keyword, negative keyword, or search term record plus metadata, ensures complete reference content |
| Context refresh interval | Daily | Matches the daily update frequency of search ad data, ensures reviews use the latest bid and negative keyword data |
| Recalled content scope | Only the current project’s keyword list, negative keyword table, and bid records | Defines retrieval boundaries, reduces irrelevant data token usage, improves review accuracy |
| Professional term optimization | Enabled | Adapts to search ad professional terminology, reduces invalid token usage, improves context matching efficiency |

## Three common misconfigurations
- After adjusting the context quota, review requests do not load the current project’s keyword management data, and instead introduce irrelevant general knowledge. This occurs because the recalled content scope is not limited, leading the retrieval range to cover non-target category documents.
- After configuring the max single reference token limit, review content for long keywords is truncated. This occurs because the max single reference token value is set too small, and does not match the actual length of keywords plus metadata such as match type and bid amount.
- Review results remain unchanged after waiting more than one week. This occurs because the context refresh interval is set too long, and does not match the daily update frequency of search ad data, leading to reviews using outdated data.

## How to confirm configurations are properly set
- Upload a test keyword list or negative keyword table, submit a review request, and confirm that the recalled context content only includes the uploaded document data, with no irrelevant general information.
- Enter a long keyword review request that includes complete metadata, and confirm that the returned content is not truncated, and that the single reference token usage falls within the configured range.
- Wait for one full update cycle, submit a review request that includes the latest bid adjustments, and confirm that the results include the latest bid data.
- Check the context token usage metrics, confirm that the usage does not exceed the configured max context token count, and that no overflow errors appear.

The values provided are common starting points, and should be evaluated against the reader's own samples.
