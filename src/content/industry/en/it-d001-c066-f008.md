# Code and Change Review Assistance for Search Ad Keyword Management: Workflow Orchestration

## What Data for This Category Looks Like
Core users of this category are SEM optimizers, agency operations staff, and brand marketing personnel. Four core daily work documents are keyword lists, negative keyword tables, bid records, and search term reports. Data comes primarily from search ad backends, search term reports, bidding ranking data, and landing page data, with daily or weekly update frequencies. Document fields include keyword text, matching mode, single bid, click volume, conversion cost, and more. Units include RMB, times, yuan per conversion, and others. Field names vary slightly across different data sources.

## What Constraints These Characteristics Impose on Workflow Orchestration
Since data sources for this category are scattered and field names have slight differences, cross-data source field alignment nodes must be configured for workflow orchestration to uniformly process keyword and bid data exported from different search ad backends. As data updates occur daily or weekly, the workflow must support two trigger modes — scheduled triggering or file upload triggering — to adapt to daily batch processing needs. Structural differences among the four core documents require the workflow to set up multiple file parsing branches to separately process input files of different types such as keyword lists and negative keyword tables. Numeric fields with units require additional configuration of format verification nodes to avoid calculation errors caused by unit mismatches. Additionally, as a code and change review assistance scenario, the workflow must include a keyword comparison step before and after changes to ensure adjusted content complies with preset rules.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Scheduled trigger (every 12 hours) / File upload trigger | Adapts to daily/weekly updated data processing rhythm, matches daily batch processing needs |
| `variables` | Preset global variables such as keyword matching modes, bid units | Unifies field verification standards across data sources, reduces format conflicts |
| Multi-file parsing branches | Assign corresponding parsing nodes by document type | Adapts to the different structural requirements of the four core documents |
| Context retention rounds | Previous 3 conversation rounds | Balances information completeness and processing efficiency for AI calls, aligns with short conversation processing scenarios |
| Node timeout period | 600 seconds | Adapts to the time consumption requirement of batch processing large volumes of keyword data, avoids mid-execution interruptions |
| File upload size limit | Single file no larger than 1000 MB | Matches the size range of daily exported ad data files |

## Three Common Configuration Mistakes
- Symptom: After configuring a file upload node in the workflow, calling the document parsing tool returns an invalid path error. Cause: The `CUSTOM_READ_FILE_URL` environment variable is not configured correctly, causing the tool to fail to read the storage path of uploaded files.
- Symptom: When triggering the workflow multiple times with the same ID, the context retention rounds for AI calls do not match expected results. Cause: The session identification parameter is not bound via `variables`, causing different calls to reuse the same context cache.
- Symptom: When batch processing keyword lists, unit verification for some fields does not take effect. Cause: Unit verification rules are not preset in global variables, causing field formats across data sources to remain ununified.

## How to Verify Proper Configuration
- Trigger test: A test negative keyword table is manually uploaded. Whether the workflow automatically starts and generates parsing results is verified.
- Variable verification: Test parameters are added to the application link. Whether the workflow's `variables` correctly receive incoming values is verified.
- Timeout test: Batch processing of 1000 keyword entries is simulated. Whether the workflow completes execution within 600 seconds without interruptions is verified.
- Context test: The workflow is triggered twice with the same ID. Whether the context of the second call conforms to the preset retention rounds is verified.

The values provided are common starting points and should be measured against the reader's own samples.
