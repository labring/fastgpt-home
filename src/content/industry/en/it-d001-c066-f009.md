# Code and Change Review Assistance for Search Ad Keyword Management: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category originates primarily from search ad backends, search term reports, bidding ranking data, and landing page data. Daily generated documents include keyword lists, negative keyword tables, bid records, and search term reports. Fields include keyword text, matching mode, bid unit, search volume, conversion association identifiers, and more. Data updates run on daily or weekly cycles. The number of entries per document varies based on account scale. Core fields are all text or numeric types, with no complex nested structures.

## Constraints Imposed on Tool Calling and Plugins
Since data for this category consists mostly of structured text and numeric entries with fixed update cycles, tool calling must adapt to batch retrieval and incremental synchronization scenarios. It must avoid overloading single requests. Daily document fields are relatively fixed. Plugins must explicitly match specified fields such as keywords, matching modes, and bids. They cannot support parsing of non-standard fields. The change review process requires comparing current and historical keyword configurations. Tool calling must link to historical data interfaces. It must also handle call rate limits from ad backend interfaces to prevent triggering account risk controls. The multi-platform nature of data sources requires plugins to support interface adaptation for different ad backends. It must avoid hard-coding request logic for a single platform. Plugins must also adapt to the most time-consuming scenarios for this category, such as keyword expansion and negative keyword filtering, to improve review efficiency.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `{"type": "function", "function": {"name": "keyword_review"}}` | Mandatorily specify calling the dedicated keyword review tool, prevent the model from selecting unrelated tools autonomously |
| `functionCall` | Enable forced function calling | Ensure the return format of tool calling meets the structured parsing requirements for change reviews |
| Tool calling timeout | 300 seconds | Match the average response duration of ad backend interfaces, avoid call failures caused by interface delays |
| Batch request batch size | First 20 entries | Match the typical entry scale of a single keyword list, prevent single requests from exceeding interface capacity limits |
| Plugin data field mapping | Match keyword, matching mode, bid amount | Adapt to the standard field structure of documents for this category, ensure accurate parsing results |
| Authentication method | Use application API Key | Follow FastGPT authentication specifications, avoid mixing with AI Proxy admin tokens corresponding to `AIPROXY_API_TOKEN` |

## Three Common Misconfigurations
- A model returns an error stating that function calling is not supported when calling a tool, but the application configuration test runs normally. The cause is incorrect setup of the `toolChoice` parameter, or the model channel configuration does not use a model that supports function calling.
- Keyword data pulled by the tool is missing the matching mode field. The cause is that the plugin's field mapping configuration does not cover the standard fields for this category, or the field names returned by the ad backend interface do not match the mapping rules.
- Interface rate limiting is triggered during batch tool calls. The cause is that the batch request batch size is set too large, exceeding the interface call rate limit of the ad backend.

## How to Verify Proper Configuration
- Check the App/Admin server environment variables for FastGPT v4.17.0. Confirm that `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN` are correctly configured, and that no duplicate entries exist in the application configuration.
- Run a tool calling test. Verify that the returned results include standard fields for this category such as keywords, matching modes, and bid amounts. Confirm the format meets preset function calling requirements.
- Simulate a change review scenario. Submit batch keyword data. Confirm that the response duration of tool calling meets the preset timeout threshold, and no frequent rate limiting errors occur.
- View FastGPT system logs. Confirm that the application API Key is used in the request headers for tool calling. Do not use AI Proxy admin tokens corresponding to `AIPROXY_API_TOKEN`.
