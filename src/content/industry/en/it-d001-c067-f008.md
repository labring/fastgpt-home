# Code and Change Review Assistance for Data Security Classification and Grading: Workflow Orchestration

## What the data for this category looks like
This category of data mainly comes from data asset inventory results, database metadata, business system documentation, and publicly available regulatory documents. Daily produced documents include data catalogs, classification and grading rule tables, important data identification lists, and review minutes. Data is updated quarterly or triggered by business system changes. Data fields include asset identifiers, sensitivity levels, owning departments, compliance requirements, etc. There is no unified fixed unit, and it adjusts according to different asset types.

## What constraints these characteristics impose on the "workflow orchestration" link
Disparate data sources and non-fixed update cycles require workflows to support multi-source data pulling and incremental synchronization configuration, and adapt to pulling logic for different data sources. Diverse document structures require workflows to support importing rule tables and identification lists in different formats, to avoid format verification failures. Complex update trigger scenarios require support for both scheduled and event-driven startup modes, to cover the needs of quarterly regular updates and temporary system changes. Review minutes need to be associated with corresponding classification and grading configurations, requiring workflows to retain context-associated nodes to ensure that compliance review processes can be traced. Additionally, the operational habits of data governance teams require workflows to have configurable manual approval nodes, to align with offline compliance review processes.

## How to set the configurations
This configuration guide is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind global variables to the unified path prefix of data catalogs and classification rule tables | Match the call paths of multi-source data, adapt to the pulling logic of different assets |
| `nodeId` | Bind the nodeId of the preceding data pulling node | Ensure accurate data transfer between workflow nodes, avoid cross-node data loss |
| Trigger Mode | Dual mode of scheduled trigger + event trigger, set the scheduled cycle to 7 days, bind data change webhooks for event triggers | Adapt to the dual needs of quarterly updates and temporary changes |
| Context Retention Settings | Retain 3 rounds of dialog for preceding data verification nodes, retain 1 round of dialog for rule matching nodes | Match functional differences of different nodes, avoid context redundancy affecting matching accuracy |
| Variable Update Configuration | Bind empty value updates to the empty fields output by the node | Resolve common issues of failed variable updates, ensure correct transmission of empty values |
| URL Parameter Binding | Enable parameter mapping in application startup configuration, bind the data parameter to global variables | Support passing custom global variable values via application links |

## Three common mistakes
- Variable updates to empty values do not take effect in workflows. The symptom is that the node output field shows empty, but the corresponding field in the global variable panel still retains the original value. The cause is that no conditional judgment node triggered by empty values is bound, and the variable update component is called directly.
- Passing global variables via application links fails. The symptom is that global variables do not carry specified parameters after opening the application. The cause is that the parameter binding switch is not enabled in the application startup configuration, and the URL parameter mapping rules are not correctly configured.
- Inconsistent context retention during multiple visits. The symptom is that after multiple visits with the same ID, the dialog rounds of preceding nodes do not match the configuration. The cause is that the dialog context is not bound to the user ID, leading to global overwriting of the context.

## How to confirm the configuration is complete
- Manually trigger the workflow, check whether the data pulling node correctly imports the configured document content, and verify that the fields match the source data.
- Configure an empty value update trigger node, pass a test empty field, and check whether the global variables are correctly updated to empty values.
- Configure a URL parameter transfer test, access the application link with the `data=1123` parameter, and check whether the global variables correctly receive the parameter value.
- Simulate multiple visits with the same ID, and check whether the context retention of different nodes meets the configuration requirements.

The values provided here are common starting points and should be measured against the reader's own samples.
