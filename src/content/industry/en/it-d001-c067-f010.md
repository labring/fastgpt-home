# Code and Change Review Assistance for Data Security Classification and Grading: Citation Sources and Traceability

## What data falls under this category
Data for this category originates from data asset inventories, database metadata, business system descriptions, and regulatory documents. Its update frequency is quarterly or after each business system change. Daily deliverables include data catalogs, classification and grading rules, important data identification tables, and review minutes. Document fields include data asset unique identifiers, sensitive field definitions, grading standards, review conclusions, and similar items. There are no unified fixed units; labeling is based solely on the attributes of individual data items. This data covers all data assets except personal information. It primarily supports review work for data governance teams, security consultants, and legal compliance personnel.

## Constraints for the citation sources and traceability link
Multi-source data sources require the traceability link to associate unique identifiers across different systems. This prevents cross-system data confusion.
The quarterly or post-business-change update frequency requires traceability configurations to support regular synchronization of data sources. This ensures the timeliness of cited content.
Daily documents include classification rules, identification tables, and review minutes. Traceability must accurately match specific entries to avoid generalized citations that cause review deviations.
Coverage of all data assets except personal information requires the traceability link to strictly distinguish data types. This ensures compliant citations.
The time-consuming nature of review scenarios requires traceability content to be concise and efficient. This avoids excessive consumption of review context.

## How to configure the settings
The following configurations are based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | Adapts to the average content length of classification and grading rules and important data identification tables, avoiding truncation of compliance-related fields |
| `responseData` | Enable original text return | Ensures that original text of data catalogs and review minutes can be directly obtained during traceability, without additional associated queries |
| `detail` | Enable detailed traceability identification | Associates unique identifiers from data asset inventory and database metadata, facilitating quick location of corresponding data items |
| Single recall result limit | Top 4 entries | Matches the entry scale of daily review minutes, avoiding excessive content interfering with review logic |
| Global variable binding rule | Configure by data source group | Adapts to the characteristics of multi-source data, ensuring accurate association of metadata from different business systems |
| Synchronization trigger timing | After system changes or quarterly | Matches the data update frequency, ensuring the timeliness of traceability data |

## Three common configuration errors
- Phenomenon: Global variables configured in the workflow are not called by retrieval nodes. The interface shows the variables as empty. Cause: Global variables are not bound by data source group. This causes variable scope conflicts for multi-source data.
- Phenomenon: Retrieved traceability content is automatically rewritten. The original document format and complete content are not retained. Cause: The `responseData` original text return configuration is not enabled. This leads the large model to perform unnecessary summarization of traceability content.
- Phenomenon: Traceability entries returned by a single retrieval do not meet review scenario requirements. Entries are either too many or too few. Cause: The single recall limit is not adjusted based on the actual entry scale of classification and grading documents. This leads to context overload or insufficient information.

## How to confirm the configuration is correct
- Check the configuration items of the retrieval node. Confirm that the value of `quoteMaxToken` matches the average length of the currently used classification and grading documents.
- Trigger a code review assistance process. Check whether the returned traceability content is the complete text of the original document, with no automatic rewriting or summarization.
- Verify the unique identifiers associated with traceability content. Confirm that they match the corresponding identifiers from data asset inventory and database metadata.
- Test global variable binding for different data sources. Confirm that the corresponding nodes can correctly call the bound variables.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
