# Code and Change Review Assistance for Database Cloud Service Operations: Tool Calling and Plugins

## What the data for this category looks like
Data for this category is primarily sourced from cloud database consoles, slow logs, monitoring metrics, and ticket systems. Daily generated documents include instance change orders, backup and restore records, performance diagnosis reports, and parameter adjustment records. These documents contain fields such as instance ID, change time, slow SQL execution duration, and backup file size. Data is updated daily or upon completion of each change operation. Data formats vary across sources: console data mostly takes the form of structured key-value pairs, while slow logs contain text-form SQL statements and execution durations.

## Constraints imposed on tool calling and plugin workflows
Multiple data sources with varied formats require tool calling to adapt to different data source API formats. For example, calls to cloud database console APIs require tenant ID and instance permission parameters. Slow log parsing requires handling unstructured text. Updates are triggered by changes, so tool calling must support on-demand pulling of the latest data to avoid using expired backups or change records. Daily document fields are inconsistent, so plugins must preset field mapping rules to convert documents from different sources into a unified review and validation format. Multi-tenant service boundaries are involved, so tool calling must validate the caller's permission scope to prevent cross-tenant data access.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic tool selection for multiple data sources, covering scenarios such as slow log parsing and console data pulling |
| `functionCall` | Enabled | Enables structured output of review results to facilitate alignment with fields in change orders and ticket systems |
| Tool call timeout duration | 300 seconds | Matches the average response duration of cloud database APIs, preventing task failures caused by prolonged slow log pulling |
| Context retention rounds | First 3 conversation turns | Adapts to the short context requirements of change reviews, reducing redundant data consumption of token quotas |
| Permission validation switch | Enabled | Complies with multi-tenant service boundary constraints, preventing unauthorized access to other tenants' database data via tool calls |

## Three common configuration errors
- Phenomenon: After `toolChoice` is set to `auto`, tool calls return "No available tools found". Cause: No cloud database-related API plugins are bound in the plugin marketplace, or plugin permission parameters are not configured.
- Phenomenon: Tool call tasks time out, with status code 504 displayed in the interface. Cause: The configured timeout duration is shorter than the average time required to pull cloud database slow logs, and does not match the update rhythm of business data.
- Phenomenon: After output thinking is enabled, no thinking content appears in tool call results. Cause: The output format for `functionCall` is not correctly configured, or the model does not support structured thinking return requirements.

## How to confirm successful configuration
- The tool management page in FastGPT v4.17.0 is accessed to confirm that plugins related to cloud database consoles and slow log parsing have been bound.
- A simulated change review request is submitted to check whether tool calls can pull backup and restore records for the corresponding instance.
- Tool call logs are reviewed to confirm that returned results include preset fields such as instance ID and change time, with formats aligned with business documents.
- Cross-tenant tool call requests are tested to confirm that access to other tenants' database data is not permitted without proper authorization.
