# Code and Change Review Assistance for Data Cleaning and Quality Inspection: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data processed for this category comes from raw datasets, ETL logs, annotation platforms, and sampling results. Update frequency is daily or per data batch. Associated daily documents include cleaning rules, quality inspection sampling tables, abnormal data lists, and delivery reports. Document fields include data identifiers, anomaly types, sampling rates, processing results, and other related items. There are no unified mandatory units; field specifications must match the corresponding data source.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Data sources for this category are diverse, update rhythm follows batch or daily schedules, and multiple types of structured documents are associated. These factors create multiple constraints for multi-turn dialogue and prompt configuration. Data formats vary across different sources, so multi-turn dialogue must adapt to field mapping rules to avoid context parsing errors. Batch-updated data requires dialogue contexts to be isolated per batch to prevent cross-batch data confusion. Daily associated documents such as cleaning rules and anomaly lists require explicit embedding of field specifications in prompts to ensure reviews match existing business logic. Historical anomaly data and delivery reports must be included as context references, and context length must be limited to avoid overflow.

## Configuration Setup
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier per data batch | Ensure dialogue context isolation for the same batch of data, avoid cross-batch data confusion, and match the daily/per-batch update data characteristics of this category |
| `messages` | Retain the first 10 rounds of dialogue context for the current batch | Prevent context overflow, adapt to the field parsing requirements of multiple document types in this category, and avoid redundant data interfering with reviews |
| `variables` | Bind cleaning rules and abnormal list fields for the current batch | Ensure prompts can automatically call current business rules, and match the field specifications of daily documents for this category |
| Maximum context length | 8000–12000 characters | Adapt to the number of fields from multi-source data in this category, while avoiding parsing failures caused by overly long contexts |
| Context isolation strategy | Trigger session reset per data batch | Match the daily/per-batch update data rhythm of this category, prevent cross-contamination of context from different batches |

## Three Common Misconfigurations
- A `Cannot read properties of null (reading 'q')` error occurs when calling the dialogue interface. The `variables` parameter is not bound correctly, causing empty fields referenced in the prompt to remain unreplaced, triggering a null pointer exception.
- Cross-batch data is automatically associated during multi-turn dialogue, causing review results to mix in abnormal data from other batches. The `chatId` parameter is not configured per data batch, so session contexts for different batches are not isolated, violating the daily/per-batch update data rhythm of this category.
- Submitted dialogue requests do not comply with FastGPT specifications, and prompts cannot be parsed normally. The structure of the `messages` parameter is not organized correctly, causing interface call failures and preventing the review process from triggering.

## How to Verify Correct Configuration
- Check if the `chatId` parameter corresponds one-to-one with the current data batch, and confirm that the session context isolation logic is active.
- Verify that the `variables` parameter binds fields from documents such as current batch cleaning rules and abnormal lists, ensuring that prompts can call business rules.
- Test the context retention range of multi-turn dialogue, confirming that only data from the current batch is included in the context.
- Cross-check the structure of the `messages` parameter in dialogue requests, confirming compliance with FastGPT interface specifications to avoid call failures.

The values provided are common starting points and should be measured against the reader's own samples.
