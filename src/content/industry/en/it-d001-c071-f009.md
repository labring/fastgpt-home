# Code and Change Review Assistance for Data Masking: Tool Calls and Plugins

## What data in this category looks like
Data for this category comes from enterprise databases, data dictionaries, in-house masking tools, and access approval systems. Updates follow project batches or individual data processing tasks. Daily maintained documents include masking plans, field mapping tables, masking validation reports, and approval records. Core fields include sensitive field identifiers, masking rule types, execution status, and approval numbers. There are no fixed universal units; values adjust based on specific data processing scenarios and compliance requirements.

## What constraints do these characteristics impose on the tool calls and plugins workflow
The scattered data sources require tool calls to support integration with multiple system interfaces, adapting to different calling logic such as database queries and data dictionary pulls. The update rhythm changes with projects, so tools must support dynamic adjustment of request parameters and trigger timing to fit non-fixed-cycle data processing tasks. The diverse document structures require plugins to have built-in format parsing logic to automatically adapt to different types of input files such as masking plans and field mapping tables. The accuracy of sensitive fields is directly linked to compliance risks, so an additional parameter verification step must be added during the tool call phase to ensure that the incoming sensitive field identifiers match the actual data.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to tool call requirements across different scenarios, no need to manually specify specific functions |
| `functionCall` | Triggered according to data masking process nodes | Matches the segmented execution logic of data masking processing, avoids invalid calls |
| Sensitive field verification threshold | 0.85–0.95 | Balances the accuracy and recall rate of sensitive field identification, adapts to different business scenarios |
| Plugin timeout duration | 300 seconds | Fits the conventional response duration of database queries and masking tool calls |
| Retry count | 2 times | Addresses scenarios of temporary network fluctuations or short-term system unavailability |

## Three Common Configuration Mistakes
- Phenomenon: The masking results returned by the API call do not match the test results in the platform chat interface. Cause: The `toolChoice` parameter was not configured correctly in the API request, causing the tool call logic to be misaligned.
- Phenomenon: Timeout errors occur when the plugin calls the masking tool. Cause: The set timeout duration is shorter than the actual response duration of the database query or masking tool.
- Phenomenon: Unable to accurately call the specified masking processing workflow in multi-workflow scenarios. Cause: No independent plugin trigger identifier was configured for each workflow, resulting in chaotic call routing.

## How to Confirm the Configuration Is Complete
- On the plugin management page of FastGPT v4.17.0, check whether the parameters of the configured masking processing plugin match the preset configuration.
- Initiate a test call to verify whether the returned results include correct masked fields and validation report links.
- Simulate a temporary network fluctuation scenario to confirm that the plugin triggers the preset retry logic and timeout prompt.
- Verify the approval record synchronization status, confirm that the approval records generated after the tool call can be correctly synchronized to the access approval system.
