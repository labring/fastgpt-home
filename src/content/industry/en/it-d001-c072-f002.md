# Code and Change Review Assistance for Data Collection Task Design: Context and Token

## What the data for this category looks like
This category of data is generated across the full lifecycle of collection tasks. Sources include clear client collection requirements, publicly available data sources, on-site deployed collection tools, and internally accumulated sample libraries. Daily deliverable documents include collection plans, sample specification descriptions, data authorization documents, and task scheduling tables. Update frequency follows individual project progress or weekly iterations. Data fields cover collection scope, field definitions, compliance check items, execution nodes, etc. There are no unified fixed units, and adjustments must be made based on the client’s business scenario.

## What constraints these characteristics impose on the "context and token" link
The volume of documents and data for collection task design fluctuates with project complexity. The cumulative text of a single project’s collection plan, authorization description, and other materials can reach thousands of characters, and must be linked to client business rules. Context must cover requirement changes and sample adjustment records throughout the project lifecycle. If context is redundant or token limits are exceeded, the large language model will fail to accurately associate the latest collection rules. Additionally, field specifications vary significantly across different projects. Context must precisely match the field definitions of the current task to avoid cross-project data contamination, and token usage must be strictly controlled to fit the large language model’s input upper limit.

## How to set the configurations
Under FastGPT v4.17.0, the configuration items are as follows:

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Maximum number of context entries | Top 10–15 entries | Matches the number of task scheduling and compliance documents updated weekly per project, avoids context overload |
| `maxContext` | 8000–12000 token | Adapts to the total length of cumulative text such as collection plans and sample specifications, covers core data for single projects |
| Context recall threshold | 0.75–0.85 | Requires differentiation between client business fields and general text, avoids recalling irrelevant historical project data |
| `quoteMaxToken` | 2000–3000 characters | Limits the length of a single recalled context entry, ensures key information from a single sample specification document is fully extracted |
| Context refresh timing | Triggered after task scheduling updates | Ensures the latest collection rules and authorization changes are included in the context |
| Context filtering rules | Match by project ID | Excludes collection data from other projects, avoids context contamination |

## Three common configuration mistakes
- Setting `maxContext` to 15 entries but only showing 2 entries in conversation details: This occurs because the current project’s context filtering rules are not correctly associated, and irrelevant data from historical sessions is incorrectly recalled, resulting in valid context being filtered out.
- The large language model returns a JSON reply that does not follow the required format: This occurs because the context contains unformatted collection plan fragments, which interfere with the large language model’s format output. Restrict `quoteMaxToken` to only recall structured sample specification documents.
- The large language model prompts that the context token count exceeds the limit: This occurs because `quoteMaxToken` is not set, and the length of a single recalled collection plan text is too long, causing total token usage to exceed the large language model’s input upper limit.

## How to confirm the configuration is correct
- View the context list to confirm that only the current project’s collection plans, sample specifications, and other documents are included, with no historical data from other projects.
- Trigger the code review assistance function to check that the number of returned context entries matches the set `maxContext` value.
- Verify the length of a single recalled context entry to confirm it does not exceed the `quoteMaxToken` limit.
- Simulate a task scheduling update to check whether the context automatically refreshes and includes the latest adjusted content.

The values given are common starting points and should be measured against the reader's own samples.
