# Code and Change Review Assistance for Data Collection Task Design: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data for this category is generated across the full lifecycle of data collection projects. Core daily documents include four types: collection plans, sample specifications, authorization statements, and task schedules. Data sources include customer requirements, public data sources, collection tool outputs, and internal sample libraries. Updates follow individual project or weekly cycles. Data fields cover sample scope, field specifications, collection permissions, schedule milestones, and similar items. Common units are characters, records, days, and others. Unlike subsequent data cleaning and quality inspection stages, data in this category directly determines how raw data is acquired.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data sources for this category are scattered, and update cycles are flexible. Multi-turn dialogue must incrementally request details from different sources based on project phases, avoiding loading excessive irrelevant data at once. The field structure of daily documents is fixed. Prompts must accurately bind core fields from documents such as collection plans and sample specifications, ensuring dialogue outputs align with actual project requirements. Context update frequency within a single project cycle requires the dialogue context window to match the length of a single document, preventing truncation of critical information. The most time-consuming steps of defining sample scope and confirming field specifications require prompts to focus on optimizing interaction logic for these steps, reducing repeated communication.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Dialogue context window | 800–1200 characters | Adapts to the length of single documents such as collection plans and sample specifications, prevents truncation of key fields, and aligns with FastGPT v4.17.0 context management rules |
| `messages` history turn limit | First 10 conversation turns | Matches the weekly update context rhythm of individual projects, avoids redundant historical information interfering with current interactions |
| `variables` binding scope | Bind collection plans, sample specifications, authorization statements | Corresponds to core fields of daily documents, ensures prompts call accurate project data |
| `chatId` session isolation rule | Divide by project dimension | Matches the update frequency per project or week, prevents cross-project data confusion |
| Prompt trigger threshold | Calibrated via actual testing | Adapts to dialogue rhythm for time-consuming steps such as defining sample scope and confirming field specifications |

## Three common configuration errors
- Calling the dialogue interface returns a 404 status code with no body. This occurs when the collection plan document corresponding to `variables` is not correctly bound, leading to context call failure.
- Refreshing the page displays the prompt "No available index model detected". This occurs when `chatId` isolation rules are not configured by project dimension, leading to cross-project index resource conflicts.
- Attempting to cancel the download validity period of a conversation file still triggers an expiration prompt. This occurs when the validity period configuration parameter of the authorization statement is not synchronized in `messages`, leading to the context not using the latest rules.

## How to verify proper configuration
- Create a new test session, enter "Confirm the sample scope for this collection", and check if the dialogue automatically associates the bound collection plan fields.
- Simulate multi-turn requests for sample specification details, and check if the dialogue context retains valid historical information from the first 10 turns.
- Switch session IDs for different projects, and verify that dialogue contexts for different projects do not interfere with one another.
- Upload a test authorization statement document, and check if the dialogue correctly calls its legality verification rules.

The values provided here are common starting points, and should be evaluated against your own specific samples.
