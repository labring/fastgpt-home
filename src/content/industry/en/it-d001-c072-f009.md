# Code and Change Review Assistance for Data Collection Task Design: Tool Calling and Plugins

## What the data for this category looks like
The core data for data collection task design comes from customer requirements, public data sources, collection tools, and sample libraries. Update frequency is per project or weekly. Daily deliverable documents include collection plans, sample specifications, authorization statements, and task schedules. Data fields cover sample scope, field names, units, authorization periods, schedule nodes, and more. There is no fixed, unified field format. Adjustments must be made flexibly based on customer requirements.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multiple data sources require tool calling to support integration with different types of data source interfaces, to avoid using a single calling logic for all scenarios. The update rhythm of per project or weekly requires plugins to support periodic synchronization of collection configurations and data source information. Diverse document types and flexible field structures require tool calling to associate and retrieve documents such as collection plans and sample specifications, to assist in verifying field compliance. The risk of unusable samples and infringement consequences requires tool calling to embed legality verification links, to avoid collection compliance issues.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the dynamic calling requirements of multi-source data collection, automatically matches the tool calling logic for corresponding data sources |
| `functionCall` | Triggered by collection task type | Differentiates calling rules for different scenarios such as public data sources and customer-owned data sources, to avoid invalid calls |
| Tool call timeout | 600 seconds | Adapts to the time requirements of collection links such as multi-source data pulling and sample scope verification |
| Context window length | 800–1200 characters | Adapts to the retrieval length of documents such as collection plans and sample specifications, retains key configuration information |
| Traffic shunting rule | Allocated by data source type | Differentiates traffic for knowledge base retrieval and MCP calls, to avoid resource contention |
| Concurrent call limit | First 3 entries per single call | Controls concurrent pressure for single-batch collection, reduces the probability of empty returns |

## Three common configuration errors
- Phenomenon: The large language model does not trigger tool calling, and the returned result is empty. Cause: The `toolChoice` parameter is not configured correctly, and the triggering rule adapted to the collection task is not specified.
- Phenomenon: When the concurrent call volume reaches 2-3 times per second, MCP calls return `none`. Cause: The tool call timeout is set too short, which does not adapt to the pulling time required for multi-source collection, resulting in request interruption.
- Phenomenon: Tool calling cannot associate collection plan documents. Cause: The context window length is set too small, causing key configuration information of the collection plan to be truncated, and the corresponding tool cannot be triggered.

## How to verify correct configuration
The tool call logs in FastGPT v4.17.0 can be reviewed to confirm that the `functionCall` triggering rule matches the current collection task type.
A concurrent test of 2-3 calls per second can be run to verify that each call returns a non-empty result with no timeout errors.
Collection plan documents can be retrieved to confirm that tool calling can correctly associate corresponding document fragments and extract key information such as sample scope and field specifications.
A Python call script can be run to verify that the interface can normally return tool call configurations, with no errors caused by incorrect parameter formats.

The values provided are common starting points and should be measured against the reader's own samples.
