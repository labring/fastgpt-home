# Code and Change Review Assistance for Data Collection Task Design: Citation Sources and Traceability

## What This Type of Data Entails
This data covers the full lifecycle of data collection projects. Sources include customer requirement documents, public data source descriptions, collection tool configuration logs, and internal sample library records.
Daily deliverable documents include collection plans, sample specification sheets, data authorization statements, and task scheduling sheets. Common fields include sample scope, collection fields, compliance check items, and delivery cycles.
Data updates follow individual project cycles, or weekly syncs of the latest collection rules and authorization documents. Overall document structure adjusts per project, with no fixed unified format.

## Constraints Imposed on Citation and Traceability Workflows
The non-standardized document structure of this data requires traceability to support metadata extraction from multi-format source files, without enforcing mandatory unified structured fields.
Differences in update cycles across projects require the traceability chain to bind all versioned data within a project cycle, preventing references to expired collection rules.
The strong correlation between sample scope and compliance check items requires citation traceability to also link data legality certification documents, ensuring compliance of collected data.
Decentralized storage of collection tool configuration logs requires the traceability link to pull associated collection execution records across tools, ensuring complete traceability of citation sources.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Most collection task documents are multi-paragraph unstructured content. This value range covers key information from a single core collection document, and adapts to the context length limit of FastGPT v4.17.0 |
| Citation Matching Threshold | 0.72–0.85 | Field descriptions in collection plans use mostly technical terminology. This range accurately matches similar rule content, avoiding incorrect association with unrelated documents |
| `responseData` | Enable "Return Full Source File Path" | Traceability of collection tasks requires association with original configuration files and authorization statements. Full paths enable quick location of source data, facilitating subsequent compliance checks |
| `detail` | Enable "Extract Document Metadata" | Daily documents include non-text metadata such as authorization statements and scheduling sheets. Enabling this supplements compliance information for traceability, improving the completeness of citation sources |
| Single Search Limit | Top 3 results | Core document count for a single collection project is limited. Excessive results increase context redundancy, reducing the accuracy of AI responses |

## Three Common Misconfigurations
- Only text datasets are returned in search results, with non-text sample specification sheets and authorization statements not included in citations. Phenomenon: Knowledge base search results only display text-format documents, with no matching entries for other-format source files. Cause: Chunking and indexing rules for unstructured documents are not configured, and only text dataset retrieval is enabled.
- No citation content is displayed after embedding FastGPT via iframe. Phenomenon: Frontend pages do not display citation source pop-ups or lists as configured. Cause: Frontend rendering configuration for `responseData` is not enabled, or citation display permissions are not enabled in embedding parameters.
- Knowledge base search with dynamic parameters returns no citation results. Phenomenon: AI responses do not associate with knowledge base content corresponding to the configured knowledgeSearch variable, with no citation sources displayed. Cause: Dynamic parameters are not bound to the retrieval scope for citation traceability, or retrieval threshold is set too high, causing matching failures.

## How to Verify Correct Configuration
- A collection plan document is uploaded to the bound knowledge base. A retrieval is initiated, and the returned results are checked for the full source file path of the document.
- After the `detail` parameter is enabled, search results are checked for compliance metadata tags associated with data authorization statements.
- After dynamic parameters are configured, retrieval is triggered in the workflow, and returned results are confirmed to match the passed knowledge base scope.
- Backend retrieval logs for FastGPT v4.17.0 are checked to confirm the configured `quoteMaxToken` parameter is correctly included in the request.

The values listed are common starting points, and should be evaluated against samples from the actual deployment environment.
