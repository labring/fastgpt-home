# Code and Change Review Assistance for Dataset Delivery and Version Management: Multi-turn Dialogue and Prompts

## What this category of data looks like
This category of data originates from object storage, data warehouses, annotation platforms, and customer acceptance feedback. Daily produced documents include dataset descriptions, version records, delivery checklists, and acceptance reports. Covered fields include version numbers, sample counts, delivery scopes, difference descriptions, and more. Data updates occur per batch delivery or version release. Work centers on dataset delivery packages and version traceability. Each delivery round must ensure metadata matches actual samples.

## What constraints these characteristics impose on multi-turn dialogue and prompts
Multiple data sources require multi-turn dialogue to link version records across different systems. This prevents mixing data from different batches. Fixed update schedules require dialogue context to bind the current batch’s version identifier. This stops the model from calling expired delivery information. Fixed field structures in documents require prompts to preset metadata extraction rules. This ensures automatic verification of delivery completeness during dialogue. Time-consuming tasks such as version number management and sample difference descriptions require multi-turn dialogue to support automatic comparison of changes across versions. This reduces manual verification workload.

## How to configure settings
For FastGPT v4.17.0, the multi-turn dialogue and prompt configuration for dataset delivery and version management scenarios is as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Fixed per batch delivery session | Ensures multi-turn dialogue for the same batch of datasets links to the same context, avoiding version confusion |
| `messages` | Include historical turns with version numbers and delivery checklist fields | Allows the dialogue model to associate dataset version information for the current session, supporting version comparison for change reviews |
| `variables` | Pass key fields from dataset descriptions and acceptance reports | Provides the model with metadata for the current delivery package, supporting automatic verification of change content |
| Streaming return interval | 1–3 seconds | Adapts to front-end display rhythm, avoiding excessive wait times that reduce review efficiency |
| Maximum context token count | 8000–12000 tokens | Accommodates version records and delivery details for multi-turn change reviews, preventing context truncation |

## Three common configuration mistakes
- Issue: After calling the dialogue API, the dialogue log details do not match the actual returned answer content. Cause: The latest dataset version identifier is not included in `messages`, so the model reuses context cache from previous sessions.
- Issue: The streaming output return interval is fixed at 4 seconds and cannot be adjusted. Cause: The streaming return interval parameter is not configured, so the platform’s default fixed interval value is used.
- Issue: Content becomes mixed when concatenating two AI dialogue outputs. Cause: No session separator identifier is added to `variables`, so the model cannot distinguish the context boundaries of the two dialogues.

## How to verify correct configuration
- Initiate a multi-turn change review dialogue. Check that all requests use the same `chatId` to confirm correct context association.
- Call the API to retrieve dialogue logs. Verify that the `messages` field includes the current batch’s dataset version number and delivery scope information.
- Enable streaming output mode. Observe whether the return interval falls within the preset 1–3 second range. Adjust the setting and validate front-end display effects.
- Test scenarios where two independent dialogue outputs are concatenated. Confirm that output content has no cross-mixing, and context boundaries are clear.

The values provided here are common starting points. Always validate against your own specific samples.
