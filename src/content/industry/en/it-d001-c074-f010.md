# Code and Change Review Assistance for Text Annotation Projects: Citation Sources and Traceability

## What This Category’s Data Looks Like
Core data for text annotation projects comes from corpus provided by clients, annotation results from internal annotation platforms, specialized vocabularies, and quality inspection sampling results. Daily maintained documents include annotation specifications, sample packages, quality inspection reports, and problem feedback forms. Data updates occur daily or after each batch of annotation tasks is completed. This category of data focuses on semantic boundaries, entity recognition, and intent classification, differing from the visual feature annotation requirements of image annotation projects. Data fields include annotation content, tag values, annotators, quality inspection results, with no additional visual fields.

## Constraints on Citation and Traceability Workflows
Decentralized and frequently updated data sources require precise matching of current batch or daily annotation documents during traceability, to avoid cross-batch data confusion. Multiple document types require support for extracting traceability information from sources such as annotation specifications and quality inspection reports, so retrieval rules for multiple document types must be adapted. Data fields focus on semantic tags, so traceability must associate annotation content with the basis for corresponding tags, and cannot rely on visual association logic. High update frequency means the retrieval range must be limited to the most recent period, preventing expired annotation data from being called and affecting review accuracy.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | Adapts to content truncation needs for long documents of text annotation projects such as complete sample packages and quality inspection reports, avoiding truncation of key tag basis |
| Reranking | Enabled | Text annotation data has strong semantic association. Enabling reranking improves the relevance of traceability results and accurately matches annotation basis |
| Single Search Limit | Top 6 entries | Matches the single-batch sample scale of annotation projects, avoiding excessive redundant data interfering with the core logic of code and change reviews |
| `detail` | Enabled | Needs to return complete fields of traceability data including annotator and quality inspection result, to support responsibility tracing and compliance verification for change reviews |
| Maximum Context | 3 conversation turns | Adapts to continuous change descriptions in code reviews, avoiding traceability deviation caused by lost context |
| `responseData` | Only return annotation-related fields | Filters irrelevant document content, focusing on core traceability sources such as annotation specifications and quality inspection results |

## Three Common Configuration Errors
- Phenomenon: After continuously submitting change requests related to code reviews, traceability results cannot associate previous annotation sample descriptions. Cause: No reasonable maximum context parameter is configured, causing conversation context to be truncated and unable to trace previous annotation basis.
- Phenomenon: Key fields such as annotator and quality inspection status are missing from traceability results. Cause: The `detail` parameter is not enabled, or the range of fields to return is not specified. Only document fragments are returned without extracting core metadata.
- Phenomenon: Timeout errors occur when retrieving complete sample packages. Cause: The `quoteMaxToken` setting exceeds the maximum threshold allowed by the system, or the document type for retrieval is not limited, resulting in loading excessive redundant data.

## How to Verify Correct Configuration
- Submit a retrieval request containing multiple batches of annotation content, check whether the document types of the returned results only include target documents such as annotation specifications, sample packages, and quality inspection reports.
- View the field list of retrieval results, confirm that required traceability metadata such as annotator and quality inspection results are included.
- Submit three consecutive follow-up questions related to change reviews, confirm that traceability results always associate with current batch annotation data, and no cross-batch content appears.
- In FastGPT v4.17.0, verify that the AI advanced configuration page allows custom citation templates to match the current traceability configuration rules.

The values given are common starting points and should be measured against the reader's own samples.
