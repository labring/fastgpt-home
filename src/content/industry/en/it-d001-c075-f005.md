# Code and Change Review Assistance for Documentation Site Maintenance: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The data for this category comes primarily from code repository commit records, documentation site build logs, user-submitted feedback and Issues, and version release records. Daily produced documentation includes installation guides, API reference documents, version migration guides, and frequently asked questions. Document structures typically include fields such as version identifiers, operation steps, parameter descriptions, and error code comparison tables. Data update frequency is usually once per week, or synchronized with each version release.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Heterogeneous code, documentation, and feedback content form the data sources. Multi-turn dialogue must clearly distinguish between different input types. Prompts must define clear context boundaries to prevent confusion. Update frequency varies with version releases. Dialogue must dynamically adapt to the latest version information. Prompts must include version verification logic to filter expired content. Document structures contain multiple specialized fields. Multi-turn dialogue must trigger distinct retrieval and response logic based on document type, to ensure responses align with the expression habits of the corresponding documentation. User feedback and Issue data must be linked to specific document nodes. Prompts must support associated traceability, to ensure responses point to accurate documentation or code locations.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 characters | Adapts to the total length of multiple documents and code snippets, avoids exceeding the processing limit of FastGPT v4.17.0 |
| Prompt template | Separate templates per document type: installation guide template, API documentation template, migration guide template | Matches the specialized expression habits of different document categories, improves response accuracy |
| Variable binding | Bind current version number, document build time | Dynamically inserts context information, ensures responses point to the latest version content |
| `chatId` association | Bind sessions to specified document repository IDs | Ensures session context only links to data sources for the corresponding documentation site, avoids interference from cross-repository data |
| Single retrieval limit | Top 3 results | Prevents excessive content from disrupting dialogue logic, focuses on core information |
| Session timeout period | 600 seconds | Prevents unresponsive long conversations, adapts to multi-turn review scenarios for documentation site maintenance |

## Three Common Configuration Mistakes
- The symptom is that configured prompts do not affect response content, and responses do not follow preset rules. The cause is that prompts are not correctly bound to the `messages` queue of the dialogue flow, and are not loaded during session initialization.
- The symptom is that the front-end dialogue page displays outputs from multiple unrelated modules at the same time, and results for specific document types cannot be distinguished. The cause is that sessions are not bound to specified document repositories via `chatId`, and dialogue context is not split by document type.
- The symptom is that historical user feedback or Issue-related content cannot be retrieved during dialogue, and the number of search results is 0. The cause is that session context association logic is not configured, and traceability binding for session IDs is not enabled.

## How to Verify Correct Configuration
- Initiate a query that includes a version number, confirm that the bound variable information is automatically inserted into the response.
- Switch questions for different document types, confirm that responses match the expression style and content of the corresponding documentation.
- Ask multiple questions after opening a session, confirm that the document repository data linked to the session is correctly called.
- Check dialogue logs, confirm that the `messages` queue splits input content by document type.
