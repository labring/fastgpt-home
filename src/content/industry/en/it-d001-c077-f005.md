# Code and Change Review Assistance for Computer Room Inspection and Environmental Monitoring: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The data for this category comes primarily from environmental and equipment monitoring systems, access control systems, UPS monitoring devices, and video inspection tools. Daily generated documents include inspection sheets, temperature and humidity records, alarm records, and duty logs. Automated inspection script code and equipment change application documents may also be included in some scenarios.

Inspection sheets record inspection time, equipment numbers, temperature and humidity values, and inspection status. Temperature and humidity records include timestamps, measurement point locations, and percentage values. Alarm records include trigger time, associated equipment, and alarm codes.

Data updates occur daily or in real time, changing dynamically based on the computer room’s operating status. Core work for this category centers on confirming abnormal alarms, recording on-site inspections, and handing over facility status.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data sources for this category are scattered, with significant format differences. Multi-turn dialogue must distinguish contexts from different data sources such as environmental monitoring and access control to avoid mixing cross-category data.

Real-time updated alarm and temperature and humidity data require the dialogue module to pull the latest entries immediately. Prompts must explicitly specify calling the latest knowledge base content.

Inspection sheets and alarm records include specific fields such as equipment numbers and percentage values. Prompts must explicitly require extraction of these corresponding fields to avoid generic responses.

Text content in duty logs requires retaining historical dialogue context. This ensures that previous inspection and alarm confirmation processes can be traced during multi-turn interactions.

For code and change review assistance requirements, multi-turn dialogue must link inspection script code, equipment change records, and corresponding operating data to verify the rationality and compliance of changes.

## Configuration Settings
Note: The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context | Previous 8 turns of dialogue + last 24 hours of knowledge base data (approximately 12000 characters) | Computer room inspection data updates daily or in real time. Retaining recent dialogue context and the latest inspection and alarm records avoids outdated information. |
| Question Optimization | Enabled | Inspection-related questions often include details such as equipment numbers and temperature and humidity values. Optimization allows more accurate matching of corresponding knowledge base entries. |
| Single Search Limit | Top 6 results | The number of associated devices for inspection and alarm records is limited. Too many results will interfere with dialogue understanding. |
| Variable Binding | Bind inspection equipment number, alarm level, and inspection script version variables | This category of data includes clear equipment, alarm, and code fields. Variables can accurately locate corresponding knowledge base content. |
| Dialogue Context Retention | Retain for 7 days per session | Duty logs and inspection handovers require tracing across multiple turns of dialogue. A 7-day retention period covers standard duty cycles. |

## Three Common Misconfigurations
- Issue: Dialogue replies do not display image URLs configured in the knowledge base. Cause: The prompt does not explicitly require returning a displayable form of the image, or the multimedia content parsing configuration is not enabled.
- Issue: Calling the dialogue interface fails to accurately associate the inspection knowledge base for the specified computer room. Cause: The `variables` variable is not correctly bound in the request parameters, causing the search scope to cover all knowledge base content.
- Issue: Historical inspection records cannot be traced after the dialogue exceeds the set number of turns. Cause: The context retention rule for the `messages` parameter is not correctly configured, and historical dialogue beyond the limit is automatically cleared.

## How to Confirm Successful Configuration
- Initiate a dialogue that includes a specific equipment number, and check if the reply accurately matches the temperature and humidity and alarm records for that equipment.
- Enter a knowledge base query that includes an image URL, and confirm that the reply correctly displays the corresponding URL or a clickable image link.
- Initiate a continuous multi-turn dialogue, and check that previous inspection confirmation processes can still be correctly traced after 8 consecutive turns of interaction.
- Call the dialogue interface with the specified `chatId`, and confirm that the context within the same session is correctly retained.
