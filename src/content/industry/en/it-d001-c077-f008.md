# Code and Change Review Assistance for Computer Room Inspection and Environmental Monitoring: Workflow Orchestration

## Data Overview for This Category
The data sources for this category are computer room power and environment monitoring systems, access control systems, UPS monitoring devices, and video inspection terminals. Data update cadence falls into two categories: real-time alert push and daily inspection record archiving. Daily documents include inspection sheets, temperature and humidity records, alert logs, and duty logs. Fields include device unique identifier, temperature and humidity values (units: degrees Celsius and relative humidity percentage), alert level, timestamp, inspector ID, and facility status description.

## Constraints Imposed on Workflow Orchestration
Multiple data sources require workflows to be configured with multiple parallel nodes to pull different types of data. Real-time alert data requires short-interval trigger nodes to ensure response timeliness. Structured inspection documents and alert records must extract fields via the `variables` node for subsequent association verification during code change reviews. The personnel and time fields in duty logs must be mapped to workflow global variables to ensure traceability of operation subjects during reviews. The abnormal alert confirmation link must be configured with branch judgment nodes, which trigger different processing branches based on alert levels to avoid invalid review processes occupying resources.

## Configuration Guidelines
This document applies to FastGPT v4.17.0 and above.
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Map core fields of inspection sheets and alert records, such as device ID, temperature and humidity values, alert level | Match the structured field characteristics of this category of data to facilitate subsequent calls in review links |
| Trigger Node Interval | Set real-time alert nodes to 30 seconds, inspection archiving nodes to 86400 seconds | Match the real-time update and daily update cadence of data, balancing timeliness and resource usage |
| AI Conversation Context Window | Set to 1500–2000 characters | Adapt to the average length of inspection documents and alert records, avoiding context overflow |
| Branch Judgment Node | Divide into three processing branches based on alert levels: low, medium, high | Adapt to the business logic of graded alert processing, avoiding invalid review processes |
| `nodeId` | Assign a unique identifier to each data source access node | Facilitate workflow debugging and data transfer between nodes |
| Workflow Failure Handling | Configure alert push and log recording actions | Match the emergency response requirements for the consequences of errors in this category, ensuring traceability of abnormalities |

## Three Common Configuration Errors
- Form input fields configured in the workflow do not display in the conversation interface. The symptom is that submitted inspection information does not appear in the workflow context. The cause is that the output of the form node is not bound to the `variables` node, so global variables do not synchronize input content.
- The file link configuration item of the AI conversation module does not take effect. The symptom is that computer room temperature and humidity records cannot be retrieved during the review link. The causes are failure to fill in the correct knowledge base association ID, or failure to upload documents to the knowledge base bound to the workflow.
- Workflow execution times out. The symptom is that the node status remains in running for a long time. The cause is that the trigger node interval is set too short, leading to high-frequency pulling of power and environment monitoring data exceeding service resource limits.

## How to Verify Successful Configuration
- Start workflow testing, submit a simulated inspection form, and check whether the `variables` node correctly extracts form fields and displays them in the context.
- Configure the file link for the AI conversation module, upload a test inspection record, initiate a review request, and check whether the record content can be retrieved.
- Manually trigger the real-time alert node, and check whether the branch judgment node correctly jumps to the corresponding processing branch based on the alert level.
- View workflow running logs, confirm that the `nodeId` identifiers of all nodes are normal, with no unbound variables or missing configuration items.
