# Code and Change Review Assistance for Computer Room Inspection and Environmental Monitoring: Source Citation and Traceability

## What data for this category looks like
Data for this category mainly comes from environment and power monitoring systems, access control management systems, UPS monitoring equipment, and video inspection records. Daily generated documents include inspection reports, temperature and humidity logs, alarm logs, and duty rosters. Data fields include device identifiers, temperature and humidity values, alarm times, access records, voltage parameters, and more. Units include degrees Celsius, percentage, timestamps, and more.
Data updates follow two rhythms: real-time alarm push and daily inspection archiving. Synchronization only occurs at actual collection nodes, with no fixed bulk statistical scale.

## What constraints do these characteristics impose on source citation and traceability
This category has multi-source heterogeneous data sources and mixed manual and hardware-collected document structures. These traits impose multiple constraints on the source citation and traceability process.
Hardware-collected data from power and environment monitoring, access control, and other systems has large format differences from manually filled inspection reports. Association mapping between device identifiers and log fields is required to avoid cross-source data matching confusion.
Real-time updated alarm and inspection data requires citation contexts to match data synchronization rhythms, to avoid referencing expired or unsynced records.
Diverse units including timestamps, temperature and humidity values, and voltage parameters require unified field parsing rules during traceability, to ensure the accuracy of cited sources.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the text length of multi-source data for computer room inspection and environmental monitoring, avoids truncating critical alarms and device parameters |
| Citation data source scope | Enable only the three core data sources: power and environment monitoring, UPS monitoring, and inspection reports | Reduces interference from irrelevant data, aligns with core business documents for this category |
| Context recall count | Top 6 entries | Matches the conventional data scale of daily inspection archiving and real-time alarms, avoids context overload |
| `detail` | Enabled | Retains field and unit information from original data, ensures key parameters such as temperature and humidity and voltage can be verified during traceability |
| `responseData` | Include original data identifiers | Associates device IDs and collection timestamps, facilitates quick location of traceability sources |

This configuration example is based on FastGPT v4.17.0.

## Three common misconfigurations
- Symptom: After configuration, original alarm files from power and environment monitoring cannot be cited, with a prompt that the data source does not match. Cause: The power and environment monitoring system was not added to the allowed citation data source scope, so the system cannot recognize the corresponding data source.
- Symptom: The model context panel only displays 30 records, but the actual recall count is 310. Cause: The value of `quoteMaxToken` was not set correctly, so context exceeding the threshold is automatically truncated, leaving only the first 30 entries.
- Symptom: Cited inspection report data does not include temperature and humidity units. Cause: The `detail` configuration was not enabled, so field metadata from original data is filtered out, and unit parameters such as degrees Celsius cannot be displayed.

## How to confirm configuration is successful
- View the citation preview panel, confirm that original data fields and corresponding units from power and environment monitoring and UPS monitoring are displayed.
- Submit a review request for an inspection change, verify that the returned result includes original data identifiers matching the device ID.
- Adjust the value of `quoteMaxToken`, verify that the context recall count changes with the configuration.
- Check the data source scope settings, confirm that only core business data sources for this category are included, with no redundant entries.
