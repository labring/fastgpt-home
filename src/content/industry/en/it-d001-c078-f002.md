# Code and Change Review Assistance for Cabinet Rack Installation and Cabling: Context and Token

## What the data for this category looks like
The core users of this category are IDC operations engineers, network engineers, and equipment implementation personnel. They regularly process documents including rack installation applications, cabinet cabling diagrams, port label sheets, and construction records. Data mainly comes from DCIM systems, asset management systems, network topology tools, and customer work orders. Update frequency is per ticket or daily. Document structures include structured fields such as cabinet U-position numbers, port numbers, cable lengths, and unstructured content such as cabling diagrams, on-site photos. Fields do not have a unified standard format. Some documents require cross-system association and verification.

## Constraints on Context and Token Configuration From These Data Characteristics
The data characteristics of this category directly restrict context and token configuration logic. A large number of structured fields with inconsistent field names cause fluctuating token consumption during context recall. Unstructured cabling diagrams and photos must first be converted to text tokens. Token volume varies significantly across images of different resolutions after conversion. Ticket-based data updates require the context to associate the latest work orders and equipment information in real time. Old data tokens must be cleaned promptly. Cross-system associated documents require limiting the token share of a single data source to avoid overall context overflow.

## How to Set the Configuration
The following configurations are based on the interface logic of FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 10000–14000 token | Based on the average token consumption of a complete review package including installation application, port label sheet, cabling diagram, to avoid context overflow |
| `quoteMaxToken` | 2500–3500 token | Based on the token conversion limit for a single cabinet cabling diagram or network topology, preventing a single reference from occupying too much context |
| Chunk Length | 800–1200 characters | Based on the single field length of port label sheets and construction records, balancing recall accuracy and token consumption |
| Context Refresh Interval | Refresh after each ticket completion | Based on the ticket-based update frequency of this category’s data, ensuring the latest cabinet position and cabling data is used during reviews |
| Recall Match Count | Top 5–7 entries | Based on the three core data types including cabinet positions, ports, cables that need verification during daily reviews; too many entries increase token burden |

## Three Common Misconfigurations
- When uploading high-resolution cabinet cabling diagrams, some images trigger a `token limit exceeded` error, while low-resolution images can upload normally. This occurs because no token limit is set for image-to-text conversion. The token consumption of high-resolution images exceeds the configured threshold, and the system blocks excess content.
- When `maxContext` is set to 15000 token, the response token for a specific change review request automatically changes to 200, and the reply content is truncated. This happens because the total token count of core documents recalled by the context exceeds the actual configured limit. The system automatically truncates non-critical context, compressing the response token count.
- When associating a DCIM cloud storage data source, corresponding token data fails to load, and the review process throws an error. This occurs because the token association logic for the cloud storage is not configured correctly, preventing the context from reading token content from the corresponding data source.

## How to Verify Correct Configuration
- Upload a complete cabinet rack installation application and cabling diagram. Check the total token count displayed in the FastGPT context preview panel to confirm it does not exceed the configured `maxContext` threshold.
- Submit a change review request. Check the token length of the response content to confirm it is not accidentally truncated to 200 tokens or fewer.
- Test uploading cabling diagrams of different resolutions. Confirm all images load normally and convert to text tokens without errors.
- Check the data source association configuration. Confirm the update frequency of DCIM and asset systems matches the configured context refresh interval.

The values listed are common starting points and should be evaluated against relevant samples.
