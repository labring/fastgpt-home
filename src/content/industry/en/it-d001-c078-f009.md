# Code and Change Review Assistance for Cabinet Rack Installation and Cabling: Tool Calling and Plugins

## What data for this category looks like
The service targets IDC operations engineers, network engineers, and equipment implementation personnel. Data sources include DCIM systems, asset management systems, network topology diagrams, and customer service tickets. Daily deliverables include rack installation application forms, cabinet cabling diagrams, port label sheets, construction records, and other documents. Fields include rack unit number, cable specification, port identifier, construction date, and more. Units involve rack unit U, cable length in meters, port sequence number, and others. Data is updated once per job, with daily synchronization and verification for daily operation documents.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The need to access multiple data sources requires plugins to be configured with multiple sets of authentication rules to avoid cross-system call failures. Both unstructured cabling diagrams and structured ticket data must be supported, so tools need to simultaneously support structured field validation and multimodal content recognition. Data updates follow ticket workflows, so tool triggering timing must be bound to ticket status changes to avoid calling outdated data. Since errors directly impact business delivery, tools must add cross-data source consistency checks to reduce risks such as incorrect port connections.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic scheduling of multiple tools, matching the need for multi-data source calls in cabinet rack installation scenarios |
| Plugin Authentication Configuration | Fill in the keys generated by the connected systems, set the timeout period to 30 seconds | Adapts to different authentication logic of DCIM, asset systems, and other platforms, avoiding call timeouts that interrupt reviews |
| Multimodal Tool Calling Threshold | Set confidence threshold to 0.75 | Used to verify the accuracy of port identifier recognition from cabling diagrams, matching business acceptance standards |
| Tool Trigger Timing | Trigger 10 minutes after ticket submission | Matches the approval and workflow rhythm of rack installation applications, avoiding early calls that result in outdated data |
| Context Window Size | 8000 token | Accommodates review content across multiple documents including cabinet cabling diagrams and port label sheets |
| `functionCall` | Enable with a loop trigger limit of 2 times | Adapts to review requirements for multi-round port validation, avoiding invalid loop calls |

## Three common mistakes
- When calling the Zhipu multimodal model, parameter errors are continuously reported, but calling the OneApi interface via the OpenAI protocol succeeds. The cause is failure to correctly configure the dedicated authentication parameters for the multimodal tool, or failure to set `toolChoice` to a mode compatible with multimodal calls.
- After upgrading to FastGPT v4.17.0, the plugin editing page always displays "Unsaved" at the top regardless of operations, and no changes occur after clicking the save button. The cause is that the front-end state synchronization logic is not correctly bound to the return result of the save interface, causing the page state flag to not update.
- When configuring multi-round review tools, only prompting the model to think via the prompt word does not actually trigger multiple tool calls. The cause is failure to correctly set the loop trigger condition for `functionCall`, or failure to bind ticket status changes as the call trigger node.

## How to confirm the configuration is correct
- Trigger a test ticket, check the tool call logs, and confirm that all multi-data source interfaces return valid data.
- Upload a cabinet cabling diagram, call the multimodal tool, and confirm that the returned port identifier recognition results meet expectations.
- Click save after modifying the plugin configuration, and check whether the page state flag updates to "Saved".
- Configure cross-data source validation rules, import inconsistent port data, and confirm that the tool triggers an alert prompt.
