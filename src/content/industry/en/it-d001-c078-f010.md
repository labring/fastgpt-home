# Code and Change Review Assistance for Cabinet Rack Installation and Cabling: Source Citation and Traceability

In FastGPT v4.17.0, `quoteMaxToken` controls the maximum token length of cited content, `responseData` configures the format of returned data, and `detail` toggles retrieval of detailed associated document information.

## What the Data for This Category Looks Like
Data sources for this category include DCIM systems, asset management systems, network topology diagrams, and customer work orders. Daily produced documents include rack installation applications, cabinet cabling diagrams, port label sheets, and construction records.
Data updates occur per order or daily. Each data entry corresponds to a single rack installation or cabling task. Fields include cabinet number, physical port number, logical port mapping relationship, device model, operation time, and acceptance status. Some documents require association with device physical location and network configuration information.

## Constraints on Source Citation and Traceability
Data for this category is distributed across multiple systems and documents. Citation and traceability workflows must match both structured DCIM asset fields and unstructured cabling diagrams and construction records.
Data updates happen frequently. Changes for a single task must link to the latest work order and asset data in real time to avoid citing expired information.
Field structures vary widely across different documents. Rack installation applications include an approval status field. Port label sheets require mapping between physical and logical ports. Traceability configurations must accommodate these differences.
Physical access errors directly disrupt business operations. Traceability must accurately bind cabinet positions and port information. This ensures cited content fully aligns with actual construction processes.

## Three Common Configuration Errors
- Citation mark garbling appears in conversation output, displayed as non-standard quotation marks. This occurs when citation identifier rules for response data format are not configured correctly, causing encoding parsing errors in output content.
- The tool call module fails to return cited content after linking a knowledge base. This happens when the detailed retrieval toggle is not enabled, or the single search limit is set too low to retrieve category-specific documents such as rack installation applications and cabinet cabling diagrams.
- The conversation request interface does not return the cite citation ID. This occurs when the response data format is not configured to include full citation identifiers, or the maximum citation token count is set too small, truncating the returned content of citation fields.

## How to Verify Proper Configuration
- Initiate a test query that includes cabinet numbers and port information. Check if output content carries citation identifiers for the corresponding documents.
- Call the conversation request interface. Verify if the returned data includes the cite citation ID field.
- Submit a test query unrelated to cabinet rack installation. Confirm that cited content from category-specific documents is not returned.
- Observe if citation symbols in output content use standard formatting with no garbled characters.
