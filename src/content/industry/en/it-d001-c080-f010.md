# Desktop Terminal Support for Code and Change Review Assistance: Citation Sources and Traceability

## What the Data for This Category Looks Like
This category of data primarily comes from terminal management platforms, enterprise asset systems, user trouble tickets, and software repositories. Daily generated documents include terminal trouble tickets, installation manifests, software installation records, and remote assistance operation logs. Data is updated either via daily batch synchronization or real-time updates alongside terminal operations. Document fields include device ID, fault description, operation steps, software version, trouble report time, and more. There are no unified fixed units; some fields need to be matched based on specific device scenarios.

## Constraints on Citation and Traceability
Decentralized data sources require cross-system association and matching during traceability. Multi-source data association rules must be configured to unify device identifiers. Differences in update frequencies require distinguishing between real-time operation records and historical batch-synced asset data during traceability, to avoid lagging traceability information. Inconsistent document fields require supplementing auxiliary fields such as device ID and operation time during traceability to accurately locate sources. The fragmented nature of terminal operation logs requires associating contextual information during traceability, to avoid being unable to fully restore fault troubleshooting scenarios from a single record.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Matches the total length of documents such as terminal trouble tickets and remote assistance logs, to avoid truncating critical traceability information |
| `responseData` | `Include source document ID, update time` | Meets the need to confirm device operation time and source document integrity during traceability for desktop operation and maintenance scenarios |
| `detail` | `Enabled` | Supplements fields such as source document device ID and software version, to adapt to the multi-dimensional traceability needs of terminal data |
| Single maximum retrieved source documents | `Top 10` | Balances fault troubleshooting efficiency and traceability comprehensiveness, to avoid excessive redundant information interfering with AI responses |
| Source document matching threshold | `0.6–0.7` | Calibrated based on actual testing, adapts to the colloquial nature of terminal fault descriptions, to avoid retrieving irrelevant device configuration records |
| Multi-source data association switch | `Enabled` | Associates device information from terminal management platforms and asset systems, to ensure unified device identifiers during traceability |

## Three Common Configuration Mistakes
- Symptom: The AI response does not display any source document attribution, or the source document fields are empty. Cause: The `responseData` configuration item is not enabled, or the extraction rule for source document identifiers is not configured.
- Symptom: The number of retrieved source documents exceeds expectations, or target trouble ticket content cannot be retrieved. Cause: The single maximum retrieved source documents setting is too high, or the matching threshold is set too low, leading to retrieval of a large number of irrelevant software repository records.
- Symptom: The `quoteMaxToken` parameter value cannot be adjusted in a local deployment environment. Cause: The edit permission for this parameter is not enabled in the local configuration file, or the FastGPT version in use does not support custom adjustment of this configuration item.

## How to Verify Correct Configuration
- Submit a test request simulating terminal fault troubleshooting, check whether the AI response displays identifying information such as source document device ID and trouble report time at the end.
- Adjust the `quoteMaxToken` parameter to a smaller value, verify whether traceability content from long documents is truncated, to confirm the parameter takes effect.
- Simulate a scenario where the target document is not matched, check whether a prompt for missing traceability information is triggered, to confirm the matching threshold configuration meets expectations.
- View backend logs, confirm whether device information from terminal management platforms and asset systems is successfully associated after the multi-source data association switch is enabled.

The values provided are common starting points and should be measured against the reader's own samples.
