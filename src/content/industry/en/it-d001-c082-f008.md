# Code and Change Review Assistance for Channel Attribution and Lead Distribution: Workflow Orchestration
This document is written based on FastGPT v4.17.0.

## What this category of data looks like
Data for this category primarily comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Daily produced documents include attribution rule configuration tables, lead distribution lists, channel performance reports, and abnormal lead checklists. Most data updates occur on a daily or weekly basis. Fields include channel identifiers, lead unique codes, assigned sales IDs, conversion timestamps, attribution weight values, and more. Some fields are enumeration values, some are numeric values, and there are no unified fixed units.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multi-source data access requirements require splitting workflows into multiple data source nodes to connect to different systems separately, avoiding overly complex single-node configurations. Data update frequency matches daily business cycles, so workflows must support scheduled triggers to adapt to daily or weekly batch data processing. Document structures include rules and reports, so workflows need form nodes for entering custom rule parameters, as well as retrieval nodes to call corresponding documents for validation. The most time-consuming daily tasks—channel parameter verification and duplicate lead deduplication—require adding parameter verification and deduplication nodes to workflows, as well as variable mapping steps to align scattered fields and prevent execution failures caused by parameter mismatches.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variables | `variables` configured as the mapping between channel ID, lead ID, and assigned sales ID | Adapts to multi-data-source field alignment needs, preventing cross-node data mismatches |
| Scheduled trigger node | Trigger on a daily basis | Matches the daily update frequency of this category's data, ensuring processing of the latest attribution and distribution data |
| Form input node | Configured as channel rule entry and abnormal lead marking fields | Matches daily document entry requirements, supporting manual supplementation of data not automatically collected by systems |
| Data source node | Configured separately for advertising platforms, CRM, and attribution SDK | Meets multi-source data access requirements, splitting nodes to reduce configuration complexity |
| Parameter verification node | Verify channel parameter legitimacy, set timeout threshold to 600 seconds | Prevents invalid parameters from entering subsequent processes, the timeout threshold adapts to time requirements of batch data processing |

## Three Common Configuration Mistakes
- Form input fields set in the workflow do not display in the conversation, and the interface interaction content is blank. The cause is that no binding mapping for form fields is configured in `variables`, causing the node to fail to read form parameters.
- The file link configuration item of the AI chat module does not take effect, and the specified attribution rule document cannot be called. The cause is that the unique identifier of the document is not filled in, or the configured file link is not added to the globally accessible knowledge base scope.
- A field empty error occurs during workflow execution, and the assigned sales ID of the lead cannot be passed normally. The cause is that the mapping of this field is omitted in cross-node `variables` configuration, causing data flow interruption.

## How to Confirm the Configuration Is Complete
- Manually trigger the workflow, submit test channel parameters and lead data, and check if the node flow log shows all configured `variables` parameters have been loaded correctly.
- Open the configuration panel of the AI chat module, verify that the attribution rule document pointed to by the file link can be previewed normally, and the user question input box can normally receive input content.
- View the scheduled trigger settings of the workflow, confirm that the trigger frequency matches the data update cycle, and that the settings have been saved and activated.
- Simulate input of invalid parameters, check if the node intercepts invalid channel IDs, and confirm that the verification logic operates normally.
