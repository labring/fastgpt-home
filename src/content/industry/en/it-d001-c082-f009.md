# Code and Change Review Assistance for Channel Attribution and Lead Distribution: Tool Calling and Plugins

## What the Data for This Category Looks Like
Core data for channel attribution and lead distribution comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Most updates occur daily or weekly. Daily processed documents include attribution rule configuration tables, lead distribution lists, channel traffic reports, and abnormal lead checklists. Fields cover channel identifiers, conversion times, lead source parameters, sales attribution IDs, budget allocation amounts, and more. Data structures adjust based on channel type and business rules, with no unified fixed format.

## Constraints on the Tool Calling and Plugins Workflow
Data sources for this category are scattered, and formats are inconsistent. The tool calling workflow must support multi-source API authentication and dynamic field mapping. This adapts to return structures from different channels and systems. Data update frequencies vary. Configure differentiated calling scheduling rules for daily and weekly updated data. Core time-consuming steps rely on automated data comparison. The tool calling workflow must automatically pull attribution rules and lead data for verification. Configure strict parameter verification logic. This prevents subsequent business issues caused by misplaced channel parameters. Errors in this category directly impact business metrics. The tool calling workflow must include failure retry and alert mechanisms. This reduces the impact of anomalies on channel ROI and sales attribution judgments. Match the business scenario to the per-call data volume. This avoids interface timeouts caused by pulling too much data.

## How to Configure Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic selection logic for multi-source plugin calls, matching the calling needs of this category's multiple data sources |
| `functionCall` | `enabled` | Enables structured function calls to ensure accurate delivery of channel parameters and lead fields |
| Plugin API Address | Replace with the exclusive API domain name of the corresponding advertising platform or CRM system | Resolves AxiosError 404 address configuration errors, matching the interface addresses of each data source |
| Calling Timeout | 30–60 seconds | Adapts to batch pull durations for daily updated data, avoiding call interruptions caused by excessive data volume |
| Data Entries Per Call | Top 50–100 entries | Adapts to batch verification scales for lead data, avoiding excessive data returned by interfaces |
| Data Pull Interval | 1 day / 7 days | Adapts to the data update rhythm of this category's daily or weekly updated data |
| Failure Retry Count | 2–3 times | Addresses temporary fluctuations in advertising platform interfaces, reducing verification interruptions caused by single call failures |

## Three Common Configuration Mistakes
- An AxiosError 404 is returned when calling a plugin, and the interface prompts that the API does not exist. The cause is failing to replace the plugin API address with the exclusive domain name of the corresponding data source, and still using the default `api.example.com` placeholder address.
- The channel parameter verification result is empty, and no matching data is returned after tool calling. The cause is failing to configure field mapping rules, causing the plugin to fail to correctly map fields from local documents to fields returned by data sources.
- An abnormal result is returned when calling the BI chart plugin, and the data dimensions do not match expectations. The cause is failing to adjust the calling scheduling rules based on the data update frequency, pulling expired channel report data.

## How to Verify Correct Configuration
Trigger a plugin call manually using the plugin calling log function available in FastGPT v4.17.0. Check if the returned interface status code is 200 to confirm the API address is configured correctly.
Import a test lead data entry. Verify if channel identifiers and sales attribution IDs are correctly mapped after tool calling to confirm field mapping rules are active.
Simulate a temporary exception scenario for the advertising platform interface. Check if the preset retry mechanism and alert logic are triggered to confirm failure handling configurations are active.
View the structured call return results. Confirm that the data format after the `functionCall` parameter is enabled meets the field requirements of attribution rules.
