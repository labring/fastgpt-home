# Code and Change Review Assistance for Channel Attribution and Lead Distribution: Citation Sources and Traceability

## What Data for This Category Looks Like
Data for this category originates primarily from advertising platforms, CRM systems, attribution SDKs, and form systems. Update cycles are mostly daily or weekly. Core daily-produced documents include attribution rule configuration tables, lead distribution tables, channel effect reports, and exception checklists. Document fields include channel identifiers, conversion touchpoints, lead attribution IDs, conversion amounts, check markers, and other fields. Some documents require cross-domain data association across multiple systems, leading to relatively complex structures.

## Constraints for Citation Sources and Traceability
Cross-system data sources require traceability workflows to link original data identifiers across multiple platforms, to avoid bias from single data sources. Daily or weekly update cycles mean traceability workflows must adapt to batch data verification rhythms, and cannot support real-time high-frequency traceability requests. The complexity of document structures requires precise matching of field association relationships during traceability. For example, map lead attribution IDs to CRM sales allocation records to avoid attribution disputes caused by mismatching. Additionally, the presence of exception checklists requires traceability workflows to quickly locate anomalies in original data, to support troubleshooting.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum token count for citation sources | 800–1200 token | Adapts to the typical field length of channel reports and lead distribution tables, avoids truncating critical traceability information. Corresponds to the `quoteMaxToken` parameter |
| Return data includes original sources | Enabled | Meets attribution check requirements for channel attribution and lead distribution, links original data identifiers from advertising platforms and CRM systems. Corresponds to the `responseData` parameter |
| Detail display toggle | Enabled | Shows field details of original data, supports troubleshooting for exception checklists. Corresponds to the `detail` parameter |
| Batch traceability limit | Top 20 records | Matches the processing rhythm of daily batch data, avoids overloading single requests |
| Timeout wait duration | 600 seconds | Adapts to latency across cross-system data pulls, prevents traceability failure due to unreturned data |
| Version compatibility | FastGPT v4.17.0 | Ensures configuration items align with functional logic of the current version |

## Three Common Misconfigurations
- Phenomenon: After configuring the traceability function, only original data links are returned, and no attribution analysis conclusions are generated. Cause: The detail display toggle is not enabled, resulting in only original sources being returned without content integration.
- Phenomenon: Some lead distribution tables do not generate traceable question-answer pairs, and raw text is inserted directly. Cause: No field matching rules for original data are configured, resulting in failure to identify key attribution fields in documents.
- Phenomenon: Testing shows an error after configuration, but the citation function runs normally. Cause: No permission configuration for cross-system interfaces is verified. Test requests trigger permission interception, but formal citations pass identity verification.

## How to Confirm Proper Configuration
- Upload a channel report document, trigger the traceability workflow, and check if the returned results include links and field details of original data.
- Batch upload up to 10 lead distribution tables, and check if the number of traceability results matches the number of uploaded items.
- View the workflow configuration panel, confirm that the switch status for returning data including original sources matches the preset configuration.
- Wait 600 seconds, then check the task status, confirm no timeout error occurs.

The values provided are common starting points and should be measured against the reader's own samples.
