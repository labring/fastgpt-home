# Code and Change Review Assistance for Game Content Compliance Self-Check: Multi-turn Dialogue and Prompt Engineering

## What the data for this use case looks like
The data for this use case primarily comes from game text, story scripts, art assets during game development, and publicly available regulatory compliance requirements. Daily associated documents include content self-checklists, sensitive content modification records, user agreements, and compliance review minutes. Data updates follow game version iterations or event launch cycles, with updates per version or event. The data structure primarily uses text fields, including story lines, scene descriptions, art annotations, summaries of compliance clauses, and more. There is no unified fixed unit; fields are adjusted based on game content type and compliance requirements.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering workflow
Game content compliance self-check data has a high update frequency. Multi-turn dialogue must support syncing the latest version of self-checklists and modification records in context to avoid referencing outdated content. Data sources include both text and art assets, so prompts must adapt to compliance verification logic for both formats, and cannot only cover a single content type. Daily documents include review minutes and modification records, so multi-turn dialogue must support retrieving past review opinions and associating them with the compliance status of current changes. Publicly available regulatory requirements are updated dynamically, so prompts must be configured to sync the latest compliance clauses regularly to ensure accurate verification basis. Additionally, compliance verification fields vary significantly across different games, so prompts must support flexible adjustment of verification dimensions to adapt to the development needs of different game categories.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Game compliance text includes multiple sections such as story content and user agreements, requiring context coverage of the complete self-check document for a single version, and adapting to the context processing rules of FastGPT v4.17.0 |
| `variables` | Bind current version self-checklist ID and event compliance rules | Ensure the dialogue always associates with the exclusive compliance verification basis for the current version, avoiding cross-version confusion |
| `messages` history count limit | First 10 historical dialogue turns | Compliance reviews require access to past modification records. Excessive historical content will interfere with the verification logic for current changes; focus on content related to the most recent two review sessions |
| Conversation timeout period | 600 seconds | Art asset compliance verification requires parsing multiple files, so sufficient time must be reserved for file processing and verification |
| Knowledge base recall limit | Top 5 compliance clauses | The number of publicly available regulatory compliance clauses is limited. Excessive recall will dilute the core verification logic, ensuring prompts focus on the latest compliance requirements |
| `chatId` session identifier | Bind game version ID | Ensure that compliance review dialogue contexts for the same version do not mix with those of other versions, maintaining session consistency |

## Three Common Misconfigurations
- Phenomenon: An error indicating file parsing failure is returned after calling the API to upload art assets or story scripts. Cause: The parsing rule for the corresponding resource format is not configured, or the file size exceeds the preset limit.
- Phenomenon: No compliance self-check questions or verification results are returned after starting a multi-turn dialogue. Cause: The compliance basis document corresponding to the `variables` parameter is not bound, and the prompt lacks the core information required for verification.
- Phenomenon: The test dialogue result within the platform is inconsistent with the result returned by the API call. Cause: The API call does not carry the `messages` historical context parameter, causing the dialogue context to not sync the historical interaction content within the platform.

## How to Verify Proper Configuration
- View the `variables` configuration item to confirm that the current version’s compliance self-checklist and rule documents have been bound.
- Test uploading a single copy of a game story script to check whether multi-turn dialogue guidance related to compliance verification is returned.
- Call the API with the `messages` historical parameter, and compare whether the platform test and API returned dialogue results are consistent.
- Simulate a data change after a version update, and check whether the dialogue context syncs the updated compliance content.

The values given are common starting points and should be measured against the reader's own samples.
