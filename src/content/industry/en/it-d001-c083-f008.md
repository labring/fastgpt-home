# Code and Change Review Assistance for Game Content Compliance Self-Check: Workflow Orchestration

## What Data Looks Like for This Category
Data for this category primarily comes from story scripts, game text, art assets during game development, and publicly released regulatory compliance requirements. Daily associated documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Data updates follow game version iterations or event launch cycles, with one update per version or event. Data fields cover content compliance check items, modification traces, review comments, and more. Field names and units adjust dynamically based on the specific check item type.

## What Constraints These Characteristics Impose on Workflow Orchestration
Data for this category is scattered and updated with version iterations. Workflows must support flexible configuration of multi-source data access nodes to adapt to validation needs for different data sources including story scripts, game text, art assets, and others. Data update cycles are tied to game versions or event schedules. Workflows must support version-triggered startup mechanisms to support full compliance checks for a single version. Associated documents include sensitive content modification records and review minutes. Workflows must support context association nodes to include historical modification traces as validation basis. Additionally, compliance check items adjust dynamically based on regulatory requirements. Workflows must load rules dynamically via `variables` configuration without needing to modify internal node logic each time.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global Variables | Define variables by version and check type, with value ranges including compliance rule libraries and version identifiers, calibrated via actual testing | Adapt to dynamically updated compliance requirements and version-associated data characteristics |
| Parallel Node Configuration | Start three nodes simultaneously: text check, art check, and story script check, calibrated via actual testing | Match multi-source data parallel validation needs for this category, shorten check cycles |
| Conversation Log Association | Bind user session identifiers and version identifiers, calibrated via actual testing | Meet closed-loop traceability requirements for compliance review comments |
| Query Merge Module | Merge compliance check results from multiple nodes, sort by exception priority and display the top N results, with N calibrated via actual testing | Correspond to integrated display requirements for compliance check results |
| Knowledge Base Selection Variable | Data type is text, value range is compliance rule knowledge base | Match user-defined variable configuration needs, adapt to dynamic calls of compliance rules |
| Timeout Setting | Single node execution duration does not exceed 600 seconds | Adapt to the overall cycle of version checks, avoid full workflow interruption due to single node timeout |

## Three Common Misconfigurations
- Phenomenon: After multiple AI conversation nodes are configured, the workflow still executes in serial order with no parallel execution markers. Cause: Parallel node trigger rules are not correctly configured, and the default serial workflow logic is retained.
- Phenomenon: Corresponding version check identifiers cannot be associated in conversation logs, and log fields are empty. Cause: Global variable binding configuration is not enabled, and version identifiers are not associated with log nodes.
- Phenomenon: Custom knowledge base selection variables fail to load compliance rules normally, triggering configuration errors. Cause: The variable data type is not set correctly, and the text-type variable is configured as another format.

## How to Confirm Proper Configuration
- Launch a workflow test, check the node runtime panel, and confirm that configured parallel nodes all enter the running state simultaneously.
- Check the workflow conversation logs, and confirm that each log is associated with a version identifier and check item tags.
- Trigger the query merge module, and confirm that the output results include check data from all configured nodes.
- Edit custom global variables, and confirm that the variable data type matches the storage format of the compliance rule knowledge base.
