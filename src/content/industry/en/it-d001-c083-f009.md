# Code and Change Review Assistance for Game Content Compliance Self-Check: Tool Calling and Plugins

## What the data for this category looks like
The data for this category comes from game text, story scripts, art assets during game development, and publicly available regulatory compliance requirements. Daily associated documents include content self-checklists, sensitive content modification records, user agreements, and compliance review minutes. Data updates follow game version iterations or event launch schedules, with one update per version or event. Data fields cover text compliance keywords, art asset compliance identifiers, story node compliance status, and closed-loop records of review opinions. There are no unified fixed units; adjustments are made according to the field requirements of the corresponding documents.

## What constraints these characteristics impose on the "tool calling and plugins" link
Multi-type data sources require tool calling to adapt to inputs in different formats such as text, art, and scripts, to avoid verification failures caused by format incompatibility. The high-frequency update rhythm requires tool calling to support incremental verification or version-associated caching, to reduce the overhead of repeatedly processing full-volume data. Diverse daily document structures require plugins to support parsing self-checklists and review minutes in different formats, to flexibly adapt to different review scenarios. The business positioning of pre-review requires tool calling to be embedded in the early stages of the development workflow, to ensure that compliance issues are identified before version launch. The high consequences of compliance risks require that the results of tool calling can be traced, and parameter configuration needs to support fine-grained adjustments to reduce the probability of false positives.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the automatic matching needs of multi-type compliance data sources, support triggering corresponding compliance check tools based on input content |
| Tool calling timeout | 300–600 seconds | Cover the time required for compliance checks to traverse multiple texts and story scripts, avoid interrupting the review workflow |
| Result caching strategy | Cache by version granularity | Match the update rhythm per version or event, reduce resource consumption from repeated calls |
| Context retention length | First 2000–3000 characters | Cover the core content of compliance self-checklists and review minutes, avoid truncation of key parameters |
| `functionCall` | Call grouped by compliance check type | Split independent calls for text compliance, art compliance, story compliance, etc., reducing the complexity of a single call |
| Parameter supplement trigger | Trigger by review node | Adapt to the parameter supplement needs of multi-step compliance checks, ensure that tool calls obtain complete verification information |

## Three common mistakes
- Phenomenon: After each compliance check tool call, the model context is truncated, and subsequent review-related content cannot be displayed normally. Cause: No reasonable context retention length is configured, and the tool call return results occupy too much context space.
- Phenomenon: When calling a multi-parameter compliance tool, missing verification parameters cannot be supplemented via workflow questions and answers. Cause: The parameter supplement logic triggered by review node is not enabled, and tool calls only support single fixed parameter input.
- Phenomenon: When the compliance content retrieved from the knowledge base is too long, no rearrangement operation is triggered, causing key information to be overlooked. Cause: No rearrangement trigger rule for long-text compliance content is configured, only the default context truncation logic is relied on.

## How to confirm the configuration is complete
- Trigger a single-type compliance check, verify whether the tool call return result matches the preset compliance data source.
- Submit a multi-parameter compliance check request, confirm whether the workflow can guide the supplement of missing verification parameters.
- Simulate two compliance checks for the same version, confirm whether the result cache takes effect and whether the call duration meets expectations.
- Access the FastGPT v4.17.0 tool call configuration panel, confirm that all setting items have been saved as required.
