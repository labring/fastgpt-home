# Code and Change Review Assistance for Game Content Compliance Self-Check: Citation Sources and Traceability

## What this type of data looks like
Data for this category originates from game text, art assets, plot scripts, and publicly available regulatory requirements. Update frequency follows each version or event cycle. Daily associated documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Data fields include content snippets, modification markers, compliance check results, review comments, and similar items. There are no unified fixed units; adjustments are made based on specific check items.

## What constraints do these characteristics impose on the citation sources and traceability link
The check content for game content compliance self-check is mostly incremental content within a version or event cycle. Citation traceability must accurately match the context scope of a single check to avoid interference from cross-version redundant data. Citations of publicly available regulatory requirements must clearly mark source channels to ensure traceability. Traceability of sensitive content modification records must link original content and modification traces. The lack of fixed units for fields requires flexible adaptation to citations of different content lengths. Additionally, citations of review minutes must correspond to specific check links to avoid confusion between different batches of review comments.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapt to the average length of game plot scripts and text snippets, avoid truncating key context for compliance checks, applicable to FastGPT v4.17.0 |
| `responseData` | Return only knowledge base matching results | Ensure output strictly comes from preset compliance self-check documents, no additional content generated |
| `detail` | Enabled | Fully display field information of citation sources, including content snippets, modification markers, and review comments |
| Single recall limit | Top 3 entries | Match the number of core content for single-version checks, avoid excessive redundant data interfering with reviews |
| Citation matching threshold | 0.85–0.95 | Calibrated based on actual tests, ensure accurate matching of compliance self-check lists and sensitive content modification records |

## Three common misconfigurations
- Phenomenon: Returned compliance self-check results are not linked to any knowledge base source, and citation fields are empty. Cause: The `detail` configuration item is not enabled, and the detailed citation display function is not activated.
- Phenomenon: Knowledge base citation-related variables cannot be selected in workflow nodes. Cause: The citation traceability switch is not enabled in the knowledge base configuration, or the target knowledge base is not bound to the current workflow node.
- Phenomenon: Returned citation content includes redundant data from old versions, exceeding the context scope of the current check. Cause: A reasonable `quoteMaxToken` parameter is not set, or historical data in the knowledge base is not filtered by version cycle.

## How to confirm proper configuration
- Upload a single game plot script snippet to the associated knowledge base, initiate a compliance self-check request, and check if the returned results include the original content snippet.
- View the variable selection panel of the workflow node, confirm that options related to knowledge base citations are available.
- Adjust `quoteMaxToken` to 100 tokens, initiate a test request, and check if the length of the returned citation content matches the set value.
- View the source annotation of the returned results, confirm that identifiers for preset documents such as content self-check lists and sensitive content modification records are included.
