# Code and Change Review Assistance for Game Publication License and Declaration: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category’s data centers on full-process materials for a single game’s publication declaration, including declaration request documents, game application forms, copyright certificates, review reports, and additional relevant items. Data sources include National Press and Publication Administration service guidelines, copyright registration documents, game packages, and materials submitted by operating institutions. Data updates occur irregularly during a single game’s declaration cycle, with supplementary materials added as declaration stages progress. No fixed batch update schedule applies. Individual data fields include declaration subject information, game content descriptions, copyright ownership, review opinions, and other relevant items. Fields must align with declaration requirements, and no unified standardized units exist.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Data for this category originates from multiple dispersed sources and updates irregularly across declaration stages. Multi-turn dialogue must gradually align materials from different stages. The document structure for a single game is inconsistent. Material formats vary widely across different declaration stages. Prompts must adapt to field requirements for each stage. The material consistency check process takes significant time. Multi-turn dialogue must gradually sort out differences between materials. Approval errors can lead to failed approval or delayed game launch. Prompts must strictly match declaration field requirements to avoid missing critical information.

| `chatId` | Bound to the exclusive `chatId` for a single game’s declaration | Enables session isolation, prevents confusion between dialogue data from different declaration projects, and ensures exclusive context for a single game’s declaration. |
| `messages` | Retain the first 20 historical dialogue messages | Adapts to the dialogue context length for a single game’s declaration, avoids exceeding model limits, and is calibrated based on actual testing. |

## Three Common Configuration Errors
- Symptom: The dialogue interface displays a prompt that no knowledge base is selected, but functionality works normally during debug preview. Cause: The knowledge base bound to `chatId` is not correctly associated with the current declaration project’s knowledge base configuration, so the corresponding knowledge base fails to load during formal invocation.
- Symptom: Context is lost during multi-turn dialogue, and previous declaration material check records cannot be retrieved. Cause: The `messages` parameter does not retain enough historical messages, leading to early context truncation and inability to associate previous declaration material information.
- Symptom: Material fields returned by the dialogue do not match the current declaration stage. Cause: Fixed fields for the current declaration stage are not correctly populated in `variables`, so the prompt cannot focus on review requirements for the current stage.
