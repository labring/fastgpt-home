# Code and Change Review Assistance for Game Publication License and Declaration: Workflow Orchestration
This page applies to FastGPT v4.17.0

## What the Data for This Category Looks Like
Data sources include the National Press and Publication Administration service platform, copyright registration system, game package files, and qualification materials submitted by operating institutions. Daily documents include declaration request documents, game publication application forms, copyright registration certificates, and content review reports. The document structure mixes structured forms and unstructured text, with fixed fields such as work identifier, copyright holder information, and review conclusions. The data update rhythm is irregular for each game, with adjustments made along with the declaration process.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Dispersed data sources involving multiple official and local files require workflows to be configured with multiple nodes to pull content from different data sources, plus permission check nodes to ensure compliant data calls.
Mixed structured and unstructured document structures require different nodes to be set in the workflow to handle form field extraction and text review content parsing separately.
Irregular data update rhythms require workflows to support on-demand triggering to adapt to each game's declaration rhythm.
Process errors will cause approval delays or operational qualification restrictions, requiring workflows to be configured with failure retry and exception alert nodes to ensure process stability.

## How to Configure the Workflow
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Store fixed field mappings for each declaration material, such as `{"gameName":"","copyrightHolder":""}` | Used to pass standardized declaration data across nodes, avoiding duplicate entry and format inconsistencies |
| Node trigger condition | Trigger based on upstream node completion status | Adapt to the irregular declaration rhythm of each game, no fixed scheduled execution required |
| Tool call timeout | 600 seconds | Covers the standard response duration of official service platforms |
| Code run node input | First 10 tool call results | Ensure sufficient declaration material information is obtained for content verification and cleaning |
| `nodeId` | Bind the unique identifier of the review report parsing node | Ensure accurate node pointing for data flow in the workflow, avoiding data transfer errors |
| Single file upload limit | 1000 MB | Adapt to the standard size requirements of game packages |

## Three Common Misconfigurations
- Tool call nodes return redundant content. The setup works during debugging, but content wrapped in think tags remains during formal operation. Cause: Complete content cleaning logic is not configured in the code run node, or upstream node output context is not passed via `variables`, causing the code node to fail to correctly receive target data.
- Workflow problem optimization nodes cannot obtain historical declaration records. Cause: `variables` for storing associated fields of historical records are not configured in the workflow, causing the node to fail to read context data from upstream processes.
- Workflows cannot upload and download game packages via HTTP interfaces. Cause: File storage path parameters and permission settings are not configured, and the node's data source is not bound to associate game package files.

## How to Confirm Proper Configuration
- Manually trigger the workflow, check if the declaration fields stored in `variables` match the content of the uploaded game application form.
- After running the tool call node, view the output of the code run node, confirm that the content wrapped in think tags has been removed.
- Trigger the problem optimization node, check if relevant historical declaration data can be read.
- Call the HTTP interface, verify that game package files can be uploaded and downloaded normally.

The values provided here are common starting points and should be measured against the reader's own samples.
