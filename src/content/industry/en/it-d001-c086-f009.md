# Code and Change Review Assistance for Game Publication License and Publishing Declaration: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category comes primarily from the National Press and Publication Administration’s service platform, copyright registration archives, game package files, and qualification materials submitted by operating institutions. Daily processed documents include declaration request files, game publishing application forms, copyright ownership certificates, and content review reports. Data updates follow individual game declaration processes on an irregular schedule. Material copies are generated for each declaration phase. Materials contain structured fields such as ownership ID, package checksum, review opinion identifier, and accompanying unstructured document content.

## Constraints on Tool Calling and Plugins Workflows
Data sources for this category are dispersed. Tool calling must support integration with multiple external data source interfaces to avoid manual cross-platform material copying. Data updates follow individual declaration processes on an irregular schedule. Tool triggering must support on-demand calling, and fixed periodic synchronization is not recommended. Daily processed documents have diverse formats. Plugins must adapt to parsing rules for different document types. Material consistency verification requires cross-data source field comparison. Tool calling must pass clear data source identifiers and permission parameters. Approval processes have strict requirements for material accuracy. Tool calling failures must trigger retries and exception log recording to avoid impacting declaration progress.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `toolChoice` | `auto` or `required` | Determined based on whether tool calling is mandatory for the declaration process. Auto mode adapts to flexible calling scenarios, while mandatory mode ensures tool calling for critical steps |
| Knowledge Base Binding Scope | Only bind the dedicated knowledge base for the current declaration batch | Prevents irrelevant data from interfering with material consistency verification, and meets the requirements for exclusive data per individual declaration |
| Data Source Permission Configuration | Configure read-only permissions per declaration subject, with validity tied to the current declaration cycle | Complies with confidentiality requirements for copyright and declaration materials, and prevents unauthorized access |
| Retry Count | 2–3 times | Balances tool calling success rate and process duration, and avoids excessive retries from consuming resources |
| Timeout Threshold | 300–600 seconds | Adapts to the average response duration for retrieving materials across multiple data sources, and prevents process interruption due to network fluctuations |
| `functionCall` | Enable parameter verification mode | Ensures parameters passed to tools meet the format requirements of declaration materials, and reduces approval failures caused by format errors |

## Three Common Misconfigurations
- Symptom: Tool calling prompts that the knowledge base cannot be found or referenced. Errors persist even after passing global variable configurations. Cause: The knowledge base ID for the current declaration batch was not explicitly passed to tool calling parameters. Only global variables were configured without binding to the specific tool instance.
- Symptom: After configuring a MySQL database connection, executing SQL queries returns empty results or errors. Cause: Read-only permissions for the declaration data source were not configured for the database connection. Or the SQL statement did not match the field format of the declaration materials.
- Symptom: Tool calling responses are delayed or blocked when sending multiple declaration-related requests consecutively. Cause: No concurrency limits were set for tool calling. Multiple requests simultaneously occupy data source interface quotas.

## How to Verify Successful Configuration
- Trigger a single tool call, and check if returned results include exclusive knowledge base data for the current declaration batch.
- Simulate a tool calling failure scenario, and confirm the system triggers the preset number of retries and generates exception logs.
- Access the tool configuration interface, and confirm knowledge base binding scope and data source permissions are set as configured.
- Test sending two declaration-related requests consecutively, and confirm tool calling does not experience blocking or timeout.
