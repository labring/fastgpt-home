# Code and Change Review Assistance for Game Publication License and Publishing Declaration: Citation Sources and Traceability

## What the Data for This Category Looks Like
Core data for this category originates from the National Press and Publication Administration service platform, copyright registration archives, game package files, and operating institution filing materials. Daily processing covers declaration request files, game publishing application forms, copyright ownership certificates, and content review reports. Document length varies widely, ranging from hundreds-word application forms to tens of thousands-word review reports. Data updates trigger irregularly alongside each game’s declaration process. Covered fields include declaration subject information, content compliance descriptions, ownership certificate numbers, and other relevant fields. No fixed batch update cycle exists.

## Constraints on Citation and Traceability
The data characteristics of this category impose multiple constraints on the citation and traceability workflow. Documents have wide length variation, so systems must adapt to both short application forms and long review reports. This prevents critical compliance fields from being split across chunks. Data sources are scattered, so systems must accurately match fields across documents from National Press and Publication Administration filings, copyright registrations, game packages, and other sources. This avoids confusion from cross-source citations. Update timing is irregular, so systems must support dynamic loading of newly submitted declaration materials. Fixed offline data sources cannot be relied upon. Declaration materials for a single game are highly correlated, so citation and traceability must explicitly bind to the exclusive documents of the corresponding project. This prevents cross-project citations that cause material inconsistencies and disrupt approval workflows.

## Three Common Misconfigurations
- Observation: No citation fields appear in model responses returned by the API, and citation content is not displayed on the published terminal. Cause: The configuration items for reranking and returning citation data are not enabled, or the API request does not correctly specify the parameter for returning citation data.
- Observation: Critical compliance paragraphs are incorrectly split when long review reports are chunked, leading to missing core information in citation and traceability. Cause: Only title hierarchy is used as a chunk separator, without adapting to the mixed structure of short application forms and long review reports in this category.
- Observation: Expected single-game declaration materials are not returned after dynamically passing knowledge base variables. Cause: A reasonable similarity threshold is not configured, or exclusive tags for the corresponding project are not bound during dynamic parameter passing, leading to search scope covering irrelevant documents.

## How to Verify Successful Configuration
- Initiate a test query targeting a single game’s declaration materials, and check whether the returned results include metadata fields for citation sources.
- Review knowledge base chunk logs, and confirm that documents of all lengths are correctly split, with no critical fields truncated.
- Validate the dynamic parameter passing function, pass keywords for a specified game project, and confirm that search results only return declaration materials for that project.
- Compare citation data returned by the API with original documents, and confirm that cited content matches source paths accurately.
