# Code and Change Review Assistance for Game Design and Numerical Design: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Daily work documents for this category include gameplay design docs, numerical tables, version requirement sheets, and balance test records. Data sources include player behavior data, public competitor materials, battle logs, and version feedback. Update cycles are typically weekly or per-version. Most document fields are quantitative metrics, including rule parameters, numerical thresholds, resource consumption ratios, and more. Units cover specific quantitative dimensions such as damage values, retention rates, and item output volumes.

## What Constraints Do These Characteristics Impose on the "Multi-turn Dialogue and Prompt Engineering" Link?
Data for this category is scattered and comes from multiple sources. Multi-turn dialogue must gradually align numerical information from different sources like player behavior data and battle logs. This avoids deviations when breaking down rules. The fixed weekly or per-version update cycle requires dialogue context to adapt to version iteration milestones. It must also link to numerical records from historical versions. Most document fields are quantitative metrics. Prompts must clearly specify units and threshold boundaries. This ensures numerical simulations during reviews comply with business rules. Change reviews require tracing back to numerical tables and requirement sheets from historical versions. Multi-turn dialogue must retain context to compare rule differences before and after changes.

## Three Common Misconfigurations
- Dialogue records that exceed the configured retention period can still be retrieved. This happens when the corresponding parameter for dialogue retention duration is not properly configured, or the configured setting does not take effect in the system.
- Sensitive numerical tables in the knowledge base are accessed by unauthorized roles. This happens when knowledge base permissions are not configured by team roles, and full knowledge base access is granted directly.
- Numerical simulation results in multi-turn dialogue have large deviations. This happens when prompts fail to clearly specify units and rule boundaries for document fields. This leads to context recall that mixes numerical parameters from different versions.

## How to Verify Proper Configuration
- Manually create a test conversation, set the retention period to 30 days. Wait for the period to elapse, then confirm whether the record can still be retrieved in the conversation list.
- Switch to an unauthorized role account. Attempt to access the numerical table knowledge base configured with role permissions, then confirm that the corresponding content cannot be retrieved normally.
- Input a test scenario containing multiple historical conversations. Check whether the system truncates redundant context according to the configured `messages` threshold, only retaining content related to the current review.
- Create a new conversation and name the session identifier by version number. Confirm that the conversation list automatically groups all associated conversations by version.
