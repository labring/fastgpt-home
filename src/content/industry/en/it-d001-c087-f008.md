# Code and Change Review Assistance for Game Design and Numeric Design: Workflow Orchestration

## What the data for this category looks like
Daily deliverables for game design and numeric design include gameplay design documents, numeric tables, version requirement sheets, and balance test records. Data sources include player behavior data, public competitor materials, battle logs, and version feedback. Update frequency is weekly or per version. Document fields include damage coefficients, growth curve parameters, rule descriptions, version node identifiers, and others. The field structures of different documents vary significantly. Numeric tables are mostly structured tabular data, while design documents are mostly semi-structured text content.

## What constraints these characteristics impose on the "workflow orchestration" link
Since data updates follow weekly or version-based cycles, workflows must support configuration for scheduled triggers or version node triggers. Document structures vary, so workflows need to adapt parsing rules for structured numeric tables and semi-structured design documents. Data from multiple sources must be connected to different workflow nodes separately to avoid data mixing. The review link must associate all documents for a corresponding version, so global variables must be configured to bind version identifiers to ensure data relevance. Business errors can cause gameplay imbalance or version rework, so workflows must include validation and alert configurations to intercept abnormal changes promptly.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global Variables | Configure `variables` to bind version requirement sheet numbers and current version number | Matches core identifiers of business documents, facilitates association of full-process review data |
| Trigger Node | Trigger based on version submission time, with a `12 hour` delay | Adapts to weekly or per-version update rhythms, reserves time for data collection and organization |
| Tool Call Node | Call a code parsing tool to process the `first 20` numeric table entries | Matches the processing scale of daily single-batch documents, avoids node overload |
| Context Window | Retain `8000–12000 characters` | Covers complete review content for gameplay design documents and numeric tables, reduces information truncation |
| Failure Handling | Bind `nodeId` to point to the alert notification node | Corresponds to the feature that business error consequences are severe, pushes exception reminders promptly |

## Three common mistakes
- Attempting to retrieve a shared application URL via code returns a null value. The cause is that permission parameters for the shared node are not configured in `variables`, resulting in the interface call lacking permission to access the corresponding resource.
- Updated global variables in the workflow do not take effect. The cause is that `nodeId` is not pointed to the correct variable update node, resulting in the configuration not being recognized as a valid update by the system.
- Enabling AI advanced configuration prevents custom prompt words. The cause is that the currently used FastGPT version is lower than v4.9.7. The function can only be used after upgrading to the corresponding version.

## How to confirm the configuration is complete
- Trigger the workflow, then check if the global variables panel correctly displays the bound version requirement sheet numbers and current version number.
- View the running logs of the tool call node, confirm that numeric table entries are correctly parsed and passed to subsequent review links.
- Simulate a version submission to trigger the workflow, verify that alert notifications are sent to the specified channel according to preset rules.
- Confirm that the current FastGPT version is v4.17.0, ensuring advanced configuration and custom prompt word functions work properly.
