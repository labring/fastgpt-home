# Code and Change Review Assistance for Game Design and Numerical Balance Design: Tool Calling and Plugins

## What Data Looks Like for This Category
The work data for game design and numerical balance design mainly comes from player behavior data, public competitor materials, battle logs, and version feedback. Daily delivered documents include gameplay design plans, numerical tables, version requirement sheets, and balance test records. Numerical tables typically contain fields such as damage coefficients, growth curve parameters, and resource consumption ratios, with units involving custom or standard measurement identifiers like percentages, seconds, and counts. Data update frequency is mostly weekly or per version, and the document volume for a single update ranges from a few pages to dozens of pages.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Unlike level content creation scenarios, reviews for game design and numerical balance design rely on real-time numerical and rule verification. The multi-source nature of data requires tool calling plugins to be compatible with different document formats and data sources; for example, structured numerical data extracted from battle logs and unstructured logs of player behavior need separate adaptation of parsing logic. The short-cycle update feature requires the tool calling process to quickly respond to review needs for version iterations, avoiding review delays caused by inflexible configurations. The diversity of fields and units requires the verification rules built into the plugin to recognize non-standard measurement identifiers, preventing review errors caused by unit mismatches. Additionally, the risk of gameplay imbalance and version rework requires the tool calling function to have failure retry and result verification mechanisms to reduce the chance of review mistakes.

## Three Common Misconfigurations
- Phenomenon: Tool calling nodes cannot be connected to code running nodes. Cause: Custom tool configuration permissions are not enabled in the workflow, only direct connections to built-in tools are supported.
- Phenomenon: Call return result fields are empty. Cause: Unit verification rules are not configured, the tool cannot recognize non-standard measurement identifiers in numerical tables, leading to parameter parsing failure.
- Phenomenon: Tool calling triggers a timeout error. Cause: The timeout setting is not adjusted, the default short duration cannot complete complex multi-dimensional numerical simulation calculations.

## How to Confirm Proper Configuration
- Upload a numerical table containing custom units, trigger a tool call, and check whether the return result correctly identifies and verifies the unit fields.
- View the workflow configuration page, confirm that the `toolChoice` and `functionCall` parameters are enabled according to the preset values.
- Simulate the review scenario of a version requirement sheet, call the tool, and check that the number of return results matches the preset single limit.
- Run a complete numerical simulation task, confirm that no timeout error is triggered, and the result matches the expected verification logic.
