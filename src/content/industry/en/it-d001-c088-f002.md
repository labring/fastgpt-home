# Code and Change Review Assistance for Game Operation Activity Configuration: Context and Token

## What the data for this category looks like
Core data for game operation activity configuration comes from operation backends, player segmentation systems, payment data platforms, and activity log systems. Daily produced documents include activity plans, reward configuration tables, launch checklists, and activity post-mortem records. Fields cover activity ID, reward type, distribution thresholds, effective times, player tiering rules, and more. Data update frequency is mostly weekly; emergency updates are triggered by holiday temporary activities.

## What constraints do these characteristics impose on context and token processing
The multi-source data characteristics of game operation activity configuration impose multiple constraints on context and token processing. Large differences in field formats across different systems can easily cause context confusion when directly concatenated. The combination of weekly and emergency update rhythms requires context to support dynamic refresh and temporary expansion. The long-text attributes of reward configuration tables and post-mortem documents quickly consume token quotas. Core links such as reward verification and exception compensation require complete historical context support, and critical information must not be truncated. Additionally, the consequences of errors directly relate to player experience and revenue, so the accuracy and completeness requirements for context are higher than in general scenarios.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Covers full weekly activity configuration data and 3 historical post-mortem records, avoiding truncation of critical verification information |
| `quoteMaxToken` | 1500–2000 characters | Matches the field length of single entries in reward configuration forms, ensuring context integrity during numerical verification |
| Context refresh interval | Every 12 hours | Adapts to weekly update rhythms, avoiding loading expired activity log data |
| Temporary activity context expansion threshold | Calibrated via actual testing | Handles sudden data volumes from holiday temporary activities, automatically adjusting context limits when triggered |
| Global context binding identifier | Activity ID | Ensures isolation of configuration data across different activities, avoiding context confusion |

## Three common misconfigurations
- The interface displays a context length of only 500 tokens, while the actual `maxContext` configuration is 8000 tokens. This occurs because the model's input token limit is confused with the system context storage length parameter, and the scope of action for the two types of configurations is not distinguished.
- `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` cannot be configured in workflow global variables, application API request headers, or the general model management page. This is because these are App/Admin server environment variables, which must be configured during service deployment.
- An error occurs after starting a local deployment, prompting that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are invalid. This is due to one of the following: required App/Admin server environment variables are not configured, the configured parameters do not match the actual root address and administrator token of the local AI Proxy service, or the parameter format contains invalid characters such as extra spaces or quotation marks.

## How to verify a successful configuration
- Upload a single reward configuration table and activity post-mortem record, check the token consumption value in the system context preview panel, and confirm it does not exceed the configured `maxContext` limit.
- Submit a code change review request, check whether the returned results include verification fields from historical activities, and confirm that global context variables have been loaded correctly.
- Test the context loading scenario for holiday temporary activities, observe whether the system automatically triggers the context expansion logic without error prompts.
- Verify the App/Admin server environment variables for local deployment, confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have no format errors, and match the actual root address and administrator token of the local AI Proxy service.
