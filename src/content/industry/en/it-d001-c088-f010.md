# Code and Change Review Assistance for Game Operation Activity Configuration: Citation Source and Traceability

## What This Category’s Data Looks Like
Daily documents for this category include activity plans, reward configuration tables, launch checklists, and activity post-event reviews. Data sources cover operation backend configurations, player segment tags, paid data reports, and activity runtime logs. Update cadence is typically weekly or ad-hoc adjustments ahead of holiday events. Document fields include activity ID, reward type, distribution threshold, trigger conditions, and more. Most units are numeric (such as distribution quantity, timestamp) or enumeration (such as activity status).

## Constraints for Citation Source and Traceability
The diversity of daily documents and data sources demands that citation traceability accurately match fields and versions across different sources. Weekly or ad-hoc update cadence requires linking change records to activity launch times to avoid citing expired configurations. Structural differences across multiple document types require identifying unique identification rules for documents such as activity plans and reward configuration tables during traceability. Differences in data formats across sources require unified conversion before associating citations, to prevent review errors caused by field mismatches.

The following configurations are based on the citation traceability module of FastGPT v4.17.0.

## How to Configure Settings
| Config Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Matches the average length of activity configuration documents to avoid truncating critical cited content |
| `responseData` | Return only the ID and update time of associated documents | Reduces redundant information to fit the lightweight review needs of operation activity configurations |
| `detail` | Display field change records of source documents | Facilitates quick location of timing and content of configuration adjustments |
| Maximum number of citations | Top 3 entries | Focuses on core configuration basis, aligns with efficiency requirements for reviews |
| Retrieval timeout threshold | 600 seconds | Fits the fast review rhythm of activity configurations to avoid excessive waiting |

## Three Common Configuration Mistakes
-  Citation results display configuration documents unrelated to the current activity. This occurs when activity ID is not used as a retrieval filter condition, leading to incorrect recall of cross-activity configurations.
-  Review flows prompt that the citation source does not exist. This occurs when the `quoteMaxToken` configuration is set too small, truncating the source document’s identification information and preventing successful traceability matching.
-  Cited content includes outdated, expired configurations. This occurs when the activity’s update timestamp is not bound, and old version data earlier than the activity launch time is not filtered out.

## How to Confirm Configurations Are Correctly Set
-  Manually enter a keyword for an activity configuration, retrieve citation sources, and confirm returned documents match the current activity’s ID and time range.
-  View the citation traceability detail panel, and confirm the `detail` field displays the most recent change record of the source document.
-  Trigger a change review process, and verify the cited token length is not truncated, aligning with the `quoteMaxToken` setting.
-  Validate the retrieval timeout logic, and confirm the process does not experience abnormal interruptions exceeding 600 seconds when retrieving multi-source data.

The values provided are common starting points and should be measured against the reader's own samples.
