# Code and Change Review Assistance for Player Customer Service and Public Opinion Handling: Source Citation and Traceability

## What Data for This Category Looks Like
Data for this category originates primarily from customer service systems, community forums, app store reviews, and game logs. Daily processed documents include player support tickets, compensation requests, public opinion daily reports, and standardized response scripts.
Update cycles are typically real-time or daily. Core fields include player account identifiers, feedback content, processing progress, and rule bases. There are no fixed, unified units. Data must be aggregated per single feedback or batch daily report dimensions.

## Constraints Imposed by These Characteristics on Source Citation and Traceability
Data sources are scattered, and update cycles vary widely. During traceability, timestamps and unique identifiers from different systems must be matched to avoid cross-source data confusion.
Fields for player support tickets and public opinion content differ significantly. Corresponding recall rules must be configured for each document type to ensure cited content aligns with the original feedback scenario.
Real-time updated game log data must be prioritized for recall to prevent citing expired rules. Compensation rule judgment requires traceability of code changes, so code commit timestamps and change records must be matched.
The traceability scope must also be controlled to avoid introducing redundant data from non-customer service scenarios, which can cause responses to deviate from business goals.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---|---|--- |
| `quoteMaxToken` | 1000–1500 token | Matches the average length of player support tickets and public opinion content to avoid truncating critical cited content |
| `responseData` | Only return reply fields | Ensures outputs use the original reply text from question-answer pairs in the knowledge base, aligning with business standardization requirements |
| Maximum number of citations | Top 3 entries | Controls information density per round of responses to avoid overwhelming players with reading load |
| `detail` | Enabled | Displays document ID and update time of cited sources for quick verification |
| Chunk length | 800–1200 characters | Adapts to the paragraph length of customer service documents to improve recall accuracy |
| Timeout threshold | 300 seconds | Prevents citation failures caused by overly slow data loading |

## Three Common Configuration Mistakes
- Phenomenon: Cited content is returned even when citation configuration items are not enabled. Cause: In FastGPT v4.17.0, priority conflicts exist between some global configurations and knowledge base-specific configurations, and default settings are not correctly overridden.
- Phenomenon: Knowledge base variable reference format is invalid, and the specified dataset cannot be called normally. Cause: The platform-specified variable format is not used, and a non-standard object structure is incorrectly spliced.
- Phenomenon: Complete content cannot be output after citing source data. Cause: The `quoteMaxToken` configuration value is too small, causing cited content to be truncated and unable to be spliced normally, or the `responseData` configuration item is not correctly enabled.

## How to Verify Configuration Is Correctly Applied
- A test question may be submitted, and returned content checked to confirm it only includes original reply text from question-answer pairs in the knowledge base, with no AI-generated extra content.
- Citation markers at the bottom of responses may be reviewed to confirm document identifiers and update times of source data are displayed.
- The value of `quoteMaxToken` may be adjusted to verify that the truncation logic for cited content meets expected behavior.
- Different types of player feedback questions may be tested to confirm only content from the customer service-specific knowledge base is recalled, with no redundant data included.

The values listed above are common starting points and should be evaluated against applicable operational samples.
