# Code and Change Review Assistance for On-Site Deployment Implementation: Context and Token

## What this category of data looks like
Core data for on-site deployment implementation comes from customer data center environments, device inventories, software packages, and network topologies. Daily supporting documents include deployment manuals, installation records, configuration lists, and on-site check-in sheets.
Data updates occur per project or per phase, with new content added dynamically during on-site installation, configuration, and troubleshooting workflows.
Document structures include standardized fields such as version numbers and installation steps in deployment manuals, IP addresses and port numbers in configuration lists, arrival times and customer confirmation signatures on on-site check-in sheets. There is no unified, fixed field format across projects.

## What constraints do these characteristics impose on the context and token workflow
Since data sources are scattered and updated dynamically across project phases, context recall must accurately match the document type for the current phase. Loading irrelevant historical phase data will rapidly consume tokens and slow response speeds.
Single-phase data volume for on-site deployment implementation is limited but has high real-time requirements. The context window must adapt to the actual data scale of individual projects. Fixed configurations for general scenarios cannot be used.
Additionally, the non-standardized document structure requires strict limits on the length of recalled content. Overly long reference content may exceed token limits and cause truncation or failures.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | `8000–12000 token` | Matches the total document data volume for single phases of on-site deployment implementation, and avoids exceeding the default model window of FastGPT v4.17.0 |
| Number of recall matches | Top 6 entries | Corresponds to the number of core documents for on-site deployment, reducing unnecessary token usage |
| `quoteMaxToken` | 2000–3000 token | Limits token usage for individual reference entries, preventing overly long single documents from slowing overall response speeds |
| `maxContext` | Calibrated based on single project phase data volume | Adapts to data update characteristics per project or phase, preventing context overload |
| Reranker model token quota | 1500 token/entry | Matches the average page length of deployment documents, improving the accuracy of recalled content |

## Three common misconfigurations
- Slow question-and-answer response and high token consumption: Response time for code and change review queries exceeds 10 seconds per request. Background logs show token usage exceeds preset thresholds. The root cause is failure to restrict the maximum context range, resulting in loading full non-real-time data such as customer data center environments and device inventories.
- Failed to pull Reranker model ACCESS Token: A token invalid error pop-up appears on the interface. The model fails to start after executing the docker run command. The root cause is incorrect configuration of the model access credential mounting path, or lack of permissions granted to the deployment container for the credentials.
- Truncated knowledge base answer: Simple mode conversations output complete content normally, but content terminates early in review scenarios. The root cause is `quoteMaxToken` set too small, or `maxContext` exceeding the model's supported window limit.

## How to confirm configurations are correct
- Log in to the FastGPT backend configuration page, verify that the values of `maxContext` and `quoteMaxToken` fall within the data volume range for the current project phase.
- Initiate a simulated code change review query, check that response time and token usage stay within preset ranges, with no significant delays or abnormal error messages.
- Test pulling the Reranker model, confirm that the returned token verification result is normal, with no error messages related to invalid credentials.
- Trigger a knowledge base recall operation, check that the number of returned reference documents and individual entry length match configuration requirements, with no excessive irrelevant content or overly long single reference entries.

The values provided are common starting points and should be measured against the reader's own samples.
