# Code and Change Review Assistance for On-Site Deployment: Multi-Turn Dialogues and Prompt Templates

## What Data for This Category Looks Like
This category's data primarily comes from on-site first-hand resources such as customer computer room environments, equipment lists, software packages, and network topologies. Daily associated documents include deployment manuals, installation records, configuration lists, and on-site check-in sheets. Data update cycles follow each individual order or implementation phase, with different configurations and record-type documents corresponding to different phases. Data fields include equipment models, software versions, configuration parameters, on-site check-in information, and more. There is no unified standardized format, and variations exist based on differences in customer on-site environments.

## What Constraints Do These Characteristics Bring to Multi-Turn Dialogues and Prompt Templates
On-site deployment data is updated per order and has highly differentiated scenarios. This requires multi-turn dialogues to bind to the context of a single implementation scenario to avoid mixing data across different orders. There are diverse document types with no fixed structure, so prompt templates must adapt to the field characteristics of different documents, and cannot use generic templates for direct matching. Most data sources are on-site static resources, so the dialogue function must support calling unstructured documents imported locally or on-site, and must limit the context window to avoid loading redundant data. Additionally, implementation personnel often operate in offline or weak network environments, so multi-turn dialogues must support local context caching to avoid reliance on continuous network connections.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Context window size | First 10 dialogue turns + first 8000 characters of imported documents | Matches the phase data volume of on-site deployment orders, avoids exceeding model processing limits |
| Session binding identifier | Generated based on implementation work order number | Prevents context confusion across work orders, aligns with the independent update rhythm of per-order data |
| Variable configuration | Bound to field mappings of deployment manuals and equipment lists | Adapts to the non-fixed structure of on-site documents, accurately extracts required configuration parameters |
| Multi-turn dialogue timeout | 600 seconds | Aligns with the time rhythm of on-site problem troubleshooting, avoids session interruptions mid-process |
| Model selection scope | Includes locally deployed open-source models and connected third-party models | Adapts to FastGPT v4.17.0's multi-model access framework, covers different computing power scenarios for on-site deployment |
| Prompt template | Dynamically switched based on document type | Adapts to the field characteristics of different documents such as deployment manuals and installation records |

## Three Common Misconfiguration Issues
- Symptom: Configured English prompt templates in the interface do not take effect, and returned review suggestions are still in Chinese. Cause: The prompt template was not bound to the session's `variables` parameter, and the system called the default generic template instead.
- Symptom: After multiple consecutive dialogue turns, subsequent replies cannot associate previous equipment list information, and context is broken. Cause: The session binding identifier was not set correctly, resulting in the `chatId` not being associated with the current implementation work order, and context was not persistently stored.
- Symptom: Imported network topology diagrams cannot be parsed, and the text extraction result is empty. Cause: The multimodal input configuration item was not enabled, and only parsing rules for text-based documents were configured, so image-based on-site data cannot be recognized.

## How to Verify Successful Configuration
- Initiate a test dialogue, enter the equipment model of the current implementation work order, and check whether the reply associates field information from the corresponding document.
- Switch the session identifier to another work order number, confirm that the context of the new session does not associate historical data from previous work orders.
- Import deployment manuals and equipment topology diagrams, verify that the parsing results of multimodal inputs cover the required on-site data.
- Continue the dialogue after waiting 600 seconds, confirm that the session does not automatically time out and disconnect, matching the preset timeout configuration.

The values given are common starting points and should be measured against the reader's own samples.
