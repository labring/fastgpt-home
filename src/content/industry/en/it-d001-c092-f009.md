# Code and Change Review Assistance for On-Site Deployment Implementation: Tool Calling and Plugins

## What This Category of Data Looks Like
Data for this category primarily comes from first-hand on-site resources including customer data center environments, device lists, software packages, and network topologies. Updates occur once per order or per phase.
Daily produced documents include deployment manuals, installation records, configuration lists, and on-site check-in sheets. Core fields cover device models, software versions, configuration parameters, and on-site check-in information. There is no unified standard format, and updates must be synchronized with on-site implementation progress.

## Constraints Imposed on Tool Calling and Plugins
On-site deployment data sources are scattered and change per order. Tool calling must adapt to different customers' devices and software versions. Plugins must support dynamic reading of parameters from on-site configuration lists.
Data updates occur once per order or per phase. Tool calling workflows must support real-time pulling of the latest installation records and configuration information, to avoid using expired on-site data.
Most daily produced documents are unstructured text. Plugins must be able to parse deployment manuals and extract configuration parameters, and adapt to format differences of on-site check-in sheets.
Network restrictions in on-site environments may affect tool calling stability. Reserve fault tolerance space to handle sudden network fluctuations.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | auto | Adapt to tool calling needs of different on-site environments, no need to manually specify specific tools, cover diverse deployment scenarios |
| `functionCall` | enabled | Support plugins calling code execution nodes, meet code verification and configuration verification requirements in change reviews |
| Plugin timeout duration | 300–600 seconds | On-site deployment environment checks, software installation and other steps take a long time, need to adapt to long-cycle tool calling scenarios |
| Plugin parameter reading scope | Top 3 installation records | Only the latest 3 on-site installation records are needed to cover the core configuration information of current deployment, avoid interference from redundant data |
| Document parsing threshold | 800–1200 characters | Core configuration paragraphs of deployment manuals are usually this length, can accurately extract valid configuration parameters and filter irrelevant content |

## Three Common Mistakes
- Phenomenon: Interface error occurs after adding Doc2X-type system plugins. Cause: The correct API key and calling address were not configured in the plugin management of FastGPT v4.17.0, causing the plugin to fail to pull the document parsing service normally.
- Phenomenon: Error occurs when clicking the input box after adding a plugin node followed by a code execution node in a workflow. Cause: The `functionCall` parameter was not correctly set to enabled, causing the workflow to fail to trigger the code execution logic after the plugin.
- Phenomenon: Tool calling returns empty results or incorrect number of entries. Cause: The plugin parameter reading scope was not adjusted according to the on-site deployment configuration list, resulting in no valid configuration data being extracted.

## How to Confirm Proper Configuration
- Navigate to the plugin management page, check that configured tool plugins are in normal running status.
- Create a new test workflow, add a plugin node and a code execution node, trigger a test call, and check if returned results contain valid configuration information.
- View workflow logs, confirm that the tool call triggered by the `toolChoice` parameter meets expectations, with no timeout or error messages.
- Import a simulated deployment manual, verify that the plugin can correctly extract core configuration parameters from it.

The values provided are common starting points and should be measured against the reader's own samples.
