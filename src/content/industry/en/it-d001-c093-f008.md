# Code and Change Review Assistance for User Growth and Retention Operations: Workflow Orchestration

## What the data for this category looks like
Daily data sources for user growth and retention operations include user behavior logs, push systems, experiment platforms, and CRM systems. Most updates run on a daily or weekly cadence. Daily produced documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Document fields cover user segmentation tags, outreach time windows, experimental control group data, retention rate metrics, and similar items. Common units include user count, outreach occurrences, time cycles (days), and more.

## What constraints do these characteristics impose on workflow orchestration?
Differing update cadences across multiple data sources require workflows to match corresponding trigger frequencies. This avoids frequent pulls of low-frequency data or delayed processing of high-frequency data. The diversity of document structures requires extraction components in workflows to adapt to mapping rules for different fields. Cross-node field transfer must be implemented via the `variables` configuration. Business attributes tied to data associations require change review links to verify consistency between configurations and business documents. This prevents mismatches between outreach rules and user segments. Errors may lead to user dissatisfaction or wasted budget, so failure handling nodes and validation logic must be configured in the workflow.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind corresponding field mappings by document type | Daily documents include different structures such as user segmentation tables and outreach copy. Matching corresponding extraction fields enables precise invocation |
| `nodeId` | Assign a unique identifier to each data source node | Cross-system data synchronization requires accurate identification of node status to avoid configuration confusion |
| Trigger frequency | Set to daily/weekly triggers based on data update cadence | Data sources update on a daily or weekly basis. Matching the cadence reduces unnecessary calls |
| Failure retry count | 3 retries, 60-second interval | Prevents information extraction failures caused by temporary system fluctuations |
| Global variable validation | Enable required validation only for the current workflow | Prevents inheriting variable rules from previous configurations when switching workflows |
| Knowledge base extraction scope | Bind business-specific knowledge base, extract top 10 matching results | Growth operation documents are mostly concentrated in business knowledge bases. Excessive results increase processing burden |

## Three common mistakes
- Knowledge base information extraction in workflows returns empty. The symptom is nodes returning empty fields. The cause is failure to bind the business-specific knowledge base, or setting the extraction scope beyond the coverage of existing documents.
- Required validation triggers after switching to a workflow without global variables. The symptom is required variable error pop-ups on the interface. The cause is failure to turn off the global variable inheritance switch, leaving configuration rules from the previous workflow intact.
- Workflow saves successfully but configurations are lost after refresh. The symptom is a blank page or disappearance of existing configurations. The cause is refreshing the page before saving completes, or browser cache causing abnormal configuration synchronization.

## How to confirm configurations are set correctly
- Trigger the workflow once, check node logs to confirm the `variables` parameter is passed correctly and matches the document field requirements of the current workflow.
- Switch to another workflow without global variables, confirm no validation rules are triggered and no additional error prompts appear.
- Wait 10 seconds after saving the workflow before refreshing the page, confirm existing configurations are fully retained.
- Extract knowledge base content, verify returned results match the field and unit requirements of business documents.

The values provided here are common starting points and should be measured against in-house samples.
