# Code and Change Review Assistance for User Growth and Retention Operations: Tool Calling and Plugins

## What the data for this category looks like
The business data for user growth and retention operations mainly comes from user behavior logs, push systems, experiment platforms, and CRM systems. Daily produced documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Document structures primarily use structured fields, including user identifiers, behavior timestamps, outreach status, experiment groups, and other fields. Update frequencies are divided into daily and weekly categories. Core metrics are updated in real time or periodically according to business rhythms.

## What constraints these characteristics impose on the tool calling and plugins link
The data sources for this category are scattered and involve multi-system interactions, requiring tool calling to support cross-platform data pulling and integration. Documents primarily follow structured business rules, so tool calling must accurately match specific fields in documents to avoid passing invalid parameters. Differences in update frequencies require tool calling cycles to align with data update rhythms, preventing the use of outdated data. Core time-consuming links are concentrated in user segmentation, outreach rhythm design, and experiment attribution. Tool calling must help shorten the review cycle for these links, while strictly controlling the impact of failure scenarios to avoid user dissatisfaction or reduced retention caused by tool anomalies.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to scenarios where growth operations need to call multiple types of tools, automatically selecting plugins suitable for user segmentation and outreach analysis |
| `functionCall` | `enabled` | Supports using growth experiment parameters as function input parameters, automatically generating structured calls for outreach copy |
| Plugin call timeout threshold | `600 seconds` | Growth operation data pulling involves multi-system interactions; 600 seconds covers the conventional time for cross-platform data synchronization, preventing review failures caused by timeout interruptions |
| Maximum number of plugin return results | `Top 10 items` | The data volume of user segmentation tables and retention reports is usually concentrated in the top 10 core metrics; too many results will increase review time |
| Change review trigger rule | Triggered by code changes to outreach copy and user segmentation rules | Core changes for growth operations are concentrated in outreach logic and user segmentation rules; precise triggering reduces invalid reviews |

## Three common configuration mistakes
- Plugin call no response but points deducted: After submitting a code change, tool calling is not triggered, but platform point records show consumption. The cause is that `toolChoice` is not configured to a valid mode, causing the calling logic to not start, but no pre-check is performed in the point verification link.
- Custom plugins cannot be triggered: Self-developed plugins have not completed access configuration on the platform, and calling instructions in the code cannot be parsed by the platform, causing the plugin to never execute. The cause is failure to follow the platform's plugin access specifications.
- Change review misses core field verification: Tool calling does not map key tag fields of the user segmentation table, causing review results to fail to cover core business rules, the cause is failure to configure field mapping parameters for plugin calls.

## How to verify correct configuration
- Submit a code change that includes user segmentation table fields, check whether the tool call logs of FastGPT v4.17.0 trigger the corresponding plugins.
- Simulate a code submission for outreach copy, check whether the plugin return results include core metric fields for user segmentation.
- Disconnect the network connection of the experiment platform, check whether the preset failure handling logic is triggered to avoid invalid point deductions.
- View the platform's point consumption records, confirm that point consumption only occurs after valid tool calls are completed.
