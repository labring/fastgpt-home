# Code and Change Review Assistance for User Growth and Retention Operations: Citation Sources and Traceability

## What Data for This Category Looks Like
This category’s data primarily comes from user behavior logs, push systems, experiment platforms, and CRM systems. Most updates occur on a daily or weekly basis. Daily output documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Common data fields include user identifiers, outreach channels, experiment groups, retention durations, conversion metrics, and more. There is no unified mandatory format, so fields and structure must be adjusted based on specific business scenarios. This category mainly operates the in-app user lifecycle. Unlike online advertising optimization scenarios, all data focuses on in-app user behavior and business operation results.

## Constraints on Citation Sources and Traceability Processes
The data characteristics of this category impose multiple constraints on citation sources and traceability processes. Decentralized, inconsistently formatted data from multiple systems requires traceability processes to support cross-source field mapping, to avoid confusion between user identifiers and metric data from different systems. Daily or weekly update frequencies require processes to support scheduled pulling or incremental synchronization, to ensure cited content uses the latest business data. Diverse document types and non-mandatory formats require support for custom citation templates to adapt to different document structures such as growth experiment plans and user segmentation tables. Additionally, the most time-consuming links in this category—user segmentation, experiment result attribution, and others—require citation traceability processes to quickly locate associated data, reducing manual verification time. Traceability errors directly impact business outcomes, so processes must accurately bind cited content to its original data source.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.75–0.85 | Matches semantic matching accuracy for user segmentation tables and outreach copy, balances recall and precision |
| Single Search Limit | Top 8 results | Matches the scale of daily updated business data, avoids overloading retrieval resources |
| Reranking | Enabled | Improves recall priority for highly relevant content, adapts to decentralized multi-source business data |
| `quoteMaxToken` | 1200–1800 token | Controls the content length of a single citation, avoids context overflow impacting generation results |
| `detail` | Enabled | Retains complete field information from original citations, facilitates verification of business data sources during traceability |
| `responseData` | Enabled | Retains complete data structure from original retrievals, supports cross-source traceability field mapping |

## Three Common Configuration Mistakes
- Enabling reranking results in empty citations or no search snippets. Cause: The similarity threshold was not adjusted accordingly, and highly relevant content was incorrectly filtered out of the retrieval scope.
- Unable to access custom citation templates or advanced configuration interfaces. Cause: The installed FastGPT version is lower than v4.17.0. Upgrade to the corresponding version before use.
- Field mismatch errors occur during citation traceability. Cause: The `detail` parameter was not enabled, so complete field information from original citations was not retained, making cross-source data verification impossible.

## How to Confirm Proper Configuration
- A test retrieval request should be submitted, and citation sources in returned results should be verified to match the fields and update times of business documents.
- Parameters including reranking and similarity threshold in the configuration interface should be reviewed, to confirm that values matching the scale of business data have been configured.
- A citation traceability report should be generated, and each cited entry should be verified to be bound to the original data source path and update time.
- Citations for long documents should be tested, and the `quoteMaxToken` parameter value should be confirmed to not exceed context limits.

The values provided are common starting points and should be validated against local business samples.
