# Code and Change Review Assistance for User Acceptance Testing Support: Tool Calling and Plugins

## What the data for this category looks like
Typical participants in this category are implementation consultants, test managers, and customer business representatives. The documents they regularly produce and use include UAT test cases, acceptance issue tickets, acceptance reports, and signed confirmation forms. Data sources cover requirement specifications, test environment configurations, customer business samples, and defect management systems. The update frequency is once per phase or version. Document structures are fixed: UAT test cases include scenario, precondition, and expected result fields. Acceptance issue tickets include defect ID, reproduction steps, and severity fields. No additional custom non-standard fields are supported.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources are scattered across multiple systems including requirements, test environments, and customer samples. Tool calling must support associated pull configuration for multi-source data. Since the update frequency is phase or version level, plugins must support incremental synchronization triggered by version. This avoids excessive resource usage from full data pulls. The fixed document structure requirement means tool calling parameters must match fixed fields, with no need for adaptation to non-standard fields. The inclusion of customer business representatives as participants requires plugins to configure role permission verification rules. These rules distinguish access permissions between internal and customer sides.

## How to set configurations
| Config Item | Suggested Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Supports automatic selection of tools adapted for UAT review scenarios, no manual specification required |
| `functionCall` | `[{"name":"fetch_uat_review_data","parameters":{"doc_type":["uat_case","acceptance_issue"]}}]` | Matches the document types of UAT test cases and acceptance issue tickets, accurately pulls target data |
| Single tool call timeout | `600 seconds` | UAT review data pulling involves multi-source association, reserve sufficient response time |
| Data source association scope | Current version associated requirement, test environment, and customer sample data | Limit to valid data from the current phase, avoid redundant content interfering with reviews |
| Synchronization trigger timing | 2-5 days before each version release | Matches the update frequency of this category per phase or version, synchronize the latest data in advance |
| Permission verification switch | Enabled | Adapts to scenarios where customer business representatives participate, distinguish access permissions for different roles |

## Three common misconfigurations
- Phenomenon: Tool calls return a connection error. Cause: Basic parameters for data source integration are not correctly configured. The storage system hosting UAT test cases and acceptance issue tickets cannot be accessed.
- Phenomenon: API call results do not include expected UAT knowledge base content. Cause: The document type for pulling UAT-related content is not specified in the `functionCall` parameter. The tool does not trigger the associated query for the corresponding knowledge base.
- Phenomenon: The acceptance conclusion field returned by the tool call is empty. Cause: The version-triggered synchronization mechanism is not configured. The latest acceptance report data is not pulled.

## How to confirm the configuration is complete
- Access the plugin management page of FastGPT v4.17.0. Review the parameter list of the configured UAT review tool, confirm that the `toolChoice` and `functionCall` parameters are filled correctly.
- Initiate a test call. Verify that the returned results include UAT test cases and acceptance issue ticket data associated with the current version.
- Simulate a version update to trigger synchronization. Verify that the data source automatically pulls the latest acceptance reports and signed confirmation form data.
- Switch to different role accounts to initiate calls. Confirm that the permission verification configuration takes effect, and non-authorized roles cannot access sensitive customer business data.
