# Code and Change Review Assistance for User Acceptance Testing Support: Citation Sources and Traceability

## What the data for this category looks like
Core data for this category comes from four sources: requirement specifications, test environments, client business examples, and defect systems. Update frequency is once per phase or version. Daily produced documents include UAT use cases, acceptance issue tickets, acceptance reports, and signed confirmation forms. The document structure centers on business scenarios, including fields such as use case steps, issue descriptions, acceptance conclusions, and signature information. The length of a single document ranges from hundreds to thousands of characters. The data association logic revolves around the client business confirmation process.

## What constraints do these characteristics impose on the citation sources and traceability link
First, data sources are scattered and linked to client business processes. The traceability link must accurately match specified data sources such as requirement specifications and defect systems, and avoid mixing irrelevant test data.
Second, the update frequency is phase or version level. The timeliness of citations must be tied to the current acceptance phase, and expired historical data cannot be used.
Third, daily documents include signed confirmation forms and other documents with business confirmation validity. The traceability link must retain complete signature identifiers and association relationships to ensure that acceptance conclusions can be traced.
Fourth, the document structure centers on business scenarios. Citations must be associated according to the classification logic of use cases and issue tickets, matching the process order of business confirmation to reduce the time spent on reproduction and classification.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the single-paragraph citation length requirements for UAT use cases and acceptance issue tickets, avoids truncating critical business information |
| `responseData` | Return only associated document metadata | Filters redundant test environment raw data, focuses on requirement specifications and defect system content related to acceptance |
| `detail` | Full | Retains signature identifiers on signed confirmation forms and conclusion fields of acceptance reports, ensuring complete traceability information |
| Single search limit | Top 5 entries | Matches the association density of client business examples, avoids returning too many irrelevant data |
| Maximum context | 10 associated data entries | Covers the update data volume per phase or version, ensures citations cover all valid documents within the current acceptance cycle |

## Three Common Misconfigurations
- Phenomenon: Unassociated non-acceptance document links appear in returned content. Cause: `responseData` is not set to return only associated metadata, resulting in mixing of irrelevant test environment raw data.
- Phenomenon: Citation source fields are empty or lack signature identifiers. Cause: `detail` is not configured to full mode, and the unique traceability identifier of the signed confirmation form is not extracted.
- Phenomenon: The number of returned citations exceeds the expected limit. Cause: The single search limit is not configured, pulling too many defect system data leading to chaotic traceability results.

## How to confirm the configuration is correct
- (Under FastGPT v4.17.0) Initiate a query related to a UAT use case, check if the returned citation sources only include specified category documents such as requirement specifications and acceptance issue tickets.
- Check the token usage of the citation area, confirm it falls within the 800–1200 token range.
- Check if the citation sources include the unique identifier field of the signed confirmation form, verify that the `detail` configuration is effective.
- Trigger a query after a version update, confirm that the update time of the cited data matches the current acceptance phase.
