# Code and Change Review Assistance for Community Report Handling: Multi-turn Dialogue and Prompt Engineering

## What this category of data consists of
This category of data typically originates from community report systems, content detail pages awaiting review, user historical behavior records, and official audit rule libraries. Daily generated documents include report work orders, report processing records, user appeal forms, and standardized user notification templates. Data updates occur in real time or daily. Each data entry contains fields such as work order ID, associated content ID, report subject information, disposal status, and timestamp. There are no additional unified statistical caliber fields.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
This category processes specific user-submitted report content on a per-work-order basis. Multi-turn dialogue must bind `chatId` to associate the full context of a single report work order, preventing information confusion across work orders. Since data updates are real-time or daily, prompt engineering must support real-time retrieval of the latest audit rule library content to ensure disposal judgments align with current standards. Daily documents include appeal forms and historical processing records, so multi-turn dialogue must support retrieving past disposal information for a specified work order. It is also necessary to limit the context length of `messages` to avoid loading excessive redundant data unrelated to the current work order, which would reduce response efficiency. The `variables` parameter must pass the exclusive identifier of the current work order to provide precise contextual support for the prompt.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Dialogue context limit | Top 10 historical messages | Process report work orders individually, avoid cross-work-order context interference |
| `chatId` binding rule | Bind current report work order ID | Ensure multi-turn dialogue only associates processing records for the current work order |
| `messages` context truncation threshold | Conversation messages within 600 seconds | Match the real-time response rhythm of report processing, prevent redundant data loading |
| `variables` parameter configuration | Pass current work order ID and associated content ID | Provide exclusive context for prompts for individual reports |
| Prompt real-time update switch | Enabled | Adapt to real-time update requirements for audit rules |

## Three common mistakes
- Phenomenon: After calling multi-turn dialogue, `chatId` is empty, and content return time exceeds 600 seconds. Cause: The `chatId` of the current report work order is not correctly bound, causing the system to load a large amount of irrelevant contextual data.
- Phenomenon: Execution error occurs after configuring the database connection plugin. Cause: The `variables` parameter does not correctly pass the authentication information required for database connections, or the permission scope for database calls is not declared in the prompt.
- Phenomenon: Empty results are returned when searching a specified collection in the knowledge base. Cause: The identifier of the target collection is not specified in the prompt, or the `messages` context does not carry the pre-instruction for collection queries.

## How to verify correct configuration
- Initiate a test report work order, start a conversation in the FastGPT v4.17.0 environment, and confirm that the conversation only loads historical processing records for this work order, with no redundant information from other work orders.
- After passing the `variables` parameter, check whether the prompt correctly calls the associated content ID and audit rules for the current work order.
- Trigger conversation context truncation, and confirm that historical messages older than 600 seconds are not loaded into the current conversation.
- After enabling the prompt real-time update switch, modify the audit rules and verify that the conversation uses the latest rules for judgments.
