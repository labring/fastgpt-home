# Code and Change Review Assistance for Community Report Handling: Tool Calling and Plugins

## What Data for This Category Looks Like
This category of data comes from community report systems, content details pages awaiting review, historical behavior records of reporting users, and official audit rule libraries.
Daily produced documents include report tickets, report processing records, user appeal forms, and standardized user notification templates.
Data updates occur in real time or on a daily basis.
Core fields include unique report identifiers, associated content IDs, report types, processing statuses, disposal results, and associated user information.
No additional statistical quantitative fields are included.

## Constraints for Tool Calling and Plugin Workflows
This category processes specific user-submitted report content on a per-ticket basis.
Data sources are scattered and update flexibly. Tool calling must adapt to permission and pull logic across multiple data sources.
Fixed document structures require tool input parameters to strictly match the field formats of report tickets and processing records. Parameter mismatches cause data pull failures.
Real-time or daily updated data requires tool calling timeout thresholds to align with actual data pull durations.
Each tool call only processes a single report ticket. This prevents cross-ticket data confusion.

## Configuration Guidelines
This document is written based on FastGPT v4.17.0. The following are configuration references for tool calling and plugins:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` or specified as `["preLogin", "getReportTicket"]` | Automatically selects the pre-login interface and report ticket pull tool. Adapts to pre-verification and data pull requirements for community report handling |
| `functionCall` | Allow function calls | Must call the preLogin interface to complete pre-verification, then call the report details pull tool to obtain data required for processing |
| Tool call timeout duration | `600 seconds` | Community report data may require pulling from multiple sources. Reserve sufficient interface response time to avoid interrupting the processing flow due to timeout |
| Single tool call limit | `1 time` | This category processes report tickets on a per-ticket basis. Each call only needs to pull data related to a single report. Prevents cross-ticket data confusion |
| Function call parameter validation | Enable mandatory validation | Ensure that the formats of parameters such as report IDs and user identifiers are correct. Avoid tool call failures caused by parameter errors |

## Three Common Misconfigurations
- Tool calls return a 400 status code with no body. The symptom is an interface response with no content and a 400 status code. The cause is usually failure to first call the preLogin interface to complete pre-verification, or incorrect format of the passed report ID parameter.
- Tool calls do not trigger the preLogin interface. The symptom is failure to pull detailed data for report tickets. The cause is failure to configure `toolChoice` to automatically call the pre-verification interface, or failure to add preLogin to the allowed function list.
- Function call performance is poor. The symptom is that model-generated tool call parameters do not match actual requirements. The cause is failure to optimize function call prompt words based on the field structure of report tickets, or failure to limit the `functionCall` scope to only community report-related tools.

## How to Verify Proper Configuration
- Submit a test report ticket to simulate a real request. Call the tool chain. Check if the preLogin interface is automatically triggered and returns valid verification results.
- View tool call logs. Confirm that each call only pulls data related to a single report. No cross-ticket data is included.
- Test the parameter validation function. Pass a report ID with an incorrect format. Check if a parameter error prompt is triggered and tool calls are blocked.
- Adjust the `toolChoice` configuration to manual specification. Confirm that the tool only calls preset community report-related functions. No unrelated calls are made.

The values provided are common starting points and should be evaluated against the reader's own samples.
