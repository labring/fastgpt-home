# Code and Change Review Assistance for Community Report Handling: Citation Sources and Traceability

## What This Category of Data Looks Like
This category of data typically comes from community reporting systems, content detail pages pending review, user historical behavior records, and built-in audit rule libraries. Daily processing relies on documents including report tickets, disposal progress records, user appeal forms, and standardized notification templates.
Update frequency is mostly real-time or daily. Single data entries include fields such as report identifier, associated content ID, reporter and reported party information, violation type tags, and disposal results. There is no unified fixed unit; values vary based on individual content and operation steps.

## Constraints Imposed by These Characteristics on the "Citation Sources and Traceability" Link
Since data sources for this category are scattered and single tickets link to multi-dimensional content, citation traceability must cover original report content, historical disposal records, and built-in audit rules. This requires support for associated calls across multiple data sources.
Real-time or daily update rhythms require the traceability link to have low-latency data pulling capabilities, to avoid delays in the disposal process.
Field differences across different document types require unified data extraction mapping rules during configuration, to prevent citation failures caused by field mismatches.
Additionally, the single-ticket processing business characteristic requires that traceability results only link to the current report ticket, to avoid cross-ticket data confusion that impacts disposal accuracy.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Max citation token count | 800–1200 token | Adapts to the total length of multi-document content linked to a single report ticket, avoids exceeding model context limits |
| Data pull timeout | 600 seconds | Adapts to real-time report data pull requirements, prevents disposal interruptions from data delays |
| Return data scope | Only include report tickets, disposal records, audit rules | Focuses on core business data for this category, reduces resource usage from irrelevant content |
| Detail field switch | Enable full field display | Ensures extracted fields cover key information such as report identifier and associated content ID, meets traceability verification needs |
| Single recall count | Top 3 associated data entries | Matches the single-ticket processing business feature, only calls associated data for the current report ticket, avoids cross-ticket interference |
| Context recall threshold | Calibrate based on actual testing | Adapts to content density and report volume across different communities, ensures relevance of recalled data |

## Three Common Misconfigurations
- Phenomenon: The interface displays the `quote type error` error, and citation configuration cannot be completed. Cause: Data mapping is not configured according to the field format of the report ticket, causing the system to fail to recognize the passed variable type.
- Phenomenon: Citation results only return a single data entry, and cannot cover multi-source report associated content. Cause: The single recall count configuration is not adjusted, only single-category data is called, failing to cover multi-dimensional content such as tickets, records, and rules.
- Phenomenon: Citation content does not include associated file address information, or the knowledge base source display cannot be hidden. Cause: The detail field switch is not enabled to extract the file address field in the content details, or the default source display switch is not turned off, resulting in redundant information.

## How to Confirm Proper Configuration
- Confirm that the current FastGPT v4.17.0 version supports the selected configuration items.
- Submit a test report ticket, check whether the reply content includes core fields such as ticket ID and disposal records.
- Check system logs to confirm there are no field matching errors of the `quote type error` category.
- Verify the token consumption of the cited content, ensure it does not exceed the configured maximum citation token count range, and only links associated data for the current test ticket.
