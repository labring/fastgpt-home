# Code and Change Review Assistance for Mobile Development: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes primarily from code repositories, app store backends, crash monitoring platforms, and device coverage data. Common associated documents include end-version release notes, device adaptation lists, crash analysis reports, and app store submission materials.
Data updates follow daily synchronization or per-version release schedules. Fields vary across documents:
- Code repositories contain commit records and change diffs
- App store backends track released versions and review statuses
- Crash monitoring platforms store exception stacks and triggering device models
- Device coverage data marks system version distribution for each device model

## Constraints Imposed on Tool Calling and Plugins
Decentralized data sources and update cycles that shift with version releases require tool calling to support asynchronous fetching and incremental synchronization across multiple sources.
Large differences in fields across daily documents require plugins to support custom field mapping. This adapts to different formats, such as version numbers in end-version release notes and device lists in adaptation lists.
Associated calls between crash analysis reports and device coverage data require the toolchain to support cross-platform data context association. This avoids calling failures caused by inconsistent data source formats.
Plugins related to app store reviews must strictly follow review workflow trigger timing. They must not interfere with core daily code review processes.

## How to Set Up Configurations
The following configurations are based on FastGPT v4.17.0 interface and parameter rules. They apply to mobile development code and change review assistance scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Set to `auto` | Adapts to multi-tool calling scenarios where mobile development needs to automatically match code diff, crash monitoring, and app store data |
| `functionCall` | Enabled | Used for structured extraction of permission calls and device adaptation entries in code changes. This matches standardized field requirements for review documents |
| Knowledge base binding method | Pass the knowledge base ID bound to a global variable | Adapts to daily needs of cross-device teams reusing device adaptation and crash troubleshooting knowledge bases |
| Data source synchronization cycle | Calibrated based on actual testing (10-30 minutes) | Matches daily or per-version update cycles. Balances data timeliness and resource usage |
| Tool call timeout threshold | 600 seconds | Adapts to time requirements for cross-platform data fetching. Avoids call interruptions caused by large volumes of device coverage data |

## Three Common Configuration Mistakes
- A prompt indicates the knowledge base cannot be referenced when invoking a workflow, with empty returned fields. The cause is either failing to correctly bind the knowledge base ID to a global variable, or failing to synchronize the global variable configuration to the workflow's tool calling step.
- SQL extraction results fail to run after configuring a MySQL database connection. The cause is either failing to set correct data source permissions for mobile development code repositories or crash data scenarios, or failing to match connection parameters to the corresponding database port and access whitelist.
- Generation is interrupted or delayed when sending review requests consecutively. The cause is either failing to set a reasonable tool call timeout threshold, or configuring `toolChoice` to force lock a tool, resulting in resource preemption that prevents timely response to new review requests.

## How to Confirm Configuration Completion
- Trigger a tool call for a code change review. Check if returned results include mobile development-related review fields such as code diffs and device adaptation items.
- View tool call logs. Confirm that incremental data within the data source synchronization cycle has been fetched normally, with no timeout errors.
- Test whether the knowledge base bound to the global variable can be normally referenced by the workflow. Verify that structured extracted fields meet the format requirements of review documents.
- Initiate two review requests consecutively. Confirm that tool calls can respond normally, with no obvious delays or interruptions.
