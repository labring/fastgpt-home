# Code and Change Review Assistance for Cybersecurity Level Protection Assessment Consulting: Workflow Orchestration

## What the data for this category looks like
The data for this category comes from scanning results of assessment tools, on-site interview records, asset system inventories, and security device logs. Core daily output documents include classification determination reports, gap analysis reports, rectification plans, and assessment reports. Data is updated once per project or annually. Data fields cover control item numbers, gap item descriptions, rectification measures, evidence material association numbers, and similar items. There are no unified fixed units; values adjust dynamically based on the technical requirements of specific assessment items.

## What constraints these characteristics impose on the "workflow orchestration" link
Scattered data sources with diverse formats require workflow orchestration to include multi-source data import nodes that adapt to raw data in different formats. Data updated per project requires workflows to support project-level isolation of `variables` to avoid cross-project data confusion. Core document fields adjust based on assessment items, requiring workflows to include custom field mapping nodes to adapt to document structures for different projects. The severe consequences of errors require workflows to add pre-check links to verify control item gap check results and rectification evidence completeness, blocking abnormal data from entering subsequent processes. Additionally, time-consuming sorting and checking links require workflows to include built-in automated matching nodes to reduce manual operations. ## Three common mistakes
- Symptom: Unable to generate a standard JSON file when attempting to export a workflow, or exported content lacks node configurations. Cause: The JSON export option was not enabled in workflow settings, or configuration parameters for all nodes were not saved.
- Symptom: Cannot find the text processing module in the local workflow editor, but the module exists when importing a JSON workflow shared by others. Cause: The local editor did not enable the permission switch for the corresponding function, or the imported workflow contains module configurations incompatible with the current version.
- Symptom: When binding a workflow in the robot configuration interface, only a single workflow can be called, and multiple independent workflow nodes cannot be added. Cause: The robot's workflow call rules were not configured correctly, and the multi-workflow binding function was not enabled.

## How to confirm the configuration is complete
- Import multi-source test data, check if nodes can correctly parse raw files in different formats, and confirm that field mappings match the structure of core documents.
- Run the workflow and trigger the check link, view whether the check result can correctly identify abnormal data, and confirm that the pre-check function is active.
- Attempt to export the workflow in JSON format, check the integrity of the exported file, and confirm that the export function works properly.
- Bind workflow nodes in the robot configuration interface, verify that the call process for multiple workflows runs smoothly, and confirm that the multi-workflow binding function is active.
