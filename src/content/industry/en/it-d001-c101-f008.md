# Code and Change Review Assistance for Renewal Health Management: Workflow Orchestration

## What the Data for This Category Looks Like
Renewal health management business data typically comes from four sources: CRM systems, product usage data backends, customer service ticket statistics, and contract ledgers. The update frequency is weekly or monthly. Daily processed documents include customer health reports, renewal forecast sheets, high-risk customer lists, and customer communication notes. Document structures contain fields such as customer identifiers, contract cycles, usage metrics, risk tags, and renewal intentions. No unified, fixed single-size format exists, and some documents may contain nested sub-item data. This content is compatible with FastGPT v4.17.0 and later versions.

## What Constraints These Characteristics Impose on Workflow Orchestration
Data from multiple sources requires configuring multiple independent data source nodes to pull data separately, to avoid data confusion or pull failures. The weekly or monthly update rhythm requires that workflow trigger cycles match data update cycles; excessively frequent execution intervals are not recommended. Diverse document structures require configuring flexible field mapping rules to adapt to field differences across different documents. Large-volume contract ledgers or high-risk customer lists require configuring loop processing logic to avoid exceeding system load thresholds during single execution. Cross-system data pulling also requires considering timeout risks caused by network latency, so node execution timeout parameters should be set appropriately.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger cycle | Once weekly or once monthly | Matches the weekly or monthly update rhythm of renewal health management |
| Data source node configuration | Connect to the service addresses of CRM, product usage data, and ticket statistics separately | Adapts to multi-source data pulling requirements |
| Field mapping rules | Match data source return fields according to business document fields | Ensure extracted data is consistent with business document structures |
| Node execution timeout | 600 seconds | Addresses latency issues during cross-system data pulling |
| Loop body parameters | Set single-loop processing entries according to single-batch data volume | Process large-volume contract ledgers or high-risk customer list data |

## Three Common Misconfigurations
- Symptom: A database connection timeout error occurs during workflow execution, and ETIMEDOUT is displayed in the interface. Cause: Network access rules for cross-system data sources are not properly configured, or the timeout threshold is set too low.
- Symptom: Workflow startup verification fails, prompting that a required environment variable is missing. Troubleshooting steps: Verify whether the App/Admin server has configured AIPROXY_API_ENDPOINT (root address of the AI Proxy service) and AIPROXY_API_TOKEN (AI Proxy administrator Token, consistent with the AI Proxy server configuration and cannot be empty), and that the variable values are not empty.
- Symptom: The loop body executes abnormally and cannot process multi-layer nested business data structures. Cause: The nested level rules of the loop body are not properly configured, or the nested field structure of the business document is not matched.

## How to Confirm the Configuration Is Complete
- Verify the environment variable configuration on the App/Admin server, and confirm that AIPROXY_API_ENDPOINT (root address of the AI Proxy service) and AIPROXY_API_TOKEN (AI Proxy administrator Token, consistent with the AI Proxy server configuration and cannot be empty) have been correctly added and are not empty.
- The workflow can be manually triggered once, execution logs reviewed, and confirmation secured that all data source nodes have successfully pulled corresponding data.
- Field mapping results of the workflow can be reviewed to confirm that extracted data fields fully match the fields of the business document.
- Large-volume data processing via the loop body can be tested to confirm that no timeout or abnormal interruption occurs during execution.
