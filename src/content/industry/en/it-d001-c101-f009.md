# Code and Change Review Assistance for Renewal Health Management: Tool Calling and Plugins

## What the data for this category looks like
This category of data typically comes from CRM systems, product usage dashboards, ticket statistics ledgers, and contract management archives. Data update cycles are mostly weekly or monthly. Core documents include customer health reports, renewal forecast sheets, high-risk customer lists, and cross-department communication minutes. Data fields include customer unique identifiers, contract cycle milestones, product usage frequency in recent cycles, ticket response times, contract amount ranges associated with renewals, etc. There is no unified mandatory format, and adaptation to internal enterprise customer management standards is required.

## What constraints these characteristics bring to the tool calling and plugins workflow
The data characteristics of this category impose multiple constraints on the tool calling and plugins workflow. First, data sources are scattered and formats are inconsistent. Plugins that support structured parsing of multiple data sources must be configured to adapt to field formats from different sources such as CRM and product usage data. Second, data updates occur weekly or monthly. Tool trigger cycles must match the data update rhythm to avoid frequent calls to outdated, unupdated data. Third, core documents include non-standardized communication minutes. Tools that support natural language semantic parsing must be enabled to automatically extract high-risk customer tags and follow-up actions from these minutes. Additionally, data fields must match internal enterprise customer management standards. Tool calling parameters must support custom field mapping to prevent abnormal results caused by field mismatches.

## Configuration Guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts to different risk identification scenarios, no need to manually specify specific tools |
| `functionCall` | Enabled | Supports structured output of risk classification results for subsequent automated processing |
| Single data pull limit | Top 100 entries | Matches the batch processing scale of weekly or monthly data, avoids overload from single calls |
| Trigger cycle | Once per week | Matches the weekly data update rhythm, prevents repeated calls to unupdated data |
| Field mapping rules | Configured according to internal enterprise customer management standards | Adapts to field differences across scattered data sources, ensures accurate data parsing |
| Timeout threshold | 600 seconds | Matches the time required for multi-data-source parsing, prevents task failure from parsing timeouts |

## Three Common Misconfigurations
- Symptom: An error is returned when calling `functionCall`, or no deployed large model can trigger tool calls. Cause: A proxy tool that does not support `functionCall` is used, and the adapted call chain is not switched to.
- Symptom: Tool calls time out, and tasks are terminated by the system. Cause: The set timeout threshold is too short, and does not match the actual time required for multi-data-source parsing.
- Symptom: Pulled data fields do not match expectations, leading to deviations in risk classification results. Cause: Field mapping rules matching internal enterprise customer management standards are not configured, and default field parsing is used directly for scattered data sources.

## How to Verify Proper Configuration
- View tool call logs to confirm that the `functionCall` parameter is correctly identified and there are no error messages.
- Manually trigger a tool call and verify that the number of pulled data entries matches the set single pull limit.
- Check the field mapping results to confirm that the pulled data fields match internal enterprise customer management standards.
- Wait for a full trigger cycle to confirm that the tool runs automatically at the preset rhythm with no abnormal interruptions.
