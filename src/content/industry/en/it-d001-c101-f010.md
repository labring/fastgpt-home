# Code and Change Review Assistance for Renewal Health Management: Citation Sources and Traceability

## What Data for This Category Looks Like
The data for the renewal health management category primarily originates from CRM systems, product usage data, ticket statistics ledgers, and contract ledgers. Update frequencies are mostly weekly or monthly. Daily produced documents include customer health reports, renewal forecast sheets, high-risk customer lists, and customer communication minutes. Fields across individual documents include customer unique identifiers, contract expiration dates, product usage frequency, ticket response time, and more. There is no unified field standard across documents, so association and traceability must be completed using customer identifiers.

## What Constraints Do These Characteristics Impose on the Citation Sources and Traceability Process
The data characteristics of this category impose multiple constraints on the citation sources and traceability process. First, data sources are scattered across multiple systems, so the traceability process must support cross-data-source association matching to avoid relying on a single source that cannot cover risk judgment basis. Second, update frequencies are weekly or monthly, so cited data sources must be limited to the latest versions within the current contract cycle to prevent distorted judgments from expired historical data. Third, daily document types are diverse and fields are inconsistent, so the traceability process must configure classified search rules based on document types to ensure accurate identification of source identifiers for different documents.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 5 entries | Matches the typical number of entries in high-risk customer lists, avoids retrieval overload |
| `quoteMaxToken` | 1200–1800 token | Adapts to the single-page content length of renewal forecast sheets, ensures complete citation of core data |
| `responseData` | Enable return | Used to associate traceability identifiers for ticket statistics, supplements source detail information |
| Maximum Context | 6000 characters | Accommodates integrated content from multiple customer health reports, supports cross-document citation |
| `detail` | Enable detailed traceability | Displays specific document paths for data sources, meets traceability verification requirements |
| Field Mapping Rules | Calibrated via actual testing | Adapts to field differences between CRM and product usage data, ensures accurate association |

## Three Common Misconfigurations
- The symptom is that after increasing the value of `quoteMaxToken`, the generated result does not include any citation source identifiers. The cause is that the `detail` parameter was not enabled simultaneously; the system only completed data recall but did not bind source traceability information.
- The symptom is that the citation field is empty and no source description is included in results returned via external API calls. The cause is that the `responseData` parameter for returning traceability data was not enabled, so the interface does not expose source association information.
- The symptom is that after cross-document association search, traceability results include historical data across cycles. The cause is that the search time range was not configured according to document update frequencies, resulting in accidental recall of expired data.
