# Code and Change Review Assistance for Defect Management and Regression Testing: Source Citation and Traceability

## What Data for This Category Looks Like
This category of data primarily comes from defect management systems, test reports, code commit records, and user feedback. Daily produced documents include defect tickets, regression checklists, repair verification records, and defect statistical reports. Data updates occur daily or per version release cycle. Data fields include unique defect identifiers, associated version numbers, code commit hashes, reproduction steps, priority, repair status, verification results, and more. Field naming varies across different data sources.

## How These Characteristics Impact Source Citation and Traceability
Data sources are scattered and formats are inconsistent. Traceability functions must support associating data sources across multiple systems to avoid information silos.
Data is updated per version or daily. Traceability functions must support filtering scope by version number and commit time, to return only content relevant to the current review.
Document lengths for defect tickets, regression checklists, and similar items vary widely. Traceability functions must limit returned context length to avoid disrupting review judgments.
Field naming differs across data sources. Traceability functions must support mapping unified identifier fields, such as defect IDs and code commit hashes.

## Configuration Guidelines
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average content length of defect tickets and regression checklists, prevents context overflow from disrupting reviews |
| `responseData` | `Include defect ID, version number, commit hash` | Accurately locates defects and code changes associated with the current review, ensures traceability information is traceable |
| `detail` | Enabled | Displays complete information for defect reproduction steps and repair verification records, meets detailed review requirements |
| Citation source filter scope | Filter by version number, commit time | Aligns with the version-based update pattern of data in this category, limits valid traceability scope |
| Number of traceability results returned per request | Top 3–5 entries | Avoids excessive redundant information interfering with review judgments, focuses on core relevant content |

## Three Common Misconfigurations
- Symptom: Traceability results do not include defect IDs and their corresponding version numbers. Cause: The `responseData` parameter is not configured to specify required return fields, leading to traceability information that cannot be accurately linked to specific defects.
- Symptom: Traceability content generated by the model is excessively truncated, with critical defect reproduction steps missing. Cause: The `quoteMaxToken` value is set too small, failing to match the actual content length of defect tickets and verification records.
- Symptom: Traceability data cannot be filtered by the current review's version number, returning irrelevant defect information from historical versions. Cause: Version-based filtering for citation sources is not configured, defaulting to full data search which cannot match the current review's version range.

## How to Verify Successful Configuration
- Code change reviews can be initiated, and generated traceability results checked for core identifier fields such as defect IDs and version numbers.
- The `quoteMaxToken` parameter can be adjusted, and traceability content truncation verified to meet expectations with no critical information missing.
- Defect data can be filtered by a specified version number, and traceability results confirmed to only return defects and test records for that version.
- Generated traceability information can be checked for complete defect reproduction steps and repair verification details.

The values provided are common starting points and should be evaluated using samples relevant to the specific deployment.
