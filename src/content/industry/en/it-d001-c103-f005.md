# Code and Change Review Assistance for Art Asset Production Management: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data for this category primarily comes from art asset libraries, project management systems, engine resource packages, and outsourced delivery packages. Daily circulating documents include art requirement sheets, asset specification sheets, outsourced feedback sheets, and acceptance records. Document fields include role numbers, scene dimensions, texture resolution, rework items, acceptance scores, and more. Some documents include units such as pixels, polygon counts, and frame rates. Data update frequency is daily or weekly, adjusted according to the rhythm of asset production, outsourced delivery, and project acceptance.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Scattered data sources require multi-turn dialogue to integrate cross-system context, avoiding missed specification requirements from project management systems or rework feedback during reviews. Diversity of document fields and units requires prompts to clearly adapt to different document formats, preventing review errors caused by field mismatches. Fluctuating data update frequencies require prompts to regularly synchronize the latest asset specifications, ensuring timeliness of review basis. Errors can lead to resource mismatches and performance overrun, requiring multi-turn dialogue to automatically verify field consistency and intercept non-compliant asset changes in advance.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| ---|---|--- |
| `messages` | Retain the first 20 turns of dialogue context | Art asset review context mostly consists of specifications and rework records; 20 turns covers a single review cycle |
| `variables` | Bind permission variables for art asset libraries and project management systems | Automatically pull application-related data under specified accounts, reducing manual entry errors |
| `chatId` | Generate a unique session ID linked to the project ID | Ensure review dialogue contexts for the same project do not interfere, avoiding cross-project data confusion |
| Maximum context length | 8000–12000 characters | Adapt to long text content of art asset documents, avoiding truncation of critical specification parameters |
| Image recognition toggle | Set based on actual testing | Must match multimodal model capabilities and adapt to asset preview image formats exported by engines |
| Attached file display | Disabled | Aligns with FastGPT v4.17.0 configuration logic, adapting to concise review scenarios |

## Three Common Misconfigurations
- Symptom: After uploading an asset preview image, the model cannot provide image content. Cause: Image recognition permission is not enabled in the multimodal model configuration, or the prompt does not declare support for image input parsing.
- Symptom: Dialogue replies automatically include an attached file list at the end, which cannot be disabled. Cause: The attached file display toggle is not turned off in the chat node configuration, or the prompt does not explicitly require hiding attached content.
- Symptom: Prompt content for a specified application under a specified account cannot be retrieved. Cause: `variables` are not configured to bind permission parameters for the target account, or the session ID is not linked to the authorization information of the corresponding application.

## How to Verify Successful Configuration
- Upload an asset preview image exported by an engine, initiate a test dialogue, and check whether the model correctly parses the image content and generates corresponding review suggestions.
- Configure `variables` to bind the target application for a test account, initiate a query for "get current application prompt", and check whether the corresponding content can be pulled normally.
- Initiate a test dialogue containing art requirement sheet fields, and confirm no extra attached file list appears at the end of the reply, verifying the display toggle is disabled.
- Switch between different project IDs to generate `chatId`, initiate two independent review dialogues, and verify the contexts of the two sessions do not interfere with each other.
