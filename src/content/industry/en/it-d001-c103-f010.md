# Code and Change Review Assistance for Art Asset Production Management: Citation Sources and Traceability

## What Data for This Category Looks Like
Daily documents for this category include art requirement sheets, asset specification sheets, outsourcing feedback forms, and acceptance records. Document fields cover asset ID, version number, delivery status, specification parameters, and more. Data sources include internal art asset libraries, project management systems, game engine resource directories, and outsourcing delivery packages, most of which are compressed format resource files. Data update frequencies are split into daily synchronized asset library changes, and weekly updated outsourcing acceptance and feedback records.

## What Constraints Do These Characteristics Impose on the "Citation Sources and Traceability" Link
The multi-source mixed data structure requires the traceability link to distinguish different data formats between internal asset libraries and outsourcing deliveries. This avoids confusing compressed package metadata with structured documents. Differences in fields across documents require configuring matching recall rules by document type. For example, extract polygon count and texture resolution parameters from asset specification sheets, and obtain version numbers and delivery times from acceptance records. Differences in update frequencies require setting incremental recall time windows. This prevents recalling expired outsourcing feedback older than one week. Severe error consequences require that traceability results accurately associate resources of the corresponding version. This stops older version assets from being mixed into the current review process.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of a single art asset document, to avoid truncating critical specification parameters |
| `responseData` | Includes asset ID, version number, source type | Corresponds to the field structure of each data source, to facilitate displaying traceability information in review results |
| `detail` | Enabled | Supports recalling repair details from outsourcing feedback forms, for use as a basis for change reviews |
| Single search limit | Top 6 entries | Covers multiple acceptance records and delivery packages associated with a single art requirement |
| Similarity threshold | 0.65–0.75 | Distinguishes asset specifications of different versions, to avoid recalling mismatched resources |
| Version compatibility | FastGPT v4.17.0 | Ensures functional compatibility between variable configuration and context recall |

## Three Common Configuration Mistakes
- When directly entering a knowledge base ID or reference variable, the output is consistent, and an error occurs when applying the variable to the knowledge base. The symptom is that knowledge base invocation fails after configuration variable replacement, returning a parameter error status code. The root cause is failure to bind the permission scope of the corresponding knowledge base in variable configuration, or the variable format does not meet the requirements of FastGPT v4.17.0.
- Historical conversations cannot be directly referenced. The symptom is that the historical conversation module cannot be dragged into the citation traceability link, or empty fields are returned during calls. The root cause is failure to enable the context recall switch for historical conversations, or the link configuration does not associate the conversation storage node.
- The number of cited entries cannot grow with parameter adjustments. The symptom is that after adjusting the similarity threshold and single search limit, the number of recall results remains fixed. The root cause is failure to enable incremental recall mode, or vector index sharding of the art asset library limits the single recall upper limit.

## How to Confirm the Configuration Is Complete
- Submit a test art requirement review request, check whether the output result includes traceability information of asset ID and source type.
- Adjust the `quoteMaxToken` parameter value, verify whether the truncation length of the output content matches the configuration.
- Simulate expired outsourcing delivery package data, confirm that recall results do not include content older than the update cycle.
- Trigger the variable replacement operation, verify that the knowledge base call normally returns the specification documents of the corresponding asset.
