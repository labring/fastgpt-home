# Code and Change Review Assistance for Landing Page Conversion Optimization: Context and Token

## What the data for this category looks like
Core data for landing page conversion optimization comes from landing page access logs, heatmaps, form data, and ad source parameters. Daily associated documents include landing page plans, tracking requirements, AB test reports, and form field lists.
Data update frequency is weekly or adjusted per single campaign cycle. Fields include page path, dwell time, form submission status, ad channel ID, and more. Units are mostly seconds, count, and characters.

## What constraints these characteristics impose on the context and token link
Data sources for landing page conversion optimization are scattered, with complex association logic. Integration of ad source parameters and page behavior data is required, so context must bind associated information across multiple document types.
Data update frequency adjusts with campaigns. Context must support dynamic refresh to match the latest tracking or test reports.
Single campaign document lengths vary widely, ranging from short form field lists to complete AB test analyses. Token usage fluctuates significantly. Strict control of total context length and token share per reference is required to avoid exceeding model limits.
The most time-consuming steps for this category include page path analysis, form blockage troubleshooting, and experiment result judgment. Errors directly impact ad delivery effectiveness. Missing context or token overrun causes analysis bias, leading to lead loss and cost increases.

## Configuration Settings
| Config Item | Recommended Value | Rationale |
| --- | --- | --- |
| Max Context Window (`maxContext`) | 8000–12000 token | Matches total length of landing page-related documents, covers all associated data for a single campaign, and does not exceed context limits of most open-source models |
| Quote Max Token (`quoteMaxToken`) | 1500–2000 characters | Corresponds to typical length of single tracking data or form field list, ensures complete extraction of key business information and avoids truncating core content |
| Single Recall Count | Top 6 entries | Matches number of documents for weekly campaigns, avoids context overload causing model inference delay |
| Context Update Cycle | Per campaign cycle | Matches update rhythm of landing page campaigns, ensures latest plans and test reports are loaded when each campaign launches |
| Single Document Chunk Length | 800 characters | Adapts to paragraph structure of landing page plans, preserves logical connections between content, and avoids breaking business context via chunking |

## Three Common Misconfigurations
- Phenomenon: Search results fail to associate context for the current landing page, and returned analysis is unrelated to the campaign. Cause: Landing page access logs and ad source parameters are not bound to the context of the search request, only independent query keywords are used.
- Phenomenon: Code review prompts token overrun, and change review process is interrupted. Cause: The value of `maxContext` is not restricted, and all historical campaign documents are loaded into the current context, exceeding the token limit supported by the model.
- Phenomenon: Privately deployed applications cannot be accessed via the specified path, and the page returns a 404 error. Cause: The application access context path is not correctly set in FastGPT configuration, causing route matching failure.

## How to Confirm the Configuration Is Correct
- Log in to the FastGPT v4.17.0 backend, enter the context settings panel in application configuration, and confirm that the values of `maxContext` and `quoteMaxToken` match the preset configuration.
- Import a complete landing page campaign document, trigger the retrieval function, and check that the returned context includes associated information such as ad source parameters and form field lists.
- Trigger a code review process, view the number of loaded documents and token usage of the context, and confirm that they fall within the preset configuration range.
- Access the privately deployed application, verify that the application interface loads normally via the /fastgpt path, and confirm that the route configuration takes effect.
