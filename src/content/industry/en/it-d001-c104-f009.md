# Code and Change Review Assistance for Landing Page Conversion Optimization: Tool Calls and Plugins

## What the data for this category looks like
The core data sources for landing page conversion optimization include landing page access logs, heatmaps, form data, and ad source parameters. Daily associated work documents include landing page plans, tracking requirements, A/B test reports, and form field lists. These materials are organized and archived per single campaign or weekly basis.
Data fields include page paths, dwell time, form submission records, ad channel identifiers, and more. The update rhythm follows the campaign cycle or weekly execution, with no fixed mandatory update frequency requirements.

## What constraints these characteristics impose on the "tool calls and plugins" workflow
Multiple scattered data sources require tool calls to support integration with different types of data source interfaces. Tool calls must also bind the exclusive data range of the corresponding campaign to avoid cross-campaign data confusion.
The update rhythm per campaign or weekly means tool calls should not use overly short trigger intervals. The interval must match the data update cycle to avoid invalid pull requests.
The strong binding between daily documents and data requires tool calls to associate campaign metadata from documents. This ensures quick location of corresponding data basis when reviewing code or changes.
Errors can lead to lead loss or inability to attribute data. Tool calls must therefore be configured with failure retry and exception alert mechanisms.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to calling requirements for different data sources, automatically selects appropriate tool execution logic |
| `functionCall` | `enabled` | Enables function call capability forcibly, ensuring the tool can pull landing page-related data from external data sources |
| Data source binding scope | Bind the exclusive landing page data source for the current campaign | Matches the daily campaign-based document management habit, avoiding cross-campaign data interference during reviews |
| MCP service access address | Fill in the MCP service address corresponding to the landing page data source | FastGPT v4.17.0 natively supports MCP service integration, enabling quick connection to external data sources |
| Call trigger cycle | `Every 24 hours` | Matches the weekly or single-campaign data update rhythm, reducing invalid pull attempts |
| Number of failure retries | `3 times` | Covers common exceptions such as temporary network fluctuations, preventing review interruptions caused by a single failed call |
| Result filtering threshold | `Top 10 entries` | Focuses on core data such as page paths and form submissions, simplifying information processing during review sessions |

## Three common misconfigurations
- Symptom: Landing page data fields returned after the call are empty. Cause: The data source range for the corresponding campaign was not bound, so the tool cannot pull matching business data.
- Symptom: The console returns the `The dollar ($) prefixed field '$schema'` error. Cause: An illegal field starting with $ was accidentally added when configuring tool call parameters, which does not meet the platform's parameter format requirements.
- Symptom: The tool call cannot be triggered successfully via the curl command. Cause: The API request parameter format was not correctly spliced, or the allowed call source whitelist was not configured.

## How to confirm the configuration is complete
- View the tool call log panel to confirm that there are data pull records for the corresponding campaign.
- Initiate a test call to verify that the returned results include expected landing page-related fields such as page paths and form submission records.
- Simulate a call failure scenario to confirm that the system triggers the preset retry mechanism.
- Enter the historical call log panel of the knowledge base to confirm that detailed records of the corresponding tool call can be viewed.
- Check the associated landing page documents to confirm that the tool call can correctly match the document metadata for the corresponding campaign.

The values listed above are common starting points. Adjust them based on your own specific samples and use cases.
