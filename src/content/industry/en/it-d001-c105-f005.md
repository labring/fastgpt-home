# Code and Change Review Assistance for License Compliance and Copyright Statements: Multi-turn Dialogues and Prompt Engineering

## What This Category's Data Consists Of
Data for this category originates from code repositories, dependency lists, license texts, and contribution records. Updates are triggered on each version release or each dependency change. Routine compliance deliverables include LICENSE files, NOTICE files, dependency license lists, and copyright statements. Data fields cover license types, copyright attribution entities, dependency names, and version identifiers. No custom units are used. All data is updated in sync with code and dependency iterations.

## What Constraints Do These Characteristics Impose on Multi-turn Dialogues and Prompt Engineering
Data for this category is scattered and updated frequently. Multi-turn dialogues must pull content from distinct data sources such as code repositories and dependency lists in sequence. Full context must be retained to connect verification logic across all steps. Standardized compliance deliverables require prompts to precisely match the structure of LICENSE, NOTICE, and similar files, to avoid non-compliant output. For high accuracy requirements, multi-turn dialogues must confirm key details such as copyright attribution and license compatibility in stages. Full validation cannot be completed in a single dialogue. Outdated dependency and license data must be avoided.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |

| Timeout Duration | 600 seconds | Pulling data such as dependency lists and license texts may involve multiple repository nodes. A sufficient timeout prevents verification interruptions |
| Single Retrieval Result Count | Top 5 entries | Key compliance information for this category is concentrated. A small number of precise results improves verification efficiency |
| Variable Passing | Pass dependency list path, LICENSE file address | Data for this category originates from code repositories and dependency lists. Variables enable calls to up-to-date real-time data |
| Prompt Template | Written in three stages: copyright confirmation, license compatibility, NOTICE updates | Compliance workflows for this category are fixed. Staged prompts precisely match verification needs for each stage |

## Three Common Mistakes
- Dialogue return results are not wrapped in the specified format. This occurs when output format requirements are not clearly stated in the prompt, leading to failed structured extraction of compliance content.
- After upgrading to FastGPT v4.17.0, an error `fail to create post presigned url` is displayed when uploading attachment files. This occurs because pre-signed URL expiration parameters for S3 storage are improperly configured, preventing attachment loading.
- Connection timeout errors appear in the dialogue window. This occurs when the timeout duration is set below 600 seconds, which prevents completion of multi-repository compliance data pulling and verification workflows.

## How to Verify Proper Configuration
- Initiate a test dialogue that includes a dependency list query, and verify that returned results match the preset data source content.
- Trigger a multi-turn verification workflow, and confirm that dialogue history is fully retained, enabling review of verification records across all stages.
- Upload test LICENSE and NOTICE files, and confirm that files load normally and are recognized by the prompt.
- Initiate a batch dependency verification request, and confirm that no connection timeout errors occur. Adjust the timeout duration to a range that meets business requirements.
