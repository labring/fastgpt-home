# Code and Change Review Assistance for Speech Annotation and Transcription: Workflow Orchestration
This page’s configuration is based on FastGPT v4.17.0.

## What the data for this category looks like
Data for this category primarily comes from pending audio files, intermediate results from annotation platforms, industry-specific term lists, and spot-check quality control samples. Daily associated documents include transcription specifications, audio batch lists, quality inspection reports, and speaker annotation forms. Data updates follow a daily or single-batch audio task schedule. Core data consists of structured transcribed text. Audio-to-text conversion must be completed first, followed by steps such as speaker differentiation and proprietary term proofreading. The overall process relies on collaboration across multiple document and data sources.

## What constraints these characteristics impose on workflow orchestration
Data characteristics of this category impose multiple constraints on workflow orchestration. Audio data sources require the workflow to support format verification and pre-transcription nodes to prevent invalid audio input from entering subsequent processes. The daily or single-batch update rhythm requires the workflow to support triggering by task batches, adapting to single or bulk task requirements. Multiple types of associated documents require the workflow to configure multi-variable reference and verification logic to ensure synchronized updates of resources such as transcription specifications and term lists. Core time-consuming steps must be split into subtask nodes, enabling orchestration of steps such as noise segment judgment and speaker differentiation to ensure overall process efficiency.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Associate three types of variables: audio list, transcription specifications, and term lists | Adapt to bulk call requirements for multiple data sources, match daily/batch update rhythms |
| Node trigger condition | Trigger transcription nodes after audio format verification passes | Prevent invalid audio input from entering subsequent processes, reduce redundant computation |
| Batch task threshold | Process 100–200 audio files per single run | Balance server load and task processing efficiency, calibrated based on actual testing |
| `nodeId` | Assign independent identifiers to noise segment judgment and speaker differentiation nodes | Facilitate locating abnormal nodes during change reviews, quickly troubleshoot transcription errors |
| Variable reference scope | Support combined multi-variable reference | Adapt to verification requirements for multiple documents such as transcription specifications and term lists, resolve limitations of single-variable reference |
| Single-node timeout setting | 600 seconds | Adapt to time requirements for long audio transcription and complex verification, calibrated based on actual testing |

## Three common mistakes
- Symptom: Incorrect assignment of global variable parameters when calling APIs, causing transcription nodes to fail to read audio lists. Cause: Parameter mapping was not configured according to batch task variable rules, and variable formats for single tasks and bulk tasks were confused.
- Symptom: Knowledge base reference results returned after workflow operation do not comply with transcription specifications, and abnormal reference sources cannot be located. Cause: Independent `nodeId` was not assigned to the knowledge base verification node, making it impossible to quickly trace reference logic during change reviews.
- Symptom: Only a single variable can be selected from the drop-down menu, and transcription specifications and term lists cannot be referenced simultaneously. Cause: The combined multi-variable reference configuration option was not enabled, failing to adapt to business requirements for multi-document verification.

## How to confirm the configuration is complete
- Invoke the test API, submit a single audio file and associated variables, and verify that the transcription node triggers normally and returns structured text.
- Review the workflow node list, and confirm that core nodes such as noise segment judgment and speaker differentiation are configured with independent `nodeId`.
- Open the variable reference configuration interface, and verify that multiple variables including transcription specifications and term lists can be selected simultaneously.
- Submit a bulk test task, and adjust the batch task threshold and single-node timeout setting based on actual operating conditions.
