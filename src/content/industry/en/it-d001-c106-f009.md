# Code and Change Review Assistance for Speech Annotation and Transcription: Tool Calling and Plugins

## What the Data for This Category Looks Like
Core data for the speech annotation and transcription category comes from audio files, annotation results exported from annotation platforms, custom term lists, spot check samples, and similar sources. Daily produced documents include transcription specifications, audio delivery lists, quality inspection reports, speaker annotation sheets, and more. Data update frequency is mostly daily updates or updates per delivery batch. The most time-consuming core links of this category are noise segment judgment, speaker differentiation, and custom term proofreading. Errors in these links can lead to recognition training deviations, transcription rework, or delivery delays. Unlike text annotation categories, audio content must first be converted to structured text before subsequent annotation work can begin.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
The raw data for audio transcription has a large volume, and custom term list verification is required, so tool calling must adapt to the context requirements of batch audio processing. Data updated per delivery batch requires tool calling to support triggering tasks per batch, to avoid reprocessing already annotated content. Time-consuming links such as noise segment judgment and speaker differentiation require tool calling to reasonably allocate computing resources, to avoid single request timeouts. The output format of structured text must align with the fields of the annotation platform, and tool return results must include accurate speaker identifiers, custom term matches, and similar information, to ensure the subsequent annotation process can be directly reused.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to variable custom term verification and speaker differentiation scenarios in speech annotation, automatically selecting appropriate tools to perform tasks |
| Tool call timeout threshold | 600 seconds | Matches the average processing duration of time-consuming links such as noise segment judgment and speaker differentiation, to avoid request interruptions |
| Maximum number of audios per single request | 10 | Adapts to the scale of audio lists delivered per batch, balancing request load and processing efficiency |
| Maximum content volume per single request | 800–1200 characters | Adapts to the text length after transcription of a single audio file, to avoid exceeding system processing limits |
| `functionCall` | Enable mandatory format validation | Ensures structured text returned by tools meets the field requirements of the annotation platform, reducing subsequent verification costs |

This configuration applies to FastGPT v4.17.0.

## Three Common Mistakes
- Phenomenon: Direct calls to the model API respond quickly, but response delay increases significantly after configuring tool calling in FastGPT. Cause: The timeout threshold was not adjusted for the time-consuming links of speech annotation, or the content volume per single request was not set reasonably, leading to insufficient system resource allocation.
- Phenomenon: Tool call return results lack speaker identifiers or custom term matches. Cause: Mandatory format validation for `functionCall` was not enabled, and field requirements of the annotation platform were not aligned.
- Phenomenon: Tool calling and knowledge base search cannot be linked, and custom term lists cannot be called for proofreading. Cause: The custom term list in the knowledge base was not correctly bound to the tool calling process, preventing the tool from obtaining the required thesaurus data for verification.

## How to Confirm the Configuration Is Complete
- Upload a single audio file containing custom terms, trigger tool calling, and check whether the return result includes accurate speaker identifiers and custom term matches.
- View the tool call log to confirm that the duration of a single request does not exceed the preset 600-second threshold.
- Test triggering tool calls per delivery batch, and check whether only unannotated audio files are processed, with no duplicate calls.
- Compare the structured text returned by the tool with the format of the speaker annotation sheet, confirming that the fields are aligned consistently.

The values provided are common starting points and should be measured against the reader's own samples.
