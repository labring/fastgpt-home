# Code and Change Review Assistance for Speech Annotation and Transcription: Source Citation and Traceability

## What data belongs to this category?
Data for speech annotation and transcription originates from audio files, annotation platforms, custom vocabulary lists, and spot-check samples. Daily output documents include transcription specifications, audio inventory lists, quality inspection reports, and speaker annotation tables. Data updates occur daily or per annotation batch.
This category first converts audio content into structured text. Core time-consuming steps include noise segment identification, speaker differentiation, and custom vocabulary verification. Errors here may lead to recognition training deviations, transcription rework, or delayed deliveries.

## What constraints do these data characteristics impose on the source citation and traceability process?
The data characteristics of this category create multiple constraints for the source citation and traceability workflow.
First, data sources include audio files and annotation metadata. Traceability links must associate information such as audio IDs and annotation batch numbers to ensure retrieval results can be traced back to original data sources.
Second, the presence of multiple daily document types requires retrieval systems to distinguish between different document types such as transcription specifications and quality inspection reports, to match code and change review scenario requirements.
Third, the batch or daily update rhythm requires regular refreshes of knowledge base indexes to avoid retrieving expired annotation data.
Fourth, the structured text conversion logic requires retrieval matching to account for the correspondence between audio segments and transcribed content. Relying solely on plain text keyword matching cannot cover full traceability requirements.

## How to configure the settings?
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of speech transcription text, avoids truncating custom vocabulary and speaker annotation information |
| `responseData` | Includes audio file path, annotation batch number, quality inspection report ID | Associates retrieval results with original audio data sources to meet traceability requirements |
| `detail` | Enables full field return | Displays associated content such as transcription specifications and speaker differentiation rules to assist code review |
| Single search limit | Top 5 entries | Matches the spot-check sample size for a single batch of speech annotations, controls retrieval overhead |
| Maximum context window | 600 seconds | Corresponds to the total duration of a single batch of audio, ensures full coverage of the retrieval scope |
| Reranking threshold | 0.75–0.85 | Calibrated through actual testing, matches the text similarity characteristics of speech transcription |

This configuration applies to FastGPT v4.17.0.

## Three common misconfigurations
- Phenomenon: Retrieval results only return 1 knowledge base citation, and cannot match multi-document scenarios. Cause: `quoteMaxToken` is not adjusted to fit multi-document text length, or the single search limit is set too low to cover multiple document types such as transcription specifications and quality inspection reports.
- Phenomenon: The knowledge base selection is empty after import, and the target knowledge base must be selected manually. Cause: `responseData` is not configured to associate the knowledge base with imported audio inventory metadata, causing the system to fail to automatically match the preset knowledge base.
- Phenomenon: Cited content cannot be downloaded, or returns empty fields. Cause: `detail` full field return is not enabled, or the maximum context window is set too short, truncating associated quality inspection reports and annotation table information.

## How to confirm the configuration is correctly set
- Initiate a search for custom vocabulary, check if returned results include citations for multiple document types such as transcription specifications and quality inspection reports.
- Import preset audio inventory and annotation batch data, confirm if the system automatically associates the corresponding knowledge base without manual selection.
- View the details page of retrieval results, confirm if traceability fields such as audio ID and annotation batch number are included.
- Test batch retrieval of multiple batches of speech data, check if the number of returned citations matches the set single search limit.

The values provided are common starting points and should be measured against the reader's own samples.
