# Code and Change Review Assistance for Account Ban and Appeal Review: Multi-turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
The core data for this category comes from risk control systems, audit records, user behavior logs, and report evidence. Update frequency is mostly real-time or daily. Daily processed documents include structured ban records, appeal materials, review opinions, and user notifications. Common fields include account ID, violation type, appeal submission time, audit status, disposal result, etc. There are no unified fixed units, and fields are dynamically adjusted based on platform risk control rules, with significant differences between platforms.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Because data is updated in real time or daily, multi-turn dialogue must support real-time retrieval of the latest ban records and appeal materials to avoid misjudgments caused by using outdated information. As document fields are dynamically adjusted based on platform rules, prompts must be adapted to parse non-fixed structure fields, reduce hardcoding dependencies, and improve versatility. The high-risk nature of account-level review requires verifying the consistency of core variables such as account ID and violation type during dialogue, to avoid incorrect cross-account associations. At the same time, multi-turn dialogue must gradually guide users to supplement appeal materials, reduce information overload in a single input, and improve process efficiency.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current account appeal session | Ensure multi-turn dialogue context is tied to the corresponding account's appeal process, avoiding cross-session confusion |
| `messages` | Retain the first 20 rounds of dialogue content, calibrated via actual testing | Balance context completeness and response speed, avoiding delays caused by overly long context |
| `variables` | Store globally fixed variables such as account ID, violation type, and appeal submission time | Enable reuse of core information across rounds, eliminating the need to repeatedly ask users |
| Single search limit | Top 3 results | Match the typical number of violation evidence items to verify in a single review, avoiding interference from excessive redundant information |
| Maximum context | 8000–12000 token | Adapt to the multi-dimensional information needs of account ban review, while controlling response delay |
| Similarity threshold | 0.75–0.85 | Precisely match the relevance between appeal materials and historical violation records, reducing false match rates |

## Three Common Misconfigurations
- Phenomenon: Inconsistent results from knowledge base retrieval triggered by dialogue, with some rounds failing to return the current account's exclusive ban records. Cause: `chatId` is not bound to the session context, so the system cannot associate the corresponding account's exclusive knowledge base data, and randomly calls the general knowledge base or returns no matching results.
- Phenomenon: Globally fixed variables such as account ID are lost after multiple rounds of dialogue, requiring repeated user input. Cause: The `variables` configuration item is not used to store global variables, and variables are only stored in temporary dialogue context, which is automatically reset for each new round.
- Phenomenon: Response delay increases significantly after multiple rounds of dialogue, with a single knowledge base retrieval taking more than 60 seconds, while new sessions return to normal. Cause: The number of retained `messages` rounds is not limited, leading to overly long context that requires the system to process excessive historical content, and the single search limit is not configured, resulting in retrieval of redundant data.

## How to Verify Proper Configuration
- Initiate a new account appeal dialogue, enter the account ID and violation type, and confirm that this information can be directly reused in subsequent rounds without re-entry.
- Launch 3 consecutive dialogue rounds, check that each knowledge base retrieval returns the current account's exclusive ban records, and confirm consistent retrieval results.
- Launch 10 consecutive dialogue rounds, observe whether response delay remains stable, and confirm no significant increase.
- Attempt to reference appeal material content from historical dialogue, and confirm that the module can normally read and associate it with the current review process.

The values provided are common starting points and should be measured against the reader's own samples.
