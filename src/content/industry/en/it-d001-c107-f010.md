# Code and Change Review Assistance for Account Ban and Appeal Review: Citation Sources and Traceability

## What the Data for This Category Looks Like
Platform governance, audit quality control, and customer service teams are typical executing bodies for this category. Daily processed documents include four core types: ban records, appeal materials, review opinions, and user notifications.
Data sources cover risk control systems, audit records, user behavior logs, and report evidence. Update frequency is daily or real-time.
Each record typically includes fields such as account identifier, associated violation entry ID, appeal submission content, and audit disposition result. There is no unified cross-system format standard.

## Constraints on Citation Sources and Traceability
Multi-source heterogeneous data sources require the traceability link to bind account IDs for cross-system association. This avoids retrieving records of unrelated accounts.
Daily or real-time update frequency requires retrieval to match the latest disposition data. Expired caches cannot be used.
The document structure centered on accounts, violations, and appeals requires cited sources to be accurately bound to the currently reviewed account. Retrieval only targets violation content for that account.
Severe error consequences require traceability results to be directly traced back to original records. Unrelated cited content must not appear.

## Configuration Settings
This configuration explanation is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the single text length of ban records and appeal materials, to avoid truncating critical evidence |
| `responseData` | Return only records associated with the target account | Aligns with the business requirement of account-level review, filtering out unrelated content |
| `detail` | Enabled | Displays full fields of original records, to facilitate auditors verifying specific information |
| Single search limit | Top 3 entries | Focuses on the most relevant risk control and appeal records, avoiding information overload |
| Maximum context timeout | 600 seconds | Adapts to the retrieval timeliness of real-time updated risk control logs, avoiding timeout interruptions |

## Three Common Misconfigurations
- Phenomenon: Returned review results are completely unrelated to knowledge base citations, and citations point to records not belonging to the current account. Cause: No account ID dimension is bound for retrieval, resulting in retrieval of violation records from other accounts.
- Phenomenon: The system returns only a list of citation sources, without generating actual review opinions. Cause: The effective content generation logic for `responseData` is not properly configured, only triggering the traceability retrieval step.
- Phenomenon: The number of retrieved evidence entries exceeds expectations, making it difficult for auditors to quickly locate key information. Cause: The single search limit is set too high, without adjustment based on the actual number of records associated with a single account.

## How to Confirm Correct Configuration
- Submit an appeal review request for a test account. Check whether returned citation sources only associate ban and appeal records of that test account.
- View system logs. Confirm that the retrieval request carries the account ID as the core retrieval condition, with no generalized retrieval behavior.
- Trigger a review process. Check whether the returned result contains complete `detail` field information, with no critical content truncated.
- Simulate a delayed risk control log request. Verify that retrieval completes within 600 seconds and no timeout error is returned.

The values provided are common starting points and should be evaluated against the reader's own samples.
