# Code and Change Review Assistance for Warranty Period Defect Response: Source Citation and Traceability

## What this category of data looks like
This category of data is generated around post-delivery warranty services. Daily documents include warranty work orders, defect confirmation sheets, repair records, and customer confirmation sheets. Data sources cover customer-submitted service work orders, system operation logs, project contract warranty clauses, and code version commit records.
Data updates proceed alongside service work order progress, typically updated per individual order. Each document contains fields such as defect description, associated code snippets, version number, and customer confirmation status. There is no fixed unified format, so multi-source data must be associated per work order.

## Constraints on source citation and traceability
The multi-source, scattered nature of this data requires citation traceability to link information across different sources such as work orders, logs, and version records. This avoids bias from relying on a single data source.
The update cadence tied to individual work orders requires traceability logic to bind to the context of the current service work order. It cannot reference irrelevant data across cycles.
The lack of fixed document formats requires traceability configuration to support flexible field matching. This adapts to structural differences across different work orders.
Errors in this process can trigger warranty disputes. Traceability must accurately link responsibility boundaries and repair actions. Every citation must be traceable back to original service records.

## Configuration settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Matches the total data length of a single warranty work order and associated repair records, to avoid truncation of valid associated content |
| `responseData` | Enabled | Outputs unique identifiers of associated defect confirmation sheets and repair records to enable basic traceability |
| `detail` | Enabled | Displays specific fields of citation sources, such as work order number, code version number, defect description snippet |
| Single search limit | Top 3 entries | Limits the number of returned associated data entries to avoid introducing irrelevant historical defect records |
| Similarity threshold | 0.6–0.7 | Matches the relevance between defect descriptions and historical repair records, filters low-correlation content |
| Maximum context | Calibrated via actual testing | Adapts to the full range of associated data for a single warranty work order |

## Three common configuration mistakes
- Phenomenon: AI responses do not display citation sources, or return empty source fields. Cause: The `responseData` configuration item is not enabled, and the traceability display function is not turned on.
- Phenomenon: Knowledge base search returns insufficient results to match corresponding defect repair records. Cause: The `quoteMaxToken` value is not adjusted based on the batch data of the warranty work order, resulting in truncation of valid associated data.
- Phenomenon: Search results associate defect records from non-current warranty periods. Cause: Data is not filtered via the code version record field, leading to cross-cycle reference of invalid content.

## How to confirm correct configuration
- Upload a test warranty work order and corresponding repair records, submit an AI code review request, and check whether the returned results include associated source identifiers.
- Adjust the value of `quoteMaxToken`, and verify whether the length of returned citation data matches the expected setting.
- Check the `detail` switch status in the configuration interface, and confirm whether the detailed source display function is enabled.
- Simulate submitting a query across warranty cycles, and verify whether the returned results only include associated data within the current service cycle.

The values provided are common starting points and should be evaluated against the reader's own samples.
