# Code and Change Review Assistance for Identity Account and Permission Management: Context and Token

## What this category of data looks like
This category of data primarily comes from enterprise IAM systems, HR systems, business system logs, and approval systems. Updates occur either daily or in real time alongside personnel onboarding, offboarding, transfers, or adjustments. Daily generated documents include account application forms, permission matrices, offboarding recovery forms, and audit reports. Data fields include account unique identifiers, permission assignment scopes, effective and expiration times, approval statuses, and no additional custom statistical fields.

## Constraints these characteristics impose on the context and token stage
Account and permission data fields are clear and linked to full personnel lifecycle operations. Context must accurately match the permission scope of the currently reviewed account, to avoid introducing irrelevant business data. Data update frequency is high, so context cache must be refreshed regularly to align with the latest permission matrix. Otherwise, permission judgment deviations may occur. Audit report compliance requirements mandate that context retains complete approval chain information. Token quotas must reserve sufficient space to store multi-round review conversations and approval node data, while limiting token usage per round of context to avoid exceeding large model call limits. FastGPT v4.17.0 context configuration must adapt to these data characteristics.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Max context token count | 8000–12000 token | Matches the typical token usage of IAM permission data and code review conversations, avoids exceeding large model call limits |
| Context refresh cycle | Every 4 hours | Matches the rhythm of daily data updates and real-time personnel changes, ensures timeliness of permission data |
| Associated data recall limit | Top 6 permission records | Limits redundant data per round of context, avoids excessive token usage |
| Approval chain storage toggle | Enabled | Retains complete approval node information required for audits, meets compliance requirements |
| Token reuse toggle | Disabled | Prevents confusion of permission context across multiple review rounds, ensures independent context for each review |

## Three Common Configuration Mistakes
- Phenomenon: Permission judgment deviations occur after orchestrating multiple AI large models. Logs show the context includes account permission data unrelated to the current review. Cause: The associated data recall limit is not configured, leading to recall of expired or irrelevant permission records.
- Phenomenon: Call errors displaying `Reached the max retries p` are triggered, and context token usage is too high. Cause: The max context token count is not limited, causing requests to exceed the large model's token quota and trigger retry limits.
- Phenomenon: Audit report fields are empty and fail to meet compliance requirements. Cause: The approval chain storage toggle is not enabled, so complete approval node context data is not retained.

## How to Confirm the Configuration Is Correct
- Log in to the FastGPT v4.17.0 backend, navigate to the context configuration page in the identity account and permission management module, and confirm that the max context token count and associated data recall limit values match the preset ranges.
- Initiate a code review process, and check that the returned context data only includes permission records for the current account and the approval chain for this review.
- View system logs, confirm that the context refresh cycle runs every 4 hours, with no prompts for expired permission data.
- Simulate a personnel offboarding change for an account, and check whether the context synchronizes the permission expiration status of the corresponding account.
