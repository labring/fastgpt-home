# Code and Change Review Assistance for On-site Outsourced Operations Services: Source Citation and Traceability

## What This Category of Data Looks Like
Core data for on-site outsourced operations services comes from customer ITSM systems, monitoring platforms, asset inventories, and on-duty logs. Update frequencies are split into daily and monthly cycles. Daily produced documents include on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports. Common document fields include ticket number, inspection time period, service response duration, and SLA compliance status. Data structure shifts slightly based on specific customer delivery requirements. All data is generated around the delivery process and performance status of on-site services.

## Constraints Imposed on Source Citation and Traceability
Data for this category is scattered across multiple customer-owned systems, with inconsistent update schedules. Citation and traceability workflows must associate unique identifiers from different data sources at the same time, to prevent cross-system data confusion. There are many types of daily documents, with large differences in core fields between document types. For example, on-site daily reports must link to on-duty logs, while SLA monthly reports must correspond to inspection reports and service desk tickets. This means citation and traceability must adapt to field association rules for different document types. Additionally, data directly ties to service delivery performance. Citation accuracy directly impacts subsequent SLA verification and service judgment, creating clear requirements for traceability precision.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Citation Limit | Top 3-5 entries | Core documents for on-site services revolve around a single ticket or single inspection report. Excessive citations will distract reviewers, and will also exceed response token limits |
| `quoteMaxToken` | 800-1200 token | Single documents such as on-site daily reports and inspection reports are mostly 500-800 characters in length. This range can cover 1-2 complete documents without exceeding context thresholds |
| Response Data Format | Include source metadata | Traceability for on-site services requires clear documentation of the system of origin and generation time. Enabling `responseData` will return complete document identification information |
| `detail` Toggle | Enabled | Code and change reviews require verification of fields such as ticket number and inspection time period. When enabled, complete associated document information will be displayed |
| Total Context Length | Calibrated via actual testing | Document structure and volume vary significantly across different customers. Adjust based on actual delivery scenarios to avoid token overflow |

## Three Common Misconfigurations
- Symptom: Generated code and change review results do not display the source of any cited documents. Cause: The `responseData` configuration item is not enabled, or metadata fields for the corresponding documents are not associated.
- Symptom: The token count of a single review result far exceeds the set limit, and may trigger a timeout error. Cause: `quoteMaxToken` is set above 2000, and the average length of single documents for on-site services is relatively high. Combined multiple document citations lead to token overflow.
- Symptom: The number of cited documents far exceeds the actual required review scope, interfering with verification of core change content. Cause: A reasonable citation limit is not set, or association rules are not adjusted based on the document types used for on-site services, leading to recall of irrelevant historical tickets.

## How to Confirm Proper Configuration
- Use FastGPT v4.17.0 to generate test content for code change reviews, and check if returned results include source identifiers and field information for associated documents.
- Adjust the value of `quoteMaxToken`, and observe if the number of cited documents and token consumption of returned results meet expected standards.
- After enabling the `detail` toggle, check if returned cited documents include unique on-site service metadata fields such as ticket number and inspection time period.
- Simulate multiple review requests, and confirm that citation and traceability results do not show abnormal associations as request count increases.
