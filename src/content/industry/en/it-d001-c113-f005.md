# Code and Change Review Assistance for Integration Testing and API Testing: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The data for this category centers on activities related to API and integration testing. Daily documents include API test cases, joint debugging issue tickets, test environment descriptions, and test reports. Data sources include API management platforms, test environment logs, business databases, and message queues. The data update frequency is daily or per version release cycle. Document fields include API addresses, request parameters, response formats, link topologies, issue reproduction steps, and more. There are no uniform mandatory units for fields; they are adjusted based on specific test scenarios.

## What Constraints Do These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
API test cases are updated with daily iterations or per version release. Multi-turn dialogue must bind context corresponding to the current version to avoid confusion across version data. Test environment logs come from real-time links. Dialogue context must limit the time range of associated logs to prevent redundant data from interfering with analysis. Joint debugging issue tickets contain link node information. Prompt engineering must explicitly specify extraction of designated fields to avoid irrelevant content interfering with judgment. Real-time data from message queues must be synchronized in batches. The context window for multi-turn dialogue must adapt to the data update rhythm to prevent context overflow from affecting response efficiency.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context | Previous 8 turns of dialogue + associated test documents | Adapts to the daily update frequency of API testing data, prevents context overflow |
| Context Filtering Rules | Retain only logs and test cases from the current test environment | Matches environment isolation requirements of data sources, prevents cross-environment interference |
| Variable Binding | Bind API addresses and environment identifiers from `variables` | Ensures multi-turn dialogue associates with real parameters of the current test |
| Dialogue Trigger Timing | Trigger after each version release or on a daily scheduled basis | Matches the daily/per version data update frequency, reduces invalid calls |
| Session State Maintenance | Maintain dialogue context by binding `chatId` | Ensures continuity of multi-turn dialogue, avoids session resets |

## Three Common Misconfiguration Issues
- Only a small amount of context is displayed in dialogue details, making it impossible to associate historical test data. This occurs because the maximum context retention rule is not configured correctly, and only a small number of default historical entries are loaded.
- Prompt engineering fails to correctly recognize spaces in API parameters. This occurs because the prompt does not explicitly specify retaining whitespace characters in parameters, and no format validation is performed on input text.
- Loop dialogue does not terminate as expected after triggering. This occurs because `chatId` is not bound in multi-turn dialogue to maintain session state, causing context to reset each loop.

## How to Verify Successful Configuration
- Initiate a dialogue related to a test case, check whether the associated API documents and log content are included in the dialogue details to confirm that the context loading range matches the configured requirements.
- Enter API parameters containing spaces, check whether the AI reply correctly identifies and handles the whitespace characters in the parameters to verify that the prompt engineering configuration is effective.
- Trigger the loop dialogue flow, check whether the session terminates as expected to confirm that the `chatId` binding logic properly maintains the session state.
- View the FastGPT v4.17.0 configuration page to confirm that the maximum context count and filtering rules match the preset requirements.
