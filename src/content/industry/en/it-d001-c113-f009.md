# Code and Change Review Assistance for Integration and API Testing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for this category include API management platforms, test environment logs, databases, and message queues. Update frequency is daily or when a version is released. Daily supporting documents include API test cases, joint debugging issue tickets, environment descriptions, and test reports. API test cases contain API addresses, request methods, input parameters, and expected response structures. Test environment logs include fields such as timestamps, request identifiers, response status codes, and link latency. Data is updated dynamically with API iterations and test executions, covering full-link test records for cross-module interactions.

## How These Characteristics Impact Tool Calling and Plugin Requirements
Scattered data sources linked to multiple systems require plugins to support connections to multiple data source types including API management platforms and test log libraries, to pull test cases and link logs. Update frequency aligns with daily test runs and version releases. Tool calling must support real-time or near-real-time configuration synchronization to prevent use of expired API parameters. Daily document structures follow fixed standards. Plugins must parse standardized test case fields and automatically extract validation rules. For the most time-consuming steps of dependent service preparation and link problem identification, tool calling must automatically pull environment configurations and associated logs to reduce manual verification work. For cross-module interaction verification requirements, tool calling must associate log data across multiple services to quickly locate joint debugging issues.

## How to Configure Settings
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Meets dynamic tool calling requirements for integration testing scenarios, no manual specification of called functions required |
| `functionCall` | Set based on actual testing | Must match the parameter structure of integration test cases to avoid format incompatibility |
| Call timeout | 300–600 seconds | Integration testing requires waiting for responses from multiple services, reserve sufficient time for link troubleshooting |
| Number of results returned | Top 10 entries | Focuses on core joint debugging issues and test case validation results |
| Context window size | 8000–12000 tokens | Accommodates test cases and log content across multiple APIs |
| Plugin trigger timing | Automatically triggered after change submission | Aligns with pre-check workflows for code reviews, to intercept API parameter errors early |

## Three Common Configuration Mistakes
- Phenomenon: A `Your model may not support tool_call SyntaxError` error is returned when calling a tool. Cause: The `functionCall` parameter is not configured correctly, or the model does not support the specified tool calling format.
- Phenomenon: Visual content returned by third-party tools cannot be displayed in the chat interface. Cause: Returned data does not follow the media format specifications supported by FastGPT, or field mapping does not meet preset requirements.
- Phenomenon: After importing or exporting a workflow, referenced plugins fail to load normally. Cause: The workflow configuration does not carry the globally unique identifier of the plugin, or the corresponding plugin is not deployed in the target environment.

## How to Confirm Correct Configuration
- Initiate a simulated code change review to trigger tool calling, check if test case data for the corresponding API can be pulled.
- Review tool calling logs, confirm that the `toolChoice` parameter has taken effect, and no abnormal prompts for forced specification of called functions appear.
- After importing or exporting a workflow, verify plugin configuration items, confirm that the identifiers of all associated plugins match the target environment.
- Trigger a simulated timeout scenario, confirm that the call timeout configuration aligns with the current link latency range for integration testing.

The values provided are common starting points and should be measured against the reader's own samples.
