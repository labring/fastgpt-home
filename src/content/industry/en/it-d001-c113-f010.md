# Code and Change Review Assistance for Integration Testing and API Testing: Citation Sources and Traceability

## What this category of data looks like
Data for this category comes from API management platforms, test environment logs, databases, and message queues. Update frequency follows a daily or per-version release cycle. Daily associated documents include API test cases, commissioning issue tickets, environment descriptions, and test reports. Data fields include API path, request parameters, expected response, call chain ID, response status code, and dependent service identifier. All fields are stored in their native system formats, with no additional custom units.

## What constraints do these characteristics impose on the citation sources and traceability workflow
Dispersed storage of multi-source data requires traceability processes to complete matching across API management platforms, test log systems, and other tools, to avoid missing information from single data sources. The daily or version-level update rhythm requires configuring switching logic between incremental sync and full rebuild to adapt to data sources with different update frequencies. Differences in field priority across document types require prioritizing high-identification fields like call chain ID and response status code during traceability; matching priority for generic API parameters is lower. Dependent service identifiers must be strictly aligned to prevent cross-service reference confusion, avoid service call failures and commissioning delays. The most time-consuming link problem location process also relies on precise traceability association to shorten processing cycles.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | Adapts to the length of single entries from API test cases and logs, ensures complete citation information |
| `responseData` | Enabled | Displays raw interface response content and status codes to support traceability verification |
| `detail` | Enabled | Outputs source system and update time of associated data, improves traceability link completeness |
| Single recall limit | Top 6–10 entries | Adapts to the average number of associated data sources in integration and API testing scenarios, avoids redundant information interfering with review judgments |
| Context cache duration | 3600 seconds | Adapts to the daily test data sync rhythm, ensures context consistency during reviews |
| Source filtering rules | Only retain data from API management platforms and test log systems | Filters irrelevant data not associated with this category, improves traceability accuracy |

## Three common configuration mistakes
- Phenomenon: Returned citations do not match the test case document marked as the top-ranked overall. Cause: No rule configured to sort by association matching priority, incorrectly used document upload time as the sorting basis.
- Phenomenon: When calling via API, the returned results do not include the cited API test case file name or log path. Cause: The `detail` configuration item is not enabled, and the metadata return switch is not activated.
- Phenomenon: Citation content truncates critical response status code or call chain ID information. Cause: `quoteMaxToken` value is too small, does not adapt to the typical content length of API test data.

## How to confirm the configuration is applied correctly
- Submit a test review request that includes a clear call chain ID, check whether the returned citation content includes log and case information for the corresponding chain.
- View the effective status of configuration items, confirm that the values of `quoteMaxToken`, `responseData`, and `detail` match the preset configuration. This check applies to FastGPT v4.17.0.
- Initiate a multi-source data association search, verify that associated content from both API management platforms and test log systems can be matched simultaneously.
- Call the API interface, check whether the returned results include source system identifiers and file path information.

The values provided are common starting points and should be measured against the reader's own samples.
