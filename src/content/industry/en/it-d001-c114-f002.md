# Code and Change Review Assistance for Requirements Analysis and PRD Management: Context and Token

## What This Category of Data Looks Like
Core data for requirements analysis and PRD management comes from daily deliverables of internet product teams, business analysts, and product managers. These include requirement research notes, PRD documents, user story lists, and requirement change tickets. Data sources cover customer interview records, internal ticketing systems, public competitor pages, and analytics dashboards. Update frequency is weekly or per version release cycle. Individual documents contain fields such as business objectives, acceptance criteria, boundary conditions, and change records. There are no unified fixed unit requirements, and content structure varies significantly based on requirement complexity.

## What Constraints Do These Characteristics Impose on the Context and Token Workflow
The structure and length of requirement-related documents vary widely. The token count of individual core content fluctuates significantly. This requires strict control of the total token limit during context concatenation to avoid exceeding the large model window. Data updates happen weekly or per version cycle, so frequent knowledge base refreshes are unnecessary. However, the recall timeliness of change tickets must be ensured. Data from multiple sources has semantic overlap and priority differences. Precise similarity filtering and sorting are required to prevent irrelevant content from occupying context tokens. Delayed synchronization of requirement changes may lead to recall of outdated content via context. A regular knowledge base synchronization mechanism must be configured. Omitting boundary conditions directly causes rework in development. Context recall must prioritize covering key field content.

## How to Set Configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the context windows of mainstream large models, covering the total token requirements for a single round of requirement review |
| Single search limit | Top 6–8 entries | The number of associated entries for requirement-related documents is limited; too many entries will occupy excessive context tokens |
| `quoteMaxToken` | `2000–3000 characters` | Matches the core content length of a single PRD or change ticket, preventing individual citations from exceeding reasonable limits |
| Overlap length | `150–200 characters` | Ensures logical coherence of requirement documents, avoiding chunking that cuts off critical boundary condition descriptions |
| Similarity threshold | `0.72–0.80` | Distinguishes semantic relevance of requirement content, filtering out historical documents unrelated to the current requirement |

## Three Common Misconfigurations
- Symptom: When the single search limit or `quoteMaxToken` is set too high, the context preview displays normally in the chat interface, but the large model cannot receive the context content. Cause: The total context token count exceeds the large model's window limit, and FastGPT automatically truncates the context data to be sent.
- Symptom: After deploying the embedding service offline, an error occurs during calling that the cl100k.tiktoken file cannot be loaded. Cause: The locally deployed embedding service attempts to pull the tokenizer file from the public internet by default, and the local tokenizer path is not configured.
- Symptom: When the large model requires a fixed token generation rate, the actual generation rate is much lower than expected. Cause: The value of `maxContext` is not adjusted based on the large model's hardware requirements, and excessive context occupies the model's computing resources.

## How to Confirm the Configuration Is Correct
- Upload a complete PRD document, view the chunk preview on the knowledge base management page, and confirm that the chunk length and overlap length meet the configuration requirements.
- Initiate a search for requirement change tickets, check the number and similarity of recall results, and confirm that the single search limit and similarity threshold configurations are active.
- Initiate a query that includes clear boundary conditions, check whether the large model's returned content contains the recalled context information, and confirm that the configurations for `maxContext` and `quoteMaxToken` do not exceed the window limit.
- Check the FastGPT v4.17.0 system logs to confirm that no external network request errors related to tokenizer appear during embedding service calls.

The values provided are common starting points and should be evaluated against the reader's own samples.
