# Code and Change Review Assistance for Requirements Analysis and PRD Management: Tool Calling and Plugins

## What data falls under this category
Data for this category comes from internet product teams’ requirement research notes, PRD documents, user story lists, and requirement change forms.
Data sources include customer interview records, ticketing systems, public competitor pages, and event tracking dashboards.
Data updates occur weekly or per release cycle.
Document structures contain core fields such as business objectives, acceptance criteria, functional scope, and change descriptions.
No unified mandatory format exists for these documents.
Some documents include unstructured user feedback snippets.

## Constraints on tool calling and plugins workflows
Since data sources include multiple types of unstructured documents, tool calling must support multi-format parsing and adaptation to avoid missing core information across different PRD formats.
Data updates follow a weekly or per-release cycle. Plugin trigger timing must align with this cycle to keep synchronized requirement content matched to team work progress.
No unified standard exists for document fields. Tool calling must support custom field extraction rules to accurately match different teams’ requirement definition habits.
Requirement change form statuses change frequently. Plugins must have the ability to capture changes in real time to avoid information gaps caused by delayed synchronization.

## Configuration guidelines
These configurations apply to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `"auto"` | Adapts to tool calling needs for multiple PRD document types, automatically selects appropriate extraction logic |
| `functionCall` | `{"name": "extract_prd_fields", "parameters": {"fields": ["业务目标", "验收口径", "变更范围"]}}` | Accurately extracts core business fields from PRDs, avoids redundant information interfering with requirement analysis |
| Tool call timeout period | `600 seconds` | PRD document parsing typically requires long processing times, prevents task interruptions from timeouts |
| Plugin trigger timing | `24 hours before release` | Aligns with weekly or per-release requirement document update cycles, ensures synchronized content is available promptly |
| Number of returns per tool call | `Top 3` | Controls the volume of returned information, prevents excessive redundant content from reducing requirement review efficiency |
| Document format adaptation switch | `Enable Word/Markdown dual format support` | Covers common PRD writing formats, adapts to different teams’ document habits |

## Three common misconfigurations
- Symptom: Tool call returns empty results or extracted fields do not match PRD document content. Cause: Incorrectly configured parameter matching rules for `functionCall`, failure to associate core business fields from PRD documents.
- Symptom: Authentication failure occurs when calling the application API externally, returns 401 status code. Cause: Used AI Proxy admin Token as application API Key for authentication.
- Symptom: Data lag occurs when plugins synchronize requirement documents weekly. Cause: Plugin trigger timing does not match the weekly or per-release PRD document update cycle.

## How to confirm configurations are correctly set up
- Check environment variable configurations in the App/Admin backend, confirm `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured and not empty.
- Upload a typical PRD document, initiate a tool call test, verify that core fields such as business objectives and acceptance criteria from the document are correctly extracted.
- Manually trigger plugin execution, confirm that the plugin synchronizes the latest content of requirement change forms at the set timing.
- Review tool call logs, confirm there are no timeout or parameter error records.

The values given are common starting points and should be measured against the reader's own samples.
