# Code and Change Review Assistance for Requirements Analysis and PRD Management: Citation Sources and Traceability

## What the data for this category looks like
The core data for this category comes from the daily deliverables of internet product teams, business analysts, and product managers. This includes requirement research notes, PRD documents, user story lists, and requirement change forms. Data sources cover customer interview records, internal ticket systems, public industry pages, and analytics dashboards. Updates are released weekly or with each version iteration. Document structures typically include fields such as business goal definitions, acceptance boundary conditions, and change trigger nodes. There is no unified mandatory format, so configurations must be adapted to the team’s daily collaboration habits.

## Constraints imposed on citation sources and traceability
The lack of a unified mandatory format for documents in this category means the citation traceability workflow must adapt to multiple text structures. Fixed fields cannot be used for automatic matching, so additional configuration of text feature recognition rules is required. The weekly or per-version update rhythm requires the traceability system to support associating historical documents by version, to avoid reference confusion across versions. Multi-channel data sources require integrating citation markers from scattered sources such as customer interview records and ticket systems, to ensure all original basis is covered during traceability. The requirement for strict acceptance criteria means the traceability workflow must accurately link to original business definitions, reducing the likelihood of subsequent development rework and acceptance disputes.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | Adapts to the length of single blocks of content in PRD documents, avoiding truncation of key citation basis |
| `responseData` | Enable citation source display | Meets the core traceability needs of product teams, ensuring that formal outputs include cited document information |
| `detail` | Full traceability mode | Covers detailed citation markers for multiple types of documents such as requirement research notes and change forms, supporting display of complete original citation information |
| Single search limit | Top 5 entries | Controls the amount of traceability result information, avoiding excessive redundant content that disrupts reviews |
| Context cache duration | 7 days | Matches the weekly or per-version update rhythm of this category, retaining citation association data for the corresponding period |

## Three common configuration errors
- Phenomenon: The citation document page link displays on the debug page, but does not appear on the officially released chat page. Cause: The formal environment traceability display switch corresponding to `responseData` was not enabled, and metadata output was only activated in debug mode.
- Phenomenon: The text content extraction component fails to extract citation-associated content from the knowledge base. Cause: `detail` was not configured as full traceability mode. The component only captures plain text fragments and does not link to original citation metadata.
- Phenomenon: The released knowledge base page does not display the source of cited documents. Cause: A reasonable value for `quoteMaxToken` was not configured, leading to truncated citation markers or missing complete traceability links.

## How to confirm correct configuration
- Access the officially released chat page of FastGPT v4.17.0, check for the presence of cited document source information, and confirm that the `responseData` configuration is active.
- Call the text content extraction component to verify that it can extract citation metadata associated with the knowledge base, and confirm that the `detail` configuration meets requirements.
- Submit a requirement change review request, check that traceability results cover all relevant documents within the corresponding period, and confirm that the context cache duration configuration matches the update rhythm.
- Review system operation logs to confirm that the value of `quoteMaxToken` does not truncate key citation basis content.
