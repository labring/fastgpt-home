# Code and Change Review Assistance for Project Implementation Plan Management: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The data for this category primarily comes from contracts, work breakdown structures (WBS), client schedules, and project management systems. Daily produced documents include project plans, milestone lists, weekly reports, and risk issue lists. Fields cover task names, responsible parties, delivery deadlines, risk levels, and response measures. Data updates occur once weekly or when triggered by individual milestone nodes. Document structures primarily use hierarchical task trees and linear timelines. There is no unified standardized field format, so adaptation is required for formats exported by different project management tools.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Decentralized data sources and inconsistent formats require multi-turn dialogue to support dynamic adaptation to input from project documents of different formats. Prompts must clearly distinguish between task types and data fields. Data updated weekly or by milestone requires multi-turn dialogue to retain context from historical project nodes, avoiding repeated questions about confirmed information. Scenarios with high time consumption for task decomposition and scheduling coordination require prompts to preset a logical framework for task decomposition, reducing redundant manual input steps. Dynamic tracking of risk issues requires the dialogue flow to associate the latest risk list data in real time, avoiding calls to outdated information.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | First 12000 characters | Adapt to the hierarchical structure of project documents, avoid context overflow, and align with FastGPT v4.17.0 context processing logic |
| Session Binding Rule | Bind by `chatId` | Differentiate conversation histories for different projects, avoid context confusion |
| Dynamic Variable Call | Pass project fields using `variables` | Load the latest project plans, milestones, and other data for the current project in real time |
| Historical Message Transmission | Pass the complete `messages` array | Retain the context logic of multi-turn dialogue, support cross-turn task tracking |
| Knowledge Base Recall Limit | Top 3 matching documents | Project document volume is limited, avoid redundant recall interfering with core logic |
| Question Optimization Switch | Enabled | Simplify non-standard input from project managers, adapt to colloquial questions |

## Three Common Mistakes
- Symptom: Dialogue works normally during debug preview, but prompts that no knowledge base is selected after official release. Cause: The official environment is not bound to the knowledge base for the corresponding project documents, and only temporary data sources are loaded during debugging.
- Symptom: Unable to retrieve chat data for a specified user when calling the API interface. Cause: The user and conversation history are not associated via `chatId`, only the default session identifier is used.
- Symptom: Outdated project progress data appears in multi-turn dialogue. Cause: Context refresh triggered by data update time is not configured, and old `variables` parameter values are still called.

## How to Confirm the Configuration Is Complete
- Input task decomposition requests for different projects, verify whether the dialogue can automatically associate WBS data for the corresponding project.
- Call the API interface, pass the specified `chatId`, verify whether the complete `messages` history for the corresponding session is returned.
- View the knowledge base binding list, confirm that the official environment has loaded documents such as the current project’s plans and milestones.
- Adjust the context length parameter, test whether truncation or overflow prompts appear when inputting long documents.
