# Code and Change Review Assistance for Project Implementation Plan Management: Workflow Orchestration

## What this category's data looks like
Data typically comes from project contracts, work breakdown structures (WBS), customer-confirmed schedules, and existing project management systems.
Daily maintained documents include project plans, milestone lists, weekly reports, and risk and issue lists.
Common fields include task identifiers, responsible persons, deliverable requirements, progress percentage, and risk level.
Update cadence is weekly, or once per project milestone sync.

## What constraints these characteristics place on workflow orchestration
Dispersed data sources require the workflow to include multi-source data access nodes, to adapt to imports from different data sources such as contracts and WBS.
Flexible update cadence requires the workflow to support both scheduled and manual trigger modes, to fit weekly sync and milestone validation scenarios.
Multi-type document processing requirements mean workflow nodes must support upload and parsing links for different document formats.
Task and review result association logic requires configuring `variables` in the workflow to bind task IDs and change review entries, ensuring review results accurately link to corresponding project tasks.
Unlike on-premise deployment categories, this category focuses on progress, scope, and responsible person association. The workflow must bind responsible person fields and review results to clarify accountability.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow trigger mode | Scheduled trigger by milestone node or manual trigger | Adapt to the update cadence of project weekly sync and milestone validation |
| Form input node default value | Use the project ID field from global `variables` | Ensure the form automatically associates the current project context |
| Tool call routing rules | Prioritize knowledge base calls, MCP calls only for change impact assessment | Match core requirements of code review and change assistance |
| Supported document upload formats | Support docx, xlsx, pdf formats | Cover common document types such as project plans, weekly reports |
| Failure retry configuration | Retry 3 times, interval 600 seconds | Respond to temporary network fluctuations during multi-source data access |
| Variable binding node | Bind `nodeId` as the task review node | Ensure review results accurately link to corresponding tasks |

## Three common misconfigurations
- Workflow fails to import normally after export, prompting format error. Cause: Did not select FastGPT official export format, directly copied interface text leading to structural damage.
- Tool call routing does not take effect, knowledge base calls are always triggered. Cause: Routing rules did not configure the request type field in `variables` as a judgment condition, unable to identify MCP call scenarios.
- Form input node cannot obtain global variable values, fields are empty. Cause: Did not map global variables to the form's default value binding item, did not correctly associate global parameters in `variables`.

## How to confirm the configuration is complete
- Manually trigger the workflow once, check if WBS data from the project management system can be imported correctly.
- Submit a change review request, confirm that tool calls will route to the knowledge base or MCP node based on the request type.
- Open the form input node, check if the default value automatically fills in the global `variables` parameters of the current project.
- Upload a docx format weekly project report, confirm that progress update content can be extracted after parsing.
