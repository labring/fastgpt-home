# Code and Change Review Assistance for Project Implementation Plan Management: Citation Sources and Traceability

## What the data for this category looks like
Core data for this category comes from contracts, work breakdown structures (WBS), client schedules, and project management systems. Daily output documents include project plans, milestone lists, weekly reports, and risk issue lists. Updates occur weekly or when individual milestone nodes are reached. Fields include task unique identifiers, executing responsible persons, planned durations, risk levels, associated contract numbers, and more. Durations use natural days as the unit. The responsible person field uses enumerated text format.

## How these characteristics impose constraints on citation and traceability
Core data is scattered across multiple sources including contracts, WBS, and project management systems. The citation and traceability workflow must support cross-data-source association matching to prevent cited content from disconnecting from actual project data. Data update cycles are not fixed. Retrieval time windows must limit results to data from the currently active project cycle. Daily document structures vary. Some fields use enumerated formats. Retrieval processes must specify matching rules for corresponding fields to ensure retrieved content correlates strongly with actual task, responsible person, duration, and other details for the current project. Project implementation plan traceability must link to specific task nodes. This prevents returns of only generic, non-specific project management content.

## How to set the configuration
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of single documents for this category. It ensures retrieved project plans, weekly reports, and other content fully cover core task information. |
| `responseData` | Return only associated task fields | Filters out irrelevant generic project management content. It retains only fields directly related to the current review task, such as responsible persons, durations, and risk levels. |
| `detail` | Enable full-field traceability | Fully displays original fields of cited content. This lets reviewers verify information such as contract numbers and client schedules linked to tasks. |
| Single search limit | Top 3 results | Matches the number of core tasks for a single project in this category. It avoids retrieving excessive redundant data that disrupts review work. |
| Retrieval time range | Past 30 days or current milestone cycle | Aligns with data update rhythms. It only retrieves project data from the currently active cycle. |

## Three common misconfigurations
- Phenomenon: Only text datasets are retrieved. Non-text format WBS tables and project management system export files are not cited. Cause: The parsing switch for corresponding file formats is not enabled. Only the retrieval configuration for text datasets is activated.
- Phenomenon: The AI response does not link to specific tasks of the current project. It returns generic project management content. Cause: The filtering rule for `responseData` is not specified. Retrieval fields are not limited to task-related fields within the project plan.
- Phenomenon: Cited content exceeds the response context range. Traceability information cannot be displayed normally. Cause: The value of `quoteMaxToken` is set too high. It exceeds the context window limit of the model.

## How to confirm the configuration is correct
- Upload a typical document for this category, such as a project plan template. Submit a code and change review request. Check whether retrieved content only includes task, duration, and other fields from that document.
- Open the citation traceability module. Confirm returned citation sources include the file name and update time of the corresponding document. Confirm these match the actual cycle of the current project.
- Adjust the value of `quoteMaxToken`. Test the length of retrieved content across different values. Ensure no content is truncated and no context overflow occurs.
- Try uploading non-text format documents, such as Excel-format WBS tables. Check whether these documents can be normally retrieved and return cited content.
