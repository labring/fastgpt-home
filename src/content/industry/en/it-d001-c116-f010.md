# Code and Change Review Assistance for Project Document Handover and Archiving: Citation Sources and Traceability

## What the data for this category looks like
This category of data primarily comes from project document libraries, configuration lists, meeting minutes, and test reports. Daily outputs include completion documents, configuration manuals, training records, and acceptance certificates. Data updates follow the rhythm of project phase milestones or project wrap-up. A single document usually includes fields such as document number, version identifier, associated project identifier, signing date, and archiving status. Some technical documents also include module code and change log fields. The overall data structure adjusts based on project scale, only needs to meet the general requirements of project delivery, and there is no mandatory unified format. This document organizes relevant configuration requirements based on the functional logic of FastGPT v4.17.0.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Since data sources are scattered across multiple carriers such as project document libraries, configuration lists, and meeting minutes, the citation traceability link needs to support cross-multiple-document-source retrieval and matching. Data updates follow project phase or wrap-up rhythms and cannot be synchronized on a fixed cycle, so a trigger-based document update mechanism needs to be configured to synchronize data only when project milestones change. The inconsistent structure of single documents without fixed formats means general retrieval rules cannot adapt, so field mapping rules need to be configured for different document types such as completion documents and configuration manuals. At the same time, citation traceability needs to associate project identifiers to filter out documents from non-target projects, avoid mixing irrelevant content during reviews, and verify version consistency between change records and archived documents.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | The core content of project documents usually falls within this range, to avoid truncating change logs and archiving identifiers |
| `responseData` | Return only document number, version identifier, associated project identifier | Reviews for this category only require core traceability fields, to reduce interference from redundant information |
| `detail` | Enabled | Full change records of associated documents need to be displayed to ensure traceability of the source |
| Citation Trigger Timing | Triggered by project milestones | Data updates for this category follow phase or wrap-up rhythms, no fixed-cycle synchronization required |
| Document Field Mapping Rules | Preset matching based on document type | Different documents have inconsistent structures, so mappings need to be configured separately for completion documents, configuration manuals, and similar document types |
| Single Retrieval Limit | `Top 10 entries` | Core archived deliverables for a single project usually do not exceed 10 copies; too many will increase review burden |

## Three Common Misconfigurations
- Symptom: After configuring and triggering the workflow, the answer still displays input and response citations from knowledge base searches. Cause: The configuration does not limit the citation scope only associated with the workflow, or the switch for displaying citations from non-workflow sources is not turned off.
- Symptom: An error occurs during citation traceability, prompting that document fields cannot be matched. Cause: Field mapping rules are not configured for different document types, and general retrieval rules are used to match project documents with inconsistent structures.
- Symptom: Citation content is truncated, and complete change logs cannot be viewed. Cause: The value of `quoteMaxToken` is set too small, truncating document content exceeding the threshold.

## How to Confirm the Configuration is Correct
- Initiate a code change review for a specific project, check whether the returned citation content only includes archived documents of that project.
- View the citation display area, confirm that only core traceability fields such as document number and version identifier are displayed, with no redundant content.
- Test triggering a project milestone update, check whether associated documents are automatically synchronized to the retrieval scope.
- Verify that citation content of long documents is complete, with no truncation.
