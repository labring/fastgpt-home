# Publishing Instructions and Operational Report Summary for IT Asset Inventory: Scheduled Tasks and Automation

## What the data for this category looks like
IT asset inventory data is sourced from asset management systems, procurement systems, financial fixed asset systems, and terminal management platforms. Update frequencies are typically monthly, quarterly, or annually. Daily produced documents include asset ledgers, inventory sheets, requisition and return forms, and scrap applications. Fields include asset number, name, specification model, user, storage location, usage status, and others. Units are mostly physical measurement units such as units, sets, and pieces. Cross-system integration is required to conduct account-physical verification work.

## Constraints on Scheduled Tasks and Automation
Since data update frequencies are monthly, quarterly, or annually, scheduled tasks do not need to run at high frequency. Align tasks with business update rhythms to avoid resource waste. Multi-data-source docking requires automated workflows to support cross-system data pulling and format compatibility. This prevents data loss from differences in system interfaces. Account-physical verification is the core time-consuming step. Automation must complete automatic data comparison and exception marking. It must also retain complete operation logs to meet audit requirements. Data anomalies have serious consequences. Configure failure retry and alert mechanisms to prevent asset loss or financial account discrepancies.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Scheduled task trigger cycle | 00:00 on the 1st of each month, or 00:00 on the 1st of the first month of each quarter | Aligns with the monthly/quarterly update frequency of asset inventory |
| Data source docking whitelist | Asset management systems, procurement systems, financial fixed asset systems, terminal management platforms | Covers all data sources for this category |
| Bulk document import limit | 500 items per run | Balances system processing efficiency and data integrity |
| Failure retry count | 2 retries | Prevents task failure from single temporary exceptions, while avoiding duplicate submissions |
| Alert trigger threshold | 2 consecutive execution failures | Notifies administrators of exceptions in a timely manner, avoiding data delays |
| Task log retention period | 180 days | Meets audit and troubleshooting requirements |

## Three Common Misconfigurations
- Symptom: Some fields in the asset ledger are empty after a scheduled task runs. Cause: Docking permissions for the corresponding data source are not configured, resulting in failure to pull data from some systems.
- Symptom: Task execution times out and returns a 504 status code. Cause: The bulk document import limit is set too high, and the trigger cycle is too short, exceeding the system's single-run processing capacity.
- Symptom: Tool calls cannot trigger asset inventory and ledger updates simultaneously. Cause: Multi-tool parallel execution configuration is not enabled; the task process uses serial execution logic by default.

## How to Verify Proper Configuration
- Navigate to the scheduled task management page in FastGPT v4.17.0, and check whether the trigger cycle of the created IT asset inventory summary task matches the configured settings.
- Manually trigger a test task, and verify that the pulled data source data includes required fields such as asset number, user, and storage location.
- View the task execution logs to confirm there are no consecutive failure records, and that alert rules are not triggered.
- Generate a temporary operational report, and check whether the asset quantity in the report matches the original data exported from the data source.
