# Publishing Instructions and Operational Report Summary for IT Asset Inventory: Workflow Orchestration

## What Data for This Category Looks Like
IT asset inventory data is sourced from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Daily generated documents include asset ledgers, inventory sheets, requisition and return forms, and scrap applications. Core fields include asset number, ownership entity, storage location, user, asset status, procurement time, and scrap time. Common units are sets, pieces, or individual units. Data update frequency is typically monthly, quarterly, or annually. A single inventory involves batch structured forms, requiring cross-system integration of multi-dimensional information.

## What Constraints These Characteristics Impose on Workflow Orchestration
Data comes from multiple heterogeneous systems, so workflows must include cross-system data pull nodes to unify asset information from different sources. Data update frequency is low, so workflows do not need high-frequency triggering. A scheduled trigger mechanism matches typical inventory cycles. Core documents are structured forms, so workflows must include field validation nodes to ensure key fields such as asset number and user are complete and accurate. Account-physical verification is the most time-consuming step, so workflows must include automatic comparison nodes to reduce manual verification workload. Asset inventory errors can cause asset loss and inconsistent financial accounts, so workflows must have failure retry and exception alert mechanisms to maintain process stability. IT asset inventory focuses on asset ownership, location, and user, which differs significantly from configuration management scenarios. Workflow orchestration must prioritize circulation and validation of these core fields.

## Configuration Recommendations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Configure asset field mapping rules | Unify field formats for asset data from multiple system sources to support cross-system integration |
| Scheduled trigger cycle | `30 days` | Match the update frequency of most enterprises' quarterly or monthly asset inventory |
| External node log recording | Enable the recording switch | Ensure operations calling third-party plugins or applications are traceable, meeting audit requirements |
| `nodeId` | Bind to the core asset verification node | Allow quick identification of problematic nodes during workflow exceptions, improving troubleshooting efficiency |
| URL parameter passthrough | Enable global variable passthrough configuration | Support passing inventory scope parameters from shared links to adapt to flexible inventory scenarios |
| Failure retry configuration | `2 times` with an interval of `60 seconds` | Address temporary fluctuations in multi-system interface calls and lower the risk of process interruption |

## Three Common Misconfigurations
- No conversation log after calling external applications or plugins: The workflow node shows execution successful, but no corresponding call record is generated. This happens because the log recording switch for external nodes is not enabled, and only basic core workflow logs are recorded by default.
- Global variables cannot be passed via URL parameters: Global variables in the workflow do not update synchronously when the shared link carries parameters. This happens because mapping rules between global variables and URL parameters are not configured.
- Unable to call custom Python code functions: Workflow node execution returns an error that the target function cannot be found. This happens because the Python code is not deployed as a callable plugin node, or the function's input parameter format is not configured correctly.

## How to Confirm Proper Configuration
- Trigger a test workflow, verify that each data source node correctly pulls asset data from the corresponding system, and that field completeness meets expectations.
- Review workflow execution logs to confirm that execution records and parameter transfer records for external application call nodes have been generated.
- Access the workflow shared link with test parameters, confirm that global variables have been updated correctly to the passed parameter values.
- Simulate an external interface call failure, check that the workflow triggers the preset retry mechanism, and that the number of retries matches the configured requirements.
