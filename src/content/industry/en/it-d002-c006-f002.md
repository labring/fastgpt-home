# Pull Request Review Release Notes and Operations Report Summary: Context and Token

## What This Category’s Data Looks Like
Data for this category originates from code repositories, CI pipelines, Issue links, and contributor submission records. Daily generated documents include PR descriptions, code review comments, CI execution results, and merge operation logs.
Data update cycles are typically daily or weekly. A single data entry includes fields such as PR number, list of changed files, review comment entries, CI pass rate, and merge status.
Primary stakeholders include project maintainers, module owners, and contributors. Work focuses centrally on reviewing and summarizing mergeable code changes. Unlike issue triage tasks, this category only processes data related to mergeable code changes.

## Constraints on Context and Token Workflows
This category’s data sources are scattered, including code text, CI logs, review comments and other formatted content. The proportion of token usage varies significantly across different formats, so context token quotas must be allocated rationally.
A single PR data entry includes multiple change items and review records. The context window must cover sufficient relevant information to accurately summarize release notes and operation reports.
Data updates occur daily or weekly. Frequent recall is not required, but recalled content must match the latest merge and review status.
Core steps such as confirming change intent and verifying test results rely on complete context. Insufficient token quotas will cause loss of critical information, leading to regression defects or unstable main branches, and adversely impacting contributor experience.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | PR data for this category includes multiple change items and review content. This range covers the associated context of typical PRs |
| `quoteMaxToken` | `1000–1500 characters` | Single valid segments of review comments and CI logs typically fall within this range, avoiding excessive consumption of context quotas |
| Context Refresh Cycle | Once daily | Data updates occur daily or weekly. Daily refresh ensures the context matches the latest merge and review records |
| Number of Recalled Relevant Entries | The top 6 entries | Core review and change content typically falls within the most recent 6 submitted records, balancing recall efficiency and information completeness |
| Incremental Recall Threshold | Calibrated via actual testing | Code change density varies across repositories. Adjust recall trigger conditions based on actual scenarios |

## Three Common Misconfigurations
- After configuring `quoteMaxToken`, the returned referenced content exceeds the specified length. The cause is failure to clearly define the parameter’s effective scope, with the parameter not bound to the corresponding reference type content in some scenarios.
- An error is triggered when submitting Chinese content, while English input operates normally. The cause is that the context quota does not adapt to the token calculation rules for Chinese encoding, leading to token count deviations that trigger restrictions.
- The generated release notes omit key change content. The cause is that `maxContext` is set too small, failing to cover all associated PR change and review records.

## How to Verify Correct Configuration
- A typical PR data entry is imported, and the number and length of contextually recalled content are checked to confirm alignment with the configured value range.
- Test content containing both Chinese and English is submitted, and triggered errors are reviewed to verify that the token calculation rules adapt to the current scenario.
- Summary results generated after configuration takes effect are reviewed, and confirmation is made that key change and review records are included in the context.
- One full update cycle is allowed to pass, and checks are performed to confirm whether the context automatically refreshes to display the latest PR data and review records.

The values listed here are common starting points and should be evaluated against the reader’s own samples.
