# Release Notes and Operation Report Summary for SLA and Service Reports: Scheduled Tasks and Automation

## What the data for this category looks like
This category includes contractually agreed SLA metrics, availability statistics during the service cycle, work order response and completion records, and abnormal feedback from customer communications. Data comes from internal monitoring systems, work order systems, archived contracts, and customer communication logs. Updates run monthly or quarterly, aligned with SLA service cycles. Documents use a combination of structured tables and text minutes. Fields change based on metric type, and include metric name, cycle range, actual achieved value, and abnormal event description. No fixed unified unit exists. Adapt based on specific business scenarios. This content is compatible with FastGPT v4.17.0.

## Constraints for Scheduled Tasks and Automation
Data sources are scattered. Pull and integrate data from multiple systems. Scheduled tasks must adapt to multi-interface call sequences to avoid overall task failure from single system interface exceptions. Update frequency is monthly or quarterly. Task execution cycles must match business release rhythms. Too frequent execution wastes resources. Too infrequent execution misses report release windows. Document structures include structured metrics and unstructured minutes. Separate processing of structured data extraction and text content aggregation is required to avoid format confusion. No fixed unified standard exists for fields. Tasks must support dynamic field mapping to avoid adaptation failures from hardcoding. Data errors can trigger compensation disputes and customer complaints. Tasks must include verification steps to ensure statistical results match original data.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Task Trigger Cycle | Monthly execution (00:00 on the 1st of each month) | Matches the release rhythm of monthly SLA service reports, covering complete natural month statistical data |
| Data Source Pull Scope | Full data from the past 30/90 days | Corresponds to monthly/quarterly statistical cycles, avoiding omission of valid data across cycles |
| Data Validation Threshold | Calibrated based on actual testing | Ensures pulled data source fields are complete, avoiding null values or missing fields that impact metric calculation |
| Abnormal Alert Trigger Condition | Task execution timeout exceeding 120 minutes | Notifies operations personnel promptly to handle interrupted statistical tasks, avoiding delayed report release |
| Task Retry Count | 3 retries, 600-second interval | Addresses temporary system interface fluctuations, reducing task failure probability |
| Report Generation Format | Structured table + text minutes hybrid | Matches the standard structure of daily documents, facilitating customer review and internal alignment |

## Three Common Configuration Mistakes
- Symptom: Duplicate SLA metric entries appear in regularly generated service reports, or multiple duplicate indexes appear in associated datasets. Cause: The task does not have deduplication logic enabled, and cross-cycle historical data is pulled repeatedly, leading to superposition of statistical entries.
- Symptom: The scheduled task returns a 404 status code after execution, and cannot pull data from the work order system. Cause: The data source interface address configured for the task has not been updated, or permission configurations have not been synchronized to the scheduled execution node, resulting in inability to access internal systems.
- Symptom: Customer communication screenshot links embedded in service reports cannot be accessed. Cause: The task does not have image domain name replacement logic configured, only retaining local file paths and not replacing local addresses with publicly accessible domain names.

## How to Verify Correct Configuration
- Manually trigger a scheduled task, and verify that the pulled data source range covers all data for the specified cycle.
- Check that the generated report format meets the preset requirements of a structured table and text minutes hybrid.
- Verify that abnormal alerts trigger when task timeouts or data source missing occur.
- Cross-check that fields in the generated report match the contractually agreed SLA metrics.
