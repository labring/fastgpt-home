# Release Notes and Operation Report Summary for Personal Information Protection Compliance: Database and Operations

This document applies to FastGPT v4.17.0.

## What the Data for This Category Looks Like
This category of data primarily comes from business systems, App permission lists, privacy policies, and user request records. Daily generated documents include personal information lists, processing rules, impact assessment reports, and user authorization texts.
Data updates follow a quarterly cadence or are triggered alongside product version changes. Individual documents contain fields such as information subject identifiers, processing purposes, storage periods, and sharing scopes. There is no unified fixed unit; field definitions must be matched to specific business scenarios.

## What Constraints Do These Characteristics Impose on Database and Operations Workflows
The data sources for this category are scattered and have significant format differences, requiring the database to support unified storage and parsing of multi-source heterogeneous data.
The update cadence has no fixed schedule. Batch data adjustments may be triggered alongside product changes, so the database must have flexible write and update capabilities to avoid table locking or business process interruptions.
Since the data involves information that can identify natural persons, the database must support fine-grained permission control, allowing only compliance teams to access sensitive fields.
Additionally, complete audit logs must be retained for data changes to support subsequent compliance audits. The operations link must ensure the availability of data storage to avoid loss of compliance materials due to outages.

## How to Configure
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | mongodb://user:pass@host1:port1,host2:port2/dbname?replicaSet=rs0 | Supports multi-node replica set deployment, adapts to distributed storage of multi-source compliance data, and configures application identifiers to facilitate log differentiation of different business sources |
| `PG_URL` | postgresql://user:pass@host:port/compliance_db?sslmode=require | Supports transactional operations, ensures atomic writes and rollbacks of compliance documents, and meets data consistency requirements |
| `DB_MAX_LINK` | 20–30 | Balances database connection resources and concurrent processing capabilities, avoiding connection exhaustion under high concurrency |
| `REDIS_URL` | redis://:pass@host:port/0?maxmemory-policy=allkeys-lru | Used to cache frequently accessed personal information list data, reducing query pressure on the primary database, and limits cache memory usage |
| Database connection timeout | 300 seconds | Prevents connection interruptions due to temporary network fluctuations, ensuring stable queries of compliance data |
| Log storage retention period | 90 days | Meets log retention requirements for compliance audits, facilitating subsequent issue tracing and verification |

## Three Common Misconfigurations
- Issue: Cannot distinguish connection requests from different compliance business sources in MongoDB logs. Cause: No application identifier parameter is configured in `MONGODB_URI`, so logs only show connection addresses and cannot trace specific business modules.
- Issue: Database connection plugin execution time has increased significantly compared to older versions, with single call execution exceeding 1 second. Cause: `DB_MAX_LINK` is configured too low, leading to an overly long connection wait queue, or the timeout setting is too short, triggering retry mechanisms.
- Issue: Database connection error "connect ETIMEDOUT" appears in workflows, while the database can be accessed normally locally. Cause: Correct network access policies are not configured, or the host address bound in `PG_URL` does not have the corresponding port open, preventing the platform from accessing the remote database.

## How to Confirm Proper Configuration
- Run the database connection test script to verify that the configured connection address and permissions can establish a normal connection, and adjust the timeout and connection pool parameters based on test results.
- View database audit logs to confirm that connection requests from different business sources can be correctly recorded and differentiated, meeting compliance audit requirements.
- Simulate batch import operations of compliance data, observe system resource usage and connection status, and adjust concurrency throttling thresholds and backup frequencies.
- Check the integrity and recoverability of data backup files, confirm that the backup process triggers normally and retains complete logs.
