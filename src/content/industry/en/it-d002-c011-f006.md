# Release Notes and Operations Report Summary for Cloud Host Provisioning and Resource Activation: Scheduled Tasks and Automation

## What Data for This Category Looks Like
Data for this category typically originates from cloud management platforms, order systems, IAM permission systems, and billing systems. Daily associated documents include resource activation approval forms, cloud host instance configuration tables, account permission application forms, and delivery confirmation receipts. Data updates are generated in real time or updated per order as each activation order is processed. Core fields include instance unique identifier, CPU and memory specifications, network segment, bound permission account, billing cycle, and more. Common units are units, GB, hours, days. Field naming conventions vary across different source systems, so unified formatting via mapping is required.

## Constraints Imposed on Scheduled Tasks and Automation Workflows
Because data sources are decentralized and update rhythms vary per order, scheduled tasks must match the real-time requirements of order generation while avoiding excessive data pulling that increases system load. Field differences in daily associated documents require automated summary workflows to support dynamic mapping. Without this, report data may be missing or incorrect. Additionally, errors in this category directly impact customer deployment and billing accuracy. Automated workflows must therefore include validation and retry mechanisms, and support exception alerts to quickly respond to interface or data anomalies.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Scheduled task trigger interval | 15-30 minutes | Matches the average generation interval of cloud host activation orders, balances data real-time performance and system load, and complies with the scheduled task scheduling configuration specifications of FastGPT v4.17.0 |
| Data pull scope | New orders from the past 1 hour | Adapts to the per-order/real-time update rhythm, avoids pulling duplicate or expired data |
| Field mapping rules | Calibrated based on actual testing | Covers field differences across multiple document types including resource activation forms and instance configuration tables, unifies report output formats |
| Failure retry count | 3 times | Addresses temporary system interface fluctuations, reduces the risk of report missing caused by a single pull failure |
| Exception alert threshold | 2 consecutive task failures | Notifies operations personnel in a timely manner to resolve interface exceptions or data synchronization issues |
| Report generation trigger condition | 23:00 daily + completion of new orders received that day | Balances the needs of daily operations summary and real-time delivery confirmation |

## Three Common Misconfigurations
- Empty instance configuration fields in reports after scheduled task execution: Field name differences between the cloud management platform and order system were not properly mapped, leading to failure to extract core data such as instance specifications.
- 404 Not Found errors returned by API requests: The instance ID pulled via scheduled tasks has not been synchronized to the cloud management platform, or the configured pull range does not include activated cloud host resources.
- Global variables not updating automatically: The conditions for triggering variable updates were not configured, or the scheduled task was not bound to the variable update execution action, resulting in classification call count statistics not being synchronized to the operations report.

## How to Verify Successful Configuration
- Manually trigger a scheduled task. Confirm that the generated report includes new cloud host activation order data from the past 1 hour.
- Simulate an abnormal interface request. Confirm that the task triggers an alert and generates a corresponding log record.
- Submit a classification call request. Verify that the call count statistics in the report update automatically with the request, and confirm that the global variable update function operates correctly.
- Randomly select an activated cloud host order. Cross-check the billing fields in the report with raw data exported from the billing system, and confirm that field mapping is accurate.
