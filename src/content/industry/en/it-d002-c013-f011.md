# Release Notes and Operations Report Summary for Cloud Billing and Cost Accounting: Database and Operations

## What data for this category looks like
Data for this category typically comes from cloud billing systems, tag data, order systems, and resource monitoring tools. Daily outputs include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Data updates follow a daily or monthly cadence. Each document includes fields such as resource ID, billing item, usage quantity, cost amount, and attribution tag. Units include yuan, hours, GB, and others. Data must be cross-checked by linking resource attributes and cost attribution scopes. The core goal is to explain resource consumption through cost attribution scopes.

## Constraints for database and operations workflows
Multi-source data access requires support for incremental synchronization and idempotent writes to avoid duplicate data accumulation. Multi-dimensional indexing must be built for complex field associations, to cut response times for core time-consuming tasks such as tag attribution verification and abnormal cost troubleshooting. Strict data validation mechanisms prevent incorrect data from triggering customer billing disputes, budget overruns, or resource waste. Cross-version upgrades must maintain database structure compatibility, to avoid report generation failures caused by field changes. Local deployments must reserve sufficient storage for monthly billing details and historical report data, to prevent disk space exhaustion.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:27017/fastgpt?authSource=admin` | Adapts to unstructured storage requirements for multi-source billing data, supports associated queries for tags and cost data, and is compatible with the database architecture of FastGPT v4.17.0 |
| `PG_URL` | `postgresql://[username]:[password]@[host address]:5432/fastgpt` | Used to store structured cost allocation tables and optimization suggestion sheets, ensuring stability for complex associated queries |
| `DB_MAX_LINK` | `150–200` | Adapts to concurrent connection requirements during daily bulk billing data imports, preventing synchronization failures caused by exhausted connections |
| `REDIS_URL` | `redis://[host address]:6379/0` | Used to cache frequently accessed resource tags and billing rules, reducing response times for abnormal cost troubleshooting |

## Three common errors
- Symptom: `getaddrinfo EAI_AGAIN mongo` error occurs after cross-version upgrade, and database connection fails. Cause: The host address in the `MONGODB_URI` configuration item was not updated when migrating the database directory, causing the service to fail to resolve the database address.
- Symptom: Disk space is exhausted during local deployment, and the process hangs and cannot write billing data. Cause: The storage cycle for historical billing data was not limited, and the automatic cleanup mechanism was not enabled, causing monthly bulk billing data to continuously occupy disk space.
- Symptom: Tag attribution verification takes too long, and report generation times out. Cause: No database index was created for the resource ID and tag fields, leading to low query efficiency caused by full table scans.

## How to confirm configurations are properly set
- Run a database connection test script to verify that the `MONGODB_URI` and `PG_URL` configurations can establish normal connections, with no timeout or permission errors.
- Import a test billing detail dataset to confirm that data can be written normally and linked to corresponding tags and billing items, with no missing fields or format errors.
- Check the database connection pool status to confirm that the current number of connections does not reach the limit set by `DB_MAX_LINK`, with no exhausted connections.
- Trigger a monthly report generation task to confirm that the task completes within a reasonable time frame, with no timeout interruptions.
