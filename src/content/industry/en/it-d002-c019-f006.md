# Release Notes and Operations Report Summary for Crowdsourced Annotator Management: Scheduled Tasks and Automation

## What Data for This Category Looks Like
This category’s data primarily comes from crowdsourcing platform backends, annotation quality spot-check records, annotator training exam results, and financial settlement systems. Daily produced documents include personnel access rules, onboarding training materials, monthly performance sheets, and quarterly settlement statements. Data updates follow daily and monthly cycles. Core fields include annotator ID, access review status, training exam score, order completion rate, quality pass rate, settlement amount, and more. Unlike single-item data processing for text annotation projects, this category focuses on data related to human resource organization and performance settlement for annotators, with no unified fixed field format.

## What Constraints These Characteristics Impose on Scheduled Tasks and Automation
The scattered data sources and inconsistent update cycles for this category require scheduled tasks to align with each data source’s update period. This prevents pulling incomplete temporary data. The field structures of different document types vary significantly. Automated summary workflows need separate parsing logic configured for personnel access rules, performance sheets, and settlement statements. This avoids field matching errors. Daily data summary tasks are suitable for triggering during non-business peak hours. Monthly settlement tasks must run after the financial system closes its books. Otherwise, unconfirmed temporary data will be pulled. Tasks involving settlements directly impact personnel salary payments. Clear retry mechanisms and exception alert rules must be configured. This prevents delays to the overall settlement process caused by single exceptions.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| Task Trigger Period | Daily tasks set to `02:00-04:00`, monthly tasks set to `01:00` on the 1st of each month | Avoids business peak hours, prevents disruption to annotator task acceptance and daily platform operations |
| Data Source Pull Interval | Daily quality data pull interval set to `1800 seconds`, monthly settlement data pull interval set to `86400 seconds` | Matches the update frequency of each data type, avoids redundant pulls that waste system resources |
| Document Parsing Template | Configure dedicated parsing templates for personnel access rules, performance sheets, and settlement statements | Adapts to differences in field structures across document types, improves the accuracy of summary results |
| Failure Retry Count | Set to `3 times`, retry interval set to `300 seconds` | Addresses temporary network fluctuations or short system freezes, reduces the probability of task failure |
| Exception Alert Trigger Threshold | Trigger alerts when task failure rate exceeds `10%` | Detects systemic exceptions promptly, prevents bulk errors in summary results |

## Three Common Misconfigurations
- Symptom: Automatically generated annotator performance indexes disappear automatically several hours after creation. Cause: No index persistence storage path is configured, or the task execution overwrites the storage directory of the existing index.
- Symptom: The personnel settlement amount field is empty in automatically generated monthly settlement statement summaries. Cause: No match is made for the settlement field aliases in the financial system, so the parsing process cannot correctly extract target data.
- Symptom: The platform root user password resets to the initial value automatically the next day. Cause: The scheduled task script accidentally includes execution logic for system initialization configuration, and does not limit processing to only configuration related to annotator data.

## How to Verify Proper Configuration
- Manually trigger a daily summary task, check whether the task logs include all configured data source pull records.
- Extract a sample generated operations report, verify whether core fields match the content of the original data sources.
- Simulate a task failure scenario, confirm whether the preset exception alert notification is triggered.
- Check the index storage directory, confirm that the generated annotator performance indexes are not automatically overwritten or deleted.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
