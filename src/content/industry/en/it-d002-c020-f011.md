# Release Notes and Operation Report Summary for Supplier and Equipment Arrival Management: Database and Operations

## What This Category of Data Looks Like
Typically, data for this category originates from ERP systems, supplier shipping invoices, logistics information platforms, and equipment manufacturer backends. Updates occur per order or weekly. Daily documents include purchase orders, arrival acceptance slips, serial number lists, and invoice materials. Data fields include purchase identifiers, equipment models, unique serial numbers, arrival times, acceptance results, associated project IDs, and additional relevant fields. This data supports full-process management of equipment arrivals for integrated projects, with the core goal of ensuring equipment aligns with project requirements and that book records match physical inventory.

## Constraints Imposed on the Database and Operations Link
Multiple data sources require the database to support integration with heterogeneous data sources, while meeting storage needs for both structured relational data and unstructured document data. The per-order or weekly update frequency requires the database to support incremental updates and bulk import capabilities, to avoid performance losses from full synchronization operations. Diverse document types require matching different table structure designs, such as a dedicated table for storing unique serial number identifiers, and a purchase order table linked to projects. At the same time, errors directly impact project delivery, so data backup and data entry verification mechanisms must be configured to prevent issues such as equipment mismatches and discrepancies between book records and physical inventory.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/fastgpt_arrival` | Stores unstructured business data such as equipment serial numbers and arrival acceptance records, specifies a dedicated database name to isolate business data |
| `PG_URL` | `postgresql://username:password@host:port/fastgpt_pub` | Stores relational data such as purchase orders and project association information, supports complex queries and transaction operations |
| `DB_MAX_LINK` | `20–30` | Adapts to the per-order or weekly update frequency, avoids excessive connection counts exhausting database resources, while ensuring concurrent processing capabilities |
| `REDIS_URL` | `redis://:password@host:port/0` | Caches logistics query results and equipment model mapping tables, reduces latency from multi-source data queries |

## Three Common Configuration Errors
- Symptom: After starting FastGPT v4.17.0, the mongo/data folder is not generated in the same-level directory. Cause: `MONGODB_URI` is not correctly configured to point to an external MongoDB instance, and the default built-in storage path is not enabled.
- Symptom: After using mongorestore to import knowledge base data, corresponding results cannot be queried. Cause: Data index reconstruction was not performed after import, or the database namespace of the current instance was not matched during the import process.
- Symptom: A MongoServerError: The dollar ($) p related error is prompted when loading a plugin. Cause: The deployed MongoDB version is incompatible with the current FastGPT v4.17.0 (such as 4.4.29), and the query syntax relied on by the plugin does not match the database version.

## How to Verify Successful Configuration
- Execute a database connection test command to verify the validity of the `MONGODB_URI` and `PG_URL` configurations, and confirm that the corresponding business tables can be read and written normally.
- Import a simulated purchase order data set, check whether the data can be correctly written to the corresponding database table, and that no fields are missing.
- View the Redis cache monitoring dashboard to confirm that the cache service configured via `REDIS_URL` can normally store and read temporary data such as logistics query results.
- Adjust the `DB_MAX_LINK` configuration, observe changes in database connection counts, and confirm that the connection count is controlled within a reasonable range.

The values provided are common starting points and should be measured against the reader's own samples.
