# Release Notes and Operations Report Summary for In-Feed Ad Creative Testing: Scheduled Tasks and Automation

## What This Category’s Data Looks Like
Core data for this category comes from ad platform APIs, internal asset libraries, user interaction data, and conversion data. Update frequencies are typically daily or weekly.
Documents processed daily include creative scripts, asset test sheets, delivery data reports, and iteration checklists. Asset test sheets typically use a structure where each row corresponds to a set of creative variable combinations, with fields including asset ID, copy content, delivery time slot, impressions, conversions, and more.
Data volume grows as test batches increase. A single week’s test data usually includes full delivery records for dozens of creative combinations.

## Constraints Imposed on Scheduled Tasks and Automation
Scattered data sources that require scheduled pulling mean scheduled tasks must support multi-data source call logic and permission verification.
Document structures center on row-level data, so automated processing must avoid invalid cross-row segmentation.
Differences in update frequencies require flexible adjustment of task cycles to meet needs for daily summaries and weekly iteration reports.
The timeliness of delivery data requires tasks to run during non-peak hours to avoid impacting online delivery.
Data anomalies may cause deviations in creative test conclusions, so failure alerts and retry mechanisms must be configured.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Scheduled Task Trigger Cycle | Once daily (2–4 AM) or once weekly (3 AM Monday) | Matches daily/weekly data update rhythms and avoids online delivery peak hours |
| Text Segmentation Rule | Split by row, treat each row as an independent segmentation unit | Adapts to the row-level data structure of asset test sheets and avoids logical confusion caused by default automatic segmentation |
| Data Source Pull Scope | Last 7 days of creative test data | Covers a complete creative iteration cycle and ensures reference value of summary reports |
| Failure Retry Count | 3 retries, 600-second interval | Addresses temporary fluctuations in ad platform APIs and reduces probability of single task failure |
| Alert Trigger Threshold | 2 consecutive task execution failures | Balances false alert risk and response timeliness for abnormal issues |
| Task Execution Permissions | Restricted to members of the creative team and growth team | Limits access scope for sensitive delivery data and aligns with internal permission management requirements |

## Three Common Misconfigurations
- Phenomenon: Automatic segmentation results are chaotic, with each row of test data not treated as an independent segment. Cause: The row-based segmentation rule was not configured, and default automatic segmentation logic was used instead.
- Phenomenon: No valid output or empty results after scheduled task execution. Cause: The API key for the ad platform data source was not configured correctly, or the pull scope was set too narrow to retrieve valid data.
- Phenomenon: Scheduled tasks fail to run normally after a local deployment version update. Cause: System environment variables were not configured per FastGPT v4.17.0 version requirements, and the service was not restarted to load new configurations.

## How to Verify Proper Configuration
- Manually trigger a scheduled task, then review the generated operations report segment content to confirm each row of test data corresponds to an independent segmentation unit.
- View task execution logs to confirm data source pulling was successful, with no API errors or missing data fields.
- Simulate a task failure scenario to verify that preset alert notifications are triggered.
- Check the local deployment environment variable configuration file to confirm version-required variables have been added correctly and are active.

Note: The configuration values listed above are common starting points. They should be evaluated against your own specific samples and use cases.
