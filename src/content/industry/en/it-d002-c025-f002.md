# Release Notes and Operations Report Summary for Duty Scheduling and Handover: Context and Token

## What the data for this category looks like
Core data for this category comes from scheduling systems, fault tickets, monitoring alerts, and organizational contact lists. Four types of documents are regularly output: duty schedules, handover records, escalation contact lists, and daily duty reports.
Update frequencies fall into two categories: daily and weekly. Duty schedules and same-day daily duty reports are updated daily. Escalation contact lists and monthly handover summaries are updated weekly.
Document structures include clear fields such as responsible parties, time ranges, pending items, and escalation paths. There is no unified standardized format, and data fields vary across different sources.

## What Constraints These Characteristics Impose on the Context and Token Link
Multi-source data with different update frequencies requires distinguishing the scope and priority of context recall. Real-time daily-updated data should be prioritized for inclusion in the context, while static weekly-updated data can be updated on a regular basis.
The token volume varies significantly across different documents. A single daily duty report is approximately hundreds of tokens, and a monthly handover summary can reach thousands of tokens. It is necessary to strictly control the total context token limit and the single reference token limit to avoid exceeding the model window.
The non-standardized nature of data fields requires matching core business fields during context recall to avoid unnecessary token consumption from irrelevant content.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | The total token volume of aggregated duty scheduling and handover documents usually falls within this range, and it adapts to the mainstream large model context windows supported by FastGPT v4.17.0 |
| `quoteMaxToken` | `2000–3000 token` | The token proportion of a single core business document such as same-day daily duty report or pending item handover slip, to avoid excessive context resource occupation from a single reference |
| Context recall limit | Top 10 entries | Prioritize recalling real-time data such as same-day duty schedules and fault tickets according to data priority, and limit the number of entries to control total token consumption |
| Context update frequency | Set separately according to data source | Scheduling system data is updated daily, escalation contact lists are updated weekly, matching the original data update rhythm to avoid redundant token consumption |

## Three Common Misconfigurations
- Phenomenon: The model prompts that the context token limit is exceeded, with the error message "context length exceeded". Cause: The `maxContext` parameter is not adjusted based on the actual total token volume of the duty scheduling summary document, causing the total context token to exceed the model limit.
- Phenomenon: Handover records recalled by the knowledge base are incomplete, and key pending items are not included in the context. Cause: `quoteMaxToken` is set too low, and the content of a single handover record is truncated, preventing core information from being fully transmitted.
- Phenomenon: The token consumption record from the Mongo query is inconsistent with the token statistics returned by the API. Cause: The context recall token and the token generated by the model reply are not distinguished. The splicing of multi-source duty scheduling data will generate additional token overhead, and this part of the consumption is not counted separately.

## How to Verify Proper Configuration
- Upload a typical duty scheduling summary document, check the total token count in the FastGPT context preview area, and confirm that it does not exceed the `maxContext` setting.
- Trigger a recall operation for handover records, check the completeness of the referenced content, and confirm that the token count of a single reference does not exceed the `quoteMaxToken` setting.
- Adjust the context recall limit parameter to verify that the number of returned duty data entries matches the expected priority sorting.
- Check the token consumption record in the FastGPT logs, compare the actual called token count with the set context token limit, and confirm that the matching meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
