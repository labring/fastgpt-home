# Release Notes and Operations Report Summary for Duty Scheduling and Handover: Database and Operations Maintenance

## What This Category’s Data Looks Like
This category includes four types of daily core documents: duty schedules, handover records, escalation contact lists, and daily duty reports. Data sources include scheduling systems, fault tickets, monitoring alerts, and organizational contact directories. Update frequency is daily or weekly.
Duty schedule fields include duty time periods, responsible persons, and contact information. Handover records include pending items, pending alerts, and escalation paths. Escalation contact lists include job roles, names, and backup contact information. Daily duty reports include daily alert volume and processing status. Most field types are text, time, and contact identifiers, with no complex numerical units.

## Constraints for Database and Operations Maintenance
The multi-source nature of the four core document types requires the database to support mixed unstructured and structured storage. Establish an association between duty responsible persons and the organizational contact directory. The daily or weekly update frequency requires configuring differentiated scheduled synchronization tasks to balance data timeliness and system load. Implement transaction consistency guarantees for strongly associated fields such as pending items and escalation paths to prevent response delays caused by missed handovers. Configure the database connection pool with sufficient concurrent connections to meet the real-time requirements of fault tickets and monitoring alerts, avoiding query timeouts. Create a dedicated index for the duty schedule time period field to accelerate scheduling conflict troubleshooting. Synchronize contact information changes across all associated documents to avoid unresponsive issues caused by invalid contact details.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:27017/fastgpt_sre?retryWrites=true` | Stores unstructured handover records and daily duty reports, supports flexible field expansion and associated queries |
| `PG_URL` | `postgresql://[username]:[password]@[host]:5432/sre_ops` | Stores structured duty schedules and escalation contact lists, ensures transaction consistency and associated query efficiency |
| `DB_MAX_LINK` | `15–25` | Adapts to concurrent requirements of batch synchronization tasks and real-time alert queries, prevents connection pool exhaustion |
| `REDIS_URL` | `redis://:[password]@[host]:6379/1` | Caches frequently accessed escalation contact and duty time period data, reduces database query pressure |
| Scheduled Synchronization Trigger Cycle | 10–15 minutes (real-time alert scenarios), 24 hours (weekly scheduling scenarios) | Matches the daily/weekly data update frequency, balances timeliness and system resource usage |

## Three Common Configuration Errors
- Symptom: Local database connection fails after deployment. Logs return `connection timed out` or `authentication failed`. Cause: Host address, port, or authentication parameters for `MONGODB_URI` or `PG_URL` are not configured correctly. Network access permissions for the local database are not opened.
- Symptom: Timeout errors occur during batch scheduling data synchronization. Query result counts are lower than expected. Cause: The `DB_MAX_LINK` parameter is not set appropriately. Insufficient concurrent connections cause partial queries to queue and time out.
- Symptom: The pending items field in duty handover records is empty, and cannot be associated with corresponding fault tickets. Cause: Multi-table association foreign key constraints are not configured, or scheduled synchronization task cycles are too long, resulting in delayed data synchronization.

## How to Verify Configurations Are Correct
- Execute a database connection test script to verify connectivity for `MONGODB_URI`, `PG_URL`, and `REDIS_URL`. Verify no authentication or network errors are present.
- Manually trigger a scheduled synchronization task. Check that duty schedule and handover record data is fully synchronized, with no missing fields.
- View database index status. Confirm that the composite index for duty time period and responsible person fields has been created and activated.
- Simulate a scheduling conflict query. Verify that query response time meets business requirement thresholds. These thresholds must be calibrated based on actual concurrent volume.

The values provided are common starting points and should be measured against the reader's own samples.
