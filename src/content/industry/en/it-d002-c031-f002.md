# Release Notes and Operation Report Summary for Creator Onboarding and Verification: Context and Token

## What the data for this category looks like
Normally, data for creator onboarding and verification comes from creator backend, enterprise credit information query APIs, account historical operation logs, and contract systems. Daily processed documents include onboarding application forms, transcribed text of identity qualification scans, verification audit records, and draft cooperation agreements. Data update frequency is either daily batch synchronization or real-time updates per individual application. Data fields associated with a single application usually include account ID, qualification number, audit status, cooperation period, and similar items. There are no unified fixed statistical percentage data.

## What constraints these characteristics impose on context and token processing
Dispersed data sources and varied fields require context recall to cover associated data from multiple systems, and prevent token overflow. Differences in update frequency require configured token thresholds to adapt to distinct scenarios of real-time applications and batch audits. The number of documents associated with a single application is limited, but their content complexity is high. Precise control of the total context token volume is needed to ensure efficiency of qualification verification and risk judgment. Differences in audit processes across entities require certain flexibility in context chunking and recall rules, to avoid data loss caused by fixed configurations.

These configurations are based on FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Supports total token volume of multiple associated documents including onboarding applications, qualification materials, and audit records, and adapts to the average data scale of daily business |
| `quoteMaxToken` | `2000–3000 token` | Limits token consumption of a single core document such as transcribed qualification text or cooperation agreement, to avoid single reference exceeding billing or processing thresholds |
| Context recall count | Top 3–5 entries | Audit records and qualification materials associated with a single application usually do not exceed 5 entries. Excessive recall will occupy unnecessary token resources |
| Qualification data chunk length | 1000–1500 characters | Adapts to single-block text length of enterprise credit information and account history, and balances recall accuracy and token consumption |
| Audit history token quota | Calibrated via actual testing | The number of audit record fields varies across platforms. Adjust specific values based on actual business data |

## Three common configuration mistakes
- Scenario: Calling the FastGPT workflow API returns an empty context, even when context is configured in the workflow. Cause: The context parameter matching `maxContext` is not included in the API request, or the parameter value does not cover audit records and qualification materials associated with the application.
- Scenario: Official point billing is abnormal, and token consumption exceeds expectations. Cause: No reasonable upper limit is set for `quoteMaxToken`, causing token consumption of a single qualification document to exceed the threshold corresponding to billing rules.
- Scenario: Qualification verification fails after deploying bge-reranker via docker. Cause: No parameters matching FastGPT context configuration are added to the environment configuration in docker-compose.yml, causing chunked qualification data to not be correctly reranked.

## How to confirm correct configuration
- Log in to the FastGPT backend, enter the configuration panel of the target workflow, and check whether the values of `maxContext` and `quoteMaxToken` match the average token volume of business documents.
- Submit a test onboarding application, call the workflow API, and check whether the returned context data includes complete qualification materials, audit records, and account historical information.
- Check the official point consumption log, compare the token consumption of a single application with the setting of `quoteMaxToken`, and confirm that consumption does not exceed the preset range.
- Check the docker-compose.yml file of the docker-deployed bge-reranker service, and confirm that context processing parameters in the environment configuration match the FastGPT configuration.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
