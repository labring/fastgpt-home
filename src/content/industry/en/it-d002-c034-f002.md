# Release Notes and Operation Report Summary for Office System Process Configuration: Context and Token

## What the data for this category looks like
Core data for this category comes from enterprise OA systems, organizational structure libraries, internal system documents, and user feedback. Four types of documents are regularly generated: process configuration sheets, approval node tables, form field descriptions, and change records. Data is updated in real time when processes are modified, or synchronized once per month on a centralized basis. Document structures center on core fields including process nodes, permission rules, and form fields, and include content such as node approver scope, trigger conditions, and field validation rules. There is no unified fixed standard format, and structures are adjusted to fit the enterprise’s office system.

## Constraints on context and token processing
Data sources are scattered and formats vary significantly. Format confusion is likely to occur when combining context, so targeted processing of document structures from different sources is required. Update frequencies fluctuate widely. If temporarily changed process data is not synchronized in a timely manner, the context will contain expired configuration rules. Single documents focus on a single process node, and integrating complete logic across multiple nodes consumes a large amount of token. A balance must be struck between context completeness and token usage limits. Additionally, accuracy requirements for configuration content are high. Context truncation or token overflow will cause approval rules to be lost, leading to process exceptions.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Single-node document content for office process configurations is usually several hundred characters. Integrating complete context for 5 to 8 nodes requires matching this token limit, which is calibrated based on actual testing in FastGPT v4.17.0 |
| `quoteMaxToken` | 1500–2000 token | When extracting core referenced content such as approval rules and permission configurations, ensure key information is complete and does not exceed the single-segment token limit |
| Chunk overlap length | 100–150 characters | There are associated logical relationships between process nodes; overlapping chunks prevent associated node information from being truncated |
| Single recall limit | Top 6 entries | Associated documents for office process configurations are mostly node tables and change records within the same system; recalling too many entries will cause excessive token usage |
| Context truncation strategy | Retain latest changed content | Process data is updated frequently; prioritize recently effective configuration rules to avoid expired information interfering with configuration logic |

## Three common misconfigurations
- Incorrectly setting the App/Admin server environment variables `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` may result in connection timeout or 401 Unauthorized errors. Troubleshooting steps include confirming the variable values do not contain extra spaces, are not empty, and match the AI Proxy server configuration. `AIPROXY_API_ENDPOINT` is the root address of the AI Proxy service (format example: http://aiproxy:3000, do not append paths such as /v1). `AIPROXY_API_TOKEN` is the AI Proxy administrator token.
- An E11000 duplicate key error occurs when adding users related to process configuration, indicating a conflict in the wisegpt collection. The cause is duplicate submission of the same user identification field, and no unique key validation rule was set in the configuration.
- Excessively large chunk sizes during RAG knowledge base processing lead to excessive context token usage, resulting in result truncation or matching failures. The cause is failing to adjust chunk parameters, and using default values directly when processing Excel-format process configuration data.

## How to confirm configurations are correctly set
- Submit a single process change test, check whether approval node configurations are fully loaded, with no missing or incorrect permission rules.
- Check the App/Admin service startup logs, confirm that the server environment variables `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` loaded normally, with no startup validation failure prompts.
- Randomly select 10 process configuration documents, verify that the chunked context content has no obvious truncation, and core approval rules are fully retained.
- Simulate a user feedback submission, confirm the system can correctly recall relevant change records and system documents, with no unrelated content included.
