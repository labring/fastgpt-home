# Release Notes and Operations Report Summary for Change Management and Release Windows: Scheduled Tasks and Automation

## What the data for this category looks like
Data for this category comes from change management systems, CI pipelines, business monitoring data, and business calendars. Daily associated documents include change request forms, risk assessment reports, launch window plans, and rollback plan documents. Data updates follow individual change or weekly cycles. Individual data entries include fields such as change number, application time, risk rating, window time period, associated CI task ID, and monitoring indicator thresholds. There is no unified fixed unit standard; field formats are defined based on the business attributes of each associated document.

## What constraints do these data characteristics impose on scheduled tasks and automation
The data characteristics of this category impose multiple constraints on scheduled tasks and automation. Multi-source data integration requires tasks to adapt to authentication rules and data formats of different interfaces such as change management systems and CI pipelines, to prevent cross-system synchronization failures. The update rhythm tied to individual changes or weekly cycles requires task trigger cycles to match the planned periods of change windows, to avoid running summary operations during business peak hours. Differences in fields across multiple associated document types require automated logic to be configured with flexible field extraction rules, to adapt to the structures of different documents such as change request forms and risk reports. Additionally, the high potential impact of errors requires tasks to be configured with failure retry and alert mechanisms, to prevent missing summary data from causing approval oversights or business outages.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Task trigger cycle | 1 day before the change window / every Monday at 00:00 | Matches the update rhythm of this category’s individual change or weekly cycles, to avoid affecting approval processes by running too early or too late |
| Data pull scope | Last 7 days of change records / pending approval change requests | Covers all change data within the current cycle, to avoid missing critical information |
| Failure retry count | 3 times | Addresses pull failures caused by temporary interface fluctuations, to reduce manual intervention costs |
| Alert trigger threshold | 2 consecutive pull failures | Notifies operations personnel promptly to troubleshoot system abnormalities, to avoid summary delays |
| Document field mapping rules | Calibrated based on actual testing | Adapts to field differences across documents such as change requests and risk assessments, to ensure accurate summary data |
| Task execution time window | Business low-peak period (such as 2:00 - 4:00 AM) | Avoids occupying production resources and disrupting business operations |

## Three common configuration mistakes
- Symptom: Scheduled tasks do not trigger according to the change window, and summary data for the corresponding cycle is not generated. Cause: The task trigger cycle is configured as fixed daily execution, and does not match the update rhythm of this category’s individual change or weekly cycles.
- Symptom: The change summary task returns a 403 status code, and cannot pull data from the change management system. Cause: Cross-system integration authentication parameters are not configured, resulting in interface access being blocked.
- Symptom: Risk rating fields are empty or formatted incorrectly in operation reports. Cause: Field mapping rules adapted to different documents are not configured, so the rating fields in risk assessment reports cannot be identified.

## How to confirm correct configuration
- Manually trigger a scheduled task on FastGPT v4.17.0, and check if the generated operation report includes all associated documents within the current cycle.
- Simulate an interface pull failure, and confirm if the preset alert notification is triggered.
- Review the task execution log to confirm that the data pull scope matches the configured trigger cycle.
- Verify the field mapping rules to confirm that core fields such as risk rating and launch window can be correctly extracted.
