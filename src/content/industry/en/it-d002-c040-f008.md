# Release Notes and Operation Report Summary for Pre-sales Technical Solutions: Workflow Orchestration

## What the data for this category looks like
Data related to pre-sales technical solutions comes from customer interview records, bidding documents, vendor product materials, and historical project plans. The update frequency is per order or weekly. Daily output documents include technical proposal books, customer demand research forms, quotation lists, and demo scripts. Data fields cover technical routes, implementation boundaries, quotation items, demo nodes, and more. Fields across different documents have high correlation, so cross-document consistency checks are required to ensure unified and accurate proposal content.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Multi-source data requires cross-source verification nodes to be added to the workflow to prevent conflicts between data obtained from different channels. The high update frequency requires the workflow to support rapid iterative adjustments, reduce repeated configuration steps, and adapt to the rapid update needs of individual pre-sales solutions. Multiple types of documents need to adapt to the format parsing capabilities of different components to ensure that fields from each document can be called uniformly. The most time-consuming demand clarification and solution boundary design links must be split into independent workflow nodes to enable targeted optimization. Data errors may lead to consequences such as lost bidding opportunities, so verification and rollback links must be added to ensure solution quality.

## Configuration Settings
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable scope | Only current workflow instance | Ensure data isolation for individual pre-sales solutions, avoid confusion between `variables` from different projects |
| Node timeout period | 300-600 seconds | Adapt to the conventional processing duration of individual pre-sales solution links, avoid process interruption due to excessive waiting time |
| Component parameter editing permission | Customizable editing | Adapt to the personalized parameter needs of different pre-sales solutions, support adding custom parameters for specified `nodeId` |
| Log retention period | 7 days | Adapt to the log retention requirements of pre-sales solutions, facilitate later troubleshooting of workflow issues |
| Variable trigger timing | After the pre-assignment node is completed | Ensure that completed assigned `variables` can be obtained when the button is clicked |
| Workflow export format | Standard structured format | Facilitate solution reuse and cross-team transmission |

## Three Common Configuration Errors
- The print information of workflow code running nodes cannot be viewed. This occurs because the log collection configuration for the corresponding node is not enabled.
- The parameters of workflow components cannot be modified. This occurs because the default configuration of basic components is locked, and custom editing permission is not enabled.
- The global variable obtained when the button is clicked is empty. This occurs because the trigger timing precedes the `variables` assignment node, and the system does not wait for variable assignment to complete.

## How to Confirm the Configuration Is Correct
- Trigger the corresponding workflow node, view the node log panel, and confirm that print information is output normally.
- Edit the target workflow component, confirm that the parameter editing box opens normally and allows modification of parameter content.
- Trigger the button bound to the variable acquisition logic, view the global variable panel, and confirm that the assigned variable value is obtained.
- Export the current workflow configuration, confirm that the exported file format is complete and includes all configuration items.
