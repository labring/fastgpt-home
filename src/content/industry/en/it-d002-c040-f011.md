# Release Notes and Operation Report Summary for Pre-Sales Technical Solutions: Database and Operations

## What Data for This Category Looks Like
This category of data primarily comes from daily deliverables created by system integrator pre-sales consultants, solution architects, and sales teams. Deliverables include technical proposal documents, customer requirement survey forms, quotation lists, and demo scripts. Data sources include customer interview records, bidding documents, vendor product materials, and historical project proposals. The update frequency is per order or weekly. Data document structures include fields such as customer requirement items, technical roadmaps, implementation boundaries, and quotation items. Field units are typically items, yuan, days, and similar units. There is no fixed, rigid unified format. The structure must adapt to storage needs for multiple types of documents.

## Constraints on Database and Operations Workflows
Diverse data sources and uneven update frequencies require the database to support on-demand synchronization and regular incremental updates. This avoids excessive container resource usage from full synchronization operations. The multi-type document structure demands flexible field mapping capabilities. Hard-coded fixed table structures cannot be used. Errors in pre-sales proposals directly impact bidding and project revenue. A data verification and backup mechanism must be configured to ensure data integrity. The pre-sales team’s collaboration needs require the database to support high-frequency concurrent retrieval. Index and connection pool parameters must be properly designed to prevent retrieval delays that reduce daily work efficiency.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:password@mongo:27017/fastgpt?authSource=admin` | Adapt to non-relational document storage for FastGPT v4.17.0, supports flexible storage of multiple types of pre-sales proposals |
| `DB_MAX_LINK` | `12` | Matches concurrent access needs for up to 20 pre-sales proposals per week, avoids container connection pool overflow |
| `REDIS_URL` | `redis://redis:6379/1` | Caches historical proposal keywords and quotation data from frequent retrievals, reduces database query latency |
| `PG_URL` | `postgresql://fastgpt:password@postgres:5432/fastgpt?schema=pre_sales` | Stores structured customer requirements and quotation lists, supports complex conditional queries |

## Three Common Misconfigurations
- Symptom: No results are returned when checking database dependency versions using in-container commands, even though corresponding dependency declarations exist in package.json. Cause: The dependency query command was not executed in the correct working directory of the FastGPT container, or the container does not have a complete dependency toolchain pre-installed.
- Symptom: Empty or malformed fields are returned when retrieving pre-sales proposals. Cause: Storage types for structured and unstructured data were not differentiated, and all pre-sales documents were stored in a single database collection, leading to failed field mapping.
- Symptom: Connection timeouts occur when concurrently calling proposal retrieval interfaces. Cause: The `DB_MAX_LINK` configuration value is too low to meet the concurrent access needs of multiple pre-sales team members collaborating.

## How to Confirm Configuration Is Complete
- Execute the in-container database connectivity test command to verify the connection status of `MONGODB_URI` and `PG_URL`, and confirm configuration correctness based on returned success indicators.
- Import a test pre-sales proposal document, check if stored data fields match the original document structure, and adjust mapping rules based on actual document formats.
- Initiate multiple concurrent proposal retrieval requests, observe database connection pool usage, and adjust the `DB_MAX_LINK` value based on concurrent access scale.
- Trigger a database backup operation, verify that the backup file is fully generated and restorable, and set the backup cycle based on data update frequency.

The values provided are common starting points and should be measured against the reader's own samples.
