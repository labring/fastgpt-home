# Release Notes and Operations Report Summary for Security Training and Phishing Drills: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category typically originates from employee contact lists, corporate email gateways, internal training platforms, and user click statistics systems. Daily produced documents include security training courseware, phishing drill plans, phishing email templates, and drill result reports. The data update cycle is mostly quarterly or annual. Core fields cover the scope of drill coverage, template content, click behavior data, review conclusions, and more. There are no fixed, unified standard units, and adjustments are made per internal enterprise specifications.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
Data for this category comes from dispersed sources. Multiple external systems must be integrated to obtain personnel information, email sending data, and behavior statistics. As a result, interfaces must support multi-source data pulling and unified authentication.
Data updates occur at a slow pace but involve large single-batch data volumes. Interfaces must support batch requests and pagination processing to avoid overload from individual requests.
Drill result reports require complete audit trails to be retained. Interface return fields must include traceable operation identifiers and timestamps to prevent audit gaps caused by missing fields.
Additionally, because errors may lead to the risk of employee data leaks, interface error handling must include clear status codes and error messages to enable rapid problem identification and remediation.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${secret_key}` | Complies with the interface authentication specification of FastGPT v4.17.0, ensuring secure calls from external systems |
| `variables` | `{"campaign_id": "xxx", "template_type": "phishing"}` | Passes the campaign identifier and template type for phishing drills, matching the parameter matching rules of external systems |
| `responseData` | `Top 1000 records` | Adapts to the conventional data volume of review reports, avoiding performance impacts from overly large returned data sets |
| Interface Timeout | `600 seconds` | Adapts to the time required for batch pulling of drill data, preventing mid-process interruptions that result in incomplete data |
| Data Pull Scope | `Last 1 quarter` | Matches the conventional update frequency of this category, reducing invalid data pulls and resource consumption |

## Three Common Configuration Mistakes
- The phenomenon is that interface calls return delays far exceeding the duration of direct curl calls. The cause is that FastGPT’s internal context splicing and data verification processes consume additional time, and the request pipeline is not optimized for batch pulling of drill data.
- The phenomenon is that click statistics fields returned by the interface are empty. The cause is that the campaign ID or template type parameters in `variables` are not configured correctly, preventing external systems from matching the corresponding drill data.
- The phenomenon is that interface calls return a 403 status code. The cause is that the `Authorization` parameter does not carry a valid authentication key, or the key’s permissions do not cover the pull scope of drill data.

## How to Verify Correct Configuration
- Run a curl command to call the configured interface, and check if the returned `responseData` field includes personnel or click data related to drills.
- View the FastGPT interface call logs, and confirm that the format of the `Authorization` parameter complies with the `Bearer ${secret_key}` specification.
- Compare the original data from external systems with the fields returned by the interface, and confirm that the campaign identifier passed by the `variables` parameter matches correctly.
- Simulate a batch data pull, and check that the number of records returned by the interface falls within the preset range defined by the `responseData` value.
