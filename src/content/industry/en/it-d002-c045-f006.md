# Release Notes and Operations Report Summary for Security Training and Phishing Drills: Scheduled Tasks and Automation

## What This Category's Data Looks Like
This category’s core data comes from employee contact lists, corporate email gateways, internal training platforms, and phishing drill click statistics systems. Some assessment score data comes from the online quiz module of the training platform. Daily produced documents include standardized training courseware, single drill plans, phishing email templates, and final drill result reports. The data update rhythm is usually quarterly or annual. Some high-frequency temporary drill scenarios can adjust the update frequency as needed. Data fields include drill population scope, email sending records, click behavior data, training assessment scores, etc. There are no unified fixed units, and corresponding dimensions need to be matched based on individual drill scenarios.

## What Constraints Do These Characteristics Impose on the Scheduled Tasks and Automation Link
The data sources for this category are scattered and diverse, requiring scheduled tasks to adapt to multi-system interface docking and permission verification, and avoid permission verification conflicts during cross-data source synchronization. Daily document formats are not uniform, so automated processes need to preset parsing and archiving rules for multiple types of documents, ensuring that drill materials and result reports are classified and stored in line with internal training and audit requirements. Data update rhythms are flexible, so the trigger cycle of scheduled tasks needs to support custom adjustments to adapt to the different needs of quarterly regular drills and temporary emergency drills. Full data aggregation is the core of review, so automated tasks need to ensure the integrity of data source pulling. Otherwise, audit missing items or risks of rectification without evidence will occur.

## How to Set Up the Configuration
This configuration is based on the scheduled task module of FastGPT v4.17.0. The specific parameter settings are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Cycle | Set according to the drill plan, supports `1 day`, `7 days`, `30 days` or custom cycles | Adapt to flexible scheduling for quarterly/annual regular drills and temporary scenarios |
| Data Source Pull Scope | Check the three core data sources: employee contact list, email gateway, and click statistics | Cover complete collection of drill population, sending records, and behavior data |
| Result Report Archiving Path | Fixed to the corporate security operations exclusive directory | Meet fast retrieval requirements during audits |
| Failure Retry Count | `3 times`, with a retry interval of `60 seconds` | Respond to task interruptions caused by temporary network fluctuations or interface timeouts |
| Abnormal Alarm Trigger Threshold | Trigger an alarm when the task failure rate exceeds `10%` | Timely locate batch data pull abnormal issues |
| Document Automatic Classification Rule | Match corresponding folders by drill type | Distinguish storage logic for training courseware, drill plans, and result reports |

## Three Common Mistakes
- Phenomenon: The classified call count statistics field is empty after the scheduled task runs. Cause: The employee contact list data source was not checked, resulting in the classified population scope not being synchronized, making it impossible to count the call data for the corresponding classification.
- Phenomenon: Document content conflict fields appear in the operation report generated by the scheduled task. Cause: No document deduplication and conflict verification rules were configured, resulting in inconsistent content in the same field across multiple drill materials.
- Phenomenon: Active message sending to WeChat Work external groups fails, returning status code 403. Cause: External group conversation permissions were not configured, or the robot account for the scheduled task was not added to the target external group.

## How to Confirm the Configuration is Complete
- View the scheduled task trigger log to confirm that all configured data sources have successfully pulled data.
- Manually trigger a task to verify that the generated result report is archived and classified and stored according to the preset path.
- Simulate a data source interface exception to confirm whether the task triggers retries and alarms as configured.
- Reconcile the statistical data of a single drill to confirm that fields such as classified call counts and click data match actual collection results.
