# Release Notes and Operations Report Summary for Security Training and Phishing Drills: Database and Operations Maintenance

## What this category's data looks like
Data for this category originates primarily from employee contact lists, email gateways, training platforms, and click statistics tools. Daily generated documents include training courseware, drill plans, phishing email templates, and drill result reports. Data updates occur on a quarterly or annual basis. Core fields include participant information, click behavior records, drill completion status, and rectification associated records. No fixed statistical units are tied to the data. Corresponding behaviors and results are only recorded per business scenario. No unified statistical caliber is preconfigured.

## Constraints on database and operations maintenance
Decentralized data sources require connection configuration for multiple data source types. Corresponding connection parameters must be set for different data sources such as employee contact lists and email gateways. Data updates concentrate immediately after drill completion. Bulk records may be generated in a short time. Database maximum connection counts must be limited to avoid resource exhaustion. Flexible field structures have no mandatory fixed format. Databases that support dynamic schema must be selected. Data involves employee behavior and security results. Permission isolation rules must be configured to prevent sensitive data leaks. Indexes must be optimized during group filtering queries to improve retrieval efficiency and reduce single-task duration.

## Configuration guidelines
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/[database name]?authSource=admin` | Meets storage requirements for unstructured data such as phishing drill click statistics and employee contact lists |
| `PG_URL` | `postgresql://[username]:[password]@[host address]:[port]/[database name]` | Used to store structured fixed-format data such as drill plans and result reports |
| `DB_MAX_LINK` | 10–15 | Balances concurrent demand for bulk data writes after drills and database resource usage, avoiding connection exhaustion |
| `REDIS_URL` | `redis://[host address]:[port]/[database number]` | Caches temporary query results for drill group filtering, reducing repeated database query overhead |
| Database connection timeout | 600 seconds | Adapts to latency across cross-data source queries, preventing task interruptions from network fluctuations |

## Three common configuration errors
- Issue: Parameter format errors occur when passing database connection parameters via variables. Manual SQL execution runs without errors. Cause: Special characters in variables are not properly escaped. Connection strings are truncated or corrupted, so databases cannot recognize them.
- Issue: Database tool calls in workflows return connection timeout or permission denied errors. Cause: Cross-network access security group rules are not configured, or database connection pool parameters are set too small, leading to insufficient concurrency to handle bulk requests.
- Issue: Authentication failure prompts appear when connecting to MongoDB. Cause: The `authSource` parameter is not correctly specified, or special characters in the username or password are not escaped in the connection address, so identity verification fails.

## How to verify successful configuration
- Manually fill in test connection parameters, run basic query statements, and confirm expected test data is returned.
- Import a small drill plan template, submit a storage request, and confirm data is successfully written to the corresponding database table or collection.
- Trigger a simulated group filtering query, check that cached results are correctly generated and can be read quickly.
- Simulate bulk writing of drill result data, observe that database connection counts do not exceed limits, and tasks execute successfully without errors.
