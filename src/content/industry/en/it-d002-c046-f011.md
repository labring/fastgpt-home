# Release Notes and Operation Report Summary for Security Baseline Checks: Database and Operations

## What the data for this category looks like
This category of data is sourced from server configurations, middleware configurations, security device policies, and collection results from baseline tools. Four types of documents are regularly produced: baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. Data is updated monthly or quarterly. Core fields include configuration item number, current configuration value, compliance status, rectification deadline, and exception approval number. No fixed statistical values exist; corresponding records are generated only based on actual verification results.

## What constraints these characteristics impose on the database and operations link
Data sources are scattered and mostly static configurations. Multi-source heterogeneous database access must be supported. Update frequency is low, but historical versions must be retained. Therefore, the database must support periodic archiving and version rollback. Daily documents include multi-field associated records. An association index between configuration items and verification results must be established. The most time-consuming verification link must support batch import and export to reduce manual entry costs. Errors are linked to security risks. The database must ensure that configuration data cannot be tampered with and that access audits are supported.

## How to set configurations
These configurations apply to FastGPT v4.17.0 for the database and operations link:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `PG_URL` | Configure as an authenticated cluster access address that includes all collection nodes, set connection timeout to 30 seconds | Adapt to distributed storage of multi-source baseline data, ensure connectivity for writing and reading structured verification records |
| `DB_MAX_LINK` | 100–200 connections | Match the batch processing concurrency requirements of monthly updated data, avoid exhausting database connection resources |
| `REDIS_URL` | Configure a local cache node, set key expiration time to 86400 seconds | Cache frequently accessed baseline templates and approval statuses, improve query efficiency |
| `MONGODB_URI` | Configure read-write separated cluster connection parameters | Used to store unstructured original baseline verification data, improve high-volume write performance |
| Database backup path | Specify an independent disk directory mounted locally, storage space no less than 1000 MB, automatically archive quarterly | Meet compliance data retention requirements, prevent data loss |

## Three Common Mistakes
- A database connection error occurs, with the log showing "retry init root user mongo start connect init root user error". The cause is that the correct authentication username and password were not added to `MONGODB_URI`, or the allowed access IP whitelist was not configured.
- Knowledge base data fails to synchronize to the deployed database, and the knowledge base list appears empty in the interface. The cause is that `PG_URL` was not correctly configured to point to the Docker-deployed database instance during source code deployment, and the initialization script for synchronizing table structures was not executed.
- A field mismatch error occurs when batch importing baseline checklists. The cause is that the upload was not performed according to the preset document field order, causing the database to fail to recognize the corresponding relationship between configuration items and compliance status.

## How to Confirm Configurations Are Correctly Set
- Perform a batch import test of baseline data, check the database logs for connection exception errors, confirm that configuration items such as `PG_URL` and `MONGODB_URI` correctly point to the target database instances.
- Log in to the database management interface, check whether the table structures corresponding to baseline checklists and configuration verification records have been generated, confirm that the data writing function operates normally.
- Trigger a quarterly data update task, check whether the corresponding baseline template cache keys have been generated on the cache node linked to `REDIS_URL`, confirm that the cache configuration is effective.
- View the database connection number monitoring panel, confirm that the current connection number does not exceed the threshold set by `DB_MAX_LINK`, confirm that the connection resource configuration is reasonable.

The values provided are common starting points and should be measured against the reader's own samples.
