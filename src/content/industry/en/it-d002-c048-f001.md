# Release Notes and Operation Report Summary for Security Monitoring and SOC Duty: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category primarily comes from SIEM, EDR, NDR, and third-party threat intelligence sources. Update cycles fall into two categories: real-time and daily. Routine produced documents include alarm disposal sheets, duty logs, threat intelligence briefings, and monthly operation weekly reports. Each document contains fields such as alarm ID, disposal time, involved IP, judgment result, and dispatch record. Some daily documents require hourly aggregation of alarm counts and disposal progress. Fields must uniformly comply with standardized security operation format requirements.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multi-source heterogeneous data sources require HTTP interfaces to support parsing and adaptation of different security data formats. This avoids alarm judgment delays caused by missing fields or inconsistent formats. Real-time updated alarm data requires setting a reasonable interval for interface timeout thresholds. This ensures stability of real-time data synchronization and avoids impacting false positive elimination and upgrade disposal workflows. Daily updated operation reports require support for batch pulling. Interfaces must have pagination pulling capabilities. This prevents timeouts or response failures caused by excessive data volume in a single request, which would affect the efficiency of daily and weekly report aggregation. Additionally, fields in security operation documents must align with downstream systems such as ticketing systems and command platforms. Interfaces must support custom field mapping. This ensures consistency of data flow and adapts to standardized disposal workflows in SOC duty scenarios.

## How to configure the settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a token in the format `Bearer <API_KEY>` | Complies with HTTP interface authentication standards and adapts to access requirements for multiple security data sources |
| `variables` | Set to `{"source": ["SIEM", "EDR", "NDR"]}` | Limits data pulling scope and matches the multi-source data source characteristics of this category |
| `responseData` | Only return the fields `alert_id, handle_time, threat_level` | Filters redundant data and adapts to lightweight data flow requirements in SOC duty scenarios |
| Timeout Threshold | 600 seconds | Adapts to pulling delays for real-time alarm data and avoids request failures caused by network fluctuations |
| Pagination Parameters | 100 entries per page | Adapts to batch pulling requirements for daily updated operation reports and balances request efficiency and data volume |

## Three common configuration mistakes
- Receiving empty results or a 401 status code after calling the HTTP interface. The cause is incorrect configuration of the `Authorization` parameter, non-compliant token format, or failure to bind the corresponding API key.
- Only partial data being returned when pulling operation reports in batch. The cause is failure to set reasonable pagination parameters, with the single request data volume exceeding the interface's carrying limit, leading to data truncation.
- No synchronized update of the alarm judgment workflow being triggered after calling the interface. The cause is failure to configure the correct data source identifier in `variables`, causing the interface to fail to match data from corresponding security devices.

## How to confirm successful configuration
- Manually call the configured HTTP interface and check if the returned `responseData` fields include preset alarm or operation report fields.
- Simulate the push of real-time alarm data and confirm that external systems can normally receive synchronized alarm information.
- Check the FastGPT interface call logs to confirm there are no records of authentication failures, timeouts, or field parsing errors.
- Compare manually exported operation reports with data pulled via the interface to confirm consistency of fields and content.
