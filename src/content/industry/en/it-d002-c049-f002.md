# Release Notes and Operation Report Summary for Customer Training and Usage Manuals: Context and Token

## What the data for this category looks like
Daily documents for this category include training slides, user manuals, training attendance sheets, and Q&A lists. Data sources primarily include the product help center, customer organizational structures, recorded training sessions, and ticket systems. Updates occur per order or per version. Document structures typically include fields such as version identifiers, operation steps, permission descriptions, and Q&A records. There are no unified fixed units. Some documents must be associated with customer-specific organizational information and usage scenarios.

## What constraints these characteristics impose on the context and token workflow
Data sources are scattered and include unstructured recorded training sessions and ticket records. Incorporating split segments into context leads to fluctuating token consumption, so the total length of recalled segments must be strictly controlled. Update frequency varies by version or order. Each update requires rechecking document versions associated with the context to avoid mixing old version content into the current context, which would add unnecessary token consumption. Documents include segmented fields such as role permission descriptions. Context recall must accurately match customer roles; otherwise, token limits will be exceeded, resulting in responses that include content beyond permission boundaries. Q&A lists have significant long-tail content. The effective length of a single recalled segment must be controlled to prevent token overflow from affecting response completeness and accuracy.

## How to Set Configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Aligns with the model context limit for FastGPT v4.17.0, matches the average length of single documents such as training slides and user manuals, and prevents single recalls from exceeding model context limits |
| `quoteMaxToken` | `1000–1500 characters` | Matches the per-entry content length of Q&A lists and ticket records, ensuring recalled segments do not consume excessive tokens |
| Maximum context recall count | Top 3 entries | Controls total token consumption based on the volume of associated data from training attendance sheets and organizational structures |
| Context matching threshold | `0.75–0.85` | Accurately matches customer roles and permission descriptions, preventing irrelevant content from being included in the context |
| Token overflow handling strategy | Truncate redundant segments at the end | When total context tokens exceed limits, prioritize retaining the latest version of training content and core operation instructions |

## Three Common Mistakes
- Increasing chat history limits does not enable context memory, and responses returned by the interface do not reference historical training content. The cause is incorrect configuration of the `maxContext` parameter, or an overly high recall matching threshold, which prevents valid historical segments from being included in the context.
- Knowledge base capacity calculation results do not match expectations, and token consumption costs cannot be accurately estimated. The cause is failure to limit the length of single recalled segments using `quoteMaxToken`, leading to a discrepancy between the total estimated document tokens and actual storage consumption.
- Token limit exceeded errors are returned when calling dataset creation-related APIs. The cause is failure to control the total token count for context recalls, resulting in the inclusion of multiple outdated versions of redundant training slides and Q&A records.

## How to Verify Correct Configuration
- A test training slide is uploaded, and the recalled context segments are checked to confirm they include the latest version of operation steps.
- A user query from a corresponding role is simulated, and the referenced content in the response is verified to match the permission description for that role.
- The token consumption field returned by the API is reviewed, and the total tokens are confirmed to not exceed the preset `maxContext` limit.
- After multiple document version updates, the context recall content is verified to automatically switch to the latest version of the documents.

The values provided are common starting points and should be evaluated against relevant samples.
