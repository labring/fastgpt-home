# Release Notes and Operation Report Summary for Customer Data Import Migration: Context and Token

## What the data for this category looks like
Typical executors for this category include implementation consultants, data implementation engineers, and customer IT liaisons. They regularly produce four core documents: data templates, migration plans, field mapping tables, and migration verification reports. Data sources cover customer legacy systems, CSV or Excel templates, database exports, and product import logs. Update frequency is per order or irregular. Core time-consuming steps focus on field mapping confirmation, dirty data cleaning, and post-import sampling checks. Consequences of errors include lost historical data, misaligned fields, and customer rejection. This process only handles migration of business data into the new system, and is distinct from tenant initialization operations.

## How these characteristics constrain context and token configuration
The data characteristics of this category directly restrict context and token configuration logic. Multi-source heterogeneous data sources lead to significant differences in token consumption per batch of data. The two core parameters `maxContext` and `quoteMaxToken` must be flexibly adjusted to adjust context quotas, to cover import logs, field mapping tables, and historical data fragments. Irregular update frequencies mean configurations do not need to be fixed for a single business scenario, and can be dynamically adjusted based on the document structure of each migration order. The high proportion of dirty data requires reasonable truncation of overly long fields, to avoid content loss due to exceeding token limits. At the same time, core business data includes import logs and mapping tables, which must be included in the context range to support summary analysis of release notes and operation reports. Sufficient token quotas must therefore be reserved for calls of this reference data.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 2000–8000 tokens, adjusted based on migration order data volume | Large differences exist in data batches for this category, requiring coverage of total token consumption from import logs, field mapping tables, and historical data fragments |
| `quoteMaxToken` | 500–1200 tokens, upper limit for single referenced data entry | Field lengths for business data in this category are uneven; overly long fields will exceed token limits and trigger truncation |
| Maximum context window | Calibrated via actual testing, no more than 80% of the model’s supported limit | Token quotas must be reserved for display of summary text from release notes and operation reports |
| Context recall count | 3–7 entries, adjusted based on imported data scale | Core reference data for this category includes import logs and field mapping tables; too many entries will consume excessive token quotas |

## Three common configuration mistakes
- Phenomenon: Migration task classification results always match the default fallback category, and do not associate with historical field mapping rules. Cause: `maxContext` is not configured to include historical reference data, and only the token quota for the current single data entry is called. This prevents the model from obtaining sufficient contextual features.
- Phenomenon: Token encoder-related infinite restart errors occur on Docker-deployed FastGPT instances. Cause: `quoteMaxToken` is not adjusted based on the total token volume of imported data, leading to token encoding overflow that triggers abnormal system restarts.
- Phenomenon: After increasing context recall count, summary content in release notes does not include expected historical import logs. Cause: `maxContext` quota is not adjusted synchronously, leading to newly added recall entries exceeding the token limit and being automatically filtered out.

## How to confirm correct configuration
- View the import log details page for FastGPT v4.17.0, confirm that the context area displays at least 3 historical import records and corresponding field mapping information.
- Test importing CSV data with a single overly long field, confirm that no token overflow error prompts appear, and that content is not truncated meaninglessly.
- Cross-check the summary text in release notes, confirm that associated migration plans and verification report fragments have been correctly included in the context display range.
- Check the system’s token usage statistics panel, confirm that total consumption does not exceed the configured context quota limit.
