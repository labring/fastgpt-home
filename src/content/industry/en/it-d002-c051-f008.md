# Summary of Release Notes and Operational Reports for Customer Data Import and Migration: Workflow Orchestration

## What this category of data looks like
The data for this category primarily comes from customer historical business systems, CSV/Excel templates, and database export results. Its update frequency is per individual order or irregularly. Daily supporting documents include data templates, migration plans, field mapping tables, and migration verification reports. Data fields must match the business rules of the target system, including core fields such as customer identifiers, business serial numbers, and business content. There are no unified fixed units, and values vary based on specific business scenarios.

## Constraints on Workflow Orchestration From These Characteristics
Data sources are scattered and formats are inconsistent. This requires workflows to support multi-format data access nodes, and adapt parsing rules for different export formats. Update frequencies are not fixed, so workflows must support on-demand triggering to avoid resource waste from fixed cycles. Supporting documents rely on field mapping relationships. Workflows must embed field validation nodes to ensure mapping rules match the target system. Missing core fields or incorrect format errors will cause migration failures. Workflows must configure dirty data cleaning and exception interception steps to reduce error risks.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Field mapping validation rules | Configure validation logic according to the field mapping table provided by the customer, matching required fields of the target system | Ensure imported data complies with target system field requirements, avoid field misalignment |
| Dirty data cleaning threshold | Trigger interception when null value proportion exceeds 30% | Filter invalid data, reduce import failure probability |
| Workflow trigger timing | Trigger based on the import task identifier in `variables` | Match business scenarios where individual tasks run independently, support parallel multi-tasks |
| Import timeout setting | 600 seconds | Adapt processing duration for bulk data imports, avoid task interruptions |
| Exception alert node | Push import logs to a specified receiving channel after triggering | Facilitate timely troubleshooting of migration failure causes |
| Sampling verification node | Extract the first 100 data entries for field validation after import | Verify overall migration accuracy |

## Three Common Misconfigurations
- The text extraction node in the workflow does not configure a user input waiting branch after failing to match target content, and directly triggers the end node. The phenomenon is that workflow run logs show the workflow ends immediately after the text extraction node has no matching results, with no fallback response. The cause is that no fallback response and waiting logic are configured for extraction failure scenarios, leading to early task termination.
- Multimodal data and plain text data are not split according to processing needs, and tool call nodes are used uniformly. The phenomenon is that the workflow uniformly calls tool call nodes to process multimodal data, and returned results do not meet expectations. The cause is that no data type judgment branch is configured in the workflow, and adaptive models for different data types are not distinguished.
- The reference upper limit setting for knowledge base search is set to 3000, which is inconsistent with the configuration rules of the simplified Chinese application terminal. The phenomenon is that the number of returned results from the knowledge base search node in the workflow does not match expectations. The cause is that configuration differences between workflows and application terminals are not distinguished, and parameters from other scenarios are incorrectly reused.

## How to Verify Correct Configuration
- Upload a test CSV template, trigger workflow execution, and check if each node’s run logs match the configured validation rules.
- Construct test data with a null value proportion exceeding 30%, verify if the dirty data interception node normally triggers an alert.
- Configure the import task identifier in `variables`, trigger the workflow, and confirm the trigger timing matches expectations.
- Extract partial data after import, check if field mapping matches preset rules.

The values provided are common starting points and should be measured against the reader's own samples.
