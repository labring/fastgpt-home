# Release Notes and Operation Report Summary for Customer Demand Pool Management: Workflow Orchestration

## What the data for this category looks like
This category of data mainly comes from ticketing systems, customer interview records, CRM systems, and product roadmaps. Daily produced documents include demand pool lists, demand assessment forms, customer feedback records, and version planning descriptions. The data update frequency is once per week or per product version. Fields include demand ID, associated customer identifier, feedback time, priority tags, assessment cost items, and scheduling status. There is no unified mandatory format, and documents must be organized according to the team’s general template.

## What constraints these characteristics impose on the "workflow orchestration" link
Data for this category comes from multiple disparate systems, and documents have no unified format. This requires workflows to support multi-source data pulling and flexible field mapping configurations. The data update frequency is once per week or per version, so workflows must support both scheduled triggering and manual triggering. Since demand-related information is complex, workflow nodes must pass core fields such as demand ID and customer identifier via `variables`, and use `nodeId` to distinguish pulling nodes from different data sources to avoid data confusion. Additionally, the demand merging and assessment links take a long time, so workflows must include preset automatic merging rule nodes to reduce repetitive manual operations.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable configuration | Preset `variables` as demand ID, associated customer identifier | Aligns with FastGPT v4.17.0 global variable calling rules, used to pass core demand identifiers across nodes |
| Workflow trigger rule | 2 AM every Monday or 1 day before each version release | Matches the weekly or per-version data update frequency |
| Field mapping rule | Adjust field correspondence according to the team’s general document template | Adapts to daily demand documents with no unified format |
| Node identifier configuration | Use `nodeId` to distinguish data source pulling nodes | Differentiates demand data from different sources such as ticketing systems and CRM |
| Error retry configuration | Retry 3 times after failure, 60-second interval | Addresses temporary exceptions in third-party system interface calls |
| Demand merging rule | Merge duplicate demands via keyword matching | Reduces time-consuming manual merging operations |

## Three common misconfigurations
- Phenomenon: Knowledge base retrieval nodes in workflows cannot reference preset `variables`. The interface shows empty variables or errors occur during calling. Cause: Global variable reference permission is not enabled in node configuration, or variable names do not match preset names.
- Phenomenon: The number of demand matching results returned after workflow runs does not match expectations, or no matching data is returned. Cause: Field mapping rules do not correctly associate demand keywords with retrieval conditions, leading to incorrect retrieval scope.
- Phenomenon: Workflows remain unresponsive for a long time after triggering, or stay in the running status. Cause: No error retry rule is configured, and the workflow does not automatically terminate after the first third-party system interface call fails.

## How to confirm the configuration is complete
- Enter the workflow editing page, check whether the global variable list includes preset fields such as demand ID and associated customer identifier.
- Manually trigger the workflow once, view the node running logs, and confirm that the `variables` field has been correctly passed to downstream nodes.
- Verify that the workflow trigger time matches the data update frequency, and confirm that the scheduled task has been enabled normally.
- Simulate a third-party system interface call failure scenario, and check whether the preset retry rule is triggered.
