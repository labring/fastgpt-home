# Publishing Instructions and Operation Report Summary for Advertising Compliance Record-Keeping: HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data covers all compliance retention vouchers for the full advertising compliance workflow. Daily documents include four core file types: advertising review forms, qualification attachments, delivery records, and rectification notices. Data sources are advertising platform backends, customer qualification systems, contract management systems, and public regulatory rule databases. Updates are triggered by individual advertising campaigns, with monthly summary archiving. Each data entry includes fields such as compliance subject identifier, review node time, retained file hash value, rectification closed-loop status, and does not have a fixed unit field. Unit information from the original business system must be associated.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Since data sources cover multiple dispersed external systems, HTTP interfaces must support multi-source identity authentication and adapt to authentication formats of different systems. Data updates are triggered by individual advertising campaigns, with monthly summary archiving. Interfaces must support on-demand trigger synchronization to avoid invalid polling consuming resources. Compliance voucher data must fully retain key node information. Interfaces must verify the completeness of required fields in returned data. Additionally, since errors may lead to regulatory penalties and customer accountability, interfaces must record request and return logs for each call, and support retry recovery after failures. This configuration is formulated based on the interface specifications of FastGPT v4.17.0.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication Method | Set the `Authorization` parameter to `Bearer {dedicated API key}` | Compliance data requires strict access control, meeting identity authentication requirements for advertising compliance |
| Sync Trigger Parameter | Set `variables` to `{"sync_scope": "active_campaign", "archive_cycle": "monthly"}` | Adapts to the category's rhythm of activity-based updates and monthly summarization, avoiding unnecessary synchronization |
| Return Data Validation | Validate required fields in `responseData` | Ensures compliance voucher data is complete, preventing missing key information such as review nodes and file associations |
| Retry Count | 3 times | Addresses scenarios where external systems are temporarily unavailable, ensuring synchronization success rate |
| Timeout Period | 600 seconds | Adapts to time requirements for pulling multi-source data, preventing synchronization process interruptions |
| Log Storage Configuration | Store complete request and return logs | Meets compliance traceability requirements, facilitating troubleshooting of missing evidence during regulatory inspections |

## Three Common Configuration Mistakes
- Issue: The `responseData` field is empty after calling the interface. Cause: The synchronization scope in the `variables` parameter was not configured correctly, causing the interface to fail to match the corresponding compliance data source.
- Issue: The interface returns a 401 Unauthorized status code. Cause: The `Authorization` parameter was not configured correctly, using an expired or non-dedicated API key.
- Issue: Some delivery records are not archived after synchronization. Cause: Required fields in returned data were not validated, causing some compliance vouchers to fail to be retained successfully.

## How to Verify Successful Configuration
- Call the interface and check that the return status code is 200 to confirm that the authentication configuration is effective
- Check that the returned `responseData` field includes preset required compliance fields to confirm that the data validation configuration is correct
- Simulate a single advertising campaign to trigger synchronization, check that the number of synchronized data records recorded in the logs matches expectations, to confirm that the sync trigger configuration is effective
- Confirm that the currently used FastGPT version is v4.17.0 to ensure interface configuration is compatible with the version
