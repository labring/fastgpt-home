# Publishing Notes and Operational Report Summary for Ad Creative Review: HTTP Interfaces and External Systems

## What the data for this category looks like
The core document carriers for this category’s data are ad creatives, landing page screenshots, review opinions, and modification records. Data sources include ad delivery platforms, landing page hosting services, product qualification filing systems, and advertising law compliance clause libraries. Data updates occur in real time or via daily batch jobs. Each individual data entry includes a unique creative identifier, delivery channel type, violation point classification, review result, and modification traceability fields. There are no universal standard units for these fields. Some fields require association with external compliance libraries for validation.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Multiple data sources require interfaces to support multiple sets of authentication rules to adapt to different external systems. Real-time or high-frequency update requirements require interface timeout thresholds to match business response rhythms, avoiding data delays. Core documents include unstructured creatives and structured review records. Interfaces must support both file stream and structured parameter transmission. Fields must strictly match the compliance verification logic of ad reviews. Interface parameters must cover exclusive fields such as violation types and review statuses. Error responses must clearly associate specific exceptions in the review process, enabling rapid localization of compliance risks.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {Exclusive Authentication Key for Ad Platform}` | Adapts to the standard authentication format for external ad review systems, ensuring interface access permissions |
| `variables` | `{"audit_scope": "creative compliance", "channel_list": ["mainstream delivery channels"]}` | Passes exclusive business identifiers for ad creative review, enabling external systems to classify and aggregate operational data |
| `responseData` | `Includes creative ID, violation type, review time, handler identifier` | Accurately returns core fields required for operational report aggregation, reducing invalid data transmission |
| Number of creatives per single request | 50–100 entries | Calibrated via actual testing, adapts to daily batch processing scales for ad reviews, avoiding overload of external systems |
| Interface timeout threshold | 180–300 seconds | Matches the average review duration for a single ad creative, preventing mid-task interruptions for batch jobs |

## Three common mistakes
- When calling the interface, the return message is "Workflow verification failed. Please check for missing or empty fields, and verify that connections are normal". The cause is failure to correctly pass the exclusive ad creative review fields in `variables`, or failure to configure a valid key for the `Authorization` parameter. This prevents external systems from identifying the business context.
- The `Human` field in the interface’s `responseData` is null. The cause is failure to include an association identifier for the creative submitter in the request parameters, or failure of the external system to synchronously store this field information, resulting in missing returned data.
- Configuring `AIPROXY_API_ENDPOINT` to an incorrect address. This variable is the root address of the AI Proxy service (for example, http://aiproxy:3000. Do not append /v1 or business interface paths). It is a required environment variable for the App/Admin server. Incorrect configuration will cause failure of the AI Proxy dependency startup verification.

## How to confirm correct configuration
- Call the test interface, verify that the `Authorization` parameter is correctly carried, and that the response header includes a valid authentication status code.
- Check that the fields returned in `responseData` include core content required for operational report aggregation, such as creative ID and violation type, with no redundant fields.
- Submit a batch creative request, confirm that the interface returns a complete list of review results within the timeout threshold matching the average review duration for a single ad creative, with no timeout errors.
- Check that the `variables` parameter received by the external system includes correct ad review business identifiers, enabling normal classification and statistics of operational data.
