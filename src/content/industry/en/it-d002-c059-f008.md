# Release Notes and Operational Report Summary for Ad Creative Review: Workflow Orchestration

## What this category of data looks like
This category of data comes from advertising delivery platforms, landing page hosting services, product qualification documents, and advertising law compliance clauses. Daily processed documents include ad creative files, landing page screenshots, review opinion sheets, and modification record ledgers. The data update frequency is daily or real-time. Each piece of data corresponds to the full-process information of a single delivery creative. Fields include creative unique identifier, violation type label, review opinion content, and modification timestamp. The most time-consuming processing steps are creative copy compliance check, landing page content consistency verification, and manual violation point annotation.

## What constraints these characteristics impose on the "workflow orchestration" link
Decentralized data sources require the workflow to connect to multiple independent data source nodes, pulling creatives, landing pages, and qualification documents separately to avoid data aggregation confusion. Real-time or daily update frequencies require the workflow to support a combination of event triggering and scheduled polling, preventing compliance risks caused by delayed processing. The characteristic that a single creative corresponds to an independent review process requires the workflow to split tasks by creative unique identifier, avoiding logical conflicts from batch processing. The sensitivity of compliance-related data requires the workflow to configure permission isolation nodes to prevent sensitive qualification information leaks. The review result of each creative is directly linked to delivery risk, so a result verification and abnormal alert link must be added to the workflow to ensure problems are detected in a timely manner.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Event triggering + scheduled polling (interval 300 seconds) | Matches real-time update and daily batch processing needs, avoids missing creative updates |
| `variables` Assignment Rules | Bind three fields: creative ID, violation type, review opinion ID | Accurately associates full-process data of a single creative, meets the requirement of splitting tasks by creative |
| Data Source Node Concurrency | 2-4 | Adapts to the pulling needs of multiple data sources, avoids exceeding interface call limits |
| `nodeId` Mapping Rules | Bind in the order of creative review nodes: creative pull → compliance check → result generation → alert push | Ensures workflow node execution order matches the review process, avoids logical confusion |
| Abnormal Alert Trigger Conditions | Review failure, unmarked violation items, timeout exceeding 600 seconds | Covers core error scenarios, notifies reviewers in a timely manner |

## Three Common Misconfigurations
- Phenomenon: The `variables` parameter is assigned an empty value during API calls, and the workflow cannot pull the corresponding creative data. Cause: Core fields such as creative ID are not bound to the `variables` configuration item, resulting in missing parameter transmission.
- Phenomenon: When calling a large model to check knowledge base references in the workflow, only a single reference content is returned, and compliance basis from multiple sources cannot be associated. Cause: The `variables` binding rule for multiple fields is not configured correctly, preventing the large model from obtaining complete reference data.
- Phenomenon: Workflow node execution exceeds the set threshold, triggering an abnormal alert but failing to locate the specific problematic creative. Cause: Nodes and creative identifiers are not bound according to the `nodeId` mapping rule, causing the alert to fail to associate with the problematic creative.

## How to Confirm the Configuration is Correct
- Trigger the review process for a test creative, check whether the workflow log pulls the corresponding creative, landing page, and qualification data.
- Call the test API, verify whether the `variables` parameter correctly transmits core fields such as creative ID, and whether the returned result matches expectations.
- Simulate a review failure scenario, confirm whether the abnormal alert node is triggered and associates the corresponding `nodeId` and creative identifier.
- Check the workflow node execution order, confirm whether each link is executed in sequence according to the `nodeId` mapping rule.
