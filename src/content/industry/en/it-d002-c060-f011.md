# Release Notes and Operation Report Summary for Ad Account Opening Audit: Database and Operations

## What the data for this category looks like
This category's data primarily comes from ad platform backends, the National Enterprise Credit Information Publicity System, customer-submitted account opening application materials, and industry access rule documents.
Data updates follow two cadences: daily batch synchronization of qualification data, or real-time submission triggered by individual account opening applications.
A complete single dataset includes fields including subject name, qualification certificate number, audit status, submission time, and correction communication records.
Each dataset is associated with the full set of qualifications and audit process records for a single account opening subject.

## Constraints on Database and Operations Workflows
Differences in multi-source data formats require the database layer to perform unified field mapping, to avoid data chaos after ingestion.
The update cadence of either per-application or daily requires support for high-concurrency single writes and precise queries, to avoid long table locks that impact audit efficiency.
Sensitive qualification data storage requires strict permission isolation to prevent information leaks.
Data anomalies directly lead to account opening failures or non-compliant delivery.
Therefore, data validation rules must be configured to intercept non-compliant fields before ingestion, ensuring data quality.

## Configuration Settings
This configuration is based on FastGPT v4.17.0 database operations logic.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://audit:secure123@db-host:27017/advert_audit?authSource=admin` | Stores unstructured qualification scans and audit record attachments, supports flexible field expansion |
| `PG_URL` | `postgresql://audit:secure456@db-host:5432/audit_core?sslmode=require` | Stores structured account opening applications, audit statuses and correction processes, ensures transaction atomicity |
| `DB_MAX_LINK` | `25–35` | Meets concurrent connection requirements for daily batch qualification verification and real-time account opening audits |
| `REDIS_URL` | `redis://:redis-pass@cache-host:6379/1` | Caches frequently accessed industry access rules and subject verification results, reduces repeated database queries |
| Data Validation Switch | Enabled | Intercepts invalid data with missing qualification numbers or empty subject names, prevents invalid data ingestion |

## Three Common Configuration Mistakes
- Symptom: Connection timeout or authentication failure is displayed when connecting to the FastGPT local MongoDB database via MongoDB Compass. Cause: The username, password and authentication database parameters in `MONGODB_URI` are not configured correctly, or the local firewall blocks access to port 27017.
- Symptom: The number of audit records returned by database queries does not match the actual number of submitted applications. Cause: The `DB_MAX_LINK` parameter is not set appropriately, and some connections are rejected during concurrent writes, leading to data loss.
- Symptom: Structured audit status fields are empty, making it impossible to generate operation reports. Cause: The data validation switch is not enabled, leading to invalid empty field data being ingested, which destroys the integrity of report statistics.

## How to Verify Correct Configuration
- Run the FastGPT built-in database connectivity detection script to verify whether the connections for `MONGODB_URI` and `PG_URL` are normal.
- Submit a simulated account opening application, check whether data can be correctly written to the corresponding database instance, and that all required fields have content.
- View the Redis cache hit statistics metrics to confirm that the cache service configured via `REDIS_URL` properly handles high-frequency query requests.
- Adjust the `DB_MAX_LINK` parameter, simulate a high-concurrency write scenario, and observe whether connection exhaustion-related errors occur.

The values provided are common starting points and should be measured against the reader's own samples.
