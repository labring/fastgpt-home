# Release Notes and Operation Report Summary for Campaign Setup: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category typically originates from advertising platform APIs, user profiling tools, budget scheduling spreadsheets, and attribution tools. Update cadences fall into two categories: daily updates and triggers per individual campaign. Commonly referenced documents include campaign plans, targeting settings, budget schedules, and conversion tracking configurations. Core fields include targeting dimensions, budget amounts, conversion event IDs, delivery time windows, and similar attributes. Common units of measurement are yuan, occurrences, days, and other standard units.

## Constraints on HTTP Interfaces and External Systems
Multi-source, structurally complex data for this category creates multiple constraints for HTTP interface and external system integrations. First, advertising platforms, user profiling tools, and other disparate sources use different authentication rules. Interfaces must support standardized authentication configurations to prevent cross-platform call failures. Second, update cadences include daily updates and single-campaign triggers. This requires interfaces to support both scheduled pulling and event-triggered call modes to fit different operational scenarios. Additionally, campaign plans include multi-field structures such as targeting settings and budget scheduling. Configuration must be passed via structured parameters to avoid delivery errors caused by missing fields. FastGPT v4.17.0 includes optimized interface adaptation logic for this scenario, supporting format conversion and validation for multi-source data.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${custom token}` | Matches the universal authentication format for advertising platform APIs |
| `variables` | Structured object containing targeting dimensions, a budget amount of 5000-10000 yuan, and conversion event IDs | Matches the field structure of campaign plan documents |
| `responseData` | Return the first 10 active campaign plans for the current day | Adapts to daily operational summary viewing needs |
| Retry Threshold | 3 retries with a 60-second interval | Addresses temporary fluctuations in advertising platform interface performance |
| Timeout Setting | 300 seconds | Adapts to interface response times for complex campaign plans |

## Three Common Configuration Mistakes
- Interface call results do not match platform test interface display: Returned campaign plan data differs from content shown in the interface. The root cause is failure to correctly pass targeting configuration filter parameters via `variables`, leading to mismatched request coverage.
- Empty interface response fields: Conversion tracking data is missing. This occurs when required return fields are not specified in `responseData`, leading to valid data being filtered out.
- Frequent rate limiting triggers: A 429 status code is returned. This occurs when a reasonable request interval is not set, exceeding the advertising platform's call frequency limits.

## How to Verify Successful Configuration
- Call the interface, then review the returned `responseData` to confirm it includes core campaign plan fields.
- Compare the number of active daily campaign plans returned by the interface with the count shown in the platform interface to confirm data alignment.
- Simulate an abnormal request to confirm the interface returns an expected error status code.
- Configure a scheduled trigger task to confirm automatic pulling of the latest operation report data on a daily basis.
