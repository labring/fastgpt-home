# Publishing Instructions and Operational Report Summary for Campaign Setup: Scheduled Tasks and Automation

## What This Category of Data Looks Like
This category of data primarily comes from advertising platform APIs, user profile datasets, internal budget scheduling tables, and attribution tool APIs. Daily produced documents include campaign setup documents, targeting setting configuration tables, budget scheduling tables, and conversion tracking configuration items. The data update frequency is daily or within the corresponding advertising campaign launch cycle. Individual data entries include fields such as target audience tags, budget amounts, and conversion event identifiers. Field units include yuan, person-times, days, and others. There is no unified fixed format, and each dataset must match the field specifications of the corresponding advertising platform.

## What Constraints Do These Characteristics Impose on Scheduled Tasks and Automation
Since data sources involve multiple external tools and internal documents, scheduled tasks must adapt to the interface formats of different advertising platforms to avoid cross-platform data parsing failures. Data update frequencies are not fixed, so task trigger logic must support daily cycles or triggers based on advertising campaign nodes. Daily document structures vary, so automated workflows must support documents in multiple formats such as campaign setup and targeting settings, and cannot rely on a single parsing template. There are no unified field specifications, so flexible field mapping rules must be configured to prevent misalignment of core data such as target audiences and budget amounts. At the same time, the most time-consuming links including audience targeting configuration, budget allocation, and conversion event verification must be covered to reduce manual operation costs.

## How to Configure Settings
This instruction applies to FastGPT v4.17.0.

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Task Trigger Timing | 2 AM daily / 1 day before advertising campaign launch | Matches the daily data update rhythm of advertising platforms and pre-launch preparation needs |
| Data Pull Scope | Campaign setup documents and associated data from the past 7 days | Covers the complete campaign preparation cycle to avoid missing pre-launch configurations |
| Field Mapping Rules | Match preset fields for the target advertising platform | Adapts to field formats of different platforms and reduces data parsing errors |
| Failure Retry Count | 3 times | Balances API call costs and data pull success rates |
| Abnormal Alert Trigger Condition | 2 consecutive failed task executions | Notifies abnormal situations promptly to avoid impacting campaign preparation |
| Document Parsing Mode | Auto-adapt based on document type | Supports documents in multiple formats such as campaign setup and targeting settings |

## Three Common Mistakes
- Symptom: The pop-up window remains visible when a campaign setup task nested in another workflow is executed. Cause: The pop-up trigger configuration for the task node was not disabled, and nested calls retain the original pop-up settings by default.
- Symptom: When a scheduled task pulls campaign setup documents from an external data source, returned fields are empty. Cause: Automatic synchronization permissions for the corresponding data source were not configured, so the task cannot obtain the latest document content.
- Symptom: Frequent API call failure errors occur during task execution. Cause: Reasonable failure retry counts were not set, and the single API call timeout did not trigger the retry mechanism.

## How to Confirm Proper Configuration
- Manually trigger a scheduled task, check the task execution log, and confirm that data pulling, document parsing, and field mapping links are all completed normally.
- Simulate a task failure scenario and confirm that abnormal alert notifications are triggered properly.
- Compare automatically generated operational reports with manually organized campaign setup data and confirm that core fields match correctly.
- Test the nested call scenario and confirm that no extra pop-up windows are displayed during task execution.
