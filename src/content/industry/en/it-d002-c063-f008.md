# Publishing Instructions and Operation Report Summary for Campaign Setup: Workflow Orchestration

## What the data for this category looks like
The data used for campaign setup scenarios comes primarily from advertising platforms, user profile databases, budget scheduling tables, and attribution tools. Four types of documents are produced regularly: campaign plans, targeting settings, budget schedules, and conversion tracking configurations. Fields include targeting audience tags, budget amounts, conversion event IDs, delivery time windows, and more. Units include yuan, visits, days, and others. Data updates typically happen daily or when a single campaign starts. There is no fixed batch synchronization cycle. The size of individual data entries shifts based on campaign scale. This document is written based on FastGPT v4.17.0.

## What constraints these characteristics impose on workflow orchestration
Campaign setup data is multi-source heterogeneous and updates on a flexible schedule. Workflows must support parameter transfer between multiple nodes to maintain data consistency across targeting settings, budget allocation, conversion verification, and other steps. Document structures have many subdivided fields, so input and output variables for each node must be mapped precisely to avoid parameter mismatches. Since data updates have no fixed batch cycle, workflows must support event-triggered or short-interval scheduled runs to accommodate temporary campaign plan adjustments. Incorrect delivery configuration will directly cause budget waste or delivery failure. Workflows must include built-in exception capture and retry mechanisms.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Mode | Triggered by campaign plan update events, interval no more than 600 seconds | Matches the daily or campaign-level update rhythm of campaign plans |
| Variable Binding | Associate targeting audience and budget amount fields in `variables` | Corresponds to the standard field structure of campaign plan documents |
| Execution Order Configuration | Sort all tool nodes in ascending order of `nodeId` | Ensures tool calls are executed sequentially, avoiding dependency conflicts |
| Failure Retry Strategy | Up to 3 retries, 120 seconds interval per attempt | Addresses temporary fluctuations in advertising platform APIs |
| Context Retention | Cache logs and parameters from the last 2 workflow executions | Facilitates troubleshooting of campaign plan configuration exceptions |
| Variable Reference Scope | Limited to the `variables` of the current workflow node | Prevents parameter pollution across workflows |

## Three common configuration errors
- Multiple tools in the workflow do not execute in the expected order, and some nodes have no call logs. The cause is failure to configure the execution order by `nodeId`, or failure to correctly bind dependency parameters between nodes.
- After deployment, the workflow and knowledge base configuration is blank, but the API can be called normally. The cause is that the local storage volume was not mounted persistently, and configuration files were not retained after container restart.
- Variable references are invalid when selecting a knowledge base, and the specified knowledge base content cannot be loaded. The cause is failure to declare the referenced knowledge base ID variable in `variables`, or the variable scope does not cover the current node.

## How to confirm the configuration is complete
- Trigger a test campaign plan update, and check whether the execution status of each node in the workflow log is successful.
- Manually modify the field values of the campaign plan document, and verify whether the workflow automatically pulls the updated parameters for execution.
- Disconnect the advertising platform API to simulate an exception, and check whether the workflow triggers the preset failure retry logic.
- View the `variables` configuration panel, and confirm that all referenced campaign plan fields have been correctly mapped.
