# Publishing Instructions and Operation Report Summary for Tender Document Preparation: HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data comes from tender announcements, bidding documents, enterprise qualification databases, and supplier quotations. Each tender project receives independent updates for its associated data. Core documents cover tender documents, qualification certificates, business deviation tables, and technical deviation tables. Fields include tender numbers, project names, qualification verification items, clause response content, associated file IDs, and other relevant items. There are no unified fixed multi-project batch fields. A single document is bound to exactly one tender project.

## What constraints these characteristics impose on HTTP interfaces and external systems
The single-project bound data characteristic requires interface calls to use a unique tender project ID as the core identifier. This prevents cross-project data confusion. The differentiated field structures of multiple document types require interface parameters to support dynamic field mapping. This adapts to the field requirements of different documents such as qualification certificates and deviation tables. The decentralized nature of data sources requires external systems to aggregate multi-source data via HTTP interfaces. It also requires strict compliance checks on incoming fields to prevent bid invalidation risks. Each call must match the full data scope of a single project. This avoids missing key qualifications or response clauses.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Interface authentication method | `Authorization` header carries `Bearer Token` format | Complies with industry-standard API authentication specifications to secure interface calls |
| Request timeout period | 300–600 seconds | Tender document data for single projects has large volume; prevents call interruptions due to network latency |
| Variable mapping rule | Bind a dedicated field set per tender project ID | Adapts to the data characteristic of independent updates per single project, avoids cross-project data confusion |
| Response data processing | Only return business results encapsulated in the `responseData` field | Complies with FastGPT standard interface return formats, simplifies external system data parsing |
| Retry trigger condition | Trigger when receiving a 5xx status code or an empty `responseData` field | Addresses temporary network fluctuations or interface exceptions, ensures complete data acquisition |
| Field verification configuration | Verify the existence of mandatory fields specified in tender requirements | Aligns with the consequences of errors during tender document preparation, proactively avoids bid invalidation risks |

## Three common configuration errors
- Issue: When passing a file ID during an interface call, the returned collection ID does not match the expected value. Cause: The mapping relationship between file collections and file IDs was not bound per tender project dimension. This causes cross-project data interference.
- Issue: The `responseData` field returned by the interface is missing key qualification item content. Cause: The corresponding field mapping rules for tender requirements were not configured in `variables`. This prevents the interface from extracting correct business data.
- Issue: Unnecessary retry operations are triggered after an interface call. Cause: Retry trigger conditions were not configured correctly. 4xx status codes for parameter errors were included in the retry scope, wasting call resources.

## How to confirm configuration is complete
- Call the interface with parameters for a known tender project. Check if the returned `responseData` field contains core document data for that project.
- Simulate a temporary network exception. Check if the interface triggers retry actions per the configured retry conditions.
- Pass fields that do not meet tender requirements. Check if the interface triggers the corresponding verification logic.
- Call the interface to obtain a collection ID. Check if it is correctly bound to the passed file-id.
