# Publishing Instructions and Operation Report Summary for Bid Document Preparation: Database and Operations

## Data Structure for This Category
This category of data is generated for bid-related business. Daily processed documents include bid documents, qualification certificates, commercial deviation forms, and technical deviation forms. Data sources include tender announcements, bidding documents, enterprise qualification databases, and supplier quotations. A full data update runs for each completed bid project. Most document structures include fixed-format response clauses, qualification verification fields, quotation details, and format check items. Most fields tie directly to bidding requirements, with no universal standard format. Single-document data volume shifts based on bidding project complexity.

## Database and Operations Constraints
The data characteristics of this category create multiple constraints for database and operations workflows. Data sources include public tender information and internal enterprise qualification databases. Cross-source data synchronization must maintain accuracy and real-time performance. Each project runs one data update per order. The workflow must support high-frequency, short-cycle data write and read operations. Document structures lack unified standard formats. Databases must support flexible field expansion and unstructured data storage to prevent field mismatches from bidding requirement changes. Bidding process errors directly result in bid invalidation. Database read/write operations must maintain stability and data consistency. Complete operation logs must be retained for problem tracing. This page is written based on FastGPT v4.17.0.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:password@db-host:27017/bid_db?authSource=admin` | Adapt to unstructured bid document and qualification certificate storage, support flexible field expansion |
| `PG_URL` | `postgresql://admin:password@db-host:5432/bid_struct?sslmode=disable` | Used to store structured bidding clauses and quotation detail data, ensure query efficiency |
| `DB_MAX_LINK` | `20–30 connections` | Match the high-frequency, short-cycle data read and write requirements of single projects, avoid connection exhaustion |
| `REDIS_URL` | `redis://default:password@redis-host:6379/0` | Cache frequently accessed tender announcements and qualification data, reduce database pressure |
| Concurrency setting | `First 5–10 documents` | Adapt to the scenario of parallel processing of multiple documents in a single project, avoid load overload |

## Common Configuration Errors
- Symptom: Unable to read tender data after configuring `PG_URL` or `MONGODB_URI`. Cause: The FastGPT deployment server’s IP address is not added to the database whitelist, or connection string username, password, or port settings are incorrect.
- Symptom: No results return when running SQL to extract qualification data. Cause: Database connection permissions are not granted to the target business account, or the SQL statement does not match the bid document’s actual field structure.
- Symptom: Timeout errors occur during concurrent bid document processing. Cause: The `DB_MAX_LINK` configuration value is too low, leading to database connection exhaustion and failure to respond to new read/write requests.

## Verifying Configuration Success
- Run a database connection test script to validate the connection status of `MONGODB_URI` and `PG_URL`, and confirm no authentication or address errors.
- Import a test bidding document dataset, perform data write and query operations, and confirm normal data storage and reading.
- Adjust the concurrency setting, launch a multi-document parallel processing task, and confirm database connection counts stay within the `DB_MAX_LINK` configured range.
- Check Redis cache logs to confirm frequent tender announcement data is cached and read normally.
