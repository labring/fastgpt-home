# Release Notes and Operation Report Summary for Data Cleaning and Quality Inspection: HTTP Interfaces and External Systems
## What data for this category includes
This category of data originates primarily from raw datasets, ETL logs, annotation platforms, and sampling results. Daily output documents include cleaning rules, quality inspection sampling tables, abnormal data lists, and delivery reports. Data updates run on a daily schedule or trigger per batch task. Core processing steps focus on duplicate data identification, outlier handling, and sampling quality inspection. Data fields cover raw data identifiers, cleaning rule versions, anomaly types, sampling pass rates, delivery status, and additional relevant metrics. Standard business identifiers and numeric formats are used, with no non-standard units included.

## Constraints imposed by these characteristics on HTTP interfaces and external systems
Data sources for this category are scattered, and update schedules are inconsistent. HTTP interfaces must support on-demand pulling of multi-source datasets, while adapting to batch pulling request formats. Daily output documents include structured rules and reports. Interfaces must support passing multiple parameter types. Core processing steps take extended time. Interfaces must set reasonable timeout thresholds to prevent mid-request interruptions. Delivery reports must be synchronized to external systems. Interfaces must support batch pushing of structured result data and status callbacks to ensure complete data synchronization.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer Token format, carry the API key assigned by the platform | Complies with general API authentication specifications for external systems, ensures secure interface calls |
| `variables` | Pass cleaning rule ID, sampling batch number, anomaly type filter conditions | Adapts to configuration for different batches of cleaning and quality inspection tasks, enables on-demand processing of specified data ranges |
| `responseData` | Return structured JSON containing abnormal data lists, sampling pass rates, and delivery report links | Allows external systems to directly parse and synchronize to internal document or report systems |
| Interface timeout duration | 600 seconds | Core processing steps include duplicate data identification and outlier handling, which take extended time. Prevents mid-request interruptions. This configuration applies to FastGPT v4.17.0 |
| Batch pull limit | Top 1000 entries | Balances interface load and data pulling efficiency, adapts to conventional requirements for single-batch data scale |

## Three common configuration errors
- Phenomenon: The interface returns authentication failure with status code 401. Cause: The `Authorization` parameter is not configured correctly, and valid platform authentication keys are not included.
- Phenomenon: The interface responds slowly, with single request duration exceeding expectations. Cause: A reasonable batch pull limit is not set, and the single pull data scale is too large, exceeding the interface's processing capacity.
- Phenomenon: Interface returned results contain redundant fields. Cause: Required business fields are not specified via the `responseData` parameter, and the interface returns all fields by default.

## How to verify correct configuration
- A test request is initiated. Check if the returned HTTP status code is 200, to confirm authentication configuration is effective.
- Fields returned by the interface are compared against preset business requirements, to confirm the `responseData` parameter configuration matches expectations.
- A single-batch task call is simulated. Check if response duration meets preset timeout threshold requirements.
- The data format received by the external system is reviewed, to confirm the configuration passed via the `variables` parameter takes effect correctly.

The values provided here are common starting points, and should be measured against the reader's own samples.
