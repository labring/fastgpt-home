# Release Notes and Operation Report Summary for Data Collection Task Design: Context and Token

## What this category of data looks like
Core data for this category is produced by data service project managers, collection teams, and customer algorithm teams. Daily documents fall into four categories: collection plans, sample specifications, authorization statements, and task schedules. Data sources include customer requirements, public data sources, collection tools, and sample libraries. Update frequency is per project or weekly. Each document includes clear fields such as sample scope, field specifications, and compliance notes. Content is dynamically adjusted based on project requirements, with no unified fixed unit.

## What constraints do these characteristics impose on context and token processing
Data sources for this category are diverse and formats are inconsistent. Context management must adapt to field differences across multiple sources to avoid unbalanced token allocation. Update frequency is per project or weekly, so context caching must match project cycles to prevent loading expired collection parameters. Daily documents include compliance content, so key documents such as authorization statements must be included in the context. Therefore, the `maxContext` and `quoteMaxToken` parameters must be used to adjust the total context token limit, covering the total length of all documents for a single project. The sample scope definition and field specification confirmation process takes a long time. Parameters from this process must be included in token statistics to prevent task errors caused by failure to load key configurations. The FastGPT v4.17.0 context management module must adapt to the dynamic data characteristics of this category to ensure token usage meets business requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 12000 token | Adapts to the total length of all documents for a single project collection task, complies with FastGPT v4.17.0 parameter specifications |
| `quoteMaxToken` | 1800 characters | Corresponds to the field specification content of a single collection sample, ensures single reference does not exceed token limits |
| Context refresh interval | Set according to project cycle | Matches the data update frequency of per project or weekly, ensures context always uses the latest task parameters |
| Token warning threshold | 90% of total context tokens | Reserves redundant space to handle temporarily added collection schedule documents |
| Number of context documents loaded per time | First 3 latest documents | Focuses on core collection documents for the current project, reduces invalid token consumption |

## Three common misconfigurations
- Phenomenon: Token consumption during collection task execution far exceeds the preset value, and a context overflow prompt pops up on the interface. Cause: Failed to adjust the `quoteMaxToken` value based on the field specifications of a single sample. The default setting is too large, causing redundant token consumption, which corresponds to the common problem of oversized Excel data blocks and insufficient granularity.
- Phenomenon: Retry limit exceeded prompt when calling the collection task interface. Cause: Failed to refresh the context cache according to the project cycle. Repeated requests using old collection parameters lead to exceeded interface call limits, consistent with the error logic of login retry restrictions.
- Phenomenon: Sample scope definition field is empty in the collection task, unable to generate a valid collection task. Cause: Failed to reserve sufficient context space to accommodate compliance documents such as authorization statements, leading to failure to load key configurations and triggering field missing errors.

## How to confirm configurations are correct
- View the collection task's context loading log, confirm that the loaded documents match the current project's collection plan, sample specifications, and authorization statements.
- Simulate submitting a sample data entry, check that the token consumption prompt is within the preset `maxContext` value, and adjust the threshold to match actual business needs.
- Verify the reference length of a single sample, confirm it does not exceed the preset `quoteMaxToken` value, avoiding single data overflow.
- Wait for one project cycle, check if the context automatically refreshes to the latest task schedule and collection parameters, ensuring cache updates match the set refresh interval.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
