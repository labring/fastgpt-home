# Release Notes and Operation Report Summary for Computer Room Inspection and Environmental Monitoring: Database and Operations

## What data for this category looks like
Data for this category comes primarily from environmental monitoring systems, access control systems, UPS monitoring tools, and video inspection equipment. Four standard document types are generated: inspection reports, temperature and humidity records, alarm records, and duty logs.

Data updates follow two cycles: real-time and daily. Real-time data includes device real-time temperature and humidity readings and alarm trigger statuses. Daily data aggregates that day’s inspection items and duty handover records.

Fields include device unique identifiers, monitoring values, alarm levels, timestamps, and physical device locations. Units include degrees Celsius, percentage values, timestamp formats, and others.

## What constraints these characteristics impose on database and operations workflows
High-frequency writes of multi-source real-time data require database connection pools to support high-concurrency scenarios, preventing connection exhaustion.
Batch daily summary data needs batch write interfaces to reduce per-interaction overhead.
High-frequency alarm record generation needs reasonable index configuration to balance query efficiency and write performance.
Data formats vary across different device sources, so unified field mapping rules are required to avoid field missing or type mismatch during storage.
Structured duty log storage needs full-text search support to enable quick location of historical records.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Full connection string containing authentication information and read-write separation node addresses | Adapts to mixed read-write requirements for multi-source inspection data, supports load balancing |
| `PG_URL` | Configured as the connection address of a dedicated read-only node, enable SSL encryption | Ensures security and stability for daily summary batch queries |
| `DB_MAX_LINK` | `20–30` | Matches peak concurrent write traffic for computer room inspection data, avoids connection pool exhaustion |
| `REDIS_URL` | Configured as a local cache node address, set key expiration time to `300 seconds` | Caches real-time temperature and humidity data for high-frequency queries, reduces database access pressure |
| Database connection timeout threshold | `10 seconds` | Adapts to real-time transmission delay of environmental monitoring data, avoids unnecessary waiting |

## Three common configuration mistakes
- Symptom: Database connection error with prompt `Access denied for user`, interface returns connection failed status. Cause: Authentication information in `MONGODB_URI` or `PG_URL` is not configured correctly, leading to permission verification failure.
- Symptom: Interface restricted error occurs during concurrent inspection data writes, returns status code 429. Cause: `DB_MAX_LINK` parameter is not set reasonably, connection pool size is insufficient to support peak concurrent writes.
- Symptom: Real-time temperature and humidity data query delay is too high, exceeding business tolerance limits. Cause: Cache node is not configured using `REDIS_URL`, high-frequency queries directly hit the primary database causing performance bottlenecks.

## How to confirm configuration is valid
- Execute database connection tests, verify returned results include valid data, with no permission or connection failure prompts.
- Simulate peak concurrent write scenarios, observe if database connection counts fluctuate within the configured `DB_MAX_LINK` range.
- Review cache hit rates for real-time monitoring data, confirm high-frequency query requests do not directly access the primary database.
- Export daily summary data, inspect field integrity and format consistency, confirm no missing or abnormal values.
