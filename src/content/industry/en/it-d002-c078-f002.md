# Release Notes and Operation Report Summary for Cabinet Rack Installation and Cabling: Context and Token

## What data for this category looks like
IDC operations engineers, network engineers, and equipment implementation specialists are the typical users of this scenario. Daily processed documents include rack installation applications, cabinet cabling diagrams, port label sheets, and construction records. Data sources cover DCIM systems, asset systems, network topology diagrams, and customer support tickets. Update frequency is once per ticket or once per day. Core work steps include slot planning, cable label verification, and rack installation acceptance. Errors can lead to incorrect port connections, impaired heat dissipation, or delayed customer service activation. The key difference between this scenario and the data center room inspection category is that this scenario focuses on the physical access process for new or modified equipment. This document is written based on the configuration logic of FastGPT v4.17.0.

## What constraints these characteristics impose on context and token workflows
Multi-source heterogeneous data sources create differences in field formats and units across documents. Context splicing requires unified formatting, otherwise additional token usage will occur. The number of documents associated with a single ticket and their content scale vary widely. The total token usage of the context must be flexibly controlled. Text density varies significantly across documents such as construction records and port label sheets. Chunk processing must match content characteristics to avoid unbalanced token allocation. At the same time, the scope of context recall must be strictly limited. Irrelevant cross-ticket data is prevented from occupying limited token resources and affecting the processing efficiency of core content.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | The total token count of documents associated with a single ticket for this category typically falls within this range, covering core content such as rack installation applications, cabling diagram descriptions, and port label sheets, while avoiding exceeding the model context limit |
| `quoteMaxToken` | 2000–3000 token | The core text token count of a single port label sheet or construction record typically falls within this range, preventing a single quote from occupying too much context space |
| Chunk Length | 1000–1500 characters | Matches the text annotation length of cabinet cabling diagrams and single-line field length of port label sheets, balancing token consumption and recall accuracy |
| Single Search Limit | Top 6 entries | The number of documents associated with a single ticket typically does not exceed 6, preventing irrelevant data from being recalled and occupying tokens |
| Re-ranking | Enabled | Documents in this category have strong relevance, and re-ranking improves token allocation efficiency for relevant content and optimizes context recall results |

## Three common misconfigurations
- An error indicating token limit exceeded is prompted when uploading some cabinet cabling diagrams, while some images can be uploaded normally. Cause: No reasonable token conversion rule is set for metadata associated with images, leading to unexpected token consumption from metadata of low-resolution images.
- An error indicating insufficient tokens is prompted when executing operation report summary, even if the model token limit has been set to a large value. Cause: `quoteMaxToken` is not configured, and the full text of a single port label sheet is recalled, occupying too much context token and causing the total to exceed the model limit.
- Context recall results include equipment installation documents from other tickets. Cause: The association scope of single searches is not limited, and historical data across tickets is recalled, leading to additional token usage by irrelevant content.

## How to confirm proper configuration
- Upload a single rack installation application form, check the context splicing log returned by the system, and verify that the number of recalled documents matches the single search limit setting.
- Submit a ticket containing multiple cabling diagrams, check the token consumption statistics generated by the system, and confirm that total consumption falls within the `maxContext` setting range.
- Trigger an operation report summary task for rack installation acceptance, check that returned results only include documents associated with the current ticket, with no cross-ticket data.
- Adjust the chunk length parameter, compare token consumption across different settings, and confirm that the value matches the text density characteristics of the target documents.
