# Release Notes and Operations Report Summary for Cabinet Rack Installation and Cabling: Database and Operations

## What data for this category looks like
Data for this category primarily comes from DCIM systems, asset management systems, network topology diagrams, and customer tickets. Daily produced documents include rack installation application forms, cabinet cabling diagrams, port label tables, and construction records.
Rack installation application forms contain fields such as rack position number, device model, and number of access ports.
Cabinet cabling diagrams mark cable IDs and port identifiers at both ends.
Port label tables record port numbers and corresponding device locations.
Construction records retain construction time and acceptance status.
Data updates occur once per order or daily, and are synced with construction process progress.

## What constraints these characteristics impose on the database and operations link
Multi-source data access typically requires database configurations that support connection adaptation for multiple data source types. This avoids synchronization failures caused by differences in data formats.
High-frequency update characteristics require reasonable database connection pool parameter settings. This prevents connection exhaustion from concurrent construction requests.
Diverse document field structures require database table structures that support flexible expansion. This adapts to field mapping for different documents such as installation applications, cabling diagrams, and label tables.
Exclusive physical access attributes require separate storage of dedicated records for cabinet rack installation and cabling in the database. This distinguishes the data from equipment room inspection data, and avoids deployment errors caused by data mixing.

## Three common mistakes
- Using environment variables to pass `MONGODB_URI` in database connection configurations triggers an "invalid connection string" error. Manual entry of SQL statements runs normally. The cause is that environment variables do not correctly escape passwords or host addresses containing special characters, leading to connection string parsing failure.
- A "connection refused" error occurs when calling database tools in a workflow. The cause is that the Docker-deployed FastGPT container does not have correct database port mappings configured, so it cannot access the backend database service.
- An "authentication failed" error occurs when using `MONGODB_URI` to connect. The cause is that the configured database user is not granted read and write permissions for the dedicated cabinet rack installation and cabling database, leading to verification failure.

## How to confirm configurations are correct
- Run a database connection test script to verify connectivity for `MONGODB_URI` and `PG_URL`, adjust connection parameters based on test results.
- Submit a simulated rack installation application data entry, check if it can be written to the database normally, verify field mapping correctness based on write results.
- View port label data cached in Redis, confirm that cache updates meet the real-time requirements of the construction process, adjust cache configurations based on business needs.
- Check the active connection count of the database connection pool, confirm that the current connection status meets business concurrency requirements, adjust parameters based on actual operating conditions.
