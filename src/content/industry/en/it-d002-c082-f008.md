# Release Notes and Operational Report Summary for Channel Attribution and Lead Distribution: Workflow Orchestration

## What Data for This Category Looks Like
Data for the channel attribution and lead distribution category primarily comes from advertising platforms, customer relationship management systems, front-end attribution SDKs, and landing page form systems. Data is updated in batches daily or weekly. Daily output documents include channel parameter rule sheets, lead distribution allocation forms, channel effect daily reports, and abnormal lead verification checklists. Data fields include channel unique identifier, lead generation time, conversion touchpoint, sales attribution ID, and conversion amount, with corresponding units of identification number, timestamp, touchpoint name, employee ID, and currency unit.

## What Constraints These Characteristics Impose on Workflow Orchestration
For multi-source data access, configure cross-source data mapping nodes in workflow orchestration to match channel codes from advertising platforms with channel attribution IDs in CRM systems. Align the workflow trigger period with the data sync cycle for daily or weekly updates to avoid duplicate processing or missed data. Embed standardized nodes for channel parameter format verification, duplicate lead deduplication, and sales attribution confirmation in the workflow to meet field verification requirements for daily documents, reducing manual verification time. Configure branch nodes to handle abnormal data with format errors or attribution conflicts to support abnormal lead verification needs.

## How to Set Configurations
These configurations apply to FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Cross-source mapping rules including channel identifiers, lead IDs, and sales attribution IDs | Match the field alignment requirements of multiple data sources |
| Trigger Cycle | Set to 2 AM daily or 1 AM every Monday according to the data sync cycle | Align with the daily/weekly data sync rhythm to avoid execution before data is ready |
| `nodeId` | Configure unique identifiers for the channel parameter verification, lead deduplication, and attribution confirmation nodes separately | Facilitate quick location of abnormally executed nodes in the workflow |
| Abnormal Branch Threshold | Trigger manual review when abnormal data accounts for more than 5% | Match the processing standards of the abnormal lead verification checklist |
| Single Node Timeout Setting | 600 seconds | Adapt to the average time required for pulling multi-source data |
| Variable Mapping Rule | Map advertising platform channel codes to CRM channel attribution IDs | Resolve the issue of inconsistent fields across systems |

## Three Common Misconfigurations
- Workflow execution becomes unresponsive after reaching a tool call node, with status showing timeout. The cause is that connection parameters for advertising platforms and CRM systems are not configured in `variables`, leading to failure to pull attribution data from the corresponding data sources.
- Channel testing succeeds but cosyvoice calls fail, with a permission error prompt returned on the interface. The cause is that the voice service key is not configured in `variables`, or the node corresponding to `nodeId` is not bound to the calling permission of the corresponding service.
- The file links generated by the workflow cannot open the original document preview, returning a 404 error. The cause is that the file path variable in `variables` is not bound to the original file storage field of the knowledge base slice, leading to incorrect link pointing.

## How to Confirm Proper Configuration
- Manually trigger the workflow, check the execution logs of each node, and confirm that all parameters in `variables` have been correctly loaded.
- Simulate a piece of abnormal lead data to verify whether the abnormal branch node triggers the manual review process.
- Compare the lead distribution table output by the workflow with the fields of the original data source to confirm that the mapping rules are effective.
- Check the execution status of the node corresponding to `nodeId` to confirm that there are no timeout or error records.
