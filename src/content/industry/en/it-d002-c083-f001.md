# Release Notes and Operation Report Summary for Game Content Compliance Self-Check: HTTP Interfaces and External Systems

## What data for this category looks like
The data for this category comes from text, art assets, plot scripts during game development, and publicly released compliance requirements from regulators. Daily produced documents include content self-checklists, sensitive content modification records, user agreements, and compliance review minutes. Data updates follow game version or event schedules, with no fixed cycle. Each individual document contains fields such as self-check items, modification traces, and review comments. There are no unified mandatory units. Only identifiers like content type, version number, and submission time are labeled according to business scenarios.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Updates to data for this category are triggered by game versions or events, with no fixed cycle. HTTP interfaces must support on-demand calls to align with the business’s version release rhythm. Data sources include multiple content types such as text, art assets, and plot scripts. Interfaces must support pulling and submitting content in different formats. There are no unified mandatory standards for document fields. Interfaces must support custom field mapping to adapt to the document structures of self-checklists, review minutes, and other materials for different business scenarios. Additionally, since errors directly affect launch progress, interfaces must have clear timeout and retry rules configured to ensure call stability. FastGPT v4.17.0 and later versions support flexible adjustment of the above configuration items.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {API key assigned by FastGPT platform}` | Complies with FastGPT API identity verification specifications to ensure the security of interface calls |
| `variables` | `{"version": "current game version number", "updateType": "version/event"}` | Adapts to the update rhythm triggered by business versions or events, and transmits core business identifiers |
| `responseData` | `{"status": "string", "auditResult": "object", "errorMsg": "string"}` | Matches the field structure of compliance self-check reports to facilitate subsequent processing of audit results and exception information |
| API call timeout period | `600 seconds` | Covers the full inspection time for text and art assets to avoid call interruptions due to timeout |
| Retry count | `2–3 times` | Addresses temporary network fluctuations to ensure call success rate and avoid repeated audits caused by repeated submissions |
| Callback address configuration | `Publicly accessible HTTPS address. Certificate verification can be disabled if no valid certificate is available` | Complies with the verification requirements of FastGPT callback interfaces to ensure that audit results can be normally pushed to the business system |

## Three common errors
- Symptom: Interface returns "Message receiving address verification failed". Cause: The deployed FastGPT service is not exposed to the public network, or a valid SSL certificate is not configured.
- Symptom: The `responseData` field returned by the interface lacks core audit results. Cause: The return data mapping rule is not correctly specified in the configuration, causing key information from compliance self-checks to not be extracted.
- Symptom: Interface call times out. Cause: The configured timeout period is shorter than the average processing duration of compliance self-checks, causing the call to be interrupted before the inspection is completed.

## How to confirm the configuration is correct
- Call the test interface, check whether the `Authorization` parameter is correctly carried in the request header, and confirm that identity verification is passed.
- Submit a test self-check document, check whether the `responseData` contains the preset audit result fields, and confirm that data mapping is correct.
- Simulate a temporary network fluctuation scenario, check whether the interface triggers retries according to the configuration, and confirm call stability in exception scenarios.
- Verify that the callback address can normally receive the returned audit results, and confirm that the business system can normally receive pushed data.
