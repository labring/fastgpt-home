# Release Notes and Operation Report Summary for Game Content Compliance Self-Check: Workflow Orchestration

## What the data for this category looks like
This category’s data primarily comes from text, art assets, plot scripts during game development, and publicly available regulatory compliance requirements. Daily associated documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Data updates occur per version or per event cycle. Data fields include content type, review status, modification traces, review opinion identification numbers, and more. Art asset data includes resource path and format information. Text data includes original content, modified content, and compliance check tags.

## What constraints these characteristics impose on the "workflow orchestration" link
The high-frequency update requirement per version or event means workflows must support periodic batch verification and summary processes. Differences across multiple data source types require workflows to adapt to input formats and verification logic for varied types, to prevent verification failures from format incompatibility. Field variations across document data require workflows to set unified parameter mapping rules, standardizing compliance fields from different documents into a consistent format. The time-consuming nature of the review link requires configuring state transitions and timeout reminders between workflow nodes, to keep the closed-loop review opinion process from stalling. Error consequences tie to launch risks, so workflows must include failure alerts and rollback mechanisms to block non-compliant content from entering the release stage.

## How to set configurations

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Configure version number and activity ID as global variables | Uniformly pass version-related verification and summary parameters, adapting to FastGPT v4.17.0 global variable configuration rules |
| Trigger Condition | Trigger on a scheduled basis per version/activity cycle, with a single verification limit of 1000 resources | Match the update rhythm of the category per version or activity, avoiding timeouts caused by excessive single-processing volume |
| `nodeId` | Bind unique identifiers for each review node | Ensure precise control of workflow node transitions, avoiding node confusion |
| Node Transition Rules | Branch jumps based on review status | Adapt to the closed-loop process of content self-check, modification, and review |
| Failure Alert Threshold | Trigger notifications after 2 consecutive verification failures | Avoid process interruption caused by single anomalies |
| Single Node Timeout | Set to 600 seconds | Adapt to the time characteristics of text and art checks |

## Three common mistakes
- Phenomenon: An external script call returns a parameter error, prompting a body field mismatch, when converting local desktop images to base64 encoding or processing compliance text. Cause: Parameters configured in `variables` are not aligned with the parameter names expected by the script, leading to parameter mapping failure.
- Phenomenon: The knowledge base search node does not filter compliance content by the specified version, resulting in recalled data ranges that do not meet current version requirements. Cause: The version number from the global variable is not passed to the filter parameters of the knowledge base search node, leading to recalled cross-version data.
- Phenomenon: The workflow stalls after reaching the review link with no subsequent transitions. Cause: Branch jump rules based on review status are not configured, so the corresponding subsequent nodes cannot be triggered based on the pass or reject status of review opinions.

## How to confirm proper configuration
- Trigger a test workflow, check whether the version number and activity ID configured in `variables` are correctly passed to the logs of each node.
- Call the external script node, pass test local images or compliance text, confirm that the returned base64 encoding or verification results match the expected format.
- Simulate inputs with different review statuses, verify whether the workflow jumps to the corresponding subsequent nodes according to the configured branch rules.
- Simulate a single node timeout scenario, confirm that the failure alert notification triggers normally.
