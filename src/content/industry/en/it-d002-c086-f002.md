# Publishing Instructions and Operation Report Summary for Game Edition License and Publication Declaration: Context and Token

## What Data for This Category Looks Like
This category of data is produced daily by entities engaged in game development and distribution. Core documents include declaration request files, game application forms, copyright certificates, review reports, and more. Data sources include the National Press and Publication Administration’s service platform, copyright registration systems, game packages, and operational institution materials. Updates proceed irregularly in line with the declaration process for individual games. Each document contains fields such as declaration number, copyright registration number, review revision opinions, and operational data summary. Some materials must be submitted with both scanned copies and structured information, with no unified fixed format.

## What Constraints These Characteristics Impose on the Context and Token Link
Documents in this category have inconsistent formats, including structured tables and scanned text. This requires context splicing to adapt to multiple content structures, limiting the value range of general parameters. Data updates irregularly alongside the declaration process for individual games. Latest materials must be dynamically loaded during sessions, which creates requirements for real-time context update mechanisms. Single declaration materials involve multiple types of approval fields. Cross-source verification increases context token usage. Total length must be strictly controlled to avoid overflow. Additionally, some materials contain sensitive approval information. Context calls must limit access scope to prevent token leakage risks.

## How to Set Configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total content length of individual game declaration materials, avoids context token overflow |
| `quoteMaxToken` | 1500–2000 token | Limits token usage of a single referenced document, ensures reasonable context when multiple materials are spliced |
| Context refresh trigger condition | Updated with declaration nodes | Matches the irregular update rhythm of data along individual game processes, ensures sessions use the latest materials |
| Sensitive information filtering | Enable permission binding | Limits access scope for context, adapts to the sensitive nature of approval materials |
| Single recall count | Top 3–5 entries | Controls total context token usage, prevents parameter limits from being exceeded due to excessive materials |

## Three Common Mistakes
- Issue: Call fails during local deployment, returns `401 Unauthorized` error, or the server fails to load the `AIPROXY_API_TOKEN` environment variable. Troubleshooting: The server environment variable `AIPROXY_API_TOKEN` is not configured (must be a non-empty administrator token matching the AI Proxy server configuration), or `AIPROXY_API_ENDPOINT` is not set to the root address of the AI Proxy service (for example, `http://aiproxy:3000`; do not append `/v1` or model service paths).
- Issue: Context splicing exceeds the `maxContext` limit, causing session interruption. Cause: The `maxContext` value is not adjusted based on the actual content of individual declaration materials, and the generic default value is used directly.
- Issue: Recalled materials do not match the current declaration task, and the result count is abnormal. Cause: The recall scope of the context is not limited, leading to loading irrelevant historical declaration materials and excessive token usage.

## How to Confirm Configurations Are Set Correctly
- Check the environment variable configuration deployed on the server. Confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (administrator token matching the AI Proxy server configuration) match the deployment environment.
- Upload a single typical declaration material. Test the total token count after context splicing, confirm it does not exceed the `maxContext` setting.
- Trigger a simulated call for a declaration process. Check if the returned results include the latest review report or application form content, confirm context refresh takes effect.
- Check the sensitive information filtering rules. Confirm core approval fields are included in the permission control scope to avoid leakage.

All recommended configuration values are common starting points. Adjust them based on your own specific samples and use cases.
