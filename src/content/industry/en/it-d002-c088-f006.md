# Release Notes and Operations Report Summary for Game Operation Activity Configuration: Scheduled Tasks and Automation

## Data Profile for This Category
Daily documents for this category include activity plans, reward configuration tables, launch checklists, and activity post-mortems. Fields cover activity time, reward ID, distribution quantity, trigger conditions, player segment tags, and similar items. Units include times, yuan, and users. Data sources are the operation backend, player segment system, paid data platform, and activity log system. Update frequency follows weekly or holiday-based cycles, with no fixed daily update rhythm.

## Constraints Imposed on Scheduled Tasks and Automation
Multiple heterogeneous data sources require scheduled tasks to support incremental pulls per module, avoiding resource overhead from full pulls. Non-fixed update rhythms require flexible trigger rule configuration, supporting triggers based on activity time nodes or holidays. Documents are closely linked to data fields, so field mapping rules must be configured to ensure accurate synchronization of key information such as reward configurations and activity times. Errors directly impact player experience and revenue, so pre-check links and failure retry mechanisms must be added to reduce the probability of abnormal execution.

## Configuration Settings
The following configurations are based on the scheduled task module of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Timing | 1 hour before activity launch, 3 days before holiday activities | Aligns with fixed launch times of activity plans and weekly/holiday update rhythms |
| Data Source Pull Scope | Recent 7 days of activity logs, currently active reward configuration tables | Covers latest activity execution data and configuration content, avoids redundant pulls |
| Abnormal Check Threshold | Reward distribution deviation ≥1%, empty activity time configuration | Intercepts abnormal configurations that may cause player complaints in advance |
| Failure Retry Count | 2 times | Prevents task failure from single network fluctuation, while controlling resource consumption |
| Task Timeout | 600 seconds | Adapts to the volume of documents and data processed in a single run, prevents long-term occupation of system resources |
| Result Merging Rule | Group summary reports by activity ID | Matches the grouping requirements of activity post-mortem documents, facilitates subsequent analysis |

## Common Misconfigurations
Three frequent misconfigurations are listed below:
- Symptom: Unconfigured scheduled tasks trigger on the hour, calling the GPT-4-turbo model. Cause: The global default scheduled trigger rule was not disabled, or the system scheduled task was incorrectly bound to the activity configuration workflow.
- Symptom: Numeric fields in activity reward configurations are empty, causing task execution failure. Cause: No data source pull check rules were configured, and invalid reward configuration table entries were not filtered.
- Symptom: Merge result order for multiple prompts targeting the same input is chaotic. Cause: No merging rules were specified, the default model return order was used for concatenation, and sorting by activity priority was not implemented.

## How to Verify Correct Configuration
- Manually trigger a test task, and verify that pulled data sources include the latest reward configuration tables and activity logs.
- Review task execution logs to confirm that the abnormal check link intercepted invalid configuration entries, with no unhandled exceptions present.
- Review scheduled task trigger logs to confirm triggers only occur before activity launch or at specified times, with no unexpected trigger behavior.
- Export the summarized operation report to confirm that results are grouped by activity ID, with fields matching the requirements of activity post-mortem documents.
