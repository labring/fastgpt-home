# Publishing Instructions and Operations Report Summary for Player Customer Service and Public Opinion Processing: Database and Operations

## What Data for This Category Looks Like
Data for this category originates primarily from game customer service systems, community forums, app store reviews, and game runtime logs. Processed daily documents include player tickets, compensation applications, public opinion daily reports, and standardized response scripts. Data is updated daily or synced in real time. Each data entry typically contains fields such as player account identifiers, feedback content, submission time, processing status, and associated ticket numbers. No mandatory additional statistical unit requirements apply.

## Constraints on Database and Operations Workflows
Real-time or high-frequency update data sources require database connections to support low latency and high concurrent loads, preventing timeouts during ticket submission and public opinion crawling. Validate heterogeneous data from multiple sources in advance to stop dirty data from entering the storage layer. Create indexes for player account association fields to speed up verification queries; without these indexes, the account verification process will experience excessive delays. Data volume fluctuates with game promotional events, so reserve sufficient connection pool headroom to avoid connection exhaustion during peak periods. Configure monitoring alerts for core storage nodes to prevent processing workflow interruptions caused by storage failures.

The following configurations apply to FastGPT v4.17.0 and later versions.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Database Connection URI | `mongodb://user:pass@host:port/dbname?authSource=admin` | Stores unstructured data such as player tickets and public opinion logs; requires specifying the authentication source and target database |
| Maximum Database Connection Pool Size | 200–300 | Adapts to high-frequency real-time ticket submission and query requests, avoiding connection pool exhaustion |
| Redis Connection Address | `redis://:password@host:6379/0` | Caches frequently queried player account verification results and temporary response scripts to reduce database load |
| PG Database Connection Address | `postgresql://user:pass@host:5432/dbname?sslmode=require` | Stores structured operational report data and compensation application approval records; requires SSL to enable secure transmission |
| Database Connection Timeout | 600 seconds | Adapts to cross-data-center database access scenarios, preventing normal requests from being blocked by short timeouts |
| Storage Path Configuration | Set based on local disk free space | Stores temporarily generated public opinion analysis files, avoiding workflow interruptions caused by insufficient disk space |

## Three Common Configuration Mistakes
- A service startup error indicates a database connection failure, but mongosh can connect normally. This occurs because database connection parameters are not correctly configured in the FastGPT server environment variables, or the server network policy restricts access to the database port.
- Attempting to use a custom vector database as knowledge base storage. This occurs because the distinction between FastGPT's vector retrieval configuration and underlying data storage responsibilities is blurred. The platform's knowledge base storage relies on specified database components, and external custom vector databases are not supported.
- Workflow canvas drag-and-drop lag, with the service version being 4.6.5. This occurs because database connection pool parameters are not adjusted based on the number of business nodes. Excessive concurrent connections consume server resources, leading to interface response delays.

## How to Verify Successful Configuration
- Start the FastGPT service and check that there are no database connection-related error messages in the startup logs.
- Submit a test player ticket and verify that data is correctly written to the specified database collection or table.
- Execute high-frequency player account verification queries and confirm that response delays meet business expectations.
- Check the service monitoring panel to confirm that database connection counts do not exceed the configured maximum connection threshold.
