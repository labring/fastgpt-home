# Release Notes and Operation Report Summary for On-Site Deployment Implementation: Context and Token

## What the data for this category looks like
The data for this category primarily comes from on-site first-hand resources including customer computer room environments, equipment inventories, software packages, and network topologies. Four types of documents are regularly generated: deployment manuals, installation records, configuration lists, and on-site check-in sheets. On-site implementation engineers, system engineers, and customer IT staff jointly maintain the data, with updates occurring per order or per phase. Fields include equipment model, software version, configuration parameters, check-in time, and more. No unified fixed units exist, and values are adjusted based on the actual on-site environment.

## What constraints these characteristics impose on the context and token workflow
The data sources for on-site deployment implementation are scattered and vary per order. This requires context to dynamically adapt to the differentiated document structures of deployment manuals, installation records, and similar materials, making fixed template loading unfeasible. Data updates occur per order or per phase, so the context cache duration must match this update rhythm to avoid loading expired configuration or check-in data. Document fields are diverse, and token usage varies significantly across different documents. Token quotas must be allocated appropriately to cover all on-site document types, while also preventing system unavailability caused by token overflow. Additionally, the accuracy of on-site data directly affects deployment outcomes. The context filtering logic must strictly match field rules to avoid invalid information occupying token resources and ensure the correctness of deployment configurations.

## How to configure these settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Matches the total token usage range of on-site deployment-related documents, with reasonable redundancy reserved to avoid context overflow |
| `quoteMaxToken` | 1500–2000 token | Adapts to the typical length of single-segment content such as deployment manuals and installation records, preventing single-segment citations from occupying excessive context quota |
| Context refresh timing | Triggered upon completion of a deployment phase | Matches the rhythm of phase-based data updates for this category, ensuring the latest versions of configuration and check-in records are loaded |
| Context content filtering threshold | Calibrated via actual testing | Filters meaningless on-site environment notes to reduce invalid token usage |

## Three common configuration mistakes
- Symptom: An LLM returns a "context token overflow" error after deployment, or output content is truncated. Cause: The `maxContext` parameter was not adjusted based on the actual total length of on-site deployment documents, and the default parameter fails to cover the token usage of a single deployment manual.
- Symptom: Returned citation content is empty or incomplete during invocation. Cause: No reasonable `quoteMaxToken` parameter was set, and the single-segment citation length exceeds the limit, causing content truncation.
- Symptom: The latest configuration from on-site deployment is not loaded into the context. Cause: The context refresh timing was set incorrectly, failing to match the rhythm of phase-based data updates, and old configuration records are still used.

## How to verify proper configuration
- Review the configured value of the `maxContext` parameter, confirm it matches the total token usage range of the current deployment documents.
- Test loading a single segment of installation record, check if the `quoteMaxToken` parameter allows full loading of the segment.
- Simulate a deployment phase update, confirm that the context automatically refreshes to the latest configuration list content.
- Trigger an LLM invocation, check that the cited on-site document content in the returned results is complete and not truncated.

The values provided are common starting points and should be measured against the reader's own samples.
