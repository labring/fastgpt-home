# Summary of On-Site Deployment Release Notes and Operational Reports: Workflow Orchestration

## What Data for This Category Looks Like
Data sources for this category include customer on-site computer room environments, equipment lists, software packages, and network topologies. Update frequency follows per order or per phase. Daily produced documents include deployment manuals, installation records, configuration lists, and on-site check-in sheets. Core fields include deployment node IP addresses, software version numbers, configuration parameters, check-in times, and troubleshooting records. Units include units, pieces, days, bytes, and others. All data is generated and updated incrementally throughout the on-site deployment workflow.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Data sources are scattered and updated dynamically alongside on-site processes. Workflows must support real-time pulling and correlation of multi-source data.
Update frequency follows per order or per phase. Workflows must allow phase-triggered summary logic.
On-site environments vary significantly. Workflows must include built-in branch judgment nodes to adapt to different computer room configurations.
Documents and data are tightly bound. Workflow nodes must be associated with corresponding deployment documents. This ensures release notes and operational reports accurately match actual on-site conditions.

## How to Configure Settings
| Configuration Item | Recommended Setup | Rationale |
| --- | --- | --- |
| Global variable configuration | Configure `variables` with deployment environment identifier, software version number, file root path | Matches fields from on-site deployment equipment lists and configuration lists, adapts to FastGPT v4.17.0 variable binding rules |
| Node ID binding | Bind `nodeId` to environment check nodes, document parsing nodes, troubleshooting nodes | Corresponds to core on-site deployment process steps, enabling easy tracking of execution status for each step |
| Trigger timing setup | Trigger 120 seconds after deployment phase nodes complete | Matches update frequency per order or phase, ensuring operational reports are automatically summarized by phase |
| Result output rules | Only output summarized release notes and reports, hide raw tool call content | Avoids redundant information interfering with on-site deployment personnel, complies with release document specification requirements |
| Knowledge base matching rules | Match the top 3 relevant deployment documents by deployment environment type | Adapts to differences in customer computer room environments, enabling quick access to corresponding deployment guidance content |
| File path verification | Configure for local file paths under 500 MB | Limits parsed file size to prevent server resource overload |

## Three Common Configuration Mistakes
- No result output after tool calls: Workflows only bind tool call end nodes, and do not configure result summary nodes. Raw tool call content is not included in the release or report process.
- 404 error during server-side document parsing: No local-to-server file path mapping is configured via `variables`. The parsing node cannot read uploaded files stored on the server.
- Global variable assignment fails to take effect: No trigger timing for variable assignment is bound to the workflow start node, or no `nodeId` is specified to associate with the assignment node. Global variables do not update as expected.

## How to Confirm Configuration Is Correct
- View the `variables` configuration of the workflow. Confirm that required fields such as deployment environment identifier and software version number are included.
- Trigger a test deployment node. Check that corresponding release note drafts are generated by phase, with no redundant raw tool call content.
- Upload a test file to the server deployment directory. Confirm that the document parsing node can correctly read the file content, with no 404 errors.
- Trigger a global variable assignment operation. Confirm that the `nodeId` binding for the corresponding node is correct, and variable values function normally in subsequent workflow nodes.
