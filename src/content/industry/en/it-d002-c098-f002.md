# Release Notes and Operations Report Summary for Community Contributor Governance: Context and Token

## What this category of data includes
Data sources for this category include code repository commit records, community forum interaction data, contribution statistics reports, and governance meeting minutes. Update frequency is monthly or quarterly. Daily documents include contribution guidelines, code of conduct, maintainer lists, and governance meeting minutes. Data fields cover contributor identifiers, contribution types, permission levels, resolution items, and execution nodes. There are no unified fixed numerical statistical units. Data is stored only in the natural format of documents and records.

## What constraints do these characteristics impose on context and token handling
Documents and data for this category are scattered across multiple platforms such as code repositories and community forums. A single context integration must cover multiple pieces of content including contribution guidelines, maintainer lists, and governance resolutions. Therefore, sufficient token space must be reserved to carry complete associated information. The monthly or quarterly update rhythm reduces the need for frequent refreshes. The latest permission rules and contributor status must be verified before each call to avoid loading expired data. Most contributor-related fields are text identifiers. Token consumption is directly related to the length of loaded documents. The number of historical records recalled in a single call must be limited to prevent exceeding the model's context upper limit.

## Configuration settings
The following configurations are based on the context and token management logic of FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Aligns with the integration needs of community governance-related documents, historical resolutions, and maintainer lists, avoiding truncation of critical rule information |
| `quoteMaxToken` | 2000–3000 token | Limits token consumption for single-reference community documents, preventing individual content from occupying too much context space |
| Maximum number of context recall entries | Top 3–5 entries | Matches the monthly or quarterly update rhythm of the category, only recalling the latest governance content and permission information |
| Context refresh interval | 720 hours (30 days) | Aligns with the category's update frequency, reducing unnecessary context refresh operations |
| Contribution record recall limit | Top 10–15 entries | Covers core data of monthly contribution statistics, avoiding loading excessive unnecessary historical commit records |

## Three common misconfigurations
- When `maxContext` is set to 3000 token, generated governance reports experience content truncation, and cannot fully display maintainer lists and latest resolutions. Troubleshooting steps: Check whether the `maxContext` configuration adapts to the actual length of community documents, and whether critical information is truncated by the model.
- In some scenarios, the response length automatically changes to 200 tokens, and complete contributor promotion assessment content cannot be output. Troubleshooting steps: Check whether the `maxContext` configuration adapts to the long-content generation requirements of governance tasks.
- A context token limit exceeded prompt appears during calls, and complete governance meeting minutes cannot be loaded. Troubleshooting steps: Check whether the number of context recall entries in a single call exceeds the limit, and whether token consumption falls within the ranges configured for `maxContext` and `quoteMaxToken`.

## How to verify correct configuration
- Verify the environment variable configurations in the App/Admin server. Confirm that `AIPROXY_API_ENDPOINT` (the root address of the AI Proxy service, for example http://aiproxy:3000; do not append paths such as /v1 or /chat/completions, and it is not a single-model address) and `AIPROXY_API_TOKEN` (the AI Proxy administrator token, consistent with the AI Proxy server configuration and cannot be empty; it is not an application API Key or model vendor key) are correctly configured. Do not set these variables in workflow global variables, application API request headers, or ordinary model management pages.
- Initiate a community governance report generation request, and check whether the returned content covers contribution guidelines, maintainer lists, and the latest governance resolutions, with no critical information truncated.
- View model call logs to confirm that context token consumption falls within the limits configured for `maxContext` and `quoteMaxToken`.
- Wait 30 days, and verify that the context loads the latest governance meeting minutes and contribution statistics data.

Note: All configuration values listed are common starting points. Adjust them based on your own specific samples and use cases.
