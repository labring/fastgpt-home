# Release Notes and Operations Report Summary for Mobile Development: Context and Token

## What data for this category looks like
Data for mobile development release notes and operations report summaries comes from code repositories, app store backends, crash monitoring platforms, and device coverage datasets.
Daily documents include version release checklists, device adaptation lists, crash analysis reports, and app store submission materials.
Data updates follow a daily or per-version release cycle.
Document structures use version numbers as the core identifier. They include fields such as device adaptation scope, crash rate, token consumption statistics, and app store review status.
Field types include strings, integers, and status identifiers. No unified fixed statistical format is used.

## Constraints imposed on context and token processing
Multi-source, non-uniform format data for mobile development requires context integration to support different document structures, and avoid invalid content consuming token.
Data update rhythms vary. Context refresh timing must be adjusted to match version release cycles, to ensure latest adaptation information and review materials are included.
Content such as device adaptation scope and app store submission materials has strict format requirements. Context truncation rules must retain key fields, to prevent damage to submission content integrity.
A requirement to count token consumption per application means context data must be split by application, to avoid cross-application token statistics confusion.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Max context length | 8000–12000 token | Adapts to the total length after integrating multiple documents, and avoids exceeding model call limits |
| Max reference token | 2000–3000 token | Matches the typical content length of a single crash analysis report or app store submission material |
| Context refresh interval | 1–7 days, calibrated via actual testing | Matches the daily or per-version data update rhythm, and ensures context timeliness |
| Context filtering rules | Only retain version number, device scope, and token consumption fields | Reduces token consumption by invalid content, and improves context accuracy |
| Content truncation rules | Retain key fields at the start and end of documents | Adapts to the format requirements of app store submission materials, and prevents required fields from being lost |

## Three common configuration errors
- Phenomenon: System reports `AIPROXY_API_TOKEN is not set` error. Cause: Server environment variable `AIPROXY_API_TOKEN` (AI Proxy admin token, must match AI Proxy server configuration and cannot be empty) is not configured, leading to AI Proxy call failure or startup verification failure.
- Phenomenon: Unable to count model token consumption per application. Cause: Context filtering rules are not configured, and non-application-related log data is included in token statistics, leading to distorted statistical results.
- Phenomenon: App store submission materials are rejected. Cause: Context truncation rules do not retain required fields for app store materials, leading to submission content that does not meet review requirements.

## How to verify successful configuration
- View the system's token consumption statistics dashboard, and verify whether per-application consumption data matches the preset statistical dimensions.
- Trigger a context call related to version releases, and check whether the returned content includes the latest version information and adaptation lists.
- Simulate the app store submission material submission process, and verify whether context content retains required fields without truncation.
- Check environment variable configurations on the App/Admin server, and confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000; do not append paths such as /v1) and a non-empty `AIPROXY_API_TOKEN` (AI Proxy admin token, must match AI Proxy server configuration) are correctly set.

The values given are common starting points and should be measured against the reader's own samples.
