# Release Notes and Operation Report Summary for Warranty Period Defect Response: Database and Operations

## What Data for This Category Looks Like
This category’s data comes primarily from customer-submitted warranty work orders, system operation logs, project contract warranty clauses, and software version records.
Daily output documents include warranty work orders, defect confirmation sheets, repair records, and customer confirmation sheets.
Most data updates are triggered by individual work orders. Some summary data is updated daily.
Individual data entries contain fields such as work order unique identifier, specific defect description, responsible party determination, repair version, repair duration, and customer confirmation status. There are no standard fixed units. Values adjust based on specific business items.

## Constraints Imposed on Database and Operations Workflows
Data for this category originates from scattered sources, including customer work orders, operation logs, contract clauses, and version records. Update frequencies vary.
Some data is written in real time when individual work orders are submitted. Other summary data is updated daily.
Daily document types are diverse. Storage must support form data with varying structures.
Data must be linked to project contracts and version records. This requires the database to support accurate cross-table association queries.
Individual data entries include sensitive fields such as responsible boundary determinations. An independent permission control mechanism must be configured.
The lack of fixed update cycles requires steps to avoid database connection exhaustion or write blocking disrupting business processes. Low latency for data writes and queries is needed to support real-time after-sales response.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:securepass@db-host:27017/qc_defect?authSource=admin` | Stores semi-structured data such as warranty work orders and defect confirmation sheets |
| `PG_URL` | `postgresql://qc_user:pass@pg-host:5432/qc_contract` | Stores associated structured data such as contract warranty clauses and customer confirmation sheets |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent connection requirements for individual work order real-time writes and daily batch summary tasks |
| `REDIS_URL` | `redis://:redis-pass@cache-host:6379/1` | Caches temporary work order status and permission verification information to reduce pressure from high-frequency database queries |

## Three Common Configuration Mistakes
- Symptom: A `connection refused` error appears after startup. Logs indicate database connection failure. Cause: Connection parameters for `MONGODB_URI` or `PG_URL` are misconfigured. This includes incorrect host addresses or authentication details.
- Symptom: Batch summary tasks time out and return empty results. Cause: Connection count is not limited by `DB_MAX_LINK`. Exhausted concurrent connections cause write blocking, preventing daily summary tasks from completing.
- Symptom: After directly operating the vector database via a third-party tool, the system cannot retrieve the latest defect repair records. Cause: Vector database operations were performed outside the FastGPT built-in interface. Direct data modification creates a mismatch between metadata and actual stored data.

## How to Verify Proper Configuration
- Call the individual warranty work order creation interface. Check if a corresponding record is generated in the database. Verify field completeness.
- Trigger the daily summary task. Confirm that contract clauses and version records are correctly associated with work order data.
- Review database connection count monitoring. Confirm that current connection counts do not exceed the `DB_MAX_LINK` configuration value.
- Test access to the vector database using the FastGPT built-in tool. Confirm that defect repair-related document content can be retrieved normally.
