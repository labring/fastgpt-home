# Release Notes and Operations Report Summary for Identity Account and Permission Management: Context and Token

## What the data for this category looks like
Core data for this category comes from IAM systems, HR systems, business system logs, and approval systems. Update frequency is daily or triggered by personnel changes. Documents maintained on a daily basis include account application forms, permission matrices, offboarding recovery forms, and audit reports. Account application forms include fields such as applicant ID, job position, applied permission scope, and more. Permission matrices include fields such as account ID, associated system, permission level, effective time, and more. Offboarding recovery forms include fields such as departing employee ID, recovered permission list, operator, and more. Audit reports include content such as permission change records, abnormal account entries, and more.

## What constraints do these characteristics impose on the context and token workflow
Integrating multi-source data increases token usage per single context entry. Limit the number of data sources loaded per time to avoid exceeding the model context upper limit. The data update frequency is daily or triggered by personnel changes, so the validity period of the context cache must match the update rhythm to prevent expired data. The field lengths of different documents vary widely. A single entry in a permission matrix may be lengthy, so configure differentiated token upper limits for different types of context. Audit documents include sensitive permission details, so control the total token amount per single context to ensure compliance.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | The single-entry length of core documents for this category, such as permission matrices and audit reports, falls within this range, and it adapts to the model context upper limit of FastGPT v4.17.0 |
| `quoteMaxToken` | `1500–2000 token` | The content length of a single account application form or offboarding recovery form typically falls within this range, ensuring referenced content is complete without occupying excessive total context |
| Context cache validity period | Refresh every 12 hours | The data update frequency for this category is daily or triggered by personnel changes. Refreshing every 12 hours balances data timeliness and token consumption |
| Data source filtering rules | Only load permission change logs from the past 7 days | Abnormal permission issues in IAM-class data mostly occur within the past 7 days. Filtering old data reduces token usage |
| Context splitting rules | Split by document type | The fields of different documents in this category vary widely. Splitting allows precise configuration of token upper limits for each type |

## Three common configuration mistakes
- Phenomenon: An E11000 duplicate key database error occurs. Troubleshooting: Check whether multiple deployments configure parameters with environment isolation to avoid sharing the same database collection. This error is unrelated to the `AIPROXY_API_ENDPOINT` (AI Proxy service root address, format example: http://aiproxy:3000, do not append path suffixes) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with server-side configuration) environment variables.
- Phenomenon: When loading Excel permission matrix data with 10000+ rows, token usage exceeds the upper limit, resulting in truncated results. Troubleshooting: Check whether the context token quota configuration adapts to large-volume source data for this category, and confirm whether default parameters are being used.
- Phenomenon: No matching permission verification records appear when adding a new employee account. Troubleshooting: Check the data source association rule configuration, and confirm whether personnel change data from the HR system is loaded as context.

## How to confirm the configuration is complete
- View App/Admin server runtime logs to confirm that the `AIPROXY_API_ENDPOINT` (AI Proxy service root address, format example: http://aiproxy:3000, do not append path suffixes) and non-empty `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with server-side configuration) environment variables load normally, with no connection timeout errors.
- Import 1000 rows of permission matrix Excel test data, and verify that the returned context token usage falls within the configured `maxContext` range.
- Simulate an offboarding employee account recovery operation, and confirm that the system can load the context of the corresponding offboarding recovery form and complete permission verification.
- Generate a permission audit report, and verify that the token consumption of context calls conforms to the preset `quoteMaxToken` and `maxContext` quotas.
