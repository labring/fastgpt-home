# Release Notes and Operations Report Summary for On-site Outsourced Operations Services: Context and Token

## What this category of data looks like
Data for release notes and operations report summaries for on-site outsourced operations services is sourced from customer ITSM systems, on-site monitoring platforms, asset inventories, and on-duty records.
Data update cycles are split into daily and monthly.
Daily data corresponds to on-site daily reports and service desk tickets.
Monthly data corresponds to inspection reports and SLA monthly reports.
Document structures include fields such as on-site staff information, ticket numbers, inspection item completion status, and service delivery duration.
No unified fixed format exists. Multi-source data must be integrated based on business scenarios.
This content follows the technical specifications of FastGPT v4.17.0.

## What constraints these characteristics impose on context and token processing
Multiple scattered data sources require context integration to cover documents from systems including ITSM and monitoring. This increases uncertainty in token consumption.
Daily and monthly update cycles cause token consumption to fluctuate with task cycles. Total token counts for monthly summaries may far exceed those of daily tasks.
Documents lack unified formats and have diverse fields. Precise screening of content relevant to summary tasks is required to avoid irrelevant data occupying context space.
Summary results for on-site services directly link to customer service evaluations. Accurate token counting and context recall without omissions or redundancy are required to ensure summary content meets business delivery requirements.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | The cumulative valid token count of daily summary documents for on-site outsourced operations services typically falls within this range. This avoids content truncation caused by exceeding model context limits |
| `quoteMaxToken` | `2000–3000 token` | The core token count of a single on-site daily report or service desk ticket usually does not exceed this range. This ensures complete single-reference information |
| Context matching threshold | Calibrated via actual testing | Must match the field characteristics of on-site service documents, such as ticket numbers and inspection items. This ensures recalled context is strongly relevant to summary tasks |
| Single recall upper limit | Top 10 entries | Operations report summaries for outsourced operations typically only require core documents from the past 7 days or past 1 month. Limiting recall entries avoids excessive token consumption |
| Context update frequency | Matched to task cycle | Daily summaries use same-day context. Monthly summaries use full-cycle context. This aligns with business data update rhythms |

## Three common configuration errors
- Starting the FastGPT service returns the error `AIPROXY_API_ENDPOINT or AIPROXY_API_TOKEN is not set`. The cause is failure to configure the corresponding environment variables on the App/Admin server. Variables are mistakenly filled into workflow global variables, application API request headers, or the standard model management page.
- The summary result contains a large number of document fragments unrelated to on-site outsourced operations services. The cause is failure to set a reasonable context matching threshold. Non-business-related system logs or service data from other categories is recalled.
- Workflow nodes fail to isolate context. Processing results of different on-site tickets interfere with each other. The cause is failure to limit the context scope of workflow nodes to documents associated with the current task.

## How to verify correct configuration
- Check the environment variable configuration on the App/Admin server. Confirm `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly filled and not empty.
- Trigger an on-site daily report summary task. Check the token consumption statistics of the returned results. Confirm the value matches the configured context upper limit.
- Test the context isolation function of workflow nodes. Ensure processing results of different tickets do not reference unrelated documents.
- Check model call logs. Confirm all recalled context documents are business data for on-site outsourced operations services, with no unrelated content.
