# Release Notes and Operational Report Summary for Incident Management and Root Cause Analysis: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category primarily comes from incident timelines, system operation logs, monitoring metrics, and code commit records. Daily produced documents include RCA reports, incident tickets, review minutes, and rectification tracking sheets. Data update frequency is either after each major incident or once per month. Document structures include fields such as incident ID, root cause analysis conclusion, associated evidence snippets, and rectification tracking nodes. There are no unified fixed units; fields are adjusted based on specific incident scenarios, and document fields vary across different incidents.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data sources for this category are scattered and update rhythms are inconsistent. They include both real-time logs and monitoring data generated after an unexpected incident, as well as monthly aggregated review documents. Therefore, HTTP interfaces must support two invocation modes: on-demand triggering and scheduled pulling. At the same time, document structures have no fixed unified fields, so interfaces must support dynamic adaptation of returned fields to avoid hard-coded mapping logic. Additionally, data contains operation and maintenance sensitive information, so interfaces must be configured with reliable authentication parameters to ensure the security of external system calls. Since data is associated with the full incident chain, interfaces must also support carrying incident IDs for precise data pulling to improve data matching efficiency.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${bound FastGPT API key}` | Complies with HTTP interface authentication specifications to ensure the security of external system calls |
| `variables` | `{"faultId": "unique incident identifier", "timeRange": "start time~end time"}` | Used to pass precise query conditions to match associated data for RCA reports and incident tickets |
| `responseData` | `Return only incident ID, root cause description, and rectification measure fields` | Filters redundant data, reduces interface transmission bandwidth usage, and improves aggregation efficiency |
| Maximum number of data entries per request | `50–200 entries` | Adapts to incident data pulling requirements of different scales, avoiding overload from single requests |
| Request timeout threshold | `300–600 seconds` | Covers the pulling time of multi-source logs and monitoring data, preventing request interruption mid-process |

## Three common misconfigurations
- Uploading HTML interface documents generated by javadoc to the knowledge base results in no parsed content. The reason is that FastGPT HTTP interface document upload only supports structured API definition formats, and javadoc documents in HTML format are not recognized as parsable metadata.
- Receiving a 401 Unauthorized error when calling an external system interface. The reason is that the `Authorization` parameter is not configured correctly, or the permission scope of the bound API key is insufficient to access target RCA-related data.
- Receiving a timeout error when pulling RCA data in batches. The reason is that the number of data entries in a single request exceeds the configured limit, or the request timeout threshold is set too low to cover the pulling time of multi-source logs and monitoring data.

## How to confirm configuration is complete
- Call the configured HTTP interface and check if the returned `responseData` includes expected fields such as incident ID, root cause description, and rectification measures.
- Pass test `variables` parameters to verify if the interface can accurately pull associated data for the corresponding time range and incident ID.
- Send 10 consecutive requests and check that all interface return status codes are 200, with no timeout or authentication failure errors.
- View external system call logs in FastGPT v4.17.0 to confirm that request authentication parameters, query conditions, and configuration items fully match.

The values given are common starting points and should be measured against the reader's own samples.
