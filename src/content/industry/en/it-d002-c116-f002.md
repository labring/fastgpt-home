# Release Notes and Operations Report Summary for Project Document Handover Archiving: Context and Token

## What This Category’s Data Looks Like
Data for this category primarily comes from project document libraries, configuration lists, meeting minutes, and test reports. Daily produced documents include completion documents, configuration manuals, training records, and acceptance certificates. Data is updated synchronously after each project phase delivery or when a single project concludes. Documents typically include fields such as project number, version identifier, document type, signature status, and handover target. There is no unified fixed format, so customization per project is required.

## Constraints on Context and Token Workflows
Document update frequency for this category is uneven. A large volume of historical documents may be imported at once during a single project handover. Strictly control context capacity to avoid exceeding token limits. Document fields vary significantly across different projects. Context recall must accurately match project-related content to prevent unrelated documents from being included. Core handover materials such as completion documents and acceptance certificates have a high token proportion. Prioritize token quotas for these materials, and prevent non-core documents from occupying context space. Many fragmented documents exist, such as meeting minutes. Set the number of context recall entries reasonably to avoid redundant content interfering with core information extraction.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum context entries | Top 20 entries | Matches the phase-based update rhythm of project documents, avoids polluting the context with excessive historical documents |
| `maxContext` | 15–25 entries | Adapts to the volume of documents for a single project handover, balances recall accuracy and token usage, aligns with FastGPT v4.17.0 parameter logic |
| Single-batch recall token limit | 8000 token | Prevents single-batch recalled content from exceeding the context limit of general large models |
| `quoteMaxToken` | 6000–10000 token | Matches the average token length of core materials such as completion documents and acceptance certificates, ensures complete core information |
| Context recall similarity threshold | 0.75–0.85 | Distinguishes project-specific documents from general templates, reduces inclusion of unrelated content |
| Single-batch recalled document count | Top 8 entries | Adapts to fragmented document types such as meeting minutes and training records, controls overall token consumption |

## Three Common Configuration Mistakes
- Setting `maxContext` to 30 entries but only 2 entries appear in conversation details: This occurs because the value of `quoteMaxToken` was not configured synchronously. After exceeding the token limit, the system automatically truncates early context content.
- Large model prompts that context token count is exceeded: This occurs because `quoteMaxToken` was not adjusted for long documents such as completion documents and acceptance certificates, causing core handover materials to occupy excessive token space.
- Unexpected JSON format content appears in responses: This occurs because recalled configuration manuals and test reports contain structured code blocks, and context filtering rules were not used to exclude non-business-related format content.

## How to Verify Correct Configuration
- Import a typical document set for a single project, view the context recall list, and confirm that only core materials such as completion documents and acceptance certificates for that project are included.
- Simulate multi-round business conversations, check whether large model responses can associate content from meeting minutes and training records of the corresponding phase, with no document information from unrelated projects.
- View system operation logs, confirm that no token limit error messages appear, and that the number of context entries matches the configured `maxContext` value.
- Test long document import scenarios, confirm that `quoteMaxToken` takes effect, and that no excessive truncation of core content occurs.

The values provided are common starting points and should be measured against the reader's own samples.
