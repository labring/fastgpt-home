# Security and Compliance Material Review for CDN and Edge Acceleration Configuration: Document Parsing and Chunking

## What the data for this category looks like
Daily documents for this category typically fall into four types: domain access forms, cache rules, refresh and preheating records, and fault analysis reports. Data sources generally include CDN consoles, DNS resolution records, public network access logs, and node monitoring alert information. Data update frequency is daily aggregation or real-time updates when configurations change. Document structures include both structured forms with fixed fields, and unstructured log snippets and fault descriptions. Common fields include domain name, cache policy type, refresh time, node IP, alert level, and so on. There is no unified long-text format.

## What constraints these characteristics impose on the document parsing and chunking link
Since documents include structured forms and unstructured logs, parsing and chunking must balance field integrity and semantic coherence, to avoid breaking configuration associations during splitting. Data updates occur frequently, so batch parsing tasks must limit single-task duration to prevent disruption to business processes. Log snippets from document sources have varying formats, so chunking rules must adapt to different types of CDN business documents. Parsing results must retain key identifiers tied to domain names and nodes, to allow quick location of corresponding resources during later compliance reviews. Some documents are PDF-format filing materials, so systems must support custom parsing to extract structured fields, preventing key information loss from default parsing.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | CDN-related documents are mostly structured configurations and log snippets. This length adapts to RAG retrieval accuracy and recall efficiency |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Batch uploads of refresh and preheating records or fault analysis reports have longer single parsing durations. This setting prevents task timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | This covers the size range of most CDN business documents, and adapts to batch import requirements for compliance materials |
| `customPdfParse` | Enabled | For structured documents such as domain name filing PDFs, this setting preserves key fields including filing numbers and access domain names, to meet compliance review needs |
| `chunkSplitter` | Semantic + paragraph-based chunking | This adapts to the paragraph structure of CDN documents, and avoids splitting coherent configuration content such as cache rules and alert descriptions |
| `chunkSettingMode` | Manual configuration | CDN document fields are fixed. Manual adjustment of chunking parameters allows precise adaptation to retrieval requirements for specific business scenarios |

This configuration applies to FastGPT v4.17.0.

## Three common configuration errors
- Phenomenon: After parsing a domain access form PDF, key fields such as filing number and access domain name are empty. Cause: The `customPdfParse` custom parsing mode is not enabled. Default parsing does not extract structured business fields.
- Phenomenon: When uploading a cache rule file larger than 100 MB in batches, the parsing task returns a timeout error. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual parsing duration of the batch files, and does not adapt to batch processing requirements for CDN documents.
- Phenomenon: After calling the workflow API to upload an image file, the returned result does not contain image parsing content. Cause: Image parameters are not passed according to interface requirements, or the uploaded file size exceeds the `UPLOAD_FILE_MAX_SIZE` limit.

## How to confirm the configuration is active
- Upload a single domain access form PDF, and check whether the parsing result includes key fields such as filing number and access domain name. This confirms that the `customPdfParse` configuration takes effect.
- Upload a 100 MB cache rule file, and check whether the parsing task completes within the duration set by `PARSE_FILE_TIMEOUT_SECONDS` with no timeout errors.
- Call the workflow API to upload a compliant image file, and check whether the returned parameters include parsed text content. This confirms that parameter transfer meets interface requirements.
- View the file parsing statistics panel in the console, and confirm that the chunked text length falls within the 800–1200 character range set by `chunkSize`.

The values provided are common starting points and should be measured against the reader's own samples.
