# Security and Compliance Material Review for IT Service Desk Ticket Processing: Document Parsing and Chunking

This document adapts to the functional logic of FastGPT v4.17.0.

## What data in this category looks like
The data for this category comes from enterprise ITSM systems, phone or chat records, asset systems, and internal knowledge bases. Daily processed documents include service request forms, incident tickets, processing records, and user satisfaction surveys. Data updates occur on a daily basis or in real time.
Documents typically include fields such as ticket ID, submission time, user identity identifier, problem description, processing steps, and compliance check tags. There is no fixed unified external format. Some documents come from structured files exported from systems, while others are unstructured text from chat transcripts.

## What constraints these characteristics impose on the document parsing and chunking link
The diversity of data sources requires the parsing link to support structured ticket files, chat transcripts, and digitally signed PDFs, to avoid parsing failures for some file types.
The real-time update feature requires parsing timeout settings to match the time requirements of ticket processing, to avoid excessive waiting that disrupts business workflows.
Documents include key fields such as compliance check tags and ticket IDs. During chunking, the association between fields and context must be retained, to avoid losing critical compliance information after splitting.
Unstructured chat transcripts may contain colloquial expressions. Basic format regularization must be performed before chunking, to ensure that the chunking logic follows the problem-processing flow structure of tickets.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of a single problem or processing step in ticket documents, avoids excessively large chunks that reduce retrieval accuracy, or excessively small chunks that break context association |
| `chunkSplitter` | Split by paragraph and semantic meaning | Matches the natural paragraph structure of ticket documents, retains the complete logic of problem descriptions and processing steps |
| `customPdfParse` | Enable signed PDF parsing adaptation | Resolves the issue where digitally signed PDF compliance materials cannot have their content recognized, adapts to common approval file formats in tickets |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the common size of ticket attachments in enterprise IT service desks, avoids failed uploads of compliance materials |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Matches the time requirements of real-time ticket processing, avoids long waits that disrupt ticket assignment |
| `chunkSettingMode` | Manual calibration | Adapts to the mixed structured and unstructured format of ticket documents, flexibly adjusts chunking parameters to support different source document types |

## Three common mistakes
- Phenomenon: After uploading a digitally signed PDF compliance material, the parsing result is empty or fails to recognize valid content. Cause: The signed PDF parsing adaptation of `customPdfParse` is not enabled, and the default parsing logic cannot handle signed document formats.
- Phenomenon: A file read error occurs when calling the document parsing process, and a prompt for abnormally formatted content is returned. Cause: The uploaded ticket attachment exceeds the set value of `UPLOAD_FILE_MAX_SIZE`, resulting in failed file reading.
- Phenomenon: No image information is extracted from the parsed document chunks, and the large language model cannot associate image content when generating answers. Cause: The image extraction logic in the document parsing link is not configured, or the associated metadata of images is not retained during chunking.

## How to confirm that the configuration is correct
- Upload a test digitally signed PDF ticket attachment, check whether the parsing result contains complete text content, to verify that the `customPdfParse` configuration takes effect.
- Upload ticket documents in different formats, including structured tables and chat transcripts, check whether the chunking result retains key fields and context association.
- Upload a test attachment that exceeds the conventional size, confirm whether an upload limit prompt is triggered, to verify that the `UPLOAD_FILE_MAX_SIZE` configuration is correct.
- Wait for the parsing to complete, check whether the returned access link can be accessed normally, to confirm that the `PARSE_FILE_TIMEOUT_SECONDS` setting matches the parsing duration.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
