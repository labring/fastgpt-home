# Security and Compliance Material Review for IT Asset Inventory: Permission and Data Isolation

## What This Category's Data Looks Like
This category’s data includes four core document types: asset ledgers, inventory sheets, loan and return forms, and scrap applications. Data sources cover asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms.
Update frequencies typically follow monthly, quarterly, or annual cycles. Document fields include asset number, user, location, ownership information, purchase date, and scrap status. Units include units, sets, yuan, and others.
This data centers on asset ownership, usage status, and physical location. Its difference from configuration management data is that it focuses more on the actual usage subject and ownership of assets.

## Constraints for Permission and Data Isolation
Multi-source data access creates demand for cross-system data permission alignment. Ensure asset data imported from different systems is only visible to authorized roles.
Asset data ties to financial and audit compliance requirements. Permission configuration must cover hierarchical access to documents such as asset ledgers and loan and return forms.
Fields including user, location, and ownership information require data isolation based on department and user dimensions.
Update cycles are long, but errors carry severe consequences. Configure operation logging and permission change audit mechanisms to prevent asset loss or audit non-compliance caused by unauthorized access.
This category also prioritizes isolation of asset usage subjects, avoiding cross-user asset data interference.

## How to Configure
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Team Permission Binding | Associate `teamId` with asset data scope | Match business needs for independent asset management across teams, enable cross-team data isolation |
| Data Isolation Granularity | Divide by `tmbId` or user ID | Cover core fields such as asset user and location, enable fine-grained access control |
| Audit Log Retention | Set based on actual measurements | Meet log retention requirements for compliance audits, prevent unauthorized operations from being untraceable |
| SSO Login Configuration | Enable commercial edition features | Unify enterprise identity verification processes, meet security and compliance access standards |
| Global Variable Isolation | Isolate variables with the same name by user ID | Prevent conflicts between asset configuration variables of different users, ensure data independence |
| Team Data Storage | Store interface return data by team | Ensure correct data isolation when switching teams, match the update cycle characteristics of asset data |

## Three Common Configuration Mistakes
- Phenomenon: Administrators from different teams can view asset ledgers and loan records of other teams after logging in. Cause: The binding relationship between `teamId` and asset data scope is not configured, so team permission isolation does not take effect.
- Phenomenon: When different users create global variables with the same name, their modification operations interfere with each other. Cause: The setting to isolate global variables by user ID is not enabled, and the default global scope configuration is used.
- Phenomenon: After switching teams using the tokenLogin interface, the returned asset data does not update synchronously. Cause: Interface return data is not stored by team, leading to incorrect data association when switching teams.

## How to Confirm Proper Configuration
- Log in with administrator accounts from two different teams, view asset ledgers, and confirm that only asset data managed by the current team is visible.
- Create global variables with the same name using two different user identities, modify each variable’s value separately, and confirm that the variable values do not interfere with each other.
- Perform a permission change operation, and confirm that the system generates a corresponding audit log entry.
- Switch teams using the tokenLogin interface, and confirm that the returned team data matches the currently logged-in team.
