# Security and Compliance Material Review for IT Asset Inventory: Model Access and Configuration

## What Data Looks Like for This Category
IT asset inventory data originates from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Daily generated documents include asset ledgers, inventory sheets, loan and return forms, and scrap applications.
Data updates occur monthly, quarterly, or annually. A single update covers current period asset change information.
Document fields include asset number, name, specification model, user, storage location, loan date, scrap status, and more. Units are primarily physical measurement units such as unit, set, and piece. Some finance-associated fields must align with fixed asset accounting standards.

## Constraints Imposed on Model Access and Configuration
Multiple data sources require model access configuration to support format adaptation across different systems, preventing field parsing deviations.
Monthly, quarterly, or annual update cycles mean model batch processing frequency does not need to be high, supporting periodic inventory review tasks.
Diverse document types require configuration parameters that support multi-format parsing, ensuring consistent review of different documents such as asset ledgers and loan forms.
Rich field content requires sufficient reserved space for context length parameters, to fully carry compliance review information related to assets.
Time-consuming links including account-physical verification and scrap material organization require model tool call configuration to support automated process integration.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Documents such as asset ledgers and inventory sheets contain many fields, requiring full accommodation of asset information and review records |
| `maxTokens` | `2000–3000 token` | The content length of materials for a single compliance review is moderate, avoiding exceeding the model context limit |
| `quoteMaxToken` | `500 token` | The length of asset document fragments requiring quotation is limited, reasonably controlling the occupied space of quoted content |
| `toolChoice` | `auto` | Adapts to automated review processes such as account-physical verification and scrap material verification, automatically calling corresponding tools |
| `temperature` | `0.1–0.3` | Compliance review requires strictness, reducing randomness of generated content to avoid deviations |
| `AIPROXY_API_TOKEN` | Fill in the non-empty administrator Token consistent with AI Proxy server configuration | As an environment variable for the App/Admin server, completes identity verification for the AI Proxy service. This variable cannot be configured in the model management page, workflow global variables, or application API request headers |

## Three Common Configuration Mistakes
- Model test returns error "[] is too short - 'messages'". Troubleshooting: check initial context parameters for the model conversation, confirm the incoming message array is non-empty and meets required length.
- Models on ONEAPI cannot connect, and new model configurations are not visible after restarting FastGPT. Troubleshooting: required environment variables `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not configured on the App/Admin server, or environment variables do not take effect correctly.
- Conversation records are shared across multiple users. Cause: independent access keys are not generated for each user, or key configurations are not bound to user identities.

## How to Confirm Configuration Is Complete
- Check the App/Admin server startup log, confirm there are no startup verification failure prompts related to `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`.
- Upload an asset inventory sheet, trigger model review, and verify core fields such as asset number and user are correctly identified.
- Initiate a model test conversation, confirm there are no errors related to "messages", and returned results meet compliance review requirements.
- After configuring multi-user keys, switch to different user identities to initiate conversations, verify conversation records are isolated.
