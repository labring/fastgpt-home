# Security and Compliance Material Review for IT Procurement and Supplier Management: Citation Sources and Traceability

## What this category of data looks like
This category of data typically comes from internal enterprise procurement systems, supplier quotation documents, budget sheets, and contract systems. Daily processed documents include purchase requisitions, price comparison records, formal contracts, and acceptance documents. Data updates follow cycles per purchase order or monthly. Data fields include procurement requirement specifications, supplier qualification numbers, contract clause numbers, budget amounts, and more. There is no unified mandatory format, and it adjusts based on internal enterprise procurement processes.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Procurement and supplier management documents are mostly a mix of structured and semi-structured data. A single document is linked to multiple stages of data, so traceability requires precise matching of the procurement process node the document belongs to, to avoid cross-order confusion. Data update frequency changes with orders, so cited data sources must be the currently valid version, to avoid calling expired price comparison records or old contract versions. Documents from different sources have large format differences, so the unique identifier of the corresponding purchase order must be associated during traceability, to ensure cited content is directly related to the current procurement demand. Legal and procurement links have high requirements for traceability rigor, so the original document type and generation time of cited content must be clearly marked, to meet basic compliance review requirements.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Matches the average length of procurement and contract documents, ensuring complete citation of key compliance clauses |
| Single search limit | Top 8 entries | Covers multiple documents linked to a single purchase order, avoiding missed price comparison records and contract attachments |
| `responseData` | Includes original document path, generation time | Meets traceability requirements for compliance reviews, facilitating verification of the original source of cited content |
| Reranking | By purchase order priority of the linked document | Prioritizes displaying supplier qualification and contract content directly related to the current procurement demand |
| `detail` | Enable full traceability | Outputs the specific paragraph position of the cited content in the original document, improving review accuracy |

## Three common configuration errors
- Setting `quoteMaxToken` to 3000 token results in truncated cited content, with incomplete compliance clause fragments displayed in the interface. This occurs because the setting does not match the average length of procurement and contract documents, and cannot fully load key clause content.
- Setting the single search limit to 15 entries results in the answer citing too many historical documents not linked to the current purchase order, with an unexpected number of citations. This occurs because the unique identifier of the current purchase order is not associated, and cross-order data sources are not filtered.
- Not enabling the `responseData` configuration results in the answer only displaying cited text, with no way to view the original document path and generation time, making compliance traceability verification impossible. This occurs because the traceability rigor requirements for this category are overlooked, and the original data return item is not configured.

## How to verify successful configuration
A simulated procurement compliance review request is submitted. The answer is checked for inclusion of the original document identifier and generation time of cited content, to confirm the `responseData` configuration is active.
Requests for different purchase orders are tested. The returned cited documents are checked to confirm they only link to data sources of the current order, verifying the search filtering logic works properly.
The value range of `quoteMaxToken` is adjusted. The length of returned cited fragments is verified to match the configured token interval, confirming the parameter is active.
A preset compliance check workflow is triggered. The system is confirmed to output the corresponding original cited content and problem description when cited content fails to meet procurement or legal requirements.

The values provided are common starting points and should be measured against the reader's own samples.
