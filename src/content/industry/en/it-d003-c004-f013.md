# Security and Compliance Material Review for IT Procurement and Supplier Management: Permissions and Data Isolation

## What data falls under this category
Data for this category primarily comes from internal enterprise procurement systems, supplier quotation documents, budget spreadsheets, and contract systems. Daily generated documents include procurement request forms, comparison records, formal contracts, and acceptance receipts. Data updates follow individual procurement workflows, with one update per finished order. Monthly summary data is updated each month. Individual documents contain fields such as procurement order number, supplier qualification number, budget amount, contract clause summary, and acceptance milestones. Units include monetary values and days.

## What constraints do these characteristics impose on permissions and data isolation?
Data for this category is scattered across multiple internal systems. It includes sensitive information such as budget amounts and contract clauses. Permissions must align with the responsibility boundaries of different roles. Individual data entries are independent per procurement order. Documents for different procurement projects must be strictly isolated to prevent cross-project permission leaks. Data updates progress alongside procurement workflows. Permission configurations must adapt to changes in workflow nodes. Only personnel involved in the current project can access corresponding documents. Some documents may only be viewed by core roles such as legal and finance teams. Regular interns cannot access sensitive content.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Team permission groups | Divide by procurement departments and project teams | Aligns with the business structure of this category, which is organized by procurement teams and project management. Ensures team members share access to corresponding procurement documents. |
| `teamId` binding | Bind to the procurement project's `teamId` | Data for this category is independent per procurement order. Using `teamId` accurately links all documents for a single procurement workflow, enabling project-level isolation. |
| Sensitive data access restrictions | Allow access only to legal and finance role accounts | Contract and budget documents for this category are highly sensitive. Access must be limited to core personnel such as legal and finance teams. |
| Intern account permissions | Restrict intern account access to only public documents | Interns do not need access to sensitive data from full procurement workflows. They may only view public content such as procurement request templates. |
| Permission expiration configuration | Set a validity period of 7–30 days aligned with procurement project cycles | Data updates for this category follow procurement order cycles. Permissions automatically expire when a project ends, preventing lingering long-term permissions. |
| Referenced document display scope | Only display document entries within the current permission scope | Avoid returning references to documents the user cannot access, which complies with security and compliance review requirements. |

## Three common configuration errors
- Scenario: Unauthorized members can access sensitive procurement documents, such as contract clauses or budget amounts. Cause: Documents are not correctly bound to `teamId`. Only global permission groups are configured, and project-level isolation is not implemented.
- Scenario: Intern accounts can view full contract and budget documents. Cause: Permission scopes are not separately configured for intern accounts. Public permissions are mistakenly mixed with core role permissions.
- Scenario: Members assigned write permissions cannot create a knowledge base for the corresponding procurement project. Cause: The team is not associated with the corresponding procurement project using `teamId`. Permission configurations do not match the business unit of the project.

## How to confirm proper configuration
- Select an unauthorized account, attempt to access contract documents for the corresponding procurement project, and confirm that the user cannot open or view restricted content.
- Check the permission binding relationships of the knowledge base, and confirm that all associated procurement documents are bound to the corresponding `teamId`.
- Submit a document query for a procurement workflow, and confirm that returned reference entries only include documents the current account has permission to access.
- In FastGPT v4.17.0, verify the permission expiration configuration. After simulating project completion, confirm that the original authorized account can no longer access the corresponding documents.
