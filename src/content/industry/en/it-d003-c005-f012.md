# Security and Compliance Material Review for Issue Triage and Response: Document Parsing and Chunking

## What data looks like for this category
This category of data primarily comes from Issues, release notes, user environment information, and code repositories on GitHub or Gitee. The update frequency is daily or weekly. Daily processed documents include Issue templates, label rules, problem response records, and problem reproduction instructions. Each data entry contains fields such as Issue number, status, associated labels, reproduction steps, and environment configuration. Some data includes compliance-related attachments in PDF, Word, or PPT formats.

## What constraints these characteristics impose on the document parsing and chunking link
The data structure for this category is fragmented and comes in diverse formats. It includes short-text problem descriptions, long paragraphs of reproduction instructions and compliance documents, plus attachments in multiple formats. This requires the parsing process to adapt to text of varying lengths and formats. The data update frequency is high, so parsing efficiency must be maintained to avoid backlogs of issues. Security and compliance reviews require that key context be retained during chunking, and key compliance clauses and problem-related information must not be split. Local deployment scenarios must also address constraints related to file upload and parsing timeouts.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the text length of Issue reproduction instructions, avoid splitting critical problem steps |
| `chunkSplitter` | Prioritize paragraphs | Match logically segmented responses and reproduction records in Issues, retain context integrity |
| `customPdfParse` | Enabled | Process compliance documents in Issue attachments, retain original layout and annotation information |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Accommodate upload requirements for large-volume release notes and compliance reports |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Address time spent parsing long documents, avoid task interruption mid-process |
| `chunkSettingMode` | Manual configuration | Flexibly adjust parameters for scenarios mixing Issue-style short text and long attachments |

*Note: The configurations on this page apply to FastGPT v4.17.0*

## Three common configuration mistakes
- Setting `UPLOAD_FILE_MAX_SIZE` too small. When uploading compliance documents exceeding the threshold, a 413 Request Entity Too Large status code is returned, because the configuration was not adjusted for large-volume Issue attachments.
- Not enabling `customPdfParse`, resulting in empty fields after parsing annotated PDF compliance documents, making it impossible to extract key compliance clauses.
- Failing to correctly bind the temporary path of uploaded files in the workflow. Calling `CUSTOM_READ_FILE_URL` returns a parsing failure, because the file address was not correctly associated with the parsing step.

## How to confirm configurations are set correctly
- Upload a test Issue reproduction instruction document, check the parsed chunk results, confirm that paragraph splits are logical and critical steps are not truncated.
- Check the configuration values of `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS`, match them with local deployment server resources and file upload limits.
- Test compliance attachments in PDF, Word, and PPT formats, confirm that all formats can be parsed normally and complete chunked data is generated.
- Review system logs, confirm there are no error records for parsing timeouts or file size limits exceeded.

The values provided here are common starting points, and should be evaluated against specific samples and deployment environments of the target use case.
