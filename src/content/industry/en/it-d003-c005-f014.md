# Security and Compliance Material Review for Issue Triage and Response: Model Access and Configuration

## What data looks like for this category
Data for this category primarily comes from GitHub or Gitee Issues, code repository version logs, user-submitted environment information and problem reproduction descriptions. Daily maintained documents include Issue templates, tag rules, and historical reply records. Data updates occur on a daily or weekly basis. Each data entry contains fields such as problem description, reproduction steps, associated code snippets, and user environment parameters. There is no unified fixed format, so adaptation to different repository Issue submission specifications is required.

## What constraints these characteristics impose on model access and configuration
Data sources are scattered and formats are inconsistent. When connecting models, adapt to unstructured text from multiple sources and limited image content such as error screenshots uploaded by users. Data updates occur frequently. Configure processes that support dynamic incremental indexing to avoid resource consumption from full reindexing. Fields vary widely across individual data entries. Models must have flexible intent recognition capabilities. Limit the context length per processing run to prevent call failures from overly long inputs. Security and compliance review requires filtering sensitive information and prohibited content in Issues. Add corresponding validation steps in model configuration.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the total length of multiple sections of problem descriptions, reproduction steps and code snippets included in Issues, avoiding context overflow |
| `maxTokens` | 2000–3000 token | Controls the output length per round of responses, ensuring triage results are clear and concise, matching the standard format of community Issue replies |
| `vision` | Enabled | Supports recognition of image content such as user-uploaded error screenshots and log screenshots, matching non-text compliance materials included in data |
| `temperature` | 0.3–0.5 | Reduces randomness, ensuring stable and consistent classification and compliance check results, meeting the deterministic requirements of security reviews |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service, for example http://aiproxy:3000 | Required environment variable for the App/Admin server. Do not add paths such as /v1 or /chat/completions. This is not a single-model service address |
| `toolChoice` | auto | Allows the model to independently choose whether to call tools, adapting to compliance verification and classification requirements across different scenarios |

## Three common misconfigurations
- Vector index build tasks stay stuck with no progress. The interface does not display index completion or update status. The cause is failure to adapt to the unstructured characteristics of Issue data and configure corresponding data processing rules, resulting in the index process failing to trigger normally.
- Model calls throw errors when receiving Chinese input, and return abnormal formats for English input. The cause is failure to adapt the model's input language to Chinese, or an unreasonable `temperature` parameter range, resulting in model output that does not match expected formats.
- Recognition results of locally deployed VLM models in FastGPT do not match results from direct API calls. The cause is failure to correctly configure the `vision` parameter call chain in FastGPT, or failure to align the model's input format with FastGPT requirements.

## How to confirm configuration is complete
Use the following actions to verify configuration effectiveness. This verification process applies to FastGPT v4.17.0:
- Submit a test Issue containing text and images, check whether the model correctly recognizes image content and completes classification.
- View model call logs, confirm that the `maxContext` and `maxTokens` parameters do not trigger overflow errors, and that response lengths meet expectations.
- Test inputs in different languages, confirm that the model's classification results are stable in Chinese scenarios with no format abnormalities.
- Check whether the App/Admin server has correctly configured non-empty `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` environment variables, ensuring service startup verification passes.

The values provided are common starting points and should be measured against the reader's own samples.
