# Security and Compliance Material Review for Pull Request Reviews: Citation Sources and Traceability

This configuration applies to FastGPT v4.17.0.

## What This Category of Data Looks Like
Typical data for this category comes from code repositories, CI pipelines, Issue links, and contributor submissions. Update frequency is typically daily or weekly. Daily documents include PR descriptions, code review comments, CI results, and merge records. Fields cover PR numbers, changed file lists, reviewer identifiers, CI pass rates, associated Issue addresses, and similar items. There are no uniform fixed unit requirements, and the data structure adjusts dynamically based on a project’s review rules.

## How These Characteristics Impact Citation Sources and Traceability
The scattered nature of data sources requires the traceability link to associate business data across multiple platforms, and avoid only searching content from a single repository. The periodic update frequency means traceability must support incremental pulling, so full historical data does not need to be reprocessed. The flexible document structure means traceability configuration must adapt to field rules for different projects, and cannot hardcode fixed fields. At the same time, errors in this category directly affect main branch stability, so traceability results must accurately associate the current PR’s changed content, and avoid introducing irrelevant data to interfere with reviews.

## How to Configure Settings
The following configuration items correspond to core FastGPT parameters: quote maximum token count maps to `quoteMaxToken`, returned data range maps to `responseData`, and traceability detail switch maps to `detail`.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Quote maximum token count | 8000–12000 token | Covers complete content of typical compliance materials such as PR descriptions and CI results |
| Returned data range | Include associated PR numbers, CI log links, and Issue addresses | Matches core business traceability requirements for PR reviews |
| Traceability detail switch | Enabled | Displays specific fragments of citation sources to facilitate review and compliance verification |
| Single recall limit | Top 3–5 items | Avoids redundant data interfering with reviews, and aligns with the lightweight review habit of PR reviews |
| Retrieval timeout threshold | 600 seconds | Adapts to large-scale data retrieval requirements for open source projects, and avoids prematurely terminating valid traceability |

## Three Common Configuration Mistakes
- Phenomenon: Citation sources displayed in conversations cannot be hidden. Cause: The traceability detail switch was incorrectly set to enabled, and the parameter for hiding citations was not properly configured.
- Phenomenon: Returned citation sources are not associated with the current PR’s changed content. Cause: The retrieval scope was not limited to only associated data from code repositories, CI pipelines, and Issue links, leading to retrieval of irrelevant business documents.
- Phenomenon: Traceability retrieval times out. Cause: The quote maximum token count was set to an unreasonable range, resulting in an excessively large single processing data volume.

## How to Verify Successful Configuration
- Initiate a test PR that includes changed files and CI results, trigger the compliance review process, and check if the returned results include associated PR numbers and CI log links.
- Adjust the value of the single recall limit, trigger a retrieval, and confirm that the number of returned citation contents matches the set range.
- View FastGPT runtime logs to confirm that no timeout or field missing errors related to traceability retrieval have occurred.
- Simulate the compliance review trigger logic, confirm that only business data related to the current PR is retrieved, and no irrelevant knowledge base content is introduced.

The values provided are common starting points and should be evaluated using samples tailored to individual use cases.
