# Security and Compliance Material Review for Pull Request Reviews: Model Integration and Configuration

## Data Characteristics for This Category
The data for this category primarily comes from code repositories, CI pipelines, Issue links, and contributor-submitted content. Daily processed documents include PR descriptions, code review comments, CI results, and merge records.

Data update cycles follow daily or weekly schedules. Each individual data entry includes change scope descriptions, CI validation results, review comment entries, contributor information, and merge status fields. There are no fixed-format standardized statistical fields; entries are generated dynamically alongside PR submission and processing workflows. Content formats mix text, code snippets, and structured validation results.

## Constraints on Model Integration and Configuration
The data sources for this category are scattered and have diverse formats, including code snippets, text descriptions, and structured validation results. This requires the model integration phase to support mixed-format inputs and context correlation.

Data update cycles change dynamically with PR submission schedules. The context length for single processing has fluctuating upper limits. Total token consumption must be limited to avoid call timeouts. Each individual PR contains a large number of review comments and change entries. The number of entries processed in a single model call must be controlled to prevent exceeding the model context window.

Data is linked to code repositories and CI results. The model call must correctly bind the context for the corresponding PR to avoid mixing processing data from different review tasks.

## Configuration Settings
This document is written based on the configuration logic of FastGPT v4.17.0. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Values | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of PR change descriptions, review comments, and CI results, avoiding exceeding the context window limits of general large models |
| `maxTokens` | 2000–3000 token | Controls the length of compliance review results output in a single model call, matching the short conclusion output requirements of review scenarios |
| `quoteMaxToken` | 1000–1500 token | Limits the length of original PR text referenced, ensuring review content focuses on core changes and compliance risks |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensuring consistency and accuracy of compliance review results, and avoiding subjective bias |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000. Do not append paths such as /v1 or /chat/completions. Non-single-model service address | Required environment variable for the App/Admin server |
| `AIPROXY_API_TOKEN` | Non-empty administrator token matching the AI Proxy server configuration | Required environment variable for the App/Admin server, used for AI Proxy service identity verification |

## Three Common Misconfigurations
- Symptom: GPU memory usage rapidly increases to 6–7 GB after calling the reranking model, and usage appears on every GPU. Cause: Concurrency call limits for the reranking model are not configured, causing a single PR review to trigger multiple model instance loads, exceeding single-card memory thresholds.
- Symptom: `rerank error` is prompted when offline integrating the reranking model, and the log returns `{ message: { detail: '`. Cause: The local storage path of the model is not configured correctly, or the dependent library version does not match the requirements of FastGPT v4.17.0.
- Symptom: Invalid token prompt appears when integrating domestically developed models, and testing via a separate proxy interface works normally. Troubleshooting steps: Check if the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configured on the App/Admin server are correct and match the AI Proxy server configuration; check the running status of the AI Proxy service.

## How to Confirm Successful Configuration
- The `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` values configured on the App/Admin server are verified to match the AI Proxy server configuration, with no spelling errors or extra spaces.
- A test PR is submitted to trigger the security and compliance review workflow, and platform logs are checked for normal review results with no `rerank error` or invalid token related errors.
- GPU resource monitoring panels are reviewed to confirm that the reranking model's memory usage stays within a reasonable range, with no abnormal spikes or duplicate multi-card usage.
- A PR containing mixed-format content including code snippets and text descriptions is tested, and the model's ability to correctly identify and process different types of input content, as well as output expected review conclusions, is confirmed.
