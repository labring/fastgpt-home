# Security and Compliance Material Review for SLA and Service Reports: Citation Sources and Traceability

## What this category of data looks like
The data for this category comes from monitoring systems, ticket systems, contract documents, and customer communication records. The update cycle is monthly or quarterly. Daily produced documents include SLA clauses, monthly service reports, availability statistics items, and customer review minutes. Core fields cover service cycle range, event response duration range, service indicator items agreed in contracts, and summary records of service events within the corresponding cycle. The data structure is adjusted based on the contract cycle and service frequency.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
The data sources for this category are scattered, and include multiple types of system records such as contracts, tickets, and monitoring logs. Citation traceability requires simultaneous association of original contract clauses, specific ticket events, and monitoring log metadata. Since data is updated on a monthly or quarterly cycle, cited source data must correspond to the archived version within the specified service cycle. This avoids calling temporary data that has not been fully summarized. Documents are mainly summary reports. Cited fragments must be traced back to original document fragments before slicing, and cannot rely solely on secondarily processed summary content. At the same time, the original event number corresponding to the service indicator must be matched to ensure traceability accuracy.

## Configuration Settings
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the length of a single core fragment for SLA and service reports, to avoid truncation of key service indicator content |
| `responseData` | Enabled | Ensures the output result includes the archived cycle and slicing position of the source document, meeting the recording requirements for compliant traceability |
| `detail` | Full original file preview | Supports jumping to the original document before slicing, matching user needs to view the original file |
| Single recall limit | Top 5 entries | Adapts to the multi-source data summary scenario of monthly service reports, controlling the number of returned source data |
| Source data matching rule | Calibrated by contract cycle | Matches the cycle-based update data characteristics of this category, avoiding confusion of source data across cycles |

## Three Common Misconfigurations
- Phenomenon: Failure to open the original document prior to slicing after citing a fragment. Cause: The `detail` configuration is not set to full original file preview mode, and only secondarily processed summary report content is returned.
- Phenomenon: External testing passes, but a string of red numeric errors is returned when citing SLA data in FastGPT. Cause: The cycle-based update data characteristics of this category are not matched, resulting in failed association of source data across service cycles.
- Phenomenon: Inability to confirm the specific source document and corresponding cycle of the output content. Cause: The `responseData` configuration item is not enabled, and no metadata information of the source document is carried in the result.

## How to Confirm Proper Configuration
- A citation query for SLA clauses is initiated. The path and cycle information of the source document in the returned result is verified.
- The preview link of a cited fragment is clicked. Successful jumping to the original document before slicing is confirmed.
- The value of `quoteMaxToken` is adjusted. Full retention of core service indicator content is verified.
- A cross-cycle citation query is simulated. Only source data within the corresponding cycle in the returned result is confirmed.

The values provided are common starting points and should be evaluated against applicable internal samples.
