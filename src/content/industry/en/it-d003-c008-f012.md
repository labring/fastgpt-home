# Security and Compliance Material Review for Special Event Operations: Document Parsing and Chunking

## What data for this category looks like
Data for special event operations typically comes from content libraries, event backends, traffic metrics, and user feedback. Commonly processed documents include event plans, resource slot schedules, event page copy, and post-event review reports. Most documents include structured fields such as event IDs, resource slot numbers, traffic metrics, and review statuses. Update cycles follow weekly or holiday schedules. Document lengths vary widely, from short event notifications to dozens of pages of review reports.

## Constraints imposed on document parsing and chunking by these characteristics
The hierarchical structure and structured fields of event documents require that parsing and chunking preserve the correspondence between headings and paragraphs. This prevents loss of core associated information such as event phases and resource slot assignments after splitting. Frequently updated event materials need to support incremental parsing and batch uploads. Large post-event review reports may require extended parsing time. Compliance review of event materials requires accurate identification of sensitive content. Chunks should not be too small, which breaks context, or too large, which leads to missed reviews. Parsing results for non-plain text content such as tables and images must also be retained.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Event plans and review reports are mostly long texts. This range preserves core information such as event cycles and resource slots without truncation |
| `chunkSplitter` | Split by paragraph + heading | Event documents often contain hierarchical headings such as event themes and execution steps. Preserving structure facilitates location during compliance reviews |
| `customPdfParse` | Enabled | Event documents are often submitted in PDF format. Enabling this setting extracts embedded image text and layout information |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Event-related material packages may include multi-page PDFs and collections of schedule tables. This setting supports batch upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large event review reports take a long time to parse. This avoids parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Event documents have large structural differences. Manual adjustment adapts to different types of event materials |

## Three common configuration mistakes
- Parsing times out after uploading event-related PDFs, and the interface shows a request failure. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. The default duration is insufficient for parsing large review reports.
- After uploading a resource slot schedule in table format, some data is lost. The cause is failure to enable `customPdfParse` or configure the corresponding chunking rules, leading to truncation of structured table fields.
- After exporting and importing the knowledge base, image parsing results for event copy are lost. The cause is failure to package associated image files, or failure to enable the `customPdfParse` setting on the new server.

## How to verify correct configuration
- Upload a typical event plan PDF, and check if the parsed chunks retain hierarchical content such as event themes and execution steps.
- Upload an event material package larger than 500 MB, and confirm that the upload proceeds normally without triggering a file size limit prompt.
- Wait for parsing to complete, and check logs to confirm no timeout errors occur. The number of chunks matches the number of document pages.
- Export the event materials from the current knowledge base, import them into the FastGPT v4.17.0 test environment, and confirm that all structured data matches the original documents.
