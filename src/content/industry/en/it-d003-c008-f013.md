# Security and Compliance Material Review for Special Event Operations: Permission and Data Isolation

## What this category's data looks like
Daily data for special event operations includes four core document types: event plans, resource slot schedules, event page copy, and post-event review reports. Data sources include content libraries, event backends, traffic data, and user feedback.
Update frequency is mostly weekly. Temporary adjustments are made around holidays based on event timelines.
Document structure includes dedicated fields such as event cycle, resource slot location, copy version, and review cycle. There is no unified general statistical standard. Data volume fluctuates with event cycles.

## What constraints do these characteristics impose on permission and data isolation?
Event plans, page copy, and similar documents are divided by event cycle. Permissions must be isolated for different cycles to prevent cross-cycle data leaks.
Resource slot schedules involve cross-department collaboration. Access ranges must be divided by team affiliation to prevent unauthorized personnel from adjusting core operational resources.
Data comes from multiple sources. Traffic data and user feedback from different sources must be visible only at permission levels to ensure sensitive operational data is not leaked.
Weekly and temporary holiday data updates require synchronized permission configuration updates to prevent access errors caused by expired permissions.

## How to configure settings
FastGPT v4.17.0 supports the following permission and data isolation configurations:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` data binding | Bind to the owning team of event plans and review reports, limit to event documents from the last 7 days | Event documents are divided by team affiliation, and update frequency is weekly. Limiting the cycle reduces invalid data access and aligns with the cycle characteristics of special events |
| `tmbId` resource isolation | Limit resource slot schedules to be visible only to members under the corresponding `tmbId`. Single-team resource slot storage limit is 1000 MB | Resource slots are team-specific operational resources. Isolating by `tmbId` prevents cross-team resource adjustments. The storage limit prevents excessive resource occupation by a single team |
| Global variable scope | Isolate identical-named global variables by `teamId`, each team’s variable values are independent | Different operational teams may use identical-named global variables for their events. Isolating by `teamId` ensures each team’s variable values remain independent and avoids cross-team conflicts |
| SSO permission sync | Enable for commercial editions, sync team permissions from enterprise organizational structures | Special event operation teams are mostly internal enterprise organizations. A unified permission entry improves configuration efficiency |
| Token login team storage | Bind the current `teamId` to user sessions. Permission verification timeout is 30 seconds | Team switching requires real-time updates to permission scopes. The timeout setting prevents invalid permission occupation |

## Three common configuration mistakes
- Issue: Non-commercial edition users cannot find SSO-related options in the permission configuration page. Cause: The SSO permission sync feature is only available in commercial editions. Failing to confirm the edition in advance prevents successful configuration.
- Issue: Identical-named global variables across different operational teams have their values overwritten, leading to errors in event copy or schedules. Cause: Global variable scope was not configured by `teamId`, resulting in cross-team data conflicts.
- Issue: After switching teams, the event data list does not update and still displays content from the original team. Cause: Token login team data was not bound to `teamId` via user sessions, so permission scopes were not updated in real time.

## How to confirm configuration is complete
- Log into accounts under different `teamId`s, verify that only event plans and resource slot schedule documents created by the corresponding team are visible.
- Test identical-named global variables across different teams, confirm that each team’s variable values do not affect one another, with no cross-team overwriting.
- Perform a team switch operation, verify that the team data returned after Token login updates synchronously, and permission scopes match the current team in real time.
- If using the SSO feature, confirm that commercial edition accounts can automatically sync team permissions via enterprise organizational structures, with no manual configuration required.
