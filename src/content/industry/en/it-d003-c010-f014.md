# Security and Compliance Material Review for Incident Response and Troubleshooting: Model Integration and Configuration

## What data for this category looks like
Data for this category originates from monitoring alerts, log platforms, APM tools, and user feedback. Updates occur in real time or each time an event is triggered.
Daily processed documents include trouble tickets, event timelines, emergency response plans, and incident notifications. Most document fields include event ID, occurrence time, impact scope, remediation steps, notification recipients, and similar items. There is no fixed unified format, and it adjusts dynamically based on the specific event scenario.

## Constraints imposed by these characteristics on model integration and configuration
Dispersed data sources and flexible update schedules require the model integration process to support rapid integration and retrieval of multi-source data. Daily documents have no fixed format, so parsing logic for unstructured text must be configured to prevent content extraction failures caused by format differences. Single-event remediation windows are limited, so model inference latency and output length must be controlled to maintain response efficiency. Incident notifications involve compliance content, so returned reference materials must be accurate and traceable. Real-time updated data requires configuration options that support dynamic adjustment of context length to avoid exceeding model processing limits.

## How to set configurations
The following configurations are based on the parameter logic of FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to multi-source document integration needs for single events, avoids exceeding model context limits |
| `maxTokens` | `2000–3000 token` | Controls single inference output length, meets fast response requirements for incident remediation |
| `quoteMaxToken` | `1500 token` | Limits total token count of reference materials, ensures content is precise and non-redundant during compliance reviews |
| `toolChoice` | `auto` | Automatically selects whether to call tools, adapts to dynamic needs for multi-source data retrieval |
| `temperature` | `0.2–0.4` | Reduces output randomness, ensures consistency and accuracy of compliance review results |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example `http://aiproxy:3000`. Do not add path suffixes such as `/v1` or `/chat/completions`, and do not point to a single model service address | Configures the access root address for the AI Proxy service. This is a required environment variable for the App/Admin backend |
| `AIPROXY_API_TOKEN` | Enter the admin token consistent with the AI Proxy backend configuration. Do not leave this blank | Configures the authentication credential for the AI Proxy service. This is a required environment variable for the App/Admin backend |

## Three common configuration errors
- Symptom: The model returns only 1 knowledge base matching text block, and cannot output comprehensive results. Cause: Related configurations were not adjusted, and only the single highest-match content was pulled.
- Symptom: After the document parsing node is configured, the model cannot read uploaded trouble tickets or emergency response plan files. Cause: Access permissions for the file storage path were not correctly configured, or the parsing node trigger logic was not bound to the event upload action.
- Symptom: Model calls return authentication failure or request URL error, and startup verification fails. Troubleshooting items: `AIPROXY_API_TOKEN` was entered incorrectly, or `AIPROXY_API_ENDPOINT` points to a non-AI Proxy service root address or has an invalid path suffix added.

## How to confirm configurations are correctly set
- Submit a test request for a simulated event, verify that the number of reference materials returned by the model matches expected values, and adjust related configurations to align with requirements.
- Upload a test trouble ticket file, confirm that the model can correctly read and associate the parsed text content, and check file access permission configurations.
- Verify that the App/Admin backend startup verification passes, and confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations meet requirements.
- Adjust the `temperature` parameter, verify that the randomness of output results meets the strictness requirements for compliance reviews, and adjust the value range as needed.

The values provided here are common starting points, and should be evaluated against your own samples.
