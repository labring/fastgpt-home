# Security and Compliance Material Review for Cloud Host Delivery and Resource Provisioning: Citation Sources and Traceability

## What this category of data looks like
The data for this category originates from cloud management platforms, order systems, IAM permission systems, and billing systems. Updates occur per individual order or in real time. Daily associated documents include resource provisioning forms, instance configuration sheets, account permission forms, and delivery confirmation forms. Core fields include instance unique identifiers, compute specifications, network security group configurations, permission scopes, billing nodes, and more. Field units typically include CPU core count, memory in GB, duration, instance count, and similar metrics. The data volume of a single document fluctuates based on delivery scale.

## Constraints imposed on citation sources and traceability
Multi-source data requirements mean the traceability workflow must associate unique identifiers across multiple systems such as cloud management platforms and order systems. This prevents cross-order data confusion. Real-time updated delivery data means traceability logic must pull the latest configurations synchronously, and cannot rely on static caching. Multiple associated document types mean traceability must bind specific delivery order numbers, and match fields such as instance IDs and permission configurations. This ensures compliance review materials correspond one-to-one with actual delivered resources. Failure to follow this practice may lead to resource misalignment or billing disputes.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average character count of a single delivery document, ensuring cited content fully covers resource configuration details |
| `responseData` | Enabled | Binds multi-system identifiers for cloud host delivery, enabling cross-data source association verification |
| `detail` | Enabled | Covers core fields such as instance IDs, permission configurations, and billing nodes, meeting traceability requirements for compliance reviews |
| Single search limit | Top 5 entries | Limits the number of returned delivery orders, preventing excessive traceability results from interfering with reviews |
| Citation matching threshold | 0.85–0.95 | Calibrated based on actual testing, preventing low-matching irrelevant delivery orders from being associated |

## Three common configuration errors
- Non-standard quotation marks appear at the end of each paragraph in conversation outputs, and revert to standard quotation marks after refresh: The `responseData` field is not configured correctly, causing abnormal rendering of traceability identifiers.
- Irrelevant delivery order citations are returned when querying non-existent cloud host delivery issues in the knowledge base: The citation matching threshold is set too low, matching unrelated document content.
- No cite reference ID is returned when calling the conversation interface: The `detail` configuration is not enabled, so no traceable citation identifier fields are generated.

## How to confirm the configuration is complete
- Initiate a query containing a known cloud host instance ID, and check if the returned result includes matching citation identifier fields in FastGPT v4.17.0.
- Submit a test delivery order to trigger the compliance review process, confirming that cited content matches the core fields of the delivery order.
- Check citation markers in conversation outputs, confirming no garbled formatting and adherence to standard quotation mark specifications.
- Call the conversation interface, verifying the returned result includes a list of citation IDs from the `detail` field, with a count not exceeding the top 5 entries.
