# Security and Compliance Material Review for Cloud Host Provisioning and Resource Activation: Document Parsing and Chunking

## What This Category of Data Looks Like
The core data for this category comes from cloud management platforms, order systems, IAM permission systems, and billing systems. Update frequency is per order or real-time.
Daily processed documents include resource activation forms, instance configuration sheets, account permission forms, and delivery confirmation forms. Most document structures include business titles, specific configuration fields, and approval statuses. Fields cover instance specifications, network security group configurations, permission scopes, delivery nodes, and more. No unified standardized format exists. Some documents are generated by splicing exports from different systems.

## Constraints for Document Parsing and Chunking
Multi-source, heterogeneous document formats require parsing processes to adapt to different export styles, and avoid losing field associations. Real-time or per-order update rhythms require parsing processes to have low latency, and batch preprocessing cannot be used.
Strongly associated fields in forms (such as instance specifications and corresponding security group configurations) require chunking to retain business context, rather than splitting solely by character length. Otherwise, data misalignment will occur in subsequent specification verification and permission verification steps. A single batch delivery may include multiple forms, so chunking confusion across forms must be avoided.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single business blocks in resource activation documents, avoiding splitting configuration content that spans multiple fields |
| `chunkSplitter` | Split by paragraph + title | Matches the form structure of resource activation forms, retaining context for associated fields such as instance specifications and security group configurations |
| `customPdfParse` | Enabled | Adapts to non-standard PDF formats exported by cloud management platforms, retaining table and field layouts from the original document |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the maximum file size in bulk resource delivery scenarios, supporting bulk upload and parsing of multiple forms |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for complex instance configuration sheets, preventing task interruptions caused by overly long single-file parsing |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for the exclusive document structure of cloud host provisioning, adapting to business forms with multiple associated fields |

## Three Common Configuration Mistakes
- Symptom: No log output appears for the parsing node after uploading a PDF document, and the task status shows failed. Cause: The `customPdfParse` configuration is not enabled, so non-standard PDF formats exported by cloud management platforms cannot be recognized.
- Symptom: Field misalignment occurs in parsed chunks, such as security group configurations and corresponding instance specifications being split into different chunks. Cause: `chunkSplitter` is set to split only by character count, without matching the document's title and paragraph structure.
- Symptom: Bulk delivery forms uploaded cannot be submitted for parsing, and the system prompts that the file exceeds the limit. Cause: The `UPLOAD_FILE_MAX_SIZE` configuration value is lower than the actual size of the currently uploaded file.

## How to Verify Correct Configuration
- Upload a standard resource activation form PDF, and check if parsed chunks retain complete business field blocks including form titles, instance specifications, and permission configurations.
- Check system backend file parsing logs to confirm parsing time does not exceed the `PARSE_FILE_TIMEOUT_SECONDS` configuration value.
- Upload documents in different formats, such as Excel instance configuration sheets and Word account permission forms, to verify integrity and association of parsed data fields.
- Check the `UPLOAD_FILE_MAX_SIZE` configuration item to confirm test uploaded file sizes do not exceed the set threshold.
