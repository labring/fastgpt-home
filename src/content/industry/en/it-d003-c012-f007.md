# Security and Compliance Material Review for Cloud Network and Load Balancer Configuration: Conversation Logs and Auditing

## What data for this category includes
Core data for this category comes from cloud platform consoles, network topologies, traffic monitoring, and customer architecture diagrams. Daily associated documents include VPC plans, security group rules, load balancer configuration sheets, and change tickets.
Data updates occur per order or each configuration change. Core fields include session ID, operation time, cloud resource unique identifier, parameter values before and after configuration changes, and operator information.
Data structure centers on a single network configuration change. It only covers core content related to cloud network connectivity and traffic distribution.

## What constraints this category imposes on conversation logs and auditing workflows
This category’s data is tied to specific cloud network resources. Conversation logs must be linked to unique identifiers such as load balancer instances and security groups. Without this linkage, precise compliance review cannot be completed.
Data updates are grouped by single configuration changes. Auditing systems must aggregate logs by change ticket dimensions to avoid redundant or missing records.
Core fields focus on specific configuration change content. Logs must only retain information related to cloud network connectivity and traffic distribution, and filter out irrelevant content.
Auditing rules must adapt to the specific scenario of a single change.

## How to set up configurations
These configuration rules apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Log retention period | 30–90 days | Matches standard retention requirements for cloud network change tickets, aligns with compliance review cycle ranges |
| `chatId` binding rule | Attach cloud resource unique identifier as a suffix | Ensures each log is linked to a specific load balancer instance or security group configuration |
| Maximum single log length | 800–1200 characters | Adapts to log display and storage limits of cloud platform consoles |
| Log detail fields | Only retain configuration change content in `detail` | Focuses on core review goals for cloud network and load balancer configurations, filters out irrelevant information |
| Auditing trigger condition | Match configuration change operations | Covers the full process of every load balancer rule adjustment and security group rule update |
| `responseChatItemId` association rule | Bind change ticket number | Enables linkage verification between logs and offline change processes |

## Three common configuration errors
- Failing to bind cloud resource unique identifiers to `chatId` prevents retrieval of corresponding conversation logs via cloud resources. Not attaching additional identifiers as required by the `chatId` binding rule breaks the link between logs and actual cloud network resources.
- Not configuring the `responseChatItemId` and change ticket number association rule prevents matching audit logs to offline change processes. Without binding change ticket numbers, full-link verification cannot be completed in audit workflows.
- Interface operation buttons become unresponsive after triggering configuration change auditing, and logs show an empty `detail` field. Not configuring the rule to only retain configuration change content in the `detail` field causes log processing blockages due to redundant information.

## How to verify correct configuration
- Search for the `chatId` of a specified load balancer instance, confirm that corresponding conversation logs exist and are linked to the correct cloud resource identifier.
- Trigger a test security group rule change, check that audit logs are generated and include configuration change content in the `detail` field.
- Export a batch of audit logs, confirm that the format meets preset structured requirements.
- Cross-check auditing trigger conditions, confirm that logs are only generated during configuration change operations, with no redundant triggers.
