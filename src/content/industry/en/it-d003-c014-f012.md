# Security and Compliance Material Review for Cloud Resource Compliance Audit: Document Parsing and Chunking

## What the Data for This Category Looks Like
The data sources for this category are cloud audit logs, IAM, CMDB, and security baseline scan results, with an update frequency of monthly or quarterly. Commonly processed documents include compliance checklists, permission audit reports, resource lists, and rectification tracking forms. Most documents are in structured or semi-structured formats, containing fields such as resource identifiers, permission configuration items, compliance check results, and rectification tracking numbers. No custom dedicated units are used.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
Documents in this category come from diverse sources and have significant structural differences. Some are checklists with fixed headers, while others are resource lists in long list format. Parsing must adapt to different formatting rules to avoid missing key fields. Single document size may grow with cloud resource scale, so chunking parameters must be controlled to avoid exceeding context capacity limits. Update frequency is low, but parsing consistency for historical documents must be ensured. Chunking logic must adapt to common document structures in this category. Rectification tracking forms contain associated number and status fields. Chunking must retain contextual associations to prevent splitting associated information across fields.

## How to Configure Settings
For FastGPT v4.17.0, the following configuration items can be adjusted for this category scenario:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the long entries in cloud resource lists and paragraph lengths of compliance checklists, avoiding truncation of associated field combinations |
| `chunkSplitter` | Split by paragraph + title | Adapts to the diverse document structures in this category, retaining the association between headers and corresponding content |
| `customPdfParse` | Enabled | Accurately extracts structured tables and list content from PDFs exported from cloud platforms, avoiding missing critical data |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the size of large resource list documents updated quarterly, meeting single-document upload requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for large compliance reports, preventing parsing interruptions due to insufficient time |
| `chunkSettingMode` | Manual mode | Adjusts chunking parameters for different types of compliance documents, optimizing parsing and chunking effects |

## Three Common Mistakes
- After uploading a compliance PDF, there is no parsing completion prompt and search test results are empty. The cause is that `customPdfParse` is not enabled, so structured table content within the PDF cannot be extracted correctly.
- Some PDF files are recognized as empty. The cause is that the document size exceeds the `UPLOAD_FILE_MAX_SIZE` limit, or the parsing duration exceeds the value set in `PARSE_FILE_TIMEOUT_SECONDS`.
- Resource IDs and their corresponding permission configurations are separated after chunking. The cause is that `chunkSize` is set too small, truncating associated field combinations across paragraphs.

## How to Verify the Configuration Is Correct
- A typical cloud resource list PDF is uploaded, and the parsed text is reviewed to confirm full extraction of table columns and entry content.
- The largest single compliance document is uploaded, and the parsing process is checked for timeout errors.
- The `chunkSize` parameter is adjusted, and chunked text is compared to confirm retention of the association between resource identifiers and their corresponding compliance statuses.
- The `UPLOAD_FILE_MAX_SIZE` setting is reviewed to confirm it covers the size requirements of the largest document in the category.

The values given are common starting points and should be measured against the reader's own samples.
