# Security and Compliance Material Review for Enterprise Software License Management: Document Parsing and Chunking

## What this category’s data looks like
Data for this category primarily comes from software asset management systems, procurement systems, terminal scanning tools, and vendor authorization documents. Commonly processed documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Data is updated monthly or quarterly. Document structures combine structured tables and unstructured paragraphs. Core fields include software name, authorization number, authorized quantity, validity period, bound terminal identifier, and others. Some contract documents contain free-text paragraphs with inconsistent formatting.

## What constraints do these characteristics impose on the document parsing and chunking link
Mixed-format data from multiple sources requires parsing tools to support both structured tables and unstructured text, to avoid missing field extractions or splicing errors. Monthly or quarterly batch update requirements mean parsing workflows must support batch task scheduling and consistency checks. The correlation of core compliance fields must be preserved. Chunking must not break the binding relationship between authorizations and terminals, or between procurement contracts and authorization documents. Long paragraphs from large compliance audit reports and annual procurement contracts require reasonable control of chunk boundaries to prevent loss of complete business logic after splitting.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to both structured tables with short fields and unstructured contract paragraphs in documents of this category, balancing context completeness and retrieval accuracy |
| `chunkSplitter` | Split by paragraph + heading | Documents in this category include ledger tables, contract clauses, and audit report chapters. Splitting by paragraph + heading preserves the logical structure of the document and avoids splitting cross-chapter authorization descriptions |
| `customPdfParse` | Enable structured table parsing mode | A large number of documents in this category contain table data from license ledgers. Enabling this mode accurately extracts table fields and prevents incorrect splicing of table content |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to large files such as quarterly compliance audit reports and multi-terminal scanning lists imported in batches, meeting batch processing requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Reserves sufficient parsing time for large procurement contracts and complete annual compliance audit reports, avoiding parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Documents in this category have large format differences. Manual configuration allows adjusting chunking parameters for different document types, adapting to structured and unstructured scenarios |

## Three common misconfigurations
- After uploading a license ledger table, some authorization number and terminal identifier fields are empty. The structured table parsing mode of `customPdfParse` is not enabled, causing table cell content to be misjudged as plain text and split incorrectly.
- When batch importing quarterly software usage lists, parsing tasks return timeout errors. `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a sufficient duration, or `UPLOAD_FILE_MAX_SIZE` is set too small, causing large files to be truncated.
- After uploading a PDF file containing a screenshot of a vendor authorization letter, the text in the image is not parsed. The FastGPT built-in image OCR parsing plugin is not enabled, and the current configuration does not link the OCR processing workflow.

## How to confirm the configuration is complete
The following verification steps are based on FastGPT v4.17.0:
- Upload a single license ledger table, check that the parsed fields fully include core fields such as software name, authorization number, and validity period.
- Upload a compliance audit report containing multi-page tables and unstructured paragraphs, check that the chunking results preserve the association between chapter headings and corresponding paragraphs.
- Upload a single procurement contract with a size not exceeding 1000 MB, wait for parsing to complete and confirm there are no timeout errors.
- After enabling the image OCR plugin, upload a PDF file containing a screenshot of a vendor authorization letter, check that the text content in the image is correctly extracted and included in the chunks.

The values listed above are common starting points and should be evaluated against the reader's own samples.
