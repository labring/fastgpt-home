# Security and Compliance Material Review for Enterprise Software License Management: Permissions and Data Isolation

## What This Category of Data Entails
Core data sources for this category include software asset management systems, procurement systems, endpoint scanning tools, and vendor authorization documents. Daily maintained documents cover license ledgers, software usage lists, procurement contracts, and compliance audit reports.
Data updates occur monthly or quarterly. Core fields include authorized quantity, installed node count, expiration date, and the isolation-related `teamId` and `tmbId` fields.
The license ledger records the authorization scope and actual usage of individual software. Compliance audit reports summarize the enterprise-wide license compliance status. Access subjects for each document correspond to IT asset managers, procurement personnel, and legal compliance staff.

## Constraints on Permissions and Data Isolation
Data sources for this category are scattered across procurement, IT, legal and other departments. Access permissions for different subjects must be strictly separated to prevent cross-departmental unauthorized access to sensitive procurement contracts or compliance audit reports.
Data updates happen monthly or quarterly. Synchronize periodic data snapshots and bind them to corresponding permission scopes to avoid expired data leaks.
The core fields `teamId` and `tmbId` are used to distinguish teams and software historical versions. Apply real-time permission filtering based on these two fields. Without this, cross-team data access or missing historical version fields may occur.
Additionally, different document types have varying sensitivity levels. Assign permissions at the document granularity.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `teamId` | Bind the unique `teamId` of the internal enterprise team | Define the data isolation boundary for different teams' license data |
| `tmbId` | Generate a unique `tmbId` for each software historical version; automatically complete missing fields | Match the field specification of the MongoAppVersion table, fix missing historical version field issues |
| Permission check timeout threshold | No more than 500 milliseconds | Avoid data query delays impacting daily operations of IT asset managers |
| Data access granularity | Filter by individual license record | Minimize the impact of permission control on business processes |
| Data synchronization cycle | Execute monthly or quarterly | Match the actual update frequency of license data |
| Permission check trigger timing | Execute every time data is queried | Ensure real-time filtering of unauthorized cross-team access |

## Three Common Misconfigurations
- Missing fields in historical version data queries: The symptom is that earlier historical version documents in the MongoAppVersion table lack the `tmbId` field, leading to permission check failures. The cause is failure to automatically generate unique identifiers for historical versions with missing `tmbId` during data import.
- Permission check errors in on-premises deployments: The symptom is that after deploying with docker-compose, the MySQL service starts normally but related services report connection refused. The cause is failure to bind the correct database access permission scope via the `teamId` configuration, leading to incorrect inter-container permission isolation.
- Failed team member permission assignment: The symptom is that entering a team member account displays an invalid username. The cause is failure to synchronize team member data by `teamId` dimension, leading to failed cross-team permission checks.

## How to Confirm Configuration Completion
- View historical version documents in the MongoAppVersion table, confirm that each includes the `tmbId` field.
- Initiate a cross-team license data query, confirm that non-authorized teams cannot access corresponding data.
- Trigger a permission check operation, confirm that the check duration does not exceed the preset 500 millisecond threshold.
- Test adding a team member, confirm that entering a valid account allows normal assignment of corresponding permissions.
