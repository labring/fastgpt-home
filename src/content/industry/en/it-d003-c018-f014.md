# Security and Compliance Material Review for Enterprise Software License Management: Model Integration and Configuration

## What data for this category includes
This category’s data comes primarily from software asset management systems, procurement systems, endpoint scanning tools, and vendor authorization documents. Daily output documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Data fields include authorization number, authorized quantity, installed node count, expiration date, and others. Units include units, copies, days, and similar measures. Most data updates occur monthly or quarterly. Some core compliance audit reports are updated quarterly.

## Constraints on model integration and configuration
This category has many data fields and complex associated relationships. Models must accurately match core fields such as authorized quantity and installed node count. Prioritize output accuracy during model integration. Data update frequency is low, so real-time processing for high-frequency incremental data is not required. Compliance reviews carry audit penalty risks. Model calls must follow parameter constraints strictly to avoid incorrect outputs. Data formats vary across sources. Adaptations are needed for parsing multiple document types.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Set as an environment variable for the App/Admin server. Use the root address of the AI Proxy service as the value, for example `http://aiproxy:3000`. Do not fill in single-model service addresses such as VLLM/Ollama/Xinference | Complies with FastGPT v4.17.0 official environment variable requirements; no additional path suffixes are needed |
| `AIPROXY_API_TOKEN` | Set as an environment variable for the App/Admin server. Use the administrator token matching the AI Proxy server configuration as the value. Do not use application API keys, model vendor keys, or tokens issued per application as substitutes | Meets official mandatory validation requirements; variable values cannot be empty |
| `temperature` | `0.1–0.3` | Ensures output accuracy for compliance reviews, and avoids irrelevant or incorrect field matching |
| `maxContext` | `8000–12000 characters` | Adapts to the context requirements of this category’s multi-field, multi-document associations |
| `vision` | Enabled | Supports parsing scanned format compliance materials such as vendor authorization documents |
| `maxTokens` | `2000 characters` | Controls single-round output length to avoid exceeding format requirements for compliance reports |

## Three common configuration errors
- Service startup validation failures or model call errors happen when `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` environment variables for the App/Admin server are not set correctly. This prevents normal calls to the AI Proxy service.
- Entering the AI Proxy administrator token into the application API key field during configuration. This stems from confusing server environment variables and application authentication parameters, and violates official configuration rules.
- Failing to confirm upstream model support for visual parsing capabilities after enabling `vision`. This prevents scanned format authorization documents from being parsed normally.

## How to verify successful configuration
- Check the App/Admin server’s environment variable configuration. Confirm `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly set and not empty.
- Initiate a test call to verify the model can return field matching results for compliance materials normally, with no error prompts.
- Review AI Proxy service logs to confirm there are no connection failure or authentication failure records.
- Test parsing compliance documents in both text and scanned formats to verify the `vision` configuration works as expected.
