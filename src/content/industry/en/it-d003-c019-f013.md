# Security and Compliance Material Review for Crowdsourced Annotator Management: Permissions and Data Isolation

## What data looks like for this category
This category of data primarily comes from crowdsourcing platform backends, annotation quality reporting systems, personnel training assessment records, and financial settlement systems. Daily maintained documents include personnel access rules, pre-job training materials, monthly performance ranking tables, and settlement reconciliation checklists. Data update frequencies are mostly daily (for annotation quality and performance data) or monthly (for personnel changes and settlement data). Data fields include unique personnel identifiers, access review status, training assessment scores, single annotation task volume, settlement amount, and more, with corresponding units varying by document type.

## Constraints on permissions and data isolation
Data sources are scattered and involve multiple types of sensitive information. Isolate access permissions for different sources to prevent non-quality inspection personnel from tampering with annotation quality data, and unauthorized viewing of financial information such as settlement lists. Personnel access rules and training materials are internal management documents. Differentiate access levels between new hires, formal annotators, and project supervisors. Daily updated annotation quality and performance data require real-time permission checks to avoid permission vulnerabilities caused by delays. Personnel status is updated daily. Support fast permission adjustments to adapt to daily personnel changes.

## Configuration settings
These configurations are formulated based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Assign a unique identifier to each annotation project | Precisely divide personnel and data boundaries between different projects to avoid cross-project data leakage |
| `tmbId` | Bind fixed identifiers by personnel role | Quickly differentiate access levels between annotators, quality inspection leads, and project supervisors |
| Data resource isolation scope | Divide access permissions by document type | Annotators can only access assigned task materials, while supervisors can access all management documents |
| Permission change synchronization cycle | Complete synchronization within 10 minutes | Adapt to daily updated personnel status and annotation data to avoid permission lag |
| Financial data access restriction | Only designated roles can view | Protect sensitive financial information such as settlement lists to comply with internal management requirements |

## Three common misconfigurations
- Symptom: The test-deployed program prompts insufficient permissions and fails to load annotation data. Cause: Personnel permissions for the corresponding project were not bound via `teamId`, resulting in cross-project access being blocked.
- Symptom: Team members cannot view settlement list data. Cause: Exclusive access permissions for financial data were not configured, and only public resources were open by default.
- Symptom: Permissions for new hire annotators are not updated in a timely manner. Cause: The permission change synchronization cycle was set too long, failing to adapt to daily updated personnel status data.

## How to verify successful configuration
- Log in to accounts with different roles and verify that only documents and data within the corresponding permission range can be accessed.
- Submit a permission change request and confirm that it takes effect within the set synchronization cycle.
- Attempt to access data across projects and verify that it is blocked by the permission rules corresponding to `teamId`.
- Test access to financial data and confirm that only designated roles can view settlement lists.

The values provided are common starting points and should be measured against the reader's own samples.
