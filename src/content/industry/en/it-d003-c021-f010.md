# Security and Compliance Material Review for Supply Chain Security and Open Source Dependency Governance: Citation Sources and Traceability

## What this category of data looks like
Data for this category primarily originates from package managers, code repositories, public vulnerability databases, and license databases. Updates occur daily or with each version release. Routine output documents include SBOM lists, dependency risk reports, license lists, and repair tickets. Fields include third-party component name, version number, license type, associated vulnerability identification numbers, and more. There is no fixed unified format template, and each data source has minor field differences.

## What constraints do these characteristics place on the citation sources and traceability link
Data sources for this category are scattered, and fields vary between sources. The citation traceability process must connect multiple data sources such as package managers and vulnerability databases. This avoids missing information from single data sources. Data updates occur at a high frequency. The traceability process must support real-time pulling of the latest dependency components and vulnerability information. This ensures the timeliness of compliance reviews. Field differences in third-party component documentation require traceability matching to use the exact combination of component name and version number as the core. This prevents incorrect associations caused by fuzzy matching. Additionally, documents such as SBOM lists have large content sizes. The traceability process must reasonably limit the token usage of citations.

## How to configure settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | Matches the typical content length of SBOM lists and dependency risk reports, avoids truncating critical traceability information |
| `responseData` | Enable citation source field | Ensures returned results include data source identifiers for component sources, corresponding to associated information from vulnerability databases and license databases |
| `detail` | Enable detailed traceability mode | Displays complete license types and vulnerability repair status for components, matches the detailed requirements of compliance reviews |
| Maximum number of citations | Top 5 | Avoids excessive citations causing redundant results, focuses on compliance information for core dependency components |
| Real-time data source synchronization | Triggered by update frequency | Matches the daily or per-version update rhythm of data in this category, ensures timeliness of traceability information |

## Three common configuration errors
- Phenomenon: Returned answers have no connection to knowledge base citation content, and citation fields point to unrelated components. Cause: Did not use the exact combination of component name and version number as the matching condition, only used keyword matching leading to incorrect associations.
- Phenomenon: Cannot display detailed information of citation sources after configuration. Cause: Did not enable the `detail` parameter, or did not correctly configure the enable switch for `responseData`.
- Phenomenon: Timeout errors occur in the traceability process. Cause: Did not set a reasonable value for `quoteMaxToken`, causing token usage for a single citation to exceed system limits.

## How to confirm successful configuration
- Check system logs, confirm that returned results include the `responseData` field, and that the field content includes data source identifiers for component sources.
- Enter a query that includes a known third-party component name and version number, verify that the returned citation sources match the corresponding package manager or vulnerability database information.
- Test queries related to high-risk dependencies, confirm that the `detail` parameter is enabled and displays complete license types and vulnerability repair status.
- Adjust the value of `quoteMaxToken`, verify that the returned citation content does not show truncation.

The provided configuration values are common starting points, and should be evaluated against individual user samples.
