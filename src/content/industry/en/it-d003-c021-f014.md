# Security and Compliance Material Review for Supply Chain Security and Open Source Dependency Governance: Model Access and Configuration

## What Data Looks Like for This Category
Data for this category primarily comes from package managers, code repositories, public vulnerability databases, and license databases. Daily generated documents include SBOM lists, dependency risk reports, license lists, and repair tickets. Fields cover third-party component names, version numbers, license types, vulnerability IDs, repair status, and additional relevant details. Data updates occur daily or upon each software version release. Asset information, vulnerability status, and license compliance for different components are synchronized with upstream sources.

## Constraints Imposed on the Model Access and Configuration Workflow
This content is written based on the configuration logic of FastGPT v4.17.0. Multi-source heterogeneous data formats require model access to adapt to input parsing rules for different structures, and support multiple document types including package management metadata, vulnerability reports, and license text. The content volume of SBOM and risk reports increases with project scale. It is necessary to limit context length and single-generation token count to avoid exceeding model capacity limits. Accurate vulnerability matching and license compliance verification require stable output formats, so generation randomness must be controlled. Daily ticket processing and asset inventory require the model to call tools stably. Configure the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables on the FastGPT App/Admin server to ensure routing and identity validity for model calls, and prevent task interruptions caused by unstable connections or authentication failures.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–16000 token` | Adapts to the context length after splicing multiple documents such as SBOM and vulnerability reports, and avoids exceeding model capacity limits |
| `maxTokens` | `2000–4000 token` | Limits the length of compliance review and vulnerability analysis results generated in a single run, and prevents redundant output or truncation |
| `temperature` | `0.1–0.3` | Ensures output consistency for vulnerability matching and license compliance judgments, and avoids rule misjudgments caused by randomness |
| `toolChoice` | `auto` | Automatically triggers tool calls such as dependent asset identification and vulnerability query, and adapts to multi-step governance workflows |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service (for example, `http://aiproxy:3000`; do not append paths such as `/v1` or `/chat/completions`). Must match the actual deployed AI Proxy service address | This environment variable is required for the FastGPT App/Admin server, ensures that model requests are correctly routed to the AI Proxy service, and adapts to private deployment requirements for supply chain security scenarios |
| `AIPROXY_API_TOKEN` | Administrator token matching the AI Proxy server configuration, and cannot be empty | This environment variable is required for the FastGPT App/Admin server, ensures identity validity for API calls, and prevents unauthorized access |

## Three Common Misconfigurations
- Symptom: A `429 Too Many Requests` error with the message "Current group upstream load is saturated, please try again later" appears after configuration. Troubleshooting steps: Check whether model concurrent call limits are not set, whether the proxy service request quota is exhausted, or whether the FastGPT server fails to start or experiences service exceptions due to incorrect configuration of the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables.
- Symptom: Component fields in SBOM lists cannot be extracted correctly, and some key version information is missing. Troubleshooting steps: Check whether structural differences of multi-source documents are not adapted, or whether the `maxContext` configuration is insufficient, causing key information to be truncated.
- Symptom: Random deviations appear in license compliance judgment results, and different conclusions are generated for the same input across multiple runs. Troubleshooting steps: Check whether the `temperature` parameter is set too high, causing inconsistent judgment logic generated by the model.

## How to Confirm Successful Configuration
- Upload a single SBOM list, verify whether the component list output by the model matches the fields in the original document, and adjust configuration items until the extraction results are complete.
- Initiate a batch vulnerability matching test, check whether tool calls are automatically triggered and return correct risk levels, and confirm that the `toolChoice` configuration takes effect.
- Verify that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables are correctly configured on the FastGPT App/Admin server, check whether the service startup verification passes, and avoid authentication or routing errors. The `AIPROXY_API_ENDPOINT` must be the root address of the AI Proxy service (for example, `http://aiproxy:3000`; do not append paths such as `/v1`). The `AIPROXY_API_TOKEN` must match the AI Proxy server configuration.
- Adjust the `temperature` parameter, compare the outputs of two identical input runs, and confirm that the consistency of generated results meets expectations.
