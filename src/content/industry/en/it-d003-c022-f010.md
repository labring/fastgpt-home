# Secure and Compliance Material Review for Trusted Innovation Replacement Adaptation: Citation Sources and Traceability

## What the data for this category looks like
The core data for this category is produced and maintained by enterprise IT architects, localization project teams, and system integrators. Daily documents include adaptation lists, compatibility test reports, migration plans, and issue logs. Data sources cover existing system inventories, official directories of domestic hardware and software, local test environment records, and publicly available materials from hardware and software vendors. Data updates follow individual project cycles, with some general adaptation documents refreshed quarterly. Individual documents contain fields such as system model, hardware and software version, compatibility conclusion, and test results. There are no unified mandatory unit requirements, and adjustments should be made flexibly based on document type.

## What constraints these characteristics impose on the "citation sources and traceability" link
The data sources for this category are scattered and diverse in type, so the traceability function must support associating metadata from multiple data sources to ensure cited content can be traced back to the original document. Update frequencies are not fixed, so an automated refresh or manually triggered traceability update mechanism must be configured to avoid citing outdated adaptation information. Document structures and fields vary significantly, so support is needed for matching citation rules by document type, while also supporting traceability display for different fields. Individual documents have high length and content complexity, so the length of a single citation must be limited to avoid exceeding model context limits. Errors directly impact project delivery, so traceability information must be auditable to ensure compliance reviews can be traced.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average single-paragraph length of adaptation documents, to avoid truncating critical compatibility conclusions or test data |
| Maximum number of knowledge base citations | Top 3–5 entries | The number of adaptation documents per project is limited. Too many citations will interfere with model judgment and reduce response speed |
| `responseData` | Enable full traceability fields | Must fully record metadata such as citation document source and update time to meet compliance review requirements |
| `detail` | Enable detailed citation markers | Clearly mark the position of cited content in the original document to facilitate subsequent verification |
| Maximum context | `2000–3000 characters` | Adapts to the core content length of a single migration plan or compatibility test report, to avoid exceeding model capacity limits |

## Three common configuration mistakes
- Symptom: Unparsed `\n` characters appear in responses after configuring `quoteMaxToken`. Cause: The text formatting switch is not enabled, so line breaks are retained as plain characters and cannot be displayed normally.
- Symptom: Returns empty results or critical information is truncated when the number of citations exceeds the set limit. Cause: No overflow handling logic is configured for `responseData`, so complete traceability information cannot be returned normally when the `quoteMaxToken` limit is exceeded.
- Symptom: Response timeout errors occur when the maximum number of knowledge base citations is set too high. Cause: The single-length nature of adaptation documents is not considered. Too many citations will exceed the context capacity limit of FastGPT v4.17.0, resulting in a timeout.

## How to confirm the configuration is complete
- Upload a single adaptation list document, initiate a test that includes compatibility queries, and check whether the response includes clear source document identifiers and citation positions.
- Adjust the `quoteMaxToken` parameter to different ranges, and verify that cited content from long documents is complete, with no truncation or garbled characters.
- Simulate a multi-document scenario, check whether the number of returned citations matches the set value range, with no abnormal overflow.
- View system logs to confirm that metadata for traceability information (such as document source and update time) has been fully recorded and can be used for compliance verification.

The values provided are common starting points and should be measured against the reader's own samples.
