# Security and Compliance Material Review for Informatization Budget and Project Portfolio Management: Permission and Data Isolation

## What data looks like for this category
Core data for this category originates from financial systems, project management systems, contract ledgers, and business department requirements. Daily outputs include annual budget sheets, project initiation documents, project portfolio dashboards, and investment review reports. Data fields include project numbers, budget amounts, priority markers, revenue review data, and other items. Update cycles are monthly, quarterly, or annually. Single document sizes typically range from thousands to tens of thousands of characters. Field overlaps and relational links exist across different documents. Trained knowledge base content must be stored in the tenant database table associated with `teamId`. Consult official documentation for specific storage paths and export methods.

## What constraints do these characteristics impose on permission and data isolation
Data sources are scattered across multiple independent systems. Imported datasets must be isolated by source to avoid cross-contamination between data from different systems. Documents contain sensitive decision-making information such as budget amounts and project priorities. Permission scopes must be divided by user role to prevent unauthorized access to core data. Update cycles are monthly, quarterly, or annually. Batch updated datasets must be bound to corresponding permission groups to ensure only authorized roles can access documents from the matching cycle. Project portfolio dashboard data generated through cross-department collaboration must isolate exclusive data from different business departments to prevent data leaks and misuse across departments.

## How to configure settings
For local deployment scenarios, enable team version configuration first, then complete the following permission and data isolation settings. All configurations below are written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind to the team ID of the corresponding project group | Matches the business scenario of dividing budget and project data by project group for this category |
| `tmbId` | Update tenant data isolation identifier quarterly | Adapts to the monthly/quarterly/annual update cycle of this category, avoiding cross-cycle data confusion |
| Role permission scope | Split permission intervals by CIO, PMO, and financial BP; permission value ranges match role access permissions | Aligns with the responsibility boundaries of typical user roles, preventing sensitive data leaks |
| Dataset access validity period | Configure as 7–30 day temporary access permissions | Adapts to the monthly/quarterly document update cycle, avoiding long-term retention of unauthorized access entry points |
| Cross-department data isolation | Enable department-level data sharding | Meets cross-department collaboration requirements for project portfolio dashboards, isolating exclusive data from different business departments |

## Three common configuration errors
- Symptom: Imported financial system data and project management system data show cross-contamination, and some budget data is accessed by non-corresponding project groups. Cause: The `teamId` configuration is not bound, and datasets are not isolated by project group.
- Symptom: After permission configuration, financial BPs cannot view budget sheets for the current quarter, and the interface returns empty fields. Cause: The `tmbId` configuration does not match the tenant identifier for the current update cycle, resulting in data not being correctly associated with the permission group.
- Symptom: Cross-department project portfolio dashboards display unauthorized business department data, creating decision risks such as duplicate project construction. Cause: Cross-department data isolation configuration is not enabled, and data sharding is not divided by business department.

## How to confirm successful configuration
- Log in to the FastGPT backend, view the dataset list corresponding to `teamId`, confirm that it only contains budget and project documents for this project group. The association between data and permissions can be verified via the official permission database relationship diagram.
- Switch between different role accounts, confirm that only documents within the corresponding responsibility scope are visible, and unauthorized data cannot be accessed.
- Upload a quarterly updated budget sheet, confirm that the system automatically binds the current `tmbId` and associates it with the corresponding permission group.
- View the data source configuration of the cross-department project portfolio dashboard, confirm that department-level data isolation is enabled, and only project data within the authorized scope is displayed.
