# Security and Compliance Material Review for In-feed Advertisement Creative Testing: Conversation Logs and Auditing

This configuration is based on FastGPT v4.17.0, and adapts to the security and compliance auditing needs of in-feed advertisement creative testing.

## What the Data for This Category Looks Like

The data for this category comes from advertising platforms, internal material libraries, user interaction data, and conversion data. Daily produced documents include creative scripts, material test sheets, delivery data reports, and iteration checklists. Update frequency is mostly daily or weekly. Data fields include creative material type, copy content, delivery time slot, test variables, conversion indicators, and more. Common units are number of materials, impressions, clicks, and conversion cost. This work focuses on creative combination testing for in-feed advertisements, with core focus on delivery effects and compliance review of different graphic, video, and copy combinations.

## Constraints on Conversation Logs and Auditing

Data sources for this category are scattered, including external advertising platforms and internal business systems. Conversation logs and auditing must support multi-source data formats to avoid traceability failures caused by field mismatches. Update frequency is mostly daily or weekly. The auditing process must support batch log retrieval on a daily or weekly basis to align with the team’s creative test iteration rhythm. Daily documents revolve around creative testing. Logs must be associated with version information of corresponding documents to facilitate traceability of specific compliance review bases. The core focus is compliance of creative combinations. Auditing must cover full process records of material compliance checks and delivery rule matching involved in conversations. It must also support log filtering by dimensions such as creative variables and delivery time slots to improve efficiency of summarizing test conclusions. Missing or incomplete logs will directly lead to inability to trace non-compliant materials, triggering business risks such as reduced click-through rates and increased costs.

## How to Configure the Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Log Retention Period | 30–90 days | Matches creative test iteration cycles and compliance traceability requirements |
| `chatId` Association Switch | Enabled | Binds individual test conversations to corresponding creative variable records, facilitating log filtering by test task |
| `detail` Log Switch | Enabled | Fully records compliance check details in conversations, covering the full process of material compliance review |
| Audit Log Filter Dimensions | By delivery time slot, creative type | Aligns with daily document summarization habits based on test cycles and material categories |
| Log Export Format | CSV format | Compatible with delivery data report processing tools, facilitating integrated analysis |
| `responseChatItemId` Association Switch | Enabled | Binds conversation replies to corresponding compliance check results, facilitating traceability of non-compliance judgment basis |

## Three Common Misconfigurations

- Symptom: After calling an advertising platform interface, the corresponding record does not appear in the conversation logs, even though the call completed successfully. Cause: The `detail` log switch is not enabled. Only basic session information is recorded, and detailed logs of interface calls are not captured.
- Symptom: A 503 error is prompted when uploading a creative script or material test sheet on the conversation page. Background logs show the file upload was successful. Cause: The front-end request timeout threshold is set too short, while background file processing takes a long time. This leads to a front-end timeout error even though the upload completed in the background.
- Symptom: When attempting to update the number of creative test calls via variables, no corresponding count record appears in the logs. Cause: No log trigger rule is configured for variable updates. Variable modification operations are not included in the audit log scope.

## How to Verify Successful Configuration

- Initiate a creative compliance check conversation. Check for the presence of the session record for the corresponding `chatId` in the log list.
- Export the log file. Confirm that the format is CSV and that compliance check details under the `detail` field are included.
- Simulate uploading a creative script. Check for a 503 error on the front end, and confirm that background log upload records match front-end prompts.
- After configuring variable update rules, initiate a test call. Confirm that the log includes records of variable modifications.
