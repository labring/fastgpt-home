# Security and Compliance Material Review for Duty Scheduling and Handover: Model Access and Configuration

## What data for this category looks like
Data for this category comes from scheduling systems, fault tickets, monitoring alerts, and organization contact lists. Update frequency is daily or weekly. Daily produced documents include duty schedules, handover records, escalation contact lists, and daily duty reports. Duty schedules contain fields for date, duty personnel, and duty time slots. Handover records mark open items and pending faults. Escalation contact lists list contact methods by job role. Daily duty reports summarize daily alerts and handling statuses. Data structure varies slightly based on operational teams' scheduling rules, with core fields focused on duty responsibilities and task flow.

## What constraints these characteristics impose on model access and configuration
Data sources are scattered and update cycles are flexible. Model access must support batch synchronization and incremental updates across multiple data sources, to avoid excessive resource usage from full pulls. Daily document fields lack unified standards. Configure parsing rules adapted to multi-format text, to ensure accurate recognition of time slot fields in duty schedules and open item tags in handover records. Differences in update frequencies require configurable custom sync cycles, to accommodate daily duty reports and weekly escalation contact lists. Data is tied to operational response timelines. Model calls must guarantee low latency, to avoid disrupting scheduling conflict coordination and handover processes.

| `toolChoice` | auto | Allows the model to automatically choose whether to call tools for tasks such as scheduling conflict coordination and handover item verification |

## Three common mistakes
- Symptom: Startup verification fails when deploying the App/Admin service locally. Troubleshoot by checking if `AIPROXY_API_ENDPOINT` is configured correctly, and confirming connectivity to the AI Proxy service.
- Symptom: Model calls cannot associate the specified duty schedule file. Cause: No reasonable value set for `maxContext`, leading to context truncation and inability to read the full content of the specified file.
- Symptom: Generated compliance review results contain large amounts of irrelevant content. Cause: `temperature` is set to an overly high range, leading to excessive model output randomness and deviation from fixed compliance review rules.

## How to confirm configuration is complete
1. Access the `AIPROXY_API_ENDPOINT` configured on the server, verify the returned interface status code is 200, to confirm normal connectivity.
2. Upload a standard duty schedule document, trigger a model review task, check that the returned results include core fields such as duty personnel and duty time slots, to confirm normal context reading.
3. Adjust the `temperature` parameter to the 0.1 range, initiate multiple test calls, observe consistency of output results, to confirm randomness meets expectations.
4. Configure an incremental sync task, set the sync cycle to 1 day or 7 days, wait one cycle and check the data sync logs, to confirm newly generated daily duty reports have been correctly loaded.
