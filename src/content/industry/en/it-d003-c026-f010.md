# Security and Compliance Material Review for Level Content Creation: Citation Sources and Traceability

## What data looks like for this category
Typical data for this category comes from level editors, art resource libraries, player test data, and defect systems. Daily outputs include level design documents, resource requirement sheets, test feedback forms, and version submission records. Level design documents contain fields such as path nodes, trigger conditions, and bound resource IDs. Resource requirement sheets mark resource type, quantity, and delivery deadlines. Test feedback forms record stuck positions and feedback times. Version submission records include submitter, version number, and modification content. Data updates follow a weekly or per-version submission cycle. Each document is strongly tied to a specific level instance, and some documents include unique identifier fields.

## What constraints these characteristics impose on citation sources and traceability
Data is scattered across multiple independent systems. Traceability systems must support indexing integration with multiple data sources to avoid missing data. Documents are strongly tied to specific level instances and include unique identifiers. This means traceability results must be linked to corresponding level nodes or resources, and cannot return generalized content only. The weekly or per-version update cycle requires index update cycles to match submission nodes, ensuring data timeliness. Errors directly affect level playability and launch progress. As such, the accuracy and completeness of traceability must meet compliance review requirements. Mismatching or truncation of key information is not allowed.

## How to set up configurations
This setup applies to FastGPT v4.17.0. Specific configuration items are listed below:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single documents for this category, avoids truncating key information such as level paths and resource bindings |
| `responseData` | Associate level ID and resource ID fields, return the correct unique identifier {{id}} | Ensures traceability results are directly bound to specific level nodes or art resources, enables quick location of review targets, and matches usage requirements for citation IDs |
| `detail` | Enable full traceability | Retains complete modification traces of test feedback forms and version submission records, meets traceability requirements for compliance reviews |
| Data source classification rules | Configure classification by level editor and art resource library | Distinguishes data indexes from different sources, prevents cross-category data from mixing into current level review tasks |
| Index update trigger timing | Trigger on version submission nodes | Matches the weekly or per-version update cycle of this category, ensures newly submitted level data can be indexed in a timely manner |
| Single recall limit | Top 6 entries | Matches the information density of a single round of review, avoids excessive redundant data interfering with reviews |

## Three common misconfigurations
- Phenomenon: Non-current level resource data appears in citation traceability results. Cause: No association rule between data sources and level IDs is configured, leading to cross-system data confusion.
- Phenomenon: Temperature parameter cannot be adjusted when using variable reference mode. Cause: Some interface configuration items do not retain the original parameter entry after switching to variable reference mode. Adjustments must be made via global configuration synchronization.
- Phenomenon: Multi-turn conversation context cannot be correctly referenced to the current level review task. Cause: The switch for binding conversation history to level context is not enabled, so traceability does not link to the current task's conversation chain.

## How to confirm configurations are correct
- Manually import a test level design document, trigger citation traceability, and check if the returned results only include associated data for that level.
- Adjust the `quoteMaxToken` parameter, then verify if the truncation length of recalled content matches the expected setting.
- Submit a version update, then confirm that the index automatically refreshes after submission is complete, and new data can be properly traced.
- Switch to variable reference mode, confirm that the temperature setting entry is still accessible and can be used to adjust parameters.

The values provided are common starting points and should be measured against the reader's own samples.
