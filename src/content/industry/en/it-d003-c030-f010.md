# Security and Compliance Material Review for Internal Network and WiFi Operations: Citation Sources and Traceability

## What Data for This Category Looks Like
The data for this category primarily comes from switch consoles, wireless controllers, office network monitoring systems, and user trouble reporting channels. Daily produced documents include network topology diagrams, change tickets, fault records, and wireless coverage inspection reports. Teams update data daily or synchronize it immediately following network changes. Document fields include port numbers, VLAN identifiers, wireless signal strength, connected device counts, and other relevant metrics. Units include dBm, units, pieces, and others. No unified standardized format exists, and teams adjust configurations flexibly based on operation and maintenance scenarios.

## What Constraints These Characteristics Impose on Citation Sources and Traceability
Data for this category is scattered across multiple operation and maintenance systems. Citation traceability requires associating device identifiers and records from different systems, which increases cross-source matching complexity. Data updates follow no fixed cycle, so traceability results must match the latest network change records. This avoids citing outdated topology or inspection data. Document formats vary: some use structured change ticket fields, while others include unstructured topology diagram text. Teams must support different content splitting and display logic. Additionally, citations in operation and maintenance scenarios must tie to specific faults or change events. Relying solely on generalized knowledge base associations will not support fault location or compliance audit requirements.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Citation Visibility Settings | Differentiate by workflow node | Aligns with operation and maintenance team role permission divisions. Only grant full source view permissions to fault troubleshooting staff. |
| Maximum Citation Token Count | 800–1200 token | Uniformly control cited content length to avoid truncating key operation and maintenance information such as ports and VLANs. |
| Context Recall Limit | Top 5 entries | Covers the range of common documents used in daily inspections and fault troubleshooting. Prevents redundant data from interfering with query results. |
| Citation Source Display Format | Classify by document type | Differentiates display styles for different documents such as network topology diagrams and change tickets. Facilitates quick location of target content. |
| Citation Details Toggle | Enable/disable by scenario | Controls whether to display full cited content details. Adapts to viewing needs for different operation and maintenance roles. |
| Associated Data Toggle | Enable device identifier association | Ensures search results tie to specific switch and wireless controller numbers. Meets precise traceability requirements. |

## Three Common Configuration Errors
- Symptom: After configuring citation visibility settings, external on-site personnel can still view full source text. Cause: Only the global visibility switch was adjusted. Node-level permission configuration based on operation and maintenance roles was not completed.
- Symptom: Some network topology diagrams directly include original text when generating cited content. No structured association information is generated. Cause: Adapted chunking rules were not configured for unstructured topology diagram documents. The splitting logic fails as a result.
- Symptom: An interface error prompts when testing the citation traceability function. Cited content displays normally during formal operation. Cause: The call timeout threshold was set too strictly during the test phase. It does not match the model interface parameters used in formal operation.
