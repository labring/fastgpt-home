# Security and Compliance Material Review for Internal Network and WiFi Operations: Document Parsing and Chunking

## What the data for this category looks like
This category’s data comes primarily from switch consoles, wireless controllers, monitoring systems, and frontline user trouble reporting channels. Daily processing covers network topology diagrams, change orders, fault records, and wireless coverage inspection forms. Data updates occur daily or immediately after network changes. Most document structures include fields such as device numbers, port configurations, VLAN information, and signal strength parameters. Some documents include visual topology graphics and tabular inspection data.

## What constraints these characteristics impose on document parsing and chunking
Command line logs from switch consoles follow a standardized format but include many professional abbreviations. Wireless coverage inspection forms are multi-column numerical tables. Network topology diagrams are mostly PDF documents with vector graphics. Teams must parse frequently updated change orders and fault records quickly to avoid delaying operation and maintenance responses. The mixed multi-format document types require the parsing process to support text, tables, and vector graphic content. Key fields such as device numbers and VLAN IDs have strong correlations. Chunking processes must retain context association between adjacent fields to prevent critical configuration information from being split apart.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the information density per chunk of documents such as inspection forms and change orders, preventing critical configuration fields from being split |
| `chunkSplitter` | Split by paragraph + title | Matches the hierarchical structure of network documents, retaining context associations such as topology descriptions and change reasons |
| `customPdfParse` | Enable vector text extraction mode | For PDF documents such as network topology diagrams, fully extract device annotations and configuration text attached to graphics |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatibility with batch-imported inspection reports and historical fault record documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Meets the parsing time requirements for large topology diagrams and multi-page fault record documents |
| `chunkSettingMode` | Manual configuration mode | For the non-general structure of documents in this category, flexibly adjust chunking rules to retain key associated information |

## Three common configuration mistakes
- Symptom: An unsupported format error appears when uploading Excel-format inspection forms or change orders. Only two columns of data remain after importing a CSV file. Cause: Custom parsing configuration for table documents is not enabled, and default parsing rules have insufficient adaptability for multi-column structured data.
- Symptom: The PDF parsing service deployed in a Docker environment throws a connection failure error. Testing with the local address 127.0.0.1 fails to connect. Cause: The parsing service port inside the container is not correctly mapped, or the container network policy restricts local loopback access.
- Symptom: Parsed chunk content loses association between device numbers and port configurations. Critical fault location information is split into different chunks. Cause: The chunking parameter is set too short, failing to retain context association between adjacent fields.

## How to verify correct configuration
- Teams can upload a typical wireless coverage inspection form and check the parsed text to confirm full retention of all column fields and numerical data.
- Teams can import a small network topology diagram PDF and verify that the parsed result includes key information such as device annotations and connection descriptions.
- Teams can adjust the `chunkSize` parameter, compare chunking results across different values, and confirm that critical configuration fields are not split across chunks.
- Teams can upload a single document of the maximum allowed size for testing and confirm that no timeout error occurs during the parsing process.

The values listed here are common starting points, and should be evaluated against the organization’s own samples.
