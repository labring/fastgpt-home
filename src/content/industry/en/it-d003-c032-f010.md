# Security and Compliance Material Review for Creator Incentive Settlement: Citation Source and Traceability

## What This Category of Data Looks Like
Daily documents for this category include incentive rules, settlement details, appeal records, and payment lists. Data sources cover content data, advertising revenue sharing systems, financial systems, and account backends. Most updates run on a monthly basis or within a single campaign cycle. Fields typically include creator identifiers, revenue metrics, payment statuses, appeal reasons, and similar items. Most documents use structured table formats, while some rule documents are plain text. Data updates are mostly triggered in batches, with no real-time high-frequency update scenarios.

## What Constraints Do These Characteristics Impose on the Citation Source and Traceability Link
The multi-source data requirements of this category mean the traceability link must associate documents from different systems, to ensure cited content matches records from actual business systems. The non-real-time batch update rhythm requires the knowledge base refresh cycle to align with business update frequencies, to avoid citing expired incentive rules or settlement data. Structured document fields require precise matching of corresponding fields during traceability, to avoid confusing settlement data from different creators or different cycles. Additionally, error consequences directly relate to settlement disputes and incorrect or missed payments, so cited sources must be verifiable, ensuring the basis for each settlement can be traced.

## How to Configure Settings
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single documents such as settlement details and incentive rules, to avoid truncating key structured fields |
| `responseData` | Return only core business fields | Limits returned content to settlement-related items including creator ID, settlement cycle, payment amount, and similar details, filtering out irrelevant fields |
| `detail` | Enable traceability detail display | Shows the source system and update time of cited documents, to facilitate verification of timeliness and compliance of sources |
| Single search limit | Top 5 results | Matches the volume of associated data for monthly batch settlements, to avoid overloading from recalling too many historical documents |
| Maximum context | Calibrated via actual testing | Adapts the stitching length of multi-system documents, ensuring the model can fully process associated business data |

## Three Common Configuration Mistakes
- Setting `quoteMaxToken` too small: Settlement detail documents will be truncated, and key revenue metric fields will be missing from cited content displayed in the interface. This occurs because the setting does not match the average length of category documents, and does not reserve enough tokens to carry structured fields.
- Failing to limit the return scope of `responseData`: The knowledge base will return historical appeal records unrelated to the current settlement, leading to irrelevant results during queries. This occurs because no field filtering is performed for the category's structured data, recalling documents from non-current settlement cycles.
- Failing to enable the `detail` configuration: The update time of cited documents cannot be viewed. When settlement rules are updated without synchronizing the knowledge base, continuing to use old rules to calculate revenue will lead to disputes. This occurs because the document update time is not linked to the category's monthly update rhythm, making timeliness verification impossible.

## How to Confirm the Configuration Is Correct
- Submit a test query containing specified settlement cycle keywords, check whether returned cited documents include settlement detail fields for the corresponding cycle.
- Check the cited source display area, confirm whether the source system and update time of the document are shown.
- Upload updated incentive rule documents, verify that the knowledge base search can recall the latest version of the content.
- Adjust the value of `quoteMaxToken`, test whether long settlement documents are returned completely without truncation.
