# Security and Compliance Material Review for Office System Process Configuration: Model Access and Configuration

## What the data for this category looks like
This category of data primarily comes from enterprise OA systems, organizational structure repositories, internal system documents, and user feedback. Daily produced documents include process configuration sheets, approval node tables, form field descriptions, and change records. Data updates are triggered by process changes, typically at least once per month. Data fields include process node identifiers, approval permission scopes, form validation rules, node execution time limit descriptions, and more. There is no fixed unified standard format, and it adjusts based on internal enterprise management requirements.

## What constraints these characteristics impose on the "model access and configuration" link
Data sources are scattered and formats are inconsistent. Model access must support parsing and adaptation of multi-source heterogeneous documents, making it difficult to rely on fixed input templates. Updates are triggered by process changes. A dynamic data synchronization mechanism must be configured to prevent the model from using outdated process configuration information. Approval node and permission fields involve internal enterprise permission rules. Model calls must strictly follow data isolation requirements to prevent leakage of sensitive permission information. Process change records must be included in the context window. This ensures that configuration suggestions generated by the model align with historical adjustment logic, and adapts to the validation needs of security and compliance reviews.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length of multiple documents such as process configuration sheets and approval node tables, avoiding truncation of key approval rules |
| `maxTokens` | 2000–3000 token | Meets the complete parsing requirement for long-text approval rules during compliance reviews |
| `temperature` | 0.1–0.3 | Reduces randomness of configuration suggestions, ensuring consistency and compliance of approval rule configurations |
| `toolChoice` | auto | Automatically triggers tool calls to read process configuration documents, adapting to the validation needs of multi-source data |

## Three common mistakes
- Phenomenon: The model context is interrupted after calling the MCP tool, and the response content is disjointed. Cause: The `maxContext` parameter is not configured correctly. The original process configuration context window is not retained during tool calls, resulting in loss of key approval rule information.
- Phenomenon: Model call responses time out, and generated content is stuck or incomplete. Cause: No reasonable `maxTokens` value is set, or no dynamic data synchronization mechanism is configured. This causes the model to need to load too many outdated process configuration documents.
- Phenomenon: The reranking model fails to take effect normally, and the returned results do not meet the compliance review priority requirements. Cause: FastGPT v4.17.0 version support for Qwen3-Reranker-8B is not confirmed, or reranking parameter configurations do not match the model input requirements.

## How to confirm the configuration is complete
- Submit a compliance verification request for a process configuration sheet. Check whether the configuration suggestions returned by the model include the approval node information in the current system.
- Trigger an MCP tool call to retrieve process change records. Confirm that the model context is not truncated and retains complete historical configuration logic.
- View the model call logs. Confirm that the authentication token and API endpoint configurations are correct, with no abnormal errors from external interface calls.
- Test the reranking model call. Adjust parameters to match actual verification needs. Confirm that the returned document sorting meets the priority requirements of compliance reviews.
