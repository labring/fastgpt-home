# Security and Compliance Material Review for Unit and Component Testing: Citation Sources and Traceability

## What this category of data looks like
Data for this category primarily comes from code repositories, test framework reports, requirement specifications, and interface definitions. The update rhythm is daily or after each code commit. Daily produced documents include standardized test cases, code coverage reports, Mock interface descriptions, and defect tickets. Each document has fixed fields:
Test cases include case ID, preconditions, execution steps, and expected results. Coverage reports include file path and coverage line percentage. Mock descriptions include interface address, request parameters, and return format. Defect tickets include defect number, reproduction steps, and severity level.

## Constraints on citation sources and traceability
Data sources are scattered and updated frequently. Traceability must bind code commit hash or test task ID as a unique identifier to avoid referencing expired test cases or coverage data. Test document fields have high standardization but large format differences. Traceability must match document type fields to ensure referenced materials are from the correct link. Fast update frequency requires real-time pulling of the latest data. Static caching cannot be used, otherwise referenced content will not match the current test status. Defect tickets and test cases must be accurately bound via case ID to avoid mixing results from different test tasks during traceability. Traceability errors lead to distorted test results, missed local logic defects, or increased regression costs.

## Configuration Settings
Configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of documents such as test cases and coverage reports, ensuring complete citation of core content |
| `responseData` | Return only metadata and citation snippets of associated test documents | Reduces invalid data transmission, adapting to the lightweight traceability requirements of test data |
| `detail` | Enable full field display | Facilitates extraction of key traceability information such as test case ID and code commit hash |
| Single search limit | Top 10 entries | Covers common document types under a single test task, avoiding missed Mock descriptions or defect tickets |
| Context cache duration | 300 seconds | Matches the daily or per-commit update frequency, preventing reference to outdated data due to cache expiration |

## Three Common Configuration Errors
- Confusing the configuration logic of prompt templates and citation content templates, resulting in test data citations not displaying in the required format. The cause is failing to distinguish between the instruction logic of the prompt and the format definition of citation content, writing the citation template into the prompt configuration item.
- No optional values appear when selecting variable references in the interface, making it impossible to bind the test case ID field. The cause is not outputting test task-related variables in the preceding node, or variables not being defined in the required format.
- A `Cannot redefine property: toString` error is thrown in the production environment. The cause is repeatedly defining the toString method in a custom script, which conflicts with the object prototype method built into FastGPT.

## How to Verify Correct Configuration
- Trigger a test task review process, check if the cited traceability information includes unique identifiers such as test case ID and code commit hash.
- Adjust the `quoteMaxToken` parameter value, verify that the length of the cited document fragments meets expectations, with no truncation or overflow.
- Simulate an update after a code commit, check if the traceability system pulls the latest coverage report or defect ticket data.
- Check the `detail` switch status in the configuration panel, confirm that full field display is enabled, and all necessary traceability metadata can be extracted.

The values provided are common starting points and should be measured against the reader's own samples.
