# Security and Compliance Material Review for Prototyping and Interaction Design: Conversation Logs and Audits
This document is written based on FastGPT v4.17.0.

## What data for this category includes
This work typically serves product designers, interaction designers, and front-end product teams. Daily deliverables include interactive prototypes, page flowcharts, component specifications, and review records.
Data sources are mostly Figma or Axure files, team design systems, user feedback, and usability test records. Update frequency is usually weekly or per version iteration.
The core fields of the data structure are page operation paths, component attributes, and review opinions. There is no unified fixed format template, and adjustments must be made based on the design specifications of specific projects.

## What constraints these characteristics impose on conversation logs and audits
Since data sources rely on design tool files and review communication records, conversation logs must be bound to the unique identifier of the corresponding prototype project to ensure logs can be associated with actual design content.
Update frequency is synchronized with project iterations. Audit cycles must match weekly or version-level review rhythms to avoid delayed log retention.
The core of this data is operation paths and review opinions. Logs must fully record prompt and response content in conversations to facilitate tracing the generation chain of design deviations.
Errors in this category of data can lead to R&D understanding deviations, incorrect operation paths after launch, or even rework. Therefore, logs must retain complete conversation chains to support full-process traceability during compliance reviews.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind the unique identifier of the current prototype project | Associate interactive prototype files with conversation logs to facilitate tracing the complete chain of design reviews |
| `responseChatItemId` | Generate a unique identifier for each LLM review response | Accurately locate the content of a single review conversation to avoid confusion between logs from different sessions |
| `detail` | Enable full log recording | Retain complete prompt and response content to meet the full-chain traceability requirements of compliance reviews |
| Maximum Context | 80–120 conversation records | Match the conventional conversation rounds of prototype design reviews, avoiding context overflow or information loss |
| Log Retention Period | 6 months | Match the conventional retention period of compliance reviews, adapting to the traceability needs of project iterations |
| Session Timeout Threshold | 600 seconds | Adapt to the review time of large prototype files, avoiding exceptions triggered by prolonged file loading |

## Three common misconfigurations
- Code run inputs in workflows that include historical records fail validation. The symptom is that the workflow fails to start after historical records are associated with the configuration, triggering a validation error. The cause is that the `chatId` parameter is not correctly bound, leading to failed context association validation for historical records.
- Occasional empty LLM responses followed by an error after 10 seconds of hanging. The symptom is that the `responseChatItemId` field is empty in the conversation log, accompanied by a timeout prompt. The cause is that full `detail` log recording is not enabled, making it impossible to fully trace the exception chain.
- Conversation logs only display a fixed number of historical records, with excess content unavailable. The symptom is that the chat record limit is 50 entries, and subsequent review conversations cannot be loaded. The cause is that the maximum context configuration value is too low, failing to match the actual rounds of review conversations.

## How to confirm configurations are correct
- View the log details of any conversation, confirm that each conversation is bound to the `chatId` identifier of the corresponding prototype project.
- Trigger a design review conversation, check that the `responseChatItemId` field exists and is unique, with no duplicates or empty values.
- Import historical conversation records exceeding 50 entries, verify that logs can load completely, and confirm that the maximum context configuration takes effect.
- Simulate a workflow call, input parameters that include historical records, confirm that there are no validation failure errors, and the workflow can start normally.
