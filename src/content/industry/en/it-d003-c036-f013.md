# Security and Compliance Material Review for Prototyping and Interaction Design: Permissions and Data Isolation

## What data in this category looks like
Data for the prototyping and interaction design category typically comes from design tools including Figma, Axure. Core documents include interactive prototype files, page flowcharts, component specification documents, and design review records.
Data updates follow weekly iterations or synchronized releases with product versions.
Single documents include fields such as page node attributes, operation path logic, component parameters, and review comments. There is no unified fixed unit. Basic description units are pages, steps, and components.

## What constraints these characteristics impose on permissions and data isolation
Data in this category is mostly internal team design collaboration content. It includes undisclosed product operation paths and internal review comments.
Permission isolation must match the team ownership and role permissions of the data.
Frequent version updates require permission configurations to be quickly synchronized with changes. This avoids leakage risks caused by old permissions binding new data.
Different document types (such as prototype files and review records) need differentiated permission granularity. This ensures only authorized roles can access corresponding content, preventing unauthorized personnel from obtaining undisclosed design plans.

## How to set configurations

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Team ownership binding | Associate prototype files by `teamId` | Match the team ownership identifier of prototype files, to ensure cross-team data is not visible |
| Role permission configuration | Assign `tmbId` permission ranges (100-999) by role | Differentiate operation permission scopes for designers, reviewers, and administrators |
| Data access timeout | 300 seconds | Adapt to the average time required for prototype file loading and permission verification |
| Service dependency configuration | Set App/Admin server environment variables `AIPROXY_API_ENDPOINT` to `http://aiproxy:3000`, and `AIPROXY_API_TOKEN` to a non-empty administrator token consistent with the AI Proxy server configuration | Meet the startup verification requirements of FastGPT v4.17.0. This configuration can only be set in App/Admin server environment variables, not in the application interface, workflow global variables, or application API request headers, to ensure normal operation of the permission service |
| Cross-team access restriction | Disable cross-team file sharing | Prevent unauthorized teams from obtaining undisclosed prototype and review data |
| Sensitive data desensitization | Enable review record desensitization | Avoid sensitive information such as internal user feedback from being viewed by unauthorized roles |

## Three common configuration errors
- Phenomenon: Team members can still access original prototype files after being removed. Cause: The `teamId` binding relationship was not synchronized and updated. Residual old permission configurations lead to incomplete permission recovery.
- Phenomenon: Regular users cannot view specified prototype files. Cause: The `tmbId` permission value was mistakenly set to the administrator-exclusive range, which does not match the permission requirements of the corresponding role.
- Phenomenon: Team management functions cannot be enabled normally. Cause: The `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` environment variables were not configured correctly, leading to service startup verification failure.

## How to verify a complete configuration
- Log in to test accounts with different roles, and verify that only team-owned prototype files, review records, and other content can be accessed.
- Manually modify the `teamId` binding configuration of a prototype file, and verify that unauthorized team members cannot access the file.
- Check the service startup logs, and confirm that there are no error messages indicating missing `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- Trigger a team member permission change operation, and verify that the access permissions of the corresponding role take effect synchronously after the update.
