# Security and Compliance Material Review for Change Management and Release Windows: Conversation Logs and Auditing

This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Data sources for this category include change management systems, CI pipelines, monitoring data, and business calendars. Update frequency follows a weekly cadence or triggers with each change. Associated daily documents include change requests, risk assessment forms, launch window plans, and rollback plans. Core fields include change unique identifier, request submission time, compliance approval node, production window period, and rollback trigger conditions. Data is updated in real time or in batches as the change process advances.

## What constraints do these characteristics impose on conversation logs and auditing
Decentralized data sources require conversation logs and auditing to cover associated records from multiple sources including change management systems, CI pipelines, and monitoring data. This ensures full-link traceability. Flexible update frequency requires log retention periods to match weekly or single change cycles, to avoid redundancy or missing data. Complex document structure requires audit fields to accurately correspond to core document items such as change requests, risk assessments, and approval nodes. This ensures compliance review can be implemented. Error consequences such as failures caused by changes and missing approvals require the audit link to include full-process records of rollback triggers and execution.

## Configuration settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `chatId` | Bound to the change ID of the change management system, fixed as string format | Ensures each audit log is strongly associated with the corresponding change process, avoids log confusion |
| `responseChatItemId` | Numbered in approval node order, range 1-20 | Matches the number of approval nodes in the change process, ensures each node’s conversation records can be individually traced |
| `detail` | Contains change window period, risk level, rollback plan, storage range 1000-1500 characters | Covers core document information required for compliance review, meets audit requirements |
| Log retention period | Extended by 7 days relative to the change cycle, range 7-30 days | Matches change process review and compliance archive requirements |
| Multi-source data synchronization interval | Synchronize every 15 minutes | Balances data timeliness and system load |
| Audit log export format | JSON format, single file size no more than 1000 MB | Adapts to general format and storage requirements for compliance archiving |

## Three common configuration errors
- Phenomenon: Conversation log fields are empty when calling other configured applications or plugins in a workflow. Cause: `chatId` is not bound to the session of the called application, causing logs to fail to associate with the main change process.
- Phenomenon: Only conversation content is stored when configuring the `detail` field, and core information such as change window period and risk level is not included. Cause: The structural characteristics of daily documents in this category are not matched, and key fields required for compliance review are omitted.
- Phenomenon: When calling interface historical records, only logs from the API source are returned, and associated records from CI pipelines or monitoring data cannot be obtained. Cause: Association rules for multi-source data synchronization are not configured, resulting in incomplete audit links.

## How to confirm configuration is complete
- Randomly select a completed change process, check whether `chatId` matches the change ID in the change management system.
- Export audit logs, check whether the `detail` field includes core document information such as change requests and window plans.
- Call the interface to view historical records, confirm that associated logs from multiple sources have been synchronously displayed.
- View system logs, confirm there are no error messages about log collection failures or synchronization timeouts.
