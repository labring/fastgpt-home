# Security and Compliance Material Review for Pre-Sales Technical Proposals: Permissions and Data Isolation

## What data belongs to this category
Data sources for pre-sales technical proposal records include customer interview transcripts, bidding documents, vendor product materials, and historical project proposals. Daily output documents include technical proposal books, customer requirement survey forms, quotation lists, and demo scripts. Data updates occur per order or once per week. Core fields for a single document cover technical routes, implementation boundaries, quotation items, and customer requirement points. There are no fixed standard units. Field content adjusts dynamically based on the specific needs of individual pre-sales projects. Document content varies significantly across different projects.

## What constraints do these characteristics impose on permissions and data isolation?
The per-order or weekly update requirement means permission isolation must tie to individual pre-sales project dimensions. This stops cross-access to proposal data across different projects and prevents mixing of cross-project proposal content. The multi-role pre-sales team division requires setting differentiated permission ranges for consultants, architects, and sales. This blocks unauthorized modification of sensitive content such as quotation lists and avoids over-commitment risks. Document sources include confidential materials like bidding documents. Access must be strictly limited to authorized members of the corresponding project to maintain compliance. The dynamic field structure of single documents means permission configurations must update alongside project changes. This prevents mismatches between permissions and data and ensures review process accuracy.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind to the exclusive `teamId` of a single pre-sales project | Matches the business characteristic of managing pre-sales technical proposals by project dimension |
| Member permission scope | Assign read-only/edit permissions based on pre-sales roles | Adapts to division of labor differences among system integrator pre-sales teams |
| Document access scope | Limit to technical proposals, quotation lists, and other materials associated with the current project | Corresponds to the attribute that daily documents only belong to a single pre-sales project |
| Session validity duration | 7200 seconds | Prevents cross-project permission leaks caused by long-duration sessions |
| Single-project storage limit | 4000–6000 MB | Calibrated based on conventional size of pre-sales project documents |

## Three common configuration errors
- Phenomenon: Permission errors appear after restarting Docker, with a prompt that pre-sales proposal documents cannot be read. Cause: The association configuration between `teamId` and project documents was not reconfirmed after restarting, resulting in invalid permission binding relationships.
- Phenomenon: Non-project authorized members can view quotation lists of other pre-sales projects. Cause: The document access scope was not configured as exclusive to the current project, resulting in blurred permission isolation boundaries.
- Phenomenon: Some fields in pre-sales proposals cannot be submitted normally, and the review process gets stuck. Cause: Edit permissions were not assigned based on roles, resulting in some members being unable to fully enter project data.

## How to confirm the configuration is complete
- Use a non-project member account to log in to FastGPT v4.17.0, and verify that access to the technical proposal documents of the current pre-sales project is blocked.
- View the `teamId` binding configuration, and confirm that the documents of each pre-sales project are only associated with the exclusive `teamId` of the corresponding project.
- Restart the Docker service, verify that no permission configuration errors occur, and that access permissions for existing projects take effect normally.
- Check the single-project storage limit configuration, and confirm that the total size of documents for the current project does not exceed the set range.
