# Security and Compliance Material Review for Backup Recovery and Disaster Recovery Drills: Citation Source and Traceability

## What data looks like for this category
This category of data originates from backup systems, database logs, object storage, and disaster recovery platforms. Four core document types are regularly generated: backup policies, recovery drill reports, disaster recovery switchover plans, and data verification records.

Data update cycles fall into three categories: daily, monthly, and quarterly. Backup policies and data verification records are updated more frequently. Disaster recovery switchover plans are typically updated on a quarterly basis.

Each individual document contains clear fields including operation paths, timestamps, verification values, and recovery success rates. The data focuses on cross-system recovery link information.

## What constraints do these characteristics impose on citation source and traceability
Mixed access to multi-source data requires the traceability process to clearly mark the source type of each citation. This prevents confusion between cross-system data.

Based on daily, monthly, and quarterly update cycles, index refresh cycles must be adjusted correspondingly. This ensures cited content aligns with currently active backup policies and the latest drill reports.

The fixed document field structure simplifies field matching logic during traceability. However, timestamps and verification values from documents must be strictly matched. This prevents invalid data from expired or tampered citations.

Cross-system recoverability positioning requires traceability results to link to specific disaster recovery nodes. Only referencing general knowledge base entries cannot cover business requirements.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 characters | Matches the average length of individual disaster recovery documents, avoids truncating critical verification values and timestamps, and complies with FastGPT v4.17.0 parameter configuration specifications |
| `responseData` | Enabled | Meets traceability requirements for compliance reviews, and clearly links to sources such as backup systems and disaster recovery platforms |
| Single search limit | Top 5 entries | Controls the display density of traceability results, avoids redundant information interfering with recovery point confirmation |
| Index refresh cycle | Matches data update cycles (daily/monthly/quarterly) | Aligns with update frequencies of backup policies and drill reports, ensuring cited content takes effect in real time |
| `detail` | Enabled | Displays specific document fields, making it easier to verify data consistency and recovery success rates |
| Timeout threshold | 600 seconds | Matches the average execution duration of disaster recovery drills, prevents premature termination of verification processes |

## Three common configuration errors
- Phenomenon: When configuring a knowledge base search node in a workflow and selecting a variable to reference the knowledge base, the returned citation list is empty. Cause: The knowledge base identification variable was not passed correctly during API calls. This prevents the node from matching the corresponding disaster recovery-related document sources.
- Phenomenon: When calling the chat interface, the number of returned citation entries exceeds the preset range. Cause: A reasonable value for the `quoteMaxToken` parameter was not set. This causes the system to return too many redundant documents unrelated to disaster recovery scenarios.
- Phenomenon: Queries in disaster recovery scenarios do not return corresponding backup policy content. The citation list marks the correct source, but the answer does not link to it. Cause: The `detail` parameter was not enabled. The system does not load structured fields from documents, so it cannot match the query intent of recovery point confirmation.

## How to confirm configuration is complete
- Initiate an API call that passes the knowledge base variable. Check if the returned citation list includes fields from the corresponding disaster recovery documents.
- Call the chat interface. Verify that the returned citation data marks specified sources such as backup systems and object storage.
- Trigger a query related to a recovery drill. Confirm that the returned content includes exclusive fields such as verification values and recovery success rates.
- View the configuration panel. Confirm that the values of `quoteMaxToken`, `responseData`, and `detail` parameters meet the requirements of the current disaster recovery scenario.

The values provided are common starting points and should be measured against the reader's own samples.
