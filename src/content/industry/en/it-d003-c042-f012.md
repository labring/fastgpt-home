# Security and Compliance Material Review for Backup Recovery and Disaster Recovery Drill: Document Parsing and Chunking

## What the data for this category looks like
Data for this category primarily comes from backup systems, database logs, object storage, and disaster recovery platforms. Commonly processed compliance-related documents include backup policies, recovery drill reports, disaster recovery switchover plans, and data validation records.
Document structures include clear time fields, recovery metrics, and validation result items. Update frequencies range from daily, monthly, to quarterly.
Fields vary significantly across different documents. Backup policies include recovery target parameters. Drill reports record execution processes and exceptions. Data validation records include validation dimensions and results.

## What constraints do these characteristics impose on the document parsing and chunking link
This category has diverse document types with notable structural differences. Compliance review requirements mandate that document parsing preserves the relational context of original fields, to avoid breaking the traceability of business logic through chunking.
Backup policies and validation records often contain structured tables and fixed metric fields. Chunking must avoid splitting critical business parameters.
Recovery drill reports and disaster recovery plans include long paragraph process descriptions. Context coherence must be preserved for these documents.
Data sources cover multiple systems, with export formats including Word, PDF, CSV, and others. Parsing rules must adapt to different formats.
Update frequencies span daily, monthly, and quarterly. Parsing must support on-demand triggering and batch processing, while ensuring document version consistency required for compliance reviews.

## How to configure settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category of documents includes long process descriptions and structured metrics. This range balances context coherence and retrieval accuracy |
| `chunkSplitter` | Split by paragraph + semantic | Disaster recovery plans and drill reports include multi-segment process descriptions. Splitting by paragraph preserves business logic integrity |
| `customPdfParse` | Enabled | PDF documents in this category often include tables and image annotations. Enabling this optimizes structured content extraction results |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Batch-imported collections of disaster recovery drill reports may occupy significant storage space. This upper limit ensures batch processing stability |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large backup policy documents and multi-page drill reports have long parsing times. This duration covers parsing needs for most scenarios |
| `chunkSettingMode` | Manual configuration | Document structures vary significantly across this category. Manual configuration allows targeted adjustment of chunking rules to fit different document types |

## Three common configuration errors
- Enabling `customPdfParse` without observed effect. Symptom: No structured extraction results for tables in PDFs. Cause: Dependent services for the corresponding parsing plugin were not enabled synchronously.
- Custom parsing URL returns no data. Symptom: Parsing task status remains pending. Cause: Correct authentication parameters were not configured, or the target service did not have cross-domain access permissions enabled.
- Poor recognition after importing a Word document with multiple tables. Symptom: Table content is split into scattered text chunks. Cause: The `chunkSplitter` rule was not adjusted to split by table boundaries.

## How to verify successful configuration
- Upload a single backup policy PDF document, check if parsed text chunks retain complete context for key metrics such as RPO and RTO.
- Upload a Word drill report document containing multiple tables, verify that parsed results present tables as structured chunks.
- Upload a batch validation record file under 100 MB, confirm that the parsing task completes within the duration set by `PARSE_FILE_TIMEOUT_SECONDS`.
- View parsing logs, confirm that no file size limit or timeout errors occur, matching the configuration ranges of `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided are common starting points and should be measured against the reader's own samples.
