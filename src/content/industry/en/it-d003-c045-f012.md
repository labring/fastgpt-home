# Security and Compliance Material Review for Security Training and Phishing Drills: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category comes from daily business outputs and operational data of security operations teams, internal training teams, or external security service providers. Daily documents include four types: training courseware, phishing email drill plans, phishing email templates, and drill result reports. Data sources cover employee contact lists, corporate email gateways, internal training platforms, and user click statistics systems. Data update frequency is typically quarterly or annual. Most document structures include structured fields such as drill time, participant groups, and unstructured paragraphs such as training content and email copy. Some reports include statistical fields.

## What constraints these characteristics impose on document parsing and chunking
The diversity of daily documents requires the parsing module to support multi-page layouts of courseware, short-text copy of email templates, and long-paragraph review content of reports. Dispersed data sources lead to inconsistent document formats, so the module must adapt to file styles exported by different platforms. Quarterly or annual update frequency means a single parse job may process multiple documents in a batch, so the module must balance batch processing efficiency. Compliance requirements for phishing email templates demand retaining original copy details; chunking must not truncate key statements. Statistical fields in drill result reports must be bound to unstructured content to avoid losing association after chunking. Deviations in parsing and chunking may lead to employee data leakage risks, audit gaps, or compliance issues without evidence for rectification.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to short copy in phishing email templates and long paragraphs in drill reports, avoids truncating key compliance statements |
| `chunkSplitter` | Split by paragraph + heading | Matches the structured hierarchy of training courseware and drill plans, retains logical associations within documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Accommodates training courseware or drill reports with hundreds of pages per file, avoids parsing timeouts for large files |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch import of multiple documents updated quarterly, meets batch processing needs of internal training teams |
| `customPdfParse` | Enabled | Adapts to PDF training courseware in different formats, retains original document layout and image association information |

## Three common errors
- Phenomenon: Calling `customPdfParse` to parse JSON-format attachments of phishing email templates returns parsing errors. Cause: No dedicated parsing rules are configured for structured attachments of email templates, and the default parsing logic cannot recognize non-standard JSON fields.
- Phenomenon: After deploying FastGPT v4.17.0 locally, the file parsing function fails when batch importing drill result reports. Cause: The `UPLOAD_FILE_MAX_SIZE` parameter was not adjusted to accommodate large individual reports, or the file storage permission configuration for the local deployment is incorrect.
- Phenomenon: When `PARSE_FILE_TIMEOUT_SECONDS` is set to 120 seconds, parsing a training courseware PDF with more than 200 pages triggers a timeout. Cause: The default timeout threshold is insufficient to cover the parsing time of long documents, and the parameter was not adjusted based on the average page count of documents in this category.

## How to confirm the configuration is correct
- Upload a single phishing email template document, check if the parsed chunks retain complete email copy paragraphs with no truncation.
- Batch upload quarterly updated drill reports, confirm that parsing tasks can be submitted normally and chunking results are generated, with no batch processing errors.
- Adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter, then upload the largest test document, verify that the parsing task completes within the set duration.
- Check if structured fields in the parsing results such as drill time, participant groups match the original document, with no missing content.

The values provided are common starting points and should be measured against the reader's own samples.
