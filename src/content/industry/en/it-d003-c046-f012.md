# Security and Compliance Material Review for Security Baseline Checks: Document Parsing and Chunking

## What the data for this category looks like
This category’s data originates from server configurations, middleware configurations, security device policy outputs, and baseline tool export results. Updates occur on a monthly or quarterly basis. Daily processed documents include baseline checklists, configuration verification records, rectification suggestion sheets, and exception approval forms. Most documents combine structured tables and paragraphs, with fields including configuration item names, current values, compliance status, rectification requirements, and similar items. There are no unified fixed units, and some fields vary based on device type.

## What constraints do these characteristics impose on the document parsing and chunking link?
The mixed structure of structured tables and paragraphs requires parsing tools to support both table extraction and text splitting. This avoids breaking the association between configuration items and their compliance status. The monthly or quarterly update frequency requires the parsing process to be stable and capable of batch processing, without the need for high-frequency real-time adjustments. Heterogeneous data from multiple sources requires unified parsing rules to adapt to format differences across baseline tool exports. For core documents focused on configuration item verification, chunking must retain the contextual association between configuration items and their corresponding verification results. This prevents information loss from broken chunks.

## How to configure the settings
This guide is compatible with FastGPT v4.17.0. Specific configuration items and recommendations are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the contextual length of configuration items and verification results in baseline checklists, to avoid losing associations after splitting |
| `chunkSplitter` | Split by paragraph + title | Matches the hierarchical structure of configuration item groups and rectification suggestions in documents |
| `customPdfParse` | Enable table extraction mode | Adapts to the structured table format of baseline checklists, to fully extract configuration item fields |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the file size of multi-device configuration verification records exported in quarterly batches |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing duration of full configuration documents exported by large-scale baseline tools |
| `chunkSettingMode` | Manual configuration | Flexibly adjust chunking rules for different types of compliance documents |

## Three common mistakes
- A timeout error is returned when calling the file parsing tool. The cause is failing to adjust `PARSE_FILE_TIMEOUT_SECONDS` to a value suitable for large baseline documents.
- The configuration item fields in the parsed baseline checklist are empty. The cause is failing to enable the table extraction mode of `customPdfParse`, resulting in structured content being ignored.
- Local deployment versions cannot properly parse formula-based configuration descriptions. The cause is that the deployed FastGPT version does not match the online version, and the compatible version of the corresponding parsing plugin is not used.

## How to confirm the configuration is complete
- Upload a single baseline checklist document, and check whether the configuration item, current value, and compliance status fields are fully extracted in the parsing results.
- Upload a batch-exported configuration verification record file, and confirm that no timeout error is triggered for the parsing task.
- Adjust the `chunkSize` value, and verify whether the chunked results retain the complete contextual information of a single configuration item.
- Compare the parsing effects of different types of compliance documents, and confirm that the hierarchical splitting rules of `chunkSplitter` are suitable for the current document structure.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
