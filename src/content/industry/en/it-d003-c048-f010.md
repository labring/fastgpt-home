# Security and Compliance Material Review for Security Monitoring and SOC Duty: Citation Source and Traceability
## What this category of data looks like
This data category draws from SIEM, EDR, NDR, and various threat intelligence sources. Data updates follow two rhythms: real-time and daily. Daily processed documents include alarm disposal sheets, duty records, threat intelligence bulletins, and daily/weekly reports. Each document includes fields such as alarm ID, disposal process, threat level, and associated device information. Some weekly reports summarize weekly alarm counts and disposal results. Most data fields are structured operation records and security indicators, with no complex unstructured text nesting.

## How These Characteristics Impact the Citation Source and Traceability Link
Decentralized data sources require simultaneous connections to multiple knowledge bases and data sources. Real-time updated alarm data requires the traceability link to support low-latency calls. The high volume of structured fields requires precise matching of unique identifiers such as alarm IDs during traceability to avoid false associations. Daily updated weekly reports require filtering the traceability scope by time dimension to prevent expired data from being included. The continuous operation feature of SOC duty requires the traceability link to have fault tolerance, preventing single data source exceptions from interrupting the overall process.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 1000–1500 token | Adapt to the field length of documents such as alarm disposal sheets and threat intelligence bulletins, avoiding exceeding context limits |
| `responseData` | Full structured fields | Meet requirements for precise traceability of unique identifiers such as alarm ID and disposal time |
| `detail` | Enabled | Support extraction of complete links and original content from threat intelligence sources to complete compliant traceability |
| Single recall limit | Top 6–10 entries | Match daily alarm volume processed by SOC duty, avoiding redundant data interfering with judgment and analysis |
| Context timeout threshold | 200–400 seconds | Adapt to low-latency response requirements of real-time alarms, preventing timeouts from affecting duty processes |

## Three Common Misconfigurations
- The default list is empty when calling the knowledge base, and the target knowledge base cannot be selected directly. The root cause is that the default associated data source path is not configured, causing the system to fail to automatically load corresponding SIEM and EDR knowledge bases.
- Cited content exceeds the limit, causing the alarm judgment link to be interrupted. The root cause is that the `quoteMaxToken` parameter is not adjusted to a value adapted to the document length, exceeding the system context limit.
- The cited original source cannot be downloaded or displays abnormally. The root cause is that the `detail` switch is not enabled, and complete link information of threat intelligence sources is not extracted.

## How to Verify Successful Configuration
- Submit a test alarm disposal sheet, and confirm the citation and traceability module automatically loads associated SIEM data source content.
- After adjusting configuration items, check whether the `responseData` return format includes required fields such as alarm ID and disposal time.
- Trigger a real-time alarm query, and confirm the traceability link's response time meets the preset timeout threshold requirements.
- Test simultaneous calls to multiple data sources, and confirm content from SIEM and threat intelligence sources can be correctly integrated.

The values given are common starting points and should be measured against the reader's own samples.
