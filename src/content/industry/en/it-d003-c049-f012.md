# Security and Compliance Material Review for Customer Training and Usage Manuals: Document Parsing and Chunking

## What data looks like for this category
Daily documents for this category fall into four types: training courseware, user manuals, training attendance sheets, and question and answer lists formatted as Q&A pairs. Data is primarily sourced from product help centers, customer organizational structures, recorded training sessions, and ticket systems. Update frequency is adjusted based on customer orders or product version iterations. Most document structures include hierarchical chapters, sequential operation steps, and permission description entries. Some documents include customer-specific identifiers, version numbers, and update time fields. No mandatory uniform units exist. Some operation step documents include sample parameter values.

## Constraints imposed by these characteristics on document parsing and chunking
Hierarchical chapter structures require chunking tools to adapt to document hierarchy. They must avoid splitting permission explanations or operation step content across chapters. This ensures complete logical content during compliance reviews. Metadata such as customer-specific identifiers and version numbers must be retained during parsing. This supports compliance traceability and version matching. Question and answer lists formatted as Q&A pairs require separate differentiation of question and answer fields. This prevents confusing content boundaries. Frequent version iterations require parsing processes to flexibly adapt to document structure changes. No repeated adjustments to basic configurations are needed. Spoken content transcribed from recorded training sessions must retain contextual connections. This maintains content integrity.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific settings are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single-chapter content in user manuals and training courseware, avoiding splitting complete operation steps |
| `chunkSplitter` | Split by document hierarchy | Matches the hierarchical structure of documents in this category, retaining logical integrity of chapters and steps |
| `customPdfParse` | Enabled | Adapts to PDF formats of training courseware and user manuals, retaining embedded notes and interactive elements |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatible with large recorded training transcript files and multi-page user manual collections |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Prevents timeout interruptions during parsing of large documents or batch files |
| `chunkSettingMode` | Manual configuration | Adapts to chunking requirements for different document types, supporting separate parameter adjustments for question and answer lists |

## Three Common Configuration Mistakes
- Symptom: Uploaded Excel format files fail to parse, or CSV files imported only have their first two columns recognized. Cause: Parsing configuration adapted for non-standard table documents is not enabled. Default parsing rules only recognize basic two-column structures.
- Symptom: After batch importing question and answer lists formatted as Q&A pairs, some chunked content is missing or logically disconnected. Cause: `chunkSize` is set too small, splitting complete question and answer pair content.
- Symptom: Connection failure errors occur when calling `customPdfParse`, and locally deployed parsing services cannot connect normally. Cause: Port mapping for the local parsing service is not configured correctly, or there are conflicts in Docker container network settings.

## How to Verify Correct Configuration
- Upload a typical user manual PDF. Check that parsed chunks retain chapter titles and complete operation steps, with no cross-chapter splits.
- Upload a CSV file formatted as Q&A pairs. Confirm that all column content is correctly recognized and chunked, with no content omitted.
- Upload a large training courseware collection. Check that the parsing process does not show timeout errors, and that the file size falls within the configured range.
- Trigger a parsing task. Confirm that the locally deployed PDF parsing service can connect normally, with no connection failure prompts.

The values listed are common starting points and should be evaluated against samples specific to the intended use case.
