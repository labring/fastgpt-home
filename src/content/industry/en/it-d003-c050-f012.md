# Security and Compliance Material Review for Customer Onboarding and Tenant Initialization: Document Parsing and Chunking

## What Data for This Category Looks Like
Core data for this category typically comes from CRM systems, contract orders, identity management systems, and product backends. Commonly processed documents include customer onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation slips. Data updates occur per order or daily. Individual data entries include fields such as customer identity information, tenant permission configurations, and delivery node status. There is no unified fixed unit, as dimensions vary per customer order.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
Data sources for this category are scattered and have diverse formats. The document parsing link must support multiple native office document formats. Data updates occur per single delivery or daily. Parsing tasks need rapid response capabilities to avoid delays that disrupt customer onboarding workflows. Most daily processed documents are structured short text. Chunking must avoid breaking the integrity of critical fields such as customer identity and permission configurations. It must also ensure sensitive information is not included in unrelated chunks. Additionally, data dimensions vary per customer order. Parsing rules must support flexible adaptation to differences in configuration fields across different customers.

## How to Set Configurations
Configurations on this page are based on FastGPT v4.17.0. Specific configuration items are listed below:

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the field length of structured short text for this category, avoiding splitting critical permission configuration information |
| `chunkSplitter` | Split by paragraph | Matches the paragraph structure of daily documents, preserving complete semantics of customer information and permission items |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the maximum possible size of single delivery confirmation slips and tenant configuration sheets, adapting to bulk onboarding scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Matches the daily or batch update rhythm of data, avoiding onboarding workflow interruptions caused by parsing timeouts |
| `customPdfParse` | Enabled | Preserves table and field layout in PDF-format onboarding application forms, ensuring accurate recognition of permission configuration items |

## Three Common Misconfigurations
- Issue: After deploying the packaged project to a server, uploading compliance documents triggers a 404 error during parsing. Cause: The file path uses a local relative path when uploading in the local environment, and the file storage directory configuration is not updated synchronously after deployment to the server, causing the parsing node to fail to locate the target file.
- Issue: Parsing tasks return empty results, and logs show no file content was read. Cause: File storage directory permissions are not configured correctly, causing the parsing node to fail to access uploaded document files.
- Issue: After bulk pushing compliance documents to external systems, chunking results do not include sensitive fields. Cause: The `customPdfParse` configuration is not enabled, causing table fields in PDF-format administrator account lists to be automatically skipped.

## How to Confirm Configurations Are Correct
- Upload a standard customer onboarding application form, check the chunk count of the parsing result, and confirm that chunk lengths fall within the preset `chunkSize` range.
- Deploy a test environment and upload documents, verify that the parsing node can normally read file content, and troubleshoot path-related errors.
- Check system logs, confirm that the execution duration of parsing tasks does not exceed the value set for `PARSE_FILE_TIMEOUT_SECONDS`.
- Check the permissions configuration of the file storage directory, ensure the parsing node has permission to read uploaded files.

The values provided are common starting points and should be measured against the reader's own samples.
