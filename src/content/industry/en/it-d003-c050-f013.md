# Security and Compliance Material Review for Customer Onboarding and Tenant Initialization: Permissions and Data Isolation

## What this category of data looks like
Data for this category typically comes from CRM, contract order, identity management, and product backend systems. Daily documents include onboarding application forms, tenant configuration sheets, admin account lists, and delivery confirmation slips. Each onboarding application form is associated with a unique `teamId` identifier. Tenant configuration sheets include core fields such as `tmbId` and permission scope. Admin account lists record authorized member permission identifiers. Delivery confirmation slips are tied to corresponding contract order numbers. Data updates are triggered by individual customer onboarding. Member information from identity management systems is synced daily, with no additional bulk update schedules.

## What constraints do these characteristics impose on the permissions and data isolation link
Data for this category comes from dispersed sources and is tied to customer contracts and identity information. Permission configurations must strictly match the service scope a customer actually purchased to prevent unauthorized access. Document data includes clear permission lists. Member access permissions must be verified against these lists to ensure only authorized personnel can modify tenant configurations. Data update frequency is tied to individual customer onboarding. Permission configurations usually need to be synced immediately after each onboarding to avoid permission anomalies caused by delays. Cross-system data interactions require a verification chain to ensure consistent permission data across CRM, identity systems, and product backends. Otherwise, issues such as customer login failures or delivery delays may occur.

## How to set the configurations
| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| Team ID Binding Configuration | Bind to the `teamId` associated with CRM contracts | Ensure tenant permissions match the service scope agreed in the contract |
| Tenant Permission Scope Configuration | Configure based on permission intervals defined in delivery confirmation slips | Match the functional and data permissions actually purchased by the customer |
| Member Permission Verification Rules | Verify that `tmbId` matches entries in the admin account list | Ensure only registered members can access tenant configurations |
| Data Isolation Storage Configuration | Allocate independent storage quotas of under 1000 MB per tenant | Prevent cross-tenant data access |
| Onboarding Result Sync Configuration | Sync to identity management systems every 600 seconds | Align with the data update schedule |
| Permission Audit Configuration | Retain permission operation logs for the past 30 days | Meet traceability requirements for compliance reviews |

## Three Common Misconfigurations
- Unable to open the team management page, with an error prompt "Insufficient permissions". Cause: The current account is not bound to the tenant configuration for the corresponding `teamId`.
- Queries associated with non-intra-team knowledge bases return no relevant content. Cause: The `tmbId` association rule was not configured correctly, resulting in cross-tenant data isolation blocking.
- Members cannot view model usage records within the team. Cause: The member's permission identifier was not entered in the admin account list, so the verification rule failed.

## How to Confirm Proper Configuration
- Access the FastGPT v4.17.0 backend, enter the target `teamId`, and verify that the team management page can be accessed normally.
- Associate knowledge bases and applications from the same tenant, initiate a query, and confirm that matching knowledge base content is returned.
- Import the admin account list, batch verify the permission access scope of members, and confirm there are no unauthorized configurations.
- View the permission operation logs, and confirm that a sync record for the most recent tenant initialization has been generated.
