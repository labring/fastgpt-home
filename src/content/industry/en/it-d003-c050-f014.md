# Security and Compliance Material Review for Customer Onboarding and Tenant Initialization: Model Integration and Configuration

## What the data for this category looks like
Core data for this category typically comes from CRM systems, contract order databases, identity management systems, and product backends. Updates occur per order or daily. Daily associated documents include onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation documents. Most data fields include customer entity information, permission configuration items, administrator account lists, and acceptance milestones. Data formats are primarily structured tables and standardized forms. Single-tenant data volume is usually small, but field requirements are strict. Fixed validation rules for compliance review must be followed.

## What constraints these characteristics impose on the model integration and configuration link
Multi-source heterogeneous data sources require model integration to support cross-system data format alignment and validation, to prevent review failures caused by data format mismatches. The small volume but high strictness of field requirements for single tenants means model configuration must adapt to fixed field validation logic, and validation dimensions cannot be adjusted arbitrarily. The per order or daily update frequency requires configured context length and processing efficiency to match the single-tenant business volume per operation, to avoid resource waste or processing timeouts. Severe consequences of errors require a pre-validation link in the configuration, to ensure that compliance conclusions output by the model can be directly used for delivery acceptance.

## How to set the configuration
This configuration is based on the parameter logic of FastGPT v4.17.0. Specific items are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Matches the total length of all associated documents for a single tenant, prevents review interruptions caused by context overflow |
| `maxTokens` | `2000–3000 token` | Covers the full output requirements of compliance review reports, ensures all validation conclusions are fully presented |
| `toolChoice` | `auto` | Enables the model to independently determine whether to call the knowledge base to verify customer qualification materials, adapts to material differences across tenants |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example `http://aiproxy:3000`. Do not append `/v1` or `/chat/completions` paths. Do not use single-model service addresses | Ensures correct model request routing, avoids cross-region access delays or request failures |
| `temperature` | `0.1–0.3` | Reduces randomness in model output, ensures the rigor and consistency of compliance review conclusions |
| `quoteMaxToken` | `1500 token` | Limits the length of referenced compliance materials, ensures review content focuses on core clauses, avoids interference from redundant information |

## Three common mistakes
- Scenario: The model does not automatically call the knowledge base to verify materials after tenant review is triggered, and only generates generic responses. Cause: The `toolChoice` parameter is incorrectly set to `none`, and automatic tool calling capability is not enabled, so the model cannot obtain associated data from compliance materials.
- Scenario: The interface displays the "Field validation failed" error, and tenant initialization cannot be completed. Troubleshooting items: Check whether `maxContext` matches the total length of multiple documents. Check whether the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` server environment variables are configured and meet requirements.
- Scenario: The compliance review report has vague conclusions that cannot be directly used for delivery confirmation. Cause: The `temperature` parameter is set too high, leading to high randomness in model output, which does not meet the rigor requirements of compliance review.

## How to confirm the configuration is complete
- Submit an onboarding application form for a test tenant, check whether the model automatically calls the knowledge base to verify the consistency between identity data from the identity management system and application form information.
- View the review report generated by the model, confirm that fields from all associated documents are covered, and no validation items are missed.
- Simulate input of test data with incorrect formats, check whether the model triggers the corresponding compliance validation prompt, and review cannot be completed directly.
- After verifying the `AIPROXY_API_ENDPOINT` (AI Proxy service root address) and `AIPROXY_API_TOKEN` (AI Proxy administrator Token) server environment variables, initiate a test request without connection timeouts or permission errors.
