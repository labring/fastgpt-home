# Security and Compliance Review of Customer Data Import Migration: Citation Sources and Traceability

## What This Category of Data Looks Like
This category of data primarily comes from customer historical business systems, standard CSV or Excel data templates, database export files, and import operation logs within the FastGPT product. Daily supporting documents include data import templates, migration execution plans, field mapping comparison tables, and migration effect verification reports. Data update rhythms are adjusted irregularly based on individual customer project progress, with no fixed cycle. Data fields include business entity identifiers, original field names, mapped field names, data values, import status, and more. There are no unified fixed units, and values vary based on customer business scenarios.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Link
Access to multiple data sources requires that citation traceability be linked to the specific source path of original data, to avoid cross-data-source confusion. Version differences in supporting documents will affect the accuracy of field mapping. The traceability link must be bound to the migration plan and field mapping table of the corresponding version. Irregularly updated data requires recording the timestamp and operator of each import, to ensure compliance audit traceability. For business fields with no fixed units, traceability must retain the original field names and mapping relationships of the data, to avoid misalignment during subsequent verification. Complete retention of import logs is a necessary basis for compliance review. Traceability information must be linkable to the full chain of a single imported data entry.

## How to Configure Settings
The following configuration items are written based on FastGPT v4.17.0, and can be adjusted according to actual business scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Citation Source Switch | Enabled | Binds the original source path of imported data to meet compliance traceability requirements |
| `quoteMaxToken` | 1000–1500 token | Matches the single-batch text length of customer imported data, to avoid truncation of traceability information |
| `responseData` | Retain original fields and original text | Retains the original field names and values of imported data, to ensure direct reference to original text during retrieval |
| `detail` | Enable full operation logs | Records the operator, timestamp, and status of each import, to improve audit chain completeness |
| Single Recall Count | Top 3 entries | Matches the single-batch quantity of imported data, to avoid interference from redundant information |
| Import Timeout Duration | 600 seconds | Matches the maximum waiting time for batch imports, to avoid abnormal task interruptions |
| Field Mapping Verification | Enable forced matching | Verifies the consistency between imported data and preset mapping tables, to avoid field misalignment |
| Log Retention Period | Retain for 90 days | Meets the basic retention requirements for compliance audits |

## Three Common Configuration Errors
- Symptom: After retrieval, imported question-and-answer pair data returns a reply that does not match the knowledge base original text, but generates new content. Cause: The `responseData` parameter is not configured correctly, and the original text reference mode is not enabled. This causes the system to fail to bind the original imported question-and-answer pair text.
- Symptom: After the import task is executed, the traceability log does not display the original data source path. Cause: The citation source switch is not enabled, and the `detail` parameter is not configured to enable full logs. This results in the original source information not being recorded.
- Symptom: The same field data from multiple batch imports shows misalignment, and cannot be traced by batch. Cause: The corresponding field mapping table is not bound to each import batch. This causes the traceability link to fail to distinguish field mapping relationships across different batches.

## How to Confirm Correct Configuration
- Perform a test data import, and check whether the import log contains original data sources, operation time, and field mapping information.
- Retrieve the imported question-and-answer pair data, and confirm that the returned reply directly references original text fragments without generating additional content.
- Check the configured value of the `quoteMaxToken` parameter, to ensure it matches the single-text length of the test data.
- View the system-retained import logs, to confirm the retention period meets preset requirements.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
