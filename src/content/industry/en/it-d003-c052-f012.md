# Security and Compliance Material Review for Client Permissions and Organizational Structure Configuration: Document Parsing and Chunking

## What the Data for This Category Looks Like
This category of data primarily originates from client HR systems, identity directories, product backends, and audit logs. Daily processed documents include permission matrices, organizational structure tables, role configuration records, and permission change forms. Data updates are triggered per form or irregularly. Single document sets contain between several and dozens of entries. Core fields include department hierarchy codes, role identifiers, permission coverage ranges, and change effective times. Some fields use enumeration types, with no unified fixed unit.

## Constraints on the Document Parsing and Chunking Link
Data sources for this category are scattered. Some documents are structured tables, while others are hierarchical text. Documents processed in a single batch have closely linked fields. Document updates follow no fixed cycle. Parsing and incremental synchronization must support on-demand processing.
Since this work involves permission and compliance reviews, chunking operations must not separate the corresponding relationship between roles and permissions. They must also not break the complete chain of organizational hierarchies.
Some documents come from audit logs, which contain long text lines. Chunking must avoid truncation that causes permission mapping logic to fail.
Some compliance documents include image-based permission descriptions. The parsing link must ensure that associated information can be extracted synchronously.

## Configuration Settings
The following configurations are based on the document parsing and chunking logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of permission matrices and organizational structure tables, and avoids splitting the association between roles and permissions |
| `chunkSplitter` | Group by hierarchy and fields | Retains the hierarchical chain of organizational structures and the binding relationship between role permissions, and meets the field integrity requirements of compliance reviews |
| `customPdfParse` | Enable structured parsing mode | Adapts to PDF-format permission documents exported from product backends, and preserves the original typesetting of tables and hierarchical structures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Covers the time requirements for single-batch parsing of permission change forms, and avoids parsing interruptions caused by a large number of document entries |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Limits the upload size of a single compliance document, and avoids excessive occupation of system resources during batch parsing |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for documents from different sources (such as Excel exported from HR systems, audit log text) to adapt to data characteristics |

## Three Common Misconfiguration Issues
- After uploading a permission compliance document that includes images, question-and-answer testing cannot associate the permission descriptions in the images. The cause is that image parsing configuration is not enabled, and only text content is extracted. This corresponds to the problem reported by users in actual scenarios where images in the knowledge base cannot be called by question-and-answer functions.
- Structured parsing errors occur when parsing permission matrix Excel documents, and role and permission fields are misaligned. The cause is that the grouping rules for `chunkSplitter` are not configured. Default line break splitting causes structured data to be disrupted.
- Parsing timeouts occur when multiple permission change forms are uploaded in batches. The cause is that the value of `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted. The default duration is insufficient for processing multi-entry audit log documents.

## How to Verify Correct Configuration
- Upload a permission matrix document, review the parsed chunk results, and confirm that role and permission fields are not split across different chunks.
- Upload an organizational structure table with a hierarchical structure, check that the parsing result retains the departmental hierarchical chain, and no field truncation is present.
- Adjust the value of `PARSE_FILE_TIMEOUT_SECONDS`, then upload multiple permission change forms in batches, and confirm that no timeout error prompts appear.
- Upload a compliance document that includes images, and confirm that the parsing result includes text descriptions or image links associated with the images.

The values provided are common starting points and should be evaluated against local samples.
