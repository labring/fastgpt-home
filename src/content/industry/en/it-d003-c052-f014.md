# Security and Compliance Material Review for Customer Permission and Organization Architecture Configuration: Model Access and Configuration

## What Data Is Included in This Category
Core data for this category comes from customer HR systems, identity directories, product backends, and audit logs. Four types of documents are maintained regularly: permission matrices, organization architecture tables, role configuration records, and permission change tickets. Updates occur per ticket or irregularly, triggered by customer permission adjustments or organization architecture changes. Data fields include role ID, department hierarchy, permission nodes, change time, and more. There is no unified fixed single document size. Configurations must adapt to customer organization data of varying scales.

## Constraints Imposed on Model Access and Configuration
Data originates from multiple systems, so model access must support connecting to multi-source identity data. Synchronization rules for multiple data sources must be configured. Updates are irregular, so incremental pull configuration must be enabled to avoid reprocessing old data. Document structures are fixed but vary widely in size. Adjustable context length parameters must be configured to fit permission documents of different sizes. Error outcomes include unauthorized access and audit failures. Stable output parameters must be configured to ensure the accuracy of permission mapping.

## Configuration Guidelines
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the total field length of permission matrices and organization architecture tables |
| `maxTokens` | `4000–6000 token` | Covers the content volume of a single role configuration record or permission change ticket |
| `temperature` | `0.1–0.3` | Ensures output stability for permission mapping and hierarchy verification |
| `AIPROXY_API_ENDPOINT` | `http://{Deployment IP}:{Proxy Port}` | Root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths, and do not point to single-model addresses such as VLLM/Ollama/Xinference |
| `AIPROXY_API_TOKEN` | `Non-empty administrator token consistent with AI Proxy server configuration` | Completes security identity verification for the AI Proxy service. Do not use application API keys, model vendor keys, or tokens issued per application |

## Three Common Misconfiguration Issues
- Abnormal results or connection failures returned when calling the model. Troubleshooting steps: Check if `AIPROXY_API_ENDPOINT` is the root address of the AI Proxy service, and does not point to single-model addresses such as Ollama. Check the connectivity between the AI Proxy service and upstream model services.
- Model test fails after server restart. This occurs because the Ollama service is not set to start automatically on boot, or the Docker image startup sequence is incorrect, causing the proxy to fail to connect to the local model and resulting in connection timeout errors.
- Image input option cannot be enabled after configuring an image model. This occurs because the `vision` parameter is not set to `true`, or the corresponding switch for image support is not checked in the model access interface, preventing the model from recognizing image inputs.

## How to Verify Successful Configuration
- Check the environment variable configuration of the App/Admin server. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly set and non-empty.
- Upload a permission matrix document to initiate a model test. Check if the returned result includes structured entries for role permission mapping.
- View the audit log in the product backend. Confirm that model call requests and responses are properly recorded, with no abnormal error fields.
- Adjust the value range of the `maxContext` parameter. Verify that the configuration can adapt to organization architecture data of different scales.

The values provided are common starting points and should be measured against the reader's own samples.
