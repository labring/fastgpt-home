# Security and Compliance Material Review for Container Platform Operations: Citation Sources and Traceability

## What This Category of Data Looks Like
Core data for this category comes from Kubernetes API, image registries, monitoring systems, and CI pipelines. Four standard operation and maintenance documents are generated: cluster change tickets, namespace quota tables, deployment records, and fault reports.
Data updates occur daily or when triggered by cluster changes.
Document fields include cluster identifiers, image tags, change times, resource quota thresholds, Pod running status, and other details. There is no unified fixed format, and it adjusts based on specific operation and maintenance workflows.

## Constraints on Citation Sources and Traceability
Data sources are scattered and updated in real time as cluster changes occur. The citation and traceability process must accurately match data sources and change timestamps to avoid referencing expired quotas or deployment records.
Document structures for cluster change tickets, deployment records, and other materials are inconsistent. During retrieval, the unique identifier of the corresponding operation and maintenance workflow must be associated. This ensures traceability information maps to specific Pod scheduling or resource adjustment operations.
At the same time, core data for container platform operations is strongly tied to cluster resources. When citing, cluster namespace and resource ID must be included. This guarantees traceability uniqueness and avoids confusion of configuration information across different clusters.

## How to Configure Settings
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | Single compliance documents for container platform operations typically range from 500–1000 token. Combined with retrieved chunk sizes and business document lengths, this avoids truncating critical quota or change information |
| `responseData` | Include source document metadata | Metadata such as cluster ID, change time, and image registry address must be returned to meet the requirement of associating traceability with specific operation and maintenance records |
| `detail` | Enable full source information display | Facilitates verification of consistency between cited content and actual cluster configurations, matching fault troubleshooting or compliance review scenarios |
| Single search limit | Top 3–5 results | Compliance documents for container platform operations have high relevance. Excessive results increase traceability complexity, and this aligns with typical retrieval volumes for cluster change records |
| Chunk overlap length | 100–200 token | Adapts to chunked linking for long texts such as cluster change tickets, prevents key change steps from being split across different chunks, and ensures complete citation of change workflows |

## Three Common Configuration Errors
- Symptom: Matching knowledge base chunks are retrieved, but returned results do not include citation source addresses. Cause: The metadata return switch for the `responseData` configuration item is not enabled, and the storage path or API address of the source document is not included.
- Symptom: Returned cited content exceeds the set `quoteMaxToken` limit. Cause: The knowledge base chunk size is set to 5000 token, which exceeds the `quoteMaxToken` value, causing a single chunk to directly exceed the limit.
- Symptom: After workflows categorized differently call the knowledge base, traceability information cannot be uniformly associated. Cause: The identification field of source document metadata is not unified in the configuration, leading to inconsistent traceability formats across different knowledge bases.

## How to Confirm Successful Configuration
- Initiate a query related to cluster change tickets, and check whether returned results include metadata such as cluster namespace and change time.
- Check the token length of returned content, and confirm it does not exceed the set `quoteMaxToken` value.
- Test calls from workflows categorized differently, and confirm all knowledge bases return consistent traceability formats.
- Simulate retrieval of expired deployment records, and confirm returned source data timestamps match actual change times.

The values provided here are common starting points, and should be evaluated against corresponding samples.
