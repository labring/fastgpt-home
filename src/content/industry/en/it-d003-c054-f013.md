# Security and Compliance Material Review for Container Platform Operations: Permissions and Data Isolation

## What Data for This Category Looks Like
Data for this category primarily comes from Kubernetes APIs, image registries, monitoring systems, and CI pipelines. Daily generated documents include cluster change tickets, namespace quota tables, deployment records, and fault reports.
Cluster change tickets record change times, affected namespaces, and adjusted resource parameters. Namespace quota tables list namespace names and CPU, memory quota limits. Deployment records retain application versions and deployment node information. Fault reports include anomaly occurrence times and troubleshooting steps.
Data update frequency is daily or after each cluster change.

## Constraints Imposed by These Characteristics on Permissions and Data Isolation
The diversity of data sources requires permission isolation to cover access permissions across multiple systems, preventing cross-system data leaks.
Differences in field attributes across documents require permission configurations to be segmented by document type. For example, only cluster administrators are allowed to modify core fields of namespace quota tables.
The relatively high data update frequency means permission changes must take effect synchronously, with no delayed processing allowed.
Consequences of errors such as business interruptions and resource preemption require permission isolation to include operation auditing and abnormal interception mechanisms, restricting unauthorized resource adjustment operations.
The data association between CI pipelines and image registries requires permission isolation to cover the full link from code submission to image deployment, preventing unauthorized images from being deployed to clusters.

## Configuration Settings
The following configuration items apply to FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Unique identifier bound to the cluster namespace | Matches the namespace isolation logic of the container platform, ensuring permission scope aligns with actual resource boundaries |
| `tmbId` | Unique identifier configured per cluster node group | Implements node-level data isolation, preventing cross-node resource access conflicts |
| Permission audit log retention period | 7 days | Meets compliance review log retention requirements while controlling storage resource usage |
| Maximum concurrent operations per namespace | 10 operations per minute | Prevents resource preemption and avoids cluster overload that impacts business operations |
| Unauthorized operation interception threshold | Calibrated via actual testing | Adapts to the load conditions of different clusters, avoiding false interception of normal maintenance operations |

## Three Common Misconfigurations
- Custom plugin input and output parameters do not display after adding them to a workflow task. The cause is failure to correctly configure the association between `teamId` and the plugin's deployed namespace, resulting in hidden parameters due to failed permission verification.
- Multiple team accounts cannot log in to the same team. The cause is failure to correctly set the binding relationship between `tmbId` and team members, resulting in failed permission verification that cannot recognize valid accounts.
- Historical version data lacks the `tmbId` field. The cause is that the old version configuration did not enable the `tmbId` field generation logic synchronously, resulting in existing data not carrying this identifier.

## How to Verify Correct Configuration
- Attempt to perform a cluster change operation in an unauthorized namespace, confirm that the operation is intercepted and returns an insufficient permissions prompt.
- View the permission audit log, confirm that all operations are associated with the correct `teamId` and `tmbId` identifiers.
- Verify the multi-account login to the same team function, confirm that different accounts can access resource data of their corresponding namespaces.
- Check historical version data, confirm that newly added versions all include the `tmbId` field.
