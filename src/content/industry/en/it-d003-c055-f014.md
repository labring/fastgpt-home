# Security and Compliance Material Review for Capacity Planning and Resource Scaling: Model Access and Configuration

## What Data This Category Includes
The data for this category mainly comes from cloud bills, monitoring systems, business forecast reports, and stress test results. Daily produced documents include capacity planning reports, expansion application forms, resource utilization reports, and budget calculation sheets. Update cycles are mostly weekly or monthly. Data fields include resource types such as CPU, memory, storage, usage values for corresponding time periods, business peak forecast values, procurement budget amounts, and more. There is no unified mandatory format, and adjustments must be made in accordance with internal enterprise operation and maintenance specifications.

## What Constraints These Characteristics Impose on Model Access and Configuration
The data for this category has scattered sources, non-standardized document structures, and long update cycles. This requires the model access link to adapt to multi-source data call requirements, and to configure interface parameters compatible with multiple channels. Low-frequency, high-volume document content requires context parameters to reserve sufficient token space to fully read files such as capacity planning reports and budget calculation sheets. Non-standardized field formats require flexible model call parameters to adapt to different input structures. Configuration errors may cause peak failures or resource waste, so failure retry and load balancing configurations for model access must meet stability requirements for operation and maintenance scenarios.

## How to Configure Parameters
This applies to FastGPT v4.17.0. The following are server environment variables and model access parameter configurations required for this version. `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` must be configured as environment variables for the App/Admin server. Do not fill these values in the model access interface, workflow global variables, or application API requests.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, such as `http://aiproxy:3000`. Do not append paths like `/v1` or `/chat/completions`. Do not configure this as a single model service address | Required environment variable for FastGPT App/Admin server. Used to specify the AI Proxy service address, ensuring model calls are forwarded through AI Proxy |
| `AIPROXY_API_TOKEN` | Enter the administrator token matching the AI Proxy server configuration. Do not leave this blank | Required environment variable for FastGPT App/Admin server. Used for AI Proxy service authentication. Do not use application API keys, model vendor keys, or other types of tokens |
| `maxContext` | 8000–12000 token | Adapt to full reading of long documents such as capacity planning reports and budget calculation sheets, avoiding content truncation that affects analysis accuracy |
| `temperature` | 0.2–0.4 | Maintain consistency of analysis results, preventing non-standardized operation and maintenance documents from generating resource configuration recommendations that deviate from actual conditions |
| `maxTokens` | 2000–3000 token | Limit the length of single-round model output, adapting to structured report generation requirements for operation and maintenance scenarios, avoiding processing delays caused by overly long outputs |
| `toolChoice` | auto | Allow the model to independently choose whether to call data tools, adapting to real-time query requirements for multi-source operation and maintenance data |

## Three Common Configuration Errors
- Symptom: Frequent timeouts or unresponsive channels during model calls, with status codes 503 or 429 returned. Troubleshooting steps: Check if the load balancing rules for model channel configurations are active. Confirm that no single interface bears all call requests, exceeding its carrying limit. Also check if `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured as server environment variables. Missing required variables will cause startup verification failures.
- Symptom: Model output includes extra thought process logs, and the requirement to return only compliance review results is not met. Troubleshooting steps: Check if the model's chain-of-thought output switch is turned off, or if the `toolChoice` parameter configuration logic matches expectations. Verify whether extra logs are returned along with the main content.
- Symptom: Some files are not fully read during batch processing of capacity planning documents. Troubleshooting steps: Check if the `maxContext` parameter value is too small. Confirm that long documents are not truncated, and that core fields such as resource usage and budget amounts required for compliance review can be fully extracted.

## How to Confirm Successful Configuration
- Invoke the test interface with a standard capacity planning report, then verify that the returned result includes core fields such as complete resource usage, peak forecasts, and budget calculations. Field integrity must meet the specification requirements of enterprise operation and maintenance documents.
- View model call logs, confirm that the request address matches the `AIPROXY_API_ENDPOINT` server environment variable configuration, and that the authentication token passes verification with no permission errors.
- Simulate multiple concurrent requests, observe the response stability of model calls, confirm that load balancing rules are active, and that no single interface is overloaded.
- Adjust the `temperature` parameter to different ranges, verify the consistency of output results, and confirm that the parameter configuration affects the analysis logic as expected.
