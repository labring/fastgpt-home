# Security and Compliance Material Review for Object Storage and Backup Services: Document Parsing and Chunking

## What Data in This Category Looks Like
Daily documents for this category fall into four main types: bucket configurations, backup policies, recovery records, and lifecycle rules. Data sources include object storage consoles, backup systems, access logs, and customer policy tables.
Document structures combine structured configuration items and unstructured descriptions. Fields include Bucket name, permission policy entries, backup retention periods, recovery task IDs, and others.
Update frequency is either daily synchronization or real-time updates when policies change.
The most time-consuming daily tasks are permission policy verification, backup task monitoring, and recovery spot checks. Processing errors may lead to data leaks, backup failures, or unavailable recovery.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Link
Documents in this category include structured configuration items and unstructured descriptions, with scattered data sources and varying update frequencies.
First, structured fields such as Bucket name and permission policy entries must retain their associated relationships. Chunking must not damage the integrity of permission logic.
Second, when batch processing documents from multiple sources, metadata structures of different formats must be adapted to avoid loss of key configuration information during parsing.
In addition, updates to backup policies and lifecycle rules are triggered by business changes. The parsing process must support incremental parsing to reduce repeated processing overhead.
Recovery records include traceable task IDs and timestamps. Chunking must retain metadata associations to enable quick location of corresponding backup tasks during compliance reviews.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Backup files and bucket configuration files for this category typically do not exceed 1000 MB per file; exceeding this size may trigger upload timeouts |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Bucket configuration and backup policy files may contain a large number of permission entries, requiring sufficient time to complete full parsing |
| `chunkSize` | `800–1200 characters` | Documents in this category combine structured configurations and descriptions; this length preserves the integrity of a single policy or paragraph of description |
| `chunkSplitter` | Split by line breaks and configuration item boundaries | Documents in this category take structured configuration items as core units, and the complete logic of configuration items must be retained |
| `customPdfParse` | Enabled | Backup policies and recovery records for this category are mostly PDF files exported from consoles; custom parsing optimizes structured content extraction |
| `chunkSettingMode` | Manual configuration | Document formats vary widely for this category; manual configuration allows adaptation to different types of business documents |

## Three Common Mistakes
- Issue: An error occurs when processing PDF files after deploying Marker, and the interface displays parsing failure status code 500. Cause: The Marker environment variable pointing to the object storage temporary file directory was not configured correctly, causing the parsing process to fail to read the uploaded PDF source file.
- Issue: After setting a custom splitter, chunking results either merge multiple configuration entries or split a single permission policy into multiple chunks. Cause: The `chunkSize` parameter was not adjusted to match the average length of configuration items, and the splitter and chunk length were not aligned, leading to chaotic chunking logic.
- Issue: Uploading a PDF backup policy file larger than 3 MB triggers an upload failure error. Cause: The `UPLOAD_FILE_MAX_SIZE` parameter was not adjusted, and the default value is insufficient to accommodate large PDF export files for this category.

## How to Confirm Configuration Is Correct
- A typical bucket configuration file for this category may be uploaded, and parsing results in the FastGPT v4.17.0 console checked to confirm that single permission policies are not split or merged.
- Parsing logs may be reviewed to confirm that PDF file parsing time does not exceed the duration set by `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout errors.
- After adjusting the `chunkSize` parameter, the backup policy file may be re-uploaded, and the content association of the chunked results compared to ensure that the associated relationships of configuration items are complete.
- A test file of approximately 1000 MB may be uploaded to verify that the upload process does not trigger size limit errors.
