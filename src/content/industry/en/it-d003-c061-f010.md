# Security and Compliance Material Review for Performance Testing and Capacity Evaluation: Citation Sources and Traceability

## What Data for This Category Looks Like
Data sources for this category include operational data collected by stress testing platforms, link latency monitored by APM tools, query bottlenecks recorded in database slow logs, and peak thresholds from production traffic baselines. Daily generated documents include stress testing plans, capacity evaluation reports, stress testing data records, and optimization suggestion sheets. Data is updated monthly or when major versions are released. Data fields include throughput (unit: requests/second), average latency (unit: milliseconds), CPU/memory usage rate, remaining resource capacity (unit: GB), and core content such as stress testing model configurations and bottleneck location conclusions.

## Constraints Imposed on Citation Sources and Traceability
Data sources for this category are scattered and mostly technical monitoring data. Corresponding records from multiple data sources such as stress testing platforms and APM monitoring tools must be associated during citation and traceability to avoid limitations of a single data source. Data update frequency is low, but changes significantly during major version iterations. The corresponding version of the dataset must be bound during citation to ensure traceability consistency. Daily documents include multiple types of professional technical files, and most fields are performance-related quantitative indicators. Field names and units must be accurately matched to avoid indicator confusion. Additionally, since this category focuses on throughput, latency, and remaining resource capacity, the collection scenario of the corresponding indicator must be clearly marked when citing. If traceability fails, performance evaluation conclusions may be distorted, leading to issues such as peak-time timeouts, insufficient resource procurement, or over-provisioning.

## Configuration Settings
The following configurations are formulated based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Adapt to the content length of long documents such as capacity evaluation reports and stress testing data records, and avoid truncating core performance indicators |
| `responseData` | Return only associated documents | Limit returned content to citation sources directly related to performance testing indicators, filtering out irrelevant non-business content |
| `detail` | Display full citation metadata | Include the file name, collection time, and corresponding indicator fields of the cited document to meet traceability requirements for compliance reviews |
| Citation data source scope | Stress testing platforms, APM monitoring, database slow logs | Cover the core data sources of this category to ensure completeness and accuracy of citations |
| Version lock switch | Enabled | Bind data update version nodes to prevent traceability failure caused by data iteration |

## Three Common Configuration Errors
- The `quote type error` alert appears: A prompt indicating invalid parameter format is displayed on the interface. The cause is that the cited performance indicator field does not match the preset quantitative field rules, or the input variable format does not meet system requirements.
- The drop-down menu only shows a single selectable variable: Multiple stress testing indicators or documents cannot be selected as citation sources. The cause is that multi-variable citation configuration is not enabled, and the system only supports single-variable association by default.
- Citation content does not display file addresses: The storage path or collection source of the cited document is not included in the response. The cause is that the metadata display switch for the `detail` configuration is not enabled, and only the indicator content is returned without traceability information.

## How to Verify Proper Configuration
- Submit a test request containing a performance indicator query, and check whether the returned result includes citation records from at least two different data sources.
- Trigger a citation test with format exceptions, and verify whether the `quote type error` alert disappears after adjusting the configuration.
- View the citation configuration panel, and confirm that the value of `quoteMaxToken` matches the average length of documents in this category.
- Generate a simulated capacity evaluation report query, and check whether the returned result includes metadata such as the document file name and collection time.
