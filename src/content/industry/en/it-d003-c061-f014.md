# Security and Compliance Material Review for Performance Testing and Capacity Assessment: Model Access and Configuration

## What this category of data looks like
This category of data mainly originates from pressure testing platforms, APM monitoring systems, database slow logs, and production traffic baselines. Daily documents include pressure testing plans, capacity assessment reports, pressure testing data records, and optimization suggestion sheets. Data updates occur monthly or when major versions are released.
Data fields include throughput rate, latency, resource occupancy rate, and peak concurrent count. Their units are requests/second, milliseconds, percentage, and concurrent count respectively.
Core processing links focus on pressure testing model design, bottleneck indicator identification, and capacity conclusion review. Results directly relate to service stability during peak business hours and the rationality of resource investment. This content is written based on FastGPT v4.17.0.

## What constraints do these characteristics impose on model access and configuration
Scattered data sources and fixed update rhythms require model access to support scheduled tasks for pulling multi-source data, to avoid frequent pulling that occupies pressure testing and monitoring resources.
Daily documents have standardized structures and clear fields. The model must recognize fixed-format pressure testing indicators without additional adaptation for different source document formats.
Core indicators such as throughput rate and latency have high real-time requirements. Configure appropriate context length and response parameters to ensure analysis results match business iteration rhythms.
Capacity assessment conclusions must be rigorous and traceable. Enable relevant result reference configurations to support traceability for security and compliance reviews.

## How to set the configurations
| Configuration Item | Recommended Value | Basis for This Setting |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | As an environment variable for the App/Admin server, specify the access address of the AI Proxy service to ensure valid communication between services |
| `AIPROXY_API_TOKEN` | Fill in the administrator token consistent with the AI Proxy server configuration. This value cannot be empty | As an environment variable for the App/Admin server, used for identity authentication with the AI Proxy service, meeting compliance review requirements |
| `maxContext` | 8000–12000 token | Adapt to the average length of documents such as pressure testing reports and capacity assessment reports, avoid context truncation that causes loss of key indicators |
| `maxTokens` | 2000–3000 token | Control the length of the model's output capacity assessment conclusions, ensure results are concise and cover core optimization suggestions |
| `quoteMaxToken` | 1000 token | Limit the length of referenced pressure testing data fragments, enable quick location of indicator basis during compliance reviews |
| `temperature` | 0.3–0.5 | Reduce output randomness, ensure the rigor and consistency of capacity assessment conclusions |

## Three common misconfigurations
- After selecting a simplified model, the workflow fails to load normally. The cause is that the permissions and call path of the corresponding model are not associated in the model access configuration, causing the system to fail to recognize available models.
- Model calls time out or respond too slowly. The cause is that `maxContext` and response timeout parameters are not properly configured, causing the model to process overly long pressure testing data contexts that exceed the system resource carrying limit.
- Model testing passes on third-party platforms but throws errors in FastGPT. Troubleshooting steps: Check if the `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` configured on the App/Admin server are consistent with the AI Proxy server configuration. Missing required configuration items will cause startup verification to fail.

## How to confirm the configuration is correct
- Verify the content filled in for `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` to ensure they are consistent with the AI Proxy server configuration.
- Run a single model analysis task for pressure testing data, check if the output results include complete core indicators such as throughput rate and latency, with no obvious context truncation.
- View the reference fragments in the model output, confirm that the `quoteMaxToken` configuration meets the fragment length requirements during compliance reviews.
- Adjust the `temperature` parameter and compare two output results, confirm that output consistency meets the rigor requirements of capacity assessment.
