# Safety and Compliance Material Review for Delivery Effect Optimization: Conversation Logs and Auditing

## What This Category’s Data Looks Like
Data for this category primarily comes from ad platform backend data, attribution systems, CRM lead databases, and landing page traffic statistics tools. Update frequencies are mostly real-time or daily batch updates. Daily generated documents include delivery daily reports, delivery weekly reports, material price adjustment records, material A/B test ledgers, and optimization review reports. Common data fields include session ID, associated ad account ID, material code, original operation instructions, response adjustment content, and session timestamp. No fixed mandatory units are used; values adapt to associated business data.

## Constraints Imposed on Conversation Logs and Auditing Workflows
Since data updates are mostly real-time or daily batch updates, the conversation logs and auditing workflow must support quick filtering by session timestamp to meet frequent abnormal indicator locating needs. Storing logs with business fields such as associated ad accounts and material codes helps quickly align delivery adjustment operations with conversation interaction content, reducing cross-system verification costs. Daily generated delivery reports, price adjustment records and other documents require audit logs to be exported as entries matching business document formats for compliant archiving. In scenarios where multiple accounts share an application, logs must be isolated by session initiator or associated ad account to prevent unauthorized access. At the same time, compliance review requirements mandate retaining complete conversation requests and response content, with no arbitrary truncation of key parameters.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Log retention period | `30–90 days` | Matches business review cycles and compliance archiving requirements |
| `detail` log detail switch | Enabled | Meets compliance review requirements for retaining complete conversation content |
| `chatId` associated field configuration | Bound to ad account ID | Enables quick filtering of session logs by business dimension |
| Maximum length of single session log | `8000–12000 characters` | Prevents truncation of complete optimization instructions and response content |
| Log export format | CSV format | Adapts to import and verification needs of daily delivery reports |
| `responseChatItemId` associated configuration | Bound to material code | Aligns conversation interactions with material adjustment operations |

## Three Common Configuration Mistakes
- Symptom: Console.log output from code execution modules does not appear in log previews. Cause: The log detail switch corresponding to the `detail` parameter is not enabled. Basic logs alone do not capture console output content.
- Symptom: When multiple accounts share an application, accounts that did not initiate a session can view other accounts' conversation records. Cause: Log storage is not isolated by session initiator or user identifier bound to `chatId`, resulting in unsegmented log permissions.
- Symptom: In conversation records created via API, the Human input field displays as null. Cause: Session identifier parameters are not passed correctly, resulting in logs failing to capture complete user input content.

## How to Verify Proper Configuration
1. Access the FastGPT v4.17.0 backend, navigate to the log management page of the corresponding application, select filtering by ad account ID, and verify that complete logs for the corresponding session can be retrieved.
2. Trigger a conversation including a code execution module, review log details, and confirm that console.log output content is included when the `detail` parameter is enabled.
3. Call the API to create a session, review the page log list, and verify that API-generated sessions display normally and the `chatId` field is correctly populated.
4. Switch between different test accounts to initiate conversations, verify that only session logs initiated by the active test account are visible, with no cross-account access.
