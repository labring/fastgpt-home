# Safety and Compliance Material Review for Delivery Effect Optimization: Citation Sources and Traceability

## What the data for this category looks like
Daily data sources for delivery effect optimization include advertising platform data, attribution systems, CRM leads, and landing page data. Update frequency is daily or real-time.
Daily documents fall into four categories: daily/weekly reports, price adjustment records, material test sheets, and optimization reviews. Daily/weekly reports summarize daily delivery metrics and results. Price adjustment records track adjustment times, bids, and plan IDs. Material test sheets count material IDs, test channels, and click-through rates. Optimization reviews record adjustment actions and result changes. Most data fields are structured identifiers and quantitative indicators, with no complex nested content.

## What constraints do these characteristics impose on the citation sources and traceability link
Data for delivery effect optimization is multi-source, scattered, and updated frequently. This requires the traceability link to associate unique identifiers across multiple systems, such as ad plan IDs and material IDs, to avoid confusion across documents.
There are diverse document types including structured tables. This requires the traceability link to retain the original document’s field structure, ensuring precise matching of corresponding data during citation.
The real-time update feature requires the traceability link to support incremental synchronization, avoiding repeated processing of old data. It is also necessary to control the number of returned entries to meet the efficiency requirements of real-time review.

## How to configure the settings
This configuration applies to FastGPT v4.17.0 and above versions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context token count | 800–1200 token | Adapts to the short-text and structured table characteristics of daily delivery optimization documents, balancing context completeness and overflow risk |
| Associated source return limit | Top 3 entries | Aligns with the multi-source and scattered nature of delivery data, improving real-time review response speed |
| Metadata traceability toggle | Enabled | Requires association with key identifiers such as ad plan IDs and material IDs, fully extracting metadata to complete precise compliance reviews |
| Document format retention | Original structure | Meets the field display requirements of structured documents like price adjustment records and material test sheets, avoiding loss of key identifiers during citation |
| Incremental synchronization toggle | Triggered daily | Matches the daily/real-time update rhythm of delivery data, reducing resource usage from repeated traceability |

## Three common mistakes
- Phenomenon: Only plain text is displayed in context citations, and Markdown formats such as tables and bold cannot be retained. Cause: The document format retention configuration is not enabled, only plain text content is extracted, and the original document’s structure and field information are not associated.
- Phenomenon: Some questions cannot be associated with the corresponding delivery data document, and an empty source list is returned. Cause: The metadata traceability toggle is not configured, so key associated fields such as ad plan IDs and material IDs cannot be extracted, and precise matching of cross-system documents cannot be completed.
- Phenomenon: Context overflow causes review interruption, with an error prompt returned. Cause: The maximum context token count is set too low, and cannot accommodate the fully associated content of multiple documents such as delivery daily reports and price adjustment records.

## How to confirm the configuration is correct
- Upload a price adjustment record or material test sheet, initiate a query that includes document fields, and check if the returned citation sources include the corresponding document identifiers and field information.
- Adjust the maximum context token count setting, initiate a query that includes multiple delivery documents, and verify that associated sources can be fully displayed without overflow errors.
- Disable the metadata traceability toggle, initiate a query, and check if the returned citations only include plain text with no structured field information, confirming that the configuration takes effect.
- Simulate updated delivery data, initiate a query associated with the new data, and verify that the incremental synchronization configuration can correctly associate the latest document content.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
