# Security and Compliance Material Review for Delivery Effect Optimization: Permissions and Data Isolation

## What This Category of Data Looks Like
Data for this category primarily comes from advertising platform APIs, attribution systems, CRM lead databases, and landing page tracking data. Four main document types are accumulated daily: daily and weekly reports, price adjustment records, material test sheets, and optimization review documents.
Update frequency is mostly daily or real-time. Each data entry includes fields such as ad plan ID, impressions, clicks, conversion cost, material ID, and landing page jump link. Units include times, yuan, items, hours, and others. There is no unified fixed format, and business attribution is distinguished by document naming and field comments.

## What Constraints These Characteristics Create for Permissions and Data Isolation
The scattered sources and dynamic update nature of this category's data create multiple constraints for permissions and data isolation.
Multi-source data must be managed in layers according to business links to prevent unauthorized access across advertising platforms and attribution systems. Non-uniform format documents such as daily reports and price adjustment records must be grouped using `teamId` and `tmbId` to avoid cross-team data confusion. Sensitive documents containing budgets and conversion costs must be restricted to only viewable by corresponding project members. Real-time delivery indicator data requires permission checks to adapt to low-latency requirements, so as not to interfere with real-time adjustments to delivery effects.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `teamId` binding rule | Bind a dedicated ID per advertising project | Matches the project grouping logic of delivery effect optimization, ensuring that project members only access corresponding data |
| `tmbId` resource grouping | Split grouping by two document types: materials and price adjustment records | Distinguishes document permissions for different business types, preventing sensitive data leaks across types |
| Real-time data permission check latency | No more than 200 milliseconds | Adapts to the real-time adjustment needs of delivery effect optimization, avoiding delays that impact delivery decisions |
| Sensitive document storage quota | `1000 MB` | Adapts to the storage requirements of daily delivery data for a single project |
| Sensitive document edit permissions | Only project creators and designated optimizers can edit | Matches the sensitive nature of this category's documents, which contain budgets and conversion costs |

## Three Common Misconfigurations
- An interface error occurs after configuring `teamId`, and forced ignoring allows it to run in references. Cause: No binding verification was performed between `teamId` and the data source of the current advertising project, resulting in a mismatch between the permission check logic and the actual data link.
- Unable to view cross-project material test sheet data. Cause: `tmbId` resource grouping was not configured correctly, with material documents from different projects assigned to the same group.
- Unable to generate team invitation links in a local deployment environment. Cause: The team collaboration module configuration for FastGPT v4.17.0 was not enabled; this function is disabled by default.

## How to Confirm the Configuration Is Complete
- Log in to the account corresponding to `teamId`, attempt to access price adjustment record documents from a different project, and confirm that access is denied or a permission insufficient prompt is displayed.
- Submit a query request for real-time delivery data, and check whether the permission check latency meets the delay requirements for business adjustments.
- Switch accounts for different `tmbId` groups, and confirm that only material test sheets and daily reports within the corresponding group can be accessed.
- Check the edit permissions of sensitive documents, and confirm that only designated members can modify fields related to budgets and conversion costs.
