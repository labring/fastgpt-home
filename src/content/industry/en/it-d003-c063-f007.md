# Security and Compliance Material Review for Campaign Setup: Conversation Logs and Auditing

## What this category's data looks like
Data for this category primarily comes from advertising platform backends, budget scheduling sheets, conversion attribution tools, and user profile datasets. Core daily produced documents include campaign plans, targeting setting rules, budget allocation plans, and conversion tracking configuration items.
Most data updates occur via daily synchronization or single event-triggered updates.
Document fields include plan unique identifier, targeting audience package code, daily budget limit, conversion event type, and more. Some fields have corresponding business units: budget uses yuan as the unit, conversion events use times as the statistical unit.

## What constraints these characteristics impose on conversation logs and auditing
Core data for campaign setup is linked to account structure configuration before ad launch. Data changes directly affect campaign launch status. Conversation logs must fully record the context of every configuration modification.
Dispersed data sources require logs to associate synchronization status across multiple systems. Log entries from different sources must match the corresponding campaign plan ID.
Uncertain update frequencies require audit logs to support filtering by campaign cycle or time range. This prevents redundant data accumulation.
Compliance verification for conversion tracking configurations requires associating parameter modification records from historical conversations. Every adjustment must have traceable operation records.

## How to configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Conversation Log Association Identifier | Bind `chatId` and `responseChatItemId` | Ensures logs only associate with operations for the current campaign plan, avoiding cross-plan data confusion |
| Log Detail Field | Enable `detail` parameter | Meets full-process traceability requirements for compliance audits, records complete parameters for targeting settings and budget adjustments |
| Log Retention Period | 180 days | Matches standard compliance audit cycles for the advertising industry |
| Log Sync Trigger Timing | Triggered on configuration submission action | Ensures audit records are generated immediately for every campaign plan modification |
| Log Query Limit | Top 1000 entries | Controls resource consumption for single queries, fitting daily auditing scenarios |
| Log Format Compatibility | Compatible with FastGPT v4.17.0 | Ensures log format matches the current platform version |

## Three common errors
- Calling the interface to retrieve conversation records returns an empty list. Cause: The `chatId` parameter for the target campaign plan is not bound, so the system cannot match the target context.
- An interface error appears after configuring the token, and the log shows the token as "fastgpt". Cause: The token configuration is not associated with the exclusive auditing permission for the campaign plan. The system uses the universal token by default, causing verification failure.
- Inconsistent historical conversation rounds after multiple accesses to the same campaign plan ID. Cause: The association rule for `responseChatItemId` is not fixed, leading different calling requests to read log fragments from different time periods.

## How to confirm configuration is complete
- Submit a modification to the targeting settings of a campaign plan, check if the system generates an audit log with a complete `detail` field.
- Enter the target `chatId` to query logs, confirm only conversation records for the current campaign plan are returned, with no cross-plan data mixed in.
- Adjust the log retention period configuration, verify that the system automatically cleans up expired logs according to the set 180-day cycle.
- Export a log file for a specified time period, confirm the format meets preset standards and can be directly imported into data analysis tools.
