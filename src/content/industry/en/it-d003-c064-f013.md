# Security and Compliance Material Review for Bid Document Preparation: Permissions and Data Isolation

## What this category of data looks like
The core documents for this category are bid documents, qualification certificates, commercial deviation tables, and technical deviation tables. Data sources include tender announcements, bidding documents, enterprise qualification databases, and supplier quotations. The update frequency is once per individual bid project. Document structures strictly follow the format requirements of the tenderer, with fixed fields including bidder qualification numbers, quoted amounts, and clause response content. No redundant general business data is included. Data is only generated and used during the corresponding bid project cycle, and is uniformly archived after the project ends.

## What constraints these characteristics impose on permissions and data isolation
Data sources for this category are scattered and tied to core bid qualifications. The update rhythm for each individual project is independent. A cross-project data leak or permission escalation could directly lead to bid disqualification, score deductions, or earnest money losses. Document structures are fixed, with sensitive fields concentrated. Access must be strictly controlled per project dimension to avoid mixing qualification and quotation data across different bid projects. Participants are mostly from commercial and pre-sales teams. Minimal permissions must be assigned per project to prevent unauthorized personnel from accessing incomplete bid materials.

## Configuration Settings
This page’s configuration is based on FastGPT v4.17.0. Below are permission and data isolation configuration recommendations adapted for the bid document preparation scenario.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind a unique `teamId` to a single bid project, use the unique identifier string registered for the project | Each bid project’s data is isolated, preventing cross-project permission leaks, and aligns with the business rhythm of per-project updates |
| `tmbId` | Bind the `teamId` scope to project-authorized members, use the collection of authorized personnel’s `tmbId` values | Only commercial and pre-sales personnel participating in the corresponding bid project are allowed to access sensitive data, matching the permission requirements of participating teams |
| Sensitive Data Encryption Rule | Automatically encrypt qualification certificates and supplier quotation documents, trigger encryption when file size exceeds 100 KB | Qualification materials and quotations are core sensitive data, requiring targeted encryption to ensure storage security |
| Permission Check Trigger Timing | Trigger checks during document upload, editing, and download | Bid data is updated frequently; real-time checks can intercept unauthorized operations in a timely manner |
| Project Data Isolation Scope | Divide storage path prefixes by `teamId`, use `/project/{teamId}/` | Ensures physical isolation of documents across different projects, preventing cross-data access |

## Three Common Misconfigurations
- Phenomenon: After adding a custom plugin, no input or output parameters are displayed in workflow tasks, and no error logs are generated. Cause: The plugin is not bound to the project corresponding to the `teamId`, causing the permission check to block the plugin parameter loading process.
- Phenomenon: After local deployment, multiple accounts cannot share bid project data. Cause: No cross-account binding rules for `teamId` are configured; by default, only the project creator is allowed to separately access the corresponding bid data.
- Phenomenon: After connecting SSO authentication, bid documents cannot be accessed. Cause: The SSO user’s `tmbId` is not mapped to the authorized scope of the corresponding bid project, resulting in a failed permission check.

## How to Verify Proper Configuration
- Upload a qualification certificate document, verify that only authorized team members can retrieve the file in the document list for the corresponding project.
- Use a non-authorized account to attempt to access the bid documents for the target project, confirm that the system returns a permission denied prompt.
- Run a workflow that includes a custom plugin, verify that input and output parameters load normally and are displayed in the task configuration interface.
- After configuring SSO authentication, log in with an SSO account bound to project permissions, confirm that authorized bid project data can be accessed normally.
