# Security and Compliance Material Review for Database Cloud Service Operations: Citation Sources and Traceability

## What data in this category looks like
Data in this category typically originates from cloud database consoles, slow logs, monitoring metrics, and ticketing systems. Update cadences follow either daily synchronization or real-time updates triggered by configuration changes. Daily documents include instance change orders, backup and recovery records, performance diagnostic reports, and parameter adjustment records. A single document usually contains fields such as instance identifier, operation time, operator, associated resource path, and performance metric values. Some documents include millisecond-level time units and GB-level storage capacity units.

## What constraints do these characteristics impose on the citation sources and traceability workflow
Data sources for this category are scattered and have diverse formats, creating multiple constraints for the citation traceability workflow. Data sources across cloud service modules must be associated via a unified instance identifier field; otherwise, operations and corresponding documents cannot be accurately matched. Update cadences vary significantly across different data sources: real-time generated slow logs and periodically archived backup records require adapting to different index update frequencies to ensure traceability data timeliness. Diverse document types correspond to different metadata structures, so targeted field extraction is needed to retain core traceability information such as operator and change time. Some documents include unit-attached values such as performance metrics and storage capacity; unit information must be fully retained to ensure traceability content accuracy. In multi-tenant scenarios, document data from different customers must be strictly isolated to prevent cross-tenant leakage of traceability results.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of database operation and maintenance documents, avoiding truncation of core traceability information |
| `responseData` | Enabled | Returns complete citation source metadata, including document source paths and field information |
| `detail` | Enabled | Displays complete field content of traceability documents, not limited to titles |
| Number of citation sources displayed | Top 3–5 entries | Controls the density of traceability information per conversation, avoiding content overload |
| Traceability data synchronization frequency | Calibrated based on actual testing | Adapts to update cadences of different data sources, balancing timeliness and resource usage |

## Three Common Misconfigurations
- Symptom: Citation lists only display document titles and do not show core field content. Cause: The `detail` configuration item is not enabled, and only the title field of document metadata is extracted.
- Symptom: Cross-tenant document information appears in traceability results. Cause: Multi-tenant data isolation rules are not configured, resulting in no permission isolation between customer document indexes.
- Symptom: Citation content is truncated, making complete change records unavailable. Cause: The value of `quoteMaxToken` is too small; document content is automatically truncated after exceeding the configured token limit.

## How to Verify Proper Configuration
- Initiate a conversation containing keywords related to database operation and maintenance, check the citation module in the returned results, and confirm that complete document field information is displayed.
- Switch to different test tenants, initiate a conversation, and confirm that the returned citation documents only belong to resources under the current test tenant.
- Adjust the value of `quoteMaxToken`, initiate a query containing a long document, and confirm that the truncation of citation content matches expectations.
- Check the FastGPT v4.17.0 system logs to confirm that the traceability data synchronization frequency matches the configured update strategy.
