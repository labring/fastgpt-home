# Security and Compliance Material Review for Database Cloud Service Operations: Permissions and Data Isolation

## What this category’s data looks like
This category of data primarily comes from cloud database consoles, slow logs, monitoring metrics, and ticketing systems. Daily produced documents include instance change orders, backup and restore records, performance diagnosis reports, and parameter adjustment records. Data is updated either via daily synchronization or in real time following configuration changes. Individual records contain fields such as instance identifier, operator account, change time, and associated ticket number. Some monitoring metrics record performance and storage status in units of milliseconds and MB.

## Constraints imposed on permissions and data isolation
Data sources are scattered across cloud database consoles, slow logs, monitoring metrics, and ticketing systems. Permission configurations must cover multiple system modules to avoid cross-platform permission vulnerabilities. Data updates in real time following configuration changes. Permission verification must be tied to operational actions in real time to match the real-time data update rhythm. Daily documents contain sensitive operation records. Permission granularity must be refined to the instance level and operation type to prevent unauthorized modification of backups or parameter adjustments. Multi-tenant service boundaries require strict isolation of different customers’ database data to prevent cross-tenant data leaks and unauthorized access.

## How to configure settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Team permission group binding | Bind `teamId` according to instance ownership | Matches the multi-tenant ownership rules of database cloud services, ensuring only team members can access corresponding instance data |
| Operator permission verification | Enable `tmbId` binding verification | Associates account identifiers from the cloud console, preventing unauthorized execution of instance changes, backup restores, and other operations |
| Sensitive operation approval time limit | Single operation approval time limit no more than 3600 seconds | Matches the review cycle of daily change orders, preventing operation blocking due to approval timeout |
| Cross-tenant data isolation | Divide data isolation scope by instance ID | Complies with multi-tenant service boundary requirements of cloud databases, preventing cross-customer data leaks |
| Permission audit log retention | Retain the most recent 30 days of operation records | Meets log retention requirements for compliance reviews, facilitating traceability of permission usage |

## Three common mistakes
- Symptom: Cross-team knowledge base queries return no relevant content. Cause: The `teamId` of the knowledge base and the `teamId` of the application have not been bound. Permission verification blocks cross-team data access.
- Symptom: Operator identifier fields are empty in background operation logs. Cause: `tmbId` binding verification is not enabled, and cloud console account information is not associated. Permission usage behavior cannot be traced.
- Symptom: Instance parameter adjustment operations do not trigger compliance audits. Cause: Sensitive operation approval rules are not configured. Default settings bypass permission verification and execute operations directly.

## How to confirm configurations are complete
- After performing a login to the FastGPT backend, access the team management page and confirm that each database instance has been bound to the corresponding `teamId`, with no unbound instances across teams.
- Perform a simulated instance change operation, then check that the operation log records complete `tmbId` and operation time information.
- Configure cross-team knowledge base association, then verify that applications with different `teamId` cannot access corresponding knowledge base data.
- Access the compliance audit module and confirm that the approval process for sensitive operations has been triggered normally and operation records are retained.

The values provided are common starting points and should be measured against local samples.
