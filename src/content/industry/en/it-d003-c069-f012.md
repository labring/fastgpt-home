# Security and Compliance Material Review for Database Operations: Document Parsing and Chunking

## What this category of data looks like
Core documents for database operations scenarios fall into four categories: database change tickets, slow SQL reports, backup records, and permission application forms. Data comes from database monitoring systems, audit logs, SQL execution plan files, and internal ticketing systems. Documents are updated per individual database change or daily batch task runs. Each document mixes structured fields and long-form text. For example, change tickets include approval process and change content fields. Slow SQL reports include execution duration, lock wait time, and corresponding SQL statements. Sensitive permission fields and long text SQL fragments are present in documents. There is no unified fixed formatting. Some documents are stored as PDF or structured text files.

## Constraints on document parsing and chunking
The multi-source and mixed structure characteristics of database operation documents create multiple constraints for the parsing and chunking process. First, documents contain sensitive permission fields and long SQL fragments. Chunking must retain the association between fields to avoid truncating critical approval chains or SQL statements. Second, some documents are long-form text generated in batches. Parsing must adapt to content of varying lengths to avoid content fragmentation caused by overly small chunking parameters. Third, some documents are stored as PDF format. Parsing must support field extraction from complex layouts to ensure that metrics and corresponding text in backup records and slow SQL reports are not lost. Finally, documents are updated frequently. Parsing must support fast processing of batch-submitted documents to avoid task failure due to timeout.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the length of long text in slow SQL reports and SQL execution plans, avoiding truncation of critical SQL statements and metrics |
| `chunkSplitter` | Split by paragraph | Matches the approval workflow structure of database change tickets and permission application forms, retaining context between approval nodes and corresponding application content |
| `customPdfParse` | Enabled | Adapts to PDF format documents such as backup records and slow SQL reports, retaining field information and layout logic from the original layout |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for long SQL execution plans and batch audit logs, avoiding parsing timeout failure for long documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to large file upload requirements for batch backup records and audit logs, supporting submission of multiple documents in a single request |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for specific fields in database operation documents, adapting to retention requirements for sensitive permission fields and long SQL fragments |

## Three common configuration errors
- PDF parsing fails in the interface, returning status code 504. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. Parsing time for long audit log PDFs exceeds the default threshold.
- SQL statements and slow query duration metrics are split into different chunks after processing. The cause is selecting character-based chunking instead of configuring `chunkSplitter` to split by paragraph, leading to truncation of critical associated content.
- PDF enhanced parsing functionality cannot be enabled. The cause is failure to enable the `customPdfParse` configuration item, or failure to complete deployment and configuration of the corresponding parsing plugin.

## How to verify configurations are correct
- Upload a database change ticket PDF, and check if the parsed text fully retains contextual association between fields such as change time, applicant, and approval comments.
- Check background logs for parsing tasks to confirm no timeout errors occur, and that the `PARSE_FILE_TIMEOUT_SECONDS` configuration value matches actual parsing time.
- Inspect chunked document fragments to confirm that SQL execution plans and corresponding slow query duration metrics are not split into different chunks.
- Call the FastGPT v4.17.0 API interface to upload a document, and confirm that the returned parsing result includes complete document fields with no missing or truncated content.
