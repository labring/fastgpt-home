# Security and Compliance Material Review for Data Cleaning and Quality Inspection: Model Integration and Configuration

## What the data for this category looks like
Data for this category comes from raw datasets, ETL run logs, annotation platform output results, and sampling quality inspection results. Update frequency follows a daily schedule or per batch task cycle. Daily associated documents include cleaning rule configuration files, quality inspection sampling tables, abnormal data lists, and final delivery reports. No additional custom units are used. Core fields include raw data content, data quality tags, anomaly type identifiers, and sampling verification results.

## What constraints these characteristics impose on model integration and configuration
Dispersed data sources and short update cycles require model integration to support parsing multi-source data formats. Configuration must support dynamic parameter adjustment per task batch. Daily documents are mostly structured rules and lists, so models must support reading structured fields for compliance verification. Configuration must include field mapping adaptation settings. Abnormal data lists and delivery reports require models to output structured results, so configuration must restrict output formats to match downstream document generation requirements. The risk of data unavailability or distorted indicators also requires model integration to include fault-tolerant configuration, to avoid disrupting the overall quality inspection process due to model call failures.

## How to set the configuration
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to multi-field context reading for cleaning rules and quality inspection sampling tables, avoids truncating key compliance verification logic |
| `maxTokens` | 2000–3000 token | Matches the structured output length of abnormal data lists and final delivery reports, ensures complete return of verification results |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures consistency of compliance review results, avoids inconsistent quality inspection standards due to fluctuations |
| `quoteMaxToken` | 500–800 token | Limits the length of referenced data, ensures only necessary abnormal data content is loaded during compliance reviews |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | Used as an environment variable for the FastGPT App/Admin server, specifies the access address of the AI Proxy service, not the address of a single model or third-party model vendor |
| `AIPROXY_API_TOKEN` | Enter the administrator token consistent with the AI Proxy server configuration, and it cannot be empty | Used as an environment variable for the FastGPT App/Admin server, used for identity verification with the AI Proxy service, not a model vendor key or application API Key |

## Three common configuration errors
- A model provider that passes tests in OneAPI returns a 404 error when added to FastGPT for testing. The cause is failure to correctly match the model ID with the model identifier configured in OneAPI, or spelling deviations in the interface address entry.
- When calling the integrated DeepSeek R1 model, the output does not include thought process content. The cause is failure to enable the model's thought process output configuration, or the `temperature` parameter being set too high, resulting in simplified output format.
- In a private deployment scenario, the model inference speed is significantly different from tests on cloud platforms. The cause is the `maxContext` parameter exceeding the server's video memory capacity, or failure to adjust the context window value based on actual tasks.

## How to verify successful configuration
- Execute a model test call, check whether the returned result fields include core content such as abnormal data identifiers and compliance verification conclusions, to ensure they match the fields in the category's abnormal data list.
- View the FastGPT server startup verification logs, confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured and non-empty, with no spelling or format errors.
- Adjust the context length of the test dataset, verify that the `maxContext` parameter can fully load the content of cleaning rules and quality inspection sampling tables without truncation.
- Call the same test dataset multiple times, check the consistency of the output results, and confirm that the `temperature` parameter value meets expectations.

The values provided are common starting points and should be evaluated against the reader's own samples.
