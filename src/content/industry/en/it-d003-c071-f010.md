# Security and Compliance Material Review for Data Masking Processing: Citation Sources and Traceability
This document applies to FastGPT v4.17.0.

## What This Category of Data Looks Like
Data for this category primarily comes from databases, data dictionaries, masking tools, and access approval systems. Daily associated documents include masking plans, field mapping tables, masking validation reports, and approval records.
Data updates follow project batch cycles. Each data entry corresponds to specific sensitive field identification, rule configuration, and validation results. Core fields include sensitive field identifier, masking rule code, source data path, and approval status. There is no unified fixed unit; values adjust dynamically based on project batches.

## What Constraints Do These Characteristics Impose on Citation Sources and Traceability
The data characteristics of this category impose multiple constraints on the citation sources and traceability link.
Multi-source data requirements mean traceability systems must associate metadata from multiple systems including databases and masking tools, to ensure complete visibility of citation content links. Updates tied to project batches require traceability to bind project identifiers and batch numbers, to avoid mixing masked data from different batches. The time-consuming sensitive field identification and rule configuration steps require traceability to retain complete process logs, to support backtracking of configuration processes during compliance audits. The severe consequences of errors require traceability records to be unalterable, and to link approval records as compliance evidence.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of masked text, to avoid truncating critical traceability information |
| `responseData` | Includes source file path, masked field tags | Ensures traceability can locate the specific location of original masked data and processing logic |
| `detail` | Enabled | Retains complete process logs for sensitive field identification and masking rule application |
| Number of citation sources displayed | Top 3 | Avoids overloading the compliance review interface, while covering citation content that forms core review basis |
| Traceability log retention period | 180 days | Meets the basic record cycle requirements for compliance audits |
| Associated document types | Only masking plans, field mapping tables | Filters irrelevant documents, improving the accuracy of traceability queries |

## Three Common Misconfigurations
- Phenomenon: The interface returns empty content after a traceability request is initiated. Cause: The source file path binding for the `responseData` parameter was not enabled correctly, preventing loading of the original masked citation content.
- Phenomenon: Garbled text appears in cited content. Cause: Character encoding was not unified between the masking tool and FastGPT, leading to encoding mismatches during field mapping parsing.
- Phenomenon: Citation source display format is messy and redundant. Cause: No display filtering rules were configured for the `detail` parameter, resulting in direct concatenation of unformatted masked logs and source file information.

## How to Verify Correct Configuration
- Upload a test document containing sensitive fields, run a compliance review, and check if the returned results include source file paths and masked field tags.
- Access the system log page, confirm that complete records exist for sensitive field identification and masking rule application.
- Initiate a batch traceability request, check if the returned content field contains valid masked citation content, with no empty values or garbled text.
- Verify the system storage policy, confirm that the traceability log retention period matches the preset 180-day requirement.

The values listed are common starting points, and should be evaluated against the reader's own samples.
