# Security and Compliance Material Review for Log Platforms and Observability: Document Parsing and Chunking

## What This Category's Data Looks Like
This category’s data comes from logging systems, trace platforms, metrics systems, and application SDKs. Commonly processed documents include log collection specifications, distributed tracing instructions, metric dictionaries, and dashboard configuration records. Data updates occur daily or per version, and include structured tables and unstructured text. Fields include log level, TraceID, metric name, response time unit, and more. Some data contains cross-column associated business logic.

## What Constraints Do These Characteristics Impose on the "Document Parsing and Chunking" Link?
Multi-column structured data requires retaining field association relationships during parsing to avoid truncating cross-column business logic. For scenarios mixing unstructured text and structured data, adapt chunking boundaries for different formats to prevent breaking context associations. Frequently updated data requires chunk processing to support incremental synchronization, avoiding repeated parsing of full content. Information required for link correlation such as TraceID and log context must be fully retained during chunking. Failure to do so will impact fault location and audit trails for subsequent security and compliance reviews.

## How to Configure Parameters
The following configurations apply to FastGPT v4.17.0. Specific parameters must be adjusted based on actual business scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the information density per chunk of log text and metric dictionaries, balancing retrieval accuracy and context completeness |
| `chunkSplitter` | Semantic + fixed-length hybrid | Adapts to structured tables and unstructured log text, retaining field associations and trace ID context |
| `customPdfParse` | Enabled | Adapts to PDF documents such as distributed tracing instructions and collection specifications, retaining typesetting and multi-column table structures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of batch logs and large-volume dashboard configuration records, avoiding timeout interruptions |
| `chunkSettingMode` | Manual configuration | For multi-column Excel and structured log tables, customize chunking boundaries to avoid truncating cross-column associated information |

## Three Common Misconfigurations
- Symptom: After uploading a multi-column Excel metric dictionary, only the first two columns of content are recognized. Cause: `chunkSettingMode` is not set to manual chunking, and the default chunking logic truncates multi-column associated fields.
- Symptom: Parsing a PDF document with `customPdfParse` returns a failure. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a reasonable duration, and large-volume PDF document parsing is interrupted due to timeout.
- Symptom: Boolean data parsed via the HTTP component becomes empty after processing by the conditional judgment component. Cause: The context binding relationship of the boolean field is truncated during chunking, resulting in loss of field association information during parsing.

## How to Verify Correct Configuration
- Upload a single multi-column Excel metric dictionary, and check if the parsed data includes all column fields and content.
- Upload a large-volume PDF distributed tracing instruction document, and confirm that parsing completes within `PARSE_FILE_TIMEOUT_SECONDS`.
- Set `chunkSize` to 800 characters, extract a single chunk of parsed content, and verify that it contains a complete TraceID and associated log context.
- After enabling `customPdfParse`, parse the tables in the PDF document, and confirm that the table structure is not flattened or damaged.

The values provided are common starting points and should be evaluated against samples relevant to the specific use case.
