# Security and Compliance Material Review for Computer Room Inspection and Environmental Monitoring: Citation Sources and Traceability

## What data in this category looks like
Typical users include IDC on-duty operation and maintenance staff, facility engineers, and monitoring center personnel. Daily documents include inspection checklists, temperature and humidity records, alarm logs, and duty logs. Data mainly comes from environmental monitoring systems, access control systems, UPS monitoring equipment, and video inspection tools. Update frequencies are mostly real-time or daily. Each single data entry includes fields such as device ID, timestamp, monitoring value, and alarm level. Temperature and humidity records use degrees Celsius and percentage units. Alarm logs include trigger time and associated device information. The overall structure varies by data source type. Unlike the cabinet installation and wiring category, this category focuses on the continuous operating status of existing computer rooms, so all data consists of real-time or periodic monitoring records.

## What constraints do these characteristics impose on the citation sources and traceability link
Mixed access to multiple data sources requires citation traceability to distinguish document types from different sources, to avoid confusing identifiers between inspection records and alarm logs. Real-time or high-frequency updated data requires configuration of incremental synchronization and expiration cleanup rules, to prevent referencing outdated monitoring data. Field differences across different data sources require the traceability system to match document types with corresponding fields, ensuring that referenced content and identifiers are accurately matched. Additionally, abnormal computer room operations may lead to SLA impairment risks, so the accuracy and timeliness of citation traceability must strictly align with business requirements. No discrepancies between referenced content and actual monitoring data are allowed.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 500–800 characters | Matches the average content length of inspection records and alarm logs, avoids overly fragmented or overly long chunks that affect recall accuracy |
| Maximum Citation Token Count | 800–1200 tokens | Adapts to the total content volume of computer room monitoring data, ensures referenced content is complete and does not exceed the context window limit |
| Context Recall Limit | Top 6 entries | Balances the richness of traceability information and response speed, avoids excessive redundant content interfering with the main reply |
| Citation Source Display Method | Categorized by data source | Matches the multi-data source business scenario, allows operation and maintenance staff to quickly locate corresponding monitoring records |
| Response Data Format | Complete structured data | Ensures valid content returned by the interface can be parsed normally, avoids missing fields or format errors |
| Detail Display Switch | Enabled | Allows display of complete field information for citation sources, meets traceability requirements for compliance reviews |

The above configurations correspond to core parameters in FastGPT such as `quoteMaxToken`, `responseData`, and `detail`. Adjustments can be made via the visual interface or API interface.

## Three common mistakes
- Phenomenon: Calling a local large model interface returns a 200 status code, but the response body has no content field. Cause: Failed to correctly configure the response data format extraction rules, and failed to specify extracting valid content from the corresponding fields in the interface response.
- Phenomenon: The citation sources in the generated reply are poorly formatted, and identifiers for inspection records and alarm logs cannot be distinguished. Cause: Did not display citation sources categorized by data source, and did not enable the corresponding display configuration.
- Phenomenon: Garbled characters appear in referenced temperature and humidity data, such as abnormal characters replacing the degree Celsius symbol. Cause: Did not uniformly configure the encoding formats of different data sources, and did not perform encoding conversion processing for cross-source data.

- Connect different types of data sources, confirm that document identifiers from each source are correctly categorized and displayed.
