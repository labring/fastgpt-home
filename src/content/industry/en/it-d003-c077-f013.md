# Security and Compliance Material Review for Computer Room Inspection and Environmental Monitoring: Permission and Data Isolation

## What the data for this category looks like
The core data for this category comes from four sources: environmental monitoring, access control systems, UPS monitoring, and video inspection. Update frequency is daily or real-time. Daily produced documents include inspection reports, temperature and humidity records, alarm records, and duty logs. Fields include device ID, temperature and humidity values (unit: ℃), voltage values (unit: V), alarm timestamps, access control records, inspector signatures, and more. The text length of a single record ranges from tens to hundreds of characters.

## What constraints do these characteristics impose on permission and data isolation
Real-time updated alarm and temperature and humidity data requires permission checks to match the update rhythm. This prevents unauthorized access caused by delays. Multi-source heterogeneous data sources need to bind permissions by computer room area. This prevents cross-computer room data leaks. Various document types need to divide access scope by job roles. For example, duty logs are only visible to on-duty operations staff. Alarm summary records can be accessed by the monitoring center. Cross-team computer room asset isolation requires strict matching of `teamId` and data ownership. Otherwise, device status information may be leaked. This leads to the risk of device downtime or customer SLA impairment. In addition, inspection records include sensitive information such as personnel signatures. The viewing scope for unauthorized personnel must be further restricted to avoid internal information leaks.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `teamId` | Team identifier bound to computer room assets | Matches the computer room ownership of the data source, ensures data is only visible to authorized teams |
| `tmbId` | Template ID bound to role permissions | Differentiates access permission scopes for operations, administrator, and monitoring roles |
| Real-time data check interval | 60 seconds | Matches the real-time update rhythm of inspection data, blocks unauthorized access in a timely manner |
| Single-request document return limit | Top 20 entries | Limits the number of inspection records returned in a single request, avoids bulk leakage of sensitive data |
| Team data storage quota | 1000 MB | Corresponds to the storage limit for alarm and temperature and humidity records per team, prevents resource abuse |

## Three Common Misconfigurations
- Unable to open the team management page, with an insufficient permissions prompt. Cause: The current account is not bound to the `teamId` of the corresponding computer room, and has no team management permissions.
- Unable to view the model usage of team members. Cause: The administrator permission template corresponding to `tmbId` is not configured, and only basic inspection permissions are enabled.
- Cross-team application calls the knowledge base query with no relevant content. Cause: The `teamId` bound to the application is inconsistent with the team to which the knowledge base belongs, and data isolation blocks the cross-team request.

## How to Confirm the Configuration Is Correct
- Log in to FastGPT v4.17.0, enter the team management page, and confirm that the current account is associated with the `teamId` of the target computer room.
- Switch to an unauthorized team account, attempt to access the inspection data of the target computer room, and confirm that access is denied.
- Submit a simulated alarm record, and confirm that only accounts of the authorized team can retrieve the record.
- View the real-time data check log, confirm that the permission check is triggered every 60 seconds, with no abnormal errors.
