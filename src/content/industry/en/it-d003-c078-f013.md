# Security and Compliance Material Review for Cabinet Rack Installation and Cabling: Permissions and Data Isolation

This configuration is based on FastGPT v4.17.0, and adapts to security and compliance review requirements for cabinet rack installation and cabling.

## What the data for this category looks like
Core data for this category comes from DCIM systems, asset systems, network topology tools, and customer work orders. The update frequency is per order or daily. Daily generated documents include rack installation applications, cabinet cabling diagrams, port label tables, and construction records. Data fields include rack position numbers, port identifiers, cable specifications, construction dates, and customer requirement information.

Data flow centers on the addition or change of physical device access. Different documents correspond to different business links. Access boundaries must be divided by operating role to prevent unauthorized cross-link operations.

## How these characteristics impose constraints on permissions and data isolation
Multi-source data access requires permission isolation covering data sources across different systems, to prevent unauthorized cross-system access.
The per-order or daily update frequency requires permission rules to take effect in real time with work orders, to avoid old permission rules affecting new rack installation tasks.
Diverse document types require differentiated access permission configurations for different documents such as installation applications and cabling diagrams, to match the operational needs of roles including operation and maintenance, approval, and implementation.
The serious consequences of physical access errors require permission isolation rules to strictly restrict modification permissions for key data, to prevent unauthorized personnel from modifying rack position or port configurations.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind a dedicated `teamId` to each IDC project | Isolate rack installation data across different customers or projects, prevent unauthorized cross-project access |
| Role permission mapping | Divide roles by operation engineer, approval specialist, and implementation staff | Match the role division of cabinet rack installation business, restrict unauthorized operations |
| Data access validity period | Set according to work order cycle, maximum 7 days | Adapt to per-order or daily update frequency, reduce exposure risk of idle data |
| Access log retention | 30 days | Meet audit requirements for security review, facilitate tracing of operation trails |
| `tmbId` | Bind dedicated `tmbId` to cabling diagrams and port label tables | Isolate access permissions for different documents, prevent unauthorized personnel from modifying physical access documents |
| Cross-team data sharing | Trigger only through designated interfaces | Avoid unauthorized cross-project data flow, comply with data isolation requirements |

## Three common misconfigurations
- Phenomenon: After adding a custom plugin to a workflow, input and output parameters do not display, and no error logs are generated. Cause: No permission rule bound to `teamId` is configured for the plugin, causing permission verification to block the parameter loading process.
- Phenomenon: After local deployment, multiple accounts cannot be created to join the same team, and adding data to tables has no response. Cause: The team association logic for `teamId` is not configured correctly, causing the binding relationship between accounts and teams to not take effect.
- Phenomenon: After submitting a cabinet cabling diagram, cross-project modification of others' rack installation documents occurs. Cause: No dedicated `tmbId` is bound to the document, causing the permission isolation rule to not take effect.

## How to verify successful configuration
- Use an account not bound to the target project to attempt accessing the designated rack installation application document, confirm that viewing or editing is not possible
- Enter the team permission settings page, verify that the binding relationship between `teamId` and the current IDC project is correct
- Trigger a rack installation work order process, check that access logs are generated and retained for more than 30 days
- Configure the `teamId` permission rule for the custom plugin, verify that input and output parameters display normally in the workflow
