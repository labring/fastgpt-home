# Security and Compliance Material Review for Cabinet Rack Installation and Cabling: Model Access and Configuration

## What the data for this category looks like
Core data for this category comes from data center infrastructure management (DCIM) systems, enterprise asset systems, network topology diagrams, and customer construction work orders. Daily processed documents include rack installation applications, cabinet cabling diagrams, port label sheets, and construction acceptance records. Fields include rack position numbers, cable specifications, port identifiers, device models, and more. Data updates occur per order or daily. The volume of documents associated with a single work order varies based on the number of connected cabinet devices. All core fields are structured content related to physical locations and device connections, with no real-time streaming data.

## What constraints these characteristics impose on model access and configuration
Data for this category is scattered across multiple systems. Documents associated with a single work order are temporary construction materials, so model access configurations must support context integration across multiple temporary documents. Physical deployment documents contain many structured fields, so the model must accurately match physical identifiers such as rack positions and ports. Configurations must therefore balance context length and output accuracy. Construction data updates occur per order or daily, so model calls must adapt to temporary data loading for single tasks. Long-term caching mechanisms should be avoided to prevent data expiration or mismatch issues.

## Three Common Configuration Mistakes
- Phenomenon: GPU video memory rapidly increases to 6–7 GB when calling a reranking model, and all multi-GPUs show usage. Cause: Batch processing parameters for the model were not adjusted for structured documents such as cabinet cabling diagrams, resulting in loading too many context fragments in a single call.
- Phenomenon: Invalid token prompt appears when configuring a domestic model, and third-party proxy tests function normally. Cause: The required environment variables `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` for the App/Admin server were not configured correctly, or the interface address and vendor credentials for the model channel were not configured properly.
- Phenomenon: Offline reranking model access fails, returning `rerank error fastgpt | { message: { detail: ' error. Cause: The model file was not placed in the model loading directory specified by FastGPT, or the model file format does not match the reranking model formats supported by FastGPT.

## How to Verify Successful Configuration
- Perform a single work order compliance review test in FastGPT v4.17.0, and verify whether the model's output compliance items cover all core fields in the installation application and cabling diagram.
