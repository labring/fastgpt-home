# Security and Compliance Material Review for Desktop Terminal Support: Document Parsing and Chunking

## What the Data for This Category Looks Like
It typically includes four core document types for terminal operation and maintenance scenarios: terminal trouble tickets, installation checklists, software installation records, and remote assistance records. Data sources include terminal management platforms, enterprise asset systems, user reporting channels, and software repositories. Document update frequency follows daily batch imports or real-time submission with operation and maintenance requests. Some scanning-based installation checklists are stored in image format. Document fields include device unique identifiers, fault types, operation times, software versions, processing steps, and more. No unified mandatory format exists. Some Excel-format trouble tickets have non-standard structures such as merged cells and hidden columns.

## Constraints on Document Parsing and Chunking
The non-standard structure of terminal operation and maintenance documents requires the parsing process to retain field association, and avoid splitting device IDs from their corresponding fault descriptions. Otherwise, fault chain traceability during compliance review will be compromised. The mixed format of scanning-based installation checklists may cause parsing tools to trigger full OCR unnecessarily, increasing invalid time consumption and potentially leading to recognition errors. Large-volume remote assistance records lengthen parsing cycles, requiring adaptation to longer timeout thresholds. Real-time submitted operation and maintenance work orders require parsing processes to have low-latency processing capabilities, while also avoiding context breaks caused by overly fine chunking. In addition, batch-imported asset system export files may have large single-file sizes, requiring adaptation to a reasonable upload limit.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the information density of single chunks in terminal documents, avoids splitting device-associated fields, and ensures context integrity during compliance reviews |
| `chunkSplitter` | Split by paragraph + semantic segmentation | Matches the natural paragraph segmentation logic of terminal documents, and retains the integrity of continuous operations such as fault processing steps and software installation workflows |
| `customPdfParse` | Enable text-first mode | For scanned installation checklists, prioritize extracting identifiable embedded text, and avoid font recognition errors caused by forced OCR |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of large-volume remote assistance records and batch asset files, and prevents timeout failures during processing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates batch terminal device lists exported from enterprise asset systems, and meets daily batch import requirements for operation and maintenance |
| `chunkSettingMode` | Manual configuration | Flexibly adjust chunking parameters for different types of terminal documents, and adapt to parsing requirements for formats such as trouble tickets and installation checklists |

## Three Common Misconfigurations
- Parsed text is missing after uploading a scanned installation checklist. Verify whether the text-first mode of `customPdfParse` is not enabled. This mode prevents forced full OCR, which can cause incorrect recognition of some scanned fonts.
- Vectorization index errors occur after uploading an Excel-format trouble ticket. Verify whether `chunkSplitter` is not configured to adapt to table data. This configuration prevents device IDs and their corresponding fault descriptions from being split into different chunks by direct character-based splitting.
- Parsing tasks fail during batch upload of terminal asset files. Verify whether the value of `PARSE_FILE_TIMEOUT_SECONDS` is set too small to match the parsing time of large files.

## How to Verify Proper Configuration
- Upload a single scanned installation checklist, and confirm that the parsed result retains the original text content with no obvious OCR recognition errors.
- Upload an Excel-format trouble ticket, and confirm that chunking results associate device IDs with fault descriptions by table row, with no isolated field fragments.
- Upload a remote assistance record file larger than 100MB, and confirm that the parsing task does not trigger a timeout error.
- Verify that the server environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000, do not append paths such as /v1 or /chat/completions) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with the AI Proxy server configuration and cannot be empty) are correctly configured to pass startup verification for FastGPT v4.17.0.
