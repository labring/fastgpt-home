# Security and Compliance Material Review for Desktop Terminal Support: Permissions and Data Isolation

## What data for this category includes
Data for this category primarily comes from terminal management platforms, asset systems, user support channels, and software repositories. Documents processed daily include terminal trouble tickets, installation manifests, software installation records, and remote assistance records. Individual documents contain fields such as device ID, fault description, installation configuration, and operation logs. Data is updated via daily batch synchronization or triggered by single requests, with no uniform fixed batch cycle. Individual records link specific terminal devices and operator information.

## What constraints these characteristics impose on permissions and data isolation
Terminal device-associated operation and maintenance data involves employee office devices and operation traces. Permission isolation must align with the team that owns the device and the authority and responsibility scope of operation and maintenance personnel. Data from different sources must be divided into access boundaries according to the department to which the terminal belongs, to prevent cross-team operation and maintenance personnel from accessing device records outside their job responsibilities. Temporary data triggered by requests must be automatically cleaned up after the session ends, to prevent the retention and leakage of temporarily generated installation manifests and fault troubleshooting logs. At the same time, cross-asset system data splicing must be restricted, ensuring that only authorized operation and maintenance personnel can access full-link troubleshooting data for corresponding devices.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `teamId` | Team ID bound to the department that owns the terminal, use a valid team identifier already created on the platform | Match the business team that owns the device, ensuring operation and maintenance personnel only access terminal data for their corresponding team |
| `tmbId` | Bound to the terminal support group to which the operation and maintenance personnel belong, use the unique identifier of the corresponding group | Restrict operation and maintenance personnel to only operate terminal devices within their job responsibilities |
| Session data retention duration | 30–60 minutes, calibrated based on actual testing | Temporarily generated fault troubleshooting and remote assistance records do not need long-term retention, to avoid data accumulation and leakage risks |
| Cross-system data access permissions | Enabled per device owning team, only callable by authorized operation and maintenance personnel from the same team | Prevent cross-team operation and maintenance personnel from accessing terminal asset data outside their job responsibilities |
| Temporary document automatic cleanup switch | Enabled, bound to session lifecycle | Temporary data such as installation manifests and trouble tickets generated per request is automatically destroyed when the session ends |
| Maximum number of data returned per single query | Top 100 entries | Avoid excessive terminal data returned by a single request leading to permission leakage and resource consumption |

## Three common configuration errors
- When calling an application associated with a knowledge base to query terminal-related data, no matching content is returned, and logs show cross-team data access was blocked. The association rule between `teamId` and the knowledge base owning team was not configured, causing cross-team data requests to be blocked by permission checks.
- Unable to open the team management page, or there is no usage statistics data for terminal operation and maintenance personnel on the page. The team permission configuration switch for terminal support scenarios was not enabled, causing permission verification for the corresponding page to fail.
- Remote assistance records are not automatically cleaned up per session, leading to historical data retention beyond the safe scope. The temporary document automatic cleanup switch was not enabled, or the configured retention duration exceeded the safe threshold.

## How to confirm configurations are properly applied
- Log in to the FastGPT backend, enter the permission configuration page for the corresponding team, and check whether the binding relationship between `teamId` and `tmbId` matches the terminal owning department and operation and maintenance group.
- Initiate a cross-team terminal data query request, check whether a permission interception prompt or no matching content is returned, confirming that cross-team access is correctly restricted.
- Enable temporary sessions to generate test data, wait 30 minutes before accessing again, confirming that the data has been automatically cleaned up.
- Enter the team management page, check whether the usage statistics data for terminal operation and maintenance personnel loads normally, confirming that the permission configuration has taken effect.

The configuration values provided are common starting points and should be evaluated against individual deployment samples.
