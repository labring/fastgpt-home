# Security and Compliance Material Review for Desktop Terminal Support: Model Access and Configuration

## What data for this category looks like
This category's data comes from terminal management platforms, asset systems, user trouble reporting channels, and software repositories. Commonly processed documents include terminal trouble tickets, installation manifests, software installation records, and remote assistance records. Terminal trouble tickets include fields for terminal ID, trouble type, trouble reporting time, and processing progress. Installation manifests include fields for hardware model, software version, and installation time. Remote assistance records include fields for session duration and operation logs. Data update frequency is either daily batch synchronization or real-time updates following user requests.

## What constraints these characteristics impose on the "model access and configuration" link
Multi-source and scattered data sources require configuring multi-channel data access rules. The model can correctly map fields from different data sources such as terminal management platforms and asset systems. The dual characteristics of batch and real-time data update frequencies require configuring model invocation logic that supports on-demand pulling and scheduled synchronization. This avoids processing outdated terminal asset information. Diverse document fields and sensitive terminal information require configuring strict permission verification rules. This prevents unauthorized access to terminal data. It also defines the field scope for model input to avoid irrelevant information interfering with compliance reviews.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | The total context volume of single-batch documents related to desktop terminals is large. This setting covers most scenario document content and avoids context overflow |
| `maxTokens` | `2000–3000 token` | Compliance reviews require outputting detailed verification conclusions and rectification suggestions. This setting reserves sufficient output space |
| `quoteMaxToken` | `1000–1500 token` | The review process needs to reference terminal asset data as a basis. This setting controls the length of referenced text to avoid redundant information interfering with model judgment |
| `toolChoice` | `auto` | Automatic invocation of compliance verification tools is required to handle terminal security rules. Automatic mode can adapt to different types of review tasks |
| `temperature` | `0.1–0.3` | Compliance reviews need to maintain output rigor. Lower temperature values reduce output randomness and ensure consistent conclusions |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths, and do not configure it as a single-model service address | This variable is a required environment variable for the App/Admin server. Desktop terminal data is mostly stored in an intranet environment, and AI Proxy must be used to securely forward model requests to ensure data transmission security |

## Three common configuration mistakes
- Symptom: Interface calls return `400 Bad Request` with a prompt that the context length exceeds the limit. Troubleshooting item: The `maxContext` parameter is not configured correctly, exceeding the context threshold supported by the model.
- Symptom: Compliance review results do not include chain-of-thought content. Troubleshooting item: The model's chain-of-thought output switch is not enabled, or the corresponding parameter is not configured, matching common community consultation scenarios for API response chain-of-thought content.
- Symptom: POST requests return connection timeout or empty response. Troubleshooting item: `AIPROXY_API_ENDPOINT` is not configured correctly (not pointing to the AI Proxy service root address, with extra paths appended), `AIPROXY_API_TOKEN` is not configured as a non-empty value, or the AI Proxy service is not running normally, matching common community interface call test scenarios.

## How to confirm the configuration is complete
- Submit a compliance review request for a terminal trouble ticket, and check that the interface return result includes the expected compliance verification fields.
- Check that the server environment variable configuration has no startup verification errors, and the AI Proxy service is running normally.
- Test calls for different types of terminal documents, such as installation manifests and remote assistance records, and confirm that the review results cover the fields of the corresponding documents.
- Verify that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured correctly, and the AI Proxy service is running normally.
