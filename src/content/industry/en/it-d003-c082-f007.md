# Security and Compliance Material Review for Channel Attribution and Lead Distribution: Conversation Logs and Auditing

## What the Data for This Category Looks Like
This category's data originates primarily from advertising platforms, CRM systems, attribution SDKs, and form systems. Most updates occur daily or weekly. Daily associated documents include attribution rules, lead distribution tables, channel reports, and exception checklists. Core fields include channel identifiers, lead unique IDs, affiliated sales accounts, conversion timestamps, conversion amount units (yuan), and more. The data structure is designed around lead source tracking and sales attribution allocation.

## Constraints Imposed on Conversation Logs and Auditing
Multi-source data access requires conversation logs to link advertising platform channel codes, CRM lead IDs, and SDK reporting identifiers simultaneously. This enables cross-system traceability. Following the daily or weekly update rhythm, configure periodic log archiving rules to prevent data redundancy that slows auditing efficiency. Daily associated multi-type documents require logs to mark corresponding attribution rule versions and lead distribution table effective times to support dispute verification. To avoid issues such as distorted channel ROI, sales attribution disputes, and budget misalignment, the auditing workflow must retain complete parameter adjustment and result verification records to ensure every operation can be traced.

## Configuration Settings
The following configurations are adjusted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Associate and store by lead attribution batch | Must bind unique lead identifiers to enable auditing grouped by channel or sales team |
| `responseChatItemId` | Retain full-link interaction node IDs | Used to trace the complete attribution conversation flow for a single lead |
| `detail` | Enable full-field log output | Covers core audit fields such as channel parameters and conversion data |
| Log storage period | 30–90 days | Matches industry standard compliance audit cycle requirements |
| Log retrieval limit | Top 1000 entries | Avoids performance impacts from loading excessive data during single audits |
| Log archiving trigger | Execute weekly | Matches the weekly update rhythm of data for this category |

## Three Common Configuration Mistakes
- Symptom: Cannot locate the log storage directory associated with `chatId`. Cause: Log association rules are not configured by lead batch, leading to a mismatch between logs and lead data.
- Symptom: The `detail` field in logs is missing channel parameters and conversion amounts. Cause: The full-field log output switch is not enabled, so only basic interactive text content is retained.
- Symptom: Duplicate lead attribution conflict records appear during audits. Cause: The effective time of the lead distribution table is not associated, making it impossible to verify version differences in attribution rules.

## How to Verify the Configuration Is Correct
- Retrieve logs for a specified `chatId` and confirm that core fields such as channel identifiers and lead IDs are present.
- View the log storage directory and confirm that archive files are generated weekly.
- Trigger a lead attribution workflow and verify that `responseChatItemId` fully records all interaction nodes.
- Check the log output configuration and confirm that the `detail` field is enabled for full content output.

The values provided are common starting points and should be measured against the reader's own samples.
