# Security and Compliance Material Review for Channel Attribution and Lead Distribution: Document Parsing and Chunking

## What Data for This Category Looks Like
The core data for this category comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Daily processed documents include attribution rule configuration tables, lead distribution tables, channel effect reports, and abnormal lead checklists.
Data updates occur primarily on a daily or weekly basis. Document structures vary significantly across different sources:
- Reports exported from advertising platforms include fields for channel ID, impressions, and conversions.
- Lead tables exported from CRM systems include fields for assigned sales and conversion time.
- Rule files generated by attribution SDKs include parameter verification logic.
- Abnormal checklists include fields for problem descriptions and processing status.

## Constraints on Document Parsing and Chunking
Differences in document structures across multiple sources require parsing logic to adapt to different formats. Advertising reports are mostly standardized tables. CRM lead tables include nested fields. Attribution rule files include code-like configurations. Parsers must support mixed-format parsing.
Document fields contain business-sensitive information. Chunking must retain field association relationships. This avoids losing critical linked information such as assigned sales and channel ID after splitting.
High-frequency daily and weekly updates require stable parsing processes. Single parsing duration must match the update rhythm. Compliance review requires retaining full original document fields. Do not omit verification parameters and abnormal marker content. Missing these may cause compliance verification to fail after chunk splitting.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the combined field length of channel reports and lead tables, avoiding loss of association between channel ID and assigned sales after splitting |
| `chunkSplitter` | Split by table row | Adapts to standardized table documents from multiple sources, retaining the integrity of single lead or single channel data |
| `customPdfParse` | Enabled | Supports extraction of parameter configuration text from attribution rule PDF files, avoiding loss of verification logic content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to large-file requirements for daily batch parsing, preventing update process interruptions caused by single parsing timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatible with batch-exported channel report files, meeting upload requirements for weekly aggregated data |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different source documents, adapting to non-standardized structures of attribution rules and abnormal checklists |

## Three Common Mistakes
- Scenario: After uploading an Excel-format lead distribution table, some fields are empty in the parsing result. Cause: The table-adapted chunking logic is not enabled. The default parsing rule fails to recognize Excel multi-header and merged cell structures.
- Scenario: After uploading a weekly aggregated channel report, the parsing process exceeds 2 minutes and shows a request failure. Restarting the server does not resolve the issue. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for large aggregated files. The file size is not confirmed to be within the `UPLOAD_FILE_MAX_SIZE` limit.
- Scenario: After uploading an attribution rule PDF file, parameter verification-related configuration content is missing from the parsing result. Cause: The `customPdfParse` configuration is not enabled. The default PDF parsing only extracts plain text, failing to retain structured parameter logic content.

## How to Verify Proper Configuration
- Upload a single standardized channel report file, and verify that the parsed chunked content includes complete core fields such as channel ID and conversions.
- Check the `PARSE_FILE_TIMEOUT_SECONDS` parameter setting, confirm that its value exceeds the estimated duration of single batch parsing.
- Upload a test file of the maximum allowed size, confirm that no error prompts appear during upload and parsing.
- After enabling `customPdfParse`, upload an attribution rule PDF file, and verify that parameter verification-related text content is retained.

The values provided are common starting points and should be measured against the reader's own samples.
