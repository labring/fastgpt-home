# Security and Compliance Material Review for Channel Attribution and Lead Distribution: Permission and Data Isolation

## What the data for this category looks like
Core business data for this category includes attribution rules, lead distribution tables, channel reports, and exception reconciliation sheets. This data is synchronized from advertising platforms, CRM systems, attribution SDKs, and form systems. Data updates typically run daily or weekly. Document fields include channel identifiers, lead IDs, assigned sales IDs, conversion amounts, and attribution parameters. Units include timestamps, currency units, and channel codes. Permission boundaries for documents generated and used by different business roles differ significantly.

## Constraints Imposed on Permission and Data Isolation
Multi-source data synchronization creates a need for cross-system data permission alignment. Advertising conversion data and CRM lead data from different sources must be strictly isolated by owning entity. Daily and weekly update cycles require permission configurations to support concurrent batch data processing. This avoids permission verification delays that disrupt business workflows. Documents contain sensitive information such as sales assignments and conversion amounts. Set field-level permissions for different roles to prevent unauthorized access or modification of core attribution rules and lead ownership details. Strictly separate operational permission boundaries for different roles. This stops sales disputes or budget mismatches caused by incorrect permission configurations.

## How to Configure Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Divide data isolation dimensions by business team | Adapt to data isolation requirements for multi-channel and multi-sales team scenarios |
| `tmbId` | Bind preset role templates | Match the responsibility boundaries of growth operations, sales operations, and data analysts |
| Field-level permission switch | Enable fine-grained control over conversion amount and sales assignment fields | Protect sensitive business data and prevent unauthorized access |
| Data access time limit | Configure a 7-day historical data access window | Adapt to the daily/weekly data update rhythm |
| Cross-system synchronization permission | Only open to data analyst roles | Match the business process of multiple data sources requiring professional verification |

## Three Common Misconfiguration Issues
- Symptom: Cross-team data appears mixed in channel ROI reports, and the interface returns a `403 Forbidden` status code. Cause: Data isolation dimensions were not configured using `teamId`, so attribution data from different teams is visible to one another.
- Symptom: Sales staff cannot view lead ownership information for their assigned leads, and corresponding fields in the lead distribution table are empty. Cause: The role template was not bound to the correct `tmbId` permissions, so sales staff lead view permissions were not enabled.
- Symptom: Permission verification times out during batch attribution rule updates. Cause: No reasonable data access time limit was configured, so batch data processing exceeded the default permission verification window.

## How to Verify Successful Configuration
- Switch test accounts using different `teamId` values, and confirm channel reports only show attribution data for the corresponding team.
- Log into the system with a sales role, and check that the lead distribution table only displays sales assignment information for leads the staff is responsible for.
- Trigger a batch attribution rule update process, and confirm no abnormal errors occur in the permission verification flow.
- Review data access logs, and confirm only authorized roles can access historical data, with access scope matching the configured time limit requirements.
