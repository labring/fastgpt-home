# Security and Compliance Material Review for Channel Attribution and Lead Distribution: Model Integration and Configuration
This guide is written for FastGPT v4.17.0.

## What Data for This Category Looks Like
Core data for this category comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Update frequency is typically daily or weekly. Commonly processed documents include attribution rule configuration tables, lead distribution lists, channel traffic reports, and exception checklists. Fields usually include channel identifiers, conversion times, lead IDs, sales owners, budget allocation amounts, and similar items. There is no unified mandatory format. Field structures must match the original export format from each connected system.

## Constraints Imposed by Data Characteristics on Model Integration and Configuration
Decentralized data sources lead to inconsistent field formats. Field mapping for multi-source heterogeneous data must be supported during model integration to avoid sales attribution disputes caused by parameter misalignment. Daily or weekly batch data updates require configuration that supports scheduled batch calls. Reasonable context and token limits must be set to handle multi-source data concatenation, preventing budget misalignment caused by batch task timeouts. High complexity of lead attribution verification requires the model to support multi-field association verification. Parameters must be adjusted to balance accuracy and logical rigor, avoiding channel parameter verification errors that cause distorted channel ROI. Unstructured content in exception checklists must support visual parsing to handle image-based exception vouchers.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the context length after concatenating multi-source data, avoiding truncation of core attribution rules and lead fields |
| `maxTokens` | 4000 token | Limits single-round output length, adapts to parsing requirements for channel reports and exception checklists, avoiding redundant output |
| `vision` | Enabled | Supports parsing image-based vouchers in exception checklists, adapting to unstructured data processing scenarios |
| `temperature` | 0.2–0.4 | Reduces randomness, improving logical rigor for channel parameter verification and lead deduplication |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service. Example format: http://aiproxy:3000. Do not append paths such as /v1 or /chat/completions. Do not enter single-model service addresses | Required environment variable for FastGPT App/Admin server, used for routing model requests |
| `AIPROXY_API_TOKEN` | Enter a non-empty administrator token matching the AI Proxy server configuration | Required environment variable for FastGPT App/Admin server. Do not use application API keys or model vendor keys |

## Three Common Misconfigurations
- Channel link calls return the "undefined is not valid json" error. Troubleshooting steps: Check if the FastGPT App/Admin server has correctly configured `AIPROXY_API_ENDPOINT` (AI Proxy service root address, format example: http://aiproxy:3000, do not append additional paths) and a non-empty `AIPROXY_API_TOKEN`. Missing or incorrect configuration causes service startup verification failure or failed model request routing, leading to response parsing exceptions.
- Local deployment instances cannot see the image understanding model option when creating a knowledge base. Cause: The `vision` configuration item is not enabled, or the deployment environment has not loaded the corresponding visual model dependency packages.
- Timeout errors occur during batch calls of daily data. Cause: `maxContext` and `maxTokens` are not set reasonably, leading to excessive data processed in a single request, exceeding the interface response time limit.

## How to Verify Successful Configuration
- Run a single lead attribution verification test, confirm whether the model’s output attribution result matches the manual verification result.
- Upload an exception checklist containing images, confirm that the model can normally extract key information from the images and generate parsing results.
- Configure a scheduled batch task, verify that the model can normally call and process context after concatenating multi-source data during daily data updates.
- Check the FastGPT App/Admin server environment variable configuration, confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly set. Check API call logs, confirm that application API requests use valid application API keys for authentication, and that request paths match the configured `AIPROXY_API_ENDPOINT` root address.

The configuration values provided here are common starting points. They should be evaluated against specific samples and use cases.
