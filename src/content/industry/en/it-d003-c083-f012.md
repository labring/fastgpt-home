# Security and Compliance Material Review for Game Content Self-Inspection: Document Parsing and Chunking

## What Data for This Category Looks Like
This category’s core data originates from compliance process documents and content assets created during game development and operations. These include plot scripts, user agreements, compliance review minutes, sensitive content modification records, and more. Data updates trigger alongside game version releases or operational activities, with each single update containing a collection of documents across multiple types and formats. Each individual document includes fixed fields such as content fragments, compliance tags, version numbers, and review comments. Data units are primarily characters and entry counts. Some documents linked to art resources will also include resource reference information.

## Constraints on Document Parsing and Chunking
Compliance documents must strictly align with review logic, so the parsing process cannot lose critical context or split associated content. The mixed format of multiple document types requires the parsing engine to support plain text, PDF, and scripts with resource references. High-frequency update demands require the parsing process to deliver high batch processing efficiency. Compliance reviews have strict accuracy requirements; any parsing error may block subsequent review steps. Additionally, art resource references included in some documents require extra parsing support to prevent unrecognized resource addresses.

## Configuration Settings
FastGPT v4.17.0 and later versions support standard behavior for the following configuration items:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | A single chunk of compliance document content must cover a complete plot fragment or review entry, avoid splitting critical context, and ensure reviewers can quickly locate associated content |
| `chunkSplitter` | Chunk by paragraph + semantics | Dividing game scripts and review minutes by logical paragraphs better aligns with compliance review reading habits, reducing disruption to content coherence |
| `customPdfParse` | Enabled | Most compliance documents are PDF-format review minutes and version descriptions. Enabling enhanced parsing preserves original formatting and critical tags, preventing content loss |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | A single version compliance document package may include large numbers of plot scripts, art resource descriptions, and review records, requiring sufficient upload space |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large compliance document packages takes significant time. Setting a longer timeout prevents task interruption mid-process |
| `chunkSettingMode` | Manual configuration | Compliance reviews require precise control over chunking rules to adapt to different document types. Manual configuration allows flexible adjustment of chunking parameters |

## Three Common Misconfigurations
- Issue: Content missing or formatting disordered after parsing PDF compliance documents. Cause: The `customPdfParse` configuration is not enabled, and the default parsing engine cannot adapt to the complex formatting and tags of compliance documents.
- Issue: Parsing task times out and fails. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` setting value is too short, failing to reserve enough time to process large compliance document packages.
- Troubleshooting step: Check whether the App/Admin server’s `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000, must not add path suffixes such as /v1 or /chat/completions) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with the AI Proxy server configuration and cannot be empty) have been correctly configured. Failure to configure these will cause startup verification failure.

## How to Confirm Configuration Is Complete
- Check the App/Admin server’s environment variables to confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have been correctly configured with no empty values.
- Upload a test compliance document (such as a plot script fragment) and verify that the parsed chunk results match the expected `chunkSize` and chunking logic.
- Submit a batch parsing task, wait for completion, and confirm there are no timeout or content loss errors.
- View the chunk storage records in the knowledge base to confirm that document fragments have been correctly generated with no abnormal fields.

The configuration values listed above are common starting points, and should be evaluated against the reader’s own specific samples.
