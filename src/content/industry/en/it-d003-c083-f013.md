# Security and Compliance Material Review for Game Content Compliance Self-Check: Permissions and Data Isolation

## Data profile for this category
This category’s data is generated for compliance self-checks of game versions and events. Sources include game text, art assets, plot scripts, and publicly released regulatory compliance requirements. Teams produce daily documents including content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Each document links to a unique identifier for its corresponding version or event. Game version iterations and event launches trigger data updates. Each update covers all self-check related materials for the current version. Updates follow no fixed schedule, but tie strictly to version release milestones.

## Permissions and data isolation constraints
Teams isolate game content compliance self-check data by version and event. Self-check materials for different versions must use strictly separated permission scopes to prevent cross-version data leaks. Administrators bind personnel in different roles to permissions for corresponding versions or events, to block unauthorized access to compliance materials from other projects. Sensitive content modification records and review minutes contain internal compliance judgments, so teams restrict access to these materials to compliance team members only. Frequent data updates tie to version milestones. Teams must adjust permission configurations dynamically alongside version releases, to avoid leftover permissions for old versions or delayed activation of permissions for new versions.

## Configuration guidelines
This document is written for FastGPT v4.17.0.
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `teamId` | Bind to the dedicated team ID for the game project | Isolate compliance self-check data across different game projects, prevent cross-project permission leaks |
| `tmbId` | Link to the unique identifier for the current version or event | Match the data update pattern of this category (updated per version or event) to achieve permission isolation for single-version materials |
| Permission role configuration | Divide into three categories: auditor, producer, compliance administrator | Match permission requirements of business roles, restrict access to sensitive review minutes to compliance administrators only |
| Data access validity period | Only open during the version self-check cycle | Adapt to the high update frequency of this category, avoid long-term exposure of old version data |
| Version permission synchronization switch | Enable | Ensure permission configurations for newly released versions take effect automatically, reduce manual configuration overhead |

## Three common configuration errors
- Symptom: After restarting the Docker service, access to compliance self-check data returns a permission error with the prompt "No access permission". Cause: The `teamId` configuration was not bound to the container permissions reloaded after restart, leading to invalidation of the original permission configuration.
- Symptom: When viewing compliance materials across versions, content self-check lists from other versions are visible. Cause: The version isolation configuration linked to `tmbId` was not enabled, and permissions were not divided by version.
- Symptom: Input parameters for custom compliance review plugins cannot be displayed in workflows. Cause: Permission configurations do not grant access to edit plugin parameters, or role groups do not include access permissions for parameter configuration.

## How to verify correct configuration
- Log in to accounts with different roles, confirm that auditors can only view text and art inspection results, and cannot access compliance review minutes.
- Switch the `tmbId` for different versions, confirm that only self-check materials for the corresponding version are visible, with no cross-version data leaks.
- Restart the Docker service, then access the self-check data again, confirm that the permission configuration has not failed, and no permission errors occur.
- Submit new version self-check materials, verify that the permission configuration takes effect automatically with the version, without requiring manual reconfiguration.
