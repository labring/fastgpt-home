# Security and Compliance Material Review for Game Content Self-Check: Model Access and Configuration

## What this category of data looks like
The data sources for this category are game text, art assets, plot scripts, and public regulatory requirements. Daily processed documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Data updates trigger when game versions iterate or events launch. A single update covers all plot, event copy, and supporting art materials for one version. Data includes structured self-check items, unstructured text fragments, and visual resources. There is no fixed unified field structure. It must adapt to multiple input formats.

## What constraints these characteristics impose on model access and configuration
This category of data contains mixed multi-type content and updates frequently with version iterations. Model access must support both text and visual input. This requires configuring multimodal model parameters. Data has no fixed unified field structure. The model must have flexible content understanding capabilities. Do not set overly strict format constraints. Single update coverage is broad. Limit the maximum context length per processing round to avoid exceeding model capacity limits. Compliance review must strictly match regulatory requirements. Ensure the model call link is stable. Avoid review result deviations caused by configuration errors. This link occurs before game version updates and event launches. It is distinct from batch centralized processing during the game license application stage. It must adapt to high-frequency, small-scale update requirements. The content of this page is compatible with FastGPT v4.17.0.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `vision` | Enabled | This category requires art asset review. It needs to support compliance analysis of visual materials such as character portraits and scene images |
| `maxContext` | 8000–12000 token | Adapts to the total length of plot text and event copy for one version. Prevents context overflow and loss of key information |
| `maxTokens` | 2000–3000 token | Limits the output length per review round. Ensures compliance opinions are clear and not redundant, and aligns with review minute recording standards |
| `temperature` | 0.1–0.3 | Reduces output randomness. Ensures consistency and rigor across compliance review results for different batches |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | As an environment variable for the App/Admin server, configure the access address of the AI Proxy service to ensure normal connection to the AI Proxy service |
| `AIPROXY_API_TOKEN` | Enter the administrator token consistent with the AI Proxy server configuration. Do not leave it blank | As an environment variable for the App/Admin server, used for identity verification of the AI Proxy service. Ensures valid service call permissions |

## Three common configuration mistakes
- Phenomenon: The preset compliance review prompt fails to take effect when calling a model deployed via ollama. Verifiable troubleshooting steps: Check whether the `toolChoice` parameter is configured correctly, or whether the model has enabled tool call adaptation mode.
- Phenomenon: Generated compliance review results do not incorporate the current version's plot context. Verifiable troubleshooting steps: Check whether the `maxContext` parameter value is too small, causing key text from historical and current versions to be truncated.
- Phenomenon: Calls to third-party proxy interfaces return payment-related prompts. Verifiable troubleshooting steps: Check whether the upstream model channel address and supplier credential configuration are correct, or whether the model channel configuration has permission restrictions.

## How to confirm configuration is complete
- Log in to the model management page of the FastGPT platform. Check whether the `vision` parameter's enabled status matches the configured setting.
- Submit a single segment of game plot text and supporting art materials to trigger the review process. Check whether the output result includes both text and visual compliance analysis content.
- Call the test interface and pass a preset compliance review prompt. Confirm whether the returned result matches the review logic defined by the prompt.
- View the model call logs. Confirm that the verification request for `AIPROXY_API_TOKEN` returns a normal status code.
