# Security and Compliance Material Review for Game Publication License and Publishing Declaration: Document Parsing and Chunking

## What this category of data looks like
Daily documents for this category include declaration request files, game application forms, copyright certificates, review reports, and more. Data sources include the national press and publication administration’s service portal, copyright registration systems, game packages, and materials submitted by operating institutions.
Data updates occur irregularly for each individual game. Most documents use fixed declaration templates with filled content. Some review reports are in long-text format without unified standardized fields. Adaptation is required for differences in document formats across different declaration stages.

## What constraints these characteristics impose on the document parsing and chunking link
Documents from multiple sources with inconsistent formats require the parsing process to adapt to multiple formats such as docx and pdf, to avoid loss of core fields from non-standard declaration templates.
Long-text review reports can reach thousands of pages, which introduces parsing timeout risks. Timeout thresholds for parsing and chunking must be adjusted.
Irregularly updated declaration materials for a single game require support for batch parallel upload of multiple files, to avoid slow processing from serial handling.
Large differences in document fields across different declaration stages require retaining contextual associations during chunking, to avoid losing logical connections related to declarations after splitting. This affects consistent verification in subsequent compliance reviews.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---|---|--- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single-segment declaration logic for individual game declaration materials, avoiding loss of contextual associations after splitting |
| `chunkSplitter` | Split by paragraph + heading | Matches the fixed template structure of declaration documents, retaining the association between declaration fields and their corresponding content |
| `customPdfParse` | Enable standard parsing mode | Adapts to PDF review reports exported from game packages, retaining the original document layout and core field positions |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 seconds | Addresses parsing time for thousands-of-page long PDF review reports, avoiding timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch parallel upload of multiple declaration files, covering the total size of full declaration materials for a single game |
| `chunkSettingMode` | Manual configuration | Adapts to differences in document formats across different declaration stages, enabling flexible adjustment of chunking rules |

## Three common errors
- Issue: Partial files fail to parse during batch upload of multiple declaration files, and a timeout status code is returned. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the parsing time for thousands-of-page PDF review reports exceeds the default threshold.
- Issue: When creating a new text dataset in the knowledge base, internal Confluence pages cannot be parsed for content, while external links can be parsed normally. Cause: Parsing permissions for the corresponding internal environment are not configured, and the document parsing process cannot access internal network resources.
- Issue: After enabling the parent-child chunking function, the hierarchical structure of declaration documents is not retained. Cause: The hierarchical recognition rules for `chunkSplitter` are not configured correctly, or the current configuration does not match the fixed heading hierarchy of game declaration documents.

## How to confirm the configuration is complete
- Upload a typical thousands-of-page PDF review report, check whether the parsing progress bar completes normally without timeout errors.
- Batch upload multiple docx format declaration files, confirm that no files are skipped or fail to parse during parallel processing.
- Review the chunked text blocks, confirm that the length of each block meets expectations, and no single-segment declaration logic is split.
- Test the parsing configuration for internal Confluence pages, confirm that the parsing process can normally access internal network resources.
