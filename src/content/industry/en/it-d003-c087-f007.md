# Security and Compliance Material Review for Game Design and Numerical Design: Conversation Logs and Auditing

## What Data Looks Like for This Category
This category's data mainly comes from player behavior data, publicly available competitor materials, battle logs, and version feedback. Updates follow a weekly or per-version iteration rhythm. Daily output documents include gameplay design plans, numerical tables, version requirement sheets, and balance test records. Common data fields include damage coefficients, resource output quantities, turn-based rule parameters, and more. Units include numerical points, time intervals, percentages, and others. Most document structures combine structured tables and plain text descriptions.

## Constraints Imposed by These Characteristics on Conversation Logs and Auditing
Scattered data sources and tight update rhythms for this category require conversation logs to fully retain input content from every large language model call. This includes uploaded numerical table fragments, gameplay design plan fragments, and version feedback content. This ensures every parameter adjustment operation is traceable.
Structured numerical tables and rule documents require the auditing process to accurately locate call records for specific fields. Examples include modification trajectories for damage coefficients and resource output quantities.
Additionally, the impact of errors such as gameplay imbalance and version rework requires the auditing chain to cover the full workflow from data upload to model output. This prevents key steps from being lost or tampered with.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the exclusive identifier of the current game project | Ensure all conversation logs under the same project can be grouped by project, facilitating compliance auditing, and compatible with FastGPT v4.17.0 project identifier management logic |
| `responseChatItemId` | Record the unique identifier of each large language model output | Accurately locate the input and output link of a single round of conversation, to troubleshoot abnormalities in numerical simulation or rule breakdown |
| `detail` | Enable full log recording mode | Retain original uploaded content such as numerical tables and gameplay design documents, to meet compliance review requirements |
| Log storage granularity | Split by individual design document or numerical table | Align with the business habit of auditing by document category for this category, facilitating quick location of corresponding content |
| Log retention period | 25–35 days | Calibrated through actual testing, covers the complete review cycle for version iterations |
| Audit log export format | Structured CSV | Adapt to subsequent analysis needs for numerical tables and battle logs |

## Three Common Misconfigurations
- Symptom: Uploaded numerical tables or gameplay design document content do not appear in conversation logs, and model outputs are not associated with uploaded raw data. Cause: The full recording mode of the `detail` parameter is not enabled, so original uploaded data is not retained by the log system.
- Symptom: Calling a multimodal interface to process battle log screenshots returns a 400 invalid image error, and the conversation logs do not contain complete records of the corresponding abnormal request. Cause: No image format verification rules are configured, or the uploaded image resolution exceeds the system-supported range, resulting in incomplete logging of abnormal requests.
- Symptom: After executing a conversation log cleanup operation, logs associated with a specific version of numerical design are not deleted. Cause: The cleanup scope is not filtered by the project identifier bound to `chatId`, resulting in accidental operation or omission of log data for a specific project.

## How to Verify Correct Configuration
- Upload a test numerical table, check whether the uploaded file content and input parameters of the model call are fully recorded in the conversation logs.
- Initiate a multimodal call and trigger an exception, check whether the conversation logs contain complete error information and request links.
- Filter logs by project identifier, confirm that only logs for the current project are queried or exported, with no redundant cross-project data.
- Adjust the log retention period configuration, verify that the system automatically cleans up expired logs according to the set cycle.
