# Security and Compliance Material Review for Game Planning and Numerical Design: Citation Sources and Traceability

## What Data Looks Like for This Category
The daily deliverables of game planning and numerical design work include four core document types: gameplay design documents, numerical tables, version requirement sheets, and balance test records. Data sources primarily include player behavior data, public competitor materials, battle logs, and version feedback. Updates follow a weekly or per-version cycle. Numerical tables contain structured fields with units such as damage coefficients and growth curve parameters. Gameplay design documents include unstructured content such as rule descriptions and trigger conditions.

## Constraints on Citation and Traceability Workflows
The mixed structure of the four document types requires traceability systems to support both structured numerical matching and full-text retrieval, to prevent missing key parameters. The weekly or per-version update frequency requires traceability to link to document snapshots from the corresponding version, avoiding use of outdated cited content. Non-standard formats of player behavior and battle logs require adaptation to field mapping rules across different sources, to ensure traceability information accurately maps to original data. The risk of gameplay imbalance errors requires citations to be tied to clear source documents and update times, preventing unsubstantiated rule adjustments.

## Configuration Settings
This configuration applies to FastGPT v4.17.0. Specific parameter settings are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average character length of a single paragraph in gameplay design documents, to avoid truncating complete cited content |
| `responseData` | Return only matching items | Ensure outputs strictly use the original text of question-answer pairs stored in the knowledge base, without generating additional content |
| `detail` | Enabled | Display the document name, chapter location, and update time of the citation source, to meet compliance review requirements |
| Single search limit | Top 6 entries | Cover the citation needs of multi-dimensional parameters in numerical tables, to avoid missing key matching results |
| Maximum context | 3000 characters | Adapt to the long-text traceability requirements of version requirement sheets, to fully load associated rule descriptions |

## Three Common Configuration Errors
- Service stagnation with no response, and the interface displays a 504 timeout status code. Cause: The citation matching logic was not adjusted for structured data in numerical tables, leading to resource overload when calling the indexing model.
- The response does not return original text from the knowledge base, and AI-generated custom content appears. Cause: The `responseData` parameter was not configured correctly, and unrestricted generation mode was enabled.
- Citation source fields are empty, and traceability information cannot be viewed. Cause: The `detail` parameter was not enabled, and the interface switch for source display was not turned on.

## How to Verify Successful Configuration
- Import a structured numerical fragment from a gameplay design document into the knowledge base, initiate a query that includes that numerical value, and check if the response fully matches the original text content.
- View the citation section below the response, and confirm that the document name, specific chapter, and update timestamp of the corresponding document are displayed.
- Initiate a query that includes multi-layer numerical parameters, and check that the number of returned citation results matches the preset single search limit.
- Upload an updated version requirement sheet to the knowledge base, initiate a corresponding query, and confirm that the cited content is from the latest version of the document.
