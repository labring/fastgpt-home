# Security and Compliance Material Review for Game Design and Numerical Design: Permissions and Data Isolation

## What Data for This Category Looks Like
The daily documents for this category include gameplay design docs, numerical configuration tables, version requirement sheets, and balance test records. Data sources are primarily internal battle logs, player behavior records, public competitor materials, and version feedback information. Document update cycles are usually weekly or per-version iterations. Numerical configuration tables contain fields such as character growth parameters, skill damage thresholds, resource output values, and more. Gameplay design docs focus on rule descriptions and logical flows.

## What Constraints These Characteristics Impose on Permissions and Data Isolation
Core documents for this category involve gameplay rules and numerical parameters. A leak would harm product competitiveness, so permissions must be divided based on document type and user role. Highly sensitive numerical configuration tables may only be accessed by lead designers and producers. Gameplay design docs can be isolated by project teams to prevent cross-team information leaks. Document update frequency is high, so permission configurations must support dynamic adjustments per version cycle. For example, temporarily open test permissions before a new version launches, and revoke unnecessary access permissions after launch. Internal battle logs and player behavior data contain sensitive information. Access scope must be strictly limited to avoid compliance risks.

## How to Configure Settings
This configuration scheme applies to FastGPT v4.17.0. The details are as follows:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Team Access Permissions | Bind `teamId` by project group | Matches the business model of game design teams divided by project groups, prevents cross-project permission leaks |
| Document Group Isolation | Split knowledge base groups by document type | Differentiates documents of different sensitivity levels, such as numerical configuration tables and gameplay design docs |
| Temporary Access Permission Validity Period | `7–14 days` | Adapts to weekly or per-version document update cycles, avoids unnecessarily long open access permissions |
| Sensitive Document Access Scope | Only accessible to core design teams | Targets highly sensitive documents like numerical configuration tables, limits access scope to reduce leak risks |
| Permission Approval Workflow | Enable two-level approval | Prevents unauthorized personnel from modifying or accessing core documents at will, aligns with business characteristics where errors have severe consequences |
| Data Source Isolation | Divide access permissions by data source | Differentiates data from different sources such as internal battle logs and public materials, meets compliance requirements |

## Three Common Misconfigurations
- Symptom: Intern accounts cannot view core numerical configuration tables, and an access denied prompt appears. Cause: The intern account was not added to the corresponding permission group, or the permission configuration does not cover the project group scope.
- Symptom: Planners across project groups can access gameplay design docs from other projects, leading to information leaks. Cause: Permissions were not bound to project groups via `teamId`, or document group isolation configuration is incorrect.
- Symptom: After configuring permissions, team members still cannot create new numerical configuration documents. Cause: Permissions were only set to view access, and edit permissions were not enabled, or the `tmbId` binding scope does not cover member accounts.

## How to Verify Successful Configuration
- Log in with a test regular member account, verify that only documents from their assigned project group are accessible, and that numerical configuration tables from other project groups cannot be viewed.
- Check the validity period of temporary permission accounts, confirm that access permissions are automatically revoked after expiration.
- Attempt to access sensitive documents with a non-core member account, verify that an access denied prompt appears.
- Submit a permission application, confirm that two-level approval is required before access to the corresponding documents is granted.
