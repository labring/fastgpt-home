# Security and Compliance Material Review for Game Design and Numerical Balance: Model Access and Configuration

## Data characteristics of this category
This category regularly produces documents including gameplay design plans, numerical tables, version requirement sheets, and balance test records. Data sources include player behavior data, public competitor materials, battle logs, and version feedback. Data updates follow a weekly or per-version cycle. Numerical tables contain fields such as level, damage coefficient, and resource consumption, with units including gold, diamonds, and seconds. Gameplay design plans include unstructured content such as rule descriptions and trigger conditions. The overall data includes both structured fields and free text.

## Constraints on model access and configuration
The mixed format of structured numerical tables and unstructured gameplay descriptions requires model access configuration to support both field extraction and text understanding. Data updates follow a weekly or per-version cycle, so knowledge base synchronization must match this pace to avoid expired data interfering with review results. Data sources include real-time battle logs and version feedback, so context length must be controlled during retrieval to ensure response speed. Compliance review results directly affect gameplay balance and version launch, so recall must cover all core document content to avoid missing key validation items.

## Configuration guidelines

| `AIPROXY_API_TOKEN` | Admin token consistent with the AI Proxy server configuration, and cannot be empty | Used for authentication between the App/Admin service and the AI Proxy service. Do not use application API keys, model vendor keys, or other types of tokens. |

## Three common configuration errors
- Phenomenon: Knowledge base retrieval response is slow, with the page waiting more than 10 seconds without returning results. Cause: Index sharding rules are not optimized for the category's structured numerical tables, leading to loading too many shard files during retrieval.
- Phenomenon: After uploading a gameplay design plan or numerical table, parsing results miss core fields such as damage coefficient and resource consumption. Cause: Parsing logic for structured documents is not adapted, leading to failure to correctly extract field association information from numerical tables.
- Phenomenon: Logs showing `gpt-4o-mini call failed` appear during workflow runtime, and the model call is not actively configured. Cause: Uncleaned model reference configuration remains in workflow nodes, and the system attempts to trigger invalid calls.

## How to verify successful configuration
- Upload a typical numerical table document, check if the parsing result completely includes core fields such as level, damage coefficient, and resource consumption.
- Initiate a compliance review request, check if the response time meets business expectations with no obvious timeouts.
- Verify the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations, initiate a test call to confirm the App/Admin service can normally connect to the AI Proxy service.
- Run a workflow including a compliance review node, check that there are no error messages about invalid model calls in the logs.
