# Security and Compliance Material Review for Version Releases and Release Notes: Citation Sources and Traceability

## What Data for This Category Looks Like
Core documents for this category include Release Notes, change logs, version tags, and release checklists. Data originates from version tags in Git repositories, merge commit records, artifact packages generated by CI/CD workflows, and associated Issue milestone entries. Data updates follow a fixed cadence of one release per version. Core fields include version number, change classification, breaking change notes, artifact hashes, and associated commit IDs. All data is tightly bound to a specific version.

## Constraints on Citation Sources and Traceability
Data for this category is tightly linked to specific version identifiers. Citation and traceability must accurately associate all relevant data for the corresponding version, to avoid compliance risks from cross-version confusion. Data sources are scattered across Git repositories, CI/CD artifact packages, and Issue milestone systems. A unified version-based association index must be built, to ensure full-chain change, artifact, and review data can be quickly retrieved during traceability. The fixed version update cadence means traceability configurations must align with a single release cycle, without frequent adjustments to association rules. Compliance check items in release checklists must also map one-to-one with traceability data, to let the security review process trace the source and compliance of every change.

## Three Common Misconfigurations
- Symptom: The traceability information returned by the AI only includes partial change records, and is missing key artifact hashes or commit IDs. Cause: The value set for `quoteMaxToken` is too small, causing the context to be truncated and unable to carry all associated data for a single version of this category.
- Symptom: After calling the API to retrieve corpus, the AI response does not display any source traceability information. Cause: The full return configuration for `responseData` is not enabled, so the associated data required for traceability is not passed to the model.
- Symptom: Even if the knowledge base content is highly relevant to the target version, the system still cannot retrieve the required content. Cause: No version number matching association rule is set, causing the system to retrieve data across versions and fail to accurately match the compliance review materials for the current release.

## How to Verify Successful Configuration
- Upload single-version Release Notes and associated data, trigger the security review workflow, and check if the returned traceability information covers all associated Git commits, CI artifacts, and Issue entries.
- View the citation source module in the AI response, confirm that the number of displayed entries matches the preset rule, and each entry has a clear version number identifier.
- Call the test API, pass query parameters for a specified version, and check if the returned response data includes complete traceability fields, with no truncation or missing content.
- Adjust the value of `quoteMaxToken`, verify that the display length of traceability information synchronously changes with the parameter modification, to ensure the configuration takes effect.
