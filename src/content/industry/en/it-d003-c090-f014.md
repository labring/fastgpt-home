# Security and Compliance Material Review for Version Releases and Release Notes: Model Integration and Configuration

## What data for this category looks like
This category of data consists of structured change records for a single version release. Common delivery formats include Release Notes, change logs, version tags, and release checklists.
Data sources include Git tags, merged commit records, CI build artifacts, and Issue milestone entries. Updates occur once per version release.
Each entry includes fields such as change type, associated commit hash, associated Issue number, and artifact checksum. It covers full process information from code changes through to release artifacts.

## Constraints for model integration and configuration
The long-text nature of this category of data requires sufficient context capacity when integrating models. This avoids truncation of critical change information.
The version-triggered update rhythm requires configuring review workflows that support manual or scheduled triggers. This aligns with the daily operational habits of release-related personnel.
Data sources rely on code repositories and CI artifacts. Model integration must support parsing structured code text and checksum information. This ensures review scope only covers merged release content.
Review results must directly map to compliance requirements for Release Notes. Configure model output formats to align with the fields of release documentation.

## Configuration settings
These configurations are customized for this scenario, and are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` (example root address, replace with actual AI Proxy service root address) | Root address of the AI Proxy service. Do not append `/v1` or specific model paths. This is a required environment variable for the App/Admin server. |
| `AIPROXY_API_TOKEN` | Administrator token matching the AI Proxy server configuration | Completes identity verification for the AI Proxy service. Ensures valid call permissions. Do not use model vendor keys or application API Keys. This is a required environment variable for the App/Admin server. |
| `maxContext` | `8000–12000 token` | Accommodates full long-text change records for a single version, avoiding input truncation |
| `temperature` | `0.1–0.3` | Generates stable compliance review and change classification results. Prevents irrelevant output from interfering with Release Notes authoring |
| `maxTokens` | `1500–2000 token` | Controls output length of individual review results. Aligns with release document formatting specifications |
| `toolChoice` | `none` | Focuses on text review tasks. No external tool calls required |

## Three common configuration errors
- A `422 "Messages token length must` error is returned when calling the model. Cause: The `maxContext` parameter was not adjusted for this category's long-text change data. This causes input context to exceed the model's supported token limit.
- Review results return false after reordering models are configured. Cause: The reordering model was not bound to the trigger workflow for the corresponding review task. Or the input format of the configured reordering model does not match the change log fields of this category.
- A locally deployed custom model cannot connect properly. Cause: The upstream model channel for AI Proxy docking was not configured correctly. Or the permission scope of the AI Proxy administrator token was not set correctly.

## How to confirm correct configuration
- Check the App/Admin service startup logs. Confirm there are no startup validation failure prompts related to `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- Review model call logs. Confirm `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have no format errors, and network connections are functional.
- Trigger an automatic review workflow for a version release. Confirm it can properly pull category data such as Git tags and CI artifacts, with no missing or truncated data.
- Adjust the value range of the `temperature` parameter. Compare review result consistency across different configurations. Confirm stability matches expected standards.

The values provided are common starting points. They should be evaluated against the reader's own samples.
