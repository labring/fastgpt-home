# Security and Compliance Material Review for On-Site Deployment Implementation: Source Citation and Traceability

## What Data for This Category Looks Like
Data for the on-site deployment implementation category originates from first-hand on-site resources including customer data center environments, equipment inventories, software packages, network topologies, and more. Teams produce four types of documents regularly: deployment manuals, installation records, configuration lists, and on-site check-in sheets.
Data updates occur per order or per phase. Fields include deployment node identifiers, software version numbers, configuration parameter values, on-site check-in times, network connectivity status, and additional relevant details. No unified standard format exists, and adjustments are made based on differences in customer on-site environments.

## What Constraints Do These Characteristics Impose on Source Citation and Traceability?
Data sources for on-site deployment implementation are mostly first-hand on-site customer resources, and updates occur per order or per phase. This requires that citation traceability must be accurately bound to specific document entries for individual deployment tasks.
Daily document formats are inconsistent, so support for source tagging across multiple document types is required. Data links to actual results of on-site installation and configuration, so traceability must distinguish between actual execution data for deployment implementation and pre-planning documents.
Additionally, on-site data has strong uniqueness. Staff must avoid confusion between citation content from different deployment orders, ensuring that the traceability chain can be traced back to specific on-site links.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 2–4 entries | Matches the core document count for on-site deployment orders, avoids introducing irrelevant redundant content |
| `quoteMaxToken` | 1200–1800 token | Adapts to the typical 5000 token chunk setting for on-site deployment documents, controls the length of a single citation |
| `responseData` | Include source path, document type fields | Extracts identifiers for on-site documents such as deployment manuals and installation records, supports precise traceability |
| Maximum Context | No more than 5000 token | Matches knowledge base chunk sizes, accommodates complete configuration information for a single phase of deployment |
| `detail` | Enabled | Displays specific document entries, such as node information from installation records, to refine traceability dimensions |

## Three Common Misconfigurations
- Phenomenon: Matching on-site deployment document chunks are retrieved, but the final cited content exceeds the set `quoteMaxToken` limit. Cause: The knowledge base chunk size is not linked to the `quoteMaxToken` configuration, and the content length within the chunk exceeds the set token limit.
- Phenomenon: Citation sources only display the knowledge base name, and do not mark specific document types such as deployment manuals or installation records. Cause: The field extraction configuration for `responseData` is not enabled, and the mapping rules for source paths and document types are not configured.
- Phenomenon: Citation content from multiple deployment orders is confused, and on-site data from different customers cannot be distinguished. Cause: Deployment task IDs are not bound as retrieval filter conditions, resulting in incorrect recall of document content across orders.

## How to Confirm Configuration Is Properly Set Up
- Initiate a retrieval targeting on-site deployment documents, check that the source fields of returned results include corresponding types such as deployment manuals and installation records.
- Adjust `quoteMaxToken` to 1000 token, retrieve a single 5000 token chunk, confirm that the cited content does not exceed the set token length.
- Initiate retrievals for two different deployment orders, confirm that returned source information only relates to documents for the current task, with no cross-order confusion.
- View the `detail` field of returned results, confirm that it includes specific on-site deployment details such as node identifiers and configuration parameters.

The values provided are common starting points and should be measured against the reader's own samples.
