# Security and Compliance Material Review for On-Site Deployment: Document Parsing and Chunking

## What the data for this category looks like
Typical data comes from customer on-site data center environments, equipment lists, software packages, and network topology documents. Update frequency follows per order or project phase.
Daily processed documents include deployment manuals, installation records, configuration inventories, and on-site check-in sheets.
Most document structures are multi-column tables, sectioned explanations, and parameter lists. Fields include device model, IP address, software version, configuration parameters, and check-in time. Units include units, pieces, seconds, MB, and others.

## Constraints on Document Parsing and Chunking
Parsing tools must retain column associations for multi-column table documents, including configuration inventories and network topologies. Default rules that only recognize the first two columns must be avoided.
Parsing cannot accurately extract fields from non-standard on-site documents, such as deployment manuals with handwritten annotations, when using general parsing rules.
Single document volumes vary widely, from a few KB on-site check-in sheets to tens of MB equipment lists. This creates a need for flexible parsing timeout settings.
Each order’s data is independent and has no universal template. Custom chunking rules must be supported to adapt to different customers’ document formats.

## How to Configure Settings
This guide is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single sections in deployment manuals and configuration inventories, avoids overly fragmented chunks that cause scattered retrieval, or overly long chunks that cause context overflow |
| `chunkSplitter` | Split by paragraph + header | Adapts to multi-column table documents, retains the association between columns and content, avoids only recognizing the first two columns of data |
| `customPdfParse` | Enabled | Adapts to non-standard layout on-site PDF documents, extracts key fields such as device model and version number from the original layout |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time consumption for large equipment lists and complex topology files, avoids parsing failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the upload requirements for large equipment lists and topology files in on-site deployment scenarios |
| `chunkSettingMode` | Manual mode | Adapts to different types of on-site documents, flexibly adjusts chunking rules to match document structures |

## Three Common Misconfigurations
- Phenomenon: After uploading a multi-column configuration inventory Excel file, only the first two columns of content can be matched during retrieval. Cause: The chunking rules were not adjusted, and the default configuration was used which only recognizes the first two columns of data.
- Phenomenon: Device model fields are missing after parsing a deployment manual PDF. Cause: The `customPdfParse` parameter was not enabled, and the default parsing cannot adapt to non-standard on-site document layouts.
- Phenomenon: Boolean configuration parameters parsed later become empty after conditional judgment. Cause: The original data type was not retained during parsing, and no adaptation processing was performed after conversion to a string.

## How to Verify Proper Configuration
- Upload a single typical configuration inventory Excel file, check that the number of parsed data columns matches the original document.
- Upload a non-standard layout deployment manual PDF, confirm that the parsed results include key fields such as device model and version number.
- Trigger a parsing task for a large equipment list, check that the task log has no timeout errors, and confirm that the time consumption meets the preset range.
- Import test data with boolean type parameters, verify that the conditional judgment component can correctly recognize the parameter type.

The values provided are common starting points and should be measured against the reader's own samples.
