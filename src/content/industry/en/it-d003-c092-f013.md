# Security and Compliance Material Review for On-Site Deployment: Permissions and Data Isolation

## What Data for This Category Looks Like
Data sources for this category include on-site first-hand resources such as customer computer room environments, device lists, software packages, and network topologies. Four types of documents are routinely produced: deployment manuals, installation records, configuration lists, and on-site check-in forms. Data is updated per order or per phase. Fields include device identifiers, configuration parameters, deployment times, permission allocation items, and more. There are no unified fixed units, and values adjust based on customer on-site environments and project requirements.

## Constraints on Permissions and Data Isolation
On-site deployment data often involves core customer computer room resources and sensitive configurations. Each order’s data is independent and updated frequently. This requires permission isolation to match the exclusive data boundaries of individual projects. Documents such as deployment manuals and installation records contain undisclosed configuration details. Access must be restricted to authorized personnel only. Network topology data from customer computer room environments relates to security topologies. Permission configurations must align with on-site network isolation rules to avoid cross-project data confusion. At the same time, personnel operation records such as on-site check-in forms must be tied to corresponding implementer permissions. This ensures operational traceability and reduces compliance risks.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Team Permission Binding | Bind exclusive project teams via `teamId` | Matches the characteristic of independent data per on-site deployment project, prevents cross-project permission confusion |
| Member Permission Granularity | Divide by job role: implementation engineers can only read and write deployment configurations; customer IT personnel can only view on-site records | Adapts to the different role needs of implementation engineers, system engineers, and customer IT staff |
| API Call Permissions | Only open API call permissions under the specified `teamId`, valid for 7 days | Limits external call scope, matches the temporary deployment scenario of on-site deployment |
| Knowledge Base Access Isolation | Bind `tmbId` with customer computer room device identifiers | Ensures the knowledge base is only visible to authorized personnel for the corresponding project |
| Operation Log Retention | Retain for 30 days after the project cycle ends | Meets traceability requirements for compliance reviews |
| Version Compatibility | FastGPT v4.17.0 | Ensures configuration items are compatible with the current version |

## Three Common Configuration Errors
- Symptom: Project-specific API calls return a 403 permission denied error. Cause: API call permissions are not bound to the corresponding `teamId`, leading to failed cross-project permission verification.
- Symptom: Non-project personnel can view deployment configuration documents for the current project. Cause: Project data and permissions are not isolated via `tmbId`, and permission configurations are not bound to project identifiers.
- Symptom: Deleted team members can still access project data. Cause: Permission binding relationships are not updated synchronously, and residual permission configurations are not cleaned up.

## How to Verify Correct Configurations
- Attempt to log in to the backend using an unauthorized account, verify that deployment configurations and knowledge base content for the current project cannot be accessed.
- Call the API interface bound to `teamId`, verify that only authorized accounts can return valid data, and unauthorized accounts receive a permission denied prompt.
- Check the operation log module, confirm that all permission changes and configuration operations record corresponding personnel identifiers and timestamps.
- Verify that deleted team member accounts can no longer access project-related documents and configuration items.
