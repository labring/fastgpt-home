# Security and Compliance Material Review for User Growth and Retention Operations: Permissions and Data Isolation

## What Data for This Category Looks Like
Typical daily documents for this category include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Data sources include user behavior logs, push systems, experiment platforms, and CRM systems. User segmentation tables contain fields such as user ID, outreach count, retention duration, and more. Outreach copy marks push channels and trigger conditions. Growth experiment plans record experiment groups and core metrics. Retention analysis reports summarize daily and weekly retention data. Data updates generate daily behavior log summaries, and output user segmentation and retention reports on a weekly basis.

## What Constraints Do These Characteristics Impose on Permissions and Data Isolation?
Data involved in this category includes sensitive content such as user behavior and CRM customer information. Unauthorized or cross-team access may lead to user dissatisfaction and reduced retention. Multi-source data and multiple types of documents require isolation by project groups. The permissions of different operation personnel must match their assigned experiments and user segmentation scopes. Daily and weekly data updates require synchronized permission configurations to prevent newly generated reports from being excluded from permission filtering. At the same time, content such as login-free links and session records must be bound to the operating subject of the corresponding team to prevent unauthorized access.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Team Permission Binding | Assign exclusive data scope by `teamId` | Matches the project-based work model of growth operations, prevents cross-team data leaks |
| Login-Free Link Quota | Configure 10-100 per team by `teamId` | Adapts to the basic limits of the team version package, can be adjusted based on business needs |
| Data Scope Filtering | Only open user segmentation tables and retention reports under the current `teamId` | Prevents operation personnel from accessing sensitive user data from non-current projects |
| Session Permission Verification | Verify the binding relationship between `teamId` and the current session | Prevents unauthorized users from operating exclusive operation session records |
| Operation Log Audit | Retain full operation logs for `7 days` | Facilitates backtracking of permission violation operations, meets compliance review requirements |

## Three Common Configuration Mistakes
- When creating a login-free link, a prompt appears indicating the quota limit has been exceeded. The cause is that the login-free link quota for the current `teamId` has been exhausted, and the upper limit for the corresponding team was not adjusted via configuration.
- When operating conversation records, a "No permission to operate this conversation record" prompt appears. The cause is that the current user is not bound to the operating permissions of the corresponding `teamId`, or the `teamId` to which the session belongs does not match the current context.
- Cross-team viewing of retention analysis reports from other projects. The cause is that data scope filtering by `teamId` was not configured, leading to failed permission isolation.

## How to Verify Successful Configuration
- Switch accounts with different `teamId` values, verify that only the user segmentation tables, experiment reports, and outreach copy of the corresponding team can be accessed.
- Attempt to create a login-free link, confirm that the number of created links does not exceed the quota limit configured for the current `teamId`.
- When operating exclusive operation sessions, check that only users belonging to the current `teamId` are allowed to perform edit and delete operations.
- View operation logs, confirm that all sensitive operations are associated with the operating subject of the corresponding `teamId`.
