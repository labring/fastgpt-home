# Security and Compliance Material Review for User Acceptance Testing Support: Citation Sources and Traceability
This document applies to FastGPT v4.17.0.

## What the Data for This Category Looks Like
Core data for this category is generated across the full user acceptance testing (UAT) workflow. Daily documents include UAT test cases, acceptance issue tickets, acceptance reports, and signed confirmation forms. Data sources are requirement specifications, test environments, client business samples, and defect systems. Update frequency follows per-phase or per-version cycles. Fields include test case ID, issue description, acceptance conclusion, associated defect ID, and additional relevant fields. There are no uniform fixed units. Matching must be done based on the business scenario of each individual document. Data is maintained jointly by implementation consultants, test managers, and client business representatives. Core associations rely on results confirmed by target clients per their business scenarios.

## Constraints for Citation Sources and Traceability
The exclusive scope of data sources requires traceability to strictly link to specified sources such as requirement specifications and test environments. Non-UAT process documents must not be included. The periodic update frequency requires traceability data to match the current acceptance phase. Expired historical data must be avoided in citations. The non-standardized document structure requires traceability to locate content via the business node of each individual document. Unified field rules cannot cover all use cases. The diverse data maintenance subjects require traceability to support association with multi-role operation records. This ensures the traceability of acceptance conclusions. The severity of error consequences means no mistakes are allowed in the traceability link. Otherwise, acceptance delays, delayed final payments, or scope disputes may occur.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum citation token count | 800–1200 token | Matches the average length of individual UAT test case documents, ensuring complete coverage of cited content |
| Response data filter | Only retain acceptance report and defect system fields | Filters non-business redundant data, focusing on core UAT documents |
| Citation detail display | Enabled | Shows specific nodes of citation sources, facilitating test managers to verify acceptance basis |
| Single recall limit | Top 5 entries | Matches the volume scale of UAT test cases per phase, avoiding redundant citations |
| Context length | Calibrated via actual testing | Adapts to the volume of requirement specification data updated per phase, preventing context overflow |

## Three Common Configuration Errors
- A parameter error is returned when viewing citation sources in chat responses. The cause is that filter rules are not configured per the UAT category's data source scope, and unauthorized documents outside requirement specifications are called.
- Knowledge base search input and output citation content still appears after workflow invocation. The cause is that the citation display switch for non-core documents is not turned off, and temporary data from test environments is included in the traceability scope.
- Cited UAT test case content is truncated and cannot be viewed in full. The cause is that `quoteMaxToken` is set too small, failing to match the average character length of individual test cases.

## How to Verify Proper Configuration
- Input a question related to UAT acceptance, check the citation sources below the response, and confirm only documents of the specified category such as requirement specifications and acceptance reports are displayed.
- Trigger a workflow invocation, check that the response only shows the final acceptance conclusion, with no intermediate input and output content from tool calls.
- Adjust the value of `quoteMaxToken`, verify that cited content is displayed in full without truncation.
- Simulate an acceptance phase switch, check that traceability data automatically associates with UAT test cases and defect records from the current phase.

The values provided are common starting points and should be measured against the reader's own samples.
