# Security and Compliance Material Review for Monitoring Alert Configuration: Document Parsing and Chunking

## What Data Looks Like for This Category
This category of data originates from operational tools including Prometheus, Zabbix, cloud monitoring, application logs, and CMDB. Updates occur daily or when configuration changes are made. Daily documents include monitoring metric lists, alert rules, on-duty manuals, and alert change records. Metric lists contain fields such as metric names, collection cycles, and threshold ranges. Alert rules include structured content like trigger conditions, associated metrics, and notification links. Change records include metadata such as operation time, operator, and change details.

## What Constraints Do These Characteristics Impose on Document Parsing and Chunking
The structured nature of monitoring alert configuration documents requires parsing and chunking to preserve field association relationships. Do not split content that breaks alert rule trigger logic.
Format differences across multiple sources — including Prometheus YAML, Zabbix XML, and exported PDF reports — require parsing logic with format adaptation capabilities.
Frequently updated documents need efficient parsing workflows. Delayed parsing can compromise the timeliness of compliance reviews.
Large batch-imported CMDB export files require adaptive chunking parameters and timeout settings. These settings prevent parsing interruptions.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of alert rules and metric lists. Avoids splitting that breaks complete logic such as thresholds and trigger conditions |
| `chunkSplitter` | Semantic chunking | Preserves nested trigger conditions and metric association relationships in alert rules. Avoids logical breaks caused by mechanical splitting |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 seconds | Adapts to the parsing duration of batch alert configuration files. Prevents parsing timeouts for large-volume alert change records |
| `UPLOAD_FILE_MAX_SIZE` | 100–200 MB | Adapts to batch-imported CMDB export files and quarterly alert change records. Meets batch requirements for compliance reviews |
| `customPdfParse` | Enabled | Adapts to exported Zabbix monitoring report PDFs. Preserves structured information from tables and metric rows |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different source documents (such as Prometheus YAML, Zabbix XML). Adapt parsing requirements for structured data |

## Three Common Configuration Mistakes
- Some uploaded PDF files show empty content, while others are partially recognizable. Cause: The `customPdfParse` configuration is not enabled. The custom parsing logic is not triggered for encrypted or non-standard PDF alert reports.
- Renaming Java interface file extensions to .txt and importing them results in no parsing output. Cause: Alert configuration documents mostly use structured formats. Plain text import does not trigger format recognition rules. It cannot extract key fields such as metrics and thresholds.
- Using chunk mode to call the pushdata API for upload shows "indexing" indefinitely. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too low. Batch alert change record parsing does not complete before entering the indexing stage. Or the `chunkSize` setting is too small, leading to too many chunks and backlogged indexing queues.

## How to Confirm Configuration Is Successful
- Check the environment variable configuration of the App/Admin server. Confirm that `AIPROXY_API_ENDPOINT` (the root address of the AI Proxy service. Do not append paths such as /v1 or /chat/completions. Do not configure it as a single model address such as VLLM/Ollama/Xinference) and `AIPROXY_API_TOKEN` (the AI Proxy administrator token. It must match the AI Proxy server configuration and cannot be empty. Do not use it as an application API key or model vendor key) are correctly set. Do not configure these values in workflow global variables, application API request headers, or the general model management page.
- Upload a single typical alert rule file. View the parsed chunk content. Confirm that key fields such as metric names, thresholds, and trigger conditions are not split or lost.
- Batch import CMDB-exported alert configuration files. Verify that the number of parsed entries matches the number of records in the original file. No empty fields or abnormal truncation occur.
- View FastGPT server logs and AI Proxy service logs. Troubleshoot errors related to authentication failures or connection exceptions when FastGPT calls AI Proxy. Verify that the configuration takes effect.
