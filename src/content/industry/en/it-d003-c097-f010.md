# Security and Compliance Material Review for Community Events and Developer Relations: Source Citation and Traceability

## What data for this category looks like
This category applies to campaign operations focused on outreach, Q&A, and user connection, and is distinct from community contributor governance work. Typical data comes from community forums, registration systems, social media, and project roadmaps. Four types of documents are regularly generated: activity plans, speaking scripts, registration lists, and post-event activity reviews. Document structures cover structured registration fields and unstructured speaking script content. Update cycles follow monthly intervals or individual activity periods, with no fixed mandatory update rhythm. Data fields include activity topics, speaker information, registration status, community feedback, and more. There are no unified mandatory format requirements.

## What constraints these characteristics impose on source citation and traceability
Community event and developer relations data sources are scattered and have diverse formats. Traceability functions must support multi-source knowledge base association and mixed retrieval of structured and unstructured content. Document update frequencies are not fixed. The system must adapt to dynamically updated knowledge base content, and avoid citing expired materials. Compliance review of activity-related materials must strictly match original content. No modifications or truncation that cause traceability deviations are allowed. Complete source metadata must be retained to meet compliance requirements. Additionally, activity materials for this category are usually limited in quantity. Retrieval and recall must control scope to avoid introducing irrelevant content that reduces review efficiency.

## How to configure settings
These configurations apply to FastGPT v4.17.0 and later.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Activity-related documents are usually moderate in length. This range fully retains core content required for traceability, and avoids truncating critical information |
| `responseData` | `Return full original text fragments` | Compliance review requires direct matching with original materials. Avoid AI modifications that prevent traceability matching |
| `detail` | `Enabled` | Document ID, update time, and other metadata of cited sources must be displayed to meet traceability requirements for compliance |
| Single recall count | `Top 3–5 results` | Reference materials related to community activities are usually limited in quantity. Excessive recall will introduce irrelevant content |
| Multi-knowledge base association | `Bind activity-specific knowledge base and community general knowledge base` | Activity plans come from the activity-specific library, and community rules come from the general library. This covers both types of traceability needs |
| Retrieval trigger condition | `Trigger via workflow node` | Adapt to staged review scenarios in DevRel workflows, and avoid unnecessary retrieval resource consumption |

## Three common misconfigurations
- Only the first workflow node triggers knowledge base citations, with no citation results in subsequent nodes. This occurs because knowledge base association is not configured separately for each retrieval node.
- Retrieval results return empty or lack source metadata. This occurs because the `detail` parameter is not correctly configured, or the App/Admin server has not correctly configured non-empty `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`.
- AI-generated knowledge base content is automatically modified. This occurs because `responseData` is not set to return full original text fragments, and the default content organization logic is enabled.

## How to verify correct configuration
- Check the App/Admin server environment variables. Confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy administrator token) are correctly configured and not empty.
- Run a workflow test. View the return results of each retrieval node. Confirm that the results include original text fragments and metadata information.
- Adjust the value of `quoteMaxToken`. Verify that the length of returned content meets expectations, with no truncation.
- Switch the multi-knowledge base association configuration. Confirm that retrieval results cover content from both the activity-specific knowledge base and the community general knowledge base.

The values provided are common starting points, and should be measured against applicable samples.
