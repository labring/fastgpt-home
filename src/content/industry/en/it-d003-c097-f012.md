# Security and Compliance Material Review for Community Events and Developer Relations: Document Parsing and Chunking

## Data Profile for This Category
The core data for this category comes from community forums, event registration systems, social media platforms, and project roadmaps. Updates occur monthly or per individual event cycle. Daily processed documents include event execution plans, public speaking scripts, event registration lists, and post-event review materials. Most document structures include fields such as event theme, participant information, compliance reminders, and process nodes. Some documents include image or link attachments. Document planning, speaker coordination, and other workflow links often rely on these materials.

## Constraints Imposed on Document Parsing and Chunking
Differences in document formats across multiple sources create parsing compatibility constraints. The parsing process must adapt to multiple formats including rich text, tables, and long-form text. Frequently updated documents require batch processing support, to avoid delaying event preparation. Documents contain sensitive or critical content such as registration lists and compliance reminders. Chunking must preserve semantic integrity, to avoid breaking associative logic between compliance clauses and participant information. Some documents include technical links or images. Parsing must retain attachment associations. Missing information may lead to event delays, incomplete community feedback collection, or damage to brand reputation.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Event plans, speaking scripts, and similar documents are mostly technical or event-related long-form text. This range preserves semantic integrity and avoids splitting that breaks the association between event processes and compliance clauses. |
| `chunkSplitter` | Split by paragraph + heading | Daily documents mostly include hierarchical headings and paragraph structures. Splitting this way ensures chunks correspond to independent event links or compliance clauses. |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Individual event review materials or bulk registration list files have large file sizes. This duration prevents parsing timeouts from interrupting the workflow. |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Some event material packages include multiple documents and image attachments. This upper limit covers bulk upload requirements. |
| `chunkSettingMode` | Manual configuration | Chunking requirements differ across document types, such as registration lists versus event plans. Manual configuration allows flexible parameter adjustments to fit specific scenarios. |
| `customPdfParse` | Enabled | Some event speaking scripts are published in PDF format. Enabling custom parsing accurately extracts text and embedded links, avoiding information loss. |

*Note: This document is written based on FastGPT v4.17.0*

## Three Common Configuration Mistakes
- When parsing event speaking scripts with embedded demonstration links, a "failed to associate attachments" log prompt appears. Cause: The `customPdfParse` parameter is not enabled, and the default parsing logic does not retain the association between embedded links and text blocks.
- When bulk uploading multiple event material packages, some files fail to upload with a "file size limit exceeded" prompt. Cause: The `UPLOAD_FILE_MAX_SIZE` parameter is not adjusted, and the default upper limit is insufficient to cover the total volume of event material packages.
- After uploading a Word-format event review material, the document can be parsed but embedded image links cannot be called during question answering. Cause: No image association parsing rules are configured, and only text content is extracted during chunking without retaining the binding relationship between image links and corresponding text.

## How to Verify Configuration Correctness
- Upload a single event plan document, check if the number of parsed chunks matches the number of document paragraphs, and adjust `chunkSize` to achieve the expected chunk granularity.
- Upload a table document containing a registration list, verify that each chunk after chunking contains complete single registration information, and confirm that the chunking rule adapts to the table structure.
- Upload a PDF speaking script containing embedded links or images, check if the parsing result retains attachment association information, and verify that the `customPdfParse` parameter is enabled.
- Bulk upload multiple event material packages, confirm that the upload process does not trigger a file size limit prompt, and verify that the `UPLOAD_FILE_MAX_SIZE` parameter is configured correctly.

The values listed above are common starting points and should be evaluated against respective samples.
