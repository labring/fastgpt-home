# Security and Compliance Review for Community Events and Developer Relations: Permissions and Data Isolation

## What this category of data includes
Typical entities for this category are community operations teams, project maintainers, and developer relations specialists. Teams produce daily documents including event plans, public speaking scripts, registration lists, and post-event review records. Data sources cover community forums, event registration systems, social media accounts, and public project roadmaps. Data is updated on a monthly or single-event cycle.
Event plans include fields for theme, time, speaker information, and budget. Registration lists include fields for attendee name, contact information, and registration time. Speaking scripts include fields for topic, duration, and speaker notes. Data volume fluctuates with event scale. Documents related to a single event typically do not exceed 1000 MB.

## What constraints these characteristics impose on permissions and data isolation workflows
Multiple data sources lead to significant differences in information sensitivity across channels. For example, contact information in registration lists counts as sensitive data. This data must be strictly isolated from public speaking scripts. Event-driven update cycles require permission configurations to support temporary adjustments and periodic expiration. This prevents unexpired access permissions from remaining active after an event concludes.
Differences in usage scenarios for different documents require layered permission granularity. For example, only core teams may edit plans during the event planning phase. Post-event review materials may be opened to community members for viewing.
This category supports communication, Q&A, and user connection, and differs from community contributor governance. Permission configurations must balance boundaries between public and sensitive data. Incorrect permission configurations may lead to sensitive data leaks, or unauthorized personnel interfering with event preparation. This can result in low event turnout or damage to brand reputation.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind a dedicated `teamId` for each community event, only add the event's operations personnel to the corresponding team | Clearly define data boundaries between different events, avoid cross-event data confusion |
| `tmbId` | Assign independent `tmbId` values to speakers and volunteers, only grant access to public materials and registration lists for the corresponding event | Restrict external participants to only access published event content, prevent access to sensitive information |
| Login-free link validity period | `72 hours`, calibrated to the event preparation cycle | Match the time window from event planning to execution, prevent unauthorized use if links are leaked long-term |
| Data export permissions | Only open to administrators bound to the `teamId`, restrict export scope to current event documents and registration data | Prevent unauthorized export of sensitive registration lists or unpublished event plans |
| Member permission granularity | Divide by role (planning/execution/public), only grant corresponding permissions | Match work division scenarios of DevRel teams, prevent unauthorized modification or viewing of sensitive documents |

## Three common configuration errors
- Symptom: After local deployment, team groups cannot be created, and a prompt states the team identification field is empty. Cause: Initialization parameters for `teamId` were not configured correctly, and no dedicated team identification was bound to the event.
- Symptom: Login-free links allow unauthorized users to access sensitive data such as registration lists. Cause: The login-free link was not bound to the corresponding `tmbId`, and permission verification did not associate the event's dedicated data scope.
- Symptom: Exported conversation or document content includes materials from other events. Cause: Permission configurations did not filter data by `teamId`, and cross-event documents were not isolated.

## How to verify correct configuration
- Attempt to access the current event's registration list using an unauthorized account, confirm the corresponding page cannot be opened.
- View the member list bound to the `teamId`, confirm it only includes the current event's operations personnel and authorized roles.
- Generate a login-free link, verify the link is only valid for 72 hours, and cannot access documents from other events.
- Attempt to export event data, confirm only documents and registration information for the current event can be exported.
