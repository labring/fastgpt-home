# Security and Compliance Material Review for Community Contributor Governance: Conversation Logs and Audits

## What this type of data looks like
Data sources include code repository commit records, community forum posts, contributor contribution statistics reports, and governance meeting minutes.
Update cadence is monthly or quarterly.
Daily associated documents include contribution guidelines, community code of conduct, maintainer lists, and governance decision minutes.
Single record fields include contributor unique identifier, operation time, operation type, associated document version number, and reviewer identifier.
Statistics use entries as the unit, with no fixed quantitative unit.
This page content is compiled based on FastGPT v4.17.0.

## What constraints these characteristics impose on conversation logs and audits
Data sources are scattered across multiple platforms such as code repositories and community forums. Conversation logs and audits must use unified associated identifiers to ensure cross-source records can be matched.
Update frequency is monthly or quarterly. Audit retention periods must cover all historical changes, and no frequent truncation is required.
Associated documents include rule texts such as code of conduct and contribution guidelines. Audit records must bind corresponding document versions to avoid ambiguity in rule traceability.
Fields include sensitive information such as contributor identity and review operations. Log access ranges must be restricted to only roles related to governance.
Governance processes involve steps such as role permission confirmation and contributor promotion evaluation. Audit logs must fully record every operation to ensure traceability of decision-making processes.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Combine contributor unique identifier and session creation timestamp | Unify log association identifiers across code repositories and community forums, matching cross-source data characteristics |
| Conversation log retention period | 90 days | Cover monthly/quarterly governance update cycles, meet full audit traceability requirements |
| `detail` | Enable full field recording | Include complete information such as contributor ID and operation type, support governance dispute traceback |
| `responseChatItemId` | Bind unique record ID of review operation | Associate conversation content with final governance decisions, clarify operation association subject |
| Log export permissions | Only open to maintainer committee members | Restrict access to sensitive governance information, comply with compliance requirements |
| Audit record granularity | Generate single log per single operation | Match low update frequency of community governance data, avoid log redundancy |

## Three common configuration errors
- Phenomenon: When the same contributor ID initiates multiple governance-related conversations, historical conversations are not loaded, and only a single interaction is retained in the session log. Cause: The `chatId` is not used to bind log association identifiers across sessions, so the system cannot identify historical interactions from the same contributor.
- Phenomenon: Associated document version information is missing from exported conversation logs, making corresponding governance rules untraceable. Cause: Full field recording for the `detail` parameter is not enabled, so the document version number field is omitted.
- Phenomenon: The system prompts a database connection error, and audit logs cannot be written to storage normally. Cause: Log storage database connection information is not configured correctly, or connection parameters do not match the database service port.

## How to confirm configuration is successfully applied
- Initiate a conversation related to contributor governance. Check if the spliced `chatId` field is included in the log to confirm cross-source association configuration is active.
- Check the log storage directory or database to confirm log retention periods meet configured requirements, with no automatic cleanup rules triggered.
- Attempt to access logs using a role that is not a maintainer committee member. Confirm the system rejects access to verify permission configuration is active.
- Export a test log. Check if full fields are included, such as document version and review operation ID, to confirm the `detail` parameter is configured correctly.
