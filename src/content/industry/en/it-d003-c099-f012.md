# Security and Compliance Material Review for Mobile Development: Document Parsing and Chunking

## What data looks like for this category
This category of data primarily comes from code repositories, app store backends, crash monitoring platforms, and device coverage data. Commonly processed documents include device version release notes, device adaptation lists, crash analysis reports, and app store listing materials. Data updates follow a daily or per-version release cycle. Most documents have fixed fields such as version number, compatible device range, permission call configuration, and review status identifier. Some documents include embedded screenshots, multi-column tables, and cross-page compliance attachments.

## What constraints these characteristics impose on document parsing and chunking
The multi-device fields in version release notes and adaptation lists, plus the segmented compliance requirements for app store materials, require that parsing preserves field relationships to avoid information fragmentation from cross-field chunking. Multi-column tables and cross-page documents can cause content disconnection with generic chunking logic, so targeted adjustments to chunk boundaries are needed. Time-series data in crash analysis reports require chunking to retain contextual connections, and critical time-series nodes must not be split. Embedded image attachments and multi-format content need to be associated with corresponding text during parsing to avoid separation of text and assets. Additionally, daily updated version data and periodically released documents require the parsing process to have stable timeout handling to adapt to the high-frequency update business rhythm.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the field length of mobile documents and the segmentation requirements of compliance materials, avoiding splitting critical permission configurations or version information |
| `chunkSplitter` | Split by paragraph + heading | Adapts to the structured document structure of version release notes and adaptation lists, preserving field relationships |
| `customPdfParse` | Enabled | Compatible with FastGPT v4.17.0’s PDF parsing engine, supporting extraction of complex layouts with multi-column tables and embedded images |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the maximum attachment size for a single version release note or listing material, meeting upload requirements for large adaptation lists |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of multi-device adaptation lists and crash analysis reports, avoiding parsing interruptions in high-frequency update scenarios |
| `chunkSettingMode` | Manual configuration | For special layouts of mobile documents, customize chunk boundaries and association rules to adapt to different types of compliance materials |

## Three common errors
- After uploading a PDF document with embedded images, the parsing result only returns text content with no associated image information. This occurs because the `customPdfParse` configuration is not enabled, and the default parsing logic does not extract and associate embedded image content.
- After importing multi-column adaptation lists or app store materials, table content shows column misalignment or field merging. This occurs because the `chunkSplitter` set to split by paragraph + heading is not used, and generic chunking logic cannot identify the structural boundaries of multi-column documents.
- Timeout errors with status code 504 occur when parsing large version release notes. This occurs because `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a value range suitable for large documents, and the default timeout duration is insufficient to complete full parsing.

## How to confirm configurations are set correctly
- A test document containing multi-column tables and embedded images may be uploaded, and the parsing result may be verified to fully retain the table structure and image-associated text.
- A single document with a size matching the `UPLOAD_FILE_MAX_SIZE` value may be uploaded, and the upload and parsing processes may be checked for no interruptions or errors.
- For time-series crash analysis reports, the chunking results may be checked to retain contextual connections between adjacent nodes, with no critical time-series information split.
- After adjusting the `chunkSize` value, the chunked text units may be verified to fully cover a single compliance field or version information.

The values provided are common starting points and should be measured against the reader's own samples.
