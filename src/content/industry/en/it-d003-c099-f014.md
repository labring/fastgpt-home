# Security and Compliance Material Review for Mobile Development: Model Integration and Configuration

## What Data Looks Like for This Category
Data for this category primarily comes from code repositories, app store backends, crash monitoring platforms, and device coverage data. Update cadence follows daily or per-version release cycles. Daily produced documents include device version release notes, device adaptation lists, crash analysis reports, and app store review materials. Document fields cover version numbers, compatible device ranges, permission invocation instructions, review statuses, and more. There is no unified mandatory format; configurations must align with specific requirements of app stores and internal R&D processes.

## What Constraints Do These Characteristics Impose on Model Integration and Configuration
Scattered data sources and fluctuating update cadence tied to versions require model integration to support batch reading of multi-source data and incremental synchronization. Unstructured document formats require flexible context parsing rules to adapt to different release notes and adaptation lists. Regional differences exist in compliance requirements for devices and app stores; rule adjustment space must be reserved in model configuration to avoid hardcoding compliance clauses. Crash data has high real-time requirements; model call response time must be limited to ensure review efficiency. Different app stores have varying review standards; models must adapt to diverse output format requirements.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example `http://aiproxy:3000`. Do not append `/v1` or `/chat/completions` paths | Ensures the App/Admin service can correctly connect to the AI Proxy service, and adapts to AI Proxy nodes across different deployments |
| `AIPROXY_API_TOKEN` | Administrator Token matching the AI Proxy server configuration, cannot be empty | Completes identity verification between the App/Admin service and the AI Proxy service |
| `maxContext` | `8000–12000 token` | Adapts to batch parsing requirements for multi-source documents, covers multiple input content types including standard documents and style documents, avoids context overflow |
| `maxTokens` | `2000–3000 token` | Controls single-round output length, ensures generated review reports comply with character limit requirements of app stores |
| `temperature` | `0.1–0.3` | Reduces output randomness, ensures consistency of compliance review results, avoids inconsistent review standards caused by random output |
| `toolChoice` | `auto` | Automatically determines whether to call tools to assist compliance verification, adapts to review requirements across different scenarios |

## Three Common Mistakes
- Phenomenon: Model responses display "Completion Reason: Connection disconnected". Troubleshooting: Check if the `AIPROXY_API_ENDPOINT` configured on the App/Admin server is a valid root address for the AI Proxy service, or if the `AIPROXY_API_TOKEN` matches the AI Proxy server configuration and is not empty.
- Phenomenon: After using the same prompt to query, output results differ from native models. Cause: The `temperature` parameter was not adjusted to the low-randomness interval required for compliance review, or the `maxContext` value was too small, causing input documents to be truncated.
- Phenomenon: Call logs are not displayed on the model provider page. Troubleshooting: Check if the address and credentials configured for the upstream model channel are correct, or if the upstream model service is running normally.

## How to Confirm Configuration Is Complete
- Check that the App/Admin server has configured non-empty `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables, and service startup verification passes.
- View model call return results, confirm that the output format meets the structured requirements of app store review materials, with no obvious format errors.
- Verify that the `AIPROXY_API_ENDPOINT` configured on the App/Admin server is a valid root address for the AI Proxy service, and that the `AIPROXY_API_TOKEN` matches the AI Proxy server configuration and is not empty.
- Check that the model integration configuration supports batch reading of multi-source data and incremental synchronization, ensuring the data synchronization process operates normally.

The values provided are common starting points and should be measured against the reader's own samples.
