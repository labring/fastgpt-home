# Security and Compliance Material Review for Art Asset Production Management: Permissions and Data Isolation

## What data for this category looks like
Data sources for this category include art asset libraries, project management systems, engine resources, and outsourced delivery packages. Daily produced documents include art requirement sheets, asset specifications, outsourced feedback forms, and acceptance records.
Art requirement sheets include project ID, asset type, and delivery deadline fields. Asset specifications note resolution and triangle count units. Outsourced feedback forms record version numbers and modification items. Acceptance records include acceptance status and score fields.
Most data updates occur daily or weekly. Involved roles include art PMs, concept artists, 3D artists, and outsourced project managers.

## Constraints imposed by these characteristics on permissions and data isolation
Dispersed storage of multi-source data requires separate isolation rules for art asset libraries, engine resources, and outsourced delivery packages. This prevents unauthorized cross-source access.
Daily or weekly update frequency requires permission configurations that can be synchronized quickly. This adapts to asset iteration cycles.
Significant differences exist in document fields and operation permissions across roles. Precise matching of roles to accessible data ranges is required to prevent resource mismatches or performance overload issues.
Outsourced teams may only access assets they delivered. Separate permission boundaries must be defined to avoid internal asset leaks.

## Configuration Guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` binding | Assign a dedicated `teamId` to each R&D project | Art assets are stored categorized by project teams. After binding, only corresponding team members may access associated assets |
| `teamId` global verification | Enable the `teamId` global verification switch | Block unauthorized access requests for unbound projects, prevent cross-project resource misuse |
| `tmbId` role mapping | Assign dedicated `tmbId`s for art PMs, concept artists, and outsourced managers respectively | Significant differences exist in asset operation permissions across roles. Mapping allows precise control of operation scope |
| Data access validity period | Limit access to art assets updated in the last 7 days | Matches the daily or weekly update frequency of this category, avoids using expired or unaccepted assets |
| Permission synchronization cycle | Configure permission updates to sync every 10 minutes | Adapts to asset iteration cycles, ensures permission changes take effect promptly |
| Single retrieval limit | Limit the number of asset entries returned per single request to 20 | Controls data return scope, prevents bulk access to assets outside authorized permissions |

## Three common configuration errors
- Symptom: After configuring permissions, other team members can still edit art requirement sheets. Cause: Member accounts are not bound to the corresponding project's `teamId`, the global verification switch is not enabled, and permission verification does not take effect.
- Symptom: Outsourced members cannot view the 3D asset packages they delivered. Cause: Independent `tmbId` permissions are not assigned per outsourcer, shared `tmbId`s are incorrectly configured for all outsourced teams, leading to overlapping permission scopes.
- Symptom: Performance overload errors occur after importing art assets. Cause: Data access validity period restrictions are not enabled, members access high-polygon asset files that exceed specifications, leading to abnormal engine resource usage.

## How to confirm the configuration is correctly set up
- Log in with a test account that is not a project member, attempt to access the art asset library for the corresponding project, confirm that no asset content can be viewed or edited.
- Switch to a test account with an outsourced role, confirm that only the assigned dedicated outsourced delivery package can be viewed, and assets or documents from other teams cannot be accessed.
- Submit a permission update request, wait 10 minutes for synchronization, verify that the operation permissions of the role match the configured `tmbId` mapping rules.
- Import a test high-polygon asset, confirm that only roles authorized to access high-specification assets can view it normally, other roles cannot access the asset.
