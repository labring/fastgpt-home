# Security and Compliance Material Review for Art Asset Production Management: Model Access and Configuration

## What data for this category looks like
It typically includes documents created daily by art project managers, 2D artists, 3D artists, and outsourcing managers. These documents cover art requirement sheets, asset specifications, outsourcing feedback forms, and acceptance records.
Data sources include art asset libraries, project management systems, engine resources, and outsourcing delivery packages. Update frequency is daily or weekly.
Document fields include asset unique identifiers, specification parameters, delivery times, acceptance statuses, outsourcing party information, and more. Some documents include art resource preview images or delivery package files. Data structures vary across different sources.

## Constraints on model access and configuration from these data characteristics
Art asset production management data characteristics create multiple constraints for the model access and configuration process.
First, multi-source heterogeneous data formats require models to support parsing documents from different sources. Adaptation parameters must be configured.
Second, daily or weekly update frequencies require model contexts to synchronize latest asset information promptly. Expired data must be avoided.
Third, diverse document fields require models to accurately identify association relationships between different fields. This ensures accuracy of compliance reviews.
Fourth, the most time-consuming tasks of specification confirmation, outsourcing rework communication, and engine import inspection require models to prioritize recall and generation for these scenarios. This optimizes review efficiency.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to long text content related to art asset documents. Prevents truncation of critical asset specification and acceptance requirement information |
| `maxTokens` | 2000–3000 token | Meets length requirements for generating compliance review reports, outsourcing rework instructions, and similar content |
| `temperature` | 0.2–0.4 | Maintains rigor of compliance reviews. Prevents generation of content that does not match asset specifications |
| `vision` | Enabled | Supports compliance checks for art asset preview images and screenshots from outsourcing delivery packages |
| `AIPROXY_API_TOKEN` | Configure a non-empty administrator token matching the AI Proxy server | Used as an environment variable for the App/Admin server. Used for AI Proxy service identity verification. Must not be used as an application API call credential |
| `AIPROXY_API_ENDPOINT` | Configure the root address of the AI Proxy service, for example http://aiproxy:3000 | Used as an environment variable for the App/Admin server. Points to the AI Proxy service address. Must not include /v1 or model service paths |

## Three common misconfigurations
- No model creation icon in the top-right corner of the interface. Phenomenon: No model creation entry button appears after logging into the system. Cause: Corresponding permissions are not enabled, or the deployed version does not support custom model creation. Check permission configurations for FastGPT v4.17.0.
- Slow model response and high hard disk usage. Phenomenon: Slow response when calling the model. System hard disk IO occupancy rate is high. Troubleshooting steps: Check if `maxContext` and `maxTokens` parameter configurations match business requirements. Confirm that system hard disk IO load matches model call status.
- Accessible via local Docker deployment but cannot connect via OneApi. Phenomenon: Model calls work normally in a local Docker environment, but requests forwarded via OneApi fail. Troubleshooting steps: Check if `AIPROXY_API_ENDPOINT` is configured as the AI Proxy service root address. Confirm if network policies restrict cross-service access.

## How to confirm configurations are properly set
- Check environment variable configurations on the App/Admin server. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured and not empty.
- Initiate a compliance review test for an art requirement sheet. Verify that the model can correctly extract asset specification fields and generate compliance descriptions.
- Review system logs. Confirm there are no records of model call timeouts or parameter parsing errors. Adjust parameter values based on actual call conditions.
- Verify that the App/Admin server starts without validation errors related to missing environment variables. Confirm that the model call link is working normally.
