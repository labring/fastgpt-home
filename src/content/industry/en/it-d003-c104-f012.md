# Security and Compliance Material Review for Landing Page Conversion Optimization: Document Parsing and Chunking

## What data looks like for this use case
Service teams and personnel for this use case include growth product teams, front-end operations staff, and ad optimizers. Daily processed documents include landing page plans, tracking requirement documents, AB test reports, and form field lists. Data sources cover landing page access logs, page heatmaps, form submission data, and ad source parameters. Update frequency is weekly or within a single campaign cycle. Document structures include structured parameters, multiple sets of comparative data, and hierarchical page configurations. Common fields include page paths, form field names, and ad delivery identifiers. No fixed unified format template exists. FastGPT v4.17.0 includes specialized adaptive optimizations for document formats in this scenario.

## What constraints do these characteristics create for the document parsing and chunking step
The diversity of daily documents requires chunking rules to adapt to different content types. For example, structured parameters in tracking requirement documents must retain field associations. Multiple sets of data in AB test reports must avoid being split into disconnected chunks. The short-cycle update rhythm requires the parsing process to support fast batch processing. This avoids delaying campaign preparation due to excessive time consumption. Data attribution relies on complete document content. If parsing fails or chunking is improper, subsequent page path analysis and form blockage troubleshooting cannot proceed normally. This leads to lead loss and increased ad costs. Additionally, non-standardized document source formats require parsing tools to have flexible adaptive capabilities.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the single-section content length of landing page plans and AB test reports, avoids chunking too finely to lose context or too long to complete embedding |
| `chunkSplitter` | Separate by paragraph + heading | Matches the hierarchical structure of landing page plans, retains contextual associations for form field lists and tracking requirement documents |
| `customPdfParse` | Enabled | Processes PDF documents exported from landing pages, retains structured information such as form fields and page paths, prevents format loss |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to batch upload requirements for multiple documents within a single campaign cycle, prevents task interruption due to exceeding single upload limits |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 seconds | Covers the full parsing time of large AB test reports, prevents parsing failure due to timeout |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types, adapts to differentiated parsing requirements for tracking requirements and form field lists |

## Three common mistakes
- Symptom: Markdown formatting is not rendered in context references, only raw markup is displayed. Cause: `customPdfParse` is not enabled, or format markers are not retained during chunking, resulting in lost formatting information after parsing.
- Symptom: Document content cannot be parsed after passing in a link, only version update prompts are returned. Cause: Link crawling rules for `chunkSplitter` are not configured correctly, or `PARSE_FILE_TIMEOUT_SECONDS` is set too short, causing parsing timeout.
- Symptom: Chunk IDs in the knowledge base cannot be copied. Cause: ID display configuration for `chunkSettingMode` is not enabled, or front-end rendering logic is not bound to copy interaction events.

## How to confirm correct configuration
- Upload a landing page plan PDF, check if the parsed chunks retain heading hierarchies and form field information.
- Pass in a public landing page document link, wait for parsing to complete, and verify that all content is fully extracted.
- View the chunk list in the knowledge base, confirm that a copyable interaction button is displayed next to each chunk ID.
- Trigger a parsing task for a large AB test report, check that the task duration does not exceed the value set for `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided are common starting points and should be validated against local samples.
