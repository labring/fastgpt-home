# Security and Compliance Material Review for License Compliance and Copyright Notices: Conversation Logs and Auditing

## What this category of data looks like
Data for this category centers on license and copyright compliance for open source projects. Sources include LICENSE and NOTICE files in code repositories, third-party dependency lists, contributor commit records, and official standard license texts.
Updates trigger when project versions iterate or dependencies change. A single update covers license information, copyright attribution statements, and compliance terms for newly added dependencies.
Data structure includes fields such as dependency package name, license type, copyright holder, version number, and compliance validation flag. There is no unified fixed unit; each field is defined per the standards of its corresponding document.

## What constraints this category of data imposes on conversation logs and auditing workflows
Data for this category updates frequently with project version iterations or dependency changes. Conversation logs must link to compliance document snapshots for the corresponding version to avoid referencing outdated content during audits.
Multi-source data requires traceability paths marked in logs to ensure cross-checks for copyright statements and license texts can be traced back to their origins.
Audits must cover changes in compliance status before and after dependency changes, so conversation logs must retain full context of dependency additions and removals.
Additionally, compliance document fields have no unified fixed unit. Audits must match validation logic for corresponding fields to avoid cross-version field confusion, ensuring every compliance check basis is traceable.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Unique identifier binding the current compliance review session to the corresponding project version | Used in FastGPT v4.17.0 to link conversation logs and compliance review tasks, ensuring full-process review records for a single project can be quickly located during audits |
| `responseChatItemId` | Conversation node ID associated with each compliance check result | Used to mark specific conversation steps for single license compatibility checks or copyright attribution confirmations, facilitating detail tracing during audits |
| `detail` | Enable full log mode | Retain full context including dependency lists, license text snippets, validation rules, and more, to meet end-to-end traceability requirements for compliance audits |
| Conversation log retention period | 30–90 days | Matches the regular cycle of open source project version iterations, ensuring audits can cover at least one full version review cycle |
| Audit log export format | Standard JSON format | Adapts to import requirements of general compliance systems, facilitating subsequent archiving and batch validation |

## Three Common Misconfigurations
- Misconfiguration: Conversation logs do not display full license text for dependencies, and relevant fields are empty. Verify whether full log mode has not been enabled.
- Misconfiguration: Audits cannot locate review records for the corresponding project using `chatId`, and the number of results does not match expectations. Verify that `chatId` is bound to the project version number.
- Misconfiguration: Starting a new session with historical compliance review records has no effect, and previous validation context cannot be loaded. Verify that `responseChatItemId` is correctly associated with historical nodes.

## How to confirm configuration is complete
- Start the FastGPT server, verify that environment variables `AIPROXY_API_ENDPOINT` (AI Proxy service root address) and `AIPROXY_API_TOKEN` (AI Proxy administrator Token, non-empty and consistent with server configuration) are correctly configured and have no empty values.
- Initiate a compliance review session, check that the conversation log includes the `chatId` and `responseChatItemId` fields, and the `detail` field is marked as enabled.
- Attempt to export conversation logs, confirm that the export format matches the preset standard format and includes all dependency license information and validation records.
- Call the historical session retrieval interface, verify that complete review logs for the corresponding project can be retrieved using `chatId`, with no missing or confused records.
