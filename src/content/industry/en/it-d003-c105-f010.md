# Security and Compliance Material Review for License Compliance and Copyright Notices: Citation Sources and Traceability

## What Data Falls Under This Category
Data for this category originates from code repositories, dependency manifests, license texts, and contribution records. Core documents maintained regularly include LICENSE files, NOTICE files, dependency license lists, and copyright notices.
Data is updated synchronously with each version release or dependency change. Each type of document has distinct core fields:
- LICENSE files contain license type and authorization scope
- NOTICE files record copyright holders and third-party authorization statements
- Dependency license lists summarize compliance information for all third-party dependencies of a project
- Copyright notices mark the core copyright ownership of a project
Associated stakeholders include open source offices, project maintainers, and legal staff, who use this data for daily compliance checks and distribution authorization management.

## Constraints Imposed on Citation Sources and Traceability
Data sources are scattered across two primary channels: code repositories and dependency manifests. Traceability processes must support multi-data-source association verification to avoid missing compliance information when relying solely on a single list.
Data is updated at a relatively high frequency. Traceability processes must support matching versions to corresponding compliance documents, ensuring cited content aligns with the actual version of the current project or dependency.
Different documents have clearly distinct fields. Traceability processes must accurately locate content from target fields. For example, extract license type from LICENSE files, and obtain copyright notice information from NOTICE files.
The most time-consuming compliance check step relies on traceability accuracy. Traceability results must directly link to specific locations in original documents to meet traceability requirements for subsequent compliance audits.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `quoteMaxToken` | 800–1200 token | Matches the average character length of license and copyright notice documents, avoiding truncation of critical compliance information |
| `responseData` | Only include license number, copyright holder | Focuses on core compliance fields, reducing redundant content that occupies context space |
| `detail` | Enabled | Requires displaying specific file paths and version information for traceability, meeting traceability requirements for compliance reviews |
| Data Source Priority | Code repositories take precedence over dependency manifests | Official license files in code repositories have higher credibility, serving as the primary traceability baseline |
| Version Matching Toggle | Enabled | Data in this category is updated per version, requiring matching compliance documents for the corresponding version to avoid version mismatches |

## Three Common Misconfigurations
- Chat replies display knowledge base citation errors with a 400 status code. The cause is failure to configure the `quoteMaxToken` parameter, resulting in cited content exceeding context length limits.
- Replies show redundant knowledge base search input and response content. The cause is failing to disable display switches for non-core compliance information, accidentally including intermediate tool call steps in traceability displays.
- Traceability results fail to match license files for the corresponding version. The cause is not enabling version matching rules, using the latest version of documents to match compliance data for older dependency versions.

## How to Verify Proper Configuration
- Generate test queries that include dependency license information, and verify that the length of cited content falls within the preset token range.
- Review reply content, confirm that only core compliance fields are displayed, with no redundant intermediate tool call steps.
- Switch between different versions of dependency data, and verify that traceability results match compliance documents for the corresponding version.
- Check FastGPT v4.17.0 system logs, and confirm there are no citation-related error records.
