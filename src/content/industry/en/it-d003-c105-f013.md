# Security and Compliance Material Review for License Compliance and Copyright Notices: Permissions and Data Isolation

This document applies to FastGPT v4.17.0.

## What data for this category looks like
Data for this category comes from code repositories, dependency lists, license texts, and contribution records. Updates occur alongside project version releases or dependency package changes. Daily documents include LICENSE files, NOTICE files, dependency license lists, and copyright notices. Each entry includes fields such as license type, copyright holder, dependency package identifier, and release version. No additional statistical numbers are included. The data structure adjusts slightly based on project compliance requirements.

## What constraints do these characteristics impose on permissions and data isolation
This category of data is updated frequently and contains sensitive copyright ownership and license compliance information. Compliance data for different open source projects must be strictly isolated to prevent cross-project sensitive information leaks. Data sources involve multiple types of repositories and lists. Permission scopes must be divided by project to ensure only authorized team members can access compliance documents for their corresponding project. Additionally, contribution records and maintenance permissions must be tied to roles. This prevents unauthorized personnel from modifying compliance files and impacting the project’s license compliance.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind a unique value per project | Match compliance data isolation requirements for different open source projects, ensure license data for each project is only visible to authorized teams |
| Member permission configuration | Divide view/edit permissions by role | Differentiate between maintainers and regular members, only maintainers can modify compliance documents such as LICENSE and NOTICE |
| Data storage isolation | Divide independent storage paths by project directory | Avoid cross-storage of compliance data for different projects, meet data isolation requirements |
| Session isolation toggle | Enable | Ensure that compliance review chat records for different teams are not accessible across teams |
| Timeout threshold | 600 seconds | Adapt to complex calculation scenarios for license compatibility checks, prevent session interruptions due to excessive runtime |
| Data sync trigger | Trigger by version update | Match the update rhythm of this category of data, ensure real-time synchronization of compliance data |

## Three common mistakes
- Phenomenon: After generating a publicly accessible link, unauthorized members can view compliance review chat records for other projects. Cause: The session is not bound to the corresponding project via `teamId`, resulting in session data not being isolated by project.
- Phenomenon: After configuring the license compatibility check tool, clicking test prompts an error, and it can run normally after forcibly ignoring. Cause: Data storage isolation permissions are not configured, causing the tool to fail to read dependency list data for the specified project.
- Phenomenon: After local deployment, new members cannot be invited to join the compliance review team. Cause: Team permission isolation configuration is not enabled, causing the invitation function to not be activated.

## How to confirm the configuration is complete
- Access the compliance review pages for different projects, verify that only authorized team members can view LICENSE and NOTICE files for their corresponding project.
- Generate a publicly accessible link, verify that unauthorized users cannot access compliance review data for other teams.
- Trigger a license compatibility check task, verify that the task only runs within the permission scope of the authorized team.
- View the data storage directory, verify that compliance data for different projects is divided into independent storage paths.
