# Security and Compliance Material Review for Account Ban and Appeal Reconsideration: Citation Sources and Traceability

## What this category of data includes
Core data for this category is generated during account-level penalty and appeal reconsideration workflows. Daily documents include account ban records, user appeal materials, reconsideration judgment opinions, and violation disposal notifications. Data comes from violation trigger logs in risk control systems, manual review operation records, user behavior retention logs, and evidence materials retained from reports. Updates happen in real time or via daily batch jobs. Data fields include account unique identifiers, violation type tags, disposal levels, appeal submission times, and reconsideration results. There is no unified fixed unit; values vary by document type.

## Constraints for citation sources and traceability
Data sources are spread across multiple independent systems. Citation traceability first requires cross-source field mapping. This ensures account identifiers, violation content, and other fields from different systems can be uniformly linked. Real-time or daily updated data requires traceability logic to support incremental pulling or full verification. This prevents missing newly submitted appeal or reconsideration records. Account-level business attributes require traceability results to bind to unique account identifiers. This stops violation evidence from being confused across accounts. Disposal results tie to compliance verification requirements. Traceability must retain complete evidence chains. This ensures every cited item can be directly traced to its original record. It provides verifiable basis for reconsideration or appeals, and reduces risks such as false bans or returning violating accounts.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `1000–1500 token` | Appeal and ban documents for this category are mostly around 1000 characters per piece. This range retains core cited content fully while controlling context overhead |
| `detail` | `true` | Full metadata and original content of appeal materials must be obtained. Setting `detail` to `true` returns untruncated document information and account-bound fields |
| `responseData` | Return original document identifiers and account-bound fields | This category requires binding citation results to corresponding accounts. This ensures traceability does not mix violation evidence from different accounts |
| Single citation return limit | Top 5 entries | Core violation evidence for this category usually falls within 3-5 entries. Too many citations increase verification burden for review teams |
| Traceability data source scope | Risk control systems, review records, report evidence library | Core data sources for this category are the three systems listed. Limiting the scope avoids irrelevant data interfering with traceability results |
| Incremental update switch | Enabled | Data updates primarily use real-time or daily batch methods. Incremental pulling improves traceability efficiency and reduces repeated verification overhead |

## Three common configuration errors
- Phenomenon: Returned citation content does not include appeal materials for the specified account, or associates incorrect violation records. Cause: The account unique identifier is not bound in the `responseData` configuration. This leads to traceability results mixing original data from different accounts.
- Phenomenon: Knowledge base output citation files point to incorrect ban records or appeal materials. Cause: The `detail` parameter is not configured correctly. Only compressed metadata is returned, which cannot match the unique identifier of the original document.
- Phenomenon: FastGPT v4.17.0 returns citation content even after the citation switch is turned off. Cause: Version compatibility issue causes the verification logic for global configuration and single-call parameters to not take effect correctly. Non-expected citation returns are not blocked.

## How to confirm configurations are set correctly
- Initiate a call with a test account identifier. Check if the returned results include citation information for appeal materials and ban records bound to that account. Confirm accuracy of traceability association.
- Adjust the `quoteMaxToken` value range. Verify returned citation content has no truncation or overflow. Confirm context configuration meets business requirements.
- Turn off the citation switch and initiate a call. Confirm no additional citation content is returned. Verify configuration effectiveness.
- Check system operation logs. Confirm traceability requests correctly pull content from specified risk control systems, review records, and other data sources. Verify correctness of data source scope configuration.
